CIA Triad: Analyzing Real-World Breaches
Pending

Scenario: Three Incidents, One Framework

Three security incidents have occurred at your organization. Your job is to analyze each incident through the CIA triad lens — identify which pillars were violated, which were preserved, and what the impact was on each property.

Incident What Happened CIA Impact
Incident A Ransomware encrypted all production file servers. Systems are inaccessible but data has not been exfiltrated. Integrity violated (encrypted files are corrupted/inaccessible). Availability violated (files cannot be accessed). Confidentiality may be preserved (no data left the building).
Incident B A database administrator copies and sells 500,000 customer records to a competitor. No systems were disrupted. Confidentiality violated (data disclosed to unauthorized parties). Integrity preserved (data unchanged). Availability preserved (systems operational).
Incident C A SQL injection attack modifies pricing data in an e-commerce database, changing $500 items to $5 for 2 hours. Integrity violated (data modified by unauthorized party). Confidentiality may be violated (attacker read the database). Availability preserved (site remained operational).

The Analyst Mindset: Always Ask Three Questions

  • Confidentiality: Was data accessed or disclosed to unauthorized parties?
  • Integrity: Was data or system state altered without authorization?
  • Availability: Were legitimate users denied access to systems or data?

Tasks

Analysis Question

An attacker compromises a hospital's medical imaging server and changes patient names in MRI reports to incorrect names before doctors review them. Analyze this incident against all three CIA pillars. Which pillar is most critically violated and why? What are the real-world consequences beyond the technical impact?

Quantitative Risk Assessment: ALE Calculations
Pending

Scenario: Building a Risk Register

Your organization needs to build a quantitative risk register for three threat scenarios to justify security investment decisions to the CFO. Calculate the ALE for each scenario and recommend which vulnerability to address first.

QUANTITATIVE RISK FORMULAS: SLE = Asset Value x Exposure Factor ARO = How often the event occurs per year ALE = SLE x ARO SCENARIO TABLE: ┌──────────────────────┬────────────────┬──────────┬─────┬──────────┐ │ Threat Scenario │ Asset Value │ Exp Fac │ ARO │ ALE │ ├──────────────────────┼────────────────┼──────────┼─────┼──────────┤ │ A: Server ransomware │ $2,000,000 │ 40% │ 0.5 │ $400,000 │ │ (once/2yrs avg) │ │ │ │ │ ├──────────────────────┼────────────────┼──────────┼─────┼──────────┤ │ B: Employee data │ $500,000 │ 20% │ 2.0 │ $200,000 │ │ breach (2x/year) │ │ │ │ │ ├──────────────────────┼────────────────┼──────────┼─────┼──────────┤ │ C: Laptop theft │ $3,000/laptop │ 100% │ 10 │ $30,000 │ │ (10x/year avg) │ │ │ │ │ └──────────────────────┴────────────────┴──────────┴─────┴──────────┘ ALE tells you the expected annual cost from each risk. This justifies security controls — a $50,000 control that eliminates a $400,000 ALE risk is a clear ROI winner.

Quantitative vs. Qualitative Risk Assessment

  • Quantitative: Assigns dollar values using ALE = SLE x ARO. Precise but difficult — exposure factors are estimates, not guarantees
  • Qualitative: Uses High/Medium/Low matrices. Faster but subjective. Better for preliminary risk assessment
  • Best practice: Use qualitative for initial triage, quantitative for justifying major control investments

Decision Challenge

Calculate the risk reduction for each option and recommend which to implement, with full justification.

Penetration Testing Phases: Planning and Scoping Exercise

Scenario: Planning Your First Authorized Pentest

Your organization has hired an external penetration testing firm. You are responsible for preparing the scoping document and rules of engagement. Understanding each phase of NIST SP 800-115 is critical to ensuring a safe, authorized, and valuable test.

NIST SP 800-115 PENTEST PHASES: ┌─────────────┐ │ PLANNING │ — Timing, scope, authorization (WRITTEN!) └──────┬──────┘ No technical work. NEVER skip. │ ┌──────▼──────┐ │ DISCOVERY │ — Recon, OSINT, port scanning, vulnerability scanning └──────┬──────┘ No exploitation yet — identification only │ ┌──────▼──────┐ │ EXECUTE │ — Bypass controls, gain access, escalate privileges, │ ATTACK │ browse systems, install tools. May loop back to Discovery. └──────┬──────┘ │ ┌──────▼──────┐ │ REPORTING │ — Document findings. Prioritize by risk. └─────────────┘ Provide remediation recommendations. RED TEAM vs. PENTEST: • Pentest = structured test of specific systems with defined scope • Red Team = simulates full adversary campaign, often scope-blind • Blue Team = defenders responding to Red Team activity • White Team = referees, maintain simulated environment, arbitrate
