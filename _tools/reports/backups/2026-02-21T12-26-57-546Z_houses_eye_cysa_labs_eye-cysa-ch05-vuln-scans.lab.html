Scenario: Contradictory Scan Evidence

Nessus reports Apache 2.2.3 with a critical CVE. The admin says the server was patched to Apache 2.4.54 last month. Your job: determine if this is a false positive and what corrective action is needed.

NESSUS FINDING: Apache HTTP Server 2.2.3 - Remote Code Execution CVE: CVE-2006-3918 | CVSS: 7.8 (HIGH) Evidence: HTTP Server Header returned: "Apache/2.2.3 (Unix)" Port: 80/tcp ADMIN NOTES: Patch Date: 2026-01-15 New Version: Apache 2.4.54 Change Ticket: CHG-2024-0891 (CLOSED) Apache config: ServerTokens Full [displays full version string] ACTUAL SERVER STATE (manually verified): $ apache2 -v Server version: Apache/2.4.54 (Ubuntu) $ dpkg -l apache2 ii apache2 2.4.54-2ubuntu1 amd64 Apache HTTP Server EXPLANATION: ServerTokens Full causes Apache to report version in HTTP headers. However, the scanner found "Apache/2.2.3" -- an OLD cached banner. Root cause: Load balancer in front of web server caches responses. Cached response still contains old banner from before the patch. The scanner read the load balancer cache, not the actual server.

Key Validation Methods

  • Check patch status: verify installed package version against CVE affected versions
  • Verify configuration: confirm the actual running state, not just what was reported
  • Check for cached responses: load balancers and CDNs can serve stale banner data
  • Attempt controlled exploitation: if safe to do so, confirm exploitability against the actual target
  • Cross-reference with CMDB: does asset inventory reflect the correct version?

Documentation Question

This finding turned out to be a false positive caused by a load balancer cache serving stale headers. Write the documented exception note you would enter in Nessus to explain why this finding is suppressed, including what validation was performed and what the real remediation is.
