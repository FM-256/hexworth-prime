TLS Inspection & JA3 Fingerprinting

Transport Layer Security encrypts application data, preventing direct payload inspection. However, the TLS handshake itself is unencrypted and contains a wealth of metadata. This module teaches you to extract intelligence from TLS handshakes — particularly using JA3 and JA3S fingerprinting to identify malware families, correlate encrypted sessions, and detect anomalous TLS configurations without breaking encryption.

Learning Objectives

  • Parse TLS Client Hello and Server Hello messages in Wireshark
  • Extract and interpret JA3 and JA3S hash values
  • Use JA3 hashes to fingerprint malware families and non-browser TLS clients
  • Identify weak TLS configurations: deprecated versions, weak cipher suites, missing extensions
  • Detect certificate anomalies: self-signed, expired, mismatched CN/SAN
  • Build TLS-focused display filters for security analysis

TLS Handshake Anatomy

Every TLS connection begins with an unencrypted handshake that negotiates cryptographic parameters. The handshake reveals client capabilities, server choices, and certificate information — all visible in Wireshark without decryption keys.

MessageDirectionKey FieldsIntelligence Value
Client HelloClient → ServerTLS version, cipher suites, extensions, SNI, supported groupsJA3 hash — fingerprints the client application
Server HelloServer → ClientSelected cipher suite, TLS version, extensionsJA3S hash — fingerprints the server configuration
CertificateServer → ClientX.509 certificate chain, CN, SAN, issuer, validityServer identity verification, self-signed detection
Server Key ExchangeServer → ClientDH/ECDH parametersKey exchange strength analysis
Client Key ExchangeClient → ServerPre-master secret (encrypted)Marks end of plaintext handshake data

JA3 Fingerprinting

JA3 creates a fingerprint by hashing specific fields from the TLS Client Hello message: TLS version, accepted cipher suites, extensions list, elliptic curves, and elliptic curve point formats. The MD5 hash of these concatenated values produces a 32-character string that uniquely identifies the TLS client implementation.

What JA3 Identifies

  • Browser type and version — Chrome, Firefox, Safari each produce distinct JA3 hashes
  • Malware families — Cobalt Strike, Metasploit, Empire each have characteristic JA3 hashes
  • Programming language TLS stacks — Python requests, Go net/http, Java HttpClient each differ
  • Automated tools — curl, wget, Nmap have unique fingerprints

Wireshark JA3 Filters

// Display JA3 hash for all Client Hello messages tls.handshake.ja3 // Find a specific JA3 hash (replace with known malware JA3) tls.handshake.ja3 == "e35df3e00ca4ef31d42b34bebaa2f86e" // JA3S (server fingerprint) tls.handshake.ja3s == "ae4edc6faf64d08308082ad26be60767" // Find Client Hellos that do NOT match common browser JA3s tls.handshake.type == 1 && !(tls.handshake.ja3 in {"769,49195-49199,23-65281-10-11-35-16-5-13-28,29-23-24,0"})
JA3 Evasion

Modern C2 frameworks (Cobalt Strike 4.x, Sliver, Mythic) can randomize their Client Hello to mimic legitimate browser JA3 hashes. JA3 alone is not sufficient for detection — combine with behavioral analysis, certificate inspection, and connection patterns.

Certificate Analysis

The server certificate reveals identity information even in encrypted connections. Wireshark dissects the full X.509 certificate chain.

Deprecated TLS Detection

// TLS 1.0 connections (deprecated, vulnerable to BEAST/POODLE) tls.record.version == 0x0301 // TLS 1.1 connections (deprecated) tls.record.version == 0x0302 // SSLv3 connections (completely broken — POODLE) tls.record.version == 0x0300 // Weak cipher suites (RC4, DES, export ciphers) tls.handshake.ciphersuite in {0x0004, 0x0005, 0x000a, 0x0013, 0x002f}

Key Takeaways

  • The TLS handshake is unencrypted and reveals client capabilities, server configuration, and certificate details.
  • JA3 fingerprints the Client Hello to identify client applications — different browsers, malware, and tools produce unique hashes.
  • JA3S fingerprints the Server Hello — useful for identifying C2 server configurations.
  • Certificate analysis reveals self-signed certs, expired certs, mismatched CNs, and other anomalies common in malware infrastructure.
  • Modern C2 frameworks can forge JA3 hashes — use JA3 as one signal among many, not as a standalone detection.
  • Deprecated TLS versions (1.0, 1.1, SSLv3) represent both security risks and potential indicators of compromise.
