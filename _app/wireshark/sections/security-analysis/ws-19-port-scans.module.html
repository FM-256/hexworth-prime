Port Scan Signatures

Port scanning is typically the first active reconnaissance an attacker performs against a target network. Each scanning technique produces a distinct packet pattern in Wireshark. This module teaches you to identify SYN scans, NULL scans, FIN scans, Xmas scans, UDP scans, and ACK scans by their TCP flag combinations and response patterns — allowing you to detect reconnaissance before the attacker moves to exploitation.

Learning Objectives

  • Identify TCP SYN (half-open) scan patterns and distinguish them from normal connections
  • Recognize stealth scan signatures: NULL, FIN, and Xmas scans by their flag combinations
  • Detect UDP port scans through ICMP Port Unreachable responses
  • Use TCP flag filters to isolate scanning activity in large captures
  • Estimate scan scope and target range from packet capture data
  • Build alerting filters for each scan type

TCP SYN Scan (Half-Open Scan)

The SYN scan sends a TCP SYN packet to each target port. If the port is open, the target responds with SYN-ACK. The scanner then sends RST instead of completing the handshake — this is why it is called "half-open." Nmap's default scan type (nmap -sS).

Pattern in Wireshark

  • Open port: SYN → SYN-ACK → RST (three packets, no established connection)
  • Closed port: SYN → RST-ACK (two packets)
  • Filtered port: SYN → (no response or ICMP unreachable)
// Find SYN-only packets (no ACK flag) — scan probes tcp.flags.syn == 1 && tcp.flags.ack == 0 // SYN scan from a specific source ip.src == 10.0.0.99 && tcp.flags.syn == 1 && tcp.flags.ack == 0 // RST responses (port closed or scanner aborting handshake) tcp.flags.rst == 1 // Count unique destination ports to estimate scan scope // Statistics -> Endpoints -> TCP tab, filter by source IP

NULL Scan

A NULL scan sends TCP packets with no flags set at all. Per RFC 793, a closed port should respond with RST; an open port should silently drop the packet. This scan exploits RFC-compliant TCP stacks and does not work against Windows hosts.

// NULL scan: TCP packet with no flags (flags byte = 0) tcp.flags == 0x000

FIN Scan

A FIN scan sends TCP packets with only the FIN flag set. Like NULL scans, closed ports respond with RST while open ports drop the packet silently.

// FIN scan: only FIN flag set (no SYN, no ACK) tcp.flags.fin == 1 && tcp.flags.syn == 0 && tcp.flags.ack == 0

Xmas Scan

An Xmas scan sets the FIN, PSH, and URG flags simultaneously — "lighting up the packet like a Christmas tree." Same response logic as NULL and FIN scans.

// Xmas scan: FIN + PSH + URG flags set tcp.flags.fin == 1 && tcp.flags.push == 1 && tcp.flags.urg == 1 // Or by flag value (FIN=1, PSH=8, URG=32 = 41 = 0x029) tcp.flags == 0x029

UDP Scan

UDP scanning sends empty UDP datagrams (or protocol-specific payloads) to target ports. Closed ports respond with ICMP Port Unreachable (type 3, code 3). Open ports either respond with data or silently accept the datagram.

// ICMP Port Unreachable responses (indicates closed UDP port) icmp.type == 3 && icmp.code == 3 // High volume of ICMP unreachable from a target = UDP scan in progress icmp.type == 3 && ip.src == 192.168.1.100

Quick Scan Detection

The fastest way to detect a port scan in Wireshark: go to Statistics → Endpoints → TCP tab. Sort by the source address column. If one IP has connections to dozens or hundreds of unique destination ports, it is scanning.

Scan Signature Challenge

Identify the scan type from the described packet pattern.

1. You see 500 TCP packets from 10.0.0.99 to 192.168.1.50, each targeting a different port. Every packet has only the SYN flag set. For open ports, the target responds SYN-ACK and 10.0.0.99 immediately sends RST. For closed ports, the target responds RST-ACK. What scan type is this?
2. TCP packets arrive with FIN, PSH, and URG flags all set simultaneously, but no SYN or ACK. This combination never appears in normal TCP communication. What scan type is this?
3. Which display filter would you use to find TCP packets with NO flags set at all?

Key Takeaways

  • SYN scan is the most common — look for SYN-only packets to many ports followed by RST responses.
  • NULL, FIN, and Xmas scans use flag combinations that never appear in legitimate traffic — any occurrence is a definitive scan indicator.
  • UDP scans trigger ICMP Port Unreachable responses from closed ports — high volumes of ICMP type 3 code 3 indicate UDP scanning.
  • Statistics → Endpoints sorted by source IP is the fastest way to identify scanning hosts.
  • Scan scope estimation: count unique destination ports and IPs targeted from the scanning source.
