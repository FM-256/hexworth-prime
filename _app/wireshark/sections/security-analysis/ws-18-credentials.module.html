Credential Exposure in Traffic

Credentials transmitted in cleartext or weakly encoded formats are immediately visible in packet captures. This lab teaches you to locate plaintext passwords, NTLM hashes, HTTP Basic authentication, FTP credentials, and email login sequences in Wireshark. Every credential found in a capture represents a critical finding that must be reported and remediated.

Learning Objectives

  • Extract HTTP Basic authentication credentials from packet captures
  • Identify FTP, Telnet, and SMTP plaintext password transmissions
  • Locate NTLM authentication exchanges and extract challenge/response hashes
  • Detect HTTP form-based login credential submission in POST bodies
  • Use Wireshark's credential-specific display filters for rapid discovery
  • Understand the security implications of each credential exposure type

HTTP Basic Authentication

HTTP Basic auth transmits credentials as a Base64-encoded string in the Authorization header. Base64 is encoding, not encryption — anyone with the capture can decode it instantly.

Detection Filter

// Find HTTP Basic auth headers http.authbasic // The field value shows the decoded username:password pair // Add http.authbasic as a column to see credentials directly

Extraction Steps

  1. Apply filter http.authbasic
  2. Select a matching packet and expand HTTP › Authorization header
  3. Wireshark automatically decodes the Base64 and shows the username:password pair
  4. The http.authbasic field displays the decoded credentials directly

FTP Credentials

FTP transmits usernames and passwords in plaintext as USER and PASS commands. These are trivially visible in packet captures.

// FTP username ftp.request.command == "USER" // FTP password ftp.request.command == "PASS" // Both in one filter ftp.request.command in {"USER", "PASS"}
FTP Is Cleartext

FTP sends everything in cleartext — usernames, passwords, file contents, and directory listings. There is no encryption option in the FTP protocol itself. SFTP (SSH File Transfer Protocol) and FTPS (FTP over TLS) are the encrypted alternatives. Any FTP traffic on a network is a finding.

Telnet Credentials

Telnet transmits every keystroke in cleartext, including passwords. Each character is sent as a separate TCP segment.

// Filter for Telnet traffic telnet // To reconstruct the full session including typed password: // Right-click any Telnet packet -> Follow -> TCP Stream // The password appears character-by-character in the stream

NTLM Authentication

NTLM authentication transmits a challenge-response hash that can be cracked offline. While not cleartext, NTLM hashes captured from the wire are valuable targets for password cracking tools like hashcat.

// Find NTLM authentication exchanges ntlmssp // NTLM Negotiate message (Type 1) ntlmssp.messagetype == 1 // NTLM Challenge message (Type 2) — contains the server challenge ntlmssp.messagetype == 2 // NTLM Authenticate message (Type 3) — contains the hash to crack ntlmssp.messagetype == 3

Extracting NTLMv2 Hashes for Cracking

  1. Filter for ntlmssp.messagetype == 2 — note the Server Challenge value (8 bytes hex)
  2. Filter for ntlmssp.messagetype == 3 — note the NTProofStr, NTLMv2 Response, User name, and Domain name
  3. Format for hashcat: username::domain:ServerChallenge:NTProofStr:NTLMv2Response
  4. Crack with: hashcat -m 5600 hash.txt wordlist.txt

HTTP Form Login Credentials

// HTTP POST requests (form submissions often include credentials) http.request.method == "POST" // Look for common credential field names in POST body urlencoded-form.key contains "password" urlencoded-form.key contains "passwd" urlencoded-form.key contains "pass" // Follow the HTTP stream to see the full POST body with credentials

Email Credentials

// SMTP AUTH LOGIN (Base64 encoded credentials) smtp.auth.password // IMAP LOGIN command (plaintext) imap.request contains "LOGIN" // POP3 USER and PASS commands pop.request.command == "PASS"

Credential Detection Challenge

Identify the credential exposure type in each scenario.

1. You see an HTTP request with the header Authorization: Basic YWRtaW46UEBzc3cwcmQhMjM=. What credentials are exposed?
2. Which Wireshark filter shows ALL NTLM authentication messages including the hash that can be cracked offline?

Key Takeaways

  • HTTP Basic auth is Base64-encoded plaintext — Wireshark decodes it automatically via the http.authbasic field.
  • FTP, Telnet, and POP3 transmit credentials in complete cleartext. Their presence on a network is itself a security finding.
  • NTLM challenge-response hashes can be extracted from captures and cracked offline with hashcat.
  • HTTP form submissions over non-HTTPS connections expose usernames and passwords in POST bodies.
  • Always document every credential found in a capture — each one represents a potential compromise that requires password reset.
