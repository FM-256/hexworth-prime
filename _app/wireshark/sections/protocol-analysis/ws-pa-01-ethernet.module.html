Ethernet Frame Structure

Every packet you capture in Wireshark rides inside an Ethernet frame at Layer 2. Before TCP, IP, or any application-layer data can be interpreted, Wireshark must parse this outer shell. Understanding each field — what it contains, how many bytes it occupies, and what it tells a forensic analyst — is the foundation of packet-level investigation.

Learning Objectives

  • Identify all six fields of the Ethernet II frame and their byte lengths
  • Explain the role of the preamble and SFD during physical-layer framing
  • Decode destination and source MAC addresses from a hex dump
  • Interpret EtherType values to determine the encapsulated protocol
  • Understand FCS and its significance for frame integrity

Field Reference

Field Size Offset (hex) Purpose
Preamble + SFD 8 bytes 0x00 – 0x07 Clock synchronization; SFD byte 0xAB marks frame start. Stripped before Wireshark sees the frame.
Destination MAC 6 bytes 0x00 – 0x05 Hardware address of the intended recipient on the local segment.
Source MAC 6 bytes 0x06 – 0x0B Hardware address of the sender. Forgeable at Layer 2; cannot be trusted in isolation.
EtherType 2 bytes 0x0C – 0x0D Identifies the Layer 3 protocol: 0x0800 = IPv4, 0x86DD = IPv6, 0x0806 = ARP.
Payload 46 – 1500 bytes 0x0E + The encapsulated Layer 3 datagram. Minimum 46 bytes enforced by padding to prevent late collision detection issues.
FCS 4 bytes Last 4 bytes CRC-32 checksum over the entire frame minus preamble. Most NICs strip FCS; Wireshark rarely displays it by default.

Reading the Hex Dump

When you select an Ethernet frame in Wireshark and click the Ethernet II row in the Packet Details pane, the first 14 bytes light up in the Packet Bytes pane. Here is what you are looking at:

-- Packet Bytes pane — offsets in hex (preamble stripped by NIC driver) -- 0000 c8 d7 19 f2 a3 b1 00 1b 44 11 3a b7 08 00 45 00 ^^^^^^^^^^^^^^^^^^^ ^^^^^^^^^^^^^^^^^^^ ^^^^^ Dst MAC (6 bytes) Src MAC (6 bytes) EtherType 0x0800 = IPv4 0010 00 34 1a 2c 40 00 40 06 9d 3f c0 a8 01 69 5d b8 0020 d8 22 d4 31 00 50 00 00 00 00 00 00 00 00 50 02 0030 fa f0 c3 a2 00 00 <-- payload ends here
Note

The preamble (8 bytes) is consumed by the NIC and never delivered to the OS. Wireshark captures frames after kernel delivery, so offset 0x00 in the Bytes pane always corresponds to the first byte of the Destination MAC, not the preamble.

Security Note

An EtherType value below 0x0600 indicates an IEEE 802.3 length field (pre-Ethernet II). If you see 0x0800 but the Details pane shows ARP or another protocol, a crafted or malformed frame may be present — treat it as anomalous during incident investigation.

MAC Address Analysis

A MAC address is a 48-bit Layer 2 hardware identifier written as six colon-separated octets. Two structural bits inside the first octet carry critical classification information. Recognizing broadcast, multicast, and locally administered addresses at a glance is a core packet analysis skill — and spotting a spoofed or randomized MAC is a key threat-hunting signal.

Address Structure

The 48 bits split into two 24-bit halves. The first half is the OUI (Organizationally Unique Identifier) assigned to a vendor by IEEE. The second half is the NIC-specific portion assigned by the vendor. Two special bits inside the first octet override the OUI's meaning:

MAC Address Anatomy — 00:1B:44:11:3A:B7
00: 1B: 44: 11: 3A: B7
OUI — vendor-assigned, first 24 bits
NIC-specific — device-assigned, last 24 bits

The Two Control Bits

BitPosition in First OctetValue 0Value 1
I/G (Individual/Group) Least significant bit (bit 0) Unicast — sent to one device Multicast/Broadcast — sent to a group
U/L (Universal/Local) Second least significant bit (bit 1) Universally administered (OUI is valid) Locally administered (OUI is fabricated or randomized)
Tip

To read the I/G bit: convert the first octet to binary. The rightmost bit is I/G. 00 binary is 00000000 — I/G=0 (unicast), U/L=0 (universally administered). 02 binary is 00000010 — I/G=0, U/L=1 (locally administered unicast — a common MAC randomization signature).

Address Types

Global Unicast
00:1B:44:11:3A:B7
I/G=0, U/L=0. First octet LSB is 0 and second LSB is 0. OUI 00:1B:44 is IEEE-registered to a specific vendor. The address uniquely identifies one NIC globally.
Broadcast
FF:FF:FF:FF:FF:FF
All 48 bits set to 1. Every device on the local segment receives and processes frames with this destination. ARP requests are the most common carrier. In Wireshark, the Destination column shows Broadcast.
IPv4 Multicast
01:00:5E:xx:xx:xx
I/G=1 (first octet ends in odd hex digit). IPv4 multicast MACs begin with 01:00:5E and map the low 23 bits of the multicast IP group. A device joined to the group processes these frames; others discard at the NIC.
Locally Administered
02:xx:xx:xx:xx:xx
U/L=1 (second LSB of first octet is 1). The OUI is meaningless — the address was assigned by software. MAC randomization in modern OSes and containers sets this bit. A high density of locally administered MACs in a capture is a strong indicator of privacy tools or MAC spoofing.

Threat Hunting

During lateral movement, attackers frequently clone the MAC address of a legitimate host to bypass NAC (Network Access Control) policies. If two frames in the same capture share a source MAC but carry different IP addresses — and one matches a known asset — investigate immediately. Use eth.src == aa:bb:cc:dd:ee:ff to isolate all traffic from a suspect MAC.

Wireshark Ethernet Filters

Ethernet-layer display filters let you isolate traffic by hardware address or frame type before any IP-layer context is available. Address Filters

eth.addr == c8:d7:19:f2:a3:b1
All frames where this MAC appears as either source or destination. The fastest way to isolate one device's full Layer 2 conversation.
eth.src == 00:1b:44:11:3a:b7
Frames originating from this specific MAC. Use during post-incident review to reconstruct what a specific NIC transmitted.
eth.dst == ff:ff:ff:ff:ff:ff
All broadcast frames. Excessive broadcasts from a single source can indicate a misconfigured device, worm propagation, or ARP flooding.
eth.dst[0] & 1
All multicast and broadcast frames. Masks the I/G bit (LSB of first octet). Useful for baselining Layer 2 multicast density on a segment.
eth.addr[0] & 2
Frames carrying a locally administered (U/L=1) MAC address. Filters for MAC-randomized clients, VMs with synthetic MACs, and potential spoofing.
!(eth.addr == your:own:mac)
Exclude your own MAC from results. Useful when capturing in promiscuous mode to focus on third-party traffic passing through the segment.

EtherType Filters

eth.type == 0x0806
ARP frames only. Essential first step when investigating ARP poisoning — look for unsolicited ARP replies or duplicate IP-to-MAC mappings.
eth.type == 0x8100
802.1Q VLAN-tagged frames. If you see these on an access port, a device may be sending tagged frames attempting VLAN hopping.
eth.type == 0x86dd
IPv6 frames. Use to isolate IPv6 traffic when investigating dual-stack environments or unexpected tunneled traffic.
eth.type < 0x0600
IEEE 802.3 length-field frames (pre-Ethernet II). Frames with a sub-0x0600 type field carry LLC/SNAP headers. Unexpected on modern Ethernet — investigate anomalous frames.

OUI-Based Filters

You can filter by OUI prefix to isolate traffic from a specific vendor — useful when hunting for unauthorized devices or mapping what hardware is active on a segment.

-- Show all frames where source OUI matches Apple (AC:DE:48) -- eth.src[0:3] == ac:de:48 -- Show all frames where destination OUI matches Cisco (00:00:0C) -- eth.dst[0:3] == 00:00:0c -- Combine: source from Intel (8C:8D:28) sending to broadcast -- eth.src[0:3] == 8c:8d:28 && eth.dst == ff:ff:ff:ff:ff:ff

Combining with Higher-Layer Filters

Ethernet filters compose freely with IP, TCP, and application filters using boolean operators. The full filter expression evaluates against every field in the dissected frame.

-- ARP storm detection: ARP from one specific MAC at high rate -- arp && eth.src == de:ad:be:ef:00:01 -- VLAN-tagged frames carrying IPv4 (potential VLAN hopping probe) -- eth.type == 0x8100 && vlan.id == 10 && ip -- Non-broadcast traffic where the MAC OUI is locally administered -- eth.src[0] & 2 && eth.dst != ff:ff:ff:ff:ff:ff
Tip

Right-click any MAC address field in the Packet Details pane and select Apply as Filter › Selected. Wireshark automatically generates the correct eth.addr or eth.src expression and applies it without manual typing.

VLAN Tagging (802.1Q)

IEEE 802.1Q inserts a 4-byte tag between the Source MAC and EtherType fields of a standard Ethernet frame. This tag carries VLAN membership information, allowing a single physical link to carry traffic for multiple logical networks simultaneously. Understanding tagged frames in Wireshark is essential for analyzing trunk links, investigating VLAN hopping attacks, and correlating traffic across segmented environments.

802.1Q Tagged Frame Structure

The 802.1Q tag increases total frame size from 1518 bytes to 1522 bytes (maximum). Wireshark recognizes the tag automatically when EtherType 0x8100 is detected and renders a separate 802.1Q Virtual LAN layer in the Packet Details tree.

Trunk vs. Access Links

Trunk Link
  • Carries traffic for multiple VLANs
  • Frames are tagged with 802.1Q VID
  • Typically between switches, or switch-to-router
  • Native VLAN frames are untagged by default
  • In Wireshark: mix of tagged (eth.type == 0x8100) and untagged frames
Access Link
  • Carries traffic for one VLAN only
  • Frames are untagged — switch adds/removes tag internally
  • Typically connects end devices (workstations, servers)
  • If you capture tagged frames on an access port, investigate immediately
  • In Wireshark: no eth.type == 0x8100 frames expected

VLAN Hopping

VLAN hopping is a Layer 2 attack that allows an attacker on one VLAN to send traffic to another VLAN without passing through a router. Two techniques exist:

Switch Spoofing

An attacker configures their NIC to speak the Dynamic Trunking Protocol (DTP) and convinces the switch to establish a trunk. The attacker's interface then receives tagged traffic for all VLANs. Wireshark evidence: DTP frames (ethertype == 0x2004) originating from an endpoint rather than a switch.

Double Tagging

The attacker crafts a frame with two 802.1Q tags. The outer tag matches the attacker's access VLAN and is stripped by the first switch. The inner tag carries the target VLAN ID and is forwarded by the second switch into the victim VLAN. This technique works in one direction only (attacker cannot receive responses).

-- Double-tagged frame in Wireshark Packet Details -- Ethernet II Type: 802.1Q (0x8100) 802.1Q Tag VLAN ID: 1 (outer tag — attacker's VLAN, stripped at first switch) Type: 802.1Q (0x8100) <-- second 0x8100 signals double-tagging 802.1Q Tag VLAN ID: 20 (inner tag — victim VLAN) Type: IPv4 (0x0800)
Detection Filter

Use vlan && vlan in Wireshark to display frames that contain two or more nested 802.1Q tags. Any such frame arriving from an end-device access port is a high-confidence double-tagging indicator.

Key Takeaways

  • An Ethernet II frame has six fields: Preamble (stripped by NIC), Destination MAC, Source MAC, EtherType, Payload, and FCS (also stripped). Wireshark shows bytes starting at Destination MAC.
  • EtherType at offset 0x0C determines the Layer 3 protocol: 0x0800 = IPv4, 0x0806 = ARP, 0x86DD = IPv6, 0x8100 = 802.1Q.
  • The I/G bit (LSB of first octet) distinguishes unicast from multicast/broadcast. The U/L bit identifies locally administered addresses — a key indicator of MAC randomization or spoofing.
  • eth.addr matches source or destination; eth.src and eth.dst are directional. OUI-prefix filters use the eth.src[0:3] slice syntax.
  • 802.1Q inserts a 4-byte tag after the Source MAC field. The 12-bit VID supports VLAN IDs 1–4094. Double-tagged frames (vlan && vlan) are a reliable VLAN hopping indicator.
  • Tagged frames on an access port are anomalous and warrant immediate investigation for switch spoofing or VLAN hopping activity.
