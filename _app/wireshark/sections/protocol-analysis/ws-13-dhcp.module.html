DHCP Lease Analysis

DHCP (Dynamic Host Configuration Protocol) assigns IP addresses, subnet masks, gateways, and DNS servers to network clients. Analyzing DHCP traffic in Wireshark reveals the DORA process (Discover, Offer, Request, Acknowledge), option fields that fingerprint client operating systems, and rogue DHCP server indicators. DHCP analysis is essential for network troubleshooting and detecting unauthorized infrastructure on the network.

Learning Objectives

  • Trace the DORA (Discover-Offer-Request-Acknowledge) lease process in Wireshark
  • Extract client identification from DHCP option fields (hostname, vendor class)
  • Detect rogue DHCP servers by monitoring Offer messages from unexpected sources
  • Analyze DHCP lease timing for troubleshooting address conflicts
  • Build display filters for DHCP message types

The DORA Process

StepMessageDirectionDescriptionFilter
1DiscoverClient → BroadcastClient broadcasts request for IP addressdhcp.option.dhcp == 1
2OfferServer → ClientServer offers an available IP addressdhcp.option.dhcp == 2
3RequestClient → BroadcastClient formally requests the offered addressdhcp.option.dhcp == 3
4AcknowledgeServer → ClientServer confirms the leasedhcp.option.dhcp == 5

Key DHCP Filters

// All DHCP traffic dhcp // DHCP Discover (new clients requesting addresses) dhcp.option.dhcp == 1 // DHCP Offer (servers responding with available addresses) dhcp.option.dhcp == 2 // DHCP NAK (server rejecting a request) dhcp.option.dhcp == 6 // Client hostname (Option 12) dhcp.option.hostname // Vendor class (Option 60 — OS fingerprinting) dhcp.option.vendor_class_id

Rogue DHCP Server Detection

A rogue DHCP server is an unauthorized server on the network that responds to DHCP Discover messages. It can redirect client traffic through attacker-controlled gateways and DNS servers (DHCP spoofing / DHCP poisoning).

Detection Method

  1. Filter for DHCP Offer messages: dhcp.option.dhcp == 2
  2. Examine the Server Identifier (Option 54) in each Offer
  3. If Offers come from more than one server IP, investigate the unexpected one
  4. Check the offered Router (Option 3) and DNS (Option 6) — rogue servers often point these to attacker-controlled addresses
DHCP Spoofing Impact

A rogue DHCP server that provides a malicious default gateway enables man-in-the-middle attacks on all client traffic. A malicious DNS server enables phishing and credential interception. DHCP spoofing is one of the most impactful LAN-based attacks and is trivially detectable in Wireshark.

DHCP Option Fingerprinting

The combination and order of DHCP options in a Discover message fingerprints the client operating system. This is because different OS DHCP clients request options in different orders.

Key Takeaways

  • DHCP follows the DORA process: Discover, Offer, Request, Acknowledge.
  • Filter by message type using dhcp.option.dhcp == N (1=Discover, 2=Offer, 3=Request, 5=ACK, 6=NAK).
  • Rogue DHCP servers are detected by monitoring Offer messages from unexpected server IPs.
  • DHCP option 55 (Parameter Request List) fingerprints the client operating system.
  • A rogue server providing malicious gateway/DNS enables man-in-the-middle attacks on all clients.
