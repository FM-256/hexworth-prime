Evidence-Grade Packet Capture

Forensic packet capture goes beyond routine network analysis. When captures may be used as legal evidence, every step must follow chain-of-custody procedures, integrity verification, and documentation standards. This module covers the techniques and tools for creating forensically sound packet captures that withstand legal scrutiny.

Learning Objectives

  • Configure Wireshark and dumpcap for forensic-quality captures
  • Implement hash verification (MD5, SHA-256) for PCAP integrity
  • Set up ring buffer captures for continuous evidence preservation
  • Document chain of custody for packet capture evidence
  • Understand legal requirements for network evidence admissibility

Forensic Capture Requirements

A forensically sound packet capture must meet three criteria: completeness (no dropped packets), integrity (hash-verified, unmodified), and chain of custody (documented handling from capture to court).

Capture Configuration

# Forensic capture with dumpcap — maximizes reliability dumpcap -i eth0 -w /evidence/case-2026-001/capture.pcapng \ -b filesize:100000 \ -b files:50 \ --capture-comment "Case 2026-001, Analyst: Smith, Auth: Warrant #4521" # Parameters: # -b filesize:100000 Ring buffer: 100 MB per file # -b files:50 Keep last 50 files (5 GB rolling window) # --capture-comment Embeds metadata in the pcapng file
dumpcap vs Wireshark for Evidence

Always use dumpcap for forensic captures, not the Wireshark GUI. dumpcap is a minimal, single-purpose capture tool that is less likely to drop packets under load. The Wireshark GUI performs real-time dissection which can cause packet loss on high-speed links.

Integrity Verification

Immediately after capture, generate cryptographic hashes to prove the file has not been modified.

# Generate SHA-256 hash immediately after capture sha256sum capture.pcapng > capture.pcapng.sha256 # Generate MD5 hash (for compatibility with some legal systems) md5sum capture.pcapng > capture.pcapng.md5 # Verify integrity at any later point sha256sum -c capture.pcapng.sha256

Chain of Custody Documentation

Every person who handles the capture file must be documented. The chain of custody form should include:

  • Case number and incident reference
  • Date/time of capture start and stop (UTC)
  • Capture point — interface, SPAN port, or TAP location
  • Analyst name and authorization (warrant, consent, policy)
  • File hashes computed at time of capture
  • Transfer log — who received the file, when, via what method
  • Storage location — encrypted drive, evidence locker reference

Ring Buffer Strategy

Ring buffers ensure continuous capture without unbounded disk consumption. When the maximum number of files is reached, the oldest file is overwritten. This is essential for long-running captures on production taps.

pcapng vs pcap Format

For forensic work, always use pcapng (the default in modern Wireshark). It supports features critical for evidence:

  • Capture comments — embed case metadata directly in the file
  • Interface information — records which NIC captured each packet
  • Nanosecond timestamps — higher precision than pcap's microseconds
  • Multiple interfaces — one file can contain captures from multiple NICs
  • Packet comments — annotate individual packets during analysis

Key Takeaways

  • Use dumpcap (not the Wireshark GUI) for forensic captures to minimize packet loss.
  • Compute SHA-256 hashes immediately after capture — before opening the file for analysis.
  • Ring buffers prevent unbounded disk usage while maintaining a rolling capture window.
  • pcapng format supports capture comments, nanosecond timestamps, and per-packet annotations.
  • Chain of custody must document every person who handles the evidence file.
  • Embed case metadata in the capture file using the --capture-comment flag.
