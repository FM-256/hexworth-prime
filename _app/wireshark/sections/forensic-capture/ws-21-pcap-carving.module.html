PCAP Artifact Carving

Packet captures contain more than protocol headers — they contain the actual files, images, documents, and credentials that were transmitted over the network. Artifact carving extracts these embedded objects from capture files, reconstructing what was downloaded, uploaded, or transferred during the captured timeframe. This is a core forensic skill for incident response.

Learning Objectives

  • Extract HTTP objects (files, images, scripts) using Wireshark's built-in export
  • Carve files from TCP streams using Follow Stream and manual extraction
  • Extract email attachments from SMTP/IMAP captures
  • Use tshark and third-party tools for automated bulk extraction
  • Verify extracted file integrity with hash comparison
  • Handle encrypted content and compressed transfers

Wireshark's Built-In HTTP Object Export

Wireshark can automatically extract all HTTP-transferred files from a capture. This is the fastest method for HTTP traffic.

  1. Open the capture file in Wireshark
  2. Go to File › Export Objects › HTTP
  3. The dialog lists every HTTP object (HTML pages, images, JavaScript, CSS, downloads)
  4. Click Save All to extract everything, or select individual files
  5. Each file is saved with its original filename when available
Other Export Object Types

Wireshark also supports exporting objects from SMB (File › Export Objects › SMB), DICOM (medical imaging), TFTP, and IMF (email messages). Check all available protocols when carving artifacts from a capture.

Manual Stream Extraction

When automatic export fails (fragmented transfers, non-HTTP protocols, or custom encodings), extract files manually from TCP streams.

  1. Identify the stream containing the file transfer
  2. Right-click a packet in the stream → Follow › TCP Stream
  3. In the Follow Stream dialog, change Show data as to Raw
  4. If the file is in only one direction, select the appropriate direction from the dropdown
  5. Click Save As to save the raw bytes to a file
  6. You may need to trim protocol headers from the beginning of the saved data

Automated Extraction with tshark

# Export all HTTP objects via command line tshark -r capture.pcapng --export-objects http,/output/http/ # Export SMB transferred files tshark -r capture.pcapng --export-objects smb,/output/smb/ # Extract specific fields for analysis tshark -r capture.pcapng -Y "http.response" \ -T fields -e http.content_type -e http.response.code -e http.request.uri

File Type Identification

After extraction, verify file types using magic bytes rather than file extensions. Attackers frequently rename malicious files with benign extensions.

# Check file type by magic bytes file extracted_image.jpg # Output: extracted_image.jpg: PE32 executable (GUI) Intel 80386, for MS Windows # The file claimed to be a JPEG but is actually a Windows executable # Compute hash for IOC matching sha256sum extracted_file.exe # Compare against VirusTotal, MISP, or internal IOC databases

Email Attachment Extraction

For SMTP captures, email messages (including attachments) can be exported:

  1. Go to File › Export Objects › IMF (Internet Message Format)
  2. Each email message is saved as a .eml file
  3. Open the .eml file with an email client or parser to extract attachments
  4. For IMAP captures, Follow TCP Stream on the FETCH response to extract message content
Malware Handling

Extracted files may contain live malware. Always perform extraction on an isolated analysis workstation. Use a VM snapshot that can be reverted. Hash all extracted files and check against threat intelligence databases before opening.

Key Takeaways

  • File › Export Objects › HTTP is the fastest extraction method for HTTP-transferred files.
  • Manual extraction via Follow Stream (Raw mode) works for any TCP-based protocol.
  • tshark --export-objects enables automated, scriptable bulk extraction.
  • Always verify file types with magic bytes (file command), not extensions — attackers disguise executables.
  • Hash all extracted artifacts for IOC matching against threat intelligence databases.
  • Extract on isolated analysis workstations — carved files may contain live malware.
