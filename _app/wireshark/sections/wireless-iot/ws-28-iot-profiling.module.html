IoT Traffic Profiling

IoT devices generate predictable network traffic patterns — regular check-ins with cloud services, firmware update polls, telemetry uploads, and command responses. Profiling these patterns establishes a behavioral baseline that makes anomalies immediately visible. This module teaches you to build traffic profiles for IoT devices using Wireshark, identify common IoT protocols, and detect compromised IoT devices through behavioral deviation.

Learning Objectives

  • Build baseline traffic profiles for common IoT device categories
  • Identify IoT-specific protocols: MQTT, CoAP, mDNS, SSDP
  • Detect anomalous IoT behavior: unexpected destinations, volume spikes, new protocols
  • Use Wireshark to identify unpatched IoT devices by protocol version and behavior
  • Analyze IoT cloud API communication patterns

Building a Device Profile

A traffic profile documents the expected network behavior of a specific IoT device type. Create one by capturing 24-48 hours of normal operation.

Profile Components

  • Destinations — which external IPs/domains the device contacts (cloud APIs, NTP, manufacturer servers)
  • Protocols — which protocols the device uses (MQTT, HTTPS, DNS, NTP)
  • Ports — expected destination ports
  • Volume — typical bytes/hour upload and download
  • Timing — telemetry reporting interval, firmware check frequency
  • DNS queries — which domains the device resolves

Anomaly Detection

Once you have a baseline profile, deviations indicate compromise or misconfiguration:

  • New destinations — device contacting IPs or domains not in the profile
  • New protocols — device suddenly using SSH, Telnet, or SMB
  • Volume spikes — upload volume 10x normal (possible exfiltration via IoT device)
  • Scan behavior — IoT device sending SYN packets to internal hosts (compromised, used for lateral movement)
  • DNS anomalies — device querying domains outside its profile (C2 communication)

MQTT Analysis

// All MQTT traffic mqtt // MQTT CONNECT messages (new client connections) mqtt.msgtype == 1 // MQTT PUBLISH messages (data being sent) mqtt.msgtype == 3 // MQTT SUBSCRIBE messages (topics being monitored) mqtt.msgtype == 8 // MQTT without TLS (cleartext — security finding) mqtt && tcp.port == 1883
Unencrypted MQTT

MQTT on port 1883 transmits all messages — including credentials, sensor data, and commands — in cleartext. Many IoT deployments skip TLS due to device resource constraints. Any unencrypted MQTT traffic is a critical security finding that should be escalated.

Key Takeaways

  • IoT devices have predictable traffic profiles — baseline them to detect anomalies.
  • MQTT, CoAP, mDNS, and SSDP are the primary IoT protocols visible in Wireshark.
  • Unencrypted MQTT (port 1883) exposes all sensor data and commands — always a critical finding.
  • Compromised IoT devices show new destinations, new protocols, volume spikes, and scan behavior.
  • IoT devices are increasingly used as pivot points for lateral movement — monitor internal connections.
