802.11 Packet Capture

Wireless packet capture requires a fundamentally different approach from wired Ethernet capture. The wireless NIC must be placed into monitor mode to see raw 802.11 frames — management frames, control frames, and data frames — rather than the pre-processed Ethernet frames that normal Wi-Fi drivers present to the operating system. This module covers monitor mode configuration, radiotap header interpretation, and 802.11 frame type analysis in Wireshark.

Learning Objectives

  • Configure a wireless interface for monitor mode on Linux
  • Understand the three 802.11 frame types: management, control, and data
  • Interpret radiotap headers for signal strength, channel, and data rate
  • Filter captures by frame type, BSSID, and station address
  • Capture on specific channels and understand channel hopping

Setting Up Monitor Mode

# Method 1: Using airmon-ng (requires aircrack-ng suite) sudo airmon-ng start wlan0 # Creates wlan0mon interface in monitor mode # Method 2: Using iw (native Linux) sudo ip link set wlan0 down sudo iw wlan0 set type monitor sudo ip link set wlan0 up # Verify monitor mode is active iw wlan0 info # Should show "type monitor" # Set to a specific channel sudo iw wlan0 set channel 6
Hardware Requirements

Not all wireless NICs support monitor mode. USB adapters with Atheros (ath9k_htc) or Realtek (rtl8812au) chipsets are the most reliable for monitor mode capture. Intel integrated Wi-Fi chips have limited monitor mode support on some kernels.

Key Management Frame Filters

// Beacon frames (AP advertising its presence) wlan.fc.type_subtype == 0x0008 // Probe requests (clients searching for networks) wlan.fc.type_subtype == 0x0004 // Authentication frames wlan.fc.type_subtype == 0x000b // Deauthentication frames (potential attack indicator) wlan.fc.type_subtype == 0x000c // Filter by BSSID (specific access point) wlan.bssid == aa:bb:cc:dd:ee:ff

Radiotap Header Analysis

The radiotap header is prepended by the wireless driver and contains metadata about the captured frame. It is not part of the 802.11 frame itself.

FieldDescriptionAnalysis Use
Signal strength (dBm)Received signal powerProximity estimation, coverage mapping

Data ratePHY transmission rate (Mbps)Performance analysis, client capability detection
FrequencyCenter frequency in MHz2.4 GHz vs 5 GHz band identification

Key Takeaways

  • Monitor mode is required to see raw 802.11 frames — managed mode only shows Ethernet-encapsulated data frames.
  • 802.11 has three frame types: management (beacons, auth), control (ACK, RTS/CTS), and data (payload).
  • Radiotap headers provide signal strength, channel, and data rate metadata for each captured frame.
  • Filter by BSSID to isolate traffic from a specific access point in a multi-AP environment.
  • Channel selection matters — capture only on the target channel, or use channel hopping to survey all channels.
