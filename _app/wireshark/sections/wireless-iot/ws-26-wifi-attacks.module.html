WiFi Attack Signatures

Wireless networks face unique attack vectors that produce distinct packet signatures in monitor-mode captures. This lab teaches you to recognize deauthentication floods, PMKID capture attempts, evil twin access points, and WPA handshake attacks by their 802.11 frame patterns in Wireshark.

Learning Objectives

  • Detect deauthentication flood attacks by frame volume and source patterns
  • Identify PMKID capture attempts in EAPOL key frames
  • Recognize evil twin access points by duplicate SSIDs with different BSSIDs
  • Analyze WPA 4-way handshake captures for completeness
  • Build wireless-specific alerting filters

Deauthentication Attack Detection

A deauthentication attack floods a target client or AP with deauth frames, forcing disconnection. The attacker uses this to capture the WPA handshake when the client reconnects, or as a denial-of-service attack.

Indicators

  • High volume of deauth frames (type/subtype 0x000c) in a short time period
  • Deauth frames targeting a specific client (unicast) or all clients (broadcast)
  • Source MAC may be spoofed to appear as the legitimate AP
  • Reason code often set to 7 ("Class 3 frame received from nonassociated STA")
// Deauthentication frames wlan.fc.type_subtype == 0x000c // Deauth frames from a specific BSSID (possibly spoofed) wlan.fc.type_subtype == 0x000c && wlan.sa == aa:bb:cc:dd:ee:ff // High-rate deauth detection: >10 deauth frames in any 1-second window // Use Statistics -> IO Graph with Y: Packets, Interval: 1 sec, filter: wlan.fc.type_subtype == 0x000c // Disassociation frames (similar attack, different frame type) wlan.fc.type_subtype == 0x000a

PMKID Attack

The PMKID attack captures the Pairwise Master Key Identifier from the first EAPOL frame of the WPA handshake, without requiring a full 4-way handshake. This is faster than traditional handshake capture.

// EAPOL key frames (WPA handshake messages) eapol // First message of 4-way handshake (contains PMKID if supported) eapol.keydes.type == 2

Evil Twin Detection

An evil twin is a rogue access point that broadcasts the same SSID as a legitimate network but with a different BSSID (MAC address). Detection requires comparing beacon frames.

// Filter beacons for a specific SSID wlan.ssid == "Corporate-WiFi" && wlan.fc.type_subtype == 0x0008 // If this filter shows beacons from more than one BSSID, // one of them may be an evil twin. Verify by checking: // 1. Signal strength (evil twin may be unusually strong or weak) // 2. Supported rates and capabilities (may differ from legitimate AP) // 3. Channel (evil twin may be on a different channel)

WiFi Attack Challenge

Identify the wireless attack from the described capture observations.

1. Your monitor-mode capture shows 500 deauthentication frames in 10 seconds, all with source MAC matching the legitimate AP's BSSID and targeting a broadcast destination. Shortly after, you see EAPOL handshake frames from several clients reconnecting. What attack is occurring?
2. Beacon frame analysis for SSID "CompanyNet" reveals two different BSSIDs broadcasting the same SSID. One has signal strength -30 dBm (very strong) while the legitimate AP is typically -65 dBm. What is the likely situation?

Key Takeaways

  • Deauth floods produce hundreds of deauth frames per second from a spoofed BSSID — use IO Graphs to visualize the burst.
  • PMKID attacks target the first EAPOL key frame — filter on eapol to identify handshake capture attempts.
  • Evil twins broadcast the same SSID from a different BSSID — compare beacon sources, signal strength, and capabilities.
  • Legitimate APs rarely send broadcast deauthentication frames — any occurrence warrants investigation.
