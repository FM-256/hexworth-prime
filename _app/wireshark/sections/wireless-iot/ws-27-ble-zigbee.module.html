BLE & Zigbee Dissection

Bluetooth Low Energy (BLE) and Zigbee are the dominant short-range wireless protocols in IoT deployments. Wireshark can dissect both when captured with appropriate hardware (Ubertooth for BLE, TI CC2531 for Zigbee). This module covers the frame structures, advertising mechanisms, and security implications of each protocol.

Learning Objectives

  • Understand BLE advertising packets and connection procedures
  • Interpret Zigbee frame structure: MAC, NWK, and APS layers
  • Capture BLE traffic with Ubertooth and Zigbee with TI CC2531 sniffers
  • Identify unencrypted BLE characteristics that leak sensitive data
  • Detect Zigbee network key exposure and replay attacks

BLE Protocol Overview

BLE uses 40 channels in the 2.4 GHz band (2402-2480 MHz). Three channels (37, 38, 39) are dedicated to advertising; the remaining 37 are data channels used after connection establishment.

BLE Advertising Packets

// BLE advertising packets btle.advertising_header // Connectable undirected advertising (most common) btle.advertising_header.pdu_type == 0x00 // Scan response (device name, services) btle.advertising_header.pdu_type == 0x04 // Filter by BLE device address btle.advertising_address == aa:bb:cc:dd:ee:ff

BLE Security Concerns

  • Unencrypted characteristics — many BLE devices transmit sensor data, configuration, and even credentials without encryption
  • MAC address tracking — devices using static BLE addresses can be tracked across locations
  • Pairing vulnerabilities — Just Works pairing (no PIN) provides no protection against MITM
  • GATT profile exposure — service and characteristic UUIDs reveal device functionality

Zigbee Protocol Overview

Zigbee operates on IEEE 802.15.4 at the MAC layer, with the Zigbee NWK (Network) and APS (Application Support) layers above. It uses 16 channels in the 2.4 GHz band (channels 11-26).

Zigbee Frame Filters

// All Zigbee frames zbee_nwk // Zigbee beacon frames (network discovery) wpan.frame_type == 0 // Zigbee NWK commands (join, leave, route) zbee_nwk.frame_type == 1 // Zigbee APS layer (application data) zbee_aps // Transport key (network key being distributed — security critical) zbee_aps.cmd.id == 5
Zigbee Key Sniffing

When a new device joins a Zigbee network, the network key is transmitted over the air encrypted with a well-known "Trust Center Link Key" (often the default ZigBee Alliance key). If you capture the join process, you can decrypt all subsequent Zigbee traffic. This is a fundamental design weakness in many Zigbee deployments.

Key Takeaways

  • BLE advertising on channels 37-39 reveals device presence and capabilities — even without establishing a connection.
  • Many BLE devices transmit sensitive data without encryption over GATT characteristics.
  • Zigbee network key distribution during device joining is a critical security weakness.
  • Specialized hardware is required: Ubertooth for BLE, TI CC2531 for Zigbee capture.
  • Wireshark can dissect both BLE and Zigbee frames when captured with supported sniffers.
