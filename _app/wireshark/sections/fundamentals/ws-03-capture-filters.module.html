Capture Filters (BPF)

Capture filters determine which packets make it into the capture file in the first place. Unlike display filters, which merely hide traffic after capture, a capture filter permanently discards everything that does not match. This module covers Berkeley Packet Filter (BPF) syntax — the language shared by Wireshark, tcpdump, and every libpcap-based tool.

Learning Objectives

  • Explain the difference between capture filters and display filters in both function and syntax
  • Write BPF expressions using host, net, port, proto, and directional primitives
  • Combine primitives with logical operators (and, or, not) to build precise filters
  • Use byte-offset expressions for advanced protocol matching
  • Apply capture filters via Wireshark GUI and the command line
  • Avoid common capture filter mistakes that cause silent data loss

Why Capture Filters Matter

On a busy network, a full capture can generate gigabytes per hour. Capture filters solve three problems simultaneously:

  • Disk space — only the traffic you need lands on disk, extending recording windows from minutes to days
  • Performance — the kernel discards non-matching packets before they cross the user-kernel boundary, reducing CPU overhead and preventing packet drops
  • Scope control — in forensic investigations, limiting capture scope to a target host prevents inadvertent collection of privileged communications
Critical Difference

Capture filters use BPF syntax (e.g., host 10.0.0.5). Display filters use Wireshark display filter syntax (e.g., ip.addr == 10.0.0.5). These are completely different languages. A display filter expression pasted into the capture filter field will silently fail or be rejected.

BPF Primitive Reference

Every BPF expression is built from primitives. A primitive consists of an optional qualifier followed by a value. The three qualifier types are:

  • Type — what the value represents: host, net, port, portrange
  • Direction — which address to match: src, dst, src or dst, src and dst
  • Protocol — which protocol layer: ether, ip, ip6, arp, tcp, udp, icmp
Primitive BPF Syntax Description
host host 192.168.1.50 Match packets where the IP address appears as source or destination
src host src host 10.0.0.1 Match only when the IP is the source address
dst host dst host 10.0.0.1 Match only when the IP is the destination address
net net 10.0.0.0/24 Match any IP within the specified subnet
port port 443 Match TCP or UDP traffic on the specified port (either direction)
dst port dst port 80 Match only when the destination port equals 80
portrange portrange 8000-8080 Match any port within the specified inclusive range
proto icmp Match a specific IP protocol (icmp, tcp, udp, etc.)
ether host ether host aa:bb:cc:dd:ee:ff Match by MAC address at the Ethernet layer
broadcast ether broadcast Match Ethernet broadcast frames (dst ff:ff:ff:ff:ff:ff)
vlan vlan 100 Match 802.1Q tagged frames on VLAN 100

Logical Operators

Primitives combine with standard boolean logic. BPF supports both symbolic and keyword forms:

Operation Keyword Symbol Example
AND and && host 10.0.0.5 and port 443
OR or || port 80 or port 443
NOT not ! not arp
Grouping ( ) (port 80 or port 443) and host 10.0.0.5
Operator Precedence

not binds tightest, then and, then or. When in doubt, use parentheses. The expression not host 10.0.0.1 and port 80 means "not from 10.0.0.1 AND on port 80" — it does not mean "not (host 10.0.0.1 and port 80)". Use explicit parentheses to avoid ambiguity.

Common Capture Filter Patterns

These patterns cover the scenarios you will encounter most frequently in security analysis, network troubleshooting, and forensic capture.

Isolate a Single Host

host 192.168.1.100

Captures all traffic to and from the target host. This is the most common starting point for incident response — narrow focus to the compromised machine.

Capture Only Web Traffic

tcp port 80 or tcp port 443

Restricts capture to HTTP and HTTPS. Useful when investigating web-based attacks, phishing callbacks, or web application performance.

Exclude Noisy Protocols

not arp and not icmp and not port 53

Removes ARP, ICMP, and DNS from the capture. On a busy LAN, these three protocols can account for 40% or more of all traffic.

Capture a Subnet

net 10.10.0.0/16

Matches all traffic where either source or destination falls within the /16 subnet. Essential for monitoring an entire VLAN or department segment.

Capture Traffic Between Two Hosts

host 10.0.0.5 and host 10.0.0.10

Captures only the conversation between two specific endpoints. Both addresses must appear in the same packet (one as source, one as destination).

Capture Non-Standard Ports

tcp and not portrange 1-1024

Captures only TCP traffic on ephemeral and high ports. Useful for spotting C2 channels that avoid well-known ports.

Capture Only SYN Packets (Connection Initiations)

tcp[tcpflags] & tcp-syn != 0 and tcp[tcpflags] & tcp-ack == 0

Matches only the initial SYN of TCP handshakes — no SYN-ACKs, no data packets. This is a lightweight way to log every new connection attempt on a link without storing full payloads.

Byte-Offset Expressions

BPF allows you to match on arbitrary byte positions in a packet using bracket notation. This is how you filter on fields that have no dedicated BPF keyword.

Syntax

proto[offset:length]

Where proto is the protocol layer (ip, tcp, udp, icmp, ether), offset is the byte position from the start of that header, and length is how many bytes to read (1, 2, or 4). Omit length for a single byte.

Examples

Expression Matches Explanation
ip[8] < 5 Low TTL packets Byte 8 of the IP header is the TTL field. Values below 5 suggest traceroute probes or misconfigured routers.
tcp[13] & 2 != 0 TCP SYN flag set Byte 13 of the TCP header contains the flags. Bit 1 (value 2) is the SYN flag.
tcp[13] == 18 TCP SYN-ACK only Value 18 = SYN (2) + ACK (16). Matches only SYN-ACK responses.
icmp[0] == 8 ICMP Echo Request Byte 0 of the ICMP header is the Type field. Type 8 is Echo Request (ping).
ip[6:2] & 0x1fff != 0 IP fragments Bytes 6-7 contain the fragment offset. Non-zero means this is a fragment (not the first).
ether[12:2] == 0x0806 ARP frames Bytes 12-13 of the Ethernet frame hold the EtherType. 0x0806 is ARP.
TCP Flag Bitmask Reference

TCP flags byte (offset 13): FIN=1, SYN=2, RST=4, PSH=8, ACK=16, URG=32, ECE=64, CWR=128. Combine values for multi-flag matches: SYN+ACK = 18, FIN+ACK = 17, RST+ACK = 20.

Applying Capture Filters

In Wireshark GUI

  1. Go to Capture › Options (or press Ctrl+K)
  2. Select the target interface in the interface list
  3. Enter the BPF expression in the Capture Filter field at the bottom
  4. The field turns green if the syntax is valid, red if invalid
  5. Click Start to begin capturing with the filter active

With dumpcap (Command Line)

dumpcap -i eth0 -f "host 10.0.0.5 and port 443" -w capture.pcapng

The -f flag accepts BPF syntax. This is how Wireshark internally invokes capture — dumpcap runs with elevated privileges while the GUI runs as your regular user.

With tcpdump

tcpdump -i eth0 -w capture.pcap "host 10.0.0.5 and port 443"

tcpdump uses identical BPF syntax. Filters written for tcpdump work in Wireshark and vice versa.

Common Mistakes

Mistake 1: Using Display Filter Syntax

Writing ip.addr == 10.0.0.5 in the capture filter field. BPF does not understand Wireshark display filter syntax. Use host 10.0.0.5 instead.

Mistake 2: Overly Narrow Filters

Setting dst port 443 only captures outbound HTTPS — you miss the server responses. Use port 443 to capture both directions, or explicitly write src port 443 or dst port 443.

Mistake 3: Forgetting DNS/DHCP

Filtering on host 10.0.0.5 will not capture the DNS query that resolved the target hostname. If you need DNS resolution context, add or port 53.

Mistake 4: No Filter on Production Taps

Running a full capture on a 10 Gbps link will drop packets within seconds. Always apply a capture filter on high-speed links, even if you think you want everything. Consider ring buffers with -b filesize:100000 (100 MB files) as a safety net.

Key Takeaways

  • Capture filters use BPF syntax — a completely different language from Wireshark display filters. They cannot be interchanged.
  • BPF primitives are built from type (host/net/port), direction (src/dst), and protocol (tcp/udp/icmp) qualifiers.
  • Combine primitives with and, or, not, and parentheses. Use parentheses liberally to avoid precedence surprises.
  • Byte-offset expressions (tcp[13], ip[8]) allow matching on any header field, even those without BPF keywords.
  • Capture filters discard non-matching packets permanently — there is no undo. When in doubt, capture more broadly and filter at display time.
  • The same BPF syntax works in Wireshark, dumpcap, tcpdump, tshark, and any libpcap-based tool.
