Profiles & Preferences

A Wireshark profile is a complete configuration snapshot — column layouts, coloring rules, display filters, name resolution settings, protocol preferences, and capture options bundled into one switchable unit. Security analysts maintain separate profiles for different investigation types. This module covers profile creation, the preference system, coloring rules, and column customization so you can build purpose-built analysis workspaces.

Learning Objectives

  • Create, clone, and switch between Wireshark configuration profiles
  • Customize the Packet List column layout for security analysis
  • Write and prioritize coloring rules for rapid visual triage
  • Configure key preferences: name resolution, protocol settings, and capture defaults
  • Export and import profiles for team standardization
  • Build three purpose-built profiles for security, performance, and forensics

What a Profile Contains

Each profile is a directory inside Wireshark's personal configuration folder. The directory contains configuration files that control every aspect of the interface and dissector behavior.

File Controls Key Settings
preferences Global preferences Name resolution, GUI layout, capture buffer size, protocol-specific settings
recent Recent state Last opened files, pane sizes, column widths, time display format
colorfilters Coloring rules Display filter to background/foreground color mappings
dfilters Saved display filters Filter bookmark library
decode_as_entries Decode-As rules Manual protocol assignment overrides (e.g., port 8443 as TLS)
disabled_protos Disabled protocols Protocols you have turned off to speed up dissection

Profile Storage Locations

# Linux ~/.config/wireshark/profiles/<profile-name>/ # macOS ~/.config/wireshark/profiles/<profile-name>/ # Windows %APPDATA%\Wireshark\profiles\<profile-name>\

Creating and Managing Profiles

Open the Profile Manager

Go to Edit › Configuration Profiles or right-click the profile name in the status bar and select Manage Profiles. Keyboard shortcut: Ctrl+Shift+A.

Create a New Profile

Click the + button. Give the profile a descriptive name like "Security-Analysis" or "Performance-Triage". The new profile starts as a copy of the Default profile.

Clone an Existing Profile

Select an existing profile and click Copy. This duplicates all settings — useful when you want a variant of an existing configuration. Rename the clone to distinguish it.

Switch Profiles

Click the profile name in the bottom-left of the status bar. A dropdown lists all available profiles. Switching is instant — columns, colors, and filters update immediately.

Export for Team Use

Compress the profile directory into a zip file. Share it with your team. They extract it into their own profiles directory and it appears in the profile manager.

Best Practice

Never modify the Default profile. Create purpose-built profiles and leave Default untouched as a fallback. If you break a profile's settings, you can always switch back to Default and start fresh.

Column Layout Customization

The Packet List columns determine what information you see at a glance. Different analysis tasks demand different column sets. A security analyst needs ports and delta time; a performance engineer needs window size and RTT.

Adding a Column

  1. Right-click any column header in the Packet List pane
  2. Select Column Preferences
  3. Click the + button to add a new column
  4. Set the Title (display name) and Fields (the Wireshark field name)
  5. Drag to reorder, or use the up/down arrows

Quick Method: Apply as Column

Right-click any field in the Packet Details pane and select Apply as Column. The field immediately appears as a new column. This is the fastest way to add custom columns during live analysis.

Coloring Rules

Coloring rules assign background and foreground colors to packets based on display filter expressions. They are evaluated in order from top to bottom — the first matching rule determines the color. Place the most specific rules at the top and broad protocol rules at the bottom.

Managing Coloring Rules

  1. Go to View › Coloring Rules
  2. Click + to add a new rule
  3. Enter a Name, a Filter (any valid display filter), and choose Foreground and Background colors
  4. Drag rules to reorder — higher rules take priority
  5. Use the checkbox to temporarily disable a rule without deleting it

Security-Focused Coloring Rules

Priority Rule Name Filter Color Scheme
1 (top) Checksum Errors tcp.checksum.status == "Bad" || ip.checksum.status == "Bad" Red background / white text
2 TCP RST tcp.flags.rst == 1 Dark red background / light text
3 Retransmissions tcp.analysis.retransmission Yellow background / dark text
4 SYN Only (Scan?) tcp.flags.syn == 1 && tcp.flags.ack == 0 Orange background / dark text
5 DNS dns Cyan background / dark text
6 HTTP http Green background / dark text
7 TLS tls Blue background / dark text
8 (bottom) ARP arp Purple background / dark text
Rule Order Matters

If you place the broad tcp coloring rule above the specific tcp.flags.rst rule, RST packets will get the generic TCP color instead of the alert red. Always order from most specific (top) to most general (bottom).

Three Profiles Every Analyst Should Build

1. Security Analysis Profile

Optimized for threat hunting and incident response.

  • Columns: No., Time (UTC), Delta, Source, Src Port, Destination, Dst Port, Protocol, Info
  • Colors: RST=red, retransmission=yellow, SYN-only=orange, DNS=cyan, HTTP=green
  • Preferences: Name resolution disabled, UTC timestamps, TCP reassembly enabled
  • Bookmarks: Cleartext creds, DNS tunneling, port scans, C2 beaconing

2. Performance Triage Profile

Optimized for network performance troubleshooting.

  • Columns: No., Time, Delta, Source, Destination, Protocol, TCP Window, ACK RTT, Length, Info
  • Colors: Zero window=red, retransmission=yellow, duplicate ACK=orange, out-of-order=purple
  • Preferences: Relative sequence numbers enabled, TCP calculate timestamps enabled
  • Bookmarks: All TCP issues, high RTT, zero window, slow start

3. Forensic Evidence Profile

Optimized for evidence collection and chain-of-custody documentation.

  • Columns: No., Absolute Time (UTC), Source, Destination, Protocol, Length, Info
  • Colors: Minimal — avoid subjective visual bias in evidence presentation
  • Preferences: Name resolution fully disabled, no GeoIP, no decode-as overrides
  • Bookmarks: Frame time range, specific IP conversations, protocol isolation

Key Takeaways

  • Profiles bundle all Wireshark settings — columns, colors, filters, preferences — into switchable configurations.
  • Never modify the Default profile. Build purpose-specific profiles for security, performance, and forensics.
  • Column layout is the single biggest productivity lever — add delta time, ports, and protocol-specific fields for your analysis type.
  • Coloring rules are evaluated top-to-bottom. Place specific rules (RST, retransmission) above general protocol rules (TCP, DNS).
  • Disable name resolution in security profiles to prevent DNS leakage and improve performance.
  • Profiles are portable directories — zip and share them for team standardization.
