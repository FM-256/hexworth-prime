Filter Expression Builder

Wireshark includes a GUI-driven Filter Expression Builder that constructs display filters without requiring you to memorize field names. This lab module teaches you to use the builder efficiently, leverage autocompletion, manage filter bookmarks, and then challenges you to write filters for real-world investigation scenarios.

Learning Objectives

  • Navigate the Filter Expression dialog to browse available protocol fields
  • Use autocompletion in the filter bar to discover field names quickly
  • Save and organize filter bookmarks for rapid reuse
  • Construct multi-clause filters combining protocol, address, and behavioral criteria
  • Build filters for five common investigation scenarios from scratch

The Filter Expression Dialog

Access the dialog via Analyze › Display Filter Expression or by clicking the Expression... button next to the filter bar (if enabled in your profile). The dialog presents three panels:

Left Panel: Field Tree

A hierarchical tree of every protocol Wireshark knows how to dissect. Expand a protocol to see its fields. Each field shows its internal name (e.g., tcp.srcport) and a human-readable description.

Middle Panel: Relation

After selecting a field, choose the comparison operator: ==, !=, >, <, >=, <=, contains, matches, or the special is present (field existence).

Right Panel: Value

Enter the comparison value. For enumerated fields (like TCP flags or DNS record types), the dialog provides a dropdown of valid values with their human-readable names.

Pro Tip

The Expression dialog is useful for learning field names, but experienced analysts rarely use it. Once you know the field name, typing directly into the filter bar with autocompletion is faster. Use the dialog to discover fields you have never used before, then switch to direct typing.

Filter Bar Autocompletion

Wireshark's filter bar provides real-time autocompletion as you type. This is the fastest way to build filters once you know the general field name pattern.

How It Works

  1. Click the filter bar or press Ctrl+/ to focus it
  2. Start typing a protocol or field name (e.g., tcp.)
  3. A dropdown appears showing all matching fields
  4. Use Up/Down arrows to navigate the suggestions
  5. Press Tab or Enter to accept a suggestion
  6. Continue typing the operator and value

Naming Conventions

Wireshark field names follow a consistent dot-notation pattern. Learning these patterns lets you guess field names accurately:

Pattern Examples Convention
proto.field tcp.srcport, ip.ttl, dns.qry.name Protocol name, then the field in that protocol
proto.field.subfield tcp.flags.syn, tls.handshake.type Nested fields within a parent field
proto.request.* http.request.method, http.request.uri Request-specific fields
proto.response.* http.response.code, dns.resp.type Response-specific fields
proto.analysis.* tcp.analysis.retransmission, tcp.analysis.zero_window Wireshark-calculated analysis fields (not in the packet itself)

Managing Filter Bookmarks

Filter bookmarks let you save commonly used expressions for one-click reuse. Bookmarks persist across Wireshark sessions and are stored in your profile's dfilters file.

Creating a Bookmark

  1. Type a filter expression in the filter bar
  2. Click the bookmark icon (blue ribbon) at the left end of the filter bar
  3. Select Save this filter
  4. Give it a descriptive name (e.g., "C2 Beacon Check")

Organizing Bookmarks

Go to Analyze › Display Filters to see all saved bookmarks. From this dialog you can:

  • Rename bookmarks with descriptive labels
  • Reorder them by priority (most-used at the top)
  • Delete outdated filters
  • Import/export the dfilters file to share bookmarks across machines

Lab Exercises: Build the Filter

For each scenario, construct the display filter that would isolate the relevant traffic. Type your answer and check it.

Scenario 1: DNS Exfiltration Hunt
A host at 10.10.5.22 is suspected of using DNS tunneling to exfiltrate data. You need to find all DNS queries from this host where the query name is unusually long (more than 40 characters). Write a display filter.
Scenario 2: Failed Login Detection
Your web application at 192.168.1.100 is receiving brute-force login attempts. You need to see all HTTP POST requests to the login page (URI contains "/login") that received a 401 Unauthorized response. Write a filter that shows the HTTP responses with status code 401 going back to any source.
Scenario 3: TLS Version Audit
You need to identify any connections still using TLS 1.0 or TLS 1.1 (which are deprecated and insecure). TLS 1.0 has record version 0x0301 and TLS 1.1 has record version 0x0302. Write a filter to find Client Hello messages using these versions.
Scenario 4: Port Scan Detection
You suspect host 10.0.0.99 is running a SYN scan against your network. A SYN scan sends TCP SYN packets without completing the handshake. Write a filter to find all SYN packets (SYN flag set, ACK flag NOT set) where the source is 10.0.0.99.
Scenario 5: Lateral Movement via SMB
An attacker has compromised host 10.0.0.50 and is moving laterally via SMB (port 445). You need to see all SMB traffic originating from this host to any other internal host (10.0.0.0/24 subnet). Write the filter.

Key Takeaways

  • The Filter Expression dialog browses all available fields by protocol — useful for discovering field names you have never used.
  • Autocompletion in the filter bar is faster than the dialog once you know the naming pattern (protocol.field.subfield).
  • Filter bookmarks save time during investigations — pre-build a library of security, performance, and forensics filters.
  • Bookmarks are profile-specific and stored in the dfilters file — they can be shared across analyst workstations.
  • Practice building filters from scenario descriptions — in a real incident you will not have a cheat sheet.
