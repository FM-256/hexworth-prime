SG-35
Authorized Use Only — FCC and CFAA Warning

Transmitting deauthentication frames disrupts network service for all clients on the target AP. This constitutes unauthorized interference with a radio communication service under 47 U.S.C. § 333 (Communications Act) and may additionally violate 18 U.S.C. § 1030 (CFAA). It is illegal to operate this device against any network you do not own or have explicit written authorization to test. Use only in isolated lab environments, on your own equipment, with no live clients affected.

SG-35 — Red Team Hardware

WiFi Deauther & Scanner

Build an 802.11 deauthentication and scanning platform using an $8 ESP32 development board. Flash ESP32 Marauder firmware for AP scanning, client enumeration, packet monitoring, and deauth frame injection.

Intermediate ~$10 USD 2–3 Hours ESP32 / Arduino IDE
Section 1

▶ How It Works

The 802.11 standard defines a deauthentication frame as a management frame sent by an AP to inform a client that it has been disconnected. In 802.11a/b/g/n networks without Protected Management Frames (PMF / 802.11w), these frames are unauthenticated — any device can send one with a spoofed source MAC address. This is a design flaw in the original 802.11 specification, not a software vulnerability.

The ESP32 microcontroller (Espressif Systems, dual-core Xtensa LX6, integrated 802.11 b/g/n WiFi) provides raw frame injection capability through its WiFi driver when running custom firmware. ESP32 Marauder (by Justin Ruble) is the community standard for this purpose — it provides a serial command interface for scanning, deauth, beacon spam, probe request capture, and packet monitoring.

Deauth Mechanism
IEEE 802.11 Frame Type 0x0C
Management frame, subtype 12 (0x0C). Sent by ESP32 with spoofed source MAC = target AP BSSID. No encryption required — management frames are plaintext in WPA2.
Effective Range
~30m Indoors / 100m Open
ESP32 onboard antenna provides approximately the same range as a standard consumer router. External antenna connector (u.FL) on some ESP32 variants extends this further.
Target Firmware
ESP32 Marauder v1.x
Open-source firmware by Justin Ruble. Serial command interface over USB. Supports OLED display output. Actively maintained — check GitHub for latest release.

▶ Wiring — OLED Display (Optional)

The SSD1306 OLED communicates over I2C. The ESP32 has dedicated I2C pins: GPIO21 (SDA) and GPIO22 (SCL). The display runs on 3.3V — do not connect to 5V on this module.

Section 4

▶ Flashing ESP32 Marauder Firmware

There are two methods to flash the firmware: using the Arduino IDE (method A, recommended for students — you see and can modify the source code) or using esptool.py with a pre-compiled binary (method B, faster).

Method A — Arduino IDE 2.x:

Shell — Arduino IDE Setup for ESP32 
# Step 1: Install Arduino IDE 2.x from arduino.cc/en/software

# Step 2: Add ESP32 board support
# In Arduino IDE: File > Preferences > Additional Boards Manager URLs
# Add: https://raw.githubusercontent.com/espressif/arduino-esp32/gh-pages/package_esp32_index.json
# Then: Tools > Board > Boards Manager > search "esp32" > Install "esp32 by Espressif Systems" v2.x

# Step 3: Clone ESP32 Marauder source
git clone https://github.com/justcallmekoko/ESP32Marauder.git
cd ESP32Marauder

# Step 4: Install required Arduino libraries via Sketch > Include Library > Manage Libraries:
#   - TFT_eSPI (by Bodmer) v2.x          — display driver
#   - lv_arduino (LittlevGL) v3.x        — UI framework (if using TFT variant)
#   - NimBLE-Arduino v1.x                — Bluetooth scanning
#   - ArduinoJson v6.x                   — config parsing
#   - AsyncTCP (by me-no-dev)            — async networking
#   - ESPAsyncWebServer (by me-no-dev)   — web interface

# Step 5: Board selection in Arduino IDE:
#   Tools > Board > ESP32 Arduino > ESP32 Dev Module
#   Tools > Partition Scheme > Minimal SPIFFS (Large APPS with OTA)
#   Tools > Upload Speed > 921600
#   Tools > Flash Size > 4MB (or match your board)

# Step 6: Open esp32_marauder.ino and click Upload (Ctrl+U)

Method B — esptool.py with pre-compiled binary (faster):

Shell — Flash Pre-compiled Binary via esptool.py
# Install esptool pip install esptool # Download pre-compiled Marauder binary from GitHub Releases: # https://github.com/justcallmekoko/ESP32Marauder/releases # Download: esp32_marauder_vX.X.X_[your_board].bin # Find your ESP32 serial port ls /dev/tty.usbserial* # macOS (CP2102 chip) ls /dev/ttyUSB* # Linux (CP2102 chip) ls /dev/tty.SLAB* # macOS (CH340 chip) # Erase existing flash (recommended before first flash) esptool.py --chip esp32 --port /dev/ttyUSB0 --baud 921600 erase_flash # Flash the Marauder binary esptool.py --chip esp32 \ --port /dev/ttyUSB0 \ --baud 921600 \ --before default_reset \ --after hard_reset \ write_flash -z \ --flash_mode dio \ --flash_freq 80m \ --flash_size detect \ 0x1000 esp32_marauder_v1.1.0_esp32_dev_board.bin # Expected output on success: # Hash of data verified. # Leaving... # Hard resetting via RTS pin...
Section 5

▶ Using ESP32 Marauder — Serial Commands

Connect to the ESP32 at 115200 baud via any serial terminal. Marauder presents a command prompt. All commands are entered as plain text. The OLED display (if wired) mirrors the serial output.

Shell — Connect to Marauder Serial Interface
# macOS / Linux screen /dev/ttyUSB0 115200 # or minicom -b 115200 -D /dev/ttyUSB0 # Windows: use PuTTY — Serial, COM port from Device Manager, 115200 baud
Marauder Serial Commands — Reference
### SCANNING ### scanap # Scan for all nearby access points (APs) # Output: BSSID, SSID, Channel, RSSI, Encryption scansta # Scan for associated stations (clients) # Requires: run scanap first to build AP list list ap # List scanned APs with index numbers list sta # List scanned stations with index numbers ### TARGET SELECTION ### select ap 0 # Select AP at index 0 for attack select ap 0,1,2 # Select multiple APs select sta 0 # Select specific station (client) ### DEAUTHENTICATION ### deauth # Send deauth frames to selected AP targets # Affects all clients associated with that AP # WARNING: disrupts service for all users on target AP ### PACKET CAPTURE ### sniff probe # Capture probe request frames # Shows: MAC address, SSID probed, RSSI sniff beacon # Capture beacon frames from nearby APs sniff deauth # Monitor for deauth frames (detect attacks) sniff pwnagotchi # Capture Pwnagotchi peer frames ### BEACON SPAM ### beaconlist # Broadcast fake AP beacons (random SSIDs) # Educational: demonstrates how rogue AP lists work ### UTILITY ### stopscan # Stop all active scanning clearap # Clear AP list from memory reboot # Reboot the ESP32 help # Print all available commands

Section 6

▶ Custom Arduino Sketch — Basic WiFi Scanner

For students who want to understand the underlying WiFi API without loading full Marauder firmware, this minimal sketch demonstrates AP scanning and displays results over Serial. Flash it via Arduino IDE with "ESP32 Dev Module" board selected.

Arduino C++ — wifi_scanner.ino
#include <WiFi.h> void setup() { Serial.begin(115200); delay(500); Serial.println("\n=== ESP32 WiFi Scanner ==="); // Set WiFi to station mode, disconnect from any AP WiFi.mode(WIFI_STA); WiFi.disconnect(); delay(100); } void loop() { Serial.println("\n[SCAN] Scanning for access points..."); // Synchronous scan: blocks until complete // Parameters: show_hidden=true, passive=false, max_ms_per_chan=300 int n = WiFi.scanNetworks(false, true); if (n == 0) { Serial.println("[SCAN] No networks found."); } else { Serial.printf("[SCAN] Found %d networks:\n\n", n); Serial.printf("%-4s %-18s %-32s %-5s %-5s %s\n", "Idx", "BSSID", "SSID", "Ch", "RSSI", "Encryption"); Serial.println("───────────────────────────────────────────────────────────────"); for (int i = 0; i < n; ++i) { String enc; switch (WiFi.encryptionType(i)) { case WIFI_AUTH_OPEN: enc = "OPEN"; break; case WIFI_AUTH_WEP: enc = "WEP"; break; case WIFI_AUTH_WPA_PSK: enc = "WPA"; break; case WIFI_AUTH_WPA2_PSK: enc = "WPA2"; break; case WIFI_AUTH_WPA_WPA2_PSK: enc = "WPA/2"; break; case WIFI_AUTH_WPA3_PSK: enc = "WPA3"; break; default: enc = "UNKNOWN"; break; } Serial.printf("%-4d %-18s %-32s %-5d %-5d %s\n", i, WiFi.BSSIDstr(i).c_str(), WiFi.SSID(i).c_str(), WiFi.channel(i), WiFi.RSSI(i), enc.c_str() ); } } // Free scan results from memory WiFi.scanDelete(); Serial.println("\n[WAIT] Next scan in 10 seconds..."); delay(10000); }

▶ Testing and Verification

Test Only on Your Own Network

The scanning sketch is passive and safe to run anywhere. The Marauder deauth command must only be used against networks you own or have explicit authorization to test. Even a brief deauth test against a neighbor's or employer's network is a federal crime. For lab testing, use a dedicated router with no live clients connected.

Section 8

▶ How to Defend Against This — Blue Team Perspective

802.11w — Protected Management Frames (PMF)

802.11w, ratified in 2009 and mandatory in WPA3, adds cryptographic protection to management frames including deauthentication and disassociation frames. APs and clients that both support PMF will reject unauthenticated deauth frames — the attack does not work. Enable PMF in your AP configuration: on most consumer routers it appears as "Protected Management Frames" set to "Required" rather than "Optional". All devices running WPA3 support PMF by default.

WPA3 — Simultaneous Authentication of Equals (SAE)

WPA3 replaces the WPA2 Pre-Shared Key handshake with SAE (also known as Dragonfly), which provides forward secrecy and resistance to offline dictionary attacks. WPA3 networks are not vulnerable to deauth-triggered PMKID capture attacks that affect WPA2. Upgrading infrastructure to WPA3 (or WPA2/WPA3 transition mode) eliminates several attack vectors simultaneously.

Wireless Intrusion Detection Systems (WIDS)

Enterprise WIDS products (Cisco CleanAir, Aruba RFProtect, Kismet with WIDS rules) passively monitor the 802.11 management frame stream and alert on deauthentication flood patterns. Signatures include: high deauth frame rate, deauth frames with spoofed source MACs not matching known AP BSSIDs, deauth reason codes 6 or 7 (unspecified reasons commonly used by attack tools). Alert thresholds are typically 10+ deauth frames per second from a single source.

Channel Monitoring and Rogue AP Detection

The beacon spam and probe capture features of Marauder enable rogue AP attacks. Defenses include: 802.1X (RADIUS authentication) so clients only associate with authorized APs, dedicated WIDS sensors that detect SSIDs matching your organization's networks but broadcasting from unknown BSSIDs, and client-side certificate pinning (EAP-TLS) that prevents connection to rogue APs even if the SSID matches.
