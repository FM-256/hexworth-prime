SG-37
Authorized Use Only — Network Interception Warning

Capturing network traffic on a network you do not own or have explicit written authorization to monitor is a federal offense under 18 U.S.C. § 2511 (Wiretap Act) and 18 U.S.C. § 1030 (CFAA). This includes corporate networks, ISP infrastructure, and any shared network segment. Analyze traffic only on networks you control, in isolated lab environments, or under documented Rules of Engagement for an authorized penetration test. All RFC 5737 addresses (192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24) are used in examples to avoid confusion with real addresses.

SG-37 — Red Team Hardware

Network Packet Sniffer

Build a hardware Ethernet packet sniffer using a $12 Raspberry Pi Pico W and a W5500 Ethernet module. Capture, parse, and log network frames to flash storage using MicroPython with the Wiznet library.

Advanced ~$14 USD 4–6 Hours MicroPython 1.23
Section 1

▶ How It Works

Ethernet frames flow across a network segment as electrical signals. Any device with an Ethernet interface can, in principle, read every frame on the segment — not just frames addressed to it. This is promiscuous mode operation, and it is the basis for all network packet sniffers including Wireshark, tcpdump, and Zeek.

The W5500 is a hardwired TCP/IP offload engine from WIZnet that interfaces to microcontrollers via SPI. Critically, the W5500 supports raw socket mode — it can pass raw Ethernet frames directly to the host microcontroller without any TCP/IP stack processing. This allows the Raspberry Pi Pico W to receive, inspect, and log every frame the W5500 receives on the wire, including frames not addressed to the Pico's own MAC address.

The device is wired inline between a network device (e.g., a workstation) and a switch. The W5500's second Ethernet port forwards traffic to the switch while the Pico logs everything it sees. In a tap configuration, the Pico only observes — it does not modify or block traffic, making it nearly undetectable at the network layer.

Interface
WIZnet W5500
Hardwired TCP/IP + raw socket engine. 10/100 Mbps. SPI interface at up to 80 MHz. Datasheet at wiznet.io. Supported by MicroPython Wiznet driver.
Capture Rate
~10 Mbps Effective
SPI throughput and Pico's flash write speed limit sustained capture to ~10 Mbps. Suitable for DNS, HTTP, credential sniffing, and protocol analysis on low-traffic segments.
Storage
2MB Flash (Pico W)
Log decoded packet metadata rather than raw bytes to maximize storage. Metadata (src/dst IP, protocol, port, timestamp, first 64 bytes of payload) stores ~100 bytes per packet.

▶ Wiring Diagram — SPI Pin Connections

The W5500 module connects to the Pico W via SPI0 on the standard hardware SPI pins. Use short wires (under 20cm) for SPI connections — longer runs cause signal integrity issues at higher speeds. Connect at 10 MHz initially and increase if the link is stable.

For a full inline tap, a network switch with port mirroring is simpler than dual-NIC forwarding at Pico speeds. W5500 Module Variants

Two common W5500 module types: the WIZnet W5500-EVB (evaluation board with onboard 3.3V regulator, two RJ45 ports, USB) and the generic breakout board (single RJ45, minimal components, ~$3). For this build the generic breakout is sufficient. Confirm your module operates at 3.3V logic — some older modules require 5V and need a level shifter between the Pico and the SPI pins.

▶ MicroPython Setup and W5500 Driver

This build uses MicroPython 1.23 (rather than CircuitPython) because MicroPython provides the most mature W5500 driver and a more complete socket API for raw frame access. The W5500 driver is built into MicroPython for the RP2040 — no external library installation required.

▶ Complete MicroPython Code

MicroPython — main.py (Packet Sniffer)
import network import socket import struct import time import machine from machine import Pin, SPI # ─── Hardware Configuration ─────────────────────────────────────────────────── SPI_ID = 0 SCK_PIN = 18 # GP18 → W5500 SCLK MOSI_PIN = 19 # GP19 → W5500 MOSI MISO_PIN = 16 # GP16 → W5500 MISO CS_PIN = 17 # GP17 → W5500 CS RST_PIN = 20 # GP20 → W5500 RST LOG_FILE = "/packets.log" LOG_FLUSH_EVERY = 10 # Flush to flash every N packets CAPTURE_LIMIT = 500 # Stop after this many packets (0 = unlimited) # ─── Initialize SPI and W5500 ───────────────────────────────────────────────── spi = SPI(SPI_ID, baudrate=10_000_000, polarity=0, phase=0, sck=Pin(SCK_PIN), mosi=Pin(MOSI_PIN), miso=Pin(MISO_PIN)) cs = Pin(CS_PIN, Pin.OUT, value=1) rst = Pin(RST_PIN, Pin.OUT, value=1) # Hardware reset: pull RST low for 100ms, then release rst.value(0) time.sleep_ms(100) rst.value(1) time.sleep_ms(200) # Initialize WIZNET5K driver (uses SPI0) nic = network.WIZNET5K(spi, cs, rst) nic.active(True) # Configure a static IP on the monitoring interface # Use an address in the target subnet to avoid ARP anomalies # All addresses below use RFC 5737 documentation ranges nic.ifconfig(('192.0.2.200', '255.255.255.0', '192.0.2.1', '8.8.8.8')) print(f"[INIT] W5500 online. MAC: {':'.join(f'{b:02x}' for b in nic.config('mac'))}") print(f"[INIT] IP: {nic.ifconfig()[0]}") # ─── Protocol Parsers ───────────────────────────────────────────────────────── def parse_ethernet(frame): """Parse Ethernet II header — first 14 bytes.""" if len(frame) < 14: return None dst_mac = ':'.join(f'{b:02x}' for b in frame[0:6]) src_mac = ':'.join(f'{b:02x}' for b in frame[6:12]) ethertype = struct.unpack('>H', frame[12:14])[0] return {'dst': dst_mac, 'src': src_mac, 'type': ethertype, 'payload': frame[14:]} def parse_ipv4(payload): """Parse IPv4 header — minimum 20 bytes.""" if len(payload) < 20: return None ihl = (payload[0] & 0x0F) * 4 # Header length in bytes proto = payload[9] src_ip = '.'.join(str(b) for b in payload[12:16]) dst_ip = '.'.join(str(b) for b in payload[16:20]) return {'src': src_ip, 'dst': dst_ip, 'proto': proto, 'payload': payload[ihl:]} def parse_tcp_udp(payload, proto): """Parse TCP (proto=6) or UDP (proto=17) header for port numbers.""" if len(payload) < 4: return None, None, payload src_port, dst_port = struct.unpack('>HH', payload[0:4]) offset = (13 * 4) if proto == 6 else 8 # TCP: 20+ bytes header; UDP: 8 bytes return src_port, dst_port, payload[offset:] def proto_name(n): return {1: 'ICMP', 6: 'TCP', 17: 'UDP'}.get(n, f'PROTO{n}') # ─── Capture Loop ───────────────────────────────────────────────────────────── # Open raw socket — MAC layer, receives all frames sock = socket.socket(socket.AF_PACKET, socket.SOCK_RAW, socket.htons(0x0003)) sock.setblocking(False) log_buffer = [] packet_count = 0 print(f"[SNIFF] Capturing packets to {LOG_FILE}. Ctrl+C to stop.\n") try: while True: if CAPTURE_LIMIT > 0 and packet_count >= CAPTURE_LIMIT: break try: frame = sock.recv(1514) # Max Ethernet frame size except OSError: time.sleep_us(100) continue ts = time.ticks_ms() eth = parse_ethernet(frame) if not eth: continue line = f"{ts} ETH {eth['src']} > {eth['dst']} type=0x{eth['type']:04x}" if eth['type'] == 0x0800: # IPv4 ip = parse_ipv4(eth['payload']) if ip: sp, dp, app = parse_tcp_udp(ip['payload'], ip['proto']) proto = proto_name(ip['proto']) line = f"{ts} {proto} {ip['src']}:{sp} > {ip['dst']}:{dp}" # DNS logging (UDP port 53) if dp == 53 or sp == 53: line += " [DNS]" if len(app) > 12: line += f" payload_hex={app[:16].hex()}" # HTTP logging (TCP port 80) elif dp == 80 or sp == 80: try: http_start = app[:64].decode('ascii', errors='replace') line += f" [HTTP] {http_start.split(chr(13))[0]}" except: pass elif eth['type'] == 0x0806: # ARP line += " [ARP]" if len(eth['payload']) >= 28: sender_ip = '.'.join(str(b) for b in eth['payload'][14:18]) target_ip = '.'.join(str(b) for b in eth['payload'][24:28]) line += f" sender={sender_ip} target={target_ip}" print(line) log_buffer.append(line + "\n") packet_count += 1 if packet_count % LOG_FLUSH_EVERY == 0: try: with open(LOG_FILE, 'a') as f: f.writelines(log_buffer) log_buffer = [] except OSError as e: print(f"[WARN] Flash write failed: {e}") except KeyboardInterrupt: print("\n[STOP] Capture interrupted.") finally: if log_buffer: with open(LOG_FILE, 'a') as f: f.writelines(log_buffer) sock.close() print(f"[DONE] {packet_count} packets logged to {LOG_FILE}")

Encrypted Traffic (HTTPS / TLS)

TCP connections to port 443 show as opaque PROTO6 lines — the payload is encrypted. This sniffer captures metadata (source IP, destination IP, port, timing) but not content for TLS-encrypted sessions. This metadata alone is significant for traffic analysis — timing, volume, and destination information can reveal application behavior and communication patterns without decrypting the payload.

▶ How to Defend Against This — Blue Team Perspective

802.1X Port-Based Network Access Control

IEEE 802.1X requires every device connecting to a switch port to authenticate before it can pass traffic. Authentication uses EAP (Extensible Authentication Protocol) against a RADIUS server (FreeRADIUS, Cisco ISE, Microsoft NPS). An unauthorized hardware sniffer connected to a switch port fails authentication and the port is placed in an unauthorized VLAN with no traffic. This is the most effective control against hardware tap devices.

Encrypted Protocols — TLS 1.3, HTTPS, DNS-over-HTTPS

A hardware sniffer captures everything — but encrypted traffic reveals only metadata, not content. Enforcing HTTPS everywhere (HSTS preloading, HTTPS-only mode), deploying DNS-over-HTTPS (DoH) or DNS-over-TLS (DoT), and using TLS 1.3 for all internal services ensures that even a successful tap yields only connection metadata, not credential or data content. TLS 1.3 with forward secrecy means captured sessions cannot be decrypted later even if the server private key is obtained.

Network Monitoring for Promiscuous Mode Devices

A device in promiscuous mode (accepting frames not addressed to its own MAC) does not generate distinctive traffic by itself. However, active detection is possible: send a packet with a deliberately incorrect MAC address but correct IP address to the suspected monitor device. If the device responds at the IP layer (sending an ARP, ICMP, or TCP RST), it was processing frames addressed to other MACs — proving promiscuous mode. Tools like Wireshark's "promiscuous mode detector" and Nmap scripts implement this technique.

Physical Security — Cable and Port Inspection

A hardware tap requires physical access to an Ethernet cable or patch panel port. Physical security controls that prevent unauthorized access to network infrastructure — locked communications closets (TIA-942 standard), cable management with tamper-evident seals, and regular physical audits of network cable routes — directly mitigate hardware tap placement. Data center environments should log all physical access to network infrastructure areas via badged entry systems.
