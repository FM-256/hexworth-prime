Rufus

Windows MIT License

Rufus creates bootable USB drives from ISO images on Windows. It formats the drive, writes the image, and handles UEFI/BIOS boot configuration in one step. It is the fastest tool in its class and handles edge cases (Windows 11 TPM bypass, persistent Linux partitions) that other tools ignore.

What It Does

Rufus takes an ISO file (a disc image of an operating system or utility) and writes it to a USB flash drive so you can boot a computer from that drive. It handles partition scheme selection (MBR vs GPT), filesystem formatting (FAT32, NTFS, exFAT), and boot loader installation automatically. It is a single portable executable with no installation required.

Why You Need It

Every IT and cybersecurity professional needs to boot from USB regularly -- installing operating systems, running live forensic distributions, recovering broken machines, or deploying security tools like Kali Linux. Rufus is the standard Windows tool for this job. It is referenced in SG-31: Build a Bootable USB Drive in the Signal field prep guides. If you are on Windows and need a bootable USB, Rufus is the answer.

How to Install It

Option 1 -- Direct download (portable, no install):

  1. Go to https://rufus.ie/en/
  2. Download the latest rufus-X.XX.exe (standard version, not the "p" portable variant -- they are both portable, the "p" variant just stores settings in a file instead of the registry)
  3. Run it directly. No installation needed.

Option 2 -- winget (Windows Package Manager):

winget install Rufus.Rufus

Option 3 -- Chocolatey:

choco install rufus

Rufus is Windows-only. For Linux or macOS, use balenaEtcher or dd.

How to Use It

  1. Insert your USB drive and launch Rufus. It detects connected USB drives automatically. Verify the correct drive is selected in the Device dropdown -- Rufus will destroy everything on the selected drive.
  2. Select your ISO. Click SELECT next to "Boot selection" and browse to your ISO file (e.g., ubuntu-24.04-desktop-amd64.iso or kali-linux-2024.4-installer-amd64.iso).
  3. Set the partition scheme. For modern machines (2015+), select GPT and target system UEFI (non CSM). For older machines or legacy BIOS, select MBR. If you are unsure, GPT/UEFI is almost always correct.
  4. Leave the rest at defaults unless you know you need something specific. File system will auto-select (FAT32 for UEFI Linux, NTFS for Windows). Cluster size defaults are fine.
  5. Click START. Rufus will warn you that all data on the drive will be destroyed. Confirm. For Windows 11 ISOs, Rufus will offer to bypass TPM 2.0, Secure Boot, and RAM requirements -- check those boxes if installing on unsupported hardware.

The process takes 3-15 minutes depending on ISO size and USB drive speed. When the progress bar says READY, your drive is bootable.

Common Gotchas

  • DD mode vs ISO mode. Some ISOs (especially hybrid Linux images) prompt you to choose between "Write in ISO Image mode" and "Write in DD Image mode." Use ISO mode unless the image documentation specifically says DD. ISO mode creates a readable filesystem; DD does a raw byte copy that makes the USB unreadable to Windows Explorer afterward.
  • FAT32 4GB file size limit. If your ISO contains a file larger than 4GB (common with Windows ISOs), Rufus must use NTFS. Some UEFI firmware cannot boot from NTFS. Rufus handles this by splitting the large file automatically when possible -- but if the target machine will not boot, switch to MBR/BIOS mode or use Ventoy instead.
  • Wrong drive selected. Rufus will happily overwrite an external hard drive if you select the wrong device. Always double-check the drive letter and size before clicking START. Disconnect drives you want to protect.
  • Antivirus interference. Some antivirus software flags Rufus or blocks USB write operations. If the process stalls or fails, temporarily disable real-time protection.
  • Persistent partition for Linux. Rufus supports creating a persistent storage partition for Ubuntu/Debian-based live USBs. The slider appears after selecting the ISO -- set it to allocate space for saving files across reboots. Not all distributions support this feature.
