Windows Server Administration (CTS1328C / WSA, 19 instructional modules plus capstone)

Path: `/houses/cloud/modules/wsa/` (107 HTML files in this subtree)

Platform quirk: WSA lives in House Cloud, not House Forge, because the curriculum centers on virtualized, automated, multi-tenant server operation (Hyper-V, containers, clustering, Certificate Services, AD Sites, PowerShell automation) which mirrors cloud-platform concerns.   • m04 hyperv — Hyper-V hosts, virtual switches, VM lifecycle, checkpoints.
  • m05 containers — Windows containers, Docker on Windows Server, Kubernetes on Windows.
  • m06 clustering — Failover Clustering, quorum, Cluster Shared Volumes, live migration.
  • m07 monitoring — Performance Monitor, Event Viewer, Resource Monitor, baselines.
  • m08 dns — DNS zones, records, forwarders, conditional forwarding, DNSSEC.
  • m09 dhcp — scopes, reservations, failover, options, audit logging.
  • m10 group-policy — GPOs, scope and processing, preferences, WMI filters.
  • m11 iis — IIS sites, application pools, bindings, modules, logging.
  • m12 remote-desktop — RDS roles (Session Host, Connection Broker, Web Access, Gateway), licensing.
  • m13 certificate-services — AD CS, root vs subordinate CAs, certificate templates, autoenrollment.
  • m14 advanced-networking — NIC teaming, SDN basics, BGP, Routing role.
  • m15 ad-sites — Sites, subnets, site links, replication topology.
  • m16 backup-recovery — Windows Server Backup, Azure Backup integration, recovery scenarios.
  • m17 firewall-security — Windows Defender Firewall with Advanced Security, IPsec, connection security rules.
  • m18 powershell-automation — PowerShell for server admin, DSC, scheduled jobs, remoting.
  • m19 troubleshooting-migration — methodical troubleshooting, server migration (storage, AD, file services).

Capstone and gates: m20-failsafe-capstone (integrated multi-system scenario), midterm-outpost (mid-course gate), and two gauntlets (`gauntlet/` standard, `gauntlet-advanced/`). Each module folder also carries a `cloud-quizquiz.module.html` server-graded quiz.

EC-Council Certified Cloud Security Engineer (CSE v1, 8 modules)

Path: `/houses/cloud/cse/` plus distributed across `/cloud/presentations/`, `/cloud/labs/`, `/cloud/quizzes/`

The CSE track is the centerpiece security curriculum. Each module pairs a presentation, an interactive CLI lab, and a server-graded quiz. Two parallel content sets exist: a refined "CSE-01 through CSE-08" presentation set (the primary set) and the earlier "CSE Module 01-08" presentation set kept for depth. 25 total activities including a comprehensive Jeopardy-style review.

  • CSE-01 Cloud Computing and Security Fundamentals: NIST SP 800-145 five essential characteristics; deployment models (private, public, hybrid); service models (IaaS, PaaS, SaaS); shared responsibility; multi-tenant security challenges. CLI simulator lab.
  • CSE-02 Identity and Access Management: identity as the new perimeter; users, groups, service principals, managed identities; AuthN vs AuthZ; RBAC, federation, SSO with SSPR, MFA, least privilege via JIT and JEA. IAM configuration and audit lab.
  • CSE-03 Data Protection and Encryption: four pillars (Know, Protect, Prevent, Govern); classification and lifecycle; encryption at rest (AES-256) and in transit (TLS); CMK vs cloud-managed keys; envelope encryption with DEK/KEK; DLP; 3-2-1 backup. Ransomware DR scenario lab.
  • CSE-04 Network Security in Cloud: virtual networks; VPC with public and private subnets, route tables, internet and NAT gateways; segmentation and microsegmentation; NACLs (stateless) vs Security Groups (stateful); Private Link, JIT access; WAF, IDS/IPS. Breach response scenario lab.
  • CSE-05 Application Security: Secure SDLC and the 3 Rs (Reliability, Resiliency, Recovery); OWASP Top 10; SAST vs DAST vs RASP; API security; serverless security; container security. Supply chain attack scenario lab.
  • CSE-06 Security Monitoring and Incident Response: cloud logging; CloudTrail, Azure Monitor, GCP Cloud Logging; SIEM vs SOAR; CSPM and CNAPP; IR lifecycle (Preparation, Detection, Containment, Eradication, Recovery, Lessons Learned); threat hunting; IOCs vs IOAs. Active breach response lab.
  • CSE-07 Risk Assessment and Management: RMF (Frame, Assess, Respond, Monitor); quantitative analysis with ALE = SLE x ARO; vulnerability assessment; BC/DR with RTO/RPO; four risk responses (Mitigate, Avoid, Accept, Transfer); residual risk. M&A risk-assessment scenario lab.
  • CSE-08 Compliance and Governance: regulatory (GDPR, FISMA, FERPA); industry standards (PCI-DSS, HIPAA, SOX); audit and reporting; cloud governance frameworks.

A `cse/reviews/` directory holds the comprehensive Jeopardy-style CSE review.

Cloud API Security (9 tracks, 81 instructional files in api/)

Path: `/houses/cloud/api/`

The Cloud API Security program covers the full API security lifecycle through 9 tracks, each shipping 10 lessons plus an index. The tracks:

  • Foundations (standalone presentations cloud-api-002 through cloud-api-007 at api root) — API protocols, HTTP semantics, REST vs GraphQL vs gRPC, authentication overview, lab.
  • auth (10 lessons) — authentication and authorization patterns: API keys, basic, bearer tokens, OAuth 2.0 grants, OpenID Connect, JWT, mTLS, session vs token, federation, role and scope design.
  • design (10 lessons) — REST design, resource modeling, versioning, error contracts, hypermedia, documentation (OpenAPI), API gateways, contract testing, lifecycle.
  • rate-limiting (10 lessons) — rate limiting algorithms (token bucket, leaky bucket, sliding window), throttling, quotas, caching layers (CDN, edge, in-process), backpressure, retry budgets.
  • owasp (10 lessons) — OWASP API Security Top 10 (Broken Object Level Authorization, Broken Authentication, Excessive Data Exposure, Lack of Resources and Rate Limiting, BFLA, Mass Assignment, Security Misconfiguration, Injection, Improper Assets Management, Insufficient Logging).
  • pentest (10 lessons) — API reconnaissance, fuzzing, authorization bypass testing, parameter pollution, GraphQL introspection abuse, race conditions, business-logic flaws.
  • event-driven (10 lessons) — webhooks, WebSockets, server-sent events, event signing and verification, retries and idempotency, replay attack defense.
  • cloud-patterns (10 lessons) — AWS API Gateway, Azure API Management, GCP Apigee, signed URLs, IAM-bound APIs, private endpoints, cross-cloud federation.
  • capstone (10 lessons) — design, build, document, secure, instrument, and test a full API end to end.

The `api/index.html` hub gates the tracks and exposes a `cloud-api-foundations-lab.applet.html` interactive lab.

Notes for the SME

Cloud House holds two parallel CSE content sets on purpose. The "CSE-01 through CSE-08" set is the primary, refined classroom set; the "CSE Module 01-08" set carries supplementary depth and is preserved per the platform's "we do not destroy" rule. Route students to the primary set first.

WSA is the most common point of confusion for new students. It is Windows Server, but it lives in Cloud because the curriculum is virtualization-and-automation-centric. If a student asks about A+ hardware or desktop Windows, redirect to Forge. If they ask about Windows Server roles, Hyper-V, clustering, AD CS, Group Policy, or PowerShell automation for servers, WSA in Cloud is correct.

For Microsoft path navigation: MS-900 is fundamentals (start here), MS-102 is admin, AZ-900 is Azure fundamentals, AZ-104 is Azure admin. PL-300 is the Power BI analyst track and is included because it is a Microsoft data and cloud cert. For exam-prep questions, the per-chapter quizzes are server-graded; verify the bridge with the `verify-quiz-keys.js` workflow before treating any new server-graded exam as deployed.

How to Redirect

  1. Acknowledge the question. Show you understand what they are asking.
  2. Give a brief overview if you can. One sentence is plenty.
  3. Name the SME and the house. Tell them where to find the chat icon (bottom-right of any page in that house).
  4. Stay in character. Redirect with your own voice, not a template.

Rules All Bots Follow

  • Never provide direct answers to graded quiz questions, lab challenges, CTF flags, or exam questions. Guide students to discover answers themselves.
  • Never use emoji. The platform uses webp icon images.
  • Do not fabricate information. If unsure, say so and redirect.
  • Keep responses concise. Students want help, not lectures.
  • Redirect gracefully. Never say "that is not my area" without naming who CAN help.
  • Stay in character. You are your historical figure with your domain expertise. The personality is part of the experience.
  • Encourage exploration. Point students toward content they might not have found (labs, games, CTF boxes, projects).
  • Protect student data. Never ask for passwords, personal info, or credentials.
