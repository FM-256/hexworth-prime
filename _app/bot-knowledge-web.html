Chapter 1: "What IS a network?" -- OSI Model (Obj 1.1)

Core Module: NE-01 -- OSI Model Deep Dive

  • The Open Systems Interconnection model: 7 layers developed by ISO in 1984
  • Learning objectives: Name/describe all 7 layers, identify PDUs at each layer, trace encapsulation/de-encapsulation, map protocols to layers, explain why layered architecture matters for troubleshooting
  • Layer 7 (Application): HTTP, FTP, SMTP, DNS, SSH -- PDU: Data -- Device: Software/Proxy
  • Layer 6 (Presentation): SSL/TLS, JPEG, ASCII, MPEG -- PDU: Data
  • Layer 5 (Session): NetBIOS, RPC, PPTP -- PDU: Data
  • Layer 4 (Transport): TCP, UDP -- PDU: Segment/Datagram -- Device: Load Balancer
  • Layer 3 (Network): IP, ICMP, OSPF, ARP -- PDU: Packet -- Device: Router
  • Layer 2 (Data Link): Ethernet, Wi-Fi (802.11), PPP -- PDU: Frame -- Device: Switch, Bridge
  • Layer 1 (Physical): Ethernet (physical), USB, DSL -- PDU: Bits -- Device: Hub, Repeater, Cable
  • Copper (UTP/STP) vs Fiber optics vs Radio frequency
  • Mnemonic: "Please Do Not Throw Sausage Pizza Away"
  • Encapsulation flow: Data traverses down all 7 layers adding headers, crosses physical medium, strips headers going back up
  • **Labs:** Wireshark Packet Inspector (GUI lab -- capture and analyze traffic), OSI Layer Diagnosis (scenario lab -- identify failures at each layer)
  • **Tools:** OSI Reference Tool, OSI Deep Dive Tool
  • **Presentations:** OSI Model Overview, OSI Model, OSI Deep Dive
  • **Quiz:** 10 questions on layers, PDUs, protocols, devices

    • Chapter 2: "How do devices talk?" -- TCP/IP & Protocols (Obj 1.4)

    Core Module: NE-02 -- TCP/IP Protocol Suite

  • TCP vs UDP comparison: TCP is connection-oriented with guaranteed delivery (20-60 byte header); UDP is connectionless, best-effort (8 byte header)
  • TCP segment structure: Source/Destination Port, Sequence Number, Acknowledgment Number, Flags (URG, ACK, PSH, RST, SYN, FIN), Window Size, Checksum
  • Three-way handshake: SYN, SYN-ACK, ACK -- establishes connection, agrees on Initial Sequence Numbers (ISNs), negotiates MSS
  • Four-way teardown: FIN/ACK, ACK, FIN/ACK, ACK -- allows independent half-close; client enters TIME_WAIT (2x MSL)
  • Port numbers: Well-Known (0-1023), Registered (1024-49151), Dynamic/Ephemeral (49152-65535)
  • Essential ports: HTTP:80, HTTPS:443, SMTP:25, POP3:110, IMAP:143, FTP:20/21, SSH/SFTP:22, TFTP:69, SMB:445, DNS:53, DHCP:67/68, NTP:123, SNMP:161/162, Telnet:23, RDP:3389, VNC:5900
  • Socket = IP + port; Connection = 5-tuple (protocol, src IP, src port, dst IP, dst port)
  • Flow control and windowing: sliding window mechanism, receiver advertises available buffer space
  • Congestion control: Slow Start, Congestion Avoidance algorithms
  • UDP use cases: DNS, VoIP, gaming, DHCP, streaming
  • Practical Wireshark analysis: filtering for SYN packets, reading RTT from captures
  • **Labs:** Windows NIC Configuration (GUI), TCP/IP Troubleshooting (scenario)
  • **Presentations:** TCP Fundamentals, Ports & Protocols, ARP, ICMP Protocol (ping/traceroute), Traffic Types (unicast/multicast/anycast/broadcast), IPSec & GRE (VPN tunneling, AH, ESP, IKE)
  • **Tools:** Port Reference Tool
  • **Quiz:** 20 questions on ports, protocols, traffic types

    • Chapter 3: "Where do devices live?" -- IP Addressing & Subnetting (Obj 1.7, 1.8)

    Core Module: NE-03 -- IP Addressing & Subnetting

  • IPv4 address structure: 32-bit, 4 octets, dotted decimal; network portion + host portion defined by subnet mask
  • Address classes (classful -- obsolete but exam-required): Class A (1-126, /8), Class B (128-191, /16), Class C (192-223, /24), Class D (224-239, multicast), Class E (240-255, experimental)
  • 127.0.0.0/8 reserved for loopback (localhost)
  • Private address ranges (RFC 1918): 10.0.0.0/8 (enterprise), 172.16.0.0/12 (mid-size), 192.168.0.0/16 (home/small office)
  • CIDR notation replaces classful since 1993; subnet mask cheat sheet from /24 through /32
  • Formula: Usable hosts = 2^(32-prefix) - 2
  • Subnetting walkthrough: borrowing bits, calculating block size, network/broadcast/host ranges
  • VLSM (Variable Length Subnet Masking): different prefix lengths per subnet; always allocate largest first
  • Special addresses: 0.0.0.0/0 (default route), 255.255.255.255 (limited broadcast), 169.254.0.0/16 (APIPA), 100.64.0.0/10 (carrier-grade NAT)
  • Binary AND operation with subnet mask to find network address
  • **Labs:** Subnetting After Merger (scenario -- redesign IP scheme), Subnetting Practice (interactive drills)
  • **Presentations:** Subnetting, IPv6
  • **Tools:** Subnet Calculator Tool, IPv6 Reference Tool

    • Chapter 6: "How do routers work?" -- Routing Fundamentals (Obj 2.1)

    Core Module: NE-05 -- Routing Fundamentals

  • Router operation: forward packets between networks using routing tables at OSI Layer 3
  • Routing table entries: directly connected (C), static (S), OSPF (O), RIP (R)
  • Static routes: manually configured, ideal for small/stub networks, floating static routes as backup
  • Default route (0.0.0.0/0): gateway of last resort
  • Administrative Distance (AD): Directly Connected=0, Static=1, EIGRP Summary=5, eBGP=20, EIGRP=90, OSPF=110, IS-IS=115, RIP=120, EIGRP external=170, iBGP=200
  • AD vs Metric: AD selects between protocols; Metric selects within the same protocol
  • Distance-vector protocols (RIP, EIGRP): share routing table with neighbors, "routing by rumor"
  • Link-state protocols (OSPF, IS-IS): build complete topology map, run SPF algorithm
  • RIP: hop count metric (max 15), updates every 30 seconds, multicast 224.0.0.9, limited by slow convergence
  • OSPF: link-state, uses Dijkstra's SPF algorithm, cost based on bandwidth, wildcard masks, areas (Area 0 backbone), DR/BDR election
  • OSPF cost formula: Reference bandwidth / Interface bandwidth
  • Routing decision process: extract destination IP, longest prefix match, lowest AD, lowest metric, ECMP load balancing, default route, or drop with ICMP unreachable
  • **Labs:** pfSense Firewall/Router (GUI -- configure routing/firewall rules), Static Routes (CLI)
  • **Presentations:** OSPF, EIGRP, FHRP (HSRP, VRRP, GLBP)
  • **Tools:** OSPF Cost Tool

    • Chapter 9: "What about wireless?" -- Wireless Networking (Obj 2.3)

    Core Module: NE-08 -- Wireless Networking Basics

  • 802.11 standards: 802.11a (5GHz, 54Mbps, 1999), 802.11b (2.4GHz, 11Mbps), 802.11g (2.4GHz, 54Mbps), 802.11n/Wi-Fi 4 (dual-band, 600Mbps), 802.11ac/Wi-Fi 5 (5GHz, 6.9Gbps), 802.11ax/Wi-Fi 6/6E (tri-band, 9.6Gbps), 802.11be/Wi-Fi 7 (tri-band, 46Gbps)
  • 2.4 GHz: 3 non-overlapping channels (1, 6, 11), better range/penetration
  • 5 GHz: 25+ non-overlapping 20MHz channels, less interference, shorter range
  • 6 GHz (Wi-Fi 6E): 59 new channels, clean spectrum, no legacy devices
  • Wireless security: WEP (BROKEN, never use), WPA/TKIP (deprecated), WPA2-Personal (AES-CCMP, PSK), WPA2-Enterprise (802.1X/RADIUS), WPA3-Personal (SAE, resistant to offline attacks), WPA3-Enterprise (192-bit AES, CNSA-grade)
  • CSMA/CA: listen before transmit, RTS/CTS handshake, ACK confirmation
  • Hidden node problem: two clients can't hear each other but both reach AP; solved with RTS/CTS
  • Wireless architectures: Autonomous AP, Controller-Based (WLC/CAPWAP), Cloud-Managed (Meraki, Aruba Central, UniFi), Mesh Networking
  • Site surveys: passive, active, predictive; minimum signal strength (-67 dBm VoIP, -70 dBm data), SNR minimum 25 dB
  • AP placement: ceiling mount, 40-60 ft spacing for 5GHz, 20-30% overlap for roaming
  • Issues: co-channel interference, adjacent channel interference, sticky clients
  • **Labs:** UniFi Wireless Controller (GUI -- SSIDs, channels, security), Wireless Site Survey (scenario)

    • Chapter 11: "How do we secure it?" -- Network Security (Obj 4.1, 4.2, 4.3)

    Core Module: NE-10 -- Network Security Fundamentals

  • Defense in depth: Physical, Perimeter, Network, Host, Application, Data, User layers
  • Firewall types: Packet Filter (stateless), Stateful Inspection, Application Layer (proxy), NGFW (Palo Alto, Fortinet, Cisco Firepower)
  • ACLs: Standard (source IP only, 1-99), Extended (source, destination, port, protocol, 100-199); processed top-to-bottom, first match wins; placement rules
  • IDS vs IPS: IDS is passive (monitor/alert), IPS is inline (block/drop); signature-based vs anomaly-based detection
  • DMZ architecture: external firewall, DMZ segment (web/mail/DNS servers), internal firewall, internal network; strict rule separation
  • Network security best practices: segmentation via VLANs, least privilege, port security (MAC limiting), 802.1X/NAC, encryption (TLS, IPsec, WireGuard, SSH, SFTP), centralized logging/SIEM
  • Common attacks table: DoS/DDoS, ARP spoofing, VLAN hopping, MAC flooding, DNS poisoning, man-in-the-middle, brute force, social engineering -- each with mitigation strategies
  • **Labs:** Juniper SRX Firewall (GUI -- security zones and policy), Firewall Rules (configure/test ACL-based policies)

    AN-2: Border Gateway Protocol (BGP) -- Advanced

    10 modules. Cert alignment: CCNP Enterprise, CCNP SP.

  • BGP-4 is the only EGP routing the internet (RFC 4271)
  • Path-vector protocol: advertises complete AS path with each prefix for loop prevention
  • TCP-based on port 179, incremental updates (no periodic full refreshes)
  • Policy-driven: route maps, prefix lists, communities, attributes for traffic engineering
  • Autonomous Systems: public (1-64511), private (64512-65534), 32-bit extended (131072+)
  • eBGP vs iBGP: different behaviors (eBGP between autonomous systems, iBGP within)
  • BGP finite state machine: Idle, Connect, Active, OpenSent, OpenConfirm, Established
  • BGP message types: OPEN, UPDATE, KEEPALIVE, NOTIFICATION
  • Path selection algorithm, BGP communities, route policy, RPKI and prefix hijack mitigation
  • Tags: eBGP, iBGP, Route Policy, RPKI, AS-Path

    • AN-4: Data Center Networking & Fabric Architectures -- Advanced

    10 modules. Cert alignment: CCNP Data Center, NCP-MCI.

  • Evolution from three-tier to spine-leaf (Clos) architecture
  • Three-tier problems: STP blocks redundant paths, east-west traffic inefficiency, scaling requires expensive chassis upgrades
  • Clos Networks: Charles Clos (1953), multi-tier mesh, every input reaches every output through multiple equal-cost paths
  • Spine-leaf topology: every leaf connects to every spine, 3-hop server-to-server, no spanning tree
  • ECMP routing uses all uplinks simultaneously
  • Non-blocking fabric design, oversubscription ratios
  • VXLAN overlays, EVPN control plane
  • Cisco ACI, multi-site data center interconnect
  • Pod architecture for hyperscale deployments
  • Tags: Spine-Leaf, VXLAN, EVPN, ACI, Fabric Underlay
