Standard ACLs: Place Close to the Destination

Standard ACLs only filter on source IP. Placing them near the source would block traffic to ALL destinations from that source, not just the intended one.

Extended ACLs: Place Close to the Source

Extended ACLs filter on source, destination, protocol, and port. Place them near the source to drop unwanted traffic early and save bandwidth.

Implicit Deny at the End

Every ACL has an invisible "deny ip any any" at the end. If no rule matches, the packet is dropped. Always add at least one permit statement, or nothing gets through.

Order Matters

ACLs are processed top-down. The first matching rule wins. Place more specific rules before general ones.

One ACL Per Interface, Per Direction, Per Protocol

You can have one inbound and one outbound ACL per interface (per protocol). Applying a new ACL replaces the old one.

Use Named ACLs

Named ACLs are easier to edit (you can insert and delete individual entries by sequence number). Numbered ACLs require deleting and recreating the entire ACL to reorder.

Wildcard Mask Logic

Wildcard mask 0 = must match. Wildcard mask 255 = don't care. So 0.0.0.255 matches 256 addresses in the last octet. To match a single host, use wildcard 0.0.0.0 (or the keyword "host").

Always Log Denied Traffic (in production)

Add the "log" keyword to deny statements: deny ip any any log. This helps with troubleshooting and security monitoring.
