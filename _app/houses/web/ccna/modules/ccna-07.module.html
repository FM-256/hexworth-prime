VLAN Concepts & Benefits

A Virtual LAN (VLAN) is a logical grouping of switch ports that creates a separate broadcast domain within a single physical switch. Without VLANs, every device connected to a switch shares the same broadcast domain -- meaning a broadcast from any device reaches every other device. VLANs solve this by logically segmenting the network.

Broadcast Control Each VLAN is its own broadcast domain. Broadcasts from VLAN 10 never reach VLAN 20. This reduces unnecessary traffic and CPU load on end devices.
Security Sensitive departments (finance, HR) can be isolated on their own VLAN. Inter-VLAN traffic must pass through a router or firewall where ACLs can filter it.
Flexibility Users can be grouped by function regardless of physical location. Moving a user to another floor does not require re-cabling -- just change the VLAN assignment.
Performance Smaller broadcast domains mean less broadcast traffic, freeing bandwidth for real data. Critical applications can be prioritized per VLAN with QoS.

VLAN Types

Cisco switches support several VLAN types, each serving a specific purpose. Understanding these types is critical for both configuration and the exam.

VLAN Type Default ID Purpose
Default VLAN VLAN 1 All switch ports belong to VLAN 1 by default. Cannot be deleted or renamed. Carries CDP, VTP, and STP traffic by default.
Data VLAN User-defined (2-1001) Carries user-generated traffic (PCs, printers, servers). Sometimes called a "user VLAN."
Voice VLAN User-defined Dedicated VLAN for IP phone traffic. Ensures QoS for voice. Configured separately from data VLAN on the same port.
Management VLAN User-defined (best practice: not VLAN 1) Used for remote switch management (SSH, SNMP, HTTP). The SVI for this VLAN gets an IP address for management access.
Native VLAN VLAN 1 (by default) Untagged traffic on a trunk link is placed in the native VLAN. Both sides of a trunk must agree on the native VLAN, or traffic gets misrouted.
Security Best Practice:

Never use VLAN 1 for user data or management traffic. Attackers target VLAN 1 because it is the default. Create a dedicated management VLAN (e.g., VLAN 99) and change the native VLAN on trunks to an unused VLAN (e.g., VLAN 999) to mitigate VLAN hopping attacks.

Creating & Assigning VLANs

VLAN configuration is straightforward on Cisco IOS. You create the VLAN in global configuration mode, then assign individual ports to that VLAN in interface configuration mode.

! ---- Step 1: Create VLANs ---- Switch(config)# vlan 10 Switch(config-vlan)# name SALES Switch(config-vlan)# exit Switch(config)# vlan 20 Switch(config-vlan)# name ENGINEERING Switch(config-vlan)# exit Switch(config)# vlan 30 Switch(config-vlan)# name MANAGEMENT Switch(config-vlan)# exit Switch(config)# vlan 99 Switch(config-vlan)# name NATIVE-UNUSED Switch(config-vlan)# exit ! ---- Step 2: Assign Ports to VLANs ---- Switch(config)# interface GigabitEthernet0/1 Switch(config-if)# switchport mode access ! Set port as access (not trunk) Switch(config-if)# switchport access vlan 10 ! Assign to VLAN 10 (Sales) Switch(config-if)# exit ! ---- Assign a range of ports at once ---- Switch(config)# interface range GigabitEthernet0/5 - 10 Switch(config-if-range)# switchport mode access Switch(config-if-range)# switchport access vlan 20 Switch(config-if-range)# exit ! ---- Verify ---- Switch# show vlan brief VLAN Name Status Ports ---- -------------------------------- --------- ---------------------------- 1 default active Gi0/11, Gi0/12 10 SALES active Gi0/1, Gi0/2, Gi0/3, Gi0/4 20 ENGINEERING active Gi0/5, Gi0/6, Gi0/7, Gi0/8, Gi0/9, Gi0/10 30 MANAGEMENT active 99 NATIVE-UNUSED active
Important:

If you assign a port to a VLAN that does not exist yet, Cisco IOS will create the VLAN automatically. However, the VLAN will have no name. Best practice is to always create and name VLANs explicitly before assigning ports.

Trunk Ports & 802.1Q Tagging

A trunk port carries traffic for multiple VLANs between switches (or between a switch and a router). Trunk links use 802.1Q encapsulation to tag each frame with its VLAN ID, so the receiving switch knows which VLAN the frame belongs to.

/* 802.1Q Tag inserted into the Ethernet frame */ | Dest MAC | Src MAC | 802.1Q Tag (4 bytes) | Type | Data | FCS | /* 802.1Q Tag Structure: */ | TPID (2 bytes) | TCI (2 bytes) | | 0x8100 | PRI (3 bits) | DEI (1 bit) | VID (12 bits) | TPID: Tag Protocol Identifier -- always 0x8100 for 802.1Q PRI: Priority Code Point (PCP) -- used for QoS (0-7) DEI: Drop Eligible Indicator VID: VLAN Identifier -- 12 bits = VLANs 0-4095 (usable: 1-4094)

The native VLAN is the one VLAN whose traffic is NOT tagged on a trunk. If a switch receives an untagged frame on a trunk port, it places that frame into the native VLAN. Both ends of the trunk must be configured with the same native VLAN, or traffic will be misrouted.

! ---- Configure a trunk port ---- Switch(config)# interface GigabitEthernet0/24 Switch(config-if)# switchport trunk encapsulation dot1q ! Required on some platforms Switch(config-if)# switchport mode trunk ! Force trunk mode Switch(config-if)# switchport trunk native vlan 99 ! Set native VLAN to 99 Switch(config-if)# switchport trunk allowed vlan 10,20,30,99 ! Allow only specific VLANs ! ---- Disable DTP (Dynamic Trunking Protocol) ---- Switch(config-if)# switchport nonegotiate ! Prevents DTP negotiation ! ---- Verify trunk configuration ---- Switch# show interfaces trunk Port Mode Encapsulation Status Native vlan Gi0/24 on 802.1q trunking 99 Port Vlans allowed on trunk Gi0/24 10,20,30,99 Port Vlans allowed and active in management domain Gi0/24 10,20,30,99
DTP Security Risk:

Dynamic Trunking Protocol (DTP) allows a switch port to automatically negotiate becoming a trunk. An attacker can exploit this by sending DTP frames from a PC to turn an access port into a trunk, gaining access to all VLANs. Always disable DTP on access ports with switchport mode access and on trunk ports with switchport nonegotiate.

Inter-VLAN Routing: Router-on-a-Stick

Devices in different VLANs cannot communicate at Layer 2 -- they need a Layer 3 device (router or Layer 3 switch) to route traffic between VLANs. Router-on-a-stick (ROAS) uses a single physical router interface divided into subinterfaces, one per VLAN.

! ---- Router Configuration (Router-on-a-Stick) ---- ! The router's Gi0/0 connects to a trunk port on the switch. ! Each subinterface handles one VLAN. Router(config)# interface GigabitEthernet0/0 Router(config-if)# no shutdown Router(config)# interface GigabitEthernet0/0.10 ! Subinterface for VLAN 10 Router(config-subif)# encapsulation dot1Q 10 ! Tag traffic with VLAN 10 Router(config-subif)# ip address 192.168.10.1 255.255.255.0 ! Gateway for VLAN 10 Router(config)# interface GigabitEthernet0/0.20 ! Subinterface for VLAN 20 Router(config-subif)# encapsulation dot1Q 20 Router(config-subif)# ip address 192.168.20.1 255.255.255.0 Router(config)# interface GigabitEthernet0/0.99 ! Subinterface for native VLAN Router(config-subif)# encapsulation dot1Q 99 native ! "native" keyword for native VLAN Router(config-subif)# ip address 192.168.99.1 255.255.255.0 ! ---- Switch Side: Trunk to the Router ---- Switch(config)# interface GigabitEthernet0/24 Switch(config-if)# switchport trunk encapsulation dot1q Switch(config-if)# switchport mode trunk Switch(config-if)# switchport trunk native vlan 99 Switch(config-if)# switchport trunk allowed vlan 10,20,99

With ROAS, a PC in VLAN 10 (192.168.10.0/24) uses 192.168.10.1 as its default gateway. Traffic destined for VLAN 20 (192.168.20.0/24) is sent to the router, which routes it to the Gi0/0.20 subinterface. The router sends the reply back down the same physical link, tagged for the destination VLAN.

Limitation:

Router-on-a-stick funnels all inter-VLAN traffic through a single physical link. This creates a bandwidth bottleneck in large networks. For high-throughput environments, use a Layer 3 switch with SVIs instead.

Inter-VLAN Routing: Layer 3 Switch (SVIs)

A Layer 3 switch performs routing in hardware (ASIC) at wire speed, eliminating the bottleneck of router-on-a-stick. Instead of subinterfaces on a router, you create Switch Virtual Interfaces (SVIs) -- one per VLAN -- directly on the switch.

! ---- Layer 3 Switch Configuration ---- ! Step 1: Enable IP routing L3-Switch(config)# ip routing ! Step 2: Create VLANs L3-Switch(config)# vlan 10 L3-Switch(config-vlan)# name SALES L3-Switch(config-vlan)# exit L3-Switch(config)# vlan 20 L3-Switch(config-vlan)# name ENGINEERING L3-Switch(config-vlan)# exit ! Step 3: Create SVIs (these are the default gateways for each VLAN) L3-Switch(config)# interface vlan 10 L3-Switch(config-if)# ip address 192.168.10.1 255.255.255.0 L3-Switch(config-if)# no shutdown L3-Switch(config-if)# exit L3-Switch(config)# interface vlan 20 L3-Switch(config-if)# ip address 192.168.20.1 255.255.255.0 L3-Switch(config-if)# no shutdown L3-Switch(config-if)# exit ! Step 4: Assign access ports to VLANs L3-Switch(config)# interface range Gi0/1 - 12 L3-Switch(config-if-range)# switchport mode access L3-Switch(config-if-range)# switchport access vlan 10 L3-Switch(config-if-range)# exit L3-Switch(config)# interface range Gi0/13 - 24 L3-Switch(config-if-range)# switchport mode access L3-Switch(config-if-range)# switchport access vlan 20 L3-Switch(config-if-range)# exit ! Verify routing table L3-Switch# show ip route C 192.168.10.0/24 is directly connected, Vlan10 C 192.168.20.0/24 is directly connected, Vlan20
Method Pros Cons
Router-on-a-Stick Works with any router and L2 switch; simple for small networks Single link bottleneck; all traffic traverses router CPU
Layer 3 Switch (SVI) Wire-speed routing in hardware; no bottleneck; scalable Requires a more expensive Layer 3 switch (Catalyst 3560/3850/9300+)
Separate Interfaces Each VLAN gets its own physical router port -- no trunking needed Wastes router ports; does not scale; legacy approach

Voice VLAN Configuration

Cisco IP phones are typically daisy-chained: the switch port connects to the phone, and the PC connects to the phone's built-in switch port. The phone sends voice traffic on the voice VLAN and passes PC traffic on the data (access) VLAN -- untagged.

! ---- Configure a port for phone + PC ---- Switch(config)# interface GigabitEthernet0/5 Switch(config-if)# switchport mode access Switch(config-if)# switchport access vlan 10 ! Data VLAN for PC Switch(config-if)# switchport voice vlan 150 ! Voice VLAN for IP phone Switch(config-if)# mls qos trust cos ! Trust CoS markings from phone Switch(config-if)# spanning-tree portfast ! Fast convergence for end devices ! The phone uses 802.1Q to tag voice traffic with VLAN 150. ! PC traffic arrives untagged and goes to VLAN 10 (access VLAN). ! ---- Verify ---- Switch# show interfaces GigabitEthernet0/5 switchport Name: Gi0/5 Switchport: Enabled Administrative Mode: static access Operational Mode: static access Access Mode VLAN: 10 (SALES) Voice VLAN: 150 Trunking Native Mode VLAN: 1

VLAN Troubleshooting

VLAN problems are among the most common Layer 2 issues. Follow a systematic approach: verify VLAN existence, port assignment, trunk configuration, and native VLAN consistency.

Symptom Likely Cause Verification Command
PC cannot reach devices in same VLAN Wrong VLAN assignment or VLAN does not exist on switch show vlan brief
Inter-VLAN routing fails Missing SVI, SVI is shut down, or ip routing not enabled show ip interface brief
Trunk link not passing VLAN traffic VLAN not in allowed list, trunk encapsulation mismatch, or native VLAN mismatch show interfaces trunk
IP phone has no connectivity Voice VLAN not configured, or voice VLAN missing on trunk allowed list show interfaces switchport
Native VLAN mismatch syslog message Trunk endpoints configured with different native VLANs show interfaces trunk
! ---- Essential Verification Commands ---- Switch# show vlan brief ! All VLANs and port assignments Switch# show interfaces trunk ! Trunk ports, native VLAN, allowed VLANs Switch# show interfaces Gi0/1 switchport ! Detailed port VLAN info Switch# show ip interface brief ! SVI status (up/down) Switch# show running-config interface vlan 10 ! SVI configuration L3-Switch# show ip route ! Verify connected routes for VLANs
Troubleshooting Checklist:

1) Does the VLAN exist on the switch? 2) Is the port assigned to the correct VLAN? 3) Is the trunk passing the VLAN? 4) Do both ends of the trunk agree on native VLAN? 5) Is the SVI up and configured with the correct IP? 6) Is ip routing enabled on the L3 switch?

Key Takeaways

  • VLANs create logical broadcast domains on a switch -- improving security, performance, and manageability
  • VLAN types include data, voice, management, native (untagged on trunk), and default (VLAN 1)
  • Access ports carry one VLAN; trunk ports carry multiple VLANs using 802.1Q tags (4-byte insertion)
  • Always change the native VLAN away from VLAN 1 and disable DTP on all ports
  • Router-on-a-stick uses subinterfaces with encapsulation dot1Q for inter-VLAN routing
  • Layer 3 switches use SVIs (interface vlan X) and "ip routing" for wire-speed inter-VLAN routing
  • Voice VLANs are configured alongside data VLANs on the same port for Cisco IP phones
  • Verify with show vlan brief, show interfaces trunk, show ip interface brief
