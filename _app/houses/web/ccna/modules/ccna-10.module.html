Router Operation at Layer 3

A router is a Layer 3 device that connects separate networks and makes forwarding decisions based on destination IP addresses. Every interface on a router belongs to a different IP network, creating separate broadcast domains. When a frame arrives at a router interface, the router strips the Layer 2 header, examines the destination IP in the Layer 3 header, performs a routing table lookup, and re-encapsulates the packet in a new frame for the outgoing interface.

This process is called packet switching. Unlike Layer 2 switches that use MAC addresses, routers use IP addresses and maintain a routing table to determine the best path to every known destination network.

Layer 2 Switch Forwards frames using MAC address table. Operates within a single broadcast domain. Does not modify Layer 3 headers.
Layer 3 Router Forwards packets using routing table and destination IP. Separates broadcast domains. Decrements TTL, recalculates checksum, re-encapsulates frame.
Cisco Router Boot Sequence:

POST (Power-On Self Test) -> Load bootstrap from ROM -> Find and load IOS from flash -> Find and load startup-config from NVRAM -> Enter user EXEC mode. If no startup-config is found, the router enters setup mode.

Routing Table Structure

The routing table is the core data structure a router uses for forwarding decisions. It contains a list of known destination networks, how they were learned, the metric (cost), the next-hop address or exit interface, and the age of the route. Use show ip route to examine it.

Router# show ip route Codes: L - local, C - connected, S - static, R - RIP, O - OSPF, D - EIGRP, B - BGP, * - candidate default Gateway of last resort is 10.0.0.1 to network 0.0.0.0 10.0.0.0/8 is variably subnetted, 2 subnets, 2 masks C 10.0.0.0/30 is directly connected, GigabitEthernet0/0 L 10.0.0.2/32 is directly connected, GigabitEthernet0/0 S 172.16.0.0/16 [1/0] via 10.0.0.1 O 192.168.2.0/24 [110/20] via 10.0.0.1, 00:05:12, GigabitEthernet0/0 S* 0.0.0.0/0 [1/0] via 10.0.0.1

Each route entry shows: the route source code, the destination network and prefix length, the administrative distance and metric in brackets [AD/metric], the next-hop IP or exit interface, the route age (for dynamic routes), and the outgoing interface.

Administrative Distance

When multiple routing sources provide routes to the same destination network, the router needs a way to determine which source to trust. Administrative Distance (AD) is the trustworthiness rating assigned to each routing source. Lower AD means more trustworthy. AD is used to choose between different routing protocols -- it is not used for path selection within the same protocol (that is the metric's job).

Route SourceDefault ADNotes
Directly Connected0Highest trust -- the network is right here

OSPF110All OSPF route types

AD vs. Metric -- Know the Difference:

AD selects between different routing sources (e.g., OSPF route vs. RIP route to the same destination -- OSPF wins with AD 110 vs. 120). Metric selects between different paths within the same protocol (e.g., two OSPF routes to 10.0.0.0/8 -- the one with lower cost wins). They solve fundamentally different problems.

How Routes Enter the Table

Routes appear in the routing table through three mechanisms. Understanding all three is critical for predicting router behavior and troubleshooting missing routes.

Connected Routes (C) Automatically created when an interface is configured with an IP address and is in the up/up state. No manual configuration needed. If the interface goes down, the connected route is immediately removed.
Local Routes (L) Automatically created alongside connected routes. Represents the router's own IP address with a /32 prefix. Used by the router to identify traffic destined for itself (not to be forwarded).
Static Routes (S) Manually configured by the administrator using the ip route command. Remain in the table as long as the next-hop or exit interface is reachable. Removed if the exit interface goes down.
Dynamic Routes (O, D, R, B) Learned automatically from routing protocols (OSPF, EIGRP, RIP, BGP). Added and removed based on protocol updates. The protocol determines the metric and selects the best path.
/* Example: Interface configured with IP and brought up */ Router(config)# interface GigabitEthernet0/0 Router(config-if)# ip address 192.168.1.1 255.255.255.0 Router(config-if)# no shutdown /* Two routes are automatically created: */ C 192.168.1.0/24 is directly connected, GigabitEthernet0/0 L 192.168.1.1/32 is directly connected, GigabitEthernet0/0 /* The C route: any traffic for 192.168.1.x goes out Gi0/0 */ /* The L route: traffic TO 192.168.1.1 is for the router itself */

Reading show ip route -- Field by Field

The show ip route output contains dense information. Each line encodes the route source, destination network, administrative distance, metric, next hop, age, and exit interface. Here is how to decode a single route entry.

O 192.168.2.0/24 [110/20] via 10.0.0.1, 00:05:12, GigabitEthernet0/0 /* Field breakdown: */ O // Route source: OSPF 192.168.2.0/24 // Destination network and prefix length [110/20] // [Administrative Distance / Metric] // AD 110 = OSPF, Metric 20 = OSPF cost via 10.0.0.1 // Next-hop IP address 00:05:12 // Route age (hours:minutes:seconds) GigabitEthernet0/0 // Exit interface /* Parent route vs. child routes: */ 10.0.0.0/8 is variably subnetted, 4 subnets, 3 masks C 10.0.0.0/30 is directly connected, Serial0/0/0 L 10.0.0.2/32 is directly connected, Serial0/0/0 C 10.0.1.0/30 is directly connected, Serial0/0/1 L 10.0.1.2/32 is directly connected, Serial0/0/1 /* The top line is the parent route (classful boundary 10.0.0.0/8) */ /* "variably subnetted" means subnets have different mask lengths */ /* "4 subnets, 3 masks" = 4 entries using 3 different prefix lengths */

Longest Prefix Match

The longest prefix match rule is the primary mechanism routers use to select a route. When multiple routing table entries match a destination IP, the router always selects the entry with the longest (most specific) subnet mask. This takes precedence over AD and metric.

/* Routing table contains: */ S 10.0.0.0/8 [1/0] via 192.168.1.1 // matches 10.anything O 10.1.0.0/16 [110/20] via 192.168.1.2 // matches 10.1.anything O 10.1.1.0/24 [110/30] via 192.168.1.3 // matches 10.1.1.anything S 10.1.1.128/25 [1/0] via 192.168.1.4 // matches 10.1.1.128-255 /* Packet destined for 10.1.1.200: */ // All four routes match, but /25 is the longest prefix // Winner: 10.1.1.128/25 via 192.168.1.4 /* Packet destined for 10.1.2.50: */ // Matches /8 and /16, but NOT /24 or /25 // Winner: 10.1.0.0/16 via 192.168.1.2
Exam Alert:

Longest prefix match always wins, regardless of AD or metric. A static route to 10.0.0.0/8 (AD 1) will lose to an OSPF route to 10.1.1.0/24 (AD 110) for destination 10.1.1.50 because /24 is more specific than /8.

Static Route Configuration

Static routes are manually configured and do not change unless the administrator modifies them. They are appropriate for small networks, stub networks (only one exit path), and as backup routes. The syntax allows specifying either a next-hop IP address, an exit interface, or both.

/* Static Route Syntax */ Router(config)# ip route [network] [mask] [next-hop | exit-interface] /* Next-Hop Route -- most common */ Router(config)# ip route 172.16.0.0 255.255.0.0 10.0.0.1 /* Exit-Interface Route (point-to-point links) */ Router(config)# ip route 172.16.0.0 255.255.0.0 Serial0/0/0 /* Fully Specified Route (both next-hop AND exit interface) */ Router(config)# ip route 172.16.0.0 255.255.0.0 GigabitEthernet0/1 10.0.0.1 /* Verify static routes */ Router# show ip route static Router# show running-config | include ip route
Next-Hop Route Specifies the IP of the next router. Router must perform recursive lookup to find the exit interface. Most common for multi-access networks (Ethernet).
Exit-Interface Route Specifies the local outgoing interface. No recursive lookup needed. Best for point-to-point serial links. On multi-access networks, triggers proxy ARP.

Default Route & Gateway of Last Resort

A default route matches all destinations that are not explicitly listed in the routing table. It is the "catch-all" route, and it sets the gateway of last resort. The default route uses 0.0.0.0/0 as the destination, which is the shortest possible prefix and therefore only matches when no more specific route exists.

/* Configure a default static route */ Router(config)# ip route 0.0.0.0 0.0.0.0 10.0.0.1 /* Verify the gateway of last resort */ Router# show ip route Gateway of last resort is 10.0.0.1 to network 0.0.0.0 S* 0.0.0.0/0 [1/0] via 10.0.0.1 /* The asterisk (*) marks it as the candidate default route */ /* "Gateway of last resort" appears at the top of show ip route */

Default routes are essential for stub networks that only have one exit path to the rest of the network. Without a default route, any packet destined for an unknown network is dropped and the router sends an ICMP Destination Unreachable message back to the source.

Floating Static Routes

A floating static route is a backup static route configured with a higher Administrative Distance than the primary route. Under normal conditions, the primary route (learned via OSPF, EIGRP, or a regular static route) is installed in the routing table. The floating static route "floats" above the routing table, only being installed when the primary route fails.

/* Primary route: OSPF-learned route to 172.16.0.0/16 (AD 110) */ /* This route is in the routing table under normal conditions */ /* Floating static backup with AD 130 (higher than OSPF's 110) */ Router(config)# ip route 172.16.0.0 255.255.0.0 10.0.1.1 130 /* The "130" at the end overrides the default static AD of 1 */ /* Since 130 > 110, this route is NOT installed while OSPF is up */ /* If OSPF route disappears, this route activates automatically */ /* Verify -- check that the floating route is NOT in the table */ Router# show ip route /* You will see the OSPF route (O) but NOT the floating static (S) */ /* Shut down the OSPF path, then check again -- now S appears */
Common Floating Static AD Values:

To back up OSPF (AD 110), set the floating static AD to any value 111-254. Common choices: 125, 130, or 200. To back up EIGRP (AD 90), use any value 91-254. The key rule: the backup AD must be higher than the primary route's AD.

Equal-Cost Multi-Path (ECMP)

When a router has multiple routes to the same destination with identical AD and metric, it installs all of them in the routing table and load-balances traffic across them. This is called Equal-Cost Multi-Path (ECMP) routing. Cisco IOS supports up to 4 equal-cost paths by default (configurable up to 32 for some protocols).

/* Two equal-cost static routes to 172.16.0.0/16 */ Router(config)# ip route 172.16.0.0 255.255.0.0 10.0.0.1 Router(config)# ip route 172.16.0.0 255.255.0.0 10.0.1.1 Router# show ip route 172.16.0.0 Routing entry for 172.16.0.0/16 Known via "static", distance 1, metric 0 Routing Descriptor Blocks: * 10.0.0.1 * 10.0.1.1 /* Change maximum ECMP paths for OSPF */ Router(config)# router ospf 1 Router(config-router)# maximum-paths 8

ECMP load balancing on Cisco routers is per-destination by default (CEF -- Cisco Express Forwarding). This means packets to the same destination host follow the same path, preventing out-of-order delivery. Per-packet load balancing is possible but rarely used due to the reordering issue.

Static Route Configuration Scenario

Consider a three-router topology: R1 connects to a LAN (192.168.1.0/24), R2 is a transit router, and R3 connects to a server network (10.10.10.0/24). R1-R2 link is 172.16.0.0/30, R2-R3 link is 172.16.0.4/30. Configure full reachability using static routes.

/* ──── R1 Configuration ──── */ R1(config)# interface GigabitEthernet0/0 R1(config-if)# ip address 192.168.1.1 255.255.255.0 R1(config-if)# no shutdown R1(config)# interface Serial0/0/0 R1(config-if)# ip address 172.16.0.1 255.255.255.252 R1(config-if)# no shutdown /* R1 needs routes to: 10.10.10.0/24 and 172.16.0.4/30 */ R1(config)# ip route 10.10.10.0 255.255.255.0 172.16.0.2 R1(config)# ip route 172.16.0.4 255.255.255.252 172.16.0.2 /* ──── R2 Configuration ──── */ R2(config)# interface Serial0/0/0 R2(config-if)# ip address 172.16.0.2 255.255.255.252 R2(config)# interface Serial0/0/1 R2(config-if)# ip address 172.16.0.5 255.255.255.252 /* R2 has connected routes to both transit networks */ /* R2 needs routes to: 192.168.1.0/24 and 10.10.10.0/24 */ R2(config)# ip route 192.168.1.0 255.255.255.0 172.16.0.1 R2(config)# ip route 10.10.10.0 255.255.255.0 172.16.0.6 /* ──── R3 Configuration ──── */ R3(config)# interface Serial0/0/0 R3(config-if)# ip address 172.16.0.6 255.255.255.252 R3(config)# interface GigabitEthernet0/0 R3(config-if)# ip address 10.10.10.1 255.255.255.0 /* R3 uses a default route (only one exit path) */ R3(config)# ip route 0.0.0.0 0.0.0.0 172.16.0.5 /* Verify: ping from R1 LAN host to R3 server network */ R1# ping 10.10.10.1 source 192.168.1.1 Type escape sequence to abort. Sending 5, 100-byte ICMP Echos to 10.10.10.1, timeout is 2 seconds: !!!!! Success rate is 100 percent (5/5), round-trip min/avg/max = 1/2/4 ms
Common Mistake -- Asymmetric Routing:

If R1 has a route to 10.10.10.0/24 but R3 has no return path to 192.168.1.0/24, the ping request reaches R3 but the reply is dropped. Always configure routes in both directions. Use ping [dest] source [source-ip] to test end-to-end reachability from specific interfaces.

IPv6 Static Routes

Static routing concepts apply equally to IPv6. The syntax is similar but uses ipv6 route instead of ip route. IPv6 must be enabled on the router first with ipv6 unicast-routing. All the same principles apply -- next-hop, exit interface, default route, floating static, and ECMP.

/* Enable IPv6 routing (required on Cisco IOS) */ Router(config)# ipv6 unicast-routing /* IPv6 static route to a specific network */ Router(config)# ipv6 route 2001:db8:acad:2::/64 2001:db8:acad:1::2 /* IPv6 static route via exit interface */ Router(config)# ipv6 route 2001:db8:acad:2::/64 GigabitEthernet0/0 /* IPv6 fully specified route */ Router(config)# ipv6 route 2001:db8:acad:2::/64 GigabitEthernet0/0 fe80::2 /* Link-local next-hop requires exit interface to be specified */ /* IPv6 default route */ Router(config)# ipv6 route ::/0 2001:db8:acad:1::1 /* IPv6 floating static route (AD 130) */ Router(config)# ipv6 route 2001:db8:acad:2::/64 2001:db8:feed::2 130 /* Verify IPv6 routing table */ Router# show ipv6 route Router# show ipv6 route static
Link-Local Next-Hop:

When using a link-local address (fe80::) as the next-hop in an IPv6 static route, you must also specify the exit interface. Link-local addresses are ambiguous because the same address can exist on multiple interfaces. The router needs the exit interface to resolve which neighbor you mean.

When to Use Static vs. Dynamic Routing

Choosing between static and dynamic routing depends on network size, complexity, and administrative requirements. Many networks use a combination of both.

CriteriaStatic RoutesDynamic Routing
Network SizeSmall networks, stub networksMedium to large networks
ScalabilityPoor -- every route must be manually configured on every routerGood -- routers discover routes automatically
ConvergenceNo convergence -- admin must manually fix failed pathsAutomatic -- protocol detects failures and recalculates paths
CPU/MemoryZero overhead (no protocol running)Protocol processes consume CPU and memory
BandwidthNo routing updates sentProtocol updates consume bandwidth (minimal for OSPF/EIGRP)
SecurityMore secure -- no routing protocol to attackVulnerable to rogue routers and spoofed updates (use authentication)
Common UseDefault routes, backup paths, stub networks, hub-and-spoke WANCore/distribution networks, campus LANs, any redundant topology

Static routes can silently fail for several reasons. Use this checklist when a static route is configured but traffic is not reaching the destination.

/* Common mistake: static route with wrong mask */ Router(config)# ip route 10.1.1.0 255.255.0.0 172.16.0.1 /* This routes ALL of 10.1.0.0/16, not just 10.1.1.0/24! */ /* Correct: ip route 10.1.1.0 255.255.255.0 172.16.0.1 */ /* Common mistake: next-hop not reachable */ Router(config)# ip route 10.1.1.0 255.255.255.0 172.16.99.1 /* If 172.16.99.1 is not reachable via any connected route, */ /* this static route will NOT appear in the routing table */ /* Use show ip route [next-hop] to verify reachability */ Router# show ip route 172.16.99.1 % Network not in table /* The static route cannot be installed */

Routing Decision Process

When a packet arrives at a router, the forwarding decision follows a specific sequence. Understanding this order is critical for troubleshooting.

[1] Packet arrives -- extract destination IP from Layer 3 header | [2] Perform longest prefix match against routing table | +-- Multiple prefix lengths match? --> Select longest (most specific) prefix | [3] Same prefix, multiple sources? --> Select lowest Administrative Distance | [4] Same AD, multiple paths? --> Select lowest metric | [5] Equal-cost paths? --> Load-balance across all (ECMP) | [6] No match found? --> Use default route (0.0.0.0/0) | [7] No default route? --> DROP packet, send ICMP Destination Unreachable

Key Takeaways

  • Routers operate at Layer 3, forwarding packets between networks using the routing table
  • Route source codes (C, L, S, O, D, R, B) identify how each route was learned
  • Administrative Distance selects between different routing sources -- lower is more trusted
  • Connected = 0, Static = 1, EIGRP = 90, OSPF = 110, RIP = 120, iBGP = 200
  • Longest prefix match always wins over AD or metric
  • Static routes: ip route [network] [mask] [next-hop]
  • Default route: ip route 0.0.0.0 0.0.0.0 [next-hop] sets the gateway of last resort
  • Floating static routes use a higher AD to serve as automatic backups
  • ECMP load-balances across equal-cost paths (default 4 on Cisco IOS)
