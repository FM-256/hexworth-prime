Why STP Exists

Redundant links between switches are essential for high availability -- if one link fails, traffic can take an alternate path. But redundant Layer 2 links create a fatal problem: switching loops. Without a loop-prevention mechanism, three things happen simultaneously:

Broadcast Storms A broadcast frame is forwarded out all ports. With a loop, it returns on another port and is forwarded again, endlessly. Bandwidth saturates in seconds.
MAC Table Instability The switch sees the same source MAC arriving on multiple ports, constantly updating its CAM table. The table "flaps" and forwarding breaks.
Duplicate Frames The destination host receives multiple copies of the same frame. This corrupts data at higher layers and causes application errors.
Network Meltdown CPU utilization on all switches hits 100%. Management access is lost. The only recovery is physically disconnecting cables.

Spanning Tree Protocol (STP), defined by IEEE 802.1D, prevents loops by logically blocking redundant paths. It creates a loop-free tree topology while keeping the redundant links available as backups. If the active path fails, STP unblocks an alternate path and restores connectivity.

STP Operation: Root Bridge Election

STP begins by electing a single root bridge -- the focal point of the spanning tree. All other switches calculate the best path to the root bridge and block any redundant paths.

The root bridge is elected based on the Bridge ID (BID), which consists of two parts:

/* Bridge ID (BID) Structure */ | Bridge Priority (2 bytes) | MAC Address (6 bytes) | | 4 bits Priority | 12 bits Extended System ID | 6 bytes base MAC | | (default: 32768) | (= VLAN ID for PVST+) | | /* Election Rules: */ 1. Lowest Bridge Priority wins. 2. If priority is tied, lowest MAC address wins. 3. The root bridge is elected per-VLAN in PVST+. /* Example: */ Switch A: Priority 32769 (32768 + VLAN 1) MAC aabb.cc00.0100 --> BID = 32769.aabb.cc00.0100 Switch B: Priority 32769 (32768 + VLAN 1) MAC aabb.cc00.0200 --> BID = 32769.aabb.cc00.0200 Switch C: Priority 24577 (24576 + VLAN 1) MAC aabb.cc00.0300 --> BID = 24577.aabb.cc00.0300 Winner: Switch C (lowest priority = 24577)

Sets priority to 24576 (or 4096 less than current root) Switch(config)# spanning-tree vlan 1 root secondary ! Sets priority to 28672 (backup root) ! Or set priority manually (must be a multiple of 4096): Switch(config)# spanning-tree vlan 1 priority 4096 ! Valid priorities: 0, 4096, 8192, 12288, 16384, 20480, 24576, 28672, 32768, ...

Port Roles & Port States

After the root bridge is elected, every other switch determines which of its ports gets which role. The goal is to have exactly one active path from every switch to the root bridge.

Port Role Location Description
Root Port Non-root switches The port with the lowest cost path to the root bridge. Every non-root switch has exactly one root port. Forwards traffic.
Designated Port Every segment The port that forwards traffic on a given segment. The root bridge's ports are all designated. On shared segments, the switch with the lower BID wins.
Blocked (Non-designated) Non-root switches Ports that would create a loop. They do not forward user traffic -- only listen for BPDUs in case the topology changes.

STP uses path cost to determine the best path to the root. The cost is based on the link speed. Lower cost = better path.

Convergence Time:

Classic STP takes 30-50 seconds to converge after a topology change (20 sec Max Age + 15 sec Listening + 15 sec Learning). During this time, traffic is disrupted. This is the primary motivation for Rapid STP.

Rapid STP (RSTP / 802.1w)

RSTP (IEEE 802.1w) dramatically improves convergence time -- from 30-50 seconds down to 1-2 seconds. It achieves this through active topology negotiation instead of passive timer-based convergence.

Feature Classic STP (802.1D) Rapid STP (802.1w)
Convergence 30-50 seconds 1-2 seconds (sub-second possible)
Port States 5 (Disabled, Blocking, Listening, Learning, Forwarding) 3 (Discarding, Learning, Forwarding)
Port Roles Root, Designated, Blocked Root, Designated, Alternate, Backup
Topology Change Only root bridge generates TC BPDUs Any switch can originate TC BPDUs
Edge Ports PortFast (Cisco proprietary) Edge port concept built into the standard
BPDU Processing Relays BPDUs from root only All switches generate their own BPDUs

RSTP introduces two new port roles. An Alternate Port is a backup root port -- it provides an alternate path to the root bridge and can take over immediately if the root port fails. A Backup Port is a backup designated port on the same segment (rare in modern switched networks).

PortFast & BPDU Guard

Access ports connected to end devices (PCs, printers, servers) should not need to wait 30-50 seconds for STP convergence. PortFast and BPDU Guard are Cisco features that solve this problem.

PortFast Immediately transitions a port to forwarding state, bypassing listening and learning. Should only be enabled on ports connected to end devices -- never on switch-to-switch links.
BPDU Guard Protects PortFast-enabled ports by shutting them down (err-disable) if a BPDU is received. This prevents someone from plugging in a rogue switch that could destabilize the STP topology.
! ---- Enable PortFast on individual port ---- Switch(config)# interface GigabitEthernet0/1 Switch(config-if)# spanning-tree portfast ! ---- Enable PortFast on ALL access ports globally ---- Switch(config)# spanning-tree portfast default ! Applies to all access ports ! ---- Enable BPDU Guard on individual port ---- Switch(config)# interface GigabitEthernet0/1 Switch(config-if)# spanning-tree bpduguard enable ! ---- Enable BPDU Guard globally on all PortFast ports ---- Switch(config)# spanning-tree portfast bpduguard default ! ---- Recovery from BPDU Guard err-disable ---- Switch(config)# errdisable recovery cause bpduguard Switch(config)# errdisable recovery interval 300 ! Auto-recover after 300 sec ! ---- Verify PortFast status ---- Switch# show spanning-tree interface GigabitEthernet0/1 portfast VLAN0001 enabled
Critical Warning:

Never enable PortFast on a port that connects to another switch. If a loop is created through that port, STP cannot prevent it because PortFast skips the listening/learning states. Always pair PortFast with BPDU Guard as a safety net.

Cisco Per-VLAN STP: PVST+ and Rapid PVST+

Cisco runs a separate STP instance for each VLAN. This allows per-VLAN root bridge placement and per-VLAN load balancing across redundant links.

Protocol Standard Instance Convergence
PVST+ Cisco proprietary (based on 802.1D) One STP instance per VLAN 30-50 seconds
Rapid PVST+ Cisco proprietary (based on 802.1w) One RSTP instance per VLAN 1-2 seconds
MSTP (802.1s) IEEE standard Maps multiple VLANs to one STP instance Fast (similar to RSTP)
! ---- Load-balance STP across two switches ---- ! Make Switch A root for odd VLANs, Switch B root for even VLANs ! Switch A: SW-A(config)# spanning-tree vlan 1,3,5,7,9 root primary SW-A(config)# spanning-tree vlan 2,4,6,8,10 root secondary ! Switch B: SW-B(config)# spanning-tree vlan 2,4,6,8,10 root primary SW-B(config)# spanning-tree vlan 1,3,5,7,9 root secondary ! This ensures that odd-VLAN traffic takes Path A and even-VLAN traffic takes Path B. ! Both links are actively used -- no wasted bandwidth.

EtherChannel Concepts

EtherChannel (also called link aggregation or port channel) bundles multiple physical links between switches into a single logical link. STP sees the bundle as one link, so it does not block any of the member ports. This provides both increased bandwidth and redundancy.

Bandwidth Aggregation Two 1 Gbps links bundled = 2 Gbps logical bandwidth. Up to 8 links per EtherChannel (8 Gbps for Gigabit, 80 Gbps for 10G).
Redundancy If one member link fails, traffic is redistributed across the remaining links. No STP reconvergence required.
STP Integration STP treats the entire EtherChannel as a single port. No links are blocked due to redundancy -- the full aggregate bandwidth is always available.
Load Distribution Traffic is distributed across member links using a hash algorithm (based on source/destination MAC, IP, or port). Not per-packet -- per-flow.

EtherChannel Protocols: LACP vs PAgP

Two negotiation protocols can be used to form EtherChannels. Both sides must agree on the protocol, or the channel will not form.

Feature LACP (802.3ad) PAgP (Cisco Proprietary)
Standard IEEE 802.3ad (open standard) Cisco proprietary
Modes active (initiates) / passive (waits) desirable (initiates) / auto (waits)
Compatibility Works with any vendor Cisco-to-Cisco only
Max Links 16 (8 active + 8 standby) 8
Recommendation Preferred -- industry standard Legacy -- use LACP for new deployments
/* Channel Formation Rules: */ LACP: active + active = Channel forms active + passive = Channel forms passive + passive = Channel does NOT form (neither side initiates) PAgP: desirable + desirable = Channel forms desirable + auto = Channel forms auto + auto = Channel does NOT form Static (on): on + on = Channel forms (no negotiation protocol -- both sides must match) on + active/desirable = Channel does NOT form
Exam Tip:

LACP is the correct answer on any question asking about an "open standard" or "IEEE standard" EtherChannel protocol. PAgP is Cisco-only. The keyword "active" maps to LACP; "desirable" maps to PAgP.

EtherChannel Configuration

All member interfaces must have identical settings: same speed, duplex, switchport mode (access or trunk), VLAN assignment (for access) or allowed VLANs (for trunk), and native VLAN. If any setting differs, the channel will not form.

! ---- LACP EtherChannel (Recommended) ---- Switch-A(config)# interface range GigabitEthernet0/1 - 4 Switch-A(config-if-range)# channel-group 1 mode active ! LACP active Switch-A(config-if-range)# exit ! STP & EtherChannel Troubleshooting

Troubleshooting STP and EtherChannel issues requires methodical verification. Here are the most common problems and how to diagnose them.

Symptom Likely Cause Fix
Port stuck in Blocking for wrong VLAN Wrong root bridge elected Set correct root with spanning-tree vlan X root primary
30-50 second connectivity loss on link change Running classic STP (802.1D) instead of RSTP spanning-tree mode rapid-pvst
Port err-disabled after plugging in a switch BPDU Guard triggered (correctly -- rogue switch detected) Verify intent; if legitimate, remove BPDU Guard from that port
EtherChannel not forming Mismatched settings (speed, duplex, VLAN, trunk mode) or incompatible modes Ensure all member ports are identical; check mode compatibility
EtherChannel members show (I) stand-alone Channel-group mode mismatch between switches Verify both sides use compatible modes (active/passive or desirable/auto)

Key Takeaways

  • STP prevents Layer 2 loops by blocking redundant paths; the root bridge is elected by lowest Bridge ID (priority + MAC)
  • STP port roles: Root Port (best path to root), Designated Port (forwards on segment), Blocked (prevents loops)
  • Classic STP converges in 30-50 seconds; Rapid STP (802.1w) converges in 1-2 seconds
  • Cisco runs PVST+ or Rapid PVST+ -- one STP instance per VLAN for per-VLAN root placement
  • PortFast skips STP states on access ports; always pair with BPDU Guard to catch rogue switches
  • EtherChannel bundles up to 8 physical links into one logical link -- STP sees it as a single port
  • LACP (IEEE 802.3ad, modes: active/passive) is preferred over PAgP (Cisco, modes: desirable/auto)
  • All EtherChannel member ports must have identical speed, duplex, VLAN, and trunk settings
