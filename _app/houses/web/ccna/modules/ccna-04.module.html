IPv6 Address Format

IPv6 uses 128-bit addresses, written as eight groups of four hexadecimal digits separated by colons. This provides approximately 3.4 x 10^38 addresses -- enough to assign a unique address to every grain of sand on Earth and still have addresses left over.

/* Full IPv6 Address */ 2001:0DB8:0000:0000:0000:0000:0000:0001 8 groups x 4 hex digits = 32 hex characters = 128 bits Each hex digit = 4 bits Each group (hextet) = 16 bits /* Compare to IPv4 */ IPv4: 32 bits = ~4.3 billion addresses IPv6: 128 bits = ~340 undecillion addresses

Address Shortening Rules

IPv6 addresses are long, so two shortening rules make them more manageable. You must know both rules and be able to expand shortened addresses back to full form on the CCNA exam.

Rule 1: Drop leading zeros within each group 2001:0DB8:0000:0000:0000:0000:0000:0001 2001:DB8:0:0:0:0:0:1 Rule 2: Replace ONE consecutive run of all-zero groups with :: 2001:DB8:0:0:0:0:0:1 2001:DB8::1 /* :: can only be used ONCE per address. If used twice, you cannot determine how many zero groups each :: represents. */ More examples: FE80:0000:0000:0000:0000:0000:0000:0001 -> FE80::1 2001:0DB8:AAAA:0000:0000:0000:0000:0100 -> 2001:DB8:AAAA::100 FF02:0000:0000:0000:0000:0000:0000:0001 -> FF02::1 0000:0000:0000:0000:0000:0000:0000:0001 -> ::1 (loopback) 0000:0000:0000:0000:0000:0000:0000:0000 -> :: (unspecified)

IPv6 Address Types

IPv6 does not use broadcast addresses like IPv4. Instead, it uses unicast, multicast, and anycast. Every IPv6-enabled interface automatically has at least two addresses: a link-local and a global unicast (if configured).

Type Prefix Scope Description
Global Unicast (GUA) 2000::/3 (starts with 2 or 3) Internet-routable Equivalent to IPv4 public addresses. Assigned by ISPs. Globally unique.
Link-Local FE80::/10 Single link only Auto-generated on every IPv6 interface. Used for NDP, OSPFv3 neighbor adjacency, next-hop addresses. Never routed beyond the local link.
Unique Local (ULA) FC00::/7 (typically FD00::/8) Organization-internal Similar to RFC 1918 in IPv4. Not routable on the internet. Used for internal-only addressing.
Multicast FF00::/8 Varies by scope One-to-many delivery. Replaces IPv4 broadcast. FF02::1 = all nodes, FF02::2 = all routers.
Anycast (any unicast address) Nearest device Same address on multiple devices -- traffic goes to the nearest one. Used for load balancing and redundancy.
Loopback ::1/128 Host only Equivalent to IPv4 127.0.0.1. Used for local testing.
Unspecified ::/128 N/A Equivalent to IPv4 0.0.0.0. Used as source in DAD (Duplicate Address Detection).

Global Unicast Address Structure

/* GUA Structure -- Typical /48 allocation */ |<--- 48 bits --->|<- 16 bits ->|<-------- 64 bits -------->| +------------------+-------------+---------------------------+ | Global Routing | Subnet ID | Interface ID | | Prefix | | | +------------------+-------------+---------------------------+ Example: 2001:0DB8:ACAD:0001:0000:0000:0000:0001/64 |---- Prefix ----|Sub |---- Interface ID ----| ISP assigns the /48 prefix Organization creates subnets with the 16-bit subnet ID (2^16 = 65,536 subnets) Interface ID is 64 bits -- auto-generated (EUI-64 or random) or manually configured
Key Difference from IPv4:

IPv6 has NO broadcast addresses. Where IPv4 uses 255.255.255.255 (limited broadcast) or a directed broadcast, IPv6 uses multicast groups. For example, FF02::1 replaces the all-hosts broadcast, and FF02::2 reaches all routers on the link. This is more efficient because only devices listening to that multicast group process the traffic.

SLAAC and DHCPv6

IPv6 devices can obtain their addresses in multiple ways. SLAAC (Stateless Address Autoconfiguration) is unique to IPv6 and allows a host to configure itself without a DHCP server.

SLAAC (Stateless) Host generates its own address using the Router Advertisement prefix + self-generated interface ID. No server needed. The router sends RA messages with prefix, prefix length, default gateway. Host creates full address autonomously.
Stateless DHCPv6 SLAAC provides the address, but DHCPv6 provides additional info (DNS servers, domain name). The RA sets the O flag (Other Configuration) to tell hosts to contact a DHCPv6 server for this extra info.
Stateful DHCPv6 The DHCPv6 server assigns the full address (like IPv4 DHCP). The RA sets the M flag (Managed Address Configuration). The server tracks which addresses are assigned to which clients.
Static Configuration Administrator manually assigns the address on the interface. Used for routers, servers, and infrastructure devices that need permanent, predictable addresses.

How SLAAC Works (Step by Step)

1. Host sends Router Solicitation (RS) to FF02::2 (all-routers multicast) 2. Router responds with Router Advertisement (RA) containing: - Network prefix (e.g., 2001:DB8:ACAD:1::/64) - Prefix length (/64) - Default gateway (router's link-local address) - Flags: M=0, O=0 (SLAAC only) 3. Host generates Interface ID using: - EUI-64 (based on MAC address), or - Random (privacy extensions, RFC 7217) 4. Host combines prefix + interface ID: Prefix: 2001:DB8:ACAD:1:: Interface ID: A2B3:C4FF:FED5:E6F7 Full address: 2001:DB8:ACAD:1:A2B3:C4FF:FED5:E6F7/64 5. Host performs DAD (Duplicate Address Detection) via NDP 6. If no duplicate, address is assigned and used

EUI-64 Process

EUI-64 converts a 48-bit MAC address into a 64-bit interface ID by inserting FF:FE in the middle and flipping the 7th bit (U/L bit). This provides a deterministic, unique interface ID.

/* EUI-64 Conversion */ MAC Address: 00:1A:2B:3C:4D:5E Step 1: Split MAC in half 00:1A:2B | 3C:4D:5E Step 2: Insert FF:FE in the middle 00:1A:2B:FF:FE:3C:4D:5E Step 3: Flip the 7th bit (U/L bit) of the first byte 00 in binary = 0000 0000 Flip 7th bit = 0000 0010 = 02 Result: 021A:2BFF:FE3C:4D5E Full address with prefix 2001:DB8:1:1::/64: 2001:DB8:1:1:021A:2BFF:FE3C:4D5E

IPv4 to IPv6 Transition Mechanisms

The internet cannot switch from IPv4 to IPv6 overnight. Cisco supports three transition strategies that allow both protocols to coexist.

Mechanism Description Cisco Implementation
Dual-Stack Every device runs both IPv4 and IPv6 simultaneously. Each interface has both an IPv4 and IPv6 address. The OS and routing protocols handle both stacks independently. Default recommendation. Cisco IOS supports dual-stack natively. Routing protocols (OSPFv2 for IPv4, OSPFv3 for IPv6) run side by side.
Tunneling IPv6 packets are encapsulated inside IPv4 packets to cross an IPv4-only network. Types include GRE tunnels, 6to4, ISATAP, and Teredo. GRE tunnels are the most common in Cisco environments. Configured with tunnel mode ipv6ip or tunnel mode gre ip.
NAT64 Translates IPv6 packets to IPv4 and vice versa at the network boundary. Allows IPv6-only clients to reach IPv4-only servers. Cisco supports stateful NAT64 on ISR and ASR routers. Used when dual-stack is not feasible.
Cisco Best Practice:

Cisco recommends dual-stack as the primary transition strategy. It avoids the complexity of tunneling and the overhead of translation. Most modern Cisco hardware and IOS versions support dual-stack with no performance penalty.

Cisco IOS IPv6 Configuration

IPv6 routing must be explicitly enabled on Cisco routers with the ipv6 unicast-routing command. Without it, the router will accept IPv6 addresses on interfaces but will not forward IPv6 packets.

Basic IPv6 Interface Configuration

! Step 1: Enable IPv6 routing globally Router(config)# ipv6 unicast-routing ! Step 2: Configure a global unicast address on an interface Router(config)# interface GigabitEthernet0/0 Router(config-if)# ipv6 address 2001:DB8:ACAD:1::1/64 Router(config-if)# no shutdown ! Link-local is auto-generated, but you can set it manually: Router(config-if)# ipv6 address FE80::1 link-local ! Use EUI-64 to auto-generate the interface ID from MAC: Router(config-if)# ipv6 address 2001:DB8:ACAD:1::/64 eui-64

Verification Commands

Router# show ipv6 interface brief GigabitEthernet0/0 [up/up] FE80::1 2001:DB8:ACAD:1::1 GigabitEthernet0/1 [up/up] FE80::2 2001:DB8:ACAD:2::1 Loopback0 [up/up] FE80::1 2001:DB8:ACAD:FF::1 ! Note: Every interface has BOTH a link-local (FE80::) ! AND a global unicast address. The link-local is ALWAYS present ! once "ipv6 enable" or any ipv6 address is configured.

Neighbor Discovery Protocol (NDP)

NDP is an ICMPv6-based protocol that replaces ARP, ICMP Router Discovery, and ICMP Redirect from IPv4. It handles address resolution, router discovery, duplicate address detection, and more.

NDP Message ICMPv6 Type Function IPv4 Equivalent
Router Solicitation (RS) 133 Host asks for router info (sent to FF02::2) DHCP Discover (partially)
Router Advertisement (RA) 134 Router announces prefix, gateway, flags (sent to FF02::1) DHCP Offer + ICMP Router Advertisement
Neighbor Solicitation (NS) 135 Resolves IPv6 address to MAC address, also used for DAD ARP Request
Neighbor Advertisement (NA) 136 Responds with MAC address ARP Reply
Redirect 137 Router tells host about a better next-hop ICMP Redirect

DAD (Duplicate Address Detection)

Before using any IPv6 address, a device performs DAD by sending a Neighbor Solicitation to its own address. If no Neighbor Advertisement comes back, the address is unique and safe to use. If a reply is received, the address is a duplicate and is not assigned. Cisco IOS performs DAD automatically.

/* Verify NDP neighbor table (IPv6 equivalent of ARP table) */ Router# show ipv6 neighbors IPv6 Address Age Link-layer Addr State Interface FE80::A2B3:C4FF:FED5:E6F7 5 001a.2b3c.4d5e REACH Gi0/0 2001:DB8:ACAD:1::100 12 00ab.cdef.1234 STALE Gi0/0 States: REACH = recently confirmed reachable STALE = not recently confirmed, will reverify on next use DELAY = waiting for reachability confirmation INCOMPLETE = resolution in progress

Key Takeaways

  • IPv6 is 128 bits, written as 8 hextets -- shorten with leading zero removal and :: (once per address)
  • Global Unicast (2000::/3) is internet-routable; Link-Local (FE80::/10) stays on the local segment
  • SLAAC lets hosts auto-configure without a server; DHCPv6 offers stateless (O flag) and stateful (M flag) options
  • EUI-64 builds a 64-bit interface ID from a 48-bit MAC by inserting FF:FE and flipping the 7th bit
  • IPv6 has NO broadcast -- multicast (FF02::1, FF02::2) replaces it
  • NDP replaces ARP -- Neighbor Solicitation/Advertisement resolve IPv6 to MAC
  • Enable IPv6 routing with ipv6 unicast-routing before configuring interfaces
  • Dual-stack is Cisco's recommended transition strategy
