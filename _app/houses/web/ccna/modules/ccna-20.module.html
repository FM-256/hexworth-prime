MAC Flooding & Port Security

A MAC flooding attack overwhelms the switch's CAM (Content Addressable Memory) table with thousands of fake MAC addresses. When the CAM table is full, the switch cannot learn new legitimate MAC entries and begins flooding all unicast traffic out all ports -- behaving like a hub. This allows the attacker to sniff all traffic on the VLAN. Port security limits the number of MAC addresses allowed on a port, stopping this attack.

! ── Enable port security on an access port ── Switch(config)# interface GigabitEthernet0/1 Switch(config-if)# switchport mode access Switch(config-if)# switchport port-security Switch(config-if)# switchport port-security maximum 2 ! Allow maximum 2 MAC addresses on this port (PC + IP phone) ! ── Violation modes ── Switch(config-if)# switchport port-security violation shutdown ! shutdown: err-disable port, send SNMP trap, log (DEFAULT) ! restrict: drop offending frames, increment violation counter, send trap ! protect: drop offending frames silently (no log, no trap) ! ── Sticky MAC learning ── Switch(config-if)# switchport port-security mac-address sticky ! Dynamically learns MACs and writes them to running-config ! Survives reboot if you "copy run start" ! ── Static MAC address ── Switch(config-if)# switchport port-security mac-address aaaa.bbbb.cccc ! ── Aging (remove learned MACs after inactivity) ── Switch(config-if)# switchport port-security aging time 60 Switch(config-if)# switchport port-security aging type inactivity

DHCP Snooping

DHCP snooping prevents rogue DHCP servers from distributing incorrect IP addresses, gateways, or DNS servers to clients. It classifies switch ports as trusted (connected to legitimate DHCP servers) and untrusted (client ports). DHCP server responses are only allowed on trusted ports. DHCP snooping builds a binding table mapping MAC addresses to IP addresses, which is also used by DAI and IP Source Guard.

! ── Enable DHCP snooping globally ── Switch(config)# ip dhcp snooping Switch(config)# ip dhcp snooping vlan 10,20,30 ! ── Trust the uplink to the real DHCP server ── Switch(config)# interface GigabitEthernet0/24 Switch(config-if)# ip dhcp snooping trust ! All other ports are untrusted by default ! ── Rate limit DHCP requests on untrusted ports ── Switch(config)# interface range GigabitEthernet0/1 - 23 Switch(config-if-range)# ip dhcp snooping limit rate 15 ! Max 15 DHCP packets per second -- prevents DHCP starvation attacks ! ── Disable Option 82 insertion (often needed) ── Switch(config)# no ip dhcp snooping information option ! Some DHCP servers reject packets with Option 82 if not expected ! ── Verify DHCP snooping ── Switch# show ip dhcp snooping Switch# show ip dhcp snooping binding MacAddress IpAddress Lease(sec) Type VLAN Interface ------------------ --------------- ---------- ------------- ---- --------- AA:BB:CC:DD:EE:01 192.168.10.50 86400 dhcp-snooping 10 Gi0/1 AA:BB:CC:DD:EE:02 192.168.10.51 86400 dhcp-snooping 10 Gi0/2

Dynamic ARP Inspection (DAI)

ARP spoofing (ARP poisoning) allows an attacker to associate their MAC address with another host's IP address, intercepting traffic intended for that host (man-in-the-middle). DAI validates ARP packets against the DHCP snooping binding table. Invalid ARP packets on untrusted ports are dropped.

! ── Enable DAI on VLANs (requires DHCP snooping enabled first) ── Switch(config)# ip arp inspection vlan 10,20,30 ! ── Trust the uplink (same as DHCP snooping trust) ── Switch(config)# interface GigabitEthernet0/24 Switch(config-if)# ip arp inspection trust ! ── Rate limit ARP on untrusted ports ── Switch(config)# interface range GigabitEthernet0/1 - 23 Switch(config-if-range)# ip arp inspection limit rate 20 ! ── Additional DAI validation ── Switch(config)# ip arp inspection validate src-mac dst-mac ip ! Validates source MAC, destination MAC, and IP address in ARP packets ! ── For static IP hosts (no DHCP), use ARP ACLs ── Switch(config)# arp access-list STATIC-ARP Switch(config-arp-nacl)# permit ip host 192.168.10.100 mac host aaaa.bbbb.cccc Switch(config)# ip arp inspection filter STATIC-ARP vlan 10 ! ── Verify DAI ── Switch# show ip arp inspection Switch# show ip arp inspection statistics

802.1X Port-Based Authentication

802.1X provides port-based network access control. Before a device can send any traffic through a switch port, it must authenticate via EAP (Extensible Authentication Protocol). This prevents unauthorized devices from accessing the network -- even if they physically plug into a switch port.

Supplicant The client device requesting access (laptop, phone). Runs 802.1X client software (built into Windows, macOS, Linux). Sends EAP credentials to the authenticator.
Authenticator The switch port. Relays EAP messages between the supplicant and the authentication server. Controls port state (authorized/unauthorized). Does not make the authentication decision.
Authentication Server RADIUS server (Cisco ISE). Validates credentials against the identity store (Active Directory, LDAP). Returns authorization (VLAN, ACL, SGT) to the authenticator.
MAB (MAC Authentication Bypass) Fallback for devices without 802.1X support (printers, IoT). The switch sends the device's MAC address as the username/password to RADIUS. Less secure but practical.
! ── Enable 802.1X globally ── Switch(config)# aaa new-model Switch(config)# aaa authentication dot1x default group radius Switch(config)# dot1x system-auth-control ! ── Configure RADIUS server ── Switch(config)# radius server ISE Switch(config-radius-server)# address ipv4 10.1.1.100 auth-port 1812 acct-port 1813 Switch(config-radius-server)# key R4d1usK3y! ! ── Enable 802.1X on an access port ── Switch(config)# interface GigabitEthernet0/1 Switch(config-if)# switchport mode access Switch(config-if)# authentication port-control auto Switch(config-if)# dot1x pae authenticator Switch(config-if)# authentication host-mode multi-auth ! multi-auth: each device on the port authenticates individually

VLAN Attacks & Mitigation

Switch Spoofing Attacker configures their NIC to negotiate DTP (Dynamic Trunking Protocol), forming a trunk with the switch. This gives access to ALL VLANs. Mitigation: disable DTP, set ports to access mode.
Double Tagging Attacker sends a frame with two 802.1Q tags. The first tag matches the native VLAN and is stripped by the first switch. The second tag routes the frame to the target VLAN. One-way attack. Mitigation: change native VLAN to unused VLAN, tag native VLAN.
! ── Mitigate Switch Spoofing ── Switch(config)# interface range GigabitEthernet0/1 - 23 Switch(config-if-range)# switchport mode access Switch(config-if-range)# switchport nonegotiate ! Disable DTP -- port will not negotiate trunking ! ── Mitigate Double Tagging ── Switch(config)# interface GigabitEthernet0/24 Switch(config-if)# switchport trunk encapsulation dot1q Switch(config-if)# switchport mode trunk Switch(config-if)# switchport trunk native vlan 999 ! Change native VLAN to an unused VLAN (not VLAN 1) Switch(config-if)# switchport nonegotiate ! ── Disable unused ports ── Switch(config)# interface range GigabitEthernet0/13 - 20 Switch(config-if-range)# shutdown Switch(config-if-range)# switchport access vlan 999 ! Assign to a "black hole" VLAN with no gateway -- even if ! someone enables the port, they have no network access

Private VLANs (Concepts)

Private VLANs provide Layer 2 isolation between ports within the same VLAN. This is useful in DMZ environments where multiple servers share a subnet but should not communicate directly with each other. Private VLANs use primary and secondary VLANs with two port types.

Promiscuous Port Can communicate with all ports in the private VLAN (isolated and community). Typically the default gateway or firewall interface.
Isolated Port Can only communicate with promiscuous ports. Cannot communicate with other isolated ports or community ports. Maximum isolation.
Community Port Can communicate with other ports in the same community and with promiscuous ports. Cannot communicate with isolated ports or other communities.
Use Case: DMZ Web server, mail server, and DNS server share a /24 subnet but cannot reach each other. Each is on an isolated port. The firewall is on a promiscuous port. Compromising one server does not give access to the others.

IP Source Guard

IP Source Guard works with DHCP snooping to prevent IP spoofing at Layer 2. It validates the source IP address of every packet against the DHCP snooping binding table. If the source IP does not match the binding for that port, the packet is dropped.

! ── Enable IP Source Guard per-interface ── Switch(config)# interface GigabitEthernet0/1 Switch(config-if)# ip verify source ! Validates source IP against DHCP snooping binding table ! ── IP Source Guard with MAC verification ── Switch(config-if)# ip verify source port-security ! Validates both source IP AND source MAC address ! ── For static IP hosts, add static binding ── Switch(config)# ip source binding aaaa.bbbb.cccc vlan 10 192.168.10.200 interface Gi0/5

STP Security -- BPDU Guard & Root Guard

BPDU Guard Placed on access ports (PortFast-enabled). If a BPDU is received on this port, the port is immediately err-disabled. Prevents rogue switches or STP attacks from disrupting the topology.
Root Guard Placed on ports where root bridge BPDUs should never arrive. If a superior BPDU is received, the port goes to root-inconsistent state (blocking). Protects the designed root bridge position.
! ── BPDU Guard on all access ports ── Switch(config)# interface range GigabitEthernet0/1 - 23 Switch(config-if-range)# spanning-tree portfast Switch(config-if-range)# spanning-tree bpduguard enable ! Key Takeaways

  • Port security limits MAC addresses per port -- violation modes: shutdown (default), restrict, protect
  • Sticky MAC learning auto-saves learned MACs to running-config for persistence
  • DHCP snooping: trusted ports (DHCP server), untrusted ports (clients). Builds binding table.
  • DAI validates ARP packets against the DHCP snooping binding table -- requires snooping enabled first
  • 802.1X: supplicant (client) + authenticator (switch) + authentication server (RADIUS/ISE)
  • Mitigate switch spoofing: switchport mode access + switchport nonegotiate
  • Mitigate double tagging: change native VLAN to an unused VLAN (not VLAN 1)
  • Always disable unused ports and assign them to a black hole VLAN
