The Default Gateway Problem

End devices (PCs, servers, phones) are configured with a single default gateway IP address. If that gateway router fails, every device on the subnet loses connectivity to remote networks -- even if a second router exists on the same segment. The devices have no mechanism to automatically switch to a backup gateway.

First Hop Redundancy Protocols (FHRPs) solve this by creating a virtual IP address and virtual MAC address shared between two or more routers. Devices point their default gateway to the virtual IP. If the active router fails, another router takes over the virtual IP transparently -- no configuration change needed on any end device.

Without FHRP Router A (10.0.0.1) fails. All hosts with default gateway 10.0.0.1 lose connectivity. Router B (10.0.0.2) is working but hosts do not know to use it. Manual reconfiguration of every host is required.
With FHRP Virtual IP: 10.0.0.254. Hosts point to 10.0.0.254. Router A is active, Router B is standby. Router A fails -- Router B assumes 10.0.0.254 within seconds. Hosts never notice the change.

HSRP -- Hot Standby Router Protocol

HSRP is Cisco's proprietary FHRP. It allows two or more routers to work together to present a single virtual gateway to hosts. One router is elected Active (forwards traffic) and one is Standby (monitors the Active and takes over if it fails). All other HSRP-configured routers on the segment are in Listen state.

HSRP States & Election

HSRP routers transition through a series of states during initialization. The election process determines which router becomes Active.

StateDescription
InitialHSRP is not running. Entered after configuration change or interface startup.
LearnRouter has not determined the virtual IP. Waiting to hear from the Active router.
ListenRouter knows the virtual IP. Listening for Hello messages from Active and Standby. Not the Active or Standby.
SpeakRouter is sending Hello messages and participating in the Active/Standby election.
StandbyRouter is the backup. Monitors the Active router. Ready to take over if Active fails.
ActiveRouter is forwarding packets sent to the virtual MAC. Sends periodic Hello messages.

Election is NOT preemptive by default // If Active fails and Standby takes over, the original Active // does NOT reclaim Active role when it comes back -- unless // preemption is enabled

HSRP Configuration

HSRP is configured per interface. Both routers must be on the same subnet, use the same HSRP group number, and the same virtual IP address. The actual interface IPs are different from the virtual IP.

/* ──── Router A (intended Active) ──── */ RouterA(config)# interface GigabitEthernet0/0 RouterA(config-if)# ip address 10.0.0.2 255.255.255.0 RouterA(config-if)# standby 1 ip 10.0.0.254 RouterA(config-if)# standby 1 priority 110 RouterA(config-if)# standby 1 preempt RouterA(config-if)# standby 1 version 2 /* ──── Router B (Standby) ──── */ RouterB(config)# interface GigabitEthernet0/0 RouterB(config-if)# ip address 10.0.0.3 255.255.255.0 RouterB(config-if)# standby 1 ip 10.0.0.254 RouterB(config-if)# standby 1 priority 100 RouterB(config-if)# standby 1 version 2 /* Key points: */ /* - Group number (1) must match on both routers */ /* - Virtual IP (10.0.0.254) must match on both routers */ /* - Virtual IP is different from both routers' real IPs */ /* - Hosts set default gateway to 10.0.0.254 (the virtual IP) */ /* - Preempt on RouterA: if it recovers, it reclaims Active */

HSRP Interface Tracking

HSRP tracking monitors an upstream interface and automatically decrements the HSRP priority if that interface goes down. This triggers a failover to the Standby router, which has a path to the upstream network. Without tracking, a router could be Active but unable to reach upstream networks.

/* Track the upstream WAN interface */ /* If GigabitEthernet0/1 (WAN) goes down, reduce priority by 20 */ RouterA(config-if)# standby 1 track GigabitEthernet0/1 20 /* What happens: */ /* Normal state: priority = 110 (Active) */ /* Gi0/1 goes down: priority = 110 - 20 = 90 */ /* RouterB's priority = 100 (now higher) */ /* RouterB becomes Active (if preemption is enabled on B) */ /* Track using a track object (more flexible) */ RouterA(config)# track 1 interface GigabitEthernet0/1 line-protocol RouterA(config)# interface GigabitEthernet0/0 RouterA(config-if)# standby 1 track 1 decrement 20
Tracking Best Practice:

Set the decrement value large enough that the tracked router's priority drops below the Standby router's priority. If Active has priority 110 and Standby has 100, the decrement must be at least 11 (110 - 11 = 99, which is less than 100). Remember: the Standby router also needs standby preempt to actually take over.

HSRPv1 vs. HSRPv2

VRRP -- Virtual Router Redundancy Protocol

VRRP (RFC 5798) is the open-standard alternative to HSRP. It works across vendor equipment, making it the choice for multi-vendor environments. The concepts are nearly identical to HSRP, but with different terminology and a few behavioral differences.

PropertyValue
StandardIETF RFC 5798 (open standard)
RolesMaster (active), Backup (standby)
Virtual MAC0000.5e00.01XX (XX = group in hex)
Multicast224.0.0.18
Default Priority100 (range 1-254)
PreemptionEnabled by default (unlike HSRP)
Virtual IP as Real IPAllowed (router with matching IP gets priority 255)
Hello Timer1 second (default)
Master Down Interval3x hello + skew time
Key VRRP Difference:

VRRP allows the virtual IP to be the same as a router's real interface IP. That router automatically gets priority 255 (the IP address owner) and always becomes Master. This saves an IP address. HSRP requires the virtual IP to be different from all physical interface IPs.

GLBP -- Gateway Load Balancing Protocol

GLBP is Cisco proprietary and provides both redundancy AND load balancing. While HSRP and VRRP only allow one Active/Master to forward traffic at a time, GLBP allows multiple routers to actively forward traffic simultaneously using a single virtual IP but multiple virtual MACs.

AVG (Active Virtual Gateway) One router is elected AVG. It responds to ARP requests for the virtual IP by handing out different virtual MAC addresses to different hosts, distributing traffic across multiple routers.
AVF (Active Virtual Forwarder) Each router that forwards traffic is an AVF. Up to 4 AVFs per GLBP group. Each AVF has its own virtual MAC. The AVG assigns AVF roles and distributes MACs round-robin to ARP requestors.
/* GLBP Configuration */ Router(config)# interface GigabitEthernet0/0 Router(config-if)# glbp 1 ip 10.0.0.254 Router(config-if)# glbp 1 priority 110 Router(config-if)# glbp 1 preempt Router(config-if)# glbp 1 load-balancing round-robin /* Verify GLBP */ Router# show glbp

HSRP Load Balancing with Multiple Groups

While a single HSRP group only allows one Active router, you can achieve load balancing by configuring multiple HSRP groups on the same interface. Half the hosts use Virtual IP 1 (Active on R1) and the other half use Virtual IP 2 (Active on R2). Both routers actively forward traffic.

/* ──── Router A: Active for Group 1, Standby for Group 2 ──── */ RouterA(config)# interface GigabitEthernet0/0 RouterA(config-if)# standby 1 ip 10.0.0.253 RouterA(config-if)# standby 1 priority 110 RouterA(config-if)# standby 1 preempt RouterA(config-if)# standby 2 ip 10.0.0.254 RouterA(config-if)# standby 2 priority 90 /* ──── Router B: Active for Group 2, Standby for Group 1 ──── */ RouterB(config)# interface GigabitEthernet0/0 RouterB(config-if)# standby 1 ip 10.0.0.253 RouterB(config-if)# standby 1 priority 90 RouterB(config-if)# standby 2 ip 10.0.0.254 RouterB(config-if)# standby 2 priority 110 RouterB(config-if)# standby 2 preempt /* Result: */ /* Hosts A-F use default gateway 10.0.0.253 (Active: RouterA) */ /* Hosts G-L use default gateway 10.0.0.254 (Active: RouterB) */ /* Both routers forward traffic -- effective load balancing */ /* If either router fails, the other handles ALL traffic */
DHCP Integration:

Configure DHCP scopes to assign different default gateways to different groups of hosts. Scope A assigns 10.0.0.253, Scope B assigns 10.0.0.254. Or use a single scope with one VIP and accept that load balancing requires GLBP.

FHRP Design Considerations

Selecting and implementing the right FHRP requires understanding your network's vendor environment, traffic patterns, and failover requirements.

Single-Vendor (Cisco) Use HSRP for simple redundancy. Use GLBP if you need both redundancy and load balancing without multiple HSRP groups. Both are well-tested and widely deployed.
Multi-Vendor Use VRRP (open standard). It works across Cisco, Juniper, Arista, and others. Preemption is enabled by default, so a recovered primary automatically reclaims the Master role.
Convergence Speed HSRP default failover: ~10 seconds (hold timer). VRRP default: ~3.6 seconds. Both can be tuned with millisecond timers. For sub-second failover, combine FHRP with BFD (Bidirectional Forwarding Detection).
Tracking Strategy Always track upstream interfaces or reachability, not just the local LAN interface. A router can be Active on the LAN but have no upstream path. Interface tracking prevents this black-hole scenario.

EIGRP Fundamentals

Enhanced Interior Gateway Routing Protocol (EIGRP) was originally Cisco proprietary but is now published as an informational RFC (RFC 7868). It is often called an "advanced distance-vector" or "hybrid" protocol because it uses features from both distance-vector and link-state designs. EIGRP forms neighbor adjacencies, sends partial updates only when changes occur, and uses the Diffusing Update Algorithm (DUAL) for loop-free path calculation.

DUAL Algorithm & Metric

DUAL maintains a topology table with all routes learned from neighbors. It identifies a Successor (the best path) and optionally one or more Feasible Successors (guaranteed loop-free backup paths). If the Successor fails and a Feasible Successor exists, EIGRP can switch instantly without querying other routers.

Successor The best route to a destination. Installed in the routing table. Has the lowest Feasible Distance (FD) -- the total metric from this router to the destination through that next-hop.
Feasible Successor A backup path that meets the Feasibility Condition: the neighbor's Reported Distance (RD) must be less than the current Successor's Feasible Distance. This guarantees the backup path is loop-free.
/* EIGRP Composite Metric Components: */ Bandwidth -- minimum bandwidth along the path (used by default) Delay -- cumulative delay along the path (used by default) Reliability -- (NOT used by default, K-value = 0) Load -- (NOT used by default, K-value = 0) MTU -- (NOT used in metric calculation, carried in updates) /* Default metric formula (K1=1, K2=0, K3=1, K4=0, K5=0): */ /* Metric = 256 * (10^7 / min_bandwidth + cumulative_delay) */ /* Bandwidth in Kbps, Delay in microseconds / 10 */ /* View EIGRP topology table */ Router# show ip eigrp topology P 192.168.1.0/24, 1 successors, FD is 28160 via 10.0.0.2 (28160/2816), GigabitEthernet0/0 via 10.0.1.2 (30720/2816), GigabitEthernet0/1 /* (FD/RD) format: Feasible Distance / Reported Distance */ /* Feasible Successor check: RD (2816) < Successor FD (28160)? Yes */ /* So the second path is a valid Feasible Successor */

EIGRP Configuration

EIGRP configuration follows a similar pattern to OSPF, but uses an Autonomous System (AS) number instead of a process ID. The AS number MUST match between neighbors for adjacency to form.

/* Basic EIGRP Configuration */ Router(config)# router eigrp 100 /* AS number 100 -- must match on all EIGRP neighbors */ Router(config-router)# eigrp router-id 1.1.1.1 Router(config-router)# network 192.168.1.0 0.0.0.255 Router(config-router)# network 10.0.0.0 0.0.0.3 Router(config-router)# no auto-summary /* Disables automatic classful summarization at network boundaries */ /* Always use no auto-summary in modern networks */ Router(config-router)# passive-interface GigabitEthernet0/2 /* Same concept as OSPF -- no EIGRP hellos on LAN-facing interfaces */ /* Verification Commands */ Router# show ip eigrp neighbors Router# show ip eigrp topology Router# show ip route eigrp Router# show ip protocols /* EIGRP Named Mode (modern syntax, preferred) */ Router(config)# router eigrp MYNET Router(config-router)# address-family ipv4 unicast autonomous-system 100 Router(config-router-af)# network 192.168.1.0 0.0.0.255 Router(config-router-af)# eigrp router-id 1.1.1.1
EIGRP vs. OSPF -- Quick Comparison:

EIGRP uses AS numbers (must match), OSPF uses process IDs (locally significant). EIGRP supports unequal-cost load balancing (with variance), OSPF only supports equal-cost. EIGRP has faster convergence in many scenarios (Feasible Successors provide instant failover). OSPF is an open standard, EIGRP is now open but still primarily Cisco-deployed.

EIGRP Unequal-Cost Load Balancing

EIGRP is the only CCNA-level routing protocol that supports unequal-cost load balancing. The variance command allows traffic to be distributed across paths with different metrics, as long as the alternate path meets the Feasibility Condition (is a Feasible Successor).

/* Topology: Two paths to 192.168.1.0/24 */ /* Path A: FD = 28160 (Successor -- best path) */ /* Path B: FD = 46080 (Feasible Successor -- backup) */ /* Variance = FD of alternate / FD of Successor */ /* 46080 / 28160 = 1.63 -- so variance must be at least 2 */ Router(config)# router eigrp 100 Router(config-router)# variance 2 /* Any path with FD <= 2 * 28160 (56320) is used */ /* Path B (46080) qualifies -- both paths now used */ /* Traffic is distributed proportional to metrics by default */ /* Path A carries more traffic than Path B (lower metric = more) */ /* Verify */ Router# show ip route 192.168.1.0 Routing entry for 192.168.1.0/24 Known via "eigrp 100", distance 90, metric 28160 Routing Descriptor Blocks: * 10.0.0.2, from 10.0.0.2, FD is 28160 // Successor * 10.0.1.2, from 10.0.1.2, FD is 46080 // Feasible Successor
Variance Rule:

A Feasible Successor is only eligible for unequal-cost load balancing if its Feasible Distance is less than or equal to the Successor's FD multiplied by the variance value. The path must also be a valid Feasible Successor (RD < Successor's FD).

Key Takeaways

  • FHRPs solve the single-point-of-failure default gateway problem with a virtual IP/MAC
  • HSRP: Cisco proprietary, Active/Standby, preemption disabled by default, priority 100 default
  • HSRP config: standby [group] ip [virtual-ip], standby [group] priority, standby [group] preempt
  • HSRPv2 supports groups 0-4095, millisecond timers, and IPv6
  • VRRP is the open standard: Master/Backup roles, preemption enabled by default, VIP can equal real IP
  • GLBP is the only FHRP that provides both redundancy AND load balancing
  • EIGRP uses DUAL algorithm with Successor (best path) and Feasible Successor (loop-free backup)
  • EIGRP metric uses bandwidth and delay by default. AS number must match between neighbors
  • Always configure no auto-summary in classic EIGRP mode
  • Verify HSRP: show standby and show standby brief
