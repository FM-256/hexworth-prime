Authentication Methods

PSK (Pre-Shared Key) All users share the same password. Simple to deploy but difficult to manage at scale. Changing the key means reconfiguring every device. If the key leaks, the entire network is compromised.
802.1X / EAP Each user authenticates with unique credentials (username/password, certificate). The AP/WLC forwards credentials to a RADIUS server (Cisco ISE). Revoking one user does not affect others.

EAP-TLSClient certificate + server certificateStrongest -- mutual authenticationComplex -- requires PKI for client certs
PEAP (EAP-MSCHAPv2)Server certificate + username/passwordStrong -- TLS tunnel protects credentialsCommon -- works with Active Directory
EAP-FASTPAC (Protected Access Credential)Strong -- Cisco proprietaryModerate -- no client certificates needed
EAP-TTLSServer certificate + inner methodStrong -- similar to PEAPFlexible inner authentication methods

WPA2 Weakness:

WPA2 management frames (deauth, disassociation) are unprotected. An attacker can send spoofed deauth frames to disconnect clients at will. WPA3 addresses this with Protected Management Frames (PMF / 802.11w), which are mandatory.

WPA3 Improvements

SAE (Simultaneous Authentication of Equals) Replaces the 4-way handshake PSK exchange with a Dragonfly key exchange. Provides forward secrecy -- even if the password is later compromised, previously captured traffic cannot be decrypted. Resistant to offline dictionary attacks.
OWE (Opportunistic Wireless Encryption) Encrypts open networks (coffee shops, airports) without requiring a password. Uses Diffie-Hellman key exchange to establish per-client encryption. No more plaintext open Wi-Fi.
192-bit Security Suite WPA3-Enterprise optional mode using CNSA (Commercial National Security Algorithm) suite: AES-256-GCM encryption, SHA-384, ECDSA-384. Designed for government and high-security environments.
Protected Management Frames (PMF) Mandatory in WPA3. Encrypts management frames (deauth, disassociation), preventing spoofed deauthentication attacks. Based on IEEE 802.11w amendment.

Cisco WLC Security Policies

The Cisco Wireless LAN Controller (WLC) centralizes wireless security configuration. Security policies are defined per WLAN (SSID) and applied to all associated APs. The WLC handles authentication, encryption, and access control -- APs in lightweight mode are just radio endpoints.

/* Cisco WLC WLAN Security Configuration (GUI/CLI concepts) */ WLAN: Corporate-WiFi Security Layer 2: WPA2+WPA3 (transition mode) Authentication: 802.1X (EAP) Encryption: AES-CCMP-256 PMF: Required RADIUS Server: 10.1.1.100 (Cisco ISE) WLAN: Guest-WiFi Security Layer 2: Open + OWE (WPA3 Transition) Web Auth: Enabled (captive portal) Guest VLAN: VLAN 50 ACL: Internet-Only (no internal access) Session Timeout: 3600 seconds (1 hour) Bandwidth Contract: 5 Mbps down / 2 Mbps up Rogue AP Detection: Classification: Friendly / Malicious / Unclassified Containment: Auto-contain malicious rogues Alert: SNMP trap + syslog on rogue detection

Guest Wireless Access Design

Separate SSID & VLAN Guest traffic on a dedicated VLAN (e.g., VLAN 50) with no access to internal networks. Firewall rules enforce internet-only access.
Captive Portal Web authentication page presented before granting access. Can require acceptance of Acceptable Use Policy (AUP), email registration, or sponsor approval.
Bandwidth Limiting Rate-limit guest traffic to prevent one user from consuming all bandwidth. Typical: 5 Mbps down / 2 Mbps up per client.
Session & Idle Timeout Automatically disconnect guest sessions after a defined period. Force re-authentication. Prevents abandoned sessions from consuming resources.

Wireless IDS/IPS & MAC Filtering

Cisco WLCs include wireless IDS/IPS (wIDS/wIPS) capabilities. The APs monitor the RF environment for rogue devices, unauthorized SSIDs, deauthentication attacks, and other wireless-specific threats. Alerts are sent to the WLC and optionally to Cisco DNA Center or a SIEM.

MAC Filtering Limitations:

MAC filtering allows or blocks devices by MAC address. However, MAC addresses are trivially spoofed -- an attacker can observe an authorized MAC via wireless sniffing and clone it. MAC filtering provides minimal security and should never be used as the sole access control mechanism. It is acceptable as an additional layer alongside 802.1X.

Cisco Meraki Security Features

Cisco Meraki provides cloud-managed networking with built-in security features configured through a web dashboard. No on-premises controller is needed -- all management is cloud-based.

Group Policies Apply per-user or per-device policies: bandwidth limits, VLAN assignment, firewall rules, application restrictions. Policies follow the user across APs.
Client Isolation Prevents wireless clients from communicating directly with each other on the same SSID. Each client can only reach the gateway. Essential for guest networks.
Content Filtering URL and content category blocking at the AP level. Block adult content, malware domains, or specific categories for guest or BYOD networks.
Air Marshal (wIDS/wIPS) Meraki's built-in wireless intrusion detection. Detects rogue APs, evil twins, and wireless attacks. Can auto-contain detected threats. Included in all Meraki AP licenses.

Wi-Fi 6 / 6E Security Enhancements

Wi-Fi 6 (802.11ax) and Wi-Fi 6E bring security improvements beyond WPA3. These are relevant for CCNA as modern enterprise deployments increasingly require understanding of the latest standards.

Target Wake Time (TWT) Reduces the time devices are awake on the wireless network, decreasing the attack surface for deauthentication and timing-based attacks. Devices sleep on a negotiated schedule.
BSS Coloring Tags frames from different BSSs in overlapping areas. Reduces co-channel interference and helps prevent cross-BSS attacks in dense deployments.
6 GHz Band (Wi-Fi 6E) 1200 MHz of new spectrum. WPA3 is mandatory on 6 GHz -- no legacy WPA2-only mode allowed. Clean spectrum with no legacy device interference.
Enhanced Open (OWE) Available on Wi-Fi 6/6E. Encrypts open network traffic using Diffie-Hellman key exchange. No password needed, but each client gets unique encryption. Replaces insecure open Wi-Fi.

Transition Mode:

WPA3 Transition Mode allows WPA2 and WPA3 clients to connect to the same SSID. WPA2 clients use the 4-way handshake, WPA3 clients use SAE. This enables gradual migration without requiring all devices to support WPA3 on day one.

RADIUS Integration for Enterprise Wireless

In enterprise wireless deployments, the WLC acts as a RADIUS client (NAS -- Network Access Server). It forwards EAP authentication requests to the RADIUS server (Cisco ISE). The RADIUS server validates credentials and returns authorization attributes.

/* Enterprise Wireless Authentication Flow */ 1. Client associates with SSID (802.11 association) 2. WLC sends EAP-Request/Identity to client 3. Client sends EAP-Response/Identity (username) 4. WLC forwards to RADIUS server (Cisco ISE) 5. RADIUS challenges client via EAP method (PEAP, EAP-TLS) 6. Client responds with credentials (through WLC relay) 7. RADIUS validates against identity store (Active Directory) 8. RADIUS sends Access-Accept with authorization: - Dynamic VLAN assignment (Tunnel-Private-Group-ID = 10) - Downloadable ACL (Filter-Id = EMPLOYEE-ACL) - Security Group Tag (cisco-av-pair = cts:security-group-tag=5) 9. WLC places client in the authorized VLAN with applied policies 10. Client completes 4-way handshake and receives encryption keys /* Key Point: Each user gets a unique session key. Compromising one user's session does not expose other users' traffic. This is the fundamental advantage over PSK. */

Wireless Deployment Models

Autonomous APs Each AP is independently configured. No controller. Suitable only for very small deployments (1-3 APs). No centralized management, no roaming support, no unified security policy.
Lightweight APs + WLC APs are "dumb" -- all management functions centralized on the WLC. Uses CAPWAP protocol (UDP 5246/5247) for AP-to-WLC communication. The enterprise standard.
Cloud-Managed (Meraki) APs managed through Meraki cloud dashboard. No on-premises controller. Zero-touch provisioning. Management requires internet, data plane is local.
FlexConnect (Hybrid) Lightweight APs at remote sites can locally switch traffic if WLC connectivity is lost. Combines centralized control with local data forwarding for branch offices.

Key Takeaways

  • Rogue APs, evil twins, and deauthentication attacks are the primary wireless threats
  • WPA2-Personal uses PSK (shared password); WPA2-Enterprise uses 802.1X/EAP (per-user credentials)
  • WPA3-Personal uses SAE -- forward secrecy, resistant to offline dictionary attacks
  • WPA3 OWE encrypts open networks without requiring a password
  • WPA3 mandates Protected Management Frames (PMF) -- prevents deauth attacks
  • Enterprise wireless: PEAP or EAP-TLS via RADIUS (Cisco ISE) for per-user authentication
  • Guest wireless: separate SSID/VLAN, captive portal, bandwidth limits, no internal access
  • MAC filtering is trivially bypassed by spoofing -- never use as sole security measure
