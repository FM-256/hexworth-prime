The OSI 7-Layer Model (Cisco Perspective)

The OSI (Open Systems Interconnection) model is the universal reference framework for network communication. Cisco uses it extensively in documentation, troubleshooting guides, and certification exams. Each layer has a specific responsibility, and Cisco products operate at specific layers.

Layer Name PDU Cisco-Relevant Protocols Cisco Devices
7 Application Data HTTP, HTTPS, SSH, Telnet, SNMP, Syslog, DNS, DHCP, TFTP, FTP, NTP WLC GUI, DNA Center, Meraki Dashboard
6 Presentation Data SSL/TLS (encryption), JPEG, ASCII/Unicode encoding, compression --
5 Session Data TLS session management, NetBIOS, RPC, PPTP --
4 Transport Segment (TCP) / Datagram (UDP) TCP (SSH, HTTP, HTTPS, BGP), UDP (SNMP, Syslog, TFTP, DHCP, RIP) Load balancers, stateful firewalls (ASA/Firepower)
3 Network Packet IPv4, IPv6, ICMP, OSPF, EIGRP, BGP, ARP Routers (ISR, ASR, C8000), Layer 3 switches
2 Data Link Frame Ethernet (802.3), 802.11 (Wi-Fi), 802.1Q (VLAN tagging), STP, CDP, LLDP Switches (Catalyst), APs, bridges
1 Physical Bits Ethernet physical (100BASE-T, 1000BASE-T), fiber (1000BASE-LX), serial, DSL NICs, cables, SFP modules, hubs, repeaters
Cisco Exam Tip:

On the CCNA exam, Cisco tends to focus on Layers 1-4 and Layer 7 because those map directly to network infrastructure. Layers 5 and 6 are rarely tested in isolation -- in the TCP/IP model, they are folded into the Application layer.

TCP/IP Model (4-Layer)

The TCP/IP model is the practical model that the internet actually uses. Cisco documentation frequently references both models, but the TCP/IP model is what drives real protocol implementations. It has four layers:

TCP/IP Layer OSI Equivalent Function Key Protocols
Application Layers 7, 6, 5 User-facing services, data formatting, session management HTTP, HTTPS, SSH, SNMP, DNS, DHCP, TFTP, Syslog, NTP, TACACS+, RADIUS
Transport Layer 4 End-to-end delivery, port numbers, flow control, error recovery TCP, UDP
Internet Layer 3 Logical addressing, routing between networks IPv4, IPv6, ICMP, ICMPv6, OSPF, EIGRP, BGP
Network Access Layers 2, 1 Physical transmission and local delivery using MAC addresses Ethernet, 802.11, ARP, STP, CDP

When Cisco engineers say "Layer 3 switch," they mean a switch that can also perform IP routing (Internet layer). When they say "Layer 7 firewall," they mean a next-gen firewall that inspects application-layer protocols. This OSI layer numbering is used even when the actual implementation follows the TCP/IP model.

PDUs and Encapsulation

As data moves down through the layers, each layer wraps the data from the layer above with its own header (and sometimes trailer). This process is called encapsulation. The wrapped unit at each layer has a specific name -- the Protocol Data Unit (PDU).

/* Encapsulation -- Layer by Layer */ Application (Layer 7): [DATA] | Transport (Layer 4): [TCP/UDP Header][DATA] = Segment (TCP) / Datagram (UDP) | Network (Layer 3): [IP Header][TCP Header][DATA] = Packet | Data Link (Layer 2): [Frame Header][IP][TCP][DATA][FCS] = Frame | Physical (Layer 1): 10110110101001110101010... = Bits

TCP Three-Way Handshake

TCP is connection-oriented -- before any data is exchanged, the two endpoints must establish a connection using a three-step process. This is fundamental to every TCP-based service on a Cisco network (SSH, HTTP, BGP, etc.).

/* TCP Three-Way Handshake */ Step 1 -- SYN Client sends a TCP segment with the SYN flag set. Seq=100, SYN=1, ACK=0 "I want to establish a connection. My initial sequence number is 100." Step 2 -- SYN-ACK Server responds with both SYN and ACK flags set. Seq=300, SYN=1, ACK=1, Ack#=101 "I acknowledge your SYN. My sequence number is 300. I expect your next byte to be 101." Step 3 -- ACK Client sends an ACK to confirm. Seq=101, SYN=0, ACK=1, Ack#=301 "Connection established. I expect your next byte to be 301." /* Connection is now ESTABLISHED -- data transfer begins */

TCP Connection Teardown (Four-Way)

Step 1: Client sends FIN // "I'm done sending" Step 2: Server sends ACK // "Got it" Step 3: Server sends FIN // "I'm done too" Step 4: Client sends ACK // "Acknowledged -- connection closed"
Packet Tracer Context:

In Cisco Packet Tracer's simulation mode, you can watch the SYN/SYN-ACK/ACK exchange in real time. Place a PC and a server on the canvas, configure IP addresses, then use the web browser on the PC to connect. Switch to simulation mode and step through each PDU to see the handshake before HTTP data flows.

TCP vs UDP

TCP and UDP are the two transport-layer protocols. The choice between them depends on whether the application needs reliability (TCP) or speed (UDP). Cisco services use both.

Feature TCP UDP
Connection Connection-oriented (3-way handshake) Connectionless (no handshake)
Reliability Guaranteed delivery, sequencing, retransmission Best-effort delivery, no guarantees
Flow Control Windowing / sliding window None
Overhead 20-byte header minimum 8-byte header (fixed)
Speed Slower due to acknowledgments Faster -- fire and forget
Use Cases SSH, HTTPS, BGP, FTP, SMTP, Telnet SNMP, Syslog, TFTP, DHCP, DNS (queries), RIP, VoIP
Cisco IOS Example SSH session to a switch (ssh -l admin 10.0.0.1) SNMP polling (snmp-server community public RO)

Common Port Numbers (Cisco Focus)

Port numbers identify specific applications at the transport layer. Well-known ports (0-1023) are assigned by IANA. The CCNA exam expects you to know these ports cold -- especially the ones used by Cisco infrastructure services.

Port Protocol Transport Description Cisco Context
22 SSH TCP Secure remote CLI access Primary method for managing Cisco devices. Always prefer over Telnet.
23 Telnet TCP Unencrypted remote CLI access Legacy management. Sends passwords in cleartext. Disable in production.
53 DNS TCP/UDP Domain name resolution UDP for queries, TCP for zone transfers. ip name-server configures DNS on IOS.
67/68 DHCP UDP Dynamic IP assignment 67 = server, 68 = client. ip helper-address relays DHCP across subnets.
69 TFTP UDP Trivial file transfer Used to transfer IOS images and configs. copy tftp: flash:
80 HTTP TCP Web traffic (unencrypted) Cisco device web GUI (if enabled). ip http server
443 HTTPS TCP Web traffic (encrypted) Secure device management GUI. ip http secure-server
161/162 SNMP UDP Network monitoring 161 = agent (device), 162 = trap receiver (NMS). Used by DNA Center, SolarWinds.
514 Syslog UDP Centralized logging logging host 10.0.0.100 sends logs to a syslog server.
49 TACACS+ TCP AAA authentication/authorization Cisco-proprietary AAA protocol. Encrypts entire packet body. Used with Cisco ISE.
1812/1813 RADIUS UDP AAA authentication/accounting Industry-standard AAA. 1812 = auth, 1813 = accounting. Encrypts password only.
123 NTP UDP Time synchronization ntp server 10.0.0.1 -- critical for log correlation and certificates.
20/21 FTP TCP File transfer 20 = data, 21 = control. Used for IOS image transfers when TFTP is not enough.
179 BGP TCP Border Gateway Protocol The routing protocol of the internet. Cisco routers use TCP 179 for BGP peering.
TACACS+ vs RADIUS -- Cisco's Preference:

Cisco recommends TACACS+ for device administration (CLI access) because it encrypts the entire packet and supports per-command authorization. RADIUS is preferred for network access (802.1X, VPN) because it is an open standard and integrates with more vendors. Both are configured through Cisco ISE.

Key Takeaways

  • The OSI model has 7 layers; the TCP/IP model has 4 -- Cisco uses both in documentation and exams
  • PDUs progress from Data (L7) to Segments (L4) to Packets (L3) to Frames (L2) to Bits (L1)
  • Encapsulation adds headers going down; de-encapsulation strips them going up
  • TCP uses a 3-way handshake (SYN, SYN-ACK, ACK) and provides reliable delivery
  • UDP is connectionless and faster -- used by SNMP, Syslog, TFTP, DHCP
  • TACACS+ (TCP/49) is Cisco-preferred for device admin; RADIUS (UDP/1812-1813) for network access
  • Know ports 22, 23, 49, 53, 67/68, 69, 80, 123, 161/162, 179, 443, 514, 1812/1813
