Ethernet Frame Structure

Ethernet is the dominant Layer 2 LAN technology. Every frame transmitted on an Ethernet network follows a strict format defined by IEEE 802.3. Understanding this structure is foundational for switch operation, troubleshooting, and packet analysis.

/* IEEE 802.3 Ethernet Frame */ | Preamble | SFD | Dest MAC | Source MAC | Type/Length | Data + Pad | FCS | | 7 bytes | 1 B | 6 bytes | 6 bytes | 2 bytes | 46-1500 B | 4 B | /* Field Breakdown: */ Preamble (7 bytes): Alternating 1s and 0s for clock sync (10101010...) SFD (1 byte): Start Frame Delimiter -- signals "frame starts now" (10101011) Destination MAC (6B): Where the frame is going (unicast, multicast, or broadcast) Source MAC (6 bytes): Where the frame came from (always unicast) Type/Length (2 bytes): EtherType (e.g., 0x0800 = IPv4, 0x86DD = IPv6, 0x0806 = ARP) Data (46-1500 bytes): The payload -- carries the Layer 3 packet FCS (4 bytes): Frame Check Sequence -- CRC-32 for error detection

The minimum Ethernet frame size is 64 bytes (excluding preamble and SFD). If the data payload is less than 46 bytes, padding is added to meet the minimum. The maximum frame size is 1518 bytes. Jumbo frames extend this to 9216 bytes but are not part of the IEEE standard.

Exam Tip:

The Type field distinguishes Ethernet II frames from IEEE 802.3 frames. If the value is 0x0600 (1536) or greater, it is an EtherType (Ethernet II). If less, it indicates the length of the data field (IEEE 802.3). Modern networks overwhelmingly use Ethernet II.

MAC Address Format & OUI

A MAC (Media Access Control) address is a 48-bit (6-byte) hardware address burned into every network interface card. It uniquely identifies a device on the local network segment. MAC addresses operate at Layer 2 and are used by switches for frame forwarding.

/* MAC Address Structure */ AA:BB:CC:DD:EE:FF |------| |------| OUI Device ID (Vendor) (Unique per NIC) /* Common Formats: */ Colon notation: AA:BB:CC:DD:EE:FF Hyphen notation: AA-BB-CC-DD-EE-FF Cisco notation: AABB.CCDD.EEFF // Cisco uses dot-separated groups of 4 hex chars /* Special Addresses: */ FF:FF:FF:FF:FF:FF = Broadcast (all hosts on segment) 01:00:5E:xx:xx:xx = IPv4 Multicast 33:33:xx:xx:xx:xx = IPv6 Multicast

The first 3 bytes (24 bits) are the Organizationally Unique Identifier (OUI), assigned by the IEEE to manufacturers. The last 3 bytes are assigned by the manufacturer to each individual NIC. This ensures global uniqueness. You can look up any OUI at ieee.org to identify the vendor of a device.

Unicast vs Multicast Bit:

The least significant bit of the first byte determines the address type. If bit 0 = 0, the address is unicast (destined for one host). If bit 0 = 1, the address is multicast (destined for a group). Broadcast (FF:FF:FF:FF:FF:FF) is a special case of multicast.

How Switches Learn MAC Addresses

A Cisco switch builds its MAC address table (also called the CAM table -- Content Addressable Memory) dynamically by examining the source MAC address of every incoming frame. This process is automatic and requires no configuration.

Step 1: Frame Arrives A frame arrives on port Gi0/1. The switch reads the source MAC address from the frame header.
Step 2: Learn Source MAC The switch records the source MAC and the ingress port in its MAC address table, along with a timestamp and VLAN ID.
Step 3: Lookup Destination MAC The switch checks the destination MAC against its table. If a match exists, it forwards the frame out the associated port only.
Step 4: Unknown Unicast Flooding If no match exists, the switch floods the frame out all ports in the same VLAN (except the ingress port). The destination host replies, and the switch learns its MAC too.

MAC address table entries age out after 300 seconds (5 minutes) by default on Cisco switches. This timer ensures the table stays current even as devices move or disconnect. The aging timer is configurable with mac address-table aging-time.

Shows only dynamically learned entries Switch# show mac address-table address aabb.cc00.0100 ! Look up a specific MAC address Switch# show mac address-table vlan 10 ! Filter by VLAN Switch# clear mac address-table dynamic ! Flush all dynamic entries (forces re-learning)
CAM Table Overflow Attack:

An attacker can flood a switch with thousands of fake source MACs, filling the CAM table. When the table is full, the switch can no longer learn new entries and begins flooding all traffic like a hub -- allowing the attacker to sniff all frames. Port security and 802.1X mitigate this attack.

Switch Forwarding Methods

Cisco Catalyst switches support two primary forwarding methods. The method determines when the switch begins forwarding the frame -- immediately after reading the destination MAC, or only after receiving the entire frame.

Method How It Works Latency Error Handling
Store-and-Forward Receives the entire frame, checks the FCS for errors, then forwards. Drops corrupted frames. Higher (variable, depends on frame size) Full CRC check -- no bad frames forwarded
Cut-Through Reads only the destination MAC (first 14 bytes after preamble), then begins forwarding immediately. Low (fixed, ~few microseconds) No error check -- corrupted frames are forwarded
Fragment-Free A variant of cut-through that reads the first 64 bytes before forwarding. Catches runt frames caused by collisions. Low (slightly more than cut-through) Catches collision fragments only
Cisco Default:

Modern Cisco Catalyst switches (2960, 3850, 9200, 9300 series) default to store-and-forward switching. At today's line speeds (1 Gbps, 10 Gbps, 25 Gbps), the latency difference is negligible, and the error-checking benefit outweighs the performance cost. Cut-through is primarily used in data center switches like the Nexus series.

Full-Duplex, Half-Duplex & Auto-Negotiation

Duplex settings determine whether a device can send and receive simultaneously. Mismatched duplex settings between a switch port and a connected device are a common source of performance problems and frame errors.

Half-Duplex Device can either send OR receive at any given moment, but not both. Uses CSMA/CD for collision detection. Common with hubs. Rarely used today.
Full-Duplex Device sends and receives simultaneously on separate wire pairs. No collisions possible. Standard on modern switch-to-device connections.

Auto-negotiation (IEEE 802.3u) allows a switch port and a connected device to automatically agree on speed and duplex settings. When both sides support auto-negotiation, they exchange capabilities and select the highest common speed and duplex. When one side is hard-coded and the other is set to auto, the auto side detects the speed but defaults to half-duplex -- causing a duplex mismatch.

Switch(config)# interface GigabitEthernet0/1 Switch(config-if)# speed auto ! Auto-negotiate speed (default) Switch(config-if)# duplex auto ! Auto-negotiate duplex (default) ! Hard-code speed and duplex (when connecting to a device that doesn't auto-negotiate): Switch(config-if)# speed 1000 ! Force 1 Gbps Switch(config-if)# duplex full ! Force full-duplex ! Verify current settings: Switch# show interfaces GigabitEthernet0/1 GigabitEthernet0/1 is up, line protocol is up Hardware is Gigabit Ethernet, address is aabb.cc00.0100 Full-duplex, 1000Mb/s, media type is 10/100/1000BaseTX ... 0 input errors, 0 CRC, 0 frame, 0 overrun, 0 ignored 0 output errors, 0 collisions, 0 interface resets
Duplex Mismatch Symptoms:

A duplex mismatch causes late collisions, FCS errors, and runts on the half-duplex side, and CRC errors on the full-duplex side. Performance drops dramatically. Always verify duplex settings with show interfaces when troubleshooting slow links.

Collision Domains vs Broadcast Domains

Understanding how network devices segment traffic is critical for designing efficient LANs and for the CCNA exam. The two key concepts are collision domains and broadcast domains.

Concept Definition Broken By
Collision Domain The set of devices that can experience a frame collision with each other. All devices on the same hub port or shared segment are in one collision domain. Switches (each port = 1 collision domain), bridges, routers
Broadcast Domain The set of devices that receive a Layer 2 broadcast frame (FF:FF:FF:FF:FF:FF). All ports on a switch in the same VLAN share one broadcast domain. Routers, Layer 3 switches (VLANs)
/* Example: 24-port Catalyst switch with all ports in VLAN 1 */ Collision domains: 24 // Each switch port is its own collision domain Broadcast domains: 1 // All ports in VLAN 1 = one broadcast domain /* Add a router between two switches: */ Collision domains: 48 + 2 // 24 per switch + 2 router interfaces Broadcast domains: 2 // Router separates broadcast domains /* Hubs DO NOT break collision domains: */ // A 24-port hub = 1 collision domain, 1 broadcast domain
Key Principle:

Switches segment collision domains (one per port). Routers (and VLANs on Layer 3 switches) segment broadcast domains. This is why switches replaced hubs -- they eliminate collisions and improve bandwidth utilization.

Port Security Basics

Port security is a Layer 2 feature on Cisco switches that restricts the number of valid MAC addresses allowed on a port. It prevents unauthorized devices from connecting and mitigates CAM table overflow attacks.

! Enable port security on an access port Switch(config)# interface GigabitEthernet0/1 Switch(config-if)# switchport mode access ! Must be access or trunk Switch(config-if)# switchport port-security ! Enable port security Switch(config-if)# switchport port-security maximum 2 ! Allow max 2 MACs (default is 1) Switch(config-if)# switchport port-security violation shutdown ! Action on violation Switch(config-if)# switchport port-security mac-address sticky ! Learn and persist MACs ! Violation modes: shutdown - Port goes err-disabled (default). Requires admin to recover. restrict - Drops offending frames, increments violation counter, sends SNMP trap. protect - Silently drops offending frames. No log, no counter. ! Verify port security: Switch# show port-security interface GigabitEthernet0/1 Port Security : Enabled Port Status : Secure-up Violation Mode : Shutdown Aging Time : 0 mins Maximum MAC Addresses : 2 Total MAC Addresses : 1 Sticky MAC Addresses : 1 Security Violation Count : 0 ! Recovery from err-disabled state: Switch(config)# interface GigabitEthernet0/1 Switch(config-if)# shutdown Switch(config-if)# no shutdown ! Or enable auto-recovery: Switch(config)# errdisable recovery cause psecure-violation Switch(config)# errdisable recovery interval 300 ! Recover after 300 seconds
Sticky MAC Addresses:

When you configure switchport port-security mac-address sticky, the switch dynamically learns the MAC addresses on the port and adds them to the running configuration as static entries. This persists across reboots if you save the config with copy running-config startup-config.

Key Takeaways

  • Ethernet frames carry destination MAC, source MAC, type/length, data, and FCS -- minimum 64 bytes, maximum 1518 bytes
  • MAC addresses are 48-bit, with the first 24 bits (OUI) identifying the vendor and the last 24 bits identifying the device
  • Switches learn MAC addresses dynamically by reading the source MAC of incoming frames and associating it with the ingress port
  • Store-and-forward checks the entire frame for errors before forwarding; cut-through begins forwarding after reading only the destination MAC
  • Each switch port creates a separate collision domain; VLANs and routers create separate broadcast domains
  • Port security limits the number of allowed MACs per port -- violation modes are shutdown (default), restrict, and protect
  • Use show mac address-table, show interfaces status, and show port-security for verification
