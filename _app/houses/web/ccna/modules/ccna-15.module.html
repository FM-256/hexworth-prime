DHCP Operation -- The DORA Process

DHCP (Dynamic Host Configuration Protocol) automates IP address assignment. Without DHCP, every device on the network would need manual IP configuration -- impractical at any scale. DHCP uses a four-step process known as DORA.

D - Discover Client broadcasts a DHCPDISCOVER message (destination 255.255.255.255, UDP port 67). The client has no IP yet, so the source is 0.0.0.0. This is a Layer 2 broadcast.
O - Offer DHCP server responds with a DHCPOFFER containing a proposed IP address, subnet mask, default gateway, DNS servers, and lease duration. Also broadcast or unicast to the client's MAC.
R - Request Client broadcasts a DHCPREQUEST accepting the offer. This is broadcast because other DHCP servers on the network need to know this client chose a different server's offer.
A - Acknowledge Server sends DHCPACK confirming the lease. The client can now use the assigned IP address. Lease timer begins. Client will attempt renewal at 50% (T1) and 87.5% (T2) of lease time.
Port Numbers:

DHCP server listens on UDP port 67. DHCP client sends from UDP port 68. These are the only two ports involved in DHCP communication.

DHCP Relay -- ip helper-address

DHCP Discover is a broadcast. Broadcasts do not cross router boundaries. If the DHCP server is on a different subnet, the router must be configured as a DHCP relay agent using ip helper-address. The router converts the broadcast to a unicast and forwards it to the DHCP server.

! ── Configure DHCP relay on the router interface facing the clients ── Router(config)# interface GigabitEthernet0/0 Router(config-if)# description Client VLAN 10 Router(config-if)# ip address 10.10.10.1 255.255.255.0 Router(config-if)# ip helper-address 10.20.20.100 ! 10.20.20.100 is the DHCP server on a remote subnet ! The router will relay DHCP broadcasts from VLAN 10 to that server ! ! ip helper-address also forwards these UDP protocols by default: ! TFTP (69), DNS (53), Time (37), TACACS (49), ! NetBIOS (137/138), DHCP (67/68) ! ── Multiple DHCP servers? Add multiple helper addresses ── Router(config-if)# ip helper-address 10.20.20.100 Router(config-if)# ip helper-address 10.20.20.101

DNS Fundamentals

DNS (Domain Name System) translates human-readable domain names to IP addresses. Without DNS, you would need to memorize the IP address of every website. DNS uses a hierarchical, distributed database architecture with root servers, TLD servers, and authoritative name servers.

Record TypePurposeExample
AMaps hostname to IPv4 addresswww.cisco.com --> 72.163.4.185
AAAAMaps hostname to IPv6 addresswww.cisco.com --> 2001:420:1101:1::185
CNAMEAlias -- points one name to another namemail.company.com --> outlook.office365.com
MXMail exchange -- directs email to mail serverscompany.com MX 10 mail1.company.com
PTRReverse lookup -- maps IP to hostname185.4.163.72.in-addr.arpa --> www.cisco.com
NSNameserver -- identifies authoritative DNS servers for a zonecisco.com NS ns1.cisco.com
SOAStart of Authority -- zone metadata (serial, refresh, retry)Primary DNS server, admin email, timers
TXTArbitrary text data (SPF, DKIM, domain verification)v=spf1 include:_spf.google.com ~all

NTP -- Network Time Protocol

Synchronized time is critical for log correlation, certificate validation, authentication protocols (Kerberos requires clocks within 5 minutes), and troubleshooting. NTP uses UDP port 123 and operates in a hierarchical stratum model. Stratum 0 = atomic clocks. Stratum 1 = directly connected to stratum 0. Each hop adds one stratum level.

! ── Point router to an NTP server ── Router(config)# ntp server 10.1.1.1 Router(config)# ntp server 10.1.1.2 ! Multiple NTP servers for redundancy ! ── Make this router an NTP master (authoritative source) ── Router(config)# ntp master 3 ! Stratum level 3 -- this router claims to be a stratum 3 source ! ── NTP authentication (secure time synchronization) ── Router(config)# ntp authenticate Router(config)# ntp authentication-key 1 md5 SecureTime2026 Router(config)# ntp trusted-key 1 Router(config)# ntp server 10.1.1.1 key 1 ! ── Verify NTP status ── Router# show ntp status Clock is synchronized, stratum 4, reference is 10.1.1.1 nominal freq is 250.0000 Hz, actual freq is 250.0000 Hz clock offset is 0.5432 msec, root delay is 12.45 msec Router# show ntp associations address ref clock st when poll reach delay offset disp *~10.1.1.1 10.0.0.1 3 45 64 377 4.2 0.54 1.2 +~10.1.1.2 10.0.0.1 3 32 64 377 5.1 0.67 1.5 ! * = selected master + = candidate ~ = configured

SNMP -- Simple Network Management Protocol

SNMP allows centralized monitoring and management of network devices. An SNMP manager (NMS) polls agents (routers, switches) for data stored in a Management Information Base (MIB). Agents can also send unsolicited alerts called traps.

VersionAuthenticationEncryptionNotes
SNMPv1Community string (plaintext)NoneOriginal version. Insecure. Do not use in production.
SNMPv2cCommunity string (plaintext)NoneImproved error handling, bulk retrieval. Still insecure authentication.
SNMPv3Username + HMAC (MD5/SHA)AES/DESRecommended. Provides authentication, integrity, and confidentiality.
! ── SNMPv2c Configuration ── Router(config)# snmp-server community ReadOnly RO Router(config)# snmp-server community ReadWrite RW Router(config)# snmp-server host 10.1.1.50 version 2c ReadOnly ! RO = read-only (GET operations only) ! RW = read-write (GET and SET operations) ! ── SNMPv3 Configuration (recommended) ── Router(config)# snmp-server group MONITOR-GROUP v3 priv Router(config)# snmp-server user admin1 MONITOR-GROUP v3 auth sha AuthPass123 priv aes 128 PrivPass456
SNMPv3 Security Levels:

noAuthNoPriv -- username only, no encryption. authNoPriv -- username + HMAC authentication, no encryption. authPriv -- authentication + AES encryption. Always use authPriv in production.

Syslog -- Centralized Logging

Syslog provides a standard mechanism for devices to send log messages to a central server. Messages are categorized by facility (which process generated it) and severity level (how critical it is). Cisco devices can log to the console, terminal lines, buffer, or a remote syslog server.

LevelKeywordDescriptionExample
0EmergencySystem is unusableHardware failure, system crash
1AlertImmediate action neededTemperature critical
2CriticalCritical conditionsMemory allocation failure
3ErrorError conditionsInterface down
4WarningWarning conditionsConfiguration change
5NotificationNormal but significantInterface up/down transition
6InformationalInformational messagesACL match logged
7DebuggingDebug-level messagesDetailed protocol operation
Mnemonic:

"Every Awesome Cisco Engineer Will Need Ice cream Daily" -- Emergency, Alert, Critical, Error, Warning, Notification, Informational, Debugging. Setting level 4 captures levels 0-4 (everything at that severity and above).

! ── Configure syslog server ── Router(config)# logging host 10.1.1.50 Router(config)# logging trap informational ! Sends levels 0-6 to the syslog server ! ── Configure logging to the buffer ── Router(config)# logging buffered 16384 debugging ! 16KB buffer, captures all levels 0-7 ! ── Add timestamps to log messages ── Router(config)# service timestamps log datetime msec ! Without timestamps, log correlation is nearly impossible ! ── Console logging ── Router(config)# logging console warnings ! Only levels 0-4 displayed on console (reduces noise) ! ── Verify logging configuration ── Router# show logging Syslog logging: enabled (0 messages dropped, 0 messages rate-limited) Console logging: level warnings, 42 messages logged Monitor logging: level debugging, 0 messages logged Buffer logging: level debugging, 1523 messages logged Logging to 10.1.1.50 (udp port 514, audit disabled)

DHCP Lease Lifecycle

DHCP leases are temporary. Understanding the lease lifecycle is important for capacity planning and troubleshooting address exhaustion.

TimerPercentageAction
T1 (Renewal)50% of lease timeClient sends unicast DHCPREQUEST to the original server to renew the lease
T2 (Rebinding)87.5% of lease timeIf T1 renewal failed, client broadcasts DHCPREQUEST to any DHCP server
Lease Expiry100%Client must stop using the IP address and restart the DORA process from scratch
Lease Time Strategy:

Short leases (1-4 hours) for guest networks, hotspots, and high-turnover environments -- addresses are recycled quickly. Long leases (7-30 days) for stable office environments -- reduces DHCP traffic and ensures devices keep their addresses.

DNS Resolution -- Step by Step

When a client queries www.cisco.com, the resolution follows a hierarchical process through multiple DNS servers.

/* DNS Resolution Flow */ Step 1: Client checks local DNS cache Step 2: Client queries configured DNS server (recursive resolver) Step 3: Resolver checks its cache -- if miss, queries root server Step 4: Root server responds: "Ask the .com TLD server at X.X.X.X" Step 5: Resolver queries .com TLD server Step 6: TLD server responds: "Ask cisco.com's authoritative server at Y.Y.Y.Y" Step 7: Resolver queries cisco.com's authoritative DNS server Step 8: Authoritative server responds: "www.cisco.com = 72.163.4.185" Step 9: Resolver caches the answer and returns it to the client Step 10: Client caches the answer and connects to 72.163.4.185 /* DNS Query Types */ Recursive: Client asks resolver to do all the work and return the final answer Iterative: Server returns the best answer it has (may be a referral to another server) /* TTL (Time to Live) */ Each DNS record has a TTL value (seconds). The resolver caches the record for TTL seconds before querying again. Low TTL = more DNS traffic but faster propagation of changes. High TTL = less traffic but stale records longer.

Key Takeaways

  • DHCP uses the DORA process: Discover, Offer, Request, Acknowledge (UDP ports 67/68)
  • ip helper-address relays DHCP broadcasts across router boundaries to remote DHCP servers
  • Cisco IOS DHCP server config: ip dhcp pool, network, default-router, dns-server
  • DNS maps names to IPs: A (IPv4), AAAA (IPv6), CNAME (alias), MX (mail), PTR (reverse)
  • NTP (UDP 123) synchronizes clocks using a stratum hierarchy -- critical for log correlation
  • SNMPv3 is the only version providing authentication and encryption -- always prefer it
  • Syslog levels 0-7: lower number = higher severity. Setting level N captures N and everything above it
  • service timestamps log datetime msec -- always enable this on every Cisco device
