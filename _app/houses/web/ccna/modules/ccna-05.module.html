IOS CLI Modes

Cisco IOS uses a hierarchical mode structure. Each mode provides a specific set of commands, and you must navigate between modes to perform different tasks. The prompt changes to indicate which mode you are in.

Mode Prompt Access Command Purpose
User EXEC Router> Default on login Limited monitoring only. Cannot view or change configuration. Can use ping, traceroute, show version.
Privileged EXEC Router# enable Full monitoring access. All show commands available. Can save config, copy files, reload. Cannot change configuration directly.
Global Configuration Router(config)# configure terminal Change device-wide settings: hostname, routing, AAA, banners, etc.
Interface Config Router(config-if)# interface Gi0/0 Configure a specific interface: IP address, shutdown/no shutdown, speed, duplex.
Router Config (OSPF, EIGRP) Router(config-router)# router ospf 1 Configure routing protocol parameters: network statements, area, timers.
Line Config Router(config-line)# line console 0 or line vty 0 15 Configure console, VTY (Telnet/SSH), and auxiliary line access.

Mode Navigation

/* Navigating between IOS modes */ Router> enable ! User EXEC -> Privileged EXEC Router# configure terminal ! Priv EXEC -> Global Config Router(config)# interface Gi0/0 ! Global -> Interface Config Router(config-if)# exit ! Back one level -> Global Config Router(config)# line console 0 ! Global -> Line Config Router(config-line)# end ! Any config mode -> Priv EXEC Router# disable ! Priv EXEC -> User EXEC Router> /* Keyboard shortcut: Ctrl+Z = same as "end" command Takes you from ANY config mode directly to Privileged EXEC */
Common Mistake:

New engineers often try to run show commands from Global Config mode and get errors. Most show commands must be run from Privileged EXEC mode. However, you can prefix any Privileged EXEC command with do from any config mode: Router(config)# do show ip interface brief

Essential Show Commands

Show commands are your primary diagnostic and verification tools. These commands do not change anything -- they only display information. Memorize these for both the exam and real-world troubleshooting.

Command Output
show running-config Current active configuration in RAM. This is what the device is actually using right now.
show startup-config Saved configuration in NVRAM. This is what loads on next boot. May differ from running-config if changes have not been saved.
show ip interface brief Summary of all interfaces: IP address, status (up/down), protocol (up/down). Quick health check.
show interfaces Detailed per-interface stats: MAC address, MTU, bandwidth, duplex, errors, CRC, collisions, input/output packets.
show version IOS version, uptime, hardware model, memory, boot image location, license info, config register.
show vlan brief VLAN database: VLAN ID, name, status, assigned ports. (Switches only)
show mac address-table MAC address table: which MAC is learned on which port. (Switches only)
show ip route Routing table: connected, static, and dynamic routes with next-hop and metrics.
show cdp neighbors Cisco Discovery Protocol: shows directly connected Cisco devices, their hostname, platform, and connected interface.

Saving Configuration

Cisco IOS stores two configurations: the running-config (active in RAM) and the startup-config (saved in NVRAM, loaded on boot). Any changes you make in config mode modify the running-config immediately. If you do not save, those changes are lost on reboot.

! Method 1: copy command (formal syntax) Router# copy running-config startup-config Destination filename [startup-config]? ! Press Enter to confirm Building configuration... [OK] ! Method 2: write memory (shorthand, same result) Router# write memory Building configuration... [OK] ! Method 3: abbreviated (even shorter) Router# wr ! Erase startup-config (factory reset on next boot) Router# erase startup-config Router# reload

Configuration Memory Locations

Memory Type Contents Volatile? Cisco Relevance
RAM Running-config, routing tables, ARP/MAC tables, packet buffers Yes (lost on reboot) show running-config
NVRAM Startup-config No (persists across reboots) show startup-config
Flash IOS image file(s) No show flash:
ROM POST, bootstrap, ROMMON No (read-only) Used for password recovery, disaster recovery boot

Password & Security Configuration

Securing a Cisco device starts with passwords at every access point: console, VTY lines (remote access), and privileged EXEC mode. Always use encrypted passwords and SSH instead of Telnet.

Enable Secret (Privileged EXEC Password)

! enable secret uses SHA-256 (type 9) or MD5 (type 5) hashing Router(config)# enable secret Cisco!SecurePass123 ! NEVER use "enable password" -- it stores in cleartext (type 0) ! "enable secret" ALWAYS takes priority over "enable password"

Console Line Security

Router(config)# line console 0 Router(config-line)# password ConsolePass!2026 Router(config-line)# login Router(config-line)# logging synchronous ! Prevents syslog messages from interrupting your typing Router(config-line)# exec-timeout 5 0 ! Auto-logout after 5 minutes idle Router(config-line)# exit

VTY Line Security (Remote Access)

Router(config)# line vty 0 15 ! Lines 0-15 = 16 concurrent sessions Router(config-line)# transport input ssh ! SSH only (disables Telnet) Router(config-line)# login local ! Use local username database Router(config-line)# exec-timeout 10 0 ! 10-minute idle timeout Router(config-line)# exit

Encrypt All Plaintext Passwords

Router(config)# service password-encryption ! This applies type 7 (Vigenere) encryption to all passwords ! currently stored in cleartext in the running-config. ! WARNING: Type 7 is easily reversible -- it is obfuscation, not security. ! Always prefer "enable secret" (type 5/8/9) for critical passwords.

Banner MOTD (Message of the Day)

Router(config)# banner motd # *********************************************** * WARNING: Authorized Access Only! * * Unauthorized access is prohibited and will * * be prosecuted to the fullest extent of law. * *********************************************** # ! The # character is the delimiter -- it marks the start and end. ! You can use any character that does not appear in the banner text. ! Legal banners should NOT say "Welcome" -- that implies authorization.

SSH Configuration (Step by Step)

SSH (Secure Shell) encrypts all management traffic between your workstation and the Cisco device. Cisco considers SSH mandatory for production environments. Telnet transmits everything in cleartext -- including passwords.

! Step 1: Set a hostname (required for RSA key generation) Router(config)# hostname HQ-RTR-01 ! Step 2: Set a domain name (required for RSA key generation) HQ-RTR-01(config)# ip domain-name hexworth.local ! Step 3: Generate RSA key pair (minimum 2048 bits for SSHv2) HQ-RTR-01(config)# crypto key generate rsa modulus 2048 The name for the keys will be: HQ-RTR-01.hexworth.local % The key modulus size is 2048 bits % Generating 2048 bit RSA keys, keys will be non-exportable... [OK] ! Step 4: Create a local user account HQ-RTR-01(config)# username admin privilege 15 secret AdminPass!2026 ! Step 5: Enable SSH version 2 HQ-RTR-01(config)# ip ssh version 2 ! Step 6: Configure VTY lines for SSH only HQ-RTR-01(config)# line vty 0 15 HQ-RTR-01(config-line)# transport input ssh HQ-RTR-01(config-line)# login local HQ-RTR-01(config-line)# exit ! Step 7: Verify SSH status HQ-RTR-01# show ip ssh SSH Enabled - version 2.0 Authentication timeout: 120 secs; Authentication retries: 3 Minimum expected Diffie Hellman key size : 2048 bits ! Step 8: View active SSH sessions HQ-RTR-01# show ssh Connection Version Mode Encryption Hmac State Username 0 2.0 IN aes256-ctr hmac-sha2 Session admin 0 2.0 OUT aes256-ctr hmac-sha2 Session admin
SSH Checklist (Exam and Lab):

1. Hostname set (not "Router" or "Switch"). 2. Domain name configured. 3. RSA keys generated (2048+ bits). 4. Local user created with secret. 5. ip ssh version 2 set. 6. VTY lines: transport input ssh + login local. Miss any step and SSH will not work.

IOS File System & Boot Process

Understanding where IOS stores its files and how it boots is critical for upgrades, disaster recovery, and password recovery.

Boot Sequence

1. POST (Power-On Self Test) - ROM runs hardware diagnostics - Tests CPU, memory, interfaces 2. Bootstrap - ROM loads the bootstrap program - Bootstrap locates and loads the IOS image 3. IOS Load - Bootstrap checks the config register and boot system commands - Default: loads IOS from flash memory - boot system flash:isr4300-universalk9.17.06.01.SPA.bin 4. Startup-Config Load - IOS loads startup-config from NVRAM into RAM (becomes running-config) - If no startup-config exists: enters Setup Mode (initial dialog) 5. CLI Ready - Device presents the CLI prompt - Router> (User EXEC)

Password Recovery Concepts

If you are locked out of a Cisco device, password recovery allows you to regain access. The process varies slightly between routers and switches, but the core concept is the same:

Step 1: Interrupt Boot Power cycle the device and send a Break signal during the first 60 seconds to enter ROMMON mode.
Step 2: Change Config Register Set the config register to 0x2142, which tells the router to skip loading startup-config on next boot.
Step 3: Reload and Reconfigure The device boots with no config. Copy startup-config to running-config, change the password, then reset the config register to 0x2102.
Step 4: Save and Reload Save the new running-config (with the new password) to startup-config. Reload. Normal boot resumes with the updated password.
/* Password Recovery -- Router (abbreviated) */ rommon 1 > confreg 0x2142 ! Skip startup-config rommon 2 > reset ! Reboot ! After reboot, device starts with no config Router> enable ! No password required Router# copy startup-config running-config ! Restore old config Router# configure terminal Router(config)# enable secret NewPassword!2026 Router(config)# config-register 0x2102 ! Normal boot next time Router(config)# end Router# copy running-config startup-config Router# reload
Security Note:

Password recovery requires physical access to the console port. This is why physical security of networking equipment is critical. An attacker with console access can reset any password. Some organizations disable password recovery entirely using no service password-recovery -- but this means a lost password requires a full factory reset and reconfiguration.

Key Takeaways

  • IOS has a hierarchy of CLI modes: User EXEC (>), Privileged EXEC (#), Global Config, and sub-config modes
  • Use enable to enter Privileged EXEC, configure terminal for Global Config, exit to go back, end to jump to Priv EXEC
  • Running-config lives in RAM (volatile); startup-config lives in NVRAM (persistent) -- save with copy run start or wr
  • Always use enable secret (not enable password) and service password-encryption
  • SSH requires: hostname, domain-name, RSA 2048+ keys, local user, ip ssh version 2, VTY transport input ssh
  • The boot process: POST -> Bootstrap -> IOS from Flash -> Startup-config from NVRAM
  • Password recovery uses config-register 0x2142 to skip startup-config, then restores and changes the password
  • Use do prefix to run show commands from any config mode: do show ip int brief
