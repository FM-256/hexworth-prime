ACL Concepts

An Access Control List is an ordered set of permit/deny rules that a router evaluates against each packet. ACLs filter traffic on interfaces (inbound or outbound), control VTY access, identify "interesting" traffic for NAT/VPN, and match routes in route-maps. Packets are checked against each rule in sequence -- the first match wins.

Top-Down Processing ACL rules are evaluated from top to bottom. The first rule that matches the packet determines the action (permit or deny). All subsequent rules are skipped.
Implicit Deny Every ACL ends with an invisible "deny any" rule. If no explicit rule matches the packet, it is dropped. You MUST add at least one permit statement or all traffic is blocked.
One ACL Per Interface Per Direction An interface can have one inbound ACL and one outbound ACL per protocol (IPv4, IPv6). Applying a new ACL replaces the existing one.
Inbound vs. Outbound Inbound: ACL is checked BEFORE routing decision. More efficient -- drops unwanted traffic early. Outbound: ACL is checked AFTER routing decision, just before the packet exits the interface.

Standard ACLs

Standard ACLs filter based on source IP address only. They cannot match destination, protocol, or port. Because they are limited, they should be placed as close to the destination as possible to avoid unintentionally blocking traffic to other destinations.

! ── Numbered Standard ACL ── ! Block 192.168.1.0/24 from reaching this router's network Router(config)# access-list 10 deny 192.168.1.0 0.0.0.255 Router(config)# access-list 10 permit any ! "permit any" is required -- otherwise the implicit deny blocks everything ! Apply inbound on the interface closest to the destination Router(config)# interface GigabitEthernet0/0 Router(config-if)# ip access-group 10 in ! ── Named Standard ACL ── Router(config)# ip access-list standard BLOCK-GUEST Router(config-std-nacl)# deny 10.10.10.0 0.0.0.255 Router(config-std-nacl)# permit any Router(config)# interface GigabitEthernet0/1 Router(config-if)# ip access-group BLOCK-GUEST in ! ── Standard ACL for VTY line access ── Router(config)# access-list 5 permit 10.1.1.0 0.0.0.255 Router(config)# line vty 0 15 Router(config-line)# access-class 5 in ! Only 10.1.1.0/24 can SSH/Telnet into this router

Wildcard Masks

Wildcard masks are the inverse of subnet masks. A 0 bit means "must match." A 1 bit means "don't care." To convert a subnet mask to a wildcard mask, subtract each octet from 255.

255.255.255.0 (/24)0.0.0.255192.168.1.0192.168.1.0 - 192.168.1.255 (256 hosts)
255.255.255.128 (/25)0.0.0.12710.0.0.010.0.0.0 - 10.0.0.127 (128 hosts)
255.255.255.240 (/28)0.0.0.15172.16.1.0172.16.1.0 - 172.16.1.15 (16 hosts)
255.255.0.0 (/16)0.0.255.255172.16.0.0172.16.0.0 - 172.16.255.255 (65,536 hosts)
255.255.255.255 (/32)0.0.0.010.1.1.1Exactly 10.1.1.1 (single host)
Shortcut Keywords:

host 10.1.1.1 is equivalent to 10.1.1.1 0.0.0.0 (match exactly one address). any is equivalent to 0.0.0.0 255.255.255.255 (match all addresses).

Extended ACLs

Extended ACLs can match source IP, destination IP, protocol (TCP, UDP, ICMP), and port numbers. Because they are specific, they should be placed as close to the source as possible to avoid wasting bandwidth carrying traffic that will be dropped later.

! ── Numbered Extended ACL ── ! Allow 192.168.1.0/24 to access web servers on 10.0.0.0/24 Router(config)# access-list 100 permit tcp 192.168.1.0 0.0.0.255 10.0.0.0 0.0.0.255 eq 80 Router(config)# access-list 100 permit tcp 192.168.1.0 0.0.0.255 10.0.0.0 0.0.0.255 eq 443 ! Allow DNS queries Router(config)# access-list 100 permit udp 192.168.1.0 0.0.0.255 host 10.0.0.53 eq 53 ! Allow ICMP (ping) for troubleshooting Router(config)# access-list 100 permit icmp 192.168.1.0 0.0.0.255 10.0.0.0 0.0.0.255 ! Deny everything else (implicit deny, but make it explicit for logging) Router(config)# access-list 100 deny ip any any log ! Apply close to source Router(config)# interface GigabitEthernet0/0 Router(config-if)# ip access-group 100 in
! ── Named Extended ACL (recommended -- easier to edit) ── Router(config)# ip access-list extended SALES-TO-SERVERS Router(config-ext-nacl)# 10 permit tcp 192.168.10.0 0.0.0.255 10.0.0.0 0.0.0.255 eq 443 Router(config-ext-nacl)# 20 permit tcp 192.168.10.0 0.0.0.255 10.0.0.0 0.0.0.255 eq 80 Router(config-ext-nacl)# 30 permit icmp 192.168.10.0 0.0.0.255 10.0.0.0 0.0.0.255 Router(config-ext-nacl)# 40 deny ip any any log ! Named ACLs use sequence numbers -- you can insert, delete, or reorder rules: ! Router(config-ext-nacl)# 15 permit tcp 192.168.10.0 0.0.0.255 host 10.0.0.25 eq 22 ! This inserts a new rule between sequence 10 and 20 ! ── Remove a specific line ── Router(config-ext-nacl)# no 30 ! Removes the ICMP permit rule (sequence 30)

ACL Placement Best Practices

Standard ACLs: Near Destination Standard ACLs only match source IP. If placed near the source, they block that source from ALL destinations -- not just the intended one. Place near the destination to be precise.
Extended ACLs: Near Source Extended ACLs match source, destination, protocol, and port. Place them near the source to drop unwanted traffic before it wastes bandwidth traversing the network.
Most Specific Rules First Because ACLs use first-match logic, place the most specific rules at the top. A broad "permit any" at the top would match everything and make all subsequent rules useless.
Document Every ACL Use the remark command to document each ACL's purpose. Undocumented ACLs become impossible to maintain and create security holes when administrators are afraid to modify them.
! ── Document ACLs with remarks ── Router(config)# ip access-list extended WEB-ACCESS Router(config-ext-nacl)# remark Allow Sales VLAN to reach web servers on DMZ Router(config-ext-nacl)# permit tcp 192.168.10.0 0.0.0.255 10.0.0.0 0.0.0.255 eq 443 Router(config-ext-nacl)# remark Block all other traffic and log for review Router(config-ext-nacl)# deny ip any any log

ACL Verification & Troubleshooting

! ── Show all ACLs with hit counts ── Router# show access-lists Extended IP access list SALES-TO-SERVERS 10 permit tcp 192.168.10.0 0.0.0.255 10.0.0.0 0.0.0.255 eq 443 (1523 matches) 20 permit tcp 192.168.10.0 0.0.0.255 10.0.0.0 0.0.0.255 eq 80 (892 matches) 30 permit icmp 192.168.10.0 0.0.0.255 10.0.0.0 0.0.0.255 (45 matches) 40 deny ip any any log (234 matches) ! ── Show which ACLs are applied to an interface ── Router# show ip interface GigabitEthernet0/0 GigabitEthernet0/0 is up, line protocol is up Internet address is 192.168.10.1/24 Inbound access list is SALES-TO-SERVERS Outgoing access list is not set ! ── Show a specific ACL ── Router# show access-lists SALES-TO-SERVERS ! ── Clear ACL counters ── Router# clear access-list counters

Common ACL troubleshooting methodology:

SymptomLikely CauseFix
All traffic blockedNo permit statement; implicit deny catches everythingAdd explicit permit rules before the implicit deny
ACL has no effectACL not applied to an interface or applied wrong directionCheck with show ip interface, apply with ip access-group
Wrong traffic matchedWildcard mask error or rules in wrong orderVerify wildcard masks; reorder rules (most specific first)
Cannot SSH to routerACL blocking management traffic (TCP 22)Add permit for management subnet before deny statements
Hit counts zero on a ruleEarlier rule matching the traffic firstCheck rule order; move specific rules above broader ones

IPv6 ACLs

IPv6 ACLs are always named (no numbered option) and always extended (can match source, destination, protocol, port). They include implicit permits for ICMPv6 Neighbor Discovery (ND) messages, which are essential for IPv6 operation.

! ── IPv6 Named ACL ── Router(config)# ipv6 access-list BLOCK-GUEST-V6 Router(config-ipv6-acl)# deny ipv6 2001:db8:10::/48 any Router(config-ipv6-acl)# permit ipv6 any any ! Apply to interface Router(config)# interface GigabitEthernet0/0 Router(config-if)# ipv6 traffic-filter BLOCK-GUEST-V6 in ! Note: IPv6 uses "traffic-filter" instead of "access-group" ! IPv6 ACLs have implicit entries at the end: ! permit icmp any any nd-na (Neighbor Advertisement) ! permit icmp any any nd-ns (Neighbor Solicitation) ! deny ipv6 any any (implicit deny all else)

Key Takeaways

  • ACLs process rules top-down -- first match wins, then processing stops
  • Every ACL ends with an implicit "deny any" -- always include at least one permit statement
  • Standard ACLs (1-99): source IP only, place near destination
  • Extended ACLs (100-199): source, dest, protocol, port -- place near source
  • Wildcard masks: inverse of subnet mask (255 - each octet). 0 = must match, 1 = don't care.
  • Named ACLs allow sequence numbers for inserting, deleting, and reordering rules
  • show access-lists shows hit counts; show ip interface shows which ACL is applied where
  • IPv6 ACLs are always named, use "traffic-filter" instead of "access-group"
