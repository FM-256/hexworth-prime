Why Multi-Area OSPF?

As a single-area OSPF network grows beyond approximately 50 routers, several problems emerge: the Link-State Database (LSDB) becomes large, consuming memory on every router; every topology change triggers a full SPF recalculation on every router; and the routing table grows without any way to summarize routes. Multi-area OSPF solves these problems by dividing the network into smaller logical areas.

Smaller LSDBs Each area maintains its own LSDB. Routers only store detailed topology for their own area. Inter-area routes appear as summary entries, not full topology.
Localized SPF A topology change in Area 1 only triggers SPF recalculation in Area 1. Area 2 routers are unaffected. Reduces CPU usage across the network.
Route Summarization ABRs can summarize routes at area boundaries, reducing routing table size. One summary entry replaces dozens of specific routes.
Fault Isolation Network instability (flapping links) in one area does not propagate to other areas. The ABR absorbs the impact and only updates summary routes if needed.

OSPF Area Types

OSPF defines several area types that control which LSAs are permitted within the area. Understanding area types determines what routes internal routers will see and how they reach external destinations.

Area TypeDescriptionLSAs Allowed
Backbone (Area 0)The core of the OSPF domain. All other areas MUST connect to Area 0 (directly or via virtual links). All inter-area traffic transits Area 0.All types (1, 2, 3, 4, 5)
Regular AreaStandard non-backbone area. Receives all LSA types including external routes. No restrictions on LSA flooding.All types (1, 2, 3, 4, 5)
Stub AreaBlocks Type 5 external LSAs. The ABR injects a default route (0.0.0.0/0) instead. Reduces LSDB and routing table size for areas that only have one exit point.Types 1, 2, 3 + default route
Totally StubbyCisco proprietary. Blocks both Type 3 (inter-area) and Type 5 (external) LSAs. Only default route and intra-area routes are present. Maximum LSDB reduction.Types 1, 2 + default route only
NSSA (Not-So-Stubby Area)Like stub area but allows limited external routes via Type 7 LSAs. The ABR converts Type 7 to Type 5 at the area boundary. Used when a stub area needs to redistribute from a local ASBR.Types 1, 2, 3, 7
/* Configure a stub area (on ALL routers in the area) */ Router(config)# router ospf 1 Router(config-router)# area 10 stub /* Totally stubby -- add on the ABR only */ ABR(config-router)# area 10 stub no-summary /* NSSA configuration */ Router(config-router)# area 20 nssa

ABR and ASBR Roles

Multi-area OSPF introduces two special router roles that operate at area boundaries. Understanding these roles is critical for predicting how routes propagate through the network.

ABR (Area Border Router) Has interfaces in two or more OSPF areas, with at least one interface in Area 0. Maintains a separate LSDB for each area. Generates Type 3 Summary LSAs to advertise routes between areas. Can perform route summarization at area boundaries.
ASBR (Autonomous System Boundary Router) Connects the OSPF domain to external routing domains (other protocols or autonomous systems). Performs route redistribution. Generates Type 5 External LSAs to inject external routes into OSPF. Can be in any area.
/* Verify router roles */ Router# show ip ospf Routing Process "ospf 1" with ID 1.1.1.1 ... This router is an ABR Number of areas: 2 Area 0 (Backbone): 3 interfaces Area 10: 2 interfaces /* A router is an ASBR when it redistributes external routes */ Router(config)# router ospf 1 Router(config-router)# redistribute static subnets /* This router is now an ASBR */

LSA Types Overview

OSPF uses different LSA types to carry different kinds of routing information. Each type has a specific scope -- some remain within an area, others are flooded across the entire OSPF domain. The CCNA exam focuses on Types 1, 2, 3, and 5.

LSA TypeNameGenerated ByScopeDescription
1Router LSAEvery routerIntra-area onlyDescribes the router's directly connected links and their states. Every router generates one Type 1 LSA per area. Does NOT cross area boundaries.
2Network LSADR onlyIntra-area onlyDescribes all routers attached to a multi-access segment. Only generated on segments where a DR is elected. Represents the "pseudo-node" for the network segment.
3Summary LSAABRInter-areaCarries inter-area route information. The ABR generates a Type 3 LSA for each network from one area and floods it into adjacent areas. Represents routes from other areas.
5External LSAASBREntire OSPF domainCarries routes redistributed from external sources (static routes, other routing protocols). Flooded throughout the entire OSPF domain (except stub/NSSA areas).

Multi-Area OSPF Configuration

Consider a three-area topology: Area 0 (backbone) connects Area 10 (branch) and Area 20 (data center). R1 is an internal router in Area 0. R2 is the ABR connecting Area 0 and Area 10. R3 is in Area 10. R4 is the ABR connecting Area 0 and Area 20.

/* ──── R2 (ABR: Area 0 + Area 10) ──── */ R2(config)# router ospf 1 R2(config-router)# router-id 2.2.2.2 /* Interface toward Area 0 backbone */ R2(config-router)# network 10.0.0.0 0.0.0.3 area 0 /* Interfaces toward Area 10 branch */ R2(config-router)# network 192.168.10.0 0.0.0.255 area 10 R2(config-router)# network 192.168.11.0 0.0.0.255 area 10 /* This makes R2 an ABR -- it has interfaces in two areas */ /* R2 will generate Type 3 Summary LSAs in both directions: */ /* Area 0 networks -> summarized into Area 10 */ /* Area 10 networks -> summarized into Area 0 */ /* ──── R3 (Internal router in Area 10) ──── */ R3(config)# router ospf 1 R3(config-router)# router-id 3.3.3.3 R3(config-router)# network 192.168.10.0 0.0.0.255 area 10 R3(config-router)# network 192.168.12.0 0.0.0.255 area 10 /* R3 sees Area 0 routes as O IA (OSPF Inter-Area) */ R3# show ip route ospf O IA 10.0.0.0/30 [110/65] via 192.168.10.1, 00:10:23, Gi0/0 O 192.168.11.0/24 [110/2] via 192.168.10.1, 00:10:20, Gi0/0 /* Notice: O = intra-area, O IA = inter-area */

Virtual Links

Every OSPF area must connect to Area 0. If an area cannot be directly connected (due to physical topology limitations), a virtual link tunnels OSPF through a transit area to reach the backbone. Virtual links are a workaround, not a best practice -- redesigning the topology is preferred.

/* Scenario: Area 30 connects to Area 10, not directly to Area 0 */ /* Configure a virtual link through Area 10 (transit area) */ /* On ABR between Area 0 and Area 10 (Router ID 2.2.2.2): */ R2(config)# router ospf 1 R2(config-router)# area 10 virtual-link 5.5.5.5 /* 5.5.5.5 = Router ID of the far-end ABR (Area 10 to Area 30) */ /* On ABR between Area 10 and Area 30 (Router ID 5.5.5.5): */ R5(config)# router ospf 1 R5(config-router)# area 10 virtual-link 2.2.2.2 /* 2.2.2.2 = Router ID of the far-end ABR (Area 0 to Area 10) */ /* Verify the virtual link */ R2# show ip ospf virtual-links Virtual Link OSPF_VL0 to router 5.5.5.5 is up Transit area 10, via interface GigabitEthernet0/1
Virtual Link Restrictions:

Virtual links cannot traverse stub areas, totally stubby areas, or NSSA areas. The transit area must be a normal (regular) area. If you need a virtual link through a stub area, you must first change the area type.

Inter-Area Route Summarization

Route summarization reduces the number of routes advertised between areas by combining multiple specific routes into a single summary route. Only ABRs can perform inter-area summarization. This reduces routing table size, decreases LSA flooding, and improves network stability.

/* Area 10 has these networks: */ /* 192.168.10.0/24, 192.168.11.0/24 */ /* 192.168.12.0/24, 192.168.13.0/24 */ /* Without summarization: 4 Type 3 LSAs flooded into Area 0 */ /* With summarization: 1 summary route */ /* Configure on the ABR */ ABR(config)# router ospf 1 ABR(config-router)# area 10 range 192.168.8.0 255.255.248.0 /* Summarizes 192.168.8.0 - 192.168.15.0 into one route */ /* Only advertises 192.168.8.0/21 into Area 0 */ /* ASBR external route summarization uses a different command: */ ASBR(config-router)# summary-address 10.0.0.0 255.0.0.0
Summarization Best Practice:

Design your IP addressing scheme with summarization in mind. Assign contiguous address blocks to each area so they can be cleanly summarized. A well-designed addressing plan is the foundation of scalable OSPF.

OSPF Authentication

OSPF supports authentication to prevent unauthorized routers from injecting false routing information. Two authentication types are available: simple password (Type 1) and MD5 hash (Type 2). MD5 is strongly recommended because simple authentication sends the password in cleartext.

/* MD5 Authentication -- Interface Level (recommended) */ Router(config)# interface GigabitEthernet0/0 Router(config-if)# ip ospf message-digest-key 1 md5 MySecretKey Router(config-if)# ip ospf authentication message-digest /* MD5 Authentication -- Area Level */ Router(config)# router ospf 1 Router(config-router)# area 0 authentication message-digest /* Then set the key on each interface in the area: */ Router(config)# interface GigabitEthernet0/0 Router(config-if)# ip ospf message-digest-key 1 md5 MySecretKey /* Simple Password Authentication (NOT recommended) */ Router(config-if)# ip ospf authentication-key cisco123 Router(config-if)# ip ospf authentication /* Verify authentication */ Router# show ip ospf interface GigabitEthernet0/0 | include authentication Message digest authentication enabled Youngest key id is 1
Authentication Must Match:

Both sides of an OSPF link must use the same authentication type and the same key. Mismatched authentication causes neighbors to fail during Hello exchange -- they will be stuck in Down or Init state. Always configure both ends before verifying.

OSPF Timer Tuning

OSPF uses timers to maintain neighbor relationships. The hello timer controls how often Hello packets are sent, and the dead timer defines how long a router waits before declaring a neighbor down. Tuning these timers can improve convergence speed at the cost of increased control-plane traffic.

TimerBroadcast DefaultNBMA DefaultPoint-to-Point Default
Hello Interval10 seconds30 seconds10 seconds
Dead Interval40 seconds120 seconds40 seconds
Wait Timer40 seconds120 seconds40 seconds
Retransmit Interval5 seconds5 seconds5 seconds
/* Modify hello and dead timers on an interface */ Router(config)# interface GigabitEthernet0/0 Router(config-if)# ip ospf hello-interval 5 Router(config-if)# ip ospf dead-interval 20 /* Dead interval is typically 4x hello, but can be set independently */ /* Sub-second convergence with BFD (Bidirectional Forwarding Detection) */ Router(config)# interface GigabitEthernet0/0 Router(config-if)# bfd interval 50 min_rx 50 multiplier 3 Router(config)# router ospf 1 Router(config-router)# bfd all-interfaces /* Verify timer settings */ Router# show ip ospf interface GigabitEthernet0/0 Timer intervals: Hello 5, Dead 20, Wait 20, Retransmit 5
Timer Match Requirement:

Hello and dead timers MUST match between OSPF neighbors on the same link. Mismatched timers prevent adjacency formation. If you change timers on one side, immediately change them on the other. Use show ip ospf interface to verify.

Interpreting show ip ospf database

The show ip ospf database command displays the complete Link-State Database. Each section corresponds to a different LSA type. Understanding this output is essential for verifying that the LSDB is consistent across routers in the same area.

Router# show ip ospf database /* Router Link States = Type 1 LSAs */ /* One per router in the area. Link ID = originating Router ID */ /* ADV Router = the router that created this LSA */ /* Net Link States = Type 2 LSAs */ /* One per multi-access network with a DR */ /* Link ID = DR's interface IP on that segment */ /* Summary Net Link States = Type 3 LSAs */ /* One per inter-area route, generated by ABR */ /* Link ID = destination network address */ /* AS External Link States = Type 5 LSAs */ /* One per external route, generated by ASBR */ /* Link ID = external destination network */ /* Key fields in each entry: */ /* Age: seconds since created (max 3600, then reflooded) */ /* Seq#: incremented on each update (detects stale LSAs) */ /* Checksum: integrity check */ /* All routers in the same area should have identical */ /* Type 1 and Type 2 LSA sections */

OSPF Route Redistribution Concepts

Route redistribution injects routes from one routing source into OSPF. The router performing redistribution becomes an ASBR and generates Type 5 External LSAs. Common redistribution sources include static routes, connected routes, EIGRP, RIP, and BGP. Redistribution requires careful planning to avoid routing loops.

/* Redistribute static routes into OSPF */ Router(config)# router ospf 1 Router(config-router)# redistribute static subnets /* "subnets" keyword is critical -- without it, only classful */ /* networks are redistributed */ /* Redistribute connected routes */ Router(config-router)# redistribute connected subnets /* Redistribute EIGRP into OSPF */ Router(config-router)# redistribute eigrp 100 subnets /* Redistributed routes appear as E2 (External Type 2) by default */ Router# show ip route ospf O E2 172.20.0.0/16 [110/20] via 10.0.0.1, 00:03:45, Gi0/0 /* E2 metric does not change as route propagates through OSPF */ /* E1 metric adds internal OSPF cost (specify metric-type 1) */
External Type 2 (E2) Default type. Cost is the seed metric set during redistribution and does not increase as the route is advertised through OSPF. Simpler but less optimal when multiple ASBRs exist for the same external route.
External Type 1 (E1) Cost = external seed metric + internal OSPF cost to reach the ASBR. Better path selection when multiple ASBRs inject the same route. Configure with metric-type 1 keyword.

Default Route Injection

To propagate a default route throughout the OSPF domain, use the default-information originate command. This is typically configured on a border router that has a default route to the internet or an upstream provider. The command creates a Type 5 External LSA for 0.0.0.0/0.

/* Standard: only advertises default if one exists in the routing table */ Router(config)# router ospf 1 Router(config-router)# default-information originate /* Always: advertises default route even if no default exists locally */ Router(config-router)# default-information originate always /* With metric (cost) override */ Router(config-router)# default-information originate always metric 100 /* Prerequisite: the originating router usually has a static default */ Router(config)# ip route 0.0.0.0 0.0.0.0 203.0.113.1 Router(config)# router ospf 1 Router(config-router)# default-information originate /* Verify on other routers */ Remote# show ip route O*E2 0.0.0.0/0 [110/1] via 10.0.0.1, 00:02:15, GigabitEthernet0/0 /* O*E2 = OSPF external type 2 default route */
E1 vs. E2 External Routes:

Type E2 (default) uses only the external metric -- the cost does not increase as the route is propagated through OSPF. Type E1 adds the internal OSPF cost to the external metric. E2 is simpler but E1 makes better path decisions when multiple ASBRs inject the same external route.

OSPFv3 for IPv6

OSPFv3 extends OSPF to support IPv6 addressing. The core protocol mechanics remain the same -- same packet types, same neighbor states, same area design. The key differences are in addressing and configuration syntax.

OSPFv3 Key Differences Uses link-local addresses for neighbor communication. Network command is replaced by per-interface configuration. Router ID is still a 32-bit value (configured in IPv4 dotted-decimal format even for IPv6).
OSPFv3 Address Families Modern OSPFv3 supports both IPv4 and IPv6 address families in a single process. This simplifies management for dual-stack networks. Configured using address-family ipv4/ipv6 unicast.
/* OSPFv3 configuration (traditional per-interface method) */ Router(config)# ipv6 unicast-routing Router(config)# ipv6 router ospf 1 Router(config-rtr)# router-id 1.1.1.1 Router(config)# interface GigabitEthernet0/0 Router(config-if)# ipv6 ospf 1 area 0 /* Verification */ Router# show ipv6 ospf neighbor Router# show ipv6 ospf interface Router# show ipv6 route ospf

Key Takeaways

  • Multi-area OSPF reduces LSDB size, localizes SPF calculations, and enables route summarization
  • Area 0 (backbone) is mandatory -- all other areas must connect to it
  • ABRs connect areas and generate Type 3 Summary LSAs; ASBRs connect to external domains and generate Type 5 External LSAs
  • Type 1 (Router) and Type 2 (Network) LSAs stay within an area; Type 3 and 5 cross boundaries
  • Stub areas block Type 5 LSAs; totally stubby areas block Types 3 and 5; NSSA allows local redistribution
  • Summarize at ABRs with area [id] range [network] [mask]
  • Use MD5 authentication -- never simple password in production
  • Hello and dead timers must match between neighbors
  • MTU mismatch causes neighbors to get stuck in ExStart/Exchange
  • Inject default route: default-information originate [always]
