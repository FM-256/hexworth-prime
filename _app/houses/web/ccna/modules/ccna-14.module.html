Why NAT Exists

IPv4 provides approximately 4.3 billion addresses (2^32). With billions of devices online, we exhausted the available public address space. IANA allocated the last /8 blocks to the Regional Internet Registries (RIRs) in 2011. NAT (Network Address Translation) is the mechanism that lets entire private networks share a smaller pool of public IP addresses.

RFC 1918 defines three private address ranges that are never routed on the public internet. Any organization can use these internally, relying on NAT to translate them to public addresses when traffic leaves the network.

RFC 1918 RangeCIDRAddressesTypical Use
10.0.0.0 - 10.255.255.25510.0.0.0/816,777,216Enterprise networks

Exam Tip:

NAT operates at Layer 3 (Network) of the OSI model. The router performing NAT modifies the IP header (and TCP/UDP port numbers for PAT) before forwarding the packet. The original source device has no knowledge that translation occurred.

NAT Address Terminology

Cisco uses four terms to describe addresses in NAT. Understanding these is critical for the CCNA exam. Think of "inside" as your network and "outside" as the internet. "Local" is the address as seen from the inside perspective; "global" is the address as seen from the outside perspective.

Inside Local The private IP address assigned to an inside host. Example: 192.168.1.50. This is how YOU see the device on your LAN.
Inside Global The public IP address representing the inside host after NAT translation. Example: 203.0.113.10. This is how the INTERNET sees your device.
Outside Local The address of the outside host as seen from the inside network. Usually identical to the outside global address unless destination NAT is in use.
Outside Global The actual public IP address of the external host. Example: 93.184.216.34. The real routable address of the remote server.
/* NAT Address Flow Diagram */ Inside Network NAT Router Outside Network Host A: 192.168.1.50 -----> Translates to -----> Server: 93.184.216.34 (Inside Local) 203.0.113.10 (Outside Global) (Inside Global) /* The host sends with source 192.168.1.50 The router replaces source with 203.0.113.10 The server sees the packet from 203.0.113.10 Return traffic is translated back to 192.168.1.50 */

NAT Types

TypeMappingUse CaseScalability
Static NAT 1:1 -- one private IP permanently mapped to one public IP Servers that need a consistent public address (web, mail, DNS) Poor -- requires one public IP per mapped device
Dynamic NAT Many:Many -- pool of public IPs assigned from a defined pool on demand Organizations with a block of public IPs, fewer internal hosts active at once Moderate -- limited by pool size
PAT (Overload) Many:1 -- all internal devices share one (or few) public IPs using unique port numbers Home routers, small to large enterprises. Most common NAT type on the internet. Excellent -- one public IP supports ~65,000 concurrent sessions

Static NAT Configuration

Static NAT creates a permanent one-to-one mapping between an inside local address and an inside global address. This is essential for servers that must be reachable from the internet at a predictable address.

! ── Step 1: Define the static mapping ── Router(config)# ip nat inside source static 192.168.1.10 203.0.113.10 ! ── Step 2: Designate inside and outside interfaces ── Router(config)# interface GigabitEthernet0/0 Router(config-if)# description LAN-facing interface Router(config-if)# ip address 192.168.1.1 255.255.255.0 Router(config-if)# ip nat inside Router(config-if)# no shutdown Router(config)# interface GigabitEthernet0/1 Router(config-if)# description WAN-facing interface Router(config-if)# ip address 203.0.113.1 255.255.255.0 Router(config-if)# ip nat outside Router(config-if)# no shutdown ! ── Static NAT with port mapping (port forwarding) ── Router(config)# ip nat inside source static tcp 192.168.1.10 80 203.0.113.10 80 Router(config)# ip nat inside source static tcp 192.168.1.10 443 203.0.113.10 443
Key Rule:

Every NAT configuration requires at least one interface marked ip nat inside and one marked ip nat outside. Without both designations, NAT will not translate any traffic.

Dynamic NAT Configuration

Dynamic NAT assigns public addresses from a defined pool on a first-come, first-served basis. When the pool is exhausted, subsequent connections are dropped until an address is freed.

! ── Step 1: Define the pool of public addresses ── Router(config)# ip nat pool PUBLIC-POOL 203.0.113.10 203.0.113.14 netmask 255.255.255.240 ! ── Step 2: Create an ACL to identify "interesting" traffic ── Router(config)# access-list 10 permit 192.168.1.0 0.0.0.255 ! ── Step 3: Bind the ACL to the NAT pool ── Router(config)# ip nat inside source list 10 pool PUBLIC-POOL ! ── Step 4: Designate interfaces (same as static) ── Router(config)# interface GigabitEthernet0/0 Router(config-if)# ip nat inside Router(config)# interface GigabitEthernet0/1 Router(config-if)# ip nat outside ! Note: This pool has 5 addresses (203.0.113.10 through .14) ! Only 5 inside hosts can be translated simultaneously

PAT (NAT Overload) Configuration

PAT is the most common form of NAT. It allows thousands of internal hosts to share a single public IP address by tracking sessions with unique source port numbers. Your home router uses PAT. Enterprise networks use PAT. It is everywhere.

! ── Method 1: PAT using the outside interface address ── Router(config)# access-list 1 permit 192.168.1.0 0.0.0.255 Router(config)# ip nat inside source list 1 interface GigabitEthernet0/1 overload Router(config)# interface GigabitEthernet0/0 Router(config-if)# ip nat inside Router(config)# interface GigabitEthernet0/1 Router(config-if)# ip nat outside ! ── Method 2: PAT using a NAT pool (multiple public IPs) ── Router(config)# ip nat pool PAT-POOL 203.0.113.10 203.0.113.12 netmask 255.255.255.240 Router(config)# access-list 1 permit 10.0.0.0 0.255.255.255 Router(config)# ip nat inside source list 1 pool PAT-POOL overload ! The keyword "overload" is what makes it PAT instead of Dynamic NAT. ! Without "overload", it is Dynamic NAT (one IP per host). ! With "overload", many hosts share each pool address via port numbers.
Exam Tip:

The overload keyword is the difference between Dynamic NAT and PAT. Dynamic NAT = ip nat inside source list [ACL] pool [name]. PAT = same command + overload.

PAT Translation Table

PAT tracks connections using the combination of IP address and port number. Each internal connection gets a unique port mapping on the public address, allowing the router to direct return traffic to the correct inside host.

/* Three devices browsing simultaneously via PAT */ Outbound (LAN --> Internet): Laptop 192.168.1.50:49152 --> NAT --> 203.0.113.1:50001 --> 93.184.216.34:443 Phone 192.168.1.51:49200 --> NAT --> 203.0.113.1:50002 --> 93.184.216.34:443 Desktop 192.168.1.52:49300 --> NAT --> 203.0.113.1:50003 --> 142.250.80.46:443 /* NAT Translation Table (show ip nat translations) */ Pro Inside Local Inside Global Outside Local Outside Global tcp 192.168.1.50:49152 203.0.113.1:50001 93.184.216.34:443 93.184.216.34:443 tcp 192.168.1.51:49200 203.0.113.1:50002 93.184.216.34:443 93.184.216.34:443 tcp 192.168.1.52:49300 203.0.113.1:50003 142.250.80.46:443 142.250.80.46:443 /* Return traffic: router uses port number to route response to the correct inside host. Port 50002 --> 192.168.1.51 */

NAT Verification & Troubleshooting

Cisco IOS provides several show and debug commands for validating NAT operation and troubleshooting translation failures.

! ── Show active translations ── Router# show ip nat translations Pro Inside global Inside local Outside local Outside global tcp 203.0.113.1:50001 192.168.1.50:49152 93.184.216.34:443 93.184.216.34:443 --- 203.0.113.10 192.168.1.10 --- --- ! ── Show NAT statistics (hit counts, pool usage) ── Router# show ip nat statistics Total active translations: 4 (1 static, 3 dynamic; 3 extended) Peak translations: 12, occurred 00:45:22 ago Outside interfaces: GigabitEthernet0/1 Inside interfaces: GigabitEthernet0/0 Hits: 1523 Misses: 4 Expired translations: 18 Dynamic mappings: -- Inside Source access-list 1 pool PAT-POOL refcount 3 ! ── Clear NAT translations (useful for testing) ── Router# clear ip nat translation * ! ── Debug NAT (real-time translation logging) ── Router# debug ip nat NAT: s=192.168.1.50->203.0.113.1, d=93.184.216.34 [12345] NAT*: s=93.184.216.34, d=203.0.113.1->192.168.1.50 [12346] ! NAT64 -- IPv4/IPv6 Coexistence

NAT64 translates between IPv6 and IPv4, enabling IPv6-only hosts to communicate with IPv4-only servers. This is a key transition technology as networks migrate to IPv6. NAT64 is often paired with DNS64, which synthesizes AAAA records for IPv4-only destinations.

Stateful NAT64 Maintains a translation table (like PAT). IPv6 hosts initiate connections to IPv4 servers. The NAT64 gateway translates headers and tracks sessions. Most common deployment.
Stateless NAT64 No translation table. Uses algorithmic mapping between IPv6 and IPv4 addresses. Requires pre-provisioned address mappings. Lower overhead, but less flexible.
DNS64 Works with NAT64 to synthesize IPv6 addresses (AAAA records) for IPv4-only destinations. The DNS64 server embeds the IPv4 address in a well-known IPv6 prefix (64:ff9b::/96).
Dual Stack Alternative Running both IPv4 and IPv6 simultaneously avoids NAT64 complexity. However, it requires IPv4 addresses on every interface, which is increasingly scarce and expensive.
! ── NAT64 Stateful Configuration Example ── Router(config)# nat64 enable Router(config)# nat64 prefix stateful 64:ff9b::/96 Router(config)# nat64 v4 pool NAT64-POOL 203.0.113.100 203.0.113.110 Router(config)# nat64 v6v4 list NAT64-ACL pool NAT64-POOL overload ! Verify NAT64 translations: Router# show nat64 translations

NAT Best Practices

PracticeRationale
Use PAT for general internet accessConserves public addresses; one IP supports thousands of sessions
Use Static NAT for servers onlyServers need consistent public addresses; workstations do not
Place NAT at the network edgeTranslate once at the boundary, not at multiple points
Document all static mappingsUndocumented entries become orphaned and create security holes
Monitor NAT table sizeLarge tables consume memory and CPU; set timeouts appropriately
Use specific ACLs for interesting trafficOverly broad ACLs translate traffic that should stay private

NAT Processing Order

Understanding when NAT translation occurs relative to other operations (routing, ACLs) is critical for troubleshooting. The processing order differs for inbound and outbound traffic.

DirectionProcessing Order
Inside to Outside (outbound)1. Routing decision, 2. Check outbound ACL, 3. NAT translation (inside local to inside global)
Outside to Inside (inbound)1. NAT translation (inside global to inside local), 2. Check inbound ACL, 3. Routing decision
Why This Matters:

ACLs on the outside interface reference the translated (global) address for inbound traffic but the original (local) address for outbound traffic. Getting this wrong means your ACLs will not match the traffic you intend.

Common NAT Scenarios

Small Office / Home Office (SOHO) PAT using the ISP-assigned address on the WAN interface. All devices share one public IP. This is the most common deployment on the planet -- every home router does this.
Enterprise Branch Office PAT with a pool of public addresses for employee internet access. Static NAT for servers that need inbound access (e.g., VPN concentrator). Separate policies for different traffic types.
Data Center Hosting Static NAT 1:1 mapping for each public-facing server. Web servers, mail servers, DNS servers each get a dedicated public IP. Firewall rules control which services are exposed.
Overlapping Address Spaces When two organizations with the same RFC 1918 ranges merge or connect via VPN. NAT translates both sides to unique address spaces to prevent conflicts.

Key Takeaways

  • NAT translates private RFC 1918 addresses to public addresses, extending IPv4's usable lifespan
  • Static NAT = 1:1 permanent mapping; Dynamic NAT = pool-based; PAT = many-to-one using ports
  • PAT (overload) is the most common -- one public IP supports ~65,000 concurrent translations
  • Every NAT config requires at least one ip nat inside and one ip nat outside interface
  • The "overload" keyword differentiates PAT from Dynamic NAT
  • show ip nat translations and show ip nat statistics are your primary troubleshooting tools
  • NAT64 bridges IPv6-only hosts to IPv4-only servers during the IPv6 transition
