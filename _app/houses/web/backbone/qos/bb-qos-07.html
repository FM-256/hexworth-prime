SD-WAN QoS Architecture

SD-WAN fundamentally changes the QoS model. Traditional QoS operates on a single path between two points -- you configure policy and live with whatever path the IGP selects. SD-WAN introduces application-aware routing: real-time path quality metrics (latency, jitter, packet loss) are continuously measured for each available WAN transport (MPLS, broadband, LTE), and traffic is automatically steered to the path best suited to each application class.

SD-WAN QoS vs Traditional QoS

Traditional QoS: one path, prioritize traffic when congested. SD-WAN QoS: multiple paths, select the best path per application class in real time, apply traditional QoS policies within each path's tunnel. SD-WAN does not replace per-class queuing -- it adds path intelligence on top of it.

Application Identification Deep packet inspection identifies applications (Webex, Salesforce, Office 365) beyond port numbers. Cisco SD-WAN uses Cisco NBAR2 signatures updated continuously from cloud intelligence.
Path Quality Monitoring BFD probes continuously measure latency, jitter, and packet loss on every WAN transport. Metrics are updated every second (or faster with sub-second BFD timers).
SLA-Based Steering Application policies define SLA thresholds (e.g., voice requires <150 ms latency, <1% loss). When the preferred path violates SLA, traffic automatically moves to the next-best compliant path.
Per-Tunnel QoS Traditional LLQ/CBWFQ policies are applied within each WAN tunnel, ensuring that even the SD-WAN-selected path respects queuing priorities.

SLA Classes and Traffic Classes

Cisco SD-WAN (Viptela) organizes traffic into queues based on DSCP values. The vEdge/cEdge supports multiple forwarding classes that map to transmit queues. QoS configuration in vManage defines class maps, schedulers, and mapping tables that are pushed to all edge devices centrally.

Application-Aware Routing and SLA Policies

Cisco SD-WAN -- App-Route Policy SLA Definition (vManage CLI)
! SLA classes define path quality requirements per application
policy
 sla-class VOICE-SLA
  latency   150
  jitter     30
  loss       1

 sla-class VIDEO-SLA
  latency   300
  jitter     50
  loss       2

 app-route-policy ENTERPRISE-AAR
  vpn-list ALL-VPNS
   sequence 10
    match
     dscp 46
    action
     sla-class VOICE-SLA
     preferred-color mpls
     ! Prefer MPLS for voice; fall back to broadband if SLA violated
   sequence 20
    match
     dscp 34 36
    action
     sla-class VIDEO-SLA
     preferred-color mpls biz-internet

Path Preference vs SLA Enforcement

SD-WAN AAR has two behaviors. "Preferred color" sends traffic to the preferred transport when it meets SLA. When the preferred transport violates SLA, traffic automatically moves to any transport currently meeting SLA. If no transport meets SLA, the SD-WAN controller can optionally trigger alerts or apply fallback actions. This real-time failover is the key differentiator vs. static policy routing.

Forward Error Correction and Packet Duplication

SD-WAN platforms provide two mechanisms to improve voice quality on lossy transports (broadband internet, LTE) without waiting for SLA-triggered path switching:

Forward Error Correction (FEC) Sender adds redundancy packets (XOR of packet groups) to allow the receiver to reconstruct dropped packets. Increases bandwidth consumption by ~25-33% but masks up to 50% packet loss for voice.
Packet Duplication Copies the same packet across two WAN transports simultaneously. The first copy that arrives is used. Doubles bandwidth consumption. Zero recovery time -- no jitter buffer depth needed for loss recovery.

FEC and Packet Duplication Overhead

Both mechanisms consume additional bandwidth. FEC adds 20-33% overhead; packet duplication effectively doubles bandwidth use for the affected traffic. Apply selectively to voice and video streams only -- applying to all traffic would create a bandwidth problem larger than the loss problem being solved. Configure in AAR policy for voice DSCP values only.

Practice Scenario

A retail company deploys SD-WAN at 200 branch sites. Each site has one MPLS circuit (10 Mbps) and one broadband DIA (50 Mbps). VoIP and video conferencing must be maintained even during MPLS outages.

  1. Define three SLA classes (voice, interactive video, bulk data) with appropriate thresholds for latency, jitter, and loss. Justify each value.
  2. Write the app-route policy that sends voice (EF) to MPLS when SLA is met, falls back to broadband when MPLS violates SLA, and uses FEC on the broadband path for voice.
  3. MPLS is currently at 9.8 Mbps utilization and voice quality is degrading. The SD-WAN shows MPLS meeting latency SLA but jitter is 45 ms (SLA threshold 30 ms). What happens automatically and what should you investigate?
  4. Explain why enabling packet duplication for Webex video (AF41) on both MPLS and broadband simultaneously might create a problem at the receiving end.

Key Takeaways

  • SD-WAN adds application-aware path selection on top of traditional QoS -- it selects which path, then queuing manages priority within that path
  • BFD probes continuously measure latency, jitter, and loss per WAN transport -- SLA violations trigger automatic traffic steering
  • AAR policies define: which traffic class, what SLA requirements, preferred transport, and fallback behavior
  • SLA thresholds are enforced in real time -- voice automatically fails over to any compliant path when MPLS degrades
  • FEC adds redundancy packets to mask loss; packet duplication sends copies on multiple paths -- both trade bandwidth for resilience
  • Apply FEC/duplication selectively to voice/video DSCP values -- applying to all traffic defeats the purpose
  • SD-WAN QoS policies are centrally managed and pushed to all edges via vManage -- eliminates per-device CLI configuration
