The Token Bucket Model

Both policing and shaping are based on the token bucket algorithm. Tokens accumulate in a bucket at a rate equal to the Committed Information Rate (CIR). Each packet consumes tokens proportional to its size. When tokens are available, the packet is conforming and transmitted (or passed). When the bucket is empty, the packet is exceeding -- and is either delayed (shaping) or dropped/remarked (policing).

ParameterFull NameDescription
CIRCommitted Information RateGuaranteed average rate in bps. Token replenishment rate.
PIRPeak Information RateMaximum allowed burst rate -- used in two-rate policing (dual token bucket).
BcCommitted Burst SizeMaximum bytes that can be sent in one Tc interval at CIR. Bc = CIR * Tc
BeExcess Burst SizeAdditional burst allowed beyond Bc if tokens have accumulated. One-time allowance after idle period.
TcTime IntervalMeasurement interval. Typically 125 ms (1/8 second). Tokens replenish every Tc. Tc = Bc / CIR

Token Bucket Calculation Example

CIR = 1 Mbps, Tc = 125 ms (default). Bc = CIR x Tc = 1,000,000 x 0.125 = 125,000 bytes = 125 KB. The device can burst at full line rate until the bucket empties, but averaged over any 125 ms window, transmission cannot exceed 125 KB (= 1 Mbps average). Be = an additional 125 KB can be used if tokens accumulated during idle periods.

Policing vs Shaping

Policing Instantaneous enforcement. Exceeding packets are dropped or remarked immediately. No buffering. Used on ingress or egress. Introduces no delay for conforming traffic.
Shaping Excess traffic is buffered and delayed until tokens are available. Smooths bursts rather than dropping them. Egress only. Adds latency to shaped traffic.

Policing is the right tool when enforcing service provider SLAs -- any traffic above the purchased CIR is immediately dropped or remarked to a lower DSCP class. Shaping is the right tool when the local network sends traffic faster than a WAN circuit supports -- rather than causing tail drops at the SP edge, the customer router shapes egress to the contracted CIR, allowing QoS queues to operate properly upstream.

Why Shape Before the WAN?

If your LAN interface is 1 Gbps and your WAN circuit is 10 Mbps, packets leaving the router hit the 1 Gbps LAN at full speed -- but the SP edge policer drops everything above 10 Mbps. By shaping to 10 Mbps at the customer edge, you control which packets get dropped locally (via QoS queuing) rather than having the SP randomly drop them. This allows your LLQ voice priority to function correctly.

MQC Policing Configuration

Cisco IOS -- Single-Rate Two-Action Policing
! Police incoming traffic from an untrusted source
! Conform = transmit, exceed = drop
policy-map INBOUND-POLICE
 class CUSTOMER-A-TRAFFIC
  police rate 10000000 bps burst 1250000
   conform-action transmit
   exceed-action drop

interface GigabitEthernet0/0
 service-policy input INBOUND-POLICE
Cisco IOS -- Two-Rate Three-Color Policing (CIR + PIR)
! Three-color: conform (green), exceed (yellow), violate (red)
! Conform <= CIR: transmit and mark AF41
! Exceed > CIR but <= PIR: transmit and mark AF43 (higher drop probability)
! Violate > PIR: drop
policy-map DUAL-RATE-POLICE
 class VIDEO-TRAFFIC
  police cir 5000000 bc 625000 pir 10000000 be 1250000
   conform-action set-dscp-transmit af41
   exceed-action  set-dscp-transmit af43
   violate-action drop

MQC Traffic Shaping

Cisco IOS -- Shaping to WAN CIR with Nested LLQ
! Inner policy handles LLQ for voice/video
policy-map INNER-QOS
 class VOICE-BEARER
  priority percent 20
 class VIDEO-CONF
  bandwidth percent 35
 class class-default
  fair-queue

! Outer policy shapes to WAN CIR and applies inner QoS
policy-map OUTER-SHAPE
 class class-default
  shape average 10000000
  ! Shape to 10 Mbps CIR
  service-policy INNER-QOS
  ! Nested policy: LLQ runs within the shaped tunnel

interface GigabitEthernet0/0
 service-policy output OUTER-SHAPE

Hierarchical QoS (HQoS)

The nested policy pattern above is called HQoS -- Hierarchical QoS. The outer policy shapes to the WAN CIR, creating a virtual 10 Mbps pipe. The inner policy runs LLQ within that shaped rate. This is the correct way to implement QoS on FastEthernet/GigabitEthernet interfaces connected to metered WAN circuits. Without the outer shaper, LLQ bandwidth percentages are relative to the full 1 Gbps physical interface -- not the 10 Mbps you are actually paying for.

Linux tc -- Traffic Control

Linux implements traffic shaping and policing through the tc (traffic control) command, which interfaces with the kernel's queuing disciplines (qdiscs). Common qdiscs include HTB (Hierarchical Token Bucket) for shaping with class hierarchies, and HFSC for more precise latency control.

Linux -- tc HTB Shaping to 10 Mbps with Classes
# Create root qdisc -- HTB handles class hierarchy
$ tc qdisc add dev eth0 root handle 1: htb default 30

# Root class: shape total egress to 10 Mbps
$ tc class add dev eth0 parent 1: classid 1:1 htb rate 10mbit

# Voice class: 2 Mbps guaranteed, 3 Mbps burst ceiling
$ tc class add dev eth0 parent 1:1 classid 1:10 htb \
    rate 2mbit ceil 3mbit prio 1

# Video class: 4 Mbps guaranteed
$ tc class add dev eth0 parent 1:1 classid 1:20 htb \
    rate 4mbit ceil 7mbit prio 2

# Default class: remaining bandwidth
$ tc class add dev eth0 parent 1:1 classid 1:30 htb \
    rate 1mbit ceil 10mbit prio 3

# Filters: classify DSCP EF (0xb8 = EF in TOS byte) to voice class
$ tc filter add dev eth0 parent 1:0 protocol ip u32 \
    match ip tos 0xb8 0xfc flowid 1:10

# Verify
$ tc -s class show dev eth0

Key Takeaways

  • Token bucket: tokens accumulate at CIR rate; conforming packets consume tokens; empty bucket means exceeding
  • CIR = committed rate; PIR = peak rate; Bc = committed burst; Be = excess burst; Tc = measurement interval
  • Policing drops or remarks exceeding traffic immediately -- no buffering, no added latency for conforming traffic
  • Shaping buffers exceeding traffic and delays it -- smooths bursts, adds latency, must be used before WAN policers
  • Two-rate three-color policing (CIR + PIR): conform = green, exceed = yellow (remark), violate = red (drop)
  • HQoS: outer policy shapes to WAN CIR; inner LLQ policy allocates bandwidth within the shaped rate -- required on GigE WAN handoffs
  • Linux tc with HTB provides Cisco-equivalent HQoS -- critical for Linux-based SD-WAN and uCPE deployments
