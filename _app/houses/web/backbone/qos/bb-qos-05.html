Voice Quality Requirements

VoIP calls have strict, non-negotiable quality requirements. These numbers come from ITU-T G.114 and industry standards for acceptable call quality:

ParameterRequirementImpact of Violation
One-way latency< 150 ms (preferred), < 400 ms (max)Conversation overlap -- parties talk over each other
Jitter< 30 ms (preferred < 10 ms)Gaps, clicks, chopped words in audio
Packet loss< 1% (preferred < 0.5%)Audio artifacts, garbling at > 3% becomes unintelligible
MOS score> 4.0 (excellent = 4.5, good = 4.0)Mean Opinion Score: subjective call quality metric

QoS Cannot Fix Bandwidth Problems

If a link is 100% saturated with voice traffic, no amount of QoS policy will reduce latency. QoS gives voice priority over competing traffic. If voice itself is the oversubscribing source, you need Call Admission Control (CAC) to limit the number of simultaneous calls, or you need more bandwidth.

Codec Bandwidth Calculation

VoIP bandwidth is not just the codec payload rate. Each RTP packet has overhead from IP, UDP, and RTP headers, plus Layer 2 framing. The actual bandwidth per call depends on the codec, packetization interval, and transport headers.

Header breakdown for G.711 on Ethernet (20 ms ptime): IP header = 20 bytes, UDP = 8 bytes, RTP = 12 bytes, Ethernet = 18 bytes. Total overhead = 58 bytes. Payload = 160 bytes. Total per packet = 218 bytes. Packets per second = 1000/20 = 50 pps. Bandwidth = 218 x 8 x 50 = 87,200 bps ≈ 87 kbps per call (each direction).

cRTP -- Compressed RTP

On low-speed serial links, cRTP (Compressed RTP) reduces the IP/UDP/RTP header from 40 bytes down to 2-4 bytes. This is significant when headers represent a large fraction of total packet size. G.729 at 8 kbps with 40-byte headers sees ~74% overhead -- cRTP reduces effective bandwidth nearly in half. Enable with ip rtp header-compression on the interface.

RTP and Jitter Buffers

Real-time Transport Protocol (RTP) carries voice and video payload over UDP. RTP packets include sequence numbers and timestamps, which endpoints use to detect reordering and calculate jitter. The jitter buffer at the receiving endpoint holds incoming packets briefly to smooth out arrival time variation before playing them out.

Fixed Jitter Buffer Always delays playout by a fixed amount (e.g., 50 ms). Predictable but wastes buffer depth when jitter is low. Legacy POTS gateways.
Adaptive Jitter Buffer Dynamically adjusts playout delay based on measured network jitter. Most modern IP phones. Balances low latency with protection against jitter spikes.
RTCP (Control) RTP Control Protocol. Carries statistics: jitter, packet loss, round-trip delay. Sent periodically -- QoS tools can read RTCP reports for IP SLA monitoring.
SRTP (Secure RTP) Encrypts RTP payload and authenticates headers. Standard for enterprise and WebRTC. Adds minimal overhead but prevents eavesdropping of voice streams.

Voice VLAN Design

Separating voice traffic into a dedicated VLAN provides both QoS and security benefits. The access switch port is configured as a multi-VLAN port (data VLAN for the PC, voice VLAN for the IP phone). The phone negotiates the voice VLAN via CDP or LLDP-MED. Voice frames leave the phone tagged with the voice VLAN ID and CoS 5 (EF equivalent at Layer 2).

Cisco IOS -- Voice VLAN Access Port Configuration
! Switch port with PC in VLAN 10, IP phone in VLAN 110
interface GigabitEthernet1/0/1
 description IP-Phone-plus-PC
 switchport mode access
 switchport access vlan 10
 switchport voice vlan 110
 ! Trust CoS from IP phone, reclassify PC traffic
 mls qos trust cos
 mls qos cos override
 spanning-tree portfast

Practice Scenario

You are designing a 20-site enterprise VoIP deployment. Each site has a 10 Mbps WAN link. Peak concurrent calls per site: 30 G.711 calls and 5 G.729 calls simultaneously.

  1. Calculate the exact bandwidth required for 30 G.711 calls and 5 G.729 calls (include all headers). Is the 10 Mbps link sufficient if voice gets 25% priority?
  2. Users at one site report choppy audio but the LLQ shows no drops in the voice class. Identify three possible causes not related to QoS policy drops.
  3. A new Cisco IP phone is plugged in and the voice VLAN is not being assigned. What two protocols could be used to auto-provision the voice VLAN and how would you verify?
  4. Explain why SRTP does not affect QoS policy effectiveness even though the payload is encrypted.

Key Takeaways

  • Voice requires: latency < 150 ms, jitter < 30 ms, packet loss < 1% -- all three must be met simultaneously
  • G.711 consumes ~87 kbps per call (including headers) at 20 ms ptime -- always calculate with headers for capacity planning
  • Jitter buffers absorb arrival-time variation -- adaptive buffers are standard; excessive jitter causes audio gaps regardless of QoS
  • RTP carries voice payload over UDP; RTCP carries per-stream statistics; SRTP encrypts the payload without affecting QoS classification
  • Voice VLAN separates phone traffic from data traffic at Layer 2 -- provides QoS trust point and security isolation
  • LLQ strict-priority queue handles voice RTP; separate CBWFQ class handles signaling -- never combine them in the same class
  • QoS cannot compensate for insufficient bandwidth -- use Call Admission Control when voice load exceeds LLQ policing rate
