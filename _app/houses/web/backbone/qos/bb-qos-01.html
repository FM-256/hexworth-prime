Why QoS?

Networks carry traffic with wildly different requirements. A VoIP call needs low latency (under 150 ms one-way) and minimal jitter (under 30 ms), but can tolerate minor packet loss. A file transfer tolerates seconds of delay but demands zero loss. Bulk backups are happy with any available bandwidth. Without Quality of Service mechanisms, all traffic competes equally -- and the applications that can least tolerate congestion suffer most.

QoS is the set of mechanisms that allows a network to differentiate traffic and provide preferential treatment to sensitive flows. It does not create bandwidth -- it allocates what exists according to policy.

The Three Problems QoS Solves

  • Bandwidth -- guaranteeing minimum bandwidth for critical applications
  • Delay (latency) -- limiting end-to-end transit time, especially for voice/video
  • Jitter -- smoothing variation in delay, which destroys real-time media quality
Best Effort (Default) No QoS. All packets treated identically. First-in, first-out. Adequate for non-converged networks carrying only data.
IntServ (RSVP) Per-flow resource reservation using RSVP signaling. Hard guarantees but does not scale beyond small networks -- state maintained per flow at every hop.
DiffServ (DSCP) Class-based treatment using DSCP markings in the IP header. Scales to internet size. The dominant QoS model in enterprise and service provider networks.
MQC (Cisco) Modular QoS CLI -- class-map to classify, policy-map to define actions, service-policy to apply. The standard IOS framework for implementing DiffServ.

DSCP and IP Precedence

The IPv4 Type of Service (ToS) byte was repurposed by RFC 2474 into the Differentiated Services field (DS field). The top 6 bits form the DSCP value (0-63). The bottom 2 bits are the ECN field (Explicit Congestion Notification). Legacy IP Precedence used only the top 3 bits (values 0-7), and DSCP was designed to be backward compatible with it.

Within the AF (Assured Forwarding) classes, the DSCP value encodes both the class (1-4) and the drop precedence (1-3, where higher = more likely to be dropped under congestion). AF41 = class 4, drop precedence 1 (lowest drop probability). AF43 = class 4, drop precedence 3 (highest drop probability within class 4).

802.1p and CoS Marking

Layer 2 QoS uses the 802.1p Priority Code Point (PCP) field in the 802.1Q VLAN tag. This 3-bit field (values 0-7) is called Class of Service (CoS). It serves the same purpose as DSCP but only within a Layer 2 domain -- it is not carried in untagged frames or across routed boundaries.

Trust Boundaries

A trust boundary is the point in the network where the QoS markings in incoming packets are either trusted and preserved, or overwritten with locally determined values. The trust boundary is a security and policy decision -- you control who is allowed to set QoS markings.

The Trust Boundary Problem

If you trust user devices to set their own DSCP markings, a malicious or misconfigured endpoint can mark all its traffic EF (voice priority), starving legitimate voice traffic. The trust boundary should be placed at the first network device that you control -- typically the access-layer switch port connected to the endpoint.

Common trust boundary placements:

  • IP phones: Trust the phone's DSCP markings, remark PC traffic attached through the phone to CS1 or BE
  • Access switches: Trust DSCP from known IP phones; do not trust markings from PCs or unknown devices
  • Distribution/core: Trust all markings from access layer -- classification should already be done
  • WAN edge: May remark or re-classify based on service provider QoS policy
Cisco IOS -- MQC Classification and Marking
! Step 1: Class maps define what to match
class-map match-any VOICE-BEARER
 match dscp ef
 match dscp cs5

class-map match-any VIDEO-CONF
 match dscp af41 af42 af43

class-map match-any CALL-SIGNALING
 match dscp af31 cs3

class-map match-any NET-CONTROL
 match dscp cs6 cs7

! Step 2: Policy map defines actions per class
policy-map MARK-INBOUND
 class VOICE-BEARER
  set dscp ef
 class VIDEO-CONF
  set dscp af41
 class CALL-SIGNALING
  set dscp af31
 class NET-CONTROL
  set dscp cs6
 class class-default
  set dscp default

! Step 3: Apply at the trust boundary (access port)
interface GigabitEthernet0/1
 service-policy input MARK-INBOUND

NBAR -- Protocol-Based Classification

Network-Based Application Recognition (NBAR) allows classification by application rather than just by port number or DSCP value. NBAR uses deep packet inspection to identify protocols including those that use dynamic port numbers or run over HTTP. It is CPU-intensive but provides the most accurate classification when markings cannot be trusted.

Cisco IOS -- NBAR Classification in MQC
! Classify Webex and Zoom traffic using NBAR
class-map match-any VIDEO-APPS
 match protocol webex-media
 match protocol zoom

class-map match-any VOICE-APPS
 match protocol skinny
 match protocol sip
 match protocol h323

policy-map CLASSIFY-NBAR
 class VIDEO-APPS
  set dscp af41
 class VOICE-APPS
  set dscp ef
 class class-default
  set dscp default

interface GigabitEthernet0/0
 ip nbar protocol-discovery
 service-policy input CLASSIFY-NBAR

NBAR2 and Protocol Packs

Modern IOS-XE uses NBAR2 with regularly updated Protocol Packs that add recognition signatures for new applications without a software upgrade. Use show ip nbar protocol-discovery to see recognized applications per interface and their traffic volumes.

Practice Scenario

Your network carries VoIP, video conferencing, ERP database traffic, and general internet browsing. You are deploying QoS at the access layer.

  1. Map each traffic type to the appropriate DSCP value and PHB class, justifying each choice.
  2. A PC is plugged into an IP phone's data port. The phone tags its own RTP traffic as DSCP EF. What should the switch do with CoS markings arriving from the PC's port on the phone?
  3. Write an MQC class-map that matches traffic from the ERP server at 10.10.5.0/24 to source port range 1521-1522 (Oracle DB) and marks it AF21.
  4. Explain why placing the trust boundary at the PC NIC rather than the access switch is a security risk.

Key Takeaways

  • QoS solves bandwidth, delay, and jitter problems -- it manages existing bandwidth, it does not create it
  • DiffServ using DSCP is the dominant QoS model -- scalable and ubiquitous across enterprise and SP networks
  • DSCP uses 6 bits (0-63); EF (46) for voice, AF4x for video, AF3x for signaling, CS6/CS7 for network control
  • CoS (802.1p) operates at Layer 2 within the VLAN tag -- not carried across routed hops
  • Trust boundaries define where incoming markings are honored vs. overwritten -- always classify at the network edge you control
  • MQC uses class-map (match) + policy-map (action) + service-policy (application) -- consistent across all Cisco IOS QoS features
  • NBAR provides application-layer classification using DPI -- useful when port-based matching is insufficient
