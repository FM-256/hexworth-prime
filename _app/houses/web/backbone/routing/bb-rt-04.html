OSPF LSA Types Reference

OSPF uses seven LSA types to carry different kinds of topology and routing information. Each LSA type has defined origination rules, flooding scope, and behavior at area boundaries:

TypeNameOriginated ByFlooding ScopeContents
1Router LSAEvery routerWithin area onlyAll router's interfaces, costs, neighbor relationships in that area
2Network LSADR onlyWithin area onlyList of routers on a multi-access segment, generated by DR
3Summary LSAABRInto area from backboneInter-area routes (prefixes from other areas) -- translated by ABR
4ASBR Summary LSAABRInto areaLocation/cost to reach an ASBR (used by remote areas to find external routes)
5AS External LSAASBREntire OSPF domainExternal routes redistributed into OSPF. Type E1 or E2. NOT flooded into stub areas.
6Group MembershipMulticast routersWithin areaMOSPF -- multicast extensions. Rarely deployed.
7NSSA External LSAASBR in NSSANSSA area onlyExternal routes in NSSA areas. ABR translates Type 7 to Type 5 for propagation.

OSPF Area Types

Standard Area Receives all LSA types (1-5). Full LSDB. Used for the backbone (area 0) and any area needing external route visibility.
Stub Area Blocks Type 5 LSAs (external). ABR injects Type 3 default route. Reduces LSDB. Use when area routers don't need external route specifics.
Totally Stubby Area Blocks Type 3, 4, and 5 LSAs. Only a single Type 3 default route from the ABR. Minimum LSDB. Cisco proprietary. Best for spoke sites with single ABR exit.
NSSA (Not-So-Stubby Area) Like stub (no Type 5) but allows local ASBR redistribution using Type 7. ABR translates Type 7 to Type 5 at the boundary. Use when stub area needs a local ASBR.
Cisco IOS -- OSPF Area Type Configuration
! Stub area (ABR and all internal routers must be configured)
router ospf 1
 area 10 stub
 ! On ABR and all routers in area 10

! Totally stubby (ABR only -- internal routers just use "stub")
router ospf 1
 area 20 stub no-summary
 ! "no-summary" suppresses Type 3 LSAs -- only on the ABR

! NSSA area
router ospf 1
 area 30 nssa

! NSSA totally stubby (suppress Type 3 but allow Type 7)
router ospf 1
 area 30 nssa no-summary

Type 7 to Type 5 Translation

In an NSSA, when an ASBR redistributes external routes, it generates Type 7 LSAs (NSSA External). These only flood within the NSSA area. When the ABR receives a Type 7 LSA, it translates it to a Type 5 LSA and floods it into the backbone so other areas can reach those external destinations. If multiple ABRs exist, the one with the highest Router ID performs the translation (bit in the Type 7 header).

NSSA Translation and the P-bit

The Propagate (P) bit in the Type 7 LSA header controls whether the ABR translates it to Type 5. By default, ASBR-originated Type 7s have P=1 (translate). If P=0, the route stays in the NSSA and is not propagated to other areas. Use area [n] nssa no-redistribution on an ABR that is also an ASBR to prevent it from translating its own redistributed routes.

OSPF Virtual Links

OSPF requires all areas to be connected to Area 0 (the backbone). When a non-backbone area cannot be directly connected to Area 0 -- for example, in a merger where two OSPF domains are joined -- a Virtual Link provides a logical connection through a transit area. Virtual Links run over an existing OSPF adjacency path and appear to be a point-to-point connection to Area 0.

Virtual Links Are a Workaround, Not a Design

Virtual links are a transitional tool for network mergers and topological constraints. They should not appear in normal network designs. Use them only when physically connecting an area to Area 0 is impossible or impractical. Virtual links cannot traverse stub areas, and their use indicates a topology that should be refactored when possible.

Cisco IOS -- OSPF Virtual Link Configuration
! Area 20 is disconnected from Area 0. Area 10 is the transit area.
! Configure virtual link on BOTH ABRs: ABR1 (connects Area 0 and Area 10)
! and ABR2 (connects Area 10 and Area 20)

! On ABR1 (Router ID 10.0.0.1)
router ospf 1
 area 10 virtual-link 10.0.0.2
 ! Specify the Router ID of the far-end ABR (ABR2)

! On ABR2 (Router ID 10.0.0.2)
router ospf 1
 area 10 virtual-link 10.0.0.1
 ! Specify the Router ID of ABR1

! Verify
ABR1# show ip ospf virtual-links
Virtual Link OSPF_VL0 to router 10.0.0.2 is up
  Run as demand circuit
  DoNotAge LSA allowed.
  Transit area 10, via interface GigabitEthernet0/1
  Transmit Delay is 1 sec, State POINT_TO_POINT

OSPFv3 for IPv6

OSPFv3 (RFC 5340) supports IPv6 natively. Key changes from OSPFv2: uses link-local addresses for neighbor relationships (not interface IP addresses), runs over IPv6 (protocol 89 over IPv6), removes network address from LSAs (addressing is in separate LSA types), adds support for address families (can carry both IPv4 and IPv6 in one process with RFC 5838).

Cisco IOS -- OSPFv3 for IPv6 Configuration
! IPv6 must be enabled globally
ipv6 unicast-routing

! Enable OSPFv3 process
router ospfv3 1
 router-id 10.0.0.1
 ! Router ID is still required -- must be configured manually
 ! (no IPv4 interfaces to auto-derive from in pure IPv6 env)

interface GigabitEthernet0/0
 ipv6 address 2001:db8:1::1/64
 ospfv3 1 ipv6 area 0

interface Loopback0
 ipv6 address 2001:db8::1/128
 ospfv3 1 ipv6 area 0

! Verify OSPFv3 neighbors (uses link-local addresses)
R1# show ospfv3 neighbor

          OSPFv3 1 address-family ipv6 (router-id 10.0.0.1)

Neighbor ID     Pri   State     Dead Time   Interface ID    Interface
10.0.0.2          1   FULL/DR   00:00:33    4               GiO/0

Practice Scenario

An enterprise network has three OSPF areas. Area 0 (backbone), Area 10 (branch offices -- needs a local ASBR redistributing static routes from branch firewalls), Area 20 (remote sites with only one ABR and no external routing needed).

  1. What area type should Area 10 be? Area 20? Write the complete configuration for both ABRs and explain which LSA types each area receives.
  2. After configuring Area 10 as NSSA, the ASBR in Area 10 redistributes 10 static routes. How many Type 7 LSAs appear in Area 10's LSDB? How many Type 5 LSAs appear in Area 0? What triggers the translation?
  3. A post-merger scenario: the acquired company runs OSPF Area 50, but Area 50 cannot be directly connected to the existing Area 0 -- it must transit through Area 30. Write the virtual link configuration on both ABRs and explain what LSA types can the transit area NOT be configured as.
  4. OSPF is consuming excessive memory on branch routers in Area 20. You change it from standard to totally-stubby. What LSA types are now blocked, and what default route is installed and from whom?

Key Takeaways

  • Type 1/2 LSAs: intra-area topology. Type 3: inter-area (from ABR). Type 4: ASBR location. Type 5: external routes (domain-wide). Type 7: NSSA externals
  • Stub: blocks Type 5. Totally-stubby: blocks Type 3, 4, 5 (Cisco). NSSA: blocks Type 5 but allows Type 7 from local ASBR
  • Type 7 flooded only within NSSA; ABR with highest RID translates Type 7 to Type 5 for the backbone (P-bit must be set)
  • Virtual links provide a logical backbone connection through a transit area -- transitional workaround, not a design pattern
  • Virtual links cannot traverse stub areas -- the transit area must be a standard area (or NSSA)
  • OSPFv3 uses link-local addresses for adjacencies, runs natively over IPv6, separates addressing from topology information
  • OSPFv3 router-id must be manually configured in IPv6-only environments -- no IPv4 interfaces to derive it from automatically
