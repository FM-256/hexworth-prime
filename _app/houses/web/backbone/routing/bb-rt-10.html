Core Routing Design Principles

Good routing design is invisible in operation — traffic flows optimally, failures converge quickly, and the configuration is simple enough to troubleshoot under pressure. Poor design is apparent only when it fails. The foundational principle is that routing complexity must be justified by a specific operational requirement; complexity introduced without purpose creates fragility.

Three properties drive design decisions: scalability (how many routers and routes can the design support without degradation), convergence (how quickly does the network reach a stable state after a topology change), and operational simplicity (how easy is it to understand and troubleshoot the routing domain).

Scalability Hierarchical areas, summarization, and controlled redistribution contain the blast radius of topology changes. A flat design with 500 routers in a single OSPF area cannot scale.
Convergence BFD + tuned hello timers + pre-computed backup paths (IP FRR, LFA, TI-LFA) drive sub-second convergence. Protocol selection matters: EIGRP converges faster than OSPF in some topologies.
Determinism Traffic must follow predictable paths. Avoid ECMP where asymmetric routing creates firewall state issues. Use metrics deliberately, not incidentally.
Failure Isolation Area boundaries, redistribution filters, and summarization prevent a single router's failure from triggering a full-domain SPF recalculation or route churn everywhere.
Hierarchical Routing Design

Hierarchical design divides the routing domain into layers with clearly defined roles: core (high-speed transit only), distribution (aggregation and policy enforcement), and access (endpoint connectivity). Each layer has reduced visibility into the details of adjacent layers, achieved through summarization.

! ===== Three-Tier OSPF Hierarchy ===== ! Core routers: Area 0 backbone only — no non-backbone adjacencies ! Distribution routers: ABR between Area 0 and access areas ! Access routers: Stub areas — no transit, default route only ! Distribution router — ABR configuration: router ospf 1 router-id 10.255.0.2 area 10 stub no-summary ! 'no-summary' = totally stubby — only default injected into area area 10 range 10.10.0.0 255.255.0.0 ! Summarize all area 10 prefixes into a single /16 at the ABR ! Access area sees no backbone details; backbone sees one summary ! ===== IS-IS Two-Level Hierarchy ===== ! Level-2: backbone — all L2-only routers in the core ! Level-1: area — distribution/access in their own area ! L1/L2 (ABR equivalent): route leaking with explicit filter router isis CORE is-type level-2-only net 49.0001.0000.0000.0002.00 ! L1/L2 border router with controlled leaking: router isis CORE is-type level-1-2 net 49.0002.0000.0000.0001.00 summary-address 10.20.0.0/16 level-2 ! Announce only the summary to L2, not individual L1 prefixes
Summarization is the Key to Hierarchy

A hierarchical design without summarization is just a flat design with area labels. The value comes entirely from summary routes: failures within an area trigger SPF only within that area, and only the summary (if it disappears) propagates the failure signal upward. Proper summarization requires disciplined IP addressing — contiguous blocks per area.

Topology Patterns: Hub-and-Spoke, Partial Mesh, Full Mesh

Physical topology shapes routing protocol behavior. NBMA (non-broadcast multi-access) links like DMVPN and MPLS L3VPN require explicit neighbor configuration or network type adjustments. Full mesh provides maximum redundancy but O(n^2) scaling — used in core layers only.

Pattern Routing Protocol Fit Scalability Use Case
Hub-and-Spoke EIGRP stub, OSPF with hub as DR, BGP route-reflector at hub High — spoke count scales linearly Branch WAN, DMVPN Phase 1, SD-WAN hub
Partial Mesh OSPF NBMA with selected neighbors, EIGRP with split-horizon disabled on hub Medium — careful neighbor design required DMVPN Phase 2/3, regional hub sites
Full Mesh OSPF broadcast, EIGRP full neighbor matrix, iBGP without RR Low — n*(n-1)/2 sessions limit scale to ~15-20 nodes Core/backbone layer, data center spine, small high-availability clusters
Route Reflector Cluster iBGP with RR eliminates full mesh requirement High — clients need only peer to RRs Large enterprise or SP iBGP domain

Point-to-multipoint: no DR election, each spoke is a neighbor ! Spoke-to-spoke traffic goes through hub ! ===== DMVPN Spoke — EIGRP Stub ===== router eigrp CORP address-family ipv4 unicast autonomous-system 100 af-interface Tunnel0 stub connected summary ! Stub: spoke does not forward transit, suppresses queries from hub ! Dramatically reduces convergence time for hub when a spoke fails ! ===== iBGP Route Reflector Design ===== ! Protocol Selection Framework

Protocol selection is one of the most consequential routing design decisions. The criteria are scale, convergence requirement, vendor environment, operational skill, and integration with MPLS/Segment Routing.

Criterion OSPF EIGRP IS-IS BGP
Max Scale ~500 routers / area, unlimited areas ~300 routers / AS practical Unlimited — used in all Tier-1 cores Millions of routes (full table)
Convergence 1-2s with tuned timers + BFD Sub-second with DUAL + BFD Sub-second, fewer SPF triggers Slow by default; fast with BFD + PIC
Vendor Support Universal — all vendors Cisco-primary (partial others) Universal — SP grade Universal — all vendors
MPLS/SR Integration SR-OSPF TLVs, widely supported Limited SR support SR-IS-IS TLVs, preferred for SP SR BGP-SR / BGP-LS for controller
Best Fit Enterprise campus/WAN, multi-vendor Cisco-only enterprise, DMVPN SP core, large enterprise backbone Inter-domain, large-scale iBGP
Redistribution Architecture and Loop Prevention

Redistribution between routing protocols is necessary at protocol boundaries — OSPF-to-EIGRP at a campus edge, static-to-BGP at an internet edge. Poorly designed redistribution creates routing loops, suboptimal paths, and unpredictable convergence. The safest architecture uses a single redistribution point per routing domain boundary.

! ===== Single Redistribution Point (Preferred) ===== ! One ASBR handles both directions — no loop risk router ospf 1 redistribute eigrp 100 subnets route-map EIGRP-TO-OSPF router eigrp 100 redistribute ospf 1 route-map OSPF-TO-EIGRP ! ===== Dual Redistribution Point — Route Tags for Loop Prevention ===== ! Tag routes when redistributing INTO a protocol ! Filter routes WITH that tag before redistributing back route-map EIGRP-TO-OSPF permit 10 set tag 100 ! Tag = 100 means "this route came from EIGRP" route-map OSPF-TO-EIGRP deny 5 match tag 100 ! On OSPF-to-EIGRP: block routes already tagged with 100 route-map OSPF-TO-EIGRP permit 10 set tag 200 ! Tag = 200 means "this route came from OSPF" route-map EIGRP-TO-OSPF deny 5 match tag 200 ! On EIGRP-to-OSPF: block routes tagged with 200 ! Loop closed — each ASBR rejects routes it originally injected ! Apply on ASBR-1 (OSPF domain): router ospf 1 redistribute eigrp 100 subnets route-map EIGRP-TO-OSPF ! Apply on ASBR-1 (EIGRP domain): router eigrp 100 redistribute ospf 1 route-map OSPF-TO-EIGRP
Administrative Distance Manipulation at Redistribution Points

When OSPF and EIGRP both have a route to the same destination, the lower AD wins and enters the RIB. EIGRP internal (90) beats OSPF (110). If you need OSPF to win for specific prefixes, raise EIGRP's AD for those routes using a distance command with an ACL. Never lower OSPF's AD globally — this breaks the entire domain's failure recovery.

IP Fast Reroute and Loop-Free Alternates

BFD detects failures in 150–300ms. Traditional SPF-driven reconvergence then takes another 200–500ms depending on timers. During this window, traffic to destinations whose primary next-hop failed is black-holed. IP FRR with Loop-Free Alternates (LFA) pre-computes backup paths before a failure occurs, enabling the forwarding plane to switch to the backup in under 50ms without waiting for routing protocol reconvergence.

! ===== OSPF LFA (Loop-Free Alternate) ===== router ospf 1 fast-reroute per-link enable ! Per-link LFA: computed per outgoing interface ! Requirement: alternate next-hop satisfies Loop-Free Condition ! (Alt's distance to destination) < (Alt's distance to S) + (S's distance to D) fast-reroute per-prefix enable ! Per-prefix LFA: more granular backup path selection ! ===== TI-LFA with Segment Routing (OSPF) ===== router ospf 1 segment-routing mpls fast-reroute per-prefix enable fast-reroute per-prefix ti-lfa enable ! TI-LFA uses SR to build guaranteed loop-free backup paths ! Works even where classic LFA has no valid alternate ! Provides ~100% link and node protection coverage ! ===== Verify LFA Backup Paths ===== show ip ospf fast-reroute ! Displays per-prefix backup next-hops and protection type show ip route repair-paths ! Shows which routes have pre-computed repair paths in the FIB
LFA Coverage Limitations

Classic LFA cannot always find a loop-free alternate — ring topologies and point-to-point chains leave some prefixes unprotected. Remote LFA (rLFA) extends coverage by tunneling to a repair tunnel endpoint further in the network. TI-LFA with Segment Routing provides 100% coverage by using SR-computed explicit paths that are guaranteed loop-free by construction.

Routing Design Review Checklist

Before finalizing a routing design, systematically verify these decision points. A design that cannot answer all of these clearly is not ready for production.

Category Questions to Answer
Addressing Is addressing hierarchical and summarizable at each tier boundary? Are all loopback and management prefixes in contiguous blocks?
Failure Domains What is the blast radius of a single router failure? Does a core failure trigger SPF in access areas? Are areas properly sized (<50 routers for clean convergence)?
Convergence Is BFD configured on all links with SLA requirements? Are hello/dead timers tuned? Is IP FRR deployed for critical paths?
Redistribution How many redistribution points exist? Is loop prevention in place? Are seed metrics set appropriately? Is there a mechanism to prefer native routes over redistributed ones?
Security Is neighbor authentication enabled on all protocol adjacencies? Are bogon filters applied at all eBGP peering points? Is GTSM configured?
Scalability What is the projected 3-year router and prefix count? Does the design accommodate that growth without architectural changes?

Key Takeaways

  • Hierarchical design (core/distribution/access) limits failure blast radius and reduces SPF scope through area boundaries and summarization
  • Summarization is only possible with hierarchical, contiguous IP addressing — retrofit is painful; plan addressing first
  • Hub-and-spoke suits DMVPN/branch with EIGRP stub or OSPF P2MP; full mesh is reserved for small high-availability cores
  • IS-IS is preferred for SP/large backbone Segment Routing deployments; OSPF is the universal choice for enterprise
  • Route tags at dual redistribution points prevent routing loops — each ASBR rejects routes tagged with the tag it originally set
  • TI-LFA with Segment Routing provides 100% fast-reroute coverage; classic LFA has topology gaps that leave some prefixes unprotected
