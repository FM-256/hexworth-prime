IS-IS Origins and Architecture

Intermediate System to Intermediate System (IS-IS) was originally designed by ISO for routing CLNP (Connectionless Network Protocol) in OSI networks (ISO 10589). When the internet needed a scalable interior routing protocol, IS-IS was adapted to carry IPv4 (and later IPv6) reachability as an extension rather than as its native payload. This architecture makes IS-IS uniquely flexible -- it runs over its own Layer 2 protocol (not IP), making it immune to many IP-layer attacks and misconfiguration issues that affect OSPF.

Today IS-IS is the dominant IGP in large service provider networks (major ISPs, hyperscaler backbones) and is widely used in data center fabrics. Its primary advantages over OSPF: simpler two-level hierarchy (vs. OSPF's complex area types), native TLV extensibility (adding new capabilities requires only new TLVs, not protocol version changes), and better scalability at large link counts.

Runs Below IP IS-IS PDUs are sent directly over Layer 2 using CLNP SAP values (0xFE), not over IP/UDP. The protocol stack cannot be attacked via IP-layer vulnerabilities like spoofed UDP packets.
TLV Extensible All IS-IS information is carried in Type-Length-Value structures. New capabilities (IPv6, Segment Routing, BFD) are added by defining new TLVs without changing the core protocol.
Two-Level Hierarchy Level 1 = intra-area routing. Level 2 = inter-area (backbone) routing. Simpler than OSPF's area types -- no stub, totally-stub, NSSA complexity at L1/L2 boundary.
Link State Protocol Like OSPF, uses Dijkstra's SPF algorithm. Maintains Link State PDU (LSP) database. Floods topology changes throughout each level independently.

CLNS Addressing and the NET

Every IS-IS router is identified by a Network Entity Title (NET), which is a CLNS address format. The NET has three parts:

FieldLengthExampleDescription
AFI + Area ID1-13 bytes49.0001AFI 49 = private addressing. Area ID identifies the routing area (like OSPF area number).
System ID6 bytes0100.1001.0001Uniquely identifies this router within the IS-IS domain. Often derived from a loopback IP for readability.
NSEL1 byte00N-Selector. Always 00 for a NET (identifies the router itself vs. a specific transport connection).

Full example NET: 49.0001.0100.1001.0001.00

To derive the System ID from a loopback address: take 10.1.1.1, pad to 010.001.001.001, rearrange to 0100.0100.1001 -- each group is 4 hex digits, 3 groups = 6 bytes. Different operators use different derivation conventions; the key requirement is that System IDs are unique within the IS-IS domain.

The ATT (Attached) Bit

When a Level 1-2 router has connectivity to the Level 2 backbone, it sets the Attached bit in its Level 1 LSP. Level 1 routers that see this bit automatically install a default route pointing toward the ATT-setting router. This is how L1 routers reach destinations outside their area without needing the full backbone topology -- similar in concept to an OSPF stub area default route.

DIS Election

On multi-access (broadcast) networks, IS-IS elects a Designated Intermediate System (DIS) -- analogous to OSPF's DR. The DIS generates a pseudo-node LSP that represents the LAN segment itself, simplifying the topology (N routers + 1 pseudo-node vs. N*(N-1)/2 adjacencies). The DIS election is based on configured priority (highest wins, default 64), then highest MAC address as tiebreaker.

DIS vs OSPF DR -- Key Differences

Unlike OSPF's DR, there is no BDR in IS-IS. All routers form full adjacencies with each other on a LAN (and with the DIS). The DIS also differs in that it sends periodic CSNP (Complete Sequence Number PDUs) to synchronize LSDBs, rather than OSPF's full database exchange. DIS preemption is also different: if a higher-priority router comes up, it immediately becomes the new DIS (OSPF DR does not preempt).

IS-IS TLV Types

Every piece of IS-IS information is encoded as a TLV (Type-Length-Value) within LSPs, Hello PDUs, and SNPs. This modularity allows new features to be added without protocol changes:

Practice Scenario

A service provider network has three areas: Area 49.0001 (backbone Level 2), Area 49.0002 (branch Level 1), and Area 49.0003 (data center Level 1). Router ABR-1 connects all three areas.

  1. Write the NET address for ABR-1 (Area 49.0002, loopback 10.2.0.1) and explain each field.
  2. A Level 1 router in Area 49.0002 needs to reach a destination in Area 49.0003. Explain the complete routing process: what route it uses, what ATT bit is involved, and which router it sends traffic to first.
  3. On a multi-access Ethernet segment with four IS-IS routers, explain: (a) how many pseudo-node LSPs exist, (b) who generates them, and (c) what triggers a new DIS election.
  4. An operator configures isis metric 1000 on an interface but the interface is running with legacy narrow metrics (max 63). What happens and how do you fix it?

Key Takeaways

  • IS-IS runs below IP (over Layer 2 directly) -- immune to IP-layer routing attacks that affect OSPF
  • NET = Area ID + System ID (6 bytes) + NSEL (00) -- System ID uniquely identifies the router within the domain
  • L1 routers: intra-area only, use default route from ATT bit. L2: backbone only. L1-2: full visibility, sets ATT bit
  • DIS (Designated IS) generates pseudo-node LSP on multi-access networks, uses CSNP for LSDB sync -- no BDR, DIS preempts
  • TLV extensibility allows new capabilities (IPv6, SR, TE) without protocol version changes -- a major architectural advantage
  • Always configure metric-style wide -- narrow metrics top out at 63, wide metrics support up to 16,777,215
  • Use isis network point-to-point on P2P links to avoid DIS election overhead and speed up adjacency formation
