Route Redistribution

Learning Objectives

  • Explain when and why route redistribution is necessary between routing domains
  • Configure mutual redistribution between OSPF and EIGRP with appropriate metrics
  • Identify the redistribution loop problem and implement route maps to prevent it
  • Use administrative distance manipulation to resolve suboptimal routing from redistribution
  • Apply prefix lists and route maps to filter routes during redistribution

When Redistribution Is Needed

Route redistribution transfers routes learned by one routing protocol into another. Common scenarios: corporate mergers joining different IGP domains, stub sites running EIGRP attached to an OSPF backbone, legacy network segments running RIPv2, static routes needing to be shared across the dynamic routing domain, or BGP prefixes being injected into an IGP for specific use cases.

Redistribution Risk: Always a Last Resort

Route redistribution introduces multiple failure modes: routing loops, suboptimal paths, metric incompatibilities, and routing instability. The safest network designs avoid redistribution entirely by running a single IGP domain-wide. If redistribution is unavoidable, it must be carefully controlled with route-maps, prefix-lists, and administrative distance adjustments to prevent the redistribution loop problem.

Metrics and Seed Metrics

When a route is redistributed into a new protocol, it needs a metric that makes sense in that protocol. Each protocol has different metric structures:

EIGRP Requires Explicit Seed Metric

Redistributing into EIGRP without specifying a metric results in all routes being redistributed with an infinite metric -- they will not be installed in the routing table. Always specify a reasonable metric. Example for a T1 equivalent: metric 1544 2000 255 1 1500 (bandwidth 1544 kbps, delay 2000 tens-of-microseconds, reliability 255, load 1, MTU 1500).

The Redistribution Loop Problem

When two routing protocols exchange routes through mutual redistribution at two or more boundary routers, a routing loop can form. Routes from OSPF get redistributed into EIGRP, travel across the EIGRP domain to the other boundary router, and get redistributed back into OSPF -- now competing with the original OSPF route, potentially winning due to lower OSPF external type or metric.

Cisco IOS -- Preventing Redistribution Loops with Route Maps and Tags
! Strategy: tag routes when redistributing out of OSPF into EIGRP
! At the other boundary: deny any EIGRP routes that carry the OSPF tag
! before redistributing back into OSPF

! On BOUNDARY-ROUTER-1: redistribute OSPF into EIGRP with tag
route-map OSPF-TO-EIGRP permit 10
 match ip address prefix-list OSPF-ROUTES
 set tag 100
 ! Tag 100 = "this route came from OSPF"

router eigrp 100
 redistribute ospf 1 metric 1544 2000 255 1 1500 route-map OSPF-TO-EIGRP

! On BOUNDARY-ROUTER-1: redistribute EIGRP into OSPF, deny tagged routes
route-map EIGRP-TO-OSPF deny 5
 match tag 100
 ! Drop any EIGRP routes that were originally from OSPF (looped routes)
route-map EIGRP-TO-OSPF permit 10
 ! Allow all other EIGRP routes into OSPF

router ospf 1
 redistribute eigrp 100 metric 100 subnets route-map EIGRP-TO-OSPF

Administrative Distance Manipulation

Administrative distance (AD) determines which protocol's routes are preferred when the same prefix is learned from multiple sources. In a redistribution scenario, a route may appear in both OSPF (as native) and EIGRP (as redistributed external). If EIGRP's redistributed route has lower AD than OSPF's native route, packets could take a suboptimal path. Adjusting AD resolves this.

! OSPF routes being preferred over EIGRP internal due to redistribution
! Solution: raise the AD of OSPF external routes on this router
! so EIGRP internal routes (AD 90) are preferred

router ospf 1

router ospf 1
 distance 200 10.0.0.0 0.0.0.255
 ! Raise AD to 200 for OSPF routes learned from 10.0.0.0/24 neighbor

Practice Scenario

A corporate merger requires mutual redistribution between an OSPF domain (100 routers) and an EIGRP domain (AS 200, 50 routers). Two ASBR routers connect the domains: ASBR1 and ASBR2. Without controls, a redistribution loop forms.

  1. Draw and explain the redistribution loop path: how does an OSPF route end up being re-advertised back into OSPF from EIGRP at ASBR2?
  2. Design a complete loop-prevention strategy using route tags. What tag value do you assign to OSPF routes redistributed into EIGRP? What route-map logic at ASBR2 prevents the loop?
  3. After deploying redistribution, traceroute from an OSPF router shows traffic taking a suboptimal path through EIGRP to reach an OSPF destination. The routing table shows the EIGRP-external route is preferred over the OSPF-internal. What is the AD comparison causing this and how do you fix it?
  4. Write the complete redistribution configuration for ASBR1 including: OSPF-to-EIGRP with seed metric, EIGRP-to-OSPF, and route-map for loop prevention using tags.

Key Takeaways

  • Redistribution is a last resort -- design for single IGP when possible; redistribution introduces loops, suboptimal paths, and instability risks
  • Seed metrics must be specified when redistributing into EIGRP -- omission results in infinite metric and routes are not installed
  • Redistribution loops form when two boundary routers mutually redistribute -- routes cycle back to their origin protocol via the other domain
  • Route tags prevent loops: tag routes at the source domain boundary, deny tagged routes at the destination-to-source redistribution point
  • Administrative distance determines which protocol wins when the same prefix is learned by multiple protocols -- external routes have higher AD than internal
  • Adjust AD per protocol or per source with distance commands to ensure native routes are preferred over redistributed copies
  • Always use route-maps with prefix-lists for redistribution control -- bare redistribute commands without filtering are dangerous
