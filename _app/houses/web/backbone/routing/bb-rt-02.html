Multi-Area IS-IS Design

IS-IS areas provide topology hiding and limit LSP flooding scope. Level 1 areas maintain their own LSDB visible only within the area. Level 2 forms the backbone -- L1-2 routers are at the boundary. Unlike OSPF's complex area type taxonomy, IS-IS uses only two levels with a clean separation of concerns.

Single Area (L2 only) All routers are L2-only. Simple, full topology visibility network-wide. Preferred for service provider cores where all routes must be visible to all backbone nodes.
Two-Level Design L1 areas for branches/edge, L2 backbone between areas. L1 routers use default routes. L1-2 ABRs hold both databases. Scales to large enterprise networks.

IS-IS vs OSPF Area Complexity

OSPF requires careful area type planning: backbone (area 0), standard areas, stub areas, totally-stub, NSSA, totally-NSSA. Each has different LSA handling rules. IS-IS is far simpler: L1 areas are inherently stub-like (use default routes to backbone). There are no special area type configurations -- the hierarchical behavior is automatic.

Route Leaking

In standard IS-IS, L1 routers use a default route to reach all inter-area destinations -- they have no detail about what's in other areas. Route leaking selectively injects L2 routes down into L1, giving L1 routers more specific paths when multiple exit points exist. Without leaking, all inter-area traffic from L1 flows to the nearest ATT router regardless of the actual best path.

Cisco IOS -- IS-IS Route Leaking (L2 to L1)
! Leak specific L2 routes into L1 for optimal exit selection
router isis CORE
 address-family ipv4 unicast
  redistribute isis ip level-2 into level-1 route-map LEAK-L2-TO-L1

route-map LEAK-L2-TO-L1 permit 10
 match ip address prefix-list REMOTE-DCS
 ! Only leak specific data center prefixes -- not the whole L2 table

ip prefix-list REMOTE-DCS seq 5 permit 10.100.0.0/16 le 24
ip prefix-list REMOTE-DCS seq 10 permit 10.200.0.0/16 le 24

Route Leaking and Loops

When leaking routes from L2 to L1, IS-IS marks them with the "down" bit (TLV 135 sub-TLV) to prevent them from being re-leaked back up to L2. Without this safeguard, leaked routes could re-enter L2, creating routing loops. Verify that your implementation honors the down bit -- show isis database detail and look for D flag on leaked prefixes.

The Overload Bit

The overload bit (OL bit) in an IS-IS LSP signals to all other routers in the LSDB that this router should not be used for transit -- traffic should not pass through it, only traffic destined for directly connected prefixes. Other routers still see the OL-bit router in the topology but run SPF such that no transit paths cross it.

Maintenance Mode Set overload before planned maintenance. Traffic migrates off the router before shutdown. After maintenance, clear overload and traffic gradually returns via normal SPF. No black-holing.
Startup Delay Set overload on startup until BGP converges. Prevents IS-IS from forwarding traffic before BGP tables are populated, avoiding black-holes during the convergence window.
Cisco IOS -- Overload Bit Configuration
! Manual overload for maintenance
router isis CORE
 set-overload-bit

! Startup overload: hold until BGP is ready (300 second timer)
router isis CORE
 set-overload-bit on-startup wait-for-bgp
 ! Waits for BGP to signal readiness, max 600 seconds

! Or use fixed timer
router isis CORE
 set-overload-bit on-startup 300

! Verify
R1# show isis database R1.00-00 detail | include Overload
  Overload bit set

IS-IS Summarization

Route summarization at level boundaries reduces the number of prefixes in the L2 LSDB, improving scalability and hiding topology detail. Unlike OSPF (where summarization happens at ABRs), IS-IS summarization is configured on the L1-2 router when redistributing L1 routes into L2 or when advertising local prefixes.

Cisco IOS -- IS-IS Summary Address
! Summarize area prefixes when advertising into L2 backbone
router isis CORE
 summary-address 10.10.0.0 255.255.0.0 level-2
 ! All 10.10.x.x prefixes from this area advertised as single /16 into L2
 ! Original specific routes suppressed from L2 LSDB

! Verify: show only the summary in L2 LSDB
R1# show isis database level-2 detail | include 10.10
  10.10.0.0/16         metric: 10
  ! Only summary visible, not individual /24 subnets

Segment Routing Extensions

Segment Routing (SR) uses IS-IS (and OSPF) to distribute MPLS label assignments. Each router advertises a Node SID (Segment ID) that identifies it globally within the SR domain. Adjacency SIDs identify specific links. The SR extensions to IS-IS use new TLVs within the existing LSP structure -- no new protocol required, no RSVP-TE signaling overhead.

SR ConceptIS-IS TLVDescription
SR CapabilityTLV 242Advertises SR support and the Global Block (SRGB -- label range allocated for SR node SIDs)
Prefix SIDSub-TLV of TLV 135Index into SRGB for the loopback prefix -- globally unique node SID
Adjacency SIDSub-TLV of TLV 22Locally significant label for a specific adjacency -- used in SR-TE policies
MSD (Max SID Depth)TLV 267Maximum number of SR labels a node can impose -- constrains SR-TE path depth
Cisco IOS-XE -- IS-IS Segment Routing Configuration
! Enable SR-MPLS with IS-IS
router isis CORE
 segment-routing mpls
 ! Activates SR, uses SRGB 16000-23999 by default

! Assign Prefix SID to loopback
interface Loopback0
 ip address 10.0.0.1 255.255.255.255
 ip router isis CORE
 isis prefix-sid index 1
 ! Node SID = SRGB base + index = 16000 + 1 = 16001

! Verify SR database
R1# show isis segment-routing prefix-sid-map
Prefix            SID Index  Flags  SRMS-Pref.  Status
10.0.0.1/32       1          N      0           reachable
10.0.0.2/32       2          N      0           reachable

IS-IS Authentication

Cisco IOS -- IS-IS HMAC-SHA Authentication
! Interface-level authentication (Hello PDUs)
interface GigabitEthernet0/0
 isis authentication mode md5
 isis authentication key-chain ISIS-KEYS

! Area-level authentication (LSPs and SNPs)
router isis CORE
 authentication mode md5 level-1
 authentication key-chain ISIS-KEYS level-1
 authentication mode md5 level-2
 authentication key-chain ISIS-KEYS level-2

key chain ISIS-KEYS
 key 1
  key-string IS1SSecretKey99
  cryptographic-algorithm hmac-sha-256

Practice Scenario

A service provider is planning maintenance on a core Level 2 router carrying significant transit traffic. They also want to enable Segment Routing on the backbone.

  1. Write the complete procedure (CLI commands) to gracefully remove the router from transit forwarding before maintenance, confirm traffic has shifted, perform the maintenance, and restore the router to full service.
  2. After enabling the overload bit, some traffic still traverses the router. Identify two possible reasons why and how to diagnose each.
  3. For an SR deployment with 50 nodes and SRGB 16000-23999, what is the maximum number of node SIDs available? Assign SID index 10 to router 10.0.0.10 and write the IOS-XE configuration.
  4. A new IS-IS neighbor relationship shows up in the LSDB but the adjacency keeps going down. You suspect authentication mismatch. What command shows whether authentication is the issue and what does a successful auth negotiation look like in debug output?

Key Takeaways

  • Route leaking injects L2 specifics into L1 for optimal exit selection -- the down bit prevents leaking loops
  • Overload bit prevents transit use while keeping the router in the topology -- essential for planned maintenance and graceful startup
  • Use set-overload-bit on-startup wait-for-bgp to prevent black-holing during the IS-IS/BGP convergence gap after router restart
  • IS-IS summarization reduces L2 LSDB size by hiding area-internal detail -- configured at the L1-2 boundary router
  • SR extensions use new TLVs within existing LSPs -- Node SIDs identify routers, Adjacency SIDs identify links
  • SRGB (Segment Routing Global Block) defines the label range; Prefix SID index + SRGB base = the globally unique SR label for a node
  • IS-IS authentication uses key chains with HMAC-SHA-256 -- configure at interface level (Hellos) and area level (LSPs/SNPs) separately
