IPv6 Address Planning

Unlike IPv4 where every address was precious, IPv6 planning is about structure and predictability. The goal is an addressing hierarchy that enables route summarization, meaningful prefix lengths at each layer, and room for growth without renumbering.

Enterprise IPv6 Addressing Hierarchy Example
# Organization receives /32 from ARIN via their ISP (PA) or directly (PI)
2001:db8::/32   Organization total allocation

# Subdivide into /48 per site (65,536 sites possible)
2001:db8:0000::/48   HQ campus (New York)
2001:db8:0001::/48   DC East (Virginia)
2001:db8:0002::/48   DC West (Oregon)
2001:db8:0100::/48   Branch offices (Americas)
2001:db8:0200::/48   Branch offices (EMEA)
2001:db8:0300::/48   Branch offices (APAC)

# Each /48 subdivided into /64 per VLAN (65,536 VLANs per site)
2001:db8:0000:0001::/64  HQ VLAN 1 (Management)
2001:db8:0000:0010::/64  HQ VLAN 16 (Servers)
2001:db8:0000:0020::/64  HQ VLAN 32 (User LAN)
2001:db8:0000:0040::/64  HQ VLAN 64 (WiFi)
2001:db8:0000:fffd::/64  HQ P2P links (/126 carved from here)
2001:db8:0000:fffe::/64  HQ Loopbacks (/128 per device)

P2P Link Addressing

For point-to-point router links, use /126 prefixes (4 addresses: network, 2 hosts, broadcast-like unused). Some organizations use /127 (RFC 6164), which provides exactly 2 host addresses and prevents "off-subnet" attacks. Avoid /64 on P2P links -- it wastes enormous address space and makes routing table entries unnecessarily broad.

PI Space vs PA Space

Enterprise IPv6 addresses can come from two sources: Provider Aggregatable (PA) space assigned by your ISP, or Provider Independent (PI) space assigned directly from a Regional Internet Registry (ARIN, RIPE, APNIC, etc.).

AttributePA SpacePI Space
SourceYour ISP sub-allocates from their /32 or /48Obtained directly from RIR (ARIN charges ~$250/yr)
PortabilityLost if you change ISPs -- must renumberPortable -- take it to any ISP
BGP announcementCovered by ISP's aggregate routeYou must announce your prefix to all upstream peers
Internet routing tableNot added (aggregated by ISP)Adds one entry -- RIRs impose /48 minimum for PI
Best forSmall/medium businesses with single ISPLarge enterprises, multihomed organizations

For enterprises with a single ISP, PA space is fine. For multihomed enterprises requiring ISP independence, PI space is the right choice despite the overhead of direct BGP peering and RIR registration fees.

IPv6 Policy-Based Routing

Policy-Based Routing (PBR) in IPv6 follows the same logic as IPv4: route-maps applied to interfaces steer traffic based on match criteria that override the normal FIB lookup. IPv6 PBR uses ipv6 policy route-map and supports matching on IPv6 ACLs, prefix lists, and packet length.

Cisco IOS -- IPv6 Policy-Based Routing
! Match GUA traffic and send via primary ISP
! Match LLA traffic and drop (don't route)

ipv6 access-list GUA-TRAFFIC
 permit ipv6 2001:db8:cafe::/48 any

route-map IPv6-PBR permit 10
 match ipv6 address GUA-TRAFFIC
 set ipv6 next-hop 2001:db8:isp1::1

route-map IPv6-PBR permit 20
 ! All other traffic: normal routing

interface GigabitEthernet0/0
 ! Apply PBR to inbound traffic on LAN interface
 ipv6 policy route-map IPv6-PBR

! Verify PBR hits
R1# show ipv6 policy
Interface      Routemap
Gi0/0          IPv6-PBR

R1# show route-map IPv6-PBR
route-map IPv6-PBR, permit, sequence 10
  Match clauses:
    ipv6 address (access-lists): GUA-TRAFFIC
  Set clauses:
    ipv6 next-hop 2001:DB8:ISP1::1

Phased Enterprise Deployment

No enterprise should flip to IPv6 overnight. A phased approach minimizes risk while making measurable progress.

PhaseScopeKey Actions
Phase 1 Assessment & Planning Inventory hardware/OS IPv6 support, obtain IPv6 address block, design addressing plan, identify IPv4-only applications
Phase 2 Infrastructure Enable IPv6 on core and distribution layer, enable OSPFv3 or IS-IS AF, configure BGP IPv6 AF with upstreams
Phase 3 Services IPv6-enable DNS (AAAA records), mail servers, web servers, VPN concentrators, and load balancers
Phase 4 Access Layer Enable dual-stack on access VLANs, configure RA, deploy DHCPv6 or SLAAC+RDNSS, deploy first-hop security
Phase 5 IPv4 Reduction Monitor IPv4 traffic decline, identify and remediate remaining IPv4-only apps, begin IPv4 address reclamation

Practice Questions

  1. An organization has been allocated 2001:db8:ab00::/40. They need addressing for 5 sites with up to 20 VLANs each, plus infrastructure loopbacks and P2P links. Sketch the allocation hierarchy.
  2. A company currently multihomes to two ISPs using PA space from each. They want to maintain connectivity if one ISP fails without renumbering. What should they obtain and what routing protocol change is needed?
  3. Write the IOS configuration for IPv6 PBR that sends traffic from the 2001:db8:exec::/64 subnet out interface Gi0/1 (executive MPLS link) and all other traffic out Gi0/0 (general internet).

Key Takeaways

  • Enterprise IPv6 planning uses /48 per site and /64 per VLAN -- structure enables summarization and growth
  • Use /127 or /126 for P2P links; avoid /64 on router-to-router links
  • PA space is ISP-assigned and non-portable; PI space is RIR-assigned and portable but requires direct BGP peering
  • IPv6 PBR uses ipv6 policy route-map on interfaces -- same logic as IPv4 PBR, different match objects
  • A five-phase deployment approach (assessment, infrastructure, services, access, IPv4 reduction) manages risk
