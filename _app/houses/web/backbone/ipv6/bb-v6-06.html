IPv6 First-Hop Security Threat Model

IPv6 introduces new attack surfaces that have no direct IPv4 equivalent. Because NDP relies on unauthenticated ICMPv6 multicast messages, the local link is an implicit trust domain. Any host on the link can send forged NDP messages affecting all other hosts.

AttackMechanismImpact
Rogue RA Attacker sends forged Router Advertisement on ff02::1 claiming to be a router with a /64 prefix Hosts autoconfigure addresses from attacker's prefix, redirect traffic through attacker's machine, or get invalid default gateway
Rogue DHCPv6 Attacker runs DHCPv6 server responding to SOLICITs before legitimate server Hosts receive attacker-controlled DNS servers, default gateway, or addresses
NDP Spoofing Attacker sends forged Neighbor Advertisement claiming to own a legitimate host's IPv6 address Traffic destined for the legitimate host is redirected to attacker (IPv6 ARP poisoning)
DAD DoS Attacker responds to every DAD probe claiming the address is already in use All new IPv6 addresses on the link fail DAD, preventing any host from getting a usable address
IPv6 Source Spoofing Host sends packets with a source IPv6 address not assigned to its interface Traffic laundering, DDoS amplification, bypassing ACLs tied to specific addresses

RA Guard (RFC 6105)

RA Guard is a switch-level feature that drops Router Advertisement and Router Redirect messages received on ports designated as "host" ports. Only ports explicitly configured as "router" ports are permitted to transmit RA messages.

Cisco IOS Switch -- RA Guard Configuration
! Define RA Guard policies
ipv6 nd raguard policy HOST-POLICY
 device-role host    # Drop all RA from host ports

ipv6 nd raguard policy ROUTER-POLICY
 device-role router
 # Optional: only allow RA from specific prefixes
 prefix-list RA-ALLOWED-PREFIXES permit 2001:db8:cafe::/48

! Apply to interfaces
interface GigabitEthernet0/1   # host-facing port
 ipv6 nd raguard attach-policy HOST-POLICY

interface GigabitEthernet0/48  # uplink to router
 ipv6 nd raguard attach-policy ROUTER-POLICY

SW1# show ipv6 nd raguard policy HOST-POLICY
Target: Gi0/1 - Gi0/24
  Device Role: host
  RA messages: DROPPED
  Redirect messages: DROPPED

RA Attack Tools

Tools like radvd, fake_router6 (from the THC IPv6 Attack Toolkit), and Scapy make it trivial to send forged Router Advertisements. In a penetration test, a single rogue RA can redirect all traffic on a /64 LAN through the attacker's machine. RA Guard is non-negotiable on any production access layer switch with IPv6 enabled.

DHCPv6 Guard

DHCPv6 Guard blocks DHCPv6 server messages (ADVERTISE, REPLY) received on host ports. Like RA Guard, it is enforced at the switch port level based on a device-role policy.

Cisco IOS Switch -- DHCPv6 Guard Configuration
! Policy for host ports
ipv6 dhcp guard policy DHCP-HOST
 device-role client

! Policy for trusted server-facing ports
ipv6 dhcp guard policy DHCP-SERVER
 device-role server

! Apply to VLAN or interface
interface GigabitEthernet0/1
 ipv6 dhcp guard attach-policy DHCP-HOST

interface GigabitEthernet0/48
 ipv6 dhcp guard attach-policy DHCP-SERVER

! Or apply at VLAN level (IOS 15.2+)
vlan configuration 100
 ipv6 dhcp guard attach-policy DHCP-HOST

SW1# show ipv6 dhcp guard policy DHCP-HOST
DHCPv6 guard policy DHCP-HOST configuration:
  Device Role: dhcp client
  ADVERTISE messages: DROPPED on host ports
  REPLY messages: DROPPED on host ports

IPv6 ND Inspection (SAVI)

Neighbor Discovery Inspection (also called Source Address Validation Improvement -- SAVI, RFC 7219) builds a binding table that maps IPv6 addresses to switch ports and MAC addresses. It validates that NDP messages match the binding table, dropping spoofed messages.

Cisco IOS Switch -- ND Inspection and Binding Table
! Enable IPv6 snooping globally
ipv6 snooping policy ND-POLICY
 security-level inspect
 device-role node
 tracking enable

interface range GigabitEthernet0/1 - 24
 ipv6 snooping attach-policy ND-POLICY

SW1# show ipv6 neighbors binding
Binding Table has 4 entries:
Codes: L - LOCAL, S - STATIC, ND - Neighbor Discovery

IPv6 Source Guard

IPv6 Source Guard uses the SAVI/ND Inspection binding table to enforce that traffic sourced from a port matches the binding. Packets with source addresses not in the binding table for that port are dropped at ingress.

Cisco IOS Switch -- IPv6 Source Guard
! Requires ND Inspection/snooping binding table first
ipv6 source-guard policy SG-POLICY
 deny global-autoconf       # block SLAAC-assigned addresses not in binding
 permit link-local          # allow link-local traffic

interface GigabitEthernet0/1
 ipv6 source-guard attach-policy SG-POLICY

! Verify drops
SW1# show ipv6 source-guard policy SG-POLICY
Source Guard policy SG-POLICY configuration:
  Deny: global-autoconf
  Permit: link-local
  Data glean: disabled
  Statistics: 14 packets dropped (source not in binding table)

Practice Questions

  1. An attacker connects a laptop to your LAN and runs a rogue RA tool. Describe exactly which Cisco switch feature prevents this, what configuration is needed, and what happens to the RA packets.
  2. A new host boots on the network and tries to obtain an address via SLAAC. The ND Inspection binding table is empty for this port. Will the host succeed? Explain the binding population process.
  3. Which IPv6 first-hop security feature is the IPv6 equivalent of IPv4 Dynamic ARP Inspection (DAI)?
  4. A security engineer finds that hosts on VLAN 100 are receiving DNS responses pointing to an attacker's server despite having RA Guard enabled. What additional control should they deploy?

Key Takeaways

  • IPv6 introduces new first-hop threats: rogue RA, rogue DHCPv6, NDP spoofing, and DAD DoS
  • RA Guard blocks Router Advertisements on host ports -- mandatory on any access layer switch with IPv6
  • DHCPv6 Guard blocks DHCPv6 server messages on host ports, preventing rogue DHCP servers
  • ND Inspection (SAVI) builds a binding table mapping IPv6 addresses to ports and MAC addresses
  • IPv6 Source Guard enforces the binding table at ingress, dropping spoofed source address traffic
  • Deploy all four mechanisms (RA Guard + DHCPv6 Guard + ND Inspection + Source Guard) together for comprehensive first-hop security
