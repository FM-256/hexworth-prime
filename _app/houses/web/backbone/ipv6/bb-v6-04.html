OSPFv3 vs OSPFv2

OSPFv3 (RFC 5340) is not simply OSPFv2 with IPv6 addresses substituted. Several fundamental changes were made to decouple the protocol from its addressing family, remove IPv4-specific assumptions, and leverage IPv6 capabilities.

AspectOSPFv2OSPFv3
TransportIP protocol 89, IPv4IP protocol 89, IPv6 -- uses LLAs for neighbor relationships
AddressingIPv4 addresses in LSAsAddress-family independent LSA structure; addressing in separate LSA types
AuthenticationBuilt-in MD5/SHA in packetsAuthentication removed from OSPFv3 header -- uses IPv6 AH/ESP extension headers (IPsec)
Neighbor formationBased on subnet membershipBased on link; neighbors form via LLA regardless of GUA prefix
Router IDDerived from interface IPv4Still a 32-bit value in dotted-decimal notation -- must be manually configured or borrowed from IPv4
Multi-address per linkOne prefix per interfaceMultiple IPv6 prefixes per link supported natively
Instance IDNot present8-bit Instance ID in header allows multiple OSPFv3 instances per link

Router ID Requirement

OSPFv3 still uses a 32-bit Router ID. In IPv6-only environments with no IPv4 configured, the router ID will not auto-select. You must configure it manually with router-id A.B.C.D under the OSPFv3 process. Forgetting this is the most common OSPFv3 misconfiguration in IPv6-only deployments.

OSPFv3 LSA Types

OSPFv3 retains the OSPFv2 LSA types but adds new ones to carry IPv6 addressing separately from topology information.

TypeNameScopeContent
0x2001Router LSAAreaRouter's links (interfaces) and their states. No IP addresses -- only topology. Each router generates one per area.
0x2002Network LSAAreaGenerated by Designated Router. Lists all routers attached to the broadcast segment. No addresses.
0x2003Inter-Area Prefix LSAAreaReplaces OSPFv2 Type 3 Summary LSA. Carries IPv6 prefixes between areas. Generated by ABRs.
0x2004Inter-Area Router LSAAreaReplaces OSPFv2 Type 4 ASBR Summary LSA. Points to ASBRs in other areas.
0x4005AS External LSAASRedistributed external routes. Flooded throughout the entire AS (except stub areas). Equivalent to OSPFv2 Type 5.
0x2007NSSA External LSAAreaExternal routes in Not-So-Stubby Areas. Translated to Type 5 by ABR at area boundary.
0x0008Link LSALinkNew in OSPFv3. Contains router's LLA and all IPv6 prefixes on the link. Used only within the link.
0x2009Intra-Area Prefix LSAAreaNew in OSPFv3. Carries all IPv6 prefixes for a router or network segment within an area. Replaces the prefix information that was embedded in OSPFv2 Router and Network LSAs.

OSPFv3 Configuration

Cisco IOS supports two OSPFv3 configuration syntaxes. The legacy per-interface syntax enables OSPFv3 on individual interfaces. The newer address-family syntax (preferred) mirrors OSPFv2 configuration and supports both IPv4 and IPv6 address families under a single OSPFv3 process.

Cisco IOS -- OSPFv3 Interface-Level Syntax (Legacy)
! Required if no IPv4 is configured -- manual Router ID
ipv6 router ospf 1
 router-id 1.1.1.1
 area 0 range 2001:db8:cafe::/48

interface GigabitEthernet0/0
 ipv6 ospf 1 area 0
 ipv6 ospf priority 200

interface Loopback0
 ipv6 address 2001:db8:ffff::1/128
 ipv6 ospf 1 area 0

R1# show ipv6 ospf neighbor
Neighbor ID     Pri   State           Dead Time   Interface ID    Interface
2.2.2.2           1   FULL/DR         00:00:33    4               Gi0/0
3.3.3.3           1   FULL/BDR        00:00:31    4               Gi0/0
Cisco IOS -- OSPFv3 Address-Family Syntax (Preferred)
! Single process can run both IPv4 and IPv6 AF
router ospfv3 1
 router-id 1.1.1.1
 !
 address-family ipv6 unicast
  area 1 stub
  area 0 range 2001:db8:cafe::/48
 exit-address-family

interface GigabitEthernet0/0
 ospfv3 1 ipv6 area 0

R1# show ospfv3 ipv6 database
            OSPFv3 Router with ID (1.1.1.1) (Process ID 1)
                Router Link States (Area 0)
Link ID         ADV Router      Age         Seq#         Checksum  Link count
1.1.1.1         1.1.1.1         342         0x80000003   0x006A45  1
2.2.2.2         2.2.2.2         341         0x80000003   0x001234  1

OSPFv3 Authentication with IPsec

OSPFv3 removed authentication from its packet header. Authentication is provided by IPv6 extension headers using IPsec Authentication Header (AH) or Encapsulating Security Payload (ESP). This applies at the interface level using manually defined Security Parameter Indexes (SPIs).

Cisco IOS -- OSPFv3 Authentication via IPsec AH
! Configure SHA-1 authentication on an interface
interface GigabitEthernet0/0
 ipv6 ospf authentication ipsec spi 256 sha1 12345678901234567890123456789012345678ab

! Or on the OSPFv3 area for all interfaces in the area
ipv6 router ospf 1
 area 0 authentication ipsec spi 256 sha1 12345678901234567890123456789012345678ab

! With address-family syntax:
router ospfv3 1
 address-family ipv6 unicast
  area 0 authentication ipsec spi 256 sha1 12345678901234567890123456789012345678ab

R1# show ipv6 ospf interface Gi0/0 | include auth
  Authentication: Using AH authentication, SPI 256, SHA-1 algorithm

OSPFv3 vs OSPFv2 Authentication

OSPFv2 uses MD5 or SHA keys configured directly in the protocol. OSPFv3 delegates this to IPsec, which is architecturally cleaner but operationally more complex. Both peers must use the same SPI and key. The SPI is a locally significant index -- it does not need to match on both routers, but the key must be identical. In practice, operators commonly set matching SPIs for simplicity.

Multi-Area OSPFv3 Design

OSPFv3 follows the same hierarchical area design principles as OSPFv2. All areas must connect to Area 0 (backbone area). Area types -- stub, totally stub, NSSA -- work identically in v3 as in v2.

Multi-Area OSPFv3 ABR Configuration
! ABR connecting Area 0 and Area 1
router ospfv3 1
 router-id 2.2.2.2
 address-family ipv6 unicast
  ! Summarize Area 1 prefix into Area 0
  area 1 range 2001:db8:cafe:100::/56
  ! Make Area 1 a stub (no external routes)
  area 1 stub
 exit-address-family

interface GigabitEthernet0/0
 ospfv3 1 ipv6 area 0   # Area 0 interface

interface GigabitEthernet0/1
 ospfv3 1 ipv6 area 1   # Area 1 interface

R2# show ospfv3 ipv6 border-routers

Router ID       Cost  Next Hop            Via         Area

Practice Questions

  1. In an IPv6-only network with OSPFv3, R1 has no loopback configured and no IPv4 addresses. The OSPFv3 process fails to start. What is the fix, and what command applies it?
  2. What OSPFv3 LSA type carries IPv6 prefix information for intra-area routes, and why was this information moved out of the Router LSA compared to OSPFv2?
  3. OSPFv3 neighbors form over link-local addresses. R1 has two interfaces in Area 0 with different GUA prefixes but the same LLA (fe80::1). What problem will this cause, and how is it resolved?
  4. Write the IOS configuration to enable OSPFv3 SHA-1 authentication on all interfaces in Area 0 using the address-family syntax.

Key Takeaways

  • OSPFv3 uses IPv6 link-local addresses for all neighbor relationships -- Router ID is still 32-bit and must be manually set in IPv6-only environments
  • New LSA types 0x0008 (Link) and 0x2009 (Intra-Area Prefix) carry IPv6 addressing separate from topology data
  • Authentication moved out of OSPFv3 packets -- IPsec AH or ESP provides it via IPv6 extension headers
  • The address-family syntax (ospfv3 process) is preferred over legacy per-interface ipv6 ospf syntax
  • Multi-area design, stub areas, and summarization work identically to OSPFv2 -- the concepts transfer directly
