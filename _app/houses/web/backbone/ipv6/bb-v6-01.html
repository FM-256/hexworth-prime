Learning Objectives

  • Identify and distinguish all IPv6 address types: GUA, LLA, ULA, anycast, and multicast
  • Explain the structure of a 128-bit IPv6 address and apply compression rules correctly
  • Describe multicast scope levels and their operational significance

  • Configure IPv6 addresses on Cisco IOS and Linux interfaces

Why IPv6?

IPv4's 32-bit address space yields approximately 4.3 billion addresses. IANA exhausted its free pool in February 2011. Regional registries followed shortly after. IPv6 uses 128-bit addresses, providing 340 undecillion (3.4 x 10^38) addresses -- roughly 4.8 x 10^28 per human being on Earth. Scarcity is not a concern.

Beyond address space, IPv6 eliminates NAT as a default design requirement, simplifies the IP header from 12 fields to 8, and builds neighbor discovery, stateless address autoconfiguration, and mandatory IPsec support directly into the protocol. It is not simply "more addresses" -- it is a redesigned network layer.

128-bit Addresses 340 undecillion unique addresses. Enough for global direct-reachability without NAT at any foreseeable scale.
Simplified Header Fixed 40-byte header. Options moved to extension headers. No checksum field -- that burden moves to transport layer.
Built-in Autoconfiguration SLAAC enables a host to configure a routable address from a router advertisement alone -- no DHCP server required.
No Broadcast Broadcast is abolished. All former broadcast functions are handled by scoped multicast, reducing unnecessary host interrupts.

Address Notation and Compression

An IPv6 address is 128 bits written as eight groups of four hexadecimal digits separated by colons. Two compression rules reduce verbosity:

Compression Rules

  • Rule 1: Leading zeros in each group may be omitted. 0042 becomes 42
  • Rule 2: One consecutive sequence of all-zero groups may be replaced with ::. This can appear only once per address.
IPv6 Address Compression Examples
# Full form
2001:0db8:0000:0000:0000:ff00:0042:8329

# Rule 1: remove leading zeros per group
2001:db8:0:0:0:ff00:42:8329

# Rule 2: collapse longest consecutive zero run with ::
2001:db8::ff00:42:8329

# Loopback address (127 zeros, then 1)
::1

# All-zeros unspecified address
::

# IPv4-mapped IPv6 address
::ffff:192.168.1.1

The prefix length follows the address with a slash, exactly as CIDR notation in IPv4. A /64 prefix is the standard for a link (subnet), leaving 64 bits for the interface identifier. A /48 is commonly allocated to an organization. A /32 is a typical ISP allocation.

Address Types

TypePrefix RangeScopePurpose
GUA 2000::/3 Global Globally Unique Addresses. Internet-routable. Currently allocated from 2001::/16 through 3fff::/16.
LLA fe80::/10 Link-local Link-Local Addresses. Auto-configured on every IPv6-capable interface. Never routed off-link. Required for NDP and routing protocol neighbor relationships.
ULA fc00::/7 (fd00::/8 in practice) Organization Unique Local Addresses. RFC 4193. Private range for internal use. Globally unique within the organization but not routable on the internet.
Multicast ff00::/8 Variable One-to-many delivery to all members of a multicast group. Scope encoded in bits 4-7 of the prefix byte.
Anycast Drawn from GUA/ULA space Global/Site Assigned to multiple interfaces. Packet delivered to topologically nearest interface. Used for DNS root servers, CDN PoPs, and 6to4 relays.
Loopback ::1/128 Host Equivalent to IPv4 127.0.0.1. Used for testing the local IPv6 stack.
Unspecified ::/128 Host Indicates absence of an address. Used in DAD probes and initial DHCPv6 source.

Multicast Scopes

IPv6 multicast addresses encode their delivery scope in the second nibble of the address. This tells routers how far to forward the packet without relying on TTL thresholds as IPv4 did.

Scope ValueNameExampleUsage
0x1Interface-localff01::1Loopback only. Packets cannot leave the interface.
0x2Link-localff02::1All nodes on the local link. Used by NDP (ff02::2 = all routers).
0x5Site-localff05::2All routers in a site. Scope is administratively defined.
0x8Organization-localff08::fbAll interfaces in an organization. Crosses sites but not internet.
0xeGlobalff0e::101Internet-wide. Used for public multicast services like NTP (ff0e::101).

ff02::2   All routers on the link
ff02::5   All OSPFv3 routers
ff02::6   All OSPFv3 designated routers
ff02::9   All RIPng routers

Interface Identifier: EUI-64

The lower 64 bits of an IPv6 address identify the interface on a link. Two methods generate this interface ID automatically.

EUI-64 (Extended Unique Identifier) derives the interface ID from the MAC address. The process:

EUI-64 Derivation from MAC Address
# Starting MAC: 00:1a:2b:3c:4d:5e

# Step 1: Split MAC in half and insert FF:FE in the middle
00:1a:2b : ff:fe : 3c:4d:5e

# Step 2: Flip bit 7 (U/L bit) of the first byte
# 0x00 = 00000000 -> flip bit 7 -> 00000010 = 0x02
02:1a:2b:ff:fe:3c:4d:5e

# Final EUI-64 interface ID (grouped as IPv6 nibbles)
021a:2bff:fe3c:4d5e

# Full LLA if on fe80::/10
fe80::021a:2bff:fe3c:4d5e
# Compressed:
fe80::21a:2bff:fe3c:4d5e

EUI-64 Privacy Risk

EUI-64 embeds the hardware MAC address in the IPv6 address. This enables tracking across networks -- any server you connect to can identify your NIC. RFC 4941 (Privacy Extensions) addresses this by generating a random, temporary interface ID for outbound connections. Most modern operating systems enable this by default.

Privacy Extensions (RFC 4941)

Privacy extensions generate a cryptographically random interface ID for each prefix. The host maintains a stable address (often EUI-64 or opaque as per RFC 7217) for inbound connections and a rotating temporary address for outbound connections.

Linux -- Checking Privacy Extension Status
$ sysctl net.ipv6.conf.eth0.use_tempaddr
net.ipv6.conf.eth0.use_tempaddr = 2
# 0=disabled, 1=enabled (prefer stable), 2=enabled (prefer temp)

$ ip -6 addr show eth0
3: eth0: <BROADCAST,MULTICAST,UP>
    inet6 2001:db8:cafe:1:21a:2bff:fe3c:4d5e/64 scope global # stable (EUI-64)
         valid_lft forever preferred_lft forever
    inet6 2001:db8:cafe:1:a3f2:9b11:cd44:8e7a/64 scope global temporary # privacy
         valid_lft 86395sec preferred_lft 14395sec
    inet6 fe80::21a:2bff:fe3c:4d5e/64 scope link
         valid_lft forever preferred_lft forever

RFC 7217 (Opaque Stable Addresses) improves on both approaches: it generates a stable but unpredictable interface ID using a cryptographic hash of the prefix, interface name, and a secret key. This prevents tracking across networks while maintaining a stable address per network prefix.

Configuring IPv6 Addresses

Cisco IOS -- IPv6 Interface Configuration
! Enable IPv6 routing globally
ipv6 unicast-routing

interface GigabitEthernet0/0
 ! Manual GUA assignment
 ipv6 address 2001:db8:cafe:1::1/64
 ! EUI-64 derived from MAC address
 ipv6 address 2001:db8:cafe:1::/64 eui-64
 ! LLA is auto-generated but can be set manually
 ipv6 address fe80::1 link-local
 no shutdown

R1# show ipv6 interface GigabitEthernet0/0
GigabitEthernet0/0 is up, line protocol is up
  IPv6 is enabled, link-local address is FE80::1
  No Virtual link-local address(es):
  Global unicast address(es):
    2001:DB8:CAFE:1::1, subnet is 2001:DB8:CAFE:1::/64
  Joined group address(es):
    FF02::1
    FF02::2
    FF02::1:FF00:1  (solicited-node for ::1)
Linux -- ip Command IPv6 Configuration
# Add GUA manually
$ sudo ip -6 addr add 2001:db8:cafe:1::10/64 dev eth0

# Add LLA manually (replaces auto-generated)
$ sudo ip -6 addr add fe80::10/64 dev eth0

# Verify
$ ip -6 addr show eth0
2001:db8:cafe:1::10/64 scope global
fe80::10/64 scope link

Practice Questions

  1. A host has MAC address c0:ff:ee:aa:bb:cc. What is its EUI-64 link-local address? Show each derivation step.
  2. Compress this address to its shortest valid form: 2001:0db8:0000:0000:0001:0000:0000:0001
  3. What multicast group does every IPv6 host automatically join, and what is the IPv4 equivalent behavior?
  4. A network admin proposes using fd00::/8 for internal infrastructure. Is this appropriate? What type of address is this and when would you choose it over a GUA?

Key Takeaways

  • IPv6 uses 128-bit addresses written in hexadecimal groups; two compression rules reduce notation length
  • GUA (2000::/3) is globally routable; LLA (fe80::/10) is link-scoped and mandatory on every interface
  • ULA (fd00::/8) serves the same role as RFC 1918 private space -- internal use, not internet-routable
  • Multicast replaces all broadcast functions; scope is encoded in the address, not the TTL
  • EUI-64 embeds the MAC address in the interface ID -- RFC 4941 privacy extensions randomize it to prevent tracking
  • Every IPv6 interface automatically joins ff02::1 (all-nodes) and its own solicited-node multicast group
