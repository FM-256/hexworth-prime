DHCPv6 vs SLAAC

SLAAC is powerful but stateless -- the network has no central record of which host took which address. DHCPv6 (RFC 8415) provides centralized address management with lease tracking, just like DHCPv4. The choice between SLAAC and DHCPv6 (or both) is controlled by the M and O flags in Router Advertisements.

Stateful DHCPv6 Server assigns specific IPv6 addresses and tracks leases per client. M flag = 1 in RA. Required when you need address management visibility or must provide specific addresses to specific hosts.
Stateless DHCPv6 Host uses SLAAC for address configuration but contacts DHCPv6 server for DNS servers, NTP, domain names, etc. O flag = 1, M flag = 0. No lease state maintained for addresses.
SLAAC + RDNSS RFC 8106 adds DNS server information directly to Router Advertisements. Fully serverless -- no DHCPv6 needed at all. Increasingly common in mobile and IoT deployments.
Prefix Delegation DHCPv6 PD (IA_PD) assigns entire prefixes (typically /48 or /56) to routers rather than individual addresses. ISPs use this to delegate space to CPE routers.

DHCPv6 uses UDP port 546 (client) and UDP port 547 (server/relay). The all-DHCPv6-servers multicast address is ff02::1:2 for link-local scope and ff05::1:3 for site-local. Unlike DHCPv4, DHCPv6 cannot operate without a functioning IPv6 link-local address on the client.

DHCPv6 Message Exchange

Stateful DHCPv6 uses a four-message exchange. Each client and server is identified by a DUID (DHCP Unique Identifier) rather than MAC addresses, making DHCPv6 hardware-independent.

DHCPv6 Stateful Exchange (Four-Message)
Client                                    Server
  |                                          |
SOLICIT ─────────────────────────────────>  # Client discovers servers
  Src: fe80::client    Dst: ff02::1:2
  IA_NA (Identity Association for Non-temp Addr)
  |                                          |
  <──────────────────────────────── ADVERTISE  # Server offers address
  Contains: IA_NA with 2001:db8:cafe:1::10
  Preferred lifetime: 14400s, Valid: 86400s
  |                                          |
REQUEST ─────────────────────────────────>  # Client requests specific offer
  Client ID + Server ID + IA_NA address
  |                                          |
  <────────────────────────────────── REPLY   # Server confirms assignment
  Address confirmed, DNS options, lease times

--- Rapid Commit (Two-Message, O flag in SOLICIT) ---
SOLICIT (Rapid Commit option) ──────────>
  <────────────────────────────────── REPLY
  Skips ADVERTISE + REQUEST round trip
Message TypeValueDirectionPurpose
SOLICIT1Client → ff02::1:2Discover available DHCPv6 servers
ADVERTISE2Server → Client LLAServer offers an address and options
REQUEST3Client → ff02::1:2Client requests specific address from chosen server
REPLY7Server → Client LLAServer confirms assignment; also used for renew/rebind responses
RENEW5Client → Server unicastExtend lease before T1 timer expires (default 50% of preferred lifetime)
REBIND6Client → ff02::1:2Extend lease after T1 expires, before preferred lifetime ends; any server may respond
RELEASE8Client → Server unicastClient returns address before lease expires
INFORMATION-REQUEST11Client → ff02::1:2Stateless mode: request only options (DNS, NTP), no address

DHCPv6 Prefix Delegation

Prefix Delegation (PD) allows a DHCPv6 server to assign an entire prefix to a requesting router. The requesting router (typically a CPE or branch office router) then subnets that delegated prefix for its downstream interfaces. This is the standard mechanism for ISPs to provision customer IPv6 connectivity.

DHCPv6 PD Flow: ISP to CPE Router
# ISP DHCPv6 server has pool: 2001:db8::/32
# Customer CPE requests a /56 prefix via IA_PD

CPE                              ISP-DHCPv6-Server
SOLICIT (IA_PD, hint: /56) ──>
  <── ADVERTISE (IA_PD: 2001:db8:ab00::/56)
REQUEST (IA_PD: 2001:db8:ab00::/56) ──>
  <── REPLY (confirmed)

# CPE now subnets /56 into 256 x /64 for LAN interfaces:
2001:db8:ab00:0000::/64  LAN1 (eth0)
2001:db8:ab00:0001::/64  LAN2 (eth1)
2001:db8:ab00:00ff::/64  ... up to 256 subnets

# CPE sends RA with these prefixes to downstream hosts
# Hosts SLAAC from the delegated /64 prefixes

Common prefix delegation sizes: ISPs receive /32 from their RIR. They typically delegate /48 to large enterprise customers, /56 to SMB customers, and /60 or /64 to residential customers. A /48 provides 65,536 subnets of /64 -- enough for any enterprise.

DHCPv6 Relay Agents

DHCPv6 clients send Solicit messages to ff02::1:2, a link-local multicast. DHCPv6 servers cannot be on a different subnet without a relay agent -- the multicast does not cross router boundaries.

Cisco IOS -- DHCPv6 Server and Relay Configuration
! DHCPv6 server configuration
ipv6 dhcp pool ENTERPRISE-POOL
 address prefix 2001:db8:cafe:1::/64 lifetime 86400 14400
 dns-server 2001:db8::53
 domain-name corp.example.com

interface GigabitEthernet0/0
 ipv6 address 2001:db8:cafe:1::1/64
 ipv6 dhcp server ENTERPRISE-POOL
 ipv6 nd managed-config-flag
 ipv6 nd other-config-flag

! DHCPv6 relay on a different segment's router
interface GigabitEthernet0/1
 ipv6 address 2001:db8:cafe:2::1/64
 ! Forward DHCPv6 to server at 2001:db8:cafe:1::1
 ipv6 dhcp relay destination 2001:db8:cafe:1::1

Client: DUID 00:01:00:01:1a:2b:3c:4d

  Address: 2001:DB8:CAFE:1::A

DHCPv6 Configuration: ISC Kea

On Linux servers, ISC Kea (successor to ISC DHCP) is the standard DHCPv6 server. The configuration uses JSON format and supports prefix delegation, relay, and high availability.

ISC Kea -- Minimal DHCPv6 Configuration (/etc/kea/kea-dhcp6.conf)
{
  "Dhcp6": {
    "interfaces-config": {
      "interfaces": [ "eth0" ]
    },
    "subnet6": [{
      "subnet": "2001:db8:cafe:1::/64",
      "pools": [{
        "pool": "2001:db8:cafe:1::100-2001:db8:cafe:1::1ff"
      }],
      "pd-pools": [{
        "prefix": "2001:db8:ab00::",
        "prefix-len": 48,
        "delegated-len": 56
      }],
      "option-data": [{
        "name": "dns-servers",
        "data": "2001:db8::53, 2001:db8::54"
      }]
    }]
  }
}

Practice Questions

  1. An RA arrives with M=0 and O=1. A host sends a DHCPv6 INFORMATION-REQUEST. What message type does the server respond with, and what does it contain?
  2. A CPE router is delegated the prefix 2001:db8:abcd::/48. The CPE has three LAN ports. Assign a /64 prefix to each and write the first host's SLAAC address if its MAC is aa:bb:cc:dd:ee:ff.
  3. Why can DHCPv4 work without a relay when the server is on a different VLAN, but DHCPv6 cannot? (Hint: compare IPv4 broadcast vs IPv6 multicast routing behavior.)
  4. What is the DHCPv6 equivalent of a MAC address reservation, and what identifier does the server use?

Key Takeaways

  • Stateful DHCPv6 (M=1) assigns addresses with lease tracking; stateless (M=0, O=1) provides only options like DNS
  • DHCPv6 uses UDP 546/547, and multicast address ff02::1:2 for link-local server discovery
  • The four-message exchange is SOLICIT / ADVERTISE / REQUEST / REPLY; rapid commit shortens it to two
  • Prefix Delegation (IA_PD) assigns entire prefixes to routers -- the ISP-to-CPE provisioning mechanism
  • DHCPv6 relay agents are required when the server is not on the same link as clients
  • Clients use DUID identifiers rather than MAC addresses, making DHCPv6 hardware-agnostic
