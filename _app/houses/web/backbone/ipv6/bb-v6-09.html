IPv6 Ping and Traceroute

The fundamental connectivity test tools work for IPv6 but require attention to address syntax, especially for link-local addresses which require a zone ID (interface specifier) to disambiguate which interface to use.

Linux -- ping6 and traceroute6 Usage
# Ping a GUA -- no zone ID needed
$ ping6 2001:db8:cafe:1::1
PING 2001:db8:cafe:1::1 56 data bytes
64 bytes from 2001:db8:cafe:1::1: icmp_seq=1 ttl=64 time=0.412 ms

# Ping a link-local address -- MUST specify interface with %
$ ping6 fe80::1%eth0
PING fe80::1%eth0 56 data bytes
64 bytes from fe80::1%eth0: icmp_seq=1 ttl=64 time=0.318 ms

# Traceroute IPv6
$ traceroute6 2001:db8:cafe:ff::1
traceroute to 2001:db8:cafe:ff::1, 30 hops max, 80 byte packets
 1  fe80::1%eth0  0.412 ms  0.388 ms  0.401 ms
 2  2001:db8:0:1::2  1.231 ms  1.198 ms  1.204 ms
 3  2001:db8:cafe:ff::1  2.018 ms  1.999 ms  2.011 ms
Cisco IOS -- Extended ping6
R1# ping ipv6 2001:db8:cafe:1::10 repeat 100 size 1400 source lo0
Sending 100, 1400-byte ICMP Echos to 2001:DB8:CAFE:1::10
Success rate is 100 percent (100/100), round-trip min/avg/max = 1/2/5 ms

! Ping link-local from IOS -- must specify source interface
R1# ping ipv6 fe80::2 source GigabitEthernet0/0
!!!!!
Success rate is 100 percent (5/5)

Essential Show Commands

Cisco IOS -- IPv6 Show Command Reference
# Interface and address state
R1# show ipv6 interface brief
GigabitEthernet0/0  [up/up]
    FE80::1
    2001:DB8:CAFE:1::1
Loopback0           [up/up]
    FE80::1
    2001:DB8:FFFF::1

# Full interface detail (RA config, joined groups)
R1# show ipv6 interface GigabitEthernet0/0

# Routing table
R1# show ipv6 route
R1# show ipv6 route 2001:db8:cafe:2::/64     # specific prefix

# NDP neighbor table (like arp -n)
R1# show ipv6 neighbors

# OSPFv3 neighbors
R1# show ipv6 ospf neighbor
R1# show ospfv3 ipv6 neighbor detail

# BGP IPv6 table
R1# show bgp ipv6 unicast summary
R1# show bgp ipv6 unicast 2001:db8::/32

# Verify traffic flow
R1# show ipv6 traffic
Linux -- IPv6 Diagnostic Commands
# Show all IPv6 addresses
$ ip -6 addr show

# Show IPv6 routing table
$ ip -6 route show

# Show NDP neighbor cache
$ ip -6 neigh show

# Check default gateway
$ ip -6 route show default
default via fe80::1 dev eth0 proto ra metric 100

# Show received RAs (requires rdisc6 from ndisc6 package)
$ rdisc6 eth0

Common Failure Modes

SymptomRoot CauseFix
Host has LLA but no GUA No RA received; router RA suppressed or not configured; M flag ignored by host Check show ipv6 interface for RA suppression; verify OSPFv3/interface has ipv6 unicast-routing enabled
ping6 to GUA fails, ping6 to LLA succeeds No default route from RA; routing protocol not redistributing; wrong next-hop in route Check ip -6 route show default; verify RA router-lifetime is non-zero
OSPFv3 neighbors won't form Missing ipv6 unicast-routing; interface not in process; mismatched area ID; Router ID not set in IPv6-only environment Confirm show ipv6 ospf interface shows correct area; set manual Router ID
BGP IPv6 prefixes in table but not FIB Unreachable next-hop (missing next-hop-self on iBGP); invalid RD; route filtered Add neighbor X next-hop-self in address-family ipv6; check show bgp ipv6 unicast X detail
DAD failure on new interface Cloned VM with duplicate MAC; physical hardware failure; rogue DAD DoS Check for duplicate MACs; verify no rogue ND tool running; check show ipv6 interface for DUPLICATE state
IPv6 works on LAN, not to internet ISP not advertising default IPv6 route; ACL blocking ICMPv6; MTU mismatch (PMTUD blackhole) Verify default route in BGP; check show ipv6 route ::/0; test with ping6 of various sizes
PMTUD blackhole Firewall or middlebox dropping ICMPv6 type 2 (Packet Too Big) Permit ICMPv6 type 2 through firewalls; configure MSS clamping as workaround

ICMPv6 Must Not Be Blocked

IPv6 Path MTU Discovery depends entirely on ICMPv6 Packet Too Big messages (type 2). If a firewall drops these, connections hang silently after the first large packet. Unlike IPv4 which has fragmentation as a fallback (with its own issues), IPv6 routers do not fragment packets -- only the source does, and only if it receives PTB messages. Permit ICMPv6 types 1-4 and 133-137 through all firewalls unconditionally.

Key Takeaways

  • Link-local ping requires a zone ID (%interface) -- forgetting this is the most common ping6 mistake
  • The structured approach: verify LLA first, then GUA, then default route, then reachability, then service
  • Most common OSPFv3 failure: missing Router ID in IPv6-only environment
  • Most common BGP IPv6 failure: missing next-hop-self for iBGP
  • ICMPv6 Packet Too Big (type 2) must be permitted through all firewalls -- blocking it creates PMTUD blackholes
  • DAD duplicate state disables the address; check for cloned MACs and rogue ND tools
