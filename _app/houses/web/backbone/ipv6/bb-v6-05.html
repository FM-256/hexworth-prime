Multiprotocol BGP (MP-BGP)

Standard BGP-4 was designed for IPv4. RFC 4760 extended BGP with Multiprotocol Extensions (MP-BGP), adding two new optional non-transitive path attributes: MP_REACH_NLRI and MP_UNREACH_NLRI. These carry address family information for any protocol -- IPv6, VPNv4, VPNv6, L2VPN, and more.

The BGP session itself (TCP port 179) can be established over either IPv4 or IPv6. The address family carried within that session is independent of the session's transport. You can have an IPv4 BGP session that carries IPv6 prefixes, or an IPv6 BGP session that carries VPNv4 routes.

MP_REACH_NLRI Carries reachable prefixes and their next-hop for a specific address family. Contains AFI (Address Family Identifier) and SAFI (Subsequent AFI) to identify the protocol.
MP_UNREACH_NLRI Withdraws previously advertised prefixes for a specific address family. Allows granular withdrawal without affecting other address families on the same session.
AFI 1 / SAFI 1 IPv4 unicast -- the traditional BGP address family. AFI 2 / SAFI 1 is IPv6 unicast. Multiple AFIs can run on a single BGP session.
Capability Negotiation During OPEN message exchange, routers advertise which AFI/SAFI combinations they support. Only mutually agreed address families are exchanged.

Configuring BGP IPv6 Address Family

IPv6 BGP configuration on Cisco IOS uses the address-family ipv6 context under the BGP process. The session can be established using either the IPv6 LLA or GUA of the peer.

Cisco IOS -- eBGP IPv6 Peering Configuration
router bgp 65001
 bgp router-id 1.1.1.1
 bgp log-neighbor-changes
 ! Define neighbor using IPv6 address
 neighbor 2001:db8:peer::2 remote-as 65002
 neighbor 2001:db8:peer::2 description eBGP-to-ISP-IPv6
 ! Activate IPv6 address family for this neighbor
 address-family ipv6
  neighbor 2001:db8:peer::2 activate
  ! Advertise our IPv6 prefix
  network 2001:db8:cafe::/48
  ! Ensure aggregate exists in routing table
  aggregate-address 2001:db8:cafe::/48 summary-only
 exit-address-family

R1# show bgp ipv6 unicast summary
BGP router identifier 1.1.1.1, local AS number 65001
Neighbor             V    AS MsgRcvd MsgSent  TblVer  Up/Down  State/PfxRcd
2001:DB8:PEER::2     4 65002      78      82       15  01:12:44        2048

IPv6 Next-Hop Problem in iBGP

A common pitfall: when a router learns IPv6 prefixes from an eBGP peer and then advertises them to iBGP peers, it preserves the original next-hop (the eBGP peer's address). The iBGP peers may not have a route to that address, making the BGP route unusable.

Next-Hop Self is Critical for IPv6 iBGP

In IPv4 iBGP, next-hop-self is standard practice. In IPv6, the same rule applies. When a border router advertises IPv6 prefixes learned from eBGP into your iBGP mesh, configure neighbor X next-hop-self in the IPv6 address family so iBGP peers use your loopback as the next-hop. Without this, routes have an unreachable next-hop and are not installed in the FIB.

Cisco IOS -- iBGP IPv6 with Next-Hop-Self
router bgp 65001
 bgp router-id 1.1.1.1
 ! iBGP neighbor using IPv6 loopback
 neighbor 2001:db8:ffff::2 remote-as 65001
 neighbor 2001:db8:ffff::2 update-source Loopback0
 ! Ensure the loopback is reachable via IGP
 address-family ipv6
  neighbor 2001:db8:ffff::2 activate
  neighbor 2001:db8:ffff::2 next-hop-self
 exit-address-family

6PE: IPv6 Provider Edge

Many service provider backbones are IPv4-only MPLS networks. 6PE (RFC 4798) allows these networks to carry IPv6 customer traffic without upgrading every core router to IPv6. Only the Provider Edge (PE) routers need IPv6 capability.

6PE Architecture and Configuration
# Topology: IPv6 CE -- 6PE1 -- MPLS Core (IPv4 only) -- 6PE2 -- IPv6 CE
#
# 6PE routers peer over IPv4 using MP-BGP with IPv6 AFI
# They encode IPv6 next-hop inside a ::ffff:0:0/96 IPv4-mapped address

router bgp 65000
 bgp router-id 1.1.1.1
 ! iBGP to remote 6PE using IPv4 loopback
 neighbor 2.2.2.2 remote-as 65000
 neighbor 2.2.2.2 update-source Loopback0
 ! IPv6 address family over IPv4 session
 address-family ipv6
  neighbor 2.2.2.2 activate
  neighbor 2.2.2.2 send-label    # 6PE: send MPLS labels with IPv6 prefixes
 exit-address-family

PE1# show bgp ipv6 unicast
Network          Next Hop         Metric LocPrf Weight Path
*> 2001:db8:ce1::/48
                 ::FFFF:1.1.1.1          100      0 i
*> 2001:db8:ce2::/48
                 ::FFFF:2.2.2.2          100      0 i
# ::FFFF:x.x.x.x = IPv4-mapped next-hop used in 6PE

6VPE (RFC 4659) extends 6PE to support VPN isolation. IPv6 customer routes are carried in VPNv6 address family (AFI 2, SAFI 128) using Route Distinguishers and Route Targets, enabling multiple IPv6 VPNs over the same MPLS backbone.

6PE (RFC 4798) IPv6 transit over IPv4 MPLS. Single global IPv6 routing table on PE. Suitable for internet IPv6 transit where isolation is not needed.
6VPE (RFC 4659) IPv6 VPN service over IPv4 MPLS. VPNv6 address family with RD/RT. Each VPN customer gets isolated IPv6 routing. Equivalent to IPv4 L3VPN.

Practice Questions

  2. In a 6PE deployment, what IPv6 address format is used in the BGP next-hop field, and why does this format exist?
  3. Write the IOS configuration for a dual-stack eBGP peer session that exchanges both IPv4 and IPv6 prefixes with a single neighbor at 192.168.1.2 (IPv4 session, peer AS 65002).
  4. What is the difference between 6PE and 6VPE in terms of the BGP address families used and the isolation they provide?

Key Takeaways

  • MP-BGP adds AFI/SAFI to carry any address family -- IPv6 unicast is AFI 2 / SAFI 1
  • IPv6 BGP sessions activate per-neighbor in the address-family ipv6 context; the TCP session can be IPv4 or IPv6
  • next-hop-self is essential for iBGP IPv6 -- without it, iBGP peers cannot resolve the eBGP next-hop
  • 6PE carries IPv6 over IPv4 MPLS using IPv4-mapped IPv6 next-hops (::ffff:x.x.x.x) with labeled routes
  • 6VPE extends 6PE to VPN isolation using VPNv6 AFI with Route Distinguishers and Route Targets
