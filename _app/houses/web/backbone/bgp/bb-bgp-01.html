What Is BGP?

Border Gateway Protocol version 4 (BGP-4) is the routing protocol that interconnects the entire internet. While OSPF and EIGRP handle routing within a network, BGP handles routing between networks -- specifically between Autonomous Systems (ASes). It is the only Exterior Gateway Protocol (EGP) in widespread use today, standardized in RFC 4271.

Unlike OSPF which floods topology information, BGP is a path-vector protocol. Each BGP router advertises prefixes along with the full AS path those prefixes have traversed. This makes BGP loop-resistant by design: a router simply drops any update that contains its own AS number in the AS path.

Key Characteristic

BGP is a policy-driven protocol. It is intentionally designed to be controlled. Network operators apply route filters, communities, and local preference to shape exactly which paths traffic takes. This makes BGP the most powerful -- and most complex -- routing protocol in existence.

Path Vector Protocol Advertises complete AS path with each prefix, enabling loop prevention without topology flooding.
TCP-Based (Port 179) Rides on TCP for reliability. BGP itself handles no fragmentation or retransmission -- TCP does.
Incremental Updates After initial full table exchange, only changed prefixes are sent. No periodic full refreshes.
Policy Engine Route maps, prefix lists, communities, and attributes give operators granular traffic engineering control.

Autonomous Systems

An Autonomous System is a collection of IP prefixes under a single administrative domain that presents a common routing policy to the internet. Each AS is identified by an AS Number (ASN). Originally 16-bit (1-65535), AS numbers were extended to 32-bit (4-byte) in RFC 4893 to accommodate growth.

ASN Range Type Purpose
1 - 64511 Public (16-bit) Globally routable, assigned by IANA via RIRs (ARIN, RIPE, APNIC)
64512 - 65534 Private (16-bit) Internal use only -- must be stripped before advertising to internet peers
65535 Reserved Used in documentation and examples (like 65535 itself, 65534, 64512)
131072 - 4199999999 Public (32-bit) Extended range for 4-byte ASNs to support internet growth
4200000000 - 4294967294 Private (32-bit) Large private range for internal 4-byte ASN use

4-byte ASNs are represented in either plain notation (e.g. 65536) or dot notation (e.g. 1.0 for 65536). Cisco IOS defaults to plain notation but supports dot notation with bgp asnotation dot.

eBGP vs iBGP

BGP comes in two flavors distinguished by whether the peering occurs between the same or different AS numbers.

eBGP (External BGP) Peering between different ASes. The default assumption is directly connected neighbors. Administrative distance is 20. TTL of BGP packets is 1 by default, preventing multi-hop without explicit configuration.
iBGP (Internal BGP) Peering within the same AS. Neighbors do not need to be directly connected. Administrative distance is 200. iBGP speakers do not re-advertise routes learned from other iBGP peers -- this prevents loops but requires full mesh or route reflectors.

iBGP Split Horizon Rule

A route learned from an iBGP peer is never advertised to another iBGP peer. This is not configurable -- it is BGP's loop-prevention mechanism for internal routing. The consequence: without route reflectors or confederations, all iBGP speakers must form a full mesh. For n routers, that means n*(n-1)/2 sessions.

BGP Message Types

BGP defines four message types, all sharing a common 19-byte header containing a 16-byte marker, 2-byte length, and 1-byte type field.

TypeNamePurpose
1OPENInitiates a BGP session. Contains BGP version (4), local ASN, hold time, BGP identifier (Router ID), and optional capabilities.
2UPDATEAdvertises new prefixes (NLRI) or withdraws previously advertised routes. Contains path attributes for new routes.
3NOTIFICATIONSignals an error condition. Immediately followed by session teardown. Contains error code and subcode.
4KEEPALIVE19-byte header only (no data). Sent every 1/3 of the hold timer to maintain the session. Default: every 60 seconds.

BGP Finite State Machine

Before two BGP routers can exchange routing information, they must progress through six states. Understanding these states is essential for troubleshooting sessions that fail to establish.

StateDescription
IdleInitial state. BGP is not attempting a connection. Caused by admin shutdown, failed TCP connection, or hold timer expiry. The router waits ConnectRetryTimer before trying again.
ConnectWaiting for TCP connection to complete on port 179. If TCP succeeds, moves to OpenSent. If it fails, moves to Active and retries.
ActiveTCP connection failed. BGP is actively trying to initiate a new TCP session. A router stuck in Active typically means TCP connectivity issues.
OpenSentTCP connected. Local OPEN message sent. Waiting to receive OPEN from the peer. Verifies BGP version, ASN, and hold time in received OPEN.
OpenConfirmLocal OPEN processed successfully. Sent KEEPALIVE in response. Waiting for peer's KEEPALIVE to confirm the session parameters.
EstablishedSession is up. KEEPALIVE received from peer. BGP UPDATE messages can now be exchanged. This is the operational state.
Cisco IOS -- Verify BGP Session State
R1# show ip bgp summary
BGP router identifier 10.0.0.1, local AS number 65001
BGP table version is 12, main routing table version 12
5 network entries using 740 bytes of memory

Neighbor        V    AS MsgRcvd MsgSent   TblVer  InQ OutQ Up/Down  State/PfxRcd
10.0.0.2        4 65002      48      51       12    0    0 00:38:15        3
192.168.1.1     4 65001      22      24       12    0    0 00:31:04        2

When the State/PfxRcd column shows a number, the session is Established and that number is how many prefixes were received from that peer. Any state name (Idle, Active, Connect) indicates the session is not up.

BGP Router ID

Every BGP speaker identifies itself with a 32-bit BGP Router ID (RID). It is formatted like an IP address but functions purely as an identifier -- it does not need to be routable. Cisco IOS selects the RID automatically in this order:

  1. Highest IP address on a loopback interface
  2. Highest IP address on any active interface (if no loopbacks exist)
  3. Manually configured via bgp router-id A.B.C.D

In production, always manually configure the Router ID from a loopback interface. Automatic selection from physical interfaces can change if an interface goes down, potentially causing a session reset.

Cisco IOS -- Manual Router ID and Basic eBGP Session
! Configure BGP process with AS number
router bgp 65001
 bgp router-id 1.1.1.1
 bgp log-neighbor-changes
 ! eBGP peer in AS 65002
 neighbor 10.0.0.2 remote-as 65002
 neighbor 10.0.0.2 description eBGP-to-ISP-A

Hold Timer and Keepalives

During OPEN message exchange, both routers negotiate a hold timer. The lower value of the two offered hold times is used. If a router does not receive a KEEPALIVE or UPDATE within the hold timer period, it declares the session dead and sends a NOTIFICATION.

The default hold time is 180 seconds. Keepalives are sent every 60 seconds (1/3 of hold time). In configurations requiring fast failover, operators reduce these values:

Cisco IOS -- Tuning Timers (aggressive failover)
router bgp 65001
 neighbor 10.0.0.2 timers 10 30
 ! keepalive=10s, hold-time=30s
 ! Peer with fastest detection possible: BFD integration
 neighbor 10.0.0.2 fall-over bfd

Timer Negotiation

If Router A offers hold time 30 and Router B offers hold time 180, the negotiated hold time is 30. The keepalive interval becomes 10 seconds. Always ensure both sides of a peering agree on appropriate timer values to avoid unexpected session drops under load.

Practice Scenario

You are configuring a BGP peering between two routers. R1 is in AS 65001 with IP 192.168.12.1. R2 is in AS 65002 with IP 192.168.12.2. After entering the configuration, the session stays in Active state.

  1. List at least four reasons a BGP session might be stuck in Active state.
  2. What command would you use on R1 to verify whether TCP port 179 is reachable to 192.168.12.2?
  3. R2 is configured with neighbor 192.168.12.1 remote-as 65005 but R1's actual AS is 65001. In which state will the session fail, and what message type will signal the error?
  4. Write the IOS configuration for both routers to establish an eBGP session and manually set each router's BGP Router ID from its loopback.

Key Takeaways

  • BGP-4 is the only EGP on the internet -- a path-vector protocol running over TCP port 179
  • AS numbers identify administrative domains; private ASNs (64512-65534) must be stripped before internet peering
  • eBGP peers between different ASes (AD 20, TTL 1 default); iBGP peers within the same AS (AD 200, full mesh required)
  • BGP has four message types: OPEN, UPDATE, NOTIFICATION, KEEPALIVE
  • The FSM progresses: Idle → Connect → Active → OpenSent → OpenConfirm → Established
  • A session stuck in Active means TCP cannot complete -- check reachability, ACLs, and remote AS config
  • Always manually configure the BGP Router ID from a stable loopback interface
