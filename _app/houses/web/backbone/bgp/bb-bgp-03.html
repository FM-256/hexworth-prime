Learning Objectives

  • Recite and apply all 13 steps of Cisco's BGP path selection algorithm in order
  • Predict which path BGP will select given a set of path attributes
  • Explain why a route marked valid may not be the best path
  • Use show commands to identify which step eliminated a competing path

The BGP Decision Process

When BGP has multiple paths to the same destination prefix, it applies a deterministic sequence of tiebreakers to select a single best path. This best path is installed in the routing table and advertised to peers. All other paths are retained in the BGP table as alternates but are not used unless the best path fails.

Before any comparison occurs, a path must be valid: the next-hop must be reachable, the path must not be on the route suppression list, and the peer must be in Established state. Only valid paths enter the decision process.

The Mnemonic: "We Love Oranges As Oranges Mean Pure Refreshment"

Weight, Local-pref, Originated-locally, AS-path-length, Origin-type, MED, Paths-eBGP-over-iBGP, Router-ID (lowest). This covers the first eight steps -- the most important ones to memorize for CCNP-level exams and real-world troubleshooting.

The 13-Step Decision Algorithm

Steps are evaluated in order. The first step that produces a winner ends the comparison. If all steps tie, the route is not added and BGP uses only one path (unless multipath is configured).

  1. 1
    Highest Weight
    Prefer the path with the highest weight. Default is 0 for learned routes, 32768 for locally originated.
    Cisco-proprietary -- local to this router only, not advertised
  2. 2
    Highest Local Preference
    Prefer the path with the highest LOCAL_PREF. Default is 100. Applies within an AS via iBGP.
    Well-known discretionary -- propagated to all iBGP peers
  3. 3
    Locally Originated Route
    Prefer routes originated by the local router via network, redistribute, or aggregate-address.
    Local -- this router originated the route into BGP
  4. 4
    Shortest AS Path
    Prefer the path with the fewest AS hops. AS_SET counts as 1 regardless of its contents. Controllable via AS path prepending.
    Well-known mandatory attribute -- key inbound traffic engineering lever
  5. 5
    Lowest Origin Type
    IGP (i) preferred over EGP (e) preferred over Incomplete (?). In practice this usually means "network" command routes beat redistributed routes.
    Well-known mandatory attribute
  6. 6
    Lowest MED
    Prefer the path with the lowest MULTI_EXIT_DISC. Only compared between paths from the same neighboring AS by default.
    Optional non-transitive -- not propagated beyond the neighboring AS
  7. 7
    eBGP over iBGP
    Prefer paths learned from external BGP peers over internal BGP peers.
    Protocol behavior -- external routes considered more specific/authoritative
  8. 8
    Lowest IGP Metric to Next Hop
    Prefer the path whose BGP next-hop is reachable via the lowest IGP metric (hot potato routing).
    IGP-dependent -- OSPF cost, EIGRP metric, or static route distance
  9. 9
    Oldest eBGP Path
    If multiple eBGP paths tie above, prefer the oldest (most stable) path. This step is skipped if bgp deterministic-med or bgp bestpath as-path ignore is configured.
    Stability preference -- avoids unnecessary path oscillation
  10. 10
    Lowest BGP Router ID (Neighbor RID)
    Prefer the path advertised by the neighbor with the lowest BGP Router ID. This is the primary tiebreaker when all attributes are equal.
    If route reflectors are in use, use Originator ID instead of Router ID
  11. 11
    Shortest Cluster List
    In route reflector environments, prefer the path with the shortest CLUSTER_LIST length.
    Route reflector environments only
  12. 12
    Lowest Neighbor IP Address
    Final tiebreaker: prefer the path from the neighbor with the numerically lowest IP address.
    Final deterministic tiebreaker

Reading Path Selection in show ip bgp

The show ip bgp [prefix] command shows all paths and why each one was or was not selected. The best path is marked with >. For each non-best path, trace through the decision steps to find the first difference.

BGP Multipath

By default BGP installs only one best path into the routing table. Multipath configuration allows BGP to install multiple equal-cost paths, enabling load balancing. The paths must be equal through step 8 (IGP metric) before multipath can apply.

Cisco IOS -- BGP Multipath Configuration
router bgp 65001
 address-family ipv4 unicast
  ! Allow up to 4 eBGP equal-cost paths
  maximum-paths 4
  ! Allow up to 4 iBGP equal-cost paths
  maximum-paths ibgp 4
  ! eiBGP multipath (mix of eBGP and iBGP)
  maximum-paths eibgp 4

Multipath Constraints

For eBGP multipath, paths must have identical AS path length and the same neighbor AS (unless bgp bestpath as-path multipath-relax is configured). For iBGP multipath, all next-hops must have equal IGP metrics. Violating these conditions results in only one path being selected even with multipath enabled.

Conditional Route Advertisement

BGP advertises the best path to peers. It will not advertise a route to a peer if that peer is the source of the best path (split-horizon behavior for eBGP, plus iBGP split-horizon rules). Understanding this is critical when troubleshooting routes that appear in the local BGP table but are not being sent to a specific neighbor.

Cisco IOS -- Verify what is being advertised to a peer

Practice Scenario

Router R1 in AS 65100 has four paths to 198.51.100.0/24. Using the decision algorithm, determine which path wins:

  1. Path A: Weight 100, Local-Pref 150, AS-Path 64500, Origin IGP, MED 50, from eBGP peer 10.0.0.2
  2. Path B: Weight 100, Local-Pref 200, AS-Path 64500 64501, Origin IGP, MED 10, from eBGP peer 10.0.1.2
  3. Path C: Weight 200, Local-Pref 150, AS-Path 64500, Origin IGP, MED 100, from eBGP peer 10.0.2.2
  4. Path D: Weight 100, Local-Pref 150, AS-Path 64500, Origin IGP, MED 50, from iBGP peer 192.168.1.1

Work through each step until a winner emerges. Which step determines the winner? Which paths are eliminated at each step?

Key Takeaways

  • A path must be valid (reachable next-hop, peer Established) before entering the decision process
  • The 13 steps are applied in order -- the first differentiator wins; remaining steps are skipped
  • First 8 steps (mnemonic "We Love Oranges...") cover all practical engineering scenarios
  • Weight and Local Preference are the primary levers operators use to control path selection
  • Steps 9-12 are tiebreakers for paths equal through step 8 -- rarely relevant in production unless paths are intentionally equal
  • BGP multipath requires equality through step 8; use maximum-paths to enable load balancing
  • Use show ip bgp [prefix] to see all paths and identify why a path was not selected
