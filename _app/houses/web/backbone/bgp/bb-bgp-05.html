Learning Objectives

  • Build prefix lists to filter BGP routes by network and prefix length range
  • Construct route maps for multi-condition filtering with attribute manipulation
  • Write AS path access lists using regular expressions to match BGP paths
  • Apply filters correctly as inbound or outbound policy on specific neighbors
  • Verify filter effectiveness using show commands and debug

Filtering Tool Comparison

BGP provides three primary filtering mechanisms. Each has different capabilities and appropriate use cases. Route maps are the most powerful -- they can both filter and modify attributes in a single policy.

Prefix List Matches on network address and prefix length. Fast, simple, preferred for pure prefix-based filtering. Supports ge/le range operators.
AS Path ACL Matches on the AS_PATH attribute using regular expressions. Use when you need to filter based on the ASes a route traversed, not the prefix itself.
Route Map Multi-condition policy with permit/deny and attribute setting. Can match prefix, AS path, community, MED, and more -- and modify attributes on permit.

IP Prefix Lists

Prefix lists are the recommended tool for filtering BGP routes based on IP prefix and length. They process faster than access lists and provide clearer syntax. The sequence number controls evaluation order -- lower numbers are evaluated first.

Prefix lists match two things: the network address AND the prefix length. The ge (greater than or equal) and le (less than or equal) operators define a length range.

Prefix List Syntax and Examples
! Exact match: only 10.0.0.0/8 with length exactly /8
ip prefix-list EXACT-MATCH seq 10 permit 10.0.0.0/8

! Match 10.0.0.0/8 and all more-specific prefixes (/9 through /32)
ip prefix-list ALL-MORE-SPECIFIC seq 10 permit 10.0.0.0/8 le 32

! Match any prefix between /24 and /28 (common: accept host routes up to /28)
ip prefix-list MEDIUM-BLOCKS seq 10 permit 0.0.0.0/0 ge 24 le 28

! Deny default route (0.0.0.0/0) -- block a received default
ip prefix-list NO-DEFAULT seq 5 deny 0.0.0.0/0
ip prefix-list NO-DEFAULT seq 10 permit 0.0.0.0/0 le 32

! Apply to neighbor inbound
router bgp 65001
 address-family ipv4 unicast
  neighbor 10.0.0.2 prefix-list NO-DEFAULT in

Implicit Deny

Like access lists, prefix lists have an implicit deny-all at the end. If you create a prefix list with only deny statements, the last implicit deny will drop everything not matched. Always add a catch-all permit if you want to allow anything not explicitly denied.

AS Path Access Lists

AS path access lists use Cisco-flavor regular expressions to match the AS_PATH attribute. They are applied with ip as-path access-list and referenced from route maps or directly as filter-list on neighbors.

AS Path Regex Reference and Examples
! Regex special characters in AS path context:
! ^   = beginning of AS path (the originating AS)
! $   = end of AS path (the peer's AS, closest to us)
! _   = delimiter: space, start, end, or comma (AS path boundary)
! .   = match any single character
! *   = zero or more of preceding
! +   = one or more of preceding
! ?   = zero or one of preceding (escape with Ctrl+V in IOS CLI)
! []  = character class

! Match routes originated in AS 64500 (and only 64500)
ip as-path access-list 1 permit ^64500$

! Match routes that passed through AS 64500 anywhere in path
ip as-path access-list 2 permit _64500_

! Match locally originated routes (empty AS path)
ip as-path access-list 3 permit ^$

! Match routes that have traversed exactly 2 AS hops
ip as-path access-list 4 permit ^[0-9]+ [0-9]+$

! Deny routes from private AS range (64512-65534)
ip as-path access-list 10 deny _6(4[5-9][0-9][0-9]|5[0-4][0-9][0-9]|5[0-3][0-9])_
ip as-path access-list 10 permit .*

! Apply as filter-list on neighbor
router bgp 65001
 address-family ipv4 unicast
  neighbor 10.0.0.2 filter-list 1 in

Route Maps for BGP Filtering

Route maps are the most flexible BGP filtering tool. They consist of numbered entries with permit or deny actions. Within a permit entry, match conditions are ANDed (all must match). Unmatched routes fall through to the next entry. Entries with no match conditions match everything.

Cisco IOS -- Route Map with Multiple Match Conditions
! Define match objects
ip prefix-list ALLOW-BLOCKS seq 10 permit 192.168.0.0/16 le 24
ip prefix-list ALLOW-BLOCKS seq 20 permit 10.0.0.0/8 le 24
ip as-path access-list 5 permit ^64500$

! Route map: accept matching routes with modified local-pref
!            deny everything else
route-map ISP-A-INBOUND permit 10
 match ip address prefix-list ALLOW-BLOCKS
 match as-path 5
 set local-preference 200
 set community 65001:100
! Implicit deny at end of route-map

! Apply inbound to neighbor
router bgp 65001
 address-family ipv4 unicast
  neighbor 203.0.113.1 route-map ISP-A-INBOUND in

Outbound Filtering: What You Advertise

Outbound filtering controls what prefixes you send to a peer. This is critical for two reasons: security (do not leak internal routes) and BGP hygiene (do not become an accidental transit AS). Every multihomed enterprise should apply strict outbound filters to ISP peers.

BGP Route Leak Prevention

A BGP route leak occurs when a network advertises prefixes it learned from one provider to another provider, accidentally becoming a transit AS and disrupting internet routing. In 2019, a misconfigured Cloudflare customer's router leaked 70,000 prefixes to Verizon, causing major internet disruptions. Outbound prefix list filtering prevents this.

Cisco IOS -- Outbound filter preventing route leaks
! Only allow our own prefixes outbound -- nothing from other ASes ip prefix-list OUR-PREFIXES seq 10 permit 203.0.113.0/24 ip prefix-list OUR-PREFIXES seq 20 permit 10.100.0.0/16 ! Implicit deny: blocks all other prefixes including transit routes router bgp 65001 address-family ipv4 unicast neighbor 203.0.113.1 prefix-list OUR-PREFIXES out neighbor 198.51.100.1 prefix-list OUR-PREFIXES out

Verifying Filters

Cisco IOS -- Filter Verification Commands
! Test a prefix list against a specific prefix
R1# show ip prefix-list detail NO-DEFAULT
ip prefix-list NO-DEFAULT:
   count: 2, range entries: 1, sequences: 5 - 10
   seq 5 deny 0.0.0.0/0 (hit count: 3, refcount: 1)
   seq 10 permit 0.0.0.0/0 le 32 (hit count: 142, refcount: 1)

! Show what was received from a peer (requires soft-reconfig inbound)
R1# show ip bgp neighbors 10.0.0.2 received-routes

! Show what is being sent to a peer
R1# show ip bgp neighbors 10.0.0.2 advertised-routes

! Test an AS path regex before applying
R1# show ip bgp regexp ^64500$

Filtering Lab

AS 65200 is a transit provider. Configure the following policies:

  1. Write a prefix list that accepts only prefixes between /8 and /24, blocking both default routes and host routes (/25 through /32).
  2. Write an AS path ACL that matches any route that passed through AS 64500 anywhere in its path (not just originated there).
  3. Write an AS path ACL that matches routes originated by directly connected peers only (AS path length of exactly 1).
  4. Build a route map that: permits routes matching the prefix list from question 1 AND the AS path from question 2, setting local preference to 150 -- and denies all others.
  5. Write the outbound filter that prevents AS 65200 from leaking transit routes (routes not originating in 65200) to its upstream providers.

Key Takeaways

  • Prefix lists filter on network + prefix length; use ge/le for length ranges; implicit deny at end
  • AS path access lists use regex: ^$ matches locally originated, _ASN_ matches paths through an AS
  • Route maps are the most powerful tool -- they can both filter and set attributes in permit clauses
  • Inbound filters control what you accept; outbound filters control what you advertise to peers
  • Every multihomed network must apply strict outbound filters to ISPs to prevent route leaks
  • Use show ip bgp regexp [regex] to test AS path patterns before applying them
  • Apply clear ip bgp soft after adding or modifying filters to activate them without resetting sessions
