The Problem SD-WAN Solves

Traditional enterprise WANs use MPLS circuits from a single carrier for site-to-site connectivity. MPLS is reliable and has predictable performance, but it is expensive, slow to provision (weeks to months per circuit), inflexible for application-level steering, and incapable of leveraging cheaper internet broadband or LTE as efficient alternatives.

SD-WAN introduces a software layer that abstracts the underlying transport. Multiple transports -- MPLS, broadband internet, LTE/5G -- are bonded into a logical WAN fabric. A centralized controller applies application-aware routing: voice traffic goes over MPLS, bulk transfers use internet broadband, and LTE acts as failover. All sites are provisioned and managed through a single orchestration interface.

Overlay and Underlay Architecture

SD-WAN Overlay / Underlay Separation
OVERLAY (SD-WAN Fabric -- logical, controller-managed)
+--------+     IPsec/GRE tunnels     +--------+     +--------+
| Site A |<-------------------------->| Site B |     | Site C |
| vEdge  |<-----------+              | vEdge  |<--->| vEdge  |
+--------+            |              +--------+     +--------+
                      v
              vManage / vSmart
           (Centralized Orchestration)

UNDERLAY (Physical transports -- unmanaged by SD-WAN)
+----------+   +------------+   +--------+
| MPLS     |   | Broadband  |   | LTE    |
| Circuit  |   | Internet   |   | 4G/5G  |
| (T1/T3)  |   | (Cable/DSL)|   | (eSIM) |
+----------+   +------------+   +--------+
All three carry SD-WAN encrypted tunnels simultaneously

The SD-WAN edge device (vEdge or cEdge) builds encrypted IPsec tunnels over every available underlay transport. The controller continuously monitors each tunnel's latency, jitter, packet loss, and bandwidth. Application-aware routing policies then determine which tunnel carries which application, in real time.

Cisco SD-WAN (Viptela) Components

vManage The GUI and REST API orchestration plane. Network engineers configure policies, templates, and monitor health from vManage. Single pane of glass for the entire SD-WAN fabric.
vSmart Controller Distributes routing and policy information to vEdge devices using OMP (Overlay Management Protocol). Acts as the centralized route reflector for the overlay. Runs as a VM or container.
vBond Orchestrator First point of contact for new vEdge devices. Authenticates the device certificate, discovers vManage and vSmart addresses, and facilitates NAT traversal for the initial connection.
vEdge / cEdge The data plane at each site. vEdge is Viptela hardware; cEdge is Cisco IOS XE running the SD-WAN software. Builds tunnels, enforces policies, and forwards traffic at line rate.
OMP: Overlay Management Protocol
# OMP runs over DTLS/TLS between vEdge and vSmart
# OMP distributes three types of routes:

# 1. OMP Routes (overlay prefixes reachable at each site)
vEdge-Site-A announces:
  prefix=10.1.0.0/16, tloc=203.0.113.1 mpls, color=mpls
  prefix=10.1.0.0/16, tloc=198.51.100.1 inet, color=biz-internet

# 2. TLOC Routes (Transport Locator -- the underlay endpoints)
tloc=203.0.113.1, color=mpls, encap=ipsec, preference=100
tloc=198.51.100.1, color=biz-internet, encap=ipsec, preference=50

# 3. Service Routes (for service insertion: firewall, SIG)
service=firewall, tloc=203.0.113.10, vpn=1

# vSmart applies policy, then distributes routes to all vEdges
# vEdge installs routes in its RIB and builds IPsec BFD sessions

Zero-Touch Provisioning (ZTP)

ZTP allows a new SD-WAN edge device to be shipped directly to a remote site, plugged in by non-technical staff, and automatically provisioned without any manual configuration. The only requirement is that the device can reach the internet.

ZTP Onboarding Sequence
# 1. vEdge ships from factory with Cisco-signed certificate
# 2. Site staff plugs in power + WAN circuit
# 3. vEdge contacts Cisco ZTP server (ztp.viptela.com)
vEdge --[HTTPS: "who is my vBond?"]--> ztp.viptela.com
ZTP server responds: vBond=203.0.113.100

# 4. vEdge contacts vBond, presents certificate
vEdge --[DTLS: cert=12345]--> vBond
vBond validates cert against whitelist in vManage
vBond responds: vManage=10.0.0.1, vSmart=10.0.0.2

# 5. vEdge downloads device template from vManage
vEdge --[NETCONF]--> vManage: "apply my template"
vManage sends: hostname, VPN config, interface roles, routing policy

# 6. vEdge builds BFD sessions to discover available TLOCs
# 7. vEdge announces OMP routes to vSmart
# 8. Site is operational -- no CLI touch required

Application-Aware Routing Policies

The core value proposition of SD-WAN is steering applications to the best-performing path. Policies are defined in vManage as data policies applied to VPN traffic. BFD (Bidirectional Forwarding Detection) runs over each tunnel and measures loss, latency, and jitter every second.

vManage Data Policy -- SLA-Based Routing (CLI representation)
# Policy: Voice (DSCP EF) must use path with <50ms latency, <1% loss
# Prefer MPLS; failover to biz-internet if MPLS SLA is violated

policy
 data-policy _Voice_SLA
  vpn-list Corporate
   sequence 10
    match
     dscp 46         # DSCP EF = voice traffic
    action accept
     set
      local-tloc-list
       color mpls
       encap ipsec
      backup-tloc-list
       color biz-internet
       encap ipsec
      sla-class VoiceSLA   # Reference SLA definition below
   default-action accept

sla-class VoiceSLA
 loss    1           # Max 1% packet loss
 latency 50          # Max 50ms round-trip latency
 jitter  10          # Max 10ms jitter

Key Takeaways

  • SD-WAN overlays an encrypted fabric over multiple transport types (MPLS, internet, LTE) simultaneously
  • Cisco SD-WAN uses four planes: vManage (orchestration), vSmart (control/OMP), vBond (NAT/auth), vEdge/cEdge (data)
  • OMP distributes overlay routes, TLOC routes, and service routes between vSmart and all vEdge devices
  • ZTP enables plug-and-go deployment: device contacts Cisco ZTP server, receives vBond address, self-provisions from vManage template
  • BFD probes each tunnel every second; SLA policies switch traffic to backup paths automatically when thresholds are violated
