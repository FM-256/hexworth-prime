The Programmability Stack

Network programmability standardizes how management tools interact with network devices. The stack replaces ad-hoc CLI scraping with structured, schema-validated APIs. The four key technologies are NETCONF (protocol), RESTCONF (HTTP wrapper), YANG (data modeling language), and gRPC/gNMI (high-performance streaming telemetry).

NETCONF: Sessions and Operations

NETCONF runs over SSH on port 830. The client and server exchange capabilities in the Hello phase, then the client can perform NETCONF operations (RPC calls) on the server's datastores. NETCONF defines three datastores: running (active config), candidate (staging area), and startup (config applied at boot).

NETCONF Session with ncclient (Python)
from ncclient import manager
import xmltodict
import json

# Connect to device via NETCONF (SSH port 830)
with manager.connect(
    host='192.168.1.1',
    port=830,
    username='admin',
    password='secret',
    hostkey_verify=False
) as m:

    # Get running configuration (all or filtered)
    filter_xml = """
    <filter type="subtree">
      <native xmlns="http://cisco.com/ns/yang/Cisco-IOS-XE-native">
        <interface/>
      </native>
    </filter>
    """
    response = m.get_config(source='running', filter=filter_xml)
    config_dict = xmltodict.parse(response.xml)
    interfaces = config_dict['rpc-reply']['data']['native']['interface']
    print(json.dumps(interfaces, indent=2))

    # Edit configuration: set interface description
    edit_payload = """
    <config>
      <native xmlns="http://cisco.com/ns/yang/Cisco-IOS-XE-native">
        <interface>
          <GigabitEthernet>
            <name>1</name>
            <description>Uplink to Core-01</description>
          </GigabitEthernet>
        </interface>
      </native>
    </config>
    """
    m.edit_config(target='running', config=edit_payload)

RESTCONF: REST API over YANG

RESTCONF (RFC 8040) maps YANG data model paths to URL paths and uses standard HTTP verbs: GET (read), PUT (replace), PATCH (merge/update), POST (create), DELETE. The root URL is /restconf; data is accessed under /restconf/data.

RESTCONF with Python requests
import requests
requests.packages.urllib3.disable_warnings()

BASE = 'https://192.168.1.1/restconf/data'
HEADERS = {
    'Accept': 'application/yang-data+json',
    'Content-Type': 'application/yang-data+json'
}
AUTH = ('admin', 'secret')

# GET: Read all interfaces
r = requests.get(
    f'{BASE}/ietf-interfaces:interfaces',
    headers=HEADERS, auth=AUTH, verify=False
)
print(r.json())

# PATCH: Enable an interface
payload = {
    "ietf-interfaces:interface": [{
        "name": "GigabitEthernet1",
        "enabled": True,
        "description": "Uplink-Core"
    }]
}
r = requests.patch(
    f'{BASE}/ietf-interfaces:interfaces',
    headers=HEADERS, auth=AUTH, json=payload, verify=False
)
print(r.status_code)  # 204 No Content = success

# DELETE: Remove a static route
r = requests.delete(
    f'{BASE}/ietf-routing:routing/static-routes/route=0.0.0.0%2F0',
    headers=HEADERS, auth=AUTH, verify=False
)
print(r.status_code)  # 204 = success

YANG Data Models

YANG (RFC 7950) is the data modeling language used by NETCONF and RESTCONF. It defines the structure, syntax, and semantics of configuration and operational data exposed by network devices. YANG is hierarchical: modules contain containers and lists, which contain leaf nodes with typed values.

YANG Module Structure (Simplified Interface Model)
# Simplified YANG for interface configuration
module ietf-interfaces {
  namespace "urn:ietf:params:xml:ns:yang:ietf-interfaces";
  prefix if;

  container interfaces {              // Container: groups related nodes
    list interface {                  // List: multiple instances, keyed by 'name'
      key "name";

      leaf name {                     // Leaf: single value
        type string;
        mandatory true;
      }
      leaf description {
        type string;
      }
      leaf enabled {
        type boolean;
        default true;
      }
      leaf-list alias {               // leaf-list: multiple string values
        type string;
      }
      container ipv4 {
        leaf address {
          type inet:ipv4-prefix;
        }
      }
    }
  }
}

# YANG types: string, uint8/16/32/64, boolean, enumeration,
#             inet:ipv4-address, inet:ipv6-prefix, identityref
YANG Model Sources

Standard YANG models are defined by IETF (ietf-interfaces, ietf-routing), OpenConfig (openconfig-bgp, openconfig-mpls), and vendors (Cisco-IOS-XE-*, Juniper-*). The Yang Catalog (yangcatalog.org) indexes thousands of published modules. The pyang tool validates and visualizes YANG trees.

gRPC and gNMI Streaming Telemetry

gRPC Network Management Interface (gNMI) uses Protocol Buffers over HTTP/2 for high-performance, low-latency telemetry. Unlike SNMP polling, gNMI uses a push model: the device streams data at configured intervals or on change. This enables sub-second visibility into interface counters, BGP state, CPU, and buffer utilization.

gNMI Subscription with pygnmi (Python)
from pygnmi.client import gNMIclient, telemetryParser

# Define paths to subscribe to
paths = [
    'interfaces/interface[name=GigabitEthernet1]/state/counters',
    'system/memory/state',
    'network-instances/network-instance[name=default]/protocols/protocol[name=BGP]/bgp/neighbors'
]

with gNMIclient(
    target=('192.168.1.1', 6030),
    username='admin',
    password='secret',
    insecure=True
) as gc:

    # Subscribe: SAMPLE mode every 10 seconds
    telemetry_stream = gc.subscribe(
        subscribe={
            'subscription': [
                {'path': path, 'mode': 'SAMPLE',
                 'sample_interval': 10_000_000_000}
                for path in paths
            ],
            'mode': 'STREAM',
            'encoding': 'JSON_IETF'
        }
    )

    for item in telemetry_stream:
        data = telemetryParser(item)
        print(json.dumps(data, indent=2))

Key Takeaways

  • NETCONF uses SSH port 830, XML encoding, and exposes running/candidate/startup datastores via RPC operations
  • RESTCONF maps YANG paths to URL paths; HTTP verbs (GET/PATCH/PUT/DELETE) correspond to CRUD operations
  • YANG is the schema language -- modules define containers, lists, and leafs; all NETCONF/RESTCONF data conforms to YANG models
  • gNMI streaming telemetry pushes data at sub-second intervals; ON_CHANGE subscriptions fire only when state changes, reducing bandwidth
  • Python libraries: ncclient (NETCONF), requests (RESTCONF), pygnmi (gNMI) -- the core automation toolkit for any network engineer
