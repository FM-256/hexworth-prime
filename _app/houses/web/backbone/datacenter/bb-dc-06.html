The Storage/Compute Network Divide

Traditional data centers ran two physically separate networks: a compute network for server-to-server and server-to-internet traffic (Ethernet), and a storage network connecting servers to SAN (Storage Area Network) arrays (Fibre Channel). This separation was justified by performance requirements: storage I/O is extremely latency-sensitive, and mixing it with general-purpose network traffic risked introducing jitter and packet loss that would destroy storage performance.

Fibre Channel's lossless, in-order delivery guarantees made it the dominant storage fabric for 20+ years. But maintaining two separate physical networks doubled cabling costs, doubled switch costs, doubled operational complexity, and required specialized FC skills. The 10GbE and 25GbE era brought enough bandwidth headroom that storage and compute traffic could safely share a single Ethernet fabric -- provided the Ethernet fabric could be made lossless.

Fibre Channel (FC) Purpose-built lossless 4/8/16/32G storage protocol. Guaranteed delivery, ordered frames. Mature ecosystem but proprietary, expensive, requires FC skills.
FCoE FC frames encapsulated in Ethernet. Converges FC and Ethernet on single physical infrastructure. Requires DCB (lossless Ethernet) but not a dedicated FC fabric.
iSCSI SCSI over TCP/IP. Runs on standard Ethernet, no special hardware. Lower performance but massively simplified operations and lower cost.
NVMe-oF NVMe protocol over a fabric transport (RoCE, iWARP, TCP, FC). Designed from scratch for flash storage -- microsecond latency, parallel queues, no SCSI overhead.

Fibre Channel Architecture

A Fibre Channel SAN consists of Initiators (servers with HBAs -- Host Bus Adapters), Targets (storage array controllers), and Fabric switches (FC switches from Cisco MDS, Brocade). The fabric provides three services: NS (Name Server) for device discovery, FLOGI/PLOGI for login and session establishment, and zoning for access control.

  WWPN: World Wide Port Name -- unique per HBA port (like MAC address)
  WWNN: World Wide Node Name -- unique per device
  FC-ID: 24-bit address assigned by fabric after FLOGI
  Zoning: controls which initiator WWPNs can see which target WWPNs

Zoning is the FC equivalent of ACLs for storage access control. Hard zoning enforces access in hardware (ASIC). Soft zoning enforces it in the Name Server (can be bypassed by a misconfigured HBA). Best practice is hard zoning with WWPN-based zones, with a single initiator per zone (one server per zone prevents one server from accidentally accessing another server's storage LUN).

FCoE: Converging FC onto Ethernet

FCoE (Fibre Channel over Ethernet, IEEE 802.1Qbb) encapsulates FC frames in Ethernet frames for transmission over a standard 10G+ Ethernet network. A CNA (Converged Network Adapter) in the server appears as both an FC HBA and an Ethernet NIC to the OS, sending both FC and Ethernet traffic over the same physical cable to a top-of-rack switch that supports both Ethernet and FCoE forwarding.

FCoE requires lossless Ethernet because FC has no mechanism to recover from dropped frames -- a dropped FC frame requires the entire transaction to restart (unlike TCP which retransmits individual segments). Ethernet is fundamentally lossy under congestion. DCB (Data Center Bridging) makes Ethernet lossless for FCoE traffic.

DCB: Making Ethernet Lossless

Data Center Bridging is a suite of IEEE 802.1 extensions that add lossless behavior to Ethernet for storage traffic:

  • PFC (Priority Flow Control, 802.1Qbb): Per-priority pause frames. When a buffer threshold is reached for a specific CoS (class of service), the switch sends a PAUSE frame only for that CoS value, not all traffic. FC/FCoE traffic uses CoS 3.
  • ETS (Enhanced Transmission Selection, 802.1Qaz): Bandwidth allocation between traffic classes (e.g., 40% for FCoE, 60% for Ethernet).
  • DCBX (DCB Capability Exchange, 802.1Qaz): Protocol for switches and CNAs to negotiate DCB parameters automatically.

iSCSI

iSCSI (Internet SCSI, RFC 3720) encapsulates SCSI commands in TCP/IP, allowing block storage access over any standard Ethernet network. Unlike FCoE, iSCSI does not require special hardware or lossless Ethernet -- it runs on standard NICs and standard Ethernet switches. TCP's reliability layer provides error correction and retransmission.

The performance penalty of running SCSI over TCP adds latency: TCP's three-way handshake, ACK overhead, and retransmission mechanics add milliseconds in congested networks. For high-performance workloads (databases, virtual desktop infrastructure), iSCSI over standard Ethernet is often insufficient. iSCSI performance improves significantly on networks with RDMA (Remote Direct Memory Access) capable NICs.

NVMe-oF: The Future of Storage Networking

NVMe (Non-Volatile Memory Express) is the protocol designed for flash storage. Traditional SCSI has a single command queue with up to 32 outstanding commands -- a design from the spinning disk era. NVMe supports 65,535 queues with 65,535 commands per queue, matching the parallelism of modern NVMe SSDs. NVMe-oF (NVMe over Fabrics) extends this protocol over a network fabric.

NVMe-oF defines transport bindings: RoCE v2 (RDMA over Converged Ethernet), iWARP (RDMA over TCP), Fibre Channel (NVMe/FC), and TCP (NVMe/TCP added in 2021). Each transport has different performance characteristics and infrastructure requirements.

NVMe-oF Transport Comparison
NVMe/FC
  Host NVMe driver --> FC HBA --> FC Fabric --> Storage Target
  Latency: ~5-10 us
  Requires: Existing FC infrastructure + NVMe/FC capable HBAs
  Status: Mature, shipping from Pure, NetApp, HPE

NVMe/RoCE v2
  Host NVMe driver --> RDMA NIC --> Lossless Ethernet --> Storage Target
  Latency: ~15-30 us
  Requires: RDMA-capable NICs (Mellanox/NVIDIA ConnectX), DCB/PFC on fabric
  Status: Production at hyperscale, shipping from many vendors

NVMe/iWARP
  Host NVMe driver --> iWARP NIC --> Standard Ethernet --> Storage Target
  Latency: ~40-80 us (TCP overhead vs. RoCE)
  Requires: iWARP-capable NICs (Chelsio T6, Intel E810 with iWARP)
  Status: Niche, simpler than RoCE but less adopted

NVMe/TCP
  Host NVMe driver --> Standard NIC --> Standard Ethernet --> Storage Target
  Latency: ~100-300 us
  Requires: Standard hardware -- no special NICs, no DCB
  Status: Most accessible, recommended for new deployments where FC is absent

NVMe/TCP: The Right Default for New Deployments

  • NVMe/TCP requires zero special hardware -- works on any NIC, any Ethernet switch
  • Latency is higher than RoCE but dramatically lower than iSCSI for equivalent workloads because NVMe eliminates SCSI command overhead
  • Linux kernel 5.14+ includes native NVMe/TCP target support -- no proprietary software required
  • Choose NVMe/RoCE when you need sub-50us latency and already have or plan RDMA infrastructure
  • Keep Fibre Channel if you have existing FC investment and no compelling reason to migrate -- FC is mature and stable

Converged vs. Dedicated Storage Fabrics

Modern DC design decisions around storage networking center on whether to converge storage traffic onto the general Ethernet fabric or maintain a dedicated storage fabric.

Key Takeaways

  • Fibre Channel provides native lossless storage networking but requires dedicated infrastructure and specialized skills
  • FCoE converges FC onto Ethernet but requires DCB (PFC + ETS + DCBX) to make Ethernet lossless for storage traffic
  • iSCSI is the simplest storage network option -- standard NICs, standard Ethernet -- but pays a TCP overhead latency penalty
  • NVMe-oF is the future: NVMe's 65,535-queue parallelism maps to flash hardware, eliminating the SCSI single-queue bottleneck
  • NVMe/TCP is the most accessible NVMe-oF transport -- no special hardware; NVMe/RoCE delivers microsecond latency when RDMA NICs and DCB are available
  • Converged fabrics reduce cost and operational complexity; dedicated FC SANs remain appropriate for tier-1 enterprise databases with existing investment
