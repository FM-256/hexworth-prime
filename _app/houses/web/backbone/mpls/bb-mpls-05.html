Why Traffic Engineering?

Traditional routing protocols (OSPF, IS-IS) select paths based on lowest metric. This leads to traffic concentration on shortest paths while parallel, higher-metric paths remain underutilized. In SP networks with expensive long-haul fiber, this asymmetry is operationally costly and creates congestion on preferred links.

MPLS Traffic Engineering (RFC 3209, RFC 2702) allows operators to explicitly route traffic over specific paths independent of IGP shortest-path, reserve bandwidth along those paths, and provide fast protection switching when links or nodes fail. TE decouples the traffic placement decision from the IGP topology calculation.

  IGP Shortest Path:            TE-Optimized Path:

        10 Gbps                       10 Gbps
  A ---[10 Gbps]--- B           A ---[10 Gbps]--- B
  |                 |           |                 |
  |  metric=10      | metric=5  | Tunnel-1: 5G   | Tunnel-2: 5G
  |                 |           |  over top path  |  over bottom path
  C ---[10 Gbps]--- D           C ---[10 Gbps]--- D
        metric=20                     metric=20

  IGP sends ALL traffic A->D    TE distributes load:
  via B (lowest metric=15)      5G on A-B-D, 5G on A-C-D
  C-D link sits idle            No congestion on either path

TE Constraints and CSPF

MPLS-TE uses Constrained Shortest Path First (CSPF) to compute TE tunnel paths. CSPF extends Dijkstra's algorithm with constraint pruning: before running SPF, links that cannot satisfy the tunnel's constraints are removed from the topology graph.

ConstraintDescriptionIGP TE Extension
BandwidthMinimum available bandwidth required on each link. Links with insufficient bandwidth are pruned before CSPF run.OSPF-TE sub-TLV, IS-IS-TE sub-TLV (RFC 3630, RFC 3784)
Affinity (Admin Groups)Color-coded link attributes. Tunnel can include or exclude links with specific colors. Used for policy: "use only gold links" or "avoid backup links."Link color attribute in TE extensions
Hop LimitMaximum number of hops the path may traverse. Limits latency and prevents paths through distant parts of the network.Configured per tunnel
Explicit PathOperator manually specifies exact routers (strict) or waypoints (loose) the path must traverse. Overrides CSPF computation entirely.Explicit Route Object (ERO) in RSVP PATH

TE topology information (available bandwidth, admin groups) is flooded by the IGP using TE extensions. Each router maintains a TE database (TED) that is the input to CSPF. The TED is separate from and supplemental to the normal IGP topology.

RSVP-TE: Signaling the LSP

Once CSPF computes a path, RSVP-TE (Resource Reservation Protocol - Traffic Engineering, RFC 3209) signals the path and reserves bandwidth. RSVP-TE uses two message types in a request-response exchange:

  Ingress                                            Egress
  [PE1] --PATH--> [P1] --PATH--> [P2] --PATH--> [PE2]
        <----RESV--- [  ] <----RESV--- [  ] <----RESV---

  PATH message (ingress to egress):
  - Session: identifies the LSP (tunnel endpoint + ID)
  - ERO: Explicit Route Object -- the computed or configured path
  - TSPEC: traffic spec (peak rate, token bucket)
  - SENDER_TEMPLATE: tunnel sender address + LSP-ID

  RESV message (egress to ingress, reverse path):
  - Carries LABEL object: each router allocates and returns a label
  - FLOWSPEC: confirms bandwidth reservation
  - Each hop builds an RSVP soft-state entry + installs LFIB entry
RSVP Soft State

Unlike LDP which uses hard state, RSVP uses soft state: PATH and RESV messages are refreshed periodically (default every 30 seconds). If a router stops receiving refreshes, it tears down the RSVP state after the refresh timeout. This means RSVP state is automatically cleaned up if a tunnel disappears, but also requires ongoing keepalive traffic. RSVP Summary Refresh (RFC 2961) greatly reduces this overhead in production networks.

Configuring MPLS-TE Tunnels

IOS-XE — MPLS-TE prerequisites and tunnel creation
! Enable TE globally and enable RSVP on interfaces
PE1(config)# mpls traffic-eng tunnels
PE1(config)# interface GigabitEthernet0/0
PE1(config-if)# mpls traffic-eng tunnels
PE1(config-if)# ip rsvp bandwidth 1000000   ! 1000 Mbps reservable

! Enable TE in OSPF (floods TE link attributes)
PE1(config)# router ospf 1
PE1(config-router)# mpls traffic-eng area 0
PE1(config-router)# mpls traffic-eng router-id Loopback0

! Create TE tunnel interface
PE1(config)# interface Tunnel100
PE1(config-if)# ip unnumbered Loopback0
PE1(config-if)# tunnel mode mpls traffic-eng
PE1(config-if)# tunnel destination 10.0.0.3        ! PE3 loopback
PE1(config-if)# tunnel mpls traffic-eng bandwidth 500000   ! Reserve 500 Mbps
PE1(config-if)# tunnel mpls traffic-eng path-option 1 dynamic   ! CSPF

! Verify tunnel is up and path is computed
PE1# show mpls traffic-eng tunnels brief

                                    TUNNEL   LSP
NAME                     DEST       STATUS   STATUS   PATH   BW
Tunnel100                10.0.0.3   up       up       OSPF   500000
  path option 1, type dynamic  Gi0/0 -> Gi0/1 -> (to 10.0.0.3)
IOS-XE — explicit path configuration
! Define an explicit path through specific routers
PE1(config)# ip explicit-path name TO-PE3-VIA-P2 enable
PE1(config-ip-expl-path)# next-address strict 10.1.12.2   ! must go via P2
PE1(config-ip-expl-path)# next-address strict 10.0.0.3

! Apply to tunnel as path-option (lower number = preferred)
PE1(config)# interface Tunnel100
PE1(config-if)# tunnel mpls traffic-eng path-option 1 explicit name TO-PE3-VIA-P2
PE1(config-if)# tunnel mpls traffic-eng path-option 2 dynamic   ! fallback

MPLS-TE Fast Reroute (FRR)

MPLS-TE FRR provides sub-50ms protection against link and node failures. When a protected LSP's primary path fails, traffic is immediately switched to a pre-computed and pre-signaled backup path. The backup path is established before any failure occurs, so protection switching is local and instantaneous.

Link Protection Protects against failure of a single link. Backup LSP bypasses the protected link. Node that detects the failure switches traffic to bypass in <50ms without waiting for IGP reconvergence.
Node Protection Protects against failure of an intermediate node (router). Backup LSP bypasses both the link to the failed node and the node itself. More comprehensive but requires more complex path computation.
IOS-XE — FRR configuration (primary and backup tunnel)
! Enable FRR on the primary tunnel (Tunnel100)
PE1(config)# interface Tunnel100
PE1(config-if)# tunnel mpls traffic-eng fast-reroute

! Create backup tunnel (bypass) on the PLR (Point of Local Repair)
P1(config)# interface Tunnel900
P1(config-if)# ip unnumbered Loopback0
P1(config-if)# tunnel mode mpls traffic-eng
P1(config-if)# tunnel destination 10.0.0.3
P1(config-if)# tunnel mpls traffic-eng path-option 1 dynamic
P1(config-if)# tunnel mpls traffic-eng backup-bw any

! Verify FRR protected tunnels
P1# show mpls traffic-eng fast-reroute database

Tunnel head end:
  Tunnel100 (10.0.0.1:100)  state: Standby
    Primary (in use):   10.0.0.1 -> P1 -> P2 -> 10.0.0.3
    Backup:             10.0.0.1 -> P1 -> P3 -> 10.0.0.3 (Tunnel900)
    Protection: link
FRR Timing

FRR's protection advantage comes from local failure detection and switching. When P1 detects the P1-P2 link failure (via BFD or hold-down timer), it immediately switches all affected LSPs to the bypass tunnel -- no IGP convergence, no RSVP signaling required. After IGP reconverges (seconds), RSVP re-signals the primary path and traffic reverts.

Steering Traffic into TE Tunnels

Creating a TE tunnel is not enough -- you must configure the router to actually forward traffic through it. Options include:

  • 1.Autoroute Announce: The tunnel is treated as a link in the IGP. OSPF/IS-IS computes shortest paths considering the tunnel. Traffic naturally flows into the tunnel for destinations it serves. Simplest option.
  • 2.Forwarding Adjacency: Tunnel is advertised as a proper TE link into the IGP, allowing other routers to route over it, not just the head-end. More complex but enables multi-hop TE.
  • 3.Static Route: Add a static route for the destination subnet pointing to the tunnel interface. Most explicit control but least dynamic.
  • 4.Policy-Based Routing: Use PBR to redirect specific flows into the tunnel. Useful for per-application TE.
IOS-XE — autoroute announce on TE tunnel
PE1(config)# interface Tunnel100
PE1(config-if)# tunnel mpls traffic-eng autoroute announce

! Verify tunnel appears in IP routing table
PE1# show ip route 10.0.0.3

Routing entry for 10.0.0.3/32
  Known via "ospf 1", distance 110, metric 1
  Routing Descriptor Blocks:
  * 10.0.0.3, via Tunnel100
      Route metric is 1, traffic share count is 1
Knowledge Check

1. What is the role of CSPF in MPLS-TE path computation?

  • A. CSPF distributes TE topology information to all routers in the area
  • B. CSPF signals bandwidth reservations along the computed path using RSVP
  • C. CSPF runs Dijkstra's SPF algorithm on a pruned topology -- links not meeting constraints are removed before computation
  • D. CSPF monitors link utilization and dynamically adjusts tunnel paths every 30 seconds
CSPF is the path computation algorithm. It first prunes the TE topology database (removes links that fail bandwidth, affinity, or hop-count constraints), then runs Dijkstra's SPF on the pruned graph to find the best path. RSVP-TE then signals this path.

2. MPLS-TE Fast Reroute achieves sub-50ms protection because:

  • A. RSVP-TE re-signals a new LSP path within 50ms of detecting a failure
  • B. IGP reconverges within 50ms and RSVP follows immediately
  • C. The bypass tunnel is pre-established before any failure; local failure detection triggers an immediate local switchover without waiting for IGP reconvergence
  • D. BFD replaces RSVP for path signaling in FRR scenarios
FRR's key insight is pre-establishment. The backup bypass tunnel exists before failure. When the PLR (Point of Local Repair) detects the failure, it immediately (in <50ms) redirects traffic to the bypass, entirely independently of IGP/RSVP reconvergence which happens afterward.

3. What is the difference between RSVP-TE link protection and node protection in FRR?

  • A. Link protection bypasses a failed link; node protection bypasses both the failed link and the downstream router, protecting against router failures
  • B. Link protection is faster (<50ms); node protection takes up to 200ms
  • C. Link protection requires RSVP; node protection uses BFD instead
  • D. They are functionally equivalent; the distinction is only in configuration syntax
Link protection backup bypass goes from the PLR to the next-hop router via an alternate path, protecting against link failure. Node protection backup bypass goes from the PLR all the way to the next-next-hop, also protecting against failure of the intermediate node/router.

Key Takeaways

  • MPLS-TE allows explicit path control independent of IGP shortest-path, enabling load distribution
  • CSPF prunes the TE topology (removes links failing constraints) then runs Dijkstra to find the path
  • TE constraints: bandwidth reservation, admin group affinity, hop limit, explicit path
  • RSVP-TE signals the path: PATH message (ingress to egress) + RESV message (egress to ingress, carries labels)
  • RSVP uses soft state -- PATH/RESV must be refreshed periodically (default 30s) to maintain LSP
  • FRR provides sub-50ms protection via pre-established bypass tunnels -- no IGP wait required
  • Link protection bypasses a link; node protection bypasses a failed router entirely
  • Autoroute Announce is the simplest way to steer traffic into TE tunnels via IGP integration
