What Problem Does MPLS Solve?

Traditional IP forwarding requires every router in the path to perform a full routing table lookup for each packet. At internet backbone scale, routers carry millions of routes. Each lookup consumes memory bandwidth and CPU time. In the late 1990s, routing silicon was slow relative to traffic growth, and per-packet longest-prefix-match lookups on million-entry tables were becoming a bottleneck.

MPLS solves this by making a single forwarding decision at the network edge and encoding that decision as a short fixed-length label. Interior routers forward purely on the label -- a simple table lookup against a label switching database with far fewer entries than a full BGP table. The result is deterministic, hardware-friendly forwarding at line rate.

Beyond raw forwarding speed, MPLS creates a separation between the IP routing topology and actual packet paths. This enables traffic engineering (directing flows around congestion), VPN services (isolating customer traffic through label stacks), and QoS differentiation -- all without modifying the IP header.

The MPLS Label

An MPLS label is a 32-bit value inserted between the Layer 2 header and the IP header. This position is sometimes called "Layer 2.5." The label field breaks down as follows:

+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|                Label Value (20 bits)                | EXP |S|  TTL  |

FieldBitsPurpose
Label Value20The forwarding identifier. Values 0-15 are reserved. Normal labels start at 16. Maximum label value is 1,048,575.
EXP (TC)3Originally "Experimental," now called Traffic Class. Used for QoS marking (maps to DSCP). Provides 8 priority classes.
S (Bottom of Stack)1Set to 1 on the innermost label in the stack. Tells the LSR that the next header is IP (or the payload).
TTL8Time to live. Decremented at each hop like IP TTL. Prevents forwarding loops.
Reserved Labels

Labels 0-15 are reserved. Label 0 = IPv4 Explicit NULL (causes penultimate hop to pop and expose IP header). Label 2 = IPv6 Explicit NULL. Label 3 = Implicit NULL (signals penultimate hop popping). Label 14 = OAM Alert Label.

The Label Stack

MPLS supports stacking multiple labels. Each label entry is 4 bytes. The outermost label is processed first. The Bottom-of-Stack (S) bit marks the innermost label. This is critical for VPN services where a transport label (outer) identifies the LSP path and a VPN label (inner) identifies the customer VRF.

  +--------------------+
  |   Ethernet Header  |  (Layer 2)
  +--------------------+
  | Outer Label (20b)|EXP|S=0|TTL |  Transport / tunnel label
  +--------------------+
  | Inner Label (20b)|EXP|S=1|TTL |  VPN / service label (S=1 = bottom)
  +--------------------+
  |    IP Header       |  (Layer 3)
  +--------------------+
  |    Payload         |
  +--------------------+

Routers perform three label operations:

PUSH Add one or more labels to the top of the stack. Done by the ingress LER when a packet enters the MPLS domain.
SWAP Replace the top label with a new label value. Done by P routers (transit LSRs) at each hop along the LSP.
POP Remove the top label. Done by the egress LER or the penultimate hop (PHP). Exposes the next label or the IP header.
PUSH+SWAP Push a new outer label while keeping inner labels unchanged. Used in hierarchical LSP setups and TE tunnels.

Forwarding Equivalence Classes (FEC)

A Forwarding Equivalence Class is the set of packets that receive identical forwarding treatment: same outgoing interface, same next-hop, same label. Packets are classified into a FEC at the ingress LER and assigned a label. From that point forward, each transit LSR makes its forwarding decision based solely on the FEC label.

The most common FEC definition is a destination IP prefix -- all traffic destined for 192.0.2.0/24 forms one FEC. But FECs can also be defined by:

  • - BGP next-hop (very common in SP cores -- one LSP per BGP next-hop address)
  • - OSPF/IS-IS host route (loopback address of a PE router)
  • - Traffic engineering tunnel endpoint
  • - VPN customer prefix (inner label in L3VPN)
FEC vs Route

A FEC is not identical to an IP route. Multiple routes can belong to the same FEC if they share the same forwarding treatment. In an SP core running LDP, the typical FEC granularity is one per /32 loopback of each PE/P router, not one per customer prefix.

Label Switched Paths (LSP)

An LSP is the unidirectional path through the MPLS network that a labeled packet follows for a given FEC. LSPs are built by label distribution protocols (LDP, RSVP-TE, or BGP). LSPs are simplex -- you need one LSP in each direction for bidirectional communication.

Reading the table: when this P router receives a packet with label 16000, it swaps to label 16001 and forwards out Gi0/0/0/0 to next-hop 10.1.12.2. Label 16010 shows "Pop" -- this router is the penultimate hop for prefix 10.0.0.3/32 and will remove the label before forwarding.

Penultimate Hop Popping (PHP)

PHP is a performance optimization. Normally the egress LER receives a labeled packet, performs a label lookup (POP), then performs an IP lookup to forward the packet. PHP shifts the POP operation to the second-to-last router (penultimate hop), eliminating a lookup at the egress.

The egress LER signals PHP by advertising label 3 (Implicit NULL) for its directly connected prefixes. When the penultimate hop receives this, it pops the label before forwarding -- delivering an unlabeled IP packet to the egress LER, which then only needs an IP lookup.

IOS-XE — verifying PHP on egress PE
PE2# show mpls ldp bindings 10.0.0.2 32

  lib entry: 10.0.0.2/32, rev 12
    local binding:  label: imp-null   <-- advertising Implicit NULL (PHP)
    remote binding: lsr: 10.0.0.1:0, label: 100
    remote binding: lsr: 10.0.0.3:0, label: 200
Explicit NULL vs Implicit NULL

Implicit NULL (label 3) causes PHP -- the penultimate router pops the label and forwards an unlabeled packet. Explicit NULL (label 0 for IPv4, label 2 for IPv6) preserves the label until the actual egress, allowing the EXP/TC bits to be read for QoS even at the final hop. Use Explicit NULL when you need to honor QoS markings at the egress LER.

MPLS Packet Walk-Through

Trace a packet from CE1 to CE2 across a three-router MPLS core (PE1, P1, PE2):

Step-by-step label operations
Step 1: CE1 sends IP packet to PE1 (no label)
  CE1 --> PE1:  [IP: src=10.10.1.1, dst=10.20.1.1]

Step 2: PE1 is ingress LER — classifies into FEC, pushes label stack
  PE1 --> P1:   [VPN Label=5001 S=1] [Transport Label=1001 S=0] [IP]
                 (inner=VPN label for CE2 VRF)
                 (outer=transport label for LSP to PE2)

Step 3: P1 is transit LSR — swaps outer transport label only
  P1 --> PE2:   [VPN Label=5001 S=1] [Transport Label=2001 S=0] [IP]
                 (swapped 1001 -> 2001, VPN label untouched)

Step 4: PE2 is egress LER — pops transport label (PHP or explicit pop)
         then pops VPN label, looks up in VRF routing table
  PE2 --> CE2:  [IP: src=10.10.1.1, dst=10.20.1.1]
                 (native IP delivered to CE2)
Knowledge Check

1. A router receives a packet with label 16005 and its LFIB entry for 16005 shows "outgoing label: Pop, interface: Gi0/1." What operation does this router perform?

  • A. Swap label 16005 with a new label and forward
  • B. Remove (pop) the label and forward the unlabeled packet out Gi0/1
  • C. Push an additional label onto the stack
  • D. Drop the packet because the label is reserved
Pop means remove the top label. This router is acting as a penultimate hop (PHP) or the egress LER.

2. Which label value does an egress LER advertise to request Penultimate Hop Popping?

  • A. Label 0 (IPv4 Explicit NULL)
  • B. Label 1
  • C. Label 3 (Implicit NULL)
  • D. Label 16 (first available non-reserved label)
Label 3 is Implicit NULL. Advertising it tells the upstream neighbor to pop the label before forwarding -- that is PHP. Label 0 is Explicit NULL which preserves the label to the final egress.

3. In the MPLS label structure, what does the S bit (Bottom of Stack) being set to 1 indicate?

  • A. The packet is the first in a sequence
  • B. This is the innermost label in the stack; the next header is the payload (IP)
  • C. The TTL field should not be decremented
  • D. The label was pushed by a PE router
The S=1 bit marks the bottom of the label stack. When a router processes S=1, it knows the next byte after this label is the IP header (or other payload), not another label.

Key Takeaways

  • MPLS inserts a 32-bit label between L2 and L3 headers (Layer 2.5)
  • Labels contain: 20-bit value, 3-bit EXP/TC for QoS, S (bottom of stack) bit, 8-bit TTL
  • Three operations: PUSH (ingress), SWAP (transit), POP (egress)
  • FEC = group of packets receiving identical forwarding treatment; assigned at ingress LER
  • LSP = unidirectional path through MPLS domain; one per FEC per direction
  • PHP: egress advertises label 3 (Implicit NULL) to offload POP to penultimate hop
  • P routers are pure LSRs -- they never examine IP headers or VPN state
  • PE routers are LERs that maintain per-customer VRF state at the MPLS edge
