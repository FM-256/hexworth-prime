L2VPN vs L3VPN

In MPLS L3VPN, the SP terminates the customer's Layer 3 routing -- the PE router participates in routing with the CE. In MPLS L2VPN, the SP is transparent at Layer 3. The customer's Layer 2 frames are encapsulated and tunneled across the MPLS network, appearing to the customer as if they have a direct Layer 2 connection between sites.

L2VPN is preferred when customers want to control their own routing (often enterprise customers with complex routing policies), need Layer 2 protocols to traverse the SP network (spanning tree, LACP, CDP), or require point-to-point Ethernet WAN replacement.

L3VPN (RFC 4364) PE terminates routing. SP participates in IP routing. Scales to millions of routes. Customer uses RFC 1918 space freely. Complex PE configuration.
L2VPN (Pseudowire/VPLS) SP is L3-transparent. Customer controls routing. Supports non-IP protocols. Simpler CE requirements. Customer manages their own addressing.

Pseudowires: Point-to-Point L2 Circuits

A pseudowire (PW) emulates a point-to-point physical circuit across a packet-switched network. The source PE takes customer Layer 2 frames, encapsulates them with a PW label (inner) and a transport label (outer), and forwards them through the MPLS core to the destination PE, which strips both labels and delivers native L2 frames to the remote CE.

  CE-1 (VLAN 100)                                    CE-2 (VLAN 100)
      |                                                    |
  [PE-1]-- [PW-Label=300|Transport=1001|Eth Frame] -->[PE-2]
      |                                                    |
  Attach Circuit                                    Attach Circuit
  (CE-1 Gi0/1)                                     (CE-2 Gi0/1)

  PE-1 PW operation:
  1. Receive Ethernet frame on attach circuit (CE-1 Gi0/1)
  2. Push PW label (300) identifying this specific pseudowire
  3. Push transport label (1001) for LSP to PE-2
  4. Forward into MPLS core

  PE-2 PW operation:
  1. PHP removes transport label (arrives as [PW-Label=300|Frame])
  2. Match PW label 300 to local attach circuit (CE-2 Gi0/1)
  3. Pop PW label, deliver native Ethernet frame to CE-2

Pseudowires can carry many payload types: Ethernet (most common), ATM, Frame Relay, HDLC, PPP, and TDM circuits. The payload type is signaled during PW setup. RFC 4447 defines the standard PW setup and maintenance protocol.

PW Signaling: LDP vs BGP

MechanismStandardHow It WorksUse Case
LDP (Targeted) RFC 4447 Two PEs establish a targeted LDP session. FEC 128 (VCID) or FEC 129 (BGP-based) used to signal PW labels. Each PW requires a separate LDP FEC. Point-to-point PWs between two PEs. Simpler setup, no BGP required for PW signaling.
BGP (RFC 6624) RFC 6624 Uses BGP L2VPN AFI/SAFI to distribute PW information. Same BGP sessions used for L3VPN. Scales better for large PW deployments. Large-scale VPLS deployments, inter-AS scenarios. Reuses existing BGP RR infrastructure.

VPLS: Virtual Private LAN Service

VPLS extends pseudowire technology to multipoint. Instead of point-to-point, VPLS creates a virtual Ethernet switch (LAN) across the MPLS network. Multiple customer sites connect to the same VPLS instance and can communicate as if on the same Ethernet segment, including MAC learning, flooding, and broadcast.

  Site-A ---[PE-1]                     [PE-3]--- Site-C
                 \                       /
                  +-- Full PW Mesh --+
                 /                       \
  Site-B ---[PE-2]                     [PE-4]--- Site-D

  Each PE maintains:
  - One PW to every other PE (full mesh = N*(N-1)/2 PWs)
  - A MAC address table per VPLS instance
  - Flood/learn behavior: unknown unicast flooded to all PWs
  - Split horizon: frames received on a PW not forwarded to other PWs
VPLS Scalability: The Full-Mesh Problem

N PEs in a VPLS instance require N*(N-1)/2 pseudowires. With 100 PEs, that is 4,950 PWs. This is the fundamental scalability constraint of flat VPLS. H-VPLS (hierarchical VPLS) addresses this by using MTU-s (Multi-Tenant Unit) switches as spoke aggregation points, reducing the PE full-mesh size.

VPLS Split Horizon and MAC Learning

VPLS implements split-horizon forwarding to prevent bridging loops: a frame received on a pseudowire is never forwarded to another pseudowire within the same VPLS instance. It may only be forwarded to local attachment circuits (CE-facing interfaces).

MAC learning in VPLS works like a traditional bridge: the source MAC of each received frame is associated with the interface (PW or attachment circuit) it arrived on. Unknown destination MACs trigger flooding to all attachment circuits and all PWs in the instance (subject to split horizon).

IOS-XE — VPLS configuration using l2vpn vfi
! Define the VPLS VFI (Virtual Forwarding Instance)
PE1(config)# l2vpn vfi context CUSTOMER-LAN
PE1(config-vfi)# vpn id 200
PE1(config-vfi)# member 10.0.0.2 encapsulation mpls
PE1(config-vfi)# member 10.0.0.3 encapsulation mpls
PE1(config-vfi)# exit

! Create a bridge domain and attach CE interface + VFI
PE1(config)# bridge-domain 200
PE1(config-bdomain)# member GigabitEthernet0/1 service-instance 200
PE1(config-bdomain)# member vfi CUSTOMER-LAN

! Verify VPLS state
PE1# show l2vpn vfi name CUSTOMER-LAN

  VPN ID: 200
  Peers:
    10.0.0.2        pw-class not set, VC-ID 200, state: up

H-VPLS: Hierarchical Scaling

Hierarchical VPLS (H-VPLS) reduces the PE full-mesh by introducing a two-tier hierarchy. Customer sites connect to access-layer MTU-s devices (often cheaper switches or routers). MTU-s devices connect to a subset of PE routers via spoke pseudowires. PE routers maintain the full-mesh among themselves but aggregate many access sites per PE.

MTU-s (Access Node) Multi-Tenant Unit switch. Aggregates customer attachment circuits. Connects to PE via a single spoke PW. Does not participate in the PE full-mesh.
PE (Core Node) Full-mesh PE only connects to other PEs (mesh PWs) and MTU-s nodes (spoke PWs). MAC learning spans both levels. Fewer PEs needed in the mesh.
VPLS vs EVPN-VXLAN

Modern data center designs have largely replaced VPLS with EVPN-VXLAN, which solves the MAC learning and flooding problems more elegantly using BGP as a control plane for MAC/IP advertisements. VPLS remains common in legacy SP Ethernet services and WAN interconnects. EVPN is covered in Module 10.

Knowledge Check

1. What is the key difference between VPLS and a point-to-point pseudowire?

  • A. VPLS uses BGP for signaling; pseudowires always use LDP
  • B. VPLS is multipoint (emulates a switched LAN); pseudowire is point-to-point (emulates a leased line)
  • C. VPLS carries IP frames; pseudowires carry only Ethernet frames
  • D. VPLS requires a VRF on the PE; pseudowires do not
A pseudowire is strictly point-to-point, replacing a leased line between two sites. VPLS extends this to multipoint, creating a virtual Ethernet switch where all sites in the VPLS instance can communicate as if on the same LAN segment.

2. In a VPLS instance with 5 PE routers, how many pseudowires are required for the full PE mesh?

  • A. 5
  • B. 10
  • C. 20
  • D. 25
The formula is N*(N-1)/2. For 5 PEs: 5*4/2 = 10 pseudowires. Each pair of PEs requires one PW (PWs are bidirectional in terms of traffic flow but unidirectional in terms of label assignment).

3. Why does VPLS implement split-horizon forwarding for pseudowires?

  • A. To prevent MAC addresses from being learned on pseudowire interfaces
  • B. To prevent bridging loops -- frames received on one PW are not forwarded to other PWs
  • C. To enforce QoS policies on pseudowire traffic
  • D. To reduce the number of MAC addresses that must be flooded
In a full-mesh of PWs without split-horizon, a broadcast frame from Site-A would be forwarded PE-by-PE around the mesh multiple times, creating loops. Split-horizon ensures that PE-2 receiving a frame on its PW from PE-1 will NOT forward that frame out its PWs to PE-3 or PE-4.

Key Takeaways

  • L2VPN: SP is Layer 3 transparent -- customer Layer 2 frames tunneled end-to-end
  • Pseudowire: point-to-point L2 circuit emulation -- attach circuit + PW label + transport label
  • VCID (VC-ID) must match on both PEs for LDP-signaled pseudowires to come up
  • VPLS: multipoint L2 service -- creates a virtual Ethernet switch across the MPLS network
  • VPLS requires a full mesh of PWs between all PE routers: N*(N-1)/2 PWs
  • Split-horizon on PWs prevents bridging loops in the VPLS full-mesh
  • H-VPLS uses MTU-s access nodes to reduce PE full-mesh size and improve scalability
  • EVPN-VXLAN is the modern successor to VPLS, solving MAC learning scalability with BGP control plane
