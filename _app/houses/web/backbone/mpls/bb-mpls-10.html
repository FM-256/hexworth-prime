From VLANs to VXLAN: The Scalability Problem

IEEE 802.1Q VLANs support only 4,094 unique VLAN IDs (12-bit field). In modern multi-tenant data centers hosting thousands of customers with isolated Layer 2 domains, this limit is quickly exhausted. Additionally, VLANs require spanning tree for loop prevention, which is a poor fit for Clos (spine-leaf) fabrics with their inherent multi-path topology.

VXLAN (Virtual Extensible LAN, RFC 7348) solves both problems. It encapsulates Layer 2 Ethernet frames in UDP/IP, providing a 24-bit VXLAN Network Identifier (VNI) -- over 16 million unique overlay segments. The underlay is standard IP, so ECMP routing handles multi-pathing without spanning tree.

24-bit VNI 16,777,216 unique overlay segments vs 4,094 VLANs. Sufficient for any multi-tenant data center deployment.
IP Underlay VXLAN runs over standard IP/UDP. ECMP routing in the underlay provides active/active multi-pathing without spanning tree.
Tenant Isolation Each VNI is an isolated broadcast domain. Customer traffic is separated at the VNI level across the shared physical fabric.
Any-to-Any Connectivity VXLAN enables VM-to-VM communication across any physical host in the data center without Layer 2 adjacency constraints.

VTEP: VXLAN Tunnel Endpoints

A VTEP (VXLAN Tunnel Endpoint) is the device that performs VXLAN encapsulation and decapsulation. In a spine-leaf fabric, each leaf switch is a VTEP. VTEPs are identified by their loopback IP address (the VTEP IP). A VXLAN packet flows:

  Server-A (VM: 10.10.1.5, MAC: aa:bb:cc)      Server-B (VM: 10.10.2.5, MAC: dd:ee:ff)
      |                                                  |
  [Leaf-1 (VTEP: 192.168.1.1)]              [Leaf-2 (VTEP: 192.168.1.2)]
      |                                                  |
      +----------[ Spine-1 / Spine-2 ]-----------+
                   (IP underlay -- ECMP)

  Packet from Server-A to Server-B:
  Leaf-1 encapsulates:
  [Outer IP: src=192.168.1.1 dst=192.168.1.2]
  [UDP dst=4789 (VXLAN port)]
  [VXLAN header: VNI=10100]
  [Inner Ethernet: src=aa:bb:cc dst=dd:ee:ff]
  [Inner IP: 10.10.1.5 -> 10.10.2.5]

  Leaf-2 decapsulates and delivers inner frame to Server-B

VXLAN uses UDP destination port 4789. The source UDP port is typically a hash of the inner frame (to enable ECMP load balancing in the underlay). The outer IP uses the VTEP loopback IPs for transport.

EVPN: BGP Control Plane for VXLAN

Without a control plane, VXLAN relies on multicast or ingress replication (flooding) to distribute MAC address information -- similar to traditional Ethernet flooding. This does not scale. EVPN (Ethernet VPN, RFC 7432) replaces flooding with BGP-based MAC and IP advertisement.

In EVPN-VXLAN, each VTEP participates in BGP using the L2VPN EVPN address family. When a VM connects to a leaf switch, the leaf advertises the VM's MAC address (and optionally its IP address) to all other VTEPs via BGP. VTEPs learn MAC-to-VTEP mappings from BGP instead of flooding -- making the control plane proactive and explicit.

EVPN Address Family

EVPN uses AFI 25 (L2VPN) and SAFI 70 (EVPN) in BGP. Route Reflectors in the spine layer (or dedicated RR servers) distribute EVPN routes between all VTEPs. Each VTEP peers only with the RRs -- the same BGP RR scaling principle as MPLS L3VPN.

EVPN Route Types

EVPN defines multiple Route Types for different information. The two most critical for EVPN-VXLAN are:

Route TypeNameWhat It AdvertisesUse Case
Type 1 Ethernet Auto-Discovery VTEP presence and multihoming (ESI). Used for fast convergence when a host has multiple uplinks (MLAG/ESI multihoming). Multihomed host failover, mass withdrawal during link failure.
Type 2 MAC/IP Advertisement Host MAC address, optionally with host IP (ARP suppression). The primary route for MAC learning in EVPN. VNI and VTEP IP included. MAC learning, ARP suppression, host mobility tracking.
Type 3 Inclusive Multicast Ethernet Tag BUM (Broadcast, Unknown Unicast, Multicast) flooding tree membership. Signals which VTEPs are members of a VNI. Establishing the head-end replication list for BUM traffic per VNI.
Type 5 IP Prefix Route IP prefixes (subnets, aggregates) reachable via a VTEP. The key route type for inter-subnet and external routing. Carries VNI and next-hop VTEP. Inter-VNI routing, advertising external prefixes into EVPN domain, integration with MPLS L3VPN.

Symmetric vs Asymmetric IRB

Integrated Routing and Bridging (IRB) is how EVPN performs inter-VXLAN routing. Two models exist:

Asymmetric IRB Routing done at the ingress leaf only. Ingress leaf routes to destination VNI, bridges into that VNI, sends encapsulated frame. Egress leaf only bridges. Each leaf must have ALL VNIs configured locally. Simple but does not scale with many VNIs.
Symmetric IRB Both ingress and egress leaf perform routing. Uses a dedicated L3 VNI (per VRF) for routed traffic. Ingress routes from source VNI to L3 VNI. Egress routes from L3 VNI to destination VNI. Requires only local VNIs + L3 VNI. Scales much better -- preferred design. 
  Symmetric IRB (preferred):

  Server-A (VNI 10100)                   Server-B (VNI 10200)
      |                                           |
  [Leaf-1]                               [Leaf-2]
  Route: VNI 10100 -> L3 VNI 50000       Route: L3 VNI 50000 -> VNI 10200
  Encap: VNI=50000                        Decap, route, encap: VNI=10200

  Packet path (outer label equivalent):
  [VXLAN VNI=50000 (L3 VNI)] across fabric
  Leaf-2 decaps, routes in VRF, re-encaps into VNI 10200 for Server-B

  Both leaves do routing, each only needs to know their local VNIs + L3 VNI

Leaf-1(config-if-nve)# member vni 10100
Leaf-1(config-if-nve-vni)#  ingress-replication protocol bgp   ! EVPN-controlled BUM

! L3 VNI for symmetric IRB (per VRF)
Leaf-1(config)# vlan 3967

Leaf-1(config-vrf)# rd auto

EVPN-VXLAN and MPLS Integration

Modern SP and enterprise networks often need EVPN-VXLAN data centers to integrate with MPLS L3VPN WAN networks. The standard integration point is at the data center border leaf (border gateway), which runs both EVPN-VXLAN (toward the DC fabric) and MPLS L3VPN (toward the WAN PE).

Route Type 5 (IP Prefix) is the bridge between EVPN and MPLS L3VPN. The border leaf redistributes DC prefixes from EVPN RT-5 into VPNv4 BGP for the WAN, and redistributes WAN VPNv4 routes as EVPN RT-5 into the fabric. VTEP and PE roles coexist on the border leaf.

Underlay Design is Critical

EVPN-VXLAN performance depends entirely on the IP underlay. Design principles: use OSPF or IS-IS for underlay (fast convergence, ECMP); assign unique loopbacks to all VTEPs; enable ECMP for equal-cost paths (spine-leaf provides N equal paths); size MTU to accommodate VXLAN header (50 bytes overhead -- set underlay links to 1550+ MTU for 1500-byte payloads).

ARP Suppression

In traditional VLANs, ARP broadcasts flood the entire VLAN. In a large VXLAN fabric, ARP floods would be replicated to every VTEP in the VNI. EVPN enables ARP suppression: each VTEP caches MAC-to-IP mappings learned from EVPN RT-2 routes. When a local host sends an ARP request, the local VTEP responds directly from its ARP suppression cache, without flooding the request to remote VTEPs.

This eliminates BUM (Broadcast, Unknown Unicast, Multicast) traffic for known hosts -- the dominant source of fabric-wide flooding overhead in multi-tenant environments.

Knowledge Check

1. What is the primary function of EVPN Route Type 2 in an EVPN-VXLAN fabric?

  • A. Advertises IP prefixes (subnets) reachable via a VTEP for inter-VRF routing
  • B. Advertises host MAC addresses (and optionally IP addresses) to eliminate flooding for MAC learning
  • C. Signals VTEP membership in a VNI for BUM traffic replication tree construction
  • D. Establishes the underlay ECMP topology between spine and leaf switches
EVPN RT-2 (MAC/IP Advertisement) is the route type that replaces traditional MAC flooding. When a host connects to a leaf, the leaf advertises an RT-2 containing the host's MAC (and optionally its IP for ARP suppression) to all other VTEPs via BGP. VTEPs populate their MAC tables from RT-2 without flooding.

2. Why is Symmetric IRB preferred over Asymmetric IRB in large EVPN-VXLAN deployments?

  • A. Symmetric IRB provides lower latency for inter-subnet routing
  • B. Symmetric IRB uses a shared L3 VNI per VRF, so each leaf only needs its local VNIs plus the L3 VNI -- not all VNIs across the fabric (which asymmetric requires)
  • C. Symmetric IRB eliminates the need for BGP in the control plane
  • D. Symmetric IRB supports IPv6 while asymmetric supports only IPv4
Asymmetric IRB requires every leaf to have every VNI locally instantiated (to bridge into the destination VNI). In a fabric with 1,000 VNIs, every leaf needs all 1,000 VNIs. Symmetric IRB eliminates this by routing through a per-VRF L3 VNI -- each leaf only needs its own VNIs plus the L3 VNI for each VRF it participates in.

3. What EVPN Route Type is used to integrate a VXLAN fabric with an MPLS L3VPN WAN network?

  • A. Route Type 1 (Ethernet Auto-Discovery)
  • B. Route Type 2 (MAC/IP Advertisement)
  • C. Route Type 3 (Inclusive Multicast Ethernet Tag)
  • D. Route Type 5 (IP Prefix Route)
EVPN RT-5 (IP Prefix Route) is the integration point between EVPN-VXLAN and MPLS L3VPN. The border leaf (or gateway) redistributes WAN routes received as VPNv4 BGP into EVPN as RT-5, and redistributes DC prefixes from RT-5 into VPNv4 for the WAN. RT-5 is also used for external route advertisement in pure EVPN environments.

Key Takeaways

  • VXLAN: 24-bit VNI (16M+ segments) over UDP/IP underlay -- replaces 4,094-limit 802.1Q VLANs
  • VTEP: leaf switch performing VXLAN encap/decap; identified by loopback IP; VNI identifies the tenant segment
  • EVPN: BGP control plane (L2VPN AFI 25, SAFI 70) that distributes MAC/IP bindings -- replaces flooding
  • RT-2: MAC/IP advertisement -- enables ARP suppression and BGP-based MAC learning
  • RT-3: BUM flooding tree -- defines ingress replication list per VNI
  • RT-5: IP prefix route -- used for inter-VRF routing and WAN/MPLS integration at border leaf
  • Symmetric IRB (preferred): uses L3 VNI per VRF; each leaf only needs local VNIs + L3 VNI
  • EVPN-VXLAN + MPLS L3VPN: border leaf redistributes RT-5 into VPNv4 and vice versa for WAN integration
