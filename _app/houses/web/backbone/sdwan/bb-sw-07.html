Deploying SD-WAN at scale requires a disciplined approach across three operational phases. Day-0 covers infrastructure standup and device onboarding via ZTP. Day-1 applies service policies, QoS, and security. Day-2 is ongoing operations: monitoring, software upgrades, and policy tuning. This module covers each phase with the CLI and vManage steps needed in a real production rollout.

Zero-Touch Provisioning Flow

ZTP allows a WAN-Edge to bootstrap itself with no manual CLI configuration on-site. The device contacts a cloud ZTP server, authenticates via a certificate signed by Cisco's root CA, obtains the vBond address, and joins the overlay. On-site staff only need to cable the device and power it on.

ZTP Bootstrap Sequence

1. Device powers on with factory image. 2. Queries DNS for "ztp.viptela.com" (or customer-configured ZTP server). 3. Downloads the vBond IP from the ZTP server using the device serial number and chassis ID. 4. Contacts vBond to get vSmart and vManage addresses. 5. Establishes DTLS/TLS control connections to vManage and vSmart. 6. vManage pushes device template — configuration is applied automatically.

Template Push Impact Pushing a new device template triggers a full configuration replacement on the WAN-Edge. BFD sessions briefly flap, and traffic may black-hole for 5-30 seconds during convergence. Always push templates during change windows for production sites.

Phased Migration from Legacy MPLS

Most enterprises do not rip-and-replace their MPLS overnight. A phased migration runs the SD-WAN overlay alongside the existing MPLS for months, migrating sites in waves while maintaining fallback.

PhaseActionTraffic State
Phase 1: ParallelInstall SD-WAN alongside MPLS router; MPLS carries all production trafficMPLS primary, SD-WAN idle
Phase 2: PilotMigrate 5-10 non-critical sites to SD-WAN; monitor for 30 daysPilot sites: SD-WAN; others: MPLS
Phase 3: Wave rolloutMigrate sites in geographic batches; use AAR to keep critical apps on MPLS until validatedMixed — per-app path selection
Phase 4: MPLS off-rampCancel MPLS circuits after SD-WAN proven stable; retain for final 10% if contractually boundSD-WAN primary, MPLS as backup only
Phase 5: Full cutoverDecommission all MPLS; DIA + SD-WAN overlay onlySD-WAN only
Dual-Router vs In-Situ Migration Dual-router migration (placing a WAN-Edge alongside the existing CE router) is safer and allows instant rollback but doubles hardware costs during the transition. In-situ migration (replacing the CE router with a WAN-Edge) is faster but requires a longer maintenance window per site.

Module Takeaways

  • ZTP eliminates on-site CLI configuration — devices bootstrap via DNS, certificates, and vManage template push
  • Day-0 focuses on control plane HA, certificate PKI, and ZTP registration before any branch comes online
  • Device Templates with variable substitution enable consistent, repeatable configuration across hundreds of sites
  • Template pushes cause brief traffic interruption — schedule during change windows
  • Phased MPLS migration reduces risk: run overlay in parallel, pilot with non-critical sites, then wave-migrate
