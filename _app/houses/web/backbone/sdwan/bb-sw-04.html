The Security Challenge of Direct Internet Access

Traditional WAN architectures backhauled all internet traffic through HQ, where a central NGFW provided inspection. SD-WAN's Direct Internet Access (DIA) model breaks this -- each branch now has its own internet connection that must be secured independently. Deploying a separate physical NGFW appliance at every branch is cost-prohibitive for most enterprises.

SD-WAN addresses this by integrating security capabilities directly into the WAN edge platform. Cisco SD-WAN integrates with Cisco Umbrella and Zscaler for cloud-delivered security. Fortinet FortiSD-WAN runs FortiGate's full NGFW stack natively on the same appliance as the SD-WAN engine. Palo Alto Prisma SD-WAN pairs with Prisma Access for cloud-delivered SASE.

SASE: Security and SD-WAN Converging

Secure Access Service Edge (SASE) converges SD-WAN with cloud-delivered security (SWG, CASB, ZTNA, FWaaS) into a unified architecture. Instead of routing internet traffic to a branch firewall, traffic is forwarded to the nearest SASE PoP for inspection before reaching the internet. This is the architectural direction all major SD-WAN vendors are moving toward -- Cisco SSE+SD-WAN, Fortinet SASE, Palo Alto Prisma SASE.

Zone-Based Firewall in SD-WAN

Cisco SD-WAN's integrated firewall uses a zone-based model. Interfaces are assigned to security zones (LAN, WAN, DMZ, Guest), and policies control what traffic is permitted between zones. Unlike a traditional ACL, zone-based firewall is stateful -- return traffic for established connections is automatically permitted.

Zone Pairs and Policies Policies are defined for traffic flowing from a source zone to a destination zone. LAN-to-WAN allows branch users to initiate internet connections; WAN-to-LAN blocks all uninitiated inbound traffic by default.
Application-Level Inspection ZBFW can inspect at Layer 7 -- block specific applications even over allowed ports. Block BitTorrent even over port 80, or restrict SSH to only management networks while allowing it generally from LAN.
Cisco SD-WAN -- Zone-Based Firewall Policy (vManage Template)
! Security policy applied via vManage templates
! This is the equivalent CLI representation

security
 zones
  zone lan-zone
   vpn 1 10                    ! LAN VPN and service VPN
  zone internet-zone
   vpn 0                       ! Transport/WAN VPN
 
 zone-pair lan-to-internet
  source-zone lan-zone
  destination-zone internet-zone
  policy ALLOW-LAN-INTERNET

policy
 security-group ALLOW-LAN-INTERNET
  sequence 10
   match source-data-prefix-list LAN-PREFIXES
   action inspect           ! Stateful inspect -- allow + track
  sequence 100              ! Default deny
   action drop
   log

Intrusion Prevention System (IPS)

SD-WAN IPS inspects traffic for known attack signatures, protocol anomalies, and exploit attempts. In Cisco SD-WAN, IPS uses Snort 3 signatures. In FortiSD-WAN, it uses FortiGuard IPS signatures. Signature updates are pushed automatically from the cloud, ensuring protection against new CVEs without manual intervention.

IPS ModeActionPerformance ImpactUse Case
Detection (IDS)Log and alert only -- no blockingMinimal (async path)Initial deployment, baselining false positives before enabling prevention
Prevention (IPS)Block matching traffic and logModerate -- adds inline inspection latencyActive protection after signature tuning; default for production
BalancedBlock critical/high signatures, alert medium/lowLow-moderateCommon compromise -- aggressive protection on high-severity, visibility on lower

IPS Throughput Impact

Full IPS inspection with all signature categories enabled can reduce WAN edge throughput by 20-50% on lower-end platforms. Always check your WAN edge model's "threat protection" throughput spec versus its base forwarding throughput. For a 100Mb/s branch, this is usually fine. For a 1Gb/s datacenter edge running IPS, ensure the platform supports that inspection rate or offload to a dedicated NGFW.

URL Filtering and DNS Security

URL filtering blocks access to malicious, inappropriate, or policy-violating web content at the branch before traffic exits to the internet. DNS security (Cisco Umbrella integration, FortiGuard DNS filtering) blocks DNS resolution for known malicious domains at the DNS layer -- before the TCP/HTTP connection is even established.

Zero Trust Network Access (ZTNA)

ZTNA replaces traditional VPN for remote user access. Instead of putting remote users "on the network" with broad access, ZTNA grants access to specific applications after verifying device posture and user identity. SD-WAN vendors integrate ZTNA through their cloud security platforms.

Application-Level Access ZTNA grants access per-application, not per-network. A contractor gets access to the project portal only. An employee gets access to the file server and ERP. Neither gets broad network access that traditional VPN provides.
Continuous Verification Device posture is checked continuously -- not just at login. If a device fails a compliance check mid-session (antivirus disabled, OS unpatched), access is immediately revoked without requiring re-authentication.
Cisco SD-WAN + Duo/Umbrella Cisco integrates SD-WAN with Duo for MFA and device trust, and Umbrella for cloud-delivered ZTNA. Remote users access applications through the Umbrella PoP closest to them -- no corporate VPN backhaul required.
Fortinet ZTNA FortiSD-WAN integrates FortiClient for endpoint verification and ZTNA proxy on FortiGate. Tag-based policies: only devices with FortiClient reporting compliant posture can access tagged applications.

Practice Scenario

A retail chain is deploying SD-WAN at 200 stores. Each store has a WAN edge with two transports: MPLS and broadband. Stores have guest WiFi and employee POS (point-of-sale) networks on the same WAN edge.

  1. Design a zone-based firewall policy for this scenario. Define the zones needed, the zone pairs, and the permit/deny rules for each zone pair. Consider PCI-DSS requirements for POS traffic isolation.
  2. The CISO requires URL filtering for all internet traffic from stores. Describe how you would implement this using Cisco Umbrella and what categories you would block (list at least 5 categories relevant to a retail environment).
  3. IPS is enabled on the WAN edge but is causing 100ms added latency for POS credit card transactions. Describe two approaches to reduce this latency impact while maintaining security posture.
  4. Guest WiFi must be isolated from the employee POS network but both share the same WAN edge. How does SD-WAN's VPN segmentation solve this, and what firewall policy ensures the isolation is enforced?

Key Takeaways

  • SD-WAN DIA requires per-branch security -- integrated ZBFW, IPS, URL filtering, and DNS security replace HQ-centric backhaul
  • Zone-based firewall (ZBFW) provides stateful inspection between security zones -- LAN, WAN, Guest, DMZ
  • IPS inline inspection adds latency -- size platforms for threat protection throughput, not just base forwarding throughput
  • Umbrella/FortiGuard DNS security blocks malicious domains at DNS resolution before TCP connections are established
  • SASE converges SD-WAN with cloud-delivered security (SWG, CASB, ZTNA, FWaaS) -- the architectural direction of the industry
  • ZTNA provides per-application access instead of broad network access -- continuous posture verification, not just login-time
  • VPN segmentation in SD-WAN provides L3 isolation between networks (POS vs. Guest) sharing the same WAN edge hardware
