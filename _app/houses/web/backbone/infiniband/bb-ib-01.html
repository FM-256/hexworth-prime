What Is InfiniBand?

InfiniBand (IB) is a switched fabric interconnect standard designed from the ground up for low-latency, high-bandwidth communication between servers, storage, and networking equipment. Unlike Ethernet, which evolved from a shared-medium LAN technology, InfiniBand was purpose-built for data center and HPC environments where microsecond latency and deterministic delivery are non-negotiable.

At its core, InfiniBand enables Remote Direct Memory Access (RDMA) -- allowing one node to directly read or write the memory of another node without involving the CPU on either end. This dramatically reduces latency and CPU overhead compared to traditional socket-based networking. Today, virtually every major AI training cluster and top-500 supercomputer uses InfiniBand or its Ethernet-based derivative, RoCE.

Why InfiniBand Dominates HPC

The TOP500 list consistently shows InfiniBand deployed in over 60% of the world's fastest supercomputers. NVIDIA's acquisition of Mellanox (2020) and the subsequent HDR/NDR roadmap cemented InfiniBand as the default fabric for AI training clusters running GPUs at scale. AWS, Microsoft Azure, and Google all operate InfiniBand-based HPC clusters.

Sub-Microsecond Latency End-to-end latency as low as 600ns for RDMA read/write operations, versus 10-50 microseconds for typical Ethernet TCP.
NDR: 400 Gb/s per Port Next Data Rate delivers 400Gb/s per port (2x200G lanes). HDR is 200Gb/s. Roadmap extends to XDR at 800Gb/s.
Hardware-Offloaded Transport Reliability, ordering, and flow control are handled in the HCA hardware -- not the kernel or CPU -- freeing application cycles.
Lossless By Design InfiniBand uses credit-based flow control at the hardware level. Packets are never dropped due to congestion -- back-pressure propagates instead.

InfiniBand Fabric Components

An InfiniBand fabric consists of three types of components: end nodes (servers/storage), switches, and the subnet manager. Understanding how these interact is fundamental to administering and troubleshooting any IB installation.

Component Role Key Detail
HCA Host Channel Adapter -- the NIC equivalent for InfiniBand Installed in servers. Exposes RDMA verbs to applications. Examples: NVIDIA ConnectX-7, ConnectX-6 Dx
IB Switch Forwarding device with no IP stack; routes by LID Examples: NVIDIA Quantum-2 (400Gb/s NDR), Quantum (200Gb/s HDR). Low radix edge switches aggregate to spine.
Subnet Manager (SM) Control plane -- discovers topology, assigns LIDs, computes routes Runs on a designated SM host (OpenSM) or embedded in managed switches. Only one SM is master; others are standby.
Subnet Administrator (SA) Query interface to the SM's fabric database Applications use SA queries (PathRecord, NodeRecord) to discover routes before establishing connections.

One Master Subnet Manager Per Subnet

A single InfiniBand subnet can have only one active (master) subnet manager. Multiple SM instances may run for redundancy -- the one with the highest priority becomes master via a negotiation process. If the master SM goes down, a standby SM takes over. Running two SM instances at equal priority causes unnecessary topology churn. Always set SM priorities explicitly in production.

Addressing: LIDs and GUIDs

InfiniBand uses two address spaces that serve different purposes. Understanding both is essential for reading diagnostic output and understanding SM behavior.

LID -- Local Identifier 16-bit address assigned by the SM during fabric initialization. Used for all unicast routing within a subnet. LIDs are ephemeral -- they change when the SM re-initializes or a new SM takes over. Not globally unique.
GUID -- Globally Unique Identifier 64-bit address burned into HCA firmware at manufacture. Globally unique and permanent. The SM uses GUIDs to track nodes across reboots and re-assign consistent LIDs. Port GUIDs and node GUIDs are distinct.

Each InfiniBand port has a Port GUID that uniquely identifies it globally. The HCA also has a Node GUID (the system-level identifier). When using GID (Global Identifier) addresses for routing between subnets, the GID is constructed as a 128-bit value combining a subnet prefix with the port GUID.

InfiniBand Link Speeds

InfiniBand uses a generational naming scheme based on data rates. Modern deployments use HDR or NDR for new clusters, while older SDR/DDR/QDR/FDR infrastructure is still encountered in legacy HPC environments.

GenerationNamePer-Port SpeedSignal Rate
SDRSingle Data Rate10 Gb/s2.5 GT/s
DDRDouble Data Rate20 Gb/s5 GT/s
QDRQuad Data Rate40 Gb/s10 GT/s
FDRFourteen Data Rate56 Gb/s14 GT/s
EDREnhanced Data Rate100 Gb/s25 GT/s
HDRHigh Data Rate200 Gb/s50 GT/s (PAM4)
NDRNext Data Rate400 Gb/s100 GT/s (PAM4)
XDRExtended Data Rate800 Gb/s200 GT/s (roadmap)

HDR and NDR use PAM4 (Pulse Amplitude Modulation, 4 levels) encoding rather than NRZ (Non-Return-to-Zero) used in earlier generations. PAM4 encodes 2 bits per symbol, doubling throughput at the same signaling rate while requiring more sophisticated equalization and error correction in the HCA hardware.

Fabric Topology: Fat-Tree

InfiniBand fabrics almost universally use fat-tree (folded-Clos) topology for HPC deployments. Fat-tree provides full bisection bandwidth -- every node can communicate at full line rate simultaneously -- and deterministic low-latency paths.

A two-tier fat-tree has edge switches (connected to servers) and spine switches (connected only to edge switches). A three-tier adds a core layer between spine and edge. The SM computes a forwarding table (Linear Forwarding Table, LFT) for each switch during fabric initialization. Each LFT entry maps a destination LID to an output port.

Subnet Manager Operation

The subnet manager is the brain of the InfiniBand fabric. It performs topology discovery using Subnet Management Packets (SMPs), assigns LIDs, computes forwarding tables, and programs them into each switch. Understanding SM operation is critical for diagnosing fabric initialization failures and performance issues.

The SM initialization sequence:

  1. SM broadcasts LID-Routed Discovery -- sends SMP MADs to discover all ports and their neighbors
  2. Builds a complete topology graph of all switches and end nodes
  3. Assigns LIDs to each port (1 to N, where N ≤ 49151 for unicast)
  4. Runs a routing algorithm (min-hop by default, or fat-tree/DFSSSP)
  5. Programs Linear Forwarding Tables into each switch via SMP Write
  6. Sets port state to Active, enabling data traffic
OpenSM -- Basic Configuration (/etc/opensm/opensm.conf)
# SM priority -- higher wins master election (0-15)
sm_priority 8

# Routing algorithm: minhop, ftree, updn, dfsssp
routing_engine ftree

# Enable perfmgr for port counter collection
perfmgr TRUE
perfmgr_sweep_time_s 180

# Log verbosity (0x03 = errors+warnings, 0x43 = verbose)
log_flags 0x03
log_file /var/log/opensm.log

Practice Scenario

You are administering a 64-node InfiniBand cluster with two-tier fat-tree topology (8 edge switches, 4 spine switches). The SM is running OpenSM on a dedicated management node.

  1. The SM log shows "Master SM at LID 1 -- node at LID 47 has mismatched GUID." What does this indicate and what command would you run to investigate the affected port?
  2. A new compute node is added to the fabric. The administrator connects its HCA but forgets to restart OpenSM. Will the new node be able to communicate? Why or why not?
  3. You want to confirm all 64 nodes are registered with the SM and their LIDs are correctly assigned. Write the command and describe the output fields you would check.
  4. What is the difference between the Port GUID and the Node GUID shown in ibstat output, and when does each matter?

Key Takeaways

  • InfiniBand is a purpose-built switched fabric for RDMA -- sub-microsecond latency, lossless hardware flow control
  • Three fabric components: HCAs (end nodes), IB switches (LID-based forwarding), and the Subnet Manager (control plane)
  • LIDs are 16-bit ephemeral addresses assigned by the SM; GUIDs are 64-bit permanent hardware identifiers
  • Only one master SM may exist per subnet; multiple SMs run for redundancy with priority-based master election
  • Fat-tree (folded-Clos) topology provides full bisection bandwidth and is the standard for HPC/AI clusters
  • NDR (400Gb/s) and HDR (200Gb/s) are current deployment standards; XDR (800Gb/s) is on the roadmap
  • The SM programs Linear Forwarding Tables into every switch -- without a working SM, no new traffic flows
