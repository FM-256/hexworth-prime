Defense in Depth

< NetSec Course

Learning Objectives

  • Define defense in depth and explain why no single control is sufficient
  • Map the security zone model and assign trust levels to each zone
  • Design a DMZ architecture for internet-facing services
  • Apply the principle of least privilege to network segmentation
  • Identify the controls that should exist at each layer of the security stack

Why Defense in Depth?

Defense in depth (DiD) is the strategic principle that security should be provided by multiple independent layers of controls rather than a single perimeter. The term originates from military strategy: slow an adversary's advance by requiring them to defeat successive defensive lines, each buying time and increasing the probability of detection.

In network security, the perimeter is dead. Employees work from coffee shops; partners connect via API; cloud workloads span multiple providers. The idea that a single firewall at the network edge can protect the organization is a 1990s model that has not survived contact with reality. DiD accepts that any single control will eventually be defeated and designs for detection and containment when that happens.

The Swiss Cheese Model

Each security control has holes (limitations, misconfiguration, zero-days). DiD layers multiple controls so that the holes do not align. A threat must pass through every layer successfully to reach the target. The more layers and the more independent their failure modes, the smaller the probability of a complete breach.

The Security Layer Model

DiD is organized into concentric layers, each with its own controls. The key is that each layer is independently enforced -- a failure at one layer does not cascade immediately to the next.

Security Zones and Trust Levels

A security zone is a network segment with a uniform trust level and consistent security policy. Traffic between zones passes through a security control (firewall, proxy, NAC). Trust levels are assigned based on who controls the devices in the zone and what data those devices handle.

The Principle of Least Privilege Applied to Networks

Network access should be granted only to the specific sources, destinations, and protocols required for legitimate business function -- nothing more. The default posture is deny-all; every allow rule is a deliberate, documented exception. Regularly audit and recertify ACLs because allow rules accumulate over time and legacy rules are rarely removed.

DMZ Architecture

The DMZ (Demilitarized Zone) is the zone between the internet and the internal network that hosts services that must be accessible from the internet. The canonical DMZ design uses two firewalls: an outer firewall between the internet and the DMZ, and an inner firewall between the DMZ and the internal network. Even if an attacker compromises a DMZ server, they face a second firewall before reaching internal resources.

Dual-Firewall DMZ Architecture
Internet (Untrusted)
       |
  [Edge Router / DDoS Scrubbing]
       |
  [Outer Firewall (NGFW-A)]
  Policy: Allow 80,443,25 inbound only
       |
  +------- DMZ Segment (10.0.1.0/24) --------+
  |  [Web Server 1]  [Web Server 2]           |
  |  [Reverse Proxy] [Mail Gateway (MX)]      |
  +-------------------------------------------+
       |
  [Inner Firewall (NGFW-B)]
  Policy: Allow app-specific flows; deny all else
       |
  +------- Internal Network (10.10.0.0/16) ---+
  |  [App Servers]  [Databases]               |
  |  [Domain Controllers]  [File Servers]     |
  +-------------------------------------------+

Key rules:
- Outer FW: Internet -> DMZ on permitted ports only
- Outer FW: NEVER allow internet -> internal directly
- Inner FW: DMZ -> Internal on specific app ports only
- Inner FW: Internal -> DMZ on specific admin ports only
- Both FW: Log all connections, deny-all default

Network Segmentation Strategies

VLAN-Based Segmentation Separate VLANs for each security zone. Inter-VLAN routing forced through firewall or L3 security appliance. Simple, widely supported, but VLANs share the same physical infrastructure.
Micro-Segmentation Host-level policy enforcement (VMware NSX-T, Cisco ACI, cloud security groups). Every workload protected individually. Lateral movement within a VLAN is blocked. Ideal for multi-tenant and cloud workloads.
Air Gap / Physical Separation Highest-trust networks (OT/ICS, classified data) use physically separate infrastructure with no logical connection to corporate IT. Data transfer via controlled unidirectional gateway (data diode).
Software-Defined Perimeter (SDP) Resources are invisible until a user authenticates and passes posture checks. Even authenticated users only see the specific resources they are authorized for. Basis of zero trust access.

Firewall Rule Design Best Practices

Cisco ASA -- DMZ Firewall Ruleset Example
! Interface security levels: higher = more trusted
interface GigabitEthernet0/0
 nameif outside
 security-level 0          ! Internet

interface GigabitEthernet0/1
 nameif dmz
 security-level 50         ! DMZ

interface GigabitEthernet0/2
 nameif inside
 security-level 100        ! Internal

! ACL: Internet -> DMZ (only HTTP, HTTPS, SMTP)
access-list OUTSIDE_IN extended permit tcp any host 203.0.113.10 eq 80
access-list OUTSIDE_IN extended permit tcp any host 203.0.113.10 eq 443
access-list OUTSIDE_IN extended permit tcp any host 203.0.113.20 eq 25
access-list OUTSIDE_IN extended deny ip any any log
access-group OUTSIDE_IN in interface outside

! ACL: DMZ -> Inside (only specific app server ports)
access-list DMZ_IN extended permit tcp host 10.0.1.5 host 10.10.5.10 eq 8080
access-list DMZ_IN extended deny ip any any log
access-group DMZ_IN in interface dmz

! Threat detection and basic IPS
threat-detection basic-threat
threat-detection statistics access-list

Key Takeaways

  • Defense in depth uses independent, layered controls so that no single failure results in a complete breach
  • Security zones assign trust levels; traffic between zones is always controlled by a security enforcement point
  • The DMZ uses two firewalls: one facing the internet, one facing the internal network -- a compromised DMZ host cannot directly reach internal systems
  • Micro-segmentation extends the DMZ concept to individual workloads, blocking lateral movement even within a VLAN
  • Firewall rulesets default-deny with explicit allows; every allow rule is documented and reviewed regularly
  • Layer your controls to match the threat: external attackers hit the perimeter; insiders and compromised hosts require internal segmentation and endpoint controls
