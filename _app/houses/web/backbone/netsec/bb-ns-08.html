NetFlow and IPFIX

NetFlow (Cisco proprietary) and IPFIX (Internet Protocol Flow Information Export, RFC 7011 -- the IETF standardization of NetFlow v9) are flow-based monitoring protocols. Rather than capturing every packet, they export metadata about each network conversation (flow): source/destination IP, ports, protocol, byte count, packet count, and start/end times. This enables traffic analysis at scale without the storage cost of full packet capture.

NetFlow Record Structure and Configuration
# A NetFlow v9 flow record contains:
Flow:
  src_ip:         192.168.1.50
  dst_ip:         203.0.113.100
  src_port:       54321
  dst_port:       443
  protocol:       6 (TCP)
  tos:            0
  tcp_flags:      0x18 (PSH+ACK)
  packets:        142
  bytes:          48203
  flow_start:     2026-03-16T14:22:01Z
  flow_end:       2026-03-16T14:22:47Z
  ingress_if:     GigabitEthernet0/1 (ifIndex 3)
  bgp_src_as:     0
  bgp_dst_as:     13335    # Cloudflare AS

# Cisco IOS XE -- NetFlow v9 configuration
flow record SECURITY-REC
 match ipv4 source address
 match ipv4 destination address
 match transport source-port
 match transport destination-port
 match ipv4 protocol
 collect counter bytes
 collect counter packets
 collect timestamp sys-uptime first
 collect timestamp sys-uptime last
 collect transport tcp flags

flow exporter FLOW-EXPORT
 destination 10.0.0.50     # Flow collector (Elastic, ntopng, etc.)
 source Loopback0
 transport udp 2055
 export-protocol netflow-v9

flow monitor SECURITY-MON
 record SECURITY-REC
 exporter FLOW-EXPORT
 cache timeout active 60
 cache timeout inactive 15

interface GigabitEthernet0/0
 ip flow monitor SECURITY-MON input
 ip flow monitor SECURITY-MON output

Packet Capture Methods

SPAN (Switch Port Analyzer) Switch mirrors traffic from one or more source ports/VLANs to a destination port connected to a capture device. No hardware modification; uses switch CPU. Drops packets under high load -- may miss traffic. Best for lab or low-volume monitoring.
Network TAP (Test Access Point) Hardware device inserted inline that passively copies all traffic to a monitoring port. No packet drops (hardware-based). Preferred for production environments. Passive TAP has no IP address -- invisible to attackers.
RSPAN (Remote SPAN) Extends SPAN over a VLAN to a remote switch. Allows centralized monitoring without a capture device on every floor switch. Increases VLAN utilization and may affect performance on the RSPAN VLAN path.
SSL Decryption TAP Places the NGFW or SSL proxy in the capture path to decrypt traffic before it reaches the capture device. Required to see content of HTTPS sessions. Must handle key material securely.
Cisco IOS -- SPAN Configuration
! Monitor all traffic on VLAN 10 and 20, send to port Gi1/0/48 (IDS)
monitor session 1 source vlan 10 - 20 both
monitor session 1 destination interface GigabitEthernet1/0/48
! "both" = ingress + egress; can use "rx" or "tx" for one direction

! RSPAN: source on floor switch, destination on central monitor switch
! Floor switch (source):
vlan 999
 name RSPAN-VLAN
 remote-span

monitor session 1 source interface GigabitEthernet1/0/5 both
monitor session 1 destination remote vlan 999

! Monitor switch (destination):
monitor session 1 source remote vlan 999
monitor session 1 destination interface GigabitEthernet0/48

SIEM Architecture

A Security Information and Event Management (SIEM) system centralizes log collection, normalizes events from diverse sources, correlates events across systems, and generates alerts. The four stages of SIEM processing are: collection, normalization, correlation, and response.

StageFunctionExample
CollectionIngest logs from all sources via syslog, SNMP, API, agentFirewall deny logs, Windows Event IDs, IPS alerts, NetFlow
NormalizationParse vendor-specific formats into common data model (CDM)Cisco syslog timestamp + Palo Alto JSON timestamp both become UTC ISO 8601
CorrelationApply rules that match patterns across multiple events/sourcesFailed login from IP X + port scan from IP X = credential stuffing attack
Alerting / ResponseGenerate tickets, call webhooks, trigger SOAR playbooksOpen ServiceNow ticket + isolate endpoint via EDR API
Splunk SPL -- Lateral Movement Detection Query
| Search: Windows Security Event ID 4624 (successful logon)
| Detect: multiple workstations logging in from same source within 5 minutes

index=windows EventCode=4624
  Logon_Type=3                          /* Network logon (lateral movement) */
  NOT (Account_Name="*$")               /* Exclude machine accounts */
| bucket _time span=5m
| stats dc(ComputerName) as unique_hosts
         values(ComputerName) as hosts
         count
  by _time, Account_Name, src_ip
| where unique_hosts >= 5              /* 5+ distinct hosts in 5 minutes */
| table _time, Account_Name, src_ip, unique_hosts, hosts, count
| sort -count

Key Security Events to Monitor

Critical Security Event Categories
# Network Layer
- Firewall permit on blocked ports (policy bypass attempts)
- Internal to external on unusual ports (beaconing, exfil)
- Large data transfers to new external IPs (>100MB first contact)
- DNS queries for high-entropy domains (DGA malware)
- SSH/RDP from internet to internal endpoints (initial access)
- ICMP type 0/8 in large volume (covert channel or recon)

# Authentication
- Multiple failed logons then success (brute force + success)
- Successful logon from impossible geography (travel-time impossible)
- First-time admin logon to a server (lateral movement)
- Service account interactive logon (credential abuse)
- Kerberoasting: LDAP queries for SPN, then TGS requests for many accounts

# Windows Events (Critical IDs)
4625  - Failed logon
4648  - Explicit credential logon (runas, pass-the-hash)
4698  - Scheduled task created (persistence)
4720  - New user account created
4732  - Member added to Administrators group
7045  - New service installed (persistence)
4104  - PowerShell script block logging (obfuscated commands)

# Endpoint (if EDR feeds SIEM)
- Process created with encoded command line (-enc, base64)
- Network connection by lsass.exe, svchost.exe to external IP
- Credential dump tools: mimikatz.exe, procdump on lsass
- Living-off-the-land: certutil, mshta, wscript executing remote content

Network Behavioral Analytics (NBA)

NBA systems establish traffic baselines for each host, subnet, and protocol, then alert on deviations. Unlike signature-based detection, NBA can detect unknown threats -- zero-days, novel malware, insider threats -- by their abnormal behavior pattern.

Volumetric Baseline Learn normal bytes/packets per hour per host. Alert on 3-sigma deviation. Catches data exfiltration (host suddenly transfers 50GB at 2am) and C2 (host starts receiving large payloads from single IP).
Peer Group Analysis Group similar hosts (all accounting workstations). Flag workstations communicating differently from their peers (one accounting workstation suddenly accessing server admin shares -- anomalous for the group).
Protocol Anomaly HTTP GET with 200KB User-Agent string; SMB sessions to 300 hosts in 30 seconds; DNS TXT records larger than 512 bytes. Protocol abuse patterns that deviation detection catches before signature update.
Time-Based Anomaly Server authentication at 3am by a user who normally works 9-5. Payroll database queries on Sunday. Normal credentials, abnormal timing -- often indicates stolen credential use by adversary in different timezone.

Key Takeaways

  • NetFlow/IPFIX exports flow metadata (5-tuple + counters) rather than full packets; enables security analysis at line rate without massive storage
  • Hardware TAPs provide zero-drop capture; SPAN is simpler but drops packets under load and uses switch CPU -- use TAPs for production monitoring
  • SIEM pipeline: collect from all sources, normalize to common schema, correlate across sources, alert and trigger SOAR response
  • Critical Windows events: 4624/4625 (logon), 4698 (scheduled task), 4720 (new account), 4104 (PowerShell) -- configure forwarding immediately
  • NBA detects unknown threats by baseline deviation: volumetric, peer group, protocol anomaly, and time-based analysis -- complement to signature-based IPS
