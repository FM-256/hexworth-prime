802.1X: Port-Based Authentication

IEEE 802.1X is the standard for port-based network access control. It controls access to a LAN switch port (wired or wireless) based on authentication. A device that plugs into an 802.1X-enabled port is placed in an "unauthorized" state -- it can only exchange EAP authentication frames. Only after successful authentication does the port move to "authorized" and allow normal traffic.

802.1X Three-Party Authentication
Supplicant          Authenticator        Auth Server
(Laptop/Device)   (Switch/AP)           (RADIUS - ISE/NPS)
     |                  |                      |
     |--- EAPOL-Start -->|                      |
     |<-- EAP-Request ---|                      |
     |--- EAP-Response -->|--- RADIUS Access-Req->|
     |                  |                      | (validates
     |                  |                      |  credentials
     |                  |<-- RADIUS Access-Acc --| /certificate)
     |<-- EAP-Success ---|                      |
     |                  |                      |
  Port moves to AUTHORIZED state               |
  RADIUS returns: VLAN=10, dACL=Employee-ACL   |
     |                  |                      |
  Normal traffic now permitted                 |
EAP Methods EAP-TLS (certificate-based, strongest), PEAP-MSCHAPv2 (password in TLS tunnel, most common), EAP-FAST (Cisco, no cert required on client), EAP-TTLS (similar to PEAP).
Multi-Auth Mode Switch can authenticate multiple devices per port (e.g., PC + IP phone). Each device independently authenticates and receives separate policy. Reduces need for access port per device.
Auth-Fail VLAN If authentication fails (bad credentials, certificate expired), the port can be placed in a restricted VLAN with internet-only access and a remediation portal URL.
Guest VLAN If no 802.1X supplicant responds within the timeout, the port moves to a Guest VLAN. Useful for conference rooms where guest laptops without domain credentials connect.

RADIUS vs. TACACS+

AttributeRADIUS (RFC 2865)TACACS+ (Cisco proprietary)
TransportUDP 1812 (auth), 1813 (accounting)TCP 49 (reliable)
EncryptionPassword only encrypted (MD5 shared secret)Entire payload encrypted (shared secret)
AAA SeparationCombined Authentication + AuthorizationSeparate Authentication, Authorization, Accounting
Primary UseNetwork access (802.1X, VPN, wireless)Device administration (router/switch CLI access)
Command AuthorizationLimited (via VSA extensions)Per-command authorization (show, conf t, etc.)

When to Use Each

Use RADIUS for network access control: 802.1X wired, wireless authentication, VPN. Use TACACS+ for network device administration: SSH login to routers and switches, command authorization (which commands each user role can run). Cisco ISE supports both protocols from a single policy engine.

Posture Assessment

Posture assessment checks whether a device meets security requirements before granting full network access. Checks typically include: OS patch level, antivirus installed and current, disk encryption enabled, host firewall active, and absence of known malware signatures. Cisco ISE, Microsoft Intune, and ClearPass are common posture engines.

ISE Posture Workflow
# 1. Device authenticates via 802.1X (EAP-TLS with machine certificate)
# 2. ISE grants temporary access to posture assessment VLAN
# 3. ISE Agent on endpoint reports compliance status to ISE

ISE Posture Conditions (example):
  Condition: "Windows-Compliant"
    - OS: Windows 11 (any patch)
    - Patch level: MS patches < 30 days old
    - AV: Defender real-time enabled AND definitions < 7 days
    - Disk Encryption: BitLocker enabled

# 4a. Compliant: ISE sends RADIUS CoA (Change of Authorization)
#     Port moves to Employee VLAN, receives Employee dACL
RADIUS CoA: Disconnect-Message or Re-Auth
  New attributes: Tunnel-Private-Group-ID=10 (Employee VLAN)
                  Filter-Id=Employee-ACL

# 4b. Non-compliant: Redirected to remediation portal
#     ACL only allows: DHCP, DNS, remediation server HTTPS
# 5. After remediation (patch applied, AV updated):
#    Agent re-checks; ISE grants full access via CoA

MAC Authentication Bypass (MAB)

Not all devices support 802.1X supplicants: IP phones, printers, IoT sensors, and network cameras typically do not. MAC Authentication Bypass (MAB) allows these devices to authenticate using their MAC address as the credential. The switch sends the MAC address as the RADIUS username and password; ISE validates it against a device whitelist and assigns the appropriate VLAN and policy.

Cisco IOS -- 802.1X + MAB on Access Port
! Configure 802.1X on access port (with MAB fallback)
interface GigabitEthernet1/0/24
 description IP-Phone-or-PC
 switchport mode access
 switchport access vlan 10
 authentication event fail action next-method
 authentication event no-response action next-method
 authentication host-mode multi-auth
 authentication order dot1x mab        ! Try 802.1X first, MAB if no response
 authentication priority dot1x mab
 authentication port-control auto
 authentication violation restrict
 dot1x pae authenticator
 spanning-tree portfast
 service-policy input AUTOQOS-SRND4-CISCOPHONE-POLICY

! Global 802.1X configuration
aaa new-model
aaa authentication dot1x default group ISE-RADIUS
aaa authorization network default group ISE-RADIUS
aaa accounting dot1x default start-stop group ISE-RADIUS

radius server ISE-PSN1
 address ipv4 10.0.0.10 auth-port 1812 acct-port 1813
 key Sup3rS3cr3tK3y!

Dynamic ACL (dACL) and VLAN Assignment

RADIUS can return authorization attributes that dynamically configure the switch port after authentication. The two most common are VLAN assignment (Tunnel attributes) and downloadable ACL (dACL), which is pushed from ISE to the switch and applied to the port for the duration of the session.

ISE dACL Example: Contractor Policy
# ISE Authorization Profile: "Contractor"
dACL Name: Contractor-Access
Contents:
  permit tcp any host 10.10.5.20 eq 443     # Contractor portal HTTPS
  permit udp any host 10.0.0.1 eq 53        # DNS to internal resolver
  permit icmp any host 10.0.0.1             # Ping gateway
  deny ip any 10.0.0.0 0.255.255.255        # Block all other internal access
  permit ip any any                          # Allow internet access

# RADIUS Access-Accept attributes returned to switch:
Tunnel-Type:         VLAN (13)
Tunnel-Medium-Type:  802 (6)
Tunnel-Private-Group-ID: 50        # VLAN 50 = Contractor VLAN
cisco-av-pair: ip:inacl#1=permit tcp any host 10.10.5.20 eq 443
cisco-av-pair: ip:inacl#2=deny ip any 10.0.0.0 0.255.255.255 log
cisco-av-pair: ip:inacl#3=permit ip any any

Key Takeaways

  • 802.1X requires three parties: supplicant (client), authenticator (switch/AP), and authentication server (RADIUS/ISE)
  • EAP-TLS (mutual certificate) is the strongest method; PEAP-MSCHAPv2 is most common for password-based environments
  • RADIUS is for network access; TACACS+ is for device administration -- use both for a complete AAA architecture
  • Posture assessment grants temporary access, checks compliance (patch/AV/encryption), then grants full or quarantine access via RADIUS CoA
  • MAB authenticates non-802.1X devices by MAC address; should be combined with profiling and device whitelists in ISE
  • dACLs push per-session ACLs from ISE to switch ports, enabling dynamic policy without pre-configuring ACLs on every switch
