Control and User Plane Separation (CUPS)

The defining architectural change in the 5GC is the complete separation of control plane and user plane. In 4G, the P-GW combined control (IP address assignment, policy binding) and user plane (packet forwarding) functions. In 5G, the SMF handles control and the UPF handles user plane, connected via the N4 interface using PFCP (Packet Forwarding Control Protocol).

This separation enables independent scaling: deploy hundreds of UPF instances in MEC edge locations close to users for low-latency data paths, while running a smaller number of centralized SMF instances that control all UPFs. The UPF is entirely data-plane logic — it has no signaling intelligence.

SMF — Control Plane IP address allocation, QoS rule installation (via PFCP to UPF), session selection, charging trigger, UPF selection. Connects to AMF (N11), UDM (N10), PCF (N7), UPF (N4).
UPF — User Plane Packet detection rules (PDRs), forwarding action rules (FARs), QoS enforcement rules (QERs) — all installed by SMF via PFCP. Connects to gNB (N3), SMF (N4), DN (N6).
UE Registration Procedure

The registration procedure establishes the UE's presence in the network, authenticates the subscriber, and prepares the AMF for handling subsequent PDU session requests. The following is the simplified procedure for an initial SA 5G registration.

==== 5G SA Registration Procedure (Simplified) ==== 1. UE → gNB: RRC Setup Request UE establishes radio connection 2. UE → AMF: Registration Request Contains: SUCI (concealed SUPI), Requested NSSAI, 5G-GUTI (if re-registering), UE capabilities SUCI: Subscription Concealed Identifier SUPI encrypted with home network public key → prevents IMSI catching 3. AMF → AUSF: Authentication Request AUSF invokes UDM to retrieve SUPI and auth vectors UDM generates 5G-AKA or EAP-AKA' auth vector 4. AMF ↔ UE: Authentication Challenge / Response UE derives session keys, proves knowledge of K AMF/AUSF verify response, confirm UE is legitimate 5. AMF → UDM: Registration notification UDM updates serving AMF, retrieves subscriber data 6. AMF → PCF: AM Policy Association Establishment PCF returns access/mobility policies 7. AMF → UE: Registration Accept Contains: 5G-GUTI, Allowed NSSAI, TAI list ==== After Registration: PDU Session Establishment ==== 8. UE → AMF: PDU Session Establishment Request Requested S-NSSAI, DNN (Data Network Name) 9. AMF → SMF: Create SM Context Request (Nsmf) AMF selects SMF based on S-NSSAI and DNN 10. SMF → UDM: Retrieve session management subscription data 11. SMF → PCF: SM Policy Association (Npcf) PCF returns QoS rules, charging rules 12. SMF → UPF: N4 Session Establishment (PFCP) SMF installs PDRs, FARs, QERs in UPF 13. SMF → AMF: PDU Session Create Response Returns UPF N3 tunnel endpoint (TEID, IP) 14. AMF → gNB: PDU Session Resource Setup gNB sets up DRB (Data Radio Bearer) 15. UE ↔ DN: User plane data flows through gNB → UPF → Internet
PFCP and UPF Packet Processing Rules

The SMF programs the UPF using PFCP (Packet Forwarding Control Protocol, based on the earlier Sx interface in 4G). PFCP uses a session model: each PDU session is represented as a PFCP session containing sets of rules that define packet detection, forwarding, and QoS treatment.

Rule Type Abbreviation Function
Packet Detection Rule PDR Matches packets to a session using source interface, SDF (Service Data Flow) filters, or TEID. Each PDR references a FAR.
Forwarding Action Rule FAR Defines what to do with matched packets: forward to N3/N6/N9 with encapsulation, duplicate (for lawful intercept), drop, or buffer.
QoS Enforcement Rule QER Applies GBR/MBR rate limits, DSCP marking, and per-flow or per-session shaping. Referenced from PDR.
Usage Reporting Rule URR Measures volume/time for charging. Triggers reports to SMF when thresholds are crossed. Used by online and offline charging.
Uplink Classifier (ULCL) for Local Breakout

In Multi-Access Edge Computing (MEC) deployments, the SMF inserts a UPF at the edge near the gNB as an Uplink Classifier. The ULCL UPF inspects uplink packets and applies PDRs to route specific traffic locally to an edge data center (N6) instead of hairpinning to a central UPF. This enables MEC applications with sub-10ms latency to users without requiring central core traversal for edge-bound traffic.

PCF — Policy Control Function

The PCF (Policy Control Function) is the central policy brain of the 5GC. It provides two categories of policy: Access and Mobility (AM) policies delivered to the AMF for UE-level restrictions, and Session Management (SM) policies delivered to the SMF for PDU session QoS and charging rules. The PCF retrieves subscriber policy profiles from the UDR (Unified Data Repository).

==== PCF Policy Model ==== AM Policy (via AMF): - Service area restrictions (which TAIs UE can register in) - RFSP (RAT/Frequency Selection Priority) index - UE ambr (Aggregate Maximum Bit Rate) — caps total UE throughput SM Policy (via SMF, per PDU session): - QoS Flows: 5QI (5G QoS Identifier) + ARP (Allocation Retention Priority) - PCC Rules: SDF filter → QoS parameters - Charging key and reporting level ==== 5QI Table (Selected Values) ==== 5QI 1: GBR 100ms | Priority 2 | Conversational Voice 5QI 2: GBR 150ms | Priority 4 | Conversational Video 5QI 4: GBR 300ms | Priority 5 | Non-Conversational Video 5QI 5: Non-GBR 100ms | Priority 1 | IMS Signaling 5QI 8: Non-GBR 300ms | Priority 8 | Video/TCP-based 5QI 9: Non-GBR 300ms | Priority 9 | Default Internet 5QI 69: Non-GBR 60ms | Priority 0.5| Mission-Critical Push-to-Talk 5QI 80: Non-GBR 10ms | Priority 68 | Low-Latency URLLC Applications ==== GBR vs Non-GBR QoS Flows ==== GBR flows: Guaranteed bit rate — radio resources reserved Used for VoNR (Voice over NR), priority video Non-GBR flows: Best-effort within UE AMBR cap Default PDU session = 5QI 9 Non-GBR
UPF Anchoring and I-UPF Architecture

A single PDU session can traverse multiple UPFs in a chain. The PDU Session Anchor (PSA-UPF) holds the stable IP address assigned to the UE and connects to the external Data Network (N6). When the UE moves between areas, intermediate UPFs (I-UPF) can be inserted and released dynamically to minimize the path without changing the UE's IP address.

The N9 interface carries GTP-U tunnels between chained UPFs. The PSA-UPF remains stable; the path from gNB to PSA-UPF may change through I-UPF insertions and removals as the UE moves, maintaining session continuity without re-establishing the PDU session.

PSA-UPF (PDU Session Anchor) Assigns the UE's IP address. Connects to external DN via N6. Remains the same for the PDU session lifetime. Located at the regional or central data center.
I-UPF (Intermediate UPF) Inserted between gNB (N3) and PSA-UPF (N9) for path optimization. Can be co-located with edge sites for ULCL. Added/removed by SMF without affecting PDU session continuity.
ULCL UPF Uplink Classifier — inspects uplink traffic and routes matching flows to a local Data Network (N6-local) instead of forwarding to PSA-UPF. Enables MEC local breakout.
Branching Point IPv6 Multi-homed PDU sessions: multiple PSA-UPFs with different IP prefixes. Traffic split based on IPv6 prefix. Alternative to ULCL for multi-home architectures.

Key Takeaways

  • CUPS separates SMF (control: session establishment, QoS rules) from UPF (user plane: packet forwarding only) — enables independent scaling and MEC placement
  • SMF programs UPF via N4/PFCP using PDRs (match), FARs (forward/drop), QERs (rate limit), and URRs (measure for charging)
  • SUCI (encrypted SUPI) is sent during registration — prevents IMSI catchers from tracking subscribers over the air
  • 5QI defines the QoS class for a flow: 5QI 1 is GBR voice (100ms), 5QI 9 is default non-GBR internet (300ms), 5QI 80 is URLLC (10ms)
  • ULCL UPF enables MEC local breakout — SMF inserts it dynamically and programs PDRs to route edge-bound flows to the local N6
  • PSA-UPF holds the UE IP address; I-UPFs are inserted/removed by SMF during mobility without changing the UE's session or IP
