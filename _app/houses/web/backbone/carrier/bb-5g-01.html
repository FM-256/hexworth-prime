What 5G Is and Why It Matters

5G is not merely a faster LTE. It is a redesigned system architecture built to support three fundamentally different service categories simultaneously: enhanced Mobile Broadband (eMBB) for high-throughput consumer and enterprise data, Ultra-Reliable Low-Latency Communications (URLLC) for industrial automation and critical infrastructure, and massive Machine-Type Communications (mMTC) for IoT at planetary scale.

The architectural leap from 4G to 5G includes a fully disaggregated radio access network (gNodeB with CU/DU functional split), a cloud-native 5G Core (5GC) with a service-based architecture replacing the monolithic EPC nodes, and native network slicing support allowing multiple logical networks to share a single physical infrastructure.

eMBB Peak 20 Gbps downlink, 10 Gbps uplink. Gigabit mobile, fixed wireless access, stadium coverage. Primary driver of 5G NR mmWave deployments.
URLLC 1ms user-plane latency, 99.9999% reliability. Factory automation, remote surgery, vehicle-to-everything (V2X). Requires network slicing and MEC.
mMTC 1 million devices per km2. Low-power, infrequent data. NB-IoT and LTE-M serve this today; 5G RedCap (Release 17) brings reduced-capability NR devices.
Network Slicing Multiple end-to-end virtual networks on shared infrastructure. Each slice has its own QoS, latency, and isolation characteristics. Native to 5GC SA architecture.
5G System Architecture — Key Nodes

The 5G system is divided into three domains: the User Equipment (UE), the 5G Radio Access Network (NG-RAN), and the 5G Core (5GC). The NG-RAN consists of gNodeBs (gNBs). The 5GC replaces the 4G EPC with a set of disaggregated Network Functions (NFs) that communicate via a Service-Based Interface (SBI) using HTTP/2 over JSON.

Node / Function Domain Role 4G Equivalent
gNB NG-RAN 5G New Radio base station. CU (Centralized Unit) handles RRC/PDCP; DU (Distributed Unit) handles RLC/MAC/PHY. eNodeB
AMF 5GC — Control Plane Access and Mobility Management Function. Handles registration, authentication, mobility, and paging. MME
SMF 5GC — Control Plane Session Management Function. Establishes, modifies, and releases PDU sessions. Controls UPF via N4/PFCP. PGW-C / SGW-C
UPF 5GC — User Plane User Plane Function. Packet routing and forwarding, QoS enforcement, traffic reporting. The only node that touches user data. PGW-U / SGW-U
PCF 5GC — Control Plane Policy Control Function. Provides QoS policies and charging rules to AMF and SMF. PCRF
NRF 5GC — Control Plane Network Repository Function. Service discovery registry — NFs register their services and discover peers here. No equivalent
UDM 5GC — Control Plane Unified Data Management. Stores subscriber data, authentication credentials, subscription profiles. HSS
Standalone vs. Non-Standalone Deployments

The 3GPP defined multiple migration options. Non-Standalone (NSA) — Option 3x — was the first commercially deployed mode in 2019 because it allowed operators to add 5G NR capacity while keeping the existing 4G EPC as the control-plane anchor. Standalone (SA) — Option 2 — uses the full 5GC and is required for network slicing, URLLC, and all advanced 5G features.

NSA (Option 3x) LTE eNodeB as master node (MN), gNB as secondary node (SN). 4G EPC handles all control plane (S1-MME). 5G NR adds user-plane throughput only. No slicing. No 5GC features. Fastest time-to-market in 2019-2021.
SA (Option 2) gNB connects directly to 5GC (NG-C for control, NG-U for user plane). Full 5GC feature set: network slicing, URLLC, AMF/SMF/UPF architecture, SBA. Required for industrial 5G and private networks.
Migration Path: NSA to SA

Most tier-1 operators launched with NSA to recycle EPC infrastructure investments. The migration to SA requires 5GC deployment, SIM re-provisioning for 5G-AKA, and gNB software upgrades. Many operators run NSA and SA in parallel — legacy devices anchor to NSA, new 5G SA-capable devices use the 5GC path.

Service-Based Architecture (SBA)

The 5GC SBA replaces the point-to-point interface model of 4G EPC with a microservices approach. Each Network Function (NF) exposes a set of services via RESTful HTTP/2 APIs. The NRF acts as a service registry — NFs register on startup and query it to discover peer NFs. This enables horizontal scaling, rolling upgrades, and cloud-native deployment on Kubernetes.

# Example: NF Registration request to NRF (simplified JSON) # NF registers its capabilities and endpoints PUT https://nrf.5gc.example.com/nnrf-nfm/v1/nf-instances/{nfInstanceId} Content-Type: application/json { "nfInstanceId": "amf-01-uuid", "nfType": "AMF", "nfStatus": "REGISTERED", "plmnList": [{"mcc": "310", "mnc": "260"}], "amfInfo": { "amfSetId": "3FF", "amfRegionId": "CA" }, "ipv4Addresses": ["10.96.0.10"], "nfServices": [{ "serviceInstanceId": "namf-comm-svc", "serviceName": "namf-comm", "versions": [{"apiVersionInUri": "v1"}], "scheme": "https", "nfServiceStatus": "REGISTERED" }] } # SMF discovers AMF via NRF query: GET https://nrf.5gc.example.com/nnrf-disc/v1/nf-instances?target-nf-type=AMF&requester-nf-type=SMF # Returns list of AMF instances with their service endpoints

Key SBI reference points include: Namf (AMF services — communication, event exposure), Nsmf (SMF services — PDU session management), Nupf (UPF services via N4/PFCP rather than HTTP/2), Nudm (UDM subscriber data), Nnrf (NRF discovery and management), and Npcf (PCF policy services).

gNodeB Functional Split: CU, DU, and RU

The 5G gNodeB can be deployed as a single unit or split into three functional components: the Radio Unit (RU), the Distributed Unit (DU), and the Centralized Unit (CU). The O-RAN Alliance's functional split option 7-2x is the most deployed split today, placing the upper PHY processing in the DU and the antenna/RF in the RU.

Component Protocol Layers Deployment Location Interface
CU (Centralized Unit) PDCP, RRC, SDAP Regional data center or edge cloud F1 to DU; NG to 5GC
DU (Distributed Unit) RLC, MAC, Upper PHY Cell site or aggregation point F1 to CU; Fronthaul to RU
RU (Radio Unit) Lower PHY, RF Antenna mast / rooftop eCPRI/Open Fronthaul to DU
Fronthaul Timing Requirements

The fronthaul link between RU and DU must meet stringent latency and timing requirements. eCPRI (enhanced Common Public Radio Interface) requires sub-100 microsecond one-way latency and IEEE 1588v2 PTP for phase synchronization with sub-100ns accuracy. These requirements fundamentally shape the transport network design — conventional IP/MPLS networks with standard QoS are insufficient without explicit PTP support.

Practice Questions

  1. A carrier deploys 5G NR but retains its existing EPC infrastructure. The marketing team advertises 5G slicing capabilities. Is this accurate? What deployment mode is in use, and what would be required to enable slicing?
  2. In a 5GC SA deployment, which NF is responsible for: (a) authenticating the subscriber, (b) establishing the PDU session, (c) forwarding user data packets to the internet, (d) discovering the SMF's IP address?
  3. The NRF goes offline. What impact does this have on existing active PDU sessions? On new session establishment? Explain the sequence.
  4. A gNB is deployed with a CU/DU split using fronthaul. What protocol carries traffic between the DU and RU, and what are the timing requirements on that link?
  5. Compare the AMF and the 4G MME. What new capabilities does the AMF have that the MME did not?

Key Takeaways

  • 5G serves three service categories: eMBB (throughput), URLLC (latency/reliability), mMTC (device density) — each requires different network characteristics
  • NSA (Option 3x) anchors 5G NR to the 4G EPC for control plane; SA (Option 2) uses the full 5GC and is required for slicing and URLLC
  • The 5GC service-based architecture uses HTTP/2 RESTful APIs; NFs register with the NRF for service discovery
  • UPF is the only 5GC node that handles user data — all other core NFs are control plane
  • The gNB CU/DU/RU split with eCPRI fronthaul imposes sub-100us latency and PTP phase sync requirements on transport
  • The NRF is the service registry — its availability is critical for new session establishment but not for existing active sessions
