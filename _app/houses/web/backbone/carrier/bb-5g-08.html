Carrier Ethernet and the MEF Forum

Carrier Ethernet (CE) is not simply Ethernet at large scale — it adds the carrier-grade attributes missing from enterprise Ethernet: service scalability (millions of customers), standardized service definitions, guaranteed performance, quality management, and service operations/administration/maintenance (OAM). The MEF Forum (formerly Metro Ethernet Forum) defines the standards that allow multi-vendor, multi-operator CE deployments with consistent service semantics.

MEF 3.0 (published 2019) is the current unified Carrier Ethernet service framework, encompassing the full lifecycle from service ordering to performance reporting. MEF-certified services from compliant operators carry a standardized definition that allows customers to compare and verify services across providers.

Standardized Service Types E-Line (point-to-point), E-LAN (multipoint-to-multipoint), E-Tree (rooted multipoint). Each maps to specific connectivity semantics and traffic behavior.
Service OAM IEEE 802.1ag CFM (Connectivity Fault Management) for connectivity verification, fault isolation, and performance monitoring. Y.1731 for performance measurement (delay, jitter, loss per EVC).
Bandwidth Profiles CIR, EIR, CBS, EBS — same token bucket model as IP QoS policing but defined per EVC/CoS. MEF 10.4 defines the exact conformance model.
Multi-Operator Support MEF defines Operator Virtual Connections (OVCs) for inter-provider stitching. Two carriers can interconnect CE services at an E-NNI (External Network-to-Network Interface).
E-Line, E-LAN, and E-Tree Service Types

MEF defines three fundamental service types based on their UNI (User Network Interface) connectivity model. Each type has specific frame delivery semantics — which frames from one UNI are delivered to which other UNIs.

Service Type MEF Name Topology Frame Delivery Use Case
E-Line Ethernet Private Line (EPL) / Ethernet Virtual Private Line (EVPL) Point-to-point (2 UNIs) All frames from UNI-A delivered to UNI-B only. Bidirectional. Site-to-site WAN, data center interconnect, leased line replacement
E-LAN Ethernet Private LAN (EP-LAN) / Ethernet Virtual Private LAN (EVP-LAN) Multipoint-to-multipoint (N UNIs) Frames from any UNI delivered to all other UNIs (like a LAN switch). Unicast frames to the correct destination only after learning. Multi-site enterprise LAN extension, data center fabric interconnect
E-Tree Ethernet Private Tree (EP-Tree) / Ethernet Virtual Private Tree (EVP-Tree) Rooted multipoint (root UNI + leaf UNIs) Root can communicate with all leaves. Leaves cannot communicate with each other. Only root-to-leaf and leaf-to-root traffic permitted. Broadband access (FTTH aggregation), cellular backhaul, spoke-and-hub
EPL vs EVPL: Port Mode vs VLAN Mode

Ethernet Private Line (EPL) provides dedicated port mode — all frames on the UNI port belong to the single EVC, and the UNI is entirely private to one customer. Ethernet Virtual Private Line (EVPL) multiplexes multiple EVCs on a single UNI using C-VLAN (customer VLAN) tags to identify each service — one physical port can carry multiple logical E-Line services to different destinations. EVPL is the most commercially common form due to port efficiency.

EVC, OVC, and the CE Network Model

The Ethernet Virtual Connection (EVC) is the end-to-end logical connection as seen by the subscriber, spanning from one UNI to another UNI across the provider network. The Operator Virtual Connection (OVC) is the carrier-internal component of the service, spanning from a UNI to an ENNI (External NNI, interconnection with another carrier) or within the same carrier network.

==== CE Network Reference Model ==== Subscriber Site A Subscriber Site B [CE Router] — UNI-A UNI-B — [CE Router] | | [Provider Edge A] ←EVC→ [Provider Edge B] | | | Provider Network (MPLS/SD-WAN) | |————————————————————————————————| UNI: User Network Interface - Physical handoff point (1GE, 10GE, etc.) - MEF defines UNI attributes: speed, C-VLAN ID map, bandwidth profile EVC: End-to-end service instance - Identified by EVC ID - Has associated bandwidth profile (CIR, EIR, CBS, EBS per CoS) - Has performance SLA (FD, FDV, FLR) OVC: Operator-internal half of EVC (used in multi-provider scenarios) OVC-End at UNI: UNI-side OVC endpoint OVC-End at ENNI: Inter-provider side OVC endpoint ==== Multi-Provider E-Line via OVC Stitching ==== Site A — UNI — [Provider 1 PE] — ENNI — [Provider 2 PE] — UNI — Site B OVC-1 OVC-2 |———————— EVC ————————————————|
MEF Bandwidth Profile and CoS Performance Attributes

MEF defines bandwidth profiles using the same token bucket model as IP policing. Each EVC (or per-CoS within an EVC) has a bandwidth profile that defines the rate of committed and excess traffic. Performance attributes define the measurable SLA metrics for the service.

==== MEF Bandwidth Profile Parameters ==== CIR (Committed Information Rate): Guaranteed throughput (always delivered) EIR (Excess Information Rate): Best-effort above CIR (may be discarded under congestion) CBS (Committed Burst Size): Token bucket depth for CIR bursting EBS (Excess Burst Size): Token bucket depth for EIR bursting Conformance: Green (within CIR+CBS) | Yellow (within EIR+EBS) | Red (discard) Example E-Line with two CoS (bandwidth profile per CoS): EVC: EVPL-CORP-NYC-LAX UNI speed: 1 GbE CoS HIGH (real-time): CIR = 100 Mbps | CBS = 12,500 bytes | EIR = 0 | EBS = 0 CoS MEDIUM (enterprise apps): CIR = 400 Mbps | CBS = 50,000 bytes | EIR = 100 Mbps | EBS = 100,000 bytes CoS LOW (backup/bulk): CIR = 100 Mbps | CBS = 12,500 bytes | EIR = 300 Mbps | EBS = 1,000,000 bytes ==== MEF Performance SLA Attributes ==== FD (Frame Delay): One-way or round-trip latency Example: <5ms for HIGH CoS, <20ms for MEDIUM FDV (Frame Delay Variation): Jitter — difference between min and max FD Example: <1ms for HIGH CoS (voice-sensitive) FLR (Frame Loss Ratio): Percentage of frames not delivered Example: <0.001% (10^-5) for HIGH CoS ==== MEF OAM — IEEE 802.1ag / Y.1731 ==== CFM (Connectivity Fault Management): MEP (Maintenance End Point) — at each UNI or NNI MIP (Maintenance Intermediate Point) — at internal PE nodes CCM (Continuity Check Message) — heartbeat every 1s, 10s, 1min LBM/LBR (Loopback) — connectivity test LTM/LTR (Linktrace) — path tracing through provider network Y.1731 Performance Measurement: 1DM (One-way Delay Measurement) DMM/DMR (Two-way Delay Measurement) LMM/LMR (Loss Measurement)
Carrier Ethernet over MPLS and SD-WAN

Carrier Ethernet services are most commonly delivered over MPLS networks. E-Line services map to VPWS (Virtual Private Wire Service) using MPLS pseudowires (RFC 4447, Ethernet pseudowire). E-LAN services map to VPLS (Virtual Private LAN Service, RFC 4762) or EVPN (RFC 7432). Modern implementations increasingly use EVPN as the control plane for all three service types.

VPWS (E-Line) Point-to-point MPLS pseudowire. LDP-based or BGP-based signaling (RFC 4447). MPLS label stack: tunnel label + VC label. Simple, low overhead.
VPLS (E-LAN) Multi-point bridging over MPLS. Full mesh of pseudowires between PE routers. MAC learning per pseudowire. Scalability limited by O(n^2) pseudowires.
EVPN (E-Line/E-LAN/E-Tree) BGP control plane (RFC 7432). All-active multihoming, distributed MAC/IP learning, ECMP. Replaces both VPWS and VPLS for modern deployments. Supports E-Tree with route target policies.
SD-WAN Delivery MEF 70.1 defines SD-WAN service attributes using MEF framework. Overlay tunnels (IPsec, GRE) replace MPLS PW. Same bandwidth profile and CoS attributes apply — provider-agnostic.

Practice Questions

  1. A customer has 5 branch offices that all need full connectivity with each other. Which MEF service type provides this, and how does frame delivery work when Site-A sends a broadcast frame?
  2. Explain the difference between EPL and EVPL. A provider UNI port handles 10 different customers' E-Line services. Which service type enables this, and what mechanism identifies each customer's traffic?
  3. An EVC bandwidth profile specifies CIR=100Mbps, EIR=50Mbps. A burst of 180Mbps arrives on the UNI. What happens to each portion of the traffic (Green, Yellow, Red), and what determines whether Yellow frames are ultimately delivered?
  4. How does Y.1731 differ from IEEE 802.1ag in terms of function? Which one measures actual latency and loss, and which one only tests connectivity?
  5. A network engineer needs to implement an E-LAN service for 8 sites using MPLS. They choose VPLS. How many pseudowires are required in a full mesh? What is the advantage of using EVPN instead?

Key Takeaways

  • Carrier Ethernet adds scalability, standardized service definitions, OAM, and performance SLAs to enterprise Ethernet — MEF 3.0 is the governing framework
  • E-Line is point-to-point, E-LAN is multipoint-to-multipoint (all-to-all), E-Tree is rooted multipoint (root-to-leaf only, no leaf-to-leaf)
  • EVPL multiplexes multiple EVCs on one UNI using C-VLAN tags; EPL dedicates the entire UNI port to a single customer/service
  • MEF bandwidth profile: CIR (committed, Green), EIR (excess, Yellow), CBS/EBS (burst sizes); Yellow frames are delivered under low load but discarded first under congestion
  • Y.1731 measures actual performance (FD, FDV, FLR); 802.1ag CFM provides connectivity monitoring and fault isolation
  • EVPN (RFC 7432) with BGP control plane has replaced VPLS for E-LAN deployments — eliminates the O(n^2) pseudowire scaling problem and adds multihoming
