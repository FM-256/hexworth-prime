5G Use Cases by Service Category

The 3GPP 5G architecture was designed from the ground up to serve three fundamentally different performance profiles simultaneously. Real deployments rarely use a single profile — a manufacturing site might have eMBB for video surveillance, URLLC for robotic control, and mMTC for thousands of environmental sensors, all on the same 5G infrastructure.

Category Key Requirement Use Cases 5G Feature Required
eMBB Peak throughput, spectral efficiency Fixed Wireless Access (FWA), mobile video, AR/VR, stadium/venue, drone video mmWave FR2, massive MIMO, carrier aggregation, 5QI 9/8
URLLC Sub-1ms latency, 99.9999% reliability Factory robotics, remote surgery, vehicle teleoperation (V2X), smart grid protection relay, drone swarm control 5G SA, URLLC slice (SST=2), MEC, 5QI 80, network slicing, PDCP diversity
mMTC Device density, low power, low cost Smart meters, precision agriculture sensors, asset tracking, building automation NB-IoT, LTE-M, 5G RedCap (Release 17), PSM/eDRX power saving
Multi-Access Edge Computing (MEC)

ETSI MEC (Multi-Access Edge Computing) places compute, storage, and application hosting at or near the radio access point — at the edge of the network, not in a distant data center. This eliminates the round-trip to the cloud for latency-sensitive applications. A factory robotic arm control application running on a MEC server co-located with the gNB DU has a user-plane path of: robot → gNB → UPF (edge) → MEC app → back in milliseconds.

MEC Host Physical infrastructure: server co-located with the gNB or at a small aggregation point. Runs a virtualization platform (Kubernetes, OpenStack). Hosts MEC applications as VMs or containers.
MEC Platform Middleware exposing APIs to MEC applications: Radio Network Information (RNI) API, location service, bandwidth management, traffic routing (via UPF ULCL integration).
MEC Orchestrator Manages MEC applications lifecycle across MEC hosts. Selects which MEC host runs each application based on UE location. Interfaces with 5GC SMF for ULCL UPF provisioning.
UPF ULCL Integration SMF inserts ULCL UPF between gNB (N3) and PSA-UPF. ULCL routes application-specific traffic to local MEC app (N6-local). Non-MEC traffic continues to central UPF.
==== MEC Traffic Path: Factory Robot Control ==== Without MEC: Robot → gNB → UPF(Central DC) → Control Server(Central DC) Round-trip: ~20-40ms — too slow for real-time control With MEC: Robot → gNB → ULCL-UPF(Edge) → Control App(MEC Host co-located) Round-trip: <5ms — meets URLLC requirement PDU Session with ULCL: SMF programs ULCL-UPF PDR: Match: src IP = robot_ip, dst port = 5000 (control app port) FAR: forward to N6-local (MEC app IP: 192.168.200.10) Other traffic (internet): ULCL FAR → N9 → PSA-UPF → Internet ==== ETSI MEC API Example: Radio Network Information (RNI) ==== GET https://mec-platform/mec_rni/v2/queries/layer2_meas ?ue_addr=192.168.10.50 Response: { "l2Meas": { "cellInfo": [ {"ecgi": "310260000001A", "rsrp": -82, "rsrq": -11, "ul_nprb": 48} ], "ueInfo": { "associateId": [{"type": "IPV4_ADDR", "value": "192.168.10.50"}], "dl_gbr_prb_usage_cell": 12, "ue_ul_mac_thr": 8500000 } } } MEC app uses real-time radio conditions to adapt video quality or workload
5G Network API Exposure: NEF and CAPIF

The 5GC exposes network capabilities to third-party applications through the NEF (Network Exposure Function). This allows enterprise applications, hyperscalers, and MEC apps to request network capabilities on behalf of their users — QoS boost for a video call, location queries, UE reachability notifications, or network slice selection.

API Function Use Case
QoS on Demand Request a temporary QoS boost (5QI upgrade) for specific UE + application flow Video game app requests low-latency session for ranked gameplay; removed after session ends
UE Reachability Subscribe to notifications when a specific UE returns to coverage Push messaging for IoT devices that frequently sleep (NB-IoT)
Location Request UE location (cell ID, GPS if available) with user consent Location-based services, asset tracking, emergency services
Traffic Influence Request that the SMF steer specific UE's traffic to a particular UPF / DNN CDN edge server selection based on UE location, MEC app routing control
CAPIF — Common API Framework

CAPIF (3GPP TS 23.222) is the governance layer for service API exposure. It provides API invocation authentication and authorization, API discovery (CAPIF core function), and audit logging. Third-party API consumers must register with the CAPIF core function and present valid credentials before accessing NEF-exposed APIs. This prevents unauthorized applications from manipulating network QoS or accessing subscriber location data.

5G IoT: NB-IoT, LTE-M, and RedCap

The mMTC vision of 1 million devices per km2 is served by three cellular IoT technologies, each optimized for different points on the power/throughput/latency spectrum. All three can coexist within a 5G SA network using the 5GC, though NB-IoT and LTE-M use the LTE air interface (not 5G NR) and thus require EPC or 5GC-EPC interworking.

Technology Bandwidth Peak DL Rate Power Best For
NB-IoT 200 kHz ~250 kbps Extreme low power (10yr battery) Smart meters, leak sensors, underground/deep-coverage locations. PSM: 10+ year battery life.
LTE-M (Cat-M1) 1.4 MHz ~1 Mbps Very low power (5yr battery) Asset tracking (GPS), wearables, remote monitoring with voice support. Mobility + PSM.
5G RedCap (NR-Light) 20 MHz (FR1) ~150 Mbps Low (moderate battery) Industrial IoT sensors, video surveillance, wearables needing NR throughput without full UE complexity.

Fixed Wireless Access (FWA) with 5G

5G Fixed Wireless Access replaces wireline broadband (cable, DSL) in underserved areas and provides a competitive alternative in urban markets. The 5G FWA CPE (Customer Premises Equipment) is a fixed router that connects to the 5G network via an external or integrated antenna and provides Wi-Fi and Ethernet to the home or business.

T-Mobile's Home Internet product uses sub-6 GHz NR (Band n41, 2.5 GHz) and has become the fastest-growing ISP in the US by new subscribers. Verizon's 5G Home product uses mmWave (28 GHz) for dense urban high-throughput delivery. Both rely on the same 5GC infrastructure as mobile subscribers but with specific DNN and APN profiles for residential internet billing.

Outdoor CPE Directional antenna aimed at nearest gNB. Window-mount or pole-mount. Higher gain than indoor CPE. Required for mmWave (line-of-sight critical) and rural sub-6 at cell edge.
Indoor CPE Self-install, plug-and-play. Suitable for sub-6 GHz near-urban where signal penetrates walls. T-Mobile Home Internet uses this model. 5G NR + Wi-Fi 6 integrated unit.
5GC DNN for FWA FWA CPE uses a specific DNN (e.g., "home.internet") with different billing, QoS (no per-device policy — full UE AMBR), and routing rules (static IP option) vs mobile DNN.
Spectrum Strategy Rural FWA: 600 MHz or 700 MHz for max coverage (10-20 km). Suburban: C-band 3.5 GHz for throughput + coverage balance. Dense urban: mmWave 28/39 GHz for Gbps throughput.

Practice Questions

  1. A port operator wants to use 5G for automated crane control (URLLC) and 4K surveillance cameras (eMBB). Identify the 5G service category, required slice characteristics, and MEC deployment pattern for each application.
  2. A MEC application for AR navigation needs real-time UE location. Which 5GC NF is used to expose this data, and what governance framework controls which third-party apps can access this API?
  3. An IoT deployment requires 50,000 soil moisture sensors across a 500 km2 agricultural area. Each sensor sends 100 bytes of data once per day. Compare NB-IoT and LTE-M for this use case, and specify the PSM timer values that would achieve ~10-year battery life.
  4. Explain how ULCL routes traffic from a factory robot's PDU session to a MEC application without changing the UE's IP address or tearing down the PDU session. Which NF installs the routing rules in the ULCL UPF?
  5. 5G RedCap (Release 17) targets industrial IoT. How does it differ from a full 5G UE in terms of antenna complexity and bandwidth, and what is the trade-off compared to using NB-IoT for the same use case?

Key Takeaways

  • eMBB (throughput) uses mmWave + massive MIMO; URLLC (latency) requires 5G SA + MEC + URLLC slice; mMTC (density) uses NB-IoT/LTE-M/RedCap with PSM power saving
  • MEC places compute at the radio edge — the UPF ULCL routes application traffic locally; MEC Platform exposes RNI, location, and bandwidth management APIs to edge applications
  • NEF exposes 5GC capabilities (QoS boost, location, traffic influence) to third-party applications; CAPIF provides API authentication, authorization, and discovery governance
  • NB-IoT: 200 kHz, 10-year battery, best coverage penetration; LTE-M: 1.4 MHz, 5-year battery, mobility + voice; RedCap: 20 MHz NR, ~150 Mbps, industrial IoT with 5G latency
  • PSM allows IoT devices to sleep for up to 413 days (T3412 timer) — single AA battery can last 10+ years at 1 message per day transmission rate
  • 5G FWA uses the same 5GC infrastructure as mobile but with separate DNN profiles for residential billing, static IP, and full-UE AMBR allocation rather than per-app QoS
