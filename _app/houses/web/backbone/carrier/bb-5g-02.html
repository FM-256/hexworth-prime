5G NR Numerology

5G New Radio introduces a flexible numerology framework where the subcarrier spacing (SCS) is configurable as 2^mu x 15 kHz (mu = 0 through 4). Each mu value defines a numerology with different subcarrier spacing, symbol duration, and slot duration. This flexibility allows a single waveform to serve low-latency URLLC (small slots), high-throughput eMBB (large bandwidth), and mmWave bands (wider SCS to combat phase noise).

Numerology (mu) SCS (kHz) Slot Duration (ms) Use Case Frequency
0 15 1.0 LTE-compatible, sub-6 GHz eMBB FR1
1 30 0.5 Primary eMBB and URLLC in sub-6 FR1
2 60 0.25 Low-latency URLLC FR1 / FR2
3 120 0.125 mmWave eMBB FR2
4 240 0.0625 mmWave reference signals only FR2
Why Numerology Matters for Transport Engineers

Higher numerology (wider SCS, shorter slots) reduces over-the-air latency but also reduces the time budget for fronthaul. With mu=3 (120 kHz SCS), each slot is 0.125ms. The fronthaul link between RU and DU must deliver samples within a fraction of this window, driving the sub-100 microsecond one-way latency requirement. Slot duration directly determines fronthaul transport design constraints.

Frequency Ranges: FR1 and FR2

3GPP defines two frequency ranges for 5G NR. FR1 (sub-6 GHz, 410 MHz to 7.125 GHz) provides wide coverage, good building penetration, and supports both NSA and SA deployments. FR2 (mmWave, 24.25 GHz to 52.6 GHz) delivers extreme bandwidth for dense urban hotspots but has limited range (hundreds of meters) and poor obstacle penetration.

FR1 — Sub-6 GHz Coverage Layer C-band (3.5 GHz) is the primary 5G SA band globally. 100 MHz channel bandwidth typical. 1-3 km macro cell coverage. Penetrates buildings. Supports mobility. Backbone of nationwide 5G.
FR2 — mmWave Capacity Layer 28 GHz, 39 GHz, 60 GHz bands. 400-800 MHz channel bandwidth. Gigabit+ per device throughput. 100-300m range. Line-of-sight preferred. Fixed wireless access (FWA) and stadium deployments.
Low-Band (600/700 MHz) Wide-area coverage and rural 5G. Lower throughput but excellent propagation. 10-20 km macro cell range. T-Mobile's nationwide 5G backbone in the US uses 600 MHz NR.
CBRS (3.5 GHz, US) Citizens Broadband Radio Service — shared federal/commercial spectrum. 150 MHz of unlicensed/GAA spectrum. Enables private 5G enterprise deployments without licensed spectrum.
Massive MIMO and Beamforming

Massive MIMO (Multiple Input Multiple Output) uses a large antenna array — typically 64T64R (64 transmit, 64 receive antenna elements) or more — at the base station. By controlling the phase and amplitude of each antenna element independently, the system can form narrow, directed beams aimed precisely at individual UEs (beamforming) and serve multiple UEs simultaneously on the same time-frequency resource (spatial multiplexing / MU-MIMO).

Traditional LTE used 2T2R or 4T4R antenna configurations. A 64T64R massive MIMO array can achieve 8-16x spectrum efficiency improvement in dense environments by spatially multiplexing up to 16 UE streams on the same physical resource blocks.

==== Key Massive MIMO Concepts ==== Antenna Array: 64 transmit / 64 receive elements (often displayed as 8x8 cross-polarized = 128 ports) Beamforming Types: Analog Beamforming: Phase shifters in RF domain Single beam per time slot Used in mmWave (FR2) — cost efficient Digital Beamforming: Separate digital chains per element Multiple simultaneous beams Full flexibility, higher power consumption Used in sub-6 GHz (FR1) massive MIMO Hybrid Beamforming: Digital + analog combination Balances cost and capability MU-MIMO Streams: Up to 16 simultaneous spatial streams Each stream = independent UE data Requires channel state feedback (CSI-RS) CSI-RS (Channel State Info Reference Signals): gNB transmits CSI-RS → UE measures, reports back gNB uses reports to compute optimal beam weights Type I: Explicit codebook feedback (lower overhead) Type II: Enhanced feedback for higher MU-MIMO gains
Beamforming in Practice

In a dense urban C-band deployment, a 64T64R massive MIMO radio can serve 8-12 simultaneous UEs on the same PRBs (physical resource blocks), multiplying effective cell capacity by 8-12x compared to single-user MIMO. The antenna array also generates vertical beam tilt control (elevation beamforming / 3D-MIMO), allowing precise coverage shaping to multi-floor buildings from a single macro site.

Small Cells and Heterogeneous Networks

Macro cells provide coverage. Small cells provide capacity where demand exceeds the macro layer's throughput. A heterogeneous network (HetNet) combines macro, micro, pico, and femto cells into a unified NG-RAN, managed by the gNB CU via the F1 interface. The Xn interface connects neighboring gNBs for handover coordination.

Cell Type Power (Tx) Coverage Deployment
Macro 40-80W 1-20 km Towers, rooftops. Coverage layer. Sub-6 GHz and low-band.
Micro 5-10W 200m-2km Urban street-level poles, building facades. Capacity offload.
Pico 100mW-2W 50-200m Indoor enterprise, stadiums, shopping malls. Typically ceiling-mounted.
Femto 10-100mW 10-50m Residential or small office. Customer-managed. HeNB (home eNB) in LTE.

Dual Connectivity (DC) allows a UE to connect simultaneously to a macro cell (primary) and a small cell (secondary), aggregating throughput across both links. In 5G this extends to Multi-RAT DC (MR-DC), where the macro may be LTE and the small cell 5G NR, or both may be 5G NR but on different frequency bands.

O-RAN Alliance and Open RAN

The O-RAN Alliance defines open, interoperable interfaces between RAN components, enabling mix-and-match of RU, DU, and CU hardware from different vendors. The two key O-RAN interfaces are the Open Fronthaul (between RU and DU, based on eCPRI + option 7-2x split) and the E2 interface (between the gNB and the RAN Intelligent Controller, which provides AI/ML-driven optimization).

O-RU (Radio Unit) Antenna and lower PHY. O-RAN open fronthaul interface. Vendors: Fujitsu, Samsung, Airspan, JMA. Can be paired with third-party O-DU.
O-DU (Distributed Unit) Upper PHY, MAC, RLC. Often software running on COTS x86 servers. Vendors: Mavenir, Altiostar (Rakuten), Radisys.
Near-RT RIC RAN Intelligent Controller — near real-time (10ms-1s loop). Hosts xApps for interference management, load balancing, handover optimization.
Non-RT RIC Non-real-time (greater than 1s loop). Hosts rApps for AI/ML model training, policy configuration. Interfaces to OSS/BSS via A1 policy.
O-RAN Deployment Reality

As of 2025, O-RAN deployments are production in select markets (Rakuten, Dish, DISH) but integrated-vendor RAN (Ericsson, Nokia, Huawei) still dominates global macro deployments. Performance parity with integrated RAN on massive MIMO workloads remains a key technical challenge for O-RAN in high-capacity deployments. The fronthaul bandwidth requirement is also substantial — a 64T64R antenna with 100 MHz bandwidth generates ~150 Gbps of eCPRI fronthaul traffic.

Practice Questions

  1. A 5G network uses numerology mu=1 (30 kHz SCS). What is the slot duration? If a URLLC application requires 0.5ms over-the-air latency, which numerology is the minimum required?
  2. A stadium deployment needs multi-Gbps throughput to thousands of concurrent users in a 200-meter radius. Which frequency range is most appropriate? What MIMO configuration would maximize spatial multiplexing gains?
  3. Explain the difference between analog beamforming and digital beamforming. Which is used for mmWave small cells and why?
  4. A dual-connectivity device has a macro cell (LTE 1800 MHz) as primary and a 5G NR small cell (3.5 GHz) as secondary. What 3GPP option is this, and which network handles the control plane?
  5. What is the O-RAN Near-RT RIC, and how does it differ from the Non-RT RIC in terms of control loop latency and function?

Key Takeaways

  • 5G NR numerology (mu 0-4) defines subcarrier spacing from 15 kHz to 240 kHz; wider SCS means shorter slots and lower over-the-air latency but tighter fronthaul timing
  • FR1 (sub-6 GHz) provides coverage; FR2 (mmWave) provides extreme capacity at short range — most deployments layer both
  • Massive MIMO (64T64R) achieves 8-16x cell capacity by spatially multiplexing multiple UE streams on the same physical resources using digital beamforming
  • HetNets combine macro, micro, pico, and femto cells; dual connectivity aggregates throughput across macro and small cell simultaneously
  • O-RAN defines open interfaces (Open Fronthaul, E2) enabling multi-vendor disaggregation; the Near-RT RIC hosts xApps for AI-driven RAN optimization
  • A 64T64R O-RU generates ~150 Gbps of eCPRI fronthaul traffic — fronthaul transport must be engineered specifically for this load and timing requirements
