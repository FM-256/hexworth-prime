Fronthaul, Midhaul, and Backhaul

The 5G transport network is divided into three segments based on which RAN functional blocks they connect. The naming derives from the RU/DU/CU disaggregation model. Each segment has different bandwidth, latency, and timing requirements that drive distinct transport technology choices.

Segment Connects Bandwidth (per sector) Latency Req Timing Req
Fronthaul O-RU to O-DU 10-150+ Gbps (64T64R) <100 us one-way IEEE 1588 phase sync <100ns
Midhaul O-DU to O-CU 1-25 Gbps <1 ms one-way SyncE + PTP frequency sync
Backhaul O-CU / gNB to 5GC 1-100 Gbps per site <5 ms one-way (typical) SyncE frequency sync
Fronthaul is Not Traditional Backhaul

Fronthaul carries raw IQ samples (or lightly processed samples depending on the functional split) rather than IP packets. A 64T64R RU with 100 MHz channel bandwidth generates approximately 150 Gbps of eCPRI traffic toward the DU. This dwarfs the processed IP traffic on the backhaul. Many operators use dedicated dark fiber for fronthaul — conventional IP/MPLS switches cannot handle the latency requirements without careful engineering.

eCPRI and Open Fronthaul

eCPRI (enhanced Common Public Radio Interface) is the protocol defined by the eCPRI Industry Cooperation and adopted by the O-RAN Alliance for the open fronthaul interface. It carries digitized antenna samples (user-plane data) and control/synchronization information between the O-RU and O-DU over Ethernet or IP/UDP transport.

The O-RAN functional split (option 7-2x) defines exactly where the PHY layer is divided between RU and DU. The RU handles lower PHY (FFT/IFFT, cyclic prefix) and antenna RF; the DU handles upper PHY (channel coding, HARQ, beamforming weights). eCPRI carries the compressed IQ samples between them.

SyncE and IEEE 1588v2 PTP Synchronization

5G NR requires two types of synchronization throughout the network. Frequency synchronization (SyncE) ensures all network elements run at the same clock rate — required for TDD operation and inter-cell interference management. Phase/time synchronization (IEEE 1588v2 PTP) aligns the absolute time reference across all base stations — critical for TDD uplink/downlink switching and URLLC timing.

SyncE (G.8261) Frequency synchronization via Ethernet physical layer. Clock recovered from incoming Ethernet signal and distributed downstream. Achieves ppb-level frequency accuracy. All switches must support SyncE.
IEEE 1588v2 PTP (G.8275.1) Telecom Profile for phase/time sync. Grand Master clock (GNSS-disciplined) distributes timestamps via PTP messages. Boundary Clocks (BC) at every hop. Target: <100ns end-to-end.
==== PTP G.8275.1 Architecture ==== GNSS Antenna → Grandmaster Clock (T-GM) | PTP messages (Sync, Follow_Up, Delay_Req, Delay_Resp) | Boundary Clock (T-BC) — at aggregation router [corrects for residence time, forwards PTP downstream] | Boundary Clock (T-BC) — at cell site router | Transparent Clock (optional, corrects link delay) | O-DU / O-RU — Ordinary Clock (T-OC), slave mode Timing budget for G.8275.1: T-GM accuracy: ±100ns (from GNSS) T-BC per hop budget: ±20ns error accumulation Typical 5G target: ±130ns at the antenna (3GPP TS 38.133) Max hops T-BC: ≈8-10 hops at 20ns per hop ==== Cisco IOS-XE PTP Boundary Clock (Example) ==== ptp clock boundary domain 44 profile g8275.1 clock-port UPSTREAM slave transport ethernet multicast interface GigabitEthernet0/0 sync limit-exceeded-action log clock-port DOWNSTREAM master transport ethernet multicast interface GigabitEthernet0/1
Why Phase Sync Matters for TDD

5G NR's primary band (C-band 3.5 GHz) uses TDD (Time Division Duplex) — uplink and downlink share the same frequency but are separated in time. All gNBs in a region must switch between UL and DL at exactly the same time. If two adjacent cells are out of phase by even a few microseconds, the UL transmission from one cell hits the DL reception window of the neighbor, causing massive inter-cell interference. This is why sub-100ns phase alignment across the entire transport network is a hard requirement.

FlexE — Flexible Ethernet for Transport Slicing

FlexE (Flexible Ethernet, OIF FlexE 2.1) decouples the Ethernet MAC rate from the PHY rate, enabling a single 100GE physical port to carry multiple logical channels of different rates (e.g., 10G + 25G + 50G = 85G total). This creates hard-isolated transport pipes on shared physical infrastructure — the foundation for transport network slicing.

FlexE clients are Ethernet MACs at arbitrary rates. They are mapped to FlexE calendar slots on a 100GE or 400GE PHY. Different calendar slot assignments for different slices guarantee complete data-plane isolation — a traffic burst in one FlexE client cannot affect another.

Hard Isolation FlexE calendar slot assignment provides deterministic bandwidth — not statistical. A 10G FlexE channel always gets exactly 10G regardless of other clients' utilization.
Sub-rate Support FlexE calendar granularity is 5G on a 100GE PHY. Supports channels: 5G, 10G, 15G, 25G, 50G, 100G within a 100GE PHY. Flexible allocation at provisioning time.
Bonding Multiple PHYs can be bonded into a single FlexE group (e.g., 4x100GE = 400G FlexE group) with 5G slot granularity across the whole group.
Transport Slicing URLLC slice: dedicated 10G FlexE channel. eMBB slice: 50G FlexE channel. Management: 5G FlexE channel. Each slice isolated at the Ethernet layer below IP/MPLS.
IP/MPLS Backhaul with Segment Routing

The 5G backhaul between gNB CU and the 5GC uses IP/MPLS with GTP-U tunnels on the NG-U interface. Segment Routing (SR-MPLS or SRv6) enables traffic engineering for per-slice path selection and fast reroute without per-flow state in the core. Each slice's N3 traffic can be steered onto an SR-TE policy with specific latency, bandwidth, and disjointness guarantees.

Practice Questions

  1. A 64T64R O-RU operates with 100 MHz bandwidth and mu=1 numerology. Estimate the fronthaul bandwidth required before compression, and explain why a conventional 10GE switch would be insufficient.
  2. What is the difference between SyncE and IEEE 1588v2 PTP? Which provides frequency synchronization and which provides phase synchronization? Why does TDD require both?
  3. An operator uses G.8275.1 PTP. The Grandmaster has ±100ns accuracy. The path from GM to the gNB passes through 6 Boundary Clocks each contributing ±20ns. What is the estimated phase error at the antenna?
  4. Explain how FlexE provides transport slicing isolation that IP/MPLS QoS cannot. What is the fundamental difference between a FlexE channel and a DSCP traffic class?
  5. A URLLC slice requires a specific low-latency path through the backhaul that avoids a high-latency satellite link. Which SR-TE component defines the explicit path, and how does the gNB's traffic get mapped to this SR-TE policy?

Key Takeaways

  • Fronthaul (RU to DU): <100us latency, <100ns phase sync, 10-150+ Gbps per sector — fundamentally different from backhaul in every dimension
  • eCPRI carries compressed IQ samples over Ethernet; a 64T64R antenna generates ~150 Gbps of fronthaul traffic after BFP compression
  • SyncE provides frequency sync via Ethernet PHY clock recovery; IEEE 1588v2 G.8275.1 provides phase/time sync via Boundary Clocks — both required for TDD 5G NR
  • TDD inter-cell interference is the primary driver for sub-100ns phase alignment — adjacent cells must switch UL/DL simultaneously
  • FlexE provides hard-isolated transport channels on shared physical Ethernet — deterministic bandwidth, not statistical QoS shaping
  • SR-TE with BGP color extended community enables per-slice path steering in IP/MPLS backhaul without per-flow state in the core
