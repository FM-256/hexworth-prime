High-Density Venue Design

High-density wireless (HDW) design inverts conventional wisdom: the problem is not lack of coverage signal, it is an overabundance of co-channel interference and airtime contention. A stadium, convention center, or lecture hall with 5,000 simultaneous users requires a fundamentally different approach than a standard office floor.

Cell Splitting Deploy many low-power APs instead of few high-power APs. Target cell radius of 6-10 meters per AP in seating areas. Each AP serves 30-50 clients maximum. Use directional patch antennas pointed at seating sections to control cell boundaries.
Under-Seat / Under-Table APs Mount APs underneath stadium seats or conference table legs for hyper-dense environments. Keeps APs at 0.5-1 m distance from clients, allowing minimum transmit power (5-8 dBm) and maximum client density without CCI propagating across the venue.
Disable Legacy Rates Remove 1, 2, 5.5, 11 Mbps basic rates from SSID configuration. Slower clients transmit longer, consuming more airtime from all other clients. Minimum basic rate of 12 or 24 Mbps forces legacy devices off the network and reduces airtime waste.
Minimize SSID Count Each SSID requires its own beacons every 102.4 ms. In a 5,000-client venue with 300 APs, each extra SSID consumes 300 x (1/0.1024) = 2,929 beacon frames per second of shared airtime. Limit to 2-3 SSIDs maximum per radio.

5 GHz Channel Width in High-Density

Use 20 MHz channels in high-density environments, not 80 MHz or 160 MHz. Wider channels reduce the number of non-overlapping channels available (25 non-overlapping at 20 MHz vs 5 at 80 MHz). Fewer channels means more co-channel APs per deployment — exactly the opposite of what HDW design requires. Save 80 MHz for perimeter APs with fewer clients and more open spectrum.

Design Parameter Standard Office High-Density Venue
Clients per AP 25-50 25-35 (strict)
AP Tx Power 14-20 dBm (auto) 5-10 dBm (forced low)
Channel Width (5 GHz) 40-80 MHz 20 MHz
Minimum Basic Rate 6 Mbps 12 or 24 Mbps
SSID Count 3-5 2 maximum per radio
AP Placement Ceiling-mount, 15-20 m spacing Under-seat/table, 6-10 m spacing with directional antennas

Fast Roaming: 802.11r, 802.11k, 802.11v

Standard 802.11 roaming requires the client to perform a full 802.1X authentication to the new AP before traffic can resume — taking 300-800 ms. VoIP calls drop if the break exceeds ~150 ms. The 802.11r/k/v trio reduces roaming time to under 50 ms.

Standard 802.11 Roam vs 802.11r FT Roam
# Standard 802.11 Roam (slow path)
Client --[Probe Request]--> New AP           # discovery
Client <-[Probe Response]-- New AP
Client --[Auth Request]---> New AP
Client <-[Auth Response]--- New AP
Client --[Assoc Request]--> New AP
Client <-[Assoc Response]-- New AP
Client --[EAPOL Start]----> RADIUS Server    # full 802.1X re-auth
...  (4-8 round-trips, 300-800 ms total)

# 802.11r Fast BSS Transition (fast path)
Client --[Auth with FT IEs]--> New AP       # includes PMK-R1 key pre-positioned
Client <-[Auth Response]------ New AP       # key already present on AP
Client --[FT Reassoc Req]----> New AP
Client <-[FT Reassoc Resp]---- New AP       # data flows immediately
Total: ~2 round-trips, 20-50 ms

# Key pre-positioning (how FT achieves this)
# WLC pre-distributes PMK-R1 to all APs in the mobility domain
# when a client first authenticates, so the new AP already has
# the necessary keying material before the client arrives
Standard Function Mechanism Benefit
802.11r (FT) Fast BSS Transition Pre-positions PMK-R1 key to neighbor APs; combines auth + reassoc into 2 frames Reduces roam time from 300-800 ms to under 50 ms; critical for VoIP
802.11k (RRM) Radio Resource Management AP sends Neighbor Report to client listing nearby APs with BSSID, channel, and RSSI Client targets the right AP immediately instead of scanning all channels — faster probe phase
802.11v (BSS TM) BSS Transition Management AP sends BSS Transition Request to client recommending a new AP (with candidate list) Network-directed roaming; AP evicts sticky clients; enables load balancing across APs

Sticky Client Problem

A "sticky client" holds on to a distant AP instead of roaming to a closer one. The client hears the old AP at -80 dBm (poor signal) and the nearby AP at -60 dBm but refuses to roam because its RSSI threshold is too aggressive. 802.11v allows the WLC to force the client off the old AP by sending a BSS Transition Request with a Disassociation Imminent bit set — the client must roam within the specified transition timeout or be kicked off. Cisco's Cisco Optimized Roaming uses 802.11v to solve this in enterprise deployments.

Cisco WLC — Fast Roaming Configuration
# Enable 802.11r Fast Transition on WLAN
config wlan security ft enable <wlan-id>

# Enable 802.11k RRM Neighbor Reports
config wlan ccx aironet-ie enable <wlan-id>

# Enable 802.11v BSS Transition Management
config wlan bss-transition enable <wlan-id>

# Verify FT configuration
show wlan <wlan-id>
# Look for:
#   Fast Transition (802.11r)................... Enabled
#   FT Mobility Domain......................... [MD-ID]
#   FT PSK Mode................................ Disabled (use enterprise only)
#   FT Over DS (over Distribution System)...... Enabled
#   PMK-R1 Push............................... Enabled

# Validate roam events (client MAC 00:11:22:33:44:55)
show client detail 00:11:22:33:44:55
# Look for FT in the "Authentication Algorithm" field

QoS for Wireless (WMM)

Wi-Fi Multimedia (WMM) is the 802.11e QoS implementation mandatory for Wi-Fi CERTIFIED devices since 2004. WMM defines four Access Categories (ACs) that map to different EDCA (Enhanced Distributed Channel Access) parameters — effectively giving higher-priority traffic a shorter backoff window before transmitting.

Access Category Traffic Type DSCP Range 802.1p UP CWmin / CWmax
AC_VO (Voice) VoIP, latency-critical EF (46), CS7 (56) 6, 7 3 / 7 (very short backoff)
AC_VI (Video) Streaming video, videoconferencing AF41-43 (34-36), CS4 (32) 4, 5 7 / 15
AC_BE (Best Effort) Standard data (HTTP, email) Default (0), CS0 (0) 0, 3 15 / 1023
AC_BK (Background) Bulk transfers, backups CS1 (8), AF11-13 (10-14) 1, 2 15 / 1023 (longest backoff)

CWmin (Contention Window minimum) is the minimum random backoff before transmitting. AC_VO picks a random number between 0 and 3 — statistically transmitting much sooner than AC_BE which picks between 0 and 15. This is probabilistic priority, not strict reservation: AC_VO wins most of the time in contention, but not every time.

DSCP Trust Boundary on Wireless

  • AP marks WMM AC based on the 802.1p (UP) bits in the 802.11 QoS frame — but the client sets those bits
  • Untrusted clients can mark all traffic as AC_VO — don't trust client markings in open/guest SSIDs
  • On WLC: configure DSCP policy to override client markings based on SSID (corporate SSID trusts DSCP, guest SSID remarks everything to AC_BE)
  • Cisco QoS Profile: Platinum (maps to AC_VO), Gold (AC_VI), Silver (AC_BE), Bronze (AC_BK)

Scalable Enterprise Wireless Architecture

An enterprise spanning multiple buildings, campuses, or branch offices requires a centralized management model with distributed intelligence. The architectural choice impacts failover behavior, bandwidth consumption on WAN links, and security policy consistency.

Centralized WLC All AP traffic tunneled via CAPWAP to a central WLC in the data center or core. Simple policy enforcement but creates WAN dependency: if WAN fails, APs at remote sites lose connectivity and clients cannot authenticate. Suitable for single-site or HQ-centric deployments.
FlexConnect (H-REAP) APs maintain local switching capability when WAN to WLC is down. Configures "FlexConnect Groups" of branch APs that share common configuration and can authenticate clients locally using cached credentials. WLC manages when connected, APs operate standalone when WAN fails.
Embedded WLC (eWLC) Cisco Catalyst 9800 runs as a virtual appliance on Catalyst 9000 switches or as a dedicated hardware controller. Eliminates separate WLC appliances. Deployed per-campus or per-building with full feature parity including AireOS migration path.
Cisco SD-Access Wireless Integrates wireless into the SD-Access fabric. APs are fabric-mode APs that register with the Fabric Control Plane (LISP) and use VXLAN encapsulation. Client policy follows the user via SGT (Security Group Tag) regardless of location. Requires DNA Center.
FlexConnect Standalone Mode — Verification
# On WLC: verify FlexConnect group configuration
show flexconnect group summary
show flexconnect group detail <group-name>

# Relevant fields in group detail:

#   Local RADIUS Server: 192.168.10.5
#   Central DHCP: Disabled (clients get DHCP from local server)
#   Local Switching VLANs: 10 (corp), 20 (guest)

# When WAN is down — verify AP standalone mode on AP CLI

#   - PMK cached from last WLC-connected auth (8-hour cache by default)

#   - Internet traffic routed locally (not backhauled to DC)

# Force AP to reload and rejoin WLC after WAN restoration
debug capwap ap message enable
show log | include JOIN

For very large deployments, Cisco RF Groups allow multiple WLCs to coordinate RRM across a single physical campus. The RF Group Leader (elected by highest WLC IP) collects RF data from all member WLCs and runs DCA/TPC for the entire group. Mobility groups (separate from RF groups) handle roaming tunnels between WLCs when clients move between buildings managed by different controllers.

Design Scenario

A university has 500 classrooms, each seating 50 students. Classrooms are 10 m x 12 m with concrete block walls. Students use laptops and phones simultaneously during exams (100% occupancy, 50 concurrent users per room). Design an AP placement and SSID strategy for a single building with 30 classrooms on 3 floors. Specify AP model class (Wi-Fi 6 or 6E), AP count, channel width, SSID count, and the roaming protocol suite required.

Key Takeaways

  • High-density design means more APs at lower power, 20 MHz channels, minimum basic rate of 12-24 Mbps, and maximum 2 SSIDs per radio
  • 802.11r Fast Transition pre-distributes PMK-R1 to neighbor APs, cutting roam time from 300-800 ms to under 50 ms
  • 802.11k provides client with a Neighbor Report so it targets the correct AP immediately; 802.11v lets the network steer (or kick) sticky clients
  • WMM AC_VO wins airtime contention probabilistically through shorter backoff windows — not guaranteed reservation
  • FlexConnect enables branch APs to locally switch client traffic and authenticate from cached credentials when the WAN to WLC fails
  • RF Groups coordinate RRM (DCA + TPC) across multiple WLCs on the same campus; Mobility Groups handle inter-WLC roaming tunnels
  • Minimum basic rate, SSID count, and channel width are the three configuration levers with the highest impact on high-density performance

Practice Questions

Q1

A stadium Wi-Fi deployment uses 500 APs but users still experience poor performance during game time. RSSI heat maps show excellent signal. The channel utilization monitor shows 85% average. What is the root cause and what three configuration changes would you make immediately?

Q2

A VoIP phone roaming between APs experiences a 400 ms call gap every time it transitions. 802.11r is not enabled. Walk through the roaming sequence that causes this delay and explain exactly how 802.11r eliminates it.

Q3

Your company has 50 branch offices each with 20 APs. The WAN circuit at each branch is a 50 Mbps MPLS link to a central WLC. What happens to wireless at the branches if the central WLC fails? How does FlexConnect improve resilience?

Q4

A Cisco WLC is configured with Platinum, Gold, Silver, and Bronze QoS profiles. A guest SSID is assigned the Silver profile. A corporate SSID is assigned Platinum. A guest user marks all their traffic DSCP 46 (EF). Will they get AC_VO priority on the wireless medium? Why or why not?
