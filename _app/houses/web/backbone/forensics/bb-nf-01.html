How Packet Capture Works

Packet capture at the OS level relies on the libpcap library (Linux/macOS) or WinPcap/Npcap (Windows). When a capture is initiated, the kernel places the network interface into promiscuous mode, allowing it to receive all frames on the segment, not just those addressed to its MAC. A BPF (Berkeley Packet Filter) in the kernel filters packets before they reach user space, minimizing overhead.

Promiscuous Mode NIC passes all received frames up the stack regardless of destination MAC. Required for capturing traffic destined to other hosts on the same segment.
Monitor Mode (Wi-Fi) Distinct from promiscuous mode. Captures raw 802.11 frames including management frames, regardless of SSID association. Not supported on all drivers.
BPF Kernel Filter Berkeley Packet Filter runs in kernel space, dropping unmatched packets before syscall cost. Orders of magnitude more efficient than filtering in userspace.
Ring Buffer Captures write to a circular ring buffer. When full, oldest packets overwrite. Size the buffer to prevent drops -- use -B flag in tcpdump to increase it.

Capture Position Matters

On a switched network, you only see unicast traffic destined to your own MAC unless you configure a SPAN (Switched Port Analyzer) or mirror port. Shared hubs (now rare) see all traffic on the segment. For forensic work, configure a SPAN port on the switch mirroring the target segment, or deploy an inline network tap for passive capture without impacting traffic.

tcpdump: The Essential Tool

tcpdump is the command-line packet capture tool available on virtually every Unix-like system. It uses libpcap and supports BPF filtering syntax. For forensic work, always write to a pcap file rather than analyzing live output.

tcpdump -- Essential Options and Usage
# List available interfaces
# tcpdump -D

# Capture all traffic on eth0, write to file
# tcpdump -i eth0 -w /evidence/capture_20260316.pcap

# Capture with increased ring buffer (128MB), no name resolution
# tcpdump -i eth0 -B 131072 -n -w capture.pcap

# Rotate files every 100MB, keep 10 files (rolling capture)
# tcpdump -i eth0 -C 100 -W 10 -w /capture/rolling

# Capture and show hex + ASCII (-XX), with timestamps (-tttt)
# tcpdump -i eth0 -XX -tttt -n

# Read existing pcap file
# tcpdump -r capture.pcap -n

# Most important flags summary:
# -i interface    -w write pcap    -r read pcap
# -n no DNS       -nn no port names -v verbose
# -X hex+ASCII    -c count         -s snaplen

Capture Filters (BPF Syntax)

Capture filters apply in the kernel before packets are written to disk. They use Berkeley Packet Filter syntax. Expressions combine qualifiers (host, net, port, proto) with primitives and boolean operators (and, or, not).

BPF Capture Filter Examples
# Only traffic to/from specific host
# tcpdump -i eth0 host 10.0.0.100

# Only DNS traffic (UDP and TCP port 53)
# tcpdump -i eth0 port 53

# HTTP and HTTPS from a specific host
# tcpdump -i eth0 host 10.0.0.100 and (port 80 or port 443)

# All TCP SYN packets (connection initiation)
# tcpdump -i eth0 'tcp[tcpflags] & tcp-syn != 0 and tcp[tcpflags] & tcp-ack == 0'

# ICMP only
# tcpdump -i eth0 icmp

# Entire /24 subnet, exclude SSH to your capture machine
# tcpdump -i eth0 net 10.0.0.0/24 and not port 22

# Large packets (potential data exfiltration indicator)
# tcpdump -i eth0 'greater 1400'

# VLAN-tagged traffic
# tcpdump -i eth0 vlan 100 and host 10.0.100.50

Display Filters vs Capture Filters

Wireshark has two filter systems that beginners often confuse. Understanding the distinction is critical for efficient forensic analysis.

AttributeCapture Filter (BPF)Display Filter (Wireshark)
When appliedAt capture time -- packets not matching are never written to diskPost-capture -- all packets exist in memory, filter changes what's shown
SyntaxBPF: host 10.0.0.1 and port 80Wireshark: ip.addr == 10.0.0.1 and tcp.port == 80
Performance impactReduces disk I/O and CPU -- critical at high traffic volumesNo disk impact; can slow display on large pcaps
ReversalCannot recover filtered packets -- permanent exclusionRemove filter to see all captured packets again
Protocol awarenessLayer 2-4 only (BPF sees raw frames)Full protocol dissection -- can filter on DNS query names, HTTP headers, TLS SNI
Best forReducing capture volume on high-traffic linksPost-incident analysis and investigation
Wireshark Display Filter Examples
// Only HTTP GET requests
http.request.method == "GET"

// DNS queries for specific domain
dns.qry.name contains "evil-domain"

// TLS with specific SNI (Server Name Indication)
tls.handshake.extensions_server_name == "suspicious.example.com"

// TCP connections to non-standard ports (not 80/443/22)
tcp.dstport != 80 and tcp.dstport != 443 and tcp.dstport != 22 and tcp.flags.syn == 1

// Large UDP datagrams (potential DNS tunneling)
udp.length > 200 and dns

// Follow TCP stream: right-click a TCP packet -> Follow -> TCP Stream
// Reconstructs the full application conversation

// ICMP with large payload (possible covert channel)
icmp and data.len > 100

Forensic Capture Best Practices

Packet captures used in legal or disciplinary proceedings must maintain forensic integrity. The chain of custody starts at capture.

Forensic Integrity Rules

  • Hash every pcap file immediately after capture: sha256sum capture.pcap > capture.pcap.sha256
  • Write captures to write-once media or immediately copy to evidence storage with access logging
  • Document: who captured, which interface, start/end time (with NTP-synchronized timestamps), filter applied
  • Never analyze the original -- work on a verified copy
  • Ensure NTP sync before capture -- timestamps are useless for timeline reconstruction without accurate clock
Forensic Capture Procedure
# 1. Verify time sync before starting
# timedatectl status | grep "NTP synchronized"
NTP synchronized: yes

# 2. Start capture with forensic options
# tcpdump -i eth0 -n -B 131072 \
    -w /evidence/case_2026-0316_eth0.pcap \
    2>&1 | tee /evidence/case_2026-0316.log

# 3. Stop with SIGINT (Ctrl+C), note packets captured/dropped
1242844 packets captured
0 packets dropped by kernel  # zero drops = no gaps

# 4. Hash immediately
# sha256sum /evidence/case_2026-0316_eth0.pcap | tee /evidence/case_2026-0316.sha256
a4b8c2d1e5f0...  /evidence/case_2026-0316_eth0.pcap

Key Takeaways

  • libpcap uses BPF in the kernel to filter packets before user space -- far more efficient than post-capture filtering
  • Promiscuous mode captures all frames on the segment; a SPAN/mirror port is required to see other hosts' unicast traffic on switches
  • Capture filters (BPF syntax) are permanent exclusions; display filters (Wireshark syntax) are reversible views of already-captured data
  • tcpdump flags: -w write, -r read, -n no DNS, -B buffer, -C rotate, -W file count
  • Forensic captures require immediate SHA-256 hashing, documented chain of custody, and NTP-synchronized timestamps
  • Zero dropped packets is the goal -- increase ring buffer (-B), use fast storage, and pre-filter aggressively
