NetFlow: Traffic Telemetry Without Payload

NetFlow was developed by Cisco in the 1990s as a traffic accounting and analysis tool. Instead of capturing every packet, routers and switches summarize traffic into flow records. A flow is defined by five tuples: source IP, destination IP, source port, destination port, and IP protocol. NetFlow records the byte count, packet count, start time, and end time for each flow.

The key trade-off: NetFlow loses all payload content but generates orders of magnitude less data than full packet capture. A 10 Gbps link might generate terabytes of pcap per hour but only megabytes of NetFlow records. For long-term security monitoring, NetFlow is the only practical option at scale.

NetFlow v5 Fixed 48-byte record format. IPv4 only. 7 fields per flow. Still widely deployed despite its age. No support for IPv6, MPLS, or flexible field selection.
NetFlow v9 Template-based. Exporter defines its own record format using templates. Supports IPv6, MPLS labels, BGP next-hop, VLAN tags. More flexible but template management adds complexity.
IPFIX (RFC 7011) IETF standard based on NetFlow v9. "IP Flow Information eXport" -- the modern standard. Supports variable-length fields, bidirectional flows, enterprise-defined information elements.
sFlow Alternative to NetFlow. Uses packet sampling rather than flow tracking. Lower router CPU overhead but introduces sampling error for low-volume flows.

NetFlow Configuration and Collection

Cisco IOS -- NetFlow v9 Export Configuration
! Configure flexible NetFlow (IOS 15.x+)
flow record SECURITY-RECORD
 match ipv4 source address
 match ipv4 destination address
 match transport source-port
 match transport destination-port
 match ipv4 protocol
 collect counter bytes
 collect counter packets
 collect timestamp sys-uptime first
 collect timestamp sys-uptime last
 collect transport tcp flags

flow exporter COLLECTOR
 destination 10.0.0.200      # NetFlow collector IP
 transport udp 9995
 export-protocol netflow-v9

flow monitor SECURITY-MONITOR
 record SECURITY-RECORD
 exporter COLLECTOR
 cache timeout active 60      # export active flows every 60s
 cache timeout inactive 15   # export idle flows after 15s

interface GigabitEthernet0/0
 ip flow monitor SECURITY-MONITOR input
 ip flow monitor SECURITY-MONITOR output
nfdump -- Analyzing Collected Flow Data
# List top 20 talkers by bytes (last 24h)
$ nfdump -R /var/nfdump/2026/03/16 -s ip/bytes -n 20
Src IP Addr       Packets    Bytes  Flows
10.0.0.15         1.2M      14.2G    823  # 14GB from one host -- investigate
10.0.0.10         142K       2.1G    2341

# Show all flows to suspicious external IP
$ nfdump -R /var/nfdump/2026/03/16 'dst ip 93.184.1.1' -o long

# Detect port scanning (many unique destinations from one src)
$ nfdump -R /var/nfdump/2026/03/16 \
    'proto tcp and flags S' \
    -a -s dstport/flows -n 50

# Time-series: show flows per minute for specific host
$ nfdump -R /var/nfdump/2026/03/16 'src ip 10.0.0.15' -t 2026-03-16/14:00:00 \
    -o csv | cut -d, -f1,9 | head -60

Anomaly Detection Patterns

Threat PatternNetFlow Indicatorsnfdump Query
Port Scan One src IP, many unique dst ports or dst IPs, TCP SYN flags only, short duration, low bytes proto tcp and flags S and not flags A grouped by src
Data Exfiltration High outbound bytes to a single external IP, sustained over time, after business hours Top talkers by outbound bytes, single destination concentration
C2 Beaconing Regular flows at fixed intervals (every N minutes), small packet count, consistent byte size Time-series of flows between fixed src/dst pair
DDoS Attack Many unique src IPs to single dst, high packet rate, possibly spoofed srcs (random ports) Top flows by packet rate to target IP
Lateral Movement Internal src connecting to many internal hosts on admin ports (445, 22, 3389, WMI) Intra-LAN flows to ports 22/445/3389 from single internal host

NetFlow Retention Strategy

NIST SP 800-92 recommends retaining flow data for at least 90 days for security analysis. Full packet capture is impractical at that scale, but NetFlow data for a 10 Gbps link generates approximately 50-100 GB per day -- manageable. Most security teams keep 90 days of flow data and 24-72 hours of full pcap on demand from SPAN ports.

Practice Questions

  1. A flow record shows: src 10.0.0.50:49152, dst 192.168.100.1:445, TCP, flags S, 1 packet, 60 bytes, duration 0.001s. This pattern repeats for 100 different dst IPs over 30 seconds. What attack is this and what is the attacker doing?
  2. You see a workstation generating 500MB of outbound data daily to a single external IP on port 443. The inbound is only 10KB. What are the two most likely explanations and how would you differentiate them?
  3. Write the nfdump command to find all internal hosts (10.0.0.0/24) that connected to external IPs on TCP port 4444 in the last 24 hours, showing source IP and byte count.
  4. What is the fundamental limitation of NetFlow for forensic investigations that full packet capture does not have?

Key Takeaways

  • NetFlow summarizes traffic into 5-tuple flow records without capturing payload -- practical for long-term monitoring at scale
  • NetFlow v5 is fixed IPv4-only; v9 is template-based; IPFIX is the IETF standard supporting IPv6 and enterprise fields
  • nfdump is the standard command-line tool for analyzing captured NetFlow data in NfSen/nfdump format
  • Port scans show as many unique destinations with SYN-only flags and short durations from one source
  • Exfiltration shows as high outbound bytes to a single external destination, often sustained after hours
  • NetFlow cannot tell you what was in the payload -- if payload evidence is needed, pcap is required
