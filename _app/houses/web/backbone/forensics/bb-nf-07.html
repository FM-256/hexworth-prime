C2 Communication Fundamentals

Command-and-control infrastructure is the nervous system of an attacker's operation. Once an implant is installed, it must communicate with the operator to receive tasking and return results. The fundamental tension is between the attacker's need for reliable communication and the defender's ability to detect that communication.

Modern C2 frameworks overwhelmingly favor blending into legitimate traffic: HTTPS over port 443, HTTP over port 80, DNS over port 53. The attacker's goal is for C2 traffic to be indistinguishable from normal user activity at the network boundary.

Beaconing Detection

Beaconing is the periodic check-in behavior of implants polling their C2 for new commands. Even with jitter (random delay added to the beacon interval), statistical analysis of inter-arrival times reveals the underlying periodic pattern.

Extracting Connection Timestamps for Beaconing Analysis
# Extract all HTTPS connections from one host to one destination
$ tshark -r capture.pcap \
    -Y "ip.src == 10.0.0.15 and ip.dst == 45.77.200.100 and tcp.dstport == 443" \
    -T fields -e frame.time_epoch \
    > timestamps.txt

# Calculate inter-arrival times in Python
$ python3 - <<'EOF'
import sys

times = [float(line.strip()) for line in open('timestamps.txt') if line.strip()]
times.sort()
intervals = [times[i+1] - times[i] for i in range(len(times)-1)]

import statistics
mean = statistics.mean(intervals)
stdev = statistics.stdev(intervals)
cv = stdev / mean  # coefficient of variation -- low CV = highly periodic

print(f"Connections:  {len(times)}")
print(f"Mean interval: {mean:.1f}s")
print(f"Std deviation: {stdev:.1f}s")
print(f"Coeff of variation: {cv:.3f}")
print(f"Verdict: {'BEACON DETECTED' if cv < 0.15 else 'Not periodic'}")
EOF

Connections:   47
Mean interval: 60.3s
Std deviation: 4.8s
Coeff of variation: 0.080
Verdict: BEACON DETECTED

Jitter and Its Limits

Cobalt Strike's default sleep time is 60 seconds with 0% jitter. Operators who set jitter to 50% add randomness of +/- 30 seconds, producing a CV around 0.28. Even at 50% jitter, beaconing patterns remain detectable with enough samples -- typically 20+ connections is sufficient for statistical analysis. The real-world mean interval and jitter values are commonly found in threat intelligence reports for specific malware families.

Data Exfiltration Channels

Exfiltration is the transfer of stolen data out of the network. Attackers choose exfiltration channels based on what is permitted at the egress point. DNS exfiltration is popular because DNS is rarely inspected at the payload level and is almost universally permitted.

DNS Exfiltration Detection in a pcap
# Step 1: Extract all DNS queries and look for anomalously long subdomains
$ tshark -r capture.pcap -Y dns.qry.type==1 \
    -T fields -e dns.qry.name | awk 'length > 50' | head -10

aGVsbG93b3JsZA.secrets.attacker-domain.com
dGhpcyBpcyBleGZpbA.secrets.attacker-domain.com
dHJhdGlvbiBkYXRh.secrets.attacker-domain.com

# Step 2: Decode base64 subdomains
$ echo "aGVsbG93b3JsZA" | base64 -d
helloworld

# Step 3: Measure exfiltration bandwidth via DNS
$ tshark -r capture.pcap -Y "dns.qry.name contains secrets.attacker-domain.com" \
    -T fields -e dns.qry.name | awk '{sum += length($1)} END {print sum " bytes exfiltrated via DNS"}'
187432 bytes exfiltrated via DNS

# Step 4: Calculate entropy of subdomains -- high entropy = encoded/encrypted data
$ python3 -c "
import math, sys
data = 'aGVsbG93b3JsZA'
freq = {}
for c in data: freq[c] = freq.get(c, 0) + 1
entropy = -sum((f/len(data)) * math.log2(f/len(data)) for f in freq.values())
print(f'Entropy: {entropy:.2f} bits/char  (random base64 ~= 5.8)')
"
Entropy: 4.21 bits/char  (random base64 ~= 5.8)

    -Y "ip.src == 10.0.0.0/8 and not ip.dst == 10.0.0.0/8" \
    -T fields -e ip.src -e ip.dst -e tcp.len \

Lateral Movement Traffic Patterns

After establishing a foothold, attackers move laterally to reach high-value targets. Network traffic generated by lateral movement has distinctive port and protocol signatures even when the attacker is using legitimate administrative tools.

Detecting SMB Lateral Movement and Pass-the-Hash
# SMB lateral movement: look for rapid, sequential SMB connections from one host
$ tshark -r capture.pcap \
    -Y "tcp.dstport == 445 and ip.src == 10.0.0.15" \
    -T fields -e frame.time_relative -e ip.dst | head -20

1820.001  10.0.0.20
1820.012  10.0.0.21
1820.024  10.0.0.22
1820.031  10.0.0.23
1820.045  10.0.0.24
# 5 SMB connections in 44ms to sequential IPs = automated SMB scan/propagation

# NTLM pass-the-hash indicator: NTLM authentication on SMB
$ tshark -r capture.pcap \
    -Y "ntlmssp and ip.src == 10.0.0.15" \
    -T fields -e ip.dst -e ntlmssp.auth.username -e ntlmssp.auth.domain

10.0.0.20  Administrator  CORP
10.0.0.21  Administrator  CORP
# Same admin account authenticating to multiple hosts in seconds = PtH or stolen creds

# WMI lateral movement -- DCOM port 135 + ephemeral port
$ tshark -r capture.pcap \
    -Y "tcp.dstport == 135 and ip.src == 10.0.0.15" \
    -T fields -e frame.time_relative -e ip.dst
1850.113  10.0.0.20  <-- WMI to same targets 30 seconds after SMB probe

Living off the Land: When Legitimate Tools Look Malicious

Attackers prefer native Windows tools (PsExec, WMI, PowerShell remoting, RDP) because they blend with legitimate IT traffic and avoid antivirus detection. The network signature is identical to legitimate admin activity. Context is everything: the same SMB connection from the IT admin workstation during business hours is normal; from a developer's laptop at 2 AM is a high-confidence indicator.

Framework-Specific Signatures

Cobalt Strike, Metasploit, and Empire Indicators
## COBALT STRIKE
# Default HTTPS C2: self-signed cert with specific X.509 fields
# Subject: C=US, ST=Maryland, O=Cobalt Strike, OU=AdvancedPenTesting
$ tshark -r capture.pcap \
    -Y "tls.handshake.certificate" \
    -T fields -e x509sat.uTF8String | grep -i "cobalt\|cobaltstrike"

# Default JA3 hash for Cobalt Strike HTTPS listener
JA3: 72a589da586844d7f0818ce684948eea

## METASPLOIT METERPRETER
# Meterpreter over HTTPS: reverse_https handler
# Distinctive: GET /AAAAAAA (random uppercase alpha URI, 7 chars)
# Certificate: self-signed, subject CN=localhost
$ tshark -r capture.pcap \
    -Y "http.request.uri matches \"^/[A-Z]{7}\"" \
    -T fields -e ip.src -e ip.dst -e http.request.uri
10.0.0.15  192.168.1.100  /GTZRQWM

## EMPIRE (PowerShell)
# Staging URI: GET /index.jsp, /login/process.do (task-specific)
# Cookie-based tasking: session cookie contains base64 task
$ tshark -r capture.pcap \
    -Y "http.cookie" \
    -T fields -e ip.src -e http.cookie | grep -E "session=[A-Za-z0-9+/]{40,}"
10.0.0.15  session=SGVsbG8gZnJvbSBFbXBpcmUgQzI=  <-- base64 tasking

Practice Questions

  1. You observe a host making HTTPS connections to 45.33.32.156:443 with inter-arrival times of: 58s, 62s, 59s, 61s, 57s, 63s, 60s. Calculate the mean, standard deviation, and coefficient of variation. Is this beaconing?
  2. Your DNS logs show 5,000 queries per hour to *.secure-updates.net from a single workstation. Normal workstations generate 200-400 DNS queries/hour. The subdomain labels average 45 characters in length. What two metrics confirm DNS exfiltration and what tshark command would you run next?
  3. Describe the network evidence that distinguishes a legitimate IT admin using PsExec to deploy a patch from an attacker using PsExec for lateral movement. What contextual factors would you examine?

Key Takeaways

  • C2 channels favor blending with legitimate protocols -- HTTPS, DNS, and HTTP -- making contextual and statistical analysis essential
  • Beaconing is detectable even with jitter using coefficient of variation analysis across 20+ connection samples
  • DNS exfiltration leaves three measurable indicators: query rate, label length, and label entropy
  • Large outbound HTTPS transfers can be detected via byte asymmetry and outlier flow volume even without decrypting content
  • Framework signatures (JA3, default URIs, certificate fields) enable rapid identification of known C2 infrastructure
  • Lateral movement traffic looks like legitimate admin activity -- time, frequency, and source context distinguish the two
