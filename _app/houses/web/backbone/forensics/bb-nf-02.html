Protocol Dissection Methodology

Deep Packet Inspection (DPI) examines the full contents of packets beyond layer 4 headers. Unlike simple firewall inspection that checks source/destination IP and port, DPI reconstructs application-layer conversations and inspects payload content. In forensic analysis, DPI is used to recover evidence from unencrypted protocols and to extract behavioral indicators from encrypted ones.

The forensic DPI workflow always starts with context: what protocol is expected on this port? Is the traffic conforming to that protocol's specification? Malware commonly uses standard ports for non-standard protocols to evade port-based detection.

Protocol Conformance Does the traffic on port 443 look like valid TLS? Malware may use port 443 for its own binary protocol. Wireshark's dissector will show malformed frames if the protocol doesn't match.
Payload Analysis For cleartext protocols, inspect the actual content. HTTP request paths, POST bodies, FTP transfers, SMTP message contents -- all recoverable from pcap.
Metadata Analysis Even for encrypted traffic, metadata is visible: packet sizes, inter-arrival timing, connection patterns, certificate details, QUIC parameters.
Stream Reassembly TCP delivers byte streams, not messages. DPI tools reassemble TCP streams to reconstruct the complete application-layer conversation across many packets.

tshark: Command-Line DPI

tshark is Wireshark's command-line interface. For large pcap files (gigabytes), tshark is far more practical than the GUI. It supports all Wireshark display filters and can extract specific fields in structured output.

tshark -- Protocol Field Extraction
# List all HTTP hosts accessed
$ tshark -r capture.pcap -Y http.request -T fields \
    -e ip.src -e http.host -e http.request.uri
10.0.0.15   evil.example.com   /callback?id=abc123
10.0.0.20   update.legit.com   /check

# Extract DNS queries and responses
$ tshark -r capture.pcap -Y dns -T fields \
    -e frame.time -e ip.src -e dns.qry.name -e dns.a
2026-03-16 14:23:01  10.0.0.15  bad-domain.net  93.184.1.1

# Count connections per destination IP (top talkers)
$ tshark -r capture.pcap -Y "tcp.flags.syn==1 and tcp.flags.ack==0" \
    -T fields -e ip.dst | sort | uniq -c | sort -rn | head -20

# Extract User-Agent strings (malware identification)
$ tshark -r capture.pcap -Y http -T fields -e http.user_agent | sort -u
Mozilla/5.0 (compatible; MSIE 9.0; Windows NT 6.1)
python-requests/2.28.0   # suspicious -- raw Python in browser traffic

# Export specific protocol data to JSON
$ tshark -r capture.pcap -Y http.request -T json -e ip.src -e http.host > http_hosts.json

File Extraction from Pcap

Unencrypted file transfers (HTTP, FTP, SMB without encryption, SMTP) leave the complete file content in the packet capture. Both Wireshark and specialized tools can reconstruct these files.

Extracting Files: Wireshark and NetworkMiner
# Wireshark GUI: File > Export Objects > HTTP
# Lists all HTTP objects (files) in the capture, select to save

# tshark: export all HTTP objects to directory
$ tshark -r capture.pcap --export-objects http,/evidence/extracted_files/

# NetworkMiner (Linux via Mono) -- parses pcap and extracts
# all file types automatically by protocol
$ mono NetworkMiner.exe capture.pcap

# Manual extraction: find HTTP response containing a file
# In Wireshark: find a TCP stream with binary content
# Right-click stream > Follow TCP Stream > Save As
# Strip HTTP headers manually or use python:
$ python3 -c "
import scapy.all as scapy
# Load and extract payload from specific stream
"

# Verify extracted files (check MIME magic bytes)
$ file /evidence/extracted_files/*
document.pdf:  PDF document, version 1.7
update.exe:    PE32 executable (GUI) Intel 80386  # suspicious executable download

Malware in Extracted Files

Extracted executables, documents, and scripts from forensic captures must be handled as live malware. Open extracted files in an isolated analysis environment (VM with no network, snapshots enabled). Never double-click an extracted PE file on your analyst workstation. Submit suspicious files to VirusTotal or run them in a sandbox like Any.run or Cuckoo.

Analyzing Encrypted Traffic

The majority of modern traffic is encrypted. While you cannot inspect plaintext payload, significant intelligence is available from the unencrypted metadata surrounding encrypted sessions.

ObservableWhat It RevealsTool/Filter
TLS SNI Server hostname in ClientHello -- visible even in encrypted TLS 1.3 (unless ECH used) tls.handshake.extensions_server_name
TLS Certificate Server certificate details: CN, SAN, issuer, validity period, self-signed indicator tls.handshake.certificate
JA3 Fingerprint MD5 hash of TLS ClientHello parameters -- identifies the TLS client library/version Zeek, Suricata, ja3 tool
Packet Size Distribution Fixed-size packets at regular intervals = likely beaconing C2 traffic tshark -T fields -e frame.len
Inter-packet Timing Highly regular timing (jitter < 1%) = automated agent, not human browsing tshark -T fields -e frame.time_relative
Data Volume Asymmetry Large outbound to a single IP with minimal inbound = potential data exfiltration NetFlow analysis or tshark byte counters
Encrypted Traffic Analysis -- Behavioral Indicators
# Extract all TLS server names from a capture
$ tshark -r capture.pcap -Y tls.handshake.type==1 \
    -T fields -e ip.dst -e tls.handshake.extensions_server_name | sort -u

# Find TLS connections to unusual IP ranges (no SNI = suspicious)
$ tshark -r capture.pcap -Y "tls && !tls.handshake.extensions_server_name" \
    -T fields -e ip.dst | sort | uniq -c | sort -rn

# Detect regular beaconing: list inter-arrival times for a single flow
$ tshark -r capture.pcap \
    -Y "ip.src==10.0.0.15 and ip.dst==93.184.1.1" \
    -T fields -e frame.time_epoch | awk 'NR>1{printf "%.3f\n", $1-prev} {prev=$1}'
300.001
300.002
299.999   # Exactly 5-minute interval = C2 beacon

Practice Questions

  1. A pcap shows HTTP traffic on port 80 but Wireshark's HTTP dissector shows no valid HTTP headers -- only binary data. What does this indicate, and what tool or technique would you use to identify the actual protocol?
  2. Write the tshark command to extract all unique User-Agent strings from a pcap file named incident.pcap and sort them alphabetically.
  3. You observe TLS connections from a workstation to a single external IP every exactly 3600 seconds. The connections last 2-3 seconds each, with approximately 500 bytes outbound and 200 bytes inbound. What is the most likely explanation and what additional evidence would confirm it?
  4. What is the difference between extracting credentials from an FTP capture versus an SFTP capture, and why?

Key Takeaways

  • DPI reassembles TCP streams and inspects application-layer content -- malware detection requires checking if traffic conforms to the expected protocol for that port
  • tshark -T fields -e extracts specific protocol fields for scripted analysis of large captures
  • File objects (HTTP, FTP, SMB) can be extracted from unencrypted pcaps using Wireshark's Export Objects or tshark --export-objects
  • Extracted files must be handled as live malware -- analyze only in isolated environments
  • Encrypted traffic analysis uses metadata: TLS SNI, certificate details, JA3 fingerprint, packet timing, and data volume patterns
  • Regular inter-packet timing with jitter < 1% is a strong beaconing indicator
