What SONET/SDH Was Built to Solve

In the 1980s, T-carrier (DS1, DS3) and E-carrier (E1, E3) systems from different manufacturers could not interoperate -- even though they carried the same types of traffic. Asynchronous multiplexing required back-to-back demultiplexing and remultiplexing through the entire hierarchy at every network node, creating enormous complexity and points of failure.

SONET (North America) and SDH (international) solved this by defining a synchronous hierarchy where any tributary rate could be extracted from a higher-rate signal without demultiplexing the entire frame. A single-byte pointer in the frame header marks the start of each tributary payload, allowing add/drop multiplexers (ADMs) to insert and extract tributaries without disturbing other channels.

SONET vs SDH: Naming Difference Only

SONET (Synchronous Optical Network) is the North American standard (ANSI T1.105). SDH (Synchronous Digital Hierarchy) is the ITU-T equivalent (G.707/G.708). They are technically equivalent and interoperable at the optical layer. The key rate differences: SONET uses STS-1 (51.84 Mbps) as the base rate; SDH uses STM-1 (155.52 Mbps) which corresponds to STS-3. All higher rates are multiples.

The SONET frame itself is 125 microseconds long (8000 frames per second) -- chosen specifically so that one DS0 (64 kbps voice channel) maps to exactly one byte per frame. This synchronous timing relationship is fundamental to SONET's design: all clocks in the network are synchronized to a common Stratum hierarchy derived from GPS or cesium references.

SONET Frame Structure and Overhead

An STS-1 frame is 90 columns by 9 rows = 810 bytes transmitted every 125 microseconds (51.84 Mbps line rate). The first 3 columns (27 bytes) are overhead; the remaining 87 columns (783 bytes = payload envelope) carry the SPE (Synchronous Payload Envelope).

Section Overhead (SOH) Rows 1-3 of the transport overhead. Contains framing bytes (A1, A2), section trace (J0), BIP-8 error monitoring (B1), and data communication channels (D1-D3 for section DCC). Terminated at every regenerator.
Line Overhead (LOH) Rows 4-9 of the transport overhead. Contains APS bytes (K1, K2), line BIP-8 (B2), line DCC (D4-D12 for network management), pointer bytes (H1, H2, H3), and synchronization (S1). Terminated at Add/Drop Multiplexers.
Path Overhead (POH) First column of the SPE. Contains path trace (J1), path BIP-8 (B3), signal label (C2 identifies payload type), path status (G1), and user bytes (F2, Z3-Z5). Terminated at the service endpoints.
Pointer (H1, H2, H3) Locates the start of the SPE within the SONET frame. The SPE can float across frame boundaries due to clock differences between nodes. Pointer justification adds or removes bytes to compensate -- the mechanism that enables synchronous tributary extraction.

APS Protection: UPSR and BLSR

SONET's most valued feature in production networks was its 50ms protection switching guarantee. When a fiber cut or equipment failure occurs, SONET switches to the protect path within 50 milliseconds -- a requirement that voice services demanded and that formed the basis for carrier-grade SLA commitments.

UPSR (Unidirectional Path Switched Ring) Traffic flows in both directions around the ring simultaneously. The receiver selects the better signal. On failure, the receiver switches to the other direction within 50ms. Simple, fast, but uses half the ring capacity for protection (1:1 capacity ratio).
BLSR / MS-SPRing (Bidirectional Line Switched Ring) Half the ring bandwidth is working; half is protection. Reuses protection bandwidth for lower-priority traffic when no failure exists. On failure, nodes at either end of the failure loop traffic around the ring. More complex but better bandwidth utilization for longer spans.

The APS protocol uses K1 and K2 bytes in the Line Overhead to signal protection state between nodes. K1 carries the bridge request and channel number; K2 carries the mode (ring or linear), node ID, and active channel. APS signaling must complete within 10ms of failure detection to meet the 50ms total switchover requirement.

Why SONET Was Superseded

SONET/SDH could not efficiently carry packet traffic. A 100 Mbps Ethernet flow required an OC-3 (155 Mbps) circuit with 35% wasted capacity -- and Ethernet speeds grew far faster than SONET could standardize new rates. OTN solved this with native client mapping and hardware FEC. Carrier Ethernet with MPLS-TP replaced SONET protection for new deployments. Today SONET remains only where legacy TDM circuits (T1, DS3, OC-n voice) must be maintained for existing customers.

Key Takeaways

  • SONET (ANSI) and SDH (ITU) are equivalent standards; STS-3 = STM-1 = 155.52 Mbps is the common base
  • SONET solved asynchronous multiplexing by using pointer-based tributary extraction -- no full demux needed
  • Section/Line/Path overhead layers allow fault isolation at three independent monitoring boundaries
  • UPSR: simple, fast, 50% capacity efficiency; BLSR: more complex, better bandwidth reuse on longer rings
  • APS 50ms switchover uses K1/K2 bytes; this guarantee defined carrier-grade reliability for a generation
  • SONET clock hierarchy (Stratum 1-4) required network-wide synchronization; OTN and packet networks use different timing approaches
  • OTN replaced SONET because packet traffic could not be efficiently mapped into the rigid TDM frame structure
