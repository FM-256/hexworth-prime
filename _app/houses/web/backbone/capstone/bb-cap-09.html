Pre/Post Migration Test Plan Structure

Validation is not optional — it is how you demonstrate that the migration succeeded. A test plan structured before the change window provides objective pass/fail criteria that are immune to pressure to declare success.

TIER 1 Baseline Capture (Pre-Change)
  • BGP summary — neighbor states, prefix counts per peer
  • OSPF/IS-IS neighbor adjacencies and LSDB summary
  • Routing table summary — total route count, selected next-hops for critical prefixes
  • Interface statistics — input/output rates, error counters (establish zero-error baseline)
  • CPU and memory utilization on all affected devices
  • End-to-end ICMP results (loss %, RTT) for all critical application paths
  • Service-level measurements: jitter, loss, latency for voice/video flows
TIER 2 Functional Tests (Post-Change)
  • All Tier 1 checks re-executed; compare against baseline
  • Control-plane: verify routing protocol adjacency re-establishment times
  • Data-plane: traceroute confirms traffic path uses expected new route
  • Failover test: pull primary link; verify traffic switches within SLA
  • Application-layer: HTTP/HTTPS connectivity to key services; DNS resolution
  • QoS: DSCP markings preserved end-to-end; verify queue behavior under load
TIER 3 Capacity and Performance Tests
  • Load test to verify bandwidth throughput meets design specification
  • CPU/memory under traffic load (no hidden resource exhaustion)
  • ECMP load distribution — verify all paths are utilized
  • Convergence timing measurement: BFD detection + FRR activation + full reconvergence
  • Validate oversubscription ratios are within design parameters

IP SLA for Continuous Monitoring

Cisco IP SLA sends synthetic test traffic and measures real-world performance metrics. Unlike one-shot pings, IP SLA runs continuously and can trigger SNMP traps or static route failover based on measured results.

! IP SLA comprehensive measurement suite for post-migration monitoring ! Test 1: ICMP echo to critical server — loss/RTT ip sla 10 icmp-echo 10.20.1.1 source-interface Loopback0 frequency 5 ! Every 5 seconds threshold 50 ! Alert if RTT exceeds 50ms timeout 1000 ! 1 second timeout = packet loss if no reply ip sla schedule 10 start-time now life forever ! Test 2: UDP jitter — voice/video path quality (requires IP SLA responder on target) ip sla 20 udp-jitter 10.20.1.1 5000 num-packets 20 interval 20 codec g711alaw ! Ethernet OAM — Y.1731 and 802.1ag

Ethernet OAM provides service-level monitoring for Carrier Ethernet and MPLS-based services. 802.1ag handles fault detection; Y.1731 handles performance measurement.

OAM Function Standard PDU Type Measures
Continuity Check (CCM) IEEE 802.1ag CCM (Multicast) End-to-end path continuity; loss of CCM triggers fault
Loopback (LBM/LBR) IEEE 802.1ag LBM (Unicast) On-demand reachability check (like ping for Ethernet)
Linktrace (LTM/LTR) IEEE 802.1ag LTM (Multicast) Path discovery through intermediate bridges (like traceroute)
Frame Delay (DMM/DMR) ITU-T Y.1731 DMM (Unicast) One-way and two-way frame delay (FD)
Frame Delay Variation ITU-T Y.1731 DMM/DMR Inter-frame delay variation (FDV / jitter)
Frame Loss (LMM/LMR) ITU-T Y.1731 LMM (Unicast) Frame loss ratio (FLR) per EVC/OVC
Synthetic Loss (SLM/SLR) ITU-T Y.1731 SLM Near-zero traffic loss measurement without affecting data plane
MEF SLA Verification

For Carrier Ethernet services, Y.1731 DMM measurements provide the contractual SLA evidence. FD (frame delay), FDV (jitter), and FLR (loss ratio) must all be below MEF bandwidth profile thresholds. Collect 24-hour rolling averages post-migration to confirm SLA compliance before declaring the migration complete.

Pre/Post Check Quick Reference

BGP Prefix Counts Match pre-migration count per neighbor; investigate any reduction
OSPF/IS-IS Adjacency Count Same number of Full/Up adjacencies as baseline
Interface Error Counters Zero CRC errors, zero input errors on all modified links
Traceroute Path Verification Traffic traverses expected new path (not old path via redistribution)
MTU End-to-End 1500-byte and jumbo frames pass DF-bit set without fragmentation
DSCP Preservation DSCP EF preserved end-to-end for voice; AF41 for video
Application Reachability HTTP 200 from each critical application in monitoring list
Failover Timing Pull test on primary path confirms sub-SLA failover (e.g., <1 second with BFD+FRR)
CPU/Memory No device exceeds 70% CPU or 85% memory under baseline traffic load

Practice Questions

1. After a routing migration, traceroute shows traffic taking the old path, not the new IS-IS path. The routing table shows the IS-IS route as installed. What is the most likely cause?

A IS-IS metric is higher than OSPF — OSPF is still preferred
B CEF has not synchronized with the RIB; or the redistribution route (from old protocol) is still winning based on AD
C Traceroute is unreliable for verifying routing changes
D The IS-IS route has a /32 mask conflict with the OSPF prefix

2. Y.1731 LMM/LMR measurement shows FLR of 0.012% on an EVC with a contracted SLA of 0.01%. What is the correct next action?

A Accept the measurement — 0.012% is essentially zero
B Rerun the test — single measurement is insufficient
C Escalate — the EVC is in SLA breach; investigate queue drops and provider circuit quality
D Adjust the SLA threshold to 0.02% to match current performance

3. IP SLA udp-jitter test shows MOS score of 3.2 for a VoIP path that previously scored 4.1. The ICMP echo test shows no packet loss. What is the most likely cause?

A The IP SLA responder is misconfigured and returning wrong timestamps
B QoS is dropping ICMP packets but not UDP
C Increased jitter (delay variation) is degrading MOS even without packet loss — check queue depths and scheduling on egress interfaces
D The new path has lower latency which paradoxically lowers MOS scores
