Availability Targets and Downtime Budget

Availability is expressed as a percentage of uptime over a year. Each "nine" reduces allowed downtime by roughly 10x. Network design must allocate the downtime budget across all planned maintenance and unplanned failure scenarios.

MTTR vs MTBF

Availability = MTBF / (MTBF + MTTR). To reach five nines, either drive MTBF very high (avoid failures) or MTTR very low (recover in seconds). HA architecture targets MTTR reduction via fast detection (BFD) and pre-computed alternate paths (IP FRR).

Active/Standby vs Active/Active

Active / Standby

  • One node handles all traffic; standby is idle
  • Simpler state synchronization
  • Deterministic failover behavior
  • Wastes 50% of capacity under normal operation
  • Failover adds brief traffic interruption (seconds without NSF/SSO)
  • Example: HSRP active/standby, dual supervisors with SSO

Active / Active

  • Both nodes forward traffic simultaneously
  • Full capacity utilization
  • Requires symmetric traffic management or ECMP
  • Complex state sync — asymmetric flows can break stateful inspection
  • Load balancing adds complexity for session-based protocols
  • Example: ECMP routing, VSS/StackWise with dual active detection
Scenario Recommended Model Rationale
Core routing (OSPF/BGP) Active/Active with NSF/GR Both peers forward; NSF preserves forwarding during reconvergence
Firewall cluster Active/Standby preferred Stateful session sync complexity is higher in A/A; asymmetric flow risk
Distribution switches Active/Active (VSS/StackWise) Dual uplinks both active; no STP blocking; full bandwidth utilization
DC spine layer Active/Active (ECMP) Equal-cost multipath across all spines; any failure reduces capacity, not connectivity

NSF and SSO — Hitless Supervisor Failover

Cisco platforms with dual supervisors use SSO (Stateful Switchover) to synchronize configuration and protocol state to the standby, and NSF (Non-Stop Forwarding) to preserve the CEF/FIB during switchover so traffic continues forwarding while routing protocols reconverge.

Feature Function Protocols Supported Impact Without It
SSO Standby supervisor mirrors active; failover is subsecond Platform-level (all) Supervisor reload (minutes); all routing sessions reset
NSF (Cisco Proprietary) Continues forwarding from stale FIB; helper routers suppress route withdrawal OSPF, EIGRP, BGP, IS-IS Neighbor resets; traffic blackholed until reconvergence
Graceful Restart (RFC 5306/4724) Standards-based equivalent; restarting router signals GR capability OSPF (RFC 3623), BGP (RFC 4724), IS-IS (RFC 5306) Without GR, neighbors must be NSF-aware to help

NSF Stale Route Risk

During NSF recovery, traffic continues forwarding on stale FIB entries. If the network topology changed during the switchover (e.g., a link went down), traffic will be blackholed until reconvergence completes. NSF is not a substitute for fast reroute — combine NSF with IP FRR for comprehensive protection.

In-Service Software Upgrade (ISSU)

ISSU allows a software upgrade with minimal or zero traffic interruption on platforms with dual supervisors. The standby loads the new image first, then a SSO switchover occurs, then the original active supervisor loads the new image.

Step 1 — Load New Image on Standby
New IOS XE image is copied to standby supervisor. Standby boots into new version while active continues forwarding on old version.
Step 2 — Version Compatibility Check
System verifies ISSU compatibility between old and new versions. Major version jumps may not support ISSU — consult the compatibility matrix.
Step 3 — SSO Switchover
Standby (now running new image) becomes active. Forwarding continues via NSF. Original active supervisor becomes new standby.
Step 4 — New Standby Loads New Image
Original active supervisor reloads into new image as standby. System now running new version on both supervisors. Upgrade complete.

IP Fast Reroute — LFA and TI-LFA

IP FRR pre-computes alternate next-hops so traffic can be re-routed locally in less than 50ms when a failure is detected — without waiting for routing protocol reconvergence.

Mechanism Calculation Coverage Requirement
LFA (Loop-Free Alternate) SPF-derived neighbor that reaches destination without routing through protected link ~50-80% topologies (ring, hub-spoke have poor coverage) OSPF/IS-IS; no MPLS required
RLFA (Remote LFA) P-Q node found via targeted LDP; tunnel to extend LFA coverage ~90-95% coverage MPLS LDP required
TI-LFA (Topology-Independent LFA) SR-MPLS segment list computed via post-convergence SPF; 100% coverage guaranteed 100% by definition SR-MPLS (Segment Routing)

BFD + IP FRR Integration

BFD provides the sub-second failure detection that triggers IP FRR protection switching. Without BFD, detection relies on interface down events (immediate) or routing protocol dead timers (seconds). Combine BFD for detection with TI-LFA for instant traffic rerouting — this is the standard design for carrier-grade availability.

BFD-Driven Failover Patterns

BFD (Bidirectional Forwarding Detection) decouples failure detection from the routing protocol's hello/dead timer cycle. A failing interface or intermediate path is detected in milliseconds.

BFD Echo vs Asynchronous Mode

In echo mode, the local router sends echo packets that loop back through the remote router's forwarding plane — testing the full path including the remote data plane. Detection times can reach 10-50ms. In asynchronous mode, both routers exchange control-plane BFD hellos. Echo mode is preferred when available but may be prohibited by provider edge routers.
