Hybrid Cloud Connectivity Models

Enterprises connect to cloud providers using dedicated private circuits, IPsec tunnels over the public internet, or a combination of both. The design choice drives cost, latency, and SLA guarantees.

Method Bandwidth Latency SLA Use Case
AWS Direct Connect 1, 10, 100 Gbps (hosted: 50 Mbps - 10 Gbps) Predictable, low jitter 99.99% (2x connections) Production workloads, regulated data
Azure ExpressRoute 50 Mbps - 100 Gbps Predictable 99.95% per circuit, 99.99% dual Hybrid Identity (AD), large data transfers
Google Cloud Interconnect 10, 100 Gbps dedicated; 50 Mbps - 50 Gbps partner Predictable 99.99% dual Analytics, AI/ML workloads
IPsec VPN over Internet Variable (50 Mbps - 1 Gbps typical) Variable, internet-dependent Best-effort Dev/test, backup path, branch access
SD-WAN + Cloud OnRamp Aggregate multiple links Application-aware path selection Vendor-defined app SLA Distributed sites, SaaS optimization
Redundancy Requirement

AWS Direct Connect SLA requires two connections at separate DX locations for 99.99% availability. A single connection provides only 99.9%. Plan for distinct physical paths — same building does not count as separate.

AWS Direct Connect Deep Dive

Direct Connect (DX) is a dedicated private network connection from an on-premises router to AWS. A Virtual Interface (VIF) defines how traffic is exchanged over the physical connection.

Private VIF

  • Connects to a single VPC via Virtual Private Gateway (VGW)
  • BGP peering to VGW; advertise on-prem prefixes
  • Supports IPv4 and IPv6
  • Max 100 prefixes received from AWS by default

Transit VIF

  • Connects to AWS Transit Gateway (TGW)
  • Reach multiple VPCs through TGW route domains
  • Required for multi-VPC or multi-account architectures
  • Max 5,000 prefixes via TGW route table

Public VIF

  • Access public AWS endpoints (S3, DynamoDB) over DX
  • Receives all AWS public prefixes (~8,000 routes)
  • Traffic stays off the public internet
  • Cannot reach private VPC CIDRs

DX Link Aggregation

Link Aggregation Groups (LAG) bundle up to four DX ports at the same DX location into a single logical connection. All member ports must have the same speed. LAG provides capacity, not geographic redundancy — pair with a second DX location for full HA.

Azure ExpressRoute

ExpressRoute connects on-premises to Azure via a connectivity provider at a colocation facility, or directly via ExpressRoute Direct (10G/100G ports in Microsoft's routers). Three peering types define what can be reached.

ExpressRoute + VPN Coexistence

You can configure ExpressRoute as primary and S2S VPN as failover on the same Virtual Network Gateway. Azure uses the ExpressRoute path preferentially; VPN activates if ER goes down. This requires "coexisting connections" mode on the gateway.

Multi-Cloud BGP Routing Policy

When an enterprise connects to multiple cloud providers simultaneously, BGP communities and local-preference policies control traffic steering. A Transit Gateway or virtual router hub aggregates cloud connectivity.

! Multi-cloud hub router — AWS DX primary, Azure ER backup, VPN fallback ! BGP communities used to identify cloud source router bgp 65000 ! AWS Direct Connect neighbor neighbor 169.254.100.2 remote-as 7224 neighbor 169.254.100.2 route-map RM-AWS-IN in neighbor 169.254.100.2 route-map RM-AWS-OUT out ! Azure ExpressRoute neighbor neighbor 169.254.200.2 remote-as 12076 neighbor 169.254.200.2 route-map RM-AZURE-IN in neighbor 169.254.200.2 route-map RM-AZURE-OUT out ! Mark AWS-learned routes with community and set local-pref 200 (preferred) route-map RM-AWS-IN permit 10 set community 65000:100 ! Identifies AWS-origin routes internally set local-preference 200 ! Mark Azure-learned routes with community and set local-pref 150 route-map RM-AZURE-IN permit 10 set community 65000:200 set local-preference 150 ! Prevent cloud provider routes from leaking to each other (no re-advertisement) route-map RM-AWS-OUT permit 10 match ip address prefix-list ON-PREM-ONLY ! Only send on-prem prefixes to AWS route-map RM-AZURE-OUT permit 10 match ip address prefix-list ON-PREM-ONLY ip prefix-list ON-PREM-ONLY permit 10.10.0.0/8 le 24
Route Leak Prevention

Never advertise AWS-learned routes to Azure or vice versa. Without explicit outbound filters, your enterprise router could become a transit path between cloud providers — causing unexpected traffic flows, billing surprises, and possible contract violations. Always use strict outbound prefix-lists.

SD-WAN Cloud OnRamp

Cisco SD-WAN (Viptela/Catalyst SD-WAN) includes Cloud OnRamp (COR) to optimize both SaaS and IaaS access paths. The vSmart controller uses real-time probe data to steer application traffic.

SASE — Secure Access Service Edge

SASE (Gartner 2019) converges SD-WAN networking with a cloud-delivered security stack. Traffic is inspected at a nearby cloud Point of Presence (PoP) rather than backhauled to a central datacenter firewall.

Network Components

  • SD-WAN fabric
  • Cloud Gateway (IPsec/GRE to PoP)
  • Bandwidth aggregation
  • QoS / App-aware routing
  • BGP peering at PoPs

Security Components

  • SWG — Secure Web Gateway
  • CASB — Cloud Access Security Broker
  • ZTNA — Zero Trust Network Access
  • FWaaS — Firewall as a Service
  • DLP — Data Loss Prevention

Key Vendors

  • Cisco Umbrella + SDWAN
  • Palo Alto Prisma Access
  • Zscaler ZIA + ZPA
  • VMware SASE (VeloCloud)
  • Cato Networks
Legacy Approach SASE Approach Benefit
MPLS backhaul to DC firewall Direct internet + cloud PoP inspection Eliminates latency, reduces MPLS cost
VPN client to perimeter ZTNA — identity + posture per app Least privilege; no VPN implicit trust
On-premises web proxy SWG at nearest cloud PoP Policy follows user, not location
Physical firewall appliance FWaaS with elastic capacity No capacity planning; consistent policy
SSE vs SASE

SSE (Security Service Edge) is the security-only subset of SASE (SWG + CASB + ZTNA + FWaaS) without the SD-WAN component. Organizations with existing SD-WAN may add SSE from a separate vendor and integrate at the PoP via GRE/IPsec tunnels.
