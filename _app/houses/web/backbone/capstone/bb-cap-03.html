MPLS vs SD-WAN Decision Framework

The most consequential WAN design decision is the transport technology choice. MPLS delivers carrier-managed SLAs, predictable performance, and enterprise-grade routing. SD-WAN over commodity internet delivers agility, cost efficiency, and cloud-optimized connectivity. Most modern designs use both in a hybrid model.

Factor Choose MPLS Primary Choose SD-WAN Primary
SLA Requirement 99.99%+ carrier-backed SLA required; financial/healthcare/manufacturing 99.9% acceptable; general enterprise, retail
Latency Strict sub-10ms intra-region; real-time trading, telephony 20-50ms acceptable; collaboration tools, cloud apps
Cost Sensitivity Willing to pay 5-10x premium for guaranteed performance Cost is primary driver; broadband at 1/5th MPLS cost per site
Cloud Traffic Most traffic stays on private network (on-prem applications) Majority of traffic goes to SaaS/IaaS; direct internet breakout needed
Sites Fewer than 50 sites; MPLS provisioning complexity manageable 100+ branch sites; zero-touch provisioning critical for SD-WAN
Dual-ISP WAN with BGP Policy

Dual-ISP WAN provides both redundancy and the ability to influence inbound and outbound traffic paths using BGP attributes. The design must account for asymmetric routing (inbound from ISP-A, outbound via ISP-B) and ensure stateful firewall sessions are not broken during failover.

! ===== Dual-ISP BGP Configuration ===== ! ISP-A = primary (lower AS-path, higher local-pref) ! ISP-B = backup (AS-path prepending, lower local-pref) router bgp 65001 bgp router-id 198.51.100.1 bgp log-neighbor-changes ! ISP-A neighbor (primary) neighbor 203.0.113.1 remote-as 65100 neighbor 203.0.113.1 description ISP-A-Primary neighbor 203.0.113.1 route-map ISP-A-IN in neighbor 203.0.113.1 route-map OUT-TO-ISP-A out ! ISP-B neighbor (backup) neighbor 198.19.0.1 remote-as 65200 neighbor 198.19.0.1 description ISP-B-Backup neighbor 198.19.0.1 route-map ISP-B-IN in neighbor 198.19.0.1 route-map OUT-TO-ISP-B out ! Inbound policy: prefer ISP-A routes (higher local-pref) route-map ISP-A-IN permit 10 set local-preference 200 route-map ISP-B-IN permit 10 set local-preference 100 ! Outbound: AS-path prepend on ISP-B (make our prefix less preferred inbound) route-map OUT-TO-ISP-A permit 10 match ip address prefix-list OUR-PREFIXES ! No prepend — ISP-A is preferred inbound route-map OUT-TO-ISP-B permit 10 match ip address prefix-list OUR-PREFIXES set as-path prepend 65001 65001 65001 ! 3x prepend — ISP-B is backup inbound path
SD-WAN Application-Aware Routing (AAR)

SD-WAN AAR uses BFD-measured path metrics (latency, jitter, packet loss) to continuously evaluate available transports and steer applications onto the path that best meets their SLA class. When a path degrades below an SLA threshold, AAR automatically switches the affected application flows to a better-performing transport — without tearing down existing sessions using flow-aware migration.

SaaS apps prefer broadband for direct cloud access
SD-WAN Cloud OnRamp for SaaS

SD-WAN Cloud OnRamp for SaaS continuously probes SaaS application endpoints (Office 365, Salesforce, ServiceNow) from each available transport and selects the path with the best application response time. Traffic is dynamically shifted between ISP-A, ISP-B, and MPLS based on actual SaaS performance — not just raw WAN metrics. This typically reduces SaaS application latency by 30-60% compared to backhauling to a central data center.

SASE — Secure Access Service Edge

SASE (Secure Access Service Edge, Gartner 2019) converges SD-WAN with cloud-delivered security services: SWG (Secure Web Gateway), CASB (Cloud Access Security Broker), ZTNA (Zero Trust Network Access), FWaaS (Firewall as a Service), and DNS security — delivered from a global PoP network. Branch devices connect to the nearest SASE PoP instead of backhauling to a central security stack.

SWG + CASB Inline web filtering and cloud app control. Inspects SSL/TLS traffic (TLS inspection). Enforces DLP (Data Loss Prevention) for SaaS uploads. Replaces branch proxy.
ZTNA (Zero Trust) Replaces VPN for remote access. Identity-aware, application-level access. Never exposes internal network. Integrates with IdP (Okta, Azure AD) for continuous verification.
FWaaS Cloud-hosted stateful firewall. Branches forward all internet traffic to nearest PoP for inspection. Eliminates per-branch firewall hardware. Policy centrally managed.
SD-WAN + SASE Convergence Vendors: Cisco (Umbrella + Viptela), Palo Alto (Prisma), Zscaler (ZIA + ZPA), VMware (VeloCloud). Single platform reduces vendor complexity and improves traffic correlation.

Practice Questions

  1. A retailer has 500 branch stores, each with a 100 Mbps broadband circuit. 80% of traffic goes to SaaS. They need 99.9% availability. Recommend MPLS, SD-WAN, or hybrid and justify with the decision framework.
  2. An enterprise has two eBGP peers: ISP-A and ISP-B. They want all internet traffic to egress via ISP-A normally, but fail over to ISP-B automatically. What BGP attribute is used for outbound path preference, and what mechanism achieves automatic failover?
  3. An SD-WAN AAR policy for voice specifies latency <150ms, jitter <30ms, loss <1%. The MPLS path currently shows 80ms latency and 15ms jitter. Should voice traffic be moved to broadband (120ms, 8ms jitter, 0.5% loss)? Explain the evaluation logic.
  4. A security team wants all branch internet traffic to pass through a central firewall before reaching the internet. This creates a hairpin for SaaS traffic. What SASE component eliminates the hairpin while maintaining full inspection?
  5. AS-path prepending is applied on outbound advertisements to ISP-B with 3 prepends. Does this affect outbound routing from the enterprise, inbound routing toward the enterprise, or both? Explain.

Key Takeaways

  • MPLS: carrier SLA, predictable performance, expensive, slow provisioning — for financial/critical infrastructure with strict SLAs
  • SD-WAN: commodity internet, cost-effective, zero-touch provisioning, cloud-optimized — for cloud-heavy enterprises with 100+ sites
  • Dual-ISP BGP: local-preference controls outbound path; AS-path prepending controls inbound path; BFD integration enables sub-second failover
  • SD-WAN AAR: BFD probes measure live path quality; flows automatically shift when a path degrades below the SLA class threshold
  • SASE converges SD-WAN + SWG/CASB/ZTNA/FWaaS into a cloud-delivered service — eliminates per-branch security hardware and provides direct cloud breakout with full inspection
