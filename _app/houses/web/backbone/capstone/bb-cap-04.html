Spine-Leaf Fabric Architecture

The spine-leaf (Clos) topology replaced the legacy three-tier DC architecture (core/aggregation/access) because it provides predictable, consistent east-west latency. Every leaf switch has exactly two hops to every other leaf via the spine layer — no traffic traverses more than two switch hops regardless of which servers are communicating. This is critical for microservices and distributed applications where any server may communicate with any other.

==== Spine-Leaf Scale Design ==== Spine switches: 2-4 (for redundancy and bandwidth) Leaf switches: N (one per rack or per ToR zone) Connectivity: Each leaf has 1 uplink to EACH spine switch Leaf-to-spine bandwidth = uplinks per leaf x link speed Servers connect to leaf via downlink ports Oversubscription calculation: Leaf switch: 48x 25GbE downlinks + 8x 100GbE uplinks Downlink total: 48 x 25 = 1,200 Gbps Uplink total: 8 x 100 = 800 Gbps (with 2 spines: 4x100 per spine) Oversubscription ratio: 1,200 / 800 = 1.5:1 (Industry standard: 3:1 for most workloads; 1:1 for storage) Failure scenarios: Single spine failure: 50% bandwidth remains (all traffic via remaining spine) Single leaf failure: rack isolated, other racks unaffected Single uplink failure: ECMP continues via remaining uplinks
Spine Layer Pure transit — no server connections. High-radix 100G/400G switches. Cisco Nexus 9336C-FX2, Arista 7800R. IP routing only. BGP EVPN control plane. No QoS policy.
Leaf Layer ToR (Top-of-Rack) or EoR switches. Server-facing 10G/25G/100G. Spine-facing 100G. VXLAN VTEP termination. BGP EVPN peering to all spines. ECMP across all spine uplinks.
Border Leaf Special leaf nodes connecting the fabric to external networks (WAN edge, internet, other data centers). BGP peering external. L3 gateway for tenant VRFs to outside world.
Service Leaf Connects shared services: firewalls, load balancers, storage arrays. Traffic steered through service leaf via VXLAN encapsulation and BGP policy.
VXLAN + EVPN: The Modern DC Fabric

VXLAN (Virtual eXtensible LAN, RFC 7348) encapsulates Layer 2 frames in UDP/IP headers, stretching VLANs across an IP fabric without requiring L2 adjacency between ToR switches. EVPN (Ethernet VPN, RFC 7432) provides the BGP-based control plane that distributes MAC/IP binding information, eliminating the need for flood-and-learn across VXLAN tunnels.

DCI — Data Center Interconnect

DCI connects two or more data centers to enable workload mobility, disaster recovery, and active-active application deployments. The DCI must extend VLANs (for live migration), route between tenant VRFs, and provide high-bandwidth, low-latency transport. The most modern approach uses EVPN over MPLS or VXLAN for the DCI overlay.

DCI Model Description Use Case VLAN Extension
Active-Standby DR site is cold/warm standby. Traffic only flows to DC-A normally. DC-B activated on disaster declaration. DR / backup. Lower cost. RTO measured in minutes to hours. Not required — failover is a full cutover
Active-Active Both DCs serve traffic simultaneously. Workloads distributed across both. Failover is seamless (seconds). High availability applications, financial trading, e-commerce Required — VMs must migrate live, retaining MAC/IP
EVPN DCI Border leaf peers across DCI link with remote border leaf. MAC/IP routes distributed via EVPN Type 2/5 routes. L2 and L3 connectivity. Modern cloud-native DC interconnect VXLAN encap across WAN, or dark fiber / DWDM
Active-Active L2 Stretch: The STP Problem

Stretching Layer 2 VLANs across two data centers creates a large broadcast domain spanning both sites. A broadcast storm or STP topology change in DC-A can cascade to DC-B across the DCI link. Modern EVPN-based DCI avoids this by using IP-based learning and not flooding across the DCI for unknown unicast. Always deploy Distributed Anycast Gateway with EVPN — never rely on a single First-Hop Gateway across the DCI.

Practice Questions

  1. A spine-leaf fabric has 4 spine switches. Each leaf has 4x 100GbE uplinks (1 to each spine). The leaf has 48x 25GbE server ports. Calculate the oversubscription ratio and compare it to the 3:1 design target.
  2. Why does EVPN eliminate the need for flood-and-learn in a VXLAN fabric? What specific BGP route type carries MAC/IP binding information between VTEPs?
  3. An application requires VMs to live-migrate between DC-A and DC-B without changing IP addresses. What DCI model is required, and what is the key risk of L2 extension across data centers?
  4. In a VXLAN EVPN fabric, what is the role of the NVE (Network Virtualization Endpoint) interface, and what address is used as the VTEP source?
  5. A border leaf connects the DC fabric to the WAN edge router. Which BGP address family carries EVPN routes internally, and which carries standard IP prefixes externally?

Key Takeaways

  • Spine-leaf (Clos) provides consistent two-hop east-west latency and ECMP load sharing — every leaf is exactly 2 hops from every other leaf
  • Oversubscription = server-facing bandwidth / spine-facing bandwidth; 3:1 typical, 1.5:1 for compute-heavy, 1:1 for storage (NVMe-oF)
  • VXLAN extends L2 over L3 fabric using UDP encap; EVPN BGP control plane distributes MAC/IP bindings, eliminating flood-and-learn
  • EVPN Type 2 route = MAC/IP binding (host route); Type 5 route = IP prefix route (L3 VPN); both carried in L2VPN EVPN address family
  • Active-active DCI enables live VM migration but requires L2 stretch — use EVPN Distributed Anycast Gateway, never a single centralized gateway spanning DCs
  • Border leaf connects fabric to external networks (WAN, internet, DCI) using BGP route exchange between tenant VRFs and external routing domains
