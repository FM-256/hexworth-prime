Network Security Fundamentals
Attacks  •  Firewalls  •  IDS/IPS  •  Authentication  •  Wireless Security  •  Hardening
Network security is not optional -- it is the foundation that protects every service, every user, and every byte of data traversing your infrastructure. This chapter covers the attack surface, the defense stack, and the authentication protocols that the N10-009 exam expects you to identify and explain.

Denial of Service (DoS / DDoS)
DoS exhausts target resources with illegitimate traffic. DDoS amplifies the attack using a distributed botnet -- thousands of compromised hosts flooding a single target simultaneously.
SYN Flood
The attacker sends thousands of TCP SYN packets with spoofed source IPs. The server allocates resources for each half-open connection and never receives the completing ACK. The connection table fills, legitimate users cannot connect. Mitigation: SYN cookies allow the server to avoid allocating state until the three-way handshake completes.
Amplification Attack
The attacker sends small requests to public servers (DNS, NTP, memcached) with the source IP spoofed to the victim's address. Each server responds with a much larger reply directed at the victim. A 60-byte DNS query can generate a 4000-byte response -- a 66x amplification factor. Mitigation: BCP38 ingress filtering blocks spoofed source addresses at the network edge.
Application Layer (Layer 7)
Slow HTTP attacks like Slowloris keep connections open by sending incomplete HTTP headers. The server waits for the complete request, exhausting its thread pool with minimal attacker bandwidth. These attacks bypass volumetric defenses because the traffic volume is low. Mitigation: connection timeouts, request rate limiting per IP, and WAF rules that detect malformed request patterns.

Man-in-the-Middle & ARP Poisoning
MITM attacks intercept communication between two parties. ARP poisoning is the most common LAN-based MITM technique -- the attacker associates their MAC address with the default gateway's IP.
DNS Poisoning
The attacker corrupts the DNS cache of a resolver so that legitimate domain lookups return malicious IP addresses. Users type the correct URL but are directed to a phishing site. Defenses include DNSSEC (which signs DNS records cryptographically), DNS over HTTPS (DoH), and restricting recursive DNS queries to trusted clients only.
VLAN Hopping
Two techniques: Switch Spoofing -- the attacker configures their NIC to negotiate a trunk link with the switch, gaining access to all VLANs. Double Tagging -- the attacker sends a frame with two 802.1Q tags; the first is stripped by the access switch, the second routes the frame to a different VLAN. Defense: disable DTP on all access ports, set native VLAN to an unused VLAN ID, and explicitly configure trunk ports.

Firewalls -- Network Perimeter Defense
Firewalls filter traffic between network zones using rules based on source/destination IP, port, protocol, and application state. They are the primary perimeter defense on every network.
Packet Filtering
Stateless -- inspects each packet individually against ACL rules. Fast but cannot track connection state. A rule allowing inbound port 80 cannot distinguish between a new connection and an established reply.
Stateful Inspection
Tracks the state of active connections in a state table. Return traffic for established sessions is automatically allowed. The standard for modern enterprise firewalls since the late 1990s.
Next-Gen (NGFW)
Combines stateful inspection with deep packet inspection (DPI), application awareness (identifies Zoom vs generic HTTPS), intrusion prevention, TLS decryption, and threat intelligence feeds. Examples: Palo Alto, Fortinet, Cisco Firepower.
Implicit Deny
Every firewall ends its ruleset with an implicit deny -- any traffic not explicitly permitted is dropped. This is the foundational security principle: deny by default, allow by exception. The exam will test this concept directly.
DMZ Architecture
A demilitarized zone sits between the external and internal firewalls. Public-facing servers (web, email, DNS) live in the DMZ. If compromised, the attacker still cannot reach the internal LAN -- the inner firewall blocks lateral movement.
ACL Rule Order
Rules are processed top-down. The first match wins. Specific rules go above general rules. A permit-all rule at the top would bypass every rule below it. Order matters -- exam questions frequently test this logic.

IDS / IPS -- Intrusion Detection & Prevention
IDS monitors and alerts. IPS monitors, alerts, AND blocks. Both analyze traffic against signatures and behavioral baselines to detect threats the firewall cannot see.
Signature-Based
Compares traffic against a database of known attack patterns. Fast and accurate for known threats. Cannot detect zero-day attacks. Requires regular signature updates. Think of it as antivirus for network traffic -- effective against what it recognizes, blind to what it does not.
Anomaly-Based (Behavioral)
Establishes a baseline of normal traffic patterns, then flags deviations. Can detect novel attacks. Prone to false positives during legitimate traffic spikes. Requires a learning period to calibrate the baseline. Most modern IPS systems combine signature and anomaly detection.
HIDS vs NIDS
HIDS (Host-based) runs on individual endpoints -- monitors file integrity, log events, and process behavior. NIDS (Network-based) monitors network traffic from a span port or tap. For the exam: NIDS watches the wire, HIDS watches the host. Both feed alerts to a SIEM for correlation.

Proxy Servers & VPN Concentrators
Proxies mediate connections between clients and the internet. VPN concentrators establish encrypted tunnels for remote access and site-to-site connectivity.
Forward Proxy
Sits between internal clients and the internet. Clients send requests to the proxy, which fetches content on their behalf. Provides: URL filtering (block social media), content caching (reduce bandwidth), logging (who visited what), and anonymity (the destination sees the proxy IP, not the client's). Example: Squid, Zscaler, Blue Coat.
Reverse Proxy
Sits in front of servers, receiving client requests and distributing them to backend servers. Provides: load balancing, SSL offloading (decrypt TLS once at the proxy instead of on each server), caching, and DDoS protection. Example: Nginx, HAProxy, Cloudflare. The client never connects directly to the backend server.
Site-to-Site VPN
Permanent encrypted tunnel between two locations using IPSec. Once established, traffic flows transparently -- users do not need VPN clients. The VPN concentrator at each site encrypts/decrypts all inter-site traffic. Protocols: IKEv2 negotiates the tunnel parameters, ESP encrypts the payload. Used to connect branch offices to headquarters.
Remote Access VPN
Individual users connect from laptops or phones to the corporate VPN concentrator. Protocols: SSL/TLS VPN (uses port 443, works through most firewalls), IPSec with IKEv2, or WireGuard. Split tunneling sends only corporate traffic through the VPN; full tunnel routes all traffic through it. Split tunneling saves bandwidth but reduces security visibility.

Authentication Protocols
Network access requires authentication. These protocols centralize credential verification so every switch, AP, VPN, and firewall authenticates against one source of truth.
RADIUS
Remote Authentication Dial-In User Service. Client/server protocol on UDP 1812/1813. Encrypts only the password field. Combines authentication and authorization in one response. The standard for wireless authentication (802.1X), VPN login, and network device access. Widely supported by every vendor.
TACACS+
Terminal Access Controller Access-Control System Plus. Cisco-proprietary on TCP 49. Encrypts the entire packet body (not just the password). Separates authentication, authorization, and accounting into distinct operations. Preferred for network device administration (router/switch CLI access) because of granular command-level authorization.
Kerberos
Ticket-based authentication using a trusted third party (KDC). Uses port 88/TCP and UDP. The user authenticates once, receives a Ticket-Granting Ticket (TGT), then exchanges it for service tickets without re-entering credentials. Active Directory authentication is built on Kerberos. Provides mutual authentication -- both client and server prove their identity.
LDAP / LDAPS
Lightweight Directory Access Protocol on port 389 (636 for LDAPS with TLS). Not an authentication protocol itself -- it is a directory query protocol. RADIUS and TACACS+ servers query LDAP backends (Active Directory, OpenLDAP) to validate credentials. LDAPS encrypts the connection with TLS. Always use LDAPS in production.
SAML / SSO
Security Assertion Markup Language enables Single Sign-On (SSO) for web applications. The Identity Provider (IdP) authenticates the user once, then issues signed XML assertions to Service Providers (SPs). The user accesses multiple applications without re-authenticating. Common in cloud/SaaS environments. N10-009 expects you to recognize SAML as an SSO enabler.
Multifactor Authentication
MFA requires two or more factors from different categories: something you know (password), something you have (token, phone), something you are (biometrics). A password plus a PIN is NOT MFA -- both are "something you know." A password plus a push notification IS MFA. The exam tests the distinction between multi-factor and multi-step.

Wireless Security Standards
Wireless networks broadcast traffic over radio -- anyone within range can capture frames. Encryption and authentication are mandatory, not optional.
EAP Types
EAP-TLS: Mutual certificate authentication -- both client and server present certificates. Most secure, but requires PKI infrastructure. PEAP: Server certificate creates TLS tunnel, client authenticates inside with MSCHAPv2 (username/password). EAP-FAST: Cisco proprietary, uses Protected Access Credential (PAC) instead of certificates.
Wireless Threats
Rogue AP: Unauthorized access point connected to the corporate network, bypassing security controls. Evil Twin: Attacker-controlled AP with the same SSID as a legitimate network -- clients connect unknowingly. War Driving: Scanning for open or weak wireless networks from a vehicle. Defense: Wireless Intrusion Prevention System (WIPS), strong WPA3 Enterprise, 802.1X with RADIUS.
Exam Tips
WEP is always wrong on the exam unless the question asks what is deprecated. WPA2-Enterprise with 802.1X/RADIUS is the corporate standard. WPA3-SAE replaces PSK with a key exchange resistant to offline dictionary attacks. Know the three 802.1X roles: supplicant, authenticator, authentication server. PEAP is the most commonly deployed EAP type.

Network Hardening
Hardening reduces the attack surface by disabling unnecessary services, restricting access, and implementing switch-level security controls that prevent Layer 2 attacks.
Port Security
Limits the number of MAC addresses allowed on a switch port. If an unknown MAC appears, the port can shutdown, restrict, or protect. Prevents CAM table overflow attacks where an attacker floods the switch with fake MACs to force it into hub mode.
DHCP Snooping
Switch builds a binding table mapping MAC to IP to VLAN to port. Only trusted ports (connected to legitimate DHCP servers) can send DHCP offers. Untrusted ports sending DHCP server messages are blocked. Prevents rogue DHCP servers from poisoning client configurations.
Dynamic ARP Inspection
Uses the DHCP snooping binding table to validate ARP packets. If an ARP reply claims an IP belongs to a MAC that does not match the binding table, the frame is dropped. Directly prevents ARP poisoning attacks. Requires DHCP snooping to be enabled first.
ACLs (Access Control Lists)
Filter traffic at Layer 3/4 on routers and Layer 3 switches. Standard ACLs filter by source IP only. Extended ACLs filter by source/destination IP, port, and protocol. Applied inbound or outbound on interfaces. Processed top-down, first match wins, implicit deny at the end.
Disable Unused Ports
Every unused switch port should be administratively shut down and placed in a dead VLAN. Prevents physical access attacks -- an intruder plugging into an open port gets no network connectivity. Also disable unused services: Telnet (use SSH), HTTP (use HTTPS), SNMPv1/v2 (use SNMPv3).
Role-Based Access
Network device management should use role-based access control. Privilege levels on Cisco devices (levels 0-15) or custom roles restrict which commands each admin can execute. Combined with TACACS+ for centralized, auditable command authorization. No shared admin accounts.

Security Zones & Network Segmentation
Segmentation limits the blast radius of a breach. If an attacker compromises a workstation in the guest VLAN, segmentation prevents lateral movement to the server VLAN.
VLAN Segmentation
VLANs create logical broadcast domains on a single physical switch. Hosts in different VLANs cannot communicate without a Layer 3 device (router or L3 switch) that enforces ACLs between them. Common zones: Management VLAN (network devices), Server VLAN, User VLAN, Guest VLAN, IoT VLAN. Each zone has its own subnet and firewall rules.
Zero Trust Architecture
The traditional perimeter model assumes everything inside the firewall is trusted. Zero Trust assumes nothing is trusted -- every access request is verified regardless of location. Principles: verify explicitly (authenticate every request), use least-privilege access, assume breach. Micro-segmentation enforces policy at the workload level, not just the network boundary.
Network Access Control (NAC)
NAC evaluates device health before granting network access. Is the antivirus up to date? Is the OS patched? Is the device domain-joined? Non-compliant devices are quarantined to a remediation VLAN. NAC works with 802.1X -- the supplicant provides both user credentials and device posture. Examples: Cisco ISE, Aruba ClearPass, FortiNAC.
Honeypots and Deception
A honeypot is a deliberately vulnerable system designed to attract attackers. It provides early warning of network intrusion and diverts attackers from real assets. A honeynet is a network of honeypots. Placement: DMZ for external threats, internal network for insider threat detection. Any traffic to a honeypot is suspicious by definition -- legitimate users have no reason to connect to it.

Cryptography Essentials for Networking
Encryption, hashing, and certificates secure data in transit and at rest. The N10-009 expects you to understand where each mechanism applies in the network stack.
Symmetric Encryption
One shared key encrypts and decrypts. Fast -- used for bulk data transfer. AES-256 is the standard for VPN tunnels, wireless (WPA2/WPA3), and disk encryption. The challenge: both parties must securely exchange the shared key before communication begins (solved by asymmetric key exchange).
Asymmetric Encryption
Two mathematically linked keys: public (shared freely) and private (kept secret). Data encrypted with the public key can only be decrypted with the private key. RSA and ECDSA are common algorithms. Used for TLS handshakes, SSH authentication, and digital signatures. Slower than symmetric -- not used for bulk data.
Hashing
One-way function that produces a fixed-length digest. SHA-256 and SHA-384 are current standards. MD5 and SHA-1 are deprecated (collision vulnerabilities). Hashing verifies data integrity -- if the hash of a downloaded file matches the published hash, the file is unmodified. HMAC combines hashing with a secret key for message authentication.
TLS / SSL
TLS 1.2 and TLS 1.3 encrypt HTTP, SMTP, LDAP, and other application protocols. The TLS handshake uses asymmetric encryption to exchange a symmetric session key, then switches to symmetric encryption for performance. TLS 1.3 reduced the handshake from two round-trips to one. SSL is deprecated -- "SSL certificate" is a legacy name for a TLS certificate.
PKI and Certificates
A Certificate Authority (CA) issues digital certificates that bind a public key to an identity (domain name, organization). The browser trusts the CA, the CA vouches for the server, and the TLS connection is established. Certificate chain: Root CA signs Intermediate CA, Intermediate CA signs the server certificate. Revocation is checked via CRL or OCSP.
IPSec Components
AH (Authentication Header): Integrity and authentication only, no encryption. Protocol 51. ESP (Encapsulating Security Payload): Encryption + integrity + authentication. Protocol 50. IKE: Negotiates the security association (SA) -- the set of algorithms and keys both sides agree on. IKEv2 is the current standard for VPN tunnel establishment.

Chapter 1 Summary
Network Security Fundamentals -- key concepts for N10-009.
1DoS/DDoS attacks exhaust resources through volume (SYN flood, amplification) or application abuse (Slowloris). Mitigate with rate limiting, SYN cookies, CDN scrubbing, and BCP38 ingress filtering.
2ARP poisoning is the primary LAN-based MITM vector. Defend with Dynamic ARP Inspection + DHCP snooping. DNS poisoning redirects lookups -- defend with DNSSEC.
3Firewalls progress from stateless packet filtering to stateful inspection to NGFW with DPI and application awareness. Every ruleset ends with an implicit deny.
4IDS alerts, IPS blocks. IDS is passive (SPAN port), IPS is inline. Both use signature + anomaly detection. HIDS watches hosts, NIDS watches the network.
5RADIUS for wireless/VPN (UDP 1812), TACACS+ for device admin (TCP 49, encrypts full packet), Kerberos for AD (port 88, ticket-based SSO).
6WPA3-SAE replaces PSK with forward secrecy. 802.1X Enterprise uses supplicant + authenticator + RADIUS. EAP-TLS (certificates) is most secure, PEAP (password in tunnel) is most deployed.
7Hardening: port security, DHCP snooping, DAI, disable unused ports, disable Telnet/SNMPv1, segment with VLANs, apply ACLs between zones.
