IPv4 Addressing

The 32-Bit Address

IPv4 Structure

32 bits, written as four decimal octets separated by dots.

192 . 168 . 1 . 100
Network portion | Host portion
  • Each octet: 0 to 255
  • Total addresses: ~4.3 billion
  • Subnet mask separates network from host

IPv4 Address Classes

Class Range Default Mask Use
A 1-126 /8 Large networks
B 128-191 /16 Medium networks
C 192-223 /24 Small networks
D 224-239 N/A Multicast
E 240-255 N/A Experimental

127.x.x.x is reserved for loopback (localhost). It is not part of Class A.

CIDR Notation

Classless Inter-Domain Routing -- replaces classful addressing with flexible prefix lengths.

CIDR Subnet Mask Hosts
/24 255.255.255.0 254
/25 255.255.255.128 126
/26 255.255.255.192 62
/27 255.255.255.224 30
/28 255.255.255.240 14
/30 255.255.255.252 2

Formula: Usable hosts = 2^(host bits) - 2 (subtract network and broadcast addresses)

Subnetting Basics

Dividing One Network Into Many

Why Subnet?

  • Reduce broadcast domains -- smaller networks, less noise
  • Security -- isolate departments, guest networks
  • Efficiency -- allocate addresses based on need

Key Addresses in Each Subnet

Address Type Example (192.168.1.0/26) Description
Network Address 192.168.1.0 All host bits = 0 (not assignable)
First Usable 192.168.1.1 First host address (often the gateway)
Last Usable 192.168.1.62 Last host address
Broadcast 192.168.1.63 All host bits = 1 (not assignable)

Static vs DHCP Configuration

Manual vs Automatic IP Assignment

Static IP Configuration

Administrator manually assigns all network settings.

IP Address: 192.168.1.50 Subnet Mask: 255.255.255.0 Gateway: 192.168.1.1 DNS Server: 8.8.8.8 DNS Server 2: 8.8.4.4
  • Used for: Servers, printers, routers, network devices
  • Predictable, but doesn't scale well
  • Risk of duplicate IP conflicts if misconfigured

DHCP (Dynamic)

DHCP server automatically provides all settings.

  • Used for: Workstations, laptops, phones, IoT
  • Scales to thousands of devices
  • No risk of manual IP conflicts
  • Leases expire and are renewed automatically
  • Can still reserve IPs by MAC address

Common Mistake

Setting a static IP within the DHCP scope range without a reservation can cause IP conflicts -- the server may assign that address to another device.

Default Gateway & DNS Configuration

Getting Traffic Off the Local Network

Default Gateway

The router interface that forwards traffic to other networks. Without it, a device can only communicate on its own subnet.

DNS Configuration

Devices need at least one DNS server to resolve domain names. Best practice: configure two for redundancy.

  • Primary DNS: First server queried
  • Secondary DNS: Fallback if primary fails
Common public DNS servers: Google: 8.8.8.8 / 8.8.4.4 Cloudflare: 1.1.1.1 / 1.0.0.1 Quad9: 9.9.9.9 / 149.112.112.112

Troubleshooting Tip

If you can ping 8.8.8.8 but not ping google.com, the issue is DNS -- not connectivity.

Special IP Addresses

Loopback, APIPA, and Reserved Ranges

Loopback

127.0.0.1

Range: 127.0.0.0/8

  • Tests TCP/IP stack locally
  • Never leaves the device
  • If ping 127.0.0.1 fails, TCP/IP is broken

APIPA

169.254.x.x

Range: 169.254.0.0/16

  • Automatic Private IP Addressing
  • Assigned when DHCP fails
  • Local link only -- no routing
  • Seeing this = DHCP problem

Broadcast

255.255.255.255

Limited broadcast

  • Sent to all hosts on local network
  • Used by DHCP Discover
  • Routers do not forward broadcasts

Exam Tip

If a user's IP starts with 169.254, the device could not reach a DHCP server. Check network cable, DHCP server status, and relay agents.

Public vs Private IP Addresses

RFC 1918 and the Need for NAT

Private IP Ranges (RFC 1918)

Reserved for internal use. Not routable on the public internet.

Class Range CIDR
A 10.0.0.0 - 10.255.255.255 /8
B 172.16.0.0 - 172.31.255.255 /12
C 192.168.0.0 - 192.168.255.255 /16

Public IP Addresses

Globally unique, routable on the internet. Assigned by ISPs and managed by regional registries (IANA → RIRs).

  • Every public IP must be unique worldwide
  • IPv4 public addresses are nearly exhausted
  • This is why NAT and IPv6 exist

How to Tell?

If the address falls in 10.x.x.x, 172.16-31.x.x, or 192.168.x.x -- it is private. Everything else (that isn't reserved) is public.

NAT & PAT

Translating Private Addresses to Public

How NAT Works

Types of NAT

  • Static NAT: One-to-one mapping (private → public)
  • Dynamic NAT: Pool of public IPs, first-come-first-served
  • PAT (Port Address Translation): Many-to-one using port numbers

PAT (Overloading)

The most common form. Your home router uses PAT -- all devices share one public IP, distinguished by unique source port numbers.

192.168.1.10:52345 → 203.0.113.5:52345 192.168.1.20:49871 → 203.0.113.5:49871 192.168.1.30:60112 → 203.0.113.5:60112

IPv6 Overview

The 128-Bit Address Space

IPv6 Structure

128-bit addresses written as eight groups of four hexadecimal digits.

2001:0db8:85a3:0000:0000:8a2e:0370:7334
  • 340 undecillion addresses (3.4 x 10^38)
  • No need for NAT -- every device gets a unique IP
  • Built-in IPSec support
  • No broadcast -- uses multicast instead

Shortening Rules

  • Drop leading zeros in each group
  • Replace one consecutive group of all-zero groups with ::
  • :: can only be used once per address
Full: 2001:0db8:0000:0000:0000:0000:0000:0001 Short: 2001:db8::1

Key IPv6 Addresses

  • ::1 -- Loopback (like 127.0.0.1)
  • fe80:: -- Link-local (like APIPA)
  • ff00:: -- Multicast
  • 2000::/3 -- Global unicast (routable)

MAC Addresses & ARP

Physical Addressing and Layer 2 Resolution

MAC Address

48-bit hardware address burned into the NIC. Unique to each physical interface.

AA:BB:CC:DD:EE:FF
OUI (vendor) | Device ID
  • First 3 bytes = OUI (manufacturer ID)
  • Last 3 bytes = unique device identifier
  • Written in hexadecimal
  • Layer 2 (Data Link) addressing

ARP -- Address Resolution Protocol

Maps IP addresses (Layer 3) to MAC addresses (Layer 2).

ARP Spoofing: An attacker can send fake ARP replies to redirect traffic (man-in-the-middle). Mitigated with Dynamic ARP Inspection (DAI) on switches.

IP Configuration Commands

Viewing and Verifying Your Settings

Windows

C:\> ipconfig IPv4 Address: 192.168.1.100 Subnet Mask: 255.255.255.0 Gateway: 192.168.1.1 C:\> ipconfig /all (shows DNS, DHCP, MAC, etc.) C:\> ipconfig /release (releases DHCP lease) C:\> ipconfig /renew (requests new DHCP lease) C:\> arp -a (shows ARP cache table)

Linux / macOS

$ ip addr show (modern Linux IP config) $ ifconfig (legacy, still common) $ ip route (show routing / gateway) $ cat /etc/resolv.conf (DNS configuration) $ arp -n (show ARP cache) $ dhclient -r && dhclient (release + renew DHCP)

Exam Tip: Know the difference between ipconfig (Windows) and ifconfig/ip (Linux). Both show IP, mask, and gateway -- different syntax.

Week 3 Summary -- Network Configuration

Key Takeaways

Addressing

  • IPv4: 32-bit, dotted decimal
  • IPv6: 128-bit, hexadecimal
  • MAC: 48-bit, Layer 2 hardware
  • CIDR replaces classful addressing

Configuration

  • Static: manual, for servers/infra
  • DHCP: automatic, for endpoints
  • Gateway: router to other networks
  • DNS: name-to-IP resolution

Key Concepts

  • Private (RFC 1918) vs public IPs
  • NAT/PAT: private-to-public translation
  • ARP: IP-to-MAC resolution
  • APIPA: 169.254.x.x = DHCP failure
