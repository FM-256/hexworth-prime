What Is a Port?
IP addresses find the machine. Ports find the service on that machine.
Key Concept
A port is a 16-bit number (0-65535) that identifies a specific process or service on a host. The combination of an IP address and a port number is called a socket (e.g., 192.168.1.10:443). Think of the IP as the building's street address and each port as a different door into that building.

TCP vs UDP
Two transport protocols, two very different philosophies.
TCP — Transmission Control Protocol
Connection-oriented. Establishes a session before sending data. Guarantees delivery through acknowledgments and retransmissions. Orders packets using sequence numbers so data arrives intact. Used when accuracy matters more than speed.
Examples: HTTP, HTTPS, FTP, SSH, SMTP, POP3, IMAP
UDP — User Datagram Protocol
Connectionless. Fires and forgets — no handshake, no acknowledgments. Faster because there is no session overhead. No ordering guarantees. Lost packets stay lost. Used when speed matters more than perfect delivery.
Examples: DNS (queries), DHCP, TFTP, SNMP, VoIP, streaming
Slide 4 of 14
TCP 3-Way Handshake
Before any TCP data flows, both sides must agree to communicate.
Remember: SYN, SYN-ACK, ACK. Only TCP does this. UDP skips it entirely and starts sending data immediately. The handshake adds latency but guarantees both sides are ready.

POP3 vs IMAP
POP3 (110): Downloads mail to one device and typically removes it from the server. Simple, offline access. IMAP (143): Keeps mail on the server, synchronizes across all devices. Modern email apps use IMAP.

Port Ranges
65,536 possible ports, divided into three official categories by IANA.
Well-Known Ports
0 – 1023
Reserved for standard services (HTTP, SSH, DNS). Assigned by IANA. Require root/admin to bind on most OS.
Registered Ports
1024 – 49151
Used by vendor applications (SQL Server 1433, MySQL 3306, RDP 3389). Registered with IANA but not strictly enforced.
Dynamic / Ephemeral
49152 – 65535
Temporary source ports assigned by the OS for outbound connections. Recycled after the session ends. Never manually assigned.

HTTP & HTTPS
The protocols that power the web. One is plaintext. One is encrypted.
HTTP — Port 80
HyperText Transfer Protocol. Request-response model between browser and server. Unencrypted — anyone on the path can read the data. Still used on internal networks, but never for login forms or sensitive data.
HTTPS — Port 443
HTTP + TLS encryption. Same request-response model, but wrapped in a secure tunnel. Requires a digital certificate from a Certificate Authority (CA). Modern browsers mark HTTP sites as "Not Secure."
Slide 9 of 14
FTP, SSH & SFTP
File transfer and secure remote access — the workhorses of system administration.
FTP — Port 21 (+ 20)
File Transfer Protocol. Port 21 is the control channel (commands). Port 20 is the data channel (active mode). Unencrypted — credentials sent in plaintext. Legacy protocol; replaced by SFTP in modern environments.
SSH — Port 22
Secure Shell. Encrypted remote command-line access. Replaces Telnet (port 23). Uses public-key or password authentication. Also provides port forwarding and tunneling capabilities.
SFTP — Port 22
SSH File Transfer Protocol. Runs over the SSH tunnel on port 22. Encrypted file transfer — the secure replacement for FTP. Single port (no separate data channel needed).
Slide 10 of 14
DNS & DHCP
Name resolution and automatic IP assignment — the two services every network depends on.
DNS — Port 53 (UDP + TCP)
Domain Name System. Translates human-readable names (google.com) to IP addresses (142.250.80.46). Standard queries use UDP 53 for speed. Zone transfers between DNS servers use TCP 53 for reliability. Without DNS, you would need to memorize IP addresses.
DHCP — Ports 67/68 (UDP)
Dynamic Host Configuration Protocol. Automatically assigns IP address, subnet mask, default gateway, and DNS server. Server listens on UDP 67. Client responds on UDP 68. Process: DORA — Discover, Offer, Request, Acknowledge.
Slide 11 of 14
Email Protocols: SMTP, POP3, IMAP
Sending vs. receiving — three protocols that handle every email.
Key distinction: SMTP (port 25) is for sending. POP3 (110) and IMAP (143) are for receiving. Secure variants exist: SMTPS (587), POP3S (995), IMAPS (993) — all use TLS encryption.

Why This Matters
When you configure a firewall, you write rules at Layer 4 (port numbers) to control Layer 7 (applications). When you troubleshoot, you work from the bottom up: physical link first, then IP, then transport, then application.

Scenario: Firewall Port Rules
Applying what you know — which ports do you open for a web + mail server?
You are configuring the firewall for a small business. They run a public website, an email server, and need SSH access for remote administration. Which inbound ports must you allow?
Principle of Least Privilege: Only open the ports you actually need. Every open port is a potential attack surface. Block everything by default, then allow specific services.

Ports & Protocols: Solved
Key Takeaways
1 A port is a 16-bit number (0-65535) that identifies a service on a host. IP + port = socket.
2 TCP is connection-oriented (reliable, ordered). UDP is connectionless (fast, no guarantees).
3 TCP connection starts with the 3-way handshake: SYN, SYN-ACK, ACK.
4 Memorize: 21 FTP, 22 SSH, 25 SMTP, 53 DNS, 80 HTTP, 110 POP3, 143 IMAP, 443 HTTPS, 3389 RDP.
5 Three port ranges: Well-Known (0-1023), Registered (1024-49151), Dynamic/Ephemeral (49152-65535).
6 Firewalls use port numbers to allow or block traffic. Only open what you need.
Back to our opening scenario: the web server is unreachable because the firewall does not have port 443 (HTTPS) or port 80 (HTTP) open for inbound traffic. Add the rule, verify the service is listening, and users can connect.
