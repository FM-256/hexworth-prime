ping

The Most Basic Connectivity Test

What ping Does

Sends ICMP Echo Request packets to a target and measures if (and how fast) they reply.

  • Uses ICMP protocol (not TCP or UDP)
  • Tests basic reachability
  • Measures round-trip time (latency)
  • Reports packet loss percentage

Troubleshooting Order

  1. ping 127.0.0.1 (loopback -- is TCP/IP working?)
  2. ping own IP (is NIC working?)
  3. ping default gateway (can I reach the router?)
  4. ping remote IP (can I reach the internet?)
  5. ping domain name (is DNS working?)

Example Output

C:\> ping 8.8.8.8 Pinging 8.8.8.8 with 32 bytes of data: Reply from 8.8.8.8: bytes=32 time=12ms TTL=118 Reply from 8.8.8.8: bytes=32 time=11ms TTL=118 Reply from 8.8.8.8: bytes=32 time=13ms TTL=118 Reply from 8.8.8.8: bytes=32 time=12ms TTL=118 Ping statistics: Packets: Sent = 4, Received = 4, Lost = 0 Approximate round trip times: Minimum = 11ms, Maximum = 13ms, Average = 12ms

Note

Some hosts and firewalls block ICMP. A failed ping does not always mean the host is down -- it may just be filtering ICMP traffic.

traceroute / tracert

Mapping the Path to a Destination

How It Works

Sends packets with incrementing TTL values. Each router that decrements TTL to 0 sends back an ICMP Time Exceeded message, revealing its IP address.

Example

C:\> tracert 8.8.8.8 1 1 ms 1 ms 1 ms 192.168.1.1 2 10 ms 11 ms 10 ms 10.0.0.1 3 15 ms 14 ms 15 ms 72.14.204.68 4 12 ms 12 ms 11 ms 8.8.8.8 Trace complete.

Windows vs Linux

OS Command Protocol
Windows tracert ICMP
Linux/macOS traceroute UDP (default)

Use case: Identifying where in the path a connection fails or slows down. If hop 3 times out but hop 4 works, the issue is near hop 3.

ipconfig / ifconfig / ip

Viewing and Managing Network Configuration

Windows: ipconfig

C:\> ipconfig IPv4 Address: 192.168.1.100 Subnet Mask: 255.255.255.0 Default Gateway: 192.168.1.1 C:\> ipconfig /all (full details: MAC, DNS, DHCP, etc.) C:\> ipconfig /release (release current DHCP lease) C:\> ipconfig /renew (request new DHCP lease) C:\> ipconfig /flushdns (clear DNS resolver cache) C:\> ipconfig /displaydns (show cached DNS entries)

Linux: ip / ifconfig

$ ip addr show (show all interfaces and IPs) $ ip link show (show link state up/down) $ ip route show (show routing table / gateway) $ ifconfig (legacy, shows IP/mask/MAC) $ ifconfig eth0 down (disable interface) $ ifconfig eth0 up (enable interface)

ip is the modern replacement for ifconfig on Linux. Both work but ip is preferred and more powerful.

nslookup / dig

DNS Query Tools

nslookup (Windows & Linux)

C:\> nslookup google.com Server: dns.local Address: 192.168.1.1 Non-authoritative answer: Name: google.com Addresses: 142.250.80.46 2607:f8b0:4004:800::200e C:\> nslookup -type=MX google.com (query MX records) C:\> nslookup google.com 8.8.8.8 (use specific DNS server)

dig (Linux / macOS)

$ dig google.com ;; ANSWER SECTION: google.com. 243 IN A 142.250.80.46 $ dig google.com MX (query MX records) $ dig @8.8.8.8 google.com (use specific DNS server) $ dig google.com +short 142.250.80.46 (just the answer)

Exam Tip: nslookup is available on both Windows and Linux. dig is the more detailed tool preferred on Linux. Both test DNS resolution independent of the browser.

netstat / ss

Network Connections and Listening Ports

What netstat Shows

Displays active network connections, listening ports, routing tables, and interface statistics.

C:\> netstat -an Proto Local Address Foreign Address State TCP 0.0.0.0:80 0.0.0.0:0 LISTENING TCP 192.168.1.100:443 52.165.41.10:49832 ESTABLISHED TCP 192.168.1.100:445 0.0.0.0:0 LISTENING UDP 0.0.0.0:53 *:* C:\> netstat -b (shows which process owns each connection) C:\> netstat -r (shows routing table, same as route print)

Key Flags

Flag Purpose
-a All connections and listening ports
-n Numeric output (no DNS resolution)
-b Show owning process (Windows)
-t TCP connections only (Linux)
-u UDP connections only (Linux)
-r Routing table

Linux: ss (Socket Statistics)

Modern replacement for netstat on Linux. Faster and more detailed.

$ ss -tlnp (TCP listening ports with process names)

nmap Basics

Network Discovery and Port Scanning

What nmap Does

Scans networks to discover hosts, open ports, running services, and OS versions. The industry standard for network reconnaissance.

$ nmap 192.168.1.0/24 (discover all hosts on the subnet) $ nmap -sV 192.168.1.50 (detect service versions) $ nmap -O 192.168.1.50 (OS detection) $ nmap -p 80,443,22 192.168.1.50 (scan specific ports only) $ nmap -sn 192.168.1.0/24 (ping sweep -- host discovery only)

Common Scan Types

Flag Type Description
-sT TCP Connect Full TCP handshake
-sS SYN Scan Half-open, stealthier
-sU UDP Scan Scans UDP ports
-sn Ping Sweep Host discovery only
-sV Version Service/version detection

Legal Warning

Never scan networks you don't own or have written permission to test. Unauthorized port scanning may violate computer fraud laws.

Cable Testing Tools

Physical Layer Diagnostics

Cable Tester

Hardware
  • Verifies pin-to-pin continuity
  • Detects opens, shorts, crossed pairs
  • Tests T568A/B wiring standards
  • Simple pass/fail for basic cables

When to use: After terminating a new cable or when a cable connection is suspected of failure.

Cable Certifier

Hardware
  • Full performance testing
  • Measures crosstalk, attenuation, delay
  • Certifies cable meets Cat5e/6/6a specs
  • Required for compliance documentation
  • Expensive ($2,000-$15,000+)

TDR / OTDR

Hardware
  • TDR: Time Domain Reflectometer (copper)
  • OTDR: Optical TDR (fiber)
  • Sends signal and measures reflection
  • Finds exact distance to breaks/faults
  • Essential for long cable runs

Tone Generator, Loopback Plug, & Crimpers

Essential Physical Tools

Tone Generator & Probe

Hardware
  • Two-piece tool (toner + probe)
  • Toner injects signal on one end
  • Probe detects tone at the other end
  • Traces cables through walls/ceilings
  • Identifies unlabeled cable runs

Also called a "fox and hound" tester.

Loopback Plug

Hardware
  • Redirects transmit pins to receive pins
  • Tests NIC hardware without a network
  • If loopback test passes, NIC is functional
  • Available for RJ-45, fiber, serial
  • Simple, inexpensive diagnostic

Crimpers & Punchdown

Hardware
  • Crimper: Attaches RJ-45 connectors to cable
  • Must follow T568A or T568B standard
  • Punchdown tool: Terminates wires in patch panels and wall jacks
  • 110-type blocks are most common
  • Wire strippers: Remove jacket without nicking wires

Wi-Fi Analyzer

Wireless Network Assessment

What It Shows

Scans and visualizes wireless networks in the area. Essential for troubleshooting Wi-Fi performance and planning deployments.

  • SSID names and signal strength (dBm)
  • Channel usage and overlap
  • Security type (Open, WPA2, WPA3)
  • Frequency band (2.4 GHz, 5 GHz, 6 GHz)
  • Noise floor and signal-to-noise ratio

Common Tools

  • Wi-Fi Analyzer (Android app)
  • inSSIDer (Windows/macOS)
  • Ekahau / Acrylic (enterprise heat maps)
  • NetSpot (site survey tool)

Channel Interference

In 2.4 GHz, only channels 1, 6, and 11 are non-overlapping. Using other channels causes co-channel interference.

Troubleshooting Tips

  • Weak signal? Check distance and obstacles
  • Slow speeds? Check for channel congestion
  • Intermittent drops? Look for interference sources (microwaves, Bluetooth)

Wireshark -- Protocol Analyzer

Deep Packet Inspection

What Wireshark Does

Captures and analyzes every packet on a network interface in real time. The industry-standard protocol analyzer (packet sniffer).

  • Captures all traffic on the selected interface
  • Decodes protocols layer by layer
  • Powerful display filters
  • Color-coded by protocol type
  • Can save captures as .pcap files

Common Filters

ip.addr == 192.168.1.100 (traffic to/from this IP) tcp.port == 443 (HTTPS traffic) dns (all DNS queries/responses) http.request.method == "GET" (HTTP GET requests) tcp.flags.syn == 1 (TCP SYN packets -- new connections)

Packet Anatomy in Wireshark

Frame (Layer 1)
Raw bytes, timing, interface info
Ethernet (Layer 2)
Source/destination MAC addresses
IP (Layer 3)
Source/destination IP, TTL, protocol
TCP/UDP (Layer 4)
Ports, flags, sequence numbers
Application (Layer 7)
HTTP, DNS, SMTP payload data

Privacy: Packet captures can contain sensitive data (passwords, personal info). Only capture traffic you are authorized to inspect.

Speed Tests & Bandwidth Tools

Measuring Network Performance

Web-Based Speed Tests

  • Speedtest.net (Ookla) -- most popular
  • fast.com (Netflix) -- simple, streaming-focused
  • speed.cloudflare.com -- includes jitter and loaded latency

These measure:

  • Download speed (Mbps)
  • Upload speed (Mbps)
  • Latency/Ping (ms)
  • Jitter (variation in latency)

Command-Line Tools

$ iperf3 -s (start iperf server on one end) $ iperf3 -c 192.168.1.50 (test bandwidth to the server) $ speedtest-cli (run Ookla speedtest from terminal)

iperf3

Tests bandwidth between two points on your network (LAN or WAN). Unlike web speed tests, it measures your internal network performance, not just ISP speed.

Best Practice: Run speed tests at different times of day to identify peak congestion. Use wired connections for accurate baseline measurements.
