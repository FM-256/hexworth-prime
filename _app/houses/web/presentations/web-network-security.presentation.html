Security Fundamentals for Network+

Confidentiality

Only authorized parties can access data. Enforced by encryption, access controls, VPNs.

Integrity

Data is not altered in transit or at rest without detection. Enforced by hashing (SHA), digital signatures.

Availability

Systems are accessible when needed. Enforced by redundancy, DDoS mitigation, failover.

Defense in Depth

Multiple layers of security controls — if one layer is bypassed, others remain. Physical, perimeter, network, host, application, and data layers.

  • No single point of security failure
  • Attacker must defeat multiple independent controls

Principle of Least Privilege

Users, systems, and processes should have only the minimum access rights needed to perform their function. Reduces the blast radius of a compromise.

  • Applied to user accounts, service accounts, firewall rules, API keys

Firewall Types

Packet Filter (Stateless)

Inspects each packet in isolation — checks source/destination IP, port, and protocol against ACLs. No awareness of connection state.

  • Fast, low overhead
  • Vulnerable to IP spoofing and fragmentation attacks
  • Cannot distinguish established vs. new connections

Stateful Inspection

Tracks the state of active connections in a state table. Packets are evaluated in context of their connection.

  • Allows return traffic automatically for established connections
  • Better than stateless — can detect out-of-state packets
  • The current standard minimum for firewalls

Application-Layer (Proxy) Firewall

Operates at Layer 7. Full protocol awareness — understands HTTP, FTP, SMTP. Can inspect content within packets.

  • Can block specific URLs, file types, commands
  • Higher latency than stateful inspection

Next-Generation Firewall (NGFW)

Combines stateful inspection with deep packet inspection (DPI), application awareness, and user identity integration.

  • Application identification (not just port/protocol)
  • User-based policies — block Facebook for specific users
  • Integrated IPS/IDS
  • TLS inspection (decrypts and re-encrypts HTTPS)
  • Threat intelligence feeds
  • Vendors: Palo Alto, Fortinet, Check Point, Cisco FTD

WAF — Web Application Firewall

Specialized Layer 7 firewall protecting web applications. Blocks OWASP Top 10 attacks: SQL injection, XSS, CSRF, etc.

  • Sits in front of web servers
  • Cloud WAF: AWS WAF, Cloudflare, Akamai
  • On-premise: ModSecurity, F5 ASM

Firewall Placement & DMZ Architecture

DMZ — Demilitarized Zone

A network segment between the internet and the internal network. Public-facing servers (web, mail, DNS) are placed in the DMZ — accessible from outside but isolated from the internal LAN.

Dual-Firewall DMZ (Recommended)

Two firewalls — one between Internet and DMZ, one between DMZ and LAN. Attacker must compromise two independent firewalls to reach internal systems. Preferred architecture for high-security environments.

Single-Firewall DMZ (Three-Legged)

One firewall with three interfaces: Internet, DMZ, Internal. Simpler and cheaper, but firewall is a single point of failure. Common in SMB environments.

ACLs on Routers/Switches

Standard ACL

Filters based on source IP address only. No port or protocol awareness. Numbered 1–99 and 1300–1999 (Cisco). Apply close to destination.

Extended ACL

Filters on source IP, destination IP, protocol, source port, and destination port. Much more granular. Numbered 100–199 and 2000–2699 (Cisco). Apply close to source.

Implicit Deny

ACLs and firewall rule sets end with an implicit "deny all" — any traffic not explicitly permitted is blocked. This is why the ORDER of rules matters. First match wins.

IDS vs. IPS

Feature IDS (Intrusion Detection System) IPS (Intrusion Prevention System)
Placement Out-of-band (passive tap/SPAN port) Inline — traffic flows through it
Response Detects and alerts only — cannot block Detects AND actively blocks malicious traffic
Latency impact None — not in traffic path Slight — all traffic inspected inline
False positive risk Low impact — only generates alert High impact — false positive blocks legitimate traffic
Best use case Compliance logging, forensics, low-risk monitoring Active threat prevention in production networks

Detection Methods

  • Signature-based: Matches known attack patterns — fast, low false positives, misses zero-days
  • Anomaly/Behavior-based: Baselines normal traffic, flags deviations — catches new attacks, higher false positives
  • Policy-based: Alerts when traffic violates defined security policy

NIDS vs. HIDS

  • NIDS (Network-based): Monitors network traffic — one sensor protects many hosts. Blind to encrypted traffic.
  • HIDS (Host-based): Agent on individual host — sees decrypted traffic and host activity. Scales poorly.
  • Hybrid: Both — network visibility + host telemetry

AAA — Authentication, Authorization, Accounting

Authentication

Who are you?

Verify identity with credentials: username/password, certificate, biometric, hardware token.

Factors: Something you know, have, are

Authorization

What can you do?

Once authenticated, determines what resources and operations are permitted. RBAC, ABAC, ACLs.

Least privilege: grant minimum needed

Accounting

What did you do?

Tracks and logs user activity for auditing, billing, and forensic purposes. Non-repudiation.

Creates audit trail for compliance

RADIUS

Remote Authentication Dial-In User Service. Centralizes AAA for network access (VPN, wireless, wired 802.1X).

  • UDP 1812 (authentication), UDP 1813 (accounting)
  • Encrypts only the password in the packet
  • Combines Authentication + Authorization in single response
  • Open standard — widely supported

TACACS+

Terminal Access Controller Access-Control System Plus. Cisco proprietary. Preferred for device administration (router/switch login).

  • TCP 49 — reliable transport
  • Encrypts the ENTIRE packet (more secure than RADIUS)
  • Separates Authentication, Authorization, Accounting
  • More granular command authorization (can permit/deny specific CLI commands)

802.1X Port-Based Authentication & NAC

802.1X Overview

IEEE standard for port-based Network Access Control. Devices must authenticate before being granted network access. Applies to both wired (switchports) and wireless.

Three Roles

  • Supplicant: The device trying to connect (laptop, phone) — runs 802.1X client software
  • Authenticator: The network device controlling access — switch or WAP. Passes credentials to authentication server using RADIUS.
  • Authentication Server: RADIUS server — validates credentials. Microsoft NPS, Cisco ISE, FreeRADIUS.

EAP Methods (Common)

  • EAP-TLS: Uses certificates on both client and server — most secure
  • PEAP: TLS tunnel wrapping MSCHAPv2 — common for username/password
  • EAP-FAST: Cisco — uses Protected Access Credentials (PAC)

NAC — Network Access Control

Expands 802.1X with posture assessment — checks device health before granting access.

NAC Posture Checks

  • Is antivirus installed and up to date?
  • Is the OS patched to a minimum version?
  • Is disk encryption enabled?
  • Is the device domain-joined?
  • Is required software installed?

NAC Enforcement Actions

  • Allow: Full network access — compliant device
  • Quarantine VLAN: Isolated network for remediation — can reach patch servers only
  • Deny: No access — non-compliant device blocked entirely
  • Guest VLAN: Internet-only for unknown devices

Zero Trust Architecture

The Old Model: Perimeter Trust

Traditional security assumed everything inside the network perimeter was trusted. Once inside the firewall, lateral movement was easy.

Why Perimeter Trust Failed

  • Cloud erased the perimeter — data lives everywhere
  • Remote work eliminated the "inside the office" assumption
  • Insider threats and compromised credentials bypass perimeter
  • Attackers who breach the perimeter have free rein internally

Zero Trust Core Principle

"Never Trust, Always Verify"

No implicit trust based on network location. Every access request is authenticated, authorized, and continuously validated regardless of where the request originates.

Zero Trust Pillars

Identity Verification

Every user and device must authenticate — strong MFA required. Identity is the new perimeter. Privileged access requires step-up authentication.

Micro-Segmentation

Network divided into small isolated zones. Even authenticated users only reach exactly what they need. East-west traffic filtered as rigorously as north-south.

Least Privilege Access

Just-in-time (JIT) and just-enough-access (JEA). Time-limited access grants. No standing privileged accounts.

Continuous Monitoring

Assume breach — continuously monitor behavior for anomalies. Re-verify sessions. Log everything. SIEM integration is critical.

Network Hardening Techniques

Switch Security

Port Security

Limits the number of MAC addresses allowed on a switchport. Prevents MAC flooding attacks.

  • Shutdown: Port goes err-disabled on violation (most secure)
  • Protect: Drops violating frames, no alert
  • Restrict: Drops frames and sends SNMP trap

DHCP Snooping

Prevents rogue DHCP servers. Only "trusted" ports (uplinks) can send DHCP offers. Untrusted ports (user-facing) only receive DHCP. Protects against DHCP starvation and spoofing attacks.

Dynamic ARP Inspection (DAI)

Validates ARP packets against DHCP snooping binding table. Prevents ARP spoofing/poisoning attacks that enable MITM. Requires DHCP snooping to be enabled first.

Additional Hardening Controls

Disable Unused Ports

Unoccupied switchports should be administratively shut down and placed in an unused VLAN. Prevents unauthorized device connections.

BPDU Guard

Shuts down a port that receives a BPDU (Bridge Protocol Data Unit). Protects STP topology from rogue switches connected to access ports. Should be enabled on all access ports with PortFast.

IP Source Guard

Filters packets based on source IP AND MAC address. Uses DHCP snooping binding table to validate. Prevents IP spoofing from clients.

Private VLANs (PVLANs)

Isolate hosts within the same VLAN from communicating with each other. Community ports can talk to each other and the promiscuous port. Isolated ports can only reach the promiscuous port.

Common Network Attacks

DoS / DDoS

Denial of Service / Distributed DoS. Overwhelms a target with traffic or requests, making it unavailable to legitimate users.

  • Volumetric: Bandwidth flood — UDP flood, ICMP flood (Ping of Death, Smurf)
  • Protocol: Exploits layer 3/4 — SYN flood (TCP half-open connections)
  • Application: HTTP flood, Slowloris — fewer packets, harder to detect
  • Mitigation: Scrubbing centers, rate limiting, blackhole routing

MITM — Man-in-the-Middle

Attacker intercepts communication between two parties who believe they're talking directly.

  • ARP Poisoning: Attacker sends fake ARP replies — traffic redirected through attacker
  • DNS Spoofing: Fake DNS responses redirect users to malicious sites
  • SSL Stripping: Downgrades HTTPS to HTTP
  • Mitigation: DAI, DNSSEC, HTTPS everywhere, HSTS

VLAN Hopping

Attacker bypasses VLAN isolation to access traffic from another VLAN.

  • Switch Spoofing: Attacker's device negotiates as a trunk link using DTP — sees all VLANs. Mitigation: disable DTP on access ports (switchport nonegotiate).
  • Double Tagging: Attacker tags frame with two VLAN tags — outer tag stripped, inner tag delivers to target VLAN. Mitigation: native VLAN must not match any user VLANs.

MAC Flooding

Attacker sends thousands of frames with fake MAC addresses — fills switch CAM table. Switch falls back to hub behavior, flooding all ports. Attacker captures traffic with a sniffer.

Mitigation: Port security, limiting MAC addresses per port.

Rogue AP / Evil Twin

Unauthorized AP on the network. Evil Twin broadcasts the same SSID as legitimate AP to intercept credentials. Mitigation: wireless IDS, 802.1X on all APs, rogue AP detection.

Wireless Security — Quick Reference

Protocol Encryption Authentication Key Length Status
WEP RC4 (stream) Open / Shared Key 40/104-bit Broken — never use
WPA TKIP (RC4) PSK or 802.1X 128-bit Deprecated
WPA2-Personal AES-CCMP PSK (passphrase) 128-bit Current, vulnerable to PMKID
WPA2-Enterprise AES-CCMP 802.1X + EAP (RADIUS) 128-bit Current, recommended for enterprise
WPA3-Personal AES-GCMP-256 SAE (Simultaneous Auth of Equals) 192-bit Current, strongest personal
WPA3-Enterprise AES-GCMP-256 802.1X + EAP + TLS 1.3 192-bit Current, strongest enterprise

WPA3 Improvements

  • SAE replaces 4-way handshake — resistant to offline dictionary attacks
  • Forward Secrecy — past sessions not decryptable even if key compromised later
  • OWE (Opportunistic Wireless Encryption) for open networks

Wireless Threats to Know

  • Deauthentication flood — forces clients to reconnect (captures handshake for WPA2 cracking)
  • PMKID attack — offline WPA2 PSK cracking without capturing handshake
  • KRACK attack — WPA2 key reinstallation vulnerability (patched)

VPN Types & Encryption in Network Security

SSL/TLS VPN

Uses TLS (port 443 TCP) — same protocol as HTTPS. Very firewall-friendly; rarely blocked.

  • Clientless SSL VPN: Browser-based, no software required. Accesses web apps only.
  • SSL VPN Client: Full tunnel, all traffic encrypted. Cisco AnyConnect, GlobalProtect, OpenVPN.

PKI and Certificates

Digital Certificates

Bind a public key to an identity. Signed by a Certificate Authority (CA) — trusted third party.

  • X.509 standard — format for digital certificates
  • Contains: Subject, Public Key, Issuer (CA), Validity period, Signature
  • TLS handshake uses certificate to authenticate server

Certificate Revocation

  • CRL: Certificate Revocation List — downloaded periodically, can be stale
  • OCSP: Online Certificate Status Protocol — real-time check, more current
  • OCSP Stapling: Server pre-fetches OCSP response and includes in TLS handshake — reduces latency

Key Exchange

Diffie-Hellman (DH): Allows two parties to establish a shared secret over an insecure channel without transmitting the secret itself. Used in IPSec IKE and TLS key negotiation.

Security Monitoring & Deception Technologies

Honeypot

A decoy system designed to attract and detect attackers. Appears to contain valuable data or services but is isolated and monitored. Any access to a honeypot is inherently suspicious.

  • Low-interaction: Simulates limited services — safer, less intelligence gathered
  • High-interaction: Full real system — attacker has real environment, more intelligence gathered but more risk
  • Honeynet: Network of honeypots — more complex deception environment

Honeypot Uses

  • Early detection — attackers touch honeypot before reaching real systems
  • Intelligence gathering — understand attacker TTPs (tactics, techniques, procedures)
  • Legal: gives time to trace and document attacker activity
  • Threat research and malware analysis

SIEM — Security Information and Event Management

Aggregates, correlates, and analyzes log data from across the environment in real time.

  • Collects: firewall logs, IDS/IPS alerts, AAA logs, Windows event logs, netflow
  • Correlates events to detect complex attacks (lateral movement, brute force + exfil)
  • Generates alerts and tickets for SOC analysts
  • Products: Splunk, IBM QRadar, Microsoft Sentinel, Elastic SIEM

NetFlow for Security

Records metadata about network conversations — source/dest IP, port, protocol, byte counts, timing. Not full packet capture — lightweight and scalable.

  • Detect port scans, beaconing malware, data exfiltration
  • Baseline normal traffic patterns
  • sFlow is sampling-based alternative

Threat Intelligence Feeds

External lists of known malicious IPs, domains, hashes. NGFW and SIEM consume these to automatically block or alert on known threats. STIX/TAXII are standards for sharing threat intelligence.

Exam Focus: Network Security

Q: A switch is experiencing MAC flooding attacks — attackers are filling the CAM table. Which switch security feature limits the number of MAC addresses learned on a port?

A: Port Security — limits MAC addresses per port and shuts down the port on violation.

Q: Which AAA protocol encrypts the ENTIRE packet and is typically preferred for router/switch management access?

A: TACACS+ — encrypts the entire payload; uses TCP port 49. RADIUS only encrypts the password.

Q: A company wants to check that devices have updated antivirus before granting full network access. What technology provides this?

A: NAC (Network Access Control) — performs posture assessment and places non-compliant devices in a quarantine VLAN.

Q: An IDS is detecting attacks but not blocking them. A manager wants blocking. What should be implemented instead?

A: IPS (Intrusion Prevention System) — placed inline, actively blocks malicious traffic.

Q: Which STP protection feature shuts down a port if a BPDU is received on an access port?

A: BPDU Guard — protects against rogue switches being connected to access ports.

Q: WPA3-Personal replaces the 4-way handshake with which authentication method that resists offline dictionary attacks?

A: SAE — Simultaneous Authentication of Equals (also known as Dragonfly handshake).

Network Security Summary

Firewalls

Stateless, Stateful, NGFW, WAF — each layer adds more intelligence. DMZ isolates public-facing servers.

Detection

IDS (passive/alert) vs IPS (inline/block). Signature vs anomaly detection. HIDS vs NIDS.

Access Control

AAA, RADIUS (UDP 1812), TACACS+ (TCP 49), 802.1X, NAC posture checks, Zero Trust.

Key Takeaways for N10-009 Domain 4

  • Stateful firewall tracks connection state; stateless does not — stateful is the modern minimum
  • IDS = detect + alert (passive); IPS = detect + block (inline)
  • RADIUS: UDP 1812/1813, encrypts password only; TACACS+: TCP 49, encrypts everything
  • 802.1X: Supplicant + Authenticator + Authentication Server (RADIUS)
  • NAC = 802.1X + posture assessment — quarantine VLAN for non-compliant devices
  • Zero Trust: never trust, always verify — no implicit trust from network location
  • DHCP Snooping + DAI work together to prevent DHCP attacks and ARP poisoning
  • BPDU Guard protects STP by shutting down access ports that receive BPDUs
  • WPA3 uses SAE — resistant to offline dictionary attacks unlike WPA2-PSK
