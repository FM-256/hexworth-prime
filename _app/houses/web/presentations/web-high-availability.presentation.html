High Availability & Disaster Recovery

CompTIA Network+ N10-009 | Domain 3: Network Operations (18%)

High Availability

Redundant systems, links, and devices that keep services running when individual components fail

Disaster Recovery

Plans and procedures to restore services after a major disruptive event

Business Continuity

Maintaining critical business functions during and after a disaster — broader than just IT recovery

Key Principle

HA prevents downtime. DR recovers from downtime. Both are required for resilient infrastructure.

Availability & SLA Targets

The Nines of Availability

Availability is expressed as a percentage of uptime in a year. Each additional "9" represents a 10x reduction in downtime.

99% (2 nines) 87.6 hours downtime/year
99.9% (3 nines) 8.76 hours downtime/year
99.99% (4 nines) 52.6 minutes downtime/year
99.999% (5 nines) 5.26 minutes downtime/year
99.9999% (6 nines) 31.5 seconds downtime/year

SLA Components

Uptime Guarantee

The contractual availability commitment. Violations typically result in service credits. Most enterprise services target 99.9% to 99.999%.

Recovery Objectives

  • RTO (Recovery Time Objective): Maximum acceptable time to restore service after failure. "How long can we be down?"
  • RPO (Recovery Point Objective): Maximum acceptable data loss measured in time. "How much data can we afford to lose?" — defines backup frequency.
  • RTO and RPO drive architecture decisions: lower = more expensive

RTO vs RPO Example

RTO = 4 hours: Service must be restored within 4 hours of failure.

RPO = 1 hour: Backups must occur at least every hour — at most 1 hour of transactions can be lost.

Network Redundancy Strategies

Link Redundancy

Dual Links (EtherChannel/LACP)

Bundle multiple physical links into one logical link. Provides both redundancy AND increased bandwidth. IEEE 802.3ad — LACP (Link Aggregation Control Protocol).

  • If one physical link fails, remaining links continue carrying traffic
  • Traffic load-balanced across all active links
  • Cisco calls this EtherChannel; also called LAG (Link Aggregation Group)

Redundant Uplinks with STP

Multiple uplinks from access to distribution switches. STP blocks redundant paths to prevent loops — only one active path at a time. Fast convergence: RSTP (802.1w) converges in <1 second vs STP's 50 seconds.

Dual-Homed Servers

Servers with two NICs connected to two different switches. NIC teaming (bonding) provides failover: if one switch fails, the other NIC continues. Mode: active-passive or active-active.

Device Redundancy

FHRP — First Hop Redundancy Protocols

Multiple gateways share a virtual IP address. Clients point to the virtual IP — if the active gateway fails, a standby gateway takes over seamlessly.

  • HSRP (Cisco): Hot Standby Router Protocol — active/standby model. Uses multicast 224.0.0.2.
  • VRRP (IEEE): Virtual Router Redundancy Protocol — open standard, functionally similar to HSRP
  • GLBP (Cisco): Gateway Load Balancing Protocol — adds load balancing across multiple active gateways

Redundant Power

  • Dual PSUs: Two power supplies in one device — if one fails, the other continues. Different power circuits for true redundancy.
  • UPS: Uninterruptible Power Supply — battery backup bridges gap during power failure
  • Generator: Long-term power backup for extended outages
  • PDUs: Redundant power distribution units in racks

Load Balancing

What is Load Balancing?

Distributes incoming traffic across multiple servers or network paths. Achieves two goals simultaneously: scalability (handle more load) and availability (no single point of failure).

Load Balancing Algorithms

  • Round Robin: Distributes requests sequentially to each server in turn. Simple, no awareness of server load.
  • Weighted Round Robin: More powerful servers get proportionally more requests based on their weight value.
  • Least Connections: New requests go to the server with the fewest active connections. Better for long-lived sessions.
  • IP Hash: Same client IP always goes to the same server — session persistence (sticky sessions).
  • Random: Random server selection — simple but uneven under low load.

Load Balancer Types

Layer 4 Load Balancer (Transport)

Routes based on IP address and TCP/UDP port. Fast — no application inspection. Cannot route based on URL paths or HTTP headers. Example: AWS NLB, HAProxy TCP mode.

Layer 7 Load Balancer (Application)

Full HTTP/HTTPS inspection. Routes based on URL path, hostname, HTTP headers, cookies. Enables content-based routing:

  • /api/* → API servers
  • /static/* → CDN or static server farm
  • app1.example.com → App1 cluster

Also handles SSL termination, health checks, and session persistence. Example: AWS ALB, F5 BIG-IP, NGINX.

Health Checks

Load balancer continuously verifies backend servers are healthy. Failed servers are removed from rotation automatically — restored when healthy again. Monitors: TCP port open, HTTP 200 response, application-level probe.

Data Redundancy & RAID

RAID — Redundant Array of Inexpensive Disks

Combines multiple physical disks to improve performance, fault tolerance, or both.

RAID Level Method Min Disks Can Lose
RAID 0 Striping (no redundancy) 2 0 — any failure = all data lost
RAID 1 Mirroring 2 1 disk (as long as one mirror survives)
RAID 5 Striping with distributed parity 3 1 disk
RAID 6 Striping with dual parity 4 2 disks simultaneously
RAID 10 Striping + Mirroring 4 1 disk per mirror pair

RAID Notes for Exam

RAID 0 — No Fault Tolerance

Stripes data across all disks for maximum performance. Zero redundancy — any single disk failure loses ALL data. Use only where performance matters more than data safety (temp scratch disks, rendering).

RAID 1 — Simple Mirror

Identical copy on two disks. Reads can be load-balanced (faster reads). Writes must go to both (no write speed benefit). 50% usable capacity.

RAID 5 — Most Common

Good balance of performance, redundancy, and cost. Parity spread across all disks. Survives single disk failure — degraded performance during rebuild. Rebuild time on large disks creates risk of second failure (use RAID 6 for large disks).

RAID 10 — Best of Both

Mirrors first, then stripes across mirrors. Best performance + good redundancy. Used for high-performance databases. 50% usable capacity (same as RAID 1).

Backup Strategies

Backup Types

Type What is Backed Up Speed Recovery Complexity
Full Everything — all data Slowest backup Simplest — one backup set
Incremental Changed since LAST backup (full OR incremental) Fastest daily backup Complex — need full + all incrementals
Differential Changed since LAST FULL backup only Medium Easier — need full + latest differential only
Snapshot Point-in-time copy (CoW/RoW) Near-instant Simple — restore to snapshot point

3-2-1 Backup Rule

  • 3 copies of data
  • 2 different storage media types
  • 1 copy offsite (or in cloud)

Backup Media & Locations

On-Site Backups

  • Fast restore — data is local
  • Vulnerable to same physical disaster (fire, flood, theft)
  • NAS, SAN, tape library, disk-to-disk

Off-Site Backups

  • Protects against site-level disaster
  • Slower restore — must transfer data from remote site or cloud
  • Options: cloud backup (AWS S3 Glacier, Azure Backup), co-location facility, vaulted tape rotation

Backup Testing

Untested backups are not backups — they are hopes. Must regularly verify:

  • Backup jobs complete without errors
  • Data integrity — restore a sample of files
  • Full restore test — at least quarterly for critical systems
  • RTO achievable — can you actually restore within the SLA?

Disaster Recovery Sites

Cold Site

Facility with power, cooling, and connectivity — but NO equipment pre-installed. Hardware must be purchased/delivered and configured from scratch after disaster.

  • Lowest cost
  • Recovery time: days to weeks
  • Suitable for non-critical systems with high RTO

Warm Site

Facility with hardware pre-installed and powered on, but systems not running production workloads. Must restore from backup — takes hours to days.

  • Medium cost
  • Recovery time: hours to days
  • Most common enterprise DR site type

Hot Site

Fully operational mirror of production — systems running, data continuously replicated. Failover can occur in minutes.

  • Highest cost (essentially double infrastructure)
  • Recovery time: minutes to hours
  • Required for mission-critical systems

Cloud DR

Modern alternative to physical DR sites. Replicate to cloud (AWS, Azure). "Warm standby" in cloud is much cheaper than maintaining a physical warm site — pay for storage, not running compute. Scale up resources during actual DR event.

Geographic Considerations

  • DR site must be far enough to avoid the same regional disaster (hurricane, earthquake, flood zone)
  • But close enough that staff can travel there
  • Typical recommendation: 50–100+ miles away from primary site
  • Different power grid and telecom providers

Business Continuity Planning (BCP)

BCP Framework

Business Continuity Planning ensures the organization can continue critical operations during and after disruption. Broader than IT DR — includes people, processes, vendors.

Business Impact Analysis (BIA)

Identifies critical business functions and the impact of their disruption. Key outputs:

  • Which systems are critical?
  • What is the financial/operational impact of each hour of downtime?
  • What are the dependencies between systems?
  • Drives RTO/RPO for each system

DR Plan Components

  • Activation criteria — what triggers the DR plan?
  • Escalation contacts and communication tree
  • Step-by-step recovery procedures for each critical system
  • Vendor contacts and SLAs
  • Return to normal operations procedures

Testing DR Plans

Tabletop Exercise

Discussion-based walkthrough of the DR plan. Key stakeholders discuss responses to a hypothetical scenario. No systems affected. Low cost, identifies gaps in planning.

Functional Exercise (Walkthrough)

Team rehearses specific procedures without activating the actual DR site. Verify personnel know their roles and can execute procedures.

Full-Scale DR Test (Parallel / Cutover)

  • Parallel test: Bring up DR site alongside production — verify it works without switching over
  • Cutover test: Actually fail over to DR site — most complete test, highest risk. Typically done with advance notice and a planned maintenance window.

How Often to Test

Tabletop: quarterly. Functional: semi-annually. Full-scale: annually minimum. After major infrastructure changes — re-test.

Power Redundancy & Environmental Controls

Power Protection Layers

Surge Protector

Basic protection against voltage spikes (surges) from lightning strikes or utility switching. Does NOT protect against power outages. Minimum requirement for any equipment.

UPS — Uninterruptible Power Supply

Battery backup for short-duration power failures. Types:

  • Standby (offline): Switches to battery only when power fails — brief transfer time (ms)
  • Line-interactive: Regulates voltage (AVR) — better protection, handles brownouts
  • Online (double-conversion): Equipment always runs off battery/inverter — no transfer time, cleanest power. Used for critical systems.

Generator

Provides power for extended outages — hours to days. Typically diesel or natural gas. Takes 10–30 seconds to start — UPS bridges this gap. Critical for data centers and hospitals.

Environmental Controls

Cooling Systems

  • CRAC: Computer Room Air Conditioning — precision-controlled datacenter cooling
  • Hot/Cold aisle containment: Alternating hot-exhaust and cold-intake aisles in server racks — prevents hot air recirculation
  • ASHRAE standards: Recommended data center inlet temperature: 64.4°F–80.6°F (18–27°C)

Fire Suppression

  • Halon (legacy): Effective but ozone-depleting — prohibited in new installs
  • FM-200 / Novec 1230: Modern clean agent — does not damage equipment, safe for occupied spaces
  • Pre-action sprinkler: Requires both heat AND smoke detection before water releases — reduces accidental discharge
  • Never use standard water sprinklers near electrical equipment

Physical Security

  • Mantrap/airlock entry — prevents tailgating
  • Biometric access + badge access for server room
  • CCTV monitoring and recording
  • Cable locks for portable equipment

Clustering & Virtualization High Availability

Server Clustering

Active-Passive Cluster

One node handles all traffic; standby node monitors and takes over on failure. Failover happens automatically in seconds. Simple but standby node's resources are idle during normal operation.

  • Common for databases (SQL, Oracle), email (Exchange DAG)
  • Shared storage (SAN) accessible by both nodes

Active-Active Cluster

Multiple nodes each handle traffic simultaneously. Load balanced across all nodes. If one fails, remaining nodes absorb its load. Better resource utilization than active-passive.

  • Web servers, application servers, DNS
  • Requires stateless design or shared session store

Virtualization HA Features

VMware HA

If a hypervisor host fails, VMs automatically restart on surviving hosts in the cluster. Restart takes 1–3 minutes. Requires shared storage (SAN/NFS) accessible by all hosts.

vMotion / Live Migration

Move a running VM from one hypervisor host to another with zero downtime. Used for planned maintenance — drain VMs off a host before taking it down. Requires shared storage and fast network (10 GbE minimum).

VMware FT (Fault Tolerance)

Creates a live shadow copy of a VM running synchronously on a second host. If primary fails, shadow takes over with zero data loss — not just restarts. Highest VM HA tier, highest resource overhead. Use for zero-tolerance critical VMs.

Fault Tolerance Concepts

Single Points of Failure (SPOF)

Any component whose failure causes a system outage. HA design systematically identifies and eliminates SPOFs.

Common SPOFs in Networks

  • Single internet connection (single ISP)
  • Single core/distribution switch
  • Single firewall
  • Single power feed to a rack
  • Single DNS server
  • Single uplink from access to distribution layer

Rule: Anything with "single" in front of it is a SPOF.

Failover vs Failback

  • Failover: Automatic or manual switch from primary to secondary/standby system after failure
  • Failback: Returning to primary system after it is restored — can be automatic or manual (prefer manual to avoid flip-flopping)

Graceful Degradation

System continues to operate at reduced capacity after partial failure rather than failing completely. Examples:

  • SD-WAN: if MPLS fails, traffic continues over broadband (slower but functional)
  • RAID 5: continues operating (degraded) with one failed disk
  • Load balancer: removes failed server, distributes load across remaining servers

Five 9s Design Principles

  • Eliminate single points of failure at every layer
  • Geographic redundancy for site-level failures
  • Automated failover — humans are too slow
  • Regular testing — HA that hasn't been tested doesn't exist
  • Monitor everything — detect failures before users do

Exam Focus: High Availability & DR

Q: A company requires that service is restored within 2 hours of a failure, and can tolerate no more than 30 minutes of data loss. What are their RTO and RPO?

A: RTO = 2 hours (maximum recovery time); RPO = 30 minutes (maximum data loss — requires backups at least every 30 minutes).

Q: A RAID 5 array has 4 disks. How many disks can fail without data loss?

A: 1 disk. RAID 5 tolerates a single disk failure. For 2-disk fault tolerance, RAID 6 is required.

Q: What type of disaster recovery site has hardware pre-installed and powered on, but requires a backup restore — with a recovery time measured in hours?

A: Warm site. Cold = no hardware (days to weeks); Hot = fully synchronized (minutes).

Q: Multiple default gateways on a LAN must share one virtual IP address for client failover. Which protocol family covers this?

A: FHRP — First Hop Redundancy Protocol. Options: HSRP (Cisco), VRRP (open standard), GLBP (Cisco with load balancing).

Q: A daily full backup is taken on Sunday. Incremental backups run Monday–Saturday. A failure occurs Saturday. How many backup sets are needed to restore?

A: 7 backup sets — the Sunday full backup + incrementals for Mon, Tue, Wed, Thu, Fri, Sat. (This is why differential recovery is simpler: only full + latest differential.)

Q: A company wants to run a DR test where the DR site is brought up and verified without affecting production. What type of test is this?

A: Parallel test — both production and DR run simultaneously for verification without cutting over.

High Availability & DR Summary

Redundancy

EtherChannel/LACP, FHRP (HSRP/VRRP/GLBP), dual ISPs, dual PSUs, UPS + generator

Recovery

RTO = time to restore; RPO = data loss tolerance. Cold/Warm/Hot sites. 3-2-1 backup rule.

Testing

Tabletop, functional, parallel, cutover. Untested DR plans are not reliable plans.

Key Takeaways for N10-009 Domain 3

  • RTO = how long to restore; RPO = how much data loss is acceptable — drives backup frequency
  • 5 nines (99.999%) = 5.26 minutes downtime per year; 4 nines = 52.6 minutes
  • FHRP: HSRP (Cisco), VRRP (open standard), GLBP (Cisco with load balancing)
  • RAID 0 = no redundancy; RAID 1 = mirror; RAID 5 = 1 disk fault tolerant; RAID 6 = 2 disk; RAID 10 = best performance + redundancy
  • Incremental backs up changes since last backup (any); Differential backs up since last FULL
  • 3-2-1 rule: 3 copies, 2 media types, 1 offsite
  • Cold site = cheapest/slowest; Hot site = most expensive/fastest recovery
  • Parallel test = both sites run at once; Cutover test = actually fail over to DR
  • Active-passive cluster = one active, one standby; Active-active = both serving load
