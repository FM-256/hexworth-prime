Cloud Service Models

IaaS — Infrastructure as a Service

Rent virtualized hardware: VMs, storage, networking. You manage the OS up.

  • AWS EC2, Azure VMs, GCP Compute Engine
  • Full OS control, patch responsibility on you
  • Most flexible, most responsibility

PaaS — Platform as a Service

Rent a managed platform for app deployment. Provider manages OS and runtime.

  • AWS Elastic Beanstalk, Azure App Service, Heroku
  • Focus on code, not infrastructure
  • Less control, less maintenance

SaaS — Software as a Service

Use a fully managed application. Provider handles everything.

  • Microsoft 365, Google Workspace, Salesforce
  • No infrastructure concerns
  • Least control, least responsibility

Shared Responsibility Model

  • IaaS: You own OS, apps, data
  • PaaS: You own apps and data only
  • SaaS: You own data only (mostly)
  • Provider always owns: physical hardware, hypervisor, network fabric

Virtualization Fundamentals

What is Virtualization?

Creating software-based abstractions of physical resources. Multiple virtual machines (VMs) share a single physical host.

Type 1 Hypervisor (Bare-Metal)

Runs directly on hardware — no host OS required.

  • VMware ESXi, Microsoft Hyper-V, KVM
  • Better performance, used in data centers
  • The standard for production environments

Type 2 Hypervisor (Hosted)

Runs on top of a host OS — convenience over performance.

  • VMware Workstation, VirtualBox, Parallels
  • Easy for testing and development
  • Higher overhead than Type 1

VM Networking Concepts

Virtual Switch (vSwitch)

Software-defined switch inside the hypervisor. Connects VMs to each other and to physical NICs.

Network Modes

  • Bridged: VM gets its own IP on the physical network
  • NAT: VM shares host IP, gets private address
  • Host-Only: VM can only talk to the host
  • Internal: VMs talk only to each other

VM Benefits

  • Server consolidation — fewer physical machines
  • Rapid provisioning and cloning
  • Snapshot and rollback capability
  • Live migration (vMotion)

Containers vs. Virtual Machines

Feature Virtual Machine Container
Isolation level Full OS isolation — each VM has its own kernel Process isolation — shares host OS kernel
Boot time Minutes (full OS boot) Seconds (start a process)
Size GBs (includes full OS) MBs (just app + dependencies)
Density Tens per host Hundreds per host
Security boundary Stronger — full kernel separation Weaker — kernel escape risks
Use case Legacy apps, full OS required, strong isolation Microservices, CI/CD, cloud-native apps
Technology VMware, Hyper-V, KVM Docker, Podman, Kubernetes

Container Networking

Containers use virtual networks (bridge, overlay, host, macvlan) managed by Docker/Kubernetes. Kubernetes uses CNI plugins (Calico, Flannel, Weave) to manage pod-to-pod networking across nodes.

Software-Defined Networking (SDN)

Traditional vs. SDN

In traditional networking, the control plane (routing decisions) and data plane (packet forwarding) are tightly coupled inside each device.

SDN decouples them — centralizing control in a software controller.

SDN Architecture Layers

  • Application Layer: Network apps, security policies, analytics — communicate via northbound API
  • Control Layer: SDN Controller (OpenDaylight, ONOS, Cisco APIC) — the brain
  • Infrastructure Layer: Physical/virtual switches/routers — forward packets per controller instructions via southbound API (OpenFlow)

SDN Benefits

  • Centralized network management from a single console
  • Programmable infrastructure — push config changes via API
  • Dynamic traffic engineering and load balancing
  • Rapid policy deployment across all devices
  • Vendor-agnostic control

NFV — Network Functions Virtualization

Replace dedicated hardware appliances (firewalls, load balancers, WAN optimizers) with software running on standard servers.

  • Virtual firewall (vFW)
  • Virtual load balancer (vLB)
  • Virtual router (vRouter)
  • Reduces hardware costs significantly

Virtual Private Cloud (VPC)

What is a VPC?

A logically isolated network inside a public cloud. You control the IP address ranges, subnets, route tables, and gateways — just like a traditional network, but software-defined in the cloud.

VPC Core Components

  • Subnets: Divide the VPC into segments (public, private, isolated)
  • Route Tables: Control traffic flow between subnets and to/from the internet
  • Internet Gateway: Connects the VPC to the public internet
  • NAT Gateway: Allows private subnet instances to reach the internet without being reachable from outside
  • Security Groups: Stateful virtual firewalls at the instance level
  • NACLs: Stateless firewall rules at the subnet level

VPC Connectivity Options

VPC Peering

Private connection between two VPCs — traffic stays on the cloud backbone, never traverses the internet. Non-transitive: A peered to B, B peered to C, does NOT mean A can reach C.

VPN Gateway

Encrypted IPSec tunnel over the internet from your on-premises network to the VPC. Lower cost, higher latency than dedicated circuits.

Direct Connect / ExpressRoute

Dedicated private circuit from your data center to the cloud provider. Consistent bandwidth, lower latency, higher cost. Does NOT traverse the internet.

Transit Gateway

Hub-and-spoke model to connect multiple VPCs and on-premises networks through a single managed gateway. Solves VPC peering non-transitivity.

Cloud Storage & Network Services

Storage Types in Cloud

Block Storage

Presents raw volumes to VMs — behaves like a physical disk. High IOPS, low latency. Examples: AWS EBS, Azure Managed Disks.

Object Storage

Stores unstructured data as objects (files, images, backups). Massive scale, REST API access. Examples: AWS S3, Azure Blob, GCP Cloud Storage.

File Storage (NAS in cloud)

Shared file system accessed over NFS or SMB. Examples: AWS EFS, Azure Files. Used for shared app data across multiple instances.

Cloud Network Services

DNS (Cloud-Based)

AWS Route 53, Azure DNS, Google Cloud DNS — highly available, global authoritative DNS. Supports health checks and traffic routing policies.

CDN — Content Delivery Network

Caches content at edge locations globally to reduce latency for end users. Examples: AWS CloudFront, Azure CDN, Cloudflare.

Load Balancers

  • Layer 4 (Transport): Routes based on IP/port — TCP/UDP load balancer
  • Layer 7 (Application): Routes based on HTTP headers, URL paths — Application Load Balancer

Network Automation & Infrastructure as Code

Why Automation Matters

Manual configuration does not scale in cloud and SDN environments. Automation ensures consistency, speed, and repeatability.

Configuration Management Tools

  • Ansible: Agentless, YAML playbooks, uses SSH. Most common for network automation.
  • Puppet / Chef: Agent-based, more complex, used for server config
  • Terraform: Infrastructure as Code (IaC) — declare cloud resources in HCL, provider-agnostic

APIs in Networking

  • REST API: HTTP-based, JSON/XML — used by most cloud providers and SDN controllers
  • NETCONF: XML-based protocol for device config (RFC 6241)
  • RESTCONF: REST-like access to NETCONF data models
  • gRPC: High-performance binary protocol, used by OpenConfig

Data Formats

JSON — JavaScript Object Notation. Human-readable, widely used in REST APIs.

{"interface": "Gi0/0", "ip": "192.168.1.1", "mask": "255.255.255.0"}

YAML — Preferred for configuration files and Ansible playbooks. More readable than JSON for multi-line configs.

interface: Gi0/0 ip: 192.168.1.1 mask: 255.255.255.0

XML — Used by NETCONF/RESTCONF. Verbose but schema-validatable.

Cloud Security Concepts

Cloud Security Controls

Identity & Access Management (IAM)

Controls who can do what in your cloud environment. Principle of least privilege — grant only the permissions needed.

  • Users, Groups, Roles, Policies
  • MFA enforcement for privileged accounts
  • Service accounts for automation

Encryption in Cloud

  • At rest: Data encrypted on disk — AES-256 standard
  • In transit: TLS for all data moving between services
  • Key management: AWS KMS, Azure Key Vault — manage encryption keys separately from data

Cloud Threat Landscape

Common Cloud Risks

  • Misconfiguration: #1 cloud breach cause — open S3 buckets, permissive security groups
  • Insecure APIs: Exposed management interfaces
  • Insufficient IAM: Overprivileged accounts, no MFA
  • Shared tenancy risks: VM escape, side-channel attacks
  • Account hijacking: Phishing for cloud console credentials

Cloud Security Tools

  • CSPM: Cloud Security Posture Management — finds misconfigs
  • CASB: Cloud Access Security Broker — monitors SaaS usage
  • WAF: Web Application Firewall — layer 7 protection
  • Security Hub / Defender: Centralized cloud security alerts

Cloud Characteristics: Elasticity, Scalability & Availability

Elasticity

Automatic scaling up AND down in real time based on demand. Resources are provisioned and released dynamically.

Auto Scaling Groups, horizontal pod autoscaling

Scalability

Ability to handle increased load. Two types:

  • Vertical (Scale Up): Add CPU/RAM to existing VM — limited ceiling
  • Horizontal (Scale Out): Add more instances — preferred for cloud-native apps

High Availability

Design for uptime. Cloud availability zones are physically separate data centers within a region.

  • Availability Zone (AZ): Isolated data center — protects from local failure
  • Region: Geographic area with multiple AZs
  • Multi-AZ deployments survive AZ failure

CAPEX vs. OPEX

CAPEX (Capital Expenditure): Upfront purchase of physical hardware — servers, switches, cabling. High initial cost, depreciated over time. Traditional data center model.

OPEX (Operating Expenditure): Ongoing subscription-based spending — cloud services billed monthly. Predictable, scales with usage. Cloud model converts CAPEX to OPEX.

SD-WAN: Software-Defined Wide Area Network

What is SD-WAN?

Applies SDN principles to WAN connectivity. A centralized controller manages traffic routing policies across multiple WAN links (MPLS, broadband, LTE/5G).

Traditional WAN Pain Points

  • Expensive MPLS circuits with long provisioning times
  • All traffic must backhaul through headquarters
  • Static routing — no dynamic path selection
  • Manual configuration on each router

SD-WAN Advantages

  • Use any WAN transport (MPLS + Internet + LTE)
  • Dynamic path selection based on latency, jitter, loss
  • Direct cloud breakout from branch — no backhauling Office 365 traffic
  • Centralized policy management — change all sites at once
  • Significant cost savings vs. MPLS-only

SD-WAN Architecture

Key Components

  • SD-WAN Controller: Central orchestration — defines policies
  • SD-WAN Edge Devices: CPE at each site — enforce policies, measure link quality
  • Orchestrator: Management plane — zero-touch provisioning of new sites
  • vBond: (Cisco SDWAN) — authenticates and connects edge devices to controller

Vendors

  • Cisco Viptela / Catalyst SD-WAN
  • VMware VeloCloud
  • Fortinet Secure SD-WAN
  • Silver Peak (HPE Aruba)
  • Palo Alto Prisma SD-WAN (CloudGenix)

Exam Tip: Direct Connect vs. VPN

Direct Connect provides consistent performance and does not traverse the internet. VPN is cheaper but shares the internet. For compliance-heavy scenarios (healthcare, finance), Direct Connect/ExpressRoute is typically required.

Exam Focus: Cloud & Virtualization

Q: A company wants to run VMs with the lowest overhead and best performance. Which hypervisor type should they use?

A: Type 1 (bare-metal) hypervisor — runs directly on hardware, no host OS overhead.

Q: Which cloud model gives the customer the MOST control over the operating system?

A: IaaS — customer manages OS, middleware, and applications.

Q: An organization needs dedicated, private network connectivity from its data center to AWS. The connection must not traverse the public internet. Which solution should be used?

A: AWS Direct Connect (or Azure ExpressRoute for Azure).

Q: What SDN layer does the OpenFlow protocol operate at?

A: The southbound API layer — between the SDN controller and network devices.

Q: Which cloud characteristic automatically adjusts resource capacity in real time based on demand — provisioning AND de-provisioning?

A: Elasticity (not just scalability — elasticity implies automatic two-way adjustment).

Q: VPC A is peered with VPC B. VPC B is peered with VPC C. Can VPC A communicate with VPC C?

A: No — VPC peering is non-transitive. A direct peering connection between A and C is required.
