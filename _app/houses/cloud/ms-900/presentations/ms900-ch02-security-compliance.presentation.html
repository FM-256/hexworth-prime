Microsoft Entra ID
Cloud-based identity and access management -- the foundation of every Microsoft 365 security decision.
Identity Provider
Microsoft Entra ID is the identity provider for all Microsoft cloud services. Every user who signs into M365, Azure, Dynamics 365, or any integrated SaaS app authenticates through Entra ID. It supports cloud-only accounts and hybrid accounts synced from on-premises Active Directory via Entra Connect.
Single Sign-On (SSO)
One identity, one sign-in, access to thousands of applications. Entra ID supports SAML, OAuth 2.0, OpenID Connect, and WS-Federation. The Enterprise Application gallery has thousands of pre-integrated SaaS apps. Users sign in once and access all their applications without re-entering credentials.
Entra ID Plans
Free tier included with M365 -- basic user management and SSO. P1 (included in E3/Business Premium) adds Conditional Access, dynamic groups, and self-service password reset. P2 (included in E5) adds Identity Protection and Privileged Identity Management (PIM).

MFA and Conditional Access
Multi-factor authentication and risk-based access policies -- the two most impactful security controls in M365.
Multi-Factor Authentication
MFA requires two or more verification factors: something you know (password), something you have (phone/security key), or something you are (biometric). Microsoft Authenticator app provides push notifications, time-based one-time passwords, and passwordless sign-in. MFA blocks 99.9% of account compromise attacks.
Conditional Access
If/then policies that evaluate signals (user, device, location, app, risk level) and make access decisions (allow, block, require MFA, require compliant device). Requires Entra ID P1 or higher. Common policies: require MFA for admins, block legacy authentication, require compliant devices for sensitive apps.
Security Defaults
Free baseline security for all tenants. Requires MFA registration for all users, challenges admins with MFA on every sign-in, and blocks legacy authentication protocols. Enabled by default on new tenants. Organizations with Conditional Access should disable security defaults and create explicit policies instead.

Zero Trust Security Model
Never trust, always verify. Assume breach. Verify explicitly. Use least privilege access.
Zero Trust is the security philosophy behind all modern Microsoft 365 security features. Conditional Access policies implement "verify explicitly." Privileged Identity Management implements "least privilege." Defender suite implements "assume breach" by continuously monitoring for threats. The MS-900 exam tests your understanding of these three principles.
Identity is the Perimeter
In Zero Trust, the network perimeter is gone. Identity becomes the control plane. Every access request is authenticated and authorized regardless of where it originates -- corporate network, home Wi-Fi, or coffee shop. This is why MFA and Conditional Access are the highest-priority security investments.
Pillars of Zero Trust
Microsoft defines six pillars: Identities (Entra ID), Devices (Intune), Applications (Defender for Cloud Apps), Data (Purview/sensitivity labels), Infrastructure (Azure security), and Networks (network segmentation). M365 addresses identities, devices, applications, and data directly.
Microsoft Implementation
Conditional Access = verify explicitly. PIM = least privilege. Defender XDR = assume breach (detect, investigate, respond). Information Protection = protect data at rest and in transit. Together, they form a complete Zero Trust implementation that the MS-900 exam expects you to understand.

Microsoft 365 Defender
Unified threat protection across endpoints, email, identity, and cloud applications.
Defender for Endpoint
Endpoint detection and response (EDR) for Windows, macOS, Linux, iOS, and Android. Threat and vulnerability management identifies unpatched software. Attack surface reduction rules block common attack vectors. Automated investigation and remediation handles threats without analyst intervention.
Defender for Office 365
Protects email and collaboration tools. Safe Attachments detonates suspicious files in sandboxes. Safe Links rewrites URLs to check them at click time. Anti-phishing policies use ML to detect impersonation. Plan 1 provides protection; Plan 2 adds investigation tools, attack simulation, and automated response.
Defender for Identity
Monitors on-premises Active Directory signals to detect advanced threats, compromised identities, and malicious insider actions. Detects lateral movement, pass-the-hash, and pass-the-ticket attacks. Integrates with Entra ID Identity Protection for unified risk scoring across cloud and on-premises.
Defender for Cloud Apps
Cloud Access Security Broker (CASB) that provides visibility into SaaS app usage, governs data access, detects anomalous behavior, and enforces session controls. Discovers shadow IT -- apps employees use without IT approval. Integrates with Conditional Access for real-time session monitoring.

Microsoft Purview
Unified data governance, compliance, and risk management across Microsoft 365 and beyond.
Sensitivity Labels
Classify and protect documents and emails with labels like Confidential, Internal, or Public. Labels can enforce encryption, watermarks, headers/footers, and access restrictions. Labels travel with the document -- protection follows the data even when shared externally.
Data Loss Prevention
DLP policies detect and block sharing of sensitive information like credit card numbers, Social Security numbers, or health records. Policies apply across Exchange, SharePoint, OneDrive, Teams chat, and endpoints. Policy tips warn users before they accidentally share sensitive data.
Retention + eDiscovery
Retention policies ensure data is kept for required periods and deleted when no longer needed. Litigation holds preserve all content for legal proceedings. eDiscovery searches across mailboxes, SharePoint, Teams, and OneDrive to find relevant content for investigations.

Information Protection
Know your data, protect your data, prevent data loss -- the three pillars of Microsoft Information Protection.
Know Your Data
Sensitive information types detect patterns (credit cards, SSNs). Trainable classifiers use ML to identify document categories. Content explorer shows where sensitive data lives across M365. Data classification dashboard gives an organization-wide view.
Protect Your Data
Sensitivity labels apply encryption and visual markings. Azure Information Protection scanner finds sensitive files on-premises. Auto-labeling policies apply labels without user interaction. Double Key Encryption gives you full control of encryption keys.
Prevent Data Loss
DLP policies block sharing of sensitive content. Endpoint DLP controls copy, print, and upload of labeled files. Policy tips educate users in real time. Alerts notify compliance teams of policy violations. Reports track DLP incidents over time.
Govern Your Data
Retention labels mark individual items for retention or deletion. Retention policies apply broadly to locations (all Exchange mailboxes, all SharePoint sites). Records management handles regulatory record-keeping with immutable storage.
Insider Risk
Insider Risk Management detects potentially risky user activities -- data theft by departing employees, accidental data leaks, policy violations. Communication Compliance monitors messages for inappropriate content, regulatory violations, and code of conduct breaches.
Compliance Manager
Compliance Manager calculates a compliance score across 400+ regulations (GDPR, HIPAA, ISO 27001). Provides improvement actions with step-by-step guidance. Tracks both Microsoft-managed controls and customer-managed controls in a single dashboard.

Microsoft Privacy Principles
Six privacy principles that govern how Microsoft handles customer data in all cloud services.
Control
You own your data. Microsoft provides tools to manage it. You decide who has access, where data is stored, and when it is deleted. Data portability lets you take your data if you leave the service.
Transparency
Microsoft publishes clear privacy statements, data processing agreements, and audit reports. You know what data is collected, how it is used, and who can access it. No hidden data practices.
Security
Industry-leading security protections. Encryption at rest and in transit. Physical datacenter security with biometric access. Regular penetration testing and security audits by internal teams and third parties.
Strong Legal Protections
Microsoft challenges government requests for customer data in court. Customer data is not provided to law enforcement unless required by law. Microsoft notifies you of requests unless legally prohibited from doing so.
No Content-Based Targeting
Microsoft does not use your email, chat, files, or other personal content to target advertising. Enterprise data stays private. This distinguishes M365 from consumer services that monetize user data.
Benefits to You
Data collected is used to improve your experience -- performance optimization, security threat detection, service reliability. Diagnostic data helps Microsoft identify and fix issues before they impact your organization.

Trust Center and Service Trust Portal
Where organizations verify Microsoft's security, compliance, and privacy commitments with documentation and audit reports.
Trust Center
Public-facing website that explains how Microsoft builds, operates, and secures its cloud services. Contains information about data residency, encryption, incident response, and compliance certifications. This is where you start when evaluating Microsoft cloud services for your organization.
Service Trust Portal
Authenticated portal providing actual audit reports, compliance documents, and pen test results. Requires sign-in with a Microsoft account. Access SOC reports, ISO certifications, and regional compliance documentation. Essential for security assessments and vendor due diligence.

Data Residency and Encryption
Where your data lives and how it is protected at rest and in transit.
Data Residency
Microsoft stores core customer data (Exchange mailboxes, SharePoint files, Teams messages) in the geographic region you select during tenant creation. Multi-Geo allows organizations to store data in multiple regions. Advanced Data Residency provides contractual commitments for specific data-at-rest locations.
Encryption at Rest
All customer data in M365 is encrypted at rest using BitLocker (volume-level) and service-level encryption. Each file in SharePoint/OneDrive is encrypted with a unique key. Customer Key lets you control the root encryption keys. Double Key Encryption keeps one key that Microsoft cannot access.
Encryption in Transit
All communication between clients and M365 services uses TLS 1.2+. Server-to-server communication within Microsoft datacenters is also encrypted. Perfect Forward Secrecy ensures that compromising one session key does not compromise historical traffic.
The MS-900 exam expects you to know that Microsoft encrypts data at rest and in transit by default, that customers can control encryption keys via Customer Key, and that data residency commitments keep core data in your selected geography. These are shared responsibility items -- Microsoft provides the encryption, but you decide the key management strategy.

Identity Protection and Privileged Access
Detect risky sign-ins automatically and enforce just-in-time admin access with PIM.
Identity Protection
Uses Microsoft's threat intelligence (trillions of signals daily) to detect compromised accounts. Risk-based Conditional Access policies can automatically require MFA or block access when a sign-in is flagged as risky. User risk policies can force password resets for compromised accounts. Integrated into the Entra admin center.
Privileged Identity Management
Eliminates standing admin access. Instead of permanently assigning Global Administrator, PIM makes users eligible -- they must activate the role when needed, with approval, justification, and a time limit. Access reviews regularly verify that people still need their roles. Audit logs track every activation.
