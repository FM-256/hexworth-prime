Module AUTH-04

JWT: JSON Web Tokens

JWTs are the most widely used structured token format in modern API authentication. This module covers the three-part structure, signing algorithms, validation logic, registered claims, and the critical security pitfalls that lead to real-world JWT exploits.

Learning Objectives
  • Decode and explain each part of a JWT (header, payload, signature)
  • Compare HMAC (HS256) vs RSA (RS256) vs ECDSA (ES256) signing algorithms
  • Implement server-side JWT validation with all required checks
  • Identify and defend against the "alg: none" and key confusion attacks
  • Design appropriate claims and expiration strategies for production APIs

JWT Structure: Three Parts

A JWT consists of three Base64URL-encoded segments separated by dots: header.payload.signature. Each segment serves a distinct purpose in the token's lifecycle.

Signing Algorithms

The choice of signing algorithm determines who can create tokens and who can verify them. This distinction is critical for security architecture.

AlgorithmTypeKey UsageUse Case
HS256Symmetric (HMAC)Same secret signs and verifiesSingle-service systems where issuer = verifier
RS256Asymmetric (RSA)Private key signs, public key verifiesMulti-service architectures, OIDC providers
ES256Asymmetric (ECDSA)Private key signs, public key verifiesSame as RS256 but smaller keys and signatures
PS256Asymmetric (RSA-PSS)Private key signs, public key verifiesEnhanced RSA with probabilistic padding
Symmetric (HMAC)

Fast and simple. The same secret is used to create and verify signatures. If the resource server knows the secret, it can also forge tokens. Only use when the auth server and resource server are the same system.

Asymmetric (RSA/ECDSA)

The private key stays on the authorization server. Resource servers only need the public key to verify tokens. They cannot forge new tokens. Preferred for distributed architectures.

JWT Security Attacks

Attack 1: Algorithm None

Some JWT libraries accept "alg": "none" in the header, which means no signature verification is performed. An attacker modifies the payload, sets the algorithm to "none", removes the signature, and the server accepts it as valid.

# Malicious JWT with "alg": "none" eyJhbGciOiJub25lIiwidHlwIjoiSldUIn0 // {"alg":"none","typ":"JWT"} . eyJzdWIiOiJhZG1pbiIsInJvbGUiOiJzdXBlcmFkbWluIn0 // {"sub":"admin","role":"superadmin"} . // Empty signature! # Defense: ALWAYS whitelist allowed algorithms const decoded = jwt.verify(token, publicKey, { algorithms: ['RS256'] // Explicit allowlist -- "none" is rejected });

Attack 2: Key Confusion (RS256 to HS256)

If a server is configured to accept both RS256 and HS256, an attacker can take the server's public RSA key (which is publicly available), craft a token signed with HS256 using that public key as the HMAC secret. The server's HS256 verification path will use the same public key as the HMAC secret and validate the forged token.

Key Confusion Defense

Never allow the algorithm to be determined solely by the JWT header. Enforce the expected algorithm per key on the server side. If you use RS256, reject any token with a different algorithm regardless of what the header says.

Attack 3: Weak HMAC Secrets

HS256 tokens signed with short or predictable secrets can be brute-forced offline. Tools like hashcat and jwt-cracker can test millions of secrets per second. Use secrets with at least 256 bits of entropy (32+ random bytes).

JWT Best Practices Summary

Short Expiration Times

Access tokens: 5-15 minutes. Limits damage window if token is stolen. Use refresh tokens for longer sessions.

Minimal Claims

Include only what the resource server needs. Sensitive data in JWTs is readable (Base64, not encrypted). Use JWE if payload confidentiality is required.

Use kid Header

Include a key ID in every JWT header to support key rotation. Resource servers can look up the correct verification key from JWKS.

Revocation Strategy

JWTs cannot be revoked once issued (stateless). Implement a token blocklist for critical revocations, or keep TTL short enough that revocation is unnecessary.
