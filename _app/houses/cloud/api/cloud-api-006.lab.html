Hints

                

                    
                    
                    
                    
                


                
                

                    
                    
BOLA (Broken Object Level Authorization) means the API doesn't verify that the requester owns the object they're requesting. Try fetching a different user's record than your own.

                    
                    
The endpoint is GET /api/users/{id}. You are authenticated as user ID 1. Try changing the ID to another value while keeping your valid token.

                    
                    
Send GET /api/users/2 with header X-Auth-Token: user-token-abc123. You are user 1 but you can read user 2's private data.

                


                
                

                    
                    
Admin endpoints are often only "protected" by a header check. The server may accept any non-empty token, or a predictable one, rather than validating role membership.

                    
                    
Call GET /api/admin/users. Try the header X-Admin-Token with obvious values: admin, true, 1, or the same user token.

                    
                    
Send GET /api/admin/users with X-Admin-Token: admin. The server does a simple string equality check and accepts "admin" as a valid token.

                


                
                

                    
                    
Path traversal exploits unsanitized file path parameters. By inserting ../ sequences, you can escape the intended upload directory and read files elsewhere on the server.

                    
                    
The server stores API configuration in a file called config.env one level above the uploads directory. Try navigating up with ../.

                    
                    
Send GET /api/files/../config.env. The server fails to normalize the path and reads the config file directly.

                


                
                

                    
                    
The POST /api/search endpoint passes the query field directly into a SQL LIKE clause without parameterization. User input reaches the database unescaped.

                    
                    
Start with a single quote: {"query": "'"}. A SQL error in the response confirms the injection point. Then try a union or tautology to extract data.

                    
                    
Send POST /api/search with body {"query": "' OR '1'='1"}. The tautology makes the WHERE clause always true, returning all records including the hidden admin entry.
