The WebSocket Handshake

WebSocket connections begin as a standard HTTP request with an Upgrade header. The server responds with HTTP 101 Switching Protocols, and from that point, the connection becomes a persistent, full-duplex channel. Both sides can send messages at any time without the overhead of HTTP headers on each message.

// Client handshake request GET /chat HTTP/1.1 Host: api.example.com Upgrade: websocket Connection: Upgrade Sec-WebSocket-Key: dGhlIHNhbXBsZSBub25jZQ== Sec-WebSocket-Version: 13 Sec-WebSocket-Protocol: chat, superchat Origin: https://example.com // Server handshake response HTTP/1.1 101 Switching Protocols Upgrade: websocket Connection: Upgrade Sec-WebSocket-Accept: s3pPLMBiTxaQ9kYGzzhZRbK+xOo= Sec-WebSocket-Protocol: chat

The Sec-WebSocket-Accept value is computed by concatenating the client's Sec-WebSocket-Key with the magic string 258EAFA5-E914-47DA-95CA-C5AB0DC85B11, then computing SHA-1 and base64 encoding the result. This proves the server understands the WebSocket protocol.

Frame Structure

After the handshake, communication happens via frames. Each frame has a small header (2-14 bytes) followed by the payload. This is far more efficient than HTTP, where headers alone can be 500+ bytes per request.

OpcodeTypePurpose
0x0ContinuationContinues a fragmented message
0x1TextUTF-8 text data
0x2BinaryBinary data (images, protobuf)
0x8CloseConnection close request
0x9PingHealth check from sender
0xAPongResponse to ping
Per-Message Compression: The permessage-deflate extension compresses WebSocket messages using zlib. This can reduce bandwidth by 60-80% for JSON payloads. Enable it with Sec-WebSocket-Extensions: permessage-deflate during handshake.

Heartbeats and Connection Health

TCP connections can silently die when intermediate proxies, NATs, or load balancers close idle connections. Ping/pong frames detect dead connections before they cause application-level failures.

// Server-side: ws library with ping/pong heartbeat const WebSocket = require('ws'); const wss = new WebSocket.Server({ port: 8080 }); wss.on('connection', (ws) => { ws.isAlive = true; ws.on('pong', () => { ws.isAlive = true; }); ws.on('message', (data) => { // Handle incoming messages const msg = JSON.parse(data); handleMessage(ws, msg); }); }); // Heartbeat: ping every 30 seconds, terminate dead connections const heartbeat = setInterval(() => { wss.clients.forEach((ws) => { if (!ws.isAlive) { console.log('Terminating dead connection'); return ws.terminate(); } ws.isAlive = false; ws.ping(); }); }, 30000);

Reconnection Strategies

WebSocket connections will drop -- network changes, server deployments, load balancer timeouts. Clients need automatic reconnection with exponential backoff to avoid thundering herd problems when many clients reconnect simultaneously.

// Client-side reconnection with exponential backoff class ReconnectingWebSocket { constructor(url) { this.url = url; this.reconnectDelay = 1000; // Start at 1 second this.maxDelay = 30000; // Cap at 30 seconds this.messageQueue = []; // Buffer during disconnect this.connect(); } connect() { this.ws = new WebSocket(this.url); this.ws.onopen = () => { this.reconnectDelay = 1000; // Reset on success // Flush queued messages while (this.messageQueue.length) { this.ws.send(this.messageQueue.shift()); } }; this.ws.onclose = (event) => { if (event.code !== 1000) { // Not a clean close this.scheduleReconnect(); } }; } scheduleReconnect() { const jitter = Math.random() * 1000; const delay = Math.min(this.reconnectDelay + jitter, this.maxDelay); setTimeout(() => this.connect(), delay); this.reconnectDelay *= 2; // Exponential backoff } send(data) { if (this.ws.readyState === WebSocket.OPEN) { this.ws.send(data); } else { this.messageQueue.push(data); } } }
Add Jitter: Random jitter (0-1 second) prevents the thundering herd effect where thousands of clients reconnect at exactly the same moment after a server restart. Without jitter, reconnection backoff is predictable and synchronized.

Key Takeaways

  • WebSocket upgrades from HTTP via 101 Switching Protocols handshake
  • Frames are lightweight (2-14 byte headers) compared to HTTP requests
  • Ping/pong heartbeats detect dead connections before they cause failures
  • Reconnection requires exponential backoff with random jitter
  • Message queuing during disconnection prevents data loss
  • permessage-deflate compression reduces bandwidth by 60-80% for JSON
