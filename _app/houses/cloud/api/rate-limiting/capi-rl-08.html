DDoS Attack Layers

Distributed Denial of Service attacks target APIs at multiple layers of the OSI model. Each layer requires different defenses. Application-layer (L7) attacks are the hardest to detect because they use legitimate-looking HTTP requests.

LayerAttack TypeVolumeDefense
L3/L4 (Network)SYN flood, UDP flood, amplification100+ GbpsISP scrubbing, CDN absorption
L7 (Application)HTTP flood, slowloris, API abuseLow bandwidth, high impactWAF, rate limiting, bot detection
L7 (Logic)Expensive queries, regex DoS, zip bombsSingle request can crashInput validation, timeouts, resource limits
Application-Layer DDoS: An attacker sends 50 requests/second to your /api/search?q=*&include=all&depth=10 endpoint. Each request triggers a full-text search across millions of records with deep object expansion. Your database connection pool is exhausted in seconds. This is a low-bandwidth, high-impact attack that looks like legitimate traffic.

WAF Integration for APIs

A Web Application Firewall inspects HTTP traffic and blocks malicious requests before they reach your application. For APIs, WAF rules need to be tailored to JSON/XML payloads rather than traditional HTML form inputs.

Request Size Limits Block oversized request bodies that could be zip bombs or buffer overflow attempts. Set max body size per endpoint (e.g., 1MB for uploads, 10KB for JSON).
JSON Schema Validation Reject requests with unexpected fields, wrong types, or deeply nested objects. A 100-level deep JSON object can crash parsers and consume excessive memory.
SQL/NoSQL Injection Rules Detect injection patterns in JSON values, query parameters, and headers. API payloads are just as vulnerable as form inputs to injection attacks.
Geo-Blocking Restrict API access by country or region. If your API only serves US customers, blocking traffic from known attack origin countries reduces the attack surface significantly.
// AWS WAF rule: Block requests with deeply nested JSON { "Name": "BlockDeepJSON", "Priority": 1, "Statement": { "SizeConstraintStatement": { "FieldToMatch": { "Body": {} }, "ComparisonOperator": "GT", "Size": 10240, "TextTransformations": [{ "Priority": 0, "Type": "NONE" }] } }, "Action": { "Block": {} } }

Bot Detection and Behavioral Analysis

Sophisticated attackers bypass simple rate limits by distributing requests across thousands of IPs. Bot detection uses behavioral signals to distinguish humans and legitimate integrations from automated attacks.

Request Pattern Analysis Legitimate clients show variable timing between requests. Bots often send requests at perfectly regular intervals or in predictable bursts. Measure inter-request timing variance.
Header Fingerprinting Real browsers send consistent header sets (Accept, Accept-Language, User-Agent). Bots often send minimal headers or inconsistent combinations. Flag requests missing expected headers.
API Key Anomaly Detection Track usage patterns per API key. Alert when a key suddenly makes 100x normal requests, accesses unusual endpoints, or requests from new geographic regions.
TLS Fingerprinting (JA3) The TLS handshake reveals the client library being used. Real browsers have unique JA3 fingerprints. Python requests, curl, and Go HTTP clients each have distinct signatures.
// Simple behavioral analysis middleware const clientBehavior = new Map(); function behaviorCheck(req, res, next) { const clientId = req.headers['x-api-key'] || req.ip; const now = Date.now(); if (!clientBehavior.has(clientId)) { clientBehavior.set(clientId, { times: [], endpoints: new Set() }); } const behavior = clientBehavior.get(clientId); behavior.times.push(now); behavior.endpoints.add(req.path); // Keep last 100 request timestamps if (behavior.times.length > 100) behavior.times.shift(); // Check for suspicious patterns if (behavior.times.length >= 10) { const intervals = []; for (let i = 1; i < behavior.times.length; i++) { intervals.push(behavior.times[i] - behavior.times[i-1]); } // Low variance = bot-like regularity const avg = intervals.reduce((a,b) => a+b) / intervals.length; const variance = intervals.reduce((s,v) => s + (v-avg)**2, 0) / intervals.length; const cv = Math.sqrt(variance) / avg; // coefficient of variation if (cv < 0.1 && avg < 500) { // Very regular, very fast = likely bot req.suspicionScore = (req.suspicionScore || 0) + 50; } } next(); }

Defense in Depth Strategy

No single defense stops all attacks. A layered approach ensures that if one layer is bypassed, the next catches the threat:

// Defense layers (outer to inner): // // 1. DNS/BGP - Anycast, GSLB, DNS-based filtering // 2. CDN/Edge - DDoS absorption, volumetric filtering // 3. WAF - Payload inspection, injection prevention // 4. Gateway - Rate limiting, API key validation // 5. App - Bot detection, behavioral analysis // 6. Data - Query limits, timeouts, resource caps // // Each layer logs to a SIEM for correlation and alerting. // Security team reviews alerts and adjusts rules.
Operational Note: DDoS protection must be tested before you need it. Schedule regular DDoS simulation exercises with your cloud provider. AWS Shield, Cloudflare, and Akamai all offer authorized testing programs. Do not wait for a real attack to discover your defenses have gaps.

Key Takeaways

  • L7 application-layer DDoS is the biggest threat to APIs -- low bandwidth, high impact
  • WAF rules must be tailored for JSON/API payloads, not just HTML forms
  • Bot detection uses behavioral signals: timing variance, header consistency, TLS fingerprints
  • Defense in depth: CDN, WAF, gateway, application, and data layer protections
  • Expensive query endpoints are prime DDoS targets -- add query complexity limits
  • Test your DDoS defenses before a real attack exposes gaps
