Module OWASP-07

API6:2023 -- Unrestricted Access to Sensitive Business Flows

This is a new category in the 2023 edition. It addresses APIs that expose business-critical operations without controls that prevent automated abuse. The individual API calls are legitimate, but when automated at scale, they cause business damage -- ticket scalping, mass fake account creation, inventory hoarding, and content scraping.

Learning Objectives
  • Identify sensitive business flows that are vulnerable to automated abuse
  • Distinguish this risk from traditional rate limiting (API4)
  • Analyze real-world business logic abuse scenarios
  • Implement anti-automation defenses: CAPTCHA, device fingerprinting, behavioral analysis
  • Design business flow rate controls that do not impact legitimate users

How This Differs from API4 (Rate Limiting)

API4 (Unrestricted Resource Consumption) addresses technical resource exhaustion -- CPU, memory, bandwidth. API6 addresses business logic abuse where each individual request is technically valid and within rate limits, but the aggregate behavior is harmful.

API4: Technical Abuse

10,000 requests/second overwhelm server. Defense: rate limit requests per IP/user. Impact: service availability.

API6: Business Logic Abuse

100 bots each buy 10 tickets (1000 total) within rate limits. Each purchase is valid. Defense: behavioral detection, purchase limits. Impact: business outcomes.

Anti-Automation Defenses

Layer 1: Flow-Level Rate Limits

// Limit purchases per user per event async function purchaseTicket(req, res) { const userId = req.user.sub; const eventId = req.body.eventId; // Check: max 4 tickets per user per event const existing = await db.purchases.count({ userId, eventId }); if (existing >= 4) { return res.status(429).json({ error: 'Purchase limit reached for this event' }); } // Check: account must be >24 hours old const accountAge = Date.now() - req.user.created_at; if (accountAge < 86400000) { return res.status(403).json({ error: 'New accounts cannot purchase during high-demand events' }); } // Process purchase... }

Layer 2: Device and Behavioral Signals

Device Fingerprinting

Collect browser/device characteristics (screen size, fonts, WebGL renderer). Detect when multiple "users" share the same device fingerprint. Flag headless browsers (Puppeteer, Playwright).

Behavioral Analysis

Human users browse, hesitate, scroll. Bots go directly to checkout. Measure time between page load and purchase. Flag sub-second checkout flows as suspicious.

Layer 3: CAPTCHA and Proof of Work

// Require CAPTCHA on sensitive business flows // Not on every request -- only on high-value actions POST /api/v1/checkout { "items": [...], "captcha_token": "03AGdBq24..." // reCAPTCHA/hCaptcha token } // Server verifies CAPTCHA before processing purchase const isHuman = await verifyCaptcha(req.body.captcha_token); if (!isHuman || isHuman.score < 0.5) { return res.status(403).json({ error: 'Verification failed' }); }
CAPTCHA Is Not a Silver Bullet

CAPTCHA farms (human workers solving CAPTCHAs for bots) exist and are cheap ($1-3 per 1000 solutions). CAPTCHA should be one layer in a defense-in-depth strategy, not the sole protection. Combine with device fingerprinting, behavioral analysis, and business flow limits.
