Module OWASP-08

API7:2023 -- Server Side Request Forgery (SSRF)

SSRF occurs when an API fetches a resource from a URL provided by the user without proper validation. The attacker manipulates the URL to make the server send requests to unintended destinations -- internal services, cloud metadata endpoints, or other protected resources that the server has network access to but the attacker does not.

Learning Objectives
  • Explain how SSRF turns a server into a proxy for attacking internal infrastructure
  • Demonstrate SSRF exploitation against cloud metadata services (169.254.169.254)
  • Identify API features that are SSRF-prone (webhooks, imports, URL previews)
  • Implement URL validation with allowlists, DNS resolution checks, and network segmentation
  • Configure cloud-specific SSRF mitigations (IMDSv2, metadata endpoint blocking)

How SSRF Works

# Legitimate use: API fetches a URL provided by user POST /api/v1/import { "url": "https://partner-site.com/data.csv" } # SSRF attack: attacker targets internal service POST /api/v1/import { "url": "http://192.168.1.50:8080/admin" } # Server fetches internal admin panel -- bypasses firewall # SSRF attack: cloud metadata exfiltration POST /api/v1/import { "url": "http://169.254.169.254/latest/meta-data/iam/security-credentials/" } # Returns AWS IAM temporary credentials -- full cloud account compromise

The server makes the request from inside the network perimeter. It can reach internal services (databases, admin panels, other microservices) that are not exposed to the internet. The attacker uses the vulnerable API as a proxy to access these internal resources.

Cloud Metadata Exploitation

Cloud providers (AWS, GCP, Azure) expose instance metadata at a link-local address (169.254.169.254). This metadata contains IAM credentials, network configuration, and user data. SSRF to this endpoint has caused some of the largest cloud breaches in history.

Capital One Breach (2019)

An SSRF vulnerability in a WAF configuration allowed an attacker to access the AWS metadata endpoint, retrieve IAM role credentials, and use them to exfiltrate 100+ million customer records from S3 buckets. This breach resulted in an $80 million fine.

# AWS metadata endpoints targeted by SSRF http://169.254.169.254/latest/meta-data/iam/security-credentials/ http://169.254.169.254/latest/user-data http://169.254.169.254/latest/meta-data/hostname # GCP metadata http://metadata.google.internal/computeMetadata/v1/instance/service-accounts/ # Azure metadata http://169.254.169.254/metadata/instance?api-version=2021-02-01

SSRF Bypass Techniques

Simple URL validation (e.g., checking if the host is "169.254.169.254") is easily bypassed:

# Decimal encoding http://2852039166/ # = 169.254.169.254 # IPv6 shorthand http://[::ffff:169.254.169.254]/ # DNS rebinding: attacker's domain resolves to internal IP http://evil.attacker.com/ # First DNS lookup: 1.2.3.4 (passes check) # Second DNS lookup: 169.254.169.254 (actual request) # URL parsing inconsistencies http://169.254.169.254@legitimate-site.com/ http://legitimate-site.com#@169.254.169.254/ # Redirect chains http://attacker.com/redirect?url=http://169.254.169.254/

Defense Strategies

URL Allowlist

Only allow requests to known-good domains. For webhooks: validate against a list of registered callback domains. Reject anything not on the list.

DNS Resolution Validation

Resolve the hostname BEFORE making the request. If the resolved IP is internal (RFC 1918, link-local, loopback), reject the request. Prevents DNS rebinding.

Network Segmentation

Run URL-fetching workers in an isolated network segment with no access to internal services. Use a dedicated egress proxy with strict allowlists.

Cloud Metadata Protection

AWS: Enable IMDSv2 (requires session token). GCP: Require Metadata-Flavor header. Azure: Require Metadata: true header. Block 169.254.169.254 in firewall rules.

// Secure URL validation function const dns = require('dns').promises; const { URL } = require('url'); const ipaddr = require('ipaddr.js'); async function validateUrl(urlString) { const parsed = new URL(urlString); // Only allow HTTPS if (parsed.protocol !== 'https:') throw new Error('HTTPS required'); // Resolve DNS and check for internal IPs const addresses = await dns.resolve4(parsed.hostname); for (const addr of addresses) { const ip = ipaddr.parse(addr); const range = ip.range(); if (['private', 'loopback', 'linkLocal', 'uniqueLocal'] .includes(range)) { throw new Error('Internal IP blocked'); } } return true; }
