Module OWASP-01

Introduction to the OWASP API Security Top 10

The OWASP API Security Top 10 (2023 edition) is the industry benchmark for understanding the most critical security risks to APIs. This introductory module covers the project's methodology, the risk rating framework, what changed from 2019 to 2023, and how to use the list as a practical security tool.

Learning Objectives
  • Explain what OWASP is and why a separate API-specific Top 10 exists
  • Describe the data-driven methodology used to compile the 2023 list
  • Summarize each of the 10 API security risks at a high level
  • Compare the 2019 and 2023 editions, identifying additions and removals
  • Use the risk rating framework to prioritize remediation efforts

Why APIs Need Their Own Top 10

The original OWASP Top 10 (for web applications) focuses on vulnerabilities like XSS, SQL injection, and broken access control in server-rendered applications. APIs have a fundamentally different attack surface: they expose raw data and business logic through structured endpoints, often without the protective layer of a browser UI. Vulnerabilities like Broken Object Level Authorization (BOLA) and Unrestricted Resource Consumption are API-specific problems that the web application Top 10 does not adequately address.

The first API Security Top 10 was released in 2019. The 2023 edition reflects four years of real-world breach data, community feedback, and the evolution of API architectures (GraphQL, gRPC, serverless).

Changes from 2019 to 2023

The 2023 edition made significant changes to reflect evolving API threats:

New in 2023

API6 -- Unrestricted Access to Sensitive Business Flows (new category for business logic abuse). API7 -- SSRF (promoted from general web Top 10). API10 -- Unsafe Consumption of APIs (supply chain risk).

Merged or Removed

Excessive Data Exposure and Mass Assignment (2019 API3/API6) merged into API3:2023 -- Broken Object Property Level Authorization. Injection removed (covered by web Top 10).

API1 (BOLA) Remains Number One

Broken Object Level Authorization has been the top API risk in both 2019 and 2023. Despite widespread awareness, BOLA remains the most frequently exploited API vulnerability because it requires per-endpoint object ownership checks that are easy to forget during development.

Risk Rating Framework

Each risk in the OWASP API Top 10 is rated across four dimensions, following the standard OWASP risk methodology:

DimensionQuestionScale
ExploitabilityHow easy is it to discover and exploit?Easy / Average / Difficult
PrevalenceHow common is this vulnerability in real APIs?Widespread / Common / Uncommon
DetectabilityHow easy is it to detect via testing or scanning?Easy / Average / Difficult
Technical ImpactWhat is the potential damage if exploited?Severe / Moderate / Minor

The business impact is deliberately excluded from the framework because it varies by organization. A data leak at a healthcare company has different regulatory consequences than the same leak at a gaming company. Teams should map technical impact to their specific business context.

How to Use This Course

Modules 2-9 each cover one (or two) risks in depth, with real-world examples, vulnerable code samples, exploitation walkthroughs, and concrete remediation steps. Module 10 combines the final risk with a complete remediation playbook. For each risk, ask four questions:

1. Is my API vulnerable to this? -- Review your architecture 2. How would an attacker exploit it? -- Understand the attack vector 3. What is the potential impact? -- Map to your business context 4. How do I fix it? -- Apply the specific remediation
