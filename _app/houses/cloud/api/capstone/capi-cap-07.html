Learning Objectives

  • Write an OpenAPI 3.0 specification for your complete API
  • Set up Swagger UI for interactive documentation

  • Implement contract testing to validate API responses against the spec

OpenAPI Specification

The OpenAPI (formerly Swagger) specification is the industry standard for describing REST APIs. It defines every endpoint, parameter, request body, response shape, and authentication requirement in a machine-readable YAML/JSON format. This specification becomes your API contract -- clients, documentation tools, and test generators all consume it.

# openapi.yaml (excerpt) openapi: 3.0.3 info: title: Task Management API version: 1.0.0 description: Secure task management API built for the Capstone project servers: - url: http://localhost:3000 description: Development - url: https://api.taskmanager.com description: Production paths: /auth/login: post: tags: [Authentication] summary: Authenticate user requestBody: required: true content: application/json: schema: type: object required: [email, password] properties: email: { type: string, format: email } password: { type: string, minLength: 8 } responses: 200: description: Login successful content: application/json: schema: type: object properties: accessToken: { type: string } refreshToken: { type: string } expiresIn: { type: integer } 401: description: Invalid credentials components: securitySchemes: BearerAuth: type: http scheme: bearer bearerFormat: JWT

Automated Testing

A production API needs three layers of testing: unit tests for individual functions, integration tests for endpoint behavior, and security tests for vulnerability regression. Use Jest (Node.js) or pytest (Python) with supertest/httpx for HTTP-level assertions.

Unit Tests
Test individual functions in isolation: password hashing, JWT generation, validation schemas, authorization logic. Mock database calls. Target: 80%+ code coverage on business logic.
Integration Tests
Test complete HTTP request/response cycles against a test database. Verify status codes, response bodies, headers, and side effects. Cover happy paths, error paths, and edge cases for every endpoint.
Security Tests
Dedicated test suite for security: expired tokens rejected (401), wrong user blocked (403), SQL injection payloads rejected (400), rate limits enforced (429), mass assignment blocked (fields stripped).
Contract Testing
Validate API responses match the OpenAPI spec using tools like jest-openapi or schemathesis. Every response must match the documented schema -- no extra fields, correct types, proper status codes.
// tests/integration/tasks.test.js describe("POST /projects/:id/tasks", () => { test("creates task with valid input", async () => { const res = await request(app) .post(`/projects/${projectId}/tasks`) .set("Authorization", `Bearer ${userToken}`) .send({ title: "Implement auth", priority: "HIGH" }); expect(res.status).toBe(201); expect(res.body.data).toHaveProperty("id"); expect(res.body.data.title).toBe("Implement auth"); expect(res.body.data.priority).toBe("HIGH"); expect(res.body.data.status).toBe("TODO"); }); test("rejects missing title", async () => { const res = await request(app) .post(`/projects/${projectId}/tasks`) .set("Authorization", `Bearer ${userToken}`) .send({ priority: "HIGH" }); expect(res.status).toBe(400); expect(res.body.code).toBe("VALIDATION_ERROR"); }); test("rejects non-member access", async () => { const res = await request(app) .post(`/projects/${projectId}/tasks`) .set("Authorization", `Bearer ${otherUserToken}`) .send({ title: "Unauthorized task" }); expect(res.status).toBe(403); }); });
CI Integration: Run your test suite on every git push. Use GitHub Actions or similar CI to: (1) spin up a test database, (2) run migrations, (3) execute unit + integration + security tests, (4) report coverage. Block merges if tests fail.

Key Takeaways

  • Write an OpenAPI 3.0 spec as your API contract -- tools and clients depend on it
  • Three test layers: unit (logic), integration (HTTP), security (vulnerabilities)
  • Contract testing validates responses match the documented specification
  • Set up Swagger UI for interactive documentation (auto-generated from the spec)
  • Run tests in CI on every push -- block merges on failure
