RBAC Middleware

Role-Based Access Control restricts API endpoints based on the user's role (admin, manager, member). The middleware reads the role from the JWT claims (set during authentication) and compares it against the required role for each route.

// src/middleware/authorize.js // Role hierarchy: ADMIN > MANAGER > MEMBER const ROLE_HIERARCHY = { ADMIN: 3, MANAGER: 2, MEMBER: 1 }; exports.requireRole = (...allowedRoles) => { return (req, res, next) => { if (!req.user) { return res.status(401).json({ error: 'Authentication required' }); } const userRole = req.user.role; const hasPermission = allowedRoles.some( role => ROLE_HIERARCHY[userRole] >= ROLE_HIERARCHY[role] ); if (!hasPermission) { return res.status(403).json({ error: 'Insufficient permissions' }); } next(); }; }; // Usage in routes router.get('/users', auth, requireRole('ADMIN'), usersController.list); router.delete('/users/:id', auth, requireRole('ADMIN'), usersController.remove); router.post('/projects', auth, requireRole('MEMBER'), projectsController.create);

Object-Level Authorization

RBAC alone is insufficient. You must also verify that the authenticated user is authorized to access the specific resource they are requesting. This prevents IDOR/BOLA -- the number one API vulnerability.

// src/middleware/ownership.js // Verify user is a member of the requested project exports.requireProjectMember = async (req, res, next) => { const projectId = req.params.projectId || req.params.id; const membership = await prisma.projectMember.findFirst({ where: { projectId, userId: req.user.id } }); if (!membership && req.user.role !== 'ADMIN') { return res.status(403).json({ error: 'Not a member of this project' }); } req.projectRole = membership?.role || 'ADMIN'; next(); }; // Verify user owns the resource or is admin exports.requireOwnership = (resourceField = 'ownerId') => { return async (req, res, next) => { const resource = req.resource; // Set by previous middleware if (!resource) return res.status(404).json({ error: 'Not found' }); if (resource[resourceField] !== req.user.id && req.user.role !== 'ADMIN') { return res.status(403).json({ error: 'Access denied' }); } next(); }; }; // Route composition router.get('/projects/:id/tasks', auth, requireProjectMember, // Must be a project member tasksController.list ); router.delete('/projects/:id', auth, loadProject, // Load project into req.resource requireOwnership(), // Must be the project owner projectsController.remove );
Defense in Depth
Layer authorization: route-level RBAC + resource-level ownership + service-level business rules. If any layer fails, the request is denied. This prevents bypass through any single point of failure.
Testing Authorization
Write integration tests with multiple user accounts. For every protected endpoint, verify: (1) unauthenticated access returns 401, (2) wrong role returns 403, (3) wrong user same role returns 403, (4) correct user returns 200.

Authorization Test Suite

// tests/integration/authorization.test.js describe('Project Authorization', () => { let adminToken, userAToken, userBToken; let projectA; // owned by User A beforeAll(async () => { // Create test users and tokens adminToken = await createTestUser('admin@test.com', 'ADMIN'); userAToken = await createTestUser('usera@test.com', 'MEMBER'); userBToken = await createTestUser('userb@test.com', 'MEMBER'); projectA = await createTestProject(userAToken); }); test('User A can access own project', async () => { const res = await request(app) .get(`/projects/${projectA.id}`) .set('Authorization', `Bearer ${userAToken}`); expect(res.status).toBe(200); }); test('User B cannot access User A project', async () => { const res = await request(app) .get(`/projects/${projectA.id}`) .set('Authorization', `Bearer ${userBToken}`); expect(res.status).toBe(403); }); test('Admin can access any project', async () => { const res = await request(app) .get(`/projects/${projectA.id}`) .set('Authorization', `Bearer ${adminToken}`); expect(res.status).toBe(200); }); test('Unauthenticated request returns 401', async () => { const res = await request(app).get(`/projects/${projectA.id}`); expect(res.status).toBe(401); }); });
Production Pattern: In enterprise APIs, consider using a policy engine like Open Policy Agent (OPA) or Casbin for complex authorization rules. These decouple authorization logic from application code, making it auditable and testable independently.

Key Takeaways

  • RBAC middleware enforces role-based restrictions at the route level
  • Object-level authorization (ownership checks) prevents IDOR/BOLA vulnerabilities
  • Layer defenses: route RBAC + resource ownership + service business rules
  • Write authorization tests with multiple accounts at different privilege levels
  • Always return 403 (not 404) for resources that exist but the user cannot access
