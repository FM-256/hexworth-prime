Database Schema Design

The database schema defines your data model. Use an ORM to prevent SQL injection and enforce type safety. Prisma (Node.js) and SQLAlchemy (Python) both support migrations for safe schema evolution.

// prisma/schema.prisma model User { id String @id @default(uuid()) email String @unique passwordHash String @map("password_hash") name String role Role @default(MEMBER) emailVerified Boolean @default(false) @map("email_verified") createdAt DateTime @default(now()) @map("created_at") updatedAt DateTime @updatedAt @map("updated_at") projects ProjectMember[] assignedTasks Task[] @relation("assignee") comments Comment[] @@map("users") } model Project { id String @id @default(uuid()) name String description String? visibility Visibility @default(PRIVATE) ownerId String @map("owner_id") createdAt DateTime @default(now()) @map("created_at") members ProjectMember[] tasks Task[] @@map("projects") } model Task { id String @id @default(uuid()) title String description String? status TaskStatus @default(TODO) priority Priority @default(MEDIUM) dueDate DateTime? @map("due_date") projectId String @map("project_id") assigneeId String? @map("assignee_id") createdAt DateTime @default(now()) @map("created_at") updatedAt DateTime @updatedAt @map("updated_at") project Project @relation(fields: [projectId], references: [id]) assignee User? @relation("assignee", fields: [assigneeId], references: [id]) attachments Attachment[] comments Comment[] @@map("tasks") } enum Role { ADMIN MANAGER MEMBER } enum TaskStatus { TODO IN_PROGRESS REVIEW DONE } enum Priority { LOW MEDIUM HIGH CRITICAL } enum Visibility { PRIVATE TEAM }

Express Server Setup

The Express server configuration sets up middleware in the correct order. Security middleware (helmet, cors) runs first, followed by body parsing, then routes.

// src/app.js const express = require('express'); const helmet = require('helmet'); const cors = require('cors'); const app = express(); // Security middleware first app.use(helmet()); app.use(cors({ origin: process.env.ALLOWED_ORIGINS?.split(',') || 'http://localhost:3000', credentials: true })); // Body parsing with size limits app.use(express.json({ limit: '10kb' })); // Prevent large payload DoS app.use(express.urlencoded({ extended: false })); // Remove X-Powered-By header (information disclosure) app.disable('x-powered-by'); // Routes app.use('/auth', require('./routes/auth')); app.use('/users', require('./routes/users')); app.use('/projects', require('./routes/projects')); app.use('/tasks', require('./routes/tasks')); // Health check (no auth required) app.get('/health', (req, res) => { res.json({ status: 'ok', timestamp: new Date().toISOString() }); }); // Global error handler (never leak stack traces in production) app.use((err, req, res, next) => { console.error(err.stack); const status = err.statusCode || 500; const message = status === 500 ? 'Internal server error' : err.message; res.status(status).json({ error: message }); }); module.exports = app;

CRUD Controller Pattern

Each resource follows the same controller pattern. Consistent response formatting, proper HTTP status codes, and error handling at every level.

Status Code Discipline
200 OK (read/update), 201 Created (new resource), 204 No Content (delete), 400 Bad Request (validation), 401 Unauthorized, 403 Forbidden, 404 Not Found, 409 Conflict (duplicate), 429 Rate Limited, 500 Server Error.
Response Envelope
Wrap all responses in a consistent envelope: { data: {...}, meta: { page, total, ... } } for success, { error: "message", code: "VALIDATION_ERROR" } for failures. Never return raw database objects.
// src/controllers/projects.js const { PrismaClient } = require('@prisma/client'); const prisma = new PrismaClient(); exports.create = async (req, res, next) => { try { const project = await prisma.project.create({ data: { name: req.body.name, description: req.body.description, ownerId: req.user.id, // From auth middleware members: { create: { userId: req.user.id, role: 'OWNER' } } }, select: { // Only return needed fields id: true, name: true, description: true, visibility: true, createdAt: true } }); res.status(201).json({ data: project }); } catch (err) { next(err); } }; exports.list = async (req, res, next) => { try { const page = parseInt(req.query.page) || 1; const limit = Math.min(parseInt(req.query.limit) || 20, 100); const skip = (page - 1) * limit; const [projects, total] = await Promise.all([ prisma.project.findMany({ where: { members: { some: { userId: req.user.id } } }, skip, take: limit, orderBy: { createdAt: 'desc' }, select: { id: true, name: true, visibility: true, createdAt: true } }), prisma.project.count({ where: { members: { some: { userId: req.user.id } } } }) ]); res.json({ data: projects, meta: { page, limit, total, pages: Math.ceil(total / limit) } }); } catch (err) { next(err); } };
Security Note: Always use parameterized queries (Prisma/SQLAlchemy handle this automatically). Never interpolate user input into query strings. Use `select` to explicitly choose returned fields -- never return the entire database row, which could leak password hashes or internal IDs.

Key Takeaways

  • Initialize projects with proper .env configuration -- never hardcode secrets
  • ORM-based schemas prevent SQL injection and enforce consistent data types
  • Security middleware (helmet, cors) must execute before route handlers
  • Use select/projection to control which fields are returned -- never expose internal data
  • Consistent error handling prevents stack trace leakage in production
  • Limit request body size to prevent large-payload denial-of-service
