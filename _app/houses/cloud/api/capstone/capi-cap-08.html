Security Headers

HTTP security headers instruct browsers and clients to enforce security policies. The helmet middleware sets most of these automatically, but you should understand what each one does and configure them for your specific use case.

// Security headers via helmet (already installed in CAP-02) app.use(helmet({ contentSecurityPolicy: { directives: { defaultSrc: ["'self'"], scriptSrc: ["'self'"], styleSrc: ["'self'", "'unsafe-inline'"], imgSrc: ["'self'", "data:"], connectSrc: ["'self'"], frameSrc: ["'none'"], objectSrc: ["'none'"] } }, crossOriginEmbedderPolicy: true, crossOriginOpenerPolicy: true, crossOriginResourcePolicy: { policy: "same-site" }, hsts: { maxAge: 31536000, includeSubDomains: true, preload: true }, noSniff: true, referrerPolicy: { policy: "strict-origin-when-cross-origin" }, xssFilter: true })); // CORS configuration app.use(cors({ origin: process.env.ALLOWED_ORIGINS?.split(","), methods: ["GET", "POST", "PUT", "PATCH", "DELETE"], allowedHeaders: ["Content-Type", "Authorization"], exposedHeaders: ["X-RateLimit-Remaining", "X-RateLimit-Reset"], credentials: true, maxAge: 86400 // Preflight cache: 24 hours }));

Audit Logging

Security-relevant events must be logged for incident response, compliance, and forensics. Log authentication events (login, logout, failed attempts), authorization failures, data modifications, and administrative actions.

What to Log
Authentication: login success/failure, token refresh, password reset. Authorization: 403 responses with user ID and attempted resource. Data: create/update/delete operations with actor, target, and timestamp. Admin: user management, config changes, role assignments.
What Never to Log
Passwords (plaintext or hashed), full credit card numbers, session tokens, API keys, personal health information, or any data regulated by GDPR/HIPAA/PCI. Log the event, not the sensitive payload.
Log Format
Use structured logging (JSON) with fields: timestamp, level, event_type, user_id, ip_address, resource, action, result (success/failure), and request_id for correlation. Never log to stdout in production -- use a log aggregator.
Dependency Scanning
Run npm audit or pip-audit regularly. Use GitHub Dependabot or Snyk for automated vulnerability alerts. Pin dependency versions in lockfiles. Review and update dependencies monthly. A single vulnerable dependency can compromise your entire API.
// src/utils/auditLog.js const winston = require("winston"); const auditLogger = winston.createLogger({ level: "info", format: winston.format.combine( winston.format.timestamp(), winston.format.json() ), transports: [ new winston.transports.File({ filename: "logs/audit.log" }) ] }); exports.logEvent = (event) => { auditLogger.info({ event_type: event.type, user_id: event.userId, ip: event.ip, resource: event.resource, action: event.action, result: event.result, details: event.details }); }; // Usage in auth controller auditLog.logEvent({ type: "AUTH", userId: user.id, ip: req.ip, resource: "/auth/login", action: "LOGIN", result: "SUCCESS", details: { method: "password" } });

Hardening Checklist

Before deploying to production, verify every item on this checklist. Each item maps to a specific OWASP API Top 10 risk or security best practice.

SECURITY HARDENING CHECKLIST ============================ [ ] HTTPS enforced (redirect HTTP to HTTPS) [ ] HSTS header set with includeSubDomains and preload [ ] CORS restricted to specific allowed origins [ ] CSP headers configured (no unsafe-eval) [ ] X-Content-Type-Options: nosniff [ ] X-Frame-Options: DENY [ ] Server header removed or generic [ ] Request body size limited (10kb for JSON) [ ] File upload size limited (10MB) with type validation [ ] Rate limiting on all endpoints (strict on auth) [ ] JWT secret is 256+ bits of cryptographic randomness [ ] JWT expiry is 15 minutes or less [ ] Refresh tokens are hashed before storage [ ] Password reset tokens expire in 30 minutes [ ] bcrypt cost factor is 12 or higher [ ] All inputs validated against strict schemas [ ] Unknown JSON fields are stripped (mass assignment prevention) [ ] SQL queries use parameterized statements (ORM enforced) [ ] Error responses never expose stack traces or SQL [ ] Audit logging covers auth, authz, and data events [ ] Dependencies scanned for known vulnerabilities [ ] .env file is gitignored [ ] Debug endpoints disabled in production [ ] Database credentials use least-privilege accounts

Key Takeaways

  • Helmet sets security headers automatically -- customize CSP and CORS for your domain
  • HSTS with preload ensures browsers always use HTTPS
  • Audit logging must cover auth, authorization failures, and data modifications
  • Never log passwords, tokens, or PII -- log the event, not the payload
  • Run dependency scans (npm audit) before every deployment
