Schema Validation with Joi

Every API endpoint must validate incoming data against a strict schema before processing. Schema validation is your first line of defense against injection, type confusion, and business logic abuse. Reject invalid input early with clear error messages.

// src/validators/tasks.js const Joi = require('joi'); const createTaskSchema = Joi.object({ title: Joi.string().trim().min(1).max(200).required(), description: Joi.string().trim().max(5000).optional(), priority: Joi.string().valid('LOW', 'MEDIUM', 'HIGH', 'CRITICAL').default('MEDIUM'), status: Joi.string().valid('TODO', 'IN_PROGRESS', 'REVIEW', 'DONE').default('TODO'), assigneeId: Joi.string().uuid().optional(), dueDate: Joi.date().iso().min('now').optional() }).options({ stripUnknown: true }); // Remove unexpected fields (mass assignment prevention) const updateTaskSchema = Joi.object({ title: Joi.string().trim().min(1).max(200), description: Joi.string().trim().max(5000).allow(''), priority: Joi.string().valid('LOW', 'MEDIUM', 'HIGH', 'CRITICAL'), status: Joi.string().valid('TODO', 'IN_PROGRESS', 'REVIEW', 'DONE'), assigneeId: Joi.string().uuid().allow(null), dueDate: Joi.date().iso().allow(null) }).min(1) // At least one field required for update .options({ stripUnknown: true });

Validation Middleware

Create reusable validation middleware that runs before controllers. This middleware validates the request body, query parameters, or URL parameters against the appropriate schema and returns structured error responses.

// src/middleware/validate.js exports.validate = (schema, source = 'body') => { return (req, res, next) => { const { error, value } = schema.validate(req[source], { abortEarly: false, // Return all errors, not just the first errors: { wrap: { label: false } } }); if (error) { const details = error.details.map(d => ({ field: d.path.join('.'), message: d.message, type: d.type })); return res.status(400).json({ error: 'Validation failed', code: 'VALIDATION_ERROR', details }); } req[source] = value; // Replace with sanitized data next(); }; }; // Usage in routes router.post('/projects/:projectId/tasks', auth, requireProjectMember, validate(createTaskSchema), tasksController.create );

Structured Error Responses

Consistent error formatting across all endpoints makes your API predictable for consumers and prevents information leakage. Never expose stack traces, database queries, or internal paths in error responses.

Error Envelope
Every error follows the same structure: { error: "Human-readable message", code: "MACHINE_READABLE_CODE", details: [...optional field-level errors] }. HTTP status codes convey the category; the code field enables programmatic error handling.
Error Code Catalog
Define error codes: VALIDATION_ERROR, AUTHENTICATION_REQUIRED, INSUFFICIENT_PERMISSIONS, RESOURCE_NOT_FOUND, DUPLICATE_RESOURCE, RATE_LIMITED, INTERNAL_ERROR. Document these in your OpenAPI spec for API consumers.
// src/middleware/errorHandler.js module.exports = (err, req, res, next) => { // Log full error for debugging (never send to client) console.error(`[${new Date().toISOString()}] ${req.method} ${req.path}`, err); // Known operational errors if (err.isOperational) { return res.status(err.statusCode).json({ error: err.message, code: err.code }); } // Prisma-specific errors if (err.code === 'P2025') { return res.status(404).json({ error: 'Resource not found', code: 'RESOURCE_NOT_FOUND' }); } if (err.code === 'P2002') { return res.status(409).json({ error: 'Duplicate resource', code: 'DUPLICATE_RESOURCE' }); } // Unknown errors: generic message (never leak internals) res.status(500).json({ error: 'Internal server error', code: 'INTERNAL_ERROR' }); };

Input Sanitization

Beyond schema validation, sanitize inputs to remove potentially dangerous content. Strip HTML tags from text fields, normalize unicode, and validate file uploads by content (not just extension).

String Sanitization
Trim whitespace, normalize unicode (NFC), strip HTML tags (using a library like sanitize-html or DOMPurify), limit string length. For names and titles, reject strings containing control characters or null bytes.
Query Parameter Safety
Validate sort fields against an allowlist (never pass raw column names to ORDER BY). Validate filter operators. Cap pagination limits (max 100 per page). Parse numeric parameters with parseInt and validate ranges.
stripUnknown: true is your mass assignment prevention. When Joi strips unknown fields from the validated object, any attempt to inject role, admin, or other unauthorized fields is silently dropped before reaching your controller.

Key Takeaways

  • Validate every input against strict schemas -- reject unknown fields to prevent mass assignment
  • Return all validation errors at once, not one at a time (abortEarly: false)
  • Structured error responses use consistent format with machine-readable error codes
  • Never expose stack traces, SQL queries, or file paths in production error responses
  • Sanitize strings, cap pagination, and allowlist sort fields to prevent injection
