Presentation Structure

Your capstone presentation demonstrates both technical competence and security awareness. Structure it to show not just what you built, but why each security decision was made.

1. Architecture Overview (5 min)
Technology stack, project structure, deployment architecture. Show the request flow diagram from CAP-01. Explain why you chose each component and how the layered architecture enforces security at every level.
2. Security Controls Deep Dive (10 min)
Walk through each security layer: authentication (JWT + refresh tokens), authorization (RBAC + object-level), input validation (Joi schemas), rate limiting (Redis), security headers (helmet), and audit logging. Show code for each.
3. Live Demo (5 min)
Demonstrate the API working: register, login, create project, add task. Then demonstrate security: show IDOR blocked (403), invalid input rejected (400), rate limiting triggered (429), expired token rejected (401).
4. Audit Results & Lessons Learned (5 min)
Present your OWASP self-assessment results. Be honest about gaps -- acknowledging weaknesses shows maturity. Discuss what you would do differently and what improvements you would prioritize next.

Evaluation Criteria

Code Quality (25%)
Clean project structure, consistent coding style, proper error handling, meaningful variable names, separation of concerns. Code should be maintainable by another developer.
Security Implementation (35%)
Authentication, authorization, input validation, rate limiting, security headers, audit logging. Coverage across OWASP API Top 10. Defense in depth -- multiple layers of protection.
Testing & Documentation (20%)
Test coverage (target 80%+), OpenAPI spec completeness, security test cases, README with setup instructions. Tests actually pass and cover edge cases.
Presentation & Self-Assessment (20%)
Clear communication of design decisions, honest security audit, live demo without failures, thoughtful reflection on lessons learned and future improvements.
Capstone Completion: Submit your project repository (with all code, tests, documentation, and self-assessment) through the course submission system. Include a README with setup instructions, your OpenAPI spec, and your completed OWASP self-assessment checklist. This capstone represents the culmination of the entire API Security Track.

Key Takeaways

  • A self-assessment against OWASP API Top 10 validates your security controls actually work
  • Honest vulnerability documentation shows security maturity -- acknowledge gaps
  • Live demos should show both functionality AND security controls in action
  • The capstone demonstrates end-to-end API security: design, build, test, deploy, audit
  • Security is never "done" -- document what you would improve next
