The Capstone Challenge

Over the next 10 modules, you will design, build, secure, document, deploy, and audit a production-grade REST API from scratch. This is not a toy project -- you will implement real authentication, authorization, input validation, rate limiting, logging, monitoring, and automated testing. At the end, you will conduct a security self-assessment against the OWASP API Top 10.

The project domain is a Task Management API -- simple enough to complete in a capstone timeline, complex enough to exercise every security control. Users create accounts, manage projects, assign tasks, upload attachments, and collaborate through comments.

Functional Requirements

User Management
Registration, login, profile management, password reset. Role-based access: admin, manager, member. Email verification required before account activation.
Project Management
CRUD operations on projects. Projects have owners, members, and visibility settings (private/team). Managers can invite members and set permissions.
Task Operations
Tasks belong to projects. Fields: title, description, assignee, priority (low/medium/high/critical), status (todo/in-progress/review/done), due date. Support filtering, sorting, and pagination.
File Attachments
Upload files to tasks. File type validation, size limits (10MB), virus scanning stub. Secure file storage with signed download URLs.

Technology Stack Options

Choose one of the following stacks. Both are industry-standard and well-documented. The security principles are identical regardless of language choice.

Option A: Node.js + Express
Express.js framework, PostgreSQL with Prisma ORM, JWT with jsonwebtoken, Joi/Zod for validation, Jest for testing, Docker for deployment. Widely used in startup and enterprise environments.
Option B: Python + FastAPI
FastAPI framework, PostgreSQL with SQLAlchemy ORM, python-jose for JWT, Pydantic for validation, pytest for testing, Docker for deployment. Built-in async support and automatic OpenAPI generation.

API Architecture Design

The API follows a layered architecture with clear separation of concerns. Each layer has a specific security responsibility.

REQUEST FLOW: Client Request | v [Rate Limiter] -- Throttle excessive requests | v [Auth Middleware] -- Verify JWT, extract user context | v [Validator] -- Validate input schema, sanitize data | v [Controller] -- Route handling, orchestrate service calls | v [Service Layer] -- Business logic, authorization checks | v [Data Layer] -- ORM queries, database operations | v [Response] -- Formatted JSON, proper status codes, no data leakage
Entity Relationship Model
Users (1:N) Projects, Projects (1:N) Tasks, Tasks (1:N) Comments, Tasks (1:N) Attachments, Users (N:M) Projects (through Memberships with role). Users have: id, email, password_hash, name, role, email_verified, created_at. Tasks have: id, title, description, status, priority, assignee_id, project_id, due_date, created_at, updated_at.

Endpoint Specification

AUTH POST /auth/register -- Create account POST /auth/login -- Authenticate, receive JWT POST /auth/refresh -- Refresh access token POST /auth/logout -- Invalidate refresh token POST /auth/forgot-password -- Request password reset POST /auth/reset-password -- Reset with token USERS GET /users/me -- Current user profile PUT /users/me -- Update own profile GET /users -- List users (admin only) GET /users/:id -- Get user by ID (admin only) PROJECTS POST /projects -- Create project GET /projects -- List user's projects GET /projects/:id -- Get project details PUT /projects/:id -- Update project DELETE /projects/:id -- Delete project POST /projects/:id/members -- Add member DELETE /projects/:id/members/:userId -- Remove member TASKS POST /projects/:id/tasks -- Create task GET /projects/:id/tasks -- List tasks (filter, sort, paginate) GET /tasks/:id -- Get task details PUT /tasks/:id -- Update task DELETE /tasks/:id -- Delete task ATTACHMENTS POST /tasks/:id/attachments -- Upload file GET /attachments/:id -- Download file (signed URL) DELETE /attachments/:id -- Delete attachment
Security-First Mindset: Notice that every design decision includes a security consideration. The layered architecture ensures that security controls (rate limiting, auth, validation) execute before business logic. This is "shift left" in practice -- security is designed in, not bolted on.

Key Takeaways

  • The capstone builds a complete Task Management API with full security controls
  • Choose Express or FastAPI -- both are production-grade and well-supported
  • Layered architecture ensures security middleware executes before business logic
  • Design your entity model and endpoint specification before writing any code
  • Every endpoint must have defined authentication and authorization requirements
