Learning Objectives

  • Implement secure password hashing with bcrypt and proper cost factors

  • Create a token refresh flow that prevents token theft and replay

Password Hashing with bcrypt

Never store passwords in plaintext or with weak hashing (MD5, SHA-256 without salt). Use bcrypt, which incorporates a salt and configurable work factor (cost). A cost factor of 12 provides approximately 250ms hashing time on modern hardware -- slow enough to resist brute-force, fast enough for user experience.

// src/utils/password.js const bcrypt = require('bcrypt'); const SALT_ROUNDS = 12; // ~250ms on modern hardware exports.hashPassword = async (plaintext) => { return bcrypt.hash(plaintext, SALT_ROUNDS); }; exports.verifyPassword = async (plaintext, hash) => { return bcrypt.compare(plaintext, hash); }; // Registration controller exports.register = async (req, res) => { const { email, password, name } = req.body; // Check for existing user (prevent enumeration by using same response) const existing = await prisma.user.findUnique({ where: { email } }); if (existing) { return res.status(409).json({ error: 'Email already registered' }); } const passwordHash = await hashPassword(password); const user = await prisma.user.create({ data: { email, passwordHash, name }, select: { id: true, email: true, name: true, createdAt: true } }); res.status(201).json({ data: user }); };

JWT Token Architecture

Implement a dual-token system: a short-lived access token (15 minutes) and a long-lived refresh token (7 days). The access token travels in the Authorization header for every request. The refresh token is used only to obtain new access tokens.

// src/utils/tokens.js const jwt = require('jsonwebtoken'); const crypto = require('crypto'); exports.generateAccessToken = (user) => { return jwt.sign( { sub: user.id, role: user.role }, process.env.JWT_SECRET, { expiresIn: '15m', algorithm: 'HS256' } ); }; exports.generateRefreshToken = () => { return crypto.randomBytes(40).toString('hex'); }; // Login controller exports.login = async (req, res) => { const { email, password } = req.body; const user = await prisma.user.findUnique({ where: { email } }); // Constant-time comparison: don't reveal if email exists if (!user || !(await verifyPassword(password, user.passwordHash))) { return res.status(401).json({ error: 'Invalid credentials' }); } const accessToken = generateAccessToken(user); const refreshToken = generateRefreshToken(); // Store refresh token hash in database (not plaintext) await prisma.refreshToken.create({ data: { tokenHash: crypto.createHash('sha256').update(refreshToken).digest('hex'), userId: user.id, expiresAt: new Date(Date.now() + 7 * 24 * 60 * 60 * 1000) } }); res.json({ accessToken, refreshToken, expiresIn: 900 }); };
Auth Middleware
Extract the Bearer token from the Authorization header, verify the JWT signature and expiration, attach the decoded user to req.user, and return 401 for invalid or expired tokens. This middleware protects all authenticated routes.
Token Refresh Flow
Client sends refresh token to POST /auth/refresh. Server verifies the token hash exists in the database and has not expired. Issue new access token + new refresh token (rotation). Delete the old refresh token to prevent reuse.

Password Reset Implementation

Password reset requires a cryptographically random, time-limited, single-use token sent via email. The token hash (not the token itself) is stored in the database.

// POST /auth/forgot-password exports.forgotPassword = async (req, res) => { const { email } = req.body; const user = await prisma.user.findUnique({ where: { email } }); // Always return success (prevent email enumeration) if (!user) { return res.json({ message: 'If the email exists, a reset link was sent.' }); } const resetToken = crypto.randomBytes(32).toString('hex'); const resetHash = crypto.createHash('sha256').update(resetToken).digest('hex'); await prisma.passwordReset.create({ data: { tokenHash: resetHash, userId: user.id, expiresAt: new Date(Date.now() + 30 * 60 * 1000) // 30 minutes } }); // Send email with resetToken (not the hash) await sendResetEmail(email, resetToken); res.json({ message: 'If the email exists, a reset link was sent.' }); };
Security Checklist: Never log passwords or tokens. Use constant-time comparison for credentials. Hash refresh tokens and reset tokens before storage. Implement account lockout after 5 failed login attempts. Return identical error messages for "user not found" and "wrong password" to prevent enumeration.

Key Takeaways

  • Use bcrypt with cost factor 12+ for password hashing -- never MD5 or plain SHA
  • Short-lived access tokens (15 min) with rotating refresh tokens (7 days)
  • Store only token hashes in the database, never plaintext tokens
  • Identical error messages for missing users and wrong passwords prevent enumeration
  • Password reset tokens must be cryptographically random, time-limited, and single-use
