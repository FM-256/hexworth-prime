What is gRPC?

gRPC (Google Remote Procedure Call) is a high-performance RPC framework built on HTTP/2 and Protocol Buffers. Originally developed by Google to connect microservices, it is now a CNCF graduated project used by Netflix, Dropbox, Cisco, and many others for internal service-to-service communication.

Unlike REST, which sends JSON over HTTP/1.1, gRPC sends binary Protocol Buffer messages over HTTP/2. This yields significant performance gains: smaller payloads, multiplexed connections, header compression, and built-in streaming.

Binary Serialization Protobuf messages are 3-10x smaller than JSON equivalents and faster to parse
HTTP/2 Multiplexing Multiple RPC calls share a single TCP connection without head-of-line blocking
Strongly Typed The .proto file is the contract -- code generation ensures type safety across languages
Bidirectional Streaming Both client and server can stream messages independently over a single connection

Protocol Buffer Definitions

Proto3 is the current version of the Protocol Buffer language. A .proto file defines messages (data structures) and services (RPC methods).

// user_service.proto syntax = "proto3"; package userservice; service UserService { rpc GetUser (GetUserRequest) returns (User); rpc ListUsers (ListUsersRequest) returns (ListUsersResponse); rpc CreateUser (CreateUserRequest) returns (User); rpc StreamUpdates (StreamRequest) returns (stream UserEvent); } message User { string id = 1; string name = 2; string email = 3; Role role = 4; google.protobuf.Timestamp created_at = 5; } enum Role { ROLE_UNSPECIFIED = 0; ROLE_USER = 1; ROLE_ADMIN = 2; } message GetUserRequest { string id = 1; } message ListUsersRequest { int32 page_size = 1; string page_token = 2; }
Field Numbers Matter:

Field numbers in protobuf are part of the binary encoding. Once assigned and deployed, never reuse or change a field number. Deleting a field? Use the "reserved" keyword to prevent accidental reuse.

Four Streaming Patterns

PatternClientServerUse Case
Unary1 message1 messageStandard request/response (like REST)
Server Streaming1 messageStreamDownload large result sets, real-time feeds
Client StreamingStream1 messageFile upload, batch data ingestion
BidirectionalStreamStreamChat, multiplayer games, collaborative editing
// Service definition with all four patterns service ChatService { // Unary rpc GetRoom (GetRoomReq) returns (Room); // Server streaming rpc ListMessages (ListMsgReq) returns (stream Message); // Client streaming rpc UploadAttachments (stream FileChunk) returns (UploadResult); // Bidirectional streaming rpc Chat (stream ChatMessage) returns (stream ChatMessage); }

Code Generation

The protoc compiler generates client stubs and server interfaces from .proto files. Generated code handles serialization, HTTP/2 framing, and connection management.

# Generate Go server and client code $ protoc --go_out=. --go-grpc_out=. user_service.proto # Generate Python stubs $ python -m grpc_tools.protoc \ -I. --python_out=. --grpc_python_out=. \ user_service.proto # Generate TypeScript client $ npx grpc_tools_node_protoc \ --ts_out=./src --grpc_out=./src \ user_service.proto

Key Takeaways

  • gRPC uses Protocol Buffers for binary serialization -- 3-10x smaller than JSON
  • HTTP/2 multiplexing eliminates head-of-line blocking and connection overhead
  • Four streaming patterns cover every communication need from unary to full-duplex
  • Field numbers in protobuf are permanent -- never reuse or change them
  • Use gRPC for internal services, REST for public-facing APIs and browser clients
