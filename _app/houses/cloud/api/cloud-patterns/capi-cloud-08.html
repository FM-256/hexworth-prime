Cold Start Mitigation

Cold starts happen when a new execution environment must be initialized. The delay includes provisioning a container, loading the runtime, and initializing your code. For API backends, cold starts directly impact user-facing latency.

Provisioned Concurrency (Lambda) Keep N instances warm and ready. Eliminates cold starts but has a fixed hourly cost.
Premium Plan (Azure) Pre-warmed instances with VNet integration. No cold starts, predictable pricing.
Min Instances (Cloud Run) Set minimum instances to 1+ to keep containers warm. Pay for idle time.
Smaller Packages Reduce deployment package size. Use tree-shaking, exclude dev dependencies, use lighter runtimes.

Architecture Patterns

There are two dominant patterns for serverless API backends: function-per-route (one Lambda/Function per endpoint) and monolith-in-a-function (a full Express/FastAPI app inside a single function).

# Pattern 1: Function per route # GET /users --> getUsers Lambda # POST /users --> createUser Lambda # GET /orders --> getOrders Lambda # Each function is small, independently deployable, independently scalable # Pattern 2: Monolith in a function (or Cloud Run container) # ALL /api/* --> single Express.js application const app = express(); app.get('/api/users', getUsers); app.post('/api/users', createUser); app.get('/api/orders', getOrders); # All routes in one deployment, shared cold start

Cloud Run Advantage:

Cloud Run supports the monolith pattern naturally because it runs containers with concurrent request handling. A single Cloud Run instance can serve 1000 concurrent requests, making it more efficient than Lambda for API workloads with steady traffic.

Key Takeaways

  • Cloud Run handles concurrent requests per instance; Lambda processes one at a time by default
  • Cold starts matter for user-facing APIs -- use provisioned concurrency or min instances
  • Function-per-route is ideal for event-driven; monolith-in-function is better for REST APIs
  • At scale, Cloud Run is often cheaper than Lambda due to per-container concurrency
  • Choose based on traffic pattern: bursty/event-driven favors functions; steady traffic favors containers
