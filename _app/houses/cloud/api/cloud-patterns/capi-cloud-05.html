Managed Identity / Instance Profiles

The preferred authentication method for workloads running inside the cloud. The cloud platform automatically provides short-lived credentials to the VM, container, or function -- no keys to manage or rotate.

# AWS: Instance Profile - boto3 auto-discovers credentials import boto3 s3 = boto3.client('s3') # No credentials needed -- uses instance profile buckets = s3.list_buckets() # Azure: Managed Identity from azure.identity import DefaultAzureCredential credential = DefaultAzureCredential() # Auto-discovers managed identity # GCP: Application Default Credentials from google.cloud import storage client = storage.Client() # Auto-discovers attached service account
Never Do This:

Hardcoding access keys, client secrets, or service account key files in source code, environment variables on shared servers, or container images. Use managed identities, instance profiles, or secret managers instead.

Workload Identity Federation

Workload Identity Federation allows external identities (GitHub Actions, GitLab CI, AWS, Azure) to authenticate to cloud APIs without long-lived service account keys. It uses OIDC token exchange to grant short-lived credentials.

# GCP Workload Identity Federation with GitHub Actions # 1. GitHub OIDC token is automatically generated # 2. Token is exchanged for a GCP access token # 3. No service account key file needed - uses: google-github-actions/auth@v2 with: workload_identity_provider: 'projects/123/locations/global/workloadIdentityPools/github/providers/my-repo' service_account: 'deploy@my-project.iam.gserviceaccount.com'
AWS STS AssumeRoleWithWebIdentity Exchange an OIDC token (from GitHub, Azure, GCP) for temporary AWS credentials
Azure Federated Credentials Configure a managed identity to trust tokens from external OIDC providers
GCP Workload Identity Pool Map external identities to GCP service accounts via OIDC/SAML federation
Cross-Cloud Auth AWS workloads can authenticate to GCP/Azure APIs without storing keys in either cloud

Credential Rotation and Leak Detection

Despite best practices, credentials sometimes leak. Every cloud provider offers tools to detect and respond to leaked credentials quickly.

AWS IAM Access Analyzer, GuardDuty credential compromise alerts, GitHub secret scanning partnership
Azure Entra ID Conditional Access, Key Vault automatic rotation, Defender for Cloud alerts
GCP Security Command Center, SA key usage auditing, GitHub/GitLab leak notifications
General git-secrets pre-commit hooks, truffleHog scanning, mandatory MFA on root/admin accounts

Key Takeaways

  • Use managed identities (instance profiles, attached SAs) instead of long-lived keys
  • All three providers use the 169.254.169.254 metadata endpoint for credential delivery
  • Workload Identity Federation eliminates static credentials in CI/CD pipelines
  • Cross-cloud authentication is possible through OIDC token exchange
  • Always have a credential leak response plan: detect, revoke, rotate, audit
