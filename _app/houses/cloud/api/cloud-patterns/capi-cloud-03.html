Azure Resource Manager (ARM)

ARM is Azure's unified control plane. Every Azure resource -- VMs, databases, storage accounts, networking -- is managed through a single REST API at management.azure.com. All Azure tools (Portal, CLI, PowerShell, Terraform) ultimately call ARM APIs.

# ARM API structure GET https://management.azure.com /subscriptions/{subscriptionId} /resourceGroups/{resourceGroupName} /providers/Microsoft.Compute /virtualMachines/{vmName} ?api-version=2024-03-01 Authorization: Bearer eyJ0eXAi...

Every ARM request requires an api-version query parameter. Azure uses date-based versioning, so each API version is a specific release date. This prevents breaking changes from affecting existing clients.

Authentication: OAuth 2.0 with Entra ID

Azure APIs authenticate using OAuth 2.0 bearer tokens issued by Microsoft Entra ID (formerly Azure AD). The flow: request a token from the Entra ID token endpoint, then include it in the Authorization header.

# Step 1: Get OAuth token from Entra ID POST https://login.microsoftonline.com/{tenantId}/oauth2/v2.0/token Content-Type: application/x-www-form-urlencoded client_id={appId}& client_secret={secret}& scope=https://management.azure.com/.default& grant_type=client_credentials # Step 2: Use token in ARM request GET https://management.azure.com/subscriptions?api-version=2022-12-01 Authorization: Bearer eyJ0eXAi...

Azure RBAC

Azure Role-Based Access Control assigns permissions at various scopes (management group, subscription, resource group, or individual resource). Each role is a collection of allowed and denied operations on ARM API actions.

Owner Full access to all resources including the ability to assign roles to others
Contributor Create and manage all resources but cannot grant access to others
Reader View all resources but cannot make any changes
Custom Roles Define exactly which ARM API operations (Microsoft.Compute/virtualMachines/write) are allowed

Azure API Management (APIM)

APIM is Azure's full-lifecycle API management platform. It provides a developer portal, policy engine, analytics, and gateway capabilities for your custom APIs.

<!-- APIM Policy: Rate limiting + JWT validation --> <inbound> <rate-limit calls="100" renewal-period="60" /> <validate-jwt header-name="Authorization" failed-validation-httpcode="401"> <openid-config url="https://login.microsoftonline.com/{tenantId}/v2.0/.well-known/openid-configuration" /> <required-claims> <claim name="aud"> <value>api://my-api</value> </claim> </required-claims> </validate-jwt> </inbound>
APIM Tiers:

The Consumption tier is serverless and billed per API call (ideal for dev/test). The Developer tier includes a full developer portal. Standard and Premium add VNet integration and multi-region support.

Azure Functions HTTP Triggers

Azure Functions with HTTP triggers are the simplest way to build serverless API endpoints on Azure. Each function maps to a route and handles a specific HTTP method.

// Azure Function: HTTP trigger (Node.js) module.exports = async function (context, req) { const name = req.query.name || req.body?.name; if (!name) { context.res = { status: 400, body: "Name is required" }; return; } context.res = { status: 200, headers: { "Content-Type": "application/json" }, body: { message: `Hello, ${name}`, timestamp: new Date().toISOString() } }; };

Key Takeaways

  • ARM is Azure's unified control plane -- all resources managed through one REST API
  • Date-based api-version parameters prevent breaking changes across Azure API updates
  • OAuth 2.0 tokens from Entra ID authenticate all Azure API requests
  • APIM policies provide declarative rate limiting, JWT validation, and request transformation
  • Azure Functions HTTP triggers are the fastest path to serverless API endpoints on Azure
