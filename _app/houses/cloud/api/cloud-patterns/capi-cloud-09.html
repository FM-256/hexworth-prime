Defense in Depth for APIs

Cloud API security is layered: DDoS protection at the network edge, WAF rules before your application, authentication at the gateway, authorization in the service, input validation in the handler, and output encoding in the response. Each layer catches what the previous one missed.

Layer 1: Edge / CDN DDoS mitigation (AWS Shield, Azure DDoS Protection, Cloud Armor), geo-blocking
Layer 2: WAF OWASP rule sets, SQL injection blocking, XSS filtering, bot detection
Layer 3: Gateway Rate limiting, authentication, request validation, IP whitelisting
Layer 4: Application Authorization, business logic validation, input sanitization, output encoding

OWASP API Security Top 10

The OWASP API Security Top 10 (2023) identifies the most critical API security risks. These are not theoretical -- they are the vulnerabilities most commonly exploited in real-world API breaches.

RankRiskMitigation
API1Broken Object Level AuthorizationCheck that the user owns the resource in every handler
API2Broken AuthenticationUse OAuth 2.0, enforce token expiration, disable old API keys
API3Broken Object Property Level AuthorizationNever return fields the user should not see; filter at the API layer
API4Unrestricted Resource ConsumptionRate limiting, pagination limits, request size limits
API5Broken Function Level AuthorizationVerify admin permissions on admin endpoints, not just authentication
Most Common Real-World Failure:

Broken Object Level Authorization (BOLA/IDOR). Attacker changes /api/users/42/orders to /api/users/43/orders and sees another user's data. The fix: always verify the authenticated user has access to the specific resource being requested.

Audit Logging

Every API call to cloud provider APIs should be logged for security monitoring, compliance, and incident response.

AWS CloudTrail Logs all API calls to AWS services. Management events free; data events extra cost.
Azure Activity Log Logs control plane operations. Diagnostic settings route to Log Analytics / SIEM.
GCP Cloud Audit Logs Admin Activity (always on, free), Data Access (must enable, paid), System Events.
Your Custom APIs Log who, what, when, from where for every API call. Correlate with cloud provider logs.

Key Takeaways

  • Cloud API security is layered: edge, WAF, gateway, and application -- each layer matters
  • All three providers offer managed WAF services with OWASP rule sets
  • BOLA (Broken Object Level Authorization) is the most common real-world API vulnerability
  • Rate limiting at the infrastructure level prevents resource exhaustion attacks
  • Enable audit logging on all cloud API activity -- it is essential for incident response
