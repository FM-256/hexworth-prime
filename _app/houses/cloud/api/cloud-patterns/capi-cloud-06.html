IaC is Just API Calls

Every IaC tool is a translation layer. Terraform reads HCL and calls cloud provider REST APIs. CloudFormation reads JSON/YAML and calls AWS APIs. Bicep compiles to ARM templates and calls Azure ARM APIs. Understanding this relationship is critical for debugging.

# Terraform HCL resource "aws_s3_bucket" "data" { bucket = "my-data-bucket-2024" } # What Terraform actually does: # 1. Reads state to check if bucket exists # 2. Calls AWS S3 API: PUT / HTTP/1.1 # Host: my-data-bucket-2024.s3.amazonaws.com # Authorization: AWS4-HMAC-SHA256 ... # 3. Waits for success response # 4. Updates state file with the new resource

Terraform Provider Architecture

Terraform providers are plugins that implement CRUD operations for each resource type by wrapping cloud API calls. The provider translates HCL resource blocks into the correct API calls for create, read, update, and delete.

Plan Phase Reads current state via API (GET), compares to desired state, computes diff
Apply Phase Executes create (POST), update (PUT/PATCH), or delete (DELETE) API calls
State Refresh Calls GET APIs for every managed resource to detect drift from desired state
Import Calls GET API to read existing resource attributes and write them to state

CloudFormation and ARM Templates

AWS CloudFormation and Azure ARM templates use a different model: you submit the entire desired state to the cloud provider's orchestration service, which calculates the diff and executes API calls on your behalf.

# CloudFormation: submitted to AWS, which executes API calls Resources: MyBucket: Type: AWS::S3::Bucket Properties: BucketName: my-data-bucket-2024 # Bicep (compiles to ARM JSON, submitted to Azure) resource storageAccount 'Microsoft.Storage/storageAccounts@2023-01-01' = { name: 'mystorageaccount' location: 'eastus' sku: { name: 'Standard_LRS' } kind: 'StorageV2' }

API Rate Limits and IaC at Scale

Large Terraform deployments can trigger API rate limits. A plan refreshing 500 resources sends 500+ GET requests in rapid succession. AWS services have per-account, per-region rate limits that Terraform can easily exceed.

Mitigation Strategies:

Use -parallelism=5 to reduce concurrent API calls. Use -refresh=false when you know state is current. Split large configurations into smaller state files. Enable exponential backoff in the provider configuration.

Key Takeaways

  • Every IaC operation is ultimately an API call to the cloud provider
  • Terraform executes API calls client-side; CloudFormation/ARM execute server-side
  • State refresh sends a GET API call for every managed resource -- this triggers rate limits at scale
  • Debug IaC failures by examining the underlying API error response
  • Reduce parallelism and split state files to mitigate API throttling on large deployments
