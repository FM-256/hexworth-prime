Everything is an API

In cloud computing, every action -- launching a VM, creating a database, changing a firewall rule -- is an API call. The web console is a GUI that calls APIs. The CLI is a wrapper that calls APIs. Terraform and CloudFormation are tools that call APIs. Understanding this architecture is fundamental to working with any cloud provider.

Cloud providers build their infrastructure API-first: the API exists before the console UI. When you click "Create Instance" in the AWS console, the browser sends a signed HTTP request to the EC2 API endpoint. The console is just another API client.

Web Console GUI that translates clicks into API calls -- the most user-friendly but least automatable
CLI Tools aws cli, az cli, gcloud -- command-line wrappers around the same APIs
SDKs Language-specific libraries (boto3, Azure SDK, google-cloud-python) for programmatic access
Raw HTTP APIs Direct REST/RPC calls with signed HTTP requests -- maximum control, maximum complexity

Control Plane vs Data Plane

Every cloud service has two distinct API surfaces: the control plane (managing infrastructure) and the data plane (using infrastructure). Understanding this split is critical for security architecture and troubleshooting.

AspectControl PlaneData Plane
PurposeCreate, configure, delete resourcesRead/write data within resources
Example (S3)CreateBucket, PutBucketPolicyGetObject, PutObject
Example (RDS)CreateDBInstance, ModifyDBInstanceSQL queries over TCP/3306
Auth modelIAM roles and policiesIAM + resource policies + network ACLs
Traffic volumeLow (config changes)High (application traffic)
Audit loggingCloudTrail / Activity Log / Audit LogData access logs (often separate)
Security Implication:

Control plane access is the keys to the kingdom. An attacker with control plane access can delete databases, exfiltrate secrets, and modify security rules. Data plane access is limited to the data within specific resources. Always apply least-privilege separately for each plane.

Eventual Consistency in Cloud APIs

Cloud APIs are distributed systems, and distributed systems have consistency trade-offs. When you create a resource via the control plane API, it may take seconds to minutes before the resource is visible to all other API calls.

AWS IAM Eventually consistent globally. New policies may take up to 60 seconds to propagate across regions.
Azure RBAC Role assignments can take up to 5 minutes to propagate. Plan for delays in automation scripts.
GCP IAM Permission changes propagate in under 60 seconds but are not instantaneous.
S3 / GCS Strong read-after-write consistency for objects (improved from eventual in 2020).

Key Takeaways

  • Everything in the cloud is an API call -- the console, CLI, SDKs, and IaC tools are all API clients
  • Control plane manages infrastructure; data plane operates on data within resources
  • AWS uses SigV4 signatures; Azure and GCP use OAuth 2.0 bearer tokens
  • Cloud APIs are eventually consistent -- automation must account for propagation delays
  • Separate security policies for control plane and data plane access
