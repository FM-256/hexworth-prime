AWS API Families

AWS does not have a single API style. Different services use different protocols, a legacy of organic growth over two decades. Understanding the three main families helps when reading raw API docs or debugging SDK issues.

QueryGET/POST with URL paramsEC2, SQS, IAM, STSAction=DescribeInstances&Version=2016-11-15

Signature Version 4 (SigV4)

Every AWS API call must be signed with SigV4. This process uses your access key to create an HMAC-SHA256 signature over the request headers, URI, query parameters, and body. The signature proves your identity and ensures the request has not been tampered with in transit.

# SigV4 signing process (simplified) Step 1: Create canonical request HTTPMethod + '\n' + URI + '\n' + QueryString + '\n' + CanonicalHeaders + '\n' + SignedHeaders + '\n' + SHA256(payload) Step 2: Create string to sign Algorithm + '\n' + Timestamp + '\n' + CredentialScope + '\n' + SHA256(CanonicalRequest) Step 3: Calculate signature DateKey = HMAC-SHA256("AWS4" + SecretKey, Date) RegionKey = HMAC-SHA256(DateKey, Region) ServiceKey = HMAC-SHA256(RegionKey, Service) SigningKey = HMAC-SHA256(ServiceKey, "aws4_request") Signature = HMAC-SHA256(SigningKey, StringToSign) Step 4: Add to Authorization header Authorization: AWS4-HMAC-SHA256 Credential=AKIA.../scope, SignedHeaders=host;x-amz-date, Signature=hex(signature)
Never Sign Manually:

SDKs (boto3, AWS SDK for JS, etc.) handle SigV4 automatically. Understanding the process is important for debugging, but you should never implement signing from scratch in production code.

AWS API Gateway

API Gateway is AWS's managed service for creating, publishing, and securing APIs. It supports REST APIs, HTTP APIs (cheaper, faster), and WebSocket APIs. It sits in front of your backend (Lambda, EC2, any HTTP endpoint) and handles authentication, throttling, and request transformation.

REST API Full-featured: request validation, caching, WAF integration, API keys, usage plans
HTTP API Lighter, faster, cheaper (70% less). Supports JWT auth and Lambda proxy integration.
Lambda Integration Proxy mode passes the full request to Lambda; non-proxy allows request/response mapping
Custom Authorizers Lambda authorizer functions validate tokens and return IAM policies per request
# Lambda proxy integration: event structure { "httpMethod": "POST", "path": "/api/users", "headers": { "Authorization": "Bearer eyJ..." }, "body": "{\"name\": \"Alice\"}", "queryStringParameters": { "role": "admin" }, "requestContext": { "authorizer": { "claims": { "sub": "user-42" } } } }

IAM Authorization for APIs

AWS offers three authorization models for API Gateway: IAM authorization (SigV4-signed requests), Cognito User Pools (JWT tokens), and Lambda Authorizers (custom logic). For internal service-to-service calls, IAM auth with SigV4 is the standard pattern.

# IAM policy allowing specific API Gateway methods { "Effect": "Allow", "Action": "execute-api:Invoke", "Resource": [ "arn:aws:execute-api:us-east-1:123456789012:abc123/prod/GET/users", "arn:aws:execute-api:us-east-1:123456789012:abc123/prod/POST/users" ] }

Key Takeaways

  • AWS uses three API protocol families: Query, JSON RPC, and REST-XML
  • SigV4 signs every request with HMAC-SHA256 -- SDKs handle this automatically
  • API Gateway HTTP APIs are 70% cheaper than REST APIs for most workloads
  • Lambda proxy integration passes the full HTTP request as the event object
  • IAM authorization with SigV4 is the standard for internal service-to-service calls
