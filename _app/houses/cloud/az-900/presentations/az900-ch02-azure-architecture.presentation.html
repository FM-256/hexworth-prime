Azure Regions
Azure has 60+ regions across 140+ countries. Each region is a set of datacenters connected by a low-latency network.
What Is a Region?
A geographical area containing one or more datacenters. You choose a region when deploying resources. Pick the region closest to your users for lower latency, and check that the services you need are available in that region.
Region Pairs
Most regions are paired with another region 300+ miles away in the same geography. Azure prioritizes one region in each pair during updates. If a region fails, services automatically fail over to the paired region. Example: East US ↔ West US.
Sovereign Regions
Physically and logically isolated from the main Azure cloud. US Government regions (Virginia, Arizona, Texas) serve federal workloads. China regions are operated by 21Vianet. You cannot transfer data or subscriptions between sovereign and public Azure.
Exam Tip
Know that region pairs exist for disaster recovery, that sovereign regions are isolated, and that not all Azure services are available in every region. The exam may ask why you would choose one region over another.
Slide 3 of 12
Availability Zones
Physically separate datacenters within a single Azure region. Each zone has independent power, cooling, and networking.
Zone-Redundant Services
The platform automatically replicates across zones. Examples: Azure SQL Database (zone-redundant), Zone-Redundant Storage (ZRS). You do not pick a zone — Azure handles it. Best for high availability with minimal configuration.
Zonal Services
You pin a resource to a specific zone. Examples: Virtual Machines, Managed Disks. To get zone redundancy, you must deploy multiple instances across different zones yourself and use a load balancer in front.
Key Facts
Each enabled region has a minimum of 3 separate availability zones. Zones protect against datacenter-level failures (fire, flood, power outage). They do NOT protect against region-wide disasters — that is what region pairs are for.
Exam Alert
Not all regions support availability zones. The exam calls these "availability zone-enabled regions." If a region does not support zones, you rely on availability sets for VM redundancy within a single datacenter.

Resource Groups
Logical containers that hold related Azure resources. Every resource must live in exactly one resource group.
One RG Per Resource
Every Azure resource belongs to exactly one resource group. A resource cannot span multiple groups. You can move resources between groups, but at any given moment it is in exactly one.
Lifecycle Management
Deleting a resource group deletes every resource inside it. This makes RGs ideal for grouping by lifecycle: deploy together, delete together. Dev/test environments often use a single RG for easy teardown.
Scope for Permissions
RBAC roles, tags, locks, and policies can all be applied at the resource group level and will be inherited by all resources within. This is the most common scope for assigning permissions in Azure.
Exam Tip
Resource groups themselves have a location (metadata storage), but the resources inside can be in any region. The RG location does not restrict where resources are deployed.
Slide 5 of 12
Subscriptions and Management Groups
Subscriptions are billing and access control boundaries. Management groups create a hierarchy above subscriptions for governance at scale.
Subscriptions
Billing boundary: each subscription generates its own invoice. Access control boundary: RBAC policies are applied at the subscription level. Organizations often use separate subscriptions for dev, test, and production to isolate costs and permissions.
Management Groups
Organize subscriptions into a hierarchy. Apply Azure Policy and RBAC at the management group level and it inherits down to all child subscriptions and resource groups. Supports up to 6 levels of depth (not counting the root management group).
Key Concept
The hierarchy is: Root Management Group → Management Groups → Subscriptions → Resource Groups → Resources. Policies and access controls applied at any level inherit downward to all children.

Azure Compute Services
From full VMs to serverless functions — Azure offers a compute model for every workload pattern.
Virtual Machines
IaaS. Full control of OS, patches, and runtime. Use for legacy apps, custom OS images, or when you need root access. Scale with VM Scale Sets for auto-scaling groups of identical VMs.
App Service
PaaS. Deploy web apps, REST APIs, or mobile backends without managing infrastructure. Supports .NET, Java, Node.js, Python, PHP. Built-in autoscaling, CI/CD, and custom domains with TLS.
Azure Functions
Serverless. Run event-driven code without provisioning servers. Pay only for execution time. Triggers include HTTP requests, timers, queue messages, and blob changes. Ideal for microservices and automation.
Containers Quick Reference
Azure Container Instances (ACI) — run a single container quickly, no orchestration needed. Great for simple tasks and burst workloads. Azure Kubernetes Service (AKS) — managed Kubernetes for orchestrating many containers at scale. Use when you need service discovery, load balancing, rolling updates, and self-healing.
Slide 7 of 12
Azure Networking Services
Virtual networks, gateways, and firewalls — the backbone that connects all your Azure resources.
Virtual Networks (VNets)
The fundamental networking building block. Provides isolation, segmentation, and connectivity for Azure resources. VNets are scoped to a single region. Use VNet peering to connect VNets across regions.
VPN Gateway
Sends encrypted traffic between an Azure VNet and an on-premises network over the public internet (site-to-site) or between a single device and a VNet (point-to-site). Lower cost than ExpressRoute.
ExpressRoute
A private, dedicated connection between your on-premises network and Azure that does NOT traverse the public internet. Higher bandwidth, lower latency, more consistent than VPN. Used for mission-critical workloads.
NSG vs Azure Firewall
Network Security Groups (NSGs) filter traffic at the subnet or NIC level using simple allow/deny rules (L3-L4). Azure Firewall is a fully managed, stateful firewall with L3-L7 filtering, FQDN rules, and threat intelligence. Use NSGs for basic segmentation, Azure Firewall for enterprise perimeter protection.
Slide 8 of 12
Azure Storage Services
Five core storage types and four redundancy options. Every Azure subscription can create storage accounts to hold all of these.
Blob Storage
Object storage for unstructured data: images, videos, backups, logs. Three access tiers: Hot (frequent access, higher storage cost), Cool (infrequent, 30-day min), Archive (rare access, 180-day min, offline).
Azure Files
Fully managed file shares accessible via SMB or NFS protocols. Mount them on Windows, Linux, or macOS. Can replace or supplement on-premises file servers. Supports Azure File Sync for caching.
Redundancy Summary
LRS: 3 copies, 1 datacenter. ZRS: 3 copies, 3 zones. GRS: 6 copies, 2 regions. GZRS: ZRS in primary + LRS in secondary region. Choose based on your durability and availability requirements.
Exam Tip
The exam frequently tests the difference between storage redundancy options. Remember: LRS is cheapest but least durable. GZRS is most durable but most expensive. GRS and GZRS replicate asynchronously to a paired region.

Azure Identity Services
Microsoft Entra ID is the cloud-based identity and access management service at the heart of Azure security.
Authentication vs Authorization
Authentication (AuthN) verifies who you are — username, password, MFA. Authorization (AuthZ) determines what you can do — RBAC roles, permissions. Microsoft Entra ID handles both. Authentication always happens first.
SSO and MFA
Single Sign-On (SSO) lets users authenticate once and access multiple applications without re-entering credentials. Multi-Factor Authentication (MFA) adds a second verification method (phone, authenticator app, hardware key) beyond just a password.
Critical Terminology
Microsoft renamed "Azure Active Directory" to Microsoft Entra ID in 2023. The AZ-900 exam uses the new name. Do NOT use "Azure AD" on the exam. If you see "Azure Active Directory" in older materials, mentally translate it to Microsoft Entra ID.
Conditional Access
Conditional Access policies are if-then rules: IF a user meets certain conditions (location, device compliance, risk level), THEN enforce specific controls (allow, block, require MFA). This is the primary tool for Zero Trust security in Azure.
Slide 10 of 12
Azure Database Services
Managed relational and non-relational databases — from single-node SQL to globally distributed NoSQL.
Azure SQL Database
Fully managed relational database based on the latest SQL Server engine. Supports T-SQL, built-in intelligence for performance tuning, automatic backups, and geo-replication. Best choice for existing SQL Server workloads moving to the cloud.
Azure Cosmos DB
Globally distributed, multi-model database with guaranteed single-digit millisecond latency at the 99th percentile. Supports 5 APIs: SQL (Core), MongoDB, Cassandra, Gremlin (graph), and Table. Data is automatically replicated to any Azure region you select.
Open-Source Databases
Azure Database for MySQL and Azure Database for PostgreSQL provide fully managed, community-edition engines with built-in high availability, automated backups, and scaling. Ideal for migrating existing MySQL/PostgreSQL workloads without code changes.
Exam Tip
The exam loves Cosmos DB scenarios. If the question mentions "global distribution," "low latency," "multi-model," or "multiple consistency levels" — Cosmos DB is the answer. If it mentions T-SQL or SQL Server compatibility — Azure SQL Database.
Slide 11 of 12
Marketplace, IoT, and AI Services
Third-party solutions, Internet of Things, and artificial intelligence — the expanding edge of the Azure ecosystem.
Azure Marketplace
An online store for buying and deploying certified solutions built on or for Azure. Includes VM images, SaaS applications, container images, and ARM templates from Microsoft and third-party vendors. All billed through your existing Azure subscription.
IoT Hub vs IoT Central
IoT Hub is PaaS — you build custom IoT solutions with full control over device communication, routing, and processing. IoT Central is SaaS — a ready-made IoT dashboard that handles device management and visualization with minimal custom code.
Azure AI Services
Pre-built APIs for vision (image analysis, OCR), speech (speech-to-text, text-to-speech), language (sentiment, translation), and decision (anomaly detection, personalizer). Azure Machine Learning is the full platform for building, training, and deploying custom models.
Quick Clarification
"Azure Cognitive Services" was renamed to Azure AI Services in 2023. The exam uses the new name. Azure OpenAI Service provides access to GPT and DALL-E models through Azure's enterprise security and compliance infrastructure.

Chapter 2 Summary
Azure's physical infrastructure underpins logical organization, which in turn supports a vast catalog of compute, network, storage, identity, and data services.
1Regions and Availability Zones are the physical foundation. Regions are geographic areas with paired DR partners. Availability Zones are isolated datacenters within a region (3+ per enabled region). Sovereign regions (US Gov, China) are completely isolated.
2Organization follows a strict hierarchy. Management Groups → Subscriptions → Resource Groups → Resources. Policies and RBAC inherit downward. Every resource lives in exactly one resource group, and every RG lives in exactly one subscription.
3Compute spans the full spectrum. VMs (IaaS, full control), App Service (PaaS, managed hosting), Azure Functions (serverless, event-driven), ACI (quick containers), and AKS (Kubernetes orchestration).
4Storage redundancy is a top exam topic. LRS (3 copies, 1 DC), ZRS (3 copies, 3 zones), GRS (6 copies, 2 regions), GZRS (best of both). Blob tiers: Hot, Cool, Archive. Know which redundancy to pick for each scenario.
5Identity = Microsoft Entra ID. SSO, MFA, Conditional Access, and RBAC all live here. Cosmos DB is the go-to for global, low-latency, multi-model data. Marketplace, IoT, and AI round out the service catalog.
