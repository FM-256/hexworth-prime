What is Cloud Computing?
The delivery of computing services — servers, storage, databases, networking, software, analytics, and intelligence — over the internet to offer faster innovation, flexible resources, and economies of scale.
On-Demand Delivery
Cloud computing delivers compute, storage, and networking resources over the internet. Instead of buying and maintaining physical servers, you rent capacity from a cloud provider like Microsoft Azure. Resources are provisioned in minutes, not weeks.
Pay-As-You-Go Pricing
You pay only for what you use. Run a VM for an hour, pay for an hour. Stop it, stop paying. This consumption-based model eliminates the need for large upfront capital investments in hardware and data center space.
Shared Infrastructure
Cloud providers achieve economies of scale by pooling resources across thousands of customers. This lowers costs for everyone. Azure operates 60+ regions worldwide, giving you access to a global infrastructure you could never build or afford on your own.
Exam Tip
Cloud computing is defined by NIST as a model for enabling ubiquitous, on-demand network access to a shared pool of configurable computing resources that can be rapidly provisioned and released with minimal management effort.

Benefits of Cloud Computing
Six core benefits tested on the AZ-900 exam. Each one is a reason organizations move to the cloud.
High Availability
Azure SLAs guarantee uptime (99.9% to 99.999%). Services keep running even when components fail. Availability Zones spread resources across separate data centers in a region.
Scalability
Scale vertically (bigger VM) or horizontally (more VMs). Increase capacity to handle peak loads and scale back down when demand drops. You never pay for idle capacity you do not need.
Elasticity
Automatically adjust resources in real time based on demand. Auto-scale rules add VM instances during a traffic spike and remove them when traffic subsides. No manual intervention required.
Agility
Deploy and configure cloud resources quickly as business needs change. What used to take weeks (procure, rack, cable, configure) now takes minutes. Rapid experimentation with low risk.
Geo-Distribution
Deploy apps and data to Azure regions around the world. Users connect to the nearest region for lowest latency. Azure has 60+ regions in 140+ countries.
Disaster Recovery
Built-in backup, replication, and geo-redundancy options. Azure Site Recovery can replicate VMs to a secondary region. If a disaster strikes, failover happens within minutes.

Shared Responsibility Model
Who manages what depends on the cloud service type. Microsoft always manages the physical infrastructure. Your responsibility increases from SaaS to PaaS to IaaS.
The shared responsibility model is a core exam concept. As you move from IaaS to PaaS to SaaS, your responsibility decreases and Microsoft's increases. But you always retain responsibility for your data, endpoints, accounts, and access management regardless of the service type.
Key Rule
Data and identity are always your responsibility. Even with SaaS (like Microsoft 365), you must manage who has access, what data is shared, and how accounts are secured. Microsoft secures the platform; you secure the content and access.

Cloud Service Types: IaaS
Infrastructure as a Service — the most flexible cloud service model. You rent virtualized hardware and manage everything from the OS up.
Most Control
IaaS gives you maximum control over the computing resources. You choose the OS, install software, configure networking, and manage security patches. Azure provides the hardware; you handle the rest from the operating system up.
Most Responsibility
With great control comes great responsibility. You must patch the OS, configure firewalls, manage antivirus, handle backups, and maintain the application stack. If you skip a critical security update, that is on you.
Azure IaaS Examples
Azure Virtual Machines, Azure Virtual Network, Azure Disk Storage, Azure Blob Storage, Network Security Groups, Load Balancers. These are the building blocks you assemble yourself.
Slide 6 of 12
Cloud Service Types: PaaS
Platform as a Service — a complete development and deployment environment in the cloud. Focus on your code, not on managing the underlying infrastructure.
Focus on Code
PaaS eliminates the need to manage operating systems, middleware, and runtime environments. You deploy your application code, and Azure handles the infrastructure beneath it. This drastically reduces time-to-market and operational overhead.
Built-In Features
PaaS services come with built-in high availability, auto-scaling, security patching, and monitoring. Azure App Service, for example, provides TLS certificates, custom domains, deployment slots, and CI/CD integration out of the box.
Less Control, Less Work
You cannot RDP/SSH into the underlying servers. You cannot install arbitrary software or customize the OS. This trade-off is intentional: less control means less operational burden, fewer misconfigurations, and faster delivery.
Exam Tip
PaaS is the best choice when the question describes a development team that wants to deploy code without managing servers. If you see "deploy a web application without managing the underlying OS," the answer is PaaS (Azure App Service).
Slide 7 of 12
Cloud Service Types: SaaS
Software as a Service — fully built applications delivered over the internet. Sign in and start using. No installation, no infrastructure, no maintenance.
Ready to Use
SaaS applications are fully managed by the provider. You access them through a web browser or app. No server to configure, no OS to patch, no runtime to install. Microsoft 365, Dynamics 365, and Microsoft Teams are prime examples.
Least Control
You cannot customize the underlying platform. Configuration is limited to what the application exposes through its settings. You control your data and user access, but the application architecture, hosting, scaling, and patching are entirely Microsoft's domain.
Pay Per User
SaaS typically uses per-user, per-month pricing. No hardware investment, no IT staff to maintain servers. Ideal for organizations that want productivity tools without infrastructure overhead. Scale by adding or removing user licenses.
Slide 8 of 12
IaaS vs PaaS vs SaaS Comparison
Three service models, three levels of control and responsibility. The right choice depends on how much you want to manage versus how much you want the provider to manage.
When to use each model
Choose IaaS When
You need full control over the OS and software. Migrating existing on-premises workloads (lift-and-shift). Running legacy applications that require specific OS configurations. Building custom network architectures.
Choose PaaS When
Your team wants to focus on building applications, not managing servers. Deploying web apps, APIs, or microservices. Using managed databases. Running event-driven code with serverless compute (Azure Functions).
Choose SaaS When
You need a complete, ready-to-use application. Email and collaboration (Microsoft 365). Enterprise resource planning (Dynamics 365). No development team required. Pay per user, start immediately.
Exam Pattern
AZ-900 frequently presents a scenario and asks you to identify the correct service type. Key signal: "without managing the underlying infrastructure" = PaaS. "Rent virtual machines" = IaaS. "Use an application through a browser" = SaaS.

Public Cloud
Cloud resources owned and operated by a third-party provider and delivered over the public internet. Azure, AWS, and GCP are all public clouds.
Multi-Tenant Architecture
Public cloud resources are shared across multiple organizations (tenants). Your data is logically isolated through virtualization and identity controls, but the underlying physical hardware is shared. This pooling enables massive economies of scale.
No Capital Expenditure
You do not purchase hardware. You do not build data centers. Resources are provisioned on demand and billed based on consumption. This eliminates upfront investment and transfers infrastructure risk to the cloud provider.
Rapid Provisioning
Applications can be deployed and decommissioned quickly. You can spin up hundreds of VMs in minutes for a load test and tear them down afterward. This agility is impossible with traditional on-premises procurement cycles.
Key Fact
Azure is a public cloud. When the exam says "public cloud," it means resources accessible over the public internet, owned by a third party, and shared among multiple tenants with logical isolation.
Slide 10 of 12
Private Cloud
Cloud infrastructure dedicated to a single organization. Can be hosted on-premises or by a third party. Provides full control at a higher cost.
Dedicated Infrastructure
A private cloud is used exclusively by one organization. Hardware is not shared with other tenants. This can be on-premises in your own data center or hosted by a third-party provider like Rackspace or Azure Stack HCI in a co-location facility.
Full Control, Full Cost
You control hardware procurement, network configuration, security policies, and compliance. But you also bear the full cost of purchasing, maintaining, and eventually replacing that hardware. IT staff must manage every layer of the stack.
Compliance and Security
Organizations in regulated industries (healthcare, finance, government, defense) often require private cloud to meet strict data sovereignty and compliance requirements. Data never leaves the organization's controlled boundary.
Slide 11 of 12
Hybrid Cloud
Combines on-premises (or private cloud) infrastructure with public cloud resources. Data and applications can move between the two environments.
Best of Both Worlds
Hybrid cloud lets organizations keep sensitive data on-premises while leveraging the public cloud for burst capacity, disaster recovery, and global reach. Run legacy apps locally and modern workloads in Azure. Azure Arc extends Azure management to on-premises resources.
Connectivity Options
VPN Gateway: encrypted tunnel over the public internet. ExpressRoute: private, dedicated connection that bypasses the public internet for higher bandwidth, lower latency, and more consistent performance. Both connect your on-premises network to Azure virtual networks.
Common Scenarios
Cloud bursting (scale to Azure during peak demand). Gradual migration (move workloads one at a time). Data sovereignty (keep data local, compute in cloud). Disaster recovery (replicate on-premises to Azure as a backup site).
Exam Tip
When a question describes an organization that wants to "keep some resources on-premises and use Azure for additional capacity," the answer is hybrid cloud. Azure Arc is the key service for managing hybrid environments from a single pane of glass.

CapEx vs OpEx + Key Takeaways
Cloud computing shifts IT spending from capital expenditure (buying hardware) to operational expenditure (paying for usage). This is a fundamental economic shift the AZ-900 exam tests heavily.
CapEx vs OpEx Breakdown
Capital Expenditure (CapEx)
Upfront spending on physical infrastructure: servers, networking equipment, storage arrays, data center space. The cost is recognized over the useful life of the asset (depreciation). Requires accurate forecasting of future needs. If you over-provision, money is wasted on idle hardware. If you under-provision, scaling takes weeks.
Operational Expenditure (OpEx)
Ongoing spending for services used on a consumption basis. Cloud computing is OpEx: you pay monthly for what you consume. No depreciation, no hardware lifecycle management. Costs scale linearly with usage. Budgets can be adjusted monthly rather than locked in for 3-5 year hardware refresh cycles.
5 Key Facts for the AZ-900 Exam
1Cloud computing is the delivery of IT services over the internet using a pay-as-you-go pricing model. No upfront hardware purchase required.
2Three service types: IaaS (most control, most responsibility), PaaS (focus on code), SaaS (ready-to-use applications). Your responsibility decreases from IaaS to SaaS.
3Three deployment models: Public cloud (shared, multi-tenant), Private cloud (dedicated, single-tenant), Hybrid cloud (connects both via VPN/ExpressRoute).
4Shared responsibility: Microsoft always manages the physical infrastructure. You always manage your data and access. Everything in between depends on IaaS/PaaS/SaaS.
5CapEx vs OpEx: Traditional IT is CapEx (buy hardware). Cloud is OpEx (pay for usage). Cloud eliminates upfront costs and shifts IT spending to a consumption-based model.
