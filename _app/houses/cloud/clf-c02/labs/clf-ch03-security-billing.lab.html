Phase 1 — Identity Foundations (IAM)
Task 1
Inspect Your Identity
Run aws sts get-caller-identity to confirm which AWS account and identity you are working under -- the billing and resource boundary for everything you create.
Task 2
Create an IAM User
Run aws iam create-user --user-name secops-analyst to create a named IAM identity instead of sharing root credentials.
Task 3
Create a Least-Privilege Policy
Run aws iam create-policy --policy-name S3ReadOnlyLeastPriv --policy-document file://policies/s3-read-only.json to define exactly what the user is allowed to do.
Task 4
Attach the Policy to the User
Run aws iam attach-user-policy --user-name secops-analyst --policy-arn <arn> to grant the permissions. A policy does nothing until it is attached.
Task 5
List IAM Users
Run aws iam list-users to verify the account's identity inventory. Auditing who exists is step one of access review.
Phase 2 — Security Services
Task 6
Verify Audit Logging
Run aws cloudtrail describe-trails to confirm every API call in this account is being recorded for audit and forensics.
Task 7
Confirm Threat Detection
Run aws guardduty list-detectors to confirm Amazon GuardDuty is actively watching for anomalous or malicious account activity.
Phase 3 — Pricing and Billing
Task 8
Estimate EC2 Pricing
Run aws pricing get-products --service-code AmazonEC2 --filters "Type=TERM_MATCH,Field=instanceType,Value=t3.medium" --region us-east-1 to query On-Demand pricing directly from the AWS Price List API.
Task 9
Review Cost Explorer Data
Run aws ce get-cost-and-usage --time-period Start=2026-06-01,End=2026-06-30 --granularity MONTHLY --metrics UnblendedCost to see actual spend broken down by service.
Task 10
Create a Budget with an Alert
Run aws budgets create-budget --account-id 123456789012 --budget file://budgets/monthly-budget.json to set a spending guardrail before costs get away from you.
Task 11
Verify the Budget
Run aws budgets describe-budgets --account-id 123456789012 to confirm the budget was created correctly. Always verify governance controls after applying them.
Phase 4 — Support and Cleanup
Task 12
Review Support Severity Levels
Run aws support describe-severity-levels to see how AWS Support classifies case urgency, from "low" to "critical".
Task 13
Detach the Policy and Delete the User
Run aws iam detach-user-policy --user-name secops-analyst --policy-arn <arn> then aws iam delete-user --user-name secops-analyst. IAM will not delete a user with attached policies -- that is by design.
