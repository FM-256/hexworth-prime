The Shared Responsibility Model
AWS secures the cloud. You secure what you put in it. Exactly where the line falls shifts depending on which service you use.
EC2 (IaaS)
AWS secures the hypervisor and hardware. You patch the guest OS, configure security groups, and manage every layer above the virtual machine.
RDS / Lambda (Managed)
AWS patches the database engine or runtime. You still own your data, your IAM permissions, and your network access controls.
S3 (Storage)
AWS secures the storage infrastructure and durability. You control bucket policies, encryption, and who can read or write objects.
Exam Rule
Your responsibility never disappears -- it shifts. Regardless of the service, the customer always owns data, identities, and access management. AWS never sees a scenario answer that says "the cloud handles security for you."

IAM Fundamentals
AWS Identity and Access Management controls who can do what. Four building blocks: users, groups, roles, and policies.
Users
A persistent identity for one person or application. Has long-term credentials (password, access keys). Create one per human -- never share.
Groups
A collection of users. Attach a policy once to a group instead of to every user individually. Groups cannot be nested and cannot be assumed by a resource.
Roles
A temporary identity assumed by a user, application, or AWS service (like EC2 or Lambda). No long-term credentials -- short-lived tokens only. Preferred over embedding access keys in code.
Policies
JSON documents that define permissions. Attached to users, groups, or roles. Nothing has any access until a policy grants it -- deny is the default.
Exam Tip
The root user has unrestricted access, including the ability to close the account. Enable MFA on root immediately, do not create access keys for it, and use it only for the handful of tasks that genuinely require root (like changing the support plan).
Slide 4 of 14
IAM Policies & Least Privilege
A policy is a JSON document with a Version and one or more Statements. Grant only the permissions a job actually requires.
Least Privilege
{ "Version": "2012-10-17", "Statement": [ { "Effect": "Allow", "Action": [ "s3:GetObject", "s3:ListBucket" ], "Resource": [ "arn:aws:s3:::reports", "arn:aws:s3:::reports/*" ] } ] }
Overly Permissive
{ "Version": "2012-10-17", "Statement": [ { "Effect": "Allow", "Action": "s3:*", "Resource": "*" } ] }
1Effect: Allow or Deny. An explicit Deny always overrides any Allow, anywhere in the evaluation.
2Action: the specific API calls permitted, such as s3:GetObject or ec2:StartInstances.
3Resource: the ARN(s) the statement applies to. Scope it to one bucket, not "*" (every bucket you own).
4Managed vs. inline: AWS managed policies are maintained by AWS; customer managed policies are reusable and version-controlled by you; inline policies are embedded in a single identity and cannot be reused.
Exam Tip
By default, IAM denies everything. Access exists only where a policy explicitly allows it. The right-hand example above ("Action": "s3:*", "Resource": "*") grants full control of every S3 bucket in the account -- exactly the pattern least privilege exists to prevent.

MFA, Root Protection & IAM Identity Center
A password alone is not enough. Multi-factor authentication and centralized access are how real organizations protect accounts at scale.
Virtual MFA
An authenticator app (e.g., a TOTP app) on a phone or tablet generates a rotating six-digit code. Free and the most common option.
Hardware / Security Key
A physical FIDO security key or hardware TOTP token. Highest assurance -- recommended for the root user and privileged administrators.
MFA on Sign-In
Requires the second factor at every console sign-in. Can also be required for specific sensitive API calls via a policy condition.
Protect the Root User
Enable MFA on root immediately after account creation. Do not generate root access keys. Use root only for tasks that require it, such as changing the AWS Support plan.
IAM Identity Center
Formerly AWS SSO. Provides single sign-on across every AWS account in an AWS Organizations structure, plus supported business applications.
Permission Sets
IAM Identity Center assigns reusable permission sets to users or groups per account -- centralized management instead of one IAM user per account.
Key Point
IAM Identity Center is the recommended way to manage human access across multiple AWS accounts in an organization. Individual IAM users are still appropriate for service accounts and single-account scenarios, but do not scale cleanly across dozens of accounts.
Slide 6 of 14
Network & Application Security
Security Groups and Network ACLs filter traffic at different layers. Shield and WAF defend against attacks aimed at your applications.
Security Groups
Instance/ENI level. Stateful -- return traffic is automatically allowed. Allow rules only; everything else is implicitly denied. Evaluates every rule before deciding.
Network ACLs
Subnet level. Stateless -- return traffic must be explicitly allowed. Supports both allow and deny rules, processed in numbered order, first match wins.
AWS Shield
DDoS protection. Standard is free and automatic for every customer. Advanced adds enhanced detection, cost protection, and 24x7 DDoS Response Team access.
AWS WAF
Layer 7 web application firewall for CloudFront, ALB, API Gateway, and AppSync. Blocks common exploits like SQL injection and cross-site scripting using rule-based web ACLs.
Slide 7 of 14
Detection & Audit Services
Five managed services that watch your account, your resources, and your data so you do not have to build detection tooling yourself.
CloudTrail
Records every API call in the account -- who, what, when, from where. The audit log for forensics and compliance evidence.
GuardDuty
Continuous, ML-driven threat detection. Analyzes CloudTrail, VPC Flow Logs, and DNS logs for anomalies. No agents required.
AWS Config
Records resource configuration over time and evaluates it against Config Rules. Answers "what changed, and is it still compliant?"
Inspector
Automated vulnerability management for EC2 instances, container images in ECR, and Lambda functions. Finds software CVEs and network exposure.
Macie
Uses machine learning and pattern matching to discover sensitive data -- like PII -- stored in Amazon S3, and alerts on unintended exposure.
How They Fit Together
CloudTrail records activity. Config tracks configuration. GuardDuty and Inspector hunt for threats and vulnerabilities. Macie protects sensitive data specifically.
Exam Tip
When a scenario asks "which service tells you who did what" → CloudTrail. "Is this account under attack" → GuardDuty. "Did this resource's configuration drift" → Config. "Is there a vulnerability in this workload" → Inspector. "Is there exposed PII in my S3 buckets" → Macie.
Slide 8 of 14
Encryption & Secrets
AWS KMS manages the encryption keys. AWS Secrets Manager manages the credentials those keys often protect.
AWS KMS
Create and manage encryption keys. Integrates natively with S3, EBS, RDS, and more. Key policies control who can use or manage a key. Symmetric keys can auto-rotate annually.
AWS Secrets Manager
Stores database credentials, API keys, and tokens. Rotates them automatically on a schedule via Lambda, so applications never hardcode a password.
Envelope Encryption
KMS encrypts a data key, and that data key encrypts your actual data. This avoids repeatedly sending large amounts of data to KMS itself.
Secrets Manager vs. Parameter Store
Parameter Store (part of Systems Manager) is free at standard tier and great for configuration values. Secrets Manager costs more per secret but adds built-in automatic rotation.
Slide 9 of 14
Compliance & AWS Artifact
AWS operates under dozens of global compliance programs and gives you self-service access to the evidence auditors ask for.
AWS Artifact
A self-service portal for on-demand access to AWS compliance reports (SOC, PCI, ISO) and to review and accept agreements, such as a Business Associate Addendum (BAA) for HIPAA workloads.
Shared Compliance
AWS handles compliance of the infrastructure; you are responsible for how you configure and use it. Using a HIPAA-eligible service does not automatically make your application HIPAA compliant.
Continuous Auditing
AWS infrastructure is independently assessed on a recurring basis. New reports are published to Artifact as audits complete -- no waiting on a sales request.
1SOC 1 / 2 / 3: reports on internal controls relevant to financial reporting and security/availability/confidentiality.
2ISO 27001 / 27017 / 27018: international standards for information security management and cloud-specific privacy controls.
3PCI DSS: required for any organization that processes, stores, or transmits payment card data.
4HIPAA: AWS supports HIPAA-eligible services under a signed BAA for workloads handling protected health information.
5FedRAMP: a US government risk-management framework; AWS GovCloud (US) is designed for FedRAMP High, ITAR, and DoD workloads.
Exam Tip
If a question describes needing an audit report or signed agreement, the answer is AWS Artifact. It is not a security scanning tool -- it is a document library.

Pricing Fundamentals
Nearly every AWS bill comes down to three dimensions: compute, storage, and data transfer out.
Compute
You pay for the resource while it runs -- by the second for EC2 and Fargate, or per invocation and duration for Lambda. Stop the resource, stop paying for compute.
Storage
Billed per GB stored per month, with additional charges for requests and retrieval depending on the storage class (S3 Standard vs. Glacier, for example).
Data Transfer Out
Data transferred into AWS is free. Data transferred out to the internet is billed per GB. Transfers within the same Availability Zone are typically free or discounted.
AWS Free Tier
Three categories: Always Free (e.g., a fixed amount of Lambda requests every month, forever), 12 Months Free (new-account offers like limited EC2/S3/RDS usage), and Trials (short-term free access to specific services). Free Tier limits are illustrative and change over time -- always confirm current limits at aws.amazon.com/free.
Slide 11 of 14
Compute Pricing Models
The same EC2 instance can cost wildly different amounts depending on how you commit to using it.
On-Demand
Pay by the second, no commitment. Maximum flexibility, highest per-unit price. Best for unpredictable or short-term workloads.
Reserved Instances
Commit to a specific instance family for 1 or 3 years for a significant discount versus On-Demand. Standard RIs lock the instance type; Convertible RIs allow changes.
Savings Plans
Commit to a $/hour spend for 1 or 3 years. Compute Savings Plans apply across instance family, Region, OS, and even Fargate/Lambda. More flexible than Reserved Instances.
Spot Instances
Bid on spare AWS capacity for steep discounts versus On-Demand. AWS can reclaim a Spot instance with a two-minute warning. Ideal for fault-tolerant, flexible workloads.
Dedicated Hosts
An entire physical server dedicated to you. Useful when licensing is tied to physical cores/sockets (bring-your-own-license) or compliance requires hardware isolation.
Choosing a Model
Steady-state production → Reserved/Savings Plans. Spiky or unknown → On-Demand. Interruptible batch jobs → Spot. Licensing/compliance → Dedicated Hosts.
Exam Tip
All of these are still OpEx, not CapEx -- even a 3-year Reserved Instance is billed monthly, not purchased as a capital asset. Illustrative discount ranges (Reserved roughly 40-70% off, Spot up to ~90% off) vary by instance type and Region -- confirm current numbers with the AWS Pricing Calculator before quoting a figure.

Billing & Cost Management Tools
Estimate before you spend, watch spend as it happens, and get alerted before you blow past your plan.
AWS Pricing Calculator
Model the cost of a planned deployment before creating a single resource. Free web tool at calculator.aws. Save and share estimates with stakeholders.
Cost Explorer
Visualize and analyze spend that has already happened -- by service, account, Region, or cost allocation tag. Free to use, up to 12 months of history by default.
AWS Budgets
Set custom cost, usage, or Savings Plans/Reservation coverage thresholds and get alerted at configurable percentages before you overspend.
Cost and Usage Report (CUR)
The most granular billing data AWS produces -- hourly, resource-level line items delivered automatically to an S3 bucket for deep analysis or BI tools.
Consolidated Billing
AWS Organizations combines usage across every linked account onto a single bill, often unlocking volume pricing tiers and shared Reserved Instance/Savings Plans discounts.
Cost Allocation Tags
Key-value labels (e.g., CostCenter, Project) attached to resources. Activate them in Billing settings to break down Cost Explorer and CUR data by team or project.
Key Distinction
Pricing Calculator = before you spend (estimate). Cost Explorer = after you spend (analyze). Budgets = while you spend (alert). All three answer a different question about the same dollar.
Slide 13 of 14
AWS Support Plans
Five tiers of support, plus two tools every plan includes: Trusted Advisor and the AWS Health Dashboard.
Basic (Free)
Included with every account. Documentation, whitepapers, forums, core Trusted Advisor checks, and the AWS Health Dashboard. No technical support cases.
Developer
Business-hours email access to Cloud Support Associates. General guidance under 24 hours; system impaired under 12 hours. Good for early development.
Business
24x7 phone, chat, and email. Full Trusted Advisor checks. Production system down: under 1 hour response. The baseline for production workloads.
Enterprise On-Ramp
Everything in Business, plus a pool of Technical Account Managers (TAMs) and a business-critical response target under 30 minutes.
Enterprise
A dedicated, named TAM, a Concierge team, and a business-critical system down response under 15 minutes, 24x7. For mission-critical workloads.
Trusted Advisor
Everyone gets 7 core checks free. Business and Enterprise plans unlock the full check catalog across Cost, Performance, Security, Fault Tolerance, and Service Limits.
Exam Tip
The AWS Health Dashboard has two views: a public Service Health view (status of AWS services globally) and a personalized Account Health view (issues affecting resources you actually run). Support-plan minimum fees and exact response-time numbers change over time -- treat any dollar figure as illustrative and confirm current terms at aws.amazon.com/premiumsupport.

Well-Architected Framework + Key Takeaways
Operational Excellence
Run and monitor systems to deliver business value, and continuously improve processes and procedures.
Security
Protect data, systems, and assets through risk assessments and mitigation strategies -- everything covered in this chapter.
Reliability
Ensure a workload performs its intended function correctly and consistently, recovering quickly from failure.
Performance Efficiency
Use computing resources efficiently to meet requirements, and maintain that efficiency as demand and technology evolve.
Cost Optimization
Run systems to deliver business value at the lowest price point -- everything covered in the pricing and billing sections.
Sustainability
The newest pillar (added 2021). Minimize the environmental impact of running cloud workloads -- energy, water, and waste.
Chapter 3 — Five Key Facts
1Responsibility shifts, it never disappears. AWS secures the cloud; you always secure your data, identities, and access -- regardless of service model.
2IAM denies by default. Users, groups, and roles have zero access until a policy explicitly grants it. Least privilege means granting only what a job requires.
3Security Groups are stateful and instance-level; NACLs are stateless and subnet-level. CloudTrail audits, GuardDuty detects threats, Config tracks drift.
4Every bill reduces to compute, storage, and data transfer out. Pricing Calculator estimates before you spend; Cost Explorer analyzes after; Budgets alerts while you spend.
5Support plans scale from free to a dedicated TAM. Trusted Advisor and the Health Dashboard are included at every tier; full Trusted Advisor checks require Business or higher.
