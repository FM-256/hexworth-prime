Infrastructure as Code
Define infrastructure in code files. Version it in Git. Deploy it automatically. Never click through a console again.
What Is IaC
Infrastructure defined in declarative configuration files. Terraform (HCL), CloudFormation (YAML/JSON), Bicep (Azure). The code IS the infrastructure -- if it is not in the template, it does not exist.
Declarative vs. Imperative
Declarative: describe the desired end state. Terraform figures out what to create/modify/destroy. Imperative: write step-by-step scripts (Bash, Python). Declarative is preferred for infrastructure.
Why IaC Matters
Reproducibility: deploy identical environments. Version control: track every change in Git. Speed: create 50 servers in 2 minutes. Safety: review infrastructure changes in pull requests before applying.
Slide 3 of 13
Terraform & CloudFormation
The two dominant IaC tools. Terraform is multi-cloud. CloudFormation is AWS-native.
Terraform
HashiCorp product. HCL syntax. Works with AWS, Azure, GCP, and 1000+ providers. State file tracks what exists. Plan before apply: see exactly what will change before it happens.
CloudFormation
AWS-native IaC. YAML or JSON templates. Deep AWS integration -- supports every AWS service on launch day. Stack-based: create, update, delete entire environments as a unit.
Azure Bicep / ARM
Bicep is Azure's domain-specific IaC language. Compiles to ARM JSON templates. Simpler syntax than raw ARM. First-class Azure resource support. Azure-only -- no multi-cloud.
Slide 4 of 13
Configuration Management
IaC creates infrastructure. Config management configures what runs on it: packages, files, services, users.
Ansible
Agentless. Uses SSH to push configurations. YAML playbooks. Idempotent: run it 10 times, get the same result. The most popular CM tool for cloud environments.
Puppet & Chef
Agent-based. Puppet uses its own DSL. Chef uses Ruby. Both manage state: define desired configuration, the agent enforces it continuously. Better for large, complex fleets.
IaC + CM Together
Terraform creates the VM. Ansible configures it: installs packages, deploys app code, sets up monitoring agents. The two tools are complementary, not competing.

CI/CD Pipelines
Continuous Integration builds and tests code. Continuous Deployment pushes it to production. Automation end-to-end.
Continuous Integration
Every code commit triggers: build the application, run unit tests, run linting, scan for vulnerabilities. If any step fails, the commit is blocked. GitHub Actions, GitLab CI, Jenkins.
Continuous Deployment
After CI passes: deploy to staging, run integration tests, deploy to production. Blue/green or canary deployments minimize risk. Rollback automatically on failure.
GitOps
Git is the single source of truth for both application code AND infrastructure. Push to Git triggers automated deployment. ArgoCD and Flux watch Git repos and sync cluster state automatically.

Auto-Scaling
Automatically add or remove compute resources based on demand. The cloud killer feature.
Horizontal Scaling
Add more instances. A web farm goes from 3 to 30 instances during peak traffic. AWS Auto Scaling Groups, Azure VM Scale Sets, GCP Instance Groups. Preferred for stateless workloads.
Vertical Scaling
Make instances bigger. Upgrade from 4 vCPU to 16 vCPU. Requires a restart in most cases. Limited by the largest instance type available. Used for databases and stateful workloads.
Scaling Policies
Target tracking: maintain 70% CPU. Step scaling: add 2 instances above 80% CPU. Scheduled: scale up at 8 AM, down at 6 PM. Predictive: ML-based forecasting (AWS).

Containers & Docker
Package an application with all its dependencies into a portable, lightweight unit.
What Is a Container
A container bundles application code, runtime, libraries, and config into a single image. It runs in isolation but shares the host OS kernel. Lighter than VMs -- starts in seconds, not minutes.
Docker
The de facto container runtime. Dockerfile defines the image. Docker Hub hosts public images. Build locally, push to a registry, pull and run anywhere. Works identically on laptop, CI, and production.
Container Registries
Docker Hub, Amazon ECR, Azure Container Registry, Google Artifact Registry. Store and distribute container images. Scan images for vulnerabilities before deployment. Version with tags.
Slide 8 of 13
Kubernetes Orchestration
Kubernetes manages thousands of containers across a cluster: scheduling, scaling, networking, and self-healing.
What K8s Does
Deploys containers across nodes. Auto-scales based on CPU/memory. Self-heals: restarts crashed containers. Rolling updates: zero-downtime deployments. Service discovery: containers find each other.
Managed Kubernetes
Amazon EKS, Azure AKS, Google GKE. The provider manages the control plane (API server, etcd, scheduler). You manage worker nodes and workloads. Reduces operational overhead significantly.
When to Use K8s
Microservices architectures with many independent services. Workloads needing auto-scaling and self-healing. Teams already using containers. NOT for simple applications -- the complexity cost is real.
Slide 9 of 13
Serverless Computing
No servers to provision, patch, or scale. Write code, define triggers, and let the platform handle everything else.
Functions as a Service
AWS Lambda, Azure Functions, Google Cloud Functions. Upload a function, define a trigger (HTTP, queue, timer, file upload). The platform provisions compute, runs the function, and bills per invocation.
Event-Driven Architecture
Serverless shines with event-driven patterns: image uploaded triggers resize function, API request triggers processing function, database change triggers notification function. Each function is independent.
Serverless Trade-Offs
Cold starts: first invocation after idle has latency (100ms-2s). Execution limits: 15 min max (Lambda). Debugging is harder. Vendor lock-in: Lambda code does not run on Azure Functions without changes.
Slide 10 of 13
Orchestration Patterns
Coordinate multiple automation tools and services into a cohesive deployment workflow.
Pipeline Orchestration
CI/CD pipelines orchestrate build, test, and deploy stages. Each stage can use different tools: Terraform for infra, Docker for containers, Ansible for config, Selenium for testing.
Workflow Engines
AWS Step Functions, Azure Logic Apps, Google Workflows. Define multi-step workflows with branching, error handling, and parallel execution. Coordinate Lambda functions, APIs, and services visually.
Infrastructure Pipelines
Treat infrastructure changes like code changes: PR review, automated testing (terraform plan), staged rollout (dev then staging then prod), automated rollback on failure.
Slide 13 of 13
Key Takeaways
1IaC (Terraform, CloudFormation, Bicep) makes infrastructure reproducible, versioned, and reviewable in Git.
2Configuration management (Ansible, Puppet) configures what runs ON the infrastructure. Use IaC + CM together.
3CI/CD automates build, test, and deploy. GitOps uses Git as the single source of truth for infrastructure and code.
4Auto-scaling (horizontal and vertical) matches resources to demand. Target tracking and scheduled policies are most common.
5Containers (Docker) package apps portably. Kubernetes orchestrates containers at scale. Managed K8s reduces complexity.
6Serverless (Lambda, Functions) eliminates server management but introduces cold starts and vendor lock-in trade-offs.
