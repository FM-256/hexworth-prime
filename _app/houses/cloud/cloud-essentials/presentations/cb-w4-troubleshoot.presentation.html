Troubleshooting Methodology
Systematic approach beats random guessing. Follow the OSI model, check logs, and narrow the scope.
Identify Symptoms
What is the user experiencing? 503 errors? Timeouts? Slow responses? Data inconsistency? Start with the user impact, not the infrastructure. Symptoms guide the investigation.
Check Recent Changes
What changed in the last 24 hours? Deployments, config changes, scaling events, provider incidents. 80% of production issues are caused by recent changes. Check deployment logs first.
Isolate the Layer
Is it DNS? Network? Load balancer? Application? Database? Use the OSI model bottom-up or top-down. Ping, traceroute, curl, and log analysis narrow the scope quickly.

Deployment Failures
Code that works in staging but fails in production. The most common category of cloud issues.
Permission Errors
The deployment service account lacks permissions to create/update resources. IAM policies in production are stricter than staging. Check CloudTrail/Activity Log for Access Denied errors.
Configuration Drift
Production config differs from what was tested. Environment variables, secrets, database connection strings, feature flags. Use IaC and config management to prevent drift.
Resource Limits
Hit a quota: max VMs, max IPs, max security groups. Hit a service limit: Lambda concurrent executions, API Gateway rate limits. Request limit increases before they block deployments.

Connectivity Issues
The application cannot reach the database. The load balancer returns 502. Users get connection timeouts.
Security Group Rules
Inbound rules block the required port. Most common: database port (3306/5432) not open to the application subnet. Check security groups on BOTH the source and destination.
Route Table Misconfiguration
Subnet has no route to the internet gateway (no outbound access). Or no route to a NAT gateway for private subnets. Check route tables when instances cannot reach external services.
VPN/Peering Issues
Site-to-site VPN tunnel is down. VPC peering route not propagated. Transit Gateway attachment missing. Check tunnel status, BGP sessions, and route propagation.

Performance Bottlenecks
The system is running but slowly. Identify which resource is saturated.
CPU Saturation
Instance type is too small. Unoptimized code (infinite loops, blocking calls). Solution: scale up (bigger instance) or scale out (more instances). Profile the application to find hot paths.
Memory Pressure
Memory leaks in application code. JVM heap too small. Container memory limit too low. OOM kills crash the process. Monitor memory trends and set memory alerts.
I/O Throttling
EBS volume hitting IOPS or throughput limits. Storage tier is too slow for the workload. Solution: upgrade to io2 or gp3 with provisioned IOPS. Check CloudWatch EBS metrics.

DNS Resolution
DNS issues cause intermittent failures that are maddening to debug. The symptoms look like network problems.
DNS Propagation Delay
Changed a DNS record but clients still resolve the old IP. TTL caching. Solution: wait for TTL to expire or lower TTL before making changes. Pre-flight: lower TTL 24h before cutover.
Split-Horizon DNS
Internal and external DNS resolve the same hostname to different IPs. Internal resolves to private IP, external to public IP. Misconfiguration causes connectivity failures from unexpected locations.
DNS Health Checks
Route 53, Azure Traffic Manager health checks fail if the endpoint is unhealthy. DNS stops routing to the unhealthy endpoint. If health checks are misconfigured, healthy endpoints get removed.

Certificate Errors
TLS certificate problems cause browser warnings, API failures, and broken integrations.
Expired Certificates
Certificate not renewed before expiration. Automated renewal (ACM, Let's Encrypt) prevents this. Monitor certificate expiration dates. Alert 30 days before expiry.
Name Mismatch
Certificate issued for app.example.com but the request hits api.example.com. Wildcard certs (*.example.com) or SAN certs (multiple domains) prevent this.
Chain of Trust
Intermediate certificate missing from the server configuration. The browser cannot verify the chain from the server cert to the root CA. SSL Labs test identifies chain issues.

Quota & Limit Issues
Every cloud account has default limits. Hitting them causes cryptic failures.
Service Quotas
Max 20 VMs per region (default). Max 5 Elastic IPs. Max 200 S3 buckets. Limits vary by service and region. AWS Service Quotas console shows current usage vs. limits.
API Rate Limits
AWS API calls are rate-limited (typically 10-100 requests/second per API). Terraform deploying 500 resources can hit throttling. Implement exponential backoff and retry logic.
Proactive Management
Request limit increases BEFORE you need them. Monitor quota utilization. Include quota checks in migration planning. A quota hit during a production deployment is a preventable outage.

Cost Overruns
Unexpected cloud costs are a troubleshooting scenario. Diagnose the cause and implement controls.
Identify the Spike
Cost Explorer by service, by tag, by linked account. Identify which service caused the increase. Common culprits: forgotten dev environments, unattached EBS volumes, over-provisioned databases.
Data Transfer Costs
Egress charges surprise teams. Cross-AZ traffic costs in AWS ($0.01/GB). Cross-region costs more. NAT Gateway data processing charges add up. Use VPC endpoints to eliminate NAT costs for AWS services.
Prevention
Budget alerts, auto-shutdown for dev environments, reserved instances for steady workloads, spot instances for batch jobs. Tag everything. Review costs weekly. Assign cost ownership to teams.
Slide 10 of 13
Troubleshooting Toolkit
Essential commands and tools every cloud engineer should have ready.
Network Diagnostics
ping (reachability), traceroute (path), nslookup/dig (DNS), curl (HTTP), telnet/nc (port connectivity). These basic tools solve 90% of connectivity issues.
Cloud-Native Tools
VPC Flow Logs (packet captures), CloudTrail (API audit), CloudWatch Insights (log queries), Azure Network Watcher, GCP Network Intelligence Center. Provider tools show what OS tools cannot.
Runbook Approach
Document common issues and their solutions. "503 from ALB: check target group health, check security groups, check application logs." Runbooks reduce MTTR and enable junior engineers to resolve issues.

Key Takeaways
1Troubleshooting methodology: identify symptoms, check recent changes, isolate the layer, verify with logs.
2Deployment failures: check IAM permissions, environment configuration, and resource quotas before investigating code.
3Connectivity issues: security groups (both sides), route tables, NAT gateways, VPN tunnel status.
4Performance bottlenecks: CPU (scale out), memory (leaks/limits), I/O (storage tier), network (bandwidth).
5DNS and certificate issues cause intermittent, confusing failures. Lower TTL before changes. Automate certificate renewal.
6Cost overruns are a troubleshooting scenario. Use Cost Explorer, budget alerts, and tagging to diagnose and prevent.
