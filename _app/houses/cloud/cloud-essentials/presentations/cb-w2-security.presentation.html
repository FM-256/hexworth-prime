IAM: Identity & Access Management
Who can do what to which resources. IAM is the foundation of cloud security.
Authentication
Verifying identity: username/password, MFA, SSO, certificates, API keys. Multi-factor authentication should be mandatory for all privileged accounts.
Authorization
What an authenticated user can do: read, write, delete, admin. Policies define permissions. Principle of least privilege: grant only what is needed, nothing more.
Federation
Connect your corporate directory (Active Directory, Okta) to the cloud provider. Users sign in once and access cloud resources. SAML 2.0 and OIDC are the protocols.
Exam Focus
IAM policies follow the principle of least privilege. Roles are preferred over direct user permissions. Service accounts should have scoped, short-lived credentials -- never long-lived keys.

Encryption: At Rest
Data stored on disk must be encrypted. If a drive is stolen or a snapshot is leaked, the data is unreadable.
Server-Side Encryption
The cloud provider encrypts data before writing to disk and decrypts on read. Transparent to the application. AWS SSE-S3, Azure Storage Service Encryption, GCP default encryption.
Client-Side Encryption
You encrypt data before uploading. The provider never sees plaintext. You manage the keys. Maximum control but more operational complexity.
Key Management
AWS KMS, Azure Key Vault, GCP Cloud KMS. Centralized key storage with access policies, rotation schedules, and audit logging. Never hardcode keys in application code.
HIPAA requires encryption at rest for protected health information (PHI). A healthcare SaaS company uses Azure Storage with Microsoft-managed keys (SSE) and Azure Key Vault for application-level encryption of patient records.
Slide 4 of 14
Encryption: In Transit
Data moving between client and server, or between services, must be encrypted to prevent interception.
TLS/SSL
HTTPS enforces TLS for web traffic. TLS 1.2 minimum, TLS 1.3 preferred. Every public endpoint should have a valid certificate. AWS Certificate Manager and Azure App Service provide free managed certs.
VPN & Private Links
Site-to-site VPN encrypts traffic between on-prem and cloud. Private Link/PrivateLink provides private connectivity to cloud services without traversing the public internet.
Mutual TLS (mTLS)
Both client and server present certificates. Used for service-to-service communication in zero-trust architectures. Service meshes (Istio, Linkerd) automate mTLS for microservices.
Certificate Management
Automate certificate issuance and renewal. Let's Encrypt, ACM, and Azure certificates auto-renew. Expired certificates cause outages -- automation prevents this.

Network Security
Defense in depth: security groups, NACLs, WAFs, and DDoS protection create multiple layers of network defense.
Security Groups
Stateful firewalls attached to instances. Allow/deny traffic by port, protocol, and source IP. Default deny all inbound. AWS Security Groups, Azure NSGs, GCP Firewall Rules.
Network ACLs
Stateless packet filters at the subnet level. Evaluate rules in order. Provide an additional layer of defense beyond security groups. AWS NACLs, Azure subnet-level NSGs.
Web Application Firewall
Inspects HTTP/HTTPS traffic for SQL injection, XSS, and OWASP Top 10 attacks. AWS WAF, Azure WAF, Cloudflare. Sits in front of load balancers and API gateways.
DDoS Protection
AWS Shield, Azure DDoS Protection, GCP Cloud Armor. Absorb volumetric attacks at the network edge before they reach your application. Standard tier is often free.
Bastion Hosts / Jump Boxes
A hardened VM in a public subnet that serves as the only SSH/RDP entry point. All admin access flows through the bastion. Reduces attack surface by eliminating direct access to internal servers.

Shared Responsibility Deep Dive
The provider secures the cloud. You secure what is in the cloud. The line shifts based on service model.
Provider Always Owns
Physical data center security, hardware maintenance, hypervisor patching, network infrastructure, power and cooling. You never touch these regardless of service model.
Customer Always Owns
Data classification, user access management, client-side encryption decisions, account security (MFA, password policies), and regulatory compliance configuration.
The Gray Zone
OS patching: yours in IaaS, provider's in PaaS/SaaS. Network config: yours in IaaS, partially yours in PaaS. Application security: yours in IaaS/PaaS, provider's in SaaS.
Common Mistake
"We moved to the cloud so security is handled." Wrong. Cloud providers secure THEIR infrastructure. Misconfigured permissions, unencrypted data, and open ports are YOUR responsibility.

Compliance Frameworks
Cloud providers earn certifications. You must configure your environment to meet compliance requirements.
SOC 2 Type II
Audits security, availability, processing integrity, confidentiality, and privacy controls. Most B2B SaaS companies need SOC 2. Cloud providers publish their SOC 2 reports annually.
ISO 27001
International standard for information security management systems (ISMS). Requires risk assessment, security controls, and continuous improvement. All major cloud providers are ISO 27001 certified.
HIPAA
US healthcare data protection. Requires encryption, access controls, audit trails, and a Business Associate Agreement (BAA) with the cloud provider. AWS, Azure, and GCP all offer BAAs.
PCI-DSS
Payment card industry standard. 12 requirements covering network security, encryption, access control, and monitoring. Cloud providers are PCI-DSS compliant, but your configuration must be too.
Slide 8 of 14
Data Classification
Not all data needs the same protection. Classify data to apply appropriate security controls and reduce cost.
Confidential / Restricted
PII, PHI, payment data, trade secrets. Encrypt at rest and in transit. Strict access controls. Full audit logging. Data loss prevention (DLP) policies. Highest cost to protect.
Internal / Private
Employee data, internal reports, business plans. Not public-facing but damaging if leaked. Standard encryption, role-based access, moderate audit requirements.
Public
Marketing materials, public documentation, open-source code. No confidentiality requirement. Still needs integrity protection (no tampering) and availability.
Cloud Implementation
Use tags or labels to classify resources. Apply encryption policies, access controls, and retention rules based on classification. Azure Information Protection and AWS Macie automate classification for common data types.
Slide 9 of 14
Zero Trust Architecture
Never trust, always verify. Every request is authenticated and authorized regardless of network location.
Identity Verification
Every access request verifies user identity, device health, and context (location, time, risk score). No implicit trust based on being "inside the network."
Micro-Segmentation
Divide the network into small segments. Each segment has its own access policies. Lateral movement is blocked even if one segment is compromised.
Continuous Validation
Authentication is not a one-time event. Sessions are re-validated. Conditional access policies revoke access if device compliance changes or risk increases.
Traditional security: once past the firewall, you are trusted. Zero trust: every API call, every database query, every file access is individually authenticated. The perimeter is the identity, not the network boundary.
Slide 10 of 14
Security Monitoring
Detect threats in real time with centralized logging, SIEM integration, and automated alerting.
CloudTrail / Activity Log
Every API call is logged: who did what, when, from where. AWS CloudTrail, Azure Activity Log, GCP Cloud Audit Logs. Essential for incident investigation and compliance.
SIEM Integration
Forward cloud logs to a SIEM (Splunk, Sentinel, Chronicle). Correlate events across cloud, on-prem, and SaaS. Detect patterns that individual log sources cannot reveal.
Threat Detection
AWS GuardDuty, Azure Defender, GCP Security Command Center. ML-powered anomaly detection: unusual API calls, cryptocurrency mining, compromised credentials. Automated alerting and remediation.

Vulnerability Management
Scan, patch, and harden. Unpatched systems are the number one attack vector in cloud environments.
Image Hardening
Start with a hardened base image (CIS Benchmarks). Remove unnecessary packages, disable unused services, configure host firewalls. Use golden images in auto-scaling groups.
Patch Management
AWS Systems Manager Patch Manager, Azure Update Management. Automate OS and application patching. Schedule maintenance windows. Test patches in staging before production.
Container Security
Scan container images for known CVEs before deployment. Use minimal base images (Alpine, distroless). Never run containers as root. Tools: Trivy, Aqua, Snyk Container.
Infrastructure Scanning
Scan IaC templates (Terraform, CloudFormation) for misconfigurations before deployment. Tools: Checkov, tfsec, Bridgecrew. Shift security left into the CI/CD pipeline.
Slide 12 of 14
Incident Response in Cloud
Cloud IR follows the same phases as traditional IR but uses cloud-native tools and forensic techniques.
Preparation
Pre-stage forensic tools, define playbooks, establish roles, enable logging on all resources. Create a dedicated IR account with cross-account access for forensic analysis.
Detection & Containment
Alert fires from GuardDuty/Defender. Contain by revoking IAM credentials, isolating the instance (change security group to deny all), snapshot the volume for forensics.
Eradication & Recovery
Terminate compromised instances (do not try to clean them). Deploy fresh from known-good images. Rotate all potentially compromised credentials. Restore data from verified backups.
Cloud Advantage
In the cloud, you can snapshot, clone, and isolate in seconds. You do not need physical access to the server. Forensic images can be analyzed in a separate, isolated account. This makes cloud IR faster than on-prem IR.

Security Best Practices
10 non-negotiable security practices for any cloud environment.
1. Enable MFA Everywhere
Root account, admin accounts, all IAM users, API access. Hardware keys (YubiKey) for privileged accounts. TOTP (authenticator app) minimum for all users.
2. Least Privilege
Start with zero permissions and add only what is needed. Use managed policies. Review permissions quarterly. Remove unused accounts and roles.
3. Encrypt Everything
At rest: enable default encryption on all storage. In transit: enforce HTTPS, TLS 1.2+. In use: consider confidential computing for the most sensitive workloads.
4. Log Everything
Enable CloudTrail/Activity Log on all accounts and regions. Centralize logs. Set retention policies. You cannot investigate what you did not log.
5. Automate Security
Auto-remediate misconfigurations. Auto-patch. Auto-rotate secrets. Manual security does not scale in cloud environments with hundreds of resources.
6. Segment Networks
Separate prod, dev, and staging. Use private subnets for databases. Public subnets only for load balancers. No direct internet access for backend services.

Key Takeaways
Cloud Security -- IAM, encryption, network defense, compliance, and incident response.
1IAM is the foundation: authenticate, authorize, federate. Least privilege is non-negotiable.
2Encrypt at rest (KMS/Key Vault) and in transit (TLS 1.2+). Never store secrets in code.
3Defense in depth: security groups, NACLs, WAF, DDoS protection. Layer network controls.
4Shared responsibility: provider secures the cloud infrastructure; you secure your data, access, and configuration.
5Compliance (SOC 2, ISO 27001, HIPAA, PCI-DSS) requires both provider certification AND your correct configuration.
6Zero trust: never trust, always verify. Identity is the new perimeter.
