What Is Cloud Computing?
The delivery of computing services over the internet -- on-demand, pay-as-you-go, managed by a provider.
On-Demand Self-Service
Provision servers, storage, and networks without waiting for human approval. Spin up a VM in minutes, not weeks. The cloud console or API is your IT department.
Broad Network Access
Accessible from any device with an internet connection -- laptops, phones, tablets. No VPN required for most SaaS applications. Geography becomes irrelevant.
Resource Pooling
The provider serves multiple tenants from the same physical hardware using virtualization. You get isolated resources without owning the servers.
Rapid Elasticity
Scale up during Black Friday traffic, scale down at midnight. Resources expand and contract automatically based on demand. You only pay for what you use.
Measured Service
Every CPU cycle, GB stored, and API call is metered. The provider bills precisely for consumption. Transparency and cost control are built in.
NIST Definition
These five characteristics come from NIST SP 800-145, the formal definition of cloud computing used by CompTIA Cloud+ and every major certification exam.

The Three Service Models
IaaS, PaaS, and SaaS represent different levels of abstraction. The higher you go, the less you manage.
Think of It Like Pizza
IaaS is buying ingredients and cooking at home. PaaS is a take-and-bake pizza -- you just add toppings and bake. SaaS is ordering delivery -- you just eat. Each model trades control for convenience.
Slide 4 of 14
IaaS: Infrastructure as a Service
Maximum control, maximum responsibility. You rent virtual hardware and manage everything above it.
What You Get
Virtual machines, storage volumes, virtual networks, load balancers, firewalls. The provider manages the physical data center, power, cooling, and hardware failures.
What You Manage
Operating system patches, middleware, runtime, application code, data security. If the OS is unpatched and gets exploited, that is on you -- not the provider.
AWS EC2
Choose instance types (t3.micro to p4d.24xlarge), attach EBS storage, configure security groups. Full root access to the OS.
Azure Virtual Machines
Windows or Linux VMs with managed disks, NSGs for firewall rules, availability sets for redundancy. Integrated with Azure AD for identity.
Google Compute Engine
Custom machine types, preemptible VMs for cost savings, live migration during maintenance. Tight integration with GCP networking.
Use case: a financial services company needs to run a legacy Windows Server 2019 application that cannot be refactored. IaaS lets them lift-and-shift the VM to the cloud while keeping full control of the OS and application layer.
Slide 5 of 14
PaaS: Platform as a Service
Focus on your code. The provider handles the OS, runtime, scaling, and patching underneath.
What You Get
A managed platform for deploying applications. Push your code, the platform builds, deploys, and scales it. No server provisioning, no OS patching, no load balancer configuration.
What You Manage
Application code, data, and access control. The platform handles everything below your code. You decide what the app does -- the provider decides how it runs.
Azure App Service
Deploy web apps in .NET, Node.js, Python, Java. Built-in CI/CD, custom domains, SSL certificates, auto-scaling rules. Zero server management.
AWS Elastic Beanstalk
Upload your code and Beanstalk provisions EC2 instances, load balancers, and auto-scaling groups automatically. Still gives access to underlying resources if needed.
Google App Engine
Fully managed, zero-config deployment. Standard environment auto-scales to zero. Flexible environment supports Docker containers.
When to Choose PaaS
When your team wants to ship features, not manage servers. PaaS is ideal for web applications, APIs, and microservices where the development team should focus on business logic, not infrastructure.
Slide 6 of 14
SaaS: Software as a Service
Use the software. The provider manages literally everything else. You are a consumer, not an operator.
Microsoft 365
Email, Word, Excel, Teams, SharePoint -- all browser-based. Microsoft handles servers, updates, backups, and availability. You manage users, licenses, and data.
Salesforce
CRM platform fully managed by Salesforce. Customers configure workflows and dashboards but never touch the underlying infrastructure.
Google Workspace
Gmail, Docs, Drive, Calendar. Google runs the servers across multiple data centers. Your only responsibility is managing user accounts and organizational policies.
When your CEO says "we use the cloud" they almost always mean SaaS. Microsoft 365, Zoom, Slack, Dropbox -- these are all SaaS products. The company pays a subscription fee and gets a fully managed application.
SaaS Risk
You depend entirely on the provider for uptime, security patching, and data sovereignty. If the provider has an outage, you wait. If they change pricing, you pay. Vendor lock-in is the primary risk.

Deployment Models
Where the cloud infrastructure physically lives and who has access to it.
Exam Tip
CompTIA Cloud+ expects you to know all four deployment models and when each is appropriate. Public for cost and scale. Private for compliance and control. Hybrid for the best of both. Community for shared regulatory requirements.

Shared Responsibility Model
Security IN the cloud is yours. Security OF the cloud is the provider's. The line depends on the service model.
Customer Responsibility
Red = you own it. Data is ALWAYS your responsibility regardless of service model. The higher the stack, the more the provider takes over.
Provider Responsibility
Blue = provider owns it. Physical infrastructure is ALWAYS the provider's responsibility. SaaS shifts almost everything to the provider.

Major Cloud Providers
AWS leads in market share. Azure dominates enterprise. GCP leads in AI/ML. All three offer IaaS, PaaS, and SaaS.
Amazon Web Services
Launched 2006. 200+ services. Largest market share (~31%). Strongest in compute (EC2), storage (S3), and serverless (Lambda). Default choice for startups and tech companies.
Microsoft Azure
Launched 2010. Tight integration with Windows Server, Active Directory, and Microsoft 365. Dominates enterprise and government. Hybrid cloud leader with Azure Arc.
Google Cloud Platform
Launched 2008. Leads in data analytics (BigQuery), AI/ML (Vertex AI), and Kubernetes (GKE -- Google created K8s). Strong in developer tooling and open-source.
Other Providers
IBM Cloud, Oracle Cloud, Alibaba Cloud, DigitalOcean, Linode. The CompTIA Cloud+ exam is vendor-neutral -- it tests concepts, not specific provider consoles. But knowing the big three gives you context for every question.

Cloud Economics
Why cloud? Because CapEx becomes OpEx, and unused capacity becomes someone else's problem.
CapEx (Capital Expenditure)
Traditional model: buy servers, racks, cooling, UPS upfront. Large initial investment. Hardware depreciates over 3-5 years. Over-provision to handle peak load that may never come.
OpEx (Operational Expenditure)
Cloud model: pay monthly for what you use. No upfront hardware cost. Scale up and down as needed. Convert a large capital purchase into a predictable monthly bill.
Economies of Scale
AWS buys millions of servers at a discount you could never get. That savings passes to you as lower per-unit costs. The bigger the provider, the cheaper the resources.
Elasticity = Cost Savings
On-prem: pay for peak capacity 24/7. Cloud: scale to 100 servers during a sale, back to 5 at night. You only pay for the hours you use.
Reserved vs. On-Demand
On-demand: pay full price per hour. Reserved (1-3 year commit): 30-72% discount. Spot/preemptible: up to 90% off but can be interrupted. Match the pricing model to the workload.

Benefits of Cloud Computing
Speed, scale, global reach, and reduced operational burden. These are the business drivers.
Agility
Provision infrastructure in minutes instead of weeks. Test new ideas quickly. Fail fast and cheaply. DevOps teams can iterate without waiting for procurement.
Global Reach
Deploy to any region in the world with a few clicks. Serve users in Tokyo, London, and New York from local data centers. Latency drops dramatically.
High Availability
Multi-AZ deployments, auto-failover, SLAs of 99.95%+. The provider handles redundant power, cooling, and networking. Your uptime depends on architecture, not hardware.
Disaster Recovery
Replicate data across regions. Spin up standby environments on demand. DR in the cloud costs a fraction of maintaining a secondary physical data center.
A hospital needs to launch a patient portal in 3 weeks. On-prem: order servers (4-6 weeks lead time), rack them, install OS, configure networking. Cloud: deploy to Azure App Service today, scale tomorrow, go live next week.

Cloud Risks & Challenges
Cloud is not magic. It introduces new risks that traditional on-prem did not have.
Vendor Lock-In
Proprietary services (Lambda, DynamoDB, Cosmos DB) make migration expensive. Data egress fees discourage leaving. Multi-cloud strategy reduces risk but increases complexity.
Data Sovereignty
GDPR, HIPAA, and other regulations may require data to stay in specific countries. Misconfigured regions can violate compliance. Know where your data lives at all times.
Cost Overruns
Pay-as-you-go means costs can spiral if not monitored. Forgotten VMs, over-provisioned storage, untagged resources -- cloud billing surprises are common without governance.
Network Dependency
Cloud requires reliable internet. If your ISP goes down, your cloud infrastructure is unreachable. On-prem survives local network issues; cloud does not.
Shared Tenancy
Public cloud is multi-tenant. While providers isolate workloads, side-channel attacks and noisy neighbors are real (though rare) concerns for high-security workloads.
Compliance Complexity
Cloud does not automatically make you compliant. You still own your security controls, audit trails, and access management. The provider gives you tools -- you must use them correctly.

Beyond the Big Three: XaaS
Everything as a Service. The "as a Service" model extends to databases, functions, containers, desktops, and more.
FaaS (Functions)
Serverless compute. Write a function, trigger it with an event. No servers to manage. AWS Lambda, Azure Functions, Google Cloud Functions. Pay per invocation.
DBaaS (Database)
Managed databases. AWS RDS, Azure SQL Database, Google Cloud SQL. Provider handles backups, patching, replication, scaling. You write queries.
DaaS (Desktop)
Virtual desktops in the cloud. Azure Virtual Desktop, Amazon WorkSpaces. Users get a full Windows desktop from any device. IT manages images, not hardware.
CaaS (Containers)
Managed container orchestration. Amazon ECS, Azure Container Instances, Google Cloud Run. Run Docker containers without managing Kubernetes clusters.
SECaaS (Security)
Cloud-delivered security services. Web application firewalls, DDoS protection, identity providers. Cloudflare, Okta, CrowdStrike Falcon -- security without on-prem appliances.
AIaaS (AI/ML)
Pre-trained AI models via API. Azure OpenAI Service, AWS Bedrock, Google Vertex AI. No GPU clusters needed -- just API calls. Pay per token or prediction.

Key Takeaways
Cloud Concepts and Service Models -- everything you need for the exam and the real world.
1Cloud computing delivers on-demand resources over the internet with five NIST characteristics: on-demand, broad access, pooling, elasticity, metering.
2IaaS gives you virtual hardware (VMs, storage). You manage OS and up. PaaS manages OS and runtime. SaaS manages everything.
3Four deployment models: Public (shared, multi-tenant), Private (dedicated), Hybrid (both), Community (shared mission).
4Shared responsibility: data is ALWAYS yours. Physical infrastructure is ALWAYS the provider's. Everything in between depends on the service model.
5Cloud converts CapEx to OpEx, enables global reach, and provides elasticity -- but introduces vendor lock-in, compliance complexity, and cost management challenges.
6XaaS extends the model: FaaS (serverless), DBaaS (managed databases), DaaS (virtual desktops), CaaS (containers), SECaaS (security), AIaaS (AI/ML).
