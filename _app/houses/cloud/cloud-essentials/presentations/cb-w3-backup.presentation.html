Backup Fundamentals
Three backup types define what data is copied and how long it takes.
Full Backup
Copies ALL data every time. Longest backup window, largest storage. Simplest restore -- just load the full backup. Typically done weekly or monthly as a baseline.
Incremental Backup
Copies only data changed since the LAST backup (full or incremental). Fastest backup, smallest storage. Restore requires the full backup plus every incremental in sequence.
Differential Backup
Copies all data changed since the last FULL backup. Larger than incremental but simpler restore: full backup + latest differential. Good balance of speed and restore simplicity.

RPO and RTO
The two metrics that define your backup requirements. Every business decision starts here.
RPO (Recovery Point Objective)
Maximum acceptable data loss measured in time. RPO of 1 hour means you can lose at most 1 hour of data. Drives backup frequency: RPO of 1 hour requires hourly backups minimum.
RTO (Recovery Time Objective)
Maximum acceptable downtime. RTO of 4 hours means the system must be back online within 4 hours of failure. Drives recovery strategy: shorter RTO requires faster restore methods.
Cost vs. RPO/RTO
Lower RPO/RTO = higher cost. RPO near-zero requires real-time replication. RTO near-zero requires hot standby. Every organization must balance protection against budget.

Cloud Backup Services
Every major provider offers managed backup services that handle scheduling, retention, and cross-region replication.
AWS Backup
Centralized backup service for EC2, EBS, RDS, DynamoDB, EFS, S3. Policy-based scheduling, lifecycle rules, cross-region copy. Single pane of glass for all AWS backup management.
Azure Backup
Backs up VMs, SQL databases, file shares, SAP HANA. Recovery Services vault stores backups. Supports instant restore from snapshots. Integrates with Azure Policy for enforcement.
GCP Backup & DR
Backup for Compute Engine VMs, Cloud SQL, GKE. Backup plans define schedules and retention. Cross-region backup for disaster recovery. Managed service -- no backup server to maintain.

Snapshot Management
Snapshots capture the state of a disk at a point in time. They are the foundation of cloud backup.
How Snapshots Work
First snapshot copies the full disk (stored as blocks). Subsequent snapshots are incremental -- only changed blocks are stored. Efficient storage but the chain is important for restoration.
Application-Consistent
A crash-consistent snapshot captures disk state. An application-consistent snapshot flushes buffers and freezes I/O first. Databases REQUIRE application-consistent snapshots to avoid corruption.
Snapshot Lifecycle
Automate snapshot creation (daily, hourly). Automate deletion of old snapshots (retain 30 days). Copy snapshots to another region for DR. Tag snapshots for cost tracking and compliance.
Slide 6 of 12
Data Replication
Replication copies data to another location in real-time or near-real-time. Stronger protection than periodic backups.
Synchronous Replication
Data is written to primary and replica simultaneously. Zero data loss (RPO = 0). Higher latency on writes. Used within the same region/AZ. AWS EBS multi-attach, Azure ZRS.
Asynchronous Replication
Data is written to primary first, then replicated with a delay. Small data loss possible (RPO = seconds to minutes). Used for cross-region replication. Lower latency on writes.
Geo-Replication
Replicate data across geographic regions. Protects against regional disasters (earthquake, power grid failure). S3 Cross-Region Replication, Azure GRS, GCP multi-regional storage.
Slide 7 of 12
Retention Policies
How long to keep backups depends on compliance, cost, and business requirements.
Compliance-Driven
HIPAA: 6 years. SOX: 7 years. GDPR: varies but requires data deletion on request. PCI-DSS: 1 year minimum for audit trails. Know your requirements before setting retention.
Tiered Retention
Daily backups retained 30 days. Weekly retained 12 weeks. Monthly retained 12 months. Yearly retained 7 years. Grandfather-Father-Son (GFS) is the standard pattern.
Cost Optimization
Move old backups to cheaper storage tiers. AWS Glacier for long-term retention. Azure Archive tier. Delete backups you no longer need -- stale data costs money and increases risk.
Slide 8 of 12
The 3-2-1 Backup Rule
The gold standard for backup resilience. Simple to remember, critical to follow.
3 Copies
Keep three copies of your data: the production data plus two backups. If any one copy is lost or corrupted, you still have two others.
2 Different Media
Store backups on two different types of media or storage. Example: EBS snapshots + S3 object storage. Protects against media-specific failures.
1 Offsite Copy
Keep at least one copy in a different geographic location. Cross-region replication or cross-cloud backup. Protects against site-wide disasters (fire, flood, region outage).
Slide 9 of 12
Restore Procedures
A backup you cannot restore is worthless. Test restores regularly and document the procedure.
Restore Testing
Schedule quarterly restore tests. Pick a random backup, restore it to an isolated environment, validate data integrity. If you have never tested a restore, you do not have a backup -- you have hope.
Bare-Metal Restore
Restore an entire server from backup: OS, applications, data. Cloud equivalent: launch a new VM from a snapshot or AMI. Faster than on-prem because there is no hardware to provision.
Granular Restore
Restore a single file, table, or object from backup. File-level restore from Azure Backup. Item-level recovery from AWS Backup for DynamoDB. Faster and less disruptive than full restore.

Key Takeaways
1Three backup types: Full (all data), Incremental (changes since last backup), Differential (changes since last full).
2RPO = max acceptable data loss. RTO = max acceptable downtime. These drive backup frequency and recovery strategy.
3Cloud backup services (AWS Backup, Azure Backup) centralize scheduling, retention, and cross-region copy.
4Snapshots are incremental block copies. Always use application-consistent snapshots for databases.
5The 3-2-1 rule: 3 copies, 2 media types, 1 offsite. Non-negotiable for production data.
6Test restores quarterly. An untested backup is not a backup -- it is a liability.
