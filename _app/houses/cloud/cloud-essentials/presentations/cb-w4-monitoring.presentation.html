Cloud Observability
Three pillars of observability: metrics, logs, and traces. Together they tell you what happened, why, and where.
Metrics
Numerical measurements over time: CPU utilization, request latency, error rate, disk IOPS. CloudWatch, Azure Monitor, Cloud Monitoring. The foundation for alerting and capacity planning.
Logs
Timestamped text records of events: application logs, access logs, error logs, audit logs. CloudWatch Logs, Azure Log Analytics, Cloud Logging. Essential for debugging and compliance.
Traces
End-to-end request flow across services. AWS X-Ray, Azure Application Insights, Google Cloud Trace. Shows which microservice caused the latency. Critical for distributed systems.

Core Metrics
The essential metrics every cloud engineer monitors. These are your early warning system.
CPU Utilization
Percentage of allocated CPU in use. Sustained 80%+ indicates need to scale up or out. Spikes to 100% cause request queuing and timeouts. Most common auto-scaling trigger.
Memory Utilization
Percentage of RAM in use. Memory leaks show as steadily increasing usage. OOM (Out of Memory) kills crash containers and processes without warning. Not always available as a default metric.
Disk I/O and Latency
IOPS (operations per second) and latency (ms per operation). Database performance depends heavily on disk I/O. High latency indicates throttling or undersized storage tier.

Network & Application Metrics
Infrastructure metrics tell you WHAT is happening. Application metrics tell you HOW users are affected.
Network Throughput
Bytes in/out per second. Helps identify bandwidth bottlenecks, unexpected data transfer, and potential data exfiltration. Monitor egress to predict cost.
Request Rate & Latency
Requests per second and p50/p95/p99 latency. P99 latency is the worst 1% of requests -- often 10x the average. SLAs should target p95 or p99, not average.
Error Rate
Percentage of requests returning 4xx or 5xx errors. Spike in 5xx = server-side issue. Spike in 4xx = client-side or configuration issue. Alert on error rate thresholds.

Alerting Strategy
Alerts notify humans when metrics cross thresholds. Too few alerts miss problems. Too many cause alert fatigue.
Threshold Alerts
Fire when a metric exceeds a static value for a duration. Example: CPU > 90% for 5 minutes. Simple and predictable. Works for well-understood baselines.
Anomaly Detection
ML-based alerts that learn normal patterns and fire on deviations. No static thresholds needed. AWS CloudWatch Anomaly Detection, Azure Smart Detection. Great for variable workloads.
Alert Severity Levels
Critical: production down, wake people up. Warning: degraded performance, investigate soon. Info: capacity trending, plan for next week. Route by severity to avoid alert fatigue.

Dashboards
Dashboards visualize metrics for real-time situational awareness. Every team needs a different view.
Operational Dashboard
Real-time: request rate, error rate, latency, CPU, memory. On a wall monitor in the ops center. Shows the current health of all production systems at a glance.
Business Dashboard
Sign-ups per hour, revenue, active users, conversion rate. Leadership visibility into how the platform is performing from a business perspective.
Cost Dashboard
Daily spend, projected monthly total, spend by service, spend by team. AWS Cost Explorer, Azure Cost Management. Identify cost anomalies before they become budget overruns.

Log Aggregation
Centralize logs from every service into a single queryable system. Scattered logs are useless during an incident.
Centralized Logging
Ship all logs to one platform: CloudWatch Logs, Azure Log Analytics, ELK Stack (Elasticsearch + Logstash + Kibana), Datadog, Splunk. Search across all services in one query.
Structured Logging
Log in JSON format with consistent fields: timestamp, level, service, request_id, message. Structured logs are parseable and filterable. Unstructured text logs are noise.
Log Retention
Hot logs (searchable) retained 30-90 days. Cold logs (archived) retained per compliance: 1-7 years. Lifecycle policies automatically transition logs to cheaper storage tiers.

APM: Application Performance
APM tools trace requests through your application stack and identify performance bottlenecks.
What APM Shows
Request flow: browser to load balancer to API to database to cache. Time spent in each component. Which function call is slow. Which query is unoptimized. Which service is the bottleneck.
APM Tools
AWS X-Ray, Azure Application Insights, Google Cloud Trace, Datadog APM, New Relic. Instrument your code with tracing SDKs. Minimal performance overhead with sampling.
Service Maps
Visual maps showing how services communicate and where latency accumulates. Automatically generated from trace data. Essential for understanding complex microservice architectures.

Cost Monitoring
Cloud cost is a metric like any other. Monitor it, alert on anomalies, and optimize continuously.
Cost Allocation Tags
Tag every resource with project, team, environment. Cost reports break down spending by tag. Without tags, you cannot answer "which team is spending the most?"
Budget Alerts
Set monthly budgets with alerts at 50%, 80%, 100%, and 120%. AWS Budgets, Azure Cost Management Budgets. Automated actions: notify, throttle, or stop resources.
Right-Sizing Recommendations
AWS Compute Optimizer, Azure Advisor, GCP Recommender. Analyze utilization and recommend smaller instance types, reserved instances, or spot instances. Savings of 30-60% are common.
Slide 10 of 13
Capacity Forecasting
Predict future resource needs based on historical trends. Plan ahead instead of reacting.
Trend Analysis
Plot storage growth, request rate, and compute usage over 6-12 months. Identify linear and exponential growth patterns. Project when you will hit capacity limits.
Seasonal Patterns
E-commerce peaks in November. Tax software peaks in April. Education platforms peak in September. Historical patterns predict future demand. Schedule scaling in advance.
Capacity Buffers
Maintain 20-30% headroom above peak usage. Insufficient buffer means degraded performance during unexpected spikes. Too much buffer wastes money. Monitor and adjust quarterly.

Key Takeaways
1Three pillars of observability: metrics (numbers), logs (text events), traces (request flows).
2Core metrics: CPU, memory, disk I/O, network throughput, request rate, error rate, latency (p95/p99).
3Alert strategy: threshold for known baselines, anomaly detection for variable workloads. Route by severity.
4Centralize logs in structured JSON format. Retain hot logs 30-90 days, archive per compliance requirements.
5APM traces requests end-to-end across services. Essential for debugging distributed microservice architectures.
6Cost is a metric. Tag resources, set budget alerts, and review right-sizing recommendations monthly.
