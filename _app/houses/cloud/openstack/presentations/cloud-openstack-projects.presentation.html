Slide 2 — Core Projects Overview
The Core Projects at a Glance
Six essential services that every OpenStack deployment must have to function.
Nova
openstack-nova
Compute service. Manages VM lifecycle: spawn, schedule, migrate, and decommission virtual machines across hypervisor hosts.
Neutron
openstack-neutron
Networking service. Software Defined Networking — virtual switches, routers, security groups, floating IPs, and DHCP.
Swift
openstack-swift
Object Storage. Scalable, eventually-consistent, RESTful storage for unstructured data — similar to Amazon S3.
Cinder
openstack-cinder
Block Storage. Provides persistent block volumes that attach to instances — similar to Amazon EBS.
Keystone
openstack-keystone
Identity service. Authentication, authorization tokens, service catalog, and role-based access control.
Glance
openstack-glance
Image service. Stores and retrieves VM disk images in formats like QCOW2, VMDK, and RAW for Nova to boot instances.
Service Dependency Order (install in this sequence): Keystone → Glance → Nova → Neutron → Cinder → (Horizon)
Slide 3 — Nova: Compute
Nova: The Compute Engine
OpenStack Compute manages the full lifecycle of virtual machine instances across one or many hypervisor hosts.
⚙️ What Nova Does
  • Spawning — launches VMs from Glance images on compute hosts
  • Scheduling — nova-scheduler selects the best compute node
  • Lifecycle — resize, suspend, resume, snapshot, migrate
  • Decommissioning — cleanly deletes instances and releases resources
  • Flavors — pre-defined VM sizes (vcpus, RAM, disk)
🏗️ Nova's Distributed Components
  • nova-api — Accepts and validates all REST API requests
  • nova-scheduler — Chooses compute node using filters/weights
  • nova-conductor — Database proxy; isolates compute from DB access
  • nova-compute — Runs on each hypervisor; manages VMs via libvirt
  • nova-novncproxy — Web-based VNC console access
🔄 VM Launch Flow
User/API Request │ ▼ nova-api ──validates──▶ Keystone (token check) │ ▼ nova-scheduler ──queries──▶ nova-conductor ──▶ Database │ ▼ (selects best compute host) nova-compute ──▶ libvirt/KVM ├── Pull image from Glance ├── Allocate network via Neutron ├── Allocate volume via Cinder (optional) └── Boot VM ✓
Slide 4 — Neutron & Swift
Neutron: Networking & Swift: Object Storage
SDN-based virtual networking and massively scalable object storage.
🌐 Neutron — Software Defined Networking
  • Pluggable architecture — swap backend plugins (OVS, LinuxBridge, OVN)
  • Creates overlay networks using VXLAN, GRE, or VLAN tagging
  • Virtual routers provide inter-network routing and NAT
  • Security groups = stateful firewall rules per port
  • DHCP agents hand out IP addresses to VMs automatically
  • Floating IPs map external addresses to tenant VM private IPs
  • Load Balancer as a Service (LBaaS) and VPNaaS available
🗄️ Swift — Object Storage
  • REST API compatible with Amazon S3 — store/retrieve via HTTP
  • Data is distributed across multiple storage nodes (no single point of failure)
  • Replicated 3x by default — survives disk and node failures
  • Eventually consistent — replicas sync asynchronously
  • No metadata limits — arbitrary key/value object headers
  • Scales horizontally by adding storage nodes to the ring
  • Glance uses Swift as its image storage backend by default
Neutron Architecture: The neutron-server runs on the controller. neutron-linuxbridge-agent (or ovs-agent) runs on compute and network nodes, building the actual data-plane plumbing. The L3 agent handles virtual router operations. All agents report state back to the server via RabbitMQ.
Slide 5 — Glance, Cinder & Keystone
Glance, Cinder & Keystone
Image registry, persistent block storage, and the identity backbone of the entire platform.
🖼️ Glance — Image Service
  • Central registry of VM disk images
  • Supports: QCOW2, RAW, VMDK, VHD formats
  • Multiple storage backends: local filesystem, Swift, Ceph, S3
  • Images can be public, private, or community-shared
  • nova-compute pulls images from Glance at launch time
💾 Cinder — Block Storage
  • Persistent volumes that survive VM deletion
  • Attach/detach volumes from instances dynamically
  • Backends: LVM (default), Ceph RBD, NetApp, Pure
  • Snapshot and clone operations on volumes
  • Boot-from-volume for diskless compute nodes
🔑 Keystone — Identity
  • Issues time-limited bearer tokens (Fernet/UUID)
  • Maintains the service catalog — each service registers its endpoint
  • Projects (tenants), Users, Roles, and Domains
  • External auth: LDAP, OAuth2, SAML2 federation
  • Every API call is validated against Keystone first
Why Keystone is the linchpin: Before any other service responds to a request, it calls Keystone to validate the token. This is why Keystone must be installed first. The service catalog tells clients where to find every service's API endpoint — without it, nothing can communicate.

🔧 What Each Optional Service Does
  • Horizon — Web dashboard; GUI for all OpenStack operations
  • Heat — Orchestration; deploy complex stacks via YAML templates (HOT)
  • Ceilometer — Telemetry; collects metering data for billing/monitoring
  • Trove — Database-as-a-Service; managed MySQL, PostgreSQL, Redis
  • Sahara — Elastic Data Processing; provision Hadoop/Spark clusters
  • Magnum — Container Orchestration Engine; deploy Kubernetes clusters
Heat HOT Templates are similar to AWS CloudFormation or Terraform. A single YAML file can define multiple VMs, networks, security groups, and volumes — then Heat provisions them in the correct dependency order automatically.
Slide 7 — Knowledge Check
Knowledge Check
Select the best answer for each question, then reveal the explanation.
1. Which Nova component acts as a database proxy to isolate compute nodes from direct database access?
A
nova-api
B
nova-scheduler
C
nova-conductor
D
nova-novncproxy
Correct! nova-conductor runs on the controller and acts as a database intermediary. Compute nodes do not have direct database credentials — all DB operations go through nova-conductor via RabbitMQ, improving security and allowing rolling upgrades.
2. What is the key difference between Swift (object storage) and Cinder (block storage)?
A
Swift is faster; Cinder is larger capacity
B
Swift stores data via REST API (no OS mount); Cinder provides block devices that mount like a disk
C
Swift requires replication; Cinder does not
D
They are interchangeable — both provide the same interface
Correct! Swift is accessed via HTTP GET/PUT — applications talk to it as a web service. Cinder volumes appear as raw block devices (e.g., /dev/vdb) that the OS can partition and format like a physical disk. They serve completely different use cases.
3. Which optional OpenStack service would you use to deploy a full application stack (VMs + networks + volumes) from a single YAML template?
A
Ceilometer
B
Trove
C
Heat
D
Horizon
Correct! Heat is OpenStack's orchestration service. It uses Heat Orchestration Templates (HOT) — YAML files that describe all resources in a stack and their dependencies. Heat is deployed in 67% of OpenStack environments.
4. Keystone's service catalog tells OpenStack clients what information?
A
The list of all running virtual machines
B
The current token expiration time
C
The API endpoint URLs for every registered service
D
The list of available VM flavors
Correct! The service catalog is returned as part of the authentication response. It lists every OpenStack service (Nova, Neutron, Glance, etc.) and the URL of their API endpoints for each region. Clients use this to know where to send requests.
Slide 8 — Module Summary
Module Summary
You now understand the full OpenStack project ecosystem and the role each service plays.
Nova — Compute
Manages VM lifecycle across hypervisor nodes. Distributed components: api, scheduler, conductor, compute, novncproxy. Communicates via RabbitMQ.
Neutron — Networking
Software Defined Networking with pluggable backends (OVS, LinuxBridge). Handles virtual switches, routers, security groups, floating IPs, and DHCP.
Swift — Object Storage
RESTful, eventually-consistent, 3x-replicated object store. Similar to Amazon S3. Scales horizontally. Used as Glance's image backend.
Cinder — Block Storage
Persistent block volumes that attach to VMs like physical disks. Backends: LVM, Ceph RBD. Supports snapshots, clones, and boot-from-volume.
Keystone — Identity
Authentication, token issuance, service catalog. Install first. Every API call is validated here. Supports LDAP, OAuth2, and SAML2 federation.
Optional: Horizon, Heat
Horizon (87% adoption): web dashboard. Heat (67%): orchestration via HOT YAML templates. Ceilometer: telemetry. Trove: DBaaS. Sahara: big data clusters.
