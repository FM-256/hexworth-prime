Slide 2 — Definition
What is OpenStack?
An open-source cloud operating system that controls pools of compute, storage, and networking resources.
Core Definition: OpenStack is a free, open-source Infrastructure-as-a-Service (IaaS) platform. It lets administrators provision and manage virtual machines, object storage, and virtual networks through a single unified API or web dashboard — across an entire datacenter.
🖥️ What It Controls
  • Compute — VM lifecycle (create, schedule, destroy)
  • Storage — Object, block, and file storage layers
  • Networking — Virtual switches, routers, and subnets
  • Identity — Auth tokens and service catalog
  • Images — VM disk image registry
⚙️ How It Works
  • All services expose RESTful APIs
  • Services communicate via a shared message bus (RabbitMQ)
  • Configuration stored in SQL databases (MariaDB)
  • Tokens cached in Memcached for performance
  • Operators interact via CLI, API, or Horizon dashboard

Slide 3 — History & Use Cases
Origin Story & Real-World Use Cases
Born from a collaboration between Rackspace and NASA in 2010.
📅 Timeline
  • 2010 — Rackspace (Cloud Files) + NASA (Nebula) open-source their cloud code together
  • 2012 — OpenStack Foundation formed; governance shifts to community
  • 2016+ — Hundreds of companies contributing; over 60 releases
  • Today — Powers private clouds at telcos, governments, research labs worldwide
🌐 Who Uses OpenStack?
  • CERN — Physics research computing infrastructure
  • Walmart — Private cloud for e-commerce workloads
  • AT&T / Verizon — NFV (network function virtualization)
  • NASA — Origin organization, still in use
  • Universities — Educational labs and research HPC

Slide 4 — Hardware Requirements
Hardware Requirements
A minimal OpenStack deployment requires at least two physical nodes with specific hardware profiles.
🖥️ Controller Node
  • CPU: 4+ processor cores (no nested virt needed)
  • RAM: 16 GB minimum (32 GB recommended)
  • Disk: 1 TB storage (OS + databases + logs)
  • NICs: 2 network interface cards
  • Role: Runs all control-plane services — Keystone, Glance, Nova API, Neutron server, Horizon, MariaDB, RabbitMQ, Memcached
⚡ Compute Node
  • CPU: 4+ cores with hardware virtualization (VT-x / AMD-V)
  • RAM: 16 GB minimum (more = more VMs)
  • Disk: 1 TB (ephemeral instance storage)
  • NICs: 2 network interface cards
  • Role: Runs nova-compute + Neutron agent; hypervisor host for all guest VMs

Slide 5 — Software Requirements
Software Requirements
OpenStack is built on a stack of interdependent services, divided into core and optional components.
✅ Core Services Required
  • Nova — Compute: VM lifecycle management
  • Neutron — Networking: virtual switches and routers
  • Swift — Object Storage: scalable, RESTful
  • Cinder — Block Storage: persistent volumes
  • Keystone — Identity: auth tokens, service catalog
  • Glance — Image Service: VM disk image registry
⚙️ Optional Services Add-on
  • Horizon — Web dashboard (87% of deployments)
  • Ceilometer — Telemetry / metering data collection
  • Heat — Orchestration: deploy stacks via templates
  • Trove — Database-as-a-Service
  • Sahara — Big data / Hadoop cluster provisioning
  • Magnum — Container orchestration (Kubernetes)

Slide 6 — Network Design
Networking: Provider vs. Self-Service
OpenStack supports two fundamentally different networking models depending on complexity needs.
🔌 Provider Networks (Layer 2)
  • Simplest model — VMs connect directly to physical network
  • No virtual routers; routing is done by physical infrastructure
  • Admin creates networks; tenants cannot create their own
  • Best for: single-tenant lab environments, simple clouds
  • Uses: Linux Bridge or Open vSwitch (OVS) for switching
🌐 Self-Service Networks (Layer 3)
  • Tenants create their own private virtual networks
  • NAT-based routers connect tenant networks to provider network
  • Floating IPs for external reachability
  • Best for: multi-tenant production clouds
  • Uses: OVS with VXLAN or GRE overlay tunnels
🗺️ Network Layout (Minimal Two-Node Setup)
Management Network: 10.0.0.0/24 ├── controller → 10.0.0.11 (NIC: ens3 / eth0) └── compute → 10.0.0.31 (NIC: ens3 / eth0) Provider Network: 203.0.113.0/24 (public-facing) ├── controller → external NIC (ens4 / eth1) — no IP (raw bridging) └── compute → external NIC (ens4 / eth1) — no IP (raw bridging) VM traffic flows: VM → OVS bridge (br-ex) → physical NIC (ens4) → upstream router API traffic: stays on 10.0.0.0/24 management network

Slide 8 — Module Summary
Module Summary
You have covered the foundational concepts for understanding an OpenStack environment.
What is OpenStack?
An open-source IaaS platform that controls compute, storage, and networking resources across a datacenter through a unified API. Services communicate via RabbitMQ and store state in MariaDB.
Origin
Co-founded in 2010 by Rackspace (Cloud Files) and NASA (Nebula). The OpenStack Foundation formed in 2012 to govern the growing community project now comprising 60+ releases.
Hardware Requirements
Minimum two nodes: Controller (runs control-plane services) and Compute (runs hypervisor). Each node requires 4+ cores, 16 GB RAM, 1 TB disk, and two NICs.
Software Architecture
Core services: Nova, Neutron, Swift, Cinder, Keystone, Glance. Optional: Horizon (dashboard), Heat (orchestration), Ceilometer, Trove, Sahara, Magnum.
Network Models
Provider Networks (Layer 2): admin-controlled, simple, direct physical access. Self-Service Networks (Layer 3): tenant-controlled, NAT routers, floating IPs, VXLAN/GRE overlays.
Network Layout
Management network (10.0.0.0/24) for API/DB/MQ traffic. Provider network for VM data-plane traffic. Controller: 10.0.0.11. Compute: 10.0.0.31.
