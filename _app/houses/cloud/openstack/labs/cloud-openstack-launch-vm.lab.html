Upload a Cloud Image

Command Builder · Dropdown Selection
Glance stores VM images. Before launching any instance you must upload a bootable image. CirrOS is a minimal test cloud image (about 20 MB) commonly used for OpenStack development. The upload flags determine how the image is stored and who can use it.

Build the Correct glance Image Upload Command

Select the correct value from each dropdown to complete the OpenStack CLI command:

# Source admin credentials first . admin-openrc

# Upload the CirrOS test image openstack image create "cirros" \
  --file cirros-0.6.2-x86_64-disk.img \
  --disk-format \
  --container-format \
  --
Hint: QCOW2 (QEMU Copy-On-Write 2) is the native KVM/QEMU disk format and the standard for OpenStack. The container format describes the outer wrapper: bare means no wrapping — just raw image data. Marking the image public makes it available to all projects.

Create a Self-Service Network

Fill-in-the-Blank · CLI Commands
Self-service networks (tenant networks) allow projects to create isolated Layer 2 segments. You define a subnet CIDR, enable DHCP so instances receive IPs automatically, and set a gateway that allows traffic to reach the provider (external) network via the Neutron router.

Complete the Network and Subnet Creation Commands

This creates a private tenant network called selfservice then attaches a subnet to it:

Resulting commands (based on your answers above):

openstack network create selfservice
openstack subnet create selfservice \
  --network selfservice \
  --subnet-range ??? \
  --gateway ??? \
  --??? \
  --ip-version ???
Convention: The selfservice subnet uses RFC 1918 private space (172.16.1.0/24 is typical in OpenStack docs). The gateway (.1) is the virtual router interface. DHCP must be enabled so instances get addresses automatically.

By default, the default security group blocks all inbound traffic. You need to explicitly allow SSH (TCP/22) for remote management and ICMP for ping connectivity testing. Ingress rules are per-protocol, per-port, and per-source CIDR.

Launch an Instance

Command Assembly · Dropdown Builder
The openstack server create command assembles all the building blocks: a flavor (hardware profile), an image (boot disk), a network, a security group, and a key pair for SSH authentication. Getting any one of these wrong means the instance will fail to launch or will be unreachable.

Assemble the Server Create Command

Select the correct parameter values for each flag:

openstack server create \
  --flavor \
  --image \
  --nic net-id= \
  --security-group \
  --key-name \
  selfservice-instance
Flavor m1.nano: 1 vCPU, 64 MB RAM, 1 GB disk — the smallest flavor, perfect for CirrOS test images. Always launch on the selfservice (private) network; the public IP is added later via floating IP. The key pair must have been created first with openstack keypair create.
5

Access the Instance

Interactive Walkthrough · Checklist
Instances on the selfservice network have private IPs only. To reach them from the outside (your management workstation) you must allocate a floating IP from the provider network pool and associate it with the instance's port. Then SSH in using the key pair.

Step-by-Step: Floating IP and SSH Access

Work through each step below. Check each step off as you complete or review it.

  • 1

    Allocate a floating IP from the provider (external) network pool:

    openstack floating ip create provider
  • 2

    Note the allocated floating IP address (e.g., 203.0.113.101) shown in the output field floating_ip_address.

    openstack floating ip list
  • 3

    Associate the floating IP with the running instance:

    openstack server add floating ip selfservice-instance 203.0.113.101
  • 4

    Verify the instance has both a fixed and floating IP:

    openstack server show selfservice-instance | grep addresses
  • 5

    Test reachability with ping before attempting SSH:

    ping -c 4 203.0.113.101
  • 6

    SSH into the instance using your key pair (CirrOS default user is cirros):

    ssh -i mykey.pem cirros@203.0.113.101
Troubleshooting: If ping fails, check that (1) the router gateway is set to the provider network, (2) the security group allows ICMP ingress, (3) the floating IP is correctly associated. If SSH fails, verify the key pair file permissions are 400.
