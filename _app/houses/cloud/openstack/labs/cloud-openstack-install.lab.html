Network Interface Configuration

Fill-in-the-Blank · Form Exercise
OpenStack requires two network interfaces per node. The management network (10.0.0.0/24) carries API, database, and messaging traffic between nodes. The provider network (203.0.113.0/24) is the external-facing interface used for floating IPs and direct instance access.

Controller Node — /etc/netplan/00-installer-config.yaml

The controller node runs management services: Keystone, Glance, Nova API, Neutron Server, and the database. Fill in the correct IP address values below.

# Management interface (enp3s0) — internal API traffic network: ethernets: enp3s0: addresses: - ___.___.___.___ /24 routes: - to: default via: ___.___.___.___ nameservers: addresses: [8.8.8.8, 8.8.4.4] # Provider interface (enp4s0) — external/floating IP traffic enp4s0: dhcp4: no

Compute Node — /etc/netplan/00-installer-config.yaml

network: ethernets: enp3s0: addresses: - ___.___.___.___ /24 routes: - to: default via: ___.___.___.___ nameservers: addresses: [8.8.8.8, 8.8.4.4] enp4s0: dhcp4: no
Convention: The OpenStack documentation assigns .11 to the controller and .31 to the compute node. Gateways are always .1 on the management subnet.

NTP & Database Setup

Drag-and-Drop · Correct Order
Accurate time synchronisation is critical in OpenStack — tokens have expiry timestamps and distributed services must agree on the clock. The controller runs Chrony as an NTP server; compute nodes sync from it. MariaDB provides the relational backend for all OpenStack service databases.

Hint: Install packages first, then configure them, then restart/enable services. The database must be secured (mysql_secure_installation) before creating OpenStack databases.

Keystone Installation

Fill-in-the-Blank · Config Validation
Keystone is the Identity service — the foundation of all OpenStack authentication. Every service-to-service call passes through Keystone. You must configure the database connection string, token provider, and then bootstrap the admin credentials before initialising the Fernet key repository.

/etc/keystone/keystone.conf

[database] # MySQL connection string for Keystone's own database connection = mysql+pymysql://keystone:@controller/keystone [token] # Token provider — use fernet (stateless, scalable) provider =

Bootstrap Command

Fill in the missing arguments for the keystone-manage bootstrap command:

keystone-manage bootstrap \ --bootstrap-password \ --bootstrap-admin-url http://controller:/v3/ \ --bootstrap-internal-url http://controller:5000/v3/ \ --bootstrap-public-url http://controller:5000/v3/ \ --bootstrap-region-id
Hint: Fernet is a lightweight symmetric encryption token provider. The admin URL is typically on port 5000 in newer OpenStack releases. The default region name is RegionOne.
