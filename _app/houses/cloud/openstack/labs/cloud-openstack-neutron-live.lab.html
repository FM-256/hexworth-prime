Live Lab: Build Your Own Network

Every lab so far has borrowed a network the cloud handed you. Now you build one: your own private network, your own address range, and a router that gives it a way out. This is the difference between renting a seat on someone else’s infrastructure and actually operating your own — and it is four commands, once you know which four.
Personal cloud required. This lab creates real resources, so it needs your own cloud project. Sign in and launch below: the launcher will tell you which mode you got. If it says read-only, a personal project was not available this time (the cloud may be full, or the credential service may be briefly unreachable); try again later. Session limits still apply (120 minutes), but everything you build here lives in the cloud and will be waiting when you relaunch.

Mission Steps

See whose network you have been using

Every lab so far used shared. Look at who owns what before you build anything.

openstack network list --share # the ones the cloud lends everyone openstack network list # everything you can see openstack router list # probably empty -- you have never needed one

Start clean, then build the network and its subnet

A network is just a layer-2 broadcast domain. On its own it cannot address anything — the subnet is what carries the address range.

openstack server delete lab5-vm 2>/dev/null # leftovers from a previous run openstack router unset --external-gateway lab5-router 2>/dev/null openstack router remove subnet lab5-router lab5-subnet 2>/dev/null openstack router delete lab5-router 2>/dev/null openstack network delete lab5-net 2>/dev/null openstack network create lab5-net openstack subnet create lab5-subnet \ --network lab5-net --subnet-range 10.55.0.0/24

Order matters, and every line above earns its place. A router with an interface still attached refuses to delete; a network with a router port on it refuses to delete. Skip the remove subnet line and the teardown fails silently, so your next attempt creates a second lab5-net — and from then on every command that names it fails with More than one Network exists with the name 'lab5-net'. That is not hypothetical: this lab's own QC gate hit it and that is why the line is here.

Give it a way out

Your network is now real and completely isolated. A router with an external gateway is what connects it to the outside; the internal interface is what connects the router to your subnet. You need both.

openstack router create lab5-router openstack router set lab5-router --external-gateway public openstack router add subnet lab5-router lab5-subnet openstack router show lab5-router -f value -c external_gateway_info
EXPECTa network_id, not None (check 23 needs the gateway AND a subnet interface)
IF NOTNone means the external gateway was never set: the router exists but leads nowhere

Put a machine on it

A network with nothing on it is a diagram. Boot a server onto your own network rather than the shared one.

openstack server create \ --image <IMAGE-NAME> --flavor m1.nano \ --network lab5-net lab5-vm openstack server show lab5-vm -f value -c status # WAIT for: ACTIVE openstack server show lab5-vm -f value -c addresses # must show lab5-net
EXPECTlab5-net (check 24 wants a machine actually ON your network)
IF NOTa shared network here means you built lab5-net and then booted somewhere else
