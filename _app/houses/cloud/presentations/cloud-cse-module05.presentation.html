Section 1

Secure Software Design

The 3 R's of Software Security

R Reliability
R Resiliency
R Recovery

✅ Reliable

Software functions as expected under normal conditions. Predictable behavior, consistent outputs, and proper error handling.

💪 Resilient

Software and infrastructure can withstand misuse, attacks, and unexpected loads without catastrophic failure.

🔄 Recoverable

Application can be restored to normal operations with minimal disruption after an incident or failure.

💡 CIA Triad in Application Design

Confidentiality: Minimize sensitive data exposure, mask data, encrypt at rest/transit
Integrity: Use hashing, digital signatures, duty separation
Availability: Build redundancy, protect against DDoS, plan for DR

Section 2

Web Application Firewall (WAF)

Why Use a WAF?

Protect cloud applications from security breaches at the application layer (Layer 7)

🛡️ Key Protections

  • Cross-site scripting (XSS)
  • SQL injection
  • Cross-site request forgery (CSRF)
  • File inclusion attacks
  • Brute force attacks
  • Malware uploads

☁️ Azure WAF Options

  • Application Gateway: Regional, HTTP/S traffic management
  • Azure Front Door: Global, Layer 7 routing
  • SSL/TLS termination
  • URL-based routing

🌐 AWS WAF

  • Integrates with ALB
  • Works with CloudFront CDN
  • Custom rule sets
  • Managed rule groups

📚 M04 Connection: Network Architecture

WAF should be placed after Network Firewall in the traffic flow for defense-in-depth (Module 04).

Section 4

Security by Design Principles

🔒 Core Principles

  • Defense in Depth
  • Diversity of Defense
  • Separation of Duties
  • Least Privilege
  • Complete Mediation

🏗️ Design Concepts

  • Economy of Mechanism (keep it simple)
  • Open Design (no security by obscurity)
  • Collaborative Design
  • Component Reuse
  • Psychological Acceptability

✅ Application Best Practices

  • Prevent misconfigurations
  • Protect secrets in code
  • Close management ports
  • Monitor security posture
  • Security at design start

📊 Traceability & Integrity

  • Accountability: Who did what?
  • Auditing: When, where, what
  • Logging: Protected evidence
  • Non-repudiation: Can't deny actions

💡 Code Signing & Digital Signatures

Embed digital signatures in application code to validate integrity. Blockchain provides immutable audit trails with no single point of failure.

💡 Shift Left Security

Integrate security testing early in development (SAST) rather than waiting until production (DAST). Combine with RASP for continuous protection.

Section 6

API Security

📋 Design & Development

  • Document security requirements (NIST, OWASP)
  • Include logic in design reviews
  • Draft secure coding practices
  • Automate threat modeling
  • Use OWASP ASVS standards

☁️ Azure API Management

  • Strip sensitive response headers
  • Replace URLs with APIM gateway
  • Rate limiting and throttling
  • Monitor and alert through APIM
  • Hide original URLs

🌐 AWS Config

  • Continuous monitoring of configs
  • Audit compliance against policies
  • Evaluate after provisioning
  • Simplify troubleshooting
  • Change management control

📚 M02 Connection: API IAM

APIs must use proper authentication (OAuth, API keys) and authorization (RBAC) as covered in Module 02.

Section 7

Serverless Security

🔐 Security Best Practices

  • One role per function: Least privilege
  • Secure credentials: Use secrets manager
  • Know dependencies: Vulnerability assessments
  • Use variables: Protect hostnames in code
  • Automate security: CI/CD pipeline checks

☁️ Azure Functions

  • Perform input validation
  • Follow least privilege principles
  • Secure cloud storage encryption
  • Use Key Vault for secrets
  • Configure NSG rules
  • Enforce authentication

🌐 AWS Lambda

  • Least-privileged IAM roles
  • Separate role per function
  • Use API Gateway for DDoS protection
  • Clean /tmp directory
  • Use Secrets Manager
  • Protect CloudWatch logs

⚠️ Never Store Secrets in Code

Use AWS Secrets Manager, Azure Key Vault, or GCP Secret Manager. Never log sensitive information to console.

Section 8

Container Security

⚠️ Container Security Challenges

  • Exposed insecure ports
  • Leaked secrets and credentials
  • Elevated runtime privileges
  • Ephemeral workloads hard to monitor
  • CI/CD pipeline vulnerabilities
  • Increased attack surface in libraries

✅ Security Best Practices

  • Secure base images
  • Manage secrets securely
  • Restrict container privileges
  • Identify misconfigurations
  • Automate vulnerability scanning
  • Real-time logging and alerting
  • Adopt "shift left" security

💡 Container Security Lifecycle

Build: Scan images, sign containers
Deploy: Validate signatures, check configs
Runtime: Monitor behavior, detect anomalies
Kubernetes: Use Pod Security Policies, Network Policies, RBAC
