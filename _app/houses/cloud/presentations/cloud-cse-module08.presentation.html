Slide 2 of 11 Regulatory Compliance

Warning: Non-compliance with regulations can result in significant financial penalties and possible imprisonment. Jurisdiction is determined by local government and where data is processed/stored.

Key Regulatory Laws

GDPR (General Data Protection Regulation)

EU law protecting personal data and privacy for EU/EEA individuals.

  • Lawful, fair, transparent processing
  • Purpose and data limitation
  • Data subject rights (access, deletion, portability)
  • Consent requirements
  • Privacy by design
  • Data Protection Officer (DPO) requirement

FISMA (Federal Information Security Management Act)

U.S. federal law establishing cybersecurity standards for government IT.

  • DHS administers implementation
  • OMB oversight authority
  • US-CERT incident center
  • Major incident reporting to Congress
  • Breach notification requirements

FERPA (Family Educational Rights and Privacy Act)

Federal law protecting student education records privacy.

  • Parent rights for children's records
  • Student rights at age 18+
  • Applies to schools receiving DoE funds
  • Consent required for PII disclosure
Slide 3 of 11 Industry Compliance Standards

PCI-DSS (Payment Card Industry Data Security Standard)

Security standards for handling credit card data.

  • Build secure networks: Firewalls, no default passwords
  • Protect cardholder data: Encryption at rest/transit
  • Vulnerability management: Anti-malware, secure development
  • Access control: Need-to-know, authentication
  • Monitor & test: Network monitoring, security testing
  • Security policy: Written policies for all personnel

HIPAA (Health Insurance Portability and Accountability Act)

U.S. law protecting health information privacy and security.

  • Privacy Rule: PHI protection standards
  • Security Rule: ePHI safeguards (admin, physical, technical)
  • Breach Notification: Reporting requirements
  • Enforcement Rule: Penalties and compliance

SOX (Sarbanes-Oxley Act)

Protects investors from fraudulent accounting by public companies.

  • PCAOB oversight of audits
  • Auditor independence requirements
  • Executive certification of financials
  • Internal control reporting
  • Whistleblower protections

GLBA (Gramm-Leach-Bliley Act)

Regulates privacy/security of consumer financial information.

  • Financial Privacy Rule
  • Safeguards Rule
  • Pretexting Provisions
  • Customer consent for data sharing
Slide 4 of 11 HITRUST Common Security Framework

One Framework, One Assessment, Globally

HITRUST CSF leverages ISO, NIST, PCI, HIPAA, and GDPR to provide a comprehensive set of security and privacy controls for healthcare and beyond.

HITRUST CSF Structure

  • 19 Control Categories with control objectives and references
  • Mapped to authoritative sources for cross-references and alignment
  • Assurance Program for standardized assessment and certification
  • MyCSF Tool for managing assessments and reporting

HITRUST Certification Process

  1. Define Scope: Identify sensitive information (medical records, PII, billing)
  2. Map Data Flow: Document how data enters, exits, and moves
  3. Readiness Assessment: Self-assess using MyCSF tool
  4. Remediation: Address gaps and deficiencies
  5. Validated Assessment: External assessor performs audit
  6. Certification: HITRUST reviews and issues certification letter

Slide 6 of 11 FedRAMP Authorization

Federal Risk and Authorization Management Program

Government-wide program promoting secure cloud services across federal agencies with standardized security assessment based on FISMA and NIST standards.

FedRAMP Authorization Paths

Path Description Requirements
FedRAMP Ready Minimum security requirements met Ready for agency authorization
FedRAMP Authorized Authority to Operate (ATO) obtained Reusable by other agencies
FedRAMP Tailored Streamlined process Low-impact SaaS solutions only

Key FedRAMP Requirements

  • Continuous Monitoring (ConMon): Ongoing security performance monitoring
  • PMO Reporting: Report changes/incidents to FedRAMP PMO
  • NIST Alignment: Based on NIST 800-53 controls
  • Severe Penalties: Fines and imprisonment for non-compliance or fraud

Slide 8 of 11 Cloud Security Governance

Definition

Cloud Security Governance is the process of ensuring cloud services are used in a secure and compliant manner by defining and enforcing policies and controls.

Governance Pillars

Roles & Responsibilities

Clear accountability for security decisions

Framework Selection

ISO 27001, NIST CSF, or CSA CCM

Risk Management

Assess risks per risk appetite

Security Controls

Implement based on risk assessment

Continuous Assessment

Monitor, measure, improve

Keys to Maintaining Compliance

  1. Risk Management: Determine risk management strategy and framework
  2. Governance: Determine compliance and standards requirements
  3. Auditing & Assessment: Strategy for auditing resources for compliance
  4. Continuous Monitoring: Ongoing compliance maintenance strategy
Slide 9 of 11 Cloud-Native Auditing & Monitoring

Provider Compliance Tools

Azure Policy

  • Enforce organizational standards
  • Policy definitions and initiatives
  • Effects: audit, deny, modify, deploy
  • Compliance dashboard with drill-down
  • Automatic remediation of non-compliant resources
  • Extends to other clouds via Azure Arc

Microsoft Defender for Cloud

  • Protect multi-cloud resources
  • Integrates with Azure Policy
  • Maps to ISO, NIST, PCI, HIPAA, GDPR
  • Continuous compliance assessment
  • Remediation recommendations
  • Integrates with Purview Compliance Manager

AWS Config

  • Configuration change tracking
  • AWS-managed and custom rules
  • Compliance status reporting
  • Automatic remediation
  • Maps to ISO, NIST, PCI, HIPAA, GDPR

Amazon Inspector

  • Automatic vulnerability assessment
  • Agent-based and agentless scanning
  • CIS Benchmarks, PCI-DSS, OWASP Top 10
  • Integration with Security Hub
  • SNS notifications for findings

GCP Cloud Compliance Reports Manager

On-demand access to compliance documentation, certificates, reports, and self-assessments at no additional cost.

Slide 10 of 11 Security Assessment & Penetration Testing

Cloud Security Assessment Process

  1. Plan: Define scope and charter
  2. Execute: Perform the assessment (Examine, Interview, Test)
  3. Report: Document findings
  4. Remediate: Recommendations and POAM (Plan of Action & Milestones)

Penetration Testing Methodology

1. Recon

Gather information

2. Scanning

Identify vulnerabilities

3. Exploitation

Attempt to exploit

4. Post-Exploit

Maintain access, pivot

5. Reporting

Document findings

Cloud Penetration Testing Scope

  • Network infrastructure and VPCs
  • Authentication and access controls
  • Data storage (S3, Blob, GCS)
  • Virtual machines and containers
  • APIs and serverless functions
  • Application security

Cloud Provider Policies

Always check cloud provider policies before penetration testing. AWS, Azure, and GCP have specific rules about what testing is allowed. Some require pre-authorization or have prohibited test types.
