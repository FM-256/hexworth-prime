💡 Data Security Posture Management (DSPM)

DSPM solutions automate data discovery, policy enforcement, and compliance reporting. They support Zero Trust by analyzing permissions and enforcing least-privilege access to data.

Data Classification

Classify data based on sensitivity, regulatory requirements, and business impact.

Classification Description Examples Protection
Public No impact if disclosed Marketing materials, press releases Minimal
Internal Business use only Policies, internal memos Access controls
Confidential Significant impact if disclosed Financial data, employee PII Encryption + DLP
Restricted Severe impact if disclosed Trade secrets, customer SSNs, PHI Maximum protection

💡 Regulatory Drivers

GDPR, HIPAA, PCI DSS, and SOX all require data classification as the foundation for compliance. You can't protect what you don't know you have.

Data Protection Techniques

🏷️

Sensitivity Labels

Tag data with classification level (Public, Confidential, etc.)

💧

Watermarks

Visual markers on documents indicating sensitivity

🔐

Encryption

🚪

Access Restrictions

Limit who can view, edit, or share data

📚 Module 02 Connection: Least Privilege

Section 2: Encryption Techniques

Encryption at Rest

Encryption at rest protects data stored in databases, file systems, and storage accounts.

    ENCRYPTION AT REST
    ══════════════════

    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
    │  Plaintext  │───►│ Encryption  │───►│ Ciphertext  │
    │    Data     │    │   (AES-256) │    │  (Stored)   │
    └─────────────┘    └─────────────┘    └─────────────┘
                             │
                             ▼
                    ┌─────────────────┐
                    │  Encryption Key │
                    │  (Secured in    │
                    │   Key Vault)    │
                    └─────────────────┘

    Without the key → Data is unreadable

💡 AES-256: The Standard

AES-256 is the industry standard for encryption at rest. All major CSPs (AWS, Azure, GCP) use it by default for storage encryption.

Encryption in Transit

Encryption in transit protects data as it moves between systems using TLS (Transport Layer Security).

    ENCRYPTION IN TRANSIT (TLS)
    ═══════════════════════════

    ┌──────────┐                              ┌──────────┐
    │  Sender  │ ◄──── Encrypted Tunnel ────► │ Receiver │
    └──────────┘          (HTTPS/TLS)         └──────────┘
         │                                          │
         ▼                                          ▼
    ┌──────────┐                              ┌──────────┐
    │ Plaintext│                              │ Plaintext│
    │   Data   │                              │   Data   │
    └──────────┘                              └──────────┘

    Data in tunnel → Encrypted
    Attackers see  → Gibberish

TLS Protections

  • Confidentiality: Data encrypted, unreadable to eavesdroppers
  • Integrity: Digital signatures detect tampering
  • Authentication: Certificates verify server identity

Section 3: Key Management

Customer vs. Cloud Provider Managed Keys

Aspect CSP-Managed Keys Customer-Managed Keys (CMK)
Key Control CSP creates and manages keys You create, rotate, and revoke keys
Rotation Automatic (often annual) You define rotation schedule
Access Control CSP controls access You control via IAM policies
Compliance May not meet Separation of Duties Meets regulatory SoD requirements
Complexity Simple - zero management More complex - requires key lifecycle management

💡 When to Use CMK

Use Customer-Managed Keys when regulations require Separation of Duties (you control keys, CSP controls infrastructure) or when you need to revoke access independent of the CSP.

Section 5: Data Loss Prevention (DLP)

DLP solutions detect, alert, and block unauthorized data sharing.

🔍

Know Your Data

Classify and segregate sensitive from non-sensitive

🚫

Prevent Data Loss

Policies block over-sharing and risky behavior

📋

Govern Your Data

Train users with tips; watermark sensitive files

⚠️ DLP Catches

  • Emailing credit card numbers outside the organization
  • Uploading classified documents to personal cloud storage
  • Printing sensitive data to unmonitored printers
  • Copying PII to USB drives

CSP DLP Solutions

CSP DLP Service Key Capabilities
Microsoft Purview DLP Policy tips, content blocking, insider risk protection, SharePoint/Teams integration
Google Cloud DLP (Sensitive Data Protection) Automated discovery, de-identification, data masking, Chronicle SIEM integration
AWS Amazon Macie S3-focused, sensitive data discovery, Security Hub integration, auto-remediation

💡 DLP + Classification = Power

DLP works best when combined with data classification. Labeled "Confidential" data triggers stricter DLP policies than "Internal" data.

Section 6: Backup and Disaster Recovery

Backup vs. Replication

Aspect Backup Replication
Purpose Point-in-time data recovery Real-time data synchronization
Recovery Time Slower (restore from backup) Fast (failover to replica)
Ransomware Protection ✓ Restores clean copy ✗ Corruption replicates too
RTO Focus Higher RTO acceptable Low RTO critical
RPO Focus Depends on backup frequency Near-zero RPO

💡 RTO vs RPO

  • RTO (Recovery Time Objective): How fast must you recover?
  • RPO (Recovery Point Objective): How much data loss is acceptable?

Cloud Disaster Recovery Strategies

    DR TIERS (Cost ↔ Recovery Speed)
    ═════════════════════════════════

    ┌────────────────────────────────────────────────────────┐
    │   BACKUP ONLY              PILOT LIGHT    HOT STANDBY  │
    │   ◉────────────────────────────●─────────────────────◉ │
    │   Low Cost                                  High Cost  │
    │   High RTO                                   Low RTO   │
    └────────────────────────────────────────────────────────┘

    Backup Only:   Restore from backup when needed
    Pilot Light:   Minimal standby, scale up on failover
    Hot Standby:   Full duplicate running, instant failover

Cloud Site Recovery Benefits

  • Use cloud as "hot site" for on-premises data center failures
  • Cross-region replication for cloud workloads
  • Automated failover and failback
  • Pay only for what you use (vs. owning a secondary data center)

Module 03 Summary

🎯 Key Takeaways

  • Data Governance: Know → Protect → Prevent Loss → Govern
  • Classification: Public → Internal → Confidential → Restricted
  • Encryption at Rest: AES-256 standard for stored data

  • Key Management: CSP-managed (simple) vs CMK (compliance)
  • CSP Services: Azure Key Vault, AWS KMS/CloudHSM, GCP CMEK
  • DLP: Detect and block unauthorized data sharing
  • DR: Backup (ransomware protection) + Replication (fast recovery)
