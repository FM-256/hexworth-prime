What Is Cloud Computing?

NIST Definition of Cloud Computing

"Cloud computing is a model for enabling ubiquitous, convenient, on-demand network access to a shared pool of configurable computing resources (e.g., networks, servers, storage, applications, and services) that can be rapidly provisioned and released with minimal management effort or service provider interaction."

The Cloud Model Components

  • 5 Essential Characteristics - On-demand, broad access, pooling, elasticity, measured service
  • 3 Service Models - IaaS, PaaS, SaaS
  • 4 Deployment Models - Private, Public, Hybrid, Community

Cloud Deployment Models

🔒

Private Cloud

  • Organization owns data center
  • Maximum flexibility in implementation
  • Requires physical location
  • Capital expenditure model
  • Full control over infrastructure
🌐

Public Cloud

  • Third-party provider hosts resources
  • Multiple global data centers
  • Cost-effective entry point
  • Pay-as-you-go model
  • No upfront hardware costs
🌈

Hybrid Cloud

  • Combines two or more models
  • Maximizes flexibility
  • Balances control and scalability
  • Mixed CapEx and OpEx
  • Ideal for regulated environments
Key Insight: Hybrid cloud provides strategic balance between maintaining regulatory compliance and leveraging cloud computing advantages.

Cloud Security Challenges and Concerns

Data and Identity Governance

Utilization of private, public, and hybrid cloud models introduces potential data and identity "sprawl" requiring attention.

Cloud Knowledge and Skills

Security and privacy controls differ between cloud and on-premises. Understanding these distinctions requires training.

Shared Responsibility and Trust

Private clouds are protected against physical access; customers must rely on provider due care for physical and perimeter security.

Expanded Geographic Reach

Public cloud has no defined boundaries; customers must use provided toolset to ensure appropriate data sovereignty.

Cloud Shared Responsibilities

Key Responsibility Areas

  • Infrastructure and Defense in Depth - Layered security approach
  • Service Level Agreements (SLA) - Defined responsibilities

Collaborative Security

By sharing responsibilities for determining risks and vulnerabilities, as well as implementing security controls, the cloud service provider and users collaboratively contribute to a secure cloud environment.

Threats and Attacks in Cloud Environments

Threat Lifecycle

In cloud environments, the presence of threats and vulnerabilities poses a risk that, if exploited, can escalate into actual attacks.

  • Creation - Attack is created
  • Discovery - Attacker gathers information
  • Exploit - Attacker finds a way in
  • Disclosure - Vulnerability becomes known
  • Vendor Patch - Provider releases fix
  • Patch Installed - Customer applies fix
Key Defense: Monitoring the environment proactively identifies and addresses potential security threats, including zero-day threats, before they evolve into attacks.

Shadow IT: The Insider Threat

What is Shadow IT?

Unauthorized installation of applications that can evolve into potential threats and vulnerabilities.

Risk Factors

  • Significant attacks stem from insider exploits
  • Initiated through malicious emails, links, software
  • Bypasses security controls

3-Phase Response

Phase 1: Discover and Identify
  • Locate software being accessed
  • Evaluate and determine risk
Phase 2: Evaluate and Analyze
  • Analyze usage patterns
  • Determine compliance
Phase 3: Manage and Monitor
  • Manage access through Conditional Access
  • Block non-compliant applications
  • Continuous monitoring

Common Cloud Attack Types

Phishing

Exploits user trust with emails appearing from familiar retailers containing malicious links. Sends users to phishing websites to gather sensitive information.

Spear Phishing

Focused emails designed to appear official, mimicking employer communications. Often appears related to payroll or HR matters.

Denial-of-Service (DoS)

Flood of requests from attacker-controlled bot services. Traffic bottleneck prevents legitimate users from accessing systems. Cloud providers offer DDoS protection.

Brute Force Attacks

Systematically attempts all possible password combinations. Dictionary attacks use pre-existing word lists to guess passwords.

Cross-Site Scripting (XSS)

Redirects users to malicious sites designed to steal session cookies, compromising authentication and enabling unauthorized access.

SQL Injection

Vulnerable websites permit attackers to execute malicious SQL queries. Leads to unauthorized access, manipulation, or extraction of database data.

CIA Triad: Security Foundation

Confidentiality

(Disclose)

Protect access and authorization to sensitive information/data

Integrity

(Alter)

Ensure data remains unaltered from creation to access

Availability

(Destroy)

Ensure data is accessible to authorized users when needed

Key Principles

  • All security control decisions are made based on these objectives
  • Data/Information must be categorized based on impact to these objectives
  • Security controls must balance all three objectives

Defense in Depth

Core Principle

One level of protection is not enough.

We must defend against diverse attacks from various attackers using different methods.

Cloud Provider Responsibility:

Physical security layer is handled by cloud providers for users of cloud technologies.

Your Responsibilities

  • Identity - Who can access
  • Access - What they can do
  • Perimeter - Edge protection
  • Network - Internal segmentation
  • Computing - System hardening
  • Applications - Code security
  • Data - Encryption & classification
Remember: A comprehensive approach is crucial. Instead of relying on a single security measure, defense-in-depth addresses vulnerabilities and threats at different data processing and storage stages.

Zero Trust Methodology

Three Core Principles

  • Verify Explicitly - Authenticate and validate the identity of users, devices, or systems before granting access
  • Principle of Least Privilege - Provide only minimum access required for a specific task, only for the necessary duration (Just in Time, Just Enough Access)
  • Assume Breach - Adopt a proactive mindset that considers the possibility of a security breach at any time

Secure Landing Zones

What is a Secure Landing Zone?

A scalable and modular starting point for cloud deployment with repeatable security templates and configurations.

Key Design Areas

  • Identity and Access - Who can do what
  • Network Topology - How services connect
  • Security - Protection controls
  • Management - Operations and monitoring
  • Governance - Policies and compliance

Benefits

  • Tailored architecture across the environment
  • Organized resource hierarchy
  • Repeatable deployment patterns
  • Pre-configured security controls
  • Consistent policy enforcement
Each major CSP provides Landing Zone templates: AWS Control Tower, Azure Landing Zones, Google Cloud Foundation Toolkit
