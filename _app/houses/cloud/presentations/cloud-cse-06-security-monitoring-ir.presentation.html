Cloud Logging Fundamentals

What should you log to identify threats and vulnerabilities?

Events

What is taking place with resources and infrastructure?

  • Is there suspicious activity?
  • Are there unverified changes?
  • Does behavior seem malicious?

Activity

What is being done with resources?

  • Who is accessing resources?
  • What is being accessed?
  • Is access normal and verified?

Metrics

How are resources performing?

  • Are resources acting differently?
  • Could this indicate malicious activity?
  • What are the performance baselines?

SIEM & SOAR

Enterprise security monitoring and automated response

SIEM

Security Information and Event Management - Aggregates information from disparate sources for analysis and investigation.

  • Streamlines security efforts across the organization
  • Aggregates data into single source for analysis
  • Cloud SIEM: Microsoft Sentinel, Google Chronicle
  • SIEM as a Service from managed security providers
  • Long-term storage and management of event data
  • Real-time monitoring and correlation

SOAR

Security Orchestration and Automated Response - Works with SIEM to provide efficiency through automation.

  • Uses playbooks and automation tools
  • Responds to threats proactively
  • Common threats remediated automatically
  • Minimal human interaction required
  • Reduces mean time to respond (MTTR)
  • Standardizes incident response procedures

Cloud Security Posture Management

Automated tools for identifying security risks and misconfigurations

CSPM vs CNAPP

CSPM

Cloud Security Posture Management - Automated software that identifies security risks in cloud infrastructure.

  • Scans SaaS, PaaS, IaaS, containers, serverless
  • Identifies compliance risks and misconfigurations
  • Runs in background analyzing for vulnerabilities
  • Multi-cloud visibility across all providers
  • Examples: Defender for Cloud, AWS Security Hub

CNAPP

Cloud Native Application Protection Platform - Combines CSPM, CWPP, and CIEM in one platform.

  • Full coverage and visibility into cloud estates
  • Detects risks across the entire tech stack
  • Shift-left capabilities for earlier detection
  • Combines vulnerabilities, context, and relationships
  • Examples: Defender for Cloud, CloudGuard, Prisma Cloud

Incident Response

From event detection to breach response

Timeline of a Breach

Event

Something identified as anomaly or suspicious behavior. Evaluate to determine if malicious.

Incident

Verified malicious activity. Investigation into affected resources begins.

Breach

Malicious activity has gained sensitive information. Communication plan activated.

Incident Response Plan Requirements

Have a definition of an incident for your services
Define all roles and responsibilities
Define the process from detection to resolution
Include media coordination procedures
All incidents require a communication plan
Understand legal/regulatory notification requirements
Prioritize incidents by urgency and impact
Focus on High-High identified incidents first

Key Takeaways

Log events, activity, and metrics to identify threats and anomalies
Each CSP provides native monitoring tools - CloudTrail, Azure Monitor, Cloud Logging
SIEM aggregates data; SOAR automates response with playbooks
CSPM identifies misconfigurations; CNAPP provides full stack protection
Continuous monitoring is essential - not a one-time activity
IR plans must include communication, roles, and legal requirements
