Section 1

Cloud Network Fundamentals

🌐 Virtual vs Physical

  • Virtual connections replace physical ports and cables
  • Software-defined networking (SDN)
  • Programmable infrastructure via APIs
  • Rapid provisioning and scaling

📍 IP Addressing

  • Private IP schema for internal resources
  • Public IP for external connectivity
  • CIDR block allocation
  • Elastic/Static IP options

🗺️ Regional Resources

  • Networks are region-specific
  • Resources must be in same region as network
  • VPC Peering extends across regions
  • Provider backbone for inter-region traffic

💡 Key Concept: Software-Defined Networking

Cloud networks are entirely software-defined, meaning they can be created, modified, and destroyed programmatically. This enables infrastructure-as-code approaches but also requires careful security configuration—misconfigured network rules are a leading cause of cloud breaches.

Section 2

Virtual Private Cloud (VPC)

AWS VPC

  • Logical data center network
  • Subnets per Availability Zone
  • Internet Gateway (IGW) for public access
  • Route tables, NACLs, Security Groups
  • VPC Peering across accounts

Azure VNet

  • Virtual Network with internal IP
  • Virtual Subnets for segmentation
  • Built within Resource Groups
  • VNet Peering for connectivity
  • Integration with Azure services

VPC Component Hierarchy

Internet / External Networks
↕️
Internet Gateway (IGW) / NAT Gateway
↕️
Public Subnet (Web Tier)
↕️
Private Subnet (Application Tier)
↕️
Private Subnet (Database Tier)

💡 Default Resources

AWS: Route table, NACL, and security group created automatically. IGW and subnets must be created manually.
Azure: Network security rules have defaults that need review for production workloads.

Section 3

Network Isolation & Segmentation

🎯 Segmentation Goals

  • Separate private and public resources
  • Isolate sensitive data (PCI, HIPAA)
  • Protect IaaS from public Internet
  • Limit blast radius of breaches

⚖️ Load Balancers

  • NLB: High-speed, end-to-end encryption
  • ALB: Most common, Layer 7 routing
  • TLS/SSL termination offloads crypto
  • Reduces EC2 compute overhead

Azure Front Door

  • Layer 7 traffic routing
  • Global load balancing
  • No public IP on VNet interfaces
  • WAF integration

🛡️ DDoS Protection

  • AWS Shield (standard = free)
  • Azure DDoS Basic (free tier)
  • Extended plans for reporting
  • Network perimeter protection

📚 M03 Connection: Encryption in Transit

Load balancers performing TLS termination connect to Module 03's encryption concepts. Remember: data must be re-encrypted if traveling to backend services.

Section 4

NACLs & Network Security Groups

Feature NACL (AWS) Security Group (AWS) NSG (Azure)
Type Stateless Stateful Stateful
Rules Separate inbound/outbound Combined rules Separate inbound/outbound
Scope Subnet level Instance/ENI level Subnet or NIC level
Default Behavior Default allows all; Custom denies all Denies all inbound, allows all outbound 3 default inbound, 3 default outbound
Best For Blocking IP addresses Blocking ports Both subnet and NIC protection

💡 Stateless vs Stateful

Stateless (NACL): Each packet evaluated independently. Must explicitly allow return traffic.
Stateful (Security Groups/NSG): Tracks connections. Return traffic automatically allowed.

🏢 Azure Application Security Groups

Group VMs by function (web servers, app servers, databases) and apply rules by group rather than individual IPs. Simplifies rule management at scale.

Section 5

Remote Access & Private Connections

🔗 VPC Endpoints

  • Internal gateway for AWS service access
  • Avoids internet exposure
  • IAM controls access permissions
  • Elastic Network Interface (ENI) assigned

🌉 Transit Gateway

  • Centralized VPC hub-and-spoke model
  • Connects thousands of VPCs
  • Cross-region communication
  • Route table control

Private Links

  • Direct, secure Azure service access
  • Bypasses public internet
  • Microsoft backbone network
  • Hybrid/on-premises connectivity

🏰 Azure Bastion

  • Secure RDP/SSH without port exposure
  • Access via Azure Portal
  • No public IP on VMs
  • PaaS-managed jump host
⏰

Just-In-Time (JIT) VM Access

On-demand + Time-limited access reduces attack surface. Access granted only when needed, automatically revoked after timeout.

📚 M02 Connection: Least Privilege

JIT VM access implements Module 02's Just-In-Time (JIT) access principle at the network layer.

Section 5 (continued)

NAT Gateways & Bastion Hosts

Component Purpose Direction Best Practice
NAT Instance EC2 for outbound from private subnets Outbound only Legacy - avoid for new deployments
NAT Gateway Managed outbound connectivity Outbound only Preferred - HA, scalable, secure
Bastion Host Jump box for admin access Inbound (SSH/RDP) Use managed service (Azure Bastion)

🚪 NAT Gateway Advantages

  • Reduces attack surface vs NAT instances
  • High availability per AZ
  • Scalable and burstable
  • Managed by cloud provider

🏰 Bastion Best Practices

  • Never expose management ports directly
  • Use managed bastion services
  • Enable session recording/logging
  • Combine with MFA (M02)

⚠️ Security Warning

NAT Instances and self-managed bastion hosts require patching and monitoring. Consider managed services to reduce operational security burden.

Section 6

Cloud Firewalls

Azure Firewall

  • Stateful Firewall as a Service
  • High availability + Zone redundancy
  • Next-Generation features
  • Packet filtering
  • NAT rules and routing

🌐 Web Application Firewall (WAF)

  • Layer 7 protection
  • OWASP Top 10 coverage
  • XSS and SQL injection blocking
  • Code injection prevention

WAF Deployment Options

AWS WAF

Used with ALB + CloudFront

Azure WAF

Used with App Gateway + Front Door

💡 Network Firewall vs WAF

Network Firewall: Layer 3-4, IP/port filtering, stateful inspection.
WAF: Layer 7, HTTP/HTTPS inspection, application-aware rules, OWASP protections.

Section 6 (continued)

Intrusion Detection & Prevention

🔍 Intrusion Detection System (IDS)

  • Monitors and detects threats
  • Non-intrusive - doesn't alter traffic
  • Alerts for rapid response
  • Passive monitoring mode

🛡️ Intrusion Prevention System (IPS)

  • Detects AND responds to threats
  • Actively blocks malicious traffic
  • Modifies traffic patterns
  • Inline deployment required
Capability IDS IPS
Detection ✅ Yes ✅ Yes
Prevention ❌ No (alert only) ✅ Yes (blocks/modifies)
Traffic Impact None (passive) May add latency (inline)
False Positive Risk Alert noise May block legitimate traffic
