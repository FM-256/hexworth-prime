NIC Teaming

Modes

  • Switch Independent
  • Static / LACP (802.3ad)

Load Balance

  • Address Hash / Dynamic
  • Hyper-V Port
# Create team + add VLAN PS C:\> New-NetLbfoTeam -Name "DataTeam" -TeamMembers "Ethernet1","Ethernet2" -TeamingMode SwitchIndependent -LoadBalancingAlgorithm Dynamic PS C:\> Add-NetLbfoTeamNic -Team "DataTeam" -VlanID 100 -Name "DataTeam-VLAN100"

NIC Teaming Deep Dive

Switch Independent

  • No switch config; cross-switch OK
  • Active/Standby or Active/Active

Static

  • Manual port channel, same switch

LACP

  • Dynamic, auto-negotiated
  • Best for enterprise

Hyper-V Port

  • VM pinned to one NIC

NIC Teaming, Configuration

# LACP team + verify + list members PS C:\> New-NetLbfoTeam -Name "ProdTeam" -TeamMembers "NIC1","NIC2","NIC3","NIC4" -TeamingMode LACP -LoadBalancingAlgorithm HyperVPort PS C:\> Get-NetLbfoTeam | Format-List Name, TeamingMode, Status PS C:\> Get-NetLbfoTeamMember -Team "ProdTeam"

DHCP Failover

Hot Standby

  • Primary serves, standby takes over
  • Standby reserves % of addresses

Load Balance

  • Both active, default 50/50
  • Configurable split
# Create 50/50 load-balanced failover PS C:\> Add-DhcpServerv4Failover -Name "DHCP-Failover" -PartnerServer "DHCP02" -ScopeId "10.0.1.0" -LoadBalancePercent 50 -SharedSecret "P@ssw0rd123"

DNS Policies

Types

  • Query Resolution
  • Zone Transfer / Recursion

Criteria

  • Client subnet, query type
  • Time of day, TCP/UDP

DNS Policies, Configuration

Before creating DNS policies, you must define client subnets so the DNS server can identify where queries originate from.

# Define the headquarters subnet so DNS can identify HQ clients PS C:\> Add-DnsServerClientSubnet -Name "HeadquartersSubnet" -IPv4Subnet "10.0.1.0/24" # Define the branch office subnet for location-based resolution PS C:\> Add-DnsServerClientSubnet -Name "BranchSubnet" -IPv4Subnet "10.0.2.0/24"

DNS Policies (cont.)

# Create branch scope, add A record, route via policy PS C:\> Add-DnsServerZoneScope -ZoneName "hexworth.local" -Name "BranchScope" PS C:\> Add-DnsServerResourceRecord -ZoneName "hexworth.local" -A -Name "app" -IPv4Address "10.0.2.100" -ZoneScope "BranchScope" PS C:\> Add-DnsServerQueryResolutionPolicy -Name "BranchPolicy" -Action ALLOW -ClientSubnet "EQ,BranchSubnet" -ZoneScope "BranchScope,1" -ZoneName "hexworth.local"

Split-Brain DNS

How

  • Same name, different IPs
  • Internal vs external clients

Uses

  • Web apps int/ext
  • Exchange Autodiscover, SP

Split-Brain DNS, Configuration

# External scope + public IP + policy for non-internal PS C:\> Add-DnsServerZoneScope -ZoneName "hexworth.local" -Name "ExternalScope" PS C:\> Add-DnsServerResourceRecord -ZoneName "hexworth.local" -A -Name "app" -IPv4Address "203.0.113.50" -ZoneScope "ExternalScope" PS C:\> Add-DnsServerQueryResolutionPolicy -Name "SplitBrainExternal" -Action ALLOW -ClientSubnet "NE,InternalSubnet" -ZoneScope "ExternalScope,1" -ZoneName "hexworth.local"

DNSSEC (DNS Security Extensions)

Components

  • RRSIG, DNSKEY, DS
  • NSEC/NSEC3, KSK

Benefits

  • Prevents cache poisoning
  • Chain of trust root→zone

DNSSEC, Configuration

# Sign zone + add trust anchor + verify PS C:\> Invoke-DnsServerZoneSign -ZoneName "hexworth.local" -SignWithDefault PS C:\> Add-DnsServerTrustAnchor -Name "hexworth.local" -CryptoAlgorithm RsaSha256 -KeyTag 12345 -Digest "ABCDEF..." -DigestType Sha256 PS C:\> Get-DnsServerDnsSecZoneSetting -ZoneName "hexworth.local"

IPAM (IP Address Management)

Features

  • Centralized IP tracking
  • Manages DHCP + DNS

Components

  • IPAM Server + DB (WID/SQL)
  • Managed Servers + Client

IPAM (IP Address Management), Configuration

IPAM requires its Windows feature to be installed first. The management tools include both the Server Manager snap-in and PowerShell module.

# Install the IPAM role and its management tools PS C:\> Install-WindowsFeature -Name IPAM -IncludeManagementTools
# Initialize the IPAM database using Windows Internal Database PS C:\> Invoke-IpamServerProvisioning -WidSchemaPath "C:\Windows\System32\ipam\ipamschema.mdf"

IPAM (IP Address Management), Configuration (cont.)

After provisioning, discover DHCP, DNS, and domain controller servers across the domain so IPAM can begin tracking their address spaces.

# Scan the domain to discover all DHCP, DNS, and DC servers PS C:\> Invoke-IpamServerDiscovery -Domain "hexworth.local"
# Check IP address utilization across all managed subnets PS C:\> Get-IpamSubnet | Select-Object NetworkId, PercentageUtilized, TotalAddresses

Network Policy Server (NPS/RADIUS)

Use Cases

  • VPN, Wi-Fi 802.1X, wired
  • RADIUS proxy

Components

  • RADIUS clients, conn policies
  • Network policies, accounting

NPS/RADIUS, Configuration

# Install + register + add VPN as RADIUS client PS C:\> Install-WindowsFeature -Name NPAS -IncludeManagementTools PS C:\> netsh nps set registeredserver domain=hexworth.local server=NPS01 PS C:\> New-NpsRadiusClient -Name "VPN-Server" -Address "10.0.1.5" -SharedSecret "R@diusSecret123"

VPN Types

Protocols

  • IKEv2 (recommended), SSTP
  • L2TP/IPsec, PPTP (avoid)

Picking

  • IKEv2 = mobile reconnect
  • SSTP = firewall-friendly

VPN Types, Configuration

# Install RRAS + VPN, set client pool PS C:\> Install-WindowsFeature -Name DirectAccess-VPN,Routing -IncludeManagementTools PS C:\> Install-RemoteAccess -VpnType Vpn PS C:\> Set-RemoteAccessConfiguration -VpnAddressPool "10.0.100.1","10.0.100.254"

DirectAccess

How

  • Auto-connects outside corp net
  • IPv6 (6to4, Teredo, IP-HTTPS)
  • Bi-directional, machine certs

Requirements

  • Windows Enterprise, domain-joined
  • AD + GPO + AD CS
  • DA server with 2 NICs

DirectAccess, Configuration

# Install DA + deploy + force tunnel PS C:\> Install-WindowsFeature -Name DirectAccess-VPN -IncludeManagementTools PS C:\> Install-RemoteAccess -DAInstallType FullInstall -ConnectToAddress "da.hexworth.com" PS C:\> Set-DAClient -ComputerName "DA-Clients" -ForceTunnel Enabled

BranchCache, Configuration

# Build VNet properties with two subnets PS C:\> $vnetProperties = @{ AddressSpace = @{AddressPrefixes=@("10.100.0.0/16")}; Subnets = @(@{ResourceId="WebTier";Properties=@{AddressPrefix="10.100.1.0/24"}}) }

Windows Firewall with Advanced Security

Rule Types

  • Inbound / Outbound
  • Connection Security (IPsec)
# Allow HTTPS in, block Telnet out PS C:\> New-NetFirewallRule -DisplayName "Allow HTTPS" -Direction Inbound -Protocol TCP -LocalPort 443 -Action Allow PS C:\> New-NetFirewallRule -DisplayName "Block Telnet" -Direction Outbound -Protocol TCP -RemotePort 23 -Action Block

IPsec Configuration

Modes

  • Transport (payload only)
  • Tunnel (full packet, VPN)

Auth

  • Kerberos / Certs / PSK
# Require IPsec for traffic to 10.0.1.0/24 PS C:\> New-NetIPsecRule -DisplayName "Encrypt DC Traffic" -InboundSecurity Require -OutboundSecurity Require -RemoteAddress "10.0.1.0/24"

Quality of Service (QoS)

QoS Mechanisms

  • DSCP Marking + Throttle Rate
  • Application-based + Port-based
# Mark VoIP DSCP 46 + throttle backup PS C:\> New-NetQosPolicy -Name "VoIP Priority" -IPDstPortStart 5060 -IPDstPortEnd 5061 -DSCPAction 46 -NetworkProfile Domain PS C:\> New-NetQosPolicy -Name "Backup Throttle" -AppPathNameMatchCondition "backup.exe" -ThrottleRateActionBitsPerSecond 100MB

Network Address Translation (NAT)

Types

  • SNAT (out) / DNAT (port fwd)
  • Static 1:1 / Dynamic pool

Uses

  • Private → internet
  • Lab / containers
# NAT for 192.168.100/24 + port forward 8080→80 PS C:\> New-NetNat -Name "LabNAT" -InternalIPInterfaceAddressPrefix "192.168.100.0/24" PS C:\> Add-NetNatStaticMapping -NatName "LabNAT" -Protocol TCP -ExternalIPAddress "0.0.0.0" -ExternalPort 8080 -InternalIPAddress "192.168.100.10" -InternalPort 80

Network Diagnostics

Troubleshoot network issues with built-in Windows tools and PowerShell cmdlets.

Diagnostic Tools

  • Test-NetConnection: Connectivity testing
  • Get-NetTCPConnection: Active connections
  • Get-NetRoute: Routing table
  • netsh trace: Packet capture

Performance Counters

  • Network Interface\Bytes/sec
  • TCPv4\Connections Established
  • Network Adapter\Packets/sec
  • RDMA Activity counters

Network Diagnostics, Configuration

# Test TCP connectivity to a remote server on port 443 (HTTPS) PS C:\> Test-NetConnection -ComputerName "server.hexworth.local" -Port 443 # Group established TCP connections by remote IP to find top talkers PS C:\> Get-NetTCPConnection -State Established | Group-Object RemoteAddress # Start a packet capture and save it to an ETL trace file PS C:\> netsh trace start capture=yes tracefile=C:\Temp\trace.etl
