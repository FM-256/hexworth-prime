PowerShell Script Fundamentals

Robust scripts share one skeleton: prereqs, params, fail loud, log all.

Structure

  • #Requires · param() typed + validated
  • Begin/Process/End pipeline-friendly
  • Approved verbs (Get/Set/New) + -WhatIf + strict mode
# Production script header PS> #Requires -Version 5.1 #Requires -RunAsAdministrator param([Parameter(Mandatory)][string]$ServerName, [switch]$Force) Set-StrictMode -Version Latest $ErrorActionPreference = 'Stop'

Error Handling & Logging

Production scripts need error handling + logging. A reusable Write-Log timestamps every action; try/catch/finally captures failures instead of losing them silently.

# Logging + try/catch pattern PS> function Write-Log { param($Msg, $Level='INFO') "[$(Get-Date -f 'yyyy-MM-dd HH:mm:ss')] [$Level] $Msg" | Add-Content $LogPath } $ErrorActionPreference = 'Stop' # ensure try/catch catches all try { Write-Log "Starting on $S"; Invoke-Command -ComputerName $S -Sb {Get-Service} } catch { Write-Log "ERROR: $_" -Level 'ERROR'; throw } finally { Write-Log "Done" }

Task Scheduler Integration

Three pieces: trigger, action, conditions.

Trigger types

  • Time — daily/weekly/monthly, startup, idle
  • Event — event-log entry, lock/unlock
  • Run as — SYSTEM or user (works logged off)
# Daily maintenance task at 2 AM as SYSTEM PS> $action = New-ScheduledTaskAction -Execute 'powershell.exe' -Argument '-File C:\Scripts\DailyMaint.ps1' $trigger = New-ScheduledTaskTrigger -Daily -At '2:00AM' $principal = New-ScheduledTaskPrincipal -UserId 'SYSTEM' -RunLevel Highest Register-ScheduledTask -TaskName 'DailyMaint' -Action $action -Trigger $trigger -Principal $principal

Desired State Configuration (DSC)

Declarative config. You describe state; LCM applies + re-applies on drift.

Pieces

  • Configuration block · Resources (File, Service, WindowsFeature, …)
  • MOF — compiled config · LCM — agent applies + monitors
# Declare: IIS installed, default page present PS> Configuration WebServerConfig { Node 'WebServer01' { WindowsFeature IIS { Name = 'Web-Server'; Ensure = 'Present' } File WebsiteContent { DestinationPath = 'C:\inetpub\wwwroot\index.html' Contents = '<h1>Welcome</h1>'; Ensure = 'Present' } } }

Implementing DSC

Four steps: define, compile, push, verify. Push on-demand; Pull nodes poll server.

# 1. Define — security baseline as code PS> Configuration SecureServer { Import-DscResource -ModuleName PSDesiredStateConfiguration Node $AllNodes.NodeName { WindowsFeature RemoveTelnet { Name = 'Telnet-Client'; Ensure = 'Absent' } Service WinRM { Name = 'WinRM'; State = 'Running'; StartupType = 'Automatic' } } } # 2. Compile to MOF · 3. Push · 4. Verify SecureServer -OutputPath 'C:\DSC\SecureServer' Start-DscConfiguration -Path 'C:\DSC\SecureServer' -Wait -Verbose Test-DscConfiguration -Detailed

PowerShell Remoting

Fan a script across N servers in parallel.

Four patterns

  • Invoke-Command — fire-and-forget remote exec
  • Enter-PSSession — interactive remote shell
  • New-PSSession — persistent reusable connection
  • CIM/WMI — many queries without remoting
# Uptime + free space across N servers in parallel PS> Invoke-Command -ComputerName DC01,WEB01,SQL01,FILE01 -ThrottleLimit 10 -ScriptBlock { [PSCustomObject]@{ ComputerName = $env:COMPUTERNAME UptimeDays = ((Get-Date) - (Get-CimInstance Win32_OperatingSystem).LastBootUpTime).Days FreeGB = [math]::Round((Get-PSDrive C).Free / 1GB, 2) } }

Automation Workflow Patterns

Four enterprise patterns. Same idiom: function + params → structured output.

  • Provisioning · Deployment · Compliance · Backup
# Reusable onboarding function — wraps 3 steps in 1 call PS> function New-HexworthUser { param($FirstName, $LastName, $Department) $u = ($FirstName.Substring(0,1) + $LastName).ToLower() New-ADUser -Name "$FirstName $LastName" -SamAccountName $u -Department $Department -Enabled $true Add-ADGroupMember -Identity "GRP-$Department" -Members $u New-Item -Path "\\fileserver\users\$u" -ItemType Directory }

PowerShell Modules & Repositories

Modules = reusable functions. Repos = PSGallery / internal NuGet / file share.

Layout

  • .psm1 module body · .psd1 manifest (version, exports, deps)
  • Public/ · Private/ · Tests/ — exported / internal / Pester
# Install from PSGallery · register internal · publish PS> Install-Module -Name 'Az.Accounts' -Scope AllUsers Register-PSRepository -Name 'HexworthRepo' -SourceLocation '\\fileserver\PSModules' -InstallationPolicy Trusted Publish-Module -Name 'HexworthTools' -Repository 'HexworthRepo'
