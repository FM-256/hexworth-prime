What Are AD Sites?

Purpose

  • Control replication flow
  • Direct clients to local DC

Components

  • Sites + Subnets + Site Links
  • Servers assigned to sites

Subnets and Site Association

Admins must register each subnet → site. Unmapped = random DC.

  • DC locator uses site-aware SRV; no match = falls back to all-DC list
  • One subnet → one site; site → many subnets
  • Branch subnets often forgotten → cross-WAN logon
# Register branch subnet + check NO_CLIENT_SITE PS C:\> New-ADReplicationSubnet -Name "10.20.0.0/24" -Site "Boston" PS C:\> Get-Content $env:SystemRoot\debug\netlogon.log | Select-String "NO_CLIENT_SITE"

Why Subnet Mapping Matters

  • Clients find nearest DC via subnet→site
  • Unmapped = random DC, wrong GPO link
# Create, list, reassign subnets PS C:\> New-ADReplicationSubnet -Name "10.1.0.0/16" -Site "Branch-Office" PS C:\> Get-ADReplicationSubnet -Filter * | Select Name, Site PS C:\> Set-ADReplicationSubnet -Identity "10.1.0.0/16" -Site "New-Site"

Site Links

Properties

  • Cost (lower = preferred)
  • Interval (min 15), schedule, transport

Default Link

  • DEFAULTIPSITELINK auto-created
  • Cost 100, interval 180, 24x7
# Create HQ↔Branch link, then lower its cost PS C:\> New-ADReplicationSiteLink -Name "HQ-Branch" -SitesIncluded HQ-Site,Branch-Site -Cost 50 -ReplicationFrequencyInMinutes 15 PS C:\> Set-ADReplicationSiteLink -Identity "HQ-Branch" -Cost 25

Intrasite vs Intersite Replication

Intrasite

  • Change-notify, near-instant
  • Uncompressed, ring topology

Intersite

  • Schedule (default 180 min)
  • Compressed via bridgeheads

Knowledge Consistency Checker (KCC)

KCC builds replication topology automatically.

  • Runs every 15 min per DC
  • Intrasite: full mesh ≤7 DCs, else ring (3 hop max)
  • Intersite: spanning tree via bridgeheads, compressed
  • ISTG: one DC per site handles intersite calc
# Force KCC recompute + show ISTG PS C:\> repadmin /kcc PS C:\> repadmin /istg

KCC Functions

  • Runs on every DC every 15 minutes
  • Creates intrasite connection objects automatically
  • Calculates intersite topology from site links
  • Rebuilds topology when DCs are added/removed
  • Ensures no more than 3 hops between any DCs in a site

When you add or remove DCs, force the KCC to rebuild the replication topology immediately rather than waiting for its 15-minute cycle.

# Trigger the KCC to recalculate the replication topology now PS C:\> repadmin /kcc

KCC Functions (cont.)

# List connections + show replication errors PS C:\> Get-ADReplicationConnection -Filter * PS C:\> repadmin /showrepl * /errorsonly

Bridgehead Servers

Bridgeheads = designated intersite replication partners.

Selection

  • KCC picks one per site per partition (lowest GUID)
  • Preferred can be set manually; KCC auto-fails-over
# Query current bridgeheads per site PS C:\> Get-ADReplicationSite -Filter * | Get-ADObject -Properties bridgeheadServerListBL

Site Link Bridges

Site link bridges control whether transitive replication is allowed across site links.

Transitivity (default: ON)

  • All site links are bridged by default — Site A ↔ B + B ↔ C means A can replicate to C via B
  • Disable bridging when you need explicit control (e.g., hub-and-spoke topology)
  • Create manual bridges for specific paths only
When to disable: Only in complex hub-and-spoke networks where you need explicit control over which sites can talk to which.

Replication Troubleshooting

Three-layer diagnostic: connectivity → replication → convergence.

  • Connectivity: time skew, DNS SRV, RPC ports
  • Replication: repadmin /replsummary, /showrepl
  • Convergence: test object on partner DCs
# Global health + per-DC detail + test suite PS C:\> repadmin /replsummary PS C:\> repadmin /showrepl <dc-name> PS C:\> dcdiag /test:replications

Key Diagnostic Commands

The replication summary gives a quick health check across every DC, showing the largest replication delay and failure count for each partner.

# Get a high-level replication health summary for all DCs PS C:\> repadmin /replsummary
# Show detailed replication status for a specific domain controller PS C:\> repadmin /showrepl DC1

Key Diagnostic Commands (cont.)

# Force replication, check queue, list failures PS C:\> repadmin /syncall DC1 /AeD PS C:\> repadmin /queue PS C:\> Get-ADReplicationFailure -Target hexworth.local -Scope Domain

Common Issues

  • DNS, RPC firewall, time skew >5min, lingering objects

SYSVOL Replication

SYSVOL contains Group Policy templates and scripts that must be synchronized across all DCs.

FRS (Legacy)

  • File Replication Service
  • Used in Windows 2000/2003
  • Single-master conflict resolution
  • Deprecated - should migrate away

DFS-R (Modern)

  • Distributed File System Replication
  • Default since Windows Server 2008
  • RDC for bandwidth efficiency
  • Better conflict handling

SYSVOL Replication, Configuration

Before migrating from FRS, check whether your domain has already completed the migration to DFS-R by querying the global state.

# Check the current SYSVOL replication migration state PS C:\> dfsrmig /getglobalstate # Verify all DCs have reached the target migration state PS C:\> dfsrmig /getmigrationstate

SYSVOL Replication, Configuration (cont.)

Forcing AD polling ensures the DFS-R service picks up any recent configuration changes without waiting for the next automatic cycle.

# Force DFS-R to poll Active Directory for configuration changes PS C:\> dfsrdiag pollad
# Confirm the SYSVOL share exists and is accessible PS C:\> Get-SmbShare -Name SYSVOL

Read-Only Domain Controllers

RODC Characteristics

  • One-way replication, no AD changes
  • No passwords cached by default
  • Filtered attribute set for sensitive data
  • Best for branch / DMZ
# Promote as RODC + allow branch passwords PS C:\> Install-ADDSDomainController -DomainName "hexworth.local" -ReadOnlyReplica:$true -SiteName "Branch-Site" PS C:\> Add-ADDomainControllerPasswordReplicationPolicy -Identity "RODC1" -AllowedList "Branch-Users"
