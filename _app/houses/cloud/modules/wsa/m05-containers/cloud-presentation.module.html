Containers vs Virtual Machines

Containers and VMs both isolate workloads, but at very different layers. The right-side diagram shows the stack difference; the table tells you when to pick which.

Container VM
OSShared host kernelFull OS per VM
StartupSecondsMinutes
SizeMBs (image layers)GBs (full OS)
Density100s per host10s per host
IsolationProcess-levelHardware-level
Best forMicroservices, CI/CDLegacy, different OS

Windows Container Isolation Modes

Windows Server supports two container isolation modes. The right-side diagram shows the stack difference; pick by trust level and host match.

Process Hyper-V
KernelShared with hostOwn (lightweight VM)
SpeedFastestSlightly slower
TrustSame-OS onlyCross-version OK
Best forInternal workloadsMulti-tenant, untrusted
# Choose isolation at runtime PS> docker run --isolation=process servercore:ltsc2022 PS> docker run --isolation=hyperv servercore:ltsc2022

Default: Server defaults to process · Windows 10/11 defaults to Hyper-V for security.

Windows Container Base Images

Microsoft publishes three Windows base images on the MCR. Pick the smallest one that runs your app. Right panel compares size + use-case.

Pull commands

# Three base images: Server Core / Nano / ASP.NET on Nano PS> docker pull mcr.microsoft.com/windows/servercore:ltsc2022 PS> docker pull mcr.microsoft.com/windows/nanoserver:ltsc2022 PS> docker pull mcr.microsoft.com/dotnet/aspnet:8.0-nanoserver-ltsc2022
Version match: host OS must match or be newer than image OS (process isolation).

Essential Docker Commands (1/2)

List all container images stored locally on this host.

# Show all downloaded container images PS C:\\> docker images

Create and start a container in detached mode so it runs in the background.

# Launch a container in the background with a friendly name PS C:\\> docker run -d --name web1 mcr.microsoft.com/windows/servercore:ltsc2022

Essential Docker Commands (2/2)

Lifecycle commands: list, stop, start, remove. The right-side terminal walks through each in sequence.

# Lifecycle: list, stop, start, remove a container PS> docker ps # running (add -a for stopped) PS> docker stop web1 # graceful stop PS> docker start web1 # resume from stopped PS> docker rm web1 # delete the container PS> docker exec -it web1 powershell # shell inside the container

Common flags

  • -d detached (background) · -it interactive terminal
  • -p 80:80 port mapping (host:container)
  • -v volume mount for persistent storage

Nano Server Overview

Nano Server is a deliberately-minimal Windows base image (~300MB) optimized for cloud-native, microservices, and fast-startup workloads. The right-side diagram shows exactly what's in and what's out.

Optimized for

  • Container base image — the smallest official Windows image
  • Cloud-native apps — .NET Core, ASP.NET Core
  • Microservices — minimal attack surface, fast start
  • Remote management only — no local logon, no GUI, PowerShell Core
Note: Since Server 2019, Nano Server is container-only — no standalone install.

Building Custom Images with Dockerfile

A Dockerfile defines how to build a custom image. Key verbs: FROM (base) · WORKDIR (cwd inside) · COPY (files in) · EXPOSE (ports) · ENTRYPOINT (start command).

# Dockerfile for ASP.NET Core app on Nano Server FROM mcr.microsoft.com/dotnet/aspnet:8.0-nanoserver-ltsc2022 WORKDIR /app COPY publish/ . EXPOSE 80 ENTRYPOINT ["dotnet", "MyWebApp.dll"]
# Build the image, then run it on host port 8080 PS> docker build -t myapp:v1 . PS> docker run -d -p 8080:80 --name webapp myapp:v1
