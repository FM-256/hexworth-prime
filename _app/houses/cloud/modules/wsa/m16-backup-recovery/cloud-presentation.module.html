# Install Windows Server Backup feature PS C:\> Install-WindowsFeature -Name Windows-Server-Backup -IncludeManagementTools

System State Backup

Components

All

  • Registry, COM+, boot, WFP

Role-Specific

  • NTDS.dit, SYSVOL, CertSrv, Cluster
# System State backup to E: PS C:\> wbadmin start systemstatebackup -backupTarget:E:

Bare Metal Recovery (BMR)

BMR = restore entire server to blank hardware from a backup image.

  • OS partition + critical volumes + System State, atomic
  • Needs boot media (install USB / recovery)
  • Target reachable from boot env
  • Different hardware OK — may need storage drivers
# Boot from Windows install media → Repair → Troubleshoot → # System Image Recovery → pick image → Finish

BMR Includes

  • System State + critical volumes
  • Partition layout (everything for bare hw)
# Build + execute BMR backup to E: PS C:\> $policy = New-WBPolicy; Add-WBBareMetalRecovery -Policy $policy PS C:\> Add-WBBackupTarget -Policy $policy -Target (New-WBBackupTarget -VolumePath "E:") PS C:\> Start-WBBackup -Policy $policy

Scheduling Backups

Scheduling Options

  • Once daily / multiple per day
  • Task Scheduler / PowerShell
# Schedule BMR at 21:00 and 03:00 daily PS C:\> $policy = New-WBPolicy; Add-WBBareMetalRecovery -Policy $policy PS C:\> Set-WBSchedule -Policy $policy -Schedule 21:00,03:00; Set-WBPolicy -Policy $policy
Best Practice: Schedule backups during low-usage periods to minimize performance impact, but ensure they complete before business hours begin.

Active Directory Recovery

Non-Authoritative

  • Default; partners update DC
  • Use for DC failure

Authoritative

  • Object replicates TO others
  • DSRM + ntdsutil; recover deletions
# Restore System State (DSRM) + mark object authoritative PS C:\> wbadmin start systemstaterecovery -version:01/31/2026-06:00 PS C:\> ntdsutil "activate instance ntds" "authoritative restore" "restore object \"CN=John Doe,OU=Users,DC=hexworth,DC=local\"" quit quit

Active Directory Recycle Bin

AD Recycle Bin recovers deleted AD objects with all attributes intact — no authoritative restore needed.

  • Per-forest, one-way — plan rollout deliberately
  • Needs forest functional level 2008 R2+
  • Without it: objects tombstone, lose attributes
  • With it: attributes preserved for 180 days
# Enable, list, restore deleted objects PS> Enable-ADOptionalFeature 'Recycle Bin Feature' -Scope ForestOrConfigurationSet -Target hexworth.local PS> Get-ADObject -Filter 'isDeleted -eq $true' -IncludeDeletedObjects | Restore-ADObject PS> # If parent OU was deleted: pass -TargetPath explicitly

Benefits

  • Recover deleted objects with all attributes intact
  • No downtime required for recovery
  • Objects recoverable for 180 days (default)
  • No authoritative restore needed

Enabling the Recycle Bin is a one-time, irreversible operation that requires Enterprise Admin privileges and raises the forest functional level.

# Enable the AD Recycle Bin feature for the entire forest PS C:\> Enable-ADOptionalFeature -Identity "Recycle Bin Feature" -Scope ForestOrConfigurationSet -Target "hexworth.local"

Benefits (cont.)

Once enabled, you can query for all recently deleted objects in the directory to see what is available for recovery.

# List all deleted objects currently in the AD Recycle Bin PS C:\> Get-ADObject -Filter {isDeleted -eq $true} -IncludeDeletedObjects
# Find and restore the deleted user "John Doe" from the Recycle Bin PS C:\> Get-ADObject -Filter {displayName -eq "John Doe"} -IncludeDeletedObjects | Restore-ADObject

Volume Shadow Copy Service (VSS)

VSS = point-in-time snapshots that make live-backup consistent.

  • App-consistent if a Writer exists (SQL, Exchange, AD); else crash-consistent
  • Copy-on-write — snapshot fast; shadow storage grows with writes
# Diagnose VSS health (run as Admin) PS C:\> vssadmin list writers PS C:\> vssadmin list shadows ; vssadmin list shadowstorage

VSS Components

  • Requestor: backup app
  • Provider: creates shadow copies
  • Writer: per-app consistency
# List writers + shadow copies PS C:\> vssadmin list writers ; vssadmin list shadows

VSS Components (cont.)

Creating a manual shadow copy gives you an immediate recovery point before making risky changes like software updates.

# Create a new shadow copy of the C: drive right now PS C:\> vssadmin create shadow /for=C:
# Count the total number of shadow copies via PowerShell PS C:\> (Get-WmiObject Win32_ShadowCopy).Count
Troubleshooting Tip: If backups fail, check VSS writer status with "vssadmin list writers". Failed writers often indicate application issues.
