IIS Architecture

Components

  • HTTP.sys (kernel) → WAS → W3SVC → w3wp.exe
  • Modules: native (C++) + managed (.NET)
# Install IIS + ASP.NET + redirect PS C:\> Install-WindowsFeature Web-Server,Web-Asp-Net45,Web-Http-Redirect -IncludeManagementTools

Request Processing Pipeline

Request Flow

  • HTTP.sys queues the request in kernel mode
  • WAS picks the app pool
  • W3SVC routes to the worker process
  • w3wp.exe runs the module pipeline

Integrated Pipeline

  • Native and managed modules unified
  • Default mode for IIS 7.0+

Classic Pipeline

  • Separate ISAPI and .NET pipelines
  • Legacy compatibility mode

Websites and Bindings

Binding Components

  • IP — All Unassigned or specific
  • Port — 80 (HTTP), 443 (HTTPS)
  • Host Header — virtual hosting
  • Protocol — HTTP / HTTPS
# New site + add HTTPS binding PS C:\> New-Website -Name "Corporate Portal" -PhysicalPath "C:\inetpub\portal" -HostHeader "portal.hexworth.local" -Port 80 PS C:\> New-WebBinding -Name "Corporate Portal" -Protocol https -Port 443 -HostHeader "portal.hexworth.local"

Website vs Web Application vs Virtual Directory

  • Website: top-level container, unique IP:port:hostname
  • Application: sub-path, own pool + config scope
  • Virtual Dir: URL → folder, inherits parent pool

Application Pools

  • Benefits: process isolation, distinct identity, independent recycling
  • Identities: ApplicationPoolIdentity (default), NetworkService, custom
# Create a pool, set runtime + identity PS C:\> New-WebAppPool -Name "PortalAppPool" PS C:\> Set-ItemProperty "IIS:\AppPools\PortalAppPool" -Name processModel.identityType -Value ApplicationPoolIdentity

Application Pool Recycling

Triggers + Behavior

  • Triggers: time (1740 min), memory, request count
  • Overlapped: new w3wp before old exits, in-flight reqs finish
# Set private-memory cap + scheduled 3 AM PS C:\> Set-ItemProperty "IIS:\AppPools\PortalAppPool" -Name recycling.periodicRestart.privateMemory -Value 1048576

Virtual Directories & Applications

VDir vs Application

  • VDir: URL → folder, inherits parent pool
  • App: own config + can use own pool
# VDir to external folder, then App with own pool PS C:\> New-WebVirtualDirectory -Site "Corporate Portal" -Name "docs" -PhysicalPath "D:\Documentation" PS C:\> New-WebApplication -Site "Corporate Portal" -Name "api" -PhysicalPath "C:\inetpub\portal\api" -ApplicationPool "APIAppPool"

Default Documents & Directory Browsing

  • Default doc: ordered list IIS walks; first match wins
  • Dir browsing: off by default — enable only for download sites
# Promote home.html, enable browsing on /docs only PS C:\> Add-WebConfiguration -Filter "/system.webServer/defaultDocument/files" -PSPath "IIS:\Sites\Corporate Portal" -AtIndex 0 -Value @{value="home.html"}

SSL/TLS Configuration

Certificate Sources

  • Internal CA (AD CS): intranet
  • Public CA / Let's Encrypt: internet
  • Self-signed: testing only
# Self-signed cert, then bind to HTTPS PS C:\> New-SelfSignedCertificate -DnsName "portal.hexworth.local" -CertStoreLocation "Cert:\LocalMachine\My" PS C:\> $cert = Get-ChildItem Cert:\LocalMachine\My | Where-Object { $_.Subject -like "*portal*" } PS C:\> New-Item "IIS:\SslBindings\0.0.0.0!443!portal.hexworth.local" -Value $cert

SSL/TLS Best Practices

Protocols

  • Disable: SSL 2/3, TLS 1.0/1.1
  • Enable: TLS 1.2, TLS 1.3
  • Strong ciphers + PFS

Cert Practices

  • 2048-bit RSA minimum
  • Include all SANs
  • Renewal alerts + HSTS
# Require SSL on the site PS C:\> Set-WebConfigurationProperty -Filter "system.webServer/security/access" -Name "sslFlags" -Value "Ssl" -PSPath "IIS:\Sites\Corporate Portal"

Authentication Methods

  • Windows: NTLM/Kerberos, SSO, intranet
  • Basic / Digest / Forms / Anonymous
# Enable Windows auth, disable anonymous PS C:\> Set-WebConfigurationProperty -Filter "/system.webServer/security/authentication/windowsAuthentication" -Name "enabled" -Value "True" -PSPath "IIS:\Sites\Corporate Portal"

Authentication Deep Dive

Anonymous / Basic

  • Anonymous: IUSR account, public sites
  • Basic: Base64 — HTTPS required

Digest / Windows

  • Digest: MD5 hash, AD-bound, rare today
  • Windows: Kerberos+NTLM, SSO, intranet

URL Authorization

Rules

  • Allow / Deny users, roles, verbs
  • First match wins (top-down)
  • Scope: site, app, or directory
<!-- web.config: allow WebAdmins only --> <authorization> <add accessType="Allow" roles="HEXWORTH\WebAdmins" /> <add accessType="Deny" users="*" /> </authorization>

Request Filtering

  • Filters: extensions, URL sequences, verbs, hidden segments
  • Limits: content 30 MB, URL 4096 B, query 2048 B
# Block .bak files from being served PS C:\> Add-WebConfigurationProperty -Filter "system.webServer/security/requestFiltering/fileExtensions" -Name "." -Value @{fileExtension='.bak';allowed='False'}

Request Handling

Key Features

  • Static / Dynamic Compression
  • Output Caching
  • Request Filtering
# Enable static + dynamic compression PS C:\> Enable-WindowsOptionalFeature -Online -FeatureName IIS-HttpCompressionStatic PS C:\> Enable-WindowsOptionalFeature -Online -FeatureName IIS-HttpCompressionDynamic

HTTP Logging

Formats

  • W3C Extended: default, customizable
  • IIS / NCSA / Custom

Fields

  • Date, Time, Client IP
  • Method, URI, status
  • Bytes, User agent, referer
# Set W3C format, redirect logs to D: PS C:\> Set-WebConfigurationProperty -Filter "system.applicationHost/sites/site[@name='Corporate Portal']/logFile" -Name "logFormat" -Value "W3C" -PSPath "MACHINE/WEBROOT/APPHOST" PS C:\> Set-ItemProperty "IIS:\Sites\Corporate Portal" -Name logFile.directory -Value "D:\IISLogs"

  • Rules: per-path R/W perms, require HTTPS

IIS PowerShell Module

The WebAdministration and IISAdministration modules provide comprehensive PowerShell management.

WebAdministration (Legacy)

  • Uses IIS: PSDrive provider
  • Navigate like a file system
  • Broad compatibility
  • Cmdlets: New-Website, Get-WebBinding

IISAdministration (Modern)

  • Pipeline-friendly objects
  • Better performance
  • Available on IIS 10+
  • Cmdlets: Get-IISSite, New-IISSite

IIS PowerShell, Configuration

# Load module, list sites + pools, export config PS C:\> Import-Module WebAdministration PS C:\> Get-IISSite PS C:\> Get-ChildItem IIS:\Sites PS C:\> Get-ChildItem IIS:\AppPools PS C:\> Get-WebConfiguration -Filter "system.webServer" -PSPath "IIS:\Sites\Corporate Portal" | Export-Clixml "C:\Backup\portal-config.xml"
