What is Failover Clustering?

A failover cluster is a group of independent servers (nodes) that work together to keep applications and services available. The right-side diagram shows what happens when the active node fails.

Four ingredients

  • Automatic Failover — when a node fails, workloads move to surviving nodes
  • Shared Storage — all nodes access the same data via SAN, iSCSI, or S2D
  • Heartbeat Network — nodes constantly monitor each other's health
  • Clustered Roles — services that can move between nodes (VMs, File Servers, SQL)

Quorum & Witness Configuration

Quorum = voting system that prevents split-brain when nodes disagree. Right panel shows a 4-node + witness scenario.

Four witness types

  • Node Majority — best for odd node counts
  • Disk Witness — shared disk vote, even-node tiebreak
  • Cloud Witness — Azure blob, no shared storage
  • File Share Witness — SMB share, no Azure dep
# Set Azure blob storage as the cluster quorum witness PS> Set-ClusterQuorum -CloudWitness -AccountName "hexworthwitness" -AccessKey "<key>"

Cluster Shared Volumes (CSV)

CSV gives all cluster nodes a single unified path (C:\ClusterStorage\Volume1) they can read AND write to simultaneously. The right-side diagram shows all three nodes writing to the same volume.

# Convert a cluster disk into a Cluster Shared Volume PS> Add-ClusterSharedVolume -Name "Cluster Disk 1"

Common Clustered Roles

Clustered roles = services that fail over between nodes. Right panel shows the common ones.

Common roles

  • Hyper-V VMs — live migrate, zero downtime (most common)
  • Scale-Out File Server — continuously available SMB
  • SQL Server — FCI or Always On AG
  • Generic — DHCP, Print Server, iSCSI Target
# Register a VM as a highly available role, then require its disk PS> Add-ClusterVirtualMachineRole -VMName "SQL-VM-01" Set-ClusterResourceDependency -Resource "SQL-VM-01" -Dependency "[Cluster Disk 1]"

Cluster-Aware Updating (CAU)

CAU automates Windows updates across cluster nodes with minimal downtime. Right panel animates drain → patch → resume.

Per-node sequence: Pause → Drain → Install → Reboot → Resume. Service stays up throughout.

Three modes

  • Self-Updating — cluster updates itself on schedule
  • Remote-Updating — admin triggers from remote machine
  • Pre/Post Scripts — custom scripts around updates
# Start a rolling update across all nodes, then check status PS> Invoke-CauRun -ClusterName "HexCluster" -Force Get-CauRun -ClusterName "HexCluster"

Cluster PowerShell Commands (1/3)

Retrieve the cluster name, domain, and configuration details.

# View basic cluster information PS C:\\> Get-Cluster

List every node in the cluster and see which are currently up.

# List all nodes and their current state PS C:\\> Get-ClusterNode

See all clustered roles and which node currently owns each one.

# Show all clustered roles (VMs, file servers, etc.) PS C:\\> Get-ClusterGroup

Cluster PowerShell Commands (2/3)

Pause a node and drain its roles to another node before maintenance.

# Drain all roles off a node for planned maintenance PS C:\\> Suspend-ClusterNode -Name "Node1" -Drain

After maintenance, bring the node back into service.

# Return a paused node to active cluster duty PS C:\\> Resume-ClusterNode -Name "Node1"

Manually move a clustered role to a specific node for load balancing or testing.

# Move a clustered role to a different node PS C:\\> Move-ClusterGroup -Name "SQL-VM" -Node "Node2"

Cluster PowerShell Commands (3/3)

Before building a cluster, validate that the hardware and configuration pass all requirements.

# Run full validation tests on prospective cluster nodes PS C:\\> Test-Cluster -Node "Node1","Node2"
Best Practice: Always run Test-Cluster before creating a cluster and after adding nodes. Microsoft requires passing validation for support.

Module Summary

  • Failover Clustering provides high availability through automatic failover between nodes
  • Quorum prevents split-brain - use Cloud Witness for modern deployments
  • Cluster Shared Volumes (CSV) enable simultaneous read/write from all nodes
  • Clustered Roles include Hyper-V VMs, File Servers, SQL Server, and generic services
  • Cluster-Aware Updating (CAU) automates patching with minimal downtime
  • Always run Test-Cluster validation before production deployment
