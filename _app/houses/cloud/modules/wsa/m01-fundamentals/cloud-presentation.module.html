📦 Windows Server Editions

Windows Server 2022 comes in several editions, each designed for different workloads and environments.

Edition Use Case Licensing
Standard Physical or lightly virtualized environments Per-core + CALs, 2 VMs included
Datacenter Highly virtualized datacenters Per-core + CALs, Unlimited VMs
Essentials Small business (≤25 users) Per-server, no CALs needed
Azure Edition Azure hybrid cloud integration Azure-only features (Hotpatch)
Key Insight: The main difference between Standard and Datacenter is virtualization rights. Choose Datacenter when you need more than 2 VMs per host.

🎛️ Installation Options

Windows Server can be installed in two modes. This decision is made during installation and affects how you manage the server.

Desktop Experience

  • Full GUI with familiar Windows interface
  • Server Manager dashboard
  • Larger disk footprint (~10GB more)
  • More attack surface
  • Best for: Learning, legacy apps

Server Core

  • Command-line only (no GUI)
  • Managed via PowerShell or remote tools
  • Smaller footprint, fewer updates
  • Reduced attack surface
  • Best for: Production, security-focused
Important: You can switch from Desktop Experience to Server Core, but not the other way around without reinstallation. Choose carefully!

⚙️ Server Manager

Server Manager is the central management console for Windows Server with Desktop Experience. It launches automatically at logon.

Server Manager Dashboard

  • Welcome Tile - Quick actions (Add roles, Add servers, Create groups)

Pro Tip: Server Manager can manage multiple remote servers. Add them via "Manage > Add Servers" to create a single pane of glass for your infrastructure.

💻 PowerShell Essentials

PowerShell is the backbone of modern Windows Server administration. Every GUI action has a PowerShell equivalent - and PowerShell can do much more.

Verb-Noun Pattern

PowerShell commands (called cmdlets) follow a consistent Verb-Noun pattern that tells you exactly what each command does:

  • Get-Service, Get-Process, Get-EventLog (retrieve info)
  • Set-ExecutionPolicy, Set-Service (modify settings)
  • New-Item, New-ADUser (create objects)
  • Remove-Item, Remove-WindowsFeature (delete objects)

Getting Started

Not all PowerShell commands are cmdlets. PowerShell has built-in variables that hold system data — they always start with $. The first thing to check on any server is which PowerShell version is running, because PS 5.1 (built into Windows Server) and PS 7+ (installed separately) support different cmdlets.

# Query the built-in $PSVersionTable variable to see version details PS C:\> $PSVersionTable
# Expected output: Name Value ---- ----- PSVersion 5.1.20348.2849 PSEdition Desktop PSCompatibleVersions {1.0, 2.0, 3.0, 4.0...} CLRVersion 4.0.30319.42000

PowerShell ships with hundreds of cmdlets. You can search for them by verb to discover what's available on any server.

# List every cmdlet that starts with "Get-" on this system PS C:\> Get-Command -Verb Get
# Expected output: CommandType Name ModuleName ----------- ---- ---------- Cmdlet Get-Acl Microsoft.PowerShell.Security Cmdlet Get-ChildItem Microsoft.PowerShell.Management Cmdlet Get-ComputerInfo Microsoft.PowerShell.Management Cmdlet Get-Service Microsoft.PowerShell.Management ...hundreds more

Every cmdlet has built-in documentation. When you're unsure how to use a command, pull up its help page with real examples you can copy directly.

# Show help for Get-Service including working examples PS C:\> Get-Help Get-Service -Examples
# Expected output: NAME Get-Service SYNOPSIS Gets the services on the computer. ---------- Example 1: Get all services ---------- PS C:\> Get-Service ---------- Example 2: Get services that begin with a search string ---------- PS C:\> Get-Service -Name "wmi*"

🔗 The PowerShell Pipeline

Most commands return more data than you need. The pipeline operator | lets you send the output of one command directly into another for filtering, sorting, or formatting — all in a single line.

How the Pipeline Works

Think of the pipe | as a conveyor belt. The command on the left produces objects, and the command on the right processes each one. Unlike Linux pipes that pass raw text, PowerShell pipes pass full objects with properties you can inspect and filter.

# Send all services into Select-Object to show only the first 5 PS C:\> Get-Service | Select-Object -First 5
# Expected output: Status Name DisplayName ------ ---- ----------- Running BFE Base Filtering Engine Stopped BITS Background Intelligent Transfer Ser... Running CryptSvc Cryptographic Services Running DcomLaunch DCOM Server Process Launcher Stopped DeviceInstall Device Install Service

Filtering with Where-Object

Where-Object examines each object in the pipeline and only passes through the ones that match your condition. The condition goes inside a script block { } — curly braces that contain code to run on each object.

Inside the script block, $_ represents the current object being examined. You access its properties with a dot: $_.PropertyName. The comparison operator -eq means "equals."

# Keep only services where the Status property equals 'Running' PS C:\> Get-Service | Where-Object { $_.Status -eq 'Running' }
# Expected output: Status Name DisplayName ------ ---- ----------- Running BFE Base Filtering Engine Running CryptSvc Cryptographic Services Running DcomLaunch DCOM Server Process Launcher

Let's break down that command piece by piece:

Piece Meaning
Get-Service Retrieve all services on this server
| Pipe — send the results into the next command
Where-Object Filter — only keep objects that match the condition
{ } Script block — code that tests each object
$_ The current object (one service at a time)
.Status Access the Status property of that object
-eq Comparison operator: equals
'Running' The value to compare against

Comparison Operators

PowerShell uses dash-prefixed operators instead of symbols like == or >. Boolean values are $true and $false.

Operator Meaning Example
-eq Equals $_.Status -eq 'Running'
-ne Not equals $_.Status -ne 'Stopped'
-gt / -lt Greater / Less than $_.CPU -gt 100
-like Wildcard match $_.Name -like 'Win*'

Chaining Multiple Pipes

You can chain as many pipes as you need. Each | passes the result to the next command, building a data processing assembly line.

# Get processes → sort by CPU usage (highest first) → take the top 5 PS C:\> Get-Process | Sort-Object CPU -Descending | Select-Object -First 5
# Expected output: Handles NPM(K) PM(K) WS(K) CPU(s) Id ProcessName ------- ------ ----- ----- ------ -- ----------- 1842 98 245612 301244 184.33 4012 svchost 623 31 87204 93180 72.08 2548 ServerManager 412 22 51020 58432 31.55 876 lsass
Lab Preview: In Lab 2, you'll use Get-WindowsFeature | Where-Object { $_.Installed -eq $true } to filter installed server roles. This works exactly the same way — $_ is each feature, .Installed is a boolean property, and $true is the PowerShell boolean value for true.

📋 Essential Commands

System Information

The first thing you do on any new server is get its identity and hardware details. These two commands give you the full picture and the quick answer.

# Pull detailed hardware, OS, and domain info for this server PS C:\> Get-ComputerInfo
# Expected output: WindowsProductName WindowsVersion CsDomain ------------------ -------------- -------- Windows Server 2022 Standard 21H2 corp.local
# Return just the server's hostname (quick identity check) PS C:\> hostname
# Expected output: DC01

Services Management

Services are the backbone of Windows Server. You need to check which ones are running, start stopped services, and restart misbehaving ones.

# Filter the service list to show only services currently running PS C:\> Get-Service | Where-Object {$_.Status -eq 'Running'}
# Expected output: Status Name DisplayName ------ ---- ----------- Running BFE Base Filtering Engine Running CryptSvc Cryptographic Services Running DcomLaunch DCOM Server Process Launcher Running Dhcp DHCP Client Running W32Time Windows Time
# Start the Print Spooler service if it was stopped PS C:\> Start-Service -Name Spooler
# Restart the Windows Time service to force a time resync PS C:\> Restart-Service -Name W32Time

Process Management

When a server is running slow, you need to find which processes are consuming the most CPU.

# Sort all processes by CPU usage and show the top 10 consumers PS C:\> Get-Process | Sort-Object CPU -Descending | Select-Object -First 10
# Expected output: Handles NPM(K) PM(K) WS(K) CPU(s) Id ProcessName ------- ------ ----- ----- ------ -- ----------- 1842 98 245612 301244 184.33 4012 svchost 623 31 87204 93180 72.08 2548 ServerManager 412 22 51020 58432 31.55 876 lsass

Event Logs

Event logs are your server's diary. Check recent entries to spot issues, or filter by error level when troubleshooting a specific problem.

# Show the 20 most recent entries from the System event log PS C:\> Get-EventLog -LogName System -Newest 20
# Expected output: Index Time EntryType Source EventID Message ----- ---- --------- ------ ------- ------- 8842 Feb 08 10:15 Information Service Control Mgr 7036 The Windows Time... 8841 Feb 08 10:12 Warning Win32k 263 Display driver... 8840 Feb 08 09:58 Information EventLog 6013 The system uptime...
# Filter the System log to show only Error-level entries PS C:\> Get-EventLog -LogName System -EntryType Error
# Expected output: Index Time EntryType Source EventID Message ----- ---- --------- ------ ------- ------- 8839 Feb 08 08:30 Error NETLOGON 5719 No domain control... 8835 Feb 07 22:10 Error Disk 11 The driver detect...
Pro Tip: Use Get-Help cmdlet -Online to open Microsoft documentation in your browser for any command.

🔧 Initial Configuration

After installing Windows Server, complete these essential configuration tasks:

Post-Installation Checklist

  1. Set Computer Name - Rename from default (WIN-XXXXX)
  2. Configure Network - Static IP for servers, DNS settings
  3. Windows Update - Apply latest security patches
  4. Time Zone - Critical for Active Directory and logging
  5. Remote Desktop - Enable for remote management
  6. Windows Firewall - Configure for required services
  7. Join Domain - Connect to Active Directory (if applicable)

PowerShell Configuration Commands

Every item on the checklist above can be done in PowerShell. These are the three commands you will run on almost every new server build.

# Rename this server from its random default name and reboot to apply PS C:\> Rename-Computer -NewName "DC01" -Restart
# Expected output: WARNING: The changes will take effect after you restart the computer WIN-A83KD92MN4P.

Servers need static IPs so other machines can always find them. This assigns an address, subnet, and gateway in one command.

# Assign a static IP address, subnet mask, and default gateway to the Ethernet adapter PS C:\> New-NetIPAddress -InterfaceAlias "Ethernet" -IPAddress 192.168.1.10 -PrefixLength 24 -DefaultGateway 192.168.1.1
# Expected output: IPAddress InterfaceAlias PrefixLength DefaultGateway --------- -------------- ------------ -------------- 192.168.1.10 Ethernet 24 192.168.1.1

Without correct DNS settings, the server cannot resolve domain names or find domain controllers for authentication.

# Point the Ethernet adapter's DNS to the local DC and a public fallback PS C:\> Set-DnsClientServerAddress -InterfaceAlias "Ethernet" -ServerAddresses 192.168.1.10,8.8.8.8

🌐 Remote Management

In production, you rarely sit at a server console. Remote management is essential.

Remote Management Options

Tool Use Case Protocol
Remote Desktop (RDP) Full GUI access TCP 3389
PowerShell Remoting Command-line administration WinRM (5985/5986)
Server Manager Multi-server GUI management WinRM
Windows Admin Center Modern web-based management HTTPS

PowerShell Remoting Commands

PowerShell Remoting lets you run commands on remote servers as if you were sitting at the console. It must be enabled first, then you can connect interactively or fan out commands to multiple machines at once.

# Enable WinRM and configure the firewall so this server accepts remote PS connections PS C:\> Enable-PSRemoting -Force
# Expected output: WinRM has been updated to receive requests. WinRM service type changed successfully. WinRM service started. WinRM has been updated for remote management. WinRM firewall exception enabled.

An interactive session gives you a live prompt on the remote server. Your prompt changes to show you are no longer running locally.

# Open an interactive PowerShell session on SERVER01 PS C:\> Enter-PSSession -ComputerName SERVER01
# Expected output: [SERVER01]: PS C:\Users\Administrator\Documents>

Invoke-Command lets you run the same script block on multiple servers in parallel, which is how admins manage fleets of machines efficiently.

# Run Get-Service on DC01 and DC02 simultaneously and return combined results PS C:\> Invoke-Command -ComputerName DC01,DC02 -ScriptBlock { Get-Service }
# Expected output: Status Name DisplayName PSComputerName ------ ---- ----------- -------------- Running W32Time Windows Time DC01 Running DNS DNS Server DC01 Running W32Time Windows Time DC02 Running DNS DNS Server DC02

🎯 Windows Admin Center

Windows Admin Center (WAC) is Microsoft's modern, browser-based management tool that consolidates many administrative tasks.

Key Features

  • Single Pane of Glass - Manage servers, clusters, and hyper-converged infrastructure
  • Azure Integration - Connect on-premises servers to Azure services
  • Role-Based Access - Delegate admin tasks securely
  • Extensions - Add functionality through Microsoft and partner extensions
  • No Agent Required - Uses existing WinRM/PowerShell
AZ-800 Note: Windows Admin Center is heavily featured in the exam. Know how to deploy it (gateway mode vs desktop mode) and use it for common tasks.

Deployment Options

  • Desktop Mode - Run on Windows 10/11 for managing a few servers
  • Gateway Mode - Install on a server for multi-user access

⌨️ Managing Server Core

Server Core has no GUI, but you have several tools for local and remote management.

Local Management

When you log into Server Core, you get a bare command prompt. Two commands get you started: sconfig for guided setup, and powershell for everything else.

# Launch the menu-driven Server Configuration tool for common setup tasks C:\> sconfig
# Expected output: =============================================== Server Configuration =============================================== 1) Domain/Workgroup: Workgroup: WORKGROUP 2) Computer Name: WIN-A83KD92MN4P 4) Configure Remote Management: Enabled 6) Windows Update Settings: Manual 7) Remote Desktop: Disabled 8) Network Settings

PowerShell is your primary tool on Server Core. From it you can install roles, manage services, and do everything the GUI would do.

# Switch from the basic command prompt into a PowerShell session C:\> powershell
# List all available roles and features and their install status PS C:\> Get-WindowsFeature
# Expected output: Display Name Name Install State ------------ ---- ------------- [ ] Active Directory Domain Services AD-Domain-Services Available [ ] DNS Server DNS Available [X] File and Storage Services FileAndStorage-Services Installed [X] .NET Framework 4.8 Features NET-Framework-45-Fea... Installed

sconfig Menu Options

  • 1) Domain/Workgroup membership
  • 2) Computer name
  • 4) Remote management settings
  • 6) Windows Update settings
  • 7) Remote Desktop
  • 8) Network settings
Best Practice: Configure Server Core remotely using Windows Admin Center, PowerShell Remoting, or RSAT (Remote Server Administration Tools) from another machine.
