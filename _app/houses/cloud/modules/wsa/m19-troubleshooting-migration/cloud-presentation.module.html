Built-in Diagnostic Tools (2/2)

Configuration recommendations

Pull the most recent critical and error events from the System log to spot failures fast.

# Filter System log for critical/error events PS C:\\> Get-WinEvent -LogName System -MaxEvents 50 | Where-Object Level -le 2

Check real-time memory availability to identify resource pressure.

# Query available memory in megabytes PS C:\\> Get-Counter '\\Memory\\Available MBytes'

Verify that a specific port is reachable on a remote server, which confirms both network path and service availability.

# Test SMB connectivity to a domain controller PS C:\\> Test-NetConnection -ComputerName DC01 -Port 445

Confirm DNS resolution is returning the correct address for your domain.

# Resolve a DNS A record for the domain PS C:\\> Resolve-DnsName -Name 'hexworth.local' -Type A

Network Troubleshooting: Connectivity Tests

Diagnose connectivity and network service issues:

  • ping - Basic reachability
  • tracert - Route path analysis
  • pathping - Combined ping + trace
  • Test-NetConnection - Port connectivity
  • nslookup/Resolve-DnsName - DNS resolution

Network Troubleshooting: Common Issues

  • IP address conflicts
  • DNS server misconfiguration
  • Firewall blocking traffic
  • VLAN/subnet mismatches
  • MTU size issues

Start by reviewing the full IP configuration to confirm addresses, gateways, and DNS servers are correct.

# Display full IP configuration for all adapters PS C:\\> Get-NetIPConfiguration

Check which adapters are active and their link speed to rule out physical layer issues.

# List adapter status and link speed PS C:\\> Get-NetAdapter | Select-Object Name, Status, LinkSpeed

Verify that the correct DNS servers are assigned to each interface.

# Show DNS server addresses per interface PS C:\\> Get-DnsClientServerAddress

Identify which ports have services actively listening, which helps detect conflicts or unexpected services.

# List all listening ports with process IDs PS C:\\> netstat -ano | Select-String 'LISTENING'

Run a detailed connectivity test against LDAP on a domain controller to confirm AD communication.

# Test LDAP port connectivity with full details PS C:\\> Test-NetConnection -ComputerName DC01 -Port 389 -InformationLevel Detailed

Replication Issues

Diagnose AD replication, authentication, and DNS issues:

  • repadmin /replsummary - Replication status
  • repadmin /showrepl - Detailed replication info
  • repadmin /syncall - Force replication
  • dcdiag /test:replications - Replication test

Authentication Issues (1/2)

Authentication Issues

  • nltest /dsgetdc: - DC discovery
  • klist - Kerberos tickets
  • setspn -L - SPN listing
  • Event ID 4771 - Kerberos failures

Run dcdiag in verbose mode for a comprehensive domain controller health report covering DNS, replication, and services.

# Run full DC diagnostics in verbose mode PS C:\\> dcdiag /v

Get a quick summary of replication status across all domain controllers to spot failures.

# Show replication summary for all DCs PS C:\\> repadmin /replsummary

Authentication Issues (2/2)

Query specific replication failures on a named DC to pinpoint the source of replication problems.

# Check replication failures on a specific DC PS C:\\> Get-ADReplicationFailure -Target DC01

Verify which domain controller a client is authenticating against and confirm proper DC discovery.

# Discover which DC is servicing this domain PS C:\\> nltest /dsgetdc:hexworth.local

List all domain controllers with their site assignments and Global Catalog status for topology review.

# List all DCs with site and GC status PS C:\\> Get-ADDomainController -Filter * | Select-Object Name, Site, IsGlobalCatalog

Boot & Startup Issues (2/2)

From the Windows Recovery Environment command prompt, repair the Master Boot Record if the system cannot find the boot partition.

# Repair the Master Boot Record (WinRE) C:\\> bootrec /fixmbr

Write a new boot sector to the system partition to fix corrupted boot code.

# Write a new boot sector C:\\> bootrec /fixboot

Rebuild the Boot Configuration Data store when Windows installations are not listed at startup.

# Rebuild the BCD store C:\\> bootrec /rebuildbcd

Review the full boot configuration to verify OS entries, boot device paths, and recovery settings.

# Display all boot configuration entries C:\\> bcdedit /enum all

Scan for and repair corrupted system files. If SFC finds unrepairable files, use DISM to restore the component store first.

# Scan and repair protected system files C:\\> sfc /scannow
# Repair the Windows component store (run before SFC if needed) C:\\> DISM /Online /Cleanup-Image /RestoreHealth
Stop Errors (BSOD): Check minidump files in C:\\Windows\\Minidump for crash analysis. Use WinDbg or BlueScreenView to analyze.

Backup & Recovery

Implement backup strategies and perform system recovery:

Backup Types

  • Full Server - Complete system state + data
  • System State - AD, registry, boot files
  • Bare Metal - Full recovery to new hardware
  • Volume/File - Specific data backup

Recovery Options

  • Non-authoritative - Restore and replicate from other DCs
  • Authoritative - Restore and replicate TO other DCs
  • BMR - Bare metal restore to new server
  • File Recovery - Restore individual files

First, install the Windows Server Backup feature if it is not already present.

# Install the Windows Server Backup feature PS C:\\> Add-WindowsFeature Windows-Server-Backup

Create a backup policy, target the C: volume and system state, then execute the backup. These commands chain together through the $policy variable.

# Build and run a backup policy for C: drive + system state PS C:\\> $policy = New-WBPolicy PS C:\\> $volume = Get-WBVolume -AllVolumes | Where-Object MountPoint -eq 'C:' PS C:\\> Add-WBVolume -Policy $policy -Volume $volume PS C:\\> Add-WBSystemState -Policy $policy PS C:\\> Start-WBBackup -Policy $policy

Server Migration Strategies

Plan and execute migrations between Windows Server versions:

Migration Approaches

  • In-place Upgrade - Upgrade OS on same hardware
  • Side-by-side - New server, migrate roles/data
  • Swing Migration - Temporary server during transition
  • Cluster Rolling - Upgrade cluster nodes one at a time

Migration Tools

  • Windows Server Migration Tools
  • Storage Migration Service
  • ADMT - AD Migration Tool
  • USMT - User State Migration Tool
Migration Checklist:
  • Inventory current roles, features, and applications
  • Verify hardware/software compatibility
  • Full backup before migration
  • Test in lab environment first
  • Plan rollback procedure

Storage Migration Service (2/2)

Verify migration success

Install the Storage Migration Service proxy on the destination server.

# Install the SMS proxy feature PS C:\\> Install-WindowsFeature SMS-Proxy

Create a named migration job that will track the entire migration lifecycle.

# Create a new migration job PS C:\\> New-SmsJob -Name "FileServer-Migration"

Define the source and destination servers for this migration job.

# Add the source server to the migration job PS C:\\> Add-SmsSourceComputer -Name "FileServer-Migration" -ComputerName "FS-OLD"
# Set the destination server for the migration job PS C:\\> Set-SmsDestinationComputer -Name "FileServer-Migration" -ComputerName "FS-NEW"

Execute the three migration phases in order: inventory scans shares, transfer copies data, and cutover swaps server identities.

# Phase 1: Scan source for shares and data PS C:\\> Start-SmsInventory -Name "FileServer-Migration"
# Phase 2: Copy data and permissions to destination PS C:\\> Start-SmsTransfer -Name "FileServer-Migration"
# Phase 3: Swap identities (name/IP) to complete migration PS C:\\> Start-SmsCutover -Name "FileServer-Migration"
