Built-in Diagnostic Tools (1/2)

Windows Server ships with four front-line diagnostic utilities. Each answers a different question; learn which to reach for first.

Four built-in tools

  • Event Viewer — system / application / security logs (what happened)
  • Resource Monitor — real-time CPU, memory, disk, network (what's busy now)
  • Reliability Monitor — system stability timeline (when did things break)
  • Best Practices Analyzer — checks roles against Microsoft baselines (what's misconfigured)

Built-in Diagnostic Tools (2/2)

Four go-to PowerShell one-liners for triage. Each answers one common question fast.

# Recent critical + error events in the System log PS> Get-WinEvent -LogName System -MaxEvents 50 | Where-Object Level -le 2 # Live memory pressure check PS> Get-Counter '\Memory\Available MBytes' # Is a specific port open on a remote host? PS> Test-NetConnection -ComputerName DC01 -Port 445 # Is DNS resolving the right address? PS> Resolve-DnsName -Name 'hexworth.local' -Type A

Network Troubleshooting: Connectivity Tests

Five standard tools cover most reachability and DNS questions. Pick by the layer you're testing — L3 reachability, route path, port, or name.

Five tools

  • ping — basic L3 reachability
  • tracert — route path analysis (where does it stop)
  • pathping — combined ping + trace with packet loss per hop
  • Test-NetConnection — TCP port reachability (the modern one)
  • nslookup / Resolve-DnsName — DNS resolution

Network Troubleshooting: Common Issues

Five issues account for most "the network is down" calls. Walk through them in order.

Five common issues

  • IP address conflicts
  • DNS server misconfiguration
  • Firewall blocking traffic
  • VLAN/subnet mismatches
  • MTU size issues
# Triage sequence — config, links, DNS, listeners, LDAP test PS> Get-NetIPConfiguration Get-NetAdapter | Select Name, Status, LinkSpeed Get-DnsClientServerAddress netstat -ano | Select-String 'LISTENING' Test-NetConnection -ComputerName DC01 -Port 389 -InformationLevel Detailed

Replication Issues

When DCs disagree on the directory, replication has broken. Three failure modes cover most of it: lingering objects, USN rollback, RPC blocked at the firewall. The tools below tell you which.

Diagnostic commands

  • repadmin /replsummary — quick health summary across the forest
  • repadmin /showrepl — detailed per-partner replication state
  • repadmin /syncall — force replication right now
  • dcdiag /test:replications — broader replication health test

Authentication Issues (1/2) — Diagnostics

Kerberos and NTLM problems show as confusing 4625 / 4771 events. These five commands give you DC discovery, ticket state, SPN map, and overall health.

Triage toolkit

  • nltest /dsgetdc: — discover which DC is servicing this client
  • klist — current Kerberos tickets
  • setspn -L — Service Principal Name listing
  • Event ID 4771 — Kerberos auth failures (Security log)
# Full DC diagnostics + replication summary PS> dcdiag /v repadmin /replsummary

Authentication Issues (2/2)

Query specific replication failures on a named DC to pinpoint the source of replication problems.

# Check replication failures on a specific DC PS C:\\> Get-ADReplicationFailure -Target DC01
# Discover which DC is servicing this domain PS C:\\> nltest /dsgetdc:hexworth.local
# List all DCs with site and GC status PS C:\\> Get-ADDomainController -Filter * | Select-Object Name, Site, IsGlobalCatalog

Boot & Startup Issues (1/2)

Four recovery options for boot failures — pick by how broken the system is, from least invasive to most.

Recovery options

  • Safe Mode — minimal drivers/services
  • Last Known Good — undo last registry change
  • System Restore — roll back to restore point
  • Startup Repair — auto boot-sector fix (WinRE)

Boot & Startup Issues (2/2)

Bootrec from WinRE repairs BCD/MBR. Run DISM before SFC if SFC reports unrepairable files.

# Boot repair sequence (WinRE command prompt) C:\> bootrec /fixmbr # repair Master Boot Record C:\> bootrec /fixboot # write new boot sector C:\> bootrec /rebuildbcd # rebuild BCD store C:\> bcdedit /enum all # list all boot entries # System-file repair sequence C:\> DISM /Online /Cleanup-Image /RestoreHealth # repair component store first C:\> sfc /scannow # then scan + repair protected files

BSOD: minidumps in C:\Windows\Minidump · analyze with WinDbg or BlueScreenView.

Backup & Recovery

Pick the backup type for what could fail; pick recovery mode for replication direction.

Backup types

  • Full Server + System State (AD, registry, boot)
  • Bare Metal Recovery — to new hardware
  • Volume / File — specific data

Recovery

  • Non-authoritative — restore, replicate FROM other DCs
  • Authoritative — restore, replicate TO other DCs
# Install + run a backup of C: + system state PS> Add-WindowsFeature Windows-Server-Backup $policy = New-WBPolicy Add-WBVolume -Policy $policy -Volume (Get-WBVolume -AllVolumes | ? MountPoint -eq 'C:') Add-WBSystemState -Policy $policy Start-WBBackup -Policy $policy

Server Migration Strategies

Plan and execute migrations between Windows Server versions.

Approaches: In-place (same hardware) · Side-by-side (new server, migrate roles) · Swing (temp server during transition) · Cluster Rolling (one node at a time).

Tools: Windows Server Migration Tools · Storage Migration Service · ADMT (AD) · USMT (User State).

Checklist: inventory roles · verify compat · full backup · test in lab · plan rollback.

Storage Migration Service (1/2) — Phases

The Storage Migration Service (SMS) moves file servers between hosts while preserving SMB share identity, NTFS permissions, and even the source server's name/IP at cutover. Four-phase workflow.

Four phases

  • Inventory — scan source servers for shares, data, and ACLs
  • Transfer — copy data and permissions to destination
  • Cutover — swap identities (name/IP) seamlessly to the new host
  • Validate — verify shares, permissions, and clients still resolve

Storage Migration Service (2/2) — Job Lifecycle

SMS is PowerShell-driven: install proxy, create job, run three phases.

PS> Install-WindowsFeature SMS-Proxy ; New-SmsJob -Name "FS-Mig" Add-SmsSourceComputer -Name "FS-Mig" -ComputerName FS-OLD Set-SmsDestinationComputer -Name "FS-Mig" -ComputerName FS-NEW Start-SmsInventory "FS-Mig" ; Start-SmsTransfer "FS-Mig" ; Start-SmsCutover "FS-Mig"
