A Microsoft 365 tenant is the foundational container for your organization's cloud identity and services. This chapter covers provisioning a tenant, verifying custom domains with DNS records, configuring organizational settings, navigating the admin center, and monitoring service health through the Message Center.

What is a Microsoft 365 Tenant?
A dedicated instance of Microsoft Entra ID and Microsoft 365 services tied to your organization.
Tenant ID
Every tenant receives a globally unique GUID. This ID is permanent and used in API calls, Conditional Access policies, and cross-tenant configurations. You cannot change it after creation.
Default Domain
The .onmicrosoft.com domain is auto-provisioned and cannot be removed. It serves as the fallback domain for user sign-in and routing if custom domains are removed or misconfigured.
Data Residency
The geographic region you select at tenant creation determines where your data at rest is stored. Core workloads (Exchange, SharePoint, Teams) honor this region. Multi-Geo add-ons allow satellite locations.
Slide 3 of 12
Microsoft 365 Admin Center
The central management portal at admin.microsoft.com for tenant-wide administration.
Left Navigation
The admin center sidebar groups management into: Users, Groups, Roles, Resources, Billing, Settings, Health, and Reports. The Show All link reveals specialty admin centers for Exchange, SharePoint, Teams, Security, and Compliance.
Delegated Admin Roles
The Global Administrator role has full access but should be limited to 2-4 accounts. Use least-privilege roles: User Administrator for account management, Exchange Administrator for mail, SharePoint Administrator for sites. All assignable in the Roles section.
Home Dashboard
The admin center home page shows active user counts, service health status, Message Center posts, and recommended tasks. Admins can customize dashboard cards to surface the metrics most relevant to their organization.
Search + Quick Actions
The top search bar finds users, groups, settings, and documentation. Quick actions include resetting passwords, adding users, and managing licenses. Keyboard shortcut: press / to focus the search bar.

Adding Custom Domains
Replace contoso.onmicrosoft.com with your organization's domain for professional branding and email routing.
Custom domain verification proves you own the domain. Microsoft generates a unique TXT value (e.g., MS=ms12345678) that you add as a DNS record at your registrar. Once Microsoft detects the record, the domain is verified and you can configure mail routing (MX), autodiscovery (CNAME), and email authentication (SPF/DKIM/DMARC).
Exam Tip
A domain can only be verified in one M365 tenant at a time. If a domain is already verified in another tenant, you must remove it there first. The .onmicrosoft.com default domain cannot be removed or changed after tenant creation.
Slide 5 of 12
DNS Records for Microsoft 365
Each M365 service requires specific DNS records to function correctly.
TXT (Verification)
Proves domain ownership. Value: MS=ms12345678. Added at the root of your domain in your DNS registrar. Required before any other records.
MX (Mail Exchange)
Routes inbound email to Exchange Online. Points to contoso-com.mail.protection.outlook.com. Priority 0. Without this, email does not flow.
CNAME (Autodiscover)
Enables Outlook auto-configuration. autodiscover points to autodiscover.outlook.com. Required for desktop Outlook to find mailbox settings.
TXT (SPF)
Sender Policy Framework. Value: v=spf1 include:spf.protection.outlook.com -all. Tells receiving servers which IPs can send email for your domain.
CNAME (DKIM)
DomainKeys Identified Mail. Two CNAME records (selector1, selector2) point to selector1-contoso-com._domainkey.contoso.onmicrosoft.com. Cryptographically signs outbound email.
TXT (DMARC)
Domain-based Message Authentication. _dmarc TXT record sets policy (none, quarantine, reject) for messages that fail SPF or DKIM. Recommended: start with p=quarantine.
Common Pitfall
If your registrar manages DNS, M365 can auto-configure records. If DNS is hosted elsewhere (e.g., Cloudflare, Route 53), you must manually add each record. Exam scenarios test whether you can identify the correct record type for a given symptom (no email = MX, Outlook cannot connect = CNAME autodiscover).

Organizational Profile
Settings > Org settings > Organization profile -- defines your tenant's identity and contact information.
Organization Name
The display name that appears in the admin center, email headers, and billing. Set during signup but changeable later in Settings > Org settings > Organization information.
Technical Contact
Email address that receives service notifications and technical communications from Microsoft. Should be a monitored shared mailbox or distribution group, not an individual's personal email.
Address + Phone
Physical address and phone number tied to your tenant. Used for billing verification, support requests, and compliance documentation. Must match your billing profile for license purchases.
Custom Theme + Branding
Customize the M365 portal with your organization's logo, colors, and navigation bar. Set at Settings > Org settings > Organization profile > Custom themes. Users see branded sign-in pages and the M365 app launcher.
Data Location (Geo)
The Organization profile displays where your tenant's core data is stored (e.g., United States, European Union). Set at creation and applies to Exchange, SharePoint, and Teams. Multi-Geo requires separate licensing for satellite regions.
Slide 7 of 12
Organizational Settings
Tenant-wide toggles that control how services behave for all users.
Services Tab
Controls per-service settings: Microsoft Teams (guest access, meeting policies), SharePoint (external sharing), Office installation options (update channels), and Viva Insights (data analysis opt-in). Each setting applies tenant-wide by default.
Security + Privacy Tab
Password expiration policy (default: no expiration for cloud-only), customer lockbox (approval for Microsoft support access), idle session timeout, and self-service password reset. Critical security controls for MS-102.
User Consent to Apps
Controls whether users can grant third-party apps permissions to access M365 data. Options: allow all, allow verified publishers only, or require admin approval for all apps. High-risk setting -- exam frequently tests this.
Modern Authentication
Security defaults enable MFA for all users and block legacy authentication protocols (POP, IMAP basic auth). Enabled by default on new tenants. Disable only when implementing custom Conditional Access policies.
Exam Alert
If a scenario describes users receiving unwanted consent prompts from third-party apps, the answer involves restricting user consent in Org settings > User consent to apps. This is a top-tested MS-102 concept.
Slide 8 of 12
Service Health Dashboard
Health > Service health in the admin center -- real-time status of all Microsoft 365 services.
Overview Page
Shows all M365 services with their current status. Drill into any service to see active issues, issue history (last 30 days), and planned maintenance windows. Filterable by service and date range.
Issue Details
Each incident includes: a classification (advisory, incident, or extended incident), user impact assessment, current status (investigating, restoring, resolved), root cause, and estimated time to resolution.
Planned Maintenance
Microsoft posts planned maintenance windows in advance. Admins receive notifications 7 days before major changes. Planned maintenance appears on the Message Center, not the service health page, unless it causes downtime.
Slide 9 of 12
Message Center
Health > Message center -- the primary channel for Microsoft communicating upcoming changes to your tenant.
Change Communications
Every new feature, deprecation, or policy change is posted here before it takes effect. Posts include a description, timeline, what admins need to do, and a unique Message Center ID (MC######). This is how you stay ahead of changes.
Filtering + Preferences
Filter by service (Exchange, Teams, SharePoint), category (Plan for Change, Stay Informed, Prevent or Fix Issues), or tag. Set email preferences to receive a weekly digest of new Message Center posts to a distribution group.
Action Required vs. Informational
Posts tagged "Plan for Change" or "Prevent or Fix Issues" often require admin action before a deadline. "Stay Informed" posts are awareness-only. Exam scenarios test whether you can determine the correct response to a Message Center post.
You receive a Message Center post stating that Basic Authentication for Exchange Online will be disabled in 30 days. The post is tagged "Prevent or Fix Issues." Your action: audit all apps and scripts using basic auth, migrate them to OAuth 2.0 / Modern Authentication, and test before the deadline. This is a classic MS-102 exam scenario.
Slide 10 of 12
Release Preferences
Settings > Org settings > Release preferences -- control when your tenant receives new Microsoft 365 features.
Targeted Release -- Everyone
The entire tenant receives new features as soon as they enter targeted release. Best for small organizations or dev/test tenants where all users are comfortable with early access. Not recommended for production tenants with non-technical users.
Targeted Release -- Selected Users
Only specified users (typically IT admins and champions) receive new features early. The rest of the tenant stays on standard release. This is the recommended approach -- it allows testing without impacting the broader organization.
Key Distinction
Release preferences control M365 web service features (admin center, Teams web, SharePoint Online). They do not control desktop Office app update channels. Desktop app updates are managed separately through Microsoft 365 Apps update channels (Current Channel, Monthly Enterprise, Semi-Annual Enterprise).
Slide 11 of 12
Tenant Lifecycle Management
Ongoing administration tasks that keep a production tenant healthy and secure.
License Management
Monitor purchased vs. consumed licenses at Billing > Licenses. Unassigned licenses still incur cost. Use group-based licensing in Microsoft Entra ID to auto-assign licenses when users join security groups.
Admin Role Reviews
Regularly audit who holds Global Admin and other privileged roles. Enable Privileged Identity Management (PIM) for just-in-time role activation. MS-102 emphasizes the principle of least privilege across all admin tasks.
Subscription Renewal
Monitor subscription expiry dates at Billing > Your products. Expired subscriptions enter a 30-day grace period, then 90-day disabled state, then permanent deletion. Users lose access to services during the disabled state.
Tenant Deprovisioning
Deleting a tenant requires canceling all subscriptions, removing all custom domains, and deleting all users except the Global Admin. Microsoft Entra ID retains the tenant for 30 days in a soft-deleted state. Recovery is possible during this window.
Support Requests
Create support tickets at Support > New service request. Include service health incident IDs when relevant. Premier/Unified support customers have faster SLAs. All tickets require at minimum a Service Administrator role.

Chapter 1 Summary
Key concepts for Deploy and Manage a Microsoft 365 Tenant
1Tenant fundamentals: A tenant is a dedicated M365 instance with a unique GUID, a default .onmicrosoft.com domain, and a geo-locked data residency region set at creation.
2Admin center: admin.microsoft.com is the central portal. Satellite centers (Entra, Exchange, SharePoint, Teams) handle workload-specific tasks. Use least-privilege admin roles.
3Custom domains: Add at Settings > Domains. Verify with a TXT record. Configure MX for mail routing, CNAME for autodiscover, and SPF/DKIM/DMARC for email authentication.
4Org settings: Organization profile (name, address, branding), service toggles (Teams guest access, SharePoint sharing), security (password policy, customer lockbox), and user consent to third-party apps.
5Service health + Message Center: Service health shows real-time status (operational, advisory, incident). Message Center communicates upcoming changes with action items and deadlines.
6Release preferences: Targeted release (for selected users or everyone) delivers features early. Standard release is the default. This only controls web service features, not desktop app update channels.
