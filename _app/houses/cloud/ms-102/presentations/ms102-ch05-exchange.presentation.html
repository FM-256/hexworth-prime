Exchange Online Mailbox Types
Every recipient in Exchange Online has a mailbox type that determines licensing, access, and functionality.
User Mailbox
Assigned to individual users with a license. Default 50 GB storage (100 GB with E3/E5). Supports rules, delegates, mobile access, and archive mailboxes. One user = one mailbox = one license.
Shared Mailbox
No license required (up to 50 GB). Multiple users access via delegate permissions (Full Access, Send As, Send on Behalf). No direct sign-in. Common for team inboxes like info@ or support@. Auto-grows to 50 GB; archive requires a license.
Resource Mailbox
Two subtypes: Room mailbox (conference rooms) and Equipment mailbox (projectors, vehicles). No license required. Automatically accept or decline meeting requests based on scheduling policies. Managed via booking delegates or auto-accept rules.
Exam Alert
Shared mailboxes do NOT require a license unless they exceed 50 GB or need an archive/litigation hold. Converting a user mailbox to shared releases the license. Converting shared to user requires assigning a license. This is one of the most commonly tested Exchange Online concepts on the MS-102 exam.

Mail Flow Rules (Transport Rules)
Conditions, actions, and exceptions that process messages as they flow through the Exchange Online transport pipeline.
Conditions
Evaluate message properties: sender/recipient address, subject keywords, attachment types, header values, message size, sender domain, internal vs. external, sensitivity labels. A rule fires only when all conditions are met.
Actions
What happens when conditions match: add disclaimer/header, redirect to manager, BCC compliance mailbox, moderate message, reject with NDR, encrypt with OME, prepend subject, apply rights template, route through connector.
Exceptions
Override conditions for specific cases: except if sender is in group X, except if subject contains "confidential override," except if message is digitally signed. Exceptions take priority over conditions.
Your compliance team requires a legal disclaimer appended to all external emails except those sent by the Legal department. Create a mail flow rule with condition "recipient is external," action "append disclaimer," and exception "sender is member of Legal group." This three-part structure (condition + action + exception) is the pattern tested on the exam.

Mail Flow Connectors
Connectors control how mail flows between Exchange Online and external mail systems or on-premises Exchange servers.
Inbound Connector (Partner/On-Premises to M365)
Validates the sender by IP address or TLS certificate. Use for mail from on-premises Exchange (hybrid) or trusted partner organizations. Ensures messages bypass spam filtering when from a known source. Required for hybrid mail flow.
Outbound Connector (M365 to Partner/On-Premises)
Routes mail to specific domains through a designated smart host or partner server. Use TLS enforcement and certificate validation to secure the connection. Required when routing mail through on-premises servers for compliance scanning or archival.

Anti-Spam Policies
Exchange Online Protection (EOP) evaluates every inbound message through multiple spam filtering layers.
Connection Filter
First layer: evaluates the sending server IP address. IP Allow List bypasses spam filtering for trusted senders. IP Block List rejects mail at the connection level. Configured at the organization level, not per-user. Uses the default connection filter policy.
Inbound Anti-Spam
Evaluates message content: Spam Confidence Level (SCL) scoring, bulk complaint level (BCL), phishing detection, sender reputation. Actions per SCL threshold: move to Junk, quarantine, delete, add X-header. Custom policies can target specific groups.
Outbound Anti-Spam
Monitors outbound messages from your tenant to prevent your domain from being blocklisted. Rate limits per user (default: 10,000 recipients/day external). Actions when exceeded: restrict user, alert admin. Compromised account sends trigger outbound spam alerts.
Key Concept
The Spam Confidence Level (SCL) is a score from 0-9 assigned to each inbound message. SCL 5-6 = spam (move to Junk). SCL 7-9 = high-confidence spam (quarantine or delete). SCL -1 = safe sender/allowed. Anti-spam policies define the action for each threshold. The default policy applies to all recipients; custom policies override the default for targeted groups.

Anti-Malware Policies
EOP scans all messages for malware using multiple engines, zero-hour auto purge, and common attachment filtering.
Malware Detection
Multiple anti-malware engines scan every attachment in real time. Zero-hour Auto Purge (ZAP) retroactively removes messages from mailboxes when a previously unknown attachment is later identified as malicious. Quarantine action replaces the attachment with a notification text file.
Common Attachment Filter
Blocks file types by extension (e.g., .exe, .bat, .vbs, .js, .scr). Enabled in the anti-malware policy with a predefined list. Action: reject the message (NDR), quarantine, or remove the attachment. Protects against executable payloads even if the malware signature is unknown.
Admin Notifications
Configure notifications to internal or external senders when their message is quarantined. Optionally notify an admin (security team DL) for all malware detections. Notifications help legitimate senders re-send clean files and alert security of active threats.
Safe Attachments (Defender)
Microsoft Defender for Office 365 adds sandboxed detonation: attachments are opened in a virtual environment to detect zero-day malware that signature-based engines miss. Requires Defender for Office 365 Plan 1 or Plan 2 licensing (not included in base EOP).

Quarantine Management
Quarantine holds messages that triggered spam, phishing, malware, or mail flow rule actions for admin or user review.
Quarantine Policies
Define what users can do with quarantined messages: view only, release, delete, report false positive. Policies are assigned per protection feature (spam, phishing, malware). AdminOnlyAccessPolicy restricts all actions to admins. DefaultFullAccessPolicy lets users release their own quarantined mail.
Quarantine Notifications
End-user spam notifications (quarantine notifications) send periodic digests to users listing their quarantined messages. Users can review and release directly from the notification email. Frequency is configurable (default: every 3 days). Requires the quarantine policy to allow user access.
Admin Review + Release
Admins access quarantine at security.microsoft.com > Email & collaboration > Review > Quarantine. Filter by reason (spam, phish, malware), recipient, sender, or date. Release to recipient, release and report false positive, or permanently delete. Malware quarantine is admin-only by default.
A user reports missing an expected email from a partner. You check quarantine and find the message was flagged as high-confidence phishing. After verifying the sender is legitimate, you release the message and add the sender domain to the allowed senders list in the anti-spam policy. You then submit the message to Microsoft as a false positive for filter improvement.

Public Folders
Legacy shared content repositories hosted in Exchange Online for organizational-wide access to mail, calendars, and contacts.
Public Folder Mailboxes
Content is stored in special public folder mailboxes (not user mailboxes). One primary hierarchy mailbox contains the folder tree structure. Secondary mailboxes hold content and serve read-only copies of the hierarchy for load distribution.
Permissions
Granular permission levels: Owner, Publishing Editor, Editor, Publishing Author, Author, Contributor, Reviewer, None. Assigned per folder. Mail-enabled public folders can receive external email with their own SMTP address. Permissions are managed via EAC or PowerShell.
Migration from On-Premises
Batch migration moves public folders from on-premises Exchange to Exchange Online. Steps: create CSV mapping file, create migration endpoint, start migration batch, validate, complete (cutover). Users see no interruption after the final cutover and DNS update.
Modern Alternative
Microsoft recommends Microsoft 365 Groups and SharePoint team sites as modern replacements for public folders. Groups provide a shared mailbox, calendar, file library, Planner, and OneNote. Public folders remain supported for backward compatibility but receive limited new investment. Exam scenarios may ask you to recommend the appropriate solution based on requirements.

Mailbox Migration Methods
Three primary methods to migrate mailboxes from on-premises Exchange to Exchange Online.
Cutover Migration
Moves ALL mailboxes at once in a single batch. Best for small organizations (fewer than 150 mailboxes) running Exchange 2003 or later. All mailboxes, contacts, and distribution groups migrate together. MX record changes to point to Exchange Online after migration completes.
Staged Migration
Moves mailboxes in batches over weeks or months using CSV files to define each batch. Requires Exchange 2003 or 2007 with directory synchronization (DirSync/Entra Connect). Users are migrated in groups based on department, location, or priority. Coexistence during migration.
Hybrid Migration
Full coexistence between on-premises Exchange and Exchange Online. Requires Exchange 2010 or later with Entra Connect and the Hybrid Configuration Wizard. Supports move requests in either direction. Shared namespace, free/busy, cross-premises mail flow. Long-term or permanent coexistence.
Exam Decision Tree
Fewer than 150 mailboxes + Exchange 2003+? Cutover. Exchange 2003/2007 + need batches? Staged. Exchange 2010+ + long-term coexistence or bi-directional moves? Hybrid. The exam tests your ability to select the correct migration method based on Exchange version, mailbox count, and coexistence requirements.

Hybrid Configuration
The Hybrid Configuration Wizard automates the setup of coexistence between on-premises Exchange and Exchange Online.
HCW
Hybrid Configuration Wizard creates send/receive connectors, configures OAuth, and sets up the shared namespace between on-premises and cloud.
Free/Busy
Cross-premises calendar availability. On-premises users see cloud users' free/busy and vice versa. Requires OAuth or federation trust.
Mail Routing
Centralized or decentralized. Centralized: all inbound mail routes through on-premises first. Decentralized: MX points directly to Exchange Online.
Move Requests
Onboarding (on-prem to cloud) and offboarding (cloud to on-prem) migration batches. Users retain their email address and Outlook profile.
Entra Connect
Required for hybrid. Syncs user objects so mailboxes appear in both directories. Exchange hybrid attributes (mailNickname, proxyAddresses) must sync.
Edge Transport
Optional: Edge Transport server in the DMZ handles inbound/outbound mail flow between the internet and on-premises Exchange. Adds a layer of protection.

Exchange Online Administration
Day-to-day management tasks and tools for Exchange Online.
Exchange Admin Center (EAC)
Web portal at admin.exchange.microsoft.com. Manage mailboxes, groups, mail flow rules, connectors, and migration batches. The new EAC replaces the classic EAC and adds a modern interface with improved search and bulk operations.
Exchange Online PowerShell
Connect-ExchangeOnline module for automation and bulk operations. Required for tasks not available in EAC: message tracking, detailed mailbox statistics, advanced transport rule conditions, and programmatic management of thousands of objects.
Recipient Management
Create and manage mailboxes, distribution lists, dynamic distribution groups, mail contacts (external), and mail users (external with credentials). Assign mailbox permissions (Full Access, Send As, Send on Behalf) per recipient.
Message Trace
Track message delivery through the transport pipeline. Filter by sender, recipient, date range, subject, and status. Shows each hop: received, delivered, failed, quarantined, expanded (DL). Essential for troubleshooting delivery issues. Results available for up to 90 days.
Accepted Domains
Authoritative: Exchange Online is the only mail system for this domain (all recipients must exist). Internal Relay: Exchange Online accepts mail but forwards unknown recipients to on-premises. External Relay: forwards to an external mail system. Type determines how unresolvable recipients are handled.

Chapter 5 Summary
Key concepts for Manage Exchange Online
1Mailbox types: User mailboxes require a license. Shared mailboxes (up to 50 GB) and resource mailboxes (room/equipment) do not. Converting between types changes licensing requirements.
2Mail flow rules: Transport rules use conditions + actions + exceptions. Common uses: disclaimers, BCC compliance, encryption, message routing. Rules are processed in priority order.
3Connectors: Inbound connectors validate mail from on-premises/partners (by IP or certificate). Outbound connectors route mail to specific destinations with TLS enforcement.
4Anti-spam: Three layers -- connection filter (IP), inbound anti-spam (SCL scoring), outbound anti-spam (rate limiting). Custom policies override the default for targeted groups.
5Quarantine: Policies control user vs. admin access. Notifications send periodic digests. Malware quarantine is admin-only by default. Release, delete, or report false positives.
6Migration: Cutover (all at once, <150 mailboxes). Staged (batched, Exchange 2003/2007). Hybrid (full coexistence, Exchange 2010+, bidirectional moves, HCW required).
