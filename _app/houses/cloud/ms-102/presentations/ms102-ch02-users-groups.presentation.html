Creating and Managing User Accounts
User accounts are identity objects in Microsoft Entra ID that grant access to M365 services.
User Principal Name (UPN)
The UPN is the user's sign-in name in email format (e.g., jsmith@contoso.com). It must be unique within the tenant. The domain portion must be a verified domain. Changing the UPN changes the sign-in address but not the underlying Object ID.
Usage Location
A two-letter country code (e.g., US) that determines which M365 services are available to the user based on regional regulations. Required before a license can be assigned. Users without a usage location cannot receive licenses.
Block Sign-in
Disabling sign-in prevents the user from authenticating without deleting the account. Use this for employees on leave or during security investigations. Existing sessions are revoked within 60 minutes. The account, mailbox, and data remain intact.

Modify and Delete Users
Editing user properties and understanding the soft-delete recovery window.
Soft Delete (30-Day Window)
When you delete a user, the account moves to the Deleted Users container in the M365 admin center. For 30 days, you can restore the user with all properties, group memberships, and mailbox data intact. After 30 days, the account is permanently purged and cannot be recovered.
Restoring a Deleted User
Navigate to Users > Deleted users in the admin center, select the account, and click Restore. If the original UPN is taken, you must assign a new one. The license must be re-assigned manually after restoration. Group memberships are preserved.
Exam Tip
When a user is deleted, their license is released immediately and can be reassigned to another user. However, the mailbox enters an inactive state and is retained for 30 days by default. OneDrive data follows the retention policy set in the SharePoint admin center (default: 30 days after account deletion).

Bulk User Operations
Use CSV files to create, modify, or delete users at scale from the M365 admin center.
Bulk Create
Upload a CSV with required columns: User name, First name, Last name, Display name. Each user receives a temporary password. Download the CSV template from the admin center to ensure correct column headers.
Bulk Delete
Upload a CSV containing UPNs of users to delete. All listed accounts move to the soft-deleted state with the standard 30-day recovery window. Useful for offboarding entire departments or class cohorts at once.
PowerShell Alternative
For advanced bulk operations, use Import-Csv piped to New-MgUser (Microsoft Graph PowerShell). This allows setting properties not available in the CSV template, such as custom attributes, manager, and password policies.
Exam Tip
The M365 admin center bulk operations support four actions: bulk create, bulk delete, bulk invite (guest users), and bulk download (export user list). Each uses a specific CSV template. Licenses are NOT assigned during bulk create -- they must be assigned separately after user creation.

Guest Users and B2B Collaboration
Microsoft Entra B2B lets external users access your M365 resources using their own identity.
What is B2B?
Business-to-Business collaboration allows you to invite external users (partners, vendors, contractors) as guest accounts. They sign in with their own organizational or personal credentials -- no separate password to manage.
Invitation Flow
Invite via admin center, Teams, SharePoint, or PowerShell. The guest receives an email with a redemption link. After accepting, they appear in your directory as UserType: Guest.
Guest Permissions
By default, guests have limited directory access. They can participate in Teams channels, access shared files, and use assigned apps. Permissions are controlled by external collaboration settings and Conditional Access policies.
External Collaboration Settings
Control who can invite guests: only admins, members + admins, or anyone including guests. Restrict invitations to specific domains using allow/deny lists. Found at Entra ID > External Identities.
Guest Licensing
Guests do not consume a paid license for basic collaboration (Teams, SharePoint, OneDrive sharing). However, if you assign a premium feature (e.g., Power BI Pro), a license is consumed from your tenant pool.
Bulk Invite
Use the admin center bulk invite feature to send invitations via CSV. Required columns: Email address and Redirect URL. PowerShell alternative: New-MgInvitation.
Common Pitfall
Guest users count toward the 50,000-object limit in Microsoft Entra ID Free tier. In Entra ID P1/P2 tenants, there is no hard object limit, but excessive guest accounts without access reviews create security risks. Implement regular guest access reviews using Entra ID Governance.

Microsoft 365 Group Types
Four group types serve different purposes -- choosing the right type is critical for the MS-102 exam.
Microsoft 365 Groups
A collaboration group that provisions a shared mailbox, SharePoint site, OneNote notebook, Planner board, and Teams workspace. Members can be internal users or guests. Supports dynamic or assigned membership. This is the recommended group for collaboration workloads.
Security Groups
Used to control access to resources: SharePoint sites, apps, Conditional Access policies, and license assignment. No shared mailbox or collaboration tools. Supports dynamic or assigned membership. Members: users, devices, other groups, or service principals.
Distribution Groups
Email-only groups for sending messages to a collection of recipients. No access control capabilities. Managed in Exchange admin center. Cannot use dynamic membership. Being gradually replaced by M365 Groups which can also receive email.
Mail-Enabled Security Groups
Combines security group access control with a distribution list email address. Use when you need both email delivery AND permission assignment to the same set of users. Cannot use dynamic membership. Managed in Exchange admin center.
Quick Comparison
Need collaboration (Teams, SharePoint)? M365 Group. Need access control only? Security Group. Need email-only distribution? Distribution Group. Need email + access control? Mail-Enabled Security Group. Only M365 Groups and Security Groups support dynamic membership.

Dynamic Membership Rules
Automatically add or remove members based on user or device attribute expressions.
Instead of manually managing group membership, dynamic groups use rules that evaluate user attributes (department, job title, usage location, etc.) or device attributes (OS, compliance state). When a user's attributes change, they are automatically added to or removed from matching dynamic groups.
Rule Syntax
Rules use the expression format: (user.department -eq "Sales"). Combine with -and, -or, -not. Complex example: (user.department -eq "Sales") -and (user.country -eq "US"). The rule builder in Entra ID provides a visual editor.
Supported Attributes
User attributes: department, jobTitle, usageLocation, companyName, userType (Member/Guest), and 15+ extension attributes. Device attributes: deviceOSType, deviceOwnership, enrollmentProfileName.
Processing Delay
Dynamic membership changes are not instant. After an attribute update, the rule re-evaluates during the next processing cycle -- typically within minutes but can take up to 24 hours for large tenants. There is no manual refresh option in the portal.
Exam Tip
Dynamic groups require Microsoft Entra ID P1 or P2 licensing. They are available for M365 Groups and Security Groups only -- not Distribution Groups or Mail-Enabled Security Groups. You cannot manually add or remove members from a dynamic group; membership is entirely rule-driven.

Self-Service Group Management
Delegate group creation and membership management to end users while maintaining admin oversight.
Group Creation Policy
By default, all users can create M365 Groups (which creates Teams, SharePoint sites, etc.). To prevent sprawl, restrict creation to a security group of approved users via Entra ID > Groups > General > Self-service group management. This requires Entra ID P1.
Naming Policies
Enforce consistent naming with prefix/suffix policies. Example: GRP_[GroupName]_[Department]. Block custom words (profanity, reserved names). Configured in Entra ID > Groups > Naming policy. Requires Entra ID P1.
Expiration Policies
M365 Groups can be set to expire after 180, 365, or a custom number of days. Owners receive renewal notifications 30 days, 15 days, and 1 day before expiry. Unrenewed groups are soft-deleted (30-day recovery). Configured at Entra ID > Groups > Expiration.
Owner vs. Member
Group owners can add/remove members, approve join requests, edit group settings, and renew expiring groups. Members have access to group resources but cannot manage membership. Every group should have at least two owners for continuity.
Exam Tip
Restricting M365 Group creation does NOT prevent users from creating Security Groups or Distribution Groups in Outlook. The restriction applies only to M365 Groups (Teams, SharePoint, Planner). This distinction is frequently tested on the MS-102 exam.

License Assignment
Two methods: direct assignment per user, or group-based licensing for automatic assignment.
Group-Based Licensing
Assign a license (e.g., M365 E5) to a Security Group or M365 Group. All members automatically receive the license. When a user is removed from the group, the license is reclaimed. Works with dynamic groups for fully automated license management.
Service Plan Toggle
Each M365 license contains multiple service plans (Exchange, Teams, SharePoint, etc.). Both direct and group-based assignment let you enable or disable individual service plans. Example: assign M365 E5 but disable Power BI Pro for a specific group.
License Conflicts
If a user inherits conflicting licenses from multiple groups (e.g., E3 from Group A and E5 from Group B), the conflict is flagged in the admin center. The License assignment errors blade shows which users have conflicts and which service plans overlap.
Exam Tip
Usage location is required before any license can be assigned -- whether direct or group-based. If a user in a licensed group has no usage location, the license assignment fails silently for that user. Check Entra ID > Groups > [Group] > Licenses > Assignment errors for failures.

Microsoft 365 Groups Deep Dive
One group object that provisions multiple collaboration workloads simultaneously.
Shared Mailbox
Every M365 Group gets a shared Exchange mailbox. Members can send/receive as the group. The address is groupname@contoso.com. Emails are stored centrally, not in individual mailboxes.
SharePoint Site
A team site is auto-provisioned with a document library, pages, and lists. Group members have Edit access by default. The site URL follows the pattern: contoso.sharepoint.com/sites/groupname.
Teams Workspace
When Teams is added, the M365 Group becomes the Teams backend. Channels, chats, meetings, and file storage all connect to the same group membership. Removing a Team does not delete the M365 Group.
Planner Board
A Planner plan is available to group members for task management. Tasks can be assigned, categorized with labels, and tracked with charts. The plan is accessible from Teams, Outlook, and the Planner web app.
OneNote Notebook
A shared notebook is created for the group. Useful for meeting notes, shared references, and project documentation. Accessible through the group in Outlook, Teams, or directly via OneNote.
Guest Access
External users can be added as group members. Guest access must be enabled at the tenant level (Entra ID > External Identities) and at the group level. Guests see the group in their own tenant's guest list.

Administration Best Practices
Key strategies for managing users and groups at enterprise scale.
Least-Privilege Roles
Use User Administrator for creating and managing users and groups (not Global Admin). Use Groups Administrator for group-only management. Use License Administrator for license assignment. Reserve Global Admin for tenant-level operations.
Access Reviews
Schedule regular access reviews for guest users and group memberships. Entra ID Governance (P2) automates this: reviewers confirm or deny continued access, and stale accounts are auto-removed. Critical for compliance (SOC 2, HIPAA, CMMC).
Administrative Units
Scope admin permissions to a subset of users. Example: a regional IT admin can manage only users in the "UK" administrative unit. Supported roles: User Administrator, Groups Administrator, Helpdesk Administrator, and more. Requires Entra ID P1.
Monitoring and Alerts
Enable audit logging for user and group changes in the M365 Compliance center. Set up alerts for bulk deletions, privileged role assignments, and guest invitation surges. Integrate with Microsoft Sentinel for advanced SIEM capabilities.
Hybrid Considerations
Organizations with on-premises Active Directory use Microsoft Entra Connect to sync users and groups. Synced objects are managed on-premises -- changes in the admin center are overwritten on the next sync cycle. Cloud-only attributes (e.g., licenses) are managed in Entra ID.
Password Policies
Cloud-only users follow the tenant password policy (default: never expire per Microsoft recommendation). Enforce strong passwords via banned password lists and Smart Lockout. Synced users follow on-premises AD password policies unless Password Writeback is enabled.

Chapter 2 Summary
Key concepts for Manage Users and Groups
1User accounts: Created in Microsoft Entra ID with a UPN, display name, and usage location. Usage location is required before license assignment. Block sign-in disables access without deleting the account.
2Soft delete: Deleted users move to a recycle bin with a 30-day recovery window. Licenses are released immediately. After 30 days, accounts are permanently purged and irrecoverable.
3Bulk operations: CSV import via admin center supports bulk create, delete, and invite. Max 50,000 users per CSV. Licenses must be assigned separately after bulk creation.
4Guest users (B2B): External users sign in with their own credentials. Controlled by external collaboration settings in Entra ID. Basic collaboration does not consume a paid license.
5Group types: M365 Groups (collaboration), Security Groups (access control), Distribution Groups (email only), Mail-Enabled Security Groups (email + access). Dynamic membership requires Entra ID P1 and is only for M365 and Security groups.
6License assignment: Direct (per user) or group-based (via Security/M365 Group). Group-based licensing requires Entra ID P1. Usage location must be set or assignment fails silently.
