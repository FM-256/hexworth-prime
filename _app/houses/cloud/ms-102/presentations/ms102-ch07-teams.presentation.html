Manage Microsoft Teams
Policies  •  Guest Access  •  Channels  •  App Management  •  Voice  •  Compliance
Microsoft Teams is the collaboration hub of Microsoft 365, combining chat, meetings, calling, and apps. This chapter covers Teams policies (messaging, meeting, calling, app setup/permission), guest access configuration, team creation patterns, channel types, app management, voice features (Phone System, calling plans, auto attendants, call queues), the Teams admin center, and compliance capabilities including retention, DLP, and eDiscovery for Teams data.

Teams Policy Types
Policies control what users can do in Teams. Each policy type governs a specific feature area.
Messaging Policies
Control chat features: edit/delete sent messages, read receipts, chat permissions, Giphy and meme usage, URL previews, and message translation. Assigned per-user or per-group.
Meeting Policies
Control meeting behavior: who can bypass the lobby, recording permissions, transcription, screen sharing, participant limits, and whether anonymous users can join. Separate policies for organizers and attendees.
Calling Policies
Control calling features: call forwarding, simultaneous ring, voicemail, call delegation, inbound call routing, and busy-on-busy handling. Only applies to users with Phone System licenses.
App Setup Policies
Control which apps are pinned to the Teams sidebar and the order they appear. Pin custom LOB apps, remove default apps, or enforce a standard app layout across the organization.
App Permission Policies
Control which apps users can install: allow all, block all, or allow/block specific apps by publisher (Microsoft, third-party, custom). Separate controls for each publisher category.
Teams Update Policy
Control which Teams client users receive: the new Teams client, classic Teams, or user choice. Manage the rollout of Teams client updates across the organization.
Exam Tip
Policies are applied in priority order: direct user assignment > group assignment > global (org-wide default). If a user has both a direct and group policy for the same type, the direct assignment wins. The global policy applies to all users who have no other assignment.

Guest Access Configuration
Guest access requires configuration at both the Entra ID level and the Teams admin center level.
Guest Access Configuration Steps
1Microsoft Entra ID -- External Collaboration Settings -- configure who can invite guests (everyone, members only, admins only, or no one). Set allowed/blocked guest domains. Found at Entra admin center > External Identities > External collaboration settings.
2Microsoft 365 Groups -- Guest Settings -- enable "Let group owners add people outside your organization to Microsoft 365 Groups as guests." Found at M365 admin center > Settings > Org settings > Microsoft 365 Groups.
3Teams Admin Center -- Guest Access -- toggle guest access on/off. Configure guest capabilities: calling, meeting, messaging. Found at Teams admin center > Users > Guest access.
4SharePoint -- External Sharing -- must allow at least "Existing guests" for guests to access files shared in Teams channels (files are stored in SharePoint).
Guest Capabilities
Guests can: participate in channel conversations, access shared files, join meetings, and be added to channels. Guests cannot: create teams, discover teams, see org charts, or access the Teams calendar unless explicitly invited to meetings.
Common Failure Points
Guest access fails if any layer is disabled. The most common mistake is enabling guest access in Teams but forgetting to enable it in Entra ID External Collaboration settings or M365 Groups. All four layers must be configured.

Team Creation and Templates
Control who can create teams and standardize team structure with templates.
Standard Teams
Created by any licensed user by default. Each team creates a connected M365 Group, SharePoint site, Exchange mailbox, and OneNote notebook. To restrict creation, use a Microsoft Entra ID security group -- only members of that group can create new teams/groups.
Org-Wide Teams
Automatically includes every user in the organization. Limited to tenants with 10,000 or fewer users. Maximum 5 org-wide teams. Only Global Admins can create them. Members are auto-added/removed as users join/leave the organization.
Team Templates
Pre-built team structures with predefined channels, apps, and settings. Microsoft provides templates (e.g., "Manage a Project," "Incident Response"). Admins can create custom templates in the Teams admin center to enforce organizational standards.
Restricting Team Creation
To restrict who can create M365 Groups (and therefore Teams), create a security group in Entra ID (e.g., "GroupCreators"), then use the Set-MgBetaDirectorySetting PowerShell cmdlet to set the GroupCreationAllowedGroupId to that group's object ID. This applies to Teams, Outlook groups, SharePoint team sites, Planner, and Yammer.

Channel Types: Standard, Private, Shared
Channels organize conversations and files within a team. Each type has different access and storage behavior.
Standard Channels
Visible to all team members. Files stored in the team's SharePoint site under a folder matching the channel name. Every team starts with a "General" channel that cannot be deleted. Members can create additional standard channels by default.
Private Channels
Only visible to channel members (a subset of the team). Creates a separate SharePoint site collection with its own permissions. Maximum 30 private channels per team. Team owners can see that private channels exist but cannot access content unless they are members.
Shared Channels
Can include people from outside the team and even outside the organization (via Entra ID B2B direct connect). Members access the shared channel without switching teams. Creates a separate SharePoint site. Maximum 200 shared channels per team. Requires Entra ID cross-tenant access settings for external sharing.
Exam Tip
Private and shared channels each get their own SharePoint site collection -- separate from the parent team site. This means storage quotas, permissions, and retention policies apply independently to each channel site. The General channel always uses the parent team's SharePoint site.

App Management
Control which apps are available, who can install them, and how they appear in the Teams client.
Org-Wide App Settings
Master toggle in Teams admin center > Teams apps > Manage apps > Org-wide app settings. Controls: allow third-party apps (on/off), allow custom apps (on/off), and whether users can request admin approval for blocked apps. This is the highest-level control.
Manage Apps (App Catalog)
Lists every app available in Teams (Microsoft, third-party, custom). Admins can block or allow individual apps. Blocked apps are invisible to all users regardless of their permission policy. Custom LOB apps are uploaded here.
App Permission Policies
Per-user policies controlling which app categories are allowed: Microsoft apps, third-party apps, custom apps. Each category can be set to "Allow all," "Block all," or "Allow/block specific apps." Layered on top of the app catalog.
Custom LOB Apps
Line-of-business apps built with Teams Toolkit, Power Apps, or the Teams platform SDK. Uploaded as .zip packages to the Manage Apps page. Must be explicitly allowed in both the app catalog and the user's app permission policy.
App Setup Policies
Control the Teams sidebar layout: pin specific apps, set pin order, and control whether users can upload custom apps. The "Global (Org-wide default)" setup policy applies to everyone unless overridden by a direct or group assignment.

Voice Features: Phone System
Teams Phone System enables PSTN calling, auto attendants, and call queues for enterprise telephony.
Teams Phone System
A cloud PBX that replaces traditional on-premises phone systems. Provides call control (hold, transfer, forward, park), voicemail, and PSTN connectivity. Requires a Teams Phone license (standalone or included in E5). Does not include PSTN minutes -- requires a separate calling plan or Direct Routing.
Calling Plans
Microsoft-provided PSTN connectivity. Three types: Domestic, International, and Pay-As-You-Go. Users receive a phone number directly from Microsoft. Simplest option but limited geographic availability. Alternative: Direct Routing connects Teams to your existing SBC/carrier.
Auto Attendants
Automated phone menu system ("Press 1 for Sales, 2 for Support"). Routes inbound calls based on caller input, time of day, or holidays. Supports nested menus, dial-by-name directory, and speech recognition. Configured in the Teams admin center > Voice > Auto attendants.
Call Queues
Routes inbound calls to a group of agents. Supports routing methods: attendant (ring all), serial, round robin, and longest idle. Configurable hold music, overflow handling (redirect after N minutes), and timeout actions. Agents can opt in/out of queues.
Common Pitfall
Phone System is the license/feature. Calling Plan is the PSTN connectivity method. Direct Routing is an alternative to Calling Plans that uses a Session Border Controller (SBC) to connect to your carrier. Operator Connect is a third option where the carrier manages the SBC. Exam questions test which component provides what capability.

Teams Admin Center
The central portal at admin.teams.microsoft.com for managing all Teams settings, policies, and users.
Users
View and manage individual user settings, policy assignments, and phone numbers. Search by user, edit policies directly, and view call quality data per user.
Teams / Groups
Manage existing teams: view channels, members, settings. Cannot create teams here -- teams are created by users or via PowerShell. Archive or delete teams. View team analytics.
Meetings
Configure meeting policies, meeting settings (anonymous join, PSTN dial-in), conference bridges, and meeting templates. Live events policies are also configured here.
Messaging Policies
Create and assign messaging policies. Control read receipts, chat, Giphy, memes, stickers, URL previews, code snippets, and message translation per-user or per-group.
Teams Apps
Manage apps (catalog), permission policies, setup policies, and org-wide app settings. Upload custom LOB apps. View app usage analytics.
Voice
Phone numbers, calling policies, call park policies, caller ID policies, auto attendants, call queues, and Direct Routing configuration. Requires Teams Phone license for most features.

Teams Compliance
Retention, DLP, and eDiscovery extend to Teams chat and channel messages.
Retention Policies
Applied via Microsoft Purview compliance portal. Separate policies for Teams channel messages and Teams chats. Retain messages for a set period (e.g., 7 years), delete after a period, or retain-then-delete. Messages are stored in a hidden folder in user/group mailboxes and preserved even if deleted by users.
DLP for Teams
Data Loss Prevention policies scan Teams chat and channel messages in real-time. Can detect sensitive data (credit card numbers, SSNs, custom patterns) and block the message, notify the sender, or alert compliance officers. Requires Microsoft 365 E5 or E5 Compliance add-on.
eDiscovery for Teams
Teams messages are searchable in Content Search and eDiscovery cases in the Purview compliance portal. Chat messages are stored in user mailboxes. Channel messages are stored in the group mailbox. Private channel messages are stored in individual user mailboxes. Results can be exported for legal review.
Communication Compliance
Detects inappropriate content, sensitive information, or regulatory violations in Teams messages. Uses trainable classifiers and keyword dictionaries. Generates alerts for compliance reviewers who can remediate (delete, notify, escalate).
Legal Hold
eDiscovery hold placed on user mailboxes preserves all Teams chat messages (including edited and deleted messages). For channel messages, place the hold on the M365 Group mailbox. Hold ensures data is immutable for litigation or investigation purposes.

Advanced Meeting Configuration
Meeting policies and settings control the full meeting experience across the organization.
Lobby Settings
Control who bypasses the lobby: everyone, people in the org, people in the org and trusted orgs, people who were invited, or only organizers. Critical for security -- prevents uninvited users from joining sensitive meetings. Set in meeting policies.
Recording and Transcription
Meeting recordings are saved to OneDrive (for non-channel meetings) or SharePoint (for channel meetings). Transcription provides real-time captions and a searchable transcript. Both can be enabled/disabled via meeting policies. Recordings expire after a configurable period (default: 120 days).
Audio Conferencing
Provides dial-in phone numbers for meetings so participants can join via PSTN. Requires an Audio Conferencing license. Conference bridge numbers are managed in the Teams admin center. Toll and toll-free numbers available. Default and per-user number assignment.
Meeting Templates and Sensitivity
Custom meeting templates enforce settings (recording, chat, lobby) for specific meeting types. Sensitivity labels can be applied to meetings to control features based on data classification. E.g., "Confidential" meetings disable recording and require lobby for external attendees.
Real-World Scenario
A healthcare organization creates a "Patient Consultation" meeting template that disables recording, requires lobby for all non-organizer participants, blocks anonymous join, and applies the "HIPAA Protected" sensitivity label. The template is assigned via a meeting policy to clinical staff.

MS-102 Exam Scenarios
Common exam question patterns for Microsoft Teams administration.
Scenario: Block Third-Party Apps
Block all third-party apps for the entire organization. Solution: go to Teams admin center > Teams apps > Manage apps > Org-wide app settings and toggle "Allow third-party apps" to Off. This overrides all permission policies.
Scenario: Guest Cannot Access Team
A guest was invited to a team but cannot access it. Troubleshoot in order: check Entra ID External Collaboration settings, M365 Groups guest settings, Teams guest access toggle, and SharePoint external sharing level. All four must be enabled.
Scenario: Restrict Team Creation
Only IT staff should create teams. Solution: create an Entra ID security group with IT members, then use PowerShell to set GroupCreationAllowedGroupId in directory settings. This blocks M365 Group creation for all non-members.
Scenario: Deploy Auto Attendant
Set up a main company phone number with "Press 1 for Sales." Solution: assign a service number, create an auto attendant with a greeting and menu options, create a call queue for Sales with agent routing, and link the auto attendant menu option to the Sales call queue.
Key Distinction
Teams policies are assigned to users, not teams. If a user has a messaging policy that disables Giphy, they cannot use Giphy in any team -- even if other team members can. Policies follow the user across all teams and channels they participate in.

Chapter 7 Summary
Key concepts for Manage Microsoft Teams
1Policies: Six policy types (messaging, meeting, calling, app setup, app permission, update) applied in priority order: direct user > group > global default.
2Guest access: Four layers must all be enabled -- Entra ID external collaboration, M365 Groups guest settings, Teams guest access toggle, and SharePoint external sharing.
3Channels: Standard (all members, parent SharePoint site), private (subset of members, separate SharePoint site), shared (cross-team/cross-org, separate SharePoint site, requires Entra ID B2B direct connect).
4App management: Three layers -- org-wide settings (master toggle), app catalog (allow/block individual apps), permission policies (per-user app category controls).
5Voice: Phone System (cloud PBX license) + Calling Plan or Direct Routing (PSTN connectivity). Auto attendants route by menu. Call queues route to agent groups.
6Compliance: Retention policies (channel messages + chats), DLP (real-time message scanning), eDiscovery (chat in user mailbox, channels in group mailbox), legal hold preserves edited/deleted messages.
