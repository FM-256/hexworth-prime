This chapter covers site collection types, org-level and site-level sharing policies, storage quotas, OneDrive sync client configuration (Known Folder Move, Files On-Demand), site permissions, content types, information architecture, and inactive site policies for lifecycle management.

SharePoint Site Collection Types
Three primary site types serve different collaboration needs across your organization.
Team Sites
Connected to a Microsoft 365 Group. Designed for team collaboration with shared document libraries, lists, and a connected Teams channel. Default permission model uses group membership. Created automatically when a new M365 Group or Team is provisioned.
Communication Sites
Not connected to a group. Designed for broadcasting information to a broad audience (company news, policies, events). Uses a publishing-style layout with hero web parts, news posts, and page templates. Permissions are managed via site-level SharePoint groups.
Hub Sites
A registered hub that other sites associate with. Provides shared navigation, theme, search scope, and news aggregation across associated sites. Any team or communication site can be registered as a hub (requires SharePoint admin). Maximum 2,000 hub associations per tenant.
Exam Tip
Hub sites do not change permissions or storage on associated sites. They only provide shared navigation, theme, and search. A site can only associate with one hub at a time. Hub registration requires the SharePoint Administrator role or higher.

Sharing Settings: Org-Level vs. Site-Level
Sharing is controlled at two levels -- org-wide sets the ceiling, site-level sets the floor.
Org-Level (Tenant-Wide)
Set in the SharePoint admin center under Policies > Sharing. This is the maximum sharing level for the entire tenant. Individual sites cannot exceed the org-level setting. Default for new tenants: "Anyone" (anonymous links enabled).
Site-Level Override
Each site can be set to a more restrictive sharing level than the org default. For example, org allows "Anyone" links but an HR site is locked to "Only people in your org." Site-level can never exceed org-level.
Common Pitfall
If the org-level is set to "Existing guests only," no site can enable "Anyone" links -- even if a site admin tries. The org-level is the ceiling. Exam questions frequently test this hierarchy.

External Sharing Advanced Controls
Fine-grained controls beyond the four sharing levels.
Link Expiration
Set default expiration for "Anyone" links (e.g., 30 days). After expiration, the link stops working. Configurable at org-level and overridden per-site.
Link Permissions
Default link type: Anyone, People in org, Specific people. Default permission: View only or Edit. Controls what users see when they click "Share."
Domain Allow/Block
Restrict external sharing to specific domains (allow list) or block specific domains (block list). Set at org-level or per-site. Cannot use both simultaneously.
Guest Expiration
Guests who have not re-authenticated within a set number of days lose access. Works with Entra ID access reviews to auto-remove stale guest accounts.
People Picker
Control whether site members can invite guests directly or if sharing is restricted to site owners. Reduces accidental over-sharing by limiting who can grant external access.
File/Folder vs. Site
Sharing can be restricted so external sharing is allowed for files and folders but not for entire sites. Granular control prevents exposing full site libraries to external users.
Real-World Scenario
A financial services company sets org-level sharing to "New and existing guests," blocks sharing with competitor domains, sets "Anyone" link expiration to 7 days, and restricts guest invitations to site owners only on all sensitive sites.

Storage Quotas and Limits
SharePoint storage is pooled at the tenant level and allocated to individual sites.
Tenant Storage Pool
Base: 1 TB + 10 GB per licensed user. Example: 500 users = 1 TB + 5 TB = 6 TB total. Additional storage can be purchased in 1 GB increments. The pool is shared across all SharePoint sites.
Per-Site Limits
Default per-site limit: 25 TB (recently increased to 25 TB for most tenants). Admins can set custom storage limits per site in the SharePoint admin center to prevent any single site from consuming the entire pool.
Automatic vs. Manual
Automatic mode (default): SharePoint manages storage per site automatically, allocating up to 25 TB as needed. Manual mode: Admins set explicit quotas per site and receive alerts at configurable thresholds (e.g., 90% full).
OneDrive Storage
Default per-user: 1 TB (can be increased to 5 TB by admin, or unlimited with specific licenses). OneDrive storage draws from the same tenant pool. Set default via SharePoint admin center > Settings > OneDrive storage limit.
Exam Tip
OneDrive storage quotas are managed in the SharePoint admin center, not a separate OneDrive admin center. When a user leaves the organization, their OneDrive data is retained for 30 days by default (configurable up to 3,650 days) before automatic deletion.

OneDrive Sync Client
Known Folder Move and Files On-Demand are the two critical sync features for the MS-102 exam.
Known Folder Move (KFM)
Silently redirects user Desktop, Documents, and Pictures folders to OneDrive. Configured via Group Policy or Intune. Two modes: prompt users to move, or silently move without notification. Once enabled, files sync to the cloud and appear in OneDrive. Critical for data protection -- ensures user files are backed up even if the device is lost.
Files On-Demand
Files appear in File Explorer but are not downloaded until opened. Three states: cloud-only (online), locally available (downloaded), and always keep on device (pinned). Saves disk space on endpoints. Enabled by default in the sync client. Can be enforced via Group Policy to prevent users from disabling it.
KFM Deployment via Intune
1Get Tenant ID -- required for the KFM policy. Found at Microsoft Entra admin center > Overview.
2Create device configuration profile -- use Settings Catalog or Administrative Templates (ADMX) in Intune.
3Enable "Silently move Windows known folders" -- set tenant ID. This moves Desktop, Documents, Pictures without user prompts.
4Assign to device groups -- deploy to pilot group first, then expand. Monitor sync status in the OneDrive admin center health dashboard.
Common Pitfall
KFM requires the OneDrive sync client version 18.111.0603.0004 or later. If users have files in known folders that contain unsupported characters or exceed path length limits (400 characters), KFM will fail silently. Always check the sync health dashboard after deployment.

Site Permissions Model
SharePoint permissions use groups and sharing links to control access at the site, library, folder, and item levels.
SharePoint Groups
Every site has three default groups: Owners (Full Control), Members (Edit), Visitors (Read). Team sites inherit membership from the connected M365 Group. Communication sites use standalone SharePoint groups.
Sharing Links
Four link types: Anyone (anonymous), People in your org, People with existing access, Specific people. Each link type can grant View or Edit. Links are the primary way end users share content in SharePoint and OneDrive.
Permission Inheritance
By default, items inherit permissions from their parent (library inherits from site, folder inherits from library). Inheritance can be broken at any level, creating unique permissions. Breaking inheritance creates a management burden -- use sparingly.
Best Practice
Use M365 Groups for team site membership, SharePoint groups for communication sites, and sharing links for ad-hoc access. Avoid granting direct user permissions at the item level -- it creates unmanageable permission sprawl. Use sensitivity labels with Entra ID Conditional Access for data classification-based access control.

Content Types and Information Architecture
Content types standardize metadata, templates, and workflows across sites and libraries.
Content Types
A reusable collection of metadata columns, templates, and behaviors. Defined in the Content Type Hub (or SharePoint admin center) and published to all sites. Examples: "Contract" (with columns for expiration date, department, status), "Policy Document" (with approval workflow). Libraries can host multiple content types.
Site Columns
Reusable column definitions (metadata fields) created at the site or tenant level. Used inside content types to enforce consistent metadata. Examples: Department (choice), Project Code (text), Expiration Date (date). Avoid creating the same column in multiple libraries -- create once, reuse everywhere.
Term Store
Managed metadata service. Central taxonomy of terms organized in term sets and groups. Enables consistent tagging across all sites. Powers managed metadata columns and site navigation.
Document Sets
A special content type that groups related documents as a single entity. Shared metadata, versioning, and workflows apply to the set. Example: an RFP document set containing proposal, budget, and timeline documents.
Content Type Hub
A designated site (or the modern SharePoint admin center) that publishes content types to all sites in the tenant. Changes propagate automatically. Ensures enterprise-wide consistency for metadata and document templates.

Site Lifecycle Management
Inactive site policies help manage sprawl and ensure governance across hundreds or thousands of sites.
Inactive Site Policy Flow
1Detection -- SharePoint identifies sites with no user activity (no file edits, page views, or visits) for a configurable period (e.g., 6 months, 1 year).
2Notification -- Site owners receive email notifications warning that their site is inactive and may be archived or deleted if no action is taken.
3Owner Confirmation -- Owners can confirm the site is still needed (resets the inactivity timer) or acknowledge it should be archived/deleted.
4Admin Action -- If owners do not respond, admins can archive the site (read-only), delete it, or reassign ownership. Microsoft 365 Archive (preview) moves inactive sites to cold storage at reduced cost.
M365 Archive
Moves inactive sites to cold storage. Content is preserved but inaccessible to users. Reduces active storage costs. Sites can be reactivated by admins within the retention period. Configured in SharePoint admin center > Settings > Site lifecycle management.
Deleted Site Retention
Deleted sites go to the site collection Recycle Bin for 93 days. During this period, admins can restore the site with all content and permissions intact. After 93 days, the site is permanently deleted. User-deleted items follow a two-stage recycle bin (93 days total).

SharePoint Admin Center
The central management portal for SharePoint Online and OneDrive administration.
Active Sites
View, create, and manage all site collections. Set storage limits, sharing policies, and hub associations. Export site inventory to CSV. Filter by template, storage usage, or activity.
Policies > Sharing
Configure org-level sharing settings, default link types, link expiration, and domain restrictions. This page sets the tenant-wide sharing ceiling that individual sites inherit.
Policies > Access Control
Unmanaged device access policies, network location-based access, idle session sign-out, and apps that do not use modern authentication. Integrates with Entra ID Conditional Access.
Settings
OneDrive storage limits, default admin experience, notifications, site creation (self-service on/off), and site lifecycle management configuration.
Content Services
Term store management, content type gallery, and content type publishing. Manage the enterprise taxonomy and metadata schema from this section.
Migration
SharePoint Migration Tool (SPMT) and Migration Manager for moving content from on-premises SharePoint, file shares, Google Drive, or Box to SharePoint Online and OneDrive.

MS-102 Exam Scenarios
Common exam question patterns for SharePoint and OneDrive administration.
Scenario: Block Anonymous Sharing for One Site
Org-level allows "Anyone" links. An HR site must block anonymous sharing. Solution: set site-level sharing to "Only people in your org" in the SharePoint admin center > Active sites > select site > Sharing. No change to org-level needed.
Scenario: Deploy KFM Silently
Deploy Known Folder Move without user interaction. Solution: create an Intune device configuration profile with the "Silently move Windows known folders to OneDrive" setting, provide the tenant ID, and assign to a device group. Users see no prompts.
Scenario: User Left -- Preserve OneDrive Data
A user's account is deleted. Their OneDrive data must be preserved for 1 year. Solution: set OneDrive retention days to 365 in SharePoint admin center > Settings > OneDrive > Retention. The manager receives delegate access automatically.
Scenario: External Partner Collaboration
Allow partners from fabrikam.com to access a project site but block all other external domains. Solution: set org-level sharing to "New and existing guests," then configure domain allow list with fabrikam.com in Policies > Sharing > Advanced external sharing settings.
Key Distinction
OneDrive sharing settings follow the same hierarchy as SharePoint: the org-level setting in SharePoint admin center applies to both SharePoint sites and OneDrive. However, OneDrive has its own separate slider that can be more restrictive than the SharePoint org-level.

Chapter 6 Summary
Key concepts for Manage SharePoint and OneDrive
1Site types: Team sites (M365 Group-connected), communication sites (broadcast/publishing), and hub sites (shared navigation, theme, and search across associated sites).
2Sharing hierarchy: Org-level sets the ceiling, site-level can only be equal or more restrictive. Four levels: Anyone, New and existing guests, Existing guests, Only people in your org.
3Storage: Tenant pool = 1 TB + 10 GB per user. Per-site default: 25 TB. OneDrive default: 1 TB per user. Managed in SharePoint admin center.
4OneDrive sync: Known Folder Move silently redirects Desktop/Documents/Pictures to OneDrive. Files On-Demand saves disk space with cloud-only placeholders.
5Permissions: SharePoint groups (Owners/Members/Visitors), M365 Group membership for team sites, sharing links for ad-hoc access. Avoid breaking inheritance at item level.
6Lifecycle: Inactive site policies detect unused sites, notify owners, and enable archival or deletion. Deleted sites retained 93 days in recycle bin.
