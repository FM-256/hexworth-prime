Security and Compliance
Microsoft Purview  •  DLP  •  Sensitivity Labels  •  Retention  •  eDiscovery  •  Audit  •  Insider Risk
Microsoft Purview provides a unified compliance platform for protecting sensitive data, managing information lifecycle, discovering content for legal matters, auditing user activity, and detecting insider threats. This chapter covers Compliance Manager, DLP policies, sensitivity labels, retention policies, eDiscovery, audit logging, insider risk management, and communication compliance.

Microsoft Purview Compliance Portal
The central hub at compliance.microsoft.com for all compliance and data governance tasks.
Compliance Manager
Measures your compliance posture with a score (0-100%). Provides assessments for regulatory frameworks (GDPR, NIST 800-53, ISO 27001) and tracks improvement actions that raise your score.
Content Explorer
Browse items that have sensitivity labels, retention labels, or match sensitive information types. Requires Content Explorer Content Viewer role for reading actual content.
Activity Explorer
View a timeline of label activity: labels applied, labels changed, files copied to removable media, DLP policy matches, and auto-labeling events across workloads.
Slide 3 of 16
Compliance Manager: Assessments and Score
A risk-based score that quantifies your organization's compliance posture across regulatory frameworks.
Assessments
Each assessment maps to a regulation (e.g., GDPR, HIPAA, NIST 800-53). An assessment contains controls, which are grouped into control families. Each control maps to one or more improvement actions. Microsoft manages some actions (infrastructure controls); you manage tenant-level actions.
Compliance Score
Points are earned by completing improvement actions. The score is a percentage of total achievable points. Microsoft-managed actions are scored automatically. Your actions are scored when marked complete with evidence. Higher-risk actions earn more points.
Improvement actions are ranked by impact: mandatory > discretionary, preventive > detective > corrective. Completing a high-impact preventive action (e.g., enabling MFA) earns more points than a low-impact corrective action.
Improvement Actions
Each action has implementation status (not implemented, in progress, implemented, alternative), test status, and assigned owner. Actions can link directly to the configuration page in the admin center.
Action Groups
Actions shared across assessments only need to be completed once. If you enable MFA for a GDPR assessment, the NIST assessment auto-credits the same action. This prevents duplicate work.
Built-in Assessments
Microsoft 365 Data Protection Baseline is included by default. Additional templates (GDPR, HIPAA, PCI DSS, SOC 2, FedRAMP) are available. Premium templates require E5 or add-on licensing.

Data Loss Prevention (DLP) Policies
Prevent accidental or intentional sharing of sensitive data across Exchange, SharePoint, OneDrive, Teams, and endpoints.
Conditions
DLP rules trigger on sensitive information types (SSN, credit card, passport numbers), sensitivity labels, file extensions, or custom regex/keyword dictionaries. Conditions support instance count thresholds (e.g., block when 5+ SSNs detected).
Actions
Block access to the content, restrict external sharing, display a policy tip to the user (with override option), send incident reports to admins, and generate alerts in the DLP alerts dashboard. Users can provide a business justification to override.
Locations
Policies are scoped to locations: Exchange Online (email), SharePoint sites, OneDrive accounts, Teams chat/channel messages, Windows 10/11 endpoints, on-premises repositories, and Power BI. Each location can include/exclude specific users or groups.
Slide 5 of 16
Sensitive Information Types
Pattern-based classifiers that DLP and auto-labeling use to identify sensitive content.
Built-in SITs
Microsoft provides 300+ built-in sensitive information types covering credit card numbers (Luhn check), SSNs (format + context), passport numbers, medical IDs, and financial codes across 40+ countries. Each SIT uses pattern matching, keyword proximity, checksum validation, and confidence levels (low/medium/high).
Custom SITs
Create custom types using regex patterns, keyword lists, keyword dictionaries (upload a file with thousands of terms), or exact data match (EDM) that hashes your actual data (e.g., employee IDs). EDM provides exact matching with near-zero false positives.
Exam Tip
Confidence levels matter. A DLP rule set to high confidence triggers only when the pattern, supporting keywords, and checksum all match. Low confidence matches on pattern alone, producing more false positives. Tune instance count + confidence level to balance protection vs. user friction.
Trainable Classifiers
Machine learning classifiers trained on sample content (resumes, source code, contracts). Pre-trained classifiers are available for common categories. Custom classifiers need 50+ positive samples and 50+ negative samples.
Fingerprinting
Document fingerprinting creates a hash template from a standard form (tax form, patent application). Any document matching the fingerprint structure triggers DLP, even if the content differs.
Exact Data Match
Upload a schema + hashed data table (employee IDs, patient numbers). DLP matches content against the exact values without storing plaintext sensitive data. Best for org-specific identifiers with no pattern.

Sensitivity Labels
Persistent metadata tags that classify, encrypt, and visually mark content -- travel with the document.
Encryption
Labels can apply Azure Rights Management encryption. Define who can access (specific users, groups, or all org members), what they can do (view, edit, print, copy, forward), and when access expires (never, specific date, or days after applying). Offline access period configurable.
Content Marking
Add headers, footers, and watermarks to documents. Configure text, font size, color, and alignment. Markings are applied when the label is applied in Office apps. Different markings can be set per Office app type (Word vs. PowerPoint).
Auto-Labeling
Client-side auto-labeling recommends or auto-applies labels when sensitive info types are detected in Office apps. Service-side auto-labeling scans content at rest in SharePoint, OneDrive, and Exchange. Service-side auto-labeling requires E5.
Sensitivity labels are persistent -- they follow the content regardless of where it is stored or shared. A "Confidential" label with encryption ensures only authorized users can open the document even if it is emailed externally, copied to USB, or uploaded to a third-party cloud service.
Label Priority
Labels are ordered by priority (lowest number = lowest sensitivity). Users can upgrade a label (General to Confidential) freely but must provide a justification to downgrade. Admins see downgrade events in Activity Explorer.
Label Scopes
Labels can be scoped to files and emails, groups and sites (controls privacy, external access, unmanaged device access for the M365 group/Teams site), or schematized data assets in Purview Data Map.
Slide 7 of 16
Sensitivity Label Policies
Policies publish labels to users and enforce labeling behavior across the organization.
1Create labels in the Purview compliance portal with desired protections (encryption, marking, scope).
2Create a label policy that selects which labels to publish and to which users/groups.
3Configure policy settings: require a label on documents, require a label on emails, require justification on downgrade or removal, set a default label for documents/emails/groups.
4Deploy: policies take up to 24 hours to propagate. Labels then appear in Office apps, Outlook, SharePoint, and OneDrive.
Default Label
Set a default label so all new documents automatically receive a baseline classification (e.g., "General"). Users can change the label -- if the new label is lower priority, justification is required. Default labels reduce the number of unlabeled documents in the tenant.
Mandatory Labeling
Require users to apply a label before saving a document or sending an email. Without a label, the save/send action is blocked. Combined with a default label, this ensures 100% label coverage across the organization.
Exam Tip
Label policies and labels are separate objects. Deleting a label policy does not remove labels already applied to documents. Labels persist on the content permanently until manually changed or removed by a user or auto-labeling policy.

Retention Policies and Labels
Govern the lifecycle of content: retain it, delete it, or retain then delete -- enforced across M365 workloads.
Retention Policies
Apply broadly to entire locations (all Exchange mailboxes, all SharePoint sites, all Teams channels). Settings: retain for X years, delete after X years, or retain then delete. Applied silently -- users do not see the policy. Content is held in the Preservation Hold Library (SharePoint) or Recoverable Items folder (Exchange).
Retention Labels
Applied to individual items (documents, emails) manually by users, auto-applied by conditions, or applied by default to a document library. Labels are visible to users. Labels can trigger a disposition review at the end of the retention period before content is deleted.
Retention overrides deletion. If a retention policy says "retain for 7 years" and a user deletes the file, the content is preserved in the Preservation Hold Library until the retention period expires. Users cannot permanently delete retained content.
Retain then Delete
Most common pattern: retain content for a defined period (e.g., 7 years from creation), then automatically delete it. Start date can be based on creation date, last modified date, labeled date, or an event (employee departure).
Label Priority
When multiple retention labels apply, the principles of retention resolve conflicts: retention wins over deletion, the longest retention period wins, explicit inclusion wins over implicit, and the shortest delete period wins.
Record Management
Mark content as a record (locks editing) or regulatory record (locks editing AND prevents the label from being removed, even by admins). Used for financial records, legal documents, and regulatory compliance where immutability is required.

eDiscovery: Standard vs. Premium
Search, hold, and export content across Microsoft 365 for legal investigations and regulatory requests.
eDiscovery (Standard)
Included with E3. Create cases, place content on hold (Exchange mailboxes, SharePoint sites, OneDrive accounts), run keyword/date/sender searches across held locations, preview results, and export to PST or individual messages. Supports KQL query syntax.
eDiscovery (Premium)
Requires E5 or add-on. Adds custodian management, legal hold notifications, review sets with AI-powered analytics (near-duplicate detection, email threading, themes, relevance scoring), advanced indexing for large items, and conversation reconstruction for Teams chats.
Holds
Preserve content in place. Held content cannot be permanently deleted by users. Supports query-based holds to preserve only matching content.
Searches
KQL keyword queries across mailboxes, sites, and Teams. Filter by date range, sender, recipient, file type, and sensitivity label.
Review Sets
Premium feature. Add search results to a review set for analysis. AI identifies near-duplicates, threads email conversations, and scores relevance.
Custodians
Premium feature. Map data sources (mailbox, OneDrive, Teams) to specific people under investigation. Issue and track legal hold notifications.
Export
Download search results as PST files, individual messages, or native file formats. Export includes a load file for third-party review tools.
Permissions
eDiscovery Manager can manage own cases. eDiscovery Administrator can access all cases. Both require explicit role assignment -- Global Admin alone is not sufficient.

Audit Log: Standard vs. Premium
Track user and admin activity across all Microsoft 365 services with searchable audit records.
Audit (Standard)
Included with E3/E5. Logs user and admin activities across Exchange, SharePoint, OneDrive, Teams, Entra ID, and more. Records are retained for 180 days by default. Search by activity, date range, users, and IP addresses. Results exportable to CSV.
Audit (Premium)
Requires E5. Extends retention to 1 year (configurable up to 10 years with add-on). Adds high-value audit events: MailItemsAccessed (mailbox access for breach forensics), Send (email sent events), and SearchQueryInitiatedExchange/SharePoint.
Audit (Premium) is critical for breach investigations. The MailItemsAccessed event tells you exactly which emails an attacker read after compromising a mailbox -- this event is not available in Audit (Standard).
Audit Log Search
Search the unified audit log at compliance.microsoft.com or via Search-UnifiedAuditLog PowerShell cmdlet. Filter by activity type, date range, users, file/folder/site, and IP address. Results include timestamp, user, activity, item, and detail columns.
Retention Policies
Create custom audit log retention policies to keep specific activity types longer. E.g., retain all Exchange admin activities for 2 years while keeping general activities at the default 180 days. Higher-priority policies override lower-priority ones.
Enabling Audit
Audit logging is enabled by default for E3/E5 tenants. However, mailbox auditing must be verified. Use Get-AdminAuditLogConfig to confirm. For Premium events, users must be assigned an E5 license or the Audit (Premium) add-on.

Insider Risk Management
Detect, investigate, and act on risky insider activities -- data theft, policy violations, and security breaches by internal users.
Policy Templates
Pre-built templates: Data theft by departing users, General data leaks, Data leaks by priority users, Security policy violations, Patient data misuse (healthcare). Templates define which indicators and triggering events to monitor.
Triggering Events
Events that activate monitoring for a user: HR connector signals (resignation notice, termination date), DLP policy match, user submits resignation in HR system. Without a triggering event, the user is not in scope (except for general data leak policies).
Indicators
Signals that contribute to risk scoring: file downloads from SharePoint, email to external recipients, USB copy activity, printing spikes, cloud upload to personal storage, sequence of suspicious activities (download then email then resign).
Alerts and Investigation
When risk scores exceed thresholds, alerts are generated. Analysts triage alerts (confirm, dismiss, or escalate). Confirmed alerts open a case with a timeline of all risky activities. Cases can be escalated to eDiscovery (Premium) for legal review.
Privacy and Pseudonymization
By default, user identities in alerts are pseudonymized (User-1, User-2). Analysts with the Insider Risk Management Investigator role can de-anonymize. This protects user privacy during initial triage and complies with data protection regulations.
Slide 12 of 16
Communication Compliance
Monitor and remediate inappropriate or risky communications in Exchange, Teams, and Viva Engage.
Policy Templates
Pre-built templates: Inappropriate text (profanity, harassment, threats), Inappropriate images, Sensitive information (detect PII/financial data in messages), Regulatory compliance (communications with external parties), Custom keyword policies.
Detection Scope
Monitor inbound, outbound, or internal communications. Scope to specific users/groups or the entire org. Covers Exchange email, Teams chat and channel messages, Viva Engage posts, and third-party sources via connectors.
Review and Remediation
Flagged messages appear in a review queue. Reviewers can: tag as compliant (false positive), tag as non-compliant, escalate, resolve with notification to the sender, remove the message from Teams, or create a case. All reviewer actions are logged.
Exam Tip
Communication compliance uses machine learning classifiers for inappropriate content detection -- it is not purely keyword-based. The classifier can detect harassing language, threats, and discriminatory content even without explicit keyword matches.

How It All Connects: DLP + Labels + Retention
These three pillars work together to classify, protect, and govern content throughout its lifecycle.
Labels as DLP Conditions
DLP policies can use sensitivity labels as conditions. Example: "Block external sharing of any document labeled Highly Confidential." This is more reliable than content inspection alone because the label persists even if sensitive content is removed.
Auto-Labeling + DLP
Service-side auto-labeling applies sensitivity labels to content at rest based on SIT matches. DLP then enforces sharing restrictions based on those labels. This creates an automated classify-and-protect pipeline with no user action required.
Retention + Sensitivity
Both sensitivity labels and retention labels can coexist on the same document. A file can be "Confidential" (sensitivity) and "Retain 7 years" (retention) simultaneously. These are independent label systems managed in different areas of the compliance portal.

Licensing: E3 vs. E5 Compliance
Know which features require E5 or add-on licensing -- a frequent exam topic.
Included in E3
Manual sensitivity labels, basic DLP (Exchange + SharePoint + OneDrive), retention policies and labels, eDiscovery (Standard), Audit (Standard) with 180-day retention, Compliance Manager (default baseline assessment), basic communication compliance.
Requires E5 or Add-on
Auto-labeling (service-side), endpoint DLP, DLP for Teams messages, eDiscovery (Premium) with review sets and custodian management, Audit (Premium) with 1-year retention and MailItemsAccessed events, insider risk management, advanced communication compliance with ML classifiers, premium Compliance Manager templates.
Common Trap
Client-side auto-labeling (recommendations in Office apps) is included in E3 with the Azure Information Protection P1 plan. Service-side auto-labeling (scanning content at rest in SharePoint/OneDrive/Exchange) requires E5. The exam tests this distinction.

Scenario: Protecting Financial Data
A compliance team needs to protect sensitive financial data across the organization.
1Create sensitivity labels: "Internal -- Finance" with encryption (Finance team = co-author, everyone else = viewer) and watermark "INTERNAL FINANCE" on all pages.
2Publish via label policy: Publish to the Finance group with mandatory labeling and "General" as default. Require justification on downgrade.
3Create auto-labeling policy: Service-side scan of Finance SharePoint site. Auto-apply "Internal -- Finance" label when 3+ credit card numbers or bank account numbers are detected.
4Create DLP policy: Condition: sensitivity label = "Internal -- Finance." Action: block external sharing, notify user with policy tip, alert Compliance Officer. Locations: SharePoint, OneDrive, Exchange, Teams.
5Create retention label: "Finance -- 7 Year Retain" applied by default to the Finance document library. Retain for 7 years from creation date, then trigger disposition review.
6Monitor in Compliance Manager: Mark the DLP and labeling improvement actions as implemented. Compliance score increases as controls are verified.
Result
Financial documents are automatically classified, encrypted, watermarked, protected from external sharing, retained for 7 years, and tracked in the compliance score -- all without relying on user action beyond the initial label policy.

Chapter 8 Summary
Key concepts for Security and Compliance
1Compliance Manager: Risk-based compliance score driven by improvement actions across regulatory assessments. Shared actions count once across multiple frameworks.
2DLP policies: Conditions (SITs, labels, regex) + actions (block, notify, alert) + locations (Exchange, SPO, OD, Teams, endpoints). Confidence levels and instance counts tune precision.
3Sensitivity labels: Persistent classification with encryption, content marking, and auto-labeling. Published via label policies. Priority determines upgrade/downgrade behavior.
4Retention: Policies (broad, silent) vs. labels (item-level, user-visible). Retention wins over deletion. Longest retention period wins. Records lock content from editing.
5eDiscovery: Standard (holds, searches, export) vs. Premium (custodians, review sets, AI analytics). eDiscovery Manager vs. Administrator role scope.
6Audit: Standard (180-day retention) vs. Premium (1 year+, MailItemsAccessed). Custom retention policies can extend specific activity types.
7Insider risk: Triggering events activate monitoring, indicators drive risk scores, pseudonymized alerts protect privacy. Policy templates target departing users, data leaks, and security violations.
8Communication compliance: ML-powered detection of inappropriate content, sensitive data in messages, and regulatory violations across Exchange, Teams, and Viva Engage.
