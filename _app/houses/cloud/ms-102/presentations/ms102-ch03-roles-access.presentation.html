Manage Roles and Access
Built-in Roles  •  Custom Roles  •  Administrative Units  •  PIM  •  Conditional Access
Microsoft Entra ID uses role-based access control (RBAC) to govern who can manage what across your Microsoft 365 tenant. This chapter covers built-in admin roles, custom role creation, administrative units for scoped delegation, Privileged Identity Management (PIM) for just-in-time access, and Conditional Access policies that enforce security conditions at sign-in.

Built-in Admin Roles
Microsoft Entra ID provides over 80 built-in roles. Six are critical for the MS-102 exam.
Global Administrator
Full access to all admin features across every M365 service. Can manage all other roles. Limit to 2-4 accounts. Required for tenant-level changes like custom domains and billing.
Exchange Administrator
Full control of Exchange Online: mailboxes, mail flow rules, connectors, transport rules, and anti-spam policies. Cannot manage Entra ID users or groups directly.
SharePoint Administrator
Manages all SharePoint Online sites, site collections, sharing settings, storage quotas, and OneDrive policies. Can create and delete site collections.
Teams Administrator
Manages Microsoft Teams policies: messaging, meeting, calling, and app policies. Controls Teams device configuration and manages the Teams admin center.
Security Administrator
Read/write access to security features: Microsoft Defender, Conditional Access, identity protection, and security policies. Cannot manage compliance features.
Compliance Administrator
Manages compliance features: data loss prevention, retention policies, sensitivity labels, eDiscovery, and audit logs. Separate from security administration.
Exam Tip
The principle of least privilege is a core MS-102 theme. Never assign Global Administrator when a scoped role exists. The exam tests whether you can identify the correct role for a given task -- for example, configuring mail flow rules requires Exchange Administrator, not Global Administrator.

Role Scope and Permissions
Each built-in role grants specific permissions across defined resource scopes.
User Administrator
Creates and manages users and groups, resets passwords, manages licenses, and monitors service health. Cannot manage Exchange, SharePoint, or security-specific settings.
Helpdesk Administrator
Resets passwords for non-admin users and other helpdesk admins. Can force sign-out and manage service requests. Cannot reset passwords for Global, Exchange, or Security admins.
Global Reader
Read-only access to all admin centers and settings that a Global Admin can see. Cannot make any changes. Ideal for auditors and security reviewers who need visibility without write access.

Custom Roles in Microsoft Entra ID
When built-in roles are too broad or too narrow, create custom roles with granular permissions.
When to Use Custom Roles
Create custom roles when a built-in role grants too many permissions (violating least privilege) or when you need to combine permissions from multiple built-in roles into a single assignment. Example: a role that can only reset passwords and manage group memberships but nothing else.
Licensing Requirement
Custom roles require Microsoft Entra ID P1 (create and assign) or P2 (assign via PIM with eligible activation). Without P1, you are limited to the built-in roles only. This is a frequently tested licensing question on the MS-102 exam.
Common Pitfall
Custom roles currently support permissions scoped to application registrations, enterprise applications, users, groups, and administrative units. Not all Microsoft 365 workload permissions are available for custom roles -- Exchange and SharePoint administration still requires built-in roles.

Administrative Units
Scope admin role assignments to a subset of users, groups, or devices rather than the entire tenant.
Membership Types
Administrative units support three membership types: Assigned (manually add users), Dynamic User (auto-populate based on user attributes like department or country), and Dynamic Device (auto-populate devices based on properties).
Supported Roles
Only specific roles can be scoped to an AU: User Administrator, Helpdesk Administrator, Password Administrator, Groups Administrator, Authentication Administrator, and License Administrator. Global Admin always has full scope regardless.
Restricted Management
Enable the Restricted management flag on an AU to prevent tenant-level admins (except Global Admin and Privileged Role Admin) from modifying members inside that AU. This creates a hard boundary for sensitive accounts.

Privileged Identity Management (PIM)
Reduce standing admin access by making role assignments eligible instead of permanently active.
Eligible vs. Active
Eligible: User can activate the role when needed -- zero standing access. Active: Permanently assigned -- role is always on. PIM shifts organizations from active to eligible assignments to reduce the attack surface from compromised admin accounts.
Just-in-Time Access
When an eligible user needs admin access, they activate the role through PIM. Activation requires MFA, a business justification, and optionally manager approval. The role activates for a configurable time window (default 1 hour, max 24 hours) then automatically deactivates.
Licensing
PIM requires Microsoft Entra ID P2 (included in Entra ID Governance or EMS E5). P1 does not include PIM. Every user with an eligible assignment needs a P2 license -- this is a high-frequency exam question.
Slide 7 of 12
PIM Role Settings
Configure activation requirements, duration, and notifications per role.
Activation Settings
Max duration: 1-24 hours (default 8). MFA on activation: require re-authentication. Justification: require a text reason. Ticket info: optionally require a ticket number for change management integration.
Approval Workflow
Enable approval so a designated approver must authorize the activation request before the role becomes active. Approvers can be users or groups. If no approver responds within the timeout, the request is denied automatically.
Assignment Settings
Permanent eligible: no end date on eligibility. Time-bound eligible: eligibility expires on a set date. Permanent active: always-on (use sparingly). All assignments are auditable in the Entra audit log.
Notifications
PIM sends email notifications for: role assignments, role activations, activation approvals/denials, and role expirations. Configure notification recipients per role -- typically Global Admin and Security Admin receive all PIM alerts.
Access Reviews
PIM integrates with Entra ID Access Reviews. Schedule periodic reviews of role assignments -- reviewers confirm whether each user still needs the role. Non-responsive reviews can auto-remove assignments. Required for audit compliance (SOC 2, ISO 27001).
Exam Tip
The exam tests the difference between eligible and active assignment settings. A common scenario: "A user needs Global Admin access once per month for billing tasks." The correct answer is an eligible PIM assignment with approval, not a permanent active assignment.

Conditional Access Policies
If-then rules that evaluate conditions at sign-in and enforce access controls.
Conditional Access policies follow an if-then model: IF a set of conditions match (user, location, device, risk level), THEN apply access controls (grant with requirements, or block entirely). Multiple policies can apply to a single sign-in -- the most restrictive combination of controls is enforced. Policies require Microsoft Entra ID P1 or higher.
Exam Tip
Conditional Access replaces Security Defaults. You cannot have both enabled simultaneously. When Conditional Access is active, Security Defaults must be disabled. The exam tests this conflict frequently.
Slide 9 of 12
Conditional Access Conditions
The "if" side of a Conditional Access policy -- signals evaluated at every sign-in attempt.
Users and Groups
Target specific users, groups, or directory roles. Exclude break-glass accounts from all policies. Can target "All users" or specific groups like "Marketing" or "Executives."
Cloud Apps
Select which applications the policy applies to: all cloud apps, specific apps (Exchange Online, SharePoint), or user actions like "Register security info" or "Register or join devices."
Locations
Define named locations by IP ranges or countries. Mark trusted locations (corporate office IPs). Policies can require MFA only when signing in from outside trusted locations.
Device Platforms
Filter by operating system: Windows, macOS, iOS, Android, Linux. Create platform-specific policies -- for example, block Linux devices from accessing Exchange Online.
Client Apps
Distinguish between browser, mobile apps and desktop clients, Exchange ActiveSync, and other clients. Block legacy authentication protocols that do not support MFA.
Sign-in Risk / User Risk
Requires Entra ID P2. Use Identity Protection risk signals: anonymous IP, atypical travel, malware-linked IP, leaked credentials. Trigger MFA or block based on risk level (low, medium, high).

Conditional Access Controls
The "then" side of a Conditional Access policy -- what happens when conditions are met.
Grant: Require MFA
The most common grant control. Users must complete multi-factor authentication before access is granted. Can be combined with other controls using AND (require all) or OR (require one of).
Grant: Compliant Device
Require that the device is marked compliant in Microsoft Intune. The device must meet all compliance policies (encryption, OS version, antivirus). Non-compliant devices are blocked.
Grant: Entra Joined Device
Require that the device is either Microsoft Entra joined or Microsoft Entra hybrid joined. Ensures only organization-managed devices can access corporate resources.
Block Access
Deny access completely when conditions are met. Common use: block all sign-ins from countries where the organization has no employees, or block legacy authentication protocols that cannot support MFA.
Session: App-Enforced
Session controls limit the experience after sign-in. App-enforced restrictions provide limited access in SharePoint (view-only, no download). Sign-in frequency forces re-authentication after a set time.
Session: CAS Integration
Conditional Access App Control routes sessions through Microsoft Defender for Cloud Apps. Enables real-time monitoring, block downloads, prevent copy/paste, and watermark documents during the session.

Roles and Access Best Practices
Operational guidance tested on the MS-102 exam.
Break-Glass Accounts
Maintain at least 2 emergency access accounts with permanent Global Admin assignments. Exclude them from ALL Conditional Access policies. Use long, complex passwords stored in a secure vault. Monitor sign-ins to these accounts with alerts.
Report-Only Mode
Always deploy new Conditional Access policies in Report-Only mode first. This logs what would happen without enforcing the policy. Review the sign-in logs and What-If tool before switching to On. Never deploy directly to production.
Least Privilege + PIM
Convert all permanent active admin assignments to eligible PIM assignments. Require MFA and justification for every activation. Schedule quarterly access reviews. The only exception: break-glass accounts must remain permanently active.
Block Legacy Auth
Create a Conditional Access policy that blocks legacy authentication protocols (POP3, IMAP, SMTP Basic Auth, older Office clients). These protocols cannot support MFA and are the most common vector for credential-spray attacks.
The What-If Tool
The Conditional Access What-If tool (Entra admin center > Protection > Conditional Access > What-If) simulates a sign-in with specific parameters and shows exactly which policies would apply and what the outcome would be. Essential for troubleshooting access issues and validating policy behavior before enforcement.

Chapter 3 Summary
Key concepts for Manage Roles and Access
1Built-in roles: Global Admin (full access, limit 2-4), Exchange Admin, SharePoint Admin, Teams Admin, Security Admin, Compliance Admin. Always apply least privilege.
2Custom roles: Require Entra ID P1. Define granular permissions, scope to tenant or admin unit, assign directly or via PIM. Use when built-in roles are too broad.
3Administrative units: Scope role assignments to subsets of users/groups/devices. Support assigned and dynamic membership. Enable restricted management for hard boundaries.
4PIM: Requires Entra ID P2. Eligible assignments activate on-demand with MFA, justification, and optional approval. Time-bound (1-24 hours). Eliminates standing admin access.
5Conditional Access: If-then policies evaluated at sign-in. Conditions: user, location, device, risk. Controls: grant + MFA, require compliant device, or block. Report-Only mode before enforcement.
6Best practices: Break-glass accounts excluded from all CA policies. Block legacy authentication. PIM for all admin roles. Quarterly access reviews. What-If tool for troubleshooting.
