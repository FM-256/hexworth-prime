Digital Forensics Artifacts

Forensic artifacts are traces left behind by user activity, system processes, and malicious actions. SOC analysts interpret these artifacts to reconstruct events, establish timelines, and identify indicators of compromise.

Artifact Categories

File System

Created/modified files, timestamps (MAC times), deleted file remnants, file signatures

Registry (Windows)

Run keys, services, user activity, USB history, recently accessed files

Network

DNS cache, ARP cache, connection history, browser artifacts

Memory

Running processes, loaded DLLs, network connections, decrypted data

Artifact Analysis

Timeline Analysis

Forensic timelines combine timestamps from multiple artifacts to reconstruct the sequence of events. Key timestamp types:

Modified (M)

When file content was last changed

Accessed (A)

When file was last read (less reliable)

Changed (C)

When metadata was last modified

Birth/Created (B)

When file was originally created

Practical: Reconstructing an Attack from Artifacts

Step 1: Initial access Event 4624 (Type 10) — RDP logon from 185.234.72.18 at 02:17 AM Prefetch: mstsc.exe executed on victim workstation Step 2: Execution Sysmon Event 1 — powershell.exe -enc [base64] spawned by explorer.exe Amcache: mimikatz.exe hash matches known tool Step 3: Persistence Event 7045 — new service "WindowsUpdateHelper" installed Registry: HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run — new entry Step 4: Lateral movement Event 4624 (Type 3) on DC — network logon with stolen admin creds Sysmon Event 3 — SMB connection from workstation to domain controller Step 5: Exfiltration Sysmon Event 3 — outbound HTTP to 103.245.67.89 (known C2) NetFlow: 2.5 GB transferred over 4 hours
SOC Analyst Tip

Anti-Forensics Awareness: Attackers may timestomp files (alter timestamps), clear event logs (Event ID 1102 = audit log cleared), use in-memory-only malware (fileless), or living-off-the-land binaries (LOLBins like PowerShell, certutil, wmic). Always corroborate findings across multiple artifact sources — if an attacker clears Windows logs, Sysmon logs may still be intact. If they clear local logs, SIEM copies survive.
