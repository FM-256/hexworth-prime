Security Event Sources

A SOC analyst's effectiveness depends on understanding where security events originate and how to correlate data across multiple source technologies. Modern security operations aggregate events from dozens of sources into a centralized SIEM.

Event Source Categories

Network Security

Firewalls, IDS/IPS, proxy servers, NetFlow collectors, packet captures

Endpoint Security

EDR agents, antivirus, host-based IDS, Windows Event Logs, syslog

Identity & Access

Active Directory, LDAP, SSO providers, MFA systems, PAM solutions

Cloud & SaaS

AWS CloudTrail, Azure Monitor, GCP Audit Logs, O365 audit logs

Windows Event IDs for Security

Critical Security Event IDs: 4624 - Successful logon 4625 - Failed logon 4648 - Logon using explicit credentials 4672 - Special privileges assigned (admin logon) 4720 - User account created 4726 - User account deleted 4732 - Member added to security group 4688 - Process creation (with command line) 7045 - Service installed

SOC Integration Strategies

Log Collection Architecture

Syslog Forwarding

Traditional method via UDP/514 or TCP/514. Consider TLS for sensitive data (TCP/6514).

Agent-Based Collection

Splunk UF, Elastic Agent, or vendor agents. Better reliability and parsing.

API Integration

REST APIs for cloud services. Rate limits and authentication considerations.

Log Aggregators

Kafka, Logstash, Fluentd as intermediate layers for scale and transformation.

SOC Analyst Tip

Normalization is Critical: Raw logs from different sources use different field names for the same data. SIEM normalization (CIM, ECS) enables consistent queries across all sources.

Event Correlation Example

// Correlate failed logins with successful login from different IP index=windows EventCode=4625 | stats count by user, src_ip | where count > 5 | join user [ search index=windows EventCode=4624 | stats latest(src_ip) as success_ip by user ] | where src_ip != success_ip | table user, src_ip, count, success_ip
