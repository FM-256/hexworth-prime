Analyzing Indicators of Compromise

Network event monitoring methods (router-based, active, passive), network IOC taxonomy, host-level indicators, application anomalies, detection techniques, rogue device identification, and MITRE ATT&CK framework mapping.

Slide 1 — Network Event Monitoring Methods

Three Approaches to Network Monitoring

Many incidents begin with the discovery of suspicious or unexpected network traffic. Network event analysis is a core daily task for cybersecurity analysts — gathering, correlating, and analyzing data from different systems and sensors to detect or prevent incidents.

METHOD 1

Router-Based Monitoring

  • Netflow, sFlow, J-Flow standards
  • Count information at interface level
  • Samples traffic (1:100, 1:1000)
  • RMON operates at OSI Layers 1-4
  • SNMP collects device (not traffic) data
  • SNMPv3 adds encryption and authentication
METHOD 2

Active Network Monitoring

  • Sends requests to remote systems
  • Collects availability, route, delay data
  • Ping: ICMP-based up/down and latency
  • iPerf: measures max bandwidth of links
  • Useful for establishing baselines
  • Does not capture actual traffic content
METHOD 3

Passive Monitoring

  • Network tap copies all traffic
  • No impact on production traffic
  • Detailed: rate, protocols, content
  • Useful for after-the-fact analysis
  • SPAN/mirror ports on managed switches
  • Full packet capture possible
Slide 2 — Network Monitoring Tools
PRTG

Paessler Router Traffic Grapher. Packet sniffing, flows, SNMP, WMI. Server and bandwidth monitoring.

SolarWinds NTA

Flow sources, utilization analysis, endpoint identification. Network Fault Detection and availability monitoring.

Nagios

Network and system log monitoring. GUI for system/service monitoring. Thresholds are user-configured, not CVE-based.

Cacti

Open source. Uses SNMP polling to gain status of network devices. Graph-based visualization of performance data.

Wireshark

Full packet capture and deep protocol analysis. Manual analysis of captured traffic. Protocol decode library.

Zeek (Bro)

Network security monitor. Generates structured logs from traffic. Programmable analysis engine for custom detection.

Suricata

IDS/IPS with multi-threading. Signature-based detection plus protocol identification. Compatible with Snort rules.

Tcpdump

CLI packet capture. Lightweight, available on every Linux system. Essential for command-line incident response.

Slide 4 — Host-Based Indicators of Compromise

CPU / Memory Anomalies

Unexpected CPU spikes may indicate crypto-mining, exploit execution, or DoS. Consistently high utilization without known cause warrants investigation. Memory leaks — programs not releasing memory — can be induced by malware or indicate a compromised process.

Filesystem Changes

New files in unexpected locations, permission changes, modified system binaries, or files with timestamps inconsistent with system activity. Tools: Tripwire, AIDE, Wazuh Security Platform monitor for unauthorized changes in real time.

Registry Modifications (Windows)

Run keys (HKLM\Software\Microsoft\Windows\CurrentVersion\Run) are a favorite attacker persistence mechanism. Unauthorized entries in startup folders or Run keys indicate persistent malware. Agent-based monitoring required on workstations.

Unauthorized Scheduled Tasks

Attackers create scheduled tasks to maintain access or execute malware on a schedule. Windows Task Scheduler shows task details and execution history. On Linux, check crontab -l and /etc/cron.*/ directories for unauthorized entries.

Abnormal Process Behavior

Rootkits and malware inject into legitimate processes (svchost.exe, lsass.exe) or use names similar to legitimate processes (svch0st.exe, Isass.exe with capital i). Metasploit has built-in process injection capabilities. Baseline process lists are essential.

Unauthorized User/Account Activity

New accounts created without authorization, privilege escalation events, accounts with excessive permissions, logins from unexpected geographic locations or at unusual hours. Central management tools (SIEM) correlate authentication logs across all systems.

Slide 6 — Detecting Rogue Devices

Rogue Wired and Wireless Devices

Detection MethodApplication
MAC Address ValidationCompare all network-connected device MACs against an authorized device database. Flag unknown MACs immediately. Check vendor OUI prefix against known-good vendors.
Network ScanningRegular Nmap scans of all subnets to identify devices. Compare results against asset inventory. New devices that appear between scans require investigation.
Physical Site InspectionWalk the facility looking for unauthorized devices plugged into network jacks, unauthorized switches/hubs, or rogue wireless access points.
Traffic Behavior AnalysisUnusual traffic patterns from an IP or MAC that doesn't match expected behavior for that network segment — rogue devices often generate distinctive traffic.
Wireless SurveysUse wireless scanning tools to map all access points in the facility. Rogue APs appear as unexpected SSIDs or unrecognized BSSIDs. Evil Twin attacks use identical SSIDs to steal credentials.
802.1X NACNetwork Access Control requires authentication before granting network access. Prevents unauthorized devices from connecting even if physically plugged in.
Slide 7 — MITRE ATT&CK Framework: Mapping IOCs to Tactics

ATT&CK: Adversarial Tactics, Techniques, and Common Knowledge

The MITRE ATT&CK framework is a globally accessible knowledge base of adversary tactics and techniques based on real-world observations. It provides a common language for describing attacker behavior, mapping detections to specific techniques, and identifying coverage gaps. The framework has three matrices: Enterprise (Windows/Linux/macOS), Mobile, and ICS/OT.

TA0001
Initial Access
Getting Into the Network

Phishing (T1566), Valid Accounts (T1078), Exploit Public-Facing Application (T1190). IOC: unusual logons, exploit traffic in WAF logs, credential stuffing attempts.

TA0002
Execution
Running Malicious Code

Command and Script Interpreter (T1059), Scheduled Task/Job (T1053). IOC: PowerShell execution with encoded commands, unusual scheduled tasks, script interpreter spawning network connections.

TA0003
Persistence
Maintaining a Foothold

Registry Run Keys (T1547.001), Boot/Logon Startup (T1037), Create Account (T1136). IOC: new registry run keys, new accounts, startup folder modifications.

TA0010
Exfiltration
Stealing Data

Exfiltration Over C2 Channel (T1041), Exfiltration Over Alternative Protocol (T1048), Exfiltration to Cloud Storage (T1567). IOC: large outbound transfers, DNS TXT record usage, unexpected cloud service connections.

TA0011
C2 / Command & Control
Communicating with Compromised Systems

Application Layer Protocol (T1071), Encrypted Channel (T1573), Dynamic Resolution / DGA (T1568). IOC: beaconing traffic, DGA-generated domains, non-standard ports with encrypted traffic.

THREAT HUNTING APPLICATION

ATT&CK is not just a reference — it is an active threat hunting framework. For each technique in the matrix, MITRE provides data sources needed to detect it, detection notes, and known malware/groups that use it. Analysts use ATT&CK Navigator to visualize their detection coverage gaps: green means you have detections, red means blind spots. Those red cells become your threat hunting priorities.

Slide 8 — Behavior Analysis: UEBA and Anomaly Detection

User and Entity Behavior Analytics (UEBA)

UEBA analyzes normal user behavior to detect anomalous patterns. Unlike signature-based detection, UEBA can identify previously unknown attack patterns by focusing on behavioral deviation from established baselines.

How it works: Machine learning and statistical analysis create baseline behavior profiles for each user and entity (devices, applications, services). Actions that deviate from the baseline — logging in at 3 AM, downloading 10x normal data volume, accessing sensitive files not in normal work scope — generate risk scores and alerts.

Key differentiator: A fired employee's credentials used the day after termination would not match a signature (valid credentials, valid login) but would be immediately flagged by UEBA (account that logged in every weekday is now active at 2 AM from a foreign IP).

Filesystem Monitoring for Threat Detection

Real-time filesystem monitoring detects unauthorized or unexpected changes as they happen. Monitoring focuses on files, permissions, ownership, and file attributes — generating alerts when protected files are modified.

Tools: Tripwire (commercial and open source), OSSEC/Wazuh, commercial HIDS (Host-based Intrusion Detection Systems), AIDE (Advanced Intrusion Detection Environment). These tools create cryptographic hashes of protected files at baseline; any change in hash value triggers an alert.

FIELD INSIGHT: THE BASELINE IMPERATIVE

Every detection technique in Chapter 12 depends on one capability: knowing what normal looks like. Beaconing detection requires a network baseline. CPU anomaly detection requires a performance baseline. UEBA requires a behavioral baseline. Filesystem monitoring requires a known-good baseline. Without baselines, everything looks like noise. Establishing and maintaining baselines — and updating them as the environment legitimately changes — is the most important operational discipline in security monitoring.
