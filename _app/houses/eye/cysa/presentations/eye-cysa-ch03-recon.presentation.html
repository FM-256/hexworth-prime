CHAPTER 3 — PRESENTATION

Reconnaissance and Intelligence Gathering

Host enumeration, active vs. passive recon, port scanning, DNS harvesting, OSINT aggregation tools, log and configuration analysis, and detecting and preventing reconnaissance activity.

Slide 1 — Mapping and Enumeration Fundamentals

What Is Reconnaissance?

Host enumeration creates a detailed map of an organization's networks, systems, and infrastructure. This is the foundational phase of any penetration test — before attacking, you must know what exists and where.

Three major standards govern professional recon methodology:

OSSTMM (isecom.org) — Open Source Security Testing Methodology Manual covering physical, human, wireless, telecom, and data networks comprehensively.

PTES (pentest-standard.org) — Penetration Testing Execution Standard, a seven-phase structured methodology for professional engagements.

NIST SP 800-115 — Technical Guide to Information Security Testing and Assessment — government standard for discovery, attack, and reporting phases.

Slide 2 — Active vs. Passive Reconnaissance

Passive Reconnaissance

  • Uses publicly available data — no direct contact with target systems
  • Leaves no traces in target system logs
  • Data may be outdated (relies on cached or archived information)
  • Sources: WHOIS, DNS records, search engines, social media, job postings, public documents
  • Cannot be detected by the target organization in real-time

Active Reconnaissance

  • Directly interacts with target systems using scanning tools
  • Identifies live hosts, open ports, OS versions, and services
  • Does NOT include exploitation — only identification
  • Requires written authorization — can be mistaken for an attack
  • Generates log entries and may trigger IDS/IPS alerts on the target
CySA+ EXAM CRITICAL

The exam will test your ability to distinguish active from passive recon. Key differentiator: does the technique send packets to or interact with the target's systems? If yes, it is active. WHOIS lookups, DNS queries to public resolvers, and reviewing cached web pages are passive. Port scans, ping sweeps, and banner grabbing are active.

Slide 3 — Port Scanning and Service Identification

Nmap — The Standard Port Scanner

Nmap is the most commonly used command-line port scanner — free, open source, and extraordinarily capable. It provides host discovery, port scanning, service version identification, OS fingerprinting, and scripting engine capabilities. By default, nmap scans the 1,000 most common ports.

nmap [ScanType] [Options] {targets} # OS detection + no ping + SYN scan: nmap -O -PO -sS 10.0.2.4 # Flags explained: # -O = Operating system identification (via TTL and TCP stack analysis) # -PO = Skip ping before scan (treat host as alive regardless) # -sS = TCP SYN scan — send SYN, receive SYN-ACK, then RST (stealth/half-open) # Service version detection: nmap -sV 10.0.2.4 # Full port scan (all 65535 ports): nmap -p- 10.0.2.4 # Hping3 — custom probe against port 80 (bypasses ICMP firewall blocks): hping3 -p 80 -S 172.31.48.137 # -p 80 = probe using port 80 # -S = send SYN (mimics legitimate HTTP connection request)

Service Version Identification Methods

Banner grabbing: connect to the service and read the banner or connection information it provides (e.g., SSH-2.0-OpenSSH_8.2, Apache/2.4.41).

Signature comparison: compare the service's response patterns and behaviors to a database of known service signatures without relying on the banner (useful when banners are stripped or customized).

Other Port Scanner Tools

Angry IP Scanner

Multiplatform GUI scanner (Windows/Linux/macOS). Less featured than nmap by default — requires "fetchers" for OS/service details.

Zenmap

Graphical front-end for nmap. Excellent for network topology mapping. Provides visual network graphs.

Metasploit Scanners

Built-in auxiliary scanning modules for targeted service enumeration during exploitation workflows.

Slide 4 — Log and Configuration Analysis

Passive Network Mapping via Log Data

Local system configuration data and log files can be used to build a network map without sending a single active probe. While some tools exist to parse configuration files into topologies, much of this work is done manually.

Log/Config Source What It Reveals
Network Device Logs Log level events, security warnings, attack indicators, configuration issues. Cisco: 0 (Emergency) through 7 (Debug) severity levels.
Network Device Configs All routes and devices in detail, SNMP/SYSLOG server addresses, admin/user account information, interface configurations.
DHCP Logs (/var/log/dhcpd.log) DHCPREQUEST and DHCPACK entries reveal IP addresses, MAC addresses, and hostname associations — quick host inventory.
Firewall Logs and Configs Accepted and blocked connections reveal network design. Configs are faster to read than reverse-engineering logs. "show logging" on Cisco IOS.
Netflow Data Cisco protocol capturing IP traffic: source/dest IP, source/dest port, class of service, packet and byte counts. Reveals traffic patterns and anomalies.
Netstat Built-in Windows/Linux utility showing active TCP/UDP connections, process IDs using connections, route tables, and Ethernet statistics.
Windows Event Logs Application, Security, Setup, and System logs. Security log records login events, resource usage, file activity.
Linux System Logs /var/log directory contains auth.log, syslog, kern.log, and application-specific logs. Applications may store logs elsewhere.
Slide 5 — DNS Harvesting and WHOIS

Why DNS Is the First Step in OSINT

DNS information is publicly available and immediately reveals organizational structure. A hostname like DC1.company.com suggests a domain controller. MX records reveal email providers. NS records expose DNS infrastructure.

WHOIS: Searches databases for domain and IP block registration information — names, addresses, phone numbers, registration dates, nameservers. Five regional authorities manage IP space: AFRINIC (Africa), ARIN (North America), APNIC (Asia-Pacific), LACNIC (Latin America), RIPE NCC (Europe/Middle East).

nslookup: Convert domain names to IP addresses and query specific record types (MX, NS, TXT, AAAA).

DNS Zone Transfers: Designed to replicate DNS databases between servers. If misconfigured to allow unauthorized transfers, reveals the entire DNS database. Test with: dig axfr @dns-server domain.name

DNS Brute Forcing: When zone transfers are blocked, send scripted DNS queries for common subdomain names. Defenses: slow rate limiting, IDS/IPS rules, CAPTCHA on public services.

Slide 6 — OSINT Aggregation and Document Harvesting

Information Aggregation Tools

theHarvester

Text-based Kali tool. Gathers emails, domains, hostnames, employee names, open ports, and banners from public sources.

Maltego

Builds relationship maps between people, domains, IPs, organizations, and social media accounts. Visual OSINT correlation.

Shodan

Search engine for internet-connected devices — finds webcams, ICS/SCADA systems, databases, and their known vulnerabilities.

Responder

Python script. Starts passive listening for network transmissions, then switches to active mode to hijack connections and capture credentials.

Wireshark

Packet capture and analysis. Requires network access position. Reveals hosts, OS, shares, protocols, and credentials in transit.

Social Engineering Toolkit

Exploits the human element — phishing campaigns, credential harvesting, and social media OSINT via phone, email, or in-person.

Document Harvesting and Metadata

Document Metadata: Contains author names and software version information. Word documents, PDFs, and presentations embed this data invisibly. Author names reveal employee identities and internal naming conventions.

EXIF Data: Photos contain geolocation coordinates, camera model, timestamps, and GPS coordinates. An employee photo posted on LinkedIn could reveal facility locations.

Organizations should scrub metadata and EXIF data from all files published to the web. Historical cached content persists at archive.org, timetravel.mementoweb.org, and cachedview.com even after deletion.

Slide 7 — Detecting Reconnaissance Activity

Analysis Techniques for Recon Detection

Anomaly Analysis

What is different from the baseline? Unusual port scan patterns, unexpected DNS queries, or new source IPs querying WHOIS are anomalies. Requires establishing a solid baseline first.

Trend Analysis

Identifies future problems based on historical patterns. An increasing rate of failed authentication attempts or port probes over time indicates escalating targeting.

Signature Analysis

Fingerprints or hashes of known attack tools and recon patterns. nmap's SYN scan has a characteristic fingerprint detectable by IDS/IPS signature rules.

Behavioral/Heuristic Analysis

Detects threats based on behavior patterns rather than known signatures. Useful for detecting novel reconnaissance tools that have no existing signatures.

Preventing Active and Passive Reconnaissance

Preventing Active Recon: Deploy IPS to limit or stop port probes and scans. Limit external exposure of services — minimize your forward-facing footprint. Use monitoring and alert systems combining signature, behavior, and anomaly detection approaches.

Preventing Passive Recon: Control the information you release publicly. Use domain privacy services to protect WHOIS registrant data. Educate employees about social media oversharing. Rate-limit DNS lookups and searches. Avoid publishing zone files. Set strong privacy controls on all public-facing organizational content. Blacklist systems abusing your public services.
