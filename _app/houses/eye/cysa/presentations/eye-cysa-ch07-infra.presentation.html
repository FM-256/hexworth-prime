CH 7 — PRESENTATION

Infrastructure Security & Controls

Defense in depth, network segmentation, zero trust, layered host security, technical and administrative controls, personnel security, and reviewing security architectures for analyst-level evaluation.

Slide 1 — Defense in Depth & Zero Trust

Defense in Depth

The foundational security architecture principle: never rely on a single defensive control. Layer multiple independent defenses so that an attacker who bypasses one layer is still stopped by the next. Addresses all elements of CIA (Confidentiality, Integrity, Availability).

Layered security is difficult to design and implement correctly because each layer must account for business needs, usability, and the gaps between adjacent layers. Security theater — adding layers without evaluating their effectiveness — is the common failure mode.

Zero Trust Architecture

Removes the implicit trust that used to be placed in anything inside the network perimeter. Every access request — regardless of source — must be verified and validated before being granted.

  • Moves away from perimeter as the primary security layer
  • Every device, application, and user account is subject to verification
  • Requires blending of technologies, processes, and policies
  • "Never trust, always verify" — assume breach at all times
  • Enables: micro-segmentation, continuous monitoring, just-in-time access
Slide 2 — Network Segmentation

Why Segment?

Segmentation compartmentalizes the network to limit the blast radius of a breach. Benefits: reduces attack surface, limits regulatory compliance scope, increases availability of critical services by isolating failure domains, and increases network efficiency.

Physical Segmentation

Separate physical infrastructure and cabling. Air gaps for the highest security requirements (classified networks, OT/ICS systems). Maximum isolation — no shared hardware path between segments.

Virtual Segmentation

VLANs, virtual firewalls, VRFs, and micro-segmentation using software-defined networking. Logical separation on shared physical infrastructure. Faster to reconfigure but requires strict access controls on management planes.

System Isolation

Ensuring that specific high-value systems are separated from general network traffic. Containerization (Docker, Kubernetes) provides application-level isolation even on shared OS infrastructure.

Jump Box

A system that resides inside a segmented environment and is used to access and manage devices in that segment. Because it spans two security zones, the jump box itself must be hardened, patched, monitored, and protected with strong authentication. Compromise of the jump box defeats the entire segmentation strategy.

VPN

Virtual Private Networks provide encrypted tunnels for remote access and for bridging security zones. Encryption is not inherent in the VPN concept — most implementations use IPSec or TLS. Configuration errors and missing firmware patches are primary VPN vulnerability sources. Modern ZTNA (Zero Trust Network Access) is gradually replacing traditional VPNs.

Slide 3 — Network Architecture Types
Physical Network

Traditional routers, switches, firewalls, IDS/IPS, cabling, and security appliances. Forms the foundation — physical controls cannot be bypassed by software alone. Includes UTM (Unified Threat Management) appliances combining firewall, IPS, antivirus, and VPN.

  • Firewalls — rule-based traffic control
  • IPS/IDS — behavioral and signature detection
  • Content filtering and web proxies
  • NAC — Network Access Control
Software-Defined Network (SDN)

Makes networks programmable by separating the control plane from the data plane. Centralized network management via APIs enables rapid policy changes and automation. SD-WAN extends SDN to wide-area networks. Security considerations: API security and secure code development practices are critical components.

Virtualization & Containers

Virtual machines run on hypervisors. VDI streams desktops from central hardware. Containers (Docker, Kubernetes) isolate application environments. Serverless (AWS Lambda, Azure Functions) executes functions on demand. Each layer introduces new attack surfaces alongside the isolation benefits.

Slide 4 — Security Control Framework

Controls by Type and Function

Control Type Description Examples
Technical Use technology to reduce vulnerabilities Firewalls, IDS/IPS, encryption, NAC, DLP, EDR, authentication systems
Administrative Use management processes to reduce risk Incident response plans, account management, awareness training, change control
Physical Physical barriers and environmental controls Lighting, fences, security guards, locks, badge readers, cameras
Preventive Stop incidents before they occur Firewalls (block traffic), training (prevent phishing), guards (deny access)
Detective Identify and document incidents in progress IDS, SIEM alerts, audit logs, motion sensors, alarms
Corrective Remediate damage after an incident Patch management, antimalware cleanup, system restores from backup
Slide 5 — Layered Host Security

Endpoints: The Most At-Risk Network Layer

Servers, desktops, laptops, and smartphones are where users directly interact with systems — making them the most frequently targeted attack surface. Layered host security applies multiple independent controls to each endpoint.

Detection Controls
  • Antimalware / AV software
  • Host-based IPS (HIPS)
  • EDR (Endpoint Detection and Response) — continuous monitoring and threat response
  • File Integrity Monitoring (FIM)
  • Logging of all events and issues
Prevention Controls
  • Strong passwords and MFA
  • Host firewalls
  • Application whitelisting / blacklisting
  • Patch management — OS, applications, firmware
  • System hardening — disable unnecessary services
  • DLP (Data Loss Prevention) software
Data Protection
  • File-level encryption for sensitive data
  • Full disk encryption (BitLocker, FileVault) for data at rest
  • Key and passphrase management is critical — lost key = lost data
  • File hashing for integrity verification
  • Configuration management — enforce and validate settings
Slide 6 — Technical Controls Deep Dive

Active Defense Technologies

  • Sinkholing — Redirects malicious traffic from its intended destination to an analyst-controlled system for examination. Effective against botnet C2 (command-and-control) infrastructure.
  • Port Security — Switch-level control that monitors MAC addresses connecting to switch ports and allows or denies access based on a MAC whitelist. Prevents unauthorized device connection.
  • Sandboxing — Executes untrusted code in an isolated environment with full instrumentation to observe behavior. Enables dynamic malware analysis without risking production systems.
  • NAC (Network Access Control) — Requires authentication or posture assessment before network admission. Ensures only healthy, authorized devices connect.

Honeypots

Systems designed to appear as attractive targets to attackers — configured with deliberate vulnerabilities and fake valuable data. When an attacker interacts with a honeypot, analysts gain intelligence on:

  • Attacker tools and techniques
  • Attack sequences and timelines
  • What resources and data adversaries value
  • Novel attack methods not yet in signature databases

Honeynets (networks of honeypots) provide richer intelligence. Legal considerations apply — deliberate entrapment is distinct from passive observation.

Slide 7 — Malware Signatures & Detection

Beyond File Signatures

Traditional signature-based antivirus matches known malware hashes. Modern malware defeats this through polymorphism (changing its binary on each infection) and packing (obfuscating code). Modern detection requires multiple layers:

  • Behavior-based detection — Watches what an executable does rather than what it looks like. Catches polymorphic and previously unknown malware by identifying suspicious action sequences (file encryption, network beaconing, registry persistence).
  • Heuristic detection — Identifies code patterns statistically associated with malicious behavior without requiring an exact signature match.
  • Dynamic analysis (sandbox) — Executes malware in an instrumented environment and records all system calls, network activity, and file operations. Produces behavioral indicators of compromise (IOCs).
  • Threat intelligence feeds — Real-time IOC feeds from threat intelligence providers enable rapid detection of known bad IPs, domains, and file hashes across the organization.
Slide 8 — Personnel Security Controls

Separation of Duties

No single person completes a sensitive task alone. Divides critical functions to prevent fraud and abuse.

Dual Control

Two individuals must simultaneously perform an action (e.g., unlocking a server room or safe). Stronger than separation of duties.

Mandatory Vacations

Forces continuous-access users to step away, allowing concealed fraud or unauthorized activity to surface.

Background Checks

Criminal history, credit, and reference verification prior to hiring. Financial institutions often require credit checks for access to financial systems.

Cross-Training

Ensures critical duties have backup personnel. Prevents single point of knowledge failure and enables normal operations during absences.

Succession Planning

Identifies who performs critical functions if primary personnel leave. Primary and backup administrators for every critical system.

Termination Procedures

Structured offboarding: retrieve company property, disable all accounts, change shared credentials, and revoke physical access on the termination date.

Change Control

Formal process for approving infrastructure changes. Prevents unauthorized modifications and provides audit trail for security reviews.

ARCHITECTURE REVIEW METHODOLOGY

When reviewing a security architecture, examine three views: (1) Operational — how is the function performed? (2) Technical — what technologies, configurations, and settings are in use? (3) Logical — how are systems interconnected? The exam tests all three. Common findings: single points of failure, missing data validation, authentication and authorization weaknesses, and user behavior gaps. Identifying these systematically — not just hunting for known CVEs — defines the infrastructure security analyst role.
