Scenario: Secure Workstation Deployment for a Government Contractor

You are the security architect for a company that handles Controlled Unclassified Information (CUI) for a DoD contract. Design the hardware security stack for 500 employee workstations.

Hardware Security Hierarchy: Root of Trust Chain

Hardware Root of Trust (Firmware/UEFI) > TPM 2.0 > Secure Boot > OS Integrity Verification > Application Layer. Each layer depends on the integrity of the layer below it. If the hardware root of trust is compromised, no software security measure can compensate.

Hardware ControlCUI Protection FunctionConfiguration Requirement
TPM 2.0Enables BitLocker full-disk encryption, secure boot attestation, platform integrity measurementMust be enabled in UEFI, firmware version verified, BitLocker configured with TPM+PIN policy
Secure BootPrevents boot-level rootkits and unauthorized OS loading — ensures only signed bootloaders executeUEFI Secure Boot enabled, custom keys deployed, legacy BIOS mode disabled
Self-Encrypting Drive (SED)Hardware-level encryption independent of OS — protects data if drive is removed from laptopPre-boot authentication configured, encryption key management via enterprise key server
HSM (for CA/PKI)Protect the private keys of your PKI certificate authority — if CA key is stolen, all certs are untrustedFIPS 140-2 Level 3 HSM for root CA, Level 2 acceptable for issuing CAs
