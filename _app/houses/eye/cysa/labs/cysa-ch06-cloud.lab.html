Scenario: AWS Account Security Audit

You ran ScoutSuite against your AWS production account. Review the simulated findings below and develop a remediation plan addressing the most critical issues first.

SCOUTSUITE AWS AUDIT REPORT — prod-account-12345 Generated: 2026-02-21 [DANGER] EC2 Security Groups — 3 findings [!] Security group "sg-prod-web" allows inbound 0.0.0.0/0 on port 22 (SSH) Risk: SSH exposed to the entire internet. Brute-force, credential stuffing. Fix: Restrict SSH to specific IP ranges (VPN egress IPs only) [!] Security group "sg-prod-db" allows inbound 0.0.0.0/0 on port 3306 (MySQL) Risk: Database exposed to internet — any attacker can attempt to connect. Fix: Restrict MySQL to application server security group only. [!] Security group "sg-lambda" allows all outbound traffic (0.0.0.0/0) Risk: Compromised Lambda can exfiltrate data to any destination. Fix: Restrict outbound to required destinations only. [WARNING] IAM — 4 findings [!] Root account has no MFA enabled Risk: Root account compromise = total account loss. Fix: Enable MFA on root immediately. Do not use root for daily tasks. [!] 3 IAM users have AdministratorAccess policy attached Risk: Excessive admin privileges increase blast radius of credential compromise. Fix: Apply least privilege — remove AdministratorAccess where not required. [!] Access keys older than 90 days exist for 5 users Risk: Long-lived credentials increase window of opportunity if stolen. Fix: Rotate access keys every 90 days. Enable access key rotation policy. [!] IAM password policy does not enforce minimum 12 character length Risk: Weak passwords susceptible to brute force. Fix: Update IAM password policy: minLength=12, require mixed case, numbers, symbols. [INFO] S3 — 2 findings [i] S3 bucket "prod-logs-archive" has versioning disabled Risk: Accidental deletion or ransomware encryption would be unrecoverable. Fix: Enable versioning and lifecycle policies. [i] S3 bucket "prod-assets" ACL allows authenticated AWS users read access Risk: Any authenticated AWS account worldwide can read this bucket. Fix: Switch to bucket policy restricting access to your account only.

Remediation Priority Plan

Write a prioritized remediation plan for the top 4 findings. For each, specify: the exact fix, who is responsible (cloud team vs. security team vs. management), and how you would verify remediation is complete.

Scenario: Shadow IT and DLP for a Financial Firm

A financial services firm discovered employees are uploading client financial data to personal Dropbox accounts. Additionally, 47 unsanctioned cloud applications have been detected in network logs. Management wants a CASB solution to provide visibility and enforcement. Design the deployment architecture.

CASB Decision Framework

  • Need to BLOCK requests in real time? Use inline CASB (proxy or endpoint agent)
  • Need visibility into SaaS usage without device changes? Use API-based CASB
  • Need both blocking AND SaaS visibility? Deploy both modes (many vendors support this)
  • Key use case for inline: Prevent uploads to unsanctioned apps before they happen
  • Key use case for API: Monitor and remediate policy violations in M365, Google Workspace

CASB Architecture Proposal

Write a CASB deployment recommendation for this financial firm. Specify: inline vs API mode (or both) and why, the cloud applications to monitor, three specific DLP policies to configure, and how you would handle the 47 discovered shadow IT applications (block all? block some? create approved alternatives?).
