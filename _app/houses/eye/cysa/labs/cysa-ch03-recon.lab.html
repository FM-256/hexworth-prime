DNS enumeration is the first active step in most penetration tests. Understanding what information DNS reveals, what defenses prevent enumeration, and how to interpret results is a core analyst skill.

OSSTMM vs. PTES: Framework Guidance for Active Scanning

  • OSSTMM (Open Source Security Testing Methodology Manual): Defines operational security testing; emphasizes measuring actual security surface area via RAV (Risk Assessment Value)
  • PTES (Penetration Testing Execution Standard): Seven-phase framework; Pre-engagement, Intelligence Gathering, Threat Modeling, Vulnerability Analysis, Exploitation, Post-Exploitation, Reporting
  • Active scanning begins in PTES Phase 2 (Intelligence Gathering) and continues through Phase 4 (Vulnerability Analysis)
  • Both frameworks require written authorization before any active scanning begins

Defense Design: Detecting and Preventing Reconnaissance

Scenario: Hardening the Intelligence-Gathering Attack Surface

After a red team engagement, the report lists 12 findings related to excessive information disclosure during reconnaissance. Your job is to build a comprehensive anti-reconnaissance strategy covering technical controls, network architecture, and detection capabilities.

ANTI-RECONNAISSANCE DEFENSE FRAMEWORK: PASSIVE RECON REDUCTION: DNS Hardening: - Restrict zone transfers to authorized slave servers only - Remove internal hostnames from external DNS (split-horizon DNS) - Minimize TXT record disclosure (review SPF, DMARC for over-sharing) - Use privacy services for WHOIS registrant information - Register domain variations to prevent squatting and phishing setup Document and Metadata Control: - Strip metadata from all public-facing documents before publishing - Use document DLP to prevent internal paths/usernames from leaking - Review GitHub/GitLab public repos for credential and config exposure - Monitor job postings for technology stack disclosure (use generic terms) - Social media policy: prohibit employees from disclosing vendor names ACTIVE RECON DETECTION: Network-Level Controls: - IDS/IPS rules: flag sequential port scans (SYN count thresholds) - Firewall logging: log ALL deny events, not just allows - Netflow analysis: detect horizontal scan patterns (1 src, many dst) - Honeypot ports: flag any connection to non-advertised services - Rate limiting on DNS: prevent rapid subdomain brute force Endpoint and Application: - WAF rules: detect scanner user-agents (Nikto, sqlmap, Nessus) - Web server: suppress version disclosure in HTTP headers (Server:) - Error pages: generic 404/500 pages only, no stack traces - Banner suppression: remove SSH, FTP, SMTP version banners DETECTION ANALYSIS METHODS: Anomaly: Baseline traffic, alert on deviations (statistical model) Trend: Track scan frequency over time; increasing trend = probe Signature: Match known scan patterns (SYN flood, XMAS scan signatures) Behavioral: Profile normal host behavior; flag unusual port diversity
