Scenario: Design SIEM Rules for Common Attack Patterns

Your SIEM has raw log ingestion but no detection rules for critical attack patterns. Write the logic for 3 correlation rules that would have detected the attack in Exercise 2 earlier.

Correlation Rule Components

  • Condition: The event pattern or threshold that must match (WHAT to look for)
  • Time Window: The period over which the condition is evaluated (e.g., within 5 minutes)
  • Data Sources: Which log types feed this rule (firewall, web app, DB audit)
  • Action: What happens when the rule fires (alert, block, ticket, page on-call)
  • Severity: HIGH / MEDIUM / LOW / CRITICAL
Rule NameDetection PatternTime WindowAction
SQL Injection Probe Detection Web server returns HTTP 500 errors on same URL with parameter variations, followed by HTTP 200 on UNION/SELECT payloads from same source IP 5 minutes HIGH alert, block source IP at WAF, notify security team
Webshell Upload Detection HTTP POST to upload directory results in creation of .php, .aspx, or .jsp file, followed by HTTP GET to that same file within 10 minutes 10 minutes CRITICAL alert, isolate web server, immediate escalation
Database Mass Exfiltration Single database user account returns more than 500 rows in any query, or total rows returned in 10 minutes exceeds 1000, from application user account 10 minutes HIGH alert, kill DB session, notify DBA and security team

Scenario: Phishing Email Investigation

The accounting department received an email claiming to be from the CFO requesting an urgent wire transfer. Analyze the email headers to determine if it is a spoofed phishing email.

From: "CFO John Williams" <jwilliams@company.com> Reply-To: urgent-finance@gmail.com Subject: URGENT: Wire Transfer Required Today Date: Mon, 15 Mar 2024 09:23:14 +0800 Received: from mail-yw1-x12b.google.com (209.85.161.99) by company-mx.company.com Received: from [192.168.5.45] by mail-yw1-x12b.google.com Authentication-Results: company-mx.company.com; spf=fail (sender IP 209.85.161.99 is not in SPF record for company.com); dkim=fail (no DKIM signature found matching company.com); dmarc=fail action=none (p=none; dis=none) header.from=company.com X-Originating-IP: 192.168.5.45 X-Mailer: Microsoft Outlook 16.0 Message: Please process a $45,000 wire transfer to our new vendor immediately. Vendor: Global Trade Partners LLC Account: 8834729103 Routing: 021000089 This is time-sensitive. Do not call me - I am in meetings all day. - John Williams, CFO

Email Authentication Result Interpretation

  • SPF=fail: Sending server IP (209.85.161.99 = Gmail) is not authorized to send as company.com
  • DKIM=fail: No valid DKIM signature from company.com domain exists — email was not signed by company.com mail infrastructure
  • DMARC=fail + p=none: Both SPF and DKIM failed but DMARC policy is "none" — meaning it only reports, does NOT reject or quarantine. This is a misconfiguration allowing spoofed emails through.
  • Reply-To mismatch: Display address shows company.com but replies go to gmail.com — a classic BEC technique
