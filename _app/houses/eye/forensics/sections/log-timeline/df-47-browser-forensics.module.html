Browser Artifact Locations

Browser data is stored in well-known locations on each operating system. Chromium-based browsers (Chrome, Edge, Brave, Opera) share a similar structure. Firefox uses its own format. All modern browsers store structured data in SQLite databases.

Browser Windows Path Key Files
Chrome %LOCALAPPDATA%\Google\Chrome\User Data\Default\ History, Cookies, Login Data, Web Data, Bookmarks, Preferences
Edge %LOCALAPPDATA%\Microsoft\Edge\User Data\Default\ Same as Chrome (Chromium-based)
Firefox %APPDATA%\Mozilla\Firefox\Profiles\*.default-release\ places.sqlite, cookies.sqlite, formhistory.sqlite, logins.json
Safari (macOS) ~/Library/Safari/ History.db, Downloads.plist, Bookmarks.plist

Database Locking

SQLite databases used by running browsers may be locked. On a live system, copy the files before querying. On a forensic image, this is not an issue. Some databases also have Write-Ahead Log (WAL) files (-wal and -shm) that contain recent uncommitted data -- always collect these alongside the main database.

History Database Analysis

The browsing history database is the most frequently examined browser artifact. Chrome and Edge store history in a SQLite file named History. Firefox stores it in places.sqlite.

Chrome/Edge History -- SQL Queries
-- All visited URLs with timestamps (Chrome epoch: microseconds since 1601-01-01)
SELECT
    datetime(last_visit_time/1000000 - 11644473600, 'unixepoch') as visit_time,
    url,
    title,
    visit_count,
    typed_count
FROM urls
ORDER BY last_visit_time DESC;

-- Visit details with transition types
SELECT
    datetime(v.visit_time/1000000 - 11644473600, 'unixepoch') as visit_time,
    u.url,
    u.title,
    CASE v.transition & 0xFF
        WHEN 0 THEN 'Link'
        WHEN 1 THEN 'Typed'
        WHEN 2 THEN 'Auto Bookmark'
        WHEN 3 THEN 'Auto Subframe'
        WHEN 5 THEN 'Form Submit'
        WHEN 6 THEN 'Reload'
        WHEN 7 THEN 'Generated'
    END as transition_type
FROM visits v
JOIN urls u ON v.url = u.id
ORDER BY v.visit_time DESC;

-- Downloads with source URLs and file paths
SELECT
    datetime(start_time/1000000 - 11644473600, 'unixepoch') as download_time,
    tab_url as source_url,
    target_path,
    total_bytes,
    mime_type,
    CASE state WHEN 0 THEN 'In Progress' WHEN 1 THEN 'Complete' WHEN 2 THEN 'Cancelled' END as status
FROM downloads
ORDER BY start_time DESC;
Firefox places.sqlite -- SQL Queries
-- Firefox browsing history (uses standard Unix epoch in microseconds)
SELECT
    datetime(v.visit_date/1000000, 'unixepoch') as visit_time,
    p.url,
    p.title,
    p.visit_count,
    CASE v.visit_type
        WHEN 1 THEN 'Link'
        WHEN 2 THEN 'Typed'
        WHEN 3 THEN 'Bookmark'
        WHEN 4 THEN 'Embed'
        WHEN 5 THEN 'Redirect Permanent'
        WHEN 6 THEN 'Redirect Temporary'
        WHEN 7 THEN 'Download'
    END as visit_type
FROM moz_historyvisits v
JOIN moz_places p ON v.place_id = p.id
ORDER BY v.visit_date DESC;

Additional Browser Artifacts

Cache Cached web content (images, scripts, HTML). Chrome uses a proprietary format in the Cache directory. Tools like ChromeCacheView or NirSoft can extract cached content including resources from visited sites.
Cookies Session tokens, tracking identifiers, authentication state. The Cookies SQLite database maps domains to cookie values with expiration dates. Can prove site access even if history was deleted.
Local Storage / IndexedDB Web application data stored persistently. Can contain login state, application configuration, cached API responses, and user-generated content for web apps.
Form Autofill Data Stored in Web Data (Chrome) or formhistory.sqlite (Firefox). Contains text entered into form fields -- names, addresses, search queries, usernames. Highly revealing of user activity.
Bookmarks Chrome: JSON file (Bookmarks). Firefox: embedded in places.sqlite. Bookmarked URLs indicate intentional interest. Timestamps show when bookmarks were added.
Extensions Installed browser extensions in the Extensions directory. Malicious extensions can steal credentials, inject ads, or exfiltrate data. Check extension IDs against known malicious lists.

Incognito / Private Mode

Incognito mode prevents the browser from writing history, cookies, and form data to disk after the session ends. However, it does not provide complete privacy from forensic analysis:

What IS Protected Browser history, cookies, form data, and site data are deleted when the incognito window closes. No entries appear in the History database after the session.
What Is NOT Protected Downloaded files remain on disk. DNS cache may retain lookups. RAM may contain session data (memory forensics). Network traffic is logged by firewalls/proxies. Websites log your visits server-side.

Memory Forensics and Incognito

If the incognito session is still active (or was recently closed), memory forensics can recover URLs, page content, and session data. The Chrome process stores page content in heap memory that may persist even after the tab is closed, until the memory is reallocated. Tools like Volatility's chromehistory plugin target this data.

Practice: Analyze Browser Evidence

Given this SQL query result from a suspect's Chrome History database, answer the questions below:

visit_time           | url                                           | typed_count
2026-03-15 09:12:01  | https://mail.google.com/                        | 1
2026-03-15 09:15:33  | https://mail.google.com/mail/#inbox/FMfcgz...   | 0
2026-03-15 09:15:48  | https://drive.google.com/file/d/1xK.../view    | 0
2026-03-15 09:16:02  | https://suspicious-domain.xyz/invoice.pdf       | 0
2026-03-15 09:16:44  | https://suspicious-domain.xyz/download/payload  | 0
2026-03-15 09:20:11  | https://www.google.com/search?q=how+to+open+.hta+file | 1
2026-03-15 09:22:05  | https://stackoverflow.com/questions/hta-file    | 0
  1. What was the likely attack vector?
  2. Which entries indicate user interaction vs. automatic navigation?
  3. What does the Google search suggest about the payload?

Analysis: (1) Phishing email via Gmail -- user opened an email, clicked a Drive link that redirected to a malicious domain. (2) typed_count=1 entries were directly navigated; typed_count=0 entries were reached via links/redirects. (3) The search for "how to open .hta file" suggests the downloaded payload was an HTA file, and the user was unfamiliar with the format -- indicating the attack may have required user action to execute.

Key Takeaways

  • Browser artifacts are stored in SQLite databases at well-known OS-specific paths
  • Chrome uses a custom epoch (microseconds since 1601-01-01) -- conversion is required
  • Always collect WAL and SHM files alongside main SQLite databases
  • Incognito mode does not survive memory forensics, DNS cache, or network monitoring
  • Downloaded files persist on disk regardless of browsing mode
  • Hindsight automates Chromium artifact parsing into an investigation-ready spreadsheet
  • Form autofill data can reveal searches, usernames, and personal information
