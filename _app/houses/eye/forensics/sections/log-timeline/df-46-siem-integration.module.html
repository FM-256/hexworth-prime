SIEM Architecture

A Security Information and Event Management (SIEM) system collects, normalizes, correlates, and stores log data from across the enterprise. For forensic investigators, a properly configured SIEM is a force multiplier -- it provides pre-indexed, searchable, correlated data that would otherwise require hours of manual log parsing.

Collection Agents, syslog forwarding, API integrations, file monitoring. Collects logs from endpoints, servers, network devices, cloud services, and applications into a central repository.
Normalization Parses raw log formats into structured fields. A "source IP" is extracted regardless of whether the original log called it src_ip, client, or RemoteAddress.
Correlation Rules engine that links events across sources. Detects patterns like "failed login from IP X on host A, followed by successful login from IP X on host B within 5 minutes."
Storage & Search Indexed storage enabling fast full-text and field-based searches across millions of events. Retention periods from 90 days to 7+ years depending on policy.

Splunk SPL for Forensics

Splunk's Search Processing Language (SPL) is widely used in enterprise SOCs. These queries demonstrate forensic analysis patterns:

Splunk SPL -- Forensic Queries
| Find all events from a specific IP across all indexes
index=* src_ip="203.0.113.77" OR dest_ip="203.0.113.77"
| sort _time
| table _time, index, sourcetype, src_ip, dest_ip, action, user

| Brute force detection -- failed logins followed by success
index=windows sourcetype=WinEventLog:Security EventCode=4625 OR EventCode=4624
| sort _time
| transaction src_ip maxspan=30m
| where eventcount > 5
| search EventCode=4624
| table _time, src_ip, user, eventcount

| Suspicious process creation (living off the land binaries)
index=sysmon EventCode=1
| search (process_name="powershell.exe" OR process_name="cmd.exe"
    OR process_name="certutil.exe" OR process_name="mshta.exe"
    OR process_name="regsvr32.exe" OR process_name="wmic.exe")
| stats count by process_name, parent_process_name, user, CommandLine
| sort -count

| Data exfiltration -- large outbound transfers
index=firewall action=allowed direction=outbound
| stats sum(bytes_out) as total_bytes by src_ip, dest_ip
| where total_bytes > 104857600
| sort -total_bytes
| eval total_MB = round(total_bytes/1048576, 2)
| table src_ip, dest_ip, total_MB

| Account creation and privilege escalation timeline
index=windows sourcetype=WinEventLog:Security
    (EventCode=4720 OR EventCode=4722 OR EventCode=4732 OR EventCode=4672)
| sort _time
| table _time, EventCode, Account_Name, Group_Name, Logon_ID

Elasticsearch / Kibana KQL

The Elastic Stack (ELK) is the most common open-source SIEM platform. Kibana Query Language (KQL) provides a simplified search syntax for forensic analysis.

Kibana KQL -- Forensic Queries
# All events from a suspect IP in the last 7 days
source.ip: "203.0.113.77" or destination.ip: "203.0.113.77"

# Failed SSH logins
event.action: "ssh_login" and event.outcome: "failure"

# PowerShell execution events
process.name: "powershell.exe" and event.category: "process"

# File creation in suspicious directories
event.action: "creation" and file.path: (*\\Temp\\* or *\\tmp\\* or *\\Downloads\\*)

# DNS queries to suspicious TLDs
dns.question.name: (*.tk or *.xyz or *.top or *.buzz) and network.direction: "outbound"
Elasticsearch DSL -- Aggregation Query
GET /logs-*/_search
{
  "size": 0,
  "query": {
    "bool": {
      "must": [
        { "term": { "event.action": "authentication_failure" } },
        { "range": { "@timestamp": { "gte": "now-24h" } } }
      ]
    }
  },
  "aggs": {
    "by_source": {
      "terms": { "field": "source.ip", "size": 20 },
      "aggs": {
        "by_user": {
          "terms": { "field": "user.name", "size": 10 }
        }
      }
    }
  }
}

Correlation Rules

Effective SIEM correlation rules codify known attack patterns. These rules automatically flag suspicious activity for investigation.

Rule Name Correlation Logic Severity
Brute Force Success 5+ failed logins from same source IP within 10 minutes, followed by successful login from same IP within 5 minutes High
Impossible Travel Successful logins from two geographically distant locations within a timeframe shorter than possible travel time High
Service Account Interactive Login Service accounts (svc_*) performing interactive (Type 2) or RDP (Type 10) logon Critical
Log Source Silence Expected log source stops sending events for > 15 minutes during business hours Medium
Lateral Movement Chain Authentication from host A to B, then B to C, within 30 minutes using the same credentials Critical

Log Retention Policies

Retention policies determine how long evidence is available in the SIEM. Different regulatory frameworks impose different requirements:

Framework Minimum Retention Notes
PCI DSS1 year (3 months online)Audit trail for cardholder data access
HIPAA6 yearsAll security-related logs
SOX7 yearsFinancial system audit trails
NIST 800-171Not specified (3+ years recommended)CUI access and security events
GDPRAs short as possibleData minimization principle -- balance with security needs

Retention vs. Storage Cost

A SIEM ingesting 500GB/day requires 182TB for one year of hot storage. Most organizations use tiered retention: 90 days hot (searchable), 1 year warm (archived, slower search), 7 years cold (compliance archive, manual retrieval). Define retention tiers based on regulatory requirements and investigation needs.

Practice: Write SIEM Queries

Write Splunk SPL or KQL queries for the following forensic scenarios:

  1. Find all RDP (LogonType 10) connections to domain controllers in the last 48 hours
  2. Identify the top 10 source IPs generating authentication failures
  3. Find all instances where PowerShell downloaded content from the internet
  4. Detect event log clearing (Event ID 1102) across all Windows hosts

Sample SPL Answers:

| 1. RDP to domain controllers
index=windows EventCode=4624 LogonType=10 dest_category="domain_controller"
| table _time, src_ip, user, dest

| 2. Top failed auth sources
index=* tag=authentication action=failure earliest=-48h
| stats count by src_ip | sort -count | head 10

| 3. PowerShell downloads
index=sysmon EventCode=1 process_name="powershell.exe"
| search CommandLine="*Net.WebClient*" OR CommandLine="*Invoke-WebRequest*"
    OR CommandLine="*wget*" OR CommandLine="*curl*" OR CommandLine="*DownloadFile*"

| 4. Log clearing events
index=windows EventCode=1102
| table _time, host, user, Message

Key Takeaways

  • SIEMs provide pre-indexed, normalized, correlated data that accelerates forensic analysis
  • Splunk SPL and Elasticsearch KQL are the two most common SIEM query languages
  • Correlation rules automate detection of multi-stage attack patterns
  • Log retention policies must balance regulatory requirements against storage costs
  • Tiered retention (hot/warm/cold) manages the cost of long-term log storage
  • SIEM data is only as good as the sources feeding it -- coverage gaps mean evidence gaps
