Learning Objectives

  • Reconstruct a complete ransomware attack timeline from multiple evidence sources
  • Correlate Windows event logs, Sysmon, firewall, email, browser, registry, and file system evidence
  • Identify initial access, execution, persistence, lateral movement, and impact phases
  • Produce a professional investigation report with evidence citations

Scenario: Ransomware Incident

On Monday 2026-03-16 at 06:15 UTC, the IT team at Meridian Financial Services discovered that the shared file server (FS01, 10.1.1.100) had been encrypted. All files had the .lockbit3 extension. A ransom note named README_RESTORE.txt was found in every directory. You have been engaged to investigate.

Your task is to analyze the evidence from seven sources, construct a complete attack timeline, and deliver a structured investigation report.

Scope

Three systems are in scope: Workstation WS-JCOOPER (10.1.1.15), Domain Controller DC01 (10.1.1.10), and File Server FS01 (10.1.1.100). All timestamps are in UTC.

Investigation Report Template

1. Executive Summary High-level overview for non-technical leadership. Scope, impact, cause, and recommended actions in 1 page.
2. Incident Timeline Chronological event table with timestamps, descriptions, evidence sources, and ATT&CK mappings. The core deliverable.
3. Evidence Inventory List of all evidence collected: hashes, acquisition method, chain of custody, storage location.
4. Technical Analysis Detailed findings per evidence source. IOCs extracted (IPs, domains, file hashes, registry keys). Malware analysis summary.
5. Root Cause Analysis How the attack succeeded. Contributing factors: no email authentication (DMARC), macros enabled, service account with excessive privileges, no network segmentation.
6. Recommendations Immediate: Reset all credentials, isolate affected systems, block IOCs. Long-term: Implement DMARC, disable macros by policy, segment network, deploy EDR.

Capstone Exercise

Using the evidence above, answer these investigation questions:

  1. What was the dwell time (initial access to impact)?
  2. What credential was used for lateral movement, and how was it likely obtained?
  3. List all Indicators of Compromise (IOCs) from this investigation.
  4. What security controls failed, and what would you recommend?
  5. Why did the firewall block the FS01 C2 connection but allow the WS-JCOOPER one?

Answers: (1) ~45 hours (Mar 14 08:33 to Mar 16 05:30). (2) svc_backup service account -- likely obtained via Kerberoasting (RC4 encrypted service tickets cracked offline). (3) IOCs: IP 198.51.100.42, domain m3ridian-financial.com, file payload.dll, file locker.exe, registry key "WindowsDefenderUpdate", extension .lockbit3. (4) No DMARC enforcement (phishing delivered), macros enabled (execution), service account in Domain Admins (privilege), flat network (lateral movement). (5) Likely because FS01 was on a server VLAN with stricter egress rules, while the workstation VLAN allowed outbound HTTPS -- demonstrating partial but insufficient network segmentation.

Key Takeaways

  • Ransomware attacks follow a predictable kill chain: phishing, execution, persistence, credential access, lateral movement, impact
  • Dwell time reveals how long the attacker had access before encryption -- this determines the scope of compromise
  • Every evidence source fills gaps that others miss -- no single source tells the complete story
  • ATT&CK mapping structures your findings and enables comparison with known threat actor TTPs
  • A professional report requires both an executive summary and detailed technical analysis
  • Root cause analysis should identify contributing security control failures, not just the attack chain
