What is NetFlow?

NetFlow, developed by Cisco, summarizes network traffic into flow records. Instead of capturing every packet (which requires massive storage), NetFlow records metadata about each conversation: who talked to whom, on what ports, how much data, and when.

Think of NetFlow as the phone bill of your network. It does not record the conversation content, but it tells you every call made, to whom, how long, and how much data was exchanged. For forensic investigations, this metadata is often sufficient to map attacker activity across the entire network.

NetFlow vs Full Packet Capture

  • NetFlow: ~0.5% storage of full capture. Weeks/months of retention feasible
  • Full PCAP: 100% of traffic. Hours/days of retention at high bandwidth
  • NetFlow shows WHO communicated; PCAP shows WHAT was communicated
  • Best practice: NetFlow for long-term visibility, PCAP for targeted deep analysis

NetFlow Versions

Feature NetFlow v5 NetFlow v9 IPFIX

Flow Record Fields

A flow record contains the metadata for a single network conversation (defined by the 5-tuple or 7-tuple):

NetFlow v5 Record Structure
# The 7-tuple that defines a unique flow:
Source IP:        10.0.0.50
Destination IP:   185.234.52.18
Source Port:      49301
Destination Port: 443
Protocol:         TCP (6)
Type of Service:  0
Input Interface:  GigabitEthernet0/1

# Additional flow metadata:
Start Time:       2024-03-15 14:32:18
End Time:         2024-03-15 15:47:22
Duration:         4504 seconds
Packets:          12,847
Bytes:            4,218,304
TCP Flags:        .AP.SF (ACK, PUSH, SYN, FIN)

Forensic Analysis Patterns

Beaconing Detection Flows with regular intervals (e.g., every 60 seconds) to the same destination. Sort by destination and look for repeating time deltas. C2 beacons are rarely perfectly periodic -- look for consistent intervals with slight jitter.
Large Data Transfers Sort flows by byte count descending. Outbound flows with gigabytes of data to external IPs are exfiltration candidates. Compare against normal upload patterns for the source host.
Lateral Movement A single internal IP connecting to many internal hosts on SMB (445), RDP (3389), WinRM (5985), or SSH (22). Normal workstations connect to few internal servers; compromised ones scan broadly.
Unusual Protocols ICMP flows with high byte counts (tunneling), GRE (protocol 47), or traffic on uncommon ports. Baseline your network to know what is normal.

Analysis Tools

nfdump Analysis Commands
# Top 10 talkers by bytes (outbound)
$ nfdump -r flows.nfcapd -s srcip/bytes -n 10

# Show all flows from a specific source IP
$ nfdump -r flows.nfcapd 'src ip 10.0.0.50'

# Find flows to a known C2 IP
$ nfdump -r flows.nfcapd 'dst ip 185.234.52.18'

# Detect lateral movement: internal to internal on SMB
$ nfdump -r flows.nfcapd 'src net 10.0.0.0/8 and dst net 10.0.0.0/8 and dst port 445'

# Long-duration flows (persistent C2 connections)
$ nfdump -r flows.nfcapd -s record/duration -n 20

# Unusual ports (not 80, 443, 53, 22)
$ nfdump -r flows.nfcapd 'not dst port in [80 443 53 22 25 993 587]' \
    -s dstport/flows -n 20

# Time-series analysis for beaconing
$ nfdump -r flows.nfcapd 'dst ip 185.234.52.18' -o fmt:%ts,%sa,%da,%dp,%byt
SiLK Analysis Commands
# SiLK (System for Internet-Level Knowledge) -- NSA-developed flow analysis

# Query flows for a specific IP
$ rwfilter --start=2024/03/15 --end=2024/03/15 \
    --saddress=10.0.0.50 --type=all --pass=stdout | rwcut

# Top destination ports
$ rwfilter --start=2024/03/15 --type=all --pass=stdout | \
    rwstats --fields=dport --values=flows,bytes --count=20

# Detect scanning (many destinations, few packets per flow)
$ rwfilter --start=2024/03/15 --type=out \
    --packets=1-3 --pass=stdout | \
    rwstats --fields=sip --values=flows --count=10

Practice: Flow Analysis Scenarios

Analyze these flow records and identify the suspicious activity:

Start Time          Src IP       Dst IP          Port  Proto  Bytes     Pkts
14:32:18  10.0.0.50    185.234.52.18   443   TCP    4,218,304  12,847
14:32:20  10.0.0.50    185.234.52.18   443   TCP      128,000     320
14:33:20  10.0.0.50    185.234.52.18   443   TCP      128,512     322
14:34:20  10.0.0.50    185.234.52.18   443   TCP      127,488     318
14:35:44  10.0.0.50    10.0.0.10       445   TCP    2,048,000   4,096
14:36:02  10.0.0.50    10.0.0.11       445   TCP    1,536,000   3,072
14:36:15  10.0.0.50    10.0.0.12       445   TCP    1,024,000   2,048
14:36:30  10.0.0.50    10.0.0.13       3389  TCP       24,576      48
  1. What is the beaconing interval to 185.234.52.18?
  2. What does the first flow to 185.234.52.18 suggest compared to the subsequent flows?
  3. What is happening with the internal connections on port 445?
  4. What does the connection to port 3389 indicate?

Answers:

1. 60-second beaconing interval (14:32:20, 14:33:20, 14:34:20). 2. The first flow is much larger (4.2 MB vs 128 KB) -- likely the initial payload download, followed by periodic beacon check-ins. 3. Lateral movement via SMB to three internal servers with significant data transfer (1-2 MB each -- possibly file copying or PsExec deployment). 4. RDP connection attempt to 10.0.0.13 -- the attacker is trying to gain interactive GUI access to another workstation or server.

Key Takeaways

  • NetFlow provides network metadata at ~0.5% of full packet capture storage
  • Flow records show who communicated, when, how much, and on what ports
  • Beaconing detection relies on identifying regular time intervals to the same destination
  • Lateral movement shows as a single host connecting to many internal hosts on admin ports
  • nfdump and SiLK are the primary open-source flow analysis tools
  • Combine flow analysis with PCAP for complete investigation coverage
