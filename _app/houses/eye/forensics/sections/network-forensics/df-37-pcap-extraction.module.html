Learning Objectives

  • Extract files from PCAP using Wireshark, NetworkMiner, and foremost
  • Recover cleartext credentials from network captures
  • Extract indicators of compromise (IPs, domains, URLs, hashes)
  • Generate Zeek (Bro) logs from PCAP files for structured analysis
  • Automate evidence extraction with tshark

File Extraction Methods

Wireshark Export Objects File > Export Objects > HTTP/SMB/TFTP/IMF. Reassembles files from protocol-level data. Best for HTTP downloads, SMB file transfers, and email attachments.
NetworkMiner Automatic file extraction, OS fingerprinting, and credential harvesting from PCAP. Extracts images, documents, executables, and certificates. GUI-based, excellent for quick triage.
foremost / binwalk File carving from raw data. Searches for magic bytes (file signatures) regardless of protocol. Use on raw TCP stream data when protocol-aware tools fail.
tshark --export-objects Command-line extraction for scripted/automated processing. Supports HTTP, SMB, DICOM, IMF, and TFTP protocols. Ideal for batch processing multiple PCAPs.
Automated File Extraction
# tshark: extract all HTTP objects
$ tshark -r evidence.pcap --export-objects http,./http_files/

# tshark: extract all SMB objects
$ tshark -r evidence.pcap --export-objects smb,./smb_files/

# List extracted files with types
$ file ./http_files/*
update.dll:      PE32+ executable (DLL) x86-64
invoice.pdf:     PDF document, version 1.7
logo.png:        PNG image data, 200 x 50
config.php:      PHP script text

# Hash all extracted files for IOC generation
$ sha256sum ./http_files/* > file_hashes.txt
$ md5sum ./http_files/* >> file_hashes.txt

# Scan with YARA rules
$ yara -r malware_rules.yar ./http_files/
Emotet_Payload ./http_files/update.dll

Credential Extraction

Cleartext protocols expose credentials directly in packet captures. This is critical both for understanding what the attacker accessed and for identifying credential exposure that requires password resets.

Extracting Credentials from PCAP
# HTTP Basic Authentication (base64-encoded, not encrypted)
$ tshark -r evidence.pcap -Y "http.authorization" \
    -T fields -e ip.src -e http.host -e http.authorization

10.0.0.50  admin-portal.local  Basic YWRtaW46UEBzc3cwcmQxMjM=
# Decode: echo "YWRtaW46UEBzc3cwcmQxMjM=" | base64 -d
# Result: admin:P@ssw0rd123

# FTP credentials
$ tshark -r evidence.pcap -Y "ftp.request.command == USER or ftp.request.command == PASS" \
    -T fields -e ip.src -e ftp.request.command -e ftp.request.arg

10.0.0.50  USER  admin
10.0.0.50  PASS  Summer2024!

# HTTP POST form data (login forms)
$ tshark -r evidence.pcap -Y "http.request.method == POST" \
    -T fields -e ip.src -e http.host -e http.file_data | \
    grep -i "user\|pass\|login\|pwd"

# Telnet credentials (character-by-character, follow TCP stream)
$ tshark -r evidence.pcap -Y "telnet" -z follow,tcp,ascii,0

Credential Exposure Response

Any credential found in cleartext in a PCAP is compromised. Document the username, the service accessed, and the timestamp. Immediately recommend password reset for all exposed accounts. If the credentials provide access to other systems (password reuse), those systems are at risk too.

IOC Extraction

Indicators of Compromise (IOCs) extracted from PCAP evidence feed into threat intelligence platforms, SIEM rules, and network-wide hunting operations.

Systematic IOC Extraction
# Extract all unique destination IPs
$ tshark -r evidence.pcap -T fields -e ip.dst | sort -u > dest_ips.txt

# Extract all DNS query domains
$ tshark -r evidence.pcap -Y "dns.flags.response == 0" \
    -T fields -e dns.qry.name | sort -u > domains.txt

# Extract all URLs from HTTP requests
$ tshark -r evidence.pcap -Y "http.request" \
    -T fields -e http.host -e http.request.uri | \
    awk '{print "http://"$1$2}' > urls.txt

# Extract TLS SNI (Server Name Indication) values
$ tshark -r evidence.pcap -Y "tls.handshake.extensions_server_name" \
    -T fields -e tls.handshake.extensions_server_name | sort -u > tls_sni.txt

# Extract User-Agent strings
$ tshark -r evidence.pcap -Y "http.user_agent" \
    -T fields -e http.user_agent | sort -u > user_agents.txt

# Extract JA3 hashes
$ tshark -r evidence.pcap -Y "tls.handshake.type == 1" \
    -T fields -e ip.src -e ip.dst -e tls.handshake.ja3 | sort -u > ja3.txt

Zeek Log Generation

Zeek (formerly Bro) processes a PCAP and generates structured log files that are far easier to analyze than raw packets. Each log type covers a specific protocol or activity.

Zeek PCAP Processing
# Process PCAP with Zeek
$ zeek -r evidence.pcap

# Generated log files:
conn.log      -- All connections (like NetFlow on steroids)
dns.log       -- All DNS queries and responses
http.log      -- HTTP requests with headers, URIs, response codes
ssl.log       -- TLS handshake details, certificates, JA3
files.log     -- Files transferred over any protocol (with hashes)
notice.log    -- Anomalies and alerts detected by Zeek
weird.log     -- Protocol violations and unexpected behavior

# Query conn.log for long connections (C2 persistence)
$ cat conn.log | zeek-cut id.orig_h id.resp_h id.resp_p duration orig_bytes resp_bytes | \
    sort -t$'\t' -k4 -rn | head -10

# Query files.log for executables
$ cat files.log | zeek-cut filename mime_type md5 sha1 | \
    grep -i "executable\|dll\|octet"

# Query http.log for suspicious downloads
$ cat http.log | zeek-cut host uri resp_mime_types status_code | \
    grep -i "executable\|dll\|octet-stream"

Why Zeek for Forensics

  • Zeek files.log automatically hashes all transferred files (MD5 + SHA1)
  • Zeek conn.log provides connection metadata comparable to NetFlow
  • Zeek ssl.log extracts certificate details and JA3 fingerprints
  • Tab-separated format integrates easily with grep, awk, and SIEM ingestion

Practice: Extract Evidence from a Scenario

You have a PCAP from a compromised web server. Write the tshark commands to extract:

  1. All HTTP POST requests (potential web shell commands or data uploads)
  2. All files downloaded via HTTP, saved to an output directory
  3. All unique external IP addresses that connected to the server
  4. Any cleartext FTP credentials
  5. All DNS queries made by the server (for C2 domain identification)

Answers:

1. tshark -r server.pcap -Y "http.request.method == POST" -T fields -e ip.src -e http.host -e http.request.uri -e http.file_data

2. tshark -r server.pcap --export-objects http,./extracted/

3. tshark -r server.pcap -Y "ip.dst == [server_ip]" -T fields -e ip.src | sort -u

4. tshark -r server.pcap -Y "ftp.request.command == USER or ftp.request.command == PASS" -T fields -e frame.time -e ip.src -e ftp.request.command -e ftp.request.arg

5. tshark -r server.pcap -Y "dns.flags.response == 0 and ip.src == [server_ip]" -T fields -e dns.qry.name | sort -u

Key Takeaways

  • Multiple tools exist for file extraction: Wireshark (GUI), tshark (CLI), NetworkMiner (auto), foremost (carving)
  • Cleartext credentials in FTP, HTTP, and Telnet must be documented and trigger password resets
  • IOC extraction produces actionable intelligence: IPs, domains, URLs, hashes, JA3, user agents
  • Zeek generates structured logs from PCAP that are far easier to query than raw packets
  • Always hash extracted files and check against threat intelligence databases
  • Automated extraction with tshark enables batch processing of multiple PCAP files
