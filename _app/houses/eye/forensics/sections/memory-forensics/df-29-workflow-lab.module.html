Learning Objectives

  • Execute a complete memory forensics workflow from receipt to report
  • Apply triage methodology to rapidly identify suspicious activity
  • Chain multiple Volatility plugins into a coherent investigation
  • Document findings in a structured forensic report format
  • Prioritize investigation steps based on initial triage results

Scenario Briefing

The SOC has escalated an alert to your forensics team. A Windows 10 workstation (DESKTOP-ACME42) triggered multiple alerts: unusual outbound HTTPS connections from a non-browser process, PowerShell execution with encoded commands, and a new local administrator account. The endpoint was isolated and a memory dump was captured using DumpIt. The raw image file is acme42-20260312-1423.bin (16 GB).

Your task: analyze the memory dump, identify the compromise, trace the attack chain, extract IOCs, and produce a report. Follow the guided workflow below.

Lab Approach

This lab walks through each step with the exact commands and expected output. In a real engagement, your output will differ, but the methodology is identical. Follow along command-by-command, understanding what each step reveals and how it connects to the next.

Practice: Write the Report Summary

Using the findings from this walkthrough, draft a one-paragraph executive summary and a bulleted technical summary that covers:

  1. How the attacker gained initial access (based on the process chain)
  2. What the attacker did after gaining access (persistence, credential theft, lateral movement)
  3. What C2 infrastructure was used
  4. What immediate containment actions are recommended
  5. What additional systems need investigation based on lateral movement evidence

Key points to include: svchost.exe exploitation led to cmd.exe/PowerShell execution at 14:15. Attacker established dual C2 channels, created a backdoor account (svc_update), installed persistent dropper, and pivoted to at least two internal hosts. Block C2 IPs, disable svc_update, remove persistence, investigate 192.168.1.10 and 10.0.1.100.

Key Takeaways

  • The workflow follows a repeatable pattern: validate, triage, investigate, extract, report
  • Start with windows.info and process analysis before diving into injection or network data
  • Each finding should lead to the next investigation step -- process to injection to network to persistence
  • Compare pslist and psscan counts early to detect process hiding
  • IOC compilation happens throughout the investigation, not just at the end
  • The report must include both executive-level summary and technical detail with actionable IOCs
