Memory Acquisition Overview

Memory acquisition is the process of copying the contents of physical RAM to a file for offline analysis. Every acquisition tool modifies the target system to some degree -- loading a driver, allocating memory for the tool itself, and writing the output file. The goal is to minimize this footprint while capturing a complete and accurate snapshot.

The tool you choose depends on the target operating system, whether you have physical or remote access, and what output format your analysis tools require.

Tool Comparison

Tool Platform Output Format Notes
FTK Imager Windows Raw (.mem, .bin) GUI-based, widely accepted in court, also captures pagefile
WinPmem Windows Raw, AFF4 Open-source, command-line, part of the Rekall project
DumpIt Windows Raw (.bin) Single executable, double-click operation, ideal for non-technical responders
Magnet RAM Capture Windows Raw (.bin) Free, minimal footprint, simple GUI
LiME Linux Raw, Lime, padded Loadable kernel module, gold standard for Linux memory capture
AVML Linux Raw, compressed Microsoft's tool, no kernel module needed, runs in user space

FTK Imager Memory Capture

AccessData's FTK Imager is the most widely used commercial tool for Windows memory acquisition. Its GUI interface and court-accepted pedigree make it the default choice for law enforcement and corporate IR teams.

FTK Imager - Memory Capture Steps
# FTK Imager GUI workflow:
1. File > Capture Memory
2. Set destination path (external USB drive recommended)
3. Check "Include pagefile" for additional artifacts
4. Click "Capture Memory"

# Output files:
memdump.mem      # Raw physical memory dump
pagefile.sys     # Windows pagefile (if selected)

# Typical capture time:
8 GB RAM  ~  2-4 minutes
16 GB RAM ~  4-8 minutes
32 GB RAM ~  8-15 minutes

WinPmem (Command Line)

WinPmem is the open-source alternative for Windows memory acquisition. It loads a signed kernel driver to access physical memory and supports multiple output formats including the AFF4 forensic container.

WinPmem Acquisition
# Basic raw memory dump
C:\> winpmem_mini_x64.exe output.raw

# AFF4 format (includes metadata)
C:\> winpmem_mini_x64.exe -o output.aff4

# Verify the dump was created
C:\> dir output.raw
 03/15/2026  14:23    8,589,934,592 output.raw

# Hash the output for chain of custody
C:\> certutil -hashfile output.raw SHA256
SHA256 hash of output.raw:
a3f2b8c9d1e4f5a6b7c8d9e0f1a2b3c4d5e6f7a8b9c0d1e2f3a4b5c6d7e8f9a0

Driver Signing

On 64-bit Windows with Secure Boot enabled, WinPmem requires a signed driver. Unsigned drivers will be blocked. Always test your acquisition tools on a similar system before deploying to a live incident.

LiME for Linux

LiME (Linux Memory Extractor) is a loadable kernel module (LKM) that captures physical memory on Linux systems. It must be compiled against the target system's kernel headers, which is why pre-building modules for your environment's standard kernel versions is critical IR preparation.

LiME Acquisition on Linux
# Build LiME module (do this on a matching system, NOT the target)
$ git clone https://github.com/504ensicsLabs/LiME.git
$ cd LiME/src
$ make
make -C /lib/modules/5.15.0-91-generic/build M=/home/analyst/LiME/src
  Building modules, stage 2.
  MODPOST 1 modules

# Load the module on the target (captures memory immediately)
$ sudo insmod lime-5.15.0-91-generic.ko "path=/mnt/usb/memory.lime format=lime"

# Alternative: raw format for Volatility compatibility
$ sudo insmod lime-5.15.0-91-generic.ko "path=/mnt/usb/memory.raw format=raw"

# Capture over network (avoid writing to target disk)
$ sudo insmod lime-5.15.0-91-generic.ko "path=tcp:4444 format=lime"
# On analyst machine:
$ nc target_ip 4444 > memory.lime

LiME Format Options

  • raw -- Concatenated physical memory ranges. Universal compatibility with analysis tools.
  • lime -- Includes address space metadata. Preferred for LiME-aware tools.
  • padded -- Zero-fills gaps in physical address space. Largest output but preserves address offsets.

DumpIt - One-Click Capture

DumpIt by Comae Technologies is designed for simplicity. A single executable, no installation, no command-line arguments required. Double-click and confirm. This makes it ideal for first responders who may not have forensic training.

DumpIt Usage
# Option 1: Double-click DumpIt.exe
# Prompts: "Are you sure you want to continue? [y/n]"
# Creates: HOSTNAME-YYYYMMDD-HHMMSS.dmp in the same directory

# Option 2: Command-line (scriptable)
C:\> DumpIt.exe /OUTPUT E:\evidence\memory.bin /QUIET

# Output confirmation:
  DumpIt - v3.5.0
  Address space size:       8589934592 (  8.00 GB)
  Destination path:         E:\evidence\memory.bin
  Acquisition started...    [####################] 100%
  Acquisition completed successfully.

Output Formats

Raw / dd Format Byte-for-byte copy of physical memory. Universal compatibility. No metadata. Extensions: .raw, .bin, .mem, .dd. Works with all analysis frameworks.
Windows Crashdump Microsoft's crash dump format (.dmp). Contains header with system info, memory manager data. Supported by WinDbg and Volatility.
AFF4 (Advanced Forensic Format) Container format with compression, metadata, and hash verification built in. Supported by Rekall and newer tools.
LiME Format Linux-specific format with address range headers. Preserves physical memory layout information that raw format loses.

Format Compatibility

When in doubt, use raw format. Every analysis tool supports it. AFF4 and LiME formats offer advantages but limit your tool options. Always verify your analysis framework can read your chosen format before deploying to a live incident.

Practice: Tool Selection

For each scenario, identify the best acquisition tool and justify your choice:

  1. A non-technical HR representative needs to capture memory from a Windows laptop suspected of policy violation
  2. You have SSH access to a compromised Ubuntu 22.04 web server in a data center
  3. A Windows 10 workstation infected with ransomware -- you need the memory dump for court evidence
  4. An incident response engagement where you need to capture 50 Windows endpoints remotely

Suggested answers: 1-DumpIt (simplest), 2-LiME (Linux, network capture), 3-FTK Imager (court-accepted, includes pagefile), 4-WinPmem or Magnet RAM Capture (scriptable, deployable via GPO/SCCM)

Key Takeaways

  • Choose your acquisition tool based on OS, access method, and legal requirements
  • FTK Imager is the gold standard for court-admissible Windows memory captures
  • LiME is the only reliable option for Linux -- pre-compile modules for your kernel versions
  • DumpIt provides one-click capture for non-technical responders
  • Raw format offers universal compatibility; use it when interoperability matters
  • Always hash your memory dump immediately after capture for chain of custody
  • Write the dump to external media -- never write to the target system's disk
