Disk Imaging

Forensic disk imaging creates a bit-for-bit copy of a storage device, preserving all data including deleted files, slack space, and unallocated areas. The image — not the original — is what you analyze. This module covers the major imaging tools, image formats, and verification procedures.

Learning Objectives

  • Create forensic images using dd, dcfldd, and FTK Imager
  • Compare Raw, E01, and AFF image formats
  • Verify image integrity with hash comparison
  • Follow imaging best practices for court-admissible evidence

dd: The Foundation

dd is the original Unix disk copying utility. It creates raw (bit-for-bit) images and is available on every Linux and macOS system.

# Basic forensic imaging with dd # if = input file (source device) # of = output file (destination image) # bs = block size (larger = faster, 4M is common) # conv = conversion options sudo dd if=/dev/sdb of=/evidence/case001/drive.dd bs=4M \ conv=noerror,sync status=progress # Key options: # conv=noerror — continue on read errors (don't stop) # conv=sync — pad error blocks with zeros (maintain alignment) # status=progress — show transfer progress # Hash the source and image for verification sudo sha256sum /dev/sdb sha256sum /evidence/case001/drive.dd

dd has no safety net. If you reverse if and of, you will overwrite your evidence. Always triple-check the source and destination. The forensic community calls dd "disk destroyer" for this reason. Consider using dcfldd or dc3dd instead.

dcfldd: Enhanced dd for Forensics

dcfldd was developed by the DoD Computer Forensics Lab. It adds hashing, split output, progress display, and verification features to dd.

# Image with on-the-fly hashing and split output sudo dcfldd if=/dev/sdb \ hash=sha256 \ hashlog=/evidence/case001/hash.log \ of=/evidence/case001/drive.dd \ bs=4M \ split=2G \ splitformat=000 # Key advantages over dd: # hash=sha256 — computes hash during imaging (no separate step) # hashlog=file — saves hash to a log file # split=2G — splits image into 2GB segments # splitformat=000 — naming: drive.dd.000, drive.dd.001, etc. # hashwindow=1G — hash every 1GB (piecewise verification)

FTK Imager

FTK Imager (AccessData/Exterro) is a free Windows GUI tool that creates forensic images in multiple formats. It is widely accepted in court and used by law enforcement agencies worldwide.

FTK Imager Workflow

  1. File > Create Disk Image
  2. Select source type: Physical Drive, Logical Drive, Image File, or Contents of Folder
  3. Select destination format: Raw (dd), E01 (EnCase), or AFF
  4. Enter case information: case number, evidence number, examiner, description
  5. Set image fragment size (E01: typically 2 GB segments)
  6. Select compression level (E01 supports compression)
  7. Enable "Verify images after they are created"
  8. Click Start and wait for completion

Guymager: Linux GUI Imager

Guymager is an open-source forensic imaging tool with a Qt-based GUI. It is included in forensic Linux distributions like CAINE and Paladin.

# Install Guymager on Debian/Ubuntu sudo apt install guymager # Launch with root privileges sudo guymager # Guymager features: # - Multi-threaded imaging (significantly faster than dd) # - Creates E01, EWF, and raw formats # - On-the-fly MD5 and SHA-256 hashing # - Automatic verification after imaging # - Generates info file with case metadata

Imaging Best Practices

  1. Use a write blocker — always connect the source device through a hardware or software write blocker
  2. Hash before imaging — compute the hash of the source device before creating the image
  3. Hash after imaging — compute the hash of the completed image and compare to the source hash
  4. Create two copies — create a working copy and a verified archive copy
  5. Document everything — record device details, imaging tool/version, start/end times, hash values
  6. Verify after storage — re-verify hashes when retrieving images from storage
  7. Image entire device — image the physical device, not just partitions (captures unallocated space between partitions)

SSD Considerations: SSDs with TRIM enabled may automatically zero deleted data blocks, making recovery impossible. If possible, disable TRIM before imaging (or use a write blocker that blocks TRIM commands). NVMe drives may require special adapters for hardware write blocking.

Practice: Imaging Command Construction

Write the correct command for each scenario:

  1. Create a raw image of /dev/sdc with 4M block size, continuing on errors, with progress display
  2. Create a dcfldd image with SHA-256 hashing, split into 1.5GB segments, with hash log
  3. Verify an existing image against a known SHA-256 hash

Key Takeaways

  • Always use a write blocker when imaging source media
  • dd is universal but dangerous; dcfldd adds hashing and safety features
  • E01 format is most widely used in law enforcement (compression, metadata, block CRCs)
  • Hash source before imaging, hash image after, compare both values
  • Image the entire physical device, not just individual partitions
