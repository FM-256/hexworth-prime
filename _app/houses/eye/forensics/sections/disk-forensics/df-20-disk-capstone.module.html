Disk Forensics Capstone: Data Exfiltration Investigation

This capstone integrates all skills from modules DF-11 through DF-19. You will investigate a suspected employee data exfiltration case using disk forensics techniques. Work through each task sequentially, documenting your process as you would for a real investigation report.

Capstone Objectives

  • Describe the disk imaging process with write blocker selection and hash verification
  • Analyze MFT entries for suspicious timestamp patterns
  • Recover deleted files from a forensic image
  • Extract and analyze file metadata
  • Examine slack space for hidden data remnants
  • Produce a professional investigation report with supporting evidence

Scenario: Project Meridian Theft

Background: Vektor Dynamics, a defense contractor, suspects that Marcus Webb, a software engineer with Secret clearance, copied classified design files from Project Meridian before his planned departure to a competitor. IT security flagged anomalous USB activity on his workstation (Dell Precision 5570, Windows 11, 1TB NVMe SSD, NTFS). Your firm was engaged to perform a forensic examination under a court order authorizing full disk analysis. The workstation has been powered off and secured in the evidence room.

Task 1: Imaging Process

Document your complete imaging procedure for the laptop's NVMe SSD:

  1. Which write blocker would you use for an NVMe drive? Justify your selection.
  2. What image format would you choose (Raw, E01, AFF) and why?
  3. Write the exact imaging command you would use
  4. Document the hash verification workflow (pre-image, post-image, source re-verify)
  5. The SSD is BitLocker encrypted. How does this affect your imaging approach?

Task 2: MFT Timeline Analysis

IT security flagged activity during the following windows:

  • February 28, 2026: 22:00-23:59 UTC (after-hours activity)
  • March 3, 2026: 12:00-13:00 UTC (lunch hour)
  • March 10, 2026: 21:00-23:59 UTC (Webb's second-to-last day)

Your tasks:

  1. Extract the $MFT and run analyzeMFT. Filter for files modified during the flagged windows.
  2. Check for timestomping: compare $STANDARD_INFORMATION and $FILE_NAME timestamps for any Project Meridian files.
  3. Check the $UsnJrnl for file rename, deletion, and creation events during the flagged windows.
  4. Look for USB-related artifacts: setupapi.dev.log, Windows Event Logs for removable storage.

Task 3: Deleted File Recovery

MFT analysis reveals several deleted files in Documents\ProjectMeridian\:

  • PM_Schematics_v4.2.dwg (deleted March 10, 23:15 UTC)
  • PM_ComponentList_CLASSIFIED.xlsx (deleted March 10, 23:16 UTC)
  • PM_TestResults_2026Q1.pdf (deleted March 10, 23:16 UTC)
  • copy_complete.log (deleted March 10, 23:18 UTC)
  1. Use Autopsy or icat to attempt recovery of each file. Note which are recoverable and which are not.
  2. For files that cannot be recovered via metadata, attempt file carving from unallocated space.
  3. Hash each recovered file and document the hash values.
  4. The file "copy_complete.log" is particularly interesting — what might it contain?

Task 4: Metadata Analysis

Run ExifTool on recovered files and answer:

  1. Who is listed as the author of the Excel spreadsheet? Does this match the suspect?
  2. What software was used to create the DWG file? What version?
  3. Do the internal document timestamps align with the MFT timestamps?
  4. Are there any signs of metadata sanitization on any of the recovered files?

Task 5: Slack Space and Hidden Data

  1. Extract file slack from clusters allocated to files in the ProjectMeridian directory. Search for project-related strings.
  2. Check for Alternate Data Streams on files in Webb's home directory.
  3. Verify the drive has no HPA or DCO hiding additional sectors.
  4. Examine the USB drive (Item 003) for remnants of copied files, even if it appears formatted.

Produce a professional investigation report using this structure:

Capstone Review

  • This scenario tested file systems (DF-11), imaging (DF-12), Autopsy (DF-13), carving (DF-14), metadata (DF-15), deleted recovery (DF-16), MFT analysis (DF-17), slack space (DF-18), and write blockers (DF-19)
  • Real investigations require combining multiple techniques — no single tool or approach is sufficient
  • Documentation quality is as important as technical findings — undocumented evidence may be inadmissible
  • Always consider anti-forensic techniques (timestomping, secure deletion, ADS) in your analysis
  • The investigation report must present findings objectively, including limitations and alternative explanations
