File Carving & Recovery

File carving recovers files from raw data without relying on file system metadata. It works by scanning for known file signatures (headers and footers) in unallocated space, deleted areas, or damaged media. This technique recovers files that the file system no longer tracks.

Learning Objectives

  • Explain how header/footer carving works
  • Use PhotoRec, Scalpel, and foremost for file recovery
  • Configure custom carving rules for non-standard file types
  • Identify carving limitations and validate recovered files

How File Carving Works

Every file format has a characteristic signature — a sequence of bytes at the beginning (header) and often at the end (footer) of the file. Carving tools scan raw disk data byte-by-byte looking for these signatures.

PhotoRec

PhotoRec is a powerful open-source carving tool included with TestDisk. Despite its name, it recovers far more than photos — it supports over 480 file formats.

# Install PhotoRec (included with testdisk package) sudo apt install testdisk # Run PhotoRec against a disk image photorec /d /recovery/output /cmd image.dd fileopt,everything,enable,search # Interactive mode (recommended for first use) photorec image.dd # 1. Select the disk/partition # 2. Choose file system type (ext/Other or FAT/NTFS) # 3. Choose scope: Free (unallocated only) or Whole (entire image) # 4. Select output directory # 5. PhotoRec begins scanning and recovering files # Output structure: # /recovery/output/recup_dir.1/ — first batch of recovered files # /recovery/output/recup_dir.2/ — second batch (max 500 files per dir) # Files named: f0000001.jpg, f0000002.pdf, etc.

Scalpel

Scalpel is a configurable carving tool that uses a configuration file to define file types, headers, footers, and maximum file sizes.

# Install Scalpel sudo apt install scalpel # Edit the configuration file to enable file types sudo nano /etc/scalpel/scalpel.conf # Example configuration entries (uncomment to enable): # jpg y 20000000 \xff\xd8\xff \xff\xd9 # png y 20000000 \x89PNG \xff\xfc\xfd\xfe # pdf y 50000000 %PDF %EOF\x0d # doc y 40000000 \xd0\xcf\x11\xe0\xa1\xb1\x1a\xe1 # Custom header for a proprietary format: # myformat y 5000000 MYHEAD MYFOOT # Run Scalpel scalpel -o /recovery/output image.dd # Key options: # -o output_dir — where to save recovered files # -c config_file — custom configuration file # -b blocksize — block size for reading (default 512)

foremost

foremost is similar to Scalpel (Scalpel was originally a fork of foremost). It is included in many forensic Linux distributions.

# Install foremost sudo apt install foremost # Basic carving from a disk image foremost -t all -i image.dd -o /recovery/output # Key options: # -t type — file types to carve (jpg, png, pdf, doc, all) # -i input — input file (disk image) # -o output — output directory # -v — verbose mode # -q — quick mode (search only at 512-byte boundaries) # Output includes an audit.txt file listing all recovered files

Carving Limitations

Fragmentation

The primary limitation of carving. If a file's data blocks are not contiguous on disk, header/footer carving will produce a corrupted file. The carved file will contain the header, then data from whatever occupied the next blocks. Fragmented files are common on nearly full or heavily used drives.

Overwritten Data

If new data has been written to the blocks previously occupied by a deleted file, that data is gone. Carving cannot recover overwritten content.

Encrypted Files

Encrypted file content has no recognizable headers or footers. Carving tools cannot identify or recover encrypted files unless the encryption wrapper itself has a known signature.

Files Without Footers

Many file formats (EXE, AVI, MP3) do not have distinct footer signatures. Carving tools must estimate file size from header fields or use a maximum size, often recovering excess trailing data.

Validating Carved Files

Not every carved file is valid. Post-carving validation is essential:

# Validate JPEG files identify recovered_image.jpg 2>&1 # If corrupt: "identify: Not a JPEG file" # Validate PDF files pdfinfo recovered_document.pdf # If corrupt: "Error: May not be a PDF file" # Check file type against extension file recovered_file.doc # Should report: "Microsoft Word" not "data" # Bulk validation with a script for f in /recovery/output/recup_dir.*/*.jpg; do identify "$f" > /dev/null 2>&1 || echo "CORRUPT: $f" done

Practice: File Carving Exercise

Using a practice disk image containing deleted files:

  1. Run PhotoRec against the image and note how many files are recovered
  2. Run Scalpel with a configuration that only carves JPEG and PDF files
  3. Compare the results — did each tool find different files?
  4. Validate the recovered files and count how many are corrupt
  5. Explain why some recovered files might be corrupt (fragmentation, overwrite, truncation)

Key Takeaways

  • File carving uses header/footer signatures to recover files from raw data without file system metadata
  • PhotoRec supports 480+ formats; Scalpel/foremost offer configurable header/footer definitions
  • Fragmentation is the primary cause of carved file corruption
  • Always validate carved files before including them as evidence
  • Carving cannot recover overwritten data or encrypted content without known signatures
