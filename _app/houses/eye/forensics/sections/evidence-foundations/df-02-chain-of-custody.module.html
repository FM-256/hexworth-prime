Chain of Custody

The chain of custody (CoC) is the documented chronological history of evidence from the moment of seizure to its presentation in court. A single gap in the chain can render evidence inadmissible. This module covers the complete 7-step process, common failure points, and practical documentation techniques.

Learning Objectives

  • Execute the 7-step chain of custody process for digital evidence
  • Complete an evidence intake form with all required fields
  • Implement hash verification at every transfer point
  • Identify and avoid common chain of custody failures

The 7-Step Chain of Custody Process

Step 1: Identification

Locate and recognize items of evidentiary value. Document each item's physical description, location where found, and the person who discovered it. In digital forensics, this includes noting the device type, make, model, serial number, and current state (powered on/off).

Step 2: Collection

Physically seize or acquire the evidence using forensically sound methods. For powered-on systems, capture volatile data first (see DF-04: Order of Volatility). Use anti-static bags for storage media. Photograph the scene before and after collection. Use evidence tags and tamper-evident bags.

Never power off a running system without first capturing volatile data. RAM contents, running processes, and network connections are lost forever on shutdown. Follow your organization's live acquisition procedures.

Step 3: Transport

Move evidence from the collection site to the forensic laboratory or evidence storage facility. Use padded containers to prevent physical damage. Maintain constant custody — evidence should never be left unattended during transport. Document the transport method, vehicle, and personnel involved.

Step 4: Storage

Secure evidence in a controlled-access environment. Requirements include: locked evidence room with limited key/badge access, environmental controls (temperature, humidity), surveillance cameras, and an access log for the storage area. Digital evidence requires protection from electromagnetic interference and static discharge.

Step 5: Transfer

Any handoff between custodians must be documented with signatures from both parties, the date/time, reason for transfer, and condition of the evidence. Hash values should be verified at each transfer point. This is the step where most chain of custody failures occur.

Step 6: Analysis

The forensic examination itself. Work only on forensic copies, never the original. Document every tool used, every action taken, and every finding. The analysis must be reproducible by another qualified examiner using the same tools and methodology.

Step 7: Return/Disposition

After the case concludes, evidence is either returned to the owner, destroyed, or retained per policy. Document the final disposition and obtain appropriate signatures. Some jurisdictions require evidence retention for a specified period after case closure.

Hash Verification Script

Automate hash verification at every transfer point:

#!/bin/bash # coc-hash-verify.sh — Chain of Custody hash verification # Usage: ./coc-hash-verify.sh <evidence_file> [expected_hash] EVIDENCE="$1" EXPECTED="$2" TIMESTAMP=$(date -u +"%Y-%m-%d %H:%M:%S UTC") EXAMINER=$(whoami) if [ ! -f "$EVIDENCE" ]; then echo "[ERROR] File not found: $EVIDENCE" exit 1 fi echo "=== Chain of Custody Hash Verification ===" echo "File: $EVIDENCE" echo "Timestamp: $TIMESTAMP" echo "Examiner: $EXAMINER" COMPUTED=$(sha256sum "$EVIDENCE" | awk '{print $1}') echo "SHA-256: $COMPUTED" if [ -n "$EXPECTED" ]; then if [ "$COMPUTED" = "$EXPECTED" ]; then echo "Status: MATCH — Integrity verified" else echo "Status: MISMATCH — EVIDENCE MAY BE COMPROMISED" echo "Expected: $EXPECTED" exit 2 fi fi # Append to verification log echo "$TIMESTAMP | $EXAMINER | $EVIDENCE | $COMPUTED" \ >> coc_hash_log.txt echo "Logged to coc_hash_log.txt"

Common Chain of Custody Failures

Failure Consequence Prevention
Unsigned transfer Gap in custody timeline; defense argues tampering Require dual signatures at every handoff
Missing timestamps Cannot prove when evidence was in whose possession Use UTC timestamps; log immediately, not later
No hash at intake Cannot prove evidence was not altered after seizure Hash original media on-scene before transport
Unsecured storage Evidence accessible to unauthorized personnel Access-controlled room with logging
Working on originals Original evidence modified during analysis Always work on verified forensic copies
Lost evidence tag Cannot associate item with case documentation Photograph tags; use tamper-evident bags
Incomplete description Cannot distinguish between similar items Record make, model, serial number, unique marks

Case Study: In United States v. Comprehensive Drug Testing (2009), the Ninth Circuit criticized the government's failure to maintain proper chain of custody for seized digital records. The court established strict protocols for handling digital evidence, including requiring the government to return or destroy non-responsive data.

Practice Scenario: The Missing Link

You are called to investigate a suspected insider threat. Upon arriving at the scene, you find a workstation that is still powered on, a USB drive on the desk, and a stack of printed emails. Your task:

  1. List the evidence items you would collect, in the correct order
  2. For each item, describe the collection method you would use
  3. Fill out the evidence intake form fields for the USB drive
  4. Describe the hash verification steps you would take for the workstation's hard drive
  5. Identify three potential chain of custody failures if the first responder simply unplugged the workstation and put everything in a cardboard box

Key Takeaways

  • The 7-step CoC process: Identification, Collection, Transport, Storage, Transfer, Analysis, Return/Disposition
  • Every transfer requires dual signatures, timestamps, and hash verification
  • Work only on forensic copies — never the original evidence
  • A single undocumented gap can make evidence inadmissible
  • Automate hash verification to reduce human error
