IoT Forensics Challenges

Internet of Things devices present unique forensic challenges that differ fundamentally from traditional computer forensics. These devices often run proprietary operating systems, have minimal or no local logging, store data exclusively in volatile memory, and may lack standard interfaces for data extraction.

Proprietary Systems Custom RTOS, embedded Linux variants, or bare-metal firmware. No standard forensic tools exist for most devices. Each investigation may require reverse engineering the storage format.
Limited Storage Many IoT devices have only kilobytes or megabytes of storage. Logs (if they exist) are circular buffers that overwrite quickly. Historical evidence has a short lifespan.
Volatile-Only Memory Some devices store operational data only in RAM. A power cycle destroys all evidence. Live acquisition is the only option, but connecting to the device may alter its state.
Network-Centric Evidence Since device-level evidence is often limited, network traffic captures (PCAP) become the primary evidence source. Network monitoring must be in place before an incident.

Firmware Extraction

When device-level access is needed, firmware extraction through hardware interfaces provides access to the device's code and data.

InterfaceMethodEvidence Obtained
UARTConnect to serial debug port (TX/RX/GND). Often provides console access or bootloader shell.Boot logs, filesystem access, command shell. Non-destructive. Requires identifying pins on PCB.
JTAGJoint Test Action Group debug interface. Direct memory access through debug port.Full memory dump, firmware image, ability to halt processor for live state capture. Non-destructive.
SPI/I2C FlashConnect directly to flash memory chip with a clip or desolder chip. Read with programmer.Complete firmware image including filesystem, configuration, credentials, certificates.
Chip-OffPhysically remove flash chip from PCB, read with dedicated reader.Raw flash contents. Destructive to the device. Last resort when other methods fail.
Firmware Analysis with Binwalk
# Scan firmware image for embedded files and filesystems
binwalk firmware.bin

# Extract all identified components
binwalk -e firmware.bin

# Search for hardcoded credentials
strings firmware.bin | grep -i "password\|passwd\|secret\|key"

# Identify filesystem type
binwalk -A firmware.bin
# Common: SquashFS, JFFS2, CramFS, YAFFS2

Smart Home Device Forensics

Amazon Alexa / Echo Voice recordings stored in Amazon cloud (accessible via account or legal process). Device interaction logs, Wi-Fi network history, paired device list. Wake word detection timestamps.
Google Home / Nest Activity logs via Google My Activity. Camera footage (Nest Cam) stored in cloud with retention limits. Thermostat occupancy detection logs. Hub device communication records.
Ring Doorbell Video recordings in Ring cloud (30-180 day retention depending on plan). Motion detection events with timestamps. Wi-Fi network information. Shared user access logs.
Smart Locks Access logs with timestamps and method (PIN, fingerprint, Bluetooth, remote). User management history. Battery status changes. Failed access attempts.

Vehicle Forensics

Modern vehicles are networks of 70-100+ embedded computers (ECUs) connected via CAN bus, with infotainment systems running full operating systems (often Linux or QNX).

SystemForensic Data
InfotainmentPaired Bluetooth devices, call logs, contacts synced from phones, navigation history (with GPS coordinates), media history, recent destinations, Wi-Fi hotspot connections.
TelematicsGPS tracking data (cloud-stored by manufacturer), crash data (airbag deployment records), remote start/unlock logs, geofence alerts, vehicle health reports.
OBD-IIDiagnostic trouble codes, engine runtime, speed data at time of crash, RPM history, fuel level. Accessible via standard OBD-II port under dashboard.
Event Data RecorderPre-crash data: speed, brake application, steering angle, throttle position, seatbelt status, airbag deployment timing. Similar to aviation black box.

SCADA/ICS Forensics

Industrial Control Systems forensics requires extreme caution -- disrupting operations can have physical safety consequences. Never power cycle or modify a running industrial system without authorization from operations personnel.

Safety First

ICS/SCADA environments control physical processes (power generation, water treatment, manufacturing). Forensic actions that disrupt these systems can cause physical harm, environmental damage, or loss of life. Always coordinate with plant operators and OT (Operational Technology) engineers before any forensic activity.

Key ICS forensic sources: PLC (Programmable Logic Controller) program comparison against known-good baseline, HMI (Human-Machine Interface) operator action logs, historian database queries for process anomalies, and network traffic captures on the OT network. The Stuxnet investigation demonstrated that PLC code analysis is critical -- malware modified centrifuge control logic while displaying normal readings to operators.

Practice: IoT Forensics Planning

A smart home was burglarized. Available IoT devices: Ring doorbell, Alexa Echo, smart lock (August), and a Wi-Fi router. Plan your forensic approach:

  1. What evidence would you request from each device/cloud service?
  2. In what order would you collect evidence and why?
  3. What network-level evidence might exist on the router?

Answers: (1) Ring: motion-triggered video recordings with timestamps. Alexa: voice interaction logs (did anyone speak commands?), routine activity. August: lock/unlock log with method and user ID. Router: DHCP leases, connected device list, DNS queries. (2) Priority order: Ring video (highest probative value, cloud retention limited), smart lock logs (entry timeline), Alexa logs, router logs. Collect cloud data first since it has retention limits. (3) Router may show: DHCP leases revealing devices connected during the burglary window, DNS queries showing if any device phoned home to unusual servers, and potentially MAC addresses of unknown devices that joined the network.

Key Takeaways

  • IoT devices often lack standard logging -- network traffic captures are frequently the primary evidence source
  • Firmware extraction via UART, JTAG, or SPI provides access to device code and data
  • Smart home cloud services (Ring, Alexa, Nest) store data with limited retention -- collect early
  • Vehicle infotainment systems contain paired phone data, navigation history, and call records
  • SCADA/ICS forensics requires coordination with operations -- safety is paramount
  • Binwalk is the primary tool for firmware image analysis and embedded filesystem extraction
  • Many IoT forensic artifacts exist only in cloud services, requiring legal process for acquisition
