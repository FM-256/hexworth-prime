Hard Disk Drives (HDD)
Spinning magnetic platters with a read/write head on an actuator arm. Mechanical, moving parts.
3.5-inch (Desktop)
Standard desktop size. 5,400 or 7,200 RPM. Capacities up to 20+ TB. SATA III interface (6 Gbps). Needs both SATA data and SATA power cables. Reads ~150-200 MB/s sequential.
2.5-inch (Laptop)
Laptop and portable size. Usually 5,400 RPM. Up to 5 TB. Also used in some NAS and external enclosures. Thinner, lighter, lower power. Same SATA interface.
5,400 RPM
Lower speed, quieter, less heat, lower power. Good for bulk storage, media drives, NAS. Not for OS boot drives.
7,200 RPM
Standard desktop speed. Faster access times, better throughput. The minimum for any performance-sensitive HDD task.
10,000+ RPM
Enterprise drives (WD VelociRaptor, SAS). Near-SSD random I/O. Very expensive, high heat. Largely replaced by SSDs.

Solid State Drives (SSD)
No moving parts. NAND flash memory. Dramatically faster than HDDs for all operations.
NAND Types
SLC (1 bit/cell): fastest, most durable, expensive. MLC (2 bits): good balance. TLC (3 bits): mainstream consumer. QLC (4 bits): cheapest, lowest endurance.
Advantages over HDD
No moving parts = shock resistant. Silent. 100x faster random I/O. Lower power consumption. Instant access (no seek time). Lighter weight.
Limitations
Higher cost per GB. Limited write endurance (TBW rating). Performance degrades when nearly full (keep 10-20% free). Data recovery is harder than HDD.

NVMe Protocol
Non-Volatile Memory Express -- a protocol designed specifically for flash storage over PCIe. Not a form factor.
NVMe vs. AHCI
AHCI was designed for spinning disks (1 command queue, 32 depth). NVMe: 65,535 queues, 65,536 commands each. Massively parallel I/O. Lower latency. Direct PCIe path to CPU.
NVMe Form Factors
Most common: M.2 2280 (Key M). Also available as PCIe add-in cards (x4), U.2 (2.5" enterprise), and EDSFF (next-gen data center). The protocol is the same regardless of form factor.
Key distinction: SATA is both a protocol AND a connector. NVMe is only a protocol -- it can run over different physical interfaces (M.2, PCIe card, U.2). M.2 is a form factor that can run either SATA or NVMe.

RAID Levels
Redundant Array of Independent Disks -- combines multiple drives for performance, redundancy, or both.
RAID 0
Data striped across drives. Doubles read/write speed. Zero fault tolerance -- one drive fails, all data lost. Use: scratch disks, temp files.
RAID 1
Data mirrored (duplicated). Survives one drive failure. Usable capacity = 50%. Read speed improved, write speed unchanged. Use: OS drives.
RAID 5
Data striped with distributed parity. Survives one drive failure. Usable capacity = (N-1) drives. Good read speed, slower writes. Use: file servers.
RAID 10 (1+0)
Mirrored pairs, then striped. Survives one failure per mirror pair. 50% usable capacity. Best performance + redundancy. Use: databases, VMs.
Slide 6 of 14
RAID Capacity Math
How to calculate usable capacity for each RAID level. Essential for the A+ exam.
R0RAID 0: Total = Sum of all drives. 4 x 1TB = 4 TB usable. No parity, no mirror overhead.
R1RAID 1: Total = Size of smallest drive. 2 x 1TB = 1 TB usable. Everything is duplicated.
R5RAID 5: Total = (N - 1) x smallest drive. 4 x 1TB = 3 TB usable. One drive worth of parity distributed across all drives.
R6RAID 6: Total = (N - 2) x smallest drive. 4 x 1TB = 2 TB usable. Double parity, survives 2 simultaneous failures. Min: 4 drives.
R10RAID 10: Total = (N / 2) x smallest drive. 4 x 1TB = 2 TB usable. Mirror first, then stripe the pairs.
Exam formula: Always use the smallest drive size in calculations. Mixing drive sizes wastes capacity. RAID 5 minimum = 3 drives. RAID 6 minimum = 4 drives. RAID 10 minimum = 4 drives (even number).
Slide 7 of 14
Hardware vs Software RAID
RAID can be implemented in hardware (dedicated controller) or software (OS-managed).
Hardware RAID
Dedicated RAID controller card (PCIe) with its own processor and cache. Battery-backed write cache (BBU) protects during power loss. Best performance. Hot-swap support. Transparent to OS.
Software RAID
OS manages RAID (Windows Storage Spaces, Linux mdadm, macOS Disk Utility). Uses CPU for parity calculations. Free. Easier to migrate between systems. No BBU protection.
Fake RAID (BIOS RAID)
Motherboard BIOS RAID using Intel RST or AMD RAIDXpert. No dedicated processor. Relies on CPU + BIOS driver. Tied to that motherboard. Neither true hardware nor true software RAID.
RAID is Not Backup
RAID protects against drive failure, not against ransomware, deletion, corruption, or fire. You still need backups. RAID + backups = proper data protection strategy.

Optical Drives
CD, DVD, and Blu-ray -- still tested on the A+ exam even though usage has declined.
CD-ROM / CD-RW
700 MB capacity. Used for audio CDs, old software. CD-R: write once. CD-RW: rewritable. Read speed: 150 KB/s base (1x). Largely obsolete.
DVD-ROM / DVD-RW
Single layer: 4.7 GB. Dual layer: 8.5 GB. DVD-R and DVD+R for write-once. DVD-RW/+RW for rewritable. Still used for OS install media and legacy software.
Blu-ray
Single layer: 25 GB. Dual layer: 50 GB. BD-XL: 100-128 GB. Used for HD/4K video and large backups. Requires Blu-ray drive (reads DVDs and CDs too).
Slide 9 of 14
External Storage
Portable drives, flash drives, and network-attached storage for backup and file sharing.
USB Flash Drives
Compact NAND flash with USB connector. 4 GB to 2 TB. USB 3.0+ for reasonable speed. Used for file transfer, bootable OS installers, portable apps. Easy to lose.
External HDDs/SSDs
2.5" or 3.5" drives in USB enclosures. USB 3.0/3.2 or Thunderbolt. SSDs are faster and more durable. Used for backups, Time Machine, media libraries.
NAS (Network Attached Storage)
Dedicated file server on the network. Multi-bay for RAID. Synology, QNAP, TrueNAS. Accessible by all devices on the network. Runs apps (media server, backup target).
SD / microSD Cards
Secure Digital cards. SDHC (up to 32 GB), SDXC (up to 2 TB). Used in cameras, phones, Raspberry Pi, drones. Speed classes: UHS-I, UHS-II, V30, V60, V90.
Cloud Storage
OneDrive, Google Drive, iCloud, Dropbox. Accessible anywhere. Automatic backup/sync. Pay per GB. Requires internet. Privacy and compliance considerations.

Drive Interfaces Compared
SATA vs. NVMe vs. SAS -- when to use each interface.
SATA III
6 Gbps (practical ~550 MB/s). Used for: 2.5" SSDs, HDDs, optical drives. Cheapest option. Adequate for bulk storage and secondary drives.
NVMe (PCIe)
Gen 4: ~7 GB/s. Gen 5: ~14 GB/s. Used for: OS boot drive, gaming, video editing. M.2 slot on motherboard. The default choice for primary storage.
SAS
12 Gbps (SAS-3). Enterprise only. Dual-port for redundancy. Higher reliability ratings. Used in servers and SANs. More expensive than SATA. Not found in consumer PCs.

Drive Installation
Step-by-step for installing HDDs, SSDs, and NVMe drives.
HDD3.5" HDD: Mount in drive bay with screws or tool-less rails. Connect SATA data cable to motherboard. Connect SATA power from PSU. Vibration-dampening mounts reduce noise.
SSD2.5" SSD: Mount in 2.5" bay or use 3.5" adapter bracket. Same SATA data + power cables as HDD. Some cases have SSD mounts behind the motherboard tray.
M.2M.2 NVMe: Remove mounting screw. Insert at 30-degree angle into M.2 slot. Press flat and secure with screw. Install heatsink if included. No cables needed.
After install: Initialize the drive in Disk Management (Windows) or Disks/fdisk (Linux). Choose GPT for UEFI systems, MBR only for legacy BIOS. Format with NTFS (Windows) or ext4 (Linux).

Storage Troubleshooting
Common drive problems and their solutions.
1Drive not detected in BIOS: Check SATA/power cables. Try different SATA port. For M.2: confirm slot supports NVMe (not just SATA). Check if M.2 disables certain SATA ports.
2Clicking/grinding noise (HDD): Mechanical failure imminent. Back up immediately. Do not power cycle repeatedly. Head crash destroys data.
3Slow performance: Check SMART data (CrystalDiskInfo). SSD nearly full? Free up space. HDD fragmented? Defragment (never defrag an SSD). Check if AHCI mode is enabled.
4Boot drive not found: Check boot order in BIOS. Verify Secure Boot and CSM settings. For NVMe: ensure UEFI boot mode, not legacy.
5RAID degraded: Replace failed drive. Rebuild array. Do not remove multiple drives. Check RAID controller status regularly.

SSD Best Practices
Maintaining SSD health and performance over time.
TRIM
TRIM tells the SSD which blocks are no longer in use. Enables the SSD to pre-erase them for faster future writes. Enabled by default on modern OS + AHCI mode. Essential for longevity.
Over-Provisioning
Keep 10-20% of SSD free. Gives the controller spare blocks for wear leveling and garbage collection. A 100% full SSD performs significantly worse.
Never Defragment an SSD
SSDs have no seek time -- defragmentation provides zero benefit and burns write cycles. Windows automatically runs TRIM (not defrag) on SSDs. Disable defrag for SSDs.
Monitor SMART Data
Check wear level, reallocated sectors, temperature. Tools: CrystalDiskInfo, smartmontools. Replace before failure -- SSDs can fail suddenly without warning.

Storage Summary
1HDD: Mechanical, cheap per GB, up to 20 TB. Best for bulk storage. 7,200 RPM minimum for performance.
2SSD: No moving parts, 100x faster random I/O. SATA SSD: ~550 MB/s. NVMe Gen 4: ~7,000 MB/s. Default choice for OS boot.
3NVMe is a protocol (not a form factor). It runs over PCIe. M.2 is the physical slot. An M.2 slot can be NVMe or SATA.
4RAID 0 = speed (no redundancy). RAID 1 = mirror. RAID 5 = parity (N-1). RAID 10 = mirror + stripe (N/2).
5RAID is not backup. It protects against drive failure only. Always maintain separate backups.
6TRIM is essential for SSD health. Never defragment an SSD. Keep 10-20% free space.
