CompTIA's 6-Step Methodology
The official troubleshooting process. Every scenario on the exam should be approached this way.
1Identify the problem. Question the user. Identify changes. Check logs and error messages. Reproduce the issue if possible.
2Establish a theory of probable cause. Question the obvious first. Consider multiple causes. Research symptoms online if needed.
3Test the theory. If confirmed, determine next steps. If not confirmed, re-establish a new theory or escalate.
4Establish a plan of action. Plan the fix. Consider impact on other systems. Get approval if needed. Schedule downtime.
5Implement the solution or escalate. Apply the fix. If beyond your skill, escalate to senior tech or vendor. Do not guess.
6Verify full functionality and document. Confirm the fix resolved the issue AND did not break anything else. Document root cause, steps taken, and resolution.
Exam tip: "Question the obvious" means start with simple things: is it plugged in? Is it turned on? Is the correct input selected? Do not jump to complex theories before ruling out the basics.

POST Codes
Power-On Self-Test diagnostic codes displayed on a POST card, motherboard LED display, or debug LEDs.
POST Card (Debug Card)
PCIe/USB diagnostic card that displays 2-digit hex codes during POST. Each code corresponds to a specific test. Stops at the code that failed. Invaluable for no-POST situations.
Onboard Debug LEDs
Modern motherboards have 4 LEDs: CPU, DRAM, VGA, BOOT. They light up during POST and stay lit on the one that failed. Quick visual diagnosis without a POST card.
No POST at All
No fans, no LEDs, nothing. Check: PSU switch, power cable, wall outlet. Test PSU with paperclip test or PSU tester. Check 24-pin and 8-pin CPU connections.
POST Passes, No Boot
POST completes (display shows) but OS does not load. Check boot order, boot device connection, Secure Boot settings, MBR/GPT corruption.

Beep Codes
Audio POST codes -- the motherboard speaker beeps in patterns to indicate hardware failure when video is not yet initialized.
1 shortNormal POST. System passed all tests. This is the good beep. (AMI/Award BIOS)
1 long, 2 shortVideo/GPU failure. GPU not detected, not seated, or failed. Reseat GPU. Try different slot. Test with known-good GPU.
1 long, 3 shortMemory (RAM) failure. RAM not detected or failed. Reseat DIMMs. Try one stick at a time. Try different slots.
ContinuousMemory or power issue. Continuous beeping = RAM not detected at all. Check seating, check power connections.
No beepNo POST occurring. CPU not receiving power, motherboard dead, or no speaker connected. Check PSU and CPU power.
Important: Beep codes vary by BIOS manufacturer (AMI, Award, Phoenix, UEFI). Always check the motherboard manual for the specific beep code chart. The patterns above are common AMI codes.

Hardware Diagnostics
Built-in and third-party tools for testing components.
Windows Memory Diagnostic
Built into Windows. mdsched.exe. Reboots and tests RAM. Reports results after restart. Good first test for random BSODs and crashes.
MemTest86
Bootable USB tool. Tests RAM independently of OS. Run overnight for thorough results. Industry standard. Free version available. Detects individual bad modules.
SMART Monitoring
Self-Monitoring, Analysis, and Reporting Technology. Built into every drive. CrystalDiskInfo (Windows), smartctl (Linux). Warns before drive failure. Check: reallocated sectors, pending sectors, temperature.
Manufacturer Diagnostics
Dell: ePSA/SupportAssist. HP: PC Hardware Diagnostics. Lenovo: Lenovo Diagnostics. Built into UEFI firmware. Tests CPU, RAM, storage, display, battery. Run from boot menu.
Event Viewer
Windows Event Viewer (eventvwr.msc). System log for hardware errors. Application log for software crashes. Check for WHEA errors (hardware), Disk errors, driver failures.
Multimeter
Tests PSU voltage output (12V, 5V, 3.3V rails). Tests cable continuity. Tests wall outlet voltage. Essential for power troubleshooting. Set to DC volts for PSU testing.

Common Symptoms -- Power
Mapping symptoms to probable causes for power-related failures.
SDead system, no LEDs: Wall power, PSU switch, PSU failure, motherboard failure. Test outlet with known-good device. Paperclip test PSU.
SFans spin briefly then stop: Short circuit on motherboard. CPU power not connected. Standoff causing ground contact. Remove board and test on bench.
SRandom shutdowns under load: Overheating (check temps) or PSU undersized for components. Check thermal paste, fan operation, PSU wattage.
SSystem powers on but no display: GPU not seated, GPU power not connected, monitor on wrong input, RAM not seated. Listen for beep codes.
SBurning smell: Immediately unplug. Inspect all connectors, especially 12VHPWR. Check for swollen capacitors on motherboard. Do not power on again until source identified.

Common Symptoms -- Storage
SClicking/grinding (HDD): Head crash imminent. Back up immediately. Do not attempt repair. Replace drive.
SBoot device not found: Check SATA/power cables. Check boot order in BIOS. For NVMe: check if M.2 slot is enabled. Check Secure Boot / CSM settings.
SBSOD (IRQL_NOT_LESS_OR_EQUAL): Often RAM or driver issue. Run memory diagnostics. Boot in Safe Mode. Check recently installed drivers.
SSlow performance: Check drive health (SMART). SSD full? HDD fragmented? Check Task Manager for 100% disk usage (Windows Search indexer, antivirus).
SData corruption: Failing drive, bad RAM, or power instability during writes. Run chkdsk (Windows) or fsck (Linux). Check SMART data. Test RAM.

Common Symptoms -- Display
SNo display output: Monitor power, correct input selected, cable connected, GPU seated, GPU power connected. Try different cable/port. Test with another monitor.
SDistorted/artifacting: GPU overheating, failing VRAM, bad driver. Check GPU temps. Rollback driver. Test with different GPU.
SFlickering: Loose cable, failing backlight (laptop), wrong refresh rate setting, bad driver. Try different cable. Check refresh rate in Display Settings.
SDim display (laptop): Brightness turned down, power saving mode, failing backlight or inverter. Check brightness keys. Connect external monitor to test.
SDead pixels: Stuck pixel (always one color) vs dead pixel (always black). Some can be fixed with pixel-exercising software. Usually requires panel replacement.

Isolation Technique
When you cannot identify the failing component, isolate by removing variables one at a time.
1Minimum boot config: CPU + 1 RAM stick + onboard video (no GPU). If it POSTs, add components back one at a time.
2Swap known-good parts: Replace suspect component with a known-working one. If problem disappears, you found the culprit.
3Move suspect part to another system: If the component fails in a different system, the part is bad. If it works, the original system has the issue.
4Document each swap: Test one variable at a time. If you change two things, you will not know which fixed it.
Bench testing: For stubborn no-POST issues, remove the motherboard from the case and test on a non-conductive surface (motherboard box). This eliminates case shorts and grounding issues.

Documentation
Step 6 of the CompTIA methodology. Every resolution must be documented.
What to Document
Date/time. Reporter name. Symptoms described. Steps taken to diagnose. Root cause identified. Fix applied. Parts replaced. Verification steps. Technician name.
Why Document
Creates knowledge base for future issues. Establishes patterns (recurring failures). Provides audit trail. Protects the technician. Required by SLAs and compliance frameworks.
Ticketing Systems
ServiceNow, Jira Service Management, Zendesk, osTicket. Track incidents from open to resolved. SLA timers. Escalation paths. Reporting and metrics.
Knowledge Base (KB)
Searchable database of known issues and solutions. Write KB articles for recurring problems. Include symptoms, cause, and step-by-step fix. Saves time for the next tech.
Change Management
For infrastructure changes: document what changed, why, rollback plan, and approval. Prevents unauthorized changes from causing outages. Required in ITIL environments.

Safety Procedures
Protect yourself, your equipment, and your data during hardware troubleshooting.
ESD Prevention
Anti-static wrist strap. Touch case chassis before handling components. Anti-static bags for storage. Do not work on carpet. Low humidity increases ESD risk.
PSU Safety
Never open a PSU -- capacitors hold lethal charge even when unplugged. Replace, do not repair. Wait 1 minute after unplugging before disconnecting cables.
CRT/Laser Safety
CRT monitors hold 25,000+ volt charge. Laser printers have hot fusers (200C). Power off and wait before servicing. Never look directly at a laser beam.
Data Protection
Back up user data before any repair. Verify backup integrity. If drive is failing, clone before repair attempt. Document data handling for compliance.
Environmental
Dispose of batteries (CMOS, laptop) at battery recycling. Toner cartridges: recycle through manufacturer programs. CRTs contain lead -- hazmat disposal. Follow local e-waste regulations.
