🔐 Windows Account Types

Account Type Capabilities Use Case
Administrator Full system control, install software, modify system settings, manage users IT staff, system setup
Standard User Run apps, access own files, limited system changes Day-to-day work, most users
Guest Very limited access, temporary use, disabled by default Kiosk, temporary access
Power User Legacy (Windows XP), more than standard but less than admin Deprecated - compatibility only
Exam Tip: Standard User is the recommended account type for daily use. Only use Administrator when necessary for security purposes.

🌐 Local vs Domain Accounts

Local Accounts

  • Stored on the local computer only
  • Can only log in to that specific machine
  • Managed through Computer Management → Local Users and Groups
  • SAM database stores hashed passwords locally

Domain Accounts

  • Stored in Active Directory on domain controller
  • Can log in to any domain-joined computer
  • Centralized management and Group Policy
  • Single Sign-On (SSO) capability
Microsoft Account: Cloud-based account that syncs settings, apps, and files across devices. Links to services like OneDrive, Microsoft 365, and Xbox.

🛡️ User Account Control (UAC)

UAC prevents unauthorized changes by requiring elevation for administrative tasks.

UAC Prompts

  • Consent prompt: Shown to administrators - "Do you want to allow this?"
  • Credential prompt: Shown to standard users - requires admin credentials

UAC Levels (4 Settings)

LevelBehavior
Always notifyPrompt for ALL changes (most secure)
Notify only when apps try to make changesDefault - dim desktop
Notify but don't dim desktopLess secure, faster
Never notifyUAC disabled (NOT recommended)
Access UAC settings: Control Panel → User Accounts → Change User Account Control settings

📁 NTFS Permissions

NTFS permissions control access to files and folders on NTFS-formatted drives.

PermissionAllows
Full Control All permissions + change permissions + take ownership
Modify Read, write, execute, delete files/subfolders
Read & Execute View contents and run programs
List Folder Contents View folder contents (folders only)
Read View files and view attributes
Write Create files/folders, modify attributes
Access: Right-click file/folder → Properties → Security tab

🔄 Permission Inheritance

Child objects (files/subfolders) inherit permissions from parent folders by default.

Key Concepts

  • Inherited permissions: Automatically flow down from parent folders
  • Explicit permissions: Directly assigned to the object
  • Break inheritance: Stop inheriting from parent (copy or remove)

Permission Conflicts

  • Allow + Allow = Cumulative (most permissive wins)
  • Allow + Deny = Deny wins
  • Explicit permissions override inherited permissions
Best Practice: Apply permissions to folders, not individual files. Use groups instead of individual users.

🔗 Share Permissions vs NTFS

Feature Share Permissions NTFS Permissions
Apply to Network access only Local AND network access
Granularity Basic (Read, Change, Full Control) Detailed (6+ permissions)
File level Folder level only Files and folders
Inheritance No Yes
Combined Access: When both share and NTFS permissions apply, the most restrictive permission wins!

Example

Share = Full Control, NTFS = Read → Effective = Read

⚖️ Effective Permissions

The actual access a user has after all permissions are calculated.

Calculation Order

  1. Combine all Allow permissions (cumulative)
  2. Apply any Deny permissions (override allows)
  3. Compare Share vs NTFS → take most restrictive
View Effective Permissions:
Properties → Security → Advanced → Effective Access tab
Enter user/group name to see their calculated permissions

Troubleshooting Access Issues

  • Check group memberships (user may be in denied group)
  • Check inherited vs explicit permissions
  • Check share permissions (if accessing over network)
  • Use Effective Access to verify

💻 Command-Line User Management

Net User Commands

net user - List all users

net user username /add - Create new user

net user username password - Set password

net user username /delete - Delete user

net user username /active:no - Disable account

Net Localgroup Commands

net localgroup - List all groups

net localgroup Administrators - Show group members

net localgroup Administrators username /add - Add to group

✅ Chapter Summary

Key Takeaways

  • Standard User is recommended for daily use
  • UAC protects against unauthorized system changes
  • NTFS permissions are more granular than share permissions
  • Deny always overrides Allow
  • When share + NTFS both apply, most restrictive wins
  • Permissions inherit from parent by default
  • Use groups for permission management, not individual users
