⚠️ What is an Incident?

A security incident is any event that threatens the confidentiality, integrity, or availability of information systems or data.

Common Incident Types

  • Malware infection: Virus, ransomware, or other malicious software
  • Unauthorized access: Someone accessing systems without permission
  • Data breach: Sensitive data exposed or stolen
  • Denial of Service: System or network made unavailable
  • Social engineering: Phishing, vishing, or other deception
  • Physical security breach: Unauthorized physical access
Key Point: Not every event is an incident. An incident has potential to cause harm to the organization.

🔍 Incident Identification

Signs of a Security Incident

CategoryIndicators
SystemUnusual processes, high CPU/memory, disabled security software
NetworkUnexpected traffic, connections to unknown IPs, bandwidth spikes
UserFailed login attempts, account lockouts, privilege escalation
DataModified files, unauthorized access, data exfiltration attempts
PhysicalTailgating, tampering, missing equipment
Report immediately: When in doubt, report suspicious activity. False alarms are better than missed incidents.

🧑‍🚒 First Responder Actions

As a first responder, your immediate actions can make or break an investigation.

Immediate Steps

  1. Stay calm - Don't panic or make hasty decisions
  2. Secure the scene - Limit access to affected systems
  3. Don't touch - Avoid altering evidence on devices
  4. Document everything - Start recording observations
  5. Report up - Notify supervisor/incident response team
  6. Preserve state - Don't power off (unless instructed)
Critical: Do NOT attempt to investigate or remediate on your own. Your job is to preserve evidence and report.

📝 Documentation & Reporting

What to Document

  • Date and time - Exact timestamps of observations and actions
  • Who discovered it - Name and contact information
  • How it was discovered - Alert, user report, routine check
  • Systems affected - Computer names, IP addresses, locations
  • Actions taken - Every step you performed
  • Witnesses - Anyone who observed the incident
Best Practice: Use an incident report form or ticketing system. Written records are essential for legal proceedings.

⛓️ Chain of Custody

The chain of custody documents everyone who handled evidence from collection to court.

Chain of Custody Requirements

ElementPurpose
WhoName of person handling evidence
WhatDescription of the evidence item
WhenDate and time of transfer
WhereLocation where evidence was stored
WhyReason for transfer or access
Legal Importance: Broken chain of custody can make evidence inadmissible in court. Every transfer must be documented.

🔒 Evidence Preservation

Types of Evidence

  • Digital evidence: Files, logs, emails, memory dumps, disk images
  • Physical evidence: Hardware, documents, access cards
  • Testimonial evidence: Witness statements, interviews

Preservation Principles

  • Never work on original - Always use forensic copies
  • Use write blockers - Prevent accidental modification
  • Hash verification - Prove evidence integrity (MD5, SHA-256)
  • Secure storage - Lock evidence in controlled environment

⏱️ Order of Volatility

Collect evidence starting with the most volatile (easily lost) data first.

  • CPU registers, cache - Lost immediately when power off
  • RAM (memory) - Contains running processes, encryption keys
  • Network state - Active connections, routing tables
  • Running processes - What programs are executing
  • Disk storage - Files, logs, databases
  • Remote logging - SIEM, syslog servers
  • Physical media - USB drives, backup tapes
Key Insight: Once you power off a system, volatile data is gone forever. That's why imaging RAM is critical.

💻 Device Handling

Computer Systems

  • Running: Do NOT power off - capture volatile data first
  • Off: Do NOT power on - could trigger malware or overwrite data
  • Screen: Photograph current display before any action

Mobile Devices

  • Airplane mode: Prevent remote wipe commands
  • Faraday bag: Block all wireless signals
  • Keep charged: Dead battery = locked device
  • Don't unlock: Avoid changing device state
Remote Wipe Risk: An attacker could remotely wipe a mobile device. Isolate from network immediately.

📊 Incident Response Process

PhaseActivities
1. PreparationCreate IR plan, train team, gather tools
2. IdentificationDetect and confirm the incident
3. ContainmentStop the spread, isolate affected systems
4. EradicationRemove the threat from systems
5. RecoveryRestore systems to normal operation
6. Lessons LearnedDocument findings, improve defenses
CompTIA Note: Know this 6-phase model - it's commonly tested on the exam.

🔄 Post-Incident Analysis

Lessons Learned Meeting

  • What happened? - Timeline and root cause
  • What worked well? - Effective responses
  • What could improve? - Gaps in response
  • What changes needed? - Policies, procedures, tools

Documentation Updates

  • Update incident response procedures
  • Revise security policies if needed
  • Add indicators of compromise to monitoring
  • Schedule additional training if gaps identified
Continuous Improvement: Every incident is a learning opportunity. Use it to strengthen defenses.

✅ Chapter Summary

  • Incident = event that threatens confidentiality, integrity, or availability
  • First responder: Secure, document, report - don't investigate
  • Chain of custody: Who, what, when, where, why for all evidence
  • Order of volatility: Collect most volatile data first (RAM before disk)
  • Evidence integrity: Use write blockers and hash verification
  • Mobile devices: Faraday bag, airplane mode, keep charged
  • 6 phases: Prepare, identify, contain, eradicate, recover, lessons learned
