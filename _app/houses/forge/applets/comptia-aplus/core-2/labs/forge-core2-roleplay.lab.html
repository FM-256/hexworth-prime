Root Cause Analysis

Issue: Windows 11 boot failure with "No bootable device found" error

Root Cause: BIOS boot order was changed or reset, causing the system to attempt booting from a non-bootable device (likely USB or network) before checking the internal hard drive containing the OS Boot Manager.

Why It Occurred: Common triggers include Windows updates, BIOS resets, CMOS battery issues, or accidentally changing boot priority when a USB device was connected.

Replication Steps (For Setup)
  1. Access BIOS/UEFI on a Windows 11 machine (typically F2, F9, F12, or Del during POST)
  2. Navigate to Boot Order or Boot Priority settings
  3. Move "OS Boot Manager" or "Windows Boot Manager" down in priority below USB or Network Boot
  4. Save changes and exit (F10)
  5. System will display "No bootable device" error on next startup
Troubleshooting Workflow
  1. Gather Information: Confirm symptoms, OS version, and laptop manufacturer
  2. Access Boot Menu: Guide user to manufacturer-specific boot key (F9 for HP)
  3. Verify Hardware Detection: Confirm OS Boot Manager appears in boot options
  4. Restore Functionality: Select correct boot device
  5. Explain Root Cause: Educate user on boot order and prevention
  6. Document: Note resolution for future reference

Root Cause Analysis

Issue: Windows 10 desktop experiencing slow network connectivity despite hardwired ethernet connection

Root Cause: DHCP client failure resulting in APIPA (Automatic Private IP Addressing) assignment of 169.254.x.x address. Computer unable to communicate with DHCP server on router to obtain valid IP configuration.

Why It Occurred: Common causes include temporary DHCP server unavailability during boot, network cable disconnect/reconnect, router restart without successful DHCP lease, or Windows network service glitch.

Replication Steps (For Setup)
  1. On Windows 10 machine, open Command Prompt as Administrator
  2. Disable DHCP client service: net stop dhcp
  3. Release current IP: ipconfig /release
  4. System will auto-assign APIPA address in 169.254.0.0/16 range
  5. Verify with ipconfig - should show 169.254.x.x
  6. To restore for student: net start dhcp then ipconfig /renew
Troubleshooting Workflow
  1. Isolate the Issue: Confirm single device vs. network-wide problem
  2. Check Physical Layer: Verify cable connection (though not required in this scenario)
  3. Diagnose IP Configuration: Use ipconfig to identify APIPA address
  4. Resolve DHCP Issue: Release and renew IP address lease
  5. Verify Resolution: Confirm valid IP address assigned and test connectivity
  6. Educate User: Explain APIPA, DHCP, and how to recognize/fix in future
Learning Objectives (CompTIA A+ Core 2)
  • 1.4: Given a scenario, use the appropriate Microsoft command-line tool – Mastery of ipconfig, /release, and /renew switches
  • 1.6: Given a scenario, configure Microsoft Windows networking features on a client/desktop – Understanding DHCP, APIPA, and IP addressing

Root Cause Analysis

Issue: Windows 11 desktop experiencing repeated BSOD (Blue Screen of Death) with stop code DRIVER_IRQL_NOT_LESS_OR_EQUAL after installing a new NVIDIA RTX 4070 graphics card

Root Cause: An incompatible or buggy GPU driver is attempting to access an invalid memory address at an elevated IRQL (Interrupt Request Level), causing a kernel-level exception that triggers the blue screen crash.

Why It Occurred: The user installed the latest NVIDIA driver package, which may contain a bug specific to their hardware revision, motherboard chipset, or BIOS version. Driver version incompatibilities are common with newly released GPU models or freshly published driver packages that have not been widely tested across all configurations.

Replication Steps (For Setup)
  1. On a Windows 11 machine with a dedicated GPU, open Device Manager
  2. Expand Display adapters, right-click the GPU, and select Properties
  3. Under the Driver tab, note the current driver version for rollback reference
  4. To simulate the error state: install an intentionally mismatched or older driver version for the GPU, or use Device Manager to set the device status to "error" for demonstration
  5. For verbal-only simulation, describe the BSOD stop code and have students walk through the diagnostic and resolution process
  6. Ensure students can navigate the full Safe Mode boot path: Settings → System → Recovery → Advanced startup → Troubleshoot → Advanced options → Startup Settings → Enable Safe Mode
Troubleshooting Workflow
  1. Identify the Stop Code: Record the BSOD error message (DRIVER_IRQL_NOT_LESS_OR_EQUAL) and correlate with recent changes
  2. Establish Timeline: Confirm the crashes began immediately after the new GPU and driver installation
  3. Boot to Safe Mode: Use Settings → Recovery → Advanced startup, or Shift+Restart from the login screen, to access Windows Recovery Environment and select Safe Mode
  4. Open Device Manager: Right-click Start → Device Manager. Expand Display adapters and locate the GPU with the yellow exclamation mark
  5. Roll Back or Uninstall Driver: Open GPU properties → Driver tab → Roll Back Driver. If Roll Back is unavailable, select Uninstall Device and allow Windows to load a generic driver on reboot
  6. Restart and Verify: Boot normally and confirm the system is stable without BSOD recurrence
  7. Educate User: Explain driver compatibility, recommend checking release notes before future driver updates, and mention Windows Update as an alternative driver source
