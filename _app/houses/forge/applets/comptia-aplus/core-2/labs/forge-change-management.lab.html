SCENARIO: Email Server Security Patch Deployment

Change Request Background

A critical security vulnerability (CVE-2024-1234) has been discovered in the company's email server software. Microsoft has released a patch that needs to be deployed to fix the vulnerability.

  • System: Exchange Server 2019 (MAIL-SRV-01)
  • Users Affected: 250 employees
  • Current Version: 15.2.1118.20
  • Target Version: 15.2.1118.26 (Security Update)
  • Vulnerability: Remote code execution (CVSS 9.8 - Critical)

Task 3: Detailed Rollback Plan

Every change must have a rollback plan. Create a detailed procedure for reverting this change if something goes wrong.

Why Rollback Plans Matter

If the Exchange patch causes issues (email outage, data corruption, service failures), you need to restore service quickly. The rollback plan must be clear enough for any team member to execute.

Task 4: CAB Presentation

Present your change request to the Change Advisory Board. Answer their questions to demonstrate readiness.

CAB Meeting Agenda

The CAB needs to understand the business justification, technical approach, risk assessment, and rollback capability before approving any change.

Sarah Chen (IT Manager)

Can you explain why this change cannot wait until the next scheduled maintenance window in 3 weeks?

Question 1: Why is this urgent?

"Microsoft told us to patch immediately."
"This CVE has a CVSS score of 9.8 (Critical) and allows remote code execution. Active exploitation has been observed in the wild. Delaying 3 weeks significantly increases our risk of compromise. The vulnerability affects our internet-facing Exchange server."
"We usually patch right away. It's just standard procedure."
Marcus Johnson (Security Officer)

What is your rollback plan if the patch causes issues? How quickly can you restore email service?

Question 2: What about rollback?

"We can just uninstall the patch if it doesn't work."
"We haven't really thought about that yet. We'll figure it out if we need to."
"We have a full system backup and Exchange database backup that have been verified. Our rollback procedure is documented step-by-step and can restore service within 30-60 minutes. The rollback can be authorized by the on-call Technical Lead without additional CAB approval."

CAB Feedback: Presentation Approved

The board is satisfied with your technical justification, risk assessment, and rollback planning. Proceed to formal approval voting.
