1 Server Roles Overview

Networks rely on various servers to provide essential services. Each server role handles specific tasks that keep the network functioning efficiently.

Web Server

  • Hosts websites and web applications
  • Responds to HTTP/HTTPS requests
  • Apache, IIS, Nginx are common examples
  • Uses ports 80 (HTTP) and 443 (HTTPS)

File Server

  • Centralized storage for network files
  • Manages file permissions and access
  • Enables file sharing across the network
  • Uses SMB (Windows) or NFS (Linux)

Print Server

  • Manages networked printers
  • Handles print job queuing
  • Can be dedicated hardware or software
  • Centralizes printer management

Mail Server

  • Sends and receives email
  • Provides anti-spam filtering
  • SMTP (25), POP3 (110), IMAP (143)
  • Exchange, Postfix are examples

Dedicated vs Non-Dedicated Servers

Dedicated Server: Performs only server functions, optimized for its role. Used in enterprise environments.

Non-Dedicated Server: Also used as a workstation while providing services. Common in small offices.

DHCP Server

  • Automatically assigns IP addresses
  • DORA Process: Discover, Offer, Request, Acknowledge
  • Scope: Range of available IPs
  • Reservations: Static assignment by MAC

Proxy Server

  • Acts as intermediary for requests
  • Caching: Speeds up common requests
  • Filtering: Blocks unwanted content
  • Hides client identity from servers

Exam Tip

Remember DORA for DHCP: Discover (client broadcasts), Offer (server responds), Request (client accepts), Acknowledge (server confirms). This process is heavily tested!

2 DNS Deep Dive

The Domain Name System (DNS) translates human-readable domain names into IP addresses. Understanding DNS hierarchy and record types is essential for the exam.

DNS Resource Records

DNS uses Zone Files containing Resource Records (RRs) to map names to addresses. There are over 30 record types, but these are most important:

Record Type Purpose Example
A Maps hostname to IPv4 address www.example.com → 192.168.1.1
AAAA Maps hostname to IPv6 address www.example.com → 2001:db8::1
MX Mail Exchange - identifies mail server example.com → mail.example.com
CNAME Canonical Name - alias for another domain www → webserver.example.com
PTR Pointer - reverse lookup (IP to name) 192.168.1.1 → www.example.com

Memory Trick: DNS Records

A = Address (IPv4) | AAAA = Four A's for IPv6 (128-bit) | MX = Mail eXchange | CNAME = CanonNAME (alias) | PTR = PoinTeR (reverse)

Exam Tip

A vs AAAA: A record = IPv4 (32-bit), AAAA = IPv6 (128-bit). The "quad-A" has 4 letters for the larger address space. This distinction appears frequently on exams!

3 Authentication & Logging

Authentication servers verify user identities and control access to network resources. Logging servers collect and analyze security events.

AAA Framework

Authentication

  • Verifies user identity
  • "Who are you?"
  • Username/password, tokens, biometrics

Authorization

  • Determines access permissions
  • "What can you do?"
  • Based on roles, groups, policies

Accounting

  • Tracks user activities
  • "What did you do?"
  • Logging, auditing, billing

Authentication Protocols

Protocol Type Features
RADIUS Open Standard Authentication + Authorization only; encrypts password only; UDP-based; widely used
TACACS+ Cisco Proprietary Full AAA support; encrypts entire packet; TCP-based; granular control

Exam Tip

RADIUS vs TACACS+: Remember - RADIUS = Open standard, TACACS+ = Cisco proprietary. TACACS+ provides full AAA and encrypts the entire packet, while RADIUS only encrypts the password.

Syslog

Syslog is a standard protocol for collecting and storing log messages from network devices.

Syslog Clients

  • Send messages to the server
  • Facility Code: 0-23 (identifies device type)
  • Severity Level: 0-7 (importance)
  • Text description of the event

Syslog Servers

  • Collect and store messages
  • Listener service receives logs
  • Database stores events
  • Management/filtering software

Syslog Severity Levels

Level Name Description
0 Emergency System is unusable
1 Alert Immediate action needed
2 Critical Critical conditions
3 Error Error conditions
4 Warning Warning conditions
5 Notice Normal but significant
6 Informational Informational messages
7 Debug Debug-level messages

Memory Trick: Syslog Severity

"Every Alley Cat Eats Watery Noodle In Dishes"
Emergency(0) - Alert(1) - Critical(2) - Error(3) - Warning(4) - Notice(5) - Informational(6) - Debug(7)
Lower number = More severe!

4 Internet Appliances

Internet appliances are specialized network devices that perform specific functions to improve security, performance, and management.

Spam Gateway

  • Filters malicious emails
  • Blocks phishing attempts
  • Quarantines suspicious messages
  • Sits between internet and mail server

Unified Threat Management (UTM)

  • All-in-one security appliance
  • Combines multiple security features
  • Firewall + IDS/IPS + Antivirus
  • VPN + Content filtering

Load Balancer

  • Distributes traffic across servers
  • Performance: Faster response
  • Scalability: Easy to add servers
  • Reliability: Redundancy if one fails

Endpoint Management Server

  • Deploys security policies
  • Installs/updates operating systems
  • Centralized backup management
  • Monitors endpoint compliance

DMZ (Demilitarized Zone)

Also called Perimeter Network or Screened Subnet. A DMZ is a network segment that sits between the internal network and the internet, hosting public-facing services (web servers, mail servers) while protecting the internal network with firewalls on both sides.

Exam Tip

UTM is the "Swiss Army knife" of network security - it combines firewall, intrusion detection, antivirus, VPN, and content filtering into one device. Know that it "unifies multiple security features onto a single platform."

5 Legacy, Embedded Systems & IoT

Legacy Systems

Legacy systems are older technologies still in use due to cost, compatibility, or critical functions:

Legacy Hardware

  • Older servers and workstations
  • Proprietary equipment
  • May lack modern security features

Legacy Software

  • Applications no longer supported
  • Critical business functions
  • May have security vulnerabilities

Legacy Network Protocols

  • Older protocols still required
  • Compatibility requirements
  • Security concerns

Embedded Systems

Embedded systems are small or large non-computer devices with integrated software on microcontrollers/microprocessors for performing dedicated functions.

SCADA - Supervisory Control and Data Acquisition

Industrial control systems used to monitor and control infrastructure (power grids, water treatment, manufacturing). SCADA systems are often legacy/embedded and require special security considerations.

Internet of Things (IoT)

IoT devices connect everyday objects to the internet, enabling automation and remote control:

Home Automation

  • Smart thermostats (Nest, Ecobee)
  • Smart lighting systems
  • Window treatments/blinds
  • Sprinkler/irrigation systems

Home Security

  • Smart door locks
  • Video doorbells (Ring)
  • Security cameras
  • Motion sensors

Voice Assistants

  • Amazon Alexa
  • Google Assistant
  • Apple Siri
  • Voice-enabled devices

Exam Tip

IoT security is a growing concern! These devices often have weak default passwords, limited update capabilities, and can be entry points for network attacks. Always change default credentials and isolate IoT devices on separate network segments when possible.

6 Cloud Computing Models

"The Cloud" refers to accessing remote servers over the internet to store files, run applications, or use computing resources. Understanding the three main service models is crucial for the exam.

IaaS - Infrastructure as a Service

  • Provider gives: Network hardware, storage, servers
  • You manage: OS, applications, data
  • Pay for what you use
  • Examples: AWS EC2, Azure VMs, Google Compute

PaaS - Platform as a Service

  • Builds on IaaS
  • Adds: Development tools, middleware
  • You manage: Applications and data
  • Examples: Google App Engine, Azure App Service

SaaS - Software as a Service

  • Subscription-based
  • Everything is rented (software, platform, infrastructure)
  • You manage: Just your data
  • Examples: Google Docs, Office 365, Salesforce

Responsibility Matrix

Who manages what? This is critical for the exam:

Layer On-Premises IaaS PaaS SaaS
Applications You You You Provider
Data You You You You
Runtime/Middleware You You Provider Provider
OS You You Provider Provider
Virtualization You Provider Provider Provider
Servers/Storage/Network You Provider Provider Provider

Blue = You manage | Purple = Provider manages

Memory Trick: Cloud Services

IaaS = "I" manage the most (Infrastructure - you get raw resources)
PaaS = "P"rogrammers love this (Platform - development tools included)
SaaS = "S"imple to use (Software - just log in and use it)

Exam Tip

When asked "Which cloud model...?" look for keywords:
- Virtual servers, raw computing = IaaS
- Development platform, deploy apps = PaaS
- Subscription, web-based app = SaaS

7 Cloud Deployment Types & Features

Cloud Deployment Models

Type Description Best For
Private Cloud Dedicated infrastructure for one organization; can be on-premises or hosted Enterprises with security/compliance needs
Public Cloud Shared infrastructure provided by third party; multi-tenant Startups, variable workloads, cost savings
Hybrid Cloud Combination of private and public; data/apps can move between Organizations needing flexibility
Community Cloud Shared by organizations with common concerns; cost shared Government, healthcare, research groups

Cloud Characteristics

On-Demand Self-Service

  • Access resources without human intervention
  • Provision storage, computing as needed
  • Self-service portal

Broad Network Access

  • Access from any device via network
  • Workstations, laptops, mobile phones
  • Web browser interface
  • Ubiquitous access - anywhere, anytime

Resource Pooling

  • One large pool divided among clients
  • Multi-tenant model
  • Dynamic resource assignment

Rapid Elasticity

  • Scale up or down quickly
  • Pay-as-you-grow
  • Handle traffic spikes

Measured (Metered) Service

  • Pay only for what you use
  • Usage tracking and billing
  • Transparency in resource consumption

High Availability

  • 99.9% uptime (three nines)
  • 99.99% uptime (four nines)
  • Redundancy and failover

Cloud Storage & Applications

Service Free Tier Type
Dropbox 2 GB Cloud Storage
Apple iCloud 5 GB Cloud Storage
Microsoft OneDrive 5 GB Cloud Storage
Box 10 GB Cloud Storage
Google Drive 15 GB Cloud Storage

Synchronization Applications

Cloud sync apps run in the background, keeping local folders synchronized with cloud storage. Files appear as if stored locally but are actually mirrored to the cloud, enabling access from any device and automatic backup.

Exam Tip

Rapid Elasticity is a key cloud characteristic! It means resources can be quickly scaled up or down based on demand. This is different from traditional IT where you must purchase and install new hardware.

8 Virtualization Concepts

Virtualization creates logical (virtual) versions of computing resources, allowing multiple operating systems to run on a single physical machine.

Hypervisor Types

A Hypervisor (Virtual Machine Manager/VMM) is software that allows multiple operating systems to share a single hardware host.

Feature Type 1 (Bare Metal) Type 2 (Hosted)
Runs On Directly on hardware On top of existing OS
Use Case Servers, data centers Desktop virtualization
Performance Better (no host OS overhead) Lower (host OS adds overhead)
Examples VMware ESXi, Microsoft Hyper-V, Citrix XenServer VirtualBox, VMware Workstation, Parallels

Memory Trick: Hypervisor Types

Type 1 = #1 performance (bare metal, directly on hardware)
Type 2 = 2 layers (Host OS + Hypervisor stacked)

Purpose of Virtual Machines

Cost Savings

  • Run multiple servers on one physical machine
  • Reduce hardware costs
  • Lower power consumption

Sandbox Testing

  • Isolated environment for testing
  • Test software without risk
  • Malware analysis in safe space

Development/Testing

  • Create test environments quickly
  • Snapshot and rollback capabilities
  • Test different OS configurations

Legacy Software/OS

  • Run old applications
  • Cross-platform virtualization
  • Compatibility without old hardware

Client-Side Virtualization Requirements

Resource Requirement
CPU Multiple cores; virtualization support (Intel VT-x, AMD-V)
RAM Enough to support host OS AND all guest VMs simultaneously
Storage (HDD/SSD) Sufficient space for each guest OS installation
Network Adequate bandwidth if VMs need network access

Virtual Desktop Infrastructure (VDI)

On-Premises VDI: Virtual desktops hosted on local servers in your data center.
Cloud VDI: Virtual desktops hosted by cloud providers (Azure Virtual Desktop, AWS WorkSpaces).

VM Security & Network Requirements

Security Requirements

  • Same as physical machines!
  • Anti-malware protection
  • Regular OS updates
  • Firewall configuration

Network Requirements

  • Same as host if network access needed
  • NAT, Bridged, or Host-only modes
  • Virtual switches for VM networking

Exam Tip

Type 1 vs Type 2 is HEAVILY tested! Remember:
- Type 1 (ESXi, Hyper-V) = Bare metal = Servers = Better performance
- Type 2 (VirtualBox, VMware Workstation) = Hosted = Desktop = Runs on existing OS
