Domain 4: Cloud & Virtualization

Cloud Models, Services & Virtual Machines (11% of Exam)

Cloud Deployment Models

Cloud computing delivers computing resources over the network instead of locally.

☁️ Public Cloud

Shared infrastructure

AWS, Azure, Google

Pay per use

Highest scalability

🏢 Private Cloud

Single organization

On-premises or hosted

Maximum control

Higher cost

🔄 Hybrid Cloud

Mix of public + private

Flexible workloads

Data sovereignty

Complex management

👥 Community Cloud

Shared by organizations

Common requirements

Example: government

Shared costs

Public cloud = shared resources, lowest cost, internet access. Private cloud = dedicated resources, highest security, can be on-premises. Hybrid = best of both.

Cloud Service Models

IaaS

Infrastructure as a Service

VMs, storage, networks

You manage: OS, apps

Ex: AWS EC2, Azure VMs

PaaS

Platform as a Service

Development platform

You manage: Code, data

Ex: Heroku, App Engine

SaaS

Software as a Service

Complete applications

You manage: Users only

Ex: Microsoft 365, Gmail

Pizza Analogy: IaaS = you get ingredients and make pizza. PaaS = you get dough and toppings, oven provided. SaaS = pizza delivered ready to eat.

Cloud Characteristics

  • Elasticity: Scale up/down automatically based on demand
  • On-demand: Resources available when needed
  • Metered/Pay-per-use: Pay only for what you consume
  • High Availability: Multiple data centers, redundancy
  • Resource Pooling: Shared infrastructure, multi-tenant

Client-Side Virtualization

Virtualization allows running multiple operating systems on a single physical machine.

Virtual Machine Components

  • Hypervisor: Software that creates and manages VMs
  • Guest OS: Operating system running in the VM
  • Host OS: Operating system on physical machine
  • Virtual Hard Disk: File representing VM's storage
  • Virtual Network: Software-defined networking for VMs

Hypervisor Types

Type 1 (Bare Metal)

Runs on hardware directly

VMware ESXi, Hyper-V

Better performance

Server environments

Type 2 (Hosted)

Runs on top of OS

VirtualBox, VMware Workstation

Easier to set up

Desktop use

VM Use Cases

  • Testing: Try software without affecting main system
  • Development: Test across different OS environments
  • Legacy Software: Run old apps requiring older OS
  • Security: Sandboxed environment for suspicious files
  • Training: Create lab environments
VMs require CPU virtualization support (Intel VT-x or AMD-V). This must be enabled in BIOS/UEFI. Check with Task Manager → Performance → CPU → "Virtualization: Enabled".
