Local vs Microsoft Account
Two account types, two fundamentally different trust models.
Local Account Characteristics
Stored in SAM database on local machine. Valid only on that device. Managed via Computer Management or net user. No sync, no cloud backup. Suitable for standalone workstations or offline environments. No internet required.
Microsoft Account Characteristics
Consumer cloud identity (outlook.com, hotmail.com). Syncs settings, themes, passwords across devices. Required for Windows 11 Home during setup. Not appropriate for enterprise domain or Azure AD environments — use Azure AD accounts instead.

UAC Elevation Flow
How Windows handles privilege elevation from user request to elevated process.
Consent Prompt (Administrator)
Blue shield. Shown when an Administrator-level account tries to run an elevated operation. User clicks Yes — no credentials required. The default for admin accounts on Windows.
Credential Prompt (Standard User)
Blue shield with user icon. Shown to standard users. Must enter local or domain Administrator credentials to proceed. Prevents privilege escalation without explicit admin authorization.

NTFS Permission Inheritance
Permissions flow down from parent to child — unless inheritance is blocked.
Inheritance Rules
Child objects inherit parent permissions by default. Explicit permissions on a child take precedence over inherited ones. Deny always overrides Allow at the same or higher level. Effective permissions = union of all permissions.
NTFS Standard Permissions
Full Control, Modify, Read & Execute, List Folder Contents, Read, Write. Full Control includes Delete and Change Permissions. Modify does not include Delete Subfolders or Change Permissions.
Breaking Inheritance
Right-click folder → Properties → Security → Advanced → Disable Inheritance. Choose to copy or remove inherited entries. Use when a subfolder needs fundamentally different access than the parent (e.g., confidential data folder).

Authentication Flow
Credentials travel a defined path before access tokens are issued.
NTLM vs. Kerberos
NTLM = challenge-response hash authentication used for local accounts. Kerberos = ticket-based authentication used on domain-joined machines. Kerberos requires line-of-sight to a domain controller. When the DC is unreachable, Windows falls back to NTLM.

UAC Configuration Levels
Four UAC slider positions — know which is default, which is dangerous, which is locked down.
Level 4 — Always Notify (Highest)
Prompts for ALL changes — software-initiated AND user-initiated changes to Windows settings. Most secure. Recommended for high-security environments and kiosks. Can feel intrusive for daily use.
Level 3 — Notify Apps Only (DEFAULT)
Prompts when apps try to make changes. Does NOT prompt when the user directly changes Windows settings. This is the Windows default. Secure Desktop enabled. Balances security with usability for most users.
Level 2 — Notify Apps, No Secure Desktop
Same as Level 3 but WITHOUT Secure Desktop dimming. Susceptible to UI spoofing — a malicious process could potentially overlay the UAC prompt. Not recommended. Rarely used in practice.
Level 1 — Never Notify (DISABLED)
UAC effectively off. All elevation is silent — no prompts. Apps can make system changes without any user notification. Significant security risk. Only appropriate for locked-down kiosk where policies control everything else.
UAC Group Policy Path
Computer Configuration > Windows Settings > Security Settings > Local Policies > Security Options > "User Account Control: ..." — If UAC prompts disrupt a LOB app, correct fix is a Scheduled Task with "Run with highest privileges" — NOT disabling UAC.

Windows Hello Authentication
Five sign-in options — PIN is more secure than a password and that is heavily tested.
Password
Traditional text credential. Stored as NTLM hash locally. Susceptible to phishing and credential stuffing. Complexity enforced via Group Policy or Intune. Weakest factor category: something you know.
PIN (Windows Hello)
Tied to the device TPM — the PIN is valid ONLY on that specific device. Even if an attacker learns the PIN, it is useless on another device. Backed by cryptographic keys in TPM. More secure than a password despite appearing simpler.
Biometrics
Fingerprint: Requires fingerprint reader. Template in TPM — never sent to Microsoft. Face: Requires Windows Hello IR camera. Uses infrared depth — resistant to photo spoofing. Both templates stay on device.
FIDO2 Security Keys
Hardware keys (YubiKey, etc.). Phishing-resistant — the key verifies the relying party's domain before responding. Highest assurance level. Supports passwordless Azure AD sign-in. Something you have category.
WHfB vs. Windows Hello (Consumer)
Windows Hello for Business = enterprise-grade, configured via GPO or Intune, requires Azure AD or AD, supports Conditional Access MFA compliance. Consumer Hello is local-only, tied to Microsoft account or local account.

NTFS vs Share Permissions
Two permission systems — effective access is always the most restrictive combination.
NTFS PermissionWhat It Allows
Full ControlEverything including Delete, Change Permissions, Take Ownership
ModifyRead, write, delete files/folders but not change permissions
Read & ExecuteOpen and run files; traverse folders
List FolderView filenames inside folder (no access to content)
ReadOpen and read files; no write, no execute
WriteCreate files and folders; modify existing
Share PermissionWhat It Allows
Full ControlRead, Change, and set permissions for the share
ChangeRead and Write — can modify and delete but not set permissions
ReadView file names, read content, run programs
Most Restrictive Wins
Effective access over the network = most restrictive of NTFS AND Share permissions. Example: NTFS Modify + Share Read = effective Read only over network. Locally, only NTFS applies (shares don't apply to local access).

Credential Manager & Stored Credentials
Windows stores credentials in a vault — useful for troubleshooting auth failures.
Windows Credential Vault
Stores: saved passwords for network shares, RDP connections, mapped drives, web credentials (Internet Explorer/Edge legacy). Access via Control Panel > Credential Manager or cmdkey /list from CLI. Credentials are encrypted with the user's profile key.
Certificate-Based Credentials
Windows Hello for Business, smart cards, VPN certificates. Stored in the Windows Certificate Store (certmgr.msc or certlm.msc for machine). Personal store holds user certs; Computer Personal store holds machine certs.
Troubleshooting Auth Failures
cmdkey /list — list stored credentials
cmdkey /delete:target — remove specific credential
whoami /all — show current token, SID, groups
klist — list Kerberos tickets (domain only)
Common Auth Issues
Stale cached credentials preventing new password use — clear Credential Manager
Kerberos clock skew >5 minutes causes ticket rejection
Duplicate SIDs on domain — machines cloned without sysprep

Calculating Effective Permissions
Three rules determine what a user can actually do with a file or folder.
1
Cumulative permissions — A user's effective NTFS permissions = union of all Allow permissions from their user account AND all group memberships. If User1 is in Group-A (Read) and Group-B (Write), they get Read + Write = Modify effective.
2
Deny overrides Allow — Explicit Deny always overrides Allow, regardless of source. If any group the user belongs to has Deny on a resource, that deny takes effect even if the user's account has Allow. Exception: Full Control trumps Deny on subfolders if set at parent.
3
Local vs. network access — Locally logged in: only NTFS permissions apply. Over the network via share: effective access = most restrictive of NTFS and Share permissions combined.
Worked Example
User is in Sales (NTFS: Modify on Reports folder) and Managers (Share: Read on Reports share). Accessing Reports over the network: NTFS Modify combined with Share Read = effective network access is Read. Accessing locally: Modify applies (share permissions ignored for local access).
View Effective Permissions
File/Folder Properties > Security > Advanced > Effective Access tab. Enter a user or group name to see their calculated effective permissions. Use this to troubleshoot "access denied" errors without having to manually enumerate all group memberships.

MFA & Conditional Access
Modern authentication adds context to identity verification beyond just the password.
Three Authentication Factors
Something you know: Password, PIN, security questions. Something you have: Authenticator app, SMS code, FIDO2 key, smart card. Something you are: Fingerprint, face scan, iris scan. MFA requires two or more factor categories.
Microsoft Authenticator App
Time-based One-Time Password (TOTP) codes, number matching prompts, and passwordless phone sign-in. Most common MFA factor in Microsoft 365 environments. Users register via aka.ms/mfasetup. Backup codes available for emergency access.
Conditional Access (Azure AD)
Policy-based access control: grant/block/require MFA based on conditions. Conditions include: user/group, device compliance status, location (trusted IP), app being accessed, sign-in risk level. Example policy: require MFA for all access outside corporate network.
Exam Fact: WHfB and MFA
Windows Hello for Business satisfies Azure AD's MFA requirement natively. WHfB = something you have (device with TPM) + something you know or are (PIN or biometric). A WHfB sign-in counts as an MFA-compliant authentication for Conditional Access policies.

Built-in Administrator
The built-in Administrator account is disabled by default and has no UAC lockout policy. Do not enable it for routine use. To enable in emergencies: net user Administrator /active:yes. Always rename it and set a strong password.

BitLocker & Drive Encryption
Full-disk encryption protects data at rest — authorization controls who can unlock.
BitLocker Requirements
Windows Pro, Enterprise, or Education. TPM 1.2 or higher (TPM 2.0 preferred). UEFI with Secure Boot recommended. Without TPM: can use USB startup key or password at boot (requires Group Policy change). Not available on Windows Home.
BitLocker Unlock Methods
TPM-only: Silently unlocks if hardware state matches (most common). TPM + PIN: Requires PIN at boot — most secure. TPM + USB: Requires startup USB key. Password: No TPM required. Recovery Key: 48-digit key stored in AD/Azure AD or file/print.
Device Encryption (Home)
Simplified automatic encryption on Windows Home for devices with Modern Standby / Connected Standby and TPM. Narrower than BitLocker — no management tools, no policy control. Recovery key backed up to Microsoft account automatically.
BitLocker Commands
manage-bde -status — show encryption status • manage-bde -on C: -RecoveryPassword — enable with recovery key • manage-bde -protectors -get C: — show key protectors • Store recovery keys in Active Directory or Azure AD for enterprise recovery.

Knowledge Check
Three exam-style scenarios — authentication, UAC, and permissions.
Q1: UAC Prompt Fatigue
A user is prompted by UAC every time they open a LOB app. They are a local Admin. Security policy prohibits disabling UAC. Best solution?

A) Set UAC to Never Notify • B) Move user to Power Users • C) Create elevated Scheduled Task • D) Add to Backup Operators

Answer: C) — Scheduled Task with "Run with highest privileges" elevates without triggering UAC consent prompt. Policy-compliant.
Q2: BYOD Device Registration
Contractors use personal laptops to access Microsoft 365. IT wants basic compliance (screen lock, encryption) but NOT full MDM of personal devices. Which join type?

A) Azure AD Joined • B) Azure AD Registered • C) Hybrid AD Joined • D) Domain Joined

Answer: B) — Azure AD Registered = BYOD. MAM policies apply at app level without full MDM enrollment.
Q3: Windows Hello PIN
Why is a 6-digit Windows Hello PIN considered more secure than a complex password?

A) Longer • B) Encrypted differently • C) Device-bound via TPM • D) Biometric backup

Answer: C) — PIN is bound to the device TPM. Stolen PIN is useless on any other device. Password is portable — stolen credentials work anywhere.

Module Summary
01
Authentication = "Who are you?" | Authorization = "What can you do?" — both must be correctly configured on every Windows client.
02
Local account = SAM database, device-only. Microsoft Account = cloud sync, consumer. Azure AD = enterprise SSO. Domain/AD DS = on-prem, requires Pro+.
03
Domain Join requires Pro or higher. Windows Home cannot join an Active Directory domain or access gpedit.msc.
04
UAC default level = Notify when apps make changes (Level 3). Never Notify = UAC disabled — never the right answer for prompt fatigue. Use Scheduled Tasks instead.
05
Windows Hello PIN is hardware-bound to the TPM — more secure than a password even though it appears simpler. Biometric templates never leave the device.
06
Azure AD Joined = company-owned, full MDM. Azure AD Registered = BYOD, MAM/app-level policies only. Hybrid Join = domain-joined + Azure AD synced.
07
NTFS + Share permissions: Most restrictive of the two applies over network. Locally, only NTFS applies. Deny always overrides Allow. Effective permissions = union of all Allow minus any Deny.
08
Built-in Administrator is disabled by default and has no lockout policy. Leave it disabled — use named admin accounts instead.
09
WHfB satisfies MFA for Conditional Access policies — it counts as two factors (device + PIN/biometric). Consumer Windows Hello is local-only and does not meet this requirement.
10
BitLocker requires Pro/Enterprise/Education. Not available on Home. Device Encryption (Home) is a simplified subset with narrower hardware requirements.
