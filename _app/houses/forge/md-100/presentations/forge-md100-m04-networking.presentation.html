IPv4 Configuration
Addressing, assignment methods, and the APIPA fallback.
Static Assignment
Manually set: IP address, subnet mask, default gateway, preferred DNS, alternate DNS. Path: Settings > Network & Internet > adapter properties, or Control Panel > Network Connections. Required for servers, printers, and infrastructure devices that must be located by a fixed IP.
DHCP Assignment
Server assigns IP automatically. Lease-based — expires and renews. Appropriate for end-user workstations. DHCP delivers: IP, subnet mask, default gateway, DNS server, lease duration. If DHCP fails, Windows falls back to APIPA automatically.
APIPA Fallback
169.254.0.0/16 range assigned automatically when DHCP server is unreachable. APIPA allows communication with other APIPA hosts on the same segment only — no internet, no domain access, no default gateway. Seeing this IP means DHCP is broken.
ipconfig /all
Show all adapter details: MAC, DHCP server, lease info, DNS servers, IPv4/IPv6 addresses
ipconfig /release && ipconfig /renew
Release current DHCP lease then request a new one — resolves most DHCP failures
ipconfig /flushdns
Clear the local DNS resolver cache — removes stale or corrupt DNS entries
Exam Tip
169.254.x.x in ipconfig output = DHCP unreachable. The client cannot reach the internet or any routed resource. Fix by restoring DHCP connectivity — check NIC link, switch port, and DHCP server availability.

IPv6 & Dual-Stack
128-bit addressing, address types, and Windows dual-stack behavior.
Link-Local (fe80::/10)
Automatically configured on every IPv6-enabled interface without any server. Always starts with fe80::. Not routable — stays within the local segment only. Windows always has a link-local address. Used by neighbor discovery and routing protocols.
Global Unicast
Globally routable IPv6 addresses — the IPv6 equivalent of a public IPv4 address. Assigned by ISPs or DHCPv6. Typically starts with 2001: or 2600:. Used for internet-facing communication. Example: 2001:db8::1.
Unique Local (fc00::/7)
The IPv6 equivalent of RFC 1918 private addresses. Range: fc00:: to fdff::. Used internally, not routed on the public internet. Starts with fc or fd. Similar purpose to 10.x.x.x, 172.16.x.x, 192.168.x.x in IPv4.
Dual-Stack
Windows supports both IPv4 and IPv6 simultaneously on the same adapter by default. Both stacks operate independently. Windows prefers IPv6 when available. Disabling IPv6 entirely can break certain Windows features including some DirectAccess scenarios.
Exam Tip
Know the three IPv6 types cold: fe80:: = link-local (always auto-configured, never routable), Global Unicast = public routable, fc/fd:: = unique local (private). The exam tests whether you can classify an address by its prefix.
A client shows fe80::1c3a:5b2d in ipconfig but no 2001: address. This is normal — link-local is always present. It becomes a problem only if a global unicast address was expected and is missing, indicating a DHCPv6 or SLAAC configuration issue.

DHCP Four-Way Handshake
DORA: Discover → Offer → Request → Acknowledge.
Lease Renewal
At 50% of lease duration the client unicasts a Request to the original DHCP server to renew. At 87.5% it broadcasts to any server if the first renewal failed. If no server responds, the lease expires and APIPA activates. Use ipconfig /renew to force immediate renewal.
Relay Agents
DHCP Discovers are broadcasts — they do not cross routers. In enterprise networks, a DHCP relay agent (ip helper-address on a router interface) forwards the broadcast as a unicast to the DHCP server on another subnet, enabling one server to serve multiple VLANs.

Subnetting Fundamentals
CIDR notation, private address ranges, and the math behind subnet masks.
Why Subnet?
A flat /24 puts every device in the same broadcast domain. Subnetting isolates departments (Engineering, Guest, Printers), limits broadcast storms, and enforces security boundaries. Devices in different subnets must route through a gateway — they cannot communicate directly.
CIDR Notation
The /prefix number indicates how many bits are the network portion. /24 = 254 usable hosts. /25 = 126. /26 = 62. /27 = 30. /30 = 2 (point-to-point links only). Each additional bit halves hosts and doubles subnets.
RFC 1918 Private Ranges
10.0.0.0/8 — 16.7M addresses (large enterprise)
172.16.0.0/12 — 1M addresses (172.16–172.31)
192.168.0.0/16 — 65K addresses (small office/home)
These are never routed on the public internet — NAT translates them at the edge.

The Two Rules
Usable hosts = 2^(32 − prefix) − 2 (subtract network address and broadcast address). Wrong subnet mask is the most common misconfiguration — it causes devices to decide "local vs. remote" incorrectly, breaking communication silently.
Slide 7 of 18
Subnet Splitting — Visual Breakdown
Splitting 192.168.1.0/24 into /25 and /26 subnets.
Splitting Process
1. Decide how many subnets — round to power of 2. 2. Add bits to prefix (+1 = /25, +2 = /26). 3. Jump size = 256 / subnets. 4. Each subnet: network at start, first host = start+1, broadcast = next start−1, last host = broadcast−1.
Gateway Convention
Gateways use the first usable IP in each subnet by convention. For 192.168.1.128/25: gateway = 192.168.1.129. Network address (.128) and broadcast (.255) are reserved. Gateway devices do NOT set a default gateway — they ARE the gateway.

Name Resolution Order
How Windows translates hostnames to IP addresses — six steps in order.
1
Local DNS Cache — checked first; fastest. View with ipconfig /displaydns
2
Hosts File — C:\Windows\System32\drivers\etc\hosts. Overrides DNS unconditionally
3
DNS Server Query — sent to the configured DNS servers in adapter properties
4
NetBIOS Cache — local broadcast name cache from recent sessions
5
WINS Server — legacy; maps NetBIOS names to IPs for older environments
6
NetBIOS Broadcast — last resort; floods local segment. Modern networks disable this
Security: Hosts File Hijacking
The hosts file overrides DNS — malware and attackers modify it to redirect legitimate sites to malicious IPs. If google.com resolves to an unexpected IP, check the hosts file immediately. It requires admin rights to edit, but privilege escalation exploits can target it.
NetBIOS Modern Guidance
Modern Windows uses DNS for all name resolution. NetBIOS should be disabled where possible: adapter properties > IPv4 > Advanced > WINS > Disable NetBIOS over TCP/IP. Reduces attack surface (LLMNR and NBT-NS poisoning attacks).
A user reports that https://intranet.corp.com redirects to an unknown site. Other users are unaffected. Root cause: the hosts file on that one machine has a rogue entry overriding DNS. Check hosts first whenever a name resolution issue is isolated to one machine.

DNS Troubleshooting
Can ping by IP but not by name = DNS failure. Isolate with these commands.
nslookup google.com
Query the default DNS server — shows which server responded and the resolved IP address
nslookup google.com 8.8.8.8
Query a specific server — useful to test whether internal DNS is the problem vs. internet DNS
ipconfig /displaydns
Display all entries in the local DNS resolver cache including TTL values
ipconfig /flushdns
Clear the resolver cache — forces fresh DNS lookup on next name resolution attempt
Get-DnsClientCache
PowerShell equivalent — returns cache entries as objects with TTL, usable in scripts
Step 1: Isolate
Ping the target by IP address. If that works but ping by name fails, the problem is exclusively DNS. The NIC, gateway, and routing are all functioning correctly. Do not replace hardware or check cables.
Step 2: Identify
Run nslookup against the internal DNS server, then against 8.8.8.8. If internal DNS fails but 8.8.8.8 works: internal DNS server issue. If both fail: the adapter DNS settings are wrong or the DNS service is down network-wide.
Step 3: Fix
For stale cache: ipconfig /flushdns. For wrong DNS server: update adapter settings. For poisoned hosts file: remove the rogue entry. For DNS server outage: escalate or switch to a secondary DNS server (e.g., 8.8.8.8 as temporary alternate).
Slide 10 of 18
Network Diagnostic Commands
Beyond ping and ipconfig — locating where the network breaks.
tracert google.com
Show every router hop to destination. An asterisk (*) = timeout at that hop. Identifies WHERE connectivity breaks, not just IF.
tracert -d 192.168.1.1
Skip DNS lookups per hop (–d flag) — much faster when you only need hop IPs
netstat -an
All connections and listening ports in numeric format. LISTENING = open port, ESTABLISHED = active session
netstat -b
Show owning process per connection (admin required) — identifies which program holds a port
route print
Display full IP routing table. 0.0.0.0 row = default route. Wrong default gateway here = nothing reaches internet
route add 10.0.0.0 mask 255.0.0.0 192.168.1.1 -p
Add persistent static route (–p survives reboot) — directs 10.x traffic via specified gateway
arp -a
Show ARP cache mapping IPs to MACs. Two MACs claiming same IP = IP conflict on the segment
netsh wlan show profile name="Corp" key=clear
Show Wi-Fi profile including saved password in plaintext (admin required)
Layered Troubleshooting Order
ipconfig (have IP?) → ping 127.0.0.1 (TCP/IP stack up?) → ping [gateway] (local routing?) → ping 8.8.8.8 (internet reachable?) → ping google.com (DNS working?) → tracert (where exactly does it fail?). Work bottom-up before escalating.

Wireless Profiles & Mobile Features
Managing saved networks, hotspot, and WPA2-Enterprise deployment.
Wi-Fi Profiles
Saved via Settings > Network & Internet > Wi-Fi > Manage known networks. Export with: netsh wlan export profile name="SSID" folder=C:\path. Import with: netsh wlan add profile filename="path.xml". Used for mass deployment to corporate machines.
Mobile Hotspot
Settings > Network & Internet > Mobile hotspot. Shares the machine's internet connection (cellular, Ethernet, or Wi-Fi) via a new Wi-Fi access point. Useful for providing connectivity to other devices when only one wired connection is available.
Airplane Mode
Disables all wireless radios simultaneously: Wi-Fi, Bluetooth, and cellular. Individual radios can be selectively re-enabled after activating airplane mode. Quick access via Action Center or Settings > Network & Internet > Airplane mode.
WPA2-Enterprise Requirements
Requires a RADIUS/NPS server on the backend. Each user authenticates with their own domain credentials — no shared passphrase. Even if an employee is terminated and their credentials revoked, they immediately lose Wi-Fi access. Cannot be deployed without server infrastructure.
Exam Tip
WPA2-Personal uses a single shared passphrase for all users — rotating it requires reconfiguring every device. WPA2-Enterprise eliminates this by tying access to individual user accounts via 802.1X authentication and a RADIUS/NPS server. Know when each is appropriate.

VPN Protocol Comparison
PPTP, L2TP/IPsec, SSTP, IKEv2 — selecting the right one for the scenario.
PPTP
Port TCP 1723. Easy setup. MS-CHAPv2 — vulnerable to offline brute force. Avoid in production.
L2TP/IPsec
UDP 1701, 500, 4500. IPsec encrypts. Blocked by strict NAT. Needs PSK or cert. Solid when it works.
IKEv2
UDP 500, 4500. MOBIKE — reconnects seamlessly when changing networks. Best for mobile workers.
SSTP
TCP 443 (HTTPS). Passes through virtually every firewall. Windows-only. Best for restrictive networks.

Always On VPN & DirectAccess
Automatic always-connected enterprise VPN solutions — and why Always On VPN replaced DirectAccess.
DirectAccess (Legacy)
Windows Server feature providing automatic always-connected tunnels for domain-joined devices. No manual connection required — transparent to users. Requires: Windows Enterprise on clients, complex PKI infrastructure, IPv6, and Windows Server. Being deprecated in favor of Always On VPN. Still found in legacy enterprise environments.
Always On VPN (Current)
Microsoft's DirectAccess replacement. Uses IKEv2 or SSTP. Manages separate device tunnel (pre-login) and user tunnel (post-login). Works with domain-joined AND Azure AD-joined devices. Supports Windows 10/11 Pro and above. More flexible, no IPv6 dependency, modern deployment via Intune or SCCM.
Always On VPN: Two Tunnel Types
Device tunnel — activates before user login. Allows remote domain authentication, Group Policy application, and helpdesk RDP access to the lock screen. Configured in SYSTEM context. Requires IKEv2 with machine certificates.

User tunnel — activates after user logs in. Provides access to user-specific resources. Can use IKEv2 or SSTP. Configured in user context. Supports conditional access with Azure AD.
Exam Tip
Know the difference: DirectAccess = legacy, requires Enterprise edition, complex PKI + IPv6. Always On VPN = current, works on Pro+, Azure AD compatible, Intune-deployable. If the exam asks about seamless always-connected VPN for modern Azure hybrid environments, the answer is Always On VPN.
Scenario: A mobile sales team complains their VPN drops every time they move between Wi-Fi and cellular. Protocol recommendation: IKEv2 with MOBIKE — it maintains the VPN session across network transitions without manual reconnection.

Remote Desktop & WinRM
Graphical remote access and the command-line management protocol.
Remote Desktop Protocol (RDP)
Full graphical remote session. Port TCP 3389. Client: mstsc.exe. Host requirements: Windows Pro or above (Home cannot host RDP), Remote Desktop enabled in Settings > System > Remote Desktop, user in Remote Desktop Users group or Administrators. Supports multi-monitor, clipboard, drive, and audio redirection.
Windows Remote Management (WinRM)
Microsoft's WS-Management implementation. Enables PowerShell Remoting and remote management via CLI. Enable with: winrm quickconfig. HTTP port 5985, HTTPS port 5986. Required before any Invoke-Command or Enter-PSSession will work remotely.
mstsc.exe /v:server01
Open Remote Desktop connection to server01 directly from command line
winrm quickconfig
Enable WinRM: starts service, creates listener, opens firewall rule — run on target machine first
winrm get winrm/config
Display current WinRM configuration including allowed remote hosts
Critical Exam Fact
Remote Desktop HOST requires Windows Pro or higher. A Windows Home machine can CONNECT to another machine using mstsc.exe, but CANNOT receive incoming RDP connections. If the exam scenario requires a user to remote into their work PC, the work PC must be Pro or Enterprise.
Security Best Practice
Change the RDP port from 3389 (via registry) to reduce automated scanning exposure. Enable Network Level Authentication (NLA) — requires authentication before the session is established, preventing unauthenticated access to the login screen. Use VPN + RDP rather than exposing port 3389 to the internet.

PowerShell Remoting & RSAT
Managing multiple machines without leaving your desk.
PowerShell Remoting
Run commands on one or many remote machines simultaneously. Requires WinRM enabled on the target and appropriate firewall rules. Credentials must have rights on the remote machine. Works across domains with explicit credentials using -Credential parameter.
RSAT (Remote Server Administration Tools)
Optional Windows feature that installs server management tools (Active Directory Users and Computers, DNS Manager, DHCP, Group Policy Management Console) on a Windows 10/11 client. Install via: Settings > Apps > Optional Features > Add a feature > search RSAT.
Enter-PSSession -ComputerName server01
Start an interactive PowerShell session on server01 — prompt changes to [server01]
Invoke-Command -ComputerName server01 -ScriptBlock { Get-Service }
Run Get-Service on server01 and return results to local machine — non-interactive
Invoke-Command -ComputerName (Get-Content servers.txt) -ScriptBlock { Restart-Service spooler }
Restart the spooler service on every computer listed in servers.txt simultaneously
New-PSSession -ComputerName server01 -Credential (Get-Credential)
Create a reusable persistent session with explicit credentials — efficient for multiple commands
Quick Assist
Built-in Windows tool for screen-sharing remote support. No infrastructure required — works over the internet using a Microsoft account. Technician provides a 6-digit code; user enters it at quickassist.microsoft.com or via Start > Quick Assist. Ideal for supporting remote home users.
Exam Tip
RSAT installs server management GUIs on a CLIENT OS — it does NOT turn the client into a server. The tools connect remotely to actual servers. Quick Assist requires no infrastructure setup and uses Microsoft's relay service — it works even when the remote user is behind NAT with no open ports.
