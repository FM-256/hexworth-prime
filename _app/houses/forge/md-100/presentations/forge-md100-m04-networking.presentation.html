Configuring Networking on Windows Clients

IP connectivity, name resolution, wireless, VPN, and remote management

Why Networking Is Critical

A Windows client that cannot communicate is useless. Every enterprise service — Active Directory, file shares, email, cloud apps — depends on correctly configured networking. Network misconfiguration is one of the most common real-world IT issues and a heavily tested MD-100 domain.

Exam Relevance

MD-100 — Module 4

IP Network Connectivity

IPv4, IPv6, DHCP, static assignment, and the essential ipconfig commands

4⃣

IPv4 Configuration

Configure via: Settings > Network & Internet > adapter properties, or Control Panel > Network Connections. Static assignment requires: IP address, subnet mask, default gateway, preferred DNS server, alternate DNS server. APIPA range: 169.254.x.x — assigned automatically when DHCP fails. Indicates a DHCP problem.

IPv6 Configuration

128-bit addresses in hexadecimal (e.g., 2001:db8::1). Types: Link-local (fe80::/10 — auto-configured, not routable), Global Unicast (globally routable, similar to IPv4 public), Unique Local (fc00::/7 — similar to IPv4 private). Windows supports dual-stack (IPv4 + IPv6) by default.

DHCP vs. Static

DHCP: Server assigns IP automatically. Lease-based — expires and renews. Appropriate for end-user workstations. Static: Manually assigned, never changes. Required for servers, printers, and network infrastructure devices that other systems must reliably locate by IP.

ipconfig /all
Show all adapter details including MAC address, DHCP server, lease info, DNS servers
ipconfig /release && ipconfig /renew
Release current DHCP lease and request a new one — fixes most DHCP-related issues
ipconfig /flushdns
Clear the local DNS resolver cache — fixes stale DNS entries
ping 8.8.8.8 && ping google.com
Test IP connectivity (first), then DNS resolution (second) — isolates network vs. name resolution failures
Exam Tip

An IP address in the 169.254.0.0/16 range (APIPA) means the client could not reach a DHCP server and assigned itself an address. The machine can communicate with other APIPA machines on the same segment but cannot reach the internet or most network resources. The fix is to restore DHCP connectivity — check the NIC, switch port, and DHCP server.

Name Resolution

DNS, hosts file, NetBIOS — how Windows translates names to addresses

Windows Name Resolution Order

Windows checks these sources in order: (1) Local cache, (2) Hosts file (C:\Windows\System32\drivers\etc\hosts), (3) DNS server query, (4) NetBIOS cache, (5) WINS server, (6) NetBIOS broadcast. The hosts file always overrides DNS — a common source of misconfiguration and a malware attack vector.

DNS Troubleshooting

Can ping by IP but not by name = DNS problem. Steps: (1) ipconfig /displaydns — view cached entries. (2) ipconfig /flushdns — clear stale cache. (3) nslookup hostname — query the DNS server directly. (4) Check DNS server address in adapter settings. (5) Verify DNS server is reachable.

NetBIOS Name Resolution

Legacy name resolution using broadcasts. NetBIOS over TCP/IP (NetBT): Allows old Windows names to resolve on modern TCP/IP networks. WINS: NetBIOS name server (Windows Internet Name Service) — used in legacy environments. Modern Windows uses DNS for everything — NetBIOS should be disabled where possible for security.

nslookup google.com
Query default DNS server for google.com — shows which server responded and the resolved IP
nslookup google.com 8.8.8.8
Query a SPECIFIC DNS server (8.8.8.8) — useful to test if internal DNS is the problem vs. the internet
ipconfig /displaydns
Display all entries currently in the local DNS resolver cache
Get-DnsClientCache
PowerShell equivalent — shows DNS cache with TTL values

Hosts File Security Note

  • Hosts file overrides DNS — malware and attackers modify it to redirect legitimate sites to malicious IPs
  • Location: C:\Windows\System32\drivers\etc\hosts — requires admin rights to edit
  • If a known-good domain resolves to an unexpected IP, check the hosts file immediately
  • Default entry: 127.0.0.1 localhost — do not remove this

Wireless Networking

Wi-Fi security standards, profiles, and mobile connectivity

Security Standard Encryption Authentication Security Level
WEP RC4 (40/128-bit) Shared key Broken — never use
WPA (TKIP) TKIP (RC4-based) PSK or 802.1X Deprecated — weak
WPA2-Personal AES-CCMP (128-bit) Pre-shared key (passphrase) Good — still widely used
WPA2-Enterprise AES-CCMP (128-bit) 802.1X (RADIUS server) Strong — required for enterprise
WPA3-Personal AES-GCMP (192-bit) SAE (replaces PSK) Strongest personal — protects against brute force
WPA3-Enterprise AES-GCMP (192-bit) 802.1X + enhanced cryptography Highest security — gov/critical infra

Wireless Profiles and Mobile Features

  • Wi-Fi Profiles: Saved via Settings > Network & Internet > Wi-Fi > Manage known networks. Export with netsh wlan export profile name="SSID" folder=C:\path
  • Mobile Hotspot: Settings > Network & Internet > Mobile hotspot — shares cellular or Ethernet connection via Wi-Fi
  • Airplane Mode: Disables all wireless radios (Wi-Fi, Bluetooth, cellular). Individual radios can be re-enabled after airplane mode is on
  • WPA2-Enterprise requires a RADIUS/NPS server — no shared passphrase; each user authenticates with their own credentials

Remote Access & VPN

Connecting remote workers securely — protocol selection matters

PPTP
Point-to-Point Tunneling Protocol
Port: TCP 1723
Oldest VPN protocol. Easy to configure. Works through most firewalls. Uses MS-CHAPv2 for authentication — known to be vulnerable to offline brute-force attacks.
Security: Avoid — use only as last resort
L2TP/IPsec
Layer 2 Tunneling Protocol over IPsec
Port: UDP 1701, 500, 4500
L2TP provides the tunnel; IPsec provides encryption. Requires pre-shared key or certificate. Blocked by strict NAT/firewalls because it needs specific UDP ports. Solid security when working.
Security: Good — blocked by some firewalls
SSTP
Secure Socket Tunneling Protocol
Port: TCP 443 (HTTPS)
Tunnels VPN traffic over HTTPS. Passes through virtually all firewalls and web proxies — appears as normal web traffic. Microsoft-only protocol. Requires Windows Server with certificate. Excellent for restrictive environments.
Security: Strong — great firewall traversal
IKEv2
Internet Key Exchange v2 + IPsec
Port: UDP 500, 4500
Fastest reconnection of any VPN protocol — ideal for mobile workers who switch networks (MOBIKE protocol). Strong encryption. Supported on Windows, macOS, iOS, Android. Preferred for Always On VPN deployments.
Security: Strongest — recommended for most deployments
Always On VPN vs. DirectAccess

DirectAccess — Windows Server feature, automatic always-connected tunnel for domain-joined devices. Requires Enterprise edition on clients and complex PKI/IPv6 infrastructure. Being deprecated in favor of Always On VPN.

Always On VPN — Microsoft's replacement for DirectAccess. Uses IKEv2 (or SSTP). Manages individual tunnels per user and device. Works with both domain-joined and Azure AD-joined devices. More flexible deployment, works with Windows 10/11 Pro and above.

Remote Management

Managing Windows clients without sitting in front of them

Remote Desktop (RDP)

Full graphical remote session. Host requirements: Windows Pro or above, Remote Desktop enabled (Settings > System > Remote Desktop), user must be in Remote Desktop Users group (or Administrators). Client: mstsc.exe. Port: TCP 3389. Supports multiple monitors, clipboard sharing, drive redirection, and RemoteFX audio.

Windows Remote Management (WinRM)

Microsoft's implementation of the WS-Management protocol. Enables PowerShell Remoting and remote management via command line. Enable with: winrm quickconfig. Uses HTTP (port 5985) or HTTPS (port 5986). Required for PowerShell Remoting (Invoke-Command, Enter-PSSession).

PowerShell Remoting

Run PowerShell commands on one or many remote machines. Enter-PSSession -ComputerName server01 — interactive session. Invoke-Command -ComputerName server01 -ScriptBlock { Get-Service } — run commands remotely. Requires WinRM enabled on the target and appropriate firewall rules.

RSAT & Quick Assist

RSAT (Remote Server Administration Tools): Optional Windows feature — installs server management tools (ADUC, DNS Manager, DHCP, Group Policy) on a Windows 10/11 client. Install via: Settings > Apps > Optional Features. Quick Assist: Built-in tool for remote support via screen sharing. No infrastructure needed — works over internet with Microsoft account.

Exam Tip

Remote Desktop cannot be hosted on Windows Home. A Windows Home machine can connect TO another machine using the RDP client (mstsc.exe) but cannot receive incoming RDP connections. This is one of the key reasons businesses need Windows Pro. On the exam, if a scenario says "user needs to remote into their work PC from home," the work PC must be running Pro or Enterprise.

Summary

Module 4 consolidated — networking on Windows clients

IP Connectivity

APIPA (169.254.x.x) = DHCP failure. ipconfig /release, /renew, /flushdns are core commands. Static IP for servers and printers. DHCP for workstations. IPv6 link-local (fe80::) is always auto-configured, not routable.

Name Resolution

Resolution order: cache → hosts file → DNS. Hosts file overrides DNS — check it when names resolve to wrong IPs. nslookup hostname to test DNS. ipconfig /flushdns to clear stale cache. Can ping by IP but not name = DNS problem.

Wireless Security

WEP = broken, never use. WPA = deprecated. WPA2-Personal = AES, passphrase. WPA2-Enterprise = 802.1X, RADIUS, per-user credentials. WPA3 = strongest available. Enterprise wireless requires NPS/RADIUS server.

VPN & Remote Access

IKEv2 = best for mobile workers (MOBIKE). SSTP = best for restrictive firewalls (port 443). PPTP = avoid (weak). RDP requires Pro+. WinRM enables PowerShell Remoting. RSAT installs server admin tools on client OS.

Critical Exam Facts

  • APIPA range 169.254.0.0/16 = DHCP server unreachable — not a valid routable address
  • Hosts file takes precedence over DNS — check it first when names resolve incorrectly
  • WPA2-Enterprise requires a RADIUS/NPS server; WPA2-Personal uses a shared passphrase
  • IKEv2 supports MOBIKE — seamless reconnection when switching networks (ideal for mobile workers)
  • SSTP uses TCP 443 — passes through virtually any firewall (looks like HTTPS traffic)
  • Remote Desktop HOST requires Windows Pro or higher — Home can only be a client, not a host
  • winrm quickconfig enables PowerShell Remoting — required before using Invoke-Command remotely
