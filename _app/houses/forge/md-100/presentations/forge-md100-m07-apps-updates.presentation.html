Group Policy App Deployment

Deploys MSI packages via Active Directory GPO. Two assignment modes:

  • →Published — available in Add/Remove Programs, not installed automatically
  • →Assigned — installed automatically at logon or computer startup
  • →User-assigned apps follow the user; computer-assigned apps install on the machine

Sideloading

Installing UWP/AppX packages outside the Microsoft Store. Requires enabling sideloading in Settings → Update & Security → For Developers, or via Group Policy.

Common in enterprise for internally developed apps that have not been published to the Store. The device must trust the signing certificate used to sign the package.

EXAM TIP

GPO can only deploy MSI packages natively — not EXE or MSIX. For modern formats, use Microsoft Intune or Microsoft Endpoint Configuration Manager (MECM). Publishing vs. Assigning is a common exam distinction: published apps require the user to initiate installation.

UWP Apps

Universal Windows Platform architecture, app lifecycle, and AppLocker

UWP Architecture

Universal Windows Platform apps run in a sandboxed container with limited system access. Key characteristics:

  • →Sandboxed — cannot access arbitrary file system locations
  • →Permissions declared in app manifest
  • →Update via Microsoft Store automatically
  • →Installed per-user by default
  • →Can be provisioned to all users at OS deployment time

Microsoft Store for Business

Enterprise version of the Microsoft Store. Allows organizations to purchase apps in volume, distribute them to users without requiring a personal Microsoft account, and curate a private store of approved apps.

Integrates with Intune and Microsoft Endpoint Manager for deployment.

AppLocker

Group Policy-based application control. Administrators define rules about which applications users are allowed to run. More granular than Software Restriction Policies.

Rule types:

  • →Publisher — based on digital signature (most flexible)
  • →Path — based on file location (risky if path is writable)
  • →Hash — based on file hash (must update on each version)

Rule collections: Executable rules, Windows Installer rules, Script rules, DLL rules, Packaged app rules

APPLOCKER REQUIREMENTS

  • AppLocker requires the Application Identity (AppIDSvc) service to be running
  • Available on Windows 10 Enterprise and Education — not available on Home or Pro
  • Rules with no default allow rule block all unlisted apps for that collection
  • Always create default rules first to prevent locking out administrators

Microsoft Edge

Chromium-based Edge, profiles, IE mode, and enterprise policies

🌐

Chromium-Based Edge

Released January 2020, replacing the legacy EdgeHTML-based browser. Built on the same Blink rendering engine as Google Chrome. Provides better compatibility with modern web standards and improved extension support via Chrome Web Store.

👤

Profiles

Multiple user profiles within a single browser installation. Each profile maintains separate bookmarks, history, saved passwords, and extensions. Work accounts (Azure AD) and personal Microsoft accounts can both be used. Supports automatic sign-in with Azure AD in domain environments.

🔙

IE Mode

Renders specific sites using the Internet Explorer 11 engine inside an Edge tab. Critical for legacy intranet applications that require ActiveX controls or IE-specific rendering. Configured via an Enterprise Site List (XML file) deployed through Group Policy.

⚙️

Edge Policies via GPO

Edge supports over 500 Group Policy settings. Requires the Edge ADMX template files installed in the Group Policy Central Store. Settings include startup pages, password manager control, extension management, and security policies like certificate validation.

EXAM TIP

Internet Explorer 11 reached end of life on June 15, 2022. IE mode in Edge is the supported path forward for legacy applications. The Enterprise Site List is required to configure which sites open in IE mode — this cannot be configured per-user in the browser UI in managed environments.

Windows Servicing Model

Windows as a Service, feature vs. quality updates, and servicing channels

Windows as a Service (WaaS)

Microsoft's continuous delivery model introduced with Windows 10. Eliminates the traditional major-release cycle. Instead:

  • →Feature Updates — released annually (previously twice yearly). Major OS enhancements. Named by year and month (e.g., 22H2).
  • →Quality Updates — cumulative monthly patches. Security fixes, bug fixes. Released "Patch Tuesday" (second Tuesday of each month).
  • →Driver Updates — hardware driver updates via Windows Update.

Servicing Channels

Control when devices receive updates by placing them in the appropriate channel:

General Availability Channel (GAC)

Receives feature updates as they are released. Appropriate for most enterprise devices. Previously called Semi-Annual Channel.

Long-Term Servicing Channel (LTSC)

Fixed-feature releases with 5-year mainstream + 5-year extended support. No feature updates — security only. For specialized systems (medical, ATM, industrial control).

Windows Insider Program

Pre-release builds for testing. Dev, Beta, and Release Preview rings.

Pilot (Ring 1)
IT staff and power users. First to receive updates. Validates compatibility before broad deployment.
Broad (Ring 2)
Most devices in the organization. Receives updates after pilot validates. Delayed by 2–4 weeks.
Critical (Ring 3)
Mission-critical systems. Maximum deferral. Longest validation period before receiving updates.

Updating Windows

Windows Update, WSUS, Windows Update for Business, and Delivery Optimization

🔄

Windows Update

Direct update delivery from Microsoft's CDN. Default for consumer and small business. Settings → Windows Update controls active hours, pause settings, and update history. Delivery Optimization (DO) uses P2P sharing to reduce bandwidth — devices share update files with peers on the same network or across the internet.

🖥️

WSUS

Windows Server Update Services — on-premises update management. IT approves which updates are deployed before they reach client machines. Reduces internet bandwidth by caching updates on a local server. Requires Windows Server. Integrates with Active Directory GPO for client targeting.

☁️

Windows Update for Business

Cloud-based update management without a WSUS server. Updates still come from Microsoft CDN but administrators control deferral periods via Group Policy or Intune. Supports deferring feature updates up to 365 days and quality updates up to 30 days (Pro) or longer (Enterprise).

🔧

Update Troubleshooting

Common troubleshooting steps: run Windows Update troubleshooter, reset Windows Update components (net stop/start wuauserv bits), check C:\Windows\WindowsUpdate.log (post-Windows 10: use Get-WindowsUpdateLog), verify disk space (>10 GB free required for feature updates).

EXAM TIP

WSUS requires a Windows Server and is for organizations that need to approve each update before deployment. Windows Update for Business is the cloud-managed alternative — it controls timing but not approval. For fully managed enterprise deployments, Microsoft Endpoint Configuration Manager (MECM) is the gold standard.

Module 7 Summary

Manage Apps and Windows Updates — key takeaways

  • GPO Software Installation deploys MSI packages; it cannot deploy EXE or MSIX packages natively
  • Published apps require user initiation; Assigned apps install automatically at logon or startup
  • AppLocker requires the Application Identity service and is only available on Enterprise and Education editions
  • UWP apps are sandboxed, installed per-user, and updated via the Microsoft Store
  • IE mode in Edge uses the IE 11 engine — configured via Enterprise Site List XML deployed through GPO
  • Feature updates add new Windows capabilities; Quality updates are monthly cumulative security and bug fixes
  • General Availability Channel receives feature updates as released; LTSC is fixed-feature, security-only for specialized systems
  • WSUS provides on-premises update approval and caching; Windows Update for Business provides cloud-managed deferral
  • Delivery Optimization uses peer-to-peer sharing to reduce bandwidth for Windows Update downloads
  • Feature updates require at least 10 GB of free disk space to install successfully
EXAM FOCUS AREAS

Know the servicing channel names and their use cases. LTSC vs. GAC is a classic exam scenario. For app deployment, GPO = MSI only, and know Published vs. Assigned. AppLocker availability (Enterprise/Education only) is commonly tested.
