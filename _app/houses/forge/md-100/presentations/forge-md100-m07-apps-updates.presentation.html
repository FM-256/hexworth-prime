App Installation Formats
MSI, MSIX, AppX, and EXE — the four formats encountered in enterprise Windows deployments.
MSI (Windows Installer)
The legacy enterprise standard. Structured database of installation instructions, files, registry entries, and repair data. Supports Group Policy deployment, silent install flags (/quiet /norestart), and MST transform files for customization. Managed by the Windows Installer service (msiexec.exe). Widely supported by all deployment tools.
MSIX
Modern replacement for MSI and AppX. Containerized packaging with clean install/uninstall using a virtual file system. Supports modification packages (mod packages for enterprise customization). Requires Windows 10 1709+. Sideloading requires allowing Developer Mode or a trusted certificate. Recommended format for all new enterprise applications.
AppX (Universal Windows Platform)
Package format for UWP (Store) apps. Digitally signed. Sandboxed execution model with declared capabilities. Installed per-user or provisioned for all users. Managed via Add-AppxPackage and Remove-AppxPackage PowerShell cmdlets. AppXBundle is a multi-architecture package container.
EXE (Setup Executables)
Traditional Win32 installer. Most flexible but no structured deployment standard. Many EXEs wrap an MSI internally. Common silent install flags: /S, /silent, /quiet, /norestart. Check vendor documentation for specific parameters. Not natively deployable via GPO without extra tooling.
Deployment Recommendation
MSI for legacy enterprise apps deployed via GPO or SCCM. MSIX for modern apps. Use Intune for cloud-managed deployments supporting both MSI (line-of-business) and MSIX/AppX packages.

App Installation Flow
Decision path from package format to deployment method to installed state.
msiexec.exe Silent Install
msiexec /i app.msi /quiet /norestart /l*v install.log — silent install with verbose log. /x {GUID} removes by product code. GPO can deploy MSI to Computer or User configuration for machine-wide or per-user installation.
MSIX Sideloading
Enterprise MSIX packages must be signed by a certificate trusted by the client. Enable sideloading via Settings → Developer Mode, or via GPO: Allow all trusted apps to install (AllowAllTrustedApps). Then: Add-AppxPackage -Path .\app.msix.
winget
Windows Package Manager (Windows 10 1809+). winget install VLC, winget upgrade --all. Installs from the Microsoft Store and GitHub-hosted packages. Scriptable for provisioning. Not a full enterprise deployment solution but useful for individual machines.

Microsoft Store and Provisioned Apps
Managing built-in UWP apps and the Microsoft Store in enterprise environments.
Provisioned vs. Installed AppX
Provisioned: Staged in the image and installed for new users on first login. Stored in C:\Program Files\WindowsApps and C:\ProgramData\Microsoft\Windows\AppRepository. Per-user installed: In user profile AppData. Provisioned apps are managed per-machine; installed apps are per-user.
Remove Built-in Apps
Remove for one user: Get-AppxPackage *XboxApp* | Remove-AppxPackage
Remove for all existing users + new users: Get-AppxPackage -AllUsers *XboxApp* | Remove-AppxPackage -AllUsers
Remove provisioned package: Get-AppxProvisionedPackage -Online | Where-Object {$_.PackageName -like "*Xbox*"} | Remove-AppxProvisionedPackage -Online
Disable Store via GPO
Computer Configuration → Administrative Templates → Windows Components → Store → Turn off the Store application. Prevents users from installing apps from the public store. Does not affect side-loaded or enterprise MSIX packages.
Windows 11 Store Change
Windows 11 Store supports Win32 apps in addition to UWP. This allows IT to distribute traditional Win32 applications through the Store infrastructure with centralized management, reducing dependence on legacy deployment tools for simple single-application deployments.

Windows Update Overview
Update types, release channels, and the servicing model for Windows 10.
Quality Updates (Cumulative)
Monthly security and bug fixes. Released on Patch Tuesday (second Tuesday of each month). Cumulative: each update includes all previous monthly patches. A single monthly cumulative update brings a machine fully current from any prior state. No need to chain earlier updates.
Feature Updates (Semi-Annual)
New OS versions released approximately twice per year (Spring H1, Fall H2). Major version updates: 21H2, 22H2, 23H2. Each introduces new features, UI changes, and deprecations. Require more testing than quality updates. Can be deferred via update policy for up to 365 days.
Driver Updates
Hardware driver updates distributed through Windows Update. Can be managed separately from OS updates. Some organizations block driver updates via policy to maintain approved driver baselines. Settings → Windows Update → Advanced Options → Receive updates for other Microsoft products.

Windows Update Deployment Rings
Staged rollout strategy to validate updates before broad production deployment.
Configure Rings via Intune
Intune → Devices → Windows 10 Update Rings. Create a ring policy, set quality update deferral period, feature update deferral, and assign to device groups. Each ring is a separate policy assigned to a different Azure AD group.
Configure Rings via GPO
Computer Configuration → Administrative Templates → Windows Components → Windows Update → Windows Update for Business. Set "Select when Quality Updates are received" and "Select when Feature Updates are received" with target version and deferral days.

WSUS Architecture
Windows Server Update Services — on-premises update server for enterprise environments.
GPO Client Configuration
Computer Configuration → Admin Templates → Windows Components → Windows Update → "Specify intranet Microsoft update service location." Set both the update service URL and statistics URL to http://wsusserver:8530. Port 8530 (HTTP) or 8531 (HTTPS).
Approval Workflow
Updates arrive as "Not Approved." Admin reviews and approves per group. Test group approvals test compatibility. Production approval follows after test sign-off. Declined updates are not distributed to any group. Emergency security updates can be approved immediately to all groups.
Downstream WSUS
Hierarchical deployment: upstream WSUS syncs from Microsoft, downstream WSUS servers replicate from upstream. Useful for branch offices with limited WAN bandwidth. Downstream servers can be autonomous (own approvals) or replica (inherits upstream approvals).
Slide 8 of 19
Windows Update for Business
Cloud-based update management without an on-premises WSUS infrastructure.
What it Provides
Direct connection to Microsoft Update with policy-controlled deferrals. No server infrastructure required. Managed via GPO, MDM (Intune), or Settings. Supports quality and feature update deferral, maintenance windows, and active hours configuration. Ideal for cloud-managed environments.
Active Hours
Prevent Windows from restarting during working hours. Default: 8 AM to 5 PM. Configurable to up to 18 hours. Set via Settings → Windows Update → Advanced Options → Active Hours, or GPO: "Turn off auto-restart for updates during active hours." Restart will occur outside defined active hours.
Delivery Optimization (DO)
Peer-to-peer update distribution. Windows 10 clients on the same network share downloaded update content. Reduces WAN bandwidth consumption. Modes: LAN only (preferred for enterprise), Internet + LAN, Group (by AD/AAD group). Configure via Settings or MDM policy.
WUfB vs WSUS
WSUS gives granular control over which specific updates are approved and distributed, requiring on-premises infrastructure. WUfB provides deferral-based management using cloud connectivity — no server required. For hybrid or cloud-native environments, WUfB via Intune is the recommended path. WSUS remains relevant for large on-premises fleets with bandwidth constraints.

Application Compatibility Flowchart
Diagnosing and resolving application compatibility issues on Windows 10.
Compatibility Tab Options
Right-click EXE → Properties → Compatibility. Available modes: Windows 95, 98/ME, XP (SP2/SP3), Vista, 7, 8. Additional options: Run in 256 colors, 640x480 resolution, disable fullscreen optimizations, run as administrator. These apply shims via the Application Compatibility Infrastructure (ACI).
Application Compatibility Toolkit (ACT)
Microsoft tool for enterprise-scale compatibility assessment before OS upgrades. Inventory installed apps, test against target OS, flag known incompatibilities, create custom shims. Included with Windows ADK. Essential for organizations migrating from Windows 7/8 to 10/11.
Compatibility Shims
Small code patches applied at runtime to modify how an application interacts with the OS. Examples: redirect file writes from System32 to AppData, lie about OS version number, inject missing API functions. Applied transparently without modifying the application binary.

Managing Apps via PowerShell
PowerShell and winget commands for application management in enterprise deployments.
# Query installed Win32 apps
Get-Package
Get-Package -Name "Visual Studio Code"

# Query AppX packages for current user
Get-AppxPackage
Get-AppxPackage -AllUsers | Select Name, PackageFullName

# Remove a provisioned app (all new users)
Get-AppxProvisionedPackage -Online |
Where {$_.PackageName -like "*BingWeather*"} |
Remove-AppxProvisionedPackage -Online

# Install MSIX/AppX
Add-AppxPackage -Path "C:\Packages\app.msix"

# winget bulk upgrade
winget upgrade --all --silent
Get-Package vs Get-AppxPackage
Get-Package queries the Windows Installer database — traditional Win32 and MSI apps. Get-AppxPackage queries the AppX manifest store — UWP and MSIX apps. Both are needed for a complete application inventory.
Automation Use Cases
Generate software compliance reports. Remove bloatware from OEM images during provisioning. Deploy enterprise line-of-business MSIX packages post-imaging. Audit versions against known-vulnerable package lists.

Optional Features and Windows Capabilities
Adding and removing Windows OS components without a full reinstall.
Windows Features
Legacy feature management: Control Panel → Programs and Features → Turn Windows features on or off. Examples: Hyper-V, IIS, .NET Framework 3.5, Windows Subsystem for Linux, Telnet Client. Or via DISM: DISM /Online /Enable-Feature /FeatureName:Hyper-V /All.
Optional Features (Modern)
Settings → Apps → Optional Features. Add features: OpenSSH Server/Client, RSAT Tools, Windows Media Player, WordPad, Notepad. Add via PowerShell: Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0. Downloaded from Windows Update on demand.
RSAT (Remote Server Admin Tools)
Manage Active Directory, DHCP, DNS, and other server roles from a Windows 10/11 client. Install via Optional Features or: Get-WindowsCapability -Online | Where Name -like 'Rsat*' | Add-WindowsCapability -Online. Requires access to Windows Update or WSUS for download.
# List available optional features
Get-WindowsOptionalFeature -Online

# Enable Hyper-V
Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V -All

# List and install capabilities
Get-WindowsCapability -Online | Where State -eq "NotPresent" | Where Name -like "Rsat*"
Add-WindowsCapability -Online -Name Rsat.ActiveDirectory.DS-LDS.Tools~~~~0.0.1.0

App Deployment via Group Policy
Software installation policies using MSI packages and Group Policy Objects.
Published vs. Assigned
Published (User Config): App appears in Add/Remove Programs; user installs on demand. Available for user-targeted deployments. Assigned (User or Computer Config): App installs automatically. Advertised on desktop; installs on first launch. Computer assignment installs for all users of that machine.
GPO Path
User/Computer Configuration → Software Settings → Software Installation. Add new package (must be MSI). Source must be a UNC path accessible by all target machines. The distribution share must have Everyone: Read permission so the computer account can download the MSI during machine startup (for Computer assignments).
MST Transform Files
Customize MSI installations without modifying the original package. Examples: pre-configure settings, suppress reboot, set install directory. Apply via GPO by adding the transform to the MSI deployment package properties. Created with the Microsoft Orca tool or third-party repackaging tools.
Targeting
Computer assignments target the OU containing computer objects. User assignments target the OU containing user objects. WMI filters and GPO Security Filtering further narrow which computers or users receive the deployment. Test with a small pilot OU before production deployment.
GPO Software Limitations
Only MSI packages natively. No EXE or MSIX without wrapping. Deployment is slow (requires computer/user login cycle). No bandwidth throttling. No deployment status reporting. For modern deployments, Intune or SCCM/Endpoint Manager provides superior control and reporting.

Intune App Deployment
Cloud-based app lifecycle management for modern Windows 10 environments.
App Types in Intune
Line-of-business (LOB) MSI/MSIX uploads. Windows app (Win32) using .intunewin wrapper. Microsoft Store apps. Web apps (browser shortcuts). Microsoft 365 Apps (click-to-run). Each type has a deployment category: Required, Available for enrolled devices, Uninstall.
Win32 App Wrapping
The Microsoft Win32 Content Prep Tool converts an EXE or MSI installer into a .intunewin file. Upload to Intune with install/uninstall command lines, detection rules (registry key, file, MSI product code), and return codes. Supports complex application packages that GPO MSI deployment cannot handle.
Required vs. Available
Required: Pushed to assigned devices/users automatically. No user interaction needed (or possible). Use for compliance applications. Available: Appears in Company Portal for user self-service installation. User initiates install when needed. Use for optional productivity tools.
Migration scenario: IT needs to deploy a legacy EXE across 500 machines without GPO. Solution: wrap with IntuneWinAppUtil.exe to create a .intunewin file, upload to Intune as Win32 app, set install command (setup.exe /silent), detection rule (check for HKLM registry key set by installer), assign as Required to All Devices group. Intune agent handles download and silent install during next policy sync.

App Lifecycle Management
Deployment, update, and retirement of enterprise applications.
Software Inventory
Know what is installed before managing it. Tools: SCCM Hardware/Software Inventory, Intune App Inventory, PowerShell Get-Package and Get-AppxPackage queries, WSUS compliance reports, Azure Log Analytics. Accurate inventory is prerequisite to patch compliance tracking.
Supersedence and Replacement
When a new version of an application replaces an old one, configure supersedence in SCCM/Intune to uninstall the old version as part of the new installation deployment. Prevents version accumulation where multiple versions of the same app consume disk space and create security exposure.
Application Retirement
End-of-life apps should be actively removed, not just abandoned. Remove GPO deployment links. Set Intune assignment to "Uninstall." Use SCCM deployment type set to uninstall. Remove from software catalog. Document the retirement in change management. Running obsolete apps creates vulnerability surface area.
App Version Pinning
Some enterprise applications require a specific version for regulatory compliance or dependency reasons. Pin via Intune Win32 detection rules tied to exact version strings. Document the business reason. Establish a review cycle to evaluate whether the version lock can be lifted after vendor qualification updates.

Exam Scenarios
Six app and update situations tested on MD-100.
Q1
A legacy app designed for Windows 7 crashes on Windows 10. The first troubleshooting step? — Right-click the EXE → Properties → Compatibility tab → Run in Windows 7 compatibility mode.
Q2
IT needs to prevent Windows 10 clients from receiving feature updates for 60 days. How? — Configure Windows Update for Business GPO: "Select when Feature Updates are received" with a 60-day deferral. Or use an Intune Update Ring with FeatureUpdatesDeferralPeriodInDays=60.
Q3
WSUS clients show "No updates available" but Microsoft's site shows new patches. Cause? — The patches have not been approved in WSUS for those computer groups. Log into WSUS console and approve the updates for the affected group.
Q4
A user receives Windows Update error 0x800F0922. What should be checked first? — Disk space. 0x800F0922 commonly occurs when insufficient disk space is available for the feature update staging area. Requires at least 10 GB free.
Q5
An EXE installer needs to deploy silently via GPO. What is required? — EXE files cannot be deployed directly via GPO Software Installation (MSI only). Wrap the EXE in an MSI using a repackaging tool, or use Intune Win32 app deployment instead.
Q6
A new MSIX app fails to install with "Certificate not trusted." Fix? — The signing certificate of the MSIX is not in the Trusted Root or Trusted Publishers store. Add the certificate via GPO Certificate Management or enable Developer Mode if in a test environment.

Module 7 Summary
Eight key takeaways for the MD-100 apps and updates domain.
1
MSI is the legacy enterprise standard for GPO deployment. MSIX is the modern replacement with containerized clean install/uninstall. AppX is the UWP format managed via Add-AppxPackage.
2
Quality updates are monthly cumulative patches. Feature updates are semi-annual OS versions. Both can be deferred via Windows Update for Business (cloud) or WSUS (on-premises).
3
Update rings provide staged rollout: Ring 0 (IT/Preview) receives immediately, Ring 1 (Pilot) defers 7–14 days, Ring 2 (Broad) defers 21–30 days. This validates compatibility before broad deployment.
4
WSUS requires explicit approval before distributing updates to client groups. "No updates available" typically means not approved, not that no updates exist.
5
GPO Software Installation supports MSI only. EXE installers require repackaging or Intune Win32 app wrapping (.intunewin format) for automated enterprise deployment.
6
Application compatibility troubleshooting order: (1) Run as Admin. (2) Compatibility tab (OS version mode). (3) Compatibility Troubleshooter. (4) Hyper-V VM or app replacement.
7
MSIX sideloading requires the signing certificate to be trusted on the client machine. Developer Mode enables broad trust for testing; enterprise deployments use a trusted code-signing certificate.
8
Delivery Optimization uses P2P content sharing between LAN clients to reduce bandwidth for Windows Update, Store app, and MSIX downloads. Configure mode via MDM or GPO.
