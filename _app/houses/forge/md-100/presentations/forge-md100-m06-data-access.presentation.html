Windows File Systems

NTFS features, ReFS overview, and FAT comparison

NTFS — New Technology File System

The standard Windows file system for all internal drives. Rich feature set that no alternative matches:

  • →Access Control Lists (ACLs) — granular user/group permissions
  • →EFS — Encrypting File System (user-level encryption)
  • →Compression — transparent file/folder compression
  • →Disk Quotas — per-user storage limits
  • →Volume Shadow Copy — previous versions snapshots
  • →Journaling — transaction log for crash recovery
  • →Alternate Data Streams — metadata attached to files

ReFS — Resilient File System

Designed for large-scale storage and data integrity. Used with Storage Spaces on Windows 10 Pro for Workstations and Server environments.

  • →Integrity checksums on metadata and data
  • →Automatic corruption detection and repair
  • →No CHKDSK needed — self-healing
  • →Does NOT support EFS or disk quotas

FAT32 and exFAT

FAT32 — Legacy. Maximum 4 GB file size. Used for boot media and legacy compatibility. Cannot store NTFS permissions.

exFAT — Extended FAT for removable media. No file size limit, no permissions model. Best for USB drives shared between Windows and macOS.

EXAM TIP

NTFS is the only file system that supports ACL-based permissions, EFS encryption, compression, and disk quotas. Any question about file-level security on a Windows volume implies NTFS.

INHERITANCE RULES

  • Child objects inherit permissions from parent by default
  • Explicit permissions override inherited permissions
  • Deny always overrides Allow at the same level
  • Break inheritance to set unique permissions on a subfolder
  • Effective permissions = union of all Allow groups minus any Deny

icacls Command

Command-line tool for viewing and modifying NTFS ACLs:

# View permissions
icacls "C:\Data"

# Grant Modify to a user
icacls "C:\Data" /grant jsmith:(M)

# Deny Write
icacls "C:\Data" /deny jsmith:(W)
EXAM TIP

When a user belongs to multiple groups with different NTFS permissions, the effective permission is the cumulative union of all Allow permissions — EXCEPT when any group has an explicit Deny, which overrides Allow. This is the most commonly tested permissions scenario.

Shared Folders

Creating shares, share vs. NTFS permissions, admin shares, and net share

Share Permissions vs. NTFS Permissions

When a resource is accessed over the network, both share and NTFS permissions apply. The effective access is the most restrictive of the two.

Example:

Share permission: Full Control

NTFS permission: Read

Effective access over network: Read

NTFS always wins when it is the more restrictive. Local access ignores share permissions entirely.

Administrative Shares

Hidden shares created automatically by Windows. Accessible only to administrators. The dollar sign suffix hides them from network browsing.

  • →C$, D$ — root of each local drive
  • →ADMIN$ — Windows installation directory
  • →IPC$ — inter-process communication pipe
  • →PRINT$ — printer driver files

Creating and Managing Shares

Three methods to create a shared folder:

1. File Explorer

Right-click folder → Properties → Sharing tab → Advanced Sharing

2. Computer Management

compmgmt.msc → Shared Folders → Shares → New Share wizard

3. net share command

# Create a share
net share Data=C:\Data /grant:Everyone,Read

# View all shares
net share

# Remove a share
net share Data /delete

Mapping Network Drives

Assign a drive letter to a network share for persistent access. Use Group Policy Preferences to deploy mapped drives to users automatically at logon.

net use Z: \\server\Data /persistent:yes

Managing User Files

OneDrive, Known Folder Move, Work Folders, and Offline Files

OneDrive Sync

Synchronizes files between the local device and cloud storage. Files On-Demand shows cloud files without downloading — they appear in Explorer but are only fetched when opened. Always Available files are fully cached locally.

Known Folder Move (KFM)

Redirects Desktop, Documents, and Pictures folders into OneDrive automatically. Deployed via Group Policy or Intune. Ensures user data is backed up to cloud without user action. Critical for endpoint protection in Microsoft 365 environments.

Work Folders

On-premises alternative to OneDrive for Business. Syncs a defined server folder to user devices. Does not require a cloud subscription. Accessible on domain and non-domain joined devices. Set up via Work Folders server role.

Offline Files

Caches network shared folders locally so users can work without network connectivity. Configured via Sync Center. Changes sync back to the server when reconnected. Ideal for mobile workers who use mapped drives.

FOLDER REDIRECTION vs. OFFLINE FILES

  • Folder Redirection — moves user profile folders (Documents, Desktop) to a network location. Managed via Group Policy.
  • Offline Files — caches those redirected folders locally so the user can work disconnected.
  • These two technologies are typically used together in traditional domain environments.
  • In modern deployments, KFM + OneDrive replaces both for cloud-joined devices.

File Access Best Practices

Least privilege, permission auditing, EFS, and access-based enumeration

Principle of Least Privilege

Grant users only the minimum permissions they need to perform their job. Never grant Full Control unless the user needs to change permissions or take ownership. Assign permissions to groups, not individuals — manage group membership, not per-user ACLs.

Permission Auditing

Enable object access auditing via Group Policy (Security Settings → Advanced Audit Policy). Configure audit entries on the folder's security tab to log successful and failed access attempts. View results in Event Viewer → Security log (Event ID 4663 = object access).

EFS — Encrypting File System

NTFS-level user encryption. Files are encrypted with a user certificate — only that user (and designated recovery agents) can open them. Transparent to the user once enabled. Right-click → Properties → Advanced → Encrypt contents. Does not protect against logged-in user attacks.

Access-Based Enumeration (ABE)

When enabled on a shared folder, users only see files and subfolders they have permission to access. Prevents information leakage — a user cannot see the names of files or folders they cannot open. Enable in Share properties → Advanced Sharing → Caching or via Computer Management.

Real-World Scenario

A department shares a server folder. HR staff should not know which other folders exist on the same share (e.g., Payroll, Executives). The correct solution is to enable Access-Based Enumeration on the shared folder combined with strict NTFS permissions. HR will see only the folders their accounts have at least Read permission on — the rest are invisible.

Module 6 Summary

Configure Data Access and Usage — key takeaways

  • NTFS is the only Windows file system supporting ACLs, EFS, compression, quotas, and Volume Shadow Copy
  • NTFS permission levels in order: Read → Read & Execute → Write → Modify → Full Control
  • Deny permissions override Allow at the same level; explicit permissions override inherited permissions
  • Effective permissions are the union of all group Allow permissions minus any Deny
  • Over the network, effective access is the most restrictive of Share and NTFS permissions combined
  • Local access ignores share permissions entirely — only NTFS applies
  • Administrative shares (C$, ADMIN$, IPC$) are hidden, auto-created, and admin-only
  • Known Folder Move redirects Desktop, Documents, and Pictures to OneDrive — essential for cloud-first environments
  • Folder Redirection + Offline Files is the traditional domain equivalent of KFM + OneDrive
  • Access-Based Enumeration prevents users from seeing file and folder names they cannot access
EXAM FOCUS AREAS

Share vs. NTFS permissions interaction is tested heavily. Know the rule: most restrictive wins when accessed over the network; NTFS only when accessed locally. Also know that Deny overrides Allow but only at the same level — inherited Allow is overridden by explicit Deny.
