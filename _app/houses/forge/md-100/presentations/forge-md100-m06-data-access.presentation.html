File System Comparison
NTFS vs. FAT32 vs. exFAT — feature capabilities side by side.
Exam Rule
EFS (Encrypting File System) is an NTFS-only feature. A file cannot be both NTFS-compressed and EFS-encrypted simultaneously. Moving an NTFS encrypted file to FAT32 removes the encryption because FAT32 has no ACL or encryption infrastructure.
Slide 3 of 19
NTFS Permissions
File and folder permissions enforced by the kernel regardless of access method.
Full Control
Read, write, execute, delete, change permissions, and take ownership. Supersedes all other permission levels. Grants ability to modify the ACL itself. Assign only to resource owners and administrators.
Modify
Read, write, execute, and delete files and subfolders. Cannot change permissions or take ownership. Most common permission for collaborative work folders. Prevents accidental ACL modification by regular users.
Read & Execute
View and run files. Cannot modify or delete. Traverse folder permission is implied. Appropriate for application directories where users need to run programs but not modify installation files.
Read
View file contents and folder structure. Cannot execute programs or modify files. Appropriate for read-only data shares such as reference documents or templates.
Write
Create new files and subfolders, and modify existing files. Cannot read existing contents. Unusual permission combination — typically paired with Read for a useful access level.
Special / Advanced
Granular individual permissions: traverse folder, list folder, read attributes, write attributes, delete subfolders, delete, read permissions, change permissions, take ownership. Access via Advanced button in Security tab.
Inheritance
NTFS permissions are inherited from parent folder by default. Explicitly assigned permissions at a lower level take precedence over inherited permissions. To break inheritance: Properties → Security → Advanced → Disable inheritance.
Slide 4 of 19
Share Permissions
Network-only access control — three levels, applied at the share entry point.
Read (Share)
View file names and attributes, read file contents, run programs. Cannot create, modify, or delete files. Applied at the share boundary — all network access starts with this check before NTFS permissions are evaluated.
Change (Share)
All Read permissions plus: create files and subfolders, change file contents, delete files and subfolders. Roughly equivalent to NTFS Modify in scope but has no effect on local (non-network) access.
Full Control (Share)
All Change permissions plus: change permissions (on FAT volumes where share permissions are the only ACL). On NTFS volumes, share Full Control does not grant ability to change NTFS ACLs — NTFS Full Control is required for that.
Share Permissions Only Apply Over the Network
If a user logs on locally (Console session, RDP with local access, or physical keyboard), share permissions do NOT apply. Only NTFS permissions control local file access. This is the most important distinction between the two permission types.
Common Best Practice
Grant Everyone: Full Control at the share level, then apply all granular access control through NTFS permissions. This simplifies administration by keeping all meaningful ACL work in one place (NTFS), while share permissions act only as a coarse gate.
Slide 5 of 19
Most Restrictive Wins Rule
When share and NTFS permissions combine, the effective permission is always the most restrictive of the two.
Example Calculation
Share permission: Full Control. NTFS permission: Read. Effective: Read. The more restrictive NTFS permission wins.

Share permission: Read. NTFS permission: Full Control. Effective: Read. The more restrictive share permission wins.
Deny is Absolute
An explicit Deny entry overrides all Allow entries. If a user is a member of two groups — one with Allow Read and one with Deny Read — the Deny takes effect. Deny is evaluated first in every permission check. Use sparingly.
Slide 6 of 19
Managing NTFS Permissions
GUI and command-line tools for assigning and auditing NTFS ACLs.
File Explorer (GUI)
Right-click file or folder → Properties → Security tab. Shows principal (user or group) and their Allow/Deny entries. Click Edit to add or remove entries. Advanced button exposes ownership, inheritance, and auditing settings.
icacls (Command Line)
icacls C:\Data — display permissions. icacls C:\Data /grant "Domain Users":(OI)(CI)R — grant recursive read. icacls C:\Data /deny UserA:W — deny write. icacls C:\Data /reset — reset to inherited. Supports scripting and bulk operations.
takeown / whoami
takeown /f C:\file.txt — take ownership of a locked file. whoami /groups — show group membership and SIDs. Use when a user cannot access a file they should own, or to diagnose inherited group permission issues.
# View current ACL
icacls "C:\Data\Reports"

# Grant Marketing group modify on folder and all children (OI=object inherit, CI=container inherit)
icacls "C:\Data\Reports" /grant "Marketing":(OI)(CI)M

# Remove a group from the ACL
icacls "C:\Data\Reports" /remove "Marketing"

# Reset ACL to only inherited permissions
icacls "C:\Data\Reports" /reset /T

Creating and Managing Shares
Making folders accessible over the network with proper share-level access controls.
Share Methods
File Explorer: Right-click folder → Properties → Sharing tab → Advanced Sharing.
Computer Management: Shared Folders → Shares → New Share.
Command line: net share Data=C:\Data /grant:Domain Users,Read
PowerShell: New-SmbShare -Name Data -Path C:\Data
Administrative Shares
Windows creates hidden administrative shares by default: C$ (C: drive root), ADMIN$ (Windows folder), IPC$ (inter-process communication). Accessible only to members of Administrators. Trailing $ hides share from browse lists. Cannot be permanently removed without registry change.
UNC Path
Universal Naming Convention: \\ServerName\ShareName\subfolder\file.txt. Used in Explorer address bar, net use commands, and GPO scripts. IP addresses also work: \\192.168.1.10\Data.
net use (Map Drive)
net use Z: \\Server\Data /persistent:yes — maps a drive letter persistently. net use Z: /delete — disconnects. net use alone lists all current connections. Persistent mapping survives reboot for the current user.
SMB Versions
SMB 1.0 is disabled by default on Windows 10/11 (security vulnerability). SMB 2.x and 3.x are used for all modern Windows file sharing. SMB 3.1.1 supports end-to-end encryption. Check via Get-SmbServerConfiguration.
Slide 8 of 19
EFS Encryption Flow
Encrypting File System — per-user transparent encryption for NTFS files.
Enable EFS
File Properties → General → Advanced → Encrypt contents. Or: cipher /e /s:C:\ConfidentialFolder. First encryption creates a self-signed certificate and private key stored in the user profile.
EFS Risks
EFS is user-bound. Rebuild the machine without exporting the certificate and the files are permanently unrecoverable. Always export the EFS certificate: certmgr.msc → Personal → Certificates → Export with private key.
Data Recovery Agent
Domain administrator is automatically a DRA in AD environments. The FEK is also encrypted with the DRA public key (stored in the file's Data Recovery Field). Allows admins to decrypt EFS files when user private key is lost.
Slide 9 of 19
Folder Redirection
Transparently move user profile folders to a network share for centralized management.
Which Folders Can Be Redirected
AppData (Roaming), Desktop, Start Menu, Documents, Pictures, Music, Videos, Favorites, Contacts, Downloads. Configure each folder independently in the GPO under User Configuration → Windows Settings → Folder Redirection.
Offline Files
Caches redirected folder contents locally so users can work without network connectivity. Sync occurs on reconnect. Enable via: Computer Configuration → Administrative Templates → Network → Offline Files. Configured per-machine, not per-user.
Redirection vs. Roaming Profiles
Folder Redirection moves specific folders to the server, leaving the rest of the profile local. Roaming Profiles copy the entire user profile to a network share. Best practice: combine both — redirect key folders, use roaming profiles for settings synchronization.
Slide 10 of 19
Effective Permissions Tool
Calculating what a user can actually do after all permissions are combined.
GUI Tool: Advanced Security
File or folder Properties → Security tab → Advanced → Effective Access tab. Enter a user or group name and click View effective access. Shows the final computed permissions considering group memberships, inheritance, and explicit entries. Does not account for share permissions in the local view.
Permission Calculation Rules
1. Permissions accumulate across all group memberships (union).
2. Explicit permissions override inherited permissions.
3. Deny overrides Allow at the same inheritance level.
4. When combining share and NTFS: take the more restrictive.
5. Creator/Owner gets special inherited permissions.
User Jane is in both Sales (Read) and Managers (Modify) groups on the Reports folder. NTFS effective: Modify (permissions accumulate). The share grants Sales: Read. Combined effective permission over the network: Read (most restrictive of Modify NTFS and Read share). Locally: Modify. This split is a common exam trap.
Creator/Owner
The user who creates a file or folder has Full Control of that object by default (as Creator Owner special identity). This implicit permission is not always visible in the standard ACL view but appears in the Advanced Security settings.
Take Ownership
Administrators can take ownership of any file or folder regardless of ACL settings. Ownership change does not require existing permissions. Command: takeown /f C:\path /r /d y. After taking ownership, assign permissions explicitly to restore intended access.
Access-Based Enumeration
ABE hides files and folders from users who do not have at least Read permission. Enabled per-share on Windows Server. Prevents users from seeing the names of files they cannot access. Configure via PowerShell: Set-SmbShare -Name Data -FolderEnumerationMode AccessBased.
Slide 11 of 19
User Account Control (UAC)
Principle of least privilege enforcement for Windows interactive sessions.
What UAC Does
Splits administrator accounts into a filtered standard token (used for normal operations) and a full administrator token (used only when elevated). Standard users receive a credential prompt. Admins receive a consent prompt. Reduces the impact of malware running under an admin account.
UAC Levels
Always notify: Prompts for all changes including Windows Settings. Default: Prompt only when apps try to make changes; dim desktop. Notify for app changes only (no dim): Same as default but no secure desktop. Never notify: UAC effectively disabled. Only appropriate for isolated test environments.
Run As Administrator
Right-click an executable → Run as administrator. Or: runas /user:Administrator cmd.exe from command line. Elevated processes run with the full admin token. Required for Disk Management, registry changes, system32 file modifications, and service installation.
UAC Virtualization
Legacy 32-bit applications that write to protected locations (Program Files, Windows, HKLM registry) are redirected transparently to per-user virtual stores. This prevents application failures while maintaining system integrity. 64-bit applications do not receive virtualization — they must be rewritten to write to user-accessible locations.
Slide 12 of 19
NTFS Compression vs. EFS
Two NTFS attributes that cannot coexist on the same file.
NTFS Compression
Per-file or per-folder attribute. Windows compresses files transparently on write, decompresses on read. Performance impact on high-speed SSDs. File names appear blue in Explorer when compression is enabled. Command: compact /c /s C:\OldData. Cannot be combined with EFS on the same file.
EFS Encryption
Per-file or per-folder attribute. Files appear green in Explorer when EFS is enabled. Requires a user certificate. Available on Windows 10 Pro, Enterprise, and Education — not on Home editions. Key stored in user profile; must be backed up before profile migration.
cipher Command
cipher /e C:\file.txt — encrypt a file.
cipher /d C:\file.txt — decrypt a file.
cipher /s:C:\folder — encrypt folder recursively.
cipher /w:C:\ — wipe free space (overwrites deleted file data).
Mutually Exclusive
Enabling EFS on a compressed file automatically removes compression. Enabling compression on an EFS-encrypted file removes encryption. This is an NTFS design constraint — both attributes live in the same file metadata field and cannot coexist.
Not Available on Home
EFS requires Windows 10/11 Pro, Enterprise, or Education. Windows Home users cannot encrypt files with EFS. The Advanced button in file properties is present but the encryption checkbox is greyed out. BitLocker is the full-disk alternative for all editions with TPM.
Slide 13 of 19
Auditing File Access
Track who accesses what files using NTFS auditing and Security Event Log.
Step 1: Enable Audit Policy
Local Security Policy or GPO → Security Settings → Local Policies → Audit Policy → Audit object access: Success, Failure. Without this policy enabled, no file access events are written to the Security log regardless of SACL configuration.
Step 2: Configure SACL
File Properties → Security → Advanced → Auditing tab → Add an entry. Select users or groups to audit, which permissions to track (Read, Write, Delete), and whether to log Success, Failure, or both. SACL = System Access Control List.
Step 3: Review Event Log
Event Viewer → Windows Logs → Security. Filter by Event ID 4663 (file access attempt) and 4660 (object deleted). Each entry shows: username, object name, process name, access requested, and success/failure.
Legal compliance requirement: log all delete operations on the Contracts share. Solution: (1) Enable "Audit object access: Success and Failure" via GPO. (2) Add an auditing entry on \\Server\Contracts for Everyone → Delete. (3) Collect Security event log with SIEM or forward to a central log server. Event ID 4660 fires on each delete.

Windows Hello and Biometric Access
PIN, fingerprint, and facial recognition as local authentication factors.
Windows Hello PIN
Not the same as a password. PIN is tied to the specific device and backed by TPM. If the device is lost, the PIN has no value elsewhere. Stored as a hash in the TPM, never transmitted over the network. Required for Windows Hello biometric setup.
Fingerprint / Face Recognition
Requires compatible hardware (fingerprint reader, IR camera). Biometric data stored locally in encrypted form; never sent to Microsoft or cloud. Setup via Settings → Accounts → Sign-in options. Uses asymmetric cryptography via TPM for the actual authentication handshake.
FIDO2 / Security Keys
Hardware security keys (YubiKey, etc.) supported for Windows Hello for Business and Azure AD-joined devices. Phishing-resistant: the key signs a challenge from the specific domain it was registered for — no credential reuse across domains.
MD-100 Exam Context
Know that Windows Hello PIN is TPM-bound and device-local. Distinguish it from a Microsoft Account password. Know that biometric data does not leave the device. Questions may present scenarios where a user reports their fingerprint no longer works after a Windows reinstall — the answer is that biometric data must be re-enrolled because the TPM binding is reset.
Slide 15 of 19
Dynamic Access Control (DAC)
Claim-based access control beyond standard user and group membership.
What is DAC
Extends NTFS permissions with conditional expressions based on user claims (department, clearance level) and file classification properties (sensitivity label, project code). Policies defined centrally in Active Directory and pushed via GPO. Requires Windows Server 2012+ domain and Windows 8+ clients.
Central Access Policies
Defined in AD DS → Dynamic Access Control → Central Access Policies. Published via GPO. Allows a single policy like "Finance files can only be accessed by Finance department employees" to apply to all classified files without manually updating individual ACLs.
File Classification Infrastructure
Automatically tags files based on content (e.g., files containing credit card numbers tagged "Confidential"). Tags stored as NTFS extended attributes. DAC policies can then restrict access based on these tags rather than requiring manual security labeling.
MD-100 vs. Server Admin Scope
DAC is primarily a server-side and enterprise feature. MD-100 expects basic awareness — know that DAC provides claim-based conditional access, requires AD, and operates on top of standard NTFS/share permissions. Deep configuration is in the MD-101 (Enterprise) scope.
Resource Properties
File server administrators apply Resource Properties to files and folders (e.g., Confidentiality = High, Department = Finance). These properties flow into DAC rule evaluation. Combined with user claims, they enable fine-grained policy that traditional ACLs cannot express.

Diagnostic Sequence
(1) Confirm user identity with whoami /groups. (2) Check effective NTFS permissions with Advanced Security → Effective Access. (3) Check share permissions if over network. (4) Check for explicit Deny entries. (5) Confirm inheritance chain has no conflict. Resolve in that order before escalating.
Slide 17 of 19
Exam Scenarios
Six data access situations tested on MD-100.
Q1
A user has NTFS Modify on a folder. The share permission is Read. What is the effective permission over the network? — Read. Most restrictive wins. Share Read beats NTFS Modify when accessing over the network.
Q2
A user is in Group A (Allow Read) and Group B (Deny Write) on a file. Can they read the file? — Yes. Deny Write only blocks writing. Allow Read is cumulative across groups. They can read but not write.
Q3
A user's EFS-encrypted files are inaccessible after a fresh Windows install on the same machine. Why? — The EFS certificate (private key) was not exported before reinstall. The FEK is now unrecoverable without the DRA or the original certificate backup.
Q4
Folder redirection is configured via GPO but the Documents folder still points to C:\Users\Bob. What is the first thing to check? — Whether the GPO is actually applying to the user (run gpresult /r). Verify the OU contains the user and the GPO link is enabled.
Q5
A user can read files in a shared folder but cannot create new files despite having NTFS Write. What is the cause? — The share permission is Read, not Change or Full Control. Share Read prevents file creation even when NTFS Write is granted.
Q6
An admin tries to access C:\Users\Jane\Documents but gets "Access Denied." How should they proceed? — Use takeown to take ownership of the folder, then assign Full Control to the Administrators group via icacls or File Explorer.

Module 6 Summary
Eight key takeaways for the MD-100 data access domain.
1
NTFS permissions apply locally and over the network. Share permissions apply only over the network. When combined, the most restrictive of the two is the effective permission.
2
Deny overrides Allow at the same level. An explicit Deny blocks access regardless of any Allow entries in the same ACL or in group memberships.
3
EFS is NTFS-only, user-bound, and requires a certificate backup. Files cannot be both compressed and EFS-encrypted. The private key must be exported before migrating or rebuilding the OS.
4
Folder Redirection via GPO moves profile folders to a file server. Combined with Offline Files, users can work offline. Best practice: grant Everyone Full Control at the share, control all access via NTFS.
5
Administrative shares (C$, ADMIN$) are auto-created by Windows, hidden, and admin-only. They cannot be permanently removed without a registry modification.
6
icacls is the primary CLI tool for NTFS ACL management. Use takeown to take ownership of locked files before modifying their ACLs.
7
UAC splits admin tokens for least-privilege enforcement. Standard users are prompted for credentials; admins receive consent prompts. Never disable UAC in production.
8
Effective Access tab in Advanced Security shows computed permissions for a specific user. Always use this tool to diagnose permission problems before making changes.
