Device Driver Failures

Device Manager error codes and driver management tools

Code Meaning Typical Fix
Code 1 Device not configured correctly Update or reinstall the driver
Code 10 Device cannot start — most common code Update driver; check for hardware failure; verify power
Code 28 Drivers not installed (no driver found) Install the correct driver from manufacturer
Code 31 Device not working properly — driver issue Reinstall driver; check Windows Update for driver
Code 39 Driver corrupt or missing (registry error) Reinstall driver; run SFC to repair system files
Code 43 Device has reported a problem and stopped working Reinstall driver; replace hardware if driver reinstall fails

Driver Signing Enforcement

Windows 10 64-bit requires all kernel-mode drivers to be digitally signed by Microsoft. Unsigned drivers are blocked from loading. Temporarily disable from WinRE → Startup Settings → "Disable driver signature enforcement" for testing. Use pnputil /add-driver driver.inf /install to install signed drivers from the command line.

Driver Store & Rollback

The Driver Store (C:\Windows\System32\DriverStore) holds all installed driver packages. If a new driver causes problems, right-click the device in Device Manager → Properties → Driver tab → Roll Back Driver. The previous version is restored from the store without needing the original media.

Exam Tip

Code 43 is the most common code for USB devices that have physically failed. Code 10 is the most common code for driver-related failures. Code 28 means no driver exists at all — you must install one.

Physical Hardware Troubleshooting

When the problem is the hardware itself, not the software

POST Codes & Beep Codes

Power-On Self Test runs before the OS. UEFI systems display numeric error codes on-screen or via diagnostic LEDs. Legacy BIOS systems use beep codes. 1 beep typically = passed POST. Multiple beeps indicate RAM, GPU, or other hardware failure. Codes are manufacturer-specific — always reference the motherboard manual.

Memory Diagnostics

Run Windows Memory Diagnostic (mdsched.exe) — tests RAM on next reboot with Standard, Basic, or Extended test modes. Symptoms of bad RAM: random BSODs, spontaneous reboots, application crashes, data corruption. Reseat RAM first. If using multiple DIMMs, test one at a time to isolate a failed module.

Thermal Issues

Overheating causes thermal throttling (reduced performance) and emergency shutdown. Symptoms: system hot to the touch, fans at maximum speed, spontaneous shutdowns under load. Use HWMonitor or UEFI hardware monitor to check temperatures. Clean dust from heatsinks and fans. Verify thermal paste contact on CPU.

PSU Testing

A failing PSU causes random reboots, failure to POST, and instability under load. Use a PSU tester or multimeter to verify voltage rails: +12V (within ±5%), +5V, +3.3V. Swap with a known-good PSU as the most reliable test. Insufficient wattage from a good PSU also causes instability when a GPU or new hardware was added.

Hard Drive Diagnostics

  • chkdsk C: /f /r — checks file system integrity (/f fixes errors) and scans for bad sectors (/r recovers data from bad sectors). Requires a reboot on the system drive.
  • S.M.A.R.T. data: Hard drives report internal health metrics. Use manufacturer tools (SeaTools, WD Diagnostics) or CrystalDiskInfo to read SMART data — reallocated sectors increasing is a failure warning sign.
  • Clicking or grinding sounds from an HDD = immediate backup and replacement — mechanical failure is imminent

BSOD Stop Code Analysis

Blue Screen of Death — reading the crash, not just rebooting from it

IRQL_NOT_LESS_OR_EQUAL
Stop: 0x0000000A
Driver accessed invalid memory at elevated IRQL. Usually a faulty or incompatible driver. Install recent Windows updates, roll back newly installed drivers.
KERNEL_DATA_INPAGE_ERROR
Stop: 0x0000007A
Windows could not read required data from the pagefile or a mapped file. Points to bad RAM, failing hard drive, or corrupted pagefile. Run mdsched and chkdsk.
CRITICAL_PROCESS_DIED
Stop: 0x000000EF
A critical Windows process (e.g., csrss.exe, lsass.exe, winlogon.exe) terminated unexpectedly. Run SFC and DISM to repair OS files. May indicate malware.
PAGE_FAULT_IN_NONPAGED_AREA
Stop: 0x00000050
A driver or system component referenced memory that should not be paged out. Faulty RAM or driver bug. Run memory diagnostic and update/roll back drivers.
SYSTEM_THREAD_EXCEPTION_NOT_HANDLED
Stop: 0x0000007E
A system thread generated an exception that the error handler didn't catch. Often shows the faulting driver filename. Roll back or update the named driver.
DRIVER_IRQL_NOT_LESS_OR_EQUAL
Stop: 0x000000D1
Variant of 0xA — driver accessed paged memory at improper IRQL. Check the faulting module name in the minidump. Update or remove the listed driver.

Minidump Analysis

  • Minidumps stored at C:\Windows\Minidump\ — each BSOD creates a small dump file with stop code, faulting module, and stack trace
  • WinDbg (Windows Debugger) from the Windows SDK can open minidumps. Run !analyze -v for automated analysis pointing to the likely faulting driver
  • Enable complete memory dumps via Advanced System Properties → Startup and Recovery Settings for more detailed analysis

Peripheral Troubleshooting

USB, display, audio, Bluetooth, printers, and network adapters

USB Issues

Device not recognized: Try different port (USB 2.0 vs 3.0), check Device Manager for Code 43 or Unknown Device, reinstall USB controller drivers.
Power issues: USB hubs without external power cannot provide full 900mA (USB 3.0). Use a powered hub for power-hungry devices.
USB Selective Suspend: Power saving may disconnect idle devices — disable in Power Options → Advanced → USB Settings.

Display Problems

No signal: Check cable connections, try a different cable and port, test the monitor on a known-good PC.
Wrong resolution: Update GPU driver. Check Display Settings → Advanced Display Settings for native resolution.
Multiple monitor issues: Windows+P cycles projection modes. Check Display Settings for arrangement and scaling.

Audio Troubleshooting

No sound: Check default playback device in Sound Settings. Verify Windows Audio service is running. Check volume mixer — per-app muting is common.
Wrong device: Right-click speaker icon → Open Sound Settings → set correct Output device. HDMI audio requires selecting the display as the output device.

Printer & Bluetooth

Print spooler issues: Services.msc → restart Print Spooler service. Clear stuck jobs from C:\Windows\System32\spool\PRINTERS\.
Bluetooth pairing failures: Remove device from both sides (PC and device), toggle Bluetooth off/on, ensure device is in pairing mode, check for driver updates.

Exam Tip

For printer troubleshooting: spooler restart fixes most queue issues. For network adapters not working after a driver update: Device Manager → Roll Back Driver is faster than downloading the old driver manually. For Bluetooth: "Remove device" on both sides before re-pairing is the reset most people skip.

Hardware Diagnostics Toolkit

The right tool for every hardware investigation

msinfo32.exe
System Information — comprehensive hardware and software inventory. IRQ conflicts, PCI devices, driver versions, loaded modules, network adapters, storage devices. Export to .NFO or .TXT for remote analysis.
dxdiag.exe
DirectX Diagnostic Tool — display adapter details, DirectX version, driver date and version, audio device details. Identifies display driver crashes (DXGI errors). Use "Save All Information" to create a shareable report.
mdsched.exe
Windows Memory Diagnostic — tests RAM for errors on next reboot. Choose Standard (default counters), Basic (quick), or Extended (stress test). Results shown after reboot in Event Viewer → System log (source: MemoryDiagnostics-Results).
chkdsk /f /r
Check Disk — fixes file system errors (/f) and recovers data from bad sectors (/r). Run on suspect drives. Results logged to Event Viewer → Application log (source: Chkdsk). Schedule for system drive via Task Scheduler for next reboot.
Device Manager
devmgmt.msc — central hub for driver status, error codes, enabling/disabling devices, updating/rolling back drivers, and scanning for hardware changes. Right-click → Scan for hardware changes re-enumerates the PCI and USB buses.
Hardware Troubleshooters
Settings → Update & Security → Troubleshoot. Built-in troubleshooters for Printer, Bluetooth, Camera, Audio, Internet Connections, Hardware and Devices. Good first automated step before manual investigation. Results logged in Event Viewer.
Exam Tip

msinfo32 is the first tool to open for a hardware inventory question. dxdiag is specific to display and audio. mdsched tests RAM. chkdsk tests the storage file system and sectors. Know which tool answers which question — exam scenarios describe a problem and ask you to select the diagnostic tool.

Summary

Module 11 — Core concepts to retain

Driver Failures

Code 10 = cannot start (driver issue). Code 28 = no driver installed. Code 43 = device-reported failure (often hardware). Roll Back Driver in Device Manager is the fastest fix after a bad update.

Physical Hardware

POST beep codes = manufacturer-specific hardware failure. mdsched.exe tests RAM. chkdsk /f /r repairs file system and bad sectors. Clicking HDD = immediate backup and replacement.

BSOD Analysis

IRQL errors = driver memory access violation. CRITICAL_PROCESS_DIED = OS process crash (possible malware). Minidumps in C:\Windows\Minidump — WinDbg with !analyze -v identifies the faulting driver.

Diagnostics Toolkit

msinfo32 for full hardware inventory. dxdiag for display and DirectX. mdsched for RAM testing. chkdsk for disk health. Device Manager for driver status and error codes.

Critical Exam Points

  • Device Manager Code 43 on USB device = hardware failure, not driver issue — replace the device
  • Driver signing enforcement is required for 64-bit Windows 10 kernel-mode drivers — no exceptions in production
  • IRQL BSODs occurring after a driver install = roll back that driver first before any other action
  • dxdiag is purpose-built for display/audio driver details; msinfo32 covers all hardware broadly
  • Print Spooler restart + clear C:\Windows\System32\spool\PRINTERS\ resolves most stuck print queue issues
