Device Driver Failures
Device Manager error codes and driver management tools.
CodeMeaningTypical Fix
Code 1Device not configured correctlyUpdate or reinstall the driver
Code 10Device cannot start — most commonUpdate driver; check for hardware failure; verify power
Code 28Drivers not installed (no driver found)Install correct driver from manufacturer
Code 31Device not working properly — driver issueReinstall driver; check Windows Update for driver
Code 39Driver corrupt or missing (registry error)Reinstall driver; run SFC to repair system files
Code 43Device has reported a problem and stoppedReinstall driver; replace hardware if reinstall fails
Driver Signing Enforcement
Windows 10/11 64-bit requires all kernel-mode drivers to be digitally signed by Microsoft. Unsigned drivers are blocked. Temporarily disable from WinRE → Startup Settings → "Disable driver signature enforcement" for testing. Use pnputil to install signed drivers from the command line.
Driver Store & Rollback
The Driver Store (C:\Windows\System32\DriverStore) holds all installed driver packages. If a new driver causes problems: Device Manager → right-click device → Properties → Driver tab → Roll Back Driver. The previous version is restored from the store without needing original media.
Exam Tip
Code 43 is the most common code for USB devices that have physically failed. Code 10 is the most common for driver-related failures. Code 28 means no driver exists at all — you must install one from scratch.

Hardware Diagnostic Flowchart
Symptom to isolation to test to replace — the structured hardware troubleshooting process.
Isolate Effectively
Remove all non-essential components: extra RAM sticks, expansion cards, storage drives. Boot with minimum config (CPU + one RAM stick + GPU if needed). Add components back one at a time until the failure reappears — this identifies the culprit.
Known-Good Swap Method
Replace the suspected component with a confirmed-working identical or compatible part. If the problem resolves, the original component failed. This is more reliable than any software diagnostic because it physically eliminates the component as a variable.
Document Every Test
Record which component was swapped, what was observed, and the result. In complex multi-component failures, without documentation you may re-test combinations you already eliminated. A simple note in your ticket saves significant time.

Physical Hardware Troubleshooting
POST codes, memory diagnostics, thermal issues, and PSU testing.
POST Codes & Beep Codes
Power-On Self Test runs before the OS. UEFI systems display numeric error codes on-screen or via diagnostic LEDs. Legacy BIOS uses beep codes. 1 short beep typically = passed POST. Multiple beeps indicate RAM, GPU, or other hardware failure. Codes are manufacturer-specific — always reference the motherboard manual.
Memory Diagnostics (mdsched.exe)
Windows Memory Diagnostic tests RAM on next reboot. Test modes: Basic (quick), Standard (default), Extended (stress test). Symptoms of bad RAM: random BSODs, spontaneous reboots, application crashes, data corruption. Reseat RAM first — a poor connection causes failures without the module itself being faulty.
Thermal Issues
Overheating causes thermal throttling and emergency shutdown. Symptoms: system hot to touch, fans at maximum speed, spontaneous shutdowns under load. Use HWMonitor or UEFI hardware monitor to check temperatures. Clean dust from heatsinks and fans. Verify thermal paste contact on CPU — replace if dry or cracked.
PSU Testing
A failing PSU causes random reboots, failure to POST, and instability under load. Verify voltage rails with a PSU tester: +12V (within ±5%), +5V, +3.3V. Swap with a known-good PSU as the most reliable test. Insufficient wattage from a good PSU also causes instability when a GPU or new hardware was added.
Hard Drive Quick Indicators
Clicking or grinding sounds from an HDD = immediate backup and replacement — mechanical failure is imminent. Check S.M.A.R.T. data with manufacturer tools (SeaTools, WD Diagnostics) or CrystalDiskInfo. Reallocated sectors increasing over time = impending failure.

Display Troubleshooting Decision Tree
Systematic path from "no display" to root cause — cable, GPU, driver, or monitor.
No Signal / Blank Screen
Check cable connections. Try a different cable and port type (HDMI vs DisplayPort). Verify the monitor input source matches the connected port. Test the monitor on a known-good PC to determine if the monitor or GPU is the failure point.
Wrong Resolution / Scaling
Update GPU driver first. Then check Display Settings → Advanced Display → Display adapter properties for native resolution. On multi-monitor setups, Windows+P cycles projection modes. DPI scaling mismatches cause blurry text — set per-application scaling in Compatibility tab or System-wide in Display Settings.
Multiple Monitor Issues
Windows+P cycles: PC screen only / Duplicate / Extend / Second screen only. Check Display Settings for arrangement (drag displays to match physical layout) and individual scaling settings. HDMI audio may need to be set as default output device separately from the display.

S.M.A.R.T. Storage Failure Indicators
Self-Monitoring Analysis and Reporting Technology — reading the warning signs before failure.
Reading S.M.A.R.T. Data
Each S.M.A.R.T. attribute has a current value, worst value, and threshold. When the current value drops below the threshold, the drive reports a failure status. CrystalDiskInfo summarizes this as Good, Caution, or Bad — read the raw attribute values for the full picture.
chkdsk vs. S.M.A.R.T.
chkdsk checks the file system layer — it finds and repairs logical corruption and bad sectors at the OS level. S.M.A.R.T. reads the drive's internal firmware metrics — it indicates physical degradation below the file system. Both are needed for complete storage health assessment.
SSD Health Metrics
SSDs use different S.M.A.R.T. attributes: Media Wearout Indicator (available spare blocks dropping), Total Bytes Written (TBW budget consumed), Uncorrectable Error Count (fatal errors). Monitor with manufacturer tools (Samsung Magician, Intel SSD Toolbox) for accurate SSD health.

Power Troubleshooting Sequence
PSU to motherboard to components — systematic power fault isolation.
PSU Failure Symptoms
Random reboots under load, failure to POST, system doesn't start, instability after adding hardware. Test with a PSU tester first. If passing, swap to a known-good PSU of adequate wattage for the configuration. Underrated PSUs pass voltage tests at idle but fail under GPU + CPU load.
CMOS Battery
A dead CMOS (CR2032) battery causes: date/time resetting to defaults on every reboot, BIOS settings not saving, boot configuration prompts on every start. Replace the coin cell battery on the motherboard — available at any electronics store. Clear CMOS settings will also clear overclocking configs.
Power Plan Settings
Performance settings: Control Panel → Power Options. Balanced (default), Power Saver (reduced performance), High Performance (no throttling). Laptops have additional Battery Saver mode. USB Selective Suspend in Advanced settings can disconnect idle USB devices — disable for persistent connected peripherals.

Minidump Analysis
Minidumps: C:\Windows\Minidump\. Open with WinDbg → run !analyze -v for automated analysis. The output identifies the faulting driver, module, and call stack. Configure dump type: Advanced System Properties → Startup and Recovery → Automatic memory dump.
Reliability Monitor
Action Center → Reliability Monitor shows a visual timeline of BSODs, application crashes, and hardware errors. Each event is clickable for details. Cross-reference the BSOD timestamp with driver installs or Windows updates shown on the same timeline to identify the triggering change.

Peripheral Troubleshooting
USB, audio, Bluetooth, printers, and network adapter fixes.
USB Issues
Device not recognized: Try different port (USB 2.0 vs 3.0). Check Device Manager for Code 43 or Unknown Device. Reinstall USB controller drivers.
Power issues: USB hubs without external power cannot provide full 900mA. Use a powered hub for power-hungry devices.
USB Selective Suspend: Power Options → Advanced → USB Settings → disable for persistent devices.
Audio Troubleshooting
No sound: Check default playback device in Sound Settings. Verify Windows Audio service is running. Check volume mixer — per-app muting is common.
Wrong device: Right-click speaker icon → Open Sound Settings → set correct Output device. HDMI audio requires selecting the display as the audio output device.
Bluetooth Pairing Failures
Remove the device from both sides (PC and device) before re-pairing — most people skip this step. Toggle Bluetooth off/on on the PC. Ensure the device is in pairing mode (holding the pairing button). Check for Bluetooth driver updates in Device Manager. Bluetooth stack relies on correct adapter firmware.
Printer Issues
Stuck jobs: Stop Print Spooler service, clear C:\Windows\System32\spool\PRINTERS\, restart service.
Driver corrupt: Remove and reinstall the printer driver package completely — do not just update over a corrupt driver.
Network printer: Verify the IP address is static or the hostname resolves correctly.
Network Adapter
After a driver update breaks networking: Device Manager → Roll Back Driver is faster than downloading the old driver manually. For intermittent drops: check for Power Management settings that allow the adapter to be turned off to save power. Disable in Device Manager → Properties → Power Management.

Driver Management Commands
driverquery, pnputil, and PowerShell for driver audit and control.
Audit & Query
driverquery /v /fo csv > drivers.csv
Export all installed drivers with verbose details to CSV. Essential for auditing driver state or comparing across machines after a deployment.
driverquery /si
Show signed driver information — whether each driver is digitally signed and by whom. Unsigned drivers are a common BSOD cause and a security risk.
pnputil /enum-drivers
List all third-party drivers in the driver store. Shows OEM INF file, provider, class, and version. The store is the repository Windows pulls from during device plug-in.
Install & Remove
pnputil /add-driver C:\Drivers\*.inf /subdirs /install
Add and install all driver packages from a folder and subfolders. Used for bulk-loading drivers after a clean install.
pnputil /delete-driver oem42.inf /force
Remove a specific driver package from the store. /force removes even if the driver is currently in use — device falls back to a generic driver.
Get-PnpDevice -Status ERROR | Format-Table Class,FriendlyName
PowerShell: list all devices currently in an error state. Faster than scrolling through Device Manager. Use -Status OK to verify working devices.
Driver Rollback Availability
Driver rollback is only available if a previous version exists in the driver store. In Device Manager, if "Roll Back Driver" is greyed out, no previous version is stored. If rollback is unavailable and the new driver causes issues, uninstall the device and let Windows reinstall the previous version from the store on next reboot.

POST, UEFI, & Firmware Settings
What happens before Windows loads — and how firmware settings affect hardware behavior.
UEFI vs. Legacy BIOS
UEFI: Supports GPT disks, Secure Boot, mouse navigation, 2.2 TB+ boot drives, faster boot times (UEFI fast boot). Required for Windows 11.
Legacy BIOS: MBR only, max 2.2 TB boot disk, text-mode interface, 16-bit real mode. No Secure Boot support.
Secure Boot
UEFI security feature that checks digital signatures of bootloaders and drivers before loading. Prevents bootkit malware from loading before the OS. Can be temporarily disabled for installing unsigned Linux or older OS. Required for Windows 11. Check status: msinfo32 → Secure Boot State.
TPM (Trusted Platform Module)
Security chip that stores encryption keys (BitLocker), certificates, and boot measurements. Required for Windows 11 (TPM 2.0). Check status: tpm.msc. If TPM shows as unavailable, enable it in UEFI under Security or Advanced settings. Must be TPM 2.0 for Windows 11 compliance.
Virtualization Extensions
Intel VT-x or AMD-V must be enabled in UEFI before Hyper-V, WSL 2, or other hypervisors can run 64-bit VMs. Often disabled on OEM machines by default. Check: Task Manager → Performance → CPU → "Virtualization: Enabled." Enable in UEFI if shown as disabled.
Windows 11 upgrade blocked: "This PC doesn't currently meet Windows 11 system requirements." Most common reasons: TPM 2.0 disabled in UEFI, Secure Boot disabled, CPU not in compatibility list. Enable TPM 2.0 and Secure Boot in UEFI, then re-run PC Health Check.

Thermal & Environmental Issues
Heat, dust, humidity, and electrostatic discharge as hardware failure causes.
CPU Thermal Throttling
When CPU temperature exceeds the thermal design limit, it reduces clock speed to generate less heat. Symptoms: system feels fast at startup, slows noticeably under sustained load. Use HWMonitor or UEFI sensor readings. Clean dust from heatsink fins. Verify fan is spinning and seated correctly.
GPU Overheating
GPU temps above 90°C under load indicate inadequate cooling. Symptoms: screen artifacts, driver crashes (DXGI errors), system shutdown mid-game. Clean GPU heatsink and fans. Improve case airflow (front intake, rear/top exhaust). Repaste the GPU if it's over 3 years old and running hot.
Electrostatic Discharge (ESD)
ESD can permanently damage components without visible signs. Always use an anti-static wrist strap or regularly touch the metal chassis before handling components. Work on anti-static mats. Never handle PCBs by contact pads. Low humidity environments are especially high-risk for ESD damage.
Environmental Checklist
Server room / workstation area requirements: ambient temperature 18-27°C (65-80°F), relative humidity 40-60%, no direct sunlight on equipment, clean filtered air supply. Moisture and corrosion cause intermittent contact failures that are extremely difficult to diagnose — the hardware tests fine when cool and dry.
A user reports their PC crashes every afternoon but is fine in the morning. Check ambient temperature — afternoon sun may be heating the room beyond safe operating range. Also check that the case vents are not blocked by the wall or furniture reducing airflow.

Storage Troubleshooting
RAID, NVMe, and advanced storage diagnostic techniques.
RAID Failure Indicators
Windows Storage Spaces or hardware RAID controller shows degraded array status when a drive fails. Replace the failed drive immediately — a second drive failure during rebuild destroys all data. RAID 5 can tolerate one failure; RAID 1 can tolerate one failure; RAID 0 has zero redundancy.
NVMe vs. SATA Troubleshooting
NVMe drives that disappear after warm reboot (not cold boot) indicate an ASPM (Active State Power Management) or PCIe power state issue. Disable ASPM in UEFI or adjust PCIe power management in Device Manager. NVMe not detected at all: check M.2 slot compatibility (PCIe 3.0 vs 4.0) and UEFI NVMe driver support.
Storage Spaces
Windows 10/11 built-in software-defined storage. Creates a "pool" from multiple drives with optional redundancy (Mirror, Parity). Manage via Settings → System → Storage → Manage Storage Spaces. Failed drives show status in the interface with replacement instructions. No third-party controller required.
Disk Management & diskpart
Disk Management (diskmgmt.msc) shows all volumes, their status (Healthy, Failed Redundancy, Unallocated), and partition layout. For CLI: diskpart → list disk → select disk N → detail disk shows drive status, partition style (MBR/GPT), and volume assignments.

Memory & RAM Deep Dive
Diagnosing RAM failures and configuring virtual memory correctly.
RAM Failure Symptoms
Random BSODs (especially 0x50 or 0x1A), application crashes without consistent patterns, data corruption in files, system fails to boot or boot loop. Blue screen with different stop codes each time = classic bad RAM signature. Reseat sticks first — poor contact mimics bad RAM.
mdsched.exe Test Modes
Basic: Quick test, limited pass count — catches obvious failures only.
Standard (default): Runs more tests, adequate for most situations.
Extended: Maximum test coverage, may take hours — use for intermittent failures. Results appear in Event Viewer → System after reboot.
Virtual Memory / Pagefile
System-managed pagefile is generally optimal. Manual sizing: minimum 1.5x RAM, maximum 3x RAM. Custom pagefile on a separate fast drive (SSD) improves HDD-primary systems. Configure via Advanced System Properties → Advanced → Performance Settings → Advanced → Change. Setting pagefile = 0 disables it — not recommended.
ReadyBoost
Insert a USB flash drive or SD card and configure it as ReadyBoost cache for additional RAM caching on HDD-based systems. Effective when RAM is limited and the storage is HDD-speed. Has zero benefit on SSD systems because the SSD is already faster than USB. Configure: right-click the USB drive → Properties → ReadyBoost tab.
Exam Tip
Pagefile too small causes "Your computer is low on memory" warnings and application crashes. Always set system-managed first. Only override manually when you have specific performance profiling data justifying a custom size. Disabling the pagefile entirely prevents crash dump creation.

Driver management, device diagnostics, and hardware verification tools.
Device & Driver
driverquery /v /fo csv > drivers.csv
Export all installed drivers with verbose details to CSV for auditing driver state across machines.
sigverif
File Signature Verification — GUI tool scans system files for unsigned drivers. Log at %systemroot%\sigverif.txt. Unsigned files may have been tampered with.
verifier /standard /all
Enable Driver Verifier — stress tests all drivers. May cause immediate BSOD on a bad driver. Reset: verifier /reset
Diagnostics & Info
dxdiag
DirectX Diagnostic Tool — display adapter, driver version, audio devices, WHQL certification status. Save All Information for a shareable report.
mdsched.exe
Schedule a Windows Memory Diagnostic to run at next reboot. Choose Standard or Extended test mode. Results logged in Event Viewer System log after reboot.
Get-PnpDevice -Status ERROR | Format-Table Class,FriendlyName,Status
PowerShell: list all devices currently in an error state. Faster than navigating Device Manager for quick error triage on multiple machines.
Exam Tip
Driver Verifier (/standard /all) is specifically used to identify unstable drivers by subjecting them to intensive stress testing. It intentionally causes BSODs when a buggy driver is found — this is by design. Only use it in a diagnostic context. Always have a recovery path ready before enabling it.

Module 11 Summary
Core concepts to retain for the MD-100 exam.
Driver Failures
Code 43 = physical failure or driver. Code 10 = cannot start (driver). Code 28 = no driver. Rollback from Driver tab. Offline removal via WinRE: dism /image + pnputil.
Hardware Diagnostics
msinfo32 = full inventory. dxdiag = display/audio. mdsched = RAM. chkdsk = file system/sectors. verifier = driver stress test. Known-good swap is the most reliable physical test.
Common Failure Patterns
Crashes under load = PSU/thermal. Random BSODs with different codes = RAM. S.M.A.R.T. reallocated sectors increasing = drive failing. USB Code 43 = physical or driver issue. Afternoon crashes = thermal/environmental.
