Troubleshooting Methodology

The CompTIA structured approach — never skip steps

1

Identify the Problem

Gather information from the user, error messages, and system logs. Ask open-ended questions: "What changed recently?" Check event logs for timestamps matching the issue onset.

2

Establish a Theory of Probable Cause

Start with the most likely and simplest cause first (Occam's Razor). Consider hardware, software, configuration, and user error. Use divide-and-conquer to isolate the failure domain.

3

Test the Theory

Perform a targeted test to confirm or deny your theory. If confirmed, move to step 4. If not, establish a new theory. This step prevents applying the wrong fix.

4

Establish a Plan of Action & Implement

Before touching anything, consider side effects. Back up data. Get user approval for significant changes. Then implement the fix in a controlled, documented manner.

5

Verify Functionality & Prevent Recurrence

Confirm the problem is fully resolved, not just masked. Apply preventive measures: Windows updates, driver updates, policy changes. Have the user verify from their perspective.

6

Document Findings & Outcomes

Record what the problem was, what caused it, and how it was resolved. Documentation builds your personal knowledge base and enables team knowledge sharing.

Exam Tip

Exam questions often describe a technician skipping steps (e.g., implementing a fix before testing the theory). Identify the missing step. Root cause analysis means asking "why did this fail" — not just fixing the symptom.

Windows Architecture

What is actually running under the hood

⚙️

Kernel Mode vs. User Mode

Kernel Mode: Full hardware access. Crashes here are catastrophic (BSODs). Houses the kernel, HAL, device drivers, and system services.

User Mode: Restricted access. Application crashes here are isolated — they don't take down the OS. Windows API, environment subsystems (Win32), and applications run here.

🗂️

Registry Hives

HKLM (HKEY_LOCAL_MACHINE): Machine-wide settings, hardware configuration, installed software, services.

HKCU (HKEY_CURRENT_USER): Per-user settings, preferences, and profile data for the logged-in user.

HKCR (HKEY_CLASSES_ROOT): File extension associations and COM object registrations. Merged view of HKLM\Software\Classes and HKCU\Software\Classes.

Windows Boot Sequence

  • POST / UEFI: Hardware self-test, firmware initializes, locates bootable device, hands off to Windows Boot Manager
  • bootmgr / Windows Boot Manager: Reads BCD (Boot Configuration Data) store — defines available OS entries
  • winload.exe: Loads the kernel (ntoskrnl.exe), HAL, and boot-start drivers into memory
  • Kernel Initialization: ntoskrnl starts, loads registry, initializes sessions, launches smss.exe (Session Manager)
  • Logon: winlogon.exe handles authentication, userinit.exe sets up the user shell (explorer.exe)
Exam Tip

Know which file does what: bootmgr reads BCD, winload.exe loads the kernel, ntoskrnl.exe IS the kernel. BCD errors break the boot menu; winload errors mean the kernel cannot load.

Support & Diagnostic Tools

Know the right tool for every problem

Tool Access Primary Use
Event Viewer (eventvwr.msc) Start menu / Run System, Application, Security logs — timestamps, Error/Warning IDs, source correlation
Reliability Monitor Control Panel → Security & Maintenance Visual timeline of crashes, installs, and failures. Shows stability score history.
Resource Monitor (resmon.exe) Task Manager → Performance tab Real-time CPU, Memory, Disk, and Network usage per-process. Identify file locks.
Task Manager (taskmgr.exe) Ctrl+Shift+Esc Kill processes, manage startup items, view service status, performance graphs
Performance Monitor (perfmon.exe) Run → perfmon Counter-based monitoring, Data Collector Sets for baselining, reports

Event Viewer Log Types

System log: OS and driver events, service start/stop failures.
Application log: App crashes, .NET errors, vendor events.
Security log: Logon events, policy changes, audit records.

Performance Monitor Key Counters

% Processor Time: CPU load — sustained >80% = bottleneck.
Available MBytes: RAM remaining — low = paging activity.
Disk Queue Length: >2 per spindle = storage bottleneck.
Pages/sec: High = excessive paging, add RAM.

Performance Troubleshooting

Identifying and resolving resource bottlenecks

🧠

CPU Bottlenecks

% Processor Time sustained above 85% indicates CPU saturation. Use Task Manager → Details tab to find the offending process. Check for malware mining crypto, runaway processes, or an underpowered CPU for the workload.

📊

Memory Bottlenecks

Watch Pages/sec and Available MBytes in PerfMon. High paging indicates insufficient RAM. Excessive hard faults cause disk thrashing. Short-term fix: close applications. Long-term: add RAM or adjust pagefile.

💾

Disk Bottlenecks

Avg. Disk Queue Length >2 per spindle signals a storage bottleneck. HDDs are far more susceptible than SSDs. Investigate with Resource Monitor's Disk tab to see which process hammers I/O most.

🌐

Network Bottlenecks

Resource Monitor Network tab shows per-process bandwidth and TCP connections. Network saturation, DNS resolution failures, or a chatty application can all cause perceived "slowness" that isn't CPU or RAM related.

Performance Tuning Options

  • ReadyBoost: Use a USB flash drive or SD card as a cache to supplement RAM — effective on HDD-based systems, no benefit on SSD
  • Virtual Memory / Pagefile: System-managed is generally best. Manual size: 1.5x RAM minimum, 3x RAM maximum. Custom pagefile on a separate drive can help HDD systems.
  • Performance Baseline: Create Data Collector Sets in PerfMon before problems occur — gives you a normal reference to compare against during incidents
  • Startup Impact: Task Manager → Startup tab shows startup programs rated High/Medium/Low impact — disable unnecessary items

System Recovery

Restoring functionality when normal troubleshooting fails

🔄

System Restore

Rolls Windows back to a restore point created before a problem-causing change. Does not affect user data files. Does undo driver installs, app installs, and registry changes. Requires restore points to exist — verify System Protection is enabled on C:. Access via rstrui.exe or WinRE.

🔁

Reset this PC

Keep my files: Reinstalls Windows, removes apps and settings, preserves personal files in user folders.

Remove everything: Full wipe and reinstall. Use before selling or repurposing a device. Can also fully clean the drive for secure disposal.

🛠️

Windows Recovery Environment (WinRE)

Accessed by holding Shift during restart or from Settings → Recovery. Provides: Startup Repair, System Restore, System Image Recovery, Command Prompt, and Startup Settings (Safe Mode access). The command prompt here runs as SYSTEM — powerful recovery capability.

⚠️

Safe Mode & Advanced Startup

Safe Mode: Loads minimal drivers only. Isolates third-party driver conflicts.
Safe Mode with Networking: Adds network drivers for downloading fixes.
Safe Mode with Command Prompt: No Explorer shell — pure command line recovery.

Exam Tip

Know the decision tree: driver crash → Safe Mode + rollback. Software change broke boot → System Restore. OS corruption → Reset Keep files. Need access to files before full wipe → WinRE Command Prompt. Unrecoverable + selling device → Reset Remove everything.

Summary

Module 9 — Core concepts to retain

📋

Troubleshooting Process

Identify → Theory → Test → Implement → Verify → Document. Never skip steps. Root cause analysis prevents recurrence, not just symptom fixing.

🏗️

Windows Architecture

Kernel mode (drivers, BSODs) vs. user mode (apps, isolated crashes). Boot: UEFI → bootmgr → winload → kernel → logon. HKLM = machine, HKCU = user, HKCR = file types.

🔬

Diagnostic Tools

Event Viewer for historical logs, Resource Monitor for real-time file/network/CPU per-process, Performance Monitor for baselining, Reliability Monitor for visual crash timeline.

🔄

Recovery Options

Safe Mode isolates drivers. System Restore reverses software changes (no data loss). Reset PC — Keep files reinstalls Windows. WinRE provides all recovery tools when the OS won't boot normally.

Critical Exam Points

  • Kernel mode crash = BSOD; user mode crash = application error — different severity, different tools
  • Disk Queue Length >2 = disk bottleneck; Pages/sec high = insufficient RAM
  • System Restore does NOT delete user files; Reset → Remove everything DOES
  • WinRE Command Prompt runs as SYSTEM — most powerful recovery option
  • Data Collector Sets in PerfMon are the right tool for creating performance baselines
