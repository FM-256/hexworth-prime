Troubleshooting Methodology
The CompTIA structured approach — never skip a step.
1
Identify the Problem — Gather information from the user, error messages, and system logs. Ask open-ended questions: "What changed recently?" Check Event Logs for timestamps matching the issue onset.
2
Establish a Theory of Probable Cause — Start with the most likely and simplest cause first (Occam's Razor). Divide the failure domain: hardware, software, configuration, or user error.
3
Test the Theory — Perform a targeted test to confirm or deny. If confirmed, move to step 4. If denied, form a new theory. This prevents applying the wrong fix.
4
Establish a Plan of Action & Implement — Consider side effects before touching anything. Back up data. Get user approval for significant changes. Implement in a controlled manner.
5
Verify Functionality & Prevent Recurrence — Confirm the problem is fully resolved, not just masked. Apply preventive measures: updates, policy changes. Have the user verify from their perspective.
6
Document Findings & Outcomes — Record what the problem was, what caused it, and how it was resolved. Documentation builds your knowledge base and enables team knowledge sharing.
Exam Tip
Questions often describe a technician skipping steps — implement before testing, or fix without documenting. Identify the missing step. Root cause analysis means asking "why did this fail" — not just fixing the symptom.

Windows Architecture
Kernel mode, user mode, registry hives, and the boot sequence.
Kernel Mode vs. User Mode
Kernel Mode: Full hardware access. Crashes here are catastrophic (BSODs). Houses the kernel, HAL, device drivers, and system services.

User Mode: Restricted access. Application crashes are isolated — they do not take down the OS. Win32 API, environment subsystems, and user applications run here.
Registry Hives
HKLM: Machine-wide settings, hardware, installed software, services.
HKCU: Per-user settings and preferences for the logged-in user.
HKCR: File extension associations and COM object registrations — merged view of HKLM and HKCU Software\Classes.
Windows Boot Sequence
POST / UEFI → bootmgr reads BCD → winload.exe loads kernel (ntoskrnl.exe) and HAL → Kernel initialization, smss.exe (Session Manager) → winlogon.exe authentication → userinit.exe → explorer.exe shell
Exam Tip
Know which file does what: bootmgr reads BCD. winload.exe loads the kernel. ntoskrnl.exe IS the kernel. BCD errors break the boot menu; winload errors mean the kernel cannot load.

Remote Desktop Architecture
How RDP connects a client to a remote Windows session over port 3389.
Enable Remote Desktop
Settings → System → Remote Desktop. Toggle "Enable Remote Desktop." Requires Windows 10/11 Pro, Enterprise, or Education — Home edition cannot host RDP connections. Allow through Windows Firewall automatically.
Port & Security
Default port TCP 3389. TLS encryption protects the session. Network Level Authentication (NLA) requires users to authenticate before a full desktop session is established — prevents unauthenticated session initiation.
mstsc.exe Options
Local Resources tab lets you redirect local drives, printers, clipboard, and audio into the remote session. Smart sizing scales the remote desktop to the client window. Save connections as .rdp files for quick reconnection.

Performance Troubleshooting
Identifying and resolving resource bottlenecks systematically.
CPU Bottlenecks
% Processor Time sustained above 85% indicates CPU saturation. Use Task Manager → Details tab to find the offending process. Check for malware mining crypto, runaway processes, or an underpowered CPU for the workload.
Memory Bottlenecks
Watch Pages/sec and Available MBytes in PerfMon. High paging indicates insufficient RAM. Short-term fix: close applications. Long-term: add RAM or adjust pagefile. Virtual Memory: system-managed is generally best.
Disk Bottlenecks
Avg. Disk Queue Length >2 per spindle signals a storage bottleneck. HDDs are far more susceptible than SSDs. Use Resource Monitor's Disk tab to identify which process hammers I/O most.
Network Bottlenecks
Resource Monitor Network tab shows per-process bandwidth and TCP connections. DNS resolution failures or a chatty application can cause perceived slowness that is not CPU or RAM related.
Performance Tuning
ReadyBoost: USB cache to supplement RAM — only effective on HDD-based systems. Startup Impact: Task Manager → Startup tab shows items rated High/Medium/Low — disable unnecessary items. Data Collector Sets: Create in PerfMon before problems occur for a normal reference baseline.

Windows Recovery Environment Boot Options
WinRE flowchart — from access method to available recovery tools.
Key Fact
The WinRE Command Prompt runs as SYSTEM — the most powerful recovery context available. All repair commands (bootrec, bcdedit, sfc, dism, chkdsk) can be run here even when the OS will not boot normally.

System Restore Timeline
Restore points on a timeline — rolling Windows back to a known-good state.
What System Restore Affects
Undoes driver installs, app installs, and registry changes made after the restore point. Does NOT affect user data files (documents, photos, downloads). Access via rstrui.exe or WinRE → System Restore.
Requirements & Limits
Requires System Protection to be enabled on C: (Settings → System → About → System Protection). Points are created automatically before updates and app installs. Limited by disk space allocated (default 3-5%). If System Protection is off, no points exist.

Backup Types Comparison
Full, incremental, and differential — speed vs. restore complexity tradeoff.
Full Backup
Copies all selected data every time. Clears the archive bit. Slowest to create, fastest to restore — only one set needed. High storage cost.
Incremental Backup
Backs up only data changed since the last backup of any type. Clears the archive bit. Fastest to create, slowest to restore — requires the full set plus every incremental in sequence.
Differential Backup
Backs up all data changed since the last full backup. Does NOT clear the archive bit. Grows larger each day. Restore requires only the full backup plus the most recent differential — a good middle ground.

Windows Backup Tools
File History, Backup and Restore, and wbAdmin for enterprise scenarios.
File History
Continuous backup of Libraries, Desktop, Contacts, and Favorites to an external drive or network share. Default every hour. Configured in Settings → Update & Security → Backup. Users restore via "Restore personal files" — NOT the Previous Versions tab.
Backup and Restore (Windows 7)
Legacy tool kept in Windows 10/11 for backward compatibility. Creates system image backups (bare-metal restore) and scheduled file backups. Access via Control Panel → Backup and Restore (Windows 7).
Previous Versions (VSS)
Volume Shadow Copy Service creates automatic snapshots. Right-click any file/folder → Properties → Previous Versions tab. No external drive needed — stored on the same volume. Created at restore points and before updates.
wbAdmin (Command Line)
wbAdmin start backup — enterprise-grade, scriptable backup. wbAdmin start recovery — restores files, applications, volumes, or the OS. wbAdmin is the command-line equivalent of Backup and Restore and is used by Group Policy and automation scripts.
Exam Tip
Previous Versions = VSS/shadow copies = no external drive or setup needed. File History = continuous backup = must be configured in advance. Windows File Recovery (winfr) = recovers deleted files without any prior backup configuration.

System Recovery Options
Choosing the right recovery depth — from Safe Mode to full reset.
Safe Mode
Safe Mode (Minimal): Loads minimal drivers only. Isolates third-party driver conflicts.
Safe Mode with Networking: Adds network drivers for downloading fixes.
Safe Mode with Command Prompt: No Explorer shell — pure command line recovery.
System Restore
Rolls Windows back to a restore point. Does NOT affect user data files. Does undo driver installs, app installs, and registry changes. Access via rstrui.exe or WinRE. Requires System Protection enabled on C:.
Reset This PC — Keep Files
Reinstalls Windows and removes apps and settings while preserving personal files in user folders. Faster than a clean install. Good when the OS is corrupted but data must be preserved. Run from Settings → Recovery.
Reset This PC — Remove Everything
Full wipe and reinstall. Use before selling or repurposing a device. The "Clean the drive" option overwrites disk space to prevent data recovery — use for secure disposal. This is the most destructive option.
Decision framework: driver crash on every boot → Safe Mode + rollback. Software change broke boot → System Restore. OS corruption → Reset, Keep files. Selling the device → Reset, Remove everything, Clean the drive.

Diagnostic & Monitoring Commands
Tools for system health, performance analysis, and event investigation.
Event & Performance
eventvwr.msc
Event Viewer. Key logs: Application (app crashes), System (driver/service failures), Security (audit). Filter by Event ID, source, or level.
perfmon /report
60-second system diagnostic report. CPU, memory, disk, and network data with HTML output and green/yellow/red indicators. Fastest "overall health check" command.
resmon
Resource Monitor — real-time per-process CPU, memory, disk, and network. Shows which process holds which file or port.
Repair & Inventory
sfc /scannow
Scan and repair protected system files from an elevated cmd. If it fails to fix, run DISM /RestoreHealth first, then re-run SFC.
chkdsk C: /f /r
/f fixes file system errors, /r locates bad sectors and recovers data. Schedules for next reboot if drive is in use.
msinfo32
System Information — hardware and software inventory. Components section shows IRQ conflicts, problem devices, and driver versions. Export to .nfo for remote analysis.
Exam Tip
perfmon /report is the fastest way to get a system health assessment — runs for 60 seconds and categorizes findings. For ongoing monitoring, use Performance Monitor with custom Data Collector Sets.

Remote Support Tools
Quick Assist, Remote Assistance, and RDP for different support scenarios.
Quick Assist
Built into Windows 10/11. Helper and sharer both open Quick Assist. Helper generates a 6-digit code, sharer enters it to establish a session. Supports full control or view-only. Works over the internet — no VPN needed. Replaces Windows Remote Assistance for consumer support.
Remote Desktop (RDP)
Full remote session to Windows Pro/Enterprise/Education. Requires port 3389 open, NLA preferred. The user at the remote machine is logged out when a remote session connects (unlike Quick Assist). Best for IT administration, not concurrent collaboration.
Remote Assistance (MSRA)
Legacy tool — user invites a helper using an email, file, or Easy Connect. Both parties can see the screen simultaneously. Helper can request control. Still available in Windows 10 via msra.exe. Being phased out in favor of Quick Assist.

Windows Update Management
Keeping Windows current while managing update deployment risks.
Update Types
Quality Updates: Cumulative monthly patches (security + bug fixes). Released Patch Tuesday (second Tuesday). Can be paused up to 35 days.
Feature Updates: Major OS version upgrades (e.g., 22H2 → 23H2). Deployed in staged rollouts. Can be deferred in Pro/Enterprise.
WSUS & Windows Update for Business
WSUS (Windows Server Update Services): On-premises update server. IT approves updates before clients install them. Reduces internet bandwidth. Managed via Group Policy.
Windows Update for Business: Cloud-based equivalent using Azure AD and Intune. Defer and ring-based deployment.
Troubleshooting Failed Updates
Run Windows Update Troubleshooter (Settings → Troubleshoot). Reset Windows Update components: stop wuauserv and bits, clear C:\Windows\SoftwareDistribution, restart services. Check Event Viewer → Windows Update logs for error codes.
Update Deferral Policy
Group Policy: Computer Configuration → Administrative Templates → Windows Components → Windows Update. Policies allow deferring quality updates up to 30 days and feature updates up to 365 days on Windows 10 Pro and above.

Event Viewer Deep Dive
Reading logs effectively — IDs, sources, and correlation for triage.
Get-EventLog -LogName System -EntryType Error -Newest 20
PowerShell: get the 20 most recent System errors. Faster than scrolling through Event Viewer for quick triage.
wevtutil qe System /c:10 /f:text /q:"*[System[(Level=2)]]"
Command-line event query: last 10 Error events (Level=2) from the System log. Works without PowerShell.
Get-WinEvent -FilterHashtable @{LogName='Application';Level=2} -MaxEvents 15
PowerShell modern: filter Application log for errors. Level 1=Critical, 2=Error, 3=Warning, 4=Information.

AppLocker & Software Restriction
Controlling which applications are allowed to run on Windows clients.
AppLocker (Windows 10/11 Enterprise)
Group Policy-based application whitelisting. Rules can be based on publisher (digital signature), file path, or file hash. Rule collections: Executable, Windows Installer, Script, Packaged Apps. Applied per security group. Requires Application Identity service to be running.
Software Restriction Policies
Legacy version — available on all editions. Rules: Unrestricted, Basic User, Disallowed. Rule types: Hash, Certificate, Path, Network Zone. Default All Software Rules set to Unrestricted. Less granular than AppLocker but works on Home/Pro editions.

Exam Tip
AppLocker requires Enterprise or Education. For Home and Pro clients, Software Restriction Policies is the only built-in option. AppLocker in Audit mode logs blocked apps without actually blocking them — useful for testing rules before enforcement.

Core concepts to retain for the MD-100 exam.
Troubleshooting Process
Identify → Theory → Test → Implement → Verify → Document. Never skip steps. Root cause analysis prevents recurrence.
Remote Support
RDP = TCP 3389, Pro+ host, user disconnected. Quick Assist = any edition, Microsoft relay, collaborative. MSRA = legacy, being phased out.
Backup Strategy
Full = most storage, easiest restore. Incremental = least storage, most tapes needed for restore. Differential = middle ground. Archive bit distinguishes backup types.
