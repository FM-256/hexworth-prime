File Recovery Options
Getting data back when it has been deleted or corrupted.
Previous Versions (Shadow Copies)
Snapshots created by Volume Shadow Copy Service (VSS). Right-click any file or folder → Properties → Previous Versions tab. Requires System Protection enabled on the volume. Created automatically at restore points and before Windows updates — no external drive needed.
File History
Continuous backup of Libraries, Desktop, Contacts, and Favorites. Copies go to an external drive or network share every hour by default. Configured in Settings → Update & Security → Backup. Restore via "Restore personal files" — not the Previous Versions tab. Must be configured before data loss occurs.
Recycle Bin
Files deleted from local drives go to the Recycle Bin. Files deleted from network shares or via Shift+Delete bypass it permanently. Each volume has its own Recycle Bin folder ($Recycle.Bin). Shift+Delete cannot be recovered via the Recycle Bin — a common support call.
Windows File Recovery (winfr)
Free Microsoft command-line tool from the Store. Recovers files from NTFS, FAT, exFAT, and ReFS. Three modes: Default (NTFS, recent deletes), Segment (NTFS, uses file records), Signature (any FS, searches by file type). Output destination MUST be a different drive than the source.
Exam Tip
Previous Versions = VSS/shadow copies (automatic, on-volume, no setup). File History = scheduled backup to external/network (requires prior setup). Windows File Recovery (winfr) = deleted file recovery without any prior backup configuration.

Application Troubleshooting
Compatibility, crashes, and dependency failures.
Compatibility Mode
Right-click the executable → Properties → Compatibility tab. Set the OS version the app was designed for (e.g., Windows 7). Can also reduce color depth, disable DPI scaling, and run as Administrator. Applies per executable, per user account.
Compatibility Troubleshooter
Right-click → "Troubleshoot compatibility." Wizard-driven — tests different compatibility settings automatically. Good first step before manually configuring the Compatibility tab.
Program Compatibility Assistant
Automatic background detection. Windows detects when an older program is installing or has crashed, then prompts to apply compatibility fixes automatically. Runs silently — the user may see a prompt after a crash.
Dependencies: .NET and Visual C++
Many apps require specific .NET Framework or Visual C++ Redistributable versions. Missing or corrupt runtimes cause crashes with cryptic error messages. Check Event Viewer Application log for .NET Runtime source (Event ID 1026) or Application Error (Event ID 1000) for the faulting module name.
App crash workflow: Event Viewer → Windows Logs → Application. Event ID 1000 gives the faulting module. If the module is VCRUNTIME140.DLL, reinstall the Visual C++ redistributable. If it is a .NET assembly, repair or reinstall the required .NET version.

BSOD Diagnostic Flow
Stop code to fix — reading the crash instead of just rebooting from it.
Reading a Stop Code
The BSOD displays a stop code (e.g., IRQL_NOT_LESS_OR_EQUAL), a hex value (0x0000000A), and often the faulting file name. Write down the stop code and filename before rebooting — they are your primary diagnostic leads.
WinDbg Analysis
Open a minidump in WinDbg (Windows Debugger from the Windows SDK). Run !analyze -v for automated analysis that identifies the likely faulting driver, module, and call stack. The output directly points to what to roll back or update.
Configure Dump Type
Advanced System Settings → Startup and Recovery. "Automatic memory dump" is the recommended setting — captures kernel context without requiring huge disk space. Minidump is stored in C:\Windows\Minidump\. Enable "Overwrite any existing file" for ongoing capture.

Common BSOD Stop Codes
Know these by name, hex value, and cause for the MD-100 exam.
Stop CodeHexCause & Fix
IRQL_NOT_LESS_OR_EQUAL0x0000000ADriver accessed invalid memory at elevated IRQL. Roll back or update recently installed drivers.
KERNEL_DATA_INPAGE_ERROR0x0000007AWindows could not read from pagefile or mapped file. Run mdsched (bad RAM) and chkdsk (bad drive).
CRITICAL_PROCESS_DIED0x000000EFA critical process (csrss, lsass, winlogon) terminated. Run SFC and DISM to repair OS files; check for malware.
PAGE_FAULT_IN_NONPAGED_AREA0x00000050Driver referenced memory that should not be paged out. Faulty RAM or driver bug. Run memory diagnostic.
SYSTEM_THREAD_EXCEPTION0x0000007ESystem thread generated unhandled exception. Stop code often shows faulting driver filename — roll it back.
DRIVER_IRQL_NOT_LESS_OR_EQUAL0x000000D1Driver accessed paged memory at improper IRQL. Check the named module in the minidump — update or remove.
Minidump Location
Minidumps stored at C:\Windows\Minidump\ — each BSOD creates a small file with stop code, faulting module, and stack trace. WinDbg command !analyze -v for automated analysis.
Driver Verifier
verifier /standard /all — stress tests all drivers to expose hidden bugs. May trigger an immediate BSOD if a bad driver is present, identifying it. Reset with verifier /reset to disable.

Startup Repair Decision Tree
Matching boot error symptoms to the correct repair tool or command.
"BOOTMGR is missing"
MBR or Volume Boot Record corrupt. From WinRE Command Prompt: bootrec /fixmbr then bootrec /fixboot. Rewrite the master boot record and boot sector without changing the partition table.
"Boot BCD" or 0xc000000f
BCD store is missing or corrupt. Run bootrec /scanos to find Windows installations, then bootrec /rebuildbcd to reconstruct the BCD store from discovered installations.
"winload.exe missing"
Kernel loader file is missing or the path in BCD is incorrect. Run Startup Repair first. If it fails, use bcdedit /enum all to verify the Windows Boot Loader entry points to the correct partition and winload.exe path.
Slide 7 of 19
Boot Repair Commands
Run from WinRE Command Prompt — order matters.
bootrec Commands
bootrec /fixmbr
Rewrites the MBR without changing the partition table. Use when malware or a failed dual-boot corrupts the MBR. Least destructive — run first.
bootrec /fixboot
Writes a new boot sector to the system partition. Use when the boot sector is damaged or overwritten by a non-Windows bootloader.
bootrec /scanos
Scans all disks for Windows installations not currently in the BCD. Shows found installations — add them manually with bcdedit if needed.
bootrec /rebuildbcd
Nuclear option — rebuilds BCD store from all detected installations. Run last when /fixmbr and /fixboot do not resolve boot failures.
bcdedit Commands
bcdedit /enum all
List all boot entries. Verify the Windows Boot Loader entry points to the correct partition and winload.exe path. Use to audit after bootrec repairs.
bcdedit /set {default} safeboot minimal
Force next boot into Safe Mode (minimal). Remove with: bcdedit /deletevalue {default} safeboot. Use "network" for Safe Mode with Networking.
bcdedit /set recoveryenabled yes
Ensures WinRE activates automatically after two consecutive boot failures. Verify this is enabled on all managed machines.
shutdown /r /o /t 0
Restart directly into Advanced Startup Options (WinRE). Command-line equivalent of Shift+Restart — useful when running a remote session.
UEFI / GPT Note
On UEFI systems with GPT disks, bootrec /fixmbr is not applicable. Use bcdboot C:\Windows /s S: /f UEFI to repair the EFI boot files instead. The /s S: parameter specifies the EFI system partition drive letter.

Event Viewer Log Analysis Flow
Systematic approach to correlating log entries for application crash triage.
Event ID 1000 — Application Error
Application crash. Details include the faulting application name, faulting module name, and exception code. The faulting module is the DLL or EXE that caused the crash — this is your primary fix target.
Custom Views
Event Viewer → Create Custom View. Filter by time range, event level (Error, Critical), and event source across multiple logs simultaneously. Save views for reuse. Custom Views are persistent across sessions — create a "Crash Triage" view for rapid response.
Event Subscriptions
Collect events from multiple remote computers into a central Event Viewer. Requires WinRM configured on source computers. Useful for monitoring a group of machines without logging into each one individually.

OS Service Issues
Diagnosing and resolving Windows service failures.
Services.msc Essentials
Startup types: Automatic, Manual, Disabled, Automatic (Delayed Start). The Recovery tab is critical — configure what happens on first, second, and subsequent failures: Restart the Service, Run a Program, or Restart the Computer.
Service Dependencies
Properties → Dependencies tab shows what a service depends on and what depends on it. A failed dependency silently prevents the dependent service from starting. Always trace the dependency chain — the root failure is often several services up from the reported error.
sc.exe Command Reference
sc query wuauserv
Query Windows Update service status — shows STATE (RUNNING/STOPPED), START_TYPE, and PID.
sc start wuauserv                     sc stop wuauserv
Start or stop a service by name. Use sc start for stopped services, sc stop before modifying config.
sc config wuauserv start= auto
Set startup type. Note the space after the =. Valid values: auto, demand, disabled, delayed-auto.
sc failure wuauserv reset= 86400 actions= restart/60000
Configure recovery: restart the service 60 seconds after failure, reset failure count after 1 day (86400 seconds).
Hung Service
If a service is stuck "Stopping," use taskkill /F /IM servicename.exe then restart it. In Safe Mode, only essential Microsoft services load — use it to isolate third-party service conflicts immediately.

Application Crash Troubleshooting Steps
Structured process from first crash report to confirmed resolution.
App Compatibility Mode Path
If the app predates Windows 10, right-click the executable → Properties → Compatibility. Set the target OS version. Also enable "Run as administrator" if the app requires elevated access that was implicit on older systems.
Side-by-Side DLL Errors
Event ID 59 from source SideBySide indicates a manifest or dependency conflict. The app depends on a version of a DLL not present in the WinSxS store. Install the specific Visual C++ or .NET redistributable version listed in the event details.
Crash Dumps for Apps
User-mode crash dumps can be configured per application via HKLM\SOFTWARE\Microsoft\Windows\Windows Error Reporting\LocalDumps. Set DumpFolder, DumpCount, and DumpType to capture full memory dumps for deep analysis with WinDbg or Visual Studio.

Advanced Recovery: SFC, DISM, & System Image
Repairing OS file corruption — always run DISM before SFC.
SFC /scannow
System File Checker scans and repairs protected system files using a cached copy. Run from elevated cmd. Results logged to C:\Windows\Logs\CBS\CBS.log. If SFC reports corrupt files it cannot repair, run DISM /RestoreHealth first — then re-run SFC.
DISM Commands
Repairs the Windows Component Store (WinSxS) — the source SFC uses.
DISM /Online /Cleanup-Image /CheckHealth
DISM /Online /Cleanup-Image /ScanHealth
DISM /Online /Cleanup-Image /RestoreHealth
RestoreHealth downloads replacements from Windows Update.
System Image Recovery
Restores a full bare-metal backup created by Windows Backup (wbAdmin or Backup and Restore). Accessed from WinRE → Advanced Options → System Image Recovery. Replaces the entire OS partition — all changes after the image date are lost. Most destructive option but fully restores a known-good state.
Canonical repair sequence for OS corruption: DISM /RestoreHealth (fixes component store) → SFC /scannow (repairs system files from the now-healthy store) → reboot. Running SFC before DISM means SFC may fail because its own source files are corrupt.
DISM /Online /Cleanup-Image /RestoreHealth /Source:D:\sources\install.wim /LimitAccess
Use a local Windows ISO as the repair source instead of Windows Update — critical when internet is unavailable or corporate environments block WU.
Slide 12 of 19
OS & App Recovery Commands
Boot repair, startup troubleshooting, and cleanup — all from elevated cmd or WinRE.
Boot & Startup
bootrec /fixmbr && bootrec /fixboot
Rewrite MBR then boot sector. Run in sequence from WinRE Command Prompt for BOOTMGR errors.
bootrec /rebuildbcd
Scan all disks and rebuild BCD store. Use when previous two commands do not resolve boot failure.
bcdedit /set {bootmgr} displaybootmenu yes
Force boot menu to display on every startup. Useful for dual-boot systems or ongoing boot issue diagnosis.
Cleanup & File System
chkdsk C: /f /r /x
/x forces dismount before check. Use from WinRE when the OS drive is in use. /f fixes errors, /r recovers bad sectors.
DISM /Online /Cleanup-Image /StartComponentCleanup /ResetBase
Remove ALL superseded update components permanently. Frees significant disk space but prevents uninstalling cleaned updates.
wevtutil cl Application
Clear the Application event log. Use before a clean test to avoid noise from old events. Replace "Application" with "System" or "Security" as needed.
Exam Tip
DISM before SFC for OS corruption. bootrec /fixmbr then /fixboot then /rebuildbcd for boot failures — order matters, least destructive first. If UEFI/GPT, skip bootrec /fixmbr and use bcdboot instead.

Driver Rollback From WinRE
Removing a driver that crashes the OS before the OS can load.
Problem Scenario
A driver update crashes the OS every time it loads. Normal boot and Safe Mode both fail. Device Manager is unreachable. You must remove the driver from WinRE Command Prompt using DISM and pnputil before the OS will boot.
DISM Offline Driver Commands
dism /image:C:\ /get-drivers — lists all third-party drivers installed in the offline OS image at C:\.
pnputil /delete-driver oem42.inf /force — remove the specific driver package by OEM INF filename. Force removes even if in use.
Full Offline Driver Removal Process
dism /image:C:\ /get-drivers /format:table
Step 1: List all third-party (OEM) drivers in the offline Windows image. Note the Published Name (oem##.inf) of the problem driver.
dism /image:C:\ /remove-driver /driver:oem42.inf
Step 2: Remove the driver by Published Name from the offline image. The device will fall back to a generic Windows driver or show as unknown in Device Manager after reboot.
dism /image:C:\ /get-drivers
Step 3: Verify the driver is gone, then reboot. Install the correct driver version from within the running OS once it boots successfully.
Exam Tip
If a question asks how to remove a driver when the OS won't boot, the answer involves booting to WinRE and using DISM /image offline driver commands — NOT Device Manager, which requires the OS to be running.

Common Service Failures
Specific service troubleshooting patterns frequently tested on MD-100.
Print Spooler
Stuck print jobs prevent new jobs from printing. Stop the Spooler service, clear C:\Windows\System32\spool\PRINTERS\, restart the service. If the spooler crashes on every start, a corrupt driver package in the spool directory or registry is the likely cause — delete and reinstall the printer driver.
Windows Update (wuauserv)
Common fix: stop wuauserv and bits services, delete contents of C:\Windows\SoftwareDistribution\Download, restart both services. Run Windows Update Troubleshooter first. Event Viewer → Windows Update Medic Service logs failure codes.
DNS Client (dnscache)
If the DNS Client service stops, name resolution falls back to direct DNS queries without caching. Symptoms: intermittent web access, slow name resolution. Service may be disabled by malware. Verify status with sc query dnscache and set startup to Automatic.
Service Account Issues
A service running as a custom account fails if the account password changed or the account was disabled. Check in services.msc → Properties → Log On tab. Update the password or restore the account, then restart the service. The Event Viewer System log (source: Service Control Manager) logs every failure with reason codes including account-related errors.

Windows File Recovery (winfr)
Command-line tool to recover deleted files without prior backup setup.
Regular Mode (NTFS)
Fastest mode. Best for recently deleted files on NTFS volumes where the MFT entry still exists. Uses the file system metadata to locate deleted file data. Command: winfr C: D:\Recovery /regular /n *.docx
Extensive Mode (NTFS)
Deeper scan using file record segments when the MFT entry is gone. Use when regular mode returns no results. Slower but recovers files deleted longer ago. Command: winfr C: D:\Recovery /extensive
Signature Mode (FAT/exFAT)
Searches disk for known file type signatures (magic bytes). Required for FAT, exFAT, and ReFS volumes where MFT is not available. Specify file types with /n parameter. Slowest but works across all file systems. Command: winfr D: E:\Recovery /extensive /n *.jpg
Critical Rule
The recovery destination MUST be on a different drive than the source. Recovering to the same drive overwrites the deleted file data you are trying to recover. Always use a separate USB drive or second internal drive as the output location.
A user accidentally Shift+Deleted their project folder from a USB drive (FAT32). The Recycle Bin cannot help. Use winfr with extensive mode targeting the USB drive letter, outputting to a different drive, and filtering for the relevant file extensions.

Application Control & Compatibility
AppLocker, Software Restriction Policies, and IE Mode for legacy apps.
AppLocker (Enterprise)
Group Policy-based application whitelisting. Rule collections: Executable, Windows Installer, Script, Packaged Apps. Rules by publisher (signature), path, or hash. Requires Application Identity service running. Audit mode available — logs without blocking.
Software Restriction Policies
Legacy version, works on all editions. Levels: Unrestricted, Basic User, Disallowed. Rule types: Hash, Certificate, Path, Network Zone. Less granular than AppLocker but no edition requirement. Available via Group Policy → Security Settings.
IE Mode in Edge
Legacy apps built for Internet Explorer can run in Microsoft Edge's IE Mode, which renders pages using the Trident engine (IE 11). Configure via Edge Group Policy or the Enterprise Mode Site List. Eliminates the need to keep Internet Explorer installed.
Virtual Application Delivery
App-V (Application Virtualization) packages legacy apps into isolated containers — no installation conflicts. MSIX App Attach (Intune/AVD) delivers packaged apps dynamically. Both approaches resolve compatibility without rewriting the application.
Exam Tip
AppLocker requires Enterprise or Education edition and the Application Identity service must be running. If a question specifies a Windows Pro client, AppLocker is not available — Software Restriction Policies is the only built-in whitelist option.

Module 10 Summary
Core concepts to retain for the MD-100 exam.
File Recovery
Previous Versions = VSS (no setup). File History = continuous backup (must configure). winfr = deleted file recovery (no prior backup needed, output to different drive).
Boot Repair
Startup Repair first. Then bootrec sequence: /fixmbr → /fixboot → /rebuildbcd. BOOTMGR = MBR/VBR. BCD errors = missing boot entries. UEFI/GPT = use bcdboot instead.
OS Repair Commands
Always DISM /RestoreHealth before SFC /scannow for corruption. DISM fixes the component store; SFC uses that store. System Image = last resort, full partition replace.
