File Recovery

Getting data back when it has been deleted or corrupted

📸

Previous Versions (Shadow Copies)

Previous Versions are snapshots created by the Volume Shadow Copy Service (VSS). Right-click any file or folder → Properties → Previous Versions tab. Requires System Protection to be enabled on the volume. VSS snapshots are also created at restore points and before Windows updates — giving you automatic rollback points without extra configuration.

🕐

File History

File History is the user-facing continuous backup feature. It monitors Libraries, Desktop, Contacts, and Favorites by default. Copies are stored to an external drive or network share. Runs on a schedule (default every hour). Configured in Settings → Update & Security → Backup. Users restore files via the "Restore personal files" interface — not the Previous Versions tab.

🗑️

Recycle Bin

Files deleted from local drives go to the Recycle Bin. Files deleted from network shares or via Shift+Delete bypass the Recycle Bin permanently. Each volume has its own Recycle Bin folder ($Recycle.Bin). Size is configurable per drive. A common support call: the user used Shift+Delete — the Recycle Bin cannot help here.

🛠️

Windows File Recovery Tool

A free Microsoft command-line tool from the Store (winfr). Recovers files from NTFS, FAT, exFAT, and ReFS volumes. Three modes: Default (NTFS, recently deleted), Segment (NTFS, using file record segments), and Signature (all file systems, searches by file type signature). Critical: the output destination must be a different drive than the source.

Exam Tip

Know the distinction: Previous Versions = VSS/shadow copies (automatic, on-volume). File History = scheduled backup to external/network (requires setup). Windows File Recovery = command-line recovery of deleted files without prior backup configuration.

Application Troubleshooting

Compatibility, crashes, and dependency failures

🪟

Compatibility Mode

Right-click the executable → Properties → Compatibility tab. Set the OS version the app was designed for (e.g., Windows 7). Can also reduce color depth, disable DPI scaling, and run as Administrator. Applies per executable, per user account.

🧙

Compatibility Troubleshooter

Right-click → "Troubleshoot compatibility." Wizard-driven — tests different compatibility settings automatically and lets you confirm which works. Good first step before manually configuring settings.

🤖

Program Compatibility Assistant

Automatic detection system. Windows detects when an older program is installing or has crashed, then prompts to apply compatibility fixes automatically. This runs silently in the background — the user may see a prompt after a crash.

🔗

Dependencies: .NET and Visual C++

Many apps require specific .NET Framework or Visual C++ Redistributable versions. Missing or corrupt runtimes cause crashes with cryptic error messages. Check Event Viewer Application log for .NET runtime errors (source: .NET Runtime) and install the required version from Microsoft.

App Crash Workflow

Step 1: Open Event Viewer → Windows Logs → Application. Filter for Error level events around the time of the crash.

Step 2: Look at the Event ID and Source. Event ID 1000 (Application Error) or 1026 (.NET Runtime) gives you the faulting module name and exception code.

Step 3: If the faulting module is a C++ runtime DLL (e.g., VCRUNTIME140.DLL), reinstall the Visual C++ redistributable. If it is a .NET assembly, repair or reinstall the required .NET version.

Windows Startup Troubleshooting

Boot failures, BCD corruption, and repair commands

📋

Boot Process Failures

"BOOTMGR is missing" — MBR or Volume Boot Record corrupt. Use bootrec /fixmbr and bootrec /fixboot.

"Boot BCD" or "0xc000000f" — BCD store is missing or corrupt. Use bootrec /rebuildbcd to scan and rebuild.

"winload.exe missing or corrupt" — kernel loader file issue. Startup Repair or manual bcdedit correction needed.

⌨️

bootrec Commands (WinRE)

Run from WinRE Command Prompt. Each command targets a specific failure point:

bootrec /fixmbr
Rewrites the MBR without changing partition table

bootrec /fixboot
Writes a new boot sector to the system partition

bootrec /scanos
Scans all disks for Windows installations

bootrec /rebuildbcd
Rebuilds BCD store from detected installations

Startup Repair and bcdedit

  • Startup Repair: Automated tool in WinRE. Scans and fixes common boot issues automatically. Run this before manual commands.
  • bcdedit /enum all: Lists all entries in the BCD store — verify the Windows Boot Loader entry points to the correct partition and path
  • bcdedit /set recoveryenabled yes: Ensures WinRE automatically activates after two consecutive boot failures
  • WinRE Startup Settings: F8 equivalent. Boots into Safe Mode, Safe Mode with Networking, disable driver signature enforcement, and other diagnostic modes
Exam Tip

Order matters for boot repair: run Startup Repair first. If that fails, use bootrec in order: /fixmbr → /fixboot → /rebuildbcd. Each command targets a progressively deeper layer of the boot structure.

OS Service Issues

Diagnosing and resolving Windows service failures

⚙️

Services.msc Essentials

Services console shows startup type (Automatic, Manual, Disabled, Automatic Delayed Start), current status, and recovery options. Recovery tab is critical: configure what happens on first, second, and subsequent failures — Restart the Service, Run a Program, or Restart the Computer.

🔗

Service Dependencies

In Services.msc, a service's Properties → Dependencies tab shows what it depends on (and what depends on it). A failed dependency silently prevents a service from starting. Always trace the dependency chain — the root failure is often three services up the chain from the reported error.

sc.exe Command Reference

sc query wuauserv — Query Windows Update service status
sc start wuauserv — Start a stopped service
sc stop wuauserv — Stop a running service
sc config wuauserv start= auto — Set startup type (note space after =)
sc failure wuauserv reset= 86400 actions= restart/60000
— Configure recovery: restart after 60s, reset failure count after 1 day

Troubleshooting Hung Services

  • Safe Mode: Only essential Microsoft services load — isolates third-party service conflicts immediately
  • Service accounts: A service running as a custom account fails if the account password changed or the account was disabled — check in services.msc Log On tab
  • Event Viewer System log: Service Control Manager (source: Service Control Manager) logs every service failure with reason codes
  • Process kill: If a service is stuck "Stopping," use Task Manager or taskkill /F /IM servicename.exe then restart it

Advanced Recovery

SFC, DISM, System Image Recovery, and WinRE command-line

🔍

SFC /scannow

System File Checker scans and repairs protected system files using a cached copy. Run from an elevated command prompt. Results logged to C:\Windows\Logs\CBS\CBS.log. If SFC reports corrupt files it cannot repair, run DISM first to repair the component store, then re-run SFC.

🏗️

DISM Commands

Deployment Image Servicing and Management repairs the Windows Component Store (WinSxS) that SFC draws from.

DISM /Online /Cleanup-Image /CheckHealth
DISM /Online /Cleanup-Image /ScanHealth
DISM /Online /Cleanup-Image /RestoreHealth

RestoreHealth downloads replacements from Windows Update. Use /Source to point to mounted ISO if no internet.

💽

System Image Recovery

Restores a full bare-metal backup created by Windows Backup (wbAdmin or the Backup and Restore control panel applet). Accessed from WinRE → Advanced Options → System Image Recovery. Replaces the entire OS partition — all changes after the image date are lost. Most destructive option but fully restores a known-good state.

🔙

Driver Rollback from WinRE

If a driver crashes the OS on every boot, boot to WinRE → Command Prompt. Use dism /image:C:\ /get-drivers to list installed drivers, then pnputil /delete-driver to remove the bad driver. Avoids needing the OS to load to remove the driver causing it not to load.

Exam Tip

The canonical repair sequence for OS corruption: DISM /RestoreHealth (fixes the component store) → SFC /scannow (repairs system files using the now-healthy store) → reboot. Running SFC before DISM means SFC may fail to repair because its source files are also corrupt.

Summary

Module 10 — Core concepts to retain

📁

File Recovery

Previous Versions uses VSS (no setup needed). File History requires prior configuration to a backup drive. Windows File Recovery (winfr) recovers deleted files without prior backup setup.

💻

App Troubleshooting

Compatibility Mode, Troubleshooter, and the automatic Program Compatibility Assistant for legacy apps. Event ID 1000 = application crash. Check .NET and Visual C++ redistributable versions when crashes have cryptic errors.

🚀

Boot Repair

Startup Repair first. Then bootrec /fixmbr → /fixboot → /rebuildbcd in sequence. BOOTMGR errors = MBR/VBR. BCD errors = missing boot entries. winload errors = kernel loader path broken.

🔬

OS Repair Commands

Always run DISM /RestoreHealth before SFC /scannow for corruption. DISM fixes the source; SFC uses that source to repair files. System Image Recovery is the last resort — full partition restore.

Critical Exam Points

  • Previous Versions = shadow copies = VSS — no external drive or setup needed
  • File History = continuous backup — must be configured by the user in advance
  • DISM before SFC — SFC cannot repair what DISM has not yet repaired in the component store
  • bootrec /rebuildbcd scans all disks and offers to add found Windows installs to BCD
  • Service recovery options live in Properties → Recovery tab in services.msc
