Windows Installation Flow
The complete journey from boot media to a configured desktop.
Key Concept
Windows PE (WinPE) is the lightweight OS that runs from the boot media. It loads the installer, lets you partition the disk, and applies the WIM image. Without WinPE, there is no Windows setup.
Slide 3 of 19
Clean Install vs. In-Place Upgrade
Two paths to a running Windows — choose based on scenario constraints.
Use Clean Install When
New hardware, migrating from incompatible OS version (Win7 to Win11), severely corrupted OS, or when maximum security baseline is required. Boot from USB, delete partitions, install fresh.
Use In-Place Upgrade When
Individual workstation needing version bump with existing apps and data preserved. Run setup.exe from media inside Windows. Supported paths: Win7/8.1/10 to Win10, Win10 to Win11.
Slide 4 of 19
Disk Partition Layout
UEFI clean install creates four distinct partitions — each has a required purpose.
EFI System Partition (ESP)
FAT32, 100 MB. Stores the Windows Boot Manager (bootmgfw.efi). UEFI firmware reads this partition to start the OS. Required for UEFI boot — no MBR needed.
Windows OS Partition
NTFS, bulk of disk. Houses \Windows, \Users, \Program Files. Gets drive letter C:. This is where DISM applies the install.wim image during installation.
Recovery Partition
NTFS, 529 MB+. Contains WinRE (Windows Recovery Environment). Powers "Reset this PC", Startup Repair, and System Restore. Must be enabled via reagentc /enable.
Slide 5 of 19
Boot Process: BIOS vs UEFI
Understanding the firmware layer is essential for troubleshooting failed boots.
Legacy BIOS Limitations
MBR supports disks up to 2 TB max, only 4 primary partitions. No Secure Boot — firmware cannot verify bootloader integrity. Being phased out; Windows 11 cannot install on BIOS-only firmware.
UEFI Advantages
GPT supports 128 partitions, disks over 2 TB. Secure Boot blocks unsigned bootloaders. Faster POST. Required for TPM 2.0 integration. Mouse-driven firmware interface. Boot-time network stack (PXE without legacy option ROM).

Installation Methods
Four approaches, each with different prerequisites and use cases.
Clean Install
Wipes partition, installs fresh. Boot from USB/DVD, delete partitions, install. No previous data retained. Best for new hardware, corrupted OS, or cross-version migration. Creates all required UEFI partitions automatically.
In-Place Upgrade
Run setup.exe inside the running OS. Keeps apps, data, settings. Supported: Win7/8.1/10 to Win10, Win10 to Win11. Cannot skip versions. Cannot upgrade Win10 Home directly to Enterprise (edition change is separate process).
Image-Based (WIM/ESD)
Deploy pre-configured image via sysprep + DISM or MDT. Same config deployed to hundreds of machines in minutes. WIM = container format; install.wim = core image file. Must sysprep before capture to reset SID.
Network / PXE Boot
Pre-boot Execution Environment boots from NIC. Requires WDS server on LAN. Machine downloads WinPE boot image, then OS image from server. No physical media needed at all. Enterprise standard for volume deployments.
Upgrade Path Traps
Windows 7 to Win11 = NOT possible via in-place upgrade (clean install required). 32-bit to 64-bit = clean install only. Win10 Home to Enterprise = license/edition change, not in-place upgrade. Skipping versions = not supported.
Slide 9 of 19
Windows as a Service (WaaS)
Microsoft replaced major version releases with continuous delivery and servicing channels.
Feature Updates
Add new capabilities. Windows 10: historically twice per year (20H1, 20H2). Windows 11: annual. Each version supported for 18-36 months. Feature Updates require more planning — IT should test in pilot rings before broad deployment.
Quality Updates (Patch Tuesday)
Security and bug fixes released the second Tuesday of each month. Cumulative — each update replaces all previous updates. No need to install sequentially. Should be applied within 30 days of release per security best practice.
Servicing ChannelUse Case
General Availability ChannelStandard enterprise ring; broad feature updates
Long-Term Servicing Channel (LTSC)Kiosks, ATMs, medical — minimal features, max stability
Windows InsiderPreview / testing only; not for production
LTSC Remember
LTSC does NOT include: Microsoft Store, Microsoft Edge, Cortana, Timeline. Receives security updates for 10 years but no feature updates. Cannot be obtained from a standard Microsoft 365 subscription.
Slide 10 of 19
User State Migration (USMT)
ScanState captures. LoadState restores. The enterprise-scale migration tool.
ScanState — Capture
Runs on source machine. Captures user accounts, documents, app settings, browser favorites, wallpaper. Uses XML rule files (miguser.xml, migapp.xml) to define what to capture. Stores to a network share or local path. Syntax: scanstate \\server\share\user /i:miguser.xml
LoadState — Restore
Runs on destination machine after OS install. Reads capture store and restores user state. XML rules can map old folder paths to new locations. Syntax: loadstate \\server\share\user /i:miguser.xml
Side-by-Side Migration
Old machine stays running during transition. Data migrated to new machine. User productive on old machine until new one is ready. Best for hardware refresh where old machine is not reused.
Wipe-and-Load Migration
Capture data from machine, wipe and reinstall OS, restore data to same machine. Most common enterprise approach for OS upgrades on existing hardware. Requires temporary storage for the captured state.
Exam Trap
Windows Easy Transfer was RETIRED in Windows 10. It does NOT exist on Win10/11 media. If a scenario asks for the right migration tool, the answer is USMT for enterprise scale. OneDrive KFM handles only Desktop, Documents, Pictures by default.

Scaling from 10 to 10,000 machines — choose the right tool for the infrastructure.

Windows Autopilot
Vendor pre-registers hardware IDs in Azure AD. Device arrives, user powers on, signs into Azure AD. Intune applies configuration. Zero touch — no IT hands required. No imaging required.
MDT vs WDS
WDS provides the PXE boot server and image hosting. MDT builds on top of WDS adding task sequences, driver injection, application deployment, and customization. MDT alone requires WDS as its transport layer.
SCCM / MECM
Enterprise full lifecycle management. OSD (OS Deployment), software distribution, patch management, hardware inventory, compliance baselines. Co-management with Intune allows hybrid cloud + on-prem control.
Slide 12 of 19
sysprep & DISM
The two tools that power image capture and deployment at enterprise scale.
sysprep /generalize /oobe /shutdown
The pre-capture sequence. /generalize removes hardware-specific data and resets the SID. /oobe forces the Out-of-Box Experience on next boot. /shutdown powers off so the image can be captured. Every cloned machine needs a unique SID or domain authentication breaks.
DISM /Apply-Image
Deploys WIM image to target partition. Run from WinPE: DISM /Apply-Image /ImageFile:install.wim /Index:3 /ApplyDir:C:\. Index number selects the edition (1=Home, 2=Pro, 3=Enterprise). Check with /Get-ImageInfo first.
DISM /Online /Enable-Feature
Add Windows features to running OS: DISM /Online /Enable-Feature /FeatureName:NetFx3 /All. Enables .NET 3.5 required by many legacy line-of-business applications. /All enables parent dependencies automatically.
SID Warning
Cloning a machine without sysprep creates duplicate SIDs. On a domain, this causes: authentication failures, GPO targeting errors, WSUS identification conflicts, and Windows Activation issues. Always sysprep before capture.

OOBE & Initial Setup
Out-of-Box Experience — the final phase that creates the first user account.
Home Edition OOBE
Requires internet connection and a Microsoft Account. Cannot create a local account via the standard flow — requires workaround (disconnect network, use "fake" email to trigger local option, or use OOBE\BypassNRO). Local-only setup is deliberately discouraged by Microsoft.
Pro Edition OOBE
Offers "Set up for an organization" path. Can join Azure AD or Active Directory domain during setup. Can skip Microsoft Account and create a local account. Offline setup supported. Most flexible for IT-controlled deployments.
Autopilot OOBE
Device detects it is Autopilot-registered and skips standard OOBE. Applies Autopilot deployment profile, enrolls in Intune, downloads assigned apps and policies — all automatically during setup. User only sees a branded login screen.

Region and keyboard — First OOBE screens regardless of edition
2
Network connection — Connect to Wi-Fi or skip (Pro allows skip)
3

5
Cortana / OneDrive setup — Consumer features; suppressed in enterprise Autopilot profiles

Windows Activation
Three activation methods — each suited to a different deployment model.
KMS (Key Management Service)
On-premises activation server. Machines activate against KMS every 180 days. Requires 25+ activations to function (Windows client). Uses Generic Volume License Key (GVLK). Most common in large enterprise environments without cloud connectivity.
MAK (Multiple Activation Key)
Single key with a fixed activation count (like 100 activations). Each activation uses one count against Microsoft's servers. Use for small deployments, isolated labs, or machines without domain connectivity. Count cannot be refunded for reinstalls without calling Microsoft.
Digital License (OEM)
Activation tied to hardware (motherboard) via digital entitlement stored in Microsoft's servers. No product key visible. Windows reinstalls activate automatically when connected to internet. OEM licenses are not transferable to different hardware.
Activation Commands
slmgr /xpr — show activation expiry date • slmgr /ato — force activation now • slmgr /dli — display license info • slmgr /upk — uninstall current product key (before rekey)

Knowledge Check
Three exam-style scenarios covering installation, deployment, and migration.
Q1: Deployment Tool
A healthcare org deploys 400 laptops. No on-prem servers. Uses Intune and Azure AD. Users should self-provision on first power-on. Which tool?

A) WDS with PXE • B) MDT task sequences • C) Windows Autopilot • D) USMT

Answer: C) Windows Autopilot — Cloud-native, zero-touch, requires only Azure AD and Intune. No on-prem infra needed.
Q2: USMT Scenario
Migrating 50 users to new hardware. Data is in custom folder locations not under Documents. Which migration tool?

A) OneDrive KFM • B) Windows Easy Transfer • C) USMT with XML rules • D) Robocopy

Answer: C) USMT with custom XML — KFM only handles 3 default folders. Easy Transfer is retired. USMT XML handles any path.
Q3: Upgrade Block
A tech wants to upgrade Windows 10 Home to Windows 10 Enterprise via in-place upgrade. Will it work?

A) Yes, any edition to any edition • B) Yes, but only same architecture • C) No, edition change is not an in-place upgrade • D) Yes, if TPM 2.0 is present

Answer: C) — Home-to-Enterprise requires a license change (VLSC/MAK), not an in-place OS upgrade.
