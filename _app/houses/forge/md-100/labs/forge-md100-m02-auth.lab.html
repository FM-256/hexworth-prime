Task 3: UAC Configuration

Drag each slider to the appropriate UAC notification level for the described user scenario. Levels: Always Notify, Notify for app changes only (default), Notify without dimming desktop, Never notify.

User A: Standard End User
Regular office worker who should not be able to install software without IT approval. Must be warned before any app makes system changes.
Notify for app changes (Default)
User B: Developer/Power User
Developer who frequently runs scripts and installs dev tools. UAC prompts slow them down, but complete disabling poses security risk. Compromise solution needed.
Notify for app changes (Default)
User C: Kiosk Machine
Public-facing kiosk running a single locked-down app. No admin activities will ever occur. Prompts would confuse users and disrupt operation.
Notify for app changes (Default)
User D: Local Administrator in High-Security Environment
IT admin account in a financial institution. Must be notified for ALL changes — including Windows-signed apps. Highest security posture required.
Notify for app changes (Default)

Task 4: Group Membership

For each user below, select which built-in local group they should be added to based on their required access level.

Alice — Helpdesk Technician
Alice needs to install software, manage local user accounts, and change system settings — but the organization doesn't want her to have unrestricted domain admin access.
Bob — Remote Worker
Bob works from home and needs to RDP into his office workstation. He doesn't need admin rights — just the ability to establish a remote session.
Carol — Backup Administrator
Carol manages nightly backups using Windows Server Backup. She needs to read and write files across all NTFS permissions — but should not be able to change security settings.
Dave — Temporary Contractor
Dave needs extremely limited access for one day. He should not be able to save files locally or access any system settings. Lowest possible privilege.

Task 5: Azure AD Join Scenarios

For each device and user situation, determine the correct Azure AD registration method: Azure AD Join (cloud-only, replaces on-prem domain join), Azure AD Register (BYOD, keeps existing identity), or Hybrid Azure AD Join (both on-prem AD and Azure AD).

Scenario 5A
Company laptop, cloud-first org. No on-premises AD exists. Device will be managed by Microsoft Intune. Employee signs in with work Microsoft 365 credentials.
Scenario 5B
Employee's personal iPhone. They want access to corporate email and SharePoint but IT doesn't want to manage the device at OS level — just the app data.
Scenario 5C
Large enterprise with existing on-prem Active Directory and Group Policy infrastructure. Moving to Microsoft 365 but must maintain GPO-based management and on-prem resource access.
Scenario 5D
New startup — 10 employees, no servers, Azure AD Premium P1 licensed. All workstations are company-owned Windows 11 machines. Must support Conditional Access and Intune policies.
