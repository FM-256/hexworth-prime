Task 4: Windows Update Troubleshooting
Each scenario describes a Windows Update failure. Select the most appropriate first troubleshooting step.

Scenario A - Error 0x80070005

A device consistently fails Windows Update with error 0x80070005 (Access Denied). The device is domain-joined. Updates worked last month before a software deployment.

Scenario B - Stuck at 0%

Update downloads but never starts installing, stuck at 0% for 3 hours. Disk shows 15 GB free. No errors are displayed.

Scenario C - Feature Update Fails Post-Reboot

A feature update installs but the device rolls back every time after restart. The WindowsUpdate.log shows component store corruption.

Task 5: Delivery Optimization Configuration
Select the correct Delivery Optimization download mode for each network topology scenario.
DO Modes: 0 - HTTP only, no peering | 1 - LAN peers only | 2 - LAN + Group (VLAN-based) | 3 - Internet peers (anonymous) | 99 - Simple (no peering, bypasses DO) | 100 - Bypass (use BITS instead)

Branch Office (200 users, single 50 Mbps WAN link, no WSUS)

You need devices to share updates with each other on the local network to reduce WAN traffic. All devices are on the same subnet.

VPN-Connected Remote Workers

Remote employees VPN into HQ. Peer sharing over VPN causes high latency. You want each device to get updates directly from Microsoft without peering.

Cloud-Only Organization (Azure AD, multiple office VLANs)

Devices are spread across multiple VLANs at different sites. You want to enable peering within the same logical group regardless of subnet boundaries, using AAD Group ID.
