Mobile Application Management
Protecting corporate data at the application layer, not the device layer.
MAM Without Enrollment
Protects corporate data inside specific apps without enrolling the device in MDM. Users install Outlook or Teams, sign in with their Azure AD account, and App Protection Policies engage. The org controls corporate data within the app without touching the device. The canonical BYOD answer on the exam.
MAM With Enrollment (MDM+MAM)
Combines full device management with app-level data protection. Device is enrolled in Intune and App Protection Policies add an additional layer on top. Provides the highest control: manage both the device and the data within apps. Best for corporate-owned devices.

App ProtectionYes (APP SDK)Yes (APP + device)

Exam Tip
MAM without enrollment is always the BYOD answer. When employees refuse full MDM, this protects corporate data inside apps without touching personal content.

App Deployment Pipeline
From packaging to active monitoring — the full lifecycle in Intune.
Stage 1: Package
Run IntuneWinAppUtil.exe to wrap your installer. Specify source folder, setup file, and output path. Result is a compressed, encrypted .intunewin file.
Stage 2: Assign
Upload .intunewin to Intune, configure install/uninstall commands, detection rules, and requirements. Set assignment to Required or Available for target groups.
Stage 3 & 4: Deploy + Monitor
Intune Management Extension downloads and runs the installer silently. Detection rules confirm success. Reporting console shows install state per device and user.

App Types in Intune
Five categories — know which to use for every exam scenario.
Store Apps
Apps from Microsoft Store, Apple App Store, or Google Play. Intune links to the store listing. Updates are managed by the store. Simplest type to deploy. Limited to publicly available applications.
Line-of-Business (LOB)
Custom or in-house apps. Upload the installer: .msi for Windows, .ipa for iOS, .apk for Android. Limited to simpler installer formats. Cannot handle .exe or complex dependencies. Use Win32 for those.
Win32 Apps
Most powerful Windows type. Supports .exe, .msi, any complex installer packaged as .intunewin. Supports detection rules, requirements, dependencies, and supersedence. Recommended for most Windows deployments.
Web Links / Web Apps
URL shortcuts placed on device Start menu or home screen. No actual app installed. For SaaS tools like Salesforce, ServiceNow, or internal portals. Can wrap in managed browser for additional data control.
Microsoft 365 Apps
Dedicated type for deploying the Office suite. Uses the Office Deployment Tool under the hood. Select apps (Word, Excel, Teams), update channel, architecture (32/64-bit), languages, and shared activation options.
Exam Tip
If the question involves a .exe installer, the answer is Win32 (IntuneWinAppUtil). LOB only accepts .msi, .appx, .appxbundle, .msix. A raw .exe cannot be uploaded as an LOB app.

App Assignment Types
Required, Available, Uninstall — three deployment intents with very different behaviors.
Assignment TypeBehaviorUser ExperienceTargetsUse Case
RequiredAuto-installs silentlyNo user action neededUser groups + Device groupsOutlook, Teams, security agents
AvailableAppears in Company PortalUser chooses to installUser groups onlyOptional tools: Visio, Project, dept apps
UninstallRemoves app automaticallyApp removed silentlyUser groups + Device groupsRetiring apps, blocking unauthorized SW
Company Portal
Self-service app catalog for end users. Available apps appear here for browsing and on-demand install. Also shows device compliance status, allows device sync, and provides IT support contact info.
Assignment Targeting
Apps assigned to user groups follow the user to any device. Apps assigned to device groups install on the machine regardless of who logs in. Required apps support both target types. Available apps support user groups only.
Exam Tip
Available apps require Company Portal and can only target user groups. If a shared device needs an app with no user interaction, the answer is Required assigned to a device group.

App Protection Policies
Data loss prevention at the application layer — with or without device enrollment.
What Are APPs?
Rules that protect corporate data within managed apps: cut/copy/paste restrictions, save-as controls, PIN requirements, encryption. Works without MDM enrollment via the APP SDK.
Data Protection
Block copy/paste to unmanaged apps. Prevent Save As to personal storage (iCloud, personal OneDrive). Require encryption of org data. Block screen capture on Android.
Access Requirements
Require PIN or biometric to open managed apps. Configure PIN complexity, length, reset timeout. Require corporate credentials for app access. Set grace periods.
Conditional Launch
Define conditions for app launch: min OS version, max threat level, min app version. Actions on failure: warn, block, or wipe corporate data from the app.
Hospital scenario: Doctors use personal iPhones to access patient data. APP policy blocks copy/paste to personal apps, blocks save to iCloud, requires 6-digit PIN, and wipes corporate data if the device is jailbroken. Zero MDM enrollment required.
Exam Tip
APPs work WITHOUT device enrollment. This is their defining feature. The APP SDK must be integrated into the app (all Microsoft first-party apps support this, and many third-party apps do as well).

Win32 App Deployment
The most capable Windows app type. Use it for any .exe or complex installer.
1. Package with IntuneWinAppUtil
Run: IntuneWinAppUtil.exe -c <src> -s setup.exe -o <out>. Creates a compressed, encrypted .intunewin file. Download tool from Microsoft GitHub.
2. Configure & Upload
Upload .intunewin to Intune. Specify install command (e.g., setup.exe /quiet) and uninstall command. Set requirements: OS version, architecture, disk space, RAM.
3. Detection Rules
Mandatory. Options: MSI product code (auto for MSI), file/folder existence, registry key/value, or custom PowerShell detection script. Intune uses these to confirm the app is installed.
Dependencies (up to 5 levels)
Define apps that must install before this one. Example: .NET Framework must install before a .NET-based LOB app. Intune installs dependencies automatically in order.
Supersedence (up to 10 levels)
Replace or update older app versions. Update mode: install new, keep data. Replace mode: uninstall old, install new. Supports version upgrade pipelines.
Return Codes
0 = Success | 1707 = Success | 3010 = Soft reboot | 1641 = Hard reboot | 1618 = Retry. Custom return codes can be mapped to any of these behaviors.

Microsoft 365 Apps Deployment
Dedicated app type in Intune using the Office Deployment Tool behind the scenes.
What to Configure
Select which apps to include (Word, Excel, PowerPoint, Outlook, Teams, OneNote, Access, Publisher). Choose architecture (64-bit recommended). Add language packs. Enable "Remove other Office versions" to uninstall legacy MSI Office.
Update Channels
Current Channel: Latest features as soon as ready — least predictable. Monthly Enterprise: Monthly cadence, predictable schedule. Semi-Annual Enterprise: Features twice per year, maximum stability for controlled environments.

Exam Tip
Shared computer activation: enable when multiple users log into a single device (VDI, kiosks, lab computers). Without it, licensing conflicts occur when multiple users activate Office on the same machine.

App Configuration Policies
Pre-configure app settings before users ever launch them — zero manual setup required.
What They Do
Push settings directly into apps on deployment. Pre-configure Outlook with email server, set Edge homepage, push VPN config for per-app VPN, configure Teams defaults. Users launch the app fully configured. Works via MDM channel (enrolled) or MAM channel (unenrolled).
Managed Devices vs. Managed Apps
Managed devices: Config pushed via MDM channel. Requires enrollment. Managed apps: Config pushed via MAM channel. Works without device enrollment for any app with the Intune App SDK or App Configuration framework support.
1Pre-configure Outlook with Exchange Online or on-premises email account
2Set the default homepage in Edge or another managed browser
3Configure Teams background blur or camera default
4Push per-app VPN configuration for specific LOB apps
5Set custom key-value pairs for any third-party app that supports app config
6Apps must support the Intune App SDK or App Configuration framework to receive settings

Conditional Launch Actions
When conditions are not met: Warn (show message, allow access), Block access (deny until condition met), Wipe data (selective wipe of corporate data from app). Conditions include jailbreak/root detection, OS minimum version, and app version minimums.
Selective Wipe
Removes only corporate data from managed apps on the device. Personal data and personal apps are never affected. Triggered manually via Intune console, or automatically via conditional launch rules (e.g., jailbreak detected). No device wipe required.

Win32 App Advanced Features
Dependencies, supersedence, requirements, and return codes for complex deployments.
Dependencies (max 5 levels)
Prerequisite apps that must install first. Intune resolves the chain automatically. Can be set to auto-install (Intune pushes it) or manual (user must install manually). Use for .NET, VC++ Redistributable, Java Runtime dependencies.
Supersedence (max 10 levels)
Update: Install new version, preserve existing data. Replace: Uninstall old version entirely, install new. Supports multi-version upgrade pipelines. Replaces manual re-deployment workflows.
Requirements Rules
OS architecture (32/64-bit), minimum OS version, disk space, physical memory, CPU core count. Custom requirement scripts: PowerShell scripts that return true/false to conditionally gate installation on any custom logic.

Critical Exam Facts
These are the high-probability test points for Module 4.
1MAM without enrollment = BYOD answer. Protects data on personal devices without MDM. APP SDK required.
2Win32 is the only app type that supports .exe installers. LOB only accepts .msi/.appx/.msix.
3Available apps require Company Portal and can only target user groups, not device groups.
4Required apps auto-install silently and can target both user groups and device groups.
5Detection rules are mandatory for Win32 apps. Options: file, registry, MSI product code, custom script.
6App Protection Policies work without device enrollment. They protect data inside the app, not the device.
7Monthly Enterprise Channel = predictable monthly cadence. Semi-Annual = slowest, most stable.
8Win32 dependencies support up to 5 levels. Supersedence chains support up to 10 levels.
9Selective wipe removes only corporate data from managed apps. Personal data is never touched.
10Shared computer activation is required for multi-user devices (VDI, kiosks) running M365 Apps.

Module 4 Summary
Application management mastery consolidated.
MAM & App Types
MAM without enrollment = BYOD. MAM + MDM = corporate devices with maximum control. App types: Store (simple), LOB (.msi/.appx), Win32 (.intunewin, most capable), Web links (URL), M365 Apps (Office suite).
Deployment & Assignment
Required auto-installs (user + device groups). Available in Company Portal (user groups only). Uninstall removes app. Win32 uses IntuneWinAppUtil, requires detection rules, supports dependencies and supersedence.
App Protection Policies
No enrollment required. Controls copy/paste, save-as, encryption, PIN, screen capture. Conditional launch triggers warn/block/wipe on jailbreak, OS version, or threat level. Selective wipe removes only org data.
M365 Apps & Config Policies
Dedicated app type for Office suite. Update channels: Current (fast), Monthly Enterprise (balanced), Semi-Annual (stable). App Configuration Policies pre-configure apps on delivery. Shared activation for VDI/kiosk.
