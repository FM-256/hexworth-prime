Application Management

Deploying, protecting, and managing apps across your fleet

What This Module Covers

Mobile Application Management (MAM), app types in Intune, deployment assignments (Required, Available, Uninstall), App Protection Policies, Win32 app packaging with IntuneWinAppUtil, Microsoft 365 Apps deployment, and app configuration policies.

Exam Relevance

Application management is a major exam domain. Expect questions on app types, deployment methods, App Protection Policies (especially for BYOD), Win32 app requirements, and the difference between MAM with and without enrollment.

️

Users need their apps. Whether it is Microsoft 365, custom LOB tools, or third-party software, Intune is the delivery mechanism. Getting app deployment right means users are productive from day one. Getting it wrong means helpdesk tickets.

MD-101 — Module 4

Mobile Application Management

Protecting corporate data at the application level

MAM Without Enrollment

Protects corporate data within specific apps without enrolling the device in MDM. The user installs an app (like Outlook or Teams), signs in with their Azure AD account, and App Protection Policies kick in. The organization controls the corporate data inside the app without managing the entire device. Ideal for BYOD.

📡

MAM With Enrollment (MDM+MAM)

Combines full device management (MDM) with application-level protection (MAM). The device is enrolled in Intune, and App Protection Policies add an additional layer of data protection on top of device management. Provides the highest level of control over both the device and the data.

Feature MAM Without Enrollment MAM With Enrollment (MDM+MAM)
Device enrollment Not required Required
Device management No device control Full device control
App protection Yes (APP) Yes (APP + device policies)
Wipe capability Selective wipe (app data only) Full wipe or selective wipe
Best for BYOD / personal devices Corporate-owned devices
Exam Tip

MAM without enrollment is the key BYOD answer. When a question describes a scenario where employees use personal devices and refuse to let IT manage their entire device, MAM without enrollment is always the correct approach. It protects corporate data within apps while leaving personal data completely untouched.

App Types in Intune

Five categories of applications you can deploy

🏫

Store Apps

Apps from the Microsoft Store, Apple App Store, or Google Play. Intune links to the store listing. Updates are managed by the store automatically. Simplest app type to deploy, but limited to publicly available store applications.

Line-of-Business (LOB) Apps

Custom apps developed in-house. Upload the installer directly to Intune: .msi for Windows, .ipa for iOS, .apk for Android. Intune handles distribution. LOB apps are limited to simpler installer formats — for complex installs, use Win32 app type.

Web Links / Web Apps

Shortcuts to web applications. Creates a link on the device (Start menu, home screen) pointing to a URL. No actual app is installed. Useful for SaaS applications like Salesforce, ServiceNow, or internal web portals. Can be wrapped in a managed browser for additional control.

Win32 Apps

The most versatile Windows app type. Supports .exe, .msi, and any complex installer packaged into an .intunewin format using the IntuneWinAppUtil tool. Supports detection rules, requirements, dependencies, and supersedence. The recommended app type for Windows deployments.

Microsoft 365 Apps

  • A dedicated app type in Intune specifically for deploying Microsoft 365 Apps (Word, Excel, PowerPoint, Outlook, etc.)
  • Configure which apps to include, update channel, architecture (32-bit/64-bit), and language
  • Intune handles download, installation, and ongoing updates via the Office CDN
  • Can configure update channel: Current, Monthly Enterprise, Semi-Annual Enterprise
  • Supports shared computer activation for multi-user devices

App Assignment Types

Required, Available, and Uninstall — three deployment intents

Assignment Type Behavior User Experience Use Case
Required Auto-installs on all targeted devices/users Silent install, no user choice Critical business apps (Outlook, Teams, security agents)
Available Shows in Company Portal for optional install User chooses to install Optional tools (Visio, Project, department-specific apps)
Uninstall Removes the app from targeted devices App removed automatically Retiring apps, removing unauthorized software
🛒

Company Portal

The Company Portal app is the self-service app catalog for end users. Available apps appear here. Users can browse, search, and install apps on demand. The Company Portal also shows device compliance status, allows device sync, and provides access to IT support contact information.

Assignment Targeting

Apps can be assigned to user groups (app follows the user) or device groups (app is on the machine regardless of user). Required apps can target both. Available apps can only target user groups (users need Company Portal to browse). Assignment filters refine targeting.

Exam Tip

Available apps require Company Portal and can only be assigned to user groups, not device groups. Required apps can be assigned to both user and device groups. If a question describes a shared device that needs an app without user interaction, the answer is Required assigned to a device group.

App Protection Policies

Data loss prevention at the application level

️

What are APPs?

App Protection Policies (APPs) define rules that protect corporate data within managed apps. They control how data moves in and out of apps: cut/copy/paste restrictions, save-as controls, PIN requirements, encryption, and more. APPs work with or without device enrollment.

Data Protection Settings

Control data movement: block cut/copy/paste to non-managed apps, prevent "Save As" to personal storage, require encryption of org data, block screen capture, and restrict web content to managed browsers. These settings create a container around corporate data within the app.

Access Requirements

Require a PIN or biometric to open managed apps. Configure PIN complexity (numeric, passcode), length, and reset timeout. Require corporate credentials for app access. Set a grace period before access requirements kick in after app launch.

Conditional Launch

Define conditions that must be met for the app to launch: minimum OS version, maximum allowed threat level, minimum app version. If conditions are not met, actions include: warn, block access, or wipe corporate data from the app.

Exam Tip

App Protection Policies work WITHOUT device enrollment. This is their key differentiator. They protect data within apps on BYOD devices where the user has NOT enrolled the device in Intune. The APP SDK must be integrated into the app (all Microsoft apps and many third-party apps support this).

Real-World APP Scenario

A hospital allows doctors to use personal iPhones to access patient records via Outlook and a custom health records app. The hospital needs to ensure:

  • 1Patient data cannot be copied to personal apps (iMessage, personal Notes)
  • 2Files cannot be saved to personal cloud storage (iCloud, personal OneDrive)
  • 3A PIN is required to open work apps
  • 4If the device is jailbroken, corporate data is automatically wiped

Solution: Create an App Protection Policy with cut/copy/paste blocked to unmanaged apps, save-as blocked to personal storage, 6-digit PIN required, and conditional launch set to wipe on jailbreak detection.

Win32 App Deployment

The most capable app type for Windows deployments

Win32 App Packaging Process
  • 1Download IntuneWinAppUtil.exe from Microsoft GitHub
  • 2Place your installer files in a source folder
  • 3Run: IntuneWinAppUtil.exe -c <source_folder> -s <setup.exe> -o <output_folder>
  • 4Tool creates a .intunewin file (compressed, encrypted package)
  • 5Upload .intunewin to Intune > Apps > Windows > Add > Windows app (Win32)
  • 6Configure install/uninstall commands, detection rules, requirements, and assignments

Detection Rules

Define how Intune verifies the app is installed. Options: MSI product code (automatic for MSI), File/folder existence (check for an exe at a path), Registry key/value (check for a specific registry entry), or Custom script (PowerShell detection script).

Requirements & Dependencies

Requirements: OS version, architecture (32/64-bit), disk space, RAM. Dependencies: Other Win32 apps that must be installed first (e.g., .NET Framework before an LOB app). Supersedence: Replace or update an older version of the same app.

Exam Tip

The IntuneWinAppUtil.exe tool is required to package Win32 apps. The output is a .intunewin file. You must also specify install and uninstall commands (e.g., setup.exe /quiet for install, setup.exe /uninstall /quiet for uninstall). Detection rules are mandatory — Intune uses them to verify installation status.

Microsoft 365 Apps Deployment

Deploying the Office suite through Intune

Dedicated App Type

Intune has a dedicated "Microsoft 365 Apps for Windows 10 and later" app type. This uses the Office Deployment Tool (ODT) behind the scenes. Select which apps to include (Word, Excel, PowerPoint, Outlook, Teams, etc.) and exclude apps you do not want.

Update Channels

Current Channel: Latest features as soon as they are ready. Monthly Enterprise: Monthly updates with a predictable schedule. Semi-Annual Enterprise: Feature updates twice a year, for environments needing maximum stability and testing time.

M365 Apps Configuration Options

  • Architecture: 64-bit (recommended) or 32-bit
  • Apps to include: Select from Word, Excel, PowerPoint, Outlook, OneNote, Access, Publisher, Teams, etc.
  • Languages: Add language packs during deployment
  • Update channel: Current, Monthly Enterprise, or Semi-Annual Enterprise
  • Remove other Office versions: Automatically uninstall legacy MSI-based Office
  • Shared computer activation: Enable for multi-user or VDI scenarios
  • Accept EULA: Silently accept on behalf of users
Exam Tip

Know the update channels. Current Channel = latest features immediately. Monthly Enterprise = predictable monthly cadence. Semi-Annual Enterprise = slowest, most stable. The exam may ask which channel is appropriate for a risk-averse organization (Semi-Annual) versus one that wants the latest features (Current).

App Configuration Policies

Pre-configuring app settings before users launch them

️

What are App Configuration Policies?

App Configuration Policies push settings directly into apps, so users do not need to manually configure them. For example, pre-configure Outlook with the user's email server, or set a custom home URL in a managed browser. These work for both managed devices and managed apps.

Managed Devices vs. Managed Apps

Managed devices: Configuration is pushed via the MDM channel to enrolled devices. Managed apps: Configuration is pushed via the MAM channel, works without device enrollment. Choose based on whether the device is enrolled or using MAM-only.

Common App Configuration Scenarios

  • Pre-configure Outlook with the user's email account (Exchange Online or on-premises)
  • Set the default homepage in Edge or a managed browser
  • Configure Microsoft Teams with background blur enabled by default
  • Push VPN per-app configuration for specific line-of-business apps
  • Set custom key-value pairs for third-party apps that support configuration
  • Apps must support the Intune App SDK or App Configuration framework to receive settings

If a question involves deploying a .exe installer through Intune, the answer is Win32 app type (using IntuneWinAppUtil). You cannot upload a raw .exe as an LOB app — LOB only accepts .msi, .appx, .appxbundle, .msix, and .msixbundle. Win32 is the only option for .exe-based installers.

Win32 App Advanced Features

Dependencies, supersedence, and return codes

Dependencies

Define apps that must be installed before this app. For example, a Java-based LOB app depends on Java Runtime. Intune automatically installs dependencies first. Maximum dependency chain depth is 5 levels. Dependencies can be auto-install or manual-install.

Supersedence

Replace or update an older version of an app. Configure a new version to supersede the previous one. Options: Update (install new, keep old data) or Replace (uninstall old, install new). Supersedence chains support up to 10 levels.

Return Codes

Configure how Intune interprets exit codes from the installer. Default codes: 0 = Success, 1707 = Success, 3010 = Soft reboot, 1641 = Hard reboot, 1618 = Retry. Custom return codes can be mapped to Success, Failed, Soft Reboot, Hard Reboot, or Retry behaviors.

Win32 App Requirements Rules

  • OS architecture: 32-bit, 64-bit, or both
  • Minimum OS version: e.g., Windows 10 21H2 or later
  • Disk space required: Minimum free disk space before install
  • Physical memory required: Minimum RAM to proceed
  • Minimum logical processors: CPU core requirements
  • Custom requirement scripts: PowerShell scripts that return true/false for custom conditions

Summary

Module 4 consolidated — application management mastery

MAM

MAM without enrollment = BYOD answer. Protects data within apps without device management. MAM with enrollment = corporate devices with app-level + device-level protection. APP SDK required in apps.

App Types

Store (simplest), LOB (.msi/.appx), Win32 (.intunewin, most capable), Web links (URL shortcuts), M365 Apps (dedicated Office deployment). Use Win32 for .exe installers.

️

App Protection Policies

Control data movement: cut/copy/paste, save-as, printing, screen capture. Require PIN/biometric. Conditional launch (min OS, jailbreak detection). Works without enrollment.

Win32 & M365 Apps

IntuneWinAppUtil packages .exe/.msi to .intunewin. Detection rules verify install. Dependencies chain prerequisites. M365 Apps: select apps, update channel, architecture, shared activation.

Critical Exam Facts

  • MAM without enrollment protects data on personal devices without MDM — the BYOD answer
  • Win32 is the only app type that supports .exe installers (LOB only supports .msi/.appx)
  • Available apps require Company Portal and can only target user groups
  • Required apps auto-install and can target both user and device groups
  • Detection rules are mandatory for Win32 apps: file, registry, MSI code, or custom script
  • App Protection Policies work without device enrollment (APP SDK required)
  • Monthly Enterprise Channel = predictable monthly updates for M365 Apps
  • Win32 app dependencies support up to 5 levels; supersedence supports up to 10
