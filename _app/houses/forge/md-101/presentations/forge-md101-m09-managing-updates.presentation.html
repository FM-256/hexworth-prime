Windows as a Service (WaaS)

The modern servicing model that delivers continuous improvements

The Servicing Model

Windows as a Service replaces the traditional 3-5 year major release cycle with continuous, incremental updates. This keeps devices current with the latest features and security patches.

Key principles:

  • →Continuous updates — no more waiting years for the next version
  • →Smaller, frequent changes — reduces deployment risk vs. massive upgrades
  • →Deployment rings — staged rollout to minimize impact
  • →Servicing channels — control the pace of feature adoption

Servicing Channels

Windows provides different servicing channels for controlling when feature updates are received:

  • →General Availability Channel — standard release for all devices (formerly Semi-Annual Channel)
  • →Long-Term Servicing Channel (LTSC) — for specialized devices (ATMs, medical, factory) that need maximum stability; no feature updates, security only; 5-year support
  • →Windows Insider — pre-release builds for testing; Dev, Beta, and Release Preview rings
EXAM TIP

LTSC is for special-purpose devices only — it does not receive feature updates, only security patches. It is NOT recommended for general-purpose workstations. The exam tests whether you can identify appropriate LTSC use cases (medical devices, kiosks, factory equipment) vs. devices that should be on the General Availability Channel.

Update Types

Feature updates, quality updates, drivers, firmware, and definition updates

Feature Updates
Major version upgrades delivered annually (e.g., 22H2, 23H2). Include new features, capabilities, and sometimes UI changes. Larger download. Can be deferred up to 365 days. 24 months support (Home/Pro) or 36 months (Enterprise/Education).
Quality Updates
Monthly cumulative security and reliability patches released on Patch Tuesday (second Tuesday of each month). Cumulative means each update includes all previous patches. Can be deferred up to 30 days. Critical for security posture.
Driver Updates
Hardware driver updates delivered through Windows Update. Classified as automatic (install without approval) or manual (require explicit approval). Can be managed via WUfB or WSUS policies.
Firmware Updates
UEFI firmware updates delivered through Windows Update on supported hardware. Uses the UEFI Capsule update mechanism. Critical for security (Secure Boot, TPM). Less frequent than other update types.
Definition Updates
Microsoft Defender antivirus signature updates. Released multiple times daily. Not deferrable — these are critical for real-time threat protection. Delivered automatically via Windows Update, WSUS, or SCCM.
Servicing Stack Updates
Updates to the update engine itself. Must be installed before other updates can be applied. Delivered separately to ensure the update mechanism works correctly. Critical prerequisite for quality and feature updates.
EXAM TIP

Quality updates are cumulative — installing the latest monthly update includes all previous patches. Feature updates can be deferred up to 365 days; quality updates can be deferred up to 30 days. Definition updates cannot be deferred. Know these deferral limits for the exam.

Windows Update for Business (WUfB)

Cloud-based update management — the modern approach to patching

WUfB Overview

Windows Update for Business provides policies to control when and how devices receive updates directly from the Windows Update service. No on-premises infrastructure required.

Key capabilities:

  • →Deferral policies — delay feature and quality updates by defined periods
  • →Pause updates — temporarily halt updates for up to 35 days
  • →Update rings — group devices with different deferral settings
  • →Deadline policies — enforce installation by a specific date
  • →Active hours — prevent restarts during business hours

WUfB Configuration in Intune

Configure WUfB policies through the Intune admin center:

  • →Devices > Windows > Update rings for Windows 10 and later
  • →Set feature update deferral (0-365 days)
  • →Set quality update deferral (0-30 days)
  • →Configure automatic reboot behavior and deadlines
  • →Assign to device groups or user groups
EXAM TIP

WUfB is a cloud-native update management solution — it does NOT require WSUS or SCCM. Devices receive updates directly from Microsoft. WUfB policies can be configured via Intune, Group Policy, or MDM CSP. Know the deferral maximums: 365 days for feature updates, 30 days for quality updates. Pause is temporary (up to 35 days) and cannot be extended once activated.

Update Rings

Staged deployment strategy to minimize risk across the organization

🧪
Preview Ring
IT testers and volunteers. 0 days deferral. First to receive updates. ~1-5% of devices. Catches critical issues early.
👥
Pilot Ring
Broad cross-section of users. 5-10 day deferral. Validates across departments. ~10-15% of devices. Tests app compatibility.
🏢
Broad Ring
Majority of organization. 10-15 day deferral. Most issues caught by now. ~70-80% of devices. General production rollout.
🏥
Critical Ring
Mission-critical systems. 15-30 day deferral. Maximum validation. ~5-10%. Highest risk tolerance for delay.

UPDATE RING CONFIGURATION

  • Feature update deferral — number of days to wait after GA release before offering the update
  • Quality update deferral — number of days to wait after Patch Tuesday before offering the update
  • Deadline for feature updates — days after update is offered before forced install and reboot
  • Deadline for quality updates — typically shorter deadline (2-7 days for security patches)
  • Grace period — additional days after deadline before automatic reboot (gives user warning time)
Real-World Update Ring Example
A quality update is released on Patch Tuesday (January 14). The Preview Ring (0 days deferral) receives it immediately. The Pilot Ring (7 days deferral) gets it on January 21. The Broad Ring (14 days deferral) receives it on January 28. The Critical Ring (21 days deferral) gets it on February 4. If a critical issue is found in the Preview ring, IT can pause updates for other rings before they receive the problematic patch.

Windows Server Update Services (WSUS)

On-premises update management for traditional enterprise environments

WSUS Architecture

WSUS is a Windows Server role that acts as a local update repository. It downloads updates from Microsoft Update and distributes them to internal clients, providing granular approval control.

  • →Centralized control — approve/decline updates before deployment
  • →Bandwidth savings — download once, distribute locally to many clients
  • →Computer groups — target different updates to different device groups
  • →Reporting — compliance reports showing update status per computer
  • →Hierarchy — upstream/downstream server architecture for multi-site

WSUS Configuration

Clients connect to WSUS via Group Policy or registry settings:

  • →Specify intranet Microsoft update service location — point clients to WSUS server
  • →Configure Automatic Updates — set schedule for download and install
  • →Enable client-side targeting — auto-assign computers to WSUS groups
  • →GPO path: Computer Config > Admin Templates > Windows Components > Windows Update

Delivery Optimization

Peer-to-peer content distribution to reduce bandwidth consumption

How Delivery Optimization Works

Delivery Optimization (DO) enables devices to share update content with each other via peer-to-peer, reducing the load on internet connections and update servers.

  • →Device downloads update content in pieces from both Microsoft CDN and local peers
  • →Content is verified via hash validation — no security risk from peer sharing
  • →Applies to Windows updates, Microsoft Store apps, and Microsoft 365 Apps
  • →Configurable bandwidth limits to prevent network saturation

DO Download Modes

Control the scope of peer-to-peer sharing:

  • →HTTP only (0) — no peer sharing, download from Microsoft only
  • →LAN (1) — share with peers on the same local subnet (default for domain)
  • →Group (2) — share within a defined group (by AD site or custom group ID)
  • →Internet (3) — share with peers across the internet (default for non-domain)
  • →Bypass (99) — disable DO, use BITS only
EXAM TIP

Delivery Optimization is especially important for WUfB deployments since devices download updates directly from Microsoft. Without DO, every device downloads the full update independently. With DO in LAN or Group mode, the first device on a subnet downloads the update and shares it with peers. Configure via Intune: Devices > Configuration profiles > Delivery Optimization.

Feature Update Policies

Controlling which feature update version devices receive via Intune

Feature Updates for Windows 10 and Later

A separate Intune policy type that targets a specific feature update version. Unlike update rings (which control timing), feature update policies control which version devices install.

  • →Lock devices to a specific Windows version (e.g., Windows 11 23H2)
  • →Prevent devices from upgrading beyond the specified version
  • →Devices on older versions will upgrade to the target version
  • →Quality updates continue to install normally

Rollout Options

Feature update policies include rollout scheduling capabilities:

  • →Make available as soon as possible — immediate deployment
  • →Make available on a specific date — scheduled availability
  • →Make available gradually — phased rollout over a configured number of days
  • →Gradual rollout randomly distributes updates across the configured period
When to Use Feature Update Policies vs. Update Rings
Update rings control when updates install (deferral, deadlines, active hours). Feature update policies control which version devices run. Use both together: a feature update policy targets Windows 11 23H2, while update rings manage the timing of quality updates. If you need to hold devices on a specific version (e.g., for app compatibility testing), use a feature update policy.

Update Compliance & Reporting

Monitoring update deployment status and identifying non-compliant devices

Windows Update for Business Reports

Cloud-based reporting solution that provides visibility into update compliance status across your device fleet.

  • →Quality update status — which devices have the latest patches
  • →Feature update status — version distribution across your organization
  • →Delivery Optimization — bandwidth savings from peer-to-peer sharing
  • →Driver update status — track driver update deployment
  • →Requires Azure Log Analytics workspace

Intune Update Reports

Built-in reporting within the Intune admin center:

  • →Per-ring compliance — see how each update ring is progressing
  • →Per-device status — identify individual devices with update failures
  • →Update failure reasons — error codes and remediation guidance
  • →Feature update readiness — compatibility assessment before deployment
EXAM TIP

Windows Update for Business reports require diagnostic data to be set to Required (Basic) or Optional (Full) level. Devices must also have a valid Azure AD identity. The reports provide a dashboard view of update compliance but do NOT control update deployment — that is the role of update rings and feature update policies.

Troubleshooting Windows Updates

Common update failures, diagnostic tools, and remediation strategies

🔧

Windows Update Troubleshooter

Built-in automated troubleshooter that diagnoses and fixes common update issues. Resets Windows Update components, clears the update cache, and restarts required services. Access via Settings > Troubleshoot > Other troubleshooters.

📄

Update Logs

Key log files for diagnosing update failures: WindowsUpdate.log (generated via Get-WindowsUpdateLog PowerShell), CBS.log (component-based servicing), and DISM.log (image servicing operations).

🛠️

Manual Remediation

When automated tools fail: stop WU services, rename SoftwareDistribution and catroot2 folders, restart services. Use DISM /Online /Cleanup-Image /RestoreHealth to repair the component store. Last resort: in-place upgrade to repair the OS.

COMMON UPDATE ERROR CODES

  • 0x80073712 — damaged or missing component store file; run DISM /RestoreHealth
  • 0x800F0922 — insufficient System Reserved partition space or VPN connectivity issue during update
  • 0x80070002 — file not found; corrupt update cache; clear SoftwareDistribution folder
  • 0x80240034 — update not applicable to device; check architecture and edition compatibility
  • 0xC1900208 — incompatible application blocking feature update; identify and remove/update the app

  • Windows as a Service delivers continuous updates through feature updates (annual) and quality updates (monthly)

  • WUfB policies configured via Intune control deferral, deadlines, active hours, and pause
