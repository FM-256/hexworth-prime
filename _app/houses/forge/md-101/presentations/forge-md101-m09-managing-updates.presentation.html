Windows as a Service (WaaS)
Continuous delivery replaces the 3-5 year major release cycle.
The WaaS Model
Windows 10 introduced "Windows as a Service" in 2015. Instead of waiting years between versions, Microsoft delivers incremental improvements continuously. Two types of updates: feature updates (new capabilities, released annually) and quality updates (cumulative security and reliability patches, monthly). Devices stay current without major migrations.
Core WaaS Principles
Continuous delivery of features and patches. Cumulative updates simplify patch management (install the latest = have all previous). Deployment rings stagger rollout to reduce risk. Servicing channels control the pace of feature adoption by device role. Telemetry enables data-driven deployment planning.
Feature Updates
Released annually (e.g., 22H2, 23H2, 24H2). Include new OS capabilities, UI changes, and sometimes architecture changes. Larger download than quality updates. Can be deferred up to 365 days on Enterprise/Education. Supported for 24 months on Home/Pro, 36 months on Enterprise/Education.
Quality Updates
Released on Patch Tuesday (second Tuesday each month). Cumulative — includes all previous patches. Security fixes, reliability improvements, and out-of-band emergency patches between Patch Tuesdays. Can be deferred up to 30 days. Critical for maintaining security posture.
Definition Updates
Microsoft Defender antivirus signature updates. Released multiple times daily. Not deferrable. Critical for real-time threat protection. Delivered via Windows Update, WSUS, SCCM, or Intune. Even devices in restricted update rings must receive definition updates without delay.

Servicing Channels
Control when a device receives feature updates based on its role and stability requirements.
General Availability Channel
The standard channel for production devices. Formerly called the Semi-Annual Channel (SAC). Receives both feature and quality updates. Organizations use WUfB or WSUS to control when the feature update is applied using deferral policies. Default for all Windows 10/11 devices unless configured otherwise.
Long-Term Servicing Channel (LTSC)
For specialized, stability-critical devices. Receives no feature updates — only cumulative security patches for the life of the release. Support lifecycle: 5 years mainstream + 5 years extended. LTSC versions: Windows 10 2019, 2021; Windows 11 2024. NOT recommended for general-purpose workstations or laptops.
Windows Insider Program
Pre-release builds for testing purposes only. Three rings: Dev (newest features, unstable), Beta (more stable, still pre-release), Release Preview (close to GA quality, used to validate updates). Devices on Insider should be test machines only. Configuring via Intune is possible but not recommended for production fleets.

Windows Server Update Services (WSUS)
On-premises update management — download once to the server, distribute to all clients.
WSUS Architecture
WSUS is a Windows Server role that downloads updates from Microsoft Update to a local server, then distributes them to clients. Clients are pointed to the WSUS server via GPO (WUAU settings) or registry. Reduces internet bandwidth by downloading each update once regardless of how many clients need it. Requires SQL Server Express or full SQL for the database.
WSUS Administration
Updates must be approved in the WSUS console before clients can download them. Approval can be by product (Windows 11), classification (Security Updates, Critical Updates, Feature Packs), and computer group. Automatic approval rules can be configured for specific classifications like Security Updates. Declined updates are suppressed for all clients.
Computer Groups
WSUS organizes clients into computer groups (analogous to deployment rings). Approve updates to the Pilot group first, validate, then approve to the Broad group. Client-side targeting (set by GPO) or server-side targeting allows automated group assignment. Default groups: All Computers, Unassigned Computers.
WSUS Limitations
Requires on-premises Windows Server infrastructure. Does not manage Microsoft Store apps, driver updates (configurable), or Defender definitions natively. Poor visibility into client compliance without additional reporting tools. Does not integrate directly with Intune for cloud-managed devices. Being phased out in favor of WUfB for modern environments.
WSUS vs. WUfB
WSUS requires on-prem server infrastructure, admin approval of each update. WUfB requires only Intune or GPO configuration, manages deferral periods without per-update approval. Organizations with existing WSUS can run both simultaneously. Microsoft is investing in WUfB as the modern replacement; WSUS remains on the exam for legacy and hybrid scenarios.

Windows Update for Business (WUfB)
Cloud-native update management — deferral policies without an on-premises server.
What WUfB Does
Windows Update for Business allows IT to control the timing of feature and quality update installation using deferral policies. Policies are configured via Intune update rings, Group Policy (GPO), or MDM CSP. The device still downloads updates directly from Microsoft or peers (via Delivery Optimization) — WUfB controls WHEN updates apply, not where they come from.
Deferral Periods
Feature updates: can be deferred 0-365 days. Quality updates: can be deferred 0-30 days. Definition updates: cannot be deferred (always install immediately). Driver updates: can be excluded entirely from Windows Update via policy. Pause periods: up to 35 days for both feature and quality updates.
Configuration Methods
Intune Update Rings (recommended for cloud-managed). Group Policy: Computer Configuration > Administrative Templates > Windows Components > Windows Update. MDM CSP: Update/ namespace policies. All three methods use the same underlying Windows policies; Intune is the modern, cloud-native approach.
WUfB Deadlines
In addition to deferral, you can configure installation deadlines. If a device has not installed an update by the deadline, Windows will automatically schedule and force the installation. Quality deadline: typically 2-7 days after deferral period ends. Feature deadline: typically 2-14 days. Grace period allows users to delay the restart after installation.
Active Hours
Active hours prevent devices from restarting for updates during user work hours. Default: 8 AM - 5 PM. Configurable via policy to match organizational work schedules. "Intelligent active hours" learns from user behavior and sets active hours automatically. Updates install and restart occur only outside active hours.

WUfB Ring Deployment Model
Staged rollout that limits blast radius — preview rings catch issues before they reach the full fleet.
Ring Strategy Rationale
The preview ring's small population catches application compatibility issues and driver conflicts before they affect most users. Only after the preview ring runs without reported issues does IT release to the broad ring. Critical systems get maximum deferral because unplanned downtime on those devices has outsized business impact.
Intune Update Ring Settings
Each Intune update ring policy controls: feature update deferral, quality update deferral, deadline, restart grace period, auto-restart notification, active hours. Assign each ring to an Azure AD device group. Three rings (pilot, broad, critical) with different deferral values covers most enterprise scenarios.
Feature Update Policies
Separate from update rings in Intune. Feature Update deployment policies allow you to pin devices to a specific Windows version (e.g., hold all devices on Windows 11 23H2 until you're ready for 24H2). Rings control deferral timing; feature update policies control the specific version being deployed.

WSUS vs. WUfB vs. Intune
Three tools for managing update rollout — each with distinct infrastructure and control models.
Exam rule: if the scenario says "on-premises" with domain-joined clients, consider WSUS or WUfB via GPO. If the scenario says "Intune-managed" or "Azure AD joined," the answer is Intune Update Rings. These tools are not mutually exclusive — co-managed devices can use both.

Update Types Reference
All six update classifications and how they behave under WUfB deferral policies.
Feature Updates
Annual release. New OS capabilities and sometimes UI changes. Example: Windows 11 22H2 to 23H2. Download size: 2-5 GB. Max deferral: 365 days (Enterprise/Education). Support: 24 months (Home/Pro), 36 months (Enterprise/Education).
Quality Updates
Monthly (Patch Tuesday). Cumulative — install latest = have all previous. Content: security fixes, reliability improvements. Max deferral: 30 days. Out-of-band emergency patches may also be released between Patch Tuesdays for critical vulnerabilities.
Driver Updates
Hardware driver updates via Windows Update. Can be excluded via WUfB policy ("Do not include drivers with Windows Updates"). Enterprise environments often manage drivers separately through SCCM or MDT to control tested driver versions.
Firmware Updates
UEFI firmware updates on supported hardware via Windows Update. Uses UEFI Capsule mechanism. Less frequent. Critical for Secure Boot and TPM firmware. Can be excluded via policy. Always test firmware updates on a small group first due to brick risk on incompatible hardware.
Definition Updates
Microsoft Defender AV signatures. Released multiple times daily. Cannot be deferred. Must reach devices regardless of ring policy. Can be distributed via WSUS to reduce internet bandwidth. SCCM can also distribute definitions via software distribution if WSUS bandwidth is a concern.
Servicing Stack Updates
Updates to the Windows Update engine itself. Must be installed before other updates can be applied. Windows delivers SSUs automatically, often bundled with quality updates in recent releases. Critical prerequisite that cannot be blocked; attempting to skip an SSU breaks the update pipeline.

Update Compliance Monitoring
Visibility into update deployment status across the entire managed fleet.
Intune Update Reports
Intune provides built-in Windows Update reports under Reports > Windows Updates. Shows per-device update status, pending updates, and failed installations. The "Windows Update compliance" workbook (requires Azure Monitor) gives fleet-level views. Per-device diagnostics accessible via the device page in Intune.
Windows Update for Business Reports
Log Analytics-based reporting solution for WUfB. Requires devices to be configured to send Windows diagnostic data to Microsoft. Provides dashboards showing update deployment progress, device update health, and compliance across rings. Available in Azure portal as a Workbook.
SCCM Software Update Reports
For SCCM-managed devices, use the built-in software updates compliance reports. Filter by software update group, computer collection, or individual device. Reports show installation state: Required, Installed, Failed, Unknown. Critical for co-managed environments where SCCM still controls the Windows Updates workload.

WSUS Maintenance and Health
A neglected WSUS server is worse than no WSUS server — maintenance is non-negotiable.
WSUS Database Maintenance
The WSUS database (SUSDB) requires regular maintenance: re-indexing, statistics updates, and obsolete update cleanup. Use the WSUS Server Cleanup Wizard monthly (or the WID database maintenance scripts). Unneeded updates consume significant disk space. WSUS DB corruption causes sync failures and client connection issues.
IIS Application Pool Reset
WSUS runs as an IIS web application. The WsusPool application pool must be configured with sufficient memory (minimum 4 GB private memory limit for large deployments). Clients that cannot connect to WSUS often have IIS application pool crashes or memory limit exhaustion as the root cause. Monitor in IIS Manager.
Disk Space Management
WSUS downloads update content to the local server. For a typical enterprise environment, the download folder can grow to 100+ GB. Decline superseded updates and run cleanup monthly. The Cleanup Wizard removes: expired updates, superseded updates, unnecessary update files. Configure automatic approval rules to limit product/classification scope.
GPO Configuration for Clients
Point clients to WSUS via GPO: Computer Configuration > Admin Templates > Windows Components > Windows Update. Set "Specify intranet Microsoft update service location" to the WSUS URL. Set "Configure Automatic Updates" to the desired installation behavior. Set "Specify intranet statistics server" (can be same as WSUS).
WSUS Sync Schedule
WSUS syncs metadata from Microsoft Update on a schedule. Default sync is daily. Configure product and classification subscriptions to limit what WSUS downloads. Synchronize only Windows 10/11 + Office products + Security/Critical classifications to avoid downloading drivers and optional updates that inflate disk usage.

Feature Update Policies in Intune
Pin devices to specific Windows versions and control the exact timing of major upgrades.
Feature Update Deployment Policy
In Intune: Devices > Windows Updates > Feature updates for Windows 10 and later. Create a policy targeting a specific Windows version (e.g., Windows 11 24H2). Assign to device groups. Devices matching the policy will upgrade to the specified version on the deployment schedule. Separate from update rings, which only control deferral timing.
Safeguard Holds
Microsoft may place a safeguard hold on a device, blocking it from receiving a specific feature update due to a known compatibility issue (specific hardware or software). Displayed in the Intune update status as "safeguard hold." Organizations can override safeguard holds via the "Allow optional content" setting, but this is not recommended unless the issue is understood.
Gradual Rollout
When a new Windows version becomes available, Microsoft uses a gradual rollout mechanism even for devices with no deferral policy. Early adopters receive the update first; Microsoft monitors telemetry and expands availability as confidence grows. This is separate from organizational ring policies — it is a Microsoft-side throttle on availability.
Monitoring Feature Update Progress
Track per-device status in Intune: Devices > Monitor > Feature update failures. Common states: Offered (device has been offered the update), In Progress, Success, Error. Error details include Windows Setup error codes. For broad ring failures, check the Top errors by feature update report to identify fleet-wide blockers.
Rollback
Windows preserves the previous OS installation for 10 days after a feature update. Users can roll back via Settings > Recovery > Go back. After 10 days, the previous installation is automatically deleted to reclaim disk space. IT can trigger rollback remotely for a device via Intune if a feature update causes critical issues post-deployment.

SCCM Software Update Management
Enterprise patch orchestration for on-premises and co-managed environments.
Software Update Point (SUP)
SCCM site system role that integrates with WSUS. The SUP syncs updates from WSUS and makes them available in the SCCM console. All SCCM software update management flows through a SUP. Multiple SUPs can be configured for redundancy and branch office load distribution.
Software Update Groups
Logical groupings of updates in SCCM. Create monthly groups (e.g., "June 2025 Security Updates") or by product. Deploy update groups to device collections. SCCM tracks which devices in the collection have/need each update in the group. Required vs. Available deployment types control whether installation is forced or optional.
Automatic Deployment Rules (ADR)
Automate monthly patching without manual approval. Configure an ADR to automatically download and deploy updates matching criteria (Classification = Security Updates, Product = Windows 11) to a device collection on a schedule. ADRs run after Patch Tuesday sync to automate the approval and deployment pipeline.
Phased Deployments
SCCM phased deployments mirror the ring concept. Phase 1 (pilot collection): deploy to 50 devices, monitor for 7 days. Phase 2 (broad): auto-advance to full collection if success criteria met. Configurable success criteria: percentage of devices successfully installed, no error threshold exceeded. Built-in ring logic without manual steps.
Co-Management Update Workload
In co-managed environments, the Windows Update workload determines whether SCCM or Intune controls update policy for a device. Set to SCCM: existing SCCM ADRs and SUG deployments continue to govern updates. Set to Intune: Intune update rings take over. During transition, move the pilot collection to Intune first.

Delivery Optimization
Reduce WAN bandwidth consumption for Windows Update content by enabling peer-to-peer caching.
How Delivery Optimization Works
When Device A downloads Windows Update content, it caches it locally. Device B on the same LAN (or DO group) queries the DO service for peers that have the content. Device B downloads from Device A at LAN speed instead of from Microsoft's CDN. The DO service tracks which devices have which content without exposing private data.
Download Mode Settings
0 = HTTP only (no peers). 1 = LAN peers only. 2 = Group peers (DO GroupID match). 3 = Internet peers (public DO network). 99 = Bypass DO entirely (use BITS). 100 = Simple download (no peer selection). Mode 1 or Mode 2 is appropriate for enterprise networks.
Connected Cache
Deploy a Microsoft Connected Cache (MCC) server on-premises. The cache intercepts DO requests and serves content from local NTFS storage. SCCM distribution points can function as MCC servers. Provides LAN-speed delivery from a dedicated server without peer-to-peer complexity. Critical for branch offices on slow WAN links.
Exam scenario: branch office with 200 PCs on a 20 Mbps WAN link. Each PC downloads a 600 MB quality update. Without DO, that is 120 GB of WAN traffic. With DO Mode 1, only one or a few devices download from the internet; the rest pull from local peers. WAN consumption drops by 95%+.

Pause, Uninstall, and Recovery
Emergency controls for when an update causes issues across the fleet.
Pause Updates
Temporarily stop receiving both feature and quality updates for up to 35 days. Configured via Intune update ring (Pause quality updates, Pause feature updates) or GPO. After 35 days, the pause expires automatically and updates resume. The pause can be reset from Intune or removed from GPO before 35 days if resolved sooner.
Uninstall Quality Update
Windows keeps the previous quality update available for uninstall for a configurable period (default 30 days, configurable 10-60 days). Intune: device action "Uninstall" for update. WUfB GPO: configure maximum days to keep a quality update for rollback. After the window closes, uninstall is no longer possible without manual intervention.
Uninstall Feature Update
Windows preserves the previous OS for 10 days after a feature update. Roll back via Settings > System > Recovery > Go back. IT can trigger remotely via Intune device action. After 10 days, the previous OS partition is reclaimed. Feature update rollback does not affect user files but does revert app compatibility changes.
SCCM Software Updates Pause
In SCCM, remove the deployment from the affected device collection or change the deployment deadline to a future date to pause distribution. Remove the device from the software update group assignment. SCCM does not have a native "pause" button; stopping a deployment is achieved by modifying collection membership or deployment settings.
Safe Orchestration Approach
When a problematic update is identified: 1) Immediately pause the update ring in Intune for all rings. 2) Identify affected device scope in Intune reports. 3) Test the fix (workaround or next update) on the preview ring. 4) Resume rings incrementally after validation. 5) Document the incident in the change management system.

Exam Scenario Practice
High-frequency scenario types from the MD-101 update management domain.
1Scenario: IT needs to prevent the latest feature update from installing on production devices for 6 months while a compatibility test is run. Answer: Configure a WUfB feature update deferral of 180 days via Intune update ring or GPO.
2Scenario: A monthly quality update is causing BSODs on a specific hardware model. IT needs to stop it immediately. Answer: Pause quality updates in the Intune update ring (up to 35 days) and remove approval in WSUS for on-prem clients.
3Scenario: Branch office WAN links are saturated every Patch Tuesday. 150 devices, 20 Mbps WAN. Answer: Enable Delivery Optimization Mode 1 (LAN peers) and/or deploy a Connected Cache server at the branch.
4Scenario: Devices running medical imaging software must never receive feature updates automatically. Answer: Assign devices to LTSC channel, OR configure maximum feature update deferral (365 days) and use a Feature Update deployment policy to pin them to the current version.
5Scenario: Compliance report shows 15% of devices have not installed the current quality update 45 days after release. Answer: Check Intune update compliance for failed states. Likely causes: deadline not configured, devices offline during active hours window, or network connectivity issues. Configure a deadline to force installation.
6Scenario: Antivirus signatures are being deferred by the WUfB ring policy. Answer: Definition updates cannot be deferred by WUfB. If signatures are not updating, the cause is something else: network connectivity, WSUS classification not syncing definitions, or Defender policy misconfiguration.

Update Compliance Deep Dive
Interpreting compliance data and acting on failure states in Intune.
Intune Device States
Pending Install: update offered but not yet installed. Installed: update applied successfully. Failed: Windows Update returned an error code during install or download. Not applicable: update does not apply to this device (wrong OS version or edition). Unknown: device has not checked in recently; check last sync date.
Common Failure Codes
0x80070020: file in use, reboot needed. 0x80073712: component store corruption (run DISM /restorehealth). 0x800705B4: timeout (slow network or large update). 0x8024402C: WSUS connectivity failure. 0x80240017: update not applicable. Check Windows Update logs for full context.
Windows Update Log
Windows 10/11 no longer uses the traditional WindowsUpdate.log directly. Run Get-WindowsUpdateLog PowerShell cmdlet to decode and generate a readable log file. The resulting log is placed on the Desktop. Filter for "Agent" and "Handler" entries to trace specific update failures.
WUfB Reports Workbook
The Windows Update for Business Reports workbook in Azure Monitor provides fleet-level compliance views. Prerequisite: devices configured to send Windows diagnostic data (Level 1 / Required minimum). Data latency: 24-72 hours. Shows update readiness, active issues, safeguard holds, and per-ring deployment progress across all enrolled devices.
Intune Built-in Reports
Intune Reports > Windows Updates includes: Per-device status for update rings, Feature update failures, Windows Expedited update status. Device diagnostics (Collect diagnostics button) captures WU logs, event logs, and MDM traces without requiring RDP or on-site access. Critical for remote troubleshooting of persistent update failures.

Module 9 Summary
Core concepts for the MD-101 update management domain.
WaaS & Channels
General Availability Channel for all production devices. LTSC for specialized hardware only — no feature updates, security-only, 5+5 year support. Insider Preview for testing only. Feature updates annually; quality updates monthly on Patch Tuesday.
WUfB Rings
Preview ring (0 deferral, 2-5% fleet), Broad ring (90-120d feature / 7-14d quality, 85-90% fleet), Critical ring (365d feature / 30d quality, 5-10% fleet). Maximum deferrals: Feature = 365d, Quality = 30d, Definitions = 0d (non-deferrable).
Tools Comparison
WSUS = on-prem server, manual approval, bandwidth reduction. WUfB via GPO = no server, deferral-based, on-prem AD. Intune Update Rings = cloud-native, Azure AD joined devices. SCCM = enterprise, ADRs, phased deployments, SUP + SUG. Delivery Optimization reduces WAN bandwidth via peer caching (Mode 1 = LAN).
Critical Exam Rules
Definition updates cannot be deferred under any WUfB configuration. Feature update max deferral is 365 days. Quality update max deferral is 30 days. LTSC is NOT appropriate for general-purpose workstations. Pause updates max duration is 35 days. Feature update rollback window is 10 days. Quality update uninstall window is configurable (default 30 days). WSUS requires GPO options 66/67 equivalent (intranet update service location).
