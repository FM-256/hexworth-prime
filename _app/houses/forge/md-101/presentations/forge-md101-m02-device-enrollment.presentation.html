MD-101 — Module 2

Device Enrollment

Getting devices into your management ecosystem

📱

What This Module Covers

Azure AD device identity types, Intune enrollment methods, Device Enrollment Manager accounts, bulk enrollment with provisioning packages, Windows Autopilot deployment profiles, and enrollment restrictions. Every device management journey starts here.

🎯

Exam Relevance

MD-101 heavily tests enrollment scenarios. You must match the correct enrollment method to a given scenario (BYOD vs. corporate, single device vs. bulk, user-driven vs. automated). Expect 4-6 questions directly tied to enrollment concepts.

🛠️

Real-World Application

Enrollment is the gateway to management. A device that is not enrolled cannot receive policies, apps, or compliance checks. Choosing the wrong enrollment method creates friction for users and overhead for IT. Get this right, and everything else flows.

Learning Objectives

  • Differentiate between Azure AD Registered, Azure AD Joined, and Hybrid Azure AD Joined devices
  • Configure automatic MDM enrollment via Azure AD Join
  • Use Device Enrollment Manager (DEM) accounts for bulk scenarios
  • Create provisioning packages with Windows Configuration Designer
  • Configure Windows Autopilot deployment profiles
  • Set enrollment restrictions and device platform limits

Azure AD Joined is Windows-only. You cannot Azure AD Join an iOS device, an Android device, or a Mac. Those platforms can only be Azure AD Registered. This is a commonly tested distinction. Also remember: Azure AD Join replaces the need for on-premises domain join entirely.

Intune Enrollment Methods

Multiple paths to get devices under management

👤

User Self-Enrollment

Users go to Settings > Accounts > Access work or school > Connect and sign in with their Azure AD credentials. The device registers with Azure AD and automatically enrolls in Intune if auto-enrollment is configured. Simplest method for individual devices.

⚡

Auto-Enrollment via Azure AD Join

When a user Azure AD Joins a device, Intune MDM enrollment happens automatically if MDM auto-enrollment is enabled in Azure AD. Configure in Azure AD > Mobility (MDM and MAM) > Microsoft Intune. Set scope to All or specific groups.

👥

Device Enrollment Manager (DEM)

A special Intune role that allows a single account to enroll up to 1,000 devices. Ideal for shared devices, kiosks, or bulk enrollment events. DEM-enrolled devices cannot use Autopilot, and the DEM user cannot use Conditional Access or user-targeted apps.

📦

Bulk Enrollment

Create provisioning packages using Windows Configuration Designer (WCD). Packages are saved as .ppkg files and can be applied during OOBE or via Settings. Useful for enrolling many devices without individual user sign-in.

Enrollment Method Decision Tree

  • Single user device, cloud-only → Azure AD Join with auto-enrollment
  • BYOD / personal device → User self-enrollment (Azure AD Register)
  • Shared device / kiosk (no assigned user) → DEM account or Autopilot Self-Deploying
  • Large batch, no Autopilot → Provisioning package (WCD)
  • New devices from vendor → Windows Autopilot
  • Existing on-prem AD devices → Hybrid Azure AD Join + co-management + auto-enrollment

Auto-Enrollment Configuration

Seamless MDM enrollment triggered by Azure AD Join

How Auto-Enrollment Works

When properly configured, the moment a device joins Azure AD, it automatically enrolls in Intune MDM. Here is the configuration path:

  • 1Navigate to Azure AD > Mobility (MDM and MAM)
  • 2Select Microsoft Intune from the application list
  • 3Set MDM user scope to All or select specific Azure AD groups
  • 4Optionally set MAM user scope for application-level management
  • 5Verify MDM URLs are populated (they auto-populate for Intune)
  • 6When a user joins a device to Azure AD, Intune enrollment triggers automatically

Auto-Enrollment Requirements

  • Azure AD Premium P1 license (or higher) is required for auto-enrollment
  • MDM authority must be set to Intune (not co-existence with another MDM)
  • Users must have an Intune license assigned
  • Works with both Azure AD Join and Hybrid Azure AD Join (via Group Policy)
  • For Hybrid Join: configure auto-enrollment via GPO at Computer Config > Administrative Templates > Windows Components > MDM > Enable auto MDM enrollment using default Azure AD credentials
Exam Tip

Auto-enrollment requires Azure AD Premium P1. Without P1, you cannot configure automatic MDM enrollment. Users would need to manually enroll through Company Portal or Settings. This is a commonly tested licensing requirement on the MD-101 exam.

Device Enrollment Manager (DEM)

A single account that can enroll up to 1,000 devices

👥

What is DEM?

A DEM is an Azure AD user account with special Intune permissions to enroll up to 1,000 devices. The DEM user signs in on each device to trigger enrollment. Devices enrolled via DEM are associated with the DEM account, not an end user.

✅

Best Use Cases

Shared devices (tablets in a hospital ward), kiosk devices, point-of-sale terminals, classroom devices, or any device that does not have a single assigned user. DEM is ideal when you need to quickly enroll many devices with one set of credentials.

DEM Limitations

  • Maximum 1,000 devices per DEM account (up to 150 DEM accounts per tenant)
  • DEM-enrolled devices cannot use Windows Autopilot
  • DEM users cannot use Conditional Access for themselves
  • User-targeted apps and policies do not apply — only device-targeted ones
  • Company Portal cannot be used for Available apps on DEM-enrolled devices
  • DEM account must have an Intune license assigned
  • DEM works with Windows, iOS, and Android (not macOS)
Exam Tip

If a scenario describes shared devices and asks for the quickest enrollment method without Autopilot, DEM is the answer. But if the scenario requires user-specific apps, Conditional Access per user, or Autopilot, DEM is NOT appropriate. The 1,000-device limit per DEM account is frequently tested.

Bulk Enrollment & Provisioning Packages

Windows Configuration Designer for mass provisioning

📦

Windows Configuration Designer (WCD)

A free Microsoft tool (available from Microsoft Store) that creates provisioning packages (.ppkg files). These packages can configure Windows settings, enroll in Azure AD, join a domain, install certificates, and trigger Intune enrollment in a single automated step.

💾

Provisioning Package (.ppkg)

A .ppkg file contains configuration settings that can be applied during OOBE (first run), from Settings, or via USB. When applied, the device can be renamed, joined to Azure AD, enrolled in Intune, and configured with Wi-Fi profiles—all without manual intervention.

Creating a Provisioning Package
  • 1Install Windows Configuration Designer from the Microsoft Store
  • 2Select Provision desktop devices wizard
  • 3Configure device name pattern (e.g., KIOSK-%SERIAL%)
  • 4Set up Wi-Fi network connection if needed
  • 5Configure Azure AD enrollment with a bulk enrollment token
  • 6Export the .ppkg file to a USB drive
  • 7Insert USB during OOBE on new devices — package applies automatically

Key Provisioning Package Facts

  • Packages can be applied during OOBE by inserting a USB with the .ppkg file
  • Packages can also be applied via Settings > Accounts > Access work or school > Add provisioning package
  • Bulk tokens for Azure AD enrollment expire after a configurable period
  • Provisioning packages do NOT support Autopilot — they are a separate enrollment path
  • WCD also supports advanced provisioning for certificates, VPN profiles, and network settings

Windows Autopilot Enrollment

Cloud-native device provisioning from hardware hash to Intune

🛠️

Hardware Hash Registration

Each device has a unique hardware hash (derived from hardware identifiers). OEM vendors or IT can extract hashes using PowerShell (Get-WindowsAutopilotInfo) and upload them as a CSV to the Intune admin center.

📄

Deployment Profiles

Autopilot deployment profiles define the OOBE experience: skip privacy settings, skip EULA, hide change account options, set device name template. Profiles are assigned to device groups and determine which Autopilot mode is used (user-driven, self-deploying, etc.).

👥

Dynamic Groups

Create Azure AD dynamic device groups using the ZTDID (Zero Touch Device ID) attribute. All Autopilot-registered devices can be automatically added to a group, and that group can be targeted with deployment profiles, apps, and policies.

🔧

Enrollment Status Page (ESP)

The ESP shows provisioning progress during Autopilot enrollment. It tracks device preparation, device setup (apps, profiles), and account setup phases. Can be configured to block device use until all required apps are installed — ensuring the device is ready before the user begins working.

Exam Tip

The Enrollment Status Page (ESP) is commonly tested. Know that it can be configured to block the user from using the device until all required apps and profiles are installed. This is critical for compliance-sensitive environments where a device must be fully configured before any user interaction.

Autopilot Deployment Modes

Matching the deployment mode to the scenario

Mode User Interaction TPM 2.0 Best For
User-Driven User signs in with Azure AD credentials Recommended Standard employee laptops/desktops
Self-Deploying None — fully automated Required Kiosks, signage, shared devices
Pre-Provisioning IT does initial setup, user completes Required High-security or app-heavy deployments
Autopilot Reset None (remote or local trigger) Not required Re-provisioning existing devices

Autopilot User-Driven Flow

  • User powers on new device and selects language/region/keyboard
  • Device connects to the internet (Wi-Fi or Ethernet)
  • OOBE contacts Azure AD and downloads the Autopilot profile
  • Customized OOBE experience appears (company branding, simplified screens)
  • User signs in with Azure AD credentials
  • Device Azure AD Joins and auto-enrolls in Intune
  • Enrollment Status Page tracks app and policy installation
  • User lands on the desktop with all apps and policies applied
Exam Tip

Autopilot Reset removes all user data, apps, and settings while preserving the Azure AD join and Intune enrollment. It is used to re-provision a device for a new user without re-imaging. This is different from a full wipe, which removes everything including the Autopilot profile.

Enrollment Restrictions

Controlling which devices can enroll and how many

🚫

Device Type Restrictions

Control which platforms can enroll: Windows, iOS, Android, macOS. You can also block personally-owned devices (BYOD) from enrolling while allowing corporate-owned devices. Set minimum and maximum OS version requirements for enrollment.

🔢

Device Limit Restrictions

Limit the number of devices a single user can enroll. Default is 5 devices per user. Can be set from 1 to 15 devices. Prevents users from enrolling excessive numbers of devices. Does not apply to DEM accounts or Autopilot devices.

Enrollment Restriction Configuration

  • Configure at Intune > Devices > Enrollment restrictions
  • Default restrictions apply to all users; custom restrictions can target specific groups
  • Restrictions are prioritized by order — higher priority restrictions override lower ones
  • Block personally-owned Windows devices while allowing corporate devices
  • Block Android device administrator enrollment (force Android Enterprise instead)
  • Set minimum OS version to prevent outdated, insecure devices from enrolling
Real-World Scenario

A financial services company wants to ensure: (1) only corporate-owned Windows and iOS devices can enroll, (2) no personally-owned devices, (3) each user can enroll a maximum of 3 devices, and (4) all Windows devices must run version 22H2 or later.

Configuration: Create a device type restriction that blocks Android and macOS, blocks personally-owned devices, and sets minimum Windows version to 10.0.19045 (22H2). Create a device limit restriction set to 3.

Summary

Module 2 consolidated — device enrollment mastery

🔑

Device Identity Types

Registered = BYOD/personal. Joined = cloud-only corporate. Hybrid Joined = on-prem AD + Azure AD. Azure AD Join is Windows-only. Registration supports all platforms.

📱

Enrollment Methods

User self-enrollment for BYOD. Auto-enrollment via Azure AD Join (requires P1). DEM for shared devices (up to 1,000). Provisioning packages for bulk without Autopilot. Autopilot for cloud-native deployments.

🚀

Autopilot Modes

User-driven (standard). Self-deploying (kiosks, requires TPM 2.0). Pre-provisioning (IT pre-stages). Autopilot Reset (re-provision without re-imaging). ESP blocks use until apps are installed.

🚫

Enrollment Restrictions

Device type restrictions control platforms and block personal devices. Device limit restrictions cap per-user device count (default 5, max 15). Custom restrictions target specific groups with priority ordering.

Critical Exam Facts

  • Auto-enrollment requires Azure AD Premium P1 — without it, users must manually enroll
  • DEM accounts can enroll up to 1,000 devices but cannot use Autopilot or Conditional Access
  • Autopilot Self-Deploying mode requires TPM 2.0; User-driven does not strictly require it
  • Autopilot Reset preserves Azure AD join and Intune enrollment; full wipe removes everything
  • Azure AD Joined = Windows only; Azure AD Registered = all platforms
  • Enrollment Status Page (ESP) can block device use until required apps are installed
