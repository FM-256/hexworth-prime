Encrypting File System (EFS)

File-level encryption built into NTFS for protecting individual files and folders

How EFS Works

EFS uses asymmetric cryptography to encrypt individual files and folders on NTFS volumes. Each file is encrypted with a unique symmetric File Encryption Key (FEK), which is then encrypted with the user's public key.

Key characteristics:

  • →Transparent encryption — files decrypt automatically for the authorized user
  • →Per-user encryption — only the encrypting user can decrypt by default
  • →NTFS only — does not work on FAT32 or exFAT volumes
  • →Certificate-based — requires a user certificate (auto-generated or domain-issued)

EFS Recovery Agent

The Data Recovery Agent (DRA) is a designated account that can decrypt any EFS-encrypted file. In domain environments, the domain administrator is the default DRA.

  • →Configure DRA via Group Policy: Computer Config > Windows Settings > Security Settings > Public Key Policies
  • →Export and back up the DRA certificate — loss means no recovery option
  • →Use cipher /r to generate a recovery agent certificate
  • →Use cipher /u to update encrypted files with new recovery keys
EXAM TIP

EFS encrypts files, not volumes. BitLocker encrypts volumes, not individual files. Copying an EFS-encrypted file to a non-NTFS volume removes encryption. If a user's profile is lost or certificate is deleted without backup, the encrypted files become permanently inaccessible unless a DRA is configured.

BitLocker Drive Encryption

Full-volume encryption with enterprise management and Intune integration

BitLocker Fundamentals

BitLocker protects entire volumes against offline attacks. In the MD-101 context, focus is on enterprise deployment and management through Intune and Configuration Manager.

  • →TPM + PIN — recommended enterprise configuration for maximum security
  • →Silent encryption — Intune can enable BitLocker without user interaction
  • →Recovery key escrow — keys stored in Azure AD or on-prem AD DS
  • →Used space only vs. full encryption — used space is faster for new deployments

Managing BitLocker with Intune

Microsoft Intune provides centralized BitLocker policy management for modern-managed devices.

  • →Endpoint Security > Disk Encryption > BitLocker profile
  • →Configure encryption method: XTS-AES 128 or XTS-AES 256
  • →Rotate recovery keys from the Intune portal
  • →View encryption status per device in Intune compliance reports

Microsoft Defender for Endpoint

Enterprise EDR platform for prevention, detection, investigation, and response

🔎

Endpoint Detection & Response

Continuously monitors endpoint behavior to detect advanced threats. Provides rich investigation tools, timeline views, and automated remediation. Security analysts can pivot across alerts, machines, and files.

🧠

Threat & Vulnerability Management

Real-time discovery of software vulnerabilities and misconfigurations on endpoints. Provides risk-based prioritization and remediation recommendations integrated into the security operations workflow.

⚙️

Automated Investigation

AI-driven automation examines alerts and determines remediation actions. Reduces alert fatigue by automatically resolving common incidents. Configurable automation levels from semi to fully automated.

ONBOARDING METHODS

  • Microsoft Intune — preferred for cloud-managed devices; deploy onboarding configuration package via device configuration profile
  • Group Policy — domain-joined devices; deploy onboarding script via GPO
  • Local script — up to 10 devices for testing; download from Microsoft 365 Defender portal
  • SCCM / Configuration Manager — large-scale on-premises deployment with client settings
  • VDI onboarding — special configuration for non-persistent virtual desktop infrastructure
EXAM TIP

Microsoft Defender for Endpoint requires a separate license (Plan 1 or Plan 2). It is not the same as the built-in Microsoft Defender Antivirus. Know the onboarding methods and that Intune is the recommended approach for modern-managed devices. The Microsoft 365 Defender portal (security.microsoft.com) is the central management console.

Defender for Endpoint Capabilities

Attack surface reduction, next-gen protection, and advanced hunting

Attack Surface Reduction

A collection of capabilities that reduce the ways attacks can penetrate your environment:

  • →ASR rules — block Office macro abuse, script execution, credential theft from LSASS
  • →Controlled folder access — anti-ransomware protection for critical directories
  • →Network protection — blocks connections to malicious domains and IPs
  • →Web protection — web threat and content filtering integration
  • →Exploit protection — system and app-level mitigations (DEP, ASLR, CFG)

Next-Generation Protection

Advanced antimalware capabilities beyond traditional signature-based detection:

  • →Behavior-based detection — identifies threats by analyzing process behavior patterns
  • →Cloud-delivered protection — millisecond verdicts from the Microsoft Intelligent Security Graph
  • →Machine learning models — client-side and cloud-based ML classifiers
  • →Tamper protection — prevents unauthorized changes to security settings
Advanced Hunting
Advanced hunting in Microsoft 365 Defender uses Kusto Query Language (KQL) to proactively search for threats across endpoint data. Security analysts write queries against tables like DeviceProcessEvents, DeviceNetworkEvents, and DeviceFileEvents to find suspicious patterns that automated detection may miss. This is a Plan 2 feature.

Windows Defender Application Guard

Hardware-based browser isolation using Hyper-V containers

How Application Guard Works

WDAG opens untrusted websites and Office documents in an isolated Hyper-V container. Even if malicious code executes, it is confined to the disposable container and cannot access the host OS, local network, or enterprise data.

  • →Enterprise-managed mode — IT defines trusted sites; all others open in container
  • →Standalone mode — user manually launches isolated browsing sessions
  • →Requires Hyper-V, 64-bit CPU with virtualization extensions
  • →Available on Enterprise and Education editions

Configuration Options

Configure via Group Policy or Intune:

  • →Clipboard behavior — allow/block copy-paste between container and host
  • →Print settings — control printing from isolated sessions
  • →Camera and microphone — enable/disable device access in container
  • →Data persistence — retain or discard user data between sessions
  • →Network isolation — define enterprise cloud resources and network boundaries
EXAM TIP

Application Guard uses hardware-based isolation (Hyper-V), making it fundamentally different from sandboxing. It requires Windows 10/11 Enterprise or Education and Hyper-V capability. Know the difference between enterprise-managed mode (IT controls trusted site list) and standalone mode (user-initiated).

Credential Guard & System Guard

Virtualization-based security for credential isolation and measured boot

Windows Defender Credential Guard

Uses virtualization-based security (VBS) to isolate NTLM hashes, Kerberos tickets, and other credentials in a secure container that even kernel-level malware cannot access.

Requirements:

  • →UEFI firmware with Secure Boot
  • →Virtualization extensions (Intel VT-x / AMD-V)
  • →TPM 2.0 (recommended)
  • →Windows Enterprise or Education
  • →64-bit operating system

System Guard (Measured Boot)

Ensures the integrity of the boot process by measuring each component and storing the measurements in the TPM. If tampering is detected, the system can prevent access to enterprise resources.

  • →DRTM — Dynamic Root of Trust for Measurement ensures secure launch
  • →Runtime attestation — validates system integrity after boot
  • →SMM protection — guards against System Management Mode attacks
Why Credential Guard Matters
Without Credential Guard, tools like Mimikatz can extract NTLM hashes and Kerberos tickets directly from the LSASS process memory. With Credential Guard enabled, credentials are stored in an isolated virtual container using VBS — even a compromised kernel cannot reach them. This is the primary defense against Pass-the-Hash and Pass-the-Ticket attacks in enterprise environments.

Application Control (WDAC)

Windows Defender Application Control — whitelisting for enterprise security

WDAC Overview

Windows Defender Application Control replaces AppLocker as Microsoft's recommended application whitelisting solution. It controls which drivers and applications are allowed to run.

  • →Kernel-mode enforcement — controls which drivers can load
  • →User-mode enforcement — controls which applications can execute
  • →Managed Installer — auto-trusts apps deployed via SCCM or Intune
  • →Intelligent Security Graph — reputation-based trust decisions

WDAC vs. AppLocker

While both control application execution, WDAC operates at a lower level and provides stronger security guarantees:

  • →WDAC — enforced by the kernel; cannot be bypassed by admin users
  • →AppLocker — runs as a service; local admins can modify or disable it
  • →WDAC supports both audit and enforce modes for policy testing
  • →WDAC policies deploy via Intune, Group Policy, or MDM
EXAM TIP

WDAC is Microsoft's recommended application control solution going forward. It is more secure than AppLocker because it operates at the kernel level. AppLocker is still supported but primarily used alongside WDAC for user-mode rules. The exam tests the differences between the two and when to use each.

Exploit Guard & ASR Rules

Behavioral-based attack mitigation and surface reduction

Exploit Protection
System and app-level exploit mitigations replacing EMET. Includes DEP, ASLR, SEHOP, CFG, and heap integrity. Configure per-system defaults and per-application overrides.
ASR Rules
Block common attack techniques: Office macros creating child processes, credential theft from LSASS, script obfuscation, untrusted USB processes. Deploy via Intune or Group Policy.
Network Protection
Extends SmartScreen to block outbound connections to low-reputation hosts. Prevents connections to phishing sites, exploit servers, and C2 infrastructure at the network layer.
Controlled Folder Access
Anti-ransomware: blocks untrusted processes from writing to protected folders (Documents, Pictures, etc.). Trusted apps can be whitelisted. Requires real-time protection enabled.
SmartScreen
Reputation-based protection checking downloaded files and URLs against Microsoft's cloud intelligence. Integrated into Edge, Windows Explorer, and Microsoft Store app installs.
Device Guard
Combines WDAC with VBS and HVCI (Hypervisor-protected Code Integrity) to lock down devices so only trusted applications run. Enterprise-grade protection against unknown code.

ASR RULE DEPLOYMENT MODES

  • Not configured — rule is disabled (default for most rules)
  • Block — rule actively blocks the behavior and generates an alert
  • Audit — rule logs the behavior without blocking — use first to assess impact
  • Warn — shows a warning dialog to the user but allows override

Security Baselines & Compliance

Standardized security configurations and compliance monitoring

Microsoft Security Baselines

Pre-configured sets of Windows settings recommended by Microsoft security teams. Based on feedback from Microsoft security engineering, product groups, partners, and customers.

  • →Deploy via Intune security baselines or Group Policy
  • →Baselines available for Windows 10/11, Microsoft Edge, Microsoft 365 Apps
  • →Microsoft Security Compliance Toolkit (SCT) for on-prem analysis
  • →Customizable — adjust settings to match organizational requirements

Intune Compliance Policies

Define the minimum security requirements devices must meet to access corporate resources. Non-compliant devices can be blocked via Conditional Access.

  • →BitLocker required — device must have encryption enabled
  • →Minimum OS version — enforce patch currency
  • →Defender status — real-time protection must be active
  • →Risk score — integration with Defender for Endpoint threat level
EXAM TIP

Security baselines in Intune provide a quick way to apply Microsoft-recommended settings without building custom profiles from scratch. Compliance policies combined with Conditional Access create a Zero Trust enforcement loop: only compliant, healthy devices can access corporate resources. Know the distinction between configuration profiles (push settings) and compliance policies (evaluate state).

Module 6 Summary

Managing Security — key takeaways

  • EFS encrypts individual files using per-user certificates; BitLocker encrypts entire volumes using TPM
  • EFS requires NTFS; copying encrypted files to non-NTFS removes encryption
  • Data Recovery Agent (DRA) is the enterprise fail-safe for EFS — configure and back up the DRA certificate
  • BitLocker can be silently deployed via Intune with recovery key escrow to Azure AD
  • Microsoft Defender for Endpoint is a separate licensed EDR platform — not the built-in Defender Antivirus
  • Onboard devices to Defender for Endpoint via Intune, Group Policy, local script, or SCCM
  • Application Guard isolates untrusted sites in Hyper-V containers — requires Enterprise/Education
  • Credential Guard uses VBS to isolate credentials and prevent Pass-the-Hash attacks
  • WDAC is the recommended application control solution; operates at kernel level, stronger than AppLocker
  • ASR rules block common attack techniques — deploy in Audit mode first, then switch to Block
  • Security baselines in Intune provide Microsoft-recommended settings as a deployment starting point
  • Compliance policies combined with Conditional Access enforce Zero Trust endpoint security
