Microsoft Defender for Endpoint
Enterprise endpoint detection, response, and automated investigation platform.
What Is MDE?
Microsoft Defender for Endpoint (MDE) is an enterprise-grade EDR (Endpoint Detection and Response) platform. It provides behavioral sensors, cloud-powered threat intelligence, automated investigation and remediation, and threat hunting capabilities. Formerly known as Microsoft Defender ATP.
MDE Plan 1 vs. Plan 2
Plan 1: Next-gen antivirus, ASR rules, device control, web content filtering, manual response actions. Plan 2: Everything in P1 plus EDR, automated investigation, threat & vulnerability management, threat analytics, sandbox analysis, and 6-month data retention.
Onboarding Methods
Windows: via Intune, Group Policy, Configuration Manager, or local script. macOS/Linux: via Intune, script, or manual install. Mobile: via Intune MDM. Onboarding deploys the Defender sensor that streams signals to Microsoft 365 Defender portal.
Exam Tip
MDE is included in M365 E5 and Microsoft Defender for Endpoint standalone. M365 E3 includes Defender Plan 1 only. Plan 2 (EDR, TVM) requires E5 or a separate Plan 2 license. Know which plan provides which capability.

Threat & Vulnerability Management
Continuous discovery, prioritization, and remediation of endpoint vulnerabilities.
Discovery
MDE continuously inventories all software installed on onboarded endpoints, discovers missing patches, misconfigurations, and known CVEs. No additional scanning agent required. Discovery runs passively using the same Defender sensor used for threat detection.
Prioritization (Exposure Score)
TVM calculates an Exposure Score (0-100) for your organization based on vulnerability criticality, exploitability in the wild, and the number of affected devices. Higher score = more exposed. Also generates a Microsoft Secure Score for Devices.
Remediation Workflow
Recommendations can be submitted as remediation activities to Intune. Admins review, approve, and deploy patches or configuration changes through the existing Intune workflow. Provides an audit trail from vulnerability discovery to remediation completion.
Security Recommendations
TVM generates prioritized security recommendations: enable BitLocker, update software version X, disable legacy protocol Y. Each recommendation shows affected devices, exposure level, and the remediation action required. Filter by category: software, OS, network.
Software Inventory
Complete catalog of all software across all onboarded devices. Shows version, vendor, number of installed instances, and any known CVEs. Filter for vulnerable software versions. Click through to see exactly which devices have each vulnerability.

Attack Surface Reduction
Eliminate attack vectors before they are exploited — proactive versus reactive defense.
ASR Rules
Attack Surface Reduction rules block specific malicious behaviors at the OS level: block Office apps from creating child processes, block Office from injecting into other processes, block executable content from email, block credential theft from LSASS, block untrusted USB execution, block obfuscated script execution.
ASR Rule Modes
Block: Rule is enforced, action is blocked. Audit: Rule evaluates but does not block. Logs what would have been blocked in Windows Event Viewer. Use Audit mode before switching to Block to understand impact. Warn: Blocks and shows a user notification.
Controlled Folder Access
Protects specified folders (Documents, Pictures, etc.) from unauthorized writes by non-whitelisted apps. Blocks ransomware from encrypting files in protected folders. Can add custom protected folders and whitelist specific trusted applications.
Device Control
Controls which removable storage devices (USB drives, external drives) can be used and what operations are permitted (read, write, execute). Policy can block all USB storage, allow only approved USB device IDs, or allow read-only access. Prevents data exfiltration via USB.
Network Protection
Extends SmartScreen protection to the network level. Blocks outbound connections to low-reputation IP addresses and domains (known C2 servers, phishing domains). Works for all traffic on the device, not just browser traffic. Audit or Block mode.

ASR rules are deployed using Intune Endpoint Security policies (Attack surface reduction profile) or via Configuration Manager / Group Policy. Always start in Audit mode, monitor Windows Defender logs for false positives, then switch to Block mode.

Security Baselines
Microsoft-recommended security configuration templates deployed through Intune.
What Are Security Baselines?
Pre-configured groups of Windows settings that represent the security posture recommended by Microsoft security teams. Based on best practices from Microsoft, NIST, and CIS benchmarks. Baselines are versioned and updated as the threat landscape evolves. Available for Windows 10/11, Microsoft Edge, Microsoft 365 Apps, and Defender for Endpoint.
Available Baselines
Windows Security Baseline: 150+ settings covering firewall, BitLocker, credential guard, account lockout, UAC, Windows Defender. Edge Security Baseline: Browser security settings. M365 Apps Baseline: Office macro settings, Trust Center config. MDE Baseline: Defender-specific hardening.
Deployment in Intune
Endpoint Security > Security Baselines > Select baseline type > Create profile > Customize settings if needed > Assign to device groups. Baseline settings merge with other configuration profiles. In conflicts, last-write wins unless the baseline uses a higher-priority CSP.
Exam Tip
Security Baselines are the fastest path to a hardened configuration. They ship pre-configured and only need an assignment to take effect. Unlike Compliance policies (which evaluate and report), baselines actively configure device settings. Think of baselines as "configuration" and compliance policies as "evaluation."

Security Baseline Deployment Pipeline
How Microsoft baseline recommendations flow from Intune to endpoint configuration.
Baseline Versioning
Security baselines are versioned (e.g., Windows Security Baseline for Windows 10 v21H2). When a new version is released you choose to update your assigned profile or remain on the current version. Updating a baseline version does not automatically apply — you must accept the update.
Conflict Resolution
When a baseline setting conflicts with a manually configured Configuration Profile or Endpoint Security policy, a conflict is reported in Intune. Conflicts must be resolved manually. Intune does not automatically pick a winner for conflicting settings.

BitLocker Encryption
Full-volume encryption for Windows devices — deployed and managed via Intune.
What BitLocker Protects
BitLocker encrypts the entire OS drive and any additional drives. Without the encryption key, data on a stolen or lost device is unreadable. Uses AES-128 or AES-256. TPM chip stores the key and validates the pre-boot environment before unlocking the drive.
TPM + BitLocker
TPM 1.2 or 2.0 required for silent/automatic encryption. TPM validates the boot chain: if the system has been tampered with (bootkit, different hardware), TPM withholds the key and prompts for the recovery key. TPM + PIN = adds a second authentication factor at pre-boot.
Recovery Keys
48-digit recovery key is escrowed to Azure AD automatically when BitLocker is configured via Intune with "Back up BitLocker recovery information to Azure AD." Admins retrieve keys from Intune device details. Required when: TPM fails, forgotten PIN, hardware change, firmware update.

Windows Encryption & Protection Features
The full suite of Windows security features beyond BitLocker.
Credential Guard
Uses virtualization-based security (VBS) to isolate the LSASS process that stores credentials. Credentials are stored in an isolated container that even the OS kernel cannot directly access. Prevents Pass-the-Hash and Pass-the-Ticket attacks. Requires VBS-capable CPU and UEFI.
Windows Defender Application Guard
Opens untrusted websites or Office files in an isolated Hyper-V container. If a malicious site compromises the browser inside the container, it cannot reach the actual host OS. Container is destroyed after the session. Requires Hyper-V capable hardware and Windows 10/11 Enterprise.
Exploit Protection
System-level and per-app mitigations against memory-based exploits: DEP (Data Execution Prevention), ASLR (Address Space Layout Randomization), Control Flow Guard, Stack randomization. Replaces EMET (Enhanced Mitigation Experience Toolkit). Configurable via Intune or Group Policy.
Secure Boot
UEFI firmware validates that the boot loader and OS kernel are signed by trusted keys before loading. Prevents bootkit malware from loading before Windows. Required by compliance policies in MDE onboarding. Cannot be bypassed without physical access and disabling UEFI secure boot.

Endpoint Security Profiles in Intune
Intune Endpoint Security is the admin hub for deploying all security configurations.
Antivirus
Configure Microsoft Defender Antivirus settings: real-time protection, cloud-delivered protection, sample submission, behavior monitoring, exclusion paths, scheduled scan settings. Separate profile for Windows Security app UI (show/hide to end users).
Disk Encryption
BitLocker for Windows (OS drive, fixed drives, removable drives). FileVault for macOS. Configure encryption algorithm (XTS-AES 128/256), recovery key escrowing, silent enablement, startup authentication (TPM, PIN, USB key), and recovery message on unlock screen.
Firewall
Configure Windows Defender Firewall: enable/disable per network profile (Domain, Private, Public), default allow/block inbound, logging configuration, custom firewall rules (allow specific ports/applications). Deploy consistent firewall policy across the fleet regardless of GPO.
Endpoint Detection & Response
Onboard devices to MDE via Intune. Configure sample sharing, telemetry reporting frequency, and the MDE onboarding blob. Manage offboarding (remove device from MDE monitoring). EDR profile is the primary onboarding method for Intune-managed devices.
Attack Surface Reduction
Deploy ASR rules by GUID with Block/Audit/Warn mode. Configure Controlled Folder Access protected folders and allowed apps. Device control: USB block/allow rules. Network protection mode. Web content filtering categories (block adult content, social media, etc.).
Account Protection
Windows Hello for Business deployment: enable, configure PIN complexity (length, characters), require biometrics. Local Administrator Password Solution (LAPS) configuration: rotate local admin passwords, store in AAD, expiry settings. Prevents credential reuse attacks.

Microsoft Defender Antivirus
The built-in real-time protection engine — configurable at scale through Intune.
Cloud-Delivered Protection
Sends file hash and behavioral telemetry to Microsoft cloud for near-instant threat intelligence. Cloud protection can block files within seconds of detection by any device in the Microsoft network — before signatures are distributed to all endpoints. Strongly recommended to enable.
Potentially Unwanted Applications (PUA)
Blocks software that is not technically malware but is unwanted: adware, browser hijackers, coin miners, bundled software. PUA protection has Audit and Block modes. Separate from virus/malware detection. Reduces the noise from legitimate-but-unwanted software installs.

MDE Alerts & Incidents
Alert triage, incident correlation, and automated investigation in the M365 Defender portal.
Alerts
An alert is generated when MDE detects suspicious behavior on a device. Alert severity: Informational, Low, Medium, High. Alerts include: timeline of events, file/process involved, MITRE ATT&CK technique, and recommended response actions. Multiple related alerts are grouped into an Incident.
Incidents
An incident is a collection of correlated alerts that represent an attack chain. The M365 Defender portal automatically correlates alerts across endpoints, identities, email, and cloud apps into a single incident view. Provides a full attack story from initial compromise to impact.
Automated Investigation
MDE Plan 2 automatically investigates alerts and takes remediation actions: quarantine malware, kill malicious processes, remove persistence mechanisms, isolate the device. The admin reviews the investigation tree and approves or rejects pending remediation actions. Reduces analyst triage time.
Response Actions
Manual response actions available in MDE: Isolate device (cut all network except Defender communication), run antivirus scan, collect investigation package, restrict app execution (block non-Microsoft-signed binaries), initiate automated investigation, live response (remote shell session).

8MDE onboarding via Intune deploys via the Endpoint Security > Endpoint Detection & Response profile. Not via a Configuration Profile.
9Device isolation in MDE cuts all network connections except Defender communication. Used for active incident containment.
10Tamper protection prevents users and non-admin processes from disabling Microsoft Defender. Must be enabled in AV policy.

Module 6 Summary
Managing security mastery consolidated.
MDE & TVM
MDE Plan 1 = AV + ASR. Plan 2 adds EDR, TVM, automated investigation. Onboard via Intune EDR profile. TVM: Discover CVEs, prioritize via Exposure Score, submit to Intune for remediation. Secure Score for Devices improves as you fix issues.
Attack Surface Reduction
ASR rules block malicious behaviors (Office child processes, LSASS access, email executables). Always audit before blocking. Controlled Folder Access stops ransomware. Device Control blocks USB exfiltration. Network Protection extends SmartScreen to all traffic.
Security Baselines & Encryption
Security Baselines deploy 150+ Microsoft-recommended settings in one profile assignment. BitLocker encrypts OS drives with TPM. Recovery keys escrowed to Azure AD. Credential Guard protects LSASS via VBS. Exploit Protection replaces EMET.
Endpoint Security Profiles
Intune Endpoint Security hub: Antivirus, Disk Encryption, Firewall, EDR (onboarding), ASR, Account Protection (WHfB + LAPS). Each profile targets specific security concerns. Security Baselines cover most settings; individual profiles allow fine-grained control.
