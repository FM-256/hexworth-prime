Configuring Profiles

Shaping device behavior through Intune configuration policies

️

What This Module Covers

Device configuration profiles in Intune, profile types (device restrictions, Wi-Fi, VPN, email, certificates), administrative templates, custom OMA-URI profiles, the Settings Catalog, PowerShell script deployment, and profile conflict resolution.

Exam Relevance

Configuration profiles are tested extensively on MD-101. You must know which profile type to use for a given scenario, understand user vs. device scope, resolve profile conflicts, and know when to use custom OMA-URI versus built-in templates.

️

Real-World Application

Configuration profiles replace Group Policy for cloud-managed devices. Every setting you once configured via GPO can now be delivered through Intune profiles, reaching devices anywhere on the internet without requiring VPN or line-of-sight to a domain controller.

Learning Objectives

  • Create and assign device configuration profiles in Intune
  • Identify the correct profile type for common configuration scenarios
  • Configure administrative templates as the cloud equivalent of Group Policy
  • Use custom profiles with OMA-URI for settings not available in built-in templates
  • Navigate the Settings Catalog for granular, searchable configuration
  • Deploy PowerShell scripts to managed devices via Intune
  • Understand profile conflicts and resolution behavior

MD-101 — Module 3

Configuration Profile Types

Built-in profile templates for common configuration needs

🚫

Device Restrictions

Control device features: camera, Bluetooth, screen capture, USB storage, password requirements, lock screen behavior, Windows Spotlight, app store access, and more. The most commonly used profile type for enforcing security baselines.

Wi-Fi Profiles

Pre-configure Wi-Fi networks on managed devices. Set SSID, security type (WPA2-Enterprise, WPA3), authentication method (certificate, EAP-TLS), and proxy settings. Devices automatically connect to corporate Wi-Fi without manual configuration.

VPN Profiles

Configure VPN connections: connection type (IKEv2, SSTP, L2TP, third-party like Cisco AnyConnect, Palo Alto GlobalProtect), server address, authentication method, split tunneling, always-on VPN, and per-app VPN for specific applications.

Email Profiles

Configure Exchange email on devices automatically. Set the Exchange server, username format (@domain.com), authentication method, and sync settings (how many days of email to sync, sync calendar/contacts). Supports Exchange Online and on-premises Exchange.

Additional Profile Types

  • Certificates — Deploy SCEP or PKCS certificates for Wi-Fi, VPN, and email authentication
  • Edition Upgrade — Upgrade Windows 10/11 Pro to Enterprise using a product key or license file
  • Endpoint Protection — Configure Defender Firewall, BitLocker, Exploit Guard, and Attack Surface Reduction rules
  • Identity Protection — Configure Windows Hello for Business settings
  • Kiosk — Lock down a device to run a single app or limited set of apps
  • Shared Multi-User Device — Configure shared PC mode with guest accounts and auto-cleanup

Exam Tip

Device restriction profiles use the MDM channel (CSP policies) to enforce settings. They are NOT the same as Group Policy. Some GPO settings do not have MDM equivalents. When a setting is available in both device restrictions and administrative templates, device restrictions take precedence because they use a more specific CSP.

Administrative Templates

Group Policy in the cloud — familiar settings, modern delivery

What are Administrative Templates?

Intune administrative templates provide over 5,000 settings that mirror Group Policy ADMX templates. They include settings for Edge, Office, OneDrive, Windows components, and more. If you know Group Policy, you already know how to navigate these templates.

GPO to Intune Migration

Microsoft provides Group Policy Analytics in Intune to import existing GPO backups and see which settings have MDM equivalents. This tool generates a migration readiness report showing supported, partially supported, and unsupported settings.

Creating an Administrative Template Profile
  • 1Navigate to Intune > Devices > Configuration profiles > Create profile
  • 2Select platform: Windows 10 and later
  • 3Select profile type: Templates > Administrative Templates
  • 4Browse settings by category (Computer Configuration / User Configuration)
  • 5Configure each setting as Enabled, Disabled, or Not configured
  • 6Assign to Azure AD groups (users or devices)

Administrative Templates vs. Device Restrictions

  • Administrative templates mirror GPO ADMX settings — familiar structure for AD admins
  • Device restrictions use MDM CSP policies — more modern, designed for cloud-native management
  • Some settings exist in BOTH — if they conflict, the last applied policy wins (usually CSP)
  • Administrative templates support both Computer and User configuration contexts
  • When migrating from GPO, use Group Policy Analytics to identify which settings translate

Custom Profiles & OMA-URI

Accessing settings beyond built-in templates

What is OMA-URI?

Open Mobile Alliance Uniform Resource Identifier — a standard path format used to address specific Configuration Service Provider (CSP) settings. When Intune does not have a built-in template for a setting, you can use a custom profile to target the CSP directly via its OMA-URI path.

CSP Documentation

Microsoft documents all available CSPs at learn.microsoft.com/windows/client-management/mdm/. Each CSP has specific OMA-URI paths. For example, the BitLocker CSP path for requiring encryption is: ./Device/Vendor/MSFT/BitLocker/RequireDeviceEncryption

OMA-URI Format

Every OMA-URI path follows a pattern: ./Device/Vendor/MSFT/[CSP]/[SettingPath] for device-scope settings, or ./User/Vendor/MSFT/[CSP]/[SettingPath] for user-scope settings. Data types include Integer, String, Boolean, Base64, and XML.

Custom Profile Example: Disable Cortana
  • 1Create profile: Windows 10 and later > Templates > Custom
  • 2Add an OMA-URI setting row
  • 3Name: Disable Cortana
  • 4OMA-URI: ./Device/Vendor/MSFT/Policy/Config/Experience/AllowCortana
  • 5Data type: Integer
  • 6Value: 0 (0 = disabled, 1 = enabled)
Exam Tip

Use custom OMA-URI profiles only when a setting is not available in built-in templates, administrative templates, or the Settings Catalog. The exam may present a scenario where a specific CSP path is needed. Recognize the OMA-URI format: ./Device/Vendor/MSFT/ is always the prefix for device-scoped settings.

Settings Catalog

The modern, searchable approach to device configuration

What is the Settings Catalog?

A flat, searchable list of all available settings across all CSPs. Unlike templates that group settings by category, the Settings Catalog lets you search for any setting by name, pick exactly the ones you need, and build a custom profile with only those specific settings.

Advantages Over Templates

Settings Catalog is constantly updated with new settings as Microsoft adds CSPs. It provides a single location for all settings. You can search across categories instead of browsing through template hierarchies. Microsoft recommends Settings Catalog as the preferred approach for new configurations.

Settings Catalog vs. Templates

Templates offer pre-grouped settings with guidance. Settings Catalog offers individual setting granularity. Both deliver settings via the same MDM channel. Microsoft is migrating more settings into the Catalog, making it the future of Intune configuration.

Exam Tip

Microsoft is moving toward the Settings Catalog as the primary configuration method. The exam may present scenarios where the correct answer is to use the Settings Catalog because a specific setting is available there but not in a built-in template. Know that Settings Catalog provides the broadest built-in coverage.

PowerShell Scripts via Intune

Extending Intune capabilities beyond built-in profiles

Script Deployment

Intune can deploy PowerShell scripts to managed Windows devices. Scripts run via the Intune Management Extension (IME), which is automatically installed when a script or Win32 app is assigned. Scripts can configure settings, install software, or perform tasks that profiles cannot.

️

Script Configuration Options

When adding a script, configure: Run as system or user context, Enforce script signature check (recommended for security), Run in 64-bit PowerShell (important for accessing correct registry paths), and script timeout (default 60 minutes maximum).

PowerShell Script Behavior in Intune

  • Scripts run once by default — they do not re-run unless the script content changes
  • Scripts are delivered via the Intune Management Extension (IME), not the MDM channel
  • IME checks for new scripts every hour during normal operation
  • Scripts can run in SYSTEM context (for machine-wide changes) or user context (for per-user settings)
  • Maximum script size is 200 KB
  • Script output is captured in Intune for troubleshooting (success/failure)
  • Logs are stored on the device at C:\ProgramData\Microsoft\IntuneManagementExtension\Logs
Exam Tip

Know that PowerShell scripts in Intune run once by default and require the Intune Management Extension. The IME is automatically installed when scripts or Win32 apps are assigned. If a question asks about running a script on every sign-in or repeatedly, a scheduled task or a different mechanism (like a remediation script in Endpoint Analytics) would be needed.

Profile Assignment & Scope

User scope vs. device scope — and how assignments work

User Scope

Profiles assigned to user groups follow the user to every device they sign into. User-scoped settings include email configuration, OneDrive settings, and user-specific restrictions. The profile applies wherever the user authenticates.

Device Scope

Profiles assigned to device groups apply to the device regardless of who signs in. Device-scoped settings include BitLocker encryption, firewall rules, Wi-Fi profiles, and hardware restrictions. The profile is tied to the machine, not the user.

Assignment Options

  • Include groups — Azure AD groups (user or device) that receive the profile
  • Exclude groups — Azure AD groups excluded from receiving the profile (overrides include)
  • All Users — Built-in target that includes every licensed user
  • All Devices — Built-in target that includes every enrolled device
  • Profiles can use Applicability Rules to filter by OS edition or version
  • Assignment filters allow targeting based on device properties (manufacturer, model, OS version)
Exam Tip

Exclude groups always win over include groups. If a user is in both an included group and an excluded group, the profile will NOT apply. This is the same behavior as Azure AD Conditional Access exclusions. Also know that you can assign a profile to "All Users" and then exclude specific groups for exceptions.

Profile Conflicts & Monitoring

What happens when multiple profiles set the same value?

️

Conflict Behavior

When two profiles configure the same setting with different values, the setting enters a conflict state. The device reports the conflict in Intune, and the setting is marked as "Error" or "Conflict." Neither value is reliably enforced until the conflict is resolved.

Monitoring Profiles

Monitor profile status at Intune > Devices > Configuration profiles > [Profile] > Device status. Status values: Succeeded, Pending, Error, Conflict, Not applicable.

Conflict Resolution Rules

  • If the same setting is configured in multiple profiles, the most restrictive value wins for security settings
  • For non-security settings, the conflict is reported and the setting may not be applied at all
  • Settings from the Settings Catalog report conflicts more clearly than template-based profiles
  • Best practice: avoid overlapping settings across profiles — one profile per function
  • Use per-setting status reports to identify exactly which settings are in conflict
  • GPO settings (Hybrid Azure AD Join) can also conflict with Intune MDM settings — MDM wins by default in Windows 10/11
Common Conflict Scenario

Profile A sets minimum password length to 8 characters. Profile B sets minimum password length to 12 characters. Both are assigned to the same device group.

Result: The setting enters a conflict state. For password length (a security setting), the more restrictive value (12) should be enforced, but the profile will report "Conflict." Best practice: consolidate into a single password policy profile to eliminate the conflict.

Approach When to Use Settings Access Complexity

Exam Tip

The exam expects you to select the simplest, most appropriate configuration method. Preference order: Settings Catalog or built-in template first, then administrative templates, then custom OMA-URI, then PowerShell scripts. Never use custom OMA-URI when a built-in option exists.
