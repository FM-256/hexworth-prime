Deployment Readiness Assessment

Evaluate hardware, applications, and infrastructure before deploying Windows

Hardware Compatibility

Before deploying a new Windows version, verify that existing hardware meets minimum and recommended requirements.

Windows 11 Requirements:

  • →CPU — 1 GHz+, 2+ cores, 64-bit compatible processor
  • →RAM — 4 GB minimum
  • →Storage — 64 GB minimum
  • →TPM — TPM 2.0 required
  • →UEFI + Secure Boot — required (no legacy BIOS)

Application Compatibility

Identify and remediate application compatibility issues before deployment to prevent post-migration disruption.

  • →Desktop Analytics — cloud-based compatibility assessment service
  • →App Assure — Microsoft service for resolving compatibility issues
  • →Compatibility modes — run legacy apps in compatibility mode for older Windows versions
  • →Test deployment rings — pilot group testing before broad deployment
EXAM TIP

Desktop Analytics (now part of Intune) collects telemetry data to assess application and driver compatibility before deploying new Windows versions. It creates deployment plans that identify pilot devices and categorize apps as Low Risk, Medium Risk, High Risk, or Insufficient Data. Know that it requires Windows diagnostic data level set to Required or Optional.

Deployment Methods Overview

Understanding the deployment landscape — from traditional imaging to modern provisioning

In-Place Upgrade
Upgrade the existing OS in place. Preserves apps, settings, and data. Simplest method. Best for updating existing machines to a new Windows version. Uses setup.exe from installation media.
Wipe and Load (Refresh)
Back up user data, wipe the disk, install fresh OS, restore data. Used when existing installation is corrupted or when migrating to new hardware architecture (BIOS to UEFI).
Bare Metal
Deploy to brand new hardware with no existing OS. PXE boot from WDS, apply image, configure settings. Standard for new hardware purchases in enterprise environments.
Replace
Retire old hardware and migrate user state to a new computer. Capture user data from source, provision new device, restore data to destination. USMT handles the migration.
Provisioning
Configure an existing Windows installation with corporate settings without reimaging. Uses provisioning packages (.ppkg) created with Windows Configuration Designer or Autopilot profiles.
Subscription Activation
Upgrade Windows edition (Pro to Enterprise) by simply changing the license. No reimage required. User signs in with Azure AD credentials and the device automatically activates.

CHOOSING THE RIGHT METHOD

  • In-place upgrade — lowest risk, preserves everything, best for same-hardware version upgrades
  • Wipe and load — fresh start on existing hardware, use when OS is degraded or architecture change needed
  • Bare metal — new hardware with no OS, requires PXE or USB boot
  • Replace — old hardware retiring, need to migrate user data to new device

Microsoft Deployment Toolkit (MDT)

Free framework for automating Windows deployment with task sequences

MDT Architecture

MDT provides a unified deployment console that automates desktop and server deployment using task sequences and deployment shares.

Key components:

  • →Deployment Workbench — MMC console for managing all deployment resources
  • →Deployment share — network folder containing OS images, drivers, applications, and scripts
  • →Task sequences — ordered list of steps that automate the deployment process
  • →Boot images — WinPE-based images used to start deployment (PXE or USB)

Task Sequence Steps

A typical MDT task sequence includes these phases:

  • 1. Initialization — gather information, validate prerequisites
  • 2. State Capture — back up user data with USMT (if upgrade/refresh)
  • 3. Preinstall — partition disk, inject drivers
  • 4. Install — apply the OS image
  • 5. Post-Install — install applications, configure settings
  • 6. State Restore — restore user data with USMT
EXAM TIP

MDT is a free tool that requires no licensing. It depends on the Windows ADK (Assessment and Deployment Kit) for boot image generation. MDT alone has no built-in OS deployment service — it needs WDS for PXE boot or uses USB/DVD boot media. For enterprise-scale automated deployment, pair MDT with SCCM.

WDS and Configuration Manager

Network-based deployment services and enterprise-scale management

Windows Deployment Services (WDS)

Server role that enables network-based OS deployment via PXE boot. WDS replaces RIS (Remote Installation Services).

  • →PXE server — responds to client boot requests over the network
  • →Image store — hosts boot images (WinPE) and install images (WIM)
  • →Multicast — deploy to multiple machines simultaneously, saving bandwidth
  • →Requires — AD DS, DNS, DHCP on the network

SCCM / MECM (Configuration Manager)

Microsoft's full-featured endpoint management platform for large enterprise deployments. Renamed to Microsoft Endpoint Configuration Manager (MECM).

  • →OS Deployment (OSD) — task sequence-driven imaging with zero-touch capability
  • →Software distribution — deploy applications and updates at scale
  • →Inventory and reporting — comprehensive hardware and software tracking
  • →Co-management — can work alongside Intune for hybrid scenarios

Windows Imaging

Image types, capture strategies, and the Windows ADK toolchain

Image Types

Understanding image strategies is fundamental to enterprise deployment planning:

  • →Thick image — includes OS, apps, drivers, and configurations baked in; large, hardware-specific, hard to maintain
  • →Thin image — minimal OS only; apps and drivers installed post-deployment via task sequence; most flexible, easiest to maintain
  • →Hybrid image — OS plus core applications; balance of deployment speed and maintainability

Windows ADK Tools

The Assessment and Deployment Kit provides essential imaging tools:

  • →DISM — mount, modify, and service WIM images offline (add drivers, packages, features)
  • →Sysprep — generalize an image by removing hardware-specific data and resetting SID
  • →Windows PE — minimal OS environment for deployment, recovery, and troubleshooting
  • →Windows SIM — create answer files (unattend.xml) for automated installations

SYSPREP KEY FACTS

  • sysprep /generalize — removes hardware-specific information, resets Windows activation
  • sysprep /oobe — configures next boot to run Out-of-Box Experience
  • sysprep /shutdown — shuts down after generalization (ready to capture)
  • Must run Sysprep before capturing a reference image to avoid duplicate SIDs on the network
  • Sysprep has a rearm limit — can only reset activation a limited number of times

User State Migration Tool (USMT)

Capture and restore user profiles, settings, and data during OS migration

USMT Commands

USMT consists of two primary command-line tools that work as a pair:

  • →ScanState.exe — captures user state from the source computer. Collects user profiles, documents, application settings, and OS settings. Run on the old OS before migration.
  • →LoadState.exe — restores captured user state to the destination computer. Applied after the new OS is installed. Restores profiles, files, and settings.
  • →USMTUtils.exe — utility for managing encrypted migration stores, extracting files, and verifying store integrity.

Migration XML Files

USMT uses XML configuration files to define what gets migrated:

  • →MigApp.xml — application settings (Office, IE, Windows Media Player, etc.)
  • →MigDocs.xml — user documents based on file extension rules
  • →MigUser.xml — user profile folders (Desktop, Documents, Favorites, etc.)
  • →Custom XML — define additional rules for proprietary applications or specific file locations
EXAM TIP

ScanState runs on the source (old) machine; LoadState runs on the destination (new) machine. USMT does not migrate applications themselves — only application settings. The apps must be installed separately on the new machine before running LoadState. USMT is part of the Windows ADK, not a standalone download.

USMT Migration Scenarios

Hard-link migration, side-by-side, and remote store strategies

🔗
Hard-Link Migration
Used for wipe-and-load on the same computer. Data stays on disk; USMT creates hard links instead of copying files. Fastest method — no network transfer required. Data remains in place during reinstall.
💾
Side-by-Side Migration
Migration between two different computers (replace scenario). ScanState on source stores data to a network share or removable media. LoadState on destination restores it. Standard for hardware refresh.
☁️
Remote Store
User state stored on a network file share. Useful for large organizations with centralized storage. Can be encrypted for security. Supports compression to reduce storage requirements.

USMT MIGRATION STORE TYPES

  • Uncompressed — plain file/folder structure on the store; easy to browse but uses most space
  • Compressed — single image file; reduced storage but cannot browse individual files
  • Hard-link — in-place migration store using NTFS hard links; fastest, no data copy needed
  • Encrypted — any store type can be encrypted with /encrypt flag; requires key for LoadState
Real-World Scenario
An organization is upgrading 500 workstations from Windows 10 to Windows 11 using a wipe-and-load method on the same hardware. To minimize downtime and avoid network bottlenecks, the IT team uses USMT with hard-link migration. ScanState creates hard links to user data on the local disk. The OS is reformatted around the migration store, and LoadState restores the data — all without any network transfer.

Provisioning Packages

Configure devices without reimaging using Windows Configuration Designer

Windows Configuration Designer

A tool for creating provisioning packages (.ppkg) that apply configurations to Windows devices without requiring a full reimage.

What packages can configure:

  • →Azure AD or domain join
  • →Wi-Fi profiles and VPN connections
  • →Certificates and security policies
  • →Edition upgrade (Pro to Enterprise)
  • →Start menu layout and desktop customization

Applying Provisioning Packages

Multiple methods to apply .ppkg files to devices:

  • →During OOBE — insert USB with .ppkg during first-run setup
  • →Settings app — Accounts > Access work or school > Add or remove a provisioning package
  • →Double-click — run the .ppkg file directly from Explorer
  • →Email/network share — distribute via internal channels
EXAM TIP

Provisioning packages are ideal for quickly configuring devices without reimaging. They can be applied during OOBE or on already-configured systems. Know that .ppkg files can perform Azure AD join, Wi-Fi setup, and even edition upgrade — all without touching the base OS image. This is a lighter alternative to full deployment for preconfigured hardware.

Deployment Planning

Pilot rings, scheduling, and rollback strategies for enterprise deployment

🧪
IT Team
First ring: IT staff test internally. Catch critical issues early. ~1% of organization.
👥
Early Adopters
Volunteer users across departments. Broader app testing. ~5-10% of organization.
🏢
Broad Deploy
Full deployment to remaining users. Phased by department or location. ~80-90%.
⚠️
Critical Systems
Mission-critical workstations deployed last. Maximum testing completed. ~5-10%.

DEPLOYMENT PLANNING CHECKLIST

  • Inventory all hardware and validate compatibility with target OS version
  • Catalog all applications and test against the target OS in a lab environment
  • Define deployment rings with clear success criteria for advancing to the next ring
  • Establish rollback procedures — know how to revert if critical issues arise
  • Plan network bandwidth — stagger deployments to avoid saturating WAN links
  • Train helpdesk staff on new OS features and known issues before broad deployment
  • Create a communication plan to inform users of deployment schedule and expectations
