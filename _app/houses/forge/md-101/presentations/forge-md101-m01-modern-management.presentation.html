MD-101 — Module 1

Enterprise Desktop Life Cycle

Five phases every device passes through in the enterprise

📋

1. Plan

Assess business requirements, determine hardware specifications, select Windows editions and licensing, define security baselines, and choose a management strategy (traditional, modern, or co-management). This phase drives every subsequent decision.

🛒

2. Purchase

Procure hardware from OEM vendors, negotiate volume licensing agreements (Microsoft 365 E3/E5, Windows Enterprise E3/E5), and arrange for device registration with Windows Autopilot through the hardware vendor or distributor.

📦

3. Deploy

Provision devices using traditional imaging (MDT/SCCM) or modern methods (Autopilot + Intune). Configure profiles, install applications, apply security policies, and join devices to Azure AD or on-premises Active Directory.

💻

4. Use (Manage)

Ongoing management: deploy updates via Windows Update for Business or WSUS, push application updates, enforce compliance policies, monitor device health, respond to security incidents, and provide helpdesk support.

5. Retire / Replace

  • Wipe corporate data from the device (full wipe or selective wipe via Intune)
  • Remove the device from Azure AD and Intune enrollment
  • Recycle or dispose of hardware according to environmental and data security policies
  • If BYOD: selective wipe removes only corporate data, personal data is untouched
  • The cycle restarts with planning for the replacement device
Exam Tip

The MD-101 exam tests the full life cycle. Expect questions about which phase a specific activity belongs to. For example, "defining compliance policies" is part of Plan, while "enforcing compliance policies" is part of Use/Manage. Know the distinction.

The Transition Reality

Most enterprises do not jump from traditional to modern overnight. Microsoft provides co-management as a bridge: devices are managed by both SCCM and Intune simultaneously. Workloads can be shifted from SCCM to Intune one at a time (compliance policies, device configuration, Windows Update, etc.) until full modern management is achieved.

Azure Active Directory

Cloud identity and access management for the modern enterprise

🔑

What is Azure AD?

Microsoft's cloud-based identity and access management service. It is not a cloud version of on-premises AD DS. Azure AD uses REST APIs and modern authentication protocols (OAuth 2.0, OpenID Connect, SAML) instead of LDAP and Kerberos.

👥

Azure AD Tenants

An Azure AD tenant is a dedicated instance of Azure AD that an organization receives when signing up for a Microsoft cloud service (Microsoft 365, Azure, Intune). Each tenant has its own directory of users, groups, and registered applications.

🔄

Azure AD Connect

Synchronizes on-premises AD DS identities to Azure AD, enabling hybrid identity. Users get a single identity that works for both on-premises and cloud resources. Supports password hash sync, pass-through authentication, and federation (AD FS).

🔐

Single Sign-On (SSO)

Azure AD enables SSO to thousands of SaaS applications (Salesforce, ServiceNow, Zoom, etc.) plus all Microsoft 365 services. Users authenticate once and access all assigned applications without re-entering credentials.

Exam Tip

Azure AD is NOT Active Directory Domain Services (AD DS) in the cloud. They are fundamentally different services. Azure AD uses flat structures (no OUs, no Group Policy, no LDAP). On-premises AD DS uses hierarchical OUs, Group Policy, Kerberos, and LDAP. Azure AD Connect bridges the two, but they are separate identity platforms.

Azure AD Registered vs. Azure AD Joined is a frequently tested distinction. Registered = BYOD, personal device, user signs in with a personal account. Microsoft Intune

Cloud-based unified endpoint management

📡

Mobile Device Management (MDM)

Full device management: enforce policies, deploy apps, configure Wi-Fi/VPN/email, manage updates, and perform remote actions (wipe, lock, retire). The device is enrolled in Intune and the organization has full control over device settings and security configuration.

📱

Mobile Application Management (MAM)

Application-level management without full device enrollment. Protects corporate data within apps using App Protection Policies (cut/copy/paste restrictions, PIN requirements, encryption). Ideal for BYOD scenarios where users reject full device management.

🌐

Multi-Platform Support

Intune manages Windows 10/11, macOS, iOS/iPadOS, Android, and Linux (Ubuntu). Each platform has specific enrollment methods and available policy types. Windows and iOS have the deepest management capabilities.

📊

Intune Admin Center

Web-based management console at intune.microsoft.com (formerly Endpoint Manager). Centralized dashboard for devices, apps, users, groups, compliance, configuration profiles, and reporting. Also accessible through the Microsoft 365 admin center.

Core Intune Capabilities

  • Device enrollment — Auto-enrollment, bulk enrollment, Autopilot
  • Configuration profiles — Device restrictions, Wi-Fi, VPN, email, certificates
  • Compliance policies — Define minimum security requirements for device access
  • App deployment — Required, available, and uninstall assignments
  • Conditional Access integration — Only compliant devices access corporate resources
  • Remote actions — Wipe, retire, lock, restart, sync, fresh start

Co-Management with SCCM

Bridge between traditional and modern management

🔗

What is Co-Management?

A device is simultaneously managed by both Microsoft Endpoint Configuration Manager (MECM/SCCM) and Microsoft Intune. This allows organizations to gradually shift workloads from on-premises SCCM to cloud-based Intune without a disruptive cutover.

🔧

Prerequisites

Hybrid Azure AD joined devices, Azure AD Connect configured, SCCM current branch (1710+), Intune subscription, and co-management enabled in the SCCM console. Devices must be in both management planes simultaneously.

Co-Management Workloads

  • Compliance policies — Shift compliance evaluation from SCCM to Intune
  • Device configuration — Use Intune profiles instead of GPOs for managed settings
  • Windows Update policies — Move from WSUS/SUP to Windows Update for Business
  • Resource access policies — Wi-Fi, VPN, email, and certificate profiles via Intune
  • Endpoint Protection — Manage Defender settings through Intune
  • Client apps — Deploy applications from Intune instead of SCCM
  • Office Click-to-Run apps — Manage Microsoft 365 Apps via Intune
Transition Strategy

A large enterprise with 5,000 SCCM-managed devices wants to move to modern management. The recommended approach:

  • 1Configure Hybrid Azure AD Join and Azure AD Connect
  • 2Enable co-management in SCCM console
  • 3Start with a pilot group — shift compliance policies to Intune first
  • 4Gradually move remaining workloads (configuration, updates, apps)
  • 5Once all workloads are in Intune, new devices can be Azure AD Joined only

Windows Autopilot

Zero-touch deployment from factory to user

🚀

How Autopilot Works

The hardware vendor registers device hardware hashes with the organization's Azure AD tenant. When a user unboxes the device and connects to the internet, Windows OOBE contacts Azure AD, identifies the device, and automatically applies the Autopilot deployment profile, enrolls in Intune, and configures the device.

📦

No Imaging Required

Unlike traditional deployments (MDT/SCCM), Autopilot uses the OEM-installed Windows image. No custom images to build, maintain, or distribute. Configuration is applied via Intune profiles, not baked into an image. This dramatically reduces deployment infrastructure.

👤

User-Driven Mode

The user powers on the device, selects language/keyboard, connects to Wi-Fi, and signs in with their Azure AD credentials. Everything else is automated: Azure AD join, Intune enrollment, policy application, app installation. No IT technician required.

🤖

Self-Deploying Mode

For shared devices, kiosks, and digital signage. No user interaction required after network connection. The device automatically joins Azure AD, enrolls in Intune, and configures itself. Requires TPM 2.0 for device attestation.

Exam Tip

Autopilot requires three things: Azure AD Premium P1 (or higher), Microsoft Intune (or equivalent MDM), and devices with hardware hashes registered in the tenant. Autopilot does NOT require on-premises infrastructure, WDS, or MDT. It also requires the device to have internet access during the OOBE.

Matching the right Autopilot mode to the right use case

Scenario Mode User Interaction TPM Required
New employee receives laptop User-driven Sign in with Azure AD credentials Recommended
Shared kiosk / digital signage Self-deploying None (fully automated) Required (2.0)
Existing device re-provisioning Autopilot Reset None (remote trigger) No

Pre-Provisioning (White Glove) Flow

For organizations that need apps pre-installed before the user receives the device:

  • 1IT technician boots the device and presses Windows key 5 times during OOBE
  • 2Device connects to Azure AD and downloads the Autopilot profile
  • 3Device-targeted apps and policies are installed (device context)
  • 4Technician verifies and reseals the device
  • 5User receives the device, signs in, and user-targeted apps install
Exam Tip

Self-deploying mode requires TPM 2.0 because device attestation (proving the device is who it claims to be without a user) relies on the hardware TPM. User-driven mode does not strictly require TPM, but it is recommended. Pre-provisioning also requires TPM 2.0.

Summary

Module 1 consolidated — modern management foundations

🔄

Life Cycle Phases

Plan, Purchase, Deploy, Use/Manage, Retire/Replace. Each phase maps to specific tools and processes. Modern management shifts every phase toward cloud services.

🔑

Azure AD Identity

Three device identity types: Registered (BYOD), Joined (cloud-only corporate), Hybrid Joined (on-prem + cloud). Azure AD is NOT AD DS in the cloud. Azure AD Connect bridges the two.

📡

Intune Capabilities

MDM for full device management, MAM for app-level protection without enrollment. Supports Windows, macOS, iOS, Android, and Linux. Configuration profiles, compliance policies, app deployment, remote actions.

🚀

Autopilot

Zero-touch cloud deployment. User-driven (standard), Self-deploying (kiosks, TPM 2.0 required), Pre-provisioning (IT pre-stages), Reset (re-provision existing). No imaging infrastructure needed.

Critical Exam Facts

  • Azure AD Registered = BYOD; Azure AD Joined = corporate cloud-only; Hybrid = both AD DS + Azure AD
  • Co-management requires Hybrid Azure AD Join, SCCM current branch, and Intune subscription
  • Autopilot Self-Deploying mode requires TPM 2.0 for device attestation
  • Azure AD P1 = Conditional Access; Azure AD P2 = Identity Protection + PIM
  • MAM without enrollment protects corporate data on personal devices without full MDM control
  • Intune is included in Microsoft 365 Business Premium, E3, and E5 plans
