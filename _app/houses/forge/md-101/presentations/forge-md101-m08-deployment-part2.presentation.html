Windows Autopilot Overview

Cloud-driven, zero-touch device provisioning for modern enterprises

What is Autopilot?

Windows Autopilot is a collection of technologies that set up and pre-configure new devices, getting them business-ready. It eliminates the need for custom OS images.

How it works:

  • 1. OEM registers device hardware hash with your Azure AD tenant
  • 2. IT creates Autopilot deployment profile in Intune
  • 3. Device ships directly to end user
  • 4. User powers on and connects to internet
  • 5. Device auto-configures based on the profile — joins Azure AD, enrolls in Intune, installs apps

Requirements

Autopilot requires specific infrastructure and licensing:

  • →Azure AD Premium P1 (or higher) for automatic MDM enrollment
  • →Microsoft Intune (or another MDM service)
  • →Windows 10/11 Pro, Enterprise, or Education
  • →Internet connectivity — device must reach Microsoft cloud services
  • →Hardware hash registered in the Autopilot service
EXAM TIP

The hardware hash uniquely identifies each device and links it to your Azure AD tenant. It can be collected by the OEM, extracted using a PowerShell script (Get-WindowsAutopilotInfo), or obtained from an existing Intune-enrolled device. Without the hardware hash registered, the device will not receive its Autopilot profile at OOBE.

Autopilot Deployment Scenarios

User-driven, self-deploying, pre-provisioned, and Autopilot Reset

User-Driven Mode
Most common scenario. User powers on the device, enters Azure AD credentials, and the device automatically configures itself. The user sees a streamlined OOBE with organizational branding. Device joins Azure AD and enrolls in Intune. Apps and policies deploy in the background.
Self-Deploying Mode
Fully automated — no user interaction required. Designed for shared devices, kiosks, and digital signage. Device powers on, connects to network, and provisions itself entirely. Requires TPM 2.0 for device attestation. Does not support Hybrid Azure AD Join.
Pre-Provisioned (White Glove)
Split provisioning between IT and end user. IT (or partner) completes initial setup: Azure AD join, Intune enrollment, device-targeted apps and policies. Device is then shipped to user who completes the user-specific portion. Reduces user wait time to minutes.
Autopilot Reset
Repurpose an existing device for a new user without reimaging. Removes user data, apps, and settings while preserving the OS, Azure AD join, and Intune enrollment. Device returns to a business-ready state. Triggered remotely from Intune or locally.

AUTOPILOT PROFILE SETTINGS

  • Skip privacy settings — hide privacy configuration screens during OOBE
  • Hide EULA — suppress the license agreement screen
  • Disable local admin — prevent user from creating a local admin account
  • Apply device name template — auto-name devices (e.g., CONTOSO-%SERIAL%)
  • User account type — set the user as Standard User or Administrator

Azure AD Join Types

Cloud-only join, hybrid join, and Azure AD registration — know the differences

☁️
Azure AD Joined
Cloud-only identity. Device exists only in Azure AD. Managed exclusively by Intune. No on-prem AD dependency. Best for cloud-first organizations. Users sign in with Azure AD credentials.
🔄
Hybrid Azure AD Joined
Device joined to both on-prem AD and Azure AD. Requires Azure AD Connect sync. Supports both Group Policy and Intune. Transition state for organizations moving to cloud. SSO to both cloud and on-prem resources.
📱
Azure AD Registered
BYOD scenario. Device is personal, not corporate. User adds work account to access corporate resources. Device is not fully managed. Supports conditional access for app-level control. No domain join.

Dynamic Provisioning

Transform new devices into managed endpoints using cloud services and runtime configuration

Enrollment Status Page (ESP)

The ESP tracks device provisioning progress and prevents users from accessing the desktop until critical configurations are complete.

  • →Device preparation — Intune enrollment and policy application
  • →Device setup — device-targeted apps and security policies install
  • →Account setup — user-targeted apps and policies deploy
  • →Can block usage until all required apps are installed
  • →Configurable timeout (default: 60 minutes)

MDM Automatic Enrollment

When a user joins a device to Azure AD, it can automatically enroll in Intune without any additional user action.

  • →Azure AD Premium P1 required for auto-enrollment
  • →Configure MDM scope in Azure AD > Mobility (MDM and MAM)
  • →Set scope to All or specific security groups
  • →Works with both Azure AD Join and Hybrid Azure AD Join
Autopilot + ESP Flow
A new employee receives a laptop shipped directly from Dell. They power it on at home, connect to Wi-Fi, and sign in with their corporate Azure AD credentials. The Enrollment Status Page appears showing progress: Device preparation (joining Azure AD, enrolling in Intune) → Device setup (security baselines, VPN profile, certificates) → Account setup (Office 365, Teams, company portal). Once complete, the user reaches a fully configured desktop with all required applications installed.

Subscription Activation

Upgrade Windows editions via licensing without reimaging or product keys

How Subscription Activation Works

Subscription activation enables a seamless step-up from Windows Pro to Enterprise when a user with an appropriate license signs in.

  • →Device must be running Windows 10/11 Pro
  • →User needs a Windows Enterprise E3/E5 or Microsoft 365 E3/E5 license
  • →Device must be Azure AD joined or Hybrid Azure AD joined
  • →Upgrade happens automatically at sign-in — no reboot required
  • →If license is removed, device reverts to Pro after grace period

Edition Upgrade Paths

Windows supports specific edition upgrade paths. Not all combinations are valid:

  • →Pro → Enterprise — subscription activation or product key
  • →Pro → Education — product key or provisioning package
  • →Home → Pro — product key through Settings or Microsoft Store
  • →Enterprise → Home — not supported (clean install required)
EXAM TIP

Subscription activation is license-based, not image-based. The underlying OS bits for Enterprise are already present in Pro — the license simply unlocks them. Know that subscription activation requires Azure AD (joined or hybrid) and a qualifying E3/E5 license. Devices revert to Pro if the license is removed. This is the modern alternative to KMS and MAK volume activation.

Co-Management

Simultaneously manage devices with Configuration Manager and Intune

What is Co-Management?

Co-management enables concurrent management of Windows devices by both SCCM (Configuration Manager) and Intune. Organizations can gradually transition workloads from on-premises to cloud management.

Prerequisites:

  • →Azure AD Premium P1 license
  • →Intune subscription
  • →Configuration Manager current branch (version 1710+)
  • →Hybrid Azure AD Join (devices in both AD and Azure AD)
  • →Azure AD Connect configured

Co-Management Workloads

Each workload can be independently switched between SCCM and Intune:

  • →Compliance policies
  • →Device configuration
  • →Windows Update policies
  • →Resource access policies
  • →Endpoint protection
  • →Client apps
  • →Office Click-to-Run apps
EXAM TIP

Co-management is the bridge strategy for organizations transitioning from SCCM to Intune. Each workload can be moved independently using a slider between Configuration Manager, Pilot Intune, and Intune. Know that Conditional Access requires the compliance workload to be managed by Intune. The exam frequently tests which workloads should move first and the prerequisites for enabling co-management.

Cloud Attach & Tenant Attach

Connecting Configuration Manager to the Microsoft cloud ecosystem

Tenant Attach

Upload your Configuration Manager device inventory to the Intune admin center. Enables cloud-based actions on SCCM-managed devices without full co-management.

  • →View SCCM devices in the Intune admin center
  • →Run CMPivot queries from the cloud
  • →Deploy Endpoint Security policies to SCCM devices
  • →View device timeline and inventory remotely
  • →Lower barrier to entry than full co-management

Cloud Management Gateway (CMG)

A cloud-based service that enables SCCM to manage internet-based clients without VPN. Essential for remote workers.

  • →Deployed as an Azure cloud service
  • →Proxies client communication to on-prem SCCM infrastructure
  • →Supports software updates, inventory, and compliance
  • →Certificate-based or Azure AD token authentication
  • →No VPN required for remote management

CLOUD INTEGRATION PROGRESSION

  • Step 1: Tenant attach — upload inventory to Intune admin center (lowest effort)
  • Step 2: CMG — manage internet clients via cloud proxy
  • Step 3: Co-management — gradually move workloads to Intune
  • Step 4: Cloud-native — Azure AD join + Intune only (fully modern)

Autopilot for Existing Devices

Extending Autopilot to devices already in your environment

Autopilot for Existing Devices

Enables the Autopilot user-driven experience on devices already deployed with Configuration Manager. Useful for transitioning existing SCCM-managed devices to modern management.

Process:

  • 1. Create an Autopilot profile JSON file
  • 2. Create a SCCM task sequence that reimages the device
  • 3. Task sequence deploys the Autopilot profile JSON to the device
  • 4. Device reboots into OOBE and follows the Autopilot flow
  • 5. Device joins Azure AD and enrolls in Intune

Hybrid Azure AD Join with Autopilot

Autopilot supports Hybrid Azure AD Join for organizations that still require on-premises AD domain join:

  • →Requires the Intune Connector for Active Directory on-premises
  • →Connector creates the computer object in on-prem AD
  • →Device line-of-sight to a domain controller is required
  • →Azure AD Connect syncs the device object to Azure AD
  • →Slower than pure Azure AD join due to sync dependency
EXAM TIP

Autopilot for existing devices uses a Configuration Manager task sequence to reimage the device and inject the Autopilot profile. The device does NOT need its hardware hash pre-registered — the profile JSON file provides the configuration. For Hybrid Azure AD Join via Autopilot, the Intune Connector for Active Directory must be installed on-premises and the device must have line-of-sight to a domain controller.

Modern Management Strategy

Planning the transition from traditional to modern endpoint management

Traditional Management
On-premises AD + Group Policy + SCCM. Custom images. VPN-dependent remote management. Hardware-specific driver packs. Proven but inflexible for modern work.
Hybrid / Co-Managed
SCCM + Intune co-management. Hybrid Azure AD Join. Gradual workload migration. CMG for internet clients. Transition state enabling measured cloud adoption.
Cloud-Native
Azure AD Join + Intune only. Windows Autopilot deployment. No on-prem infrastructure dependency. Zero-touch provisioning. Optimal for remote-first organizations.
