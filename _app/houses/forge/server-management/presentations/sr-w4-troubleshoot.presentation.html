Troubleshooting Methodology
A structured approach to server problem diagnosis.
CompTIA Steps
1. Identify the problem. 2. Establish theory of probable cause. 3. Test the theory. 4. Plan of action. 5. Implement. 6. Verify full functionality. 7. Document findings.
Key Questions
What changed recently? When did it start? Who is affected? Is it reproducible? Correlate with Event Viewer timestamps and recent changes.

Boot Failures
When the server will not start.
Common Issues
Missing/corrupt bootloader (BCD). BSOD during boot (driver conflict). Boot device not found (disk failure/BIOS change). Stuck at logo (driver/service hang).
Recovery Tools
WinRE from install media. bootrec /fixmbr, /fixboot, /rebuildbcd. Safe Mode (bcdedit /set safeboot minimal). Last Known Good. BMR from backup.
Slide 4 of 10
BSOD Analysis
Kernel-mode crashes that halt the OS.
Common Stop Codes
IRQL_NOT_LESS_OR_EQUAL: driver accessing invalid memory. KERNEL_DATA_INPAGE_ERROR: disk read failure. SYSTEM_SERVICE_EXCEPTION: driver/system service crash.
Memory Dump Analysis
Configure kernel dump in Startup and Recovery settings. Analyze with WinDbg: !analyze -v identifies faulting driver/module.

Service & Performance Issues
When services fail or resources are exhausted.
Service Failures
Check service status: Get-Service. Check Event Viewer for error events. Common causes: dependency down, port conflict, permissions, missing DLL. Configure recovery actions.
CPU Bottleneck
High CPU in Task Manager. Identify consuming process. Solutions: optimize app, add cores, check for malware.
Memory Bottleneck
Available MBytes near zero, high Pages/sec. Find memory leaks (rising handle count). Add RAM or reduce services.

Network Diagnostics
Diagnosing server connectivity problems.
Key Commands
Test-NetConnection -Port 443 (TCP test), ipconfig /all, nslookup, tracert, netstat -ano (active connections + PIDs).
Common Issues
Wrong IP/subnet. DNS failure. Firewall blocking. NIC teaming failure. VLAN misconfiguration.
Slide 7 of 10
Runbooks & SOPs
Operational documentation for consistent incident response.
What to Document
Server inventory (hardware, OS, roles, IPs, dependencies). SOPs for common tasks. Runbooks for incident response. Network diagrams. Credential vault.
Runbook Contents
Problem description + symptoms. Diagnostic steps (what to check, in order). Resolution steps (exact commands). Escalation path. Post-resolution verification.
Slide 8 of 10
Change Management
Controlling changes to prevent self-inflicted outages.
Change Process
1. Submit change request. 2. CAB review/approve. 3. Schedule maintenance window. 4. Implement with rollback ready. 5. Verify. 6. Document. 7. Close.
Rollback Plans
Every change needs a rollback plan. Checkpoint VMs before changes. Document exact undo steps. Define rollback decision point. Test in staging first.

Server Core Troubleshooting
Diagnostic commands essential for headless servers.
Essential Commands
sconfig (menu), Get-EventLog (events), Get-Process | Sort CPU -Desc (top CPU), Get-Counter (perf counters), Restart-Service.
Remote Tools
Windows Admin Center (browser GUI). Remote PowerShell (Enter-PSSession). Remote Event Viewer. Remote PerfMon. All via WinRM.
