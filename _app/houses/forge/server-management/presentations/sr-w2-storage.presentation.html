Basic vs Dynamic Disks
Two disk types in Windows -- basic uses traditional partitions, dynamic supports advanced volumes.
Basic Disks
Traditional partition table (MBR or GPT). Up to 4 primary partitions (MBR) or 128 (GPT). Simple volumes only. Compatible with all OSes. Default for new disks.
Dynamic Disks
Support spanned, striped, mirrored, RAID-5 volumes. Can span multiple physical disks. Being replaced by Storage Spaces. Not recommended for new deployments.
Slide 3 of 10
MBR vs GPT
Partition styles determine disk layout structure.
MBR (Master Boot Record)
Legacy. Max 4 primary partitions. Max 2 TB disk size. Single point of failure. Required for BIOS boot.
GPT (GUID Partition Table)
Modern. 128 partitions. 18.8 EB max. Redundant tables. CRC checksums. Required for UEFI. Use for all new servers.
Slide 4 of 10
NTFS vs ReFS
Two file systems -- NTFS is the workhorse, ReFS is for resilience.
NTFS
Standard FS. Permissions (ACLs), EFS encryption, compression, quotas, dedup. Required for boot volume. Max 256 TB. Battle-tested.
ReFS
Resilient File System. Auto integrity/corruption repair via checksums. No EFS/compression. Cannot boot. Ideal for Hyper-V VHD storage and backup targets.
Slide 5 of 10
Storage Spaces
Software-defined storage -- pool physical disks into flexible, resilient virtual disks.
Simple
Striping for performance. No redundancy. Use for temp/scratch data only. Min 1 disk.
Mirror
Two-way or three-way mirroring. Survives 1-2 disk failures. Best for critical data. Min 2 or 5 disks.
Parity
Erasure coding (RAID 5/6-like). Efficient capacity. Slower writes. Best for archival. Min 3 or 7 disks.
Slide 6 of 10
iSCSI Storage
Block-level storage over the network -- remote storage appears as local disks.
iSCSI Target
Server presenting storage. Built-in role in Windows Server. Creates virtual disks (VHDs) as LUNs. Common for Hyper-V shared storage and clustering.
iSCSI Initiator
Client consuming storage. Built into Windows (iscsicpl.exe). Connects via IQN. CHAP authentication. Dedicated NICs recommended. MPIO for redundancy.
Slide 7 of 10
SMB Shares & Permissions
File-level sharing -- the backbone of Windows file servers.
Share Permissions
Applied at share level. Read, Change, Full Control. Best practice: Everyone = Full Control, then control via NTFS only.
NTFS Permissions
Applied at file/folder level. Granular: Read, Write, Modify, Full Control. Inherited from parent. The real access control layer.
Effective Permissions
Most restrictive wins when both apply. Share=Full Control + NTFS=Read = Read access for the user.
Slide 8 of 10
DFS & FSRM
Unified file share paths, replication, quotas, and file screening.
DFS Namespaces
Single virtual path (\\corp.local\shares) mapping to multiple servers. Users see one unified tree. Domain-based namespaces replicate via AD.
DFS Replication
Replicates folder contents between servers. Remote Differential Compression -- only changed blocks transfer. Great for branch office sync.
FSRM
Quotas (hard/soft), file screening (block .exe/.mp3), storage reports (duplicate files, usage by owner). Capacity management essentials.
Slide 9 of 10
Data Deduplication & Best Practices
Eliminate duplicate data and follow production storage guidelines.
Deduplication
Scans for duplicate data chunks. Stores unique chunks once. 30-50% savings on file shares, 80-95% on VDI. Not for active databases.
Best Practices
Separate OS and data volumes. Use RAID/mirror for production. Monitor at 80% capacity. Storage resilience is NOT backup -- both are required.

Week 2 Summary
Storage Management and File Systems -- key takeaways.
1Disk types: Basic (standard) vs Dynamic (legacy advanced). Use basic + Storage Spaces.
2Partitions: GPT for all new servers. MBR only for legacy BIOS.
3File systems: NTFS for most workloads. ReFS for Hyper-V and backups.
4Storage Spaces: Simple/Mirror/Parity. S2D for multi-server pooling (Datacenter only).
5Network storage: iSCSI (block-level), SMB (file-level), DFS (namespace/replication).
6Management: FSRM quotas/screening, deduplication, PowerShell disk cmdlets.
