Monitoring & Backup
Performance Monitor -- Event Viewer -- Resource Monitor -- Backup Types -- BMR -- VSS
A server that is not monitored is a server waiting to fail. Monitoring detects problems before they cause outages. Backups ensure recovery when prevention fails. Together they form the foundation of operational resilience.

Performance Monitor
Real-time and historical performance data collection.
Key Counters
CPU: % Processor Time (>85% = bottleneck). Memory: Available MBytes (<200 MB = low). Disk: Avg. Disk Queue Length (>2/spindle = bottleneck). Network: Bytes Total/sec.
Data Collector Sets
Schedule counter collection over hours/days. Analyze trends. Built-in templates: System Performance, System Diagnostics. Export to CSV.
Alerts
Trigger actions when thresholds are crossed. Send email, start data collection, or run a script. Example: alert when free space < 10%.
Slide 3 of 8
Event Viewer
Centralized log viewer for system, application, and security events.
Log Types
System: OS events. Application: software events. Security: audit events (logon, file access). Setup: role installation.
Key Event IDs
4625: Failed logon. 4624: Successful logon. 7036: Service state change. 1074: Shutdown/restart. 41: Unexpected power loss.
Event Subscriptions
Forward events from multiple servers to one collector for centralized monitoring. Filter by source, level, or ID.

Windows Server Backup
Built-in backup solution -- no third-party required.
Backup Types
Full: entire volume. Incremental: only changed blocks since last backup. WSB does full + incremental (no differential). Schedule via wbadmin or GUI.
System State
Registry, AD database (on DCs), boot files, COM+, certificate services, SYSVOL. Critical for AD disaster recovery. wbadmin start systemstatebackup.
Bare Metal Recovery
Complete volume restore. OS + roles + data. Boot from install media > Repair > System Image Recovery. Server reboots exactly as at backup time.
Slide 5 of 8
VSS -- Volume Shadow Copy Service
Application-consistent snapshots of volumes while services run.
How VSS Works
Coordinates backup app (requester), VSS service, and applications (writers). Writers flush + freeze I/O. Shadow copy created. Writers resume. Backup reads from shadow copy.
Shadow Copies for Users
Enable per-volume. Users restore via right-click > Previous Versions. Schedule twice daily. Stored on same volume. Not a backup replacement.
Slide 6 of 8
Backup Strategy
Designing backup plans around RPO and RTO requirements.
RPO (Recovery Point Objective)
Maximum acceptable data loss. RPO=4hr means backups every 4 hours minimum. Drives backup frequency.
RTO (Recovery Time Objective)
Maximum acceptable downtime. RTO=30min means recovery must complete in 30 minutes. Drives backup type and storage location.
Slide 7 of 8
Monitoring Best Practices
Production monitoring guidelines.
Baseline Everything
Capture normal performance metrics during typical workloads. Compare current metrics to baseline to detect deviations before they become outages.
Centralize Logs
Use event subscriptions or a SIEM to collect logs from all servers. Correlate events across systems. Set alerts for critical/error events.
Test Restores
A backup that has never been tested is not a backup. Schedule quarterly restore tests. Document recovery time. Verify data integrity.

Week 3 Summary
Monitoring and Backup -- key takeaways.
1PerfMon: Key counters for CPU, memory, disk, network. Data Collector Sets for trends.
2Event Viewer: System/Application/Security logs. Event IDs 4625, 7036, 41. Subscriptions for centralization.
3Backup types: Full + incremental. System State for AD. Bare Metal Recovery for complete restore.
4VSS: Application-consistent snapshots. Shadow Copies for user self-service file recovery.
5RPO/RTO: RPO drives frequency. RTO drives backup type and storage proximity.
6Best practices: Baseline metrics, centralize logs, test restores quarterly.
