Virtualization with Hyper-V
Hypervisor Types -- VM Creation -- Virtual Switches -- Checkpoints -- Live Migration -- Replica
Hyper-V transforms a single physical server into a platform hosting dozens of isolated virtual machines. Understanding hypervisor architecture, virtual networking, resource allocation, and migration is essential for modern server administration.

Hypervisor Types
Type 1 runs on bare metal. Type 2 runs on top of an OS.
Type 1 -- Bare Metal
Installs directly on hardware. No host OS. Better performance. Examples: Hyper-V, VMware ESXi, KVM. Production data centers.
Type 2 -- Hosted
Runs as an app on a host OS. More overhead. Examples: VirtualBox, VMware Workstation. Development/testing only.
Slide 3 of 10
VM Creation
Define CPU, memory, storage, and network for each VM.
Generation 1
Legacy BIOS. IDE boot disk. For older OSes (Server 2008). Use only when required.
Generation 2
UEFI + Secure Boot. SCSI boot. Faster. PXE from vNIC. For Windows 2012+ and modern Linux. Use for all new VMs.
Slide 4 of 10
Virtual Switches
Three types control VM network connectivity.
External
Binds to physical NIC. VMs reach physical network + internet. Most common for production.
Internal
VMs + host communication. No physical network. For management/host-to-VM.
Private
VMs only. Complete isolation. For testing and security labs.
Slide 5 of 10
Checkpoints & Integration Services
Point-in-time VM snapshots and host-guest coordination.
Production Checkpoints
VSS-based (Windows) or fs-freeze (Linux). Application-consistent. Safe for production. Default since 2016.
Standard Checkpoints
Captures memory state. Exact point-in-time. Good for testing. Not production-safe.
Integration Services
Time sync, data exchange (KVP), heartbeat, guest shutdown, VSS. Improve VM performance and manageability.
Slide 6 of 10
Resource Allocation
Controlling how VMs share host CPU, memory, and storage.
CPU Weight & Limits
Reserve: guaranteed minimum %. Limit: max %. Weight: relative priority under contention. Default weight: 100.
Dynamic Memory
Startup/min/max RAM range. Auto-adjusts based on demand. Memory buffer for spikes. Smart Paging as last resort.
Storage QoS
Min/max IOPS per virtual disk. Prevents I/O monopolization. Critical for shared storage.
Slide 7 of 10
Live Migration
Move running VMs between hosts with zero downtime.
Live Migration
Transfers running VM memory/state to another host. Sub-second pause. Requires compatible CPUs and network connectivity.
Storage Migration
Moves VM disks between storage locations while running. No shared storage required. Combine with live migration for full mobility.
Slide 8 of 10
Hyper-V Replica
Asynchronous VM replication for disaster recovery.
How It Works
Primary replicates VM changes to replica host every 30s/5m/15m. HTTP/HTTPS. No shared storage needed. Replica stays off until failover.
Failover Types
Planned: graceful, zero data loss. Unplanned: primary is down, start from last replication point. Extended: chain a third host.
Slide 9 of 10
Hyper-V Security
Securing the hypervisor and virtual machines.
Shielded VMs
Datacenter only. Encrypts VM state/disks via Host Guardian Service. Protects from compromised hosts/admins. Uses vTPM + BitLocker.
Secure Boot
Gen 2 VMs support UEFI Secure Boot. Prevents unauthorized bootloaders inside VMs.
Network Isolation
Private switches, VLAN tagging, port ACLs, extended port ACLs for stateful filtering.

Week 2 Summary
Virtualization with Hyper-V -- key takeaways.
1Hypervisors: Type 1 (Hyper-V, ESXi) for production. Type 2 (VirtualBox) for labs.
2VM creation: Generation 2 for all new VMs. VHDX (64 TB max). Dynamic Memory.
3Switches: External (production), Internal (host+VMs), Private (isolated).
4Checkpoints: Production (VSS) for production. Standard for testing. NOT backups.
5Live migration: Zero-downtime VM movement. Storage migration for disks.
6Replica: Async DR replication. 30s/5m/15m intervals. No shared storage needed.
