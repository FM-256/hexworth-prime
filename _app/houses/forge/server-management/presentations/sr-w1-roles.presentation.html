Server Roles & Features
AD DS -- DNS -- DHCP -- File Server -- IIS -- Print Server -- PowerShell Management
A bare Windows Server does nothing until you install roles. Roles define what the server does (domain controller, DNS server, web server). Features add supporting capabilities (.NET, Windows Backup, Telnet). This deck covers the core roles every server admin must know.

Roles vs Features
Roles define the server's primary function. Features add supporting capabilities.
Server Roles
Primary services the server provides to the network: AD DS, DNS, DHCP, File Server, Web Server (IIS), Print Server, Hyper-V, Remote Desktop Services. A server typically runs 1-3 roles.
Features
Supporting tools and services: .NET Framework, Windows Backup, Telnet Client, SNMP, BitLocker, Failover Clustering, Windows Subsystem for Linux. Features support roles or add standalone capabilities.
Role dependencies: Some roles require specific features. When you install AD DS, the wizard automatically adds required features like Group Policy Management and DNS. PowerShell: Install-WindowsFeature -Name AD-Domain-Services -IncludeManagementTools

Active Directory Domain Services
The identity backbone -- centralized authentication, authorization, and policy management.
What AD DS Does
Stores user accounts, computer objects, groups, and OUs in a hierarchical database. Authenticates logons via Kerberos. Enforces Group Policy (GPOs) for security and configuration.
Domain Controllers (DCs)
Servers running AD DS. Multi-master replication -- changes on any DC replicate to all others. Minimum: 2 DCs per domain for redundancy. FSMO roles distribute special operations.
Key Components
Forest: Top-level container. Domain: Security boundary. OU: Organizational unit for GPO targeting. Sites: Physical topology for replication optimization.
PowerShell: Install-ADDSForest -DomainName "corp.local" promotes the first DC. Install-ADDSDomainController adds additional DCs. Always have at least 2 DCs.

DNS Server Role
Name resolution -- translating hostnames to IP addresses. Required for Active Directory.
Forward Lookup Zones
Hostname to IP: SRV-DC01.corp.local resolves to 10.0.0.10. A records (IPv4) and AAAA records (IPv6). CNAME records create aliases (mail.corp.local pointing to SRV-EXCH01).
Reverse Lookup Zones
IP to hostname: 10.0.0.10 resolves to SRV-DC01.corp.local. PTR records. Required for some services (email SPF, security auditing). Create for each subnet.
AD-Integrated DNS
DNS zones stored in Active Directory (not flat files). Secure dynamic updates. Multi-master replication with AD. Automatic cleanup (scavenging) of stale records. Best practice for AD environments.
Why DNS + AD: Active Directory clients use DNS SRV records to locate domain controllers. Without DNS, no client can find a DC to authenticate. DNS is always installed alongside AD DS -- they are inseparable in practice.

DHCP Server Role
Automatic IP address assignment -- eliminate manual IP configuration for clients.
DHCP Scopes
Define an IP range (e.g., 10.0.0.100 - 10.0.0.200), subnet mask, default gateway, DNS servers, and lease duration. Exclusion ranges reserve IPs for static devices (printers, servers).
DHCP Reservations
Bind a specific IP to a device's MAC address. The device always gets the same IP from DHCP. Best for printers, network devices, and servers that need predictable IPs without manual config.
DORA process: Discover (client broadcasts), Offer (server proposes IP), Request (client accepts), Acknowledge (server confirms lease). DHCP must be authorized in AD before it will serve addresses -- prevents rogue DHCP servers.

File Server & Storage Roles
Centralized file storage, sharing, and access control.
SMB File Shares
Server Message Block protocol. Create shared folders accessible via UNC paths (\\SRV-FILE01\Sales). SMB 3.x supports encryption, multichannel, and failover. PowerShell: New-SmbShare
NTFS Permissions
File-level access control. Inherited from parent folders. Combine with share permissions (most restrictive wins). Best practice: Share = Everyone Full Control, control access via NTFS only.
DFS & FSRM
DFS Namespaces: Single UNC path across multiple servers (\\corp.local\shares). DFS Replication: Sync folders between servers. FSRM: Quotas, file screening, storage reports.
Access-Based Enumeration (ABE): Users only see files/folders they have permission to access. Enable per-share to prevent users from seeing folder names they cannot open -- critical for compliance.
Slide 7 of 13
Web Server (IIS)
Internet Information Services -- hosting websites, web apps, and APIs on Windows Server.
Sites & Bindings
Each site has bindings: IP address, port, host header. Multiple sites on one server use different host headers or ports. Default site listens on port 80 (HTTP) and 443 (HTTPS).
Application Pools
Worker processes (w3wp.exe) that run site code. Each app pool runs under its own identity. Isolates sites -- one crash does not affect others. Configure recycling schedule for stability.
SSL/TLS Certificates
Bind SSL certificates to HTTPS bindings. Use internal CA for intranet or public CA (Let's Encrypt, DigiCert) for internet-facing. TLS 1.2+ required -- disable older protocols.
PowerShell: Install-WindowsFeature -Name Web-Server -IncludeManagementTools installs IIS. New-WebSite -Name "Intranet" -PhysicalPath "C:\inetpub\intranet" -HostHeader "intranet.corp.local"

Print Server Role
Centralized printer management -- deploy printers via Group Policy, monitor queues, manage drivers.
Print Management Console
Single pane of glass for all printers. Add/remove printers, manage queues, deploy via GPO, install drivers. Filter views by status (error, warning, ready). Monitor print volume per printer.
GPO Printer Deployment
Deploy printers to users or computers via Group Policy. User-based: printers follow the user. Computer-based: printers are tied to the workstation. Use Print Management to generate the GPO link.
Driver isolation: Run printer drivers in isolated processes (not shared with the spooler). If a bad driver crashes, it does not take down the entire print service. Enable via Print Management properties.

Key Features
Features you will install alongside roles -- supporting tools and services.
.NET Framework
Required by many applications and roles. 3.5 (legacy apps) and 4.x (modern) both available. Install both for compatibility.
Windows Backup
Built-in backup solution. System State, bare metal, volume-level. Schedule via wbadmin or GUI. Covered in Week 3.
Telnet Client
Not installed by default. Used for testing TCP port connectivity (telnet server 25). Quick test: is the port open? Replaced by Test-NetConnection.
Failover Clustering
Enables HA for Hyper-V, file servers, SQL Server. Requires shared storage. Covered in detail in Week 3.
PowerShell: Get-WindowsFeature | Where-Object InstallState -eq Installed lists all currently installed roles and features. Install-WindowsFeature -Name Telnet-Client adds a feature.

PowerShell Role Management
Every role and feature can be installed, configured, and removed via PowerShell.
1Get-WindowsFeature -- list all roles/features with install status
2Install-WindowsFeature -Name DNS -IncludeManagementTools -- install DNS with admin tools
3Uninstall-WindowsFeature -Name Print-Server -Remove -- remove role AND binaries from disk
4Install-WindowsFeature -Name DHCP -ComputerName SRV-DHCP01 -- install remotely
5Add-DhcpServerv4Scope -Name "LAN" -StartRange 10.0.0.100 -EndRange 10.0.0.200 -SubnetMask 255.255.255.0
6Add-DnsServerPrimaryZone -Name "corp.local" -ReplicationScope Domain -- create AD-integrated zone
7New-ADUser -Name "Jane Doe" -SamAccountName jdoe -Enabled $true -AccountPassword (ConvertTo-SecureString "P@ss" -AsPlainText -Force)
Script it: PowerShell scripts make role deployment repeatable and auditable. Save your server build scripts in version control. Use Desired State Configuration (DSC) for automated compliance enforcement.
Slide 11 of 13
Role Dependencies
Some roles require other roles or features to function. The wizard handles this automatically.
AD DS Requires DNS
Active Directory stores SRV records in DNS for DC location. If DNS is not installed, the AD DS wizard will install it automatically. Best practice: co-locate DNS on every DC.
Failover Clustering + Hyper-V
Clustered Hyper-V requires the Failover Clustering feature, shared storage (iSCSI/FC/S2D), and the Hyper-V role on all nodes. The cluster validates prerequisites before creation.
NPS + AD DS
Network Policy Server (RADIUS) requires AD DS for user authentication. NPS evaluates connection requests against AD group membership and policies.

Role Placement Best Practices
Which roles go on the same server? Which must be separated?
Safe to Combine
DC + DNS + DHCP: Common in small environments.
File Server + Print Server: Low resource overlap.
Web Server (IIS) + .NET: Natural pairing for web apps.
Keep Separate
DC + Exchange/SQL: Too resource-intensive. Security risk.
Hyper-V host + other roles: Host should run VMs only.
Edge roles (WAP/VPN) + DC: Never expose a DC to the internet.
Virtualization changes everything: In modern environments, each role runs in its own VM. The physical host runs only Hyper-V. This provides isolation, snapshots, and the ability to move workloads between hosts.

1Roles vs Features: Roles = primary function (AD DS, DNS). Features = supporting tools (.NET, Backup, Clustering).
2AD DS: Identity backbone. Domain controllers, forests, domains, OUs. Kerberos authentication. Always 2+ DCs.

4DHCP: Automatic IP assignment. DORA process. Must be authorized in AD. Scopes, reservations, exclusions.

7PowerShell: Install-WindowsFeature, Get-WindowsFeature. Every role is scriptable and remotely deployable.
