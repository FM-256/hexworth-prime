Failover Clustering
Multiple nodes as one logical unit. Automatic workload migration on failure.
How It Works
Nodes share storage (SAN/iSCSI/S2D). Cluster monitors heartbeat. Node failure triggers automatic role migration to surviving nodes. 5-30 second failover.
Requirements
Same OS version. Shared storage. Dedicated heartbeat network. Run Cluster Validation Wizard before creation.
Cluster Roles
Hyper-V VMs, File Server, DHCP, SQL Server, Exchange. Each role gets a virtual name/IP that moves with it. Clients connect to the virtual name.

Network Load Balancing
Distribute traffic across multiple servers.
NLB vs Clustering
NLB: stateless traffic (web, RDP Gateway). Failover Clustering: stateful services (SQL, file, VMs). Never use both on the same servers.
How NLB Works
All nodes share a virtual IP. Each node handles its portion of packets. Affinity settings control session persistence (single/class C/none).
Slide 4 of 8
Cluster Shared Volumes
Multiple nodes simultaneously accessing the same volume.
CSV Benefits
Multiple VMs on same volume owned by different nodes. Fewer LUNs needed. Supports live migration without storage moves. Redirected I/O for failover.
Architecture
One coordinator node handles metadata. All nodes do direct I/O. Coordinator failure triggers automatic takeover. Mounted under C:\ClusterStorage\.

Witness Types
The deciding vote in cluster quorum during node splits.
Disk Witness
Small shared disk (1 GB+). One quorum vote. Best for SAN-based clusters. Cannot be a CSV.
File Share Witness
SMB share on separate server. Best for S2D and multi-site clusters. Share must be accessible by all nodes.
Cloud Witness
Azure Blob Storage. No on-premises dependency. Best for multi-site and hybrid clusters. Requires internet from all nodes.
Slide 6 of 8
VM Failover & Affinity
Controlling VM behavior during cluster events.
Priority
High/Medium/Low per VM. High-priority VMs start first after failover. Low-priority may not start if resources are insufficient.
Anti-Affinity
Keep VMs on different nodes. Redundant DCs, SQL replicas. Prevents single-node failure from taking out both copies.
Drain on Shutdown
Maintenance mode: VMs auto-migrate before node shutdown. Cluster-Aware Updating (CAU) enables zero-downtime patching.
Slide 7 of 8
Stretch Clusters
Extend failover clustering across two physical sites.
Synchronous Replication
Storage Replica syncs volumes between sites. Zero data loss (RPO=0). Requires low-latency link (<5ms RTT). Same metro area.
Site Failover
Each site has own storage kept in sync. Site failure triggers automatic VM failover to surviving site with identical data.

Week 3 Summary
High Availability and Clustering -- key takeaways.
1Failover Clustering: Shared storage, heartbeat, automatic role migration. 5-30s failover.
2NLB: Stateless traffic distribution. Never combine with failover clustering on same servers.
3CSV: Multiple nodes read/write same volume. Simplifies Hyper-V storage management.
4Witnesses: Disk, File Share, or Cloud. Provides quorum vote for split-brain protection.
5VM Affinity: Anti-affinity keeps redundant VMs on separate nodes.
6Stretch Clusters: Storage Replica between sites. Zero data loss site-level DR.
