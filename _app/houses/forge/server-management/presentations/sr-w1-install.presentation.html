Windows Server Editions
Three editions, each designed for a different scale of deployment.
Essentials
Built for small businesses. Limited to 25 users and 50 devices. No CALs needed. Cannot be a Hyper-V host. Pre-configured with essentials dashboard.
Standard
The workhorse edition. Licensed per core (16-core minimum). Includes 2 Hyper-V VM licenses. All roles available. Requires CALs (user or device).
Datacenter
Enterprise-grade. Unlimited VMs, Shielded VMs, Storage Spaces Direct (S2D), Software-Defined Networking. Same core licensing as Standard but higher cost.
Key distinction: Standard and Datacenter have identical features for physical server roles. The difference is virtualization rights -- Standard = 2 VMs, Datacenter = unlimited VMs.

Installation Methods
Three ways to install Windows Server -- each with different management trade-offs.
Desktop Experience (GUI)
Full graphical interface. Server Manager, MMC snap-ins, Explorer. Easiest to manage but largest attack surface and more patching. Best for admins new to Windows Server.
Server Core
Command-line only -- no Explorer, no GUI tools. Managed via PowerShell, sconfig, or remote tools (RSAT/WAC). Smaller footprint, fewer updates, reduced attack surface. Microsoft's recommended default.
Nano Server
Ultra-minimal image for containers only. No local logon, no RDP. Managed entirely remotely. Smallest footprint (~500 MB). Deployed as a container base image, not a standalone OS.

Hardware Requirements
Minimum specs vs. production recommendations for Windows Server 2022.
Minimum Requirements
CPU: 1.4 GHz 64-bit processor
RAM: 512 MB (Core) / 2 GB (Desktop Experience)
Disk: 32 GB minimum
Network: Gigabit Ethernet adapter
Other: UEFI 2.3.1c, Secure Boot, TPM 2.0 recommended
Production Recommendations
CPU: Multi-core Xeon / EPYC (match workload)
RAM: 16-64 GB+ (Hyper-V hosts need more)
Disk: RAID array, SSD for OS, NVMe for VMs
Network: Dual NIC (teaming), 10 GbE for storage
Other: Redundant PSU, iLO/iDRAC/IPMI for remote management
Production reality: Minimum specs are for lab/test only. A production file server with 50 users needs at minimum 4 cores, 16 GB RAM, and RAID storage. Hyper-V hosts typically need 64-512 GB RAM.

Server Licensing
Core-based server licensing + Client Access Licenses (CALs) for every user or device.
Core-Based Licensing
Licenses sold in 2-core packs. Minimum: 8 core packs (16 cores) per physical server. All physical cores must be licensed. Standard and Datacenter use the same core model.
Client Access Licenses (CALs)
Every user or device accessing the server needs a CAL. Two types: User CAL (per person, any device) or Device CAL (per device, any user). Cannot mix within a server -- pick one model.
When to use each: User CALs are better when employees use multiple devices. Device CALs are better for shared workstations (kiosks, labs, factory floors) where many users share few devices.

Initial Configuration
The first steps after installation -- before any roles are added.
1Set hostname: Rename-Computer -NewName "SRV-DC01" -Restart -- use a naming convention (function-location-number).
2Configure static IP: New-NetIPAddress -InterfaceIndex 12 -IPAddress 10.0.0.10 -PrefixLength 24 -DefaultGateway 10.0.0.1
3Set DNS: Set-DnsClientServerAddress -InterfaceIndex 12 -ServerAddresses 10.0.0.10,10.0.0.11
4Join domain: Add-Computer -DomainName "corp.local" -Credential corp\admin -Restart
5Enable Remote Desktop: Set-ItemProperty 'HKLM:\System\CurrentControlSet\Control\Terminal Server' -Name fDenyTSConnections -Value 0
6Configure Windows Firewall: Enable required rules, disable unnecessary services, and run Windows Update.
7Activate Windows: slmgr.vbs /ipk <product-key> or connect to a KMS server for volume licensing.
Server Core shortcut: Run sconfig for a text-based menu covering hostname, IP, domain join, remote management, Windows Update, and more -- all without typing full PowerShell commands.

Server Manager
The central dashboard for managing local and remote Windows Servers (Desktop Experience only).
Add Roles & Features
Wizard-driven installation of server roles (AD DS, DNS, DHCP, etc.) and features (.NET, Telnet Client, SNMP). Handles dependencies automatically.
Multi-Server Management
Add remote servers to manage from one console. Group by role, location, or function. Monitor status, events, and services across all servers.
Best Practices Analyzer
Built-in BPA scans configurations against Microsoft best practices. Flags security risks, performance issues, and misconfigurations for each role.
Slide 8 of 13
Windows Admin Center
The modern, browser-based replacement for RSAT tools -- manage Server Core and remote servers from any browser.
Browser-Based
Runs as a local gateway service. Access via https://gateway:443 from any modern browser. No client software to install on admin workstations.
Server Core Essential
Server Core has no local GUI -- WAC provides the graphical management experience over the network. File explorer, registry editor, certificates, firewall, all in the browser.
Extensible
Microsoft and third-party extensions add capabilities: Azure integration, SDN management, GPU monitoring. Replaces dozens of individual MMC snap-ins.
Deployment: Install WAC on a management server (not on the managed servers themselves). All connections use WinRM (PowerShell Remoting) over port 5985/5986.

Clean Install vs Upgrade vs Migration
Three paths to get a new version of Windows Server into production.
Clean Install
Wipe and reload. Fresh OS on new/existing hardware. Most reliable but requires reconfiguring everything. Best for new deployments and major version jumps.
In-Place Upgrade
Run setup from within the running OS. Preserves roles, data, and settings. Supported for 1-2 version jumps (e.g., 2016 to 2019 to 2022). Risk of inherited issues.
Role Migration
Build a new server, migrate roles using Windows Server Migration Tools (smigdeploy.exe). Zero downtime with DNS cutover. Best practice for production AD/DNS/DHCP.
Best practice: For Active Directory, always migrate -- build a new DC, replicate, transfer FSMO roles, then demote the old DC. Never in-place upgrade a domain controller.
Slide 10 of 13
Automated Deployment
Scale server deployment with answer files and network-based imaging.
Unattended Installation
autounattend.xml answer file on USB or in the ISO. Created with Windows System Image Manager (WSIM). Automates: partition layout, edition selection, admin password, locale, computer name, domain join, and role installation.
Windows Deployment Services (WDS)
PXE boot from the network. WDS server hosts install images (.wim) and answer files. Client boots, downloads the image, installs unattended. Ideal for deploying dozens of servers from a single source image.
Modern alternative: Microsoft Deployment Toolkit (MDT) and System Center Configuration Manager (SCCM/MECM) provide more advanced task sequences, driver injection, and application installation during deployment.

PowerShell Configuration
Every GUI action in Server Manager has a PowerShell equivalent -- and scripts are repeatable.
1Get-WindowsFeature -- lists all available roles and features with install status
2Install-WindowsFeature -Name AD-Domain-Services -IncludeManagementTools -- installs a role
3Get-NetIPConfiguration -- shows current IP configuration for all adapters
4Test-NetConnection -ComputerName dc01 -Port 389 -- tests LDAP connectivity to a DC
5Enable-PSRemoting -Force -- enables WinRM for remote PowerShell management
6Enter-PSSession -ComputerName SRV-FILE01 -- opens an interactive remote session
7Invoke-Command -ComputerName SRV-DC01,SRV-DC02 -ScriptBlock { Get-Service } -- run commands on multiple servers
Why PowerShell matters: Server Core has no GUI. Desired State Configuration (DSC) uses PowerShell to define and enforce server configurations as code -- the foundation of Infrastructure as Code (IaC) on Windows.

Security Hardening
Post-installation security steps -- minimize the attack surface before going into production.
Disable Unnecessary Services
Turn off services that the server does not need: Print Spooler on non-print servers, Xbox services, Browser service. Each running service is a potential attack vector.
Windows Firewall Profiles
Domain, Private, Public profiles. Keep the firewall ON for all profiles. Open only the ports required for the server's roles. Block all inbound by default.
Rename/Disable Default Admin
Rename the built-in Administrator account. Create individual named admin accounts. Enforce strong passwords and account lockout policies via Group Policy.
Windows Update & Patching
Configure WSUS or Windows Update for Business. Schedule monthly patching windows. Test patches in staging before production. Prioritize critical/security updates.
CIS Benchmarks: The Center for Internet Security publishes hardening guides for each Windows Server version. These are the gold standard for server security configuration and are referenced by auditors.

Week 1A Summary
Server Installation and Configuration -- key takeaways.
1Three editions: Essentials (small biz, no CALs), Standard (2 VMs), Datacenter (unlimited VMs, S2D, Shielded VMs)
2Three install types: Desktop Experience (GUI), Server Core (CLI, recommended), Nano Server (containers only)
3Licensing: Core-based (16-core min) + CALs (User or Device). Essentials has no CAL requirement.
4Initial config: Hostname, static IP, DNS, domain join, RDP, firewall, activation -- sconfig on Core
5Management tools: Server Manager (GUI), Windows Admin Center (browser), PowerShell (CLI/remote)
6Deployment at scale: Answer files (autounattend.xml), WDS (PXE), MDT/SCCM for enterprise
7Security: Disable unused services, firewall on, rename admin, patch regularly, follow CIS benchmarks
