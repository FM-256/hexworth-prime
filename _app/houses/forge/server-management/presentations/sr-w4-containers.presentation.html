Containers & Nano Server
Windows Containers -- Hyper-V Containers -- Docker -- Dockerfile -- Nano Server -- Orchestration
Containers package applications with their dependencies into lightweight, portable units. Unlike VMs, containers share the host OS kernel -- faster to start, smaller, more efficient. Windows Server brings containers to the enterprise with Docker integration and Hyper-V isolation.

Containers vs VMs
Fundamentally different approaches to application isolation.
Virtual Machines
Own OS kernel, drivers, libraries. GB-sized. Minutes to start. Hardware-level isolation. Best for: different OS versions, legacy apps, untrusted workloads.
Containers
Share host OS kernel. App + dependencies only. MB-sized. Seconds to start. Process-level isolation. Best for: microservices, CI/CD, horizontal scaling.
When to Use Each
VMs: full OS isolation, different OS versions, hardware-level security. Containers: fast deployment, consistent environments, stateless scaling.
Slide 3 of 9
Windows Container Types
Two isolation modes for Windows containers.
Windows Server Containers
Process isolation. Share host kernel. Fast. Lower overhead. Use when container and host trust each other (same org, same patch level).
Hyper-V Containers
Each container in a lightweight Hyper-V VM. Own kernel copy. Stronger isolation. For untrusted code, multi-tenant, or mismatched OS versions.
Slide 4 of 9
Docker on Windows
Docker Engine is the container runtime for Windows Server.
Key Commands
docker pull (download image), docker run -d -p 80:80 (start container), docker ps (list running), docker logs (view output), docker stop/rm.
Images & Registries
Images: read-only templates. Containers: running instances. Microsoft Container Registry (MCR) for official images. Docker Hub for community. Private registries for enterprise.
Slide 5 of 9
Dockerfile & Image Building
Automate container image creation.
Key Instructions
FROM (base image), COPY (add files), RUN (execute commands during build), EXPOSE (document port), CMD (default startup command). Build: docker build -t app:v1 .
Best Practices
Use specific image tags (not :latest). Minimize layers. Multi-stage builds for smaller images. Copy only needed files. Use .dockerignore.
Slide 6 of 9
Nano Server
Ultra-lightweight Windows container base image.
What It Is
Minimal container image (~300 MB). No local logon, no GUI, no RDP. Runs .NET Core, IIS. Container-only since 2019. Fastest Windows container image.
Use Cases
.NET Core web APIs. IIS web apps. CI/CD build agents. Any workload not needing full Windows API surface. Much smaller than Server Core (~1.8 GB).
Slide 7 of 9
Container Orchestration
Managing containers at scale across multiple hosts.
Kubernetes
Industry standard. Manages deployment, scaling, networking across clusters. Windows node support for mixed clusters. Azure Kubernetes Service (AKS) for managed K8s.
Docker Swarm
Docker built-in orchestration. Simpler than K8s. Manager + worker nodes. Service definitions for scaling and rolling updates. Good for smaller deployments.
Slide 8 of 9
Container Networking & Storage
Connecting and persisting container data.
Networking
Bridge (default private network), Host (shares host networking), Overlay (cross-host for Swarm/K8s). Port mapping: -p host:container.
Volumes
Containers are ephemeral -- data lost on removal. Volumes persist data on host or external storage. Named volumes, bind mounts, or volume drivers for networked storage.

Week 4 Summary
Containers and Nano Server -- key takeaways.
1Containers vs VMs: Containers share host kernel (fast, small). VMs have own kernel (stronger isolation).
2Windows types: Process isolation (default, fast). Hyper-V isolation (VM-level security).
3Docker: pull, run, ps, logs, stop, rm. Build images with Dockerfile. Push to registries.
4Nano Server: ~300 MB container-only image. For .NET Core, IIS, lightweight workloads.
5Orchestration: Kubernetes (industry standard) or Docker Swarm (simpler).
