Exception Hierarchy & Custom Exceptions

Python's exception system is a class hierarchy rooted at BaseException. Understanding this hierarchy lets you catch the right level of granularity — catching too broadly hides bugs, catching too narrowly misses errors.

The Hierarchy

  • BaseException — root of all exceptions (includes SystemExit, KeyboardInterrupt)
  • Exception — base for all non-system-exit errors; catch this in general handlers
  • ValueError, TypeError, OSError — standard built-in exceptions
  • Your custom classes — extend Exception or a built-in subclass

try / except / else / finally

try:
    result = parse_alert(raw_data)
except ValueError as e:
    # Runs when a ValueError is raised
    log.error(f"Bad alert format: {e}")
except (OSError, TimeoutError) as e:
    # Catch multiple exception types in one clause
    log.critical(f"I/O failure: {e}")
else:
    # Runs ONLY if no exception was raised
    forward_to_siem(result)
finally:
    # ALWAYS runs — cleanup goes here
    close_connection()

Custom Exception Classes for Security Contexts

Custom exceptions carry domain-specific data (like severity or source IP) that generic exceptions cannot. They also let you catch entire categories of errors with a single except SecurityError clause.

class SecurityError(Exception):
    """Base exception for security operations."""
    def __init__(self, message, severity="HIGH"):
        self.severity = severity
        super().__init__(f"[{severity}] {message}")

class AuthenticationError(SecurityError):
    """Failed authentication attempt."""
    pass

class AuthorizationError(SecurityError):
    """Insufficient permissions for requested resource."""
    pass

class IntrusionDetected(SecurityError):
    """Potential intrusion detected from a source IP."""
    def __init__(self, source_ip, message):
        self.source_ip = source_ip
        super().__init__(message, severity="CRITICAL")

# Catch the whole security family
try:
    validate_access(token, resource)
except AuthenticationError:
    trigger_lockout()
except AuthorizationError:
    log_privilege_violation()
except SecurityError as e:
    # Any other SecurityError subclass
    alert_soc(e.severity, str(e))
Security: Granular Exceptions = Granular Response

Each custom exception type can trigger a different incident response procedure. AuthenticationError locks the account. IntrusionDetected pages the on-call analyst and blocks the IP. Generic exceptions can't carry this context cleanly.

Context-Aware Error Handling

Real systems have multiple failure modes. Context-aware error handling chains exceptions to preserve the original cause, suppresses expected errors cleanly, and degrades gracefully when components fail.

Exception Chaining with raise...from

When you catch one exception and raise another, use raise X from Y to preserve the original traceback. This is critical for debugging — you see both the root cause and the higher-level failure.

class ConfigurationError(Exception):
    pass

def load_security_config(path):
    try:
        with open(path) as f:
            return json.load(f)
    except FileNotFoundError as e:
        # Chain: ConfigurationError caused BY FileNotFoundError
        raise ConfigurationError(
            f"Missing security config: {path}"
        ) from e
    except json.JSONDecodeError as e:
        raise ConfigurationError(
            f"Malformed config file: {e.msg}"
        ) from e

contextlib.suppress for Expected Errors

from contextlib import suppress

# Clean way to ignore expected failures
with suppress(FileNotFoundError):
    os.remove("/tmp/stale_lock.pid")

# vs. the verbose alternative:
try:
    os.remove("/tmp/stale_lock.pid")
except FileNotFoundError:
    pass

Graceful Degradation

Security systems must keep running when components fail. A SOC alert pipeline that crashes when the primary threat feed is down is worse than one that falls back to cached data.

def get_threat_intel(ioc):
    """Fetch threat data with cascading fallback."""
    # Try primary: live API
    try:
        return primary_api.lookup(ioc)
    except (ConnectionError, TimeoutError):
        pass  # Fall through to cache

    # Try secondary: local cache
    try:
        return local_cache.get(ioc)
    except CacheError:
        pass  # Fall through to defaults

    # Final fallback: safe defaults
    return {"ioc": ioc, "reputation": "UNKNOWN", "source": "default"}
Tip: Log at Each Fallback Level

When falling back, log a WARNING at each level. This creates an observable degradation trace: analysts can see that the system is running on cached data and investigate the primary source outage separately.

Structured Logging

Python's logging module is far more powerful than print(). It provides log levels, multiple output targets, structured formatting, and a hierarchical logger namespace — all essential for production security tooling.

Loggers, Handlers, and Formatters

  • Logger — the entry point you call (e.g. logger.warning(...))
  • Handler — decides where the log goes (console, file, network)
  • Formatter — controls how the message looks

Log Levels

  • DEBUG — Verbose diagnostic output (10)
  • INFO — Normal operational events (20)
  • WARNING — Something unexpected but recoverable (30)
  • ERROR — An operation failed (40)
  • CRITICAL — System-level failure requiring immediate action (50)

Configuring Multiple Handlers

import logging

logger = logging.getLogger("security_monitor")
logger.setLevel(logging.DEBUG)

# Console handler — WARNING and above only
console = logging.StreamHandler()
console.setLevel(logging.WARNING)
console.setFormatter(logging.Formatter(
    '%(levelname)s - %(message)s'
))

# File handler — every level, full detail
file_handler = logging.FileHandler('security.log')
file_handler.setLevel(logging.DEBUG)
file_handler.setFormatter(logging.Formatter(
    '%(asctime)s - %(name)s - %(levelname)s - %(message)s'
))

logger.addHandler(console)
logger.addHandler(file_handler)

# Usage
logger.debug("Parsed 142 packets from 10.0.0.5")    # file only
logger.warning("Port scan detected from 203.0.113.9")  # console + file
logger.critical("Root login attempt blocked")           # console + file
Info: Logger Hierarchy

Logger names are dot-separated namespaces: "security.scanner" is a child of "security". Child loggers propagate to parent loggers by default. Use this to set a root security log level and have all sub-modules inherit it.

SIEM-Ready Log Pipelines

SIEM tools (Splunk, ELK, QRadar) ingest structured data. Plain-text log lines require expensive parsing rules. JSON logs are machine-parseable by default — each field lands in the right column automatically.

Custom JSON Formatter

import json
import logging

class JSONFormatter(logging.Formatter):
    """Emit log records as JSON for SIEM ingestion."""
    def format(self, record):
        log_entry = {
            "timestamp": self.formatTime(record),
            "level": record.levelname,
            "logger": record.name,
            "message": record.getMessage(),
            "source": f"{record.filename}:{record.lineno}"
        }
        if hasattr(record, 'event_type'):
            log_entry['event_type'] = record.event_type
        if record.exc_info:
            log_entry['exception'] = self.formatException(record.exc_info)
        return json.dumps(log_entry)

Log Rotation

Security logs grow fast. Without rotation, a single log file can fill a disk within hours during an active incident. RotatingFileHandler caps file size and keeps a configurable number of backups.

from logging.handlers import RotatingFileHandler

handler = RotatingFileHandler(
    "security_events.log",
    maxBytes=10 * 1024 * 1024,  # 10 MB per file
    backupCount=5                    # Keep 5 rotated files
)
handler.setFormatter(JSONFormatter())

Adding Extra Fields to Log Records

# Use LoggerAdapter to inject context fields
adapter = logging.LoggerAdapter(
    logger,
    {"analyst": "alice", "session_id": "abc123"}
)
adapter.warning("Anomalous login pattern detected")
# JSON output: {..., "analyst": "alice", "session_id": "abc123"}

# Or pass extra directly per-call
logger.info(
    "Port scan detected",
    extra={"event_type": "SCAN", "source_ip": "203.0.113.42"}
)
Security: Never Log Secrets

Passwords, tokens, PII, and cryptographic keys must never appear in log output. Use a custom filter or sanitizer to scrub sensitive fields before they reach any handler. Once in a log file, secrets propagate to SIEM, backup storage, and monitoring dashboards.

Security Event Monitoring

Combining exception handling with structured logging creates a self-observing alerting pipeline. Errors surface as structured events, thresholds trigger escalations, and every failure is traceable.

Combining Error Handling + Logging

def process_alert(raw_alert, logger):
    try:
        alert = parse_alert(raw_alert)
        result = correlate(alert)
        logger.info("Alert processed", extra={"alert_id": alert.id})
        return result
    except ValueError as e:
        logger.warning(f"Malformed alert dropped: {e}",
                        extra={"raw": raw_alert[:200]})
    except CorrelationError as e:
        logger.error(f"Correlation failed: {e}",
                      extra={"severity": e.severity})
        raise  # Re-raise so the caller can escalate

Threshold-Based Alerting

from collections import defaultdict
import time

failure_counts = defaultdict(int)
LOCKOUT_THRESHOLD = 5

def record_failure(source_ip, logger):
    failure_counts[source_ip] += 1
    count = failure_counts[source_ip]
    if count == LOCKOUT_THRESHOLD:
        logger.critical(
            f"LOCKOUT: {source_ip} exceeded {LOCKOUT_THRESHOLD} failures",
            extra={"event_type": "LOCKOUT", "source_ip": source_ip}
        )
        block_ip(source_ip)
    elif count > 2:
        logger.warning(f"Repeated failure from {source_ip}: attempt {count}")
CODE REVIEW Find the Logging Issues

Review this code. It contains 3 serious issues related to logging and error handling in a security context.

import logging

# --- Issue 1: Logging sensitive data ---
def authenticate(username, password):
    logging.info(f"Login attempt: user={username} pass={password}")
    # ^ Passwords in log output propagate to SIEM, backups,
    #   and every downstream consumer. Never log credentials.

# --- Issue 2: Bare except swallows everything ---
def process_events(events):
    for event in events:
        try:
            handle(event)
        except:   # Bare except catches SystemExit and KeyboardInterrupt!
            pass  # Silently discards ALL errors including Ctrl+C

# --- Issue 3: No log rotation ---
handler = logging.FileHandler("security.log")
# ^ Unbounded file will fill disk during a high-volume incident.
#   Use RotatingFileHandler or TimedRotatingFileHandler instead.

Issues:

  1. Logging sensitive data — password is written directly to the log message. Credentials propagate to every SIEM, backup, and monitoring system that receives the log stream. Always log only the username and a boolean success/failure flag.
  2. Bare except: clause — catches SystemExit and KeyboardInterrupt, making it impossible to stop the process cleanly. It also silences every real error. Use except Exception: at the broadest, and log before passing.
  3. Missing log rotation — logging.FileHandler writes to a single unbounded file. During a DDoS or active intrusion, event volume can fill a disk in minutes. Use RotatingFileHandler(maxBytes=10*1024*1024, backupCount=5).
