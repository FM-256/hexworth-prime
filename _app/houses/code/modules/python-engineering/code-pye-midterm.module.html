Configuration lives in a single authoritative dict. Environment variables override defaults at startup. Never scatter config values across your codebase.

Data Pipeline

Security log files can be gigabytes in size. Loading an entire file into memory before processing is not viable. Generator-based pipelines process one event at a time, keeping memory usage constant regardless of log volume.

Generator-Based Log Parsing

A generator function yields one parsed event per raw log line. Callers iterate over the generator without ever materializing the full dataset.

import re
from typing import Generator, Dict

def parse_log_stream(lines) -> Generator[Dict, None, None]:
    """Parse raw log lines into structured events."""
    patterns = {
        "auth_failure": re.compile(
            r"(\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}).*"
            r"Failed password for (\w+) from ([\d.]+)"
        ),
        "sudo_usage": re.compile(
            r"(\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}).*"
            r"sudo:\s+(\w+).*COMMAND=(.*)"
        )
    }

    for line in lines:
        for event_type, pattern in patterns.items():
            match = pattern.search(line)
            if match:
                yield {
                    "type": event_type,
                    "timestamp": match.group(1),
                    "raw": line.strip(),
                    "groups": match.groups()
                }

Using itertools for Efficient Processing

The itertools module provides combinators that chain generators without breaking the lazy evaluation model.

import itertools

def from_multiple_sources(*log_files):
    """Yield events from multiple log files as a single stream."""
    sources = (open(f) for f in log_files)
    combined = itertools.chain.from_iterable(sources)
    yield from parse_log_stream(combined)

# Process a week of auth logs without loading them all
for event in from_multiple_sources("auth-mon.log", "auth-tue.log", "auth-wed.log"):
    process(event)
Security: Log Integrity

Real auth logs contain sensitive data: usernames, source IPs, timestamps. Never buffer these in global variables or write them to /tmp without encryption. Process in-stream and emit only sanitized, aggregated output.

Processing Engine

Raw parsed events feed the processing engine, which applies decorators for instrumentation and uses context managers to scope batch operations safely. This is where Chapter 3 patterns become operationally valuable.

Decorators for Audit Trails and Timing

Cross-cutting concerns — logging, timing, counting — belong in decorators. The business logic stays clean and testable; the operational wrappers are composable.

import functools
from contextlib import contextmanager

def track_processing(func):
    """Decorator to track processing metrics."""
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        wrapper.call_count += 1
        result = func(*args, **kwargs)
        wrapper.events_processed += len(result) if isinstance(result, list) else 1
        return result
    wrapper.call_count = 0
    wrapper.events_processed = 0
    return wrapper

@contextmanager
def event_batch(batch_name):
    """Context manager for processing event batches."""
    batch = {"name": batch_name, "events": [], "errors": []}
    try:
        yield batch
    finally:
        print(f"Batch '{batch_name}': {len(batch['events'])} processed, {len(batch['errors'])} errors")

Event Correlation and Aggregation

Correlation means grouping related events and finding patterns. The classic brute force signal is many authentication failures from the same source IP within a short time window.

from collections import defaultdict

def correlate_events(events, threshold=5):
    """Group events by source IP, flag IPs exceeding failure threshold."""
    failures_by_ip = defaultdict(list)

    for event in events:
        if event.get("type") == "auth_failure":
            ip = event.get("source_ip", "unknown")
            failures_by_ip[ip].append(event)

    # Flag IPs that exceed the threshold
    flagged = {
        ip: evts
        for ip, evts in failures_by_ip.items()
        if len(evts) >= threshold
    }
    return flagged
Info: SIEM Correlation Rules

The pattern above is a simplified SIEM correlation rule. Production SIEMs (Splunk, Elastic SIEM) evaluate hundreds of such rules per second against streaming event data. The key insight is the same: group by a pivot field, evaluate aggregate conditions, emit alerts.

Alert System

The alert system is the output layer of the processor. It receives correlated findings and dispatches them to operators. The quality of the alert design directly determines whether responders can act quickly or waste time hunting for context.

Custom Exceptions for Alert Levels

Use a hierarchy of custom exceptions to signal different alert severities. This lets callers handle CriticalAlert differently from LowAlert without inspecting string fields.

class AlertBase(Exception):
    """Base class for all processor alerts."""
    severity = "UNKNOWN"

class LowAlert(AlertBase):
    severity = "LOW"

class HighAlert(AlertBase):
    severity = "HIGH"

class CriticalAlert(AlertBase):
    severity = "CRITICAL"

def dispatch_alert(ip, count, config):
    """Raise the appropriate alert class based on failure count."""
    threshold = config.get("alert_threshold", 5)
    msg = f"Brute force detected: {ip} ({count} failures)"
    if count >= threshold * 3:
        raise CriticalAlert(msg)
    elif count >= threshold:
        raise HighAlert(msg)
    else:
        raise LowAlert(msg)

Structured Alert Output

Structured JSON output lets downstream systems (SIEM ingestion endpoints, webhooks, dashboards) parse alerts without fragile text manipulation.

import json
from datetime import datetime

def format_alert(alert_type, source_ip, event_count, config):
    """Return a structured alert record as a JSON string."""
    record = {
        "timestamp": datetime.utcnow().isoformat() + "Z",
        "severity": alert_type.severity,
        "source_ip": source_ip,
        "event_count": event_count,
        "output_format": config.get("output_format", "json")
    }
    return json.dumps(record, indent=2)
CODE REVIEW Find the Issues in This Alert Module

Review the alert dispatch code below. It has 3 significant defects. Identify each one before reading the analysis.

import json

ALERT_FILE = "/var/log/security_alerts.log"  # Issue 2: hardcoded path

def send_alert(source_ip, count):
    """Write a security alert to the alert log."""
    try:
        record = {
            "source_ip": source_ip,
            "count": count
            # Issue 3: no timestamp on alert record
        }
        with open(ALERT_FILE, "a") as f:
            f.write(json.dumps(record) + "\n")
    except Exception:
        pass  # Issue 1: silently drops ALL errors including disk full

Issues:

  1. Silent exception swallow — except Exception: pass discards disk-full errors, permission errors, and serialization failures. Alerts are dropped with no indication. At minimum, log the error to stderr or re-raise after cleanup.
  2. Hardcoded output path — ALERT_FILE is a constant string. This makes the module impossible to unit-test without writing to the real filesystem. The path should come from config (config.get("alert_output_path")).
  3. No timestamp on alert records — An alert without a timestamp is nearly useless for incident response. Responders cannot correlate it with firewall logs, packet captures, or change management records. Always include datetime.utcnow().isoformat().
