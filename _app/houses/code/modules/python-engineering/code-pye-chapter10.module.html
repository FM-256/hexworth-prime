System Administration Scripts

Python's os, subprocess, and pathlib modules are the foundation of system administration automation. Together they let you gather system intelligence, check service health, and audit file states — all from a single script.

subprocess.run for Shell Commands

Use subprocess.run() with capture_output=True and text=True to run system commands and capture their output as strings. Avoid shell=True whenever possible to prevent command injection.

pathlib for Safe Path Operations

pathlib.Path treats paths as objects rather than strings, making cross-platform path manipulation safe and readable. Use p.exists(), p.stat(), p.read_text(), and p.glob() instead of string concatenation.

import os
import subprocess
from pathlib import Path

def check_system_health():
    """Gather structured system health information."""
    info = {}

    # Disk usage — capture_output avoids shell pipe overhead
    result = subprocess.run(
        ["df", "-h", "/"],
        capture_output=True, text=True
    )
    info["disk"] = result.stdout

    # Top memory consumers
    result = subprocess.run(
        ["ps", "aux", "--sort=-%mem"],
        capture_output=True, text=True
    )
    info["top_processes"] = result.stdout.split('\n')[:6]

    # Audit critical system file states
    critical_paths = [
        Path("/var/log/auth.log"),
        Path("/etc/ssh/sshd_config"),
        Path("/etc/passwd")
    ]
    info["file_status"] = {
        str(p): {
            "exists": p.exists(),
            "size": p.stat().st_size if p.exists() else 0
        }
        for p in critical_paths
    }

    return info
Security: Never Use shell=True with External Input

Passing shell=True to subprocess.run and including any user-controlled string in the command creates a command injection vulnerability. Always use a list of arguments and let Python handle escaping. If a shell feature is truly needed, sanitize input with shlex.quote().

Log Forensics Tools

Authentication logs are a primary forensic artifact for incident response. Python's re module and collections library let you parse, group, and threshold log data to surface attacker behavior automatically.

Parsing Auth Logs with Regex

The /var/log/auth.log file records all SSH and sudo events. Failed login attempts follow a consistent pattern that regex can extract: timestamp, attempted username, and source IP.

Brute Force Detection Logic

Brute force attacks leave a clear signature: many failed login attempts from a single IP in a short window. Group failures by IP with defaultdict, then flag any IP exceeding a threshold.

import re
from collections import Counter, defaultdict

def analyze_auth_log(log_lines):
    """Analyze authentication log for suspicious activity."""
    failed_pattern = re.compile(
        r"(\w+\s+\d+\s+[\d:]+).*Failed password for (?:invalid user )?(\w+) from ([\d.]+)"
    )

    failures_by_ip = defaultdict(list)

    for line in log_lines:
        match = failed_pattern.search(line)
        if match:
            timestamp, username, ip = match.groups()
            failures_by_ip[ip].append({
                "timestamp": timestamp,
                "username": username
            })

    # Detect brute force: more than 5 failures from the same IP
    brute_force_ips = {
        ip: attempts
        for ip, attempts in failures_by_ip.items()
        if len(attempts) > 5
    }

    return {
        "total_failures": sum(len(v) for v in failures_by_ip.values()),
        "unique_ips": len(failures_by_ip),
        "brute_force_detected": brute_force_ips
    }
Info: Timeline Reconstruction

For deeper analysis, parse timestamps into datetime objects and use time-windowed grouping — count failures per IP within rolling 5-minute windows. This detects slow-and-low brute force attacks that stay under per-hour thresholds.

Configuration Management

Production security tools need validated, environment-aware configuration. Hardcoded values are brittle and dangerous. YAML-based config with validation and environment overrides is the standard pattern for deployable scripts.

YAML Parsing with PyYAML

Always use yaml.safe_load(), never yaml.load(). The unsafe variant can execute arbitrary Python when parsing untrusted YAML files — a critical vulnerability if your config could ever be attacker-controlled.

Environment-Specific Overrides

Good config files define shared defaults at the top level and override them per environment (development, staging, production). Read APP_ENV from the environment and merge the appropriate block.

import yaml
import os

def load_config(config_path, environment=None):
    """Load, merge environment overrides, and validate config."""
    with open(config_path) as f:
        config = yaml.safe_load(f)  # safe_load prevents arbitrary code execution

    # Apply environment-specific overrides
    env = environment or os.getenv("APP_ENV", "development")
    if env in config.get("environments", {}):
        env_config = config["environments"][env]
        config.update(env_config)

    # Validate that all required fields are present
    required = ["log_path", "alert_threshold", "api_endpoint"]
    missing = [f for f in required if f not in config]
    if missing:
        raise ValueError(f"Missing required config fields: {missing}")

    return config
Security: yaml.safe_load vs yaml.load

Using yaml.load() without an explicit Loader argument allows YAML to deserialize arbitrary Python objects. An attacker who can write to your config file can achieve remote code execution. yaml.safe_load() restricts deserialization to basic types (str, int, list, dict) only.

Deployment Automation

Production security scripts need proper CLI interfaces: argument parsing, help text, exit codes, and signal handling. argparse and signal turn a working script into a deployable tool that integrates cleanly with cron jobs, CI/CD pipelines, and shell orchestration.

argparse: Professional CLI Interfaces

Every field defined with add_argument() becomes a named attribute on the args object returned by parse_args(). Choices, types, defaults, and help strings are all declared inline — argparse generates --help automatically.

Exit Codes and Signal Handling

Shell scripts and monitoring systems rely on exit codes: 0 for success, non-zero for failure. Use sys.exit(code) explicitly. Register SIGINT and SIGTERM handlers to save state on Ctrl-C or graceful shutdown.

import argparse
import sys
import signal

def create_parser():
    parser = argparse.ArgumentParser(
        description="Security Audit Tool",
        formatter_class=argparse.RawDescriptionHelpFormatter
    )
    parser.add_argument("target", help="Target host or network CIDR")
    parser.add_argument("-p", "--ports", default="1-1024",
                        help="Port range (default: 1-1024)")
    parser.add_argument("-o", "--output", choices=["json", "csv", "table"],
                        default="table", help="Output format")
    parser.add_argument("-v", "--verbose", action="store_true",
                        help="Enable verbose output")
    parser.add_argument("--timeout", type=float, default=2.0,
                        help="Connection timeout in seconds")
    return parser

def signal_handler(signum, frame):
    print("\nInterrupted. Saving partial results...")
    sys.exit(130)  # POSIX convention: 128 + signal number

signal.signal(signal.SIGINT, signal_handler)

if __name__ == "__main__":
    args = create_parser().parse_args()
    if args.verbose:
        print(f"Scanning {args.target}, ports {args.ports}")
Tip: Exit Code Conventions

Use exit code 0 for success, 1 for general errors, 2 for invalid arguments (argparse uses this automatically), and 130 for SIGINT (Ctrl-C). Monitoring systems and shell scripts test $? after your tool runs — consistent exit codes make automation reliable.

System Hardening Scripts

Hardening scripts automate compliance: verifying file permissions, checking service states, and validating configuration against security baselines. The quality of these scripts directly determines whether your security posture is measurable and repeatable.

File Permission Auditing

Use os.stat() or pathlib.Path.stat() combined with stat.S_IMODE() to read permission bits. Compare against expected modes (e.g., 0o600 for SSH keys, 0o644 for public config) and flag violations.

Service and Compliance Checks

Use subprocess.run(["systemctl", "is-active", service_name], capture_output=True) and check the return code — 0 means active, non-zero means stopped or failed. Always check result.returncode explicitly; never assume success.

Tip: Use pathlib for Cross-Platform Paths

Hardcoded path strings like "/var/log" + "/" + filename break on Windows and create subtle bugs when paths contain spaces. Path("/var/log") / filename handles separators, normalization, and edge cases automatically on every platform.

CODE REVIEW Find the Issues

Review this system hardening script. It has 3 bugs that create either security vulnerabilities or silent operational failures.

import subprocess
import os

def check_service(service_name):
    """Check if a system service is active."""
    cmd = f"systemctl is-active {service_name}"
    result = subprocess.run(cmd, shell=True,   # Issue 1
                            capture_output=True, text=True)
    return result.stdout.strip() == "active"    # Issue 2

def audit_permissions(directory):
    """Audit files in a directory for insecure permissions."""
    violations = []
    log_dir = "/var/log" + "/" + directory      # Issue 3
    for entry in os.scandir(log_dir):
        mode = oct(os.stat(entry.path).st_mode)
        if "7" in mode:  # World-writable or executable
            violations.append(entry.path)
    return violations

Issues Identified:

  1. Command injection via shell=True (line 5-6): Building a shell command string with f"systemctl is-active {service_name}" and passing shell=True allows injection if service_name ever comes from external input (e.g., "sshd; rm -rf /"). Fix: use a list: ["systemctl", "is-active", service_name] with shell=False (the default).
  2. Unchecked return code (line 8): Only checking stdout for "active" ignores the case where systemctl itself fails (service not found, permission denied, systemd not running). A failed command returns a non-zero returncode — always check result.returncode == 0 in addition to or instead of parsing stdout.
  3. Hardcoded path string concatenation (line 12): "/var/log" + "/" + directory breaks if directory starts with /, contains .., or runs on Windows. Replace with Path("/var/log") / directory, which handles separator normalization and works cross-platform.
