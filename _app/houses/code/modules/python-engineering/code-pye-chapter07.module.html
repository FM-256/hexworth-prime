HTTP & the requests Library

HTTP is the foundation of web communication and the protocol underlying every REST API, webhook, and threat intel feed your tools will ever touch. Python's requests library makes HTTP intuitive — but production-grade API clients require more than a single get() call.

HTTP Methods

  • GET — Retrieve a resource (read-only, no request body)
  • POST — Create a resource or submit data (has a body)
  • PUT — Replace a resource entirely
  • PATCH — Partially update a resource
  • DELETE — Remove a resource

Making Requests

import requests

# GET request with headers and query params
response = requests.get(
    "https://api.threatintel.example/v1/indicators",
    headers={"Authorization": "Bearer TOKEN_HERE"},
    params={"type": "ip", "limit": 100},
    timeout=30
)

if response.status_code == 200:
    data = response.json()
    for indicator in data["indicators"]:
        print(f"[{indicator['severity']}] {indicator['value']}")
else:
    print(f"Error: {response.status_code} - {response.text}")

# Session for persistent connections and shared headers
session = requests.Session()
session.headers.update({"Authorization": "Bearer TOKEN"})
session.verify = True  # Always verify SSL certificates

# Both requests share auth headers automatically
r1 = session.get("/api/alerts")
r2 = session.get("/api/incidents")

Response Handling

# Status code ranges
# 2xx — Success (200 OK, 201 Created, 204 No Content)
# 4xx — Client error (400 Bad Request, 401 Unauthorized, 404 Not Found)
# 5xx — Server error (500 Internal Error, 503 Unavailable)

# Raise an exception for 4xx/5xx status codes
response.raise_for_status()

# Parse JSON body
data = response.json()

# Raw text body
text = response.text

# Response headers
rate_limit_remaining = response.headers.get("X-RateLimit-Remaining")
Security: Always Set a Timeout

Without a timeout parameter, requests will wait indefinitely. A hung connection can block your tool, exhaust thread pools, or allow a slow-response attack. Always pass timeout=30 (or lower for internal services).

API Authentication

Authentication tells an API who you are. Authorization determines what you are allowed to do. Most security APIs use one of a few key schemes — and how you handle credentials in your code is as important as how you authenticate.

Common API Auth Schemes

  • API Key (Header): Authorization: Bearer <key> or X-Api-Key: <key> — most common
  • API Key (Query Param): ?api_key=abc123 — avoid if possible; keys appear in server logs
  • OAuth2: Token exchange flow; short-lived access tokens refreshed via a refresh token
  • HMAC Signing: Cryptographic signature of the request; proves the request wasn't tampered with
  • JWT: Self-contained signed token with claims; validate the signature and expiry before trusting

Loading Credentials Securely

import os
import time
import hmac
import hashlib

# API key from environment variable — NEVER hardcode!
API_KEY = os.environ.get("THREAT_API_KEY")
if not API_KEY:
    raise EnvironmentError("THREAT_API_KEY not set")

# HMAC request signing — proves identity AND integrity
def sign_request(method, path, body, secret):
    """Create HMAC-SHA256 signature for an API request."""
    timestamp = str(int(time.time()))
    message = f"{method}\n{path}\n{timestamp}\n{body}"
    signature = hmac.new(
        secret.encode(),
        message.encode(),
        hashlib.sha256
    ).hexdigest()
    return {"X-Timestamp": timestamp, "X-Signature": signature}
Security: Never Hardcode Credentials

Hardcoded API keys get committed to git, show up in logs, and leak through stack traces. Use environment variables (os.environ.get()) or a secrets manager. If a key is ever in source code, rotate it immediately — assume it is compromised.

JWT Validation Pattern

import base64
import json

def decode_jwt_payload(token):
    """Decode JWT payload for inspection (does NOT verify signature)."""
    parts = token.split(".")
    if len(parts) != 3:
        raise ValueError("Invalid JWT format")
    # Add padding for base64 decode
    padded = parts[1] + "=="
    payload = json.loads(base64.urlsafe_b64decode(padded))
    if payload.get("exp", 0) < time.time():
        raise ValueError("JWT token has expired")
    return payload

# import jwt; jwt.decode(token, PUBLIC_KEY, algorithms=["RS256"])

Consuming Security APIs

Security tools live and die by the quality of their data. Threat intel APIs, CVE databases, and reputation feeds all expose HTTP APIs with similar patterns: paginated results, rate limits, and structured JSON responses. Knowing how to handle these patterns correctly separates fragile scripts from reliable tools.

Pagination

APIs return data in pages to limit response size. Always handle pagination or you will silently miss data.

class CVELookup:
    """Query a CVE database for vulnerability information."""
    BASE_URL = "https://cve.example/api/v1"

    def __init__(self, api_key):
        self.session = requests.Session()
        self.session.headers["X-Api-Key"] = api_key

    def search(self, keyword, severity=None):
        params = {"keyword": keyword}
        if severity:
            params["severity"] = severity

        results = []
        page = 1
        while True:
            params["page"] = page
            resp = self.session.get(
                f"{self.BASE_URL}/cves",
                params=params,
                timeout=30
            )
            resp.raise_for_status()
            data = resp.json()
            results.extend(data["cves"])

            if page >= data["total_pages"]:
                break
            page += 1

        return results

Rate Limiting

import time

def check_with_rate_limit(session, urls, calls_per_minute=60):
    """Check a list of URLs respecting rate limits."""
    delay = 60 / calls_per_minute
    results = []
    for url in urls:
        resp = session.get(url, timeout=30)
        results.append(resp.json())
        time.sleep(delay)  # Respect the rate limit
    return results

# Also check Retry-After header when you get a 429
if resp.status_code == 429:
    wait = int(resp.headers.get("Retry-After", 60))
    time.sleep(wait)
Tip: Use raise_for_status()

Instead of checking status_code == 200 manually, call response.raise_for_status(). It raises an HTTPError for any 4xx or 5xx response, which you can catch explicitly. This keeps your code clean and ensures you never silently process an error response as data.

Building APIs with Flask

Consuming APIs is one skill. Building them is another. Flask is the go-to Python micro-framework for exposing your tools over HTTP — whether that means a local alert ingestion endpoint, a SOAR integration hook, or a full-featured SOC API.

Flask Basics

from flask import Flask, request, jsonify
from datetime import datetime

app = Flask(__name__)

# In-memory alert store (use a database in production)
alerts = []

@app.route("/api/alerts", methods=["GET"])
def get_alerts():
    severity = request.args.get("severity")
    if severity:
        filtered = [a for a in alerts if a["severity"] == severity]
        return jsonify({"alerts": filtered, "count": len(filtered)})
    return jsonify({"alerts": alerts, "count": len(alerts)})

@app.route("/api/alerts", methods=["POST"])
def create_alert():
    data = request.get_json()
    if not data or "message" not in data:
        return jsonify({"error": "message is required"}), 400

    alert = {
        "id": len(alerts) + 1,
        "message": data["message"],
        "severity": data.get("severity", "MEDIUM"),
        "timestamp": datetime.utcnow().isoformat()
    }
    alerts.append(alert)
    return jsonify(alert), 201

@app.errorhandler(404)
def not_found(e):
    return jsonify({"error": "Resource not found"}), 404

Route Parameters and Validation

@app.route("/api/alerts/<int:alert_id>", methods=["GET"])
def get_alert(alert_id):
    # Find alert by ID
    alert = next((a for a in alerts if a["id"] == alert_id), None)
    if not alert:
        return jsonify({"error": f"Alert {alert_id} not found"}), 404
    return jsonify(alert)

# Input validation helper
VALID_SEVERITIES = {"LOW", "MEDIUM", "HIGH", "CRITICAL"}

def validate_alert_input(data):
    errors = []
    if not data.get("message"):
        errors.append("message is required")
    if data.get("severity") and data["severity"] not in VALID_SEVERITIES:
        errors.append(f"severity must be one of {VALID_SEVERITIES}")
    return errors
Info: Always Validate API Input

Never trust data from request.get_json(). Check for required fields, validate types and allowed values, and reject unexpected keys. This prevents data corruption and closes a class of injection vulnerabilities at the API layer.

Async HTTP

Synchronous HTTP means your code blocks while waiting for a response. When you need to check 500 IP addresses against a threat feed, blocking means waiting for each one in sequence — slow and inefficient. Async HTTP lets you fire many requests concurrently and collect results as they arrive.

aiohttp and asyncio.gather

import asyncio
import aiohttp

async def check_ip(session, ip, api_key):
    """Async check a single IP against the threat intel API."""
    url = f"https://api.threatintel.example/v1/ip/{ip}"
    async with session.get(
        url,
        headers={"Authorization": f"Bearer {api_key}"},
        timeout=aiohttp.ClientTimeout(total=10)
    ) as resp:
        data = await resp.json()
        return {"ip": ip, "result": data}

async def bulk_lookup(ip_list, api_key):
    """Check many IPs concurrently — much faster than sequential."""
    async with aiohttp.ClientSession() as session:
        tasks = [
            check_ip(session, ip, api_key)
            for ip in ip_list
        ]
        # All requests fire concurrently, results gathered when done
        results = await asyncio.gather(*tasks, return_exceptions=True)
    return results

# Run the async function
ips_to_check = ["198.51.100.1", "203.0.113.5", "192.0.2.44"]
results = asyncio.run(bulk_lookup(ips_to_check, api_key="..."))

httpx — Sync and Async in One Library

import httpx

# Sync (drop-in replacement for requests)
with httpx.Client(timeout=30) as client:
    resp = client.get("https://api.example.com/alerts")

# Async (same API surface)
async with httpx.AsyncClient(timeout=30) as client:
    resp = await client.get("https://api.example.com/alerts")
    data = resp.json()
Tip: Concurrency vs Parallelism

Async is concurrent (one thread, many I/O waits) not parallel (multiple threads/processes). For I/O-bound work like HTTP requests, async is highly effective. For CPU-bound work like parsing large log files, use multiprocessing instead.

  1. API_KEY is hardcoded — this will be committed to version control and leaked. Load it from os.environ.get("THREAT_API_KEY") instead.
