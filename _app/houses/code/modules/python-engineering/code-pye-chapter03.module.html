First-Class Functions

In Python, functions are objects. You can assign them to variables, pass them as arguments, and return them from other functions. This is the foundation for decorators.

Functions as Arguments

def apply_filter(entries, condition):
    """Apply a filter function to a list of entries."""
    return [e for e in entries if condition(e)]

def is_critical(entry):
    return entry["severity"] == "CRITICAL"

def is_external(entry):
    return not entry["src"].startswith("10.")

# Pass different functions to change behavior
critical_events = apply_filter(events, is_critical)
external_events = apply_filter(events, is_external)

Closures

A closure is a function that remembers variables from its enclosing scope, even after that scope has finished executing. This is how decorators "wrap" functions.

def make_threshold_filter(min_severity):
    """Return a function that filters by minimum severity."""
    levels = {"LOW": 0, "MEDIUM": 1, "HIGH": 2, "CRITICAL": 3}
    threshold = levels[min_severity]

    def filter_fn(entry):
        return levels.get(entry["severity"], 0) >= threshold

    return filter_fn  # Return the inner function

# Create specialized filters
high_or_above = make_threshold_filter("HIGH")
critical_only = make_threshold_filter("CRITICAL")

# Use them
high_events = apply_filter(events, high_or_above)
Info: Why This Matters

Decorators are closures that take a function as input and return a new function. If closures make sense, decorators will be straightforward.

Writing Decorators

A decorator is a function that takes another function and extends its behavior without modifying its code. The @ syntax is syntactic sugar for passing a function to the decorator.

The Decorator Pattern

import functools
import time

def timer(func):
    """Measure execution time of a function."""
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        elapsed = time.perf_counter() - start
        print(f"{func.__name__} took {elapsed:.4f}s")
        return result
    return wrapper

@timer
def scan_network(subnet):
    time.sleep(0.1)  # Simulated scan
    return ["10.0.0.1", "10.0.0.2"]

# scan_network is now the wrapped version
hosts = scan_network("10.0.0.0/24")
# Output: scan_network took 0.1003s

Why functools.wraps?

Without @functools.wraps(func), the decorated function loses its original name and docstring. Always use it to preserve function metadata.

# Without @wraps:
scan_network.__name__  # 'wrapper'  ← Wrong!

# With @wraps:
scan_network.__name__  # 'scan_network'  ← Correct!

Decorators with Arguments

def retry(max_attempts=3, delay=1.0):
    """Retry a function on failure."""
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(max_attempts):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    if attempt == max_attempts - 1:
                        raise
                    time.sleep(delay * (2 ** attempt))  # Exponential backoff
        return wrapper
    return decorator

@retry(max_attempts=5, delay=0.5)
def fetch_threat_intel(source_url):
    # May fail due to network issues
    ...

Decorator Patterns

Beyond basic wrapping, decorators can validate inputs, cache results, enforce rate limits, and compose behavior through stacking.

Input Validation Decorator

def validate_ip(func):
    """Ensure the first argument is a valid IP address."""
    @functools.wraps(func)
    def wrapper(ip, *args, **kwargs):
        parts = ip.split(".")
        if len(parts) != 4 or not all(
            p.isdigit() and 0 <= int(p) <= 255 for p in parts
        ):
            raise ValueError(f"Invalid IP address: {ip}")
        return func(ip, *args, **kwargs)
    return wrapper

@validate_ip
def scan_host(ip, ports):
    return {"host": ip, "ports": ports}

scan_host("10.0.0.1", [22, 80])    # Works
scan_host("not-an-ip", [22])      # Raises ValueError

Stacking Decorators

# Decorators execute bottom-up (closest to function first)
@timer
@validate_ip
@audit_trail
def deep_scan(ip, ports):
    ...

# Equivalent to:
# deep_scan = timer(validate_ip(audit_trail(deep_scan)))

Context Managers

Context managers ensure resources are properly acquired and released, even when exceptions occur. The with statement is your guarantee of cleanup.

Writing a Context Manager Class

class SecureConnection:
    """Encrypted connection that always closes properly."""

    def __init__(self, host, port):
        self.host = host
        self.port = port
        self.socket = None

    def __enter__(self):
        print(f"Connecting to {self.host}:{self.port}...")
        self.socket = "connected"  # Simulated
        return self  # This is what 'as' binds to

    def __exit__(self, exc_type, exc_val, exc_tb):
        print("Closing connection...")
        self.socket = None
        if exc_type:
            print(f"Error occurred: {exc_val}")
        return False  # Don't suppress exceptions

    def send(self, data):
        print(f"Sending: {data}")

# Usage: connection is ALWAYS closed, even on error
with SecureConnection("10.0.0.1", 443) as conn:
    conn.send("GET /api/status")

The __exit__ Parameters

  • exc_type — The exception class (or None if no error)
  • exc_val — The exception instance
  • exc_tb — The traceback
  • Return True to suppress the exception, False to re-raise it
Security: Resource Cleanup

Context managers prevent resource leaks: unclosed files, database connections, or network sockets. In security tools, leaked connections can exhaust system resources or leave sensitive data in memory longer than necessary.

contextlib — Generator Context Managers

The contextlib module provides shortcuts for creating context managers without writing a full class. The @contextmanager decorator turns a generator into a context manager.

@contextmanager

from contextlib import contextmanager

@contextmanager
def timed_operation(name):
    """Time a block of code."""
    import time
    start = time.perf_counter()
    try:
        yield  # This is where the 'with' block runs
    finally:
        elapsed = time.perf_counter() - start
        print(f"{name}: {elapsed:.4f}s")

with timed_operation("Network scan"):
    # ... scan code runs here
    time.sleep(0.5)
# Output: Network scan: 0.5003s

Yielding a Value

@contextmanager
def temp_config(overrides):
    """Temporarily override config values, restore on exit."""
    original = config.copy()
    config.update(overrides)
    try:
        yield config  # Yielded value binds to 'as'
    finally:
        config.clear()
        config.update(original)

with temp_config({"debug": True}) as cfg:
    print(cfg["debug"])  # True
# Config is automatically restored here

Combining Patterns

The real power comes from combining decorators and context managers. Stack decorators for cross-cutting concerns. Nest context managers for resource orchestration.

Real-World Security Tool Example

import functools
from contextlib import contextmanager

# Decorator: rate limit API calls
def rate_limit(calls_per_second=5):
    def decorator(func):
        last_call = [0]
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            elapsed = time.time() - last_call[0]
            wait = 1 / calls_per_second - elapsed
            if wait > 0:
                time.sleep(wait)
            last_call[0] = time.time()
            return func(*args, **kwargs)
        return wrapper
    return decorator

# Context manager: transaction scope
@contextmanager
def scan_session(target):
    session = {"target": target, "results": [], "start": time.time()}
    try:
        yield session
    finally:
        session["duration"] = time.time() - session["start"]
        save_scan_report(session)

# Combined usage
@rate_limit(calls_per_second=2)
@retry(max_attempts=3)
@audit_trail
def check_port(host, port):
    ...

with scan_session("10.0.0.0/24") as session:
    for host in hosts:
        for port in common_ports:
            result = check_port(host, port)
            session["results"].append(result)
Tip: Order Matters When Stacking

Decorator order is significant: @rate_limit @retry @audit_trail means rate limiting wraps retry, which wraps audit. The outermost decorator runs first. Put rate limiting outside, audit inside.

Review this code. It has 3 issues related to decorators and context managers.

def log_calls(func):
    def wrapper(*args):   # Issue 1: missing **kwargs
        print(f"Calling: {func.__name__}")
        return func(*args)
    return wrapper          # Issue 2: missing @functools.wraps

class DBConnection:
    def __enter__(self):
        self.conn = connect_db()
        return self.conn

    def __exit__(self, *args):
        return True           # Issue 3: suppresses ALL exceptions!

Issues:

  1. Missing **kwargs in wrapper — decorated functions with keyword arguments will break
  2. Missing @functools.wraps(func) — function name and docstring are lost
  3. __exit__ returns True — this silently swallows all exceptions, including real bugs. Should return False and close the connection.
