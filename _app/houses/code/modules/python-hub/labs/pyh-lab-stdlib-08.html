Logger Builder Lab

Build production-grade logging with Python's logging module — formatters, handlers, levels, and exception tracking.

1
Basic Logging

Set up basic logging with logging.basicConfig(). Configure a format string that includes the timestamp, log level, and message. Set the level to DEBUG so all messages are captured.

basic_log.py
Output
Click "Check" to validate...
Hint: logging.basicConfig(level=logging.DEBUG, format='%(asctime)s - %(levelname)s - %(message)s'). The format directives use %()s syntax: asctime, levelname, message, name, lineno are common fields.
Correct! basicConfig is the quickest way to get logging up and running. The format string controls exactly what appears in each log line.
2
File Handler

Add a FileHandler (or RotatingFileHandler) to write logs to a file. Create a Formatter separately and attach it to the handler. This pattern gives you more control than basicConfig.

file_handler.py
Output
Click "Check" to validate...
Hint: handler = logging.FileHandler('security.log') or RotatingFileHandler('security.log', maxBytes=1_000_000, backupCount=3). Create formatter: fmt = logging.Formatter('...'). Attach: handler.setFormatter(fmt). Add: logger.addHandler(handler).
Well done! FileHandler writes persistent logs. RotatingFileHandler prevents log files from consuming all disk space — a must-have for production services.
3
Multiple Levels

Create a logger that sends different log levels to different destinations. Console gets INFO and above, while the file gets DEBUG and above. Use separate handlers with different levels.

multi_level.py
Output
Click "Check" to validate...
Hint: console = logging.StreamHandler(), console.setLevel(logging.INFO). file_h = logging.FileHandler('ir.log'), file_h.setLevel(logging.DEBUG). The logger level must be <= the lowest handler level (DEBUG) for messages to reach both.
Excellent! Multi-handler routing is the standard pattern in production. Console shows summaries while files capture everything for forensic review.
4
Error Logger

Log exceptions with full tracebacks using logger.exception() or logging.error(..., exc_info=True). Wrap risky operations in try/except and capture the complete stack trace in your logs.

error_logger.py
Output
Click "Check" to validate...
Hint: try: risky_operation() except Exception as e: logger.exception("Operation failed"). The .exception() method logs at ERROR level and includes the full traceback automatically. Alternatively: logger.error("Failed", exc_info=True).
Great work! Logging exceptions with tracebacks is what separates production code from scripts. logger.exception() in a catch block is a pattern you will use thousands of times.
