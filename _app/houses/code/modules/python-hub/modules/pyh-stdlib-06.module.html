sys Module

The sys module provides access to Python interpreter variables and functions that interact with the runtime environment. It is the gateway between your script and the system it runs on.

Command-Line Arguments with sys.argv

sys.argv is a list containing the command-line arguments passed to the script. The first element is always the script name itself.

import sys

# sys.argv is a list of strings
# Running: python script.py hello world
# sys.argv = ["script.py", "hello", "world"]

print("Script:", sys.argv[0])
print("Arguments:", sys.argv[1:])
print("Argument count:", len(sys.argv) - 1)

Exiting and Version Info

import sys

# Exit with a status code (0 = success, non-zero = error)
if len(sys.argv) < 2:
    print("Usage: python script.py <filename>", file=sys.stderr)
    sys.exit(1)

# Python version information
print(sys.version)           # '3.12.0 (main, Oct  2 2023, ...)'
print(sys.version_info)      # sys.version_info(major=3, minor=12, ...)
print(sys.platform)          # 'linux', 'darwin', 'win32'

Standard Streams and Object Sizes

import sys

# Standard I/O streams
sys.stdout.write("Standard output\n")
sys.stderr.write("Error message\n")

# Redirect stdout to a file
original_stdout = sys.stdout
with open("output.txt", "w") as f:
    sys.stdout = f
    print("This goes to the file")
sys.stdout = original_stdout

# Get the size of objects in bytes
print(sys.getsizeof(42))          # 28 bytes
print(sys.getsizeof("hello"))    # 54 bytes
print(sys.getsizeof([1,2,3]))   # 88 bytes

# Module search path
for p in sys.path:
    print(p)
Tip: sys.argv vs argparse

For simple scripts with 1-2 arguments, sys.argv is fine. For anything more complex, use argparse (covered next). It handles types, defaults, help text, and validation automatically.

argparse Basics

The argparse module is Python's standard library solution for building command-line interfaces. It handles parsing, type conversion, default values, error messages, and auto-generated help text.

Creating a Parser

import argparse

# Create the parser
parser = argparse.ArgumentParser(
    description="Process and analyze log files"
)

# Add a positional argument (required)
parser.add_argument("filename",
    help="Path to the log file"
)

# Add optional arguments
parser.add_argument("-o", "--output",
    default="results.txt",
    help="Output file (default: results.txt)"
)

parser.add_argument("-v", "--verbose",
    action="store_true",
    help="Enable verbose output"
)

# Parse the arguments
args = parser.parse_args()
print(args.filename)   # positional arg
print(args.output)     # --output value
print(args.verbose)    # True/False

Type Conversion and Required Arguments

parser.add_argument("--port",
    type=int,
    default=8080,
    help="Port number (default: 8080)"
)

parser.add_argument("--threshold",
    type=float,
    required=True,
    help="Alert threshold (required)"
)

parser.add_argument("--format",
    choices=["json", "csv", "text"],
    default="text",
    help="Output format"
)

# Auto-generated help:
# $ python script.py --help
# usage: script.py [-h] [-o OUTPUT] [--port PORT] ...
Info: Auto-Generated Help

argparse automatically creates -h/--help flags. The help text comes from the description parameter and each argument's help string. This is a major advantage over manual sys.argv parsing.

argparse Advanced

For complex CLIs with multiple commands (like git add, git commit), argparse provides subparsers, mutually exclusive groups, and advanced argument patterns.

Subparsers (Sub-commands)

import argparse

parser = argparse.ArgumentParser(description="Project manager")
subparsers = parser.add_subparsers(dest="command", help="Available commands")

# 'init' sub-command
init_parser = subparsers.add_parser("init", help="Initialize a project")
init_parser.add_argument("name", help="Project name")

# 'build' sub-command
build_parser = subparsers.add_parser("build", help="Build the project")
build_parser.add_argument("--release", action="store_true")

# 'deploy' sub-command
deploy_parser = subparsers.add_parser("deploy", help="Deploy to server")
deploy_parser.add_argument("--target", required=True)

args = parser.parse_args()

# Usage:
# python tool.py init myproject
# python tool.py build --release
# python tool.py deploy --target production

Mutually Exclusive Groups

# Only one of --verbose or --quiet can be used
group = parser.add_mutually_exclusive_group()
group.add_argument("--verbose", action="store_true")
group.add_argument("--quiet", action="store_true")

nargs: Multiple Values

# Accept multiple files
parser.add_argument("files", nargs="+",
    help="One or more files to process")

# Optional list of tags
parser.add_argument("--tags", nargs="*",
    help="Optional tags")

# nargs values:
# N   - exactly N arguments
# '?' - zero or one argument
# '*' - zero or more arguments
# '+' - one or more arguments

Custom Type Validators

def valid_port(value):
    """Validate port number is in valid range."""
    port = int(value)
    if port < 1 or port > 65535:
        raise argparse.ArgumentTypeError(
            f"Port must be 1-65535, got {port}"
        )
    return port

parser.add_argument("--port", type=valid_port, default=8080)

getpass & Input

When your CLI needs to collect sensitive input like passwords, the getpass module provides secure input that hides what the user types. Combined with input validation patterns, you can build robust interactive prompts.

Secure Password Input

import getpass

# getpass.getpass() hides the typed input
password = getpass.getpass("Enter password: ")
# User types but nothing is displayed on screen

# Get the current system username
username = getpass.getuser()
print(f"Logged in as: {username}")

# Custom prompt
api_key = getpass.getpass("API Key: ")
token = getpass.getpass("Auth Token: ")

Input Validation Patterns

def get_valid_input(prompt, validator, error_msg="Invalid input"):
    """Keep asking until valid input is provided."""
    while True:
        value = input(prompt)
        if validator(value):
            return value
        print(error_msg)

# Use with different validators
age = get_valid_input(
    "Age: ",
    lambda x: x.isdigit() and 0 < int(x) < 150,
    "Enter a valid age (1-149)"
)

email = get_valid_input(
    "Email: ",
    lambda x: "@" in x and "." in x,
    "Enter a valid email address"
)
Security: Never Echo Passwords

Always use getpass.getpass() instead of input() for passwords, tokens, and API keys. The input() function displays what the user types, which can be captured by screen recording or shoulder surfing.

platform Module

The platform module provides detailed information about the system your code is running on. This is useful for system administration scripts, compatibility checks, and diagnostic tools.

System Information

import platform

# Operating system
print(platform.system())       # 'Linux', 'Windows', 'Darwin'
print(platform.release())      # '6.6.87' (kernel version)
print(platform.version())      # '#1 SMP ...' (build info)

# Machine and hostname
print(platform.machine())      # 'x86_64', 'arm64'
print(platform.node())         # hostname
print(platform.processor())    # processor description

# Python details
print(platform.python_version())        # '3.12.0'
print(platform.python_implementation()) # 'CPython'
print(platform.python_compiler())       # 'GCC 12.3.0'

Platform-Specific Behavior

import platform

# Cross-platform code
if platform.system() == "Windows":
    config_dir = "C:\\Users\\me\\AppData"
elif platform.system() == "Darwin":
    config_dir = "/Users/me/Library"
else:
    config_dir = "/home/me/.config"

# One-line system summary
print(platform.platform())
# 'Linux-6.6.87-x86_64-with-glib2.36'

# Structured info as a tuple
info = platform.uname()
print(info.system)    # 'Linux'
print(info.node)      # hostname
print(info.release)   # kernel version
print(info.machine)   # 'x86_64'
Tip: Combining sys and platform

Use sys.platform for quick checks ("linux", "win32", "darwin") and platform module for detailed info. They complement each other well in cross-platform scripts.

Building Real CLIs

A production-quality CLI combines argparse, sys, platform, and good UX patterns. This section ties everything together with exit codes, colored output, and progress indicators.

Exit Codes Convention

import sys

# Standard exit codes
EXIT_SUCCESS = 0
EXIT_ERROR = 1
EXIT_USAGE = 2    # Bad command-line arguments
EXIT_NOINPUT = 66  # Input file not found
EXIT_IOERR = 74    # I/O error

def main():
    try:
        result = process_files()
        if result:
            sys.exit(EXIT_SUCCESS)
        else:
            sys.exit(EXIT_ERROR)
    except FileNotFoundError:
        print("Error: File not found", file=sys.stderr)
        sys.exit(EXIT_NOINPUT)
    except KeyboardInterrupt:
        print("\nAborted.", file=sys.stderr)
        sys.exit(130)  # Convention for Ctrl+C

Simple Colored Output

# ANSI color codes (works on most terminals)
class Color:
    RED = "\033[91m"
    GREEN = "\033[92m"
    YELLOW = "\033[93m"
    BLUE = "\033[94m"
    RESET = "\033[0m"
    BOLD = "\033[1m"

def success(msg):
    print(f"{Color.GREEN}[OK]{Color.RESET} {msg}")

def error(msg):
    print(f"{Color.RED}[ERROR]{Color.RESET} {msg}", file=sys.stderr)

def warn(msg):
    print(f"{Color.YELLOW}[WARN]{Color.RESET} {msg}")

success("File processed successfully")
error("Could not connect to database")
warn("Config file not found, using defaults")

Putting It All Together

import argparse, sys, platform

def build_parser():
    parser = argparse.ArgumentParser(
        description="Network scanner tool",
        epilog="Example: %(prog)s scan 192.168.1.0/24 --port 80"
    )
    parser.add_argument("--version", action="version",
        version=f"%(prog)s 1.0.0 (Python {platform.python_version()})")

    sub = parser.add_subparsers(dest="command")

    scan = sub.add_parser("scan")
    scan.add_argument("target")
    scan.add_argument("--port", type=int, default=80)

    report = sub.add_parser("report")
    report.add_argument("--format", choices=["json", "csv"])

    return parser

def main():
    parser = build_parser()
    args = parser.parse_args()

    if not args.command:
        parser.print_help()
        sys.exit(2)

    # Dispatch to command handlers
    if args.command == "scan":
        print(f"Scanning {args.target} on port {args.port}")
    elif args.command == "report":
        print(f"Generating {args.format} report")

main()
Info: CLI Design Principles

Good CLIs follow these rules: (1) always provide --help, (2) use exit codes consistently, (3) write errors to stderr, (4) support both short (-v) and long (--verbose) flags, (5) provide --version, (6) handle Ctrl+C gracefully.
