subprocess.run()

The subprocess module lets Python execute external commands and programs. subprocess.run() is the recommended high-level interface for running a command and waiting for it to complete.

Basic Command Execution

import subprocess

# Run a command and capture output
result = subprocess.run(
    ["echo", "Hello from Python"],
    capture_output=True,
    text=True
)

print(result.stdout)       # "Hello from Python\n"
print(result.returncode)   # 0 (success)

Key Parameters

# capture_output — capture stdout and stderr
# text — decode bytes to str (otherwise returns bytes)
# check — raise CalledProcessError if command fails
# timeout — kill process after N seconds

result = subprocess.run(
    ["ls", "-la", "/tmp"],
    capture_output=True,
    text=True,
    check=True,          # Raises exception on failure
    timeout=10           # Kill after 10 seconds
)

print(result.stdout)
print(result.stderr)       # Error output (if any)

Handling Return Codes

result = subprocess.run(["grep", "pattern", "file.txt"],
    capture_output=True, text=True
)

if result.returncode == 0:
    print("Found:", result.stdout)
elif result.returncode == 1:
    print("Pattern not found")
else:
    print("Error:", result.stderr)

# Using check=True raises an exception on non-zero exit
try:
    subprocess.run(["false"], check=True)
except subprocess.CalledProcessError as e:
    print(f"Command failed with code {e.returncode}")
Security: Never Pass Unsanitized Input

Never construct commands from user input without sanitizing. Always pass commands as a list (not a string) and never use shell=True with user-provided data. This prevents shell injection attacks where an attacker could run arbitrary commands.

subprocess Advanced

For long-running processes, streaming output, or piping between commands, you need Popen — the lower-level interface that gives you full control over process I/O.

Popen for Streaming Output

import subprocess

# Stream output line by line (useful for long-running commands)
proc = subprocess.Popen(
    ["ping", "-c", "4", "8.8.8.8"],
    stdout=subprocess.PIPE,
    stderr=subprocess.PIPE,
    text=True
)

# Read output line by line as it arrives
for line in proc.stdout:
    print("[LIVE]", line.strip())

# Wait for process to finish
proc.wait()
print("Exit code:", proc.returncode)

Piping Between Processes

# Equivalent to: cat /var/log/syslog | grep error | wc -l
cat = subprocess.Popen(
    ["cat", "/var/log/syslog"],
    stdout=subprocess.PIPE
)
grep = subprocess.Popen(
    ["grep", "-i", "error"],
    stdin=cat.stdout,
    stdout=subprocess.PIPE
)
wc = subprocess.Popen(
    ["wc", "-l"],
    stdin=grep.stdout,
    stdout=subprocess.PIPE,
    text=True
)

cat.stdout.close()
grep.stdout.close()
output = wc.communicate()[0]
print("Error lines:", output.strip())

communicate() and poll()

# communicate() — send input and read all output
proc = subprocess.Popen(
    ["sort"],
    stdin=subprocess.PIPE,
    stdout=subprocess.PIPE,
    text=True
)
stdout, stderr = proc.communicate(input="banana\napple\ncherry")
print(stdout)  # apple\nbanana\ncherry

# poll() — check if process is still running
proc = subprocess.Popen(["sleep", "5"])
while proc.poll() is None:
    print("Still running...")
    time.sleep(1)
print("Done!")
Tip: Always Close Pipes

When chaining Popen processes, close the upstream stdout pipe after connecting it as stdin to the next process. This allows the SIGPIPE signal to propagate correctly if the downstream process exits early.

shlex — Safe Command Parsing

The shlex module provides tools for safely splitting and quoting shell command strings. It is essential for preventing shell injection when working with subprocess.

shlex.split() — Safe String to List

import shlex

# Safely split a command string into a list
cmd_str = 'grep -r "hello world" /home/user/docs'
parts = shlex.split(cmd_str)
print(parts)
# ['grep', '-r', 'hello world', '/home/user/docs']
# Note: "hello world" is kept as one argument!

# Correct handling of quotes and escapes
cmd = shlex.split("echo 'it\\'s a test'")
print(cmd)  # ['echo', "it's a test"]

shlex.quote() — Escape for Shell Safety

import shlex

# Make a string safe for shell usage
filename = "my file; rm -rf /"  # Malicious input!
safe = shlex.quote(filename)
print(safe)  # "'my file; rm -rf /'" — safely quoted

# Building safe command strings
user_input = "report.txt"
cmd = f"cat {shlex.quote(user_input)}"
print(cmd)  # "cat report.txt"
Security: shell=True Is Dangerous

Using subprocess.run(cmd, shell=True) passes the command through a shell interpreter, enabling shell features like pipes and globbing but also shell injection. An attacker can inject ; rm -rf / or $(malicious_command). Always use a list and shell=False (the default). If you must use shell=True, sanitize with shlex.quote().

Safe vs Unsafe Patterns

import subprocess, shlex

user_file = "report.txt; cat /etc/passwd"  # Malicious!

# DANGEROUS — shell injection possible
# subprocess.run(f"cat {user_file}", shell=True)  # DON'T!

# SAFE — list form, no shell interpretation
subprocess.run(["cat", user_file], capture_output=True)

# SAFE — if you must use shell=True, quote the input
safe_cmd = f"cat {shlex.quote(user_file)}"
subprocess.run(safe_cmd, shell=True, capture_output=True)

sched — Task Scheduling

The sched module provides a general-purpose event scheduler for running tasks at specific times or after delays. It is simpler than cron jobs and works cross-platform.

Basic Scheduling

import sched
import time

# Create a scheduler
scheduler = sched.scheduler(time.time, time.sleep)

def task(name):
    print(f"[{time.strftime('%H:%M:%S')}] Running: {name}")

# Schedule tasks with delays (seconds from now)
scheduler.enter(2, 1, task, ("Task A",))   # 2 sec, priority 1
scheduler.enter(5, 1, task, ("Task B",))   # 5 sec, priority 1
scheduler.enter(2, 2, task, ("Task C",))   # 2 sec, priority 2

# Priority matters when events are simultaneous:
# Lower number = higher priority
# Task A (pri 1) runs before Task C (pri 2) at the 2-sec mark

scheduler.run()  # Blocks until all events are processed

Absolute Time Scheduling

import sched, time

scheduler = sched.scheduler(time.time, time.sleep)

# Schedule at an absolute time
target_time = time.time() + 10  # 10 seconds from now
scheduler.enterabs(target_time, 1, task, ("Absolute Task",))

# Check the queue
print("Queued events:", len(scheduler.queue))
for event in scheduler.queue:
    print(f"  Time: {event.time:.0f}, Priority: {event.priority}")

scheduler.run()
Info: sched vs threading.Timer

sched runs events sequentially in a single thread. For concurrent task execution, consider threading.Timer or asyncio. The sched module is best for simple sequential scheduling where tasks don't overlap.

signal Module

The signal module lets you handle Unix signals — asynchronous notifications sent to your process by the OS or other processes. The most important use is implementing graceful shutdown on Ctrl+C (SIGINT) or system termination (SIGTERM).

Handling SIGINT (Ctrl+C)

import signal
import sys

def graceful_shutdown(signum, frame):
    """Handle Ctrl+C gracefully."""
    print("\nReceived signal", signum)
    print("Cleaning up resources...")
    # Close files, save state, flush buffers
    sys.exit(0)

# Register signal handler
signal.signal(signal.SIGINT, graceful_shutdown)
signal.signal(signal.SIGTERM, graceful_shutdown)

print("Running... Press Ctrl+C to stop")
while True:
    pass  # Main loop

Common Signals

  • SIGINT (2) — Interrupt from keyboard (Ctrl+C)
  • SIGTERM (15) — Termination request (default kill signal)
  • SIGALRM (14) — Alarm clock (timer expiration)
  • SIGHUP (1) — Hangup (terminal closed)
  • SIGKILL (9) — Force kill (cannot be caught or handled)

Timeout with SIGALRM

import signal

def timeout_handler(signum, frame):
    raise TimeoutError("Operation timed out")

# Set a 5-second alarm (Unix only)
signal.signal(signal.SIGALRM, timeout_handler)
signal.alarm(5)

try:
    # Long operation that might hang
    result = slow_network_call()
    signal.alarm(0)  # Cancel the alarm
except TimeoutError:
    print("Operation timed out after 5 seconds")
Tip: Docker and SIGTERM

When Docker stops a container, it sends SIGTERM first and waits 10 seconds before sending SIGKILL. If your Python app handles SIGTERM gracefully (saving state, closing connections), it shuts down cleanly. Without a handler, Docker force-kills your process, potentially corrupting data.

Automation Patterns

This section combines subprocess, shlex, sched, and signal into real automation scripts. These patterns form the basis of deployment tools, monitoring systems, and maintenance scripts.

Pattern: Safe Command Runner with Timeout

import subprocess, shlex, signal, sys

def safe_execute(cmd_str, timeout=30):
    """Safely execute a command string with timeout."""
    parts = shlex.split(cmd_str)
    try:
        result = subprocess.run(
            parts,
            capture_output=True,
            text=True,
            check=True,
            timeout=timeout
        )
        return {"success": True, "output": result.stdout}
    except subprocess.TimeoutExpired:
        return {"success": False, "error": "Timeout"}
    except subprocess.CalledProcessError as e:
        return {"success": False, "error": e.stderr}

Pattern: Scheduled Health Checker

import subprocess, sched, time, signal, sys

shutdown = False

def on_signal(sig, frame):
    global shutdown
    shutdown = True

signal.signal(signal.SIGINT, on_signal)

def check_service(host, scheduler):
    """Ping a host and reschedule."""
    if shutdown:
        return
    result = subprocess.run(
        ["ping", "-c", "1", "-W", "2", host],
        capture_output=True
    )
    status = "UP" if result.returncode == 0 else "DOWN"
    print(f"[{time.strftime('%H:%M:%S')}] {host}: {status}")
    # Reschedule every 30 seconds
    scheduler.enter(30, 1, check_service, (host, scheduler))

s = sched.scheduler(time.time, time.sleep)
s.enter(0, 1, check_service, ("8.8.8.8", s))
s.run()
Info: Real-World Automation

Production automation tools like Ansible, Fabric, and SaltStack use these same primitives: subprocess for command execution, signal handling for graceful shutdown, and scheduling for recurring tasks. Understanding the stdlib gives you insight into how these tools work under the hood.
