What Is C++?

C++ was created by Bjarne Stroustrup at Bell Labs in 1979, initially as "C with Classes." Standardized by ISO in 1998 (C++98) and significantly modernized with C++11, C++14, C++17, and C++20, it is today one of the most powerful and widely deployed languages in the world.

C++ sits at the intersection of high-level abstraction and low-level control. It gives you object-oriented programming, templates, the Standard Template Library, and modern language features -- while still letting you manipulate memory directly, work with raw pointers, and produce machine code as efficient as hand-written assembly.

Zero-Overhead Abstraction You pay only for the features you use. Unused abstractions compile away to nothing.
Systems Programming Operating systems, game engines, browsers, databases, and malware are all written in C++.
Security Research Reverse engineering, exploit development, and binary analysis all require deep C++ fluency.
Industry Dominance Chrome, Windows kernel drivers, Unreal Engine, LLVM, and most embedded firmware run on C++.

C vs C++

C++ is a superset of C -- almost all valid C code compiles as C++. The differences matter for security professionals:

FeatureCC++
Object-OrientedNo (structs only)Yes (classes, inheritance)
Type SafetyWeakStronger (references, RAII)
Memory ManagementManual (malloc/free)Manual + smart pointers
Templates/GenericsNoYes (powerful)
Standard Librarylibc (small)STL (large, rich)
Use CaseOS kernels, embeddedEverything C does + more

When you analyze a buffer overflow in a CTF, you are almost always looking at C or C++ code. Understanding both languages is essential for security work.

Setting Up Your Toolchain

The standard C++ compiler on Linux is g++ (part of GCC). On macOS, use clang++. On Windows, install MinGW or use WSL.

terminal -- install and verify
# Linux (Debian/Ubuntu)
$ sudo apt install g++ build-essential

# Verify installation
$ g++ --version
g++ (Ubuntu 13.2.0-23ubuntu4) 13.2.0

# macOS (installs clang++ via Xcode command line tools)
$ xcode-select --install
$ clang++ --version
Apple clang version 15.0.0 (clang-1500.3.9.4)

You also want to know which C++ standard you are compiling against. The flag -std=c++17 enables C++17 features. Without it, most compilers default to C++14 or older.

Your First C++ Program

Create a file called hello.cpp:

hello.cpp
// Include the input/output stream library
#include <iostream>

// Bring the std namespace into scope so we don't need std::cout everywhere
using namespace std;

// Every C++ program starts at main()
int main() {
    cout << "Hello, World!" << endl;

    // Variables
    int year = 2026;
    string role = "Operator";

    cout << "Year: " << year << ", Role: " << role << endl;

    return 0;  // 0 means success
}

Compile and run it:

terminal
$ g++ -std=c++17 -o hello hello.cpp
$ ./hello
Hello, World!
Year: 2026, Role: Operator

The -o hello flag names the output binary. Without it, you get a file called a.out by default. The ./ prefix runs the binary from the current directory.

The Compilation Pipeline

Understanding compilation is non-negotiable for security work. When you run g++ hello.cpp, four distinct stages happen:

1. Preprocessor Processes #include, #define, #ifdef directives. Expands macros and pastes in header files. Output is pure C++ source.
2. Compiler Translates C++ source to assembly language. This is where syntax errors are caught and optimizations are applied.
3. Assembler Converts assembly to machine code object files (.o). The binary is almost complete but unlinked.
4. Linker Combines object files and resolves external references (like calls to printf or cout). Produces the final executable.
terminal -- manual pipeline stages
# Run only the preprocessor
$ g++ -E hello.cpp -o hello.ii

# Compile to assembly only
$ g++ -S hello.cpp -o hello.s

# Compile to object file only
$ g++ -c hello.cpp -o hello.o

# Link object file to produce binary
$ g++ hello.o -o hello

# View generated assembly (useful for security analysis)
$ objdump -d hello | head -40

Useful Compiler Flags

These flags appear constantly in security-oriented C++ work:

common g++ flags
# Enable warnings (always use this during development)
g++ -Wall -Wextra -o program program.cpp

# Compile with debug symbols (needed for gdb)
g++ -g -o program program.cpp

# Enable optimizations (what production code uses)
g++ -O2 -o program program.cpp

# Enable stack protector (security hardening)
g++ -fstack-protector-strong -o program program.cpp

# Disable stack protector (for exploit lab work)
g++ -fno-stack-protector -o program program.cpp

# Specify C++ standard
g++ -std=c++17 -o program program.cpp

In module 09 (Security Applications), you will use these flags intentionally -- enabling and disabling protections to analyze how buffer overflow exploits work in practice.

Try It Yourself

Create hello.cpp and compile it yourself. Then:

  1. Run g++ -S hello.cpp -o hello.s and open hello.s in a text editor -- you are looking at raw x86 assembly
  2. Count how many lines of assembly a simple "Hello World" generates
  3. Run with -O2 and compare -- does optimization change the assembly?
  4. Intentionally introduce a syntax error (remove a semicolon) and observe the compiler error message

Try It Yourself

Extend hello.cpp to:

  1. Ask the user to enter their name using cin >> name
  2. Print a greeting using the entered name
  3. Print the size of the name string using name.size()
  4. Compile with -Wall -Wextra and fix any warnings

Key Takeaways

  • C++ is a superset of C with OOP, templates, RAII, and the Standard Template Library
  • Every C++ program has a main() function that returns an int (0 = success)
  • Compile with g++ -std=c++17 -Wall -o program program.cpp
  • The four pipeline stages are: preprocessor, compiler, assembler, linker
  • Security flags like -fstack-protector-strong and -g are essential for security work
