Move Semantics

Introduced in C++11, move semantics allow resources to be transferred rather than copied. A move operation takes ownership of data from a temporary (rvalue) object, leaving the source in a valid but empty state. This eliminates expensive deep copies for large objects like strings, vectors, and heap-managed buffers.

move_semantics.cpp
#include <iostream>
#include <vector>
#include <string>
#include <utility>  // std::move
using namespace std;

class Payload {
public:
    vector<unsigned char> data;
    string label;

    Payload(const string& lbl, size_t size) : label(lbl), data(size, 0) {
        cout << "Constructed: " << lbl << " (" << size << " bytes)" << endl;
    }

    // Copy constructor: expensive deep copy
    Payload(const Payload& other) : label(other.label), data(other.data) {
        cout << "COPIED: " << label << " (" << data.size() << " bytes)" << endl;
    }

    // Move constructor: zero-cost transfer of ownership
    Payload(Payload&& other) noexcept
        : label(move(other.label)), data(move(other.data)) {
        cout << "MOVED (fast, no copy)" << endl;
    }
};

int main() {
    Payload p1("shellcode", 1024);

    // Copy: expensive (1024 bytes copied)
    Payload p2 = p1;
    cout << "p1 still valid: " << p1.data.size() << " bytes" << endl;

    // Move: p1's data transferred to p3 -- no copy
    Payload p3 = move(p1);
    cout << "p1 after move: " << p1.data.size() << " bytes (empty)" << endl;
    cout << "p3 after move: " << p3.data.size() << " bytes" << endl;

    return 0;
}

Multithreading

C++11 standardized threading with <thread>, <mutex>, and <atomic>. Concurrency is essential for network tools, scanners, and security software that needs to process multiple connections simultaneously.

threads.cpp -- concurrent port scan simulation
#include <iostream>
#include <thread>
#include <mutex>
#include <vector>
using namespace std;

mutex output_mutex;   // prevents interleaved cout output
vector<int> open_ports;
mutex ports_mutex;    // protects shared vector

// Simulate checking a single port
void checkPort(int port) {
    // Simulate network delay (in real code: actual connect() call)
    bool is_open = (port % 100 == 0);  // pretend 100,200,300... are open

    if (is_open) {
        // lock_guard: RAII mutex lock -- released when guard goes out of scope
        lock_guard<mutex> lock(ports_mutex);
        open_ports.push_back(port);
    }

    lock_guard<mutex> out_lock(output_mutex);
    cout << "Port " << port << (is_open ? ": OPEN" : ": closed") << endl;
}

int main() {
    vector<thread> threads;

    // Launch 10 threads scanning ports 95-105
    for (int port = 95; port <= 105; port++) {
        threads.emplace_back(checkPort, port);
    }

    // Wait for all threads to finish before accessing results
    for (auto& t : threads) {
        t.join();
    }

    cout << "\nOpen ports found: ";
    for (int p : open_ports) cout << p << " ";
    cout << endl;

    return 0;
}
Compile with -lpthread

Threading requires linking the pthread library: g++ -std=c++17 -o scanner threads.cpp -lpthread. On modern Linux with GCC 13+, threading is often linked automatically, but the explicit flag is always safe.

Design Patterns

Design patterns are proven solutions to recurring design problems. Three are especially common in security tooling:

singleton.cpp -- one instance, global access point
#include <iostream>
#include <string>
using namespace std;

// Singleton: only one config instance exists in the entire program
class Config {
private:
    string log_level = "INFO";
    int timeout = 30;

    // Private constructor prevents external instantiation
    Config() = default;

public:
    // Meyers Singleton: thread-safe in C++11, static local variable
    static Config& instance() {
        static Config inst;
        return inst;
    }

    // Prevent copy and assignment
    Config(const Config&) = delete;
    Config& operator=(const Config&) = delete;

    void setLogLevel(const string& l) { log_level = l; }
    string getLogLevel() const { return log_level; }
    int getTimeout() const { return timeout; }
};

int main() {
    Config::instance().setLogLevel("DEBUG");
    cout << Config::instance().getLogLevel() << endl;  // DEBUG
    cout << Config::instance().getTimeout() << endl;   // 30
    return 0;
}
observer.cpp -- event notification pattern (alert system)
#include <iostream>
#include <vector>
#include <string>
#include <functional>
using namespace std;

class AlertSystem {
private:
    // Store callbacks as std::function for maximum flexibility
    vector<function<void(const string&)>> listeners;

public:
    void subscribe(function<void(const string&)> callback) {
        listeners.push_back(move(callback));
    }

    void emit(const string& event) {
        for (const auto& cb : listeners) cb(event);
    }
};

int main() {
    AlertSystem alerts;

    // Subscribe with lambdas -- no separate class needed
    alerts.subscribe([](const string& e) {
        cout << "[SIEM] Alert: " << e << endl;
    });
    alerts.subscribe([](const string& e) {
        cout << "[EMAIL] Notifying team: " << e << endl;
    });

    alerts.emit("Brute force detected on 192.168.1.50");
    alerts.emit("CVE-2021-44228 probe detected");
    return 0;
}

CMake: Building Multi-File Projects

CMake is the de-facto build system for C++ projects. It generates platform-specific build files (Makefiles on Linux, Visual Studio projects on Windows). Any serious C++ project you encounter in the wild uses CMake or a similar system.

CMakeLists.txt -- minimal project
# Minimum CMake version required
cmake_minimum_required(VERSION 3.16)

# Project name and language
project(NetworkScanner CXX)

# Require C++17
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

# Enable hardening flags for all targets
add_compile_options(
    -Wall -Wextra
    -fstack-protector-strong
    -D_FORTIFY_SOURCE=2
)

# Define the executable and its source files
add_executable(scanner
    src/main.cpp
    src/PortScanner.cpp
    src/ReportEngine.cpp
)

# Link threading library
find_package(Threads REQUIRED)
target_link_libraries(scanner Threads::Threads)
terminal -- cmake build workflow
# Create out-of-source build directory (keeps source tree clean)
$ mkdir build && cd build

# Generate build files (Makefile on Linux)
$ cmake ..

Key Takeaways

  • Move semantics (std::move, &&) transfer ownership instead of copying -- critical for performance
  • Always protect shared data with mutex + lock_guard -- never with raw lock/unlock pairs
  • Singleton via Meyers static local is thread-safe in C++11+ without additional locking
  • Observer with std::function is flexible and decoupled -- preferred for event systems
  • CMake is the industry standard build system -- learn it before interviewing for C++ roles
  • Compile with -fsanitize=address and -fsanitize=thread during development to catch bugs early
