CPP-05

Inheritance & Polymorphism

< C++ Track

Learning Objectives

  • Derive classes from base classes using public, protected, and private inheritance
  • Override virtual functions for runtime polymorphism
  • Define pure virtual functions to create abstract base classes
  • Understand the virtual table (vtable) and how dynamic dispatch works
  • Use virtual destructors to prevent resource leaks

Inheritance

Inheritance lets a derived class reuse and extend a base class. The derived class inherits all public and protected members of the base. This models "is-a" relationships -- a TCPPacket is-a Packet.

network_hierarchy.cpp
#include <iostream>
#include <string>
using namespace std;

// Base class
class Packet {
protected:
    // protected: visible to derived classes, hidden from outside
    string src_ip;
    string dst_ip;

public:
    Packet(const string& src, const string& dst)
        : src_ip(src), dst_ip(dst) {}

    // virtual: allows derived classes to override this behavior
    virtual void describe() const {
        cout << "Packet: " << src_ip << " -> " << dst_ip << endl;
    }

    // Virtual destructor is REQUIRED when using polymorphism
    virtual ~Packet() = default;
};

// Derived class: public inheritance preserves base's public/protected
class TCPPacket : public Packet {
private:
    int src_port, dst_port;
    bool syn, ack, fin;

public:
    TCPPacket(const string& src, const string& dst, int sp, int dp, bool s, bool a, bool f)
        : Packet(src, dst), src_port(sp), dst_port(dp), syn(s), ack(a), fin(f) {}

    // override keyword: compile error if base doesn't have this virtual function
    void describe() const override {
        cout << "TCP: " << src_ip << ":" << src_port
             << " -> " << dst_ip << ":" << dst_port
             << " [SYN=" << syn << " ACK=" << ack << " FIN=" << fin << "]" << endl;
    }
};

class UDPPacket : public Packet {
private:
    int src_port, dst_port;
    int length;

public:
    UDPPacket(const string& src, const string& dst, int sp, int dp, int len)
        : Packet(src, dst), src_port(sp), dst_port(dp), length(len) {}

    void describe() const override {
        cout << "UDP: " << src_ip << ":" << src_port
             << " -> " << dst_ip << ":" << dst_port
             << " len=" << length << endl;
    }
};

Dynamic Dispatch and the vtable

When you call a virtual function through a base class pointer or reference, C++ uses the virtual table (vtable) to find the correct function at runtime. Every class with virtual functions has a hidden vtable pointer added to each object. This is the mechanism that makes polymorphism work -- and is a target for vtable hijacking attacks.

polymorphism_demo.cpp
int main() {
    // Base class pointers can hold derived class objects
    Packet* packets[3];
    packets[0] = new Packet("1.2.3.4", "5.6.7.8");
    packets[1] = new TCPPacket("192.168.1.1", "10.0.0.1", 54321, 80, true, false, false);
    packets[2] = new UDPPacket("192.168.1.2", "8.8.8.8", 50000, 53, 42);

    // The vtable dispatches to the correct describe() at runtime
    for (int i = 0; i < 3; i++) {
        packets[i]->describe();  // runtime dispatch
    }

    // Virtual destructor ensures derived class destructor is called
    for (int i = 0; i < 3; i++) {
        delete packets[i];
    }

    return 0;
}
output
Packet: 1.2.3.4 -> 5.6.7.8
TCP: 192.168.1.1:54321 -> 10.0.0.1:80 [SYN=1 ACK=0 FIN=0]
UDP: 192.168.1.2:50000 -> 8.8.8.8:53 len=42
vtable Layout (Security Relevance)

Each object with virtual functions holds a hidden vptr at offset 0. The vptr points to the class's vtable -- an array of function pointers. Buffer overflows that corrupt heap memory can overwrite vptrs, redirecting virtual function calls to attacker-controlled code. This is the foundation of vtable hijacking exploits (CVE targets in browsers and game engines).

Abstract Classes and Pure Virtual Functions

A pure virtual function (= 0) has no implementation in the base class and must be overridden by derived classes. Any class containing a pure virtual function becomes abstract -- it cannot be instantiated directly. This enforces a contract on derived classes.

abstract_scanner.cpp
#include <iostream>
#include <string>
using namespace std;

// Abstract base: defines the interface every scanner must implement
class Scanner {
public:
    // Pure virtual: all subclasses MUST implement these
    virtual void scan(const string& target) = 0;
    virtual string getName() const = 0;

    // Non-pure virtual: default behavior, can be overridden
    virtual void report() {
        cout << "[" << getName() << "] Scan complete" << endl;
    }

    virtual ~Scanner() = default;
};

class PortScanner : public Scanner {
public:
    void scan(const string& target) override {
        cout << "Scanning ports on " << target << "..." << endl;
    }
    string getName() const override { return "PortScanner"; }
};

class VulnScanner : public Scanner {
public:
    void scan(const string& target) override {
        cout << "Probing CVEs on " << target << "..." << endl;
    }
    string getName() const override { return "VulnScanner"; }
};

int main() {
    // Cannot create Scanner directly: Scanner s;  -- compile error
    Scanner* scanners[] = { new PortScanner(), new VulnScanner() };

    for (auto* s : scanners) {
        s->scan("10.0.0.1");
        s->report();
        delete s;
    }
    return 0;
}
Virtual Destructors Are Not Optional

If you delete a derived class object through a base class pointer and the base destructor is not virtual, only the base destructor runs. The derived class destructor is silently skipped, causing resource leaks. Always make destructors virtual in polymorphic base classes.

Build a plugin system using abstract classes:

  2. Implement two concrete plugins: LogPlugin and AlertPlugin
  3. Store them in a vector<Plugin*> and call execute() on each
  4. Use dynamic_cast to check if a Plugin pointer is actually a LogPlugin at runtime

Key Takeaways

  • Public inheritance models "is-a"; the derived class can be used wherever the base is expected
  • Mark functions virtual in the base to enable runtime dispatch through the vtable
  • Always add override on derived overrides -- the compiler will catch mismatches
  • Pure virtual functions (= 0) make a class abstract -- cannot be instantiated
  • Virtual destructors prevent resource leaks in polymorphic delete
  • The vtable is a security-relevant data structure -- vtable hijacking is a real attack class
