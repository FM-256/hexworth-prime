Primitive Data Types

C++ has a rich set of built-in types. Sizes are platform-dependent but the values below are typical for 64-bit systems. Knowing exact sizes matters for buffer analysis and binary exploitation.

types.cpp -- declaring and inspecting types
#include <iostream>
#include <climits>   // INT_MAX, CHAR_MAX, etc.
using namespace std;

int main() {
    // sizeof() returns the size in bytes at compile time
    cout << "int:       " << sizeof(int) << " bytes, max: " << INT_MAX << endl;
    cout << "long long: " << sizeof(long long) << " bytes" << endl;
    cout << "char:      " << sizeof(char) << " byte,  max: " << CHAR_MAX << endl;
    cout << "double:    " << sizeof(double) << " bytes" << endl;

    // Integer overflow -- a classic security vulnerability
    unsigned char x = 255;
    x++;  // Wraps to 0 -- integer overflow!
    cout << "255 + 1 as unsigned char: " << (int)x << endl;

    return 0;
}
output

long long: 8 bytes
char:      1 byte,  max: 127
double:    8 bytes
255 + 1 as unsigned char: 0

const and constexpr

const declares a variable that cannot be changed after initialization. constexpr goes further -- it means the value is known at compile time, enabling the compiler to substitute the value directly into machine code.

constants.cpp
#include <iostream>
using namespace std;

// constexpr: evaluated at compile time, embedded in the binary
constexpr int BUFFER_SIZE = 1024;
constexpr double PI = 3.14159265358979;

int main() {
    // const: cannot reassign after initialization
    const int port = 8080;
    // port = 9090;  -- compile error: assignment of read-only variable

    // constexpr can be used as array size (const cannot always be)
    char buffer[BUFFER_SIZE];

    cout << "Buffer: " << BUFFER_SIZE << " bytes" << endl;
    cout << "PI: "     << PI << endl;
    cout << "Port: "   << port << endl;

    return 0;
}

Type Inference with auto

The auto keyword tells the compiler to deduce the type from the initializer. This is not dynamic typing -- the type is fixed at compile time. It is shorthand that reduces verbosity, especially with long STL type names.

auto_types.cpp
#include <iostream>
#include <vector>
#include <typeinfo>
using namespace std;

int main() {
    auto x = 42;          // int
    auto y = 3.14;        // double
    auto z = 'A';         // char
    auto flag = true;    // bool
    auto msg = "hello";  // const char* (NOT std::string)

    // typeid gives the mangled type name at runtime
    cout << typeid(x).name() << endl;   // i (int)
    cout << typeid(y).name() << endl;   // d (double)
    cout << typeid(msg).name() << endl; // PKc (const char*)

    // Practical use: long iterator type written concisely
    vector<int> nums = {10, 20, 30};
    for (auto it = nums.begin(); it != nums.end(); ++it) {
        cout << *it << " ";
    }
    cout << endl;

    return 0;
}

References

A reference is an alias for an existing variable. Unlike a pointer, a reference must be initialized when declared and cannot be rebound to a different variable. References are safer than pointers and are the preferred way to pass objects to functions.

references.cpp
#include <iostream>
using namespace std;

// Pass by reference: modifies the original variable
void doubleIt(int& n) {
    n *= 2;
}

// Pass by const reference: read-only, no copy overhead
void printValue(const int& n) {
    cout << "Value: " << n << endl;
}

int main() {
    int score = 50;
    int& ref = score;  // ref IS score -- same memory address

    ref = 100;  // changes score too
    cout << score << endl;  // 100
    cout << (&score == &ref) << endl;  // 1 (same address)

    doubleIt(score);
    cout << score << endl;  // 200

    printValue(score);  // no copy, no modification allowed

    return 0;
}

Type Casting

C++ provides four named cast operators. Using the correct one matters -- especially in security-critical code where incorrect casts are a common source of vulnerabilities.

casting.cpp
#include <iostream>
using namespace std;

int main() {
    // static_cast: safe compile-time conversion between related types
    double pi = 3.14159;
    int truncated = static_cast<int>(pi);  // 3 (truncates decimal)
    cout << truncated << endl;

    // C-style cast (avoid in C++ code -- no safety checks)
    int bad_cast = (int)pi;  // works but can silently do dangerous things

    // reinterpret_cast: raw bit reinterpretation
    // Used in reverse engineering to inspect raw memory
    int value = 0x41414141;  // "AAAA" in ASCII
    char* bytes = reinterpret_cast<char*>(&value);
    cout << bytes[0] << bytes[1] << bytes[2] << bytes[3] << endl; // AAAA

    // const_cast: adds or removes const qualifier
    const int locked = 42;
    int* mutable_ptr = const_cast<int*>(&locked);
    // Modifying through const_cast is undefined behavior -- shown for awareness

    return 0;
}
Security Note: Integer Overflow and Truncation

Casting a large integer to a smaller type silently truncates the high bits. Attackers exploit this to bypass bounds checks: if a size value is received as a 64-bit unsigned int and cast to a 32-bit int, values above 2^31 become negative, bypassing "if (size > 0)" guards. This class of vulnerability appears regularly in CVEs.

Try It Yourself

Write a program that demonstrates integer overflow as a security issue:

  1. Declare unsigned short user_input = 65535
  2. Add 1 to it and print the result -- what happens?
  3. Now try: cast that value to int before adding -- does the result change?
  4. Print the size of each type using sizeof()

Try It Yourself

Write a swap function that uses references:

  1. Declare void swap(int& a, int& b)
  2. Implement it using a temporary variable
  3. Verify the original variables were modified after calling it
  4. Try writing the same swap without references (pass by value) -- does it still work?

Key Takeaways

  • Use sizeof() to verify type sizes -- critical for buffer math
  • Integer overflow is silent and is a major vulnerability class in C/C++
  • const prevents reassignment; constexpr evaluates at compile time
  • References are aliases -- same address, safer than raw pointers
  • Prefer static_cast over C-style casts for type safety
  • reinterpret_cast is used in binary analysis to view memory as different types
