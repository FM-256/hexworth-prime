Value Types vs Reference Types

C#'s type system is split into two categories. Value types store data directly on the stack (or inline in a containing object). Reference types store a pointer to heap memory.

types.cs
// Value types -- copied on assignment
int a = 10;
int b = a;   // b is an independent copy
b = 99;
Console.WriteLine(a); // still 10

// Reference types -- both point to same object
var list1 = new List<int> { 1, 2, 3 };
var list2 = list1;   // same reference
list2.Add(4);
Console.WriteLine(list1.Count); // 4 -- both see the change

Nullable Types

By default, value types cannot be null. Append ? to make them nullable. In .NET 6+ with nullable reference types enabled, the compiler also warns you about potential null dereferences on reference types.

nullable.cs
// Nullable value type -- int? can hold null
int? port = null;
int? port2 = 8443;

// Check before use
if (port.HasValue)
    Console.WriteLine($"Port: {port.Value}");
else
    Console.WriteLine("No port specified");

// Null-coalescing operator: use right side if left is null
int resolved = port ?? 443;   // 443 (port is null)
Console.WriteLine(resolved);

// Null-conditional operator: ?. short-circuits on null
string? input = null;
int? len = input?.Length;  // null instead of NullReferenceException

// Null-forgiving operator: ! tells compiler you know it's not null
string definitelyNotNull = input!;  // use only when you are certain

var, const, and readonly

declarations.cs
// var: compiler infers the type -- still statically typed
var host = "192.168.1.1";     // string
var port = 8080;              // int
var ratio = 1.5;              // double

// const: compile-time constant, cannot change
const int MaxRetries = 3;
const string DefaultCipher = "AES-256-GCM";

// readonly: set once (in declaration or constructor)
readonly string _sessionId = Guid.NewGuid().ToString();

// Digit separators make large numbers readable
long maxBytes = 1_073_741_824;  // 1 GB
int hexColor = 0xFF_A0_00;

// Verbatim strings: @ prefix, backslashes are literal
string path = @"C:\Users\Operator\AppData\logs";

String Interpolation & Formatting

strings.cs
string ip = "10.0.0.14";
int openPorts = 3;
double latency = 14.7832;

// String interpolation: $"..." embeds expressions directly
Console.WriteLine($"Host: {ip}, Open ports: {openPorts}");

// Format specifiers inside interpolation
Console.WriteLine($"Latency: {latency:F2} ms");  // 14.78 ms
Console.WriteLine($"Hex: {openPorts:X4}");       // 0003
Console.WriteLine($"Padded: {ip,20}");          // right-aligned in 20 chars

// Raw string literals (C# 11+): triple quotes, no escaping needed
string json = """
{
  "host": "10.0.0.14",
  "port": 443
}
""";

// String methods commonly used in security contexts
string userInput = "  admin'; DROP TABLE users; -- ";
string trimmed = userInput.Trim();
bool hasSql = trimmed.Contains("DROP", StringComparison.OrdinalIgnoreCase);

Type Casting

casting.cs
// Implicit conversion: no data loss, compiler allows it
int small = 100;
long big = small;   // safe -- int fits in long
double d = small;   // safe

// Explicit cast: potential data loss, must be deliberate
double precise = 9.99;
int truncated = (int)precise;  // 9 -- fractional part lost

// Safe parsing: TryParse avoids exceptions
string raw = "8443";
if (int.TryParse(raw, out int portNum))
    Console.WriteLine($"Valid port: {portNum}");
else
    Console.WriteLine("Invalid port number");

// as operator: returns null instead of throwing on failure
object obj = "some string";
string? asStr = obj as string;  // "some string"
int? asInt = obj as int?;        // null -- not an int

// is operator: type check with pattern variable
if (obj is string s && s.Length > 0)
    Console.WriteLine($"String of length {s.Length}");

Try It Yourself

Build a basic network target parser:

  1. Declare a nullable string? for a hostname and a nullable int? for a port
  2. Use ?? to assign defaults if either is null
  3. Use int.TryParse to safely convert a user-provided port string
  4. Print a formatted connection string: https://host:port

Try It Yourself

Explore the type system:

  1. Assign an int to a variable, then copy it to another variable and change the copy -- verify the original is unchanged
  2. Do the same with a List<int> and observe the difference
  3. Try casting 3.99 to int -- what do you get?
  4. Use typeof(int).FullName to print the underlying .NET type name

Key Takeaways

  • Value types are copied on assignment; reference types share the same object
  • Append ? to any type to make it nullable: int?, string?
  • ?? provides a fallback for null values; ?. short-circuits on null
  • var is inferred at compile time -- it is not dynamic
  • TryParse is the safe way to convert strings to numeric types
  • Use is and as for safe runtime type checks
