The error Interface

Go's error handling is explicit. There are no try/catch blocks -- errors are values returned like any other value. The error interface has one method: Error() string. Any type that implements it can be an error.

This design means error handling is part of your function's public API. You cannot silently swallow an error -- you must handle it or explicitly pass it up the call stack. For security software, this is exactly the right behavior.

errors.go
package main

import (
    "errors"
    "fmt"
)

// Sentinel errors -- pre-declared error values for comparison
var (
    ErrNotFound    = errors.New("target not found")
    ErrUnauthorized = errors.New("unauthorized")
    ErrTimeout     = errors.New("operation timed out")
)

// Custom error type with additional context
type ScanError struct {
    Host string
    Port int
    Err  error
}

func (e *ScanError) Error() string {
    return fmt.Sprintf("scan %s:%d failed: %v", e.Host, e.Port, e.Err)
}

// Unwrap allows errors.Is/As to traverse the chain
func (e *ScanError) Unwrap() error { return e.Err }

func scan(host string, port int) error {
    // Wrap a sentinel error with host/port context
    return &ScanError{Host: host, Port: port, Err: ErrTimeout}
}

func main() {
    err := scan("10.0.0.1", 443)
    if err != nil {
        fmt.Println(err)

        // errors.Is walks the error chain
        if errors.Is(err, ErrTimeout) {
            fmt.Println("retrying after timeout...")
        }

        // errors.As extracts the typed error
        var scanErr *ScanError
        if errors.As(err, &scanErr) {
            fmt.Printf("failed host: %s\n", scanErr.Host)
        }
    }
}

// scan 10.0.0.1:443 failed: operation timed out
// retrying after timeout...
// failed host: 10.0.0.1

Wrapping Errors with fmt.Errorf

Use fmt.Errorf with the %w verb to wrap an error with additional context while preserving the original for errors.Is and errors.As.

wrap.go
package main

import (
    "errors"
    "fmt"
)

var ErrConnRefused = errors.New("connection refused")

func connect(addr string) error {
    return ErrConnRefused
}

func authenticate(addr string) error {
    if err := connect(addr); err != nil {
        // %w wraps err -- preserves it for unwrapping
        return fmt.Errorf("authenticate to %s: %w", addr, err)
    }
    return nil
}

func login(addr string) error {
    if err := authenticate(addr); err != nil {
        return fmt.Errorf("login: %w", err)
    }
    return nil
}

func main() {
    err := login("10.0.0.1:22")
    fmt.Println(err)
    fmt.Println("is refused:", errors.Is(err, ErrConnRefused))
}

// login: authenticate to 10.0.0.1:22: connection refused
// is refused: true

Writing Tests

Go's testing package is built in. Test files end in _test.go and test functions start with Test. Run them with go test ./.... Table-driven tests are the idiomatic pattern -- one function, many cases.

scanner_test.go
package scanner

import (
    "errors"
    "testing"
)

// ValidatePort checks that a port number is in range
func ValidatePort(port int) error {
    if port < 1 || port > 65535 {
        return errors.New("port out of range")
    }
    return nil
}

// TestValidatePort is a table-driven test
func TestValidatePort(t *testing.T) {
    cases := []struct {
        name    string
        port    int
        wantErr bool
    }{
        {"valid low",   1,     false},
        {"valid mid",   443,   false},
        {"valid high",  65535, false},
        {"zero",        0,     true},
        {"negative",    -1,    true},
        {"too high",    65536, true},
    }

    for _, tc := range cases {
        t.Run(tc.name, func(t *testing.T) {
            err := ValidatePort(tc.port)
            if (err != nil) != tc.wantErr {
                t.Errorf("ValidatePort(%d) error=%v, wantErr=%v",
                    tc.port, err, tc.wantErr)
            }
        })
    }
}

Benchmarks

Benchmarks measure performance. They live in the same _test.go files. The b.N value is adjusted automatically by the testing framework to produce a stable measurement.

bench_test.go
package scanner

import (
    "testing"
)

// BenchmarkValidatePort measures ValidatePort performance
func BenchmarkValidatePort(b *testing.B) {
    for i := 0; i < b.N; i++ {
        ValidatePort(443)
    }
}

// Run: go test -bench=. -benchmem
// BenchmarkValidatePort-8    1000000000    0.29 ns/op    0 B/op    0 allocs/op
go test coverage

Run go test -cover ./... to see test coverage percentage. Use go test -coverprofile=c.out ./... && go tool cover -html=c.out to open a visual coverage report in your browser highlighting which lines are untested.

Try It Yourself

Write tests for a port classifier:

  1. Create classifier.go with a function ClassifyPort(port int) string that returns "privileged", "registered", or "ephemeral"
  2. Write a table-driven test with at least 8 cases covering edge values (0, 1, 1023, 1024, 49151, 49152, 65535, 65536)
  3. Run go test -v and verify all cases pass
  4. Add a benchmark and run go test -bench=. -benchmem

Key Takeaways

  • Errors are values -- Go rejects exceptions to keep control flow explicit and predictable
  • Implement Error() string and Unwrap() error on custom error types for rich error chains
  • Use fmt.Errorf("context: %w", err) to add context without losing the original error
  • Table-driven tests are the Go idiom -- one function covering many cases with minimal boilerplate
  • The race detector (go test -race) catches concurrency bugs that would otherwise hide until production
