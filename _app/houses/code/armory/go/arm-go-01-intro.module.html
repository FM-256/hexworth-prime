Why Go?

Go (formally "Go", colloquially "Golang") was created at Google in 2007 by Robert Griesemer, Rob Pike, and Ken Thompson -- three of the most decorated systems programmers alive. They were frustrated with the compile-time pain of C++, the runtime unpredictability of Java, and the slow execution of Python. Go was their answer.

The language shipped publicly in 2009 and has since powered some of the most critical infrastructure on the internet. Docker, Kubernetes, Terraform, Prometheus, Consul, etcd, CockroachDB -- all written in Go. When you understand Go, you understand the engine underneath the cloud-native world.

Fast Compilation Compiles in seconds, not minutes. The entire Go standard library compiles faster than most C++ headers parse.
Built-in Concurrency Goroutines and channels are language primitives. Writing concurrent code is idiomatic, not an afterthought.
Static Binaries Go compiles to a single statically-linked binary with no runtime dependencies. Deploy one file anywhere.
Garbage Collected No manual memory management. Low-latency GC with sub-millisecond pauses -- safe and fast enough for production.

Installing Go

Download the official installer from go.dev/dl. On Linux, the recommended method is extracting the tarball:

terminal -- linux/macos
$ wget https://go.dev/dl/go1.22.2.linux-amd64.tar.gz
$ sudo rm -rf /usr/local/go
$ sudo tar -C /usr/local -xzf go1.22.2.linux-amd64.tar.gz
$ echo 'export PATH=$PATH:/usr/local/go/bin' >> ~/.bashrc
$ source ~/.bashrc

Verify the installation:

terminal
$ go version
go version go1.22.2 linux/amd64

$ go env GOPATH
/home/operator/go

The GOPATH is your Go workspace root. The Go toolchain places downloaded packages and compiled binaries here. With modules (the modern approach), you rarely need to think about it.

Your First Go Program

Every Go program starts with a package declaration. The main package is the entry point for executables. Create a directory for your project and initialize a module:

terminal
$ mkdir hello && cd hello
$ go mod init hello
go: creating new go.mod file; module hello

Create main.go:

main.go
package main

import "fmt"

// main is the entry point for the executable
func main() {
    fmt.Println("Hello, World!")

    name := "Operator"
    year := 2026

    fmt.Printf("Welcome, %s. The year is %d.\n", name, year)
    fmt.Printf("In 5 years it will be %d.\n", year+5)
}
terminal
$ go run main.go
Hello, World!
Welcome, Operator. The year is 2026.
In 5 years it will be 2031.

go run vs go build

Go gives you two primary ways to execute code. go run compiles and runs in one step -- ideal for development. go build produces a deployable binary.

terminal
# Run directly (no binary on disk)
$ go run main.go

# Compile to binary named after the module
$ go build -o hello .
$ ./hello
Hello, World!

# Cross-compile for Linux from macOS/Windows
$ GOOS=linux GOARCH=amd64 go build -o hello-linux .

# Check binary size
$ ls -lh hello
-rwxr-xr-x 1 operator operator 1.8M hello

That 1.8MB binary contains the entire program and runtime -- no separate Go installation needed on the target machine. This is why Go is the default choice for CLI tools and container images.

Go Modules

Go modules (introduced in Go 1.11, mandatory since 1.16) are the dependency management system. The go.mod file declares your module name and Go version. Dependencies are tracked automatically.

go.mod
module hello

go 1.22
terminal -- adding a dependency
# Add a package (e.g., a CLI library)
$ go get github.com/spf13/cobra@latest

# Remove unused dependencies
$ go mod tidy

# List all dependencies
$ go list -m all

The go.sum file records cryptographic hashes of every dependency -- a supply-chain security mechanism that ensures the code you download is exactly what the module author published.

The Go Toolchain

Go ships a complete toolchain in one binary. There is no need for separate linters, formatters, or test runners.

terminal -- essential commands
# Format all code in the current module
$ go fmt ./...

# Run the linter (catches bugs, not just style)
$ go vet ./...

# Run all tests
$ go test ./...

# Show documentation for any package or function
$ go doc fmt.Printf

# Install a binary from a module
$ go install github.com/golangci/golangci-lint/cmd/golangci-lint@latest

Try It Yourself

Create a new directory, initialize a Go module, and write a program that:

  1. Declares your name and a skill you want to learn as variables
  2. Uses fmt.Printf to print them in a formatted sentence
  3. Prints the current Go version using runtime.Version() (import "runtime")
  4. Compiles it to a binary with go build and runs the binary directly

Try It Yourself

Explore the toolchain:

  1. Run go env and identify GOOS, GOARCH, and GOPATH
  2. Cross-compile your binary for a different OS using GOOS=windows go build -o hello.exe .
  3. Run go doc fmt and read the package overview
  4. Intentionally introduce a syntax error and observe the compiler output

Key Takeaways

  • Go was built by Google to solve large-scale software engineering problems -- speed, simplicity, concurrency
  • Every Go program belongs to a package; executables use package main with a main() function
  • go run compiles and runs in one step; go build produces a portable static binary
  • Go modules (go.mod) handle dependencies with cryptographic verification via go.sum
  • The toolchain is batteries-included: fmt, vet, test, doc, and build are all built in
