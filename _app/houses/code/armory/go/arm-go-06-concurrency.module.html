Concurrency

< Go Track

Learning Objectives

  • Launch goroutines and understand their relationship to OS threads
  • Communicate between goroutines safely using channels
  • Use WaitGroup to synchronize a pool of goroutines
  • Limit concurrency with buffered channels as semaphores
  • Cancel goroutines cleanly with context.Context

Goroutines

A goroutine is a lightweight thread managed by the Go runtime. Creating 10,000 goroutines uses roughly 80MB of memory; the equivalent OS threads would require gigabytes. This is why Go can handle hundreds of concurrent network connections in a single binary.

goroutines.go
package main

import (
    "fmt"
    "sync"
)

func probe(host string, port int, wg *sync.WaitGroup) {
    defer wg.Done() // signal WaitGroup when this goroutine exits
    // In a real scanner, you would attempt a TCP dial here
    fmt.Printf("probing %s:%d\n", host, port)
}

func main() {
    ports := []int{22, 80, 443, 8080, 8443}
    host  := "192.168.1.1"

    var wg sync.WaitGroup

    for _, port := range ports {
        wg.Add(1)
        // go keyword launches a goroutine -- non-blocking
        go probe(host, port, &wg)
    }

    wg.Wait() // block until all goroutines call Done()
    fmt.Println("all probes complete")
}
Race conditions are silent killers

Run your programs with go run -race main.go during development. The built-in race detector catches concurrent writes to shared memory that would otherwise cause intermittent, hard-to-reproduce bugs in production.

Channels

Channels are typed conduits for passing data between goroutines. Go's philosophy: "Do not communicate by sharing memory; share memory by communicating." Channels let you send results from worker goroutines back to a collector without locks.

channels.go
package main

import (
    "fmt"
    "net"
    "time"
)

type ScanResult struct {
    Port  int
    Open  bool
}

// scanPort tries a TCP connection and sends result to channel
func scanPort(host string, port int, results chan<- ScanResult) {
    addr := fmt.Sprintf("%s:%d", host, port)
    conn, err := net.DialTimeout("tcp", addr, 2*time.Second)
    if err != nil {
        results <- ScanResult{Port: port, Open: false}
        return
    }
    conn.Close()
    results <- ScanResult{Port: port, Open: true}
}

func main() {
    ports := []int{22, 80, 443, 8080}
    host  := "scanme.nmap.org"

    // Buffered channel holds all results without blocking senders
    results := make(chan ScanResult, len(ports))

    for _, port := range ports {
        go scanPort(host, port, results)
    }

    // Collect exactly len(ports) results
    for i := 0; i < len(ports); i++ {
        r := <-results
        if r.Open {
            fmt.Printf("port %d: OPEN\n", r.Port)
        }
    }
}

Semaphore Pattern -- Limiting Concurrency

Launching one goroutine per port works for a small range, but scanning 65,535 ports simultaneously would exhaust file descriptors. A buffered channel used as a semaphore limits concurrent goroutines to a safe maximum.

semaphore.go
package main

import (
    "fmt"
    "sync"
)

func concurrentScan(host string, ports []int, maxConcurrent int) {
    // sem acts as a semaphore: send to acquire, receive to release
    sem := make(chan struct{}, maxConcurrent)
    var wg sync.WaitGroup

    for _, port := range ports {
        wg.Add(1)
        go func(p int) {
            defer wg.Done()
            sem <- struct{}{}  // acquire slot
            defer func() { <-sem }() // release slot when done

            // actual scan work here
            fmt.Printf("scanning %s:%d\n", host, p)
        }(port)
    }

    wg.Wait()
}

func main() {
    ports := make([]int, 100)
    for i := range ports { ports[i] = i + 1 }

    // Scan 100 ports but only 10 concurrent connections
    concurrentScan("10.0.0.1", ports, 10)
}

select and context.Context

select lets a goroutine wait on multiple channel operations simultaneously -- whichever is ready first executes. Combined with context.Context, this is the idiomatic way to implement timeouts and cancellation.

context.go
package main

import (
    "context"
    "fmt"
    "time"
)

// longScan simulates a slow operation, respects cancellation
func longScan(ctx context.Context, host string) error {
    done := make(chan struct{})

    go func() {
        // Simulate 5-second scan
        time.Sleep(5 * time.Second)
        close(done)
    }()

    select {
    case <-done:
        fmt.Printf("scan of %s complete\n", host)
        return nil
    case <-ctx.Done():
        // context cancelled or timed out
        return ctx.Err()
    }
}

func main() {
    // Cancel the scan after 2 seconds
    ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
    defer cancel() // always call cancel to release resources

    err := longScan(ctx, "10.0.0.1")
    if err != nil {
        fmt.Printf("scan aborted: %v\n", err)
    }
}

// scan aborted: context deadline exceeded
Always call cancel()

Every context created with WithTimeout, WithDeadline, or WithCancel must have its cancel function called -- even if the context expires naturally. Uncalled cancels leak the goroutine that monitors the deadline timer. Use defer cancel() immediately after creating the context.

sync.Mutex for Shared State

When goroutines must share mutable state (like a results map), protect it with a mutex. The pattern is always: lock, modify, unlock -- with unlock deferred to prevent leaks on early returns.

mutex.go
package main

import (
    "fmt"
    "sync"
)

type ScanDB struct {
    mu      sync.RWMutex
    results map[string][]int
}

func (db *ScanDB) AddResult(host string, port int) {
    db.mu.Lock()
    defer db.mu.Unlock()
    db.results[host] = append(db.results[host], port)
}

func (db *ScanDB) GetPorts(host string) []int {
    db.mu.RLock() // read lock allows concurrent readers
    defer db.mu.RUnlock()
    return db.results[host]
}

func main() {
    db := &ScanDB{results: make(map[string][]int)}
    var wg sync.WaitGroup

    hosts := []string{"10.0.0.1", "10.0.0.2", "10.0.0.1"}
    ports := []int{22, 443, 80}

    for i := range hosts {
        wg.Add(1)
        go func(h string, p int) {
            defer wg.Done()
            db.AddResult(h, p)
        }(hosts[i], ports[i])
    }

    wg.Wait()
    fmt.Printf("10.0.0.1 ports: %v\n", db.GetPorts("10.0.0.1"))
}

Key Takeaways

  • Goroutines are cheap -- thousands are normal; use them freely for I/O-bound work
  • Channels are the preferred communication mechanism between goroutines -- avoid shared memory
  • Use sync.WaitGroup to wait for a group of goroutines to finish
  • Buffered channels as semaphores limit concurrency -- critical for responsible scanning tools
  • context.Context propagates cancellation and timeouts through your call stack -- always defer cancel()
