Variable Types in Ruby

Ruby uses naming conventions (sigils) to communicate variable scope at a glance. This is intentional -- Matz wanted the variable's scope to be readable without context.

variable scopes
local_variable  = "no prefix -- local to current scope"
@instance_var   = "belongs to an object instance"
@@class_var     = "shared across all instances of a class"
$global_var     = "accessible everywhere -- use sparingly"
CONSTANT        = "uppercase -- conventionally immutable"

In practice you will use local variables most of the time. Instance variables (@name) appear inside class methods. You will see both constantly when reading Metasploit module source code.

Core Data Types

String Sequences of characters. Double-quoted strings support interpolation. "hello #{name}"
'literal string'
Integer / Float Whole numbers and decimals. No size limit on integers in Ruby. port = 443
score = 9.8
Symbol Immutable, interned identifiers. Faster than strings for keys and labels. :http
:exploit_type
nil Ruby's null value. An object of class NilClass, not a special keyword. result = nil
nil.class # NilClass
irb -- types in action
# Strings
target_ip = "192.168.1.100"
service   = 'ssh'
puts "Scanning #{service} on #{target_ip}"

# Integers and Floats
port     = 22
cvss     = 9.8
puts port.class   # Integer
puts cvss.class   # Float

# Symbols -- note the colon prefix
status = :open
proto  = :tcp
puts status       # open
puts status.class # Symbol

# Booleans and nil
found   = true
blocked = false
result  = nil
puts result.nil?  # true

Symbols vs Strings

This distinction trips up newcomers. A Symbol is an immutable, unique identifier stored once in memory. The string "exploit" and "exploit" are two separate objects in memory. The symbol :exploit is always the exact same object. This makes symbols ideal for hash keys and state labels.

irb -- symbol identity
irb> "exploit".object_id == "exploit".object_id
=> false   # two different string objects

irb> :exploit.object_id == :exploit.object_id
=> true    # same object every time

# Symbols as hash keys (common Metasploit pattern)
module_info = {
  :name        => "EternalBlue",
  :platform    => "Windows",
  :arch        => "x86_64"
}

# Modern Ruby shorthand for symbol keys
module_info = { name: "EternalBlue", platform: "Windows" }

Type Conversion

Ruby will not automatically coerce types between Strings and Integers (unlike JavaScript). You must convert explicitly. This prevents a whole class of bugs common in loosely-typed languages.

type conversion methods
# String to Integer
port_str = "443"
port_int = port_str.to_i
puts port_int + 1  # 444

# Integer to String
count = 32
msg   = "Found " + count.to_s + " hosts"
puts msg  # Found 32 hosts

# Float conversion
puts "9.8".to_f      # 9.8
puts 9.to_f          # 9.0

# String to Symbol and back
puts "tcp".to_sym     # tcp (Symbol)
puts :tcp.to_s       # "tcp" (String)

# Safe integer parsing -- returns nil on failure
puts Integer("443")   # 443
puts Integer("abc") rescue "invalid"  # invalid

String Methods

Ruby's String class is packed with useful methods. You will use these constantly when parsing output from network tools, log files, and exploit responses.

useful string methods
banner = "  Apache/2.4.51 (Ubuntu)  "

puts banner.strip          # removes whitespace
puts banner.downcase       # apache/2.4.51 (ubuntu)
puts banner.include?("Apache")  # true
puts banner.split("/")    # ["  Apache", "2.4.51 (Ubuntu)  "]
puts banner.gsub("Apache", "NGINX")  # replace

# Multi-line strings with heredoc
payload = <<~PAYLOAD
  GET / HTTP/1.1
  Host: target.local
  User-Agent: CustomScanner/1.0
PAYLOAD
puts payload

Key Takeaways

  • Variable sigils (@, @@, $) communicate scope visually
  • Symbols are immutable, interned identifiers -- prefer them over strings for hash keys
  • nil is an object of class NilClass -- use .nil? to check for it
  • Ruby does not auto-coerce types -- use .to_i, .to_s, .to_f, .to_sym
  • Metasploit module info hashes use symbol keys -- you will see name: shorthand everywhere
