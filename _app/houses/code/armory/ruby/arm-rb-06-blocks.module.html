Blocks, Procs & Lambdas

< Ruby Track

Learning Objectives

  • Understand blocks as anonymous code chunks passed to methods
  • Use yield to invoke a block from inside a method
  • Create reusable callable objects with Proc.new and lambda
  • Understand the differences between procs and lambdas (return behavior, arity)

Blocks

A block is a chunk of code you pass to a method -- it is not an object, just syntax. You have already used blocks in every .each and .map call. Blocks use either curly braces for single-line or do...end for multi-line bodies.

blocks in practice
# Single-line block with braces
[22, 80, 443].each { |port| puts "Checking port #{port}" }

# Multi-line block with do/end
["host1", "host2", "host3"].each do |host|
  puts "Connecting to #{host}"
  puts "  ...done"
end

# Blocks with multiple parameters
{ ssh: 22, http: 80, https: 443 }.each do |service, port|
  puts "#{service.upcase} runs on port #{port}"
end

yield -- Calling a Block from a Method

Any method can accept an implicit block. Use yield inside the method body to invoke it. This is how Ruby builds DSL-style APIs -- the pattern used by Rails routes, RSpec tests, and Metasploit's register_options.

yield
def with_timeout(seconds)
  puts "Starting (timeout: #{seconds}s)"
  start = Time.now
  result = yield   # invoke the caller's block
  elapsed = Time.now - start
  puts "Done in #{elapsed.round(3)}s"
  result
end

with_timeout(5) do
  # simulate work
  puts "Scanning target..."
end

# Check if a block was given before yielding
def optional_block
  if block_given?
    puts "Block provided"
    yield
  else
    puts "No block given"
  end
end

Procs and Lambdas

Procs and lambdas are first-class objects -- you can store them in variables, pass them as arguments, and call them later. The key differences concern argument handling and the behavior of return.

Block

Anonymous code chunk. Not an object. Cannot be stored. Passed implicitly to any method.

Proc

An object wrapper for a block. Lenient on argument count. return exits the enclosing method.

Lambda

Strict proc. Enforces argument count. return exits only the lambda, not the calling method.

procs and lambdas
# Proc.new
formatter = Proc.new { |ip, port| "#{ip}:#{port}" }
puts formatter.call("192.168.1.1", 80)  # 192.168.1.1:80
puts formatter.call("10.0.0.1")         # 10.0.0.1:  (nil for missing arg)

# Lambda -- strict argument checking
validator = lambda { |ip| ip.match?(/^\d{1,3}(\.\d{1,3}){3}$/) }
puts validator.call("192.168.1.1")  # true
puts validator.call("not-an-ip")    # false

# Lambda shorthand (stabby lambda) -- modern Ruby
encode = ->(str) { str.bytes.map { |b| b.to_s(16) }.join(" ") }
puts encode.call("GET")  # 47 45 54

# Passing procs/lambdas as arguments
filters = [
  ->(p) { p < 1024 },
  ->(p) { [22, 80, 443].include?(p) }
]
ports = [21, 22, 80, 3000, 443]
filters.each do |f|
  puts ports.select(&f).inspect
end

The & Operator

The & prefix converts a Proc or method reference into a block. The &:method_name shorthand converts a symbol to a proc that calls that method. You will see this everywhere in Ruby codebases.

ampersand operator
services = ["  ssh  ", "  http  ", "  ftp  "]

# Symbol-to-proc shorthand
puts services.map(&:strip)    # ["ssh", "http", "ftp"]
puts services.map(&:upcase)   # ["  SSH  ", "  HTTP  ", "  FTP  "]

# Method reference with method()
def privileged?(port)
  port < 1024
end

ports = [21, 22, 3000, 8080]
puts ports.select(&method(:privileged?)).inspect
# [21, 22]

Try It Yourself

Write a method called retry_on_fail that accepts a max attempts count and a block. It should call the block up to N times, stopping if it returns a truthy value or printing "All attempts failed" after exhausting retries. Test it with a lambda that randomly returns true or false.

Key Takeaways

  • Blocks are anonymous code chunks -- not objects -- passed to methods implicitly
  • Use yield inside a method to call the caller's block; guard with block_given?
  • Procs are lenient about argument counts; lambdas are strict
  • return inside a Proc exits the enclosing method; inside a lambda it exits only the lambda
  • Stabby lambda ->(x) { ... } is the preferred modern syntax
  • &:method_name is the most common Ruby shorthand -- know it cold
