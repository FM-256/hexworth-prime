Gem Management with Bundler

Gems are Ruby libraries. RubyGems is the package manager; Bundler is the dependency resolver. Every serious Ruby project has a Gemfile that declares exact dependencies, and a Gemfile.lock that pins exact versions.

terminal -- gem commands
# Install a gem globally
$ gem install sinatra

# Install Bundler
$ gem install bundler

# Create a Gemfile in your project
$ bundle init

# Install all Gemfile dependencies
$ bundle install

# Run a script using bundled gems
$ bundle exec ruby app.rb

# Show installed gems
$ gem list
Gemfile
# Gemfile -- project dependency declaration
source "https://rubygems.org"

ruby "3.3.0"

gem "sinatra", "~> 4.0"
gem "json"

group :development, :test do
  gem "rspec",   "~> 3.13"
  gem "rack-test"
end

Sinatra -- Minimal Web Apps

Sinatra is a lightweight DSL for building web applications in Ruby. A complete working web app fits in one file. It is the right choice for security tools, internal dashboards, API endpoints, and CTF challenge servers.

app.rb -- sinatra application
require 'sinatra'
require 'json'

# In-memory store (use a database in production)
HOSTS = []

# GET route -- render HTML or return JSON
get '/' do
  content_type :json
  { status: "ok", hosts: HOSTS.length }.to_json
end

# GET with URL parameter
get '/host/:ip' do
  ip = params[:ip]
  host = HOSTS.find { |h| h[:ip] == ip }
  halt 404, { error: "Not found" }.to_json unless host
  content_type :json
  host.to_json
end

# POST -- parse JSON body
post '/host' do
  content_type :json
  data = JSON.parse(request.body.read, symbolize_names: true)
  HOSTS << data
  status 201
  { message: "Added", ip: data[:ip] }.to_json
end

# Error handler
error 404 do
  content_type :json
  { error: "Not found" }.to_json
end

Rails -- Convention Over Configuration

Rails is a full-stack MVC framework that powers production applications at scale. It follows strict naming conventions so you write less code. Understanding its structure is important even if you use Sinatra -- Rails is everywhere in job interviews and production codebases.

terminal -- create and run a rails app
$ gem install rails
$ rails new vuln_tracker --api
$ cd vuln_tracker
$ rails generate model Vulnerability cve:string cvss:float service:string
$ rails db:migrate
$ rails server
app/models/ ActiveRecord classes. Each file maps to a database table. Business logic lives here.
app/controllers/ Handle HTTP requests. Connect models to views. Each action maps to a route.
app/views/ ERB templates rendered by controllers. Not used in --api mode.
config/routes.rb URL routing rules. resources :vulnerabilities generates 7 RESTful routes.

RSpec -- Testing

RSpec is the standard testing framework for Ruby. Its describe/context/it DSL reads like a specification document. Metasploit modules have spec files under spec/. Writing tests for your own security tools proves they behave as expected under edge cases.

spec/scanner_spec.rb
require 'rspec'
require_relative '../lib/scanner'

# Top-level group describes the subject
describe Scanner do
  # let creates a lazily-evaluated helper
  let(:scanner) { Scanner.new("192.168.1.1") }

  describe '#initialize' do
    it 'stores the target IP' do
      expect(scanner.target).to eq("192.168.1.1")
    end

    it 'starts with empty results' do
      expect(scanner.results).to be_empty
    end
  end

  describe '#privileged_ports' do
    before { scanner.instance_variable_set(:@results, [22, 80, 3000, 8080]) }

    it 'returns only ports below 1024' do
      expect(scanner.privileged_ports).to contain_exactly(22, 80)
    end

    it 'returns an array' do
      expect(scanner.privileged_ports).to be_an(Array)
    end
  end
end

Consuming APIs with net/http

The standard library's net/http handles HTTP requests without any gems. Combine with JSON parsing for API consumption in standalone scripts.

nvd api query (cve lookup)
require 'net/http'
require 'json'
require 'uri'

def lookup_cve(cve_id)
  uri = URI("https://services.nvd.nist.gov/rest/json/cves/2.0?cveId=#{cve_id}")
  response = Net::HTTP.get_response(uri)
  return nil unless response.is_a?(Net::HTTPSuccess)
  data = JSON.parse(response.body)
  vuln = data.dig("vulnerabilities", 0, "cve")
  return nil unless vuln
  {
    id:          vuln["id"],
    description: vuln.dig("descriptions", 0, "value"),
    cvss:        vuln.dig("metrics", "cvssMetricV31", 0, "cvssData", "baseScore")
  }
end

result = lookup_cve("CVE-2021-44228")
if result
  puts "#{result[:id]} -- CVSS: #{result[:cvss]}"
  puts result[:description]
end

Try It Yourself

Build a Sinatra-based vulnerability tracker API:

  1. Create a GET /vulns route that returns all stored vulnerabilities as JSON
  2. Create a POST /vulns route that accepts a JSON body with cve_id and cvss_score
  3. Create a GET /vulns/critical route that returns only vulns with cvss_score >= 9.0
  4. Write two RSpec tests using rack-test to verify your GET routes return the correct HTTP status
