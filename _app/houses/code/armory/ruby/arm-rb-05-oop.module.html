Defining Classes

Every Metasploit module is a class. When you write class MetasploitModule < Msf::Exploit::Remote you are defining a Ruby class that inherits from the framework's base exploit class. This is the same OOP you use anywhere in Ruby.

basic class
class Host
  # attr_accessor generates getter and setter methods
  attr_accessor :ip, :hostname, :os
  attr_reader   :ports   # read-only

  # initialize is the constructor
  def initialize(ip, hostname = "unknown")
    @ip       = ip
    @hostname = hostname
    @os       = nil
    @ports    = []
  end

  def add_port(port)
    @ports << port unless @ports.include?(port)
  end

  def vulnerable?
    @ports.include?(445) && @os&.include?("Windows")
  end

  # to_s is called when the object is interpolated
  def to_s
    "#{@hostname} (#{@ip}) -- #{@ports.length} ports open"
  end
end

# Usage
h = Host.new("192.168.1.50", "WORKSTATION-01")
h.os = "Windows 10"
h.add_port(80)
h.add_port(445)

puts h
puts h.vulnerable?  # true

Inheritance

Ruby uses single inheritance. A class can only have one parent, but multiple modules can be mixed in. This is the exact pattern Metasploit uses -- Msf::Exploit::Remote inherits from Msf::Exploit, which inherits from Msf::Module.

inheritance
class Scanner
  attr_reader :target, :results

  def initialize(target)
    @target  = target
    @results = []
  end

  def run
    puts "Running base scanner on #{@target}"
  end
end

class PortScanner < Scanner
  def initialize(target, port_range)
    super(target)          # call parent initialize
    @port_range = port_range
  end

  def run
    super                  # call parent run first
    @port_range.each do |port|
      # simulate scan
      @results << port if [22, 80, 443].include?(port)
    end
    puts "Open ports: #{@results.join(', ')}"
  end
end

scanner = PortScanner.new("192.168.1.1", 1..1024)
scanner.run

Modules and Mixins

Modules serve two purposes: namespacing and mixins. When you include a module in a class, its methods become instance methods. This is how Ruby achieves multiple inheritance behavior. Metasploit's Msf::Exploit::Remote is itself a module mixin providing TCP connection helpers.

modules and mixins
# Module as a mixin -- defines shared behavior
module Loggable
  def log(msg, level = :info)
    timestamp = Time.now.strftime("%H:%M:%S")
    prefix = case level
             when :info  then "[*]"
             when :warn  then "[!]"
             when :error then "[-]"
             else "[?]"
             end
    puts "#{timestamp} #{prefix} #{msg}"
  end
end

module Reportable
  def report
    puts "=== Report for #{self.class} ==="
  end
end

# Include both modules
class Exploit
  include Loggable
  include Reportable

  def run
    log("Starting exploit", :info)
    log("Target unreachable", :warn)
    report
  end
end

Exploit.new.run

Key Takeaways

  • attr_accessor :name generates both getter and setter -- saves repetitive code
  • initialize is the constructor -- called when you call ClassName.new
  • Use super in child class methods to call the parent's version
  • Modules as mixins let one class gain behavior from multiple sources
  • Metasploit modules are classes -- everything you learn here applies directly
  • The safe navigation operator &. (lonely operator) prevents nil errors on method chains
