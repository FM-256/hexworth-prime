File I/O & Error Handling

< Ruby Track

Learning Objectives

  • Read and write files with File.open and the block form

  • Handle errors with begin/rescue/ensure and retry
  • Define custom exception classes for precise error handling

Reading Files

Reading a target list, parsing a configuration file, or loading a wordlist -- file I/O is a core skill for any security script. The block form of File.open automatically closes the file even if an error occurs.

reading files
# Read entire file as a string
content = File.read("targets.txt")
puts content

# Read into array of lines (strips newlines)
targets = File.readlines("targets.txt", chomp: true)
targets.each { |ip| puts "Scanning #{ip}" }

# Block form -- file closes automatically
File.open("wordlist.txt", "r") do |f|
  f.each_line do |line|
    word = line.chomp
    puts "Trying: #{word}"
  end
end   # file is closed here regardless of errors

# Check existence before reading
path = "config.json"
if File.exist?(path)
  content = File.read(path)
else
  puts "Config file not found"
end

Writing Files

writing files
# Write (overwrites) with File.write
results = ["192.168.1.1 - open: 80, 443", "192.168.1.2 - open: 22"]
File.write("scan_results.txt", results.join("\n"))

# Append mode
File.open("scan_log.txt", "a") do |f|
  f.puts "[#{Time.now}] Scan complete"
end

# Write multiple lines
File.open("report.txt", "w") do |f|
  f.puts "=== Scan Report ==="
  results.each { |line| f.puts line }
  f.puts "=== End Report ==="
end

CSV and JSON

csv and json parsing
require 'csv'
require 'json'

# Read CSV
CSV.foreach("hosts.csv", headers: true) do |row|
  puts "#{row['ip']} -- #{row['hostname']}"
end

# Write CSV
CSV.open("results.csv", "w") do |csv|
  csv << ["ip", "port", "state", "service"]
  csv << ["192.168.1.1", 443, "open", "https"]
end

# Parse JSON
raw = File.read("vulns.json")
data = JSON.parse(raw)
data["vulnerabilities"].each { |v| puts v["cve"] }

# Generate JSON
report = { scan_time: Time.now.to_s, hosts: 42, open_ports: [22, 80, 443] }
File.write("report.json", JSON.pretty_generate(report))

begin / rescue / ensure

Ruby's error handling uses begin/rescue/ensure/end. The ensure block runs no matter what -- perfect for cleanup like closing connections. Multiple rescue clauses catch different exception types.

error handling
begin
  content = File.read("missing_file.txt")
  data = JSON.parse(content)
rescue Errno::ENOENT => e
  puts "File not found: #{e.message}"
rescue JSON::ParserError => e
  puts "Invalid JSON: #{e.message}"
rescue => e
  # catch-all for any other StandardError
  puts "Unexpected error: #{e.class} -- #{e.message}"
ensure
  puts "Cleanup complete"  # always runs
end

# Custom exception classes
class ConnectionTimeout < StandardError
  def initialize(host, timeout)
    super("Connection to #{host} timed out after #{timeout}s")
  end
end

# Retry on transient failures
attempts = 0
begin
  attempts += 1
  raise ConnectionTimeout.new("10.0.0.1", 5) if attempts < 3
  puts "Connected on attempt #{attempts}"
rescue ConnectionTimeout => e
  puts "Retrying: #{e.message}"
  retry if attempts < 3
end

Try It Yourself

Write a script that reads a list of IP addresses from a text file (one per line), builds an array of hashes with ip and a simulated status ("up" or "down" randomly), then writes the results to a JSON file. Wrap the file reading in a rescue block that handles a missing file gracefully.

Key Takeaways

  • Always use the block form of File.open -- it guarantees the file is closed
  • File.readlines(path, chomp: true) is the cleanest way to read a target list
  • Rescue specific exception classes first, then a catch-all rescue => e
  • ensure always runs -- use it for connection teardown and cleanup
  • retry re-runs the begin block -- combine with a counter to avoid infinite loops
  • Custom exceptions improve readability: class MyError < StandardError; end
