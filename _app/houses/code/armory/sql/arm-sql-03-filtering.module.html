Logical Operators: AND, OR, NOT

Combine multiple conditions to build precise filters. AND requires all conditions to be true. OR requires at least one. NOT negates a condition.

SELECT * FROM users WHERE role = 'user' AND active = 1;
Find active users with the 'user' role. Both conditions must match.
SELECT * FROM users WHERE role = 'user' AND active = 1;
sql> SELECT * FROM users WHERE role = 'user' AND active = 1;
2|jsmith|john.smith@corp.com|user|1
SELECT * FROM users WHERE role = 'admin' OR role = 'analyst';
Find users who are either admins or analysts.
SELECT * FROM users WHERE role = 'admin' OR role = 'analyst';
sql> SELECT * FROM users WHERE role = 'admin' OR role = 'analyst';
1|admin|admin@hexworth.io|admin|1
3|analyst1|sec.analyst@corp.com|analyst|1
SELECT * FROM users WHERE NOT active = 1;
Find all inactive (disabled) accounts. NOT inverts the condition.
SELECT * FROM users WHERE NOT active = 1;

Operator precedence: NOT is evaluated first, then AND, then OR. Use parentheses to make your intent clear:

Parentheses for Clarity
SELECT * FROM login_logs
WHERE (status = 'FAILED' OR status = 'BLOCKED')
AND ip_address = '192.168.1.99';

IN -- Matching Value Lists

IN checks if a value matches any item in a list. It is a cleaner alternative to chaining multiple OR conditions.

SELECT * FROM users WHERE role IN ('admin', 'analyst');
Find users whose role is either admin or analyst. Equivalent to role = 'admin' OR role = 'analyst'.
SELECT * FROM users WHERE role IN ('admin', 'analyst');
sql> SELECT * FROM users WHERE role IN ('admin', 'analyst');
1|admin|admin@hexworth.io|admin|1
3|analyst1|sec.analyst@corp.com|analyst|1

Use NOT IN to exclude values: WHERE role NOT IN ('user', 'guest')

BETWEEN -- Range Filtering

BETWEEN filters values within a range, inclusive of both endpoints. Works with numbers, dates, and text.

SELECT * FROM login_logs WHERE timestamp BETWEEN '2026-03-14' AND '2026-03-15';
Find all login events within a 24-hour window. Critical for incident timeline reconstruction.
SELECT * FROM login_logs WHERE timestamp BETWEEN '2026-03-14' AND '2026-03-15';
sql> SELECT * FROM login_logs WHERE timestamp BETWEEN '2026-03-14' AND '2026-03-15';
2026-03-14 17:00:00|jsmith|SUCCESS|10.0.0.50
2026-03-15 09:30:00|admin|SUCCESS|10.0.0.1
2026-03-15 11:45:00|hacker|FAILED|192.168.1.99
SELECT * FROM users WHERE user_id BETWEEN 2 AND 4;
Find users with IDs from 2 to 4 inclusive.
SELECT * FROM users WHERE user_id BETWEEN 2 AND 4;

LIKE -- Pattern Matching

LIKE performs pattern matching on text columns using two wildcards:

WildcardMeaningExample
%Zero or more characters'%admin%' matches "admin", "sysadmin", "admin_backup"
_Exactly one character'user_' matches "user1", "userA" but not "user" or "user12"
SELECT * FROM users WHERE email LIKE '%@corp.com';
Find all users with corporate email addresses.
SELECT * FROM users WHERE email LIKE '%@corp.com';
sql> SELECT * FROM users WHERE email LIKE '%@corp.com';
2|jsmith|john.smith@corp.com|user|1
3|analyst1|sec.analyst@corp.com|analyst|1
SELECT * FROM users WHERE username LIKE 'a%';
Find all usernames starting with the letter 'a'.
SELECT * FROM users WHERE username LIKE 'a%';
Security Note

Attackers use LIKE with wildcards during SQL injection to enumerate database contents. For example: admin' OR username LIKE '%' -- can reveal all usernames if the input is not sanitized.

IS NULL / IS NOT NULL

NULL represents missing or unknown data. You cannot use = to check for NULL -- you must use IS NULL or IS NOT NULL.

SELECT * FROM users WHERE last_login IS NULL;
Find users who have never logged in. These could be dormant accounts -- a security risk.
SELECT * FROM users WHERE last_login IS NULL;
sql> SELECT * FROM users WHERE last_login IS NULL;
4|hacker|pwned@evil.com|user|0
Common Mistake
-- WRONG: This will never match anything
SELECT * FROM users WHERE last_login = NULL;

-- CORRECT: Use IS NULL
SELECT * FROM users WHERE last_login IS NULL;

This is because NULL is not a value -- it is the absence of a value. Any comparison with NULL using = returns NULL (neither true nor false), so no rows match.

Combining Everything

Real-world queries combine multiple operators. Here is a forensic query that finds suspicious login activity:

Incident Response Query
SELECT username, ip_address, status, timestamp
FROM login_logs
WHERE status = 'FAILED'
AND timestamp BETWEEN '2026-03-15 00:00:00' AND '2026-03-15 23:59:59'
AND ip_address NOT IN ('10.0.0.1', '10.0.0.50')
ORDER BY timestamp DESC;

This query finds all failed logins today from non-internal IP addresses, sorted newest first. This is exactly the kind of query you would run during an active investigation.

Key Takeaways

  • AND requires all conditions true; OR requires at least one; NOT negates
  • IN ('a', 'b', 'c') is cleaner than chaining OR conditions
  • BETWEEN filters inclusive ranges -- works for numbers, dates, and text
  • LIKE with % (any characters) and _ (single character) for pattern matching
  • Always use IS NULL / IS NOT NULL -- never = NULL
  • Use parentheses to control operator precedence in complex conditions
