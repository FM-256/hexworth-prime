CREATE TABLE

CREATE TABLE defines a new table with named columns and data types. This is the foundation of database architecture.

Create a Security Audit Log Table
CREATE TABLE audit_log (
  log_id INTEGER PRIMARY KEY AUTOINCREMENT,
  timestamp DATETIME NOT NULL DEFAULT (datetime('now')),
  user_id INTEGER NOT NULL,
  action TEXT NOT NULL,
  target_table TEXT,
  ip_address TEXT,
  FOREIGN KEY (user_id) REFERENCES users(user_id)
);

Constraints

Constraints enforce rules on your data, preventing invalid entries at the database level. They are your last line of defense against bad data.

PRIMARY KEY Uniquely identifies each row. Auto-increment generates IDs automatically.
FOREIGN KEY References a primary key in another table. Enforces referential integrity.
NOT NULL Column cannot contain NULL. Every row must have a value.
UNIQUE No two rows can have the same value in this column (e.g., email, username).
CHECK Custom validation rule. e.g., CHECK(age >= 0) prevents negative ages.
DEFAULT Provides a fallback value when none is specified during INSERT.

Indexes

An index speeds up queries by creating a sorted lookup structure -- like an index in a book. Without indexes, the database scans every row (full table scan).

CREATE INDEX idx_login_user ON login_logs(user_id);
Create an index on user_id. Queries filtering by user_id will be dramatically faster.
CREATE INDEX idx_login_user ON login_logs(user_id);
CREATE INDEX idx_login_status_time ON login_logs(status, timestamp);
Composite index on two columns. Optimizes queries that filter by both status and time.
CREATE INDEX idx_login_status_time ON login_logs(status, timestamp);

Trade-off: Indexes speed up reads but slow down writes (INSERT/UPDATE/DELETE), because the index must be updated. Index strategically -- focus on columns used in WHERE, JOIN, and ORDER BY.

Normalization

Normalization is the process of organizing tables to reduce redundancy and prevent anomalies. There are three main normal forms:

1NF -- First Normal Form Each column holds atomic (indivisible) values. No repeating groups. Each row is unique.
2NF -- Second Normal Form Meets 1NF + every non-key column depends on the entire primary key (no partial dependencies).
3NF -- Third Normal Form Meets 2NF + no transitive dependencies. Non-key columns depend only on the primary key.
Denormalization Sometimes you intentionally break normalization for read performance. Common in analytics/reporting databases.

Security impact: Poor normalization leads to data inconsistencies. If a user's role is stored in multiple tables without foreign keys, changing it in one place creates privilege confusion -- a real attack vector.

ALTER TABLE and DROP

Modify existing table structures with ALTER TABLE. Destroy tables with DROP TABLE.

ALTER TABLE users ADD COLUMN mfa_enabled INTEGER DEFAULT 0;
Add a multi-factor authentication flag to the users table.
ALTER TABLE users ADD COLUMN mfa_enabled INTEGER DEFAULT 0;
Other ALTER Operations
-- Rename a table
ALTER TABLE old_name RENAME TO new_name;

-- Drop a table entirely (DANGER)
DROP TABLE IF EXISTS temp_data;

Entity-Relationship Diagrams

An ERD visually maps tables, their columns, and relationships. Before writing CREATE TABLE, design your ERD to ensure proper structure.

Security Database ERD (Text Representation)
[users] 1---* [login_logs]
  user_id PK      log_id PK
  username        user_id FK
  email           timestamp
  role            status
  active          ip_address

[users] 1---* [permissions]
                  perm_id PK
                  user_id FK
                  permission
                  granted_by

The 1---* notation means "one-to-many." One user can have many login logs and many permissions.

Key Takeaways

  • CREATE TABLE defines structure; choose appropriate data types
  • Constraints (PK, FK, NOT NULL, UNIQUE, CHECK) enforce data integrity at the database level
  • Indexes speed up reads but slow down writes -- index strategically
  • Normalization (1NF/2NF/3NF) reduces redundancy and prevents data anomalies
  • Design ERDs before writing SQL -- plan the structure, then build it
