Scenario: Active Breach Investigation

You are the incident responder. Your SOC has detected suspicious activity from IP 192.168.1.99. The CISO needs answers: What happened? When? What data was affected? Your tool is SQL, and the database has these tables:

users user_id, username, email, role, active, created_at, last_login
login_logs log_id, user_id, username, status, ip_address, timestamp, user_agent
permissions perm_id, user_id, permission, granted_by, granted_at
network_logs log_id, source_ip, dest_ip, port, bytes_transferred, protocol, timestamp

Phase 1: Build the Timeline

The first step in any investigation is establishing a timeline. When did the attacker arrive? What did they do? When did they leave?

Query: Attacker Activity Timeline
Map all activity from the suspicious IP, ordered chronologically.
Incident Timeline Query
SELECT
  l.timestamp,
  l.username,
  l.status,
  l.ip_address,
  l.user_agent
FROM login_logs l
WHERE l.ip_address = '192.168.1.99'
ORDER BY l.timestamp ASC;

This reveals the full attack narrative: initial probing, credential stuffing attempts, successful login, and post-compromise activity. Reading this chronologically tells you exactly what happened.

Phase 2: Brute-Force Detection

Quantify the attack. How aggressive was the attacker? Which accounts were targeted?

Brute-Force Analysis
WITH attack_stats AS (
  SELECT
    username,
    COUNT(*) AS total_attempts,
    SUM(CASE WHEN status = 'FAILED' THEN 1 ELSE 0 END) AS failures,
    SUM(CASE WHEN status = 'SUCCESS' THEN 1 ELSE 0 END) AS successes,
    MIN(timestamp) AS first_attempt,
    MAX(timestamp) AS last_attempt
  FROM login_logs
  WHERE ip_address = '192.168.1.99'
  GROUP BY username
)
SELECT *,
  ROUND(failures * 100.0 / total_attempts, 1) AS fail_pct
FROM attack_stats
ORDER BY total_attempts DESC;

This tells you which accounts the attacker targeted, how many attempts they made, and whether any succeeded. A success after many failures is strong evidence of credential compromise.

Phase 3: Privilege Audit

If the attacker compromised an account, what can that account do? Check for privilege escalation.

Compromised Account Permissions
SELECT
  u.username,
  u.role,
  p.permission,
  p.granted_by,
  p.granted_at
FROM users u
INNER JOIN permissions p ON u.user_id = p.user_id
WHERE u.username IN (
  SELECT DISTINCT username FROM login_logs
  WHERE ip_address = '192.168.1.99' AND status = 'SUCCESS'
)
ORDER BY p.permission;

Also check for permissions granted during the attack window -- the attacker may have escalated their own privileges:

Recent Permission Changes
SELECT * FROM permissions
WHERE granted_at BETWEEN '2026-03-14' AND '2026-03-16'
ORDER BY granted_at DESC;

Phase 4: Data Exfiltration Assessment

Quantify potential data loss. How much data left the network from the attacker's IP?

Exfiltration Volume Query
SELECT
  date(timestamp) AS day,
  dest_ip,
  COUNT(*) AS connections,
  SUM(bytes_transferred) AS total_bytes,
  ROUND(SUM(bytes_transferred) / 1048576.0, 2) AS total_mb
FROM network_logs
WHERE source_ip = '192.168.1.99'
GROUP BY date(timestamp), dest_ip
ORDER BY total_bytes DESC;

This shows where data went and how much. Large transfers to external IPs during the attack window are strong indicators of data exfiltration. Convert bytes to megabytes for the executive report.

Phase 5: Executive Summary

Combine everything into a single incident summary query that the CISO can read:

Incident Summary Report
WITH
timeline AS (
  SELECT MIN(timestamp) AS attack_start,
    MAX(timestamp) AS attack_end,
    COUNT(*) AS total_events
  FROM login_logs WHERE ip_address = '192.168.1.99'
),
compromised AS (
  SELECT COUNT(DISTINCT username) AS accounts_hit
  FROM login_logs
  WHERE ip_address = '192.168.1.99' AND status = 'SUCCESS'
),
exfil AS (
  SELECT ROUND(SUM(bytes_transferred) / 1048576.0, 2) AS mb_exfil
  FROM network_logs WHERE source_ip = '192.168.1.99'
)
SELECT
  t.attack_start, t.attack_end,
  t.total_events,
  c.accounts_hit,
  e.mb_exfil
FROM timeline t, compromised c, exfil e;

One query. One result row. Attack window, event count, compromised accounts, and data volume. This is the kind of output that drives executive decisions during an active incident.

Key Takeaways

  • Incident response starts with building a chronological timeline from logs
  • Aggregation (COUNT, SUM, GROUP BY, HAVING) powers brute-force detection
  • JOINs with subqueries map compromised accounts to their permissions
  • Network log analysis quantifies data exfiltration in human-readable units
  • CTEs chain multiple analysis steps into a single executive-ready report
  • SQL is not just a database tool -- it is an investigation weapon
