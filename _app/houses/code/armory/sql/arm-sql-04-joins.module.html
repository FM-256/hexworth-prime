Learning Objectives

  • Understand why JOINs are necessary in relational databases
  • Write INNER JOIN to combine matching rows from two tables
  • Use LEFT and RIGHT JOIN to include unmatched rows
  • Apply table aliases for readable multi-table queries
  • Chain multiple JOINs in a single query

Why JOINs?

Relational databases split data across multiple tables to avoid duplication. JOINs reconnect that data by matching rows based on related columns (typically primary key to foreign key).

Example: A users table stores account info. A login_logs table stores login events. To see which username is associated with each login, you JOIN the tables on the user ID.

users table login_logs table +----+----------+ +----+---------+--------+ | id | username | | id | user_id | status | +----+----------+ +----+---------+--------+ | 1 | admin | <------> | 1 | 1 | OK | | 2 | jsmith | <------> | 2 | 2 | OK | | 3 | analyst1 | | 3 | 1 | FAIL | +----+----------+ +----+---------+--------+ JOIN ON users.id = login_logs.user_id

INNER JOIN

INNER JOIN returns only rows where there is a match in both tables. If a user has no login logs, they will not appear in the results.

Syntax
SELECT columns
FROM table_a
INNER JOIN table_b ON table_a.col = table_b.col;
SELECT users.username, login_logs.status, login_logs.timestamp FROM users INNER JOIN login_logs ON users.user_id = login_logs.user_id;
Combine user names with their login events. Only users who have log entries appear.
sql> SELECT users.username, login_logs.status, login_logs.timestamp
> FROM users INNER JOIN login_logs ON users.user_id = login_logs.user_id;
admin|SUCCESS|2026-03-15 09:30:00
jsmith|SUCCESS|2026-03-14 17:00:00
hacker|FAILED|2026-03-15 11:45:00

LEFT JOIN

LEFT JOIN returns all rows from the left table, even if there is no match in the right table. Unmatched columns from the right table show as NULL.

This is critical for security auditing -- you want to find users who have never logged in (potential orphaned accounts).

SELECT u.username, l.timestamp, l.status FROM users u LEFT JOIN login_logs l ON u.user_id = l.user_id;
Show all users, including those with no login records. Notice the NULL values for users who never logged in.
sql> SELECT u.username, l.timestamp, l.status
> FROM users u LEFT JOIN login_logs l ON u.user_id = l.user_id;
admin|2026-03-15 09:30:00|SUCCESS
jsmith|2026-03-14 17:00:00|SUCCESS
analyst1|NULL|NULL
hacker|2026-03-15 11:45:00|FAILED

RIGHT JOIN and FULL OUTER JOIN

RIGHT JOIN Opposite of LEFT JOIN. Returns all rows from the right table, with NULLs for unmatched left rows. Less commonly used -- you can always swap table order and use LEFT JOIN instead.
FULL OUTER JOIN Returns all rows from both tables. Unmatched rows on either side show NULLs. Note: SQLite does not support FULL OUTER JOIN natively -- use UNION of LEFT and RIGHT JOIN.

Table Aliases

When working with multiple tables, aliases keep your queries short and readable. Define an alias after the table name:

Alias Syntax
SELECT u.username, p.permission
FROM users u
INNER JOIN permissions p ON u.user_id = p.user_id;

The AS keyword is optional: FROM users AS u and FROM users u are identical.

Multi-Table JOINs

Chain multiple JOINs to combine three or more tables. This is common in forensic investigations where you need to correlate users, logs, and permissions.

Three-Table Join
SELECT u.username, l.status, l.ip_address, p.permission
FROM users u
INNER JOIN login_logs l ON u.user_id = l.user_id
INNER JOIN permissions p ON u.user_id = p.user_id
WHERE l.status = 'FAILED'
ORDER BY l.timestamp DESC;

This query answers: "Show me every failed login attempt, including the user's permissions and the source IP." This is exactly what you would run when triaging a brute-force attack.

Self-Joins

A self-join joins a table with itself. This is useful for hierarchical data like org charts, or for comparing rows within the same table.

Self-Join Example: Find Users Who Share an IP
SELECT a.username AS user_a, b.username AS user_b, a.ip_address
FROM login_logs a
INNER JOIN login_logs b ON a.ip_address = b.ip_address
WHERE a.username != b.username;

This detects account sharing or lateral movement -- two different usernames logging in from the same IP address.

Key Takeaways

  • INNER JOIN returns only matching rows from both tables
  • LEFT JOIN includes all rows from the left table, NULLs for non-matches
  • Table aliases (u, l, p) keep multi-table queries readable
  • Chain multiple JOINs to correlate data across three or more tables
  • Self-joins compare rows within the same table -- useful for detecting shared credentials or IPs
