Learning Objectives

  • Use COUNT, SUM, AVG, MIN, and MAX aggregate functions
  • Group results with GROUP BY for category-level analysis
  • Filter grouped results with HAVING
  • Distinguish WHERE (row filtering) from HAVING (group filtering)
  • Build security analytics queries using aggregation

Aggregate Functions

Aggregate functions compute a single value from a set of rows. They collapse multiple rows into one summary result.

FunctionPurposeExample
COUNT()Number of rowsCOUNT(*) or COUNT(column)
SUM()Total of numeric valuesSUM(bytes_transferred)
AVG()Average of numeric valuesAVG(response_time)
MIN()Smallest valueMIN(timestamp)
MAX()Largest valueMAX(login_attempts)

COUNT -- Counting Rows

COUNT(*) counts all rows. COUNT(column) counts non-NULL values in that column.

SELECT COUNT(*) FROM login_logs;
How many total login events exist in the log?
sql> SELECT COUNT(*) FROM login_logs;
847
SELECT COUNT(*) FROM login_logs WHERE status = 'FAILED';
How many failed login attempts? Combine COUNT with WHERE for targeted analysis.
sql> SELECT COUNT(*) FROM login_logs WHERE status = 'FAILED';
142

SUM and AVG

SELECT SUM(bytes_transferred) FROM network_logs WHERE source_ip = '192.168.1.99';
Total data exfiltrated from a suspicious IP. Critical for breach impact assessment.
sql> SELECT SUM(bytes_transferred) FROM network_logs WHERE source_ip = '192.168.1.99';
15728640
SELECT AVG(response_time_ms) FROM web_requests WHERE endpoint = '/api/login';
Average response time for the login endpoint. Spikes may indicate a brute-force attack.

MIN and MAX

MIN and MAX find the smallest and largest values. Especially useful with timestamps to find the first and last occurrence of an event.

SELECT MIN(timestamp) AS first_seen, MAX(timestamp) AS last_seen FROM login_logs WHERE username = 'hacker';
When did the attacker first appear, and when was their last activity?
sql> SELECT MIN(timestamp) AS first_seen, MAX(timestamp) AS last_seen
> FROM login_logs WHERE username = 'hacker';
2026-03-14 02:15:00|2026-03-15 11:45:00

GROUP BY

GROUP BY divides rows into groups based on column values, then applies aggregate functions to each group separately. This turns raw data into actionable intelligence.

Syntax
SELECT column, COUNT(*)
FROM table
GROUP BY column;
SELECT status, COUNT(*) AS total FROM login_logs GROUP BY status;
Break down login events by status. How many succeeded vs. failed?
sql> SELECT status, COUNT(*) AS total FROM login_logs GROUP BY status;
FAILED|142
SUCCESS|705
SELECT ip_address, COUNT(*) AS attempts FROM login_logs WHERE status = 'FAILED' GROUP BY ip_address ORDER BY attempts DESC;
Which IPs have the most failed logins? This is brute-force detection 101.
sql> SELECT ip_address, COUNT(*) AS attempts FROM login_logs
> WHERE status = 'FAILED' GROUP BY ip_address ORDER BY attempts DESC;
192.168.1.99|87
10.0.5.23|31
172.16.0.100|24

HAVING -- Filtering Groups

HAVING filters groups after aggregation. It is like WHERE, but operates on the aggregated result rather than individual rows.

WHERE vs HAVING
-- WHERE filters rows BEFORE grouping
-- HAVING filters groups AFTER aggregation

SELECT ip_address, COUNT(*) AS fails
FROM login_logs
WHERE status = 'FAILED' -- filter rows first
GROUP BY ip_address
HAVING fails > 10 -- then filter groups
ORDER BY fails DESC;
SELECT username, COUNT(*) AS fail_count FROM login_logs WHERE status = 'FAILED' GROUP BY username HAVING fail_count > 5 ORDER BY fail_count DESC;
Find users with more than 5 failed login attempts. These accounts may be under attack.
sql> SELECT username, COUNT(*) AS fail_count FROM login_logs
> WHERE status = 'FAILED' GROUP BY username HAVING fail_count > 5;
hacker|87
admin|12

Real-World Security Analytics

Aggregation powers every SIEM, SOC dashboard, and forensic investigation. Here is a query that would appear in a real incident response runbook:

Daily Failed Login Summary
SELECT
  date(timestamp) AS day,
  COUNT(*) AS total_failures,
  COUNT(DISTINCT username) AS unique_targets,
  COUNT(DISTINCT ip_address) AS unique_sources
FROM login_logs
WHERE status = 'FAILED'
GROUP BY date(timestamp)
ORDER BY day DESC;

This shows daily trends: how many failures, how many different accounts targeted, and how many different source IPs. A sudden spike in unique_sources suggests a distributed brute-force campaign.

Key Takeaways

  • COUNT, SUM, AVG, MIN, MAX are the five core aggregate functions
  • GROUP BY splits rows into groups for per-category aggregation
  • HAVING filters groups after aggregation; WHERE filters rows before
  • Aggregation is the foundation of security analytics and SIEM dashboards
  • Combine GROUP BY with ORDER BY DESC to surface the worst offenders first
