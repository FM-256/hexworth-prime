Function Declarations

A function declaration defines a named, reusable block of code. Declarations are "hoisted" -- you can call them before they appear in the file.

// Function declaration (hoisted) function greet(name) { return `Hello, ${name}!`; } console.log(greet('Hexworth')); // 'Hello, Hexworth!' // Multiple parameters, default values function connect(host, port = 443, protocol = 'https') { return `${protocol}://${host}:${port}`; } console.log(connect('api.hexworth.io')); // https://api.hexworth.io:443 console.log(connect('db.local', 5432, 'tcp')); // tcp://db.local:5432

Function Expressions

A function expression assigns a function to a variable. Unlike declarations, they are NOT hoisted -- you must define them before calling them.

// Function expression (not hoisted) const square = function(n) { return n * n; }; console.log(square(5)); // 25 // Named function expression (useful for recursion + stack traces) const factorial = function fact(n) { if (n <= 1) return 1; return n * fact(n - 1); }; console.log(factorial(5)); // 120

Arrow Functions

Introduced in ES6, arrow functions provide a shorter syntax and lexically bind this (they inherit it from the surrounding scope). They are the standard for callbacks and short functions.

// Arrow function variations const add = (a, b) => a + b; // implicit return const double = n => n * 2; // single param: no parens needed const noop = () => {}; // no params // Multi-line arrow (needs explicit return) const classify = (score) => { if (score >= 90) return 'A'; if (score >= 80) return 'B'; if (score >= 70) return 'C'; return 'F'; }; // Returning an object literal (wrap in parens) const makeUser = (name, role) => ({ name, role, active: true }); console.log(add(3, 7)); // 10 console.log(double(21)); // 42 console.log(makeUser('Alice', 'admin')); // { name: 'Alice', role: 'admin', active: true }
When NOT to Use Arrows

Arrow functions do not have their own this, arguments, or super. Avoid them as object methods or constructors where you need this to refer to the calling object.

Closures

A closure is a function that remembers the variables from its enclosing scope even after that scope has finished executing. This is one of JavaScript's most powerful and most-tested concepts.

// A closure: inner function captures 'count' from outer scope function createCounter(start = 0) { let count = start; return { increment() { return ++count; }, decrement() { return --count; }, getCount() { return count; } }; } const counter = createCounter(10); console.log(counter.increment()); // 11 console.log(counter.increment()); // 12 console.log(counter.decrement()); // 11 console.log(counter.getCount()); // 11 // 'count' is private -- no way to access it directly console.log(counter.count); // undefined
// Practical closure: rate limiter function createRateLimiter(maxCalls, windowMs) { const calls = []; return function() { const now = Date.now(); // Remove expired timestamps while (calls.length > 0 && calls[0] <= now - windowMs) { calls.shift(); } if (calls.length >= maxCalls) { return false; // Rate limited } calls.push(now); return true; // Allowed }; } const limiter = createRateLimiter(3, 1000); // 3 calls per second

Callbacks

A callback is a function passed as an argument to another function, to be called later. This is the foundation of asynchronous JavaScript and event handling.

// Callback pattern: processing a list function processItems(items, callback) { const results = []; for (const item of items) { results.push(callback(item)); } return results; } const numbers = [1, 2, 3, 4, 5]; const doubled = processItems(numbers, n => n * 2); console.log(doubled); // [2, 4, 6, 8, 10] const labels = processItems(numbers, n => `Item #${n}`); console.log(labels); // ['Item #1', 'Item #2', ...]
// Real-world callback: event handling document.addEventListener('click', (event) => { console.log(`Clicked at (${event.clientX}, ${event.clientY})`); }); // setTimeout is a callback setTimeout(() => { console.log('This runs after 2 seconds'); }, 2000);

Rest Parameters and Spread

// Rest parameters: collect remaining arguments function logAll(label, ...values) { console.log(`[${label}]`, values); } logAll('ports', 80, 443, 8080); // [ports] [80, 443, 8080] // Spread: expand an array into individual arguments const scores = [95, 87, 92, 78]; console.log(Math.max(...scores)); // 95

Higher-Order Functions

Functions that take functions as arguments or return functions. You have already seen closures (return functions) and callbacks (take functions). Here is a practical composition example:

// Function that returns a function function createValidator(minLength) { return function(input) { if (input.length < minLength) { return `Must be at least ${minLength} characters`; } return null; // valid }; } const validatePassword = createValidator(8); const validateUsername = createValidator(3); console.log(validatePassword('abc')); // 'Must be at least 8 characters' console.log(validatePassword('secureP@ss')); // null console.log(validateUsername('ab')); // 'Must be at least 3 characters'

Practice: Function Mastery

  1. Write an arrow function isPrime(n) that returns true if n is a prime number
  2. Create a createLogger(prefix) closure that returns a function prepending the prefix to log messages
  3. Write a function retry(fn, times) that calls fn and retries up to 'times' if it throws
  4. Use setTimeout with a callback to print a countdown from 5 to 1

Key Takeaways

  • Function declarations are hoisted; expressions and arrows are not
  • Arrow functions inherit this from surrounding scope -- ideal for callbacks
  • Closures let inner functions access outer scope variables even after the outer function returns
  • Callbacks are functions passed to other functions to be invoked later
  • Rest (...args) collects arguments; spread (...arr) expands them
