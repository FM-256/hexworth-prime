Why Async?

JavaScript is single-threaded -- it can only do one thing at a time. Without async patterns, a network request would freeze the entire page until it completes. Async code lets JavaScript start an operation, continue running other code, and handle the result when it arrives.

// Synchronous: each line blocks until complete console.log('1. Start'); // If this took 5 seconds, the page would freeze: // const data = fetchDataSync('/api/users'); console.log('2. Done'); // Asynchronous: non-blocking console.log('1. Start'); setTimeout(() => console.log('2. This runs later'), 1000); console.log('3. This runs immediately'); // Output: 1, 3, 2 (after 1 second)

Promises

A Promise represents a value that may not be available yet. It is in one of three states: pending, fulfilled (resolved), or rejected. Promises replaced callback-based patterns and are the foundation of modern async JS.

// Creating a Promise const scanNetwork = new Promise((resolve, reject) => { // Simulate a network scan setTimeout(() => { const hosts = ['10.0.0.1', '10.0.0.5', '10.0.0.12']; if (hosts.length > 0) { resolve(hosts); // success } else { reject(new Error('No hosts found')); // failure } }, 2000); }); // Consuming a Promise scanNetwork .then(hosts => { console.log('Found hosts:', hosts); return hosts.length; }) .then(count => { console.log(`Total: ${count} hosts`); }) .catch(err => { console.error('Scan failed:', err.message); }) .finally(() => { console.log('Scan complete (success or fail)'); });

async / await

async/await is syntactic sugar over Promises. It makes async code look and behave like synchronous code, which is much easier to read and debug.

// An async function always returns a Promise async function getUser(id) { // 'await' pauses execution until the Promise resolves const response = await fetch(`/api/users/${id}`); const user = await response.json(); return user; } // Calling an async function const user = await getUser(42); console.log(user.name); // Arrow function version const getUser = async (id) => { const res = await fetch(`/api/users/${id}`); return res.json(); };

Error Handling in Async Code

// try/catch with async/await -- the standard pattern async function fetchData(url) { try { const response = await fetch(url); if (!response.ok) { throw new Error(`HTTP ${response.status}: ${response.statusText}`); } const data = await response.json(); return data; } catch (err) { console.error('Fetch failed:', err.message); return null; } } const data = await fetchData('https://api.example.com/data'); if (data) { console.log('Got data:', data); }
fetch() does NOT reject on HTTP errors

A 404 or 500 response does NOT throw an error. The promise resolves normally -- you must check response.ok or response.status yourself. Only network failures (DNS errors, offline) cause rejection.

The Fetch API

fetch() is the modern way to make HTTP requests. It returns a Promise and supports all HTTP methods, headers, and request bodies.

GET Request
const response = await fetch('https://api.github.com/users/octocat'); const user = await response.json(); console.log(user.login, user.public_repos);
POST Request with JSON
const response = await fetch('https://api.example.com/users', { method: 'POST', headers: { 'Content-Type': 'application/json', 'Authorization': 'Bearer sk-abc123', }, body: JSON.stringify({ name: 'Alice', role: 'admin', }), }); const created = await response.json(); console.log('Created user:', created.id);
Practical: API Helper Function
async function api(endpoint, options = {}) { const { method = 'GET', body, headers = {} } = options; const config = { method, headers: { 'Content-Type': 'application/json', ...headers, }, }; if (body) config.body = JSON.stringify(body); const res = await fetch(`https://api.example.com${endpoint}`, config); if (!res.ok) { const err = await res.json().catch(() => ({})); throw new Error(err.message || `HTTP ${res.status}`); } return res.json(); } // Usage const users = await api('/users'); const newUser = await api('/users', { method: 'POST', body: { name: 'Bob' } });

Parallel Async Operations

// Promise.all -- run in parallel, fail if ANY fails const [users, posts, comments] = await Promise.all([ fetch('/api/users').then(r => r.json()), fetch('/api/posts').then(r => r.json()), fetch('/api/comments').then(r => r.json()), ]); // All three requests run simultaneously // Promise.allSettled -- run all, never fails, reports status of each const results = await Promise.allSettled([ fetch('/api/service-a'), fetch('/api/service-b'), // even if this fails... fetch('/api/service-c'), ]); results.forEach((result, i) => { if (result.status === 'fulfilled') { console.log(`Service ${i}: OK`); } else { console.error(`Service ${i}: FAILED -`, result.reason); } }); // Promise.race -- resolve/reject as soon as the first one settles const fastest = await Promise.race([ fetch('/api/mirror-1'), fetch('/api/mirror-2'), ]);

Async Patterns: Sequential vs Parallel

const ids = [1, 2, 3, 4, 5]; // SEQUENTIAL: one at a time (slow but controlled) for (const id of ids) { const user = await getUser(id); console.log(user.name); } // PARALLEL: all at once (fast but more resource-intensive) const users = await Promise.all( ids.map(id => getUser(id)) ); users.forEach(u => console.log(u.name)); // BATCHED: parallel in chunks (balanced) async function batch(items, fn, batchSize = 3) { const results = []; for (let i = 0; i < items.length; i += batchSize) { const chunk = items.slice(i, i + batchSize); const chunkResults = await Promise.all(chunk.map(fn)); results.push(...chunkResults); } return results; } const allUsers = await batch(ids, getUser, 2);

Practice: Async Challenges

  1. Fetch your GitHub user profile: https://api.github.com/users/YOUR_USERNAME and display the result
  2. Build a delay(ms) function that returns a Promise that resolves after ms milliseconds
  3. Write a fetchWithTimeout(url, ms) that races a fetch against a timeout
  4. Use Promise.allSettled to check the status of 3 URLs simultaneously

Key Takeaways

  • async/await makes asynchronous code read like synchronous code
  • Always wrap await calls in try/catch for error handling
  • fetch() does NOT throw on HTTP errors -- check response.ok
  • Use Promise.all() for parallel operations, for...of with await for sequential
  • Promise.allSettled() is best when you want results from all requests regardless of failures
