ES6 Classes

Classes in JavaScript are syntactic sugar over prototype-based inheritance. They provide a clear, familiar syntax for creating objects with shared behavior. Under the hood, they still use prototypes.

class NetworkHost { // Constructor -- runs when you create a new instance constructor(ip, hostname, os = 'unknown') { this.ip = ip; this.hostname = hostname; this.os = os; this.ports = []; this.lastSeen = new Date(); } // Instance method addPort(port, service) { this.ports.push({ port, service, open: true }); } // Getter -- accessed like a property, computed on the fly get openPorts() { return this.ports.filter(p => p.open); } // Method with return value toJSON() { return { ip: this.ip, hostname: this.hostname, os: this.os, ports: this.ports, }; } toString() { return `${this.hostname} (${this.ip}) [${this.os}]`; } } // Creating instances const server = new NetworkHost('10.0.1.5', 'web-01', 'Ubuntu 24.04'); server.addPort(443, 'https'); server.addPort(22, 'ssh'); console.log(server.openPorts.length); // 2 console.log(server.toString()); // web-01 (10.0.1.5) [Ubuntu 24.04]

Inheritance

class Server extends NetworkHost { constructor(ip, hostname, os, role) { super(ip, hostname, os); // call parent constructor this.role = role; this.uptime = 0; } restart() { this.uptime = 0; console.log(`Restarting ${this.hostname}...`); } // Override parent method toString() { return `[${this.role}] ${super.toString()}`; // call parent version } } const db = new Server('10.0.2.1', 'db-01', 'RHEL 9', 'database'); db.addPort(5432, 'postgresql'); // inherited method console.log(db.toString()); // [database] db-01 (10.0.2.1) [RHEL 9] console.log(db instanceof Server); // true console.log(db instanceof NetworkHost); // true

Static Methods and Private Fields

class Vulnerability { // Private field (cannot access from outside the class) #severity; #exploitCode; // Static property -- belongs to the class, not instances static SEVERITY_LEVELS = ['info', 'low', 'medium', 'high', 'critical']; constructor(cve, description, severity) { this.cve = cve; this.description = description; this.#severity = severity; this.#exploitCode = null; this.discoveredAt = new Date(); } // Getter for private field get severity() { return this.#severity; } // Setter with validation set severity(level) { if (!Vulnerability.SEVERITY_LEVELS.includes(level)) { throw new Error(`Invalid severity: ${level}`); } this.#severity = level; } // Static method -- called on the class, not instances static fromJSON(json) { return new Vulnerability(json.cve, json.description, json.severity); } static compareSeverity(a, b) { const levels = Vulnerability.SEVERITY_LEVELS; return levels.indexOf(b.severity) - levels.indexOf(a.severity); } } const vuln = new Vulnerability('CVE-2024-1234', 'RCE in web app', 'critical'); console.log(vuln.severity); // 'critical' (via getter) console.log(vuln.#severity); // SyntaxError: private field const v2 = Vulnerability.fromJSON({ cve: 'CVE-2024-5678', description: 'XSS', severity: 'high' });

ES Modules

ES Modules let you split code across files and import only what you need. This is the standard module system in modern JavaScript -- both in browsers and Node.js.

utils.js -- exporting
// Named exports export function formatIP(ip) { return ip.split('.').map(n => n.padStart(3, '0')).join('.'); } export function isPrivateIP(ip) { return ip.startsWith('10.') || ip.startsWith('192.168.') || ip.startsWith('172.'); } export const COMMON_PORTS = { 22: 'SSH', 80: 'HTTP', 443: 'HTTPS', 3306: 'MySQL', 5432: 'PostgreSQL', }; // Default export (one per file) export default class Scanner { constructor(target) { this.target = target; } async scan() { /* ... */ } }
main.js -- importing
// Named imports (pick what you need) import { formatIP, isPrivateIP, COMMON_PORTS } from './utils.js'; // Default import import Scanner from './utils.js'; // Both at once import Scanner, { formatIP, COMMON_PORTS } from './utils.js'; // Rename on import import { formatIP as fmtIP } from './utils.js'; // Import everything import * as Utils from './utils.js'; Utils.formatIP('10.0.0.1');
Node.js Modules

To use ES modules in Node.js, either set "type": "module" in package.json, or use the .mjs file extension. The older require() / module.exports is CommonJS -- still widely used but ES modules are the future.

Module Organization Patterns

// Barrel export pattern: re-export from an index file // models/index.js export { NetworkHost } from './NetworkHost.js'; export { Server } from './Server.js'; export { Vulnerability } from './Vulnerability.js'; // Consumer can import from one path import { NetworkHost, Server, Vulnerability } from './models/index.js'; // Feature module pattern // auth/ // index.js -- public API (barrel) // login.js -- login logic // register.js -- registration logic // middleware.js -- auth middleware // utils.js -- internal helpers (not exported)

Dynamic Imports

// Load a module only when needed (code splitting) async function loadChart() { const { Chart } = await import('./chart.js'); const chart = new Chart(canvas); chart.render(data); } // Conditional loading if (user.role === 'admin') { const { AdminPanel } = await import('./admin/panel.js'); new AdminPanel().init(); }

Practice: Classes and Modules

  1. Create a Task class with title, priority, completed status, and a toggle() method
  2. Create a TaskList class that manages an array of Tasks with add(), remove(), and getByPriority() methods
  3. Add a static factory method Task.fromString('Buy groceries:high') that parses a string into a Task
  4. Split the Task and TaskList classes into separate files and import them into a main.js

Key Takeaways

  • Classes provide clean syntax for object creation and inheritance
  • extends creates subclasses; super calls the parent constructor/methods
  • Private fields (#field) enforce encapsulation at the language level
  • ES modules use import/export to share code between files
  • Dynamic import() loads modules on demand for performance
