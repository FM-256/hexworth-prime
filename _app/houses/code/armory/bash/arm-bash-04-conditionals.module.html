The test Command

Conditionals in bash revolve around exit codes. Every command returns 0 for success and non-zero for failure. The test command (or its alias [ ]) evaluates an expression and returns an exit code.

test / [ ] / [[ ]]
# These three are equivalent:
$ test 5 -gt 3 && echo "yes"
yes
$ [ 5 -gt 3 ] && echo "yes"
yes
$ [[ 5 -gt 3 ]] && echo "yes"
yes

Spaces matter: [ 5 -gt 3 ] works. [5 -gt 3] fails. The brackets must have spaces around them and around every operand.

Number Comparisons

Integer Comparison Operators
-eq Equal to [ "$a" -eq "$b" ]
-ne Not equal to [ "$a" -ne "$b" ]
-gt Greater than [ "$a" -gt "$b" ]
-ge Greater or equal [ "$a" -ge "$b" ]
-lt Less than [ "$a" -lt "$b" ]
-le Less or equal [ "$a" -le "$b" ]

String Comparisons

String Operators
= Equal (POSIX) [ "$a" = "$b" ]
== Equal (bash) [[ "$a" == "$b" ]]
!= Not equal [ "$a" != "$b" ]
-z String is empty [ -z "$a" ]
-n String is not empty [ -n "$a" ]
=~ Regex match (bash) [[ "$a" =~ pattern ]]

[[ ]] vs [ ]: Double brackets are a bash extension. They support regex with =~, glob matching with ==, and do not require quoting variables. Prefer [[ ]] in bash scripts; use [ ] only for POSIX sh compatibility.

File Tests

File tests are the backbone of sysadmin scripts -- checking if files exist, are readable, or have been modified.

File Test Operators
-e file Exists
-f file Is a regular file
-d file Is a directory
-r file Is readable
-w file Is writable
-x file Is executable
-s file Has size > 0
-L file Is a symbolic link
f1 -nt f2 f1 is newer than f2
File Test Example
$ [ -f /etc/passwd ] && echo "exists" || echo "missing"
exists
$ [ -d /tmp ] && echo "is a directory"
is a directory

if / elif / else

Full if Block
#!/bin/bash
DISK_PCT=$(df / | awk 'NR==2{gsub(/%/,""); print $5}')
if [[ "$DISK_PCT" -ge 90 ]]; then
echo "CRITICAL: Disk usage at ${DISK_PCT}%"
elif [[ "$DISK_PCT" -ge 75 ]]; then
echo "WARNING: Disk usage at ${DISK_PCT}%"
else
echo "OK: Disk usage at ${DISK_PCT}%"
fi

case Statements

The case statement is cleaner than a chain of if/elif when matching a variable against multiple patterns.

case Pattern Matching
#!/bin/bash
case "$1" in
start)
echo "Starting service..."
;;
stop)
echo "Stopping service..."
;;
restart)
echo "Restarting service..."
;;
status|info)
echo "Service is running"
;;
*)
echo "Usage: $0 {start|stop|restart|status}"
exit 1
;;
esac

Logical Operators

Combining Conditions
# AND -- both must be true
$ [[ -f /etc/passwd && -r /etc/passwd ]] && echo "readable"
readable
# OR -- at least one must be true
$ [[ -f /tmp/a.txt || -f /tmp/b.txt ]] && echo "found one"
# NOT -- negate
$ [[ ! -d /nonexistent ]] && echo "does not exist"
does not exist

Practical: Pre-flight Check Script

preflight.sh
#!/bin/bash
# Verify environment before deployment
ERRORS=0
if [[ ! -f ".env" ]]; then
echo "FAIL: .env file missing"
((ERRORS++))
fi
if ! command -v docker &> /dev/null; then
echo "FAIL: docker not installed"
((ERRORS++))
fi
DISK=$(df / | awk 'NR==2{gsub(/%/,"");print $5}')
if [[ "$DISK" -gt 85 ]]; then
echo "WARN: Disk usage at ${DISK}%"
fi
if [[ "$ERRORS" -gt 0 ]]; then
echo "Pre-flight FAILED ($ERRORS errors)"
exit 1
else
echo "Pre-flight PASSED"
fi

Key Takeaways

  • Bash conditionals are based on exit codes: 0 = true, non-zero = false
  • Use -eq/-ne/-gt/-lt for numbers, ==/!= for strings
  • File tests (-f, -d, -r, -x) are essential for sysadmin scripts
  • Prefer [[ ]] over [ ] in bash scripts for safety and features
  • case statements handle multi-branch matching cleanly
