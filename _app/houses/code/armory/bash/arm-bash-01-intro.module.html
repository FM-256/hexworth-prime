What is Bash?

Bash (Bourne Again SHell) is the default command-line interpreter on most Linux distributions. It is both an interactive command processor -- the thing you type commands into -- and a scripting language capable of automating complex system tasks.

When you open a terminal and type commands, you are already using Bash. A Bash script is simply a text file containing the same commands you would type interactively, executed in sequence.

Interactive Shell Type commands one at a time, see results immediately
Scripting Language Automate sequences of commands in reusable files
System Glue Connect programs together with pipes and redirections
Universal Available on every Linux, macOS, and WSL system

Shell vs Terminal

These two terms are often confused. The terminal (or terminal emulator) is the window that displays text. The shell is the program running inside that window, interpreting your commands.

Common Shells
bash - Bourne Again Shell (most common on Linux)
zsh - Z Shell (default on macOS since Catalina)
sh - Original Bourne Shell (POSIX baseline)
fish - Friendly Interactive Shell
dash - Debian Almquist Shell (fast, minimal)

Check which shell you are currently running:

echo $SHELL
Prints the path to your default login shell
$ echo $SHELL
/bin/bash

The Shebang Line

Every script should start with a shebang -- the two characters #! followed by the path to the interpreter. This tells the OS which program should execute the file.

#!/bin/bash
The standard Bash shebang -- use this for all Bash scripts
#!/bin/bash
# This is a comment -- the shell ignores lines starting with #
echo "Hello from a Bash script!"

Portable alternative: #!/usr/bin/env bash uses the env command to find bash in the user's PATH. More portable across different systems where bash may not live at /bin/bash.

Your First Script

Let's walk through the full lifecycle of creating and running a script.

Step 1: Create the file
$ echo '#!/bin/bash' > hello.sh
$ echo 'echo "Hello, $(whoami)! Today is $(date +%A)."' >> hello.sh
Step 2: Make it executable
Scripts need the execute permission before they can run directly
$ chmod +x hello.sh
$ ls -l hello.sh
-rwxr-xr-x 1 learner learner 62 Mar 15 10:00 hello.sh
Step 3: Run it
$ ./hello.sh
Hello, learner! Today is Saturday.

Why ./hello.sh? The ./ prefix tells the shell to look in the current directory. Without it, bash searches only your PATH directories and will report "command not found."

Running Scripts Without chmod

You can also run a script by passing it directly to the bash interpreter. This does not require execute permissions:

bash hello.sh
Explicitly tells bash to interpret the file
$ bash hello.sh
Hello, learner! Today is Saturday.

This is useful for testing scripts quickly, but production scripts should always be made executable with chmod and run with ./ notation.

Script File Conventions

.sh Extension Not required by the OS, but convention. Helps humans identify scripts.
Naming Use lowercase with hyphens: backup-logs.sh, check-disk.sh
Comments Start with # -- explain why, not what. Document assumptions.
Header Block Include author, date, purpose, and usage in top comments.
Script Header Template
#!/bin/bash
# -------------------------------------------------
# Script: check-disk.sh
# Purpose: Alert when disk usage exceeds threshold
# Usage: ./check-disk.sh [threshold]
# -------------------------------------------------

Key Takeaways

  • Bash is both an interactive shell and a scripting language
  • The terminal is the window; the shell is the interpreter inside it
  • Every script starts with a shebang: #!/bin/bash
  • chmod +x makes a script executable; ./ runs it from the current directory
  • Use clear naming conventions and header comments in every script
