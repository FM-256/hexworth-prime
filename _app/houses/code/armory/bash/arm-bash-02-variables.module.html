Variable Assignment

In bash, variables are assigned with the NAME=value syntax. There must be no spaces around the equals sign.

Basic Assignment
$ NAME="Alice"
$ AGE=30
$ LOGFILE="/var/log/auth.log"
$ echo "User: $NAME, Age: $AGE"
User: Alice, Age: 30

Common mistake: NAME = "Alice" with spaces will fail. Bash interprets NAME as a command and = as its first argument.

Quoting Rules

Quoting controls how the shell interprets special characters. This is one of the most important concepts in bash scripting.

Double Quotes " " Variables and command substitution expand. Spaces preserved. Use for most strings.
Single Quotes ' ' Everything is literal. No expansion at all. Use when you want exact text.
No Quotes Word splitting and globbing occur. Dangerous with filenames containing spaces.
Backticks ` ` Legacy command substitution. Prefer $() instead -- it nests cleanly.
Quoting in Action
$ GREETING="Hello"
$ echo "$GREETING World"
Hello World
$ echo '$GREETING World'
$GREETING World
$ echo $GREETING World
Hello World

Rule of thumb: Always double-quote your variables unless you have a specific reason not to. Unquoted variables break on filenames with spaces and can introduce security bugs.

Command Substitution

Capture the output of a command and store it in a variable using $(command).

$(command) Syntax
$ CURRENT_USER=$(whoami)
$ TODAY=$(date +%Y-%m-%d)
$ FILE_COUNT=$(ls | wc -l)
$ echo "User $CURRENT_USER has $FILE_COUNT files as of $TODAY"
User learner has 3 files as of 2026-03-15
Nested Substitution
$() nests cleanly -- backticks cannot do this
$ KERNEL=$(uname -r)
$ echo "Kernel: $KERNEL"
Kernel: 5.15.0-91-generic

Arithmetic

Bash supports integer arithmetic natively. Use $(( )) for arithmetic expansion.

Arithmetic Expansion
$ A=10
$ B=3
$ echo "Sum: $((A + B))"
Sum: 13
$ echo "Product: $((A * B))"
Product: 30
$ echo "Division: $((A / B))"
Division: 3
$ echo "Modulo: $((A % B))"
Modulo: 1
Increment and Decrement
$ COUNT=0
$ ((COUNT++))
$ ((COUNT++))
$ echo "$COUNT"
2

Integer only: Bash cannot do floating-point math. For decimals, pipe to bc: echo "scale=2; 10/3" | bc

Environment Variables

Shell variables exist only in the current shell. Environment variables are exported and inherited by child processes.

export
Promotes a shell variable to an environment variable
$ MY_VAR="local only"
$ export MY_VAR
# Now child processes can see MY_VAR
$ export DB_HOST="192.168.1.100"
# Assign and export in one step
Common Environment Variables
$HOME - User's home directory
$USER - Current username
$PATH - Search directories for commands
$PWD - Current working directory
$SHELL - Default login shell
$HOSTNAME - Machine hostname
$RANDOM - Random integer 0-32767

Special Variables

Bash provides several built-in variables for script control flow:

Script Parameters & Status
$0 - Name of the script
$1 - First argument
$2 - Second argument (and so on)
$# - Number of arguments
$@ - All arguments (preserves quoting)
$* - All arguments (as single string)
$? - Exit status of last command
$$ - PID of the current shell
$! - PID of last background process

Key Takeaways

  • No spaces around = in variable assignment: NAME="value"
  • Double quotes expand variables; single quotes are literal
  • $(command) captures command output into a variable
  • $(( )) handles integer arithmetic -- use bc for decimals
  • export makes variables visible to child processes
  • Always double-quote variables to prevent word splitting bugs
