Working with Objects

< PowerShell Track

Learning Objectives

  • Understand that everything in PowerShell is a .NET object
  • Inspect object properties and methods with Get-Member

  • Create custom objects with PSCustomObject

Everything Is an Object

In PowerShell, every piece of data is a .NET object with properties and methods. A string is not just text -- it is a System.String with 40+ methods. A process is a System.Diagnostics.Process with CPU time, handles, and the ability to call .Kill().

This object model is what makes the PowerShell pipeline so powerful. You never need to parse text -- properties travel intact through every pipe operator.

objects everywhere
# A string is an object
$hostname = "DC01.corp.local"
$hostname.GetType().FullName
System.String

$hostname.Split(".")
DC01
corp
local

$hostname.ToUpper()
DC01.CORP.LOCAL

$hostname.Length
15

# A date is an object
$d = Get-Date
$d.DayOfWeek    # Monday
$d.AddDays(-7)  # One week ago
($d - [datetime]"2024-01-01").Days  # Days since Jan 1 2024

Get-Member: Discover Object Members

Get-Member (alias: gm) is the single most important discovery command in PowerShell. Pipe any object to it to see every property and method available.

get-member
# Discover what Get-Process actually returns
PS C:\> Get-Process | Get-Member

   TypeName: System.Diagnostics.Process

Name                       MemberType     Definition
----                       ----------     ----------
Handles                    AliasProperty  Handles = Handlecount
Name                       AliasProperty  Name = ProcessName
NPM                        AliasProperty  NPM = NonpagedSystemMemorySize64
PM                         AliasProperty  PM = PagedMemorySize64
...
Kill                       Method         void Kill()
WaitForExit                Method         bool WaitForExit(int milliseconds)
CPU                        ScriptProperty System.Object CPU {get=...}
Path                       ScriptProperty System.Object Path {get=...}

# Filter to just properties
PS C:\> Get-Process | Get-Member -MemberType Property

# Discover string methods
PS C:\> "test" | Get-Member -MemberType Method

Formatting Output

Format cmdlets control how objects are displayed. Use them at the end of a pipeline -- never before other processing commands, because they destroy the object structure.

format-list / format-table
# Format-Table -- compact columnar output (default for most cmdlets)
PS C:\> Get-Process | Format-Table Name, Id, CPU, WorkingSet -AutoSize

# Format-List -- all properties as key:value pairs (great for detail)
PS C:\> Get-Process -Name "lsass" | Format-List *

__NounName                 : Process
Name                       : lsass
Handles                    : 1423
VM                         : 289165312
WS                         : 14610432
PM                         : 9814016
NPM                        : 58720
Path                       : C:\Windows\System32\lsass.exe
Company                    : Microsoft Corporation
CPU                        : 4.234375
...

# Out-GridView -- interactive filterable GUI table (Windows only)
PS C:\> Get-Process | Out-GridView -Title "Process Browser"

# ConvertTo-Csv -- export for spreadsheets
PS C:\> Get-Process | Select-Object Name,Id,CPU | ConvertTo-Csv -NoTypeInformation

# ConvertTo-Json -- export for APIs and SIEM ingestion
PS C:\> Get-Process | Select-Object Name,Id,Path | ConvertTo-Json

PSCustomObject

When you want to create your own structured data -- like a scan result or a report row -- use PSCustomObject. It integrates seamlessly with the pipeline and all formatting/export cmdlets.

pscustomobject
# Build a scan result object
$result = [PSCustomObject]@{
    Timestamp  = Get-Date -Format "yyyy-MM-dd HH:mm:ss"
    Host       = "10.0.0.1"
    Port       = 445
    Open       = $true
    Service    = "Microsoft-DS"
    Risk       = "HIGH"
}

$result.Host    # 10.0.0.1
$result.Risk    # HIGH

# Build a collection of results
$scanResults = @()
$targets = @("10.0.0.1", "10.0.0.2", "10.0.0.3")

foreach ($target in $targets) {
    $scanResults += [PSCustomObject]@{
        Host    = $target
        Scanned = Get-Date
        Status  = "Pending"
    }
}

# Export to CSV for your report
$scanResults | Export-Csv -Path ".\scan_results.csv" -NoTypeInformation

# Add a property after creation
$result | Add-Member -NotePropertyName "Remediated" -NotePropertyValue $false

Comparison and Sorting

sort and group
# Sort processes by CPU usage descending
Get-Process | Sort-Object CPU -Descending | Select-Object -First 10

# Group event log entries by event ID
Get-EventLog -LogName Security -Newest 1000 |
    Group-Object EventID |
    Sort-Object Count -Descending |
    Select-Object -First 10 |
    Format-Table Count, Name -AutoSize

# Measure statistics on a property
Get-Process | Measure-Object CPU -Sum -Average -Maximum
Count   : 127
Sum     : 482.34
Average : 3.80
Maximum : 185.44

# Compare two object sets -- what's new since last check?
$before = Get-Process | Select-Object -ExpandProperty Name | Sort-Object
# ... time passes, new process starts ...
$after  = Get-Process | Select-Object -ExpandProperty Name | Sort-Object
Compare-Object $before $after | Where-Object SideIndicator -eq "=>"

Try It Yourself

Build a process snapshot report:

  1. Get all running processes with Get-Process
  2. Pipe to Get-Member and identify 3 properties you find interesting
  3. Build a PSCustomObject for the top 5 CPU-consuming processes with: Name, Id, CPU (rounded to 2 decimal places), RAM in MB, and Path
  4. Export the result to a CSV file and verify it opens correctly

Key Takeaways

  • Every PowerShell value is a .NET object with properties and methods
  • Use Get-Member to discover what any object can do -- pipe anything to it
  • Format cmdlets (Format-Table, Format-List) go at the END of a pipeline only
  • PSCustomObject creates structured data that flows cleanly through pipelines
  • Export-Csv and ConvertTo-Json serialize object collections for reporting and SIEM ingestion
  • Compare-Object is a powerful drift detection tool -- compare before/after process or file lists
