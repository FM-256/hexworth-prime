File System & Registry

Learning Objectives

  • Navigate and manage the file system with Item cmdlets

Navigating the File System

PowerShell treats the file system as a provider -- a navigable namespace. The same cmdlets (Get-Item, Set-Item, New-Item, Remove-Item) work across all providers, including the registry.

file system navigation
# List directory contents
PS C:\> Get-ChildItem C:\Windows\System32 -Filter "*.dll" | Measure-Object
Count: 3842

# Recursive search -- find all PowerShell scripts in a directory tree
PS C:\> Get-ChildItem -Path C:\Users -Recurse -Filter "*.ps1" -ErrorAction SilentlyContinue

# Find recently modified files (incident response: what changed in last 24h?)
PS C:\> Get-ChildItem -Path C:\Windows\System32 -Recurse -ErrorAction SilentlyContinue |
    Where-Object { $_.LastWriteTime -gt (Get-Date).AddHours(-24) } |
    Select-Object FullName, LastWriteTime, Length |
    Sort-Object LastWriteTime -Descending

# Check if a path exists before acting on it
if (Test-Path "C:\Suspicious\payload.exe") {
    Write-Warning "Suspicious file found!"
    Get-Item "C:\Suspicious\payload.exe" | Select-Object FullName, Length, CreationTime, LastWriteTime
}

Reading and Writing Files

file i/o
# Read a text file as an array of lines
$lines = Get-Content -Path "C:\logs\auth.log"
$lines.Count  # Number of lines

# Read and immediately filter (memory-efficient for large logs)
Get-Content "C:\logs\auth.log" | Where-Object { $_ -match "FAILED" }

# Read last 100 lines (like Linux tail)
Get-Content "C:\logs\auth.log" -Tail 100

# Read binary file as bytes
$bytes = Get-Content "C:\suspicious.exe" -Encoding Byte -ReadCount 0
# Check for MZ header (Windows PE executable)
if ($bytes[0] -eq 0x4D -and $bytes[1] -eq 0x5A) {
    Write-Warning "File is a Windows executable (MZ header found)"
}

# Write content to file (overwrites)
Set-Content -Path "C:\reports\findings.txt" -Value "Scan complete"

# Append to file
Add-Content -Path "C:\reports\findings.txt" -Value "$(Get-Date): New finding"

# Write with proper encoding for reports
$report = Get-Process | ConvertTo-Csv -NoTypeInformation
$report | Out-File -FilePath "C:\reports\processes.csv" -Encoding UTF8

PSDrives and Providers

PSDrives expose different data stores using a consistent path-based interface. The file system, registry, environment variables, certificates, and more are all navigable with the same commands.

psdrives
# List all available PSDrives
PS C:\> Get-PSDrive

Name           Used (GB)     Free (GB) Provider
----           ---------     --------- --------
Alias                                  Alias
C                  85.42        414.58 FileSystem
Cert                                   Certificate
Env                                    Environment
HKCU                                   Registry
HKLM                                   Registry
Variable                               Variable

# Navigate the certificate store like a filesystem
PS C:\> Get-ChildItem Cert:\LocalMachine\My | Select-Object Subject, Thumbprint, NotAfter

# Navigate environment variables
PS C:\> Get-ChildItem Env: | Where-Object Name -like "APPDATA*"

# Create a custom drive mapped to a deep path
New-PSDrive -Name Sys32 -PSProvider FileSystem -Root C:\Windows\System32
Get-ChildItem Sys32:\drivers\etc\hosts

Registry Operations

The Windows registry is exposed as a PowerShell provider via the HKLM: and HKCU: drives. This is critical for persistence analysis -- attackers love registry run keys.

registry -- persistence hunting
# Read a registry value
PS C:\> Get-ItemProperty -Path "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion" `
    -Name ProductName

ProductName : Windows 11 Pro
PSPath      : Microsoft.PowerShell.Core\Registry::HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion

# INCIDENT RESPONSE: Check all run keys for persistence
$runKeys = @(
    "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Run",
    "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\RunOnce",
    "HKCU:\SOFTWARE\Microsoft\Windows\CurrentVersion\Run",
    "HKCU:\SOFTWARE\Microsoft\Windows\CurrentVersion\RunOnce"
)

foreach ($key in $runKeys) {
    if (Test-Path $key) {
        Write-Host "`n[RUN KEY] $key" -ForegroundColor Cyan
        Get-ItemProperty -Path $key | ForEach-Object {
            $_.PSObject.Properties |
                Where-Object { $_.Name -notlike "PS*" } |
                ForEach-Object { Write-Host "  $($_.Name) = $($_.Value)" }
        }
    }
}

# Create a registry value (requires appropriate permissions)
New-ItemProperty -Path "HKCU:\SOFTWARE\MyApp" `
    -Name "LastRun" -Value (Get-Date).ToString() -PropertyType String -Force

Try It Yourself

Run a persistence check on your own system:

  1. Query all four common Run key paths shown above
  2. List all items in HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Run and research each entry
  3. Search C:\Users\$env:USERNAME recursively for any .ps1 files modified in the last 7 days
  4. Export the run key contents to a CSV for baseline documentation

Key Takeaways

  • Item cmdlets (Get/New/Set/Remove-Item) work uniformly across all providers
  • Get-Content -Tail N reads the last N lines efficiently -- use for live log monitoring
  • PSDrives expose registry, certs, and environment variables as navigable paths
  • Registry Run keys at HKLM and HKCU are primary persistence locations -- always check during IR
  • Use -ErrorAction SilentlyContinue during recursive searches to skip protected paths
  • Always check file timestamps and MZ headers when analyzing suspicious binaries
