Active Directory

< PowerShell Track

Learning Objectives

  • Import and use the ActiveDirectory PowerShell module
  • Query, create, and modify users and groups
  • Search AD with LDAP filters
  • Identify privileged accounts and security misconfigurations

Loading the AD Module

The ActiveDirectory module ships with RSAT (Remote Server Administration Tools). On domain controllers it is available natively. For workstations, install RSAT or connect to a DC with an implicit remoting session.

setup
# Check if the module is available
PS C:\> Get-Module -ListAvailable -Name ActiveDirectory

# Import it
PS C:\> Import-Module ActiveDirectory

# Install RSAT on Windows 10/11 (admin required)
PS C:\> Add-WindowsCapability -Online -Name Rsat.ActiveDirectory.DS-LDS.Tools~~~~0.0.1.0

# Verify domain connectivity
PS C:\> Get-ADDomain | Select-Object Name, DNSRoot, DomainMode

Name      DNSRoot          DomainMode
----      -------          ----------
corp      corp.local       Windows2016Domain

Querying Users

get-aduser
# Get a specific user
PS C:\> Get-ADUser -Identity "jdoe" -Properties *

# Search with LDAP filter -- find all enabled admin accounts
PS C:\> Get-ADUser -Filter { Enabled -eq $true -and AdminCount -eq 1 } `
    -Properties AdminCount, LastLogonDate, PasswordLastSet |
    Select-Object Name, SamAccountName, LastLogonDate, PasswordLastSet

# SECURITY: Find accounts with passwords that never expire
PS C:\> Get-ADUser -Filter { PasswordNeverExpires -eq $true -and Enabled -eq $true } `
    -Properties PasswordNeverExpires, PasswordLastSet |
    Select-Object Name, SamAccountName, PasswordLastSet |
    Sort-Object PasswordLastSet

# SECURITY: Find stale accounts (no logon in 90 days)
$cutoff = (Get-Date).AddDays(-90)
PS C:\> Get-ADUser -Filter { LastLogonDate -lt $cutoff -and Enabled -eq $true } `
    -Properties LastLogonDate |
    Select-Object Name, SamAccountName, LastLogonDate |
    Sort-Object LastLogonDate |
    Export-Csv "stale_accounts.csv" -NoTypeInformation

Groups and Privileged Access

ad groups -- privilege review
# List members of Domain Admins (critical audit task)
PS C:\> Get-ADGroupMember -Identity "Domain Admins" -Recursive |
    Select-Object Name, SamAccountName, ObjectClass

# Check ALL tier-0 groups at once
$criticalGroups = @(
    "Domain Admins", "Enterprise Admins", "Schema Admins",
    "Administrators", "Account Operators", "Backup Operators"
)

foreach ($group in $criticalGroups) {
    $members = Get-ADGroupMember -Identity $group -Recursive -ErrorAction SilentlyContinue
    if ($members) {
        Write-Host "`n[$group] -- $($members.Count) member(s)" -ForegroundColor Yellow
        $members | Select-Object Name, SamAccountName | Format-Table -AutoSize
    }
}

# Find groups a user belongs to (lateral movement path analysis)
PS C:\> Get-ADPrincipalGroupMembership -Identity "jdoe" |
    Select-Object Name, GroupCategory, GroupScope

Creating and Modifying Users

new-aduser / set-aduser
# Create a new user account
$password = ConvertTo-SecureString "TempP@ss2026!" -AsPlainText -Force

New-ADUser -Name "John Smith" `
    -GivenName "John" `
    -Surname "Smith" `
    -SamAccountName "jsmith" `
    -UserPrincipalName "jsmith@corp.local" `
    -Path "OU=Staff,DC=corp,DC=local" `
    -AccountPassword $password `
    -Enabled $true `
    -ChangePasswordAtLogon $true

# Disable a compromised account immediately
Disable-ADAccount -Identity "jdoe"

# Force password reset on next logon
Set-ADUser -Identity "jdoe" -ChangePasswordAtLogon $true

# Bulk-disable accounts from a CSV list (incident response)
Import-Csv "compromised_accounts.csv" | ForEach-Object {
    Disable-ADAccount -Identity $_.SamAccountName -WhatIf
    # Remove -WhatIf when you are ready to execute
}

LDAP Filters

The -LDAPFilter parameter uses raw LDAP syntax for complex queries that PowerShell's -Filter parameter cannot express. LDAP filters are faster on large directories.

ldap filter queries
# Find Kerberoastable accounts (SPN set, enabled)
PS C:\> Get-ADUser -LDAPFilter "(&(servicePrincipalName=*)(!(userAccountControl:1.2.840.113556.1.4.803:=2)))" `
    -Properties ServicePrincipalName, LastLogonDate |
    Select-Object Name, SamAccountName, ServicePrincipalName

# Find AS-REP roastable accounts (no Kerberos pre-auth required)
PS C:\> Get-ADUser -LDAPFilter "(userAccountControl:1.2.840.113556.1.4.803:=4194304)" |
    Select-Object Name, SamAccountName

# Find unconstrained delegation (major security risk)
PS C:\> Get-ADComputer -LDAPFilter "(userAccountControl:1.2.840.113556.1.4.803:=524288)" |
    Select-Object Name, DNSHostName

# Find accounts with admin privileges across the forest
PS C:\> Get-ADUser -Filter { AdminCount -eq 1 } -Properties AdminCount |
    Measure-Object
# AdminCount=1 means AD has protected this account at some point
# Accounts with AdminCount=1 bypass inheritance -- a common misconfiguration

Try It Yourself

If you have access to a lab domain controller or read-only AD access:

  1. Run Get-ADUser -Filter * -Properties LastLogonDate | Measure-Object to count total users
  2. Find all users whose passwords have not been changed in over 180 days
  3. List members of the Domain Admins group and count them
  4. Search for any service accounts (SamAccountName containing "svc" or "_sa") and list their SPNs

Key Takeaways

  • Import the ActiveDirectory module first -- it is not loaded by default
  • Use -Properties * to retrieve all attributes; by default only a subset is returned
  • Audit Domain Admins, Enterprise Admins, and Schema Admins regularly -- these groups are Tier 0
  • Kerberoastable accounts (useraccounts with SPNs) are prime lateral movement targets
  • Use -WhatIf on destructive operations until you are certain of the target scope
  • AdminCount=1 on a non-admin account is a misconfiguration that blocks permission inheritance
