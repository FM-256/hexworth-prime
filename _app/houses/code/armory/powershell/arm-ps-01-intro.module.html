What Is PowerShell?

PowerShell is Microsoft's task automation and configuration management framework built on the .NET runtime. Unlike cmd.exe which works with text, PowerShell works with .NET objects -- every command returns structured data you can inspect, filter, and pipe into other commands.

For security professionals, PowerShell is unavoidable. It is the primary tool for Windows administration, Active Directory management, and incident response. It is also the most common living-off-the-land attack vector used by threat actors. Understanding it from both sides is non-negotiable.

Object-Based Pipeline Commands pass structured .NET objects, not raw text. Properties survive every pipe.
Windows Native Deep integration with WMI, COM, Active Directory, registry, event logs, and WinRM.
Cross-Platform (v7) PowerShell 7 runs on Linux and macOS -- same scripts, same syntax across environments.
Security Weapon Used by red teams, blue teams, and threat actors alike. Understanding it protects you.

PowerShell 5.1 vs PowerShell 7

Two major versions coexist in the wild. Know which one you are dealing with -- they differ in capability, performance, and security features.

FeatureWindows PowerShell 5.1PowerShell 7 (Core)
Runtime.NET Framework 4.x.NET 7/8 (cross-platform)
PlatformsWindows onlyWindows, Linux, macOS
Executablepowershell.exepwsh.exe
Included in WindowsYes (built-in)Manual install required
AMSI integrationYesYes (improved)
Script Block LoggingYesYes
StatusMaintenance onlyActive development

In enterprise environments you will almost always encounter 5.1. For new scripts and cross-platform work, target 7. Check your version with $PSVersionTable.

Launching PowerShell

Several ways to open PowerShell on Windows. In a security context, pay attention to whether you are elevated -- the title bar shows "Administrator" when running as admin.

launch methods
# Method 1: Start menu -- search "PowerShell" or "pwsh"
# Method 2: Run dialog (Win+R)
powershell.exe          # Windows PowerShell 5.1
pwsh.exe                # PowerShell 7 (if installed)

# Method 3: From cmd.exe or another shell
C:\> powershell.exe -NoProfile -ExecutionPolicy Bypass

Your First Commands

PowerShell commands follow a strict Verb-Noun naming convention. The verb tells you what the command does; the noun tells you what it operates on. This makes discovery natural -- if you want information about processes, try Get-Process.

# Check your PowerShell version
PS C:\> $PSVersionTable

Execution Policy

Execution policy controls which PowerShell scripts are allowed to run. It is not a true security boundary -- a determined attacker can bypass it -- but it prevents accidental script execution.

execution policy
# View current policy
PS C:\> Get-ExecutionPolicy
Restricted

# View policy at each scope level
PS C:\> Get-ExecutionPolicy -List

        Scope ExecutionPolicy
        ----- ---------------
MachinePolicy       Undefined
   UserPolicy       Undefined
      Process       Undefined
  CurrentUser       Undefined
 LocalMachine      Restricted

# Common policies:
# Restricted    -- No scripts allowed (Windows default)
# RemoteSigned  -- Local scripts OK, downloaded must be signed
# Unrestricted  -- All scripts run (with warning for downloaded)
# Bypass        -- Nothing blocked, no warnings (used by attackers)

# Set policy for current user (requires no elevation)
PS C:\> Set-ExecutionPolicy RemoteSigned -Scope CurrentUser

During incident response, a machine with Bypass policy is a red flag -- it may indicate an attacker changed it to run unsigned scripts. Check the event log (Event ID 4103) for policy change history.

Try It Yourself

Open PowerShell and run each of these commands. Observe the output:

  1. Run $PSVersionTable -- which version are you on?
  2. Run Get-ExecutionPolicy -List -- what is the LocalMachine policy?
  3. Run Get-Host -- what does this tell you about the shell environment?
  4. Run Get-Command -Verb Get | Measure-Object -- how many Get-* commands exist?

Key Takeaways

  • PowerShell works with .NET objects, not raw text -- this makes it far more powerful than cmd.exe
  • Windows PowerShell 5.1 (powershell.exe) is built into Windows; PowerShell 7 (pwsh.exe) is a separate install
  • Commands follow Verb-Noun naming: Get-Process, Set-Item, New-Object
  • Execution policy is not a security boundary -- -ExecutionPolicy Bypass overrides it instantly
  • Check $PSVersionTable to identify version; check policy with Get-ExecutionPolicy -List
