PS-03

Variables & Data Types

< PowerShell Track

Learning Objectives

  • Declare and use variables with the $ prefix
  • Understand common .NET types and type casting
  • Work with arrays and hashtables
  • Use automatic variables for scripting context

Variables

All PowerShell variables start with $. They are dynamically typed by default -- the runtime infers the type from the assigned value. You can optionally constrain the type with a type annotation.

variable basics
# Simple assignment
$targetHost = "192.168.1.100"
$port       = 445
$isAdmin    = $true

# Type annotation -- constrains the variable
[string]$username  = "jdoe"
[int]$failedLogins = 0
[datetime]$scanTime = Get-Date

# Check the actual type
$port.GetType().FullName
System.Int32

$targetHost.GetType().Name
String

# String interpolation -- $variables expand inside double quotes
Write-Host "Connecting to $targetHost on port $port"
Connecting to 192.168.1.100 on port 445

# Single quotes are LITERAL -- no expansion
Write-Host 'Value is $port'
Value is $port

Arrays

Arrays hold ordered collections of items. PowerShell uses the @() syntax for explicit arrays and supports 0-based indexing. Unlike many languages, PowerShell arrays are fixed-size -- the += operator creates a new array each time.

arrays
# Create an array
$targets = @("10.0.0.1", "10.0.0.2", "10.0.0.3")
$ports   = 22, 80, 443, 3389   # comma list also creates array

# Access by index
$targets[0]     # 10.0.0.1
$targets[-1]    # 10.0.0.3 (last element)

# Slice -- get elements 0 through 1
$targets[0..1]

# Count elements
$targets.Count  # 3

# Iterate
foreach ($ip in $targets) {
    Write-Host "Scanning $ip"
}

# Use ArrayList when you need fast appends
$findings = [System.Collections.ArrayList]::new()
[void]$findings.Add("CVE-2024-1234")
[void]$findings.Add("CVE-2024-5678")
$findings.Count  # 2

Hashtables

Hashtables store key-value pairs. They are the PowerShell equivalent of a dictionary and are used everywhere -- from splatting parameters to building custom objects.

hashtables
# Create a hashtable
$hostInfo = @{
    Hostname = "DC01"
    IP       = "10.0.0.5"
    OS       = "Windows Server 2022"
    Open443  = $true
}

# Access values
$hostInfo["Hostname"]   # DC01
$hostInfo.IP             # 10.0.0.5

# Add and remove keys
$hostInfo["LastSeen"] = Get-Date
$hostInfo.Remove("Open443")

# Iterate over key-value pairs
foreach ($key in $hostInfo.Keys) {
    Write-Host "$key = $($hostInfo[$key])"
}

# Ordered hashtable -- preserves insertion order
$report = [ordered]@{
    Target    = "192.168.1.1"
    StartTime = Get-Date
    Vulns     = 0
}

Type Casting

PowerShell coerces types automatically in many situations, but explicit casting is important for security scripts where data types affect comparison behavior.

type casting
# Explicit cast
[int]"443"       # 443 (int)
[string]3389    # "3389" (string)
[bool]0         # False
[bool]1         # True

# Parsing dates from log strings
$logDate = [datetime]"2026-03-16 09:00:00"
$logDate.DayOfWeek   # Monday

# Convert hex EventID to decimal (common in log analysis)
[int]"0x4625"    # 17957
"0x{0:X}" -f 4625  # "0x1211" -- back to hex

# SecureString -- for passwords in scripts
$secpwd = ConvertTo-SecureString "P@ssw0rd" -AsPlainText -Force
$cred   = New-Object PSCredential("domain\user", $secpwd)

# WARNING: storing plaintext passwords in scripts is bad practice
# Use Get-Credential interactively or a secrets vault instead

Automatic Variables

PowerShell provides automatic variables that hold context about the current state of the environment. These are read-only or special -- do not overwrite them.

automatic variables
# $_ / $PSItem -- current pipeline object
Get-Process | Where-Object { $_.CPU -gt 50 }

# $true / $false -- boolean constants
$isElevated = $true

# $null -- represents absence of value
if ($result -eq $null) { Write-Host "No data" }

# $? -- success status of last command
Get-Process -Name "nonexistent" -ErrorAction SilentlyContinue
if (-not $?) { Write-Host "Command failed" }

# $Error -- array of recent errors (most recent at index 0)
$Error[0].Exception.Message

# $env -- environment variables via PSDrive
$env:COMPUTERNAME   # hostname
$env:USERNAME       # current user
$env:USERPROFILE    # C:\Users\username
$env:Path           # PATH variable

# $PSScriptRoot -- directory of the running script
$logPath = Join-Path $PSScriptRoot "logs\scan.log"

Build a host inventory hashtable:

  2. Add the current date/time to the "LastSeen" key using Get-Date
  3. Loop over the hashtable and print each key-value pair formatted as "Key: Value"
  4. Convert the hashtable to a PSCustomObject and verify .GetType().Name changes

Key Takeaways

  • All variables use the $ prefix; type annotations like [int] constrain the type
  • Double quotes expand variables; single quotes are literal strings
  • Use @() for arrays; use ArrayList when you need frequent appends
  • Hashtables (@{Key=Value}) are key-value stores; use [ordered] to preserve order
  • Automatic variables like $_, $env:USERNAME, and $Error provide runtime context
  • Use SecureString and Get-Credential -- never hardcode plaintext passwords
