Conditional Logic

PowerShell comparison operators differ from most languages: they use text like -eq, -gt, -like rather than symbols. This avoids ambiguity with redirection operators.

if / elseif / else
# Risk scoring based on open port count
$openPorts = 12

if ($openPorts -gt 20) {
    Write-Host "CRITICAL: Excessive attack surface"
} elseif ($openPorts -gt 10) {
    Write-Host "HIGH: Reduce exposure"
} elseif ($openPorts -gt 5) {
    Write-Host "MEDIUM: Review open ports"
} else {
    Write-Host "LOW: Port exposure acceptable"
}
HIGH: Reduce exposure

# Common comparison operators
# -eq  -ne  -lt  -le  -gt  -ge    (equal, not-equal, less, etc.)
# -like  -notlike    (wildcard: * and ?)
# -match -notmatch   (regex)
# -contains -notcontains  (collection membership)
# -and  -or  -not   (logical operators)

Switch Statement

PowerShell's switch is more powerful than most languages -- it supports wildcards, regex, and file input in addition to exact matches.

switch
# Map Windows Event IDs to descriptions
$eventId = 4625

switch ($eventId) {
    4624 { Write-Host "Successful logon" }
    4625 { Write-Host "Failed logon -- brute force candidate" }
    4648 { Write-Host "Explicit credential use (runas / pass-the-hash)" }
    4720 { Write-Host "New user account created" }
    4728 { Write-Host "Member added to security-enabled global group" }
    default { Write-Host "Unknown event: $eventId" }
}
Failed logon -- brute force candidate

# Switch with -Wildcard (matches multiple patterns)
$filename = "payload.ps1"
switch -Wildcard ($filename) {
    "*.ps1"  { Write-Host "PowerShell script -- review carefully" }
    "*.bat"  { Write-Host "Batch file" }
    "*.vbs"  { Write-Host "VBScript" }
    "*.exe"  { Write-Host "Executable" }
}

Loops

foreach / for / while
# foreach -- iterates over a collection (most common)
$subnets = @("10.0.0.0/24", "10.0.1.0/24", "172.16.0.0/16")
foreach ($subnet in $subnets) {
    Write-Host "Scanning subnet: $subnet"
}

# ForEach-Object -- pipeline version, memory-efficient for large datasets
Get-ChildItem C:\Windows\System32 -Filter "*.exe" |
    ForEach-Object {
        Write-Host "$($_.Name) -- $([math]::Round($_.Length/1KB, 1)) KB"
    }

# for -- index-based iteration
for ($i = 1; $i -le 254; $i++) {
    $ip = "192.168.1.$i"
    # Test-Connection -Quiet returns $true/$false
    if (Test-Connection -ComputerName $ip -Count 1 -Quiet) {
        Write-Host "$ip is UP"
    }
}

# while -- condition-based, good for retry logic
$attempts = 0
$maxAttempts = 3
while ($attempts -lt $maxAttempts) {
    $attempts++
    Write-Host "Attempt $attempts of $maxAttempts"
    # break exits immediately; continue skips to next iteration
}

Functions

Functions encapsulate reusable logic. PowerShell functions can accept pipeline input, validate parameters, and emit objects -- making them first-class citizens alongside built-in cmdlets.

basic functions
# Simple function
function Get-PortRisk {
    param(
        [int]$Port
    )

    switch ($Port) {
        23   { return "CRITICAL: Telnet (cleartext)" }
        21   { return "HIGH: FTP (cleartext)" }
        445  { return "HIGH: SMB (common exploit target)" }
        3389 { return "HIGH: RDP (brute-force target)" }
        22   { return "MEDIUM: SSH (ensure key auth)" }
        443  { return "LOW: HTTPS" }
        default { return "INFO: Port $Port" }
    }
}

Get-PortRisk -Port 445
HIGH: SMB (common exploit target)

Get-PortRisk -Port 443
LOW: HTTPS

Advanced Functions with CmdletBinding

Adding [CmdletBinding()] to a function transforms it into an advanced function that supports common parameters like -Verbose, -Debug, -ErrorAction, and pipeline input binding.

advanced function
function Invoke-PortCheck {
    [CmdletBinding()]
    param(
        [Parameter(Mandatory, ValueFromPipeline)]
        [string]$ComputerName,

        [Parameter()]
        [int[]]$Port = @(22, 80, 443, 445, 3389),

        [Parameter()]
        [int]$TimeoutMs = 500
    )

    process {
        Write-Verbose "Checking $ComputerName"
        foreach ($p in $Port) {
            $tcp = New-Object System.Net.Sockets.TcpClient
            $result = $tcp.BeginConnect($ComputerName, $p, $null, $null)
            $wait   = $result.AsyncWaitHandle.WaitOne($TimeoutMs, $false)
            $open   = $wait -and -not $result.IsCompleted -eq $false

            [PSCustomObject]@{
                Host  = $ComputerName
                Port  = $p
                Open  = $open
                Risk  = Get-PortRisk -Port $p
            }
            $tcp.Close()
        }
    }
}

# Usage -- accepts pipeline input
@("10.0.0.1", "10.0.0.2") | Invoke-PortCheck -Verbose

Try It Yourself

Write a function called Get-EventSeverity that:

  1. Takes a Windows Event ID as a mandatory integer parameter
  2. Uses a switch statement to return a severity string for Event IDs 4624, 4625, 4648, 4720, 4732, 4776
  3. Returns "Unknown" for any other ID
  4. Test it with a foreach loop over an array of sample Event IDs

Key Takeaways

  • Comparison operators use words: -eq, -gt, -like, -match -- not symbols
  • Switch supports -Wildcard and -Regex flags for pattern matching
  • Use foreach for collections; ForEach-Object in pipelines for memory efficiency
  • Functions with param() blocks support named, typed, and validated parameters
  • [CmdletBinding()] unlocks -Verbose, -Debug, pipeline binding, and -ErrorAction
  • ValueFromPipeline lets your function accept piped input like a native cmdlet
