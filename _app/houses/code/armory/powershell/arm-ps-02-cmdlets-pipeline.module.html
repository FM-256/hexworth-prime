Cmdlets & Pipeline

< PowerShell Track

Learning Objectives

  • Understand the Verb-Noun cmdlet naming convention
  • Use Get-Help and Get-Command to discover commands
  • Chain commands with the pipeline operator
  • Filter and shape output with Where-Object and Select-Object

The Verb-Noun Convention

Every PowerShell cmdlet follows a Verb-Noun pattern. The verb is always an approved verb from a controlled list; the noun describes what is being acted on. This consistency makes the entire command surface discoverable even without documentation.

common verb groups
# Getting (read-only) -- safe to run on live systems
Get-Process, Get-Service, Get-Item, Get-Content

# Creating -- add new objects
New-Item, New-Object, New-LocalUser, New-ADUser

# Modifying -- change existing objects
Set-Item, Set-Content, Set-ExecutionPolicy

# Removing -- delete objects
Remove-Item, Remove-Service, Stop-Process

# Listing approved verbs (important for writing your own cmdlets)
PS C:\> Get-Verb | Sort-Object Verb

Verb        Group
----        -----
Add         Common
Clear       Common
Get         Common
New         Common
Remove      Common
Set         Common
...

Get-Help: The PowerShell Manual

Get-Help is the built-in documentation system. Before running an unfamiliar command in a security investigation or on a production system, always check the help first.

get-help usage
# Basic help -- shows synopsis and syntax
PS C:\> Get-Help Get-Process

# Detailed help -- includes parameter descriptions
PS C:\> Get-Help Get-Process -Detailed

# Examples only -- the fastest way to learn a cmdlet
PS C:\> Get-Help Get-Process -Examples

# Online help -- opens browser to official docs
PS C:\> Get-Help Get-Process -Online

# Update local help files (run as admin)
PS C:\> Update-Help -Force

# Wildcard search -- find all cmdlets mentioning "network"
PS C:\> Get-Help *network*

Get-Command: Discover What Exists

Get-Command lists available commands. Use it to find cmdlets you do not know the exact name of, or to audit what is available in the current session.

get-command discovery
# Find all cmdlets with "Event" in the name
PS C:\> Get-Command *Event*

# Find all Get- cmdlets
PS C:\> Get-Command -Verb Get

# Find cmdlets operating on services
PS C:\> Get-Command -Noun Service

CommandType  Name           Version  Source

PS C:\> Get-Command -Module ActiveDirectory | Measure-Object

The Pipeline

The pipeline (|) passes the output of one command as input to the next. Because PowerShell passes objects (not text), the receiving command can access properties directly without parsing.

pipeline fundamentals
# Without pipeline -- two separate steps
PS C:\> $procs = Get-Process
PS C:\> $procs | Sort-Object CPU -Descending

# Same thing, one line
PS C:\> Get-Process | Sort-Object CPU -Descending | Select-Object -First 10

# Security use: find processes consuming unusual CPU
PS C:\> Get-Process | Where-Object { $_.CPU -gt 100 } | Select-Object Name, Id, CPU, Path

Name       Id     CPU    Path
----       --     ---    ----
chrome   4521  185.44   C:\Program Files\Google\Chrome\Application\chrome.exe
pwsh     1234  142.31   C:\Program Files\PowerShell\7\pwsh.exe

# Count services by status
PS C:\> Get-Service | Group-Object Status

Count Name     Group
----- ----     -----
  183 Running  {AJRouter, ALG, AppIDSvc...}
   62 Stopped  {AdobeARMservice, AppMgmt...}

Where-Object: Filtering

Where-Object filters objects in the pipeline based on a condition. The automatic variable $_ (or $PSItem) refers to the current object being evaluated.

where-object filtering
# Long syntax (explicit scriptblock)
PS C:\> Get-Service | Where-Object { $_.Status -eq 'Running' }

# Short syntax (PowerShell 3+, cleaner for simple conditions)
PS C:\> Get-Service | Where-Object Status -eq 'Running'

# Security: find services running as SYSTEM
PS C:\> Get-WmiObject Win32_Service |
    Where-Object { $_.StartName -eq 'LocalSystem' -and $_.State -eq 'Running' } |
    Select-Object Name, PathName

# Find processes without a file path (possible injection)
PS C:\> Get-Process | Where-Object { $_.Path -eq $null } |
    Select-Object Name, Id, Company

# String matching with -like (wildcards) and -match (regex)
PS C:\> Get-Process | Where-Object { $_.Name -like "power*" }
PS C:\> Get-Process | Where-Object { $_.Name -match "^(cmd|powershell|pwsh)$" }

Select-Object: Shaping Output

Select-Object picks specific properties from objects and can add calculated properties. It is how you control which columns appear in output.

select-object shaping
# Select specific properties
PS C:\> Get-Process | Select-Object Name, Id, CPU, WorkingSet

# Calculated properties -- rename or transform
PS C:\> Get-Process | Select-Object Name, Id,
    @{Name='CPU_Sec'; Expression={[math]::Round($_.CPU, 2)}},
    @{Name='RAM_MB';  Expression={[math]::Round($_.WorkingSet / 1MB, 1)}} |
    Sort-Object RAM_MB -Descending | Select-Object -First 10

# First / Last N items
PS C:\> Get-Process | Sort-Object CPU -Descending | Select-Object -First 5
PS C:\> Get-EventLog -LogName Security -Newest 50 | Select-Object -Last 10

# Unique values -- deduplicate
PS C:\> Get-Process | Select-Object -ExpandProperty Name -Unique | Sort-Object

Try It Yourself

Build a process audit one-liner. In PowerShell, construct a pipeline that:

  1. Gets all running processes with Get-Process
  2. Filters for processes using more than 50MB of working set memory
  3. Selects only Name, Id, and a calculated property showing RAM in MB
  4. Sorts by RAM descending and shows the top 10

Try It Yourself

Use Get-Help to explore a new cmdlet:

  1. Run Get-Help Get-NetTCPConnection -Examples
  2. Run Get-NetTCPConnection | Where-Object State -eq 'Established'
  3. Add Select-Object LocalPort, RemoteAddress, OwningProcess to the pipeline
  4. Cross-reference OwningProcess IDs with Get-Process to identify what programs own each connection

Key Takeaways

  • All cmdlets follow Verb-Noun naming -- learn the verbs, guess the nouns
  • Get-Help CmdletName -Examples is the fastest way to learn any cmdlet
  • Get-Command *keyword* discovers unknown cmdlets by name pattern
  • The pipeline passes objects, not text -- properties remain accessible downstream
  • $_ inside scriptblocks refers to the current pipeline object
  • Where-Object filters; Select-Object shapes -- both are essential daily tools
