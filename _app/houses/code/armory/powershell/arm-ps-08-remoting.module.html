Remote Management

< PowerShell Track

Learning Objectives

  • Enable and configure PowerShell Remoting via WinRM
  • Run commands on remote systems with Invoke-Command
  • Open interactive sessions with Enter-PSSession
  • Use CIM sessions for WMI queries at scale

WinRM and PSRemoting

PowerShell Remoting is built on WS-Management (WinRM). Traffic is encrypted by default using Kerberos on domain-joined machines or HTTPS for non-domain scenarios. WinRM listens on TCP 5985 (HTTP) and 5986 (HTTPS).

From a security standpoint, WinRM access is a lateral movement path. Audit who has WinRM permissions, and ensure Event ID 4688 and 4689 (process creation/termination) are logged on remote systems.

enabling remoting
# Enable remoting on a machine (run as admin)
PS C:\> Enable-PSRemoting -Force

# Check WinRM status
PS C:\> Get-Service WinRM
Status   Name               DisplayName
------   ----               -----------
Running  WinRM              Windows Remote Management (WS-Management)

# Test connectivity before attempting a session
PS C:\> Test-WSMan -ComputerName "DC01"

# View who can connect (TrustedHosts for non-domain workgroups)
PS C:\> Get-Item WSMan:\localhost\Client\TrustedHosts

# For non-domain environments: add trusted hosts (use HTTPS in production)
PS C:\> Set-Item WSMan:\localhost\Client\TrustedHosts -Value "192.168.1.*" -Force

Invoke-Command

Invoke-Command runs a scriptblock on one or more remote computers simultaneously. Results are deserialized objects -- they retain property values but lose live methods.

invoke-command
# Run a command on a single remote host
PS C:\> Invoke-Command -ComputerName "WEB01" -ScriptBlock {
    Get-Process | Sort-Object CPU -Descending | Select-Object -First 5
}

# Run on multiple hosts in parallel (default throttle: 32)
PS C:\> $servers = @("WEB01", "WEB02", "DB01", "MGMT01")
PS C:\> Invoke-Command -ComputerName $servers -ScriptBlock {
    [PSCustomObject]@{
        Host     = $env:COMPUTERNAME
        Uptime   = (Get-Date) - (Get-CimInstance Win32_OperatingSystem).LastBootUpTime
        LoggedOn = (Get-WmiObject Win32_ComputerSystem).UserName
    }
}

# Pass local variables into the remote scriptblock with $Using:
$threshold = 80
Invoke-Command -ComputerName "DB01" -ScriptBlock {
    Get-Process | Where-Object { $_.CPU -gt $Using:threshold }
}

# Run with alternate credentials
$cred = Get-Credential
Invoke-Command -ComputerName "DC01" -Credential $cred -ScriptBlock { whoami }

Enter-PSSession

Enter-PSSession opens an interactive remote PowerShell session. The prompt changes to show the remote hostname. Use this for hands-on investigation of a specific endpoint.

interactive sessions
# Open an interactive session
PS C:\> Enter-PSSession -ComputerName "WEB01"
[WEB01]: PS C:\Users\admin\Documents> Get-Process
[WEB01]: PS C:\Users\admin\Documents> exit

# Persistent sessions -- reusable, keep state between commands
$session = New-PSSession -ComputerName "DB01" -Name "DBSession"

# Run commands against a saved session
Invoke-Command -Session $session -ScriptBlock { $dbPath = "C:\Data\prod.db" }
Invoke-Command -Session $session -ScriptBlock { Test-Path $dbPath }  # $dbPath persists!

# List active sessions
PS C:\> Get-PSSession

# Close sessions when done
PS C:\> Get-PSSession | Remove-PSSession

CIM Sessions

CIM (Common Information Model) replaces the older WMI interface. Get-CimInstance uses WinRM by default, making it firewall-friendly and consistent with modern security tooling.

cim sessions for wmi
# Query WMI via CIM locally
PS C:\> Get-CimInstance -ClassName Win32_OperatingSystem |
    Select-Object Caption, Version, LastBootUpTime, TotalVisibleMemorySize

# Query multiple remotes with a CIM session
$cimSession = New-CimSession -ComputerName @("WEB01", "DB01")

Get-CimInstance -CimSession $cimSession -ClassName Win32_Service |
    Where-Object { $_.State -eq "Running" -and $_.StartName -eq "LocalSystem" } |
    Select-Object PSComputerName, Name, PathName |
    Sort-Object PSComputerName

# Security: find autostart services with unusual paths
Get-CimInstance -ClassName Win32_Service |
    Where-Object { $_.StartMode -eq "Auto" -and $_.PathName -notlike "*System32*" } |
    Select-Object Name, PathName, StartName

$cimSession | Remove-CimSession

Try It Yourself

Practice remoting (use localhost if no remote targets are available):

  1. Run Invoke-Command -ComputerName localhost -ScriptBlock { $env:COMPUTERNAME }
  2. Use Invoke-Command to collect the top 5 CPU processes from localhost and format as a table
  3. Query Win32_LoggedOnUser via CIM to see who is currently logged on
  4. Use Get-CimInstance Win32_Service to find services with startup mode Auto that do not run from System32

Key Takeaways

  • WinRM (TCP 5985/5986) is the transport -- enable it with Enable-PSRemoting
  • Invoke-Command runs scriptblocks on remote hosts in parallel -- use it for mass data collection
  • Use $Using:varName to pass local variables into remote scriptblocks
  • Persistent sessions (New-PSSession) maintain state between commands -- clean them up with Remove-PSSession
  • CIM sessions use WinRM and are the modern replacement for legacy WMI DCOM remoting
  • From an IR standpoint, WinRM access is equivalent to remote code execution -- audit it accordingly
