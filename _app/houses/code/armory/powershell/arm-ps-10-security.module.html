Event Log Analysis

The Windows Security event log is the primary source of authentication and privilege data. Knowing which Event IDs matter -- and how to query them at scale -- separates effective incident responders from the rest.

security event log triage
# Failed logon summary (brute-force detection)
PS C:\> Get-WinEvent -FilterHashtable @{
    LogName   = 'Security'
    Id        = 4625
    StartTime = (Get-Date).AddHours(-24)
} | Group-Object { $_.Properties[5].Value } |
    Sort-Object Count -Descending |
    Select-Object -First 20 |
    Format-Table Count, Name -AutoSize

# Privileged logon activity (Event 4672 = special privileges assigned)
Get-WinEvent -FilterHashtable @{ LogName='Security'; Id=4672; StartTime=(Get-Date).AddDays(-7) } |
    ForEach-Object {
        [PSCustomObject]@{
            Time     = $_.TimeCreated
            Account  = $_.Properties[1].Value
            Logon_ID = $_.Properties[3].Value
        }
    } | Sort-Object Time -Descending | Select-Object -First 50

# PowerShell script block logging (Event 4104)
# Attackers hate this -- it captures decoded/deobfuscated commands
Get-WinEvent -LogName 'Microsoft-Windows-PowerShell/Operational' |
    Where-Object Id -eq 4104 |
    Select-Object -First 20 |
    ForEach-Object { $_.Message | Select-String -Pattern "Invoke-|IEX|EncodedCommand|DownloadString" }

Process and Network Forensics

live system triage
# Processes with no parent (possible injection or orphaned malware)
PS C:\> Get-WmiObject Win32_Process | ForEach-Object {
    $parent = Get-WmiObject Win32_Process -Filter "ProcessId=$($_.ParentProcessId)"
    [PSCustomObject]@{
        PID        = $_.ProcessId
        Name       = $_.Name
        Path       = $_.ExecutablePath
        ParentPID  = $_.ParentProcessId
        ParentName = if ($parent) { $parent.Name } else { "(none)" }
    }
} | Where-Object { $_.ParentName -eq "(none)" -and $_.PID -ne 4 }

# Active network connections with owning process
PS C:\> Get-NetTCPConnection -State Established |
    Select-Object LocalAddress, LocalPort, RemoteAddress, RemotePort, OwningProcess |
    ForEach-Object {
        $proc = Get-Process -Id $_.OwningProcess -ErrorAction SilentlyContinue
        $_ | Add-Member -NotePropertyName ProcessName -NotePropertyValue $proc.Name -PassThru
    } | Where-Object { $_.RemoteAddress -notlike "127.*" -and $_.RemoteAddress -ne "::1" } |
    Sort-Object RemoteAddress | Format-Table -AutoSize

# Find processes loading unusual DLLs from temp directories
Get-Process | ForEach-Object {
    $_.Modules | Where-Object {
        $_.FileName -match "(\\Temp\\|\\AppData\\|\\Downloads\\)"
    } | ForEach-Object {
        [PSCustomObject]@{ Process=$_.ModuleName; DLL=$_.FileName }
    }
}

AMSI and Script Block Logging

AMSI (Antimalware Scan Interface) intercepts PowerShell scripts before execution and passes content to registered antivirus engines. Script Block Logging captures the actual content of every script block that runs, even after deobfuscation.

enable script block logging via registry
# Enable Script Block Logging (logs Event 4104 to PowerShell/Operational)
$psLogPath = "HKLM:\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ScriptBlockLogging"
if (-not (Test-Path $psLogPath)) {
    New-Item -Path $psLogPath -Force | Out-Null
}
Set-ItemProperty -Path $psLogPath -Name "EnableScriptBlockLogging" -Value 1
Set-ItemProperty -Path $psLogPath -Name "EnableScriptBlockInvocationLogging" -Value 1

# Enable Module Logging (logs every module command to Security log)
$modLogPath = "HKLM:\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ModuleLogging"
if (-not (Test-Path $modLogPath)) { New-Item $modLogPath -Force | Out-Null }
Set-ItemProperty -Path $modLogPath -Name "EnableModuleLogging" -Value 1

# Verify AMSI is active in the current session
[Ref].Assembly.GetType('System.Management.Automation.AmsiUtils') |
    ForEach-Object { $_.GetField('amsiInitFailed','NonPublic,Static').GetValue($null) }
# Should return: False (AMSI is active)
# True means AMSI has been tampered with -- major red flag

Defender Note: AMSI Bypass Detection

Any attempt to patch AmsiUtils or set amsiInitFailed=True is a strong indicator of malicious PowerShell execution. Hunt for this in script block logs and alert on it immediately.

Constrained Language Mode

Constrained Language Mode (CLM) is the most effective PowerShell defense. It restricts what can execute -- no .NET type access, no COM objects, no direct API calls. It is enforced by AppLocker or WDAC policies.

language mode
# Check current language mode
PS C:\> $ExecutionContext.SessionState.LanguageMode
FullLanguage    # Default -- no restrictions
# ConstrainedLanguage -- restricted (AppLocker/WDAC enforced)
# RestrictedLanguage  -- interactive only, no scripts
# NoLanguage          -- only built-in commands

# What CLM blocks:
# - [System.Reflection.Assembly]::Load() -- no arbitrary .NET loading
# - New-Object (COM/WScript.Shell, etc.)
# - Add-Type -- no compiling inline C#
# - Invoke-Expression (IEX) -- no dynamic code execution

# What CLM allows:
# - All built-in cmdlets
# - Basic types: string, int, bool, hashtable, array
# - Approved .NET types in an allowlist

# Sign your scripts to run in CLM under AppLocker
$cert = Get-ChildItem Cert:\CurrentUser\My -CodeSigningCert
Set-AuthenticodeSignature -FilePath ".\Monitor.ps1" -Certificate $cert

Rapid IR Checklist

A repeatable PowerShell-based IR collection covers the volatile data sources that disappear when a system is rebooted. Run these in order -- fastest first.

ir collection one-liners
# 1. Current user context
whoami /all

# 2. Who is logged on
Get-WmiObject Win32_LoggedOnUser | Select-Object -Unique

# 3. Process tree snapshot
Get-WmiObject Win32_Process | Select-Object ProcessId, ParentProcessId, Name, ExecutablePath |
    Export-Csv ".\ir_processes.csv" -NoTypeInformation

# 4. Network connections
Get-NetTCPConnection | Export-Csv ".\ir_connections.csv" -NoTypeInformation

# 5. Recent failed logons (last 4 hours)
Get-WinEvent -FilterHashtable @{ LogName='Security'; Id=4625; StartTime=(Get-Date).AddHours(-4) } |
    Export-Csv ".\ir_failed_logons.csv" -NoTypeInformation

# 6. Autorun check
@("HKLM:\Software\Microsoft\Windows\CurrentVersion\Run",
  "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run") | ForEach-Object {
    if (Test-Path $_) { Get-ItemProperty $_ }
}

# 7. Scheduled tasks outside Microsoft namespace
Get-ScheduledTask | Where-Object TaskPath -notlike "\Microsoft*" |
    Select-Object TaskName, TaskPath, State | Export-Csv ".\ir_tasks.csv" -NoTypeInformation

Try It Yourself

Run a mini-IR collection on your own system:

  1. Check your language mode: $ExecutionContext.SessionState.LanguageMode
  2. Pull the last 100 Security events and group by EventID -- which IDs appear most?
  3. Collect all established TCP connections and identify the remote IPs -- look up any unknown ones
  4. Run the autorun registry check and document everything you find -- is it all expected?

Key Takeaways

  • Event ID 4625 = failed logon, 4624 = success, 4672 = privileged logon -- monitor these constantly
  • Script Block Logging (Event 4104) captures deobfuscated attacker commands -- enable it everywhere
  • AMSI bridges PowerShell to AV engines -- verify amsiInitFailed is False during IR
  • Constrained Language Mode + AppLocker is the gold standard for hardening PowerShell
  • Sign all production scripts with a code signing cert -- CLM blocks unsigned scripts in AppLocker environments
  • Collect volatile data (processes, connections, logons) immediately -- it vanishes at reboot
