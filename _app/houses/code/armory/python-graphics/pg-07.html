Game Architecture

Before writing code, plan your game's structure. Every game has these components: game objects (sprites), game rules (physics, scoring), game states (playing, paused, game over), and user interface (HUD, menus). Pong is the perfect first game because it covers all four with minimal complexity.

Pong has three game objects: two paddles and a ball. The rules: ball bounces off walls and paddles, scoring when it passes a paddle. States: playing and game over. UI: the score display.

The Paddle Class

paddle.py
class Paddle(pygame.sprite.Sprite):
    def __init__(self, x, y, color, controls=None):
        super().__init__()
        self.image = pygame.Surface((15, 90))
        self.image.fill(color)
        self.rect = self.image.get_rect(center=(x, y))
        self.speed = 6
        self.controls = controls  # (up_key, down_key) or None for AI
        self.score = 0

    def update(self, ball=None):
        if self.controls:
            # Human player
            keys = pygame.key.get_pressed()
            if keys[self.controls[0]]: self.rect.y -= self.speed
            if keys[self.controls[1]]: self.rect.y += self.speed
        elif ball:
            # Simple AI: follow the ball
            if ball.rect.centery < self.rect.centery:
                self.rect.y -= self.speed - 1  # Slightly slower than player
            elif ball.rect.centery > self.rect.centery:
                self.rect.y += self.speed - 1

        # Keep on screen
        if self.rect.top < 0: self.rect.top = 0
        if self.rect.bottom > 600: self.rect.bottom = 600

The Ball Class

ball.py
import math, random

class Ball(pygame.sprite.Sprite):
    def __init__(self):
        super().__init__()
        self.image = pygame.Surface((12, 12))
        self.image.fill((255, 255, 255))
        self.rect = self.image.get_rect(center=(400, 300))
        self.base_speed = 5
        self.reset()

    def reset(self):
        self.rect.center = (400, 300)
        angle = random.choice([
            random.uniform(-30, 30),      # Rightward
            random.uniform(150, 210)     # Leftward
        ])
        rad = math.radians(angle)
        self.vel_x = self.base_speed * math.cos(rad)
        self.vel_y = self.base_speed * math.sin(rad)

    def update(self):
        self.rect.x += int(self.vel_x)
        self.rect.y += int(self.vel_y)

        # Bounce off top and bottom walls
        if self.rect.top <= 0 or self.rect.bottom >= 600:
            self.vel_y *= -1

    def bounce_off_paddle(self, paddle):
        # Calculate bounce angle based on hit position
        offset = (self.rect.centery - paddle.rect.centery) / (paddle.rect.height / 2)
        angle = offset * 60  # Max 60 degree bounce
        speed = min(self.base_speed + 1, 10)  # Speed up slightly

        if self.vel_x < 0:  # Going left, bounce right
            self.vel_x = speed * math.cos(math.radians(angle))
        else:  # Going right, bounce left
            self.vel_x = -speed * math.cos(math.radians(angle))
        self.vel_y = speed * math.sin(math.radians(angle))

The bounce angle depends on where the ball hits the paddle. Hitting the center bounces straight, while hitting the edges creates steeper angles. This is what makes Pong skill-based -- you can aim your returns by positioning the paddle.

The Complete Game Loop

pong.py (main loop)
# Setup
player1 = Paddle(30, 300, (245,158,11), (pygame.K_w, pygame.K_s))
player2 = Paddle(770, 300, (59,130,246))  # AI (no controls)
ball = Ball()
all_sprites = pygame.sprite.Group(player1, player2, ball)
font = pygame.font.Font(None, 72)

while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT: running = False

    # Update
    player1.update()
    player2.update(ball)  # Pass ball for AI tracking
    ball.update()

    # Paddle collisions
    if ball.rect.colliderect(player1.rect) and ball.vel_x < 0:
        ball.bounce_off_paddle(player1)
    if ball.rect.colliderect(player2.rect) and ball.vel_x > 0:
        ball.bounce_off_paddle(player2)

    # Scoring
    if ball.rect.left <= 0:
        player2.score += 1; ball.reset()
    if ball.rect.right >= 800:
        player1.score += 1; ball.reset()

    # Draw
    screen.fill((9, 9, 16))
    # Center line
    pygame.draw.line(screen, (50,50,50), (400,0), (400,600), 1)
    all_sprites.draw(screen)

    # Score display
    s1 = font.render(str(player1.score), True, (245,158,11))
    s2 = font.render(str(player2.score), True, (59,130,246))
    screen.blit(s1, (320, 20))
    screen.blit(s2, (440, 20))

Game Architecture Patterns

As games grow, you need organization. Common patterns include separating game logic from rendering, using state machines for game flow, and encapsulating related functionality into classes. The Pong example above is small enough to keep in one file, but larger games benefit from splitting into modules.

A clean file structure might be: main.py (game loop), sprites.py (all sprite classes), settings.py (constants like colors, speeds, dimensions), and utils.py (helper functions).

Key Takeaways

  • Plan game objects, rules, states, and UI before coding
  • Use rect.colliderect() for rectangle-based collision detection
  • Bounce angles based on hit position make gameplay skill-based
  • AI opponents can simply track the ball with slight delay
  • Separate game state (score, lives) from rendering
  • pygame.font.render() creates text surfaces for score display
