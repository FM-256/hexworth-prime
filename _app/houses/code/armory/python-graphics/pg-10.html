Capstone Project Overview

This is where everything comes together. You will build a complete game from scratch using the skills you have developed throughout this track. The game must include: a game loop, sprite-based objects, collision detection, scoring, multiple game states, and at least one piece of polish (sound, particles, transitions).

The goal is not to build the next AAA title -- it is to demonstrate mastery of the fundamentals. A simple, well-polished game beats a complex, broken one every time.

Project Ideas

Choose one of these projects or propose your own. Each is scoped to be completable in 4-8 hours of focused work.

Space Shooter Ship at the bottom, enemies descend from top. Arrow keys to move, Space to shoot. Score per kill, lives lost when hit. Increasing difficulty.
Snake Classic snake game. Grow by eating food, die by hitting walls or yourself. Score = length. Speed increases as you grow.
Asteroid Dodge Player ship at center, asteroids fly from edges. Dodge as long as possible. Score = survival time. Asteroids speed up.
Platformer Side-scrolling character with gravity and jumping. Collect coins, avoid enemies. Multiple levels. This is the hardest option.
Tower Defense Enemies walk a path. Place towers that auto-shoot. Earn money per kill to buy more towers. Wave-based difficulty.
Maze Runner Navigate a procedurally generated maze. Timer-based scoring. Fog of war (only see nearby). Multiple maze sizes as levels.

Project Requirements

Your capstone must meet these minimum requirements:

  • A complete game loop running at 60 FPS
  • At least 3 sprite classes (player + 2 others)
  • Keyboard or mouse input for player control
  • Collision detection between game objects
  • Score tracking displayed on screen
  • At least 3 game states (menu, playing, game over)
  • Increasing difficulty (speed, count, or complexity)
  • Clean code organization (classes, functions, constants)
  • At least one polish element (sound effects, particles, transitions, or animations)
  • No crashes -- game handles all edge cases gracefully

Development Workflow

Build your game in phases. Each phase should produce a working (if incomplete) program. Never spend more than 30 minutes without running your code.

Phase 1: Window and Player (30 min) -- Get a window open with a movable player sprite. Arrow key movement, screen boundary clamping. This is your foundation -- if this does not work, nothing else will.

Phase 2: Game Objects (45 min) -- Add enemies, collectibles, or obstacles. Get them spawning and moving. Test collision detection. The game should be "playable" even if rough.

Phase 3: Scoring and Lives (30 min) -- Add the score display, life counter, and the rules that change them. Collisions should now have consequences.

Phase 4: Game States (45 min) -- Add the menu screen, pause, and game over. The player should be able to start a new game without restarting the program.

Phase 5: Difficulty and Polish (60 min) -- Add difficulty scaling. Then choose your polish element: sound effects, particle effects, smooth transitions, or visual flair.

Phase 6: Testing and Debugging (30 min) -- Play your game for real. Find and fix crashes. Edge cases: what happens when score is very high? What if all enemies are dead? What if you pause during a transition?

Common Pitfalls

Scope creep: Your first game should take 4-8 hours. If you are planning features for weeks, you are overscoping. Cut features ruthlessly. A finished simple game teaches more than an unfinished complex one.

Not testing incrementally: If you write 200 lines before running the program, you will have 10 bugs interacting with each other. Run after every 10-20 lines.

Hardcoded values: Put constants (colors, speeds, dimensions) in variables at the top of your file or in a settings module. Magic numbers buried in code are impossible to tune.

Forgetting to handle events: If your game freezes, you probably forgot to call pygame.event.get() in every state. Even the menu and game over screens need event processing.

Starter Template

game_template.py
import pygame
import sys
import random

# ---- Settings ----
WIDTH, HEIGHT = 800, 600
FPS = 60
BG_COLOR = (9, 9, 16)
AMBER = (245, 158, 11)
WHITE = (255, 255, 255)
GREEN = (74, 222, 128)
RED = (239, 68, 68)

MENU, PLAYING, GAME_OVER = "menu", "playing", "game_over"

# ---- Sprite Classes ----
class Player(pygame.sprite.Sprite):
    def __init__(self):
        super().__init__()
        self.image = pygame.Surface((30, 30))
        self.image.fill(AMBER)
        self.rect = self.image.get_rect(center=(WIDTH//2, HEIGHT//2))
        self.speed = 5

    def update(self):
        keys = pygame.key.get_pressed()
        if keys[pygame.K_LEFT]:  self.rect.x -= self.speed
        if keys[pygame.K_RIGHT]: self.rect.x += self.speed
        if keys[pygame.K_UP]:    self.rect.y -= self.speed
        if keys[pygame.K_DOWN]:  self.rect.y += self.speed
        self.rect.clamp_ip(pygame.Rect(0, 0, WIDTH, HEIGHT))

# ---- Game Class ----
class Game:
    def __init__(self):
        pygame.init()
        self.screen = pygame.display.set_mode((WIDTH, HEIGHT))
        pygame.display.set_caption("My Capstone Game")
        self.clock = pygame.time.Clock()
        self.font = pygame.font.Font(None, 48)
        self.small_font = pygame.font.Font(None, 28)
        self.state = MENU
        self.score = 0
        self.setup_sprites()

    def setup_sprites(self):
        self.all_sprites = pygame.sprite.Group()
        self.player = Player()
        self.all_sprites.add(self.player)
        # Add your game objects here

    def run(self):
        while True:
            for event in pygame.event.get():
                if event.type == pygame.QUIT:
                    pygame.quit(); sys.exit()
                self.handle_event(event)

            self.update()
            self.draw()
            pygame.display.flip()
            self.clock.tick(FPS)

    def handle_event(self, event):
        if event.type == pygame.KEYDOWN:
            if self.state == MENU and event.key == pygame.K_RETURN:
                self.state = PLAYING
                self.score = 0
                self.setup_sprites()
            elif self.state == GAME_OVER and event.key == pygame.K_RETURN:
                self.state = MENU

    def update(self):
        if self.state == PLAYING:
            self.all_sprites.update()
            # Add collision checks and game logic here

    def draw(self):
        self.screen.fill(BG_COLOR)
        if self.state == MENU:
            self.draw_centered("YOUR GAME TITLE", HEIGHT//3, self.font, AMBER)
            self.draw_centered("Press ENTER to Start", HEIGHT//2, self.small_font, WHITE)
        elif self.state == PLAYING:
            self.all_sprites.draw(self.screen)
            self.draw_centered(f"Score: {self.score}", 30, self.small_font, WHITE)
        elif self.state == GAME_OVER:
            self.draw_centered("GAME OVER", HEIGHT//3, self.font, RED)
            self.draw_centered(f"Score: {self.score}", HEIGHT//2, self.small_font, WHITE)
            self.draw_centered("Press ENTER", HEIGHT//2 + 50, self.small_font, (140,140,140))

    def draw_centered(self, text, y, font, color):
        surf = font.render(text, True, color)
        self.screen.blit(surf, surf.get_rect(center=(WIDTH//2, y)))

if __name__ == "__main__":
    Game().run()

Submission Checklist

Before considering your capstone complete, verify each item:

  • Game runs without errors from a clean Python environment
  • Game loop maintains 60 FPS
  • All three game states work (menu, playing, game over)
  • Score increases during gameplay
  • Difficulty increases over time
  • Collision detection works reliably
  • Player can restart without closing the program
  • No magic numbers -- constants are named variables
  • Code is organized into classes and functions
  • At least one polish element is present

What Comes Next?

Completing this track gives you the foundation for further game development exploration:

Arcade library: A modern Python game framework with better documentation and simpler API than Pygame. Great for 2D games.

Godot Engine: A full game engine with its own scripting language (GDScript, similar to Python). Handles rendering, physics, audio, and UI out of the box.

Game jams: Ludum Dare, PyWeek, and Global Game Jam give you 48-72 hours to build a game. They force you to scope tightly and finish projects.

Open source: Contribute to existing Python games on GitHub. Reading other people's game code teaches patterns you would never discover alone.

Key Takeaways

  • Plan before coding: define objects, states, rules, and difficulty scaling
  • Build in phases -- each phase produces a working program
  • Test every 10-20 lines, not every 200
  • Use constants and classes for clean organization
  • A finished simple game beats an unfinished complex one
  • Polish (sound, transitions, particles) transforms "homework" into "portfolio"
