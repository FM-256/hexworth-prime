Learning Objectives

  • Define and use structs to group related data
  • Understand unions and when to use them
  • Use typedef for cleaner type names
  • Build a linked list with dynamic allocation

Structs

A struct groups related variables into a single type. In security work, structs model network packet headers, file format structures, and protocol data units. They map directly onto the binary layout of real data.

Defining and using structs
struct Credentials {
char username[64];
char password_hash[65];
int access_level;
};
struct Credentials admin;
strncpy(admin.username, "root", 63);
admin.access_level = 9;
// Pointer to struct -- use arrow operator
struct Credentials *p = &admin;
printf("User: %s\n", p->username);

The dot operator (.) accesses members of a struct value. The arrow operator (->) accesses members through a struct pointer. p->field is shorthand for (*p).field.

typedef

typedef creates an alias for a type, eliminating the need to write struct everywhere. Standard practice in C codebases.

typedef patterns
// Without typedef:
struct Connection conn;
// With typedef:
typedef struct {
int socket_fd;
char remote_ip[16];
uint16_t remote_port;
} Connection;
Connection conn; // No 'struct' keyword needed

Unions

A union stores different types in the same memory location. All members share the same address. The size of a union equals the size of its largest member. Unions are used for type punning -- reinterpreting the same bytes as different types.

Union for IP address representation
typedef union {
uint32_t addr; // 4 bytes as one integer
uint8_t octets[4]; // 4 bytes as array
} IPv4;
IPv4 ip;
ip.addr = 0xC0A80001; // 192.168.0.1
printf("%d.%d.%d.%d\n",
ip.octets[3], ip.octets[2],
ip.octets[1], ip.octets[0]);
// Output: 192.168.0.1

Linked Lists

A linked list is the first dynamic data structure you build in C. Each node contains data and a pointer to the next node. Understanding linked lists is prerequisite for understanding heap exploitation techniques.

Building a linked list
Node *head = create_node(10);
head->next = create_node(20);
head->next->next = create_node(30);
// Traverse and print
Node *curr = head;
while (curr != NULL) {
printf("%d -> ", curr->data);
curr = curr->next;
}
printf("NULL\n");
// Output: 10 -> 20 -> 30 -> NULL
Freeing a linked list
Node *curr = head;
while (curr != NULL) {
Node *tmp = curr->next;
free(curr);
curr = tmp;
}
head = NULL;
Security Relevance: Heap exploitation often targets linked list metadata maintained by malloc/free. Techniques like unlink attacks, fastbin dup, and tcache poisoning all exploit the linked list structures inside the heap allocator. Understanding how linked lists work in C is the first step toward understanding heap exploitation.

Struct Padding and Alignment

Compilers insert padding bytes between struct members to align them on natural boundaries. This affects struct size and is critical when parsing binary protocols or file formats.

Padding example
struct Padded {
char a; // 1 byte + 3 padding
int b; // 4 bytes
char c; // 1 byte + 3 padding
}; // sizeof = 12 (not 6!)
// Reordered to minimize padding:
struct Packed {
int b; // 4 bytes
char a; // 1 byte
char c; // 1 byte + 2 padding
}; // sizeof = 8

Key Takeaways

  • Structs group related data -- use them for packets, headers, and records
  • Use -> for pointer-to-struct access, . for direct access
  • Unions let you interpret the same bytes as different types
  • Linked lists are the foundation for understanding heap exploitation
  • Struct padding affects binary layout -- critical for protocol parsing
