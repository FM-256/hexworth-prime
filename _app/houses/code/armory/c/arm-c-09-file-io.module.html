Opening and Closing Files

C uses FILE* pointers to represent open files. fopen opens a file and returns a pointer. fclose flushes buffers and releases the file handle. Always check the return value -- fopen returns NULL on failure.

fopen modes
"r" Read only. File must exist.
"w" Write only. Creates or truncates.
"a" Append. Creates if needed.
"rb" Read binary.
"wb" Write binary.
"r+" Read and write. Must exist.
"w+" Read and write. Creates or truncates.

Text File Operations

Reading text line by line
FILE *fp = fopen("/etc/passwd", "r");
char line[256];
while (fgets(line, sizeof(line), fp)) {
printf("%s", line);
}
fclose(fp);
Writing text
FILE *fp = fopen("output.txt", "w");
fprintf(fp, "Scan completed: %d hosts\n", count);
fputs("No vulnerabilities found.\n", fp);
fclose(fp);
Character-level I/O
int ch;
while ((ch = fgetc(fp)) != EOF) {
fputc(ch, stdout);
}

Binary File Operations

Binary I/O reads and writes raw bytes -- no character encoding, no newline translation. Essential for parsing file formats, network captures, and firmware images.

fread / fwrite
// Read a binary file header
typedef struct {
uint8_t magic[4];
uint32_t version;
uint32_t data_size;
} FileHeader;
FileHeader hdr;
FILE *fp = fopen("data.bin", "rb");
fread(&hdr, sizeof(FileHeader), 1, fp);
// Write binary data
uint8_t payload[1024];
FILE *out = fopen("output.bin", "wb");
fwrite(payload, 1, sizeof(payload), out);
File seeking
Jump to any position in a file. Critical for parsing binary formats where data is at known offsets.
fseek(fp, 0, SEEK_END); // Go to end
long size = ftell(fp); // Get position = file size
fseek(fp, 0, SEEK_SET); // Back to start
fseek(fp, 512, SEEK_SET); // Jump to offset 512

Error Handling

perror and errno
FILE *fp = fopen("/root/secret.txt", "r");
if (!fp) {
perror("Cannot open file");
// Output: Cannot open file: Permission denied
return 1;
}
// Check for read errors
if (ferror(fp)) {
fprintf(stderr, "Read error occurred\n");
}
Security Note: Always validate file paths and check permissions before operations. Path traversal attacks (e.g., ../../etc/shadow) exploit programs that construct file paths from user input without sanitization. Never use user input directly in fopen without validation.

Standard Streams

C programs have three pre-opened file streams. Understanding them is key for building tools that work with Unix pipes.

stdin, stdout, stderr
stdin -- Standard input (keyboard or piped data)
stdout -- Standard output (terminal or piped output)
stderr -- Standard error (always goes to terminal)
// Read from stdin (works with pipes)
while (fgets(line, sizeof(line), stdin)) { ... }
// Errors to stderr, data to stdout
fprintf(stderr, "[ERROR] %s\n", msg);
fprintf(stdout, "%s\n", result);

Key Takeaways

  • Always check fopen return value -- NULL means failure
  • Use "rb"/"wb" modes for binary data like network captures and firmware
  • fread/fwrite handle raw bytes; fgets/fprintf handle text
  • Always fclose files when done to flush buffers and release handles
  • Never construct file paths from unsanitized user input
