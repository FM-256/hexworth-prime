Learning Objectives

  • Declare and manipulate arrays of any type
  • Understand C strings as null-terminated char arrays
  • Use string.h functions safely
  • Recognize and prevent buffer overflow vulnerabilities

Arrays

An array is a contiguous block of memory holding elements of the same type. C arrays have a fixed size determined at compile time. There is no bounds checking -- accessing beyond the array is undefined behavior (and the basis of buffer overflow attacks).

Array declaration and access
int scores[4] = {95, 87, 92, 78};
int first = scores[0]; // 95 (zero-indexed)
int last = scores[3]; // 78
// Iterate with sizeof
int len = sizeof(scores) / sizeof(scores[0]);
for (int i = 0; i < len; i++) {
printf("%d ", scores[i]);
}
Byte buffers (critical for networking/security)
unsigned char packet[1024];
memset(packet, 0, sizeof(packet)); // Zero-fill
// Hex dump the first 16 bytes
for (int i = 0; i < 16; i++) {
printf("%02x ", packet[i]);
}

C Strings

C does not have a string type. A "string" is just an array of char terminated by a null byte ('\0', value 0x00). Every string function depends on finding this null terminator. If it is missing or overwritten, the function reads past the buffer into adjacent memory.

String representation in memory
char name[] = "root";
// Memory layout:
// [0x72][0x6f][0x6f][0x74][0x00]
// 'r' 'o' 'o' 't' '\0'
// sizeof(name) = 5 (includes null)
// strlen(name) = 4 (excludes null)
Essential string.h functions
strlen(s) // Length (excluding null)
strcmp(a, b) // Compare: 0 if equal
strncmp(a, b, n) // Compare first n chars
strcpy(dst, src) // Copy (UNSAFE!)
strncpy(dst, src, n) // Copy with limit
strcat(dst, src) // Concatenate (UNSAFE!)
strncat(dst, src, n) // Concatenate with limit
strstr(hay, needle) // Find substring
memcpy(dst, src, n) // Copy n bytes (raw)
memset(buf, val, n) // Fill n bytes with val

Buffer Overflow -- The #1 C Vulnerability

Buffer overflows occur when data is written beyond the bounds of a buffer. This is the most exploited class of vulnerabilities in history. Understanding it is essential for both attack and defense.

The classic overflow:
char password[8];
printf("Enter password: ");
gets(password); // NEVER USE gets()!
// No length check -- attacker sends 200 bytes,
// overwrites return address on the stack,
// redirects execution to attacker's shellcode.
Safe alternatives:
char password[64];
// Option 1: fgets (recommended)
fgets(password, sizeof(password), stdin);
// Option 2: scanf with width
scanf("%63s", password);
// Option 3: snprintf for formatted strings
snprintf(buf, sizeof(buf), "User: %s", name);

The rule is simple: every function that writes to a buffer must receive the buffer's size as a parameter. Functions like gets(), strcpy(), and sprintf() take no size argument and are inherently dangerous.

Key Takeaways

  • C arrays are contiguous memory blocks with zero-based indexing and no bounds checking
  • C strings are null-terminated char arrays -- the \0 marks the end
  • Never use gets(), strcpy(), or sprintf() -- use their bounded alternatives
  • Buffer overflow is the most exploited vulnerability class in C programs
