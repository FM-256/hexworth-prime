Fundamental Data Types

Every variable in C has a fixed type that determines how much memory it occupies and how the bits are interpreted. Unlike Python, C does not resize variables automatically -- if you store a value too large for the type, it overflows silently.

TypeSizeRangeFormat
char1 byte-128 to 127 (or 0-255 unsigned)%c / %d
short2 bytes-32,768 to 32,767%hd
int4 bytes-2.1B to 2.1B%d
long4-8 bytesPlatform-dependent%ld
float4 bytes~6 decimal digits precision%f
double8 bytes~15 decimal digits precision%lf / %f
Security Insight: Integer overflow is the root cause of countless CVEs. When an unsigned int at 4,294,967,295 is incremented, it wraps to 0. Attackers exploit this in length checks: if a buffer size calculation overflows, a tiny buffer gets allocated but a huge write occurs.

The sizeof Operator

sizeof returns the size of a type or variable in bytes. It is evaluated at compile time, not runtime. This is essential for portable code and buffer sizing.

sizeof in action
char: 1 bytes
int: 4 bytes
long: 8 bytes
double: 8 bytes

Sizes can vary between platforms. On a 32-bit system, long is 4 bytes. On 64-bit Linux, it is 8 bytes. This is why portable code uses sizeof instead of hardcoded sizes, and why stdint.h provides fixed-width types like int32_t and uint64_t.

printf and scanf

printf outputs formatted text. scanf reads formatted input. Both use format specifiers that must match the variable type exactly.

Common format specifiers
%d int (decimal)
%u unsigned int
%x unsigned int (hexadecimal)
%f float/double
%c char (single character)
%s string (char array)
%p pointer address
%zu size_t (sizeof result)
%ld long int
%02x hex with leading zero, 2 chars wide
Reading user input with scanf
int age;
printf("Enter age: ");
scanf("%d", &age); // & is the address-of operator
Security Warning: scanf("%s", buffer) is dangerous -- it reads until whitespace with no length limit. This is a classic buffer overflow vector. Always use width limits: scanf("%99s", buffer) for a 100-byte buffer (leaving room for the null terminator).

Type Casting

C performs implicit type conversions (promotions) and allows explicit casts. Understanding when and how conversions happen prevents subtle bugs.

Implicit vs explicit casting
// Implicit: int promoted to double
double result = 5 + 3.14; // 8.14
// Explicit: force floating-point division
int a = 7, b = 2;
double d = (double)a / b; // 3.5, not 3
// Dangerous: truncation
int x = (int)3.99; // 3, not 4
// Dangerous: signed/unsigned mismatch
unsigned int u = 0;
u = u - 1; // 4294967295 (wraps!)

Signed/unsigned mismatches are a frequent source of security bugs. When a signed negative number is compared to an unsigned number, the signed value is implicitly converted to unsigned, potentially making -1 appear as a very large positive number.

Fixed-Width Types (stdint.h)

For security and networking code where exact sizes matter, use the types from <stdint.h>:

int8_t / uint8_t Exactly 1 byte. Perfect for byte-level operations, packet parsing.
int16_t / uint16_t Exactly 2 bytes. Network port numbers, protocol fields.
int32_t / uint32_t Exactly 4 bytes. IPv4 addresses, file offsets.
int64_t / uint64_t Exactly 8 bytes. Timestamps, large counters, crypto.

Key Takeaways

  • C has fixed-size types -- int is 4 bytes, char is 1 byte
  • Integer overflow wraps silently -- a major source of security vulnerabilities
  • Always match printf/scanf format specifiers to variable types
  • Use stdint.h for exact-width types in security and networking code
