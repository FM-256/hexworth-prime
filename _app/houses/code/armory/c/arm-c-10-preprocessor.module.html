Learning Objectives

  • Use #define for constants and function-like macros
  • Write include guards for header files
  • Use conditional compilation for debug/release and cross-platform code
  • Build multi-file projects with Makefiles

The Preprocessor

The C preprocessor runs before the compiler. It handles directives that start with # -- text substitution, file inclusion, and conditional compilation. Preprocessor output is pure C code with no directives remaining. You can see the output with gcc -E.

#define Constants and Macros

Object-like macros (constants)
#define PORT 8080
#define MAX_PATH 4096
#define AUTHOR "HexTeam"
// Usage -- preprocessor replaces the name with the value
char buf[MAX_PATH];
listen(sock, PORT);
Function-like macros
#define SQUARE(x) ((x) * (x))
#define ABS(x) ((x) < 0 ? -(x) : (x))
#define ARRAY_LEN(a) (sizeof(a) / sizeof((a)[0]))
int arr[] = {1,2,3,4,5};
int len = ARRAY_LEN(arr); // 5
Macro Pitfall: Always parenthesize macro arguments. Without parentheses, SQUARE(1+2) expands to 1+2 * 1+2 = 5 instead of (1+2) * (1+2) = 9. This is a common source of subtle bugs.

#include and Include Guards

#include <file> searches system paths. #include "file" searches the current directory first. Include guards prevent a header from being processed twice, which would cause duplicate definition errors.

Include guard pattern
#ifndef MYHEADER_H // If not defined yet...
#define MYHEADER_H // ...define it (marks as included)
// Header contents here
void do_something(void);
#endif // End of guard
// Modern alternative (non-standard but widely supported):
#pragma once

Conditional Compilation

Conditional directives include or exclude code based on compile-time conditions. This is how you write code that works on multiple platforms or has debug/release modes.

Debug mode via command line
$ gcc -DDEBUG program.c -o program_debug
$ gcc program.c -o program_release
// In code:
#ifdef DEBUG
printf("[DEBUG] ptr = %p, val = %d\n", ptr, *ptr);
#endif
Predefined macros (useful for security tools)
__FILE__ // Current source file name
__LINE__ // Current line number
__func__ // Current function name
__DATE__ // Compilation date
__TIME__ // Compilation time
// Error reporting macro:
#define DIE(msg) do { \
fprintf(stderr, "FATAL [%s:%d] %s\n", \
__FILE__, __LINE__, msg); \
exit(1); \
} while(0)

Makefiles

For projects with multiple files, a Makefile automates the build process. Make only recompiles files that changed, saving time on large projects.

Basic Makefile
CC = gcc
CFLAGS = -Wall -Wextra -std=c11 -g
TARGET = scanner
SRCS = main.c network.c parser.c
OBJS = $(SRCS:.c=.o)
$(TARGET): $(OBJS)
$(CC) $(OBJS) -o $(TARGET)
%.o: %.c
$(CC) $(CFLAGS) -c $< -o $@
clean:
rm -f $(OBJS) $(TARGET)
debug: CFLAGS += -DDEBUG
debug: $(TARGET)
Using make
$ make # Build the project
$ make clean # Remove built files
$ make debug # Build with debug mode

Security Hardening Flags

Modern compilers and linkers provide security features that make exploitation harder. Always enable these in production builds.

Hardened compilation
$ gcc -Wall -Wextra -Werror \
-fstack-protector-strong \ # Stack canaries
-D_FORTIFY_SOURCE=2 \ # Buffer overflow detection
-pie -fPIE \ # Position-independent (ASLR)
-Wl,-z,relro,-z,now \ # Full RELRO (GOT protection)
-Wl,-z,noexecstack \ # Non-executable stack
-o program program.c

These flags enable stack canaries, ASLR, RELRO, and NX -- the four pillars of modern binary protection. Understanding what each one does is essential for both hardening your code and understanding exploit mitigations during penetration testing.

Key Takeaways

  • #define creates text substitutions -- always parenthesize macro arguments
  • Include guards prevent double-inclusion of headers
  • Conditional compilation enables debug/release modes and cross-platform code
  • Makefiles automate multi-file builds with incremental compilation
  • Security hardening flags (stack protector, ASLR, RELRO, NX) are mandatory for production C code
