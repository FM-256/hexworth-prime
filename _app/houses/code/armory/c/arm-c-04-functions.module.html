Learning Objectives

  • Write functions with prototypes and definitions

Function Anatomy

Every C function has a return type, a name, parameters, and a body. If a function is called before it is defined, you need a prototype (forward declaration) so the compiler knows the function's signature.

Prototype vs Definition
// Prototype (declaration) -- tells compiler the signature
int add(int a, int b);
// Definition (implementation) -- contains the body
int add(int a, int b) {
return a + b;
}
// void = no return value
void log_event(const char *msg) {
fprintf(stderr, "[LOG] %s\n", msg);
}

Pass by Value

C passes arguments by value -- the function receives a copy. Modifying the parameter inside the function does not affect the caller's variable. To modify the caller's data, you pass a pointer (covered in Module C-06).

Value copy in action
void double_it(int n) {
n = n * 2; // Modifies local copy only
}
int val = 5;
double_it(val);
printf("%d\n", val); // Still 5!
To modify the original: pass a pointer
void double_it(int *n) {
*n = *n * 2; // Dereference: modify the value at the address
}
int val = 5;
double_it(&val); // Pass address of val
printf("%d\n", val); // 10

Header Files

Header files (.h) contain function prototypes, type definitions, and constants. They let multiple .c files share declarations without duplicating code. This is how real C projects are organized.

crypto.h -- header file
#ifndef CRYPTO_H
#define CRYPTO_H
// Function prototypes
void xor_encrypt(unsigned char *data, int len, unsigned char key);
void xor_decrypt(unsigned char *data, int len, unsigned char key);
void hex_dump(const unsigned char *data, int len);
#endif
crypto.c -- implementation
#include <stdio.h>
#include "crypto.h"
void xor_encrypt(unsigned char *data, int len, unsigned char key) {
for (int i = 0; i < len; i++) {
data[i] ^= key;
}
}
Compiling multi-file projects
$ gcc -Wall -c main.c -o main.o
$ gcc -Wall -c crypto.c -o crypto.o
$ gcc main.o crypto.o -o program
# Or all at once:
$ gcc -Wall main.c crypto.c -o program

The #ifndef / #define / #endif pattern is called an include guard. It prevents the header from being included multiple times, which would cause duplicate definition errors.

Variable Scope & Lifetime

Scope rules
// Global -- visible everywhere, lives for entire program
int global_count = 0;
void example(void) {
// Local -- visible only in this function
int local = 42;
// Static local -- persists between calls
static int call_count = 0;
call_count++;
{
// Block scope -- only visible inside braces
int temp = 99;
}
// temp is not accessible here
}
Security Note: Global variables in C are initialized to zero. Local variables are NOT -- they contain whatever was previously on the stack. Uninitialized local variables can leak sensitive data from previous function calls. Always initialize your variables.

Key Takeaways

  • Functions need prototypes if called before their definition
  • C passes arguments by value -- the function gets a copy
  • Header files share declarations across multiple .c files
  • Include guards prevent duplicate definitions
  • Local variables are uninitialized -- always set a value before use
