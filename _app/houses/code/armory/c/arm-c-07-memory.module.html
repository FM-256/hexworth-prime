Learning Objectives

  • Understand heap vs stack memory
  • Use malloc, calloc, realloc, and free correctly
  • Recognize memory leaks and use-after-free bugs
  • Run Valgrind to detect memory errors

Stack vs Heap

C programs use two regions of memory. The stack is automatic -- local variables are pushed when a function is called and popped when it returns. The heap is manual -- you allocate with malloc and release with free. Heap memory persists until explicitly freed.

Stack Automatic, fast, limited size (~8MB default). Local variables, function arguments, return addresses.
Heap Manual, larger, slower. Dynamic allocations via malloc/calloc. Must be freed or memory leaks.

The Allocation Functions

malloc(size)
Allocates size bytes. Memory is NOT initialized -- contains random data from previous allocations. Returns NULL on failure.
int *p = malloc(100 * sizeof(int));
if (!p) { perror("malloc"); exit(1); }
calloc(count, size)
Allocates count * size bytes and zero-initializes all of them. Safer than malloc for buffers that must start clean.
char *buf = calloc(1024, 1); // 1024 zero bytes
realloc(ptr, new_size)
Resizes an existing allocation. May move the data to a new address. Returns NULL on failure (original is still valid).
int *tmp = realloc(arr, new_size * sizeof(int));
if (!tmp) { free(arr); exit(1); }
arr = tmp;
free(ptr)
Releases memory back to the system. Always set the pointer to NULL after freeing to prevent use-after-free.
free(arr);
arr = NULL; // Critical: prevent dangling pointer

Memory Bugs

Memory Leak: Allocated memory that is never freed. The program's memory usage grows until it crashes or the OS kills it.
while (1) {
char *p = malloc(1024);
// Never freed -- 1KB leaked per iteration
}
Use-After-Free: Accessing memory after it has been freed. The data may have been overwritten by a new allocation. This is a critical vulnerability class -- attackers can control what gets allocated in the freed slot.
char *secret = malloc(64);
strcpy(secret, "password123");
free(secret);
printf("%s\n", secret); // UAF: undefined behavior!
Double Free: Freeing the same pointer twice corrupts the heap metadata and can lead to arbitrary code execution.
free(ptr);
free(ptr); // CRASH or exploitable!

Valgrind -- The Memory Debugger

Valgrind instruments your program to detect memory errors at runtime. It catches leaks, use-after-free, double free, uninitialized reads, and buffer overflows.

Running Valgrind
$ gcc -g -o program program.c
$ valgrind --leak-check=full ./program
==12345== HEAP SUMMARY:
==12345== in use at exit: 0 bytes in 0 blocks
==12345== total heap usage: 3 allocs, 3 frees
==12345== All heap blocks were freed
==12345== ERROR SUMMARY: 0 errors from 0 contexts

Compile with -g so Valgrind can show line numbers. A clean Valgrind report ("0 errors, all blocks freed") is the gold standard for C programs.

Key Takeaways

  • Stack is automatic; heap requires manual malloc/free
  • Always check malloc's return value -- NULL means failure
  • Set pointers to NULL after free to prevent use-after-free
  • Memory leaks, UAF, and double-free are critical vulnerability classes
  • Valgrind is your best friend for finding memory bugs
