Learning Objectives

  • Understand what a pointer is and how memory addressing works
  • Use the address-of (&) and dereference (*) operators
  • Perform pointer arithmetic on arrays
  • Recognize dangling pointers and NULL pointer risks

What is a Pointer?

A pointer is a variable that stores a memory address. Instead of holding data directly, it holds the location where data lives. This is the core concept that makes C powerful -- and dangerous. Every exploit that overwrites a return address, function pointer, or vtable pointer depends on understanding this.

The two pointer operators
int x = 42;
int *p = &x; // & = address-of: p stores where x lives
int v = *p; // * = dereference: read the value at that address
// Memory visualization:
// Address Value
// 0x1000 42 <-- x lives here
// 0x1008 0x1000 <-- p stores x's address

On a 64-bit system, all pointers are 8 bytes (64 bits), regardless of what they point to. A char* is the same size as an int* -- both store an address. The type tells the compiler how many bytes to read/write when you dereference.

Pointer Arithmetic

When you add 1 to a pointer, it advances by sizeof(pointed_type) bytes, not by 1 byte. This is how you traverse arrays using pointers instead of indices.

Pointer arithmetic is type-aware
int arr[] = {10, 20, 30};
int *p = arr;
// p points to arr[0] at address 0x1000
// p+1 points to arr[1] at address 0x1004 (+4 bytes)
// p+2 points to arr[2] at address 0x1008 (+8 bytes)
// These are equivalent:
arr[i] == *(arr + i)
&arr[i] == arr + i
Walking a byte buffer
For security tools, you often walk raw bytes. Use unsigned char* for byte-level access:
unsigned char *byte_ptr = (unsigned char *)arr;
// Now byte_ptr + 1 advances by 1 byte
// You can inspect each byte of the int array
for (int i = 0; i < sizeof(arr); i++) {
printf("%02x ", byte_ptr[i]);
}

Arrays and Pointers

In most contexts, an array name decays to a pointer to its first element. This is why you can pass an array to a function that expects a pointer. But arrays and pointers are not identical -- sizeof(array) gives the total array size, while sizeof(pointer) gives 8 (on 64-bit).

Passing arrays to functions
// These two declarations are equivalent:
void process(int arr[], int len);
void process(int *arr, int len);
// Inside the function, arr is a pointer.
// sizeof(arr) == 8, NOT the array size!
// That's why you must pass len separately.

Dangerous Pointers

NULL pointer dereference: Accessing memory at address 0. Causes a segfault. Always check for NULL before dereferencing.
int *p = NULL;
*p = 42; // CRASH: segmentation fault
// Always check:
if (p != NULL) { *p = 42; }
Dangling pointer: Points to freed or out-of-scope memory. The address is valid but the data is gone.
int *bad_function(void) {
int local = 42;
return &local; // DANGER: local is destroyed on return!
}
Wild pointer: Uninitialized pointer -- points to random memory.
int *p; // Uninitialized -- contains garbage address
*p = 42; // Writing to random memory -- catastrophic
// Always initialize:
int *p = NULL;

Pointers in Security

Pointers are central to exploit development. Buffer overflows overwrite pointers on the stack. Use-after-free bugs exploit dangling pointers. Format string attacks use pointer values for arbitrary reads and writes. Understanding pointers is understanding the attack surface of every C program.

Key Takeaways

  • & gets an address, * dereferences (reads/writes the value at the address)
  • Pointer arithmetic steps by sizeof(type) bytes, not 1 byte
  • NULL, dangling, and wild pointers are all sources of crashes and vulnerabilities
  • Pointer manipulation is the foundation of exploit development and reverse engineering
