Control Flow & Functions

< Swift / Kotlin Track

Learning Objectives

  • Use if/else, Swift switch, and Kotlin when expressions for branching
  • Write for and while loops with ranges and collections
  • Define functions with parameters, return types, and default arguments
  • Write closures in Swift and lambdas in Kotlin as first-class values
  • Use Kotlin extension functions to add behavior to existing types

Conditionals

Both languages support standard if/else. Swift's switch and Kotlin's when are especially powerful -- they can match ranges, types, and arbitrary expressions with no fall-through by default.

swift -- switch
let statusCode = 403

switch statusCode {
case 200:
    print("OK")
case 401:
    print("Unauthorized")
case 403:
    print("Forbidden")
case 500..<600:
    print("Server error")
default:
    print("Unknown: \(statusCode)")
}
kotlin -- when
val statusCode = 403

when (statusCode) {
    200 -> println("OK")
    401 -> println("Unauthorized")
    403 -> println("Forbidden")
    in 500..599 ->
        println("Server error")
    else ->
        println("Unknown: $statusCode")
}

Loops

swift -- loops
// Closed range 1 through 5
for i in 1...5 {
    print(i)
}

// Half-open range 0 through 4
for i in 0..<5 {
    print(i)
}

// Stride with step
for i in stride(from: 0, to: 10, by: 2) {
    print(i) // 0 2 4 6 8
}

// while loop
var attempt = 0
while attempt < 3 {
    attempt += 1
}
kotlin -- loops
// Closed range 1 through 5
for (i in 1..5) {
    println(i)
}

// Until (exclusive end)
for (i in 0 until 5) {
    println(i)
}

// Step
for (i in 0..10 step 2) {
    println(i) // 0 2 4 6 8 10
}

// while loop
var attempt = 0
while (attempt < 3) {
    attempt++
}

Functions

Functions are first-class values in both languages. Swift uses argument labels for readable call sites. Kotlin supports default parameter values and named arguments natively.

swift -- functions
// External label, internal name
func connect(to host: String,
              port: Int = 443) -> Bool {
    print("Connecting to \(host):\(port)")
    return true
}

// Call reads like English
connect(to: "api.hexworth.io")
connect(to: "api.hexworth.io", port: 8080)

// Multiple return values via tuple
func status() -> (code: Int, msg: String) {
    return (200, "OK")
}
let (code, msg) = status()
kotlin -- functions
// Default parameters
fun connect(host: String,
             port: Int = 443): Boolean {
    println("Connecting to $host:$port")
    return true
}

// Named arguments at call site
connect("api.hexworth.io")
connect(host = "api.hexworth.io", port = 8080)

// Pair as multiple return
fun status(): Pair<Int, String> {
    return Pair(200, "OK")
}
val (code, msg) = status()

Closures & Lambdas

Both languages treat functions as first-class values that can be passed, stored, and returned. Swift calls them closures; Kotlin calls them lambdas. The syntax differs but the concept is identical.

swift -- closures
// Full closure syntax
let square: (Int) -> Int = { n in
    return n * n
}

// Shorthand -- $0 is first arg
let doubled: (Int) -> Int = { $0 * 2 }

// Trailing closure syntax
let nums = [3, 1, 4, 1, 5]
let sorted = nums.sorted { $0 < $1 }
print(sorted) // [1, 1, 3, 4, 5]
kotlin -- lambdas
// Lambda with explicit type
val square: (Int) -> Int = { n -> n * n }

// Shorthand -- 'it' is single arg
val doubled: (Int) -> Int = { it * 2 }

// Trailing lambda syntax
val nums = listOf(3, 1, 4, 1, 5)
val sorted = nums.sortedBy { it }
println(sorted) // [1, 1, 3, 4, 5]

Kotlin Extension Functions

Kotlin lets you add new functions to existing types without subclassing. Swift achieves the same through extensions. Both are core to idiomatic code in each language.

swift -- extensions
// Add a method to String
extension String {
    var isValidEmail: Bool {
        return self.contains("@")
            && self.contains(".")
    }
}

let email = "user@example.com"
print(email.isValidEmail) // true
kotlin -- extensions
// Add a function to String
fun String.isValidEmail(): Boolean {
    return contains("@")
        && contains(".")
}

val email = "user@example.com"
println(email.isValidEmail()) // true

Try It Yourself

Write the following in your language of choice (or both):

  1. A function that takes an HTTP status code Int and returns the status category string ("success", "redirect", "client error", "server error")
  2. A closure/lambda that takes a String and returns it reversed
  3. A for loop that prints only even numbers from 1 to 20
  4. An extension on Int that returns true if the number is prime

Key Takeaways

  • Swift switch and Kotlin when support pattern matching with ranges -- no fall-through by default
  • Both support half-open ranges, stride/step loops, and while loops
  • Swift uses external argument labels for readable call sites; Kotlin uses named arguments
  • Closures (Swift) and lambdas (Kotlin) are identical concepts -- functions as values
  • Extensions let you add methods to types you do not own, without subclassing
