Declarative UI: The Core Concept

Traditional mobile UIs were imperative -- you told the system exactly how to mutate the UI. Declarative UIs describe what the UI should look like for a given state, and the framework handles updates. Both SwiftUI and Jetpack Compose share this model.

SwiftUI Apple's declarative framework (iOS 13+). Views are structs. The body property returns a description of the view for the current state.
Jetpack Compose Google's declarative toolkit (stable since 2021). Composable functions are annotated with @Composable. State drives recomposition automatically.

First View

swiftui
import SwiftUI

// Views are structs conforming to View
struct LoginView: View {
    var body: some View {
        VStack(spacing: 16) {
            Text("Hexworth Prime")
                .font(.largeTitle)
                .fontWeight(.bold)

            Text("Sign in to continue")
                .foregroundColor(.secondary)

            Button("Login") {
                // action here
            }
            .buttonStyle(.borderedProminent)
        }
        .padding()
    }
}
jetpack compose
import androidx.compose.material3.*
import androidx.compose.runtime.*

// Composable functions build the UI
@Composable
fun LoginView() {
    Column(
        verticalArrangement = Arrangement.spacedBy(16.dp)
    ) {
        Text(
            "Hexworth Prime",
            style = MaterialTheme.typography.headlineLarge
        )
        Text(
            "Sign in to continue",
            color = MaterialTheme.colorScheme.secondary
        )
        Button(onClick = { /* action */ }) {
            Text("Login")
        }
    }
}

State Management

When state changes, the framework automatically re-renders only the affected parts of the UI. In SwiftUI, @State is the simplest state primitive for view-local data. In Compose, remember { mutableStateOf() } does the same job.

swiftui -- @State
struct CounterView: View {
    // @State = view-local reactive state
    @State private var count = 0
    @State private var username = ""

    var body: some View {
        VStack {
            Text("Count: \(count)")
                .font(.title)

            TextField("Username", text: $username)
                .textFieldStyle(.roundedBorder)

            Button("Increment") {
                count += 1
            }
        }.padding()
    }
}
compose -- remember
@Composable
fun CounterView() {
    // remember = survives recomposition
    var count by remember {
        mutableStateOf(0)
    }
    var username by remember {
        mutableStateOf("")
    }

    Column(modifier = Modifier.padding(16.dp)) {
        Text("Count: $count",
             style = MaterialTheme.typography.headlineSmall)
        OutlinedTextField(
            value = username,
            onValueChange = { username = it },
            label = { Text("Username") }
        )
        Button(onClick = { count++ }) {
            Text("Increment")
        }
    }
}

Lists & Navigation

swiftui -- list + navigationstack
struct HostListView: View {
    let hosts = ["10.0.0.1", "10.0.0.2",
                  "10.0.0.3"]

    var body: some View {
        NavigationStack {
            List(hosts, id: \.self) { host in
                NavigationLink(host) {
                    HostDetailView(ip: host)
                }
            }
            .navigationTitle("Network Hosts")
        }
    }
}
compose -- lazycolumn + nav
@Composable
fun HostListView(
    navController: NavController
) {
    val hosts = listOf("10.0.0.1",
        "10.0.0.2", "10.0.0.3")

    LazyColumn {
        items(hosts) { host ->
            ListItem(
                headlineContent = { Text(host) },
                modifier = Modifier.clickable {
                    navController.navigate(
                        "detail/$host")
                }
            )
        }
    }
}

  3. Color-code each row based on severity: green/yellow/red

Key Takeaways

  • Declarative UI describes what to show for a given state; the framework decides how to update
  • SwiftUI views are structs with a body property; Compose uses @Composable functions
  • @State (SwiftUI) and remember { mutableStateOf() } (Compose) create reactive local state
  • SwiftUI uses VStack/HStack/ZStack; Compose uses Column/Row/Box for layout
  • Both support lazy-loading long lists: List (SwiftUI) and LazyColumn (Compose)
