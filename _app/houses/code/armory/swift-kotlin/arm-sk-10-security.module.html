Keychain (iOS) & Keystore (Android)

Never store tokens, passwords, or cryptographic keys in UserDefaults, SharedPreferences, or plain files. The OS-provided secure storage systems (Keychain and Keystore) use hardware-backed encryption and are isolated per app.

Attack: Insecure Storage

Data stored in UserDefaults or SharedPreferences is readable by any process with filesystem access on a rooted/jailbroken device. Tokens stored there can be extracted in seconds with a file manager.

swift -- keychain wrapper
import Security

enum Keychain {
    static let service = "io.hexworth.app"

    static func save(key: String,
                        value: String) {
        guard let data = value.data(
            using: .utf8) else { return }
        let query: [CFString: Any] = [
            kSecClass: kSecClassGenericPassword,
            kSecAttrService: service,
            kSecAttrAccount: key,
            kSecValueData: data,
            // Accessible only when unlocked
            kSecAttrAccessible:
                kSecAttrAccessibleWhenUnlocked
        ]
        SecItemDelete(query as CFDictionary)
        SecItemAdd(query as CFDictionary, nil)
    }

    static func load(key: String) -> String? {
        let query: [CFString: Any] = [
            kSecClass: kSecClassGenericPassword,
            kSecAttrService: service,
            kSecAttrAccount: key,
            kSecReturnData: true
        ]
        var result: AnyObject?
        SecItemCopyMatching(
            query as CFDictionary, &result)
        guard let data = result as? Data
        else { return nil }
        return String(data: data, encoding: .utf8)
    }
}
kotlin -- encrypted datastore
import androidx.security.crypto.*

// EncryptedSharedPreferences backed by Keystore
val masterKey = MasterKey.Builder(context)
    .setKeyScheme(MasterKey.KeyScheme.AES256_GCM)
    .build()

val securePrefs = EncryptedSharedPreferences
    .create(
        context,
        "secure_prefs",
        masterKey,
        EncryptedSharedPreferences
            .PrefKeyEncryptionScheme.AES256_SIV,
        EncryptedSharedPreferences
            .PrefValueEncryptionScheme.AES256_GCM
    )

// Use like regular SharedPreferences
securePrefs.edit()
    .putString("auth_token", "eyJhbGci...")
    .apply()

val token = securePrefs.getString(
    "auth_token", null)

Biometric Authentication

Biometrics (Face ID, Touch ID, fingerprint) provide strong local authentication without transmitting credentials. The OS handles the biometric check and returns a success/failure result to your app.

swift -- face id / touch id
import LocalAuthentication

func authenticate() async -> Bool {
    let context = LAContext()
    var error: NSError?

    // Check biometric availability
    guard context.canEvaluatePolicy(
        .deviceOwnerAuthenticationWithBiometrics,
        error: &error) else {
        print("No biometrics: \(error!)")
        return false
    }

    do {
        return try await context
            .evaluatePolicy(
                .deviceOwnerAuthenticationWithBiometrics,
                localizedReason: "Unlock Hexworth")
    } catch {
        return false
    }
}
kotlin -- biometricprompt
import androidx.biometric.*

fun showBiometricPrompt(activity: FragmentActivity) {
    val executor = ContextCompat
        .getMainExecutor(activity)

    val prompt = BiometricPrompt(
        activity, executor,
        object : BiometricPrompt.AuthenticationCallback() {
            override fun onAuthenticationSucceeded(
                result: BiometricPrompt.AuthenticationResult
            ) {
                unlockApp()
            }
            override fun onAuthenticationError(
                code: Int, msg: CharSequence
            ) { /* handle error */ }
        })

    val info = BiometricPrompt.PromptInfo.Builder()
        .setTitle("Unlock Hexworth")
        .setNegativeButtonText("Cancel")
        .build()

    prompt.authenticate(info)
}

Certificate Pinning

Certificate pinning forces your app to only trust a specific server certificate or public key. This defeats MITM attacks even when the attacker installs their own CA certificate on the device (a common corporate MDM vector).

swift -- cert pinning
// Implement URLSessionDelegate
class PinnedSession: NSObject,
    URLSessionDelegate {

    // SHA-256 hash of server public key
    let pinnedHash =
        "sha256/AAAAAABBBBBBCCCCCC..."

    func urlSession(_:,
        didReceive challenge:
        URLAuthenticationChallenge,
        completionHandler: @escaping
        (URLSession.AuthChallengeDisposition,
        URLCredential?) -> Void) {

        guard let serverTrust =
            challenge.protectionSpace.serverTrust,
            isValid(serverTrust) else {
            completionHandler(.cancelAuthenticationChallenge,
                nil)
            return
        }
        completionHandler(.useCredential,
            URLCredential(trust: serverTrust))
    }
}

App Hardening Checklist

iOS Hardening

  • Enable App Transport Security (ATS) -- enforce HTTPS for all connections
  • Check for jailbreak: look for Cydia, altered sandbox, writable /Applications
  • Use kSecAttrAccessibleWhenUnlockedThisDeviceOnly to bind Keychain items to the device
  • Enable Data Protection entitlement for encrypted file storage at rest
  • Validate code signature with hardened runtime flag enabled

Android Hardening

  • Set android:allowBackup="false" in Manifest to prevent backup extraction
  • Use SafetyNet / Play Integrity API for root detection
  • Enable android:usesCleartextTraffic="false" -- enforce TLS only
  • Encrypt the database with SQLCipher or Room encryption
  • Use FLAG_SECURE on sensitive Activities to prevent screenshots

Code Signing: iOS apps are signed with a Developer Certificate and provisioning profile. Android APKs/AABs are signed with a keystore. The OS verifies the signature on install and rejects modified binaries. Never share your signing keys -- treat them as root CA private keys.

Try It Yourself

Build a minimal secure token vault:

  1. Write a Keychain/EncryptedSharedPreferences wrapper with save(key:value:) and load(key:) methods
  2. Add a biometric gate: only allow load() to succeed after successful biometric auth
  3. Add a delete(key:) method and a clear() that wipes all stored items
  4. Write a test that verifies a saved token is not retrievable as plaintext from the standard prefs file

Key Takeaways

  • Keychain (iOS) and EncryptedSharedPreferences/Keystore (Android) are the only acceptable stores for tokens and credentials
  • Biometric auth uses hardware-isolated secure enclaves -- the app never sees the fingerprint or face data
  • Certificate pinning eliminates MITM attacks that exploit rogue CA certificates on managed devices
  • Set accessibility attributes (kSecAttrAccessibleWhenUnlocked, ThisDeviceOnly) to minimize exposure windows
  • Treat code signing keys with the same discipline as infrastructure private keys -- rotate on compromise, back up securely
