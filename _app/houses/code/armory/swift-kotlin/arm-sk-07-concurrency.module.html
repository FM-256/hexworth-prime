async / await

Both languages use async/await to write asynchronous code that reads like sequential code. The runtime suspends the function at each await point without blocking a thread -- crucial for responsive mobile UIs.

swift -- async/await
// Mark the function async
func fetchToken() async throws -> String {
    let url = URL(string: "https://api/token")!
    let (data, _) = try await
        URLSession.shared.data(from: url)
    return String(data: data, encoding: .utf8)!
}

// Call with await in an async context
func loadDashboard() async {
    do {
        let token = try await fetchToken()
        print("Token: \(token)")
    } catch {
        print("Failed: \(error)")
    }
}
kotlin -- coroutines
// suspend = Kotlin's async equivalent
suspend fun fetchToken(): String {
    val response = withContext(Dispatchers.IO) {
        // Network call on IO dispatcher
        URL("https://api/token")
            .readText()
    }
    return response
}

// Launch in a coroutine scope
fun loadDashboard() {
    viewModelScope.launch {
        try {
            val token = fetchToken()
            println("Token: $token")
        } catch (e: Exception) {
            println("Failed: ${e.message}")
        }
    }
}

Parallel Work

When two operations are independent, run them in parallel to cut total latency. Swift uses async let. Kotlin uses async { } returning Deferred values, then await().

swift -- async let
func loadProfile() async throws {
    // Both start immediately in parallel
    async let user = fetchUser(id: 42)
    async let perms = fetchPermissions(id: 42)

    // Await both results together
    let (u, p) = try await (user, perms)
    print("User: \(u.name), perms: \(p)")
}
kotlin -- async/await
suspend fun loadProfile() {
    coroutineScope {
        // Both start immediately in parallel
        val userDeferred = async {
            fetchUser(42)
        }
        val permsDeferred = async {
            fetchPermissions(42)
        }
        // Await both results
        val u = userDeferred.await()
        val p = permsDeferred.await()
        println("User: ${u.name}, perms: $p")
    }
}

Thread Safety: Actors & Dispatchers

Swift actors guarantee that only one task accesses their mutable state at a time -- the compiler enforces this. Kotlin uses dispatchers to control which thread pool runs a coroutine: Main for UI, IO for network/disk, Default for CPU work.

swift -- actor
// actor = thread-safe class
actor TokenStore {
    private var token: String?

    func set(_ value: String) {
        token = value
    }

    func get() -> String? {
        return token
    }
}

let store = TokenStore()
// Must await to access actor state
await store.set("eyJhbGci...")
let t = await store.get()
kotlin -- dispatchers
suspend fun loadAndDisplay() {
    // IO dispatcher: network / disk
    val data = withContext(Dispatchers.IO) {
        fetchFromNetwork()
    }

    // Default: CPU-intensive work
    val parsed = withContext(Dispatchers.Default) {
        parseJson(data)
    }

    // Main: update UI
    withContext(Dispatchers.Main) {
        updateUI(parsed)
    }
}

Rule: Never block the main thread. Network calls, file I/O, and heavy computation must run off the UI thread. Swift async functions and Kotlin coroutines with proper dispatchers enforce this pattern.

Structured Concurrency

Structured concurrency means child tasks cannot outlive their parent. If a parent scope is cancelled (navigation, timeout, user action), all child tasks are automatically cancelled. This prevents dangling work and resource leaks.

swift -- task groups
func scanPorts(_ ports: [Int])
        async -> [Int] {
    var open = [Int]()
    await withTaskGroup(of: Int?.self) { group in
        for port in ports {
            group.addTask {
                await probe(port: port)
            }
        }
        for await result in group {
            if let p = result { open.append(p) }
        }
    }
    return open
}
kotlin -- structured scope
suspend fun scanPorts(ports: List<Int>)
    : List<Int> = coroutineScope {
    ports
        .map { port ->
            // Each port probed concurrently
            async { probe(port) }
        }
        .awaitAll()
        .filterNotNull()
} // All tasks cancelled if scope ends

Try It Yourself

Simulate an async login flow:

  1. Write a suspend fun (or async func) that simulates a 500ms network delay and returns a token string
  2. Write a second function that fetches the user profile using the token
  3. Run both sequentially and measure time, then run in parallel and compare
  4. Wrap in proper error handling so any failure surfaces a useful message

Key Takeaways

  • Swift async/await and Kotlin suspend/coroutines write async code that reads sequentially
  • Use async let (Swift) or async { } (Kotlin) to run independent work in parallel
  • Swift actors provide compile-time-enforced thread safety for mutable state
  • Kotlin dispatchers route coroutines to the correct thread pool: IO, Default, or Main
  • Structured concurrency ensures cancellation propagates to all child tasks automatically
