Error Handling

< Swift / Kotlin Track

Learning Objectives

  • Define and throw custom errors in Swift and Kotlin
  • Use do/try/catch (Swift) and try/catch (Kotlin) for error recovery
  • Use Result types to represent success or failure as a value
  • Apply optional chaining and guard let for safe access patterns

Custom Error Types

Typed errors make failure modes explicit and exhaustively handled. Swift errors conform to the Error protocol. Kotlin uses a class hierarchy -- the Exception class or custom sealed classes for domain errors.

swift -- error enum
enum AuthError: Error {
    case invalidCredentials
    case tokenExpired
    case rateLimited(retryAfter: Int)
    case serverUnavailable
}

func login(user: String,
            pass: String) throws -> String {
    guard user == "admin" else {
        throw AuthError.invalidCredentials
    }
    return "eyJhbGci..."
}
kotlin -- custom exception
sealed class AuthError(val msg: String)
    : Exception(msg) {
    object InvalidCredentials
        : AuthError("Invalid credentials")
    object TokenExpired
        : AuthError("Token expired")
    class RateLimited(val retryAfter: Int)
        : AuthError("Rate limited")
}

fun login(user: String, pass: String): String {
    if (user != "admin")
        throw AuthError.InvalidCredentials
    return "eyJhbGci..."
}

do/try/catch

swift
do {
    let token = try login(user: "hacker",
                              pass: "wrong")
    print("Token: \(token)")
} catch AuthError.invalidCredentials {
    print("Bad credentials")
} catch AuthError.rateLimited(let retry) {
    print("Retry in \(retry)s")
} catch {
    // Generic fallback
    print("Error: \(error)")
}
kotlin
try {
    val token = login("hacker", "wrong")
    println("Token: $token")
} catch (e: AuthError.InvalidCredentials) {
    println("Bad credentials")
} catch (e: AuthError.RateLimited) {
    println("Retry in ${e.retryAfter}s")
} catch (e: Exception) {
    // Generic fallback
    println("Error: ${e.message}")
} finally {
    // Always runs
    println("Login attempt logged")
}

Result Types

Result wraps either a success value or a failure error into a single type. This is powerful for async work and APIs where callers must handle both paths without try/catch boilerplate.

swift -- Result
func fetchUser(id: Int)
        -> Result<User, AuthError> {
    guard id > 0 else {
        return .failure(.invalidCredentials)
    }
    let user = User(id: id,
                    username: "alex",
                    role: "user")
    return .success(user)
}

switch fetchUser(id: 1) {
case .success(let user):
    print("Got: \(user.username)")
case .failure(let err):
    print("Failed: \(err)")
}
kotlin -- Result
fun fetchUser(id: Int): Result<User> {
    if (id <= 0)
        return Result.failure(
            AuthError.InvalidCredentials)

    val user = User(id, "alex", "user")
    return Result.success(user)
}

val result = fetchUser(1)
result
    .onSuccess { user ->
        println("Got: ${user.username}")
    }
    .onFailure { err ->
        println("Failed: ${err.message}")
    }

Optional Chaining & Guard

Optional chaining lets you call methods or access properties on optional values without forced unwrapping. If any link in the chain is nil/null, the entire expression returns nil/null safely.

swift -- optional chaining
struct Profile {
    var avatar: Image?
}
struct Image {
    var url: String
}

var profile: Profile? = Profile()

// Chain: safe at each step
let url = profile?.avatar?.url
// url is String? -- may be nil

// guard let for early exit
guard let avatarURL = profile?.avatar?.url
else {
    print("No avatar to display")
    return
}
print("Loading: \(avatarURL)")
kotlin -- safe calls
data class Image(val url: String)
data class Profile(
    var avatar: Image? = null
)

var profile: Profile? = Profile()

// Chain with ?. operator
val url: String? = profile?.avatar?.url
// url is String? -- may be null

// takeIf pattern for early exit
val avatarURL = profile?.avatar?.url
    ?: run {
        println("No avatar to display")
        return
    }
println("Loading: $avatarURL")

Try It Yourself

Build a file parser with proper error handling:

  1. Define a ParseError enum/sealed class with cases for empty input, invalid format, and unsupported version
  2. Write a parseConfig function that throws/returns the appropriate error
  3. Wrap calls to it in do/try/catch and handle each error case differently
  4. Refactor to return a Result type instead of throwing

Key Takeaways

  • Swift functions marked throws must be called with try -- the compiler enforces it
  • Kotlin exceptions are unchecked -- the compiler does not force you to handle them (use sealed classes for domain errors)
  • Result types make success and failure explicit return values -- ideal for async and testable code
  • Optional chaining with ?. prevents nil/null crashes by short-circuiting the chain
  • guard let (Swift) enforces early exit and unwraps the value for the rest of the scope
