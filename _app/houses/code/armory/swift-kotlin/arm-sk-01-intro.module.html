Learning Objectives

  • Understand where Swift and Kotlin fit in the mobile landscape
  • Set up Xcode (iOS) and Android Studio (Android) for development
  • Run code in Swift Playgrounds and the Kotlin REPL
  • Write and understand a first iOS and Android app shell

Why Swift & Kotlin?

Swift and Kotlin are the official, modern languages for iOS and Android development respectively. Apple introduced Swift in 2014 as a type-safe replacement for Objective-C. Google endorsed Kotlin as Android's primary language in 2017, replacing Java. Both share a philosophy: eliminate entire classes of bugs at compile time, not at runtime.

Together they dominate native mobile development -- and they are remarkably similar in design goals. Learning both in parallel accelerates understanding because patterns like null safety, type inference, and functional collections appear in both.

Swift iOS, iPadOS, macOS, watchOS, tvOS. ABI-stable. Open source. Used at Apple, LinkedIn, Lyft, and Airbnb.
Kotlin Android, server-side (Ktor, Spring), Kotlin Multiplatform. JVM + native targets. Used at Google, Netflix, and Pinterest.
Type Safety Both enforce types at compile time and eliminate null pointer exceptions through optionals and null-safe types.
Interoperability Swift calls Objective-C libraries. Kotlin runs on the JVM and interops with all Java libraries seamlessly.

Setting Up Your Environment

Each platform requires its own IDE. Both are free.

Xcode (Swift) Download from the Mac App Store. Requires macOS 13+. Includes Swift compiler, iOS Simulator, Instruments, and Swift Playgrounds for experimentation.
Android Studio (Kotlin) Download from developer.android.com. Runs on Windows, macOS, and Linux. Includes the Kotlin compiler, AVD Manager for emulators, and an integrated Kotlin REPL.

Verify your Swift install from the terminal (macOS only):

terminal -- swift
$ swift --version
swift-driver version: 1.87.1 Apple Swift version 5.10

$ swift repl
Welcome to Apple Swift version 5.10.

Verify Kotlin via the Kotlin command-line tools (or use Android Studio's built-in REPL):

terminal -- kotlin
$ kotlinc -version
kotlinc-jvm 1.9.22 (JRE 21.0.2)

$ kotlinc
Welcome to Kotlin version 1.9.22 (JRE 21.0.2)!

First Lines of Code

The canonical "Hello, World!" in both languages -- side by side so you can see the parallels immediately.

swift
// Swift: hello.swift
import Foundation

print("Hello, World!")

let name = "Operator"
let year = 2026

print("Welcome, \(name). Year: \(year)")
kotlin
// Kotlin: hello.kt
fun main() {
    println("Hello, World!")

    val name = "Operator"
    val year = 2026

    println("Welcome, $name. Year: $year")
}

Key parallels: both use string interpolation (Swift: \(expr), Kotlin: $name). Swift top-level code runs directly in scripts. Kotlin requires a main() entry point function.

Swift Playgrounds & Kotlin REPL

Both environments let you experiment with code without creating a full project -- essential for learning.

swift playground
// In Xcode: File > New > Playground
// Results appear in the sidebar
var score = 100
score += 50
// Sidebar shows: 150

let doubled = score * 2
// Sidebar shows: 300
kotlin repl
// Android Studio: Tools > Kotlin REPL
// Or: kotlinc in terminal
>>> var score = 100
>>> score += 50
>>> score
res0: kotlin.Int = 150
>>> score * 2
res1: kotlin.Int = 300

App Project Structure

A minimal iOS SwiftUI app and an Android Kotlin app share a similar separation of concerns: an entry point, a root view, and resource files.

ios app entry point
import SwiftUI

// @main marks the app entry point
@main
struct MyApp: App {
    var body: some Scene {
        WindowGroup {
            ContentView()
        }
    }
}
android app entry point
import android.app.Application
import androidx.activity.ComponentActivity
import androidx.activity.compose.*

// Activity = iOS ViewController equivalent
class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState) {
        super.onCreate(savedInstanceState)
        setContent { MyApp() }
    }
}

Try It Yourself

Open a Swift Playground or the Kotlin REPL and experiment:

  1. Declare a variable with your name and print a greeting
  2. Compute how many days until 2030 and print the result
  3. Try declaring the same variable twice -- observe the compiler error
  4. Explore autocomplete by typing String. and seeing what appears

Key Takeaways

  • Swift targets iOS/Apple platforms; Kotlin targets Android and the JVM
  • Both eliminate null pointer exceptions through type-safe optional/nullable systems
  • Swift uses \(expr) for string interpolation; Kotlin uses $variable or ${expr}
  • Swift top-level scripts run directly; Kotlin requires a main() function
  • Xcode Playgrounds and the Kotlin REPL are your experimentation workbenches
