The Reverse Engineering Mindset

Reverse engineering is pattern recognition at scale. Compilers transform source code into machine code through predictable transformations. Once you know the patterns, a wall of disassembly resolves into recognizable structures: functions, loops, conditionals, and data transformations.

The RE workflow for an unknown binary is: static analysis first (strings, imports, section layout, disassembly), then dynamic analysis (strace, GDB) to observe runtime behavior, then iterative analysis where each pass increases understanding. Never assume -- confirm everything in the debugger.

Recognizing Common Compiler Patterns

pattern: function prologue (gcc -O0)
; Every function compiled without optimization starts like this:
push   rbp
mov    rbp, rsp
sub    rsp, 0x30        ; allocate 48 bytes for locals

; And ends like this (epilogue):
leave                   ; = mov rsp, rbp / pop rbp
ret
pattern: null check (common after malloc, fopen, etc.)
; C:  if (ptr == NULL) { return -1; }
test   rax, rax         ; rax = return value from call
jz     error_handler    ; jump if zero (NULL)
pattern: for loop (gcc -O2 output)
; C:  for (int i = 0; i < n; i++) { sum += arr[i]; }
; Optimized: counting loop with index in register
xor    eax, eax         ; sum = 0
xor    ecx, ecx         ; i = 0
test   rdi, rdi         ; if n == 0, skip
jz     .done
.loop:
add    eax, [rsi+rcx*4] ; sum += arr[i] (rcx*4 because int = 4 bytes)
inc    ecx
cmp    ecx, edi         ; compare i to n
jl     .loop
.done:
ret
pattern: switch statement (jump table)
; C:  switch(n) { case 0: ...; case 1: ...; case 2: ...; }
; Compiled to a computed jump table when cases are dense
cmp    eax, 2           ; bounds check: if case > max, go to default
ja     .default
jmp    [rip+rax*8+0x200] ; index into table of jump targets
; The 0x200 offset points to an array of 8-byte addresses
; This is the classic jump table / computed goto pattern

Compiler Optimizations to Know

compiler optimization idioms
; Strength reduction: multiply by constant -> shift+add
; C:  n * 10  becomes:
lea    rax, [rcx+rcx*4]  ; rax = n * 5  (n + n*4)
add    rax, rax           ; rax = n * 10

; Division by constant: multiply by reciprocal
; C:  n / 7  becomes (magic number trick):
mov    ecx, 0x92492493   ; magic reciprocal constant
imul   rcx               ; rdx:rax = n * magic
mov    rax, rdx
sar    rax, 2
; This is div-by-7 but without the slow div instruction

; Tail call optimization: replace call/ret with jmp
; C:  return other_func(x);  becomes:
jmp    other_func         ; no call/ret pair needed

Ghidra: Static Analysis Workflow

Ghidra (developed by the NSA, released as open-source in 2019) is a full-featured reverse engineering suite. It combines a disassembler, decompiler, cross-reference engine, and scripting API.

ghidra workflow for a crackme
1. File > Import File -- load the binary
2. Accept auto-analysis -- Ghidra identifies functions and data
3. Symbol Tree (left panel) -- find "main" or entry function
4. Decompiler window (right panel) -- pseudocode of selected function
5. Right-click a string in .data/.rodata -- "References to" finds where it is used
6. Cross-references (XREF): find all callers of a function
7. Rename variables and functions as you understand them
8. Search > Search Program Text -- find specific strings or constants
9. Window > Function Graph -- visual CFG (control flow graph)

The decompiler output is a best guess -- it can be wrong about types, especially for pointer arithmetic and function pointer tables. Always verify decompiler output against the actual disassembly.

radare2: Command-Line Binary Analysis

radare2 (r2) is a command-line framework for reverse engineering. It is faster to use than Ghidra for quick investigations and is available on systems where installing a GUI tool is impractical.

radare2 essential commands
$ r2 ./binary                  # open binary
$ r2 -d ./binary               # open in debug mode

# After opening:
[0x00401000]> aaa              # auto-analyze all (functions, strings, xrefs)
[0x00401000]> afl              # list all identified functions
[0x00401000]> s main           # seek to main function
[0x00401000]> pdf              # print disassembly of current function
[0x00401000]> pdd              # print decompiled C-like output (r2dec plugin)
[0x00401000]> iz               # list strings in binary
[0x00401000]> axt 0x402000     # cross-references TO address 0x402000
[0x00401000]> VV               # visual control flow graph mode
[0x00401000]> q                # quit

CTF Crackme Methodology

A crackme is a binary that accepts a "password" and either succeeds or fails. The goal is to find the correct input without having the source code. The standard methodology:

crackme analysis checklist
; Step 1: Reconnaissance
$ file ./crackme                # architecture, stripped?
$ strings ./crackme             # any obvious success/failure strings?
$ ltrace ./crackme              # does it call strcmp or strncmp?

; Step 2: Static Analysis
; - Open in Ghidra / r2
; - Find the string "wrong" or "incorrect" -- xref back to the check function
; - Identify the comparison: cmp + conditional jump before the fail message
; - Determine what value is being compared to your input

; Step 3: Dynamic Analysis
; - Set breakpoint at the comparison instruction
; - Run with dummy input
; - Inspect what the binary is comparing -- often the expected value is in a register

; Common patterns in crackmes:
; - Direct strcmp(input, hardcoded_key)  -- just read the string
; - XOR transform: input[i] ^ key[i] must equal target[i]
; - Checksum: all bytes of input must sum to a specific value
; - Serial algorithm: input passes through a hash function, result checked

Build and Crack Your Own Crackme

Write a simple crackme in C, compile it, then reverse it:

  1. Create crackme.c that compares argv[1] to a hardcoded string using strcmp
  2. Compile stripped: gcc -O1 -s -o crackme crackme.c
  3. Now reverse it: use strings ./crackme -- is the password visible?
  4. Try: objdump -d -M intel ./crackme -- find the call to strcmp
  5. Use ltrace ./crackme wrongpass 2>&1 -- ltrace shows the strcmp arguments!
  6. Verify you found the password by running it correctly

Identify Patterns in Real Binaries

Apply the pattern recognition skills to system utilities:

  1. Disassemble /usr/bin/id with objdump and find the main function
  2. Identify at least one if/else pattern (cmp + conditional jump)
  3. Find any loop patterns (back-edge jumps)
  4. Use strings /usr/bin/id -- can you match strings to the code that uses them?

Key Takeaways

  • RE is pattern recognition: learn the compiler idioms for if/else, loops, switch, and function calls
  • test rax, rax / jz is a null/zero check; jmp [rip+rax*8+offset] is a jump table
  • Compilers replace mul/div with shift+add (strength reduction) and magic number multiplication
  • Ghidra workflow: import, auto-analyze, find entry/main, use XREF to trace string references
  • r2 for command-line: aaa (analyze), afl (list functions), pdf (disassemble), iz (strings)
  • ltrace shows strcmp arguments -- often reveals crackme passwords without any disassembly
