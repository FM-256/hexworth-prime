Learning Objectives

  • Use GDB to step through assembly one instruction at a time
  • Inspect and modify registers and memory in GDB
  • Use objdump to disassemble binaries in Intel syntax
  • Apply strace and ltrace to trace syscalls and library calls
  • Set software breakpoints and watchpoints

GDB: The GNU Debugger

GDB is the primary debugging tool on Linux. For assembly work you will use it at the instruction level: setting breakpoints at labels, stepping one instruction at a time with stepi, and inspecting registers with info registers. Install with sudo apt install gdb.

Two enhancements are strongly recommended: pwndbg and peda are GDB plugins that add color-coded register/stack views, automatic disassembly at each step, and exploit-development helpers. For this course, plain GDB is sufficient.

gdb session -- launching and basic navigation
$ gdb ./hello                    # load binary into gdb

(gdb) layout asm                  # show disassembly panel (TUI mode)
(gdb) layout regs                 # show registers panel
(gdb) break _start                # breakpoint at label _start
(gdb) break *0x401000             # breakpoint at specific address
(gdb) run                          # start execution
(gdb) stepi                        # step one instruction (into calls)
(gdb) nexti                        # step over calls (don't enter them)
(gdb) continue                     # run until next breakpoint
(gdb) finish                       # run until end of current function
(gdb) quit                         # exit gdb

Inspecting Registers and Memory

gdb -- registers and memory inspection
# Registers
(gdb) info registers              # all registers
(gdb) info registers rax rbx rip  # specific registers
(gdb) print $rax                   # print rax in decimal
(gdb) print/x $rax                 # print rax in hex
(gdb) set $rax = 42                # modify a register

# Memory examination: x/FMT  (format: count + format-char + size-char)
(gdb) x/8gx $rsp     # 8 qwords (g=8 bytes) in hex at RSP (the stack)
(gdb) x/16bx $rip    # 16 bytes in hex at RIP (current instruction bytes)
(gdb) x/s 0x402000   # print as null-terminated string at that address
(gdb) x/4wd $rbp-16  # 4 dwords at stack variable location

# Disassembly
(gdb) disassemble _start          # disassemble a function
(gdb) disassemble $rip,+32        # disassemble 32 bytes from current PC
(gdb) set disassembly-flavor intel # switch to Intel syntax

Breakpoints and Watchpoints

gdb -- breakpoints and watchpoints
# Software breakpoints (inserts INT3 = 0xCC at the address)
(gdb) break _start               # break at label
(gdb) break *0x40100a            # break at address
(gdb) info breakpoints           # list all breakpoints
(gdb) delete 1                    # delete breakpoint 1
(gdb) disable 2                   # disable breakpoint 2

# Conditional breakpoints
(gdb) break *0x40100a if $rax == 0

# Hardware watchpoints (break when a memory address is read/written)
(gdb) watch *0x602000             # break when this address is written
(gdb) rwatch *($rbp-8)            # break when this address is READ
(gdb) awatch *($rbp-8)            # break on any access (read or write)

objdump: Static Disassembly

objdump disassembles binaries without running them. It is the first tool to reach for when you receive an unknown binary. Key flags for security work:

objdump usage
# Disassemble all code sections in Intel syntax
$ objdump -d -M intel ./binary

# Include source annotation (if binary was compiled with -g)
$ objdump -d -M intel -S ./binary

# Show all sections and their properties
$ objdump -h ./binary

# Show string constants in all sections
$ objdump -s -j .rodata ./binary

# Show symbol table (function names)
$ objdump -t ./binary | grep -i " F "

# Show dynamic symbols (imported library functions)
$ objdump -T ./binary

# Full example: disassemble and search for syscall patterns
$ objdump -d -M intel ./binary | grep -A2 "syscall"

strace and ltrace

strace / ltrace usage
# strace: trace system calls
$ strace ./binary                    # trace all syscalls
$ strace -e open,read,write ./binary # trace specific syscalls only
$ strace -o out.txt ./binary         # save trace to file
$ strace -p 1234                     # attach to running process PID 1234
$ strace -c ./binary                 # count syscalls, print summary table

# ltrace: trace library function calls (calls into libc, etc.)
$ ltrace ./binary                    # trace all library calls
$ ltrace -e strcmp ./binary          # trace only strcmp calls

# Sample strace output for a write() call:
write(1, "Hello, World!\n", 14)      = 14
#       ^fd  ^buffer         ^count   ^bytes actually written

readelf: ELF Structure Inspection

readelf commands
# ELF header (architecture, entry point, ABI)
$ readelf -h ./binary

# Section headers (.text, .data, .bss, .rodata, ...)
$ readelf -S ./binary

# Program headers (memory segments, permissions)
$ readelf -l ./binary

# Symbol table
$ readelf -s ./binary

# Dynamic linking info (shared library dependencies)
$ readelf -d ./binary

# Sample output showing RWX permissions on segments:
  Type      Offset    VirtAddr           Flags Align
  LOAD      0x000000  0x0000000000400000 R E   0x200000  <-- code segment (RE)
  LOAD      0x001000  0x0000000000601000 RW    0x200000  <-- data segment (RW)

GDB Walkthrough

Use any program from previous modules (functions.asm is a good choice):

  1. Compile with debug symbols: nasm -f elf64 -g -F dwarf functions.asm -o functions.o
  2. Link: ld functions.o -o functions
  3. Open in GDB: gdb ./functions
  4. Set Intel syntax: (gdb) set disassembly-flavor intel
  5. Break at add_nums: (gdb) break add_nums
  6. Run: (gdb) run
  7. At the breakpoint, print rdi and rsi: (gdb) print/d $rdi
  8. Step through and watch rax accumulate the sum

objdump Investigation

Disassemble /bin/ls and answer these questions:

  1. objdump -d -M intel /bin/ls | head -50 -- what is the entry point function?
  2. objdump -T /bin/ls | head -20 -- list 5 library functions ls imports
  3. readelf -S /bin/ls | grep -E "\.text|\.data|\.bss" -- what are their sizes?
  4. Find a conditional jump in the disassembly and determine what condition it checks

Key Takeaways

  • GDB: stepi steps one instruction; nexti steps over calls; info registers shows all registers
  • Memory examination format: x/NFS where N=count, F=format (x/d/s/i), S=size (b/h/w/g)
  • Hardware watchpoints (watch/rwatch) break on memory access -- invaluable for buffer overflows
  • objdump -d -M intel: static disassembly in Intel syntax without running the binary
  • strace traces syscalls; ltrace traces library function calls -- both work on unknown binaries
  • readelf -S shows section layout and permissions; -l shows memory segment permissions
