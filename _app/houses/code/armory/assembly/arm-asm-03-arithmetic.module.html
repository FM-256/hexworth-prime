Arithmetic & Logic

< Assembly Track

Learning Objectives

  • Use add, sub, inc, dec for integer arithmetic
  • Understand how mul and div work with implicit operands
  • Apply bitwise operations: and, or, xor, not, shl, shr, sar
  • Use cmp and the FLAGS register to set up conditional logic
  • Recognize idiomatic assembly patterns used in real binaries

Addition and Subtraction

add and sub modify their destination operand in-place and update the FLAGS register. The carry flag (CF) is set on unsigned overflow; the overflow flag (OF) is set on signed overflow.

add / sub / inc / dec
; add  dst, src  --  dst = dst + src
mov  rax, 100
add  rax, 50         ; rax = 150
add  rax, rbx        ; rax = rax + rbx
add  rax, [rcx]      ; rax = rax + qword at [rcx]

; sub  dst, src  --  dst = dst - src
sub  rax, 10         ; rax -= 10
sub  rsp, 32         ; common: allocate 32 bytes on the stack

; inc / dec -- add/subtract 1 (does NOT change CF)
inc  rcx             ; rcx++
dec  rdx             ; rdx--
inc  dword [rbp-4]   ; increment 32-bit variable on stack

; adc -- add with carry (for multi-precision arithmetic)
adc  rdx, 0          ; rdx += 0 + CF (propagate carry)

Multiplication

Multiplication in x86-64 uses implicit operands. mul (unsigned) and imul (signed) have different forms. The result is wide: multiplying two 64-bit values produces a 128-bit result stored in RDX:RAX.

mul / imul
; mul src  -- unsigned: rdx:rax = rax * src
mov  rax, 1000
mov  rbx, 42
mul  rbx            ; rdx:rax = 1000 * 42 = 42000
                   ; high bits in rdx (zero here), result in rax

; imul -- signed, one operand (same as mul but signed)
mov  rax, -10
imul rbx            ; rdx:rax = -10 * rbx

; imul -- two-operand form: dst = dst * src
imul rax, rcx       ; rax = rax * rcx  (result truncated to 64 bits)

; imul -- three-operand form: dst = src * immediate (most common in compiler output)
imul rax, rcx, 7   ; rax = rcx * 7

Division

Division is the most complex arithmetic instruction. div divides the 128-bit value in RDX:RAX by the operand. The quotient lands in RAX and the remainder in RDX. You must zero RDX before dividing a 64-bit value to avoid a division fault.

div / idiv
; div src  -- unsigned: rax = rdx:rax / src,  rdx = remainder
mov  rax, 100
xor  rdx, rdx        ; CRITICAL: zero rdx before 64-bit divide
mov  rbx, 7
div  rbx             ; rax = 14 (quotient),  rdx = 2 (remainder)

; idiv -- signed division, same implicit operands
mov  rax, -100
cqo                   ; sign-extend rax into rdx:rax (use instead of xor rdx,rdx)
idiv rbx            ; signed divide

; Tip: dividing by powers of 2 uses shifts instead -- much faster
shr  rax, 3          ; rax /= 8  (unsigned)
sar  rax, 3          ; rax /= 8  (signed, preserves sign bit)

Bitwise Operations

Bitwise instructions are critical for low-level programming, cryptography, network protocol parsing, and security. Every operation works bit-by-bit across the full width of the operand.

and / or / xor / not
; and  dst, src  --  dst = dst AND src  (clear bits)
mov  rax, 0xFF
and  rax, 0x0F       ; rax = 0x0F  (mask out upper nibble)

; Common: test if a bit is set without modifying dst
and  rax, 1          ; zero flag set if bit 0 was clear

; or   dst, src  --  dst = dst OR src   (set bits)
mov  rax, 0x01
or   rax, 0x80       ; rax = 0x81  (set high bit)

; xor  dst, src  --  dst = dst XOR src  (toggle bits)
xor  rax, rax        ; rax = 0  -- idiom: zero a register efficiently
xor  rax, 0xFF       ; flip all low 8 bits
; XOR is reversible: (a XOR key) XOR key = a  -- used in simple obfuscation

; not  dst  --  dst = bitwise NOT (one's complement)
not  rax             ; flip every bit in rax

Shift Operations

Shifts move bits left or right. Left shift multiplies by powers of 2; right shift divides. Compilers optimize divisions and multiplications by constants into shifts -- you will see this constantly in disassembly.

shl / shr / sal / sar / rol / ror
; shl  dst, count  --  logical shift left (zeros shift in from right)
mov  rax, 1
shl  rax, 4          ; rax = 16  (1 << 4 = 2^4)
shl  rax, cl         ; shift count can be in cl register

; shr  dst, count  --  logical shift right (zeros shift in from left)
shr  rax, 2          ; rax /= 4  (unsigned)

; sar  dst, count  --  arithmetic shift right (sign bit preserved)
mov  rax, -32
sar  rax, 2          ; rax = -8  (signed divide by 4)

; rol / ror -- rotate (no bits are lost, they wrap around)
mov  rax, 0xFF00000000000000
ror  rax, 8          ; rax = 0x00FF000000000000 (high byte moved to second)
; Rotates appear in hash functions, crypto algorithms, and obfuscators

CMP and the FLAGS Register

cmp performs a subtraction but discards the result -- it only updates the FLAGS register. This sets up conditional jumps (covered in Module 4). test does the same but uses AND.

cmp / test
; cmp  op1, op2  --  computes op1 - op2, discards result, sets FLAGS
cmp  rax, 0          ; is rax equal to zero?
cmp  rax, rbx        ; is rax equal to rbx?
cmp  rax, 100        ; is rax less/equal/greater than 100?

; FLAGS set by cmp (and arithmetic):
;   ZF (Zero Flag)     -- set when result is zero (operands were equal)
;   SF (Sign Flag)     -- set when result is negative
;   CF (Carry Flag)    -- set on unsigned overflow/borrow
;   OF (Overflow Flag) -- set on signed overflow
;   PF (Parity Flag)   -- set when low byte has even number of set bits

; test  op1, op2  --  computes op1 AND op2, discards result, sets ZF/SF/PF
test rax, rax        ; is rax zero? (common idiom)
test rax, 1          ; is bit 0 of rax set? (test for odd/even)
XOR for zeroing registers.

You will see xor rax, rax everywhere in optimized code and shellcode. It encodes to just 2 bytes (0x31 0xC0) compared to 7 bytes for mov rax, 0. Shellcode avoids NULL bytes, so xor is the preferred zeroing idiom.

Putting It Together: Absolute Value

abs_val.asm -- compute absolute value of a signed integer
global _start

section .data
    number  dq  -42       ; signed 64-bit value

section .text
_start:
    mov   rax, [number]   ; load -42 into rax

    ; abs(rax): if rax < 0, negate it
    mov   rbx, rax        ; copy original
    neg   rbx             ; rbx = -rax
    cmp   rax, 0
    cmovl rax, rbx        ; conditional move: if rax < 0, rax = rbx
    ; rax now holds absolute value = 42

    ; exit with rax as status code (will be 42 mod 256)
    mov   rdi, rax
    mov   rax, 60
    syscall

; Compile, run, then: echo $?  -- should print 42

neg computes the two's complement negation of an operand. cmovl is a conditional move: it executes only if the less-than condition from the preceding cmp is true. Conditional moves avoid branch misprediction penalties.

Try It Yourself

Assemble and run abs_val.asm:

  1. Assemble and link: nasm -f elf64 abs_val.asm -o abs_val.o && ld abs_val.o -o abs_val
  2. Run and check exit code: ./abs_val; echo $? -- expect 42
  3. Change number to a positive value like 17 and rerun -- should still print 17
  4. Trace through in GDB: break _start, run, stepi, inspect rax and rbx after each instruction

XOR Cipher

Write an assembly snippet that XOR-encodes the byte value 0x41 with the key 0xAA, then XOR-decodes it back. Verify you recover 0x41. This is the fundamental operation of XOR encryption used in basic malware obfuscation.

  1. Place 0x41 in al
  2. XOR al with 0xAA -- what value do you get?
  3. XOR the result with 0xAA again -- did you recover 0x41?
  4. This proves XOR is its own inverse: the foundation of stream ciphers

Key Takeaways

  • add, sub, inc, dec modify their destination and set the FLAGS register
  • mul/imul use implicit rax; the 128-bit result goes in rdx:rax
  • Always zero rdx before div, or use cqo before idiv
  • xor reg, reg is the preferred idiom for zeroing a register (shorter, no NULL bytes)
  • Shifts are faster than multiplication/division by powers of 2 -- compilers use them constantly
  • cmp subtracts without storing the result; test ANDs without storing the result
  • Conditional moves (cmovcc) avoid branch mispredictions and appear in optimized code
