ELF Sections: .text, .data, .bss

An ELF (Executable and Linkable Format) binary is divided into sections. Each section has specific permissions and purposes. Understanding sections is prerequisite to understanding how memory is mapped when a program runs, and how exploits manipulate it.

.text Executable code. Read + Execute permissions. Write is NOT set -- prevents self-modifying code and certain exploits. All your instructions live here.
.data Initialized data: global/static variables with non-zero initial values. Read + Write. NOT executable. Contents are stored directly in the binary.
.bss Uninitialized data: zero-initialized globals and static variables. Read + Write. The OS zeroes this at load time. Takes no space in the binary file.
.rodata Read-only data: string literals, const globals. Read only. String literals from C code appear here. Attempting to write causes SIGSEGV.

NASM Data Directives

initialized data (.data section)
section .data
    ; db = define byte(s)
    msg      db  "Hello", 0x0a, 0  ; string + newline + null terminator
    byte_val db  0xFF               ; single byte
    byte_arr db  1, 2, 3, 4, 5   ; array of 5 bytes

    ; dw = define word (2 bytes)
    port     dw  0x0050            ; 80 (HTTP port) in network byte order

    ; dd = define dword (4 bytes)
    ip_addr  dd  0x7F000001        ; 127.0.0.1 in network byte order

    ; dq = define qword (8 bytes)
    counter  dq  0                  ; 64-bit counter

    ; equ -- constant, not stored in binary
    MSG_LEN  equ $ - msg           ; computed at assemble time
uninitialized data (.bss section)
section .bss
    ; resb/resw/resd/resq N  -- reserve N units of that size
    buffer   resb  1024    ; 1024 bytes (zero-initialized by OS)
    int_arr  resd  10      ; 10 x 4-byte integers
    ptr      resq  1       ; one 64-bit pointer slot

LEA: Load Effective Address

lea computes a memory address but does NOT access memory -- it stores the address itself into the destination. This is critically different from mov with brackets. Compilers use LEA extensively for address arithmetic and multiplications by small constants.

lea vs mov
; MOV with brackets = dereference (access memory at that address)
mov  rax, [rbx+8]    ; rax = VALUE stored at address (rbx + 8)

; LEA = compute address, do NOT access memory
lea  rax, [rbx+8]    ; rax = ADDRESS rbx + 8  (no memory access!)

; LEA for getting the address of a label (like C's & operator)
lea  rdi, [rel msg]  ; rdi = address of msg label

; LEA as a fast multiply trick (compiler optimization)
lea  rax, [rbx+rbx*2]  ; rax = rbx * 3  (no mul instruction needed)
lea  rax, [rbx*8+4]    ; rax = rbx*8 + 4

; You will see lea rax, [rbp-N] constantly in GCC output
lea  rax, [rbp-16]    ; rax = address of local variable (not its value)

Array Traversal

array_sum.asm -- sum an array of 32-bit integers
global _start

section .data
    arr   dd  10, 20, 30, 40, 50  ; 5 x dword
    count equ 5

section .text
_start:
    lea   rsi, [rel arr]   ; rsi = base address of array
    mov   ecx, count        ; loop counter = 5
    xor   eax, eax          ; eax = 0 (sum accumulator)

.loop:
    add   eax, [rsi]        ; sum += arr[i]
    add   rsi, 4             ; advance pointer by 4 bytes (dword)
    dec   ecx
    jnz   .loop

    ; rax = 150 (10+20+30+40+50)
    mov   rdi, rax
    mov   rax, 60
    syscall

String Operations: REP MOVS and REP STOS

x86-64 has a family of string/block instructions that operate on ranges of memory. They use RSI (source), RDI (destination), and RCX (count). The REP prefix repeats the operation RCX times, decrementing RCX each iteration.

string operations
; movsb/movsw/movsd/movsq  -- copy one unit from [rsi] to [rdi], advance both
; rep movsb  -- copy rcx bytes from [rsi] to [rdi]  (like memcpy)
    lea   rsi, [rel src]    ; source buffer
    lea   rdi, [rel dst]    ; destination buffer
    mov   rcx, 16            ; copy 16 bytes
    rep   movsb              ; memcpy(dst, src, 16)

; stosb/stosw/stosd/stosq  -- write al/ax/eax/rax to [rdi], advance rdi
; rep stosb  -- fill rcx bytes at [rdi] with al  (like memset)
    lea   rdi, [rel buf]    ; destination
    xor   eax, eax          ; byte to fill = 0
    mov   rcx, 64            ; 64 bytes
    rep   stosb              ; memset(buf, 0, 64)

; scasb  -- compare al with [rdi], advance rdi (used in strlen/strchr)
; repne scasb  -- repeat while NOT equal (find null terminator)
    lea   rdi, [rel str]    ; string to measure
    xor   eax, eax          ; al = 0 (null byte)
    mov   rcx, 0xFFFF       ; max search distance
    repne scasb              ; scan until [rdi] == 0
    sub   rdi, [rel str]    ; length = end - start - 1
    dec   rdi                ; (rdi points one past the null)
    ; rdi = string length

Try It Yourself

Assemble array_sum.asm and verify the result:

  1. Assemble, link, run: ./array_sum; echo $? -- expect 150 (mod 256 = 150)
  2. Add two more elements to the arr array and update count -- verify the new sum
  3. Modify the loop to use index-based access instead of pointer advancement:
    mov eax, [rsi + rcx*4] -- count down from (count-1) to 0

Implement strlen in Assembly

Write a NASM function my_strlen that takes a pointer to a null-terminated string in rdi and returns the length in rax. Two approaches:

  1. Loop: walk the pointer incrementing a counter until you hit a zero byte
  2. Use repne scasb (more idiomatic)

Key Takeaways

  • .text = code (execute), .data = initialized globals (read/write), .bss = zero-init globals (read/write)
  • db/dw/dd/dq declare initialized data; resb/resw/resd/resq reserve uninitialized space
  • equ defines an assembler constant computed at assemble time -- no memory allocated
  • LEA computes an address without dereferencing memory; MOV[addr] dereferences
  • Array indexing: [base + index * element_size], scale must be 1, 2, 4, or 8
  • rep movsb = fast memcpy; rep stosb = fast memset; repne scasb = find byte in buffer
