What Is a System Call?

User-space programs cannot directly access hardware, files, or the network. All such operations go through the kernel via a controlled interface called a system call. The syscall instruction (in x86-64 Linux) triggers a privilege transition from Ring 3 (user) to Ring 0 (kernel), executes the requested operation, then returns to user space.

Every C standard library function that touches the OS -- printf, fopen, malloc (for large allocations), fork -- is a wrapper around one or more syscalls. In assembly we bypass the C library entirely and invoke the kernel directly. This is how shellcode works.

Linux x86-64 Syscall ABI

The syscall calling convention is DIFFERENT from the regular function calling convention:

syscall register convention
; syscall number:  rax
; 1st argument:    rdi
; 2nd argument:    rsi
; 3rd argument:    rdx
; 4th argument:    r10  (NOT rcx -- rcx is clobbered by syscall instruction)
; 5th argument:    r8
; 6th argument:    r9
; return value:    rax  (negative values = -errno on error)
; clobbered:       rcx, r11 (syscall instruction uses them internally)

syscall              ; invoke the kernel

The syscall numbers are defined in the kernel header /usr/include/asm/unistd_64.h. You can also view them with ausyscall --dump or online at the Linux syscall table.

Write to stdout and stderr

write_demo.asm
global _start

section .data
    msg_out  db  "[+] Operation complete", 0x0a
    len_out  equ $ - msg_out
    msg_err  db  "[-] Error: file not found", 0x0a
    len_err  equ $ - msg_err

section .text
_start:
    ; write(1, msg_out, len_out)  -- fd 1 = stdout
    mov  rax, 1
    mov  rdi, 1
    lea  rsi, [rel msg_out]
    mov  rdx, len_out
    syscall

    ; write(2, msg_err, len_err)  -- fd 2 = stderr
    mov  rax, 1
    mov  rdi, 2
    lea  rsi, [rel msg_err]
    mov  rdx, len_err
    syscall

    ; exit(0)
    xor  rdi, rdi
    mov  rax, 60
    syscall

File I/O: open, read, write, close

file_read.asm -- open a file, read its first 64 bytes, write to stdout
global _start

section .data
    filename  db  "/etc/hostname", 0   ; null-terminated path

section .bss
    buf       resb  64               ; 64-byte read buffer

section .text
_start:
    ; open(filename, O_RDONLY=0, 0)
    mov  rax, 2                   ; syscall: open
    lea  rdi, [rel filename]      ; path
    xor  rsi, rsi                  ; O_RDONLY = 0
    xor  rdx, rdx                  ; mode = 0 (ignored for O_RDONLY)
    syscall
    mov  r12, rax                  ; save fd in r12 (callee-saved)

    ; check for error: if rax < 0, fd is invalid
    test rax, rax
    js   .error                    ; negative = error code

    ; read(fd, buf, 64)
    mov  rax, 0                   ; syscall: read
    mov  rdi, r12                  ; fd
    lea  rsi, [rel buf]            ; buffer
    mov  rdx, 64                   ; count
    syscall
    mov  r13, rax                  ; bytes actually read

    ; close(fd)
    mov  rax, 3
    mov  rdi, r12
    syscall

    ; write(1, buf, bytes_read)
    mov  rax, 1
    mov  rdi, 1
    lea  rsi, [rel buf]
    mov  rdx, r13
    syscall
    jmp  .exit

.error:
    mov  rax, 60
    mov  rdi, 1
    syscall

.exit:
    xor  rdi, rdi
    mov  rax, 60
    syscall

execve: The Shellcode Syscall

The execve syscall replaces the current process with a new program. It is syscall number 59 on x86-64 Linux. A null-terminated path, an argv array, and an envp array are the three arguments. When shellcode calls execve("/bin/sh", ["/bin/sh", NULL], NULL), it spawns a shell in the context of the exploited process.

execve /bin/sh -- the classic shellcode template
; execve("/bin/sh", ["/bin/sh", NULL], NULL)
; This is the logical structure; full shellcode optimization is in Module 10
global _start

section .data
    path  db  "/bin/sh", 0   ; null-terminated path
    argv0 dq  path             ; argv[0] = pointer to "/bin/sh"
    argv1 dq  0               ; argv[1] = NULL terminator

section .text
_start:
    mov  rax, 59              ; syscall: execve
    lea  rdi, [rel path]      ; 1st arg: path to executable
    lea  rsi, [rel argv0]     ; 2nd arg: argv array
    xor  rdx, rdx              ; 3rd arg: envp = NULL
    syscall                    ; if successful, this never returns

    ; If execve fails, exit with error
    mov  rdi, 1
    mov  rax, 60
    syscall

Try It Yourself

Assemble and run file_read.asm:

  1. Assemble, link, run: ./file_read -- should print your hostname
  2. Use strace to observe the syscalls: strace ./file_read
  3. Modify the filename to /proc/version -- what does it print?
  4. Try an invalid path like /nonexistent -- observe the error handling path via strace

Trace System Calls in Real Binaries

Use strace on common utilities to see their syscall patterns:

  1. strace /bin/ls 2>&1 | head -30 -- what are the first syscalls?
  2. strace -e trace=write /bin/echo hello -- which fd does it write to?
  3. strace -e trace=open,read,close cat /etc/hostname -- observe open/read/close sequence
  4. Look for the open() call and note the flags value -- what does O_RDONLY=0 look like?

Key Takeaways

  • syscall is the instruction; rax holds the syscall number; return value is in rax
  • Syscall ABI: rdi, rsi, rdx, r10, r8, r9 (note r10 not rcx for 4th arg)
  • Negative return values are error codes (-errno); test rax / js is the standard error check
  • fd 0=stdin, 1=stdout, 2=stderr; open() returns a new fd or negative error
  • execve(path, argv, envp) replaces the process -- the foundation of all shellcode
  • strace shows syscalls made by any binary -- essential tool for malware analysis
