Labels and the JMP Instruction

In assembly, labels are symbolic names for addresses. A label followed by a colon defines that address. Jump instructions change RIP to the target address, redirecting execution. jmp is unconditional -- it always jumps.

unconditional jump
_start:
    mov  rax, 1
    jmp  done          ; skip the next instruction unconditionally
    mov  rax, 999      ; this line is never reached
done:
    ; rax = 1 here
    mov  rdi, rax
    mov  rax, 60
    syscall

Jumps can be near (within the current segment -- 32-bit signed offset, default) or short (8-bit offset -- only for targets within -128 to +127 bytes). NASM chooses the encoding automatically.

Conditional Jump Reference

Conditional jumps test specific flag combinations set by the preceding cmp or test. There are two sets: unsigned (for unsigned integers, using CF/ZF) and signed (for signed integers, using SF/OF/ZF).

jejzEqual / ZeroZF = 1
jnejnzNot Equal / Not ZeroZF = 0
jgjnleGreater (signed)ZF=0 and SF=OF
jgejnlGreater or Equal (signed)SF = OF
jljngeLess (signed)SF != OF
jlejngLess or Equal (signed)ZF=1 or SF!=OF
jajnbeAbove (unsigned)CF=0 and ZF=0
jaejnbAbove or Equal (unsigned)CF = 0
jbjnaeBelow (unsigned)CF = 1
jbejnaBelow or Equal (unsigned)CF=1 or ZF=1
jsSign (negative)SF = 1

joOverflowOF = 1

Translating if/else

Every C if statement compiles to a comparison followed by a conditional jump to the else branch. The "fall-through" path is the true branch.

c source vs assembly equivalent
; C:  if (rax > 10) { rax = 1; } else { rax = 0; }

    cmp  rax, 10
    jle  .else_branch    ; if NOT (rax > 10), jump to else
.true_branch:
    mov  rax, 1
    jmp  .end_if
.else_branch:
    mov  rax, 0
.end_if:
    ; execution continues here

Notice the jump condition is the inverse of the C condition. If the C says "if greater than", the assembly jumps to the else on "less or equal". This pattern is universal in compiled code.

Translating while Loops

while loop pattern
; C:  while (rcx != 0) { rcx--; rax += rcx; }

.loop_start:
    test rcx, rcx       ; is rcx zero?
    jz   .loop_end      ; exit if zero
    dec  rcx
    add  rax, rcx
    jmp  .loop_start    ; unconditional back-edge
.loop_end:
    ; loop finished

Translating for Loops

for loop pattern -- sum 0 to 9
; C:  rax = 0; for (rcx = 0; rcx < 10; rcx++) { rax += rcx; }

    xor  rax, rax        ; rax = 0 (accumulator)
    xor  rcx, rcx        ; rcx = 0 (loop counter i)
.for_loop:
    cmp  rcx, 10
    jge  .for_end       ; if rcx >= 10, done
    add  rax, rcx        ; rax += rcx
    inc  rcx             ; rcx++
    jmp  .for_loop
.for_end:
    ; rax = 45 (0+1+2+...+9)

The LOOP Instruction and Dec/JNZ Pattern

The loop instruction decrements RCX and jumps if RCX is not zero. It is a compact but often slow idiom. Modern compilers prefer the dec rcx / jnz pattern, which is what you will see in real disassembly.

loop vs dec/jnz
; Using LOOP (legacy -- rare in modern compilers)
    mov  rcx, 5          ; loop 5 times
.repeat:
    ; ... body ...
    loop .repeat        ; dec rcx; if rcx != 0, jump to .repeat

; Using DEC + JNZ (common in compiler output)
    mov  rcx, 5
.repeat2:
    ; ... body ...
    dec  rcx
    jnz  .repeat2       ; jump if rcx != 0

; Counting UP (common pattern in for loops from gcc/clang)
    xor  ecx, ecx        ; ecx = 0  (32-bit zeroing is fine)
.up_loop:
    ; ... body using ecx as index ...
    inc  ecx
    cmp  ecx, 10
    jl   .up_loop

Complete Example: FizzBuzz in Assembly

fizzbuzz.asm -- prints exit code: 0=fizzbuzz, 1=fizz, 2=buzz, 3=other
; Tests if the number in rdi is divisible by 3, 5, or 15
; Returns the appropriate category as exit code
global _start

section .text
_start:
    mov  rdi, 15         ; test value -- change to 3, 5, or 7

    ; Check divisibility by 15 first (FizzBuzz)
    mov  rax, rdi
    xor  rdx, rdx
    mov  rbx, 15
    div  rbx
    test rdx, rdx        ; remainder in rdx
    jnz  .check_fizz     ; not divisible by 15
    mov  rdi, 0          ; FizzBuzz -- exit 0
    jmp  .exit

.check_fizz:
    mov  rax, rdi
    xor  rdx, rdx
    mov  rbx, 3
    div  rbx
    test rdx, rdx
    jnz  .check_buzz
    mov  rdi, 1          ; Fizz -- exit 1
    jmp  .exit

.check_buzz:
    mov  rax, rdi
    xor  rdx, rdx
    mov  rbx, 5
    div  rbx
    test rdx, rdx
    jnz  .other
    mov  rdi, 2          ; Buzz -- exit 2
    jmp  .exit

.other:
    mov  rdi, 3          ; Other -- exit 3

.exit:
    mov  rax, 60
    syscall

Try It Yourself

Assemble and test fizzbuzz.asm with different input values:

  1. Assemble and link, then run: ./fizzbuzz; echo $?
  2. Change the mov rdi, 15 to mov rdi, 9 (divisible by 3 only) -- expect exit code 1
  3. Change to mov rdi, 10 (divisible by 5 only) -- expect exit code 2
  4. Change to mov rdi, 7 (neither) -- expect exit code 3
  5. Trace through in GDB and observe how the jump conditions redirect execution

Identify the Pattern

When you run objdump -d -M intel /bin/ls | head -100, you will see real disassembly. Look for:

  1. Any cmp followed by a conditional jump -- what is it comparing?
  2. A back-edge: a jump to a lower address -- this is a loop
  3. A test rax, rax followed by jz -- this tests a return value for NULL/error
  4. Two consecutive jmp targets separated by code -- likely an if/else

Key Takeaways

  • jmp changes RIP unconditionally; conditional jumps test FLAGS set by cmp/test
  • The jump condition in assembly is always the INVERSE of the C condition (jle for "if greater")
  • Use j/jl/jg for signed comparisons; ja/jb for unsigned -- mixing these is a common bug
  • Back-edges (jumps to lower addresses) always indicate loops in disassembly
  • test rax, rax / jz is the canonical null/zero check -- appears everywhere in system code
  • The loop instruction is rare in modern output; dec + jnz is the standard pattern
