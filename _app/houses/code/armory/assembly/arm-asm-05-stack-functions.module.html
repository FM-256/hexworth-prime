The Stack: How It Works

The stack is a contiguous region of memory that grows downward in x86-64 (toward lower addresses). RSP always points to the current top. PUSH decrements RSP by 8 then writes the value; POP reads the value then increments RSP by 8.

push / pop mechanics
; Before: RSP = 0x7fffffffe000

push rax    ; RSP -= 8; [RSP] = rax
             ; RSP is now 0x7fffffffDFF8

push rbx    ; RSP -= 8; [RSP] = rbx
             ; RSP is now 0x7fffffffDFF0

pop  rcx    ; rcx = [RSP]; RSP += 8
             ; rcx = old rbx, RSP is now 0x7fffffffDFF8

; push imm64 -- push an immediate value
push 0      ; reserve 8 bytes (for local variable slot)

; The stack is 16-byte aligned at function calls per the ABI

CALL and RET

call pushes the return address (address of the next instruction after the call) onto the stack, then jumps to the target. ret pops the return address from the stack and jumps to it. This is the entire mechanism of function calls at the machine level.

call / ret mechanics
; call target  is equivalent to:
;   push  RIP_of_next_instruction
;   jmp   target

; ret  is equivalent to:
;   pop   RIP
;   (execution continues at popped address)

caller:
    call  my_func       ; push return addr, jump to my_func
    ; execution returns here after ret

my_func:
    ; function body
    mov   rax, 42
    ret                  ; pop return addr, jump back to caller
The saved return address is the target of buffer overflow attacks.

If an attacker can write past the end of a stack buffer, they can overwrite the saved return address that ret will pop. Controlling that value means controlling where execution goes next. This is the core of stack-based buffer overflow exploitation -- covered in Module 10.

Stack Frame Layout

Each function establishes a stack frame using the prologue. The prologue saves the caller's RBP, sets RBP to the current RSP (creating a stable frame base), then allocates space for local variables. The epilogue reverses this.

; Stack frame layout after prologue (grows downward) High address (stack bottom) ... [rbp + 16] <-- 2nd argument (if >6 args, else not here) [rbp + 8] <-- saved return address (pushed by call) [rbp + 0] <-- saved rbp (pushed by prologue) <-- RBP points here [rbp - 8] <-- local variable 1 [rbp - 16] <-- local variable 2 [rbp - 24] <-- local variable 3 ... <-- RSP points somewhere here Low address (stack top)
standard prologue / epilogue
my_function:
    ; Prologue -- save caller's frame, set up new frame
    push  rbp              ; save caller's base pointer
    mov   rbp, rsp         ; rbp = current top of stack
    sub   rsp, 32          ; allocate 32 bytes for locals
    ; (always align RSP to 16 bytes before any call)

    ; Access local variables relative to RBP
    mov   dword [rbp-4], 0  ; int a = 0;
    mov   dword [rbp-8], 1  ; int b = 1;

    ; Epilogue -- restore caller's frame
    mov   rsp, rbp         ; restore stack pointer (frees locals)
    pop   rbp              ; restore caller's base pointer
    ret                    ; return to caller

; Shorthand: ENTER and LEAVE instructions
; leave  =  mov rsp, rbp  /  pop rbp

System V AMD64 Calling Convention

On Linux x86-64, function arguments and return values follow the System V AMD64 ABI. This convention defines which registers carry which arguments, which registers a function must preserve (callee-saved), and which it can freely clobber (caller-saved).

system v amd64 abi -- argument passing
; Integer / pointer arguments (in order):
;   1st arg  -> rdi
;   2nd arg  -> rsi
;   3rd arg  -> rdx
;   4th arg  -> rcx
;   5th arg  -> r8
;   6th arg  -> r9
;   7th+     -> pushed on stack (right to left)

; Return value: rax (and rdx for 128-bit returns)

; Callee-saved (must be preserved): rbx, rbp, r12-r15
; Caller-saved (may be clobbered): rax, rcx, rdx, rsi, rdi, r8-r11

; Example: calling int add(int a, int b) with a=3, b=5
    mov  edi, 3       ; first arg (32-bit, zero-extends)
    mov  esi, 5       ; second arg
    call add
    ; rax = 8 (return value)

Complete Example: add and multiply Functions

functions.asm -- defines and calls two functions
; functions.asm
; Demonstrates proper function calling convention
global _start

section .text

; add_nums(a, b): rdi=a, rsi=b, returns rdi+rsi in rax
add_nums:
    push  rbp
    mov   rbp, rsp
    mov   rax, rdi       ; rax = a
    add   rax, rsi       ; rax = a + b
    pop   rbp
    ret

; multiply(a, b): rdi=a, rsi=b, returns a*b in rax
multiply:
    push  rbp
    mov   rbp, rsp
    imul  rdi, rsi       ; rdi = a * b
    mov   rax, rdi       ; return value in rax
    pop   rbp
    ret

_start:
    ; result = (3 + 5) * 2
    mov   rdi, 3          ; a = 3
    mov   rsi, 5          ; b = 5
    call  add_nums        ; rax = 8

    mov   rdi, rax        ; a = 8 (result of addition)
    mov   rsi, 2          ; b = 2
    call  multiply        ; rax = 16

    ; exit with rax as exit code (16)
    mov   rdi, rax
    mov   rax, 60
    syscall
; ./functions; echo $?  should print 16

Try It Yourself

Assemble and test functions.asm:

  1. Assemble, link, run: ./functions; echo $? -- expect 16
  2. Open in GDB. Set breakpoints at add_nums and multiply
  3. At each breakpoint, examine the stack: (gdb) x/8gx $rsp
  4. Identify: the return address pushed by call, the saved rbp, and the caller's frame
  5. Step through ret and watch RIP jump back to _start

Write a Recursive Function

Write a NASM function factorial that computes n! recursively. Start with n=5 (result = 120). Remember:

  1. Save any callee-saved registers you use (rbx is a good choice for n)
  2. Base case: if rdi == 1, return 1
  3. Recursive case: save rdi, call factorial(rdi-1), multiply result by saved rdi
  4. Exit with the result mod 256 as the exit code

Key Takeaways

  • The stack grows downward; PUSH decrements RSP, POP increments it
  • CALL pushes the return address; RET pops it and jumps there
  • The saved return address is the target of stack buffer overflow attacks
  • System V AMD64 ABI: rdi, rsi, rdx, rcx, r8, r9 for first six integer arguments
  • Return value goes in rax; caller-saved registers can be clobbered by callees
  • Standard prologue: push rbp / mov rbp, rsp / sub rsp, N
  • Standard epilogue: mov rsp, rbp (or leave) / pop rbp / ret
