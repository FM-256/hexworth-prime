The 16 General-Purpose Registers

x86-64 has 16 general-purpose 64-bit registers. Eight of them (rax through rsp) are legacy 32-bit registers extended to 64 bits. The other eight (r8 through r15) were added with AMD64 in 2003.

RegisterConventional UseCaller/Callee saved
raxReturn value; syscall numberCaller
rbxGeneral purpose; base pointer in older codeCallee
rcxFourth argument; loop counterCaller
rdxThird argument; high half of 128-bit multiplyCaller
rsiSecond argument; source index for string opsCaller
rdiFirst argument; destination indexCaller
rbpBase pointer (frame pointer)Callee
rspStack pointer -- top of the stackSpecial
r8 - r9Fifth and sixth argumentsCaller
r10 - r11Scratch / temporary useCaller
r12 - r15General purpose preserved across callsCallee

Additionally, rip is the instruction pointer (read-only in most contexts) and rflags holds condition bits set by arithmetic operations.

Register Aliasing

Each 64-bit register has overlapping sub-registers that access different portions of the same physical storage. Writing to eax has a side effect: it zero-extends into rax, clearing the upper 32 bits. Writing to ax, al, or ah does NOT zero the rest.

rax register aliasing diagram
; 64-bit: rax  = bits 63..0   (8 bytes)
;  32-bit: eax  = bits 31..0   (low 4 bytes) -- ZERO-EXTENDS into rax
;  16-bit: ax   = bits 15..0   (low 2 bytes)
;   8-bit: al   = bits  7..0   (low 1 byte)
;   8-bit: ah   = bits 15..8   (second byte)

mov  rax, 0xDEADBEEFCAFEBABE
mov  eax, 0x12345678       ; rax is now 0x0000000012345678 (upper cleared!)
mov  ax,  0xFFFF            ; rax is now 0x000000001234FFFF
mov  al,  0x00             ; rax is now 0x000000001234FF00
mov  ah,  0x11             ; rax is now 0x0000000012341100

This same aliasing applies to all eight legacy registers. The r8-r15 registers use suffix notation: r8 (64-bit), r8d (32-bit), r8w (16-bit), r8b (8-bit).

The MOV Instruction

mov is the most common instruction in any x86-64 program. It copies data from a source to a destination. Source and destination can be registers, memory locations, or immediate (constant) values -- but NOT both memory at the same time.

mov forms -- nasm intel syntax
; Register to register
mov  rbx, rax          ; rbx = rax

; Immediate (constant) to register
mov  rax, 42           ; rax = 42
mov  rcx, 0xFF         ; rcx = 255 (hex literal)
mov  rdx, 0b1010       ; rdx = 10 (binary literal)

; Memory to register (load)
mov  rax, [rbx]        ; rax = 8 bytes at address rbx
mov  eax, [rcx]        ; eax = 4 bytes at address rcx

; Register to memory (store)
mov  [rbx], rax        ; store rax at address rbx
mov  [rcx+8], rdx      ; store rdx at address rcx+8

; Immediate to memory (must specify size)
mov  qword [rax], 0   ; write 8-byte zero to address rax
mov  dword [rax], 7   ; write 4-byte value 7 to address rax

Operand Size Prefixes

When NASM cannot infer the operand size from the registers involved, you must specify it explicitly. The four size qualifiers are:

size qualifiers
byte   ; 1 byte  = 8 bits
word   ; 2 bytes = 16 bits
dword  ; 4 bytes = 32 bits  (double word)
qword  ; 8 bytes = 64 bits  (quad word)

; Example: write the byte value 0x90 to address in rax
mov  byte [rax], 0x90     ; 0x90 = NOP opcode -- useful in shellcode

Memory Addressing Modes

x86-64 supports a flexible effective address calculation: [base + index*scale + displacement]. This single mode covers all access patterns:

addressing modes
; Direct (displacement only) -- rarely used, RIP-relative preferred
mov  rax, [0x601000]     ; load from absolute address

; Register indirect (base only)
mov  rax, [rbx]          ; load 8 bytes at address in rbx

; Base + displacement -- struct field access
mov  eax, [rbp-4]        ; local variable 4 bytes below frame base
mov  rax, [rdi+16]       ; field at offset 16 in a struct

; Base + index*scale -- array access
; scale must be 1, 2, 4, or 8
mov  rax, [rbx+rcx*8]    ; 64-bit array: element [rcx]
mov  eax, [rbx+rcx*4]    ; 32-bit array: element [rcx]

; Base + index*scale + displacement -- struct array
mov  eax, [rbx+rcx*4+8]  ; element [rcx], field at offset 8

; RIP-relative addressing (position-independent code)
mov  rax, [rel myvar]     ; load myvar relative to current RIP

MOVZX and MOVSX: Zero and Sign Extension

When loading a smaller value into a larger register, you need to decide how to fill the upper bits. movzx fills with zeros (unsigned). movsx fills with copies of the sign bit (signed / two's complement).

zero vs sign extension
; movzx dst, src  -- zero-extend src into dst
movzx rax, byte [rsi]   ; load byte, zero-extend to 64 bits
; If byte = 0xFF (255 unsigned): rax = 0x00000000000000FF

; movsx dst, src  -- sign-extend src into dst
movsx rax, byte [rsi]   ; load signed byte, extend to 64 bits
; If byte = 0xFF (-1 signed):   rax = 0xFFFFFFFFFFFFFFFF

; movsxd -- sign-extend 32-bit to 64-bit
movsxd rax, ecx         ; sign-extend ecx into rax

Data Movement Program Example

registers_demo.asm
; registers_demo.asm
; Demonstrates register aliasing and mov forms.
; Does not print -- inspect with GDB (Module 8).
; Assemble: nasm -f elf64 registers_demo.asm -o registers_demo.o
; Link:     ld registers_demo.o -o registers_demo

global _start

section .data
    value1  dq  0xDEADBEEFCAFEBABE   ; 64-bit value in .data
    value2  dd  0x12345678            ; 32-bit value in .data

section .bss
    result  resq 1                     ; reserve 8 bytes uninitialized

section .text
_start:
    ; Load 64-bit value from memory into rax
    mov   rax, [value1]      ; rax = 0xDEADBEEFCAFEBABE

    ; Copy rax into rbx, then overwrite lower 32 bits
    mov   rbx, rax           ; rbx = 0xDEADBEEFCAFEBABE
    mov   ebx, 0             ; rbx = 0x0000000000000000 (zero-extended!)

    ; Array-style access: load 32-bit value, zero-extend to 64
    movzx rcx, word [value2] ; rcx = 0x5678 (low 2 bytes only)

    ; Write computed result to .bss
    mov   rax, 0x1337C0DE
    mov   [result], rax

    ; Exit
    mov   rax, 60
    xor   rdi, rdi
    syscall

Try It Yourself

Assemble and link registers_demo.asm. Then explore with GDB (install with sudo apt install gdb):

  1. Run: gdb ./registers_demo
  2. Set a breakpoint at _start: (gdb) break _start
  3. Start execution: (gdb) run
  4. Step through: (gdb) stepi -- one instruction at a time
  5. View registers after each step: (gdb) info registers rax rbx rcx
  6. Observe how writing to ebx clears the upper 32 bits of rbx

Predict the Output

Without running the code, determine the final value of rax after these instructions:

  1. mov rax, 0xAABBCCDDEEFF0011
  2. mov eax, 0x12345678 -- what is rax now?
  3. mov ax, 0xBEEF -- what is rax now?
  4. mov al, 0x00 -- what is rax now?

Key Takeaways

  • x86-64 has 16 general-purpose 64-bit registers; rdi/rsi/rdx/rcx/r8/r9 pass function arguments
  • Writing to a 32-bit sub-register (e.g. eax) zero-extends into the full 64-bit register
  • Writing to 8/16-bit sub-registers (al, ax) does NOT clear the upper bits
  • Brackets [addr] dereference memory; without brackets you get an address/value
  • The full addressing mode is [base + index*scale + displacement]
  • Use movzx for unsigned loads and movsx for signed loads into larger registers
