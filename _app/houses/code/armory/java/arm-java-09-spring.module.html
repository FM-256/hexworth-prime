Maven Project Structure

Maven is the most common Java build tool. It manages dependencies (downloads jars from Maven Central), compiles code, runs tests, and packages your application as a jar. The pom.xml is the project manifest.

standard maven project layout
my-api/
|-- pom.xml                      # Project Object Model -- dependencies, plugins
|-- src/
|   |-- main/
|   |   |-- java/
|   |   |   |-- com/hexworth/api/
|   |   |       |-- Application.java    # entry point
|   |   |       |-- controller/
|   |   |       |-- service/
|   |   |       |-- model/
|   |   |-- resources/
|   |       |-- application.properties    # config: port, db url, etc.
|   |-- test/java/...
|-- target/                      # compiled output (gitignored)
pom.xml (minimal Spring Boot)

<project xmlns="http://maven.apache.org/POM/4.0.0">

</project>

Application Entry Point

Application.java
package com.hexworth.api;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

// @SpringBootApplication = @Configuration + @EnableAutoConfiguration + @ComponentScan
@SpringBootApplication
public class Application {
    public static void main(String[] args) {
        // Boots embedded Tomcat on port 8080 by default
        SpringApplication.run(Application.class, args);
    }
}

REST Controllers

@RestController marks a class as a web controller that returns data (not HTML views). Spring automatically serializes return values to JSON using Jackson. @RequestMapping on the class sets a base path.

HostController.java
package com.hexworth.api.controller;

import org.springframework.web.bind.annotation.*;
import java.util.*;

// Marks this as a REST controller -- combines @Controller + @ResponseBody
@RestController
@RequestMapping("/api/hosts")
public class HostController {

    // In-memory store -- replace with @Repository + DB in production
    private final List<Map<String, Object>> hosts = new ArrayList<>();

    // GET /api/hosts -- returns all hosts as JSON array
    @GetMapping
    public List<Map<String, Object>> getAllHosts() {
        return hosts;
    }

    // GET /api/hosts/{ip} -- path variable
    @GetMapping("/{ip}")
    public Map<String, Object> getHost(@PathVariable String ip) {
        return hosts.stream()
            .filter(h -> ip.equals(h.get("ip")))
            .findFirst()
            .orElseThrow(() -> new RuntimeException("Host not found: " + ip));
    }

    // POST /api/hosts -- request body auto-deserialized from JSON
    @PostMapping
    public Map<String, Object> addHost(@RequestBody Map<String, Object> host) {
        hosts.add(host);
        return host;
    }

    // DELETE /api/hosts/{ip}
    @DeleteMapping("/{ip}")
    public Map<String, String> removeHost(@PathVariable String ip) {
        hosts.removeIf(h -> ip.equals(h.get("ip")));
        return Map.of("status", "deleted");
    }
}

Dependency Injection

Spring manages object creation through its IoC (Inversion of Control) container. Instead of using new, you declare dependencies and Spring injects them. This makes components independently testable and loosely coupled.

Service layer with DI
// @Service marks this as a Spring-managed bean
@Service
public class ThreatService {
    private final List<String> threats = new ArrayList<>();

    public void recordThreat(String ip) {
        threats.add(ip);
    }

    public List<String> getThreats() {
        return Collections.unmodifiableList(threats);
    }
}

// Constructor injection -- preferred over @Autowired on field
@RestController
@RequestMapping("/api/threats")
public class ThreatController {
    private final ThreatService threatService;

    // Spring injects ThreatService here automatically
    public ThreatController(ThreatService threatService) {
        this.threatService = threatService;
    }

    @GetMapping
    public List<String> list() {
        return threatService.getThreats();
    }

    @PostMapping("/{ip}")
    public Map<String, String> record(@PathVariable String ip) {
        threatService.recordThreat(ip);
        return Map.of("recorded", ip);
    }
}
test with curl
$ curl -X POST localhost:8080/api/threats/10.10.10.10
{"recorded":"10.10.10.10"}

$ curl localhost:8080/api/threats
["10.10.10.10"]

Try It Yourself

Extend the threat API with validation and proper HTTP status codes:

  1. Add a ThreatEntry record/class with fields ip, severity (1-10), and timestamp
  2. Change the POST endpoint to accept a JSON body and validate severity range
  3. Return 400 Bad Request if severity is out of range using ResponseEntity
  4. Add a GET endpoint that filters by minimum severity: GET /api/threats?minSeverity=7
  5. Use @RequestParam(defaultValue="1") int minSeverity for the query parameter

Key Takeaways

  • Maven manages dependencies in pom.xml -- mvn spring-boot:run builds and starts the server
  • @SpringBootApplication activates auto-configuration -- Spring configures Tomcat, Jackson, etc. automatically
  • @RestController + mapping annotations (@GetMapping, @PostMapping) define REST endpoints
  • Use constructor injection (not field @Autowired) -- it makes dependencies explicit and enables easier testing
  • @PathVariable extracts from the URL path; @RequestParam extracts query parameters; @RequestBody reads the JSON body
