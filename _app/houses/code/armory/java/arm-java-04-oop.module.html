Learning Objectives

Classes and Objects

A class is a blueprint. An object is an instance of that blueprint created with the new keyword. Each object gets its own copy of instance fields but shares static fields across all instances.

NetworkHost.java
public class NetworkHost {
    // Instance fields -- each object has its own copy
    private String ip;
    private int port;
    private boolean reachable;

    // Static field -- shared across ALL NetworkHost objects
    private static int totalHosts = 0;

    // Constructor -- called when new NetworkHost(...) is used
    public NetworkHost(String ip, int port) {
        this.ip = ip;          // this.ip = field, ip = parameter
        this.port = port;
        this.reachable = false;
        totalHosts++;
    }

    // Getter -- encapsulation: field is private, access is controlled
    public String getIp() { return ip; }
    public int getPort() { return port; }
    public boolean isReachable() { return reachable; }

    // Setter with validation
    public void setPort(int port) {
        if (port < 1 || port > 65535) {
            throw new IllegalArgumentException("Invalid port: " + port);
        }
        this.port = port;
    }

    // Instance method
    public void ping() {
        // Simulate a ping
        this.reachable = true;
        System.out.println("Pinged " + ip + ":" + port);
    }

    // Static method -- no access to instance fields
    public static int getTotalHosts() { return totalHosts; }

    // toString is called automatically when printing an object
    @Override
    public String toString() {
        return "NetworkHost{" + ip + ":" + port + ", reachable=" + reachable + "}";
    }
}

Using Your Class

Main.java
public class Main {
    public static void main(String[] args) {
        // Create instances with new
        NetworkHost web = new NetworkHost("10.0.0.1", 443);
        NetworkHost db  = new NetworkHost("10.0.0.2", 3306);

        web.ping();
        System.out.println(web);             // calls toString()
        System.out.println(web.isReachable());  // true

        // Static method called on the class, not an instance
        System.out.println("Total hosts: " + NetworkHost.getTotalHosts());  // 2

        // Setter with validation
        try {
            db.setPort(99999);   // throws IllegalArgumentException
        } catch (IllegalArgumentException e) {
            System.out.println("Caught: " + e.getMessage());
        }
    }
}
terminal
$ javac NetworkHost.java Main.java
$ java Main

Constructor Chaining with this()

When a class has multiple constructors, you can call one from another using this(...). This keeps initialization logic in one place and avoids duplication.

Connection.java
public class Connection {
    private final String host;
    private final int port;
    private final int timeoutMs;

    // Full constructor
    public Connection(String host, int port, int timeoutMs) {
        this.host = host;
        this.port = port;
        this.timeoutMs = timeoutMs;
    }

    // Convenience constructor -- delegates to full constructor
    public Connection(String host, int port) {
        this(host, port, 5000);  // default 5-second timeout
    }

    // Minimal constructor
    public Connection(String host) {
        this(host, 443);         // default HTTPS port
    }

    @Override
    public String toString() {
        return host + ":" + port + " (timeout=" + timeoutMs + "ms)";
    }

    public static void main(String[] args) {
        System.out.println(new Connection("api.hexworth.io"));
        System.out.println(new Connection("db.internal", 5432));
        System.out.println(new Connection("legacy", 8080, 30000));
    }
}
output
api.hexworth.io:443 (timeout=5000ms)
db.internal:5432 (timeout=5000ms)
legacy:8080 (timeout=30000ms)

Encapsulation Benefits

Encapsulation is not just about hiding data -- it is about controlling the contract of your class. By making fields private and methods public, you can change your internal implementation without breaking callers. This is the foundation of maintainable systems.

encapsulation pattern
public class SecureConfig {
    private String apiKey;   // never expose sensitive data as public
    private String dbUrl;

    public SecureConfig(String apiKey, String dbUrl) {
        this.apiKey = apiKey;
        this.dbUrl = dbUrl;
    }

    // Partial exposure: hide key, reveal only that it exists
    public boolean hasApiKey() {
        return apiKey != null && !apiKey.isEmpty();
    }

    // Mask sensitive data in toString -- never log raw credentials
    @Override
    public String toString() {
        return "SecureConfig{dbUrl=" + dbUrl + ", key=***}";
    }
}

Try It Yourself

Build a Firewall.java class that:

  1. Has a private static int field ruleCount tracking how many rules exist
  2. Has private instance fields: sourceIp, destPort, action (String: "ALLOW" or "DENY")
  3. Constructor validates that action is either "ALLOW" or "DENY" (throw IllegalArgumentException otherwise)
  4. Has a matches(String ip, int port) method that returns true if ip and port match
  5. Overrides toString to print: [ALLOW] 10.0.0.1 -> :443

Key Takeaways

  • A class is a blueprint -- create objects with new ClassName()
  • Make fields private and expose behavior through public methods (encapsulation)
  • static belongs to the class itself -- not to any instance
  • this refers to the current object instance, or chains constructors with this(...)
  • Override toString() for readable object printing -- never log raw sensitive fields
