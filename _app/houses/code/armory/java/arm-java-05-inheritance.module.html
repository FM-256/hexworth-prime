JAVA-05

Inheritance & Polymorphism

< Java Track

Learning Objectives

  • Use extends to create subclasses that inherit parent behavior
  • Override methods and call parent implementations with super
  • Define abstract classes and interfaces to enforce contracts
  • Write polymorphic code that works on any implementation of a type

Inheritance with extends

A subclass inherits all non-private fields and methods from its parent. Use super() in the subclass constructor to call the parent constructor -- it must be the first statement.

Credential hierarchy
// Base class
public class Credential {
    protected String username;
    protected String hashedPassword;

    public Credential(String username, String hashedPassword) {
        this.username = username;
        this.hashedPassword = hashedPassword;
    }

    public boolean isValid() {
        return username != null && hashedPassword != null;
    }

    @Override
    public String toString() {
        return "Credential{" + username + "}";
    }
}

// Subclass -- extends means "is-a" relationship
public class ApiKey extends Credential {
    private String keyId;
    private String[] scopes;

    public ApiKey(String username, String hashedPassword, String keyId, String[] scopes) {
        super(username, hashedPassword);  // must be first -- calls parent constructor
        this.keyId = keyId;
        this.scopes = scopes;
    }

    // Override parent method -- @Override annotation catches typos at compile time
    @Override
    public boolean isValid() {
        return super.isValid() && keyId != null;  // parent check + extra check
    }

    public String[] getScopes() { return scopes; }

    @Override
    public String toString() {
        return "ApiKey{" + username + ", keyId=" + keyId + "}";
    }
}

Abstract Classes

An abstract class cannot be instantiated directly. It defines a partial implementation and forces subclasses to implement abstract methods. Use abstract classes when subclasses share common code but must customize specific behaviors.

AbstractScanner.java
public abstract class AbstractScanner {
    protected String target;
    protected int timeout;

    public AbstractScanner(String target, int timeout) {
        this.target = target;
        this.timeout = timeout;
    }

    // Abstract method -- subclasses MUST implement this
    public abstract void scan();

    // Concrete method -- shared by all subclasses
    public void printHeader() {
        System.out.println("[*] Scanning: " + target + " (timeout " + timeout + "ms)");
    }
}

public class PortScanner extends AbstractScanner {
    private int startPort, endPort;

    public PortScanner(String target, int start, int end) {
        super(target, 3000);
        this.startPort = start;
        this.endPort = end;
    }

    @Override
    public void scan() {
        printHeader();  // inherited concrete method
        for (int p = startPort; p <= endPort; p++) {
            System.out.println("  Checking port " + p);
        }
    }
}

public class VulnScanner extends AbstractScanner {
    public VulnScanner(String target) {
        super(target, 10000);
    }

    @Override
    public void scan() {
        printHeader();
        System.out.println("  Running CVE checks...");
    }
}

Interfaces

Interfaces define a contract -- a set of method signatures that implementing classes must provide. Unlike abstract classes, a class can implement multiple interfaces. Since Java 8, interfaces can have default method implementations.

Interface contracts
// Interface -- defines what, not how
public interface Auditable {
    void logAccess(String actor);
    void logChange(String actor, String detail);

    // Default method -- available to all implementors
    default void logDenial(String actor) {
        System.out.println("[DENIED] " + actor);
    }
}

public interface Encryptable {
    String encrypt(String plaintext);
    String decrypt(String ciphertext);
}

// A class can implement multiple interfaces
public class SecretStore implements Auditable, Encryptable {
    @Override
    public void logAccess(String actor) {
        System.out.println("[ACCESS] " + actor);
    }

    @Override
    public void logChange(String actor, String detail) {
        System.out.println("[CHANGE] " + actor + ": " + detail);
    }

    @Override
    public String encrypt(String plaintext) {
        // Simplified -- real code would use JCA
        return "ENC:" + plaintext;
    }

    @Override
    public String decrypt(String ciphertext) {
        return ciphertext.replace("ENC:", "");
    }
}

Polymorphism

Polymorphism lets you write code that operates on a parent type and works correctly for any subtype. The actual method called is determined at runtime by the object's real type -- this is called dynamic dispatch.

PolymorphismDemo.java
import java.util.ArrayList;

public class PolymorphismDemo {
    public static void main(String[] args) {
        // List holds AbstractScanner references -- can be any subtype
        ArrayList<AbstractScanner> scanners = new ArrayList<>();
        scanners.add(new PortScanner("10.0.0.1", 80, 82));
        scanners.add(new VulnScanner("10.0.0.2"));

        // Each scanner runs its own implementation of scan()
        for (AbstractScanner s : scanners) {
            s.scan();  // resolved at runtime -- correct subtype method called
            System.out.println("---");
        }

        // instanceof and pattern matching (Java 16+)
        for (AbstractScanner s : scanners) {
            if (s instanceof PortScanner ps) {
                System.out.println("Port scanner found, scopes: " + ps.getClass().getSimpleName());
            }
        }
    }
}

Try It Yourself

Build a threat detection hierarchy:

  1. Create an abstract class ThreatEvent with fields severity (int 1-10) and sourceIp
  2. Add abstract method describe() returning a String
  3. Create subclasses BruteForceEvent (adds attemptCount) and SqlInjectionEvent (adds payload)
  4. Create interface Alertable with method sendAlert(String recipient)
  5. Have BruteForceEvent implement Alertable
  6. In main, store both in a List<ThreatEvent> and print each describe()

Key Takeaways

  • extends is an "is-a" relationship -- subclass inherits parent state and behavior
  • Always add @Override when overriding -- the compiler catches method signature typos
  • Abstract classes share implementation; interfaces define contracts -- use both together
  • A class can extend only one class but implement multiple interfaces
  • Polymorphism: store subtypes in a parent-type variable, call methods, get the right behavior at runtime
