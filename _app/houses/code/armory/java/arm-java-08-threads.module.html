Creating Threads

Java threads represent independent units of execution. There are two approaches: extend Thread and override run(), or implement Runnable and pass it to a Thread. The Runnable approach is preferred because your class can still extend another class.

ThreadDemo.java
public class ThreadDemo {

    // Approach 1: implement Runnable (preferred)
    static class ScanTask implements Runnable {
        private final String target;

        ScanTask(String target) { this.target = target; }

        @Override
        public void run() {
            System.out.println(Thread.currentThread().getName()
                + ": scanning " + target);
            // Simulate work
            try { Thread.sleep(100); } catch (InterruptedException e) {
                Thread.currentThread().interrupt();  // restore interrupt flag
            }
            System.out.println("Done: " + target);
        }
    }

    public static void main(String[] args) throws InterruptedException {
        Thread t1 = new Thread(new ScanTask("10.0.0.1"));
        Thread t2 = new Thread(new ScanTask("10.0.0.2"));

        // Lambda shorthand (Runnable is a functional interface)
        Thread t3 = new Thread(() -> System.out.println("Quick probe"));

        t1.start();  // starts the thread
        t2.start();
        t3.start();

        t1.join();   // wait for t1 to finish before continuing
        t2.join();
        t3.join();
        System.out.println("All scans complete");
    }
}

Race Conditions and synchronized

When multiple threads access shared mutable state, execution order is non-deterministic. Without synchronization, a counter can lose increments because read-modify-write is not atomic. The synchronized keyword ensures only one thread executes a block at a time.

SynchronizedCounter.java
public class SynchronizedCounter {
    private int count = 0;

    // synchronized method -- only one thread in here at a time
    public synchronized void increment() {
        count++;
    }

    public synchronized int getCount() {
        return count;
    }

    public static void main(String[] args) throws InterruptedException {
        SynchronizedCounter counter = new SynchronizedCounter();

        // 10 threads each increment 1000 times
        Thread[] threads = new Thread[10];
        for (int i = 0; i < 10; i++) {
            threads[i] = new Thread(() -> {
                for (int j = 0; j < 1000; j++) counter.increment();
            });
            threads[i].start();
        }

        for (Thread t : threads) t.join();

        // With synchronized: always prints 10000
        System.out.println("Final count: " + counter.getCount());
    }
}

ExecutorService

Creating a new Thread for every task is expensive. ExecutorService manages a pool of reusable threads, queuing tasks when all threads are busy. Always shut down an executor when done -- otherwise the JVM may not exit.

ExecutorDemo.java
import java.util.concurrent.*;

public class ExecutorDemo {
    public static void main(String[] args) throws Exception {
        // Thread pool with 4 workers
        ExecutorService pool = Executors.newFixedThreadPool(4);

        // Submit tasks -- returns Future to check results later
        Future<String> f1 = pool.submit(() -> {
            Thread.sleep(100);
            return "10.0.0.1 - open:22,443";
        });

        Future<String> f2 = pool.submit(() -> {
            Thread.sleep(50);
            return "10.0.0.2 - open:80";
        });

        // get() blocks until the result is available
        System.out.println(f1.get());
        System.out.println(f2.get());

        // Shutdown: stop accepting new tasks, finish existing ones
        pool.shutdown();
        pool.awaitTermination(5, TimeUnit.SECONDS);
        System.out.println("Pool shut down");
    }
}

Concurrent Collections and Atomic Types

Standard collections like HashMap are not thread-safe. For shared collections, use ConcurrentHashMap or CopyOnWriteArrayList. For single numeric counters, AtomicInteger is more efficient than synchronized methods.

ConcurrentDemo.java
import java.util.concurrent.*;
import java.util.concurrent.atomic.*;

public class ConcurrentDemo {
    public static void main(String[] args) throws InterruptedException {
        // Thread-safe map -- fine-grained locks, better performance than Hashtable
        ConcurrentHashMap<String, Integer> hitMap = new ConcurrentHashMap<>();

        // AtomicInteger -- lock-free, uses CAS (compare-and-swap)
        AtomicInteger totalHits = new AtomicInteger(0);

        ExecutorService pool = Executors.newFixedThreadPool(4);

        String[] ips = {"10.0.0.1", "10.0.0.2", "10.0.0.1", "10.0.0.3"};
        for (String ip : ips) {
            pool.submit(() -> {
                hitMap.merge(ip, 1, Integer::sum);
                totalHits.incrementAndGet();
            });
        }

        pool.shutdown();
        pool.awaitTermination(2, TimeUnit.SECONDS);

        System.out.println("Hit map: " + hitMap);
        System.out.println("Total: " + totalHits.get());
    }
}
output
Hit map: {10.0.0.1=2, 10.0.0.2=1, 10.0.0.3=1}
Total: 4

Key Takeaways

  • Implement Runnable (not extend Thread) -- your class can still extend other classes
  • Shared mutable state requires synchronization -- unsynchronized reads and writes create race conditions
  • Use ExecutorService thread pools instead of creating raw threads -- avoid the per-thread creation cost
  • Future.get() blocks until the result is ready -- use it to collect results from submitted tasks
  • Use ConcurrentHashMap and AtomicInteger for shared state -- they are faster than synchronized methods
