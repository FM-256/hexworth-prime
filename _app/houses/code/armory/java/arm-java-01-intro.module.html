Why Java?

Java was released by Sun Microsystems in 1995 with the promise of "write once, run anywhere." Three decades later, it powers more production systems than almost any other language -- Android apps, banking backends, Netflix microservices, and Hadoop clusters all run on Java.

Java is statically typed and compiled to bytecode, which means the compiler catches entire categories of bugs before your code ever runs. That strictness is a feature, not a limitation. It is why Java dominates in domains where correctness and scale matter.

Platform Independence Compiled bytecode runs on any JVM -- Windows, Linux, macOS, embedded systems.
Strong Type System Type errors are caught at compile time, not at 3am in production.
Massive Ecosystem Maven Central hosts 500,000+ libraries. Spring, Hibernate, Kafka -- all Java-native.
Enterprise Demand Most Fortune 500 backends, Android apps, and financial systems run on Java or the JVM.

The JVM Architecture

Java source code does not compile directly to machine code. It compiles to bytecode -- a platform-neutral instruction set. The Java Virtual Machine (JVM) then interprets or JIT-compiles that bytecode to native instructions at runtime.

This three-layer architecture is why Java is portable: the JVM abstracts the hardware. The JIT (Just-In-Time) compiler optimizes hot code paths, which is why long-running Java servers can rival C++ in throughput after a warmup period.

java compilation pipeline
Source code (.java)
        |
        v  javac compiler
Bytecode (.class)
        |
        v  JVM (class loader + JIT)
Native machine instructions

Installing the JDK

The JDK (Java Development Kit) includes the compiler, runtime, and standard library. The JRE (Java Runtime Environment) only includes the runtime -- you need the JDK to compile code. Use OpenJDK 21 (LTS release) for new projects.

ubuntu / debian
$ sudo apt install openjdk-21-jdk
$ java --version
openjdk 21.0.2 2024-01-16
OpenJDK Runtime Environment (build 21.0.2+13-Ubuntu-1)
OpenJDK 64-Bit Server VM (build 21.0.2+13-Ubuntu-1, mixed mode, sharing)

$ javac --version
javac 21.0.2
macos (homebrew)
$ brew install openjdk@21
$ java --version
openjdk 21.0.2 2024-01-16

On Windows, download the OpenJDK 21 installer from adoptium.net and add the bin directory to your PATH. Verify with java --version in PowerShell.

Your First Java Program

Every Java program needs at least one class, and execution always starts at the public static void main(String[] args) method. Create a file named Hello.java -- the filename must match the public class name exactly.

Hello.java
// Every Java file that runs as a program needs a main method
public class Hello {

    // Entry point: JVM calls this method to start the program
    public static void main(String[] args) {
        System.out.println("Hello, World!");

        // Variables are explicitly typed
        String name = "Operator";
        int year = 2026;

        System.out.println("Welcome, " + name + ". Year: " + year);
    }
}

Compile and run from the terminal:

terminal
$ javac Hello.java        # produces Hello.class
$ java Hello              # runs the bytecode
Hello, World!
Welcome, Operator. Year: 2026

Since Java 11, you can also run a single-file program directly without a separate compile step, which is useful for quick experiments:

single-file shortcut (java 11+)
$ java Hello.java
Hello, World!
Welcome, Operator. Year: 2026

Understanding the main Method

The main method signature has required parts. Each keyword matters:

main method breakdown
public   // accessible by the JVM from outside this class
static   // no instance needed -- JVM calls it before any objects exist
void     // does not return a value
main     // the specific name the JVM looks for
String[] args  // command-line arguments passed in as an array of strings

You can access command-line arguments through the args array:

Greet.java
public class Greet {
    public static void main(String[] args) {
        if (args.length > 0) {
            System.out.println("Hello, " + args[0] + "!");
        } else {
            System.out.println("Usage: java Greet <name>");
        }
    }
}
terminal
$ javac Greet.java
$ java Greet Alice
Hello, Alice!

Packages

Packages are Java's namespace system. They prevent class name collisions and organize code into logical units. By convention, packages use reversed domain names: com.hexworth.security.

com/hexworth/security/Scanner.java
package com.hexworth.security;  // must be first statement in file

public class Scanner {
    public static void main(String[] args) {
        System.out.println("Port scanner initialized");
    }
}
terminal (compile from project root)
$ javac com/hexworth/security/Scanner.java
$ java com.hexworth.security.Scanner
Port scanner initialized

The directory structure must mirror the package name. com.hexworth.security.Scanner must live in com/hexworth/security/Scanner.java. Build tools like Maven and Gradle manage this automatically.

Try It Yourself

Create a file called SystemInfo.java that:

  1. Prints the Java version using System.getProperty("java.version")
  2. Prints the OS name using System.getProperty("os.name")
  3. Prints the current user using System.getProperty("user.name")
  4. Compiles and runs with javac SystemInfo.java && java SystemInfo

Try It Yourself

Pass your name as a command-line argument to your Hello program:

  1. Modify Hello.java to print args[0] if an argument was provided
  2. Add a check: if args.length == 0, print a usage message
  3. Run with: java Hello YourName

Key Takeaways

  • Java compiles to bytecode that runs on any JVM -- "write once, run anywhere"
  • Install OpenJDK 21 and verify with java --version and javac --version
  • The filename must match the public class name exactly, including capitalization
  • Every program entry point is public static void main(String[] args)
  • Packages namespace classes using dot-separated, directory-mirrored paths
