Primitive Types

Java has eight primitive types that are stored directly on the stack. They are not objects -- they have no methods and no null value. Knowing the range of each type prevents subtle overflow bugs in security code.

PrimitiveDemo.java
public class PrimitiveDemo {
    public static void main(String[] args) {
        int port = 443;
        long fileSize = 9_876_543_210L;   // L suffix required for long literals
        double ratio = 0.9375;
        boolean isSecure = true;
        char grade = 'A';

        System.out.println("Port: " + port);
        System.out.println("File size: " + fileSize + " bytes");
        System.out.println("Secure: " + isSecure);

        // Integer overflow wraps silently -- a real bug source
        int max = Integer.MAX_VALUE;    // 2,147,483,647
        System.out.println("Max + 1: " + (max + 1));  // prints -2147483648
    }
}

Type Casting

Widening conversions (smaller to larger type) happen automatically. Narrowing conversions require an explicit cast and can lose data -- the compiler forces you to acknowledge this.

TypeCasting.java
public class TypeCasting {
    public static void main(String[] args) {
        // Widening: automatic, no data loss
        int i = 42;
        long l = i;          // int -> long: safe
        double d = i;        // int -> double: safe

        // Narrowing: explicit cast required, possible data loss
        double price = 9.99;
        int truncated = (int) price;   // 9 -- decimal dropped, not rounded

        long bigNum = 99_999_999_999L;
        int overflow = (int) bigNum;    // data lost -- wraps around

        System.out.println("Truncated: " + truncated);
        System.out.println("Overflow result: " + overflow);

        // String to number conversion
        String portStr = "8443";
        int port = Integer.parseInt(portStr);
        System.out.println("Parsed port: " + port);
    }
}

Wrapper Classes & Autoboxing

Every primitive type has a corresponding wrapper class in java.lang. Wrappers are full objects: they have methods, can be null, and can be stored in collections (which only accept objects). Java automatically converts between primitives and wrappers -- called autoboxing and unboxing.

WrapperDemo.java
import java.util.ArrayList;

public class WrapperDemo {
    public static void main(String[] args) {
        // Wrapper class utility methods
        System.out.println(Integer.MAX_VALUE);          // 2147483647
        System.out.println(Integer.toBinaryString(255));  // 11111111
        System.out.println(Integer.toHexString(255));    // ff

        // Autoboxing: int automatically wrapped in Integer
        ArrayList<Integer> ports = new ArrayList<>();
        ports.add(80);    // autoboxing: 80 (int) -> Integer(80)
        ports.add(443);

        // Unboxing: Integer automatically unwrapped to int
        int first = ports.get(0);  // Integer -> int

        // Null trap -- unboxing null throws NullPointerException
        Integer maybeNull = null;
        // int bad = maybeNull;  // NullPointerException at runtime!
    }
}

Strings

Strings in Java are immutable objects, not primitive types. Every string operation that appears to modify a string actually creates a new one. For heavy concatenation, use StringBuilder.

StringDemo.java
public class StringDemo {
    public static void main(String[] args) {
        String host = "  192.168.1.1  ";

        // Common string methods
        System.out.println(host.trim());              // "192.168.1.1"
        System.out.println(host.trim().length());     // 11
        System.out.println(host.contains("168"));      // true
        System.out.println(host.replace("1.1", "0.1"));  // "  192.168.0.1  "
        System.out.println(host.toUpperCase());

        // String comparison -- NEVER use == for content equality
        String a = new String("secret");
        String b = new String("secret");
        System.out.println(a == b);          // false -- different objects
        System.out.println(a.equals(b));     // true -- content comparison

        // StringBuilder for repeated concatenation
        StringBuilder sb = new StringBuilder();
        for (int i = 0; i < 5; i++) {
            sb.append("line ").append(i).append("\n");
        }
        System.out.print(sb.toString());

        // Formatted strings (Java 15+)
        String report = """
                Host: 10.0.0.1
                Port: 22
                Status: open
                """;
        System.out.print(report);
    }
}

Reading User Input with Scanner

The Scanner class reads from an input stream. Wrap System.in for stdin. Always close your Scanner when done to release the underlying resource.

UserInput.java
import java.util.Scanner;

public class UserInput {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);

        System.out.print("Enter target IP: ");
        String ip = sc.nextLine();   // reads a full line

        System.out.print("Enter port: ");
        int port = sc.nextInt();      // reads an integer

        System.out.println("Scanning " + ip + ":" + port);

        sc.close();  // release the resource
    }
}
terminal
$ java UserInput
Enter target IP: 10.0.0.50
Enter port: 8080
Scanning 10.0.0.50:8080

  1. Reads an IP address and subnet mask from the user (as strings)
  2. Reads a port number as an int
  3. Prints whether the port is in the "well-known" range (1-1023), "registered" range (1024-49151), or "dynamic" range (49152-65535)
  4. Uses Integer.parseInt to convert any string inputs that need it

Key Takeaways

  • Java's 8 primitive types are stored on the stack -- no methods, no null
  • Narrowing casts must be explicit -- the compiler forces you to acknowledge data loss
  • Wrapper classes (Integer, Long, etc.) add methods and allow null, but carry autoboxing overhead
  • Never compare String content with == -- use .equals()
  • Use StringBuilder for repeated string concatenation in loops
