What Is PHP?

PHP (PHP: Hypertext Preprocessor) was created by Rasmus Lerdorf in 1994 and has become the server-side language of the web. It runs on the server, generates HTML, and sends that to the browser. The client never sees your PHP code -- only its output.

Today PHP powers WordPress (43% of the web), Laravel applications, Facebook's original backend (now HHVM), Wikipedia, and countless enterprise systems. As a security practitioner, you will encounter PHP codebases constantly during web application assessments.

Server-Side Execution PHP runs on the web server. The browser receives only HTML, CSS, and JS output -- never raw PHP source.
Embedded in HTML PHP can be mixed directly into HTML files using opening and closing tags, making templates natural.
Massive Ecosystem Composer package manager, Laravel, Symfony, WordPress, and Drupal -- enormous legacy footprint.
Security Attack Surface SQLi, XSS, LFI/RFI, CSRF, and file upload vulnerabilities are most common in PHP applications.

Setting Up: XAMPP (Windows/macOS)

XAMPP bundles Apache, MySQL/MariaDB, and PHP into a single installer. Download from apachefriends.org, install, and start the Apache and MySQL modules from the control panel.

xampp default paths
# Windows
C:\xampp\htdocs\          # your web root
C:\xampp\php\php.exe      # php CLI binary

# macOS
/Applications/XAMPP/htdocs/
/Applications/XAMPP/bin/php

Place your PHP files inside htdocs/ and visit http://localhost/yourfile.php in a browser.

Setting Up: LAMP (Linux)

On Debian/Ubuntu-based Linux (the platform used in most security labs), install the full stack with a single command:

terminal -- ubuntu/debian
$ sudo apt update
$ sudo apt install apache2 php php-mysql mariadb-server -y
$ sudo systemctl start apache2 mariadb
$ php --version
PHP 8.2.x (cli) (built: ...)

# Web root on Linux
$ ls /var/www/html/
index.html

PHP via the Command Line

PHP has a built-in CLI (command-line interface). You can run scripts directly without a web server -- useful for automation, quick tests, and security tooling.

terminal
# Run a script
$ php hello.php

# Interactive shell (like Python's REPL)
$ php -a
Interactive shell
php > echo "Hello, CLI";
Hello, CLI
php > var_dump(2 + 2);
int(4)
php > exit

# Evaluate a one-liner
$ php -r "echo phpversion();"
8.2.15

# Built-in dev server (no Apache needed)
$ php -S localhost:8000

Your First PHP Script

Create a file called hello.php. Every PHP block starts with <?php and ends with ?> (though closing tags are optional in pure-PHP files).

hello.php
<?php
// Single-line comment
/* Multi-line comment */

$name = 'Operator';
$year = 2026;

echo "Hello, {$name}!\n";
echo "The year is {$year}.\n";
echo "In 5 years: " . ($year + 5) . "\n";

// phpinfo() dumps full server configuration -- never leave on production
// phpinfo();
terminal output
$ php hello.php
Hello, Operator!
The year is 2026.
In 5 years: 2031

Embedding PHP in HTML

When served by Apache, a .php file can mix PHP and HTML. The server executes PHP blocks and passes the rest through as-is.

page.php -- served by apache
<!DOCTYPE html>
<html>
<head><title>My PHP Page</title></head>
<body>
<?php
    $items = ['Apache', 'PHP', 'MariaDB'];
?>
    <h1>Stack Components</h1>
    <ul>
    <?php foreach ($items as $item): ?>
        <li><?php echo htmlspecialchars($item); ?></li>
    <?php endforeach; ?>
    </ul>
</body>
</html>
Security Note: Always escape output

Never echo user-controlled data directly into HTML. Use htmlspecialchars() to prevent Cross-Site Scripting (XSS). This is the single most important habit in PHP development.

The PHP Request Lifecycle

Understanding how PHP processes requests is foundational for both development and security testing:

request lifecycle
# 1. Browser sends HTTP request to Apache
#    GET /page.php?id=42 HTTP/1.1

# 2. Apache recognizes .php extension, hands off to PHP engine

# 3. PHP parses and executes page.php
#    - Reads superglobals: $_GET, $_POST, $_SERVER, $_SESSION
#    - Runs your logic, queries databases, builds output

# 4. PHP sends generated HTML back to Apache

# 5. Apache sends HTTP response to browser
#    - Browser renders HTML -- never sees PHP source

<?php
// $_SERVER contains request metadata
echo $_SERVER['REQUEST_METHOD'];  // GET or POST
echo $_SERVER['REMOTE_ADDR'];     // client IP
echo $_SERVER['REQUEST_URI'];     // /page.php?id=42

Try It Yourself

Create a file called info.php in your web root that:

  1. Declares a variable with your name and today's date
  2. Outputs a simple HTML page using PHP to embed those values
  3. Uses date('Y-m-d') to print the current server date
  4. Displays $_SERVER['SERVER_SOFTWARE'] to show the web server version

Try It Yourself

Use the PHP CLI interactive shell:

  1. Run php -a and try echo PHP_VERSION;
  2. Try var_dump(PHP_INT_MAX); and var_dump(PHP_FLOAT_EPSILON);
  3. Try echo PHP_OS_FAMILY; -- what does this reveal?
  4. Think about why exposing this to an attacker via phpinfo() is dangerous

Key Takeaways

  • PHP executes on the server -- clients only see the HTML output, never source code
  • XAMPP (cross-platform) and LAMP (Linux) are the standard local dev stacks
  • The CLI (php script.php) lets you run PHP without a web server
  • PHP blocks open with <?php and can be embedded anywhere in HTML
  • Always use htmlspecialchars() when echoing any data into HTML -- from day one
  • Never leave phpinfo() accessible on production -- it leaks server details
