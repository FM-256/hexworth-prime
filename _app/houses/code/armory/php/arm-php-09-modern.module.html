Composer: Dependency Management

Composer is PHP's package manager, equivalent to npm for Node or pip for Python. It manages third-party libraries, generates an autoloader, and locks dependency versions for reproducible builds.

terminal
# Install composer (Linux/macOS)
$ curl -sS https://getcomposer.org/installer | php
$ sudo mv composer.phar /usr/local/bin/composer

# Create a new project
$ composer init

# Install a package (e.g., vlucas/phpdotenv for .env support)
$ composer require vlucas/phpdotenv

# Install dev-only tools (not deployed to production)
$ composer require --dev phpunit/phpunit

# Install all dependencies from composer.lock (reproducible)
$ composer install --no-dev

# Security audit -- checks all packages against known CVEs
$ composer audit
index.php -- loading composer autoloader
<?php
declare(strict_types=1);

// One line replaces every require/include statement
require_once __DIR__ . '/vendor/autoload.php';

// Load .env file into $_ENV and getenv()
$dotenv = \Dotenv\Dotenv::createImmutable(__DIR__);
$dotenv->load();
$dotenv->required(['DB_HOST', 'DB_NAME', 'DB_USER', 'DB_PASS']);

PSR Standards

PHP Standards Recommendations (PSR) are community agreements on interfaces and coding style. Following them makes your code interoperable with every major PHP framework.

psr_overview
PSR-1  Basic Coding Standard
       - Files use only <?php or <?= tags
       - UTF-8 without BOM
       - StudlyCaps for classes, camelCase for methods

PSR-2/12  Extended Coding Style (PSR-12 supersedes PSR-2)
       - 4 spaces for indentation, no tabs
       - Opening brace on same line for classes and methods
       - enforce with: composer require --dev squizlabs/php_codesniffer

PSR-4  Autoloading Standard
       - Namespace maps to directory structure
       - App\Controllers\Auth resolves to src/Controllers/Auth.php

PSR-7  HTTP Message Interface
       - Defines Request/Response objects used by frameworks
       - Guzzle, Slim, Laravel all implement PSR-7

PSR-11  Container Interface (Dependency Injection)
       - Standard interface for DI containers
       - Laravel, Symfony, PHP-DI implement this

PHP 8 Features

php8_features.php
<?php
declare(strict_types=1);

// Named Arguments (PHP 8.0) -- call parameters by name
$arr = array_slice(array: [1,2,3,4,5], offset: 1, length: 3);

// Nullsafe operator (PHP 8.0) -- chain without null check cascade
$city = $user?->getAddress()?->getCity()?->getName();

// Enums (PHP 8.1) -- replace magic constant strings
enum UserRole: string
{
    case Admin     = 'admin';
    case Moderator = 'moderator';
    case User      = 'user';
    case Guest     = 'guest';

    public function canModerate(): bool
    {
        return match($this) {
            self::Admin, self::Moderator => true,
            default => false,
        };
    }
}

$role = UserRole::from($_SESSION['role'] ?? 'guest');
if (!$role->canModerate()) {
    http_response_code(403);
    exit;
}

// Readonly properties (PHP 8.1)
class IpAddress
{
    public function __construct(
        public readonly string $value
    ) {
        if (!filter_var($value, FILTER_VALIDATE_IP)) {
            throw new \ValueError("Invalid IP: {$value}");
        }
    }
}

// Intersection types (PHP 8.1)
function processRequest(\Psr\Http\Message\ServerRequestInterface&\Countable $req): void
{
    // $req must implement BOTH interfaces
}

PHPUnit Basics

tests/PasswordTest.php
<?php
declare(strict_types=1);

namespace Tests;

use PHPUnit\Framework\TestCase;
use App\Security\Hasher;

class PasswordTest extends TestCase
{
    public function test_hash_is_not_plaintext(): void
    {
        $hash = Hasher::hash('secret');
        $this->assertNotEquals('secret', $hash);
    }

    public function test_verify_correct_password(): void
    {
        $hash = Hasher::hash('correcthorsebatterystaple');
        $this->assertTrue(Hasher::verify('correcthorsebatterystaple', $hash));
    }

    public function test_verify_wrong_password(): void
    {
        $hash = Hasher::hash('secret');
        $this->assertFalse(Hasher::verify('wrong', $hash));
    }

    public function test_two_hashes_of_same_password_differ(): void
    {
        // bcrypt uses random salt per hash
        $h1 = Hasher::hash('password');
        $h2 = Hasher::hash('password');
        $this->assertNotEquals($h1, $h2);
    }
}

// Run with: ./vendor/bin/phpunit tests/

Try It Yourself

Set up a Composer project and practice modern PHP:

  1. Run composer init and create a basic project structure
  2. Install phpunit/phpunit as a dev dependency
  3. Create a UserRole enum with values and a canAdmin() method
  4. Write a PHPUnit test class with at least 3 test methods for the enum
  5. Run composer audit and read the security report format

Key Takeaways

  • Composer manages dependencies, generates autoloaders, and audits packages for CVEs
  • composer audit checks all installed packages against the PHP Security Advisories database
  • PSR-4 autoloading maps namespaces to directory paths -- no more manual require chains
  • Enums (PHP 8.1) replace magic strings and constants with type-safe, inspectable values
  • The nullsafe operator ?-> chains method calls without nested null checks
  • PHPUnit tests are the safety net for refactoring -- write them for all critical logic
