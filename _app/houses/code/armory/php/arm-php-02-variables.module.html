Variable Basics

All PHP variables start with a dollar sign $. PHP is dynamically typed -- you do not declare a type, the engine infers it from the assigned value. Variable names are case-sensitive.

variables.php
<?php
$username  = 'operator';     // string
$port      = 8080;           // integer
$score     = 9.5;            // float
$isAdmin   = false;          // boolean
$nothing   = null;           // null

// var_dump shows type + value -- essential for debugging
var_dump($port);    // int(8080)
var_dump($score);   // float(9.5)
var_dump($isAdmin); // bool(false)

// gettype returns type name as string
echo gettype($username); // string

Type Juggling -- The Double-Edged Sword

PHP automatically converts types when comparing values with ==. This is called type juggling, and it has caused some of the most infamous PHP authentication bypasses in history.

type_juggling.php
<?php
// Loose comparison (==) -- performs type coercion
var_dump(0    == "a");    // bool(true) in PHP 7! (PHP 8 fixed this)
var_dump(0    == "");     // bool(true) in PHP 7
var_dump("1"  == "01");  // bool(true) -- both cast to int 1
var_dump(true == "admin");// bool(true) -- "admin" is truthy

// Classic PHP login bypass -- attacker sends md5 hash that starts with "0e"
// "0e462097431906509019562988736854" == "0e830400451993494058024219903391"
// Both treated as 0 * 10^N = 0. Equal under ==.

// Strict comparison (===) -- type AND value must match
var_dump(0   === "a");   // bool(false) -- SAFE
var_dump("1" === "01"); // bool(false) -- SAFE
Security Rule: Always use === for comparisons involving user input

Using == to compare passwords, tokens, or hashes is a common PHP vulnerability. PHP 8 changed some juggling rules, but the safest code uses === throughout.

String Syntax

strings.php
<?php
$host = 'db01';
$port = 3306;

// Double-quotes: variables are interpolated
echo "Connecting to {$host}:{$port}\n";

// Single-quotes: literal, no interpolation (faster for static strings)
echo 'No interpolation: $host stays literal\n';

// Heredoc: multi-line with interpolation
$query = <<<SQL
    SELECT * FROM users
    WHERE host = '{$host}'
    AND port = {$port}
SQL;

// Nowdoc: multi-line, no interpolation (like single-quote)
$template = <<<'EOT'
    No {$interpolation} here.
EOT;

// String concatenation uses dot operator
$dsn = 'mysql:host=' . $host . ';port=' . $port;

Constants

constants.php
<?php
// define() -- classic method, global scope
define('DB_HOST', 'localhost');
define('DB_PORT', 3306);
define('MAX_LOGIN_ATTEMPTS', 5);

echo DB_HOST;  // No $ sign for constants

// const -- class and file scope, resolved at compile time
const APP_VERSION = '2.1.0';
const DEBUG_MODE  = false;

// PHP built-in constants you'll use constantly
echo PHP_EOL;      // OS-appropriate newline
echo PHP_INT_MAX;  // 9223372036854775807
echo DIRECTORY_SEPARATOR; // / on Linux, \ on Windows
echo __FILE__;     // current file's absolute path
echo __DIR__;      // current file's directory
echo __LINE__;     // current line number

Type Declarations (PHP 7+)

PHP 7+ lets you enforce types on function parameters, return values, and class properties. PHP 8 added union types and mixed. Strict mode prevents silent coercion.

typed.php
<?php
declare(strict_types=1); // Must be the very first statement

// Typed function signature
function hashPassword(string $password): string {
    return password_hash($password, PASSWORD_BCRYPT);
}

// Union type: string or int
function lookup(string|int $id): array|null {
    // ...
    return null;
}

// Nullable type: ?string means string or null
function getUser(?int $id = null): ?string {
    if ($id === null) return null;
    return "user_{$id}";
}

Superglobals

Superglobals are built-in PHP variables accessible everywhere. They are the primary attack surface for web input -- always treat their contents as untrusted.

superglobals.php
<?php
// $_GET -- URL query string parameters
// URL: /search.php?q=nmap&category=tools
$query    = $_GET['q'] ?? '';        // 'nmap'
$category = $_GET['category'] ?? ''; // 'tools'

// $_POST -- form submission body data (POST method)
$username = $_POST['username'] ?? '';
$password = $_POST['password'] ?? '';

// $_SERVER -- server and request info
$clientIP  = $_SERVER['REMOTE_ADDR'];
$method    = $_SERVER['REQUEST_METHOD'];
$userAgent = $_SERVER['HTTP_USER_AGENT'];

// $_COOKIE -- cookies sent by the browser
$sessionId = $_COOKIE['session_id'] ?? '';

// $_SESSION -- server-side session data (requires session_start())
session_start();
$_SESSION['user_id'] = 42;

// $_FILES -- uploaded file metadata
// $_ENV -- environment variables
// $_GLOBALS -- all global variables
Critical: Never trust superglobal values

$_GET, $_POST, $_COOKIE, $_SERVER['HTTP_*'], and $_FILES are all attacker-controlled. Validate, sanitize, and escape all values before use. Never include them in SQL queries or HTML output without proper handling.

Try It Yourself

Create types.php and explore type juggling:

  1. Compare 0 == "password" with var_dump() -- note the result
  2. Repeat with 0 === "password" and observe the difference
  3. Try var_dump((int)"42abc") and var_dump((int)"abc42")
  4. Use settype() to convert a string to an integer and dump the result

Key Takeaways

  • PHP variables always start with $ and are dynamically typed by default
  • Use var_dump() during development to inspect type and value together
  • Type juggling with == has caused critical authentication bypasses -- use ===
  • Add declare(strict_types=1) at the top of every file to prevent silent coercion
  • Superglobals ($_GET, $_POST, $_COOKIE) are attacker-controlled -- validate everything
  • The ?? null-coalescing operator safely reads superglobal values with a fallback default
