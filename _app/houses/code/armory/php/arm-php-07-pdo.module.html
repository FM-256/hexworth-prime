Learning Objectives

  • Connect to MySQL/MariaDB using PDO with secure options
  • Execute queries using prepared statements to prevent SQL injection
  • Perform CRUD operations: SELECT, INSERT, UPDATE, DELETE
  • Use transactions to maintain database integrity
  • Recognize and prevent SQL injection attack patterns

PDO Connection

PDO (PHP Data Objects) is the standard database abstraction layer. It supports MySQL, PostgreSQL, SQLite, and others with the same API. Configure it to throw exceptions on error and disable emulated prepared statements.

Database.php
<?php
declare(strict_types=1);

class Database
{
    private static ?\PDO $instance = null;

    public static function connect(): \PDO
    {
        if (self::$instance !== null) {
            return self::$instance;
        }

        $dsn = sprintf(
            'mysql:host=%s;port=%d;dbname=%s;charset=utf8mb4',
            getenv('DB_HOST') ?: 'localhost',
            (int)(getenv('DB_PORT') ?: 3306),
            getenv('DB_NAME') ?: 'app'
        );

        self::$instance = new \PDO($dsn, getenv('DB_USER'), getenv('DB_PASS'), [
            \PDO::ATTR_ERRMODE            => \PDO::ERRMODE_EXCEPTION,
            \PDO::ATTR_DEFAULT_FETCH_MODE => \PDO::FETCH_ASSOC,
            // Critical: disabling emulation forces real prepared statements
            \PDO::ATTR_EMULATE_PREPARES   => false,
            \PDO::ATTR_PERSISTENT          => false,
        ]);

        return self::$instance;
    }
}
Never hardcode credentials

Database credentials belong in environment variables or a config file outside the web root -- never in committed PHP source code. Use getenv() or a .env file loaded by a library like vlucas/phpdotenv.

Prepared Statements -- The SQLi Defense

SQL injection happens when user input is interpolated directly into SQL strings. Prepared statements separate the query structure from the data, making injection impossible.

sqli_comparison.php
<?php
$pdo = Database::connect();

// VULNERABLE -- never do this
// Input: "' OR '1'='1" extracts all rows
$username = $_POST['username'];
$sql = "SELECT * FROM users WHERE username = '{$username}'";
$result = $pdo->query($sql); // SQL INJECTION

// SAFE -- prepared statement with named placeholder
$stmt = $pdo->prepare('SELECT * FROM users WHERE username = :username');
$stmt->execute([':username' => $_POST['username'] ?? '']);
$user = $stmt->fetch();

// SAFE -- positional placeholder
$stmt = $pdo->prepare('SELECT id, username, role FROM users WHERE id = ? AND active = ?');
$stmt->execute([$_GET['id'] ?? 0, 1]);
$user = $stmt->fetch(); // single row or false

CRUD Operations

crud.php
<?php
$pdo = Database::connect();

// SELECT -- fetch multiple rows
$stmt = $pdo->prepare('SELECT id, username, role FROM users WHERE role = :role ORDER BY id');
$stmt->execute([':role' => 'admin']);
$admins = $stmt->fetchAll(); // array of assoc arrays

foreach ($admins as $admin) {
    echo "{$admin['id']}: {$admin['username']}\n";
}

// INSERT -- returns false on failure
$stmt = $pdo->prepare(
    'INSERT INTO users (username, email, password_hash, created_at)
     VALUES (:username, :email, :hash, NOW())'
);
$stmt->execute([
    ':username' => 'operator',
    ':email'    => 'operator@hexworth.io',
    ':hash'     => password_hash('s3cret!', PASSWORD_BCRYPT),
]);
$newId = (int)$pdo->lastInsertId();

// UPDATE
$stmt = $pdo->prepare('UPDATE users SET role = :role WHERE id = :id');
$affected = $stmt->execute([':role' => 'admin', ':id' => 5]);

// DELETE
$stmt = $pdo->prepare('DELETE FROM sessions WHERE user_id = ? AND expires_at < NOW()');
$stmt->execute([$userId]);
echo $stmt->rowCount() . " expired sessions removed\n";

Transactions

Transactions group multiple queries into an atomic unit. If any step fails, all changes are rolled back. Essential for operations like transferring funds or creating related records.

transactions.php
<?php
$pdo = Database::connect();

try {
    $pdo->beginTransaction();

    // Step 1: Create the user record
    $stmt = $pdo->prepare(
        'INSERT INTO users (username, email) VALUES (:u, :e)'
    );
    $stmt->execute([':u' => 'alice', ':e' => 'alice@example.com']);
    $userId = (int)$pdo->lastInsertId();

    // Step 2: Assign default role
    $stmt = $pdo->prepare(
        'INSERT INTO user_roles (user_id, role) VALUES (?, ?)'
    );
    $stmt->execute([$userId, 'user']);

    // Step 3: Log the registration event
    $stmt = $pdo->prepare(
        'INSERT INTO audit_log (action, user_id, ip) VALUES (?, ?, ?)'
    );
    $stmt->execute(['register', $userId, $_SERVER['REMOTE_ADDR']]);

    $pdo->commit(); // all or nothing
    echo "User {$userId} registered\n";

} catch (\PDOException $e) {
    $pdo->rollBack(); // undo everything
    // Log $e->getMessage() internally -- never expose to user
    error_log('Registration failed: ' . $e->getMessage());
    throw new \RuntimeException('Registration failed. Please try again.');
}

Try It Yourself

Build a UserRepository class with PDO that provides:

  1. findById(int $id): ?array -- returns one user or null
  2. findByUsername(string $username): ?array -- prepared statement
  3. create(string $username, string $email, string $password): int -- returns new ID
  4. incrementFailedAttempts(int $id): void -- atomic increment
  5. All methods use prepared statements -- zero string interpolation in SQL

Key Takeaways

  • Always set ATTR_EMULATE_PREPARES => false -- forces real server-side prepared statements
  • Never interpolate variables into SQL strings -- use :placeholder or ? exclusively
  • Use ERRMODE_EXCEPTION so PDO errors throw catchable exceptions, not silent failures
  • Wrap multi-step operations in beginTransaction() / commit() / rollBack()
  • Log PDOException messages internally -- never display DB errors to users
  • Store credentials in environment variables, not in source code
