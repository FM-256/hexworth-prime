Sessions: Secure Configuration

PHP sessions store state on the server and reference it via a session ID cookie. The default configuration has several weak defaults that need hardening before use.

session_config.php
<?php
// Configure BEFORE session_start()
ini_set('session.use_strict_mode',    '1'); // reject uninitialized IDs
ini_set('session.use_only_cookies',   '1'); // no ?PHPSESSID= in URL
ini_set('session.cookie_httponly',    '1'); // JS cannot read the cookie
ini_set('session.cookie_secure',      '1'); // HTTPS only
ini_set('session.cookie_samesite',    'Strict'); // CSRF mitigation
ini_set('session.gc_maxlifetime',    '3600'); // 1 hour idle timeout
ini_set('session.sid_length',         '48'); // longer = harder to guess
ini_set('session.sid_bits_per_character', '6'); // max entropy per char

session_start();

Login and Logout Flow

auth.php
<?php
declare(strict_types=1);

function login(\PDO $pdo, string $username, string $password): bool
{
    // Fetch by username -- password checked AFTER fetch (prevents timing oracle)
    $stmt = $pdo->prepare(
        'SELECT id, username, password_hash, role FROM users
         WHERE username = :u AND active = 1 LIMIT 1'
    );
    $stmt->execute([':u' => $username]);
    $user = $stmt->fetch();

    if (!$user || !password_verify($password, $user['password_hash'])) {
        return false; // same response for unknown user vs wrong password
    }

    // Session fixation prevention: regenerate ID on privilege change
    session_regenerate_id(true); // true = delete old session file

    $_SESSION['user_id']  = $user['id'];
    $_SESSION['username']  = $user['username'];
    $_SESSION['role']      = $user['role'];
    $_SESSION['login_time'] = time();

    // Re-hash if cost factor has increased since last login
    if (password_needs_rehash($user['password_hash'], PASSWORD_BCRYPT, ['cost' => 12])) {
        $newHash = password_hash($password, PASSWORD_BCRYPT, ['cost' => 12]);
        $stmt = $pdo->prepare('UPDATE users SET password_hash = ? WHERE id = ?');
        $stmt->execute([$newHash, $user['id']]);
    }

    return true;
}

function logout(): void
{
    // Clear session data, invalidate cookie, destroy server-side data
    $_SESSION = [];
    session_regenerate_id(true);
    setcookie(session_name(), '', time() - 3600, '/', '', true, true);
    session_destroy();
}

function requireAuth(string ...$roles): void
{
    if (empty($_SESSION['user_id'])) {
        header('Location: /login.php');
        exit;
    }
    if (!empty($roles) && !in_array($_SESSION['role'], $roles, true)) {
        http_response_code(403);
        exit('Access denied');
    }
}
// Usage: requireAuth('admin'); requireAuth('admin', 'moderator');

Password Hashing

passwords.php
<?php
// PASSWORD_BCRYPT: slow by design, adaptive cost factor
// PASSWORD_ARGON2ID: memory-hard, recommended for new apps

$hash = password_hash('hunter2', PASSWORD_BCRYPT, ['cost' => 12]);
// $2y$12$... -- includes algorithm, cost, and salt automatically

var_dump(password_verify('hunter2',  $hash)); // bool(true)
var_dump(password_verify('wrong',    $hash)); // bool(false)

// What NOT to do -- never use these for passwords:
// md5($password)       -- broken, fast, rainbow tables trivial
// sha1($password)      -- broken
// sha256($password)    -- fast hash, not a KDF, still vulnerable to brute force
// md5(md5($password))  -- still trivially broken

// Argon2id (PHP 7.3+, preferred for new systems)
$hash2 = password_hash('hunter2', PASSWORD_ARGON2ID, [
    'memory_cost' => 65536, // 64 MB
    'time_cost'   => 4,
    'threads'     => 3,
]);

Secure Cookies

cookies.php
<?php
// setcookie($name, $value, $options_array) -- PHP 7.3+ syntax
setcookie('remember_token', bin2hex(random_bytes(32)), [
    'expires'  => time() + (30 * 24 * 3600), // 30 days
    'path'     => '/',
    'secure'   => true,   // HTTPS only -- never send over HTTP
    'httponly' => true,   // not readable by JavaScript (XSS mitigation)
    'samesite' => 'Strict', // not sent on cross-site requests (CSRF mitigation)
]);

// Reading a cookie (always treat as untrusted)
$token = $_COOKIE['remember_token'] ?? '';
if (!preg_match('/^[0-9a-f]{64}$/', $token)) {
    // Reject anything that does not match expected hex format
    $token = '';
}
Session Fixation Attack

An attacker creates a session ID, tricks a user into logging in with it, then hijacks the authenticated session. The defense is session_regenerate_id(true) immediately after successful authentication -- this invalidates the old ID.

JWT Basics (Token-Based Auth)

JSON Web Tokens (JWT) are used for stateless authentication -- common in APIs. A JWT has three base64url-encoded parts: Header, Payload, and Signature. The server verifies the signature to validate the token without storing session state.

jwt_structure.php
<?php
// JWT structure: header.payload.signature
// All parts are base64url-encoded, separated by dots

// Header: algorithm + token type
$header  = base64_encode(json_encode(['alg'=>'HS256','typ'=>'JWT']));

// Payload: claims (do not put passwords or sensitive data here -- it's readable!)
$payload = base64_encode(json_encode([
    'sub' => 42,           // subject (user ID)
    'iat' => time(),       // issued at
    'exp' => time()+3600,  // expiry (1 hour)
    'role'=> 'admin',
]));

// Signature: HMAC-SHA256 of header.payload with a secret key
$secret    = getenv('JWT_SECRET'); // 32+ random bytes
$signature = base64_encode(hash_hmac('sha256', "$header.$payload", $secret, true));

$jwt = "$header.$payload.$signature";

// Verification: split, re-sign, compare with hash_equals
// Use a library: firebase/php-jwt or lcobucci/jwt in real projects
// Never implement JWT manually in production code

// Common JWT vulnerabilities to know for pen testing:
// 1. alg:none attack -- remove signature, change alg to "none"
// 2. Weak secrets -- brute-forced with hashcat in seconds
// 3. Algorithm confusion -- RS256 vs HS256 key confusion
// 4. Missing expiry check -- tokens valid forever

Try It Yourself

Build a complete PHP login system that:

  1. Configures session with all security flags before session_start()
  2. Fetches the user by username and verifies the password with password_verify()
  3. Calls session_regenerate_id(true) on successful login
  4. Implements a requireAuth() guard that redirects unauthenticated visitors
  5. Implements logout() that destroys session data and invalidates the cookie

Key Takeaways

  • Always use password_hash() with BCRYPT or Argon2id -- never MD5, SHA1, or raw SHA256
  • Call session_regenerate_id(true) immediately after login to prevent session fixation
  • Set HttpOnly, Secure, and SameSite=Strict on all authentication cookies
  • Return the same error message for wrong username and wrong password (prevents user enumeration)
  • JWT payloads are readable (base64) -- never put sensitive data in them, only signed claims
  • Use hash_equals() for all token comparisons -- prevents timing-based attacks
