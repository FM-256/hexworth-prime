Learning Objectives

  • Process GET and POST form submissions in PHP
  • Validate and sanitize all form input using filter_var and custom rules

  • Generate and verify CSRF tokens to protect state-changing actions
  • Redirect after POST (PRG pattern) to prevent duplicate submissions

Processing GET and POST

GET sends data in the URL query string. POST sends data in the request body. Use GET for read-only operations (search, filtering) and POST for state-changing actions (login, form submission, deletion).

contact.php
<?php
declare(strict_types=1);

$errors  = [];
$success = false;

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    // Read raw POST values with safe defaults
    $name    = trim($_POST['name']    ?? '');
    $email   = trim($_POST['email']   ?? '');
    $message = trim($_POST['message'] ?? '');

    // Validate
    if (mb_strlen($name) < 2 || mb_strlen($name) > 100) {
        $errors[] = 'Name must be 2-100 characters.';
    }
    if (!filter_var($email, FILTER_VALIDATE_EMAIL)) {
        $errors[] = 'Invalid email address.';
    }
    if (mb_strlen($message) < 10) {
        $errors[] = 'Message must be at least 10 characters.';
    }

    if (empty($errors)) {
        // Process: save to DB, send email, etc.
        $success = true;
        // PRG: Redirect after POST to prevent re-submission on refresh
        header('Location: /contact.php?sent=1');
        exit;
    }
}

filter_var -- The Validation Toolkit

validation.php
<?php
// FILTER_VALIDATE_* constants
filter_var('alice@example.com', FILTER_VALIDATE_EMAIL);  // string or false
filter_var('192.168.1.1',      FILTER_VALIDATE_IP);      // string or false
filter_var('10.0.0.1',         FILTER_VALIDATE_IP, FILTER_FLAG_IPV4);
filter_var('https://hp.io',    FILTER_VALIDATE_URL);     // string or false
filter_var('42',               FILTER_VALIDATE_INT);     // 42 or false
filter_var('3.14',             FILTER_VALIDATE_FLOAT);   // 3.14 or false

// Range validation for integers
$port = filter_var($_GET['port'] ?? '', FILTER_VALIDATE_INT, [
    'options' => ['min_range' => 1, 'max_range' => 65535]
]);
if ($port === false) {
    $errors[] = 'Invalid port number.';
}

// FILTER_SANITIZE_* -- strip dangerous chars (sanitize != validate)
$clean = filter_var($_POST['name'] ?? '', FILTER_SANITIZE_SPECIAL_CHARS);

// Custom whitelist -- safest approach for constrained values
$allowed = ['asc', 'desc'];
$sort = in_array($_GET['sort'] ?? '', $allowed, true)
    ? $_GET['sort']
    : 'asc';

CSRF Token Protection

Cross-Site Request Forgery (CSRF) tricks an authenticated user's browser into sending requests to your app. The defense is a secret, unpredictable token embedded in every state-changing form.

csrf.php
<?php
session_start();

function generateCsrfToken(): string
{
    if (empty($_SESSION['csrf_token'])) {
        $_SESSION['csrf_token'] = bin2hex(random_bytes(32));
    }
    return $_SESSION['csrf_token'];
}

function verifyCsrfToken(string $token): bool
{
    $stored = $_SESSION['csrf_token'] ?? '';
    // hash_equals: constant-time comparison prevents timing attacks
    return hash_equals($stored, $token);
}

// Verify on POST requests
if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $token = $_POST['csrf_token'] ?? '';
    if (!verifyCsrfToken($token)) {
        http_response_code(403);
        exit('CSRF token mismatch');
    }
}
?>

<!-- Embed token in every form -->
<form method="post">
  <input type="hidden" name="csrf_token"
         value="<?php echo htmlspecialchars(generateCsrfToken()); ?>">
  <!-- form fields... -->
</form>

Secure File Uploads

File uploads are one of the most dangerous PHP features. An attacker who can upload a .php file and access it via the browser has Remote Code Execution.

upload.php
<?php
declare(strict_types=1);

// Never rely on client-supplied MIME type ($_FILES['mime']) -- spoofable
// Use finfo for server-side MIME detection

$allowedTypes = ['image/jpeg', 'image/png', 'image/gif'];
$maxSize      = 2 * 1024 * 1024; // 2 MB
$uploadDir    = '/var/uploads/'; // outside web root!

if (isset($_FILES['avatar']) && $_FILES['avatar']['error'] === UPLOAD_ERR_OK) {
    $tmpPath = $_FILES['avatar']['tmp_name'];
    $size    = $_FILES['avatar']['size'];

    // 1. Check size limit
    if ($size > $maxSize) { exit('File too large'); }

    // 2. Detect MIME from file contents, not extension
    $finfo    = new finfo(FILEINFO_MIME_TYPE);
    $mimeType = $finfo->file($tmpPath);
    if (!in_array($mimeType, $allowedTypes, true)) {
        exit('Invalid file type');
    }

    // 3. Generate random filename -- never use client-supplied name
    $ext      = match($mimeType) {
        'image/jpeg' => '.jpg',
        'image/png'  => '.png',
        'image/gif'  => '.gif',
    };
    $safeName = bin2hex(random_bytes(16)) . $ext;
    $destPath = $uploadDir . $safeName;

    // 4. Move from temp -- move_uploaded_file() validates it was a real upload
    if (!move_uploaded_file($tmpPath, $destPath)) {
        exit('Upload failed');
    }

    echo "Uploaded: {$safeName}\n";
}
Never store uploads inside the web root

Store uploaded files in a directory outside the Apache/Nginx document root. Serve them through a PHP controller that checks access permissions. This prevents direct URL access to uploaded files.

Try It Yourself

Build a complete registration form handler that:

  1. Accepts username (alphanumeric, 3-20 chars), email (valid format), and password (8+ chars)
  2. Includes CSRF token generation and verification
  3. Returns all validation errors in an array rather than exiting on first failure
  4. On success, hashes the password with password_hash() and redirects with PRG pattern
  5. Never echoes raw $_POST values directly into HTML -- use htmlspecialchars

Key Takeaways

  • Check $_SERVER['REQUEST_METHOD'] === 'POST' before processing form submissions
  • Use filter_var() with FILTER_VALIDATE_* constants for type and format validation
  • CSRF tokens use random_bytes(32) + hash_equals() -- never string equality
  • Redirect after POST (PRG pattern) to prevent double-submission on browser refresh
  • Validate upload MIME type server-side with finfo -- never trust client-supplied type
  • Always generate random filenames for uploads and store files outside the web root
