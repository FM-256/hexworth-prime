Sigils -- Reading Perl's Variables

Perl variables are prefixed with sigils that indicate their type. The sigil also changes based on what you are accessing, which trips up beginners.

$
Scalar
Single value: string, number, or reference. Also used to access one element of an array or hash.
@
Array
Ordered list of scalars. Use $ when accessing one element: $array[0]
%
Hash
Key-value pairs. Use $ when accessing one value: $hash{key}
variables.pl -- Perl
use strict;
use warnings;

# Scalars
my $host  = "10.0.0.1";
my $port  = 443;
my $ratio = 3.14;

# Arrays (0-indexed)
my @ports = (22, 80, 443, 8080);
print $ports[0];     # 22  -- $ sigil for single element
print scalar @ports; # 4   -- scalar context gives length

# Hashes
my %service = (
    name  => "HTTPS",
    port  => 443,
    secure => 1,
);
print $service{name};  # HTTPS -- curly braces for hash
print $service{port};  # 443

# String interpolation in double quotes
print "Host: $host, Port: $port\n";
print "Array: @ports\n";   # prints all elements space-separated

Regex -- Perl's Superpower

Perl's regex engine is the gold standard. It supports lookahead, lookbehind, named captures, non-greedy matching, and POSIX classes. The m// operator matches, s/// substitutes, tr/// transliterates.

regex.pl -- Perl
my $log = "2026-03-16 10:42:33 ERROR 192.168.1.55 login_failed";

# Basic match -- =~ binds string to regex
if ($log =~ /ERROR/) {
    print "Found an error\n";
}

# Capture groups -- $1, $2 hold matches
if ($log =~ /(\d{4}-\d{2}-\d{2}) (\d{2}:\d{2}:\d{2})/) {
    print "Date: $1, Time: $2\n";
}

# Named captures (cleaner for complex patterns)
if ($log =~ /(?<ip>\d+\.\d+\.\d+\.\d+)/) {
    print "IP: $+{ip}\n";   # 192.168.1.55
}

# Substitution -- s/pattern/replacement/flags
my $redacted = $log;
$redacted =~ s/\d+\.\d+\.\d+\.\d+/[REDACTED]/g;
print $redacted, "\n";

# Global match in list context -- returns all matches
my $text = "ports: 22 80 443 3389 8080";
my @found_ports = ($text =~ /(\d+)/g);
print "Ports: @found_ports\n";   # 22 80 443 3389 8080

File Handling

Perl file I/O uses filehandles. The <> diamond operator reads lines from STDIN or files -- the backbone of most Perl data pipelines.

fileio.pl -- Perl
use strict;
use warnings;

# Open for reading -- die on failure with file/line info
open(my $fh, '<', '/var/log/auth.log') or die "Cannot open: $!";

my $fail_count = 0;
while (my $line = <$fh>) {
    chomp $line;   # remove trailing newline
    if ($line =~ /Failed password/) {
        $fail_count++;
        print "ALERT: $line\n";
    }
}
close($fh);
print "Total failures: $fail_count\n";

# Write to file
open(my $out, '>', 'report.txt') or die "$!";
print $out "Total SSH failures: $fail_count\n";
close($out);

One-Liners

Perl's -e, -n, and -p flags enable powerful one-line programs. A skilled Perl operator can replace entire shell pipelines in a single command.

terminal -- Perl one-liners
# Print lines matching a pattern
$ perl -ne 'print if /Failed password/' /var/log/auth.log

# Count matching lines
$ perl -ne '$c++ if /Failed/; END{print "$c\n"}' auth.log

# Extract and print IPs from log
$ perl -ne 'print "$1\n" if /(\d+\.\d+\.\d+\.\d+)/' auth.log

# In-place substitution (-i edits the file directly)
$ perl -i -pe 's/password/[REDACTED]/gi' config.txt

# Sum a column of numbers (awk replacement)
$ perl -ane '$s+=$F[2]; END{print "$s\n"}' data.csv

# Print unique lines (sort | uniq replacement)
$ perl -ne 'print unless $seen{$_}++' file.txt
Flags Reference

-e execute code, -n loop over lines without printing, -p loop and auto-print, -a auto-split into @F, -i in-place edit, -l auto-chomp and add newlines.

Try It Yourself

  1. Write a Perl script that reads /etc/passwd and prints the username and shell for each user
  2. Use a one-liner to extract all email addresses from a text file (pattern: \w+@\w+\.\w+)
  3. Write a hash that maps service names to port numbers, then sort and print all entries
  4. Use s///g to sanitize a log file by replacing all IPv4 addresses with [IP]

Key Takeaways

  • Always use strict; use warnings; -- they catch the majority of common Perl mistakes
  • Sigils change based on context: $array[0] (scalar element) vs @array (whole array)
  • Perl's regex engine is unmatched -- named captures, lookahead, and non-greedy matching all built in
  • The diamond operator <> and -n flag make line-by-line log processing trivial
  • One-liners with -i -pe can perform in-place file edits -- powerful and irreversible, test first
