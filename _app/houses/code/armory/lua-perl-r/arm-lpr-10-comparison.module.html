Performance Characteristics

Raw performance matters in different ways for each language. LuaJIT is genuinely fast. Perl is fast for I/O-heavy text work. R is slow for loops but fast for vectorized operations.

Relative performance: parsing 1 million lines of text (higher = faster)

~2.1s
Perl
~2.8s
R (readLines)
~5.5s

R vectorized operations on data frames (sum, mean, filter) are compiled C code and perform similarly to Perl for numeric work. The penalty is in explicit for-loops -- avoid them in R.

The Same Task in All Three

Count the occurrences of each word in a text file -- a simple but illustrative task that reveals each language's idioms.

word_count.lua Lua
local counts = {}
for line in io.lines("text.txt") do
    for word in line:gmatch("%a+") do
        word = word:lower()
        counts[word] = (counts[word] or 0) + 1
    end
end
-- Collect and sort by count descending
local sorted = {}
for w, c in pairs(counts) do
    sorted[#sorted+1] = {word=w, count=c}
end
table.sort(sorted, function(a,b) return a.count > b.count end)
for i = 1, math.min(5, #sorted) do
    print(sorted[i].count, sorted[i].word)
end
word_count.pl Perl
use strict; use warnings;
my %counts;
while (<>) {
    $counts{lc $_}++ for /([a-z]+)/gi;
}
printf "%5d  %s\n", $counts{$_}, $_
    for (sort { $counts{$b} <=> $counts{$a} } keys %counts)[0..4];
word_count.R R
library(stringr)
text  <- tolower(paste(readLines("text.txt"), collapse = " "))
words <- str_extract_all(text, "[a-z]+")[[1]]
counts <- sort(table(words), decreasing = TRUE)
print(head(counts, 5))

Perl wins on brevity for this file-processing task. R wins on readability and built-in statistical framing. Lua is the most explicit -- appropriate when you need predictable performance in an embedded context.

Interop Patterns

Real workflows often chain languages. These are the standard interop paths:

interop patterns
# Perl generates data, R analyzes it
$ perl parse_logs.pl access.log > metrics.csv
$ Rscript analyze.R metrics.csv

# Lua embedded in C: load and call a Lua function
# In C:
#   lua_State *L = luaL_newstate();
#   luaL_dofile(L, "config.lua");
#   lua_getglobal(L, "get_rules");
#   lua_pcall(L, 0, 1, 0);

# Python calls R via subprocess (quick and dirty)
$ python3 -c "import subprocess; subprocess.run(['Rscript', 'report.R'])"

# rpy2 package: call R from Python in-process
$ pip install rpy2
$ python3 -c "import rpy2.robjects as r; r.r('summary(mtcars)')"

Key Takeaways

  • Lua wins at embedded scripting -- if you are inside another application, Lua is usually the answer
  • Perl wins at one-liners and complex regex -- text forensics and log parsing are its natural habitat
  • R wins at statistical analysis and visualization -- no other scripting language matches its data analysis depth
  • All three are stable, mature, and available on any Linux system without installation friction
  • The best tool is the one that solves the problem in the fewest lines while remaining readable to the next operator
