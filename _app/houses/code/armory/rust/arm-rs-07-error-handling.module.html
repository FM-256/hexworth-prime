Recoverable Errors: Result<T, E>

Rust has no exceptions. Recoverable errors are represented as Result<T, E> -- an enum with Ok(T) for success and Err(E) for failure. Every function that can fail returns a Result, and the compiler forces callers to handle it.

src/main.rs -- Result basics
use std::num::ParseIntError;

fn parse_port(s: &str) -> Result<u16, ParseIntError> {
    // parse() returns Result -- we return it directly
    s.trim().parse::<u16>()
}

fn main() {
    // Handle with match
    match parse_port("443") {
        Ok(port)  => println!("Port: {}", port),
        Err(e)    => println!("Parse error: {}", e),
    }

    // Handle with if let
    if let Ok(port) = parse_port("8080") {
        println!("Parsed: {}", port);
    }

    // unwrap_or -- default on error
    let port = parse_port("invalid").unwrap_or(80);
    println!("Defaulted to: {}", port);

    // unwrap() -- panics on Err, only use when you know it's safe
    let https = parse_port("443").unwrap();
    println!("HTTPS port: {}", https);
}

The ? Operator

The ? operator is shorthand for "return the error if this failed, otherwise unwrap the success value." It makes error propagation concise without hiding the fact that errors can occur.

src/main.rs -- the ? operator
use std::io;
use std::num::ParseIntError;
use std::fmt;

// A simple combined error type for demonstration
#[derive(Debug)]
enum ConfigError {
    Io(io::Error),
    Parse(ParseIntError),
    InvalidPort(u32),
}

impl fmt::Display for ConfigError {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
            ConfigError::Io(e)          => write!(f, "IO error: {}", e),
            ConfigError::Parse(e)       => write!(f, "Parse error: {}", e),
            ConfigError::InvalidPort(p) => write!(f, "Invalid port: {}", p),
        }
    }
}

impl From<io::Error> for ConfigError {
    fn from(e: io::Error) -> Self { ConfigError::Io(e) }
}

impl From<ParseIntError> for ConfigError {
    fn from(e: ParseIntError) -> Self { ConfigError::Parse(e) }
}

// ? operator propagates errors up -- clean, explicit error handling
fn load_port_config(input: &str) -> Result<u16, ConfigError> {
    let raw: u32 = input.trim().parse()? ;   // ? converts ParseIntError -> ConfigError

    if raw > 65535 {
        return Err(ConfigError::InvalidPort(raw));
    }

    Ok(raw as u16)
}

fn main() {
    let inputs = ["443", "99999", "not_a_number"];

    for input in &inputs {
        match load_port_config(input) {
            Ok(p)  => println!("Port: {}", p),
            Err(e) => println!("Error: {}", e),
        }
    }
}

Result Combinators

Results support functional chaining with combinators, letting you transform and compose error-handling logic without verbose match blocks.

src/main.rs -- Result combinators
fn main() {
    let input = "  443  ";

    // Chain operations -- each step only runs if previous succeeded
    let result: Result<String, _> = input
        .trim()
        .parse::<u16>()
        .map(|p| format!("Port {} is {}", p,
            if p == 443 { "HTTPS" } else { "other" }))
        .map_err(|e| format!("Failed to parse: {}", e));

    println!("{:?}", result);

    // and_then -- chain Results (flatMap)
    let validated = "8080"
        .parse::<u32>()
        .map_err(|e| e.to_string())
        .and_then(|p| {
            if p > 65535 {
                Err(format!("Port {} out of range", p))
            } else {
                Ok(p as u16)
            }
        });

    println!("Validated: {:?}", validated);

    // collect() on an iterator of Results
    let port_strings = vec!["22", "80", "443"];
    let ports: Result<Vec<u16>, _> = port_strings
        .iter()
        .map(|s| s.parse::<u16>())
        .collect();
    println!("All ports: {:?}", ports);
}

Unrecoverable Errors: panic!

Use panic! only for bugs (invariant violations) -- never for user input or network errors. In production code, almost all errors should go through Result. The unwrap() and expect() methods panic if the value is Err or None.

When to panic vs. return Result:

Panic when the program reaches a state that should never be possible (e.g., array index you know is valid, invariant your own code maintains). Return Result for anything that can go wrong due to external input, IO, or network conditions. Security tools that panic on invalid user input are a DoS vulnerability.

Try It Yourself

Write a function that parses a connection string like "10.0.0.1:8443":

  1. Define a custom error enum ConnError with variants MissingPort, InvalidPort(String), InvalidHost(String)

  3. Use ? where applicable and return appropriate error variants
  4. Test with valid input, a missing port, and a port number above 65535

Key Takeaways

  • Rust has no exceptions -- recoverable errors use Result<T, E>
  • The compiler forces you to handle every Result -- no silent error swallowing
  • The ? operator propagates errors up the call stack cleanly
  • Implement From conversions so ? can auto-convert error types
  • Use panic! only for programming bugs, never for user input failures
  • Result combinators (map, and_then, map_err) enable clean functional error chains
