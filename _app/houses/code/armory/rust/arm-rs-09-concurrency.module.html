Fearless Concurrency

Rust's ownership system prevents data races at compile time. A data race occurs when two threads access the same memory concurrently and at least one of them writes. The borrow checker's rules -- one writer or many readers, never both -- make this impossible without unsafe code.

Why this matters for security tools:

Port scanners, log analyzers, and network monitors are naturally concurrent. Race conditions in security tools can cause missed alerts, corrupted logs, or exploitable behavior. Rust's type system gives you concurrency without these failure modes.

Threads

Rust creates OS threads with std::thread::spawn. The closure passed to spawn must be move if it captures any values -- this transfers ownership into the thread rather than borrowing, which would be unsafe across thread boundaries.

src/main.rs -- threads
use std::thread;
use std::time::Duration;

fn main() {
    let targets = vec!["10.0.0.1", "10.0.0.2", "10.0.0.3"];
    let mut handles = Vec::new();

    for target in targets {
        // move transfers ownership of target into the closure
        let handle = thread::spawn(move || {
            // Simulate scanning target
            thread::sleep(Duration::from_millis(100));
            format!("Scanned {} -- ports 22,80 open", target)
        });
        handles.push(handle);
    }

    // Join all threads and collect results
    for handle in handles {
        match handle.join() {
            Ok(result) => println!("Result: {}", result),
            Err(_)     => println!("Thread panicked"),
        }
    }
}

Channels: Message Passing

std::sync::mpsc (multiple producer, single consumer) provides a channel for passing values between threads. Sending ownership through a channel is safe -- the data moves into the channel and out to the receiver.

src/main.rs -- channels
use std::sync::mpsc;
use std::thread;

fn main() {
    let (tx, rx) = mpsc::channel();

    // Spawn worker threads -- each gets a clone of the sender
    let ports_to_check = vec![22u16, 80, 443, 3389, 8080];

    for port in ports_to_check {
        let tx_clone = tx.clone();
        thread::spawn(move || {
            // Simulate port check result
            let is_open = port % 2 == 0;  // placeholder logic
            if is_open {
                tx_clone.send(format!("OPEN:{}", port)).unwrap();
            }
        });
    }

    // Drop original tx so the channel closes when all clones drop
    drop(tx);

    // Collect results as they arrive
    let mut open_ports = Vec::new();
    for msg in rx {
        open_ports.push(msg);
    }
    println!("Open ports: {:?}", open_ports);
}

Shared State: Arc and Mutex

When threads need to share ownership of data, use Arc<T> (Atomic Reference Counted) for shared ownership. To allow mutation, wrap the inner data with Mutex<T>. The combination Arc<Mutex<T>> is the standard pattern for shared mutable state.

src/main.rs -- Arc and Mutex
use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    // Shared counter across multiple threads
    let alert_count = Arc::new(Mutex::new(0u32));
    let mut handles = Vec::new();

    for i in 0..8 {
        let counter = Arc::clone(&alert_count);
        let handle = thread::spawn(move || {
            // Lock the mutex -- blocks until lock is acquired
            let mut count = counter.lock().unwrap();
            *count += 1;
            println!("Thread {} incremented count to {}", i, *count);
        }); // MutexGuard drops here, releasing the lock
        handles.push(handle);
    }

    for h in handles { h.join().unwrap(); }

    let final_count = alert_count.lock().unwrap();
    println!("Total alerts: {}", *final_count);
}

async/await and Tokio

OS threads are expensive for I/O-bound work like network scanning. Rust's async/await enables cooperative multitasking using lightweight tasks. The tokio crate is the standard async runtime for production Rust code.

Cargo.toml -- add tokio dependency
[dependencies]
tokio = { version = "1", features = ["full"] }
src/main.rs -- async/await with tokio
use tokio::net::TcpStream;
use tokio::time::{timeout, Duration};

// async fn -- returns a Future, does not run until awaited
async fn check_port(host: &str, port: u16) -> (u16, bool) {
    let addr = format!("{}:{}", host, port);
    let result = timeout(
        Duration::from_millis(500),
        TcpStream::connect(&addr as &str)
    ).await;

    (port, result.is_ok() && result.unwrap().is_ok())
}

// #[tokio::main] sets up the async runtime
#[tokio::main]
async fn main() {
    let host = "127.0.0.1";
    let ports = [22u16, 80, 443, 8080];

    // Spawn concurrent async tasks
    let mut tasks = Vec::new();
    for port in &ports {
        tasks.push(tokio::spawn(check_port(host, *port)));
    }

    // Await all tasks
    for task in tasks {
        if let Ok((port, open)) = task.await {
            println!("Port {:5}: {}", port, if open { "OPEN" } else { "closed" });
        }
    }
}

  1. Create a shared Arc<Mutex<Vec<String>>> to hold critical alerts

Key Takeaways

  • Rust prevents data races at compile time via the ownership and borrowing rules
  • Use thread::spawn with move closures to run code on OS threads
  • mpsc::channel enables safe message passing between threads
  • Arc<Mutex<T>> is the standard pattern for shared mutable state across threads
  • async/await with tokio is preferable for I/O-bound work like network scanning
  • The Send and Sync traits mark what types can cross thread boundaries safely
