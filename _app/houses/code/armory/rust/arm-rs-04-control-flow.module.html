if / else

Rust's if works like most languages, but with one important difference: it is an expression that returns a value. No ternary operator needed.

src/main.rs -- if as expression
fn main() {
    let port: u16 = 443;

    // if as a statement
    if port < 1024 {
        println!("Privileged port -- requires root");
    } else if port < 49152 {
        println!("Registered port");
    } else {
        println!("Dynamic/ephemeral port");
    }

    // if as an expression -- returns a value
    let protocol = if port == 443 { "HTTPS" } else if port == 80 { "HTTP" } else { "Unknown" };
    println!("Port {} runs {}", port, protocol);
}

match: Exhaustive Pattern Matching

The match expression is Rust's supercharged switch statement. Every possible case must be covered -- the compiler rejects non-exhaustive matches. This is critical for security code where missing a case (e.g., an error state) can be a vulnerability.

src/main.rs -- match
fn classify_port(port: u16) -> &'static str {
    match port {
        21          => "FTP -- unencrypted, avoid",
        22          => "SSH -- encrypted shell",
        23          => "Telnet -- unencrypted, dangerous",
        80          => "HTTP -- unencrypted web",
        443         => "HTTPS -- encrypted web",
        3389        => "RDP -- remote desktop",
        1..=1023    => "Other privileged port",  // range pattern
        _           => "Unprivileged port",          // wildcard (must be last)
    }
}

fn main() {
    for port in &[22u16, 23, 443, 8080] {
        println!("{:5} -> {}", port, classify_port(*port));
    }
}
src/main.rs -- match with bindings
fn main() {
    let score: u32 = 87;

    // Bind the matched value to a name with @
    let grade = match score {
        n @ 90..=100 => format!("A ({})", n),
        n @ 80..=89  => format!("B ({})", n),
        n @ 70..=79  => format!("C ({})", n),
        n              => format!("F ({})", n),
    };
    println!("Grade: {}", grade);
}

Loops

Rust has three loop constructs. loop runs forever until an explicit break. while loops on a condition. for iterates over a range or collection.

src/main.rs -- loops
fn main() {
    // loop -- returns a value from break
    let mut attempts = 0;
    let result = loop {
        attempts += 1;
        if attempts >= 3 {
            break "connection established";
        }
    };
    println!("After {} attempts: {}", attempts, result);

    // while
    let mut ttl = 64u8;
    while ttl > 0 {
        ttl = ttl.saturating_sub(1);
    }
    println!("TTL expired");

    // for over a range
    for octet in 1..5 {
        println!("192.168.1.{}", octet);
    }

    // for over a collection with index
    let services = ["ssh", "http", "dns"];
    for (i, svc) in services.iter().enumerate() {
        println!("{}: {}", i, svc);
    }
}

Functions

Functions in Rust require explicit type annotations on parameters and return values. The last expression in a function body is automatically the return value (no semicolon). Use return for early returns.

src/main.rs -- functions
// Parameter types and return type required
fn is_private_ip(ip: &str) -> bool {
    ip.starts_with("10.")
        || ip.starts_with("172.16.")
        || ip.starts_with("192.168.")
}

// Multiple return values via tuple
fn parse_host_port(addr: &str) -> (&str, u16) {
    let parts: Vec<&str> = addr.splitn(2, ':').collect();
    let host = parts[0];
    let port: u16 = parts.get(1)
        .and_then(|p| p.parse().ok())
        .unwrap_or(80);
    (host, port)
}

fn main() {
    println!("10.0.0.1 private: {}", is_private_ip("10.0.0.1"));
    println!("8.8.8.8 private: {}", is_private_ip("8.8.8.8"));

    let (host, port) = parse_host_port("example.com:8443");
    println!("Host: {}  Port: {}", host, port);
}

Closures and Iterators

Closures are anonymous functions that can capture variables from their surrounding scope. They are the backbone of Rust's powerful iterator API, which lets you write expressive, zero-cost data transformation pipelines.

src/main.rs -- closures and iterators
fn main() {
    let log_lines = vec![
        "INFO 2026-03-15 Login successful user=alice",
        "WARN 2026-03-15 Failed login user=bob",
        "CRIT 2026-03-15 SQL injection attempt detected",
        "INFO 2026-03-15 File downloaded user=alice",
        "CRIT 2026-03-15 Privilege escalation blocked",
    ];

    // Filter to critical events, collect into new Vec
    let critical: Vec<&str> = log_lines
        .iter()
        .filter(|line| line.starts_with("CRIT"))
        .cloned()
        .collect();

    println!("Critical events: {}", critical.len());

    // Map to extract just the descriptions after the date
    let descriptions: Vec<&str> = log_lines
        .iter()
        .filter_map(|line| line.split_once("2026-03-15 ").map(|(_, desc)| desc))
        .collect();

    for desc in &descriptions {
        println!("  - {}", desc);
    }

    // Count events by level using fold
    let critical_count = log_lines
        .iter()
        .filter(|l| l.starts_with("CRIT"))
        .count();
    println!("CRIT count: {}", critical_count);

    // Closures can capture variables from the environment
    let threshold = "WARN";
    let above_warn: Vec<&&str> = log_lines
        .iter()
        .filter(|l| l.starts_with(threshold) || l.starts_with("CRIT"))
        .collect();
    println!("Warn+ events: {}", above_warn.len());
}

Key Takeaways

  • if is an expression in Rust -- it returns a value
  • match is exhaustive -- the compiler rejects missing cases
  • loop can return a value via break value;
  • Function parameters and return types must always have explicit type annotations
  • The last expression in a function body (without semicolon) is the return value
  • Closures capture their environment; iterator adaptors like filter and map are lazy and zero-cost
