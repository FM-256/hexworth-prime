Defining Structs

Structs let you group related data into a named type. They are the primary way to create custom data structures in Rust -- the foundation of everything from network packets to user records.

src/main.rs -- struct definition
// Derive Debug to enable println! with {:?}
// Derive Clone to enable .clone()
#[derive(Debug, Clone)]
struct NetworkHost {
    hostname: String,
    ip: String,
    port: u16,
    is_tls: bool,
}

fn main() {
    // Create an instance with field: value syntax
    let host = NetworkHost {
        hostname: String::from("webserver-01"),
        ip: String::from("10.0.0.50"),
        port: 443,
        is_tls: true,
    };

    // Access fields with dot notation
    println!("{}:{} tls={}", host.ip, host.port, host.is_tls);

    // Debug print the whole struct
    println!("{:#?}", host);

    // Struct update syntax -- copy fields from another instance
    let host2 = NetworkHost {
        hostname: String::from("webserver-02"),
        ip: String::from("10.0.0.51"),
        ..host.clone()    // copy remaining fields from host
    };
    println!("Host2: {} ({})", host2.hostname, host2.ip);
}

impl Blocks and Methods

Methods are functions associated with a struct, defined in an impl block. Methods that take &self are read-only; those taking &mut self can modify the struct. Associated functions (like constructors) take no self.

src/main.rs -- impl block
#[derive(Debug)]
struct PortScan {
    target: String,
    open_ports: Vec<u16>,
    scan_time_ms: u64,
}

impl PortScan {
    // Associated function (constructor) -- called as PortScan::new()
    pub fn new(target: &str) -> Self {
        PortScan {
            target: target.to_string(),
            open_ports: Vec::new(),
            scan_time_ms: 0,
        }
    }

    // Method that mutates the struct
    pub fn add_port(&mut self, port: u16) {
        self.open_ports.push(port);
    }

    // Read-only method
    pub fn has_risky_ports(&self) -> bool {
        let risky = [21u16, 23, 3389, 5900];
        self.open_ports.iter().any(|p| risky.contains(p))
    }

    pub fn summary(&self) -> String {
        format!("{} -- {} open ports, risky={}",
            self.target, self.open_ports.len(), self.has_risky_ports())
    }
}

fn main() {
    let mut scan = PortScan::new("192.168.1.1");
    scan.add_port(22);
    scan.add_port(80);
    scan.add_port(3389);
    println!("{}", scan.summary());
}

Enums with Associated Data

Rust enums are far more powerful than enums in most languages. Each variant can hold different types and amounts of data. This makes them perfect for modeling states, protocols, and events that carry varying information.

src/main.rs -- enums
#[derive(Debug)]
enum SecurityEvent {
    LoginAttempt { user: String, success: bool },
    PortScan { source_ip: String, port_count: u32 },
    FileAccess { path: String, operation: String },
    UnknownTraffic(Vec<u8>),
}

fn describe_event(event: &SecurityEvent) -> String {
    match event {
        SecurityEvent::LoginAttempt { user, success } => {
            format!("Login {} for user {}",
                if *success { "SUCCESS" } else { "FAILED" }, user)
        }
        SecurityEvent::PortScan { source_ip, port_count } => {
            format!("Port scan from {} ({} ports)", source_ip, port_count)
        }
        SecurityEvent::FileAccess { path, operation } => {
            format!("{} on {}", operation, path)
        }
        SecurityEvent::UnknownTraffic(data) => {
            format!("Unknown traffic ({} bytes)", data.len())
        }
    }
}

fn main() {
    let events = vec![
        SecurityEvent::LoginAttempt { user: String::from("root"), success: false },
        SecurityEvent::PortScan { source_ip: String::from("10.5.0.99"), port_count: 1024 },
        SecurityEvent::FileAccess { path: String::from("/etc/passwd"), operation: String::from("READ") },
    ];

    for event in &events {
        println!("[EVENT] {}", describe_event(event));
    }
}

Option<T>: No Null Pointers

Rust has no null. Instead, optional values use Option<T>, an enum with two variants: Some(value) and None. The compiler forces you to handle both cases, eliminating null pointer dereferences.

src/main.rs -- Option<T>
fn find_user(name: &str) -> Option<String> {
    let users = ["alice", "bob", "charlie"];
    if users.contains(&name) {
        Some(format!("uid={}@corp.local", name))
    } else {
        None
    }
}

fn main() {
    // match to handle both cases
    match find_user("alice") {
        Some(uid) => println!("Found: {}", uid),
        None      => println!("User not found"),
    }

    // if let -- cleaner when only one case matters
    if let Some(uid) = find_user("bob") {
        println!("Bob's UID: {}", uid);
    }

    // unwrap_or -- provide a default
    let uid = find_user("ghost").unwrap_or(String::from("unknown"));
    println!("Ghost UID: {}", uid);

    // map -- transform the inner value if present
    let upper = find_user("charlie").map(|u| u.to_uppercase());
    println!("{:?}", upper);
}

Key Takeaways

  • Structs group related fields into a named type; impl blocks attach methods
  • Associated functions (no self) are typically used as constructors: Type::new()
  • Rust enums can carry associated data in each variant -- far more powerful than C enums
  • Option<T> replaces null -- Some(T) or None; the compiler forces you to handle both
  • Use if let Some(x) = opt for clean single-case matching
  • .map(), .unwrap_or(), and .and_then() make Option chains ergonomic
