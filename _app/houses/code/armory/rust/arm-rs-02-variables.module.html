Variables and Immutability

In Rust, variables are immutable by default. This is a deliberate design choice that prevents a whole category of bugs where a value is unexpectedly modified. If you try to reassign an immutable variable, the compiler stops you.

src/main.rs
fn main() {
    // Immutable variable -- cannot be reassigned
    let port = 8080;
    println!("Listening on port {}", port);

    // This would fail to compile:
    // port = 9090;  // error: cannot assign twice to immutable variable

    // Mutable variable -- can be reassigned
    let mut connection_count = 0;
    connection_count += 1;
    connection_count += 1;
    println!("Active connections: {}", connection_count);
}

The explicit mut keyword forces you to be intentional about what data changes. This is security-relevant: accidental mutation of a secret key or authentication token becomes a compile-time error, not a runtime surprise.

Shadowing

Shadowing lets you re-declare a variable with the same name, optionally changing its type. This is distinct from mutation -- you are creating a new binding, not modifying the original.

src/main.rs
fn main() {
    let raw_input = "  192.168.1.1  ";

    // Shadow with a new value of the same type
    let raw_input = raw_input.trim();

    // Shadow with a completely different type (str -> usize)
    let raw_input = raw_input.len();

    println!("IP length: {}", raw_input);

    // Shadowing in a transformation pipeline
    let hex_value = "0x1a2b";
    let hex_value = hex_value.trim_start_matches("0x");
    let hex_value = u32::from_str_radix(hex_value, 16).unwrap_or(0);
    println!("Decimal: {}", hex_value);
}

Scalar Types

Rust has four primary scalar types: integers, floating-point numbers, booleans, and characters.

TypeDescriptionRange / Notes
i8, i16, i32, i64, i128Signed integerse.g. i32: -2B to +2B
u8, u16, u32, u64, u128Unsigned integerse.g. u8: 0 to 255
isize, usizePointer-sized integersPlatform-dependent (64-bit on 64-bit OS)
f32, f64Floating pointf64 is the default; IEEE 754
boolBooleantrue or false (1 byte)
charUnicode scalar value4 bytes; e.g. 'A', '\u{1F600}'
src/main.rs -- scalar types in practice
fn main() {
    // Integer types -- choose based on your data range
    let port: u16 = 443;          // ports fit in u16 (0-65535)
    let file_size: u64 = 4_294_967_296; // underscore as visual separator
    let offset: i32 = -128;        // signed for values that can be negative

    // Hex, octal, binary literals
    let flags: u8 = 0b0000_1111;   // binary -- common in network programming
    let magic: u32 = 0x7f45_4c46;  // hex -- ELF magic bytes
    let perms: u32 = 0o755;         // octal -- Unix permissions

    // Float
    let entropy: f64 = 7.92;

    // Boolean
    let is_encrypted: bool = true;

    // char -- single Unicode code point (not a byte)
    let grade: char = 'A';

    println!("Port: {}  Encrypted: {}  Flags: {:08b}", port, is_encrypted, flags);
    println!("ELF magic: 0x{:08x}  Entropy: {:.2}", magic, entropy);
}

Compound Types: Tuples

Tuples group values of different types into a single compound value. They have a fixed length -- once declared, they cannot grow or shrink.

src/main.rs -- tuples
fn main() {
    // A tuple holding an IP, port, and whether it's open
    let endpoint: (&str, u16, bool) = ("10.0.0.1", 22, true);

    // Access by index
    println!("{}:{} open={}", endpoint.0, endpoint.1, endpoint.2);

    // Destructure into named variables
    let (host, port, open) = endpoint;
    println!("Host: {}  Port: {}  Open: {}", host, port, open);

    // Functions often return tuples for multiple values
    let (success, message) = check_port(443);
    println!("Result: {} -- {}", success, message);
}

fn check_port(port: u16) -> (bool, &'static str) {
    if port == 443 {
        (true, "HTTPS -- encrypted")
    } else {
        (false, "Unknown port")
    }
}

Compound Types: Arrays

Arrays in Rust hold a fixed number of elements of the same type. Unlike vectors (covered in Module 8), arrays live on the stack. Rust performs bounds checking on every array access -- accessing out of bounds panics rather than causing undefined behavior like in C.

src/main.rs -- arrays
fn main() {
    // Type annotation: [element_type; length]
    let common_ports: [u16; 5] = [22, 80, 443, 3389, 8080];

    // Access by index
    println!("First port: {}", common_ports[0]);

    // Iterate
    for port in &common_ports {
        println!("Port: {}", port);
    }

    // Initialize all elements to same value
    let buffer = [0u8; 1024];   // 1024 zero bytes -- safe default
    println!("Buffer size: {}", buffer.len());

    // Slice -- a reference to part of an array
    let slice: &[u16] = &common_ports[1..4];
    println!("Middle ports: {:?}", slice);
}

Type Inference

Rust can infer types in most situations, which keeps code concise without sacrificing type safety. The compiler deduces the type from context. You can always add explicit annotations for clarity.

src/main.rs -- type inference
fn main() {
    // Rust infers these types from the literal values
    let port = 8080;           // i32 by default
    let ratio = 0.95;          // f64 by default
    let is_tls = true;         // bool
    let label = "firewall";    // &str

    // Rust infers the vector type from the first push
    let mut ips = Vec::new();
    ips.push("10.0.0.1");    // now Rust knows: Vec<&str>
    ips.push("10.0.0.2");

    // When inference is ambiguous, annotate explicitly
    let port_u16: u16 = 443;   // explicit when u16 is needed
    let count = ips.len() as u32; // as for type casting

    println!("{} hosts on port {}", count, port_u16);
}

Key Takeaways

  • Variables are immutable by default; use mut to allow reassignment
  • Shadowing re-declares a variable and can change its type -- different from mutation
  • Integer types encode range: u16 for ports, u64 for file sizes, u8 for bytes
  • Array bounds are checked at runtime -- no out-of-bounds memory access possible
  • Type inference keeps code clean; annotate explicitly when ambiguity exists
  • Numeric overflow panics in debug builds -- use wrapping_add etc. for controlled arithmetic
