The Heap Property

A heap is a complete binary tree satisfying a structural ordering constraint. In a min-heap, every parent is less than or equal to its children — the minimum lives at the root. A max-heap inverts this: every parent is greater than or equal to its children.

Because the tree is complete (all levels filled except possibly the last, filled left to right), it maps perfectly onto a flat array — no pointers needed.

Min-Heap Implementation

class MinHeap:
    def __init__(self):
        self.data = []

    def push(self, val):
        """Insert val, then sift up to restore heap property."""
        self.data.append(val)
        self._sift_up(len(self.data) - 1)

    def pop(self):
        """Remove and return minimum. Swap root with last, sift down."""
        if not self.data:
            raise IndexError("pop from empty heap")
        # Swap min to end, shrink array, restore from root
        self._swap(0, len(self.data) - 1)
        val = self.data.pop()
        self._sift_down(0)
        return val

    def peek(self):
        return self.data[0] if self.data else None

    def _sift_up(self, i):
        """Bubble node up while smaller than its parent — O(log n)."""
        while i > 0:
            parent = (i - 1) // 2
            if self.data[i] < self.data[parent]:
                self._swap(i, parent)
                i = parent
            else:
                break

    def _sift_down(self, i):
        """Push node down while larger than smallest child — O(log n)."""
        n = len(self.data)
        while True:
            smallest, left, right = i, 2*i+1, 2*i+2
            if left < n and self.data[left] < self.data[smallest]:
                smallest = left
            if right < n and self.data[right] < self.data[smallest]:
                smallest = right
            if smallest == i:
                break
            self._swap(i, smallest)
            i = smallest

    def _swap(self, i, j):
        self.data[i], self.data[j] = self.data[j], self.data[i]

# Usage
h = MinHeap()
for v in [5, 3, 8, 1, 9, 2]:
    h.push(v)
while h.data:
    print(h.pop(), end=' ')   # 1 2 3 5 8 9
Python's heapq
Python's standard library provides a min-heap via heapq. Use heapq.heappush(h, x), heapq.heappop(h), and heapq.heapify(list). For a max-heap, negate values: push -x, pop and negate the result.

Heapify: Building in O(n)

Inserting n items one at a time costs O(n log n). Floyd's algorithm builds a heap in-place in O(n) by sifting down from the last internal node up to the root.

def heapify(arr):
    """Floyd's bottom-up heap construction — O(n).

    Key insight: leaf nodes (indices n//2 through n-1) already satisfy
    the heap property trivially. Start at the last internal node and
    sift down each subtree root.
    """
    n = len(arr)
    # Last internal node at index n//2 - 1
    for i in range(n // 2 - 1, -1, -1):
        _sift_down(arr, i, n)

def _sift_down(arr, i, n):
    while True:
        smallest, l, r = i, 2*i+1, 2*i+2
        if l < n and arr[l] < arr[smallest]: smallest = l
        if r < n and arr[r] < arr[smallest]: smallest = r
        if smallest == i: break
        arr[i], arr[smallest] = arr[smallest], arr[i]
        i = smallest

# Why O(n)? Most nodes are near the bottom and travel short distances.
# Sum: sum_{h=0}^{log n} (n / 2^h) * h = O(n) — telescoping series.
O(n) vs O(n log n)
The O(n) heapify only applies when building from a complete array at once. If you add elements one by one with push(), you pay O(log n) per element — O(n log n) total. Use heapq.heapify() when you have all data upfront.

Heap Sort

Heap sort achieves O(n log n) worst-case with O(1) extra space — a rare combination. It uses a max-heap to sort in-place: build the heap, then repeatedly extract the maximum to the end of the array.

def heap_sort(arr):
    """In-place O(n log n) sort using max-heap. O(1) extra space."""
    n = len(arr)

    # Phase 1: build max-heap — O(n)
    for i in range(n // 2 - 1, -1, -1):
        _max_sift_down(arr, i, n)

    # Phase 2: extract max to sorted position — O(n log n)
    for end in range(n - 1, 0, -1):
        arr[0], arr[end] = arr[end], arr[0]  # max to sorted region
        _max_sift_down(arr, 0, end)             # restore heap on shrunk range

def _max_sift_down(arr, i, n):
    while True:
        largest, l, r = i, 2*i+1, 2*i+2
        if l < n and arr[l] > arr[largest]: largest = l
        if r < n and arr[r] > arr[largest]: largest = r
        if largest == i: break
        arr[i], arr[largest] = arr[largest], arr[i]
        i = largest

arr = [5, 3, 8, 1, 9, 2, 7]
heap_sort(arr)
print(arr)  # [1, 2, 3, 5, 7, 8, 9]

Priority Queue Applications

import heapq

# --- Dijkstra's shortest path (canonical heap use case) ---
def dijkstra(graph, src):
    dist = {node: float('inf') for node in graph}
    dist[src] = 0
    pq = [(0, src)]  # (distance, node)

    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]: continue  # stale entry
        for v, w in graph[u]:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                heapq.heappush(pq, (dist[v], v))
    return dist

# --- K largest elements --- O(n log k)
def k_largest(nums, k):
    """Min-heap of size k: discard anything smaller than the kth largest."""
    min_h = []
    for x in nums:
        heapq.heappush(min_h, x)
        if len(min_h) > k:
            heapq.heappop(min_h)
    return sorted(min_h, reverse=True)

# --- Merge k sorted lists --- O(N log k)
def merge_k_sorted(lists):
    result, heap = [], []
    for i, lst in enumerate(lists):
        if lst:
            heapq.heappush(heap, (lst[0], i, 0))
    while heap:
        val, li, idx = heapq.heappop(heap)
        result.append(val)
        if idx + 1 < len(lists[li]):
            heapq.heappush(heap, (lists[li][idx+1], li, idx+1))
    return result

Binomial Heaps

A binomial heap is a forest of binomial trees, each satisfying the heap property. A binomial tree B_k has 2^k nodes: B_0 is a single node; B_k is formed by linking two B_{k-1} trees.

# Binomial heap merge (conceptual — linking two B_k trees)
def link_trees(t1, t2):
    """Link two B_k trees into one B_{k+1}. O(1)."""
    if t1.key <= t2.key:
        t2.sibling = t1.child
        t1.child = t2
        t1.degree += 1
        return t1
    else:
        t1.sibling = t2.child
        t2.child = t1
        t2.degree += 1
        return t2

# Key property: a binomial heap with n nodes has at most floor(log n) + 1 trees.
# Binary representation of n maps directly to tree degrees present.
# n = 13 = 1101b -> trees of degree 3, 2, 0 (sizes 8, 4, 1)
When to use binomial heaps
Binomial heaps are useful when you need O(log n) merge of two heaps — binary heaps require O(n) to merge. In practice, binomial heaps appear in mergeable priority queue problems and some graph algorithms. For most applications, Python's heapq (binary heap) is the right choice.

Fibonacci Heaps

Fibonacci heaps achieve O(1) amortized insert and decrease-key, making Dijkstra's algorithm run in O(E + V log V) — theoretically optimal for dense graphs. They maintain a lazy forest of heap-ordered trees, deferring cleanup until delete-min.

# Fibonacci heap: conceptual structure
# Each node tracks: key, degree, mark, parent, child (circular doubly linked)

# --- decrease_key: O(1) amortized ---
def decrease_key(heap, node, new_key):
    if new_key > node.key:
        raise ValueError("New key is greater")
    node.key = new_key
    parent = node.parent
    if parent and node.key < parent.key:
        _cut(heap, node, parent)       # detach from parent
        _cascading_cut(heap, parent)   # propagate marks up tree
    if node.key < heap.min_node.key:
        heap.min_node = node

# Cascading cut: if a node has already lost one child (marked),
# cut it too and continue up. Prevents trees from becoming too deep.
# Amortized analysis uses potential function Phi = trees + 2 * marked nodes.

# --- delete_min: O(log n) amortized ---
# 1. Move min's children to root list
# 2. Remove min from root list
# 3. Consolidate: link trees of same degree (like binary addition)
# 4. Find new minimum across root list
# Consolidation ensures at most O(log n) trees remain
Theory vs Practice
Fibonacci heaps have large constant factors due to pointer-heavy structure and poor cache locality. In benchmarks, binary heaps with their flat array layout typically outperform Fibonacci heaps until graph sizes reach millions of edges. For competitive programming, use heapq.

d-ary Heaps

A d-ary heap generalizes the binary heap: each node has up to d children. This reduces tree height to log_d(n), making sift-up faster (fewer levels), but sift-down requires comparing d children per level.

class DaryHeap:
    """Generic d-ary min-heap. d=4 is common for cache performance."""
    def __init__(self, d=4):
        self.d = d
        self.data = []

    def _parent(self, i):   return (i - 1) // self.d
    def _children(self, i): return range(self.d*i+1, self.d*i+self.d+1)

    def push(self, val):
        self.data.append(val)
        i = len(self.data) - 1
        while i > 0:
            p = self._parent(i)
            if self.data[i] < self.data[p]:
                self.data[i], self.data[p] = self.data[p], self.data[i]
                i = p
            else: break

    def pop(self):
        self.data[0], self.data[-1] = self.data[-1], self.data[0]
        val = self.data.pop()
        n, i = len(self.data), 0
        while True:
            smallest = i
            for c in self._children(i):
                if c < n and self.data[c] < self.data[smallest]:
                    smallest = c
            if smallest == i: break
            self.data[i], self.data[smallest] = self.data[smallest], self.data[i]
            i = smallest
        return val

# Sift-up: O(log_d n) — fewer levels, good for frequent inserts
# Sift-down: O(d * log_d n) — more comparisons per level
# 4-heap (d=4) is popular: height ~half of binary, fits cache lines well

    Key Takeaways

  • A heap is a complete binary tree stored as a flat array — parent(i) = (i-1)//2, children = 2i+1 and 2i+2.
  • Push (sift-up) and pop (sift-down) both run in O(log n). Peek is O(1).
  • Floyd's heapify builds a heap from n elements in O(n) — not O(n log n).
  • Heap sort runs in O(n log n) worst-case with O(1) extra space, but poor cache behavior makes it slower than quicksort in practice.
  • Fibonacci heaps achieve O(1) amortized decrease-key, making Dijkstra's O(E + V log V), but high constant factors limit practical use.
  • For most Python work, use heapq (binary min-heap). Negate values for max-heap behavior.
