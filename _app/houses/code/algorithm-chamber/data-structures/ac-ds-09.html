The Problem: Dynamic Connectivity

Given a set of n elements and a stream of union and same-component queries, we need a data structure that answers "are x and y in the same set?" efficiently after any sequence of merges.

Naive Implementation

class UnionFindNaive:
    """Each element points to its parent. Root points to itself."""
    def __init__(self, n):
        self.parent = list(range(n))  # parent[i] = i initially (each is its own root)

    def find(self, x):
        """Follow parent pointers to root — O(n) worst case (chain)."""
        while self.parent[x] != x:
            x = self.parent[x]
        return x

    def union(self, a, b):
        """Merge the sets containing a and b."""
        ra, rb = self.find(a), self.find(b)
        if ra != rb:
            self.parent[ra] = rb  # naive: always attach first root to second

    def connected(self, a, b):
        return self.find(a) == self.find(b)

# Worst case: union(0,1), union(1,2), ..., union(n-2, n-1)
# Creates a chain: 0 -> 1 -> 2 -> ... -> n-1
# find(0) walks the entire chain: O(n)

Path Compression

After finding the root, make every node on the path point directly to the root. Subsequent finds on any of those nodes are O(1). This flattening does not change the logical set structure.

def find_compress(self, x):
    """Two-pass path compression — O(log n) amortized."""
    root = x
    while self.parent[root] != root:  # pass 1: find root
        root = self.parent[root]
    while self.parent[x] != root:     # pass 2: flatten path to root
        nxt = self.parent[x]
        self.parent[x] = root
        x = nxt
    return root

# Alternative: recursive one-pass (modifies on the way back up)
def find_recursive(self, x):
    if self.parent[x] != x:
        self.parent[x] = self.find_recursive(self.parent[x])  # path compression
    return self.parent[x]

# "Halving" variant: point each node to its grandparent (single pass, same bound)
def find_halving(self, x):
    while self.parent[x] != x:
        self.parent[x] = self.parent[self.parent[x]]  # skip one level
        x = self.parent[x]
    return x

Union by Rank

Without size control, path compression alone can still create O(log n) deep trees. Union by rank attaches the shallower tree under the deeper one, bounding tree height at O(log n).

class UnionFind:
    """Union by rank + path compression — O(alpha(n)) amortized per op."""
    def __init__(self, n):
        self.parent = list(range(n))
        self.rank   = [0] * n   # upper bound on subtree height
        self.size   = [1] * n   # exact subtree size (for weighted union)
        self.components = n      # track number of distinct sets

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]  # path halving
            x = self.parent[x]
        return x

    def union(self, a, b):
        """Return True if a and b were in different sets (merge happened)."""
        ra, rb = self.find(a), self.find(b)
        if ra == rb: return False
        # Attach lower-rank tree under higher-rank tree
        if self.rank[ra] < self.rank[rb]: ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        if self.rank[ra] == self.rank[rb]:
            self.rank[ra] += 1  # rank only increases when two equal-rank trees merge
        self.components -= 1
        return True

    def connected(self, a, b): return self.find(a) == self.find(b)
    def component_size(self, x): return self.size[self.find(x)]

# Correctness note: rank is an UPPER BOUND, not exact height.
# Path compression may lower actual height without updating rank.
# That is fine — rank only guides union decisions, not find traversals.
The Inverse Ackermann Function
With both path compression and union by rank, each operation runs in O(alpha(n)) amortized time, where alpha is the inverse Ackermann function. For any conceivable input (n < 10^600), alpha(n) <= 4. This is effectively constant — the bound is near-optimal and provably not O(1).

Applications

1. Kruskal's MST

def kruskal_mst(n, edges):
    """Minimum spanning tree — O(E log E) dominated by sort."""
    edges.sort(key=lambda e: e[2])  # sort by weight
    uf = UnionFind(n)
    mst, total = [], 0
    for u, v, w in edges:
        if uf.union(u, v):           # only add edge if it connects two components
            mst.append((u, v, w))
            total += w
            if len(mst) == n - 1: break  # MST complete
    return mst, total

# Each union call checks if edge creates a cycle in O(alpha(n)).
# n-1 edges in MST, at most E union operations, E log E for sort.

2. Cycle Detection in Undirected Graphs

def has_cycle(n, edges):
    """Detect cycle in undirected graph using union-find — O(E * alpha(n))."""
    uf = UnionFind(n)
    for u, v in edges:
        if not uf.union(u, v):  # already connected — adding edge creates cycle
            return True
    return False

3. Connected Components in Dynamic Graph

def process_connections(n, operations):
    """Handle online add_edge and same_component queries efficiently."""
    uf = UnionFind(n)
    results = []
    for op, a, b in operations:
        if op == 'connect':
            uf.union(a, b)
        elif op == 'query':
            results.append(uf.connected(a, b))
    return results

# Cannot use BFS/DFS here — edges arrive online.
# Union-find handles each operation in O(alpha(n)) amortized.

4. Number of Islands (LeetCode classic)

def num_islands(grid):
    """Count connected land regions in 2D grid — O(m*n * alpha(m*n))."""
    if not grid: return 0
    m, n = len(grid), len(grid[0])
    uf = UnionFind(m * n)
    water = sum(grid[i][j] == '0' for i in range(m) for j in range(n))

    for i in range(m):
        for j in range(n):
            if grid[i][j] == '1':
                for di, dj in [(0,1),(1,0)]:  # only right and down to avoid double-counting
                    ni, nj = i+di, j+dj
                    if ni < m and nj < n and grid[ni][nj] == '1':
                        uf.union(i*n+j, ni*n+nj)

    return uf.components - water  # total components minus water cells

Weighted / Rollback Union-Find

class WeightedUnionFind:
    """Tracks relative weights between nodes in the same component.
    Useful for problems like 'ratio of values: a/b = 2, b/c = 3, what is a/c?'
    """
    def __init__(self, n):
        self.parent = list(range(n))
        self.weight = [1.0] * n   # weight[x] = value[x] / value[find(x)]

    def find(self, x):
        if self.parent[x] == x: return x, 1.0
        root, w = self.find(self.parent[x])
        self.parent[x] = root
        self.weight[x] *= w
        return root, self.weight[x]

    def union(self, a, b, ratio):
        """Set value[a] / value[b] = ratio."""
        ra, wa = self.find(a)
        rb, wb = self.find(b)
        if ra == rb: return
        self.parent[ra] = rb
        self.weight[ra] = ratio * wb / wa

    def query(self, a, b):
        """Return value[a] / value[b], or -1 if not in same set."""
        ra, wa = self.find(a)
        rb, wb = self.find(b)
        if ra != rb: return -1
        return wa / wb

Path Compression Breaks Rollback
If you need to undo union operations (e.g., offline dynamic connectivity with edge deletions), use union by rank without path compression. The O(log n) per operation is acceptable, and you can maintain an undo stack. Path compression rewrites parent pointers in ways that cannot be easily reversed.

    Key Takeaways

  • Union-Find maintains a partition of n elements into disjoint sets supporting union and find in near-constant time.
  • Path compression flattens trees toward the root, reducing future find traversal depth without changing logical set structure.
  • Union by rank (or size) prevents trees from growing tall by always attaching the shallower tree under the deeper one.
  • Combined, both optimizations yield O(alpha(n)) amortized per operation — effectively O(1) in practice.
  • Kruskal's MST and cycle detection are the canonical applications — each edge check costs O(alpha(n)).
  • Weighted union-find extends the structure to track relative values (ratios, sums) between connected elements.
  • For rollback support, use union by rank alone (no path compression) — the undo stack stores overwritten parent/rank values.
