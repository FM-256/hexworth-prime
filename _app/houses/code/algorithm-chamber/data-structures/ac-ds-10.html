Skip Lists

A skip list is a probabilistic data structure that achieves O(log n) expected search, insert, and delete — the same as a balanced BST — without complex rotations. It layers a sorted linked list: the bottom level holds all elements; each higher level independently includes each node with probability p (typically 0.5).

import random, math

class SkipNode:
    def __init__(self, key, val, level):
        self.key = key; self.val = val
        self.forward = [None] * (level + 1)  # pointers at each level

class SkipList:
    MAX_LEVEL = 16   # log2(max expected n)
    P = 0.5

    def __init__(self):
        self.head = SkipNode(-float('inf'), None, self.MAX_LEVEL)
        self.level = 0   # current highest level in use
        self.size = 0

    def _random_level(self):
        """Geometric distribution — each level added with prob P."""
        lvl = 0
        while random.random() < self.P and lvl < self.MAX_LEVEL: lvl += 1
        return lvl

    def insert(self, key, val):
        """O(log n) expected. Track update pointers at each level."""
        update = [None] * (self.MAX_LEVEL + 1)
        curr = self.head
        for i in range(self.level, -1, -1):
            while curr.forward[i] and curr.forward[i].key < key:
                curr = curr.forward[i]
            update[i] = curr
        curr = curr.forward[0]
        if curr and curr.key == key:
            curr.val = val; return
        new_lvl = self._random_level()
        if new_lvl > self.level:
            for i in range(self.level + 1, new_lvl + 1): update[i] = self.head
            self.level = new_lvl
        node = SkipNode(key, val, new_lvl)
        for i in range(new_lvl + 1):
            node.forward[i] = update[i].forward[i]
            update[i].forward[i] = node
        self.size += 1

    def search(self, key):
        """O(log n) expected. Returns value or None."""
        curr = self.head
        for i in range(self.level, -1, -1):
            while curr.forward[i] and curr.forward[i].key < key:
                curr = curr.forward[i]
        curr = curr.forward[0]
        return curr.val if curr and curr.key == key else None

# Expected O(log n) ops: expected number of nodes at level k is n/2^k.
# Total expected work to traverse: sum_{k=0}^{log n} n/2^k = O(n).
# Per query: O(log n) expected levels x O(1) per level = O(log n).
# Space: O(n) expected — each node has O(1) forward pointers on average.
Skip Lists in Production
Redis's sorted set (ZSET) uses a skip list internally. LevelDB and RocksDB use skip lists for their in-memory memtable. The probabilistic balancing means no rebalancing code — simpler to implement correctly than AVL or Red-Black trees.

Bloom Filters

A Bloom filter answers "is this element in the set?" in O(k) time with O(m) bits — far less memory than storing actual elements. Trade-off: false positives are possible; false negatives are not. Deletes are not supported in standard Bloom filters.

import math, hashlib

class BloomFilter:
    def __init__(self, n, fp_rate=0.01):
        """
        n        — expected number of elements
        fp_rate  — acceptable false positive probability

        Optimal bit array size: m = -n * ln(p) / (ln 2)^2
        Optimal hash count:     k = (m/n) * ln(2)
        """
        self.m = math.ceil(-n * math.log(fp_rate) / (math.log(2) ** 2))
        self.k = math.ceil((self.m / n) * math.log(2))
        self.bits = bytearray(self.m)  # 1 byte per position (bitarray would be 8x smaller)

    def _hash_positions(self, item):
        """Generate k independent positions using double hashing."""
        item_bytes = str(item).encode()
        h1 = int(hashlib.md5(item_bytes).hexdigest(), 16)
        h2 = int(hashlib.sha1(item_bytes).hexdigest(), 16)
        return [(h1 + i * h2) % self.m for i in range(self.k)]

    def add(self, item):
        """Set k bits — O(k)."""
        for pos in self._hash_positions(item):
            self.bits[pos] = 1

    def contains(self, item):
        """Check k bits — O(k). May return True for non-members (false positive)."""
        return all(self.bits[pos] for pos in self._hash_positions(item))

    @property
    def estimated_fp_rate(self):
        """Current false positive rate given number of bits set."""
        bits_set = sum(self.bits)
        return (1 - math.exp(-bits_set / self.m)) ** self.k

# Example: cache negative lookups for a URL shortener
bf = BloomFilter(n=1_000_000, fp_rate=0.001)  # ~14.4 MB for 1M items at 0.1% FP
bf.add('https://example.com')
print(bf.contains('https://example.com'))  # True (definitely present)
print(bf.contains('https://evil.com'))     # False (probably not present)

# Applications: BigTable / HBase / Cassandra use Bloom filters to avoid
# disk reads for non-existent keys. Chrome's Safe Browsing uses one for
# malicious URL detection before hitting the network.

LRU Cache

An LRU (Least Recently Used) cache evicts the least-recently-accessed item when at capacity. The canonical O(1) implementation combines a hash map (for O(1) lookup) with a doubly linked list (for O(1) eviction of the tail and promotion to head).

from collections import OrderedDict

class LRUCache:
    """O(1) get and put using OrderedDict (doubly linked list + hash map)."""
    def __init__(self, capacity):
        self.capacity = capacity
        self.cache = OrderedDict()  # maintains insertion order

    def get(self, key):
        if key not in self.cache: return -1
        self.cache.move_to_end(key)  # mark as most recently used
        return self.cache[key]

    def put(self, key, val):
        if key in self.cache:
            self.cache.move_to_end(key)
        self.cache[key] = val
        if len(self.cache) > self.capacity:
            self.cache.popitem(last=False)  # evict LRU (oldest = front)

# Manual implementation (no OrderedDict) to show the internals:
class LRUCacheManual:
    class Node:
        def __init__(self, k=0, v=0): self.k=k; self.v=v; self.prev=self.next=None

    def __init__(self, cap):
        self.cap = cap; self.map = {}
        self.head = self.Node()   # sentinel MRU end
        self.tail = self.Node()   # sentinel LRU end
        self.head.next = self.tail; self.tail.prev = self.head

    def _remove(self, n):
        n.prev.next = n.next; n.next.prev = n.prev

    def _insert_front(self, n):
        n.next = self.head.next; n.prev = self.head
        self.head.next.prev = n; self.head.next = n

    def get(self, key):
        if key not in self.map: return -1
        n = self.map[key]; self._remove(n); self._insert_front(n); return n.v

    def put(self, key, val):
        if key in self.map: self._remove(self.map[key])
        n = self.Node(key, val); self.map[key] = n; self._insert_front(n)
        if len(self.map) > self.cap:
            lru = self.tail.prev; self._remove(lru); del self.map[lru.k]

Segment Tree

A segment tree supports range queries (sum, min, max, GCD) and point updates in O(log n) time. The tree is built on top of an array: each node stores the aggregate of its range, and each internal node covers the union of its children's ranges.

class SegmentTree:
    """Range sum query + point update — O(n) build, O(log n) per op."""
    def __init__(self, arr):
        self.n = len(arr)
        self.tree = [0] * (4 * self.n)  # 4n is a safe upper bound for tree size
        self._build(arr, 1, 0, self.n - 1)

    def _build(self, arr, node, start, end):
        if start == end:
            self.tree[node] = arr[start]
        else:
            mid = (start + end) // 2
            self._build(arr, 2*node, start, mid)
            self._build(arr, 2*node+1, mid+1, end)
            self.tree[node] = self.tree[2*node] + self.tree[2*node+1]

    def update(self, idx, val, node=1, start=None, end=None):
        """Point update at arr[idx] = val — O(log n)."""
        if start is None: start, end = 0, self.n - 1
        if start == end:
            self.tree[node] = val; return
        mid = (start + end) // 2
        if idx <= mid: self.update(idx, val, 2*node, start, mid)
        else:          self.update(idx, val, 2*node+1, mid+1, end)
        self.tree[node] = self.tree[2*node] + self.tree[2*node+1]

    def query(self, l, r, node=1, start=None, end=None):
        """Range sum query over arr[l..r] — O(log n)."""
        if start is None: start, end = 0, self.n - 1
        if r < start or end < l: return 0      # out of range
        if l <= start and end <= r: return self.tree[node]  # full coverage
        mid = (start + end) // 2
        return (self.query(l, r, 2*node, start, mid) +
                self.query(l, r, 2*node+1, mid+1, end))

arr = [1, 3, 5, 7, 9, 11]
st = SegmentTree(arr)
print(st.query(1, 4))   # 3+5+7+9 = 24
st.update(3, 10)         # arr[3] = 10
print(st.query(1, 4))   # 3+5+10+9 = 27

Lazy Propagation (Range Updates)

class LazySegTree:
    """Range update (add val to arr[l..r]) + range sum query — O(log n) each.

    Lazy propagation defers range updates: instead of updating all nodes
    in range immediately, store a 'pending' add at the topmost covering node.
    Push down the lazy value when we need to recurse into children.
    """
    def __init__(self, n):
        self.n = n
        self.tree = [0] * (4*n)
        self.lazy = [0] * (4*n)

    def _push_down(self, node, start, end):
        """Propagate pending update to children before recursing."""
        if self.lazy[node]:
            mid = (start + end) // 2
            for child, s, e in [(2*node, start, mid), (2*node+1, mid+1, end)]:
                self.tree[child] += self.lazy[node] * (e - s + 1)
                self.lazy[child] += self.lazy[node]
            self.lazy[node] = 0

    def range_update(self, l, r, val, node=1, start=0, end=None):
        if end is None: end = self.n - 1
        if r < start or end < l: return
        if l <= start and end <= r:
            self.tree[node] += val * (end - start + 1)  # update aggregate
            self.lazy[node] += val                         # defer child updates
            return
        self._push_down(node, start, end)
        mid = (start + end) // 2
        self.range_update(l, r, val, 2*node, start, mid)
        self.range_update(l, r, val, 2*node+1, mid+1, end)
        self.tree[node] = self.tree[2*node] + self.tree[2*node+1]

Fenwick Tree (Binary Indexed Tree)

A Fenwick tree (BIT) answers prefix sum queries and performs point updates in O(log n) with an O(n) array and elegant bit manipulation — simpler to implement than a segment tree for this specific use case.

class FenwickTree:
    """1-indexed BIT for prefix sums. O(n) build, O(log n) query/update."""
    def __init__(self, n):
        self.n = n
        self.tree = [0] * (n + 1)

    def update(self, i, delta):
        """Add delta to position i — traverse up using i += i & (-i)."""
        while i <= self.n:
            self.tree[i] += delta
            i += i & (-i)  # lowest set bit: next responsible node

    def prefix_sum(self, i):
        """Sum arr[1..i] — traverse down using i -= i & (-i)."""
        total = 0
        while i > 0:
            total += self.tree[i]
            i -= i & (-i)  # strip lowest set bit: next parent
        return total

    def range_sum(self, l, r):
        return self.prefix_sum(r) - self.prefix_sum(l - 1)

# Why it works: each position i in the BIT stores the sum of arr[i-lowbit(i)+1..i].
# The bit trick i & (-i) isolates the lowest set bit.
# Traversal covers exactly the right partial ranges in O(log n) steps.

bit = FenwickTree(8)
for i, v in enumerate([1,3,5,7,9,11,13,15], 1): bit.update(i, v)
print(bit.range_sum(3, 6))  # 5+7+9+11 = 32
Segment Tree vs Fenwick Tree
Use a Fenwick tree when you only need prefix/range sum queries with point updates — it is simpler and faster in practice. Use a segment tree when you need range min/max, range updates, or custom aggregation (GCD, product). The Fenwick tree cannot be easily extended to arbitrary non-invertible functions.

    Key Takeaways

  • Skip lists achieve O(log n) expected operations through probabilistic layering — no rebalancing code needed, used by Redis sorted sets.
  • Bloom filters give O(k) membership tests using O(m) bits; false positives are possible, false negatives are not. Used in Cassandra, HBase, Chrome Safe Browsing.
  • LRU cache in O(1): combine a hash map (O(1) lookup) with a doubly linked list (O(1) eviction) — OrderedDict provides both in Python.
  • Segment trees answer range queries and handle point or range updates in O(log n). Lazy propagation defers range updates to avoid redundant work.
  • Fenwick trees (BIT) are simpler than segment trees for prefix sums — use i += i & (-i) to update, i -= i & (-i) to query.
  • Sparse tables offer O(1) range min/max with O(n log n) preprocessing — only suitable when the array is static (no updates).
