AVL Trees

An AVL tree (Adelson-Velsky and Landis, 1962) is a self-balancing BST where the height difference between left and right subtrees of every node is at most 1. The balance factor bf(v) = height(right) - height(left) must be in {-1, 0, 1} for all nodes. After any insertion or deletion that violates this, rotations restore balance.

LL RotationLeft-heavy left subtree. Single right rotation around the unbalanced node.
RR RotationRight-heavy right subtree. Single left rotation around the unbalanced node.
LR RotationLeft subtree is right-heavy. Double rotation: left rotate left child, then right rotate root.
RL RotationRight subtree is left-heavy. Double rotation: right rotate right child, then left rotate root.
Python -- AVL Rotation Core Logic
def height(node):
    return node.height if node else -1

def balance_factor(node):
    return height(node.right) - height(node.left)

def rotate_right(y):
    x = y.left
    T2 = x.right
    x.right = y
    y.left = T2
    # Update heights (children first)
    y.height = 1 + max(height(y.left), height(y.right))
    x.height = 1 + max(height(x.left), height(x.right))
    return x  # new root

def rotate_left(x):
    y = x.right
    T2 = y.left
    y.left = x
    x.right = T2
    x.height = 1 + max(height(x.left), height(x.right))
    y.height = 1 + max(height(y.left), height(y.right))
    return y

def rebalance(node):
    bf = balance_factor(node)
    if bf < -1:  # left-heavy
        if balance_factor(node.left) > 0:  # LR case
            node.left = rotate_left(node.left)
        return rotate_right(node)
    if bf > 1:   # right-heavy
        if balance_factor(node.right) < 0:  # RL case
            node.right = rotate_right(node.right)
        return rotate_left(node)
    return node

Red-Black Trees

Red-Black trees use a coloring scheme (each node is red or black) with invariants that guarantee tree height is at most 2*log(n+1). They perform fewer rotations than AVL on insertions and deletions, making them preferred for many practical implementations (Java TreeMap, C++ std::map, Linux kernel rbtree).

Red-Black Properties

  • Every node is either red or black
  • The root is black
  • Every leaf (NIL) is black
  • A red node's children are always black (no two consecutive reds)
  • All paths from any node to its descendant NIL leaves have the same number of black nodes (black-height)

B-Trees

B-trees generalize BSTs to nodes with multiple keys and children. A B-tree of order m has nodes holding up to m-1 keys and m children. B-trees are designed for disk access: large nodes match disk block sizes, reducing the number of disk reads needed to traverse from root to leaf.

Practice Problems

  1. Insert keys [3,2,1,4,5,6,7,10,9,8] into an AVL tree. After each insert, determine if a rotation is needed and perform it. What is the final tree height?
  2. A Red-Black tree has 1 million nodes. What is the maximum possible height? Compare to an AVL tree with the same number of nodes.
  3. A database index stores 10 billion records. A B-tree of order 1000 is used. What is the maximum number of disk reads needed to find any record?
  4. Explain why C++ std::map uses a Red-Black tree instead of an AVL tree. Under what conditions would AVL be the better choice?

Key Takeaways

  • AVL: strict balance factor |bf| ≤ 1; height ~1.44 log n; up to 4 rotation cases on rebalance
  • Red-Black: looser balance via coloring; height ≤ 2 log(n+1); at most 2 rotations per insert
  • RB trees preferred in practice: fewer rotations, simpler amortized analysis, better for mixed workloads
  • B-trees: multi-key nodes matching disk block size; minimize I/O for large datasets; order m gives O(log_m n) height
  • 2-3 trees: B-tree with m=3; theoretical tool, rarely implemented directly but proven in textbooks
  • All balanced BST variants: O(log n) search, insert, delete -- the key win over unbalanced BSTs
