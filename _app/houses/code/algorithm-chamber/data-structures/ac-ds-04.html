Hash Functions

A hash function maps a key of arbitrary type to an integer index in [0, capacity). The ideal hash function is deterministic (same key always maps to same index), fast to compute, and distributes keys uniformly across the array to minimize collisions.

Determinismh(key) always returns the same index for the same key. Required for correctness.
UniformityKeys spread evenly across buckets. Minimizes clustering that degrades O(1) performance.
Avalanche EffectSmall key change produces a completely different hash. Prevents patterns in real data from clustering.
SpeedHash computation must be O(1) or O(key length). Expensive hash negates the benefit.
Python -- Hash Function Examples
# Python's built-in hash() -- uses SipHash for strings (randomized per process)
print(hash("hello"))    # different each run (seed randomization)
print(hash(42))        # integers: hash(n) == n for small n

# Polynomial rolling hash for strings
def poly_hash(s, base=31, mod=10**9+7):
    h = 0
    for ch in s:
        h = (h * base + ord(ch)) % mod
    return h

# FNV-1a hash (fast, good avalanche)
def fnv1a(data):
    h = 2166136261
    for b in data.encode():
        h ^= b
        h = (h * 16777619) & 0xFFFFFFFF
    return h

Collision Resolution

Collisions are inevitable (pigeonhole principle). Two strategies dominate: chaining stores colliding entries in a linked list at the same bucket; open addressing probes for the next empty slot in the array itself.

StrategyMechanismLoad Factor LimitCache
ChainingEach bucket holds a list of (key, value) pairsCan exceed 1.0 (but degrades)Poor (pointer chasing)
Linear ProbingIf slot taken, try slot+1, slot+2, ...0.7 typical maxExcellent (sequential)
Quadratic ProbingTry slot+1², slot+2², slot+3²...0.5 typical maxGood
Double HashingStep size determined by second hash function0.7 typical maxVaries
Python -- Hash Map with Chaining
class HashMap:
    def __init__(self, initial_capacity=16):
        self.capacity = initial_capacity
        self.size = 0
        self.buckets = [[] for _ in range(self.capacity)]
        self.MAX_LOAD = 0.75

    def _idx(self, key):
        return hash(key) % self.capacity

    def put(self, key, value):
        bucket = self.buckets[self._idx(key)]
        for i, (k, v) in enumerate(bucket):
            if k == key:
                bucket[i] = (key, value)
                return
        bucket.append((key, value))
        self.size += 1
        if self.size / self.capacity > self.MAX_LOAD:
            self._rehash()

    def get(self, key, default=None):
        for k, v in self.buckets[self._idx(key)]:
            if k == key: return v
        return default

    def delete(self, key):
        bucket = self.buckets[self._idx(key)]
        for i, (k, v) in enumerate(bucket):
            if k == key:
                bucket.pop(i)
                self.size -= 1
                return True
        return False

    def _rehash(self):
        # Double capacity, re-insert all entries
        old = self.buckets
        self.capacity *= 2
        self.buckets = [[] for _ in range(self.capacity)]
        self.size = 0
        for bucket in old:
            for k, v in bucket:
                self.put(k, v)

Load Factor and Performance

Load factor alpha = n/m where n is the number of entries and m is the number of buckets. Average chain length with uniform hashing equals alpha. Python dict rehashes at ~2/3 load; Java HashMap at 0.75 load.

Worst-Case O(n) and Hash DoS Attacks

If all n keys hash to the same bucket, every operation degrades to O(n) -- linear scan of the chain. This is exploitable: an attacker who knows the hash function can craft inputs causing denial of service by forcing worst-case behavior. Python, Java, and other languages randomize string hash seeds per process to mitigate this.

Practice Problems

Key Takeaways

  • Hash tables: O(1) average get/put/delete via hash function mapping keys to array indices
  • Good hash functions: deterministic, uniform distribution, avalanche effect, fast computation
  • Chaining: linked list per bucket -- handles load > 1.0 but poor cache performance
  • Open addressing: linear/quadratic/double-hash probing -- better cache locality, requires load < 1.0
  • Load factor alpha = n/m; rehash (typically double) when alpha exceeds threshold (0.7-0.75)
  • Hash randomization (Python SipHash) prevents hash-flooding DoS attacks
