The Activity Selection Problem

Given n activities, each with a start time s_i and finish time f_i, select the maximum number of non-overlapping activities. Two activities i and j are compatible if their intervals do not overlap: f_i <= s_j or f_j <= s_i.

Greedy Insight

Sort activities by finish time. Always select the next activity that finishes earliest and is compatible with the last selected activity. This greedy rule is provably optimal.

Unweighted Interval Scheduling

Python -- Earliest Finish Time Greedy
def activity_selection(activities):
    """
    Select maximum number of non-overlapping activities.
    activities: list of (start, finish) tuples
    Time: O(n log n) for sort + O(n) scan = O(n log n)
    Space: O(n)
    """\span>
    # Sort by finish time -- the key greedy decision
    sorted_acts = sorted(activities, key=lambda x: x[1])

    selected = [sorted_acts[0]]   # always take the first (earliest finish)
    last_finish = sorted_acts[0][1]

    for start, finish in sorted_acts[1:]:
        if start >= last_finish:   # compatible with last selected
            selected.append((start, finish))
            last_finish = finish

    return selected

# Example
acts = [(1,4), (3,5), (0,6), (5,7), (3,9), (5,9), (6,10), (8,11), (8,12), (2,14)]
Selected: [(1,4), (5,7), (8,11)]  -- 3 activities (optimal)

Weighted Interval Scheduling

When activities have weights (profits), greedy by finish time is no longer optimal. The weighted interval scheduling problem requires dynamic programming.

Python -- Weighted Interval Scheduling via DP
import bisect

def weighted_interval_scheduling(jobs):
    """
    jobs: list of (start, finish, weight)
    Returns maximum total weight of non-overlapping jobs.
    Time: O(n log n)  Space: O(n)
    """\span>
    jobs.sort(key=lambda x: x[1])  # sort by finish time
    n = len(jobs)
    finishes = [j[1] for j in jobs]

    def latest_compatible(i):
        # binary search: latest job j where f_j <= s_i
        idx = bisect.bisect_right(finishes, jobs[i][0]) - 1
        return idx

    dp = [0] * (n + 1)
    for i in range(1, n + 1):
        j = latest_compatible(i - 1)
        # either skip job i or take job i + best compatible before it
        dp[i] = max(dp[i - 1], jobs[i - 1][2] + dp[j + 1])
    return dp[n]

Practice Problems

  1. Prove that sorting by earliest start time does NOT always give the optimal activity selection.
  2. Implement activity selection using a priority queue. What is the advantage over sorting upfront?
  3. Extend the greedy algorithm to handle k machines (k-machine interval scheduling). How does the approach change?
  4. Given weighted intervals, write the recurrence relation for the DP and trace through an example with 5 jobs.

Key Takeaways

  • Unweighted activity selection: sort by finish time, greedily take earliest-finishing compatible activity
  • Exchange argument proves correctness: greedy finish time is always <= any optimal choice at each step
  • Weighted interval scheduling requires DP because greedy cannot account for varying profits
  • Binary search on finish times gives O(n log n) for the weighted DP
  • K-machine scheduling: use a min-heap of finish times, assign each job to the machine finishing soonest
