What Is a Greedy Algorithm?

A greedy algorithm builds a solution piece by piece, always choosing the option that looks best at the current moment without reconsidering past choices. The word "greedy" captures the idea: grab what appears optimal locally and hope (or prove) that this leads to a globally optimal solution.

Greedy algorithms are appealing for two reasons: they are conceptually simple to implement, and when they are correct, they are often very fast -- typically O(n log n) at worst due to a sorting step. The difficulty lies in proving that greedily optimal local choices actually produce globally optimal results.

The Core Tension

Not every problem yields to greedy reasoning. The classic counterexample: making change for 30 cents using coins {1, 10, 25}. Greedy picks 25+1+1+1+1+1 = 6 coins. But 10+10+10 = 3 coins. When a greedy approach fails, dynamic programming is usually the correct tool.

Greedy Choice Property A globally optimal solution can be constructed by making locally optimal (greedy) choices at each step. The choice made at step k does not depend on future choices.
Optimal Substructure After making a greedy choice, the remaining subproblem has an optimal solution that combines with the greedy choice to give an overall optimal solution.
No Backtracking Greedy algorithms never reconsider a decision. Each choice is permanent. This is why proving correctness is essential before trusting a greedy approach.
Efficient Execution Because decisions are made once and in order, greedy algorithms typically run in O(n log n) or O(n) time, making them practical for large inputs.

Proving Greedy Correctness

There are two standard proof strategies for greedy algorithms. Both require you to formally argue that the greedy choice never "leaves behind" a better solution.

Proof TechniqueStrategyWhen Used
Exchange Argument Take any optimal solution. Show that by swapping the greedy choice into it (without making it worse), we can transform it into the greedy solution. Thus greedy is at least as good as optimal. Activity selection, job scheduling, Huffman coding
Greedy Stays Ahead Prove by induction that at every step k, the greedy solution is at least as good as any other partial solution after k choices. If greedy stays ahead at every step, it finishes ahead. Fractional knapsack, coin change (special coin sets)
Matroid Theory If the problem has matroid structure (hereditary independence system with exchange property), then greedy always finds the maximum-weight independent set. MST (graphic matroid), weighted matroid intersection
Python -- Generic Greedy Template
def greedy_solve(items):
    """
    Template for a greedy algorithm.
    1. Sort items by greedy criterion (most critical step).
    2. Iterate, greedily selecting feasible items.
    3. Return the accumulated solution.
    Time: O(n log n) dominated by sort.
    """
    # Step 1: establish the greedy ordering
    items_sorted = sorted(items, key=lambda x: greedy_key(x))

    solution = []
    state = initial_state()

    for item in items_sorted:
        # Step 2: check feasibility given current state
        if is_feasible(item, state):
            solution.append(item)
            state = update_state(state, item)  # commit choice

    return solution  # proven optimal by exchange argument

The Exchange Argument in Detail

The exchange argument is the most broadly applicable proof technique. Here is the formal structure, illustrated with the activity selection problem as a running example.

Exchange Argument -- Formal Structure
# Claim: the greedy algorithm produces an optimal solution S*.
# Proof by exchange argument:
#
# Let OPT be any optimal solution.
# Let G be the greedy solution.
# We show |G| >= |OPT| (for maximization).
#
# Step 1: Order both solutions.
#   OPT = {o1, o2, ..., ok}  (ordered by finish time)
#   G   = {g1, g2, ..., gm}  (ordered by finish time)
#
# Step 2: Exchange claim.
#   For each i, g_i finishes no later than o_i.
#   (The greedy choice always picks the earliest-finishing option.)
#
# Step 3: Induction.
#   Base: g1 finishes <= o1 (greedy always picks earliest finish).
#   Inductive step: if g_i finishes <= o_i, then g_{i+1} exists
#   because o_{i+1} starts after o_i finishes >= g_i finishes,
#   so o_{i+1} is compatible with g_i, and greedy would pick
#   something finishing no later.
#
# Step 4: Conclude.
#   m >= k, so greedy finds at least as many activities as OPT.
#   Since OPT is optimal, m = k and G is optimal.

The key insight: if the greedy choice never "falls behind" any optimal choice at any step, it cannot produce a worse overall result. This "greedy stays ahead" reasoning is the backbone of most greedy proofs.

When Greedy Fails

Understanding when greedy fails is as important as knowing when it succeeds. Greedy fails when making a locally optimal choice prevents access to a globally better solution.

Classic Greedy Failures

  • 0/1 Knapsack: can't take fractions, so value-density ordering breaks down
  • Shortest path with negative edges: Dijkstra's greedy relaxation becomes incorrect
  • General coin change: arbitrary denominations violate greedy substructure
  • Traveling Salesman: nearest-neighbor heuristic is not optimal in general
Python -- Greedy Failure: 0/1 Knapsack
# Capacity = 10, items: (weight, value)
items = [(6, 12), (4, 8), (3, 7)]

# Greedy by value density: 12/6=2.0, 8/4=2.0, 7/3=2.33
# Greedy picks item 3 (density 2.33), then item 1 or 2.
# item3 + item1 = weight 9, value 19  (fits)
# item3 + item2 = weight 7, value 15  (fits)
# Greedy: value 19

# Optimal (DP): item1 + item2 = weight 10, value 20
# Greedy missed it because it committed to item3 first.

Greedy: 19    Optimal: 20    Greedy suboptimal!

The fractional relaxation of the knapsack (where you can take partial items) is greedily solvable. The moment items become indivisible, the problem requires dynamic programming or branch-and-bound.

Practice Problems

Apply greedy reasoning to the following scenarios. For each, either sketch the greedy algorithm or explain why greedy fails.

  1. You have tasks with deadlines and profits. Each task takes exactly one unit of time. Maximize total profit subject to meeting deadlines. Is this greedily solvable?
  2. Given a sorted array of integers, pair adjacent elements to maximize the sum of minimum values in each pair. Prove your greedy choice is optimal.
  3. A gas station problem: n stations on a circle, each with some gas. A car needs exactly one unit of gas per edge. Prove that if a solution exists, the greedy approach (start at the highest-surplus station) finds it.
  4. You are constructing a binary string of length n. At each step you can append 0 or 1. You want the string to have no more than k consecutive identical characters. Design and prove a greedy strategy.

Key Takeaways

  • Greedy algorithms make locally optimal choices at each step with no backtracking
  • Two properties are required for correctness: greedy choice property and optimal substructure
  • Exchange argument: show any optimal solution can be transformed into the greedy solution without getting worse
  • Greedy stays ahead: prove by induction that greedy is never behind any optimal partial solution
  • Greedy fails when committing to a local optimum forecloses a globally better path
  • Most greedy algorithms run in O(n log n) due to a single sorting step followed by linear scan
