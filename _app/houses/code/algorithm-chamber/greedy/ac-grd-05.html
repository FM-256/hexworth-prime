Dijkstra as Greedy

Dijkstra's algorithm finds shortest paths from a source vertex to all other vertices in a graph with non-negative edge weights. At each step, it greedily selects the unvisited vertex with the smallest tentative distance -- this is the greedy choice.

Greedy Invariant

When a vertex u is extracted from the priority queue, dist[u] is already the true shortest-path distance from the source. This invariant holds because all edge weights are non-negative: no future path through unvisited vertices can be shorter than dist[u].

Implementation and Complexity

Python -- Dijkstra with Min-Heap
import heapq

def dijkstra(graph, source):
    """Dijkstra shortest paths. graph: {u: [(v, w)]}.
    Time: O((V+E) log V)  Space: O(V)
    """\span>
    dist = {v: float('inf') for v in graph}
    dist[source] = 0
    heap = [(0, source)]    # (distance, vertex)
    visited = set()

    while heap:
        d, u = heapq.heappop(heap)
        if u in visited: continue   # already finalized
        visited.add(u)

        # Greedy step: relax edges from u
        for v, w in graph[u]:
            if d + w < dist[v]:
                dist[v] = d + w
                heapq.heappush(heap, (dist[v], v))  # lazy deletion

    return dist

# Complexity breakdown
# V extractions from heap: O(V log V)
# E relaxations, each possibly pushing to heap: O(E log V)
# Total: O((V + E) log V)

Why Negative Edges Break Dijkstra

The greedy invariant assumes that when vertex u is finalized, no future path can improve dist[u]. With negative edges, a later path through an unvisited vertex could have negative weight that decreases the distance, violating the invariant.

Key Takeaways

  • Dijkstra is a greedy algorithm: always finalize the vertex with the smallest known distance
  • Correctness invariant: non-negative weights ensure no future path can beat a finalized distance
  • Binary heap implementation: O((V+E) log V) -- the standard for sparse graphs
  • Negative edges invalidate the greedy invariant; use Bellman-Ford for graphs with negative weights
  • For dense graphs (E ~ V^2), use an adjacency matrix version in O(V^2) which beats the heap approach
