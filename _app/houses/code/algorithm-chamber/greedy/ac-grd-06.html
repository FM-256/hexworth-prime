Problem Statement

Given n items each with weight w_i and value v_i, and a knapsack of capacity W, maximize the total value. In the fractional variant, you may take any fraction of an item. In the 0/1 variant, each item is either taken entirely or not at all.

Key Insight

For the fractional knapsack, greedily selecting items by value density (value per unit weight) is optimal. You fill the knapsack by taking as much of the densest item as fits, then move to the next densest, and so on.

Greedy Solution

Python -- Fractional Knapsack
def fractional_knapsack(items, capacity):
    """
    items: list of (value, weight) tuples
    Returns maximum value achievable.
    Time: O(n log n)  Space: O(n)
    """\span>
    # Sort by value density descending -- the greedy criterion
    items_sorted = sorted(items, key=lambda x: x[0]/x[1], reverse=True)

    total_value = 0.0
    remaining = capacity

    for value, weight in items_sorted:
        if remaining <= 0: break
        fraction = min(1.0, remaining / weight)  # take whole or partial item
        total_value += fraction * value
        remaining -= fraction * weight

    return total_value

# Example: capacity=50

Practice Problems

  1. Prove that the fractional knapsack greedy is optimal using the greedy stays-ahead technique.
  2. Construct an instance where the fractional knapsack answer is strictly greater than the 0/1 knapsack answer.
  3. The fractional knapsack gives an upper bound on the 0/1 knapsack. Why? How is this used in branch-and-bound algorithms?
  4. Generalize: if items have multiple weight dimensions (weight and volume), does the greedy approach still work?

Key Takeaways

  • Fractional knapsack: sort by value density (v_i/w_i), greedily fill with most dense items
  • Optimality: greedy stays-ahead proves no rearrangement of selected items yields more value
  • 0/1 knapsack requires DP because committing to an item with high density may leave capacity for only lower-value items
  • Fractional solution value >= 0/1 solution value -- provides an upper bound used in branch-and-bound
  • Real applications: CPU scheduling by priority-per-burst, investment portfolio by return-per-dollar
