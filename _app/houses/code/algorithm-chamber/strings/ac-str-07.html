Suffix Trees

A suffix tree for string S is a compressed trie of all suffixes of S. Each leaf represents a suffix; internal nodes represent shared prefixes. Edge labels are substrings (stored as index pairs, not actual characters). A suffix tree has O(n) nodes and can be built in O(n) time using Ukkonen's algorithm.

Compressed TrieEdge labels represent substrings, not single characters. Each leaf is a suffix; each internal node has at least 2 children. Total nodes O(n).
O(n) SpaceEdge labels stored as (start, end) index pairs -- O(1) per edge. Total O(n) edges x O(1) = O(n) space.
O(m) SearchPattern P found by following edges matching P[0..m-1] from root. All occurrences found by counting leaves in subtree.
Ukkonen's AlgorithmBuilds suffix tree online (left-to-right) in O(n) total using active point, suffix links, and open-ended edges.

Suffix Tree vs Suffix Array

Comparison -- When to Use Each
# Suffix Tree
# + O(m) search (vs O(m log n) for SA binary search)
# + Easier to reason about tree structure
# - ~40 bytes/node (20x more memory than SA)
# - Complex to implement (Ukkonen is notoriously tricky)
# Best for: many short queries, applications needing tree traversal

# Suffix Array + LCP
# + 4 bytes/entry (very cache-friendly)
# + Simpler to implement
# + O(m log n) search, O(m + log n) with LCP arrays
# - Slightly more complex queries
# Best for: memory-constrained, offline queries, competitive programming

# In practice: suffix arrays are preferred in modern systems
# bioinformatics tools (BWA, Bowtie) use suffix arrays (FM-index)

Practice Problems

  1. Describe Ukkonen's algorithm at a high level. What are the three cases for extending the suffix tree?
  2. How do suffix links accelerate Ukkonen's algorithm? What is their role?
  3. Find the longest common substring of two strings using a generalized suffix tree.
  4. The FM-index (used in BWA aligner) compresses a suffix array using BWT. Explain the connection.

Key Takeaways

  • Suffix tree: compressed trie of all suffixes; O(n) nodes, edges stored as index pairs
  • Ukkonen's algorithm: O(n) construction using active point maintenance and suffix links
  • Pattern search in O(m) by following edges; all k occurrences in O(m + k)
  • Suffix trees use ~40 bytes/node; suffix arrays use 4 bytes/position -- 10x difference
  • Modern systems prefer suffix arrays (FM-index, BWT) for space efficiency and cache performance
