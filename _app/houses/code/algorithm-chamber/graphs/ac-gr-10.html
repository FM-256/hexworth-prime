Network Topology as a Graph

Every network is a graph. Hosts are vertices. Communication paths are edges. Edge weights can represent bandwidth, latency, or trust level. This representation unlocks the full arsenal of graph algorithms for security analysis: shortest paths reveal attack routing, bridges reveal single points of failure, and centrality measures reveal high-value targets.

Degree Centrality High-degree nodes (many connections) are high-value targets. Compromising them affects the most other nodes.
Betweenness Centrality Nodes on many shortest paths control information flow. These are natural chokepoints for network segmentation.
Bridge Edges Removing a bridge disconnects the network. These single points of failure are prime targets for denial of service.
Connected Components Isolated segments cannot communicate. Proper segmentation creates intended components -- verify with component analysis.
Python -- Network Topology Analysis
from collections import defaultdict, deque

def analyze_network(hosts, connections):
    """
    hosts: list of host identifiers
    connections: list of (host_a, host_b) tuples
    Returns: degree map, bridges, component count
    """
    graph = defaultdict(list)
    for a, b in connections:
        graph[a].append(b)
        graph[b].append(a)

    # Degree centrality
    degree = {h: len(graph[h]) for h in hosts}

    # Connected components (network segments)
    visited = set()
    num_components = 0
    for h in hosts:
        if h not in visited:
            num_components += 1
            q = deque([h])
            visited.add(h)
            while q:
                v = q.popleft()
                for u in graph[v]:
                    if u not in visited:
                        visited.add(u); q.append(u)

    return degree, num_components

# Small corporate network
hosts = ['fw','dmz','web','db','intern','corp1','corp2']
links = [('fw','dmz'),('fw','intern'),('dmz','web'),
         ('web','db'),('intern','corp1'),('intern','corp2')]
deg, comps = analyze_network(hosts, links)
print("High-degree nodes:", sorted(deg.items(), key=lambda x: -x[1])[:3])
print("Network segments:", comps)

Attack Graphs

An attack graph models multi-step attack scenarios. Nodes represent system states (combinations of vulnerabilities exploited and privileges held). Edges represent exploit steps: if an attacker is in state S and exploits vulnerability V, they reach state S'. The goal is to find paths from the initial state to a target state (full compromise).

Attack Path Analysis

Shortest path algorithms on attack graphs reveal the minimum-step exploitation chain. Weighted attack graphs assign probabilities or effort scores to edges -- minimum-weight paths reveal most-likely or least-effort attack chains. Removing nodes or edges that appear on all attack paths is the most efficient remediation strategy.

Python -- Simple Attack Graph Model
# Attack graph: state = frozenset of compromised nodes
# Edge = (from_state, to_state, exploit_used, effort)
# Find minimum-effort path from initial to target state

import heapq

def min_effort_attack_path(attack_graph, initial, target):
    """
    attack_graph: dict of state -> list of (next_state, exploit, effort)
    Returns: (total_effort, path) or None if unreachable
    """
    dist = {initial: 0}
    parent = {initial: None}
    heap = [(0, initial, [])]

    while heap:
        effort, state, path = heapq.heappop(heap)
        if state == target:
            return effort, path + [state]
        if effort > dist.get(state, float('inf')):
            continue
        for next_state, exploit, e in attack_graph.get(state, []):
            new_effort = effort + e
            if new_effort < dist.get(next_state, float('inf')):
                dist[next_state] = new_effort
                heapq.heappush(heap, (new_effort, next_state, path + [state]))

    return None  # target unreachable

Dependency Graph Vulnerability Analysis

Software dependencies form directed graphs. A vulnerability in a low-level library propagates to every package that depends on it, directly or transitively. BFS/DFS on the dependency graph computes the full blast radius of a CVE.

Python -- Transitive Dependency Impact Analysis
def impact_analysis(dep_graph, vulnerable_pkg):
    """
    dep_graph: dict of package -> list of packages that DEPEND ON it
    vulnerable_pkg: the package with the CVE
    Returns: set of all affected packages (transitive dependents)
    """
    affected = set()
    queue = deque([vulnerable_pkg])
    while queue:
        pkg = queue.popleft()
        for dependent in dep_graph.get(pkg, []):
            if dependent not in affected:
                affected.add(dependent)
                queue.append(dependent)
    return affected

# Example: openssl is a dependency of many packages
# dep_graph maps: pkg -> packages that use it
dep_graph = {
    'openssl': ['nginx', 'curl', 'python-requests'],
    'curl': ['ansible', 'terraform'],
    'nginx': ['app-server'],
}
blast = impact_analysis(dep_graph, 'openssl')
print("Affected packages:", blast)
# {'nginx','curl','python-requests','ansible','terraform','app-server'}

Network Segmentation via Max-Flow Min-Cut

The min-cut of a flow network identifies the minimum set of edges that, if removed, disconnects the source from the sink. In security terms: what is the minimum firewall ruleset needed to prevent communication between two network zones? The max-flow min-cut theorem gives the answer directly.

Key Takeaways

  • Network topology is a graph -- every graph algorithm applies directly to security analysis
  • Bridges and articulation points identify single points of failure -- highest priority for redundancy
  • Attack graphs model multi-step exploits; Dijkstra finds minimum-effort attack chains
  • Dependency graphs reveal transitive CVE blast radius -- BFS computes all transitively affected packages
  • Max-flow min-cut gives the minimum firewall ruleset to segment two network zones
  • SCC analysis reveals clusters where all nodes are mutually reachable -- an all-or-nothing breach scenario
