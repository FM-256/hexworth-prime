PRAM Model and Work-Span Analysis

PRAM (Parallel Random Access Machine) is the theoretical model for parallel algorithms. Key metrics: Work W (total operations), Span S (critical path depth), Parallelism = W/S.

MetricDefinitionTarget
Work WTotal operations across all processorsO(T_sequential)
Span SLongest chain of dependent opsO(log n) or O(log^2 n)
ParallelismW / SAs high as possible
Time(p)max(S, W/p) by Brent's theoremClose to W/p for large p
Brent's TheoremT_p <= S + (W - S) / p. With enough processors p = W/S, runtime approaches the span.

Parallel Prefix (Scan)

Parallel prefix computes [a0, a0+a1, a0+a1+a2, ...] in O(log n) span and O(n) work using an up-sweep and down-sweep on a binary tree.

PythonParallel Prefix (sequential simulation with tree indices)
def parallel_prefix(arr, op=lambda a,b: a+b):
    """Simulates O(log n) span parallel prefix."""
    n = len(arr)
    result = arr[:]
    # Up-sweep (reduce)
    step = 1
    while step < n:
        for i in range(step-1, n-1, 2*step):
            result[i+step] = op(result[i], result[i+step])
        step *= 2
    result[n-1] = 0  # identity for down-sweep
    # Down-sweep
    step = n // 2
    while step >= 1:
        for i in range(step-1, n-1, 2*step):
            left = result[i]; result[i] = result[i+step]
            result[i+step] = op(left, result[i+step])
        step //= 2
    return result

Parallel Sorting and BFS

Parallel merge sort achieves O(log^2 n) span. Parallel BFS with O(V+E) work and O(D log V) span where D is the graph diameter.

AlgorithmWorkSpanSpeedup vs Sequential
Parallel PrefixO(n)O(log n)O(n / log n) on n/log n procs
Parallel Merge SortO(n log n)O(log^2 n)Nearly linear
Parallel BFSO(V+E)O(D log V)High on sparse low-diameter graphs
Parallel ReduceO(n)O(log n)Work-optimal
Practice vs TheoryPython's GIL prevents true thread-level parallelism. Use multiprocessing, Dask, or numpy vectorized operations. CUDA for GPU parallelism.

Practice

  1. Compute the parallel prefix of [1,2,3,4,5,6,7,8] by hand tracing the up-sweep and down-sweep steps.
  2. Calculate Work, Span, and Parallelism for parallel merge sort of n=1024 elements.
  3. Estimate T_p for parallel BFS on a graph with 10^6 edges, diameter 20, and p=100 processors.

Key Takeaways

  • Work = total ops; Span = critical path. Both must be good for real speedup.
  • Brent's theorem: T_p <= S + (W-S)/p.
  • Parallel prefix is the building block for parallel sort, histogram, stream compaction.
  • Python multiprocessing bypasses the GIL; use it for CPU-bound parallel workloads.
