Cache-Aware Algorithm Design

Modern CPUs are 100-1000x faster than RAM. Cache misses dominate runtime for large inputs. Access patterns matter as much as asymptotic complexity.

Memory tierLatencySizeAlgorithm implication
L1 cache~1ns32-64KBSequential access, prefetch-friendly
L2 cache~4ns256KB-1MBBlock-based algorithms
L3 cache~10ns8-32MBPartition data to fit
DRAM~100nsGBsMinimize random access
PythonCache-friendly matrix multiply (block tiling)
def matmul_naive(A, B):
    n = len(A); C = [[0]*n for _ in range(n)]
    for i in range(n):
        for j in range(n):
            for k in range(n): C[i][j] += A[i][k]*B[k][j]
    return C

def matmul_tiled(A, B, block=64):
    n = len(A); C = [[0]*n for _ in range(n)]
    for ii in range(0,n,block):
      for jj in range(0,n,block):
        for kk in range(0,n,block):
          for i in range(ii,min(ii+block,n)):
            for j in range(jj,min(jj+block,n)):
              for k in range(kk,min(kk+block,n)):
                C[i][j] += A[i][k]*B[k][j]
    return C
# In practice: use numpy.dot() — BLAS-optimized, SIMD, cache-aware

Profiling with cProfile

Always measure before optimizing. cProfile identifies which functions consume the most time.

PythonProfiling with cProfile
import cProfile, pstats, io

def profile(func, *args):
    pr = cProfile.Profile()
    pr.enable()
    result = func(*args)
    pr.disable()
    s = io.StringIO()
    ps = pstats.Stats(pr, stream=s).sort_stats('cumulative')
    ps.print_stats(10)
    print(s.getvalue())
    return result

# Usage:
# profile(my_heavy_function, large_input)
Rule of ThumbOptimize only the hottest 10% of code — Amdahl's Law limits speedup from optimizing non-bottlenecks.

NumPy Vectorization

Python loops are slow. NumPy operations call into C/Fortran BLAS kernels that are cache-optimized and SIMD-vectorized.

PythonLoop vs vectorized comparison
import numpy as np, time

N = 10**6
a = list(range(N))
na = np.arange(N)

# Python loop
t0 = time.time()
total = sum(x*x for x in a)
print(f"Loop: {time.time()-t0:.3f}s")

# NumPy vectorized
t0 = time.time()
total = np.sum(na**2)
print(f"NumPy: {time.time()-t0:.3f}s")
# NumPy is typically 50-200x faster for element-wise ops

Practice

  1. Profile a naive matrix multiply on a 200x200 matrix. Identify the bottleneck function.
  2. Rewrite the matrix multiply using numpy.dot() and measure the speedup ratio.
  3. Test matmul_tiled vs matmul_naive on a 500x500 matrix. Does tiling help in Python?

Key Takeaways

  • Cache misses are the dominant runtime cost on large inputs — measure, don't assume.
  • Block tiling restructures memory access to fit in cache.
  • Profile first: optimize only the measured hot path.
  • NumPy vectorization provides 50-200x speedup over Python loops for numerical workloads.
