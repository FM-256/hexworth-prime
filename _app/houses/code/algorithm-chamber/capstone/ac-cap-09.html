Contest Strategy Framework

Competitive programming rewards fast, correct implementations under time pressure. The process: read all problems, classify by type, estimate complexity, implement the simplest correct solution first.

Problem CategoryKey PatternComplexity Target
Array/StringSliding window, prefix sum, two pointerO(n) or O(n log n)
GraphBFS/DFS, Dijkstra, SCC, flowO(V+E) to O(E log V)

Common Pitfalls

Integer Overflow

Python ints are arbitrary precision — no overflow. C++: use long long.

Off-by-one

Fence-post errors in sliding window, binary search. Always test edge cases n=1,2.

TLE from O(n^2)

n=10^5 means O(n^2)=10^10 ops. Redesign to O(n log n) before submitting.

Wrong Modular Arithmetic

(a*b) % MOD is fine. (a+b) % MOD is fine. (a-b+MOD) % MOD for subtraction.

Graph with 1-indexing

Contest graphs are usually 1-indexed. Adjust adjacency list size to n+1.

Recursion Depth

Python default recursion limit is 1000. sys.setrecursionlimit(10**6) for DFS on large graphs.

Time LimitsPython is ~10x slower than C++. A problem with 1-second time limit effectively gives Python 0.1 seconds. Use PyPy if the judge allows it.

Practice

  1. Write the fast-I/O template from memory and test it with a simple sum problem.
  2. Solve: given n numbers, find the maximum subarray sum (Kadane's algorithm). What is the pattern?
  3. Solve: given a list of intervals, merge overlapping ones. What is the pattern and complexity?

Key Takeaways

  • Read all problems first; tackle easy ones quickly to maximize score.
  • sys.stdin.readline is 3-10x faster than input() for large inputs.
  • Always test with edge cases: n=1, empty input, all-same values, maximum n.
  • When stuck, simplify constraints and find the sub-problem you DO know how to solve.
