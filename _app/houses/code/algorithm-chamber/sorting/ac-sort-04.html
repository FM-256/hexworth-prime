Core Algorithm

Quicksort selects a pivot, partitions the array into "less than pivot" and "greater than pivot" regions, places the pivot at its final sorted position, then recursively sorts both regions. Unlike merge sort, all work happens during partitioning — the merge step is trivial.

# LOMUTO PARTITION (simpler, slightly more comparisons than Hoare)
def partition_lomuto(arr, lo, hi):
    """Pivot = arr[hi]. Maintains i as boundary of 'less than' region.
    Invariant: arr[lo..i-1] <= pivot, arr[i..j-1] > pivot, arr[j..hi-1] unseen.
    """
    pivot = arr[hi]
    i = lo - 1  # i is the rightmost index of the 'small' region
    for j in range(lo, hi):
        if arr[j] <= pivot:
            i += 1
            arr[i], arr[j] = arr[j], arr[i]
    arr[i+1], arr[hi] = arr[hi], arr[i+1]  # pivot to final position
    return i + 1  # pivot index

# HOARE PARTITION (original, ~3x fewer swaps on average)
def partition_hoare(arr, lo, hi):
    """Pivot = arr[lo]. Two pointers converge from opposite ends.
    Returns index such that arr[lo..j] <= pivot and arr[j+1..hi] >= pivot.
    Note: pivot is NOT necessarily at the returned index.
    """
    pivot = arr[(lo + hi) // 2]  # middle reduces worst case on sorted input
    i, j = lo - 1, hi + 1
    while True:
        i += 1
        while arr[i] < pivot: i += 1
        j -= 1
        while arr[j] > pivot: j -= 1
        if i >= j: return j
        arr[i], arr[j] = arr[j], arr[i]

def quicksort(arr, lo=0, hi=None):
    if hi is None: hi = len(arr) - 1
    if lo < hi:
        p = partition_hoare(arr, lo, hi)
        quicksort(arr, lo, p)
        quicksort(arr, p + 1, hi)

Randomized Quicksort

import random

def partition_random(arr, lo, hi):
    """Random pivot eliminates adversarial worst-case O(n^2).
    Expected O(n log n) for ANY input — no specific bad case exists.
    """
    rand_idx = random.randint(lo, hi)
    arr[rand_idx], arr[hi] = arr[hi], arr[rand_idx]  # swap random to end
    return partition_lomuto(arr, lo, hi)

# Median-of-three pivot: picks median of arr[lo], arr[mid], arr[hi]
# Eliminates worst case on sorted/reverse-sorted input without randomness
def median_of_three(arr, lo, hi):
    mid = (lo + hi) // 2
    # Sort lo, mid, hi in place
    if arr[lo] > arr[mid]:  arr[lo], arr[mid] = arr[mid], arr[lo]
    if arr[lo] > arr[hi]:   arr[lo], arr[hi]  = arr[hi],  arr[lo]
    if arr[mid] > arr[hi]:  arr[mid], arr[hi] = arr[hi],  arr[mid]
    # Place median at hi-1 (pivot position for Lomuto)
    arr[mid], arr[hi-1] = arr[hi-1], arr[mid]
    return arr[hi-1]

# Expected comparisons with random pivot:
# E[C(n)] = 2n*H_n - 2n where H_n = harmonic number ≈ ln(n)
# E[C(n)] ≈ 2n*ln(n) ≈ 1.386*n*log2(n) — about 39% more than merge sort
# BUT: quicksort does less data movement (in-place swaps vs allocation)
# and has better cache behavior — wins in practice on random data

Dutch National Flag (3-Way Partition)

Standard quicksort degrades to O(n^2) on arrays with many duplicate keys because all equal elements stay on one side. Dutch National Flag (Dijkstra, 1976) partitions into three regions: less than, equal to, and greater than pivot — equal elements are immediately in their final positions.

def partition_3way(arr, lo, hi):
    """Dutch National Flag — O(n) single pass with three pointers.
    After partition: arr[lo..lt-1] < pivot, arr[lt..gt] == pivot, arr[gt+1..hi] > pivot.
    """
    pivot = arr[lo]
    lt = lo   # arr[lo..lt-1] < pivot
    gt = hi   # arr[gt+1..hi] > pivot
    i = lo    # current element being examined

    while i <= gt:
        if   arr[i] < pivot: arr[lt], arr[i] = arr[i], arr[lt]; lt += 1; i += 1
        elif arr[i] > pivot: arr[i], arr[gt] = arr[gt], arr[i]; gt -= 1
        else:                i += 1  # equal to pivot — skip
    return lt, gt

def quicksort_3way(arr, lo=0, hi=None):
    if hi is None: hi = len(arr) - 1
    if lo >= hi: return
    lt, gt = partition_3way(arr, lo, hi)
    quicksort_3way(arr, lo, lt - 1)
    quicksort_3way(arr, gt + 1, hi)  # skip arr[lt..gt] — all equal to pivot

# Example: sorting [3,3,3,3,3] — 1-way and 2-way quicksort: O(n^2)
#                                   3-way quicksort: O(n) single pass
arr = [3,1,4,1,5,9,2,6,5,3,5]
quicksort_3way(arr)
print(arr)  # [1,1,2,3,3,4,5,5,5,6,9]

Introsort

Introsort is the algorithm behind C++ STL std::sort. It starts with quicksort but switches to heapsort when recursion depth exceeds 2*log(n) — guaranteeing O(n log n) worst case. For small subarrays it uses insertion sort.

import math

def introsort(arr, lo=0, hi=None, depth_limit=None):
    """Hybrid: quicksort + heapsort fallback + insertion sort for small n.
    Guarantees O(n log n) worst-case while matching quicksort in practice.
    """
    if hi is None: hi = len(arr) - 1
    if depth_limit is None:
        depth_limit = 2 * int(math.log2(hi - lo + 1)) if hi > lo else 0
    size = hi - lo + 1
    if size <= 16:
        _insertion_sort(arr, lo, hi + 1)  # small: insertion sort wins
    elif depth_limit == 0:
        _heapsort_range(arr, lo, hi + 1)  # deep recursion: heapsort for guarantee
    else:
        p = partition_lomuto(arr, lo, hi)   # normal: quicksort
        introsort(arr, lo, p - 1, depth_limit - 1)
        introsort(arr, p + 1, hi, depth_limit - 1)

def _insertion_sort(arr, lo, hi):
    for i in range(lo+1, hi):
        key, j = arr[i], i-1
        while j >= lo and arr[j] > key: arr[j+1] = arr[j]; j -= 1
        arr[j+1] = key

# Depth limit of 2*log(n) ensures heapsort triggers before O(n^2) recursion.
# In practice the depth limit is rarely hit for random data.
# pdqsort (pattern-defeating quicksort) extends introsort further:
#   - detects sorted/reverse-sorted patterns
#   - uses block-swapping partition for better branch prediction
Quicksort DoS Vulnerability
Without randomization, a naive quicksort using the first or last element as pivot can be forced into O(n^2) behavior by adversarial input. Python's sorted() and list.sort() are immune (Timsort), but custom implementations in web services using naive quicksort have been exploited. Always use random pivot or median-of-three in production.
Practice Problems

  2. Implement dual-pivot quicksort (Java's Arrays.sort for primitives): choose two pivots p1 <= p2, partition into three regions (< p1, between, > p2), and sort recursively.
  3. Sort Colors (LeetCode 75): given an array with only 0s, 1s, and 2s, sort it in-place with one pass using the Dutch National Flag algorithm.
  4. Analyze the stack space used by quicksort. Show that always recursing on the smaller partition first limits stack depth to O(log n).

    Key Takeaways

  • Quicksort is O(n log n) expected, O(n^2) worst case. Worst case occurs when the pivot is always the minimum or maximum — e.g., already-sorted input with last-element pivot.
  • Lomuto partition is simpler (one pointer); Hoare uses two pointers and does ~3x fewer swaps. Hoare is preferred in practice.
  • Random pivot selection eliminates adversarial worst case — expected O(n log n) for any input.
  • Dutch National Flag 3-way partition handles duplicate keys efficiently — essential for sorting arrays with many repeated values.
  • Introsort = quicksort + heapsort fallback (at depth 2*log n) + insertion sort (for n <= 16). Used by C++ STL — O(n log n) guaranteed, fast in practice.
  • Tail recursion on the larger partition + recursing on smaller partition first bounds stack depth to O(log n) even in the worst-pivot case.
