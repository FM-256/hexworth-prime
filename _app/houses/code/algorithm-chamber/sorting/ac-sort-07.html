Classic Binary Search

Binary search finds a target in a sorted array in O(log n) by halving the search space each step. The key to a correct implementation is maintaining a precise loop invariant: the target (if present) is always within arr[lo..hi].

def binary_search(arr, target):
    """Return index of target in sorted arr, or -1 if not found.

    Invariant: if target exists, it is at some index in arr[lo..hi].
    Loop terminates because hi - lo strictly decreases each iteration.
    """
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = lo + (hi - lo) // 2  # avoids integer overflow vs (lo+hi)//2
        if   arr[mid] == target: return mid
        elif arr[mid] < target:  lo = mid + 1
        else:                    hi = mid - 1
    return -1

# Recursive formulation (same logic, O(log n) stack space)
def binary_search_rec(arr, target, lo=0, hi=None):
    if hi is None: hi = len(arr) - 1
    if lo > hi: return -1
    mid = lo + (hi - lo) // 2
    if   arr[mid] == target: return mid
    elif arr[mid] < target:  return binary_search_rec(arr, target, mid+1, hi)
    else:                    return binary_search_rec(arr, target, lo, mid-1)

arr = [1, 3, 5, 7, 9, 11, 13]
print(binary_search(arr, 7))   # 3
print(binary_search(arr, 6))   # -1
The Classic Bug: Integer Overflow
In languages with fixed-size integers (Java, C++), mid = (lo + hi) / 2 overflows when lo + hi exceeds INT_MAX. Use mid = lo + (hi - lo) / 2 instead. In Python integers are arbitrary precision, so this is not an issue — but the pattern is important for interviews and systems code.

Lower Bound and Upper Bound

When the array contains duplicates, we often need the first or last occurrence of a value. lower_bound returns the first index where arr[i] >= target; upper_bound returns the first index where arr[i] > target.

import bisect

def lower_bound(arr, target):
    """First index i such that arr[i] >= target. O(log n).
    Equivalent to bisect.bisect_left(arr, target).
    If all elements < target, returns len(arr).
    """
    lo, hi = 0, len(arr)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if arr[mid] < target: lo = mid + 1  # target must be to the right
        else:                 hi = mid      # arr[mid] >= target, keep mid as candidate
    return lo

def upper_bound(arr, target):
    """First index i such that arr[i] > target. O(log n).
    Equivalent to bisect.bisect_right(arr, target).
    """
    lo, hi = 0, len(arr)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if arr[mid] <= target: lo = mid + 1  # target >= arr[mid], go right
        else:                  hi = mid
    return lo

def count_occurrences(arr, target):
    """Count occurrences of target — O(log n) using lower/upper bound."""
    return upper_bound(arr, target) - lower_bound(arr, target)

arr = [1, 2, 2, 2, 3, 4]
print(lower_bound(arr, 2))      # 1 (first 2 at index 1)
print(upper_bound(arr, 2))      # 4 (first > 2 at index 4)
print(count_occurrences(arr,2)) # 3
# Verify with Python's bisect:
print(bisect.bisect_left(arr, 2))   # 1
print(bisect.bisect_right(arr, 2))  # 4

Binary Search on a Predicate

The most powerful form of binary search: given any monotone boolean function f(x) where f is False for x < threshold and True for x >= threshold, find the smallest x where f(x) is True. The search space need not be an array.

def first_true(lo, hi, predicate):
    """Generic binary search: find smallest x in [lo, hi] where predicate(x) is True.
    Assumes predicate is monotone: once True, stays True.
    Returns hi+1 if predicate is never True.
    """
    result = hi + 1  # sentinel: predicate never True
    while lo <= hi:
        mid = lo + (hi - lo) // 2
        if predicate(mid):
            result = mid   # record candidate, search left half
            hi = mid - 1
        else:
            lo = mid + 1
    return result

# Example 1: Koko eating bananas (LeetCode 875)
# Can Koko eat all piles in h hours at speed k?
# Binary search on k (speed), predicate = can_finish
def min_eating_speed(piles, h):
    import math
    def can_finish(speed):
        return sum(math.ceil(p / speed) for p in piles) <= h
    return first_true(1, max(piles), can_finish)

# Example 2: Square root (floor)
# Find largest x where x*x <= n
def isqrt(n):
    if n < 0: raise ValueError
    lo, hi = 0, n
    while lo < hi:
        mid = lo + (hi - lo + 1) // 2  # round up to avoid infinite loop
        if mid * mid <= n: lo = mid
        else:              hi = mid - 1
    return lo

# Example 3: Minimum in rotated sorted array
def find_min_rotated(arr):
    """Find minimum in rotated sorted array — O(log n).
    Binary search: the minimum is in the unsorted half.
    """
    lo, hi = 0, len(arr) - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if arr[mid] > arr[hi]: lo = mid + 1  # rotation point in right half
        else:                  hi = mid      # rotation point in left half or at mid
    return arr[lo]

print(find_min_rotated([4,5,6,7,0,1,2]))  # 0

Binary Search on the Answer

# Pattern: "What is the minimum/maximum X such that condition(X) holds?"
# Binary search on X, check condition in O(n) or O(n log n).

# Example: Split Array Largest Sum (LeetCode 410)
# Minimize the largest sum when splitting array into k subarrays.
# Binary search on the answer (max_sum), check if k splits are feasible.
def split_array(nums, k):
    def can_split(max_sum):
        """Can we split into <= k parts with each part sum <= max_sum?"""
        count, curr = 1, 0
        for x in nums:
            if x > max_sum: return False  # single element exceeds limit
            if curr + x > max_sum: count += 1; curr = x
            else: curr += x
        return count <= k

    lo = max(nums)           # minimum possible: largest element alone
    hi = sum(nums)           # maximum possible: all in one group
    return first_true(lo, hi, can_split)

print(split_array([7,2,5,10,8], 2))  # 18: [7,2,5] and [10,8]

# Step-by-step invariant:
# lo = smallest possible answer, hi = largest possible answer
# can_split(lo) = True when lo reaches optimal
# Binary search narrows to the exact minimum feasible value
Common Off-By-One Errors
Binary search bugs almost always come from: (1) wrong loop condition (lo < hi vs lo <= hi), (2) wrong mid update (mid vs mid+1), or (3) infinite loop when mid == lo with round-down. The safest approach: define your invariant precisely before writing the loop, and verify it holds after each branch. If searching for the last True in a predicate, use round-up for mid.

    Key Takeaways

  • Binary search runs in O(log n) by halving the search space. Always use mid = lo + (hi - lo) // 2 to avoid overflow in fixed-size integer languages.
  • lower_bound: first index where arr[i] >= target. upper_bound: first index where arr[i] > target. Python's bisect module implements both.
  • The key invariant for lower_bound: lo always points to or left of the answer. hi is never a false candidate. Loop ends when lo == hi.
  • Generalized binary search works on any monotone predicate — the search space can be any range of integers, not just array indices.
  • Binary search on the answer: identify a monotone feasibility condition, set lo/hi to the min/max possible answer, binary search for the threshold.
  • Off-by-one errors are the most common bug — derive from invariants, not intuition.
