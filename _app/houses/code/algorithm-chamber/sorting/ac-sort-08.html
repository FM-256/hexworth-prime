The Selection Problem

Given an unsorted array of n elements, find the kth smallest element (1-indexed). The naive approach — sort then index — takes O(n log n). We can do better: O(n) expected time with quickselect, or O(n) worst-case with median-of-medians.

# Selection problem variants:
# - Minimum/maximum: k=1 or k=n — trivially O(n) with a single scan
# - Median: k = (n+1)/2 — most common selection problem
# - kth order statistic: arbitrary k in 1..n
# - top-k: all k smallest/largest — differs from kth single value

def naive_select(arr, k):
    """O(n log n) — sort and index. Correct but sub-optimal."""
    return sorted(arr)[k-1]

Quickselect

Quickselect applies the quicksort partition step but only recurses on the half that contains the kth element. It reduces the problem size by a constant fraction on average, yielding O(n) expected time.

import random

def quickselect(arr, k):
    """Find kth smallest (1-indexed). O(n) expected, O(n^2) worst case.
    Modifies arr in place (uses copy if you need arr unchanged).
    """
    arr = list(arr)  # work on a copy
    lo, hi = 0, len(arr) - 1
    target = k - 1  # convert to 0-indexed

    while lo < hi:
        pivot_idx = _partition(arr, lo, hi)
        if   pivot_idx < target: lo = pivot_idx + 1  # kth is in right half
        elif pivot_idx > target: hi = pivot_idx - 1  # kth is in left half
        else: break                                   # found it!

    return arr[target]

def _partition(arr, lo, hi):
    """Random pivot Lomuto partition — O(n) expected per call."""
    rand_idx = random.randint(lo, hi)
    arr[rand_idx], arr[hi] = arr[hi], arr[rand_idx]
    pivot = arr[hi]
    i = lo - 1
    for j in range(lo, hi):
        if arr[j] <= pivot:
            i += 1; arr[i], arr[j] = arr[j], arr[i]
    arr[i+1], arr[hi] = arr[hi], arr[i+1]
    return i + 1

print(quickselect([3,1,4,1,5,9,2,6,5,3,5], 5))  # 4 (5th smallest)
print(quickselect([3,1,4,1,5,9,2,6,5,3,5], 1))  # 1 (minimum)

# Expected complexity analysis:
# At each step, random pivot partitions into two halves.
# Expected position of pivot: uniform in [lo..hi].
# T(n) = n + T(n/2) on average (pivot splits near middle).
# By geometric series: T(n) = O(n).
# Worst case: pivot always min/max -> T(n) = n + T(n-1) = O(n^2).
# Probability of O(n^2) with random pivot: exponentially small.

Median of Medians

Median-of-medians (Blum et al. 1973) is the first algorithm that achieves O(n) worst-case selection. It guarantees a "good" pivot by computing the approximate median, eliminating a fixed fraction of elements per step.

def median_of_medians(arr, k):
    """Find kth smallest in O(n) worst case using pivot guarantee.

    Algorithm:
    1. Divide arr into groups of 5.
    2. Find median of each group (trivially with insertion sort on 5 elements).
    3. Recursively find median of medians (pivot).
    4. Partition around pivot.
    5. Recurse on the relevant partition.

    Pivot guarantee: at least 30% of elements are <= pivot and 30% >= pivot.
    This ensures T(n) <= T(n/5) + T(7n/10) + O(n) = O(n).
    """
    if len(arr) <= 5:
        return sorted(arr)[k-1]

    # Step 1 & 2: Median of each group of 5
    groups = [arr[i:i+5] for i in range(0, len(arr), 5)]
    medians = [sorted(g)[len(g)//2] for g in groups]

    # Step 3: Median of medians (recursive)
    pivot = median_of_medians(medians, len(medians)//2 + 1)

    # Step 4: Partition around pivot
    low  = [x for x in arr if x < pivot]
    high = [x for x in arr if x > pivot]
    equal_count = len(arr) - len(low) - len(high)

    # Step 5: Recurse on the relevant partition
    if   k <= len(low):                      return median_of_medians(low, k)
    elif k <= len(low) + equal_count:        return pivot
    else:                                    return median_of_medians(high, k - len(low) - equal_count)

print(median_of_medians([3,1,4,1,5,9,2,6,5,3,5], 6))  # 5

# Why O(n) worst case?
# Group-of-5 medians: n/5 medians, recursion on n/5 elements -> T(n/5)
# Pivot guarantees: at least 3 * ceil(n/5)/2 elements on each side
#   = >= 3n/10 elements on both sides
#   = at most 7n/10 elements in the recursive call -> T(7n/10)
# T(n) = T(n/5) + T(7n/10) + O(n) -- solves to O(n) by substitution
Theory vs Practice
Median-of-medians has large constants: the overhead of grouping, finding group medians, and two recursive calls makes it ~10x slower than quickselect in practice. Python's statistics.median() uses sorting. For production code, use randomized quickselect. Median-of-medians matters when a malicious adversary can choose inputs and an O(n) worst-case guarantee is required.

Introselect

def introselect(arr, k):
    """Hybrid: quickselect with median-of-medians fallback.
    O(n) expected like quickselect, O(n) worst case like MOM.
    Used by numpy's np.partition() and C++ std::nth_element().
    """
    arr = list(arr)
    lo, hi = 0, len(arr) - 1
    target = k - 1
    budget = 3 * len(arr)  # switch to MOM if budget exceeded

    while lo < hi:
        if budget <= 0:
            # Pivot guarantee: use median-of-medians for the subarray
            sub = arr[lo:hi+1]
            pivot = median_of_medians(sub, len(sub)//2 + 1)
            pivot_idx = sub.index(pivot) + lo
            arr[pivot_idx], arr[hi] = arr[hi], arr[pivot_idx]
        else:
            budget -= hi - lo

        pivot_idx = _partition(arr, lo, hi)
        if   pivot_idx < target: lo = pivot_idx + 1
        elif pivot_idx > target: hi = pivot_idx - 1
        else: break

    return arr[target]

# NumPy: np.partition(arr, k) implements introselect
# C++: std::nth_element uses introselect — O(n) worst case guaranteed

Practice Problems
  1. Kth Largest Element in a Stream (LeetCode 703): design a class that finds the kth largest element in a stream of integers. Use a min-heap of size k — O(log k) per insertion.
  2. Find the median of two sorted arrays (LeetCode 4) in O(log(min(m,n))). This is NOT a selection problem on unsorted data — it requires binary search on the partition boundary.
  3. Weighted median: given elements with weights where sum of weights = 1, find the weighted median (element where cumulative weight first reaches 0.5). Solve in O(n) using quickselect.
  4. Prove that any comparison-based selection algorithm requires at least n - 1 comparisons for finding the minimum, and at least n - 1 + ceil(log n) for finding the second smallest.

    Key Takeaways

  • Quickselect finds the kth smallest in O(n) expected, O(n^2) worst case — use random pivot to make adversarial input infeasible.
  • The recurrence T(n) = n + T(n/2) on average (pivot near median) solves to T(n) = 2n = O(n) by geometric series.
  • Median-of-medians guarantees O(n) worst case by ensuring the pivot eliminates at least 30% of elements each step.
  • Introselect = quickselect + MOM fallback — O(n) worst case in practice; used by C++ std::nth_element and NumPy np.partition.
  • For k << n, a min-heap of size k gives O(n log k) — better than O(n log n) sort, sometimes better than O(n) quickselect due to cache effects.
  • Selection != top-k: kth smallest is a single value; top-k requires all k values. Use heapq.nsmallest(k) for top-k in Python.
