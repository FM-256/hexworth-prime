Divide and Conquer

Merge sort splits the array in half, recursively sorts each half, then merges the two sorted halves. The merge step compares elements from both halves in order, producing a sorted output in O(n) time. This yields the recurrence T(n) = 2T(n/2) + O(n), which solves to T(n) = O(n log n) by the Master Theorem (case 2).

def merge_sort(arr):
    """Top-down merge sort. Stable, O(n log n) all cases, O(n) space.
    Recurrence: T(n) = 2T(n/2) + O(n)  ->  T(n) = O(n log n)
    Master Theorem case 2: a=2, b=2, f(n)=n, log_b(a)=1, f(n)=n^log_b(a)
    """
    if len(arr) <= 1: return arr
    mid = len(arr) // 2
    left  = merge_sort(arr[:mid])
    right = merge_sort(arr[mid:])
    return merge(left, right)

def merge(left, right):
    """Merge two sorted arrays — O(n) time, O(n) space."""
    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:  # <= preserves stability
            result.append(left[i]); i += 1
        else:
            result.append(right[j]); j += 1
    result.extend(left[i:])
    result.extend(right[j:])
    return result

# In-place merge sort: avoids O(n) allocation per call
def merge_sort_inplace(arr, lo=0, hi=None):
    if hi is None: hi = len(arr)
    if hi - lo <= 1: return
    mid = (lo + hi) // 2
    merge_sort_inplace(arr, lo, mid)
    merge_sort_inplace(arr, mid, hi)
    # Merge arr[lo:mid] and arr[mid:hi] into arr[lo:hi]
    tmp = arr[lo:hi]
    i, j, k = 0, mid-lo, lo
    while i < mid-lo and j < hi-lo:
        if tmp[i] <= tmp[j]: arr[k] = tmp[i]; i += 1
        else:                arr[k] = tmp[j]; j += 1
        k += 1
    while i < mid-lo: arr[k] = tmp[i]; i += 1; k += 1
    while j < hi-lo:  arr[k] = tmp[j]; j += 1; k += 1

Bottom-Up Merge Sort

Bottom-up merge sort avoids recursion entirely. It starts by treating each element as a sorted run of length 1, then iteratively merges adjacent pairs, doubling the run length each pass. This is cache-friendlier and is the basis for Timsort's merge phase.

def merge_sort_bottom_up(arr):
    """Iterative merge sort — no recursion stack, same O(n log n) time."""
    n = len(arr)
    width = 1
    while width < n:
        for lo in range(0, n, 2 * width):
            mid = min(lo + width, n)
            hi  = min(lo + 2 * width, n)
            if mid < hi:  # only merge if right half exists
                tmp = arr[lo:hi]
                i, j, k = 0, mid-lo, lo
                while i < mid-lo and j < len(tmp):
                    if tmp[i] <= tmp[j]: arr[k] = tmp[i]; i += 1
                    else:                arr[k] = tmp[j]; j += 1
                    k += 1
                while i < mid-lo: arr[k] = tmp[i]; i += 1; k += 1
                while j < len(tmp): arr[k] = tmp[j]; j += 1; k += 1
        width *= 2
    return arr

Counting Inversions

An inversion is a pair (i, j) where i < j but arr[i] > arr[j]. The number of inversions measures how far an array is from sorted — it equals the number of swaps bubble/insertion sort would make. Merge sort counts them in O(n log n) as a byproduct of the merge step.

def count_inversions(arr):
    """Count inversions in O(n log n) by modifying merge sort.

    Key insight: when merging, if arr[i] > arr[j], then ALL elements
    from arr[i] to arr[mid] are > arr[j] (both halves are sorted).
    This adds (mid - i) inversions at once.
    """
    if len(arr) <= 1: return arr, 0
    mid = len(arr) // 2
    left, li  = count_inversions(arr[:mid])
    right, ri = count_inversions(arr[mid:])

    merged, count = [], li + ri
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            merged.append(left[i]); i += 1
        else:
            # left[i..] are all > right[j] — each is an inversion
            merged.append(right[j]); j += 1
            count += len(left) - i
    merged.extend(left[i:]); merged.extend(right[j:])
    return merged, count

arr = [2, 4, 1, 3, 5]
_, inv = count_inversions(arr)
print(inv)  # 3: pairs (2,1), (4,1), (4,3)

External Sort (K-Way Merge)

When data exceeds RAM, external sorting breaks the file into sorted chunks, writes them to disk, then merges using a min-heap. This minimizes disk I/O — the bottleneck for large datasets.

import heapq

def k_way_merge(sorted_lists):
    """Merge k sorted iterables in O(N log k) where N = total elements.

    External sort pattern:
      Phase 1: Read M elements at a time, sort in memory, write chunk to disk.
      Phase 2: Open all chunk files; use k-way merge with min-heap.
    Only k iterators (chunk file handles) + heap of k elements needed in memory.
    """
    heap = []
    iters = [iter(lst) for lst in sorted_lists]

    # Seed heap with first element from each iterator
    for i, it in enumerate(iters):
        try:
            heapq.heappush(heap, (next(it), i, it))
        except StopIteration:
            pass

    while heap:
        val, i, it = heapq.heappop(heap)
        yield val
        try:
            heapq.heappush(heap, (next(it), i, it))  # refill from same iterator
        except StopIteration:
            pass

lists = [[1,4,7], [2,5,8], [3,6,9]]
print(list(k_way_merge(lists)))  # [1,2,3,4,5,6,7,8,9]

# Optimal external sort:
# Phase 1: N/M sorted runs of size M (M = RAM)
# Phase 2: 1 merge pass with k = N/M — total I/O: O(N/B * log_{M/B}(N/B)) blocks
# where B = disk block size. Double-buffering hides I/O latency during merging.

Natural Merge Sort

def natural_merge_sort(arr):
    """Exploit existing sorted runs — O(n) on sorted input, O(n log n) worst.
    Scan for monotonically non-decreasing runs, then merge adjacent pairs.
    """
    def find_runs(arr):
        runs = []
        i = 0
        while i < len(arr):
            j = i + 1
            while j < len(arr) and arr[j] >= arr[j-1]: j += 1
            runs.append(arr[i:j]); i = j
        return runs

    runs = find_runs(arr)
    while len(runs) > 1:
        new_runs = []
        for i in range(0, len(runs), 2):
            if i + 1 < len(runs): new_runs.append(merge(runs[i], runs[i+1]))
            else:                 new_runs.append(runs[i])
        runs = new_runs
    return runs[0] if runs else []

# If the array has k runs of average length n/k:
# merge passes = ceil(log2(k)), total work = O(n * log k)
# For nearly sorted data (k=O(1) runs): O(n) — much better than O(n log n)
Timsort is Natural Merge Sort
Python's Timsort starts by finding natural runs (extending descending runs by reversing them), enforces a minimum run length of 32-64 (using insertion sort to extend short runs), then merges using a sophisticated stack-based merge policy that maintains invariants ensuring O(n log n) worst case while achieving O(n) on partially sorted data.

    Key Takeaways

  • Merge sort is O(n log n) in all cases — the only simple comparison sort with a worst-case guarantee (unlike quicksort's O(n^2) worst case).
  • Stability requires using <= in the merge comparison — this preserves original relative order of equal elements.
  • Bottom-up merge sort avoids recursion and is cache-friendlier: iteratively double the merge width until the whole array is merged.
  • Inversions are counted in O(n log n) by modifying merge: when left[i] > right[j], there are (mid - i) inversions, not just 1.
  • External sort uses k-way merge with a min-heap — O(N log k) with only k + O(1) elements in memory at any time.
  • Natural merge sort detects existing runs and achieves O(n) on nearly-sorted data — Timsort extends this with stack-based merge policies.
