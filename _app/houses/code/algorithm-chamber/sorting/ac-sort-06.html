Breaking the O(n log n) Barrier

The O(n log n) lower bound applies only to the comparison model. If we know something about the structure of keys — they are integers in a bounded range, or fixed-length strings — we can sort without comparisons and achieve O(n) or O(d*n).

The Trade-Off
Non-comparison sorts trade time for assumptions: counting sort needs O(k) memory; radix sort needs integer keys of bounded width; bucket sort needs uniformly distributed input. When these assumptions hold, they are strictly faster than any comparison sort. When they don't hold, they fail or perform poorly.

Counting Sort

Counting sort counts the frequency of each key, computes prefix sums to find output positions, then places each element in its correct position. It is O(n + k) time and space where k is the key range.

def counting_sort(arr, key=lambda x: x):
    """Stable, O(n + k) time and space. k = max key value.

    Stability is critical: when used as a subroutine in radix sort,
    equal-key elements must preserve their order from the previous pass.
    The reverse-iteration in the scatter phase achieves this.
    """
    if not arr: return arr
    keys = [key(x) for x in arr]
    k = max(keys) + 1

    # Step 1: Count frequencies
    count = [0] * k
    for v in keys: count[v] += 1

    # Step 2: Prefix sum — count[v] = number of elements with key <= v
    for v in range(1, k): count[v] += count[v-1]

    # Step 3: Scatter — iterate in reverse for stability
    output = [None] * len(arr)
    for i in range(len(arr)-1, -1, -1):
        v = keys[i]
        count[v] -= 1
        output[count[v]] = arr[i]

    return output

print(counting_sort([4,2,2,8,3,3,1]))  # [1,2,2,3,3,4,8]

# Generalized: sort by a derived integer key (e.g., sort students by grade 0-100)
students = [('Alice',87), ('Bob',92), ('Carol',87), ('Dan',91)]
result = counting_sort(students, key=lambda s: s[1])
# Stability: Alice precedes Carol (both grade 87) — original order preserved

LSD Radix Sort

LSD (Least Significant Digit) radix sort processes digits from right to left. For each digit position, it applies stable counting sort. After d passes, the array is fully sorted. Each pass is O(n + b) where b is the base; total: O(d * (n + b)).

def radix_sort_lsd(arr, base=10):
    """LSD radix sort — O(d * (n + base)) where d = digits in max value.
    Stable: correct relative order from previous pass preserved.
    Requires integers >= 0.
    """
    if not arr: return arr
    max_val = max(arr)
    exp = 1
    while max_val // exp > 0:
        arr = _counting_sort_digit(arr, exp, base)
        exp *= base
    return arr

def _counting_sort_digit(arr, exp, base):
    """Stable sort by digit at position exp — O(n + base)."""
    n = len(arr)
    output = [0] * n
    count = [0] * base
    for x in arr: count[(x // exp) % base] += 1
    for i in range(1, base): count[i] += count[i-1]
    for i in range(n-1, -1, -1):  # reverse for stability
        d = (arr[i] // exp) % base
        count[d] -= 1
        output[count[d]] = arr[i]
    return output

print(radix_sort_lsd([170,45,75,90,802,24,2,66]))  # [2,24,45,66,75,90,170,802]

# Choosing base:
# base=10:    d=ceil(log10(max)), each pass O(n+10)
# base=256:   d=ceil(log256(max)), each pass O(n+256) — best for 32-bit ints (d=4)
# base=2^k:   digit extraction via bit shift — fast in practice
# Optimal base minimizes d*(n+base): sqrt(n) is theoretically optimal for n elements

MSD Radix Sort

def radix_sort_msd(arr, base=256):
    """MSD radix sort — processes most significant digit first.
    Naturally produces sorted output; can terminate early per bucket.
    Better for strings (variable length); LSD is simpler for fixed-width integers.
    """
    if not arr: return arr
    max_digits = len(str(max(arr)))
    _msd_helper(arr, 0, len(arr)-1, max_digits-1, base)
    return arr

def _msd_helper(arr, lo, hi, digit_pos, base):
    if lo >= hi or digit_pos < 0: return
    exp = base ** digit_pos
    buckets = [[] for _ in range(base)]
    for i in range(lo, hi+1):
        d = (arr[i] // exp) % base
        buckets[d].append(arr[i])
    idx = lo
    for b, bucket in enumerate(buckets):
        for x in bucket: arr[idx] = x; idx += 1
        bucket_end = idx - 1
        bucket_start = bucket_end - len(bucket) + 1
        _msd_helper(arr, bucket_start, bucket_end, digit_pos-1, base)

# LSD vs MSD:
# LSD: simpler, fixed-width keys, always O(d*n) passes — no early stop
# MSD: recursive by digit, handles variable-length strings, early stop when
#      all elements in a bucket have same remaining prefix

Bucket Sort

def bucket_sort(arr, num_buckets=None):
    """Average O(n) for uniformly distributed input in [0, 1).
    Distribute into buckets, sort each bucket (insertion sort), concatenate.

    Expected O(n): With n buckets and n uniform values,
    each bucket has O(1) elements on average -> O(1) sort per bucket.
    Worst case: all elements in one bucket -> O(n^2) for insertion sort.
    """
    if not arr: return arr
    n = len(arr)
    if num_buckets is None: num_buckets = n

    mn, mx = min(arr), max(arr)
    rng = mx - mn if mx != mn else 1

    # Create empty buckets
    buckets = [[] for _ in range(num_buckets)]

    # Distribute elements into buckets
    for x in arr:
        idx = int((x - mn) / rng * (num_buckets - 1))
        buckets[idx].append(x)

    # Sort each bucket and concatenate
    result = []
    for bucket in buckets:
        bucket.sort()  # insertion sort for small buckets
        result.extend(bucket)
    return result

print(bucket_sort([0.78, 0.17, 0.39, 0.26, 0.72, 0.94, 0.21, 0.12]))
# [0.12, 0.17, 0.21, 0.26, 0.39, 0.72, 0.78, 0.94]

    Key Takeaways

  • Non-comparison sorts bypass the O(n log n) lower bound by exploiting key structure — they do not use pairwise comparisons.
  • Counting sort is O(n + k): count frequencies, prefix-sum for positions, scatter in reverse (for stability). Use when k = O(n).
  • LSD radix sort applies stable counting sort d times from least to most significant digit — O(d*(n+b)), correct for any digit width.
  • Stability of counting sort is not optional when used inside radix sort — without it, earlier digit passes would be overwritten incorrectly.
  • Bucket sort achieves O(n) average for uniformly distributed input. Worst case O(n^2) when all elements land in one bucket.
  • Radix sort with base 256 is very efficient for 32-bit integers: d=4 passes, each O(n+256) — outperforms comparison sorts for large n.
