Interpolation Search

Interpolation search improves on binary search for uniformly distributed data. Instead of always probing the midpoint, it estimates the probe position using linear interpolation — analogous to how a human searches a phone book by jumping to the approximate alphabetical location.

def interpolation_search(arr, target):
    """O(log log n) average for uniform distributions, O(n) worst case.

    Probe formula: pos = lo + (target - arr[lo]) / (arr[hi] - arr[lo]) * (hi - lo)
    Intuition: linear interpolation of target's position between arr[lo] and arr[hi].
    """
    lo, hi = 0, len(arr) - 1
    while lo <= hi and arr[lo] <= target <= arr[hi]:
        if lo == hi:
            return lo if arr[lo] == target else -1

        # Interpolate probe position
        pos = lo + int((target - arr[lo]) * (hi - lo) / (arr[hi] - arr[lo]))

        if   arr[pos] == target: return pos
        elif arr[pos] < target:  lo = pos + 1
        else:                    hi = pos - 1
    return -1

arr = list(range(0, 1000, 10))  # uniform: [0, 10, 20, ..., 990]
print(interpolation_search(arr, 420))  # 42 (index)
print(interpolation_search(arr, 425))  # -1 (not found)

# Analysis:
# Uniform distribution: each probe eliminates a constant fraction of remaining
# candidates by "guessing" the position. Expected probes = O(log log n).
# For n=10^9: binary search ≈ 30 probes, interpolation ≈ 5 probes (log2(log2(10^9))≈5).
#
# Worst case (exponential distribution like [1, 2, 4, 8, ...]): probe always lands
# near one end -> O(n) comparisons. Use binary search for non-uniform data.

Exponential Search

Exponential search (also called doubling search) finds a range containing the target by doubling the index until it exceeds the target, then applies binary search within that range. It is ideal for unbounded arrays (streams, virtual arrays) and runs in O(log n) overall.

def exponential_search(arr, target):
    """O(log n) for sorted arrays. Optimal for:
    - Unbounded arrays (don't know length)
    - Arrays where target is near the front
    Phase 1: double index until arr[bound] >= target (O(log i))
    Phase 2: binary search in arr[bound/2 .. min(bound, n-1)] (O(log i))
    Total: O(log i) where i is target's position.
    """
    n = len(arr)
    if arr[0] == target: return 0

    # Phase 1: find upper bound by doubling
    bound = 1
    while bound < n and arr[bound] < target:
        bound *= 2

    # Phase 2: binary search in arr[bound/2 .. min(bound, n-1)]
    lo = bound // 2
    hi = min(bound, n - 1)
    while lo <= hi:
        mid = lo + (hi - lo) // 2
        if   arr[mid] == target: return mid
        elif arr[mid] < target:  lo = mid + 1
        else:                    hi = mid - 1
    return -1

# Better than binary search when:
# - Target is near the beginning (O(log i) vs O(log n) — can be much faster)
# - Array size is unknown or very large (a virtual sorted stream)

# Fibonacci search: similar idea but uses Fibonacci numbers for indices
# instead of doubling. Slightly better cache behavior on some architectures
# because it avoids division. Used in some embedded systems.

Ternary Search

Ternary search finds the maximum (or minimum) of a unimodal function — a function that strictly increases then strictly decreases (or vice versa). It divides the range into thirds at each step, eliminating one third per iteration.

def ternary_search(f, lo, hi, epsilon=1e-9):
    """Find x in [lo, hi] that maximizes f(x) where f is unimodal.
    O(log(1/epsilon)) iterations. Each iteration makes 2 function evaluations
    and eliminates 1/3 of the remaining range.
    """
    while hi - lo > epsilon:
        m1 = lo + (hi - lo) / 3
        m2 = hi - (hi - lo) / 3
        if f(m1) < f(m2):
            lo = m1  # max is in [m1, hi]
        else:
            hi = m2  # max is in [lo, m2]
    return (lo + hi) / 2

# Example: maximize f(x) = -(x-3)^2 + 9 on [-10, 10]
def f(x): return -(x-3)**2 + 9
max_x = ternary_search(f, -10, 10)
print(f'Max at x={max_x:.6f}, f(x)={f(max_x):.6f}')  # x=3.000000, f(x)=9.000000

# Integer ternary search (discrete unimodal array)
def ternary_search_int(arr):
    """Find peak element in unimodal array — O(log n)."""
    lo, hi = 0, len(arr) - 1
    while hi - lo > 2:
        m1 = lo + (hi - lo) // 3
        m2 = hi - (hi - lo) // 3
        if arr[m1] < arr[m2]: lo = m1
        else:                 hi = m2
    return arr[max(range(lo, hi+1), key=lambda i: arr[i])]

print(ternary_search_int([1,3,5,7,9,8,6,4,2]))  # 9

Order Statistics Trees

An order statistics tree augments a balanced BST (e.g., Red-Black tree) with a size field at each node — the number of nodes in its subtree. This enables O(log n) select(k) (find kth smallest) and O(log n) rank(x) (count elements smaller than x).

# Python: use sortedcontainers.SortedList for an O(log n) order statistics structure
# pip install sortedcontainers
from sortedcontainers import SortedList

class OrderStatisticsTree:
    """Wrapper around SortedList providing order statistics interface."""
    def __init__(self): self.sl = SortedList()
    def insert(self, x): self.sl.add(x)
    def delete(self, x): self.sl.remove(x)
    def rank(self, x):   return self.sl.bisect_left(x)   # count < x
    def select(self, k): return self.sl[k]                 # kth smallest (0-indexed)
    def count_range(self, lo, hi):
        return self.sl.bisect_left(hi) - self.sl.bisect_right(lo-1)

ost = OrderStatisticsTree()
for v in [5, 3, 8, 1, 9, 2]:
    ost.insert(v)
print(ost.rank(5))      # 3 (three elements less than 5: 1,2,3)
print(ost.select(2))    # 3 (2nd smallest, 0-indexed)
print(ost.count_range(2,6))  # 3 (2,3,5 in range [2,6])

# Manual augmentation for AVL/RB tree:
# Node.size = 1 + left.size + right.size
# Update size on every insert/delete during rotations.
# select(k): if left.size >= k, recurse left; else recurse right with k - left.size - 1
# rank(x): sum sizes of left subtrees along the search path

When Not to Use Binary Search
Binary search requires a sorted, randomly accessible array. For linked lists, use linear search or maintain a sorted structure (skip list). For unsorted data, a hash table gives O(1) exact lookup. For prefix searches, use a trie. The right structure depends on query type, update frequency, and memory constraints — binary search is not always the answer.

    Key Takeaways

  • Interpolation search probes using linear interpolation — O(log log n) average for uniformly distributed data, O(n) worst case. Risky for non-uniform keys.
  • Exponential search doubles the probe index until it exceeds target, then binary searches the identified range — O(log i) where i is the target position.
  • Ternary search finds the extremum of a unimodal function in O(log(range/epsilon)) — reduces range by 1/3 per iteration using 2 function evaluations.
  • Order statistics trees augment BSTs with subtree sizes, enabling O(log n) select(k) and rank(x) alongside all standard BST operations.
  • Python's sortedcontainers.SortedList provides O(sqrt(n)) amortized insert/delete and O(log n) bisect — a practical alternative to a full OSTtree.
  • Choose search structure by query type: exact lookup (hash), range/rank (sorted array + binary search or OST), prefix (trie), unimodal optimization (ternary search).
