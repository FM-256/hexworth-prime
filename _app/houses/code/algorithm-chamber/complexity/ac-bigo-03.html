The Major Complexity Classes

O(1)
Constant Time The operation count does not depend on input size. Accessing an array element by index, hash table lookup (average case), stack push/pop, and arithmetic operations are all O(1). The "1" is a placeholder -- the constant might be large, but it does not grow with n.
arr[i]dict[key]stack.pop()
O(log n)
Logarithmic Time Each step eliminates a constant fraction of the remaining work. Binary search halves the search space each step. Balanced BST operations traverse height log n. Even for n = 109, log2(109) ≈ 30 steps. Extremely efficient.
binary_searchBST lookupbit operations
O(n)
Linear Time Must touch every element at least once. Linear scan, counting elements, computing sum/max/min, and single-pass algorithms are O(n). This is often the theoretical lower bound for algorithms that must read all input. Many optimal algorithms are O(n).
linear_searchsum(arr)counting sort
O(n log n)
Linearithmic Time The sweet spot for comparison-based sorting. Merge sort, heapsort, and quicksort (average) all achieve this. It is the provable lower bound for comparison-based sorting -- no comparison sort can be faster. Fast Fourier Transform also runs in O(n log n).
merge_sortheap_sortFFT
O(n²)
Quadratic Time All-pairs comparisons. Simple sorting algorithms (bubble, insertion, selection) and naive matrix algorithms. Acceptable for small inputs (n < 10,000) but becomes prohibitive at n = 106 where n² = 1012 operations -- thousands of years at 109 ops/sec.
bubble_sortnaive matrix multall-pairs
O(2n)
Exponential Time Exploring all subsets of n elements, naive recursive Fibonacci without memoization, brute-force subset-sum. At n = 50, 250 ≈ 1015 -- about 11 days at 109 ops/sec. At n = 100, the age of the universe is insufficient. These algorithms are only tractable for tiny n.
power_setnaive_fibbrute_TSP

Code Signatures for Each Class

Python -- One Example Per Complexity Class
# O(1) -- no loops, no recursion
def get_first(arr): return arr[0]

# O(log n) -- halving at each step
def binary_search(arr, t, lo=0, hi=None):
    hi = hi if hi is not None else len(arr)-1
    if lo > hi: return -1
    mid = (lo+hi)//2
    if arr[mid]==t: return mid
    return binary_search(arr,t,mid+1,hi) if arr[mid]else binary_search(arr,t,lo,mid-1)

# O(n) -- one pass
def linear_sum(arr): return sum(arr)

# O(n log n) -- merge sort skeleton
def merge_sort(arr):
    if len(arr) <= 1: return arr
    m = len(arr)//2
    L, R = merge_sort(arr[:m]), merge_sort(arr[m:])
    return merge(L, R)  # O(n) merge step

# O(n^2) -- nested independent loops
def bubble_sort(arr):
    n = len(arr)
    for i in range(n):
        for j in range(n-i-1):
            if arr[j]>arr[j+1]: arr[j],arr[j+1] = arr[j+1],arr[j]

# O(2^n) -- two recursive calls, both on n-1
def naive_fib(n): return n if n<=1 else naive_fib(n-1)+naive_fib(n-2)

Practice Problems

  1. For each algorithm, state its complexity class and identify the code pattern that signals it: (a) Python's sorted(), (b) dictionary lookup d[k], (c) finding all pairs in a list, (d) computing all subsets of a set.
  2. Approximately how many seconds would an O(n²) algorithm take on n = 106 items if the machine executes 109 operations per second?
  3. An algorithm runs in O(n log n) on an input of size 106 in 2 seconds. Estimate its runtime on 107 items.
  4. True or false (and explain): an O(n²) algorithm can be faster than an O(n log n) algorithm for some input sizes.
  5. Write an O(n log n) Python function that, given an unsorted list, finds and returns all duplicate elements.

Key Takeaways

  • O(1): no growth -- indexing, hash lookup, stack ops; the constant can be large but is input-independent
  • O(log n): input halved each step -- binary search, BST, bit manipulation; still fast at n = 109
  • O(n): one pass over input -- required for any algorithm that must inspect all elements
  • O(n log n): optimal comparison sort; results from divide-and-conquer with O(n) merge step
  • O(n²): all-pairs comparisons -- fine up to n ~ 104, catastrophic above that
  • O(2n) and O(n!): exponential growth makes these intractable beyond n ~ 30-50
