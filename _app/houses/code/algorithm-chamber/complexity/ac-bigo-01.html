Why Asymptotic Notation?

An algorithm's exact runtime depends on the hardware, compiler, and input. What is machine-independent and input-independent is the algorithm's growth rate -- how the number of operations scales as the input size n grows toward infinity.

Two sorting algorithms both correct for n = 10 items might have drastically different behavior at n = 106. Asymptotic notation gives us precise vocabulary to describe and compare growth rates, dropping lower-order terms and constant factors that become irrelevant at scale.

The Scale Argument

An O(n²) algorithm on modern hardware might beat an O(n log n) algorithm for n = 100 if the constant factor is small. At n = 109, n² is 1018 operations while n log n is roughly 3 × 1010. At scale, the asymptotic class dominates. Asymptotic analysis is about large n behavior.

Big O: Upper Bound

f(n) = O(g(n)) means f grows no faster than g. Formally:

f(n) = O(g(n))   iff   ∃c > 0, n0 > 0: ∀n ≥ n0, f(n) ≤ c · g(n)

Equivalently, using limits: f(n) = O(g(n)) iff limn→∞ f(n)/g(n) < ∞ (the limit exists and is finite, possibly 0).

Big O is the most common notation because algorithm designers typically want to bound the worst case -- guaranteeing the algorithm is no slower than claimed.

f(n) = Θ(g(n)) iff f(n) = O(g(n)) AND f(n) = Ω(g(n)). Theta is the most informative bound because it is tight on both sides.

Proving Big O with the Formal Definition

To prove f(n) = O(g(n)), exhibit specific constants c and n0 satisfying the definition. You do not need the smallest constants -- any valid pair works.

Example -- Prove 3n^2 + 5n + 7 = O(n^2)
# Goal: find c and n0 such that 3n^2 + 5n + 7 <= c*n^2 for all n >= n0
#
# Strategy: bound each term above by something with n^2
# For n >= 1:
#   5n  <= 5n^2
#   7   <= 7n^2
# So: 3n^2 + 5n + 7 <= 3n^2 + 5n^2 + 7n^2 = 15n^2
#
# Choose c = 15, n0 = 1.
# Then for all n >= 1: 3n^2 + 5n + 7 <= 15n^2  QED

# Verify numerically
def verify_bigo(c, n0, n_range=1000):
    f = lambda n: 3*n**2 + 5*n + 7
    g = lambda n: c * n**2
    return all(f(n) <= g(n) for n in range(n0, n_range))

print(verify_bigo(c=15, n0=1))  # True

Common Simplification Rules

1. Drop lower-order terms: n² + n = O(n²). 2. Drop constants: 5n = O(n). 3. O(f) + O(g) = O(max(f,g)). 4. O(f) × O(g) = O(f × g). 5. loga(n) = Θ(logb(n)) for any constants a, b > 1 -- log base doesn't matter asymptotically.

Practice Problems

  1. Using the formal definition, prove that n² ≠ O(n). (Show that no constants c, n0 can satisfy the definition.)
  2. Determine whether n log n = O(n²). Use the limit definition.
  3. Rank these functions from slowest to fastest growth: n!, 2n, n3, n log n, log2 n, √n.
  4. Is 5n + 3 = Θ(n)? Prove it by finding constants for both the O and Ω bounds.
  5. Explain in plain English why the base of a logarithm does not matter for asymptotic analysis.

Key Takeaways

  • Asymptotic notation describes growth rate behavior as n → ∞, dropping constants and lower-order terms
  • Big O (upper bound), Ω (lower bound), Θ (tight bound) -- Θ is most informative
  • Little-o and little-ω are strict versions; f = o(g) means f grows strictly slower than g
  • To prove O, exhibit constants c and n0; to disprove, show no such constants exist
  • Growth hierarchy: O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2n) < O(n!)
  • Log base changes are constant factors -- asymptotically irrelevant. All logs are Θ of each other.
