The Complexity Hierarchy

Complexity theory organises problems by the resources needed to solve or verify them. The classes form a nested containment structure — each larger class includes all problems in the smaller ones. Whether some of those containments are strict (i.e., the classes are actually different sets) is the central open question in computer science.

EXPTIME — solvable in 2poly(n) time
▼
PSPACE — solvable with poly space
▼
NP — verifiable in polynomial time
▼
NP-complete (hardest in NP)
▼
P — solvable in polynomial time
The million-dollar question: Is P = NP? If yes, every problem whose solution can be quickly checked can also be quickly solved. Almost all experts believe P ≠ NP, but no proof exists.
Class Informal definition Formal resource bound Example
P Solvable efficiently DTIME(nk) Sorting, shortest path
NP Solution verifiable efficiently NTIME(nk) 3-SAT, TSP decision
co-NP Non-solution verifiable efficiently complement of NP TAUTOLOGY, graph non-3-colorability
NP-hard At least as hard as every NP problem Every NP problem ≤p this Halting problem, TSP optimisation
NP-complete NP-hard AND in NP NP ∩ NP-hard 3-SAT, Vertex Cover, Clique
PSPACE Solvable with polynomial memory DSPACE(nk) TQBF, many game strategies
EXPTIME Solvable in exponential time DTIME(2poly(n)) Go (exact), chess (exact)

P and NP — Precise Definitions

P is the set of decision problems (yes/no answer) solvable by a deterministic Turing machine in O(nk) steps for some constant k.

NP (non-deterministic polynomial time) is the set of decision problems where any "yes" answer has a certificate checkable in polynomial time. 

# Illustrating the P vs NP distinction with 3-SAT

# VERIFIER — polynomial time (this is what makes it NP)
def verify_3sat(formula, assignment):
    """
    formula: list of clauses, each a list of 3 literals
    assignment: dict mapping variable -> bool
    Returns True iff all clauses are satisfied.
    O(3 * len(formula)) = O(n)
    """
    for clause in formula:
        satisfied = any(
            assignment.get(abs(lit), False) == (lit > 0)
            for lit in clause
        )
        if not satisfied:
            return False
    return True

# SOLVER — exponential time (brute force; no poly algorithm known)
def solve_3sat_brute(formula, variables):
    """Try all 2^n assignments — O(2^n * n)"""
    from itertools import product
    n = len(variables)
    for vals in product([True, False], repeat=n):
        assignment = dict(zip(variables, vals))
        if verify_3sat(formula, assignment):
            return assignment   # satisfying assignment found
    return None               # unsatisfiable

# Example: (x1 OR x2 OR x3) AND (NOT x1 OR x2 OR x4) AND ...
formula  = [[1, 2, 3], [-1, 2, 4], [-2, -3, 4]]
variables = [1, 2, 3, 4]
result = solve_3sat_brute(formula, variables)
print(result)   # {1: True, 2: False, 3: False, 4: True} (one solution)
Key insight: Every problem in P is also in NP (you can verify a solution in ≤ time to find it). So P ⊆ NP. The open question is whether the inclusion is proper.

NP-hard vs NP-complete

A problem H is NP-hard if every problem L in NP can be reduced to H in polynomial time (L ≤p H). This means H is at least as hard as all NP problems — but H need not itself be in NP.

A problem is NP-complete when it is both NP-hard and in NP. These are the hardest problems still inside NP — the boundary between tractable and intractable.

Problem In NP? NP-hard? Classification
Sorting Yes No P (also NP)
3-SAT Yes Yes NP-complete
TSP decision (is there a tour ≤ k?) Yes Yes NP-complete
TSP optimisation (find shortest tour) No (not a decision problem) Yes NP-hard, not NP-complete
Halting problem No (undecidable) Yes NP-hard, not NP-complete
Chess (win in k moves?) No (EXPTIME) Yes EXPTIME-complete
Common mistake: "NP-hard" is not the same as "NP-complete." NP-hard problems can be harder than NP problems — they may not even be decidable.

co-NP

co-NP is the class of decision problems whose complement is in NP. Equivalently, a problem is in co-NP if "no" answers have short certificates checkable in polynomial time.

NP problem co-NP complement
3-SAT: "Is this formula satisfiable?" TAUTOLOGY: "Is every assignment satisfying?"
GRAPH 3-COLORABILITY: "Can this graph be 3-colored?" NON-3-COLORABILITY: "Can this graph NOT be 3-colored?"
COMPOSITE: "Is n composite?" (actually in P via AKS) PRIMES: "Is n prime?" (also in P)
CLIQUE: "Does G have a clique of size k?" INDEPENDENT SET complement query

It is widely believed that NP ≠ co-NP (i.e., some NP problems have no short "no" certificates), though this too is unproven. We do know: if NP = co-NP, then P ≠ NP would be even harder to prove, and the polynomial hierarchy would collapse. 

# PRIMES is in co-NP (the "no" case = COMPOSITE has short certificate)
# A primality certificate for the "yes" (prime) case is a Pratt certificate
# — a Lucas primality proof transmittable in O(log^2 n) bits

def is_prime_deterministic(n: int) -> bool:
    """
    Deterministic primality test.
    Modern approach: AKS algorithm is poly-time — PRIMES is in P.
    (Agrawal, Kayal, Saxena — 2002)
    """
    if n < 2: return False
    if n == 2: return True
    if n % 2 == 0: return False
    i = 3
    while i * i <= n:
        if n % i == 0: return False
        i += 2
    return True

# Composite certificate: just provide a factor
def composite_certificate(n: int):
    i = 2
    while i * i <= n:
        if n % i == 0:
            return i     # short certificate — just one factor
        i += 1
    return None  # no factor found → n is prime

PSPACE

PSPACE is the class of problems solvable by a deterministic Turing machine using polynomial space (memory), with no restriction on time. Because time ≥ space, PSPACE contains NP.

The PSPACE-complete canonical problem is TQBF (True Quantified Boolean Formula): given a fully quantified Boolean formula like ∀x ∃y (x ∨ y), is it true?

Problem Class Why
TQBF (alternating quantifiers) PSPACE-complete Alternating quantifiers = PSPACE-complete by Stockmeyer & Meyer
Game strategy (Generalized Geography) PSPACE-complete Optimal play requires exploring exponential game trees in poly space
Regex pattern matching (with backrefs) NP-hard (some PSPACE) Backreferences make matching PSPACE-complete in general
Regular language equivalence PSPACE-complete Subset construction DFA size can be exponential
Checkers (n × n board) EXPTIME-complete Game length exponential; requires exponential time for optimal play
Savitch's theorem: NPSPACE = PSPACE. Any non-deterministic polynomial-space algorithm can be simulated deterministically in polynomial space (with a quadratic blowup). This is surprising — the non-determinism buys nothing for space. 
# TQBF example: ∀x ∃y (x ∨ y) — is this true?

def eval_tqbf(formula, quantifiers, variables, assignment=None):
    """
    Recursive TQBF evaluator.
    quantifiers: list of ('forall'|'exists', var_name)
    This runs in O(2^n) time but O(n) space (depth-first recursion stack).
    """
    if assignment is None:
        assignment = {}
    if not quantifiers:
        return formula(assignment)    # evaluate the unquantified core

    quantifier, var = quantifiers[0]
    rest = quantifiers[1:]

    results = []
    for val in [True, False]:
        assignment[var] = val
        results.append(eval_tqbf(formula, rest, variables, assignment))
        del assignment[var]

    if quantifier == 'forall':
        return all(results)    # ∀ — must hold for every value
    else:
        return any(results)    # ∃ — must hold for at least one value

# Test: ∀x ∃y (x ∨ y) — should be True
eval_tqbf(
    formula     = lambda a: a['x'] or a['y'],
    quantifiers = [('forall', 'x'), ('exists', 'y')],
    variables   = ['x', 'y']
)  # True — for any x, set y=True to satisfy

EXPTIME

EXPTIME (also written EXP) is the class of problems solvable in O(2p(n)) time for some polynomial p(n). We know for certain that P ⊊ EXPTIME — this is one of the few known strict separations.

Problem Complexity Why not lower?
Chess (n×n, optimal play) EXPTIME-complete Game tree depth is polynomial but width is exponential
Go (n×n, optimal play) EXPTIME-complete Same reason; board states up to 3n²
Succinct graph problems EXPTIME-complete Graph encoded exponentially smaller than it is
LTL model checking (infinite state) EXPTIME State space can be doubly exponential in formula size
Practice implication: If a problem is EXPTIME-complete, no polynomial-time algorithm exists (unless P = EXPTIME, which would collapse the entire hierarchy and imply P = NP). These problems are provably intractable.

Approximation Algorithms

When a problem is NP-hard, we cannot expect an efficient exact algorithm (assuming P ≠ NP). Instead, we seek approximation algorithms — polynomial-time algorithms that return a solution within a guaranteed factor of optimal.

An algorithm has an approximation ratio α if for every instance the returned solution cost C satisfies: 

# For a minimisation problem:
#   C ≤ α * OPT  where α ≥ 1

# For a maximisation problem:

# ── Vertex Cover 2-approximation ──────────────────────────────────────

def vertex_cover_2approx(edges):
    """
    Greedily pick both endpoints of each unmatched edge.
    The resulting set is always a vertex cover of size ≤ 2 * OPT.
    Proof: picked edges form a matching → OPT must include at least
           one endpoint per edge → OPT ≥ |matching| → cover ≤ 2*OPT.
    """
    covered = set()
    cover   = set()
    for u, v in edges:
        if u not in covered and v not in covered:
            cover.add(u)
            cover.add(v)
            covered.add(u)
            covered.add(v)
    return cover

edges = [(1,2), (1,3), (2,4), (3,4), (4,5)]
print(vertex_cover_2approx(edges))  # e.g. {1, 2, 3, 4} — valid cover
Vertex Cover 2-approx

Greedy maximal matching. Inapproximable below 2 (assuming Unique Games Conjecture).

Metric TSP 1.5-approx

Christofides–Serdyukov algorithm (MST + minimum weight matching on odd-degree vertices).

Set Cover ln(n)-approx

Greedy: always pick the set covering the most uncovered elements. Tight — cannot do better unless P = NP.

Knapsack (0/1) FPTAS

Fully polynomial-time approximation scheme: for any ε > 0, find a solution within (1+ε) of optimal in O(n2 / ε) time.

Max 3-SAT 7/8-approx

Random assignment satisfies 7/8 of clauses in expectation. Hastad's inapproximability: no better ratio unless P = NP.

Inapproximability: Some NP-hard problems have lower bounds on how well any polynomial-time algorithm can approximate them (assuming P ≠ NP). These results come from the PCP theorem: NP = PCP(log n, 1).

Practical Implications

Understanding complexity classes directly informs engineering decisions:

Situation Class diagnosis Engineering response
Problem appears NP-complete No poly-time exact solver expected Use approximation, heuristic, or fixed-parameter tractable algorithm
Input size small (n < 30) Exponential OK Exact backtracking / dynamic programming is fine
Special case of NP-hard problem May be P on restricted input 2-SAT is P; planar graph colouring has special structure
Need only a "good enough" solution Approximation realm Pick algorithm with guaranteed ratio; document the bound
Security parameter choices (crypto) NP-hard assumption underpins security RSA/ECC security relies on factoring/DLOG being hard for random instances
Fixed-parameter tractability (FPT): Many NP-hard problems become tractable when a "parameter" k is small. Vertex Cover is solvable in O(2k * n) — exponential only in k, not n. If k ≤ 20 in practice, this is fast even on large graphs.

Try It — Classification Exercise

For each problem, determine its complexity class:

  1. "Given a sorted array of n integers, is value v present?" — P or NP-complete?
  2. "Given a graph G, does it have a Hamiltonian cycle?" — P or NP-complete?
  3. "Given a QBF ∀x ∃y ∀z φ(x,y,z), is it true?" — NP-complete or PSPACE-complete?
  4. "Given optimal play, who wins on an n×n Go board?" — PSPACE or EXPTIME?
  5. "Does this Turing machine halt on every input?" — Decidable or undecidable? What class?

Answers: (1) P — binary search O(log n). (2) NP-complete — Hamiltonian cycle is NP-complete. (3) PSPACE-complete — TQBF is PSPACE-complete. (4) EXPTIME-complete. (5) Undecidable — co-RE complete, outside the arithmetic hierarchy for the Π2 question.

Key Takeaways

  • P ⊆ NP ⊆ PSPACE ⊆ EXPTIME — whether any inclusion is strict (except P ⊊ EXPTIME) is open
  • NP problems have polynomial-time verifiers; NP-hard problems are at least as hard as all NP problems
  • NP-complete = NP ∩ NP-hard; recognising NP-completeness lets you stop searching for exact poly-time algorithms
  • co-NP is the class where "no" instances have short certificates; NP ≠ co-NP is strongly believed but unproven
  • PSPACE includes problems requiring polynomial space; Savitch's theorem shows NPSPACE = PSPACE
  • EXPTIME problems are provably harder than P — one of the few definitive separations in complexity theory
  • Approximation algorithms provide poly-time solutions with provable quality guarantees for NP-hard optimisation problems
