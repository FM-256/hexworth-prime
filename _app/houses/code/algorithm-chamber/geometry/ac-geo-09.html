Floating-Point Pitfalls

Floating-point arithmetic is not exact. In geometry, tiny errors compound — a point slightly on the wrong side of a line can cause convex hull, sweep line, or triangulation algorithms to fail catastrophically.

PythonThe floating-point trap
# What you expect:
a = 0.1 + 0.2
print(a == 0.3)  # False! 0.1+0.2 = 0.30000000000000004

# Safe comparison with epsilon
EPS = 1e-9
def eq(a, b): return abs(a-b) < EPS
def sign(x): return 0 if abs(x)else (1 if x>0 else -1)

# Orientation with epsilon
def orient_robust(O, A, B):
    val = (A[0]-O[0])*(B[1]-O[1]) - (A[1]-O[1])*(B[0]-O[0])
    return sign(val)
When Epsilon FailsA fixed epsilon is wrong for coordinates of vastly different magnitudes. Use a relative epsilon or exact arithmetic for safety-critical applications (robot surgery, autonomous vehicles, avionics).

from shapely.geometry import Point, Polygon, LineString

square = Polygon([(0,0),(1,0),(1,1),(0,1)])
pt_in  = Point(0.5, 0.5)
pt_out = Point(1.5, 0.5)
print(square.contains(pt_in))   # True
print(square.contains(pt_out))  # False
print(square.area)              # 1.0
print(square.intersection(Polygon([(0.5,0),(1.5,0),(1.5,1),(0.5,1)])).area)  # 0.5

  3. Use scipy.spatial.ConvexHull on 100 random points. How does it compare to your graham_scan?

Key Takeaways

  • Floating-point errors accumulate — use epsilon comparisons everywhere in geometry code.
  • Fixed epsilon only works for coordinates in a known bounded range.
  • For safety-critical geometry, use exact arithmetic (CGAL, or Python's Fraction/Decimal).
  • Shapely handles all 2D degeneracies correctly — use it in production Python geometry work.
