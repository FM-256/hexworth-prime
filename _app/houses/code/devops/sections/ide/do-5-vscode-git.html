VS Code — Git Integration

VS Code ships with powerful Git support out of the box. Master the Source Control panel, inline diffs, merge conflict resolution, and the extensions that turn VS Code into a full Git GUI.

~35 min Module Beginner-Intermediate

Learning Objectives

  • Navigate the Source Control panel to stage, unstage, and commit changes
  • Read gutter indicators and file badges to understand Git status at a glance
  • Stage individual lines and hunks for precise, atomic commits
  • Create branches, switch branches, and compare branches from the status bar
  • Resolve merge conflicts using the built-in 3-way merge editor
  • Use the diff viewer in side-by-side and inline modes
  • Install and configure Git Graph, GitLens, and GitHub Pull Requests extensions
  • Apply Git-related keyboard shortcuts and settings.json tweaks for an optimized workflow

1. Source Control View

The Source Control panel is your primary interface for Git operations inside VS Code. Open it with Ctrl+Shift+G (or click the branch icon in the Activity Bar). When a folder containing a .git directory is open, VS Code automatically detects it and populates the panel.

Panel Anatomy

Message Box The text input at the top where you type your commit message. Press Ctrl+Enter to commit.
Staged Changes Files explicitly added to the staging area. These will be included in your next commit.
Changes Modified, added, or deleted files that are not yet staged. Hover a file to see stage/discard icons.
Merge Changes Only appears during an active merge. Shows files with unresolved conflicts.

Staging and Unstaging

Hover over any file in the Changes section to reveal action icons. Click the + icon to stage it (moves it to Staged Changes). Click the - icon on a staged file to unstage it. You can also stage or unstage all files at once using the icons at the section header level.

Inline Diffs

Click any changed file in the Source Control panel to open a diff view. VS Code shows a side-by-side comparison with additions highlighted in green and deletions in red. This is one of the fastest ways to review what you are about to commit.

Key Concept

The Source Control panel is equivalent to running git status, git add, git reset, and git commit from the terminal — but with a visual interface that makes it harder to miss changes.

2. Git Status in the Editor

VS Code provides real-time Git status feedback directly in the editor — no need to check the Source Control panel or run git status.

Gutter Indicators

The thin colored bar in the left gutter of the editor shows line-level changes compared to the last commit:

Green Bar New lines added. These lines do not exist in the last commit.
Blue Bar Modified lines. The content at these line numbers has changed since the last commit.
Red Triangle Deleted lines. A small red arrow in the gutter marks where lines were removed.

Click on any gutter indicator to see an inline diff popup showing exactly what changed. From that popup you can revert the change back to the committed version with a single click.

File Badges in the Explorer

The Explorer sidebar shows letter badges next to modified files:

BadgeMeaningColor
MModified — file has been changedYellow/Orange
UUntracked — new file not yet added to GitGreen
AAdded — new file staged for commitGreen
DDeleted — file removedRed
CConflict — file has merge conflictsRed
RRenamed — file was renamedGreen
Status Bar Branch Indicator

The bottom-left corner of the status bar always shows the current Git branch. Click it to switch branches, create a new branch, or check out a tag. If the branch indicator shows a sync icon with numbers (e.g., 0 ↓ 2 ↑), it means you have unpushed commits or unpulled changes.

3. Staging & Committing

VS Code goes beyond simple file-level staging. You can stage individual lines or hunks within a file — giving you surgical control over what goes into each commit.

Stage Individual Lines or Hunks

Open a diff view by clicking a changed file in Source Control. In the diff editor, you can:

Stage Hunk Hover over a change block (hunk) in the diff. Click the Stage Hunk icon that appears in the gutter to stage just that block.
Stage Lines Select specific lines in the diff, then right-click and choose Stage Selected Ranges. Only those lines will be staged.
Revert Hunk Click the revert icon on a hunk to discard that change and restore the committed version of those lines.

Writing Commit Messages

Type your message in the Source Control input box and press Ctrl+Enter to commit. For multiline messages, press Enter for a new line (the setting git.inputValidationSubjectLength warns you if the first line exceeds 72 characters).

settings.json
{
    // Warn if commit subject exceeds 72 characters
    "git.inputValidationSubjectLength": 72,

    // Use full-width editor for commit messages (instead of input box)
    "git.useEditorAsCommitInput": true,

    // Show staged changes count in SCM badge
    "git.countBadge": "tracked"
}

Amending Commits

To amend the last commit (add more changes or fix the message), click the dropdown arrow next to the Commit button and choose Commit (Amend). This is equivalent to git commit --amend. The previous commit message populates the input box so you can edit it.

Amend Warning

Amending rewrites the last commit. If you have already pushed that commit to a remote, you will need to force-push (git push --force), which can cause problems for collaborators. Only amend commits that haven't been shared.

4. Branching from VS Code

Branching is one of Git's greatest strengths, and VS Code makes it accessible without touching the terminal.

The Branch Picker

Click the branch name in the bottom-left status bar to open the branch picker. From here you can:

Switch Branch CHECKOUT

Select any existing local or remote branch to switch to it

Status Bar > Click branch > Select target
Create Branch NEW

Type a new branch name to create and switch to it in one step

Status Bar > Click branch > Create new branch...
Create From... FORK

Create a new branch based on a specific existing branch or tag

Status Bar > Create new branch from...
Checkout Tag TAG

Check out a specific tag for reviewing a release

Command Palette > Git: Checkout to... > tags/v1.0

Branch Comparison

Use the Command Palette (Ctrl+Shift+P) and type Git: Compare to diff the current branch against another. This shows all files that differ between the two branches, which is useful before opening a pull request.

Remote Branches

Remote branches appear in the branch picker with their remote prefix (e.g., origin/feature-auth). Checking one out creates a local tracking branch automatically. Run Git: Fetch from the Command Palette if you don't see the latest remote branches.

5. Merge Conflicts in VS Code

When a merge, rebase, or cherry-pick produces conflicts, VS Code detects them automatically and provides a rich UI for resolution. No more manually searching for <<<<<<< markers.

The 3-Way Merge Editor

VS Code's 3-way merge editor shows three panes:

Incoming
Their Changes
+
Current
Your Changes
=
Result
Final Output
Click a pane above to learn what it shows.

Conflict Resolution Actions

For each conflict block, VS Code shows clickable actions directly above the conflict markers:

ActionWhat It Does
Accept Current ChangeKeep your version, discard theirs
Accept Incoming ChangeKeep their version, discard yours
Accept Both ChangesInclude both versions stacked (current first, then incoming)
Compare ChangesOpen a diff view to examine both versions in detail

In the 3-way merge editor, you can also manually edit the Result pane to craft a custom resolution that combines elements from both sides. When you are satisfied, save the file and click Complete Merge.

After Resolving

Once all conflicts in a file are resolved, you must stage the file (git add or click + in Source Control) and then commit. VS Code pre-fills a merge commit message for you. Do not forget this step — unresolved files block the merge.

6. Diff Viewer

The built-in diff viewer is one of VS Code's strongest Git features. It supports multiple viewing modes and can compare across branches, commits, or arbitrary files.

Side-by-Side vs Inline

ModeHow to ActivateBest For
Side-by-Side (default) Click any changed file in Source Control Reviewing large changes where context matters
Inline Click the ... menu in the diff editor toolbar and select Inline View Narrow screens or small, scattered changes

Comparing Branches

Use the Command Palette to compare across branches:

Command Palette
# Compare current branch with another
Ctrl+Shift+P > Git: Compare HEAD with...

# Compare a specific file with another branch
Ctrl+Shift+P > File: Compare Active File With...

# Compare with the clipboard content
Ctrl+Shift+P > File: Compare Active File with Clipboard

Comparing Commits

With the Timeline view (bottom of the Explorer sidebar), you can click any past commit for the current file and VS Code opens a diff between that commit and the current version. This is a fast way to trace when a specific change was introduced.

settings.json
{
    // Default to inline diff instead of side-by-side
    "diffEditor.renderSideBySide": false,

    // Ignore whitespace changes in diffs
    "diffEditor.ignoreTrimWhitespace": true,

    // Show diff decorations in the minimap
    "diffEditor.renderIndicators": true,

    // Word-level diff highlighting (very useful)
    "diffEditor.wordWrap": "on"
}
Key Concept

The diff viewer is not read-only. In the right pane (the current version), you can edit code directly. Changes are saved to the working file. This lets you review and fix issues in the same view without switching contexts.

7. Git Graph Extension

VS Code's built-in Git support covers day-to-day operations, but it lacks a visual commit history. The Git Graph extension by mhutchie fills that gap with an interactive, graphical view of your repository's branch topology.

Installation

Command Palette
# Install from the Extensions panel
Ctrl+Shift+X > Search "Git Graph" > Install

# Or from the terminal
$ code --install-extension mhutchie.git-graph

What It Shows

Branch Lines Color-coded lines showing branch topology — where branches diverge and merge back together.
Commit Nodes Each commit as a dot on the graph with hash, message, author, and date. Click to see full details.
Tag & Ref Labels Tags, HEAD, and remote tracking refs displayed as colored labels on their respective commits.

Key Actions from the Graph

Right-click any commit in the graph to access actions like: cherry-pick, revert, create branch from here, create tag, reset current branch to here, and copy commit hash. This makes Git Graph a lightweight alternative to tools like GitKraken or SourceTree.

Opening Git Graph

After installation, a new icon appears in the Source Control panel title bar. Click it to open the graph view. You can also use the Command Palette: Ctrl+Shift+P then type Git Graph: View Git Graph.

8. GitLens Extension

GitLens by GitKraken supercharges VS Code's Git capabilities with blame annotations, rich file history, and contributor insights. It is one of the most-installed VS Code extensions for a reason.

Installation

Terminal
$ code --install-extension eamodio.gitlens

Core Features

Inline Blame ANNOTATION

Shows who last modified each line, when, and the commit message — faded text at the end of the current line

John Doe, 3 days ago - Fix null check in auth
File History TIMELINE

View every commit that touched the current file, with diffs for each change

GitLens sidebar > File History
Line History DEEP DIVE

Track the complete history of a specific line or selection across renames and moves

Right-click > GitLens > Open Line History
Contributors TEAM

See who contributed to the repo, how much, and when their last commit was

GitLens sidebar > Contributors

GitLens Settings to Know

settings.json
{
    // Show blame annotation at end of current line
    "gitlens.currentLine.enabled": true,

    // Format for the inline blame annotation
    "gitlens.currentLine.format": "${author}, ${agoOrDate} - ${message|50?}",

    // Show code lens above functions/classes with recent change info
    "gitlens.codeLens.enabled": true,

    // Disable GitLens welcome/what's new on update (optional)
    "gitlens.showWelcomeOnInstall": false,
    "gitlens.showWhatsNewAfterUpgrades": false
}
Key Concept

GitLens answers the question "why does this line exist?" instantly. Instead of running git log -L or git blame in the terminal, you hover over a line and see the full commit context. This alone saves significant time during code reviews and debugging.

9. GitHub Pull Requests Extension

The official GitHub Pull Requests and Issues extension by GitHub lets you create, review, and merge pull requests without leaving VS Code. If your team uses GitHub, this is essential.

Installation

Terminal
$ code --install-extension GitHub.vscode-pull-request-github

What You Can Do

FeatureDescription
Create PRsOpen a PR directly from VS Code after pushing a branch. Set title, description, reviewers, labels, and target branch.
Review PRsCheck out a PR branch, view file changes with inline diffs, and approve or request changes.
Inline CommentsAdd review comments on specific lines of code, just like on github.com. Start threads, suggest changes.
Merge PRsMerge, squash-merge, or rebase-merge a PR after approval — all from the sidebar.
IssuesView, create, and manage GitHub issues. Link issues to PRs with keywords like Fixes #42.

Workflow: Create a PR from VS Code

Steps
# 1. Create and switch to a new branch
Status Bar > Click branch > Create new branch > feature/auth-flow

# 2. Make changes, stage, and commit
Source Control > Stage files > Write message > Ctrl+Enter

# 3. Push the branch
Status Bar > Click sync icon (or Git: Push from Command Palette)

# 4. Create the PR
GitHub PR sidebar > Create Pull Request > Fill in details > Submit
Authentication

The extension uses VS Code's built-in GitHub authentication. The first time you use it, VS Code prompts you to sign in to GitHub via the browser. The token is stored securely in VS Code's credential store — you only sign in once.

Custom Keybindings for Git

Add these to your keybindings.json (Ctrl+Shift+P > Preferences: Open Keyboard Shortcuts (JSON)) for faster Git operations:

keybindings.json
[
    // Stage the current file quickly
    {
        "key": "ctrl+shift+s",
        "command": "git.stage",
        "when": "editorTextFocus"
    },
    // Unstage the current file
    {
        "key": "ctrl+shift+u",
        "command": "git.unstage",
        "when": "editorTextFocus"
    },
    // Open Git Graph quickly
    {
        "key": "ctrl+shift+g g",
        "command": "git-graph.view"
    }
]
Key Concept

The Command Palette (Ctrl+Shift+P) is your fallback for any Git operation. Type git and you will see every available command: stash, rebase, cherry-pick, clean, and more. You do not need to memorize shortcuts for rare operations.

11. settings.json for Git

VS Code's Git behavior is highly configurable through settings.json. These are the settings that experienced developers tune first.

Recommended Git Configuration

settings.json
{
    // --- Fetch & Sync ---

    // Auto-fetch from remote every 60 seconds (default: false)
    "git.autofetch": true,
    "git.autofetchPeriod": 60,

    // Confirm before syncing (push/pull)
    "git.confirmSync": false,

    // Default branch name for new repos
    "git.defaultBranchName": "main",


    // --- Commit Behavior ---

    // Prompt to stage all changes if nothing is staged before commit
    "git.enableSmartCommit": true,

    // Open full editor for commit messages
    "git.useEditorAsCommitInput": true,

    // Post-commit action: sync after committing
    "git.postCommitCommand": "sync",


    // --- Diff & Merge ---

    // Use VS Code as the default diff tool
    "diffEditor.renderSideBySide": true,

    // Ignore whitespace in diffs
    "diffEditor.ignoreTrimWhitespace": false,

    // Enable the 3-way merge editor for conflicts
    "git.mergeEditor": true,


    // --- UI & Display ---

    // Show git decorations in the Explorer
    "git.decorations.enabled": true,

    // Show the timeline view for file history
    "timeline.showUncommitted": true,

    // Badge count mode: "all", "tracked", or "off"
    "git.countBadge": "tracked"
}

Setting VS Code as Your Git Editor and Diff Tool

You can configure Git itself (not just VS Code) to use VS Code for editing commit messages, interactive rebases, and diffs:

Terminal
# Set VS Code as your default Git editor
$ git config --global core.editor "code --wait"

# Set VS Code as your diff tool
$ git config --global diff.tool vscode
$ git config --global difftool.vscode.cmd "code --wait --diff \$LOCAL \$REMOTE"

# Set VS Code as your merge tool
$ git config --global merge.tool vscode
$ git config --global mergetool.vscode.cmd "code --wait --merge \$REMOTE \$LOCAL \$BASE \$MERGED"
The --wait Flag

The --wait flag tells the terminal to pause until you close the VS Code tab. Without it, Git thinks you finished instantly and aborts the operation. Always include --wait when using VS Code as a Git editor.

12. Tips & Workflows

Commit Message Best Practices

Good commit messages are the difference between a useful history and a useless one. Follow this structure:

Commit Message Format
Short summary in imperative mood (50 chars or less)

Blank line separates subject from body.

More detailed explanation if needed. Wrap at 72 characters.
Explain the WHY, not the WHAT. The diff shows what changed.
Reference issue numbers at the bottom.

.gitignore from VS Code

Right-click any file in the Explorer and select Add to .gitignore to append it to your .gitignore file. If the file doesn't exist yet, VS Code creates it. You can also install the gitignore extension (by CodeZombie) to pull templates from GitHub's gitignore collection directly from the Command Palette.

Git Stash from VS Code

Stashing lets you shelve uncommitted changes and return to a clean working directory. VS Code has full stash support through the Command Palette:

Git: Stash SAVE

Stash all uncommitted changes with an optional message

Ctrl+Shift+P > Git: Stash
Git: Stash (Include Untracked) FULL SAVE

Stash everything, including new files that Git is not yet tracking

Ctrl+Shift+P > Git: Stash (Include Untracked)
Git: Pop Stash RESTORE

Re-apply the most recent stash and remove it from the stash list

Ctrl+Shift+P > Git: Pop Stash
Git: Apply Stash RESTORE + KEEP

Re-apply a stash but keep it in the stash list for later use

Ctrl+Shift+P > Git: Apply Stash

Terminal vs GUI: When to Use Which

Use the GUI (Source Control Panel)Use the Terminal
Staging and committing changesComplex rebasing or interactive rebase
Reviewing diffs before committingResetting to a specific commit
Resolving merge conflictsReflog recovery and advanced troubleshooting
Creating and switching branchesBisecting to find a bug-introducing commit
Stashing and unstashing workScripting and automation (CI/CD pipelines)
Reviewing blame and file historySubmodule management
Key Concept

The VS Code Git GUI and the terminal are not competing tools — they are complementary. Use the GUI for visual tasks (diffs, staging hunks, conflict resolution) and the terminal for everything that requires precision or scripting. The best Git users are fluent in both.
