IDE Lab — VS Code Productivity Workshop

Six challenges that push your VS Code skills beyond the basics. Master keyboard-driven workflows, multi-cursor editing, debugging, remote development, and task automation.

~45 min Lab Intermediate

Lab Objectives

  • Create custom user snippets with tabstops and placeholders for DevOps boilerplate

LAB 01 Keyboard Navigation Challenge
Ctrl+P F12 Ctrl+Shift+O
Situation
You just joined a team that maintains a Node.js microservice with 40+ files spread across src/, lib/, routes/, and tests/. Your first task is a bug fix, but you have never seen this codebase before. Your mouse just broke. You need to navigate the entire project, jump between files, find symbol definitions, and trace function calls — all from the keyboard.
Your Task
  • Open a file by name using Ctrl+P (Quick Open) — type partial filenames to fuzzy-match
  • Jump to a symbol within the current file using Ctrl+Shift+O (Go to Symbol)
  • Go to the definition of a function or variable with F12 (Go to Definition)
  • Peek at all references to a symbol with Shift+F12 (Peek References)
  • Navigate back and forward through your jump history with Alt+Left / Alt+Right
  • Open the Command Palette with Ctrl+Shift+P and run at least 3 different commands
Hints
  • Ctrl+P opens Quick Open — type a filename fragment and press Enter to open it. Add : after the name to jump to a specific line number
  • Ctrl+Shift+O lists all symbols (functions, classes, variables) in the current file — type : to group them by kind
  • F12 jumps to where a symbol is defined; Alt+F12 shows the definition inline without leaving your current file
  • Ctrl+G goes to a specific line number — useful when reading error stack traces
► Show Solution

Create a small multi-file project to practice with:

Terminal — Setup
# Create a practice project with multiple files
$ mkdir -p ~/vscode-lab-s1/src ~/vscode-lab-s1/lib ~/vscode-lab-s1/routes
$ cd ~/vscode-lab-s1

# lib/db.js — a database helper module
$ cat > lib/db.js << 'EOF'
function connectDatabase(host, port) {
    console.log(`Connecting to ${host}:${port}`);
    return { connected: true, host, port };
}

function runQuery(db, sql) {
    if (!db.connected) throw new Error('Not connected');
    return { rows: [], sql };
}

module.exports = { connectDatabase, runQuery };
EOF

# src/userService.js — imports from lib/db.js
$ cat > src/userService.js << 'EOF'
const { connectDatabase, runQuery } = require('../lib/db');

function getUser(id) {
    const db = connectDatabase('localhost', 5432);
    return runQuery(db, `SELECT * FROM users WHERE id = ${id}`);
}

function listUsers() {
    const db = connectDatabase('localhost', 5432);
    return runQuery(db, 'SELECT * FROM users');
}

module.exports = { getUser, listUsers };
EOF

# routes/users.js — imports from src/userService.js
$ cat > routes/users.js << 'EOF'
const { getUser, listUsers } = require('../src/userService');

function handleGetUser(req, res) {
    const user = getUser(req.params.id);
    res.json(user);
}

function handleListUsers(req, res) {
    const users = listUsers();
    res.json(users);
}

module.exports = { handleGetUser, handleListUsers };
EOF

# Open the project in VS Code
$ code ~/vscode-lab-s1

LAB 02 Multi-Cursor Power Edit
Ctrl+D Alt+Click regex replace
Situation
A colleague exported a CSV dump of 20 server records from a spreadsheet and pasted it into a file called servers.csv. Your infrastructure-as-code tool requires JSON, and the dates are in MM/DD/YYYY format but your API expects YYYY-MM-DD. You need to convert the entire CSV block to a JSON array and reformat every date — fast. Editing each line one at a time would take forever. Multi-cursor and regex replace make this a 30-second operation.
Your Task
  • Select all occurrences of a variable name using Ctrl+D and rename them simultaneously
  • Place cursors on multiple non-adjacent lines using Alt+Click and type on all of them at once
  • Select all occurrences of a word in the file with Ctrl+Shift+L
  • Use Ctrl+H with regex mode enabled to reformat dates from MM/DD/YYYY to YYYY-MM-DD
  • Convert at least 5 CSV lines into JSON object notation using multi-cursor editing
Hints
  • Ctrl+D selects the next occurrence of the current selection — press it repeatedly to add more cursors
  • Alt+Click places an additional cursor at the clicked position — hold Alt and click multiple lines
  • In the Find/Replace dialog (Ctrl+H), click the .* button to enable regex mode
  • Regex capture groups: (\d{2})/(\d{2})/(\d{4}) captures month, day, year — replace with $3-$1-$2

Pro tip

For renaming variables, Ctrl+D is safer than Ctrl+Shift+L because it lets you add matches one at a time. Use Ctrl+K Ctrl+D to skip an occurrence you do not want to change. For true project-wide renames of code symbols, use F2 (Rename Symbol) — it is language-aware and updates imports automatically.

LAB 03 Debug a Broken API
launch.json breakpoints watch
Situation
Your team inherited a small Express API that returns user data. It has three bugs: a route that returns undefined instead of user data, a middleware that silently swallows errors, and an off-by-one pagination bug. Previous developers "debugged" by scattering console.log statements everywhere — there are 47 of them in the codebase. You are going to fix all three bugs using the VS Code debugger properly: configuring launch.json, setting breakpoints, stepping through code, and watching variables.
Your Task
  • Create a .vscode/launch.json configuration to debug the Node.js server
  • Set breakpoints on the route handler, middleware, and pagination logic
  • Use Step Over (F10), Step Into (F11), and Step Out (Shift+F11) to trace execution
  • Add variables to the Watch panel to monitor values across breakpoint hits
  • Use the Call Stack panel to understand the execution flow
  • Find and fix all three bugs without adding a single console.log
Hints
  • Open the Run and Debug panel with Ctrl+Shift+D, then click "create a launch.json file"
  • Set a breakpoint by clicking in the gutter (left margin) next to a line number, or press F9
  • Conditional breakpoints: right-click a breakpoint and add an expression like page > 1 — it only pauses when the condition is true
  • Hover over any variable while paused to see its current value inline
► Show Solution

Create the buggy API server:

Terminal — Setup
$ mkdir -p ~/vscode-lab-s3/.vscode && cd ~/vscode-lab-s3
$ npm init -y
$ npm install express
server.js — Buggy Code
// server.js — three bugs hidden inside
const express = require('express');
const app = express();

const users = [
    { id: 1, name: 'Alice', role: 'admin' },
    { id: 2, name: 'Bob', role: 'user' },
    { id: 3, name: 'Carol', role: 'user' },
    { id: 4, name: 'Dave', role: 'moderator' },
    { id: 5, name: 'Eve', role: 'user' },
    { id: 6, name: 'Frank', role: 'user' },
];

// BUG 1: Middleware swallows errors — catch block is empty
app.use((req, res, next) => {
    try {
        req.requestTime = Date.now();
        next();
    } catch (err) {
        // Bug: silently swallows the error
    }
});

// BUG 2: Returns undefined — uses = instead of ===
app.get('/users/:id', (req, res) => {
    const id = req.params.id;  // Bug: id is a string, not a number
    const user = users.find(u => u.id === id);
    res.json({ user });
});

// BUG 3: Off-by-one pagination — skips first item
app.get('/users', (req, res) => {
    const page = parseInt(req.query.page) || 1;
    const limit = parseInt(req.query.limit) || 3;
    const start = page * limit;  // Bug: should be (page - 1) * limit
    const end = start + limit;
    const results = users.slice(start, end);
    res.json({ page, limit, total: users.length, results });
});

app.listen(3000, () => {
    console.log('Server running on port 3000');
});

Create the debug configuration:

.vscode/launch.json

    "version": "0.2.0",
    "configurations": [
        {
            "type": "node",
            "request": "launch",

Debug workflow and fixes:

VS Code — Debug Walkthrough
# 1. Press F5 to start debugging (uses launch.json config)
# 2. Set breakpoint on line 27 (the .find() call)
# 3. In a terminal, run: curl http://localhost:3000/users/1
# 4. Debugger pauses. Hover over "id" — it shows "1" (string)
# 5. Hover over users[0].id — it shows 1 (number)
#    String "1" !== Number 1 — that is the bug

# FIX BUG 2: Parse the id parameter as a number
  BEFORE: const id = req.params.id;
  AFTER:  const id = parseInt(req.params.id, 10);

# 6. Set breakpoint on line 34 (const start = ...)
# 7. curl http://localhost:3000/users?page=1&limit=3
# 8. Debugger pauses. Add "start" to Watch panel.
#    start = 3 (should be 0 for page 1). Off-by-one.

# FIX BUG 3: Use (page - 1) for zero-indexed offset
  BEFORE: const start = page * limit;
  AFTER:  const start = (page - 1) * limit;

# FIX BUG 1: Propagate errors to Express error handler
  BEFORE: catch (err) { }
  AFTER:  catch (err) { next(err); }
Important

Empty catch blocks are one of the most dangerous patterns in production code. They silently hide failures, making bugs invisible until they cascade into something worse. Always either handle the error, log it, or propagate it. The VS Code debugger would have caught this immediately — the call stack shows execution jumping from the try body directly past the catch with no visible error.

LAB 04 Tasks & Build Automation
tasks.json problemMatcher keybindings
Situation
You maintain a Node.js project where the build-test-lint cycle is painful: you keep switching to the terminal, running npm run lint, reading the output, manually finding the file and line number, and fixing the issue. When the linter reports 12 errors you have to do this 12 times. VS Code Tasks can automate this entire workflow — run lint with a single keystroke and have every error appear directly in the Problems panel with clickable file/line links.
Your Task
  • Create .vscode/tasks.json with three tasks: build, test, and lint
  • Configure a problemMatcher on the lint task so errors appear in the Problems panel
  • Create a compound task that runs lint first, then test (sequentially)
  • Bind the compound task to a keyboard shortcut via keybindings.json
  • Verify that lint errors appear as clickable entries in the Problems panel
Hints
  • Run Terminal: Configure Tasks from the Command Palette to scaffold tasks.json
  • Use "problemMatcher": "$eslint-stylish" for ESLint output, or define a custom regex pattern
  • Compound tasks use "dependsOn": ["lint", "test"] with "dependsOrder": "sequence"
  • Bind tasks to keys in keybindings.json using "command": "workbench.action.tasks.runTask" with an "args" field
► Show Solution

Set up a project with lint, build, and test scripts:

Terminal — Setup
$ mkdir -p ~/vscode-lab-s4/.vscode && cd ~/vscode-lab-s4
$ npm init -y
$ npm install --save-dev eslint

# Initialize ESLint config
$ npx eslint --init
# Choose: problems only, CommonJS, None, No TypeScript, Node

# Add scripts to package.json
# "build": "echo 'Build complete'",
# "test": "echo 'Tests passed'",
# "lint": "eslint . --format stylish"

Create the tasks configuration:

.vscode/tasks.json
{
    "version": "2.0.0",
    "tasks": [
        {
            "label": "build",
            "type": "npm",
            "script": "build",
            "group": "build",
            "problemMatcher": []
        },
        {
            "label": "test",
            "type": "npm",
            "script": "test",
            "group": "test",
            "problemMatcher": []
        },
        {
            "label": "lint",
            "type": "npm",
            "script": "lint",
            "problemMatcher": ["$eslint-stylish"],
            "presentation": {
                "reveal": "silent",
                "panel": "shared"
            }
        },
        {
            "label": "lint-then-test",
            "dependsOn": ["lint", "test"],
            "dependsOrder": "sequence",
            "group": {
                "kind": "test",
                "isDefault": true
            },
            "problemMatcher": []
        }
    ]
}

Bind the compound task to a keyboard shortcut:

keybindings.json — User Keybinding
// Open with Ctrl+Shift+P > "Open Keyboard Shortcuts (JSON)"
[
    {
        "key": "ctrl+shift+t",
        "command": "workbench.action.tasks.runTask",
        "args": "lint-then-test"
    }
]
VS Code — Verify
# 1. Press Ctrl+Shift+T — runs lint, then test
# 2. Open the Problems panel (Ctrl+Shift+M)
# 3. Lint errors appear as clickable entries with file and line numbers
# 4. Click an entry — VS Code opens the file and jumps to the exact line

# You can also run individual tasks:
Ctrl+Shift+P > "Tasks: Run Task" > "lint"
Ctrl+Shift+P > "Tasks: Run Build Task" (runs the default build task)
Custom Problem Matchers

If your tool does not use a built-in format, you can define a custom problemMatcher with a regex pattern. The pattern fields file, line, column, severity, and message map capture groups from your tool's output. See the VS Code docs for "pattern": [{ "regexp": "..." }] syntax.

LAB 05 Workspace & Settings
.code-workspace settings.json extensions.json
Situation
Your project has a React frontend in client/ and a Python Flask backend in server/. The frontend team uses Prettier with 2-space indentation. The backend team uses Black with 4-space indentation. Opening both folders in a single VS Code window means one formatter conflicts with the other. You need a multi-root workspace where each folder gets its own settings, its own recommended extensions, and its own formatting rules — all version-controlled so new team members get the right setup on first open.
Your Task
  • Create a .code-workspace file that includes both client/ and server/ as workspace roots
  • Configure workspace-level settings: Prettier as the formatter for client/, Black for server/
  • Set different tab sizes per folder (2 spaces for client, 4 spaces for server)
  • Create .vscode/extensions.json in each folder with recommended extensions
  • Add editor rulers at column 80 for Python and column 100 for JavaScript
Hints
  • Create a .code-workspace file at the project root — open it with File > Open Workspace from File
  • Per-folder settings go inside the "folders" array using "settings": {} for each entry
  • extensions.json uses "recommendations" (array of extension IDs) — VS Code prompts team members to install them
  • Use "[python]" and "[javascript]" language-specific settings blocks for per-language formatting rules

Settings Precedence

VS Code settings cascade: User (global) → Workspace (.code-workspace) → Folder (.vscode/settings.json). More specific settings always win. Language-specific overrides ("[python]") take highest priority within their scope. Commit .vscode/ and .code-workspace to version control so the whole team shares the same configuration.

LAB 06 Snippets & Productivity
snippets tabstops placeholders
Situation
You write the same boilerplate dozens of times a week: Dockerfiles, docker-compose service blocks, GitHub Actions workflow steps, and Terraform resource blocks. Each one has the same structure with a few fields that change. Typing (or copy-pasting) these templates is slow and error-prone — you keep forgetting the restart: unless-stopped field or misindenting YAML. Custom VS Code snippets let you type a 3-letter prefix, press Tab, and get a perfect template with cursor positions at every field you need to fill in.
Your Task
  • Open the user snippets file for Docker (Preferences: Configure User Snippets > dockerfile)
  • Create a Dockerfile snippet with tabstops for base image, workdir, copy source, and CMD
  • Create a docker-compose service snippet (YAML) with placeholders for service name, image, ports, and environment
  • Create a GitHub Actions step snippet (YAML) with tabstops for step name, uses, and with parameters
  • Create a Terraform resource snippet (HCL) with placeholders for resource type, name, and properties
  • Test each snippet by typing the prefix and pressing Tab
Hints
  • Open snippets: Ctrl+Shift+P → "Preferences: Configure User Snippets" → select a language
  • Tabstops ($1, $2, $3) define where the cursor jumps when you press Tab. $0 is the final cursor position
  • Placeholders: ${1:default_value} pre-fills a value that gets selected so you can type over it or press Tab to accept
  • Choice lists: ${1|option1,option2,option3|} creates a dropdown menu at that tabstop
► Show Solution

   Type "dkf" then press Tab
   Full Dockerfile template appears with cursor on the FROM image
   Press Tab to jump through each placeholder

# 2. Open a new .yml file
   Type "dcs" then press Tab
   Docker Compose service block with pre-filled defaults
   The $3 placeholder auto-mirrors the service name from $1

# 3. Inside a GitHub Actions workflow YAML
   Type "gha" then press Tab
   Complete step block ready to fill in

# 4. Open a new .tf file
   Type "tfr" then press Tab
   Terraform resource with dropdown for resource type
Snippet Variables

VS Code snippets support built-in variables like $TM_FILENAME (current filename), $CURRENT_YEAR, $CLIPBOARD (paste from clipboard), and $UUID (generate a unique ID). Combine these with tabstops for dynamic templates: "// Author: $TM_FULLNAME | Date: $CURRENT_YEAR-$CURRENT_MONTH-$CURRENT_DATE".
