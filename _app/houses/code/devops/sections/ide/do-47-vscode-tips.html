VS Code Tips & Shortcuts

The difference between a developer and a fast developer is how well they know their editor. Master the shortcuts, hidden features, and power-user workflows that will transform your daily productivity.

~35 min Module All Levels

Learning Objectives

  • Memorize the essential keyboard shortcuts for navigation, editing, search, terminal, debug, and git
  • Use multi-cursor editing to make parallel changes across dozens of lines at once
  • Navigate large files efficiently with code folding, breadcrumbs, sticky scroll, and the outline view
  • Configure Zen Mode, Focus Mode, and the minimap for distraction-free coding
  • Leverage Timeline view and Sticky Scroll to maintain context in complex codebases
  • Create and manage VS Code Profiles for different workflows (DevOps, Python, Frontend)
  • Sync settings across machines and manage VS Code from the command line
  • Write custom keybindings with when clauses and multi-command macros

2. Multi-Cursor Mastery

Multi-cursor editing is the single biggest productivity multiplier in VS Code. Once you internalize these patterns, edits that would take 30 seconds with find-and-replace happen in 3 seconds with pure muscle memory.

ActionmacOSLinux / Windows
Add cursor at click positionOption+ClickAlt+Click
Add cursor aboveCmd+Option+UpCtrl+Alt+Up
Add cursor belowCmd+Option+DownCtrl+Alt+Down
Select next occurrence of wordCmd+DCtrl+D
Select ALL occurrences of wordCmd+Shift+LCtrl+Shift+L
Column (box) selectionShift+Option+DragShift+Alt+Drag
Column select via keyboardCmd+Shift+Option+ArrowCtrl+Shift+Alt+Arrow
Undo last cursor addCmd+UCtrl+U
Add cursors to line ends of selectionShift+Option+IShift+Alt+I

Pattern: Rename a Variable in Context

Place your cursor on a variable name, press Cmd+D (or Ctrl+D) repeatedly to select each occurrence one by one. Skip an occurrence with Cmd+K Cmd+D. Then type the new name — all cursors update simultaneously.

Pattern: Column Editing

When you need to add the same prefix or suffix to many consecutive lines, column selection is faster than any regex. Hold Shift+Option (macOS) or Shift+Alt (Linux/Windows) and drag down to create a vertical cursor column. Then type your text.

Before / After
# Before (place cursor at start of "alpha", column-select down 4 lines, type "export ")
alpha = 1
bravo = 2
charlie = 3
delta = 4

# After
export alpha = 1
export bravo = 2
export charlie = 3
export delta = 4

Pattern: Regex-Powered Multi-Select

Open Find (Cmd+F), enable Regex mode, enter your pattern, then press Cmd+Shift+L to place cursors at every match. This is the nuclear option for large-scale transformations.

Watch Out

Multi-cursor edits cannot be partially undone. A single Cmd+Z reverts ALL cursors. If you make a mistake mid-edit, undo everything and start again rather than trying to fix individual lines.

3. Code Folding

In large files, code folding lets you collapse sections you are not actively working on, reducing visual noise and helping you focus on the structure that matters.

ActionmacOSLinux / Windows
Fold region at cursorCmd+Option+[Ctrl+Shift+[
Unfold region at cursorCmd+Option+]Ctrl+Shift+]
Fold all regionsCmd+K Cmd+0Ctrl+K Ctrl+0
Unfold all regionsCmd+K Cmd+JCtrl+K Ctrl+J
Fold to level N (1-7)Cmd+K Cmd+NCtrl+K Ctrl+N
Fold all block commentsCmd+K Cmd+/Ctrl+K Ctrl+/
Toggle foldCmd+K Cmd+LCtrl+K Ctrl+L

Custom Fold Markers

VS Code supports language-specific fold markers. In JavaScript and TypeScript, you can define collapsible regions with comments:

JavaScript
// #region Database Helpers
function connect() { /* ... */ }
function disconnect() { /* ... */ }
function query() { /* ... */ }
// #endregion

// #region Authentication
function login() { /* ... */ }
function logout() { /* ... */ }
// #endregion

In CSS, use /* #region */ and /* #endregion */. In Python, use # region and # endregion. In HTML, use <!-- #region --> and <!-- #endregion -->.

Key Concept

Fold Level is the killer feature. Press Cmd+K Cmd+2 to fold everything to two levels deep — instantly see the top-level structure of any file. Then unfold only the section you need.

4. Zen Mode & Focus Mode

When you need to eliminate every distraction and enter a flow state, VS Code has two purpose-built modes.

Zen Mode

Activated with Cmd+K Z (macOS) or Ctrl+K Z (Linux/Windows). Zen Mode hides the sidebar, activity bar, panel, status bar, tabs, and notifications. The editor goes full-screen with your code centered. Press Escape Escape (double-tap) to exit.

settings.json
// Customize Zen Mode behavior
{
    "zenMode.fullScreen": true,
    "zenMode.centerLayout": true,
    "zenMode.hideLineNumbers": false,
    "zenMode.hideStatusBar": true,
    "zenMode.hideTabs": true,
    "zenMode.silentNotifications": true,
    "zenMode.restore": false
}

Focus Mode (Centered Layout)

If you want the centered-column layout without going full-screen, toggle Centered Layout from the Command Palette. This narrows the editor to a comfortable reading width — perfect for writing documentation or reviewing code.

When to Use Which

Zen Mode is for deep work sessions where you need zero interruptions (writing algorithms, debugging, focused refactoring). Centered Layout is for lighter focus — documentation, code review, reading — where you may still want access to the sidebar occasionally.

5. Minimap

The minimap is the bird's-eye-view scrollbar on the right side of the editor. In large files, it is an invaluable navigation tool. In small files, it wastes space. Knowing when and how to configure it is part of VS Code fluency.

settings.json
{
    // Toggle minimap visibility
    "editor.minimap.enabled": true,

    // "proportional" | "fill" | "fit" — how tall the minimap is
    "editor.minimap.size": "proportional",

    // "always" | "mouseover" — when to show the slider highlight
    "editor.minimap.showSlider": "mouseover",

    // Render actual characters (true) or colored blocks (false)
    "editor.minimap.renderCharacters": false,

    // Scale: 1, 2, or 3 (higher = bigger minimap)
    "editor.minimap.scale": 1,

    // Max column width for the minimap
    "editor.minimap.maxColumn": 80,

    // Which side of the editor
    "editor.minimap.side": "right"
}
Key Concept

Set renderCharacters to false and scale to 1 for the cleanest minimap. The colored blocks give you structural overview without trying (and failing) to render tiny text. Click anywhere on the minimap to jump instantly to that section.

6. Breadcrumbs & Outline View

In a 2,000-line file, scrolling to find a function is slow. Breadcrumbs and the Outline view give you instant structural navigation.

Breadcrumbs

The breadcrumb bar appears below the tab row and shows your current location in the file hierarchy: file path, then the symbol tree (class, function, block). Click any segment to jump. Press Cmd+Shift+. (macOS) or Ctrl+Shift+. (Linux/Windows) to focus the breadcrumbs and navigate with arrow keys.

settings.json
{
    "breadcrumbs.enabled": true,
    "breadcrumbs.filePath": "on",
    "breadcrumbs.symbolPath": "on",
    "breadcrumbs.symbolSortOrder": "position",
    "breadcrumbs.icons": true
}

Outline View

Open the Outline view in the sidebar (Explorer panel, bottom section) to see every symbol in the current file as a tree. Functions, classes, variables, headings — everything your language server can detect. Click to jump. Type to filter.

Breadcrumbs Inline, always visible, shows current scope context. Best for quick jumps within your current area.
Outline Sidebar panel, shows full file structure. Best for exploring unfamiliar files or navigating to distant symbols.
Go to Symbol Cmd+Shift+O — fastest option. Type a symbol name, press Enter, done. No mouse required.

7. Timeline View

The Timeline view is a hidden gem in the Explorer sidebar. It shows a chronological history of changes to the current file from two sources: local file saves and git commits.

What It Shows

Local History AUTO-SAVE

VS Code automatically saves snapshots of every file you edit. Even without Git, you can see and restore previous versions. These survive across restarts.

Git History COMMITS

Every git commit that touched the current file appears in the timeline. Click any entry to see the diff between that version and the current one.

Restoring a Previous Version

Click any timeline entry to see the diff. To restore that version, right-click the entry and select Restore Contents. The file reverts to that point in time — unstaged, so you can review before committing.

settings.json
{
    // Control what shows in the Timeline
    "timeline.showUncommitted": true,

    // Local history settings
    "workbench.localHistory.enabled": true,
    "workbench.localHistory.maxFileEntries": 50,
    "workbench.localHistory.maxFileSize": 256,
    "workbench.localHistory.exclude": {
        "**/node_modules/**": true,
        "**/dist/**": true
    }
}
Local History Is Not a Backup

Local history is stored in the VS Code workspace storage directory on your machine. If you delete the workspace or reinstall VS Code, local history is gone. Always use Git for real version control. Think of local history as a safety net between commits.

8. Sticky Scroll

Sticky Scroll pins the enclosing scope headers (function signatures, class declarations, loop headers, block comments) to the top of the editor as you scroll through a file. When you are deep inside a 200-line function and have scrolled past the signature, Sticky Scroll keeps it visible so you always know where you are.

settings.json
{
    // Enable Sticky Scroll
    "editor.stickyScroll.enabled": true,

    // Maximum number of sticky lines (1-10)
    "editor.stickyScroll.maxLineCount": 5,

    // Which scope levels to show: "tree" (AST), "indentation", "foldingProviders"
    "editor.stickyScroll.defaultModel": "outlineModel",

    // Also works in the terminal
    "terminal.integrated.stickyScroll.enabled": true
}
Key Concept

Click any sticky header line to jump directly to that scope boundary. Set maxLineCount to 3 or 5 depending on your screen size. Too many sticky lines eat your editing space. On a 13-inch laptop, 3 is usually the sweet spot. On a 27-inch monitor, 5 works well.

Sticky Scroll + Terminal

Since VS Code 1.85, Sticky Scroll also works in the integrated terminal. When scrolling through long command output, the original command stays pinned at the top. Enable it with terminal.integrated.stickyScroll.enabled.

9. Profiles

VS Code Profiles let you create completely separate configurations — different extensions, settings, keybindings, snippets, and UI state — and switch between them instantly. A DevOps profile looks nothing like a frontend profile.

Creating a Profile

Open the Command Palette and search for Profiles: Create Profile. Name it, choose what to include (settings, keybindings, extensions, snippets, UI state, tasks), and create. You can also create from an existing profile as a starting point.

Example Profile Setups

DevOps PROFILE

Extensions: Docker, Kubernetes, YAML, Terraform, Remote SSH, GitLens. Theme: dark, high contrast. Terminal: front and center.

Python PROFILE

Extensions: Python, Pylance, Jupyter, Black Formatter, Ruff. Settings: format on save, 4-space tabs, 88-char ruler.

Frontend PROFILE

Extensions: ESLint, Prettier, Tailwind CSS IntelliSense, Live Server, Emmet shortcuts. Settings: 2-space tabs, auto-close tags.

Writing PROFILE

Extensions: Markdown All in One, Spell Checker, Word Count. Zen Mode by default. Minimap off. Large font size.

Import / Export

Profiles can be exported as .code-profile files or shared via a GitHub gist link. This makes it easy to standardize team environments. From the Command Palette: Profiles: Export Profile and Profiles: Import Profile.

Temporary Profiles

Use Profiles: Create Temporary Profile to spin up a clean environment for testing an extension or debugging an issue. When you are done, delete it. Your default profile remains untouched.

10. Settings Sync

Settings Sync keeps your VS Code environment identical across every machine you use — work laptop, home desktop, cloud VM. It syncs via your Microsoft or GitHub account.

What Syncs

CategoryIncludesToggle
Settingssettings.json (user and remote)Yes
Keybindingskeybindings.jsonYes
ExtensionsInstalled extensions and their enabled/disabled stateYes
SnippetsUser snippetsYes
UI StateDisplay language, layout, activity bar positionYes
ProfilesAll profiles and their contentsYes
TasksUser tasksYes

Enabling Sync

Click the gear icon in the bottom-left corner of VS Code and select Turn on Settings Sync. Sign in with Microsoft or GitHub. Choose which categories to sync. Done — changes propagate automatically.

Conflict Resolution

When the same setting is changed on two machines before syncing, VS Code shows a merge editor. You can accept local, accept remote, or manually merge. For most users, accepting the newer change is the right call.

settings.json
// Exclude machine-specific settings from sync
{
    "settingsSync.ignoredSettings": [
        "terminal.integrated.fontFamily",
        "editor.fontSize",
        "window.zoomLevel"
    ],
    "settingsSync.ignoredExtensions": [
        "ms-vscode-remote.remote-ssh"
    ]
}
Machine-Specific Settings

Some settings are inherently machine-specific: font family (depends on installed fonts), font size (depends on monitor DPI), zoom level, terminal shell path. Add these to settingsSync.ignoredSettings to prevent sync conflicts.

11. The code CLI

VS Code ships with a powerful command-line interface. If you live in the terminal, the code command bridges your terminal workflow and your editor seamlessly.

Installation

On macOS, open the Command Palette and run Shell Command: Install 'code' command in PATH. On Linux and Windows, the installer adds it automatically. Verify with code --version.

Core Commands

Terminal
# Open a file
$ code server.js

# Open a folder
$ code ~/projects/my-app

# Open current directory
$ code .

# Open a file at a specific line and column
$ code --goto server.js:42:10

# Open a new window
$ code --new-window ~/projects/other-app

# Add a folder to the current workspace
$ code --add ~/projects/shared-lib

Diff & Wait

Terminal
# Diff two files in VS Code
$ code --diff old-config.yaml new-config.yaml

# Wait for VS Code to close before continuing (great for git commit editors)
$ export EDITOR="code --wait"
$ git commit  # Opens VS Code, blocks terminal until you close the tab

# Use as default git editor permanently
$ git config --global core.editor "code --wait"

# Use as default git diff tool
$ git config --global diff.tool vscode
$ git config --global difftool.vscode.cmd "code --wait --diff \$LOCAL \$REMOTE"

Extension Management

Terminal
# List installed extensions
$ code --list-extensions

# List with versions
$ code --list-extensions --show-versions

# Install an extension
$ code --install-extension ms-python.python

# Uninstall an extension
$ code --uninstall-extension ms-python.python

# Bulk install from a list (export + import pattern)
$ code --list-extensions > extensions.txt
$ cat extensions.txt | xargs -L 1 code --install-extension
Key Concept

The --list-extensions + --install-extension pattern is how you bootstrap a new machine or share your setup with teammates before adopting Profiles or Settings Sync. Export the list, check it into your dotfiles repo, run the import script on any new machine.

Workspace Organization

Multi-Root Use multi-root workspaces (.code-workspace files) to group related repos. Drag folders into VS Code or use File > Add Folder to Workspace.
Pin Tabs Right-click a tab and select Pin Tab. Pinned tabs stay on the left, never close accidentally, and show as a compact icon. Pin your main files.
Split Editors Cmd+\ (macOS) or Ctrl+\ (Linux/Windows) splits the editor. Work on HTML on the left, CSS on the right. Drag tabs between groups.
File Nesting Configure explorer.fileNesting.patterns to group related files (e.g., *.ts nests *.test.ts, *.spec.ts). Reduces clutter in the explorer.

Productivity Settings

settings.json
{
    // Auto-save after a short delay
    "files.autoSave": "afterDelay",
    "files.autoSaveDelay": 1000,

    // Format on save — never manually format again
    "editor.formatOnSave": true,
    "editor.formatOnPaste": true,

    // Trim trailing whitespace automatically
    "files.trimTrailingWhitespace": true,
    "files.insertFinalNewline": true,

    // Smooth scrolling and cursor animation
    "editor.smoothScrolling": true,
    "editor.cursorBlinking": "smooth",
    "editor.cursorSmoothCaretAnimation": "on",

    // Bracket pair colorization (built-in, no extension needed)
    "editor.bracketPairColorization.enabled": true,
    "editor.guides.bracketPairs": "active",

    // Suggest on trigger characters and tab-complete
    "editor.suggestOnTriggerCharacters": true,
    "editor.tabCompletion": "on",

    // File nesting (group related files)
    "explorer.fileNesting.enabled": true,
    "explorer.fileNesting.patterns": {
        "*.ts": "${capture}.test.ts, ${capture}.spec.ts",
        "*.js": "${capture}.test.js, ${capture}.spec.js, ${capture}.min.js",
        "package.json": "package-lock.json, yarn.lock, pnpm-lock.yaml, .npmrc",
        "tsconfig.json": "tsconfig.*.json"
    }
}

13. Custom Keybindings

When the built-in shortcuts do not match your workflow, you can override any keybinding or create entirely new ones. All custom keybindings live in keybindings.json.

Open it with Cmd+K Cmd+S (macOS) or Ctrl+K Ctrl+S (Linux/Windows), then click the file icon in the top-right corner to open the raw JSON.

Anatomy of a Keybinding

keybindings.json
[
    {
        "key": "ctrl+shift+t",          // The key combination
        "command": "workbench.action.terminal.new",  // The command to run
        "when": "editorTextFocus"        // Only active in this context
    }
]

The when Clause

The when clause controls when a keybinding is active. This prevents conflicts — the same key can do different things in different contexts.

ContextTrue When...
editorTextFocusCursor is in an editor (not sidebar, terminal, etc.)
terminalFocusCursor is in the integrated terminal
inDebugModeA debug session is active
editorLangId == 'python'The active file is a Python file
resourceExtname == '.md'The active file is a Markdown file
sideBarVisibleThe sidebar is currently visible
!editorReadonlyThe editor is writable (not readonly)
editorHasSelectionText is currently selected

Practical Custom Keybinding Examples

keybindings.json
[
    // Toggle terminal with Ctrl+` only when NOT in terminal (avoid conflict)
    {
        "key": "ctrl+`",
        "command": "workbench.action.terminal.toggleTerminal",
        "when": "!terminalFocus"
    },

    // Navigate back/forward with mouse side buttons
    {
        "key": "mouse4",
        "command": "workbench.action.navigateBack"
    },
    {
        "key": "mouse5",
        "command": "workbench.action.navigateForward"
    },

    // Quick delete line (alternative binding)
    {
        "key": "ctrl+d",
        "command": "editor.action.deleteLines",
        "when": "editorTextFocus && !editorHasSelection"
    },

    // Wrap selection in console.log (Python: print)
    {
        "key": "ctrl+shift+l",
        "command": "editor.action.insertSnippet",
        "when": "editorTextFocus && editorLangId == 'javascript'",
        "args": {
            "snippet": "console.log('$TM_SELECTED_TEXT:', $TM_SELECTED_TEXT);"
        }
    },

    // Disable an unwanted default keybinding
    {
        "key": "ctrl+k ctrl+f",
        "command": "-editor.action.formatSelection"
    }
]

Multi-Command Macros

VS Code does not natively support multi-command macros, but the multi-command extension fills that gap. Define a sequence of commands in settings.json, then bind it in keybindings.json.

settings.json (with multi-command extension)
{
    "multiCommand.commands": [
        {
            "command": "multiCommand.saveAndFormat",
            "sequence": [
                "editor.action.formatDocument",
                "workbench.action.files.save"
            ]
        },
        {
            "command": "multiCommand.closeAndFocusTerminal",
            "sequence": [
                "workbench.action.closeActiveEditor",
                "workbench.action.terminal.focus"
            ]
        }
    ]
}
keybindings.json
[
    // Bind the multi-command macros
    {
        "key": "ctrl+shift+s",
        "command": "multiCommand.saveAndFormat"
    },
    {
        "key": "ctrl+shift+w",
        "command": "multiCommand.closeAndFocusTerminal",
        "when": "editorTextFocus"
    }
]
Key Concept

Prefix a command with - in keybindings.json to remove a default binding. This is how you disable built-in shortcuts that conflict with your workflow without affecting anything else. The removal entry must match the original key and when clause exactly.

Debugging Keybindings

If a keybinding is not working, open the Command Palette and run Developer: Toggle Keyboard Shortcuts Troubleshooting. Then press the key combo. VS Code will show exactly which keybinding matched (or conflicted) and why, including the when clause evaluation.
