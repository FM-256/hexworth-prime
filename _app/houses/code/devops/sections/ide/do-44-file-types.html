Language Detection

When you open a file, VS Code determines its language using a priority chain: the file extension first (.py → Python), then the filename itself (Dockerfile, Makefile), then a first-line pattern match (e.g. #!/usr/bin/env node → JavaScript). You can always override this manually with the language selector in the bottom-right status bar.

Key Concept

Language detection drives everything downstream. Once VS Code knows a file is Python, it loads the Python grammar for highlighting, activates the Python language server for IntelliSense, and applies Python-specific settings (formatters, linters, run configurations).

File Associations

You can teach VS Code about custom extensions or override defaults in settings.json:

settings.json
{
    "files.associations": {
        "*.tpl": "html",
        "*.j2": "jinja",
        "*.conf": "ini",
        ".env.*": "dotenv",
        "Jenkinsfile*": "groovy",
        "Vagrantfile": "ruby"
    }
}

Built-in Language Support

VS Code ships with rich support for many languages out of the box — no extensions required. The depth of that support varies. Some languages get full IntelliSense, while others get only syntax highlighting.

Language Highlighting IntelliSense Debugging Notes
JavaScript Full Full (via TypeScript engine) Built-in (Node) JSDoc support, type checking via // @ts-check
TypeScript Full Full Built-in First-class citizen — VS Code is built in TypeScript
HTML Full Tags, attributes, Emmet N/A Includes auto-closing tags, color preview
CSS / SCSS / Less Full Properties, values, selectors N/A Color picker, selector specificity
JSON / JSONC Full Schema validation N/A JSONC allows comments (settings.json uses this)
Markdown Full Path completion, preview N/A Built-in preview with Ctrl+Shift+V
Python Full Basic (full via Pylance ext) Via extension Highlighting built-in; install Python ext for full power
Shell Script Full Basic Via extension Bash, sh, zsh syntax supported
Built-in Does Not Mean Complete

JavaScript gets world-class IntelliSense because VS Code runs the TypeScript compiler internally. Languages like Python, Go, or Rust need extension-provided language servers for comparable intelligence. Highlighting alone does not give you autocomplete, error detection, or refactoring.

Language Server Protocol (LSP)

Before LSP, every editor had to implement language features from scratch. If you wanted Python autocomplete in Vim, VS Code, and Sublime, you needed three separate plugins — each with its own parsing engine. LSP solved this with a standardized JSON-RPC protocol between editors and language servers.

How LSP Works

Editor Sends requests over JSON-RPC: "What completions are available at line 42, column 10?"
Server Runs as a separate process. Parses the project, resolves types, and sends back structured results.
Protocol Defines standard messages: textDocument/completion, textDocument/definition, textDocument/references, textDocument/rename, etc.
Why LSP Matters

Before LSP, supporting M editors and N languages required M x N implementations. With LSP, each language builds one server and each editor builds one client. The effort drops to M + N. Microsoft created LSP for VS Code, but now Neovim, Sublime Text, Eclipse, Emacs, and dozens of other editors all speak it.

IntelliSense

IntelliSense is VS Code's umbrella term for intelligent code assistance. It encompasses multiple features that work together to help you write code faster and with fewer errors.

Autocomplete CORE

Context-aware suggestions as you type. Triggered automatically or with Ctrl+Space. Ranked by relevance, recent usage, and type matching.

Parameter Info SIGNATURES

Shows function signatures and parameter types as you type inside parentheses. Triggered with Ctrl+Shift+Space.

Quick Info HOVER

Hover over any symbol to see its type, documentation, and definition source. Works on variables, functions, classes, imports.

Member Lists DOT TRIGGER

Type a dot after an object and see all available properties and methods, filtered by type. Works with imports, APIs, and local objects.

Configuring IntelliSense

settings.json
{
    // Trigger suggestions automatically as you type
    "editor.quickSuggestions": {
        "other": true,
        "comments": false,
        "strings": true
    },

    // Accept suggestions with Tab (not just Enter)
    "editor.tabCompletion": "on",

    // Show snippets alongside other suggestions
    "editor.snippetSuggestions": "inline",

    // Accept suggestion on commit characters (., ;, etc.)
    "editor.acceptSuggestionOnCommitCharacter": true,

    // Delay before suggestions appear (ms)
    "editor.quickSuggestionsDelay": 10,

    // Show type info in suggest widget
    "editor.suggest.showTypeParameters": true
}
IntelliSense Quality Depends on the Language Server

The built-in TypeScript engine provides excellent IntelliSense for JavaScript and TypeScript out of the box. For Python, Go, Rust, and other languages, IntelliSense quality is determined by the installed language server extension. Without one, you only get word-based completions — which are just pattern-matching on text in the current file.

Syntax Highlighting

Syntax highlighting is the most fundamental language feature. It assigns colors to tokens (keywords, strings, comments, variables) so you can visually parse code structure at a glance. VS Code uses TextMate grammars — the same grammar format originally created for the TextMate editor on macOS.

How Grammars Work

A TextMate grammar is a set of regular expressions that match patterns in source code and assign scope names to them. For example, the keyword function in JavaScript gets the scope storage.type.function.js. Your color theme then maps scopes to colors.

Scope Examples
// Keyword:       storage.type.function.js         -> purple
// String:        string.quoted.double.js           -> orange
// Comment:       comment.line.double-slash.js      -> gray
// Variable:      variable.other.readwrite.js       -> light blue
// Function name: entity.name.function.js           -> yellow
// Type:          support.type.builtin.js           -> teal

Semantic Highlighting

TextMate grammars are purely regex-based — they cannot understand types, scopes, or resolved references. Semantic highlighting is a second layer provided by language servers that adds richer token classification. For example, a semantic token provider can distinguish between a local variable, a parameter, and a global constant — something regex alone cannot do.

Scope Inspector

To see exactly how any token is classified, use the scope inspector:

Command Palette
# Open with Ctrl+Shift+P, then type:
Developer: Inspect Editor Tokens and Scopes

# Click on any token to see:
language:         javascript
standard token:   keyword.control.js
semantic token:   keyword
foreground:       #c586c0
Debugging Theme Colors

If a token looks wrong, the scope inspector tells you exactly which grammar rule matched and which theme rule is coloring it. This is essential when building or customizing themes, and useful when you suspect a grammar bug.

Code Navigation

Navigation features let you jump around a codebase without manually searching files. These are powered by the language server and become increasingly powerful as the server builds its project model.

Feature Shortcut What It Does
Go to Definition F12 Jump to where a symbol (function, class, variable) is defined
Peek Definition Alt+F12 Show definition inline without leaving current file
Go to Type Definition Ctrl+F12 (varies) Jump to the type of a variable, not the variable itself
Find All References Shift+F12 Find every place a symbol is used across the entire project
Go to Symbol Ctrl+Shift+O Jump to any function, class, or variable in the current file
Go to Symbol (Workspace) Ctrl+T Search for symbols across all files in the workspace
Call Hierarchy Shift+Alt+H Show who calls this function and what this function calls
Go to Implementation Ctrl+F12 Jump to implementations of an interface or abstract method

Breadcrumbs

The breadcrumb bar at the top of the editor shows your current location in the file's symbol hierarchy: File → Class → Method. Click any segment to navigate. Enable it in settings:

settings.json
{
    "breadcrumbs.enabled": true,
    "breadcrumbs.symbolPath": "on",
    "breadcrumbs.filePath": "on"
}
Navigation vs. Search

Ctrl+Shift+F (global text search) is for finding strings. Ctrl+T and F12 are for finding symbols — they understand the code structure. Prefer symbol navigation when you know the name of a function or class; use text search when looking for arbitrary strings, log messages, or configuration values.

Refactoring

Refactoring tools let you restructure code without changing its behavior. VS Code delegates refactoring to the language server, so available refactorings vary by language. TypeScript and Java have the richest support; Python and Go are catching up.

Rename Symbol F2

Renames a variable, function, or class across every file in the project. The language server resolves all references semantically — it does not use find-and-replace.

Place cursor on symbol → F2 → type new name → Enter
Extract Variable REFACTOR

Select an expression, extract it into a named variable. Replaces all identical occurrences in scope.

Select expression → Ctrl+Shift+R → Extract Variable
Extract Method REFACTOR

Select a block of code, extract it into a new function. Parameters and return values are inferred automatically.

Select code block → Ctrl+Shift+R → Extract Method
Code Actions LIGHTBULB

The yellow lightbulb icon appears when the language server has suggestions: organize imports, add missing types, convert between syntaxes. Trigger with Ctrl+.

Ctrl+. on a squiggly underline → pick action

Quick Fix vs. Refactor

Both appear via Ctrl+., but they serve different purposes. Quick Fixes address problems (missing imports, type errors). Refactorings restructure valid code (extract, rename, move). The lightbulb is yellow for refactorings and blue for quick fixes (VS Code 1.70+).

Always Review Rename Results

Rename Symbol is not a simple text replacement — it uses the language server to find semantic references. But in dynamic languages like JavaScript or Python, the server may miss references it cannot statically resolve (dynamic property access, eval(), reflection). Always review the changes before committing.

Kubernetes YAML with Schema Validation

The Red Hat YAML extension can validate Kubernetes manifests against the official API schemas. Configure it to auto-detect Kubernetes files:

settings.json
{
    "yaml.schemas": {
        "kubernetes": "*.k8s.yaml"
    },
    "yaml.customTags": [
        "!Ref",
        "!Sub scalar",
        "!GetAtt"
    ],
    "redhat.telemetry.enabled": false
}

Terraform Configuration

settings.json
{
    "[terraform]": {
        "editor.defaultFormatter": "hashicorp.terraform",
        "editor.formatOnSave": true
    },
    "terraform.languageServer.enable": true,
    "terraform.validation.enableEnhancedValidation": true
}
Makefile Tab Requirement

Makefiles use literal tab characters for indentation — spaces will cause syntax errors. VS Code detects this automatically for files named Makefile, but if you use a different name, set "editor.insertSpaces": false in a language-specific override for the [makefile] language ID.

Emmet

Emmet is a built-in toolkit for writing HTML and CSS at high speed using shorthand abbreviations. Type a short expression, press Tab, and VS Code expands it into full markup. This is not an extension — it ships with VS Code and works immediately in HTML, CSS, JSX, and other supported languages.

Enabling Emmet in Other Languages

By default, Emmet works in HTML, CSS, and a few related languages. To enable it in JSX, ERB, Twig, or other template languages:

settings.json
{
    "emmet.includeLanguages": {
        "javascript": "javascriptreact",
        "vue-html": "html",
        "erb": "html",
        "jinja": "html"
    },
    "emmet.triggerExpansionOnTab": true,
    "emmet.showSuggestionsAsSnippets": true
}
Wrap with Abbreviation

Select existing text, open the Command Palette (Ctrl+Shift+P), and run Emmet: Wrap with Abbreviation. Type div.wrapper and it wraps your selection in <div class="wrapper">...</div>. This works with any Emmet expression.

Formatting

Code formatting automatically reformats your source to follow consistent style rules: indentation, spacing, line length, brace placement. VS Code supports formatting through built-in formatters and extension-provided ones.

Core Formatting Commands

Action Shortcut What It Does
Format Document Shift+Alt+F Format the entire file
Format Selection Ctrl+K Ctrl+F Format only the selected text
Format on Save Setting Automatically format when saving
Format on Paste Setting Automatically format pasted code

Configuring Formatters

settings.json
{
    // Global format on save
    "editor.formatOnSave": true,
    "editor.formatOnPaste": true,

    // Set default formatter per language
    "[javascript]": {
        "editor.defaultFormatter": "esbenp.prettier-vscode"
    },
    "[python]": {
        "editor.defaultFormatter": "ms-python.black-formatter",
        "editor.formatOnSave": true
    },
    "[go]": {
        "editor.defaultFormatter": "golang.go"
    },
    "[terraform]": {
        "editor.defaultFormatter": "hashicorp.terraform"
    },

    // Formatter-specific settings (Prettier)
    "prettier.singleQuote": true,
    "prettier.tabWidth": 2,
    "prettier.trailingComma": "es5",
    "prettier.printWidth": 100
}

Formatter Conflicts

If you have multiple extensions that can format the same language, VS Code will ask you to choose. Set editor.defaultFormatter per language to avoid the prompt. If Prettier and ESLint fight, use eslint-config-prettier to disable ESLint's formatting rules and let Prettier handle style.

Linting

Linters analyze your code for errors, anti-patterns, and style violations without running it. They catch bugs before they happen: unused variables, unreachable code, security issues, deprecated API usage. VS Code displays linter output as squiggly underlines in the editor and as entries in the Problems panel (Ctrl+Shift+M).

Diagnostic Severity Levels

Error Code is broken or will fail. Red squiggly underline. Must be fixed before the code can work correctly.
Warning Potential problem or bad practice. Yellow squiggly underline. Code may work but likely has an issue.
Information Suggestion or hint. Blue squiggly underline. Code is fine but could be improved.
Hint Subtle suggestion. Faded text (unused imports, unnecessary code). The lightest level of feedback.

ESLint Configuration

settings.json
{
    // Enable ESLint for these languages
    "eslint.validate": [
        "javascript",
        "javascriptreact",
        "typescript",
        "typescriptreact"
    ],

    // Auto-fix linting issues on save
    "editor.codeActionsOnSave": {
        "source.fixAll.eslint": "explicit"
    },

    // ShellCheck settings
    "shellcheck.executablePath": "/usr/bin/shellcheck",
    "shellcheck.enable": true
}
Linting + Formatting: The DevOps Duo

Linters find bugs. Formatters fix style. Use both together. The pattern is: the formatter owns all style rules (indentation, spacing, semicolons), and the linter owns all logic rules (unused variables, type safety, security). Disable style rules in the linter (eslint-config-prettier for JS, ruff handles both for Python) to prevent conflicts.
