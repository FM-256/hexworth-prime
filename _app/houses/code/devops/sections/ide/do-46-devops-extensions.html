DevOps Extensions Toolkit

Turn VS Code into a full DevOps control plane. Manage containers, orchestrate clusters, provision infrastructure, and test APIs — all without leaving the editor.

~40 min Module Intermediate

Learning Objectives

  • Manage extensions from the marketplace, command line, and workspace recommendations
  • Use the Docker extension to build images, manage containers, and inspect logs
  • Navigate Kubernetes clusters, view pod logs, and port-forward from VS Code
  • Author Terraform HCL with autocomplete, validation, and in-editor plan execution
  • Write and lint Ansible playbooks with Red Hat's extension and ansible-navigator
  • Configure YAML schema validation for Kubernetes manifests and custom schemas
  • Test APIs with REST Client and Thunder Client without leaving the editor
  • Leverage GitLens for advanced blame, commit graphs, and interactive rebase
  • Evaluate AI coding assistants and build custom extension packs for your team

1. Extension Management

VS Code's extension marketplace is the backbone of its DevOps story. With over 40,000 extensions, the challenge isn't finding tools — it's curating the right set and keeping them manageable across machines and teams.

Installing Extensions

There are three ways to install extensions: the GUI marketplace (Ctrl+Shift+X), the command palette (Ctrl+Shift+P → "Install Extensions"), and the CLI.

Terminal
# Install an extension by its full ID
$ code --install-extension ms-azuretools.vscode-docker

# Install a specific version
$ code --install-extension hashicorp.terraform@2.30.0

# List all installed extensions
$ code --list-extensions

# Uninstall an extension
$ code --uninstall-extension ms-azuretools.vscode-docker

Per-Workspace Extensions

Not every extension belongs in every project. You can disable extensions globally and enable them only for specific workspaces, or use workspace recommendations to prompt teammates to install what they need.

JSON — .vscode/extensions.json
{
  "recommendations": [
    "ms-azuretools.vscode-docker",
    "hashicorp.terraform",
    "redhat.vscode-yaml",
    "ms-kubernetes-tools.vscode-kubernetes-tools"
  ],
  "unwantedRecommendations": [
    "some-extension.you-dont-want"
  ]
}
Key Concept

Commit .vscode/extensions.json to your repo. When a teammate opens the project, VS Code prompts them to install the recommended extensions. This ensures consistent tooling across the team without forcing anything.

Extension Management Commands

Disable (Workspace) SCOPE

Right-click an extension → "Disable (Workspace)" to turn it off for the current project only

@enabled FILTER

Type @enabled in the Extensions search bar to see all active extensions

@builtin FILTER

View built-in extensions that ship with VS Code (Git, TypeScript, etc.)

Extension Bisect DEBUG

Command Palette → "Start Extension Bisect" to find which extension causes a problem

2. Docker Extension

The Docker extension (ms-azuretools.vscode-docker) turns VS Code into a full container management interface. Build images, run containers, inspect logs, and manage compose stacks — all from the sidebar.

Docker: Build Image BUILD

Right-click a Dockerfile or use Command Palette to build. Supports build args and multi-stage builds.

Ctrl+Shift+P → "Docker: Build Image"
Container Explorer MANAGE

View running/stopped containers in the Docker sidebar. Start, stop, restart, remove, attach shell, or view logs.

Compose Up/Down COMPOSE

Right-click docker-compose.yml to bring an entire stack up or tear it down.

Right-click compose file → "Compose Up"
Dockerfile IntelliSense AUTHOR

Autocomplete for instructions (FROM, RUN, COPY), image tags, and syntax validation as you type.

Container Logs

Right-click any running container in the Docker sidebar and select "View Logs" to stream logs directly into a VS Code terminal. You can also "Attach Shell" to exec into a container without typing docker exec -it manually.

3. Kubernetes Extension

The Kubernetes extension (ms-kubernetes-tools.vscode-kubernetes-tools) provides a cluster explorer, manifest IntelliSense, Helm chart support, and the ability to stream pod logs and port-forward — all without leaving the editor.

Cluster Explorer NAVIGATE

Browse namespaces, deployments, pods, services, configmaps, and secrets in a tree view. Reads your ~/.kube/config automatically.

Pod Logs DEBUG

Right-click a pod → "Logs" to stream container output in a VS Code terminal panel.

Right-click pod → "Follow Logs"
Port Forward ACCESS

Right-click a pod or service → "Port Forward" to tunnel traffic to localhost without kubectl port-forward.

Helm Support CHARTS

Template rendering, values file IntelliSense, and lint support for Helm charts.

Useful Settings

JSON — settings.json
{
  // Path to kubectl binary (if not in $PATH)
  "vs-kubernetes.kubectl-path": "/usr/local/bin/kubectl",

  // Path to helm binary
  "vs-kubernetes.helm-path": "/usr/local/bin/helm",

  // Auto-refresh cluster explorer
  "vs-kubernetes.autoRefresh": true,

  // Default namespace filter
  "vs-kubernetes.namespace": "default"
}
Context Awareness

The extension uses your current kubectl context. Always verify which cluster you're targeting before performing destructive actions. Run kubectl config current-context or check the status bar in VS Code to confirm.

4. Terraform Extension (HashiCorp)

The official Terraform extension (hashicorp.terraform) from HashiCorp provides HCL syntax highlighting, semantic autocomplete powered by the Terraform Language Server, inline validation, and the ability to run terraform plan directly from the editor.

HCL IntelliSense SYNTAX

Autocomplete for resource types, argument names, attribute references, and built-in functions. Understands provider schemas.

Terraform: Init COMMAND

Run terraform init from the Command Palette to initialize providers and backend.

Ctrl+Shift+P → "Terraform: Init"
Terraform: Plan COMMAND

Execute a plan and view the output in the integrated terminal. Review changes before applying.

Ctrl+Shift+P → "Terraform: Plan"
Module Navigation NAVIGATE

Ctrl+Click on module sources to jump into module definitions. Go to Definition works across .tf files.

Recommended Settings

JSON — settings.json
{
  // Enable the language server for IntelliSense
  "terraform.languageServer.enable": true,

  // Format on save with terraform fmt
  "[terraform]": {
    "editor.defaultFormatter": "hashicorp.terraform",
    "editor.formatOnSave": true
  },

  // Validate on save
  "terraform.validation.enableEnhancedValidation": true,

  // Enable code lens for references
  "terraform.codelens.referenceCount": true
}
Key Concept

The Terraform Language Server downloads and caches provider schemas locally. After adding a new provider, run terraform init to update schemas and restore full autocomplete for that provider's resources and data sources.

5. Ansible Extension (Red Hat)

The Ansible extension (redhat.ansible) provides YAML-aware IntelliSense for Ansible playbooks, roles, and collections. It integrates ansible-lint for real-time validation and supports ansible-navigator for execution environments.

Playbook IntelliSense AUTHOR

Autocomplete for module names, parameters, and Jinja2 filters. Understands collection FQCNs like ansible.builtin.copy.

ansible-lint LINT

Real-time linting with squiggly underlines. Catches deprecated modules, missing names, and bad practices.

pip install ansible-lint
ansible-navigator RUN

Run playbooks inside execution environments (containers) for reproducible runs. Integrates with the extension.

pip install ansible-navigator
Role Skeleton SCAFFOLD

Command Palette → "Ansible: Create New Playbook" to scaffold a starter playbook with best-practice structure.

Settings for Ansible

JSON — settings.json
{
  "files.associations": {
    "**/playbooks/*.yml": "ansible",
    "**/roles/*/tasks/*.yml": "ansible"
  },
  "ansible.validation.lint.enabled": true,
  "ansible.executionEnvironment.enabled": true
}
File Detection

VS Code doesn't always auto-detect Ansible YAML. Use files.associations to map playbook paths to the Ansible language mode. The status bar should show "Ansible" not "YAML".

6. YAML Extension (Red Hat)

The YAML extension (redhat.vscode-yaml) brings schema-based validation and autocomplete to YAML files. It is especially powerful for Kubernetes manifests, GitHub Actions workflows, and any YAML format with a published JSON Schema.

Schema Validation

The extension maps file patterns to JSON Schemas. When a file matches, you get autocomplete, hover docs, and inline validation automatically.

JSON — settings.json
{
  // Map file globs to JSON Schemas
  "yaml.schemas": {
    // Kubernetes manifests
    "kubernetes": "k8s/*.yaml",

    // Docker Compose files
    "https://raw.githubusercontent.com/compose-spec/compose-spec/master/schema/compose-spec.json": "docker-compose*.yml",

    // GitHub Actions workflows
    "https://json.schemastore.org/github-workflow.json": ".github/workflows/*.yml",

    // Custom schema for your config format
    "./schemas/my-config.schema.json": "config/*.yaml"
  },

  // Format on save for YAML
  "[yaml]": {
    "editor.defaultFormatter": "redhat.vscode-yaml",
    "editor.formatOnSave": true
  }
}
Key Concept

The Kubernetes schema mapping ("kubernetes") is a built-in shorthand. The extension downloads the OpenAPI schema for your cluster's API version and validates all mapped files against it — catching typos in apiVersion, kind, and field names before you ever run kubectl apply.

Schema Store AUTO

The extension auto-fetches schemas from SchemaStore.org for common formats (Ansible, CircleCI, Azure Pipelines, etc.)

Inline Modeline OVERRIDE

Add # yaml-language-server: $schema=URL as the first line of any YAML file to override schema mapping per-file.

# yaml-language-server: $schema=https://json.schemastore.org/kustomization.json

7. Remote Containers as a DevOps Tool

The Dev Containers extension (ms-vscode-remote.remote-containers) lets you define your entire development environment as a Dockerfile or devcontainer.json. From a DevOps perspective, this is critical: your local dev environment matches your CI pipeline exactly.

Local Machine
VS Code Client
→
Dev Container
Full Toolchain
→
CI Pipeline
Same Image
Click a stage above to learn how Dev Containers create CI parity.
JSON — .devcontainer/devcontainer.json
{
  "name": "DevOps Workspace",
  "image": "mcr.microsoft.com/devcontainers/base:ubuntu",
  "features": {
    "ghcr.io/devcontainers/features/docker-in-docker:2": {},
    "ghcr.io/devcontainers/features/kubectl-helm-minikube:1": {},
    "ghcr.io/devcontainers/features/terraform:1": {}
  },
  "customizations": {
    "vscode": {
      "extensions": [
        "ms-azuretools.vscode-docker",
        "hashicorp.terraform",
        "ms-kubernetes-tools.vscode-kubernetes-tools"
      ]
    }
  }
}
CI Parity

The same devcontainer.json can be used in GitHub Codespaces, GitPod, and many CI systems. When your dev environment and CI environment share the same base image and toolchain, "works on my machine" stops being an excuse.

8. GitHub Actions Extension

The GitHub Actions extension (github.vscode-github-actions) provides workflow syntax highlighting, job visualization, and the ability to monitor workflow runs directly in VS Code.

Workflow IntelliSense AUTHOR

Autocomplete for action names, input parameters, expression syntax (${{ }}), and context variables like github.sha.

Run Visualization MONITOR

View workflow runs in the sidebar — see which jobs passed, failed, or are still running.

Log Streaming DEBUG

Click a workflow run step to view its logs inline. No need to open the GitHub web UI.

Secret References SECURITY

Recognizes secrets.* and vars.* references. Warns about undefined secrets in your workflow files.

YAML — .github/workflows/ci.yml
# The extension provides autocomplete for all of this
name: CI Pipeline
on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci && npm test
Pair with YAML Extension

The YAML extension (Section 6) provides the schema validation layer, while the GitHub Actions extension adds action-specific intelligence. Together they catch errors like invalid runs-on values, bad expression syntax, and unknown action inputs before you push.

9. GitLens

GitLens (eamodio.gitlens) supercharges VS Code's built-in Git support. It adds inline blame annotations, a visual commit graph, worktree management, interactive rebase, and deep repository exploration that makes git log feel primitive.

Inline Blame TRACE

See who last modified every line, when, and the commit message — displayed as a faded annotation at the end of each line.

Commit Graph VISUALIZE

Interactive branch graph showing all commits, merges, and tags. Filter by author, date, or file path.

Ctrl+Shift+P → "GitLens: Show Commit Graph"
File History TRACK

View every change made to the current file. Click any commit to see the diff at that point in time.

Worktrees PARALLEL

Create and manage Git worktrees from the sidebar. Work on multiple branches simultaneously without stashing.

Interactive Rebase REWRITE

Visual drag-and-drop rebase editor. Reorder, squash, edit, and drop commits with a GUI instead of a text file.

Ctrl+Shift+P → "GitLens: Interactive Rebase"
Code Lens CONTEXT

Shows "N authors (N changes)" above functions and classes. Click to see the full change history for that symbol.

Tuning GitLens

JSON — settings.json
{
  // Show blame inline (the ghost text at end of lines)
  "gitlens.currentLine.enabled": true,

  // Compact commit graph format
  "gitlens.graph.layout": "editor",

  // Date format for blame annotations
  "gitlens.defaultDateFormat": "YYYY-MM-DD",

  // Disable CodeLens if it feels too noisy
  "gitlens.codeLens.enabled": false
}
Key Concept

GitLens free tier covers inline blame, file history, and most sidebar features. The Commit Graph and advanced features like Worktrees and Visual Rebase are part of GitLens+ (free for public repos, paid for private). Evaluate what your team actually needs before purchasing.

10. REST Client

The REST Client extension (humao.rest-client) lets you send HTTP requests directly from .http or .rest files. No Postman needed — your API tests live in the same repo as your code and can be version controlled.

HTTP — api-tests.http
### Health Check
GET http://localhost:3000/health

###

### Create a user
POST http://localhost:3000/api/users
Content-Type: application/json
Authorization: Bearer {{auth_token}}

{
  "name": "Operator Zero",
  "role": "admin"
}

###

### Get user by ID
GET http://localhost:3000/api/users/{{user_id}}
Authorization: Bearer {{auth_token}}
How to Use

Click "Send Request" above any request block (separated by ###). The response appears in a split pane with headers, timing, and status code. Define per-environment variables in rest-client.environmentVariables in settings.json (local, staging, prod), then switch via Ctrl+Shift+P → "Rest Client: Switch Environment".

11. Thunder Client

Thunder Client (rangav.vscode-thunder-client) is a lightweight GUI alternative to Postman, built directly into VS Code. It provides a visual interface for building requests, organizing them into collections, and managing environments.

Request Builder GUI

Visual interface for method, URL, headers, body (JSON, form, XML), query params, and auth configuration.

Collections ORGANIZE

Group related requests into folders. Import/export Postman, OpenAPI, and cURL collections.

Environments CONFIG

Define variable sets (local, staging, prod) and reference them with {{variable}} syntax in any field.

Git Sync TEAM

Save collections as JSON files in your repo. Team members get the same API test suite when they clone.

thunder-tests/ directory in project root
REST Client vs Thunder Client

These two overlap significantly. REST Client is text-based (.http files committed to the repo) — ideal for developers who prefer code-first. Thunder Client provides a GUI sidebar like Postman — ideal for teams migrating from Postman. Pick one; running both clutters the command palette.

12. Shell & Scripting Extensions

DevOps engineers write a lot of shell scripts — for CI pipelines, provisioning, health checks, and glue code. These extensions bring real IDE features to Bash and PowerShell.

ShellCheck LINT

Extension ID: timonwong.shellcheck. Static analysis for Bash/sh scripts. Catches quoting bugs, unused variables, and POSIX portability issues.

# SC2086: Double quote to prevent globbing
Bash IDE LANGUAGE

Extension ID: mads-hartmann.bash-ide-vscode. Go to Definition, Find References, and autocomplete for Bash functions and variables via the Bash Language Server.

PowerShell LANGUAGE

Extension ID: ms-vscode.powershell. Full IntelliSense, debugging, Pester test integration, and PSScriptAnalyzer linting for PowerShell scripts.

Shell Format FORMAT

Extension ID: foxundermoon.shell-format. Auto-format Bash, Dockerfile, .env, and other shell-adjacent files on save using shfmt.

Requires: go install mvdan.cc/sh/v3/cmd/shfmt@latest

ShellCheck in Practice

BASH
#!/bin/bash
# ShellCheck catches this common bug:

# BAD: unquoted variable, breaks on filenames with spaces
for f in $FILES; do
  rm $f
done

# GOOD: ShellCheck suggests double-quoting
for f in "${FILES[@]}"; do
  rm "$f"
done
Key Concept

ShellCheck is also available as a standalone CLI tool. Many CI pipelines run shellcheck *.sh as a lint step. The VS Code extension gives you the same feedback in real time as you type, so scripts are clean before they ever hit CI.

13. AI Coding Assistants

AI-powered coding assistants have become a fixture in the DevOps toolkit. They accelerate boilerplate generation (Terraform modules, Kubernetes manifests, CI configs), explain unfamiliar code, and reduce context-switching between documentation and editor.

GitHub Copilot $10-39/MO

Extension ID: github.copilot. Deep GitHub integration, inline completions, chat panel, workspace-aware context.

Claude (Anthropic) API-BASED

Extension ID: anthropic.claude-code. Strong reasoning, large context window, agentic coding with terminal integration.

Codeium FREE / PRO

Extension ID: codeium.codeium. Free tier for individuals, fast autocomplete, chat, supports 70+ languages.

Continue OPEN SOURCE

Extension ID: continue.continue. Bring your own model (local Ollama or API keys), fully configurable, privacy-first.

DevOps-Specific Use Cases

IaC Generation Generate Terraform resources, Kubernetes manifests, and Helm values from natural language descriptions.
CI/CD Authoring Scaffold GitHub Actions workflows, GitLab CI configs, or Jenkinsfiles from project requirements.
Debug Assistance Paste error logs and get root-cause analysis, suggested fixes, and links to relevant documentation.
Code Review Ask AI to review Dockerfiles for security issues, Terraform plans for cost implications, or scripts for portability.
Security Consideration

AI assistants send code to external APIs. Evaluate your organization's data policy before enabling them on proprietary codebases. Some options (Continue + local models, self-hosted Copilot Enterprise) keep data on-premises. Never paste secrets into AI chat prompts.

14. Recommended Extension Packs

An extension pack is a meta-extension that installs a curated set of extensions in one click. You can create your own pack to standardize tooling across your DevOps team.

Creating Your Own Extension Pack

Terminal
# Install the extension generator
$ npm install -g yo generator-code

# Scaffold an extension pack
$ yo code
? What type of extension? → Extension Pack
? Extension pack name? → devops-toolkit
? Identifier? → my-team.devops-toolkit

package.json for an Extension Pack

JSON — package.json
{
  "name": "devops-toolkit",
  "displayName": "DevOps Toolkit",
  "description": "Standard DevOps extensions for the team",
  "version": "1.0.0",
  "categories": ["Extension Packs"],
  "extensionPack": [
    "ms-azuretools.vscode-docker",
    "ms-kubernetes-tools.vscode-kubernetes-tools",
    "hashicorp.terraform",
    "redhat.ansible",
    "redhat.vscode-yaml",
    "github.vscode-github-actions",
    "eamodio.gitlens",
    "humao.rest-client",
    "timonwong.shellcheck",
    "mads-hartmann.bash-ide-vscode"
  ]
}
Terminal
# Package and share with your team
$ npm install -g @vscode/vsce
$ vsce package
Created: devops-toolkit-1.0.0.vsix

# Install from VSIX file
$ code --install-extension devops-toolkit-1.0.0.vsix

# Or publish to the marketplace (requires publisher account)
$ vsce publish
Key Concept

Use extension packs and workspace recommendations together. The pack provides your team's baseline (Docker, Terraform, GitLens, ShellCheck) across all projects. The per-repo .vscode/extensions.json adds project-specific extras (Python for a Python repo, Go for a Go repo). This layered approach keeps everyone productive without bloating anyone's editor.
