1. HashiCorp Configuration Language

HCL is Terraform's domain-specific language. It was designed to be human-readable while remaining machine-parseable — a middle ground between JSON and a full programming language. Every .tf file is written in HCL.

Blocks, Arguments, and Expressions

HCL has three fundamental constructs. Blocks are containers that define objects (resources, variables, outputs). Arguments assign values to names inside blocks. Expressions represent values, either literally or by referencing other values.

HCL
# Block type "resource", two labels: type and name
resource "aws_instance" "web_server" {
  # Arguments: key = value pairs
  ami           = "ami-0c55b159cbfafe1f0"
  instance_type = "t3.micro"

  # Expression referencing another resource
  subnet_id     = aws_subnet.public.id

  # Nested block (no = sign, just braces)
  tags = {
    Name        = "WebServer"
    Environment = var.environment
  }
}

HCL Data Types

TypeSyntaxExample
StringDouble quotes"hello world"
NumberUnquoted digits42, 3.14
Booltrue / falsetrue
ListSquare brackets["us-east-1a", "us-east-1b"]
MapCurly braces{ Name = "web", Env = "prod" }
NullnullOmits an optional argument

String Interpolation and Heredocs

HCL
# Interpolation with ${...}
name = "server-${var.environment}-${count.index}"

# Heredoc for multi-line strings
user_data = <<-EOF
  #!/bin/bash
  echo "Hello from ${var.environment}"
  yum install -y httpd
  systemctl start httpd
EOF
Key Concept

HCL is declarative, not imperative. You describe the desired end state, and Terraform figures out the steps to get there. You never write "create this, then that" — you write "this should exist" and Terraform handles ordering.

2. Providers

Providers are plugins that let Terraform talk to APIs. Every cloud platform, SaaS tool, and service has a provider — AWS, Azure, GCP, Cloudflare, Kubernetes, GitHub, Datadog, and hundreds more. Without a provider, Terraform cannot manage anything.

Provider Configuration

HCL
# Required providers block (Terraform 1.0+)
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }

  required_version = ">= 1.5.0"
}

# Provider configuration
provider "aws" {
  region  = "us-east-1"
  profile = "default"

  default_tags {
    tags = {
      ManagedBy = "Terraform"
      Project   = "hexworth"
    }
  }
}

Version Constraints

OperatorMeaningExample
=Exact version"5.31.0"
>=Minimum version">= 5.0"
~>Pessimistic (allows rightmost increment)"~> 5.0" allows 5.x but not 6.0
>=, <Range">= 5.0, < 6.0"
Provider Authentication

Never hardcode credentials in provider blocks. Use environment variables (AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY), shared credential files, or IAM roles. Terraform reads these automatically.

Multiple Provider Instances

HCL
# Default provider (us-east-1)
provider "aws" {
  region = "us-east-1"
}

# Aliased provider for a second region
provider "aws" {
  alias  = "west"
  region = "us-west-2"
}

# Use the alias in a resource
resource "aws_instance" "west_server" {
  provider      = aws.west
  ami           = "ami-0abcdef1234567890"
  instance_type = "t3.micro"
}

3. Resources

Resources are the most important element in Terraform. Each resource block describes one or more infrastructure objects — a VM, a DNS record, a database, a firewall rule. When you run terraform apply, Terraform creates, updates, or destroys resources to match your configuration.

Resource Block Anatomy

HCL
#       type              local name
resource "aws_s3_bucket" "logs" {
  bucket = "my-app-logs-2026"

  versioning {
    enabled = true
  }

  server_side_encryption_configuration {
    rule {
      apply_server_side_encryption_by_default {
        sse_algorithm = "AES256"
      }
    }
  }

  tags = {
    Name = "Application Logs"
  }
}

# Reference this resource elsewhere
# aws_s3_bucket.logs.arn
# aws_s3_bucket.logs.bucket_domain_name

Implicit and Explicit Dependencies

HCL
# Implicit dependency: Terraform knows this needs the VPC first
resource "aws_subnet" "public" {
  vpc_id     = aws_vpc.main.id   # references aws_vpc.main
  cidr_block = "10.0.1.0/24"
}

# Explicit dependency: no attribute reference, but order matters
resource "aws_instance" "app" {
  ami           = "ami-0c55b159cbfafe1f0"
  instance_type = "t3.micro"

  depends_on = [aws_iam_role_policy.s3_access]
}
Implicit vs Explicit

Terraform automatically detects dependencies when you reference one resource inside another. Use depends_on only when there is a hidden dependency that Terraform cannot infer from your code — for example, an IAM policy that must exist before an instance can use it.

4. Data Sources

Data sources let you query information about infrastructure that already exists — things Terraform did not create. This is essential for referencing shared resources, looking up AMI IDs, reading DNS zones, or fetching secrets from a vault.

HCL
# Look up the latest Amazon Linux 2023 AMI
data "aws_ami" "amazon_linux" {
  most_recent = true
  owners      = ["amazon"]

  filter {
    name   = "name"
    values = ["al2023-ami-*-x86_64"]
  }

  filter {
    name   = "virtualization-type"
    values = ["hvm"]
  }
}

# Use it in a resource
resource "aws_instance" "web" {
  ami           = data.aws_ami.amazon_linux.id
  instance_type = "t3.micro"
}

# Look up an existing VPC by tag
data "aws_vpc" "existing" {
  filter {
    name   = "tag:Name"
    values = ["production-vpc"]
  }
}

# Reference: data.aws_vpc.existing.id
Key Concept

Data sources are read-only. They never create, modify, or destroy anything. The prefix data. distinguishes them from managed resources in expressions: data.aws_ami.amazon_linux.id vs aws_instance.web.id.

5. Variables

Input variables parameterize your Terraform configuration. Instead of hardcoding values, you define variables and set them at runtime — through CLI flags, environment variables, .tfvars files, or interactive prompts.

Variable Declaration

HCL — variables.tf
variable "environment" {
  description = "Deployment environment (dev, staging, prod)"
  type        = string
  default     = "dev"

  validation {
    condition     = contains(["dev", "staging", "prod"], var.environment)
    error_message = "Environment must be dev, staging, or prod."
  }
}

variable "instance_count" {
  description = "Number of EC2 instances to launch"
  type        = number
  default     = 1
}

variable "allowed_cidrs" {
  description = "CIDR blocks allowed to access the app"
  type        = list(string)
  default     = ["0.0.0.0/0"]
}

variable "db_password" {
  description = "Database master password"
  type        = string
  sensitive   = true   # Hidden in plan/apply output
}

Setting Variables

MethodSyntaxPriority
CLI flag-var="environment=prod"Highest
*.auto.tfvarsAuto-loaded filesHigh
terraform.tfvarsAuto-loaded default fileMedium
Environment variableTF_VAR_environment=prodLow
Default valueIn variable blockLowest
Sensitive Variables

Marking a variable as sensitive = true redacts it from CLI output and logs, but it is still stored in plain text in the state file. Always encrypt your state file at rest and restrict access to it.

6. Outputs

Output values expose information from your Terraform configuration — an instance's public IP, a load balancer's DNS name, or a database's connection string. They appear after terraform apply and can be queried later with terraform output.

HCL — outputs.tf
output "instance_public_ip" {
  description = "Public IP of the web server"
  value       = aws_instance.web.public_ip
}

output "instance_id" {
  description = "EC2 Instance ID"
  value       = aws_instance.web.id
}

output "db_connection_string" {
  description = "Database connection string"
  value       = "postgresql://${aws_db_instance.main.endpoint}/${aws_db_instance.main.db_name}"
  sensitive   = true
}

output "all_instance_ips" {
  description = "IPs of all web instances"
  value       = aws_instance.web[*].public_ip
}
Terminal
# View all outputs
$ terraform output
instance_id        = "i-0abc123def456789"
instance_public_ip = "54.210.33.112"

# Get a single output (useful for scripts)
$ terraform output -raw instance_public_ip
54.210.33.112

# JSON format for programmatic use
$ terraform output -json
Cross-Module Outputs

When using Terraform modules, outputs are the only way to pass data from a child module back to the parent. Think of them as the module's return values.

7. Locals

Local values are named expressions that simplify your configuration. Use them to compute a value once and reference it multiple times — avoiding repetition and making your code easier to maintain.

HCL
locals {
  # Computed name prefix used across many resources
  name_prefix = "${var.project}-${var.environment}"

  # Merged tags: base tags + environment-specific
  common_tags = merge(
    var.base_tags,
    {
      Environment = var.environment
      ManagedBy   = "Terraform"
      DeployedAt  = timestamp()
    }
  )

  # Conditional logic
  is_production = var.environment == "prod"
  instance_type = local.is_production ? "t3.large" : "t3.micro"
}

# Usage: reference with local.name_prefix
resource "aws_instance" "web" {
  instance_type = local.instance_type
  tags          = local.common_tags
}

Locals vs Variables

AspectVariables (var.)Locals (local.)
Set byUser at runtimeConfiguration author
PurposeParameterize from outsideSimplify internal logic
Can reference other valuesNo (only defaults)Yes (variables, resources, data, other locals)
OverridableYes (CLI, tfvars, env)No
When to Use Locals

If a value is computed from other values and should not be set by the user, make it a local. If users should be able to override it, make it a variable. A common pattern: variables for inputs, locals for derived values, outputs for results.

8. Expressions & Functions

HCL supports conditionals, iteration, and over 100 built-in functions. These let you write dynamic configurations without a full programming language.

Conditional Expressions

HCL
# Ternary: condition ? true_val : false_val
instance_type = var.environment == "prod" ? "t3.large" : "t3.micro"

# Conditional resource creation (count trick)
resource "aws_cloudwatch_metric_alarm" "high_cpu" {
  count = var.enable_monitoring ? 1 : 0
  # ... alarm config ...
}

For Expressions

HCL
# Transform a list: produce uppercase names
upper_names = [for name in var.names : upper(name)]

# Filter a list: only items that start with "prod"
prod_items = [for s in var.servers : s if startswith(s, "prod")]

# Transform a map
instance_ids = {for k, v in aws_instance.servers : k => v.id}

Essential Built-in Functions

lookup() MAP

Get a value from a map with a default fallback

lookup(var.amis, var.region, "ami-default")
join() STRING

Concatenate list elements with a separator

join(", ", var.availability_zones)
merge() MAP

Combine multiple maps (later values win)

merge(local.base_tags, { Env = "prod" })
file() FILESYSTEM

Read a file's contents as a string

file("${path.module}/scripts/init.sh")
templatefile() TEMPLATE

Render a template file with variables

templatefile("user_data.tftpl", { port = 8080 })
cidrsubnet() NETWORK

Calculate subnet CIDR blocks from a prefix

cidrsubnet("10.0.0.0/16", 8, 1) # 10.0.1.0/24
Testing Functions

Use terraform console to test expressions and functions interactively. Type any expression and see the result immediately — great for debugging for expressions and complex lookups.

9. Resource Meta-Arguments

Meta-arguments are special arguments available on every resource type. They control how Terraform creates, updates, or manages resources rather than configuring the resource itself.

count — Create Multiple Copies

HCL
resource "aws_instance" "web" {
  count         = 3
  ami           = data.aws_ami.amazon_linux.id
  instance_type = "t3.micro"

  tags = {
    Name = "web-server-${count.index}"  # web-server-0, web-server-1, web-server-2
  }
}

# Reference: aws_instance.web[0].public_ip
# All IPs:   aws_instance.web[*].public_ip

for_each — Create from a Map or Set

HCL
variable "subnets" {
  default = {
    public-a  = { cidr = "10.0.1.0/24", az = "us-east-1a" }
    public-b  = { cidr = "10.0.2.0/24", az = "us-east-1b" }
    private-a = { cidr = "10.0.10.0/24", az = "us-east-1a" }
  }
}

resource "aws_subnet" "this" {
  for_each          = var.subnets
  vpc_id            = aws_vpc.main.id
  cidr_block        = each.value.cidr
  availability_zone = each.value.az

  tags = {
    Name = each.key   # "public-a", "public-b", "private-a"
  }
}

# Reference: aws_subnet.this["public-a"].id

lifecycle — Control Create/Destroy Behavior

HCL
resource "aws_db_instance" "main" {
  engine         = "postgres"
  instance_class = "db.t3.medium"

  lifecycle {
    # Never destroy this resource (even on terraform destroy)
    prevent_destroy = true

    # Don't replace if these change outside Terraform
    ignore_changes = [
      tags,
      engine_version,
    ]

    # Create replacement before destroying old one (zero-downtime)
    create_before_destroy = true
  }
}
count vs for_each

Use count when you need N identical copies. Use for_each when each instance has a unique identity (name, config). With count, removing an item from the middle renumbers everything; with for_each, only the removed key is destroyed.

10. Terraform CLI

The Terraform CLI follows a consistent workflow: initialize, preview, apply, and optionally destroy. Understanding these commands is essential for day-to-day operations.

Core Workflow

init Downloads providers, initializes backend, installs modules. Run once per project (and after adding providers).
plan Compares config vs state. Shows what will be created (+), modified (~), or destroyed (-). No changes are made.
apply Executes the plan. Creates, updates, and destroys real infrastructure. Requires confirmation (or -auto-approve).
destroy Tears down all resources managed by this configuration. Use with extreme caution in production.
Terminal
# Initialize the project
$ terraform init
Initializing provider plugins...
- Installing hashicorp/aws v5.31.0...
Terraform has been successfully initialized!

# Preview changes (dry run)
$ terraform plan
Plan: 3 to add, 0 to change, 0 to destroy.

# Apply changes
$ terraform apply
Do you want to perform these actions?
  Enter a value: yes
Apply complete! Resources: 3 added, 0 changed, 0 destroyed.

# Destroy everything
$ terraform destroy

Additional Commands

terraform fmt FORMAT

Auto-format HCL files to canonical style

$ terraform fmt -recursive
terraform validate CHECK

Check syntax and internal consistency (no API calls)

$ terraform validate
terraform import IMPORT

Bring existing infrastructure under Terraform management

$ terraform import aws_instance.web i-0abc123
terraform state list STATE

List all resources tracked in the state file

$ terraform state list
terraform state show STATE

Show attributes of a specific resource in state

$ terraform state show aws_instance.web
terraform console DEBUG

Interactive REPL for testing expressions

$ terraform console

11. File Structure

Terraform loads all .tf files in the working directory as a single configuration. There are no mandatory filenames, but the community follows strong conventions that make projects instantly navigable.

Project Layout
my-infra/
  main.tf              # Primary resources (VPC, instances, etc.)
  variables.tf         # All input variable declarations
  outputs.tf           # All output value declarations
  providers.tf         # Provider config + required_providers
  data.tf              # Data source lookups
  locals.tf            # Local value definitions
  terraform.tfvars     # Default variable values (auto-loaded)
  prod.tfvars          # Environment-specific overrides
  .terraform.lock.hcl  # Provider version lock file (commit this)
  .terraform/          # Downloaded providers (gitignored)
  terraform.tfstate    # State file (sensitive, use remote backend)

State File Security

The state file contains every attribute of every resource — including passwords, keys, and tokens in plain text. Never commit it to version control. Use a remote backend (S3 + DynamoDB, Terraform Cloud, or GCS) with encryption and access controls.

12. First Project — AWS EC2 with VPC

Time to put everything together. This project creates a VPC, a public subnet, an internet gateway, a security group, and an EC2 instance — all from scratch. Every concept from this module appears here.

providers.tf

HCL — providers.tf
terraform {
  required_version = ">= 1.5.0"

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}

provider "aws" {
  region = var.aws_region
}

variables.tf

HCL — variables.tf
variable "aws_region" {
  description = "AWS region for all resources"
  type        = string
  default     = "us-east-1"
}

variable "project_name" {
  description = "Project name used in resource tags"
  type        = string
  default     = "terraform-lab"
}

variable "instance_type" {
  description = "EC2 instance type"
  type        = string
  default     = "t3.micro"
}

variable "allowed_ssh_cidr" {
  description = "CIDR block allowed for SSH access"
  type        = string
  default     = "0.0.0.0/0"
}

main.tf

HCL — main.tf
# --- Local Values ---
locals {
  common_tags = {
    Project   = var.project_name
    ManagedBy = "Terraform"
  }
}

# --- Data Source: Latest Amazon Linux 2023 AMI ---
data "aws_ami" "amazon_linux" {
  most_recent = true
  owners      = ["amazon"]

  filter {
    name   = "name"
    values = ["al2023-ami-*-x86_64"]
  }
  filter {
    name   = "virtualization-type"
    values = ["hvm"]
  }
}

# --- VPC ---
resource "aws_vpc" "main" {
  cidr_block           = "10.0.0.0/16"
  enable_dns_support   = true
  enable_dns_hostnames = true

  tags = merge(local.common_tags, { Name = "${var.project_name}-vpc" })
}

# --- Public Subnet ---
resource "aws_subnet" "public" {
  vpc_id                  = aws_vpc.main.id
  cidr_block              = "10.0.1.0/24"
  map_public_ip_on_launch = true
  availability_zone       = "${var.aws_region}a"

  tags = merge(local.common_tags, { Name = "${var.project_name}-public" })
}

# --- Internet Gateway ---
resource "aws_internet_gateway" "gw" {
  vpc_id = aws_vpc.main.id

  tags = merge(local.common_tags, { Name = "${var.project_name}-igw" })
}

# --- Route Table ---
resource "aws_route_table" "public" {
  vpc_id = aws_vpc.main.id

  route {
    cidr_block = "0.0.0.0/0"
    gateway_id = aws_internet_gateway.gw.id
  }

  tags = merge(local.common_tags, { Name = "${var.project_name}-public-rt" })
}

resource "aws_route_table_association" "public" {
  subnet_id      = aws_subnet.public.id
  route_table_id = aws_route_table.public.id
}

# --- Security Group ---
resource "aws_security_group" "web" {
  name        = "${var.project_name}-web-sg"
  description = "Allow SSH and HTTP inbound"
  vpc_id      = aws_vpc.main.id

  ingress {
    description = "SSH"
    from_port   = 22
    to_port     = 22
    protocol    = "tcp"
    cidr_blocks = [var.allowed_ssh_cidr]
  }

  ingress {
    description = "HTTP"
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }

  tags = merge(local.common_tags, { Name = "${var.project_name}-web-sg" })
}

# --- EC2 Instance ---
resource "aws_instance" "web" {
  ami                    = data.aws_ami.amazon_linux.id
  instance_type          = var.instance_type
  subnet_id              = aws_subnet.public.id
  vpc_security_group_ids = [aws_security_group.web.id]

  user_data = <<-EOF
    #!/bin/bash
    yum install -y httpd
    echo "<h1>Hello from Terraform</h1>" > /var/www/html/index.html
    systemctl enable httpd
    systemctl start httpd
  EOF

  tags = merge(local.common_tags, { Name = "${var.project_name}-web" })
}
