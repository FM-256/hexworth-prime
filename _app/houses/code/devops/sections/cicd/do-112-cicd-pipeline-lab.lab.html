Scaffold the Workflow

Create the workflow file with the trigger, job definition, and initial steps: checkout the code and set up Node.js.

What You Are Adding

  • Workflow name and on trigger (push to main, pull_request)
  • A ci job running on ubuntu-latest
  • actions/checkout@v4 step
  • actions/setup-node@v4 with Node 20
  • npm ci to install dependencies
Tip

YAML indentation matters. Use 2 spaces per level. The on key defines when the workflow fires. Jobs contain steps, and each step uses either run (shell command) or uses (action reference).

Phase 4 of 5

Deployment Job

Add a separate deploy job that depends on CI, uses environment protection rules, downloads the build artifact, and deploys with OIDC authentication.

What You Are Adding

  • New deploy job with needs: ci
  • Conditional: only runs on push to main (if expression)
  • Environment: production
  • OIDC permissions: id-token: write
  • Download artifact and deploy step
Important

The deploy job is a separate job, not steps in the CI job. It uses needs: ci to wait for CI to pass. The environment: production key enables GitHub's environment protection rules (approvals, wait timers). OIDC via id-token: write replaces long-lived secrets.

.github/workflows/ci-cd.yml (deploy job) Pending

Hint

Key fields: needs: ci, if: github.ref == 'refs/heads/main' && github.event_name == 'push', runs-on: ubuntu-latest, environment: production. Permissions: id-token: write and contents: read. Steps: actions/download-artifact@v4 with name: build-output, then a deploy run step like echo "Deploying to production...".

Phase 5 of 5

Notification Step

Add a Slack notification step to the deploy job that reports success or failure using a webhook.

What You Are Adding

  • Notification step using if: always() so it runs on success or failure
  • Slack webhook via curl POST request
  • Dynamic message using ${{ job.status }}
  • Webhook URL from secrets: ${{ secrets.SLACK_WEBHOOK_URL }}
Tip

The if: always() condition ensures the notification fires even if a previous step failed. Use curl to POST a JSON payload to the Slack webhook URL. Reference ${{ job.status }} in the message body to indicate pass/fail.

Hint

Use if: always(). The run command should be a curl POST: curl -X POST -H 'Content-type: application/json' --data '{"text":"Deploy ${{ job.status }} for ${{ github.repository }}"}' ${{ secrets.SLACK_WEBHOOK_URL }}
