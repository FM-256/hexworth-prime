1. Docker Aliases & Shell Functions

Typing docker container ls --all --format '{{.Names}}' fifty times a day is wasteful. A tuned alias file turns Docker into a rapid-fire CLI.

~/.bashrc or ~/.zshrc
# Core shortcuts
alias d='docker'
alias dc='docker compose'
alias dps='docker ps --format "table {{.ID}}\t{{.Names}}\t{{.Status}}\t{{.Ports}}"'
alias dpsa='docker ps -a --format "table {{.ID}}\t{{.Names}}\t{{.Status}}\t{{.Image}}"'
alias di='docker images --format "table {{.Repository}}\t{{.Tag}}\t{{.Size}}"'
alias dl='docker logs -f'
alias dex='docker exec -it'
alias dstop='docker stop $(docker ps -q)'
alias dsize='docker system df -v'

# Power functions
dsh() { docker exec -it "$1" /bin/sh -c "[ -x /bin/bash ] && exec /bin/bash || exec /bin/sh"; }
dip() { docker inspect -f '{{range.NetworkSettings.Networks}}{{.IPAddress}}{{end}}' "$1"; }
dlog() { docker logs --tail="${2:-100}" -f --timestamps "$1"; }
drun() { docker run --rm -it "$@"; }
Key Concept

The dsh function tries /bin/bash first and falls back to /bin/sh. This works on Alpine (no bash) and Debian/Ubuntu images alike.

2. Cleanup Commands

Docker hoards disk space. Stopped containers, dangling images, unused volumes, and build cache all accumulate silently. A production server can lose tens of gigabytes before anyone notices.

Terminal
# Nuclear option: remove EVERYTHING unused
$ docker system prune -a --volumes

Surgical Cleanup

docker image prune IMAGES

Remove dangling images (untagged layers from builds)

$ docker image prune -a --filter "until=72h"
docker container prune CONTAINERS

Remove all stopped containers

$ docker container prune -f
docker volume prune VOLUMES

Remove volumes not attached to containers

$ docker volume prune -f
docker builder prune BUILD CACHE

Clear BuildKit build cache

$ docker builder prune --keep-storage 5GB
Warning: Named Volumes

docker volume prune destroys named volumes not attached to a running container. If you stop a database container and prune, your data is gone. Always check docker volume ls first.

Automated Cleanup Script

docker-cleanup.sh
#!/bin/bash
# Safe weekly cleanup - add to crontab
echo "=== Docker Disk Usage BEFORE ==="
docker system df
docker container prune -f --filter "until=24h"
docker image prune -a -f --filter "until=168h"
docker builder prune -f --filter "until=168h"
echo "=== Docker Disk Usage AFTER ==="
docker system df

3. Docker Contexts

Docker Contexts let you switch between different Docker daemons — local, remote servers, cloud instances — without modifying environment variables. One command swaps your entire Docker target.

Terminal
# Create a context for a remote host
$ docker context create staging \
    --docker "host=ssh://deploy@staging.example.com" \
    --description "Staging server"

# Switch to it - ALL docker commands now hit staging
$ docker context use staging

# Or target a context without switching
$ docker --context production ps

# Switch back
$ docker context use default
How It Works

Contexts store connection details in ~/.docker/contexts/. The SSH transport uses your existing SSH keys — no daemon configuration changes needed on the remote host, just Docker installed and your user in the docker group.

4. BuildKit

BuildKit builds layers in parallel, caches more aggressively, and supports secret mounts and cache mounts. Since Docker 23.0 it is the default, but understanding its features unlocks serious build performance gains.

Cache Mounts

Persist package manager caches between builds instead of re-downloading every dependency each time.

Dockerfile
# syntax=docker/dockerfile:1
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
# Cache npm downloads between builds
RUN --mount=type=cache,target=/root/.npm npm ci --production
COPY . .
CMD ["node", "server.js"]

Secret Mounts

Inject credentials at build time without baking them into image layers. The secret exists only in memory during the RUN instruction.

Dockerfile + Build Command
# In Dockerfile: mount secret file (never stored in layer)
RUN --mount=type=secret,id=pip_conf,target=/etc/pip.conf \
    pip install -r requirements.txt

# Build with the secret
$ docker build --secret id=pip_conf,src=./pip.conf -t myapp .
Never Use Build Args for Secrets

ARG values are stored in image history and visible via docker history. Anyone who pulls your image can extract them. Always use --mount=type=secret for API keys, tokens, and credentials.

Inline Cache Export

Terminal
# Export build cache inline with the image (useful for CI)
$ docker build --build-arg BUILDKIT_INLINE_CACHE=1 -t registry.example.com/myapp:latest .

# On next build, pull cache from registry
$ docker build --cache-from registry.example.com/myapp:latest -t registry.example.com/myapp:latest .

5. docker buildx — Multi-Platform Builds

ARM processors power everything from Raspberry Pis to AWS Graviton to Apple Silicon. docker buildx builds for multiple platforms from a single machine.

Terminal
# Create a multi-platform builder
$ docker buildx create --name multiarch --use
$ docker buildx inspect --bootstrap
Platforms: linux/amd64, linux/arm64, linux/arm/v7, linux/386

# Build and push for amd64 + arm64
$ docker buildx build \
    --platform linux/amd64,linux/arm64 \
    -t registry.example.com/myapp:latest \
    --push .

# Build for local use (single platform only)
$ docker buildx build --platform linux/amd64 --load -t myapp:latest .
FlagPurpose
--platformComma-separated target platforms
--pushPush multi-platform manifest to registry
--loadLoad into local Docker (single platform only)
--cache-toExport build cache to registry or directory
QEMU Emulation

Building for a foreign architecture (arm64 on amd64) uses QEMU emulation — automatic but slower. For production CI, use native ARM runners or append remote builders via docker buildx create --append.

6. Debugging Containers

When a container misbehaves, you need to get inside, inspect state, and figure out what went wrong.

Terminal
# Shell into a running container
$ docker exec -it my-container /bin/bash

# Run as root even if container uses non-root user
$ docker exec -u 0 -it my-container /bin/bash

# Copy files out of a container (works on stopped containers too)
$ docker cp my-container:/var/log/app.log ./app.log

# See filesystem changes since container started (A=Added, C=Changed, D=Deleted)
$ docker diff my-container
C /var/log
A /var/log/app.log
D /etc/app/old-config.conf

nsenter — When There Is No Shell

Distroless and scratch-based images have no shell. nsenter enters the container's Linux namespaces from the host.

Terminal
# Get the container's PID on the host
$ PID=$(docker inspect -f '{{.State.Pid}}' my-container)

# Enter all namespaces
$ sudo nsenter -t $PID -m -u -i -n -p -- /bin/sh

# Enter only the network namespace
$ sudo nsenter -t $PID -n -- ip addr

# Trace syscalls of the main process
$ sudo strace -fp $PID -e trace=network
Debugging Distroless

Google's distroless images have zero shell utilities. Use the :debug tag variant (includes busybox) or nsenter from the host to bypass the limitation entirely.

7. Image Archaeology

When you inherit an image with no Dockerfile, or need to understand why it is 2GB, image archaeology lets you reverse-engineer the layer structure.

Terminal
# See every layer, its command, and size
$ docker history myapp:latest
$ docker history --no-trunc myapp:latest   # Full commands

# Interactive layer explorer (install: brew install dive)
$ dive myapp:latest

# CI mode: fail if image is bloated
$ dive myapp:latest --ci --lowestEfficiency 0.9

# Manual inspection: save and extract layers
$ docker save myapp:latest -o myapp.tar
$ mkdir layers && tar xf myapp.tar -C layers
$ tar tf layers/sha256_abc123/layer.tar
Common Bloat Sources

Package manager caches (apt lists, pip cache), build tools in production images, .git directories copied in, and node_modules dev dependencies. Multi-stage builds eliminate all of these.

8. Docker Compose Tricks

Override Files

Compose automatically merges docker-compose.yml with docker-compose.override.yml. Keep base config separate from dev-specific tweaks.

docker-compose.override.yml (auto-merged in dev)
services:
  api:
    build: .
    volumes:
      - .:/app
      - /app/node_modules
    environment:
      - NODE_ENV=development
      - DEBUG=*

Profiles

Define optional services that only start when explicitly requested — monitoring, debugging, or admin tools.

docker-compose.yml
services:
  api:
    image: myapp:latest
    ports: ["3000:3000"]
  adminer:
    image: adminer
    profiles: ["debug"]
    ports: ["8080:8080"]
  prometheus:
    image: prom/prometheus
    profiles: ["monitoring"]
Terminal
$ docker compose up                          # api only
$ docker compose --profile debug up            # api + adminer
$ docker compose --profile debug --profile monitoring up

YAML Anchors & Aliases

Define a block once with &, reference it everywhere with *. Eliminates duplication across services.

docker-compose.yml
x-common-env: &common-env
  LOG_LEVEL: info
  TZ: UTC
  REDIS_URL: redis://cache:6379

services:
  api:
    image: myapp-api:latest
    environment:
      <<: *common-env
      PORT: "3000"
  worker:
    image: myapp-worker:latest
    environment:
      <<: *common-env
      CONCURRENCY: "4"

9. Performance Tuning

Storage Drivers

DriverFilesystemBest For
overlay2ext4, xfsDefault. Best general performance.
btrfsbtrfsNative snapshots, build-heavy workloads
zfszfsChecksumming, compression

Logging Drivers

The default json-file driver has no size limits. A chatty container can fill a disk in days.

/etc/docker/daemon.json
{
  "log-driver": "json-file",
  "log-opts": { "max-size": "10m", "max-file": "3", "compress": "true" },
  "default-ulimits": {
    "nofile": { "Name": "nofile", "Hard": 65536, "Soft": 65536 }
  }
}
Log Rotation Is Not Default

Out of the box, Docker does NOT limit log file size. Always configure max-size and max-file in daemon config or per-container.

DNS Caching

Containers resolve DNS on every connection. In microservice architectures with heavy inter-service traffic, DNS can become a bottleneck.

/etc/docker/daemon.json (DNS settings)
{
  "dns": ["8.8.8.8", "8.8.4.4"],
  "dns-opts": ["ndots:1", "timeout:2", "attempts:2"]
}
Terminal
# Per-container resource limits
$ docker run --memory 512m --memory-swap 512m --cpus 1.5 --pids-limit 100 myapp:latest

10. Emergency Procedures

Containers hang, the daemon freezes, and disk fills up. These are the break-glass procedures.

Recovering Data from Stopped Containers

Terminal
# Copy data out of a stopped container
$ docker cp dead-container:/app/data ./recovered-data

# If cp fails: commit as image and extract
$ docker commit dead-container rescue-image
$ docker run --rm -v $(pwd):/backup rescue-image cp -r /app/data /backup/

# Last resort: find the filesystem on disk
$ docker inspect dead-container --format '{{.GraphDriver.Data.MergedDir}}'
$ sudo ls /var/lib/docker/overlay2/abc123/merged/app/

Force Removing Stuck Containers

Terminal
$ docker stop my-container                  # SIGTERM, wait 10s, SIGKILL
$ docker kill my-container                  # SIGKILL immediately
$ docker rm -f my-container                  # Force remove even if running

# Container won't die? Kill from the host
$ PID=$(docker inspect -f '{{.State.Pid}}' my-container)
$ sudo kill -9 $PID

Daemon Won't Start

Terminal
# Check daemon logs
$ sudo journalctl -u docker.service --no-pager -n 50

# Validate daemon.json (corrupt JSON is a common cause)
$ sudo python3 -m json.tool /etc/docker/daemon.json

# Disk full? Find largest layers
$ sudo du -sh /var/lib/docker/overlay2/* | sort -rh | head

# Restart containerd + docker
$ sudo systemctl restart containerd && sudo systemctl restart docker
Nuclear Option: rm -rf /var/lib/docker

Deleting the Docker data directory removes ALL containers, images, volumes, and networks. Only use as an absolute last resort after recovering critical data. There is no undo.

Docker Desktop requires a paid subscription for companies with 250+ employees or $10M+ revenue. Several open-source alternatives provide the same experience.

ToolRuntimeKey Features
ColimaDocker / containerdMinimal CLI, fast startup, Lima-based VM. Drop-in replacement.

$ brew install colima docker docker-compose
$ colima start --cpu 4 --memory 8 --disk 60
$ docker ps   # Works exactly the same

$ brew install podman       # or: sudo apt install podman
$ podman machine init && podman machine start

Choosing an Alternative

Simplest Docker replacement: Colima. GUI with Kubernetes: Rancher Desktop. Rootless security: Podman. Best macOS performance: OrbStack.

12. Hidden Features

Environment Variables

VariableEffect
DOCKER_BUILDKIT=1Force BuildKit builder (pre-Docker 23.0)
COMPOSE_PROFILES=debug,monitoringActivate Compose profiles without --profile flags
COMPOSE_PROJECT_NAME=myprojectOverride default project name (affects container naming)
DOCKER_CONTENT_TRUST=1Only pull images with valid signatures
DOCKER_DEFAULT_PLATFORM=linux/amd64Force platform for pulls/runs (useful on Apple Silicon)
DOCKER_HOST=ssh://user@remotePoint CLI at a remote daemon (ephemeral, unlike contexts)

The --init Flag

Containers run your process as PID 1, which must reap zombie processes and handle signals. Most apps are not built for this. --init adds tini as PID 1 to handle it properly.

Terminal
# Without --init: app may ignore SIGTERM, docker stop waits 10s then SIGKILL
# With --init: tini forwards signals properly, clean shutdown
$ docker run --init myapp:latest

# In Compose: add init: true to any service

Health Check Debugging

Terminal
# See health check results and output
$ docker inspect --format '{{json .State.Health}}' my-container | python3 -m json.tool

# Override health check at runtime
$ docker run --health-cmd "curl -f http://localhost:3000/healthz" \
    --health-interval 10s --health-retries 3 myapp:latest

More Hidden Gems

--read-only Mount root filesystem as read-only. Forces you to use volumes for writable paths. Great for security.
--tmpfs Mount RAM-backed filesystem for ephemeral data: --tmpfs /tmp:size=100m
--pid=host Share host PID namespace. See all host processes from inside the container.
docker events Real-time stream of all Docker events. Invaluable for debugging orchestration.
Terminal
# Watch Docker events in real time
$ docker events --format '{{.Time}} {{.Type}} {{.Action}} {{.Actor.Attributes.name}}'

# Hardened read-only container with tmpfs
$ docker run --read-only --tmpfs /tmp:size=50m --init myapp:latest
