The Origin Story
Where Python came from and why it matters.
Created by Guido van Rossum
First released in 1991. Named after Monty Python's Flying Circus, not the snake. Designed to be readable, simple, and fun to write.
Interpreted Language
Python code is executed line by line by an interpreter, not compiled to machine code. This means faster development cycles but slightly slower execution than C or Java.
General Purpose
Web development (Django, Flask), data science (NumPy, Pandas), AI/ML (TensorFlow, PyTorch), automation, scripting, security tools. Python does it all.
Slide 3 of 14
Compiled vs. Interpreted
Understanding how your code actually runs.
Compiled (C, Java, Go)
Source code is translated to machine code BEFORE execution. Faster runtime but requires a compile step. Errors caught at compile time.
Interpreted (Python, JS, Ruby)
Source code is read and executed line by line at runtime. No compile step needed. Errors appear when that line is reached during execution.

Installing Python
Get Python on your system in three steps.
Step 1: Download
Visit python.org and download the latest Python 3 installer for your OS. Always use Python 3 (3.12+ recommended). Python 2 is end of life.
Step 2: Add to PATH
On Windows, check "Add Python to PATH" during installation. This lets you run python from any terminal. On macOS/Linux, Python 3 is usually preinstalled.
Step 3: Verify
Open a terminal and type python --version. You should see Python 3.12.x. If it shows Python 2, try python3 --version instead.
# Verify your installation $ python --version Python 3.12.3 # Or on some systems: $ python3 --version Python 3.12.3
Slide 5 of 14
The Python REPL
Read-Eval-Print Loop -- your interactive Python playground.
The REPL lets you type Python code and see results instantly. It is the fastest way to experiment with new concepts. Think of it as a calculator on steroids.
# Start the REPL by typing 'python' in your terminal $ python Python 3.12.3 (main, Apr 9 2024, 08:09:14) >>> 2 + 2 4 >>> "Hello" + " World" 'Hello World' >>> type(42) <class 'int'> >>> exit() # or Ctrl+D to quit
When to Use the REPL
Quick experiments, testing expressions, checking how a function works, exploring data types. Not for writing programs -- use a script file for that.
The >>> Prompt
The triple arrow is Python's prompt. It means "I'm ready for input." Lines without >>> are output. This convention appears in every Python textbook.

VS Code: Your Python IDE
Professional-grade editor, free and cross-platform.
Install VS Code
Download from code.visualstudio.com. Free for Windows, macOS, Linux. The most popular editor for Python development worldwide.
Python Extension
Open Extensions (Ctrl+Shift+X), search "Python" by Microsoft, click Install. This adds syntax highlighting, IntelliSense, linting, and debugging.
Integrated Terminal
Press Ctrl+` (backtick) to open the built-in terminal. Run your scripts directly: python main.py. No more switching between windows.

Your First Python Program
From empty file to running output in under a minute.
# hello.py -- your very first Python script print("Hello, World!") print("Welcome to the Snake Pit.") print("Python version: 3.12")
1.Create a new file called hello.py in VS Code
2.Type the three print() statements shown above
3.Open the terminal with Ctrl+` and run: python hello.py
4.You should see three lines of output. That is a working program.
Key Insight
A Python file is just a text file with a .py extension. The interpreter reads it top to bottom, executing each line in order. No main() function required, no class boilerplate -- just code.
Slide 8 of 14
The print() Function
Your primary tool for displaying output.
# Basic printing print("Hello") # Hello print("Age:", 25) # Age: 25 print("A", "B", "C") # A B C (space separated) print("A", "B", sep="-") # A-B (custom separator) print("Line 1", end="") # Line 1 (no newline) print() # (blank line)
Multiple Arguments
print() accepts multiple arguments separated by commas. By default it joins them with spaces. Use sep= to change the separator.
The end Parameter
By default, print() adds a newline at the end. Use end="" to suppress it. Use end=" " to end with a space instead.
Slide 9 of 14
The input() Function
Getting data from the user at runtime.
# input() always returns a STRING name = input("Enter your name: ") print("Hello,", name) # To get a number, you must convert the type age_str = input("Enter your age: ") # returns "25" (a string) age = int(age_str) # converts to 25 (an integer) # Or combine in one line: age = int(input("Enter your age: ")) # common pattern
Common Mistake
input() ALWAYS returns a string, even if the user types a number. If you need to do math with it, you must convert it using int() or float(). Forgetting this causes TypeError.
Slide 10 of 14
Comments & Code Readability
Writing code that humans can understand.
# This is a single-line comment -- the interpreter ignores it name = "Alice" # Inline comment: explains this specific line # Multi-line explanation: # This block calculates the user's birth year # based on their current age and the current year. age = 25 birth_year = 2026 - age """ This is a docstring (triple-quoted string). Used to document functions and classes. Not technically a comment, but often used as one. """
Good Comments
Explain WHY, not WHAT. # Convert to Celsius for API requirement is useful. # Subtract 32 is not -- the code already says that.
Bad Comments
# Set x to 5 followed by x = 5 adds nothing. Over-commenting obvious code is noise. Under-commenting complex code is worse.
Slide 11 of 14
Scripts vs. REPL
When to use each and how they differ.
REPL (Interactive Mode)
Type code, see results immediately. Great for quick experiments and testing. Nothing is saved. Every expression result is automatically printed. Start with python in terminal.
Script (File Mode)
Write code in a .py file, run it all at once. Code is saved and reusable. Must use print() to see output. Run with python filename.py in terminal.
Slide 12 of 14
Errors Are Normal
Every programmer makes errors. The key is reading the error message.
# SyntaxError: missing closing quote print("Hello World) File "hello.py", line 1 print("Hello World) ^ SyntaxError: unterminated string literal # NameError: variable not defined print(mesage) NameError: name 'mesage' is not defined # TypeError: wrong operation for the type print("age: " + 25) TypeError: can only concatenate str (not "int") to str
How to Read Error Messages
Python tells you the file name, line number, and error type. Read from the BOTTOM up: the last line is the actual error. The arrow (^) shows where Python got confused. Fix that spot first.
Slide 13 of 14
The Zen of Python
The philosophy embedded in the language itself.
# Type this in the Python REPL >>> import this The Zen of Python, by Tim Peters Beautiful is better than ugly. Explicit is better than implicit. Simple is better than complex. Readability counts. Errors should never pass silently. There should be one obvious way to do it.
Readability Counts
Python is designed to look like pseudocode. Use descriptive variable names, consistent indentation, and clear structure. Your code should read like English.
Simple > Complex
If there is a simpler way to do something, do it that way. Clever one-liners that nobody can read are worse than clear three-liners that everyone understands.
Explicit > Implicit
Say what you mean. Python prefers being clear about what a piece of code does, even if that means more typing. Avoid hidden magic.
