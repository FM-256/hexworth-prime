Multi-Format Parser

Intermediate

What It Does

Extends the log parser to automatically detect and parse JSON-formatted log files in addition to the standard text format. The function checks the file extension and routes to the correct parser — no user input needed.

Why it matters in IT: Real log systems (ELK Stack, Splunk, CloudWatch) ingest multiple formats. Being able to parse both structured JSON and flat-text logs is a core sysadmin skill.

Key Concepts

  • json.loads() and json.JSONDecodeError for safe parsing
  • JSONL (newline-delimited JSON) vs. JSON arrays
  • Fallback parsing with try/except
  • dict.get() with default values
  • File extension detection with .endswith()

Code Breakdown

log_parser.py
def _parse_json_log(filepath): """Parse a JSON-formatted log file (array or JSONL).""" entries = [] with open(filepath, "r") as f: content = f.read().strip() # Attempt 1: Parse as a single JSON array try: data = json.loads(content) if isinstance(data, list): for line_number, item in enumerate(data, start=1): if isinstance(item, dict) and "level" in item: entry = { "timestamp": item.get("timestamp", "N/A"), "level": item.get("level", "UNKNOWN"), "message": item.get("message", ""), "line_number": line_number, } entries.append(entry) return entries except json.JSONDecodeError: pass # Not a valid JSON array -- try JSONL below # Attempt 2: Parse as newline-delimited JSON (JSONL) for line_number, line in enumerate(content.split("\n"), start=1): line = line.strip() if not line: continue try: item = json.loads(line) if isinstance(item, dict) and "level" in item: entry = { "timestamp": item.get("timestamp", "N/A"), "level": item.get("level", "UNKNOWN"), "message": item.get("message", ""), "line_number": line_number, } entries.append(entry) except json.JSONDecodeError: continue return entries

The dispatch in parse_log_file() is simple:

def parse_log_file(filepath): # Detect format by file extension if filepath.lower().endswith(".json"): return _parse_json_log(filepath) else: return _parse_text_log(filepath)

How to Add It

  1. Add import json to the top of log_parser.py
  2. Add the _parse_json_log() function shown above
  3. Update parse_log_file() to check the file extension and call the right parser
  4. Create a test JSON log file in data/ to verify it works

Config Editor

What It Does

Reads, displays, modifies, and writes INI-style configuration files using Python's built-in configparser module. Students can view settings, change values, and save them back to disk — like editing a simplified version of system config files.

Why it matters in IT: INI files are everywhere in IT — php.ini, my.cnf (MySQL), sshd_config (conceptually similar), Windows .inf files, and Python's own setup.cfg.

Key Concepts

  • configparser.ConfigParser() for INI file handling
  • Sections and key-value pairs
  • Reading, modifying, and writing config files
  • Default values and type casting (getint(), getboolean())

Code Breakdown

config_editor.py (new file)
import configparser def load_config(filepath): """Load an INI config file and return the parser object.""" config = configparser.ConfigParser() config.read(filepath) return config def display_config(config): """Print all sections and their key-value pairs.""" for section in config.sections(): print(f"\n[{section}]") for key, value in config[section].items(): print(f" {key} = {value}") def update_config(config, section, key, value): """Update a specific key in a section.""" if not config.has_section(section): config.add_section(section) config[section][key] = value def save_config(config, filepath): """Write the config back to disk.""" with open(filepath, "w") as f: config.write(f)

Log Rotation Detector

Intermediate

What It Does

Monitors log file sizes and automatically detects when a file exceeds a threshold (e.g., 1 MB). When triggered, it renames the current log with a timestamp suffix and creates a fresh empty log file — preventing any single log from growing unbounded.

Why it matters in IT: Log rotation is a critical sysadmin task. Tools like logrotate on Linux do this automatically, but understanding the mechanics teaches file management, disk space monitoring, and operational best practices.

Key Concepts

  • os.path.getsize() for file size checking
  • os.rename() for file rotation
  • format_bytes() for human-readable sizes
  • Timestamp-based file naming
  • Threshold-based triggering

Code Breakdown

log_parser.py (add this function)
import os from datetime import datetime from utils import format_bytes def check_log_rotation(filepath, max_size_bytes=1_048_576): """ Check if a log file exceeds max_size_bytes (default 1 MB). If it does, rotate it by renaming with a timestamp suffix and create a fresh empty file in its place. Returns: tuple: (needs_rotation: bool, file_size: int) """ if not os.path.exists(filepath): return False, 0 file_size = os.path.getsize(filepath) if file_size > max_size_bytes: # Generate a timestamped archive name timestamp = datetime.now().strftime("%Y%m%d_%H%M%S") base, ext = os.path.splitext(filepath) archive_name = f"{base}_{timestamp}{ext}" # Rename current log to the archive name os.rename(filepath, archive_name) # Create a fresh empty log file with open(filepath, "w") as f: f.write("") # Empty file print(f" Log rotated: {format_bytes(file_size)} archived to {archive_name}") return True, file_size return False, file_size

How to Add It

  1. Add the check_log_rotation() function to log_parser.py
  2. Call it at the start of run_log_parser() in main.py before parsing
  3. Report the file size to the user: print(f" Log size: {format_bytes(size)}")

Color-Coded Terminal Output

Beginner

What It Does

Adds colored text output to the terminal using ANSI escape codes. Errors print in red, warnings in yellow, success messages in green. Makes the CLI output scannable at a glance instead of a wall of monochrome text.

Why it matters in IT: Every professional CLI tool uses color coding — ls --color, grep --color, systemd journal output. Understanding ANSI codes is foundational for building usable terminal tools.

Key Concepts

  • ANSI escape codes (\033[91m through \033[96m)
  • Reset code (\033[0m) to return to default colors
  • Dictionary lookup for color mapping
  • dict.get() with a default value for unknown colors

Code Breakdown

utils.py
def colored_print(text, color): """ Print text in a specified color using ANSI escape codes. ANSI codes are special character sequences that terminals interpret as formatting instructions. They start with ESC[ (\\033[) followed by a color code number, and end with \\033[0m to reset formatting. Supported colors: red, green, yellow, blue, magenta, cyan. """ # Map color names to ANSI escape code numbers colors = { "red": "\033[91m", # Bright red -- errors/critical "green": "\033[92m", # Bright green -- success "yellow": "\033[93m", # Bright yellow -- warnings "blue": "\033[94m", # Bright blue -- info "magenta": "\033[95m", # Bright magenta -- highlights "cyan": "\033[96m", # Bright cyan -- titles } # Look up the code; default to empty string if unknown code = colors.get(color.lower(), "") reset = "\033[0m" print(f"{code}{text}{reset}")

How to Add It

  1. Add the colored_print() function to utils.py
  2. Import it in any module: from utils import colored_print
  3. Replace plain print() calls with colored_print(text, "red") for errors, "green" for success, "yellow" for warnings
  4. Use it in the log report to color-code ERROR (yellow) and CRITICAL (red) entries

Search & Filter

Intermediate

What It Does

Adds keyword, severity level, and date-range filtering to the log parser. All three filters are optional and combine with AND logic — an entry must match every specified criterion to appear in results. This is the programmatic equivalent of piping through grep and awk.

Why it matters in IT: During incident response, you need to find specific log entries fast. Filtering by time range ("show me everything from 2 AM to 4 AM") combined with keyword search ("DNS") and severity ("ERROR") is how real SOC analysts triage alerts.

Key Concepts

  • Optional parameters with None defaults
  • List comprehensions for progressive filtering
  • Case-insensitive string matching with .lower()
  • ISO date string comparison (lexicographic ordering works for YYYY-MM-DD)
  • AND logic across multiple filter criteria

Code Breakdown

log_parser.py
def search_logs(entries, keyword=None, level=None, date_range=None): """ Search and filter log entries by keyword, severity, and/or date range. All filters are optional and combine with AND logic. """ results = entries # Start with all entries # Filter by keyword (case-insensitive substring match) if keyword is not None: keyword_lower = keyword.lower() results = [ e for e in results if keyword_lower in e["message"].lower() ] # Filter by severity level (exact match, case-insensitive) if level is not None: level_upper = level.upper() results = [ e for e in results if e["level"].upper() == level_upper ] # Filter by date range (inclusive on both ends) # String comparison works for ISO dates (YYYY-MM-DD) if date_range is not None: start_date, end_date = date_range results = [ e for e in results if start_date <= e["timestamp"][:10] <= end_date ] return results

How to Add It

  1. Add the search_logs() function to log_parser.py
  2. In main.py, add a sub-menu option that prompts for keyword, level, start date, and end date (leave blank to skip any filter)
  3. Build the date_range tuple only if both dates are provided
  4. Display results with color coding based on severity level

Topology Layouts

Advanced

What It Does

Adds five network topology layouts to the Turtle visualization: ring, star, bus, mesh, and hierarchical. Each layout uses trigonometric math to calculate device positions and draws different connection patterns. The user picks a layout from a menu before the window opens.

Why it matters in IT: These are the five fundamental network topologies covered in CompTIA Network+ (N10-009). Understanding how devices connect in each layout is core networking knowledge.

Key Concepts

  • math.cos(), math.sin(), math.tau for circular positioning
  • Dispatch tables (dictionary of functions) instead of if/elif chains
  • Separation of layout calculation from drawing logic
  • Three-tier hierarchical model (Cisco architecture)

Code Breakdown

Each layout function returns (positions, connections) — a list of (x, y) tuples and a list of (i, j) index pairs. Here are the ring and star layouts:

network_viz.py
def _ring_layout(devices, cx, cy, radius): """Devices arranged in a circle, each connected to neighbors.""" n = len(devices) positions = [] for i in range(n): # Distribute evenly around the circle # Subtract pi/2 to start at 12 o'clock position angle = (math.tau * i / n) - math.pi / 2 x = cx + radius * math.cos(angle) y = cy + radius * math.sin(angle) positions.append((x, y)) # Connect each device to the next, wrapping last to first connections = [(i, (i + 1) % n) for i in range(n)] return positions, connections def _star_layout(devices, cx, cy, radius): """Central hub (first router) with all others radiating outward.""" n = len(devices) # Find the first router to use as the center hub center_idx = 0 for i, d in enumerate(devices): if d.device_type.lower() == "router": center_idx = i break # Center device at origin, others distributed around circle positions = [None] * n positions[center_idx] = (cx, cy) ordered = [i for i in range(n) if i != center_idx] for pos_idx, dev_idx in enumerate(ordered): angle = (math.tau * pos_idx / max(len(ordered), 1)) - math.pi / 2 positions[dev_idx] = (cx + radius * math.cos(angle), cy + radius * math.sin(angle)) # All outer devices connect to center only connections = [(center_idx, i) for i in ordered] return positions, connections

The dispatch table in visualize_topology():

# Dispatch table maps layout name to function layout_functions = { "ring": _ring_layout, "star": _star_layout, "bus": _bus_layout, "mesh": _mesh_layout, "hierarchical": _hierarchical_layout, } # Look up the function, defaulting to ring if unknown layout_func = layout_functions.get(layout.lower(), _ring_layout) positions, connections = layout_func(devices, cx, cy, radius)

How to Add It

  1. Add import math to network_viz.py
  2. Implement all five layout functions (_ring_layout, _star_layout, _bus_layout, _mesh_layout, _hierarchical_layout)
  3. Add the dispatch table in visualize_topology()
  4. In main.py, add a layout selection menu before calling visualize_topology()

Why it matters in IT: Network monitoring dashboards (Nagios, PRTG, Zabbix) use visual indicators to show device health at a glance. Blinking/color-coded status is the universal language of NOC (Network Operations Center) displays.

Key Concepts

  • State toggling with boolean flags
  • Non-blocking animation (never use time.sleep() in GUI code)
  • Color cycling based on device status

Code Breakdown

network_viz.py (add to visualize_topology)
def _animate_status(t, screen, devices, positions): """Blink device indicators based on online/offline status.""" blink_state = [True] # Mutable so nested function can toggle def _tick(): for i, device in enumerate(devices): x, y = positions[i] t.penup() t.goto(x, y - 30) # Small indicator below device t.pendown() if device.status.lower() == "offline": # Offline: blink red/dark color = "#F44336" if blink_state[0] else "#424242" else: # Online: steady green color = "#4CAF50" t.fillcolor(color) t.begin_fill() t.circle(5) t.end_fill() blink_state[0] = not blink_state[0] # Toggle screen.ontimer(_tick, 800) # Schedule next tick in 800ms _tick() # Start the animation loop

JSON Persistence

Intermediate

What It Does

Adds save_to_json() and load_from_json() methods to DeviceInventory so the device list persists between sessions. Each device is serialized using its to_dict() method, and the correct subclass is instantiated when loading back via a TYPE_MAP dictionary.

Why it matters in IT: JSON is the dominant data format for APIs, configuration, and persistence in modern IT. Understanding serialization (object to JSON) and deserialization (JSON to object) is essential for any developer or sysadmin.

Key Concepts

  • json.dump() with indent=2 for human-readable output
  • json.load() for reading JSON files
  • Serialization via to_dict() methods on each class
  • Factory pattern using a TYPE_MAP dictionary to instantiate the right subclass
  • List comprehension: [d.to_dict() for d in self.devices]

Code Breakdown

device_manager.py — add to DeviceInventory class
import json class DeviceInventory: # Map of type strings to subclasses for deserialization TYPE_MAP = { "router": Router, "switch": Switch, "firewall": Firewall, "server": Server, "access_point": AccessPoint, "load_balancer": LoadBalancer, } def save_to_json(self, path): """Save all devices to a JSON file.""" data = [device.to_dict() for device in self.devices] with open(path, "w") as f: json.dump(data, f, indent=2) return len(data) def load_from_json(self, path): """Load devices from a JSON file, instantiating correct subclasses.""" with open(path, "r") as f: data = json.load(f) count = 0 for item in data: name = item.get("name", "unknown") ip = item.get("ip", "0.0.0.0") dtype = item.get("type", "unknown").lower() status = item.get("status", "online").lower() # Look up the correct subclass device_class = self.TYPE_MAP.get(dtype) if device_class is not None: device = device_class(name, ip, status) else: device = Device(name, ip, dtype, status) self.devices.append(device) count += 1 return count

How to Add It

  1. Add import json to device_manager.py
  2. Add TYPE_MAP, save_to_json(), and load_from_json() to DeviceInventory
  3. Make sure every subclass has a to_dict() method that calls super().to_dict() and adds its own fields
  4. Add "Save to JSON" and "Load from JSON" options in main.py

Why it matters in IT: Network uptime is the single most important metric for IT operations. SLAs (Service Level Agreements) are built around uptime percentages (99.9% = "three nines"). Subnet breakdowns help identify overloaded segments.

Key Concepts

  • sum() with a generator expression for counting
  • Dictionary accumulators: dict.get(key, 0) + 1
  • IP subnet extraction with split(".") and join()
  • Percentage calculation with round()
  • Handling empty collections gracefully

Code Breakdown

device_manager.py — add to DeviceInventory class
def get_statistics(self): """Compute uptime %, type counts, and subnet breakdown.""" total = len(self.devices) if total == 0: return {"total": 0, "online": 0, "offline": 0, "uptime_percent": 0.0, "type_counts": {}, "subnet_counts": {}} # Count online devices online = sum(1 for d in self.devices if d.status.lower() == "online") offline = total - online uptime_percent = round((online / total) * 100, 2) # Count devices per type type_counts = {} for d in self.devices: dtype = d.device_type.lower() type_counts[dtype] = type_counts.get(dtype, 0) + 1 # Count devices per subnet (first 3 octets) subnet_counts = {} for d in self.devices: parts = d.ip.split(".") if len(parts) == 4: subnet = ".".join(parts[:3]) subnet_counts[subnet] = subnet_counts.get(subnet, 0) + 1 return { "total": total, "online": online, "offline": offline, "uptime_percent": uptime_percent, "type_counts": type_counts, "subnet_counts": subnet_counts, }

Inheritance Depth

Intermediate

What It Does

Adds three new device subclasses — Server, AccessPoint, and LoadBalancer — each with unique attributes beyond the base Device class. Demonstrates how inheritance lets you extend a base class without duplicating code, using super().__init__() and method overriding.

Why it matters in IT: Real networks have diverse device types. Modeling them with inheritance mirrors how enterprise DCIM (Data Center Infrastructure Management) systems work — a common base with specialized attributes per device category.

Key Concepts

  • super().__init__() to call the parent constructor
  • Method overriding (__str__, to_dict)
  • Calling super().method() inside an override to extend (not replace)
  • IS-A relationship: a Server IS-A Device
  • DRY principle: shared code in the base class, specifics in subclasses

Code Breakdown

device_manager.py
class Server(Device): """Server with role, CPU cores, and RAM.""" def __init__(self, name, ip, status="online", role="general", cpu_cores=4, ram_gb=16): super().__init__(name, ip, "server", status) self.role = role self.cpu_cores = cpu_cores self.ram_gb = ram_gb def __str__(self): base = super().__str__() return f"{base} role={self.role} cpu={self.cpu_cores} ram={self.ram_gb}GB" def to_dict(self): d = super().to_dict() d["role"] = self.role d["cpu_cores"] = self.cpu_cores d["ram_gb"] = self.ram_gb return d class AccessPoint(Device): """Wireless AP with SSID, channel, and client count.""" def __init__(self, name, ip, status="online", ssid="Default", channel=6, clients=0): super().__init__(name, ip, "access_point", status) self.ssid = ssid self.channel = channel self.clients = clients def __str__(self): base = super().__str__() return f"{base} ssid={self.ssid} ch={self.channel} clients={self.clients}" def to_dict(self): d = super().to_dict() d["ssid"] = self.ssid d["channel"] = self.channel d["clients"] = self.clients return d class LoadBalancer(Device): """Load balancer with algorithm, backend count, connections.""" def __init__(self, name, ip, status="online", algorithm="round-robin", backend_count=2, active_connections=0): super().__init__(name, ip, "load_balancer", status) self.algorithm = algorithm self.backend_count = backend_count self.active_connections = active_connections def __str__(self): base = super().__str__() return (f"{base} algo={self.algorithm} " f"backends={self.backend_count} " f"conns={self.active_connections}") def to_dict(self): d = super().to_dict() d["algorithm"] = self.algorithm d["backend_count"] = self.backend_count d["active_connections"] = self.active_connections return d

How to Add It

  1. Add the three subclass definitions after the existing Firewall class
  2. Update the TYPE_MAP dictionary in DeviceInventory to include the new types
  3. Update the "Add device" menu in main.py to list the new types
  4. Import the new classes in main.py: from device_manager import Server, AccessPoint, LoadBalancer

What It Does

Adds a full subnet calculator as a new tab in the GUI. Enter an IP address and CIDR prefix length, and it calculates network address, broadcast address, subnet mask, wildcard mask, usable host range, and total usable hosts — all using pure bitwise arithmetic.

Key Concepts

  • Bitwise operations: & (AND), | (OR), ~ (NOT), << (shift)
  • 32-bit integer representation of IPv4 addresses
  • Subnet mask creation: (0xFFFFFFFF << (32 - prefix)) & 0xFFFFFFFF
  • Network address = IP AND mask
  • Broadcast = network OR (NOT mask)
  • Usable hosts = 2^(32-prefix) - 2

def _calculate_subnet(self): """Perform subnet calculation using bitwise arithmetic.""" ip_str = self.subnet_ip_var.get().strip() cidr_str = self.subnet_cidr_var.get().strip() # Validate inputs if not validate_ip(ip_str): messagebox.showwarning("Invalid IP", f"'{ip_str}' is not valid.") return prefix = int(cidr_str) if prefix < 0 or prefix > 32: messagebox.showwarning("Invalid CIDR", "Prefix must be 0-32.") return # Convert IP to 32-bit integer # "192.168.1.100" -> [192, 168, 1, 100] -> 0xC0A80164 octets = [int(o) for o in ip_str.split(".")] ip_int = (octets[0] << 24) | (octets[1] << 16) | (octets[2] << 8) | octets[3] # Create subnet mask if prefix == 0: mask_int = 0 else: mask_int = (0xFFFFFFFF << (32 - prefix)) & 0xFFFFFFFF # Derived addresses network_int = ip_int & mask_int # Zero out host bits wildcard_int = ~mask_int & 0xFFFFFFFF # Inverse of mask broadcast_int = network_int | wildcard_int # All host bits = 1 first_usable_int = network_int + 1 last_usable_int = broadcast_int - 1 # Usable hosts host_bits = 32 - prefix usable_hosts = (2 ** host_bits) - 2 if host_bits >= 2 else 0 # Convert 32-bit integer back to dotted decimal def int_to_ip(n): return (f"{(n >> 24) & 0xFF}." f"{(n >> 16) & 0xFF}." f"{(n >> 8) & 0xFF}." f"{n & 0xFF}") # Display results results = ( f" Input: {ip_str}/{prefix}\n" f" {'=' * 45}\n" f" Network Address: {int_to_ip(network_int)}\n" f" Broadcast: {int_to_ip(broadcast_int)}\n" f" Subnet Mask: {int_to_ip(mask_int)}\n" f" Wildcard Mask: {int_to_ip(wildcard_int)}\n" f" {'=' * 45}\n" f" First Usable: {int_to_ip(first_usable_int)}\n" f" Last Usable: {int_to_ip(last_usable_int)}\n" f" Usable Hosts: {usable_hosts:,}\n" f" {'=' * 45}\n" f" CIDR Notation: {int_to_ip(network_int)}/{prefix}\n" )
