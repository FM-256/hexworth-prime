What Is Control Flow?
By default, Python runs every line from top to bottom -- exactly once. Control flow changes that.
Default: Top to Bottom
Without control flow, every line executes in order, no matter what. Line 1, line 2, line 3... to the end. This works for simple scripts, but real programs need to make decisions.
Conditionals: Make Decisions
An if statement checks a condition and runs a block of code only when that condition is True. Today's entire topic. Programs without decisions are just calculators.
Loops: Repeat Actions
A for or while loop runs a block of code multiple times. Day 3 topic. Loops and conditionals together are the backbone of every real program.
Real life example: IF the traffic light is red, THEN stop. ELSE go. That is a conditional. Your car does not check the speed limit, calculate fuel, and play music before deciding to stop -- it checks one condition and takes one of two actions. Python conditionals work exactly the same way.
Why This Matters for IT
Every system you will ever work with is controlled by conditionals. Firewalls use them to allow or deny traffic. Monitoring scripts use them to decide when to alert. Login systems use them to verify credentials. If you understand conditionals, you understand how software makes decisions.

Comparison Operators

All of these return True or False.

The if Statement: Syntax
Three rules. Break any one of them and Python will refuse to run your code.
Rule 1: The Keyword
Start with the keyword if (lowercase). Then write your condition. Then a colon. The colon is not optional -- it tells Python that a code block is starting.
Rule 2: The Colon
The colon : at the end of the if line is mandatory. If you forget it, Python raises a SyntaxError immediately. Every if, elif, and else line ends with a colon.
Rule 3: Indentation
Everything inside the if block must be indented by exactly 4 spaces. This is how Python knows what belongs inside the block. No curly braces like JavaScript or C. Indentation IS the structure.
WRONG: Missing colon
if age >= 18 print("Adult") # SyntaxError: expected ':'
WRONG: Missing indentation
if age >= 18: print("Adult") # IndentationError: expected an indented block
# CORRECT: keyword + condition + colon + indented body if age >= 18: print("You can vote") # 4 spaces before print print("You can sign contracts") # still inside the if block
Editor tip: Set your editor to insert 4 spaces when you press Tab. In VS Code: File > Preferences > Settings, search "Tab Size", set to 4. Also enable "Insert Spaces" so you are never mixing tabs and spaces.
Slide 5 of 34
The if Statement: Examples
The body of an if block can be one line or twenty. Every line in the body must be indented.
Single-Line Body
The simplest case: one condition, one action. The body is a single indented line. If the condition is False, that line is silently skipped and execution continues below the if block.
Multi-Line Body
All lines indented at the same level belong to the same block. You can have as many lines as needed. The block ends when indentation returns to the level of the if keyword.
# Single-line body if age >= 18: print("You can vote") # Multi-line body -- all three lines are inside the if block temperature = 103.7 if temperature > 100: print("WARNING: Server overheating!") print(f"Current temperature: {temperature} degrees F") print("Shutting down non-essential services...") # This line is NOT inside the if block -- indentation is back to column 0 print("Temperature check complete")
Walk through: temperature is 103.7. Is 103.7 > 100? Yes. All three print statements run. Then execution drops out of the block and prints "Temperature check complete." Now change temperature to 98.6 -- the if body is skipped entirely, only the last print runs.
Slide 6 of 34
if / else: Two Paths
An if block runs when the condition is True. The else block runs when it is False. One or the other -- never both.
How else Works
else has no condition of its own. It is the catch-all that runs when the if condition is False. It must follow the if block with no gap, and it ends with a colon just like if.
Exactly One Path Runs
The if/else guarantees exactly one of the two blocks will run. Never zero. Never both. This makes it perfect for binary decisions: allowed or denied, found or not found, valid or invalid.
# Syntax: if condition runs when True, else runs when False if condition: # this block runs when condition is True print("Condition was True") else: # this block runs when condition is False print("Condition was False") # Practical example: even or odd check number = 7 if number % 2 == 0: print(f"{number} is even") else: print(f"{number} is odd") # Output: 7 is odd # The modulo operator % gives the remainder after division # 7 % 2 = 1, which is not 0, so the else block runs
Slide 7 of 34
if / else: IT Example
Disk space monitoring -- a script that runs on every server in your environment every 5 minutes.
The Problem
A server with a full disk stops writing logs, stops accepting uploads, and may crash services. A monitoring script checks free space and takes action before that happens. The threshold is 5 GB -- below that, alert.
Walk Through Both Paths
When free_gb = 4.2: is 4.2 < 5? Yes. The if block runs -- warning prints. When free_gb = 12.0: is 12.0 < 5? No. The else block runs -- OK message prints. Both paths are always covered.
# Disk space check -- runs on each monitored server free_gb = 4.2 threshold_gb = 5 server_name = "web-prod-01" if free_gb < threshold_gb: print(f"WARNING: Low disk space on {server_name}") print(f"Only {free_gb} GB remaining -- threshold is {threshold_gb} GB") print("Creating ServiceNow ticket...") else: print(f"OK: {server_name} has {free_gb} GB free") # Output with free_gb = 4.2: # WARNING: Low disk space on web-prod-01 # Only 4.2 GB remaining -- threshold is 5 GB # Creating ServiceNow ticket...
Real-world context: This exact pattern runs in Nagios, Zabbix, Datadog, and every other monitoring platform. The platform collects the metric, your script checks it against a threshold, and it triggers an action. You just wrote the core of a monitoring agent.
Slide 8 of 34
if / elif / else: Multiple Branches
When two paths are not enough. elif adds as many branches as you need.
What elif Means
elif is Python's shorthand for "else if." It adds an additional condition to check only if all previous conditions were False. You can chain as many elif blocks as needed.
Top to Bottom, First Match Wins
Python checks the if first. If False, it checks the first elif. If False, the next elif. It stops at the first True condition. The remaining conditions are never evaluated.
else Is Optional
The final else catches everything that did not match any condition above. It is optional -- if you leave it out and nothing matches, the entire chain is skipped silently. Include it when you need a guaranteed action.
# Full if/elif/else structure if condition1: # runs if condition1 is True elif condition2: # runs if condition1 is False AND condition2 is True elif condition3: # runs if condition1 and condition2 are False AND condition3 is True else: # runs if NONE of the conditions above were True # Key point: Python stops at the FIRST match # If condition1 is True, condition2 and condition3 are never checked

if / elif / else: Grade Calculator
A complete working example. Walk through it line by line with score = 85.
# Grade calculator -- converts a numeric score to a letter grade score = int(input("Enter your score (0-100): ")) if score >= 90: grade = "A" elif score >= 80: grade = "B" elif score >= 70: grade = "C" elif score >= 60: grade = "D" else: grade = "F" print(f"Score: {score} | Grade: {grade}")
Walk Through with score = 85
Is 85 >= 90? No. Move to next.
Is 85 >= 80? Yes! Assign "B". Stop.
The >= 70 and >= 60 checks never run.
Output: Score: 85 | Grade: B
Why Not Grade "C" Too?
85 is also >= 70 and >= 60. But Python stopped at the first True match (>= 80). That is why the output is B, not C. This "stop at first match" behavior is exactly what you want for mutually exclusive categories.
Slide 11 of 34
Order Matters
The order you write your elif conditions determines which one wins. Wrong order, wrong output.
WRONG ORDER -- broken grade calculator
score = 95 if score >= 60: # matches FIRST! grade = "D" elif score >= 70: grade = "C" # never reached elif score >= 80: grade = "B" # never reached elif score >= 90: grade = "A" # never reached # Output: D -- a 95 gets a D!
CORRECT ORDER -- most restrictive first
score = 95 if score >= 90: # checks highest first grade = "A" # matches! stops here elif score >= 80: grade = "B" elif score >= 70: grade = "C" elif score >= 60: grade = "D" # Output: A -- correct
The Rule
When conditions overlap (a score of 95 is >= 90, and also >= 80, and also >= 70), always check from most specific to least specific. For ranges that go up, check highest first. For ranges that go down, check lowest first. Draw out your ranges on paper before you code them if you are unsure.
Slide 12 of 34
Logical Operators in Conditionals
Combine multiple conditions into one expression using and, or, and not.
and: Both Must Be True
condition1 and condition2 is True only when BOTH sides are True. If the left side is False, Python does not even check the right side (short-circuit). Use and when all requirements must be met simultaneously.
or: At Least One Must Be True
condition1 or condition2 is True when EITHER side is True. If the left side is True, Python skips the right side. Use or when any one of several conditions is sufficient.
not: Flip the Result
not condition reverses the boolean. If the condition is True, not makes it False. If False, not makes it True. Use not to check that something is absent or disabled.
# and: user must be 18 AND have a valid ID if age >= 18 and has_id: print("Entry allowed") # or: either condition qualifies for the weekend discount if day == "Saturday" or day == "Sunday": print("Weekend discount applied") # not: redirect to login page if the user is NOT logged in if not logged_in: print("Redirecting to /login")

Combining Conditions: IT Examples
Real scenarios where you need more than one condition at once.
# Network access control: all three conditions must be met is_employee = True has_vpn = True is_suspended = False if is_employee and has_vpn and not is_suspended: print("Access granted to internal network") else: print("Access denied") # Port number validation: reject anything outside the valid range port = int(input("Enter port number: ")) if port < 1 or port > 65535: print(f"Error: {port} is not a valid port number") print("Valid range is 1 through 65535") else: print(f"Port {port} is valid")
Access Control Pattern
This is the exact logic used in network access control lists (ACLs), VPN gateway policies, and Zero Trust architectures. Employee? VPN connected? Account active? All three must be True. Any one failure denies access.
Range Validation Pattern
The port check uses or because either extreme is invalid. A port below 1 OR above 65535 should be rejected. The valid middle range is automatically the else case. This pattern applies to IP addresses, subnet masks, timeout values, and more.
Slide 14 of 34
Nested if Statements
An if inside another if. Use when the second decision only makes sense after the first one passes.
When to Nest
Nest when decisions depend on each other. You cannot check someone's password if you have not confirmed the account exists. You cannot check admin privileges if the user is not authenticated. The second check is only meaningful inside the first.
Indentation Doubles
Each level of nesting adds another 4 spaces of indentation. The outer if body is at 4 spaces. The inner if body is at 8 spaces. The inner else is at 4 spaces (same level as inner if). Count your spaces carefully.
# Login system: check account exists, then check password has_account = True password_correct = False if has_account: # We are now inside the outer if block (4 spaces) if password_correct: # Inside both the outer and inner if (8 spaces) print("Login successful -- welcome back!") else: # Inside the outer if, but in the inner else (8 spaces) print("Incorrect password -- try again") else: # Outside the account check entirely (0 spaces from outer else) print("Account not found -- please register") # Output: Incorrect password -- try again
Slide 15 of 34
Nested vs Flat: A Comparison
Deep nesting is hard to read, hard to debug, and hard to maintain. Prefer flat when you can.
NESTED -- hard to read at 3+ levels
if a: if b: if c: do_thing() else: print("c failed") else: print("b failed") else: print("a failed")
FLAT -- easier to read and debug
if not a: print("a failed") elif not b: print("b failed") elif not c: print("c failed") else: do_thing()
The Guard Clause Pattern
The flat version uses a technique called "early exit" or "guard clauses." Instead of nesting deeper for the happy path, you check failure conditions early and exit (or print an error). The successful case falls through to the end. This is the professional Python style -- most linters flag nesting beyond 3 levels.
Rule of thumb: If your code is indented more than 3 levels (12+ spaces from column 0), consider whether you can flatten it with and, use elif, or extract the inner logic into a separate function.
Slide 16 of 34
Ternary Expression: Inline if
A one-line shorthand for simple if/else assignments. Useful, but only for simple cases.
The Syntax
value = result_if_true if condition else result_if_false

Read it left to right: "Set value to result_if_true IF condition ELSE result_if_false." The condition goes in the middle, not at the start.
When to Use It
Use the ternary only for simple variable assignments where both outcomes are short. Never cram complex logic into a ternary. If it takes more than a few seconds to read, write the full if/else instead. Readability beats brevity.
# Ternary syntax: value = result_if_true if condition else result_if_false age = 20 status = "Adult" if age >= 18 else "Minor" print(status) # Adult # The full if/else equivalent -- same logic, more lines if age >= 18: status = "Adult" else: status = "Minor" # IT example: label a service as healthy or degraded response_ms = 340 health_label = "healthy" if response_ms < 200 else "degraded" print(f"API service status: {health_label}") # Output: API service status: degraded
Slide 17 of 34
match / case: Pattern Matching
Python 3.10 introduced match/case -- a cleaner way to write multi-branch conditionals against known values.
When to Use match/case
Use match when you are comparing a single value against a fixed set of known options. It is cleaner than a long if/elif/elif/elif chain when every branch checks the same variable. Requires Python 3.10 or later.
The Wildcard: _
The underscore _ is the wildcard pattern. It matches anything that did not match an earlier case. It behaves like the else in an if/elif/else chain. Always put it last.
# match/case: server management command dispatcher command = input("Enter command (start/stop/restart/status): ") match command: case "start": print("Starting all services...") case "stop": print("Stopping all services...") case "restart": print("Restarting services -- this takes 30 seconds") case "status": print("Checking service status...") case _: print(f"Unknown command: '{command}'") print("Valid commands: start, stop, restart, status")
Version check: Run python3 --version in your terminal. If you see 3.10 or higher, you can use match. If you see 3.9 or lower, use if/elif/else instead. Most school systems running Python 3.12 support match/case.

Truthy and Falsy Values
In Python, every value has a boolean interpretation. You do not always need == to check a condition.
Falsy Values (evaluate to False)
False -- the boolean False
0 and 0.0 -- zero integers and floats
"" -- empty string
None -- the absence of a value
[] -- empty list
{} -- empty dictionary
() -- empty tuple
Truthy Values (evaluate to True)
Everything that is NOT in the falsy list.
1, -1, 3.14 -- any non-zero number
"hello" -- any non-empty string
[1, 2, 3] -- any non-empty list
Any object that has not defined __bool__ to return False.
# Truthy/falsy in practice -- Python idiom username = input("Enter username: ") if username: # shorthand for: if username != "" print(f"Hello, {username}!") else: print("No username entered") failed_attempts = 0 if failed_attempts: # shorthand for: if failed_attempts != 0 print(f"Warning: {failed_attempts} failed login attempts") else: print("No failed attempts recorded") # Output: No failed attempts recorded (0 is falsy)
Why this matters: You will see this pattern everywhere in professional Python code. if username: is cleaner and more Pythonic than if username != "":. Both work, but the shorter form is the standard you will see in open-source projects and professional codebases.

Common Mistake: = vs ==
The single most common error for students coming from everyday math notation. One character changes everything.
= is Assignment
x = 5 means "store the value 5 in the variable x." It does not ask a question. It does not return True or False. It sets a value. Never use = inside a condition.
== is Comparison
x == 5 means "is x equal to 5?" It asks a question and returns True or False. This is what you use inside an if condition. Two equals signs, always, inside conditionals.
# WRONG: using = inside an if condition x = 5 if x = 5: # SyntaxError: invalid syntax print("x is 5") # CORRECT: using == to compare if x == 5: # asks: is x equal to 5? print("x is 5") # True, so this runs # Python 3 raises SyntaxError immediately -- it protects you # Some older languages (C, JavaScript) allow this and silently do the wrong thing # Python's error is helpful -- read SyntaxErrors carefully
Good news: Python is strict about this. If you accidentally write if x = 5:, Python will refuse to run and show a SyntaxError. In C or older JavaScript, this would silently assign 5 to x and evaluate to True -- always running the block. Python's strictness is a feature, not a bug.
Slide 21 of 34
Common Mistake: Checking Multiple Values
A very common beginner pattern that looks right but is always True -- regardless of what day it is.
WRONG -- always True, every day
day = "Monday" if day == "Saturday" or "Sunday": print("Weekend!") # Why: Python reads this as: # (day == "Saturday") or ("Sunday") # "Sunday" is a non-empty string # Non-empty strings are truthy -- always True # So this prints "Weekend!" on Monday!
CORRECT -- two full comparisons
day = "Monday" if day == "Saturday" or day == "Sunday": print("Weekend!") else: print("Weekday") # EVEN BETTER: use the 'in' operator if day in ("Saturday", "Sunday"): print("Weekend!") # Output: Weekday (correct for Monday)
The in Operator
value in (option1, option2, option3) checks whether the value matches any item in the tuple. It is cleaner and more readable than chaining or comparisons. Use it when you are checking a variable against a fixed set of valid values -- weekdays, valid commands, allowed status codes, etc.

Common Mistake: Indentation Errors
Python uses whitespace to define structure. Inconsistent indentation is a fatal error.
Tabs vs Spaces
Mixing tab characters and space characters causes an IndentationError that can be invisible in your editor. Configure your editor to always convert Tab key presses into 4 spaces. Never mix them in the same file.
VS Code Configuration
Bottom status bar: click the "Spaces: 4" indicator to open indentation settings. Set to "Spaces" and "4." Also install the "Python" extension from Microsoft -- it auto-enforces PEP 8 indentation rules and highlights problems before you run.

if age >= 18: print("Adult") # 4 spaces print("Can vote") # 6 spaces # IndentationError: unexpected indent
CORRECT: uniform 4-space indentation

Input Validation Pattern
Never trust user input. Always validate it before using it. This is a core security principle.
Why Validate?
If a user types "hello" when your program expects a number and you run int("hello"), Python raises a ValueError and crashes. Validate first: is it a number? Is it in the expected range? Can you safely use it?
str.isdigit()
"42".isdigit() returns True. "hello".isdigit() returns False. "-5".isdigit() returns False -- it does not handle negatives. Use it to check whether a string contains only digit characters before converting with int().
# Safe age input with two layers of validation age_str = input("Enter your age: ") if age_str.isdigit(): # Layer 1: is it a number at all? age = int(age_str) # safe to convert now if age < 0 or age > 150: # Layer 2: is the number sensible? print("Error: that age is not realistic") else: print(f"Your age is {age}") if age >= 18: print("You are an adult") else: print("You are a minor") else: print("Error: please enter a number, not letters or symbols")

Menu System Pattern

IT Scenario: Login System
Building the login check we described on slide 1. Real credential validation with meaningful error messages.
# Simple login checker with specific error messages per failure type # Constants: uppercase names by convention -- these are fixed values VALID_USER = "admin" VALID_PASS = "Secure@2024!" MAX_ATTEMPTS = 3 username = input("Username: ") password = input("Password: ") if username == VALID_USER and password == VALID_PASS: # Both correct: grant access print("Access granted. Welcome, administrator.") print("Last login: 2024-04-01 08:42 UTC") elif username != VALID_USER: # Wrong username: do not reveal which credential failed (security practice) print("Authentication failed. Invalid credentials.") else: # Username matched but password did not print("Authentication failed. Invalid credentials.") print("Note: after 3 failed attempts, account will be locked")
Security note: Notice that both the "wrong username" and "wrong password" cases print the same generic message. This is intentional. If the error message said "username not found," an attacker could use it to enumerate valid usernames. Always return the same error for any failed authentication. This is called credential stuffing protection.

IT Scenario: HTTP Status Codes
Every web response has a status code. A monitoring script needs to interpret them automatically.
# HTTP response code interpreter -- used in web monitoring scripts status_code = 404 if status_code == 200: print("200 OK -- page loaded successfully") elif status_code == 301: print("301 Moved Permanently -- update your bookmark") elif status_code == 302: print("302 Found -- temporary redirect") elif status_code == 403: print("403 Forbidden -- you do not have permission") elif status_code == 404: print("404 Not Found -- page does not exist") elif status_code >= 500: print(f"{status_code} Server Error -- something broke on the server side") print("Alert: paging on-call engineer") else: print(f"Unexpected status code: {status_code}")
Mix of == and >=
Notice the last meaningful branch uses >= 500 instead of listing every 5xx code. Codes 500, 502, 503, 504, and others all indicate server errors. One range check handles all of them. Mix specific checks and range checks as needed.
Real-World Use
Tools like Nagios, UptimeRobot, and Pingdom use exactly this logic. They make an HTTP request, receive a status code, and run it through a conditional chain to determine the alert level. You are building real monitoring logic.

IT Scenario: Password Strength
A password checker that tests requirements in order and gives specific feedback on the first failure it finds.
# Password strength checker with specific failure feedback password = input("Create a password: ") if len(password) < 8: # len() returns the number of characters in the string print("Too short -- password must be at least 8 characters") elif password.isalpha(): # isalpha() is True if ALL characters are letters -- no digits print("Too simple -- add at least one number") elif password.islower(): # islower() is True if ALL letters are lowercase -- no uppercase print("Too simple -- add at least one uppercase letter") elif password.isupper(): # isupper() is True if ALL letters are uppercase -- no lowercase print("Too simple -- add at least one lowercase letter") else: print("Password accepted -- meets minimum requirements")
Discussion: This checker only catches the FIRST problem it finds. If the password is 3 characters and all lowercase, it reports "too short" but does not mention the other issues. This is the "fail fast, one message at a time" pattern. An alternative design checks all conditions independently with separate ifs (not elif) and collects all errors. Practice: Rock Paper Scissors
A fun example that uses complex combined conditions. Read the logic carefully -- this is the real challenge of conditionals.
import random choices = ["rock", "paper", "scissors"] computer = random.choice(choices) # pick a random element from the list player = input("rock, paper, or scissors? ").lower() # .lower() normalizes input # Check player chose a valid option before evaluating the result if player not in choices: print(f"'{player}' is not a valid choice. Please enter rock, paper, or scissors.") elif player == computer: print(f"Both chose {player} -- it's a tie!") elif (player == "rock" and computer == "scissors") or \ (player == "paper" and computer == "rock") or \ (player == "scissors" and computer == "paper"): print(f"You chose {player}, computer chose {computer} -- you win!") else: print(f"You chose {player}, computer chose {computer} -- computer wins!")
Line Continuation with Backslash
The long elif condition is split across three lines using \ (backslash) at the end of each line. Python treats lines ending with \ as continuing on the next line. This keeps your code readable instead of one extremely long line that extends off the screen. The backslash must be the very last character on the line -- no space after it.

Slide 30 of 34
Short-Circuit Evaluation
Python stops evaluating and/or expressions as soon as it knows the final result. This has practical consequences.
and Short-Circuit
If the left side of and is False, the whole expression is False no matter what the right side is. Python skips the right side entirely. The right side is never evaluated. Use this to safely guard risky operations.
or Short-Circuit
If the left side of or is True, the whole expression is True no matter what the right side is. Python skips the right side entirely. Use this to provide a fallback value when the first option is empty or None.
# SHORT-CIRCUIT AND: prevents a divide-by-zero crash x = 0 if x != 0 and 10 / x > 2: print("Quotient is greater than 2") else: print("x is zero -- division skipped safely") # Because x != 0 is False, the 10 / x expression never runs # Without short-circuit, 10 / 0 would raise ZeroDivisionError # SHORT-CIRCUIT OR: use a default if the variable is empty username = "" display_name = username or "Guest" print(f"Hello, {display_name}!") # Hello, Guest! # username is falsy (empty string), so 'or' evaluates and returns "Guest"

The pass Statement
Python requires that every code block contain at least one statement. pass fills that requirement when you have nothing to put there yet.
What pass Does
pass is a no-operation statement. It does nothing. It exists purely to satisfy Python's syntax requirement that a block cannot be empty. The interpreter reads it, acknowledges it, and moves on. No action is taken.
When to Use It
Use pass as a placeholder during development. You might know a branch needs to exist but have not yet written the logic. Write the structure first with pass to make the code runnable, then fill it in. Common in large projects and when scaffolding new features.
# pass as a placeholder during development severity = 1 if severity == 1: pass # TODO: implement PagerDuty alert integration elif severity == 2: print("Creating ServiceNow ticket") elif severity == 3: print("Logging to syslog") # Without 'pass', Python raises SyntaxError: # "expected an indented block after 'if' statement" # pass also works in function definitions and loops def alert_admin(): pass # stub -- implement later

Debugging Conditionals
When your conditional is not doing what you expect, use these techniques to find out why.
Technique 1: Print Before Checking
Print the variable AND its type before the if statement. A common bug is checking a string against an integer or vice versa. f"{val!r}" prints the repr -- you will see quotes around strings, making the type visible.
Technique 2: Print Inside Each Branch
Add a print statement as the first line of each branch. This tells you definitively which branch Python entered. Remove the debug prints before submitting -- or use a DEBUG = True flag to toggle them.
Technique 3: Test Each Condition Alone
Open the Python interactive interpreter (type python3 in terminal). Type just the condition expression and press Enter. Python evaluates and prints the result. Check if it is True or False before putting it inside an if.
# Debug pattern: check variable value and type before the conditional age = input("Enter age: ") # user types: 25 print(f"DEBUG: age={age!r} type={type(age).__name__}") # Output: DEBUG: age='25' type=str # Problem: age is a string, not an integer! if age >= 18: # TypeError: '>=' not supported between str and int print("Adult") # Fix: convert before comparing age = int(input("Enter age: ")) print(f"DEBUG: age={age!r} type={type(age).__name__}") # Output: DEBUG: age=25 type=int -- now it works

Key Vocabulary
Terms you must know for quizzes, exams, and professional conversations. Know the definition, not just the word.
Conditional / Branch
A conditional is a statement that chooses between two or more paths of execution based on a boolean condition. Each possible path is called a branch. Only one branch executes per run.
Boolean Expression
An expression that evaluates to exactly True or False. Built from comparison operators (==, !=, <, >) and logical operators (and, or, not).
Truthy / Falsy
A value is "truthy" if Python treats it as True in a boolean context. A value is "falsy" if Python treats it as False. Falsy values: 0, "", None, [], {}, False. Everything else is truthy.
Short-Circuit Evaluation
Python stops evaluating an and or or expression as soon as the result is known. The right-side expression may not be evaluated at all. Used to prevent errors from risky operations.
Ternary Expression
A one-line inline conditional: x if condition else y. Returns x when condition is True, returns y when False. Use only for simple assignments -- complex ternaries reduce readability.
Indentation / Code Block
A code block is a group of statements that share the same indentation level. Python uses indentation -- not braces -- to define blocks. The standard is 4 spaces per level. Inconsistent indentation causes IndentationError.

Conditionals -- Key Takeaways
You now have the tools to write the login system from slide 1. Check if the username is valid. Check if the password is correct. Check if the account is locked. Each check is an if or elif. Combined with and and or, you can build any access control logic a real system requires. Day 3 adds loops -- the final piece of control flow.
7 Rules to Carry Out of This Lecture
1 if checks a condition. The colon and 4-space indentation are mandatory. Forget either one and Python stops immediately with a SyntaxError or IndentationError.
2 elif adds more branches. Python checks top to bottom and stops at the first True match. Order your conditions from most specific to least specific.
3 else has no condition. It runs when nothing above matched. It is optional, but include it as a defensive catch-all in any script that handles user input or external data.
4 and / or / not combine conditions. Use and when all must be true. Use or when any one is enough. Use not to check for the absence of something.
5 Nesting is acceptable up to 2-3 levels. Beyond that, flatten with and, use elif, or extract inner logic into a function. Deep nesting is a code quality warning.
6 Always validate user input before using it. Check that it is the right type, the right length, and within the expected range. Never pass raw input() results directly to int() without checking first.
7 = assigns a value. == compares values. Never confuse them inside a condition. Python raises SyntaxError to protect you, but only in Python -- other languages silently do the wrong thing.
