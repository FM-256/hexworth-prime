What Is Python?
A quick history before we write a single line of code.
Origin
Created by Guido van Rossum, first released in 1991. Named after Monty Python's Flying Circus — a British comedy show — not the snake. Guido wanted the language to be fun and readable.
Interpreted, Not Compiled
A compiled language (C, Java) converts your code to machine code before running. An interpreted language (Python) reads and executes your code line by line at runtime. Result: faster to write and test, slightly slower to execute. For IT scripting, that tradeoff is always worth it.
Why IT Pros Use It
Automation and scripting. REST API calls. Log parsing and data processing. Cybersecurity tools (Nmap scripting, Metasploit modules, custom scanners). System administration on Linux and Windows. The language is everywhere in IT infrastructure.
Python 2 vs Python 3 — Use 3, Period
Python 2 reached end of life on January 1, 2020. It no longer receives security patches. You may encounter Python 2 code in older systems — do not write new code in it. Every command and concept in this course uses Python 3 (currently 3.12.x). If your system runs Python 2, upgrade it.
Python in Cybersecurity
Kali Linux 2024.1 ships Python 3 as default. Tools like Impacket, Scapy, Volatility, and BloodHound are Python-based. OSCP, CEH, and Security+ all touch Python scripting. Learning Python for IT is learning the language of professional security tooling.

Your First Program: Hello, World!
Every programmer writes this first. Understand every character of it.
# File: hello.py print("Hello, World!") # Run it from the terminal: $ python hello.py Hello, World!
What print() Does
print() is a built-in function. It sends output to the screen (standard output). You call it by writing its name followed by parentheses. Whatever you put inside the parentheses gets displayed. We'll cover functions in depth later — for now, just know how to call this one.
Why Strings Need Quotes
Quotes tell Python "this is text, not code." Single quotes 'hello' and double quotes "hello" are both valid — pick one and be consistent. If you forget the quotes, Python reads the word as a variable name and crashes because that variable was never defined.
Save as .py, Run from Terminal
Save your file with a .py extension. Navigate to the folder in your terminal. Run it with python filename.py. The .py extension tells editors and tools this is Python source code — it is not required by Python itself, but always use it.
Common Beginner Error
print(Hello) — this crashes with NameError: name 'Hello' is not defined. Without quotes, Python assumes Hello is a variable you created earlier. Since you never created it, it does not exist. The fix is simple: add quotes — print("Hello").

Comments: Writing for Humans
Python ignores comments. They exist entirely for the people reading your code.
# Single-line comment — Python ignores everything after the # server_count = 50 # how many servers to check """ Multi-line comment using triple quotes. Technically this is a string literal that gets thrown away, but it is the accepted convention for longer explanations. """ # Good comment: explains WHY, not WHAT timeout = 30 # SSH connections fail silently after 30s — set explicit limit # Bad comment: just repeats the code (adds no value) x = 5 # set x to 5
Why Comment?
Code tells Python what to do. Comments tell humans why you made a decision. You will reread your own code six months from now and have no memory of writing it. Comment your reasoning, not your syntax.
Single-Line: #
The hash character # starts a comment that runs to the end of the line. Can appear at the start of a line or after code on the same line. This is the most common comment style — use it freely.
Multi-Line: Triple Quotes
Three consecutive quote characters — either """ or ''' — open and close a multi-line string. Used for longer explanations, function documentation (docstrings), and temporarily disabling blocks of code during debugging.

Variables: What Are They?
A variable is a name attached to a value stored in memory. Think: a labeled box.
The Labeled Box Mental Model
Imagine a physical box. You write a label on the outside and put something inside. In Python: the label is the variable name, the contents are the value. When you ask for the variable by name, Python retrieves whatever is in that box at that moment.
No Declaration Step
Languages like Java require you to declare a variable before using it: int age;. Python does not. The moment you assign a value, the variable exists. There is no separate "create the box" step — assignment does it all in one line.
# Creating variables by assignment name = "Alice" # box labeled 'name' contains the string "Alice" age = 25 # box labeled 'age' contains the integer 25 # Variables can change — that's the point age = 26 # the box now contains 26 # Reading a variable print(name) # Alice print(age) # 26 # Use variables in calculations next_year = age + 1 print(next_year) # 27
Key concept: Python is dynamically typed. You do not tell Python what type to put in the box — Python figures it out from the value you assign. This is convenient but means you must track your own types. type(age) tells you what type a variable currently holds.

Variable Naming: Rules & Conventions
Rules are enforced by Python. Conventions are enforced by your team.
Hard Rules (Python Enforces These)
Must start with a letter or underscore — not a digit.
Can contain letters, numbers, and underscores only.
Case-sensitive: Name and name are two different variables.
Cannot be a reserved word: if, for, while, class, True, False, None, import, return, etc.
snake_case — The Python Convention
Words separated by underscores, all lowercase.
first_name   total_score   is_active   server_count
This is called snake_case because the underscores look like a snake between words.
Defined in PEP 8 — Python's official style guide. Use it for variable and function names, always.
snake_case (Use This)
disk_usage_gb
server_name
is_connected
Python variables and functions. PEP 8 standard.
camelCase (Do Not Use for Variables)
diskUsageGb
serverName
isConnected
JavaScript and Java convention. Python will not complain, but your teammates will.
PascalCase (Classes Only)
DiskUsageGb
ServerManager
NetworkScanner
Reserved in Python for class names. Using it on a variable is confusing to any Python reader.
What is PEP 8? PEP stands for Python Enhancement Proposal. PEP 8 is the style guide for Python code. It does not change what Python accepts — it defines what Python code should look like so all Python code reads consistently, regardless of who wrote it. Think of it as the formatting standard every Python developer follows.

Data Types: The Big Four
Every value in Python has a type. The type determines what you can do with the value.
int — Whole Numbers
42    -7    0    1000000
No decimal point. Positive or negative. Use for counts, port numbers, loop counters, IDs.
server_count = 50
float — Decimal Numbers
3.14    -0.5    2.0    87.5
Has a decimal point. Use for measurements, percentages, averages, CPU usage.
cpu_usage = 87.5
str — Text
"hello"    'world'    "123"
Anything in quotes. Note: "123" is text, not a number — you cannot do math with it.
hostname = "web01"
bool — True or False
True    False
Capital T and F — required. Used for conditions, flags, switches.
is_online = True
# Check a value's type with type() print(type(42)) # <class 'int'> print(type(3.14)) # <class 'float'> print(type("hello")) # <class 'str'> print(type(True)) # <class 'bool'> print(type("123")) # <class 'str'> — note: string, NOT int
Why does this matter? Python will not let you mix incompatible types in operations. You cannot add a string to an integer. You cannot compare a float to a boolean the way you might expect. Knowing the type of your data is the first thing to check when a calculation goes wrong.
Slide 17 of 46
Integers in Depth
Whole numbers. Positive, negative, or zero. No size limit in Python 3.
What Makes an Integer
No decimal point. No quotes. Can be any size — Python handles arbitrarily large integers without overflow. This is a difference from C and Java, where integers have fixed bit-width limits. 2 ** 100 works fine in Python.
IT Use Cases
server_count = 50 — count of servers to check
port = 8080 — network port number
error_code = -1 — sentinel value for "no result"
max_retries = 3 — loop control
Division Operators
Regular division / always returns a float, even if the result is whole: 10 / 2 = 5.0. Floor division // drops the decimal: 10 // 3 = 3. Modulus % returns the remainder: 10 % 3 = 1.
# IT scenario: dividing work across threads total_servers = 50 threads = 8 servers_per_thread = total_servers // threads # 6 — floor division leftover = total_servers % threads # 2 — remainder servers print(servers_per_thread) # 6 print(leftover) # 2 # Exponentiation — 2 to the 10th power print(2 ** 10) # 1024 — useful for converting bytes to GB # Convert bytes to gigabytes using integer math bytes_free = 536870912000 gb_free = bytes_free // (1024 ** 3) # 500
Slide 18 of 46
Floats in Depth
Decimal numbers. Precise enough for most IT work — but not for money.
What Makes a Float
Any number with a decimal point: 3.14, -0.5, 2.0. Even 2.0 is a float, not an integer, because of the decimal point. Stored in IEEE 754 double precision format internally — the same as most other languages.
IT Use Cases
cpu_usage = 87.5 — percentage
response_time = 0.432 — seconds
disk_free_gb = 521.4 — measured storage
packet_loss = 0.02 — 2 percent
The 0.1 + 0.2 Problem
Try 0.1 + 0.2 in Python. You get 0.30000000000000004. This is not a Python bug — it is a fundamental property of binary floating-point representation. The value 0.1 cannot be stored exactly in binary, so small rounding errors accumulate.
# Float arithmetic cpu_usage = 87.5 threshold = 80.0 print(cpu_usage > threshold) # True # The floating-point precision issue print(0.1 + 0.2) # 0.30000000000000004 # round() controls decimal places for display result = round(0.1 + 0.2, 2) print(result) # 0.3 # When to use int vs float: # Use int for counts, IDs, index values — things that cannot be fractional # Use float for measurements, rates, percentages — things that can be fractional # Never use float for money — use the decimal module instead
Slide 19 of 46
Strings in Depth
Text data. Any character. Any length. Wrapped in quotes.
Three Ways to Create a String
Single quotes: 'hello'
Double quotes: "hello" — identical to single, just lets you include apostrophes without escaping
Triple quotes: """multi-line""" — spans multiple lines; used for long text blocks and documentation
Strings Are Sequences
Every character has a position number called an index. Indexing starts at 0, not 1. The string "web01" has five characters at positions 0, 1, 2, 3, 4. You can access individual characters or ranges. We cover this in the strings week — today, just know the concept.
Strings Are Immutable
Once created, a string cannot be changed in place. You can create a new string based on the old one, but you cannot modify individual characters. This is intentional — it makes strings safe to pass around in programs without worrying about unexpected changes.
# String creation examples hostname = "web-prod-01" message = 'Connection refused' log_entry = """2024-09-15 14:32:01 ERROR: Disk usage exceeded 90% Server: db-prod-02""" empty = "" # valid empty string — length 0 # len() returns the number of characters print(len(hostname)) # 11 print(len(empty)) # 0 # Check if a substring exists inside a string print("prod" in hostname) # True print("dev" in hostname) # False

String Concatenation
Joining strings together. Simple, but with one critical rule about types.
Joining with +
The + operator joins two strings end to end. This is called concatenation. You can chain multiple + operations. The space between words does not appear automatically — you must add it as a string: "Hello" + " " + "World".
Cannot Mix Types
You cannot concatenate a string and an integer: "Age: " + 25 raises a TypeError. Python will not automatically convert the number. You must cast it first: "Age: " + str(25). This is one of the most common beginner errors — remember it.
# String concatenation first = "Hello" last = "World" print(first + " " + last) # Hello World # Repetition with * print("ha" * 3) # hahaha print("-" * 40) # ---------------------------------------- # This crashes — cannot add string + integer age = 25 # print("Age: " + age) # TypeError: can only concatenate str (not "int") to str # Fix 1: cast the integer to string print("Age: " + str(age)) # Age: 25 # Fix 2: use an f-string (cleaner — covered on next slide) print(f"Age: {age}") # Age: 25
Building a log message: server = "db-01" and status_code = 500. The message should read "ALERT: db-01 returned 500". Using concatenation: "ALERT: " + server + " returned " + str(status_code). This works but becomes unwieldy fast. F-strings fix this.
Slide 21 of 46
F-Strings: Formatted String Literals
The modern, readable way to embed variables and expressions inside strings.
The Syntax
Put the letter f immediately before the opening quote. Inside the string, wrap any variable or expression in curly braces {}. Python evaluates what is inside the braces and inserts the result into the string. The f prefix is required — without it, {name} is just literal text.
Expressions Inside Braces
You are not limited to variable names. Anything that evaluates to a value works: {price * quantity}, {'hello'.upper()}, {2 ** 8}. This makes f-strings extremely flexible compared to concatenation.
Format Specifiers
Control decimal places: {value:.2f} rounds to 2 decimal places. Control width: {name:<20} left-pads to 20 characters. Useful for building aligned reports and tables from Python.
# Basic f-string usage name = "Rivera" age = 31 print(f"Technician: {name}, Age: {age}") # Technician: Rivera, Age: 31 # Expression inside braces price = 49.99 quantity = 3 print(f"Total: ${price * quantity:.2f}") # Total: $149.97 # IT scenario: disk space report free_gb = 521.4 total_gb = 2000 pct_free = (free_gb / total_gb) * 100 print(f"Free: {free_gb:.1f} GB ({pct_free:.1f}% available)") # Free: 521.4 GB (26.1% available) # Method call inside braces server = "web-prod-01" print(f"Server: {server.upper()}") # Server: WEB-PROD-01

Booleans: True and False
Only two possible values. More important than they look.
Capitalization Is Required
True and False — capital T and F. true and false (lowercase) are not valid Python — they will raise a NameError because Python will treat them as variable names that have not been defined.
Result of Comparisons
Every comparison expression evaluates to True or False. 5 > 3 is True. 2 == 7 is False. This is how Python makes decisions. Booleans are the language of conditions.
Truthiness and Falsiness
Every Python value has a boolean interpretation. Falsy values (evaluate as False): 0, 0.0, "", None, empty list []. Everything else is truthy. You can use any value directly in an if statement.
# Boolean values port_open = True firewall_up = False # Result of a comparison is always bool print(5 > 3) # True print(10 == 20) # False # bool() converts any value to its boolean equivalent print(bool(0)) # False print(bool(1)) # True print(bool("")) # False — empty string is falsy print(bool("hello")) # True — non-empty string is truthy # Practical truthiness check username = "" if not username: print("Username cannot be empty")
Under the hood: bool is a subclass of int in Python. True == 1 and False == 0. This means you can do math with booleans: True + True is 2. Useful trick: sum([True, False, True, True]) counts the True values (result: 3).
Slide 24 of 46
The None Type
A special value that means "nothing." Not zero, not empty string, not False.
What None Means
None represents the absence of a value. It is Python's equivalent of null in other languages. There is exactly one None object in any Python program — not multiple "empty" values, just one None. It has its own type: type(None) returns <class 'NoneType'>.
When You See None
Default parameter values: a function parameter set to None means "not provided." A function that has no return statement implicitly returns None. Variables you declare but have not populated yet. Database query results with no match.
How to Check for None
Use is None, not == None. The is operator checks object identity — it confirms you are looking at the actual None object, not just something that equals it. Python style guides require is None. PEP 8 enforces this explicitly.
# None is not the same as 0, "", or False result = None # scan result not yet available count = 0 # scan ran, found zero results — different! message = "" # empty string — also different print(result == None) # True — but do not write it this way print(result is None) # True — correct way print(count is None) # False — 0 is not None # Practical pattern: guard against None before using a value scan_output = None if scan_output is None: print("Scan has not run yet") else: print(f"Scan result: {scan_output}")

Type Casting: Converting Between Types
Python will not convert types for you automatically. You have to ask.
int() — To Integer
int("42") converts a numeric string to an integer. int(3.7) truncates — drops the decimal, does not round (result is 3, not 4). int("hello") raises a ValueError — only numeric strings work.
float() — To Float
float("3.14") converts a numeric string to a float. float(5) becomes 5.0. float("abc") raises a ValueError. Useful when you have a string that represents a decimal measurement.
str() — To String
str(42) becomes "42". str(3.14) becomes "3.14". str(True) becomes "True". Works on anything. Required when you need to concatenate a non-string value into a string.
# Type casting examples print(int("42")) # 42 — string to integer print(float("3.14")) # 3.14 print(str(42)) # "42" print(int(3.7)) # 3 — truncates, does NOT round to 4 print(bool(0)) # False print(bool(99)) # True # This raises ValueError — "hello" is not a valid integer string # int("hello") # Why this matters: input() always returns a string # raw_age = input("Enter age: ") # user types 25, raw_age is "25" not 25 # age = int(raw_age) # now it is an integer you can do math with
Critical point: int() truncates, it does not round. int(3.9) is 3, not 4. If you need rounding, use round(3.9) which gives 4, then cast if needed.

The input() Function
How your program asks the user a question. The answer is always a string.
Basic Usage
input() pauses the program, prints a prompt, waits for the user to type something and press Enter, then returns whatever they typed. The string inside input() is the prompt the user sees. If you pass an empty string or nothing, there is no prompt.
It ALWAYS Returns a String
This is the most important rule about input(). Even if the user types 42, Python gives you the string "42", not the integer 42. If you try to do math with it without casting, you get a TypeError. Always cast the result when you expect a number.
# Basic input — result is always a string name = input("Enter your name: ") print(f"Hello, {name}!") # Forgetting to cast — common beginner mistake raw_age = input("Enter your age: ") # print(raw_age + 1) # TypeError: can only concatenate str (not "int") to str # Correct: cast immediately age = int(input("Enter your age: ")) print(f"Next year you will be {age + 1}") # For decimal input, use float() gpa = float(input("Enter your GPA: ")) print(f"GPA: {gpa:.2f}")
A help desk script asks: "Enter the server port to check: " — the user types 8080. If you store that directly and try to compare it with port == 8080, you are comparing the string "8080" to the integer 8080. They are not equal. Cast immediately: port = int(input(...)).

Operator Precedence
Python evaluates operators in a specific order. Get this wrong and your calculations will be silently incorrect.
Order of Operations (PEMDAS)
P — Parentheses first
E — Exponents (**)
M/D — Multiply, Divide, Floor Divide, Modulo (left to right)
A/S — Add, Subtract (left to right)
Same as math class — Python follows standard mathematics.
Why This Matters
2 + 3 * 4 = 14, not 20 (multiplication first)
(2 + 3) * 4 = 20 (parentheses override)
If you expect 20 but get 14, your precedence is wrong.
When in Doubt, Parenthesize
Adding parentheses around sub-expressions costs nothing and eliminates ambiguity for both Python and the next human reading your code. If you are unsure whether Python will evaluate something the way you intend, wrap it in parentheses.
# Precedence examples print(2 + 3 * 4) # 14 — multiply first, then add print((2 + 3) * 4) # 20 — parentheses override print(2 ** 3 + 1) # 9 — exponent first: 8 + 1 print(2 ** (3 + 1)) # 16 — parentheses: 2 ** 4 # Real-world example: Fahrenheit to Celsius # Wrong: C = F - 32 * 5 / 9 (multiplies 32 by 5 first — incorrect) # Correct: C = (F - 32) * 5 / 9 f_temp = 98.6 c_temp = (f_temp - 32) * 5 / 9 print(round(c_temp, 1)) # 37.0

Logical Operators
Combine boolean expressions. The foundation of complex conditions.
and
Both sides must be True for the result to be True. If the left side is False, Python does not evaluate the right side — it already knows the result is False. This is called short-circuit evaluation.
True and True = True
True and False = False
False and True = False
or
At least one side must be True. If the left side is True, Python does not evaluate the right side — result is already True.
True or False = True
False or True = True
False or False = False
not
Inverts the boolean value. Turns True into False and False into True. Used to flip a condition when the positive case is harder to express.
not True = False
not False = True
not (5 > 3) = False
# IT scenario: ticket escalation decision priority = 2 wait_hours = 6.5 vip_client = True # Escalate if: priority 1, OR waited more than 4 hours AND is a VIP escalate = (priority == 1) or (wait_hours > 4 and vip_client) print(escalate) # True # not flips the result server_down = False print(not server_down) # True — server is up # Range check with and score = 78 passing = score >= 60 and score <= 100 print(passing) # True
Slide 32 of 46
Assignment Operators
Shortcuts that update a variable in place. Used constantly in loops.
What They Do
An augmented assignment operator combines a math operation with assignment in one step. x += 5 means "take the current value of x, add 5, and store the result back in x." It is exactly equivalent to x = x + 5 — just shorter. These exist for all arithmetic operators.
Why They Matter
You will see these constantly in loops that count or accumulate values. A counter that increments on every pass: count += 1. A running total: total += price. Writing the full form every time (count = count + 1) works but reads slower and is more prone to typos.
# All augmented assignment operators x = 10 x += 5 # x = x + 5 = 15 x -= 3 # x = x - 3 = 12 x *= 2 # x = x * 2 = 24 x /= 4 # x = x / 4 = 6.0 (note: becomes float) x //= 2 # x = x // 2 = 3.0 (floor division) x %= 2 # x = x % 2 = 1.0 (remainder) x **= 3 # x = x ** 3 = 1.0 (exponent) # Practical example: counting errors in a log scan error_count = 0 error_count += 1 # found one error error_count += 1 # found another error_count += 1 # and another print(error_count) # 3
Note on /=: Because / always returns a float, x /= 4 can turn an integer variable into a float. If you need an integer result, use //= instead.

Membership & Identity Operators
Two more operator categories you will use from Day 2 onward.
Membership: in and not in
in — asks "is this value somewhere inside that sequence?"
Works with strings, lists, tuples, and other sequences.
"a" in "apple" = True
"z" not in "apple" = True
"ERROR" in log_line — check if a log line contains an error
Identity: is and is not
is — asks "are these the exact same object in memory?" Not just equal — identical.
== checks value equality. is checks object identity.
Use is only for None checks: if result is None:
Do not use is to compare numbers or strings — the behavior is not guaranteed.
# Membership operator — in log_line = "2024-09-15 ERROR: Connection timeout on db-prod-01" print("ERROR" in log_line) # True print("WARNING" in log_line) # False print("WARNING" not in log_line) # True # Identity operator — is (use only for None) result = None print(result is None) # True — correct way to check None print(result is not None) # False # == vs is — why they differ a = [1, 2, 3] b = [1, 2, 3] print(a == b) # True — same contents print(a is b) # False — different objects in memory

Common Errors: Syntax Problems
Syntax errors stop your program before it runs. Python catches these before executing a single line.
SyntaxError: invalid syntax
Python could not parse your code. Common causes: missing colon after if, for, while, def. Mismatched parentheses or brackets. Missing closing quote on a string. Using Python 2 print syntax: print "hello".
IndentationError
Python uses indentation to define code blocks — not curly braces like C or Java. Every line inside an if or for must be consistently indented (use 4 spaces, not tabs). Mixing tabs and spaces causes errors that are nearly invisible to the eye.
# SyntaxError examples # Missing colon after if # if x > 5 # SyntaxError: expected ':' # Unterminated string # name = "Alice # SyntaxError: EOL while scanning string literal # Python 2 print syntax (wrong in Python 3) # print "hello" # SyntaxError: Missing parentheses # Correct versions: x = 10 if x > 5: # colon is required print("big") # 4 spaces of indentation # IndentationError example # if x > 5: # print("big") # IndentationError: expected an indented block
VS Code tip: Set your editor to use 4 spaces for indentation and to show whitespace characters. The "Indent Using Spaces" and "Render Whitespace" settings prevent most indentation errors before they happen.
Slide 36 of 46
Common Errors: Runtime Problems
Runtime errors happen while the program is running, after it passes the syntax check.
NameError
NameError: name 'x' is not defined. You used a variable before assigning it. Common causes: typo in the variable name (sever_name instead of server_name), or using the variable outside of the scope where it was created.
TypeError
TypeError: can only concatenate str (not "int") to str. You mixed incompatible types. The most common form: trying to concatenate a string and a number without casting. Fix: str(number) before the concatenation.

Slide 37 of 46
Debugging: Finding and Fixing Errors
Debugging is a skill. Good programmers are not people who write bug-free code — they are people who find bugs efficiently.
Read the Error Message First
Python tells you the file name, the line number, and what went wrong. Read every word of the error message before touching your code. The line number is where Python detected the problem — the actual cause may be one or two lines earlier.
Print Statement Debugging
Add print() calls to show variable values at different points in your program. "What is the value of x right before this crash?" — add print(x) right before that line. Remove the print statements once the bug is fixed. This is the oldest debugging technique and still the most used.
Check Types and Comment Out
When a value behaves unexpectedly, add print(type(variable)) to see what type it actually is. Comment out sections of code to isolate where the problem begins — if commenting out lines 20-30 fixes it, the bug is in those lines.
# Debugging workflow example raw_input_value = "42" # pretend this came from input() # Step 1: what type is it? print(type(raw_input_value)) # <class 'str'> — ah, it is a string # Step 2: cast it number = int(raw_input_value) print(type(number)) # <class 'int'> — now correct print(number + 8) # 50 — works
Professional habit: Google the exact error message in quotes. Stack Overflow has answers to virtually every error a beginner encounters. Learning to search effectively for technical errors is a skill as important as learning to code.

The Zen of Python
The philosophy baked into the language itself. Run import this in the Python shell.
# Easter egg — type this in the Python interactive shell >>> import this The Zen of Python, by Tim Peters Beautiful is better than ugly. Explicit is better than implicit. Simple is better than complex. Complex is better than complicated. Readability counts. Errors should never pass silently. In the face of ambiguity, refuse the temptation to guess. There should be one obvious way to do it. Now is better than never. If the implementation is hard to explain, it's a bad idea.
"Readability counts."
Code is read far more than it is written. Every decision you make about variable names, whitespace, and structure should favor the person reading it — including future you. This is why snake_case exists. This is why PEP 8 exists.
"Errors should never pass silently."
Do not swallow errors or ignore them. If something goes wrong in your script, your script should tell you clearly — not just produce a wrong answer without complaint. We will build on this when we cover exception handling.
"Simple is better than complex."
If you can accomplish something in 5 lines, do not write 20. Python culture values clarity and brevity. A solution that a beginner can read and understand is almost always better than a clever solution that confuses everyone.
