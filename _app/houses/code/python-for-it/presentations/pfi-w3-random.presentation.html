The random Module
Selection, Simulation & Security
Your First Import  •  choice / choices / sample  •  random vs secrets  •  Capstone Challenge
Every security tool, every simulation, every lab assignment randomizer needs controlled randomness. Python's random module gives you three precision instruments: one for picking a single item, one for picking many with repeats allowed, and one for picking many with no repeats. Knowing which to reach for — and when NOT to use random at all — is what separates scripts from professional tools.

Slide 2 of 10  |  Your First Import
Importing: Your First Module
Built-in functions are always available. Module functions require an import statement first.
What Is a Module?
A module is a Python file containing functions, classes, and variables that someone else wrote and packaged for reuse. The random module is part of Python's standard library — it ships with every Python installation. No pip install needed.
import random
Place import random at the top of your script. Now every function in the module is available via dot notation: random.choice(), random.sample(), etc. The import runs once; the module loads into memory for the rest of the script.
import random # Module functions use dot notation: module_name.function_name() print(random.randint(1, 100)) # random integer between 1 and 100 inclusive print(random.random()) # random float between 0.0 and 1.0 # Compare: built-in functions need no import print(len([1, 2, 3])) # 3 — len() is built-in, always available # Without the import, this crashes with NameError: # random.choice(["a", "b"]) → NameError: name 'random' is not defined
Convention: All import statements go at the very top of the file, before any other code. PEP 8 requires this. It makes dependencies visible in the first 5 lines of any script.
Slide 3 of 10  |  Tool 1: Pick One
random.choice(): Pick One Item
Selects a single random element from a non-empty sequence.
Your load balancer needs to pick one server from a pool of five. Your CTF engine needs to select one challenge box for a student. Your quiz system needs to pick one bonus question from a bank of twenty. All of these are random.choice().
How It Works
Pass any sequence (list, tuple, string). Returns exactly one element chosen at random. Each element has an equal probability of being selected. Raises IndexError if the sequence is empty.
Works On Any Sequence
Lists, tuples, strings, and ranges all work. random.choice("ABCDEF") picks one character. random.choice(range(1, 101)) picks a random number 1-100 without building a list.
When to Use
You need exactly one item. A random server, a random quiz question, a random color for a UI element. If you need more than one item, use choices() or sample() instead.
import random # Pick one server from the load balancer pool servers = ["web01", "web02", "web03", "web04", "web05"] target = random.choice(servers) print(f"Routing request to: {target}") # e.g. "web03" # Pick one challenge box for a student boxes = ["A1-Phantom", "B3-Cipher", "C7-Veiled", "D5-Breach"] assigned = random.choice(boxes) print(f"Your challenge: {assigned}") # e.g. "C7-Veiled" # Pick a random character for a simple token charset = "ABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789" print(random.choice(charset)) # e.g. "K"
Slide 4 of 10  |  Tool 2: Pick Many (Repeats OK)
random.choices(): Pick Many, Repeats Allowed
Selects k items with replacement. The same item can appear multiple times.
How It Works
random.choices(population, k=N) returns a list of N items. Each pick is independent — the same item can be selected again. Think of it as rolling a die K times: you can roll the same number twice.
The weights= Power Feature
weights=[10, 1, 1] makes the first item 10x more likely. Use this for difficulty tiers, traffic simulation, or any scenario where some outcomes should be more probable than others.
import random # Simulate network traffic: same source IP can appear multiple times source_ips = ["10.0.1.5", "10.0.1.12", "10.0.2.8", "192.168.1.100"] traffic = random.choices(source_ips, k=10) print(f"Traffic log: {traffic}") # e.g. ['10.0.1.5', '10.0.2.8', '10.0.1.5', '10.0.1.12', ...] — repeats! # Weighted selection: 70% easy boxes, 20% medium, 10% hard tiers = ["easy", "medium", "hard"] weights = [70, 20, 10] assignments = random.choices(tiers, weights=weights, k=5) print(f"Difficulty spread: {assignments}") # e.g. ['easy', 'easy', 'medium', 'easy', 'hard']
choices() vs choice(): choice() returns a single item. choices() returns a list of k items. Even choices(data, k=1) returns a list — ["web01"] not "web01". Do not confuse the singular with the plural.
Slide 5 of 10  |  Tool 3: Pick Many (No Repeats)
random.sample(): Pick Many, Guaranteed Unique
Selects k unique items. No element appears twice. Order is random.
How It Works
random.sample(population, k=N) returns a list of N unique items drawn from the population. Once an item is picked, it cannot be picked again. Raises ValueError if k exceeds the population size.
The ValueError Guard
If you request more unique items than exist, Python crashes: ValueError: Sample larger than population. Always check k <= len(population) before calling sample(). This is a common source of runtime errors.
import random # Assign 4 unique lab devices to 4 students — no device goes to two students lab_devices = ["sw-3750", "rtr-2901", "fw-asa", "ap-aironet", "srv-esxi", "sw-9300"] assigned = random.sample(lab_devices, k=4) print(f"Devices assigned: {assigned}") # e.g. ['fw-asa', 'sw-9300', 'rtr-2901', 'ap-aironet'] — all unique # Select 3 unique IPs from a scan target list targets = ["10.0.1.1", "10.0.1.2", "10.0.1.3", "10.0.1.4", "10.0.1.5"] scan_batch = random.sample(targets, k=3) print(f"Scanning: {scan_batch}") # This crashes — requesting 10 from a pool of 5 # random.sample(targets, k=10) → ValueError: Sample larger than population
When to use sample(): Any time duplicates would break your logic — device assignments, tournament brackets, raffle drawings, unique challenge selection. If two students get the same device, the lab fails. sample() prevents that by design.
Slide 6 of 10  |  Which One Do I Use?
Decision Matrix: Which Function?
Four scenarios. Four answers. Memorize this.
Need 1 item?
random.choice(pool)
Returns a single element. Simplest case. Load balancer picks one server.
Need many, repeats OK?
random.choices(pool, k=N)
Returns a list. Same item can appear twice. Simulating traffic, test data generation.
Need many, must be unique?
random.sample(pool, k=N)
Returns a list. Guaranteed no repeats. Lab device assignments, tournament brackets.
Need security (passwords, tokens)?
secrets.choice(pool)
Cryptographically secure. Use the secrets module, NOT random. Passwords, API keys, session tokens.
import random pool = ["A", "B", "C", "D", "E"] # One item print(random.choice(pool)) # 'C' # Many items, repeats allowed print(random.choices(pool, k=4)) # ['A', 'C', 'A', 'E'] — 'A' appears twice # Many items, guaranteed unique print(random.sample(pool, k=4)) # ['D', 'B', 'E', 'A'] — no repeats ever
Slide 7 of 10  |  Security Warning
random vs secrets: The Security Line
The random module is NOT safe for passwords, tokens, or keys. Ever.
Critical Security Rule
Never use the random module for security-sensitive operations. The random module uses a deterministic algorithm (Mersenne Twister). If an attacker learns the internal state — which is possible by observing enough outputs — they can predict every future value. For passwords, API keys, session tokens, and any secret: use the secrets module.
random — Predictable
Uses Mersenne Twister PRNG. Fast but deterministic. random.seed(42) produces the same sequence every time. An attacker who observes 624 outputs can reconstruct the internal state and predict all future values. Fine for simulations. Fatal for security.
secrets — Secure
Uses the operating system's entropy source (/dev/urandom on Linux). Cryptographically secure pseudorandom number generator (CSPRNG). Cannot be predicted even with unlimited observed outputs. Required for any value an attacker must not guess.
import random import secrets import string charset = string.ascii_letters + string.digits + string.punctuation # BAD: predictable password generator bad_pw = "".join(random.choices(charset, k=16)) print(f"Insecure: {bad_pw}") # Works but an attacker can predict this # GOOD: cryptographically secure password generator good_pw = "".join(secrets.choice(charset) for _ in range(16)) print(f"Secure: {good_pw}") # Cannot be predicted # Also useful: secrets.token_hex() for API keys api_key = secrets.token_hex(32) print(f"API key: {api_key}") # 64-character hex string
Slide 8 of 10  |  Capstone Challenge
Capstone: Network Device Lottery
Build a CLI tool that ties functions, built-ins, and random together.
The lab coordinator needs a tool for exam sessions. Students check in and are randomly assigned a unique network device to troubleshoot. Each device goes to exactly one student. The tool validates inputs, rejects duplicates, displays a formatted report, and produces summary statistics.
Required Functions
1 validate_student_id(sid: str) -> bool — return True only if sid matches STU- followed by exactly 5 digits. Use startswith(), isdigit(), and len().
2 build_device_pool(devices: list, count: int) -> list — use random.sample() to select count unique devices. Raise ValueError if count exceeds pool size.
3 assign_devices(students: list, devices: list) -> dict — use zip() to pair students with devices. Return a dict. Raise ValueError if list lengths differ.
4 print_report(assignments: dict, session_id: str) -> None — use enumerate() for row numbers, sorted() for alphabetical order, f-strings with width alignment for columns.
5 session_summary(assignments: dict) -> dict — return total_students (len()), device_types (set comprehension), longest_id (max() with key=len). No explicit for-loops.
6 Stretch: weighted_device_sample() — use random.choices() with weights to make routers and firewalls more likely for advanced students.
Slide 9 of 10  |  Watch Out
Common Mistakes
Every one of these has cost someone debugging time. Learn from their pain.
Forgetting to Import
random.choice(data) without import random at the top produces NameError: name 'random' is not defined. Unlike built-in functions, module functions require an explicit import.
Using random for Security
Building a "password generator" with random.choices() feels correct but is insecure. An attacker who observes enough outputs can predict the seed. Always use secrets for passwords, tokens, and keys.
choices() When You Need sample()
Using choices(devices, k=5) to assign lab equipment means two students could get the same device. That is a broken lab. Use sample() when uniqueness is required.
sample(k) > len(population)
Requesting 10 unique items from a pool of 5 raises ValueError. Always validate: if k <= len(pool) before calling sample(). This is a runtime crash, not a syntax error — tests miss it if the test data is too large.
Confusing random() with randint()
random.random() returns a float between 0.0 and 1.0. random.randint(1, 100) returns an integer between 1 and 100 inclusive. Mixing them up gives wildly wrong results with no error message.
