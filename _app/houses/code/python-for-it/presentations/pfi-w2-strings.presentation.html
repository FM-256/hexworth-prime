String Review: Quotes, Concatenation, f-strings
Day 1 callback — strings are the most common data type in IT scripting.
Three Ways to Quote
Single: 'hello'
Double: "hello"
Triple: """multi-line"""
Single and double are equivalent. Use double when your string contains apostrophes. Triple for multi-line strings or docstrings.
Concatenation with +
The + operator joins strings end to end. Both sides must be strings — you cannot add a string and an integer directly. Use str() to convert first, or use an f-string which handles it automatically.
f-strings (Python 3.6+)
Prefix the string with f and embed expressions in curly braces. The expression is evaluated at runtime and inserted. This is the preferred way to build strings in modern Python — cleaner and faster than concatenation or .format().
# Concatenation — both sides must be str host = "db-prod-01" port = 5432 msg = "Connecting to " + host + " on port " + str(port) print(msg) # Connecting to db-prod-01 on port 5432 # f-string — cleaner, handles non-string values automatically msg = f"Connecting to {host} on port {port}" print(msg) # Connecting to db-prod-01 on port 5432 # f-strings evaluate any expression inside {} print(f"Servers checked: {50 * 2}") # Servers checked: 100

String Indexing: Accessing Individual Characters
Strings are sequences. Every character has an address. Two addressing schemes exist.
Positive Indices (left to right)
Counting starts at 0, not 1. This is called zero-based indexing and is standard in most programming languages. For a string of length n, the last valid index is n-1. Accessing index n raises an IndexError.
Negative Indices (right to left)
Index -1 is always the last character. Index -2 is second from last. Negative indices count backward from the end. This is useful when you need the last few characters and do not know the string length.
# Log prefix example: "ERROR: disk usage at 94%" log = "ERROR: disk usage at 94%" # Positive indices: first character is index 0 print(log[0]) # 'E' print(log[1]) # 'R' print(log[5]) # ':' # Negative indices: -1 is always the last character print(log[-1]) # '%' print(log[-2]) # '4' print(log[-3]) # '9' # len() gives the total count of characters print(len(log)) # 24 print(log[len(log) - 1]) # '%' — same as log[-1]
IndexError
Accessing an index that does not exist raises IndexError: string index out of range. A string of 10 characters has indices 0 through 9. Accessing index 10 crashes. This is one of the most common runtime errors beginners encounter.
Slide 4 of 36
String Slicing: Extracting Substrings
Slicing returns a new string containing the characters from start up to (not including) stop.
Basic Syntax: s[start:stop]
Returns characters from index start up to but not including index stop. The stop index is exclusive. Omit start to begin from 0. Omit stop to go to the end.
With Step: s[start:stop:step]
The third parameter controls how many characters to skip between selections. s[::2] takes every other character. s[::-1] reverses the entire string — step of -1 walks backward through every character.
Slicing Never Crashes
Unlike indexing, a slice with out-of-range values does not raise an error. Python simply returns whatever is available. "hello"[0:100] returns "hello" — it stops at the end of the string gracefully.
# Syslog line: extract the severity level and message entry = "2024-11-14 08:22:01 ERROR sshd: Failed password for root" # Extract the date (first 10 characters: indices 0-9) date = entry[0:10] print(date) # 2024-11-14 # Extract the time (indices 11-18) time = entry[11:19] print(time) # 08:22:01 # Omit start — from the beginning print(entry[:10]) # 2024-11-14 # Omit stop — from index 20 to the end print(entry[20:]) # ERROR sshd: Failed password for root # Reverse the entire string with [::-1] word = "server" print(word[::-1]) # revres # Every other character print("abcdefgh"[::2]) # aceg
Slide 5 of 36
String Immutability: Strings Cannot Be Changed In Place
Once a string is created, its characters cannot be modified. You must create a new string.
What Immutable Means
Immutable means "cannot be changed after creation." You cannot reassign a character at a specific index the way you can with a list. Any string operation that appears to modify a string actually creates a brand-new string object and returns it.
Why Python Made This Choice
Immutability makes strings safe to use as dictionary keys and set members (both require objects that don't change). It also means two variables can point to the same string object in memory without either one accidentally changing it.
# This will crash — strings do not support item assignment hostname = "web-prod-01" # hostname[0] = 'W' <-- TypeError: 'str' object does not support item assignment # Correct: build a new string hostname = "W" + hostname[1:] print(hostname) # Web-prod-01 # String methods return new strings — they do not modify the original original = "access denied" upper = original.upper() print(original) # access denied (unchanged) print(upper) # ACCESS DENIED (new string) # To keep the result, assign it back to the variable original = original.upper() print(original) # ACCESS DENIED
Common mistake: calling s.upper() and then printing s expecting it to be uppercase. It is not. You must capture the return value: s = s.upper() or result = s.upper().
Slide 6 of 36
String Methods: Case Conversion
Five methods for changing letter case. Each returns a new string.
upper() and lower()
.upper() converts every letter to uppercase.
.lower() converts every letter to lowercase.
Essential for case-insensitive comparisons: normalize both sides to the same case before comparing. Non-letter characters (numbers, punctuation) are unaffected.
capitalize() and title()
.capitalize() — first character uppercase, rest lowercase.
.title() — first character of every word uppercase.
Useful for formatting names and headings. .title() treats any character after whitespace or punctuation as a word boundary.
swapcase()
Flips every letter: uppercase becomes lowercase, lowercase becomes uppercase. Rarely needed in production code but useful for obfuscation exercises, and it appears on Python certification exams. Good to know.
# Case methods — all return new strings service = "Apache Web Server" print(service.upper()) # APACHE WEB SERVER print(service.lower()) # apache web server print(service.swapcase()) # aPACHE wEB sERVER print(service.capitalize()) # Apache web server (only first letter up) print(service.title()) # Apache Web Server (every word capitalized) # Practical: case-insensitive comparison to parse log severity level = "error" if level.upper() == "ERROR": print("Critical — page the on-call engineer")
IT pattern: When you parse log files, the severity level might be written as ERROR, error, or Error depending on the application. Always normalize with .upper() or .lower() before comparing so your script handles all three.
Slide 7 of 36
String Methods: strip(), lstrip(), rstrip()
Remove unwanted whitespace or specific characters from the edges of a string.
strip()
Removes whitespace from both ends of the string. "Whitespace" includes spaces, tabs (\t), and newlines (\n). Does not touch characters in the middle of the string. This is the one you will call most often when processing file input.
lstrip() and rstrip()
.lstrip() removes from the left (leading) end only.
.rstrip() removes from the right (trailing) end only.
When reading files, every line ends with a newline \n. Use .rstrip() or .strip() to remove it before processing.
Stripping Specific Characters
Pass a string argument to strip those specific characters instead of whitespace. "***alert***".strip('*') returns "alert". The argument is a set of characters to remove, not a substring — all matching characters from the edge are removed.
# Every line read from a file ends with '\n' — strip it raw_line = " ERROR: disk usage at 94%\n" clean = raw_line.strip() print(repr(raw_line)) # ' ERROR: disk usage at 94%\n' print(repr(clean)) # 'ERROR: disk usage at 94%' # lstrip: remove only leading whitespace print(" hello ".lstrip()) # 'hello ' # rstrip: remove only trailing whitespace (common when reading files) print(" hello ".rstrip()) # ' hello' # Strip specific characters from edges print("###CRITICAL###".strip('#')) # CRITICAL print("/var/log/syslog/".rstrip('/')) # /var/log/syslog
Slide 8 of 36
String Methods: split()
Break one string into a list of smaller strings by cutting at a delimiter.
Default: Split on Any Whitespace
Called with no arguments, .split() splits on any whitespace (spaces, tabs, newlines) and discards consecutive whitespace. It handles extra spaces between words automatically. Returns a list of strings.
Split on a Specific Delimiter
Pass a string argument: .split(',') splits on commas, .split(':') on colons, .split('\t') on tabs. The delimiter is consumed — it does not appear in the resulting list. Use this to parse CSV lines, key=value config lines, and structured log formats.
# Split syslog line into its components line = "2024-11-14 08:22:01 ERROR sshd: Failed password for root" parts = line.split() # split on any whitespace print(parts[0]) # 2024-11-14 (date) print(parts[1]) # 08:22:01 (time) print(parts[2]) # ERROR (severity) # Split a CSV line on comma csv_line = "hostname,192.168.1.10,open,443" fields = csv_line.split(",") print(fields) # ['hostname', '192.168.1.10', 'open', '443'] print(fields[1]) # 192.168.1.10 # Split a config line on '=' (maxsplit=1 stops after the first split) config_line = "db_host=db-prod-01.internal" key, value = config_line.split("=", 1) print(key) # db_host print(value) # db-prod-01.internal
maxsplit parameter: .split('=', 1) splits at most once. Use this when the value portion of a config line might itself contain the delimiter (e.g., a password containing an equals sign).
Slide 9 of 36
String Methods: join()
The opposite of split. Combine a list of strings into one string with a separator between each item.
Syntax Is Reversed — Read Carefully
The separator string calls .join(), and the list is the argument: separator.join(list). This trips up nearly everyone at first. Think of the separator as the glue, and the list as the pieces being glued together.
Why join() Instead of a Loop?
You could concatenate list items in a for loop, but that creates a new string on every iteration, which is slow for large lists. .join() allocates the final string once and fills it in. For 10,000 items, .join() is many times faster.
# Rebuild a CSV line from a list of fields fields = ["hostname", "192.168.1.10", "open", "443"] csv = ",".join(fields) print(csv) # hostname,192.168.1.10,open,443 # Build a filesystem path from components parts = ["", "var", "log", "nginx", "access.log"] filepath = "/".join(parts) print(filepath) # /var/log/nginx/access.log # Join words with a space (common for rebuilding split text) words = ["Failed", "password", "for", "root"] sentence = " ".join(words) print(sentence) # Failed password for root # Join without separator — concatenate directly octets = ["192", "168", "1", "10"] print(".".join(octets)) # 192.168.1.10
Slide 10 of 36
String Methods: find(), index(), rfind()
Locate the position of a substring within a string.
find()
Returns the index of the first occurrence of the substring. Returns -1 if not found — it does not crash. Always check the return value before using it as an index. Optionally pass start and end positions to search a slice.
index()
Identical to .find() except it raises a ValueError if the substring is not found. Use .index() only when you are certain the substring exists and want the program to crash visibly if it does not.
rfind()
Like .find() but searches from the right and returns the index of the last occurrence. Useful for finding the last slash in a file path or the last occurrence of a delimiter in a line.
# Search for a substring in a log line line = "Nov 14 08:22:01 server01 sshd[8821]: Failed password for root" pos = line.find("Failed") print(pos) # 37 (index where 'Failed' starts) print(line[pos:]) # Failed password for root # find() returns -1 when not found — safe to check print(line.find("ERROR")) # -1 (not found) if line.find("Failed") != -1: print("Authentication failure detected") # rfind: locate the last slash to extract a filename path = "/var/log/nginx/access.log" last_slash = path.rfind("/") filename = path[last_slash + 1:] print(filename) # access.log

String Methods: replace()
Substitute all occurrences of a substring with a new value. Returns a new string.
Syntax
s.replace(old, new) — replaces every occurrence of old with new.
s.replace(old, new, count) — replaces at most count occurrences.
Returns a new string. The original is unchanged. Case-sensitive.
IT Use Cases
Sanitize log output before writing to a report. Replace old server names with new ones in a config file. Strip unwanted characters from user input. Mask sensitive values: replace the actual password with asterisks.
# Replace all occurrences config = "server=web-old-01\nbackup=web-old-02\nprimary=web-old-01" updated = config.replace("web-old-01", "web-new-01") print(updated) # server=web-new-01 # backup=web-old-02 # primary=web-new-01 # Replace with a count limit (only first 1 occurrence) text = "error error error" print(text.replace("error", "ERROR", 1)) # ERROR error error # Remove a character by replacing it with an empty string dirty = "192.168.1.10\r" # carriage return from a Windows file clean = dirty.replace("\r", "") print(repr(clean)) # '192.168.1.10' # Mask a password in a log message msg = "Connecting with password=s3cr3tP@ss to db-prod" safe = msg.replace("s3cr3tP@ss", "********") print(safe) # Connecting with password=******** to db-prod
Slide 13 of 36
String Methods: count(), startswith(), endswith()
Count occurrences and test the edges of a string without scanning the whole thing.
count()
Returns the number of non-overlapping occurrences of the substring. "aaa".count("aa") returns 1, not 2 — after matching at index 0, it continues from index 2. Accepts optional start and end arguments to limit the search range.
startswith()
Returns True if the string begins with the specified prefix. Accepts a tuple of prefixes — returns True if the string starts with any of them. More efficient than a slice comparison for this purpose.
endswith()
Returns True if the string ends with the specified suffix. Also accepts a tuple. Very useful for checking file extensions: filename.endswith(('.log', '.txt')) tests both in one call.
# count: how many times does 'timeout' appear in a log block? log_block = "timeout on db01\ntimeout on db02\nconnected to db03\ntimeout on db04" print(log_block.count("timeout")) # 3 # startswith: filter only error lines from a log lines = [ "ERROR: disk full on /dev/sda1", "INFO: backup completed", "ERROR: NIC down on eth0", "WARNING: memory at 88%", ] errors = [l for l in lines if l.startswith("ERROR")] print(errors) # ['ERROR: disk full on /dev/sda1', 'ERROR: NIC down on eth0'] # endswith with a tuple: find log and config files in a list files = ["syslog.log", "readme.txt", "httpd.conf", "auth.log"] logs = [f for f in files if f.endswith(('.log', '.conf'))] print(logs) # ['syslog.log', 'httpd.conf', 'auth.log']

String Methods: isdigit(), isalpha(), isalnum(), isspace()
Test the contents of a string before processing it. Returns True or False.
What These Methods Test
.isdigit() — True if every character is a digit (0-9).
.isalpha() — True if every character is a letter (a-z, A-Z).
.isalnum() — True if every character is a letter or digit.
.isspace() — True if every character is whitespace (space, tab, newline).
All return False for an empty string.
When to Use Them
Validate user input before converting. Check that a port number field contains only digits before calling int(). Detect blank lines in a file. Verify that a username contains only alphanumeric characters. These checks prevent crashes caused by malformed data.
# isdigit: validate port number before converting port_input = "8080" if port_input.isdigit(): port = int(port_input) print(f"Scanning port {port}") # Scanning port 8080 else: print("Invalid port — must be numeric") # isalpha: check that a hostname label has no digits print("webserver".isalpha()) # True print("web01".isalpha()) # False — contains digits print("web01".isalnum()) # True — letters and digits only # isspace: skip blank lines when reading a config file lines = ["[global]", " ", "port=22", "\n", "host=0.0.0.0"] for line in lines: if not line.strip().isspace() and line.strip(): print(line.strip())
Note: .isdigit() returns False for "3.14" because the decimal point is not a digit. To validate a float-like string, use a try/except around float() — covered in Week 4.
Slide 15 of 36
f-String Formatting: Format Specifications
Control how values look inside f-strings using format specs after the colon.
Decimal Places: :.2f
{value:.2f} formats a float to 2 decimal places. The f means fixed-point notation. Change the number to control precision. :.4f gives 4 decimal places. Essential for displaying percentages and measurements.
Width and Alignment: :>10
{value:>10} right-aligns the value in a field 10 characters wide. < left-aligns. ^ centers. Padding fills with spaces by default. Use this to produce columns that line up in terminal output or report files.
Zero-Padding: :05d
{value:05d} formats an integer in a field of width 5, padded with zeros on the left. d means decimal integer. Use this when generating sequential filenames, log record IDs, or zero-padded timestamps.
# Practical: format a system health report row hostname = "db-prod-01" cpu = 73.6781 mem = 88.5 disk = 94 # :.1f = 1 decimal place, :<14 = left-align in 14 chars, :5.1f = width 5 with 1 decimal print(f"{'Host':<14} {'CPU':>7} {'MEM':>7} {'DISK':>7}") print(f"{hostname:<14} {cpu:7.1f}% {mem:7.1f}% {disk:7}%") # Host CPU MEM DISK # db-prod-01 73.7% 88.5% 94% # Zero-padded file number for log rotation naming for i in range(1, 6): print(f"archive_{i:04d}.log") # archive_0001.log # archive_0002.log ...
Slide 16 of 36
String Formatting: The .format() Method
The older formatting style, still common in production codebases built before Python 3.6.
Positional and Named Placeholders
{} placeholders are filled in order from left to right by the arguments to .format(). You can also use numeric indices {0}, {1} to refer to specific arguments by position, or named placeholders {host} with keyword arguments.
f-string vs .format()
f-strings are faster, more readable, and the modern standard. Use f-strings for new code. Understand .format() because you will read it in existing scripts, Stack Overflow answers, documentation examples, and vendor tools written before 2016.
# Positional placeholders — filled left to right msg = "Host {} is running on port {}".format("web-prod-01", 443) print(msg) # Host web-prod-01 is running on port 443 # Indexed placeholders — reuse or reorder arguments template = "[{0}] {1} — {1} triggered on {0}" print(template.format("db-prod-01", "CRITICAL")) # [db-prod-01] CRITICAL — CRITICAL triggered on db-prod-01 # Named placeholders — clearer for multi-field strings report = "Host: {host}\nStatus: {status}\nUptime: {uptime}h" print(report.format(host="app-prod-02", status="OK", uptime=312)) # Host: app-prod-02 # Status: OK # Uptime: 312h # Format specs work the same way as in f-strings print("CPU: {:.1f}%".format(73.6781)) # CPU: 73.7%
Slide 17 of 36
Escape Characters & Raw Strings
Special character sequences that represent characters you cannot type directly.
Common Escape Sequences
\n — newline (moves to next line)
\t — tab (horizontal indent)
\\ — literal backslash
\' — literal single quote inside single-quoted string
\" — literal double quote inside double-quoted string
Raw Strings: r"..."
A raw string prefixed with r treats every backslash as a literal character, not an escape sequence. Used for Windows file paths and regular expression patterns where backslashes are meaningful. r"C:\Users\admin\logs" does not interpret \U or \a.
Why This Matters for File Paths
On Windows, file paths use backslashes: C:\Users\alice. In a Python string, \U and \a are escape sequences. Either double every backslash (C:\\Users\\alice) or use a raw string (r"C:\Users\alice"). On Linux/macOS this is not an issue — paths use forward slashes.
# Newline and tab in a formatted report report = "Host: db-prod-01\nStatus: OK\nUptime: 312h" print(report) # Host: db-prod-01 # Status: OK # Uptime: 312h # Literal backslash in a Windows path (double each backslash) path1 = "C:\\Users\\admin\\Documents\\logs" print(path1) # C:\Users\admin\Documents\logs # Same path using a raw string — easier to read path2 = r"C:\Users\admin\Documents\logs" print(path2) # C:\Users\admin\Documents\logs # repr() shows escape sequences explicitly — useful for debugging line = "192.168.1.10\r\n" print(repr(line)) # '192.168.1.10\r\n' (shows the \r and \n literally)

String Methods: Quick Reference
Everything covered in slides 6-16 in one place. Return a new string unless noted.
Case & Cleanup
.upper() — all uppercase
.lower() — all lowercase
.title() — first letter of each word up
.capitalize() — first letter up only
.strip() — remove edge whitespace
.lstrip() / .rstrip() — one side only
Split, Join, Replace
.split(sep) — string to list
sep.join(list) — list to string
.replace(old, new) — substitute all
.replace(old, new, n) — substitute n times
Search & Test
.find(s) — index or -1
.index(s) — index or ValueError
.rfind(s) — last occurrence
.count(s) — number of occurrences
.startswith(s) — True/False
.endswith(s) — True/False
.isdigit() / .isalpha() / .isalnum()
The Golden Rule
String methods do not change the original string. They return a new one. You must assign the result: line = line.strip() not just line.strip(). If you call a method and wonder why nothing changed — this is the reason.
You can chain methods: line.strip().lower().replace("error", "ERROR") — each method runs on the result of the previous one. Useful but keep chains short so they remain readable.

File I/O: Why Files Matter for IT
Nearly everything in IT is stored in a file. Learning to read and write files is foundational.
Configuration Files
Every service you run reads its settings from a file: /etc/ssh/sshd_config, /etc/nginx/nginx.conf, C:\Windows\System32\drivers\etc\hosts. Scripts that deploy and configure services must read and write these files.
Log Files
Services write their events to log files: /var/log/syslog, /var/log/auth.log, /var/log/nginx/access.log. Parsing logs with Python lets you extract error counts, detect intrusions, and generate alerts automatically.
CSV and Data Files
Inventory spreadsheets exported from Excel. Network scan results from Nmap. User account lists from Active Directory. All of these become CSV files that Python scripts can read, filter, and transform without human interaction.
This is the scenario we are building toward: a file called syslog.txt contains 500 log lines. Your script will open it, read every line, count how many are ERROR, WARNING, and INFO, then write a summary report to report.txt. By the end of today's slides, you will have every tool needed to write that script.
Slide 20 of 36
Opening Files: open() and File Modes
open() creates a connection between your Python script and a file on disk.
Syntax
open(filename, mode, encoding)
filename — path to the file as a string.
mode — what you intend to do (read, write, append).
encoding — character encoding. Always specify encoding='utf-8' for text files to avoid platform-specific surprises.
File Modes
'r' — read (default). File must exist.
'w' — write. Creates the file, or overwrites it entirely if it exists.
'a' — append. Creates the file if missing, adds to the end if it exists.
'x' — exclusive create. Fails with an error if the file already exists.
# Open for reading — file must already exist f = open("syslog.txt", "r", encoding="utf-8") content = f.read() f.close() # always close when done — frees the file handle # Open for writing — DESTROYS existing content f = open("report.txt", "w", encoding="utf-8") f.write("Daily Log Summary\n") f.close() # Open for appending — preserves existing content f = open("report.txt", "a", encoding="utf-8") f.write("New entry added\n") f.close()
Critical Warning
Opening an existing file in mode 'w' immediately erases all of its contents, even before you write anything new. There is no confirmation prompt. This is one of the most common data loss mistakes in scripting. Be certain before using write mode on a file that matters.
Slide 21 of 36
The with Statement: Context Manager
The right way to work with files. Automatically closes the file even if an exception occurs.
What It Does
The with statement creates a context. When execution leaves the with block — whether normally or because an exception was raised — Python automatically calls the file's .close() method. You cannot forget to close the file. This is not optional best practice — it is the standard pattern.
Why It Matters
A file that is not properly closed can hold a lock on disk, leave write buffers unflushed (data you wrote may not actually appear in the file), and exhaust the operating system's file descriptor limit if many files are opened in a loop. The with statement eliminates all three risks.
# Without with — must remember to close, no protection from crashes f = open("syslog.txt", "r", encoding="utf-8") content = f.read() f.close() # if an error occurs before this line, file stays open forever # With 'with' — close is guaranteed, always use this form with open("syslog.txt", "r", encoding="utf-8") as f: content = f.read() # f is automatically closed here, even if an exception occurred above # Open two files at once with a single with statement with open("syslog.txt", "r", encoding="utf-8") as src, \ open("report.txt", "w", encoding="utf-8") as dst: for line in src: if "ERROR" in line: dst.write(line)
Rule: From this point forward, every file you open in this course uses the with statement. No exceptions. If you open a file without with on a submitted assignment, points will be deducted.

Reading Files: read(), readline(), readlines()
Three methods for reading file content. Choose based on size and how you need to process the data.
read()
Reads the entire file into a single string. Simple for small files. Dangerous for large files — a 500 MB log file becomes a 500 MB string in memory. The string includes all newlines as \n characters.
readline()
Reads one line at a time. Each call advances the file position to the next line. Returns an empty string "" when there are no more lines. Rarely used directly — the for loop approach (slide 24) is cleaner for most purposes.
readlines()
Reads all lines and returns a list of strings, one string per line. Each string includes the trailing \n. Use when you need random access to specific line numbers. For sequential processing, use the for loop instead.
# File: syslog.txt (first 3 lines shown) # Nov 14 08:20:01 server01 sshd: Accepted publickey for alice # Nov 14 08:22:01 server01 sshd: Failed password for root # Nov 14 08:25:14 server01 CRON: session opened for root # read() — whole file as one string with open("syslog.txt", "r", encoding="utf-8") as f: all_text = f.read() print(type(all_text)) # <class 'str'> # readlines() — list of lines with open("syslog.txt", "r", encoding="utf-8") as f: lines = f.readlines() print(lines[0]) # 'Nov 14 08:20:01 server01 sshd: Accepted publickey for alice\n' print(lines[1]) # 'Nov 14 08:22:01 server01 sshd: Failed password for root\n'
Slide 24 of 36
Reading Files: Line-by-Line with a for Loop
The most memory-efficient way to read a file. Python loads one line at a time.
Why This Is the Right Default
When you iterate a file object directly in a for loop, Python reads one line at a time from disk, processes it, then discards it. A 1 GB log file uses only a few kilobytes of memory at any point. readlines() loads the entire file into RAM first — fine for small files, a problem for large ones.
Each Line Includes the Newline
Every line delivered by the for loop ends with \n (or \r\n on Windows line endings). Always call .strip() or .rstrip() as your first operation on each line. If you skip this, trailing whitespace causes your string comparisons to fail silently.
# Count lines by severity level in a syslog file error_count = 0 warning_count = 0 info_count = 0 with open("syslog.txt", "r", encoding="utf-8") as f: for line in f: line = line.strip() # remove trailing \n every time if not line: # skip blank lines continue parts = line.split() # tokenize on whitespace if len(parts) >= 5: level = parts[4].upper() if level == "ERROR": error_count += 1 if level == "WARNING": warning_count += 1 if level == "INFO": info_count += 1 print(f"ERROR: {error_count}") print(f"WARNING: {warning_count}") print(f"INFO: {info_count}")

Writing Files: write() and writelines()
Two methods for writing text to a file. write() for single strings, writelines() for lists.
write()
Writes a single string to the file. Does not add a newline automatically — you must include \n if you want each call to start on a new line. Returns the number of characters written (you can ignore this return value in most scripts).
writelines()
Accepts a list (or any iterable) of strings and writes them one after another. Does not add newlines between items — if each string in the list should be on its own line, the newline must already be part of the string. Use a list comprehension to add \n if needed.
# write(): one string at a time, newlines are your responsibility with open("report.txt", "w", encoding="utf-8") as f: f.write("=== Daily Log Summary ===\n") f.write(f"Date: 2024-11-14\n") f.write(f"ERROR: 12\n") f.write(f"WARNING: 47\n") f.write(f"INFO: 383\n") # writelines(): write a list of strings all at once lines = [ "=== Daily Log Summary ===\n", "Date: 2024-11-14\n", "ERROR: 12\n", "WARNING: 47\n", ] with open("report.txt", "w", encoding="utf-8") as f: f.writelines(lines) # Add newlines to a list that doesn't have them items = ["alice", "bob", "charlie"] with open("users.txt", "w", encoding="utf-8") as f: f.writelines(item + "\n" for item in items)
Slide 26 of 36
Appending to Files: Mode 'a'
Add new content to the end of an existing file without destroying what is already there.
When to Use Append Mode
Use 'a' when you are adding to a file that should accumulate data over time: an audit log, a daily report, a list of completed jobs. The file pointer starts at the end of the existing content. If the file does not exist, mode 'a' creates it — same as 'w' in that regard.
Append vs Write — Know the Difference
Mode 'w' truncates (empties) the file first. Mode 'a' does not. This is the entire difference. A script that runs on a schedule and opens its log file with 'w' will erase the previous run's output every time. Open with 'a' to keep a running history.
# Script that runs nightly — appends to a running audit log import datetime timestamp = datetime.datetime.now().strftime("%Y-%m-%d %H:%M:%S") summary = f"[{timestamp}] Scan complete — 3 hosts unreachable\n" # Append mode: adds to the end, never overwrites with open("audit.log", "a", encoding="utf-8") as f: f.write(summary) # After three nightly runs, audit.log contains: # [2024-11-12 02:00:01] Scan complete — 1 host unreachable # [2024-11-13 02:00:02] Scan complete — 0 hosts unreachable # [2024-11-14 02:00:01] Scan complete — 3 hosts unreachable
Common pattern: A script opens a results file in 'w' mode at the start to create a fresh report for that run, then closes it. If the same script is also writing an audit trail, it opens the audit file in 'a' mode. Two separate files, two different modes, each serving a different purpose.
Slide 27 of 36
File Paths: Relative, Absolute, and os.path
Getting the path right is the difference between your script running and a FileNotFoundError.
Relative Paths
Relative to the current working directory when the script runs. "syslog.txt" looks in the same folder as the script. "logs/syslog.txt" looks in a logs subfolder. The CWD can change based on where you launch the script from — this trips up beginners constantly.
Absolute Paths
A full path from the root of the filesystem. "/var/log/syslog" on Linux. "C:\\Logs\\syslog.txt" on Windows. Always works regardless of where you run the script from. Use absolute paths in production scripts on servers. Use relative paths for portable code that travels with its data files.
os.path Basics
The os.path module provides platform-safe path operations. os.path.exists() checks before opening. os.path.join() builds paths correctly on both Windows and Linux. os.path.basename() extracts just the filename from a full path.
import os # os.path.join: builds the correct path for the current OS # On Linux: /var/log/syslog | On Windows: C:\var\log\syslog path = os.path.join("var", "log", "syslog") print(path) # var/log/syslog (Linux) or var\log\syslog (Windows) # os.path.exists: check before opening to give a clearer error log_path = "/var/log/auth.log" if os.path.exists(log_path): with open(log_path, "r", encoding="utf-8") as f: print(f.readline().strip()) else: print(f"Log file not found: {log_path}") # os.path.basename: extract filename from a full path full = "/var/log/nginx/access.log" print(os.path.basename(full)) # access.log print(os.path.dirname(full)) # /var/log/nginx

CSV Files: Parsing Manually with split()
CSV is the lingua franca of data exchange in IT. Every tool exports to it.
What a CSV File Looks Like
Comma-Separated Values. Each row is one line. Fields within a row are separated by commas. The first row is usually a header naming each column. Some CSVs use a tab or semicolon as the delimiter instead — the approach is the same, just change the delimiter in .split().
Manual Parsing vs csv Module
For simple CSVs with no quoted fields containing commas, .split(',') is sufficient. Python also has a built-in csv module that handles quoted fields, escaping, and edge cases automatically. This slide covers the manual approach — the csv module is covered in a later week.
# File: network_hosts.csv # hostname,ip_address,status,open_port # web-prod-01,192.168.10.5,up,443 # db-prod-01,192.168.10.10,up,5432 # backup-01,192.168.10.20,down,0 with open("network_hosts.csv", "r", encoding="utf-8") as f: header = f.readline().strip() # read and skip the header row print(f"Columns: {header}") for line in f: line = line.strip() if not line: continue fields = line.split(",") # split on comma hostname, ip, status, port = fields # unpack directly if status == "down": print(f"ALERT: {hostname} ({ip}) is DOWN") # Output: # Columns: hostname,ip_address,status,open_port # ALERT: backup-01 (192.168.10.20) is DOWN

IT Scenario: Parse a Syslog File
Count ERROR, WARNING, and INFO lines in a real syslog format file.

# File: syslog.txt (sample lines) # Nov 14 08:20:01 server01 INFO sshd: session opened for alice # Nov 14 08:22:01 server01 ERROR sshd: Failed password for root # Nov 14 08:23:44 server01 WARNING kernel: disk usage 88% on /dev/sda1 # Nov 14 08:25:14 server01 INFO CRON: session opened for root # Nov 14 08:30:02 server01 ERROR sshd: Failed password for admin counts = {"ERROR": 0, "WARNING": 0, "INFO": 0, "OTHER": 0} with open("syslog.txt", "r", encoding="utf-8") as f: for line in f: line = line.strip() if not line: continue parts = line.split() level = parts[4].upper() if len(parts) > 4 else "OTHER" if level in counts: counts[level] += 1 else: counts["OTHER"] += 1 print(f"ERROR: {counts['ERROR']:>5}") print(f"WARNING: {counts['WARNING']:>5}") print(f"INFO: {counts['INFO']:>5}") # ERROR: 2 # WARNING: 1 # INFO: 2

Common Mistakes: File I/O Pitfalls
Errors that every beginner makes. Learn them here so you make them at most once.
Forgetting to Close the File
When you call f.write(), Python buffers the data in memory. It is only guaranteed to reach the disk when the file is closed. If the script crashes before f.close(), the data may be lost. Use with to make this impossible — the close happens automatically.
Using 'w' When You Mean 'a'
Opening an existing file with mode 'w' silently erases everything in it. No warning. No confirmation. Before writing, ask yourself: should the previous content survive? If yes, use 'a'. If you are building a fresh report each run, 'w' is correct.
FileNotFoundError
Opening a file with 'r' when the file does not exist raises FileNotFoundError. Check the path carefully — it is usually a typo or a wrong working directory. Use os.path.exists() to check first, or use try/except (slide 34) to handle it gracefully.
# Mistake 1: not using 'with' — data lost on crash f = open("output.txt", "w") f.write("important data") # script crashes here — output.txt may be empty # Mistake 2: stripping the wrong side — comparison fails line = "ERROR: disk full\n" if line == "ERROR: disk full": # False! \n is still there print("match") if line.strip() == "ERROR: disk full": # True print("match") # Mistake 3: reading after the file pointer is exhausted with open("syslog.txt", "r") as f: all_text = f.read() # reads entire file, pointer now at end lines = f.readlines() # returns [] — nothing left to read

try/except Preview: Handling FileNotFoundError
A brief look at error handling before it is fully covered in Week 4.
What Is an Exception?
When Python encounters an error at runtime — a file that doesn't exist, a division by zero, a variable that is the wrong type — it raises an exception. If your code does not catch the exception, the entire program stops and prints a traceback. try/except lets you catch the exception and decide what to do instead of crashing.
FileNotFoundError
Raised when you try to open a file with mode 'r' and the file does not exist. This is the most common file I/O exception you will encounter. Catching it lets you print a helpful message and exit cleanly instead of dumping a traceback at the user.
# Without error handling — crashes with a traceback with open("missing.txt", "r") as f: content = f.read() # FileNotFoundError: [Errno 2] No such file or directory: 'missing.txt' # With try/except — graceful failure try: with open("syslog.txt", "r", encoding="utf-8") as f: content = f.read() print(f"Read {len(content)} characters") except FileNotFoundError: print("Error: syslog.txt not found. Check the file path and try again.") except PermissionError: print("Error: permission denied. Run as root or check file permissions.") # Week 4 covers: multiple exception types, else, finally, raising your own exceptions
Rule for now: When you write a script that opens a file given by a user (a path typed at the command line, for example), always wrap the open() call in a try/except FileNotFoundError block. It takes two extra lines and makes your scripts professional.
