GUI Lab: Build a Server Status Tool

Step-by-step — build a complete GUI application from scratch. Each step adds one concept.

Step 1 of 10

Create the Window

Start a new file called server_tool.py. Create a window with a title and fixed size.

import tkinter as tk root = tk.Tk() root.title("Server Status Tool") root.geometry("450x350") root.resizable(False, False) root.configure(bg="#1a1a2e") # Everything else goes here root.mainloop()
Checkpoint: Run it. You should see a 450x350 dark window with "Server Status Tool" in the title bar. It should NOT be resizable.
Why resizable(False, False)? Your layout is designed for 450x350. If the user resizes, your widgets will shift and overlap. Lock the size until you learn responsive layouts.
Step 2 of 10

Add a Title Label

Add a heading at the top of the window. This teaches tk.Label with font and color styling.

# Add ABOVE root.mainloop() title_label = tk.Label( root, text="Server Status Tool", font=("Arial", 18, "bold"), fg="#c9a83a", # gold text bg="#1a1a2e" # match window background ) title_label.pack(pady=15)
Checkpoint: You should see "Server Status Tool" in gold, centered at the top with 15 pixels of padding above and below.
Why fg= and bg=? fg is foreground (text color). bg is background. If you don't set bg, the label gets a default gray background that looks wrong on your dark window. Always match the parent.
Step 3 of 10

Add an Input Field

Create a label + entry pair for the server IP address. This teaches tk.Entry and layout pairing.

# Frame to hold the input row input_frame = tk.Frame(root, bg="#1a1a2e") input_frame.pack(pady=10) ip_label = tk.Label( input_frame, text="Server IP:", font=("Arial", 11), fg="white", bg="#1a1a2e" ) ip_label.grid(row=0, column=0, padx=5) ip_entry = tk.Entry(input_frame, width=25, font=("Consolas", 11)) ip_entry.grid(row=0, column=1, padx=5) ip_entry.insert(0, "192.168.1.1") # default value
Checkpoint: Label says "Server IP:" on the left. Entry field on the right with "192.168.1.1" pre-filled. They sit on the same row because of grid(row=0).
Why Frame? We used pack() for the title label and now need grid() for the label+entry pair. You can't mix pack and grid in the SAME parent. The Frame acts as a container — grid inside the frame, pack the frame itself.
Step 4 of 10

Add the Check Button

Create a button that will trigger the status check. This teaches tk.Button and the command= pattern.

# Define the function FIRST def check_status(): ip = ip_entry.get() result_text.delete("1.0", tk.END) result_text.insert(tk.END, f"Checking {ip}...\n") result_text.insert(tk.END, f"Status: ONLINE\n") result_text.insert(tk.END, f"Response: 12ms\n") # Then create the button that calls it check_btn = tk.Button( root, text="Check Status", command=check_status, # NO parentheses! font=("Arial", 11, "bold"), bg="#c9a83a", fg="#000", cursor="hand2", width=15 ) check_btn.pack(pady=10)
Checkpoint: Gold button appears below the input. Clicking it will crash because result_text doesn't exist yet — that's Step 5.
Why no parentheses? command=check_status passes the function as a reference — "call this later when clicked." command=check_status() CALLS the function immediately when the button is created, then passes None as the command. The button would do nothing on click.
Step 5 of 10

Add the Results Area

Create a multiline text widget to display server check results.

result_text = tk.Text( root, width=50, height=8, font=("Consolas", 10), bg="#0d1117", fg="#3ab577", # dark bg, green text relief="sunken" # inset border style ) result_text.pack(padx=20, pady=5)
Checkpoint: Dark text area appears below the button. Click "Check Status" — it should now show "Checking 192.168.1.1..." with green text on dark background.
Why Consolas font? Monospace fonts align columns perfectly — essential for displaying structured data like IP addresses, log entries, and status tables. This is standard for any IT tool display.
Step 6 of 10

Add a Status Bar

A label at the bottom that shows the current state. Uses StringVar for dynamic updates.

status_var = tk.StringVar(value="Ready") status_bar = tk.Label( root, textvariable=status_var, font=("Arial", 9), fg="#64748b", bg="#12121e", anchor="w", # left-align text padx=10 ) status_bar.pack(side=tk.BOTTOM, fill=tk.X) # Update your check_status function to use it: def check_status(): ip = ip_entry.get() status_var.set(f"Checking {ip}...") # status bar updates! result_text.delete("1.0", tk.END) result_text.insert(tk.END, f"Checking {ip}...\n") result_text.insert(tk.END, f"Status: ONLINE\n") status_var.set(f"Last checked: {ip}")
Checkpoint: Gray bar at the bottom shows "Ready". Click Check Status — it updates to "Checking..." then "Last checked: 192.168.1.1".
Why StringVar instead of label.config(text=)? Both work. But StringVar can be shared — multiple widgets can watch the same variable. Change it once, everything updates. This is the pattern professional apps use.
Step 7 of 10

Add a Clear Button

A second button that clears the results. Reinforces the function-per-button pattern.

def clear_results(): result_text.delete("1.0", tk.END) ip_entry.delete(0, tk.END) status_var.set("Cleared") # Add a button frame for side-by-side buttons btn_frame = tk.Frame(root, bg="#1a1a2e") btn_frame.pack(pady=10) check_btn = tk.Button( btn_frame, text="Check Status", command=check_status, bg="#c9a83a", fg="#000", font=("Arial", 11, "bold"), width=15, cursor="hand2" ) check_btn.grid(row=0, column=0, padx=5) clear_btn = tk.Button( btn_frame, text="Clear", command=clear_results, bg="#374151", fg="white", font=("Arial", 11), width=10, cursor="hand2" ) clear_btn.grid(row=0, column=1, padx=5)
Checkpoint: Two buttons side by side — gold "Check Status" and gray "Clear". Clear empties the text area, entry field, and updates the status bar.
Why a Frame for buttons? Same reason as Step 3 — we need grid() to put buttons side by side, but the parent uses pack(). The Frame is the bridge. One Frame, two buttons inside, grid them.
Step 8 of 10

Add Input Validation with messagebox

If the user clicks Check with an empty IP field, show an error dialog instead of proceeding.

from tkinter import messagebox # add at top of file # Update check_status to validate first: def check_status(): ip = ip_entry.get().strip() if not ip: messagebox.showerror("Error", "Please enter a server IP address.") return status_var.set(f"Checking {ip}...") result_text.delete("1.0", tk.END) result_text.insert(tk.END, f"Checking {ip}...\n") result_text.insert(tk.END, f"Status: ONLINE\n") result_text.insert(tk.END, f"Response: 12ms\n") status_var.set(f"Last checked: {ip}")
Checkpoint: Clear the IP field and click Check Status. A red error dialog should pop up saying "Please enter a server IP address." Click OK and the dialog closes.
Why messagebox? Users make mistakes. Instead of crashing or silently doing nothing, you give them clear feedback. showerror() for problems, showinfo() for success, askquestion() for confirmations. Always validate before processing.
Step 9 of 10

Add Keyboard Binding: Enter Key

Let users press Enter in the IP field instead of clicking the button. This teaches .bind().

# bind() needs a function that accepts an event parameter def on_enter_key(event): check_status() # Bind the Enter key to the entry widget ip_entry.bind("<Return>", on_enter_key) # Why event parameter? # bind() always passes an event object to the handler. # command= does NOT pass anything. # That's the difference between the two.
Checkpoint: Type an IP in the entry field and press Enter. It should trigger the status check without clicking the button.
command= vs bind(): command= is for buttons only — simple, no arguments. bind() works on ANY widget for ANY event — keyboard, mouse, focus. But the handler MUST accept an event parameter even if you don't use it. That's why we wrap check_status() inside on_enter_key(event).
