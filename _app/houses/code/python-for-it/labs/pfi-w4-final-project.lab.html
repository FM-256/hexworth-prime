Requirements Review

20 minutes
Project Brief: You will build an IT utility tool of your choice. Options are listed below. Your program must meet all technical requirements. Read them carefully before writing a single line of code.

Approved Project Ideas (choose one)

  • A. Network scanner — scans a range of ports on a host and reports which are open, using socket with try/except
  • B. Log analyzer — reads a log file, counts occurrences of each IP or error type, flags suspicious entries, saves a report
  • C. Password strength checker — evaluates a password against length, complexity, and common-password rules; accepts multiple words from a file
  • D. Subnet calculator GUI — tkinter interface that accepts a CIDR notation input and displays network address, broadcast, usable range, and host count
  • E. Contact/device manager — stores device records in a list of dicts, allows add/search/delete via a menu loop, saves to and loads from a JSON file

Technical Requirements (all projects)

  • 1. Written in Python 3.x — no external libraries beyond the standard library
  • 2. Uses at least three functions with def, each with a docstring
  • 3. At least one loop (for or while) with a meaningful purpose
  • 4. At least one conditional (if/elif/else) making a real decision
  • 5. At least one try/except block handling a realistic error
  • 6. Docstring or header comment at the top of the file describing the program
  • 7. Inline comments on non-obvious lines explaining what the code does
  • 8. Input validation on any user-supplied data before using it

Self-Assessment

Open-ended (after coding)
Complete this section after you have written your program. Read your own code carefully and verify each requirement before submitting. This is not optional — it is part of professional software development practice.

Code Review Checklist

Run your program with normal inputs, boundary inputs (e.g., empty string, port 0, port 65535), and invalid inputs (e.g., letters where a number is expected). Document what happens in each case.

Submission

15 minutes
Final steps before submitting your project file. Complete each task below, then submit the single .py file to your instructor via the course LMS.

Pre-Submission Checklist

  • 1. Run the complete program one final time with fresh test data — no errors on startup
  • 2. Verify the file header comment (description, author, date) is at the top of the file
  • 3. Verify all three functions have docstrings immediately below their def line
  • 4. Count your inline comments — there should be at least one per non-trivial line or block
  • 5. Test one invalid input path (e.g., type letters where a number is expected) — confirm it does not crash
  • 6. Save the file with a meaningful name: lastname_firstname_final.py
  • 7. Upload to the course LMS assignment
File naming matters: Instructors grade dozens of files named final.py or project.py. Name yours lastname_firstname_final.py so it is immediately identifiable. This is the same convention used in professional code review systems.
