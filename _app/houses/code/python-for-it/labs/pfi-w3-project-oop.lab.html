Project Overview

Read carefully before coding
What You Are Building: An object-oriented Python program that models a small network environment. You will define a class hierarchy for network devices, build a manager class that stores and queries devices, and use turtle graphics to draw a labeled topology diagram of the devices currently in the manager.

Why This Matters

Network automation tools — Netmiko, NAPALM, Ansible network modules — are built on exactly this pattern: a class hierarchy that models device types, with shared base methods and type-specific behaviors. When you understand how to structure a NetworkDevice class with Router and Switch subclasses, reading those real tools becomes straightforward.

This project exercises the complete Week 3 OOP skill set: class definition, __init__, __str__, inheritance, method overriding, polymorphism, and the DeviceManager collection pattern. The turtle visualization ties OOP to Week 3 graphics work.

Learning Objectives

  • 1. Define classes with __init__ and __str__ methods following Python conventions
  • 2. Use inheritance to extend a base class without duplicating code
  • 3. Override methods in child classes to change behavior while keeping the same interface
  • 4. Demonstrate polymorphism by calling the same method on a mixed list of object types
  • 5. Use turtle graphics to visualize a data structure (the device list) programmatically

Class Architecture Overview

Your program will have four classes and a set of menu functions. The diagram below shows the relationship between them.

NetworkDevice (base class) |-- hostname, ip_address, device_type, status |-- __init__, __str__, ping(), get_info() | +-- Router(NetworkDevice) | |-- routing_protocol (extra attribute) | |-- show_routes() (Router-specific) | |-- get_info() (overrides base) | +-- Switch(NetworkDevice) |-- port_count (extra attribute) |-- show_vlans() (Switch-specific) |-- get_info() (overrides base) DeviceManager |-- devices (list of NetworkDevice objects) |-- add_device(), remove_device() |-- find_device(), list_all() Menu functions (top-level, not methods): show_menu(), handle_add(), handle_remove() handle_ping(), draw_topology()

Sample Program Run

After adding a Router and a Switch, selecting "List Devices" should produce output similar to this:

--- Network Devices --- [router] CORE-RTR-01 | 10.0.0.1 | Status: online Protocol : OSPF Routes : 10.0.0.0/8, 192.168.0.0/24, 0.0.0.0/0 [switch] ACCESS-SW-02 | 10.0.0.5 | Status: online Ports : 48 VLANs : VLAN 1 (default), VLAN 10 (mgmt), VLAN 20 (servers)
Simulated data: You are not connecting to real devices. ping() returns a simulated string like "Reply from 10.0.0.1: bytes=32 time=1ms TTL=128" based on the device's stored IP. show_routes() and show_vlans() return hardcoded or parameter-based lists. The behavior is realistic even though the data is fabricated.

Requirements

Your program must satisfy all 10 items
Grading is based on these requirements. Requirements 1 through 4 cover OOP fundamentals. Requirements 5 through 7 cover organization and visualization. Requirements 8 through 10 cover documentation, design quality, and execution.
  • 1. At least 2 classes have __init__ and __str__ — NetworkDevice, Router, Switch, and DeviceManager all need __init__; at minimum NetworkDevice and one child class need __str__
  • 2. Router and Switch both inherit from NetworkDevice using the class Router(NetworkDevice): syntax; each child calls super().__init__() inside its own __init__
  • 3. Router and Switch each override the get_info() method from NetworkDevice — the child version must return or print different output than the base class version
  • 4. Each class (NetworkDevice, Router, Switch, DeviceManager) has at least 3 methods beyond __init__ and __str__
  • 5. DeviceManager stores all devices in a list attribute called devices; add_device, remove_device (by hostname), find_device (by hostname), and list_all methods are all present and functional
  • 6. Menu operations are implemented as top-level functions (not inside any class); each function handles one menu action and calls manager methods to do the work
  • 7. A draw_topology() function uses turtle to draw each device in the manager as a labeled shape — at minimum a rectangle or circle per device with the hostname printed below it; at least 3 devices must be drawn when 3 are in the manager
  • 8. Every class and every method has a docstring (triple-quoted string immediately after the def line) explaining its purpose
  • 9. At least one loop in the main menu or a menu function iterates over the devices list and calls the same method on each device regardless of type — this demonstrates polymorphism
  • 10. Program runs without errors through a full session: add two devices of different types, list all, ping one, draw topology, remove one, list again, exit
Turtle window blocks execution: turtle.done() keeps the drawing window open but freezes the Python process. Structure your program so draw_topology() is an optional menu choice — do not call it unconditionally at startup or it will block the rest of the program until the user closes the window.

NetworkDevice Base Class Skeleton

class NetworkDevice: """Base class representing a generic network device. Attributes: hostname (str) : device hostname, e.g. CORE-RTR-01 ip_address (str) : IPv4 address, e.g. 10.0.0.1 device_type (str) : 'router', 'switch', etc. status (str) : 'online' or 'offline' """ def __init__(self, hostname, ip_address, device_type, status="online"): """Initialize a NetworkDevice with identity and status fields.""" # Assign parameters to instance attributes pass def __str__(self): """Return a one-line summary string for this device.""" # Return an f-string: "[device_type] hostname | ip_address | Status: status" pass def ping(self): """Simulate a ping to this device and return a result string.""" # Return a string like: "Reply from 10.0.0.1: bytes=32 time=2ms TTL=64" pass def get_info(self): """Return a formatted string with this device's details.""" # Base version: return hostname, ip, type, and status pass def set_status(self, new_status): """Update the device status to the given string.""" pass

Router Child Class Skeleton

class Router(NetworkDevice): """A network router. Extends NetworkDevice with routing information. In a real tool this would query the device. Here, return a simulated list of CIDR strings appropriate for the routing protocol. """ pass def add_route(self, route): """Add a route string to this router's route list.""" pass

Switch Child Class Skeleton

class Switch(NetworkDevice): """A network switch. Extends NetworkDevice with VLAN and port information. Additional Attributes: port_count (int) : number of switchports (e.g. 24 or 48) vlans (list) : list of VLAN description strings """ def __init__(self, hostname, ip_address, port_count=24): """Initialize a Switch — calls super().__init__ with device_type='switch'.""" super().__init__(hostname, ip_address, device_type="switch") self.port_count = port_count self.vlans = ["VLAN 1 (default)"] # every switch starts with VLAN 1 def get_info(self): """Override base get_info to include port count and VLAN list.""" pass def show_vlans(self): """Return the current list of VLAN description strings.""" pass def add_vlan(self, vlan_description): """Add a VLAN description string to this switch's VLAN list.""" pass

DeviceManager Skeleton

class DeviceManager: """Manages a collection of NetworkDevice objects. Provides add, remove, find, and list operations over the internal devices list. """ def __init__(self): """Initialize with an empty device list.""" self.devices = [] def add_device(self, device): """Add a NetworkDevice (or subclass) to the devices list.""" pass def remove_device(self, hostname): """Remove the device with the given hostname. Print a message if not found.""" pass def find_device(self, hostname): """Return the device object matching hostname, or None if not found.""" pass def list_all(self): """Print the get_info() output for every device in the list.""" # This is the polymorphism loop — call get_info() on each device # regardless of whether it is a Router or Switch if not self.devices: print("No devices in manager.") return for device in self.devices: print(device.get_info()) print("-" * 40)

Turtle Topology Function Hint

The draw_topology() function should iterate over manager.devices, draw one labeled shape per device, and space them horizontally across the screen. Use penup/goto to position each shape, then pendown to draw it.

import turtle def draw_topology(manager): """Draw a simple network topology using turtle. Each device is drawn as a rectangle with its hostname labeled below it. Devices are spaced evenly across the screen. """ screen = turtle.Screen() screen.title("Network Topology") screen.bgcolor("#0a0e1a") # match the dark theme t = turtle.Turtle() t.speed(0) # 0 = fastest, no animation delay t.hideturtle() # Starting x position for the first device x_start = -200 x_step = 150 # horizontal gap between devices y_pos = 0 for i, device in enumerate(manager.devices): x = x_start + (i * x_step) # Move to position without drawing t.penup() t.goto(x, y_pos) t.pendown() # Choose color by device type if device.device_type == "router": t.fillcolor("#10b981") # green for routers else: t.fillcolor("#3b82f6") # blue for switches # Draw a 60x40 rectangle t.begin_fill() for _ in range(2): t.forward(60) t.left(90) t.forward(40) t.left(90) t.end_fill() # Write the hostname label below the shape t.penup() t.goto(x + 30, y_pos - 20) t.color("white") t.write(device.hostname, align="center", font=("Arial", 9, "normal")) turtle.done() # keep the window open until the user closes it
Polymorphism made visible: The list_all() loop in DeviceManager calls device.get_info() on every device. Because Router.get_info() and Switch.get_info() produce different output, the same one-line method call produces type-appropriate results without any if/else type-checking. That is polymorphism. Your grader will look for this pattern.
