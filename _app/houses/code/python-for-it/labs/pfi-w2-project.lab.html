Project Overview

What You Are Building: A Python program that reads a structured server log file, parses each line to extract timestamp, severity level, and message, then produces a severity count summary, identifies unique errors, calculates an error rate, and writes a formatted report to an output file.

Why This Matters

Log analysis is one of the most common IT scripting tasks. Sysadmins, security analysts, and DevOps engineers all write scripts to parse logs. The real-world tools you will eventually use (Splunk, ELK Stack, Graylog) are sophisticated versions of exactly what you are building here. Understanding how to read, split, and aggregate log data with raw Python gives you insight into how those platforms work internally.

This project exercises the complete Week 2 skill set: file I/O, string methods, slicing, dictionaries, sets, lists, list comprehensions, and output formatting — all applied to a realistic IT problem.

Expected Output File

Your program should write a file called log_summary.txt. The output should look like the example below. Exact spacing and alignment are part of the Output Formatting rubric category.

==================================== SERVER LOG ANALYSIS REPORT ==================================== Log File : server.log Lines Read : 11 ------------------------------------ SEVERITY COUNTS INFO : 4 WARNING : 3 ERROR : 3 CRITICAL : 1 ------------------------------------ ERROR RATE : 27.27% ------------------------------------ UNIQUE ERRORS (2 total) - Connection refused to database - NIC timeout on eth0 CRITICAL EVENTS (1 total) - Primary database unreachable ====================================
Line format: Each log line follows the pattern: DATE TIME [SEVERITY] MESSAGE. The date is 10 characters, the time is 8 characters, and the severity is wrapped in brackets: [INFO], [WARNING], [ERROR], or [CRITICAL]. Use .strip("[]") to remove the brackets after splitting. Everything after the severity is the message. This consistent structure is what makes string splitting reliable.

Reading and Parsing a Log Line

Each log line has four parts separated by spaces. The split() method with no argument splits on any whitespace and handles consecutive spaces cleanly. Use maxsplit=3 so the message field is kept intact even if it contains spaces.

# Sample line from server.log line = "2026-04-01 09:17:02 [ERROR] Connection refused to database\n" # strip() removes the trailing newline before splitting parts = line.strip().split(maxsplit=3) # parts[0] = "2026-04-01" (date) # parts[1] = "09:17:02" (time) # parts[2] = "[ERROR]" (severity — still has brackets) # parts[3] = "Connection refused to database" (message) date_field = parts[0] # or use slicing: line[:10] severity = parts[2].strip("[]").upper() # strip brackets, then normalize case message = parts[3]

Suggested Data Structure Setup

Initialize these before the loop that reads the file. Adding to a dictionary key that does not exist will raise a KeyError — use the get() method with a default of 0 to handle this safely.

# Severity counter dictionary — keys added dynamically severity_counts = {} # Set for unique ERROR messages — add() ignores duplicates unique_errors = set() # Set for CRITICAL events critical_events = set() # List of all parsed entries as dicts log_entries = [] # --- Inside the file-reading loop --- # Increment the count for this severity level severity_counts[severity] = severity_counts.get(severity, 0) + 1 # Add to the unique errors set only if this is an ERROR line if severity == "ERROR": unique_errors.add(message) # Track CRITICAL events separately if severity == "CRITICAL": critical_events.add(message) # Append the parsed entry to the list log_entries.append({'date': date_field, 'severity': severity, 'message': message})

Error Rate Calculation

Calculate the error rate after the loop finishes. Guard against division by zero in case the file is empty.

# Total lines equals the length of the entries list total_lines = len(log_entries) # Avoid ZeroDivisionError if the file is empty if total_lines > 0: error_count = severity_counts.get("ERROR", 0) error_rate = (error_count / total_lines) * 100 else: error_rate = 0.0

FileNotFoundError Handler

Wrap the file open call in a try/except block. This is the correct Python pattern for handling files that may not exist.

try: with open('server.log', 'r') as f: for line in f: # parse and process each line here pass except FileNotFoundError: print("Error: server.log not found. Place the log file in the same directory as this script.") # Exit the program cleanly after printing the message exit(1)

List Comprehension Hint

After building log_entries, use a list comprehension to filter for a specific severity. This satisfies Requirement 10 and gives you a clean way to count or display a subset.

# Build a list of only the ERROR entries using a comprehension error_entries = [ entry for entry in log_entries if entry['severity'] == "ERROR" ] # error_entries is now a list of dicts, one per ERROR line print(f"Total errors found: {len(error_entries)}")

Writing the Output File

Use the same with open() pattern for writing. Every print() call inside the report section should also write to the file — use the file= parameter so you do not have to duplicate every line.

# Write the report to log_summary.txt with open('log_summary.txt', 'w') as out: # Write a separator line to the file print("=" * 36, file=out) print(f"{'SERVER LOG ANALYSIS REPORT':^36}", file=out) print("=" * 36, file=out) # Right-align the count value in a 4-character field for level in ["INFO", "WARNING", "ERROR", "CRITICAL"]: count = severity_counts.get(level, 0) print(f" {level:<9}: {count:>4}", file=out)
Centering text in an f-string: The ^ character centers a string within the field width. For example, f"{'TITLE':^36}" centers the word TITLE in a 36-character field. Use this to match the report header format shown in the expected output.
