How to Debug Python Code

A step-by-step guide for finding and fixing errors in your programs.

1

Read the Error

Python tells you exactly what went wrong and where. Learn to read a traceback.

When your program crashes, Python prints a traceback -- a report that shows where the error happened. Here is a real example:

# Running this code: def calculate_average(scores): total = sum(scores) return total / len(scores) result = calculate_average([]) # empty list! print(result)

Python produces this traceback:

Traceback (most recent call last): <-- Start of the error report File "main.py", line 5, in <module> <-- Which file and line called it result = calculate_average([]) <-- The line of code that triggered it File "main.py", line 3, in calculate_average <-- Which function the crash is in return total / len(scores) <-- The exact line that crashed ZeroDivisionError: division by zero <-- Error type + message

Read it from bottom to top:

  • 1 Last line -- the error type and message. This tells you what went wrong: ZeroDivisionError: division by zero.
  • 2 Line above it -- the exact Python statement that crashed: return total / len(scores).
  • 3 File and line number -- where in your code the problem is: File "main.py", line 3. Open your editor and go to that line.
2

Identify the Error Type

Each error type tells you a different category of problem. Here are the ones you will see most often.

Error Type What It Means Common Fix
SyntaxError Python cannot even read your code. Missing colon, unmatched parenthesis or quote, or wrong indentation. Check the line Python points to and the line above it for missing colons, quotes, or brackets.
NameError You used a variable or function name that does not exist. Usually a typo or using a variable before defining it. Check spelling. Make sure the variable is defined before you use it. Remember Python is case-sensitive.
TypeError You used the wrong data type. Common: adding a string and an integer, or passing the wrong number of arguments to a function. Use type() to check what you have. Cast with int(), str(), or float() as needed.
ValueError The type is correct but the value is wrong. Classic: int("hello") -- it is a string, but not a numeric one. Validate input before converting. Use try/except around conversion calls.
IndexError You tried to access a list index that does not exist. A list of 3 items has indices 0, 1, 2 -- not 3. Print len(your_list) to check the size. Remember indexing starts at 0.
KeyError You tried to access a dictionary key that does not exist. Use .get(key, default) instead of [key], or check with if key in my_dict first.
FileNotFoundError Python cannot find the file at the path you gave it. Wrong filename, wrong directory, or the file does not exist. Print the full path. Check spelling and file extension. Use os.path.exists() to verify before opening.
IndentationError Your indentation is inconsistent. Usually caused by mixing tabs and spaces in the same file. Configure your editor to use 4 spaces per indent. In VS Code: set "Insert Spaces" to true and "Tab Size" to 4.
3

Find the Bug

Four techniques that work every time, from simplest to most powerful.

  • A Add print() statements to trace variable values. Put print(f"DEBUG: x = {x}") before the line that crashes to see what your variables actually contain. This is the single most effective debugging technique at any level.
  • B Use the Variable Inspector in the sandbox. The Hexworth sandbox shows live variable values in the right panel. Watch them change as your code runs to catch the moment something goes wrong.
  • C Comment out code to isolate the problem. If your program has 50 lines and crashes, comment out half and run again. Does it still crash? If yes, the bug is in the remaining half. Repeat until you find the exact line. This is called binary search debugging.
  • D Check your assumptions. Print type(variable) to confirm it is what you think it is. Print len(my_list) to verify the size. Most bugs come from a variable holding something different than what you expected.

Here is what a debugging print session looks like:

# Something is wrong with this function def get_average_score(scores): print(f"DEBUG: scores = {scores}") # What did we receive? print(f"DEBUG: type = {type(scores)}") # Is it actually a list? print(f"DEBUG: length = {len(scores)}") # How many items? total = sum(scores) print(f"DEBUG: total = {total}") # Is the sum correct? average = total / len(scores) print(f"DEBUG: average = {average}") # Final result return average
4

Fix and Verify

The golden rule of debugging: change one thing at a time.

When you find the bug, resist the urge to rewrite everything. Follow this cycle:

  • 1 Make ONE change -- the smallest change that you think fixes the problem.
  • 2 Run the program again -- does the error go away? If not, undo your change and try a different fix.
  • 3 Test with different inputs -- if it works for normal data, try edge cases: empty lists, zero, negative numbers, very long strings.
  • 4 Remove your debug prints -- once the fix is confirmed, clean up all the print("DEBUG: ...") lines before committing.

Here is the fixed version of the earlier example:

def calculate_average(scores): """Calculate average score. Returns 0.0 for empty lists.""" if not scores: # Guard against empty list return 0.0 total = sum(scores) return total / len(scores) # Safe: len() is guaranteed > 0

Common Beginner Mistakes

These account for the vast majority of bugs in this course. Check this list before asking for help.

Mistake What Happens Correct Version
Not casting input() Input always returns a string. age = input("Age: ") gives you "25" not 25. Math will fail or produce wrong results. age = int(input("Age: "))
Using = instead of == Single = is assignment. if x = 5 is a SyntaxError. if x == 5:
Off-by-one in range() range(5) gives 0, 1, 2, 3, 4 -- not 1 through 5. range(1, 5) gives 1, 2, 3, 4 -- still not 5. range(1, 6) for 1 through 5
Forgetting the colon if x == 5 without a colon is a SyntaxError. Same for for, while, def, and class. if x == 5:
Mixing tabs and spaces Python sees tabs and spaces as different characters. Your code may look fine but throws IndentationError. Configure VS Code: Tab Size = 4, Insert Spaces = true
Modifying a list while iterating for item in my_list: my_list.remove(item) skips elements because the list changes size mid-loop. Build a new list: result = [x for x in my_list if x != target]
