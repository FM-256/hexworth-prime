Git Quick Reference

Every command you need for this course, organized by workflow.

Your Daily Git Workflow (End of Every Class)

1 Check what changed: git status
2 Stage your changes: git add .
3 Commit with a message: git commit -m "Add menu system with input validation"
4 Push to GitHub: git push
5 Verify on github.com — your latest code should be visible

First-Time Setup

Run these once when you first install Git.

git config --global user.name "Your Name" Set your name for all commits. Use your real name.
git config --global user.email "you@email.com" Set your email. Should match your GitHub account email.
git config --global init.defaultBranch main Set the default branch name to "main" (modern standard).

Starting a Project

Initialize a new repository or connect to GitHub.

git init Initialize a new Git repository in the current folder. Creates a hidden .git/ directory.
git remote add origin URL Link your local repo to a GitHub repository. Replace URL with your repo's HTTPS link.
git push -u origin main Push to GitHub for the first time. The -u flag sets the upstream so future pushes only need git push.
git clone URL Download an existing repository from GitHub to your machine.

Daily Commands

The commands you will use every class session.

git status Show which files have been modified, staged, or are untracked. Run this often.
git add . Stage all changed files for the next commit. The dot means "everything in this folder."
git add filename.py Stage a specific file. Use this when you only want to commit certain changes.
git commit -m "message" Create a commit (a snapshot) with a descriptive message. Write what you changed and why.
git push Upload your commits to GitHub. Your code is now backed up and visible online.
git pull Download the latest changes from GitHub. Use this if you worked on another machine.
git log --oneline View your commit history as a compact list. Each line shows the commit hash and message.
git diff Show exactly what changed in your files since the last commit. Line-by-line comparison.

Branching (Week 2+)

Work on features without affecting the main code.

git branch List all local branches. The asterisk (*) shows your current branch.
git branch week2 Create a new branch called "week2". Does not switch to it yet.
git checkout week2 Switch to the "week2" branch. All changes now happen on this branch.
git checkout -b week2 Create AND switch to a new branch in one command. Shortcut for branch + checkout.
git checkout main Switch back to the main branch.
git merge week2 Merge the "week2" branch into your current branch. Run this while on main.

Fixing Mistakes

Undo changes when things go wrong.

git checkout -- filename.py Discard changes to a specific file. Reverts it to the last committed version.
git reset HEAD filename.py Unstage a file. Removes it from staging but keeps your changes in the file.
git log --oneline Find the commit hash you want to go back to.
git revert HASH Create a new commit that undoes a specific commit. Safest way to undo work.

Common Mistakes to Avoid

  • Forgetting to add before committing: git commit only commits staged files. Always run git add first.
  • Committing the venv folder: Your .gitignore should include venv/. If you accidentally committed it, ask the instructor for help removing it.
  • Vague commit messages: "fixed stuff" tells nobody anything. Write: "Add log parser with error counting and report generation."
  • Never pushing: If you only commit locally and your laptop dies, your code is gone. Push to GitHub every class.
  • Editing on GitHub directly: Make changes locally in VS Code, commit, and push. Editing on GitHub creates conflicts.
