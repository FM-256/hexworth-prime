Process Management: ps
ps aux # all processes, all users ps -ef # full format listing ps aux --sort=-%mem # sort by memory (descending) ps aux --sort=-%cpu # sort by CPU (descending) ps -u www-data # processes by a specific user ps -C nginx # processes by command name # Columns: USER PID %CPU %MEM VSZ RSS TTY STAT START TIME COMMAND # VSZ = virtual memory size, RSS = resident (actual) memory
Slide 4 of 12
top & htop
top
Real-time process monitor. Built into every Linux system. Press M to sort by memory, P by CPU, k to kill a process, q to quit. Shows load average, CPU, memory, swap at the top.
htop
Enhanced version of top. Color-coded, mouse support, tree view (F5), search (F3), filter (F4). Install with apt install htop. Much easier to use than top. Not always installed by default.
# Load average (1min, 5min, 15min) uptime # 14:30:01 up 42 days, load average: 2.45, 1.80, 1.20 # Rule: if load > number of CPU cores, system is overloaded # Check core count: nproc or lscpu | grep "^CPU(s):"

kill & Signal Management
# Send signals to processes kill 1234 # SIGTERM (15) — graceful shutdown kill -9 1234 # SIGKILL — force kill (cannot be caught) kill -HUP 1234 # SIGHUP — reload config # Kill by name killall nginx # kill all processes named nginx pkill -u www-data # kill all processes by user # Common signals # 1 (HUP) = reload, 2 (INT) = Ctrl+C, 9 (KILL) = force # 15 (TERM) = graceful, 18 (CONT) = resume, 19 (STOP) = pause # List all signals kill -l

nice & renice
# nice values: -20 (highest priority) to 19 (lowest priority) # Default nice value is 0. Only root can set negative values. # Start a process with lower priority nice -n 10 ./long-running-task.sh # Change priority of a running process renice 15 -p 1234 # set PID 1234 to nice 15 sudo renice -5 -p 1234 # increase priority (needs root) # View nice values in ps output ps -eo pid,ni,comm --sort=ni

User Troubleshooting
Cannot Log In
Check: account locked (passwd -S user)? Password expired (chage -l user)? Shell set to /sbin/nologin? Home directory exists with correct permissions?
Permission Denied
Check: file permissions (ls -la), group membership (groups user), ACLs (getfacl), SELinux context (ls -Z), sudo configuration.
Slow Session
Check: resource limits (ulimit -a), disk quota (quota user), home directory on slow filesystem, .bashrc doing heavy operations at login.

Hardware Diagnostics
# Kernel ring buffer (hardware messages) dmesg # all messages dmesg -T # human-readable timestamps dmesg --level=err,warn # errors and warnings only dmesg | grep -i usb # USB device messages # Hardware info lspci # PCI devices (network cards, GPUs) lsusb # USB devices lsblk # block devices (disks) lshw -short # hardware summary dmidecode --type memory # BIOS-level RAM info
Slide 10 of 12
Memory & Swap Analysis
free -h # total, used, free, available vmstat 1 5 # 1-second intervals, 5 samples cat /proc/meminfo # detailed memory stats # Columns in vmstat: # r = runnable processes, b = blocked # si = swap in, so = swap out (both should be near 0) # If swap is heavily used, the system needs more RAM swapon --show cat /proc/swaps
Key Metric
The "available" column in free is more important than "free". Linux uses unused RAM for disk cache. "Available" shows how much is actually available for new processes, including reclaimable cache.

Troubleshooting Workflow
1Identify: What is the symptom? Slow, crashed, error message, unreachable?
2Gather: Check logs (journalctl, /var/log/), system resources (top, free, df), network (ss, ping).
3Hypothesize: Based on symptoms and data, form a theory about the root cause.
4Test: Make one change at a time. Verify the change fixes the issue.
5Document: Record what broke, why, and how you fixed it. Update runbooks.
6Prevent: Add monitoring, alerts, or automated remediation to prevent recurrence.
