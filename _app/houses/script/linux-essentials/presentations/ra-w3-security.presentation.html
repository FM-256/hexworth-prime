SSH Hardening
# /etc/ssh/sshd_config — critical settings PermitRootLogin no # NEVER allow root SSH login PasswordAuthentication no # force key-based auth PubkeyAuthentication yes # enable public key auth Port 2222 # change default port (security through obscurity) MaxAuthTries 3 # lock out after 3 failed attempts AllowUsers jdoe admin # whitelist specific users Protocol 2 # SSHv2 only (v1 is broken) X11Forwarding no # disable unless needed ClientAliveInterval 300 # timeout idle connections (5 min) ClientAliveCountMax 2 # disconnect after 2 missed keepalives # Reload SSH after changes sudo systemctl restart sshd

Key-Based Authentication
# Generate an SSH key pair (on your LOCAL machine) ssh-keygen -t ed25519 -C "jdoe@company.com" # Creates: ~/.ssh/id_ed25519 (private) and ~/.ssh/id_ed25519.pub (public) # Copy public key to the server ssh-copy-id -i ~/.ssh/id_ed25519.pub jdoe@server # Manual method (if ssh-copy-id unavailable) cat ~/.ssh/id_ed25519.pub | ssh jdoe@server "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys" # Correct permissions (SSH is strict about this) chmod 700 ~/.ssh chmod 600 ~/.ssh/authorized_keys
Never Share Private Keys
The private key (id_ed25519) stays on YOUR machine. Only the public key (.pub) goes to servers. If a private key is compromised, generate a new pair and remove the old public key from all servers.

PAM — Pluggable Authentication Modules
What Is PAM?
A framework that separates authentication logic from applications. Programs call PAM, PAM calls modules. Change auth policy without recompiling apps. Config files in /etc/pam.d/.
PAM Module Types
auth: verify identity. account: access control. password: password changes. session: setup/teardown (logging, resource limits). Control flags: required, requisite, sufficient, optional.
# /etc/pam.d/common-password (enforce password complexity) password requisite pam_pwquality.so retry=3 minlen=12 dcredit=-1 ucredit=-1 ocredit=-1 lcredit=-1 # /etc/security/pwquality.conf for system-wide settings

SELinux — Mandatory Access Control
# Check SELinux status getenforce # Enforcing, Permissive, or Disabled sestatus # detailed status # Change mode temporarily sudo setenforce 0 # switch to Permissive (logs only) sudo setenforce 1 # switch to Enforcing # Persistent mode: edit /etc/selinux/config SELINUX=enforcing # enforcing | permissive | disabled # View file context labels ls -Z /var/www/html # Restore default context sudo restorecon -Rv /var/www/html # View and manage booleans getsebool -a | grep httpd sudo setsebool -P httpd_can_network_connect on

AppArmor — Ubuntu's MAC
# Check AppArmor status sudo aa-status # Set a profile to complain mode (logging only) sudo aa-complain /usr/sbin/nginx # Set a profile to enforce mode sudo aa-enforce /usr/sbin/nginx # Profiles in /etc/apparmor.d/ # Logs in /var/log/syslog (search for apparmor=)
SELinux vs AppArmor
SELinux: label-based, used by RHEL/Fedora. More granular, more complex. AppArmor: path-based, used by Ubuntu/SUSE. Simpler to configure, profile per application. Both enforce MAC beyond standard DAC permissions.
When to Use
Use whichever your distro ships. Do not disable either for convenience. If something breaks, use Permissive/Complain mode to diagnose, fix the policy, then re-enable enforcement.

chroot & Sandboxing
chroot
Changes the apparent root directory for a process. The process cannot see files outside the new root. Used for SFTP jails, recovery, and basic isolation. Not a security boundary by itself -- root can escape.
systemd Sandboxing
Unit file directives: ProtectSystem=strict, ProtectHome=yes, PrivateTmp=yes, NoNewPrivileges=yes. More robust than chroot. Layered with SELinux/AppArmor for defense in depth.

File Integrity: AIDE
# Initialize the AIDE database sudo aide --init sudo mv /var/lib/aide/aide.db.new /var/lib/aide/aide.db # Check for changes sudo aide --check # Update database after legitimate changes sudo aide --update
How AIDE Works
Advanced Intrusion Detection Environment. Takes a snapshot of file metadata (size, permissions, hash). On subsequent checks, compares current state to the baseline. Any unauthorized modification is flagged. Run checks via cron daily.

Vulnerability Scanning
OpenSCAP
Security Content Automation Protocol. Scans systems against compliance profiles (CIS, DISA STIG). oscap xccdf eval --profile cis. Generates HTML reports with pass/fail results per rule.
Lynis
Lightweight security auditing tool. sudo lynis audit system. Checks kernel, authentication, networking, storage, and more. No agents or cloud dependencies. Scoring system rates your hardening level.
ClamAV
Open-source antivirus for Linux. sudo freshclam updates signatures. clamscan -r /home scans recursively. Mainly used for scanning files passing through Linux servers (mail gateways, file shares).
Slide 10 of 12
Host-Based Firewall Overview
iptables / nftables
Low-level packet filtering. iptables is legacy, nftables is the replacement (RHEL 8+, Debian 10+). Both use chains (INPUT, OUTPUT, FORWARD) and tables (filter, nat, mangle). Detailed coverage in Week 4.
firewalld / ufw
High-level frontends. firewalld uses zones (public, internal, dmz) on RHEL. ufw (Uncomplicated Firewall) is Ubuntu's frontend. Both generate iptables/nftables rules under the hood. Detailed coverage in Week 4.
Slide 11 of 12
Security Hardening Checklist
1Disable root SSH login. Use key-based authentication only.
2Enforce strong password policies via PAM and chage.
3Keep SELinux/AppArmor in Enforcing mode. Never disable permanently.
4Use AIDE or Tripwire for file integrity monitoring.
5Enable host-based firewall. Default deny, explicit allow.
6Audit SUID/SGID files and world-writable directories regularly.
7Keep software updated. Enable automatic security patches.
8Minimize installed packages. Remove unused services.
