The Linux Kernel
The kernel is the bridge between hardware and userspace.
Monolithic + Modular
The Linux kernel is monolithic (runs in a single address space) but supports loadable modules. Modules let you add/remove functionality without recompiling or rebooting.
Kernel Version
Run uname -r to see the running kernel version. Format: major.minor.patch. Modules must match the running kernel or they cannot load.
Module Directory
Kernel modules are stored in /lib/modules/$(uname -r)/. Each module is a .ko file. The directory tree organizes modules by subsystem: drivers, net, fs, crypto.
Slide 3 of 14
Kernel Module Commands
Four commands to inspect, load, and remove kernel modules.
# List all currently loaded modules lsmod # Show detailed info about a specific module modinfo e1000 # Load a module (handles dependencies automatically) sudo modprobe e1000 # Remove a module sudo modprobe -r e1000 # Low-level insert (does NOT resolve dependencies) sudo insmod /lib/modules/$(uname -r)/kernel/drivers/net/ethernet/intel/e1000/e1000.ko # Low-level remove sudo rmmod e1000
Best Practice
Always use modprobe over insmod/rmmod. modprobe reads /lib/modules/$(uname -r)/modules.dep and automatically loads required dependencies. insmod does not.
Slide 4 of 14
Persistent Module Configuration
Making module changes survive a reboot.
Auto-load on Boot
Create a file in /etc/modules-load.d/ listing one module per line. systemd reads these files during boot and loads each module.
Blacklisting Modules
Create a file in /etc/modprobe.d/ with blacklist module_name. This prevents a module from loading automatically. Useful for conflicting drivers or security hardening.
# Auto-load the bonding module on boot echo "bonding" | sudo tee /etc/modules-load.d/bonding.conf # Blacklist the nouveau driver (common before installing NVIDIA) echo "blacklist nouveau" | sudo tee /etc/modprobe.d/blacklist-nouveau.conf # Rebuild the initramfs after blacklisting sudo update-initramfs -u # Debian/Ubuntu sudo dracut --force # RHEL/Fedora
Why Rebuild initramfs?
The initial RAM filesystem (initramfs) loads before the root filesystem. If a blacklisted module is baked into the initramfs, it will still load on boot unless you regenerate the image.
Slide 5 of 14
Network Configuration Overview
Three methods to configure network interfaces on modern Linux.
ip command
The modern replacement for ifconfig. Part of the iproute2 suite. Configures addresses, routes, links. Changes are temporary -- lost on reboot.
Netplan (Ubuntu)
YAML config files in /etc/netplan/. Run netplan apply to activate. Netplan delegates to NetworkManager or systemd-networkd as a backend.
nmcli (RHEL/Fedora)
NetworkManager CLI tool. nmcli con show lists connections. Edits are persistent by default. Replaces the older /etc/sysconfig/network-scripts/ files.
Slide 6 of 14
The ip Command
Your primary tool for runtime network configuration.
# Show all interfaces and their addresses ip addr show ip a # shorthand # Show only link-layer info (MAC, state) ip link show # Assign an IP address sudo ip addr add 192.168.1.50/24 dev enp0s3 # Bring interface up / down sudo ip link set enp0s3 up sudo ip link set enp0s3 down # Show routing table ip route show # Add a default gateway sudo ip route add default via 192.168.1.1
Warning
All ip command changes are temporary. They are lost on reboot or network service restart. For persistent configuration, use netplan or nmcli.
Slide 7 of 14
Netplan Configuration
Ubuntu's declarative network configuration system.
# /etc/netplan/01-netcfg.yaml network: version: 2 renderer: networkd ethernets: enp0s3: dhcp4: false addresses: - 192.168.1.50/24 routes: - to: default via: 192.168.1.1 nameservers: addresses: - 8.8.8.8 - 8.8.4.4
Apply Changes
Run sudo netplan apply to activate the configuration. Use sudo netplan try to test changes with automatic rollback after 120 seconds if no confirmation.
YAML Syntax
Indentation must use spaces, never tabs. A single wrong indent will break the entire configuration. Use netplan generate to validate before applying.
Slide 8 of 14
nmcli — NetworkManager CLI
Persistent network configuration on RHEL, Fedora, and CentOS.
# Show all connections nmcli con show # Show device status nmcli dev status # Create a new static connection sudo nmcli con add type ethernet con-name "office" ifname enp0s3 \ ipv4.addresses 192.168.1.50/24 \ ipv4.gateway 192.168.1.1 \ ipv4.dns "8.8.8.8 8.8.4.4" \ ipv4.method manual # Activate the connection sudo nmcli con up "office" # Modify an existing connection sudo nmcli con modify "office" ipv4.dns "1.1.1.1"
Key Difference
nmcli changes are persistent by default. They are saved to connection profiles in /etc/NetworkManager/system-connections/. No extra step needed to survive a reboot.

DNS Configuration
How Linux resolves hostnames to IP addresses.
# View current DNS servers cat /etc/resolv.conf # Or with systemd-resolved: resolvectl status # Test DNS resolution dig google.com nslookup google.com host google.com # Add a local hostname override echo "192.168.1.100 myserver.local" | sudo tee -a /etc/hosts
Slide 10 of 14
Hostname Management
Three types of hostnames in Linux.
Static Hostname
Stored in /etc/hostname. Set with hostnamectl set-hostname server01. This is the persistent name used after reboot. Must follow RFC standards: lowercase, hyphens allowed, no underscores.
Pretty Hostname
A free-form name for display purposes. Set with hostnamectl set-hostname "Web Server 01" --pretty. Stored in /etc/machine-info. Can include spaces and special characters.
Transient Hostname
Assigned dynamically by DHCP. Overrides the static hostname until reboot. Check with hostnamectl status which shows all three hostname types.
# View all hostname details hostnamectl status # Set the static hostname (persists across reboots) sudo hostnamectl set-hostname web-srv-01 # Quick view with the hostname command hostname # short hostname hostname -f # FQDN hostname -I # all assigned IP addresses
Slide 11 of 14
Network Monitoring: ss and netstat
Inspect active connections, listening ports, and socket statistics.
# ss — the modern replacement for netstat ss -tuln # TCP/UDP listening sockets, numeric ss -tunap # All sockets with process names ss -s # Summary statistics # Filter by state ss state established ss -t state time-wait # Filter by port ss -tuln sport = :443 # netstat (deprecated but still on exams) netstat -tuln # Same as ss -tuln netstat -rn # Routing table (same as ip route)
ss Flag Reference
-t TCP, -u UDP, -l listening only, -n numeric (skip DNS), -a all sockets, -p process name/PID
netstat is Deprecated
netstat is part of the legacy net-tools package. Some distros no longer install it by default. Always prefer ss for new work, but know netstat for legacy systems and certification exams.
Slide 12 of 14
Network Troubleshooting Workflow
A systematic approach to diagnosing network issues.
1Check physical/link layer: ip link show -- is the interface UP?
2Check IP assignment: ip addr show -- does the NIC have an address?
3Check routing: ip route show -- is there a default route?
4Ping the gateway: ping -c 4 192.168.1.1 -- can you reach your router?
5Test DNS: dig google.com -- if IP works but names don't, it's DNS.
Slide 13 of 14
Additional Network Tools
Essential utilities for deeper network analysis.
traceroute / tracepath
Traces the path packets take to a destination. Each hop shows latency. Use traceroute -n google.com to skip DNS. tracepath does not require root.
nmap
Network scanner. nmap -sn 192.168.1.0/24 discovers live hosts. nmap -sV host detects service versions. Essential for security assessment.
tcpdump / Wireshark
tcpdump -i enp0s3 port 80 captures HTTP traffic. Use -w capture.pcap to save for analysis in Wireshark. Requires root or CAP_NET_RAW capability.
ping
ICMP echo request. ping -c 4 host sends 4 packets. ping -i 0.2 host sets 200ms interval. Use -W 2 to set timeout. Most basic connectivity test.
mtr
Combines ping + traceroute in a live updating display. mtr --report google.com generates a text report. Shows packet loss and latency at every hop.
