User Database Files
/etc/passwd
Username, UID, GID, home dir, shell. Format: user:x:1000:1000:Full Name:/home/user:/bin/bash. The x means password is in /etc/shadow. Readable by all users.
/etc/shadow
Hashed passwords, aging info, expiry dates. Only readable by root. Format includes: last change, min/max days, warn days, inactive days, expiry date.
/etc/group
Group name, GID, member list. Format: developers:x:1001:jdoe,asmith. A user's primary group is in /etc/passwd. Supplementary groups listed here.

File Permissions
# Permission bits: r(read)=4, w(write)=2, x(execute)=1 # Three groups: owner, group, others ls -l file.txt # -rwxr-xr-- 1 jdoe developers 4096 Jan 1 12:00 file.txt # ^^^ owner: rwx (7) # ^^^ group: r-x (5) # ^^^ others: r-- (4) # Numeric: 754 # chmod — change permissions chmod 755 script.sh # numeric: rwxr-xr-x chmod u+x script.sh # symbolic: add execute for owner chmod g-w file.txt # remove write for group chmod o=r file.txt # set others to read-only chmod -R 750 /opt/project # recursive

umask — Default Permissions
# umask subtracts from default permissions # Default for files: 666, directories: 777 # umask 022 = files get 644, dirs get 755 umask # show current umask umask 027 # files: 640, dirs: 750 # Persistent: add to ~/.bashrc or /etc/profile
Common umask Values
022: files 644, dirs 755 (default). 027: files 640, dirs 750 (no other access). 077: files 600, dirs 700 (owner only).
How It Works
umask bits are removed from the default. For a file with default 666 and umask 022: 666 minus 022 = 644 (rw-r--r--). For a directory with default 777: 777 minus 022 = 755.

Special Permissions: SUID, SGID, Sticky
SUID (4xxx)
Set User ID. File executes as the file owner, not the user running it. Example: /usr/bin/passwd runs as root so users can change their own passwords. chmod u+s file or chmod 4755 file.
SGID (2xxx)
Set Group ID. On files: executes with file's group. On directories: new files inherit the directory's group (not the creator's primary group). chmod g+s dir or chmod 2755 dir.
Sticky Bit (1xxx)
On directories: only the file owner can delete their files. Used on /tmp so users cannot delete each other's temp files. chmod +t dir or chmod 1777 dir.
Slide 9 of 13
Access Control Lists (ACLs)
# View ACLs getfacl file.txt # Grant read to a specific user setfacl -m u:jdoe:r file.txt # Grant read/write to a group setfacl -m g:developers:rw file.txt # Set default ACL on a directory (inherited by new files) setfacl -d -m g:developers:rw /opt/project # Remove an ACL entry setfacl -x u:jdoe file.txt # Remove all ACLs setfacl -b file.txt
When to Use ACLs
Standard Unix permissions (owner/group/other) handle most cases. ACLs are needed when multiple users or groups need different access levels to the same file without changing ownership.
