journalctl — systemd Journal
journalctl # all logs journalctl -u nginx.service # specific service journalctl -f # follow (live tail) journalctl -b # since last boot journalctl -b -1 # previous boot journalctl --since "2024-01-01 02:00" --until "2024-01-01 04:00" journalctl -p err # errors and above journalctl _UID=1000 # by user ID journalctl --disk-usage # journal size journalctl --vacuum-size=100M # shrink to 100MB

iptables Firewall
# View current rules sudo iptables -L -n -v # Allow incoming SSH sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT # Allow incoming HTTP and HTTPS sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT # Allow established/related connections sudo iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT # Default deny incoming sudo iptables -P INPUT DROP # Save rules (Debian/Ubuntu) sudo iptables-save > /etc/iptables/rules.v4

Slide 7 of 13
nftables — The iptables Replacement
# nft is the modern replacement for iptables sudo nft list ruleset # Create a table and chain sudo nft add table inet filter sudo nft add chain inet filter input { type filter hook input priority 0 ; policy drop ; } # Add rules sudo nft add rule inet filter input tcp dport 22 accept sudo nft add rule inet filter input ct state established,related accept
Migration
nftables is the kernel successor to iptables. RHEL 8+, Debian 10+. The iptables command still works via a compatibility layer but new deployments should use nft or firewalld/ufw.

Backup with tar
# Create a compressed archive tar -czf backup.tar.gz /opt/project # gzip compression tar -cjf backup.tar.bz2 /opt/project # bzip2 compression tar -cJf backup.tar.xz /opt/project # xz compression (best ratio) # List contents without extracting tar -tzf backup.tar.gz # Extract tar -xzf backup.tar.gz -C /restore/path # Flags: c=create, x=extract, t=list, z=gzip, j=bzip2, J=xz, f=file, v=verbose
Slide 9 of 13
rsync & dd
# rsync — incremental file synchronization rsync -avz /opt/project/ /backup/project/ # local sync rsync -avz -e ssh /opt/project/ user@backup:/data/ # remote sync rsync -avz --delete /src/ /dst/ # mirror (delete removed files) # dd — block-level copy (disk imaging) sudo dd if=/dev/sda of=/backup/disk.img bs=4M status=progress sudo dd if=/dev/sda of=/dev/sdb bs=4M # clone disk to disk
dd Warning
dd will overwrite anything without confirmation. Double-check if= (input) and of= (output) before running. Reversing them destroys your source. Known as "disk destroyer" for a reason.
Slide 10 of 13
Compression Tools
gzip / gunzip
Fastest compression. Moderate ratio. gzip file.txt creates file.txt.gz (original removed). gunzip file.txt.gz to decompress. Use zcat to read without extracting.
bzip2 / bunzip2
Better compression than gzip, slower. bzip2 file.txt creates file.txt.bz2. Use bzcat to read compressed files. Good balance of speed and ratio for backups.
xz / unxz
Best compression ratio, slowest. xz file.txt creates file.txt.xz. Used for Linux kernel tarballs and software distributions. xzcat for reading. Use when archive size matters most.

Slide 12 of 13
Backup Strategy
Full Backup
Complete copy of all data. Slowest, largest, simplest to restore. Baseline for incremental and differential strategies. Run weekly or monthly depending on data volume.
Incremental
Only files changed since the last backup (full or incremental). Fastest backup, smallest size. Restore requires full + all incrementals in sequence. Most common for daily backups.
Differential
All files changed since the last full backup. Larger than incremental, faster to restore. Restore requires full + latest differential only. Good middle ground.
