Common Server Roles
Web Server
Apache (httpd) or Nginx. Serves HTTP/HTTPS content. Apache uses .htaccess and virtual hosts. Nginx excels at reverse proxying and static content.
DNS Server
BIND (named) or Unbound. Translates hostnames to IPs. Forward zones map names to IPs. Reverse zones map IPs to names. If DNS fails, nothing works by name.
DHCP Server
dhcpd or dnsmasq. Assigns IP addresses, masks, gateways, and DNS to clients. Leases have durations. Reservations tie MACs to specific IPs.
Slide 3 of 12
More Server Roles
File Server
Samba (SMB/CIFS for Windows clients) or NFS (native Linux). Shared directories with permission controls. Samba can serve as an Active Directory domain controller.
Database Server
MySQL/MariaDB, PostgreSQL, MongoDB. Listen on ports 3306, 5432, 27017. Must be hardened: bind to localhost, strong auth, encrypted connections.
Mail Server
Postfix (MTA/sending), Dovecot (MDA/receiving). SMTP 25/587, IMAP 143/993, POP3 110/995. Complex to configure securely.
Slide 4 of 12
Print & Proxy Servers
Print Server (CUPS)
Common Unix Printing System. Web admin at http://localhost:631. lpstat -p lists printers. lp -d printer file.pdf prints a file.
Proxy Server
Forward proxy (Squid) caches web content and filters traffic. Reverse proxy (Nginx, HAProxy) distributes load across backend servers.

cron Directories
# Drop-in directories (scripts run automatically) /etc/cron.hourly/ # run every hour /etc/cron.daily/ # run once a day /etc/cron.weekly/ # run once a week /etc/cron.monthly/ # run once a month /etc/cron.d/ # individual crontab-format files # Access control /etc/cron.allow # whitelist (if exists, only listed users) /etc/cron.deny # blacklist
Exam Tip
If /etc/cron.allow exists, only listed users can use cron. If it does not exist, /etc/cron.deny is checked. If neither exists, behavior varies by distro.

anacron — Catch-Up Scheduling
Why anacron?
cron assumes the system is always running. If a machine is off when a cron job was scheduled, that job is skipped forever. anacron catches up on missed jobs after boot.
How It Works
/etc/anacrontab defines jobs with period (days), delay (minutes), and command. Checks timestamps in /var/spool/anacron/ to determine missed jobs.
# /etc/anacrontab: period delay identifier command 1 5 daily-backup /opt/backup/daily.sh 7 10 weekly-report /opt/reports/weekly.sh 30 15 monthly-audit /opt/audit/monthly.sh

systemd Timers
The modern alternative to cron.
# /etc/systemd/system/backup.timer [Unit] Description=Daily Backup Timer [Timer] OnCalendar=*-*-* 02:00:00 Persistent=true [Install] WantedBy=timers.target # /etc/systemd/system/backup.service [Unit] Description=Daily Backup [Service] Type=oneshot ExecStart=/opt/backup/daily.sh # Enable and list timers sudo systemctl enable --now backup.timer systemctl list-timers

Timer vs Cron Comparison
cron Advantages
Simpler syntax. Universally available. Well-understood. Single file per user. No need for two unit files. Better for quick one-liner scheduling.
systemd Timer Advantages
Better logging via journalctl. Persistent=true catches missed runs. Calendar expressions more readable. Can depend on other units. Resource control via cgroups.
