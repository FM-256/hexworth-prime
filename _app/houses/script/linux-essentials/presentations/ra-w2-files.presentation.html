File Operations
# Copy files and directories cp file.txt backup.txt # copy a file cp -r /src /dst # copy directory recursively cp -p file.txt backup.txt # preserve permissions and timestamps # Move / rename mv old.txt new.txt # rename mv file.txt /tmp/ # move to another directory # Remove rm file.txt # delete a file rm -r directory/ # delete directory recursively rm -rf directory/ # force, no prompts (DANGEROUS) # Create directories mkdir -p /path/to/nested/dir # create parent dirs as needed
Warning
rm -rf is irreversible. There is no recycle bin on the command line. Always double-check your path before running destructive commands. Consider using rm -i (interactive) for safety.

find and locate
# find — real-time filesystem search find /var/log -name "*.log" # by name find /home -type f -size +100M # files larger than 100MB find /tmp -mtime -1 # modified in last 24 hours find / -user www-data -type f # files owned by www-data find / -perm -4000 -type f # SUID files (security audit) find /var -name "*.log" -exec grep -l "ERROR" {} \; # locate — index-based (faster, but stale) locate nginx.conf sudo updatedb # refresh the locate database
find
Searches the filesystem in real time. Slower but always current. Supports complex filters: name, size, time, permissions, owner, type. The -exec flag runs commands on results.
locate
Searches a pre-built database (mlocate.db). Extremely fast but can return stale results. Run updatedb to refresh. Database updates nightly via cron by default.

I/O Redirection
Controlling where command input comes from and output goes.
echo "hello" > file.txt # stdout to file (overwrite) echo "world" >> file.txt # stdout to file (append) sort < names.txt # stdin from file ls /fake 2> errors.txt # stderr to file ls /fake &> all.txt # both stdout and stderr to file ls /fake 2>/dev/null # discard errors
Slide 5 of 13
Pipes — Chaining Commands
# The pipe (|) sends stdout of one command to stdin of the next ls -la | grep ".conf" # filter for config files cat /var/log/syslog | grep "error" | wc -l # count error lines ps aux | sort -nrk 3 | head -10 # top 10 CPU processes cat access.log | cut -d' ' -f1 | sort | uniq -c | sort -rn # IP frequency # tee — write to file AND pass to next command df -h | tee disk-report.txt | grep "/dev/sda"
Philosophy
Each Unix tool does one thing well. Pipes let you compose complex operations from simple tools. This is the Unix philosophy: write programs that do one thing and do it well, and write programs to work together.

grep — Pattern Matching
# Basic grep grep "error" /var/log/syslog # find lines containing "error" grep -i "error" syslog # case-insensitive grep -r "TODO" /home/dev/ # recursive search grep -n "failed" auth.log # show line numbers grep -c "404" access.log # count matching lines grep -v "debug" syslog # invert: show NON-matching lines grep -l "password" /etc/*.conf # list files that match # Extended regex with -E (or egrep) grep -E "error|warning|critical" syslog grep -E "^[0-9]{1,3}\." access.log # lines starting with IP

sed and awk
# sed — stream editor (find and replace) sed 's/old/new/' file.txt # replace first occurrence per line sed 's/old/new/g' file.txt # replace ALL occurrences (global) sed -i 's/old/new/g' file.txt # edit in place (modifies file) sed '/^#/d' config.txt # delete comment lines sed -n '5,10p' file.txt # print lines 5-10 only # awk — column-based text processing awk '{print $1}' access.log # print first column (space-delimited) awk -F: '{print $1, $3}' /etc/passwd # colon delimiter: username and UID awk '$3 > 1000' /etc/passwd # rows where column 3 > 1000 df -h | awk '$5+0 > 80 {print $6, $5}' # filesystems over 80% full
Slide 8 of 13
Hard Links & Soft Links
# Hard link — second directory entry pointing to same inode ln file.txt backup.txt # Symbolic (soft) link — pointer to a file path ln -s /etc/nginx/nginx.conf ~/nginx-config # Check link count and inode ls -li file.txt backup.txt stat file.txt
Hard Links
Same inode, same data. Deleting the original does not break the link. Cannot cross filesystems. Cannot link to directories. Link count tracks references.
Soft (Symbolic) Links
Points to a path, not an inode. Can cross filesystems. Can link to directories. Breaks if the target is deleted (dangling symlink). ls -l shows the arrow notation.

systemd & Service Management
The init system that manages services, targets, and the boot process.
# Service lifecycle commands sudo systemctl start nginx # start a service now sudo systemctl stop nginx # stop a service sudo systemctl restart nginx # stop then start sudo systemctl reload nginx # reload config without restart systemctl status nginx # show current state + recent logs # Boot persistence sudo systemctl enable nginx # start on boot sudo systemctl disable nginx # do not start on boot systemctl is-enabled nginx # check boot status # List all services systemctl list-units --type=service systemctl list-units --type=service --state=running
Slide 10 of 13
systemd Unit Files
# Unit files live in /etc/systemd/system/ (custom) or /lib/systemd/system/ (vendor) # Example: /etc/systemd/system/myapp.service [Unit] Description=My Custom Application After=network.target [Service] Type=simple User=appuser WorkingDirectory=/opt/myapp ExecStart=/opt/myapp/run.sh Restart=on-failure RestartSec=5 [Install] WantedBy=multi-user.target
[Unit]
Metadata and dependencies. After= controls startup order. Requires= creates hard dependencies. Wants= creates soft dependencies.
[Service]
How to run the service. ExecStart= is the command. Restart=on-failure restarts automatically on crash. Type= can be simple, forking, oneshot, notify.
[Install]
WantedBy=multi-user.target means this service starts in normal multi-user mode (equivalent to old runlevel 3). Use systemctl daemon-reload after editing unit files.
Slide 11 of 13
Runlevels & Targets
SysV Runlevels (Legacy)
0=poweroff, 1=single-user, 2=multi-user (no net), 3=multi-user (with net), 5=graphical, 6=reboot. Set with init 3. Still referenced in exams.
systemd Targets (Modern)
poweroff.target, rescue.target, multi-user.target, graphical.target, reboot.target. Targets can include other targets. More flexible than runlevels.
# View current default target systemctl get-default # Change the default boot target sudo systemctl set-default multi-user.target # CLI only (no GUI) sudo systemctl set-default graphical.target # GUI desktop # Switch target at runtime (like changing runlevel) sudo systemctl isolate rescue.target # single-user mode
Slide 12 of 13
Viewing Logs with journalctl
# View logs for a specific service journalctl -u nginx.service # Follow logs in real time journalctl -u nginx -f # Logs since last boot journalctl -b # Logs from a time range journalctl --since "2024-01-01 08:00" --until "2024-01-01 12:00" # Filter by priority (0=emerg to 7=debug) journalctl -p err # errors and above
Key Advantage
journalctl provides structured, indexed access to all systemd logs. Unlike traditional flat log files in /var/log/, journal entries include metadata: timestamp, PID, unit name, priority, and boot ID.
