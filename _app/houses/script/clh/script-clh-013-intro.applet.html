Environment Variables

Understand the shell's memory. Read, set, and exploit environment variables.

SHELL ENVIRONMENT CONTROL

Environment variables are the hidden configuration layer of every Linux system. They control where the shell finds commands, which user is logged in, where home directories live, and much more. An attacker who controls the environment can hijack command execution. A defender who understands it can spot the manipulation. Your mission: master env, export, and PATH to take control of the shell.

What Are Environment Variables?

Environment variables are key-value pairs stored in the shell's memory. They are inherited by every process you launch. When you type ls, the shell searches through the directories listed in $PATH to find the ls binary. When a program needs your username, it reads $USER. These variables are the invisible wiring behind everything the shell does.

Some variables are set automatically by the system ($HOME, $USER, $SHELL). Others you create yourself with export. Understanding the difference between shell variables (local to your session) and environment variables (inherited by child processes) is fundamental to Linux administration and security.

Why Environment Variables Matter in Security

PATH Hijacking

Attackers prepend malicious directories to $PATH so their fake ls or sudo runs instead of the real one. Always inspect $PATH for suspicious entries.

Credential Exposure

Secrets stored in environment variables (API keys, passwords) can leak through process listings, crash dumps, or child processes.

Persistence via .bashrc

Attackers modify ~/.bashrc or ~/.profile to inject malicious exports that execute on every login. Check startup files during investigations.

Privilege Escalation

Variables like LD_PRELOAD and LD_LIBRARY_PATH can force programs to load attacker-controlled libraries -- a classic privesc vector.
