DATA STREAM CONTROL BRIEFING

Every command in Linux produces data streams -- standard output (stdout), standard error (stderr), and accepts standard input (stdin). Right now, everything just dumps to your screen. Your mission: learn to redirect these streams. Capture output to files. Pipe data between commands. Split streams with tee. Silence noise with /dev/null. Control where every byte goes.

The Three Data Streams

Every Linux process has three standard data streams. stdin (file descriptor 0) is the input stream -- data flowing into a command. stdout (file descriptor 1) is the normal output -- results and data. stderr (file descriptor 2) is the error stream -- warnings and error messages.

By default, both stdout and stderr print to your terminal and stdin reads from your keyboard. Redirection lets you reroute these streams anywhere: to files, to other commands, to the void. This is how you build powerful data pipelines on the command line.

Redirection Command Reference

Operator Purpose
command > file Redirect stdout to a file (overwrites existing content)
command >> file Append stdout to a file (preserves existing content)
command 2> file Redirect stderr (errors only) to a file
command > file 2>&1 Redirect both stdout and stderr to the same file
command1 | command2 Pipe -- send stdout of command1 into stdin of command2
command | tee file Split output -- write to file AND display on screen
command > /dev/null 2>&1 Discard all output -- the black hole of Linux
operator@shadow:~$ ls intel/ > reports/filelist.txt # No output on screen -- it went to the file instead operator@shadow:~$ cat reports/filelist.txt access.log auth.log network_capture.pcap operator@shadow:~$ echo "=== SCAN COMPLETE ===" >> reports/filelist.txt # Appended to the file without erasing previous content operator@shadow:~$ find /etc -name "*.conf" 2>/dev/null | wc -l 47 # Errors silenced, only the count reaches wc

Pipes and tee in Action

operator@shadow:~$ cat intel/access.log | grep "POST" | grep "login" | wc -l 312 # 312 POST requests to login endpoints -- chain as many pipes as you need operator@shadow:~$ grep "CRITICAL" intel/syslog | tee reports/critical.txt Mar 08 14:22:01 CRITICAL: Unauthorized access detected Mar 08 14:23:55 CRITICAL: Firewall rule bypassed # Output shown on screen AND saved to file simultaneously operator@shadow:~$ ls /nonexistent 2>&1 | grep "No such" ls: cannot access '/nonexistent': No such file or directory # Merged stderr into stdout so grep can filter error messages

Why I/O Redirection Matters

Capture Evidence

Redirect scan results, log analysis output, and forensic data to files for documentation and reporting.

Build Pipelines

Chain commands with pipes to create powerful data processing workflows without intermediate files.

Clean Operations

Suppress noisy errors with 2>/dev/null so your scripts run cleanly without permission spam.

Dual-Output with tee

Monitor operations live on screen while simultaneously logging everything to a file for later review.
