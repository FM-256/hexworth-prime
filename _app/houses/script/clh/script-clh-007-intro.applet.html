Permissions & Access Control

Understand who can do what. Permissions are the first line of defense.

BLACK SITE LOCKDOWN PROTOCOL

A security audit has revealed critical permission misconfigurations across the facility's file systems. World-writable config files, improperly owned binaries, and exposed credentials have left the site vulnerable. Your mission: use chmod, chown, chgrp, and umask to lock down access, fix broken permissions, and restore the security perimeter before the breach widens.

The Linux Permission Model

Every file and directory in Linux carries three sets of permissions for three categories of users: the owner, the group, and others (everyone else). Each category gets three permission bits: read (r), write (w), and execute (x).

This system is the foundation of Linux security. A misconfigured permission can expose passwords, allow unauthorized code execution, or give attackers a foothold for privilege escalation. Understanding permissions is not optional -- it is the first line of defense.

operator@shadow:~$ ls -la /etc/shadow -rw-r----- 1 root shadow 1423 Mar 09 16:30 /etc/shadow # Owner (root): read + write # Group (shadow): read only # Others: NO access

Permission Commands

Command Purpose
chmod 755 file Set permissions using octal notation (rwxr-xr-x)
chmod u+x script.sh Add execute permission for the user (symbolic mode)
chmod go-w file Remove write permission from group and others
chown user:group file Change the owner and group of a file
chgrp developers file Change just the group ownership
umask 022 Set default permissions for newly created files (inverse mask)
operator@shadow:~$ chmod 600 credentials.conf # Now only the owner can read/write -- locked down operator@shadow:~$ chmod 755 deploy.sh # Owner: full access. Group/Others: read + execute operator@shadow:~$ chown root:www-data /var/www/config.php # Transferred ownership to root, group to www-data operator@shadow:~$ umask 0022 # Default: new files get 644, new dirs get 755

Octal Notation and Security Implications

Permissions are encoded as three octal digits: read = 4, write = 2, execute = 1. Add them together for each category. For example, 755 means owner gets 7 (rwx), group gets 5 (r-x), others get 5 (r-x).

Never Use 777

chmod 777 gives full read, write, and execute to everyone. Any user on the system can modify or delete the file.

Protect Sensitive Files

SSH keys need 600. Config files with passwords need 640 or 600. SSH will refuse to use keys with loose permissions.

SUID and SGID Bits

Files with the SUID bit (4xxx) execute as the file owner. Attackers hunt for SUID root binaries as privilege escalation vectors.

The Sticky Bit

Set on directories like /tmp (1xxx), it prevents users from deleting each other's files even with write access to the directory.

Ready to Lock Down?

Misconfigured permissions are waiting to be fixed. Use chmod, chown, and umask to secure the facility.
