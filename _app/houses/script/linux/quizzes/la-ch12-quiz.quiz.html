Compiling Source Code

10 questions on gcc, make, ./configure, Makefiles, dependencies, ldconfig, and checkinstall

QUESTION 1 OF 10
What is the correct order of steps to compile and install software from source using the traditional autotools workflow?
EXPLANATION

The standard autotools compilation workflow is: (1) ./configure — checks system, generates Makefile. (2) make — compiles source into binaries. (3) sudo make install — copies binaries to system paths. This order is mandatory: you cannot run make without a Makefile, and you cannot install without compiled binaries. The configure step requires development tools already installed.

QUESTION 2 OF 10
What does the ./configure script produce as its primary output?
EXPLANATION

The configure script checks the local system for compiler availability, required libraries, headers, and system capabilities, then generates a Makefile customized for that environment. It also generates config.h with #define constants for system-detected features. If a dependency is missing, configure exits with an error before generating the Makefile — you must install the missing package and re-run configure.

QUESTION 3 OF 10
./configure fails with "OpenSSL library not found." You confirm openssl is installed. What is the most likely fix?
EXPLANATION

When configure fails with "library not found" despite the library being installed, the issue is missing development headers. Distributions split libraries into runtime packages (just the .so file) and development packages (headers + .a files). On Debian/Ubuntu: install libssl-dev. On RHEL/Fedora: install openssl-devel. The configure script checks for header files (#include <openssl/ssl.h>), not just the runtime library.

QUESTION 4 OF 10
What does make -j$(nproc) do?
EXPLANATION

$(nproc) is command substitution that returns the number of available processor cores. make -j4 on a 4-core machine compiles 4 source files simultaneously. On a large project with hundreds of files, parallel compilation can reduce build time from minutes to seconds. The -j flag enables parallel jobs. Using more jobs than cores provides diminishing returns due to I/O and dependency constraints.

QUESTION 5 OF 10
Which make target removes compiled object files and binaries, reverting the source directory to a clean state (keeping the Makefile)?
EXPLANATION

make clean removes compiled object files (.o) and binaries, but keeps the Makefile and configuration. This is used to force a full recompile. make distclean goes further — it removes everything including the Makefile itself (full reset to pre-configure state). make uninstall removes installed files from system paths (if the Makefile supports it). There is no standard make purge target.

QUESTION 6 OF 10
What does pkg-config --cflags --libs openssl return, and how is it used?
EXPLANATION

pkg-config reads .pc files from installed libraries and outputs the correct include paths (--cflags) and link flags (--libs). Example usage: gcc myapp.c $(pkg-config --cflags --libs openssl) -o myapp. This eliminates manual tracking of where libraries are installed and handles version-specific paths. Much better than hardcoding -I/usr/include/openssl -lssl -lcrypto.

QUESTION 7 OF 10
After installing a new shared library to /usr/local/lib, which command must you run to update the linker cache?
EXPLANATION

sudo ldconfig scans directories listed in /etc/ld.so.conf (and /etc/ld.so.conf.d/*.conf) for shared libraries and rebuilds the dynamic linker cache (/etc/ld.so.cache). Without this, programs can't find newly installed .so files even if they're in a known directory. If /usr/local/lib isn't in ld.so.conf, add it: echo "/usr/local/lib" | sudo tee /etc/ld.so.conf.d/local.conf then run sudo ldconfig.

QUESTION 8 OF 10
What is the primary advantage of using checkinstall instead of sudo make install?
EXPLANATION

checkinstall intercepts make install, records all files it places on the system, and packages them into a .deb (on Debian/Ubuntu) or .rpm (on RHEL). This means the software can later be cleanly removed with sudo apt remove packagename. Without checkinstall, make install scatters files across /usr/local/ with no record, making removal difficult and error-prone.

QUESTION 9 OF 10
Which command shows the shared library dependencies of a compiled binary?
EXPLANATION

ldd myapp (List Dynamic Dependencies) shows all shared libraries that a binary links against and whether they are found on the system. Output shows each library name and its path (or "not found" if missing). This is essential for diagnosing "error while loading shared libraries" errors and for understanding what a binary needs before deploying to another system.

QUESTION 10 OF 10
Which configure option changes the installation prefix so the program installs to /opt/myapp/ instead of /usr/local/?
EXPLANATION

The --prefix option sets the installation root. ./configure --prefix=/opt/myapp installs binaries to /opt/myapp/bin/, libraries to /opt/myapp/lib/, and headers to /opt/myapp/include/. The default prefix is /usr/local. Using a custom prefix isolates the software and makes removal easy (just delete the directory). After installing, add /opt/myapp/bin to your PATH.
