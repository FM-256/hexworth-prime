CHAPTER 7 — QUIZ

Display Managers

10 questions on GDM, LightDM, SDDM, graphical sessions, .Xsession, and user environment

Question 1 / 10
QUESTION 1 OF 10
Which systemd command shows the currently active display manager service?
EXPLANATION

systemctl status display-manager uses the generic display-manager service alias, which symlinks to whichever DM is currently configured (gdm, lightdm, sddm, etc.). This is a convenient alias that works regardless of which DM is installed.

QUESTION 2 OF 10
GDM is the default display manager for which desktop environment?
EXPLANATION

GDM (GNOME Display Manager) is the default DM for GNOME-based distributions including Ubuntu (with GNOME), Fedora Workstation, and RHEL. SDDM is the default for KDE Plasma. LightDM is often used on Xfce and MATE. LXDM or LightDM is used on LXDE.

QUESTION 3 OF 10
What environment variable indicates whether the current session uses X11 or Wayland?
EXPLANATION

$XDG_SESSION_TYPE will output either x11 or wayland depending on the session type. $DISPLAY (e.g., :0) identifies the X display number and only exists in X11 sessions. $DESKTOP_SESSION identifies the desktop environment (gnome, plasma, xfce), not the protocol.

QUESTION 4 OF 10
On a Debian/Ubuntu system, which command reconfigures which display manager is used at boot?
EXPLANATION

sudo dpkg-reconfigure gdm3 (or dpkg-reconfigure lightdm) triggers the Debian package configuration dialog that asks which display manager should be the default. This updates /etc/X11/default-display-manager and sets up the appropriate systemd symlinks.

QUESTION 5 OF 10
A user's login succeeds but they immediately return to the login screen (login loop). Where should an admin look first?
EXPLANATION

~/.xsession-errors captures stderr from the user's session startup — errors in .bashrc, .profile, missing window manager binaries, or corrupted .xsession files all appear here. A login loop most commonly results from a user-space error during session initialization, making this the first diagnostic file to check.

QUESTION 6 OF 10
Which file can a user create in their home directory to override the default desktop environment launched by the display manager?
EXPLANATION

~/.xsession is executed by the display manager when a user logs in (for X11 sessions). It can contain commands like exec openbox-session to launch an alternative window manager. ~/.xinitrc serves a similar purpose but is used by the startx command, not display managers. ~/.Xdefaults sets X resource preferences (fonts, colors) but does not control which WM runs.

QUESTION 7 OF 10
SDDM is the default display manager for which desktop environment?
EXPLANATION

SDDM (Simple Desktop Display Manager) is the default DM for KDE Plasma. It is written in QML/Qt, integrating naturally with KDE's Qt-based design language. It replaced the older KDM display manager and supports both X11 and Wayland sessions.

QUESTION 8 OF 10
How do you switch the system to text-mode (no graphical login) on a systemd-based system?
EXPLANATION

sudo systemctl set-default multi-user.target configures the system to boot to runlevel 3 equivalent (multi-user, non-graphical) on next boot. graphical.target is the equivalent of runlevel 5 (with GUI). While init 3 and telinit 2 work on SysV init systems, systemctl set-default is the modern systemd approach. Disabling the DM service alone does not change the default target.

QUESTION 9 OF 10
Which command sets the system-wide locale to US English UTF-8?
EXPLANATION

localectl set-locale makes a persistent, system-wide locale change. It writes to /etc/locale.conf (or the equivalent) and takes effect on the next login. export LANG=en_US.UTF-8 only sets the locale for the current shell session — it is not persistent. timedatectl manages time zones and NTP, not locale settings.

QUESTION 10 OF 10
What is the primary advantage of Wayland over X11 from a security perspective?
EXPLANATION

In X11, any application can read keystrokes and screen contents from any other application in the same session — this is a fundamental design flaw exploited by keyloggers and screen-scrapers. Wayland's architecture isolates applications by design: each app only receives input events and display access that it is explicitly granted. This is the most significant security improvement Wayland provides over X11.
