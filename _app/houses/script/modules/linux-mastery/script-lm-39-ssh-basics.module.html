What is SSH?

SSH (Secure Shell) is a cryptographic network protocol for secure communication over an unsecured network. It provides encrypted remote login and command execution, replacing older insecure protocols like telnet and rsh.

SSH Connection Flow

Your Machine
Client
--[Encrypted]-->
Remote Server
SSH Server (port 22)
ssh user@hostname
Connect to a remote server securely
$ ssh admin@192.168.1.50
admin@192.168.1.50's password:
Welcome to Ubuntu 24.04 LTS
admin@server:~$

SSH Connection Syntax

SSH supports many connection options. Here are the most common patterns you'll use.

ssh user@server.com
Basic connection to remote host
ssh -p 2222 user@server
Connect on a custom port (non-standard)
ssh -i ~/.ssh/mykey user@server
Use a specific private key file
ssh user@server 'ls -la'
Run a single command remotely without interactive shell
-p portNon-standard port
-i keyfileIdentity (private key)
-vVerbose / debug mode
-XX11 forwarding (GUI)
-L port:host:portLocal port forwarding
-NNo remote command (tunnels)

SSH Key Pairs

SSH keys provide passwordless authentication that's more secure than passwords. A key pair consists of a private key (kept secret) and a public key (shared with servers).

id_rsa (Private Key)

Stays on YOUR machine only

NEVER share this file!

id_rsa.pub (Public Key)

Goes on remote servers

Safe to share
ssh-keygen
Generate a key pair (interactive prompts)
$ ssh-keygen -t ed25519
Generating public/private ed25519 key pair.
Enter file in which to save the key (/home/learner/.ssh/id_ed25519):
Enter passphrase (empty for no passphrase):
Your identification has been saved in /home/learner/.ssh/id_ed25519
Your public key has been saved in /home/learner/.ssh/id_ed25519.pub
ssh-keygen -t ed25519
Generate Ed25519 key (recommended -- modern and fast)
ssh-keygen -t rsa -b 4096
Generate 4096-bit RSA key (widely compatible)
Copying Your Public Key: ssh-copy-id user@server
This copies your public key to the server's ~/.ssh/authorized_keys file, enabling passwordless login.

The ~/.ssh Directory

SSH configuration and keys are stored in your home directory's .ssh folder. Understanding this structure is essential.

~/.ssh/ Directory Structure
id_rsa # Your private key (600 permissions)
id_rsa.pub # Your public key (644 permissions)
known_hosts # Fingerprints of servers you've connected to
authorized_keys # Public keys allowed to connect (on server)
config # SSH client configuration
~/.ssh/config (SSH Client Config)
# Define shortcuts for servers
Host myserver
HostName 192.168.1.50
User admin
Port 22
IdentityFile ~/.ssh/id_rsa
Host work
HostName work.example.com
User jsmith
IdentityFile ~/.ssh/work_key
# Now just type: ssh myserver
Permission Requirements: SSH is strict about file permissions for security.
~/.ssh/ directory: 700 (drwx------)
Private keys: 600 (-rw-------)
Public keys: 644 (-rw-r--r--)
authorized_keys: 600 (-rw-------)

Fix with: chmod 700 ~/.ssh && chmod 600 ~/.ssh/*

SCP - Secure Copy

scp copies files between hosts over SSH. It uses the same authentication and encryption as SSH.

scp file.txt user@server:~
Copy local file to remote home directory
$ scp report.pdf admin@server:~/documents/
report.pdf 100% 2.4MB 1.2MB/s 00:02
scp user@server:~/file.txt .
Copy remote file to current local directory
scp -r folder/ user@server:~
Copy entire directory recursively
scp -P 2222 file user@server:~
Use custom SSH port (note: uppercase -P for scp)
SCP Syntax Pattern:
Local to Remote: scp [local] [user@host:remote]
Remote to Local: scp [user@host:remote] [local]
Remote to Remote: scp [user@host1:file] [user@host2:path]

Key Takeaways

  • ssh user@host connects to remote servers securely
  • ssh-keygen generates key pairs for passwordless auth
  • Private keys stay local; public keys go to servers
  • ~/.ssh/config defines connection shortcuts
  • scp copies files over SSH encryption
  • File permissions in ~/.ssh must be strict (700/600)
