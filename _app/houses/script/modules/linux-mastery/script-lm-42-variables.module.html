Variable Assignment

Variables store data that your script can use later. In bash, variable assignment has a critical rule: no spaces around the equals sign.

Correct
NAME="John"
AGE=25
FILE=/etc/passwd
Wrong
NAME = "John"
AGE= 25
FILE = /etc/passwd
Common Mistake!
With spaces, bash interprets NAME = "John" as running a command called "NAME" with arguments "=" and "John". This is one of the most common beginner errors in shell scripting.
#!/bin/bash # Variable assignment examples NAME="Alice" AGE=30 GREETING="Hello, World!" DIRECTORY=/home/alice/documents # Using variables with $ echo "My name is $NAME" echo "I am $AGE years old"

Accessing Variables

To use a variable's value, prefix it with a dollar sign ($). There are two main syntaxes:

Syntax Example When to Use
$VAR echo $NAME Simple cases, standalone variable
${VAR} echo ${NAME}s When variable is adjacent to other text
FRUIT="apple" # Without braces - works for standalone echo "I have an $FRUIT" # Output: I have an apple # Need braces when adjacent to text echo "I have ${FRUIT}s" # Output: I have apples # Without braces, bash looks for $FRUITs echo "I have $FRUITs" # Output: I have (empty - $FRUITs doesn't exist)
Best Practice
Always use ${VAR} in scripts for consistency and to avoid ambiguity. It's clearer and prevents subtle bugs when the variable is next to other characters.

Quoting Variables

How you quote variables affects how bash interprets them:

Double Quotes "$VAR"
Variables are expanded. Preserves spaces. Recommended for most cases.
FILE="my file.txt"
cat "$FILE"
# Works correctly
Single Quotes '$VAR'
Everything is literal. No variable expansion. Use for exact strings.
echo '$USER'
# Output: $USER (literal)
No Quotes $VAR
Variables expand but spaces cause word splitting. Dangerous!
FILE="my file.txt"
cat $FILE
# Error: 2 arguments
Backticks / $(...)
Command substitution - runs command and uses output as value.
TODAY=$(date +%Y-%m-%d)
echo "Today: $TODAY"
Always Quote Variables!
Unquoted variables can break your script with filenames containing spaces. Always use "$VAR" unless you specifically need word splitting.

Command Substitution

Command substitution allows you to capture the output of a command and use it as a value:

#!/bin/bash # Modern syntax (preferred) CURRENT_DATE=$(date) FILE_COUNT=$(ls | wc -l) MY_IP=$(hostname -I | awk '{print $1}') # Old syntax (backticks) - still works but harder to read CURRENT_DATE=`date` # Nested command substitution BACKUP_NAME="backup_$(hostname)_$(date +%Y%m%d).tar.gz" echo "Files in directory: $FILE_COUNT" echo "Current date: $CURRENT_DATE" echo "Backup will be: $BACKUP_NAME"
$(...) vs `...`
The $(...) syntax is preferred over backticks because:
  • Easier to read
  • Can be nested: $(cmd1 $(cmd2))
  • No escaping issues

Special Variables
