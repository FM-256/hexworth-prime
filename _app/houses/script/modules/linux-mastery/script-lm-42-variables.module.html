Variable Assignment

Variables store data that your script can use later. In bash, variable assignment has a critical rule: no spaces around the equals sign.

Correct
NAME="John"
AGE=25
FILE=/etc/passwd
Wrong
NAME = "John"
AGE= 25
FILE = /etc/passwd
Common Mistake: With spaces, bash interprets NAME = "John" as running a command called "NAME" with arguments "=" and "John". This is one of the most common beginner errors in shell scripting.
Variable assignment examples
Create variables and use them with the $ prefix
#!/bin/bash
NAME="Alice"
AGE=30
GREETING="Hello, World!"
DIRECTORY=/home/alice/documents
echo "My name is $NAME"
echo "I am $AGE years old"

Accessing Variables

To use a variable's value, prefix it with a dollar sign ($). There are two main syntaxes:

SyntaxExampleWhen to Use
$VARecho $NAMESimple cases, standalone variable
${VAR}echo ${NAME}sWhen adjacent to other text
${VAR} vs $VAR
Braces prevent ambiguity when variable borders other text
FRUIT="apple"
# Without braces - works for standalone
echo "I have an $FRUIT"
# Output: I have an apple
# Need braces when adjacent to text
echo "I have ${FRUIT}s"
# Output: I have apples
# Without braces, bash looks for $FRUITs
echo "I have $FRUITs"
# Output: I have (empty - $FRUITs doesn't exist)
Best Practice: Always use ${VAR} in scripts for consistency and to avoid ambiguity. It's clearer and prevents subtle bugs when the variable is next to other characters.

Quoting Variables

How you quote variables affects how bash interprets them:

"$VAR"Double quotes -- expands variables, preserves spaces
'$VAR'Single quotes -- literal, no expansion
$VARNo quotes -- expands but word-splits (dangerous)
$(cmd)Command substitution -- output as value
Always Quote Variables: Unquoted variables can break your script with filenames containing spaces. Always use "$VAR" unless you specifically need word splitting.

Command Substitution

Command substitution allows you to capture the output of a command and use it as a value:

$(...) syntax
Capture command output into variables -- modern and nestable
#!/bin/bash
# Modern syntax (preferred)
CURRENT_DATE=$(date)
FILE_COUNT=$(ls | wc -l)
MY_IP=$(hostname -I | awk '{print $1}')
# Nested command substitution
BACKUP="backup_$(hostname)_$(date +%Y%m%d).tar.gz"
echo "Files: $FILE_COUNT"
echo "Date: $CURRENT_DATE"
$(...) vs `...`: The $(...) syntax is preferred over backticks because it is easier to read, can be nested ($(cmd1 $(cmd2))), and has no escaping issues.

Special Variables

Bash provides several special built-in variables:

VariableDescription
$HOMEUser's home directory
$USERCurrent username
$PWDCurrent working directory
$PATHCommand search path
$SHELLCurrent shell
$RANDOMRandom number (0-32767)
$$Current script's PID
$?Exit status of last command

Key Takeaways

  • No spaces around = when assigning: VAR=value
  • Use ${VAR} when adjacent to other text
  • Always quote variables: "$VAR"
  • Double quotes expand variables, single quotes are literal
  • Use $(command) for command substitution
