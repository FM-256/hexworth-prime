Creating Files

The touch command is the simplest way to create empty files. It's often used to create placeholder files, update timestamps, or prepare files for later content.

touch file.txt
Create an empty file named file.txt
$ touch notes.txt
touch file1 file2 file3
Create multiple files at once
$ touch a.txt b.txt c.txt
Did You Know?
If a file already exists, touch won't overwrite it. Instead, it updates the file's "last modified" timestamp to the current time. This is useful for build systems that track file changes.

Creating Directories

The mkdir command (make directory) creates new folders. You can create single directories, multiple directories, or entire directory trees.

mkdir dirname
Create a single directory
$ mkdir projects
mkdir -p path/to/dir
Create nested directories (parent + child)
$ mkdir -p src/components/ui
Option Description Example
-p Create parent directories as needed mkdir -p a/b/c
-v Verbose - print each directory created mkdir -v newdir
-m Set permissions while creating mkdir -m 755 public

Removing Files

The rm command (remove) deletes files. This is a destructive operation - there's no recycle bin in Linux by default.

DANGER ZONE
Unlike Windows or macOS, Linux doesn't have a trash bin by default. When you rm a file, it's gone forever. There is no undo. Always double-check before pressing Enter. The famous joke: "rm -rf /" would attempt to delete your entire system (don't try it).
rm file.txt
Remove a single file (permanent)
$ rm oldnotes.txt
rm -i file.txt
Interactive - ask before deleting
$ rm -i important.txt
Option Description Safety Level
-i Interactive - prompt before each removal ✓ Safest
-v Verbose - explain what is being done ○ Informative
-r Recursive - remove directories and contents Dangerous
-f Force - no prompts, ignore errors Very Dangerous

Removing Directories

There are two ways to remove directories:

rmdir dirname
Remove an empty directory only
$ rmdir old_folder
rm -r dirname
Remove directory AND all contents
$ rm -r project_backup
Pro Tip: Safe Deletion
Use rm -ri when deleting directories. The -i flag will ask you to confirm each file deletion, giving you a chance to abort if something looks wrong. For extra safety, use ls first to preview what you're about to delete.

Here's how all four file operation commands compare:

touch a.txt b.txt

Remember
touch and mkdir are safe — they create things. rm is dangerous — it destroys things permanently. When in doubt, use ls to preview and rm -i to confirm each deletion.

Key Takeaways
  • touch creates empty files or updates timestamps
  • mkdir creates directories; use -p for nested paths
  • rm permanently deletes files - use -i for safety
  • rmdir removes empty directories only
  • rm -r removes directories with contents - use carefully
  • Always preview with ls before deleting
