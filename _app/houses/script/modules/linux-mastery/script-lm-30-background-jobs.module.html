Foreground vs Background

By default, commands run in the foreground -- they take over your terminal until complete. But you can run commands in the background to keep using your terminal.

Job States
Foreground
Terminal blocked
<->
Stopped
Ctrl+Z
<->
Background
& or bg

Running in Background

Add & at the end of any command to run it in the background.

sleep 100 &
Run sleep in background
$ sleep 100 &
[1] 12345
./long-script.sh > output.log &
Run script in background, redirect output
$ ./long-script.sh > output.log &
[1] 12346
Background Output: [1] 12345 means: Job number [1], PID 12345. Background jobs still print to terminal unless redirected!

Surviving Logout: nohup

Background jobs die when you close the terminal. Use nohup to keep them running:

nohup ./script.sh &
Run script that survives logout
$ nohup ./script.sh &
nohup: ignoring input and appending output to 'nohup.out'
nohup command > output.log 2>&1 &
Redirect all output to file
Alternative: disown. Already started a job? Use disown %1 to detach it from the shell after the fact.

Key Takeaways

  • command & runs in background
  • Ctrl+Z suspends foreground job
  • jobs lists all jobs
  • fg %N brings job N to foreground
  • bg %N resumes job N in background
  • nohup keeps job running after logout
