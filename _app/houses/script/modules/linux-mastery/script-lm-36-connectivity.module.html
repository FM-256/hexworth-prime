Testing Connectivity with ping

o))
ping [options] destination
Send ICMP echo requests to test reachability

The ping command sends ICMP (Internet Control Message Protocol) packets to a host and measures the response time. It's the first tool to use when troubleshooting network connectivity.

How Ping Works
Your Machine
192.168.1.100
--ICMP Echo-->
Target Host
8.8.8.8
<--ICMP Reply--
ping localhost
Test local network stack
ping 8.8.8.8
Ping by IP address
ping -c 4 google.com
Send only 4 packets
ping -i 0.5 host
Ping every 0.5 seconds
$ ping -c 3 8.8.8.8
PING 8.8.8.8 (8.8.8.8) 56(84) bytes of data. 64 bytes from 8.8.8.8: icmp_seq=1 ttl=117 time=14.2 ms 64 bytes from 8.8.8.8: icmp_seq=2 ttl=117 time=13.8 ms 64 bytes from 8.8.8.8: icmp_seq=3 ttl=117 time=14.1 ms --- 8.8.8.8 ping statistics --- 3 packets transmitted, 3 received, 0% packet loss, time 2003ms rtt min/avg/max/mdev = 13.812/14.033/14.203/0.163 ms
Reading Ping Output
ttl - Time To Live (hops remaining)
time - Round-trip time in milliseconds
packet loss - 0% means perfect connectivity
rtt - Round-trip time statistics

Tracing Network Paths

When you need to see the path packets take to reach a destination, use traceroute or tracepath.

traceroute google.com
Show route to destination (may need sudo)
tracepath google.com
Similar, doesn't need root privileges
traceroute -n 8.8.8.8
Numeric only (skip DNS lookups)
mtr google.com
Combines ping and traceroute (live)
$ tracepath 8.8.8.8
1?: [LOCALHOST] pmtu 1500 1: _gateway 0.521ms 2: 10.0.0.1 8.234ms 3: 72.14.215.85 12.456ms 4: 142.251.49.24 13.891ms 5: 8.8.8.8 14.123ms reached Resume: pmtu 1500 hops 5 back 5
Note: Firewalls May Block
Some routers and firewalls block ICMP packets, causing asterisks (*) in traceroute output. This doesn't necessarily mean there's a problem - the route may still work for other traffic.

Viewing Ports and Connections

The ss command (socket statistics) is the modern replacement for netstat. Both show network connections, listening ports, and routing tables.

ss -tuln
Show TCP/UDP listening ports (numeric)
ss -tulnp
Include process names (needs sudo)
ss -ta
Show all TCP connections
netstat -tuln
Legacy equivalent of ss -tuln
Option Meaning
-t TCP connections
-u UDP connections
-l Listening sockets only
-n Numeric (don't resolve names)
-p Show process using socket
-a All sockets (listening + established)
$ ss -tuln
Netid State Recv-Q Send-Q Local Address:Port Peer Address:Port tcp LISTEN 0 128 0.0.0.0:22 0.0.0.0:* tcp LISTEN 0 511 0.0.0.0:80 0.0.0.0:* tcp LISTEN 0 511 0.0.0.0:443 0.0.0.0:* udp UNCONN 0 0 0.0.0.0:53 0.0.0.0:*
Common Ports
22 - SSH
80 - HTTP
443 - HTTPS
53 - DNS
3306 - MySQL
5432 - PostgreSQL

  • ss -tuln shows listening TCP/UDP ports
  • ss replaces netstat on modern systems
