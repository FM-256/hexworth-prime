Create a symbolic (soft) link that points to another file.

Learning Objectives

  • Understand the difference between hard links and symbolic links
  • Create symbolic links with ln -s
  • Create hard links with ln

  • Understand inodes and how links work at the filesystem level

What Are Links?

Links let you create multiple references to the same file or directory. Think of them as shortcuts, but with some important differences depending on the type of link.

Linux supports two types of links: hard links and symbolic (soft) links. Understanding when to use each is essential for managing files effectively.

Understanding Inodes

Before diving into links, you need to understand inodes. Every file in Linux has an inode -- a data structure that stores information about the file (permissions, ownership, timestamps, location on disk).

Key Concept: The filename you see is just a pointer to an inode. The actual file data is stored separately, referenced by the inode number.
Directory Entry Inode Table Disk +-----------+ +----------+ +---------+ | report.txt| --------> | Inode 42 | ------> | Data | +-----------+ | size: 1KB| | blocks | | owner:bob| +---------+ | perms:644| +----------+
ls -i report.txt
View a file's inode number
$ ls -i report.txt
42 report.txt

Symbolic Links (Soft Links)

A symbolic link is like a shortcut -- it's a special file that points to another file by name. It's the most commonly used type of link.

ln -s /path/to/original linkname
Create a symbolic link to a file or directory
# Link to a config file
$ ln -s /etc/nginx/nginx.conf ~/nginx.conf
# Link to a directory
$ ln -s /var/log ~/logs
Symbolic Link Original File +--------------+ +-------------+ | mylink | ----------> | report.txt | | (Inode 99) | "path" | (Inode 42) | | Contains: | +-------------+ | "/home/bob/ | | | report.txt" | v +--------------+ +-----------+ | File Data | +-----------+
ls -l mylink
Symbolic links show with an arrow in ls -l
$ ls -l mylink
lrwxrwxrwx 1 bob bob 11 Jan 26 10:00 mylink -> report.txt

Hard Links

A hard link is a direct reference to the same inode as the original file. It's essentially another name for the exact same file data.

ln original.txt hardlink.txt
Create a hard link (no -s flag) -- both share the same inode
$ ln original.txt hardlink.txt
$ ls -li
42 -rw-r--r-- 2 bob bob 1024 Jan 26 original.txt
42 -rw-r--r-- 2 bob bob 1024 Jan 26 hardlink.txt
Directory Entry 1 Inode Table Disk +-------------+ +----------+ +---------+ | original.txt| -------+ | Inode 42 | ------> | Data | +-------------+ +--> | links: 2 | | blocks | | | size: 1KB| +---------+ Directory Entry 2 | +----------+ +-------------+ | | hardlink.txt| -------+ +-------------+
Hard Link Limitations: Cannot link to directories (prevents loops), cannot cross filesystem boundaries, and must be on the same partition.

Using readlink

The readlink command shows where a symbolic link points:

readlink / readlink -f
Show link target or resolve the full canonical path
# Show link target
$ readlink mylink
/home/bob/report.txt
# Show canonical (absolute) path
$ readlink -f mylink
/home/bob/documents/report.txt
# Useful for scripts to resolve symlinks
$ readlink -f /usr/bin/python
/usr/bin/python3.10

Common Use Cases

Version Switching
Symlinks are perfect for switching between versions
# Point current to a specific version
$ ln -sf /opt/app-2.0 /opt/app-current
# Upgrade? Just update the link
$ ln -sf /opt/app-2.1 /opt/app-current
Organizing Dotfiles
Keep configs in a repo, symlink to home
$ ln -s ~/dotfiles/.bashrc ~/.bashrc
$ ln -s ~/dotfiles/.vimrc ~/.vimrc
Shared Libraries
Libraries use symlinks for version compatibility
$ ls -l /usr/lib/libssl*
libssl.so -> libssl.so.3
libssl.so.3 -> libssl.so.3.0.2
libssl.so.3.0.2 (actual file)
-sCreate symbolic (soft) link
-fForce overwrite existing link
-nDon't dereference symlinks
-vVerbose output

Key Takeaways

  • ln -s target linkname creates a symbolic link (most common)
  • ln target linkname creates a hard link (same inode)
  • Hard links survive the original being deleted; symlinks become broken
  • Hard links cannot cross filesystems or link to directories
  • Use readlink -f to resolve a symlink's full path
  • Use ls -li to see inode numbers and compare links
