What Are Links?

Links let you create multiple references to the same file or directory. Think of them as shortcuts, but with some important differences depending on the type of link.

Linux supports two types of links: hard links and symbolic (soft) links. Understanding when to use each is essential for managing files effectively.

Understanding Inodes

Before diving into links, you need to understand inodes. Every file in Linux has an inode - a data structure that stores information about the file (permissions, ownership, timestamps, location on disk).

Key Concept: Inodes

The filename you see is just a pointer to an inode. The actual file data is stored separately, referenced by the inode number.

Directory Entry Inode Table Disk +-----------+ +----------+ +---------+ | report.txt| --------> | Inode 42 | ------> | Data | +-----------+ | size: 1KB| | blocks | | owner:bob| +---------+ | perms:644| +----------+

You can see a file's inode number with ls -i:

ls -i report.txt 42 report.txt

Symbolic Links (Soft Links)

A symbolic link is like a shortcut - it's a special file that points to another file by name. It's the most commonly used type of link.

# Create a symbolic link ln -s /path/to/original linkname # Example: Link to a config file ln -s /etc/nginx/nginx.conf ~/nginx.conf # Example: Link to a directory ln -s /var/log ~/logs
How Symbolic Links Work

A symlink contains the path to the target file. When you access the symlink, the system follows that path to find the real file.

Symbolic Link Original File +--------------+ +-------------+ | mylink | ----------> | report.txt | | (Inode 99) | "path" | (Inode 42) | | Contains: | +-------------+ | "/home/bob/ | | | report.txt" | v +--------------+ +-----------+ | File Data | +-----------+

Symbolic links show with an arrow in ls -l:

ls -l mylink lrwxrwxrwx 1 bob bob 11 Jan 26 10:00 mylink -> report.txt

Hard Links

A hard link is a direct reference to the same inode as the original file. It's essentially another name for the exact same file data.

# Create a hard link (no -s flag) ln original.txt hardlink.txt # Both files now point to the same inode ls -li 42 -rw-r--r-- 2 bob bob 1024 Jan 26 original.txt 42 -rw-r--r-- 2 bob bob 1024 Jan 26 hardlink.txt

Notice both files have inode 42 and the link count is 2.

Directory Entry 1 Inode Table Disk +-------------+ +----------+ +---------+ | original.txt| -------+ | Inode 42 | ------> | Data | +-------------+ +--> | links: 2 | | blocks | | | size: 1KB| +---------+ Directory Entry 2 | +----------+ +-------------+ | | hardlink.txt| -------+ +-------------+
Hard Link Limitations
  • - Cannot link to directories (prevents loops)
  • - Cannot cross filesystem boundaries
  • - Must be on the same partition

Comparison: Hard vs Symbolic

Feature Hard Link Symbolic Link
Points to Same inode (data) Path to file
Cross filesystem No Yes
Link to directories No Yes
Original deleted Data still accessible Link becomes broken
File size Same as original Size of path string
Common use Backups, file sharing Shortcuts, versioning

Using readlink

The readlink command shows where a symbolic link points:

# Show link target readlink mylink /home/bob/report.txt # Show canonical (absolute) path readlink -f mylink /home/bob/documents/report.txt # Useful for scripts to resolve symlinks readlink -f /usr/bin/python /usr/bin/python3.10

Common Use Cases

Version Switching

Symlinks are perfect for switching between versions:

# Point current to a specific version ln -sf /opt/app-2.0 /opt/app-current # Upgrade? Just update the link ln -sf /opt/app-2.1 /opt/app-current
Organizing Dotfiles

Keep configs in a repo, symlink to home:

ln -s ~/dotfiles/.bashrc ~/.bashrc ln -s ~/dotfiles/.vimrc ~/.vimrc
Shared Libraries

Libraries use symlinks for version compatibility:

ls -l /usr/lib/libssl* libssl.so -> libssl.so.3 libssl.so.3 -> libssl.so.3.0.2 libssl.so.3.0.2 (actual file)
