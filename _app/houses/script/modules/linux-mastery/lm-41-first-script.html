What Is a Shell Script?

A shell script is a text file containing a series of commands. Instead of typing commands one by one, you write them in a file and run them all at once. It's like creating a recipe that the computer follows step by step.

#!/
#!/bin/bash
The shebang - tells the system which interpreter to use

Shell scripts are the foundation of automation in Linux. System administrators use them to automate backups, monitor systems, deploy applications, and countless other tasks.

The Shebang (#!)

Every shell script should start with a shebang (also called hashbang). This special line tells the system which program should interpret the script.

#!/bin/bash
Use Bash shell - most common choice for Linux scripts. Supports all bash features.
#!/bin/bash
#!/bin/sh
Use POSIX shell - more portable but fewer features. Works on any Unix system.
#!/bin/sh
#!/usr/bin/env bash
Find bash anywhere in PATH. More portable if bash isn't at /bin/bash.
#!/usr/bin/env bash
#!/usr/bin/python3
Not just for shell! You can specify any interpreter - Python, Perl, Ruby, etc.
#!/usr/bin/python3
Important!
The shebang must be the very first line of the file - no blank lines or spaces before it. If there's anything before the #!, it won't work.

Creating Your First Script

Let's create a simple "Hello World" script. You can use any text editor - nano, vim, or even echo with redirection.

#!/bin/bash # My first script - hello.sh # This script greets the user echo "Hello, World!" echo "Welcome to shell scripting!" echo "Today is $(date)"

Lines starting with # (except the shebang) are comments. Comments are ignored by bash but help explain what your code does.

Naming Convention
Shell scripts typically use the .sh extension, but it's not required. The shebang determines how the file is executed, not the extension. However, using .sh makes it clear the file is a shell script.

Making Scripts Executable

After creating a script, you need to make it executable using chmod:

# Give execute permission to the owner chmod +x hello.sh # Or be more specific with numeric mode chmod 755 hello.sh # Check the permissions ls -l hello.sh # -rwxr-xr-x 1 user user 89 Jan 26 10:00 hello.sh

The x in the permissions indicates the file can be executed. Without it, you'll get "Permission denied" when trying to run the script directly.

Running Your Script

There are several ways to run a shell script:

Method Command Requires +x? Notes
Direct execution ./hello.sh Yes Uses shebang to determine interpreter
Explicit interpreter bash hello.sh No Bypasses shebang, uses specified shell
Source/dot command source hello.sh No Runs in current shell (affects environment)
Full path /home/user/hello.sh Yes Can run from anywhere
Why ./script.sh?
The ./ prefix is needed because the current directory is usually not in your PATH for security reasons. It explicitly tells bash "run the script in the current directory" rather than searching PATH for a command named "script.sh".

> Key Takeaways
  • Shell scripts are text files containing commands to execute
  • Start every script with a shebang: #!/bin/bash
  • Make scripts executable with chmod +x script.sh
  • Run with ./script.sh or bash script.sh
  • Use comments (#) to document your code
