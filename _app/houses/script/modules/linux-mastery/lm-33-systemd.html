⚙️ What Is systemd?

systemd is the init system and service manager for most modern Linux distributions. It's the first process (PID 1) that starts when you boot, and it manages all other services and processes.

systemd Architecture
You (User)
↓
systemctl (Command)
↓
systemd (PID 1)
↓
Services (nginx, ssh, docker...)

You interact with systemd through the systemctl command to start, stop, and manage services.

🎮 systemctl Commands

⚙️
systemctl [action] [service]
Control and query system services
systemctl start nginx
Start a service now
systemctl stop nginx
Stop a running service
systemctl restart nginx
Stop then start service
systemctl status nginx
Check service status
systemctl enable nginx
Start at boot
systemctl disable nginx
Don't start at boot

📊 Reading Status Output

The systemctl status command shows detailed service information:

nginx.service - A high performance web server
Loaded: loaded (/lib/systemd/system/nginx.service; enabled)
Active: active (running) since Mon 2024-01-15 09:00:00 UTC
Main PID: 1234 (nginx)
Tasks: 3
Memory: 8.5M
Field Meaning
Loaded Service file location; enabled = starts at boot
Active Running state: active, inactive, failed
Main PID Process ID of the main service process
Tasks Number of tasks/threads

📋 Listing Services

Command Description
systemctl list-units List all loaded units (services, mounts, etc.)
systemctl list-units --type=service List only services
systemctl list-units --state=running List running services
systemctl list-unit-files List all available services
systemctl is-active nginx Check if service is running
systemctl is-enabled nginx Check if service starts at boot

📜 Viewing Logs: journalctl

systemd keeps centralized logs. Use journalctl to view them:

Command Description
journalctl View all logs
journalctl -u nginx Logs for specific service
journalctl -f Follow logs in real-time
journalctl -u nginx -f Follow service logs live
journalctl --since "1 hour ago" Logs from last hour
journalctl -p err Only error messages
💡 Quick Debugging
Service won't start? Check its logs:
systemctl status nginx (recent logs at bottom)
journalctl -u nginx -e (jump to end of logs)
