curl vs wget: Two Powerful Tools

Linux provides two main command-line tools for downloading files and interacting with web servers. Both are essential for system administrators and developers.

curl

"Client URL" -- versatile data transfer tool supporting many protocols. Great for APIs and scripting.

  • Outputs to stdout by default
  • Supports many protocols (HTTP, FTP, SFTP...)
  • Excellent for REST APIs
  • Single file transfers

wget

"Web Get" -- file retrieval utility designed for downloading. Perfect for bulk downloads.

  • Saves to file by default
  • Recursive downloads
  • Continues interrupted downloads
  • Mirror websites

curl - Client URL

The swiss army knife of data transfer. curl outputs to stdout by default, making it perfect for piping and scripting.

curl https://example.com
Fetch and display content to stdout
$ curl https://example.com
<!doctype html>
<html>...</html>
curl -O https://example.com/file.zip
Save with original remote filename
$ curl -O https://example.com/file.zip
% Total % Received Time Current
100 1024k 100 1024k 0 0 2.5M 0 0:00:00 --:--:-- 2.5M
curl -o myfile.zip URL
Save with a custom filename
curl -I https://github.com
Get HTTP headers only (HEAD request)
$ curl -I https://github.com
HTTP/2 200
server: GitHub.com
content-type: text/html; charset=utf-8
x-frame-options: DENY
x-content-type-options: nosniff
-OSave with remote filename
-o fileSave to specific filename
-LFollow redirects (301, 302)
-IFetch headers only
-sSilent mode
-vVerbose output
-H "Key: val"Add custom header

wget - Web Get

wget is a non-interactive network downloader. It saves to file by default and excels at recursive downloads and resuming interrupted transfers.

wget https://example.com/file.zip
Download and save file automatically
$ wget https://example.com/file.zip
Resolving example.com... 93.184.216.34
Connecting to example.com|93.184.216.34|:443... connected.
HTTP request sent, awaiting response... 200 OK
Length: 1048576 (1.0M) [application/zip]
Saving to: 'file.zip'
file.zip 100%[===================>] 1.00M 2.50MB/s in 0.4s
'file.zip' saved [1048576/1048576]
wget -c URL
Continue an interrupted download
wget -O custom.zip URL
Save with custom filename
wget -r URL
Recursive download (mirror site)
-O fileSave to specified filename
-cContinue partial download
-qQuiet (suppress output)
-bRun in background
-rRecursive download
-P dirSave to directory
--limit-rate=100kLimit download speed

Common Use Cases

Downloading Scripts: curl -fsSL https://get.docker.com | bash
Commonly used to download and execute installation scripts. The -fsSL flags mean: fail silently (-f), silent (-s), show errors (-S), follow redirects (-L).
Testing APIs: curl -s https://api.github.com/users/octocat | jq .
Fetch JSON from an API and pipe to jq for pretty-printing.
Checking Connectivity: curl -I -s https://google.com | head -1
Quick way to check if a website is responding.
SECURITY WARNING: Never pipe curl directly to bash without first inspecting the script! Malicious scripts could harm your system.

Safe approach:
curl -O https://example.com/script.sh
cat script.sh -- review the script
bash script.sh -- then execute

Key Takeaways

  • curl outputs to stdout; use -O or -o to save files
  • wget saves to file by default
  • curl -I fetches HTTP headers only
  • wget -c continues interrupted downloads
  • -L (curl) follows redirects automatically
  • Never blindly pipe downloads to bash -- inspect first!
