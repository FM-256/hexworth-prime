What is a PID?
Every process on a Linux system is assigned a Process ID (PID) — a unique integer that the kernel uses to track it. PIDs start at 1 and increment. When the system boots, the first process is the init system (PID 1) — either systemd or init. Every other process descends from PID 1 in a parent-child tree.
Key facts about PIDs:
  • PID 0 — the kernel scheduler (swapper/idle). You never see this in ps.
  • PID 1 — init/systemd. If PID 1 dies, the system panics and reboots.
  • PPID — Parent PID. Every process has a parent. Orphaned processes get adopted by PID 1.
  • PID recycling — after a process exits, its PID can be reused. Default max is 32768 (see /proc/sys/kernel/pid_max).
  • PID namespaces — in containers (Docker), processes get their own PID space. PID 1 inside the container is a different process than PID 1 on the host.
  • /proc/[pid]/ — every running process has a virtual directory in /proc with its memory maps, file descriptors, environment variables, and status.
Reading ps aux — Column by Column
ps aux is the most common way to see all running processes. Every column means something specific. Here is how to read the output:
analyst@soc-ws:~$
$ ps aux
USER         PID  %CPU  %MEM    VSZ   RSS TTY      STAT START  TIME COMMAND
root           1   0.0   0.4 169436 13204 ?        Ss   Mar19  0:03 /sbin/init
root           2   0.0   0.0      0     0 ?        S    Mar19  0:00 [kthreadd]
www-data    1847  98.2   4.1 285640 67832 ?        R    09:14 47:23 crypto-miner
analyst     2341   0.1   1.2 412800 19840 pts/0    Ss   08:47  0:01 -bash
analyst     3102   0.0   0.0      0     0 pts/0    Z+   09:31  0:00 [defunct]
root         892   0.0   0.8 163280 12448 ?        Ssl  Mar19  0:12 /usr/sbin/sshd
mysql        1204   0.3   6.8 1284520 112640 ?      Ssl  Mar19  2:41 /usr/sbin/mysqld
USER
Owner of the process. root = system, www-data = web server, your username = your processes. If a web server process runs as root, that is a security concern.
PID
Process ID. This is what you use with kill. Low PIDs (1-1000) are typically system services. High PIDs are user processes. A process you didn't start with a high PID is suspicious.
%CPU / %MEM
Current resource usage. 98% CPU = something is wrong or doing heavy work. Normal system processes use <1%. A crypto miner will peg CPU at 100%.
VSZ / RSS
VSZ = virtual memory (total allocated). RSS = resident set size (actually in RAM). RSS is what matters. If RSS > physical RAM, the system starts swapping and slows down.
TTY
Terminal associated with the process. pts/0 = SSH session or terminal emulator. ? = daemon (no terminal). tty1 = physical console.
STAT
Process state. R=running, S=sleeping (waiting), D=uninterruptible sleep (disk I/O), Z=zombie (dead but not reaped), T=stopped. Modifiers: s=session leader, l=multithreaded, +=foreground.
START / TIME
START = when the process began. TIME = cumulative CPU time consumed. A process started at 2 AM that nobody started is suspicious. 47:23 CPU time on a web worker = crypto mining.
COMMAND
The actual command that launched the process. [brackets] = kernel thread. Suspicious names: crypto-miner, svchost (on Linux), base64-encoded strings, processes running from /tmp or /dev/shm.
Process States Explained
R
Running
Actively executing on CPU or waiting in the run queue. This is the only state that consumes CPU.
S
Sleeping
Waiting for an event (user input, network data, timer). Most processes are in this state. Normal and healthy.
D
Uninterruptible
Waiting on disk I/O. Cannot be killed (not even with SIGKILL). Many D-state processes = disk problem or NFS hang.
Z
Zombie
Process exited but parent hasn't read its exit status. Shows as [defunct]. A few are normal. Hundreds indicate a buggy parent process.
T
Stopped
Suspended by Ctrl+Z or a debugger (SIGSTOP). Use fg to resume in foreground or bg for background.
The /proc Filesystem
Every running process exposes detailed information through the /proc/[pid]/ virtual filesystem. This is where tools like ps and top actually get their data.
$ ls /proc/1847/
cmdline   # Full command that started this process
cwd       # Symlink to current working directory
environ   # Environment variables (KEY=VALUE pairs)
exe       # Symlink to the actual binary on disk
fd/       # Open file descriptors (files, sockets, pipes)
maps      # Memory mappings (shared libs, heap, stack)
net/      # Network information for this process
status    # Human-readable status (PID, PPID, state, memory)
$ cat /proc/1847/status | head -8
Name:   crypto-miner
State:  R (running)
Pid:    1847
PPid:   1841
Uid:    33  33  33  33    # UID 33 = www-data
VmRSS:  67832 kB         # Physical memory used
Threads: 4
voluntary_ctxt_switches:  12
Security tip: During incident response, always check /proc/[pid]/exe — it shows the actual binary path even if the process renamed itself. If exe points to a deleted file or /tmp, that is a strong indicator of malware.

CHALLENGE 1 Incomplete
Process Detective
A runaway process is consuming CPU. Find the process with the highest CPU usage using ps aux.
Objective
Find the PID of the process using the most CPU
Use ps aux and look at the %CPU column. The highest value is your target.
CHALLENGE 2 Incomplete
Graceful Termination
Terminate the high-CPU process gracefully using SIGTERM (not SIGKILL).
Objective
Kill the runaway process with kill (not kill -9)
Use kill PID without the -9 flag. The default signal is SIGTERM.
CHALLENGE 3 Incomplete
Background Runner
Start a long backup job in the background so you can keep working.
Objective
Run backup.sh in the background
Add & at the end: ./backup.sh &
CHALLENGE 4 Incomplete
Job Juggler
List all running jobs and bring job #1 back to the foreground.
Objective
Use jobs to list, then fg to bring to foreground
Run jobs first, then fg %1
CHALLENGE 5 Incomplete
Mass Termination
Multiple zombie python processes are running. Kill all of them at once by name.
Objective
Kill all python3 processes with one command
Use killall python3 or pkill python
CHALLENGE 6 Incomplete
Cron Scheduler
Schedule a cleanup script to run every day at midnight.
Objective
Create a cron entry for daily midnight execution
Use crontab-add "0 0 * * *" "/path/script.sh" or crontab-add "@daily" "/path/script.sh"
CHALLENGE 7 Incomplete
Service Check
The web server seems down. Check if nginx is running and start it if needed.
Objective
Check nginx status and start if not running
Use systemctl status nginx then systemctl start nginx
CHALLENGE 8 Incomplete
Boot Persistence
Enable nginx to start automatically on system boot.
Objective
Configure nginx to start at boot
Use systemctl enable nginx
