What is a Database?

A database is an organized collection of structured data stored electronically. Think of it as a highly optimized filing cabinet that can search through millions of records in milliseconds. Every web application, mobile app, and enterprise system you use relies on at least one database behind the scenes.

Databases solve three fundamental problems: storage (where does the data live?), retrieval (how do we find specific records quickly?), and integrity (how do we prevent corrupt or inconsistent data?).

Relational vs Non-Relational

The two major families of databases serve different needs. Relational databases (RDBMS) organize data into tables with defined relationships between them. They use SQL as their query language and enforce strict schemas. Non-relational databases (NoSQL) use flexible data models like documents, key-value pairs, or graphs.

Feature Relational (SQL) Non-Relational (NoSQL)
Data Model Tables with rows & columns Documents, key-value, graph
Schema Fixed, defined upfront Flexible, schema-on-read
Query Language SQL (standardized) Varies by system
Relationships JOINs across tables Embedded or referenced
Examples PostgreSQL, MySQL, SQLite MongoDB, Redis, Cassandra
Best For Complex queries, transactions Flexible schemas, horizontal scale

Tables, Rows & Columns

In a relational database, data lives in tables. Each table has a name (like employees or departments) and consists of:

Columns (Fields) Define what data is stored. Each column has a name and data type (TEXT, INTEGER, REAL, etc.)
Rows (Records) Each row is one entry in the table. An employee table with 20 employees has 20 rows.
Primary Key (PK) A unique identifier for each row. Usually an auto-incrementing integer called id.
Foreign Key (FK) A column that references a primary key in another table, creating a relationship between tables.

In our training database, the employees table has a department_id column that references the id column in the departments table. This is how relational databases connect data across tables.

What is SQL?

SQL (Structured Query Language) is the standard language for communicating with relational databases. It was created in the 1970s at IBM and is now used by every major RDBMS. SQL lets you:

Query Data (DQL) SELECT statements retrieve and filter data from tables
Modify Data (DML) INSERT, UPDATE, DELETE change the data stored in tables
Define Structure (DDL) CREATE, ALTER, DROP define and modify table schemas
Control Access (DCL) GRANT, REVOKE manage who can access what data

Your First SQL Queries

The most fundamental SQL command is SELECT. It retrieves data from a table. Try these queries in the SQL console on the left:

1. View all data in a table:

SELECT * FROM employees;

The * means "all columns". This returns every row and every column in the employees table.

2. Select specific columns:

SELECT first_name, last_name, salary FROM employees;

Instead of *, list the column names you want. This is better practice in production code because it makes your intent clear and reduces data transfer.

3. Count records:

SELECT COUNT(*) FROM employees;

COUNT(*) returns the number of rows in a table. It is an aggregate function that we will explore in depth later.

4. Column aliases:

SELECT first_name AS "Name", salary AS "Annual Pay" FROM employees;

The AS keyword lets you rename columns in the output. This does not change the actual table, only the display name in your results.

The Training Database

Throughout this course, you will work with a company database for Meridian Technologies, a fictional cybersecurity firm. Click the TABLES button in the SQL console to see all available tables. The database contains:

employees (20 rows) Staff records with names, emails, salaries, hire dates, and department assignments
departments (6 rows) Company departments with locations and budgets
customers (8 rows) Client companies with contact info and locations
products (10 rows) Security and DevOps products with pricing and stock levels
orders (14 rows) Customer purchase orders with dates, totals, and status
order_items (23 rows) Individual line items linking orders to products

Key Takeaways

  • Databases organize data for efficient storage, retrieval, and integrity
  • Relational databases use tables with defined schemas and SQL
  • Tables have columns (what data), rows (individual records), and keys (identifiers)
  • SQL SELECT retrieves data; use * for all columns or list specific ones
  • COUNT(*) returns the number of rows in a table
