Learning Objectives

  • Understand what NULL means (not zero, not empty string)
  • Use IS NULL and IS NOT NULL to filter missing data
  • Use COALESCE to provide default values for NULLs
  • Use NULLIF to safely avoid division by zero
  • Understand how NULL behaves in arithmetic and comparisons

What is NULL?

In SQL, NULL represents an unknown or missing value. It is not the same as 0, an empty string '', or the word "null". NULL means "we do not know what this value is." A salary of 0 means someone earns nothing. A salary of NULL means we have no salary information on file.

This distinction matters because SQL uses three-valued logic. Instead of just TRUE and FALSE, every comparison can also evaluate to UNKNOWN. Any comparison involving NULL produces UNKNOWN, which behaves like FALSE in WHERE clauses.

Expression Result Why
5 = 5 TRUE Both values are known and equal
5 = NULL UNKNOWN Cannot compare a known value to an unknown one
NULL = NULL UNKNOWN Two unknowns are not necessarily equal
NULL != NULL UNKNOWN Cannot determine if two unknowns differ
Common Mistake

Writing WHERE salary = NULL will never return any rows, even if rows have NULL salaries. The comparison NULL = NULL evaluates to UNKNOWN, not TRUE. Always use IS NULL instead.

IS NULL / IS NOT NULL

Since you cannot use = or != to test for NULL, SQL provides special operators: IS NULL and IS NOT NULL. These are the only correct way to check for missing values.

Find employees with no manager (top-level staff):

SELECT first_name, last_name, title FROM employees WHERE manager_id IS NULL;

This returns only rows where manager_id has no value. These are typically executives or department heads who do not report to anyone in the system.

Find employees who do have a manager:

SELECT first_name, last_name, manager_id FROM employees WHERE manager_id IS NOT NULL;

IS NOT NULL filters for rows where the value is present and known. Try both queries in the SQL console to see the difference.

COALESCE

COALESCE accepts a list of values and returns the first non-NULL value it finds. It is your primary tool for providing default values when data might be missing.

SELECT first_name, COALESCE(manager_id, 0) AS mgr FROM employees;

If manager_id is NULL, the query returns 0 instead. The original data is not changed; COALESCE only affects the query output.

COALESCE can take multiple fallback values. It checks them left to right and returns the first one that is not NULL:

-- Try phone, then email, then 'No Contact' SELECT COALESCE(phone, email, 'No Contact') AS contact FROM customers;

This pattern is extremely common in real applications. Reports, dashboards, and APIs all use COALESCE to ensure clean output even when source data has gaps.

NULLIF

NULLIF does the opposite of COALESCE. It takes two arguments and returns NULL if they are equal, otherwise it returns the first argument. This is most commonly used to prevent division by zero errors.

-- Returns NULL instead of the value if salary is 0 SELECT first_name, NULLIF(salary, 0) AS safe_salary FROM employees;

The real power of NULLIF shows in division. Dividing by zero causes an error, but dividing by NULL safely returns NULL:

-- Safe division: returns NULL instead of error if quantity is 0 SELECT product_name, total_revenue / NULLIF(quantity_sold, 0) AS price_per_unit FROM products;

You can combine NULLIF with COALESCE for a complete safety net: COALESCE(total / NULLIF(quantity, 0), 0) returns 0 instead of erroring on division by zero.

NULLs in Arithmetic

Any arithmetic operation involving NULL returns NULL. The database cannot compute a result when one of the operands is unknown. This is a frequent source of unexpected results for beginners.

SELECT first_name, salary, salary + NULL AS broken FROM employees;

The broken column will be NULL for every row, regardless of the actual salary value. NULL + 5 = NULL, NULL * 100 = NULL, NULL - NULL = NULL. There are no exceptions.

This is why COALESCE matters in calculations. If you are summing values that might be NULL, wrap them first:

-- Safe: treats NULL bonus as 0 SELECT first_name, salary + COALESCE(bonus, 0) AS total_comp FROM employees;

NULLs in Aggregates

Aggregate functions handle NULL differently depending on whether you use * or a column name. This is one of the most important distinctions in SQL:

COUNT(*) Counts all rows in the result set, including rows where columns are NULL
COUNT(column) Counts only rows where the specified column is NOT NULL
SELECT COUNT(*) AS total_employees, COUNT(manager_id) AS has_manager FROM employees;

If the employees table has 20 rows and 2 employees have NULL manager_id values, COUNT(*) returns 20 while COUNT(manager_id) returns 18.

The same rule applies to other aggregate functions. SUM, AVG, MIN, and MAX all skip NULL values. This means AVG(salary) divides by the number of non-NULL salaries, not the total number of rows. This can silently skew your results if you are not aware of it.

Watch Out: AVG and NULLs

If 10 employees have salaries and 5 have NULL, AVG(salary) divides the sum by 10, not 15. To include NULLs as zero, use AVG(COALESCE(salary, 0)) which divides by all 15 rows.

Key Takeaways

  • NULL means unknown/missing, not zero or empty string
  • Use IS NULL and IS NOT NULL to test for missing values (never use = NULL)
  • COALESCE returns the first non-NULL value from a list of arguments
  • NULLIF returns NULL when two values are equal, useful for preventing division by zero
  • Any arithmetic with NULL returns NULL; use COALESCE to provide safe defaults
  • COUNT(*) counts all rows; COUNT(column) skips NULLs; SUM/AVG/MIN/MAX also skip NULLs
