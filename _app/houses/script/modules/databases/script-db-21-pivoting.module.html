What is Pivoting?

Pivoting transforms row-based data into column-based format. Instead of seeing one row per category, you see one column per category. This is the foundation of cross-tab reports, dashboards, and summary tables.

Consider a table that stores employee counts by department, one row per department. A pivot reshapes that into a single row with one column per department:

Before (Rows) Engineering: 7
Marketing: 5
Sales: 4
One row per department
After (Columns) | eng | mkt | sales |
| 7 | 5 | 4 |
One column per department

Why pivot? Because humans read tables horizontally. A manager comparing departments wants columns side by side, not a vertical list. Pivoted data also feeds naturally into charts, spreadsheets, and executive summaries.

CASE-Based Pivot

The core technique uses SUM(CASE WHEN ... THEN ... ELSE ... END) to convert row values into columns. Each CASE expression becomes one output column:

SELECT SUM(CASE WHEN department_id = 1 THEN 1 ELSE 0 END) AS engineering, SUM(CASE WHEN department_id = 2 THEN 1 ELSE 0 END) AS marketing, SUM(CASE WHEN department_id = 3 THEN 1 ELSE 0 END) AS sales FROM employees;

This produces a single row: one column for each department, with the count of employees in that department. The CASE WHEN acts as a filter inside the aggregation -- it only counts (or sums) rows that match the condition.

How it works step by step: For each row, the CASE expression returns 1 if the condition matches and 0 otherwise. SUM then adds up the 1s, giving you the count. You could also use COUNT with a NULL trick: COUNT(CASE WHEN dept = 1 THEN 1 END) -- COUNT ignores NULLs, so non-matching rows are not counted.

Try this in the terminal to see it in action. You can also pivot other aggregates like salary totals:

SELECT SUM(CASE WHEN department_id = 1 THEN salary ELSE 0 END) AS eng_payroll, SUM(CASE WHEN department_id = 2 THEN salary ELSE 0 END) AS mkt_payroll, SUM(CASE WHEN department_id = 3 THEN salary ELSE 0 END) AS sales_payroll FROM employees;

Pivot with GROUP BY (Time-Based)

Pivoting becomes truly powerful when combined with GROUP BY. You get a matrix -- rows for one dimension (like year) and columns for another (like department). This is the classic cross-tab report:

SELECT STRFTIME('%Y', hire_date) AS year, SUM(CASE WHEN department_id = 1 THEN 1 ELSE 0 END) AS eng_hires, SUM(CASE WHEN department_id = 2 THEN 1 ELSE 0 END) AS mkt_hires, SUM(CASE WHEN department_id = 3 THEN 1 ELSE 0 END) AS sales_hires FROM employees GROUP BY STRFTIME('%Y', hire_date) ORDER BY year;

This produces a hiring trend matrix -- one row per year, one column per department. At a glance you can see which departments grew fastest in which years.

The same technique works with any time granularity. Use STRFTIME('%Y-%m', hire_date) for monthly breakdowns, or STRFTIME('%Y-Q' || ((CAST(STRFTIME('%m', hire_date) AS INTEGER) - 1) / 3 + 1)) for quarterly. The pivot columns can also use AVG, MAX, MIN, or any other aggregate function instead of SUM.

Pivot with JOIN

Real-world pivots often need data from multiple tables. Use JOIN to bring in readable names, then pivot on the joined data. This salary budget matrix shows departments by name with employee counts in salary tiers:

SELECT d.name AS department, SUM(CASE WHEN e.salary >= 100000 THEN 1 ELSE 0 END) AS senior, SUM(CASE WHEN e.salary >= 80000 AND e.salary < 100000 THEN 1 ELSE 0 END) AS mid, SUM(CASE WHEN e.salary < 80000 THEN 1 ELSE 0 END) AS junior FROM employees e JOIN departments d ON e.department_id = d.id GROUP BY d.name ORDER BY d.name;

This gives you a matrix where each row is a department and each column is a salary tier. The JOIN pulls in department names from the departments table so the output is human-readable instead of showing raw IDs.

Pivot on product categories: The same pattern works with any dimension. Here is a sales pivot -- total revenue per product category, by order status:

SELECT p.category, SUM(CASE WHEN o.status = 'completed' THEN o.quantity * p.price ELSE 0 END) AS completed_rev, SUM(CASE WHEN o.status = 'pending' THEN o.quantity * p.price ELSE 0 END) AS pending_rev, SUM(CASE WHEN o.status = 'cancelled' THEN o.quantity * p.price ELSE 0 END) AS cancelled_rev FROM orders o JOIN products p ON o.product_id = p.id GROUP BY p.category ORDER BY p.category;

Creating Histograms

A histogram groups continuous data into buckets (also called bins or ranges) and counts how many values fall into each bucket. CASE expressions make this straightforward:

SELECT CASE WHEN salary < 70000 THEN 'Under 70K' WHEN salary < 90000 THEN '70K-89K' WHEN salary < 110000 THEN '90K-109K' WHEN salary < 130000 THEN '110K-129K' ELSE '130K+' END AS salary_range, COUNT(*) AS num_employees, ROUND(AVG(salary), 0) AS avg_salary FROM employees GROUP BY salary_range ORDER BY MIN(salary);

The ORDER BY MIN(salary) ensures the buckets appear in logical order (low to high) rather than alphabetical order. Each row shows the bucket label, how many employees fall in that range, and the average salary within the bucket.

You can also create a visual histogram using string repetition. SQLite does not have a REPEAT function, but you can simulate a simple bar:

SELECT CASE WHEN salary < 80000 THEN '<80K ' WHEN salary < 100000 THEN '80-99K' ELSE '100K+' END AS range, COUNT(*) AS cnt, SUBSTR('##########', 1, COUNT(*)) AS bar FROM employees GROUP BY range ORDER BY MIN(salary);

The SUBSTR trick pulls a number of # characters equal to the count, creating a crude text-based bar chart directly in your query output.

Unpivoting: Columns to Rows

Unpivoting is the reverse operation -- converting columns back into rows. This is useful when you receive data in a wide format (spreadsheet-style) but need it normalized for analysis.

In SQLite, you can unpivot using UNION ALL:

-- Given a table: budgets(dept, q1, q2, q3, q4) -- Unpivot quarterly columns into rows: SELECT name AS dept, 'Q1' AS quarter, budget * 0.25 AS amount FROM departments UNION ALL SELECT name, 'Q2', budget * 0.30 FROM departments UNION ALL SELECT name, 'Q3', budget * 0.25 FROM departments UNION ALL SELECT name, 'Q4', budget * 0.20 FROM departments ORDER BY dept, quarter;

Each UNION ALL query selects one "column" as a row. The result is a normalized table with one row per department per quarter. This is verbose but reliable across all SQL platforms.

Cross-Database Comparison

The CASE-based approach works in every SQL database. However, some platforms offer dedicated pivot syntax:

SQLite CASE WHEN only. No built-in PIVOT. This is what we use in this course.
SQL Server PIVOT / UNPIVOT operators. Declarative syntax, but limited to one aggregate.
PostgreSQL CROSSTAB function via tablefunc extension. Powerful but requires setup.
MySQL CASE WHEN only (like SQLite). No native PIVOT syntax.

Why Learn the CASE Approach?

The CASE WHEN technique is portable -- it works identically in SQLite, MySQL, PostgreSQL, SQL Server, and Oracle. Platform-specific PIVOT syntax may be more concise, but you cannot transfer it between databases. Master the universal pattern first, then learn vendor shortcuts as needed.

Key Takeaways

  • Pivoting transforms rows into columns using SUM(CASE WHEN ... THEN ... END)
  • Combine pivoting with GROUP BY to create cross-tab matrices (year x department)
  • JOIN before pivoting to get human-readable labels instead of raw IDs
  • Histograms use CASE to bucket continuous data into ranges, then COUNT per bucket
  • Unpivoting (columns to rows) uses UNION ALL in SQLite
  • The CASE approach is portable across all SQL databases -- learn it first
