ORDER BY Basics

By default, SQL returns rows in no guaranteed order. The ORDER BY clause lets you sort results by one or more columns. When you specify a column without a direction keyword, the sort defaults to ascending (smallest to largest, A to Z, earliest to latest).

Sort by salary (ascending, the default):

SELECT first_name, salary FROM employees ORDER BY salary;

This returns all employees sorted from lowest salary to highest. Since ASC is the default, writing ORDER BY salary is identical to ORDER BY salary ASC.

Sort by salary (descending):

SELECT first_name, salary FROM employees ORDER BY salary DESC;

Adding DESC reverses the order: highest salary first. This is how you find top earners, most recent records, or anything where you want the "biggest" values on top.

Sorting by Multiple Columns

You can sort by more than one column by listing them separated by commas. SQL sorts by the first column first, then uses the second column to break ties within the first, and so on. Each column can have its own sort direction.

SELECT first_name, department_id, salary
FROM employees
ORDER BY department_id ASC, salary DESC;

This first sorts by department_id in ascending order (department 1, then 2, then 3...). Within each department, employees are sorted by salary in descending order, so the highest-paid person in each department appears first.

Sorting by Column Position

Instead of column names, you can reference columns by their position in the SELECT list. The numbering starts at 1, not 0.

SELECT first_name, salary FROM employees ORDER BY 2 DESC;

Here, 2 refers to the second column in the SELECT list, which is salary. This query is equivalent to ORDER BY salary DESC. While this shorthand is occasionally useful for quick ad-hoc queries, using column names is strongly preferred in production code. Positional references break silently if someone reorders the SELECT columns.

Sorting by Expressions

You are not limited to sorting by raw column values. ORDER BY accepts any valid expression, including function calls. This lets you sort by computed values without adding them to your SELECT list.

SELECT first_name, last_name FROM employees ORDER BY LENGTH(last_name);

This sorts employees by the length of their last name, from shortest to longest. The LENGTH() function returns the number of characters in a string. You could also sort by arithmetic expressions like ORDER BY salary * 1.1 or concatenations.

NULLs in Sorting

NULL values need special consideration when sorting. Since NULL represents "unknown" or "missing", the database has to decide where to place NULLs relative to actual values. Different databases handle this differently.

SELECT first_name, manager_id FROM employees ORDER BY manager_id;

In SQLite (which powers the console on the left), NULLs sort first in ascending order and last in descending order. This means the CEO (who has no manager, so manager_id is NULL) appears at the top when sorting ascending.

SQLite First Last
PostgreSQL Last First
MySQL First Last

PostgreSQL supports NULLS FIRST and NULLS LAST modifiers to explicitly control NULL placement: ORDER BY manager_id ASC NULLS LAST. This syntax is not available in SQLite or MySQL, but it is part of the SQL standard and worth knowing.

LIMIT and OFFSET

The LIMIT clause restricts how many rows are returned. This is essential for performance (you rarely need all million rows) and for "top N" queries. LIMIT always appears at the very end of a query.

Top 5 highest-paid employees:

SELECT first_name, salary FROM employees ORDER BY salary DESC LIMIT 5;

Without ORDER BY, LIMIT returns an arbitrary set of rows, which is rarely useful. Always pair LIMIT with ORDER BY so the results are deterministic.

Pagination with OFFSET:

SELECT * FROM employees ORDER BY hire_date LIMIT 5 OFFSET 5;

OFFSET skips a specified number of rows before returning results. Here, we skip the first 5 rows and return the next 5. This is how pagination works in web applications: page 1 uses OFFSET 0, page 2 uses OFFSET 5, page 3 uses OFFSET 10, and so on (assuming 5 results per page).

LIMIT only Returns the first N rows after sorting. Great for "top N" queries.
LIMIT + OFFSET Skip rows, then return N. The foundation of pagination in every web app.

Combining It All

In practice, you will chain multiple clauses together in a single query. SQL enforces a strict clause order that you must follow:

SELECT first_name, salary
FROM employees
WHERE department_id = 1
ORDER BY salary DESC
LIMIT 3;

This query reads as: "Give me the names and salaries of employees in department 1, sorted from highest to lowest salary, but only the top 3." The clause order is always:

Order Clause Purpose
1 SELECT Which columns to return
2 FROM Which table to query
3 WHERE Filter rows (before grouping)
4 ORDER BY Sort the results
5 LIMIT / OFFSET Restrict how many rows to return

If you put ORDER BY before WHERE, or LIMIT before ORDER BY, SQL will throw a syntax error. Memorize this order early and it will save you debugging time throughout the course.

Key Takeaways

  • ORDER BY sorts results; ASC (default) for ascending, DESC for descending
  • Multi-column sorting breaks ties: first column sorts first, then the next, and so on
  • Column positions (ORDER BY 2) work but column names are clearer and safer
  • NULL sort order varies by database; SQLite puts NULLs first in ASC
  • LIMIT restricts the number of rows returned; always pair it with ORDER BY
  • OFFSET skips rows for pagination: LIMIT 10 OFFSET 20 returns rows 21-30
  • Clause order matters: SELECT, FROM, WHERE, ORDER BY, LIMIT
