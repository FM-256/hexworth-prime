Current Date & Time

Every database engine provides functions to get the current date and time. In SQLite, there are three core functions that return the current moment in different formats:

-- Date only (YYYY-MM-DD) SELECT DATE('now'); -- Time only (HH:MM:SS) SELECT TIME('now'); -- Both date and time (YYYY-MM-DD HH:MM:SS) SELECT DATETIME('now');

The string 'now' is a special keyword that tells SQLite to use the current timestamp. All three functions return UTC time by default. To get local time, add the 'localtime' modifier:

SELECT DATETIME('now', 'localtime');

Try running SELECT DATE('now'); or SELECT DATETIME('now'); in the console to see today's date. This completes the current-date task.

Extracting Date Parts

The STRFTIME function (short for "string format time") is SQLite's Swiss Army knife for dates. It lets you extract individual components from a date value using format codes:

%Y Four-digit year (2024)
%m Month 01-12
%d Day of month 01-31
%H Hour 00-23
%w Day of week 0-6 (Sun=0)
%j Day of year 001-366

Use STRFTIME to pull the year and month from employee hire dates:

SELECT first_name, hire_date, STRFTIME('%Y', hire_date) AS year, STRFTIME('%m', hire_date) AS month FROM employees;

You can also combine format codes into a single string to build custom date formats:

SELECT first_name, STRFTIME('%m/%d/%Y', hire_date) AS formatted_date FROM employees;

Date Arithmetic

One of the most common date operations is calculating the difference between two dates. SQLite uses JULIANDAY for this. Julian day numbers represent dates as a continuous count of days, making subtraction straightforward:

SELECT first_name, hire_date, DATE('now') AS today, CAST(JULIANDAY('now') - JULIANDAY(hire_date) AS INTEGER) AS days_employed FROM employees;

This calculates how many days each employee has been with the company. To convert days into approximate years, divide by 365:

SELECT first_name, hire_date, ROUND((JULIANDAY('now') - JULIANDAY(hire_date)) / 365.25, 1) AS years_employed FROM employees ORDER BY years_employed DESC;

Adding & Subtracting Intervals

SQLite's date functions accept modifiers that let you add or subtract time intervals. This is useful for calculating deadlines, expiration dates, or future events:

-- 30 days from now SELECT DATE('now', '+30 days'); -- 1 year ago SELECT DATE('now', '-1 year'); -- First day of the current month SELECT DATE('now', 'start of month');

Apply modifiers to table data. For example, calculate when each employee's 90-day probation period ended:

SELECT first_name, hire_date, DATE(hire_date, '+90 days') AS probation_end FROM employees;

You can chain multiple modifiers together. Each one is applied in order from left to right:

-- Last day of the previous month SELECT DATE('now', 'start of month', '-1 day'); -- 6 months and 15 days from hire SELECT first_name, DATE(hire_date, '+6 months', '+15 days') AS review_date FROM employees;

Filtering by Date

Date columns work with standard comparison operators in WHERE clauses. Since SQLite stores dates as text in ISO 8601 format (YYYY-MM-DD), string comparison works correctly for chronological ordering:

-- Everyone hired in 2022 or later SELECT * FROM employees WHERE hire_date >= '2022-01-01';
-- Orders in the first half of 2023 SELECT * FROM orders WHERE order_date BETWEEN '2023-01-01' AND '2023-06-30';

You can also filter using computed dates. Find employees hired in the last 2 years:

SELECT first_name, hire_date FROM employees WHERE hire_date >= DATE('now', '-2 years');

Grouping by Time Period

Combine STRFTIME with GROUP BY to aggregate data by time periods. This is how you build reports like "hires per year" or "orders per month":

-- How many people were hired each year? SELECT STRFTIME('%Y', hire_date) AS year, COUNT(*) AS hires FROM employees GROUP BY STRFTIME('%Y', hire_date) ORDER BY year;
-- Revenue by month SELECT STRFTIME('%Y-%m', order_date) AS month, COUNT(*) AS order_count, SUM(total_amount) AS revenue FROM orders GROUP BY STRFTIME('%Y-%m', order_date) ORDER BY month;

This pattern is extremely common in business reporting. The STRFTIME call in the GROUP BY must match the one in the SELECT exactly.

Cross-Database Comparison

Every database engine handles dates differently. We are learning with SQLite, but you will encounter PostgreSQL and MySQL in the real world. Here is how the same operations look across the three major engines:

Operation SQLite PostgreSQL MySQL
Current date DATE('now') CURRENT_DATE CURDATE()
Extract year STRFTIME('%Y', col) EXTRACT(YEAR FROM col) YEAR(col)
Date difference JULIANDAY(a) - JULIANDAY(b) AGE(a, b) DATEDIFF(a, b)
Add interval DATE(col, '+30 days') col + INTERVAL '30 days' DATE_ADD(col, INTERVAL 30 DAY)
Format date STRFTIME('%m/%d/%Y', col) TO_CHAR(col, 'MM/DD/YYYY') DATE_FORMAT(col, '%m/%d/%Y')
Truncate to month STRFTIME('%Y-%m-01', col) DATE_TRUNC('month', col) DATE_FORMAT(col, '%Y-%m-01')

The concepts are identical across all three: get the current date, extract parts, calculate differences, add intervals. Only the syntax changes. Once you understand the logic in SQLite, adapting to PostgreSQL or MySQL is straightforward.

Key Takeaways

  • DATE('now'), TIME('now'), and DATETIME('now') return the current moment in UTC
  • STRFTIME extracts date parts using format codes like %Y (year), %m (month), %d (day)
  • JULIANDAY converts dates to a number so you can subtract them to find intervals
  • Date modifiers like '+30 days' and '-1 year' let you add or subtract time periods
  • ISO 8601 format (YYYY-MM-DD) enables correct date comparison with standard operators
  • Combine STRFTIME with GROUP BY to aggregate data by year, month, or any time period
  • Date function syntax varies across databases, but the concepts are universal
