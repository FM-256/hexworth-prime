What is a CTE?

A Common Table Expression (CTE) is a temporary named result set that exists only for the duration of a single query. Think of it as a named subquery that you define at the top of your statement with the WITH keyword.

CTEs solve the readability problem of deeply nested subqueries. Instead of reading SQL from the inside out, you read it top to bottom like a story.

Basic CTE Syntax

Define the CTE with WITH, give it a name, then use it like a table:

WITH high_earners AS ( SELECT first_name, last_name, salary, department_id FROM employees WHERE salary > 100000 ) SELECT * FROM high_earners ORDER BY salary DESC;

The CTE high_earners filters employees first, then the outer query sorts the results. This is equivalent to a subquery in FROM, but far more readable.

Multiple CTEs

You can define multiple CTEs separated by commas. Later CTEs can reference earlier ones:

WITH dept_stats AS ( SELECT department_id, AVG(salary) AS avg_salary, COUNT(*) AS headcount FROM employees GROUP BY department_id ), dept_names AS ( SELECT ds.*, d.name AS dept_name FROM dept_stats ds JOIN departments d ON ds.department_id = d.id ) SELECT dept_name, headcount, ROUND(avg_salary, 0) AS avg_salary FROM dept_names ORDER BY avg_salary DESC;

This builds up complexity in stages: first compute stats per department, then join department names, then format the final output.

CTE with JOIN

CTEs are powerful when combined with JOINs to pre-aggregate data:

WITH order_totals AS ( SELECT customer_id, COUNT(*) AS num_orders, SUM(total) AS total_spent FROM orders WHERE status != 'cancelled' GROUP BY customer_id ) SELECT c.name, ot.num_orders, ROUND(ot.total_spent, 2) AS total_spent FROM customers c JOIN order_totals ot ON c.id = ot.customer_id ORDER BY total_spent DESC;

Recursive CTEs

A recursive CTE references itself to traverse hierarchical data. Our employees table has a manager_id that creates a tree structure. Let us walk the management chain:

WITH RECURSIVE org_chart AS ( -- Base case: top-level managers (no manager) SELECT id, first_name, last_name, manager_id, 0 AS depth FROM employees WHERE manager_id IS NULL UNION ALL -- Recursive case: employees who report to someone in the CTE SELECT e.id, e.first_name, e.last_name, e.manager_id, oc.depth + 1 FROM employees e JOIN org_chart oc ON e.manager_id = oc.id ) SELECT SUBSTR(' ', 1, depth * 4) || first_name || ' ' || last_name AS org_tree, depth FROM org_chart ORDER BY depth, last_name;

The recursive CTE has two parts joined by UNION ALL:

Base Case (Anchor) The starting rows: employees with no manager (depth 0). This runs once.
Recursive Case Joins employees back to the CTE, finding the next level down. Repeats until no new rows.

When to Use CTEs

Complex Queries Break a 50-line query into named, understandable steps
Reuse Within Query Reference the same derived data multiple times without repeating it
Hierarchical Data Org charts, category trees, bill of materials (recursive CTEs)
Step-by-Step Logic Build aggregation → filtering → formatting as a pipeline

Key Takeaways

  • CTEs use WITH ... AS to create temporary named result sets
  • They improve readability over nested subqueries (top-down vs inside-out)
  • Multiple CTEs are comma-separated; later ones can reference earlier ones
  • Recursive CTEs have a base case + recursive case joined by UNION ALL
  • Use recursive CTEs for hierarchical data (org charts, trees, graphs)
