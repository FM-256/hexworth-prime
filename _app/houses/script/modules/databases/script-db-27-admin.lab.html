Mission Briefing

Meridian Technologies needs a senior DBA to architect new schemas, enforce data integrity, optimize query performance with indexes, and run health diagnostics on production databases. Step into the admin role and prove you can handle it.

01PENDING

Build a Schema

Create a projects table with: id (INTEGER PRIMARY KEY), name (TEXT NOT NULL), budget (REAL DEFAULT 0), start_date (TEXT), and department_id (INTEGER FOREIGN KEY referencing departments).

CREATE TABLE projects ( id INTEGER PRIMARY KEY, name TEXT NOT NULL, budget REAL DEFAULT 0, start_date TEXT, department_id INTEGER, FOREIGN KEY (department_id) REFERENCES departments(id) );
02PENDING

Add Constraints

Create a users table with an email column that must be UNIQUE and an age column with a CHECK constraint ensuring age is greater than 0.

CREATE TABLE users ( id INTEGER PRIMARY KEY, name TEXT NOT NULL, email TEXT UNIQUE, age INTEGER CHECK(age > 0) );
03PENDING

Index Investigation

Use EXPLAIN QUERY PLAN on a query against employees, then create an index to optimize it.

EXPLAIN QUERY PLAN SELECT * FROM employees WHERE salary > 90000; CREATE INDEX idx_salary ON employees(salary);
04PENDING

Composite Index

Create a composite index on the employees table covering both department_id and salary columns.

CREATE INDEX idx_dept_salary ON employees(department_id, salary);
05PENDING

Schema Explorer

Query sqlite_master to list all tables and their SQL definitions in the database.

SELECT name, sql FROM sqlite_master WHERE type = 'table';
06PENDING

Column Inspector

Use PRAGMA table_info to inspect the column definitions of the employees table.

PRAGMA table_info(employees);
07PENDING

Foreign Key Enforcement

Enable foreign key enforcement with PRAGMA, then create two related tables and test referential integrity by attempting an invalid foreign key insert.

PRAGMA foreign_keys = ON; -- Then try inserting a row with an invalid FK: INSERT INTO projects (name, department_id) VALUES ('Ghost Project', 9999);
08PENDING

Database Health Check

Run a database integrity check to verify the database is healthy and uncorrupted.

PRAGMA integrity_check;
PostgreSQL Sandbox

The challenges above use SQLite. The exercises below run in a real PostgreSQL 16 terminal with the same Meridian Technologies data. Launch the sandbox, then run each command in the external terminal window.

PG-01 MANUAL
psql Meta-Commands

Explore the database using psql built-in commands. These have no equivalent in SQLite.

\dt              -- list all tables
\d employees     -- describe employees table
\di              -- list all indexes
PG-02 MANUAL
PostgreSQL Metadata

Query information_schema to inspect column details. Compare this to SQLite's sqlite_master and PRAGMA table_info.

SELECT column_name, data_type, is_nullable
FROM information_schema.columns
WHERE table_name = 'employees'
ORDER BY ordinal_position;
PG-03 MANUAL
Role Management & Permissions

Create a new role and grant it limited access. This is how real production databases restrict access.

CREATE ROLE auditor WITH LOGIN PASSWORD 'audit123';
GRANT SELECT ON employees, departments TO auditor;
PG-04 MANUAL
Database Backup

Use pg_dump to export the entire database to a SQL file. This is the standard PostgreSQL backup tool.

-- Press \q to exit psql first, then run in bash:
pg_dump -U student -h localhost meridian_db > backup.sql
-- Check the file:
head -20 backup.sql
