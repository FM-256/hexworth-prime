What Are Window Functions?

In the previous modules you learned aggregate functions like SUM and COUNT that collapse many rows into a single result. Window functions are fundamentally different: they compute a value for each row while keeping all rows visible in the result set.

The magic is the OVER() clause. Every window function uses OVER() to define the "window" of rows it should consider for its calculation. Without OVER(), the database does not know you want a window function.

Ranking ROW_NUMBER, RANK, DENSE_RANK -- assign positional numbers to rows
Value LAG, LEAD, FIRST_VALUE, LAST_VALUE -- access values from other rows
Aggregate SUM, AVG, COUNT as window functions -- running totals and moving averages
Distribution NTILE, PERCENT_RANK, CUME_DIST -- statistical distribution across rows

ROW_NUMBER

ROW_NUMBER() assigns a unique sequential integer to each row within a result set, starting at 1. The order is determined by the ORDER BY inside OVER():

SELECT first_name, last_name, salary, ROW_NUMBER() OVER (ORDER BY salary DESC) AS rank FROM employees;

This numbers every employee from 1 (highest salary) to N (lowest salary). Every row keeps its original data -- nothing is collapsed. Now add PARTITION BY to create separate numbering per group:

SELECT first_name, last_name, department_id, salary, ROW_NUMBER() OVER ( PARTITION BY department_id ORDER BY salary DESC ) AS dept_rank FROM employees;

PARTITION BY works like GROUP BY but without collapsing rows. Each department gets its own independent numbering sequence starting at 1. This is how you find "the top N per group" -- a pattern that is extremely common in real-world queries.

RANK and DENSE_RANK

ROW_NUMBER always produces unique numbers, even when rows have the same value. RANK and DENSE_RANK handle ties differently:

RANK assigns the same number to ties but then skips the next numbers. If two employees tie for 2nd place, the next gets rank 4 (1, 2, 2, 4). DENSE_RANK also assigns the same number to ties but does not skip -- the next gets rank 3 (1, 2, 2, 3).

SELECT first_name, last_name, salary, RANK() OVER (ORDER BY salary DESC) AS salary_rank, DENSE_RANK() OVER (ORDER BY salary DESC) AS salary_dense_rank FROM employees;

Run this in the terminal and compare the two columns. Where salaries are unique, RANK and DENSE_RANK produce the same values. Where ties exist, you will see RANK skip numbers while DENSE_RANK stays sequential.

When to Use Which?

Use ROW_NUMBER when you need exactly one row per position (e.g., pagination). Use RANK for competitive ranking where gaps after ties are expected (e.g., sports standings). Use DENSE_RANK when you want to know "how many distinct salary levels are above this one?"

LAG and LEAD

LAG and LEAD let you access values from neighboring rows without a self-join. LAG looks backward (previous rows) and LEAD looks forward (next rows):

SELECT first_name, last_name, hire_date, salary, LAG(salary, 1) OVER (ORDER BY hire_date) AS prev_salary, LEAD(salary, 1) OVER (ORDER BY hire_date) AS next_salary FROM employees;

The second argument is the offset -- how many rows to look back or ahead. It defaults to 1 if omitted. You can also provide a third argument as a default value for when there is no previous or next row (the first row has no LAG, the last row has no LEAD):

SELECT first_name, salary, LAG(salary, 1, 0) OVER (ORDER BY hire_date) AS prev_salary, salary - LAG(salary, 1, salary) OVER (ORDER BY hire_date) AS salary_change FROM employees;

This pattern is invaluable for calculating row-over-row changes -- comparing each value to its predecessor. Think of it like a spreadsheet formula that references the cell above.

Aggregate Window Functions

The aggregate functions you already know -- SUM, AVG, COUNT -- can also be used as window functions by adding OVER(). Instead of collapsing rows, they calculate a value relative to a window while keeping every row:

SELECT first_name, department_id, salary, AVG(salary) OVER (PARTITION BY department_id) AS dept_avg, salary - AVG(salary) OVER (PARTITION BY department_id) AS diff_from_avg FROM employees;

Each row shows the individual salary alongside the department average, plus how far that employee is from the average. No GROUP BY needed -- and no rows are lost. Now see a running total:

SELECT first_name, hire_date, salary, SUM(salary) OVER (ORDER BY hire_date) AS running_total FROM employees;

When you use ORDER BY inside OVER() with an aggregate, the database computes a cumulative result from the first row up to the current row. The running total grows with each row -- this is the default window frame behavior.

Window Frames

By default, when you specify ORDER BY inside OVER(), the window frame includes all rows from the start up to the current row. The ROWS BETWEEN clause lets you define exactly which rows the function should consider:

SELECT first_name, hire_date, salary, SUM(salary) OVER ( ORDER BY hire_date ROWS BETWEEN 2 PRECEDING AND CURRENT ROW ) AS three_row_sum FROM employees;

This calculates a 3-row moving sum: the current row plus the two rows before it. You can change the boundaries to create any window you need:

UNBOUNDED PRECEDING From the very first row of the partition
N PRECEDING N rows before the current row
CURRENT ROW The row being processed right now
N FOLLOWING N rows after the current row
UNBOUNDED FOLLOWING Through the very last row of the partition
-- Moving average of 3 rows: 1 before, current, and 1 after SELECT first_name, hire_date, salary, ROUND(AVG(salary) OVER ( ORDER BY hire_date ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING ), 2) AS moving_avg FROM employees;

Window frames give you precise control over calculations like moving averages, running totals, and sliding aggregations. They are what make window functions truly powerful for time-series analysis and reporting.

Key Takeaways

  • Window functions compute a value per row without collapsing the result set -- unlike aggregates
  • The OVER() clause is required and defines the window: PARTITION BY for groups, ORDER BY for sequence
  • ROW_NUMBER gives unique sequential numbers; RANK and DENSE_RANK handle ties differently
  • LAG accesses previous rows and LEAD accesses next rows -- perfect for row-over-row comparisons
  • SUM, AVG, and COUNT work as window functions too, enabling running totals and per-group averages
  • ROWS BETWEEN defines custom window frames for moving averages and sliding calculations
  • PARTITION BY is like GROUP BY but keeps all rows -- each partition gets independent numbering or aggregation
