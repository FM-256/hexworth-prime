The SELECT Statement

The SELECT statement is the most frequently used command in SQL. Its job is simple: retrieve data from one or more tables. The basic syntax is:

SELECT column1, column2, ... FROM table_name;

SQL is case-insensitive for keywords, meaning SELECT, select, and Select all work identically. However, the universal convention is to write SQL keywords in UPPERCASE and table/column names in lowercase. This makes queries much easier to read at a glance, especially as they grow more complex.

Every SELECT statement has at least two clauses: SELECT (what columns you want) and FROM (which table to pull from). As you progress through this course, you will add more clauses like WHERE, ORDER BY, GROUP BY, and JOIN.

Selecting All Columns

The asterisk * is a wildcard that means "every column in the table." It is the quickest way to see all data:

SELECT * FROM employees;

This returns every row and every column from the employees table. The * wildcard is excellent for exploration when you are learning a new database or debugging. You can use it on any table in the training database:

SELECT * FROM departments; SELECT * FROM products; SELECT * FROM orders;

However, in production code you should avoid SELECT * and instead list the specific columns you need. Why? Because * transfers all columns over the network even if your application only uses two of them. It also breaks if someone adds or removes columns from the table later. Think of it as a development tool, not a production pattern.

Selecting Specific Columns

To retrieve only the columns you need, list them by name after SELECT, separated by commas:

SELECT first_name, last_name, email FROM employees;

The columns appear in the result set in the order you list them, regardless of their order in the table definition. This means you can rearrange columns however you like:

SELECT email, last_name, first_name FROM employees;

Selecting specific columns has real benefits: it reduces data transfer between the database and your application, makes your query's intent explicit to other developers, and protects your code from breaking when the table schema changes.

Column Aliases

The AS keyword lets you give a column a temporary display name in the results. This is called an alias. Aliases do not change the actual table; they only affect the output of your query.

SELECT first_name AS "First Name", salary AS annual_pay FROM employees;

There are two styles of aliases. Quoted aliases (wrapped in double quotes) can contain spaces, special characters, and mixed case: AS "First Name". Unquoted aliases must be a single word with no spaces: AS annual_pay. Most developers prefer unquoted aliases for simplicity, but quoted aliases are useful when you need human-readable column headers in a report.

Aliases become especially valuable with calculated columns and CASE expressions, where the default column name would otherwise be an unreadable expression.

DISTINCT

The DISTINCT keyword removes duplicate rows from your results. Place it immediately after SELECT:

SELECT DISTINCT department_id FROM employees;

Without DISTINCT, you would see department_id repeated for every employee. With it, each unique value appears exactly once. This is useful for answering questions like "which departments have employees?" or "what cities do our customers come from?"

When you use DISTINCT with multiple columns, it removes rows where the entire combination is duplicated, not just one column:

SELECT DISTINCT department_id, salary FROM employees;

Here, two rows are only considered duplicates if they share the same department_id AND the same salary. If two employees are in the same department but have different salaries, both rows appear in the result.

Calculated Columns

SQL lets you create new columns on the fly using arithmetic expressions. These calculated columns exist only in the query results and do not modify the table:

SELECT first_name, salary, salary * 1.1 AS raise_salary FROM employees;

This creates a new column called raise_salary that shows each employee's salary increased by 10%. You can use the standard arithmetic operators: + (addition), - (subtraction), * (multiplication), / (division), and % (modulo).

You can also concatenate strings using the || operator to combine text values from multiple columns:

SELECT first_name || ' ' || last_name AS full_name FROM employees;

The || operator joins the first name, a space character, and the last name into a single full_name column. This is supported in SQLite, PostgreSQL, and Oracle. In MySQL you would use the CONCAT() function instead.

CASE Expressions

The CASE expression adds conditional logic directly inside a query. It works like an if/else chain: evaluate conditions in order and return the first matching result.

SELECT first_name, salary, CASE WHEN salary >= 100000 THEN 'Senior' WHEN salary >= 80000 THEN 'Mid' ELSE 'Junior' END AS level FROM employees;

The database evaluates each WHEN condition top to bottom. The first condition that evaluates to true determines the result. If no condition matches, the ELSE value is returned. If there is no ELSE and nothing matches, the result is NULL.

CASE expressions are incredibly powerful for data categorization, conditional formatting, and business logic. You can use them anywhere a value is expected: in SELECT, WHERE, ORDER BY, and even inside aggregate functions.

Here is another example that categorizes products by price range:

SELECT name, price, CASE WHEN price > 500 THEN 'Premium' WHEN price > 100 THEN 'Standard' ELSE 'Budget' END AS tier FROM products;

Key Takeaways

  • SELECT retrieves data; pair it with FROM to specify the source table
  • Use * for quick exploration but list specific columns in production code
  • AS creates column aliases for cleaner output; quote aliases that contain spaces
  • DISTINCT removes duplicate rows from results; it applies to the entire row
  • Arithmetic operators and || let you create calculated columns on the fly
  • CASE expressions add if/else logic directly inside your queries
