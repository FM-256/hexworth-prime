Mission Briefing

Meridian Technologies is scaling fast and their data infrastructure needs hardening. Build transactions, views, triggers, staging pipelines, and full ETL flows to keep their systems reliable as data volume grows.

01PENDING

Transaction Safety

Wrap 3 INSERT statements in a transaction so they either all succeed or all fail. Use BEGIN and COMMIT.

BEGIN TRANSACTION; INSERT INTO employees (first_name, last_name, salary, department_id) VALUES ('Alex', 'Chen', 95000, 1); INSERT INTO employees (first_name, last_name, salary, department_id) VALUES ('Maya', 'Patel', 88000, 2); INSERT INTO employees (first_name, last_name, salary, department_id) VALUES ('Jordan', 'Lee', 72000, 3); COMMIT;
02PENDING

Upsert Pattern

Use INSERT OR REPLACE to update an existing employee's salary. This pattern inserts if the row doesn't exist, or replaces it if it does.

INSERT OR REPLACE INTO employees (id, first_name, last_name, salary, department_id) VALUES (1, 'Sarah', 'Johnson', 125000, 1);
03PENDING

Create a View

Build a view called dept_stats that shows each department's name, headcount, and average salary.

CREATE VIEW dept_stats AS SELECT d.name, COUNT(e.id) AS headcount, ROUND(AVG(e.salary), 0) AS avg_salary FROM departments d LEFT JOIN employees e ON d.id = e.department_id GROUP BY d.id;
04PENDING

Materialized Snapshot

Use CREATE TABLE AS SELECT to snapshot the current order data into a new table. This materializes query results for fast access.

CREATE TABLE order_snapshot AS SELECT * FROM orders WHERE status = 'completed';
05PENDING

Data Cleaning

Find duplicate entries or clean messy data. Use HAVING COUNT to detect duplicates, or TRIM to strip whitespace from fields.

-- Find duplicates: SELECT first_name, COUNT(*) AS cnt FROM employees GROUP BY first_name HAVING COUNT(*) > 1; -- Or clean whitespace: SELECT TRIM(first_name) AS clean_name FROM employees;
06PENDING

Create a Trigger

Build a trigger that automatically logs salary changes to an audit_trail table whenever the employees table is updated.

CREATE TRIGGER log_salary_change AFTER UPDATE OF salary ON employees BEGIN INSERT INTO audit_trail (id, table_name, field_name, old_value, new_value, changed_at) VALUES (NULL, 'employees', 'salary', OLD.salary, NEW.salary, datetime('now')); END;
07PENDING

Staging Table Pipeline

Create a temporary staging table, insert raw data into it, then load the cleaned data into a permanent table. This is the staging pattern used in real ETL pipelines.

CREATE TEMP TABLE staging (name TEXT, salary REAL); INSERT INTO staging VALUES ('Test Engineer', 80000); INSERT INTO employees (first_name, salary) SELECT name, salary FROM staging;
08PENDING

Full ETL Pipeline

Build a complete Extract-Transform-Load pipeline: create a summary table from a complex query that joins multiple tables with aggregation. Combine CREATE TABLE AS with JOINs and aggregate functions.

CREATE TABLE sales_summary AS SELECT p.category, COUNT(oi.id) AS total_orders, SUM(oi.quantity) AS total_units, ROUND(SUM(oi.quantity * oi.unit_price), 2) AS total_revenue FROM orders o JOIN order_items oi ON o.id = oi.order_id JOIN products p ON oi.product_id = p.id GROUP BY p.category;

PG-01 MANUAL
CSV Import with \copy

Import employee data from a CSV file using psql's \copy command. CSV files are pre-loaded in ~/data/.

CREATE TABLE employees_import (LIKE employees INCLUDING ALL);

\copy employees_import FROM '/home/student/data/employees.csv' CSV HEADER

SELECT COUNT(*) FROM employees_import;
PG-02 MANUAL
Materialized Views

Create a materialized view that pre-computes department statistics. Unlike regular views, materialized views store their results on disk.

CREATE MATERIALIZED VIEW dept_summary AS
SELECT d.name AS department,
       COUNT(e.id) AS headcount,
       ROUND(AVG(e.salary), 0) AS avg_salary,
       SUM(e.salary) AS total_payroll
FROM departments d
LEFT JOIN employees e ON d.id = e.department_id
GROUP BY d.id, d.name;

SELECT * FROM dept_summary;

-- Refresh after data changes:
REFRESH MATERIALIZED VIEW dept_summary;
PG-03 MANUAL
Server-Side COPY

Use PostgreSQL's server-side COPY for high-performance bulk data export. Compare this to the client-side \copy from PG-01.

-- Export orders to CSV (server-side, runs as postgres):
-- First, from psql:
\! sudo -u postgres psql -d meridian_db -c \
  "COPY orders TO '/tmp/orders_export.csv' WITH CSV HEADER;"

\! head -5 /tmp/orders_export.csv
PG-04 MANUAL
Database Maintenance

Run VACUUM ANALYZE and inspect table statistics. These maintenance commands keep PostgreSQL performing well at scale.

VACUUM ANALYZE employees;

SELECT relname, n_live_tup, n_dead_tup,
       last_vacuum, last_analyze
FROM pg_stat_user_tables
ORDER BY relname;
