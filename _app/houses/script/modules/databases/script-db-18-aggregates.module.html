What Are Aggregates?

Up to now, every query you have written returns individual rows. Aggregate functions are different: they operate on a set of rows and collapse them down into a single result value.

Instead of asking "show me every employee's salary," aggregates let you ask "what is the total payroll?" or "how many employees do we have?" The database scans the matching rows, performs a calculation, and returns one number.

COUNT Counts rows or non-NULL values
SUM Adds up numeric column values
AVG Calculates the arithmetic mean
MIN / MAX Finds the smallest or largest value

COUNT

COUNT is the most commonly used aggregate. It comes in three flavors, and the differences matter:

COUNT(*) counts all rows, regardless of NULLs. COUNT(column) counts only rows where that column is not NULL. COUNT(DISTINCT column) counts unique non-NULL values.

SELECT COUNT(*) AS total, COUNT(manager_id) AS has_manager, COUNT(DISTINCT department_id) AS dept_count FROM employees;

Try this in the terminal. Notice that total includes every row, but has_manager is lower because some employees have a NULL manager_id (they are top-level managers). And dept_count tells you how many distinct departments are represented in the employee table.

SUM

SUM adds up all values in a numeric column. NULL values are silently ignored:

SELECT SUM(salary) AS total_payroll FROM employees;

SUM only works on numeric columns. Trying to SUM a text column will produce an error. If every value in the column is NULL, SUM returns NULL (not zero).

AVG

AVG calculates the arithmetic mean. Like SUM, it ignores NULLs:

SELECT ROUND(AVG(salary), 2) AS avg_salary FROM employees;

We wrap AVG in ROUND() to limit decimal places. Without it, you may get a long floating-point result.

Gotcha: AVG and NULLs

AVG ignores NULL rows entirely. If 10 employees exist but only 8 have a bonus value, AVG(bonus) divides the sum by 8, not 10. If you want NULLs treated as zero, use AVG(COALESCE(bonus, 0)) instead.

MIN and MAX

MIN and MAX find the smallest and largest values in a column. Unlike SUM and AVG, they work on any data type -- numbers, strings, and dates:

SELECT MIN(hire_date) AS first_hire, MAX(hire_date) AS latest_hire FROM employees;

For strings, MIN returns the value that sorts first alphabetically and MAX returns the last. For dates, MIN is the earliest and MAX is the most recent. NULLs are ignored.

SELECT MIN(salary) AS lowest_salary, MAX(salary) AS highest_salary, MAX(salary) - MIN(salary) AS salary_range FROM employees;

You can perform arithmetic on aggregate results directly in the SELECT clause, like calculating the range above.

Combining Aggregates

You can use multiple aggregate functions in a single query to build a comprehensive summary in one shot:

SELECT COUNT(*) AS emp_count, ROUND(AVG(salary), 0) AS avg_sal, MIN(salary) AS min_sal, MAX(salary) AS max_sal, SUM(salary) AS total_payroll FROM employees;

This single query gives you a full statistical snapshot of the salary column. Each aggregate function independently scans the rows and returns its result. The database handles this efficiently in one pass.

DISTINCT in Aggregates

Adding DISTINCT inside an aggregate tells the function to consider only unique values, ignoring duplicates:

SELECT COUNT(category) AS total_entries, COUNT(DISTINCT category) AS unique_categories FROM products;

If you have 10 products across 4 categories, COUNT(category) returns 10 but COUNT(DISTINCT category) returns 4. You can also use DISTINCT with SUM and AVG, though it is less common:

-- Sum of unique price points (ignores duplicate prices) SELECT SUM(DISTINCT price) AS unique_price_total FROM products;

Key Takeaways

  • Aggregate functions collapse multiple rows into a single result value
  • COUNT(*) counts all rows; COUNT(col) skips NULLs; COUNT(DISTINCT col) counts unique non-NULLs
  • SUM and AVG work on numeric columns only and ignore NULLs
  • MIN and MAX work on any data type: numbers, strings, and dates
  • AVG ignores NULLs -- use COALESCE if you want NULLs treated as zero
  • DISTINCT inside an aggregate removes duplicates before the calculation
  • You can combine multiple aggregates in a single SELECT for a full summary
