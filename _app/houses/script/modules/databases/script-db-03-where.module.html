The WHERE Clause

So far you have been selecting all rows from a table. In the real world, you almost never want every row. The WHERE clause lets you filter which rows are returned by specifying a condition that each row must satisfy.

Basic syntax:

SELECT columns FROM table WHERE condition;

The database evaluates the condition for every row in the table. Only rows where the condition is true appear in the results. For example, to get all employees in department 1:

SELECT * FROM employees WHERE department_id = 1;

This scans the employees table and returns only the rows where department_id equals 1. Every other row is excluded from the results.

Comparison Operators

SQL provides six standard comparison operators for building WHERE conditions. They work with numbers, text, and dates.

Operator Meaning Example
= Equal to WHERE status = 'active'
!= or <> Not equal to WHERE status != 'delivered'
< Less than WHERE salary < 80000
> Greater than WHERE salary > 100000
<= Less than or equal WHERE quantity <= 10
>= Greater than or equal WHERE hire_date >= '2024-01-01'

Filter by salary:

SELECT first_name, salary FROM employees WHERE salary > 100000;

This returns only employees earning more than $100,000. The > operator compares each row's salary value against the threshold.

Filter by text value:

SELECT * FROM orders WHERE status != 'delivered';

Text comparisons must wrap the value in single quotes. The != operator (or <>) excludes rows matching that value.

Combining Conditions: AND, OR, NOT

Real-world queries often need multiple conditions. SQL provides three logical operators to combine them.

AND requires both conditions to be true:

SELECT * FROM employees
WHERE department_id = 1 AND salary > 100000;

Only rows where the employee is in department 1 and earns over $100,000 are returned.

OR requires at least one condition to be true:

SELECT * FROM employees
WHERE department_id = 1 OR department_id = 3;

Returns employees in department 1 or department 3 (or both, if possible).

NOT inverts a condition:

SELECT * FROM employees
WHERE NOT department_id = 1;

Returns everyone except employees in department 1.

Operator precedence: AND binds tighter than OR. This means A OR B AND C is evaluated as A OR (B AND C), not (A OR B) AND C. Always use parentheses to make your intent explicit and avoid subtle bugs:

-- Without parentheses: might not do what you expect
SELECT * FROM employees
WHERE department_id = 1 OR department_id = 3 AND salary > 100000;

-- With parentheses: clear intent
SELECT * FROM employees
WHERE (department_id = 1 OR department_id = 3) AND salary > 100000;

BETWEEN

The BETWEEN operator selects values within a range. It is inclusive on both ends, meaning the boundary values are included in the results.

SELECT * FROM employees
WHERE salary BETWEEN 80000 AND 100000;

This is equivalent to WHERE salary >= 80000 AND salary <= 100000 but is more readable. BETWEEN also works with text and dates:

SELECT * FROM employees
WHERE hire_date BETWEEN '2024-01-01' AND '2024-12-31';

IN

The IN operator lets you specify a list of values to match against. It is shorthand for writing multiple OR conditions and is much cleaner when you have several values.

SELECT * FROM employees
WHERE department_id IN (1, 3, 5);

This is equivalent to writing:

SELECT * FROM employees
WHERE department_id = 1 OR department_id = 3 OR department_id = 5;

The IN version is shorter, easier to read, and harder to get wrong. You can also use NOT IN to exclude a set of values:

SELECT * FROM orders
WHERE status NOT IN ('cancelled', 'returned');

LIKE & Pattern Matching

Sometimes you need to search for partial matches rather than exact values. The LIKE operator supports two wildcard characters for pattern matching:

% (percent) Matches zero or more characters. '%tech%' matches "tech", "biotech", "technology".
_ (underscore) Matches exactly one character. '_a%' matches "Sam", "Max", "Jan" but not "Adam".

Find emails from a specific domain:

SELECT first_name, email FROM employees
WHERE email LIKE '%@meridian.io';

The % before @meridian.io matches any number of characters, so this finds all employees with a @meridian.io email address.

Find names where the second letter is 'a':

SELECT first_name FROM employees
WHERE first_name LIKE '_a%';

The _ matches exactly one character (the first letter), then a must be the second letter, and % matches everything after.

Case sensitivity note: In SQLite (which powers this console), LIKE is case-insensitive for ASCII characters by default. In PostgreSQL and MySQL, behavior varies. Always check your database's documentation when writing portable queries.

IS NULL / IS NOT NULL

NULL is a special value in SQL that represents missing or unknown data. It is not the same as zero, an empty string, or false. NULL means "we don't know."

The critical rule: you cannot use = or != with NULL. The expression WHERE manager_id = NULL will never return any rows, even if some rows have a NULL manager_id. This is because NULL represents an unknown value, and comparing anything to an unknown value produces an unknown result, not true.

Instead, use IS NULL and IS NOT NULL:

-- Find employees with no manager (top-level)
SELECT * FROM employees WHERE manager_id IS NULL;
-- Find employees who have a manager assigned
SELECT * FROM employees WHERE manager_id IS NOT NULL;

This is one of the most common mistakes beginners make with SQL. Always remember: = NULL is always wrong. Use IS NULL instead.

Key Takeaways

  • WHERE filters rows by evaluating a condition against each row
  • Six comparison operators: =, !=, <, >, <=, >= work with numbers, text, and dates
  • AND requires both conditions true; OR requires at least one; NOT inverts
  • AND binds tighter than OR -- use parentheses to make intent explicit
  • BETWEEN selects an inclusive range; IN matches against a list of values
  • LIKE uses % (any characters) and _ (one character) for pattern matching
  • Never use = NULL; always use IS NULL or IS NOT NULL
