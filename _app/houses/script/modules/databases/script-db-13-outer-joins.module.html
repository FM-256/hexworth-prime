Learning Objectives

  • Understand LEFT, RIGHT, and FULL OUTER JOIN semantics
  • Know when to use each type of outer join
  • Identify and query for unmatched rows using IS NULL
  • Recognize SQLite limitations for RIGHT and FULL joins
  • Combine outer joins with aggregation for complete reports

LEFT JOIN

A LEFT JOIN (also written as LEFT OUTER JOIN) returns all rows from the left table and the matched rows from the right table. If there is no match, the right side columns are filled with NULL.

This is the most commonly used outer join. It guarantees that every row from the left table appears in the result, even if there is no corresponding row in the right table.

SELECT e.first_name, e.last_name, d.name AS dept FROM employees e LEFT JOIN departments d ON e.department_id = d.id;

Every employee appears in the results. If an employee has a department_id that does not match any id in the departments table, the dept column will show NULL instead of being excluded from the results entirely (which is what INNER JOIN would do).

Consider this data to see the difference:

first_name last_name dept (LEFT JOIN) dept (INNER JOIN)
Sarah Chen Engineering Engineering
Marcus Rivera Marketing Marketing
Jordan Blake NULL (row missing)

With INNER JOIN, Jordan Blake disappears from the results because there is no matching department. With LEFT JOIN, Jordan still appears but with NULL for the department. This is the fundamental difference.

Finding Unmatched Rows

One of the most powerful uses of LEFT JOIN is finding rows in one table that have no match in another. This is done by adding a WHERE clause that checks for NULL on the right table's primary key:

SELECT d.name FROM departments d LEFT JOIN employees e ON d.id = e.department_id WHERE e.id IS NULL;

This query finds departments with no employees. The LEFT JOIN keeps all departments, and the WHERE e.id IS NULL filter keeps only the ones where no employee matched. This is a critical pattern you will use constantly in real-world SQL.

Why This Pattern Matters

Finding unmatched rows answers questions like: Which customers have never placed an order? Which products have never been sold? Which students are not enrolled in any class? These are among the most common business questions in database work.

You can also flip it around. To find employees who are not assigned to any department:

SELECT e.first_name, e.last_name FROM employees e LEFT JOIN departments d ON e.department_id = d.id WHERE d.id IS NULL;

RIGHT JOIN

A RIGHT JOIN is the mirror image of a LEFT JOIN. It returns all rows from the right table and the matched rows from the left table. Where there is no match, the left side columns are NULL.

SELECT e.first_name, d.name AS dept FROM employees e RIGHT JOIN departments d ON e.department_id = d.id;

This ensures every department appears even if no employee belongs to it. The result is identical to a LEFT JOIN with the tables swapped.

SQLite Does Not Support RIGHT JOIN

SQLite (which our console uses) does not natively support RIGHT JOIN. You can always rewrite a RIGHT JOIN as a LEFT JOIN by swapping the table order. The following two queries produce identical results:

-- RIGHT JOIN (not supported in SQLite) SELECT e.first_name, d.name FROM employees e RIGHT JOIN departments d ON e.department_id = d.id; -- Equivalent LEFT JOIN (works in SQLite) SELECT e.first_name, d.name FROM departments d LEFT JOIN employees e ON d.id = e.department_id;

In practice, most developers prefer LEFT JOIN over RIGHT JOIN for readability. If you always think of the "primary" table as the left table, your queries read top-to-bottom naturally.

FULL OUTER JOIN

A FULL OUTER JOIN returns all rows from both tables. Where there is no match, the missing side is filled with NULL. It is the combination of LEFT JOIN and RIGHT JOIN.

-- FULL OUTER JOIN (not directly supported in SQLite) SELECT e.first_name, d.name AS dept FROM employees e FULL OUTER JOIN departments d ON e.department_id = d.id;

The result includes:

Matched Rows Employees that belong to a department, with both sides populated
Left Only Employees with no valid department (dept columns are NULL)
Right Only Departments with no employees (employee columns are NULL)

SQLite FULL OUTER JOIN Workaround

SQLite does not support FULL OUTER JOIN directly. You can emulate it using a UNION of a LEFT JOIN and a LEFT JOIN with the tables reversed:

-- Emulate FULL OUTER JOIN in SQLite SELECT e.first_name, d.name AS dept FROM employees e LEFT JOIN departments d ON e.department_id = d.id UNION SELECT e.first_name, d.name AS dept FROM departments d LEFT JOIN employees e ON d.id = e.department_id WHERE e.id IS NULL;

The first query gets all employees (with or without departments). The second query adds departments that have no employees. UNION removes duplicates automatically.

LEFT JOIN vs INNER JOIN

Understanding when to use LEFT JOIN versus INNER JOIN is one of the most important decisions in writing SQL queries. Here is a side-by-side comparison:

Behavior INNER JOIN LEFT JOIN
Matched rows Included Included
Left table, no match Excluded Included (NULLs on right)
Right table, no match Excluded Excluded
Use when You only want rows that exist in both tables You need every row from the left table regardless

Rule of thumb: Use INNER JOIN when you only care about matches. Use LEFT JOIN when you need a complete list from one table, even if some rows have no corresponding data in the other table.

Practical: Customer Order Analysis

LEFT JOIN shines in reporting scenarios. Suppose you want to see how many orders each customer has placed, including customers who have never ordered:

SELECT c.name, COUNT(o.id) AS order_count FROM customers c LEFT JOIN orders o ON c.id = o.customer_id GROUP BY c.name;

With INNER JOIN, customers who have zero orders would disappear from the report. With LEFT JOIN, they appear with an order_count of 0. This is because COUNT(o.id) counts non-NULL values, and when there is no matching order, o.id is NULL and is not counted.

COUNT(*) vs COUNT(column)

Use COUNT(o.id) not COUNT(*) in LEFT JOIN aggregations. COUNT(*) counts all rows including those with NULLs, so a customer with zero orders would show a count of 1 (from the one NULL-filled row). COUNT(o.id) correctly returns 0 because NULL values are not counted.

Try this query in the console. You should see every customer listed with their order count. Customers with no orders show 0.

Key Takeaways

  • LEFT JOIN returns all rows from the left table, filling NULLs where the right has no match
  • Use LEFT JOIN + WHERE IS NULL to find rows with no match (orphan detection)
  • RIGHT JOIN is just a LEFT JOIN with the tables swapped; prefer LEFT JOIN for clarity
  • FULL OUTER JOIN returns all rows from both tables; emulate in SQLite with UNION
  • INNER JOIN drops unmatched rows; LEFT JOIN keeps them with NULLs on the right side
  • Use COUNT(column) instead of COUNT(*) when counting through a LEFT JOIN to get correct zero counts
