Security Operations

Security operations is where theory meets reality. Prevention controls will fail. The Security Operations Center (SOC) is the function responsible for detecting, investigating, and responding to threats in real time. This module covers the tools, processes, and skills that make SecOps effective.

Topics Covered

SOC functions, SIEM, incident response lifecycle, SOAR, threat hunting, threat intelligence, and digital forensics fundamentals.

Why It Matters

The average dwell time — time between initial compromise and detection — is 207 days (IBM 2023). Effective security operations reduces this dramatically, limiting attacker impact and data loss.

50 minutes. 13 slides.

Module Alignment

The Security Operations Center (SOC)

A SOC is a centralized function — internal, outsourced (MSSP), or hybrid — responsible for continuously monitoring, analyzing, and responding to security events across an organization's environment.

SOC Tier Structure

Tier 1 Analyst: Alert triage, initial investigation, escalation. Volume-focused — handles the bulk of incoming alerts.

Tier 2 Analyst: Deep investigation, incident handling, threat hunting, correlation across multiple alerts and data sources.

Tier 3 / Threat Intelligence: Advanced threat hunting, malware analysis, red team coordination, tool development.

SOC Functions

  • 24/7 alert monitoring and triage
  • Incident detection and response
  • Vulnerability management support
  • Threat intelligence consumption
  • Threat hunting
  • Log management and SIEM administration
  • Metrics and reporting
  • Security tool management

Key Metrics

MTTD — Mean Time to Detect. How long to identify an incident.

MTTR — Mean Time to Respond (or Remediate). How long to contain and resolve.

False Positive Rate — Percentage of alerts that are not real threats. High rates reduce analyst efficiency and cause alert fatigue.

Security Information and Event Management (SIEM)

A SIEM aggregates log data from across the enterprise, normalizes it, applies correlation rules, and generates alerts. It is the central visibility platform for security operations.

Log Sources

Firewalls, IDS/IPS, EDR, Active Directory, cloud platforms, web proxies, DNS, email gateways, application logs, network devices. The more sources, the richer the correlation — but ingestion cost scales with volume.

SIEM Capabilities

  • Log ingestion, normalization, and storage
  • Real-time correlation rules (alert generation)
  • Query language for ad-hoc investigation
  • Dashboards and reporting
  • Case management (some platforms)
  • UEBA (user behavior analytics)
  • Threat intelligence integration

Microsoft Sentinel

Cloud-native SIEM + SOAR. Consumption-based pricing. Built-in UEBA, ML-based detection, 200+ data connectors. KQL (Kusto Query Language) for queries. Integrated with Defender XDR for alert correlation across endpoint, identity, email, and cloud.

Alert Fatigue is a Real Risk

An undertunded SIEM that fires thousands of alerts per day trains analysts to ignore them. A smaller set of high-fidelity, well-tuned alerts with clear investigation guidance is far more effective than maximizing alert volume.

Incident Response Lifecycle

The NIST SP 800-61 incident response lifecycle provides a structured framework for handling security incidents. Following this process reduces chaos, contains damage, and enables learning.

1

Preparation

Develop IRP, train team, establish communication plans, maintain runbooks, deploy monitoring tools, conduct tabletop exercises. Done before any incident occurs.

2

Detection and Analysis

Identify indicators of compromise (IOCs), triage alerts, determine scope and severity. Declare incident. Preserve evidence. Timeline reconstruction. Initial stakeholder notification.

3

Containment

Short-term: stop the bleeding (isolate affected hosts, block malicious IPs). Long-term: remediate root cause without destroying evidence. Choose containment strategy based on business impact vs. forensic needs.

4

Eradication

Remove malware, close vulnerabilities, revoke compromised credentials. Verify the threat actor has been fully expelled from the environment before recovery begins.

5

Recovery

Restore systems from clean backups or rebuild. Verify integrity before reconnecting to network. Gradual restoration with enhanced monitoring to detect reinfection.

6

Lessons Learned

Post-incident review within 2 weeks. Document timeline, root cause, detection gaps, and response effectiveness. Update detection rules, IRP, and training based on findings.

Security Orchestration, Automation, and Response (SOAR)

SOAR platforms automate repetitive response actions, enabling analysts to focus on complex investigation while routine containment happens at machine speed.

Playbook Automation

Pre-defined response workflows triggered by alerts. Example: phishing alert → extract URLs → check against threat intel → sandbox detonate → if malicious, block URLs, quarantine sender, notify user manager, create ticket. All automatic, in seconds.

Orchestration

SOAR integrates disparate security tools via APIs. One investigation or response action can simultaneously query the EDR, firewall, SIEM, threat intel, ticketing system, and notification platform — without analyst context-switching.

Use Cases

Phishing triage and remediation. User account lockout investigation. Malicious IP enrichment and blocking. Vulnerability alert routing. Identity anomaly investigation. Automated IoC enrichment from threat intelligence feeds.

Microsoft Sentinel SOAR

Azure Logic Apps provides SOAR capabilities integrated directly into Sentinel. Playbooks can be triggered by analytics rules. 200+ connectors available. Analysts can build no-code playbooks for common response scenarios.

Threat Intelligence

Threat intelligence is evidence-based knowledge about adversaries — their capabilities, motivations, infrastructure, and techniques. Good intelligence drives proactive defense rather than reactive firefighting.

Intelligence Types

Strategic: Long-term trends, threat actor landscapes, geopolitical risk. Audience: executives and CISO.

Operational: Specific campaigns and attack methodologies. Audience: SOC managers and IR teams.

Tactical: TTPs (Tactics, Techniques, Procedures). Maps to MITRE ATT&CK. Audience: detection engineers and threat hunters.

Technical: IOCs — IP addresses, domains, file hashes. Audience: analysts, fed into SIEM and EDR.

Intelligence Sources

  • Commercial feeds (Recorded Future, CrowdStrike Intel)
  • Open source (MISP, AlienVault OTX, VirusTotal)
  • Government (US-CERT, CISA advisories)
  • Information Sharing (ISACs — sector-specific)
  • Dark web monitoring
  • Internal telemetry and incident data
STIX/TAXII

Structured Threat Information eXpression (STIX) is the standard format for threat intelligence data. Trusted Automated eXchange of Intelligence Information (TAXII) is the transport protocol. Together, they enable machine-readable intelligence sharing between organizations and platforms.

MITRE ATT&CK Framework

MITRE ATT&CK is a globally accessible knowledge base of adversary tactics and techniques based on real-world observations. It is the universal language of threat detection and threat hunting.

14 ATT&CK Tactics

  1. Reconnaissance
  2. Resource Development
  3. Initial Access
  4. Execution
  5. Persistence
  6. Privilege Escalation
  7. Defense Evasion
  8. Credential Access
  9. Discovery
  10. Lateral Movement
  11. Collection
  12. Command and Control
  13. Exfiltration
  14. Impact

Using ATT&CK

Detection Engineering: Map detection rules to ATT&CK techniques. Identify coverage gaps. A technique with no detection rule is a blind spot.

Threat Hunting: Use known adversary TTPs to formulate hypotheses. "If APT29 uses T1059.001 (PowerShell), what evidence would that leave?"

Purple Team: Red team simulates specific techniques; blue team validates detection and response coverage for each technique.

ATT&CK Navigator

Free web-based tool to visualize coverage. Color-code which techniques you detect, which you have controls for, and which are gaps. Share heat maps with leadership.

Threat Hunting

Threat hunting is the proactive, analyst-led search for advanced threats that automated detection has not caught. Hunters assume compromise and seek evidence using hypothesis-driven investigation.

Hunt vs. Monitoring

Monitoring is reactive — wait for an alert, then investigate. Hunting is proactive — formulate a hypothesis about how an attacker might be present and go look for evidence. Both are required in a mature SOC.

The Hunt Process

  1. Hypothesis (threat intel, ATT&CK, anomaly)
  2. Data gathering (SIEM, EDR, NetFlow query)
  3. Pattern analysis
  4. Pivot on findings
  5. Scope determination
  6. Handoff to IR if threat found
  7. Create detection rule for future automation

Common Hunt Hypotheses

  • PowerShell executing base64-encoded commands
  • User logging in from two countries in 2 hours
  • DNS queries to newly registered domains
  • Process spawning from %APPDATA% or %TEMP%
  • Large outbound data transfers after hours
  • RDP connections from service accounts

Digital Forensics Fundamentals

Digital forensics is the process of collecting, preserving, analyzing, and presenting digital evidence in a manner admissible in court and defensible to stakeholders. The foundation is the chain of custody.

Order of Volatility

Collect the most volatile evidence first. Order (most to least volatile): CPU registers/cache, RAM, running processes, network connections, disk, logs, backups. A system reboot destroys RAM and process data permanently.

Evidence Preservation

Forensic images (bit-for-bit copies) are taken rather than working on original drives. Hash the image (SHA-256) immediately. Any investigation uses a copy. The original is sealed and documented to preserve chain of custody.

Artifacts to Collect

  • Memory dump (RAM)
  • Disk image
  • System and application event logs
  • Network capture (PCAP)
  • Browser history and artifacts
  • Prefetch files, ShellBags, LNK files
  • Registry hive exports
Anti-Forensics Awareness

Sophisticated attackers use anti-forensics techniques: timestamp manipulation, log deletion, encrypted communications, steganography, and living-off-the-land to reduce forensic footprint. Forensic examiners must account for the absence of expected artifacts as itself a potential indicator.

Vulnerability Management in SecOps

Vulnerability management is a continuous process within security operations — discover, assess, prioritize, and remediate vulnerabilities before attackers exploit them.

Vulnerability Scanning

Authenticated scans (with credentials) find vulnerabilities the scanner can access internally. Unauthenticated scans simulate external attacker view. Tools: Nessus, Qualys, Rapid7 InsightVM, Microsoft Defender Vulnerability Management.

CVSS Scoring

Common Vulnerability Scoring System rates severity 0-10. Factors: attack vector, complexity, privileges required, user interaction, CIA impact. CVSS ≥ 9.0 = Critical. But CVSS alone is insufficient — weaponized exploits exist for low-CVSS vulnerabilities.

Risk-Based Prioritization

EPSS (Exploit Prediction Scoring System): probability a vulnerability will be exploited in the wild. CISA KEV: known exploited. A CVE-7.5 vulnerability that is actively exploited against your OS is higher priority than a CVE-9.8 with no public exploit.

Log Tampering

Attackers delete or modify logs as a defense evasion technique. Forward logs to a centralized, write-protected system immediately. A SIEM that receives logs via syslog is an attacker's log-deletion prevention mechanism — they cannot delete what they haven't written to.

SecOps Metrics and Continuous Improvement

Security operations must be measured to improve. Key performance indicators enable management to understand SOC effectiveness and prioritize investment.

Detection Metrics

  • MTTD (Mean Time to Detect)
  • True positive rate vs false positive rate
  • ATT&CK coverage percentage
  • Alert volume and trend
  • Escalation rate (T1 → T2)

Response Metrics

  • MTTR (Mean Time to Respond)
  • Incident severity distribution
  • Containment success rate
  • Recurrence rate (same attacker/technique)
  • Playbook automation rate

Improvement Drivers

Post-incident reviews drive detection rule improvements. Purple team exercises identify detection gaps. Threat intel feeds new hunting hypotheses. Analyst feedback tunes false positive rates. Quarterly review of top alert categories.

Module 07 — Review Questions

Q1: What is the difference between MTTD and MTTR, and which is typically more important to minimize first?

MTTD is Mean Time to Detect — how long before the SOC identifies an active incident. MTTR is Mean Time to Respond — how long from detection to containment and remediation. MTTD is typically prioritized first: you cannot respond to what you haven't detected. Reducing dwell time (time from compromise to detection) has the highest impact on limiting attacker damage.

Q2: What is the "order of volatility" and why does it matter in digital forensics?

Order of volatility defines how quickly different types of evidence disappear. RAM contents, running processes, and active network connections are lost when a system is powered off. Disk contents are more persistent. Forensic responders must collect volatile evidence (RAM dump, network state) before less volatile evidence, or that data is permanently lost.

Q3: How does SOAR reduce analyst burden without reducing security effectiveness?

SOAR automates routine, repeatable response actions that would otherwise consume analyst time: enriching IOCs, quarantining endpoints, blocking IPs, creating tickets, notifying stakeholders. Analysts focus on complex investigation requiring human judgment. The result is faster response (machine speed) and more analyst time for high-value work.

Q4: What makes MITRE ATT&CK useful for detection gap analysis?

ATT&CK maps every known adversary technique to a taxonomy. By mapping your existing detection rules to ATT&CK techniques and visualizing with ATT&CK Navigator, you can see which techniques have no detection coverage — your blind spots. This converts abstract "security gaps" into specific, actionable detection engineering work items.

Q5: Why is forwarding logs to a centralized SIEM critical beyond just correlation capabilities?

Log tampering prevention. Attackers who compromise a system can delete local logs to hide their activity. Logs that have already been forwarded to a remote SIEM cannot be retroactively deleted. The centralized system provides forensic evidence integrity — the attacker cannot erase what was already sent before they gained control.
