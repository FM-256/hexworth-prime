Endpoint Security

Endpoints — laptops, desktops, servers, mobile devices, IoT — are the primary attack surface in most organizations. They are where users interact with data, where malware executes, and where credentials are stolen. Securing endpoints is non-negotiable.

Topics Covered

Antivirus vs EDR, OS hardening, patch management, application control, mobile device management, and endpoint detection principles.

Why It Matters

According to Verizon DBIR, over 70% of initial compromises begin at the endpoint through malware, credential theft, or exploitation of unpatched vulnerabilities.

45 minutes. 12 slides.

Antivirus vs. EDR: The Evolution

Traditional antivirus (AV) was designed for a threat landscape that no longer exists — static file-based malware with known signatures. Modern threats require fundamentally different tooling.

CapabilityTraditional AVEndpoint Detection and Response (EDR)
Detection MethodSignature matchingBehavioral analysis, ML, IOC/IOA correlation
Zero-Day CoverageNone until signature updateBehavioral detection catches unknown threats
Fileless MalwareCannot detect (no file to scan)Detects memory-resident and script-based attacks
TelemetryMinimalFull process tree, network connections, registry changes
ResponseQuarantine/deleteIsolate host, kill process, rollback changes, remote investigation
HuntingNoneQuery historical telemetry for threat hunting
XDR: Extended Detection and Response

XDR extends EDR by correlating signals across endpoints, network, identity, email, and cloud workloads into a unified detection and response platform. Microsoft Defender XDR is a leading example.

Patch Management

Unpatched vulnerabilities are among the top initial access vectors. Patch management is the systematic process of identifying, acquiring, testing, and deploying software updates to reduce exposure.

Patch Management Lifecycle

  1. Inventory all assets
  2. Scan for vulnerabilities (CVSS scoring)
  3. Prioritize by risk (CVSS, exploitability, exposure)
  4. Test in non-production environment
  5. Deploy in controlled rollout
  6. Verify and document

Patch Prioritization

Critical + actively exploited = immediate. CISA KEV (Known Exploited Vulnerabilities) catalog is the authoritative source. Prioritize internet-facing systems, privileged endpoints, and critical infrastructure first.

Tools

Microsoft WSUS/MECM, Intune for cloud-managed endpoints, third-party tools (Ivanti, Qualys). SLAs: Critical = 24-72h, High = 7d, Medium = 30d, Low = 90d (adjust per policy).

Legacy/EOL Systems

End-of-life systems (Windows 7, Server 2008) receive no patches. They must be isolated, monitored with compensating controls, or decommissioned. Leaving them internet-accessible is an unacceptable risk.

Operating System Hardening

OS hardening reduces attack surface by eliminating unnecessary services, restricting permissions, and applying secure configuration baselines. A default OS installation is not a secure configuration.

Core Hardening Actions

✓
Disable unnecessary services — Stop and disable services not required for the system's function. Fewer services = smaller attack surface.
✓
Remove unused software — Every installed application is a potential vulnerability. Remove bloatware and unneeded applications.
✓
Configure host firewall — Block all inbound connections except explicitly required ports/services.
✓
Enable audit logging — Log logon events, privilege use, process creation, and policy changes for forensic capability.
✓
Enforce account policies — Password complexity, minimum length, account lockout thresholds, and MFA requirements.
✓
Enable disk encryption — BitLocker (Windows), FileVault (macOS), LUKS (Linux). Protects data if a device is stolen.
✓
Apply security baselines — CIS Benchmarks, DISA STIGs, Microsoft Security Baselines provide tested configuration templates.
Configuration Drift

Hardened configurations degrade over time through manual changes, software installs, and troubleshooting. Continuous compliance monitoring (Defender for Cloud, CIS-CAT) detects and alerts on drift from baseline.

Application Control and Allowlisting

Application control restricts which software can execute on a system. Allowlisting (also called application allowlisting or whitelisting) is the strictest model: only explicitly approved applications may run. Everything else is blocked by default.

Allowlisting

Default-deny execution model. Only signed, approved applications run. Highly effective against malware, ransomware, and unauthorized tools. Higher operational overhead — new software requires approval.

Blocklisting (Blacklisting)

Block known-bad applications. Default-allow — everything runs unless explicitly blocked. Easier to manage but reactive. Cannot stop novel malware not on the blocklist.

Windows Implementation

AppLocker (per-user, GPO-based). Windows Defender Application Control (WDAC) — kernel-level, cannot be bypassed by local admin. Use WDAC for high-security environments.

Script Control

PowerShell Constrained Language Mode. AMSI (Antimalware Scan Interface) scans script content before execution. Block unsigned PowerShell scripts via execution policy + WDAC.

EDR Detection Techniques

Modern EDR platforms use multiple detection engines simultaneously. Understanding how each works helps security teams tune and interpret alerts correctly.

IOC-Based Detection

Indicators of Compromise: file hashes, known malicious IPs/domains, registry keys, file paths. Fast, low false-positive, but only catches known threats.

IOA-Based Detection

Indicators of Attack: behavioral sequences (e.g., process spawning cmd.exe → downloading a file → executing it). Catches novel malware that hasn't been seen before.

MITRE ATT&CK Mapping

EDR alerts map to MITRE ATT&CK tactics and techniques. Enables threat hunting by technique (e.g., T1059 Command Scripting Interpreter) rather than by malware family.

Machine Learning Models

Static ML (pre-execution file analysis) and behavioral ML (runtime anomaly detection) catch variants not in signature databases. Requires tuning to reduce false positives.

Mobile Device Security

Mobile devices access corporate email, data, and applications from untrusted networks. They are lost, stolen, and infected at high rates. Mobile security strategy must balance protection with usability.

MDM (Mobile Device Management)

Full device management. Deploy certificates, enforce policies, push apps, wipe devices remotely. Requires device enrollment. Used for corporate-owned devices. Examples: Intune, Jamf, VMware Workspace ONE.

MAM (Mobile Application Management)

Manages only the managed applications and their data container, not the entire device. Suitable for BYOD — corporate data is protected without full device control. Users retain personal app control.

Key Mobile Policies

  • Require device PIN/biometric lock
  • Enable remote wipe capability
  • Enforce OS version minimums
  • Block jailbroken/rooted devices
  • Require corporate app from managed store
  • Encrypt corporate data at rest

Secure Boot, TPM, and Hardware-Based Security

Hardware security features provide root-of-trust guarantees that software cannot provide — even a compromised OS cannot defeat hardware-enforced protections.

Trusted Platform Module (TPM)

Hardware chip that stores cryptographic keys and measurements. Used for BitLocker key storage, device attestation, and certificate-based authentication. TPM 2.0 required for Windows 11. Prevents key extraction even with physical access.

Secure Boot

UEFI feature that verifies the cryptographic signature of bootloaders before executing them. Prevents bootkits and rootkits that target the pre-OS boot process. Firmware database maintains trusted signatures.

Measured Boot + Attestation

TPM records cryptographic hashes of each boot component into PCR registers. Attestation services (Microsoft Azure Attestation) verify the boot chain is unmodified. Conditional Access can require attestation before granting access.

Microsoft Pluton

Microsoft's next-generation security processor integrates directly into the CPU, eliminating the communication bus between CPU and TPM that traditional attacks targeted. Firmware updates delivered via Windows Update, not vendor-specific tools.

Security Baselines and Compliance Frameworks

Industry-standard security baselines provide tested, peer-reviewed configuration guidance that organizations can apply rather than building from scratch.

CIS Benchmarks

Center for Internet Security publishes detailed benchmarks for Windows, Linux, macOS, browsers, and cloud platforms. Free to download. Two levels: Level 1 (general use) and Level 2 (high security/high impact).

DISA STIGs

Defense Information Systems Agency Security Technical Implementation Guides. US DoD standard. Extremely detailed. STIG Viewer and SCAP content available. Mandatory for DoD contractors and federal agencies.

Microsoft Security Baselines

Group Policy objects and Intune profiles based on Microsoft security research. Available via Microsoft Security Compliance Toolkit. Regularly updated with new Windows and Office versions.

Baseline Customization Required

No baseline applies to every organization unchanged. Baselines must be tested, evaluated for operational impact, and customized to accommodate legitimate business requirements. Document all deviations with risk acceptance.

Endpoint Threat Hunting

Threat hunting is the proactive, hypothesis-driven search for threats that have evaded automated defenses. Unlike reactive incident response, hunting assumes compromise and seeks evidence.

Hunting Process

  1. Hypothesis — Based on threat intelligence, TTPs (MITRE ATT&CK), or anomalies. Example: "Are any endpoints running PowerShell that is downloading code from the internet?"
  2. Data Collection — Query EDR telemetry, event logs, DNS, proxy logs.
  3. Investigation — Analyze results, pivot on IOCs/IOAs found.
  4. Response — Contain and remediate findings.
  5. Detection Improvement — Convert successful hunt into automated detection rule.

Common Hunt Targets

  • Unusual parent-child process relationships (Word spawning PowerShell)
  • Living-off-the-land (LOLBin) abuse (certutil, bitsadmin for downloads)
  • Persistence mechanisms (scheduled tasks, run keys, services)
  • Credential access (LSASS memory reads, credential dumping tools)
  • Lateral movement (PsExec, WMI remote execution, Pass-the-Hash)
  • Beaconing to unusual external destinations

Module 04 — Review Questions

Q1: What is the key difference between IOC-based and IOA-based detection in an EDR?

IOC (Indicator of Compromise) detection matches known-bad artifacts like file hashes or IPs — it only catches known threats. IOA (Indicator of Attack) detection identifies behavioral sequences and attack patterns, catching novel threats before they have a signature in any database.

Q2: Why is fileless malware particularly difficult to detect with traditional antivirus?

Fileless malware executes entirely in memory without writing files to disk. Traditional AV scans files on disk — there is nothing for it to find. EDR with behavioral and memory scanning detects process anomalies and in-memory payloads that leave no file footprint.

Q3: What is the difference between MDM and MAM and which is more appropriate for BYOD?

MDM manages the entire device (corporate-owned appropriate). MAM manages only the corporate application container on the device. MAM is more appropriate for BYOD because employees retain control over personal apps and data while corporate data is secured in the managed container.

Q4: What does a TPM chip enable that software-only encryption cannot provide?

Hardware-rooted key storage. Encryption keys stored in the TPM cannot be extracted even if an attacker has physical access to the drive or the OS is compromised. The TPM binds key release to measured system state (boot measurements), ensuring keys are only available on the original, unmodified system.

Q5: Why is patch prioritization critical and what is the recommended source for identifying actively exploited vulnerabilities?

Patching everything immediately is operationally impossible. Prioritization directs limited resources to the highest-risk vulnerabilities first. CISA's Known Exploited Vulnerabilities (KEV) catalog is the authoritative source — it lists vulnerabilities confirmed to be actively exploited in the wild, which must be patched with the highest priority.
