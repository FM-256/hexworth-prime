Data Security

Data is the asset that attackers ultimately seek. All other security controls — firewalls, EDR, IAM — exist to protect data. This module covers how to classify, encrypt, and prevent loss of the organization's most valuable resource.

Topics Covered

Symmetric and asymmetric encryption, hashing, PKI, data classification, DLP, key management, and data state security.

Why It Matters

Data breaches cost an average of $4.45M (IBM 2023). The root cause is almost always inadequate data protection — wrong encryption, missing controls, or improper classification.

50 minutes. 13 slides.

Data States: At Rest, In Transit, In Use

Data exists in three states, each requiring specific protection mechanisms. A complete data security strategy must address all three.

Data at Rest

Stored data: databases, file shares, backups, cloud storage. Protection: full-disk encryption (BitLocker, LUKS), transparent data encryption (TDE) for databases, cloud storage-side encryption (SSE), and access controls.

Data in Transit

Data moving across a network. Protection: TLS 1.2/1.3 for web and API traffic, IPSec for VPN tunnels, SFTP/SCP for file transfer. Never transmit sensitive data over unencrypted protocols (HTTP, FTP, Telnet).

Data in Use

Data being processed in memory. Hardest to protect. Technologies: Confidential Computing (Intel SGX, AMD SEV), memory encryption, and process isolation. Prevents cloud provider or hypervisor from reading tenant data.

The Forgotten State

Most organizations encrypt data at rest and in transit but neglect in-use protection. Attackers increasingly target memory — LSASS dumps, process injection, and cold boot attacks all target data in use.

Symmetric Encryption

Symmetric encryption uses a single shared key for both encryption and decryption. It is fast, efficient, and used for bulk data encryption — but requires a secure channel to share the key.

How It Works

Plaintext + Key → Ciphertext
Ciphertext + Same Key → Plaintext

Both parties must possess the same key. Key exchange is the fundamental challenge — securely getting the key to the other party without it being intercepted.

Key Algorithms

  • AES-256 — Current gold standard. NIST approved. Used in TLS, disk encryption, VPNs. Highly secure and fast.
  • AES-128 — Faster, still very secure. Sufficient for most use cases.
  • 3DES — Legacy. Deprecated by NIST. Avoid in new systems.
  • RC4 — Broken. Never use.
  • ChaCha20 — Modern, fast on mobile hardware. Used in TLS 1.3.
Modes of Operation

Block cipher modes determine how a cipher processes data larger than one block. ECB (Electronic Codebook) is insecure — identical plaintext blocks produce identical ciphertext. Always use CBC (with random IV), GCM (provides authentication), or CTR for streaming data.

Asymmetric Encryption

Asymmetric encryption uses a mathematically linked key pair: a public key (freely distributed) and a private key (kept secret). It solves the key distribution problem of symmetric encryption.

Encryption (Confidentiality)

Plaintext + Recipient's Public Key → Ciphertext
Ciphertext + Recipient's Private Key → Plaintext

Anyone can encrypt a message to you using your public key. Only you can decrypt it with your private key.

Digital Signature (Integrity + Auth)

Message Hash + Sender's Private Key → Signature
Signature + Sender's Public Key → Verified Hash

The sender signs with their private key; anyone with the public key can verify the signature. Provides non-repudiation.

Hashing

A hash function takes input of any size and produces a fixed-size output (digest). Hashes are one-way — you cannot reverse a hash to get the original input. They protect Integrity, not Confidentiality.

Properties of a Secure Hash

  • Deterministic — Same input always produces the same output.
  • One-way (Pre-image resistant) — Cannot reverse the hash.
  • Collision resistant — Cannot find two inputs with the same hash.
  • Avalanche effect — Small input change produces completely different hash.

Never Hash Passwords with MD5 or SHA-1

MD5 and SHA-1 are fast — an attacker can compute billions of hashes per second on a GPU. For passwords, use a purpose-built slow hash: bcrypt, Argon2, or scrypt. Add a random salt to prevent rainbow table attacks.

Public Key Infrastructure (PKI)

PKI is the ecosystem that creates, manages, and validates digital certificates. It solves the problem of verifying that a public key actually belongs to who claims to own it.

Certificate Authority (CA)

A trusted entity that issues digital certificates. Signs the certificate with its private key, binding a public key to an identity. Root CAs are the ultimate trust anchors in browser/OS trust stores.

Certificate Contents

Subject (identity), Public key, Issuer (CA name), Validity period, Serial number, Signature algorithm, Extensions (SAN, key usage), CA's digital signature.

Certificate Revocation

CRL (Certificate Revocation List): published list of revoked certs. Slow to propagate. OCSP (Online Certificate Status Protocol): real-time query. OCSP Stapling: server caches and delivers OCSP response, reducing CA load and privacy issues.

Certificate Pinning

Applications can "pin" a specific certificate or CA, refusing to accept any other certificate even if it is valid and signed by a trusted CA. Protects against CA compromise or MitM attacks using rogue valid certificates. Used in high-security mobile apps.

Data Classification

Data classification assigns sensitivity labels to data, enabling organizations to apply appropriate controls based on data value and risk. You cannot protect what you have not categorized.

Public Approved for public access. Marketing materials, press releases, product documentation. No access controls required. Loss has minimal business impact.
Internal For employee use only. Operational procedures, internal policies, organizational charts. Should not leave the organization. Requires authentication to access.
Confidential Sensitive business data. Customer lists, financial records, strategic plans, intellectual property. Encryption required. Access on need-to-know basis. Regulatory implications if disclosed.
Restricted Highest sensitivity. Trade secrets, PCI cardholder data, HIPAA PHI, national security data. Strict encryption, access logging, DLP, and legal obligations. Breach carries severe penalties.
Microsoft Purview Information Protection

Applies sensitivity labels to Office documents, emails, and SharePoint content. Labels can enforce encryption, access restrictions, and visual markings automatically based on content classification or user selection.

Data Loss Prevention (DLP)

DLP solutions identify, monitor, and prevent the unauthorized movement or disclosure of sensitive data — whether accidental or malicious.

Endpoint DLP

Monitors and controls data operations on endpoints: clipboard operations, USB transfers, printing, screen capture, and application data transfer. Can block or alert on policy violations.

Network DLP

Inspects outbound network traffic for sensitive data patterns. Requires TLS inspection to see encrypted content. Can block uploads of credit card numbers, SSNs, or classified document markings.

Cloud DLP (CASB)

Cloud Access Security Broker monitors and controls data flows to cloud services. Blocks uploads of sensitive data to unauthorized cloud storage (shadow IT). API-based or proxy-based deployment.

DLP Tuning is Ongoing

DLP generates false positives at initial deployment. A DLP policy that blocks everything flagged immediately is operationally disruptive. Start in audit/monitor mode, tune to reduce false positives, then enable blocking incrementally. Engage business stakeholders.

Cryptographic Key Management

Encryption is only as strong as the security of the keys. The best cipher in the world provides no security if the keys are stored in plaintext next to the encrypted data.

Key Lifecycle

  1. Generation (CSPRNG, hardware-based)
  2. Distribution (secure channel)
  3. Storage (HSM, KMS, vault)
  4. Use (limited scope and purpose)
  5. Rotation (regular, automated)
  6. Revocation (immediate when compromised)
  7. Destruction (secure erasure)

Key Storage Options

HSM (Hardware Security Module): Tamper-resistant hardware that stores and processes keys. Keys never leave the HSM in plaintext. FIPS 140-2/3 validated.

KMS (Key Management Service): Cloud service for key management. AWS KMS, Azure Key Vault, Google Cloud KMS. Provide key rotation, auditing, and access control without on-prem HSM.

Key Rotation

Regular key rotation limits the exposure window if a key is compromised. Automate rotation where possible. Azure Key Vault supports automatic certificate and secret rotation. Never allow keys to be permanent.

TLS: Transport Layer Security

TLS is the protocol that secures nearly all internet traffic. Understanding how TLS works explains why both encryption types are needed and how PKI integrates into real-world security.

TLS Handshake (Simplified)

  1. Client sends supported cipher suites and TLS version (ClientHello)
  2. Server responds with chosen suite and sends its certificate
  3. Client verifies certificate against trusted CA store
  4. Key exchange (ECDHE): both parties generate a shared secret without transmitting it
  5. Session keys derived from shared secret using PRF
  6. Symmetric encryption begins (AES-GCM or ChaCha20-Poly1305)

Data Backup and Recovery

Backups are a critical data security control. They are the primary defense against ransomware and the only recovery option for data destruction attacks.

3-2-1 Backup Rule

3 copies of data. 2 different media types. 1 copy offsite (or offline). This rule has been extended to 3-2-1-1-0: + 1 copy air-gapped or immutable + 0 errors in restore verification.

Immutable Backups

Backups written with WORM (Write Once Read Many) protection. Cannot be encrypted or deleted by ransomware even with compromised admin credentials. Azure Blob immutability, AWS S3 Object Lock.

RTO and RPO

RTO (Recovery Time Objective): Maximum acceptable downtime. How fast must we restore? RPO (Recovery Point Objective): Maximum acceptable data loss. How old can our last backup be? These drive backup frequency and DR architecture.

Test Your Restores

A backup that has never been tested is not a backup — it is hope. Ransomware victims frequently discover their backups are corrupted, incomplete, or unrestorable only during a crisis. Schedule regular restore tests and document results.

Module 05 — Review Questions

Q1: Why can symmetric encryption not solve its own key distribution problem?

To securely share a symmetric key, you need a secure channel. But if you already have a secure channel, you could just send the data through it. Asymmetric encryption (e.g., ECDHE in TLS) solves this by enabling key agreement over an untrusted channel — neither party transmits the final shared secret.

Q2: What property of bcrypt/Argon2 makes them suitable for password storage while SHA-256 is not?

bcrypt and Argon2 are intentionally slow (computationally expensive). SHA-256 was designed for speed. Fast hashes allow attackers to compute billions of guesses per second. Slow hashes (tunable work factor) make brute-force attacks computationally infeasible even with GPU acceleration.

Q3: What is the difference between confidentiality and integrity, and which cryptographic primitive addresses each?

Confidentiality = data only readable by authorized parties. Addressed by encryption (symmetric or asymmetric). Integrity = data has not been altered. Addressed by hashing and digital signatures (MAC, HMAC, or public key signatures). AES-GCM provides both simultaneously — authenticated encryption.

Q4: What is the 3-2-1-1-0 backup rule and what does the final "0" represent?

3 copies, 2 different media types, 1 offsite, 1 air-gapped or immutable (ransomware-proof), 0 errors — meaning restore tests have been verified with no failures. The zero ensures backups are not just created but proven restorable.

Q5: What does Perfect Forward Secrecy (PFS) mean in TLS, and why does it matter?

PFS means each TLS session uses a unique ephemeral key exchange (ECDHE/DHE). Even if the server's private key is compromised in the future, past recorded sessions cannot be decrypted because the session keys were never stored and cannot be derived from the server's long-term private key.
