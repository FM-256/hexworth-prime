GPG Reference

Asymmetric keysRFC 4880

A key pair: public key (share freely) + private key (never share). Fingerprint = SHA-1 hash of the public key material.

Encryption ruleSY0-701 1.4

Encrypt with the recipient's public key. Only their private key decrypts. GPG wraps a random AES session key (hybrid crypto).

Signing rule

Sign with your private key. Anyone with your public key can verify. Proves authenticity + integrity.

Web of Trust

No central CA. You assign trust to key owners; their key signatures on third-party keys propagate that trust. unknown → marginal → full → ultimate.

Fingerprint verify

Confirm a contact's key out-of-band (phone, in person). Stops MITM key substitution. gpg --fingerprint uid.

Mission 1 — Generate your GPG key pair

Every GPG user starts by generating a key pair. The public key is freely shared so others can encrypt to you or verify your signatures. The private key stays secret forever. The key's fingerprint (a hash of the public key material) lets others confirm they have your genuine key out-of-band.

Objective: generate a real RSA-OAEP-2048 (encryption) key pair and an RSA-PSS-2048 (signing) key pair via the browser's crypto.subtle, then read off the fingerprint that was produced from your public key material. Proceed to Mission 2 once keys are ready.
$ gpg --full-generate-key

Mission 2 — Encrypt to a recipient & decrypt

Alice wants to send Bob a classified message. She encrypts it with Bob's public key. Only Bob's private key can decrypt it — not Alice's, not an eavesdropper's. You'll play both roles to complete the round trip.

Objective: (1) generate Bob's key pair, (2) encrypt Alice's message with Bob's public key (real RSA-OAEP), (3) decrypt with Bob's private key and confirm the round-trip. A wrong or missing key must fail to decrypt.
$ gpg --encrypt -r bob@shield.ops classified.txt

Mission 3 — Sign a message & catch a tampered one

Your Mission-1 keys include an RSA-PSS signing key pair. Sign a field report with your private signing key. Anyone holding your public key can verify the signature proves it came from you and was not altered. Then the lab will present a tampered version — the same signature must now report INVALID.

Objective: (1) sign the field report, (2) verify the genuine report (must be VALID), (3) verify the tampered report (must be INVALID). Both steps are required to complete the mission.
$ gpg --sign report.txt
$ gpg --verify report.txt.gpg   # VALID
$ gpg --verify tampered.txt.gpg   # INVALID
Complete Mission 1 first to get your signing key
sign the report to produce a signature

Signing rule: sign with your private key, verify with your public key. The signature covers the message content; one changed byte flips VALID to INVALID. Tie the public key to a CA-issued certificate and you also gain non-repudiation.

Mission 4 — Key trust & fingerprint verification

A contact named "Agent Morse" sends you their public key over email. Without verification, you cannot know it is genuine — an adversary could substitute their own key (MITM). You call Agent Morse on a secure line and compare fingerprints character-by-character. Only if they match exactly is the key authentic. You then assign a trust level, which determines how GPG weighs their key signatures in the web of trust.

Objective: (1) generate Agent Morse's key (simulating them sending you their public key), (2) compare the fingerprint you see on the key against the one "Morse reads to you on the phone" (the lab shows both; confirm they match), (3) assign the correct trust level for a trusted colleague you have verified in person.
$ gpg --fingerprint morse@shield.ops
$ gpg --edit-key morse@shield.ops

None (1) Known to improperly validate keys — actively distrust

GPG web-of-trust rule: 1 fully-trusted signature validates a key; 3 marginally-trusted signatures also validate it. Chains can be at most 5 levels deep. ultimate is reserved for keys you own — never assign it to a contact.

GPG Workflow

Quick Rules

Encrypt: use recipient's public key → only their private key decrypts

Sign: use your private key → anyone with your public key can verify

Fingerprint: SHA-1/SHA-256 hash of public key material — verify out-of-band before trusting

Trust levels: unknown → none → marginal → full → ultimate (own keys only)

Web of Trust: 1 full-trust signature OR 3 marginal-trust signatures = key is valid
