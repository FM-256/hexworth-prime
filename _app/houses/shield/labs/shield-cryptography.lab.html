Primitives

HashingFIPS 180-4

One-way, fixed-length, deterministic. Integrity. SHA-256/384/512. MD5 & SHA-1 are broken. Salt + KDF for passwords.

SymmetricFIPS 197

One shared key. Confidentiality. AES; use authenticated modes (GCM). ECB leaks patterns. DES/3DES retired.

AsymmetricFIPS 186

Public/private pair. Signatures (sign with private, verify with public → authenticity + integrity; bind the key via a CA for non-repudiation) & key exchange (ECDH). RSA-2048+/ECC.

Mission 1 — Integrity with SHA-256

A wire-transfer instruction was published with a SHA-256 checksum. A copy just arrived from the network. Hash it yourself and decide: was it altered in transit? A hash is one-way and deterministic — one changed character avalanches the whole digest.

Objective: compute the real SHA-256 of the received copy, compare to the published digest, and submit the correct verdict.

Why not MD5 or SHA-1? Both have practical collisions — an attacker can craft a different message with the same digest. Modern integrity uses SHA-256 or better.

Mission 2 — Confidentiality with AES-GCM

Encrypt a patient record so only a holder of the passphrase can read it. You'll derive an AES key (PBKDF2), encrypt with AES-GCM (authenticated), then decrypt. GCM also detects tampering — a wrong key or altered ciphertext fails to authenticate, instead of silently returning garbage.

Objective: encrypt the record and recover it with the correct passphrase — a real round trip. Then choose the mode fit for confidentiality.

Mission 3 — Authenticity & non-repudiation

A firmware update claims to be from the vendor. Generate an ECDSA key pair, have the vendor "sign" the update with the private key, then verify with the public key. A valid signature proves it came from whoever holds the private key (authenticity) and that the message wasn't modified (integrity). Bind that public key to a verified identity through a CA / PKI and you also gain non-repudiation — the signer can't credibly deny it.

Objective: verify the genuine signed update (VALID), then catch the attacker's forged update (INVALID).

Forged update = the attacker changes the message ("checksum 0x0000") but has no private key. The same public key now reports INVALID — the signature no longer matches.

Mission 4 — Key exchange with ECDH

Alice and Bob have never met and the channel is wide open. Each generates an ECDH key pair, they swap only their public keys, and each derives the same shared secret from their own private key + the other's public key. The eavesdropper sees both public keys and still can't compute it.

Objective: establish a shared secret on both sides and confirm the two derived secrets are identical — without ever transmitting the secret.

Mission 5 — Design the crypto suite

You've proven each primitive. Now specify the suite for the new EHR platform: match every requirement to the right primitive, and reject the weak/legacy options in the list. A single wrong or broken choice fails the review — in cryptography, the weakest link decides.

Objective: assign a sound primitive to each requirement. MD5, SHA-1, DES, RSA-512, ECB and plaintext are traps.
