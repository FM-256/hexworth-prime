Shared Responsibility Model
Security in the cloud is a shared job. Microsoft secures the infrastructure. You secure your data, identities, and configurations. The split depends on the service model.
Always Your Responsibility
Regardless of service model, you always own: data classification, account and identity management, device security, and access control decisions. Microsoft never manages your data governance for you.
Always Microsoft's Responsibility
Microsoft always owns: physical datacenters, physical network, physical hosts. You never patch a rack switch in Azure. The physical security of every Azure region is Microsoft's job.
The Shifting Middle
The layers between physical infra and data shift ownership depending on IaaS vs PaaS vs SaaS. In IaaS you patch the OS. In PaaS Microsoft patches the OS. In SaaS Microsoft handles nearly everything except your data and identity choices.

Defense in Depth
No single security layer is enough. Defense in depth uses multiple layers so if one fails, the next layer catches the attacker. Think of it as concentric rings of protection around your data.
Data at the Core
Data is the ultimate target. Every layer exists to protect it. Whether attackers want to steal it, encrypt it with ransomware, or destroy it -- every control is a barrier between them and your data.
If One Layer Fails
A phishing email bypasses the perimeter. But MFA at the identity layer stops the attacker from using the stolen password. If MFA fails, network segmentation limits lateral movement. Each layer is independent.
Microsoft's Implementation
Azure implements defense in depth through: physical datacenter security, Microsoft Entra ID for identity, Azure DDoS + Firewall for perimeter, NSGs for network, patching for compute, and encryption for data.

Zero Trust Model
Never trust, always verify. Assume breach. Verify explicitly. Use least-privilege access. These three principles replace the old "trust the corporate network" approach.
Verify Explicitly
Always authenticate and authorize based on all available signals: identity, location, device health, service or workload, data classification, and anomalies.
Least Privilege Access
Limit user access with just-in-time (JIT) and just-enough-access (JEA). Use risk-based adaptive policies and data protection to secure both data and productivity.
Assume Breach
Minimize blast radius with micro-segmentation. Use end-to-end encryption. Use analytics to detect threats, improve defenses, and drive automated responses.
Identity Pillar
Identities are the new perimeter. Every access request starts with identity verification through Microsoft Entra ID, MFA, and Conditional Access policies.
Devices Pillar
Devices create a large attack surface. Monitor device health and compliance. Only compliant, managed devices get full access to corporate resources.
Data Pillar
Classify, label, and encrypt data. Use data loss prevention policies. Data should be protected at rest, in transit, and in use regardless of where it travels.
Exam Focus
Zero Trust is the foundational security model for all Microsoft security products. Conditional Access is the Zero Trust policy engine. Every SC-900 question about security architecture maps back to these three principles.

The CIA Triad
Three pillars of information security. Every security control maps to one or more of these goals: Confidentiality, Integrity, and Availability.
Confidentiality
Only authorized people can access data. Enforced through encryption (data at rest and in transit), access controls (RBAC, Conditional Access), and data classification (sensitivity labels). A data breach violates confidentiality.
Integrity
Data has not been tampered with. Enforced through hashing (SHA-256 checksums), digital signatures, version control, and audit logs. If an attacker modifies a database record without detection, integrity is violated.
Availability
Systems and data are accessible when needed. Enforced through redundancy, load balancing, DDoS protection, backup and disaster recovery. A DDoS attack that takes down a service violates availability.

Common Threats
Know the threat landscape. The SC-900 exam expects you to identify and describe phishing, ransomware, DDoS attacks, and insider threats.
Phishing
Social engineering via email, text, or voice. Attacker impersonates a trusted entity to trick users into revealing credentials or clicking malicious links. Spear phishing targets specific individuals. Whaling targets executives. MFA and security awareness training are primary defenses.
Ransomware
Malware that encrypts files and demands payment for the decryption key. Often delivered through phishing or exploiting vulnerabilities. Defense: regular backups, endpoint protection (Defender for Endpoint), network segmentation, and patch management. Never pay the ransom.
DDoS (Distributed Denial of Service)
Overwhelms a service with massive traffic from multiple sources to make it unavailable. Targets the availability pillar of CIA. Azure DDoS Protection detects and mitigates volumetric, protocol, and application-layer attacks automatically.
Insider Threats
Malicious or negligent actions by employees, contractors, or partners with legitimate access. Harder to detect than external attacks because the user has valid credentials. Microsoft Purview Insider Risk Management uses behavioral signals to detect risky activity.
Key Insight
Most breaches start with compromised identities, not network exploits. This is why Zero Trust places identity at the center of the security model, and why MFA is the single most effective control against credential-based attacks.

Encryption Concepts
Encryption transforms readable data (plaintext) into unreadable data (ciphertext). Only authorized parties with the correct key can decrypt it back to plaintext.
Symmetric Encryption
One key for both encryption and decryption. Fast, used for bulk data encryption. Example: AES-256. Challenge: how do you securely share the key? Used for data at rest (disk encryption) and data in transit (after key exchange).
Asymmetric Encryption
Two keys: public key encrypts, private key decrypts. Slower than symmetric but solves the key distribution problem. Example: RSA. Used for digital signatures, TLS handshakes, and key exchange. The public key can be shared openly.
Hashing
One-way function: converts data into a fixed-length digest. Cannot be reversed. Same input always produces same hash. Used for password storage, file integrity verification, and digital signatures. Example: SHA-256. Any change to input produces a completely different hash.
In practice, TLS uses asymmetric encryption for the initial handshake (key exchange), then switches to symmetric encryption for the actual data transfer. This hybrid approach combines the security of asymmetric with the speed of symmetric.

Encryption for Data States
Data exists in three states, and each requires protection. Microsoft provides encryption solutions for all three.
Data at Rest
Stored on disk, database, or storage account. Azure Storage Service Encryption (SSE) encrypts all data automatically with AES-256. Azure Disk Encryption protects VM disks using BitLocker (Windows) or DM-Crypt (Linux). Keys can be managed by Microsoft or customer-managed in Azure Key Vault.
Data in Transit
Moving between locations -- user to server, server to server, datacenter to datacenter. Protected with TLS/SSL (HTTPS). Azure enforces TLS 1.2 minimum. ExpressRoute provides private connectivity. VPN Gateway encrypts site-to-site traffic.
Data in Use
Currently being processed in memory. Hardest state to protect. Azure Confidential Computing uses hardware-based Trusted Execution Environments (TEEs) to protect data in memory. Data remains encrypted even while being processed.

Governance and Compliance
Compliance means meeting regulatory, legal, and industry standards. Governance means the policies and processes that enforce compliance across your organization.
Regulatory Compliance
Laws and regulations that apply based on industry and geography. GDPR (EU data privacy), HIPAA (US healthcare), PCI DSS (payment cards), SOC 2 (service organizations). Non-compliance means fines, legal action, and reputation damage.
Microsoft Compliance Offerings
Microsoft holds 90+ compliance certifications. Azure, Microsoft 365, and Dynamics 365 are audited and certified against these standards. Microsoft provides compliance documentation, audit reports, and the Service Trust Portal for verification.
Data Residency and Sovereignty
Some regulations require data to stay within specific geographic boundaries. Azure regions let you choose where data is stored. Azure sovereign clouds (Government, China) provide isolated environments for regulated workloads.
Privacy Principles
Microsoft follows six privacy principles: control, transparency, security, strong legal protections, no content-based targeting, and benefits to users. The Microsoft Privacy Statement details how personal data is collected and used.

Identity as the Security Perimeter
The traditional network perimeter is gone. With remote work, BYOD, and cloud services, identity is now the primary security boundary. Authentication and authorization are the gatekeepers.
Authentication (AuthN)
Proving who you are. Something you know (password), something you have (phone, security key), something you are (biometrics). MFA combines two or more of these factors. Authentication answers: "Are you who you claim to be?"
Authorization (AuthZ)
Determining what you can do. After authentication confirms your identity, authorization checks your permissions. Role-Based Access Control (RBAC) assigns permissions through roles. Authorization answers: "What are you allowed to access?"
Identity Provider (IdP)
A service that creates, maintains, and manages identity information. Microsoft Entra ID is the IdP for Microsoft cloud services. An IdP handles authentication so applications do not have to build their own login systems.
Federation
Trust relationship between identity providers. Allows users authenticated by one IdP to access resources managed by another. Enables single sign-on (SSO) across organizational boundaries without sharing passwords.

Common Identity Attacks
Understanding how attackers target identities helps you appreciate why controls like MFA, Conditional Access, and password protection exist.
Password Spray
Try a few common passwords against many accounts. Avoids lockout thresholds. Microsoft Entra ID detects and blocks these patterns automatically.
Credential Stuffing
Use stolen username/password pairs from breached sites. Works because users reuse passwords. MFA stops this even if credentials are valid.
Brute Force
Try every possible password combination. Slow but effective against weak passwords. Account lockout policies and smart lockout in Entra ID mitigate this.
Man-in-the-Middle
Attacker intercepts communication between user and service. Captures credentials or session tokens. TLS encryption and certificate validation prevent this.
Token Replay
Steal and reuse a valid authentication token. Conditional Access token protection and continuous access evaluation (CAE) detect and revoke compromised tokens.
Social Engineering
Manipulate people into revealing credentials or granting access. Technical controls combined with security awareness training are the only effective defense.

Chapter 1 Summary
Key concepts you must know for the SC-900 exam.
1Shared Responsibility Model -- security responsibilities are split between Microsoft and the customer. The split varies by IaaS, PaaS, and SaaS. You always own data, identity, and access decisions.
2Defense in Depth -- multiple layers of security (physical, identity, perimeter, network, compute, application, data). No single layer is sufficient alone.
3Zero Trust -- three principles: verify explicitly, use least-privilege access, assume breach. Identity is the primary control plane.
4CIA Triad -- Confidentiality (only authorized access), Integrity (data not tampered), Availability (systems accessible when needed).
5Common Threats -- phishing (social engineering), ransomware (encrypt and extort), DDoS (overwhelm availability), insider threats (trusted users acting maliciously or negligently).
6Encryption -- symmetric (one key, fast), asymmetric (two keys, key exchange), hashing (one-way, integrity). Protect data at rest, in transit, and in use.
