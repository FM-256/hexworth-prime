Entra ID Core Concepts
A tenant is a dedicated instance of Entra ID. A directory is the container for users, groups, and apps. Every organization gets one tenant when they sign up for Microsoft cloud services.
Tenant
A dedicated, trusted instance of Microsoft Entra ID created automatically when your organization signs up for a Microsoft cloud service. Each tenant is distinct and separate. A tenant represents a single organization and has a unique tenant ID (GUID).
Users
Identity objects representing people or services. Cloud identities exist only in Entra ID. Synchronized identities come from on-premises Active Directory via Entra Connect. Guest users are external identities invited for collaboration.
Groups
Security groups manage access to resources (RBAC role assignments, app access). Microsoft 365 groups provide collaboration features (shared mailbox, SharePoint site, Teams channel). Groups can be assigned (manual) or dynamic (rule-based membership).
Key Distinction
Microsoft Entra ID is NOT the same as on-premises Active Directory Domain Services (AD DS). Entra ID is a cloud identity service using HTTP/HTTPS protocols (SAML, OAuth, OpenID Connect). AD DS uses Kerberos and LDAP. They can be synchronized but are fundamentally different products.

Authentication Methods
How users prove their identity. Microsoft Entra ID supports multiple authentication methods ranging from traditional passwords to modern passwordless options.
Passwords
Traditional but weakest method. Vulnerable to phishing, spray, and stuffing attacks. Microsoft recommends eliminating passwords where possible.
MFA
Requires two or more verification factors. Blocks 99.9% of identity attacks. Combines something you know + something you have or are.
Microsoft Authenticator
Push notification or time-based one-time password (TOTP). Number matching prevents MFA fatigue attacks. Can serve as passwordless primary factor.
FIDO2 Security Keys
Hardware tokens using public-key cryptography. Phishing-resistant because the key is bound to the origin domain. No shared secret to steal.
Windows Hello for Business
Biometric (face, fingerprint) or PIN tied to the device. Credentials never leave the device. Uses asymmetric key pairs, not passwords.
Certificate-Based Auth
X.509 certificates for authentication. Common in government and high-security environments. Certificates can be stored on smart cards or devices.

Conditional Access
The Zero Trust policy engine. Conditional Access evaluates signals (who, where, what device, what app) and enforces access decisions: allow, block, or require MFA.
Common Policy Examples
Require MFA for all admin roles. Block sign-ins from high-risk countries. Require compliant devices for accessing sensitive apps. Force password change when sign-in risk is elevated.
Session Controls
Beyond allow/block/MFA, policies can enforce session controls: sign-in frequency (force re-authentication every N hours), persistent browser sessions, and app-enforced restrictions.
Report-Only Mode
Test policies before enforcement. Report-only mode logs what the policy would do without actually blocking or requiring MFA. Essential for safe rollout of new policies in production.

Entra ID Roles
Built-in roles follow the principle of least privilege. Assign the most restrictive role that still allows the user to do their job.
Global Administrator
Full access to everything in Entra ID and all Microsoft 365 services. Can manage all aspects of the directory. Limit to 2-4 people maximum. Always protect with MFA and PIM just-in-time activation.
User Administrator
Can create and manage users and groups. Can reset passwords for non-admin users. Cannot manage Global Admin accounts or security settings. Common for helpdesk tier-2 roles.
Security Administrator
Can read security information, manage security policies, and configure identity protection. Cannot create or delete users. Designed for the security team.
Least Privilege
Never assign Global Administrator when a more specific role (User Admin, Security Admin, Billing Admin) will do. Use Privileged Identity Management (PIM) to make role assignments just-in-time rather than permanent.

Privileged Identity Management
PIM provides just-in-time privileged access. Instead of permanent admin roles, users activate roles when needed for a limited time. Requires Entra ID P2.
Just-in-Time Activation
Users are eligible for a role but not permanently assigned. They must activate the role, optionally provide justification, and the activation expires after a set duration (e.g., 8 hours). Reduces the window for compromised admin accounts.
Approval Workflows
Require a designated approver to approve role activation before it takes effect. Critical for high-impact roles like Global Administrator or Exchange Administrator.
Access Reviews
Periodic reviews of who has access to what. Reviewers confirm or deny continued access. Automated removal of access that is no longer justified. Required for compliance audits.
Audit History
Complete log of all role activations: who activated, when, for how long, and the justification provided. Essential for forensic investigation and compliance reporting.
Slide 7 of 12
Identity Governance
Identity governance ensures the right people have the right access to the right resources for the right amount of time.
Entitlement Management
Bundle resources (groups, apps, SharePoint sites) into access packages. Users request access packages. Policies define who can request, who approves, and when access expires. Self-service with governance controls.
Access Reviews
Scheduled reviews of group memberships, app assignments, and role assignments. Reviewers can be managers, resource owners, or self-review. Auto-remove access for users who do not respond or are denied.
Lifecycle Workflows
Automate identity lifecycle events: onboarding (create account, assign groups, send welcome email), role changes (add/remove access), offboarding (disable account, remove licenses, revoke access).
Slide 8 of 12
External Identities
Collaborate with people outside your organization without creating local accounts. Entra External ID covers B2B and B2C scenarios.
B2B Collaboration
Invite external users (partners, vendors, contractors) as guest users in your tenant. They authenticate with their own identity provider (their own Entra ID, Google, Microsoft account). You control what resources they can access. Their identity lifecycle is managed by their home organization.
B2C (Customer Identity)
Customer-facing identity service for apps and APIs. Users sign up with email, social accounts (Google, Facebook, Apple), or local accounts. Fully customizable sign-in experience. Separate from your corporate Entra ID tenant.
Cross-Tenant Access
Control inbound and outbound collaboration with other Entra ID organizations. Configure trust settings per organization: allow or block B2B, trust MFA from the partner tenant, trust device compliance claims.
Direct Connect
Mutual trust between two Entra ID tenants. Users from one tenant can access shared channels in Teams without being added as guest users. Seamless collaboration with reduced identity sprawl.

Entra ID Protection
Automated risk detection and remediation for identity-based threats. Analyzes sign-in behavior and user activity to detect compromised accounts.
Sign-In Risk
Detects risky sign-in attempts in real time: impossible travel (sign-in from New York then Tokyo within minutes), anonymous IP addresses, unfamiliar sign-in properties, malware-linked IP addresses. Risk levels: low, medium, high.
User Risk
Detects compromised user accounts based on offline analysis: leaked credentials (found on dark web), anomalous user activity patterns. Higher risk than sign-in risk because it indicates persistent compromise.
Risk-Based Policies
Conditional Access policies that respond to risk levels. Low risk: allow with MFA. Medium risk: require password change. High risk: block access. Automated remediation reduces SOC workload.
Slide 10 of 12
Single Sign-On (SSO)
Authenticate once, access all authorized applications. SSO reduces password fatigue, improves security, and streamlines the user experience.
How SSO Works
User signs in to Entra ID once. Entra ID issues a token. When the user accesses another app, the app redirects to Entra ID, which recognizes the existing session and issues a new token without requiring another login.
Supported Protocols
SAML 2.0, OAuth 2.0, OpenID Connect, and WS-Federation. Entra ID can federate with thousands of pre-integrated SaaS applications (Salesforce, ServiceNow, Workday, AWS) in the app gallery.
Security Benefits
Fewer passwords means fewer password-related attacks. Centralized access control through Conditional Access. Centralized audit logging of all application access. Instant revocation when a user is disabled.
Entra Connect
Synchronizes on-premises AD identities to Entra ID. Enables SSO across on-premises and cloud apps. Supports password hash sync, pass-through authentication, or federation with AD FS.
Slide 11 of 12
Entra ID Editions
Four editions with increasing capabilities. Most enterprise security features require P1 or P2 licensing.
Free
Included with Microsoft cloud subscriptions. User and group management, basic SSO, self-service password change, basic security reports. Limited to 500,000 objects.
Microsoft 365 Apps
Included with Microsoft 365 F1/F3/E3/E5. Adds: company branding, group-based access, self-service password reset for cloud users, Microsoft Identity Manager.
P1 (Premium Plan 1)
Adds: Conditional Access, dynamic groups, self-service group management, on-premises write-back, Entra Application Proxy. Required for Conditional Access policies.
P2 (Premium Plan 2)
Adds: Entra ID Protection (risk-based policies), Privileged Identity Management (PIM), access reviews, entitlement management. Required for the most advanced governance features.
