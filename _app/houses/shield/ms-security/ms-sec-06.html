What is KQL?

Kusto Query Language (KQL) is a read-only query language developed by Microsoft for querying large datasets. It powers Azure Data Explorer, Log Analytics, Microsoft Sentinel, Microsoft Defender, and Application Insights. For security analysts, KQL is the language you use to hunt for threats, write analytics rules, build workbook dashboards, and investigate incidents.

KQL is a pipe-based language. You start with a table, then chain operators using the pipe character (|). Each operator transforms or filters the data before passing it to the next. If you have used PowerShell pipelines or Unix pipes, the concept is familiar.

Basic Query Structure

Every KQL query starts with a table name, followed by operators:

Basic query pattern
TableName | where TimeGenerated > ago(24h) | where ColumnName == "value" | project Column1, Column2, Column3 | sort by TimeGenerated desc | take 100
Operator Purpose Example
where Filter rows matching a condition where ResultType != 0
project Select specific columns project TimeGenerated, UserPrincipalName
sort by Order results sort by TimeGenerated desc
take Limit number of results take 50
extend Add a calculated column extend Hour = hourofday(TimeGenerated)
distinct Return unique values distinct UserPrincipalName

String Operators

String matching is fundamental to security queries. KQL provides multiple string operators with case-sensitive and case-insensitive variants:

Operator Behavior Case Sensitive
== Exact match Yes (=~ for case-insensitive)
contains Substring match anywhere No (contains_cs for case-sensitive)
has Full-term match (word boundary) No (has_cs for case-sensitive)
startswith Matches beginning of string No
matches regex Regular expression match Yes
in Matches any value in a list Yes (in~ for case-insensitive)
Performance Tip

Use has instead of contains when possible. has uses the inverted index for fast lookups, while contains performs a full string scan. On large tables, this difference can be 10-100x in query time.

Aggregation with summarize

The summarize operator groups rows and computes aggregate values. It is the KQL equivalent of SQL's GROUP BY.

Count failed sign-ins per user
SigninLogs | where TimeGenerated > ago(24h) | where ResultType != "0" | summarize FailedCount = count() by UserPrincipalName | sort by FailedCount desc | take 20
Failed logins per hour (for timeline charts)
SigninLogs | where TimeGenerated > ago(7d) | where ResultType != "0" | summarize FailedCount = count() by bin(TimeGenerated, 1h) | render timechart

Key aggregation functions:

Function Description
count()Count of rows in each group
dcount(column)Approximate distinct count of values
sum(column)Sum of numeric values
avg(column)Average of numeric values
min() / max()Minimum / maximum value
make_set(column)Array of distinct values (useful for listing all IPs per user)
arg_max(column, *)Row with the maximum value for a column (latest event)
bin(column, interval)Rounds values into time buckets (1h, 1d, 5m)

Joins

Joins combine data from multiple tables. The most common join in security analysis: correlating sign-in events with endpoint events, or enriching alerts with user information.

Join sign-in logs with device process events
SigninLogs | where TimeGenerated > ago(1h) | where RiskLevelDuringSignIn == "high" | project SignInTime = TimeGenerated, UserPrincipalName, IPAddress | join kind=inner ( DeviceProcessEvents | where TimeGenerated > ago(1h) | project ProcessTime = TimeGenerated, AccountName, DeviceName, FileName, ProcessCommandLine ) on $left.UserPrincipalName == $right.AccountName

Common join kinds: inner (only matching rows), leftouter (all left rows, matching right rows), rightouter, fullouter, and anti (left rows with no match -- useful for finding users NOT in a group).

Real Security Queries

Brute-force detection: 10+ failures from one IP in 5 minutes
SigninLogs | where TimeGenerated > ago(1d) | where ResultType == "50126" // Invalid password | summarize FailCount = count(), TargetUsers = make_set(UserPrincipalName), FirstAttempt = min(TimeGenerated), LastAttempt = max(TimeGenerated) by IPAddress, bin(TimeGenerated, 5m) | where FailCount > 10 | sort by FailCount desc
Suspicious process chains: Office app spawning command shell
DeviceProcessEvents | where TimeGenerated > ago(7d) | where InitiatingProcessFileName in~ ("winword.exe", "excel.exe", "powerpnt.exe", "outlook.exe") | where FileName in~ ("cmd.exe", "powershell.exe", "wscript.exe", "mshta.exe") | project TimeGenerated, DeviceName, AccountName, InitiatingProcessFileName, FileName, ProcessCommandLine
New admin role assignments in the last 24 hours
AuditLogs | where TimeGenerated > ago(24h) | where OperationName == "Add member to role" | where Result == "success" | extend TargetUser = tostring(TargetResources[0].userPrincipalName) | extend RoleName = tostring(TargetResources[0].modifiedProperties[1].newValue) | project TimeGenerated, TargetUser, RoleName, InitiatedBy = InitiatedBy.user.userPrincipalName

let Statements and Functions

Use let to define variables and reusable subqueries. This makes complex queries readable and maintainable:

let timeRange = 7d; let threshold = 5; let suspiciousIPs = SigninLogs | where TimeGenerated > ago(timeRange) | where ResultType == "50126" | summarize Failures = count() by IPAddress | where Failures > threshold | project IPAddress; SigninLogs | where TimeGenerated > ago(timeRange) | where ResultType == "0" // Successful logins | where IPAddress in (suspiciousIPs) | project TimeGenerated, UserPrincipalName, IPAddress, AppDisplayName

Key Takeaways

  • KQL is a pipe-based language: start with a table, chain operators with the pipe character
  • Core operators: where (filter), project (select columns), summarize (aggregate), sort by, take
  • Use has instead of contains for better performance on large tables
  • summarize with bin() creates time-series data for charts; render timechart visualizes it
  • Joins correlate data across tables (sign-ins + endpoints, alerts + users)
  • let statements make complex queries readable and define reusable subqueries
