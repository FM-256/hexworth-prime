The Security Stack

Microsoft's security ecosystem is one of the largest in the industry. It spans identity management, endpoint protection, email security, cloud posture, data governance, and security operations. For organizations running Microsoft 365 or Azure, these tools integrate tightly -- meaning a single alert can be correlated across email, identity, endpoint, and cloud layers simultaneously.

Unlike point solutions from multiple vendors, Microsoft's approach is a unified platform where signals from one product feed into others. An email phishing attempt detected by Defender for Office 365 can trigger an identity investigation in Entra ID, which can reveal a compromised endpoint in Defender for Endpoint, all funneled into Sentinel for a single incident timeline.

Core Product Categories

Microsoft Entra ID

Identity and access management. Formerly Azure Active Directory. Manages users, groups, authentication, and conditional access policies. The identity backbone of every Microsoft environment.

Microsoft Defender for Endpoint

Endpoint detection and response (EDR). Monitors devices for threats, provides investigation tools, and enables automated remediation across Windows, macOS, Linux, Android, and iOS.

Microsoft Defender for Office 365

Email and collaboration security. Safe Links, Safe Attachments, anti-phishing, and anti-spam policies. Protects Exchange Online, SharePoint, OneDrive, and Teams.

Microsoft Sentinel

Cloud-native SIEM and SOAR. Collects logs from across the environment, runs analytics rules, generates incidents, and orchestrates automated responses via playbooks.

Microsoft Defender for Cloud

Cloud Security Posture Management (CSPM) and Cloud Workload Protection (CWP). Scores your Azure, AWS, and GCP environments and recommends security improvements.

Microsoft Purview

Data governance and compliance. Sensitivity labels, Data Loss Prevention (DLP), insider risk management, eDiscovery, and audit logs for regulatory compliance.

Microsoft 365 Defender -- The XDR Layer

Microsoft 365 Defender is the Extended Detection and Response (XDR) platform that unifies signals from Defender for Endpoint, Defender for Office 365, Defender for Identity, and Defender for Cloud Apps into a single portal at security.microsoft.com.

XDR differs from SIEM in scope. While Sentinel ingests logs from any source (including third-party), M365 Defender correlates only Microsoft security signals -- but does so with deep integration. An incident in M365 Defender automatically correlates:

Signal Source What It Detects Example
Defender for Endpoint Malware, suspicious processes, lateral movement PowerShell encoded command execution
Defender for Office 365 Phishing, malicious attachments, BEC Credential harvesting URL in email
Defender for Identity Identity attacks, AD reconnaissance Pass-the-hash, DCSync attempts
Defender for Cloud Apps Shadow IT, OAuth abuse, anomalous behavior Impossible travel detection

Where Sentinel Fits

Microsoft Sentinel sits above the XDR layer. It ingests data from M365 Defender, Azure services, on-premises infrastructure, and third-party products (firewalls, Linux servers, AWS CloudTrail, etc.). Sentinel provides:

Data Connectors

Over 100 built-in connectors for Microsoft and third-party sources. Syslog, CEF, REST API, and custom connectors for everything else.

Analytics Rules

Scheduled queries (KQL), Microsoft Security rules, ML-based anomaly detection, and fusion rules that correlate multi-stage attacks.

Incident Management

Grouped alerts with severity, status, ownership, and evidence. The SOC analyst's primary workflow surface.

Playbooks (SOAR)

Logic Apps-based automation. Auto-enrich incidents, isolate machines, disable accounts, or send notifications without human intervention.

Licensing and Portals

Microsoft security products are accessed through several portals. As a SOC analyst, you will primarily work in two:

Portal URL Purpose
Microsoft Defender Portal security.microsoft.com XDR incidents, device inventory, email investigation, hunting
Microsoft Sentinel portal.azure.com (within Azure) SIEM workspace, analytics rules, data connectors, workbooks
Entra Admin Center entra.microsoft.com User/group management, conditional access, sign-in logs
Purview Compliance compliance.microsoft.com DLP policies, sensitivity labels, audit search, eDiscovery
Note on Licensing

Most security features require Microsoft 365 E5 or standalone add-on licenses. Sentinel is billed on data ingestion volume (per GB). In enterprise environments, licensing decisions heavily influence which features are available to SOC teams.

The SOC Analyst's Daily Workflow

A typical day for a Microsoft-stack SOC analyst involves these activities, all of which this course will cover:

Triage and Investigation Flow

1. Review incoming incidents in M365 Defender or Sentinel -- prioritize by severity and affected assets.
2. Investigate the alert evidence: which user, which device, what process or URL triggered it.
3. Query raw logs using KQL to find related events before and after the alert.
4. Determine scope: is this an isolated event or part of a broader attack chain?
5. Take response actions: isolate device, disable account, block URL, or run a playbook.
6. Document findings and close the incident with a classification (true positive, false positive, benign).

Key Takeaways

  • Microsoft's security ecosystem covers identity, endpoint, email, cloud, data, and SIEM/SOAR
  • M365 Defender (XDR) correlates signals across Defender products; Sentinel adds third-party data and automation
  • The primary SOC portals are security.microsoft.com and the Azure-based Sentinel workspace
  • KQL is the query language that powers hunting and analytics across the entire stack
  • This course follows the SC-200 certification path for Security Operations Analysts
