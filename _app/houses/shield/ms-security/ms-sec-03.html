What is Defender for Endpoint?

Microsoft Defender for Endpoint (MDE) is an enterprise endpoint detection and response (EDR) platform. It provides behavioral sensors on devices that collect process execution, network connections, registry changes, file operations, and authentication events. This telemetry is sent to the Microsoft cloud for analysis, where machine learning models and threat intelligence detect malicious activity.

MDE supports Windows 10/11, Windows Server 2012 R2+, macOS, Linux, Android, and iOS. In a typical enterprise, MDE is the primary tool SOC analysts use for endpoint investigations -- answering questions like "What process ran on this machine at 3:47 AM?" or "Did this user execute a suspicious PowerShell script?"

Onboarding Devices

Before MDE can protect a device, it must be onboarded -- the MDE sensor must be installed and configured to report to your tenant. Onboarding methods vary by OS and management infrastructure:

Method Best For How It Works
Microsoft Intune Cloud-managed devices Configuration profile pushes sensor settings; automatic for Intune-enrolled devices
Group Policy Domain-joined Windows devices GPO distributes onboarding script; runs at startup or logon
Local Script Testing, small deployments Download onboarding package from portal, run WindowsDefenderATPLocalOnboardingScript.cmd
SCCM / ConfigMgr On-premises managed environments Package deployed as an application or task sequence
VDI Script Non-persistent virtual desktops Special onboarding for VDI that handles golden image scenarios
Onboarding Verification

After onboarding, run sc query sense on Windows to verify the MDE sensor service is running. The device should appear in the portal's Device Inventory within 5-30 minutes. If it does not, check the MsSense.exe logs in C:\ProgramData\Microsoft\Windows Defender Advanced Threat Protection\Cyber\.

Device Inventory

The Device Inventory in the Microsoft Defender portal shows every onboarded device with its current risk level, exposure level, OS, last seen time, and health state. Each device has a detail page showing:

Overview Tab

Device name, domain, OS version, risk level, exposure score, logged-on users, IP addresses, and group membership. First stop for any device investigation.

Alerts Tab

All alerts associated with this device, sorted by severity. Each alert links to a detailed investigation page with evidence and recommended actions.

Timeline Tab

Chronological event log showing process creation, network connections, file operations, registry modifications, and logon events. The core tool for forensic analysis.

Security Recommendations

Threat and Vulnerability Management (TVM) findings: missing patches, insecure configurations, vulnerable software. Prioritized by exposure impact.

Alert Investigation

When MDE detects suspicious activity, it generates an alert. Alerts are classified by severity (Informational, Low, Medium, High) and by category (Malware, Credential Access, Lateral Movement, etc.). The alert page provides:

Component What It Shows
Alert Story Narrative description of what happened, which MITRE ATT&CK technique was observed, and why it is suspicious
Process Tree Visual tree showing parent-child process relationships. Reveals how a malicious process was spawned (e.g., Word > cmd.exe > PowerShell)
Evidence and Entities Files, processes, IP addresses, URLs, and users involved. Each entity can be investigated further or submitted for deep analysis
Investigation Graph Visual node map connecting the alert to related entities across devices and users. Shows attack scope at a glance

A common investigation pattern: a High-severity alert fires for "Suspicious PowerShell command line." The analyst opens the alert, checks the process tree to see that outlook.exe spawned cmd.exe which launched powershell.exe -enc [Base64]. This parent-child chain (email client spawning command shell) is a textbook indicator of a phishing payload executing on the endpoint.

Response Actions

MDE provides multiple response actions that SOC analysts can execute directly from the portal. These range from information gathering to full device isolation:

Isolate Device

Cuts all network connections except to the MDE cloud service. The device remains manageable but cannot communicate with any other host. Use for confirmed compromises to prevent lateral movement.

Collect Investigation Package

Gathers forensic artifacts: running processes, network connections, scheduled tasks, services, event logs, autorun entries. Downloaded as a ZIP for offline analysis.

Run Antivirus Scan

Triggers a Microsoft Defender Antivirus quick or full scan remotely. Results appear in the device timeline. Useful when you suspect malware but have not confirmed the file.

Restrict App Execution

Only allows Microsoft-signed binaries to run. Locks down the device to prevent any further malicious execution while investigation continues.

Live Response

Remote shell session to the device. Run commands, collect files, upload remediation scripts. Requires specific RBAC permissions. Think of it as SSH to a managed endpoint.

Automated Investigation

MDE can automatically investigate alerts, analyze evidence, and take remediation actions (quarantine files, stop processes). Automation levels range from "No automation" to "Full" (auto-remediate all threats).

Advanced Hunting

Advanced Hunting in MDE lets analysts write KQL queries against raw endpoint telemetry tables. This is where proactive threat hunting happens -- searching for indicators that automated rules might miss.

// Find PowerShell executions with encoded commands in the last 7 days DeviceProcessEvents | where Timestamp > ago(7d) | where FileName == "powershell.exe" | where ProcessCommandLine contains "-enc" or ProcessCommandLine contains "-EncodedCommand" | project Timestamp, DeviceName, AccountName, InitiatingProcessFileName, ProcessCommandLine | order by Timestamp desc

Key tables available in Advanced Hunting include DeviceProcessEvents, DeviceNetworkEvents, DeviceFileEvents, DeviceRegistryEvents, DeviceLogonEvents, and DeviceImageLoadEvents. Module 6 covers KQL syntax in detail.

Key Takeaways

  • MDE is an EDR platform that monitors processes, network, files, and registry on enrolled devices
  • Devices must be onboarded via Intune, Group Policy, SCCM, or local script before telemetry flows
  • The process tree is the most important investigation tool -- it reveals parent-child execution chains
  • Response actions range from isolation (stop lateral movement) to Live Response (remote shell access)
  • Advanced Hunting provides KQL access to raw endpoint telemetry for proactive threat hunting
