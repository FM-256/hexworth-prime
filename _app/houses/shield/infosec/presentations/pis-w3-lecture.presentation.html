Slide 3 of 19  |  Topic 1: Network Architecture
The Network Is Not a Perimeter
The perimeter model assumes: everything outside is hostile, everything inside is trusted. Both assumptions have been false for decades.
The architectural shift that Week 3 is built on
Zero trust is not a product. It is an architectural principle: every access request is evaluated regardless of where it originates. NIST SP 800-207 (Zero Trust Architecture) defines the seven tenets in §2.1. The practical question is always: what is the smallest unit of access that accomplishes the task? That answer drives segmentation, firewall rules, VPN scope, and every other decision in this week.
Slide 4 of 19
Firewall Decision Logic
A firewall is a policy enforcement point. What makes it useful is not what it blocks — it is what the rules say and in what order they are evaluated.
Packet Filter (L3/L4)
Evaluates IP address, port, and protocol. Fast. Stateless. Cannot see session state. Easily bypassed by fragmentation and spoofed source addresses. Generation one — still in every router.
Stateful Inspection
Tracks connection state. Knows whether a packet belongs to an established session. Blocks unsolicited inbound packets even on allowed ports. Standard in all modern firewalls (iptables, Windows Firewall, ASA).
Next-Generation (NGFW)
Adds application identification, SSL/TLS inspection, user identity, and threat intelligence feeds. Operates at L7. Can block Dropbox uploads while allowing Dropbox downloads on the same TCP/443 flow.
The rule that decides everything
Firewall rules are evaluated top-down, first match wins. An overly permissive rule at position 1 renders every rule below it irrelevant for that traffic class. The correct default-deny design places the explicit-deny any/any at the bottom as a catch-all, never at the top. The implicit deny is enforced by the platform when no rule matches; the explicit deny gives you a log entry.
Slide 5 of 19
The DMZ and Network Segmentation
Segmentation is damage limitation. An adversary who breaches the web server should reach the web server — nothing else.
DMZ Principle
Public-facing services live in a network zone where inbound internet traffic is permitted but outbound access to internal networks is blocked. Compromise the web server: reach the web server zone, nothing behind FW-2.
VLAN Segmentation
Logical separation within the internal network. Workstations, servers, printers, and IoT on separate VLANs with inter-VLAN routing controlled by ACLs. Lateral movement requires crossing a controlled boundary at each step.
Slide 6 of 19
VPN vs. Zero Trust Network Access
VPN solved remote access for a perimeter model. ZTNA solves remote access when there is no perimeter. They answer different threat models.
VPN (Traditional)
Model: authenticated tunnel to the network edge. Result: once connected, user has network-level access to everything the network reaches. Risk: credential compromise = full internal network access. Lateral movement is trivial from a VPN-connected compromised host. Protocol: IPSec (IKEv2) or SSL/TLS VPN.
ZTNA (Zero Trust Network Access)
Model: per-application proxy. Identity + device posture evaluated per request. Result: authenticated user accesses the specific application, not the network. Risk: credential compromise = access to that application only. No network-level visibility. Example: Cloudflare Access, Zscaler ZPA, Google BeyondCorp.
The architectural question for every organization
VPN + MFA is not the same as zero trust, but it is far cheaper to deploy today. The transition from VPN to ZTNA is a 2-5 year architecture shift, not a product swap. For the exam: know that ZTNA enforces least-privilege at the application layer, while VPN enforces it (imperfectly) at the network layer. The blast radius of a VPN breach is the network; the blast radius of a ZTNA breach is one application.

Wireless Security: WPA3 and the Authentication Stack
WPA3 fixed the two structural failures of WPA2: offline dictionary attacks against the 4-way handshake, and forward secrecy.
WPA2 Weakness
The 4-way handshake can be captured passively. An attacker with a capture can run an offline dictionary attack at GPU speed with no network interaction. KRACK (2017) demonstrated key reinstallation against the WPA2 handshake across all implementations.
WPA3: SAE Handshake
Simultaneous Authentication of Equals (SAE) replaces the pre-shared key exchange with a Dragonfly key exchange derived from IEEE 802.11-2016. Each session negotiates a fresh key. A captured handshake cannot be dictionary-attacked offline. Forward secrecy is structural.
802.1X / RADIUS for Enterprise
Pre-shared keys do not scale to enterprise. 802.1X + RADIUS separates authentication (who is this user?) from the access point. EAP-TLS issues per-user certificates; EAP-PEAP wraps MSCHAPv2 in a TLS tunnel. Revoke a user in AD, revoke their wireless access.
A hospital deploys WPA2-Personal with a shared passphrase across all 300 APs. A departing employee knows the key. The hospital has no revocation mechanism — the key must be rotated on every AP and every device simultaneously. 802.1X + RADIUS eliminates this problem: disable the user account, access stops immediately.
Slide 8 of 19
Cloud: Shared Responsibility
The cloud provider secures the infrastructure. You secure what you put on it. The line shifts based on the service model. Misunderstanding the line is how buckets get exposed.
The gap that produces most cloud breaches
The provider secures the infrastructure. You configure what runs on it. The Capital One breach (2019) was a misconfigured WAF and an over-permissive EC2 role — the AWS infrastructure was fully intact. The attacker lived entirely in the customer zone. Knowing where your responsibility begins and ends is the first cloud security control.
Slide 9 of 19  |  Topic 3: PKI
Why PKI Exists
Asymmetric cryptography solves encryption. PKI solves the question that asymmetric cryptography creates: how do you know whose public key you are actually holding?
The Problem Without PKI
Alice wants to send an encrypted message to Bob. She needs Bob's public key. How does she know the public key she downloaded is actually Bob's and not an attacker performing a man-in-the-middle? Without a trusted third party, there is no answer. This is the key distribution problem.
PKI's Answer
A Certificate Authority (CA) vouches for the binding: "this public key belongs to this entity, verified as of this date, until this expiry." The vouching is a digital signature on an X.509 certificate. If you trust the CA, you trust all bindings the CA has signed. The trust is transitive.
Why the root CA is kept offline
If an attacker compromises the root CA's private key, they can sign certificates for any domain and be trusted by every browser. The root CA is therefore kept air-gapped. It signs only intermediate CA certificates. If an intermediate is compromised, it is revoked. The root CA trust anchor remains intact.
Slide 10 of 19
Certificate Lifecycle and Revocation
A certificate has a beginning, an end, and an emergency exit. The emergency exit is revocation. Knowing when revocation fails is critical for incident response.
Issuance: CSR Flow
  1. Generate RSA/EC key pair on the server.
  2. Send Certificate Signing Request (CSR) — contains public key + entity info — to the CA.
  3. CA validates domain control (DV), organization (OV), or extended validation (EV).
  4. CA issues signed X.509 cert.
Private key never leaves the server.
Revocation: CRL vs OCSP
CRL (Certificate Revocation List): a signed list of serial numbers the CA has revoked. Downloaded periodically — can be hours stale. OCSP (Online Certificate Status Protocol): a real-time query to the CA's responder. OCSP Stapling: the server caches the OCSP response and includes it in the TLS handshake, eliminating the OCSP privacy leak and latency.
Revocation Failure Modes
Browsers soft-fail OCSP by default (if the responder is unreachable, the cert is accepted). Most browsers have abandoned real-time OCSP for CRLite / pre-loaded revocation sets. The gap between compromise and revocation propagation is an exposure window an attacker can exploit.
DigiNotar (2011): a Dutch CA was compromised. Attackers issued fraudulent certificates for google.com, *.google.com, and other high-value domains. Google discovered the certificates through Certificate Transparency logs. DigiNotar's root was removed from all major trust stores within days — an unprecedented industry response that effectively ended the CA as a business. Source: ENISA — Operation Black Tulip (Certificate Authorities lose authority), 2011.
Slide 11 of 19  |  Topic 4: Security Operations
SIEM: Correlation at Scale
A SIEM does not detect threats. It collects evidence across data sources and lets you write rules that identify threat patterns across that evidence.
Normalization is the hard part
Firewall logs use different timestamp formats, field names, and severity scales than DNS logs, than endpoint EDR, than cloud APIs. Before correlation is possible, every source must be parsed into a common schema (e.g., CEF, ECS). Parsing failures are silent — the event simply never gets ingested.
Detection-to-Response gap
A SIEM generates alerts. An analyst has to triage, investigate, and respond. The gap between an alert firing and a containment action is where the breach expands. SOAR (Security Orchestration, Automation, and Response) automates tier-1 responses — isolate host, disable account, block IP — in seconds instead of hours.
Slide 12 of 19
IDS vs. IPS: Detection vs. Prevention
IDS watches and reports. IPS watches and acts. The tradeoff is false positive risk: a misconfigured IPS blocks legitimate traffic; a misconfigured IDS only misses threats.
IDS (Intrusion Detection System)
Mode: passive. Traffic is mirrored (SPAN port) to the IDS sensor. Detects and alerts. Does not interrupt traffic. A false positive produces a false alert. Network impact: zero. Deployment: low-risk; good for initial calibration and visibility in sensitive environments.
IPS (Intrusion Prevention System)
Mode: inline. Sits in the traffic path. Can block, drop, or reset connections. A false positive drops legitimate traffic. Network impact: adds latency; becomes a single point of failure if it fails closed. Deployment: requires tuned signature confidence before going inline.
Signature-Based Detection
Matches traffic against known attack patterns. Fast. Accurate for known threats. Blind to zero-days and obfuscated variants. Must be kept current — a signature set that is 30 days stale misses any CVE published in those 30 days.
Anomaly-Based Detection
Establishes a behavioral baseline; alerts on deviations. Can detect novel attacks. Produces far more false positives during normal operational variability (backups, patch cycles, end-of-quarter traffic spikes). Useful as a signal source, not a sole detection mechanism.
For the analyst: placement matters as much as mode
Network IDS/IPS at the perimeter misses encrypted lateral movement inside the network. Host-based IDS (HIDS) catches it, but at the cost of per-endpoint overhead. Modern EDR subsumes most HIDS functions while adding memory inspection, process telemetry, and automated containment. NIST SP 800-94 (February 2007) provides the foundational reference on IDS/IPS deployment; it remains the only published NIST IDS/IPS guidance, though dated.
Slide 13 of 19
Vulnerability Management: Not Patching, Managing
Vulnerability management is the continuous process of identifying, classifying, prioritizing, and remediating weaknesses before an attacker exploits them.
Discovery: Scan Scope
Authenticated scans (credentialed) find more than unauthenticated scans. Unauthenticated sees what an external attacker sees. Authenticated sees what the OS-level configuration actually exposes. Tools: Nessus Professional, Qualys VMDR, Rapid7 InsightVM. NIST recommends authenticated (credentialed) scanning per SP 800-40 Rev. 4 (April 2022).
Prioritization: CVSS + Context
CVSS 3.1 scores a vulnerability on a 0-10 scale across base, temporal, and environmental vectors. A CVSS 9.8 on an air-gapped system is lower priority than a CVSS 7.0 on your public-facing authentication endpoint. Context: exposure + exploitability in your environment > raw CVSS score.
Remediation: Patch, Compensate, Accept
Not every vulnerability can be patched immediately. A legacy ICS controller with no patch available requires a compensating control (network isolation, allowlisting). Risk acceptance must be documented and time-bounded. Unpatched critical CVEs with no compensating control and no documented acceptance are an audit failure.
CISA KEV: the prioritization shortcut
CISA's Known Exploited Vulnerabilities catalog lists CVEs where active exploitation has been observed. Federal agencies are required to patch KEV entries within defined windows (CISA BOD 22-01: 6 months for pre-2021 CVEs, 2 weeks for post-2020 CVEs). In practice, any CVE in the KEV catalog with an asset in your environment is your highest patch priority, regardless of CVSS score.
Slide 14 of 19
Threat Hunting
Threat hunting assumes the adversary is already inside. It is the proactive search for evidence of compromise that automated detection has not flagged.
Hypothesis-Driven
A hunt starts with a hypothesis: "An attacker with domain admin credentials would use LSASS memory dumping before lateral movement." The hunter then queries telemetry for the specific behavior — not an alert, a deliberate search. MITRE ATT&CK T1003.001 is the TTP reference for LSASS memory dumping.
IOC vs. TTP
IOC (Indicator of Compromise): an IP, domain, hash — point-in-time and easily rotated by the attacker. TTP (Technique, Tactic, Procedure): behavioral patterns like "scheduled task for persistence" or "living off the land with certutil." Hunting for TTPs catches adversaries who have rotated their IOCs.
Data Sources
Process creation logs (Sysmon Event ID 1), network connections (Event ID 3), PowerShell script block logging, DNS query logs, EDR telemetry. A hunt is only as good as the data available. Gaps in logging = gaps in hunt coverage.
SolarWinds (2020): the SUNBURST backdoor was present in production environments for 8-14 months before detection. Automated detection missed it because the malware mimicked legitimate SolarWinds behavior. Manual threat hunting through network traffic eventually surfaced anomalous beacon patterns. The lesson: if an adversary is patient enough, they will evade signature-based detection indefinitely.
Slide 15 of 19  |  Synthesis
How the Four Domains Connect
These are not four separate topics. They are four layers of a single defensive architecture. A gap in any one layer propagates to all the others.
Architecture Fails → SecOps is Your Last Line
A misconfigured firewall, an exposed S3 bucket, or a revoked certificate that clients still trust are architectural failures. When they happen, SIEM alerts and threat hunting are the only path to detection before the attacker achieves their objective.
SecOps Fails → Architecture Buys Time
A SIEM that is misconfigured or under-resourced will miss events. But an attacker who compromises one VLAN and cannot reach the database tier is still contained. Defense in depth means each layer independently limits damage.
Slide 16 of 19  |  Exam Anchor
Week 3 Decision Framework
SY0-701 performance-based questions test decisions, not definitions. For every Week 3 scenario, run this chain.
Scenario: Network Control Selection
Q1: Is this about restricting traffic between zones? → Firewall + VLAN/ACL.
Q2: Is this about authenticating remote users with least privilege? → ZTNA over VPN.
Q3: Is this about hiding internal IP structure from the internet? → NAT.
Q4: Do you need connection state awareness? → Stateful, not packet filter.
Scenario: Certificate or PKI Problem
Q1: Browser says "certificate not trusted." → Missing intermediate CA, or root CA not in trust store.
Q2: Certificate was valid, then compromised. → Revoke via CRL/OCSP; propagation delay is the exposure window.
Q3: Two systems need to authenticate each other. → Mutual TLS (mTLS), both present certificates.
Q4: Certificate for wildcard *.example.com → covers all subdomains, not sub-subdomains.
Scenario: Wireless Selection
Personal (home): WPA3-Personal (SAE). Enterprise (>10 users): WPA3-Enterprise + 802.1X + RADIUS. Rogue AP detected: WIPS is the automated response; port security or NAC to prevent connection. Evil twin attack: 802.1X with EAP-TLS (certificate-based) is resistant; PEAP/MSCHAPv2 is not.
Scenario: SecOps Tool Selection
Need centralized log correlation: SIEM.
Need to automate tier-1 response: SOAR.
Need real-time traffic blocking in-path: IPS.
Need endpoint memory & process telemetry: EDR.
Need to find attacker already inside: Threat hunting.
Need to assess patch exposure across 10,000 hosts: Vulnerability scanner.

In-Class Task: Containment Architecture Review
You have read the four domains. Now apply them. This 35-minute structured activity builds the reasoning pattern the exam tests.
Scenario brief
MedCore Regional Medical Center is deploying a new EHR (Electronic Health Record) system. The system has three tiers: a web front-end (patient portal), an application server, and a database. MedCore also runs a guest Wi-Fi network for patients and visitors. The CISO has asked your team to design the network architecture and security controls for this deployment.
Task 1 (10 min): Architecture
Draw the network segmentation. Identify which zones each tier lives in, what controls sit between zones, and how remote clinical staff connect. Use DMZ, VLAN, and firewall concepts from the lecture.
Task 2 (10 min): Wireless + PKI
Specify the wireless authentication method for clinical staff vs. patient Wi-Fi. Describe what certificates are needed, who issues them, and how revocation works when a staff member leaves.
Task 3 (10 min): SecOps
Identify three log sources you would ingest into SIEM, one SIEM correlation rule you would write for this environment, and the first automated response action your SOAR should take when the rule fires.
