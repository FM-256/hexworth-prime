Network Attack Taxonomy
Network attacks target the infrastructure that carries data, not the applications running on it. Different layer, different defenses.
Availability Attacks
Deny legitimate users access to resources by exhausting bandwidth, connection tables, CPU, or memory. DoS and DDoS are the primary classes. No data theft or manipulation -- the goal is to make the service unreachable. Financial damage from downtime is the weapon.
Interception Attacks
Position the attacker in the path of network traffic to eavesdrop, capture credentials, or modify data in transit. Man-in-the-middle, ARP spoofing, and DNS poisoning all establish a covert interception position. The victim believes they are communicating directly with the intended endpoint.
Replay and Injection Attacks
Captured network traffic is replayed or forged to impersonate legitimate parties. Session hijacking uses captured tokens. Replay attacks reuse valid authentication exchanges. These attacks exploit the trust relationship between endpoints established by prior legitimate communication.
OSI Layer Context
ARP attacks: Layer 2 (Data Link). IP spoofing: Layer 3 (Network). TCP session hijacking: Layer 4 (Transport). DNS attacks: Layer 7 (Application), but affect all layers above them. Understanding which layer is targeted determines which controls can mitigate the attack and at which point in the network stack those controls must be deployed.

Denial of Service Overview
A DoS attack makes a resource unavailable to its intended users. A single source distinguishes DoS from DDoS.
Volumetric Attacks
Flood the target's bandwidth or connection capacity with traffic. ICMP flood, UDP flood, SYN flood. The target becomes unreachable because its upstream link is saturated or its connection state table is exhausted. The attacker's goal is not to crash the server but to consume the resource that serves legitimate traffic.
Protocol Exploitation
Abuse a specific protocol's behavior to cause disproportionate resource consumption. Ping of Death sends oversized ICMP packets that crash the target on reassembly. Smurf attack sends ICMP echo requests to a broadcast address with the victim's spoofed source IP -- every host replies to the victim. Teardrop: overlapping IP fragment offsets crash the reassembly engine.
Application Layer (Layer 7) DoS
Exploit expensive server-side operations with minimal bandwidth. HTTP Slowloris opens many connections and sends headers slowly, holding connections open and exhausting the web server's thread pool. Slow POST sends POST data one byte at a time. Hash collision attacks cause worst-case CPU in web framework request parsers. Hard to distinguish from legitimate slow clients.

SYN Flood Mechanics
The SYN flood exploits the TCP three-way handshake by sending SYN packets without completing the connection.
-- TCP Three-Way Handshake (normal) Client --SYN---> Server (allocates state, waits) Client <---SYN-ACK-- Server Client --ACK---> Server (connection established) -- SYN Flood (attack) Attacker --SYN (spoofed src)--> Server (allocates state, waits) Server --SYN-ACK-----------> [spoofed IP -- no one there] Server waits for ACK (timeout ~75s) Repeat 10,000x: connection table is full, legitimate SYNs dropped
SYN Cookies
The server encodes the connection state into a cryptographic value in the SYN-ACK's sequence number instead of allocating a state table entry. State is only allocated when the client's ACK arrives carrying the correct cookie value. Half-open connections consume no server memory. Enabled by default on modern Linux kernels.
Rate Limiting and Firewall Rules
Limit SYN packets per source IP per second. Block traffic from known spoofed source ranges (BCP 38 -- ingress filtering). Stateful firewalls that track connection state can detect and drop packets outside of valid session flow. Rate limiting at the upstream ISP level is more effective than at the target because bandwidth is consumed before reaching the target.
Upstream ISP Mitigation
The most effective SYN flood mitigation happens before traffic reaches the target's network. ISPs and CDN providers implement traffic scrubbing -- directing traffic through DDoS mitigation infrastructure that filters attack traffic before forwarding legitimate traffic. Requires upstream provider cooperation or a managed DDoS protection service.

Distributed Denial of Service (DDoS)
Coordinated attack from thousands to millions of sources. Volumetric attacks measured in Tbps are not theoretical -- they have occurred.
The facility's external communications relay is receiving 840 Gbps of UDP traffic from 183,000 distinct source IP addresses across 47 countries. The upstream ISP's 10 Gbps link is saturated. The facility has been effectively isolated from the outside network. This is a botnet-coordinated volumetric DDoS -- the scale exceeds any single organization's capacity to absorb.
Botnets as DDoS Infrastructure
Thousands of compromised hosts (IoT devices, servers, desktop computers) are coordinated by a command-and-control server. When directed, all bots simultaneously flood the target. The distributed nature makes IP-based blocking ineffective -- the attacker has more sources than the target can block. Mirai botnet demonstrated that IoT devices make reliable DDoS nodes.
Amplification DDoS
The attacker sends small requests to reflectors with the victim's spoofed source IP. Reflectors send large responses to the victim. DNS amplification: 64-byte ANY query gets a 3,000-byte response (47x amplification). NTP monlist: 234x amplification. Memcached UDP: up to 50,000x amplification. The attacker needs minimal bandwidth to generate massive attack traffic.
DDoS Mitigation Services
Anycast diffusion (Cloudflare, Akamai) distributes attack traffic across global edge nodes -- no single point absorbs the full volume. Traffic scrubbing centers filter malicious packets before forwarding clean traffic. BGP blackhole routing discards all traffic to the attacked IP (availability sacrificed to protect the rest of the infrastructure).
Rate Limiting and CAPTCHAs
Application-layer DDoS can be partially mitigated by rate limiting per IP, connection limits, CAPTCHA challenges for new connections, and behavioral analysis that distinguishes automated from human traffic. Effective against scripted attacks; ineffective against large botnets where the attack rate per IP stays below detection thresholds.

Man-in-the-Middle Overview
The attacker secretly relays and potentially modifies communications between two parties who believe they are communicating directly.
Researcher R-88 connects to the facility portal. Unbeknownst to R-88, all traffic is passing through a compromised network switch. The attacker in the middle decrypts the TLS session (via a spoofed certificate accepted by the researcher's browser), reads all transmitted data, re-encrypts it with the real portal's certificate, and forwards it. R-88 sees a normal session. The attacker reads every keystroke.
Passive MITM (Eavesdropping)
The attacker captures traffic without modifying it. The communication proceeds normally; neither party is aware of the interception. Packet capture on a shared network segment, compromised router with traffic mirroring, or tapping physical media. Targets unencrypted protocols (HTTP, FTP, Telnet, SMTP without TLS) to capture credentials and data in plaintext.
Active MITM (Manipulation)
The attacker intercepts and modifies data in transit. Injecting malicious content into HTTP responses, altering financial transaction amounts, modifying email content, stripping encryption downgrades (SSL stripping). Active MITM requires the attacker to be in the traffic path and to handle the relay in real time -- more complex but more damaging than passive eavesdropping.
How Attackers Get In the Path
ARP spoofing (poisons Layer 2 to redirect traffic through attacker). DNS poisoning (redirects hostname resolution to attacker-controlled IP). Rogue Wi-Fi access point (victim connects to attacker's network directly). BGP hijacking (at ISP scale, redirects entire network prefixes). Compromised router or switch (insider threat or remote exploit). Each establishes a different interception point.

ARP Spoofing (ARP Poisoning)
The attacker sends forged ARP replies to poison the ARP cache of victims, redirecting Layer 2 traffic through the attacker's machine.
-- Normal ARP resolution Host A broadcasts: "Who has 10.0.0.1? Tell 10.0.0.5" Gateway replies: "10.0.0.1 is at AA:BB:CC:DD:EE:FF" Host A caches: 10.0.0.1 --> AA:BB:CC:DD:EE:FF -- ARP Spoofing attack (attacker MAC: 11:22:33:44:55:66) Attacker sends unsolicited ARP reply to Host A: "10.0.0.1 is at 11:22:33:44:55:66" (attacker's MAC) Attacker sends unsolicited ARP reply to Gateway: "10.0.0.5 is at 11:22:33:44:55:66" (attacker's MAC) -- All traffic between Host A and Gateway now flows through attacker
Dynamic ARP Inspection (DAI)
Managed switches validate ARP packets against a DHCP snooping binding table. Only ARP replies matching known IP-to-MAC mappings are forwarded. Gratuitous ARP replies from untrusted ports are dropped. DAI is a Layer 2 switch feature -- it requires managed switches and must be configured per VLAN. Eliminates ARP spoofing from the local segment.
Static ARP Entries
Manually configure static ARP entries for critical hosts (gateways, DNS servers, domain controllers). Static entries cannot be overwritten by spoofed ARP replies. Practical only for a small number of high-value hosts -- maintaining static entries for an entire network is operationally impractical. Supplement with DAI, not a replacement.
Slide 8 of 35
DNS Poisoning (Cache Poisoning)
The attacker corrupts a DNS resolver's cache to map legitimate hostnames to attacker-controlled IP addresses.
A researcher queries portal.cdc-facility.int. The internal DNS resolver has been poisoned -- it returns 203.0.113.50, the attacker's server. The researcher's browser connects to the attacker's server, which presents a cloned portal login page. Credentials submitted. The attacker captures them and redirects the researcher to the real portal. The researcher notices nothing unusual.
Kaminsky Attack Mechanics
The attacker sends a flood of DNS queries to a resolver for a subdomain it does not cache (e.g., random.target.com). Simultaneously, the attacker sends forged DNS responses claiming authority over target.com, each with a different Transaction ID. When the attacker guesses the correct Transaction ID before the legitimate response arrives, the poison entry is accepted into the cache.
DNSSEC
DNS Security Extensions cryptographically sign DNS records using public-key cryptography. Resolvers verify the signature before accepting a record. A forged response cannot produce a valid signature. DNSSEC breaks the Kaminsky attack entirely for signed zones. Adoption is incomplete -- many zones remain unsigned, leaving them vulnerable.
DNS over HTTPS (DoH) and DNS over TLS (DoT)
Encrypt DNS queries in transit, preventing eavesdropping and in-path modification of DNS responses. DoH uses port 443 (indistinguishable from HTTPS traffic). DoT uses port 853. Neither prevents cache poisoning at the resolver itself -- they protect the query-to-resolver channel but not the resolver's cache integrity (DNSSEC does that).
DNS Hijacking vs. Cache Poisoning
Cache poisoning: attacker corrupts the resolver's cache by winning a race. DNS hijacking: attacker compromises the authoritative DNS server or the domain registrar account, changing the legitimate record at the source. Hijacking produces a different record at every resolver worldwide. Both result in victims connecting to attacker-controlled addresses, but the attack vectors are completely different.

SSL Stripping and TLS Downgrade
The MITM attacker intercepts the initial HTTP request and prevents the upgrade to HTTPS, keeping the victim on an unencrypted channel.
-- Normal HTTPS upgrade flow (no MITM) Browser --HTTP GET http://portal.example.com/--> Server Server --301 Redirect to https://... -----------> Browser Browser --HTTPS GET https://... -----------------> Server -- SSL Stripping (attacker in path) Browser --HTTP GET --> Attacker --HTTPS GET --> Server Server --HTTPS resp-> Attacker --HTTP resp --> Browser -- Browser sees HTTP; all data transmitted in plaintext to attacker
HTTP Strict Transport Security (HSTS)
Server sends: Strict-Transport-Security: max-age=31536000; includeSubDomains. The browser remembers this for the specified duration and refuses to connect via HTTP for that domain. Even if the attacker attempts SSL stripping, the browser will not send the initial HTTP request -- it upgrades internally. Requires the user to have visited the site at least once over HTTPS first (HSTS preloading solves this).
HSTS Preloading
Domains submitted to the HSTS preload list are hardcoded into Chrome, Firefox, Safari, and Edge as HTTPS-only. The first-visit vulnerability is eliminated -- even a brand new browser will refuse HTTP connections to preloaded domains. Submission requires HSTS with max-age of at least one year and includeSubDomains directive. Changes are permanent and difficult to reverse.
TLS Downgrade Attacks
Some servers support legacy TLS versions (1.0, 1.1) and weak cipher suites for compatibility. A MITM attacker manipulates the TLS handshake to force use of a weak cipher (POODLE, BEAST, DROWN). The attacker then exploits the weak cipher to decrypt traffic. Mitigation: disable TLS 1.0/1.1, disable export-grade ciphers, use TLS 1.2+ with strong cipher suites only.

Replay Attacks
The attacker captures a valid authentication or authorization exchange and retransmits it to impersonate the legitimate party.
Authentication Replay
A valid authentication token, session cookie, or Kerberos ticket is captured from network traffic. The attacker retransmits it to the same server. If the server accepts the replayed credential without checking its freshness or binding, the attacker gains authenticated access without knowing the underlying password. Pass-the-hash and pass-the-ticket are Windows-specific replay variants.
Transaction Replay
A valid financial transaction, API call, or command is captured and retransmitted. If the server processes it again, the attacker can duplicate a transfer, re-execute a command, or replay a vote. Must be defended independently of channel encryption -- TLS protects the data in transit, but a captured and replayed TLS-protected message is still dangerous after session capture.
Nonces (Number Used Once)
A unique random value included in the authentication exchange. The server remembers recently used nonces and rejects any replay of a message with a previously seen nonce. Nonces expire after a short window. Challenge-response protocols (like Kerberos ticket granting) use nonces to prevent replay. TLS session IDs and sequence numbers provide similar protection at the transport layer.
Timestamps and Short Validity Windows
Authentication tokens include a timestamp. The server rejects tokens older than a defined window (commonly 5 minutes). Kerberos enforces this -- clock skew of more than 5 minutes between client and KDC causes authentication failure. NTP synchronization is not optional in Kerberos environments; clock drift enables replay attacks by extending the valid window.

Network-Layer Session Hijacking
TCP sessions are identified by a four-tuple. An attacker who can predict or capture the sequence number can inject packets into an existing session.
-- TCP Session Identified By: Source IP:Port <--> Destination IP:Port + Sequence Number -- Session Hijacking: attacker forges a packet with correct seq# Attacker crafts: src=Client_IP:Port, dst=Server_IP:Port seq=next_expected_seq_num (guessed or sniffed) Server accepts packet as if from Client -- injects arbitrary data -- BGP Hijacking: route prefix announced by attacker Attacker AS announces 10.0.0.0/8 more specifically than legitimate AS Routers prefer more-specific route -- traffic redirected to attacker
TCP Sequence Prediction
Early TCP implementations used predictable sequence numbers (sequential or time-based). Modern OSes use cryptographically random initial sequence numbers. Sequence prediction against modern systems requires packet capture (MITM) to observe the current sequence state. Encrypted sessions (TLS) prevent sequence injection because the payload would fail decryption even with a valid sequence number.
BGP Hijacking
An autonomous system announces a more-specific prefix for IP address space it does not legitimately own. Other routers, following longest-prefix-match, route traffic to the announcing AS instead of the legitimate one. The attacker becomes a MITM at internet scale. BGPSec and route origin authorization (ROA) via RPKI provide cryptographic verification of route announcements.
Defense: Encryption at All Layers
TLS over TCP makes session hijacking at the transport layer ineffective -- injected plaintext packets fail MAC verification and are discarded. IPsec in tunnel mode encrypts and authenticates all IP traffic, preventing IP-layer hijacking. End-to-end encryption eliminates the value of network-layer session capture regardless of how the interception was established.

Amplification Attacks
The attacker exploits services that return large responses to small requests, using IP spoofing to direct the amplified traffic at the victim.
DNS Amplification
Send a DNS ANY query (64 bytes) to an open resolver with the victim's spoofed source IP. The resolver returns a full response (up to 3,000 bytes) to the victim -- a 47x amplification factor. With 10,000 queries per second and 47x amplification, 10 Mbps of attacker bandwidth generates 470 Mbps of attack traffic against the victim. Open resolvers are the attack infrastructure.
NTP Amplification (Monlist)
NTP monlist command returns the last 600 hosts that queried the NTP server. A 46-byte request gets a response of up to 480 bytes -- 556-byte UDP packets repeated across multiple responses. Amplification factor up to 206x. The monlist command has been disabled in modern NTP implementations (ntpd 4.2.7p26+). Legacy devices remain vulnerable.
Memcached Amplification
Memcached exposed on UDP port 11211 responds to a 15-byte request with responses up to 1 MB. Amplification factor exceeds 50,000x in worst cases. Cloudflare documented an 1.3 Tbps attack using Memcached amplification in 2018. Defense: never expose Memcached on UDP externally. Firewall UDP/11211 at the network perimeter. Disable UDP support in Memcached configuration.
Defense Against Amplification
BCP 38 (ingress filtering): ISPs filter packets with source IPs that cannot legitimately originate from that network. Eliminates IP spoofing, which is the prerequisite for all amplification attacks. Disable services that provide large responses to unauthenticated UDP requests (restrict DNS recursion to authorized clients, disable NTP monlist, block Memcached UDP from internet). Reducing reflector availability is as important as protecting victims.
Slide 13 of 35
IP Spoofing and Source Forgery
Forging the source IP address in IP packets to impersonate other hosts, evade filtering, or redirect responses.
What IP Spoofing Enables
Reflection and amplification attacks (responses go to victim). Bypassing IP-based access controls. Disguising attack origin in logs (though traffic returns to real attacker IP, not spoofed). Session injection when combined with sequence prediction. Land attack: source and destination set to same IP, crashing some TCP stacks. IP spoofing is a prerequisite for most volumetric DDoS techniques.
BCP 38 / RFC 2827 -- Network Ingress Filtering
ISPs and network operators implement ingress filtering: discard packets arriving from a customer interface with a source address not belonging to that customer's allocated range. If every ISP implemented BCP 38, IP spoofing from customer networks would be impossible. Adoption is voluntary -- significant portions of the internet still do not implement BCP 38, which is why spoofed-source DDoS remains viable.
uRPF -- Unicast Reverse Path Forwarding
The router checks whether the source IP of an incoming packet would be reachable via the interface it arrived on. If the routing table says traffic to that source would exit a different interface, the packet is dropped as likely spoofed. Loose mode checks if the source is reachable via any interface. Strict mode (preferred) checks the exact interface. Deployed at network edges to prevent spoofing.

Wireless Network Attacks
Wi-Fi's broadcast medium and authentication protocols create unique attack surfaces not present on wired networks.
Evil Twin / Rogue AP
The attacker creates a Wi-Fi access point with the same SSID as a legitimate network. Clients that auto-connect to known SSIDs connect to the attacker's AP instead. All traffic from connected clients passes through the attacker, enabling credential capture, SSL stripping, and injection. Particularly effective in public spaces where users expect open Wi-Fi.
Deauthentication Attacks
IEEE 802.11 management frames (including deauthentication) are unauthenticated in legacy protocols. An attacker sends spoofed deauthentication frames, forcing clients off a legitimate AP. Used to capture WPA2 4-way handshake for offline cracking (disconnect client, they reconnect, attacker captures handshake). 802.11w (Management Frame Protection) authenticates management frames, preventing deauth forgery.
WPA2 Cracking
The 4-way handshake captures enough information to attempt offline dictionary attack against the Pre-Shared Key. PMKID attack allows handshake capture without waiting for a client to connect. Short or dictionary-based passwords are crackable. Defense: use WPA3 (SAE replaces PSK, provides forward secrecy and eliminates offline dictionary attack), or use strong random PSKs of 20+ characters.
WPS Vulnerabilities
Wi-Fi Protected Setup PIN authentication has a design flaw: the 8-digit PIN is validated in two 4-digit halves, reducing the search space from 100,000,000 to 11,000 combinations. Pixie Dust attack uses WPS vulnerability to recover PIN in seconds on vulnerable chipsets. Disable WPS on all access points -- it serves no security purpose and provides a trivial bypass of WPA2 encryption.

On-Path Attacks and Protocol Interception
Modern terminology for MITM. "On-path" more precisely describes the positional requirement -- the attacker must be in the communication path.
HTTPS Interception (Corporate Proxies)
Enterprise security appliances perform TLS inspection (decryption, inspection, re-encryption) to scan HTTPS traffic for malware and DLP violations. This is a deliberate on-path attack by the organization against its own employees' traffic. It requires installing a trusted root certificate on all endpoints. Employees connecting from personal devices or without the corporate cert see certificate warnings.
Certificate Pinning Bypass
Mobile applications often pin the server's certificate or public key to prevent MITM inspection. A proxy attempting to intercept traffic will present a different certificate that does not match the pin -- the app refuses the connection. Certificate pinning is a defense against MITM for specific high-value applications (banking, VPN clients) at the cost of deployment flexibility.
MITM Defense: Certificate Validation
TLS certificate validation prevents MITM by verifying: the certificate is issued by a trusted CA, the hostname matches the certificate's CN or SAN, the certificate is not expired, and it has not been revoked (OCSP/CRL). Attackers performing MITM must present a certificate the victim's browser trusts. Certificate Transparency logs make fraudulent CA-signed certificates discoverable within hours.
SY0-701 Terminology Note
CompTIA SY0-701 uses "on-path attack" as the current preferred term for man-in-the-middle. Both terms appear on the exam. On-path is accurate -- the attacker must be positioned in the actual communication path. A MITM attack performed remotely (without physical or logical positioning in the path) is not possible by definition.

Network Reconnaissance
Before attacking, adversaries map the target network. Reconnaissance is often the phase that generates the most detectable traffic.
Active Scanning
The attacker sends packets to discover live hosts, open ports, and running services. Port scanning (nmap) with techniques: SYN scan (half-open, less logged), TCP connect (full handshake), UDP scan (slower, unreliable), XMAS scan (all flags set, response indicates closed). Service fingerprinting identifies software versions. OS fingerprinting analyzes TCP/IP stack behavior.
Passive Reconnaissance
Gather information without sending packets to the target. WHOIS lookups, DNS zone transfers (if misconfigured), Google dorking, LinkedIn employee enumeration, Shodan for internet-exposed services, Certificate Transparency for subdomain discovery, GitHub for leaked credentials and infrastructure details. Passive recon generates no logs on the target's systems.
Detecting Reconnaissance
Port scans generate characteristic log patterns: large numbers of connection attempts to many ports from one source in a short window. IDS/IPS rules detect scan signatures. Honeypots (systems with no legitimate traffic) detect any contact as scanning activity. Darknet monitoring (unused IP space) flags packet arrivals from external sources. Threat intelligence feeds identify known scanner IP ranges.
Reducing Attack Surface
Every open port is a reconnaissance target. Every exposed service is a potential attack vector. Firewall rules that block unused ports prevent discovery via scanning. Removing or disabling unnecessary services eliminates the service from the attack surface entirely. Network segmentation limits which hosts a compromised machine can scan. Reduce exposure before hardening what remains.

Packet Capture and Sniffing
Capturing network traffic in transit. In a MITM position or on a shared medium, all traffic is visible to the attacker.
Promiscuous Mode
Normally, a network interface only processes packets addressed to it. In promiscuous mode, it captures all packets visible on the segment. On a hub network, all traffic on the segment is visible. On switched networks, only traffic for the local port is normally visible -- ARP spoofing or port mirroring is required to capture other hosts' traffic. Wireshark operates in promiscuous mode by default.
What Sniffing Captures
Unencrypted HTTP traffic: full URLs, form data, cookies, session tokens. Unencrypted FTP: username and password in plaintext. Unencrypted SMTP: email content and credentials. DNS queries (even when the DNS response is encrypted, queries to recursive resolvers may not be). Internal protocols that assume network trust (SNMP v1/v2, legacy database protocols). Eliminate plaintext protocols entirely.
Network Forensics
Packet capture is also a defensive tool. Full packet capture (PCAP) provides the forensic record needed to reconstruct an attack after the fact. Network detection and response (NDR) tools analyze traffic patterns for anomalies. Intrusion detection systems generate alerts when traffic matches known attack signatures. The same visibility that helps attackers also helps defenders -- who has it matters.

VLAN Hopping and Layer 2 Attacks
VLANs provide logical network segmentation. Misconfigured switch features allow attackers to cross VLAN boundaries they should not be able to cross.
Switch Spoofing
Dynamic Trunking Protocol (DTP) allows switches to automatically negotiate trunk links. An attacker connecting to an access port sends DTP frames to negotiate a trunk. If the switch accepts, the attacker's port becomes a trunk -- it receives traffic from all VLANs. Defense: disable DTP on all access ports (switchport nonegotiate), configure all non-trunk ports as access ports explicitly.
Double Tagging
802.1Q VLAN tags can be nested. An attacker on VLAN 10 sends a frame with an outer tag of VLAN 10 (their native VLAN) and an inner tag of VLAN 99 (target VLAN). The ingress switch strips the outer tag; the egress switch forwards based on the inner tag, delivering the frame to VLAN 99. One-directional attack -- responses cannot return. Effective for sending forged packets cross-VLAN.
Defense: Native VLAN Hardening
The double-tagging attack requires the attacker to be on the native VLAN of a trunk port. Set the native VLAN to an unused, dedicated VLAN ID that no hosts are assigned to. Tag the native VLAN explicitly (no untagged traffic on trunks). Disable unused switch ports and place them in a quarantine VLAN. Implement 802.1X port authentication so unauthorized devices cannot connect.
MAC Flooding
A switch's CAM (Content Addressable Memory) table maps MAC addresses to ports. If the table fills, the switch falls back to hub behavior -- flooding frames to all ports. The attacker sends frames with thousands of random source MACs, filling the CAM table, then sniffs all traffic. Defense: configure port security to limit the number of MACs per port; alert and shut down port on violation.

IPsec and VPN Security
Encrypted tunnels that protect data in transit from interception and modification. The primary defense against network-layer MITM.
IPsec Modes
Transport mode: encrypts only the payload; original IP header is preserved. Used for host-to-host encryption within a network. Tunnel mode: encrypts the entire original IP packet and wraps it in a new IP header. Used for site-to-site VPN and remote access VPN. Tunnel mode hides internal addressing from external observers; transport mode does not.
AH vs. ESP
Authentication Header (AH): provides integrity and authentication for the entire IP packet including the header, but no encryption. Broken by NAT (NAT modifies IP header, invalidating AH's signature). Encapsulating Security Payload (ESP): provides confidentiality (encryption), integrity, and authentication for the payload. ESP is preferred in almost all deployments. AH is rarely used.
IKE and Key Exchange
Internet Key Exchange (IKE) negotiates the IPsec security association (SA). IKEv1: two phases, multiple modes, more complexity and vulnerabilities. IKEv2: streamlined, built-in EAP support, mobility extensions (MOBIKE). IKEv2 is preferred. Both versions use Diffie-Hellman for key agreement -- PFS is available by using ephemeral DH groups (re-keying generates new keys not derived from the long-term key).
VPN Split Tunneling Risks
Split tunneling routes only corporate-destined traffic through the VPN; all other traffic (including attacker traffic) goes directly to the internet. A compromised endpoint with split tunneling enabled is simultaneously on the corporate network and the internet, potentially bridging the two. Full-tunnel VPN forces all traffic through corporate security controls but degrades performance.
Slide 20 of 35
Network Detection and Response (NDR)
Continuous monitoring of network traffic to detect attack patterns, lateral movement, and anomalous behavior.
IDS vs. IPS
Intrusion Detection System: monitors and alerts, does not block. Intrusion Prevention System: monitors, alerts, and actively blocks matching traffic. IPS is inline -- all traffic passes through it. IDS is out-of-band -- it receives a copy of traffic. IPS can block attacks but adds latency and risk of false-positive blocking. IDS provides visibility without risk of disrupting legitimate traffic.
Signature vs. Anomaly Detection
Signature-based: matches traffic against known attack patterns. Zero-day attacks produce no signature matches. Anomaly-based: establishes a baseline of normal behavior, alerts on deviations. Catches novel attacks but generates more false positives. Behavioral analysis combines both: signature matching catches known attacks, anomaly detection flags unusual patterns for investigation.
Network Traffic Analysis (NTA)
Analyzes network flow data (NetFlow, IPFIX, sFlow) rather than full packet captures. Flow data is much smaller than PCAP -- enables long-term retention. NTA tools detect: lateral movement (unusual internal traffic patterns), C2 beaconing (periodic outbound connections to fixed intervals), data exfiltration (abnormally large outbound transfers), port scanning (high connection counts to many destinations).
TAP vs. SPAN Port
Network TAP (Test Access Point): physical device that copies all traffic on a link to a monitoring port. Passive, cannot be disabled by software, does not consume switch resources. SPAN (Switched Port Analyzer): software-configured port mirroring on a switch. Can be disabled or disrupted, limited bandwidth for high-speed links. TAP is preferred for production monitoring; SPAN is common in lab environments.

Firewall Architecture
Firewalls are the primary network segmentation and traffic control mechanism. Architecture determines what threats each type can stop.
Packet Filter (Stateless)
Evaluates each packet independently based on source IP, destination IP, source port, destination port, and protocol. No state tracking -- a rule to allow established TCP connections requires explicit rules for return traffic. Simple, fast, but cannot detect protocol abuse or attacks that span multiple packets. Appropriate for basic edge filtering.
Stateful Inspection
Maintains a connection state table. Tracks TCP handshake state, UDP conversation state, and ICMP exchanges. Allows return traffic for established connections automatically. Detects out-of-sequence packets and protocol state violations. The standard for enterprise firewalls. Cannot inspect encrypted traffic or application-layer content.
Next-Generation Firewall (NGFW)
Adds application identification (layer 7), user identity awareness, TLS inspection, integrated IPS, URL filtering, and threat intelligence integration to stateful inspection. Can enforce policies based on the application (block Dropbox regardless of port) or user (allow CEO to access financial data). The current enterprise standard for perimeter and segmentation firewalls.
DMZ Architecture
A demilitarized zone places publicly accessible servers (web, email, DNS) in a network segment separated from both the internet and the internal network by firewalls. External traffic reaches the DMZ but not the internal network. Internal traffic can reach the DMZ to query services. Even if a DMZ server is compromised, the attacker cannot directly reach internal hosts without traversing another firewall.
Slide 22 of 35
Network Segmentation
Dividing a network into isolated segments limits the blast radius of any single compromise. The network equivalent of compartmentalization.
An attacker compromises a workstation in the research wing. On a flat network, they immediately have access to the specimen database, the SCADA controllers, the HR file server, and every other device. On a segmented network, the compromised workstation can only reach the research VLAN's authorized resources. Every cross-segment move requires traversing a firewall and generates a log entry.
VLAN Segmentation
VLANs create separate Layer 2 broadcast domains on the same physical switch infrastructure. Traffic between VLANs must pass through a Layer 3 device (router or firewall), where policies are enforced. VLANs alone are not security -- they must be paired with inter-VLAN routing controls. VLAN hopping attacks (switch spoofing, double tagging) must be mitigated through switch hardening.
Microsegmentation
Applies granular access controls at the workload level, not just the network segment level. Software-defined networking enforces east-west traffic policies between individual servers or containers within the same network segment. A web server cannot directly reach a database server even if they are in the same VLAN unless an explicit policy allows it. Zero Trust network architecture relies on microsegmentation.
Air Gap
Physical isolation -- no network connection to any other network. The most secure segmentation for ultra-high-sensitivity environments. Data transfer only via physical media (USB drives, which themselves must be controlled and scanned). Stuxnet demonstrated that air-gapped networks are breachable via physical media. An air gap is only as strong as the physical security controlling media introduction.

Zero Trust Network Access
Eliminate implicit trust from network location. Every access request is verified regardless of whether it originates from inside or outside the perimeter.
Why Perimeter Trust Fails
The perimeter model grants broad trust to traffic that has crossed the outer firewall. One compromised host inside the perimeter moves freely. Cloud and remote work eliminated a well-defined perimeter. VPN tunnels extend the perimeter to every remote endpoint. Insider threats operate inside the perimeter by definition. The perimeter has effectively ceased to exist as a meaningful trust boundary.
Zero Trust Principles (NIST SP 800-207)
All resources treated as if externally accessed. Access granted per-session based on dynamic policy. Continuous verification: identity, device health, network location. Least-privilege access: minimum necessary for the specific task. Assume breach: monitor all traffic including internal. No implicit trust from network location -- being "inside" grants nothing. All sessions authenticated and authorized individually.
Software-Defined Perimeter (SDP)
Infrastructure is invisible until authenticated. The user proves identity before any network path is established -- they cannot even probe the service. The SDP controller evaluates identity and device posture, then provisions an encrypted tunnel only to the specific resources authorized for that session. Compare to VPN: a VPN grants broad network access; SDP grants access only to authorized applications.
ZTNA Implementation Components
Identity provider (IdP) with MFA for user verification. Device trust assessment (MDM enrollment, EDR health, patch status). Policy enforcement point between the user and the resource. Continuous session monitoring with re-verification triggers on anomalies. All access logged with full context. Microsegmentation prevents lateral movement even after access is granted to one resource.

BGP and Routing Security
BGP was designed for trust among ISPs -- it has no built-in authentication, making route hijacking possible at internet scale.
BGP Route Hijacking
An AS announces a prefix it does not legitimately own. Other routers accept it because BGP has no cryptographic verification. Traffic destined for the hijacked prefix is redirected to the attacking AS. High-profile incidents: Pakistan Telecom hijacked YouTube's IP space (2008), a Russian ISP briefly routed traffic for major financial institutions (2019). The impact is global and immediate.
RPKI -- Resource Public Key Infrastructure
Cryptographically binds IP prefixes to authorized AS numbers using Route Origin Authorizations (ROAs). Routers validate BGP announcements against the RPKI cache -- announcements not matching an ROA are marked invalid and dropped (route origin validation). RPKI does not prevent path manipulation but prevents origin hijacking. Major ISPs implement RPKI; adoption is growing but incomplete.
BGPSec
Cryptographic signatures on BGP AS path attributes to prevent path manipulation (not just origin hijacking). Each AS in the path signs its portion of the route announcement. Validates that the stated AS path reflects actual routing. Operationally challenging due to key management at internet scale. Less widely deployed than RPKI but provides stronger guarantees for the full path.

Network Security Protocols
Protocols designed to provide authentication, encryption, and integrity at the network layer. SY0-701 tests protocol selection for specific scenarios.
802.1X Port Authentication
Network Access Control at the switch port level. A device connecting to a switch port must authenticate (via RADIUS/EAP) before the port is activated. Prevents rogue devices from connecting to the network by plugging into an open port. Three parties: supplicant (client), authenticator (switch), authentication server (RADIUS). Essential for zero-trust network access at the wired layer.
SNMPv3
SNMP v1 and v2c use community strings (effectively plaintext passwords) for authentication. SNMPv3 adds authentication (MD5 or SHA) and privacy (DES or AES encryption). Never use SNMPv1/v2c for network management -- community strings are routinely captured from traffic and provide full read (and sometimes write) access to device configurations. SNMPv3 with AES privacy and SHA authentication is the minimum standard.
SSH vs. Telnet
Telnet transmits all data including credentials in plaintext. Any network observer between client and server captures the credentials. SSH encrypts the entire session, provides host key verification (prevents MITM on connection), and supports key-based authentication (eliminates password brute-forcing). Telnet should never appear in any production environment. SSH v2 only -- SSH v1 has known cryptographic weaknesses.
HTTPS vs. HTTP
HTTP transmits all data in plaintext -- credentials, session cookies, form data. HTTPS wraps HTTP in TLS, providing encryption, integrity, and server authentication. Any web application that handles authentication, personal data, or session cookies must use HTTPS for all pages. Mixed content (HTTPS page loading HTTP resources) exposes those resources to interception and can be used to inject malicious scripts.

Email Security Protocols
Email was designed without authentication -- SPF, DKIM, and DMARC retrofit sender verification to prevent spoofing and phishing.
SPF -- Sender Policy Framework
A DNS TXT record listing which mail servers are authorized to send email for a domain. Receiving servers check whether the sending server's IP is listed in the SPF record. An email from hr@company.com originating from an unlisted IP fails SPF. SPF only checks the envelope sender (MAIL FROM), not the From: header visible to the user. Does not prevent header spoofing alone.
DKIM -- DomainKeys Identified Mail
The sending mail server signs the email headers and body with its private key. A DKIM signature is added as a header. The receiving server retrieves the public key from DNS and verifies the signature. DKIM proves the email was not modified in transit and was sent by a server with the domain's private key. Does not prevent spoofing of the visible From: header alone.
DMARC -- Domain-based Message Auth
DMARC ties SPF and DKIM together and specifies what to do when they fail: none (monitor only), quarantine (spam folder), or reject (discard). Requires alignment: the From: header domain must match the SPF or DKIM signing domain. DMARC reports (aggregate and forensic) give domain owners visibility into email spoofing attempts. DMARC p=reject is the only configuration that stops spoofed phishing email from reaching inboxes.

Network Attack Chain Example
Real intrusions chain network-layer attacks. Trace the attack path and identify the defensive break point at each step.
Full Attack Chain
Passive DNS enumeration discovers mail.facility.int and db.facility.int subdomains via Certificate Transparency. Port scan finds SMTP open on mail server. Discovered SMTP version has CVE. Exploit gains shell. Server used for ARP spoofing on internal research VLAN. Credentials captured from HTTP traffic to internal portal (not HTTPS). Credentials used to authenticate to db.facility.int over Telnet. Full database access obtained.
1 Subdomain discovery via CT logs: broken control. Add subdomains to Certificate Transparency monitoring. Subdomain enumeration is information disclosure -- limit what is publicly resolvable.
2 Unpatched SMTP: broken control. Vulnerability management with patching SLAs. Externally accessible services are highest priority. The SMTP server should not exist on a public-facing address without a WAF or MTA relay in front of it.
3 ARP spoofing succeeds: broken control. DAI was not configured on the research VLAN switches. Enable Dynamic ARP Inspection on all managed switches in sensitive VLANs.
4 HTTP credentials captured: broken control. HTTPS with HSTS was not enforced on the internal portal. All credential-handling applications must use TLS regardless of whether they are internal.
5 Telnet to database: broken control. SSH only, with key-based authentication. Telnet in a production environment is an automatic critical finding in any security assessment.

Threat Intelligence and Feeds
Network defenses improve when augmented with external intelligence about current attack infrastructure, TTPs, and indicators of compromise.
Indicators of Compromise (IOC)
Observable artifacts that indicate a system may be compromised: IP addresses of known C2 servers, malicious domain names, file hashes of known malware, registry keys created by specific malware, unusual outbound port usage. IOCs are integrated into firewalls, IDS/IPS, and SIEM to automate detection. IOCs expire -- known attacker infrastructure changes. Freshness matters.
Threat Intelligence Feeds
Commercial (CrowdStrike Falcon Intelligence, Recorded Future) and open-source (AlienVault OTX, Abuse.ch, Spamhaus) feeds provide continuously updated IOCs and threat actor TTPs. STIX (Structured Threat Information Expression) and TAXII (Trusted Automated Exchange of Intelligence Information) are open standards for sharing threat intelligence between organizations and platforms.
IOC vs. TTP
IOCs are specific artifacts (IP, domain, hash) that are easy to detect but easy for attackers to change -- rotate C2 infrastructure, recompile malware with a new hash. TTPs (Tactics, Techniques, and Procedures) describe how attackers behave -- harder to detect, but also harder for attackers to change. MITRE ATT&CK catalogs TTPs. Detecting TTPs is more durable than detecting IOCs.
MITRE ATT&CK Framework
A knowledge base of adversary tactics and techniques based on real-world observations. Organized by tactics (the why: Initial Access, Lateral Movement, Exfiltration) and techniques (the how: Spearphishing, ARP Cache Poisoning, DNS Hijacking). Used for threat modeling, detection coverage gap analysis, and red team planning. SY0-701 references ATT&CK in attack taxonomy questions.

Network Hardening Checklist
Operational controls that reduce the attack surface against network-layer attacks. Most require switch and router configuration changes.
1 Enable Dynamic ARP Inspection (DAI) on all VLANs with untrusted hosts. Mark uplinks to other switches and routers as trusted. Eliminates ARP spoofing from the segment.
2 Enable DHCP Snooping on all access VLANs. Creates the binding table used by DAI and also prevents rogue DHCP servers from redirecting client traffic.
3 Disable DTP on all access ports (switchport nonegotiate). Set all non-trunk ports as access ports explicitly. Prevents switch spoofing and VLAN hopping via trunk negotiation.
4 Configure port security with maximum MAC addresses per port. Prevents MAC flooding attacks that cause switches to behave as hubs. Violation action: shutdown or restrict with logging.
5 Set native VLAN to unused VLAN ID on all trunks. Explicitly tag native VLAN traffic. Prevents double-tagging attacks that allow cross-VLAN frame injection.
6 Implement 802.1X on all wired access ports. Prevents unauthorized devices from connecting to the network by plugging into switch ports. Pair with RADIUS and device certificates for strongest authentication.
7 Replace SNMPv1/v2c with SNMPv3 (AuthPriv mode: SHA authentication, AES encryption). Restrict SNMP access to management network only. Removes a commonly abused credential leak vector.

Cloud Network Security
Cloud environments shift the network security model -- physical switches are replaced by virtual networking constructs, but the attack categories remain the same.
Security Groups and NACLs
AWS Security Groups are stateful instance-level firewalls. NACLs are stateless subnet-level access control lists. Security Groups are permissive by default for outbound, restrictive for inbound. NACLs require explicit allow rules for both inbound and outbound (stateless). Both are used together: NACLs for subnet-level controls, Security Groups for instance-level. Misconfigured Security Groups allowing 0.0.0.0/0 are a common finding.
VPC Flow Logs
AWS VPC Flow Logs capture metadata about accepted and rejected traffic at the ENI level: source IP, destination IP, port, protocol, bytes, action. Equivalent to NetFlow for on-premises networks. Used for network anomaly detection, forensic investigation, and compliance logging. Does not capture packet content -- only flow metadata. Enable on all VPCs in production environments.
Cloud DDoS Protection
AWS Shield Standard (free): automatic protection against common volumetric DDoS for all AWS customers. Shield Advanced: additional detection, WAF integration, 24/7 DRT (DDoS Response Team) access, cost protection during an attack. Cloudflare Magic Transit and Azure DDoS Protection Network provide similar tiered services. Cloud DDoS protection absorbs attacks at the provider's global scale before traffic reaches the customer's resources.
Private Subnet Design
Databases, application servers, and internal services should reside in private subnets with no direct route to the internet. Access occurs via bastion hosts (for SSH), VPN, or AWS Systems Manager Session Manager. Internet-facing load balancers and NAT gateways sit in public subnets. This architecture limits DDoS exposure and removes attack surface for internet-originating threats against backend systems.

Network Attack Comparison Matrix
Cross-reference attack type, OSI layer, CIA pillar affected, and primary defense. Used for exam scenario identification.
A SYN Flood: Layer 4. CIA: Availability. Defense: SYN cookies, upstream rate limiting, stateful firewall connection limits.
B ARP Spoofing: Layer 2. CIA: Confidentiality (interception), Integrity (modification). Defense: Dynamic ARP Inspection, static ARP entries.
C DNS Poisoning: Layer 7 (affects all). CIA: Integrity (wrong mapping), Confidentiality (redirects traffic). Defense: DNSSEC, query randomization.
D SSL Stripping: Layer 7. CIA: Confidentiality (exposes encrypted data as plaintext). Defense: HSTS, HSTS preloading.
E Replay Attack: Any layer. CIA: Integrity (replayed actions are unauthorized), Availability (session exhaustion). Defense: nonces, timestamps, short validity windows.
F Amplification DDoS: Layer 3/4. CIA: Availability. Defense: BCP 38 ingress filtering, restrict amplifiable services, upstream scrubbing.
G Session Hijacking: Layer 4/7. CIA: Confidentiality (session access), Integrity (forged actions). Defense: TLS, HttpOnly/Secure cookies, token binding.

Module Summary
Network attacks exploit the infrastructure that carries communication. Every attack targets a protocol's implicit trust assumptions. The defenses add explicit verification at each layer.
Network security is fundamentally about removing implicit trust from communication paths. ARP assumed trusted neighbors; DAI adds explicit verification. BGP assumed trustworthy peers; RPKI adds cryptographic authorization. HTTP assumed network confidentiality; TLS adds encryption. Each defense adds what the original protocol designers omitted.
10 Facts to Carry Out of This Lecture
1 DoS exhausts one resource (bandwidth, connections, CPU). DDoS uses distributed sources to overwhelm defenses. Mitigation must occur upstream -- the target cannot absorb Tbps-scale attacks alone.
2 SYN flood exploits TCP handshake state allocation. SYN cookies eliminate state allocation until ACK is received, breaking the attack.
3 ARP spoofing poisons Layer 2 caches to redirect traffic through the attacker. Defense: Dynamic ARP Inspection with DHCP snooping binding tables.
4 DNS poisoning corrupts resolver caches to redirect domain lookups. DNSSEC provides cryptographic verification of records. DoH/DoT protect query transport but not cache integrity.
5 SSL stripping intercepts the initial HTTP request and prevents HTTPS upgrade. HSTS and HSTS preloading force the browser to upgrade internally before any request is sent.
6 Replay attacks retransmit valid authentication exchanges. Defense: nonces (number used once), timestamps, and short validity windows.
7 Amplification DDoS uses IP spoofing to direct amplified responses at the victim. BCP 38 ingress filtering eliminates the spoofed source prerequisite and is the single most effective defense.
8 VLAN hopping via switch spoofing is prevented by disabling DTP and explicitly configuring access ports. Double tagging is prevented by setting native VLAN to unused ID and tagging all native traffic.
9 IPsec ESP provides encryption and integrity for network-layer traffic. IKEv2 is preferred over IKEv1. Tunnel mode protects internal addressing. PFS uses ephemeral DH keys.
10 MITRE ATT&CK catalogs adversary TTPs. IOCs (IP, domain, hash) are easy to detect but easy to change. TTPs are harder to detect but more durable intelligence for detection engineering.
