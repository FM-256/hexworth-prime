Why Network Architecture Matters
The structure of your network determines the blast radius of every breach. Good architecture limits lateral movement before an attacker arrives.
Architecture Is Policy Made Physical
Every firewall rule, every VLAN boundary, every NAT translation is a security decision rendered in infrastructure. The network enforces policy automatically, without relying on human behavior. A flat network with no segmentation means a single compromised host can reach everything.
Lateral Movement Is the Real Threat
Most successful breaches begin with a single compromised endpoint. The damage is caused by lateral movement -- the attacker's ability to pivot from that foothold to high-value targets. Segmentation limits how far that pivot can reach. Without it, one phishing click can expose the entire domain.
Compliance Requires Defined Zones
PCI DSS mandates cardholder data environment isolation. HIPAA requires protected health information to be logically separated from general business systems. Regulatory compliance is often the forcing function that drives organizations to implement proper network architecture.
The SY0-701 Perspective
Network architecture appears across Domain 3.1 (Security Architecture) and 3.2 (Security Infrastructure). Exam questions focus on identifying the correct placement of controls -- where does the firewall go, what belongs in the DMZ, when do you use NAT versus a proxy. Topology decisions are always justified by security requirements.

Firewall Fundamentals
A firewall enforces access control policy at network boundaries by inspecting and filtering traffic.
Packet Filtering (Stateless)
Examines each packet independently. Decisions based on source IP, destination IP, source port, destination port, and protocol. Fast and simple. Cannot track connection state -- cannot distinguish a TCP SYN from mid-stream data. ACL-based. Legacy technology still common in routers.
Stateful Inspection
Tracks the state of active connections in a state table. Knows whether a packet belongs to an established session, is part of a new connection, or is invalid. Can block unsolicited inbound packets even if the port is technically allowed. The standard for enterprise firewalls since the 1990s.
Next-Generation Firewall (NGFW)
Combines stateful inspection with deep packet inspection (DPI), application-layer awareness, intrusion prevention, TLS inspection, user-identity integration, and threat intelligence feeds. Can identify and block applications regardless of port. Palo Alto, Fortinet, and Cisco Firepower are market leaders.
Key Exam Distinction
Stateless firewalls filter per-packet with no session context. Stateful firewalls track connection state and can block unsolicited packets. NGFWs add application awareness and DPI. SY0-701 expects you to know which type addresses which threat and the tradeoffs in performance versus inspection depth.

Firewall Rule Logic
Rules are evaluated top-to-bottom. The first match wins. An implicit deny-all at the bottom rejects unmatched traffic.
# Simplified firewall ACL -- evaluated in order PERMIT TCP 10.0.1.0/24 --> 10.0.2.10 port 443 # Allow HTTPS to web server PERMIT TCP 10.0.3.5 --> 10.0.2.20 port 1433 # Allow DB app server to SQL PERMIT ICMP 10.0.0.0/8 --> any # Allow internal ping DENY any any --> 10.0.2.20 port 1433 # Block all other SQL access DENY any any --> any # Implicit deny-all (catch-all)
Implicit Deny
Any traffic not explicitly permitted by a rule is denied. This is the foundational principle -- default deny is security. Default allow (only blocking what is explicitly listed) inverts the model and is almost always wrong for production firewalls.
Rule Ordering Matters
A PERMIT rule placed above a DENY for the same traffic causes the traffic to pass. Overly broad rules placed first can accidentally permit traffic that later specific rules would block. Rule audits must check for shadowed rules -- rules that can never be reached because a broader rule above them matches first.
Ingress vs. Egress Filtering
Ingress filtering blocks unauthorized inbound traffic. Egress filtering blocks unauthorized outbound traffic -- often overlooked. Malware C2 callbacks, data exfiltration, and DNS tunneling all require outbound connections. Egress filtering catches malware that has already executed on internal hosts.
Fail-Closed vs. Fail-Open
Fail-closed: if the firewall crashes, all traffic is blocked. Fail-open: if the firewall crashes, traffic passes unrestricted. Fail-closed is the secure default for security appliances. Fail-open is sometimes used for high-availability systems where downtime is unacceptable -- requires separate risk acceptance.

The DMZ Architecture
A demilitarized zone is a network segment that sits between the internet and the internal trusted network, hosting publicly accessible services.
The facility's public-facing specimen catalog must be accessible to approved researchers worldwide, but the specimen database holding classified containment protocols must never be directly reachable from the internet. The DMZ is the airlock between public access and sensitive internal systems.
What Goes in the DMZ
Web servers, mail relay servers, DNS servers, reverse proxies, public-facing APIs, VPN concentrators, and jump hosts. Any service that must accept connections from untrusted networks belongs in the DMZ -- not directly on the internal network.
Dual-Firewall Architecture
An outer firewall separates the internet from the DMZ. An inner firewall separates the DMZ from the internal network. An attacker who compromises a DMZ host must breach a second firewall to reach internal systems. Defense in depth at the network layer.
Single-Firewall DMZ Risk
Some architectures use a single firewall with three interfaces: WAN, DMZ, LAN. This is simpler and cheaper but introduces a single point of failure. If the firewall is compromised, both the DMZ and internal network are exposed simultaneously. Two-firewall designs avoid this.
Traffic Flow Rules
Internet to DMZ: allowed for specific services (HTTP/443, SMTP/25). DMZ to internal: strictly limited -- only specific back-end connections required by DMZ services. Internal to DMZ: typically allowed for management. Internet to internal: never directly. This asymmetry is the entire point.

Network Address Translation (NAT)
NAT rewrites IP address information in packet headers as traffic passes through a routing device. Originally designed to conserve IPv4 addresses, it provides a secondary security benefit.
Static NAT (SNAT)
One-to-one mapping between a private IP and a public IP. A DMZ web server at 192.168.1.10 is reachable at the public IP 203.0.113.50. Traffic arriving at the public IP is translated to the private IP. Used for servers that must be reachable from the internet with a consistent address.
Dynamic NAT
A pool of public IPs is shared by internal hosts. When an internal host initiates outbound traffic, it is assigned a public IP from the pool for the session duration. No consistent address -- not suitable for servers. Requires that the pool is large enough to support simultaneous sessions.
PAT / NAT Overload
Port Address Translation maps multiple internal hosts to a single public IP using unique source port numbers. The translation table tracks (private IP, private port) to (public IP, public port) mappings. This is how home routers work. Enables hundreds of hosts to share one IP address simultaneously.
NAT as a Security Benefit
NAT hides internal IP addressing from external observers. Unsolicited inbound packets are dropped because there is no existing translation entry to route them to an internal host. However, NAT is not a firewall -- it is a translation mechanism. It does not inspect traffic content. Do not rely on NAT alone for security.

VPN Fundamentals
A Virtual Private Network creates an encrypted tunnel across an untrusted network, allowing secure communication as if the endpoints were directly connected.
Site-to-Site VPN
Connects two networks permanently. A VPN gateway at each site encrypts all traffic between the networks. Remote offices connect to headquarters as if on the same LAN. Configured once, maintained automatically. Uses IPSec in most enterprise deployments. Branch-to-HQ and multi-site connectivity.
Remote Access VPN
Connects individual clients to a corporate network. The VPN client on the user's device establishes an encrypted tunnel to the VPN concentrator. The user appears to have an internal IP address. Enables remote work while maintaining network security policy. SSL/TLS VPN or IPSec client-based.
Split Tunneling
When split tunneling is enabled, only traffic destined for the corporate network goes through the VPN. Internet traffic goes directly to the ISP. Reduces load on the VPN gateway. Security risk: internet traffic from the remote device bypasses corporate web filtering and DLP. Generally disabled in high-security environments.
Always-On VPN
The VPN connects automatically whenever the device is not on the corporate network. The user cannot bypass it. All traffic passes through corporate security controls regardless of location. Enforces DLP, web filtering, and threat prevention for remote workers identically to office workers.

IPSec Architecture
IPSec is a suite of protocols that provides authentication, integrity, and encryption at the network layer (Layer 3). It is the dominant VPN protocol for site-to-site tunnels.
AH -- Authentication Header
Provides authentication and integrity for the entire IP packet including headers. Does not provide encryption -- the payload is readable. AH uses HMAC to sign packet content. Cannot traverse NAT because NAT modifies IP headers and breaks the AH signature. Rarely used alone in modern deployments.
ESP -- Encapsulating Security Payload
Provides encryption, authentication, and integrity for the payload (and optionally headers). ESP is the component used in practice for VPN tunnels. Can traverse NAT with NAT-T (NAT Traversal) which wraps ESP in UDP port 4500. Provides confidentiality that AH alone cannot provide.
IKE -- Internet Key Exchange
The key management protocol for IPSec. Phase 1 establishes the ISAKMP security association for the control channel (DH key exchange, authentication). Phase 2 establishes the IPSec security associations for data channels. IKEv2 is faster, more reliable, and supports MOBIKE for mobile clients.
Tunnel Mode vs. Transport Mode
Tunnel mode encapsulates the entire original packet inside a new IP packet -- used for gateway-to-gateway VPNs. Transport mode encrypts only the payload, preserving the original IP headers -- used for host-to-host communication. Site-to-site VPNs always use tunnel mode.
Perfect Forward Secrecy (PFS)
Each session uses a unique ephemeral DH key pair. If the long-term key is compromised, past sessions cannot be decrypted. PFS is a recommended IPSec configuration option. Without PFS, compromising the private key allows decryption of all previously captured sessions.
Slide 9 of 35
SSL/TLS VPN
TLS-based VPNs use the same protocol as HTTPS, making them firewall-friendly and easier to deploy for remote access than IPSec.
How TLS VPN Works
Traffic is encapsulated inside TLS (port 443). Because it looks like HTTPS, it passes through nearly all firewalls and proxies without special configuration. The VPN concentrator terminates TLS and forwards decrypted traffic to internal resources. Clientless web portal or full tunnel client modes available.
Clientless Mode
Access via a standard web browser -- no installed software. Users authenticate to a web portal and access specific applications through the browser. Limited to web-based applications and protocols that can be proxied through the portal. Useful for contractor access or unmanaged devices.
Full Tunnel Client
A lightweight client application creates a TLS tunnel that carries all IP traffic. Provides the same functionality as IPSec client VPN. The client can enforce pre-connection health checks (patch level, AV status) before granting access. Cisco AnyConnect, Palo Alto GlobalProtect, and Fortinet FortiClient are common implementations.
IPSec vs. TLS VPN
IPSec: network-layer, more configuration, used for site-to-site, may be blocked by strict firewalls. TLS VPN: application-layer, easier deployment, firewall-friendly, better for remote access. Both provide strong encryption. IPSec is preferred for permanent tunnel performance; TLS is preferred for remote user flexibility.

Network Segmentation
Dividing a network into isolated zones limits the blast radius of any single compromise. Segmentation is the most effective architectural control against lateral movement.
When Containment Wing C was breached, the attacker's movement was stopped at the VLAN boundary before reaching the specimen archive. The firewall rule permitting only HTTPS from Wing C to the archive server blocked the lateral pivot attempt entirely. Segmentation made the difference between a single-wing incident and a full facility compromise.
Physical Segmentation
Separate physical network infrastructure for different security domains. Air-gapped networks with no logical path between them. Maximum isolation. Used in classified government and industrial control environments where the value of the data justifies the operational complexity and cost.
VLAN Segmentation
Virtual LANs create logical isolation on shared physical infrastructure. Devices in different VLANs cannot communicate without passing through a router or Layer 3 switch -- where firewall rules are applied. Standard enterprise segmentation. Cost-effective. VLANs should be treated as a first layer, not the only layer.
Common Segmentation Zones
User workstations, servers, IoT/OT, PCI cardholder data environment, development, production, management, and DMZ. Each zone has different trust levels, different access policies, and different monitoring requirements. Zone design should follow data sensitivity and regulatory requirements.
VLAN Hopping Attack
Double tagging or switch spoofing can allow attackers to send traffic across VLAN boundaries. Mitigate by disabling trunk negotiation on access ports, using a native VLAN that carries no user traffic, and ensuring trunk ports only carry explicitly allowed VLANs.

Micro-Segmentation
Micro-segmentation extends segmentation down to the individual workload level. Each workload communicates only with the specific workloads it needs to -- nothing more.
East-West Traffic Problem
Traditional firewalls inspect north-south traffic (entering and leaving the network). East-west traffic (lateral movement between servers within the same zone) was historically trusted and uninspected. In a breach scenario, the attacker moves east-west -- from web server to database to domain controller. Micro-segmentation addresses east-west.
How It Works
Policy is applied at the individual workload (VM, container, or host) level rather than at the network perimeter. Each workload has a defined list of other workloads it can communicate with and on which ports. Traffic between workloads in the same VLAN is still inspected and filtered. Implemented via host-based firewalls, SDN, or service mesh.
Software-Defined Networking (SDN)
Separates the control plane (decisions about where traffic goes) from the data plane (the forwarding of packets). A central controller manages the entire network's policy. Micro-segmentation policies can be pushed instantly to thousands of workloads. VMware NSX and Cisco ACI are common enterprise SDN platforms.
Benefits vs. Traditional Segmentation
Granular control at the workload level rather than network zone level. Policy follows the workload when it moves (VM migration, container rescheduling). East-west traffic is inspected. Breach containment is dramatically improved. Complexity increases -- requires mature security operations to manage policy at scale.

Zero Trust Network Access
ZTNA replaces VPN and network-level access with per-application, identity-verified, posture-assessed access control.
Core Principle
No implicit trust based on network location. Being "on the corporate network" does not grant access. Every access request is evaluated against identity (who), device posture (how), and policy (what). Access is granted per-application, not per-network. Trust is earned dynamically, not assumed.
Why Traditional VPN Fails
VPN grants network-level access. Once a user connects, they often have broad lateral reach. A compromised VPN credential gives an attacker the same access as the legitimate user -- which may include dozens of internal systems. VPN also struggles with performance for globally distributed workforces and cloud resources.
ZTNA Architecture
A ZTNA broker sits between users and applications. Users connect to the broker, authenticate, and have device posture evaluated. The broker grants access only to specific applications the policy permits -- not to the underlying network. The application's real network location is never exposed to the user. Zscaler Private Access, Cloudflare Access, and similar platforms.
NIST SP 800-207 Zero Trust Tenets (Key Exam Points)
All resources are accessed securely regardless of location. Access to resources is on a per-session, per-request basis. Access is determined dynamically by policy. All asset security posture is monitored and evaluated continuously. Authentication and authorization are dynamic and strictly enforced before access is granted.

Software-Defined WAN (SD-WAN)
SD-WAN abstracts the WAN from the underlying transport, enabling intelligent routing across multiple connection types and reducing dependency on expensive MPLS circuits.
What SD-WAN Replaces
Traditional WAN used dedicated MPLS circuits from carrier networks. Expensive, inflexible, long provisioning times. SD-WAN uses commodity internet connections (broadband, LTE, 5G) with intelligent overlay routing. Traffic is sent over the best available path based on real-time performance metrics.
Security Implications
SD-WAN traffic traverses the public internet. All traffic must be encrypted. SD-WAN appliances include built-in IPSec tunneling. Many enterprise SD-WAN solutions integrate with cloud security services (SASE model) to inspect traffic at cloud PoPs before it reaches branch sites or the internet. Visibility into branch traffic improves.
SASE -- Secure Access Service Edge
Combines SD-WAN networking with cloud-delivered security services: CASB, SWG (Secure Web Gateway), ZTNA, FWaaS (Firewall as a Service). The security stack moves to the cloud edge closest to the user. Eliminates the need to backhaul branch internet traffic through the data center for inspection. Gartner-defined architecture adopted broadly.
Exam Relevance
SY0-701 tests SD-WAN as a network architecture decision with security trade-offs. Key points: SD-WAN requires encryption because it uses public internet, SASE integrates security into the WAN fabric, and SD-WAN improves performance for cloud-first organizations where traditional MPLS backhauling creates latency.

Proxy Servers
A proxy sits between clients and servers, forwarding requests on the client's behalf. Proxies provide inspection, caching, filtering, and anonymization capabilities.
Forward Proxy
Sits between internal clients and the internet. Clients send requests to the proxy, which fetches the content and returns it. Enables content filtering, web category blocking, malware scanning of downloads, caching of frequently accessed content, and logging of all web activity. Users' internal IPs are hidden from destination servers.
Reverse Proxy
Sits in front of internal servers, receiving requests from external clients. The external client sees only the proxy's IP. The proxy forwards requests to appropriate backend servers. Enables load balancing, TLS offloading, web application firewall (WAF) functionality, and protects server infrastructure from direct exposure.
Transparent vs. Explicit Proxy
Transparent proxy: clients are not configured to use it -- traffic is intercepted at the network level. No client configuration needed. Explicit proxy: clients are configured with the proxy address. Users or Group Policy pushes proxy settings. Transparent proxies can be bypassed by encrypted protocols that the proxy cannot intercept without TLS inspection.
TLS Inspection (SSL Bump)
To inspect HTTPS traffic, the proxy performs a man-in-the-middle: it terminates the TLS connection from the client using a corporate CA certificate, inspects the decrypted content, and re-encrypts to the destination. Requires deploying the corporate CA certificate as a trusted root on all managed clients. Legal and privacy considerations apply.

Load Balancers & High Availability
Load balancers distribute traffic across multiple servers to prevent any single server from becoming a bottleneck or point of failure.
Layer 4 Load Balancing
Distributes traffic based on transport-layer information (IP address and port). Does not inspect application content. Faster and simpler. Decisions are made using round-robin, least-connections, or source-IP hash algorithms. Cannot make routing decisions based on URL path or cookie values.
Layer 7 Load Balancing
Inspects application content (HTTP headers, URL paths, cookies) to make routing decisions. Can route /api requests to API servers and /static requests to CDN-backed servers. Enables A/B testing, canary deployments, and content-aware routing. Requires more processing but enables sophisticated traffic management.
Security Benefits
Load balancers with WAF functionality inspect HTTP traffic for SQLi, XSS, and other attacks before requests reach servers. They absorb volumetric DDoS attacks by distributing load and dropping malformed packets. TLS termination at the load balancer reduces certificate management complexity for backend servers.
Active/Active vs. Active/Passive
Active/active: both nodes handle traffic simultaneously. Higher throughput. Active/passive: one node handles traffic; the other is standby. Simpler failover logic. For firewalls and security appliances, active/active requires stateful session synchronization between nodes to prevent connection drops during failover.

IDS and IPS
Intrusion Detection Systems detect and alert on suspicious traffic. Intrusion Prevention Systems detect and actively block it.
NIDS -- Network IDS
Passive monitoring device connected to a mirror port (SPAN port) or tap. Analyzes a copy of traffic -- never the live traffic stream. Cannot block traffic (passive mode). Generates alerts. Placement matters: inside the firewall sees post-filter traffic; outside sees everything. Does not impact traffic flow regardless of load.
NIPS -- Network IPS
Inline device -- all traffic passes through it. Can block, drop, or modify packets in real time. If the IPS is overwhelmed or fails, traffic may be blocked (fail-closed) or pass uninspected (fail-open). Performance is critical. NGFWs include integrated IPS functionality, reducing the need for standalone IPS appliances.
Signature vs. Anomaly Detection
Signature: matches known attack patterns. Fast. Cannot detect unknown (zero-day) attacks. Requires frequent signature updates. Anomaly: establishes a baseline of normal behavior and alerts on deviations. Can detect novel attacks. Higher false positive rate -- requires tuning. Behavior-based detection is increasingly common in NGFW and EDR platforms.
False Positives and Tuning
False positive: legitimate traffic flagged as malicious. False negative: malicious traffic not detected. IDS/IPS tuning balances sensitivity. High sensitivity catches more attacks but generates noise that overwhelms analysts. Low sensitivity reduces false positives but increases false negatives. Tuning is an ongoing operational task, not a one-time setup.

Honeypots & Deception Technology
Deception technology lures attackers into interacting with fake systems, revealing their presence and methods without exposing real assets.
Honeypot
A system designed to attract attackers. It looks like a legitimate, valuable target but contains no real data. Any interaction with a honeypot is automatically suspicious -- legitimate users have no reason to access it. Provides early warning of internal reconnaissance, lateral movement, and credential stuffing.
Honeynet
A network of honeypot systems designed to simulate an entire environment. Can include fake web servers, databases, domain controllers, and file shares. Provides rich intelligence about attacker behavior, tool usage, and TTPs. More resource-intensive than a single honeypot but provides vastly better intelligence.
Honeytoken
A fake credential, document, or data record embedded among real ones. If the honeytoken is used or accessed, an attacker has stolen credentials or accessed a file share. No false positives -- any use of a honeytoken is definitively malicious. Easy to deploy as fake AWS keys, fake AD accounts, or fake documents with beaconing links.
Legal and Ethical Considerations
Honeypots must be isolated from production systems to prevent attackers who compromise the honeypot from pivoting to real systems. Entrapment is not a legal defense, but honeypots are legal -- they do not compel anyone to attack. Any evidence collected must follow chain of custody procedures to be admissible.

Jump Servers & Bastion Hosts
A bastion host is a hardened system at the network perimeter used as the sole entry point for administrative access to systems in protected zones.
Architecture Purpose
Administrators must authenticate to the bastion host before accessing systems in the DMZ or internal network. Direct administrative access (RDP, SSH) to servers from admin workstations is blocked at the firewall. All administrative sessions are funneled through one hardened, monitored chokepoint.
Session Recording
Every administrative session through the jump server can be recorded -- keystrokes, screen capture, commands executed. Provides complete audit trail of privileged activity. Enables post-incident forensics. Supports insider threat detection. Required by many compliance frameworks for privileged access management (PAM).
Hardening Requirements
Minimal installed software. MFA required for all access. No direct internet access. All access logged to a remote, tamper-evident log server. Regular patch cadence. Firewall rules allow only management protocols (SSH port 22, RDP port 3389) from the jump server to target hosts. No user workloads run on the jump server.
Single Point of Failure Risk
A compromised jump server provides administrative access to all connected systems. Protect it with the highest security controls in the environment. MFA, privileged identity management, session time limits, and anomaly-based behavioral monitoring are all appropriate. Some organizations deploy separate jump servers per security zone.

Port Security & 802.1X
Network Access Control (NAC) ensures that only authorized, compliant devices can connect to the network infrastructure.
802.1X Port Authentication
IEEE standard for port-based Network Access Control. Three parties: Supplicant (client device), Authenticator (network switch or AP), Authentication Server (RADIUS). The switch blocks all traffic until the device authenticates to the RADIUS server via EAP. An unauthorized device plugged into a port cannot communicate even if physically connected.
Switch Port Security
Limits the number of MAC addresses allowed on a switch port. If a new MAC appears beyond the limit, the port shuts down (shutdown mode), restricts the traffic (restrict mode), or drops the frame (protect mode). Prevents rogue hubs, switches, and unauthorized devices from connecting to the wired network.
Network Access Control (NAC)
Broader than 802.1X -- evaluates device health before granting network access. Checks for OS patch level, AV signature currency, disk encryption status, and approved software inventory. Non-compliant devices are placed in a remediation VLAN with limited access until they pass health checks. Enforces security posture as a network access prerequisite.
DHCP Snooping and ARP Inspection
DHCP snooping prevents rogue DHCP servers from handing out addresses on your network by only trusting DHCP responses from designated uplink ports. Dynamic ARP Inspection (DAI) validates ARP packets against the DHCP snooping binding table, preventing ARP poisoning and man-in-the-middle attacks at Layer 2.

Out-of-Band Management
A dedicated management network separated from production traffic ensures administrative access is available even when the production network is compromised or unavailable.
In-Band vs. Out-of-Band
In-band management: administrative traffic uses the same network paths as production traffic. An attacker who compromises the network can observe or intercept management sessions. Out-of-band: a separate management network, physically or logically isolated, carries only device management traffic. Used for routers, switches, firewalls, and servers.
IPMI, iDRAC, iLO
Baseboard Management Controllers (BMC) provide out-of-band access to server hardware independent of the OS. iDRAC (Dell), iLO (HPE), IPMI (standard). Allow power cycling, BIOS access, KVM-over-IP, and OS reinstallation without physical access. Must be on a dedicated management VLAN -- BMCs have historically had critical vulnerabilities and default credentials.
Console Servers
A console server (serial concentrator) aggregates the serial console ports of all network devices. Provides emergency access when network connectivity fails. Accessible via dedicated OOB network or cellular modem. Critical for data center management when the production network is the subject of an incident.
Security Requirements
Out-of-band network must be as secure as the most sensitive resource it manages. Default BMC credentials must be changed immediately. OOB network traffic should be encrypted. Access should be limited to jump server connections only. BMC firmware should be patched -- IPMI vulnerabilities (CVE-2013-4786 Cipher Zero) have been critical for years and remain unpatched on legacy hardware.

IPv6 Security Considerations
IPv6 introduces new security challenges that existing IPv4-focused controls may not address. Many enterprise environments run dual-stack, creating risk from the IPv6 side being under-managed.
Dual-Stack Risk
Many modern operating systems enable IPv6 by default even when the organization has not deployed IPv6 infrastructure. Firewalls and IDS/IPS rules that only filter IPv4 will miss IPv6 traffic entirely. An attacker can use IPv6 tunneling to bypass IPv4-only controls. Audit all security controls for dual-stack coverage.
Rogue Router Advertisements
IPv6 uses Router Advertisement (RA) messages for autoconfiguration. A rogue RA can redirect all IPv6 traffic to an attacker-controlled gateway. IPv6 RA Guard on switches filters unauthorized RAs from non-router ports. Similar to DHCP snooping but for IPv6. Often overlooked in security configurations.
IPv6 Tunneling Attacks
IPv6 can be tunneled inside IPv4 (6to4, Teredo, ISATAP) to traverse IPv4 networks. These tunnels can bypass IPv4 firewalls and IDS rules. An attacker who controls a Teredo relay can receive IPv6 traffic from a target machine that has no direct IPv6 connectivity. Disable automatic tunneling protocols on managed hosts unless explicitly required.
Firewall Rule Parity
Every IPv4 security rule must have an IPv6 equivalent. This includes both perimeter rules and host-based firewall rules. If you block SMB on IPv4 but not IPv6, an attacker with IPv6 access can use SMB. IPv6 address space (2^128 addresses) makes traditional network scanning less effective but does not eliminate the attack surface.

Network Monitoring and Visibility
You cannot defend what you cannot see. Network monitoring provides the visibility required to detect anomalies, track assets, and investigate incidents.
NetFlow / IPFIX
Flow records capture metadata about network conversations: source IP, destination IP, ports, protocol, byte counts, and timestamps. No packet payload. Lightweight. Enables traffic analysis, bandwidth accounting, and behavioral anomaly detection at scale. Identify unusual traffic volumes, port scanning, and exfiltration patterns without full packet capture.
Full Packet Capture (PCAP)
Captures the complete network traffic including payloads. Provides complete forensic evidence for incident investigation. Extremely storage-intensive -- even 1 Gbps of traffic generates terabytes per hour. Typically deployed only on critical chokepoints (DMZ, internet egress) with short retention windows or triggered by alert conditions.
SNMP Monitoring
Simple Network Management Protocol allows polling network devices for operational metrics: interface utilization, error counters, CPU and memory. SNMPv1 and v2c use community strings (shared secrets) in cleartext -- security risk. SNMPv3 adds authentication and encryption. Limit SNMP access to the management network only. Community string "public" must never be used in production.
Syslog and Log Management
All network devices, servers, and security appliances should ship logs to a central syslog server or SIEM. Centralization prevents local log tampering. Logs from network devices provide authentication records, configuration changes, and traffic anomalies. Retention periods are driven by compliance requirements (PCI DSS: 1 year minimum).

Common Network Attacks
SY0-701 requires knowledge of how specific attacks work, which layer they target, and which controls prevent them.
1 ARP Poisoning: Attacker sends gratuitous ARP replies associating their MAC with the gateway's IP. Traffic intended for the gateway is sent to the attacker. Mitigation: Dynamic ARP Inspection (DAI).
2 DNS Poisoning / Spoofing: Attacker injects false DNS records, redirecting victims to malicious IPs. Mitigation: DNSSEC validates DNS responses with digital signatures.
3 MAC Flooding: Attacker floods a switch's MAC address table with fake entries. Switch enters fail-open mode and broadcasts all frames. Mitigation: port security limiting MAC count per port.
4 VLAN Hopping: Double-tagged frames or switch spoofing allows traffic to cross VLAN boundaries. Mitigation: disable auto-trunking, use dedicated native VLAN with no user traffic.
5 DHCP Starvation: Attacker floods DHCP requests, exhausting the address pool. Legitimate clients cannot get addresses. Mitigation: DHCP snooping with rate limiting per port.
6 SYN Flood: Attacker sends many TCP SYNs with spoofed source IPs. Server exhausts half-open connection table waiting for ACKs that never arrive. Mitigation: SYN cookies, firewall rate limiting.
7 BGP Hijacking: Attacker or misconfigured router announces routes for IP prefixes they do not own. Traffic is redirected to the attacker. Mitigation: RPKI (Resource Public Key Infrastructure) route origin validation.

Secure Network Design Principles
Architectural principles that apply universally to network security design, regardless of the specific technology stack.
Defense in Depth
Multiple independent security controls. An attacker who bypasses the perimeter firewall still faces NGFW, IPS, network segmentation, host-based firewall, and endpoint detection. No single control failure results in a complete compromise. Each layer buys time for detection and response.
Principle of Least Functionality
Network devices should only perform their required function. A switch should not run a DHCP server unless it is designated to do so. Routers should not provide wireless access unless designed for that role. Unnecessary services on network infrastructure expand the attack surface without providing value.
Network Resilience
Redundant paths, redundant ISP connections, and redundant hardware ensure availability when components fail. Single points of failure in the network are availability risks. Spanning Tree Protocol prevents loops but can itself be attacked -- BPDUGuard limits STP manipulation. ECMP and link aggregation for path redundancy.
Separation of Duties at Network Level
Different teams should manage different network zones. The team managing the production server VLAN should not manage the management network VLAN. Insider threat controls require that no single administrator has unchecked control over an entire critical path. Documented change management prevents unauthorized configuration changes.

Wireless Security Foundations
Wireless networks extend the network perimeter into the physical environment. Signal propagation does not respect building walls or property boundaries.
WEP -- Do Not Use
Wired Equivalent Privacy, introduced 1999. Broken by statistical attack using captured IVs in minutes. RC4 stream cipher misuse created cryptographic weaknesses that cannot be patched by configuration. No circumstance justifies using WEP. If you see WEP on the exam, it is always the wrong answer for security.
WPA2 -- Current Minimum
Wi-Fi Protected Access 2, mandatory since 2004. AES-CCMP encryption. WPA2-Personal uses a Pre-Shared Key (PSK) -- vulnerable to offline dictionary attacks if the PSK is weak or captured during the four-way handshake. WPA2-Enterprise uses 802.1X/RADIUS for per-user authentication. Enterprise mode is required for corporate deployments.
WPA3 -- Current Best Practice
Introduced 2018. WPA3-Personal uses SAE (Simultaneous Authentication of Equals) replacing PSK -- eliminates offline dictionary attacks. WPA3-Enterprise uses 192-bit cryptographic suite for high-security environments. Management Frame Protection (MFP) prevents deauthentication attacks. Forward secrecy prevents retroactive decryption of captured traffic.
Guest Network Isolation
Guest wireless networks must be isolated from the corporate network via firewall. Guests should reach the internet only. Guest VLAN should not be able to reach any internal RFC 1918 addresses. Client isolation prevents guest devices from communicating with each other on the same SSID.

Network Architecture in the Cloud
Cloud environments implement familiar network concepts (subnets, firewalls, routing) via software-defined constructs managed through APIs.
Virtual Private Cloud (VPC)
An isolated virtual network within a public cloud environment. AWS VPC, Azure VNet, GCP VPC. Contains subnets, route tables, internet gateways, and security groups. Provides network isolation equivalent to a private data center network. Multiple VPCs can be peered but are not connected by default.
Security Groups and NACLs
AWS Security Groups: stateful virtual firewalls attached to instances. Allow rules only -- implicit deny. NACL (Network Access Control List): stateless subnet-level filtering with explicit allow and deny rules. Both are required for comprehensive cloud network security. Security groups control instance-to-instance traffic; NACLs control subnet boundaries.
Transit Gateway and Peering
Transit Gateway allows hub-and-spoke connectivity between multiple VPCs and on-premises networks. VPC Peering connects two specific VPCs directly. Both require explicit route table entries and security group rules -- connectivity is never automatic. Security architecture must account for inter-VPC traffic inspection requirements.
Private Link and Endpoint Services
VPC Endpoints allow access to AWS services (S3, DynamoDB, etc.) over the private AWS network rather than the internet. Eliminates the need for internet gateway or NAT gateway for service access. Reduces exposure. PrivateLink enables access to third-party SaaS services via private IP addresses within the VPC.

Network Architecture & Compliance
Regulatory frameworks mandate specific network controls. Architecture decisions must align with applicable compliance requirements from the design phase.
PCI DSS Network Requirements
Cardholder Data Environment (CDE) must be isolated from all other networks with firewalls. All inbound and outbound CDE traffic must pass through documented firewall rules. No direct internet access to CDE. All non-console administrative access must be encrypted. Network diagrams must document all CDE connections and be reviewed quarterly.
HIPAA Network Requirements
Covered entities must implement technical safeguards to control access to PHI on networks. Encryption of PHI in transit is an addressable (strongly recommended) implementation specification. Access controls, audit controls, and transmission security are required. The specific technology is not mandated -- documentation of the decision and its rationale is.
CMMC and FedRAMP
CMMC Level 2 (DoD contractors) requires network protection, controlled access, and audit and accountability controls aligned with NIST SP 800-171. FedRAMP governs cloud services for federal agencies -- requires approved cloud providers with specific network controls. Network segmentation of CUI (Controlled Unclassified Information) is mandatory.
Documentation Requirement
All compliance frameworks require documented network architecture diagrams. Current, accurate diagrams must show all network zones, firewall boundaries, data flows, and system connections. Undocumented connections are a finding in any audit. Architecture documentation is a control, not just an administrative artifact.

OT/ICS Network Security
Operational Technology and Industrial Control Systems require network segmentation approaches that prioritize availability and safety alongside security.
The Purdue Model
Hierarchical reference model for ICS networks. Level 0: physical process. Level 1: intelligent devices (PLCs, RTUs). Level 2: process control systems. Level 3: manufacturing operations. Level 3.5: DMZ. Level 4: business systems. Level 5: enterprise. Traffic is only permitted to flow through defined gateways between levels -- not laterally within a level and not directly between non-adjacent levels.
IT/OT Convergence Risk
Modern ICS increasingly connects to IT networks and the internet for remote monitoring, data analytics, and vendor support. This IT/OT convergence destroys the air gap that historically protected OT systems. Protocols like Modbus, DNP3, and BACnet were not designed with security in mind. Connecting them to IT networks exposes them to threats they cannot withstand.
Data Diodes
One-way data transfer devices that physically enforce unidirectional communication. Data flows from OT to IT for monitoring -- no traffic can flow in the reverse direction. Hardware-enforced -- cannot be misconfigured. Used in critical infrastructure (power plants, water treatment) where any inbound network connection to OT is unacceptable regardless of software controls.
Safety vs. Security Tension
In OT, fail-closed (drop all traffic) may be the wrong security response -- shutting down a safety system because of a network anomaly could be more dangerous than the attack it was preventing. Security controls in OT must never create safety risks. Every control must be reviewed by both security and safety engineering teams before deployment.

Network Device Hardening
Network infrastructure devices are high-value targets. Hardening reduces the attack surface of routers, switches, and firewalls themselves.
1 Change default credentials: Default usernames and passwords on all network devices must be changed immediately on deployment. Shodan catalogs millions of devices accessible with default credentials.
2 Disable unused services: Telnet, HTTP management, CDP/LLDP on external interfaces, finger, and small services (echo, chargen) should be disabled on all devices.
3 Use encrypted management protocols: SSH v2 instead of Telnet, HTTPS instead of HTTP, SNMPv3 instead of v1/v2c. All management traffic must be encrypted.
4 Management ACLs: Restrict management plane access to authorized management station IP addresses only. No device should accept SSH connections from any IP address.
5 Control plane policing: Rate-limit traffic destined to the device's CPU. BGP, OSPF, and ICMP floods targeting the control plane can disable routing without touching the data plane.
6 Firmware currency: Network device firmware contains critical vulnerabilities. Establish a patch cadence and track vendor security advisories. Many organizations leave network device firmware unchanged for years -- a known attacker target.
7 Configuration backup and integrity: Network device configurations must be backed up securely and integrity-checked. An attacker who modifies a router configuration and removes the evidence has effectively backdoored the infrastructure silently.

Firewall Type Comparison
Exam questions often require distinguishing firewall types by capability, inspection depth, and use case.
Stateless Packet Filter
Inspects each packet independently. Layer 3/4. No session state. Very fast -- minimal latency. Cannot distinguish solicited from unsolicited traffic. No application awareness. Used in router ACLs and as a first filter at high-speed network boundaries. Cannot prevent SYN flood, fragmentation attacks, or application-layer exploits.
Stateful Inspection Firewall
Tracks TCP/UDP session state. Allows return traffic for established connections. Blocks unsolicited inbound packets. Layer 3/4. No application awareness. Cannot inspect encrypted content. Cannot identify application based on port misuse (e.g., malware using port 80). Standard for network perimeter but insufficient as the only control.
Application-Layer (Proxy) Firewall
Full Layer 7 inspection. Terminates and re-initiates connections -- true application proxy. Can understand HTTP, FTP, DNS semantics and block malformed requests. High latency compared to stateful. Cannot handle all protocols -- limited to those with proxy implementations. Excellent for web, DNS, and email traffic inspection.
Next-Generation Firewall
Combines stateful inspection, application identification (App-ID), user-identity integration, IPS, URL filtering, TLS inspection, sandboxing, and threat intelligence. Inspects traffic regardless of port -- identifies applications by behavior. Performance has improved to the point where NGFW is the standard for enterprise perimeters.
Web Application Firewall (WAF)
Specialized for protecting web applications. Inspects HTTP/HTTPS traffic for OWASP Top 10 attack patterns (SQLi, XSS, CSRF). Positive model (allow only known-good requests) or negative model (block known-bad). Deployed in front of web servers in the DMZ. Not a replacement for secure coding -- a compensating control.
Unified Threat Management (UTM)
All-in-one security appliance combining firewall, IPS, antivirus, URL filtering, VPN, and sometimes email security. Common in SMB environments where dedicated appliances are too costly. Single vendor dependency. Not recommended for high-throughput enterprise environments where each function benefits from dedicated hardware.

VPN vs. Zero Trust Architecture
Understanding when to use VPN versus ZTNA and the architectural trade-offs of each model.
VPN Strengths
Mature, well-understood technology. Encrypted network-level tunnel. Supports all protocols and applications. Works for site-to-site connectivity. Widely supported by all operating systems. Client-based enforcement of security policies possible with modern VPN clients. Appropriate for use cases requiring full network access (e.g., administrators, developers needing SSH to all servers).
VPN Weaknesses
Grants network-level access -- broad lateral reach once connected. Credential theft gives attacker the same access as the user. Performance degrades with global workforce. Difficult to enforce per-application access policies. Does not assess device health post-connection. VPN concentrators are high-value targets (Pulse Secure CVE-2019-11510, Citrix CVE-2019-19781 were actively exploited).
ZTNA Strengths
Per-application, per-session access control. Continuously validates identity and device posture. Eliminates broad network access grants. Application infrastructure is never exposed to users -- they connect to the broker, not the network. Works well for cloud-hosted applications where VPN adds unnecessary latency.
ZTNA Limitations
More complex to configure and maintain. Requires application inventory and policy definition for every resource. Not all applications are ZTNA-compatible without agent or proxy. Some legacy protocols cannot be tunneled. Not suitable for replacing site-to-site VPN for branch connectivity -- different use case. Hybrid environments use both.

2 A branch office needs secure, permanent connectivity to headquarters. Network administrators should be able to manage both sites from one location. Which VPN type is most appropriate? (Site-to-site IPSec VPN in tunnel mode. Permanent encrypted tunnel between gateways, not per-user.)
3 A firewall is configured to drop all traffic if a hardware failure occurs. What is this behavior called? (Fail-closed / fail-secure. The safe state for security appliances is to block all traffic on failure.)
4 An IDS is deployed on a SPAN port. An attacker exploits a vulnerability. The IDS generates an alert but no traffic is blocked. Why? (IDS is passive -- it monitors a copy of traffic. It cannot block. An IPS in inline mode would be needed to block.)
5 An attacker inside the network sends ARP replies claiming the gateway's IP maps to the attacker's MAC. Which Layer 2 control prevents this? (Dynamic ARP Inspection (DAI) validates ARP against the DHCP snooping binding table and drops illegitimate ARP replies.)

Module Summary
Network architecture is the physical instantiation of security policy. Every topology decision has a security consequence.
The structure of the network determines the blast radius of every breach. Segmentation, firewall placement, VPN architecture, and zero trust controls do not prevent all attacks -- they constrain the damage when attacks succeed. Design for failure.
10 Facts to Carry Out of This Lecture
1 Stateless firewalls filter per packet. Stateful firewalls track session state. NGFWs add application awareness, DPI, and integrated IPS. Each offers increasing capability at increasing cost.
2 DMZ hosts publicly accessible services between two firewalls. Web servers, email relays, and DNS belong in the DMZ. The internal database never belongs in the DMZ.
3 IPSec uses AH for integrity without encryption and ESP for both. Site-to-site VPNs use tunnel mode. IKEv2 is the current key exchange standard.
4 NAT hides internal addressing but is not a firewall. Do not use NAT as a substitute for proper access control rules.
5 Micro-segmentation controls east-west traffic within the same VLAN. VLAN segmentation controls traffic between VLANs. Both are needed in modern environments.
6 ZTNA grants per-application, per-session access. VPN grants per-network access. ZTNA is architecturally superior for remote access but does not replace site-to-site VPN.
7 IDS is passive (alerts only). IPS is inline (can block). A SPAN port IDS cannot stop an attack; an inline IPS can. NGFWs include integrated IPS.
8 802.1X blocks all switch port access until the device authenticates. DHCP snooping prevents rogue DHCP servers. DAI prevents ARP poisoning. All three are Layer 2 security controls.
9 SD-WAN uses commodity internet links with intelligent overlay routing. All traffic must be encrypted. SASE integrates SD-WAN with cloud-delivered security (CASB, ZTNA, FWaaS).
10 WPA3-Personal uses SAE, eliminating offline dictionary attacks against the PSK. WPA3-Enterprise requires 802.1X/RADIUS with per-user certificates. WEP is never acceptable.
