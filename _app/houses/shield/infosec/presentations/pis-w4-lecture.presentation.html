Slide 3 of 19  |  Topic 1: Authentication
The Authentication Problem Is Unsolved
Authentication has one job: prove that the entity claiming an identity is actually that entity. Every authentication failure in history is a variation of the same problem: the proof was insufficient.
The structural insight for Week 4
Authentication failures are not configuration errors — they are architectural choices that made the proof too weak for the threat environment. Week 4's authentication domain is about choosing the right proof for the threat model, not about adding controls until something sticks. NIST SP 800-63B-4 (published July 2025) Digital Identity Guidelines defines assurance levels (AAL1/AAL2/AAL3) to match proof strength to risk.
Slide 4 of 19
MFA Mechanism Hierarchy
Not all MFA is equal. The mechanism determines the attack surface. Choosing MFA means choosing which attacks you are still vulnerable to.
SMS OTP — Weakest
One-time code delivered by SMS. Vulnerable to SIM-swap attacks, SS7 interception, and social engineering of carrier support staff. NIST SP 800-63B-4 classifies SMS OTP as a restricted authenticator specifically because of public-switched-telephone-network weaknesses (SS7 interception, SIM-swap). Still better than password-alone; still phishable through real-time proxy attacks.
TOTP (RFC 6238) — Moderate
Time-based one-time password generated by an authenticator app (Google Authenticator, Authy, Microsoft Authenticator). HMAC-SHA1 over the current 30-second time window. Not phishing-resistant: an adversary-in-the-middle site can relay the code in real time before it expires. Defeated by real-time AiTM phishing kits (Evilginx2, Modlishka).
FIDO2 / WebAuthn — Strongest
Public-key cryptography bound to the origin domain (rpId). The authenticator signs a challenge from the specific relying party. A phishing site at login.bank-secure.com cannot receive a valid FIDO2 assertion intended for bank.com — the origin binding makes relay impossible. Hardware-bound FIDO2 authenticators are multi-factor cryptographic devices with verifier impersonation resistance, satisfying the AAL3 authenticator requirements in NIST SP 800-63B-4 §2.3 (AAL3).
The exam question the drilldown deck answers in depth
Why is FIDO2 phishing-resistant when TOTP is not? The answer is origin binding. TOTP generates a code the user types; that code can be relayed. FIDO2 generates a signature over a challenge that includes the relying party's origin; the signature is cryptographically invalid for any origin other than the one it was generated for. The attacker cannot relay what they cannot forge.
Slide 5 of 19
SSO and Federated Identity
Single sign-on reduces authentication friction. Federated identity extends that trust across organizational boundaries. The trade-off in both cases is blast radius: one compromised session reaches everything the identity is authorized to access.
SAML 2.0: XML Assertions
Exchanges signed XML assertions between IdP and SP. SP-initiated flow: user hits SP, SP redirects to IdP with AuthnRequest, IdP authenticates, returns signed Assertion to SP via HTTP POST. The assertion contains attributes (email, role) the SP uses for authorization. Signature validation is mandatory; skipping it breaks the trust chain.
OAuth 2.0 + OIDC: Token Flow
OAuth 2.0 is an authorization framework (delegated access), not an authentication protocol. OIDC adds the ID Token (JWT) to provide authentication on top of OAuth 2.0. The ID Token contains identity claims (sub, email, iss, iat, exp). Authorization Code + PKCE is the recommended flow for web and native apps. Use OIDC for authentication; use OAuth 2.0 scopes for resource access.
Kerberos: Ticket-Based Enterprise
Active Directory's native authentication protocol. KDC issues TGT at login; client exchanges TGT for service tickets to specific services without re-entering credentials. Tickets are time-bounded (default 10 hours). Kerberoasting targets service account SPNs to extract ticket hashes for offline cracking. Pass-the-Ticket attacks replay stolen tickets from memory.
Slide 6 of 19  |  Topic 2: Identity Management
Access Control Models: How Permissions Are Decided
Authentication answers "who is this." Access control answers "what are they allowed to do." The model determines the mechanism, the audit surface, and the failure mode when over-permissioning occurs.
Least Privilege Is Not a Configuration
Least privilege means each identity has exactly the permissions required to perform its function, no more. The failure mode is privilege creep: over time, roles accumulate permissions that were temporarily granted and never revoked. Access reviews (quarterly or triggered by role change) are the operational control that enforces least privilege across the account lifecycle.
PAM: Privileged Access Management
Privileged accounts (domain admin, root, service accounts with broad permissions) require elevated controls: vaulted credentials rotated after every use, just-in-time provisioning (access granted only for the duration of the task), session recording, and approval workflows. CyberArk, BeyondTrust, and HashiCorp Vault are common PAM platforms. Without PAM, compromised admin credentials have no expiry and no visibility.
Slide 7 of 19
Account Lifecycle: Joiner, Mover, Leaver
Identity management is only as strong as the process that handles transitions. The majority of insider threat cases and post-breach forensic findings involve accounts that should have been deprovisioned or modified and were not.
Joiner: Provisioning
New employee. Account created with a role-appropriate baseline set of permissions. Process must be driven by HRIS data, not manual IT requests, to prevent over-provisioning. User receives least-privilege access for their role on day one. No "copy user A's permissions to user B" — that propagates every permission A ever accumulated, including ones they should not have had.
Mover: Transfer / Promotion
Employee changes role or department. The correct action is: revoke old-role permissions, add new-role permissions. The common failure: add new-role permissions without revoking old ones. Result: the user accumulates permissions from every role they have ever held. This is privilege creep at scale and is the source of most over-privileged user accounts found in incident investigations.
Leaver: Deprovisioning
Employee terminates. Account must be disabled (not just password-reset) within hours of departure, ideally triggered by HRIS termination event with no manual step required. Disabled means: AD account disabled, active sessions revoked (IdP session invalidation, Kerberos ticket expiry), email rerouted, MFA devices deregistered. Orphan accounts — active accounts with no current user — are a primary attack vector for initial access via credential spray.
Routine identity audits of enterprise Active Directory environments consistently find significant fractions of active user accounts belonging to former employees whose terminations were never propagated to IT. Those orphan accounts retain full access to file shares, internal applications, and email. The accounts are usually missed because the deprovisioning process is manual and depends on HR notifying IT by email. Automation triggered by the HRIS termination event is the only reliable fix.
Slide 8 of 19  |  Topic 3: Risk Governance
Risk Is a Formula, Not a Feeling
Risk management is the discipline of making defensible decisions about uncertainty. The language is precise: threat, vulnerability, likelihood, impact. Conflating them produces unreliable risk assessments.
Quantitative: ALE = AV x EF x ARO
Asset Value (AV): dollar value of the asset. Exposure Factor (EF): percentage of asset value lost in a single incident. Annualized Rate of Occurrence (ARO): expected frequency per year. Single Loss Expectancy (SLE): AV x EF. Annualized Loss Expectancy (ALE): SLE x ARO. If a $500,000 database (AV) has a 40% exposure factor and a 0.25 ARO: SLE = $200,000, ALE = $50,000/year. Any control costing less than $50,000/year is economically justified.
Qualitative: Risk Matrix
Rates likelihood and impact on ordinal scales (Low/Medium/High or 1-5). Produces a heat map that communicates risk priorities to executives without requiring financial estimates. Faster to produce than ALE; less precise. Useful when asset values are difficult to quantify (reputation, regulatory standing). Both methods are valid; the organization's risk appetite and regulatory context determine which to use. ISO/IEC 27005:2022 covers both approaches (scope statement is on the free landing page; full standard is paywalled).

Risk Treatment and Governance Frameworks
Once a risk is quantified, it must be treated. The organization chooses a response. The governance framework defines the process, the controls catalog, and the audit evidence requirements.
Four Risk Treatment Options
Mitigate (Reduce): apply a control that reduces likelihood or impact. Patching a critical CVE is mitigation.
Transfer (Share): shift financial consequence to another party. Cyber insurance, indemnification clauses.
Avoid (Eliminate): stop the activity that creates the risk. Do not collect certain data if its protection cost exceeds its business value.
Accept (Retain): document the residual risk and carry it. Risk acceptance must be signed by the risk owner, time-bounded, and re-evaluated at each review cycle. Unreviewed acceptances are audit findings.
Framework Landscape
NIST CSF 2.0: six functions (Govern, Identify, Protect, Detect, Respond, Recover). Voluntary framework. The Govern function was added in v2.0 (February 26, 2024) to anchor risk management at the executive level.
NIST RMF (SP 800-37 Rev. 2): seven-step process: Prepare, Categorize, Select, Implement, Assess, Authorize, Monitor. Required for U.S. federal information systems under FISMA (44 U.S.C. §3554).
ISO/IEC 27001:2022: ISMS standard. Certifiable. Annex A has 93 controls across four themes (Organizational, People, Physical, Technological). Full text is paywalled; scope and structure are on the free landing page.
HIPAA Security Rule: administrative, physical, technical safeguards for ePHI. Required risk analysis and risk management program with documented findings.
What distinguishes a compliance posture from a security posture
A compliance posture demonstrates adherence to a framework's requirements. A security posture reduces actual risk. The two are correlated but not identical: an organization can be SOC 2 compliant and breach-prone simultaneously if the framework controls are implemented at the letter but not the spirit. The NIST CSF's Govern function (added in version 2.0, February 26, 2024) explicitly addresses this by requiring executive accountability for risk tolerance, not just control checklists.

Business Impact Analysis: Putting Numbers on Downtime
BIA answers the question governance cannot answer alone: what does it actually cost when a system is unavailable? Those numbers drive BCP, DR architecture, and recovery investment decisions.
MTD vs. RTO Relationship
MTD (Maximum Tolerable Downtime) is how long the business can survive without the system before catastrophic loss occurs. RTO (Recovery Time Objective) is the target time to restore functionality. RTO must be less than MTD — if it is not, no technically achievable recovery window keeps the business viable. The gap between RTO and MTD is your operational margin.
RPO and Backup Architecture
RPO (Recovery Point Objective) defines the maximum acceptable data loss measured in time. An RPO of 4 hours means you can afford to lose up to 4 hours of transactions. That drives backup frequency: continuous replication for RPO of minutes; daily snapshots for RPO of 24 hours. RPO is a business decision. Backup frequency and replication architecture are the technical implementation of that decision.
BCP vs. DRP
BCP (Business Continuity Plan) covers all critical business functions: how operations continue when infrastructure is unavailable. DRP (Disaster Recovery Plan) is the technical subset: how IT systems are restored. BCP is the broader document; DRP is invoked within BCP for infrastructure events. Both require testing: tabletop exercises, simulation drills, and full DR failover tests at defined intervals. NIST SP 800-34 provides the federal continuity planning guide.
Slide 11 of 19  |  Topic 4: Incident Response
The IR Lifecycle: NIST SP 800-61r3 (4 phases, 6-step pedagogical expansion)
Incident response is not improvisation. It is a documented process executed under pressure. Every deviation from the process during an active incident adds to dwell time and reduces the quality of forensic evidence.
Containment: The Critical Decision
Isolation vs. Shutdown: disconnecting a compromised host from the network preserves volatile memory evidence (running processes, network connections, encryption keys in RAM). Shutdown destroys it. In most cases, isolate first, image later. Exception: if the system is actively exfiltrating data, the network impact of continued operation may justify immediate shutdown. Document the decision and rationale at the time it is made.
Evidence Preservation: Order of Volatility
Forensic collection follows volatility order: most volatile first. CPU registers and cache (nanoseconds) → RAM contents (seconds to minutes) → network state and ARP cache → running processes → disk (persistent). Tools: Volatility 3 for memory forensics, FTK Imager for disk imaging, Velociraptor for live response at scale. A forensic image is a bit-for-bit copy with cryptographic hash verification (SHA-256 of the image). Chain of custody documentation starts at collection.
Slide 12 of 19
Containment in Practice
Containment has three phases: short-term (stop bleeding), long-term (hold the line while eradicating), and the intelligence question (do you let the attacker persist briefly to gather attribution data?).
Short-Term Containment
Immediate network isolation of confirmed-compromised hosts. Options: VLAN isolation (quarantine VLAN with no inter-VLAN routing), NAC quarantine (802.1X places host in restricted segment), firewall host isolation (ACL denies all traffic except forensic collection source). Cloud: revoke IAM role, snapshot instance before termination, place security group allowing only forensic access. Speed over precision — contain first, verify scope second.
Long-Term Containment
Patching the entry vector, resetting compromised credentials, placing enhanced monitoring on adjacent systems. The goal is maintaining business operations while the full scope is determined and eradication proceeds. Long-term containment acknowledges that eradication may take days to weeks in complex environments. A rebuilt "clean" system that shares the same unpatched network path as the compromised system is not contained.
The Deception Option
Allowing a compromised system to remain briefly monitored (with data exfiltration blocked) can yield attribution data, C2 infrastructure, and full attack path mapping. This is a deliberate intelligence-gathering decision that requires senior authorization, legal review, and documented risk acceptance. Never done without explicit approval chain. See NIST SP 800-61r3 (April 2025), Table 1 — IR Lifecycle / CSF 2.0 mapping. The "delayed containment" decision is instructional content reflecting industry practice; the explicit "senior authorization, legal review, documented risk acceptance" gating is NOT a verbatim NIST requirement and should be treated as common-practice guidance.
The forensic evidence trap most teams fall into
Reimaging a compromised system immediately destroys all forensic evidence. The correct sequence is: contain → image → hash verification → chain of custody → then reimage. If a P0 incident requires immediate system recovery that will destroy evidence, that trade-off must be documented with an authorized decision-maker's signature at the time it is made, not reconstructed after the fact.
Slide 13 of 19
Lessons Learned: The Phase Most Teams Skip
An incident that does not produce documented findings, root cause analysis, and playbook updates is an investment in the same breach happening again. The post-incident review is where organizational security actually improves.
Post-Incident Review (PIR) Structure
Conducted within 2 weeks of incident closure. Attendees: IR team, affected business owners, relevant technical leads. Not a blame assignment exercise. Outputs: (1) timeline of attacker actions, (2) timeline of defender actions, (3) root cause statement, (4) gap analysis between what detection should have caught and what it actually caught, (5) specific, owned, time-bounded remediation actions. Generic action items ("improve monitoring") that are not owned and dated are equivalent to no action item.
Playbook Updates Are Mandatory, Not Optional
Every incident surfaces at least one gap in the existing IR playbook: a procedure that did not exist, a tool that was not available, a communication step that was missing, or a decision path that was ambiguous under pressure. That gap must be closed before the next incident. Playbook currency is an audit criterion under NIST SP 800-61r3. An IR playbook that has not been updated in 12 months is evidence that lessons learned is not being practiced.
The U.S. Office of Personnel Management breach (2014-2015): OPM had experienced a 2014 intrusion that should have triggered a lessons-learned cycle including improved monitoring and network segmentation. The improvements were not fully implemented when a second attacker entered through a similar vector in 2015 and exfiltrated security clearance data for 21.5 million individuals. The second breach was partially enabled by the first breach's lessons not being acted on. Source: U.S. House Committee on Oversight and Government Reform — The OPM Data Breach (September 7, 2016).

Digital Forensics: Evidence That Holds Up
Forensics is not about finding what happened. It is about collecting evidence in a manner that withstands legal scrutiny. How you collect is as important as what you collect.
Legal Admissibility Requirements
Evidence must be: relevant (directly related to the matter), reliable (collected with validated tools, documented process), authentic (provably from the source claimed), and complete (no selective collection that misrepresents the full picture). Chain of custody documentation tracks every person who accessed the evidence and every action taken, from collection through court. A gap in chain of custody is a defense attorney's tool to challenge admissibility.
Memory Forensics
RAM contains: running processes and their arguments, network connections and their sockets, encryption keys loaded in memory, injected code that is not on disk (fileless malware), and recently accessed file handles. Volatility 3 (open source) is the standard analysis framework. Key plugins: windows.pslist (process list), windows.netscan (network connections), windows.malfind (injected code detection). Memory dump must precede any host action that modifies RAM state.
Disk and Network Artifacts
Disk: NTFS timestamps ($MFT), prefetch files (evidence of execution), Windows Event Logs (Security, System, Application, PowerShell), browser history, registry hives (run keys, UserAssist, ShimCache). Network: NetFlow records (source, destination, bytes, duration — no payload), full PCAP (packet content — where retention is legal), DNS query logs, proxy access logs. Network artifacts survive host reimaging. Collect them independently and in parallel with host forensics.
The difference between incident response forensics and legal forensics
IR forensics optimizes for speed — find the attacker, contain the breach, determine scope. Legal forensics optimizes for admissibility — preserve evidence with documented chain of custody for potential litigation or prosecution. An IR team should default to legal forensics standards even when no prosecution is planned, because the organization cannot predict at collection time whether it will need evidence to be admissible later.
Slide 15 of 19  |  Synthesis
How the Four Domains Form One System
These are not independent topics. Authentication, identity, governance, and response form a chain. A break in any link propagates to all the others.
Authentication Fails → Identity Management Fails
If authentication can be bypassed (credential stuffing, pass-the-hash, AiTM), identity management cannot save you. An attacker with a valid session token has all the permissions that identity was granted. Identity management controls only what a successfully authenticated identity can reach — it has no mechanism to detect that the identity was stolen.
Governance Defines the Blast Radius
A risk governance program that approved over-permissive RBAC roles, accepted password-only authentication for high-value systems, or deferred deprovisioning automation defines the blast radius before the incident begins. IR works within whatever governance established. The fastest IR playbook cannot recover data that governance allowed to be over-exposed to begin with.

Week 4 Decision Framework
SY0-701 performance-based questions for Week 4 domains center on selecting the right control or protocol for a described scenario. Run this chain.
Authentication Scenario Decisions
Need phishing-resistant MFA: FIDO2/WebAuthn or smart card (AAL3).
Need to defeat push bombing: number-matching MFA or FIDO2.
Cross-org SSO with XML assertions: SAML 2.0.
Delegated API access (not authentication): OAuth 2.0.
Authentication over OAuth: OIDC (adds ID Token).
Enterprise Windows authentication: Kerberos via AD.
Wireless user auth without PSK: 802.1X + RADIUS + EAP.
Risk and Governance Scenario Decisions
Dollar-value risk calculation: ALE = SLE x ARO.
Federal system risk framework: NIST RMF (SP 800-37 Rev. 2).
Voluntary cross-sector framework: NIST CSF 2.0.
Certifiable ISMS standard: ISO/IEC 27001.
Healthcare ePHI requirements: HIPAA Security Rule.
EU personal data protection: GDPR.
Residual risk handling: accept (signed, time-bounded, reviewed).
Incident Response Scenario Decisions
IR lifecycle source document: NIST SP 800-61r3.
Compromised host: isolate or shut down? Isolate (preserves memory).
Evidence collection order: most volatile first (RAM before disk).
Memory forensics tooling: Volatility 3.
Who is on the IR team: CSIRT (Computer Security Incident Response Team).
After the incident: PIR within 2 weeks, playbook update mandatory.
Identity Management Scenario Decisions
Employee transfers role: revoke old, add new — not additive.
Inherited permissions between users: wrong; use role-based baseline.
Admin credential vaulting: PAM platform (just-in-time, session recording).
MAC model for classified systems: Bell-LaPadula (no read up, no write down).
Fine-grained conditional access: ABAC (attribute-based).
Quarterly access reviews: least-privilege enforcement, prevents privilege creep.

In-Class Task: Breach at Veridian Financial
You have read the four domains. Now respond to an active incident. This 35-minute structured exercise applies authentication analysis, identity audit, risk decision-making, and IR execution simultaneously.
Scenario brief
Veridian Financial Group, a mid-size investment firm, has detected anomalous behavior. The SOC has raised an incident. The CISO has activated the CSIRT. You are the lead analyst. You must determine how the attacker got in, what they accessed, make a containment decision, and document your risk acceptance for the response trade-offs you make — all while the incident clock is running.
Task 1 (10 min): Authentication Forensics
The attacker bypassed MFA. Analyze the authentication logs provided. Determine which MFA mechanism was in use, which attack technique defeats it, and what MFA upgrade would have prevented this breach. Cite NIST SP 800-63B-4 assurance level for your recommendation.
Task 2 (10 min): Identity Blast Radius Audit
A compromised service account has been identified. Using the permissions table provided, determine: (1) what this account can reach, (2) what RBAC violations exist (over-permissioned roles), and (3) what emergency deprovisioning actions must be taken in what order.
Task 3 (10 min): Containment Decision + Risk Register
Three affected systems have been identified. You must decide: isolate or shut down, and in what order. Then enter the incident as a new risk register entry: threat, vulnerability, likelihood, impact, treatment decision, residual risk, owner, review date.
