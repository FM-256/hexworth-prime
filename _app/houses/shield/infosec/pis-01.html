Mission Context

The CIA triad is not an acronym -- it is a classification system. Every specimen in this facility is assessed against three properties: is it contained (confidentiality), unmodified (integrity), and accessible to authorized operators (availability)? A breach of any one property constitutes a containment failure. This module establishes the vocabulary all subsequent protocols are built on.

CIA Triad

The CIA triad is the foundational framework of information security. Every security decision, control selection, and breach classification maps back to one or more of these three properties. SY0-701 Objective 1.1 requires you to identify which property is violated in scenario-based questions.

C Confidentiality

Information is accessible only to authorized parties. Violated when data is exposed to unauthorized individuals -- data breaches, eavesdropping, unencrypted transmission.

I Integrity

Data is accurate and unaltered except by authorized processes. Violated when data is modified without authorization -- MITM attacks, database tampering, malicious code injection.

A Availability

Systems and data are accessible when needed by authorized users. Violated when access is disrupted -- DoS attacks, ransomware encryption, hardware failures without redundancy.

Non-repudiation is often listed alongside the triad. It is the assurance that an action cannot be denied after it was performed -- that a sender cannot claim they did not send a message, or a user cannot deny accessing a file. Non-repudiation is provided by digital signatures and audit logging.

Operational Context

The 2016 Bangladesh Bank heist: attackers sent SWIFT transfer instructions for $951 million. $81 million was transferred before the scheme was detected. The attack violated integrity (fraudulent instructions injected), and non-repudiation controls were insufficient to immediately identify the attackers. $870 million was blocked by a spelling error in one of the transfer requests.

AAA Framework

Authentication, Authorization, and Accounting form the access governance framework for all systems. SY0-701 Objective 1.2 tests your ability to differentiate these three components and identify which is missing or violated in scenario questions.

Component Question It Answers Mechanisms Example
Authentication Who are you? Passwords, MFA, biometrics, certificates, smart cards User logs in with username + TOTP code
Authorization What are you allowed to do? Role-based access control (RBAC), ACLs, permissions, group policies Authenticated user can read reports but not delete records
Accounting What did you do? Audit logs, SIEM event records, syslog, NetFlow, session recording Log entry: user accessed financial record at 14:32 from 10.0.0.22

RADIUS vs TACACS+ is a common exam topic. RADIUS combines authentication and authorization into a single process and uses UDP. TACACS+ separates all three AAA functions into independent processes and uses TCP, providing more granular control and better reliability. Cisco devices in enterprise networks typically use TACACS+ for device administration and RADIUS for network access.

Operational Context

Every door in Hexworth Containment uses AAA. The perimeter gate authenticates your clearance badge, your clearance level authorizes which labs you can enter, and every access event is logged. There is no anonymous entry -- and accounting ensures no one can deny what they accessed.

Non-Repudiation Mechanisms

Non-repudiation is the assurance that an action cannot be denied after it has been performed. It is distinct from authentication -- authentication proves identity at login, while non-repudiation proves that a specific user performed a specific action. SY0-701 Objective 1.2 includes non-repudiation as a security concept you must be able to apply.

Mechanism How It Provides Non-Repudiation
Digital Signatures Signed with the sender's private key -- only they could have produced that signature. Used in email (S/MIME, PGP) and code signing.
Audit Logs Time-stamped, tamper-evident records of who did what and when. Stored on write-once media or forwarded to a separate SIEM so the subject cannot delete them.
PKI Certificates Tie a public key to a verified identity through a trusted Certificate Authority. Actions signed with a certificate-backed key are legally attributable to the certificate holder.
Video Surveillance + Biometrics Physical-layer non-repudiation -- proves a specific person was in a specific location at a specific time.
Operational Context

When a technician handles a specimen in this facility, the action is logged, camera-recorded, and biometrically attributed. If a specimen escapes, there is no "it wasn't me." Non-repudiation is what makes accountability enforceable.

Security Gap Analysis

A gap analysis compares an organization's current security posture against a desired target state -- typically a framework (NIST CSF, ISO 27001), regulation (HIPAA, PCI-DSS), or certification baseline. SY0-701 Objective 1.1 includes identifying gaps in security controls as a core skill.

Target State

The security posture defined by the framework, regulation, or policy you are measured against. Example: NIST CSF "Protect" function requires all data at rest to be encrypted.

Current State

What controls are actually implemented. Determined through interviews, document review, technical scanning, and configuration audits.

Gap Identification

Delta between target and current state. Each gap is a control that is missing, partially implemented, or implemented incorrectly.

Remediation Roadmap

Prioritized list of actions to close each gap, with risk-based prioritization. High-risk gaps with low implementation cost are addressed first.

Operational Context

Before Hexworth Containment upgrades any lab, an exposure sweep is run against the current configuration. Every missing control is documented. Every gap is assigned a risk score. Nothing is upgraded without knowing exactly what the gap costs if left open.
