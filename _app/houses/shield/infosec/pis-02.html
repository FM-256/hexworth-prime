PIS-02: Security Controls

PIS-02 SY0-701: 1.1, 1.3

Security Controls

Course Index

Learning Objectives

  • Classify security controls by category: technical, administrative, and physical
  • Identify control functions: preventive, detective, corrective, deterrent, compensating, and directive
  • Apply defense-in-depth principles to layer controls across multiple security tiers
  • Recognize when change management is a security control requirement
Mission Context

Controls are not bureaucratic requirements -- they are the physical and logical barriers between an attacker and your systems. A control taxonomy tells you what you have, what it does, and what happens when it fails. When the 2013 Target breach happened, it wasn't a single missing control -- it was missing controls at every layer simultaneously. That is what this module teaches you to prevent.

Control Categories

Security controls are classified by the type of resource or mechanism they use. SY0-701 Objective 1.1 requires you to identify the category of each control in scenario questions.

Category Definition Examples
Technical Implemented through hardware or software systems Firewalls, IDS/IPS, encryption, access control lists, MFA, endpoint protection
Administrative Implemented through policies, procedures, and training Security policies, acceptable use policies, change management, background checks, security awareness training
Physical Implemented through physical barriers and environmental controls Locks, mantraps, security cameras, guards, badge readers, cable locks, biometric entry
Operational Context

Every lab in this facility uses all three categories simultaneously. Technical: badge readers with encrypted credentials. Administrative: protocols governing who can authorize lab access. Physical: reinforced vault doors with biometric verification. No single category is sufficient -- all three must function.

Control Functions

Beyond category, each control has a function -- the action it takes to manage a risk. SY0-701 Objective 1.3 tests your ability to identify control functions in scenario questions. A single physical control can serve multiple functions.

Preventive

Stops an attack before it occurs. A firewall rule that blocks malicious traffic is preventive. A lock that stops unauthorized entry is preventive.

Detective

Identifies and alerts when an attack or violation occurs. IDS alerts, audit logs, security cameras, and SIEM events are detective controls.

Corrective

Restores the system after an incident. Backup restoration after ransomware, incident response procedures, and patch deployment after a vulnerability is exploited.

Deterrent

Discourages attackers from attempting an attack. Warning signs, visible cameras, and published security policies create deterrence without preventing action directly.

Compensating

Substitutes for a primary control when it cannot be implemented. Legacy system that cannot be patched -- network isolation compensates for missing patches.

Directive

Guides behavior through policy. Acceptable use policies, code of conduct, and regulatory compliance requirements are directive controls.

Exam key distinction: a lock on a door is preventive. A camera monitoring that door is detective (and also deterrent). A sign saying "Authorized Access Only" is deterrent (and also directive).

Operational Context

Lab containment barriers serve different functions at each layer. The sealed door is preventive. The motion sensor inside is detective. The emergency lockdown protocol is corrective. No single control handles all three functions -- layering is not optional.

Defense in Depth

Defense in depth is the principle that security controls should be layered so that if one control fails, others remain. SY0-701 Objective 1.3 addresses this as a core architectural approach. No single control is sufficient -- every control can be bypassed. Depth means the attacker must defeat multiple independent layers to succeed.

Layer Example Controls Category / Function
Perimeter Firewall, DMZ, intrusion prevention system, DDoS mitigation Technical / Preventive
Network Network segmentation, VLANs, access control lists, network monitoring Technical / Preventive + Detective
Host Endpoint detection, host-based firewall, patch management, disk encryption Technical / Preventive + Detective
Application Input validation, WAF, secure coding, code review, least privilege Technical + Administrative / Preventive
Data Encryption at rest, data loss prevention (DLP), data classification, backups Technical / Preventive + Corrective
Physical Guards, locks, biometric entry, mantraps, security cameras Physical / Preventive + Detective + Deterrent
Human Security awareness training, background checks, incident reporting culture Administrative / Preventive + Directive

The 2013 Target breach illustrates failed defense in depth: attackers entered via a third-party HVAC vendor (weak perimeter control), moved laterally across an unsegmented network (no network layer control), reached POS systems (no host layer isolation), and exfiltrated 40 million card numbers. Each missing layer created a path.

Operational Context

Hexworth Containment uses six independent barrier systems on every BSL-3 and BSL-4 lab. Breach one, you have five more to defeat. Every one of them logs the attempt. This is what multi-barrier containment looks like in practice.

Control Selection and Change Management

SY0-701 Objective 1.3 includes change management as an aspect of security control administration. Security controls must be documented, version-controlled, and changed through a formal process. An uncontrolled change to a firewall rule, an access control list, or an encryption policy can introduce a vulnerability as severe as any external attack.

Change management in security includes: a change request with documented justification, risk assessment of the change, review and approval by a change advisory board (CAB), implementation in a test environment first, rollback planning if the change fails, and post-change verification that the control still functions as intended.

Common exam scenario: An administrator modifies a firewall rule to allow a new business application without going through the change management process. The rule accidentally opens a path to a sensitive server. This is a change management failure -- the technical control was correct before the change; the administrative control (change management procedure) was bypassed.

Operational Context

No protocol in this facility is changed without a containment directive. Every modification to a barrier system requires documented justification, approval from the facility commander, and a verification sweep after implementation. Controls that change without process become liabilities.
