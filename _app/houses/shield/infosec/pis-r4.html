Windows and Linux Security Architecture

Both Windows and Linux use a privilege separation model: standard users operate with limited rights, and elevated privileges require explicit escalation. Understanding each OS's security model is required for Security+ SY0-701 Objective 3.1 and for practical incident response on mixed-environment networks.

Windows
  • Accounts: Local accounts (SAM database) and domain accounts (Active Directory). SYSTEM account has highest local privilege.
  • Privilege escalation: UAC (User Account Control) prompts for administrative tasks. Frequently targeted for bypass.
  • Access control: NTFS permissions + Active Directory Group Policy Objects (GPOs). SID-based access control.
  • Logging: Windows Event Log -- Security, System, Application channels. Event IDs 4624 (logon), 4625 (failed logon), 4648 (explicit credentials) are critical.
  • Registry: Centralized configuration database. Persistence techniques frequently abuse HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run.
Linux
  • Accounts: Defined in /etc/passwd. Passwords hashed in /etc/shadow (root-only read). UID 0 = root.
  • Privilege escalation: sudo grants elevated privileges to specific users. Misconfigured sudo rules are a frequent privilege escalation vector.
  • Access control: DAC (owner/group/other permissions) + optional SELinux or AppArmor mandatory access control.
  • Logging: /var/log/auth.log (Debian/Ubuntu) or /var/log/secure (RHEL/CentOS) for authentication. syslog/journald for system events.
  • Services: systemd manages services. Unexpected enabled services are an exposure indicator.
Operational Context:

Facility workstations run Windows. Servers run Linux. A containment operator needs to read both sets of logs, understand both permission models, and recognize anomalies in both environments.

File Permissions

File permissions determine which users and processes can read, write, or execute files. Misconfigured permissions are among the most common and consequential security findings in any environment.

Linux file permissions. Each file has an owner, a group, and a set of permissions for owner, group, and others. Permissions are displayed as a 10-character string:

-rwxr-xr--Owner: read/write/execute | Group: read/execute | Others: read only
-rw-------Owner: read/write | Group: none | Others: none (private key file -- correct)
-rwxrwxrwxWorld-writable executable -- a security finding in any context
-rwsr-xr-xSUID bit set -- executes as the file owner, not the calling user. High-value escalation target.

Windows NTFS permissions. Windows uses Access Control Lists (ACLs) on NTFS volumes. Each file and folder has a Discretionary ACL (DACL) listing Access Control Entries (ACEs) that grant or deny permissions to specific users or groups. Key permissions: Full Control, Modify, Read and Execute, Read, Write. Inheritance means child objects typically inherit parent permissions -- a misconfigured parent folder can expose all its contents.

Critical finding patterns: world-writable directories in the system path (DLL hijacking), users with write access to service executables (service binary replacement), Everyone group with modify permission on sensitive directories.

Operational Context:

Every file in the vault has an owner and an access list. A world-writable file in a critical directory is an open contamination pathway. Permissions are containment policy, enforced by the OS kernel.

User Accounts and Privilege Management

User accounts are the primary identity mechanism in any OS. Account management practices directly determine the blast radius of a compromised credential.

Account Type / ConceptSecurity Implication
Local Administrator (Windows)Full control over the local machine. Default local admin accounts should be disabled or renamed. Local admin password reuse across machines is a critical finding -- compromising one machine compromises all sharing the same password.
Domain Admin (Windows AD)Highest privilege in a Windows domain. Should be used only for domain-level tasks -- never for daily work. Compromise of a Domain Admin account is effectively total network compromise.
Root (Linux)Unrestricted access to all system resources. Direct root login via SSH should be disabled (PermitRootLogin no in sshd_config). All privileged operations should use sudo with logging.
Service AccountsAccounts used to run services and scheduled tasks. Should have minimum required permissions only. Service accounts with domain admin rights are a common attack target and configuration failure.
Shared / Generic AccountsAccounts used by multiple people. Should not exist. Shared accounts destroy the Accounting pillar of AAA -- you cannot attribute actions to an individual.
Orphaned AccountsAccounts for departed employees or decommissioned systems that remain active. A common insider threat vector and persistence mechanism. Account lifecycle review is a standard audit item.
Operational Context:

Every operator in this facility has an individual account tied to their clearance level. Shared accounts do not exist here. If something goes wrong, we know whose credentials were used. That is not optional.

Services and Attack Surface Reduction

Every running service is a potential exposure point. Services that listen on network ports are particularly significant because they accept external input -- which is where exploits enter. A service that exists but is not needed is a vulnerability waiting to be exploited.

Hardening principle: disable what you do not need. A freshly installed Windows Server 2022 has dozens of services enabled by default. Many are never needed in production. The Center for Internet Security (CIS) Benchmarks provide hardening guidance for every major OS.

Service / FeatureRisk if Left Enabled
Windows Print SpoolerPrintNightmare (CVE-2021-34527) allowed remote code execution via the print spooler service. Should be disabled on DCs and servers that do not need printing.
SMBv1Legacy protocol exploited by EternalBlue (WannaCry/NotPetya). Should be disabled on all systems -- no modern software requires SMBv1.
LLMNR / NetBIOSName resolution protocols that broadcast queries on the local network. Responder tool exploits these to capture NTLMv2 hashes. Should be disabled.
Default Apache/Nginx installsDefault installations expose version banners, test pages, and directory listing. Each reveals information useful for targeting. Disable defaults, enable only required modules.
Unnecessary cron jobs (Linux)World-writable scripts called by root cron jobs are a privilege escalation path. Cron job review is standard in Linux privilege escalation audits.
Operational Context:

Every unnecessary service running in the facility is an unlocked door in an empty corridor. You may not think anyone will try it. Someone will try it. Close every door you do not need open.

Patch Management Basics

Patch management is the process of identifying, testing, and applying software updates that fix security vulnerabilities. It is one of the highest-impact security controls available -- the majority of successful breaches exploit vulnerabilities for which patches existed at the time of the attack.

The patch-breach gap. The 2017 Equifax breach (66 days after patch release), the 2020 Pulse Secure VPN breach (months after patch release), and the 2021 ProxyLogon Exchange exploitation (days after patch release) all share the same root cause: the organization did not apply the available patch before attackers exploited the vulnerability.

ConceptDefinition / Security Relevance
CVSS ScoreCommon Vulnerability Scoring System. 0-10 scale. Critical (9.0-10.0) and High (7.0-8.9) vulnerabilities should be prioritized for immediate patching, especially if actively exploited.
CISA KEVKnown Exploited Vulnerabilities catalog. CISA maintains a list of CVEs being actively exploited in the wild. Federal agencies must patch KEV items within defined deadlines. Best practice for all organizations.
Patch TestingCritical patches should be tested in a non-production environment before deployment to prevent outages. However, for actively exploited vulnerabilities, the risk of delaying to test may exceed the risk of deploying untested.
Compensating ControlsWhen a patch cannot be immediately applied (legacy systems, vendor constraints), compensating controls reduce exposure: isolate the system, disable the vulnerable feature, apply network-level mitigations.
End of Life (EOL)Software past its support date receives no security patches. Running EOL software (Windows XP, Server 2008) means known vulnerabilities will never be fixed. Isolation or replacement is required.
Operational Context:

In this facility, inoculation delay is a containment breach in slow motion. The pathogen is known. The fix is available. Every day without the patch is a day the facility is compromised and you just haven't noticed yet.

Self-Check

  1. A Linux file has permissions -rwsr-xr-x and is owned by root. Why is this a security concern, and what is this called?
  2. An audit finds a service account in Active Directory that is a member of the Domain Admins group. The account is used to run a nightly backup script. What is wrong with this configuration and what should it be changed to?
  3. A server is running Windows Server 2012 R2, which reached end of life in October 2023. The vendor says a critical application cannot be migrated for 18 months. What compensating controls should be implemented?
  4. A new critical vulnerability is published on Monday with a CVSS score of 9.8. Proof-of-concept exploit code is publicly available. The IT team's standard patch cycle runs on Fridays. Should they wait? Justify your answer.

If you can answer all four without referring back, proceed to PIS-R5: Security Mindset.
