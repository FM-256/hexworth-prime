Mission Context

The external network is a contagion vector as much as a specimen is. Adversaries who cannot breach the facility directly will target the communication channels -- flooding the alert system, poisoning the internal DNS, or silently reading every packet between workstations. Network-layer attacks undermine the infrastructure trust model itself.

Denial of Service and Distributed Denial of Service

Denial-of-Service (DoS) attacks exhaust a target's capacity to process legitimate requests. Distributed DoS (DDoS) coordinates thousands of compromised hosts (a botnet) to amplify the attack volume beyond what any single machine can generate. SY0-701 Objective 2.4 requires you to classify attack types and identify the CIA property affected.

Volume vs. protocol vs. application: Volumetric attacks (UDP floods, ICMP floods) fill bandwidth pipes. Protocol attacks (SYN floods) exhaust stateful connection tables. Application-layer attacks (HTTP floods, slowloris) consume server CPU and thread pools with low bandwidth, making them harder to filter.

Attack Type Mechanism CIA Property Targeted Primary Mitigation
SYN Flood Sends massive TCP SYN packets without completing the handshake, filling connection tables Availability SYN cookies, rate limiting on SYN packets
UDP Flood Saturates bandwidth with spoofed UDP packets to random ports; targets Availability Availability Upstream rate limiting, traffic scrubbing
DNS/NTP Amplification Small spoofed request to a reflector returns a large response to the victim; 70-1 amplification factor Availability BCP38 ingress filtering, disable open resolvers
Layer 7 (HTTP Flood) Mimics legitimate user requests to exhaust web server threads and CPU Availability WAF rate limiting, CAPTCHA, CDN protection
Breach Example

Mirai Botnet (2016): The Mirai malware compromised 600,000 IoT devices (cameras, routers, DVRs) with default credentials and directed them at Dyn DNS infrastructure. The resulting DDoS peaked at 1.2 Tbps and took down Twitter, Reddit, Netflix, and Spotify simultaneously. The Dyn outage demonstrated that availability attacks against DNS infrastructure can cascade across the entire internet. Mirai's source code was released publicly, enabling hundreds of derivative botnets.

Man-in-the-Middle Attacks

Man-in-the-Middle (MitM) attacks position the attacker between two communicating parties. The attacker can intercept, read, and modify traffic in real time without either party detecting the interception. ARP spoofing is the most common LAN-based MitM technique. SSL stripping downgrades HTTPS to HTTP, enabling cleartext interception even on TLS-protected sessions.

ARP spoofing mechanics: ARP is stateless -- any host can broadcast a gratuitous ARP reply claiming any IP. The attacker sends unsolicited ARP replies associating their MAC with the default gateway's IP. All traffic intended for the gateway flows through the attacker instead.

1
Attacker sends gratuitous ARP

Broadcasts: "IP 192.168.1.1 is at MAC AA:BB:CC:DD:EE:FF" -- the attacker's own MAC, not the router's.

2
Victim updates ARP cache

Victim host caches the poisoned entry. All traffic destined for the gateway now goes to the attacker first.

3
Attacker forwards traffic

Attacker forwards packets to the real gateway so the session appears normal, while capturing or modifying all data.

4
SSL stripping (optional escalation)

Attacker intercepts the initial HTTP request and establishes HTTPS with the server while serving the victim plain HTTP -- credentials transmitted in cleartext.

Mitigations: Dynamic ARP Inspection (DAI) on managed switches validates ARP packets against the DHCP snooping binding table, dropping spoofed replies. HSTS (HTTP Strict Transport Security) prevents SSL stripping by instructing browsers to always use HTTPS. Network segmentation and 802.1X port authentication limit LAN access to authenticated devices.

Operational Context

Internal specimen transfer orders are digitally signed and transmitted over the facility's internal network. An undetected ARP poisoning attack on the lab LAN would allow an adversary to intercept and modify transfer orders in transit -- redirecting a BSL-4 specimen to an unsecured storage area without triggering the integrity check, because the signature was applied to data the attacker had already altered.

DNS Cache Poisoning and Replay Attacks

DNS cache poisoning (a DNS spoofing variant) injects false DNS records into a resolver's cache, redirecting users to attacker-controlled servers without their knowledge. The Kaminsky attack (2008) demonstrated that an attacker could brute-force all 65,535 source ports and 65,535 transaction IDs simultaneously, poisoning a resolver in seconds with a standard internet connection.

DNSSEC (DNS Security Extensions) adds cryptographic signatures to DNS records, allowing resolvers to verify authenticity. DNSSEC prevents cache poisoning but does not encrypt queries -- DNS over HTTPS (DoH) or DNS over TLS (DoT) address query privacy.

Replay attacks capture a valid authentication token or session credential and retransmit it to impersonate the original user. The captured token is valid -- the attacker does not need to crack it. Replay attacks differ from credential theft in that the plaintext password is never exposed.

Replay Scenario Captured Credential Mitigation
Session cookie replay HTTP session cookie intercepted from unencrypted traffic HTTPOnly + Secure cookie flags, TLS everywhere, session expiry
Kerberos pass-the-ticket Kerberos TGT or service ticket extracted from memory Short ticket lifetimes, Protected Users group, Credential Guard

Session Hijacking and Session Fixation

Session hijacking steals an authenticated session token after the user has logged in. Session fixation plants a known session token before login, then waits for the victim to authenticate -- at which point the attacker's pre-planted token becomes a valid authenticated session. Both attacks bypass the authentication mechanism entirely because the attacker presents a legitimate token.

Session hijacking vectors: Predictable session tokens (sequential IDs, low entropy), XSS to steal cookies, MitM on unencrypted channels, or packet capture on shared networks. The attack succeeds even when the user's password is strong, because the token is stolen post-authentication.

Mitigations: Regenerate session tokens on authentication (defeats fixation). Set HTTPOnly and Secure flags on session cookies (defeats XSS token theft and cleartext capture). Implement session expiry and idle timeouts. Use TLS for all authenticated sessions. Bind sessions to IP or user-agent as an additional (imperfect) signal.

Operational Context

The facility's specimen management portal uses token-based sessions for researcher authentication. Without Secure and HTTPOnly flags, a single XSS payload in a lab note field would exfiltrate every active session token. An attacker could then replay those tokens and modify containment protocols as if they were a credentialed researcher -- without ever knowing a single password.
