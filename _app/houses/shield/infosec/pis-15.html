SIEM and Log Analysis -- The Facility's Nervous System

A SIEM (Security Information and Event Management) platform aggregates log data from across the environment and applies correlation rules to detect patterns that indicate security incidents. SY0-701 Objective 4.1 tests SIEM capabilities and the log sources it consumes.

Log SourceWhat It Tells YouKey Indicators
Firewall logs Which connections were allowed or denied, to which ports and IPs Port scans (many connections to sequential ports), outbound connections to known malicious IPs, repeated deny events from internal hosts
Authentication logs Who logged in, from where, at what time, success or failure Brute force (many failed logins), credential stuffing, impossible travel (same account logging in from two countries minutes apart)
DNS logs Which domains are being resolved by internal hosts DNS tunneling (unusually long or frequent DNS queries), queries to newly registered or DGA domains, C2 beaconing patterns
Endpoint/EDR logs Process execution, file system changes, network connections per process PowerShell executing encoded commands, unusual parent-child process relationships (Word spawning cmd.exe), fileless malware artifacts
NetFlow data Volume and direction of network traffic between hosts (not payload content) Large data transfers to external IPs, unusual east-west traffic between internal segments, beaconing at regular intervals

SOAR (Security Orchestration, Automation, and Response) integrates with the SIEM to automate response actions. Where SIEM detects and alerts, SOAR acts: automatically isolating a compromised endpoint, blocking a malicious IP at the firewall, disabling a compromised user account. SOAR reduces mean time to respond (MTTR) by executing playbooks on trigger events.

Facility Context:

The facility SIEM receives 200,000 log events per hour. Correlation rules prioritize: any internal host communicating with a known malware C2 IP triggers an immediate P1 alert and a SOAR playbook that isolates the host on the network, captures its memory image, and pages the on-call analyst. Detection to isolation: under 90 seconds.

IDS and IPS -- Signature vs Anomaly Detection

An Intrusion Detection System (IDS) monitors traffic and generates alerts when suspicious patterns are detected. An Intrusion Prevention System (IPS) can block traffic in addition to alerting. The core distinction: IDS is passive (detects and alerts), IPS is active (detects, alerts, and blocks). A NIPS must be placed inline in the traffic path; a NIDS can use a SPAN port (out of band, no blocking capability).

Detection MethodHow It WorksStrengthsWeaknesses
Signature-based Compares traffic or behavior against a database of known attack patterns. Fires when traffic matches a known signature. Low false positive rate for known attacks. Fast. Deterministic. Cannot detect zero-day attacks. Signature database must be continuously updated. Evasion via obfuscation or polymorphism.
Anomaly-based (Behavioral) Establishes a baseline of normal behavior. Fires when traffic or behavior deviates significantly from the baseline. Can detect zero-day attacks and novel threats. No pre-existing signature required. Higher false positive rate. Baseline must be established during a "clean" period. Attackers can slowly shift behavior to avoid anomaly thresholds.
Heuristic Applies rules that characterize suspicious behavior. More flexible than pure signatures. Better detection of variants of known attacks. Still misses truly novel techniques. False positive rate between signature and anomaly.
Exam Trap: IDS vs IPS Placement

An IDS connected via SPAN port sees all traffic but cannot block anything -- it is physically incapable of inline blocking. An IPS must be physically inline to block traffic. If a scenario says "detect without blocking" choose SPAN-connected IDS. If "prevent attacks from reaching the server" choose inline IPS.

Facility Context:

The facility runs an inline IPS between the DMZ and the internal network. Signature-based detection catches known pathogen delivery methods. Anomaly-based detection flags when a previously quiet internal host begins making 50 outbound connections per minute -- a classic C2 beacon pattern. The IPS blocks the beaconing traffic and the SOAR playbook fires.

Vulnerability Scanning and Penetration Testing

Vulnerability scanning (tools: Nessus, OpenVAS, Qualys) identifies known vulnerabilities by comparing system configurations against a vulnerability database (CVE/NVD). Scanning is automated, non-destructive, and safe to run in production. Results in a list of findings with severity scores (CVSS). No exploitation occurs during a vulnerability scan.

Penetration testing is a controlled simulation of a real attack. Testers actively attempt to exploit discovered vulnerabilities to demonstrate actual impact. Requires written authorization. The penetration test methodology follows phases:

PhaseActivitiesOutput
1. Planning and Scoping Define scope, rules of engagement, objectives, timeline. Get written authorization. Signed scope agreement, rules of engagement document
2. Reconnaissance Passive (OSINT) and active (port scanning, service enumeration) information gathering. Target profile, open ports, running services, technologies in use
3. Exploitation Attempt to exploit identified vulnerabilities. Escalate privileges if initial access is obtained. Proof of exploitation, access level achieved, lateral movement paths
4. Post-Exploitation Maintain access, move laterally, exfiltrate sample data (simulated), document findings with evidence. Attack path documentation, data access evidence, pivot points identified
5. Reporting Document all findings: executive summary for leadership, technical findings for engineers, remediation recommendations. Penetration test report
Facility Context:

The facility conducts quarterly vulnerability scans on all systems. Findings with CVSS scores of 9.0 or higher trigger emergency patching within 72 hours. An annual penetration test -- red team vs blue team -- simulates a full attack chain from external reconnaissance through privilege escalation to specimen database access. Last year's red team reached a BSL-2 database. This year, it did not get past the DMZ.

Threat Hunting and Data Protection -- DLP, Encryption at Rest and in Transit

Threat hunting is a proactive security activity where analysts actively search for threats that have evaded automated detection. Unlike SIEM alert response (reactive), threat hunting starts with a hypothesis and hunts through data for evidence. Threat hunters use threat intelligence, MITRE ATT&CK framework TTPs, and behavioral data. The goal is to reduce dwell time.

ControlWhat It Protects AgainstImplementation
DLP (Data Loss Prevention) Unauthorized exfiltration of sensitive data through email, web upload, USB, or print Content inspection engines identify sensitive data patterns. Policy blocks or alerts on matches. Endpoint DLP covers local actions; network DLP covers egress channels.
Encryption at Rest Unauthorized access to data on storage media (stolen hard drive, improper disposal) Full disk encryption (BitLocker, FileVault), database encryption (TDE), file-level encryption. AES-256 is the current standard. Key management is the critical dependency.
Encryption in Transit Interception of data moving between systems (man-in-the-middle, network sniffer) TLS for application layer (HTTPS, SMTP with STARTTLS, LDAPS). IPSec for network layer. VPN for site-to-site and remote access. Enforce minimum TLS 1.2; disable TLS 1.0 and 1.1.
Facility Context:

Specimen classification data is protected at every state: at rest (AES-256 full disk encryption on all servers, key stored in HSM), in transit (TLS 1.3 for all internal and external connections), and in use (DLP policy monitors all outbound channels and blocks any file tagged as specimen data from leaving the facility network). Defense in depth for data means the attacker must defeat all three protections simultaneously.

Key Takeaways

  • SIEM aggregates and correlates logs; SOAR automates response playbooks triggered by SIEM alerts -- detection vs action
  • IDS detects and alerts (passive, SPAN port acceptable); IPS detects and blocks (must be inline in the traffic path)
  • Signature-based detection has low false positives but cannot catch zero-days; anomaly-based can catch novel threats but has higher false positives
  • Vulnerability scanning identifies weaknesses without exploitation (safe for production); penetration testing actively exploits (requires written authorization)
  • Threat hunting is proactive and hypothesis-driven; alert response is reactive -- both are needed
  • Encryption at rest protects data on storage media; encryption in transit protects data moving between systems; DLP prevents unauthorized exfiltration
