Firewalls: Stateless, Stateful, and Next-Generation

A firewall enforces an access control policy between network segments by inspecting and filtering traffic. SY0-701 Objective 3.2 requires you to differentiate firewall types by inspection depth and capability. The three primary types appear on the exam in scenario format.

Firewall Type Inspection Level Key Capability Limitation
Stateless (Packet Filter) Layer 3/4 headers only Filters by source IP, destination IP, port, protocol. Fast and low-overhead. No session awareness. Cannot distinguish a new connection from an ongoing one. Easily bypassed with crafted packets.
Stateful Layer 3/4 + session state Tracks TCP connection state (SYN, ESTABLISHED, FIN). Blocks packets that do not belong to a known session. Standard for perimeter firewalls. Cannot inspect application-layer content. Legitimate-looking traffic (HTTP, DNS) passes unchallenged.
Next-Generation (NGFW) Layer 7 (application layer) Deep packet inspection, application identification, SSL/TLS inspection, integrated IPS, user identity awareness, URL filtering. Can block specific apps even on permitted ports. Higher cost and processing overhead. Requires SSL inspection certificates for HTTPS traffic. Misconfiguration can break legitimate applications.

A DMZ (demilitarized zone) is a network segment between the external internet and the internal trusted network. Public-facing servers (web, email, DNS) are placed in the DMZ. A firewall on the external side allows internet traffic to the DMZ. A second firewall on the internal side allows only specific, necessary traffic from DMZ to internal. This two-firewall DMZ architecture is the standard perimeter design.

NAT (Network Address Translation) maps private IP addresses to public IP addresses. It provides implicit obscurity by hiding the internal address space from external networks, but NAT is not a security control -- it does not inspect or filter traffic. Do not confuse NAT with a firewall on the exam.

Real-World: Target Breach (2013)

Attackers compromised the HVAC vendor's network, which had direct access to Target's corporate network. No firewall segmentation existed between the vendor access zone and the payment card network. A properly implemented DMZ and segmentation policy would have contained the breach to the vendor's access path.

VPN Technologies: IPSec and SSL/TLS

A Virtual Private Network creates an encrypted tunnel over an untrusted network. SY0-701 Objective 3.1 requires you to distinguish VPN types by protocol and use case. The two major VPN protocol families tested are IPSec and SSL/TLS-based VPNs.

VPN Type Protocol Use Case Exam Notes
IPSec (Tunnel Mode) IKE for key exchange, ESP for encryption (AES-256), AH for integrity Site-to-site VPN between offices or data centers. Full network layer encryption. Tunnel mode encapsulates the entire original IP packet inside a new IP packet. Transport mode only encrypts the payload. Tunnel mode is the site-to-site standard.
SSL/TLS VPN TLS (operates over HTTPS, port 443) Remote access VPN for individual users. Clientless (browser-based) or thin-client. Traverses firewalls easily since it uses port 443. Does not require pre-installed VPN client software in clientless mode. Preferred when users are on managed or unmanaged devices.
Split Tunneling Either protocol Routes only organization traffic through the VPN; internet traffic goes direct. Reduces VPN load. Security risk: internet traffic is not inspected by corporate controls while connected. Full tunneling forces all traffic through the VPN for inspection.
Facility Context:

Field teams connecting to the facility from external locations use an SSL VPN on port 443. Traffic from their workstations arrives at the DMZ tunnel terminator, is decrypted, then re-inspected by the NGFW before reaching the internal network. Split tunneling is disabled -- all traffic routes through the facility perimeter.

Network Segmentation, Zero Trust, and Micro-Segmentation

Network segmentation divides a flat network into isolated zones, limiting lateral movement in the event of a breach. SY0-701 Objective 3.1 tests segmentation concepts including VLANs, zero trust architecture, and micro-segmentation.

VLAN segmentation uses Layer 2 virtual LANs to separate network traffic at the switch level. A VLAN-segmented network contains: a user VLAN, a server VLAN, a management VLAN, a guest VLAN, and potentially an IoT VLAN. Inter-VLAN routing is controlled by a Layer 3 switch or router with ACLs, creating choke points for traffic between zones.

Zero Trust Architecture (ZTA) operates on the principle of "never trust, always verify." Traditional perimeter security assumes that anything inside the network is safe. Zero trust eliminates that assumption entirely. Every access request is authenticated, authorized, and continuously validated regardless of whether the source is internal or external. Core components: identity verification (MFA), device health checks, least-privilege access, and continuous session monitoring.

Micro-segmentation extends zero trust to the workload level. Rather than segmenting at the network perimeter, micro-segmentation applies policy at the individual workload, container, or virtual machine. Even within the same VLAN, workloads cannot communicate unless policy explicitly permits it. Software-defined perimeter (SDP) implements this via identity-based policy enforcement rather than network topology.

Concept Granularity Lateral Movement Prevention
VLAN segmentation Network zone level Limits movement between major zones (user vs server vs management)
Zero Trust Architecture Session / identity level Every access request verified; no implicit trust from network location
Micro-segmentation Workload / container level Stops lateral movement even between hosts on the same VLAN
Facility Context:

The containment facility implements zero trust for all specimen handling systems. Lab technician workstations cannot communicate with specimen databases directly -- every access request goes through an identity-aware proxy that validates clearance level, device health, and time-of-day policy before granting access. A compromised technician workstation cannot reach the vault directly.

SD-WAN and Network Architecture Exam Scenarios

SD-WAN (Software-Defined Wide Area Network) abstracts the WAN connectivity layer, allowing traffic to be dynamically routed across multiple transport options (MPLS, broadband, LTE) based on application policy. SD-WAN centralizes management, reduces reliance on expensive MPLS circuits, and enables consistent security policy across distributed locations. From a security perspective, SD-WAN introduces encryption between sites and enables application-aware routing, but also expands the attack surface through its centralized control plane.

SY0-701 Objective 3.2 presents network architecture scenarios and asks you to identify the appropriate control. Key exam patterns to recognize:

Scenario Correct Answer Why
Attacker moves from compromised web server to internal database Network segmentation / DMZ with second firewall The web server and database should be in separate zones with firewall rules preventing direct access
Remote employee needs secure access to internal resources SSL/TLS VPN (or IPSec remote access) Encrypted tunnel authenticates the user and encrypts traffic over the untrusted internet
Organization wants to block specific applications (Zoom, Dropbox) regardless of port Next-Generation Firewall (NGFW) Stateful firewalls filter by port; NGFW identifies applications by behavior and content
Company implements "never trust, always verify" policy for all internal resources Zero Trust Architecture Zero trust eliminates implicit trust based on network location; every session verified
Two branch offices need encrypted connectivity between their local networks IPSec VPN tunnel mode (site-to-site) Site-to-site IPSec in tunnel mode encrypts entire IP packets between the two network gateways
Facility Context:

The facility's satellite labs communicate with the main campus over IPSec VPN tunnels in full tunnel mode. SD-WAN routes routine data (environmental sensors, status telemetry) over cheaper broadband links and reserves the encrypted MPLS circuit for high-priority specimen transfer data. Traffic policy is enforced centrally and pushed to all sites simultaneously.

Key Takeaways

  • NGFW operates at Layer 7 and can identify applications by behavior -- stateful firewalls only track TCP session state, not application content
  • NAT hides internal IP addresses but is not a security control -- it does not inspect or filter traffic
  • IPSec tunnel mode encrypts the entire original packet (site-to-site); transport mode encrypts only the payload
  • SSL/TLS VPN operates over port 443 and traverses most firewalls without additional rule changes
  • Zero Trust requires every access request to be verified regardless of network location -- no implicit trust from being on the internal LAN
  • Micro-segmentation extends zero trust to individual workloads, stopping lateral movement within the same VLAN
