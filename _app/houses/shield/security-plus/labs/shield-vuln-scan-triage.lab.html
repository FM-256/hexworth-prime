Vulnerability Scan Triage

Domain 4.0 Security Operations — SY0-701 Objective 4.3
Analyze a real vulnerability scanner report, filter false positives, assign remediation decisions, and apply risk-based prioritization.

Key concept: CVSS base score measures intrinsic severity in a vacuum — it does not account for your environment. Remediation priority must also factor in: asset exposure (internet-facing vs. air-gapped), active exploitation in the wild, asset criticality, and compensating controls already in place. A CVSS 10.0 on an isolated internal server can rank below a CVSS 9.8 on a public-facing web server under active attack.
Phase 1 — Triage each finding (12 rows):
For every row in the scanner report, make three decisions using the drop-down menus in the rightmost column:
(1) True / False Positive — is this a real vulnerability or a scanner error?
(2) Remediation action — Patch Now / Schedule Patch / Mitigate / Accept Risk
(3) Risk priority — Critical / High / Medium / Low — combining CVSS score WITH exposure and exploitability.

Phase 2 (unlocks after Phase 1): rank the top 3 findings to remediate first.
Critical 9.0-10.0
High 7.0-8.9
Medium 4.0-6.9
Low 0.1-3.9
# CVE ID Title Affected Asset CVSS v3.1 Exploit Status Scanner Note Your Decisions

Phase 2 — Top-3 Remediation Order

Based on your triage, select the three findings that should be remediated first, in order from most urgent (#1) to third-most urgent (#3). Apply risk-based thinking: CVSS score alone does not determine order. Internet-facing assets under active exploitation outrank higher-scored findings buried on isolated internal networks.
