Primitive Reference
TLS 1.3
Transport Layer Security. Encrypts data in transit over a network; uses a handshake to negotiate keys, then symmetric encryption for the session.
AES-256 (symmetric)
Advanced Encryption Standard, 256-bit key. Same key encrypts and decrypts. Extremely fast — suited to bulk data (files, databases, volumes).
RSA-2048 (asymmetric)
Public/private key pair. Public key encrypts; private key decrypts. Slow for bulk data; used for key wrapping, key exchange (older), or signatures.
SHA-256 (hash)
Produces a fixed-length digest from any input. One-way — cannot recover the original. Used to verify integrity, NOT to encrypt data.
HMAC
Hash-based Message Authentication Code. Combines a hash with a shared secret key. Provides both integrity and authentication of a message.
Diffie-Hellman (key exchange)
A mathematical protocol that lets two parties derive a shared secret over an untrusted channel without ever transmitting the secret itself.
Digital Signature
Sender hashes the data, then encrypts the hash with their private key. Anyone with the public key can verify it came from the correct sender and has not changed.
bcrypt / Argon2 (password hashing)
Intentionally slow, salted hash algorithms designed for storing passwords. High cost factor makes brute-force attacks impractical even if the hash database is stolen.
Full Disk Encryption
Encrypts every sector on a storage device (BitLocker on Windows, LUKS on Linux). Data is unreadable without the correct key, even if the drive is removed.
Certificate (X.509)
A digitally-signed document that binds a public key to an identity. Issued by a Certificate Authority (CA). Used in TLS, code signing, S/MIME, and smart cards.
Common confusions on SY0-701:
Hashing is one-way integrity verification — it does not encrypt.

DH exchanges keys; it does not encrypt data.

Signatures use the sender's private key (non-repudiation), not a shared key.

bcrypt/Argon2 are for passwords — do not use AES to store passwords.
