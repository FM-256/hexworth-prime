Change-Management Elements

Impact Analysis
Identifies which systems, services, and users are affected by the change and quantifies the risk if it fails.
Backout / Rollback Plan
A documented procedure to reverse the change and restore the prior working state if the deployment causes problems.
Maintenance Window
A scheduled low-impact time slot during which changes are applied to minimize disruption to business operations.
CAB Approval
Formal authorization from the Change Advisory Board (or equivalent) before any work is permitted to begin.
Test / Validation Results
A recorded outcome from trialing the change in a non-production environment before it is applied to live systems.
Stakeholder Notification
Communication sent to affected teams and departments in advance of the change, covering schedule and expected impact.
Version Control
Tracking configuration and code changes in a repository so that any revision can be audited, compared, or restored.
SOP / Documentation Update
Post-change update to written operating procedures so they accurately reflect the new process or configuration.

Exam Strategy

Sequence matters
Impact analysis and CAB approval happen before the change; test results confirm readiness; the maintenance window is when it runs; backout is the safety net; stakeholder notification is pre-change communication; version control and SOP updates are post-change housekeeping.
Read the timing cue
Descriptions that mention "before," "prior state," "scheduled time," "staging," "repository," or "after the change" each point to a distinct element.
