Microsoft Defender for Endpoint
Onboarding  •  ASR Rules  •  EDR  •  Live Response  •  Automated Investigation  •  TVM
Microsoft Defender for Endpoint is the endpoint protection platform within the Defender XDR suite. It provides endpoint detection and response (EDR), attack surface reduction, vulnerability management, and automated investigation capabilities. This chapter covers how to onboard devices, configure protections, and respond to endpoint threats.

Defender for Endpoint Architecture
Defender for Endpoint is a cloud-delivered endpoint security platform. Sensors on devices stream telemetry to the Microsoft cloud, where behavioral analytics, machine learning, and threat intelligence detect and respond to threats.
Platform Coverage
Windows 10/11, Windows Server 2012 R2+, macOS, Linux, iOS, and Android. Each platform uses a platform-specific sensor. Windows has the deepest telemetry with kernel-level behavioral monitoring.
Licensing
Defender for Endpoint Plan 1 includes ASR and next-gen protection. Plan 2 adds EDR, automated investigation, threat analytics, and TVM. Plan 2 is required for the full SC-200 exam scope.
Device Groups
Devices are organized into device groups for RBAC and automation level configuration. Each group can have different automation levels (Full, Semi, No automated response) and role-based access permissions.
Integration
Telemetry feeds into the unified Defender XDR incident queue. Endpoint alerts correlate with identity, email, and cloud app signals to form complete attack stories across the kill chain.

Device Onboarding Methods
Onboarding registers a device with Defender for Endpoint and installs the sensor. The method you choose depends on the number of devices, management infrastructure, and operating system.
Local Script
Download WindowsDefenderATPLocalOnboardingScript.cmd from the portal. Run on individual devices. Best for testing, pilot deployments, and up to 10 devices. Not suitable for production at scale.
Group Policy (GPO)
Deploy the onboarding configuration via Group Policy. Copy the onboarding package to a network share, create a GPO that runs the script at startup. Scales to domain-joined Windows devices without additional tooling.
Microsoft Intune
Create an endpoint detection and response configuration profile in Intune. Targets Microsoft Entra ID joined and hybrid-joined devices. Recommended for cloud-managed environments. Supports Windows, macOS, Linux, iOS, and Android.
SCCM / ConfigMgr
Use Microsoft Configuration Manager (formerly SCCM) to deploy the onboarding package. Best for large enterprises with existing ConfigMgr infrastructure. Supports Windows Server and workstation onboarding at scale.
Exam Tip
The local script is for up to 10 devices only. For enterprise deployment, use Intune (cloud-managed), GPO (domain-joined), or ConfigMgr (existing infrastructure). Onboarding packages are tenant-specific -- never share across tenants.
Slide 4 of 12
Onboarding Verification
After onboarding, verify that devices are reporting correctly to the service. Troubleshoot connectivity issues before assuming onboarding failed.
1Device Inventory -- check Settings > Endpoints > Device inventory in the portal. Newly onboarded devices appear within 5-30 minutes. Status shows "Active" when the sensor is reporting.
2Detection Test -- run the EICAR-equivalent test command from the official docs on the device. A test alert should appear in the portal within minutes, confirming end-to-end connectivity.
3Sensor Health -- check the MsSense.exe service on the device. It must be running and set to automatic start. Event Viewer logs under Microsoft-Windows-SENSE show connectivity status.
4Connectivity Test -- run mdatp connectivity-test (macOS/Linux) or check the Client Analyzer tool (Windows) to verify the device can reach all required cloud endpoints and URLs.
5Offboarding -- download the offboarding package from the portal. It removes the sensor and stops telemetry. Device data is retained for 180 days. Offboarding packages expire after 30 days.
Key Detail
Onboarding packages are valid for 30 days. Offboarding packages also expire after 30 days. Both are tenant-specific and contain the workspace ID and key used to authenticate with the service.

Attack Surface Reduction (ASR) Rules
ASR rules block behaviors commonly used by malware and exploits. They reduce the attack surface without impacting legitimate business operations when properly configured.
Office Rules
Block Office apps from creating child processes, injecting code, creating executable content, and launching potentially obfuscated scripts. Prevents macro-based malware.
Script Rules
Block obfuscated scripts, untrusted/unsigned processes from USB, JavaScript and VBScript from launching downloaded content. Stops script-based initial access vectors.
Email Rules
Block executable content from email client and webmail. Prevent email attachments from launching executable files. Targets phishing-to-execution kill chain.
Credential Rules
Block credential stealing from the Windows Local Security Authority Subsystem (LSASS). Prevents Mimikatz-style credential dumping attacks used in lateral movement.
Ransomware Rule
Use advanced protection against ransomware. Evaluates files entering the system against reputation and prevalence models to detect and block potential ransomware payloads.
Exploit Rule
Block process creations originating from PSExec and WMI commands. Prevents attackers from using living-off-the-land binaries for lateral movement across the network.
Deployment Modes
Audit -- log events without blocking. Use to evaluate impact before enforcement. Block -- actively prevent the behavior. Warn -- show user a warning but allow override. Deploy in audit mode first, review logs, then switch to block mode.
Slide 6 of 12
ASR Configuration
ASR rules can be deployed through multiple management tools. Exclusions prevent false positives on legitimate business applications.
Intune Policy
Create an endpoint security ASR policy in Intune. Select individual rules and set each to Audit, Block, or Warn. Assign to device groups. Recommended for cloud-managed environments.
Group Policy
Configure ASR rules via Computer Configuration > Administrative Templates > Windows Components > Microsoft Defender Antivirus > ASR. Each rule is identified by a unique GUID.
PowerShell
Use Set-MpPreference -AttackSurfaceReductionRules_Ids with rule GUIDs and -AttackSurfaceReductionRules_Actions to set modes. Useful for scripted deployments and testing.
Per-Rule Exclusions
Exclude specific files and folders from individual ASR rules. Example: a line-of-business app that legitimately creates child processes from Office. Exclusions should be as narrow as possible to maintain protection.
ASR Reporting
View ASR detections in the security portal under Reports > Attack surface reduction rules. Shows blocked events, audit events, and impacted devices. Use the report to identify false positives before switching from audit to block.

Endpoint Detection and Response (EDR)
EDR continuously monitors endpoints for post-breach activity. It detects advanced threats that bypass prevention, provides investigation tools, and enables rapid response to active attacks.
Device Timeline
Every device has a timeline showing all observed events: process execution, file operations, network connections, registry changes, and sign-ins. Filter by time range, event type, and severity to trace an attack.
Alert Queue
EDR generates alerts when behavioral detections fire. Each alert shows the detection source, MITRE ATT&CK mapping, affected entities, and recommended response actions. Alerts feed into the Defender XDR incident queue.
Advanced Hunting
Use KQL to query 30 days of raw endpoint telemetry: DeviceProcessEvents, DeviceFileEvents, DeviceNetworkEvents, DeviceRegistryEvents. Proactively hunt for threats that bypass automated detection.
EDR in Block Mode
When a third-party AV is the primary engine, EDR in block mode lets Defender for Endpoint take automated remediation on post-breach detections. Acts as a safety net behind non-Microsoft antivirus products.

Live Response Sessions
Live response provides a remote shell connection to a device for advanced investigation and remediation. It runs in the context of the SYSTEM account on the target device.
1Initiate Session -- from the device page in the portal, click "Initiate Live Response Session." The session opens a command-line interface connected to the remote device.
2Basic Commands -- dir, cd, fileinfo, processes, connections. View file system contents, running processes, and network connections on the device in real time.
3Advanced Commands -- getfile downloads a file for analysis. putfile uploads tools to the device. run executes uploaded scripts. Requires advanced live response permissions.
4Remediation -- remediate quarantines a file. undo restores a quarantined file. Use the library to upload and manage reusable investigation scripts across sessions.
Permission Levels
Basic -- read-only commands (dir, fileinfo, processes, connections). Advanced -- adds getfile, putfile, run, and remediate. Advanced permissions are configured per role in the security portal RBAC settings.
Slide 9 of 12
Automated Investigation
Automated investigation uses AI-driven playbooks to investigate endpoint alerts and take remediation actions. It reduces the manual workload on SOC analysts by automating repetitive triage and response.
Alert Trigger
An EDR alert triggers an automated investigation. The playbook expands scope by analyzing related processes, files, services, registry keys, and network connections.
Entity Analysis
Each entity is analyzed against threat intelligence, reputation services, and behavioral models. The investigation builds a graph of related artifacts across the device and potentially other devices.
Verdicts
Entities receive verdicts: Malicious, Suspicious, Clean, or No threats found. Verdicts determine which remediation actions are proposed or automatically executed.
Remediation
Actions include: quarantine file, stop process, remove registry key, isolate device. The automation level (Full, Semi, None) determines whether actions execute automatically or require approval.
Action Center
All pending and completed remediation actions appear in the Action Center. Analysts review pending actions, approve or reject, and track the history of all automated remediation across the tenant.
Device Groups
Automation levels are set per device group. Critical servers might use Semi (require approval) while standard workstations use Full automation. Allows risk-appropriate automation policies.
Slide 10 of 12
Threat Analytics Dashboards
Threat analytics provides context on active threats targeting your endpoints. Each report maps the threat to your environment and provides actionable mitigation guidance.
Analyst Reports
Written by Microsoft Threat Intelligence. Each report covers a specific threat: CVE exploits, ransomware campaigns, or APT activity. Includes TTPs, IOCs, and MITRE ATT&CK mappings specific to the threat.
Exposure View
Automatically assesses your endpoints against each threat. Shows: devices missing patches, devices without ASR rules enabled, devices with vulnerable software. Color-coded indicators for quick risk assessment.
Mitigation Status
Tracks which recommended mitigations have been applied. Shows progress over time as patches are deployed and configurations are updated. Links directly to TVM recommendations for remediation.
Security Operations Dashboard
The endpoint security dashboard shows: active alerts by severity, devices at risk, sensor health status, daily detections trend, and top alerting devices. Provides SOC teams with an at-a-glance operational picture.
Device Health Reports
Monitor sensor health, antivirus status, and OS platform distribution across the fleet. Identify devices with outdated signatures, inactive sensors, or misconfigured protection settings.
Slide 11 of 12
Threat and Vulnerability Management (TVM)
TVM discovers vulnerabilities and misconfigurations on endpoints in real time using the Defender for Endpoint sensor. No additional agents or scans required -- it uses existing telemetry.
Exposure Score
A numerical score (0-100) representing your organization's vulnerability exposure. Factors include: number of vulnerabilities, severity (CVSS), affected devices, and active exploits in the wild. Lower is better.
Security Recommendations
Prioritized list of remediation actions: patch software, update configurations, disable vulnerable features. Each recommendation shows impact score, exposed devices, and available remediation options.
Software Inventory
Complete inventory of all software installed across endpoints. Shows version numbers, known vulnerabilities (CVEs), and end-of-life status. Identifies shadow IT and unauthorized software installations.
Remediation Workflow
Create remediation tickets directly from TVM recommendations. Integrates with Intune and ConfigMgr for deployment. Track remediation progress from request through completion with full audit trail.
Browser Extensions
TVM inventories browser extensions across Chrome and Edge. Identifies extensions with excessive permissions, known vulnerabilities, or low reputation scores. Part of the complete software asset view.
Key Concept
TVM uses the same Defender for Endpoint sensor -- no additional scanning agents. Vulnerability data is continuous and real-time, not based on periodic scans. This eliminates scan windows and provides up-to-the-minute vulnerability posture.

Chapter 2 Summary
Key concepts you must know for the SC-200 exam.
1Onboarding -- local script (up to 10 devices), GPO (domain-joined), Intune (cloud-managed), ConfigMgr (enterprise). Packages are tenant-specific and expire after 30 days.
2ASR Rules -- block malware behaviors at the attack surface. Deploy in audit mode first, review impact, then switch to block. Configurable via Intune, GPO, or PowerShell.
3EDR -- continuous post-breach detection. Device timeline shows all activity. Alerts feed into Defender XDR incidents. EDR in block mode works alongside third-party AV.
4Live Response -- remote shell for investigation and remediation. Basic (read-only) and Advanced (getfile, putfile, run, remediate) permission levels. Runs as SYSTEM on the device.
5Automated Investigation -- AI-driven playbooks investigate alerts and take remediation actions. Automation levels (Full, Semi, None) are set per device group.
6TVM -- continuous vulnerability discovery using the existing sensor. Exposure score, security recommendations, software inventory. No additional agents or periodic scans required.
