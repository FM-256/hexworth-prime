Cloud Access Security Broker Overview
Defender for Cloud Apps is Microsoft's CASB solution. It sits between your users and cloud services, providing visibility, data control, and threat protection across SaaS, PaaS, and IaaS.
Discover
Cloud Discovery identifies all cloud apps in use across your organization -- sanctioned and unsanctioned. Analyzes firewall and proxy logs to build a complete shadow IT inventory with risk scores for each app.
Investigate
Deep visibility into user activities, files, and accounts within connected apps. Activity logs, file sharing analysis, and user behavior analytics reveal risky actions before they become incidents.
Control
Session policies and access policies enforce real-time controls. Block downloads on unmanaged devices, require step-up authentication, and apply sensitivity labels to files -- all inline through the reverse proxy.
Protect
Anomaly detection policies, threat detection, and DLP scanning protect data at rest and in transit. Automated governance actions can suspend users, revoke OAuth tokens, or quarantine files.
Exam Focus
The four pillars of a CASB -- Discover, Investigate, Control, Protect -- map directly to exam scenarios. Know which pillar each feature falls under and how they work together.
Slide 3 of 12
Cloud Discovery and Shadow IT
Cloud Discovery analyzes network traffic to identify all cloud apps accessed by users. It reveals shadow IT -- apps used without IT approval -- and assigns risk scores based on 90+ factors.
Log Collection Methods
Three ways to feed traffic data: automated log upload from firewalls/proxies using a log collector, Defender for Endpoint integration (per-device discovery), or manual snapshot reports for one-time analysis.
App Risk Scoring
Each discovered app gets a risk score (1-10) based on general info, security controls, compliance, and legal factors. Over 31,000 apps in the Cloud App Catalog with detailed risk assessments.
Sanctioned vs Unsanctioned
Tag apps as Sanctioned (approved), Unsanctioned (blocked), or Monitored. Unsanctioned apps can be blocked via Defender for Endpoint network protection or by generating block scripts for your firewall.
Best Practice
Defender for Endpoint integration is the recommended method for Cloud Discovery because it provides per-device, per-user visibility without requiring proxy or firewall log uploads. Enable it in Defender for Endpoint Advanced Features settings.

App Connectors -- API-Based Integration
App connectors use provider APIs to get deep visibility and control over connected cloud apps. Once connected, Defender for Cloud Apps can scan files, monitor activities, and apply governance actions.
Microsoft 365
Native integration. Provides full visibility into Exchange Online, SharePoint Online, OneDrive, Teams, and Power Platform activities. No manual connector setup required for M365 workloads.
Third-Party SaaS
API connectors for Salesforce, ServiceNow, Google Workspace, Box, Dropbox, GitHub, Okta, and more. Each connector uses OAuth or service account credentials to access the provider API.
AWS / Azure / GCP
Cloud platform connectors provide visibility into IaaS/PaaS activity. Monitor admin actions, resource changes, and security configurations across multi-cloud environments.
Key Distinction
App connectors provide out-of-band visibility -- they pull data via API after the fact. Session controls (next slide) provide inline real-time enforcement. The exam tests whether you know which approach handles which scenario.

Conditional Access App Control
Session controls use a reverse proxy architecture to enforce real-time policies during user sessions. Traffic routes through Defender for Cloud Apps, enabling inline monitoring and control.
1
Microsoft Entra ID Conditional Access policy -- Create a policy that routes sessions to Defender for Cloud Apps. The policy targets specific users, apps, and conditions (device state, location, risk level).
2
Reverse proxy redirection -- When conditions match, the user session routes through the Defender for Cloud Apps proxy (*.mcas.ms domain). The proxy sits between the user and the cloud app.
3
Session policy enforcement -- Policies inspect activities in real time: block file downloads on unmanaged devices, apply sensitivity labels on upload, prevent copy/paste of sensitive data, or watermark downloaded documents.
4
Access policy enforcement -- Access policies can block or monitor access entirely based on user, device, and location context. More restrictive than session policies -- they gate access at the door.
Exam Trap
Session controls require a Microsoft Entra ID Conditional Access policy as the trigger mechanism. Without the Conditional Access integration, traffic does not route through the proxy. This is a common exam distractor.

Anomaly Detection Policies
Anomaly detection policies use machine learning and UEBA to identify unusual behavior patterns in connected cloud apps. They are enabled by default and start learning user behavior immediately.
Impossible Travel
Detects sign-ins from geographically distant locations within an impossible timeframe. Filters out VPNs and known corporate IPs to reduce false positives.
Risky Sign-In
Identifies sign-ins from anonymous proxies, Tor exit nodes, suspicious IPs, or locations never seen for that user. Correlates with Microsoft Entra ID Protection risk signals.
Unusual Activities
Detects anomalous file download volume, unusual admin operations, multiple failed logins, and data exfiltration patterns based on learned user baselines.
Ransomware Activity
Identifies rapid file encryption patterns across cloud storage -- mass renames with known ransomware extensions, high volume of file modifications in short timeframes.
Suspicious Inbox Rules
Detects creation of inbox forwarding rules that redirect email to external addresses. Common technique used after account compromise to maintain persistence.
New Country/Region
Flags activity from a country or region never seen for that user or any user in the organization. Considers the entire organization learning period.
Slide 7 of 12
User and Entity Behavior Analytics
UEBA in Defender for Cloud Apps builds behavioral profiles for each user across all connected apps. It assigns investigation priority scores to identify the riskiest users in your organization.
Investigation Priority Score
Each user gets a dynamic score (0-100) based on anomalous activities, alert correlations, and behavioral deviations. Higher scores indicate more suspicious behavior requiring analyst investigation.
Behavioral Baselines
UEBA learns normal patterns for each user: typical sign-in locations, working hours, apps accessed, files shared, and admin operations. Deviations from baseline trigger investigation priority increases.
Cross-App Correlation
Behavior is tracked across ALL connected apps. A user who suddenly downloads large volumes from SharePoint AND creates forwarding rules in Exchange AND accesses new SaaS apps gets a compounding risk score.
User Page
The user page in the portal shows the complete investigation picture: activity timeline, alerts, connected devices, IP addresses, locations, and peer group comparison for anomaly context.
SOC Workflow
UEBA investigation priority scores help SOC analysts focus on the highest-risk users first. Sort users by priority score, then drill into the user page to review the timeline and determine if the behavior is legitimate or compromised.
Slide 8 of 12
OAuth App Governance
OAuth apps request permissions to access organizational data on behalf of users. App governance in Defender for Cloud Apps provides visibility, policy control, and remediation for OAuth apps registered in Microsoft Entra ID.
App Visibility
View all OAuth apps registered in your tenant, their permission levels, which users consented, and what data they access. Identify overprivileged apps and apps with suspicious behavior patterns.
App Policies
Create policies to detect and respond to OAuth app risks: alert on high-privilege apps, auto-revoke apps from untrusted publishers, flag apps accessing specific data types, and enforce publisher verification requirements.
Remediation
Disable risky OAuth apps, revoke permissions, or ban apps entirely. Governance actions can be manual or automated through policy rules. Banned apps cannot be re-consented by users.
Real-World Context
OAuth phishing is a growing attack vector. Attackers create malicious apps that request broad permissions (Mail.Read, Files.ReadWrite.All). Once a user consents, the attacker has persistent API access that survives password resets. App governance stops this.

File Policies and DLP
File policies scan files stored in connected cloud apps for sensitive content, external sharing, and compliance violations. They combine content inspection with governance actions for data protection.
Content Inspection
Scan files for sensitive information types (SSN, credit cards, health records) using built-in DLP engines or Microsoft Information Protection sensitivity labels. Files in SharePoint, OneDrive, Box, Dropbox, and more are scanned.
Sharing Controls
Detect files shared externally, shared with personal email addresses, or shared via public links. Policies can match on specific domains, internal-only requirements, or exclude approved partner domains.
Governance Actions
When a file matches a policy: apply a sensitivity label, remove external sharing, quarantine the file, notify the file owner, or send to an admin review queue. Actions vary by connected app capabilities.
Policy Templates
Pre-built templates for common scenarios: externally shared files with PII, files shared from quarantined users, stale externally-shared files, and files with specific extensions in cloud storage.
Integration
File policies integrate with Microsoft Information Protection. When a sensitivity label is applied by a file policy, the label persists even if the file is downloaded and shared outside the organization -- providing persistent data protection.
Slide 10 of 12
Activity Policies and Alerts
Activity policies monitor user and admin actions across connected apps. They trigger alerts and governance actions when specific activity patterns are detected.
Activity Filters
Filter on app, user, IP address, location, device type, activity type, and more. Combine multiple filters with AND/OR logic to create precise detection rules for specific scenarios.
Repeated Activity
Detect patterns where an activity occurs multiple times within a window -- for example, 10 failed logins in 5 minutes, or 50 file downloads in 1 hour. Configurable thresholds and time windows.
Governance Actions
Suspend user, require sign-in again, confirm user compromised (feeds to Microsoft Entra ID Protection), notify user/manager, or trigger a Power Automate flow for custom response workflows.
Alert Pipeline
Activity policy alerts flow into the Defender for Cloud Apps alert queue and can be integrated into Defender XDR incidents. Set severity levels (Low, Medium, High) to prioritize SOC triage and map to your incident response procedures.

Defender for Cloud Apps Architecture
How the components fit together -- from discovery through enforcement.
Data Flow
Cloud Discovery and App Connectors feed data IN. The CASB engine processes it through policies and UEBA. Alerts flow OUT to the Defender XDR unified incident queue. Session proxy operates inline for real-time enforcement.

Chapter 5 Summary
Key concepts you must know for the SC-200 exam.
1CASB Role -- Defender for Cloud Apps is the CASB. Four pillars: Discover, Investigate, Control, Protect. It sits between users and cloud services.
2Cloud Discovery -- identifies shadow IT via log collection, Defender for Endpoint integration, or snapshot reports. Apps get risk scores 1-10 and can be sanctioned or unsanctioned.
3App Connectors -- API-based, out-of-band integration with SaaS apps. Provide deep visibility into files, activities, and accounts. Microsoft 365 connector is built-in.
4Session Controls -- Conditional Access App Control uses a reverse proxy (*.mcas.ms). Requires Microsoft Entra ID Conditional Access policy. Enforces real-time download blocks, labeling, and watermarking.
5Anomaly Detection -- ML-based policies detect impossible travel, risky sign-ins, ransomware patterns, and unusual activities. UEBA assigns investigation priority scores (0-100) per user.
6OAuth Governance -- monitors registered OAuth apps, detects overprivileged permissions, and can revoke or ban risky apps. Prevents OAuth phishing attacks that survive password resets.
