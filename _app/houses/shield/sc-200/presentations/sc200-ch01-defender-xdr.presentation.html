Microsoft Defender XDR Overview
Defender XDR (Extended Detection and Response) unifies four workload-specific products into a single portal at security.microsoft.com. One console, one incident queue, one investigation experience.
Defender for Endpoint
Protects devices -- workstations, servers, mobile. Provides endpoint detection and response (EDR), attack surface reduction rules, vulnerability management, and automated investigation. Signals feed into the unified incident queue.
Defender for Identity
Monitors on-premises Active Directory signals. Detects lateral movement, credential theft, reconnaissance, and compromised identities. Integrates with Microsoft Entra ID Protection for hybrid identity threat detection.
Defender for Office 365
Protects email and collaboration tools. Safe Attachments detonates files in sandboxes. Safe Links rewrites and scans URLs. Anti-phishing policies use AI to detect impersonation and business email compromise (BEC).
Defender for Cloud Apps
Cloud Access Security Broker (CASB). Discovers shadow IT, controls app access, detects anomalous user behavior in SaaS apps. Provides session policies, app governance, and OAuth app control.
Key Concept
Defender XDR automatically correlates alerts from all four products into unified incidents. A single phishing attack that compromises a mailbox, triggers lateral movement, and exfiltrates data appears as ONE incident -- not dozens of isolated alerts.

The Unified Portal
security.microsoft.com is the single pane of glass for Microsoft 365 security operations. Every SOC workflow starts here.
Incidents and Alerts
The incident queue is the SOC analyst's starting point. Incidents group related alerts from all Defender products. Each incident shows affected entities, MITRE ATT&CK tactics, severity, and investigation status.
Investigation Graph
Visual graph connecting all entities involved in an incident: users, devices, mailboxes, files, processes, IPs. Click any entity to pivot and explore the full attack chain from initial access to impact.
RBAC and Permissions
Access is controlled through Microsoft Entra roles. Security Reader for view-only, Security Operator for response actions, Security Administrator for full configuration. Custom roles available for granular control.

Incidents vs Alerts
Alerts are individual detections. Incidents are correlated groups of alerts that represent a full attack story. SOC analysts work incidents, not individual alerts.
Alert
A single detection from one product. Example: "Suspicious email delivered" from Defender for Office 365. Alerts have severity (Informational, Low, Medium, High) and a MITRE ATT&CK tactic mapping.
Incident
A correlated group of related alerts plus all affected entities. Defender XDR uses AI to automatically group alerts that belong to the same attack. One incident = one attack story from initial access to impact.
Incident Lifecycle
New -- unassigned, awaiting triage. In Progress -- assigned analyst investigating. Resolved -- investigation complete, response actions taken. Incidents can be classified as True Positive, False Positive, or Informational.

Incident Investigation
When a SOC analyst opens an incident, they follow a structured investigation workflow: understand scope, analyze evidence, determine root cause, and take response actions.
1Attack Story tab -- timeline view showing all alerts and entities in chronological order. Start here to understand the sequence of events from initial access through impact.
2Alerts tab -- drill into individual alerts. Each alert shows the detection logic, affected entities, evidence (processes, files, registry keys), and recommended response actions.
3Assets tab -- all users, devices, and mailboxes involved. Click any entity to see its full timeline: sign-ins, file activity, process execution, network connections.
4Evidence tab -- files, processes, IPs, and URLs flagged as malicious or suspicious. Analysts can approve or reject pending remediation actions from this tab.
5Response actions -- isolate device, disable user, soft-delete email, block URL, run antivirus scan, collect investigation package. Actions can be manual or recommended by AIR.
Exam Tip
The Attack Story tab is the recommended starting point for incident investigation. It provides the chronological timeline of the full attack chain across all products.

Automated Investigation and Response (AIR)
AIR uses security playbooks to automatically investigate alerts and take remediation actions. It acts as a virtual analyst that triages, investigates, and proposes or executes fixes.
Trigger
An alert fires from any Defender product. AIR automatically starts investigating based on the alert type and configured playbooks.
Investigation
AIR expands the alert scope: analyzes related processes, files, registry changes, email headers, sign-in logs. Builds a complete entity graph of the attack.
Verdict
Each entity gets a verdict: Malicious, Suspicious, Clean, or No threats found. Verdicts drive the remediation actions that AIR recommends.
Pending Actions
Actions requiring analyst approval appear in the Action Center. Example: quarantine a file, disable an account. Analyst reviews and approves or rejects.
Auto-Remediation
With full automation, AIR executes remediation without waiting for approval. Semi-automation requires approval for specific action types. Configured per device group.
Action Center
Central hub for all pending and completed actions. Shows action type, status, entity, and which investigation triggered it. History tab tracks all past actions.
Automation Levels
Full -- all actions auto-executed. Semi -- requires approval for specific action types. No automated response -- AIR investigates but takes no action. Set per device group in Defender for Endpoint settings.

Advanced Hunting with KQL
Advanced hunting is a query-based threat hunting tool that lets analysts proactively search across 30 days of raw telemetry data using Kusto Query Language (KQL).
// Find emails with malicious URLs delivered in the last 7 days EmailEvents | where Timestamp > ago(7d) | where DeliveryAction == "Delivered" | join EmailUrlInfo on NetworkMessageId | where UrlCount > 0 | project Timestamp, SenderFromAddress, RecipientEmailAddress, Subject
KQL Basics
KQL uses a pipe-based syntax. Start with a table, filter with where, select columns with project, aggregate with summarize, join tables with join. Data flows left to right through the pipe chain.
Key Tables
DeviceEvents, DeviceProcessEvents, EmailEvents, IdentityLogonEvents, CloudAppEvents. Each table covers a Defender workload. Schema reference is available in the portal.
Custom Detections
Save hunting queries as custom detection rules. They run on a schedule (every 1, 3, 12, or 24 hours) and automatically generate alerts when results are found. Turns proactive hunting into automated detection.
Slide 8 of 12
Hunting Tables and Schema
Advanced hunting provides cross-workload tables spanning endpoints, email, identity, and cloud apps. Understanding the schema is critical for writing effective queries.
Endpoint Tables
DeviceEvents -- general device telemetry. DeviceProcessEvents -- process creation. DeviceNetworkEvents -- network connections. DeviceFileEvents -- file operations. DeviceLogonEvents -- local and remote sign-ins.
Email Tables
EmailEvents -- all email activity. EmailAttachmentInfo -- attachment metadata. EmailUrlInfo -- URLs in messages. EmailPostDeliveryEvents -- post-delivery actions like ZAP (zero-hour auto purge).
Identity Tables
IdentityLogonEvents -- sign-in events from AD and Entra ID. IdentityQueryEvents -- AD queries (LDAP, DNS). IdentityDirectoryEvents -- directory changes like group membership modifications.
Cloud App Tables
CloudAppEvents -- activity from connected cloud apps. Covers file downloads, sharing, login events, and administrative actions from SaaS applications monitored by Defender for Cloud Apps.
Cross-Workload Hunting
The real power of advanced hunting is joining tables across workloads. Example: join EmailEvents with DeviceProcessEvents to track what happened on an endpoint after a user clicked a link in a phishing email.

Threat Analytics
Threat analytics provides expert-written reports on active threat campaigns. Each report shows whether your organization is exposed and what to do about it.
Analyst Reports
Written by Microsoft Threat Intelligence researchers. Each report covers a specific threat campaign: TTPs (tactics, techniques, procedures), IOCs (indicators of compromise), and recommended mitigations.
Exposure Assessment
Each report automatically checks your environment against the threat. Shows: number of vulnerable devices, number of devices with mitigations applied, and impacted mailboxes. Color-coded risk indicators.
Mitigation Recommendations
Actionable steps to reduce exposure: apply specific patches, enable specific detection rules, block specific IOCs. Links directly to the relevant configuration pages in the portal.
Example: A new ransomware campaign is exploiting a Windows vulnerability. Threat analytics shows you have 47 unpatched devices, provides the CVE number, and links to the patch deployment workflow. SOC and IT teams collaborate to close the gap before the attack reaches your environment.
Slide 10 of 12
Microsoft Secure Score
Secure Score is a numerical representation of your organization's security posture. Higher score means more recommended security controls have been implemented.
How It Works
Microsoft evaluates your tenant configuration against hundreds of security best practices. Each recommendation earns points when implemented. Your score is a percentage of the maximum achievable points for your licensed products.
Improvement Actions
Each recommended action shows: point value, implementation status, user impact, and implementation complexity. Actions are categorized by product (Identity, Data, Device, Apps) and prioritized by impact.
Comparison and History
Compare your score against organizations of similar size and industry. Track score changes over time to measure security posture improvement. Score regression alerts notify you when the score drops.
Integration
Secure Score feeds into threat analytics exposure assessments, compliance reports, and executive dashboards. It provides a common language for communicating security posture to leadership.
Slide 11 of 12
Response Actions
SOC analysts need to contain and remediate threats quickly. Defender XDR provides response actions across all workloads -- devices, users, email, and files.
Isolate Device
Cuts network access to/from device while maintaining Defender for Endpoint connectivity. Prevents lateral movement while preserving investigation capability.
Disable User
Disables the compromised account in Microsoft Entra ID. Revokes all active sessions and refresh tokens. Blocks further access to all Microsoft 365 services.
Soft Delete Email
Moves malicious emails to Deleted Items across all affected mailboxes. Can target specific messages by NetworkMessageId. Reversible action.
Block File/URL
Adds file hash or URL to the tenant block list. Prevents execution on all endpoints and delivery through email. Applies across the entire organization.
Run AV Scan
Triggers a full Microsoft Defender Antivirus scan on a specific device. Results appear in the device timeline. Can be initiated remotely from the portal.
Collect Package
Collects a forensic investigation package from the device: running processes, scheduled tasks, security logs, network state. Downloaded as a zip for offline analysis.
