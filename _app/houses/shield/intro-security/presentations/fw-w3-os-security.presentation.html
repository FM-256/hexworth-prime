Incident Report FW-302. A technician images a new laptop for an executive and ships it with default settings -- Windows Firewall disabled for "easier setup," UAC turned off because the user "complained about prompts," and BitLocker not activated because "it slows down the drive." Three weeks later the laptop is stolen from a hotel room. The unencrypted drive yields every contract, financial projection, and client NDA the executive had ever opened. Every one of those settings existed to prevent exactly this outcome.

Windows Defender Antivirus
Built-in anti-malware that provides real-time protection, cloud-delivered intelligence, and automatic sample submission.
Real-Time Protection
Scans files as they are opened, downloaded, or executed. Uses signature-based detection for known malware and behavior-based heuristics for unknown threats. Runs as a protected process to prevent malware from disabling it.
Cloud-Delivered Protection
Suspicious files are checked against Microsoft's cloud intelligence within milliseconds. If a new threat is detected anywhere in the world, the signature can be pushed to all Defender clients within minutes. This provides near-zero-day protection for known campaigns.
Tamper Protection
Prevents unauthorized applications or users from disabling Defender, changing real-time protection settings, or modifying cloud protection. Even local administrators cannot turn off tamper protection without going through the Microsoft 365 Defender portal.
Best Practice
Keep Defender enabled and updated. Do not disable it to install third-party antivirus unless required by organizational policy. Run periodic full scans in addition to real-time protection. Review the Protection History for blocked threats.

BitLocker Drive Encryption
Full-disk encryption that protects data at rest. If a device is lost or stolen, the drive contents cannot be read without the encryption key.
How BitLocker Works
Encrypts the entire drive volume using AES-128 or AES-256. The encryption key is stored in the Trusted Platform Module (TPM) chip on the motherboard. During normal boot, the TPM releases the key automatically. If the drive is removed and placed in another machine, the TPM will not release the key and the data is unreadable.
Recovery Key
A 48-digit recovery key is generated during BitLocker setup. This key is the only way to access the drive if the TPM fails or hardware changes are detected. Recovery keys should be stored in Active Directory, Azure AD, or printed and secured in a safe. Losing the recovery key with a failed TPM means permanent data loss.
BitLocker To Go
Extends BitLocker encryption to removable USB drives and external hard drives. Encrypted USB drives require a password to unlock on any Windows machine. Prevents data exposure when removable media is lost -- USB drives are among the most commonly lost corporate devices.
Why It Matters
Without BitLocker, anyone who physically obtains a laptop can remove the hard drive, connect it to another system, and read every file without needing a password. BitLocker makes the stolen drive worthless without the encryption key. Compliance frameworks (HIPAA, PCI-DSS) often require full-disk encryption on mobile devices.

Windows Firewall
Host-based firewall that filters inbound and outbound network traffic based on rules. Each network profile (Domain, Private, Public) has independent settings.
Network Profiles
Domain profile: applied when connected to a corporate domain. Private profile: home or trusted network. Public profile: coffee shops, airports, hotels. Public profile should be the most restrictive -- block all inbound connections, allow only essential outbound traffic.
Inbound Rules
Control which incoming connections are allowed. By default, Windows Firewall blocks all unsolicited inbound connections. Rules are created per-application or per-port. Example: allow inbound TCP port 3389 only from the IT subnet for Remote Desktop access.
Outbound Rules
Control which programs can send traffic to the network. Outbound filtering is less common but blocks malware from phoning home to command-and-control servers. An outbound rule blocking all traffic except approved browsers and business applications significantly reduces the attack surface.
Never Do This
Never disable Windows Firewall entirely "to fix a connectivity issue." Diagnose the specific rule that needs adjustment. Disabling the firewall exposes every listening service on the machine to the network -- including services you did not know were running.

User Account Control (UAC)
UAC prevents unauthorized changes to the operating system by requiring explicit approval before elevated actions execute.
How UAC Works
Even administrator accounts run with standard user privileges by default. When an action requires elevation (installing software, modifying system settings, editing the registry), UAC dims the screen and prompts for confirmation. This prevents malware from silently executing with full administrative privileges.
Why Users Disable It
The "Yes/No" prompts interrupt workflow, especially for IT staff who perform frequent administrative tasks. Some users disable UAC entirely. This is a critical security mistake -- it removes the primary barrier between standard operations and system-level changes, allowing malware to run elevated without any prompt.
UAC Levels
Four levels from "Always Notify" (most secure) to "Never Notify" (disabled). The default level notifies when apps try to make changes but not when the user changes Windows settings. For maximum security, set to "Always Notify" -- the prompts are a feature, not a bug.
Standard User Accounts
Best practice: daily work accounts should be standard users, not administrators. UAC prompts for standard users require entering an administrator password, providing an additional authentication layer. This implements the principle of least privilege at the OS level.

Group Policy Basics
Centralized configuration management for Windows environments. Group Policy Objects (GPOs) enforce security settings across hundreds or thousands of machines simultaneously.
What GPOs Control
Password requirements (length, complexity, history), account lockout thresholds, firewall rules, software installation restrictions, USB device policies, screensaver timeouts, audit logging, and hundreds of other settings. A single GPO can enforce consistent security across an entire organization.
Local vs Domain Policy
Local Group Policy (gpedit.msc) applies to a single machine. Domain Group Policy (managed via Group Policy Management Console) applies to all machines in an Active Directory domain. Domain policies override local policies. In enterprise environments, domain GPOs are the primary enforcement mechanism.
Security Templates
Pre-built policy configurations that can be imported into GPOs. Microsoft provides security baselines for each Windows version. CIS Benchmarks provide independently verified hardening templates. Applying a security baseline is faster and more reliable than configuring hundreds of settings manually.
Slide 7 of 14
Account Lockout Policies
Lockout policies prevent brute-force password attacks by disabling accounts after a specified number of failed login attempts.
Lockout Threshold
Number of failed attempts before lockout. Common setting: 3-5 attempts. Too low (1-2) causes excessive lockouts from typos. Too high (10+) gives brute-force attackers too many guesses. NIST 800-63B recommends rate limiting rather than hard lockout to prevent denial-of-service via intentional lockouts.
Lockout Duration
How long the account stays locked. Common setting: 15-30 minutes. Setting to 0 means the account stays locked until an administrator manually unlocks it. Automatic unlock after a timer is more operationally practical but gives attackers another window to attempt again.
Reset Counter
Time after which the failed attempt counter resets to zero. If set to 30 minutes, an attacker who waits 31 minutes between attempts gets a fresh set of tries. This counter should be equal to or greater than the lockout duration.
Lockout as DoS Vector
An attacker who knows usernames can intentionally trigger lockouts on every account, creating a denial-of-service condition. This is why many modern systems use progressive delays (1s, 2s, 4s, 8s) or CAPTCHA challenges instead of hard lockouts for remote access portals.

Windows Update
Patch management is the single most impactful security control. Unpatched systems are the primary entry point for exploitation.
Patch Tuesday
Microsoft releases security updates on the second Tuesday of every month. These patches fix vulnerabilities that have been disclosed (and sometimes already exploited). The window between patch release and patch installation is the highest-risk period -- attackers reverse-engineer patches to build exploits for unpatched systems.
Update Categories
Critical: remotely exploitable without user interaction. Important: exploitation requires user action. Moderate: mitigated by default configuration. Low: minimal impact. Critical patches should be deployed within 24-72 hours. Important patches within 2 weeks. Delayed patching is accepted risk.
WSUS and SCCM
Windows Server Update Services (WSUS) allows IT to approve and distribute patches centrally. System Center Configuration Manager (SCCM/MECM) provides enterprise-scale patch deployment with compliance reporting. Both allow testing patches on a pilot group before organization-wide deployment.
The WannaCry Lesson
The WannaCry ransomware (May 2017) exploited a Windows SMB vulnerability (EternalBlue/MS17-010). Microsoft had released the patch two months earlier. Organizations that applied the patch were unaffected. Those that delayed patching suffered catastrophic data loss. Patching is not optional.

Event Viewer and Audit Policies
Windows logs every significant system event. Event Viewer is the primary tool for reviewing security logs, identifying threats, and supporting forensic investigations.
Key Security Event IDs
4624: Successful logon. 4625: Failed logon. 4720: Account created. 4726: Account deleted. 4732: Member added to security group. 1102: Audit log cleared (often indicates an attacker covering tracks). These event IDs are the foundation of security monitoring and incident investigation.
Audit Policies
Control what events Windows records. Configure via Group Policy under Security Settings > Advanced Audit Policy Configuration. Enable auditing for logon events, account management, object access, policy changes, and privilege use. Without audit policies enabled, critical security events are not logged.
Log Forwarding
Windows Event Forwarding (WEF) sends logs to a central collector. In enterprise environments, logs are forwarded to a SIEM (Security Information and Event Manager) like Splunk, Elastic, or Microsoft Sentinel for correlation, alerting, and long-term retention.
Log Retention
Default log sizes are often too small. Logs overwrite themselves when full, destroying evidence. Increase the Security log to at least 1 GB. For compliance, retain logs for 90 days to 1 year depending on the framework. Logs that are not retained cannot support a forensic investigation.

Screensaver Lock and Auto-Lock
Automatic screen locking prevents unauthorized access when a user walks away from their workstation.
Group Policy Setting
User Configuration > Administrative Templates > Control Panel > Personalization. Enable "Screen saver timeout" (set to 600 seconds / 10 minutes or less) and "Password protect the screen saver." This ensures machines lock automatically even if users forget.
Why 15 Minutes Is Too Long
In a busy office, an unlocked workstation for 15 minutes gives an insider or visitor enough time to copy files, install malware, or access email. For environments handling sensitive data (healthcare, finance, classified), 5 minutes is the recommended maximum idle timeout.
Win+L Manual Lock
Train users to press Win+L before leaving their desk -- even for a 30-second coffee refill. The automatic timer is a safety net, not the primary control. Building the habit of manual locking is faster and more secure than relying on the idle timeout alone.
Compliance Requirement
HIPAA, PCI-DSS, and most compliance frameworks require automatic screen locking after a period of inactivity. Failing to enforce this policy is a common audit finding. The fix takes 30 seconds in Group Policy.

Windows Security Dashboard
The Windows Security app provides a centralized view of all security features and their current status.
Virus & Threat Protection
Current threat status, scan history, protection updates, and ransomware protection settings. Controlled Folder Access prevents unauthorized applications from modifying files in protected folders -- a direct defense against ransomware encryption.
Firewall & Network Protection
Status of firewall for each network profile (Domain, Private, Public). Quick access to allow an app through the firewall, view notification settings, and access advanced firewall configuration. Green checkmarks indicate active protection.
App & Browser Control
SmartScreen settings for Microsoft Edge and Microsoft Store apps. Exploit protection settings that mitigate common exploitation techniques (DEP, ASLR, CFG). Reputation-based protection blocks downloads that are unsigned or rare.
Device Security
Core isolation (memory integrity), Secure Boot status, and TPM information. Memory integrity uses virtualization-based security to isolate critical processes. These hardware-backed features prevent rootkits and kernel-level attacks that traditional antivirus cannot detect.

SmartScreen and Exploit Protection
Reputation-based filtering and exploit mitigation that protect against malicious downloads and common attack techniques.
SmartScreen Filter
Checks downloads and websites against Microsoft's reputation database. Files that are unsigned, rare, or from known malicious sources trigger a warning or block. SmartScreen in Edge also protects against phishing sites by checking URLs against a dynamically updated list of known phishing domains.
Exploit Protection
System-level exploit mitigations: Data Execution Prevention (DEP) prevents code from running in data memory regions. Address Space Layout Randomization (ASLR) randomizes memory addresses to defeat buffer overflow attacks. Control Flow Guard (CFG) prevents control flow hijacking. These run transparently with no performance impact.
Controlled Folder Access
Ransomware protection that prevents untrusted applications from modifying files in designated folders (Documents, Desktop, Pictures by default). Only whitelisted applications can write to protected folders. If ransomware attempts to encrypt your Documents folder, Controlled Folder Access blocks the write operation.
Attack Surface Reduction
ASR rules block common malware behaviors: Office macros creating child processes, obfuscated scripts executing, credential theft from LSASS, and email attachments launching executables. ASR rules are enabled via Group Policy or Intune and provide defense against the most common malware delivery techniques.

Defense in Depth: All Settings Together
No single setting protects a system. Windows security is effective only when all layers are enabled and configured correctly.
Layer 1: Prevent
Defender catches malware before execution. Firewall blocks unauthorized network access. UAC prevents unauthorized elevation. SmartScreen blocks malicious downloads. BitLocker protects data if the device is stolen. Each layer stops a different type of attack.
Layer 2: Enforce
Group Policy enforces consistent settings across all machines. Account lockout policies prevent brute force. Password policies require complexity. Auto-lock prevents unauthorized physical access. Enforcement means settings cannot be weakened by individual users.
Layer 3: Detect
Event Viewer and audit policies record every security event. Failed logon attempts, privilege escalation, account changes, and policy modifications are all logged. Without detection, you cannot identify breaches, investigate incidents, or prove compliance. Logging is the foundation of security visibility.
The Cost of One Missing Layer
Every breach investigation reveals at least one disabled or misconfigured security setting. BitLocker was off. The firewall was disabled. UAC was turned down. Audit logging was not enabled. Patching was six months behind. Each setting is a link in the chain. One missing link is all an attacker needs.

Week 3 Summary: Windows OS Security
1 Windows Defender provides real-time, cloud-connected anti-malware with tamper protection. Keep it enabled and updated.
2 BitLocker encrypts the entire drive using AES-128/256 with TPM key storage. Without it, a stolen drive can be read by anyone.
3 Windows Firewall has three profiles (Domain, Private, Public). Never disable it entirely -- adjust specific rules instead.
4 UAC prevents unauthorized elevation. Disabling it removes the barrier between user actions and system-level changes.
5 Group Policy enforces security settings (passwords, lockout, firewall, audit) across all machines in a domain centrally.
6 Account lockout (3-5 attempts, 15-30 min duration) prevents brute-force attacks but can be used as a DoS vector.
7 Windows Update patches vulnerabilities. The WannaCry ransomware exploited a flaw patched two months prior. Patching is not optional.
8 Event Viewer logs security events (4624 logon, 4625 failed, 1102 log cleared). Audit policies must be enabled or events are not recorded.
9 Auto-lock (screensaver + password) should be 5-10 minutes. Train users to press Win+L before leaving their desk.
10 Defense in depth: Defender + BitLocker + Firewall + UAC + GPO + Audit Logs. Every disabled setting is a gap an attacker will find.
