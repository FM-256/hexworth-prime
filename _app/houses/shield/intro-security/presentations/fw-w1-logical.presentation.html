Concepts

A user logs in with a valid password. They access a file they should not have permission to read. The file is not encrypted. No firewall blocked the access. Every logical control failed -- or was never configured. This presentation covers the controls that should have been there.

The CIA Triad
Every security control maps to at least one of these three pillars.
Confidentiality
Only authorized users can access the data. Encryption, access controls, and data classification enforce confidentiality. A data breach is a confidentiality failure.
Integrity
Data has not been altered without authorization. Hashing, digital signatures, and version control verify integrity. If someone modifies a record without permission, integrity is broken.
Availability
Systems are accessible when needed. Redundancy, backups, failover, and DDoS protection maintain availability. If the server is down, availability has failed.
The Trade-Off
Maximum confidentiality (encrypt everything, restrict all access) reduces availability. Maximum availability (everything open, no restrictions) destroys confidentiality. Security engineering is finding the right balance for each context.
Slide 3 of 14
Authentication
Proving you are who you claim to be. The first gate in every logical access system.
Passwords
Something you know. The most common authentication factor. Minimum 12 characters, complexity required. Vulnerable to brute force, dictionary attacks, and credential stuffing.
Multi-Factor Authentication
Combines two or more factors: knowledge (password), possession (token/phone), inherence (biometric). MFA reduces account compromise by over 99% according to Microsoft research.
Biometric Authentication
Fingerprint, face, iris, voice. Cannot be lost or forgotten. Can be spoofed on older systems. Biometric data is irrevocable -- once compromised, it cannot be changed like a password.
Single Sign-On (SSO)
SSO allows one authentication event to grant access to multiple systems. Reduces password fatigue and help desk calls. Implemented via SAML, OAuth, or Kerberos. Risk: if the SSO credential is compromised, the attacker gets access to everything.
Slide 4 of 14
Authorization
Authentication proves identity. Authorization determines what that identity is allowed to do.
ACLs (Access Control Lists)
Lists attached to resources that specify which users or groups have what permissions. File-level ACLs (read/write/execute) and network ACLs (allow/deny traffic).
RBAC (Role-Based Access Control)
Permissions assigned to roles, not individuals. Users inherit permissions by role assignment. Examples: Admin, Editor, Viewer. Simplifies management at scale.
DAC vs MAC
Discretionary (DAC): resource owner sets permissions. Mandatory (MAC): system enforces classification labels. MAC is used in military/government. DAC is the default in Windows/Linux.
Principle of Least Privilege
Every user, process, and service gets only the minimum permissions required to perform its function. No more. Least privilege limits blast radius when an account is compromised and reduces insider threat risk.
Slide 5 of 14
Encryption Basics
Converting readable data into unreadable form. Only the key holder can reverse the process.
Symmetric Encryption
One key encrypts and decrypts. Fast, efficient for bulk data. AES-256 is the standard. Challenge: securely distributing the shared key to both parties.
Asymmetric Encryption
Two keys: public key encrypts, private key decrypts. RSA and ECC are common. Slower than symmetric. Solves the key distribution problem. Used for digital signatures and key exchange.
Hashing
One-way function that produces a fixed-length fingerprint. SHA-256 is the standard. Used for password storage and integrity verification. Cannot be reversed -- only compared.
Encryption at Rest vs In Transit
At rest: BitLocker, FileVault, LUKS encrypt stored data. In transit: TLS/SSL encrypts data moving across networks. Both are required for compliance (PCI-DSS, HIPAA).
Slide 6 of 14
Firewalls
The gatekeeper between trusted and untrusted networks.
Packet Filtering
Examines source IP, destination IP, port, and protocol. Fast but no application awareness. Stateless -- each packet evaluated independently. First-generation firewall technology.
Stateful Inspection
Tracks connection state (SYN, SYN-ACK, ACK). Allows return traffic for established connections. Blocks unsolicited inbound. Second-generation -- the modern baseline.
Next-Gen Firewalls (NGFW)
Deep packet inspection, application awareness, intrusion prevention, SSL decryption, and user identity awareness all in one device. Palo Alto, Fortinet, and Cisco are major vendors.
Host-Based vs Network-Based
Network firewalls protect the perimeter. Host firewalls (Windows Firewall, iptables) protect individual machines. Both are required. A compromised machine inside the network bypasses the perimeter firewall -- host firewalls are the last line.
Slide 7 of 14
VPNs -- Virtual Private Networks
Creating a secure, encrypted tunnel across an untrusted network.
IPSec VPN
Operates at Layer 3 (network layer). Two modes: transport (encrypts payload) and tunnel (encrypts entire packet). Used for site-to-site VPNs and remote access. Industry standard.
SSL/TLS VPN
Operates at Layer 4-7. Uses the browser or a lightweight client. Easier to deploy than IPSec. No special client software needed for basic access. Common for remote workers.
Split Tunnel vs Full Tunnel
Full tunnel: all traffic routed through VPN. Maximum security, higher latency. Split tunnel: only corporate traffic goes through VPN. Faster but personal traffic is unprotected.
Slide 8 of 14
Principle of Least Privilege
Every subject gets only the access required to do its job. Nothing more.
User Accounts
Standard users should never have admin rights. Admin access requires a separate privileged account used only for administrative tasks. Daily work uses the standard account.
Service Accounts
Applications and services run under dedicated accounts with only the permissions they need. A web server account should not have write access to the entire filesystem.
Privilege Escalation
When an attacker gains higher privileges than intended. Vertical: user -> admin. Horizontal: user A -> user B. Least privilege limits what an attacker can reach after initial compromise.
Periodic Access Reviews
Permissions drift over time. Quarterly access reviews ensure users still need the access they have. Remove stale permissions. Document exceptions. Automate where possible.
Slide 9 of 14
Defense in Depth
No single control is sufficient. Multiple layers ensure that if one fails, others catch the attack.
Perimeter Layer
Firewalls, IPS/IDS, DMZ, proxy servers. Stops attacks at the network edge. Necessary but not sufficient -- attackers bypass perimeters via phishing and VPN credentials.
Network Layer
VLANs, network segmentation, microsegmentation. Limits lateral movement after breach. A compromised workstation cannot reach the database server if they are on different segments.
Host Layer
Antivirus, endpoint detection and response (EDR), host firewall, patch management. Protects individual machines regardless of network position.
Data Layer
Encryption at rest and in transit, DLP (data loss prevention), access controls on files and databases. The last defense -- even if everything else fails, encrypted data is useless to the attacker.
Slide 10 of 14
The AAA Framework
Authentication, Authorization, and Accounting -- the three pillars of access management.
Authentication (Who?)
Verify identity. Username/password, MFA, certificate, biometric. Without authentication, there is no way to know who is making a request.
Authorization (What?)
Determine permissions. ACLs, RBAC, group policies. After identity is confirmed, the system checks what that identity is allowed to do.
Accounting (When/Where?)
Log everything. Login times, resources accessed, actions taken, logout times. Accounting provides the audit trail for compliance and incident investigation.
RADIUS and TACACS+
RADIUS: UDP-based, encrypts only the password, widely used for network access (Wi-Fi, VPN). TACACS+: TCP-based, encrypts the entire session, separates authentication/authorization/accounting. Cisco environments prefer TACACS+.
Slide 11 of 14
IDS & IPS
Intrusion Detection System watches. Intrusion Prevention System acts.
Signature-Based Detection
Compares traffic against a database of known attack patterns. Fast and accurate for known threats. Completely blind to zero-day attacks. Requires constant signature updates.
Anomaly-Based Detection
Establishes a baseline of normal behavior. Alerts when activity deviates from the baseline. Can detect zero-days. Higher false positive rate. Requires tuning.
Network vs Host-Based
NIDS/NIPS monitors network traffic at strategic points. HIDS/HIPS runs on individual hosts monitoring file changes, logs, and process activity. Both perspectives are needed.
SIEM Integration
IDS/IPS alerts feed into a SIEM (Security Information and Event Management) system. Correlation of alerts from multiple sources reveals attack patterns invisible to any single sensor.
Slide 12 of 14
Network Segmentation
Dividing a network into zones limits lateral movement and contains breaches.
VLANs
Virtual LANs segment a physical network into logical zones. Traffic between VLANs must pass through a router or Layer 3 switch with ACLs. Broadcast domains are isolated.
DMZ (Demilitarized Zone)
A screened subnet between the internal network and the internet. Public-facing services (web, email, DNS) live here. Compromising a DMZ server should not give access to internal resources.
Zero Trust Architecture
Never trust, always verify. No implicit trust based on network location. Every request authenticated and authorized regardless of origin. Microsegmentation is the implementation mechanism.
Slide 13 of 14
Core Security Principles
Principles that apply to every system, every organization, every scenario.
Separation of Duties
No single person should control all phases of a critical process. The person who writes checks should not be the person who approves them. Prevents fraud and limits insider damage.
Need to Know
Access is granted based on job requirement, not rank or seniority. A network admin does not need access to HR salary data. Need-to-know reinforces least privilege at the data level.
Job Rotation
Moving employees between roles periodically. Detects fraud (a new person notices what the predecessor hid). Cross-trains staff. Reduces key-person dependency.
Mandatory Vacations
Require employees in sensitive roles to take consecutive days off. Fraud schemes often require constant presence to maintain. A substitute may discover irregularities.
Security Through Obscurity -- Not a Strategy
Hiding a system's design does not make it secure. Kerckhoffs' principle: a cryptographic system should be secure even if everything about the system, except the key, is public knowledge. Obscurity can supplement real controls. It must never replace them.
Slide 14 of 14  |  Summary
Logical Security -- Key Takeaways
Authentication, authorization, and defense in depth are the foundations of every secure system.
1 The CIA triad (Confidentiality, Integrity, Availability) is the foundational model. Every control maps to at least one pillar.
2 Authentication proves identity. MFA combines two or more factors and reduces account compromise by over 99%.
3 Authorization uses ACLs, RBAC, DAC, and MAC to control what authenticated users can do. Least privilege is mandatory.
4 Symmetric encryption (AES) is fast for bulk data. Asymmetric (RSA/ECC) solves key distribution. Hashing (SHA-256) verifies integrity.
5 Firewalls range from packet filtering to next-gen (NGFW). Both network and host-based firewalls are required.
6 VPNs create encrypted tunnels over untrusted networks. IPSec for site-to-site, SSL/TLS VPN for remote access.
7 Defense in depth layers controls at perimeter, network, host, and data levels. No single layer is sufficient.
8 AAA framework: Authentication (who), Authorization (what), Accounting (when/where). RADIUS for network access, TACACS+ for device admin.
9 Network segmentation (VLANs, DMZ, microsegmentation) limits lateral movement. Zero trust verifies every request regardless of origin.
