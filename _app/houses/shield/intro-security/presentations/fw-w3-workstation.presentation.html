Incident Report FW-303. A department purchases 40 new workstations. IT deploys them with the manufacturer's default image -- Candy Crush pre-installed, Telnet enabled, Remote Desktop open to all networks, and the local Administrator account using the password "admin." Within 72 hours, 12 machines are compromised by automated scanning bots that discovered the open RDP port and guessed the default credentials in under 30 seconds. Every one of those compromises was preventable with a standard hardening checklist.

What Is Workstation Hardening?
Reducing the attack surface by disabling unnecessary features, removing unneeded software, and enforcing security configurations before deployment.
Attack Surface
Every running service, open port, installed application, and enabled feature is a potential entry point for an attacker. A default Windows installation includes dozens of services and features that most workstations never use. Each one is an unnecessary risk.
Hardening Principle
Remove everything that is not explicitly required. Disable every service that is not needed. Close every port that is not in use. Restrict every permission to the minimum necessary. The most secure service is one that does not exist.
Hardening Guides
CIS Benchmarks, DISA STIGs, and Microsoft Security Baselines provide step-by-step hardening checklists. These are not opinions -- they are tested, documented, and auditable configurations used by government agencies and enterprises worldwide.

Disable Unnecessary Services
Every running service is a potential attack vector. If a service is not needed, it should be disabled.
High-Risk Services to Disable
Remote Registry (allows remote editing of the registry), Telnet (unencrypted remote access), SMBv1 (exploited by WannaCry/EternalBlue), Remote Desktop (if not needed -- primary ransomware entry point), SNMP (default community strings), FTP (cleartext credentials).
How to Disable
Services console (services.msc): set startup type to Disabled. Via PowerShell: Set-Service -Name "RemoteRegistry" -StartupType Disabled. Via Group Policy: Computer Configuration > Windows Settings > Security Settings > System Services. GPO is preferred for enterprise-wide enforcement.
Print Spooler Warning
The Print Spooler service has been the target of multiple critical vulnerabilities (PrintNightmare, CVE-2021-34527). If the workstation does not print, disable the Print Spooler. Even on machines that print, apply all available patches immediately when Print Spooler CVEs are disclosed.

Remove Bloatware
Pre-installed software from manufacturers increases the attack surface, consumes resources, and may include vulnerable components.
What Is Bloatware
Pre-installed trial software (McAfee trials, Norton trials, Office trials), manufacturer utilities (HP Support Assistant, Dell SupportAssist, Lenovo Vantage), games (Candy Crush, Solitaire Collection), and browser toolbars. Each application is code running on the system that could contain vulnerabilities, phone home to external servers, or consume memory and CPU.
The Superfish Lesson
In 2015, Lenovo shipped consumer laptops with Superfish Visual Discovery -- adware that installed its own root CA certificate to inject ads into HTTPS traffic. This broke the entire TLS trust model, allowing any attacker to perform man-in-the-middle attacks on encrypted connections. Pre-installed software from a trusted manufacturer created a critical vulnerability.
Best Practice: Clean Image
Enterprise IT should build a standardized base image using a clean Windows ISO (not the OEM image) with only approved applications. Deploy this image to all workstations. This eliminates bloatware, ensures consistent configuration, and reduces the attack surface from day one.
Windows Optional Features
Go to Settings > Apps > Optional Features or Programs and Features > Turn Windows features on or off. Disable features not needed: Internet Explorer (legacy), PowerShell v2 (downgrade attack vector), SMBv1, Telnet Client, TFTP Client. Fewer features means fewer vulnerabilities.

Strong Passwords and Account Policies
Password policy is the first line of defense against brute-force and credential-stuffing attacks.
NIST 800-63B Guidelines
Minimum 8 characters (14+ recommended). Check passwords against known breach lists. Do NOT require forced periodic rotation (it leads to predictable patterns like "Summer2026!"). Allow passphrases (long, memorable phrases are stronger than short complex strings).
Passphrases Over Complexity
"correct-horse-battery-staple" (25 characters) is vastly stronger than "P@ssw0rd!" (9 characters) despite having no special characters. Length defeats brute force exponentially. Every additional character multiplies the search space by the character set size. Teach users to think in phrases, not symbols.
Password Managers
Users cannot memorize unique 20-character passwords for 50 accounts. Password managers generate and store unique credentials for every service. The user remembers one strong master passphrase. Enterprise password managers (1Password Business, Bitwarden) provide centralized deployment and audit logging.
Multi-Factor Authentication
Strong passwords alone are not sufficient. MFA (something you know + something you have) prevents credential-stuffing attacks even when the password is compromised. Enable MFA on every account that supports it -- email, VPN, cloud services, administrative consoles.

Auto-Lock and Encryption
Physical access controls and full-disk encryption protect data when the user is away from the machine or the device is stolen.
Auto-Lock Configuration
Set screensaver timeout to 5 minutes with password-on-resume via Group Policy. For high-security environments, use proximity-based locking (Bluetooth token disconnects = instant lock). Train the Win+L reflex for manual locking. An unlocked workstation is an open invitation.
Full-Disk Encryption
BitLocker (Windows Pro/Enterprise) or VeraCrypt (for Windows Home or cross-platform). Encrypts the entire drive so a stolen laptop yields encrypted data, not readable files. Without FDE, removing the hard drive and connecting it to another machine bypasses all Windows login protections.
Encrypted Removable Media
BitLocker To Go encrypts USB drives. Group Policy can require all removable drives to be encrypted before data can be written to them. This prevents data exfiltration via unencrypted USB drives -- a common vector for both accidental data loss and intentional insider theft.
Cable Locks and Physical Security
Kensington-style cable locks physically tether laptops to desks. Not foolproof (a determined thief can cut the cable) but they prevent opportunistic theft. In shared spaces, a cable lock buys time and deters casual theft of devices containing sensitive data.

Patch Management
Systematic process for identifying, testing, and deploying software updates. The most impactful single control in cybersecurity.
Why Patching Matters
The vast majority of exploited vulnerabilities have patches available at the time of exploitation. Equifax (2017): 143 million records stolen via an Apache Struts vulnerability patched two months earlier. The patch existed. It was not applied. Patching is not optional.
Patch Cycle
Critical: deploy within 24-72 hours. Important: within 2 weeks. All others: within 30 days. Test on a pilot group first when possible, but never delay critical patches for extended testing. The risk of exploitation outweighs the risk of a bad patch in almost all cases.
Beyond Windows Update
Patch everything, not just Windows. Third-party applications (browsers, PDF readers, Java, Flash legacy, 7-Zip) are major attack vectors. Use tools like WSUS, SCCM, PDQ Deploy, or Chocolatey to automate third-party patching. An unpatched Adobe Reader is as dangerous as an unpatched OS.

Application Whitelisting
Only approved applications are allowed to execute. Everything else is blocked by default -- the inverse of traditional antivirus.
How It Works
Application whitelisting (now called application control) creates a list of approved executables -- identified by file hash, publisher certificate, or file path. Any executable not on the list is blocked from running. This stops malware even if antivirus misses it, because the malware binary is not on the approved list.
Windows AppLocker
Built-in application control for Windows Enterprise/Education editions. Create rules that allow or deny executables, scripts, installers, packaged apps, and DLLs. Rules can be based on publisher (certificate), path, or file hash. Deploy via Group Policy for enterprise-wide enforcement.
Windows Defender Application Control
WDAC (formerly Device Guard) provides kernel-level application control. More secure than AppLocker because it cannot be bypassed by local administrators. WDAC uses code integrity policies that are enforced by the Windows kernel before the application loads into memory.
Operational Challenges
Whitelisting requires maintaining the approved application list. New software installations need IT approval and whitelist updates. Users will report "blocked" applications. The administrative overhead is real, but the security benefit is enormous -- it fundamentally changes the defender's advantage.

Browser Hardening
The web browser is the primary interface between users and the internet -- and the most common malware delivery channel.
Block Pop-ups and Redirects
Malicious pop-ups deliver fake virus warnings, tech support scams, and drive-by downloads. Enable the built-in pop-up blocker. Block automatic redirects. These settings prevent the most common low-sophistication web-based attacks.
Extension Management
Browser extensions run with elevated privileges and can read every page the user visits. Limit extensions to an approved list. Block installation of unapproved extensions via Group Policy. Even legitimate-looking extensions have been found to exfiltrate browsing data to third parties.
HTTPS Enforcement
Enable "Always use HTTPS" in browser settings. HSTS (HTTP Strict Transport Security) preload lists force HTTPS connections to known sites. Block mixed content (HTTP resources on HTTPS pages). These settings prevent man-in-the-middle attacks on unencrypted connections.
Enterprise Browser Management
Chrome and Edge support centralized management via Group Policy and Intune. Deploy browser settings across all workstations: homepage, allowed extensions, proxy settings, certificate requirements, download restrictions. Users should not be able to override security settings configured by IT.

USB Restrictions
USB ports are bidirectional attack vectors -- malware in, data out. Controlling USB device access is essential for both security and data loss prevention.
USB Attack Devices
Rubber Ducky: appears as a keyboard and types pre-programmed keystrokes at machine speed -- executing PowerShell commands, downloading payloads, or exfiltrating credentials in under 10 seconds. BadUSB: reprogrammed USB firmware that makes the device appear as a different device type. USB Killer: delivers an electrical charge that physically destroys the USB controller and motherboard.
Group Policy USB Controls
Computer Configuration > Administrative Templates > System > Removable Storage Access. Options: deny read, deny write, or deny all access for removable disks, CD/DVD, and floppy drives. Can also restrict to specific approved USB device IDs (vendor ID + product ID whitelisting).
Endpoint Detection
EDR solutions can monitor USB connections, log device insertions, and block unauthorized device types. Some solutions can detect when a USB device claims to be a keyboard (HID attack) when it was previously identified as a storage device -- a strong indicator of a Rubber Ducky attack.
Physical Port Blocking
Physical USB port blockers (plastic plugs that fit into USB ports and require a special tool to remove) prevent device insertion entirely. Used in environments with the highest security requirements: classified networks, payment processing systems, and air-gapped systems.

Physical Workstation Security
Software security is meaningless if an attacker can physically access the machine. Physical controls are the foundation layer.
Secure the Hardware
Cable locks for laptops in shared spaces. Locked cabinets or cages for desktops and servers. BIOS/UEFI passwords to prevent boot device changes. Disable boot from USB in BIOS to prevent live-CD attacks. Physical access to the motherboard allows a CMOS reset, so the cabinet matters.
Clean Desk Policy
At end of day: lock workstation, put sensitive documents in a locked drawer, clear whiteboards of sensitive diagrams, remove sticky notes with passwords or account numbers. Sensitive information left visible on a desk is available to any cleaning crew member, visitor, or after-hours intruder.
Visitor Management
All visitors sign in, receive a temporary badge, and are escorted. No unescorted access to workstation areas. Tailgating awareness training for all employees. A visitor with 5 unsupervised minutes near a workstation can install a hardware keylogger, insert a USB device, or photograph screens.
Surveillance
Security cameras in server rooms, network closets, and workstation areas provide both deterrence and forensic evidence. Camera footage with timestamps can prove who was present during a security incident. Cameras should record to a centralized, tamper-resistant system.

Hardening Checklist
A practical step-by-step checklist for hardening a new workstation before deployment.
Phase 1: OS Setup
Install from clean ISO (not OEM image). Run all Windows Updates until fully current. Enable BitLocker with TPM. Set BIOS/UEFI password. Disable boot from USB. Enable Secure Boot. Rename the default Administrator account.
Phase 2: Services and Features
Disable unnecessary services (Remote Registry, Telnet, SMBv1, Print Spooler if not printing). Remove Windows optional features not needed. Uninstall all bloatware and trial software. Verify Windows Defender is active with tamper protection.
Phase 3: Policies
Apply security baseline (CIS or DISA STIG). Configure password policy (14+ chars, complexity, history). Set account lockout (5 attempts, 30 min). Enable screensaver lock (5 min). Configure audit policies for logon, account management, and privilege use.
Phase 4: Network and Applications
Verify Windows Firewall enabled on all profiles. Configure host-based firewall rules. Install only approved applications. Harden browser settings. Restrict USB device access. Deploy EDR/endpoint protection. Join to domain for GPO enforcement.

Ongoing Maintenance
Hardening is not a one-time event. Security requires continuous monitoring, patching, and configuration validation.
Monthly Patching
Apply OS and third-party patches monthly at minimum. Critical patches within 72 hours. Track patch compliance across all workstations. A single unpatched machine on the network is a pivot point for an attacker who has breached any other system.
Vulnerability Scanning
Run periodic vulnerability scans (Nessus, Qualys, OpenVAS) to identify misconfigurations, missing patches, and newly discovered vulnerabilities. Scanning validates that hardening settings have not drifted from the baseline due to user changes, software installations, or policy conflicts.
Configuration Auditing
Compare current configurations against the security baseline quarterly. Tools like Microsoft Security Compliance Toolkit or CIS-CAT can automatically audit settings against benchmarks and generate compliance reports. Configuration drift is inevitable without automated monitoring.
Hardening Decay
Security configurations degrade over time. Users request exceptions. Software installations change settings. Updates reset configurations. Without ongoing validation, a hardened workstation slowly reverts to its default, vulnerable state. Automation and regular audits prevent this decay.
