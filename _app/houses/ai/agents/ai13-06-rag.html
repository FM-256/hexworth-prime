RAG Architectures

Retrieval-augmented generation: document indexing, chunking, retrieval methods, and generation pipelines.

Learning Objectives

  • Design a RAG pipeline from document ingestion through retrieval and generation
  • Compare chunking strategies: fixed-size, recursive, semantic, and document-aware
  • Implement hybrid retrieval combining dense embeddings with sparse BM25
  • Evaluate RAG quality with faithfulness, relevance, and answer correctness metrics

1. RAG Pipeline Overview

Retrieval-Augmented Generation (RAG) grounds LLM responses in external knowledge. Instead of relying solely on training data, RAG retrieves relevant documents and includes them in the prompt context. This reduces hallucination, enables domain-specific knowledge, and keeps information current.

RAG Pipeline Architecture
Indexing (offline) Documents --> [Loader] --> [Chunker] --> [Embedder] --> Vector Store Query (online) User Query --> [Embed] --> [Retrieve top-k] --> [Rerank] --> [Generate with context]

2. Chunking Strategies

Fixed-Size

Split every N characters with overlap. Simple but breaks mid-sentence.

Recursive Character

Split on paragraph, sentence, word boundaries. Respects text structure. LangChain default.

Semantic

Group sentences by embedding similarity. Topically coherent chunks.

Document-Aware

Use headers/sections as split points. Best for structured documents.

Key Takeaways

  • RAG grounds LLM responses in external knowledge, reducing hallucination and enabling domain expertise
  • Chunking strategy significantly impacts retrieval quality -- recursive splitting with overlap is a strong default
  • Hybrid retrieval (dense + sparse) outperforms either method alone for most use cases
  • The generation prompt must instruct the LLM to use only the retrieved context
  • RAGAS provides standardized metrics for evaluating each RAG pipeline component
