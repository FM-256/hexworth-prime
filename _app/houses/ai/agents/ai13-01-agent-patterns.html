Module 1 of 8 -- Agent Architecture

Agent Patterns Overview

A taxonomy of agentic reasoning: ReAct, Plan-and-Execute, MRKL, and when to use each pattern.

Learning Objectives

  • Distinguish between ReAct, Plan-and-Execute, and MRKL agent architectures
  • Map each pattern to its optimal use cases and failure modes
  • Trace the reasoning loop in a ReAct agent from observation to action
  • Evaluate trade-offs between single-step and multi-step agent designs

1. What Makes an Agent

An AI agent is a system that uses an LLM as its reasoning engine to decide which actions to take and in what order. Unlike a simple chatbot that produces text responses, an agent can observe its environment, reason about what to do, take actions (call tools, query APIs, execute code), and iterate until a goal is achieved.

Agent Loop -- Observe, Reason, Act
User Query --> [LLM Reasoning] --> Action Selection | | v v [Observation] [Tool Execution] | | +-------<-- result <----+ | Goal achieved? / \ Yes No --> loop back | Final Answer

2. ReAct: Reasoning + Acting

ReAct (Reasoning and Acting) interleaves chain-of-thought reasoning with tool use. At each step, the agent produces a Thought (reasoning about what to do), an Action (which tool to call), and an Observation (the tool's output). This cycle repeats until the agent can produce a final answer.

# ReAct agent with LangChain
from langchain.agents import create_react_agent, AgentExecutor
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="gpt-4o", temperature=0)
tools = [search_tool, calc_tool, wiki_tool]
agent = create_react_agent(llm, tools, react_prompt)
executor = AgentExecutor(agent=agent, tools=tools, verbose=True)

3. Plan-and-Execute

Plan-and-Execute separates planning from execution. A planner LLM creates a full step-by-step plan upfront, then an executor carries out each step. After each step, the plan can be revised. This pattern excels at complex, multi-step tasks where the full plan should be visible before execution begins.

Advantages

Full plan visible upfront. Easier to debug. Better for tasks requiring 5+ steps. Users can review before execution.

Disadvantages

Initial plan may be wrong. Replanning is expensive. Less reactive to unexpected outputs. Higher total token cost.

4. MRKL: Modular Reasoning, Knowledge, and Language

MRKL (pronounced "miracle") routes queries to specialized expert modules -- a calculator for math, a SQL engine for databases, a search engine for facts. The LLM acts as a router, selecting which expert to invoke.

PatternPlanningBest ForRisk
ReActStep-by-stepResearch, Q&A, explorationLoops, hallucinated actions
Plan-and-ExecuteUpfront planMulti-step, auditable workflowsStale plans, high token cost
MRKLRouter-basedTool-heavy, domain expertsMisrouting, module failures

5. Choosing the Right Pattern

The choice depends on task complexity, latency requirements, and error tolerance. Simple tool-calling tasks work well with ReAct. Complex research tasks benefit from Plan-and-Execute. Production systems with multiple specialized capabilities lean toward MRKL routing.

Production InsightMost production agent systems are hybrids. A MRKL router might dispatch to a ReAct sub-agent for research and a Plan-and-Execute sub-agent for complex operations.

Try It

  1. Implement a ReAct agent with 3 tools (search, calculator, date) using LangChain and trace the Thought/Action/Observation loop.
  2. Build a Plan-and-Execute agent that researches a cybersecurity topic. Log each step of the plan.
  3. Design a MRKL router that dispatches to 4 expert modules. Test with queries that should route to different experts.
  4. Run the same 5 queries through ReAct, Plan-and-Execute, and MRKL. Record accuracy, latency, and token cost.

Key Takeaways

  • ReAct interleaves reasoning and action -- good for exploratory tasks but can loop
  • Plan-and-Execute creates a full plan before executing -- better for auditable multi-step workflows
  • MRKL routes to specialized expert modules -- the foundation of most production agent systems
  • Production systems typically combine multiple patterns as sub-agents within a larger architecture
  • The right pattern depends on task complexity, latency budget, and error tolerance
