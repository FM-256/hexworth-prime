Tool Use and Function Calling

OpenAI function calling, tool schemas, structured outputs, and robust error handling for agent tools.

Learning Objectives

  • Define tool schemas using JSON Schema for OpenAI function calling
  • Implement parallel and sequential tool execution patterns
  • Handle tool errors gracefully with retries and fallbacks
  • Parse structured outputs with Pydantic models and response formats

1. Function Calling Fundamentals

Function calling lets an LLM generate structured JSON arguments for functions you define, rather than free-form text. The model does not execute the function -- your code does.

Function Calling Flow
User Query --> [LLM + tool schemas] --> tool_calls: call 1: get_weather(location="NYC") call 2: get_weather(location="London") --> [Your code executes] --> [Results to LLM] --> Final response

2. Defining Tool Schemas

tools = [{
    "type": "function",
    "function": {
        "name": "lookup_cve",
        "description": "Look up a CVE vulnerability by ID.",
        "parameters": {
            "type": "object",
            "properties": {
                "cve_id": {"type": "string", "description": "CVE identifier, e.g. CVE-2021-44228"}
            },
            "required": ["cve_id"]
        }
    }
}]

response = client.chat.completions.create(
    model="gpt-4o", messages=messages, tools=tools, tool_choice="auto"
)

3. Handling Tool Calls

def process_tool_calls(response, available_functions):
    messages = []
    for call in response.choices[0].message.tool_calls:
        fn_name = call.function.name
        fn_args = json.loads(call.function.arguments)
        try:
            result = available_functions[fn_name](**fn_args)
        except Exception as e:
            result = f"Error: {str(e)}"
        messages.append({"role": "tool", "tool_call_id": call.id, "content": str(result)})
    return messages

4. Structured Outputs with Pydantic

from pydantic import BaseModel
from typing import List, Literal

class VulnerabilityReport(BaseModel):
    cve_id: str
    severity: Literal["critical", "high", "medium", "low"]
    cvss_score: float
    affected_software: List[str]
    mitigation: str

response = client.beta.chat.completions.parse(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Analyze CVE-2021-44228"}],
    response_format=VulnerabilityReport,
)
report = response.choices[0].message.parsed
Parallel vs SequentialOpenAI models can return multiple tool_calls for independent operations (parallel). For dependent operations, the model returns them sequentially across turns. Design independent tool schemas for lower latency.

Key Takeaways

  • Function calling lets the LLM generate structured arguments -- your code executes the functions
  • Tool schemas use JSON Schema to define parameters, types, and descriptions
  • Parallel tool calls reduce latency when operations are independent
  • Structured outputs with Pydantic guarantee type-safe, validated responses from the LLM
  • Always handle tool errors gracefully -- the LLM can generate invalid arguments
