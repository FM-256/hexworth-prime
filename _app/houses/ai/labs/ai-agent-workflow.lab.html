Step 1 — Define the Trigger

Every agent workflow begins with a trigger — the event or condition that wakes the agent up and starts execution. Select a trigger type and configure its parameters.

Triggers are the entry point to any automation. A Webhook fires when an external system sends an HTTP request. A Schedule runs on a timer (cron). An Email received trigger listens to a mailbox. Choose based on the scenario — a SOC triage agent would likely use a Webhook from your SIEM.

Step 2 — Add the Brain (LLM)

The LLM is the reasoning core of your agent. Select a model and tune its behaviour with temperature, token limits, and a system prompt that defines its role and constraints.

Temperature controls randomness — low (0.0–0.3) for consistent, factual responses; high (0.7–1.0) for creative tasks. Max tokens limits output length. The system prompt is the most powerful tool you have — it sets persona, constraints, output format, and guardrail reminders. Be specific and explicit.

Step 3 — Connect Memory

Memory allows an agent to maintain context across multiple interactions. Without it, every invocation is stateless. Choose the memory strategy that fits your workflow's needs.

Conversation buffer keeps the full message history in the prompt — simple but token-expensive. Summary memory compresses history via LLM summarization. Vector store (RAG) stores knowledge in a database and retrieves relevant chunks at query time — ideal for large knowledge bases. Choose based on the scale of data the agent needs to recall.

Step 4 — Add Tools

Tools are external capabilities the agent can invoke. Click tools from the palette to add them to your workflow. Connect at least 2 tools. Think about what actions your agent actually needs to take.

Only add tools the agent genuinely needs — over-arming an agent increases attack surface and the blast radius if it behaves unexpectedly. A SOC triage agent needs: alert lookup, ticket creation, and possibly Slack posting. It does not need spreadsheet access or calendar booking.
Click any tool card below to add it to the workflow. Add 2–5 tools appropriate for your chosen trigger scenario.

Step 5 — Add Guardrails

Guardrails are safety controls placed between the agent's reasoning and its actions. They prevent runaway automation, protect sensitive data, and ensure humans stay in the loop for high-risk decisions. Add at least 2 guardrails.

A Rate Limiter prevents runaway loops or cost explosion. A Human Approval Gate is essential before any destructive or high-impact action (e.g. blocking an IP, sending a mass email). A PII Filter prevents sensitive data leaking into LLM prompts or external APIs. Output Validator ensures the LLM returns parseable, schema-compliant data.
