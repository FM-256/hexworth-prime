1. Bot Framework Architecture

Azure Bot Framework SDK (C# and Node.js) builds conversational AI. Core components: Bot (processes messages), Adapter (channel protocol), Dialog (conversation flow), State (persistence). Bots deploy as web apps and connect to channels through Azure Bot Service.

CLU (replaces LUIS)Intent classifiers and entity extractors for natural language understanding. Multi-lingual, transformer-based.
Custom Question AnsweringReplaces QnA Maker. FAQ knowledge bases from documents, URLs, manual entries. Semantic ranking.
Orchestration WorkflowRoutes user utterances to CLU, QA, or Azure OpenAI based on intent classification.
Channel IntegrationTeams, Web Chat, Slack, Facebook, Telephony. Single bot, multiple channels.

2. CLU Configuration

CLU is part of Azure AI Language (not standalone). Create a project, define intents and entities, provide training utterances, train, and deploy. Supports prebuilt entity types (datetime, number, email, URL) and learned entities from labeled data.

Exam Tip: LUIS vs CLU

The AI-102 exam uses CLU, not LUIS. CLU is part of Azure AI Language, uses transformer models, and has improved accuracy. Migration: export LUIS JSON, import into CLU project.

3. Dialog Management

Multi-turn conversations use waterfall dialogs (linear), adaptive dialogs (event-driven), or component dialogs (reusable). State persists in Azure Blob Storage or Cosmos DB for durability across bot restarts.

Try It

  1. Create a CLU project with 5 intents and 20 utterances per intent. Train and evaluate F1 scores.
  2. Build a Bot Framework bot using CLU for intent recognition and Custom QA for knowledge queries.
  3. Deploy the bot to Teams and Web Chat. Test conversation flows in both channels.
  4. Implement a multi-turn waterfall dialog collecting 3 pieces of information with validation.

Key Takeaways

  • CLU replaces LUIS and is part of Azure AI Language
  • Custom Question Answering replaces QnA Maker with improved semantic ranking
  • Bot Framework SDK handles dialog management, state, and multi-channel deployment
  • Orchestration workflow routes between CLU, QA, and OpenAI based on intent
