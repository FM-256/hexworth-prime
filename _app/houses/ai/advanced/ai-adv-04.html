1. The Prompting Hierarchy

Prompt engineering is the art of communicating intent to language models. Techniques range from simple instruction writing to sophisticated multi-step reasoning frameworks. The hierarchy follows a clear progression: zero-shot (no examples) to few-shot (examples) to chain-of-thought (reasoning steps) to agentic patterns (tool use, planning). Each level adds complexity but also adds reliability for harder tasks.

TechniqueWhen to UseTypical Accuracy GainCost Impact
Zero-ShotSimple, well-defined tasksBaselineLowest (fewest tokens)
Few-Shot (3-5 examples)Tasks with specific format or style+10-20% over zero-shot+200-500 tokens

2. Few-Shot Prompting

Few-Shot Classification Prompt
"""Classify the security event severity.

Event: Failed SSH login from 192.168.1.50, user root
Severity: LOW

Event: Multiple failed logins from 10 different IPs in 60 seconds
Severity: HIGH

Event: Successful login followed by privilege escalation to root
Severity: CRITICAL

Event: User changed their own password via self-service portal
Severity: INFO

Event: {new_event}
Severity:"""

Few-Shot Best Practices

Use 3-5 diverse examples covering edge cases. Order matters -- place the most representative example last (recency bias). Include examples of both positive and negative classes. Format examples identically to the expected output format. For classification, balance the number of examples per class.

3. Chain-of-Thought Reasoning

Chain-of-Thought (CoT) prompting asks the model to show its reasoning step-by-step before providing an answer. This simple technique dramatically improves performance on mathematical, logical, and multi-step reasoning tasks. The key insight: LLMs cannot reason in a single forward pass, but they can reason across multiple generated tokens.

Chain-of-Thought Example
# WITHOUT CoT
prompt = "A firewall processes 1000 packets/sec. If 3% are malicious and the IDS catches 95% of malicious packets, how many malicious packets slip through per hour?"
# Model might answer: "1.5" (wrong)

# WITH CoT
prompt = """A firewall processes 1000 packets/sec. If 3% are malicious and the IDS catches 95% of malicious packets, how many malicious packets slip through per hour?

Let me work through this step by step:
1. Packets per hour: 1000 * 3600 = 3,600,000
2. Malicious packets per hour: 3,600,000 * 0.03 = 108,000
3. IDS catches 95%, so 5% slip through
4. Packets that slip through: 108,000 * 0.05 = 5,400

Answer: 5,400 malicious packets slip through per hour."""

4. Self-Consistency

Self-consistency generates multiple CoT reasoning paths (typically 5-10) with temperature > 0, then takes a majority vote on the final answer. This leverages the observation that correct reasoning paths tend to converge on the same answer, while incorrect paths diverge. Cost is N times a single inference but provides significant reliability improvement.

Self-Consistency Implementation
from collections import Counter

def self_consistent_answer(client, prompt, n=5, temperature=0.7):
    """Generate multiple reasoning paths and take majority vote."""
    answers = []
    for _ in range(n):
        response = client.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": prompt + "\nThink step by step, then give your final answer on the last line as: ANSWER: [your answer]"}],
            temperature=temperature,
        )
        text = response.choices[0].message.content
        # Extract final answer
        for line in reversed(text.split('\n')):
            if line.strip().startswith('ANSWER:'):
                answers.append(line.split('ANSWER:')[1].strip())
                break

    # Majority vote
    vote = Counter(answers).most_common(1)
    return vote[0][0] if vote else "No consensus"

5. Structured Output

JSON Mode with Schema Enforcement
response = client.chat.completions.create(
    model="gpt-4o",
    response_format={"type": "json_object"},
    messages=[{
        "role": "system",
        "content": """Analyze the security alert and return JSON with this exact schema:
{
  "severity": "critical|high|medium|low|info",
  "attack_type": "string",
  "source_ip": "string or null",

  "confidence": 0.0 to 1.0
}"""
    }, {
        "role": "user",
        "content": "Alert: Multiple failed RDP connections from 45.33.32.156 targeting port 3389 on 12 internal hosts within 30 seconds."
    }]
)

  2. Implement self-consistency with n=5 for a logic puzzle. How often does the majority vote correct a wrong individual response?

Key Takeaways

  • Few-shot examples are the single most effective prompt engineering technique -- 3-5 examples cover most use cases
  • Chain-of-Thought prompting improves reasoning task accuracy by 15-40% by forcing explicit step-by-step thinking
  • Self-consistency (majority vote over multiple CoT paths) adds reliability at the cost of N times inference
  • Structured output (JSON mode, function calling) eliminates parsing errors in production pipelines
  • Prompt engineering is iterative -- test each change against a held-out evaluation set, not just spot-checking
