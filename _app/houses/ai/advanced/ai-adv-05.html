1. The Alignment Problem

Alignment is the challenge of making AI systems behave according to human intent, values, and instructions. A base language model (pretrained but not aligned) will complete any text pattern -- including harmful, biased, or misleading content. Alignment training modifies model behavior to be helpful, harmless, and honest. The three major approaches are RLHF (Reinforcement Learning from Human Feedback), DPO (Direct Preference Optimization), and Constitutional AI.

RLHF Train a reward model on human preferences, then use PPO (Proximal Policy Optimization) to maximize reward. Used by GPT-4, Claude, Gemini. Complex pipeline: SFT -> reward model -> PPO.
DPO (Direct Preference Optimization) Skip the reward model. Directly optimize the policy using preference pairs (chosen/rejected). Simpler than RLHF, no RL instabilities. Used by Llama-2-Chat, Zephyr.
Constitutional AI (CAI) Model critiques its own outputs against a set of principles ("constitution"), then revises. Reduces need for human labeling. Used by Claude. Self-improving safety loop.
RLAIF RL from AI Feedback. Use a stronger model as the reward signal instead of human annotators. Scales alignment training but inherits biases from the teacher model.

2. Red Teaming AI Systems

Red teaming systematically probes AI systems for failure modes, unsafe behaviors, and vulnerabilities. Unlike traditional software testing, AI red teaming must account for the vast input space of natural language and the stochastic nature of model outputs. Effective red teaming combines manual adversarial testing, automated fuzzing, and structured evaluation harnesses.

Red Team Responsibly

Red teaming should always be conducted with explicit authorization, documented protocols, and clear scope boundaries. Findings should be reported through responsible disclosure channels. Never red team production systems without permission. The goal is to improve safety, not to cause harm.

3. Production Safety Guardrails

Multi-Layer Safety Pipeline
# Layer 1: Input classification
def classify_input(text):
    """Screen user input for policy violations."""
    response = client.moderations.create(input=text)
    result = response.results[0]
    if result.flagged:
        categories = [c for c, v in result.categories.__dict__.items() if v]
        return {"safe": False, "categories": categories}
    return {"safe": True}

# Layer 2: System prompt guardrails
SYSTEM_PROMPT = """You are a cybersecurity assistant. Follow these rules strictly:
1. Never provide instructions for conducting actual attacks against systems you do not own
2. Always recommend legal and ethical approaches
3. If asked to do something harmful, explain why you cannot and suggest alternatives
4. Cite sources when making factual claims
5. Clearly distinguish between educational content and actionable advice"""

# Layer 3: Output validation
def validate_output(response_text):
    """Post-generation safety check."""
    # Check for PII leakage
    pii_patterns = [r'\b\d{3}-\d{2}-\d{4}\b', r'\b[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Z|a-z]{2,}\b']
    for pattern in pii_patterns:
        if re.search(pattern, response_text):
            return "[Response filtered: potential PII detected]"
    # Check output via moderation API
    mod = client.moderations.create(input=response_text)
    if mod.results[0].flagged:
        return "[Response filtered: content policy violation]"
    return response_text

4. The Alignment Tax

The alignment tax is the performance cost of making models safer. Aligned models sometimes refuse valid requests (false positives), give more cautious answers, or add unnecessary caveats. This tension between safety and utility is fundamental. The goal is not zero risk but an appropriate risk-utility tradeoff for each deployment context. A model assisting security researchers needs different guardrails than one serving customer support.

Graduated Autonomy Model

Start with maximum guardrails and relax them based on user role, task context, and deployment environment. Level 1 (public): strictest filters. Level 2 (authenticated users): moderate filters. Level 3 (domain experts): minimal filters with audit logging. Level 4 (admin): full access with comprehensive logging. Each level requires explicit authorization and monitoring.

Try It

  1. Use the OpenAI Moderation API to classify 20 text samples across the categories (violence, self-harm, sexual, hate). Record the category scores and thresholds.
  2. Design a 10-question red team evaluation set for a cybersecurity chatbot. Include prompt injection, jailbreak, and bias probes. Run against an LLM and document results.
  3. Implement the three-layer safety pipeline (input classification, system prompt, output validation). Test with both benign and adversarial inputs.
  4. Compare the same 10 prompts against a base model (no alignment) vs an aligned model. Categorize differences as: improved safety, unnecessary refusal, or no change.

Key Takeaways

  • RLHF remains the gold standard for alignment but DPO is simpler and increasingly competitive
  • Constitutional AI enables scalable alignment by having models self-critique against explicit principles
  • Red teaming must be systematic: cover prompt injection, jailbreaking, bias, hallucination, and data extraction
  • Production safety requires multiple layers: input filtering, system prompts, and output validation
  • The alignment tax is real -- design graduated autonomy systems that match safety level to deployment context
  • Safety is not a one-time implementation but an ongoing process of evaluation and refinement
