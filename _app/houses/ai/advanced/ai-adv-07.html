1. The Inference Cost Problem

Running large language models in production is expensive. A 70B parameter model requires ~140GB of GPU memory in FP16, multiple high-end GPUs, and generates tokens at 20-50 tokens/second per user. At scale, inference cost dominates total cost of ownership. Optimization techniques reduce memory, improve throughput, and lower latency -- often with minimal quality loss.

2. Quantization

Quantization reduces the precision of model weights from 16-bit floats to 8-bit or 4-bit integers. This directly reduces memory by 2-4x and speeds up computation on hardware with integer math units. Modern quantization methods (GPTQ, AWQ, GGUF) are calibrated on representative data to minimize quality loss.

INT4 Quantization with GPTQ
from transformers import AutoModelForCausalLM, AutoTokenizer, GPTQConfig

# Load a GPTQ-quantized model (pre-quantized from HuggingFace Hub)
model_name = "TheBloke/Llama-2-7B-GPTQ"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    device_map="auto",
    torch_dtype="auto",
)

# Model is now ~3.5GB instead of ~14GB (FP16)
# Runs on a single 8GB consumer GPU
print(f"Model size: {sum(p.numel() * p.element_size() for p in model.parameters()) / 1e9:.1f} GB")

# Quantize your own model
quantization_config = GPTQConfig(
    bits=4,
    dataset="c4",            # calibration dataset
    tokenizer=tokenizer,
    group_size=128,           # quantization group size
)
model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-2-7b-hf",
    quantization_config=quantization_config,
    device_map="auto",
)

3. Knowledge Distillation

Knowledge distillation trains a smaller "student" model to mimic the outputs of a larger "teacher" model. The student learns from the teacher's soft probability distributions (which contain more information than hard labels). This produces a model that is 5-50x smaller but retains 85-95% of the teacher's quality on the target task.

Response-Based Distillation Student matches teacher's output logits using KL divergence loss. Simplest form. Works well when student architecture is similar to teacher.
Feature-Based Distillation Student matches teacher's intermediate layer representations. Captures internal knowledge structure. Requires architecture mapping between layers.
Data Augmentation Distillation Generate large synthetic datasets using the teacher. Train student on synthetic data. Used by Alpaca, Vicuna, and many open-source chat models.
Task-Specific Distillation Distill for one specific task (e.g., classification, summarization). Student can be a simple classifier, not even an LLM. Maximum compression.

4. Speculative Decoding

Speculative decoding uses a small, fast "draft" model to generate candidate tokens, then the large "target" model verifies them in a single forward pass. Since the target model can verify multiple tokens in parallel (same cost as generating one), this provides 2-3x speedup with zero quality loss -- the output distribution is mathematically identical to the target model alone.

Production Serving with vLLM

vLLM is the standard inference server for production LLM deployments. Key features: PagedAttention (efficient KV-cache memory management), continuous batching (no wasted GPU cycles between requests), tensor parallelism (split model across GPUs), and speculative decoding. Typical throughput improvement over naive serving: 5-20x.

5. KV-Cache and Batching

The key-value cache stores computed attention states so they do not need to be recomputed for each new token. For long sequences, the KV-cache can consume more memory than the model weights themselves. PagedAttention (used by vLLM) manages KV-cache like virtual memory pages, eliminating fragmentation and enabling dynamic allocation. Continuous batching interleaves requests at the token level, keeping GPUs saturated even with varying sequence lengths.

Key Takeaways

  • INT4 quantization (GPTQ/AWQ) reduces model size by 4x with only 1-3% quality loss -- the single highest-impact optimization
  • Knowledge distillation can compress models 10-50x for task-specific deployments
  • Speculative decoding provides 2-3x speedup with zero quality loss (mathematically lossless)
  • vLLM with PagedAttention and continuous batching is 5-20x faster than naive HuggingFace inference
  • KV-cache memory often exceeds model weight memory for long sequences -- optimization here is critical at scale
  • Stack optimizations: quantize + batch + cache + speculate for maximum production throughput
