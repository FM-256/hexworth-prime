1. Vector Database Landscape

Vector databases are purpose-built storage engines that index high-dimensional vectors for fast approximate nearest neighbor (ANN) search. Unlike traditional databases that use B-trees for exact match, vector databases use algorithms like HNSW (Hierarchical Navigable Small World graphs) and IVF (Inverted File Index) to trade a small amount of recall for orders-of-magnitude speedup.

2. CRUD Operations with Chroma

Chroma -- Local Vector Database
import chromadb
from chromadb.utils import embedding_functions

# Initialize persistent client (data survives restart)
client = chromadb.PersistentClient(path="./chroma_db")

# Use sentence-transformers for auto-embedding
ef = embedding_functions.SentenceTransformerEmbeddingFunction(model_name="all-MiniLM-L6-v2")

# CREATE collection
collection = client.get_or_create_collection(name="threat_intel", embedding_function=ef)

# INSERT documents with metadata
collection.add(
    documents=[
        "APT29 uses spear-phishing with OAuth token theft",
        "Ransomware group Lockbit deploys double extortion",
        "CVE-2024-3094 xz-utils backdoor in SSH authentication",
    ],
    metadatas=[
        {"source": "mandiant", "severity": "high", "year": 2024},
        {"source": "cisa", "severity": "critical", "year": 2024},
        {"source": "nvd", "severity": "critical", "year": 2024},
    ],
    ids=["doc-001", "doc-002", "doc-003"]
)

# QUERY -- semantic search with metadata filter
results = collection.query(
    query_texts=["supply chain attack techniques"],
    n_results=2,
    where={"severity": "critical"}   # metadata filter
)
print(results["documents"])  # returns xz-utils and lockbit docs

# UPDATE document metadata
collection.update(ids=["doc-001"], metadatas=[{"source": "mandiant", "severity": "critical", "year": 2024}])

# DELETE
collection.delete(ids=["doc-001"])

3. Indexing Strategies

Flat (Brute Force) Exact nearest neighbor. Perfect recall. O(n) per query. Only viable below 100K vectors. Use for ground-truth benchmarks.
HNSW Graph-based ANN. 95-99% recall. O(log n) per query. Best for real-time serving. Higher memory (stores graph edges).
IVF (Inverted File) Clusters vectors into partitions. 90-95% recall. Lower memory than HNSW. Needs training step. Good for large static datasets.
Product Quantization (PQ) Compresses vectors to 8-32 bytes. 85-90% recall. Massive memory savings. Combine with IVF for billion-scale search.

Choosing an Index

Under 10K vectors: use flat index. 10K-1M vectors: use HNSW (ef_construction=128, M=16 is a good starting point). 1M-100M vectors: use IVF with HNSW refinement. 100M+: use IVF-PQ with disk-based storage. Always benchmark on your actual query distribution before choosing.

4. Hybrid Search

Pure vector search excels at semantic matching but can miss exact keyword matches (e.g., specific CVE IDs, IP addresses). Hybrid search combines dense vector similarity with sparse BM25 keyword matching, typically using Reciprocal Rank Fusion (RRF) to merge results. Weaviate and Qdrant support hybrid search natively.

Hybrid Search with Weaviate
import weaviate

client = weaviate.connect_to_local()  # or weaviate.connect_to_wcs()

# Hybrid search: combines BM25 + vector similarity
response = client.collections.get("ThreatIntel").query.hybrid(
    query="CVE-2024-3094 supply chain compromise",
    alpha=0.7,    # 0.0 = pure BM25, 1.0 = pure vector, 0.7 = blend
    limit=5,
    return_metadata=weaviate.classes.query.MetadataQuery(score=True)
)

for obj in response.objects:
    print(f"Score: {obj.metadata.score:.3f} | {obj.properties['title']}")

Key Takeaways

  • Vector databases enable sub-millisecond similarity search over millions of embeddings using ANN algorithms
  • HNSW provides the best recall/latency tradeoff for most production workloads under 10M vectors
  • Metadata filtering lets you scope vector search to specific categories, time ranges, or security domains
  • Hybrid search (dense + sparse) catches both semantic matches and exact keyword matches
  • Chroma is ideal for prototyping; Pinecone/Weaviate/Qdrant for production; pgvector for existing Postgres stacks
