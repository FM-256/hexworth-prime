1. When to Fine-Tune

Fine-tuning adapts a pretrained model to a specific domain or task by continuing training on your data. But it is not always the right call. Before fine-tuning, evaluate three cheaper alternatives: prompt engineering (zero cost, instant), few-shot examples (minimal cost, fast), and RAG (moderate cost, handles knowledge updates). Fine-tuning makes sense when you need consistent style, domain-specific behavior that cannot be captured in a prompt, or latency/cost reduction by using a smaller tuned model instead of a larger general one.

Prompt Engineering Zero additional cost. Adjust system prompts, examples, and constraints. Try this first -- often sufficient for 80% of use cases.
Retrieval-Augmented Generation Inject relevant context at inference time. Best for knowledge-heavy tasks where the data changes frequently.
LoRA / QLoRA Fine-Tuning Train a small set of adapter weights. Low cost, preserves base model. Best for style, format, and domain adaptation.
Full Fine-Tuning Update all model weights. Highest cost, highest flexibility. Only justified for large-scale domain shifts or custom architectures.

3. LoRA: Low-Rank Adaptation

LoRA freezes the pretrained model weights and injects trainable low-rank decomposition matrices into each Transformer layer. Instead of updating a weight matrix W directly, LoRA decomposes the update into two smaller matrices: W + delta_W where delta_W = A * B. Matrix A has shape (d, r) and B has shape (r, d), where r (the rank) is typically 4-64, dramatically reducing trainable parameters.

Key LoRA Hyperparameters

rank (r): Dimensionality of the low-rank matrices. Higher = more capacity but more parameters. Start with r=8 or r=16.
alpha: Scaling factor applied to the LoRA output. Common practice: set alpha = 2*rank. Controls how much the adapter influences the output.
target_modules: Which layers to apply LoRA to. For LLMs: typically q_proj, v_proj (attention), sometimes k_proj, o_proj, and MLP layers for stronger adaptation.

LoRA Fine-Tuning with PEFT
from peft import LoraConfig, get_peft_model, TaskType
from transformers import AutoModelForCausalLM, AutoTokenizer, TrainingArguments, Trainer

# Load base model
model_name = "meta-llama/Llama-2-7b-hf"
model = AutoModelForCausalLM.from_pretrained(model_name, torch_dtype="float16")
tokenizer = AutoTokenizer.from_pretrained(model_name)

# Configure LoRA
lora_config = LoraConfig(
    task_type=TaskType.CAUSAL_LM,
    r=16,                        # rank
    lora_alpha=32,                 # scaling factor (2x rank)
    lora_dropout=0.05,             # regularization
    target_modules=["q_proj", "v_proj", "k_proj", "o_proj"],
    bias="none",
)

# Wrap model with LoRA adapters
model = get_peft_model(model, lora_config)
model.print_trainable_parameters()
# trainable params: 4,194,304 || all params: 6,742,609,920 || trainable%: 0.0622

# Training arguments
training_args = TrainingArguments(
    output_dir="./lora-output",
    num_train_epochs=3,
    per_device_train_batch_size=4,
    gradient_accumulation_steps=4,
    learning_rate=2e-4,
    warmup_ratio=0.03,
    logging_steps=10,
    save_strategy="epoch",
    fp16=True,
)

trainer = Trainer(model=model, args=training_args, train_dataset=train_dataset)
trainer.train()

4. QLoRA: Quantized LoRA

QLoRA takes LoRA further by quantizing the base model to 4-bit precision using NF4 (NormalFloat4) quantization, then applying LoRA adapters on top. This allows fine-tuning a 65B parameter model on a single 48GB GPU. The key innovation: 4-bit NF4 quantization is information-theoretically optimal for normally distributed weights, combined with double quantization to reduce memory for quantization constants.

QLoRA Setup with BitsAndBytes
from transformers import BitsAndBytesConfig
import torch

# 4-bit quantization config
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",           # NormalFloat4
    bnb_4bit_compute_dtype=torch.float16,  # compute in FP16
    bnb_4bit_use_double_quant=True,       # double quantization
)

# Load model in 4-bit
model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-2-7b-hf",
    quantization_config=bnb_config,
    device_map="auto",
)

# Apply LoRA on top of quantized model
model = get_peft_model(model, lora_config)
# Now fine-tunable on a single consumer GPU (8-12 GB VRAM)

Catastrophic Forgetting

Full fine-tuning can cause the model to lose general capabilities as it overfits to domain data. LoRA mitigates this by keeping the base model frozen. To further prevent forgetting: (1) mix in general-purpose data during training, (2) use a low learning rate, (3) train for fewer epochs, (4) evaluate on both domain and general benchmarks.

5. Data Preparation for Fine-Tuning

Data quality matters far more than quantity for fine-tuning. A curated dataset of 1,000-5,000 high-quality examples typically outperforms 50,000 noisy examples. Format data in the instruction-response pattern your model expects.

Data Formatting
# Alpaca-style instruction format
training_examples = [
    {
        "instruction": "Classify this CVE as critical, high, medium, or low severity.",
        "input": "CVE-2024-3094: Backdoor in xz-utils 5.6.0/5.6.1 allowing remote code execution via SSH.",
        "output": "Critical. This is a supply chain backdoor affecting a widely-used compression library, enabling unauthenticated RCE through sshd. CVSS 10.0."
    },
    {
        "instruction": "Summarize this threat intel report in 2 sentences.",
        "input": "[Full report text...]",
        "output": "[Concise summary...]"
    }
]

# Convert to prompt format
def format_prompt(example):
    prompt = f"### Instruction:\n{example['instruction']}\n\n"
    if example.get('input'):
        prompt += f"### Input:\n{example['input']}\n\n"
    prompt += f"### Response:\n{example['output']}"
    return prompt

Key Takeaways

  • Always try prompt engineering and RAG before fine-tuning -- they are cheaper and faster to iterate
  • LoRA trains 0.1% of parameters while achieving 95-99% of full fine-tuning quality
  • QLoRA enables fine-tuning 7B+ models on consumer GPUs via 4-bit NF4 quantization
  • Data quality dominates data quantity -- 1K curated examples often outperform 50K noisy ones
  • LoRA adapters can be swapped at inference time, enabling multi-task deployment from a single base model
  • Monitor for catastrophic forgetting by evaluating on both domain-specific and general benchmarks
