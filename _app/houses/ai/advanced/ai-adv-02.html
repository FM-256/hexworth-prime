1. What Are Embeddings?

An embedding is a dense numerical vector that captures the semantic meaning of a piece of content. Unlike sparse representations (bag-of-words, TF-IDF), embeddings place semantically similar items close together in vector space. "King" and "Queen" will have nearby vectors, while "King" and "Bicycle" will be far apart. Modern embedding models produce vectors of 384 to 3072 dimensions, trained on billions of text pairs to capture nuanced semantic relationships.

Text Embeddings Map words, sentences, or documents to vectors. Used for semantic search, clustering, classification, and RAG retrieval.
Image Embeddings Map images to vectors via CNN or Vision Transformer encoders. Enable reverse image search, deduplication, and visual similarity.
Multi-Modal Embeddings Map text and images to the same vector space (CLIP, ALIGN). Enable text-to-image search and cross-modal retrieval.
Code Embeddings Map source code to vectors that capture function semantics. Enable semantic code search and duplicate detection.

3. Generating Embeddings

OpenAI Embeddings API
from openai import OpenAI

client = OpenAI()

# Single text embedding
response = client.embeddings.create(
    model="text-embedding-3-small",
    input="What are the MITRE ATT&CK tactics for lateral movement?"
)
vector = response.data[0].embedding  # list of 1536 floats
print(f"Dimensions: {len(vector)}")   # 1536

# Batch embedding (more efficient)
texts = [
    "phishing email detection",
    "lateral movement via RDP",
    "SQL injection prevention",
]
response = client.embeddings.create(model="text-embedding-3-small", input=texts)
vectors = [d.embedding for d in response.data]
Local Embeddings with Sentence-Transformers
from sentence_transformers import SentenceTransformer
import numpy as np

# Load model (downloads on first run, ~80MB)
model = SentenceTransformer('all-MiniLM-L6-v2')

# Encode texts
sentences = ["ransomware attack vector", "malware encryption payload", "chocolate cake recipe"]
embeddings = model.encode(sentences, normalize_embeddings=True)

# Cosine similarity (vectors are normalized, so dot product = cosine sim)
sim_01 = np.dot(embeddings[0], embeddings[1])  # ~0.68 (related)
sim_02 = np.dot(embeddings[0], embeddings[2])  # ~0.05 (unrelated)
print(f"ransomware vs malware:  {sim_01:.3f}")
print(f"ransomware vs cake:    {sim_02:.3f}")

4. Similarity Metrics

Cosine Similarity Measures angle between vectors. Range [-1, 1]. Invariant to vector magnitude. Default for text search. cos(A,B) = (A . B) / (||A|| * ||B||)
Dot Product Equivalent to cosine sim when vectors are L2-normalized. Faster to compute. Used by FAISS and most vector DBs internally.
Euclidean Distance Straight-line distance in vector space. Lower = more similar. Sensitive to magnitude. Use for absolute positioning tasks.
Manhattan Distance Sum of absolute differences per dimension. More robust to outlier dimensions. Used in some specialized retrieval systems.

Dimensionality Reduction

OpenAI's text-embedding-3 models support native dimensionality reduction via the "dimensions" parameter. You can request 256, 512, or 1024 dimensions instead of the full 3072, trading quality for storage and speed. The model truncates and renormalizes. At 256 dimensions, you retain ~95% of retrieval quality at 1/12 the storage cost.

5. Multi-Modal Embeddings with CLIP

CLIP Text-to-Image Search
from transformers import CLIPProcessor, CLIPModel
from PIL import Image
import torch

model = CLIPModel.from_pretrained("openai/clip-vit-large-patch14")
processor = CLIPProcessor.from_pretrained("openai/clip-vit-large-patch14")

# Encode text query
text_inputs = processor(text=["a network diagram showing firewall rules"], return_tensors="pt")
text_embedding = model.get_text_features(**text_inputs)  # shape: (1, 768)

# Encode image
image = Image.open("network_diagram.png")
image_inputs = processor(images=image, return_tensors="pt")
image_embedding = model.get_image_features(**image_inputs)  # shape: (1, 768)

# Compare: text and image live in the same 768-dim space
similarity = torch.cosine_similarity(text_embedding, image_embedding)
print(f"Text-Image similarity: {similarity.item():.3f}")

Key Takeaways

  • Embeddings transform text/images into dense vectors where semantic similarity maps to geometric proximity
  • Open-source models (sentence-transformers, BGE) match or beat commercial APIs for many tasks
  • Cosine similarity is the standard metric for text search -- use normalized vectors for fast dot product computation
  • Multi-modal models (CLIP) unify text and image into the same vector space, enabling cross-modal retrieval
  • Dimensionality reduction (256-512 dims) preserves 90-95% of retrieval quality at a fraction of the storage cost
  • Batch embedding is 5-10x more efficient than embedding texts one at a time
