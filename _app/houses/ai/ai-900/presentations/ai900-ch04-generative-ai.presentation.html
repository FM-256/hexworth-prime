What is Generative AI?
AI that creates NEW content — not just analyzing patterns, but producing original outputs from a learned distribution.
Discriminative vs. Generative
Traditional AI is discriminative — it classifies existing inputs ("Is this email spam?"). Generative AI creates new outputs ("Write me a phishing awareness email"). The shift from analysis to creation is what defines this category.
How It Actually Works
Under the hood, the model predicts the most likely next token given all previous tokens. It does this thousands of times in sequence. Each token is a word piece — about 4 characters on average. A 200-word response involves roughly 300 token predictions.
What It Can Generate
Text (GPT-4), images (DALL-E 3), audio (Whisper / TTS), code (GitHub Copilot), video, embeddings, and multimodal combinations. Each modality uses a different architecture, but all share the generative prediction principle.
Crawl: "It predicts the most likely next token, thousands of times." Walk: The model doesn't retrieve facts from a database — it generates probable continuations of your prompt based on statistical patterns learned during training.

Large Language Models (LLMs)
Trained on massive text datasets, LLMs learn statistical relationships between words — turning patterns into powerful language capabilities.
What Makes Them "Large"
Modern LLMs like GPT-4 have hundreds of billions to potentially over a trillion parameters — numerical weights adjusted during training. Each parameter stores a tiny fragment of learned knowledge. More parameters generally means more capacity to capture nuance, but also more compute and cost to run. Microsoft Azure provides the infrastructure to deploy these models at enterprise scale.
What They Actually Learn
LLMs do not store facts like a database. They learn statistical co-occurrence patterns — which words tend to follow which other words in which contexts. The result looks like reasoning, but is fundamentally pattern matching over an enormous learned distribution of language.
Key Concepts You Must Know
Tokens — the atomic units of text. Embeddings — numeric vectors that position tokens in meaning-space. Transformer — the neural architecture that processes tokens with self-attention. All three are on the AI-900 exam.

Tokenization
Before any processing, text is broken into tokens — the atomic units an LLM understands. Every token maps to a unique integer ID.
Why Tokenize?
Computers cannot process raw characters efficiently at scale. Tokenization compresses text into a fixed vocabulary (GPT-4 uses ~100,000 tokens). Common words like "the" get single IDs. Rare words like "hexadecimal" get split into sub-word tokens: "hex", "ade", "cimal". This balance between coverage and compression is carefully tuned.
Subword Tokenization
Most LLMs use Byte Pair Encoding (BPE). Start with characters, then repeatedly merge the most common adjacent pair. "unhappiness" might become ["un", "happiness"] or ["un", "happy", "ness"] depending on training data frequency. This handles unknown words gracefully without a huge vocabulary.
Tokens and Cost
Azure OpenAI pricing is per-token — both input (prompt) and output (completion). GPT-4 charges separately for prompt tokens and completion tokens. A rule of thumb: 1 token is roughly 4 characters or 0.75 English words. A 1000-word document is approximately 1,300 tokens. This matters for production cost planning.
Walk: "unbelievable" tokenizes as ["un", "believe", "able"] — 3 tokens, not 12 characters. The tokenizer has seen "believe" and "able" frequently enough to keep them whole, but "un" is a productive prefix worth separating.

The Transformer Architecture
The neural architecture behind every major LLM. An Encoder builds contextual embeddings; a Decoder predicts the next token using attention.
Self-Attention — Plain English
Attention is the mechanism that lets every token "look at" every other token and decide how much to weight each one. In "the dog barked at the mail carrier," when processing "barked," attention gives high weight to "dog" (the subject) and lower weight to "at." This is how the model understands context across long distances.
Why This Architecture Won
Before Transformers (2017), RNNs processed text sequentially — token by token — which created a bottleneck for long documents. Transformers process all tokens in parallel using attention matrices. This massive parallelism made training on trillion-token datasets feasible with modern GPU/TPU hardware.
GPT = Decoder-Only
GPT models (the G in Azure OpenAI's GPT-4) use only the decoder stack. BERT uses only the encoder. T5 uses both. For the AI-900 exam: encoder-only = good at understanding/classification. Decoder-only = good at generation. Encoder-decoder = good at translation and summarization.

Prompts and Completions
Users send a prompt — the model returns a completion. How you construct the prompt determines the quality of the output.
Zero-Shot Prompting
You give no examples — just the instruction. Classify this tweet as positive or negative: "I love this product!" The model uses knowledge from pretraining to figure out the task. Works well for common tasks. Fails on niche or specialized formats the model has not seen. This is the simplest prompting strategy.
Few-Shot Prompting
You provide 2-5 input/output examples before your actual query. This "shows" the model the exact format and behavior you expect. Why it works: the model performs in-context learning — it recognizes the pattern in the examples and applies it. Much more reliable than zero-shot for custom output formats or specialized tasks.
System Message
In the Chat Completions API, a system message is a special role that sets persistent context before the user's turn. "You are a cybersecurity tutor. Answer at a beginner level. Always explain acronyms." The system message shapes every response in the conversation without being visible to the end user.
Run: Few-shot works because LLMs have massive in-context learning ability — they can adapt to a new "task" from just 2-3 examples, without any gradient updates or retraining. It is effectively real-time specialization through the prompt itself.

Azure OpenAI Service
Enterprise access to industry-leading OpenAI models — with Microsoft's security, compliance, responsible AI controls, and private networking.
Enterprise Security Differentiators
Your data never trains OpenAI's public models. Deployments live in your Azure subscription with Virtual Network support, private endpoints, and customer-managed encryption keys. RBAC via Microsoft Entra ID controls who can call which model. SOC 2, ISO 27001, FedRAMP High compliant — suitable for government and healthcare workloads.
Content Filtering System
Azure OpenAI wraps every model call with a four-category content filter (hate, sexual, violence, self-harm), each configurable at threshold levels: low, medium, high, or none. Both prompt and completion are filtered independently. You can customize filtering severity per category and receive detailed filter reason codes in the API response.
Getting Started
Request access in Azure Portal, create an Azure OpenAI resource in a supported region, deploy a model in Azure AI Foundry, then call the REST API or use the Python/C#/.NET SDK. Azure AI Foundry provides a Playground for interactive testing before you write a single line of code.

Copilots and AI Agents
Copilots assist users through conversation. Agents act autonomously — planning, executing, and using tools to complete multi-step goals.
Copilots — Designed for Collaboration
A copilot is embedded in an existing workflow and surfaces at decision points to assist the user. Microsoft 365 Copilot drafts emails, summarizes meetings, and generates presentations. GitHub Copilot suggests code completions. The human always approves or rejects suggestions. The loop is: user asks, AI responds, user decides. Human remains in the loop.
Agents — Designed for Autonomy
An agent is given a goal and a toolset, then plans and executes multi-step tasks without step-by-step human guidance. "Research the top 5 Azure cost-saving strategies, write a report, and email it to the finance team." The agent decides when to search, what to read, how to synthesize, and when to send — running a complete plan without user prompting at each step.
The Progression
Autocomplete (GitHub Copilot basic) → Chat interface (GPT-4 in Azure AI Foundry) → Copilot (M365, integrated) → Agent (autonomous multi-step). The AI-900 exam tests whether you understand this hierarchy and can map Microsoft products to each level. Copilots assist; agents act.

Prompt Engineering Best Practices
The quality of your prompt determines the quality of the output. Bad prompts yield vague responses. Precise prompts yield precise results.
Be Specific and Structured
State the task explicitly. Include the output format ("respond as a JSON array"), the length ("in 3 sentences"), the audience ("for a 10-year-old"), and the constraints ("do not include code"). Every detail you remove is a decision the model makes for you — and it may not choose what you want. Specificity is the single highest-leverage prompt engineering skill.
Provide Context and Examples
Context closes the ambiguity gap. "Summarize this for my IT security team who are non-technical" produces a very different output than "Summarize this." Examples (few-shot) are even more powerful — show the model exactly what a correct output looks like and it will reproduce the pattern reliably. One well-chosen example is worth 10 sentences of description.
Iterate and Constrain
Prompt engineering is not a one-shot exercise. Start broad, evaluate the output, then tighten the constraints. Add "Do not mention X." Add "Always include a recommendation." Add "Use bullet points, not paragraphs." Each iteration narrows the output distribution toward your target. Log your prompt versions — what works for GPT-4 may not work identically on GPT-4o.

Responsible Generative AI
Generative AI introduces unique risks. Microsoft's responsible AI framework addresses them through technical controls, process, and human oversight.
Key Risks to Understand
Hallucination — models confidently generate false facts. Mitigate with grounding (RAG). Bias — training data reflects historical inequities; outputs may perpetuate them. Harmful content — models can generate dangerous instructions if not filtered. Copyright — generated text may reproduce copyrighted training data. All four appear on the AI-900 exam.
Mitigation Strategies
Grounding — provide factual context in the prompt (RAG pattern) so the model answers from your data, not its weights. Human oversight — keep humans in the review loop for high-stakes outputs. Transparency — disclose when content is AI-generated. Red-teaming — deliberately probe the system for failure modes before production deployment.
Microsoft's Six Responsible AI Principles
Microsoft's six Responsible AI principles apply directly to generative AI: Fairness (avoid biased outputs), Reliability and Safety (handle errors gracefully, don't hallucinate), Privacy and Security (protect training data and user inputs), Inclusiveness (accessible to all users), Transparency (disclose AI use and limitations), Accountability (humans responsible for AI decisions). These six principles are what the AI-900 exam tests.

Azure OpenAI in Practice
From zero to first completion: create a resource, deploy a model, configure settings, send your prompt, receive your answer.
Access Methods
Azure AI Foundry (Playground) — browser-based interface for testing prompts, comparing models, and exporting code snippets. No SDK required. REST API — direct HTTP calls, usable from any language. Python SDK — openai library with AzureOpenAI client. .NET / C# SDK — for enterprise integrations. All methods use the same endpoint and API key pattern.
Key API Parameters
temperature (0.0–2.0) — controls randomness. Low = deterministic, high = creative. max_tokens — caps the completion length. top_p — nucleus sampling alternative to temperature. frequency_penalty — discourages repetition. stop — sequence that halts generation. For the exam: temperature is the most important parameter to understand conceptually.
Deployment Names vs Model Names
In Azure OpenAI, you do not call models by their OpenAI name directly. You create a deployment with a custom name (e.g., my-gpt4-deployment) that points to a base model. Your API calls use the deployment name, not gpt-4. This indirection allows you to swap the underlying model version without changing application code — a critical operational pattern.
Run: A minimal Python call — client = AzureOpenAI(azure_endpoint=..., api_key=..., api_version="2024-02-01") then client.chat.completions.create(model="my-gpt4-deployment", messages=[...]). That is the entire integration surface for most applications.
