Predictive Models with Azure ML
AutoML  •  Designer  •  Regression  •  Classification  •  Clustering  •  Deployment
Predictive ML learns statistical patterns from historical data and applies them to new inputs — answering questions like "What will this house sell for?", "Is this transaction fraudulent?", and "Which customers behave similarly?" Azure Machine Learning provides the full toolkit to train, evaluate, and deploy these models at scale.

Azure Machine Learning Workspace
The workspace is the central container for every ML artifact — your datasets, experiments, trained models, and deployed endpoints all live here.
What a Workspace Actually Is
Think of the workspace as a project folder in the cloud, but with governance. It connects your compute resources, data sources, and code into a single tracked environment. Every training run is logged. Every model version is recorded. You never lose track of what produced what result.
Three Ways to Work Inside It
Azure ML Studio (studio.ml.azure.com) — browser-based GUI with Designer and AutoML. Python SDK v2 — programmatic access for data scientists. Azure CLI extension — for DevOps automation and CI/CD pipelines. All three operate on the same underlying workspace resources.
Linked Resources
When you create a workspace, Azure automatically provisions: a Storage Account (for data and model artifacts), a Key Vault (for secrets), a Container Registry (for Docker images), and an Application Insights instance (for telemetry). These are linked but billed separately from the workspace itself.
Crawl: "A workspace is the top-level Azure resource that organizes everything in your ML project." Walk: Every dataset you register, every training job you run, every model you produce, and every endpoint you deploy — all tracked, versioned, and auditable from one place.

Automated ML (AutoML)
You supply the data and name the target column. AutoML runs dozens of algorithm + preprocessing combinations in parallel, then hands you the best model.
What You Configure
You specify: (1) the dataset, (2) the task type — regression, classification, or time-series forecasting, (3) the target column, (4) the primary metric (e.g., R-squared for regression, AUC for classification), and (5) training time budget. AutoML handles everything else — featurization, algorithm selection, hyperparameter tuning.
What AutoML Does Automatically
Featurization: imputes missing values, encodes categoricals, normalizes numerics. Algorithm sweep: tries LightGBM, XGBoost, RandomForest, ElasticNet, and others. Hyperparameter tuning: grid search + Bayesian optimization. Ensemble stacking: combines the top models for even better accuracy. All tracked in the experiment log.
When to Use AutoML
AutoML is ideal when you need a strong baseline fast, when you do not have deep ML expertise, or when you want to verify whether a dataset has predictive signal before investing in custom modeling. It is not a replacement for domain expertise — the quality of the features and the choice of target column still require human judgment.

Azure ML Designer
A visual drag-and-drop pipeline builder — connect component blocks to build complete ML workflows without writing a single line of code.
How Designer Works
You drag component blocks from the left panel onto a canvas, then draw connectors between their output and input ports. Each component is a pre-built operation — data transformation, algorithm, evaluation metric. The pipeline is a directed acyclic graph (DAG). When you submit it, Azure ML runs each step in dependency order on the compute target you select.
Pre-Built Components Available
Data components: Import Data, Select Columns, Clean Missing Data, Split Data, Normalize Data. Algorithm components: Linear Regression, Decision Forest, Boosted Decision Tree, Neural Network, K-Means Clustering, Multiclass Logistic Regression. Evaluation: Score Model, Evaluate Model. You can also add custom Python or R script steps.
Designer vs AutoML
Designer gives you explicit control over every pipeline step — you choose the algorithm, preprocessing, and evaluation. AutoML abstracts all of that and picks the best combination automatically. Use Designer when you have domain knowledge you want to encode in the pipeline. Use AutoML for rapid exploration when you want the machine to search the algorithm space for you.
Walk: A typical Designer pipeline runs left to right — load data, clean and normalize it, split into train/test, train with your chosen algorithm, score on the test split, then evaluate metrics. You re-run the whole pipeline whenever data changes.

Regression in Practice
Regression predicts a continuous numeric value. Classic example: predict a car's sale price from its features — mileage, age, engine size, brand.
What the Model Learns
The algorithm finds the coefficients (weights) for each feature that minimize prediction error on the training set. A weight of -0.12 on mileage means each additional 1,000 miles reduces the predicted price by about $120. These weights are learned — not coded by hand — which is why ML beats hand-coded rules for complex relationships.
Key Regression Algorithms in Azure ML
Linear Regression: assumes a straight-line relationship between features and target. Fast, interpretable, but fails on non-linear patterns. Decision Forest Regression: uses many decision trees, handles non-linear data well. Boosted Decision Tree: iteratively corrects errors — often best accuracy but harder to interpret.
Reading the Scatter Plot
The diagonal line is perfect prediction (actual = predicted). Points close to the line mean accurate predictions. Points far off the line are errors. A model that clusters tightly around the diagonal has high R-squared — meaning it explains most of the variance in the target. This is one of the most direct ways to visualize regression model quality.

Classification in Practice
Classification predicts a discrete category. Example: given patient health data, does this person have diabetes — positive or negative?
Binary vs. Multiclass
Binary: two possible outcomes — positive/negative, spam/not-spam, fraud/legitimate. The model outputs a probability between 0 and 1, then applies a threshold (default 0.5) to decide the class. Multiclass: three or more outcomes — e.g., "low / medium / high risk" or "cat / dog / bird." Azure ML supports both with the same interface.
What the Confidence Score Means
An 87% confidence score does not mean there is a 13% chance the model is broken. It means the model's internal probability estimate for "positive" is 0.87. If you lower the classification threshold to 0.3, you will catch more true positives but also generate more false alarms. Tuning this threshold is part of responsible deployment — especially in healthcare or fraud detection.
Reading the Decision Boundary
The curved line separates the two classes in feature space. Points above it are predicted positive; below are predicted negative. A complex boundary (many curves) indicates a model has learned fine-grained patterns but risks overfitting to training data. A straight boundary (logistic regression) is simpler but may misclassify complex cases — the trade-off between bias and variance.

Clustering in Practice
Clustering finds natural groups in unlabeled data. No right answer to learn — the algorithm discovers structure on its own. Example: segment customers by purchasing behavior.
How K-Means Works — Step by Step
Step 1 — Initialize: place K centroids randomly in the feature space. Step 2 — Assign: each data point is assigned to its nearest centroid (Euclidean distance). Step 3 — Recenter: each centroid moves to the mean position of all points assigned to it. Step 4 — Repeat: steps 2-3 iterate until assignments stop changing. Convergence is guaranteed but may reach a local minimum.
Choosing K (Number of Clusters)
There is no single correct answer — you choose K based on business context and validation. The elbow method plots "within-cluster variance" vs. K; the bend in the curve suggests where adding more clusters stops helping meaningfully. Azure ML Designer includes a K-Means component where you set K as a hyperparameter before training.
Real-World Applications
Customer segmentation: group customers by purchase patterns to tailor marketing. Anomaly detection: points far from any centroid are outliers. Image compression: replace each pixel color with its cluster centroid. Network traffic analysis: cluster traffic patterns to identify baselines, then flag anomalies. Clustering is unsupervised — no labels required at training time.

Training and Evaluating Models
You cannot evaluate a model on the same data you trained it with — that would be like a student grading their own exam. Train/test split is non-negotiable.
Regression Metrics
RMSE (Root Mean Squared Error): average magnitude of prediction errors, in the same units as the target. Lower is better. Penalizes large errors heavily. MAE (Mean Absolute Error): average absolute error — more robust to outliers than RMSE. R-squared (R²): 0 to 1 — proportion of variance explained. R²=0.91 means the model explains 91% of the price variation. R²=0 means no better than guessing the mean.
Classification Metrics
Accuracy: fraction of correct predictions — misleading when classes are imbalanced (99% "negative" dataset). Precision: of all predicted positives, how many were truly positive? Recall: of all actual positives, how many did we catch? F1: harmonic mean of precision and recall — best single metric when both matter. AUC-ROC: 0.5 = random guessing, 1.0 = perfect. Measures rank-ordering quality across all thresholds.
Why Splitting Matters
If you evaluate on training data, the model looks perfect because it has already seen those rows — this is called "data leakage." The test set simulates real-world deployment where the model sees data it has never encountered. Overfitting is when a model memorizes training data but fails on new data — the train/test gap reveals it. Azure ML tracks both training and validation metrics automatically.

Model Deployment
A trained model sitting in a workspace helps nobody. Deployment wraps it in a REST API endpoint so client applications can send data and receive predictions in real time.
Real-Time vs. Batch Endpoints
Real-time endpoint: deploys the model as a live HTTPS service on managed compute (AKS or managed inference). Each request gets a response within milliseconds. Use for user-facing apps and automated systems. Batch endpoint: processes large files of inputs asynchronously — submit a CSV, get predictions back in minutes or hours. Use for bulk scoring scenarios like nightly report generation.
Under the Hood
Azure ML wraps your model and a scoring script in a Docker container. The scoring script defines two functions: init() loads the model into memory when the container starts, and run(data) receives the JSON input, calls model.predict(), and returns the result. This containerization means the endpoint is portable, versioned, and independently scalable.
Updating a Deployed Model
Azure ML supports traffic splitting between model versions using blue/green deployment. You can route 10% of traffic to a new model version while 90% goes to the production version, compare metrics, then gradually shift traffic. This pattern eliminates downtime during model updates and allows rollback if the new model underperforms in production.

Azure AI Foundry
Microsoft's unified platform for enterprise AI development — Azure ML, Azure OpenAI, Custom Vision, AI Services, and the model catalog all accessible from one project-based portal.
What Changed: ML Studio → AI Foundry
Azure Machine Learning Studio focuses specifically on ML workflows — datasets, pipelines, compute, model registry. Azure AI Foundry (ai.azure.com) is the broader unified portal that includes Azure ML capabilities plus Azure OpenAI, the model catalog (open-source models from Meta, Mistral, Microsoft), Prompt Flow for LLM orchestration, and built-in AI safety evaluation tooling. For the AI-900 exam, know that Foundry is the current umbrella platform.
Project-Based Organization
Inside AI Foundry, you work within Projects, which belong to a Hub. The Hub provides shared compute, connections to data sources, and governance policies. Projects let teams work independently while sharing infrastructure. You can have one hub for your entire AI organization with many projects — one for the fraud detection team, one for NLP, one for computer vision — all billing to the same Azure subscription.
The Model Catalog
The model catalog inside Foundry gives you access to hundreds of models beyond GPT-4 — Llama 3 (Meta), Mistral, Phi-3 (Microsoft), Falcon, and fine-tuned vertical models. You can deploy them as managed endpoints directly from the catalog, compare benchmark scores, and use them in Prompt Flow. This is where Microsoft is competing with HuggingFace Hub in the enterprise space.

Responsible ML
ML models can cause real harm if they are biased, opaque, or privacy-violating. Responsible ML is not a compliance checkbox — it is an engineering discipline built into the Azure ML platform.
Fairness — The Real Problem
A loan approval model trained on historical data may learn to deny applications from certain zip codes — not because of the zip code itself, but because historical discrimination produced biased outcomes in the training data. The model becomes a statistical proxy for discrimination. Azure ML includes the Fairlearn toolkit to measure accuracy disparities across demographic groups and test mitigation strategies like re-weighting or threshold adjustment by group.
Interpretability with SHAP
SHAP (SHapley Additive exPlanations) decomposes each prediction into the contribution of each feature. For a diabetes prediction: "Glucose contributed +0.61 (strong positive), Age contributed +0.34, BMI contributed +0.18." Azure ML's Responsible AI dashboard generates SHAP explanations automatically. This is critical for regulated industries — doctors and loan officers often need to explain why a decision was made.
Model Cards and Accountability
A model card documents: what the model was trained to do, what data it was trained on, known limitations and failure modes, demographic performance disparities, and the intended deployment context. Publishing a model card before deploying to production is considered best practice. Azure AI Foundry's evaluation tools generate model card content automatically from your evaluation run results.

Chapter 5 Summary
Key takeaways from Predictive Models with Azure Machine Learning — what you need to own for the AI-900 exam.
01 The Azure ML Workspace is the top-level resource that organizes datasets, jobs, models, compute, and endpoints — everything tracked and versioned in one place.
02 AutoML automates algorithm selection and hyperparameter tuning — you provide data and a target column; it produces a ranked leaderboard and registers the best model.
03 Three ML task types: Regression (supervised) predicts numeric values (RMSE, R²), Classification (supervised) predicts categories (accuracy, precision, recall, F1, AUC), Clustering (unsupervised) finds natural groups without labels. Note: AutoML supports regression, classification, and forecasting — clustering is done via the Designer or Python SDK.
04 Always split data into train (80%) and test (20%) — test data must be held out to get an honest accuracy estimate. Evaluating on training data inflates metrics and hides overfitting.
05 Deployment creates a REST API endpoint — your app sends a JSON request with feature values and receives a JSON prediction response. Real-time and batch endpoint types available.
06 Responsible ML covers fairness (Fairlearn for bias detection), interpretability (SHAP values), and data privacy. Model cards document capabilities and limitations before deployment.
