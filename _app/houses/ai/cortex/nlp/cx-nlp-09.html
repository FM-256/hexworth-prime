1. QA Task Types

Extractive QA

Answer is a span extracted verbatim from the passage. Model predicts start and end token positions. BERT on SQuAD is the canonical example. No hallucination possible.

Abstractive QA

Answer is generated text, possibly paraphrasing or synthesizing the passage. T5/BART fine-tuned on QA pairs. More natural answers, risk of hallucination.

Open-Domain QA

No passage provided — model must retrieve relevant documents from a large corpus, then answer. Combines retrieval (BM25 or dense) with reading comprehension.

2. Extractive QA: BERT on SQuAD

Extractive QA as Span Prediction
Input: [CLS] Question tokens [SEP] Passage tokens [SEP] BERT encodes all tokens with bidirectional attention Output head: Linear(d_model, 2) applied to each passage token -- logit_start[i] = score for token i being answer start -- logit_end[i] = score for token i being answer end Training loss: cross-entropy(start_logits, start_label) + cross-entropy(end_logits, end_label) Inference: argmax over valid spans where start <= end < start + max_answer_length

3. Dense Passage Retrieval

Open-domain QA requires first retrieving relevant passages from a large document collection. BM25 (sparse keyword matching) works well but misses semantic variants. Dense Passage Retrieval (DPR) uses bi-encoder neural embeddings — question and passage are encoded separately, then matched by inner product. 

from sentence_transformers import SentenceTransformer
import numpy as np
import faiss   # pip install faiss-cpu

# Bi-encoder model: encodes questions and passages into same semantic space
encoder = SentenceTransformer('multi-qa-mpnet-base-dot-v1')

# Build passage index from CVE corpus
def build_index(passages: list) -> tuple:
    """
    Encode passages and build a FAISS inner-product index.
    Returns (index, passage_list).
    """
    embeddings = encoder.encode(passages, batch_size=64,
                                show_progress_bar=True, normalize_embeddings=True)
    dim   = embeddings.shape[1]
    index = faiss.IndexFlatIP(dim)          # inner product (= cosine for L2-normalized)
    index.add(embeddings.astype(np.float32))
    return index, passages


def retrieve(query: str, index, passages: list, k: int = 5) -> list:
    """Retrieve top-k most relevant passages for a query."""
    q_emb = encoder.encode([query], normalize_embeddings=True)
    scores, indices = index.search(q_emb.astype(np.float32), k)
    return [(passages[i], scores[0][j]) for j, i in enumerate(indices[0])]

4. RAG Pipeline

Retrieval-Augmented Generation (Lewis et al. 2020) combines dense retrieval with a generative model. The retrieved passages are concatenated into the generator's prompt, grounding the answer in retrieved evidence rather than parametric memory.

RAG Pipeline
User Query: "What mitigation exists for CVE-2023-44487?" | Retriever: bi-encoder embeds query FAISS search -> top-k passages (k=5) | Reranker: (optional) cross-encoder reranks top-k passages more accurate than bi-encoder but slower | Prompt Construction: "Context: {passage_1}... {passage_k} Question: {query} Answer:" | Generator: T5 / BART / GPT-2 reads full context + question generates grounded answer | Answer: "Update to patched versions or implement rate limiting on HTTP/2 streams." 
from transformers import AutoTokenizer, AutoModelForSeq2SeqLM
import torch

# Generator model for RAG (T5 is flexible for multi-turn)
gen_tokenizer = AutoTokenizer.from_pretrained('t5-base')
gen_model     = AutoModelForSeq2SeqLM.from_pretrained('t5-base')

def rag_answer(query: str, index, passages: list, k: int = 3,
              max_answer_len: int = 150) -> dict:
    """
    Full RAG pipeline: retrieve then generate.
    Returns answer string and source passages.
    """
    # Step 1: Retrieve relevant passages
    retrieved = retrieve(query, index, passages, k=k)
    context   = ' \n\n '.join([p for p, _ in retrieved])

    # Step 2: Format prompt for T5
    prompt = f"question: {query} context: {context}"
    inputs = gen_tokenizer(prompt, return_tensors='pt', truncation=True, max_length=512)

    # Step 3: Generate answer
    with torch.no_grad():
        output = gen_model.generate(
            **inputs,
            max_new_tokens=max_answer_len,
            num_beams=4,
            no_repeat_ngram_size=3,
            early_stopping=True
        )
    answer = gen_tokenizer.decode(output[0], skip_special_tokens=True)
    return {'answer': answer, 'sources': [p for p, _ in retrieved]}

Key Takeaways

  • Extractive QA predicts start/end span positions in the passage — no hallucination, but answers limited to exact source text
  • Dense retrieval encodes questions and passages into shared embedding space for semantic matching beyond keyword overlap
  • RAG grounds LLM generation in retrieved evidence — reduces hallucination compared to purely parametric generation
  • FAISS enables efficient approximate nearest-neighbor search over millions of passage embeddings
  • Evaluate QA with both Exact Match and Token F1 — F1 gives partial credit for answers that overlap but don't exactly match
  • Cross-encoder reranking improves retrieval quality at the cost of latency — use for high-stakes applications
