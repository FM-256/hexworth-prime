1. Evolution of Machine Translation

MT Paradigm Shift
1950s-1990s: Rule-Based MT (RBMT) Hand-crafted linguistic rules, dictionaries, grammars Brittle, expensive, language-pair-specific 2000s-2016: Statistical MT (SMT) Learn phrase translation tables from parallel corpora Language model + translation model decoded by beam search Phrase tables grow massive (gigabytes per language pair) Moses toolkit was the dominant system 2016-2017: Neural MT (NMT) — attention + RNN seq2seq Google Brain, Bahdanau attention Massive quality jump -- BLEU +10 on WMT benchmarks 2017-present: Transformer-based NMT "Attention Is All You Need" -- seq2seq Transformer Current production: Google Translate, DeepL, Amazon Translate Multilingual models: mBART, mT5, NLLB-200 (200 languages)

2. BPE Tokenization

Machine translation must handle vocabulary across multiple languages. Byte Pair Encoding (BPE) learns a shared subword vocabulary from both source and target languages. Rare words decompose into known subwords — "unhappiness" becomes "un##happiness" or "un##happy##ness". 

import tokenizers
from tokenizers import Tokenizer
from tokenizers.models import BPE
from tokenizers.trainers import BpeTrainer
from tokenizers.pre_tokenizers import Whitespace

# Train BPE from scratch
tokenizer = Tokenizer(BPE(unk_token='[UNK]'))
tokenizer.pre_tokenizer = Whitespace()

trainer = BpeTrainer(
    vocab_size=32000,
    min_frequency=2,
    special_tokens=['[UNK]', '[CLS]', '[SEP]', '[PAD]', '[MASK]']
)

# Train on bilingual corpus (both source and target language files)
tokenizer.train(files=['en_corpus.txt', 'de_corpus.txt'], trainer=trainer)
tokenizer.save('bpe_tokenizer.json')

# Encode a sentence -- observe subword splits
output = tokenizer.encode("The vulnerability affects unhardened systems")
print(output.tokens)   # ['The', 'vulner', 'ability', 'affects', 'un', 'hard', 'ened', 'systems']

3. Translation with HuggingFace

from transformers import pipeline, AutoTokenizer, AutoModelForSeq2SeqLM

# MarianMT: fast, specialized per language pair
translator_de = pipeline('translation', model='Helsinki-NLP/opus-mt-en-de')
result = translator_de("The attacker exploited a zero-day vulnerability.")
print(result[0]['translation_text'])

# NLLB-200: Facebook's 200-language multilingual model
model_name = 'facebook/nllb-200-distilled-600M'
tokenizer  = AutoTokenizer.from_pretrained(model_name)
model      = AutoModelForSeq2SeqLM.from_pretrained(model_name)

def translate(text: str, src_lang: str, tgt_lang: str, max_new_tokens=128) -> str:
    """
    Translate using NLLB-200.
    Language codes: 'eng_Latn', 'deu_Latn', 'fra_Latn', 'zho_Hans', 'arb_Arab', etc.
    Full list: https://github.com/facebookresearch/flores
    """
    tokenizer.src_lang = src_lang
    inputs = tokenizer(text, return_tensors='pt', truncation=True, max_length=512)
    forced_id = tokenizer.convert_tokens_to_ids(tgt_lang)

    output = model.generate(
        **inputs,
        forced_bos_token_id=forced_id,
        max_new_tokens=max_new_tokens,
        num_beams=4,
        no_repeat_ngram_size=3
    )
    return tokenizer.decode(output[0], skip_special_tokens=True)

# Translate a CVE description into multiple languages
cve_text = "A heap buffer overflow vulnerability in OpenSSL allows remote attackers to execute arbitrary code."
for lang, code in [('German', 'deu_Latn'), ('French', 'fra_Latn'), ('Chinese', 'zho_Hans')]:
    translated = translate(cve_text, 'eng_Latn', code)
    print(f"\n[{lang}] {translated}")

4. Evaluation: BLEU and chrF

BLEU Score Formula
BLEU = BP * exp( sum_{n=1}^{N} w_n * log p_n ) p_n = modified n-gram precision (clipped by reference count) BP = brevity penalty (penalizes short translations) w_n = 1/N weights (usually N=4, w=0.25) Range: 0 (worst) to 100 (perfect match) Rough interpretation: < 10: almost useless 10-19: some signal, but very poor 20-29: understandable 30-40: good quality 40-50: high quality > 50: near human quality (rare) Limitations: exact n-gram match, does not handle paraphrase or morphology chrF: character n-gram F-score, correlates better with human judgments for morphologically rich languages 
from sacrebleu.metrics import BLEU, CHRF
# pip install sacrebleu

# Always use sacrebleu for reproducible BLEU computation
bleu = BLEU(tokenize='13a')   # standard Moses tokenization
chrf = CHRF()

hypotheses = [
    "The attacker exploited a memory corruption vulnerability.",
]
references = [[
    "The attacker took advantage of a memory corruption vulnerability.",
]]

bleu_score = bleu.corpus_score(hypotheses, references)
chrf_score = chrf.corpus_score(hypotheses, references)
print(f"BLEU: {bleu_score.score:.2f}")
print(f"chrF: {chrf_score.score:.2f}")

# Sentence-level BLEU (less reliable -- use corpus-level for evaluation)
sent_bleu = bleu.sentence_score(hypotheses[0], references[0])
print(f"Sentence BLEU: {sent_bleu.score:.2f}")

COMET: The Modern Standard COMET (Crosslingual Optimized Metric for Evaluation of Translation) is a neural metric trained on direct human assessment scores. It consistently outperforms BLEU in correlation with human judgments. Use COMET for final production evaluation; use BLEU for fast intermediate comparisons during training due to its low compute cost.

Key Takeaways

  • Modern MT is Transformer encoder-decoder — the same architecture as the original 2017 paper, now scaled to 200 languages
  • BPE tokenization solves the OOV problem for MT by decomposing rare words into known subwords across both languages
  • BLEU is the standard reporting metric but correlates poorly with human judgments — COMET is the modern alternative
  • MarianMT (Helsinki-NLP) provides fast, specialized models; NLLB-200 provides 200-language coverage in one model
  • chrF is preferred over BLEU for evaluating translation of morphologically rich languages (German, Finnish, Turkish)
  • Translation quality has reached professional quality for high-resource language pairs but remains poor for low-resource languages
