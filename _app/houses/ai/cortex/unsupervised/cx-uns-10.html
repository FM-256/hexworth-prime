Why Unsupervised for Security?

Supervised security models require labeled training data -- but attacks are constantly evolving. A model trained on yesterday's attack signatures will miss today's zero-days. Unsupervised learning builds models of normal behavior and flags deviations, making it inherently more adaptable to novel threats.

The Defender's Dilemma

Defenders must correctly classify all traffic; attackers only need to blend in with normal traffic once. Unsupervised models shift the advantage: instead of recognizing attack patterns, they recognize normal patterns. An attacker must mimic normal behavior perfectly -- a much harder constraint.

User Behavior Analytics (UBA)

UBA builds a baseline of normal behavior for each user and alerts when behavior deviates. Key features include: login times, accessed resources, data volume, geographic location, application usage patterns.

Per-User Baseline Train a separate model per user (or user group). User X accessing servers at 3am may be normal for a night-shift SRE but anomalous for a finance employee.
Autoencoder Approach Train autoencoder on each user's historical behavior. Flag sessions with reconstruction error above 95th percentile. Retrains periodically to adapt to legitimate behavior changes.
UMAP Visualization Project all user sessions to 2D with UMAP. Visualize clusters for normal user types. Sessions in unexpected regions of the plot warrant investigation.
Peer Group Analysis Cluster similar users (by role, department) and flag users whose behavior deviates from their peer group. Insider threats often stand out within their cohort even if within overall norms.

Malware Clustering

Security analysts use unsupervised clustering to group malware samples into families, enabling prioritization and attribution. Features are extracted from dynamic analysis (sandbox runs): API call sequences, network connections, file system activity, registry changes.

# Represent each sample as a bag of API calls
# api_sequences: list of strings, each being API calls joined by spaces

X_api = tfidf.fit_transform(api_sequences)

# DBSCAN with cosine distance -- robust to sequence length variation
dist_matrix = cosine_distances(X_api)
db = DBSCAN(eps=0.3, min_samples=5, metric='precomputed')
families = db.fit_predict(dist_matrix)

n_families = len(set(families)) - (1 if -1 in families else 0)
print(f"Discovered {n_families} malware families")
print(f"Novel/unclassified samples: {(families == -1).sum()}")

Key Takeaways

  • Unsupervised security ML builds models of normal behavior rather than attack signatures -- more robust to novel threats
  • Network anomaly: engineer flow-level features, apply PCA, score with Isolation Forest, alert on top percentile
  • UBA: per-user or per-group baselines; autoencoder reconstruction error is a natural anomaly signal
  • Malware clustering: TF-IDF on API call sequences + DBSCAN with cosine distance
  • Always validate against threat intelligence or analyst feedback -- unsupervised models produce many false positives without tuning
  • Concept drift: schedule periodic retraining; monitor alert rate as a health metric
