AI Meets Defense

Cybersecurity is one of the highest-stakes domains for applied ML. The asymmetry of the defender's problem — one attacker needs to succeed once; defenders must succeed every time — makes any tool that scales analytical capacity valuable. ML is compelling because it can process log volumes that no human team could analyze in real time, detect patterns too subtle for rule-based systems, and adapt to attacker behavior without requiring manual rule updates.

Every defensive AI application comes with adversarial considerations that do not exist in most ML domains: attackers will specifically attempt to evade, fool, or poison the ML systems protecting against them. This dual nature — AI as a defensive tool and AI as an adversarial target — is what makes ML for cybersecurity a distinct discipline. Course ML-13 (ML for Cybersecurity) covers the full technical depth; this module provides the architectural foundations.

Network Intrusion Detection

Anomaly-Based Network IDS

Signature-based IDS systems match traffic against known attack patterns. They are highly precise for known attacks but completely blind to novel ones. ML-based anomaly detection takes a different approach: model the distribution of normal traffic, then flag deviations as potentially malicious. This provides detection capability for zero-day attacks and novel attack patterns that have no signature.

Feature extraction from network flows: ML models for network IDS typically operate on network flow features rather than raw packets (for scalability). Key features include: flow duration, bytes per second, packets per flow, ratio of packets in each direction, TCP flag distributions (SYN/ACK/RST ratios), inter-arrival time statistics, and destination port entropy. Tools like Zeek and CICFlowMeter extract these features from captured traffic.

Common models: Isolation Forest (anomaly detection, no labeled data needed), Autoencoder (reconstruction error as anomaly score), Random Forest (supervised, requires labeled attack data), LSTM for sequential flow analysis.

Key challenge — class imbalance: In a well-defended network, attack traffic may represent 0.01% of total volume. Standard ML metrics will favor "predict all normal" with 99.99% accuracy. Evaluation must use precision, recall, and F1-score for the attack class. SMOTE or cost-sensitive learning addresses the imbalance during training.

Techniques: Isolation Forest, Autoencoder, LSTM, Random Forest | Features: NetFlow, Zeek logs, CICFlowMeter
Python — Isolation Forest anomaly detection on network flow features
import pandas as pd
import numpy as np
from sklearn.ensemble import IsolationForest
from sklearn.preprocessing import StandardScaler

# Flow features extracted from Zeek conn.log
features = ['duration', 'bytes_sent', 'bytes_recv',
            'packets_sent', 'packets_recv', 'orig_pkts']

df = pd.read_csv('conn_features.csv')
X = df[features].fillna(0)

# Scale features (Isolation Forest is scale-sensitive)
scaler = StandardScaler()
X_scaled = scaler.fit_transform(X)

# Train on "normal" traffic only (unsupervised)
clf = IsolationForest(
    contamination=0.001,  # expected fraction of anomalies
    random_state=42,
    n_estimators=200
)
clf.fit(X_scaled)

# Predict: -1 = anomaly, 1 = normal
df['anomaly'] = clf.predict(X_scaled)
df['anomaly_score'] = clf.score_samples(X_scaled)

# Surface top anomalies for analyst review
alerts = df[df['anomaly'] == -1].sort_values('anomaly_score')
print(f"Flagged {len(alerts)} suspicious flows for review")

Malware Detection and Classification

Static Malware Analysis with ML

Traditional static analysis relies on hash signatures — a single byte change defeats it. ML-based approaches extract features that are harder to evade: n-gram models of byte sequences, import table features (what API calls does the PE import?), entropy analysis (packed/encrypted sections have higher entropy), section name and size characteristics.

Malware visualization with CNNs: A creative approach pioneered by Nataraj et al. (2011) converts malware binaries to grayscale images by treating each byte as a pixel value (0-255). The resulting images show distinctive visual patterns that differ by malware family — ransomware, banking trojans, worms, and rootkits each have characteristic textures from their code structure and data sections. A CNN trained on these visualizations achieves over 95% accuracy on malware family classification and is remarkably resistant to simple evasion techniques.

Dynamic analysis: Run samples in a sandbox and analyze behavior — API call sequences, file system modifications, network connections, registry changes. LSTM and transformer models learn temporal patterns in API call sequences that characterize malware behavior families more robustly than static features.

Techniques: CNN on binary images, n-gram models, LSTM for API sequences | Tools: EMBER dataset, VirusTotal, Cuckoo sandbox

Phishing Detection

URL and Email Phishing Classification

URL features for phishing detection: Machine-readable features include: URL length, number of dots, presence of IP address instead of domain, number of subdomains, HTTPS status, domain age (from WHOIS), lexical similarity to known brands (typosquatting detection), entropy of domain name, use of URL shorteners, and presence of suspicious keywords.

Transformer-based email analysis: BERT fine-tuned on labeled phishing/legitimate email datasets achieves state-of-the-art performance on header analysis, body text classification, and sender domain analysis. The model can detect phishing language patterns, urgency indicators, and brand impersonation more robustly than rule-based systems because it generalizes to novel phrasing.

Challenge — adversarial LLMs: Generative AI significantly raises the quality ceiling for phishing content. Grammatically perfect, contextually relevant, personalized phishing at scale is now achievable with LLMs. Defenses must evolve: behavioral indicators (unusual link structure, domain age, sender reputation) become more important as content-based signals weaken.

Techniques: BERT fine-tuning, gradient boosted trees on URL features, ensemble methods

UEBA and SOC Automation

User and Entity Behavior Analytics

UEBA systems model the normal behavior of users and devices, then alert on deviations. The fundamental insight: insiders and lateral-movement attackers behave differently from the baselines those accounts have established, even when they use legitimate credentials. A user who normally logs in from Chicago, works 9-5, and accesses HR systems, suddenly logging in from an unknown country at 2am and downloading 10GB from a file server is statistically anomalous regardless of whether credentials are valid.

Core ML components: Autoencoders model the distribution of normal behavior per user; reconstruction error flags anomalies. Peer group analysis identifies when a user's behavior deviates from their peer group (similar role/department). Temporal models (LSTM) capture time-of-day and day-of-week seasonality. Risk scores are accumulated over time: one unusual event is noise; a sequence of unusual events within a window triggers an alert.

Techniques: Autoencoders, peer group analysis, LSTM, risk scoring | Commercial tools: Splunk UBA, Microsoft Sentinel, Varonis
SOC Use CaseAI/ML ApproachImpact
Alert triage LLM summarizes alert context, correlated events, and asset criticality. Analyst sees a pre-synthesized brief instead of raw logs. Reduces time-to-triage from 20-40 minutes to 2-5 minutes per alert
Threat intelligence enrichment NER models extract IOCs (IPs, hashes, domains) from unstructured reports. LLMs summarize vendor advisories into structured MITRE ATT&CK mappings. Converts hours of analyst reading into automated structured data
Playbook automation LLM interprets analyst-written natural language playbooks and converts them to automated orchestration steps. Or executes decision trees based on alert classification. Enables non-developers to build and modify automation workflows
Threat hunting LLM translates natural language hunt hypotheses ("find users exfiltrating data via DNS tunneling") into SIEM queries (KQL, SPL, EQL). Lowers barrier for analysts without deep query language expertise

AI Security Systems Are Attack Surfaces

Every ML system in a security stack is also an adversarial target. An attacker who understands your NIDS is using Isolation Forest can craft traffic that stays within the "normal" manifold while accomplishing the attack objective. An attacker who knows your email filter is BERT-based can craft phishing emails that semantically resemble legitimate communications while preserving malicious intent. Course ML-12 (Adversarial Machine Learning) covers these attack techniques and the defenses in depth.

Key Takeaways

  • Network IDS with ML uses anomaly detection (unsupervised) for zero-day detection and supervised classifiers (Random Forest, LSTM) for known attack patterns
  • Malware classification leverages static features (PE imports, byte n-grams), binary visualization with CNNs, and dynamic API call sequence analysis with LSTMs
  • Phishing detection uses URL lexical features plus transformer-based email content classification; generative AI is raising the quality of phishing attacks, weakening content-based signals
  • UEBA models per-user behavioral baselines using autoencoders and peer group analysis; accumulated risk scores trigger alerts rather than single events
  • LLMs are accelerating SOC operations through alert triage, threat intel enrichment, playbook automation, and natural language query generation
  • Every ML security system is also an adversarial target — understanding the evasion surface is part of responsible deployment
