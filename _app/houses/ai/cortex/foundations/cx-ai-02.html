Learning Objectives

The Nested Hierarchy

The terms "artificial intelligence," "machine learning," and "deep learning" are often used interchangeably in the media, but they describe nested subsets of the same field. Getting the hierarchy right matters because it clarifies what any given system actually does — and what it cannot do.

Nested Relationship — AI Superset
Artificial Intelligence (Broadest) Any technique that enables machines to perform tasks that would normally require human intelligence. Includes rule-based systems, search, planning, and all of ML.
Machine Learning (Subset of AI) Algorithms that learn from data without being explicitly programmed with rules. The system improves its performance on a task as it is exposed to more data.
Deep Learning (Subset of ML) Machine learning using artificial neural networks with multiple layers. The "deep" refers to the depth (number of layers). Drives most current state-of-the-art results.
Generative AI (Subset of DL) Deep learning systems that generate new content — text, images, audio, video. GPT, DALL-E, Stable Diffusion, and Sora are generative AI systems built on deep learning.

Traditional Programming vs Machine Learning

The fundamental paradigm shift of machine learning is a reversal of the traditional software development workflow. This distinction is worth understanding precisely because it explains both the power and the limitations of ML systems.

DimensionTraditional ProgrammingMachine Learning
What you provide Data + Rules (explicit logic) Data + Answers (labeled examples)
What you get Outputs (computed results) Rules (a learned model)
How it handles new cases Exactly as the code specifies — fails on unanticipated inputs Generalizes from patterns — handles novel inputs probabilistically
Best when Rules are well-defined, deterministic, fully understood by humans Rules are too complex or numerous to write by hand; large data exists
Example Tax calculation: precise rules defined by legislation Spam detection: too many patterns for humans to enumerate all rules

The Three Learning Paradigms

Machine learning problems are categorized by the nature of the feedback available during training. The three major paradigms cover nearly all practical applications.

Supervised Learning Trains on labeled (input, answer) pairs. The model learns a mapping from inputs to outputs. Email spam/ham, image classification, house price prediction, medical diagnosis. Most industrial ML is supervised.
Unsupervised Learning Trains on unlabeled data. The model discovers hidden structure, patterns, or groupings. Customer segmentation, anomaly detection, dimensionality reduction, generative modeling.
Reinforcement Learning An agent takes actions in an environment and receives rewards or penalties. Learns a policy that maximizes cumulative reward. Game playing (AlphaGo, AlphaStar), robotics, RLHF for LLMs.
Semi-Supervised & Self-Supervised Hybrid approaches. Semi-supervised uses small labeled sets with large unlabeled sets. Self-supervised creates its own labels from data (e.g., predicting the next word). GPT pre-training is self-supervised.
ParadigmInputSignalTypical AlgorithmsExample Task
Supervised Labeled (X, y) pairs Explicit correct answer Linear regression, SVM, random forest, neural net Classify email as spam/ham
Unsupervised Unlabeled X only Internal structure in data k-Means, DBSCAN, PCA, autoencoders Group customers by behavior
Reinforcement State observations Reward signal from environment Q-learning, PPO, actor-critic Train agent to play chess
Self-supervised Raw unlabeled data Labels created from data itself Masked language model, contrastive learning Pre-train GPT on internet text

Core ML Vocabulary

Before going further in the curriculum, these terms need to be precise. They appear in every ML paper, framework, and conversation.

TermDefinitionExample
Feature An individual measurable property of a data point. The inputs to a model. For housing prices: square footage, number of bedrooms, zip code
Label / Target The output we want the model to predict. What the model is trying to learn. For housing prices: sale price in dollars
Model A mathematical function that maps inputs (features) to outputs (predictions). The artifact produced by training. A trained neural network that takes an image and outputs "cat" or "dog"
Training Data The labeled examples used to fit (train) the model's parameters. 10,000 images each tagged with the correct animal label
Test Data Held-out examples never seen during training, used to evaluate real-world performance. 2,000 images the model has never seen — evaluates true accuracy
Overfitting Model memorizes training data instead of generalizing. High training accuracy, low test accuracy. A model that gets 99% on training images but 60% on new ones
Underfitting Model is too simple to capture the patterns in the data. Low accuracy on both training and test sets. A linear model trying to learn a complex nonlinear boundary
Hyperparameter Configuration settings chosen before training that control how the model learns (not learned from data). Learning rate, number of layers, number of trees in a forest

The Bias-Variance Tradeoff

Every ML model navigates a fundamental tension: a model complex enough to capture all patterns in training data (low bias) will tend to overfit (high variance). A model simple enough to avoid overfitting (low variance) will miss real patterns (high bias). The goal is to find the sweet spot — a model with just enough capacity for the problem. Regularization, cross-validation, and data augmentation are the primary tools for managing this tradeoff.

What Makes a Problem Well-Suited for ML?

Machine learning is not the right tool for every problem. Understanding when to reach for ML — and when not to — is a practitioner skill that separates thoughtful engineers from cargo-cult builders.

Good ML candidates Problems where patterns exist in data but rules are too complex to enumerate by hand. Examples: image recognition, speech transcription, fraud detection, medical imaging, recommendation systems.
Poor ML candidates Problems with small data, clear deterministic rules, or where correctness must be provable. Examples: tax calculation, sorting algorithms, legal compliance checks, cryptographic operations.

The ML Readiness Checklist

  • Sufficient labeled data exists (typically thousands to millions of examples)
  • The task has discoverable patterns that generalize across examples
  • Approximate solutions are acceptable (probabilistic output is fine)
  • Traditional rule-based approaches are infeasible or too brittle
  • Interpretability requirements can be met (or the domain permits a black box)

Classification Practice

For each of the following tasks, identify: (1) Is it AI / ML / DL or traditional programming? (2) If ML, which paradigm — supervised, unsupervised, or reinforcement? (3) What would the features and labels be?

  1. A program that sorts a list of numbers from smallest to largest.
  2. An application that groups news articles by topic without being told what topics exist.
  3. A model that predicts whether a bank transaction is fraudulent based on historical fraud data.
  4. An AI that learns to navigate a maze by trial and error, receiving a reward when it reaches the exit.
  5. A system that generates captions for images it has never seen before.

Key Takeaways

  • AI is the broadest category; ML is a subset of AI; deep learning is a subset of ML using multi-layer neural networks
  • Traditional programming: you write the rules. Machine learning: you provide examples and the system learns the rules
  • Supervised learning trains on labeled (input, answer) pairs — the dominant paradigm in production ML
  • Unsupervised learning finds hidden structure in unlabeled data — used for clustering, anomaly detection, compression
  • Reinforcement learning trains an agent by rewarding desired behavior — powers game AI, robotics, and RLHF
  • Features are inputs; labels are outputs; a model is a learned function mapping one to the other
  • Overfitting = memorizing training data; underfitting = too simple to learn patterns; the bias-variance tradeoff governs both
