1. The Pre-Train / Fine-Tune Paradigm

Before BERT (2018), most NLP models trained from scratch on each task, using word vectors (word2vec, GloVe) only as a warm-start. BERT introduced a paradigm shift: pre-train a deep bidirectional Transformer on massive unlabeled text, then fine-tune the entire model on small labeled datasets. This is now the dominant approach across all of NLP and beyond.

Pre-Train / Fine-Tune Pipeline
Phase 1 — Pre-Training (once, expensive) Corpus: BooksCorpus (800M words) + English Wikipedia (2.5B words) Objectives: Masked LM + Next Sentence Prediction Hardware: 64 TPU v3 chips, 4 days (BERT-Large) | v Saved checkpoint: 340M parameters | Phase 2 — Fine-Tuning (per task, cheap) Add task head: [CLS] -> Linear -> softmax / span predictor / etc. Fine-tune all parameters end-to-end Typically: 2–4 epochs, minutes on a single GPU | v Production model: SST-2 (sentiment), SQuAD (QA), NER, NLI, ...

2. Pre-Training Objectives

Masked Language Modeling (MLM)

15% of tokens are randomly selected. Of those: 80% are replaced with [MASK], 10% with a random token, 10% left unchanged. The model must predict the original token at masked positions. Because the full left AND right context is available at every unmasked position, BERT is truly bidirectional.

MLM Example
Original: "The cat sat on the mat near the window" Input: "The [MASK] sat on the mat near the window" ^ model must predict "cat" using both left and right context Loss: cross-entropy at masked positions only Key: 80% masked, 10% random token, 10% unchanged -- prevents model from only learning to restore [MASK] tokens

Next Sentence Prediction (NSP)

50% of the time, sentence B actually follows sentence A in the corpus (label: IsNext). 50% of the time, sentence B is a random sentence from elsewhere (label: NotNext). The [CLS] token representation is used to classify. NSP was intended to help tasks like QA and NLI that require sentence pair reasoning, though later work (RoBERTa) showed NSP may slightly hurt single-sentence tasks.

NSP Controversy RoBERTa (Liu et al. 2019) showed that removing NSP and training with full-sentence inputs improved all downstream benchmarks. The consensus is that NSP as originally formulated is too easy (sentences from different documents are trivially distinguishable by topic) and provides weak signal. Modern BERT variants typically drop it.

3. Input Representation

BERT encodes sentence pairs by concatenating them with special tokens. The final input embedding is the sum of three separate learned embeddings.

BERT Input Tokens for Sentence Pair
[CLS] tok1 tok2 ... tokN [SEP] tok1 tok2 ... tokM [SEP] Token embeddings: learned 30k WordPiece vocab Segment embeddings: E_A for sentence A tokens, E_B for sentence B tokens Position embeddings: learned, absolute positions 0..511 Final: token_emb + segment_emb + position_emb (all d_model=768) [CLS] -- aggregates sentence-level representation, used for classification [SEP] -- marks sentence boundary

4. Fine-Tuning for Downstream Tasks

Fine-tuning just adds a thin task-specific head on top of BERT and trains end-to-end. The table below shows the standard heads for common task types.

Task TypeInputHeadLoss
Sentence Classification Single sentence Linear([CLS], num_classes) Cross-entropy
Sentence Pair / NLI Premise + Hypothesis Linear([CLS], 3) — entail/neutral/contra Cross-entropy
Token Classification (NER) Single sentence Linear(each token hidden, num_labels) Cross-entropy per token
Extractive QA (SQuAD) Question + Passage Linear(each token, 2) — start/end logits Cross-entropy (start + end) 
from transformers import AutoTokenizer, AutoModelForSequenceClassification
import torch
from torch.optim import AdamW
from transformers import get_linear_schedule_with_warmup

# ---- 1. Load pre-trained model and tokenizer ----
MODEL_NAME = 'bert-base-uncased'
tokenizer  = AutoTokenizer.from_pretrained(MODEL_NAME)
model      = AutoModelForSequenceClassification.from_pretrained(
    MODEL_NAME, num_labels=2  # binary sentiment
)

# ---- 2. Tokenize a batch ----
texts  = ["The film was absolutely brilliant.",
          "Terrible acting, avoid at all costs."]
labels = torch.tensor([1, 0])

encoding = tokenizer(
    texts,
    padding=True,
    truncation=True,
    max_length=128,
    return_tensors='pt'
)
# encoding keys: input_ids, attention_mask, token_type_ids

# ---- 3. Forward pass ----
outputs = model(**encoding, labels=labels)
loss, logits = outputs.loss, outputs.logits
print(f"Loss: {loss.item():.4f}, Logits: {logits}")

# ---- 4. Training setup ----
NUM_EPOCHS    = 3
WARMUP_RATIO  = 0.1
TOTAL_STEPS   = NUM_EPOCHS * len_train_loader  # define based on your DataLoader

optimizer = AdamW(model.parameters(), lr=2e-5, weight_decay=0.01)
scheduler = get_linear_schedule_with_warmup(
    optimizer,
    num_warmup_steps=int(TOTAL_STEPS * WARMUP_RATIO),
    num_training_steps=TOTAL_STEPS
)

# ---- 5. Training loop ----
def train_epoch(model, loader, optimizer, scheduler, device):
    model.train()
    total_loss = 0
    for batch in loader:
        batch = {k: v.to(device) for k, v in batch.items()}
        outputs = model(**batch)
        loss    = outputs.loss
        loss.backward()
        torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)  # gradient clipping
        optimizer.step()
        scheduler.step()
        optimizer.zero_grad()
        total_loss += loss.item()
    return total_loss / len(loader)

5. BERT Variants and Successors

ModelKey ChangeParametersSpeed vs BERT-Base
BERT-Base Baseline (12 layers, 768 dim) 110M 1x
RoBERTa No NSP, dynamic masking, more data (160GB), larger batches 125M ~1x (slower training, faster fine-tuning)
DistilBERT Knowledge distillation from BERT — 6 layers, 66M params 66M 1.6x faster inference
ALBERT Factorized embeddings + cross-layer parameter sharing 12M (base) Much smaller, competitive accuracy
DeBERTa Disentangled attention (separate content/position), enhanced mask decoder 184M (base) ~1x; SOTA on GLUE/SuperGLUE at time of release
ModernBERT Flash Attention, RoPE, 8192 context, updated training recipe (2024) 149M / 395M 3x faster inference than BERT-Base

When to Use BERT

Classification, NER, extractive QA, sentence similarity — tasks that need full bidirectional context and don't require generation.

When NOT to Use BERT

Text generation (use GPT), very long documents without chunking (use Longformer / BigBird), real-time mobile inference (use DistilBERT or TinyBERT).

Domain-Specific BERT

SciBERT (scientific), BioBERT (biomedical), ClinicalBERT, LegalBERT, FinBERT — pre-training on in-domain text significantly outperforms general BERT.

6. What Does BERT Actually Learn?

Probing studies have analyzed BERT's internal representations layer by layer. The picture that emerges: lower layers encode surface features (capitalization, word morphology), middle layers encode syntax (POS, dependency parses), upper layers encode semantics and coreference. 

# Extract all layer hidden states for a sentence
from transformers import AutoModel

encoder = AutoModel.from_pretrained('bert-base-uncased', output_hidden_states=True)

text     = "The bank can guarantee deposits will eventually cover losses."
tokens   = tokenizer(text, return_tensors='pt')

with torch.no_grad():
    outputs = encoder(**tokens)

# outputs.hidden_states: tuple of (num_layers+1) tensors, each [1, seq, 768]
hidden_states = outputs.hidden_states   # 13 tensors: embedding + 12 layers

# CLS representation per layer (often used as sentence embedding)
cls_per_layer = [h[0, 0, :] for h in hidden_states]

# Token representation at layer 8 (often best for NER)
layer_8_tokens = hidden_states[8][0]   # [seq_len, 768]
print(f"Layer 8 token representations: {layer_8_tokens.shape}")
Sentence Embeddings from BERT The [CLS] token is often used as a fixed sentence embedding, but research shows it performs poorly on semantic similarity tasks without fine-tuning. Sentence-BERT (SBERT) addresses this by fine-tuning BERT with a siamese network on NLI/STS pairs, producing embeddings that work well with cosine similarity. Use sentence-transformers for retrieval, clustering, and semantic search.

from transformers import AutoTokenizer, AutoModelForSequenceClassification
from torch.utils.data import Dataset, DataLoader

class EmailDataset(Dataset):
    def __init__(self, texts, labels, tokenizer, max_len=256):
        self.encodings = tokenizer(
            texts, truncation=True, padding='max_length',
            max_length=max_len, return_tensors='pt'
        )
        self.labels = torch.tensor(labels)

    def __len__(self):
        return len(self.labels)

    def __getitem__(self, idx):
        item = {k: v[idx] for k, v in self.encodings.items()}
        item['labels'] = self.labels[idx]
        return item

Key Takeaways

  • BERT uses masked LM (predict hidden tokens with full bidirectional context) + NSP for pre-training
  • [CLS] aggregates sequence-level representation; [SEP] separates sentence pairs
  • Fine-tuning adds a small head and trains all parameters end-to-end — usually just 2–4 epochs
  • RoBERTa improves on BERT by removing NSP, using dynamic masking, and training longer on more data
  • DistilBERT retains ~97% of BERT's performance at 40% fewer parameters via knowledge distillation
  • BERT's layers encode surface features early and semantic/coreference late — choose extraction layer accordingly
  • For generation tasks, use autoregressive models (GPT family) — BERT is an encoder-only model
