The Encoder-Decoder Architecture

Sequence-to-sequence (seq2seq) models handle tasks where input and output sequences have different lengths (translation, summarization, question answering). The encoder reads the entire input sequence and compresses it into a fixed-length context vector. The decoder then generates the output sequence one token at a time, conditioned on this context.

Seq2Seq Architecture
  Encoder (LSTM/GRU):
  Input:  [w_1, w_2, w_3, w_4, w_5]
  Runs forward through all tokens, produces hidden states h_1 ... h_5
  Final hidden state h_5 = context vector c

  Decoder (LSTM/GRU):
  Initial hidden = c (encoder's final state)
  Step 1: input=[BOS], hidden=c  --> output token y_1
  Step 2: input=y_1, hidden=h'_1 --> output token y_2
  Step 3: input=y_2, hidden=h'_2 --> output token y_3
  Step 4: input=y_3, hidden=h'_3 --> output [EOS] (stop)

  BOS = beginning-of-sequence token
  EOS = end-of-sequence token (generation halts when produced)

Information Bottleneck

The context vector c is a fixed-size vector (e.g., 512 dimensions) that must encode the entire meaning of an arbitrarily long source sentence. For short sentences, this works well. For long, complex sentences, information is inevitably lost. The attention mechanism (next module) was invented specifically to solve this bottleneck by allowing the decoder to query any encoder hidden state at each step.

Teacher Forcing

During training, the decoder receives the ground-truth previous token as input at each step (rather than its own potentially wrong prediction). This is called teacher forcing. It enables much faster training convergence because errors do not compound -- each decoder step gets a correct input signal.

With Teacher Forcing (Training) Decoder input at step t = ground-truth token y_{t-1}. Training is fast and stable. Loss is computed at every step. Risk: exposure bias -- model never sees its own mistakes.
Without Teacher Forcing (Inference) Decoder input at step t = previous predicted token. At inference there is no ground truth to force, so predicted tokens are fed back. Errors from early steps can cascade.
Scheduled Sampling Curriculum strategy: start with high teacher forcing probability, gradually decay to 0. Model learns to handle its own predictions incrementally.
Exposure Bias The mismatch between training (teacher forcing) and inference (own predictions) is called exposure bias. REINFORCE and other RL methods can reduce this gap.

Decoding Strategies

StrategyMethodTradeoff
GreedyAt each step, take argmax of probability distributionFast, but locally optimal choices may miss globally better sequences
Beam Search (k=5)Maintain k best hypotheses at each step, expand all, prune to k bestBetter translations; k=5 is standard for NMT. Computational cost: k x greedy
SamplingDraw from probability distribution at each stepDiverse outputs; risk of incoherent sequences; used for creative text gen
Top-k SamplingSample only from top-k tokens at each step (others set to 0)Balance between diversity and quality. Common in LLMs with k=50
Python -- beam search decoding algorithm
import heapq

def beam_search(model, start_token, eos_token, beam_size=5, max_len=50):
    """Simple beam search for seq2seq decoding."""
    # Beam: list of (neg_log_prob, token_sequence)
    beam = [(0.0, [start_token])]
    completed = []

    for _ in range(max_len):
        candidates = []
        for score, seq in beam:
            if seq[-1] == eos_token:
                completed.append((score, seq))
                continue
            # Get next token log-probabilities from model
            log_probs = model.decode_step(seq)  # (vocab_size,)
            # Expand: add each possible next token
            for token_id in range(len(log_probs)):
                new_score = score - log_probs[token_id]  # accumulate neg log prob
                candidates.append((new_score, seq + [token_id]))

        # Keep only beam_size best hypotheses
        beam = heapq.nsmallest(beam_size, candidates)
        if not beam:
            break

    completed.extend(beam)
    # Return best completed sequence (lowest neg log prob)
    best_score, best_seq = min(completed)
    return best_seq, -best_score   # positive log prob

BLEU Score

Bilingual Evaluation Understudy (BLEU) is the standard metric for evaluating seq2seq output quality (translation, summarization). It measures n-gram overlap between the generated output and reference outputs.

BLEU Score Calculation
  BLEU = BP * exp( SUM_n  w_n * log(precision_n) )

  Where:
    precision_n = fraction of predicted n-grams that appear in any reference
    w_n = weights (typically 0.25 for n=1,2,3,4: BLEU-4)
    BP = brevity penalty (penalizes outputs shorter than reference)

  BLEU-4 range: 0 to 100
    25-30: acceptable machine translation (state of art 2016)
    50-60: very good translation; hard to distinguish from human
    WMT-level systems: BLEU 30-45 depending on language pair

  Limitations:
    - Rewards exact token matches; misses synonyms and paraphrases
    - Does not penalize grammatical errors if words overlap
    - Sacre-BLEU is the standardized implementation to use in papers

Key Takeaways

  • Seq2seq: encoder compresses input into context vector; decoder generates output conditioned on it
  • Information bottleneck: fixed-size context vector cannot faithfully encode very long inputs
  • Teacher forcing feeds ground-truth tokens during training; inference uses own predictions
  • Exposure bias: teacher forcing / inference mismatch; scheduled sampling mitigates it
  • Beam search: maintain k best hypotheses, expand and prune -- better than greedy at cost of k*speed
  • BLEU: n-gram precision with brevity penalty -- standard for translation and summarization evaluation
