Learning Objectives

  • Explain why LSTM introduces a separate cell state and how it enables gradient flow
  • Describe the forget, input, and output gates and their roles in memory management
  • Trace information flow through an LSTM cell step by step
  • Compare GRU to LSTM: fewer parameters with similar performance on most tasks
  • Implement LSTM and GRU in PyTorch and compare training dynamics

Motivation: The Constant Error Carousel

Vanilla RNNs cannot learn long-range dependencies because gradients vanish during backpropagation through many time steps. The LSTM (Long Short-Term Memory, Hochreiter & Schmidhuber 1997) solves this with a "constant error carousel": a cell state c_t that flows through time with only additive modifications, enabling gradients to flow backward without being multiplied by the same W_h matrix at every step.

LSTM Gates

An LSTM cell has two state vectors: h_t (hidden state, same as vanilla RNN) and c_t (cell state, the long-term memory). Three gates control information flow:

LSTM Cell Equations
  Inputs:  x_t (current input), h_{t-1} (previous hidden), c_{t-1} (previous cell)

  Gates (all sigmoid output in [0,1]):
    f_t = sigmoid(W_f * [h_{t-1}, x_t] + b_f)   -- Forget gate
    i_t = sigmoid(W_i * [h_{t-1}, x_t] + b_i)   -- Input gate
    o_t = sigmoid(W_o * [h_{t-1}, x_t] + b_o)   -- Output gate

  Candidate cell update (tanh in [-1,1]):
    g_t = tanh(W_g * [h_{t-1}, x_t] + b_g)

  Cell state update (additive -- key to solving vanishing gradient):
    c_t = f_t * c_{t-1}  +  i_t * g_t

  Hidden state (what we pass to next layer and use for prediction):
    h_t = o_t * tanh(c_t)
Forget Gate (f_t) Decides what to erase from the cell state. f_t close to 0 = forget; close to 1 = keep. "What from long-term memory should be discarded given current input?"
Input Gate (i_t) Decides how much of the new candidate g_t to write into cell state. i_t close to 0 = do not write; close to 1 = write fully. Controls what to memorize.
Candidate g_t What we would write to cell state if the input gate fully opened. Computed from current input and previous hidden state via tanh.
Output Gate (o_t) Decides what portion of the cell state to expose as the hidden state h_t. Controls what current information is relevant for predicting the next token.

Why the Cell State Solves Vanishing Gradients

The cell state update c_t = f_t * c_{t-1} + i_t * g_t is additive (not multiplicative with W). When gradients flow backward through this operation, they encounter f_t (a learned value close to 1 for important memories) rather than repeated matrix multiplication. The gradient highway through c avoids the eigenvalue decay problem of vanilla RNNs. This is analogous to ResNet's skip connections solving the same problem for spatial depth.

GRU: Gated Recurrent Unit

The GRU (Cho et al., 2014) simplifies the LSTM by merging the cell and hidden state into a single h_t vector and reducing to two gates. It achieves similar performance on most tasks with fewer parameters and faster training.

GRU Equations
  z_t = sigmoid(W_z * [h_{t-1}, x_t])   -- Update gate (like combined forget+input)
  r_t = sigmoid(W_r * [h_{t-1}, x_t])   -- Reset gate

  Candidate hidden state:
    h_tilde = tanh(W * [r_t * h_{t-1}, x_t])

  New hidden state (interpolation):
    h_t = (1 - z_t) * h_{t-1}  +  z_t * h_tilde

  -- When z_t = 0: keep old state (forget new input)
  -- When z_t = 1: replace with candidate (forget old state)
FeatureLSTMGRU
Statesh_t and c_t (two vectors)h_t only (one vector)
Gates3 gates (forget, input, output)2 gates (update, reset)
Parameters4 * hidden_size * (input + hidden + 1)3 * hidden_size * (input + hidden + 1)
PerformanceSlightly better on very long sequencesComparable; sometimes better with less data
SpeedSlower (more operations)~25% faster per step

PyTorch LSTM Implementation

PyTorch -- LSTM cell forward pass from scratch
class LSTMCell(nn.Module):
    def __init__(self, input_size, hidden_size):
        super().__init__()
        # All 4 gate matrices in one linear layer for efficiency
        self.linear = nn.Linear(input_size + hidden_size, 4 * hidden_size)
        self.hidden_size = hidden_size

    def forward(self, x, h_prev, c_prev):
        # Concatenate input and previous hidden state
        combined = torch.cat([x, h_prev], dim=1)
        gates = self.linear(combined)   # (batch, 4*hidden)

        # Split into 4 gates
        f, i, g, o = gates.chunk(4, dim=1)

        f = torch.sigmoid(f)   # forget gate
        i = torch.sigmoid(i)   # input gate
        g = torch.tanh(g)      # candidate cell
        o = torch.sigmoid(o)   # output gate

        c_t = f * c_prev + i * g
        h_t = o * torch.tanh(c_t)
        return h_t, c_t

# Use PyTorch's built-in (much faster -- uses cuDNN LSTM kernel on GPU):
lstm = nn.LSTM(input_size=128, hidden_size=256, num_layers=2,
               batch_first=True, dropout=0.3, bidirectional=True)
x = torch.randn(32, 50, 128)   # (batch, seq, input)
out, (h_n, c_n) = lstm(x)
print(out.shape)  # torch.Size([32, 50, 512])  -- 256*2 bidirectional
print(h_n.shape)  # torch.Size([4, 32, 256])   -- 2 layers * 2 directions

Practice Problems

  1. Trace through one LSTM step manually: x_t = [1, 0], h_{t-1} = [0, 0], c_{t-1} = [0, 0]. If the forget gate outputs [0.9, 0.1], input gate [0.7, 0.8], candidate g [0.5, -0.3], and output gate [0.6, 0.4], what are h_t and c_t?
  2. Count the total number of parameters in a two-layer bidirectional LSTM with input_size=256 and hidden_size=512. Show your calculation.
  3. A GRU and LSTM are both trained on the same machine translation task. The GRU achieves BLEU=32.1 and the LSTM achieves BLEU=32.4. Is the LSTM's slight advantage worth its 25% parameter overhead? Discuss when you would prefer each.
  4. Explain what the reset gate in a GRU does conceptually. What would happen if r_t = 0 for all steps? What if r_t = 1 always?

Key Takeaways

  • LSTM introduces a cell state c_t with additive updates: c_t = f*c_{t-1} + i*g -- gradient highway
  • Forget gate (sigmoid): what to erase; Input gate: what to write; Output gate: what to expose
  • Cell state update is additive, not multiplicative with W -- this prevents vanishing gradients
  • GRU merges cell and hidden state, uses 2 gates -- ~25% fewer parameters, similar performance
  • GRU is preferred when data is limited or training speed matters; LSTM for very long sequences
  • In practice, Transformers have replaced both for most tasks due to parallelism and better scaling
