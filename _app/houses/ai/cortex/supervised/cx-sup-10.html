Encoding Categorical Features

Machine learning algorithms operate on numbers. Categorical features must be converted before training. The choice of encoding affects model performance and can introduce unintended ordinal relationships.

One-Hot Encoding Creates a binary column for each category. No ordinal relationship implied. Required for linear models and SVMs. Danger: high-cardinality features create thousands of columns.
Ordinal Encoding Maps categories to integers (0, 1, 2...). Only valid when a natural order exists (e.g., low/medium/high). Using this for nominal categories implies false ordering.
Target Encoding Replace category with mean target value in that group. Powerful for high-cardinality features. Risk of leakage -- must be computed within CV folds only.
Binary Encoding Encode category as binary digits -- fewer columns than OHE for high cardinality. Intermediate between OHE and ordinal. Used when both cardinality is high and OHE is too wide.

Target Encoding Leakage

If you compute target encoding using the full training set and then cross-validate, your CV folds see statistics computed with their own labels. Always compute target encoding within each fold using only the training portion of that fold.

Feature Scaling

Many algorithms (SVMs, k-NN, neural networks, gradient descent-based models) are sensitive to feature scale. Features with large magnitudes dominate those with small magnitudes in distance computations and gradient updates.

MethodFormulaWhen to Use
StandardScalerx' = (x - μ) / σDefault choice; zero mean, unit variance. Assumes approximately Gaussian
MinMaxScalerx' = (x - min) / (max - min)Bounded output [0,1]. Sensitive to outliers. Use when bounded range required
RobustScalerx' = (x - median) / IQRResistant to outliers. Good for data with many outliers or skewed distributions
No scalingx' = xTree-based models (Decision Tree, Random Forest, XGBoost) are scale-invariant

Handling Missing Values

Missing data is the norm in real-world datasets. The strategy depends on why data is missing and what fraction is missing.

Python -- Imputation Strategies
from sklearn.impute import SimpleImputer, KNNImputer
import pandas as pd
import numpy as np

# Inspect missingness pattern first
missing_pct = df.isnull().mean() * 100
print(missing_pct[missing_pct > 0])

# Mean imputation: simple but distorts distribution
mean_imputer = SimpleImputer(strategy='mean')

# Median imputation: robust to outliers
median_imputer = SimpleImputer(strategy='median')

# KNN imputation: uses similar examples to fill gaps
# Better than mean/median but computationally expensive
knn_imputer = KNNImputer(n_neighbors=5)

# Add missingness indicator: sometimes "was missing" is itself informative
df['age_was_missing'] = df['age'].isnull().astype(int)

Feature Selection

Irrelevant features add noise without information. Removing them improves generalization, reduces training time, and can make models more interpretable.

MethodApproachPros / Cons
Filter methodsRank features by statistical score (correlation, mutual information, chi-squared) independent of any modelFast, model-agnostic; ignores feature interactions
Wrapper methodsEvaluate subsets of features by training a model (RFE, forward/backward selection)Finds interactions; slow, risk of overfitting to training set
Embedded methodsFeature selection built into the model (Lasso L1, Random Forest importance, gradient boosting)Efficient; model-specific, not always transferable
Python -- Complete Feature Engineering Pipeline
from sklearn.pipeline import Pipeline
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.impute import SimpleImputer
from sklearn.feature_selection import SelectFromModel
from sklearn.ensemble import RandomForestClassifier

numeric_features  = ['age', 'income', 'tenure']
category_features = ['country', 'plan']

# Separate preprocessing for numeric and categorical columns
numeric_transformer = Pipeline([
    ('imputer', SimpleImputer(strategy='median')),
    ('scaler',  StandardScaler())
])
category_transformer = Pipeline([
    ('imputer', SimpleImputer(strategy='most_frequent')),
    ('ohe',     OneHotEncoder(handle_unknown='ignore', sparse_output=False))
])

preprocessor = ColumnTransformer([
    ('num', numeric_transformer,  numeric_features),
    ('cat', category_transformer, category_features),
])

# Full pipeline: preprocess -> select features -> classify
full_pipeline = Pipeline([
    ('preprocess', preprocessor),
    ('select',     SelectFromModel(RandomForestClassifier(n_estimators=50))),
    ('clf',        RandomForestClassifier(n_estimators=200))
])

full_pipeline.fit(X_train, y_train)
# Pipeline ensures all transformations are fit on train data only
# and correctly applied to test data -- no leakage possible

Preprocessing Leakage -- The Biggest Mistake

Computing StandardScaler statistics on the full dataset (including the test set) leaks test distribution information into training. Always use sklearn Pipelines to guarantee that scalers, imputers, and encoders are fit on training data only and then applied to test data. This is non-negotiable for valid evaluation.

Key Takeaways

  • One-hot encoding for nominal categories; ordinal encoding only when true order exists
  • StandardScaler for most algorithms; RobustScaler for data with outliers; no scaling needed for tree-based models
  • Always add missingness indicators when "was missing" may itself be informative
  • Filter methods are fast but miss interactions; wrapper methods are thorough but expensive; embedded methods are the practical sweet spot
  • sklearn Pipelines prevent preprocessing leakage -- they should be your standard for all ML work
  • Feature engineering often matters more than algorithm choice -- garbage in, garbage out
