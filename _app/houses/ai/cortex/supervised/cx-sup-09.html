The Confusion Matrix

Every classification result falls into one of four categories. The confusion matrix organizes these to reveal where your model succeeds and fails:

TP
True Positive
Predicted +, Actually +
FP
False Positive
Predicted +, Actually -
FN
False Negative
Predicted -, Actually +
TN
True Negative
Predicted -, Actually -

For a security use case: TP = detected real attack, FP = false alarm (wasted analyst time), FN = missed attack (dangerous), TN = correctly ignored benign traffic. The relative cost of FP vs FN determines which metrics matter most.

Precision, Recall, and F1

Precision = TP / (TP + FP)    "Of all predicted positives, how many were actually positive?"
Recall = TP / (TP + FN)    "Of all actual positives, how many did we catch?"
F1 = 2 · (Precision · Recall) / (Precision + Recall)
F1 is the harmonic mean -- punishes large differences between P and R

Accuracy Is Misleading for Imbalanced Data

A fraud detection model that predicts "not fraud" for every transaction achieves 99.9% accuracy if fraud rate is 0.1%. Precision, recall, and F1 on the minority class are the meaningful metrics. Always check class distribution before reporting accuracy.

ScenarioPrioritizeReason
Cancer screeningRecall (sensitivity)Missed cancer (FN) is catastrophic; false alarms are tolerable
Spam filterPrecisionBlocking real email (FP) is worse than missing some spam (FN)
Intrusion detectionF1 or RecallMissing an attack (FN) is the primary cost; balance with FP burden
Search rankingPrecision@kTop results must be relevant; recall less important for user experience

ROC Curve and AUC

The Receiver Operating Characteristic (ROC) curve plots True Positive Rate (recall) vs False Positive Rate at every possible decision threshold. AUC (Area Under the Curve) summarizes the curve in one number from 0.5 (random) to 1.0 (perfect).

TPR = TP / (TP + FN)    FPR = FP / (FP + TN)
AUC = probability that model ranks a random positive higher than a random negative
Python -- Complete Evaluation Suite
from sklearn.metrics import (
    confusion_matrix, classification_report,
    roc_auc_score, roc_curve,
    precision_recall_curve, average_precision_score
)

# Get probability scores (not just hard labels)
y_prob = model.predict_proba(X_test)[:, 1]
y_pred = model.predict(X_test)

# Confusion matrix
cm = confusion_matrix(y_test, y_pred)
print(f"TP={cm[1,1]} FP={cm[0,1]} FN={cm[1,0]} TN={cm[0,0]}")

# Per-class precision, recall, F1
print(classification_report(y_test, y_pred))

# ROC-AUC (threshold-independent)
auc = roc_auc_score(y_test, y_prob)
print(f"ROC-AUC: {auc:.4f}")

# PR-AUC (better for imbalanced problems)
pr_auc = average_precision_score(y_test, y_prob)
print(f"PR-AUC: {pr_auc:.4f}")

ROC-AUC vs PR-AUC for Imbalanced Data

ROC-AUC can be misleadingly optimistic when positive class is rare (e.g., fraud at 0.1%). A model can achieve 0.99 ROC-AUC while performing poorly on the minority class. PR-AUC (Precision-Recall AUC) is more informative when the positive class is rare and your care about detecting it.

Cross-Validation

A single train/val split can give a noisy estimate of performance depending on which examples end up in each split. K-fold cross-validation addresses this by evaluating the model k times, each time using a different fold as the validation set:

Python -- Stratified K-Fold Cross-Validation
from sklearn.model_selection import StratifiedKFold, cross_validate

# Stratified: each fold has same class distribution as full dataset
# Essential for imbalanced classification
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)

results = cross_validate(
    model, X, y,
    cv=cv,
    scoring={
        'accuracy': 'accuracy',
        'f1':       'f1',
        'roc_auc':  'roc_auc'
    },
    return_train_score=True  # detect overfitting via train-val gap
)

import numpy as np
for metric in ['test_accuracy', 'test_f1', 'test_roc_auc']:
    scores = results[metric]
    print(f"{metric}: {scores.mean():.4f} +/- {scores.std():.4f}")

Key Takeaways

  • Confusion matrix: TP, FP, FN, TN -- always inspect before reporting a single number
  • Precision = how many positives you called were right; Recall = how many positives you caught
  • F1 = harmonic mean of precision and recall; use when both matter equally
  • Accuracy is misleading for imbalanced data -- always check class distribution first
  • ROC-AUC is threshold-independent and interpretable; PR-AUC is better when positive class is rare
  • Stratified k-fold cross-validation provides reliable, low-variance performance estimates
