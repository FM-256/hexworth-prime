What Is Supervised Learning?

Supervised learning is the most common paradigm in machine learning. The key ingredient is labeled data -- a dataset where every input example is paired with the correct output. The algorithm's job is to learn a mapping from inputs to outputs that generalizes to examples it has never seen.

Formally, given a training set {(x1, y1), ..., (xn, yn)}, we want to find a function f such that f(x) ≈ y for new inputs x. The function f is called the hypothesis or model.

Regression Predict a continuous value. Examples: house price prediction, stock returns, temperature forecasting. Output is a real number.
Classification Predict a discrete class label. Examples: spam vs not-spam, disease diagnosis, digit recognition. Output is a category.
Binary Classification Two possible output classes (positive/negative). The simplest classification setting -- many algorithms are designed specifically for this case.
Multi-class Classification Three or more classes. Examples: handwritten digit recognition (10 classes), language identification (100+ classes).

Supervised vs Unsupervised vs Reinforcement

  • Supervised: labeled (x, y) pairs -- learn to predict y from x
  • Unsupervised: only x, no labels -- discover structure (clustering, compression)
  • Reinforcement: agent acts in environment, receives reward signal -- learn policy to maximize reward

Feature Vectors and the Hypothesis Space

Each training example is represented as a feature vector x = (x1, x2, ..., xd) where d is the number of features (also called dimensions or attributes). For a house price prediction problem, x might contain: square footage, number of bedrooms, year built, zip code.

The choice of hypothesis class determines which functions f we are willing to consider. A linear model only searches within the space of linear functions. A decision tree searches within piecewise-constant functions. Choosing the right hypothesis class for your problem is a core engineering skill.

Python -- Feature Matrix Structure
import numpy as np
from sklearn.datasets import load_boston

# Each row is one training example, each column one feature
X = np.array([
    [1400, 3, 1985, 94103],   # house 1: sqft, beds, year, zip
    [2200, 4, 2001, 94107],   # house 2
    [980,  2, 1972, 94110],   # house 3
])
y = np.array([750000, 1100000, 620000])  # target: sale price

print(f"X shape: {X.shape}")   # (n_samples, n_features)
print(f"y shape: {y.shape}")   # (n_samples,)

Train / Validation / Test Split

You cannot evaluate a model on the same data it was trained on -- the model has memorized those examples. Instead, you hold out data it has never seen:

SplitTypical SizePurpose
Training set60-80%Model parameters are fit on this data. The algorithm sees these examples during learning.
Validation set10-20%Hyperparameter tuning and model selection. Used to compare models without contaminating test set.
Test set10-20%Final honest estimate of generalization performance. Touch this only once -- at the end.

Test Set Contamination

If you tune your model based on test set performance -- even indirectly -- your test accuracy is no longer an honest estimate of generalization. This is one of the most common mistakes in ML practice. Use the validation set for all tuning decisions; reserve the test set for a single final evaluation.

Python -- Proper Train/Val/Test Split
from sklearn.model_selection import train_test_split

# First split: carve out test set (hold it away, don't touch)
X_trainval, X_test, y_trainval, y_test = train_test_split(
    X, y, test_size=0.15, random_state=42
)

# Second split: divide remaining into train and validation
X_train, X_val, y_train, y_val = train_test_split(
    X_trainval, y_trainval, test_size=0.18, random_state=42
)
# Result: ~70% train, ~15% val, ~15% test

print(f"Train: {X_train.shape[0]} | Val: {X_val.shape[0]} | Test: {X_test.shape[0]}")

The Bias-Variance Tradeoff

The generalization error of any supervised learning algorithm can be decomposed into three terms:

Expected Error = Bias2 + Variance + Irreducible Noise
Bias-variance decomposition

Bias is the error from incorrect assumptions in the learning algorithm. A model with high bias is too simple -- it systematically misses the true pattern. This is called underfitting.

Variance is the error from sensitivity to small fluctuations in the training set. A model with high variance is too complex -- it fits the training data perfectly but fails on new examples. This is called overfitting.

Irreducible noise is the inherent randomness in the data that no model can eliminate.

SymptomCauseFix
High training error, high val error Underfitting (high bias) Use a more complex model, add features, reduce regularization
Low training error, high val error Overfitting (high variance) Get more data, increase regularization, simplify model
High training error, low val error Data leakage or data mismatch Check preprocessing pipeline for leakage; verify splits
Python -- Diagnosing Bias vs Variance with Learning Curves
from sklearn.model_selection import learning_curve
import numpy as np

# train_sizes: how many training examples to use at each point
train_sizes, train_scores, val_scores = learning_curve(
    model, X_train, y_train,
    train_sizes=np.linspace(0.1, 1.0, 10),
    cv=5, scoring='neg_mean_squared_error'
)

train_mean = -train_scores.mean(axis=1)
val_mean   = -val_scores.mean(axis=1)

# If gap between train_mean and val_mean is large: high variance (overfitting)
# If both are high: high bias (underfitting)

Choosing an Algorithm

No single algorithm works best for all problems. The "no free lunch" theorem guarantees this. As a starting framework:

ScenarioStart WithNotes
Regression, n < 10kLinear / Ridge RegressionFast, interpretable, strong baseline
Classification, n < 10kLogistic RegressionCalibrated probabilities, interpretable coefficients
Tabular data, any sizeRandom Forest / XGBoostHandles mixed features, robust to scaling
Text, images, audioNeural NetworksRepresentation learning; needs more data
High-dimensional, small nSVM with RBF kernelEffective in high dimensions with good regularization
Interpretability requiredDecision Tree / LogisticExplainable predictions; important for regulated domains

The Machine Learning Workflow

In practice, supervised learning follows a repeatable cycle. Understanding the full pipeline -- not just model training -- is what separates practitioners from academics:

Python -- Minimal Supervised Learning Pipeline
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score, classification_report

# 1. Define pipeline: preprocessing + model
pipe = Pipeline([
    ('scaler', StandardScaler()),
    ('clf', LogisticRegression(max_iter=1000))
])

# 2. Fit on training data only
pipe.fit(X_train, y_train)

# 3. Evaluate on validation set during development
val_preds = pipe.predict(X_val)
print(classification_report(y_val, val_preds))

# 4. Final evaluation on test set -- once, at the very end
test_acc = accuracy_score(y_test, pipe.predict(X_test))
print(f"Test accuracy: {test_acc:.4f}")

Key Takeaways

  • Supervised learning uses labeled (x, y) pairs to learn a function f that generalizes to new inputs
  • Regression predicts continuous values; classification predicts discrete class labels
  • Always split data into train / validation / test -- never evaluate final performance on data used for tuning
  • Bias = error from overly simple assumptions (underfitting); variance = error from over-sensitivity to training data (overfitting)
  • Learning curves reveal whether you have a bias or variance problem -- diagnose before prescribing a fix
  • The no free lunch theorem means algorithm choice matters -- understand your data before selecting a model family
