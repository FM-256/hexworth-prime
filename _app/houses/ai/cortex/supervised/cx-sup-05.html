From Single Trees to Ensembles

Single decision trees have high variance: small changes in training data produce very different trees. The solution is to train many trees and aggregate their predictions. This is the core idea of ensemble methods.

Random Forest is a bagging ensemble of decision trees with an additional randomization at the feature level. The key insight: if we train many diverse models and average their predictions, the errors cancel out while the signal reinforces.

Var(mean of n i.i.d. vars) = σ2/n → 0 as n → ∞
Averaging n uncorrelated predictions reduces variance by factor n

Bootstrap Aggregation (Bagging)

Each tree in the forest is trained on a bootstrap sample -- a random sample of the training data drawn with replacement. A bootstrap sample of size m from a dataset of size m will contain approximately 63.2% unique examples (the rest are duplicates). The remaining ~36.8% are called the out-of-bag (OOB) samples for that tree.

Averaging predictions from trees trained on different bootstrap samples reduces variance because the trees are not perfectly correlated. The more diverse (less correlated) the trees, the greater the variance reduction.

Feature Randomness: The Forest Part

In addition to row-level sampling (bagging), Random Forest introduces column-level sampling: at each split, only a random subset of features is considered. Typical defaults:

TaskDefault max_featuresEffect
Classificationsqrt(d)Each split considers square root of total features
Regressiond/3Each split considers one-third of total features
Bagged Treesd (all features)No feature sampling; less diversity, higher correlation

Why Feature Subsampling Helps

Without it, all trees would use the dominant strong feature at the root, making them highly correlated. Forcing trees to use different feature subsets decorrelates them, increasing the benefit of averaging.

Python -- Random Forest Training and Tuning
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import RandomizedSearchCV
import numpy as np

rf = RandomForestClassifier(
    n_estimators=200,       # more trees = more stable, diminishing returns after ~200
    max_features='sqrt',    # consider sqrt(d) features at each split
    max_depth=None,          # grow full trees; bagging controls variance
    min_samples_leaf=1,
    bootstrap=True,          # use bootstrap sampling
    oob_score=True,          # enable out-of-bag error estimation
    n_jobs=-1,               # use all CPU cores
    random_state=42
)
rf.fit(X_train, y_train)
print(f"OOB accuracy: {rf.oob_score_:.4f}")  # free cross-validation estimate

Feature Importance

Random Forest provides two types of feature importance:

Mean Decrease in Impurity (MDI) Average total reduction in impurity attributed to each feature across all trees. Fast to compute (already computed during training) but biased toward high-cardinality features.
Permutation Importance Randomly shuffle one feature's values, measure accuracy drop. Less biased, more reliable, but slower. Available via sklearn's permutation_importance(). Preferred for production use.
Python -- Feature Importance Analysis
import pandas as pd
from sklearn.inspection import permutation_importance

# MDI importance (fast, built-in)
mdi_importance = pd.Series(
    rf.feature_importances_,
    index=feature_names
).sort_values(ascending=False)

# Permutation importance (slower, less biased)
perm = permutation_importance(rf, X_val, y_val, n_repeats=10, random_state=42)
perm_importance = pd.Series(
    perm.importances_mean,
    index=feature_names
).sort_values(ascending=False)

print(perm_importance.head(10))

Out-of-Bag Error

Each training example is OOB (not in the bootstrap sample) for approximately 37% of the trees. We can predict each training example using only the trees for which it was OOB -- this gives a nearly unbiased generalization estimate without a separate validation set.

OOB error is especially useful when data is scarce. It is equivalent to a leave-one-out cross-validation but computed at essentially no extra cost during training.

OOB Is Not a Substitute for Test Sets

OOB error estimates generalization but still uses the same dataset for both training and evaluation. Reserve a true held-out test set for final performance reporting, especially when comparing models.

Key Takeaways

  • Random Forest = bagging (bootstrap samples) + feature subsampling at each split
  • Averaging diverse trees reduces variance without increasing bias -- the key insight of ensemble methods
  • max_features=sqrt(d) decorrelates trees; lower values = more diversity but higher individual tree bias
  • OOB score provides a free, nearly unbiased generalization estimate -- use it when validation data is scarce
  • MDI importance is fast but biased toward high-cardinality features; permutation importance is more reliable
  • n_estimators: 200-500 trees is usually sufficient; OOB score stabilizes as you add more trees
