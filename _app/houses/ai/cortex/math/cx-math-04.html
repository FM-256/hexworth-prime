Multivariable Calculus

Real ML models live in parameter spaces with millions of dimensions. The Jacobian and Hessian extend calculus to those high-dimensional landscapes — revealing curvature, critical points, and optimization geometry.

From Gradient to Jacobian

The gradient generalizes the derivative to functions with multiple inputs and one output: f: ℝⁿ → ℝ. The Jacobian generalizes further to functions with multiple outputs: f: ℝⁿ → ℝᵐ.

Jacobian matrix — definition For f : ℝⁿ → ℝᵐ, where f(x) = [f₁(x), f₂(x), ..., fₘ(x)]ᵀ J(x) = ∂f/∂x = [ ∂f₁/∂x₁ ∂f₁/∂x₂ ... ∂f₁/∂xₙ ] [ ∂f₂/∂x₁ ∂f₂/∂x₂ ... ∂f₂/∂xₙ ] [ ⋮ ⋮ ⋮ ] [ ∂fₘ/∂x₁ ∂fₘ/∂x₂ ... ∂fₘ/∂xₙ ] Shape: J ∈ ℝᵐˣⁿ (m outputs × n inputs)

Special cases you already know:

  • When m=1: Jacobian reduces to the gradient (row vector)
  • When m=n and f is a coordinate transformation: Jacobian determinant gives the volume scaling factor
  • When f is linear (f(x) = Ax): Jacobian = A everywhere

Jacobian in Backpropagation

Each layer of a neural network maps an input vector to an output vector. The chain rule in backpropagation multiplies Jacobians together as you propagate gradients backward.

Backprop as Jacobian product Network: x → z₁ = f₁(x) → z₂ = f₂(z₁) → ... → L By chain rule: dL/dx = (dL/dzₖ) · (dzₖ/dzₖ₋₁) · ... · (dz₁/dx) = ∇L · Jₖ · Jₖ₋₁ · ... · J₁ Each Jᵢ is the Jacobian of layer i. For fully-connected layers: J = W (the weight matrix).
Why batch norm has a non-trivial Jacobian
Batch normalization normalizes across the batch dimension. This means each output depends on ALL inputs in the batch — the Jacobian is dense rather than diagonal. Computing it naively is O(n²) per layer. Frameworks handle this efficiently using the closed-form batch norm backward pass.

The Hessian Matrix

The Hessian is the matrix of second partial derivatives. It captures curvature — how the gradient itself changes as you move through parameter space.

Hessian matrix — definition For f : ℝⁿ → ℝ: H[i,j] = ∂²f / (∂wᵢ ∂wⱼ) H(w) = [ ∂²f/∂w₁² ∂²f/∂w₁∂w₂ ... ∂²f/∂w₁∂wₙ ] [ ∂²f/∂w₂∂w₁ ∂²f/∂w₂² ... ∂²f/∂w₂∂wₙ ] [ ⋮ ⋮ ⋮ ] [ ∂²f/∂wₙ∂w₁ ∂²f/∂wₙ∂w₂ ... ∂²f/∂wₙ² ] Shape: H ∈ ℝⁿˣⁿ (symmetric: H[i,j] = H[j,i])

The Hessian is always symmetric because mixed partials commute: ∂²f/∂wᵢ∂wⱼ = ∂²f/∂wⱼ∂wᵢ (under mild smoothness conditions — Clairaut's theorem).

Critical Point Classification

At a critical point where ∇f(w) = 0, the Hessian tells you the nature of that point:

Hessian HCritical point typeAll eigenvalues...
Positive definiteLocal minimumPositive (λᵢ > 0 for all i)
Negative definiteLocal maximumNegative (λᵢ < 0 for all i)
IndefiniteSaddle pointMixed signs
Positive semi-definiteDegenerate (inconclusive)Non-negative, some zero
In high dimensions, almost everything is a saddle
For a 1M-parameter model, a true local minimum requires all 1M eigenvalues to be positive. This is exponentially unlikely. Research (Dauphin et al., 2014) showed that in deep networks, critical points are overwhelmingly saddle points, not local minima. This is actually fine — SGD with noise escapes saddle points effectively.

Taylor Expansion and Optimization

The Taylor series approximates a smooth function near a point using derivatives. The second-order Taylor expansion is the foundation for Newton's method and many advanced optimizers.

Second-order Taylor expansion f(w + δ) ≈ f(w) + ∇f(w)ᵀδ + (1/2)δᵀH(w)δ Where: δ = the step (displacement from current w) ∇f(w)ᵀδ = linear term (first-order, gradient direction) δᵀH(w)δ = quadratic term (second-order, curvature)

To find the optimal step δ* that minimizes this approximation, take the derivative w.r.t. δ and set to zero:

Newton's method optimal step d/dδ [f(w) + ∇fᵀδ + (1/2)δᵀHδ] = ∇f + Hδ = 0 δ* = −H⁻¹ · ∇f(w) Newton update: w ← w − H⁻¹∇f(w) vs. Gradient descent: w ← w − α·∇f(w)

Newton's method uses curvature (H⁻¹) to scale the gradient step — taking larger steps in flat regions and smaller steps in curved regions. This is the intuition behind adaptive optimizers like Adam.

Why we never actually invert the Hessian
For a model with n parameters, H is n×n. Inverting it costs O(n³). For GPT-3 (175B parameters), this is computationally impossible. Adam and other adaptive optimizers approximate H⁻¹ using only per-parameter second moment estimates — O(n) storage vs O(n²) for the full Hessian.

Directional Derivatives

The gradient tells you how f changes along each axis. The directional derivative tells you how f changes along any arbitrary direction.

Directional derivative D_v f(w) = ∇f(w) · v̂ = ||∇f(w)|| · cos(θ) Where v̂ is the unit vector in direction v, and θ is the angle between ∇f and v. Maximum rate of increase: direction = ∇f(w), D_v f = ||∇f|| Maximum rate of decrease: direction = −∇f(w), D_v f = −||∇f|| Zero change: perpendicular to ∇f, D_v f = 0

The zero-change direction is especially important: it defines the level set of f — the "contour line" where f is constant. Gradient descent trajectories are always perpendicular to these level sets.

Gradient Flow and Loss Contours

Visualizing 2D loss landscapes (e.g., loss as a function of two weights) reveals why gradient descent can be slow:

Ravines

Elongated contours cause gradient descent to zigzag. Momentum and adaptive methods navigate ravines faster.

Flat regions

Near-zero gradients slow convergence dramatically. Batch norm helps by keeping activations in non-saturating regions.

Sharp minima

High curvature minima often generalize worse. SGD noise tends to find flatter minima that generalize better.

Skip connections

ResNet skip connections smooth the loss landscape dramatically, enabling training of very deep networks.

Constrained Optimization

Many ML problems involve optimization under constraints. Lagrange multipliers convert constrained problems into unconstrained ones.

Lagrange multiplier method Minimize: f(w) Subject to: g(w) = 0 Form the Lagrangian: L(w, λ) = f(w) + λ·g(w) At the optimum: ∇_w L = 0 and ∂L/∂λ = 0 Which gives: ∇f(w) = −λ·∇g(w)

Geometric interpretation: at the constrained optimum, ∇f and ∇g are parallel — the objective function's gradient and the constraint's gradient point in the same direction.

ML applicationObjective f(w)Constraint g(w)

Probabilistic modelsMaximize likelihoodProbabilities sum to 1

Numerical Implementation

The code below computes Jacobians and Hessians numerically, verifies the second-order Taylor expansion, and demonstrates Newton's method vs gradient descent.

Python — Jacobians, Hessians, and Newton's method 
import numpy as np

# ─────────────────────────────────────────────────
# 1. Numerical Jacobian
# ─────────────────────────────────────────────────
def numerical_jacobian(f, x, h=1e-5):
    """
    Compute Jacobian of f: R^n → R^m at point x.
    Uses central differences for accuracy.
    """
    fx = f(x)
    m = len(fx)
    n = len(x)
    J = np.zeros((m, n))
    for j in range(n):
        x_plus = x.copy(); x_plus[j] += h
        x_minus = x.copy(); x_minus[j] -= h
        J[:, j] = (f(x_plus) - f(x_minus)) / (2 * h)
    return J

# Example: f(x) = [x₁², x₁·x₂, x₂³]  at x = [1, 2]
f_vec = lambda x: np.array([x[0]**2, x[0]*x[1], x[1]**3])
x0 = np.array([1.0, 2.0])

J = numerical_jacobian(f_vec, x0)
print("Jacobian at [1, 2]:")
print(J)
# Jacobian at [1, 2]:
# [[2. 0.]    ← ∂(x₁²)/∂x₁=2x₁=2,  ∂(x₁²)/∂x₂=0
#  [2. 1.]    ← ∂(x₁x₂)/∂x₁=x₂=2, ∂(x₁x₂)/∂x₂=x₁=1
#  [0. 12.]]  ← ∂(x₂³)/∂x₁=0,     ∂(x₂³)/∂x₂=3x₂²=12

# ─────────────────────────────────────────────────
# 2. Numerical Hessian
# ─────────────────────────────────────────────────
def numerical_hessian(f, x, h=1e-4):
    """
    Compute Hessian of f: R^n → R at point x.
    Uses central second differences.
    """
    n = len(x)
    H = np.zeros((n, n))
    for i in range(n):
        for j in range(n):
            if i == j:
                # Diagonal: second derivative
                xp = x.copy(); xp[i] += h
                xm = x.copy(); xm[i] -= h
                H[i, j] = (f(xp) - 2*f(x) + f(xm)) / h**2
            else:
                # Off-diagonal: mixed partial
                xpp = x.copy(); xpp[i] += h; xpp[j] += h
                xpm = x.copy(); xpm[i] += h; xpm[j] -= h
                xmp = x.copy(); xmp[i] -= h; xmp[j] += h
                xmm = x.copy(); xmm[i] -= h; xmm[j] -= h
                H[i,j] = (f(xpp) - f(xpm) - f(xmp) + f(xmm)) / (4*h**2)
    return H

# f(x,y) = x² + 2xy + 3y²  (quadratic form)
f_quad = lambda x: x[0]**2 + 2*x[0]*x[1] + 3*x[1]**2

H = numerical_hessian(f_quad, np.array([1.0, 1.0]))
print("\nHessian of x² + 2xy + 3y²:")
print(H)
print(f"Eigenvalues: {np.linalg.eigvalsh(H)}")
# Hessian of x² + 2xy + 3y²:
# [[2. 2.]
#  [2. 6.]]
# Eigenvalues: [1.17  6.83]  → both positive → positive definite → minimum

# ─────────────────────────────────────────────────
# 3. Newton's method vs gradient descent
# ─────────────────────────────────────────────────
def rosenbrock(x):
    """Classic test function: f(x,y) = (1-x)² + 100(y-x²)²
    Global minimum at (1, 1). Very ill-conditioned."""
    return (1 - x[0])**2 + 100 * (x[1] - x[0]**2)**2

def rosenbrock_grad(x):
    dfdx = -2*(1 - x[0]) - 400*x[0]*(x[1] - x[0]**2)
    dfdy = 200*(x[1] - x[0]**2)
    return np.array([dfdx, dfdy])

x_start = np.array([0.0, 0.0])

# Gradient descent
x_gd = x_start.copy()
for i in range(1000):
    x_gd -= 0.001 * rosenbrock_grad(x_gd)

# Newton's method
x_nm = x_start.copy()
for i in range(20):
    grad = rosenbrock_grad(x_nm)
    H = numerical_hessian(rosenbrock, x_nm)
    x_nm -= np.linalg.solve(H, grad)   # H·δ = grad → δ = H⁻¹grad

print(f"\nGD (1000 steps):    x={x_gd}, f={rosenbrock(x_gd):.4f}")
print(f"Newton (20 steps):  x={x_nm}, f={rosenbrock(x_nm):.6f}")
# GD (1000 steps):    x=[0.512 0.258], f=0.2373   (still far from [1,1])
# Newton (20 steps):  x=[1.000 1.000], f=0.000000  (converged)

# ─────────────────────────────────────────────────
# 4. Taylor expansion verification
# ─────────────────────────────────────────────────
w0 = np.array([0.5, 0.5])
delta = np.array([0.1, -0.05])

f_exact = f_quad(w0 + delta)
grad_w0 = np.array([2*w0[0] + 2*w0[1],
                     2*w0[0] + 6*w0[1]])
H_w0 = np.array([[2., 2.], [2., 6.]])

f_taylor2 = (f_quad(w0)
             + grad_w0 @ delta
             + 0.5 * delta @ H_w0 @ delta)

print(f"\nTaylor approximation demo:")
print(f"  Exact:   {f_exact:.6f}")
print(f"  2nd-ord: {f_taylor2:.6f}")
# Taylor approximation demo:
# Exact:   1.267500
# 2nd-ord: 1.267500  (exact for quadratic functions)

The Neural Network Loss Landscape

Understanding the multivariable calculus geometry of neural network loss surfaces is essential for debugging training failures.

PhenomenonMathematical causeRemedy
Exploding gradients Large Hessian eigenvalues (high curvature) cause large gradient norm Gradient clipping, weight initialization, careful learning rate
Vanishing gradients Chain rule products shrink; near-zero Jacobian eigenvalues ReLU activation, residual connections, LayerNorm
Slow convergence Ill-conditioned Hessian (max eigenvalue >> min eigenvalue) Adam adaptive learning rates approximate H⁻¹ scaling
Oscillations in training Learning rate too large relative to max Hessian eigenvalue Learning rate schedule, gradient clipping, warmup
Sharp vs flat minima High-curvature minima have large Hessian trace SGD noise, sharpness-aware minimization (SAM optimizer)
The condition number and learning rates
The condition number κ = λ_max / λ_min of the Hessian determines how ill-conditioned the optimization is. If κ = 1000, the optimal learning rate in the steepest direction is 1000x smaller than in the flattest direction. Adam's per-parameter learning rates automatically adapt to this — effectively approximating κ = 1 in each direction.

Module Takeaways

  • The Jacobian generalizes the gradient to vector-valued functions — each layer in backprop is a Jacobian
  • The Hessian matrix captures curvature — the second derivatives of the loss w.r.t. all pairs of parameters
  • Positive definite Hessian at a critical point means local minimum; indefinite means saddle point
  • Newton's method uses H⁻¹∇f and converges in far fewer steps but requires inverting the Hessian
  • Adaptive optimizers (Adam) approximate H⁻¹ efficiently using per-parameter second moments
  • The condition number of the Hessian explains why gradient descent is slow in ravines
  • In deep networks, almost all critical points are saddle points, not local minima
  • Flat minima (low Hessian trace) generalize better — SAM optimizer explicitly searches for them
