Numerical Computing

The gap between mathematical theory and working code is filled by numerical computing. Floating point arithmetic, numerical stability, vectorization, and memory layout determine whether your implementations are fast, correct, and reproducible.

Floating Point Arithmetic

Computers represent real numbers in finite precision. IEEE 754 is the standard, and understanding it prevents entire classes of subtle bugs in ML code.

IEEE 754 float64 structure 64 bits: 1 sign | 11 exponent | 52 mantissa Value = (−1)^sign × 2^(exponent−1023) × (1 + mantissa/2^52) Range: ±5×10⁻³²⁴ to ±1.8×10³⁰⁸ Precision: ~15-16 significant decimal digits Machine epsilon: ε_mach ≈ 2.2×10⁻¹⁶ (smallest number such that 1.0 + ε_mach ≠ 1.0) float32: 6-7 digits precision, ε_mach ≈ 1.2×10⁻⁷ bfloat16: 3 digits precision — used in TPU/GPU training
Catastrophic cancellation
Subtracting two nearly equal large numbers destroys precision: (1 + ε) − 1 = ε might give 0. In ML: computing variance as E[X²] − E[X]² can lose all precision when E[X] is large. Use numerically stable formulations — Welford's online algorithm for variance, log-space for probabilities.

Numerical Stability Techniques

Log-Sum-Exp Trick

Computing log(Σ exp(xᵢ)) naively overflows for large xᵢ. The log-sum-exp trick shifts to the maximum first:

Log-sum-exp (numerically stable) Naive: log(Σᵢ exp(xᵢ)) ← exp(1000) = Inf Stable: m = max(xᵢ) log(Σᵢ exp(xᵢ)) = m + log(Σᵢ exp(xᵢ − m)) Why it works: xᵢ − m ≤ 0 for all i, so exp(xᵢ − m) ∈ (0, 1]. No overflow possible. At least one term equals exp(0) = 1. Stable softmax: p_k = exp(x_k − m) / Σ exp(xᵢ − m)

Numerically Stable Cross-Entropy

Stable binary cross-entropy Naive: L = −y·log(σ(z)) − (1−y)·log(1−σ(z)) (log(0) = −Inf when σ(z)→0 or σ(z)→1) Stable: Use log-sigmoid directly: log(σ(z)) = z − log(1 + eᶻ) = −log(1 + e^(−z)) log(1−σ(z)) = −log(1 + eᶻ) = log(σ(−z)) Or: L = max(z, 0) − z·y + log(1 + exp(−|z|)) (PyTorch's binary_cross_entropy_with_logits)
Always use "with_logits" variants
PyTorch's F.cross_entropy and F.binary_cross_entropy_with_logits take raw logits (before softmax/sigmoid) and compute the stable version internally. Never apply softmax before the loss function — you lose numerical stability for free. This is a very common bug in new PyTorch code.

Vectorization with NumPy

NumPy operations are implemented in C and use BLAS for matrix operations. A Python loop over 10,000 elements takes milliseconds; the equivalent NumPy operation takes microseconds.

Elementwise ops

np.add, np.exp, np.sqrt, np.maximum operate element-by-element using SIMD CPU instructions.

Reductions

np.sum, np.mean, np.max use optimized tree reductions. Specify axis= to reduce along dimensions.

Matrix ops

np.dot, np.matmul, @ use OpenBLAS or MKL. Orders of magnitude faster than manual loops.

Broadcasting

Implicit array expansion: (1000,10) + (10,) applies the (10,) vector to each row without copying.

Broadcasting Rules

NumPy broadcasting rules Arrays are compatible if for each dimension (aligned from the right): 1. Dimensions are equal, OR 2. One of them is 1 (that dimension is "stretched") Examples: (3, 4) + (4,) → (3, 4) ✓ row added to each row (3, 4) + (3, 1) → (3, 4) ✓ col added to each column (3, 4) + (3,) → ERROR ✗ 3 doesn't broadcast into 4 (3, 1, 4) + (2,4) → (3, 2, 4) ✓ batch dimension expanded Fix for (3,) + (3, 4): use np.expand_dims or reshape(-1, 1)

Memory Layout and Cache Effects

Matrix memory layout determines access patterns and cache efficiency. Row-major (C order) stores rows contiguously; column-major (Fortran order) stores columns.

Row-major vs column-major layout Matrix A (3×3): [ 1 2 3 ] [ 4 5 6 ] [ 7 8 9 ] C order (row-major, NumPy default): Memory: [1, 2, 3, 4, 5, 6, 7, 8, 9] Iterating over rows is cache-friendly. Fortran order (col-major): Memory: [1, 4, 7, 2, 5, 8, 3, 6, 9] Iterating over columns is cache-friendly. Rule: iterate over the last axis (axis=-1) for NumPy speed.
Mixed precision training
Modern GPU training uses float16 or bfloat16 for forward/backward passes (faster, less memory) and float32 for the master copy of weights (for gradient accumulation precision). PyTorch's automatic mixed precision (torch.cuda.amp.autocast) handles this automatically. BF16 is preferred over FP16 for LLM training because it has the same exponent range as FP32 — preventing overflow on large activations.

Python: Numerical Best Practices

Python — floating point, stable implementations, vectorization benchmarks 
import numpy as np
import time

# ─────────────────────────────────────────────────
# 1. Floating point surprises
# ─────────────────────────────────────────────────
print("Floating point surprises:")
print(f"  0.1 + 0.2 == 0.3 : {0.1 + 0.2 == 0.3}")
print(f"  0.1 + 0.2        : {0.1 + 0.2:.20f}")
print(f"  Machine epsilon  : {np.finfo(np.float64).eps:.2e}")
print(f"  float32 eps      : {np.finfo(np.float32).eps:.2e}")
print(f"  np.exp(1000)     : {np.exp(np.float64(1000))}")
print(f"  np.exp(-800)     : {np.exp(np.float64(-800))}")
# Floating point surprises:
#   0.1 + 0.2 == 0.3 : False
#   0.1 + 0.2        : 0.30000000000000004440892...
#   Machine epsilon  : 2.22e-16
#   float32 eps      : 1.19e-07
#   np.exp(1000)     : inf
#   np.exp(-800)     : 0.0

# ─────────────────────────────────────────────────
# 2. Log-sum-exp trick
# ─────────────────────────────────────────────────
def log_sum_exp_naive(x):
    return np.log(np.sum(np.exp(x)))

def log_sum_exp_stable(x):
    m = np.max(x)
    return m + np.log(np.sum(np.exp(x - m)))

def softmax_stable(x):
    m = np.max(x)
    e = np.exp(x - m)
    return e / np.sum(e)

x_large = np.array([1000.0, 1001.0, 1002.0])
x_small = np.array([-1000.0, -999.0, -998.0])

print("\nLog-sum-exp stability:")
print(f"  Naive  (large): {log_sum_exp_naive(x_large)}")
print(f"  Stable (large): {log_sum_exp_stable(x_large):.6f}")
print(f"  Naive  (small): {log_sum_exp_naive(x_small)}")
print(f"  Stable (small): {log_sum_exp_stable(x_small):.6f}")
# Log-sum-exp stability:
#   Naive  (large): inf
#   Stable (large): 1002.407606
#   Naive  (small): -inf
#   Stable (small): -997.592394

# ─────────────────────────────────────────────────
# 3. Vectorization benchmark
# ─────────────────────────────────────────────────
n = 1_000_000
x = np.random.randn(n)
y = np.random.randn(n)

# Python loop
t0 = time.perf_counter()
result_loop = sum(x[i] * y[i] for i in range(n))
t_loop = time.perf_counter() - t0

# NumPy vectorized
t0 = time.perf_counter()
result_np = np.dot(x, y)
t_np = time.perf_counter() - t0

print(f"\nDot product of 1M elements:")
print(f"  Python loop: {t_loop*1000:.1f} ms")
print(f"  NumPy:       {t_np*1000:.2f} ms")
print(f"  Speedup:     {t_loop/t_np:.0f}x")
# Dot product of 1M elements:
#   Python loop: 412.3 ms
#   NumPy:       1.82 ms
#   Speedup:     227x

# ─────────────────────────────────────────────────
# 4. Broadcasting — compute pairwise distances
# ─────────────────────────────────────────────────
def pairwise_distances_loop(A, B):
    """O(n²) Python loops — slow."""
    n, m = len(A), len(B)
    D = np.zeros((n, m))
    for i in range(n):
        for j in range(m):
            D[i, j] = np.sum((A[i] - B[j])**2)
    return D

def pairwise_distances_vec(A, B):
    """Broadcasting: (n,1,d) - (1,m,d) → (n,m,d) → (n,m). Fast."""
    return np.sum((A[:, None, :] - B[None, :, :])**2, axis=-1)

A = np.random.randn(100, 64)
B = np.random.randn(200, 64)

t0 = time.perf_counter(); D1 = pairwise_distances_loop(A, B); t1 = time.perf_counter()
t0b = time.perf_counter(); D2 = pairwise_distances_vec(A, B); t2 = time.perf_counter()

print(f"\nPairwise distances (100×200, dim=64):")
print(f"  Loop:    {(t1-t0)*1000:.1f} ms")
print(f"  Vectorized: {(t2-t0b)*1000:.2f} ms")
print(f"  Max diff: {np.max(np.abs(D1-D2)):.2e}")
# Pairwise distances (100×200, dim=64):
#   Loop:    1523.4 ms
#   Vectorized: 5.21 ms
#   Max diff: 1.14e-12

# ─────────────────────────────────────────────────
# 5. Numerically stable Welford variance
# ─────────────────────────────────────────────────
def welford_variance(data):
    """
    Online algorithm for variance — stable for large/shifted data.
    Knuth Vol 2, eq 4.2.2.9
    """
    n = mean = M2 = 0
    for x in data:
        n += 1
        delta = x - mean
        mean += delta / n
        M2 += delta * (x - mean)
    return mean, M2 / (n - 1) if n > 1 else 0

# Shifted data — naive variance loses precision
data = np.random.randn(10000) + 1e8   # shifted far from zero
_, welford_var = welford_variance(data)
naive_var = np.mean(data**2) - np.mean(data)**2  # E[X²] - E[X]²
numpy_var = np.var(data, ddof=1)                  # numpy's stable implementation

print(f"\nVariance of shifted data (true ≈ 1.0):")
print(f"  Naive E[X²]-E[X]²: {naive_var:.4f}  ← precision loss")
print(f"  Welford:           {welford_var:.6f}")
print(f"  NumPy (stable):    {numpy_var:.6f}")
# Variance of shifted data (true ≈ 1.0):
#   Naive E[X²]-E[X]²: 0.0000  ← precision loss
#   Welford:           1.001183
#   NumPy (stable):    1.001183

Module Takeaways

  • float64 has ~15 decimal digits precision; float32 has ~7; bfloat16 has ~3 (but wider exponent range)
  • Catastrophic cancellation destroys precision when subtracting nearly equal large numbers
  • Log-sum-exp trick: subtract the max before exponentiating — prevents overflow and underflow
  • Always use "with_logits" loss variants in PyTorch — they fuse softmax and loss for numerical stability
  • NumPy vectorization is 100-1000x faster than Python loops — never iterate over array elements
  • Broadcasting allows implicit dimension expansion without memory copies — master the rules
  • Row-major (C order) arrays: iterate over the last axis for cache efficiency
  • Mixed precision (BF16 forward/backward, FP32 master weights) is the standard LLM training recipe
