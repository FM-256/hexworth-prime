Optimization

Training a neural network is fundamentally an optimization problem. Gradient descent, momentum, adaptive learning rates, and learning rate schedules determine whether your model converges — and how fast.

The Optimization Problem

Given a model f(x; w) and a loss function L(w), training solves:

Empirical risk minimization w* = argmin_w L(w) = argmin_w (1/n) Σᵢ ℓ(f(xᵢ; w), yᵢ) First-order optimality condition (necessary): ∇L(w*) = 0 For non-convex losses (neural networks): We settle for approximate critical points, not true minima.

Neural network loss functions are highly non-convex. They have exponentially many saddle points, flat regions ("loss plateaus"), and sharp vs flat local minima. Classical optimization theory provides weak guarantees here, but empirically, gradient-based methods work remarkably well.

Gradient Descent Variants

Three gradient descent regimes Batch GD (full dataset gradient): w ← w − α · (1/n) Σᵢ ∇ℓᵢ(w) + Accurate gradient, − Slow per step, − Memory intensive Stochastic GD (single sample): w ← w − α · ∇ℓ_i(w) (random sample i) + Fast, + Escapes saddle points, − Very noisy gradient Mini-batch SGD (batch of size B): w ← w − α · (1/B) Σᵢ∈batch ∇ℓᵢ(w) + Balances speed and accuracy, + GPU-efficient Standard choice: B = 32, 64, 128, 256
Why SGD noise helps generalization
SGD gradient noise acts as implicit regularization — it prefers flat minima (where many nearby weight configurations give similar loss) over sharp minima (where small perturbations cause large loss increases). Flat minima generalize better because slight distribution shift at test time causes smaller loss changes. This is the Hochreiter-Schmidhuber flatness hypothesis, empirically supported across many architectures.

Momentum

Vanilla SGD can oscillate in ravines and slow down in flat regions. Momentum accumulates a velocity vector in the direction of gradient history.

SGD with Momentum

v ← β·v − α·∇L(w) w ← w + v

β (typically 0.9) controls how much past gradients persist. The velocity v builds up in consistent gradient directions and cancels in oscillating ones. Effective learning rate in the consistent direction: α/(1−β).

Nesterov Accelerated Gradient (NAG)

v ← β·v − α·∇L(w + β·v) w ← w + v

Compute gradient at the "lookahead" position w + β·v rather than current w. More accurate gradient direction. Faster convergence on convex problems. Used as default in many frameworks.

Adaptive Optimizers

Adaptive optimizers maintain per-parameter learning rates, automatically scaling larger steps for infrequent features and smaller steps for frequent ones.

AdaGrad

G ← G + (∇L)² (accumulated squared gradients) w ← w − (α / √(G + ε)) · ∇L

Learning rate shrinks monotonically per parameter. Works well for sparse features (NLP). Problem: learning rate decays to zero, making it unsuitable for non-convex deep learning.

RMSProp

v ← γ·v + (1−γ)·(∇L)² (exponential moving average) w ← w − (α / √(v + ε)) · ∇L

Fixes AdaGrad's decaying rate issue using exponential moving average of squared gradients (γ ≈ 0.99). Proposed by Hinton in a Coursera lecture — never formally published but widely adopted.

Adam (Adaptive Moment Estimation)

m ← β₁·m + (1−β₁)·∇L (1st moment: gradient mean) v ← β₂·v + (1−β₂)·(∇L)² (2nd moment: gradient variance) m̂ = m / (1−β₁ᵗ) (bias correction) v̂ = v / (1−β₂ᵗ) w ← w − α · m̂ / (√v̂ + ε) Defaults: β₁=0.9, β₂=0.999, ε=1e-8, α=3e-4 or 1e-3

Combines momentum (1st moment) and RMSProp (2nd moment) with bias correction for the initial steps when m and v start near zero. Current default for transformer training. AdamW adds decoupled weight decay.

Adam's weight decay bug — use AdamW
Standard Adam with L2 regularization does NOT correctly implement weight decay because the adaptive scaling (÷√v̂) also scales the regularization term, reducing its effect. AdamW (Loshchilov & Hutter, 2019) decouples weight decay: w ← (1−λ)·w − α·m̂/√v̂. Always use AdamW for transformer training.

Learning Rate Schedules

A fixed learning rate is rarely optimal throughout training. Schedules adapt α over time.

ScheduleFormulaWhen to use
Step decay α ← α × γ every k steps CNNs; simple, reliable baseline
Exponential decay α(t) = α₀ · e^(−λt) Smooth decay; similar to step decay
Cosine annealing α(t) = α_min + ½(α₀−α_min)(1 + cos(πt/T)) Standard for transformers and modern CNNs
Linear warmup α(t) = α₀ · t/T_warmup for t < T_warmup Always used before transformer training; prevents early divergence
Warmup + cosine Warmup for T_warm steps, then cosine GPT, BERT, ViT — the standard recipe
Cyclical LR Oscillate between α_min and α_max cyclically Can escape sharp minima; finds flatter regions
Why warmup is essential for transformers
At initialization, Adam's 2nd moment estimate v is near zero. The effective update α/√v is enormous — potentially causing catastrophic weight updates before v stabilizes. Warmup ramps α from near-zero to the target rate over ~1000-4000 steps, giving v time to accumulate meaningful estimates. Without warmup, transformers frequently diverge in the first few hundred steps.

Convergence Theory

Convergence conditions For smooth L-Lipschitz continuous gradients: SGD requires α < 2/L for stability L-smoothness: ||∇f(w) − ∇f(v)|| ≤ L·||w − v|| (gradient doesn't change too fast) Optimal constant LR: α = 1/L Convergence rate comparisons: GD (convex): O(1/t) iterations to ε error GD (strongly convex): O(log 1/ε) — linear convergence SGD (convex): O(1/√t) — slower due to noise Adam (empirical): Much faster in practice despite weaker theory
Generalization gap: train loss vs test loss
Optimization minimizes train loss. But we care about test loss. The gap = test loss − train loss = generalization error. Optimization and generalization are separate concerns. A model can have near-zero train loss (well-optimized) but high test loss (overfit). This is why regularization, data augmentation, and architecture choices matter even after optimization is "solved."

Python: Implementing Optimizers

Python — SGD, momentum, Adam from scratch, + learning rate schedules 
import numpy as np

# ─────────────────────────────────────────────────
# Optimizers from scratch — train on Rosenbrock
# ─────────────────────────────────────────────────
def rosenbrock(w):
    x, y = w[0], w[1]
    return (1 - x)**2 + 100 * (y - x**2)**2

def rosenbrock_grad(w):
    x, y = w[0], w[1]
    dx = -2*(1-x) - 400*x*(y - x**2)
    dy = 200*(y - x**2)
    return np.array([dx, dy])

class SGD:
    def __init__(self, lr=0.001, momentum=0.0):
        self.lr = lr
        self.beta = momentum
        self.v = None

    def step(self, w, grad):
        if self.v is None: self.v = np.zeros_like(w)
        self.v = self.beta * self.v - self.lr * grad
        return w + self.v

class Adam:
    def __init__(self, lr=0.001, beta1=0.9, beta2=0.999, eps=1e-8):
        self.lr = lr; self.b1 = beta1; self.b2 = beta2; self.eps = eps
        self.m = None; self.v = None; self.t = 0

    def step(self, w, grad):
        if self.m is None:
            self.m = np.zeros_like(w)
            self.v = np.zeros_like(w)
        self.t += 1
        self.m = self.b1 * self.m + (1 - self.b1) * grad
        self.v = self.b2 * self.v + (1 - self.b2) * grad**2
        m_hat = self.m / (1 - self.b1**self.t)    # bias correction
        v_hat = self.v / (1 - self.b2**self.t)
        return w - self.lr * m_hat / (np.sqrt(v_hat) + self.eps)

# Compare optimizers on Rosenbrock (global min at [1, 1])
w0 = np.array([0.0, 0.0])
N = 5000

print("Optimizer comparison on Rosenbrock:")
for name, opt in [('SGD (lr=0.001)', SGD(0.001)),
                    ('SGD+mom (0.9)', SGD(0.001, 0.9)),
                    ('Adam (lr=0.01)', Adam(0.01))]:
    w = w0.copy()
    for _ in range(N):
        w = opt.step(w, rosenbrock_grad(w))
    print(f"  {name:20s}: w={w.round(4)}, loss={rosenbrock(w):.6f}")
# Optimizer comparison on Rosenbrock:
#   SGD (lr=0.001)      : w=[0.2847 0.0698], loss=0.512141
#   SGD+mom (0.9)       : w=[0.9981 0.9962], loss=0.000004
#   Adam (lr=0.01)      : w=[1.0000 1.0000], loss=0.000000

# ─────────────────────────────────────────────────
# Learning rate schedules
# ─────────────────────────────────────────────────
def cosine_schedule(step, total_steps, lr_max, lr_min=0):
    return lr_min + 0.5 * (lr_max - lr_min) * (1 + np.cos(np.pi * step / total_steps))

def warmup_cosine_schedule(step, warmup_steps, total_steps, lr_max, lr_min=0):
    if step < warmup_steps:
        return lr_max * step / warmup_steps     # linear warmup
    adjusted = (step - warmup_steps) / (total_steps - warmup_steps)
    return lr_min + 0.5 * (lr_max - lr_min) * (1 + np.cos(np.pi * adjusted))

# Show schedule values
total = 10000
warmup = 1000
steps = [0, 100, 500, 1000, 2500, 5000, 7500, 10000]
print("\nWarmup + Cosine schedule (lr_max=3e-4):")
for s in steps:
    lr = warmup_cosine_schedule(s, warmup, total, 3e-4)
    print(f"  step {s:5d}: lr = {lr:.2e}")
# Warmup + Cosine schedule (lr_max=3e-4):
#   step     0: lr = 0.00e+00
#   step   100: lr = 3.00e-05
#   step   500: lr = 1.50e-04
#   step  1000: lr = 3.00e-04  ← peak (warmup done)
#   step  2500: lr = 2.55e-04
#   step  5000: lr = 1.50e-04
#   step  7500: lr = 4.52e-05
#   step 10000: lr = 0.00e+00  ← fully decayed

# ─────────────────────────────────────────────────
# Gradient clipping — preventing exploding gradients
# ─────────────────────────────────────────────────
def clip_gradients(gradients, max_norm=1.0):
    """
    If ||grad||₂ > max_norm, scale down uniformly.
    Essential for RNNs and transformers.
    """
    total_norm = np.sqrt(sum(np.sum(g**2) for g in gradients))
    clip_coef = max_norm / (max(total_norm, max_norm))
    return [g * clip_coef for g in gradients], total_norm

# Simulate exploding gradient
large_grad = [np.array([100.0, -50.0]), np.array([80.0, 30.0])]
clipped, norm = clip_gradients(large_grad, max_norm=1.0)
print(f"\nGradient clipping (max_norm=1.0):")
print(f"  Original norm: {norm:.2f}")
print(f"  Clipped[0]: {clipped[0].round(4)}")
# Gradient clipping (max_norm=1.0):
#   Original norm: 135.78
#   Clipped[0]: [0.7364 -0.3682]

Diagnosing Optimization Failures

SymptomLikely causeFix
Loss explodes (NaN/Inf) Learning rate too high, exploding gradients Reduce LR 10x, add gradient clipping
Loss doesn't decrease at all LR too low, wrong loss function, vanishing gradients, bug in backprop Gradient check, increase LR, check ReLU vs sigmoid
Loss decreases then plateaus Learning rate too high (oscillating around minimum) Reduce LR, add schedule, add momentum
Train loss low, val loss high Overfitting (high variance) Regularization, dropout, data augmentation, more data
Both train and val loss high Underfitting (high bias) More capacity, fewer regularization constraints, longer training
Loss oscillates with high variance Batch size too small, LR too high Increase batch size, reduce LR proportionally

Module Takeaways

  • Mini-batch SGD is the standard — balances gradient accuracy and GPU efficiency
  • Momentum accumulates velocity, navigating ravines and escaping flat regions
  • Adam combines momentum and adaptive per-parameter learning rates with bias correction
  • Use AdamW (not Adam) for transformers — decoupled weight decay is mathematically correct
  • Linear warmup prevents Adam divergence in the first training steps while v stabilizes
  • Cosine annealing is the standard decay schedule for transformers and modern CNNs
  • Gradient clipping prevents exploding gradients — essential for RNNs, helpful for transformers
  • Diagnose by reading loss curves: NaN=LR too high; plateau=schedule issue; gap=overfit
