Calculus for ML

Derivatives, partial derivatives, the chain rule, and gradients form the engine of machine learning. Every model you train uses these concepts — whether you see them or not.

Learning Objectives

  • Compute partial derivatives of multivariate functions

Why Calculus Powers ML

Machine learning is fundamentally an optimization problem. Given a model with parameters w and a loss function L(w) that measures how wrong the model is, training means finding the values of w that minimize L. Calculus tells us how to do that systematically.

The core question calculus answers: if I nudge parameter w by a tiny amount, how much does the loss change? That answer — the derivative — points you toward better parameters.

Training

Gradient descent updates parameters using derivatives of the loss w.r.t. each weight.

Backpropagation

Chain rule applied repeatedly through a neural network's computational graph.

Activation design

ReLU, sigmoid, and GELU are chosen partly for their derivative properties.

Regularization

L1 and L2 penalties add derivative terms that shrink weights toward zero.

The Derivative

The derivative of a function f(x) at a point x is the slope of the tangent line at that point. Formally, it is defined as a limit:

Definition — derivative f'(x) = df/dx = lim[h→0] [ f(x + h) − f(x) ] / h

Intuitively: if you make a tiny step h in the x direction, how much does f change? The derivative is that ratio as the step shrinks to zero.

Notation

You will see four equivalent notations in ML literature:

Differentiation Rules

You rarely compute limits directly. These rules handle 99% of functions you'll encounter:

Core differentiation rules Power rule: d/dx [xⁿ] = n·xⁿ⁻¹ Constant: d/dx [c] = 0 Constant factor: d/dx [c·f(x)] = c·f'(x) Sum rule: d/dx [f + g] = f'(x) + g'(x) Product rule: d/dx [f·g] = f'·g + f·g' Quotient rule: d/dx [f/g] = (f'·g − f·g') / g² Chain rule: d/dx [f(g(x))] = f'(g(x)) · g'(x)
FunctionDerivativeML relevance
xⁿn·xⁿ⁻¹Polynomial activations, power features

ReLU at zero
ReLU is not differentiable at x=0. In practice, deep learning frameworks set the subgradient to 0 at that point, which works fine because the probability of hitting exactly zero is negligible during training.

The Chain Rule

The chain rule is the most important rule in ML. It allows you to differentiate composite functions — and a neural network is nothing but a very deep composite function.

Chain rule — single variable If y = f(g(x)), then: dy/dx = df/dg · dg/dx = f'(g(x)) · g'(x)

Read this as: "the rate at which y changes w.r.t. x equals the rate at which y changes w.r.t. the intermediate variable g, times the rate at which g changes w.r.t. x."

Chain Rule Through a Neural Network Layer

Consider a single neuron: z = w·x + b, then a = σ(z), then L = (a − y)². To train, we need dL/dw.

Chain rule — neuron example Forward: z = w·x + b a = σ(z) L = (a − y)² Backward (chain rule applied): dL/dw = dL/da · da/dz · dz/dw dL/da = 2(a − y) da/dz = σ(z)·(1 − σ(z)) dz/dw = x dL/dw = 2(a − y) · σ(z)·(1 − σ(z)) · x

Backpropagation in a deep network does exactly this — but across dozens or hundreds of layers, accumulating products of derivatives via the chain rule.

Vanishing gradients
Sigmoid derivatives max out at 0.25. When you multiply 50 of them together via the chain rule, the gradient shrinks to ~10⁻³⁰ — effectively zero. This is the vanishing gradient problem. ReLU avoids it because its derivative is either 0 or 1, preventing gradient collapse.

Partial Derivatives

Most ML loss functions depend on many parameters simultaneously — a model with a million weights. A partial derivative measures how the function changes when you vary one parameter while holding all others constant.

Partial derivative notation For f(x₁, x₂, ..., xₙ): ∂f/∂xᵢ = rate of change of f w.r.t. xᵢ, holding all other xⱼ (j≠i) fixed Example: f(x, y) = x²y + 3y² ∂f/∂x = 2xy (treat y as constant) ∂f/∂y = x² + 6y (treat x as constant)

The notation ∂ (curly d, "del" or "partial") distinguishes partial derivatives from ordinary derivatives.

Partial Derivatives in a Linear Model

Consider mean squared error (MSE) for linear regression with two weights:

MSE loss and its partial derivatives Model: ŷ = w₁·x₁ + w₂·x₂ + b Loss: L = (1/n) Σ (yᵢ − ŷᵢ)² Partials: ∂L/∂w₁ = (−2/n) Σ (yᵢ − ŷᵢ)·x₁ᵢ ∂L/∂w₂ = (−2/n) Σ (yᵢ − ŷᵢ)·x₂ᵢ ∂L/∂b = (−2/n) Σ (yᵢ − ŷᵢ)

These three numbers tell you exactly how to adjust each parameter to reduce the loss. This is gradient descent.

The Gradient Vector

The gradient packages all partial derivatives into a single vector. For a function f(w₁, w₂, ..., wₙ):

Gradient definition ∇f(w) = [ ∂f/∂w₁, ∂f/∂w₂, ..., ∂f/∂wₙ ]ᵀ In matrix calculus (Jacobian row form): ∇f : ℝⁿ → ℝⁿ

The gradient has a crucial geometric property: it always points in the direction of steepest ascent. To minimize a loss function, you move in the direction of the negative gradient.

Gradient descent update rule
w ← w − α · ∇L(w)

Where α (alpha) is the learning rate — the step size along the negative gradient. This single equation is the foundation of all neural network training.

Geometric Interpretation

Gradient direction

The gradient ∇f(w) points toward higher loss. Gradient descent subtracts it to move toward lower loss.

Gradient magnitude

||∇f(w)|| (the norm) tells you how steep the loss landscape is. Large magnitude means steep slope.

Zero gradient

∇f(w) = 0 means you're at a critical point — minimum, maximum, or saddle point.

Directional derivative

The rate of change in any direction v is the dot product: ∇f(w) · v̂ (unit vector v).

Saddle points in deep learning
For high-dimensional models (millions of parameters), true local minima are rare. Most critical points are saddle points — flat in some directions, curved in others. SGD with noise tends to escape saddle points efficiently, which is one reason stochastic methods outperform full-batch gradient descent in practice.

Second Derivatives and Curvature

The second derivative measures how the slope itself is changing — the curvature of the loss surface.

Second derivative f''(x) = d²f/dx² = d/dx [f'(x)] Interpretation: f''(x) > 0 → concave up (bowl shape, local min candidate) f''(x) < 0 → concave down (hill shape, local max candidate) f''(x) = 0 → inflection point (curvature changes sign)

For multivariate functions, the matrix of second partial derivatives is the Hessian (covered in depth in CX-MATH-04):

Hessian matrix — preview H[i,j] = ∂²f / (∂wᵢ ∂wⱼ) A positive definite Hessian → local minimum A negative definite Hessian → local maximum Indefinite Hessian → saddle point
Why learning rates are hard
The optimal learning rate α = 1/λ_max, where λ_max is the largest eigenvalue of the Hessian. If α is too large relative to curvature, gradient descent overshoots and diverges. Computing the Hessian is O(n²) in parameters — infeasible for large nets — which is why adaptive optimizers like Adam estimate curvature implicitly.

Automatic Differentiation

In practice, you never hand-compute gradients for neural networks. Frameworks like PyTorch and TensorFlow use automatic differentiation (autograd) — which applies the chain rule mechanically through a computation graph.

MethodHowWhen used
Symbolic differentiationAlgebraic manipulation of expressionsComputer algebra systems (SymPy, Mathematica)
Numerical differentiationf'(x) ≈ [f(x+h)−f(x−h)] / 2hGradient checking, verification
Automatic differentiationChain rule through computation graphPyTorch, TensorFlow, JAX — all deep learning

Autograd tracks every operation in the forward pass as a graph node. On the backward pass it traverses this graph in reverse, multiplying local Jacobians (chain rule). This is called reverse-mode autodiff — efficient when there are many inputs and few outputs (typical for loss functions).

NumPy + Autograd Examples

The code below demonstrates three approaches: numerical differentiation from scratch, gradient descent on a simple function, and automatic differentiation verification.

Python — derivatives, gradient descent, and autograd 
import numpy as np

# ─────────────────────────────────────────────────
# 1. Numerical differentiation (finite differences)
# ─────────────────────────────────────────────────
def numerical_gradient(f, x, h=1e-5):
    """Central difference: more accurate than forward diff."""
    return (f(x + h) - f(x - h)) / (2 * h)

# f(x) = x³ − 4x + 1, analytical f'(x) = 3x² − 4
f = lambda x: x**3 - 4*x + 1
x_val = 2.0

numerical = numerical_gradient(f, x_val)
analytical = 3 * x_val**2 - 4   # 3(4) - 4 = 8

print(f"Numerical f'(2)  = {numerical:.6f}")
print(f"Analytical f'(2) = {analytical:.6f}")
# Numerical f'(2)  = 8.000000
# Analytical f'(2) = 8.000000

# ─────────────────────────────────────────────────
# 2. Partial derivatives for MSE loss (linear model)
# ─────────────────────────────────────────────────
np.random.seed(42)
n = 100
X = np.random.randn(n, 2)         # 100 samples, 2 features
true_w = np.array([2.0, -1.5])
y = X @ true_w + np.random.randn(n) * 0.1

def mse_loss(w, X, y):
    y_hat = X @ w
    return np.mean((y - y_hat) ** 2)

def mse_gradient(w, X, y):
    """Analytical gradient of MSE w.r.t. weights w."""
    y_hat = X @ w
    residuals = y_hat - y              # (n,)
    grad = (2 / n) * X.T @ residuals  # ∂L/∂w = (2/n) Xᵀ(ŷ − y)
    return grad

# ─────────────────────────────────────────────────
# 3. Gradient descent — minimize MSE loss
# ─────────────────────────────────────────────────
w = np.zeros(2)    # start at origin
lr = 0.05          # learning rate (α)

print("\nGradient descent on linear regression:")
for step in range(200):
    grad = mse_gradient(w, X, y)
    w = w - lr * grad                  # w ← w − α·∇L
    if step % 40 == 0:
        loss = mse_loss(w, X, y)
        print(f"  Step {step:3d}: loss={loss:.5f}, w={w}")

# Step   0: loss=3.46391, w=[ 0.068  -0.043]
# Step  40: loss=0.05234, w=[ 1.782  -1.341]
# Step  80: loss=0.01247, w=[ 1.943  -1.463]
# Step 120: loss=0.01093, w=[ 1.987  -1.494]
# Step 160: loss=0.01078, w=[ 1.998  -1.500]

# ─────────────────────────────────────────────────
# 4. Chain rule example — sigmoid neuron
# ─────────────────────────────────────────────────
def sigmoid(z):
    return 1.0 / (1.0 + np.exp(-z))

def sigmoid_deriv(z):
    s = sigmoid(z)
    return s * (1 - s)    # σ(z)(1−σ(z))

# Forward pass
x, w_scalar, b = 0.5, 2.0, 0.1
z = w_scalar * x + b     # pre-activation
a = sigmoid(z)           # activation
y_target = 1.0
L = (a - y_target) ** 2  # loss

# Backward pass (chain rule)
dL_da = 2 * (a - y_target)          # ∂L/∂a
da_dz = sigmoid_deriv(z)            # ∂a/∂z
dz_dw = x                            # ∂z/∂w
dL_dw = dL_da * da_dz * dz_dw       # chain rule

print(f"\nNeuron gradient: dL/dw = {dL_dw:.6f}")

# Verify with numerical gradient
num_grad = numerical_gradient(
    lambda ww: (sigmoid(ww*x + b) - y_target)**2,
    w_scalar
)
print(f"Numerical check:  dL/dw = {num_grad:.6f}")
# Neuron gradient: dL/dw = -0.044847
# Numerical check:  dL/dw = -0.044847

# ─────────────────────────────────────────────────
# 5. Gradient of common loss functions
# ─────────────────────────────────────────────────
def cross_entropy_grad(y_true, y_pred):
    """
    Binary cross-entropy: L = −[y·log(p) + (1−y)·log(1−p)]
    Gradient w.r.t. prediction: ∂L/∂p = (p − y) / (p(1−p))
    """
    return (y_pred - y_true) / (y_pred * (1 - y_pred) + 1e-8)

# For logistic regression (sigmoid output), gradient simplifies beautifully:
# ∂L/∂w = (σ(w·x) − y) · x  — the prediction error times the input
print("\nLogistic regression gradient = (prediction − truth) × input")
print("This is why logistic regression is so elegant.")
# Logistic regression gradient = (prediction − truth) × input
# This is why logistic regression is so elegant.

Key Derivatives You Must Know

These show up constantly across ML papers, implementations, and debugging sessions. Memorize or internalize them.

Loss / FunctionGradient w.r.t. predictionNotes
MSE: (y − ŷ)² −2(y − ŷ) Penalizes large errors quadratically
MAE: |y − ŷ| sign(ŷ − y) Not differentiable at 0; subgradient used
Binary cross-entropy (ŷ − y) / (ŷ(1−ŷ)) With sigmoid: simplifies to ŷ − y
Categorical cross-entropy −y / ŷ (per class) With softmax: simplifies to ŷ − y
L2 regularization: λ||w||² 2λw Adds weight decay to gradient update
L1 regularization: λ||w|| λ·sign(w) Produces sparsity; not differentiable at 0
The softmax + cross-entropy simplification
Separately, softmax and cross-entropy have messy Jacobians. Combined, the gradient is simply ŷ − y (predicted probability minus one-hot label). This is why you almost always see them paired in classification. The math "telescopes" beautifully through the chain rule.

Gradient Checking

Before trusting an implementation, gradient checking verifies your analytical gradients against numerical ones. This catches bugs in backpropagation code that would silently produce wrong gradients and fail to converge.

Gradient check criterion Relative error = ||grad_analytical − grad_numerical|| / ||grad_analytical|| + ||grad_numerical|| Acceptable: relative error < 1e-5 Suspicious: 1e-3 to 1e-5 (investigate) Bug present: > 1e-3
When gradient checking fails
Common culprits: (1) forgot to zero gradients between batches, (2) used += instead of = in backward pass, (3) transposed a matrix in the wrong direction, (4) off-by-one in indexing. Always check gradient shapes first — a shape mismatch often means broadcasting is hiding a bug.

Module Takeaways

  • The derivative measures instantaneous rate of change — the slope of the tangent line at a point
  • The chain rule computes gradients through composite functions — it IS backpropagation
  • Partial derivatives hold all other variables fixed while varying one — required for multivariate loss functions
  • The gradient vector points in the direction of steepest ascent; subtract it to minimize
  • Gradient descent: w ← w − α·∇L(w) — this equation trains every neural network
  • ReLU avoids vanishing gradients because its derivative is 0 or 1, never shrinking
  • Autograd (PyTorch/JAX) applies chain rule automatically through computation graphs
  • Gradient checking with central differences verifies backpropagation correctness
