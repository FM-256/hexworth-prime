Reinforcement Learning — Module 06

PPO and Advanced Algorithms

Proximal Policy Optimization constrains how much the policy can change per update, enabling multiple gradient steps per rollout. SAC and TD3 extend these ideas to continuous off-policy control.

01 / trust region

Trust Region Policy Optimization

Policy gradient methods can take excessively large steps that collapse performance. TRPO constrains updates to a trust region by bounding the KL divergence between old and new policies. This guarantees monotonic improvement but requires second-order optimization (conjugate gradient + line search).

TRPO objective: maximize E[pi(a|s) / pi_old(a|s) · A(s,a)] subject to E[KL(pi_old || pi)] <= delta delta = 0.01 is typical; enforced via conjugate gradient Limitation: - Second-order optimization is expensive - Difficult to implement correctly - PPO approximates the same guarantee at first-order cost
02 / ppo

PPO: Clipped Surrogate Objective

PPO replaces TRPO's hard constraint with a clipped probability ratio. If the new policy deviates too far from the old policy, the clip removes the gradient, preventing large destructive updates.

Probability ratio: r_t(theta) = pi_theta(a|s) / pi_theta_old(a|s) Clipped objective: L_CLIP = E[ min(r_t · A_t, clip(r_t, 1-eps, 1+eps) · A_t) ] eps = 0.2 (typical) Intuition: If A_t > 0 (good action): cap ratio at 1+eps — don't boost too much If A_t < 0 (bad action): cap ratio at 1-eps — don't penalize too hard Both cases: conservative update regardless of true ratio magnitude Full PPO loss: L = L_CLIP - c1·L_VF + c2·H[pi] c1=0.5 (value loss), c2=0.01 (entropy bonus)
03 / implementation

PPO Implementation

import torch import torch.nn as nn import torch.nn.functional as F import numpy as np class PPOActorCritic(nn.Module): """Shared backbone actor-critic for PPO.""" def __init__(self, obs_dim, n_actions, hidden=64): super().__init__() self.net = nn.Sequential( nn.Linear(obs_dim, hidden), nn.Tanh(), nn.Linear(hidden, hidden), nn.Tanh(), ) self.actor = nn.Linear(hidden, n_actions) self.critic = nn.Linear(hidden, 1) def forward(self, x): h = self.net(x) probs = F.softmax(self.actor(h), dim=-1) value = self.critic(h).squeeze(-1) return probs, value def ppo_update(model, optimizer, states, actions, old_log_probs, returns, advantages, clip_eps=0.2, n_epochs=10, value_coef=0.5, entropy_coef=0.01): """ PPO gradient update: reuses one rollout for n_epochs mini-batch passes. This is the key sample-efficiency gain over vanilla actor-critic. """ dataset_size = states.size(0) batch_size = 64 for _ in range(n_epochs): # shuffle for mini-batch training perm = torch.randperm(dataset_size) for start in range(0, dataset_size, batch_size): idx = perm[start:start + batch_size] b_states = states[idx] b_actions = actions[idx] b_old_lp = old_log_probs[idx] b_returns = returns[idx] b_advs = advantages[idx] probs, values = model(b_states) dist = torch.distributions.Categorical(probs) new_log_probs = dist.log_prob(b_actions) entropy = dist.entropy().mean() # probability ratio pi_new / pi_old ratio = (new_log_probs - b_old_lp).exp() # clipped surrogate objective surr1 = ratio * b_advs surr2 = ratio.clamp(1 - clip_eps, 1 + clip_eps) * b_advs actor_loss = -torch.min(surr1, surr2).mean() # value function loss (clipped variant also possible) value_loss = F.mse_loss(values, b_returns) loss = actor_loss + value_coef * value_loss - entropy_coef * entropy optimizer.zero_grad() loss.backward() nn.utils.clip_grad_norm_(model.parameters(), 0.5) optimizer.step()
04 / ppo training

PPO Training Loop

def train_ppo(env_name='LunarLander-v2', total_steps=1_000_000, rollout_len=2048, gamma=0.99, gae_lambda=0.95): import gymnasium as gym env = gym.make(env_name) obs_d = env.observation_space.shape[0] n_act = env.action_space.n model = PPOActorCritic(obs_d, n_act) optim = torch.optim.Adam(model.parameters(), lr=3e-4, eps=1e-5) state, _ = env.reset() step = 0 while step < total_steps: # ── collect rollout ──────────────────────────────────── states, actions, rewards, dones, values, log_probs = \ [], [], [], [], [], [] for _ in range(rollout_len): state_t = torch.tensor(state, dtype=torch.float32) probs, value = model(state_t) dist = torch.distributions.Categorical(probs) action = dist.sample() lp = dist.log_prob(action) next_state, reward, term, trunc, _ = env.step(action.item()) done = term or trunc states.append(state_t) actions.append(action) rewards.append(reward) dones.append(float(done)) values.append(value.detach()) log_probs.append(lp.detach()) state = next_state if not done else env.reset()[0] step += 1 # ── compute GAE advantages and returns ──────────────── _, next_val = model(torch.tensor(state, dtype=torch.float32)) values_t = torch.stack(values) returns, advs = compute_gae( rewards, values_t.numpy(), next_val.item(), dones, gamma, gae_lambda ) # ── PPO update ──────────────────────────────────────── ppo_update( model, optim, torch.stack(states), torch.stack(actions), torch.stack(log_probs), torch.tensor(returns, dtype=torch.float32), torch.tensor(advs, dtype=torch.float32), ) def compute_gae(rewards, values, next_value, dones, gamma, lam): """Generalized Advantage Estimation for a collected rollout.""" T = len(rewards) advs = np.zeros(T, dtype=np.float32) gae = 0.0 for t in reversed(range(T)): nv = values[t + 1] if t < T - 1 else next_value delta = rewards[t] + gamma * nv * (1 - dones[t]) - values[t] gae = delta + gamma * lam * (1 - dones[t]) * gae advs[t] = gae returns = advs + values advs = (advs - advs.mean()) / (advs.std() + 1e-8) return returns, advs
05 / sac

Soft Actor-Critic (SAC)

SAC is an off-policy maximum-entropy actor-critic for continuous action spaces. It maximizes both expected return and policy entropy, encouraging exploration naturally. SAC uses two Q-networks to reduce overestimation and an automatic temperature tuning mechanism.

SAC Objective: J(pi) = E[ sum_t (r_t + alpha · H[pi(·|s_t)]) ] alpha: temperature — controls the entropy-reward trade-off Auto-tuning: alpha is treated as a Lagrangian multiplier Twin Q-Networks (prevents overestimation): Q1(s,a), Q2(s,a) — independently trained Target: r + gamma * (min(Q1,Q2)(s',a') - alpha * log pi(a'|s')) Policy Update: minimize E_s[ alpha*log pi(a|s) - min(Q1,Q2)(s,a) ] (reparameterization trick for continuous actions)
class SACQNetwork(nn.Module): """Twin Q-network for SAC. Takes (state, action) and outputs Q-value.""" def __init__(self, obs_dim, action_dim, hidden=256): super().__init__() # two Q-networks; both trained independently self.q1 = nn.Sequential( nn.Linear(obs_dim + action_dim, hidden), nn.ReLU(), nn.Linear(hidden, hidden), nn.ReLU(), nn.Linear(hidden, 1), ) self.q2 = nn.Sequential( nn.Linear(obs_dim + action_dim, hidden), nn.ReLU(), nn.Linear(hidden, hidden), nn.ReLU(), nn.Linear(hidden, 1), ) def forward(self, state, action): x = torch.cat([state, action], dim=-1) return self.q1(x).squeeze(-1), self.q2(x).squeeze(-1) class SACActor(nn.Module): """ Gaussian policy with reparameterization trick and tanh squashing. Returns action in [-1, 1] range for bounded continuous spaces. """ LOG_STD_MIN, LOG_STD_MAX = -5, 2 def __init__(self, obs_dim, action_dim, hidden=256): super().__init__() self.net = nn.Sequential(nn.Linear(obs_dim, hidden), nn.ReLU(), nn.Linear(hidden, hidden), nn.ReLU()) self.mu_head = nn.Linear(hidden, action_dim) self.ls_head = nn.Linear(hidden, action_dim) def forward(self, state): h = self.net(state) mu = self.mu_head(h) log_std = self.ls_head(h).clamp(self.LOG_STD_MIN, self.LOG_STD_MAX) std = log_std.exp() dist = torch.distributions.Normal(mu, std) # reparameterization: action = tanh(mu + std * epsilon) x_t = dist.rsample() action = torch.tanh(x_t) # log prob with tanh correction (change of variables) log_prob = dist.log_prob(x_t).sum(dim=-1) log_prob -= torch.log(1 - action.pow(2) + 1e-6).sum(dim=-1) return action, log_prob
06 / td3

Twin Delayed DDPG (TD3)

TD3 addresses three failure modes of DDPG: overestimation, policy updating too frequently relative to the Q-function, and sharp Q-landscapes from deterministic targets. Three tricks fix these.

Twin Q-Networks

Same as SAC: two Q-networks, use minimum for target. Prevents Q-overestimation that causes policy collapse.

Delayed Policy Updates

Update the actor and target networks less frequently than critics (e.g., every 2 critic steps). Ensures Q-functions are stable before actor exploits them.

Target Policy Smoothing

Add clipped noise to the target action: a' = pi(s') + clip(N(0,sigma), -c, c). Prevents exploiting sharp Q-function peaks.

Deterministic Actor

Unlike SAC, TD3 uses a deterministic policy. Exploration is achieved by adding noise to actions during data collection (Ornstein-Uhlenbeck or simple Gaussian).

07 / selection guide

Algorithm Selection Guide

Scenario Recommended Reason
Discrete actions, pixel obs DQN / Rainbow Convolutional Q-network handles images naturally
Discrete actions, vector obs PPO Simple, reliable, easy to tune
Continuous actions, sample efficiency key SAC Off-policy reuse + entropy maximization
Continuous actions, deterministic preferred TD3 More stable than DDPG, deterministic control
LLM fine-tuning / RLHF PPO Constrained updates prevent policy collapse on long sequences
Multi-agent cooperative MAPPO / QMIX Centralized training, decentralized execution
Sparse rewards / exploration critical SAC + HER Hindsight Experience Replay relabels failed trajectories as successes
08 / hyperparameters

PPO Hyperparameter Reference

Hyperparameter Typical Value Effect
clip_eps 0.1 – 0.3 Smaller = more conservative policy updates
n_epochs 4 – 10 More passes per rollout = better sample efficiency but risk overfitting
rollout_len 128 – 4096 Longer = better advantage estimates, higher memory cost
gae_lambda 0.90 – 0.99 0.95 standard; lower = lower variance, higher bias
lr 1e-4 – 3e-4 Often annealed linearly to 0 over training
entropy_coef 0.001 – 0.01 Higher = more exploration; anneal when task is learned
value_coef 0.5 Balances actor and critic loss scales
max_grad_norm 0.5 Gradient clipping; prevents catastrophic updates
PPO in Production: RLHF for LLMs PPO is the standard RL algorithm for RLHF (Reinforcement Learning from Human Feedback) used to align LLMs. The "policy" is the LLM, the "reward" comes from a reward model trained on human preference data, and the KL penalty between the fine-tuned and reference models plays the role of the clip constraint.
