Reinforcement Learning — Module 05

Policy Gradient Methods

Instead of learning a value function and deriving a policy from it, policy gradient methods directly optimize the policy parameters. They naturally handle continuous action spaces and stochastic policies.

01 / policy gradient theorem

The Policy Gradient Theorem

Let pi_theta(a|s) be a stochastic policy parameterized by theta. The objective is J(theta) = E[G_t] = sum_s d^pi(s) sum_a pi_theta(a|s) Q^pi(s,a), where d^pi is the discounted state distribution. The policy gradient theorem gives:

Policy Gradient Theorem: gradient_theta J(theta) = E_pi [ gradient_theta log pi_theta(a|s) · Q^pi(s,a) ] Intuition: - If Q(s,a) is high (good action), increase log pi(a|s) → take that action more - If Q(s,a) is low (bad action), decrease log pi(a|s) → take that action less - Score function: gradient_theta log pi_theta(a|s) — how to "steer" the policy REINFORCE (MC policy gradient): Replace Q^pi(s,a) with sampled return G_t from full episode gradient_theta J ≈ sum_t gradient_theta log pi_theta(a_t|s_t) · G_t
02 / reinforce

REINFORCE

import torch import torch.nn as nn import torch.nn.functional as F import numpy as np import gymnasium as gym class PolicyNetwork(nn.Module): """Stochastic policy: outputs action probability distribution.""" def __init__(self, obs_dim, n_actions, hidden=128): super().__init__() self.net = nn.Sequential( nn.Linear(obs_dim, hidden), nn.ReLU(), nn.Linear(hidden, hidden), nn.ReLU(), nn.Linear(hidden, n_actions), ) def forward(self, x): return F.softmax(self.net(x), dim=-1) # probability over actions def reinforce(env_name='CartPole-v1', gamma=0.99, lr=1e-3, n_episodes=2000): """ REINFORCE: Monte Carlo policy gradient. Collects full episodes, computes discounted returns, updates policy. High variance — mitigated by baseline subtraction in actor-critic. """ env = gym.make(env_name) policy = PolicyNetwork(env.observation_space.shape[0], env.action_space.n) optim = torch.optim.Adam(policy.parameters(), lr=lr) rewards_history = [] for ep in range(n_episodes): # ── collect episode ──────────────────────────────────── log_probs, rewards = [], [] state, _ = env.reset() done = False while not done: state_t = torch.tensor(state, dtype=torch.float32).unsqueeze(0) probs = policy(state_t) dist = torch.distributions.Categorical(probs) action = dist.sample() log_probs.append(dist.log_prob(action)) # log pi(a|s) state, reward, term, trunc, _ = env.step(action.item()) rewards.append(reward) done = term or trunc # ── compute discounted returns G_t ──────────────────── G, returns = 0.0, [] for r in reversed(rewards): G = r + gamma * G returns.insert(0, G) returns = torch.tensor(returns, dtype=torch.float32) # normalize returns for training stability returns = (returns - returns.mean()) / (returns.std() + 1e-8) # ── policy gradient update ──────────────────────────── loss = -torch.stack(log_probs) * returns # negative because we maximize J loss = loss.sum() optim.zero_grad() loss.backward() optim.step() rewards_history.append(sum(rewards)) if ep % 100 == 0: avg = np.mean(rewards_history[-100:]) print(f"Episode {ep:4d} | Avg Reward: {avg:.1f}") env.close() return policy
03 / baseline

Variance Reduction: Baseline and Advantage

REINFORCE has high variance because returns vary greatly across episodes. Subtracting a baseline b(s) from the return does not bias the gradient but reduces variance. The optimal baseline is V(s), leading to the advantage function.

Vanilla REINFORCE: gradient = E[ log pi(a|s) · G_t ] With Baseline: gradient = E[ log pi(a|s) · (G_t - b(s)) ] unbiased Advantage Function: A(s,a) = Q(s,a) - V(s) = how much better is action a than average? Actor-Critic: use neural V(s) as baseline, TD(0) estimate A(s,a) ≈ r + γV(s') - V(s) ← TD error as advantage
04 / actor-critic

Actor-Critic

Actor-critic methods combine a policy network (actor) with a value network (critic). The critic estimates V(s) to compute the advantage. Updates can happen at every step rather than only at episode end.

class ActorCritic(nn.Module): """ Shared feature extractor with two heads: - actor: outputs action probabilities (policy) - critic: outputs state value estimate V(s) Sharing features accelerates learning; separate networks also work. """ def __init__(self, obs_dim, n_actions, hidden=256): super().__init__() self.shared = nn.Sequential( nn.Linear(obs_dim, hidden), nn.ReLU(), nn.Linear(hidden, hidden), nn.ReLU(), ) self.actor = nn.Linear(hidden, n_actions) # policy head self.critic = nn.Linear(hidden, 1) # value head def forward(self, x): feat = self.shared(x) probs = F.softmax(self.actor(feat), dim=-1) # action probabilities value = self.critic(feat).squeeze(-1) # V(s) scalar return probs, value def actor_critic_step(model, optimizer, state, action, reward, next_state, done, gamma=0.99, entropy_coef=0.01, value_coef=0.5): """ Single actor-critic gradient step. entropy_coef: weight for entropy bonus — encourages exploration value_coef: weight balancing actor vs critic loss magnitudes """ state_t = torch.tensor(state, dtype=torch.float32) next_state_t = torch.tensor(next_state, dtype=torch.float32) probs, value = model(state_t) _, next_value = model(next_state_t) # TD advantage: r + gamma*V(s') - V(s) td_target = reward + gamma * next_value.detach() * (1 - done) advantage = (td_target - value).detach() # stop gradient through advantage # actor loss: maximize log pi(a|s) * advantage dist = torch.distributions.Categorical(probs) log_prob = dist.log_prob(torch.tensor(action)) actor_loss = -(log_prob * advantage) # critic loss: MSE on TD target critic_loss = F.mse_loss(value, td_target.detach()) # entropy bonus: -sum pi*log(pi) — penalizes deterministic policies entropy = dist.entropy() loss = actor_loss + value_coef * critic_loss - entropy_coef * entropy optimizer.zero_grad() loss.backward() nn.utils.clip_grad_norm_(model.parameters(), 0.5) optimizer.step() return loss.item()
05 / a2c

Advantage Actor-Critic (A2C)

A2C runs N parallel environment workers synchronously. Each worker collects a rollout of T steps. After all workers finish their rollout, gradients are averaged and applied. The synchronous design is simpler and more reproducible than the asynchronous A3C variant.

def compute_returns_and_advantages(rewards, values, next_value, dones, gamma=0.99, gae_lambda=0.95): """ Generalized Advantage Estimation (GAE) for A2C/PPO rollouts. gae_lambda=1.0 reduces to full MC advantage; gae_lambda=0.0 to TD advantage. Returns tensors for advantages (normalized) and discounted returns. """ T = len(rewards) advantages = torch.zeros(T) gae = 0.0 for t in reversed(range(T)): if t == T - 1: next_val = next_value else: next_val = values[t + 1] delta = rewards[t] + gamma * next_val * (1 - dones[t]) - values[t] gae = delta + gamma * gae_lambda * (1 - dones[t]) * gae advantages[t] = gae returns = advantages + values # V(s) + A(s,a) = Q(s,a) advantages = (advantages - advantages.mean()) / (advantages.std() + 1e-8) return returns, advantages def a2c_update(model, optimizer, states, actions, returns, advantages, entropy_coef=0.01, value_coef=0.5): """Batch update from a completed rollout across N workers x T steps.""" probs, values = model(states) dist = torch.distributions.Categorical(probs) log_probs = dist.log_prob(actions) entropy = dist.entropy().mean() actor_loss = -(log_probs * advantages).mean() critic_loss = F.mse_loss(values, returns) loss = actor_loss + value_coef * critic_loss - entropy_coef * entropy optimizer.zero_grad() loss.backward() nn.utils.clip_grad_norm_(model.parameters(), 0.5) optimizer.step() return {'actor': actor_loss.item(), 'critic': critic_loss.item(), 'entropy': entropy.item()}
06 / entropy

Entropy Regularization

Adding an entropy bonus H[pi] = -sum pi(a|s) log pi(a|s) to the objective encourages exploration by penalizing deterministic policies. Without it, actor-critic often collapses to a single action prematurely.

Objective with entropy: J(theta) = E[sum_t (r_t + beta · H[pi(·|s_t)])] Effect: High entropy = uniform distribution = maximum exploration Low entropy = peaked distribution = committed policy Beta annealing: high early (explore), low late (exploit) Typical values: beta = 0.01 (discrete actions, CartPole/Atari) beta = 0.001 (continuous, MuJoCo)
07 / comparison

Policy Gradient Methods Compared

Method Update Frequency Advantage Estimate Key Strength Key Weakness
REINFORCE Episode end Full MC return G_t Unbiased gradient Very high variance
REINFORCE + Baseline Episode end G_t - b(s) Lower variance Baseline adds complexity
Actor-Critic (one-step) Every step TD error r+gamma*V(s')-V(s) Low variance, online Biased advantage estimate
A2C T-step rollout GAE (n-step) Balanced bias-variance Requires parallel workers
A3C Async rollout GAE Asynchronous, fast wall-clock Non-reproducible; A2C usually better
08 / continuous actions

Continuous Action Spaces

For continuous actions (e.g., joint torques, steering angles), the policy outputs parameters of a distribution rather than class probabilities. The most common choice is a Gaussian: mu(s) and log_sigma(s) are predicted, and actions are sampled from N(mu, sigma).

class GaussianActorCritic(nn.Module): """ Actor-critic for continuous action spaces. Actor outputs mean and log-std of a Gaussian policy. Actions sampled via reparameterization: a = mu + sigma * epsilon """ def __init__(self, obs_dim, action_dim, hidden=256): super().__init__() self.shared = nn.Sequential( nn.Linear(obs_dim, hidden), nn.Tanh(), # Tanh common in MuJoCo nn.Linear(hidden, hidden), nn.Tanh(), ) self.mu_head = nn.Linear(hidden, action_dim) self.log_std_head = nn.Linear(hidden, action_dim) self.critic_head = nn.Linear(hidden, 1) def forward(self, x): feat = self.shared(x) mu = self.mu_head(feat) log_std = self.log_std_head(feat).clamp(-4, 2) # prevent extreme std values value = self.critic_head(feat).squeeze(-1) return mu, log_std.exp(), value def get_action(self, state): state_t = torch.tensor(state, dtype=torch.float32) mu, std, value = self.forward(state_t) dist = torch.distributions.Normal(mu, std) action = dist.sample() # stochastic sampling log_p = dist.log_prob(action).sum(dim=-1) # sum over action dimensions return action.detach().numpy(), log_p, value
Policy Gradient Limitation: Sample Efficiency Policy gradient methods are on-policy: data collected under the old policy cannot be reused after an update. This makes them expensive compared to off-policy methods like DQN. PPO (next module) addresses this with clipped importance sampling, allowing multiple gradient steps per rollout.
Reference: CartPole-v1 with REINFORCE With normalized returns, a 128-hidden-unit policy network and lr=1e-3 typically solves CartPole (mean reward above 475 over 100 episodes) in 500-800 episodes. Actor-critic converges 2-3x faster due to the TD baseline.
