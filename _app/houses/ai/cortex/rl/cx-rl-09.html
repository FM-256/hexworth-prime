Reinforcement Learning — Module 09

Inverse RL and Imitation Learning

When reward functions are hard to specify, we can learn them from expert demonstrations. Inverse RL recovers a reward function; behavior cloning and GAIL learn policies directly from observed behavior.

01 / problem setting

The Reward Specification Problem

Specifying a reward function is often harder than demonstrating the desired behavior. A security analyst can demonstrate good log triage without articulating a complete scoring formula. IRL and imitation learning exploit this: learn from what the expert does, not from an explicit reward.

Standard RL: Given: MDP (S, A, P, R) Find: optimal policy pi* Inverse RL (IRL): Given: MDP (S, A, P) + expert demonstrations D = {tau_1, ..., tau_n} Find: reward function R that makes expert policy optimal Imitation Learning: Given: expert demonstrations D Find: policy pi that mimics expert behavior (may not recover reward — directly clones behavior) When to use which: Behavior Cloning: fast, simple, but distribution shift problem DAgger: queries expert interactively, handles distribution shift IRL/GAIL: reward generalization, harder to implement
02 / behavior cloning

Behavior Cloning

Behavior cloning (BC) treats imitation as supervised learning: map observations to actions using the expert's demonstrations as labeled data. Simple and fast, but suffers from compounding errors when the agent encounters states outside the training distribution.

import torch import torch.nn as nn import torch.nn.functional as F import numpy as np class BCPolicy(nn.Module): """Simple MLP policy for behavior cloning.""" def __init__(self, obs_dim, n_actions, hidden=256): super().__init__() self.net = nn.Sequential( nn.Linear(obs_dim, hidden), nn.ReLU(), nn.Linear(hidden, hidden), nn.ReLU(), nn.Linear(hidden, n_actions), ) def forward(self, x): return self.net(x) class BehaviorCloningTrainer: """ Behavior Cloning: supervised learning on expert (obs, action) pairs. Handles both discrete (cross-entropy) and continuous (MSE) actions. """ def __init__(self, obs_dim, n_actions, lr=3e-4, discrete=True): self.policy = BCPolicy(obs_dim, n_actions) self.optimizer = torch.optim.Adam(self.policy.parameters(), lr=lr) self.discrete = discrete def train_on_demonstrations(self, demos, n_epochs=50, batch_size=64): """ demos: list of (obs, action) tuples from expert trajectories Returns: training loss history """ obs_arr = torch.tensor(np.array([d[0] for d in demos]), dtype=torch.float32) act_arr = torch.tensor(np.array([d[1] for d in demos]), dtype=torch.long if self.discrete else torch.float32) N = len(demos) losses = [] for epoch in range(n_epochs): perm = torch.randperm(N) ep_loss = [] for start in range(0, N, batch_size): idx = perm[start:start+batch_size] logits = self.policy(obs_arr[idx]) if self.discrete: loss = F.cross_entropy(logits, act_arr[idx]) else: loss = F.mse_loss(logits, act_arr[idx]) self.optimizer.zero_grad() loss.backward() self.optimizer.step() ep_loss.append(loss.item()) losses.append(np.mean(ep_loss)) if epoch % 10 == 0: print(f"Epoch {epoch:3d} | Loss: {losses[-1]:.4f}") return losses def predict(self, obs): with torch.no_grad(): logits = self.policy(torch.tensor(obs, dtype=torch.float32)) if self.discrete: return int(logits.argmax().item()) return logits.numpy()
03 / dagger

DAgger: Dataset Aggregation

Distribution shift is the core failure mode of BC: the agent makes a small error, enters a state the expert never demonstrated, and mistakes compound. DAgger fixes this by iteratively collecting expert labels on states the policy actually visits.

DAgger Algorithm: 1. Train initial policy pi_1 on expert demonstrations D_0 2. For iteration i = 1, 2, ..., N: a. Deploy pi_i in environment, collect trajectory b. Query expert for correct actions at every visited state c. Aggregate: D_i = D_{i-1} + new labeled states d. Retrain policy on D_i Key insight: Policy is trained on ALL states it actually visits (not just expert states) Expert corrects errors before they compound Trade-off: Requires interactive expert (can be expensive) Can use approximate expert (scripted or model-based)
def dagger_iteration(policy, env, expert_policy, n_steps=1000, beta=0.5, aggregated_data=None): """ One DAgger iteration: roll out policy, label with expert, aggregate. beta: probability of following policy (vs expert) during rollout - beta=0 → pure expert (iteration 0) - beta=1 → pure policy (last iteration) """ if aggregated_data is None: aggregated_data = [] new_data = [] state, _ = env.reset() for _ in range(n_steps): obs_t = torch.tensor(state, dtype=torch.float32) # mixed policy: beta determines exploration vs imitation if np.random.rand() < beta: with torch.no_grad(): action = int(policy(obs_t.unsqueeze(0)).argmax().item()) else: action = expert_policy(state) # always label with EXPERT action (regardless of who acted) expert_action = expert_policy(state) new_data.append((state, expert_action)) next_state, _, term, trunc, _ = env.step(action) if term or trunc: state, _ = env.reset() else: state = next_state aggregated_data.extend(new_data) return aggregated_data
04 / reward shaping

Reward Shaping

Reward shaping adds auxiliary rewards F(s,s') to the environment reward to guide learning without changing the optimal policy. Potential-based shaping guarantees policy invariance: F(s,s') = gamma * Phi(s') - Phi(s) for any potential function Phi.

def potential_based_shaping(state, next_state, gamma, phi): """ Potential-based shaping: F(s,s') = gamma*Phi(s') - Phi(s). Does NOT change the optimal policy of the original MDP. phi: callable(state) -> float — potential function """ return gamma * phi(next_state) - phi(state) def distance_to_goal_potential(state, goal_state): """Example potential: negative Euclidean distance to goal.""" return -np.linalg.norm(np.array(state) - np.array(goal_state)) class ShapedRewardWrapper: """ Gym wrapper that adds potential-based shaping to environment reward. Useful for dense guidance in sparse-reward environments. """ def __init__(self, env, phi, gamma=0.99): self.env = env self.phi = phi self.gamma = gamma self.prev_state = None def reset(self): obs, info = self.env.reset() self.prev_state = obs return obs, info def step(self, action): obs, reward, term, trunc, info = self.env.step(action) # add shaping reward shaping = potential_based_shaping(self.prev_state, obs, self.gamma, self.phi) self.prev_state = obs return obs, reward + shaping, term, trunc, info
05 / gail

Generative Adversarial Imitation Learning (GAIL)

GAIL uses a GAN-style discriminator to distinguish expert trajectories from agent trajectories. The discriminator's output serves as the reward signal: the agent is rewarded when it fools the discriminator into thinking it is the expert.

GAIL Training Loop: 1. Collect agent trajectories using current policy pi_theta 2. Update Discriminator D_psi: maximize E_expert[log D(s,a)] + E_pi[log(1 - D(s,a))] (D(s,a) = 1 for expert, 0 for agent) 3. Compute reward: r(s,a) = -log(1 - D(s,a)) (high when fooling D) 4. Update policy pi_theta using PPO/TRPO on shaped reward Connection to IRL: GAIL implicitly recovers the reward function through the discriminator D(s,a) approximates: exp(R*(s,a)) / (exp(R*(s,a)) + pi(a|s))
class Discriminator(nn.Module): """ GAIL discriminator: outputs P(expert | state, action). Trained to distinguish expert (state, action) pairs from agent pairs. """ def __init__(self, obs_dim, action_dim, hidden=128): super().__init__() self.net = nn.Sequential( nn.Linear(obs_dim + action_dim, hidden), nn.Tanh(), nn.Linear(hidden, hidden), nn.Tanh(), nn.Linear(hidden, 1), nn.Sigmoid(), ) def forward(self, obs, action): x = torch.cat([obs, action], dim=-1) return self.net(x).squeeze(-1) # P(from expert) def gail_discriminator_update(disc, disc_optimizer, expert_batch, agent_batch): """ Update discriminator to maximize log D(expert) + log(1-D(agent)). expert_batch, agent_batch: (obs, actions) tensors """ expert_obs, expert_act = expert_batch agent_obs, agent_act = agent_batch # one-hot or float actions for continuous d_expert = disc(expert_obs, expert_act.float()) d_agent = disc(agent_obs, agent_act.float()) # binary cross-entropy: expert=1, agent=0 loss = -(torch.log(d_expert + 1e-8).mean() + torch.log(1 - d_agent + 1e-8).mean()) disc_optimizer.zero_grad() loss.backward() disc_optimizer.step() return loss.item() def gail_reward(disc, obs, action): """Reward signal for agent: -log(1-D) = log D / (1-D) shaped.""" with torch.no_grad(): d = disc(obs, action.float()) return -torch.log(1 - d + 1e-8) # high when agent fools discriminator
06 / maxent irl

Maximum Entropy IRL

Maximum Entropy IRL (Ziebart et al.) recovers a reward function by finding R such that the induced policy has the same expected feature counts as the expert, while maximizing policy entropy (avoiding distributional assumptions about the expert's optimality).

def maxent_irl(feature_matrix, P, n_states, n_actions, expert_demos, gamma=0.99, lr=0.01, n_iter=200): """ Maximum Entropy IRL for small tabular MDPs. feature_matrix: (n_states, n_features) — feature representation of states expert_demos: list of state sequences from expert Returns: learned reward weights theta s.t. R(s) = theta . phi(s) """ n_features = feature_matrix.shape[1] theta = np.zeros(n_features) # reward weight vector # compute expert feature expectations mu_E mu_expert = np.zeros(n_features) for demo in expert_demos: for t, s in enumerate(demo): mu_expert += gamma**t * feature_matrix[s] mu_expert /= len(expert_demos) for iteration in range(n_iter): # compute reward from current theta R = feature_matrix @ theta # (n_states,) # solve soft value iteration (MaxEnt policy) V = np.zeros(n_states) for _ in range(100): Q = np.zeros((n_states, n_actions)) for s in range(n_states): for a in range(n_actions): Q[s, a] = R[s] + gamma * sum( P[s][a][i][0] * V[P[s][a][i][1]] for i in range(len(P[s][a])) ) V_new = np.log(np.exp(Q).sum(axis=1)) # soft-max Bellman if np.max(np.abs(V_new - V)) < 1e-6: break V = V_new # compute induced policy (softmax) pi(a|s) = exp(Q(s,a)-V(s)) pi = np.exp(Q - V[:, np.newaxis]) # compute learner feature expectations mu_L mu_learner = np.zeros(n_features) state_freq = np.ones(n_states) / n_states # uniform initial state dist for t in range(50): # trajectory length mu_learner += gamma**t * (state_freq[:, np.newaxis] * feature_matrix).sum(0) # propagate state frequency under policy pi new_freq = np.zeros(n_states) for s in range(n_states): for a in range(n_actions): for prob, ns, _, _ in P[s][a]: new_freq[ns] += state_freq[s] * pi[s, a] * prob state_freq = new_freq # gradient ascent on theta: maximize E_expert[R] - log Z grad = mu_expert - mu_learner theta += lr * grad R_final = feature_matrix @ theta return theta, R_final
07 / security applications

Imitation Learning for Security

Expert SOC Analyst Cloning

Train an agent on analyst alert triage decisions. BC learns the analyst's prioritization heuristics from historical tickets without requiring an explicit scoring formula.

Red Team TTP Imitation

Given logs from known APT campaigns (MITRE ATT&CK), learn an attacker model that generates realistic attack sequences for testing blue team detection.

Malware Behavior Modeling

IRL recovers the implicit "reward function" of malware: what objectives (persistence, exfiltration, lateral movement) drive observed system call sequences.

Patch Prioritization

Learn from expert vulnerability patching decisions to build an agent that prioritizes CVEs under CVSS uncertainty, considering attacker likelihood and asset value.

08 / comparison

Imitation Learning Methods Compared

Method Expert Interaction Reward Required Distributional Robustness Complexity
Behavior Cloning Offline only No Low (covariate shift) Low
DAgger Online (iterative) No High Medium
MaxEnt IRL Offline demos Inferred Medium High (DP per iteration)
GAIL Offline demos Inferred via D High High (GAN instability)
AIRL Offline demos Inferred, transferable High High
Offline RL: A Middle Ground Offline RL (Conservative Q-Learning, Implicit Q-Learning) learns from a fixed dataset of pre-collected experience without environment interaction — similar to BC but with RL-style credit assignment. Useful when interacting with the environment is expensive or dangerous (e.g., production network defense).
Causal Confusion in Imitation BC agents can learn spurious correlations: in a driving task, an agent might learn to steer based on the speedometer position (correlates with curves in demos) rather than the road curvature. Causal analysis and interventional data collection help identify and remove such confounders.
