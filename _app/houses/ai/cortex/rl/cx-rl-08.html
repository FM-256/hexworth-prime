Reinforcement Learning — Module 08

RL for Security

RL agents learn by trial and error — making them a natural fit for adversarial security tasks. From automated penetration testing to adaptive network defense, RL enables security systems that respond to novel threats without human-defined rules.

01 / motivation

Why RL for Security?

Traditional security tooling relies on signatures, rules, and expert knowledge. RL agents discover attack paths and defense strategies through interaction — adapting when adversaries change tactics without requiring rule updates.

Red Team

Automated Pentesting

Agent learns to find and chain vulnerabilities across network nodes to reach a target — mimicking APT lateral movement.

Blue Team

Adaptive IDS

Agent learns detection policies that minimize false positives while catching novel attack patterns not seen during training.

Red Team

Adversarial ML

RL agent generates adversarial examples or evades ML-based detectors by learning minimal perturbations that fool classifiers.

Blue Team

Cyber Deception

Agent learns optimal honeypot placement and decoy configuration to maximize attacker dwell time and intelligence collection.

02 / pentesting mdp

Pentesting as an MDP

Network penetration testing maps cleanly onto the MDP formalism. CyberBattleSim (Microsoft Research) and NetSecGame are open-source environments built on this structure.

State S: - Known network topology (discovered nodes, edges) - Compromised nodes and their privilege levels (user/root) - Discovered credentials and services - Current detection probability estimate Actions A: - scan(node): discover services and open ports - exploit(node, service, cve): attempt compromise - lateral_move(src, dst): pivot using stolen credentials - escalate(node): attempt privilege escalation - exfiltrate(node, data): retrieve target data Rewards R: + 10 per new node compromised + 100 for reaching target / exfiltrating data - 5 per failed exploit (noise increases detection risk) - 50 if agent is detected and kicked out Episode End: success (exfiltration), detection (blue team response), or step limit
03 / cyberbattle

CyberBattleSim Environment

import numpy as np from dataclasses import dataclass, field from typing import List, Dict, Set, Tuple @dataclass class NetworkNode: node_id: int services: List[str] # e.g. ['ssh', 'http', 'smb'] vulns: List[str] # CVE IDs exploitable on this node value: float # reward for compromising this node is_target: bool = False class PentestEnv: """ Simplified network penetration testing environment. Topology: directed graph of nodes with vulnerability profiles. Agent: red team operator discovering and exploiting nodes. """ def __init__(self, nodes: List[NetworkNode], edges: List[Tuple[int,int]], max_steps: int = 200): self.nodes = {n.node_id: n for n in nodes} self.edges = edges # (src, dst) adjacency self.adj = self._build_adj() self.max_steps = max_steps self.reset() def _build_adj(self): adj = {nid: [] for nid in self.nodes} for src, dst in self.edges: adj[src].append(dst) return adj def reset(self): self.compromised: Set[int] = {0} # agent starts with initial foothold self.discovered: Set[int] = {0} self.detection_score = 0.0 self.steps = 0 return self._get_obs() def _get_obs(self): N = len(self.nodes) obs = np.zeros(N * 3 + 1) # compromised, discovered, services, detection for nid in self.compromised: obs[nid] = 1.0 for nid in self.discovered: obs[N + nid] = 1.0 for nid, node in self.nodes.items(): obs[2*N + nid] = len(node.vulns) / 5.0 # normalized vuln count obs[-1] = self.detection_score / 100.0 return obs def step(self, action: Dict): """ action: {'type': 'scan'|'exploit'|'lateral', 'target': node_id, 'vuln': str} Returns: (obs, reward, done, info) """ reward = 0.0 done = False self.steps += 1 act_type = action['type'] target = action.get('target', 0) if act_type == 'scan' and target in self.compromised: # discover neighbors of a compromised node for neighbor in self.adj.get(target, []): if neighbor not in self.discovered: self.discovered.add(neighbor) reward += 1.0 # small reward for discovery self.detection_score += 0.5 elif act_type == 'exploit' and target in self.discovered: node = self.nodes[target] vuln = action.get('vuln', '') if vuln in node.vulns: success_prob = 0.75 # exploit success rate if np.random.rand() < success_prob: self.compromised.add(target) reward += node.value if node.is_target: reward += 100.0 done = True else: reward -= 2.0 # failed exploit raises detection self.detection_score += 3.0 # detection check if self.detection_score >= 100.0: reward -= 50.0 done = True if self.steps >= self.max_steps: done = True return self._get_obs(), reward, done, {'detected': self.detection_score >= 100.0}
04 / defense agent

Network Defense Agent

The blue team agent must decide, at each timestep, which nodes to patch, monitor, or isolate — with limited budget and incomplete visibility into attacker actions.

class DefenderEnv: """ Blue team environment: observe network alerts and respond. State: alert vector per node + current patch status + attacker proximity Actions: (patch node i), (isolate node i), (deploy honeypot at i), (monitor i) Reward: + per day without critical compromise, - per compromised node """ ACTIONS = ['patch', 'isolate', 'honeypot', 'monitor'] def __init__(self, n_nodes=20, budget_per_step=3): self.n_nodes = n_nodes self.budget = budget_per_step self.patched = np.zeros(n_nodes, dtype=bool) self.isolated = np.zeros(n_nodes, dtype=bool) self.honeypots = np.zeros(n_nodes, dtype=bool) self.alerts = np.zeros(n_nodes) # IDS alert levels self.compromised = np.zeros(n_nodes, dtype=bool) def get_obs(self): # partial observability: defender sees alerts, not true compromise state noisy_alerts = self.alerts + np.random.normal(0, 0.1, self.n_nodes) return np.concatenate([ noisy_alerts, self.patched.astype(float), self.isolated.astype(float), self.honeypots.astype(float), ]) def step(self, actions: List[Tuple[str, int]]): """ actions: list of (action_type, node_id) tuples, up to budget Returns: (obs, reward, info) """ reward = 1.0 # base reward per step (uptime) for act_type, node in actions[:self.budget]: if act_type == 'patch': self.patched[node] = True reward += 0.5 elif act_type == 'isolate': self.isolated[node] = True if self.compromised[node]: reward += 5.0 # caught an active intrusion self.compromised[node] = False elif act_type == 'honeypot': self.honeypots[node] = True elif act_type == 'monitor': if self.compromised[node]: self.alerts[node] = min(1.0, self.alerts[node] + 0.3) # penalize undetected critical compromises critical_nodes = [0, 5, 10] # e.g. domain controller, DB, etc. reward -= 10.0 * sum(self.compromised[n] for n in critical_nodes) return self.get_obs(), reward, {'compromised_count': self.compromised.sum()}
05 / ids

Intrusion Detection with RL

Standard IDS uses static thresholds. An RL-based IDS agent learns an adaptive policy: given a stream of network events, decide at each timestep whether to flag, investigate, or block — balancing false positive cost against missed detection cost.

import torch import torch.nn as nn class IDSAgent(nn.Module): """ LSTM-based IDS agent for sequential network traffic classification. Input: sequence of flow feature vectors (bytes, packets, duration, flags) Output: action probabilities — (allow, alert, block) Uses LSTM to capture temporal dependencies in traffic patterns. """ def __init__(self, feature_dim=20, hidden=128, n_actions=3): super().__init__() self.lstm = nn.LSTM(feature_dim, hidden, batch_first=True) self.actor = nn.Sequential(nn.Linear(hidden, hidden // 2), nn.ReLU(), nn.Linear(hidden // 2, n_actions)) self.critic = nn.Sequential(nn.Linear(hidden, hidden // 2), nn.ReLU(), nn.Linear(hidden // 2, 1)) def forward(self, flow_seq, hidden_state=None): # flow_seq: (batch, seq_len, feature_dim) lstm_out, new_hidden = self.lstm(flow_seq, hidden_state) last = lstm_out[:, -1, :] # last timestep output probs = torch.softmax(self.actor(last), dim=-1) value = self.critic(last).squeeze(-1) return probs, value, new_hidden def ids_reward(action, true_label, fp_cost=1.0, fn_cost=10.0, tp_reward=5.0): """ Asymmetric reward for IDS decisions. fn_cost >> fp_cost: missing an attack is far worse than a false alarm. action: 0=allow, 1=alert, 2=block true_label: 0=benign, 1=attack """ if true_label == 0: # benign traffic if action == 0: return 0.1 # true negative if action == 1: return -fp_cost # false positive (alert) if action == 2: return -fp_cost * 2 # false positive (block) — higher cost else: # attack traffic if action == 0: return -fn_cost # false negative — missed attack if action == 1: return tp_reward * 0.5 # true positive (alert) if action == 2: return tp_reward # true positive (block)
06 / evasion

Adversarial ML Evasion with RL

An RL agent can learn to generate adversarial examples that evade an ML-based malware classifier. The reward is the classifier's confidence in the benign class, and the action space is perturbations to the malware's binary features.

class MalwareEvasionEnv: """ RL environment for learning adversarial malware evasion. State: current feature vector of the modified malware sample Actions: toggle individual binary features (function calls, API imports, sections) Reward: - classifier confidence in 'malware' class (maximize evasion) Constraint: functionality must be preserved (content features fixed) """ def __init__(self, classifier, original_features, mutable_features, max_mods=10): """ classifier: trained sklearn/torch model for malware detection original_features: 1D numpy array of original sample features mutable_features: list of feature indices that can be safely perturbed """ self.clf = classifier self.orig = original_features.copy() self.mutable = mutable_features self.max_mods = max_mods self.current = original_features.copy() self.n_mods = 0 def reset(self): self.current = self.orig.copy() self.n_mods = 0 return self.current def step(self, feature_idx): """Toggle feature at mutable_features[feature_idx].""" real_idx = self.mutable[feature_idx % len(self.mutable)] self.current[real_idx] ^= 1 # flip binary feature self.n_mods += 1 # query classifier for malware confidence prob_malware = self.clf.predict_proba([self.current])[0][1] reward = -prob_malware # reward evasion (low malware prob) evaded = prob_malware < 0.5 done = evaded or self.n_mods >= self.max_mods if evaded: reward += 10.0 # bonus for successful evasion return self.current.copy(), reward, done, {'evaded': evaded}

08 / reward design

Reward Design for Security Tasks

Reward shaping is critical in security RL. Sparse rewards (only at compromise/detection) lead to very slow learning. Dense rewards require careful design to avoid unintended behaviors.

Common reward design mistakes: - Rewarding only terminal states (too sparse) - Rewarding discovery without exploitation (agent just scans forever) - Symmetric false-positive / false-negative costs (FN should cost more) - Not penalizing detection risk (agent ignores stealth requirement) Reward shaping principles: 1. Dense intermediate rewards (exploration, discovery, partial progress) 2. Asymmetric costs matching operational priorities (FN >> FP for IDS) 3. Potential-based shaping: F(s,s') = gamma*Phi(s') - Phi(s) (policy invariant) 4. Curriculum: start with easy topologies, gradually increase complexity
Dual-Use Warning RL-based attack agents can be genuinely dangerous if misused. All research in this module is intended for authorized testing, red team exercises, and building better defenses. Never deploy attack agents against systems you do not own or have explicit written permission to test.
