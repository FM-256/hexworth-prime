Reinforcement Learning — Module 07

Multi-Agent Reinforcement Learning

When multiple agents share an environment, each agent's optimal behavior depends on all others. MARL addresses cooperative, competitive, and mixed settings — from network intrusion teams to financial markets.

01 / fundamentals

MARL Fundamentals

Single-agent RL assumes a stationary environment. In MARL, the environment is non-stationary from each agent's perspective because other agents are also learning and changing their policies. This breaks the convergence guarantees of standard RL algorithms.

Decentralized Partially Observable MDP (Dec-POMDP): N agents, each with local observation o_i (not full state s) Each agent i has its own policy: pi_i(a_i | o_i) Joint action: a = (a_1, ..., a_N) Global reward: r(s, a) — shared in cooperative tasks Individual rewards: r_i(s, a) — competitive tasks Challenge: Non-stationarity From agent i's view: environment transitions depend on a_{-i} Other agents' policies change during training → moving target problem
02 / taxonomy

MARL Taxonomy

Fully Cooperative

All agents share a single global reward. Goal: maximize team performance. Example: robot swarm coordination, multi-UAV coverage.

Fully Competitive

Zero-sum: one agent's gain is another's loss. Nash equilibrium is the solution concept. Example: poker, chess, adversarial red vs blue.

Mixed (General-Sum)

Agents have partially overlapping goals. Example: trading markets, network congestion control, negotiation.

Team Competition

Cooperative within a team, competitive between teams. Example: 5v5 game AI, red team vs blue team security simulation.

03 / ctde

Centralized Training, Decentralized Execution (CTDE)

CTDE is the dominant MARL paradigm. During training, agents share observations and a central critic has access to global state. At execution time, each agent acts using only its local observation — enabling deployment in environments without a central coordinator.

Training: Central Critic: Q(s, a_1, ..., a_N) — uses full state + all actions Agents share experiences via shared replay buffer or shared parameters Execution: Agent i: a_i = pi_i(o_i) — only local observation No communication required at deployment Algorithms using CTDE: MADDPG — continuous actions, cooperative/competitive QMIX — cooperative, factorized Q-function MAPPO — PPO with centralized value function
04 / iql

Independent Q-Learning (IQL)

The simplest MARL baseline: treat other agents as part of the environment and train each agent independently with Q-learning. Ignores the non-stationarity problem, but works surprisingly well in practice for loosely coupled agents.

import numpy as np from collections import defaultdict class IQLAgent: """ Independent Q-Learner: standard Q-learning treating other agents as noise. Each agent maintains its own Q-table indexed by local observation. """ def __init__(self, agent_id, n_actions, alpha=0.1, gamma=0.99, epsilon=0.1): self.id = agent_id self.n_actions = n_actions self.alpha = alpha self.gamma = gamma self.epsilon = epsilon self.Q = defaultdict(lambda: np.zeros(n_actions)) def select_action(self, obs): if np.random.rand() < self.epsilon: return np.random.randint(self.n_actions) return int(np.argmax(self.Q[obs])) def update(self, obs, action, reward, next_obs, done): best_next = np.max(self.Q[next_obs]) * (1 - done) td_target = reward + self.gamma * best_next self.Q[obs][action] += self.alpha * (td_target - self.Q[obs][action]) def run_iql(env, n_agents, n_episodes=10_000): """Run IQL on a multi-agent environment with n_agents agents.""" agents = [IQLAgent(i, env.action_space[i].n) for i in range(n_agents)] rewards_log = [] for ep in range(n_episodes): obs, _ = env.reset() # obs is a dict/list per agent done = {i: False for i in range(n_agents)} ep_rew = np.zeros(n_agents) while not all(done.values()): actions = {i: agents[i].select_action(obs[i]) for i in range(n_agents)} next_obs, rewards, terminateds, truncateds, _ = env.step(actions) for i in range(n_agents): d = terminateds[i] or truncateds[i] agents[i].update(obs[i], actions[i], rewards[i], next_obs[i], d) done[i] = d ep_rew[i] += rewards[i] obs = next_obs rewards_log.append(ep_rew.sum()) return agents, rewards_log
05 / maddpg

Multi-Agent DDPG (MADDPG)

MADDPG extends CTDE to continuous action spaces. Each agent i has its own actor pi_i(o_i) but a centralized critic Q_i(s, a_1,...,a_N) that observes the joint state and all agents' actions during training.

import torch import torch.nn as nn class MADDPGCritic(nn.Module): """ Centralized critic for agent i: takes global state + all agents' actions. obs_dim: dimension of global state (concatenated all agent obs) all_act_dim: sum of all agents' action dimensions """ def __init__(self, obs_dim, all_act_dim, hidden=256): super().__init__() self.net = nn.Sequential( nn.Linear(obs_dim + all_act_dim, hidden), nn.ReLU(), nn.Linear(hidden, hidden), nn.ReLU(), nn.Linear(hidden, 1), ) def forward(self, global_obs, all_actions): # concatenate full state and all agents' actions x = torch.cat([global_obs, all_actions], dim=-1) return self.net(x).squeeze(-1) class MADDPGActor(nn.Module): """Decentralized actor: only uses local observation at execution time.""" def __init__(self, obs_dim, action_dim, hidden=128): super().__init__() self.net = nn.Sequential( nn.Linear(obs_dim, hidden), nn.ReLU(), nn.Linear(hidden, hidden), nn.ReLU(), nn.Linear(hidden, action_dim), nn.Tanh(), # bounded actions ) def forward(self, local_obs): return self.net(local_obs) def maddpg_critic_loss(critic, target_critic, target_actors, batch, gamma=0.99): """ Compute critic loss for one agent in MADDPG. batch: dict with 'obs' (all agents), 'actions' (all), 'rewards' (agent i), 'next_obs' (all), 'dones' (agent i) """ obs, actions, rewards = batch['obs'], batch['actions'], batch['rewards'] next_obs, dones = batch['next_obs'], batch['dones'] with torch.no_grad(): # compute all target actions using target actor networks target_actions = torch.cat( [ta(next_obs[j]) for j, ta in enumerate(target_actors)], dim=-1 ) global_next_obs = torch.cat(next_obs, dim=-1) next_q = target_critic(global_next_obs, target_actions) td_target = rewards + gamma * next_q * (1 - dones) global_obs = torch.cat(obs, dim=-1) all_actions = torch.cat(actions, dim=-1) q_pred = critic(global_obs, all_actions) return nn.functional.mse_loss(q_pred, td_target)
06 / qmix

QMIX: Value Decomposition for Cooperative Agents

In cooperative settings, QMIX decomposes the joint Q-function into per-agent utility functions Q_i(o_i, a_i) combined through a monotone mixing network. This guarantees that the greedy joint action equals the combination of individual greedy actions — enabling decentralized execution.

Joint Q-function factorization: Q_tot(s, a_1,...,a_N) = f(Q_1(o_1,a_1), ..., Q_N(o_N,a_N); s) f is a monotone mixing network (all weights non-negative via abs()) Monotonicity ensures: argmax Q_tot = (argmax Q_1, ..., argmax Q_N) Mixing Network: Input: Q_1, ..., Q_N (scalar utilities) Hidden: weights generated by hypernetwork conditioned on global state s Output: Q_tot (scalar) Why monotonicity matters: Agents can act greedily on their own Q_i → decentralized execution No need for joint optimization at execution time

08 / security

MARL for Security Applications

Red vs blue team simulation maps naturally onto competitive MARL. Red agents (attackers) and blue agents (defenders) each learn optimal strategies against adaptive opponents — producing more robust security policies than hand-crafted rules.

class NetworkSecurityEnv: """ Simplified red vs blue environment. Red agent: chooses exploitation paths through a network graph. Blue agent: chooses which nodes to patch or monitor. State: (node_compromised[N], node_patched[N], alert_level) """ def __init__(self, n_nodes=10, n_services=3): self.n_nodes = n_nodes self.n_services = n_services self.compromised = np.zeros(n_nodes, dtype=bool) self.patched = np.zeros(n_nodes, dtype=bool) self.alert_level = 0 def red_step(self, target_node, service): """Red agent attempts exploitation.""" reward = 0.0 success_prob = 0.7 if not self.patched[target_node] else 0.1 if np.random.rand() < success_prob: self.compromised[target_node] = True reward += 10.0 # reward for compromise self.alert_level += 1 # exploitation increases noise return reward def blue_step(self, node_to_patch, node_to_monitor): """Blue agent patches vulnerability and monitors a node.""" reward = 0.0 self.patched[node_to_patch] = True if self.compromised[node_to_monitor]: reward += 5.0 # reward for detecting compromise self.compromised[node_to_monitor] = False # remediation reward -= 0.1 * self.alert_level # cost of unpatched alerts return reward def get_red_obs(self): return np.concatenate([self.compromised.astype(float), self.patched.astype(float), [self.alert_level / 100.0]]) def get_blue_obs(self): # blue has partial observation: sees alerts but not full compromise state visible = self.compromised & (np.random.rand(self.n_nodes) > 0.5) return np.concatenate([visible.astype(float), self.patched.astype(float), [self.alert_level / 100.0]])
09 / challenges

Key MARL Challenges

Challenge Description Mitigation
Non-stationarity Other agents' policies change during training CTDE, opponent modeling, experience replay with age filtering
Credit assignment Which agent deserves credit for team reward? QMIX, COMA (counterfactual baseline), difference rewards
Scalability Joint action space grows exponentially with N agents Value decomposition (QMIX), mean-field approximation
Communication How should agents share information? CommNet, DIAL, attention-based communication protocols
Equilibrium selection Multiple Nash equilibria; which to converge to? Self-play, fictitious play, population-based training
Self-Play: The Foundation of Game-Playing AI AlphaGo, AlphaStar, and OpenAI Five all use self-play: agents train against past versions of themselves. This creates a curriculum of gradually improving opponents, avoiding the instability of two fully adversarial agents learning simultaneously.
PettingZoo: MARL Environments PettingZoo (pip install pettingzoo) provides a standardized API for MARL environments analogous to Gymnasium for single-agent RL. Includes classic board games, Atari multi-player, MPE (multi-particle environments), and SISL cooperative tasks.
