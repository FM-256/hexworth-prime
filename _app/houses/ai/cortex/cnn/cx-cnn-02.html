The CNN Pipeline

A convolutional neural network processes input through a feature extraction stage (conv + pool layers) followed by a classification head (flatten + fully connected layers). Understanding why each stage exists and what it contributes is essential for designing and debugging architectures.

Canonical CNN Architecture
  Input Image
  (3, 224, 224)
       |
  [ Conv2d + ReLU ]   -- extracts local features
  [ Pool ]            -- downsamples, increases invariance
  [ Conv2d + ReLU ]   -- extracts higher-level features
  [ Pool ]
  [ Conv2d + ReLU ]
  [ Pool ]
       |
  [ Flatten ]         -- converts 3D tensor to 1D vector
       |
  [ Linear + ReLU ]   -- learns global combinations of features
  [ Dropout ]         -- regularization
  [ Linear ]          -- maps to class scores (logits)
       |
  [ Softmax ]         -- converts to probabilities (at inference)
  Class Predictions

Convolutional Layers

Each conv layer is followed by a nonlinear activation — almost always ReLU in modern networks. Without nonlinearity, stacking multiple linear (conv) layers is equivalent to a single linear transformation, no matter how deep the network goes. ReLU introduces nonlinearity while being computationally cheap and avoiding vanishing gradients for positive activations.

ReLU: f(x) = max(0, x) Most common. Zero-cost gradient for positive activations. Risk of "dying ReLU" (neuron always outputs 0) when weights push all inputs negative.
Leaky ReLU: f(x) = max(0.01x, x) Fixes dying ReLU by allowing small negative gradient. Slope for negative inputs (0.01) is a hyperparameter.
GELU: Gaussian Error Linear Unit Used in Transformers and modern CNNs. Smooth, differentiable everywhere. Slightly more expensive than ReLU.
Batch Normalization Typically inserted after conv and before activation. Normalizes activations across the batch, stabilizing training and enabling higher learning rates.

Pooling Layers

Pooling layers reduce spatial dimensions without learnable parameters. They provide spatial translation invariance (small shifts in input produce same output) and reduce computation for subsequent layers. The two main types are max pooling and average pooling.

TypeOperationWhen to Use
Max Pool Takes the maximum value in each pool window. Retains strongest activation (presence of feature). Feature extraction, object detection. Preferred in most classification CNNs.
Avg Pool Takes average of values in pool window. Smoother, preserves spatial information better. Global context pooling, style transfer. Less aggressive than max pool.
Global Avg Pool Averages each entire feature map to a single value. Output: one value per channel. Replaces flatten + FC head in modern networks. Reduces parameters and overfitting.
Strided Conv Conv layer with stride 2 as downsampler. Learns which features to preserve. Used in ResNet and modern architectures instead of explicit pooling layers.

Why Global Average Pooling?

Traditional CNNs flatten the last feature maps to a large vector, then use FC layers. A 7x7x512 feature map flattened is 25,088 values -- the first FC layer then has millions of parameters. Global Average Pooling replaces this by averaging each feature map to one value, giving a 512-element vector directly. This dramatically reduces parameters and acts as implicit regularization.

Fully Connected Layers

After the convolutional feature extractor reduces the spatial dimensions, the classification head uses fully connected (Linear) layers to map extracted features to class scores. Every neuron connects to every input, allowing the network to learn arbitrary global combinations of the extracted features.

Dropout is typically applied in FC layers during training. With probability p, each neuron's output is set to zero. This prevents co-adaptation and acts as ensemble training over exponentially many subnetworks.

FC Layer Parameter Count

A Conv2d(512, 512, 3) layer has 512 * 512 * 3 * 3 = 2.36M parameters. A Linear(25088, 4096) layer (common in VGG) has 25088 * 4096 = 102.8M parameters. The FC layers often contain the majority of a classic CNN's parameters, which is one reason modern designs use GAP or smaller heads.

Batch Normalization

Batch Normalization (BatchNorm) normalizes the activations of a layer across the mini-batch, then scales and shifts with learnable parameters gamma and beta. This stabilizes training by reducing internal covariate shift — the change in activation distributions as earlier layers update.

BatchNorm Forward Pass
  Given mini-batch B = {x_1, ..., x_m}:

  1. mean:    mu_B  = (1/m) * SUM x_i
  2. variance: sig_B = (1/m) * SUM (x_i - mu_B)^2
  3. normalize: x_hat = (x - mu_B) / sqrt(sig_B + eps)
  4. scale+shift: y = gamma * x_hat + beta

  gamma, beta are learnable; eps ~ 1e-5 prevents div-by-zero

  At inference: uses running mean/var accumulated during training
  (not batch stats -- batch size could be 1)

BatchNorm allows much higher learning rates, reduces dependence on careful initialization, and provides mild regularization. It is placed after the conv/linear operation and before the activation function in most designs.

Building a CNN in PyTorch

PyTorch — Simple CNN for CIFAR-10 (10 classes, 32x32 RGB)
import torch
import torch.nn as nn

class SimpleCNN(nn.Module):
    def __init__(self, num_classes=10):
        super().__init__()

        # Feature extractor: 3 conv blocks
        self.features = nn.Sequential(
            # Block 1: 32x32x3 -> 32x32x32
            nn.Conv2d(3, 32, kernel_size=3, padding=1),
            nn.BatchNorm2d(32),
            nn.ReLU(inplace=True),
            nn.MaxPool2d(2, 2),            # -> 16x16x32

            # Block 2: 16x16x32 -> 16x16x64
            nn.Conv2d(32, 64, kernel_size=3, padding=1),
            nn.BatchNorm2d(64),
            nn.ReLU(inplace=True),
            nn.MaxPool2d(2, 2),            # -> 8x8x64

            # Block 3: 8x8x64 -> 8x8x128
            nn.Conv2d(64, 128, kernel_size=3, padding=1),
            nn.BatchNorm2d(128),
            nn.ReLU(inplace=True),
            nn.MaxPool2d(2, 2)             # -> 4x4x128
        )

        # Classification head
        self.classifier = nn.Sequential(
            nn.Flatten(),                   # -> 4*4*128 = 2048
            nn.Linear(2048, 512),
            nn.ReLU(inplace=True),
            nn.Dropout(0.5),
            nn.Linear(512, num_classes)
        )

    def forward(self, x):
        x = self.features(x)
        x = self.classifier(x)
        return x

# Instantiate and inspect
model = SimpleCNN(num_classes=10)
total_params = sum(p.numel() for p in model.parameters())
print(f"Total parameters: {total_params:,}")
# Total parameters: 1,172,618

# Verify forward pass shape
x = torch.randn(4, 3, 32, 32)
out = model(x)
print(out.shape)  # torch.Size([4, 10])

Key Takeaways

  • CNNs follow a feature extractor (conv+pool) then classifier (flatten/GAP + FC) pipeline
  • ReLU nonlinearity after each conv is essential -- linear-only stacks collapse to a single layer
  • Max pooling selects strongest activations; average pooling preserves spatial statistics
  • Global Average Pooling replaces the large flatten+FC stage, cutting parameters dramatically
  • Batch Normalization normalizes activations per-batch, stabilizes training, allows higher LR
  • Dropout in FC layers prevents co-adaptation and acts as implicit ensemble regularization
  • Effective receptive field grows with each pooling and conv layer -- design depth accordingly
