Why Efficiency Matters

ResNet-50 requires ~4 billion floating point operations (FLOPs) and 25M parameters per forward pass. Running this on a mobile phone or edge device is impractical for real-time applications. Efficient CNN design makes inference fast enough for phones, IoT sensors, drones, and embedded systems without sacrificing too much accuracy.

Mobile Deployment Smartphone cameras, AR apps, offline classification. Battery constraints prohibit large models. Target: <5ms inference on mobile CPU/GPU.
Edge Devices Security cameras, drones, autonomous vehicles. Dedicated NPUs (Neural Processing Units) accelerate certain operation patterns (e.g., depthwise conv).
Server Throughput Larger models = fewer requests/second = higher cost. Quantization and pruning increase throughput 2-4x on GPU without retraining.
Carbon Footprint Training large models emits significant CO2. Efficient architectures that achieve same accuracy with less compute reduce environmental impact.

Depthwise Separable Convolution

Standard convolution applies a 3D filter (C_in x k x k) at each position, mixing spatial and channel information simultaneously. Depthwise separable convolution factorizes this into two steps: a depthwise conv (spatial only, one filter per input channel) followed by a 1x1 pointwise conv (channel mixing only). This reduces computation by roughly 8-9x for 3x3 kernels.

Parameter Count Comparison (C_in=C_out=C, kernel=k)
  Standard Conv:               C * C * k * k = C^2 * k^2

  Depthwise Separable:
    Depthwise:  C * 1 * k * k = C * k^2   (one filter per channel)
    Pointwise:  C * C * 1 * 1 = C^2        (mix channels)
    Total:      C * k^2 + C^2

  Reduction ratio:  (C * k^2 + C^2) / (C^2 * k^2)
                 = 1/C + 1/k^2

  For k=3, C=128:  1/128 + 1/9 = 0.12 --> ~8x fewer parameters
PyTorch -- depthwise separable convolution block
class DepthwiseSeparableConv(nn.Module):
    def __init__(self, in_ch, out_ch, stride=1):
        super().__init__()
        self.net = nn.Sequential(
            # Depthwise: groups=in_ch means each channel has its own filter
            nn.Conv2d(in_ch, in_ch, kernel_size=3, stride=stride,
                      padding=1, groups=in_ch, bias=False),
            nn.BatchNorm2d(in_ch),
            nn.ReLU6(inplace=True),
            # Pointwise: 1x1 conv to mix channels
            nn.Conv2d(in_ch, out_ch, kernel_size=1, bias=False),
            nn.BatchNorm2d(out_ch),
            nn.ReLU6(inplace=True),
        )
    def forward(self, x): return self.net(x)

Compound Scaling (EfficientNet)

Previous work scaled depth, width, or resolution independently. EfficientNet introduces compound scaling: given a resource budget (FLOP constraint), scale all three dimensions simultaneously using a fixed ratio derived by grid search. This outperforms independently scaled networks at every budget level because depth, width, and resolution are dependent -- bigger images need deeper networks to capture fine-grained detail, which need wider networks for sufficient representational capacity.

Model Pruning

Pruning removes redundant weights or structures from a trained model. The Lottery Ticket Hypothesis (Frankle & Carlin, 2018) shows that random networks contain sparse subnetworks ("winning tickets") that can match full network performance when trained in isolation from initialization.

TypeWhat Is RemovedHardware Benefit
UnstructuredIndividual weights set to zero (magnitude thresholding). Creates sparse weight matrices.Requires sparse matrix hardware (limited); good for compression
StructuredEntire filters, channels, or layers removed. Reduces tensor dimensions.Direct speedup on any hardware -- fewer channels = fewer MACs
IterativePrune-retrain-prune cycle. Train, prune 10%, fine-tune, repeat.Recovers accuracy lost from one-shot pruning

Quantization

Standard neural networks use 32-bit floating point (FP32) weights. Quantization reduces weight precision to 8-bit integers (INT8) or even 4-bit, trading a small accuracy loss for 4x memory reduction and 2-4x faster inference on CPUs and specialized hardware.

PyTorch -- post-training static quantization
import torch.quantization

model.eval()

# Step 1: Configure for quantization
model.qconfig = torch.quantization.get_default_qconfig('fbgemm')
# 'fbgemm' = x86 CPU, 'qnnpack' = mobile/ARM

# Step 2: Prepare (insert observers to collect activation statistics)
model_prepared = torch.quantization.prepare(model)

# Step 3: Calibrate with representative data (~100-1000 samples)
with torch.no_grad():
    for images, _ in calibration_loader:
        model_prepared(images)

# Step 4: Convert to quantized model
model_int8 = torch.quantization.convert(model_prepared)

# Result: weights in INT8, activations quantized at runtime
# Typical: 4x smaller model, 2-3x faster inference on CPU

Knowledge Distillation

Knowledge distillation (Hinton et al., 2015) trains a small "student" model to mimic a large "teacher" model. The student learns from the teacher's soft probability outputs (which carry more information than hard one-hot labels) rather than from the raw training labels. The result is a compact model that exceeds what could be achieved training the small model directly.

PyTorch -- knowledge distillation training loop
def distillation_loss(student_logits, teacher_logits, labels,
                         T=4.0, alpha=0.7):
    """
    T:     temperature -- higher T = softer teacher distribution
    alpha: weight for distillation loss vs hard label loss
    """
    # Soft targets from teacher at temperature T
    soft_teacher = F.softmax(teacher_logits / T, dim=1)
    soft_student = F.log_softmax(student_logits / T, dim=1)

    # KL divergence loss (distillation)
    distill = F.kl_div(soft_student, soft_teacher, reduction='batchmean') * (T ** 2)

    # Hard label loss (standard CE)
    ce_loss = F.cross_entropy(student_logits, labels)

    return alpha * distill + (1 - alpha) * ce_loss

Key Takeaways

  • Depthwise separable conv = depthwise (spatial) + pointwise (channel): ~8-9x fewer params for 3x3
  • MobileNet uses depthwise separable convs throughout; V2 adds inverted residuals with linear bottlenecks
  • EfficientNet compound scaling jointly optimizes depth, width, and resolution under a FLOP budget
  • Structured pruning removes entire channels/filters and gives direct hardware speedup
  • INT8 quantization: 4x smaller model, 2-4x faster inference, minimal accuracy loss with calibration
  • Knowledge distillation trains small students on teacher soft outputs -- beats direct training of small models
