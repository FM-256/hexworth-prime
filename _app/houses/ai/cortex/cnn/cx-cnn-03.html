Architecture Evolution

The history of CNNs is a story of solving concrete engineering problems: reducing parameters, enabling deeper training, capturing multi-scale features. Each landmark architecture introduced one or two key ideas that the field adopted universally. Understanding this lineage is not nostalgia -- these ideas directly inform how modern architectures are designed.

LeNet-5 1998 -- LeCun et al.
The original practical CNN, designed for handwritten digit recognition (MNIST). Established the conv-pool-conv-pool-FC pattern. Trained on CPU, 32x32 inputs. Proved that local feature detection via shared weights could outperform hand-crafted features for recognition tasks.
~60K params 2 conv + 2 pool + 3 FC Input: 32x32
AlexNet 2012 -- Krizhevsky, Sutskever, Hinton
Won ILSVRC 2012 by a massive margin (top-5 error: 15.3% vs 26.2% runner-up), launching the deep learning revolution. Key innovations: ReLU instead of tanh (faster training), GPU training, dropout for regularization, data augmentation, overlapping max pooling, Local Response Normalization (LRN). First deep CNN to demonstrate the power of scale.
~60M params 5 conv + 3 FC Input: 224x224
VGGNet (VGG-16 / VGG-19) 2014 -- Simonyan, Zisserman
Systematic study showing that depth (using very small 3x3 convolutions consistently) is key to performance. Two stacked 3x3 conv layers have the same receptive field as one 5x5 layer but fewer parameters and an extra ReLU. Extremely clean, regular design. Despite 138M parameters (mostly in FC layers), it remained a dominant transfer learning backbone for years due to its feature quality.
~138M params 13-16 conv + 3 FC All 3x3 kernels
GoogLeNet / Inception v1 2014 -- Szegedy et al.
Winner of ILSVRC 2014. Introduced the Inception module: process input with 1x1, 3x3, and 5x5 conv in parallel, concatenate results. Captures multi-scale features in one layer. Used 1x1 convolutions as bottlenecks to reduce channel depth before expensive 3x3/5x5 ops. Only 6.8M parameters despite 22 layers -- dramatically more parameter-efficient than VGG.
~6.8M params 22 layers Inception modules
ResNet (ResNet-50 / 101 / 152) 2015 -- He et al., Microsoft Research
Won ILSVRC 2015 with 3.57% top-5 error (surpassing human-level 5.1%). Introduced residual connections (skip connections): the output of a block is F(x) + x. This allows gradients to flow directly through the skip connection during backprop, solving the degradation problem (deeper networks performing worse than shallower ones). Enabled training of 100+ layer networks. ResNet remains the most widely used CNN backbone in production.
~25M params (ResNet-50) 50-152 layers Bottleneck blocks

The Inception Module

The core innovation of GoogLeNet is the Inception module, which processes the same input with multiple filter sizes simultaneously and concatenates results along the channel axis. The 1x1 convolution is the secret weapon: it reduces channel depth (and therefore computation) before the expensive 3x3 and 5x5 operations.

Inception Module (with dimensionality reduction)
              Input (H x W x C)
                   |
     +-------------+-------------+-------------+
     |             |             |             |
  1x1 Conv      1x1 Conv      1x1 Conv     MaxPool
   (C -> n1)   (C -> n2)    (C -> n3)     3x3, s1
                  |             |             |
               3x3 Conv      5x5 Conv     1x1 Conv
              (n2 -> m2)   (n3 -> m3)   (C -> n4)
                  |             |
     +------------+-------------+-------------+
                        |
               Concatenate along channel axis
               Output: (H x W x [n1 + m2 + m3 + n4])

The 1x1 convolution (also called a "network in network" or "pointwise convolution") is a key building block across modern architectures. It acts as a learned linear projection across channels at each spatial position, allowing channel count expansion or compression with minimal compute cost.

Residual Connections

Deep plain networks suffer from degradation: adding more layers makes training accuracy worse, even on training data. This is not an overfitting problem -- it is an optimization problem. Residual connections solve this by reformulating layer learning as F(x) + x instead of H(x).

Residual Block (ResNet Basic Block)
  Input x
    |
    +------------ (shortcut / skip connection) ----------+
    |                                                     |
  Conv2d (3x3)                                           |
  BatchNorm                                              |
  ReLU                                                   |
  Conv2d (3x3)                                           |
  BatchNorm                                              |
    |                                                     |
    +------ Add ( F(x) + x ) --------------------------+
    |
  ReLU
  Output

  If dimensions don't match (different channel count or stride):
  -- shortcut uses a 1x1 Conv2d to project x to correct shape

Why Residual Connections Work

If the optimal function for a block is the identity (the input does not need to change), a plain network must learn to produce identity through its weights -- difficult. With a residual connection, the network only needs F(x) = 0, which is far easier to learn. Gradient highway: during backpropagation, the gradient flows directly through the skip connection to earlier layers without being diminished by matrix multiplications.

PyTorch -- ResNet BasicBlock implementation
class BasicBlock(nn.Module):
    def __init__(self, in_channels, out_channels, stride=1):
        super().__init__()
        self.conv1 = nn.Conv2d(in_channels, out_channels, 3, stride=stride, padding=1, bias=False)
        self.bn1 = nn.BatchNorm2d(out_channels)
        self.conv2 = nn.Conv2d(out_channels, out_channels, 3, padding=1, bias=False)
        self.bn2 = nn.BatchNorm2d(out_channels)
        self.relu = nn.ReLU(inplace=True)

        # Shortcut projection when dimensions change
        self.shortcut = nn.Sequential()
        if stride != 1 or in_channels != out_channels:
            self.shortcut = nn.Sequential(
                nn.Conv2d(in_channels, out_channels, 1, stride=stride, bias=False),
                nn.BatchNorm2d(out_channels)
            )

    def forward(self, x):
        out = self.relu(self.bn1(self.conv1(x)))
        out = self.bn2(self.conv2(out))
        out += self.shortcut(x)   # residual addition
        out = self.relu(out)
        return out

Using Pretrained Models

ImageNet-pretrained models are the starting point for nearly all production vision tasks. Transfer learning from these models dramatically reduces training data requirements and training time. torchvision provides all classic architectures with pretrained weights.

PyTorch + torchvision -- pretrained ResNet-50 for feature extraction
import torchvision.models as models
import torch.nn as nn

# Load ImageNet-pretrained ResNet-50
model = models.resnet50(weights=models.ResNet50_Weights.IMAGENET1K_V2)

# Option 1: Fine-tune only the final FC layer
for param in model.parameters():
    param.requires_grad = False           # freeze all layers

num_features = model.fc.in_features         # 2048 for ResNet-50
model.fc = nn.Linear(num_features, 5)     # replace head for 5-class task
# Only model.fc parameters will be trained

# Option 2: Feature extractor (no head)
feature_extractor = nn.Sequential(*list(model.children())[:-1])
# Removes final FC; output is (N, 2048, 1, 1) after GAP

x = torch.randn(1, 3, 224, 224)
features = feature_extractor(x)
print(features.shape)  # torch.Size([1, 2048, 1, 1])

Key Takeaways

  • LeNet established the conv-pool-FC blueprint; AlexNet scaled it to GPUs and launched deep learning
  • VGG proved that 3x3 kernels stacked deep outperform larger kernels -- simplicity enables depth
  • Inception modules process multiple scales in parallel; 1x1 convs reduce computation as bottlenecks
  • Residual connections (F(x) + x) solve degradation: gradients flow directly through skip connections
  • ResNet-50 achieves better accuracy than VGG-16 with 5x fewer parameters
  • Pretrained models from ImageNet are the default starting point for production vision tasks
