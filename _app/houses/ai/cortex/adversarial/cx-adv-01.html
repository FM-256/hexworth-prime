Learning Objectives

  • Define the four primary adversarial ML attack categories: evasion, poisoning, extraction, inference
  • Map each attack to real-world deployment contexts where it applies

  • Understand the MITRE ATLAS framework and how it maps attacks to the ML pipeline
  • Identify the most security-critical ML deployment contexts and their dominant attack surfaces

The Four Attack Categories

Adversarial ML attacks target the machine learning pipeline at different stages. Understanding the taxonomy is the first step to building defenses because each category requires fundamentally different mitigations.

Evasion Attacks Attack inference time. Craft inputs that fool a deployed model into wrong predictions. The model and training data are unchanged. Most studied category. Examples: adversarial images, adversarial malware samples.
Poisoning Attacks Attack training time. Inject malicious data into the training set to corrupt the learned model. Can cause targeted misclassification (backdoor) or broad degradation. Examples: data poisoning, trojan attacks.
Model Extraction Attack the model IP. Query a black-box API to reconstruct a functionally equivalent model. Enables offline adversarial attacks. Can extract training data via membership inference on the stolen model.
Inference Attacks Attack privacy. Infer membership in the training set (membership inference), reconstruct training samples (model inversion), or extract private attributes. GDPR/HIPAA compliance implications.

Threat Model Dimensions

The threat model defines what the attacker knows and can do. A thorough security analysis must specify the threat model before evaluating defenses -- a defense that is strong against black-box attacks may be trivially bypassed with white-box access.

White-Box Attacker has full access: model architecture, weights, training data distribution. Can compute exact gradients. Provides the strongest attack baseline -- if a defense fails here it fails everywhere.
Grey-Box Partial access: knows architecture but not weights, or knows training data distribution. Common in practice when attacker can replicate the model architecture from a paper.
Black-Box Query-only access: can submit inputs and observe outputs. Real-world APIs are typically black-box. Attacks rely on transferability or score/decision-based query optimization.
Hard-Label Black-Box Most restrictive: attacker sees only the final class decision, not confidence scores. Gradient-free attacks (NES, SQUARE Attack) operate in this setting.

MITRE ATLAS

MITRE ATLAS (Adversarial Threat Landscape for Artificial-Intelligence Systems) extends the ATT&CK framework to ML systems. It catalogs adversary tactics, techniques, and real-world case studies across the ML lifecycle.

ATLAS Tactic Categories

  • Reconnaissance: gather information about ML systems (model type, training data, API behavior)
  • Resource Development: train proxy models, acquire training data, prepare attack infrastructure
  • Initial Access: gain access to ML systems (API, training pipeline, data storage)
  • ML Attack Staging: craft adversarial examples, prepare poisoned data, build extraction queries
  • Exfiltration: extract model, training data, or sensitive predictions
  • Impact: evasion causing misclassification, backdoor activation, performance degradation

High-Risk Deployment Contexts

Not all ML deployments carry equal risk. Adversarial ML attacks are most consequential when the attacked model makes high-stakes decisions with limited human oversight.

Practice Problems

  1. Classify each scenario as evasion, poisoning, extraction, or inference attack: (a) An attacker adds 500 mislabeled spam emails to a public email dataset used to train a spam filter. (b) A researcher submits 50,000 queries to an ML API to reproduce its behavior. (c) A malware author modifies a binary's PE header to evade an ML-based AV. (d) An analyst determines that a specific patient's records were used to train a medical AI.
  2. Explain why "security through obscurity" (hiding the model architecture) provides only weak protection against adversarial attacks. Reference the transferability property in your answer.
  3. Map a poisoning attack against a network intrusion detection system onto the MITRE ATLAS framework. Identify at least one tactic and technique from each of: reconnaissance, ML attack staging, and impact.
  4. You are deploying an ML-based malware classifier in a high-security environment. Define a complete threat model: specify the attacker's goals, capabilities (white/grey/black-box), attack categories of concern, and deployment constraints that limit attack feasibility.

Key Takeaways

  • Four attack categories: evasion (inference), poisoning (training), extraction (IP theft), inference (privacy)
  • Threat model specifies attacker knowledge: white-box (full access), grey-box (partial), black-box (query only)
  • MITRE ATLAS maps adversarial ML attacks to lifecycle stages, mirroring the ATT&CK framework structure
  • High-risk contexts: malware detection, IDS, fraud, autonomous vehicles, face recognition, medical imaging
  • Defenses must be evaluated against the appropriate threat model -- a black-box defense may fail under white-box attack
