Module 02 — AI/ML Capstone

Data Pipeline

Build the data engine that powers your model. Collection, cleaning, augmentation, and split strategy determine model ceiling more than architecture choices. Learn to build reproducible, well-documented data pipelines using real security datasets.

Duration: 50 min Level: Capstone Domain: Data Engineering, Feature Engineering

Learning Objectives

  • Build a reproducible data collection and ingestion pipeline for security data sources
  • Apply systematic data cleaning strategies addressing missing values, outliers, and noise
  • Engineer domain-relevant features from raw network logs, system events, and binary files
  • Implement stratified train/validation/test splits that respect temporal ordering in security data
  • Document data lineage and preprocessing decisions for reproducibility and audit trails

Data Collection and Ingestion

Security data rarely arrives in model-ready form. Raw data sources — Zeek logs, Windows Event Logs, PCAP captures, threat intel feeds — require careful ingestion pipelines that preserve fidelity while enabling efficient processing.

Reproducible Ingestion Pattern

import pandas as pd import hashlib, json from pathlib import Path from datetime import datetime class DataPipeline: """Reproducible data pipeline with lineage tracking.""" def __init__(self, config_path: str): with open(config_path) as f: self.config = json.load(f) self.lineage = {"steps": [], "created_at": datetime.utcnow().isoformat()} def load(self, path: str) -> pd.DataFrame: df = pd.read_csv(path) checksum = hashlib.md5(Path(path).read_bytes()).hexdigest() self.lineage["steps"].append({ "op": "load", "path": path, "checksum": checksum, "shape": df.shape }) return df def clean(self, df: pd.DataFrame) -> pd.DataFrame: before = len(df) df = df.drop_duplicates() df = df.dropna(thresh=int(df.shape[1] * 0.8)) # drop rows missing 20%+ cols df = df.fillna(df.median(numeric_only=True)) self.lineage["steps"].append({ "op": "clean", "rows_removed": before - len(df) }) return df def save_lineage(self, out_path: str): with open(out_path, 'w') as f: json.dump(self.lineage, f, indent=2, default=str)

Feature Engineering and Splitting

Raw features from network logs are often low-signal. Feature engineering transforms them into representations the model can exploit. For security data, temporal features, protocol ratios, and entropy measures are especially valuable.

Feature Engineering for Network Data

import numpy as np from scipy.stats import entropy def engineer_network_features(df: pd.DataFrame) -> pd.DataFrame: """Derive high-signal features from raw Zeek/flow records.""" df = df.copy() # Byte ratios (asymmetry is informative) df['bytes_ratio'] = df['orig_bytes'] / (df['resp_bytes'] + 1) df['pkt_ratio'] = df['orig_pkts'] / (df['resp_pkts'] + 1) # Payload size entropy across session window (group by src IP) df['payload_entropy'] = df.groupby('id_orig_h')['orig_bytes'].transform( lambda x: entropy(np.histogram(x, bins=10)[0] + 1) ) # Connection rate per source IP (rolling 60-second window) df['ts'] = pd.to_datetime(df['ts'], unit='s') df = df.sort_values('ts') df['conn_rate_1m'] = ( df.groupby('id_orig_h') .rolling('60s', on='ts')['uid'] .count() .reset_index(level=0, drop=True) ) return df def temporal_split(df, label_col, val_frac=0.15, test_frac=0.15): """Time-based split — never shuffle security time-series data.""" n = len(df) train_end = int(n * (1 - val_frac - test_frac)) val_end = int(n * (1 - test_frac)) X = df.drop(columns=[label_col]) y = df[label_col] return (X[:train_end], y[:train_end], X[train_end:val_end], y[train_end:val_end], X[val_end:], y[val_end:])
Critical: Never Shuffle Time-Series Security Data Using random train/test splits on time-ordered data leaks future information into training. An IDS model trained on shuffled data will show inflated performance metrics that collapse in production where time ordering is enforced.
Practice: Build Your Data Pipeline
  1. Download the CICIDS 2017 dataset (Friday traffic CSV, ~700MB) or use the UNSW-NB15 sample. Load it with pandas.
  2. Run the data_audit function from Module 01 on the loaded dataframe. Document all findings.
  3. Implement the engineer_network_features function. Verify that bytes_ratio and conn_rate_1m are computed correctly on a 1000-row sample.
  4. Apply temporal_split to produce 70/15/15 train/val/test sets. Verify class distribution is preserved in each split using value_counts(normalize=True).
  5. Save your pipeline lineage JSON. Confirm it records the checksum, shape, and cleaning stats.

Key Takeaways

  • Data pipelines must be reproducible — checksum source files and log every transformation step
  • Feature engineering often contributes more to model performance than architecture changes
  • Temporal splits are mandatory for time-series security data; random splits cause data leakage
  • Security datasets have extreme class imbalance (1:1000+ attack:benign is common) — plan your strategy during pipeline design, not model training
  • Document data lineage from the start; retroactive documentation is incomplete and untrustworthy
