Transformer Architecture for LLMs

Modern LLMs (GPT-3, LLaMA, Mistral, Claude) use a decoder-only Transformer stack. Unlike the original encoder-decoder (seq2seq) Transformer, decoder-only models are trained purely on next-token prediction, which scales remarkably well.

Token Embeddings Input tokens are mapped to dense vectors via a learned embedding matrix. Vocabulary sizes typically range from 32k to 128k tokens (BPE or SentencePiece tokenization).
Positional Encoding RoPE (Rotary Position Embedding) is standard in modern LLMs. Encodes relative positions via rotation of query/key vectors, enabling better length generalization than learned absolute positions.
Causal Self-Attention Each token attends to all previous tokens (causal mask). Multi-head attention with separate Q, K, V projections per head. GQA (Grouped Query Attention) reduces KV cache memory in inference.
Feed-Forward Sublayer Two linear layers with SwiGLU activation (or GELU). Dimension typically 4x the model dimension. Stores factual knowledge -- "key-value memories" hypothesis.

Scaling Laws (Chinchilla)

Hoffmann et al. (2022) showed that for a given compute budget, the optimal strategy is to scale model size and training tokens equally. A 70B model trained on 1.4T tokens outperforms a 280B model trained on 300B tokens with the same FLOP budget. This "compute-optimal" result shifted the field from "bigger model" to "more data."

Pretraining Objective

Causal language modeling (CLM) trains the model to predict the next token given all previous tokens. For a sequence of tokens x_1, ..., x_T, the loss is the average negative log-likelihood:

L_CLM = -(1/T) * sum_{t=1}^{T} log P(x_t | x_{<t}; theta)

Python / PyTorch -- Autoregressive language model training loss
import torch
import torch.nn as nn

# input_ids: (batch, seq_len) token IDs
# logits: (batch, seq_len, vocab_size) model output
def causal_lm_loss(logits, input_ids):
    # Shift: predict position t from positions 0..t-1
    # shift_logits = positions 0 to T-2 (predicting next token)
    # shift_labels = positions 1 to T-1 (the actual next tokens)
    shift_logits = logits[:, :-1, :].contiguous()
    shift_labels = input_ids[:, 1:].contiguous()
    loss = nn.functional.cross_entropy(
        shift_logits.view(-1, shift_logits.size(-1)),
        shift_labels.view(-1),
        ignore_index=-100  # ignore padding tokens
    )
    return loss

# Autoregressive generation (greedy decoding)
def generate(model, input_ids, max_new_tokens=50):
    for _ in range(max_new_tokens):
        with torch.no_grad():
            logits = model(input_ids).logits
        next_token = logits[:, -1, :].argmax(dim=-1, keepdim=True)
        input_ids = torch.cat([input_ids, next_token], dim=1)
    return input_ids

RLHF KL Penalty

During PPO fine-tuning, a KL divergence penalty between the current policy and the SFT baseline is added to the reward. Without this, the model quickly exploits reward model weaknesses -- producing responses that score high on the RM but are nonsensical ("reward hacking"). The KL coefficient is a critical hyperparameter.

Practice Problems

  2. Explain why GPT-style models use a causal mask in self-attention. What would happen to generation quality if the causal mask were removed?
  3. Describe the "reward hacking" problem in RLHF. Give a concrete example relevant to a security assistant model and explain how the KL penalty mitigates it.
  4. Implement a temperature sampling function: given logits (vocab-sized vector) and temperature T, compute probabilities and sample a token. What happens as T approaches 0? As T approaches infinity?

Key Takeaways

  • LLMs use decoder-only Transformers with causal self-attention -- each token attends only to previous tokens
  • Pretraining on trillions of tokens via next-token prediction builds world knowledge and few-shot ability
  • Chinchilla scaling laws: compute-optimal training scales model size and token count equally
  • RLHF pipeline: pretraining, SFT, reward model training, PPO optimization with KL penalty
  • DPO provides a simpler closed-form alternative to PPO for preference alignment
  • Emergent capabilities appear at scale thresholds -- not predictable from smaller model performance
