Why Code is Different

Code has properties that make it both easier and harder to generate than natural language. Easier: code has formal syntax -- a program either parses or it does not. Executability provides an objective quality signal unavailable for prose. Harder: correctness is semantic, not syntactic -- a function can run without error while producing wrong outputs.

The distribution of public code on GitHub and other repositories contains a massive amount of paired data: natural language (docstrings, comments, issue titles) and corresponding code. This pairing is what enables models to learn code generation from natural language descriptions.

Training Data Security Implications

Public code repositories contain substantial quantities of insecure code -- SQL injection vulnerabilities, hardcoded credentials, buffer overflows, weak cryptography. Models trained on this data learn these patterns. Multiple studies have shown that GitHub Copilot and similar tools generate insecure code in measurable percentages of security-sensitive contexts.

Python -- Computing pass@k unbiased estimator
import numpy as np
from math import comb

def pass_at_k(n: int, c: int, k: int) -> float:
    """
    Unbiased estimator of pass@k from Chen et al. (Codex paper).
    n: total samples generated per problem
    c: number of correct samples
    k: the k in pass@k
    """
    if n - c < k:
        return 1.0
    return 1.0 - comb(n - c, k) / comb(n, k)

# Example: generate 20 samples, 6 are correct, evaluate pass@1 and pass@10
print(pass_at_k(20, 6, 1))   # ~0.30
print(pass_at_k(20, 6, 10))  # ~0.87

Models Comparison

Codex (OpenAI) Fine-tuned GPT-3 on 159GB of Python. 12B parameter variant achieved 28.8% pass@1 on HumanEval. Foundation for GitHub Copilot. Deprecated in favor of GPT-4 Turbo.
CodeLlama (Meta) Fine-tuned LLaMA-2 on code. 7B/13B/34B/70B variants. Supports infilling (fill-in-the-middle). Context window up to 100k tokens. Open weights for local deployment.
DeepSeek Coder Trained from scratch on 2T tokens (87% code, 13% English/Chinese NL). 1B to 33B variants. Strong on multi-language benchmarks. Outperforms CodeLlama 34B at 7B scale.
GitHub Copilot Continuously updated product. IDE integration provides file context, repository-level awareness. Uses ghost text for inline completion. Copilot Chat for conversational assistance.

Security Considerations

AI code generation introduces a new attack surface: the model itself can be a vector for introducing vulnerabilities into production code.

Security Risks in AI-Generated Code

  • Insecure defaults: generated crypto uses MD5, weak RNG, hardcoded salts
  • SQL injection: string concatenation in queries rather than parameterized statements
  • Dependency suggestions: recommends outdated or malicious packages by package name
  • Buffer overflows in generated C/C++: unchecked bounds in array operations
  • Prompt injection via docstrings: attacker-controlled comments steer completions
  • Training data poisoning: targeted repository contributions influence future model outputs

Practice Problems

  3. Describe three concrete prompt engineering techniques to reduce the probability of an LLM generating insecure code in security-sensitive contexts.

Key Takeaways

  • Code models are trained on massive code corpora; executability provides an objective quality signal unavailable for text
  • HumanEval, MBPP, and SWE-bench are the standard benchmarks; pass@k is the standard metric
  • The unbiased pass@k estimator avoids the bias of greedy selection by using combinatorics over n samples
  • CodeLlama and DeepSeek Coder are strong open-weight alternatives to proprietary models
  • AI-generated code has measurable rates of security vulnerabilities -- static analysis post-processing is essential in security-sensitive contexts
