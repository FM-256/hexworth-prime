Hardware for DL

GPUs, TPUs, distributed training, and mixed precision for efficient deep learning.

Learning Objectives

  • Explain why GPUs accelerate deep learning over CPUs
  • Describe TPU architecture and when to prefer it over GPU
  • Configure multi-GPU training with DistributedDataParallel
  • Apply mixed precision training for 2x speedup with minimal accuracy loss
  • Profile GPU memory and identify bottlenecks in training pipelines

CPUs vs GPUs

Deep learning is dominated by matrix multiplications and convolutions — operations that decompose into thousands of independent scalar multiplications. CPUs have ~20 powerful cores optimized for sequential logic. GPUs have thousands of small cores designed for parallel SIMT (Single Instruction Multiple Thread) execution.

Mixed Precision Training

FP32 uses 4 bytes per value; FP16 uses 2 bytes. Mixed precision (AMP — Automatic Mixed Precision) stores weights in FP32 but performs most forward/backward operations in FP16, roughly doubling throughput on NVIDIA GPUs with Tensor Cores. A GradScaler multiplies the loss by a large scale factor before backward to prevent underflow in FP16 gradients.

amp_training.py
import torch
from torch.cuda.amp import autocast, GradScaler

scaler = GradScaler()  # manages loss scaling for FP16

for X, y in train_loader:
    X, y = X.cuda(), y.cuda()
    optimizer.zero_grad()

    with autocast():  # FP16 context
        logits = model(X)
        loss = criterion(logits, y)

    scaler.scale(loss).backward()  # scaled backward
    scaler.step(optimizer)         # unscale + step
    scaler.update()                # adjust scale factor

Distributed Training

DataParallel (single-machine, outdated): wraps model, replicates it across GPUs, gathers gradients on GPU 0. Creates a bottleneck at GPU 0 and does not scale well.

DistributedDataParallel (DDP): each process has its own model replica and communicates gradients via all-reduce. Scales linearly to hundreds of GPUs. The recommended approach for any multi-GPU training.

ddp_launch.py
# Launch with: torchrun --nproc_per_node=4 ddp_launch.py
import torch
import torch.distributed as dist
from torch.nn.parallel import DistributedDataParallel as DDP

dist.init_process_group('nccl')  # NCCL backend for GPU-to-GPU comms
rank = dist.get_rank()
torch.cuda.set_device(rank)

model = MyModel().cuda(rank)
model = DDP(model, device_ids=[rank])

# DistributedSampler ensures each GPU sees unique data
sampler = torch.utils.data.DistributedSampler(dataset)
loader = DataLoader(dataset, batch_size=64, sampler=sampler)

for epoch in range(epochs):
    sampler.set_epoch(epoch)  # ensures different shuffle each epoch
    train_one_epoch(model, optimizer, loader)

Gradient accumulation

To simulate a batch size of 256 on a GPU that can only fit 32: run 8 forward passes without calling optimizer.step(), accumulate gradients, then step once. Call optimizer.zero_grad() only after stepping, not after each micro-batch.

Practice

  1. Profile a training step using torch.profiler. Identify whether the bottleneck is compute, data loading, or GPU-CPU transfer.
  2. Add AMP to an existing training loop. Measure throughput (samples/second) before and after. Does loss curve change?
  3. Implement gradient accumulation with accumulate_steps=4. Verify that effective batch size equals 4 * batch_size by comparing loss curves.
  4. Enable gradient checkpointing with model.gradient_checkpointing_enable() (HuggingFace) or manual checkpointing. How much larger a batch fits?

Key Takeaways

  • GPUs accelerate DL via massive parallelism; NVIDIA H100 delivers ~3x A100 throughput for transformer training
  • Mixed precision (AMP) halves memory and doubles throughput with minimal accuracy impact
  • DistributedDataParallel scales linearly; prefer it over DataParallel for multi-GPU training
  • Gradient accumulation simulates large batches without the memory cost
  • Profile before optimizing — the bottleneck is often data loading, not compute
