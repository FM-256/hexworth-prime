Training Deep Networks

Batch normalization, dropout, and weight initialization for stable deep learning.

Learning Objectives

  • Explain why deep networks are hard to train without stabilization techniques
  • Implement batch normalization and understand its internal covariate shift fix
  • Apply dropout for regularization and understand train vs. eval mode
  • Select weight initialization strategies for different activation functions
  • Build a deep network with batch norm and dropout in PyTorch

Why Depth Makes Training Hard

Adding layers multiplies gradient magnitude either toward zero (vanishing) or infinity (exploding), and shifts the distribution of layer inputs as weights change during training (internal covariate shift). Three techniques address these problems in modern practice.

Batch Normalization

Batch Normalization (Ioffe & Szegedy, 2015) normalizes each feature in a mini-batch to zero mean and unit variance, then applies learnable scale (γ) and shift (β) parameters.

μB = (1/m) ∑xi    σB2 = (1/m) ∑(xi − μB)2
x̂i = (xi − μB) / √(σB2 + ε)    yi = γ x̂i + β

At inference time, running statistics (exponential moving average of batch stats computed during training) replace the batch statistics. This is why model.eval() must be called before inference.

BatchNorm placement

The original paper places BatchNorm between the linear layer and the activation: Linear → BN → ReLU. In practice (and in residual networks) placing it after the activation or even at the start of a block also works. Experiment for your architecture.

Dropout

Dropout (Srivastava et al., 2014) randomly zeroes each neuron's activation with probability p during training. This prevents co-adaptation: neurons cannot rely on specific other neurons, forcing the network to learn redundant representations. At test time, all neurons are active but outputs are scaled by (1−p) to match the expected magnitude.

PyTorch's nn.Dropout uses the inverted dropout formulation: training activations are divided by (1−p), so test-time requires no scaling.

Weight Initialization

LeCun normal N(0, 1/√nin) SELU activations

Full PyTorch Example

deep_network.py 
import torch
import torch.nn as nn
import torch.optim as optim

class DeepNet(nn.Module):
    def __init__(self, in_dim, hidden, out_dim, p_drop=0.3):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(in_dim, hidden),
            nn.BatchNorm1d(hidden),
            nn.ReLU(),
            nn.Dropout(p=p_drop),
            nn.Linear(hidden, hidden),
            nn.BatchNorm1d(hidden),
            nn.ReLU(),
            nn.Dropout(p=p_drop),
            nn.Linear(hidden, out_dim)
        )
        # He initialization (already default, shown for clarity)
        for m in self.modules():
            if isinstance(m, nn.Linear):
                nn.init.kaiming_normal_(m.weight, nonlinearity='relu')
                nn.init.zeros_(m.bias)

    def forward(self, x):
        return self.net(x)

model = DeepNet(in_dim=784, hidden=512, out_dim=10)
optimizer = optim.Adam(model.parameters(), lr=1e-3)
criterion = nn.CrossEntropyLoss()

# Training loop (one epoch)
model.train()
for X_batch, y_batch in train_loader:
    logits = model(X_batch)
    loss = criterion(logits, y_batch)
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()

# Inference — BatchNorm uses running stats, Dropout disabled
model.eval()
with torch.no_grad():
    preds = model(X_test).argmax(dim=1)
train() / eval() is critical

Forgetting to call model.eval() before inference causes BatchNorm to use mini-batch statistics from the inference batch instead of the learned running mean/variance, and Dropout will randomly zero activations, producing different predictions each forward pass. Both bugs are silent.

Practice

  1. Train DeepNet on MNIST with and without BatchNorm. Compare convergence speed (epochs to 95% train acc) and final validation accuracy.
  2. Sweep dropout rate p over {0.0, 0.1, 0.3, 0.5} and plot train vs. validation accuracy. Identify the sweet spot.
  3. Replace He init with all-zeros init. Observe what happens to gradients in the first backward pass (use .grad.norm()).
  4. Add Layer Normalization (nn.LayerNorm) instead of BatchNorm. When would you prefer it?

Key Takeaways

  • BatchNorm normalizes layer inputs, accelerating training and allowing higher learning rates
  • model.train() and model.eval() switch BatchNorm and Dropout between training and inference modes
  • Dropout (p=0.1 to 0.5) reduces overfitting by preventing co-adaptation
  • He initialization is correct for ReLU; Xavier for sigmoid/tanh
  • All-zero initialization causes symmetry breaking failure — neurons learn identical features
