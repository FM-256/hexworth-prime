Section 1  ·  The Deployment Problem

The Deployment Gap

Industry surveys consistently find that 87–90% of AI models never make it to production. Of those that do, many are quietly decommissioned within 12 months. The prototype worked — so what went wrong?

90%
of AI prototypes fail to reach production
50%
of production deployments miss their performance targets
2–6×
typical cost overrun from prototype to scaled system

Why prototypes fail in production

  • Data in prod is messier than eval data
  • Latency requirements were never specified
  • Costs scale non-linearly with traffic
  • Model outputs are not deterministic
  • No fallback when the model is down

What production-ready AI looks like

  • Defined SLAs (latency p50/p99, uptime)
  • Cost budget with alerting
  • Graceful degradation path
  • Observability from day one
  • Human-in-the-loop for edge cases
Section 2  ·  Infrastructure Choices

API-First vs. Self-Hosted

The first architectural decision is whether you call a cloud AI API or run your own model. This choice cascades into cost structure, latency, data privacy, and operational complexity.

Dimension API-First (OpenAI, Anthropic, etc.) Self-Hosted (Ollama, vLLM, TGI)
Time to deploy Hours Days–Weeks
Ops overhead Minimal High — GPU infra, updates, scaling
Data privacy Data leaves your boundary Data stays on-prem / in your VPC
Cost at scale Linear with token volume Fixed infra cost, drops per-token
Model quality ceiling Latest frontier models Open models (often 6–18 months behind)
Vendor dependency High — API changes, pricing changes Own your stack

Decision heuristic

Start API-first. Migrate to self-hosted when: (1) you process more than ~20M tokens/day, (2) data residency requires it, or (3) you need a capability not available in any hosted API.

Section 2  ·  Infrastructure Choices

OpenAI / Anthropic API Deployment

Managed APIs are the fastest path to production. Understanding their pricing model and operational limits is essential for cost control.

Strengths

  • No GPU procurement or management
  • Access to frontier models immediately
  • Built-in redundancy and uptime SLAs
  • Rate limit tiers scale automatically
  • Fine-tuning APIs available

Risks

  • Prompts and completions leave your boundary
  • Price changes outside your control
  • Rate limits can block production traffic
  • Model deprecations require re-evals
  • Outages are third-party incidents

Section 2  ·  Infrastructure Choices

Self-Hosted Models

Running models on your own infrastructure gives you full data control and predictable costs at scale — at the cost of significant operational complexity.

Ollama

Local-first model runner. Single binary, supports most popular open models. Ideal for development, small teams, and air-gapped environments.

Best for: Dev / Air-gap

vLLM

Production inference server using PagedAttention for efficient GPU memory management. Significantly higher throughput than naive model serving.

Best for: High-throughput prod

Text Generation Inference (TGI)

Hugging Face's production serving toolkit. Strong ecosystem integration, supports continuous batching, tensor parallelism across GPUs.

Best for: HuggingFace ecosystem

Self-hosted cost break-even point

A single A100 80GB GPU costs ~$3–4/hr on-demand (AWS p4d, GCP a2). At GPT-4o-mini pricing, you break even at roughly 25–30M input tokens per day. Below that threshold, APIs are usually cheaper when you include ops overhead.

Section 2  ·  Infrastructure Choices

Serverless AI

Serverless platforms eliminate infrastructure management and charge only for actual compute time. They are ideal for low-to-medium traffic with spiky patterns.

AWS Lambda / GCP Cloud Functions

  • Best for: lightweight AI orchestration, pre/post-processing
  • Max runtime: 15 min (Lambda), no GPU support natively
  • Cold start: 200ms–3s (Go/Python)
  • Cost model: per-invocation + GB-seconds

Modal / RunPod / Replicate

  • GPU-native serverless — run inference with no infra setup
  • Modal keeps warm containers to reduce cold starts
  • Scale to zero, scale to thousands on demand
  • Cost model: GPU-seconds (A10G ~$0.31/hr billed by second)

Cold start problem

A serverless function loading a 7B model from scratch takes 15–30 seconds. Mitigation strategies: keep-warm pings, model caching at the container layer (bake model weights into the image), and hybrid routing (serverless for burst, always-on for baseline).

Section 3  ·  Performance Engineering

Quantization & Model Optimization

Running full-precision models in production is often unnecessary and expensive. These techniques reduce inference cost without significantly degrading quality.

Weight Quantization

PrecisionMemory (7B)Quality loss
FP32 (full)28 GBNone
FP16 / BF1614 GBMinimal
INT8 (GPTQ)7 GBSmall (~0.5%)
INT4 (AWQ)3.5 GBModerate (~1–2%)

Other Optimization Techniques

Speculative Decoding

Draft model generates candidate tokens; large model verifies in parallel. 2–4x speedup with identical output quality.

Continuous Batching

Process multiple requests in the same forward pass. vLLM's core feature — dramatically improves GPU utilization under concurrent load.

KV-Cache Optimization

PagedAttention (vLLM) manages KV-cache like virtual memory — eliminates memory waste from fragmentation in long-context workloads.

Section 3  ·  Performance Engineering

Caching Strategies

AI inference is expensive. Caching correct responses and reusing computation is often the single highest-ROI optimization after model selection.

Exact-Match Cache

Hash the full prompt. Return cached response on hit. Effective for repetitive queries (FAQs, structured reports). Zero computation cost on cache hit.

Cache key: SHA256(system + user)
Hit rates: 20–60% for structured apps

Semantic Cache

Embed the prompt. Find nearest neighbor in a vector store. Return cached response if similarity > threshold (typically 0.97+). Catches paraphrased identical queries.

Tools: GPTCache, Redis Vector, Qdrant
Latency: adds ~10–30ms for lookup

Prefix Cache (KV Reuse)

Cache the KV-attention state for shared prompt prefixes (long system prompts). Subsequent requests skip recomputing those tokens entirely.

Native in: vLLM, TGI, Anthropic API
Reduces prompt cost 50–90% on repeat prefix

Cache invalidation in AI

Unlike deterministic APIs, AI caches must account for model version changes (a new model produces different outputs for the same prompt), user context drift, and time-sensitivity of responses. Always namespace cache keys by model version.

Section 3  ·  Performance Engineering

Rate Limiting & Throttling

Rate limiting protects your infrastructure from abuse and protects your cost budget. AI applications have two rate-limiting planes to manage simultaneously.

Inbound: Client Rate Limits

  • Per-user or per-API-key request quotas
  • Token-based limits (not just request count)
  • Sliding window more user-friendly than fixed window
  • Implement at gateway layer (Kong, NGINX, Envoy)
  • Return 429 with Retry-After header

Outbound: Provider Rate Limits

  • OpenAI Tier system: RPM, TPM, RPD limits
  • Implement exponential backoff with jitter on 429s
  • Queue with priority lanes (premium users first)
  • Track remaining rate limit headers per response
  • Multi-key rotation for higher throughput
# Exponential backoff with jitter (outbound 429 handling) def retry_with_backoff(fn, max_retries=5): for attempt in range(max_retries): try: return fn() except RateLimitError: wait = (2 ** attempt) + random.uniform(0, 1) # jitter time.sleep(min(wait, 60)) # cap at 60s raise MaxRetriesExceeded()
Section 4  ·  Operations

Monitoring & Observability

Traditional application monitoring is insufficient for AI. LLM systems require a fourth observability pillar beyond logs, metrics, and traces: evals.

Infrastructure Metrics

  • Request latency (p50, p95, p99)
  • Tokens per second (TPS) / throughput
  • GPU memory utilization per node
  • Cache hit rate (exact + semantic)
  • Cost per request (tokens × price)

AI-Specific Metrics

  • Hallucination rate (via eval pipeline)
  • Answer relevance score
  • Guardrail trigger rate
  • Output length distribution
  • Model refusal rate

LangSmith

LangChain's tracing platform. Captures full LLM call chains with inputs, outputs, latency, cost. Supports prompt version comparison and dataset-driven evals.

Arize Phoenix

Open-source LLM observability. Embedding drift detection, RAG retrieval quality, hallucination scoring. Connects to OpenInference traces.

Custom Eval Pipelines

Use a judge LLM (GPT-4o or Claude Sonnet) to score production outputs on correctness, relevance, and safety daily. Alert when scores drop.

Section 4  ·  Operations

A/B Testing AI Responses

A/B testing in AI is more complex than feature flags — you are evaluating non-deterministic outputs across multiple quality dimensions simultaneously.

Shadow Mode Testing

Route production traffic to both models simultaneously. Show users only the existing model's response. Evaluate the challenger's outputs offline before any promotion decision. Zero user impact during evaluation.

Common A/B Testing Mistakes

  • Using only implicit signals (ignores silent failures)
  • Stopping too early (LLM quality has high variance)
  • Not holding model version constant in the control
  • Ignoring cost as a success metric

Circuit breaker thresholds

Open the circuit (stop calling primary) after 5 consecutive errors or error rate > 50% in a 10-second window. Re-probe with a single request every 30 seconds. Close on success.

Section 4  ·  Operations

Cost Management

AI inference costs are highly elastic — they scale directly with usage and can spike unexpectedly. Treat cost management as a first-class engineering concern from day one.

Hard Limits (Non-Negotiable)

  • Set max_tokens on every API call
  • Per-user daily token budget with hard cutoff
  • Monthly spend alert at 50%, 80%, 100%
  • Emergency kill switch per tenant/feature

Cost Attribution

  • Tag every API call with feature + user segment
  • Track cost per feature, not just total cost
  • Surface cost in internal dashboards weekly
  • Include AI cost in product pricing model

Model Routing (Biggest Lever)

Classify query complexity before sending to model. Route simple queries (FAQ, short summaries) to GPT-4o-mini. Reserve frontier models for complex, high-value tasks only. Typical result: 60–80% cost reduction.

Cost = (p_cheap × rate_cheap) + (p_expensive × rate_expensive)

Where p_cheap + p_expensive = 1.0 (routing probability)

Section 5  ·  Security & Compliance

Security in Production

Deploying AI introduces an attack surface that traditional applications do not have. Most of these threats are preventable with disciplined operational security.

API Key Management

  • Never hardcode keys in source code
  • Use secrets managers (AWS Secrets Manager, Vault)
  • Rotate keys every 90 days minimum
  • Separate keys per environment (dev/staging/prod)
  • Scope keys with minimum required permissions

Prompt Filtering

  • Block known injection patterns at gateway
  • Length limits on input (prevent token stuffing)
  • Detect and block PII in user input before model
  • Output filtering: redact SSN/email/credit card
  • Tools: Microsoft Presidio, LlamaGuard

Network Security

  • AI API calls from VPC private subnets only
  • mTLS between internal services
  • WAF in front of public AI endpoints
  • Block model provider IPs from direct public access
  • VPC endpoints / Private Link where available

Most common AI security incidents

In order of frequency: (1) API key leaked in frontend JS or git history, (2) prompt injection via user-controlled input, (3) excessive agency — AI agent given broader tool access than needed, (4) PII exfiltration via output that wasn't filtered.

Section 5  ·  Security & Compliance

Compliance

AI deployments intersect with GDPR, HIPAA, SOC 2, and emerging AI-specific regulations. Compliance must be designed in — retrofitting is exponentially more expensive.

GDPR Considerations

  • Data Processing Agreement (DPA) with every AI API vendor
  • Legal basis for processing (consent or legitimate interest)
  • Right to erasure: can you delete user data from model context?
  • Automated decision-making disclosure (Article 22)
  • Data residency: verify where prompts are processed and logged

Data Residency

  • OpenAI: US by default; EU offering via Azure OpenAI
  • Anthropic: US-East by default; EU via Bedrock
  • Self-hosted eliminates residency concerns entirely
  • Check if your provider logs prompts (opt-out if so)
  • Document the data flow for every AI touchpoint

Audit Logging Requirements

For every AI inference event log: timestamp, user ID (hashed if needed), model version, input token count, output token count, latency, guardrail flags triggered. Store in immutable log sink (S3 Object Lock, Splunk). Retain per regulatory requirement (typically 1–7 years).

EU AI Act (2025+)

High-risk AI systems (credit scoring, hiring, critical infrastructure) require conformity assessments, risk management systems, and human oversight mechanisms. GPAI (general-purpose AI) models above capability thresholds must publish technical documentation.

Section 6  ·  Scaling

Scaling Patterns

AI inference scales differently from traditional web services. GPU availability and memory constraints require architecture decisions that typical auto-scaling ignores.

Horizontal Scaling

Add more model-serving replicas. Each replica needs its own GPU(s). Works well with stateless inference. Bottleneck: GPU availability and lead time (hours to days for cloud GPU instances).

Best for: sustained high throughput

Vertical Scaling

Move to larger GPU instances (A10G → A100 → H100). Larger memory allows larger batch sizes = better GPU utilization. Ceiling: H100 80GB is currently the largest single-GPU option.

Best for: large model fitting

Queue-Driven Auto-Scale

Requests enter a work queue. GPU workers pull from queue. Autoscale worker count based on queue depth, not CPU/RAM. This is the correct pattern for AI inference under variable load.

Best for: production AI workloads

Scale-to-zero for cost efficiency

For workloads with predictable off-hours (internal tools, batch jobs), scale GPU workers to zero overnight. Use a warm-up probe to spin up before business hours. Combine with serverless burst capacity for unexpected spikes.

Section 7  ·  Wrap-Up

Key Takeaways

  • 01 Start API-first. Managed APIs minimize time-to-production. Migrate to self-hosted only when token volume exceeds ~25M/day or data residency demands it — not before.
  • 02 Observability is not optional. Standard APM is insufficient for AI. You need evals, LLM traces, cost attribution, and quality metrics from the first production request.
  • 03 Design your fallback path before your happy path. Circuit breakers, model fallbacks, and cached responses must be in place before launch — not added after the first outage.
  • 04 Treat prompts as code. Version-control every prompt, require eval-gated PRs for prompt changes, and maintain a golden eval dataset that grows with every production incident.
  • 05 Cost is a product metric. Set hard token budgets, alert at 80% spend, and route cheap queries to cheap models. Model routing alone can cut AI infrastructure cost by 60–80%.
  • 06 Compliance must be designed in. DPAs, audit logs, data residency, and PII filtering cannot be retrofitted at scale. Address them in the architecture phase, not after a regulatory audit.
