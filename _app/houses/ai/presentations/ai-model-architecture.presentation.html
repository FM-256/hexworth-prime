Section 1  ·  Origins

From RNNs to Transformers

The path to today's LLMs spans four decades of sequence modelling research. Each architecture solved the previous era's bottleneck — until Transformers solved them all at once.

1980s
RNNs
Sequential. Vanishing gradients. Slow.
1997
LSTMs
Gated memory. Better long-range. Still serial.
2014–16
Seq2Seq + Attention
Encoder-decoder. Attention as add-on.
2017
Transformer
Attention is all you need. Fully parallel.
2018–Now
GPT / BERT / LLMs
Scale. Pre-train. Fine-tune. Align.

The core RNN problem

Processing tokens sequentially meant earlier context was diluted by the time it reached later tokens. Long-range dependencies — "the cat, which sat on the mat that was in the corner, was" — were near-impossible to preserve.

Why Transformers won

Every token can attend to every other token simultaneously. No sequential bottleneck. Fully parallelisable on GPUs. Scales from millions to trillions of parameters with the same architecture.

Section 1  ·  Origins

The Transformer Architecture

The Transformer processes the entire input sequence in parallel. A stack of identical layers each applies self-attention followed by a feed-forward network, with residual connections and normalisation throughout.

Token + Positional Embeddings
Input Tokens

Key design decisions

  • Residual connections let gradients flow through deep stacks without vanishing
  • Layer normalisation stabilises training at each sub-layer
  • Stacked layers — GPT-4 uses ~96 layers; each refines representations
  • No recurrence — processing is fully parallel across the sequence
  • Shared weights — same layer blueprint repeated N times

Decoder-only vs Encoder-only

GPT, Claude, Llama — decoder-only: generate text left-to-right. BERT — encoder-only: builds bidirectional representations for classification/search. T5 — encoder-decoder: translation, summarisation.

Section 2  ·  Attention

Self-Attention Mechanism

Self-attention lets every token in a sequence compute a weighted summary of all other tokens. The weights reflect relevance — how much each other token should influence the current one's representation.

The Q, K, V framework

Query (Q)

"What information am I looking for?" — the current token's question to the sequence.

Key (K)

"What do I contain?" — every token advertises its content so queries can find it.

Value (V)

"What do I contribute?" — the actual information passed back once a match is found.

The formula

Attention(Q,K,V) = softmax(QKT / √dk)V

Score each key against the query, scale by dimension, normalise, then take a weighted sum of values.

Multi-Head Attention

Running attention once only captures one type of relationship. Multi-head attention runs H parallel attention operations, each learning different relationship patterns, then combines the results.

Parallelism

All heads compute simultaneously — no sequential dependency. On modern GPUs this maps perfectly to matrix operations.

Dimension split

If model dimension is 1024 and there are 16 heads, each head works in 64 dimensions. Same total compute as single-head attention.

Emergent specialisation

Heads are not told what to learn — they discover their own specialisations during training from the data.

Section 2  ·  Attention

Positional Encoding

Attention is order-agnostic by design — it treats the input as a set, not a sequence. Positional encodings inject sequence-order information so the model knows token 3 comes before token 7.

Three main approaches

Sinusoidal (original Transformer)

Fixed sine/cosine waves at different frequencies. Works at inference on sequences longer than training. Not learned.

Learned absolute (BERT, GPT-2)

Trainable embedding per position. Simple but hard-limited to context length seen at training time.

RoPE (Llama, modern LLMs)

Rotary Position Embedding — encodes relative position inside the attention score. Naturally extends to longer contexts and is now the de facto standard.

Sinusoidal pattern

Each dimension uses a different frequency — low frequencies encode coarse position, high frequencies encode fine position.

Why it works

After adding positional encodings to token embeddings, the attention mechanism can infer relative and absolute positions from the pattern of values — no separate positional lookup needed.

Section 2  ·  Architecture Internals

Feed-Forward Networks

After attention mixes information across tokens, a position-wise feed-forward network (FFN) processes each token independently. This is where most of the model's learned knowledge is stored.

Structure per token

Output (d_model = 1024)
Linear (4096 → 1024)
GELU / ReLU activation
Linear (1024 → 4096)
Input from attention (d_model)

Key properties

  • 4x expansion — hidden layer is 4× the model dimension, then compressed back
  • No cross-token interaction — each position processed identically and independently
  • Non-linearity — GELU activation enables complex function approximation
  • Factual storage — neuron probing shows factual knowledge encoded in FFN weights
  • SwiGLU variant — used in Llama, PaLM; replaces single activation with a gated mechanism

Where the parameters live

In a typical LLM, ~66% of parameters are in FFN layers. The attention layers account for ~33%. This is why scaling up mostly means bigger FFNs.

Section 2  ·  Architecture Internals

Layer Normalisation

Deep networks suffer from internal covariate shift — the distribution of activations changes as weights update, making training unstable. Layer normalisation fixes this by re-centring and re-scaling activations at each layer boundary.

The operation

y= γ ⋅ (x − μ) / √(σ² + ε) + β

Normalise across the feature dimension for each token. γ and β are learnable scale and shift parameters.

Pre-norm vs Post-norm

Pre-LayerNorm (modern default)

Normalise the input before each sub-layer. Add the raw (un-normalised) residual after. More stable gradient flow — used by GPT-3, Llama, Claude.

Post-LayerNorm (original paper)

Normalise after the sub-layer. Can diverge during training on very deep networks. Requires warm-up learning rate schedules.

Why residual connections matter

Each sub-layer computes output = LayerNorm(x + sublayer(x)). The + x is the residual connection — it creates a direct path for gradients to flow backward through hundreds of layers without vanishing.

RMS Norm (Llama 2+)

Root Mean Square Normalisation drops the mean-centring step (sets μ = 0 implicitly), saving ~20% of normalisation compute with no measurable quality degradation.

Practical effect

Without LayerNorm, training a 100-layer network diverges within a few thousand steps. With it, 100-layer networks train smoothly to convergence.

Section 3  ·  Training

Tokenisation

Before a model sees any text, it must be converted to integers. Tokenisation is the process of splitting text into discrete units that map to vocabulary entries — not characters, not full words, but sub-word pieces.

BPE: Byte-Pair Encoding

The most common algorithm. Starts with a character-level vocabulary, then iteratively merges the most frequent adjacent pair of tokens until reaching the target vocabulary size.

# Initial: character-level "unhappiness" → [u,n,h,a,p,p,i,n,e,s,s] # After merges: "unhappiness" → [un, hap, p, iness] # Final token IDs (example): "unhappiness" → [428, 5131, 1108]

Why sub-word tokenisation?

Avoids unknown-word problem

Character-level handles any word but loses meaning. Word-level fails on rare words. Sub-word handles both: known words get single tokens, rare words decompose gracefully.

Vocabulary size trade-off

Larger vocabulary = shorter sequences = faster attention. But larger vocabulary embedding tables use more memory. GPT-4: ~100K vocab. Llama 3: 128K vocab.

Practical gotchas

  • Arithmetic can fail — "100" might be one token but "99" might be two
  • Leading spaces matter — " apple" and "apple" may be different tokens
  • Non-English text uses more tokens per word
Section 3  ·  Representations

Embeddings: Words as Vectors

Every token is mapped to a high-dimensional vector — its embedding. This converts discrete token IDs into continuous representations the model can compute over. Similar tokens cluster together in this space.

The embedding table

A learned lookup table: vocabulary size × model dimension. Each row is a trainable vector updated during back-propagation.

Vocab size: 100,000 tokens Model dim: 4,096 dimensions Table size: 100K × 4096 = 409,600,000 params ≈ 400M parameters

Classic analogy

Section 3  ·  Representations

Context Windows

Every LLM has a context window — the maximum number of tokens it can consider at once. Everything outside that window is invisible to the model. This is one of the most consequential practical constraints.

Why context is expensive

Self-attention computes a score between every pair of tokens. Cost scales quadratically with sequence length:

Cost ∝ n2 × d

Double the context = 4× the attention compute. 10× the context = 100×.

Context window evolution

ModelContextYear

GPT-4 Turbo128,000 tokens2023

Practical implications

Tokens ≈ words

128K tokens ≈ 100,000 words ≈ a full novel. 200K tokens ≈ a large codebase. 1M tokens ≈ a small library.

Lost in the middle

Research shows models are best at using information near the start and end of the context window. Material buried in the middle is recalled less reliably — even with large windows.

Flash Attention

A fused GPU kernel (Dao et al., 2022) that computes attention without materialising the full n×n matrix in memory. Enables 4-8× longer contexts with the same GPU memory.

Section 4  ·  Inference

Inference: How Generation Works

At inference time, models generate text one token at a time, each time consuming the entire previous context. This autoregressive process is fundamentally sequential — you cannot generate token 5 without tokens 1-4.

The generation loop

1
Feed the full context (prompt + generated so far) through the model
2
Final layer produces a logit score for every token in the vocabulary (~100K values)
3
Apply temperature + sampling strategy to select the next token
4
Append the chosen token, repeat until EOS token or max length reached

KV Cache

Keys and Values from already-processed tokens are cached. Only the new token needs fresh computation. Reduces decode from O(n²) to O(n) per step — essential for interactive response speeds.

Prefill vs Decode phases

Prefill: process the full prompt in parallel (fast, GPU-efficient). Decode: generate tokens one at a time (slower, memory-bandwidth-bound). First-token latency reflects prefill; streaming speed reflects decode.

Section 4  ·  Inference

Temperature & Sampling

The model outputs a probability distribution over the vocabulary. Sampling strategies determine how you select the next token from that distribution — trading off diversity against accuracy.

Temperature

Divides all logits before the softmax. Controls the sharpness of the distribution:

P(token) = softmax(logit / T)
T = 0
Greedy. Always picks the top token. Deterministic.
T = 1
Balanced. Samples from model's native distribution.
T = 2
Creative / chaotic. Unlikely tokens become probable.

Top-k and Top-p (Nucleus)

Top-k sampling

Keep only the k highest-probability tokens, redistribute their probability mass, then sample. k=50 is common. Simple but inflexible — k is the same regardless of distribution shape.

Top-p (nucleus) sampling

Keep the smallest set of tokens whose cumulative probability exceeds p (e.g., 0.9). More adaptive: when confident, considers few tokens; when uncertain, considers many. Generally preferred over top-k.

Typical production settings

Code generation: temperature=0.2, top-p=0.95 (precise). Creative writing: temperature=0.9, top-p=1.0 (varied). Factual QA: temperature=0 (deterministic).

Section 4  ·  Training at Scale

Scaling Laws

Model performance follows predictable power laws with respect to model size, training data, and compute. Bigger is generally better — but there are diminishing returns, and the ratio between parameters and tokens matters as much as absolute size.

The Chinchilla result (2022)

Compute-optimal training

For a given compute budget, you should scale model size and training tokens in roughly equal proportion. Most pre-Chinchilla models (including GPT-3) were massively undertrained.

Optimal tokens ≈ 20 × parameters
70BChinchilla params
1.4TChinchilla tokens
4×less compute than Gopher (280B)

Scaling dimensions

Model parameters (N)

More parameters = larger representational capacity. Each 10× increase in N delivers consistent perplexity improvements but with diminishing returns.

Training tokens (D)

More data = better generalisation. Llama 3 (8B) trained on 15T tokens — 375× the Chinchilla-optimal ratio — to optimise for fast inference.

Compute (C = 6ND)

Total FLOPs ≈ 6 × N × D. Frontier models spend $50–200M per training run. Emergent capabilities appear at unpredictable compute thresholds.

Section 4  ·  Adaptation

Fine-Tuning vs RAG vs In-Context Learning

Three strategies exist for making a base LLM useful for a specific domain or task. Each solves the "knowledge gap" problem differently, with distinct cost/latency/quality trade-offs.

Fine-Tuning

Update the model's weights on a curated dataset. Knowledge is baked into the model permanently.

  • Best accuracy on narrow tasks
  • Expensive to run (& re-run on updates)
  • Knowledge is frozen at training time
  • Needs labelled data
USE WHEN: task-specific style, specialised vocabulary, structured outputs

RAG

Retrieve relevant documents at query time and inject them into the context. Knowledge lives in an external database.

  • Real-time knowledge updates
  • Citable, verifiable sources
  • Depends on retrieval quality
  • Adds latency
USE WHEN: enterprise knowledge bases, live data, fact-checking required

In-Context Learning

Provide examples or instructions directly in the prompt. No training. The model adapts "on the fly".

  • Zero training cost
  • Instantly updatable
  • Limited by context window
  • Doesn't persist across sessions
USE WHEN: rapid prototyping, few-shot tasks, prompt engineering

In practice: combine all three

Production systems typically fine-tune a base model for domain style (SFT), use RAG to inject fresh knowledge, and leverage in-context few-shot examples for format control. These are not mutually exclusive.

Section 4  ·  Alignment

RLHF and Alignment

A pre-trained LLM will complete any sequence — including harmful ones. Reinforcement Learning from Human Feedback (RLHF) shapes the model to be helpful, harmless, and honest by training it to match human preferences.

STEP 1
Collect Demonstrations

Human labellers write ideal responses to prompts. Used to train a supervised fine-tuned (SFT) policy.

STEP 2
Train Reward Model

Show labellers pairs of SFT responses. They rank which is better. Train a reward model to predict these preferences.

STEP 3
RL Optimisation (PPO)

Use PPO to maximise reward model score. A KL penalty prevents the model drifting too far from the SFT baseline.

DPO: Simpler alternative (2023)

Direct Preference Optimisation removes the reward model entirely. It directly optimises the LLM on preference pairs using a supervised loss. Simpler to implement, more stable, and often matches PPO quality. Most open-source fine-tuned models now use DPO.

Alignment limitations

  • Reward hacking — model finds unexpected ways to maximise reward
  • Sycophancy — models learn to agree with users even when wrong
  • Over-refusal — excessive caution on benign prompts
  • Labeller bias — human preferences are not universal

Open-weight vs open-source

Open-weight means weights are downloadable but training data and code may be proprietary. True open-source (Apache 2.0) includes weights, code, and training data. Llama models are open-weight with a Meta licence. OLMo (AI2) is the most notable truly open-source frontier model.

Section 5  ·  The Landscape

Multimodal Models

The next evolution beyond text — models that can perceive and generate across text, images, audio, and video in a unified architecture. Modality boundaries are increasingly artificial.

Vision

Images are split into patches, each encoded as a vector by a vision encoder (ViT). These patch embeddings are concatenated with text token embeddings and processed by the LLM together.

Models: GPT-4V, Claude 3 Vision, Llama 3.2 Vision

Audio

Audio waveforms → mel spectrograms → Transformer encoder → audio tokens. These can be fed to an LLM for understanding, or decoded from LLM outputs for speech generation.

Models: Whisper (STT), GPT-4o Audio, Gemini Audio

Native multimodal

Some models (Gemini 1.5) train on all modalities jointly from the start rather than adapting a text-only model. This enables deeper cross-modal reasoning and interleaved context.

Models: Gemini 1.5, GPT-4o, Reka Core

How vision tokens work

A 336×336 image with 14px patches = 576 patch tokens. These are linearly projected to the LLM's embedding dimension and treated like text tokens. The LLM's attention mechanism then attends over both text and image tokens simultaneously.

Emerging: video and documents

Video = a sequence of image frames. PDFs = text + layout + embedded images. Models like Gemini 1.5 Pro can process full-length video (1M token context = ~1 hour of video at 1fps) and entire codebases.

Section 5  ·  Deployment

Edge Deployment: Quantisation & Distillation

Frontier models require data centres. But a growing class of efficient LLMs can run on laptops, phones, and embedded devices — using quantisation, distillation, and architectural pruning.

Quantisation

Reduce the precision of model weights from 32-bit floats to smaller formats. Drastic file size reduction with modest quality loss.

Section 5  ·  Limitations

Current Limitations

LLMs are genuinely powerful tools, but understanding where they fail — and why — is essential for safe deployment. These are not bugs that will be patched next week; they are structural properties of the architecture.

Hallucination

Models generate plausible-sounding but factually incorrect text with high confidence. The next-token objective rewards fluency, not truth. The model has no internal fact-check mechanism — it doesn't know what it doesn't know.

Reasoning brittleness

Models can solve complex problems in one form but fail on trivially rephrased versions. Multi-step arithmetic, spatial reasoning, and formal logic remain unreliable without external tools or extended "thinking" time.

Training cutoff

Knowledge is frozen at the training data cutoff. Events after that date are unknown unless retrieved externally. Models may confidently confuse their cutoff date with the present.

Context window limits

Despite 200K+ token windows, models still struggle with "lost in the middle" — retrieving information from the centre of very long contexts less reliably than from the edges.

No persistent memory

Every session starts from scratch. Without external memory systems, models cannot remember previous conversations, learn user preferences, or accumulate experience over time.

Bias and toxicity

Training data reflects human-generated content — with all its embedded biases. RLHF reduces but does not eliminate harmful outputs. Jailbreaks can bypass alignment in adversarial conditions.

Section 6  ·  The Frontier

What's Next?

The most significant near-term shifts are not just about making models bigger — they are about changing how models reason, remember, and act in the world.

Test-time compute scaling (Reasoning models)

OpenAI o1, DeepSeek R1 — instead of just scaling training, scale inference. Allow the model extended internal chain-of-thought before producing a final answer. Dramatic improvements on maths, coding, and science benchmarks.

Agentic architectures

From single-shot Q&A to persistent agents with tool use, long-horizon planning, and memory. Multi-agent systems where specialised models collaborate. Computer-use models that can directly operate software.

Long-context and memory

Gemini 1.5's 1M-token context begins to challenge whether RAG is needed at all for many tasks. Coupled with persistent external memory, this enables continuity across sessions and true knowledge accumulation.

Mixture of Experts (MoE) at scale

Sparse activation: route each token to only 2-8 of 64+ expert FFN modules. Near-dense model quality at 3-5× lower inference cost. Already deployed in Mixtral, almost certainly in GPT-4. Will become the dominant large-scale architecture.

Multimodal reasoning

True interleaving of text, image, audio, and video tokens in a single unified context. Models that can watch a video, read a document, and write code based on both — simultaneously.

Efficiency and democratisation

Quantisation + distillation + architectures like Mamba (state-space models) are pushing frontier-quality intelligence toward phones and embedded devices — removing the cloud dependency entirely.

Key Takeaways

  • 1 Transformers are parallel, not sequential. Self-attention lets every token attend to every other token simultaneously — this is why they scale so effectively on GPUs.
  • 2 Q, K, V is the core mechanism. Attention is a weighted lookup: query against keys to get weights, apply to values. Multi-head runs this in parallel across different "relationship types".
  • 3 Training has three phases. Pre-training builds broad knowledge via next-token prediction. SFT teaches format. RLHF/DPO aligns to human preferences. Each phase is essential.
  • 4 Scaling laws are real but nuanced. Bigger model + more tokens = better performance. But the ratio matters — Chinchilla showed most models were undertrained, not underpowered.
  • 5 Hallucination is structural, not a bug. The next-token objective rewards fluency. Without an explicit truth signal, the model has no internal reason to be accurate — mitigation requires external grounding (RAG, tools, verification).
  • 6 The frontier is shifting toward reasoning + agency. Test-time compute, long context, MoE, and agentic architectures are the current research frontiers — not just "bigger pre-training".
