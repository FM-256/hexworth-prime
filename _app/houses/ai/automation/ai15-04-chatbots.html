1. Chatbot Architecture in N8N

N8N chatbot workflows combine webhook triggers, AI nodes, memory nodes, and channel-specific nodes. The key challenge is maintaining conversation state across multiple messages from the same user.

Chatbot Workflow Architecture
Incoming Message --> [Chat Trigger] --> [Load History] --> [AI Agent] --> [Save History] --> [Send Response] ^ | |--- Memory Store (session-based) --+

3. Memory Patterns

Window Buffer

Keep last N messages. Simple, bounded. Good for short chats.

Summary Memory

LLM summarizes older messages. Maintains context over long conversations.

External Store

Save to PostgreSQL or Redis. Persists across restarts.

Session-Based

Session IDs isolate conversations. Multiple concurrent chats.

Key Takeaways

  • N8N chatbot workflows combine webhook triggers, AI Agent nodes, and memory nodes
  • Session-based memory (keyed by user + channel) enables concurrent independent conversations
  • Multi-channel deployment uses a shared AI Agent node with platform-specific handlers
  • Escalation paths are essential -- detect when the bot cannot help and transfer to humans
  • Always log conversations for quality review and iterate based on real usage patterns
