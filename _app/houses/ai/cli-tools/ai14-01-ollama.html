Ollama Local Model Management

Install, pull, run, and manage LLMs locally with Ollama. Run Llama, Mistral, and Gemma on your own hardware.

Learning Objectives

  • Install and configure Ollama on Linux, macOS, and Windows (WSL)
  • Pull, run, and manage local models from the Ollama model library
  • Serve models via the Ollama API for application integration
  • Create custom Modelfiles with system prompts and parameter tuning

1. What is Ollama

Ollama is a tool for running large language models locally. It downloads, manages, and serves quantized models (GGUF format) through a simple CLI and REST API. No cloud account needed, no API keys, no data leaving your machine.

Local Privacy

All inference on your hardware. No data sent to any cloud provider.

Simple CLI

One command to pull and run any supported model.

REST API

OpenAI-compatible API on localhost:11434.

Modelfile

Dockerfile-like format for custom models with baked-in prompts.

2. Installation and Setup

# Linux / WSL
curl -fsSL https://ollama.com/install.sh | sh

# macOS
brew install ollama

# Start the service
ollama serve

3. Model Management

ollama pull llama3.1:8b         # 4.7 GB, runs on 8GB RAM
ollama pull mistral:7b          # 4.1 GB, fast general-purpose
ollama pull codellama:13b       # 7.4 GB, code generation
ollama list                     # show installed models
ollama run llama3.1:8b          # interactive chat
ollama show llama3.1:8b         # model details

4. Custom Modelfiles

# Modelfile.security
FROM llama3.1:8b

SYSTEM "You are a senior cybersecurity analyst. Specialize in vulnerability assessment. Never provide instructions for malicious activities."

PARAMETER temperature 0.3
PARAMETER num_ctx 4096

# Build and run
ollama create security-analyst -f Modelfile.security
ollama run security-analyst

5. API Integration

from openai import OpenAI

client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")

response = client.chat.completions.create(
    model="llama3.1:8b",
    messages=[{"role": "user", "content": "What is CVE-2021-44228?"}],
    temperature=0
)
print(response.choices[0].message.content)
Hardware Requirements7B models need ~8GB RAM. 13B models need ~16GB. 70B models need ~40GB. Quantized models (Q4_K_M) use roughly half the memory of full-precision with minimal quality loss.

Try It

  1. Install Ollama and pull 3 different models. Compare response quality on 5 security questions.
  2. Create a custom Modelfile for a specific role (SOC analyst, pen tester). Test against the base model.
  3. Integrate Ollama with a Python script using the OpenAI-compatible API.
  4. Measure inference speed (tokens/second) for different model sizes on your hardware.

Key Takeaways

  • Ollama runs LLMs locally with zero cloud dependencies -- ideal for privacy-sensitive environments
  • The CLI is simple: ollama pull, ollama run, ollama list, ollama rm for full lifecycle management
  • Custom Modelfiles bake in system prompts, temperature, and parameters for reproducible deployments
  • The OpenAI-compatible API at localhost:11434/v1 enables drop-in replacement in existing code
  • Model selection depends on hardware: 7B for 8GB RAM, 13B for 16GB, 70B for 40GB+
