Azure AI CLI Extensions

Azure OpenAI deployments, content safety, resource management, and the az ai CLI extensions.

Learning Objectives

  • Deploy Azure OpenAI models using the Azure CLI and portal
  • Configure content filtering and safety policies for deployed models
  • Use the Azure OpenAI Python SDK with managed identity authentication
  • Compare Azure OpenAI vs direct OpenAI API for enterprise deployments

1. Azure OpenAI Service

Azure OpenAI provides the same models as OpenAI but hosted within Azure's enterprise infrastructure. This means data residency guarantees, VNet integration, managed identity auth, and content filtering.

Data Residency

Data stays in selected Azure region. No training on your data. Required for GDPR, FedRAMP.

Content Filtering

Built-in content safety. Configurable severity levels per category.

Network Security

Private endpoints, VNet integration, managed identity auth.

Enterprise Monitoring

Azure Monitor, diagnostic logs, cost management integration.

2. CLI Deployment

az cognitiveservices account create \
    --name openai-hexworth --resource-group rg-ai-lab \
    --kind OpenAI --sku S0 --location eastus2

az cognitiveservices account deployment create \
    --name openai-hexworth --resource-group rg-ai-lab \
    --deployment-name gpt4o-deployment \
    --model-name gpt-4o --model-format OpenAI \
    --sku-capacity 10 --sku-name Standard

3. Python SDK Usage

from openai import AzureOpenAI

client = AzureOpenAI(
    azure_endpoint=os.environ["AZURE_OPENAI_ENDPOINT"],
    api_key=os.environ["AZURE_OPENAI_API_KEY"],
    api_version="2024-06-01"
)
response = client.chat.completions.create(
    model="gpt4o-deployment",  # deployment name, not model name
    messages=[{"role": "user", "content": "Summarize NIST 800-171."}]
)

# Managed identity (no API keys)
from azure.identity import DefaultAzureCredential, get_bearer_token_provider
credential = DefaultAzureCredential()
token_provider = get_bearer_token_provider(credential, "https://cognitiveservices.azure.com/.default")
Azure vs Direct OpenAIUse Azure OpenAI for data residency, VNet integration, managed identity, content filtering, and compliance (FedRAMP, HIPAA). Use direct OpenAI for latest models, lower friction, non-regulated projects.

Try It

  2. Configure content safety filters and test with inputs of varying severity.
  3. Implement managed identity authentication (DefaultAzureCredential) instead of API keys.
  4. Compare latency and pricing between Azure OpenAI and direct OpenAI for the same model.

Key Takeaways

  • Azure OpenAI wraps the same models in enterprise infrastructure: data residency, VNets, managed identity
  • Use deployment names (not model names) when calling the Azure OpenAI API
  • Managed identity with DefaultAzureCredential eliminates API key management entirely
  • Content Safety API provides pre-screening for harmful content with configurable thresholds
  • Azure OpenAI is the correct choice for regulated industries, government, and enterprise environments
