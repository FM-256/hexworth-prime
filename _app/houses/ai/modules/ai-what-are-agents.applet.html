Chatbot, Automation, or Agent?

Not everything labeled "AI" is an AI Agent. The term gets applied to three very different categories of software, each with distinct capabilities and limitations. Getting this distinction right is one of the most important skills in modern AI literacy.

💬
Chatbot
Follows a scripted decision tree
Matches keywords to canned responses
No reasoning or learning
Deterministic — same input, same output
Example: FAQ widgets, phone IVR menus

Automation
Trigger → Action, no intelligence
Rule-based: if X then do Y
Cannot handle ambiguous inputs
Reliable, fast, and predictable
Example: IFTTT, Zapier simple workflows
Rule-Based

AI Agent
Has a Brain (LLM), Memory, and Tools
Reasons, plans, and adapts to context
Can take multi-step actions autonomously
Handles ambiguity and novel situations
Example: Phishing triage agent, research assistant

The 3-Component Model

Every AI Agent is built from three fundamental components. Together they enable something that neither chatbots nor automation can achieve: adaptive, goal-directed action in the real world.

Brain — The LLM Core
  • A Large Language Model (e.g. GPT-4, Claude, Gemini, Llama) trained on vast text data
  • Understands natural language instructions and generates human-readable output
  • Makes multi-step decisions: "To answer this, I need to first search, then summarize, then format"
  • Handles ambiguity — unlike automation, it can interpret vague or incomplete instructions
  • Responsible for planning, reasoning, and orchestrating which tools to call and when
Memory — Context and Recall
  • Short-term (Working Memory): the conversation context window — everything said so far in the session
  • Long-term: vector databases that store embeddings — retrieved via semantic similarity (RAG)
  • RAG (Retrieval-Augmented Generation) lets agents "remember" thousands of documents without retraining
  • Without memory, agents repeat mistakes, lose context, and can't learn from previous interactions
  • Memory is what separates a smart chatbot from a truly intelligent agent that improves over time
Tools — Real-World Capabilities
  • Web search: retrieve current information beyond the LLM's training cutoff
  • Code execution: write and run Python, query databases, process files
  • API calls: interact with external services (email, Slack, SIEM, ticketing systems)
  • Document tools: read PDFs, write reports, fill out spreadsheets
  • Tools transform the agent from a text generator into an actor that changes the real world

The Junior Employee Analogy

The most useful mental model for understanding AI Agents is the junior employee. This analogy captures both the capabilities and the limitations of current agent technology.

"

AI Agents are like a smart, eager junior employee. They can handle research, drafting, analysis, and routine execution — but they need clear instructions, occasional supervision, and well-defined boundaries. You wouldn't give a new hire the root password on their first day.

Human role: judgment calls, policy decisions, ethical oversight
Agent role: execution, research, summarization, repetitive multi-step tasks

This framing is practically useful because it tells you what questions to ask before deploying an agent:

  • Would I let a new employee do this unsupervised? If no, add a human-in-the-loop checkpoint.
  • Have I given clear instructions? Ambiguous prompts produce ambiguous results.
  • What are the failure modes? Define what the agent should do when it hits an edge case.
  • What tools does it need — and which should it NOT have access to?
