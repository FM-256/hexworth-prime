1. Deployment Concepts

Azure OpenAI separates model selection from deployment. You first choose a model (e.g., gpt-4o) and version (e.g., 2024-05-13), then create a deployment with a custom name, capacity allocation, and optional content filtering policy. Multiple deployments of the same model can coexist with different configurations -- for example, one deployment with strict filtering for customer-facing use and another with relaxed filtering for internal use.

Standard DeploymentPay-per-token pricing. Shared infrastructure. Best for variable workloads. No minimum commitment. Tokens per minute (TPM) quota applies.
Provisioned (PTU)Reserved capacity. Guaranteed throughput. Predictable latency. Billed hourly/monthly regardless of usage. Best for consistent high-volume workloads.
Global DeploymentMicrosoft routes requests to the region with available capacity. Higher limits than regional. Best for non-latency-sensitive workloads.
Data Zone DeploymentRestricts processing to a geographic zone (US, EU). Combines global routing benefits with data residency compliance.

2. Model Lifecycle

Azure OpenAI models follow a lifecycle: preview, GA (general availability), deprecation, retirement. Microsoft provides 60-day deprecation notices. When a model version is deprecated, existing deployments continue to function but new deployments cannot be created. Auto-upgrade policies can be configured to automatically move deployments to newer model versions.

3. Monitoring

Azure OpenAI exposes metrics through Azure Monitor: HTTP request count, token usage (prompt + completion), latency (p50, p95, p99), content filter triggers, and error rates (429 throttling, 500 errors). Enable diagnostic settings to route logs to Log Analytics for KQL queries, or to Event Hub for streaming analytics.

Key Metrics to Monitor

Token usage (cost tracking), 429 responses (capacity limits), p95 latency (user experience), content filter triggers (safety), and model version (deprecation tracking). Set alerts for 429 rate > 5% and p95 latency > 3 seconds.

Try It

  1. Deploy the same model (GPT-4o) with two different deployment names and content filtering policies.
  2. Query Azure Monitor metrics for token usage, latency, and error rates over a 24-hour period.
  3. Test the difference between standard and global deployment types on latency for requests from multiple geographic locations.
  4. Create an auto-upgrade policy and test model version migration.

Key Takeaways

  • Deployments reference custom names, not model names -- a critical distinction for API calls
  • Standard deployments are pay-per-token; PTU provides reserved guaranteed throughput
  • Model deprecation provides 60-day notice -- configure auto-upgrade for seamless transitions
  • Monitor 429 rates, p95 latency, token usage, and content filter triggers in production
  • Multiple deployments of the same model enable different configurations for different use cases
