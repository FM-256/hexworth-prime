1. Azure OpenAI Embedding Models

Azure OpenAI provides two embedding model families: text-embedding-3-large (3072 dimensions, highest quality) and text-embedding-3-small (1536 dimensions, cost-effective). Both support native dimensionality reduction via the "dimensions" parameter -- request fewer dimensions without retraining. These models are specifically trained for search and retrieval tasks with Matryoshka Representation Learning, which means truncated vectors retain proportional quality.

2. Chunking Strategies

Document chunking directly impacts RAG quality. Chunks that are too small lose context; chunks that are too large dilute relevance. The optimal chunk size depends on your content type, embedding model, and retrieval approach.

Fixed-Size ChunkingSplit at token count (256-1024 tokens) with overlap (50-100 tokens). Simple, predictable. Works for homogeneous content.
Semantic ChunkingSplit at topic boundaries using embedding similarity between sentences. Better relevance but more complex and slower to index.
Document StructureSplit at headings, sections, or paragraph boundaries. Preserves logical units. Best for structured documents (docs, articles).
Recursive Character SplittingTry paragraph splits first, then sentences, then words. Balances chunk size with semantic boundaries. Default in LangChain.

Chunking Best Practices

Start with 512 tokens and 100-token overlap. Include document metadata (title, section, page) in each chunk. Test retrieval quality with your actual queries before optimizing chunk size. Smaller chunks (256) work better for factoid QA; larger chunks (1024) work better for summarization.

3. RAG Pipeline Architecture

A production RAG pipeline on Azure combines Azure Blob Storage (document source), Azure AI Search (vector index + hybrid search), and Azure OpenAI (embedding generation + answer generation). The indexing pipeline chunks documents, generates embeddings via the Azure OpenAI embeddings API, and stores vectors with metadata in AI Search. At query time, the user query is embedded, AI Search returns top-k relevant chunks, and GPT generates an answer grounded in the retrieved context.

Key Takeaways

  • text-embedding-3 models support native dimensionality reduction via the dimensions parameter
  • Chunking strategy directly impacts RAG quality -- test multiple approaches on your data
  • 512 tokens with 100-token overlap is a strong default starting point for most documents
  • Include document metadata (title, section, page) in every chunk for filtering and citation
  • Hybrid search (vector + BM25 + semantic ranking) outperforms pure vector search for RAG
