1. Provisioned Throughput Units (PTU)

PTU provides reserved model processing capacity, guaranteeing throughput and latency independent of other customers. Unlike standard (pay-per-token) deployments that share infrastructure, PTU allocations are dedicated to your workload. Pricing is hourly regardless of usage, making PTU cost-effective when utilization exceeds ~60-70% of allocation. Size PTU based on your peak tokens-per-minute requirement.

Capacity Planning1 PTU for GPT-4o processes approximately 450 tokens per minute. Calculate required PTUs: peak TPM / 450. Add 20% buffer for burst headroom.
Latency GuaranteePTU eliminates noisy-neighbor latency spikes. P99 latency is predictable and consistent. Critical for real-time applications.
Cost ModelHourly billing regardless of usage. Break-even at ~60-70% utilization vs standard pricing. Monthly commitments get 20%+ discount.
ScalingPTU allocations can be adjusted but not instantly. Plan for peak capacity. Use standard deployments as overflow for burst traffic.

2. Data Zone Deployments

Data zone deployments restrict data processing to a geographic zone (US or EU) while still benefiting from global load balancing within that zone. This provides the best of both worlds: data residency compliance (GDPR, sovereignty) plus higher availability and throughput than single-region deployments. Configure via deployment type selection in Azure AI Studio.

3. Enterprise Security Architecture

Production enterprise deployments layer multiple security controls: managed identity eliminates API keys entirely, private endpoints remove public internet exposure, Azure API Management provides rate limiting and API key abstraction, and diagnostic logging creates audit trails for compliance.

Managed IdentitySystem-assigned or user-assigned. Zero secrets in code or config. Works with App Service, Functions, AKS, VMs. Assign Cognitive Services User role.
API Management GatewayCentral entry point for all AI API calls. Rate limiting, key management, response caching, analytics, and policy enforcement.
Private EndpointsAzure Private Link integration. AI traffic stays on the Azure backbone. No public IP exposure. Requires DNS configuration.
Multi-Region HADeploy to 2+ regions with Azure Traffic Manager or Front Door. Active-active or active-passive failover. Independent PTU allocations per region.

Reference Architecture

Client -> API Management (rate limit, auth) -> Private Endpoint -> Azure OpenAI (PTU, data zone) -> Azure Monitor (logs, metrics) -> Log Analytics (KQL queries, alerts). All traffic on private network. Managed identity end-to-end. No secrets in code.

Try It

  1. Calculate PTU requirements for a workload of 50,000 tokens per minute. Include 20% burst buffer.
  2. Configure managed identity authentication from an Azure Function to Azure OpenAI. Verify no API keys are stored.
  3. Set up API Management as a gateway with rate limiting (100 requests/minute per client) and request logging.
  4. Design a multi-region deployment architecture with failover. Document RPO and RTO targets.

Key Takeaways

  • PTU provides reserved capacity with guaranteed throughput -- break-even at 60-70% utilization
  • Data zone deployments combine geographic data residency with load-balanced availability
  • Managed identity eliminates all API keys and secrets from code and configuration
  • API Management provides rate limiting, analytics, and policy enforcement as a central gateway
  • Multi-region deployment with Traffic Manager provides HA with independent PTU per region
  • Stack all security layers: managed identity + private endpoints + API Management + diagnostic logging
