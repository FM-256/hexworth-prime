1. When to Fine-Tune on Azure OpenAI

Azure OpenAI supports fine-tuning GPT-4o-mini and GPT-3.5-Turbo models. Fine-tuning is appropriate when prompt engineering and RAG are insufficient: you need consistent output style, domain-specific behavior embedded in the model, reduced latency (shorter prompts), or cost reduction (smaller model matching larger model quality on your task). The training data must be in JSONL format with chat completion message arrays.

Style ConsistencyFine-tune for consistent tone, formatting, and response structure. Example: always respond in structured JSON with specific field names.
Domain AdaptationTeach the model domain terminology, reasoning patterns, and task-specific behaviors that cannot be captured in a system prompt.
Cost ReductionFine-tune a smaller model (4o-mini) to match GPT-4o quality on your specific task. 10-20x cost reduction per token.
Latency ReductionEmbed few-shot examples into model weights instead of including them in every prompt. Shorter prompts = faster responses.

2. Training Data Preparation

Training data must be JSONL format with chat message arrays. Each example contains system, user, and assistant messages. Minimum 10 examples, recommended 50-100 for production quality. Data quality dominates quantity -- 50 expert-curated examples often outperform 5000 noisy examples. Include diverse examples covering edge cases and expected output variations.

Data Quality Checklist

Each example should have a clear system prompt, realistic user input, and a high-quality assistant response. Remove duplicates. Balance across categories if applicable. Include edge cases. Verify that the system prompt in training data matches your production system prompt. Target 50-100 examples for initial fine-tuning.

Hosting Costs

Fine-tuned GPT-4o-mini models incur hourly hosting charges while deployed. Delete deployments when not in use during development. GPT-3.5-Turbo fine-tuned models use shared infrastructure with no hosting fee -- consider this for cost-sensitive scenarios.

Try It

  1. Prepare a training dataset of 50 examples in JSONL chat format for a domain-specific task.
  2. Submit a fine-tuning job via the Azure OpenAI API. Monitor training progress and review the training loss curve.
  3. Evaluate the fine-tuned model against the base model on 20 holdout test examples. Score on accuracy, style, and relevance.
  4. Deploy the fine-tuned model and compare inference cost/latency against using the base model with few-shot examples.

Key Takeaways

  • Fine-tuning on Azure OpenAI is available for GPT-4o-mini and GPT-3.5-Turbo
  • Training data must be JSONL format with chat message arrays (system + user + assistant)
  • 50-100 high-quality examples typically outperform thousands of noisy examples
  • GPT-4o-mini fine-tuned models incur hourly hosting charges while deployed
  • Always compare fine-tuned model performance against prompt engineering + RAG baselines first
  • Delete unused fine-tuned deployments to avoid ongoing hosting costs
