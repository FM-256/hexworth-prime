Exercise 1: ARP Poisoning
ARP has no authentication. An attacker on the same LAN can broadcast fake ARP replies, poisoning victim and gateway caches so traffic flows through the attacker's machine.
Network topology: 10.0.0.1 (gateway) | 10.0.0.5 (victim) | 10.0.0.99 (attacker)
IP AddressMAC AddressState
10.0.0.1aa:bb:cc:11:22:33CLEAN
10.0.0.5dd:ee:ff:44:55:66CLEAN
attacker@kali — arpspoof
// Run the arpspoof commands below to poison the ARP cache
root@kali:~#
You need two arpspoof processes: one tells the victim that the attacker is the gateway, and one tells the gateway the attacker is the victim. This creates a bidirectional intercept.
Without enabling IP forwarding (ip_forward=1), the attacker's machine drops the intercepted packets and the victim loses connectivity — a denial-of-service. Enable forwarding to stay covert.
Exercise 2: Packet Sniffing
HTTP transmits data in cleartext. Use simulated tcpdump to capture packets and extract credentials. Identify protocols and understand why HTTPS is essential.
attacker@kali — tcpdump
// Run tcpdump or tshark commands to capture traffic
root@kali:~#
The -A flag prints packet payloads as ASCII. On HTTP traffic you'll see POST bodies including username= and password= fields in cleartext.
FTP (port 21) sends credentials in cleartext: USER and PASS commands are visible in the packet stream. Try sniffing port 21 to see credentials. Use SFTP or FTPS instead.
Exercise 3: MITM — Traffic Interception
With ARP poisoning active, the attacker sits between victim and gateway. Use mitmproxy to intercept HTTP requests and inject malicious content into unencrypted pages.
attacker@kali — mitmproxy
// Start mitmproxy and run intercept commands
root@kali:~#

mitmproxy in transparent mode (-T) intercepts all TCP traffic without the victim configuring a proxy. Combined with iptables REDIRECT rules and ARP poisoning, it creates a full MITM position.
SSLstrip downgrades HTTPS to HTTP by stripping redirects. Modern browsers counter this with HSTS (HTTP Strict Transport Security). HSTS-preloaded domains cannot be SSLstripped even on first visit.

    ARP-level defense: use arptables to lock IP-to-MAC mappings, or use Dynamic ARP Inspection (DAI) on managed switches to validate ARP packets against a trusted DHCP snooping database.
    To block MITM forwarding: set iptables default FORWARD policy to DROP, then only explicitly allow legitimate forwarding paths. This prevents an attacker's machine from relaying traffic even if ARP poisoning succeeds.
