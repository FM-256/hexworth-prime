Caesar cipher is a substitution cipher — each letter shifts by a fixed amount. It has only 25 possible keys, making brute force trivial. ROT-13 is Caesar-13, still used in forums to obscure spoilers.
XOR cipher with a repeating key is the Vigenere/Vernam foundation. With a truly random key as long as the message (One-Time Pad), it is theoretically unbreakable. AES-256 uses 14 rounds of substitution, permutation, and key mixing — computationally infeasible to break.

Hash length identifies algorithm: MD5=32 hex chars (128-bit), SHA-1=40 hex chars (160-bit), SHA-256=64 hex chars (256-bit). MD5 and SHA-1 are considered cryptographically broken for collision resistance.
Dictionary attacks precompute or iterate a wordlist. Rainbow tables precompute hash:plaintext pairs for common passwords. Defense: salt hashes (append random bytes before hashing) to make rainbow tables infeasible.

The private key signs; the public key verifies. You publish your public key. Anyone can verify your signatures with it, but only you can create valid signatures with the private key. RSA and ECDSA are common algorithms.
Why hash first? Asymmetric encryption of large data is slow. Instead, hash the document (fast, fixed-size output) then sign only the hash. The signature proves: (1) you signed it (authentication), (2) content is unchanged (integrity).
Exercise 4: LSB Steganography
Hide a secret message in a simulated image using Least Significant Bit (LSB) encoding. Each pixel's LSB is modified to encode one bit of the message. Observe pixel values changing.

LSB steganography changes only the last bit of each color channel (R, G, or B) per pixel. A change from 255 (11111111) to 254 (11111110) is visually imperceptible but encodes one bit of data.
Detection: steganalysis tools like StegExpose measure statistical anomalies in LSB patterns. Natural images have random LSB distributions; steganographic images often show unexpected regularity. Also: file size increase can be a tell.
