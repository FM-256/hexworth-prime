Exercise 1: Malware Classification
Read each behavior description. Select the correct malware type. You must correctly classify at least 6 of 8 samples.
Sample A: Attaches itself to legitimate .exe files. When infected executable runs, it replicates into other .exe files in the same directory. Does not spread over network.
Sample B: Scans network for SMB vulnerabilities. Exploits EternalBlue to copy itself to remote systems without any user interaction. Spreads exponentially.
Sample C: Disguised as a free game download. Once installed, silently opens a reverse shell to C2 server. Does not replicate. User-initiated installation.
Sample D: Encrypts all files on disk and mapped network drives. Appends .LOCKED extension. Drops ransom note. Deletes Volume Shadow Copies via vssadmin.
Sample E: Hooks system calls in kernel. Hides its own process from Task Manager, files from Explorer, and registry keys from regedit. Survives reboots via MBR modification.
Sample F: Logs every keystroke and periodically screenshots the desktop. Sends logs to attacker via email using SMTP. No system modification. Runs silently in background.
Sample G: Runs entirely in RAM. Uses PowerShell to download payload and inject into legitimate process (lsass.exe). Leaves no files on disk. Cleaned by reboot alone.
Sample H: Communicates with C2 over DNS. Exfiltrates data in DNS query subdomains. Beacons every 30 min. Part of a large botnet. Receives commands via TXT records.
Correct: 0/8
Key distinctions: Virus=infects host files, needs execution. Worm=self-replicates over network, no host needed. Trojan=disguised as legit software. Rootkit=hides presence via OS-level hooks. Fileless=lives in memory/registry only. Spyware=monitors without ransoming.
Exercise 2: Static Analysis
Analyze a simulated PE (Portable Executable) file without running it. Examine the file hash, strings, and import table to identify suspicious capabilities.

// Run analysis commands below. Start with file hash.

Suspicious API calls: CreateRemoteThread (inject code into other processes), VirtualAllocEx (allocate memory in remote process), WriteProcessMemory (write to remote process memory). Together these form the "process injection triad."
The strings command reveals hardcoded IPs, domains, registry keys, and error messages that malware authors forgot to obfuscate. Also look for: cmd.exe, powershell, reg add, schtasks — all common in malware.

YARA rule structure: rule name { meta: (optional metadata) strings: (patterns to find) condition: (boolean logic combining string matches) }. Use 'all of them', 'any of ($s*)', or arithmetic like '2 of ($net*)' for flexible matching.
Good YARA rules balance precision (low false positives) with recall (low false negatives). Too specific and you miss variants. Too generic and you alert on legitimate software. Use multiple unique strings combined with AND logic for best results.
