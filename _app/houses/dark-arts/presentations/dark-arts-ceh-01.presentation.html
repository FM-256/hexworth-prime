What is Footprinting?

Footprinting is the process of gathering information about a target organization before any active attack begins - determining the size and scope of the attack surface. CEH v12 splits it into two modes:

PASSIVE FOOTPRINTING

No direct interaction with the target. Comparable to eavesdropping on a conversation - looking for freely available, public information. Difficult or impossible for the target to detect.

ACTIVE FOOTPRINTING

Direct interaction with the target - comparable to interrogation rather than eavesdropping. Detection by the target is possible.

Most footprinting work should start passive and stay passive as long as possible. Every active touch is a chance to be noticed.

What Attackers Are Looking For

Footprinting collects three broad categories of information:

SYSTEM INFO

OS type, running services, usernames and passwords exposed in the open.

NETWORK INFO

DNS records, domains and sub-domains, firewall rules and network boundaries.

ORGANIZATIONAL INFO

Contact info, employee details, and physical location info.

Why It Matters

  • Reveals what security controls are in place
  • Helps an attacker focus effort on live, reachable targets
  • Feeds directly into vulnerability identification

Footprinting rarely compromises a target directly - but it is the crucial setup step for social engineering, sensitive data exposure, and system or network hacking.

Google Dorks (Google Hacking)

Google dorks are advanced search operators that narrow results to exactly what a tester is looking for - turning a generic search engine into a footprinting tool.

site:target.com   → results only within one domain
filetype:pdf     → results limited to one file type
inurl:index      → string must appear in the URL
intext:"internal use only" → string must appear in the page text

Combined: site:target.com filetype:pdf "confidential"

Google Hacking Database (GHDB)

A curated, crowd-sourced collection of dorks known to surface footholds, vulnerable files, error messages, and sensitive directories (hosted at exploit-db.com). Reviewers use it as a starting point rather than inventing dorks from scratch.

Shodan & Censys

Where Google indexes web pages, Shodan and Censys index the devices and services themselves - including internet-connected devices with no traditional interface, like cameras, printers, industrial control systems, and VoIP/VPN endpoints.

Shodan Filter Syntax

printer port:21
camera has_screenshot:true

Filters follow a filter_name:search_string pattern, letting a tester narrow results to a specific device type, port, or organization.

Censys

Censys serves a similar purpose with its own search, summary, and history views - useful for cross-checking what Shodan surfaces about the same target infrastructure.

shodan.io
censys.io

Sub-Domain Enumeration

A domain's sub-domains (e.g. vpn.target.com, dev.target.com) are separate web presences used to organize a large site - and each one expands the attack surface.

Manual Discovery

site:target.com   → Google search restricted to the domain
view-source:        → page source code often leaks internal links

Automated Discovery

Manual searching doesn't scale. Testers automate sub-domain discovery with:

Netcraft
Sublist3r

Social Networking Recon

Facebook, LinkedIn, and Twitter/X regularly leak information employees never intended to make searchable: email addresses, job titles, professional connections, badges, and even the technologies their employer uses.

What This Reveals

  • Company info - locations, reviews, community posts
  • Employee info - email formats, job titles, interests, third-party connections

Tools

Sherlock - finds a username across many platforms at once
Social Searcher - public social-media search

Job Board Recon

Job postings are a footprinting goldmine. To attract the right candidate, employers routinely publish exactly the detail an attacker wants: job roles, contact info, office locations, email address formats, and - critically - the specific vendors and technology stack in use ("5+ years administering Cisco ASA firewalls and VMware vSphere 8").

A single posting requiring "experience with Windows Server 2019 and SQL Server 2017" tells an attacker exactly which CVEs to start researching.

Deep & Dark Web Recon

SURFACE WEB

Ordinary indexed sites - the web most people browse every day.

DEEP WEB

Content not indexed by search engines: paywalled content, cloud storage, webmail, banking. Estimated to represent roughly 90%+ of internet content.

DARK NET / DARK WEB

An intentionally anonymous, encrypted network layer (Tor, or friend-to-friend networks like Freenet). The "dark web" is the set of sites that live on the dark net.

Breach data, stolen credentials, and leaked credit card numbers frequently surface on dark web markets - making it a legitimate (if unpleasant) footprinting target for confirming whether an organization's data has already been exposed.

Email Tracking

Email tracking confirms whether a message was delivered and opened - and can reveal the recipient's IP address, geolocation, how long they read it, whether links were clicked, and their OS, browser, and device type.

How It Works

  • Read receipts - the recipient's client opts in to reporting status
  • Tracking pixels - a 1x1 image embedded in the email that phones home when loaded
  • Trackable links - a redirect URL that logs the click before forwarding

In a phishing-simulation exercise, this same technique measures who opened the message and who clicked - the metric that matters for a social-engineering awareness assessment.

WHOIS & DNS

WHOIS - Thick vs Thin

THICK MODEL

Returns complete detail: administrative, billing, and technical contacts plus full domain info.

THIN MODEL

Returns only a reference to the domain's registrar WHOIS server - no direct contact detail.

DNS Record Types Worth Knowing

A / AAAA  → hostname to IPv4 / IPv6 address
MX        → mail server for the domain
NS        → authoritative name servers
CNAME     → alias to another hostname
TXT       → free-form text (SPF, verification, etc.)

Lookup tools: nslookup, dig, dnsrecon.

Zone Transfers

A zone transfer replicates every DNS record from a primary server to a secondary - meant for legitimate server sync, but a goldmine if a misconfigured server answers a stranger's request. A safe, purpose-built legal training target exists for practicing this exact technique:

dig axfr @nsztm1.digi.ninja zonetransfer.me

Social Engineering Recon

Not all footprinting happens on a screen. Human-facing recon techniques gather network info, access credentials, security control make/model, and OS details straight from people.

EAVESDROPPING

Listening in on conversations; intercepting phone, email, text, audio, or video communications.

SHOULDER SURFING

Watching over someone's shoulder for passwords, PINs, or account numbers.

DUMPSTER DIVING

Retrieving discarded day calendars, sticky notes, and printouts from the trash.

IMPERSONATION

Posing as someone else in phone or in-person conversations to extract information.

Other Tools & Countermeasures

Additional Footprinting Tools

FOCA - document metadata extraction
OSINT Framework - curated OSINT tool index
Recon-ng / Recon-Dog - automated recon frameworks
Maltego - link-analysis graphing

Defending Against Footprinting

  • Review and edit what information is publicly available; back it with a security policy
  • Run end-user security-awareness training
  • Opt in to a WHOIS privacy service
  • Encrypt sensitive communications and data
  • Sanitize job listings - don't name exact internal tech versions
  • Disable device location services

Key Takeaways
