Passive vs Active Reconnaissance

The first critical decision in reconnaissance: how visible do you want to be? Each approach has advantages and risks.

Passive Reconnaissance

Gathering information without directly interacting with the target

  • No direct contact with target systems
  • Cannot be detected or logged
  • Uses publicly available information
  • Safe, legal, stealthy
  • Limited scope of information
  • May be outdated or incomplete
# Examples:
- Google searches
- WHOIS lookups
- DNS records
- Social media
- Job postings
- Archive.org

Active Reconnaissance

Directly interacting with target systems to gather information

  • Direct contact with target
  • Generates logs and alerts
  • More accurate, current data
  • Can discover hidden assets
  • Potentially detectable
  • May trigger defensive responses
# Examples:
- Port scanning
- Ping sweeps
- DNS zone transfers
- Banner grabbing
- Web crawling
- Social engineering

Best Practice: Always start with passive recon. Exhaust all passive sources before moving to active techniques. The more you know passively, the more targeted and efficient your active recon can be.

Open Source Intelligence (OSINT) refers to information collected from publicly available sources. The internet is a goldmine of intelligence if you know where to look.

Public Websites
Social Media

Search Engines

High-Value OSINT Targets

  • Job Postings - Reveal technologies, tools, and infrastructure in use
  • LinkedIn Profiles - Organizational structure, employee names, roles, technologies

Google Dorking

Google's search operators are incredibly powerful for targeted reconnaissance. "Google Dorking" (also called Google Hacking) uses advanced operators to find specific information that regular users would never discover.

Essential Operators

site:example.com # Search only example.com
filetype:pdf # Find specific file types
intitle:"index of" # Directory listings
inurl:admin # URLs containing "admin"
intext:"password" # Pages containing specific text
cache:example.com # Google's cached version
-word # Exclude results with "word"
"exact phrase" # Exact match search
* # Wildcard operator

Powerful Dork Examples

Find Exposed Configuration Files

site:example.com filetype:env
site:example.com filetype:config
site:example.com inurl:web.config

Find Login Pages

site:example.com intitle:"login" OR intitle:"sign in"
site:example.com inurl:admin OR inurl:administrator

Find Exposed Documents

site:example.com filetype:pdf OR filetype:docx OR filetype:xlsx
site:example.com intitle:"index of" "confidential"

Legal Consideration

Finding public information is legal. Accessing protected resources, even if found via Google, may not be. Proceed carefully and stay within authorization.

WHOIS & DNS Reconnaissance

Domain registration and DNS records contain valuable intelligence about ownership, infrastructure, and associated resources.

WHOIS Lookups

WHOIS databases contain domain registration information including registrant details, registration dates, nameservers, and sometimes contact information (unless privacy-protected).

# Basic WHOIS lookup
whois example.com

# Key information to extract:
- Registrant name/organization
- Registration/expiration dates
- Nameservers
- Registrar
- Administrative/technical contacts

DNS Record Types

  • A Record - Maps domain to IPv4 address
  • AAAA Record - Maps domain to IPv6 address
  • MX Record - Mail servers for the domain
  • NS Record - Nameservers for the domain
  • TXT Record - Text records (SPF, DKIM, verification codes)
  • CNAME Record - Canonical name (alias) for another domain
  • SOA Record - Start of authority (primary nameserver info)
# Query specific DNS records
dig example.com A # IPv4 address
dig example.com MX # Mail servers
dig example.com TXT # Text records
dig example.com ANY # All records

# Reverse DNS lookup
dig -x 192.168.1.1 # IP to hostname

DNS Zone Transfers

A DNS zone transfer (AXFR) replicates entire DNS zone data. Misconfigured DNS servers may allow unauthorized zone transfers, revealing all subdomains and internal infrastructure.

# Attempt zone transfer
dig @nameserver example.com AXFR

# If successful, you get complete subdomain list

Shodan: The Search Engine for IoT

While Google indexes websites, Shodan indexes internet-connected devices. It's the most powerful tool for discovering exposed infrastructure, IoT devices, industrial control systems, and misconfigured services.

What Shodan Finds

  • Web servers and their banners (revealing software versions)
  • IoT devices (cameras, routers, smart home devices)
  • Industrial Control Systems (SCADA, ICS)
  • Database servers exposed to the internet
  • Network equipment (switches, firewalls, VPNs)
  • Webcams and surveillance systems
  • Medical devices
  • Power grid infrastructure

Shodan Search Operators

port:443 # Search by port
country:US # Filter by country
city:"New York" # Filter by city
org:"Company Name" # Search by organization
hostname:example.com # Specific hostname
product:"Apache" # Specific software
version:"2.4.41" # Specific version
os:"Windows" # Operating system
ssl:"example.com" # SSL certificate contains domain
http.title:"Dashboard" # Page title contains text

Powerful Search Examples

Find Default Credentials

"default password"
http.title:"Dashboard" http.title:"Default password"

Find Organization's Assets

org:"Example Corp" country:US
ssl:"example.com" -port:443 -port:8443

Ethical Consideration

Finding exposed systems on Shodan is legal. Accessing them without authorization is not. Use Shodan for reconnaissance only - do not interact with systems you don't own.

Email Harvesting

Email addresses are valuable intelligence. They reveal naming conventions, organizational structure, and provide targets for social engineering and password attacks.

Why Harvest Emails?

  • Social Engineering - Valid targets for phishing campaigns
  • Naming Conventions - Learn firstname.lastname@, flastname@, etc.
  • Organizational Structure - Departments, roles, hierarchies
  • Password Attacks - Username enumeration for credential stuffing
  • OSINT Pivoting - Find social media profiles, other accounts

Harvesting Techniques

theHarvester

Automated email harvesting from multiple sources
# Search all sources for emails
theHarvester -d example.com -b all

# Specific sources
theHarvester -d example.com -b google
theHarvester -d example.com -b linkedin
theHarvester -d example.com -b bing

Hunter.io

Web-based email finder and verifier

Web service that finds email addresses associated with a domain, shows email patterns, and verifies if addresses are valid. Free tier available, API for automation.

Manual Harvesting Sources

  • Company websites (About Us, Contact, Team pages)
  • LinkedIn profiles and company pages
  • GitHub commits and profile READMEs
  • Job postings (recruiter contact information)
  • Conference presentations and papers
  • Mailing list archives
  • WHOIS records (if not privacy-protected)
  • Google Dorking: site:example.com "@example.com"

Metadata Analysis

Metadata is "data about data" - hidden information embedded in files that reveals usernames, software versions, GPS coordinates, edit history, and more.

EXIF Data in Images

Digital photos contain Exchangeable Image File (EXIF) data including camera model, timestamp, GPS coordinates, and sometimes even the photographer's name.

# Extract EXIF data
exiftool image.jpg

# Common EXIF fields:
- GPS Latitude/Longitude
- Camera Make/Model
- Date/Time Original
- Software used for editing
- Author/Copyright

Document Metadata

Microsoft Office documents, PDFs, and other files contain metadata including author names, company names, software versions, edit history, and internal file paths.

What You Can Learn from Document Metadata

  • Author/Creator - Real names of employees
  • Company - Internal company name
  • Software Version - Office 2019, Acrobat DC, etc.
  • Creation/Modification Dates - Document timeline
  • File Paths - Internal directory structures (e.g., C:\Users\jsmith\Documents\Internal\)
  • Printer Information - Network printer names
  • Revision History - How many times edited
# Extract metadata from PDF
exiftool document.pdf
pdfinfo document.pdf

# Extract from Office documents
exiftool document.docx

# Bulk metadata extraction
exiftool -r -csv /path/to/folder > metadata.csv

Operational Security

Always strip metadata from files before publishing them online. Many security incidents have occurred because sensitive metadata was accidentally exposed.

Social Media OSINT

People share an incredible amount of information on social media - often without realizing its intelligence value. Social media is a goldmine for reconnaissance.

LinkedIn Intelligence

  • Organizational Structure - Who reports to whom, department sizes
  • Technologies in Use - Skills listed reveal tech stack
  • Hiring Trends - Growing teams indicate new projects/initiatives
  • Employee Timeline - Tenure, previous companies, career progression
  • Connections - Business relationships, partners, clients
  • Company Updates - New products, acquisitions, expansions

Twitter/X Intelligence

  • Real-time updates and announcements
  • Employee complaints and frustrations (potential insider threats)
  • Conference attendance and presentations
  • Technology discussions and problems
  • Geolocation data from tweets

Facebook/Instagram Intelligence

  • Personal interests and hobbies (social engineering angles)
  • Family members and relationships
  • Location check-ins and patterns
  • Photos revealing office layouts, badges, whiteboards
  • Vacation schedules (times when users are unavailable)

GitHub Intelligence

  • Source code (look for hardcoded credentials, API keys)
  • Internal project names and architectures
  • Technology choices and frameworks
  • Development practices and security awareness
  • Contributor names (employee identification)

Real-World Scenario

A developer posts on Twitter: "Finally got our new Cisco ASA firewall configured after fighting with version 9.8 bugs all week. #NetworkLife"

Intelligence gained: Company uses Cisco ASA, specific version 9.8, recent deployment (may have misconfigurations), admin was frustrated (may have rushed job).

Automated OSINT Tools

Manual reconnaissance is effective but time-consuming. Automated tools aggregate information from multiple sources and visualize relationships between entities.

Maltego

Visual link analysis and data mining tool

Maltego creates visual graphs showing relationships between people, companies, domains, IP addresses, and other entities. It uses "transforms" to query various data sources and automatically map connections.

Key Features

  • Visual graph interface showing entity relationships
  • Automated transforms query WHOIS, DNS, social media, search engines
  • Custom transforms can be written for specific data sources
  • Export findings to reports
  • Community edition available (limited transforms)

Common Use Cases

  • Mapping an organization's infrastructure (domains → IPs → nameservers)
  • Finding relationships between people and companies
  • Discovering associated domains and subdomains
  • Social network analysis

Recon-ng

Modular web reconnaissance framework (like Metasploit for OSINT)

Recon-ng is a command-line framework with modules for various reconnaissance tasks. It uses a database to store findings and allows chaining modules together.

# Launch Recon-ng
recon-ng

# Create workspace
workspaces create example_target

# Search for modules
marketplace search
marketplace search dns

# Install and use a module
marketplace install recon/domains-hosts/hackertarget
modules load recon/domains-hosts/hackertarget
options set SOURCE example.com
run

Module Categories

  • recon - Reconnaissance modules (DNS, WHOIS, subdomain enum)
  • discovery - Information discovery (email harvest, employee enum)
  • reporting - Generate reports from collected data
  • import - Import data from external sources

Building a Target Profile

Reconnaissance isn't about collecting random data. It's about building a comprehensive target profile that guides your attack strategy.

Essential Profile Components

1. Technical Infrastructure

  • Domain names and subdomains
  • IP address ranges (netblocks)
  • Hosting providers and data center locations
  • Web servers, mail servers, DNS servers
  • Technologies in use (Apache, IIS, WordPress, etc.)
  • Software versions (outdated = vulnerable)
  • SSL/TLS certificates and expiration dates
  • Email security (SPF, DMARC, DKIM)

2. Organizational Intelligence

  • Company structure and departments
  • Key personnel (executives, IT staff, developers)
  • Employee count and growth trends
  • Locations and office addresses
  • Business partners and vendors
  • Acquisitions and subsidiaries
  • Projects and initiatives

3. Human Intelligence

  • Email addresses and naming conventions
  • Employee social media profiles
  • Technical skills and expertise areas
  • Grievances and complaints (potential insider threats)
  • Personal interests (social engineering angles)
  • Work schedules and availability patterns

Synthesizing Intelligence

The goal is to identify attack vectors. Ask yourself:

  • What are the weakest entry points?
  • Which systems are outdated or misconfigured?
  • Who are the most vulnerable users to target?
  • What technologies can I exploit?
  • Where are the gaps in their security posture?

Defensive Countermeasures

Understanding reconnaissance helps you defend against it. As an ethical hacker, you must also advise clients on reducing their reconnaissance footprint.

Reducing the Attack Surface

  • WHOIS Privacy Protection - Mask registrant information
  • Disable DNS Zone Transfers - Only allow authorized servers
  • Remove Server Banners - Don't advertise software versions
  • Limit Public Information - Only publish what's necessary
  • Monitor Exposed Services - Regular Shodan searches on your own assets
  • Metadata Stripping - Remove metadata from published documents
  • Security Awareness Training - Educate employees on oversharing

Monitoring for Reconnaissance

  • Web Server Logs - Unusual crawling patterns, directory enumeration
  • DNS Query Logs - Excessive AXFR requests, subdomain brute-forcing
  • Firewall Logs - Port scanning attempts, connection patterns
  • IDS/IPS Alerts - Reconnaissance signatures (Nmap, Nikto, etc.)
  • Google Alerts - Notifications when your domain appears in new results
  • Dark Web Monitoring - Mentions of your organization

Social Media Controls

  • Social media policy for employees
  • Limit technical details shared publicly
  • Review job postings for sensitive information
  • Monitor employee social media for OPSEC violations
  • Disable geolocation features on company accounts

The Paradox of Reconnaissance

You cannot make yourself invisible on the internet and still do business. The goal is not to eliminate your footprint, but to control what information is available and monitor for reconnaissance attempts.
