Network Attack Categories

Network attacks can be classified along multiple dimensions to understand their nature and impact:

Passive vs Active Attacks

Passive Attacks

Goal: Information gathering without detection

  • Packet sniffing
  • Traffic analysis
  • Eavesdropping
  • Port scanning (sometimes)

Detection: Extremely difficult

Active Attacks

Goal: Modify data or disrupt service

  • Man-in-the-middle
  • Session hijacking
  • DoS/DDoS
  • ARP/DNS poisoning

Detection: More detectable, leaves evidence

Internal vs External Attacks

  • Internal: Originate from within trusted network perimeter (insider threats, compromised devices)
  • External: Originate from outside network (requires bypassing perimeter defenses)
Layered Defense Principle: Different attack types require different defensive strategies. No single security control protects against all network attacks.

Packet Sniffing Attacks

Packet sniffing captures network traffic to intercept sensitive data transmitted in clear text:

How Packet Capture Works

  • Promiscuous Mode: NIC accepts all packets, not just those destined for its MAC address
  • Switched Network Limitation: Modern switches only send traffic to intended recipient
  • Workarounds: ARP poisoning, MAC flooding, SPAN port access, physical taps

Wireshark - The Network Protocol Analyzer

# Common Wireshark capture filters tcp.port == 80 # Capture HTTP traffic http.request.method == POST # Capture HTTP POST requests ip.addr == 192.168.1.100 # Filter by IP address ftp or telnet # Capture insecure protocols # Display filter for credentials http.request.method == POST and http contains "password"

Vulnerable Protocols (Transmit in Clear Text)

Insecure
  • HTTP (port 80)
  • FTP (port 21)
  • Telnet (port 23)
  • SMTP (port 25)
Secure Alternatives
  • HTTPS (port 443)
  • SFTP/FTPS (ports 22/990)
  • SSH (port 22)
  • SMTPS (port 465/587)
Legal Warning: Packet sniffing on networks you don't own or have authorization for is illegal. Always obtain written permission before any network testing.

ARP Poisoning (ARP Spoofing)

ARP poisoning exploits the stateless nature of ARP to associate attacker's MAC with victim's IP:

ARP Protocol Basics

Normal ARP Process: 1. Computer A: "Who has IP 192.168.1.100? Tell 192.168.1.50" 2. Computer B: "192.168.1.100 is at MAC aa:bb:cc:dd:ee:ff" 3. Computer A caches this mapping in ARP table Problem: ARP accepts unsolicited replies (no authentication)

ARP Poisoning Attack Flow

Victim A
192.168.1.50
↔
Attacker
192.168.1.75
(Intercepts all traffic)
↔
Router
192.168.1.1
Attacker sends fake ARP replies:
To Victim: "192.168.1.1 is at [Attacker MAC]"
To Router: "192.168.1.50 is at [Attacker MAC]"

Tools for ARP Poisoning

# Ettercap - Popular ARP poisoning tool ettercap -T -M arp:remote /192.168.1.50// /192.168.1.1// # arpspoof (part of dsniff) arpspoof -i eth0 -t 192.168.1.50 192.168.1.1 # Enable IP forwarding to relay traffic echo 1 > /proc/sys/net/ipv4/ip_forward
Defense: Static ARP entries, Dynamic ARP Inspection (DAI) on switches, ARP monitoring tools (arpwatch), encrypted protocols (HTTPS, SSH) prevent data theft even if MiTM successful.

Man-in-the-Middle (MiTM) Attacks

MiTM attacks position the attacker between two communicating parties to intercept or modify traffic:

SSL Stripping Attack

Forces victims to use unencrypted HTTP instead of HTTPS:

Normal Flow: User → HTTPS → Bank (Encrypted, secure) SSL Stripping: User → HTTP → Attacker → HTTPS → Bank ↑ ↑ Unencrypted Encrypted (Attacker sees (Bank thinks it's everything) talking to user)

SSL Stripping Tools

# sslstrip - Transparent HTTPS stripping proxy iptables -t nat -A PREROUTING -p tcp --destination-port 80 \ -j REDIRECT --to-port 8080 sslstrip -l 8080 # Modern equivalent: mitmproxy mitmproxy --mode transparent --ssl-insecure

Session Hijacking

  • Cookie theft: Stealing session cookies to impersonate user
  • Session fixation: Forcing victim to use attacker-known session ID
  • TCP hijacking: Taking over established TCP connection (sequence number prediction)
Defense Against MiTM:
  • HSTS (HTTP Strict Transport Security) prevents SSL stripping
  • Certificate pinning validates specific certificate
  • Mutual authentication (client certificates)
  • Monitor for suspicious ARP traffic
  • Use VPN on untrusted networks

DNS Attacks

DNS attacks manipulate domain name resolution to redirect victims or gather information:

DNS Cache Poisoning

Inject fake DNS records into resolver's cache to redirect legitimate domain queries:

Attack Process: 1. Attacker sends flood of DNS responses to resolver 2. Responses contain fake data: "bank.com = 192.168.1.666" 3. If response arrives before legitimate one, fake entry cached 4. All users querying that resolver get poisoned response Result: Users directed to attacker's server when visiting bank.com

DNS Spoofing

Similar to poisoning, but targets local network (often combined with ARP poisoning):

# dnsspoof (part of dsniff suite) dnsspoof -i eth0 -f dns_hosts.txt # dns_hosts.txt example: 192.168.1.666 *.bank.com 192.168.1.666 facebook.com

DNS Tunneling

Covert channel technique to bypass firewall restrictions:

  • Data exfiltration: Encode data in DNS queries/responses
  • C2 communications: Malware communicates via DNS
  • Bypassing restrictions: DNS usually allowed through firewalls
Example DNS tunneling query: 64617461746f6578666974726174.attacker-domain.com Decoded: "datatoexfitrat" (hex encoded data in subdomain)
DNS Security Measures: DNSSEC (cryptographic signatures), monitoring for excessive DNS queries, DNS query length restrictions, using trusted DNS resolvers (1.1.1.1, 8.8.8.8).

DHCP Attacks

DHCP attacks exploit the automatic IP configuration process to disrupt networks or facilitate other attacks:

Rogue DHCP Server

Attacker sets up unauthorized DHCP server to provide malicious network configuration:

Malicious DHCP Response: IP Address: 192.168.1.150 (Valid) Subnet Mask: 255.255.255.0 (Valid) Default Gateway: 192.168.1.666 (Attacker's machine - MiTM) DNS Server: 192.168.1.666 (Attacker's DNS - Spoofing) Result: All traffic routed through attacker

DHCP Starvation Attack

Exhaust DHCP pool by requesting all available IP addresses:

Attack Process: 1. Attacker sends thousands of DHCP requests with fake MAC addresses 2. DHCP server assigns IPs until pool exhausted 3. Legitimate users cannot obtain IP addresses 4. Network denial of service # Tool: yersinia yersinia -G # GUI mode for DHCP attacks

DHCP Starvation → Rogue DHCP Combo

1. Starve legitimate DHCP
→
2. Deploy rogue DHCP
→
3. Control all new connections
DHCP Security:
  • DHCP Snooping: Switch feature that validates DHCP messages
  • Port Security: Limit MAC addresses per switch port
  • 802.1X: Network access control before DHCP assignment
  • Static IP assignments: For critical infrastructure

Denial of Service & Distributed DoS

DoS attacks make systems or networks unavailable to legitimate users:

SYN Flood Attack

Exploits TCP three-way handshake to exhaust server resources:

Normal TCP Handshake: Client → SYN → Server Client ← SYN-ACK ← Server Client → ACK → Server Connection established SYN Flood: Attacker → SYN (spoofed source) → Server Server ← SYN-ACK (to spoofed IP, never returns) Server waits... connection half-open (consuming resources) Result: Connection table fills, legitimate users rejected

Amplification Attacks

Use third-party servers to amplify attack traffic:

DNS Amplification

Request: 60 bytes

Response: 3000+ bytes

Amplification: 50x

NTP Amplification

Request: 8 bytes

Response: 468 bytes

Amplification: 58x

Application Layer DDoS (Layer 7)

  • HTTP Flood: Overwhelming web server with legitimate-looking requests
  • Slowloris: Opens many connections, sends partial requests slowly
  • XML bomb: Deeply nested XML causes parser resource exhaustion
DDoS Mitigation: Rate limiting, SYN cookies, traffic scrubbing services (Cloudflare, Akamai), network capacity planning, geo-blocking, CAPTCHA for suspicious traffic.

Wireless Network Attacks

Wireless networks introduce unique attack vectors due to the broadcast nature of radio signals:

Evil Twin Attack

Create fake access point with same SSID as legitimate network:

Setup: 1. Attacker creates AP with SSID "CompanyWiFi" 2. Boosts signal strength or deauths users from real AP 3. Victims connect to evil twin 4. Attacker intercepts all traffic, steals credentials # Create fake AP with hostapd hostapd hostapd.conf

Deauthentication Attack

Force clients to disconnect from wireless network:

# aireplay-ng deauth attack aireplay-ng --deauth 0 -a [AP_MAC] -c [CLIENT_MAC] wlan0mon Uses: - Force reconnection to capture WPA handshake - DoS attack against wireless users - Force connection to evil twin

WPA/WPA2 Cracking Concepts

  • Capture 4-way handshake: Passive capture or forced via deauth
  • Offline dictionary attack: Test passwords against captured handshake
  • WPS PIN attack: Brute force 8-digit WPS PIN (if enabled)
  • PMKID attack: Attack WPA2 without capturing full handshake
Wireless Security Best Practices:
  • Use WPA3 where supported (resistant to offline dictionary attacks)
  • Disable WPS completely
  • Strong, complex passphrase (20+ characters)
  • 802.1X authentication for enterprise
  • Wireless IDS to detect rogue APs and attacks

VLAN Hopping Attacks

VLAN hopping allows attackers to bypass network segmentation and access isolated VLANs:

Switch Spoofing

Attacker negotiates trunk link with switch to access all VLANs:

Attack Process: 1. Attacker port configured as access port (default) 2. Attacker sends DTP (Dynamic Trunking Protocol) messages 3. Switch negotiates trunk mode with attacker 4. Attacker now receives traffic from all VLANs # Disable DTP on all access ports: switchport mode access switchport nonegotiate

Double Tagging Attack

Exploits how switches handle 802.1Q VLAN tags:

Attacker crafts packet with TWO VLAN tags:

[Ethernet Header][VLAN 10 tag][VLAN 20 tag][Payload]
                    ↑               ↑
                 Outer tag      Inner tag
                 (stripped)     (processed)

Flow:
1. First switch strips outer tag (VLAN 10)
2. Forwards frame based on inner tag (VLAN 20)
3. Packet reaches VLAN 20 (isolated network)

Prerequisites for Double Tagging

  • Attacker must be on native VLAN of trunk
  • Only works for one-way traffic (response can't return)
  • Useful for reconnaissance and certain DoS attacks
VLAN Security Hardening:
  • Change native VLAN from default (VLAN 1)
  • Disable DTP: switchport nonegotiate
  • Explicitly configure access ports: switchport mode access
  • Use Private VLANs for additional isolation
  • Regular switch configuration audits

Network Defense Strategies

Comprehensive network security requires layered defenses across multiple domains:

Intrusion Detection & Prevention Systems

IDS (Detection)

Function: Monitor and alert

  • Passive monitoring
  • Generates alerts
  • Doesn't block traffic
  • Useful for analysis

IPS (Prevention)

Function: Detect and block

  • Inline deployment
  • Actively blocks threats
  • Can drop packets
  • Risk of false positives

Network Segmentation

Defense in Depth with Segmentation: Internet ─┬─ DMZ (Web servers, email) ─── Firewall │ ├─ User Network (VLAN 10) ────── Firewall │ ├─ Server Network (VLAN 20) ──── Firewall │ └─ Management Network (VLAN 30) ─ Strict ACLs Breach in one segment doesn't compromise entire network

Zero Trust Architecture

Never trust, always verify - continuous authentication and authorization:

  • Verify explicitly: Authenticate/authorize based on all data points
  • Least privilege access: Just-in-time, just-enough-access (JIT/JEA)
  • Assume breach: Minimize blast radius, segment access
  • Microsegmentation: Granular network zones, even for internal traffic
Additional Network Controls: Network Access Control (NAC), SIEM for log aggregation, regular vulnerability scanning, network behavior analytics, encrypted protocols everywhere.
