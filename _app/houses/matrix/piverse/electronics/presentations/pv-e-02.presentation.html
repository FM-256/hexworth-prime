GPIO with Scratch
Visual programming meets physical computing -- control LEDs and read buttons without writing code.
Scratch 3 on Pi OS includes GPIO extensions that let you control hardware using drag-and-drop blocks. It is the fastest path from zero to blinking an LED -- no syntax errors, no terminal, no debugging. Perfect for understanding GPIO concepts before moving to Python.

Scratch 3 GPIO Extension
Scratch on Pi OS ships with a built-in extension that talks to GPIO pins through the Simple Electronics blocks.
1Open Scratch 3 from the Pi OS menu: Programming > Scratch 3. The GPIO extension is pre-installed on Pi OS.
2Add the extension: Click the blue "Add Extension" button (bottom-left). Select "Raspberry Pi Simple Electronics". This adds GPIO blocks to your palette.
3New blocks appear: "set gpio [pin] to output [high/low]", "when gpio [pin] is [high/low]", and "gpio [pin] is high?" boolean block.
4Pin numbering: Scratch uses BCM numbering. GPIO17 in Scratch is the same GPIO17 you see in pinout.
No Install Required
The Simple Electronics extension is bundled with Scratch 3 on Pi OS. It communicates with GPIO through the scratch_gpio service that runs in the background. If you are using the web version of Scratch, the GPIO extension is NOT available -- it only works on the native Pi OS application.

Wiring an LED Circuit
Before writing any blocks, you need a physical circuit. One LED, one resistor, two wires.
GPIO17 (Pin 11)
Connect a jumper wire from Pin 11 on the header to one leg of a 330-ohm resistor on the breadboard.
330-ohm Resistor
The resistor limits current to about 4mA. Without it, the LED draws too much current and can damage the GPIO pin.
LED + GND
LED anode (long leg) to resistor, cathode (short leg) to GND (Pin 6). Current flows from GPIO through resistor through LED to ground.

Blinking an LED in Scratch
The classic first project: turn an LED on and off in a loop using Scratch blocks.
Scratch Block Sequence: when green flag clicked forever set gpio 17 to output high wait 1 seconds set gpio 17 to output low wait 1 seconds
What Happens
GPIO17 goes HIGH (3.3V) for 1 second, then LOW (0V) for 1 second, forever. The LED blinks at a 0.5 Hz rate. Click the red stop button to halt execution and turn the LED off.
Modify the Timing
Change the wait values to speed up or slow down the blink. Try 0.1 seconds for rapid flashing, or 0.5 for a heartbeat effect. The minimum resolution is about 0.05 seconds in Scratch.
No Syntax Errors
The block-based approach eliminates typos, missing colons, and indentation errors. If the blocks snap together, the program is syntactically valid. This lets you focus on the logic and the circuit rather than language mechanics.

Reading a Button Input
Input is the other half of GPIO. Wire a button and read its state with Scratch event blocks.
Scratch Block Sequence: when gpio 4 is low set gpio 17 to output high wait 0.5 seconds set gpio 17 to output low
Pull-Up Logic
With the internal pull-up enabled, GPIO4 reads HIGH when the button is not pressed. When pressed, the button connects GPIO4 to GND, pulling it LOW. The Scratch block "when gpio 4 is low" fires on button press.

Traffic Light Project
Combine three LEDs into a traffic light sequence -- a classic pattern for learning GPIO sequencing.
1Wire three LEDs: Red on GPIO17, Yellow on GPIO27, Green on GPIO22. Each with a 330-ohm resistor to GND.
2Green phase: Green HIGH for 5 seconds. Red and Yellow LOW.
3Yellow phase: Green goes LOW, Yellow goes HIGH for 2 seconds.
4Red phase: Yellow goes LOW, Red goes HIGH for 5 seconds.
5Red+Yellow phase: Red stays HIGH, Yellow goes HIGH for 2 seconds, then both go LOW and Green goes HIGH. Loop forever.
UK Traffic Sequence
This follows the UK pattern: Green, Yellow, Red, Red+Yellow, Green. The Red+Yellow phase warns drivers the light is about to go green. US traffic lights skip this step. Either pattern works for learning GPIO sequencing.

Variables and Conditional Logic
Scratch variables let you track state. Combine them with if/else blocks for reactive GPIO programs.
Button-toggled LED with Scratch variables: when green flag clicked set [led_state] to 0 forever if gpio 4 is low? then if [led_state] = 0 then set gpio 17 to output high set [led_state] to 1 else set gpio 17 to output low set [led_state] to 0 wait 0.3 seconds -- debounce delay wait until not gpio 4 is low?
Toggle Logic
The variable led_state tracks whether the LED is on (1) or off (0). Each button press flips the state. The "wait 0.3 seconds" prevents the button bounce from toggling multiple times.
Debouncing
Mechanical buttons bounce -- the contact makes and breaks rapidly for a few milliseconds. The wait block after toggling prevents reading the bounced signal as multiple presses.

PWM and LED Brightness
Scratch can control LED brightness using PWM output blocks with values from 0 to 100.
Breathing LED effect in Scratch: when green flag clicked forever set [brightness] to 0 repeat 20 change [brightness] by 5 set gpio 17 to output pwm [brightness] wait 0.05 seconds repeat 20 change [brightness] by -5 set gpio 17 to output pwm [brightness] wait 0.05 seconds
Software PWM
Scratch uses software PWM, not hardware PWM. The duty cycle value ranges from 0 (off) to 100 (full brightness). This is sufficient for LED effects but not precise enough for servo control. For servos, use Python with hardware PWM.

Buzzer and Sound Output
An active buzzer produces sound when voltage is applied. Wire it like an LED and control it from Scratch.
Active Buzzer
An active buzzer has a built-in oscillator. Apply 3.3V and it beeps. Wire it from GPIO to buzzer positive, buzzer negative to GND. No resistor needed for most active buzzers.
Passive Buzzer
A passive buzzer needs a frequency signal to produce sound. Use PWM in Scratch to generate different tones. Different PWM frequencies = different musical notes.
Doorbell with button and buzzer: when gpio 4 is low set gpio 22 to output high -- buzzer on wait 0.5 seconds set gpio 22 to output low -- buzzer off

Scratch vs Python GPIO
Understanding when to move from Scratch to Python for GPIO projects.
Scratch Strengths
Zero syntax errors. Visual debugging (you see which block is executing). Instant feedback. Great for prototyping circuits and learning GPIO concepts. Perfect for beginners and for testing wiring before coding in Python.
Scratch Limitations
No I2C/SPI support. No interrupt handling. Limited timing precision. Cannot run headless. No access to advanced libraries. Projects that need sensors, networking, or file I/O require Python.
Transition Strategy
Prototype your circuit in Scratch to verify wiring works, then rewrite the logic in Python for production. The GPIO concepts (HIGH/LOW, input/output, pull-ups) are identical in both environments. Only the syntax changes.

Common Troubleshooting
When your LED does not blink, check these issues in order.
1LED orientation: LEDs are polarized. The long leg (anode) goes toward GPIO, short leg (cathode) toward GND. Reversed = no light.
2Wrong pin: Scratch uses BCM numbers. GPIO17 is physical pin 11, not pin 17. Use pinout to verify.
3Breadboard rows: Components in the same row are connected. The resistor and LED leg must share a row. The gap in the middle of the breadboard breaks the connection.
4Extension not loaded: If the GPIO blocks are missing, you need to click "Add Extension" and select "Raspberry Pi Simple Electronics".
5Loose wires: Push jumper wires firmly into the breadboard. A half-inserted wire makes intermittent contact that causes flickering or no response.

Key Takeaways: GPIO with Scratch
Five facts from your first visual GPIO programming experience.
1Scratch 3 on Pi OS includes GPIO blocks. Add the "Raspberry Pi Simple Electronics" extension to access set gpio, when gpio is, and gpio is high? blocks.
2Wire first, code second. Build the physical circuit (LED + resistor + GND) before touching Scratch. Verify wiring with the pinout command.
3Buttons need pull resistors. Scratch uses internal pull-ups. Wire the button between GPIO and GND. "Low" = pressed.
4PWM controls brightness. Values 0-100 set the duty cycle. Use a repeat loop with small increments for smooth fading effects.
5Scratch is for prototyping. Use it to verify circuits and learn concepts. Move to Python when you need I2C, SPI, interrupts, or headless operation.
