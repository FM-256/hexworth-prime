The 40-Pin Header
Every Pi since the Model B+ (2014) exposes a standard 2x20 pin header. Pin 1 is nearest the board corner.
Power Pins
Two 5V pins (pins 2, 4), two 3.3V pins (pins 1, 17), and eight GND pins. Power comes from the USB-C supply through the header.
GPIO Pins
26 general-purpose I/O pins. Each can be configured as input or output. All operate at 3.3V logic -- never apply 5V to a GPIO pin.
I2C Bus
GPIO2 (SDA) and GPIO3 (SCL) on pins 3 and 5. Used for sensors, displays, and HATs. Has built-in 1.8k pull-up resistors.
SPI Bus
SPI0: MOSI (GPIO10), MISO (GPIO9), SCLK (GPIO11), CE0 (GPIO8), CE1 (GPIO7). High-speed peripheral communication.
UART
TX (GPIO14) and RX (GPIO15) on pins 8 and 10. Serial console or device communication at configurable baud rates.
PWM
Hardware PWM on GPIO12, GPIO13, GPIO18, GPIO19. Software PWM available on any GPIO pin via gpiozero or pigpio.
Critical Rule
The Pi GPIO is 3.3V ONLY. Connecting a 5V signal directly to any GPIO pin will damage the SoC permanently. Use a level shifter or voltage divider when interfacing with 5V devices.

BCM vs BOARD Numbering
Two numbering systems exist. Use BCM -- it matches the SoC datasheet and is the default in gpiozero.
BCM (Broadcom) Numbering
Refers to the GPIO number as labeled on the Broadcom SoC. GPIO17 is always GPIO17 regardless of physical position. This is the standard used by gpiozero, lgpio, and pigpio. Use pinout at the terminal to see the full map.
BOARD (Physical) Numbering
Refers to the physical pin position on the header, numbered 1-40 from top-left. Pin 11 in BOARD mode is GPIO17 in BCM. The legacy RPi.GPIO library defaults to BOARD mode. This scheme can confuse beginners because the numbers do not match documentation.
Best Practice
Always use BCM numbering. Run pinout to display the header map in your terminal. The gpiozero library defaults to BCM. If you see a tutorial using GPIO.setmode(GPIO.BOARD), mentally translate pin numbers to BCM equivalents.

Voltage Rails: 3.3V and 5V
The header provides two voltage rails. Understanding which to use and why is essential for safe wiring.
3.3V for Logic
All GPIO pins output 3.3V when HIGH and 0V when LOW. Input pins expect 3.3V signals. The 3.3V rail is regulated by the Pi's onboard regulator and has limited current capacity.
5V for Power
The 5V pins connect directly to the USB-C power input. Use them to power 5V peripherals like servos, relay modules, or Neopixel strips. Never connect 5V to a GPIO input pin.
GND is Shared
All GND pins are internally connected. Every circuit must have a return path to GND. When connecting external devices, always share a common ground with the Pi.
Slide 5 of 12
Current Limits: Per-Pin and Total
Each GPIO pin can source or sink a limited amount of current. Exceeding these limits damages the SoC.
Per-Pin Maximum
Each GPIO pin can safely source or sink up to 16mA. The absolute maximum is 18mA -- do not design for this. A standard LED with a 330-ohm resistor draws about 5mA at 3.3V, well within limits.
Total GPIO Current
The combined current across ALL GPIO pins must not exceed 50mA. If you drive 10 LEDs at 5mA each, you hit the limit. For more current, use transistors, MOSFETs, or driver ICs.
Ohm's Law applied to LED circuit: V_supply = 3.3V V_led = ~2.0V (typical red LED forward voltage) I_target = 5mA (safe, visible brightness) R = (V_supply - V_led) / I_target R = (3.3 - 2.0) / 0.005 R = 260 ohms --> use 330 ohm (nearest standard value)
Damage Warning
There is no overcurrent protection on GPIO pins. If you short a GPIO pin to 5V or draw too much current, the BCM SoC is permanently damaged. There is no fuse, no recovery. Always calculate current draw before wiring.

Pull-Up and Pull-Down Resistors
Floating inputs are undefined. Pull resistors ensure a pin reads a known state when nothing is actively driving it.
1Internal pull-ups/downs: The BCM SoC has configurable internal pull resistors (~50k ohms) on every GPIO pin. gpiozero enables pull-up by default on Button inputs.
2External pull resistors: Use 10k ohm external resistors when the internal pulls are too weak for your circuit or when you need guaranteed behavior on noisy lines.
3Why it matters: A floating input oscillates between HIGH and LOW randomly, causing phantom button presses, false sensor triggers, and unpredictable behavior.
gpiozero Default
Button(4) enables the internal pull-up automatically. The button connects GPIO4 to GND when pressed. No external resistor needed for basic button circuits with gpiozero.

Level Shifting: 3.3V to 5V
Many sensors and modules operate at 5V. You need level shifting to safely interface them with the Pi's 3.3V GPIO.
Voltage Divider
Two resistors divide a 5V signal down to 3.3V. Use 1k and 2k (or 1k and 1.8k) for a 2:1 ratio. Simple, cheap, unidirectional. Good for slow signals like button inputs from 5V logic.
Bidirectional Level Shifter
A MOSFET-based module (like the BSS138) shifts signals in both directions. Required for I2C and SPI when the peripheral is 5V. Handles high-speed signals cleanly.
Buffer IC (74LVC245)
An 8-channel buffer that translates voltage levels. Good for parallel buses or when you need to shift many signals at once. Unidirectional per channel but fast and reliable.
Never Do This
Never connect a 5V output directly to a Pi GPIO pin. The internal clamping diodes will try to absorb the excess voltage, but sustained exposure destroys the SoC input circuitry. There is no software fix for hardware damage.

The pinout Command
The pinout command-line tool shows a visual map of every pin on your Pi model.
# Run in the terminal: pinout # Output shows: # - Board model and revision # - 40-pin header diagram with color-coded functions # - BCM numbers, BOARD numbers, and function labels # - Which pins are power, ground, I2C, SPI, UART, PWM # Check a specific GPIO pin state: raspi-gpio get 17 # GPIO 17: level=0 fsel=0 func=INPUT pull=DOWN # List all pin states: raspi-gpio get
pinout (gpiozero)
Installed with gpiozero. Shows a full-color ASCII diagram of the header for your specific Pi model. The most user-friendly way to identify pin functions.
raspi-gpio
Low-level tool that reads the actual hardware state of each GPIO pin. Shows current level (0/1), function select (input/output/alt), and pull configuration. Essential for debugging.

Alt Functions and Pin Multiplexing
Most GPIO pins have alternate functions. The SoC multiplexes multiple peripherals onto the same physical pins.
1GPIO4 (Pin 7): Default GPIO, but can be configured as GPCLK0 (general-purpose clock output) for timing-critical applications.
2GPIO14/15 (Pins 8/10): Default GPIO, but Alt0 = UART0 TX/RX. When you enable the serial console, these pins become UART and cannot be used as general GPIO.
3GPIO2/3 (Pins 3/5): Default is I2C1 SDA/SCL with built-in pull-ups. These are consumed by the I2C bus and should not be used as general GPIO.
4GPIO7-11 (Pins 26,24,21,19,23): Default GPIO, but Alt0 = SPI0 (CE1, CE0, MISO, MOSI, SCLK). Enabling SPI claims these five pins.
5Device Tree Overlays: The Pi uses device tree overlays (dtoverlay in /boot/config.txt) to assign alternate functions to pins at boot time.
Practical Impact
If you enable I2C, SPI, and UART, those pins are claimed by the kernel drivers. You have 26 GPIO pins total, minus 2 for I2C, minus 5 for SPI, minus 2 for UART = 17 remaining free GPIO pins for your project.

ESD and Protection Strategies
Electrostatic discharge can kill GPIO pins instantly. Apply these protections in every project.
ESD Protection
Touch a grounded metal surface before handling the Pi. Use an anti-static wrist strap for extended work. Store the Pi in an anti-static bag. ESD damage is cumulative and invisible until the pin fails completely.
Series Resistors
Place a 330-ohm to 1k-ohm resistor in series with every GPIO connection. This limits fault current if wiring errors occur. It adds negligible resistance for digital signals but provides a safety margin.
Clamping Diodes
External Schottky diodes clamp voltage spikes. Connect the anode to the GPIO pin and the cathode to 3.3V. Any voltage above 3.6V is diverted through the diode instead of the SoC.
Optocouplers
For complete electrical isolation, use an optocoupler (e.g., PC817). The LED side and phototransistor side share no electrical connection. Essential when interfacing with mains-powered equipment.

GPIO Across Pi Models
The 40-pin header is standard since the B+, but capabilities vary across models.
Pi 4 / Pi 400
BCM2711 SoC. Full 40-pin header. Two SPI buses, six I2C buses (via dt-overlay), four UART interfaces. USB 3.0 and Gigabit Ethernet. The most capable model for GPIO projects.
Pi 5
BCM2712 SoC with new RP1 I/O controller. Same 40-pin header but GPIO is managed by the RP1 chip, not the main SoC. The lgpio library replaces the deprecated RPi.GPIO.
Pi Zero 2 W
Same 40-pin header (unpopulated -- solder your own). BCM2710 quad-core. Full GPIO compatibility but lower current capacity from the smaller power regulator. Ideal for compact projects.
Library Compatibility
gpiozero works across all Pi models because it auto-detects the underlying pin factory (lgpio on Pi 5, RPi.GPIO or pigpio on older models). Write code once with gpiozero and it runs everywhere.

Key Takeaways: GPIO Architecture
Five facts that form the foundation for every electronics project on the Pi.
140 pins, 26 GPIO. The standard header provides power (3.3V, 5V), ground (8 pins), and 26 configurable I/O pins. Every Pi since the B+ uses this layout.
2BCM numbering is the standard. Use pinout to see the map. gpiozero, lgpio, and pigpio all default to BCM. Ignore BOARD numbering.
33.3V logic, 16mA per pin, 50mA total. Never exceed these limits. Use transistors or driver ICs for high-current loads. A single LED with a 330-ohm resistor is safe.
45V kills GPIO pins. Use level shifters or voltage dividers when interfacing with 5V devices. There is no overcurrent protection and no recovery from damage.
5Pull resistors prevent floating inputs. gpiozero enables internal pull-ups on Button() by default. For noisy environments, add external 10k pull resistors.
