GPIO with Python
gpiozero -- the Pythonic way to control LEDs, buttons, buzzers, and PWM from clean, readable code.
gpiozero wraps every GPIO device into a Python class. An LED is LED(17). A button is Button(4). No boilerplate setup, no pin mode configuration, no cleanup code. Write what you mean and the library handles the hardware.

The LED Class
One line to create, one method to control. LED is the simplest gpiozero output device.
from gpiozero import LED from time import sleep led = LED(17) # GPIO17, BCM numbering led.on() # 3.3V on pin -- LED lights sleep(1) led.off() # 0V on pin -- LED dark sleep(1) led.toggle() # Flip current state led.blink(0.5, 0.5) # on_time, off_time -- runs in background sleep(5) # Blinks for 5 seconds led.off()
Key Properties
led.is_lit returns True/False. led.value returns 1 (on) or 0 (off). led.blink() runs in a background thread -- your script continues executing while the LED blinks.

The Button Class
Buttons are input devices. gpiozero provides polling, callbacks, and hold detection out of the box.
from gpiozero import Button from signal import pause btn = Button(4) # GPIO4, internal pull-up enabled # Polling approach: if btn.is_pressed: print("Button is down") # Callback approach (event-driven): btn.when_pressed = lambda: print("Pressed!") btn.when_released = lambda: print("Released!") # Hold detection: btn.hold_time = 2 # seconds btn.when_held = lambda: print("Long press!") pause() # Keep script alive for callbacks
Callbacks vs Polling
Use when_pressed callbacks for responsive event-driven programs. Use is_pressed polling only in sequential scripts. Callbacks run in a background thread and fire immediately when the button state changes.

PWMLED -- Brightness Control
PWMLED uses pulse width modulation to control LED brightness from 0.0 (off) to 1.0 (full).
from gpiozero import PWMLED from time import sleep led = PWMLED(17) led.value = 0.0 # Off led.value = 0.5 # Half brightness led.value = 1.0 # Full brightness # Smooth breathing effect: led.pulse(2, 2) # fade_in_time, fade_out_time sleep(10) # Manual fade: for brightness in range(0, 101): led.value = brightness / 100 sleep(0.02)
Software PWM
gpiozero uses software PWM by default. The CPU generates the signal. Sufficient for LEDs but can cause visible flicker on some pins under CPU load.
Hardware PWM
For flicker-free output, use pigpio as the pin factory: PGPIO_ADDR=localhost PWMLED(17). Hardware PWM is available on GPIO12, 13, 18, 19.

The Buzzer Class
Active buzzers produce sound when driven HIGH. gpiozero's Buzzer class works exactly like LED.
from gpiozero import Buzzer from time import sleep bz = Buzzer(22) bz.on() # Sound on sleep(0.5) bz.off() # Sound off bz.beep(0.2, 0.2, 5) # on_time, off_time, n_beeps # Combine with button: from gpiozero import Button btn = Button(4) btn.when_pressed = bz.on btn.when_released = bz.off
Active vs Passive
The Buzzer class drives the pin HIGH/LOW. This works for active buzzers (built-in oscillator). For passive buzzers that need a frequency signal, use TonalBuzzer from gpiozero, which generates specific pitches.

Connecting Devices with source/values
gpiozero's source property lets you wire devices together declaratively -- no callbacks, no loops.
from gpiozero import LED, Button from signal import pause led = LED(17) btn = Button(4) # LED mirrors button state: led.source = btn # LED on when pressed, off when released pause() # More complex: two buttons, two LEDs from gpiozero import LED, Button led1 = LED(17) led2 = LED(27) btn1 = Button(4) btn2 = Button(22) led1.source = btn1 led2.source = btn2
How Source Works
Every gpiozero device exposes a .values generator that yields its current state. Setting led.source = btn pipes the button's value stream into the LED. The connection runs in a background thread. This is the most Pythonic way to link input and output devices.
Slide 7 of 12
Signal Handling and Cleanup
gpiozero automatically cleans up GPIO pins when your script exits. Here is how it works.
1Automatic cleanup: When the script exits normally or receives SIGTERM, all pins return to input mode (high-impedance). No manual teardown needed.
2signal.pause(): Use pause() instead of while True: sleep(1). It blocks efficiently without consuming CPU and handles SIGTERM cleanly.
3device.close(): Call led.close() to release a specific pin without ending the script. The pin returns to its default state.
4KeyboardInterrupt: Wrap long-running scripts in try: pause() except KeyboardInterrupt: pass. gpiozero still cleans up on Ctrl+C.
Compared to RPi.GPIO
The old RPi.GPIO library requires explicit GPIO.cleanup() or pins stay in their last state after the script exits. gpiozero eliminates this common source of bugs. You never need to write cleanup code.

MotionSensor and DistanceSensor
gpiozero includes high-level classes for common sensors -- not just basic I/O.
from gpiozero import MotionSensor, DistanceSensor # PIR motion sensor on GPIO4: pir = MotionSensor(4) pir.when_motion = lambda: print("Motion detected!") pir.when_no_motion = lambda: print("All clear") # HC-SR04 ultrasonic distance sensor: dist = DistanceSensor(echo=24, trigger=18) print(f"Distance: {dist.distance * 100:.1f} cm") dist.when_in_range = lambda: print("Object close!") dist.threshold_distance = 0.2 # 20cm
MotionSensor
Wraps PIR sensors. Properties: motion_detected, when_motion, when_no_motion. The PIR outputs HIGH when motion is detected -- gpiozero maps this to the motion events automatically.
DistanceSensor
Wraps HC-SR04 ultrasonic sensors. Handles trigger pulse and echo timing internally. Returns distance in meters. Needs trigger and echo pins as arguments.
Slide 9 of 12
Servo and Motor Control
gpiozero provides Servo and Motor classes for actuator control.
from gpiozero import Servo, Motor # Standard servo on GPIO17: servo = Servo(17) servo.min() # Move to -90 degrees servo.mid() # Move to 0 degrees (center) servo.max() # Move to +90 degrees servo.value = 0.5 # Specific position (-1 to 1) # DC motor via H-bridge (L298N): motor = Motor(forward=17, backward=18) motor.forward(0.5) # Half speed forward motor.backward(1.0) # Full speed reverse motor.stop()
Power Note
Servos and motors draw far more current than GPIO can provide. Power them from the 5V rail or an external supply, never directly from a GPIO pin. The GPIO pin sends the control signal only.

Pin Factories: lgpio vs pigpio
gpiozero uses a "pin factory" backend to talk to hardware. The choice matters.
lgpio (default on Pi 5)
The modern replacement for RPi.GPIO. Uses the Linux GPIO character device. No daemon needed. Default on Pi 5 with Pi OS Bookworm. Runs locally only.
pigpio
Daemon-based. Runs pigpiod in the background. Supports hardware PWM, remote GPIO (control a Pi over the network), and precise timing. Best for servos and remote development.
RPi.GPIO (legacy)
The original library. Does NOT work on Pi 5. Requires manual setup/cleanup. Still found in older tutorials. gpiozero abstracts over it so you never need to use it directly.
Selecting a Factory
Set the environment variable: GPIOZERO_PIN_FACTORY=pigpio python3 script.py. Or in code: from gpiozero.pins.pigpio import PiGPIOFactory; Device.pin_factory = PiGPIOFactory().

Complete Example: Reaction Timer
A full gpiozero project combining LED, Button, timing, and output.
from gpiozero import LED, Button from time import sleep, time from random import uniform led = LED(17) btn = Button(4) print("Wait for the LED...") sleep(uniform(2, 5)) # Random delay 2-5 seconds led.on() start = time() btn.wait_for_press() elapsed = time() - start led.off() print(f"Reaction time: {elapsed*1000:.0f} ms")
Concepts Used
LED output, Button input, wait_for_press() blocking call, time measurement, random delay. This pattern -- wait for stimulus, measure response, report result -- appears in many interactive GPIO projects.

Key Takeaways: gpiozero Python GPIO
Five facts about controlling hardware with Python.
1One class per device. LED(17), Button(4), Buzzer(22), PWMLED(17). No setup, no pin mode, no cleanup. gpiozero handles everything.
2Callbacks over polling. Use when_pressed, when_released, when_held for responsive event-driven programs. Use signal.pause() to keep the script alive.
3PWMLED for brightness. Value 0.0 to 1.0. pulse() for breathing effects. Software PWM by default, hardware PWM via pigpio backend.
4source wires devices together. led.source = btn pipes button state to LED in real time. No callbacks, no loops. The most elegant gpiozero pattern.
5Pin factories abstract the hardware. lgpio on Pi 5, RPi.GPIO on older models, pigpio for remote and hardware PWM. Write code once, run on any Pi.
