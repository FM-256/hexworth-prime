  • Explain how UART, I2C, and SPI transfer data at the signal level
  • Identify TX/RX, SDA/SCL, and MOSI/MISO/CLK/CS on the GPIO header

Why Three Protocols?

Digital communication between chips requires a shared standard. UART, I2C, and SPI evolved for different tradeoffs -- speed, wire count, complexity, and device count. The Pi supports all three natively on its GPIO header, making it a universal bridge to nearly any peripheral.

UART: Universal Asynchronous Receiver/Transmitter

UART is the simplest serial protocol. It uses two wires: TX (transmit) and RX (receive). There is no clock line -- both sides must agree on the baud rate (bits per second) in advance. Data is framed with start bits, data bits, optional parity, and stop bits.

# Enable UART on the Pi $ sudo raspi-config # Interface Options -> Serial Port # "Would you like a login shell to be accessible over serial?" -> No # "Would you like the serial port hardware to be enabled?" -> Yes # Reboot after changing # Verify the serial device exists $ ls -l /dev/serial0 # Should show /dev/serial0 -> ttyAMA0 (or ttyS0 on older models) # Python UART communication with pyserial $ pip install pyserial import serial import time # Open UART at 9600 baud ser = serial.Serial('/dev/serial0', baudrate=9600, timeout=1) # Send data ser.write(b'Hello from Pi\n') # Read data (blocking up to timeout) response = ser.readline() print(f"Received: {response.decode().strip()}") ser.close()

I2C: Inter-Integrated Circuit

I2C uses two wires -- SDA (data) and SCL (clock) -- to connect up to 127 devices on a shared bus. Each device has a unique 7-bit address. The Pi acts as the controller (master) and sensors/displays act as targets (slaves). I2C is slower than SPI but uses fewer wires and supports multiple devices on two pins.

# Enable I2C on the Pi $ sudo raspi-config # Interface Options -> I2C -> Enable # Install I2C tools $ sudo apt install i2c-tools # Scan the I2C bus for connected devices $ i2cdetect -y 1 # Output shows a grid of addresses -- detected devices appear as hex values # Common: 0x3C (OLED display), 0x48 (TMP102 temp sensor), 0x68 (DS3231 RTC) # Read a register from device 0x48, register 0x00 $ i2cget -y 1 0x48 0x00 # Python I2C with smbus2 $ pip install smbus2 from smbus2 import SMBus bus = SMBus(1) # I2C bus 1 (GPIO2/GPIO3) # Read 2 bytes from device 0x48, register 0x00 data = bus.read_i2c_block_data(0x48, 0x00, 2) print(f"Raw bytes: {data}") # Write a byte to device 0x48, register 0x01 bus.write_byte_data(0x48, 0x01, 0x60) bus.close()
Clock Stretching:

Some I2C devices hold SCL low when they need more time to process data. This is called clock stretching. The Pi 4 and Pi 5 handle it correctly, but older Pi models (Pi 1/Zero) had hardware bugs that caused I2C failures with slow devices. If you encounter random read errors on older hardware, reduce the bus speed by adding dtparam=i2c_baudrate=50000 to /boot/config.txt.

SPI: Serial Peripheral Interface

SPI is the fastest of the three protocols. It uses four wires: MOSI (Master Out, Slave In), MISO (Master In, Slave Out), SCLK (clock), and CS/CE (chip select). SPI is full-duplex -- data flows in both directions simultaneously. Each device needs its own CS line, so the wire count grows with more devices.

# Enable SPI on the Pi $ sudo raspi-config # Interface Options -> SPI -> Enable # Verify SPI devices are available $ ls /dev/spidev* # /dev/spidev0.0 (CE0) and /dev/spidev0.1 (CE1) # Python SPI with spidev import spidev spi = spidev.SpiDev() spi.open(0, 0) # Bus 0, Device 0 (CE0) spi.max_speed_hz = 1000000 # 1 MHz clock spi.mode = 0 # SPI mode 0 (CPOL=0, CPHA=0) # Transfer data (full duplex -- send and receive simultaneously) tx_data = [0x01, 0x80, 0x00] # MCP3008 read channel 0 rx_data = spi.xfer2(tx_data) print(f"Received: {rx_data}") # Extract 10-bit ADC value from MCP3008 response value = ((rx_data[1] & 0x03) << 8) | rx_data[2] voltage = value * 3.3 / 1023 print(f"ADC value: {value}, Voltage: {voltage:.3f}V") spi.close()

Choosing the Right Protocol

Each protocol excels in different scenarios. The decision depends on speed requirements, device count, wire budget, and the specific peripheral's supported interfaces.

FeatureUARTI2CSPI
Wires (excl. power/ground)2 (TX, RX)2 (SDA, SCL)4+ (MOSI, MISO, CLK, CS per device)
SpeedUp to 115,200 bps typical100 kHz / 400 kHz / 3.4 MHzUp to ~125 MHz on Pi
DuplexFull duplexHalf duplexFull duplex
AddressingNone (point-to-point)7-bit address (up to 127 devices)CS pin per device
ClockNo clock (async, baud rate)Controller drives SCLController drives SCLK
Best ForGPS modules, serial terminals, Bluetooth modulesSensors, OLEDs, RTCs, low-speed multi-deviceADCs, TFT displays, SD cards, high-speed data
Use UART When... You need simple point-to-point communication with a GPS, Bluetooth module, or another microcontroller. No clock synchronization needed -- just match baud rates.
Use I2C When... You have multiple sensors/displays sharing a bus and speed is not critical. Only two GPIO pins consumed regardless of device count. Most breakout boards default to I2C.
Use SPI When... You need maximum speed (ADC sampling, display updates, SD card access). Willing to spend one CS pin per device. Full-duplex throughput matters.
Check the Datasheet Many chips support multiple protocols. An OLED might offer both I2C and SPI -- choose I2C for simplicity (fewer wires) or SPI for faster refresh rates.

Enabling Interfaces on the Pi

Serial interfaces are disabled by default on Raspberry Pi OS. You must enable them before use, either through raspi-config or by editing /boot/firmware/config.txt directly.

# Method 1: raspi-config (interactive) $ sudo raspi-config # Navigate: Interface Options -> I2C/SPI/Serial -> Enable # Reboot after changes # Method 2: Edit config.txt directly $ sudo nano /boot/firmware/config.txt # Add or uncomment these lines: dtparam=i2c_arm=on # Enable I2C bus 1 dtparam=spi=on # Enable SPI bus 0 enable_uart=1 # Enable UART # Additional I2C buses via device tree overlay dtoverlay=i2c3,pins_4_5 # I2C bus 3 on GPIO4 (SDA) + GPIO5 (SCL) # Additional SPI buses dtoverlay=spi1-1cs # SPI bus 1 with 1 chip select # Verify after reboot $ ls /dev/i2c-* # Should show /dev/i2c-1 $ ls /dev/spidev* # Should show /dev/spidev0.0 $ ls /dev/serial0 # Should show serial link

Key Takeaways

  • UART is asynchronous (no clock), point-to-point, and simplest to wire -- just cross TX/RX and share GND
  • I2C uses two wires (SDA/SCL) with addressing for up to 127 devices on a shared bus
  • SPI is the fastest protocol -- full-duplex at MHz speeds, but requires one CS line per device
  • All three protocols operate at 3.3V on the Pi -- level shift when connecting to 5V devices
  • Enable interfaces via raspi-config or /boot/firmware/config.txt, then reboot
  • When in doubt, check the peripheral's datasheet -- it dictates which protocols are available
