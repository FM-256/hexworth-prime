Track Context:

PiVerse Track 3 begins here -- with the hardware interface that makes the Pi more than just a small computer. The 40-pin GPIO header is the gateway to physical computing. Understanding its architecture, constraints, and protection mechanisms is the foundation for every project that follows.

The 40-Pin GPIO Header

Every Raspberry Pi model since the B+ (2014) exposes a standard 40-pin header. This 2x20 block of pins provides power, ground, digital I/O, and protocol buses. Pin 1 is the pin closest to the corner of the board, marked with a small square solder pad on the underside.

The header includes 26 GPIO pins, two 5V power pins, two 3.3V power pins, eight ground pins, and two EEPROM ID pins (reserved for HAT identification). Pins 27-28 are used internally by HATs for auto-configuration and should not be used in general projects.

BCM vs BOARD Numbering

There are two numbering schemes for GPIO pins. Confusing them is the single most common wiring error beginners make, and it can result in short circuits or damaged components.

SchemeWhat It NumbersExampleUsed By
BOARDPhysical pin position on the header (1-40)Physical pin 7Beginners, breadboard wiring
BCMBroadcom SoC GPIO numberGPIO4 (same as BOARD pin 7)gpiozero, libgpiod, pinout
# View the full pinout on your Pi $ pinout # In Python with RPi.GPIO, you choose your mode explicitly import RPi.GPIO as GPIO GPIO.setmode(GPIO.BCM) # Use Broadcom SoC numbering GPIO.setmode(GPIO.BOARD) # Use physical pin position # gpiozero uses BCM by default -- always from gpiozero import LED led = LED(17) # BCM 17 = physical pin 11
Convention:

All PiVerse modules use BCM numbering. The pinout command (pre-installed on Raspberry Pi OS) displays both schemes side by side. Run it before wiring anything.

3.3V Logic and Why It Matters

The Pi's GPIO pins operate at 3.3V logic levels. A HIGH signal is 3.3V. A LOW signal is 0V. The pins have no overvoltage protection -- applying 5V to any GPIO pin will damage the SoC permanently. There is no fuse, no protection diode, no second chance.

Safe: 3.3V Devices Most modern sensors, OLED displays, and breakout boards operate at 3.3V and connect directly to GPIO pins without any conversion.
Dangerous: 5V Devices Arduino Uno outputs, some relay modules, and legacy sensors output 5V logic. These MUST be level-shifted down to 3.3V before connecting to a Pi GPIO input.
Level Shifter (Bidirectional) A BSS138-based level shifter converts between 3.3V and 5V in both directions. Required for I2C buses shared with 5V devices.
Voltage Divider (One-Way) Two resistors (e.g., 1k and 2k) can step 5V down to 3.3V for input-only connections. Cheaper but only works in one direction.
# Voltage divider calculation: Vout = Vin * (R2 / (R1 + R2)) # To step 5V down to ~3.3V: # R1 = 1kOhm, R2 = 2kOhm # Vout = 5 * (2000 / (1000 + 2000)) = 5 * 0.667 = 3.33V # NEVER do this: # 5V sensor output ---> GPIO pin directly (DESTROYS THE PI) # Always do this: # 5V sensor output ---> level shifter ---> GPIO pin (safe)

Current Limits and Safe Draw

Each GPIO pin can source or sink a limited amount of current. Exceeding these limits damages the SoC. Unlike an Arduino, the Pi has no per-pin current limiting -- it trusts you to do the math.

ParameterLimitNotes
Single GPIO pin (max)16 mAAbsolute maximum -- do not design for this
Single GPIO pin (safe)8 mARecommended design target
All GPIO pins combined50 mATotal across all active outputs
3.3V rail (pins 1, 17)~800 mAShared with the SoC -- available current depends on total system load
5V rail (pins 2, 4)USB supply minus Pi drawPi 4 draws ~600 mA idle, ~1.2A under load. 3A supply gives ~1.8A headroom
# Calculating the resistor for an LED: # Vforward (red LED) = ~2.0V # Target current = 5 mA (safe, visible brightness) # R = (Vsource - Vforward) / I # R = (3.3 - 2.0) / 0.005 = 260 Ohm # Use 270 Ohm (nearest standard value) or 330 Ohm for extra margin
Critical Rule:

Never connect an LED directly to a GPIO pin without a resistor. The LED will draw excessive current and damage the pin. A 330-ohm resistor is a safe default for most standard LEDs.

Pull-Up and Pull-Down Resistors

A GPIO pin configured as an input that is not connected to anything is "floating" -- its value is undefined and will randomly read HIGH or LOW due to electrical noise. Pull resistors fix the pin to a known default state.

Pull-Up Resistor Connects the pin to 3.3V through a resistor (typically 10k). Pin reads HIGH by default. A button press grounds it to LOW. Most common pattern for buttons.
Pull-Down Resistor Connects the pin to GND through a resistor (typically 10k). Pin reads LOW by default. A button press pulls it HIGH to 3.3V.
# The Pi has internal pull-up/pull-down resistors (50k-65k) # You can enable them in software instead of using external resistors # gpiozero enables internal pull-up by default for Button: from gpiozero import Button btn = Button(17) # Internal pull-up enabled, wire button to GND # RPi.GPIO explicit pull control: import RPi.GPIO as GPIO GPIO.setup(17, GPIO.IN, pull_up_down=GPIO.PUD_UP) # Internal pull-up GPIO.setup(17, GPIO.IN, pull_up_down=GPIO.PUD_DOWN) # Internal pull-down

For prototyping, the Pi's internal pull resistors are sufficient. For production circuits or long wire runs (over 30cm), use external 10k resistors -- they provide a stronger pull and better noise immunity.

Protection Strategies

GPIO pins are directly connected to the Broadcom SoC with minimal protection. A single mistake can permanently disable a pin or destroy the entire processor. These strategies prevent that.

StrategyProtects AgainstImplementation
Series resistor (220-330 ohm)Accidental short to ground or 3.3VPlace in line between GPIO pin and external circuit
Level shifterOvervoltage from 5V devicesBSS138-based module between Pi and 5V device
OptocouplerElectrical isolation from high-voltage circuitsLED+phototransistor pair electrically separates circuits
Transistor driver (NPN/MOSFET)Overcurrent from motors, relays, solenoidsGPIO drives transistor gate; transistor switches high-current load
Flyback diodeInductive kickback from motors/relaysDiode across inductive load, cathode to positive supply
Design Rule:

Never drive a motor, relay, or solenoid directly from a GPIO pin. Always use a transistor or MOSFET as a switch, with the GPIO pin controlling the gate. The load draws power from the 5V rail or an external supply, not from the GPIO pin.

Inspecting GPIO State from the Command Line

Before writing code, verify your wiring by reading pin states directly from the shell. The pinout and gpioinfo commands show the current configuration of every pin.

# Show the full pinout diagram in the terminal $ pinout # List all GPIO lines and their current state (libgpiod) $ gpioinfo # Read a specific pin value (BCM 17) $ gpioget gpiochip0 17 # Set a pin high for testing (BCM 17) $ gpioset gpiochip0 17=1 # Monitor a pin for changes (press Ctrl+C to stop) $ gpiomon gpiochip0 17 # Legacy sysfs interface (deprecated but still seen in older tutorials) $ echo 17 > /sys/class/gpio/export $ cat /sys/class/gpio/gpio17/value

The libgpiod tools (gpioget, gpioset, gpiomon, gpioinfo) are the modern replacement for the deprecated sysfs interface. Install them with sudo apt install gpiod if not already present.

Key Takeaways

  • The 40-pin header provides 26 GPIO pins, power rails, ground, and protocol buses (I2C, SPI, UART)
  • BCM numbers the Broadcom SoC channels; BOARD numbers the physical pin positions -- PiVerse uses BCM
  • GPIO operates at 3.3V logic -- applying 5V destroys the pin with no recovery
  • Design for 8 mA per pin, 50 mA total across all pins; always use a resistor with LEDs
  • Floating inputs produce random values -- use pull-up or pull-down resistors to set a known default
  • Never drive motors or relays directly from GPIO -- use transistors, MOSFETs, and flyback diodes
