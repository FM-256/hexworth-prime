Learning Objectives

  • Enable the Simple Electronics GPIO extension in Scratch 3 on Raspberry Pi

Why Scratch for GPIO?

Scratch removes the syntax barrier entirely. Students see cause and effect immediately -- drag a block, click it, and the LED turns on. This makes Scratch the ideal starting point before transitioning to Python in PV-E-03. The concepts (pin numbers, HIGH/LOW, event loops) are identical regardless of language.

Enabling GPIO in Scratch 3

Scratch 3 on Raspberry Pi OS includes a built-in GPIO extension called "Simple Electronics." It must be enabled from the Extensions menu before GPIO blocks appear in the palette.

Step 1: Open Scratch 3 Launch from the desktop menu: Programming > Scratch 3. The GPIO extension only works in the desktop version on the Pi itself, not in the web browser version at scratch.mit.edu.
Step 2: Add Extension Click the blue "Add Extension" button in the bottom-left corner. Select "Simple Electronics" from the list. New GPIO blocks appear in the block palette.
Step 3: Verify Access If blocks appear grayed out, Scratch may not have GPIO permissions. Run Scratch with: sudo scratch3 from the terminal, or add your user to the gpio group.
Supported Pins The Simple Electronics extension uses BCM numbering. Available GPIO pins: 2-27. Pins 0-1 are reserved for EEPROM and are not accessible through Scratch.
# Add your user to the gpio group (one-time setup) $ sudo usermod -aG gpio $USER # Log out and back in for group change to take effect # Alternatively, launch Scratch with elevated permissions $ sudo scratch3

Wiring Your First LED

Before touching Scratch, build the physical circuit. An LED requires a current-limiting resistor (330 ohm) between the GPIO pin and the LED anode. The LED cathode connects to a ground pin.

Resistor (330 ohm)GPIO17 (BCM 17, physical pin 11)LED anode (long leg)
LEDAnode through resistor to GPIO17Cathode (short leg) to GND
Ground wireLED cathode railAny GND pin (e.g., physical pin 6)
LED Orientation:

The LED has two legs of different lengths. The long leg is the anode (positive, connects toward GPIO). The short leg is the cathode (negative, connects to ground). Inserting the LED backwards will not damage it -- it simply will not light up.

LED Control with Scratch Blocks

The Simple Electronics extension provides blocks to set output pins high or low, and to read input pins. Here is the block sequence to blink an LED:

when green flag clicked
forever
turn LED (17 v) [on v]
wait (1) seconds
turn LED (17 v) [off v]
wait (1) seconds
end

The turn LED block sets the specified BCM pin to HIGH (on) or LOW (off). The forever loop keeps the pattern repeating. Click the green flag to start; click the red stop to halt.

What Happens Electrically:

"Turn LED on" sets GPIO17 to 3.3V (HIGH). Current flows from the pin, through the resistor, through the LED, to ground. "Turn LED off" sets GPIO17 to 0V (LOW). No voltage difference means no current flows.

Reading Button Input

A button connects a GPIO input pin to ground when pressed. The Pi's internal pull-up resistor holds the pin HIGH when the button is not pressed, and the button pulls it LOW when pressed.

ComponentConnection FromConnection To
Push button (one leg)GPIO4 (BCM 4, physical pin 7)Button terminal
Push button (other leg)Button terminalGND (physical pin 9)
when green flag clicked
forever
if <button (4 v) pressed?> then
say [Button pressed!] for (1) seconds
end
end

The button pressed? block returns true when the pin reads LOW (button is connecting it to ground). Scratch polls this state inside the forever loop. The polling happens approximately 30 times per second.

Event-Driven GPIO

Instead of polling inside a forever loop, Scratch can respond to GPIO changes as events. This is cleaner and more responsive for button presses.

when green flag clicked
forever
wait until <button (4 v) pressed?>
turn LED (17 v) [on v]
wait until not <button (4 v) pressed?>
turn LED (17 v) [off v]
end

This pattern uses wait until to pause execution until the button state changes. The LED stays on exactly as long as the button is held. Releasing the button turns it off immediately. This is the Scratch equivalent of edge-triggered event handling.

Project: Toggle LED with Button

A toggle requires state tracking: each button press flips the LED between on and off. This introduces variables in Scratch for GPIO state management.

when green flag clicked
set [ledState v] to [0]
turn LED (17 v) [off v]
forever
wait until <button (4 v) pressed?>
if <(ledState) = [0]> then
turn LED (17 v) [on v]
set [ledState v] to [1]
else
turn LED (17 v) [off v]
set [ledState v] to [0]
end
wait until not <button (4 v) pressed?>
wait (0.1) seconds
end

The 0.1-second wait after the button release is a software debounce. Physical buttons create brief electrical noise (bouncing) when pressed, which can register as multiple presses. The short delay filters this out.

Traffic Light Pattern

Multiple LEDs on different pins create more complex patterns. Wire three LEDs (red on GPIO17, yellow on GPIO27, green on GPIO22) each with its own 330-ohm resistor.

when green flag clicked
forever
turn LED (22 v) [on v] -- green
wait (5) seconds
turn LED (22 v) [off v]
turn LED (27 v) [on v] -- yellow
wait (2) seconds
turn LED (27 v) [off v]
turn LED (17 v) [on v] -- red
wait (5) seconds
turn LED (17 v) [off v]
end

This sequential pattern cycles through green, yellow, red just like a real traffic light. Each LED gets its own GPIO pin. The timing is controlled by the wait blocks. Students can adjust the timing or add a pedestrian button using the input techniques from the previous section.

Scratch GPIO Limitations

Scratch is excellent for introductory GPIO work, but it has hard boundaries that Python overcomes.

LimitationImpactPython Alternative
No PWM supportCannot dim LEDs or control servo anglesgpiozero PWMLED, Servo classes
No I2C/SPI accessCannot talk to sensor breakouts or ADCssmbus2, spidev libraries
Polling only (no true interrupts)Button events can be missed during waitsgpiozero callback-based events
~30 Hz update rateToo slow for time-sensitive protocolsPython runs at microsecond precision
Desktop-only (requires monitor)Cannot run headless on remote PiPython scripts run over SSH
Transition Path:

Every Scratch GPIO concept maps directly to Python. "Turn LED on" becomes led.on(). "Button pressed?" becomes button.is_pressed. The next module (PV-E-03) makes this transition explicit.

Key Takeaways

  • Scratch 3 on Raspberry Pi OS includes the Simple Electronics extension for GPIO control
  • LEDs require a 330-ohm resistor between the GPIO pin and the anode -- never connect directly
  • The "turn LED on/off" block sets the pin HIGH (3.3V) or LOW (0V)
  • The "button pressed?" block reads an input pin -- wire buttons between GPIO and GND
  • "Wait until" creates event-driven responses; variables enable toggle and state tracking
  • Scratch GPIO is limited to digital on/off with no PWM, I2C, or SPI -- Python removes these limits
