The Missing Piece:

The Raspberry Pi's GPIO pins are purely digital -- they read HIGH (3.3V) or LOW (0V) with nothing in between. To read analog signals like temperature from a thermistor, light from an LDR, or position from a potentiometer, you need an external Analog-to-Digital Converter (ADC).

Analog vs Digital Signals

An analog signal is continuous -- it can take any value within a range. A thermistor's resistance changes smoothly with temperature. A microphone's voltage oscillates in a continuous wave. Digital signals are discrete -- they exist only as defined levels (0 or 1, LOW or HIGH). Converting between the two domains is the core challenge.

Analog Sources Potentiometers, thermistors, LDRs (light sensors), microphones, flex sensors, soil moisture sensors, analog joysticks. Output varies continuously with the measured quantity.
Digital Sources Buttons, switches, rotary encoders, digital temperature sensors (DS18B20). Output is discrete states -- ON/OFF or a serial data stream with a built-in ADC.

Sampling Theory: The Nyquist-Shannon Theorem

When you digitize an analog signal, you take periodic snapshots (samples) of its value. The Nyquist-Shannon theorem states that you must sample at least twice the highest frequency in the signal to accurately reconstruct it. Sampling below this rate causes aliasing -- the digital representation misrepresents the original signal.

Practical Implication:

For most Pi GPIO projects (reading temperature, light, potentiometer position), the signal changes slowly -- a few samples per second is plenty. The MCP3008 can sample at 200 kHz, which is far more than needed for typical sensor work. Audio sampling requires dedicated hardware (I2S DAC/ADC).

ADC Resolution: Bits and Voltage Steps

The resolution of an ADC determines how finely it divides the input voltage range. An n-bit ADC produces 2^n distinct levels. The smallest detectable voltage change (LSB -- Least Significant Bit) equals the reference voltage divided by the number of levels.

# ADC resolution calculations # 10-bit ADC with 3.3V reference levels = 2 ** 10 # 1024 vref = 3.3 lsb = vref / levels # 0.003223V = 3.22 mV per step # Convert raw ADC value to voltage raw_value = 512 # Example reading (mid-range) voltage = raw_value * vref / (levels - 1) print(f"ADC value {raw_value} = {voltage:.3f}V") # 1.650V # 12-bit ADC with 3.3V reference levels_12 = 2 ** 12 # 4096 lsb_12 = vref / levels_12 # 0.000806V = 0.81 mV per step # 4x finer resolution than 10-bit

The MCP3008: 10-Bit ADC over SPI

The MCP3008 is the go-to ADC for Raspberry Pi projects. It provides 8 analog input channels with 10-bit resolution and communicates over SPI at up to 3.6 MHz. At 3.3V reference, each step represents ~3.2 mV -- sufficient for most sensor applications.

# Reading the MCP3008 with spidev (low-level) import spidev import time spi = spidev.SpiDev() spi.open(0, 0) # Bus 0, CE0 spi.max_speed_hz = 1000000 # 1 MHz def read_channel(channel): """Read a single MCP3008 channel (0-7). Returns 0-1023.""" # MCP3008 protocol: start bit, single-ended, channel select cmd = [0x01, (0x08 | channel) << 4, 0x00] result = spi.xfer2(cmd) value = ((result[1] & 0x03) << 8) | result[2] return value try: while True: raw = read_channel(0) # Read CH0 voltage = raw * 3.3 / 1023 percent = raw / 1023 * 100 print(f"Raw: {raw:4d} | Voltage: {voltage:.3f}V | {percent:.1f}%") time.sleep(0.5) except KeyboardInterrupt: spi.close()
# Using gpiozero's built-in MCP3008 support (recommended) from gpiozero import MCP3008 import time # gpiozero wraps the SPI protocol automatically pot = MCP3008(channel=0) # CH0, uses CE0 by default try: while True: # .value returns 0.0 to 1.0 (normalized) print(f"Value: {pot.value:.3f} | Voltage: {pot.voltage:.3f}V") time.sleep(0.5) except KeyboardInterrupt: pass

Signal Conditioning and Voltage Dividers

Not all analog signals fall within the ADC's input range (0 to 3.3V for MCP3008 with 3.3V reference). Signals outside this range must be conditioned -- scaled down with a voltage divider or biased to fit the window. Exceeding the reference voltage saturates the ADC at its maximum value; exceeding the absolute maximum rating damages the chip.

# Common voltage divider calculations for ADC input # Scenario: 5V sensor output -> MCP3008 (3.3V VREF) # Need: Vout_max = 3.3V when Vin = 5V # Ratio needed: 3.3/5 = 0.66 # R2/(R1+R2) = 0.66 # R1 = 1.8k, R2 = 3.3k -> Vout = 5 * 3300/5100 = 3.24V (safe) # Scenario: 12V battery monitor # Need: Map 0-12V to 0-3.3V # Ratio: 3.3/12 = 0.275 # R1 = 10k, R2 = 3.9k -> Vout = 12 * 3900/13900 = 3.37V # Slightly over! Use R1=10k, R2=3.3k -> Vout = 12 * 3300/13300 = 2.98V (safe, with margin) def voltage_divider(vin, r1, r2): """Calculate output voltage of a voltage divider.""" return vin * r2 / (r1 + r2) # Reverse: given desired Vout and one resistor, find the other def find_r1(vin, vout, r2): """Find R1 given Vin, desired Vout, and R2.""" return r2 * (vin - vout) / vout print(f"R1 needed: {find_r1(12, 3.0, 3300):.0f} ohms") # 9900 -> use 10k
Safety Margin:

Always design voltage dividers to produce a maximum output slightly below the ADC reference voltage. Component tolerances (typically +/- 5%) mean actual resistance varies. A 3.0V maximum with a 3.3V reference gives 10% headroom for resistor tolerance, temperature drift, and voltage spikes.

Multi-Channel Sensor Dashboard

The MCP3008 has 8 channels, allowing you to monitor multiple analog sensors simultaneously. A common project reads a potentiometer, a light sensor (LDR), and a thermistor on three separate channels.

#!/usr/bin/env python3 # multi_adc.py -- Read 3 analog sensors on MCP3008 channels 0-2 from gpiozero import MCP3008 import time # Channel 0: Potentiometer (0-3.3V wiper) pot = MCP3008(channel=0) # Channel 1: LDR in voltage divider (brighter = lower resistance = higher voltage) ldr = MCP3008(channel=1) # Channel 2: Thermistor in voltage divider therm = MCP3008(channel=2) import math def thermistor_temp(adc_value, r_fixed=10000, beta=3950, t0=298.15, r0=10000): """Convert thermistor ADC reading to temperature in Celsius. Uses Steinhart-Hart simplified (Beta equation).""" if adc_value <= 0 or adc_value >= 1: return float('nan') # Calculate thermistor resistance from voltage divider r_therm = r_fixed * adc_value / (1 - adc_value) # Beta equation: 1/T = 1/T0 + (1/B) * ln(R/R0) temp_k = 1.0 / (1.0/t0 + (1.0/beta) * math.log(r_therm/r0)) return temp_k - 273.15 print("CH0: Potentiometer | CH1: Light (LDR) | CH2: Temperature") print("-" * 60) try: while True: pot_pct = pot.value * 100 light_pct = ldr.value * 100 temp_c = thermistor_temp(therm.value) print(f"Pot: {pot_pct:5.1f}% | Light: {light_pct:5.1f}% | Temp: {temp_c:5.1f} C") time.sleep(1) except KeyboardInterrupt: print("\nStopped.")

Key Takeaways

  • The Raspberry Pi has no built-in ADC -- external chips like the MCP3008 bridge the analog-digital gap
  • The Nyquist theorem requires sampling at 2x the signal frequency; most sensor signals are slow enough for simple polling
  • A 10-bit ADC divides the reference voltage into 1024 steps (~3.2 mV per step at 3.3V)
  • The MCP3008 connects via SPI and provides 8 analog channels with 10-bit resolution
  • Voltage dividers scale out-of-range signals down to fit the ADC input -- always design with safety margin
  • gpiozero provides a high-level MCP3008 class that returns normalized values (0.0-1.0) automatically
