Lab 1: RetroPie Setup and Configuration

< Back to PiVerse

Lab Objectives

  • Install RetroPie on an existing Raspberry Pi OS installation
  • Configure ROM directories and transfer a homebrew ROM
  • Set the CPU governor to performance mode for emulation
  • Configure a USB controller in EmulationStation
  • Measure and optimize input latency using RetroArch run-ahead

Task 1: Install RetroPie

Clone the RetroPie setup repository and run the installer. This will download and compile emulator cores, RetroArch, and EmulationStation.

# Clone the RetroPie setup script $ git clone --depth=1 https://github.com/RetroPie/RetroPie-Setup.git $ cd RetroPie-Setup # Run the setup script (this takes 30-60 minutes on a Pi 5) $ sudo ./retropie_setup.sh # In the menu, select: Basic Install # This installs the core packages: RetroArch, EmulationStation, and essential cores
Verification:

After installation completes, verify the directory structure exists: ls ~/RetroPie/roms/ should show system directories (nes, snes, gba, etc.).

Task 2: Transfer a Homebrew ROM

Download a free, legal homebrew NES ROM and place it in the correct directory. We will use "Alter Ego" -- a free, open-source NES game.

# Create the NES ROM directory if it does not exist $ mkdir -p ~/RetroPie/roms/nes # Download a free homebrew game (Alter Ego by Shiru) $ wget -O ~/RetroPie/roms/nes/alter_ego.nes \ https://shiru.untergrund.net/files/nes/alter_ego.nes # Verify the file $ file ~/RetroPie/roms/nes/alter_ego.nes # Should report: NES ROM image

Task 3: Set Performance Governor

The default CPU governor throttles frequency to save power. For emulation, lock the CPU at maximum frequency.

# Check current governor $ cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor # Set performance mode (all cores) $ echo performance | sudo tee /sys/devices/system/cpu/cpu*/cpufreq/scaling_governor # Verify the change $ cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor # Should output: performance # Check current CPU frequency (should be at max) $ cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_cur_freq # Monitor temperature (keep below 80C) $ vcgencmd measure_temp

Task 4: Configure Controller Input

Connect a USB controller and configure it in EmulationStation. The controller mapping is stored in a configuration file you can inspect.

# Start EmulationStation $ emulationstation # Follow the on-screen prompts to map each button: # D-Pad directions, A, B, X, Y, Start, Select, L, R # Hold any button for 3 seconds to skip a mapping # After mapping, inspect the generated config $ cat ~/.emulationstation/es_input.cfg
USB vs. Bluetooth:

For this lab, use a wired USB connection. Bluetooth adds 10-30ms of latency that will confuse the measurements in the next task. You can configure Bluetooth later once you have a latency baseline.

Task 5: Enable Run-Ahead Latency Reduction

Configure RetroArch's run-ahead feature to reduce emulator-added input latency to zero.

# Edit the RetroArch configuration $ nano /opt/retropie/configs/all/retroarch.cfg # Add or modify these lines: run_ahead_enabled = "true" run_ahead_frames = "1" run_ahead_secondary_instance = "true" # Save and exit (Ctrl+O, Enter, Ctrl+X) # Launch a game and verify run-ahead is active # In RetroArch: Quick Menu > Latency # Run-Ahead to Reduce Latency should show: ON

Test the difference: play a few rounds of a fast-paced game with run-ahead on, then off. The difference is subtle but measurable -- especially in rhythm games and fighting games where frame-perfect input matters.
