Audio Capture on the Pi

The Raspberry Pi has no built-in microphone. USB microphones (or USB sound cards with analog mic input) are the standard approach. The Pi's ALSA (Advanced Linux Sound Architecture) subsystem handles audio device management.

# List available audio input devices $ arecord -l # card 1: Device [USB Mic], device 0: USB Audio [USB Audio] # Record 10 seconds of audio (16-bit, 44.1kHz, mono) $ arecord -D plughw:1,0 -f S16_LE -r 44100 -c 1 -d 10 recording.wav # Test playback through HDMI or headphone jack $ aplay recording.wav # Python audio capture with sounddevice $ pip3 install sounddevice soundfile import sounddevice as sd import soundfile as sf # Record 10 seconds duration = 10 sample_rate = 44100 recording = sd.rec(int(duration * sample_rate), samplerate=sample_rate, channels=1) sd.wait() sf.write("capture.wav", recording, sample_rate)

Sound Classification

Sound classification converts audio into a spectrogram (a visual representation of frequencies over time) and feeds it to a classifier. The spectrogram turns a 1D audio signal into a 2D image, allowing image classification models to identify sounds.

import numpy as np import librosa import librosa.display # Load audio file audio, sr = librosa.load("capture.wav", sr=22050) # Compute mel spectrogram mel_spec = librosa.feature.melspectrogram( y=audio, sr=sr, n_mels=128, fmax=8000 ) # Convert to log scale (decibels) mel_db = librosa.power_to_db(mel_spec, ref=np.max) # mel_db is now a 2D array (128 x time_steps) # This can be fed to a CNN for classification # Simple threshold-based detection (no ML) def detect_loud_event(audio, sr, threshold_db=-20): """Detect audio events above a threshold.""" rms = librosa.feature.rms(y=audio)[0] rms_db = librosa.amplitude_to_db(rms) events = np.where(rms_db > threshold_db)[0] return events # Frame indices of loud events
Mel Spectrogram Converts frequency to mel scale (perceptual). Better for animal/speech sounds. Standard input for audio ML models.
MFCC Mel-Frequency Cepstral Coefficients. Compact feature vector. Classic for speech recognition and bird call ID.
YAMNet Pre-trained Google model. Classifies 521 audio event classes. Runs on Pi with TFLite. Ideal starting point.
BirdNET Specialized bird identification model from Cornell Lab. Identifies 6,000+ species by call. TFLite compatible.

Wildlife Monitoring Station

A wildlife monitoring station combines audio recording, camera traps, and environmental sensors into an autonomous data collection system. The Pi serves as the central controller, scheduling captures and managing storage.

# Motion-triggered camera trap with audio recording import RPi.GPIO as GPIO import subprocess, time, datetime PIR_PIN = 17 GPIO.setmode(GPIO.BCM) GPIO.setup(PIR_PIN, GPIO.IN) def on_motion(channel): ts = datetime.datetime.now().strftime("%Y%m%d_%H%M%S") # Capture image subprocess.Popen([ "libcamera-still", "-o", f"/data/images/{ts}.jpg", "-n", "--immediate" ]) # Record 30 seconds of audio subprocess.Popen([ "arecord", "-D", "plughw:1,0", "-f", "S16_LE", "-r", "44100", "-c", "1", "-d", "30", f"/data/audio/{ts}.wav" ]) GPIO.add_event_detect(PIR_PIN, GPIO.RISING, callback=on_motion, bouncetime=5000) try: while True: time.sleep(1) except KeyboardInterrupt: GPIO.cleanup()

Data Pipelines

Raw sensor data is useless without a pipeline to collect, store, process, and visualize it. A typical environmental sensing pipeline on the Pi uses SQLite for local storage and Grafana for visualization.

import sqlite3 import datetime # Create database and table conn = sqlite3.connect("/data/sensors.db") conn.execute(""" CREATE TABLE IF NOT EXISTS readings ( timestamp TEXT, sensor TEXT, value REAL, unit TEXT ) """) # Log a reading def log_reading(sensor, value, unit): conn.execute( "INSERT INTO readings VALUES (?, ?, ?, ?)", (datetime.datetime.utcnow().isoformat(), sensor, value, unit) ) conn.commit() # Example: log temperature every minute log_reading("dht22_temp", 23.4, "celsius") log_reading("dht22_humidity", 65.2, "percent") log_reading("audio_rms", -32.5, "dBFS")
Outdoor Deployment Checklist:

Weatherproof enclosure (IP65+ rated). Power: solar panel + LiPo battery with charge controller. Storage: USB SSD (SD cards fail in temperature extremes). Connectivity: Wi-Fi for periodic uploads, or store locally and retrieve physically. Boot the Pi directly into your monitoring script via systemd service.

Power Management for Field Deployment

Strategy Implementation Power Savings
Disable unused interfaces Turn off HDMI, Bluetooth, Wi-Fi when not uploading ~1W combined
Schedule-based operation Use cron to wake sensors only during active hours 50-80% during off-hours
Event-driven capture PIR sensor triggers recording instead of continuous capture 90%+ during quiet periods
Pi Zero 2 W for remote Use a Zero 2 W (1W idle) instead of Pi 5 (3W idle) 60% at idle

Key Takeaways

  • USB microphones provide audio input -- ALSA handles device management, sounddevice/librosa handle Python integration
  • Mel spectrograms convert audio to 2D images, enabling CNN-based classification of environmental sounds
  • BirdNET and YAMNet are pre-trained TFLite models that run on the Pi for species and event classification
  • Wildlife stations combine PIR motion triggers, camera, and audio for event-driven capture
  • SQLite provides reliable local storage for sensor data; Grafana visualizes trends over time
  • Outdoor deployment requires weatherproofing, solar power, SSD storage, and aggressive power management
