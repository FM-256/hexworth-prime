Seeds and Determinism

Procedural generation starts with a pseudo-random number generator (PRNG). Given the same seed, a PRNG produces the same sequence of numbers every time. This means an entire world can be recreated from a single integer -- Minecraft does exactly this.

import random # Same seed = same "random" sequence, every run random.seed(42) print(random.randint(0, 100)) # Always 81 print(random.randint(0, 100)) # Always 14 print(random.randint(0, 100)) # Always 3 # Share the seed to let others play the same level WORLD_SEED = 12345 random.seed(WORLD_SEED) level = generate_level() # Identical level for everyone using seed 12345
Design Principle:

Seeds let you combine the replayability of hand-designed levels with the infinite variety of randomness. Players who find a good seed can share it. Developers can test against a fixed seed for debugging.

Weighted Random Level Generation

The simplest procedural generation uses weighted random choices. Instead of pure randomness (which produces noise), you assign probabilities to different level elements. A platformer might have 60% flat ground, 20% gaps, 15% platforms, and 5% collectibles.

import random def generate_column(): """Generate one column of a platformer level.""" roll = random.random() # 0.0 to 1.0 if roll < 0.60: return "ground" elif roll < 0.80: return "gap" elif roll < 0.95: return "platform" else: return "collectible" # Better: Python's random.choices with weights elements = ["ground", "gap", "platform", "collectible"] weights = [60, 20, 15, 5] level = random.choices(elements, weights=weights, k=100) # Constraint: gaps cannot be wider than 3 tiles def validate_level(level): gap_count = 0 for i, elem in enumerate(level): if elem == "gap": gap_count += 1 if gap_count > 3: level[i] = "ground" # Force ground after 3 gaps else: gap_count = 0 return level

Perlin Noise

Perlin noise generates smooth, continuous random values -- unlike pure random, which jumps erratically. This makes it ideal for natural-looking terrain. Where random.random() gives you static, Perlin noise gives you rolling hills.

# Using the 'noise' library for Perlin noise $ pip3 install noise from noise import pnoise1, pnoise2 # 1D Perlin noise: terrain height profile def generate_terrain(width, scale=0.05, octaves=4, seed=0): heights = [] for x in range(width): # pnoise1 returns -1.0 to 1.0 n = pnoise1(x * scale, octaves=octaves, base=seed) # Map to a useful height range (e.g., 2-10 tiles) height = int((n + 1) * 4) + 2 heights.append(height) return heights # 2D Perlin noise: cave generation def generate_caves(width, height, threshold=0.1, scale=0.08): grid = [] for y in range(height): row = [] for x in range(width): n = pnoise2(x * scale, y * scale, octaves=4) row.append(0 if n > threshold else 1) # 0=air, 1=rock grid.append(row) return grid
Parameter Effect Typical Range
Scale How "zoomed in" the noise is -- smaller values make broader features 0.01 - 0.2
Octaves Layers of detail -- more octaves add fine detail on top of broad shapes 1 - 8
Persistence How much each octave contributes relative to the previous one 0.3 - 0.7
Threshold The cutoff between solid and empty -- controls cave density -0.2 to 0.3

Endless Runner Architecture

An endless runner generates the world in chunks ahead of the player and destroys old chunks behind them. The world is never fully in memory -- only the visible portion plus a buffer.

CHUNK_WIDTH = 20 # tiles per chunk BUFFER_AHEAD = 3 # chunks ahead of player BUFFER_BEHIND = 1 # chunks behind player before cleanup class ChunkManager: def __init__(self, seed): self.chunks = {} # chunk_index -> tile_data self.seed = seed def get_chunk(self, chunk_idx): if chunk_idx not in self.chunks: # Generate deterministically from seed + chunk index random.seed(self.seed + chunk_idx) self.chunks[chunk_idx] = self._generate(chunk_idx) return self.chunks[chunk_idx] def update(self, player_chunk): # Ensure chunks ahead are generated for i in range(player_chunk - BUFFER_BEHIND, player_chunk + BUFFER_AHEAD + 1): self.get_chunk(i) # Discard old chunks old = [k for k in self.chunks if k < player_chunk - BUFFER_BEHIND - 1] for k in old: del self.chunks[k] def _generate(self, chunk_idx): # Weighted random with difficulty scaling difficulty = min(1.0, chunk_idx / 50.0) gap_weight = 10 + difficulty * 25 # More gaps at higher difficulty # ... generate CHUNK_WIDTH columns

Difficulty Curves

Good procedural generation gets harder over time. The difficulty curve controls how generation parameters change as the player progresses. A linear curve feels monotonous. A logarithmic curve ramps fast early and plateaus. An exponential curve is gentle early and punishing late.

Linear difficulty = distance / max_distance. Simple, predictable. Used for gap width, obstacle frequency.
Logarithmic difficulty = log(distance + 1) / log(max + 1). Fast ramp, slow plateau. Good for speed increases.
Stepped difficulty = floor(distance / zone_size). Discrete difficulty zones. Classic arcade feel.
Wave difficulty = base + sin(distance * freq) * amplitude. Alternating easy/hard sections. Prevents fatigue.
Pi Performance Note:

On the Pi, procedural generation runs on the CPU. If generation is expensive (complex noise calculations), generate chunks in advance on a separate thread to avoid frame drops. Python's threading module works for I/O-bound tasks; for CPU-bound generation, consider pre-computing chunks during loading screens.

Key Takeaways

  • Seeded PRNGs produce deterministic sequences -- same seed, same world, every time
  • Weighted random choices with validation constraints create playable levels from probability distributions
  • Perlin noise produces smooth, organic shapes ideal for terrain, caves, and natural features
  • Endless runners use chunk-based generation with a sliding window of active chunks in memory
  • Difficulty curves (linear, logarithmic, stepped, wave) control how generation parameters evolve over time
  • On the Pi, pre-compute expensive generation during loading or buffer ahead to avoid frame drops
