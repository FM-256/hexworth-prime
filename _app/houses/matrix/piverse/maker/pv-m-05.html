MQTT: The IoT Messaging Protocol

MQTT (Message Queuing Telemetry Transport) is a lightweight publish/subscribe protocol designed for constrained devices and unreliable networks. Unlike HTTP's request/response model, MQTT decouples senders and receivers through a central broker. A temperature sensor publishes to a topic; any number of subscribers receive the message without the sensor knowing about them.

# Install Mosquitto MQTT broker on the Pi $ sudo apt install -y mosquitto mosquitto-clients $ sudo systemctl enable mosquitto # Publish a message $ mosquitto_pub -h localhost -t "home/livingroom/temp" -m "22.5" # Subscribe to all messages under home/ $ mosquitto_sub -h localhost -t "home/#" -v # Python MQTT client $ pip3 install paho-mqtt import paho.mqtt.client as mqtt def on_message(client, userdata, msg): print(f"{msg.topic}: {msg.payload.decode()}") client = mqtt.Client() client.on_message = on_message client.connect("localhost", 1883) client.subscribe("home/#") client.loop_forever()

Wireless Protocols Compared

Home automation devices communicate over different wireless protocols, each with trade-offs in range, power consumption, bandwidth, and ecosystem compatibility.

Protocol Frequency Range Power Mesh Pi Support
Wi-Fi 2.4 / 5 GHz 30-50m High No Built-in
Zigbee 2.4 GHz 10-20m (mesh extends) Very low Yes USB coordinator (Sonoff, ConBee)
Z-Wave 868/908 MHz 30-100m Low Yes USB stick (Aeotec)
Bluetooth LE 2.4 GHz 10-30m Very low BLE Mesh Built-in
Thread / Matter 2.4 GHz 10-30m (mesh) Low Yes USB border router
Zigbee vs. Z-Wave:

Zigbee has more devices and open standards but shares the crowded 2.4GHz band with Wi-Fi. Z-Wave uses a dedicated sub-GHz frequency (no interference) and better range through walls, but devices cost more and the protocol was proprietary until 2020. For a Pi-based hub, Zigbee with a SONOFF Zigbee 3.0 USB dongle is the most cost-effective starting point.

Home Assistant on the Pi

Home Assistant is an open-source home automation platform that runs natively on the Raspberry Pi. It integrates with over 2,000 device types and provides automations, dashboards, and voice control.

# Option 1: Home Assistant OS (recommended -- dedicated SD card) # Flash the HA OS image to an SD card using Raspberry Pi Imager # Boot the Pi -- access at http://homeassistant.local:8123 # Option 2: Home Assistant Container (on existing Pi OS) $ sudo apt install -y docker.io $ sudo docker run -d \ --name homeassistant \ --restart=unless-stopped \ -v /opt/homeassistant:/config \ -e TZ=America/New_York \ --network=host \ ghcr.io/home-assistant/home-assistant:stable # Option 3: Home Assistant Core (Python venv -- advanced) $ python3 -m venv /opt/ha-venv $ source /opt/ha-venv/bin/activate $ pip3 install homeassistant

Home Assistant OS is the simplest path -- it manages the OS, Docker, and HA itself. The Container option runs HA alongside your existing Pi OS setup. Core is for developers who want to manage dependencies manually.

Node-RED: Visual Automation

Node-RED is a flow-based programming tool that runs on the Pi. You wire together nodes (inputs, functions, outputs) in a browser-based editor. It excels at connecting MQTT messages to actions without writing code.

# Install Node-RED on Pi OS $ bash <(curl -sL https://raw.githubusercontent.com/node-red/linux-installers/master/deb/update-nodejs-and-nodered) # Start Node-RED and enable on boot $ sudo systemctl enable nodered $ sudo systemctl start nodered # Access the editor at http://<pi-ip>:1880
MQTT In Node Subscribes to an MQTT topic. Outputs the payload as a message object when data arrives.
Function Node Runs JavaScript on the message. Transform data, add logic, filter messages.
Switch Node Routes messages based on conditions. "If temperature > 30, send to alert branch."
MQTT Out Node Publishes a message to an MQTT topic. Triggers actuators, sends commands to devices.

Sensor-to-Action Pipeline

A complete automation pipeline connects sensors to actions through the message bus. Here is an example: a DHT22 temperature sensor publishes readings via MQTT. Node-RED monitors the topic and triggers a smart plug if the temperature exceeds a threshold.

# Python script on a Pi with a DHT22 sensor import time import adafruit_dht import board import paho.mqtt.client as mqtt sensor = adafruit_dht.DHT22(board.D4) client = mqtt.Client() client.connect("192.168.1.100", 1883) while True: try: temp = sensor.temperature humidity = sensor.humidity client.publish("home/office/temp", f"{temp:.1f}") client.publish("home/office/humidity", f"{humidity:.1f}") except RuntimeError: pass # DHT sensors occasionally fail -- retry next cycle time.sleep(30)
Security Note:

By default, Mosquitto accepts connections without authentication. In any non-trivial deployment, configure username/password authentication and TLS encryption. An unsecured MQTT broker on your network is an open door to controlling every connected device.

Key Takeaways

  • MQTT is a publish/subscribe protocol -- sensors publish to topics, automation systems subscribe
  • Zigbee and Z-Wave are mesh protocols designed for low-power sensors; Wi-Fi is high-bandwidth but power-hungry
  • Home Assistant integrates 2,000+ device types with automations, dashboards, and voice control
  • Node-RED provides visual flow-based automation -- wire nodes together instead of writing code
  • A sensor-to-action pipeline uses MQTT as the message bus between data collection and automation logic
  • Always secure MQTT with authentication and TLS -- an open broker is a network-wide vulnerability
