Transcoding Fundamentals

Transcoding is the process of converting media from one format or bitrate to another in real-time. When a client device cannot play the original file (wrong codec, too high bitrate, wrong resolution), the server transcodes the stream on the fly. This is the most CPU-intensive operation a media server performs.

Direct Play Client supports the original file format, codec, and bitrate. Server sends the file as-is. Zero CPU cost. This is the ideal scenario.
Direct Stream Client supports the codec but not the container (e.g., MKV vs MP4). Server remuxes without re-encoding. Very low CPU cost.
Transcode (Software) Client needs a different codec or lower bitrate. Server re-encodes using FFmpeg on the CPU. Very high CPU cost -- the Pi struggles with this.
Transcode (Hardware) Uses the Pi's VideoCore GPU for encoding/decoding. Pi 5's VideoCore VII supports H.265/HEVC decode. Limited but helpful.
Pi Limitation:

The Pi 5 can hardware-decode H.264 and H.265, but it cannot hardware-encode. Software transcoding of 1080p video at real-time speed is borderline on a Pi 5 and impossible on a Pi 4. The strategy for Pi media servers is to maximize direct play by choosing widely-compatible formats for your media library.

Streaming Protocols

Protocol Type Use Case Pi Relevance
DLNA/UPnP Local network discovery + streaming Smart TVs, game consoles auto-discover the server Supported by Jellyfin, MiniDLNA
HLS HTTP-based adaptive streaming Apple devices, web browsers, mobile apps Jellyfin web client uses HLS
DASH HTTP-based adaptive streaming Android, modern browsers, MPEG standard Alternative to HLS, similar quality
RTSP Real-time streaming IP cameras, live feeds, low latency Used for Pi Camera streaming

Adaptive streaming (HLS/DASH) splits media into small chunks at multiple quality levels. The client automatically switches between quality levels based on network conditions -- buffering on a slow connection rather than stalling.

Platform Comparison

Platform Role Strengths Limitations on Pi
Kodi Media player (local playback) Best playback UI, vast plugin ecosystem, controller support Player only -- does not serve to other devices
LibreELEC Minimal OS running Kodi Boots straight into Kodi, optimized for Pi hardware Dedicated device -- cannot run other services
Jellyfin Media server (serves to clients) Free, open-source, web UI, mobile apps, no account required Software transcoding limited by Pi CPU
Plex Media server Polished UI, Plex Pass hardware transcoding Some features require paid subscription

Jellyfin on the Pi

# Install Jellyfin on Raspberry Pi OS (64-bit) $ sudo apt install -y curl gnupg $ curl -fsSL https://repo.jellyfin.org/install-debuntu.sh | sudo bash # Mount external USB drive for media storage $ sudo mkdir -p /mnt/media $ sudo mount /dev/sda1 /mnt/media # Add to /etc/fstab for persistent mount # UUID=xxxx-xxxx /mnt/media ext4 defaults,nofail 0 2 # Set permissions so Jellyfin can read the media $ sudo chown -R jellyfin:jellyfin /mnt/media # Access web UI at http://<pi-ip>:8096 # Add library: Movies -> /mnt/media/movies # Add library: TV Shows -> /mnt/media/tv

Performance Optimization

The Pi's main bottlenecks for media serving are CPU (transcoding), USB bandwidth (storage I/O), and network throughput. Here are the key optimizations:

Avoid Transcoding Pre-encode your library to H.264 in MP4 containers with AAC audio. This combination direct-plays on virtually every client device.
Use USB 3.0 Pi 5 has dedicated USB 3.0 bandwidth (not shared with Ethernet like Pi 4). Use USB 3.0 drives for media storage.
Wired Ethernet Gigabit Ethernet delivers consistent throughput for multiple streams. Wi-Fi introduces latency and bandwidth variability.
RAM Disk for Metadata Move Jellyfin's metadata cache to a tmpfs mount to reduce SD card I/O and improve library browsing speed.
# Pre-encode media with FFmpeg for maximum compatibility $ ffmpeg -i input.mkv \ -c:v libx264 -preset medium -crf 20 \ -c:a aac -b:a 192k \ -movflags +faststart \ output.mp4 # -c:v libx264 H.264 video codec (universal support) # -preset medium Balance of speed and compression # -crf 20 Quality (18=near-lossless, 23=default, 28=low) # -c:a aac AAC audio (universal support) # -movflags Move index to start of file for instant playback

Key Takeaways

  • Transcoding is CPU-intensive -- the Pi should maximize direct play by using H.264/AAC in MP4 containers
  • DLNA handles local network discovery; HLS/DASH handle adaptive streaming over HTTP
  • Kodi/LibreELEC = local playback; Jellyfin = network server serving to multiple client devices
  • Jellyfin is free, open-source, and runs well on Pi 5 when transcoding is avoided
  • Use wired Ethernet and USB 3.0 storage to maximize throughput on the Pi
  • Pre-encode your media library with FFmpeg rather than relying on real-time transcoding
