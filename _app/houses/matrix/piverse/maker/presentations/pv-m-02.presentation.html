The Game Loop
Every real-time game runs on the same three-phase infinite loop.
1. Process Input
Read keyboard, mouse, or controller state. Determine which keys are held and which events fired this frame. This must happen first -- stale input means laggy controls.
2. Update State
Move objects, apply physics, check collisions, update scores. All game logic happens here. No drawing -- just math and decisions.
3. Render Frame
Clear the screen, draw every object at its new position, flip the buffer to the display. At 60 FPS, this entire cycle runs in under 16.67 milliseconds.
Why This Order Matters
Input before update ensures the current frame reacts to the latest button press. Update before render ensures the screen shows the result of this frame's logic, not the previous frame's.

Pygame Fundamentals
A Python library for multimedia applications -- games, visualizations, simulations.
pygame.init()
Initializes all Pygame subsystems: display, audio, font, events, timers. Must be called before any other Pygame function. Returns a tuple of (successes, failures).
pygame.display.set_mode()
Creates the game window. Takes a (width, height) tuple. Returns a Surface object -- your drawing canvas. All rendering targets this surface.
pygame.event.get()
Returns all events since last call: QUIT, KEYDOWN, KEYUP, MOUSEMOTION. Must be called every frame or the OS considers the window unresponsive.
pygame.time.Clock()
Frame rate controller. clock.tick(60) sleeps enough to maintain 60 FPS. Returns milliseconds since last call -- useful for delta-time calculations.
Pre-installed
Pygame ships with Raspberry Pi OS. Verify with: python3 -c "import pygame; print(pygame.ver)" -- upgrade with pip3 install --upgrade pygame.

The Pygame Coordinate System
(0, 0) is the top-left corner. X increases right, Y increases down.
Screen vs. Math Coordinates
In math class, Y increases upward. In Pygame (and nearly all 2D graphics systems), Y increases downward. A paddle at y=0 is at the top of the screen. This is a common source of bugs for beginners.
pygame.Rect
A rectangle defined by (x, y, width, height). Provides .top, .bottom, .left, .right, .centerx, .centery properties. Rect is the workhorse of 2D collision detection in Pygame.
# Game constants for Boing! WIDTH, HEIGHT = 800, 600 PADDLE_W, PADDLE_H = 12, 100 BALL_SIZE = 12 # Paddle rects paddle_left = pygame.Rect(30, HEIGHT // 2 - PADDLE_H // 2, PADDLE_W, PADDLE_H) paddle_right = pygame.Rect(WIDTH - 30 - PADDLE_W, HEIGHT // 2 - PADDLE_H // 2, PADDLE_W, PADDLE_H)

Input Handling
Two approaches: event-based (fires once) vs. state-based (checks every frame).
Event-Based
pygame.event.get() returns KEYDOWN/KEYUP events. Good for discrete actions: jump, pause, quit. Fires exactly once per press/release.
State-Based
pygame.key.get_pressed() returns a dict of all keys and their current state (True/False). Good for continuous movement: paddles, steering. Reads every frame.
keys = pygame.key.get_pressed() # Left paddle: W/S keys if keys[pygame.K_w] and paddle_left.top > 0: paddle_left.y -= PADDLE_SPEED if keys[pygame.K_s] and paddle_left.bottom < HEIGHT: paddle_left.y += PADDLE_SPEED # Right paddle: Up/Down arrow keys if keys[pygame.K_UP] and paddle_right.top > 0: paddle_right.y -= PADDLE_SPEED
Boundary Checks
Without paddle_left.top > 0 the paddle scrolls off the top of the screen. Always clamp movement to the play area.

Ball Physics
The ball moves at constant velocity. Collisions reverse the appropriate axis.
# Ball state ball = pygame.Rect(WIDTH // 2, HEIGHT // 2, BALL_SIZE, BALL_SIZE) ball_dx = 5 # Horizontal velocity (pixels/frame) ball_dy = 5 # Vertical velocity (pixels/frame) # Update position ball.x += ball_dx ball.y += ball_dy # Wall bounce (top and bottom) if ball.top <= 0 or ball.bottom >= HEIGHT: ball_dy = -ball_dy # Reverse vertical direction
Velocity vs. Speed
Speed is how fast (always positive). Velocity is speed with direction. ball_dx = -5 means the ball moves left at speed 5. Reversing velocity (-ball_dx) reverses direction without changing speed.

Collision Detection
AABB collision: do two axis-aligned rectangles overlap?
colliderect()
Pygame's Rect.colliderect(other_rect) returns True if two rectangles overlap. This is Axis-Aligned Bounding Box (AABB) detection -- fast, simple, and sufficient for rectangular objects.
Direction Guard
Only bounce when the ball is moving toward the paddle (ball_dx < 0 for left paddle). Without this guard, the ball can get "stuck" inside the paddle, bouncing every frame.
# Paddle collision if ball.colliderect(paddle_left) and ball_dx < 0: ball_dx = -ball_dx if ball.colliderect(paddle_right) and ball_dx > 0: ball_dx = -ball_dx # Angle variation based on hit position offset = (ball.centery - paddle_left.centery) / (PADDLE_H / 2) ball_dy = offset * MAX_BOUNCE_ANGLE
Hit Position Matters
The offset calculation maps where the ball hits the paddle (-1.0 top to +1.0 bottom) to a bounce angle. Hitting the edge sends the ball at a steep angle. Hitting center returns it flat. This is how real Pong works.

Center Line
Draw a dashed center line with multiple small rectangles in a loop. This visual element completes the classic Pong aesthetic and helps players orient on the field.

Frame Rate and Delta Time
Why clock.tick(60) is not enough for professional game physics.
Fixed Timestep
clock.tick(60) caps at 60 FPS but does not guarantee it. If a frame takes 20ms (50 FPS), the ball moves the same distance per frame as at 60 FPS -- making the game run slower on weak hardware.
Delta-Time Scaling
dt = clock.tick(60) / 1000.0 gives seconds since last frame. Multiply all velocities by dt: ball.x += ball_dx * dt. Now the ball moves the same distance per second regardless of frame rate.
# Delta-time independent movement dt = clock.tick(60) / 1000.0 # Seconds since last frame ball.x += ball_dx * dt * 60 # Normalize to 60fps baseline ball.y += ball_dy * dt * 60 # At 60fps: dt = 0.0167, movement = speed * 1.0 # At 30fps: dt = 0.0333, movement = speed * 2.0 # Result: same distance per second either way

The Rendering Pipeline
Clear, draw, flip -- in that order, every frame.
1screen.fill((0, 0, 0)) -- Clear the entire screen to black. Without this, previous frames leave trails.
2Draw center line -- Loop to draw dashed vertical rectangles down the middle of the field.
3pygame.draw.rect(screen, WHITE, paddle_left) -- Draw both paddles as solid white rectangles.
4pygame.draw.rect(screen, WHITE, ball) -- Draw the ball (square Rect drawn as a filled rectangle).
5screen.blit(score_surface, position) -- Render score text surfaces onto the screen.
6pygame.display.flip() -- Push the completed frame to the actual display. Until flip() is called, the player sees the old frame.

Polish: Sound and State
Sound effects and game states transform a prototype into a game.
Sound Effects
pygame.mixer.Sound("bounce.wav").play() triggers immediately. Use short .wav files for low latency. Load sounds once at startup, play on collision events. Volume: sound.set_volume(0.5).
Game States
A state variable (MENU, PLAYING, PAUSED, GAME_OVER) controls which code runs in the game loop. Each state has its own input handling, update logic, and rendering. State transitions happen on events (press ENTER to start).
Progressive Difficulty
Increase ball speed slightly after each paddle hit: ball_dx *= 1.05. This creates natural difficulty scaling. Cap the maximum speed to prevent the ball from tunneling through paddles when moving faster than paddle width per frame.

Key Takeaways: Boing!
The five facts that matter.
1The game loop is Input -> Update -> Render, running 60 times per second. This three-phase structure is universal to all real-time games.
2Pygame's Rect is the foundation of 2D positioning. Properties like .top, .bottom, .centerx and methods like .colliderect() handle geometry without manual math.
3Collision detection needs direction guards. Only bounce when the ball moves toward the paddle, not away from it, or the ball gets stuck.
4Delta-time scaling makes physics frame-rate independent. Multiply velocities by dt so the game runs at the same speed on fast and slow hardware.
5Rendering is always clear-draw-flip. Fill black, draw all objects, then pygame.display.flip(). No flip = invisible frame.
