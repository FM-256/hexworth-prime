The Pi Camera Ecosystem
Three tiers of imaging hardware for the Raspberry Pi.
Camera Module v3
Sony IMX708, 12MP, autofocus, HDR mode. Fixed lens, small 1.4um pixels. Good for general photography and video. $25.
HQ Camera
Sony IMX477, 12.3MP, C/CS-mount lens system. Larger 1.55um pixels with better low-light performance. Interchangeable lenses enable telephoto, macro, and wide-angle. $50.
Global Shutter Camera
Sony IMX296, 1.6MP, global shutter eliminates rolling shutter distortion. Lower resolution but critical for fast-moving subjects and machine vision applications. $50.
Sensor vs. Lens
The HQ Camera's advantage is not just its sensor -- it is the C/CS-mount system that accepts professional lenses. A 16mm telephoto lens on the HQ Camera produces images impossible to achieve with the fixed-lens Camera Module v3, regardless of sensor quality.

libcamera Stack
The modern camera framework that replaced raspistill.
L4User Applications -- libcamera-still, libcamera-vid, libcamera-hello, Picamera2 (Python). Your code interacts at this level.
L3libcamera Library -- Open-source camera support library. Handles pipeline configuration, buffer management, and request queuing. Runs in userspace.
L2IPA (Image Processing Algorithm) -- Per-sensor tuning files. Controls auto-exposure, auto-white-balance, lens shading correction, and noise reduction. Sensor-specific calibration data.
L1Kernel Driver -- V4L2 (Video4Linux2) device driver. Communicates with the sensor over I2C (control) and CSI-2 (image data). Manages DMA buffers.
Why libcamera?
The old raspistill/raspivid tools were closed-source Broadcom binaries. libcamera is open-source, supports multiple sensors, and integrates with standard Linux media frameworks. Picamera2 is the official Python wrapper built on top of libcamera.

Exposure Triangle
The three parameters that control how much light reaches the sensor.
Shutter Speed
How long the sensor collects light. Pi HQ Camera supports 1us to 230s. Longer = brighter but motion blur. Shorter = darker but frozen motion. Controlled via ExposureTime in libcamera.
ISO / Analog Gain
Sensor amplification. Higher ISO = brighter image but more noise. Pi HQ Camera range: ISO 100 to ISO 1600 (analog gain 1.0 to 16.0). Controlled via AnalogueGain.
Aperture
Lens opening size (f-stop). Wider aperture (lower f-number) = more light, shallower depth of field. Only adjustable on HQ Camera with manual lenses. Camera Module v3 has fixed aperture.
Manual Control
Computational photography requires manual exposure control. Auto-exposure optimizes for "correct" exposure but cannot produce intentional long exposures, HDR brackets, or controlled underexposure for noise stacking.

Long Exposure Photography
Using extended shutter times to capture light over seconds or minutes.
Light Trails
30-120 second exposures capture moving light sources (cars, stars) as continuous trails. The sensor accumulates photons over time, recording motion as streaks against a dark background.
Star Trails
Stack hundreds of short (15-30s) exposures instead of one ultra-long exposure. Avoids thermal noise buildup and allows removal of airplane/satellite streaks from individual frames.
# 30-second long exposure with Pi HQ Camera $ libcamera-still -t 1 --shutter 30000000 --gain 1.0 \ --denoise off --awb daylight -o long_exposure.dng # --shutter value is in microseconds (30s = 30,000,000) # --denoise off preserves star points and fine detail # -o .dng saves raw Bayer data for post-processing

HDR -- High Dynamic Range
Merging multiple exposures to capture detail in both shadows and highlights.
1Bracket capture. Take 3-5 images at different exposures: -2EV, 0EV, +2EV. Each captures detail in a different luminance range. Underexposed frames preserve highlight detail; overexposed frames reveal shadow detail.
2Alignment. If the camera moved between shots, align the frames using feature matching (ORB/SIFT). Tripod-mounted Pi cameras rarely need this step.
3Merge. Combine aligned frames into a 32-bit HDR image using Debevec or Robertson algorithms. This intermediate image contains the full dynamic range -- more than any display can show.
4Tone map. Compress the HDR data back to 8-bit (or 16-bit) using Reinhard, Drago, or Mantiuk operators. This is where the artistic choices happen -- balancing natural look vs. dramatic contrast.
Pi Limitation
HDR merging and tone mapping are CPU-intensive. Processing three 12MP raw frames can take 30-60 seconds on a Pi 5. Capture on the Pi, process on the Pi or offload to a desktop for faster iteration.

Image Stacking for Noise Reduction
Averaging multiple frames to mathematically eliminate random noise.
The Math
Random noise is different in every frame. Signal (the actual image) is the same. Averaging N frames reduces noise by a factor of sqrt(N). 16 frames = 4x noise reduction. 64 frames = 8x. This is why astrophotographers stack hundreds of exposures.
The Process
Capture N identical exposures (same shutter, gain, focus). Load all frames as numpy arrays. Compute the per-pixel median or mean across the stack. Save the result. Median stacking also removes transient objects (planes, satellites).
# Python: median stack 20 images for noise reduction import numpy as np from PIL import Image frames = [np.array(Image.open(f'frame_{i:03d}.png')) for i in range(20)] stacked = np.median(frames, axis=0).astype(np.uint8) Image.fromarray(stacked).save('stacked_result.png')

Raw vs. JPEG Pipeline
Why raw capture matters for computational photography.
JPEG Pipeline
Sensor -> Demosaic -> White Balance -> Gamma Correction -> Noise Reduction -> JPEG Compression. Each step is destructive and irreversible. 8-bit output loses shadow and highlight detail permanently.
Raw (DNG) Pipeline
Sensor -> Raw Bayer data saved directly. All processing decisions deferred to post-capture. 12-bit or 10-bit per channel preserves 16x or 4x more tonal information than 8-bit JPEG. Essential for HDR and stacking workflows.
Bayer Pattern
The sensor does not capture color directly. Each pixel has a color filter (Red, Green, or Blue) arranged in a Bayer mosaic -- RGGB pattern. Demosaicing is the interpolation algorithm that converts this mosaic into a full-color image. Different demosaic algorithms (bilinear, VNG, AHD) produce different quality/speed tradeoffs.

Picamera2 Python API
The official Python library for Pi camera control.
# Picamera2: capture raw DNG + JPEG simultaneously from picamera2 import Picamera2 cam = Picamera2() config = cam.create_still_configuration( main={"size": (4056, 3040), "format": "RGB888"}, raw={"size": (4056, 3040)}, controls={ "ExposureTime": 5000000, # 5 seconds "AnalogueGain": 1.0, # ISO 100 "AwbEnable": False, # Manual WB "ColourGains": (2.0, 1.5), # R, B gains } ) cam.configure(config) cam.start() cam.capture_file("photo.dng", name="raw") cam.capture_file("photo.jpg", name="main") cam.stop()

Time-Lapse Automation
Capturing hundreds of frames at intervals for video compilation.
1Interval capture. Use Picamera2 with a loop and time.sleep() or libcamera-still -t 0 --timelapse 10000 for 10-second intervals. Lock exposure and white balance to prevent flicker between frames.
2Storage planning. A 12MP JPEG is ~4MB. At 10-second intervals for 24 hours, that is 8,640 frames = ~34GB. Use an external USB drive. MicroSD will fill up and wear out.
3Video assembly. Use FFmpeg to compile frames into a video: ffmpeg -framerate 30 -pattern_type glob -i '*.jpg' -c:v libx264 -pix_fmt yuv420p timelapse.mp4
4Holy grail time-lapse. Day-to-night transitions require gradual exposure ramping. Script exposure time to increase as ambient light drops -- the most challenging time-lapse technique.

Focus Stacking
Combining multiple images focused at different distances for infinite depth of field.
The Problem
At macro distances, depth of field is extremely shallow -- sometimes less than 1mm. A single exposure cannot keep both the foreground and background in focus simultaneously, even at the smallest aperture.
The Solution
Capture 10-50 images, shifting focus slightly between each. Software analyzes each pixel location, selects the sharpest version from the stack, and composites them into one all-in-focus image. Tools: Hugin (free), Zerene Stacker.
Pi Implementation
With the Camera Module v3 (autofocus), Picamera2 can programmatically shift focus using the LensPosition control. Script a sweep from near to far, capture at each step, then stack. The HQ Camera requires manual focus adjustment between shots.

Key Takeaways: Computational Photography
The five facts that matter.
1The Pi HQ Camera's C/CS-mount system accepts interchangeable lenses. Lens choice matters more than sensor resolution for image quality in most scenarios.
2libcamera replaced raspistill. It is open-source, supports multiple sensors, and exposes full manual control via Picamera2 (Python) or CLI tools.
3HDR merges bracketed exposures to capture detail beyond the sensor's native dynamic range. Bracket, align, merge, tone-map.
4Image stacking reduces noise by sqrt(N). 16 averaged frames = 4x noise reduction. Essential for astrophotography and low-light work on the Pi.
5Raw (DNG) capture preserves all sensor data. JPEG processing is destructive and irreversible. Computational photography workflows require raw data for HDR, stacking, and white balance correction.
