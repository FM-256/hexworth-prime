Cloud AI vs. Edge AI
Where inference happens determines latency, privacy, and cost.
Cloud AI
Send data to a remote server (AWS, Google Cloud). Powerful GPUs process the request. Results return over the network. Latency: 100-500ms. Requires internet. Pay per inference. Privacy concerns -- your data leaves the device.
Edge AI
Run the model locally on the Pi. Inference happens on-device using the CPU (or TPU accelerator). Latency: 10-100ms. No internet required. No recurring cost. Data never leaves the local network.
The Tradeoff
Edge devices have limited compute power. A Pi 5 can run a MobileNet classifier at ~30fps but cannot run a GPT-scale language model. Edge AI requires smaller, optimized models -- and that means accepting some accuracy loss compared to massive cloud models.
Slide 3 of 12
TensorFlow Lite
Google's framework for running ML models on resource-constrained devices.
1Model Format. TFLite uses .tflite files -- a FlatBuffer-based format optimized for fast loading and small memory footprint. Models are converted from TensorFlow, PyTorch, or JAX using the TFLite Converter.
2Interpreter. The TFLite runtime allocates tensors, executes operations, and manages memory. No Python training dependencies needed at inference time -- just the lightweight runtime.
3Delegates. Hardware acceleration plugins. The XNNPACK delegate optimizes CPU inference using SIMD (NEON on ARM). The Coral Edge TPU delegate offloads to external USB accelerators.
4Quantization. Converting 32-bit floating-point weights to 8-bit integers. Reduces model size by 4x and improves inference speed 2-3x on ARM CPUs with minimal accuracy loss (typically less than 1%).

Classification vs. Detection
Two fundamentally different computer vision tasks.
Image Classification
Input: one image. Output: a label and confidence score. "This image contains a cat (94%)." The model sees the entire image and picks the most likely category. Cannot locate WHERE the object is. Fast -- one forward pass.
Object Detection
Input: one image. Output: one or more bounding boxes, each with a label and confidence score. "Cat at [x:120, y:80, w:200, h:180] (91%)." Can find multiple objects of different classes in one image. Slower -- more computation per frame.
Pi Performance
MobileNet v2 classification: ~30fps on Pi 5. SSD MobileNet v2 detection: ~10fps on Pi 5. EfficientDet-Lite0 detection: ~5fps on Pi 5. Adding a Coral USB Accelerator boosts detection to ~30fps+ for quantized models.
Slide 5 of 12
MobileNet Architecture
The model family designed specifically for mobile and edge devices.
Depthwise Separable Convolutions
Standard convolution filters spatial AND channel dimensions simultaneously (expensive). MobileNet splits this into a depthwise convolution (spatial only, per-channel) followed by a pointwise convolution (1x1, channel mixing). 8-9x fewer computations.
Width Multiplier
A tunable parameter (alpha) that uniformly reduces the number of channels in every layer. Alpha=1.0 is full model. Alpha=0.5 halves all channels, reducing computation by ~4x with modest accuracy loss. Allows trading accuracy for speed.
Model Zoo
Pre-trained MobileNet models are available at tensorflow.org/lite/models. Trained on ImageNet (1000 classes), COCO (80 object classes), or custom datasets. Start with a pre-trained model and fine-tune on your specific data if needed.

The Inference Pipeline
From camera frame to detection result -- step by step.
1Capture frame. Picamera2 grabs a video frame from the CSI camera. Typically 640x480 for real-time processing. Higher resolution adds latency without improving model accuracy.
2Preprocess. Resize to model input dimensions (224x224 or 320x320). Convert color space (BGR to RGB). Normalize pixel values (0-255 to 0.0-1.0 or -1.0 to 1.0). Match the model's expected input format exactly.
3Invoke interpreter. Copy preprocessed data into the input tensor. Call interpreter.invoke(). The TFLite runtime executes all model layers sequentially on the CPU (or delegate).
4Postprocess. Read output tensors. For detection: decode bounding boxes, apply non-maximum suppression (NMS) to remove duplicate detections, filter by confidence threshold (typically 0.5).
5Render. Draw bounding boxes and labels on the original frame. Display via Picamera2 preview overlay or save annotated image. Log detections to file or database.
Slide 7 of 12
Quantization Deep Dive
Converting float32 models to int8 for edge deployment.
Post-Training Quantization
Convert after training. Provide a representative dataset (100-500 images). The converter measures activation ranges and maps float32 to int8. Fastest approach. ~1% accuracy loss typical.
Quantization-Aware Training
Simulate quantization during training. The model learns to be robust to reduced precision. Better accuracy than post-training but requires retraining. Used when that 1% matters.
Dynamic Range Quantization
Quantize weights only (to int8), keep activations in float32. Simplest approach -- no calibration data needed. 2x size reduction but less speed improvement than full int8.
Why int8 is Faster on ARM
ARM Cortex-A76 (Pi 5) has NEON SIMD units that process 16 int8 operations in the same cycle as 4 float32 operations. Full int8 quantization unlocks 4x theoretical throughput from the same hardware.
Slide 8 of 12
Coral Edge TPU
A USB hardware accelerator purpose-built for TFLite inference.
Hardware
Google's Edge TPU ASIC. 4 TOPS (trillion operations per second) for int8 inference. Connects via USB 3.0. Draws ~2W under load. Runs fully quantized TFLite models only -- float32 operations fall back to the CPU.
Performance Impact
MobileNet v2 classification: 3ms per inference (vs. ~30ms on Pi 5 CPU). SSD MobileNet v2 detection: 12ms per inference (vs. ~100ms on CPU). Enables real-time object detection at 30fps+ on Pi hardware.
Model Compilation
Models must be compiled specifically for the Edge TPU using Google's edgetpu_compiler tool. Only fully quantized (int8) models with supported operations can run on the TPU. Unsupported ops silently fall back to the CPU, destroying performance.

Object Detection Code Pattern
A minimal TFLite detection pipeline in Python.
# TFLite object detection with Pi Camera import tflite_runtime.interpreter as tflite import numpy as np from picamera2 import Picamera2 # Load model and allocate tensors interp = tflite.Interpreter(model_path="detect.tflite") interp.allocate_tensors() inp = interp.get_input_details()[0] out = interp.get_output_details() # Capture and preprocess cam = Picamera2() cam.start() frame = cam.capture_array() resized = cv2.resize(frame, (320, 320)) input_data = np.expand_dims(resized, axis=0) # Run inference interp.set_tensor(inp["index"], input_data) interp.invoke() # Read results: boxes, classes, scores boxes = interp.get_tensor(out[0]["index"])[0] classes = interp.get_tensor(out[1]["index"])[0] scores = interp.get_tensor(out[2]["index"])[0]

Transfer Learning
Training custom models from pre-trained foundations.
1Start with a pre-trained model. MobileNet v2 trained on ImageNet already knows how to recognize edges, textures, shapes, and basic objects. This knowledge transfers to new tasks.
2Replace the classification head. Remove the final layer (1000 ImageNet classes). Add a new layer with your target classes (e.g., 5 bird species). Freeze the base model weights.
3Train on your data. 50-200 images per class is often sufficient. Train on a desktop GPU or Google Colab (free). Fine-tuning takes minutes, not days.
4Convert and deploy. Export to TFLite format with quantization. Copy the .tflite file and labels.txt to the Pi. Update the inference script with the new model path.
Tools
Google's Model Maker library simplifies the entire transfer learning pipeline to ~20 lines of Python. TensorFlow Hub hosts hundreds of base models optimized for fine-tuning.

Real-World Edge AI Projects
Practical applications running on Raspberry Pi hardware.
Wildlife Camera Trap
Pi + camera + motion sensor. On motion trigger, classify the detected animal (deer, raccoon, bird). Log species, timestamp, and confidence to CSV. Solar powered for remote deployment.
Package Detector
Pi watching a front porch. Detect when a package appears (object detection). Send notification via MQTT or email. Record delivery timestamp. No cloud subscription required.
Traffic Counter
Pi + camera at a window. Detect and track vehicles passing. Count by direction using centroid tracking. Log hourly counts for traffic pattern analysis.
Plant Health Monitor
Classify plant leaf images as healthy, nutrient-deficient, or diseased. Custom model trained on 500 images via transfer learning. Automated daily photography and analysis.

Key Takeaways: Edge AI & Computer Vision
The five facts that matter.
1Edge AI runs inference on-device. No internet required, no cloud costs, no data leaving the network. The tradeoff is smaller, less accurate models compared to cloud AI.
2TensorFlow Lite is the standard edge ML framework. Uses optimized .tflite models, supports CPU (XNNPACK) and hardware (Coral TPU) acceleration via delegates.
3Quantization (float32 to int8) is essential for Pi deployment. 4x model size reduction, 2-3x inference speedup, typically less than 1% accuracy loss.
4MobileNet uses depthwise separable convolutions for 8-9x fewer computations than standard CNNs. The architecture family is purpose-built for edge devices.
5Transfer learning enables custom models with minimal data. 50-200 images per class, fine-tune a pre-trained base, convert to TFLite, deploy to Pi.
