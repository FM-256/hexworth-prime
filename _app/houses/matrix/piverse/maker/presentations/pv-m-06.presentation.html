What is Transcoding?
Converting media between formats, codecs, or bitrates in real time.
Direct Play
Client supports the original codec, container, and bitrate. The server sends the file byte-for-byte. Zero CPU cost -- the ideal path for a Pi media server.
Direct Stream (Remux)
Client supports the codec but not the container (MKV vs MP4). The server repackages without re-encoding. Very low CPU cost -- just header rewriting.
Software Transcode
Client needs a different codec or lower bitrate. FFmpeg re-encodes on the CPU. Extremely high CPU cost -- a Pi 5 can barely handle one 1080p transcode stream.
Hardware Transcode
Uses the Pi's VideoCore GPU for decode. Pi 5 can hardware-decode H.264 and H.265 but cannot hardware-encode. Limited but helpful for reducing CPU load.

Codec Landscape
The encoding formats that determine compatibility and quality.
H.264 / AVC
Universal compatibility. Every device plays it. Larger files than H.265 at equivalent quality. The safe default for Pi servers.
H.265 / HEVC
50% smaller files at same quality. Not all devices support it natively. Pi 5 can hardware-decode but not encode.
AV1
Next-gen open codec. Better compression than H.265. No hardware support on any Pi. Software decode is too slow for real-time.
AAC Audio
Standard audio codec for streaming. Universal support. Paired with H.264 in MP4 containers for maximum compatibility.
FLAC Audio
Lossless audio. Large files but perfect quality. Direct play only -- transcoding to AAC wastes the lossless benefit.
Subtitles (SRT/ASS)
SRT text subs can be direct-played by most clients. ASS/SSA styled subs often force transcoding because the server must burn them into the video stream.

Streaming Protocols
How media travels from server to client across the network.
DLNADigital Living Network Alliance. UPnP-based discovery and streaming. Smart TVs and game consoles auto-discover DLNA servers on the LAN. Simple but limited -- no authentication, no remote access, no adaptive bitrate.
HLSHTTP Live Streaming. Apple's adaptive bitrate protocol. Segments media into small .ts chunks with an .m3u8 playlist. Client picks the best quality for its bandwidth. Used by Jellyfin's web player.
DASHDynamic Adaptive Streaming over HTTP. Open standard equivalent to HLS. Uses .mpd manifest files. Supported by most modern browsers and smart TV apps.
RTSPReal-Time Streaming Protocol. Low-latency protocol used by IP cameras and VLC. Not HTTP-based -- uses its own TCP/UDP transport. Less common for media servers.
Pi Strategy
For a Pi media server, prioritize DLNA for local smart TVs and HLS for browser/mobile access. Both can serve direct-play content without transcoding overhead.

Kodi vs. LibreELEC
Media center software optimized for local playback.
Kodi on Pi OS
Full media center application running on top of Raspberry Pi OS. Can coexist with other software. Uses more RAM and has higher latency than a dedicated build. Good for multi-purpose Pi setups.
LibreELEC
Minimal Linux distro built exclusively to run Kodi. Boots in seconds, uses minimal RAM, and dedicates all resources to media playback. The Pi becomes a dedicated media appliance.
Key Distinction
Kodi is a media player -- it plays content locally on the device it runs on. It is not a media server by default. To serve content to other devices, Kodi needs a UPnP/DLNA server add-on or a separate server like Jellyfin running alongside it.

Jellyfin Architecture
The open-source media server that replaces Plex without subscriptions.
1Media Scanner -- Monitors library directories for new files. Identifies movies, TV shows, and music using filename patterns and metadata databases (TMDb, MusicBrainz).
2Metadata Engine -- Downloads posters, descriptions, cast info, ratings. Stores everything in a local SQLite database. No external service dependency after initial scan.
3Transcode Pipeline -- FFmpeg-based. Determines if direct play, remux, or transcode is needed per client. Manages temporary transcode files and segment generation.
4Client API -- REST API serving web, Android, iOS, Roku, and smart TV clients. Each client reports its codec capabilities so the server can choose the optimal delivery method.
5User Management -- Multi-user with per-library permissions. Parental controls, watch history tracking, and playback state sync across devices.

Storage Architecture
Where media lives and how the Pi accesses it.
USB External Drive
Most common Pi setup. USB 3.0 on Pi 4/5 provides ~400MB/s throughput. Use ext4 filesystem for Linux compatibility. Mount via /etc/fstab for persistence across reboots.
NAS via NFS/SMB
Media stored on a separate NAS device. NFS preferred over SMB for Linux-to-Linux. Gigabit Ethernet on Pi 4/5 handles multiple simultaneous streams easily.
MicroSD (Avoid)
Too slow for media serving. Limited write endurance. Use only for the OS and Jellyfin application -- never for media storage. Metadata database writes will wear it out.
NVMe via HAT+
Pi 5 supports NVMe SSDs through the M.2 HAT+. PCIe Gen 2 x1 provides ~450MB/s. Best performance option but most expensive per terabyte.
Directory Structure
Jellyfin expects organized libraries: /media/movies/Movie Name (Year)/Movie.mkv and /media/tv/Show Name/Season 01/Show - S01E01.mkv. Consistent naming is critical for automatic metadata matching.
Slide 8 of 12
Network Requirements
Bandwidth calculations for reliable streaming.
720p H.264
~4 Mbps typical. Comfortable on 100Mbps Ethernet. WiFi 5GHz is reliable.
1080p H.264
~8-12 Mbps typical. Gigabit Ethernet handles 8+ simultaneous streams. WiFi can buffer.
4K H.265
~20-40 Mbps for high-quality encodes. Wired Ethernet strongly recommended. Direct play only on Pi.
Remote Access
Serving media outside your LAN requires port forwarding (default port 8096) or a reverse proxy (Caddy, nginx). HTTPS is mandatory for remote access. Bandwidth is limited by your ISP upload speed -- a 10 Mbps upload supports one 1080p remote stream.

Jellyfin Installation on Pi
Key commands and configuration steps.
# Install Jellyfin on Raspberry Pi OS (64-bit) $ sudo apt install curl gnupg $ curl -fsSL https://repo.jellyfin.org/install-debuntu.sh | sudo bash # Verify service is running $ sudo systemctl status jellyfin # Mount external USB drive $ sudo mkdir -p /media/usb $ sudo mount /dev/sda1 /media/usb # Add to /etc/fstab for persistence: # /dev/sda1 /media/usb ext4 defaults,nofail 0 2 # Give Jellyfin access to media directory $ sudo chown -R jellyfin:jellyfin /media/usb/media # Access web UI at http://<pi-ip>:8096

Performance Optimization
Maximizing streaming quality within the Pi's hardware limits.
1Pre-encode for direct play. Convert your library to H.264/AAC in MP4 containers using FFmpeg on a desktop. Every direct-play stream is a transcode the Pi never has to do.
2Use SRT subtitles. Text-based SRT subs can be rendered client-side. Image-based subs (PGS, VobSub) force server-side burn-in, which triggers a full transcode.
3Disable thumbnails and trickplay. Generating video thumbnails is CPU-intensive. Disable in Jellyfin dashboard under Scheduled Tasks to prevent background CPU spikes.
4Move metadata DB to USB/SSD. Relocate Jellyfin's data directory off the microSD to reduce write wear and improve database query performance.
5Active cooling is mandatory. Sustained media serving keeps the CPU warm. Thermal throttling at 80C degrades streaming quality. Use a heatsink with fan.

Jellyfin vs. Plex vs. Emby
Choosing the right media server for a Pi deployment.
Jellyfin
Fully open-source and free. No account required. All features unlocked. Active community development. Best choice for Pi due to zero licensing overhead.
Plex
Requires a Plex account and internet connection for auth. Hardware transcoding locked behind Plex Pass ($120 lifetime). More polished clients but not fully open.
Emby
Was open-source, now proprietary. Premiere license required for hardware transcoding and sync. Similar architecture to Jellyfin (Jellyfin forked from Emby in 2018).
Pi Recommendation
Jellyfin is the clear choice for Pi deployments. No account requirement means your server works during internet outages. No premium tier means all features are available on day one. The Pi's limited transcoding ability makes Plex's paid hardware transcoding irrelevant.

Key Takeaways: Media Server Architecture
The five facts that matter.
1Direct play is the Pi's best strategy. The Pi 5 cannot software-transcode 1080p reliably. Pre-encode media to H.264/AAC in MP4 for universal compatibility.
2DLNA handles local discovery, HLS handles adaptive streaming. Both protocols avoid transcoding when client codecs match the source file.
3Jellyfin is the optimal Pi media server. Fully open-source, no account required, no premium tier. Forked from Emby in 2018.
4Storage architecture matters. USB 3.0 external drives or NFS-mounted NAS storage -- never serve media from microSD.
5Subtitle format affects transcoding. SRT text subs render client-side (no CPU cost). PGS/VobSub image subs force server-side burn-in (full transcode).
