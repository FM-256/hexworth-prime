MQTT Publish/Subscribe
A lightweight messaging protocol designed for constrained devices and unreliable networks.
Publisher
Sends messages to a topic (e.g., "home/livingroom/temp"). Does not know or care who receives the message. Sensors, buttons, and scripts are typical publishers.
Broker
Central server (Mosquitto on the Pi) that receives all published messages and forwards them to subscribers. Routes by topic. Stores retained messages for late joiners.
Subscriber
Registers interest in one or more topics. Receives messages in real time when publishers send data. Dashboards, relays, and loggers are typical subscribers.
Decoupling
Publishers and subscribers never communicate directly. The broker handles all routing. This means you can add new subscribers (a logger, a dashboard, an alert system) without modifying any publisher code.

MQTT Topics and QoS
Hierarchical topic structure with wildcard subscriptions.
Topic Hierarchy
Topics use / as separators: home/bedroom/temp, home/kitchen/humidity. Subscribe to home/bedroom/# to get all bedroom sensors. Subscribe to home/+/temp to get temperature from all rooms.
QoS Levels
QoS 0: fire and forget (fastest, no guarantee). QoS 1: at least once delivery (may duplicate). QoS 2: exactly once delivery (slowest, guaranteed). Most sensor data uses QoS 0; critical commands use QoS 1.
# Install and start Mosquitto broker $ sudo apt install -y mosquitto mosquitto-clients $ sudo systemctl enable mosquitto # Publish a temperature reading $ mosquitto_pub -h localhost -t "home/livingroom/temp" -m "22.5" # Subscribe to all home topics $ mosquitto_sub -h localhost -t "home/#" -v

Python MQTT Client
paho-mqtt provides a clean Python API for publishing and subscribing.
import paho.mqtt.client as mqtt def on_connect(client, userdata, flags, rc): print("Connected", rc) client.subscribe("home/#") def on_message(client, userdata, msg): print(f"{msg.topic}: {msg.payload.decode()}") client = mqtt.Client() client.on_connect = on_connect client.on_message = on_message client.connect("localhost", 1883) client.loop_forever() # Publishing from a sensor script client.publish("home/office/temp", "23.1", qos=1)
Retained Messages
Publish with retain=True and the broker stores the last message on that topic. New subscribers immediately receive the most recent value without waiting for the next publish. Essential for state topics (light on/off).

Zigbee vs. Z-Wave vs. Wi-Fi
Three wireless protocols for home automation, each with distinct trade-offs.
Zigbee (2.4 GHz)
Low power, mesh networking, open standard. 10-20m range per node, extended by mesh. Shares the crowded 2.4 GHz band with Wi-Fi. USB coordinator needed (SONOFF, ConBee).
Z-Wave (908 MHz)
Dedicated sub-GHz frequency -- no Wi-Fi interference. 30-100m range through walls. Mesh networking. Devices cost more but reliability is higher. USB stick required (Aeotec).
Wi-Fi (2.4/5 GHz)
Built into the Pi, no extra hardware. High bandwidth for cameras and displays. High power consumption -- not suitable for battery sensors. No mesh. Each device needs its own IP address.
Best Starting Point
For a Pi-based hub, Zigbee with a SONOFF Zigbee 3.0 USB dongle is the most cost-effective. Sensors cost $5-15 each, the dongle is $10, and Zigbee2MQTT integrates directly with Home Assistant.

Mesh Networking
Devices relay messages for each other, extending range without a central router.
Coordinators
The USB dongle on your Pi. Manages the mesh, stores the network key, and assigns addresses. There is exactly one coordinator per Zigbee network.
Routers
Mains-powered devices (smart plugs, bulbs) that relay messages for other devices. More routers = better coverage. A smart plug in every room creates a strong mesh backbone.
End Devices
Battery-powered sensors (temperature, motion, door/window) are end devices. They sleep most of the time to save power and only wake to send data. They rely on nearby routers to relay their messages to the coordinator.

Home Assistant on the Pi
An open-source platform integrating 2,000+ device types with automations and dashboards.
1HA OS (recommended): Flash the Home Assistant OS image to an SD card. Boot the Pi. Access at http://homeassistant.local:8123. Manages everything -- OS, Docker, updates.
2HA Container: Run on existing Pi OS via Docker. sudo docker run --network=host ghcr.io/home-assistant/home-assistant:stable. Good if you need Pi OS for other projects.
3HA Core: Python venv install. For developers who want full control over dependencies. pip3 install homeassistant inside a virtual environment.
Integrations
After install, add integrations: Zigbee2MQTT for Zigbee devices, Mosquitto for MQTT, Node-RED for visual automation, ESPHome for custom ESP32 sensors. Each integration is a one-click setup in the UI.

HA Automations
Trigger -> Condition -> Action. The core pattern of all home automation.
# automation.yaml - alias: "Turn on porch light at sunset" trigger: - platform: sun event: sunset offset: "-00:15:00" condition: - condition: state entity_id: binary_sensor.vacation_mode state: "off" action: - service: light.turn_on target: entity_id: light.porch data: brightness_pct: 80 color_temp: 350
YAML vs. UI
Automations can be built entirely in the HA web UI (visual editor) or written in YAML for version control and replication. The UI generates valid YAML behind the scenes -- you can switch between them freely.

Node-RED Visual Automation
Drag-and-drop flow programming for IoT logic.
Nodes
Each node performs one operation: receive MQTT message, parse JSON, compare value, send HTTP request, control GPIO pin. Nodes are connected by wires that carry messages between them.
Flows
A flow is a connected graph of nodes. Input nodes (MQTT in, HTTP request) trigger the flow. Processing nodes (switch, change, function) transform data. Output nodes (MQTT out, GPIO) take action.
# Install Node-RED on Pi OS $ bash <(curl -sL https://raw.githubusercontent.com/node-red/linux-installers/master/deb/update-nodejs-and-nodered) $ sudo systemctl enable nodered $ sudo systemctl start nodered # Access at http://your-pi-ip:1880 # Install HA nodes: Manage palette -> @node-red-contrib-home-assistant-websocket

Sensor-to-Action Pipeline
A complete data flow from physical sensor to automated response.
1Sensor reads data: A DHT22 temperature sensor connected to an ESP32 reads 28.5C.
2ESP32 publishes: The ESP32 publishes "28.5" to MQTT topic "home/office/temp" via Wi-Fi.
3Mosquitto routes: The broker on the Pi forwards the message to all subscribers of "home/office/temp".
4Home Assistant receives: The MQTT integration updates the sensor entity in HA's state machine.
5Automation triggers: If temp > 27, HA sends a Zigbee command to turn on the fan via the coordinator.
6Dashboard updates: The HA dashboard shows current temp and fan state in real time.

Security Considerations
An insecure smart home is worse than a dumb home.
MQTT Authentication
Never run Mosquitto without a password file. mosquitto_passwd creates hashed credentials. Configure allow_anonymous false in mosquitto.conf. Enable TLS for encrypted transport.
Network Isolation
Put IoT devices on a separate VLAN. Cheap sensors with outdated firmware are attack vectors. Isolate them from your main network. The Pi hub bridges the VLANs securely.
Update Policy
Keep Home Assistant, Mosquitto, and Zigbee2MQTT updated. Disable UPnP on your router. Never expose HA directly to the internet -- use Nabu Casa or a VPN for remote access.

Key Takeaways: Home Automation
The five facts that matter.
1MQTT decouples publishers from subscribers via a broker. Topics are hierarchical (home/room/sensor). Wildcards (# and +) enable flexible subscriptions. QoS controls delivery guarantees.
2Zigbee is the best Pi-compatible protocol for sensors. Low power, mesh networking, $5-15 per device. A USB coordinator dongle connects the Pi to the Zigbee mesh.
3Home Assistant runs natively on the Pi. HA OS is the simplest install. Integrates MQTT, Zigbee, Z-Wave, Wi-Fi devices, and 2,000+ platforms into one automation engine.
4Automations follow Trigger -> Condition -> Action. Sunset triggers lights. Temperature thresholds trigger fans. Door sensors trigger notifications. All configurable in YAML or the visual editor.
5Security is non-negotiable. Authenticate MQTT, isolate IoT on a VLAN, never expose services to the internet without VPN or Nabu Casa, and keep all firmware updated.
