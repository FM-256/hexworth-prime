Seeds and Determinism
Same seed = same world, every time.
import random # Same seed produces identical sequence random.seed(42) print(random.randint(0, 100)) # Always 81 print(random.randint(0, 100)) # Always 14 print(random.randint(0, 100)) # Always 3 # Share a seed to let others play the same level WORLD_SEED = 12345 random.seed(WORLD_SEED) level = generate_level() # Identical for everyone
PRNG vs. True Random
Python's random module uses a Mersenne Twister PRNG -- a deterministic algorithm. Given the same seed, the output sequence is always identical. True randomness (from hardware noise) cannot be reproduced, which is why games use PRNGs.

Weighted Random Choices
Not all outcomes should be equally likely.
elements = ["ground", "gap", "platform", "collectible"] weights = [60, 20, 15, 5] level = random.choices(elements, weights=weights, k=100) # Constraint: no gap wider than 3 tiles def validate_level(level): gap_count = 0 for i, elem in enumerate(level): if elem == "gap": gap_count += 1 if gap_count > 3: level[i] = "ground" else: gap_count = 0 return level
Generate Then Validate
Generate content freely, then apply constraints to ensure playability. This two-pass approach (generate, validate) is simpler and more reliable than trying to build perfect constraints into the generator itself.

Perlin Noise
Smooth, continuous randomness -- rolling hills instead of static.
random.random()
Each value is independent. Adjacent values have no relationship. Plotting them produces visual noise -- jagged, incoherent, unusable as terrain.
pnoise1(x * scale)
Adjacent values are similar. The output smoothly transitions between peaks and valleys. Scale controls feature size. The result looks like natural terrain, caves, or clouds.
from noise import pnoise1 def generate_terrain(width, scale=0.05, octaves=4, seed=0): heights = [] for x in range(width): n = pnoise1(x * scale, octaves=octaves, base=seed) # Map -1.0..1.0 to tile height 2..10 height = int((n + 1) * 4) + 2 heights.append(height) return heights

Noise Parameters
Four knobs that control the character of generated content.
Scale (0.01 - 0.2)
How "zoomed in" the noise is. Small scale = broad, gentle hills. Large scale = tight, frequent peaks. Scale 0.02 gives rolling plains; scale 0.15 gives jagged mountains.
Octaves (1 - 8)
Layers of detail stacked on top of each other. Octave 1 is the broad shape. Each additional octave adds finer detail at half the amplitude. 4 octaves is a good default.
Persistence (0.3 - 0.7)
How much each octave contributes relative to the previous one. Low persistence = smooth. High persistence = rough. Controls the "bumpiness" of the output.
Threshold (-0.2 to 0.3)
For cave generation: values above threshold become air, below become rock. Lower threshold = more caves. Higher threshold = more solid rock. Controls density.

2D Noise: Cave Generation
Apply a threshold to 2D Perlin noise to carve caves from solid rock.
from noise import pnoise2 def generate_caves(width, height, threshold=0.1, scale=0.08): grid = [] for y in range(height): row = [] for x in range(width): n = pnoise2(x * scale, y * scale, octaves=4) row.append(0 if n > threshold else 1) grid.append(row) return grid # 0 = air (cave), 1 = rock (solid)
Connectivity
Raw noise caves may produce disconnected chambers. Post-process with flood-fill: find the largest connected air region, fill all smaller disconnected regions with rock. This guarantees the player can reach every part of the cave.

Endless Runner Architecture
Generate chunks ahead, destroy chunks behind. The world is never fully in memory.
CHUNK_WIDTH = 20 # Tiles per chunk BUFFER_AHEAD = 3 # Chunks ahead of player BUFFER_BEHIND = 1 # Chunks behind before cleanup class ChunkManager: def __init__(self, seed): self.chunks = {} self.seed = seed def get_chunk(self, idx): if idx not in self.chunks: random.seed(self.seed + idx) self.chunks[idx] = self._generate(idx) return self.chunks[idx] def update(self, player_chunk): for i in range(player_chunk - BUFFER_BEHIND, player_chunk + BUFFER_AHEAD + 1): self.get_chunk(i) old = [k for k in self.chunks if k < player_chunk - BUFFER_BEHIND - 1] for k in old: del self.chunks[k]

Difficulty Curves
Procedural parameters should change over time to create progression.
Linear Ramp
gap_probability = 0.1 + (chunk_idx * 0.005). Simple, predictable. Gap chance increases 0.5% per chunk. After 100 chunks, gap probability is 60%.
Logarithmic Curve
difficulty = log(chunk_idx + 1) / log(MAX_CHUNK). Starts steep (fast progression early), then flattens (slow progression late). Prevents overwhelming late-game spikes.
import math def get_difficulty(chunk_idx, max_diff=0.8): # Logarithmic curve: fast early, slow late raw = math.log(chunk_idx + 1) / math.log(200) return min(raw, max_diff) # Apply to generation parameters diff = get_difficulty(chunk_idx) gap_chance = 0.1 + diff * 0.4 # 10% -> 50% enemy_chance = 0.05 + diff * 0.25 # 5% -> 30% platform_height_var = 1 + diff * 4 # 1 -> 5 tiles

Room-Based Dungeon Generation
Place rooms randomly, then connect them with corridors.
1Place rooms: Generate random rectangles. Reject if they overlap existing rooms. Repeat until N rooms are placed or max attempts reached.
2Sort by position: Sort rooms by their center x-coordinate. This creates a natural left-to-right flow.
3Connect with corridors: For each adjacent pair of rooms, carve an L-shaped corridor (horizontal then vertical) between their centers.
4Place content: Spawn enemies, items, and the exit in rooms. The first room is the spawn, the last room is the exit. Content density scales with distance from spawn.
Roguelike Standard
This BSP (Binary Space Partition) or random-room approach is used by Rogue, Nethack, Binding of Isaac, and Dead Cells. The template is simple; the variety comes from room contents and enemy placement.

Wave Function Collapse
A constraint-based algorithm that generates content by eliminating impossibilities.
The Concept
Start with a grid where every cell can be any tile. Pick the cell with the fewest valid options. Collapse it (choose one option). Propagate constraints to neighbors. Repeat until all cells are collapsed.
Adjacency Rules
Define which tiles can be next to which. Grass can border grass, dirt, or water. Water can border water or sand -- but never directly touch grass. The rules ensure visual coherence.
Real-World Use
WFC is used in Townscaper, Bad North, and many indie games. It produces surprisingly coherent results from simple adjacency rules. On a Pi, a 50x50 grid collapses in milliseconds.

Testing Procedural Content
How do you test infinite content?
Seed Regression
Generate 1000 levels from sequential seeds. Assert none are unsolvable (path from start to exit exists). Store known-good seeds as regression test fixtures.
Statistical Analysis
Generate 10,000 levels. Measure average gap count, enemy density, completion path length. Verify distributions match design intent. Flag statistical outliers.
Visual Debug Mode
Render the level with color-coded overlay: green = reachable, red = unreachable, yellow = critical path. One glance reveals connectivity problems that statistics might miss.

Key Takeaways: Procedural Generation
The five facts that matter.
1Seeds make randomness reproducible. Same seed = same world. Share seeds for identical experiences. Use them for debugging and regression testing.
2Weighted random + constraints = playable levels. Generate freely, then validate. Reject or fix anything that violates playability rules (impossible gaps, disconnected rooms).
3Perlin noise produces coherent randomness. Scale controls feature size, octaves add detail, threshold converts continuous noise into binary maps (cave/rock).
4Endless runners use chunk-based streaming. Generate chunks ahead of the player, discard behind. The world is never fully in memory -- just the visible window plus a buffer.
5Difficulty curves apply to generation parameters. Logarithmic curves prevent late-game spikes. Every procedural parameter (gap chance, enemy density, height variance) should scale with progression.
