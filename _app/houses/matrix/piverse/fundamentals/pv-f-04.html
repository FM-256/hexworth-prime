Learning Objectives

  • Navigate the filesystem using pwd, ls, cd, and path notation
  • Create, copy, move, and delete files and directories with mkdir, cp, mv, and rm
  • Read and set file permissions using chmod, chown, and ls -l output
  • Manage software packages with apt update, apt install, and apt remove
  • Use pipes, redirection, and the nano text editor for basic file operations
  • Understand sudo for elevated privileges and SSH for remote access
Why the Command Line Matters

The desktop is convenient. The command line is powerful. Every professional Linux workflow -- server administration, scripting, automation, and remote management -- runs through the terminal. Mastering these commands is not optional for Pi work beyond basic desktop use.

The Terminal Prompt

When you open a terminal, you see a prompt. The prompt tells you who you are, what machine you are on, and where you are in the filesystem.

# Anatomy of the terminal prompt pi@piverse:~$ # pi = your username # piverse = hostname (the machine name) # ~ = current directory (~ means your home directory) # $ = regular user prompt (# means root/superuser)

The shell (Bash, by default) interprets your commands, executes them, and shows the output. Commands follow a consistent pattern: command [options] [arguments]. Options usually start with a dash (short form: -l) or double dash (long form: --long).

Filesystem Navigation

Linux organizes everything in a single directory tree starting at / (root). There are no drive letters like Windows. Everything -- files, devices, even running processes -- is represented as files in this tree.

# Print Working Directory -- where am I right now? $ pwd /home/pi # List files and directories in the current location $ ls Desktop Documents Downloads Music Pictures Videos # Detailed listing with permissions, owner, size, and date $ ls -l drwxr-xr-x 2 pi pi 4096 Apr 21 10:00 Desktop drwxr-xr-x 2 pi pi 4096 Apr 21 10:00 Documents drwxr-xr-x 2 pi pi 4096 Apr 21 10:00 Downloads # Show hidden files too (files starting with .) $ ls -la # Change directory -- move into Documents $ cd Documents $ pwd /home/pi/Documents # Go up one directory level $ cd .. # Go directly to your home directory from anywhere $ cd ~ # Or just: $ cd # Go to an absolute path (starts with /) $ cd /var/log # Go back to the previous directory $ cd -
Absolute vs. Relative Paths

An absolute path starts with / and specifies the full location from the root: /home/pi/Documents. A relative path starts from your current directory: Documents (no leading slash). Use .. to refer to the parent directory and . to refer to the current directory.

Creating, Copying, Moving, and Deleting

# Create a new directory $ mkdir projects $ mkdir -p projects/python/sensors # create nested dirs in one command # Create an empty file $ touch notes.txt # Copy a file $ cp notes.txt notes-backup.txt # Copy a directory and all its contents (-r = recursive) $ cp -r projects projects-backup # Move (rename) a file $ mv notes.txt Documents/notes.txt # Rename a file (mv is also used for renaming) $ mv notes-backup.txt old-notes.txt # Delete a file $ rm old-notes.txt # Delete a directory and all contents (-r = recursive, -f = force) $ rm -rf projects-backup
Warning: rm Has No Trash Can

Unlike the desktop file manager, rm permanently deletes files. There is no "Recycle Bin" and no undo. rm -rf is especially dangerous -- it recursively force-deletes without asking for confirmation. Always double-check the path before pressing Enter.

Command Purpose Common Flags
mkdir Create directory -p create parent dirs as needed
touch Create empty file / update timestamp --
cp Copy files/dirs -r recursive, -v verbose
mv Move or rename -v verbose
rm Delete files/dirs -r recursive, -f force, -i confirm each

Viewing File Contents

# Display entire file contents $ cat /etc/hostname piverse # Show first 10 lines of a file $ head /var/log/syslog # Show last 10 lines $ tail /var/log/syslog # Follow a log file in real time (Ctrl+C to stop) $ tail -f /var/log/syslog # Page through a long file (q to quit, Space for next page) $ less /var/log/syslog # Count lines, words, and characters in a file $ wc /etc/passwd 35 52 1842 /etc/passwd # Search for a pattern in a file $ grep "pi" /etc/passwd pi:x:1000:1000:,,,:/home/pi:/bin/bash

File Permissions

Linux controls who can read, write, and execute every file. Understanding permissions is essential for security and for running scripts.

# The permission string from ls -l: -rwxr-xr-- 1 pi pi 4096 Apr 21 10:00 script.sh # Breaking it down: # - = file type (- = regular file, d = directory, l = symlink) # rwx = owner permissions (r=read, w=write, x=execute) # r-x = group permissions (read + execute, no write) # r-- = others permissions (read only) # pi pi = owner user, owner group
Symbol Permission Numeric Value Meaning
r Read 4 View file contents / list directory entries
w Write 2 Modify file / add or remove files in directory
x Execute 1 Run as program / enter (cd into) directory
# Change permissions using numeric notation $ chmod 755 script.sh # rwxr-xr-x (owner: full, group/others: read+execute) $ chmod 644 notes.txt # rw-r--r-- (owner: read+write, group/others: read only) $ chmod 700 private/ # rwx------ (owner only, no access for anyone else) # Change permissions using symbolic notation $ chmod +x script.sh # add execute permission for everyone $ chmod u+x script.sh # add execute for owner (u=user) only $ chmod go-w file.txt # remove write from group (g) and others (o) # Change file ownership $ sudo chown root:root /etc/myconfig.conf # owner=root, group=root $ sudo chown pi:pi script.sh # give ownership to user pi

Package Management with apt

Raspberry Pi OS uses apt (Advanced Package Tool) to install, update, and remove software from the official Debian/Pi repositories. All apt commands that modify the system require sudo.

# Update the package list (checks for available updates) $ sudo apt update # Upgrade all installed packages to their latest versions $ sudo apt upgrade -y # Do both in sequence $ sudo apt update && sudo apt upgrade -y # Install a new package $ sudo apt install htop # interactive process viewer $ sudo apt install git # version control $ sudo apt install tree # visualize directory trees # Remove a package (keeps config files) $ sudo apt remove htop # Remove a package AND its config files $ sudo apt purge htop # Remove unused dependencies $ sudo apt autoremove # Search for a package by name or description $ apt search "network monitor" # Show details about a package $ apt show htop
Always Update Before Installing

Run sudo apt update before installing packages. The package list is a local cache -- if it is stale, apt install may fail to find packages or install outdated versions.

Pipes and Redirection

Pipes and redirection are how you chain commands together and save output to files. They are fundamental to every Linux workflow.

# Pipe: send output of one command as input to another $ ls -la | less # page through a long listing $ cat /etc/passwd | grep pi # search passwd file for "pi" $ ps aux | grep python # find running Python processes $ history | tail -20 # show last 20 commands # Redirect output to a file (overwrites existing content) $ ls -la > filelist.txt # Append output to a file (does not overwrite) $ date >> log.txt # Redirect errors to a file $ find /etc -name "*.conf" 2> errors.txt # Redirect both stdout and stderr to a file $ find /etc -name "*.conf" > results.txt 2>&1 # Discard output completely $ command > /dev/null 2>&1
Operator Function
| Pipe -- send stdout of left command to stdin of right command
> Redirect stdout to file (overwrite)
>> Redirect stdout to file (append)
2> Redirect stderr (error messages) to file
2>&1 Merge stderr into stdout
< Redirect file contents as stdin to a command

Editing Files with nano

nano is a simple terminal-based text editor. It is pre-installed on Raspberry Pi OS and is the easiest editor for beginners. The bottom of the screen shows keyboard shortcuts (^ means Ctrl).

# Open a file for editing (creates it if it does not exist) $ nano myfile.txt # Open a system config file (requires sudo for write access) $ sudo nano /etc/hosts # Inside nano, use these keyboard shortcuts: # Ctrl+O = Write (save) the file # Ctrl+X = Exit nano # Ctrl+K = Cut the current line # Ctrl+U = Paste (uncut) the line # Ctrl+W = Search for text # Ctrl+G = Help screen # Alt+U = Undo last action
nano vs. vim

nano is beginner-friendly with visible shortcuts. vim is more powerful but has a steep learning curve with modal editing. For this track, nano is all you need. You can explore vim later if you want a more advanced workflow.

Elevated Privileges with sudo

sudo (superuser do) lets you run a command with root (administrator) privileges. On Raspberry Pi OS, your user account is in the sudo group by default, so you can run any command as root by prefixing it with sudo.

# Run a single command as root $ sudo apt update # Edit a system file that requires root access $ sudo nano /etc/hosts # View who can use sudo $ sudo cat /etc/sudoers # Start an interactive root shell (use with caution) $ sudo -s # Check: what user am I currently? $ whoami pi $ sudo whoami root
Principle of Least Privilege

Only use sudo when you actually need root access. Running everything as root is dangerous -- a typo in an rm command with root privileges can destroy the entire system. Use sudo for the specific command that needs it, then return to your normal user.

SSH Remote Access

SSH (Secure Shell) lets you connect to your Pi from another computer over the network. This is essential for headless operation and is the standard method for managing any Linux server.

# Connect to your Pi from another computer $ ssh pi@piverse.local # Or by IP address: $ ssh pi@192.168.1.50 # First connection: you will be asked to verify the host fingerprint The authenticity of host 'piverse.local' can't be established. ED25519 key fingerprint is SHA256:xxxxxxxxxxxxxxxxxxxx. Are you sure you want to continue connecting (yes/no)? # Type "yes" -- this is normal for the first connection # Copy a file from your computer to the Pi $ scp myfile.txt pi@piverse.local:~/Documents/ # Copy a file from the Pi to your computer $ scp pi@piverse.local:~/data.csv ./ # Disconnect from SSH $ exit

SSH encrypts all traffic between your computer and the Pi. Passwords, commands, and file transfers are protected from eavesdropping. For even stronger security, you can set up SSH key-based authentication, which eliminates password login entirely.

Key Takeaways

  • pwd, ls, cd form the navigation trinity -- always know where you are in the filesystem
  • mkdir, cp, mv, rm handle file operations -- rm has no undo, so double-check before deleting
  • File permissions (rwx) control access for owner, group, and others -- chmod sets them, chown changes ownership
  • apt update + apt install is how you add software; always update the package list first
  • Pipes (|) chain commands together; redirection (> and >>) saves output to files
  • nano is the beginner-friendly text editor; Ctrl+O to save, Ctrl+X to exit
  • sudo runs commands as root -- use it only when needed (principle of least privilege)
  • SSH provides encrypted remote access -- the standard way to manage a headless Pi
