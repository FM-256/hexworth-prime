Microcontroller vs Single-Board Computer

The Raspberry Pi Pico is a microcontroller board, not a single-board computer. This is a fundamental distinction. A single-board computer (like the Raspberry Pi 4 or 5) runs a full operating system with a filesystem, process scheduler, and multitasking. A microcontroller runs a single program directly on the hardware with no OS in between.

Key Distinction:

A Pi 5 boots in 20 seconds and runs hundreds of processes. A Pico starts your code in milliseconds and runs one program in an infinite loop. The Pico excels at real-time hardware interaction -- reading sensors, driving motors, blinking LEDs -- tasks where immediate, deterministic response times matter.

The RP2040 Chip

The RP2040 is the custom silicon designed by Raspberry Pi for the Pico. It is not just another ARM chip -- it includes Programmable I/O (PIO) state machines that are unique in the microcontroller world.

Dual Cortex-M0+ Cores Two independent processor cores running at up to 133 MHz. MicroPython uses one core by default; you can assign tasks to the second core for true parallel execution.
PIO State Machines 8 programmable state machines (4 per PIO block) that execute custom I/O programs independently of the CPU. Used for WS2812 LEDs, custom serial protocols, and VGA output.
264 KB SRAM No external RAM. All your code and data must fit in 264 KB. MicroPython itself uses about 100 KB, leaving the rest for your program. This constraint forces efficient design.
2 MB Flash External QSPI flash stores the MicroPython firmware and your scripts. Code executes from flash (XIP -- Execute In Place) or can be copied to SRAM for faster execution.

Pico Pinout

The Pico has 40 pins arranged in a dual inline package (DIP) form factor designed for breadboard use. Of these, 26 are user-accessible GPIO pins. Key pins include power (VSYS, 3V3), ground (GND x 8), and special-function pins (ADC, SPI, I2C, UART).

Pin(s) Function Notes
GP0 - GP28 General Purpose I/O 3.3V logic. GP26-28 double as ADC inputs (ADC0-2).
GP25 Onboard LED Connected to the built-in LED (Pico only; Pico W uses CYW43 GPIO).
ADC_VREF ADC Reference Reference voltage for the analog-to-digital converter.
3V3(OUT) 3.3V Power Regulated 3.3V output from the onboard regulator. Max 300mA.
VSYS System Power 1.8V - 5.5V input. Connect external power here when not using USB.
GND Ground 8 ground pins distributed across the board for convenient wiring.
RUN Reset Pull low to reset the Pico. Add a button here for easy resets.
Important:

All Pico GPIO pins are 3.3V. Connecting 5V directly to a GPIO pin will damage the RP2040. If you need to interface with 5V devices, use a level shifter. The ADC channels (GP26-28) read 0-3.3V with 12-bit resolution (0-4095 values).

MicroPython vs CircuitPython

Two Python implementations target the Pico. Both let you write Python that runs directly on the microcontroller. They differ in philosophy, library ecosystem, and community support.

Aspect MicroPython CircuitPython
Creator Damien George (original project) Adafruit (fork of MicroPython)
Philosophy Lean, close to CPython, performance-focused Beginner-friendly, extensive library support
File Access REPL + file upload via Thonny Appears as USB drive -- drag and drop files
Libraries machine, utime, network (hardware-focused) board, digitalio, analogio (abstracted)
Pi Foundation Officially supported and documented Community supported, works well
Best For Performance, networking, advanced hardware control Quick prototyping, Adafruit sensor ecosystem
Recommendation:

Start with MicroPython. It is the officially supported option from the Raspberry Pi Foundation, has the best documentation for the Pico, and gives you more control over hardware. Switch to CircuitPython if you need specific Adafruit sensor libraries.

Pico W: WiFi and Bluetooth

The Pico W adds the Infineon CYW43439 wireless chip, providing 802.11n WiFi and Bluetooth 5.2 (BLE). This transforms the Pico from a standalone controller into an IoT device capable of connecting to networks, serving web pages, and communicating with cloud services.

WiFi (802.11n) 2.4 GHz single-band. Connect to your home network, make HTTP requests, serve a web dashboard, or send sensor data to a cloud API.
Bluetooth 5.2 (BLE) Low Energy Bluetooth for communication with phones, tablets, and other BLE devices. Ideal for wireless sensor readings and remote control.
Onboard LED Change On the Pico, the LED is on GP25. On the Pico W, the LED is controlled through the CYW43439 chip, requiring different code: led = Pin("LED", Pin.OUT)
Same RP2040 The Pico W uses the same RP2040 chip with identical CPU, RAM, and GPIO. Only the wireless module is added. All Pico programs work on Pico W.
# Connect Pico W to WiFi (MicroPython) import network import time wlan = network.WLAN(network.STA_IF) wlan.active(True) wlan.connect("YourNetwork", "YourPassword") # Wait for connection while not wlan.isconnected(): print("Connecting...") time.sleep(1) print("Connected!") print(f"IP: {wlan.ifconfig()[0]}")
# Simple web server on Pico W import socket addr = socket.getaddrinfo("0.0.0.0", 80)[0][-1] s = socket.socket() s.bind(addr) s.listen(1) print("Listening on port 80...") while True: cl, addr = s.accept() request = cl.recv(1024) response = "HTTP/1.0 200 OK\r\n\r\nHello from Pico W!" cl.send(response) cl.close()

USB Boot Mode and Thonny Setup

The Pico has a BOOTSEL button on the board. Holding this button while plugging in the USB cable puts the Pico into USB mass storage mode -- it appears as a drive called RPI-RP2. This is how you flash firmware (like MicroPython) onto the Pico.

Step 1: Download the MicroPython UF2 file from micropython.org/download/RPI_PICO (or RPI_PICO_W for the Pico W).

Step 2: Hold BOOTSEL, plug in USB. Drag the .uf2 file to the RPI-RP2 drive. The Pico reboots automatically.

Step 3: Open Thonny. Go to Tools > Options > Interpreter. Select "MicroPython (Raspberry Pi Pico)" and the correct COM/serial port.

Step 4: The Thonny shell now shows a MicroPython REPL running on the Pico. Type print("Hello Pico!") to verify.

# Blink the onboard LED (Pico) from machine import Pin import time led = Pin(25, Pin.OUT) # GP25 on Pico # led = Pin("LED", Pin.OUT) # Use this for Pico W while True: led.toggle() time.sleep(0.5)

When to Use Pico vs Full Pi

The decision between a Pico and a full Raspberry Pi depends on your project requirements. They are complementary -- many projects use both, with a Pico handling real-time hardware tasks and a Pi handling networking, storage, and user interface.

Use a Pico When... Use a Full Pi When...
Project needs instant-on (no boot time) Project needs a full OS (file system, networking stack)
Battery-powered (Pico uses ~1.6 mA in sleep) Need HDMI output, USB peripherals, or a desktop
Real-time control (motor PWM, precise timing) Running a web server, database, or media center
Simple sensor reading and data logging Processing images, video, or machine learning
Cost-sensitive (Pico is $4-$6) Need multiple programming languages and tools
Dedicated, single-purpose controller Multi-tasking with a graphical user interface
Combined Architecture:

A common pattern is Pi + Pico working together. The Pico handles real-time hardware tasks (reading sensors at precise intervals, generating PWM signals) and sends data to the Pi over UART or I2C. The Pi processes, stores, and displays the data. This separation keeps real-time tasks deterministic.

Key Takeaways

  • The Pico is a microcontroller (no OS, runs one program) -- the Pi is a single-board computer (runs Linux)
  • The RP2040 has dual Cortex-M0+ cores at 133 MHz, 264 KB SRAM, and unique PIO state machines
  • All GPIO pins are 3.3V -- never connect 5V directly to a Pico pin
  • MicroPython is the officially supported Python for Pico; CircuitPython is an Adafruit alternative
  • The Pico W adds CYW43439 for WiFi (802.11n) and Bluetooth 5.2 -- same RP2040 underneath
  • BOOTSEL + USB puts the Pico in mass storage mode for firmware flashing
  • Use Pico for real-time, low-power, single-purpose tasks; use full Pi for OS-dependent workloads
