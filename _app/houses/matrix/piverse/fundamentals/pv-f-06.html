Learning Objectives

  • Build a simple interactive game using sprites, costumes, and sounds

Prerequisites:

You should have your Raspberry Pi set up with Raspberry Pi OS and be comfortable navigating the desktop environment. Scratch 3 comes pre-installed on Raspberry Pi OS.

Why Visual Programming Matters

Before writing a single line of Python or C, visual programming teaches you the fundamental structures that every programming language shares. Block-based environments like Scratch remove the barrier of syntax errors and let you focus purely on logic: sequencing, branching, iteration, and event handling.

Scratch was developed at MIT's Media Lab specifically for learning. It is not a toy -- it implements real computer science concepts including concurrency (multiple sprites executing scripts simultaneously), message passing (broadcasts), and state management (variables and lists). The Raspberry Pi Foundation includes Scratch 3 in every Raspberry Pi OS installation because it is the recommended entry point for programming on the Pi.

Key Insight:

Every concept you learn in Scratch -- loops, conditionals, variables, events -- maps directly to Python, C, and every other language. You are learning programming, not just Scratch.

The Scratch 3 Interface

Launch Scratch 3 from the Raspberry Pi OS menu: Menu > Programming > Scratch 3. The interface is divided into distinct areas, each with a specific purpose.

Area Purpose
Block Palette Color-coded categories of programming blocks you can drag into the scripts area
Scripts Area Where you assemble blocks into programs -- each sprite has its own scripts
Stage The 480x360 pixel canvas where your program runs visually
Sprite Pane Thumbnails of all sprites in your project -- click to select and edit their scripts
Costumes Tab Edit sprite appearances -- each sprite can have multiple costumes for animation
Sounds Tab Record or import audio clips that sprites can play

Events: Starting Your Programs

Every Scratch program begins with an event block -- a "hat" block that defines when the script below it should execute. The most common is when green flag clicked, which fires when you press the green flag button above the stage. Events are the entry points of your program.

when green flag clicked Fires when the project starts. Most scripts begin here. Equivalent to a main() function.
when [space] key pressed Fires when a specific keyboard key is pressed. Used for player input in games.
when this sprite clicked Fires when the user clicks on the sprite. Used for interactive UI elements.
when I receive [message] Fires when another sprite sends a broadcast. This is inter-sprite communication.

A single sprite can have multiple event-driven scripts running simultaneously. This is real concurrency -- each script stack executes independently. If you have when green flag clicked on three separate script stacks, all three begin executing at the same time when the flag is pressed.

Computational Thinking:

Event-driven programming is how real software works. Web browsers, mobile apps, and operating systems all respond to events (clicks, keypresses, network data). You are learning the same paradigm.

Loops: Repetition Without Redundancy

Loops let you repeat actions without duplicating blocks. Scratch provides three loop types, each matching a pattern you will encounter in every programming language.

The forever loop is the most common in Scratch games -- it runs the game logic every frame until the program is stopped. The repeat (10) loop runs a fixed number of iterations. The repeat until loop checks a condition before each iteration and stops when the condition becomes true.

Conditionals: Making Decisions

Conditionals let your program choose between different actions based on whether a condition is true or false. Scratch provides two conditional blocks.

Scratch Block Behavior Text Equivalent
if <> then Execute enclosed blocks only if condition is true if condition:
if <> then / else Execute one branch if true, the other if false if condition: / else:

Conditions use sensing blocks (touching [Mouse]?, key [space] pressed?) and operator blocks (<, >, =, and, or, not). These are boolean expressions -- they evaluate to true or false. Combining conditionals with loops is where programs start making interesting decisions.

Pattern: Guard Clause

Place an if <touching [edge]?> then block inside a forever loop to bounce a sprite off the walls. This is a guard clause -- it checks for a boundary condition every frame and corrects it.

Variables: Storing and Tracking State

Variables store values that can change during your program. In Scratch, you create variables from the Variables category in the block palette. Each variable has a name and holds a single value (number or string).

Score Tracking Create a "score" variable. Use change [score] by (1) when the player catches something. Display it on the stage by checking the variable checkbox.
Timer / Countdown Set a "time" variable to 30. Use a repeat until <(time) = 0> loop with wait 1 second and change [time] by (-1).
Lives System Set "lives" to 3 at start. Decrease on collision. Use if <(lives) = 0> then stop [all] as your game-over condition.
For This Sprite Only Variables can be scoped to a single sprite (local) or shared across all sprites (global). Choose scope when creating the variable.

Variables in Scratch map directly to variables in text-based languages. The concept of scope -- whether a variable is visible to one sprite or all sprites -- is identical to local vs global variables in Python and C.

Broadcasts: Sprite-to-Sprite Communication

When one sprite needs to tell another sprite to do something, it sends a broadcast. This is message-passing -- a fundamental pattern in concurrent programming. The sending sprite does not need to know who is listening.

Use broadcast [message] to send and when I receive [message] to listen. The variant broadcast [message] and wait pauses the sender until all listeners finish -- useful for sequenced animations or level transitions.

Project: Cat Chases Mouse

Apply everything from this module by building a complete game. The cat sprite follows the mouse pointer. A mouse sprite moves randomly. When the cat touches the mouse, the score increases and the mouse teleports to a new location. A timer counts down from 30 seconds.

Step 1 -- Set up sprites. Keep the default Cat sprite. Add a new sprite (choose "Mouse1" from the library). Add a variable called "score" (for all sprites) and "time" (for all sprites).

Step 2 -- Cat sprite scripts.

-- Cat sprite: follow mouse pointer and detect collision -- when green flag clicked set [score] to (0) set [time] to (30) forever point towards (Mouse1 sprite) move (3) steps if <touching [Mouse1]?> then change [score] by (1) broadcast [caught] play sound [pop] end end

Step 3 -- Mouse1 sprite scripts.

-- Mouse1 sprite: teleport to random position when caught -- when green flag clicked go to x: (pick random (-200) to (200)) y: (pick random (-150) to (150)) show when I receive [caught] go to x: (pick random (-200) to (200)) y: (pick random (-150) to (150))

Step 4 -- Timer script (on Stage).

-- Stage: countdown timer -- when green flag clicked set [time] to (30) repeat until <(time) = (0)> wait (1) seconds change [time] by (-1) end stop [all]

This game uses events (green flag, broadcasts), loops (forever, repeat until), conditionals (if touching), variables (score, time), and sprite interaction. Every concept from this module is present in a working program.

Sprites, Costumes, and Sounds

Sprites are the visual objects on your stage. Each sprite has costumes (different appearances) and sounds (audio clips). Switching costumes creates animation. Playing sounds adds feedback.

Block Category Purpose
switch costume to [name] Looks Change the sprite's appearance to a specific costume
next costume Looks Cycle to the next costume -- use in a loop for walking animation
play sound [name] until done Sound Play a clip and wait for it to finish before continuing
start sound [name] Sound Play a clip without waiting -- script continues immediately
set size to (50)% Looks Scale the sprite -- useful for perspective effects

You can paint your own costumes in the built-in editor or import images. The editor supports both vector and bitmap modes. For animation, create multiple costumes with slight differences and cycle through them with next costume inside a loop with a short wait.

Key Takeaways

  • Visual programming teaches the same concepts as text-based coding -- loops, conditionals, variables, events -- without syntax barriers
  • Scratch 3 on the Pi implements real CS concepts: concurrency, message passing, state management
  • Events are program entry points -- every script starts with a hat block
  • Three loop types (forever, repeat N, repeat until) cover infinite, counted, and conditional iteration
  • Broadcasts enable decoupled sprite-to-sprite communication -- a real-world design pattern
  • Variables can be local (one sprite) or global (all sprites) -- this maps directly to scope in text languages
