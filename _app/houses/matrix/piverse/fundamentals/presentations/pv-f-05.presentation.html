The raspi-config Tool
Central configuration utility for the Raspberry Pi. Text-based menu interface. Run with sudo.
# Launch interactive menu $ sudo raspi-config # Non-interactive (scripting-friendly) $ sudo raspi-config nonint do_ssh 0 # Enable SSH $ sudo raspi-config nonint do_vnc 0 # Enable VNC $ sudo raspi-config nonint do_spi 0 # Enable SPI $ sudo raspi-config nonint do_i2c 0 # Enable I2C $ sudo raspi-config nonint do_hostname piverse $ sudo raspi-config nonint do_change_timezone America/New_York
Two Paths
Most settings can also be configured through the GUI "Raspberry Pi Configuration" tool in the Preferences menu. The terminal approach is preferred because it works over SSH and is scriptable.

raspi-config Menu Structure
Six main categories organize all Pi-specific settings.
1. System Options
Hostname, password, boot behavior (desktop vs. CLI), audio output, network at boot.
2. Display Options
Resolution, overscan, screen blanking, compositor settings.
3. Interface Options
SSH, VNC, SPI, I2C, Serial, 1-Wire, Remote GPIO. Hardware communication.
4. Performance
GPU memory split, overclock, fan control (Pi 5).
5. Localisation
Locale, timezone, keyboard layout, WLAN country code.
6. Advanced
Expand filesystem, network config, boot order (SD/USB/Network).
Slide 4 of 12
Interface Options
Enable and disable hardware communication protocols and remote access services.
SSH
Secure Shell remote terminal. Always enable. Required for headless access. ssh user@hostname.local
VNC
Remote desktop access. Enable when you need the GUI remotely. RealVNC is built in.
SPI
Serial Peripheral Interface. High-speed, short-distance. For TFT displays, ADCs, fast sensors.
I2C
Inter-Integrated Circuit. Two-wire bus. For sensors, OLEDs, PWM controllers. Multiple devices share SDA/SCL.
Serial Port
UART communication. GPIO 14 (TX), GPIO 15 (RX). For GPS, Arduino, serial consoles.
1-Wire
One-wire protocol. Primarily DS18B20 temperature sensors. Single data wire plus ground.

Localisation Settings
Timezone, locale, keyboard layout, and WLAN country -- get these right or face daily annoyances.
1Timezone: sudo raspi-config nonint do_change_timezone America/New_York -- critical for cron jobs, log timestamps, and any time-sensitive application.
2Locale: sudo raspi-config nonint do_change_locale en_US.UTF-8 -- sets language, number formats, and character encoding. UTF-8 handles international characters.
3Keyboard layout: If your @ key produces " or your | key does not work, the keyboard layout is wrong. Set it in raspi-config or via sudo dpkg-reconfigure keyboard-configuration.
4WLAN country: Required by law. Wi-Fi uses different channels and power levels in different countries. Setting the wrong country may prevent Wi-Fi from connecting or violate radio regulations.

Boot Options
Control what happens when the Pi starts up.
Desktop vs. CLI
Boot to desktop (default) or boot to command line only. Servers and headless Pis should boot to CLI to save RAM. Change in System Options > Boot / Auto Login.
Auto Login
Desktop auto-login boots straight to the desktop without a login screen. CLI auto-login drops to a terminal prompt already logged in. Disable auto-login for shared or security-sensitive Pis.
Boot Order (Pi 4/5)
In Advanced Options, set boot order: SD Card first, USB boot, or network boot (PXE). USB boot lets you boot from a fast SSD instead of a slow SD card.
Splash Screen
Enable or disable the rainbow splash screen and boot messages. Disable splash for kiosk displays where you want a clean visual transition from power-on to application.
Slide 7 of 12
GPU Memory Split
The Pi's RAM is shared between the CPU and GPU. You control the allocation.
# Set GPU memory (in MB) $ sudo raspi-config nonint do_memory_split 128 # Or edit config.txt directly $ sudo nano /boot/firmware/config.txt # Add or change: gpu_mem=128
Desktop / GUI Use
128 MB or 256 MB for the GPU. Desktop rendering, video playback, and camera processing need GPU memory. 128 MB is the default and works for most desktop use.
Headless / Server Use
16 MB minimum. If you run no desktop and no camera, give the GPU the minimum and dedicate the rest to the CPU. A server does not need GPU resources.
config.txt is the Pi's BIOS
The Pi has no BIOS/UEFI firmware menu. Instead, /boot/firmware/config.txt controls low-level hardware settings: GPU memory, overclocking, display rotation, HAT overlays, and more. Changes require a reboot to take effect.

systemd Service Management
systemd manages every service on the Pi -- from SSH to networking to your own custom services.
# Check service status $ sudo systemctl status ssh $ sudo systemctl status nginx # Start / stop / restart $ sudo systemctl start ssh $ sudo systemctl stop ssh $ sudo systemctl restart ssh # Enable at boot / disable $ sudo systemctl enable ssh # starts on every boot $ sudo systemctl disable ssh # no longer starts on boot # List all running services $ sudo systemctl list-units --type=service --state=running

Networking Configuration
Wi-Fi, Ethernet, static IPs, and hostname resolution.
# Check network interfaces $ ip addr show # Check Wi-Fi connection $ iwconfig wlan0 # Scan for Wi-Fi networks $ sudo iwlist wlan0 scan | grep ESSID # Connect to Wi-Fi via nmcli (NetworkManager) $ sudo nmcli device wifi connect "MyNetwork" password "MyPassword" # Set a static IP via nmcli $ sudo nmcli con mod "MyNetwork" ipv4.addresses 192.168.1.100/24 $ sudo nmcli con mod "MyNetwork" ipv4.gateway 192.168.1.1 $ sudo nmcli con mod "MyNetwork" ipv4.dns "8.8.8.8" $ sudo nmcli con mod "MyNetwork" ipv4.method manual $ sudo nmcli con up "MyNetwork"

Static IP vs. DHCP
When to use each and why it matters for Pi servers.
DHCP (Default)
The router assigns an IP address automatically. Easy, no configuration needed. But the address can change between reboots, breaking SSH connections and bookmarks. Fine for desktop use.
Static IP
You assign a fixed IP address that never changes. Required for servers (Pi-hole, web servers, Home Assistant) so clients can always find the Pi at the same address. Configure via nmcli or your router's DHCP reservation.
DHCP Reservation -- The Easy Path
Instead of configuring a static IP on the Pi, you can set a "DHCP reservation" on your router. The router always assigns the same IP to the Pi based on its MAC address. Same result, no Pi-side configuration needed.

Overclocking & Cooling
Push the Pi beyond stock speeds -- but manage the heat.
Overclocking
Pi 5 runs at 2.4 GHz stock. Overclock to 2.8-3.0 GHz via /boot/firmware/config.txt: arm_freq=2800. Requires active cooling and a good power supply. Voids the warranty concern is minimal -- the Pi has over-temperature protection.
Thermal Throttling
At 80 degrees C, the Pi starts reducing clock speed to prevent damage. At 85 degrees C, aggressive throttling kicks in. Check temperature: vcgencmd measure_temp. The Pi will not destroy itself -- it will just slow down.
Cooling Options
Passive heatsink (no noise, moderate cooling), active fan (best cooling, some noise), Pi 5 Active Cooler (official, designed to fit perfectly). For 24/7 servers or overclocked Pis, active cooling is strongly recommended.

Chapter 5 Summary
Your Pi is now fully configured and ready for real projects.
1raspi-config is the central configuration tool. Six categories: System, Display, Interfaces, Performance, Localisation, Advanced. Works interactively or non-interactively for scripting.
2Interface Options enable hardware protocols: SSH (remote terminal), VNC (remote desktop), SPI, I2C, Serial, 1-Wire. Enable only what you need.
3Localisation sets timezone, locale, keyboard, and WLAN country. Get these right first -- wrong settings cause daily frustration.
4systemd manages services. systemctl start/stop/restart/enable/disable controls every daemon on the system. Boot to CLI for servers, desktop for development.
5Networking: DHCP is default, static IP for servers. /boot/firmware/config.txt is the Pi's BIOS equivalent -- GPU memory, overclocking, display settings, HAT overlays.
