Your First C Program
Write, compile, run. Three steps every time -- C is a compiled language, not interpreted.
/* hello.c -- the classic first program */ #include <stdio.h> int main(void) { printf("Hello, Raspberry Pi!\n"); return 0; }
# Compile and run gcc hello.c -o hello ./hello # Output: Hello, Raspberry Pi!
#include
Preprocessor directive. <stdio.h> is the standard I/O header providing printf(), scanf(), file operations. Angle brackets = system header.
main()
Every C program starts here. Returns int -- 0 means success, non-zero means error. The OS reads this return code.
gcc
GNU C Compiler. Pre-installed on Pi OS. -o hello names the output binary. Without -o, output defaults to a.out.
Slide 3 of 12
Variables & Data Types
C is statically typed -- every variable must be declared with its type before use.
int
32-bit signed on Pi (ARM). Range: ~-2.1B to 2.1B. Use for counters, indices, general integers.
float / double
float: 32-bit, ~7 digits. double: 64-bit, ~15 digits. Use double for precision. float for memory-constrained code.
char
8-bit signed. Stores a single ASCII character or -128 to 127. Foundation of C strings: char name[] = "Pi";
long
At least 32 bits. On 64-bit Pi OS: 64 bits. Use for timestamps, large counts. long elapsed = 0;
unsigned
No negative values. Doubles the positive range. unsigned int count = 0; gives 0 to ~4.2 billion.
sizeof
sizeof(int) returns the size in bytes. On 32-bit Pi: int=4, char=1, double=8. Always verify -- sizes vary by architecture.
int count = 42; double temperature = 22.5; char grade = 'A'; unsigned int flags = 0xFF; printf("int is %zu bytes\n", sizeof(int));
Slide 4 of 12
printf: Formatted Output
printf uses format specifiers to control how values are printed -- type-safe and precise.
int pin = 17; double voltage = 3.3; char status = 'H'; printf("Pin %d: %.2f V (status: %c)\n", pin, voltage, status); // Output: Pin 17: 3.30 V (status: H) printf("Hex: 0x%X Octal: %o Binary mask: %08d\n", 255, 255, 11111111); // Output: Hex: 0xFF Octal: 377 Binary mask: 11111111
%d / %i
Signed integer. %05d = zero-padded 5 digits. %-10d = left-aligned in 10 chars.
%f / %e / %g
%f = fixed decimal, %.2f = 2 decimal places. %e = scientific notation. %g = auto-select shortest.
%s / %c
%s prints a C string (char array). %c prints a single character. %p prints a pointer address.
Mismatched format specifiers cause undefined behavior. Passing an int where %f expects a double does not just give wrong output -- it can crash your program. The compiler flag -Wall catches these errors.
Slide 5 of 12
Control Flow: if, for, while
Curly braces define blocks in C. Semicolons end every statement. Parentheses required around conditions.
Conditions
int temp = 75; if (temp > 100) { printf("CRITICAL\n"); } else if (temp > 50) { printf("WARNING\n"); } else { printf("Normal\n"); }
Loops
// for loop for (int i = 0; i < 10; i++) { printf("%d ", i); } // while loop int count = 0; while (count < 5) { printf("%d\n", count); count++; }
Common Bug: = vs ==
if (x = 5) assigns 5 to x and is always true. if (x == 5) compares. The single = is a silent logic error that compiles without warning unless you use -Wall.
switch/case
Tests one variable against constants. Always include break; -- without it execution falls through to the next case. default: handles unexpected values.
Slide 6 of 12
Pointers: Memory Addresses
A pointer stores the memory address of another variable. This is how C gives you direct hardware access.
int value = 42; int *ptr = &value; // ptr holds the address of value printf("Value: %d\n", value); // 42 printf("Address: %p\n", ptr); // 0x7fff5e8c printf("Via ptr: %d\n", *ptr); // 42 (dereference) *ptr = 99; // modify value through the pointer printf("Value: %d\n", value); // 99
& (address-of)
&value returns the memory address where value is stored. This is what you assign to a pointer variable.
* (dereference)
*ptr accesses the value at the address the pointer holds. "Go to this address and read/write what is there."
Why Pointers Matter
Hardware registers are memory addresses. GPIO pins on the Pi are controlled by writing to specific addresses. Pointers are how C talks to hardware directly.
Slide 7 of 12
Arrays & Strings
Arrays are contiguous memory blocks. C strings are null-terminated char arrays.
// Array declaration int readings[5] = {512, 480, 530, 495, 510}; // Iterate and average int sum = 0; for (int i = 0; i < 5; i++) { sum += readings[i]; } double avg = (double)sum / 5.0; // C strings char hostname[] = "raspberrypi"; // 12 bytes (11 chars + '\0') printf("Host: %s, length: %zu\n", hostname, strlen(hostname));
No Bounds Checking
C does not check array bounds. readings[10] in a 5-element array reads random memory. Buffer overflows are a major security vulnerability class.
Null Terminator
Every C string ends with '\0' (byte value 0). String functions like strlen(), strcpy(), strcmp() rely on this terminator to know where the string ends.
Slide 8 of 12
Structs: Custom Data Types
Structs group related variables into a single unit -- C's version of a simple object.
typedef struct { int pin; double temperature; double humidity; char label[32]; } Sensor; // Create and use Sensor dht = {4, 22.5, 45.0, "Living Room"}; printf("%s: %.1fC, %.0f%%\n", dht.label, dht.temperature, dht.humidity); // Pointer to struct Sensor *sp = &dht; sp->temperature = 23.1; // arrow operator for pointer access
typedef
typedef struct {...} Name; creates a type alias so you write Sensor s; instead of struct Sensor s;. Cleaner code.
Dot vs Arrow
s.field accesses through a variable. ptr->field accesses through a pointer. The arrow is shorthand for (*ptr).field.
Real Use
Linux kernel code is full of structs. Device configurations, file descriptors, network packets -- all represented as structs in C.
Slide 9 of 12
Memory Management
C gives you manual control over memory. With that power comes responsibility -- every malloc needs a free.
#include <stdlib.h> // Allocate array of 100 integers on the heap int *data = malloc(100 * sizeof(int)); if (data == NULL) { fprintf(stderr, "Out of memory\n"); return 1; } // Use the memory for (int i = 0; i < 100; i++) { data[i] = i * 2; } // Free when done -- or you have a memory leak free(data); data = NULL; // prevent use-after-free
Stack vs Heap
Local variables live on the stack (automatic, fast, limited size). malloc() allocates on the heap (manual, flexible, must free). Stack is default; heap is for dynamic sizes.
Memory Leaks
Forgetting to free() allocated memory causes leaks. In a long-running Pi program, leaks slowly consume all RAM until the OS kills your process.
valgrind
valgrind ./myprogram detects memory leaks, use-after-free, and buffer overflows. Essential debugging tool on the Pi.
Slide 10 of 12
Makefiles: Build Automation
When your project has multiple files, Makefiles automate compilation so you just type "make".
# Makefile CC = gcc CFLAGS = -Wall -Wextra -O2 sensor_app: main.o sensor.o display.o $(CC) $(CFLAGS) -o sensor_app main.o sensor.o display.o main.o: main.c sensor.h display.h $(CC) $(CFLAGS) -c main.c sensor.o: sensor.c sensor.h $(CC) $(CFLAGS) -c sensor.c display.o: display.c display.h $(CC) $(CFLAGS) -c display.c clean: rm -f *.o sensor_app
-Wall -Wextra
Enable all warnings. Catches type mismatches, unused variables, missing returns. Always compile with warnings on -- they find bugs before you do.
Incremental Builds
Make only recompiles files that changed. In a 50-file project, editing one file recompiles one .o instead of all 50. Saves minutes on the Pi.
make clean
Convention: make clean deletes all compiled files. Useful when switching compiler flags or debugging a broken build.
Slide 11 of 12
C vs Python
Different tools for different jobs. Know when to use each on the Pi.
C Strengths
10-100x faster execution. Direct hardware/memory access. No runtime overhead. Predictable timing for real-time tasks. Tiny binaries. Runs without an interpreter.
Python Strengths
Faster development time. Huge library ecosystem. No compilation step. Dynamic typing. Easier string/file handling. Built-in data structures (dict, list, set).
Use C When
Performance is critical. Real-time requirements. Kernel modules. Device drivers. Bare-metal microcontroller code. Memory-constrained environments.
Use Python When
Rapid prototyping. Web servers. Data processing. Automation scripts. GPIO with gpiozero. When development speed matters more than execution speed.
Many Pi projects use both: Python for the high-level logic and user interface, C for performance-critical routines called via ctypes or compiled as shared libraries.
Slide 12 of 12
Key Takeaways
Introducing C on Linux -- the systems language that powers your Pi.
1C is compiled, not interpreted. Write .c file, compile with gcc, run the binary. The compilation step catches errors before execution.
2Static typing prevents bugs. Every variable has a declared type. The compiler enforces type safety at build time.
3Pointers give you hardware access. Memory addresses are first-class values. This is how you control GPIO registers, DMA, and memory-mapped I/O.
4Manual memory management. malloc/free give you control but require discipline. Every allocation must have a corresponding free.
5Always compile with -Wall. Warnings are bugs waiting to happen. Fix every warning before testing your program.
