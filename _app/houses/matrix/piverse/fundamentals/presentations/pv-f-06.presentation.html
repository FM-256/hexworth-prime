Visual Programming with Scratch
Block-based programming on the Raspberry Pi — Events • Loops • Conditionals • Sprites • Games
Before writing a single line of Python or C, visual programming teaches you the fundamental structures every language shares. Scratch removes syntax barriers and lets you focus purely on logic.

Why Visual Programming Matters
Block-based environments teach real computer science without syntax errors getting in the way.
No Syntax Errors
Blocks snap together like puzzle pieces. If the shapes do not fit, the connection is invalid. You cannot make a typo that crashes your program.
Real CS Concepts
Scratch implements concurrency (multiple sprites running scripts simultaneously), message passing (broadcasts), and state management (variables and lists).
Direct Transfer
Every concept you learn in Scratch -- loops, conditionals, variables, events -- maps directly to Python, C, and every other language. You are learning programming, not just a tool.
Scratch was developed at MIT's Media Lab. The Raspberry Pi Foundation includes Scratch 3 in every Pi OS installation because it is the recommended entry point for programming on the Pi.

The Scratch 3 Interface
Launch from: Menu > Programming > Scratch 3. The workspace is divided into four main areas.
Block Palette
Color-coded categories: Motion, Looks, Sound, Events, Control, Sensing, Operators, Variables, My Blocks.
Scripts Area
Drag blocks here to build programs. Each sprite has its own independent script area.
Stage
480 x 360 pixel canvas. Coordinate system: x from -240 to 240, y from -180 to 180. Center is (0, 0).
Sprite Pane
Thumbnails of all sprites. Click to select and edit scripts. Add new sprites from the library or paint your own.
Costumes Tab
Edit sprite appearances. Multiple costumes enable animation by switching between them rapidly.
Sounds Tab
Record or import audio clips. Sprites can play sounds triggered by events or conditions.

Events: Starting Your Programs
Every Scratch program begins with an event block -- a "hat" block that defines when the script should execute.
when green flag clicked
Fires when the project starts. Most scripts begin here. Equivalent to a main() function in C or Python.
when [space] key pressed
Fires when a specific keyboard key is pressed. Used for player input in games -- jump, shoot, move.
when this sprite clicked
Fires when the user clicks on the sprite. Used for interactive UI elements and clickable game objects.
when I receive [message]
Fires when another sprite sends a broadcast. This is inter-sprite communication -- one sprite tells others to act.
A single sprite can have multiple event-driven scripts running simultaneously. This is real concurrency -- each script stack executes independently. Event-driven programming is how real software works.
Slide 5 of 12
Loops: Repetition
Loops repeat actions without duplicating blocks. Scratch has three loop types matching patterns in every language.
forever
Runs until the program stops. Game loops and animation loops use this. Equivalent to while True: in Python or while(1){} in C.
repeat (10)
Runs exactly N times. Use for drawing shapes, counted iterations. Equivalent to for i in range(10): in Python.
repeat until <>
Checks condition before each iteration, stops when true. Use for waiting on events or collisions. Equivalent to while not cond: in Python.
The forever loop is the most common in Scratch games -- it runs the game logic every frame. Inside it, you check inputs, update positions, detect collisions, and redraw sprites.
Slide 6 of 12
Conditionals: Making Decisions
Let your program choose between actions based on whether a condition is true or false.
if <> then
Execute enclosed blocks only if the condition is true. Use sensing blocks like touching [edge]? or operator blocks like <, >, =.
if <> then / else
Two branches: one executes when true, the other when false. Every decision in your game needs this -- hit or miss, alive or dead, left or right.
Comparison Operators
< less than, > greater than, = equal. Compare variables, positions, or sensor values.
Logic Operators
and, or, not. Combine conditions: <touching [edge]?> and <(speed) > 5>.
Guard Clause Pattern
Place an if <touching [edge]?> then inside a forever loop to bounce sprites off walls. Checks boundaries every frame.
Slide 7 of 12
Variables: Storing State
Variables hold values that change during your program -- scores, lives, timers, positions.
Score Tracking
Create a "score" variable. Use change [score] by (1) when the player catches something. Display it on the stage by checking the variable checkbox.
Timer / Countdown
Set "time" to 30 at start. Use repeat until <(time) = 0> with wait 1 second and change [time] by (-1) inside.
Lives System
Set "lives" to 3 at start. Decrease on collision. Use if <(lives) = 0> then stop [all] as your game-over condition.
Scope
Variables can be scoped to a single sprite (local) or shared across all sprites (global). Choose scope when creating the variable in the Variables palette.
Variables in Scratch work exactly like variables in Python and C. The concept is identical -- only the interface changes. A score counter in Scratch becomes score = score + 1 in Python.
Slide 8 of 12
Sprites & Costumes
Sprites are the actors in your program. Each has its own scripts, costumes, sounds, position, and direction.
Multiple Sprites
Each sprite runs its own scripts independently. A game might have a player sprite, enemy sprites, projectile sprites, and a background sprite -- all executing concurrently.
Costume Animation
Switch between costumes to animate. Use next costume inside a forever loop with a small wait. Walking, jumping, and explosion animations all work this way.
Cloning
create clone of [myself] spawns a copy at runtime. Use when I start as a clone to give clones behavior. Perfect for bullets, particles, and enemies.
Cloning in Scratch is equivalent to object instantiation in Python or C++. Each clone is an independent instance with its own position, variables, and execution state.
Slide 9 of 12
Broadcasts: Sprite Communication
Broadcasts let sprites send messages to each other -- the foundation of modular, event-driven design.
broadcast [message]
Sends a named message to all sprites. Any sprite with a when I receive [message] block will execute its script. The sender continues immediately.
broadcast [message] and wait
Same as broadcast, but the sender pauses until all receivers finish. Use for cutscenes, level transitions, and sequential events.
Game State Management
Broadcast "game over" when lives reach zero. All sprites receive it and can play death animations, hide, or show a score screen independently.
Level Transitions
Broadcast "next level" to reset enemy positions, change the backdrop, increase difficulty, and update the level variable -- all from a single message.
Decoupled Design
Sprites do not need to know about each other. They only listen for messages. This is the Observer pattern used in professional software engineering.
Slide 10 of 12
Building a Game Project
Combine everything into a simple catch game: a falling object, a player paddle, scoring, and a game-over condition.
1. Player Sprite
Forever loop: if <key [left] pressed?> then change x by (-10). Same for right. Stays at bottom of stage. Guard clause prevents going off-screen.
2. Falling Object
Set to random x at top. Forever loop: change y by (-5). If touching player, increase score and reset to top. If y < -170, lose a life and reset.
3. Scoring System
Variables: score (starts at 0), lives (starts at 3). Display both on stage. Increment score on catch. Decrement lives on miss.
4. Game Over
When lives = 0, broadcast "game over". Player and falling object hide. A game-over sprite shows final score. Broadcast handles all cleanup.
This game uses every concept from this chapter: events (green flag), loops (forever), conditionals (if touching), variables (score, lives), sprites (player, object), and broadcasts (game over).

From Scratch to Text Code
Every Scratch block has a direct equivalent in Python, C, and other text languages.
forever
Python: while True:
C: while(1) {}
repeat (10)
Python: for i in range(10):
C: for(i=0;i<10;i++)
if <> then / else
Python: if cond: / else:
C: if (cond) {} else {}
set [x] to (0)
Python: x = 0
C: int x = 0;
change [x] by (1)
Python: x += 1
C: x++;
broadcast [msg]
Python: function call / event
C: callback / signal

Key Takeaways
Visual Programming with Scratch -- the concepts that transfer to every language.
1Scratch teaches real programming. Sequencing, branching, iteration, events, variables, and concurrency are identical across all languages.
2Events drive execution. Programs respond to user input, timers, and messages. This is the same event-driven model used in web browsers, mobile apps, and embedded systems.
3Three loop types cover all repetition. Forever for continuous, repeat(N) for counted, repeat-until for conditional. Master these and loops in any language are trivial.
4Broadcasts decouple sprites. Message passing between components is a professional design pattern (Observer). It keeps your code modular and maintainable.
5Games combine everything. A simple catch game uses events, loops, conditionals, variables, sprites, and broadcasts -- all the fundamentals in one project.
