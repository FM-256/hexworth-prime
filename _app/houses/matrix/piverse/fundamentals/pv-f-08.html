Why C Matters

C is the language of the system. The Linux kernel is written in C. Device drivers are written in C. The Python interpreter itself is written in C (CPython). When you need direct hardware access, maximum performance, or need to understand what the computer is actually doing, you need C.

Performance C compiles directly to machine code. No interpreter, no virtual machine. A C program on the Pi runs 10-100x faster than equivalent Python for CPU-bound tasks.
Hardware Access C can read and write memory addresses directly. This is how device drivers and GPIO libraries work at the lowest level.
Portability C code compiles on every platform with a C compiler. The same source runs on Pi, desktop, server, and embedded systems.
Understanding Learning C teaches you what the computer actually does -- memory allocation, pointer arithmetic, stack frames. This knowledge makes you better in every language.

Your First C Program

Install the compiler if it is not already installed, then write, compile, and run your first program. The gcc compiler is the GNU Compiler Collection -- it translates C source code into executable machine code.

// Install gcc (usually pre-installed on Raspberry Pi OS) $ sudo apt install gcc // Create hello.c $ nano hello.c
/* hello.c -- your first C program */ #include <stdio.h> int main(void) { printf("Hello from the Raspberry Pi!\n"); return 0; }
// Compile and run $ gcc -o hello hello.c $ ./hello Hello from the Raspberry Pi!

Every C program starts at the main() function. The #include <stdio.h> directive brings in standard I/O functions like printf. The return 0 tells the operating system the program finished successfully (exit code 0). The -o hello flag names the output executable.

Variables and Types

Unlike Python, C requires you to declare the type of every variable before you use it. This is static typing -- the compiler checks types at compile time, not at runtime. This catches errors early and enables performance optimization.

/* Variables must be declared with their type */ int age = 25; /* integer (32-bit on Pi) */ float temperature = 36.6f; /* single-precision float */ double pi = 3.14159265; /* double-precision float */ char grade = 'A'; /* single character */ char name[] = "Pi User"; /* string (array of chars) */ /* Constants */ const int MAX_PINS = 40; /* printf format specifiers */ printf("Age: %d\n", age); /* %d = integer */ printf("Temp: %.1f\n", temperature);/* %.1f = float, 1 decimal */ printf("Pi: %lf\n", pi); /* %lf = double */ printf("Grade: %c\n", grade); /* %c = character */ printf("Name: %s\n", name); /* %s = string */

float 4 bytes ~7 digits precision float (Python uses double)

Input with scanf

The scanf function reads formatted input from the user. It uses the same format specifiers as printf but requires the address of the variable (using the & operator) to store the result.

/* Reading user input */ #include <stdio.h> int main(void) { int pin_number; float voltage; printf("Enter GPIO pin number: "); scanf("%d", &pin_number); /* & gives the address of pin_number */ printf("Enter voltage: "); scanf("%f", &voltage); printf("Pin %d set to %.2fV\n", pin_number, voltage); return 0; }
The & Operator:

In scanf, the & is critical. It passes the memory address of the variable so scanf knows where to store the value. Forgetting & is a common bug that causes crashes or corrupted data. Strings (char arrays) do not need & because the array name is already an address.

Pointers: Addresses and Dereferencing

A pointer is a variable that stores a memory address. Pointers are what make C powerful -- and dangerous. They enable direct memory manipulation, efficient data passing, and hardware register access. Every GPIO library you use on the Pi works through pointers internally.

/* Pointer basics */ int value = 42; int *ptr = &value; /* ptr holds the address of value */ printf("Value: %d\n", value); /* 42 */ printf("Address: %p\n", &value); /* 0x7efff5bc (example) */ printf("Pointer: %p\n", ptr); /* same address */ printf("Dereferenced: %d\n", *ptr);/* 42 -- read value at address */ *ptr = 100; /* write to the address -- value is now 100 */ printf("Value after: %d\n", value);/* 100 */
Syntax Meaning
int *ptrDeclare a pointer to an int
&valueGet the address of a variable
*ptrDereference: read/write the value at the address
ptr++Pointer arithmetic: move to next element (advances by sizeof type)

Structs: Grouping Related Data

A struct groups multiple variables (of different types) under a single name. This is C's way of creating custom data types -- similar to a Python dictionary or class, but with fixed fields known at compile time.

/* Define a struct for a GPIO pin */ struct gpio_pin { int number; char mode[10]; /* "INPUT" or "OUTPUT" */ int value; /* HIGH=1, LOW=0 */ float voltage; }; int main(void) { /* Create and initialize a struct */ struct gpio_pin led = {17, "OUTPUT", 1, 3.3}; printf("Pin %d: %s, value=%d, %.1fV\n", led.number, led.mode, led.value, led.voltage); /* Modify a field */ led.value = 0; printf("LED off: value=%d\n", led.value); /* typedef for cleaner syntax */ typedef struct { char model[32]; int ram_mb; int cores; } PiBoard; PiBoard pi5 = {"Raspberry Pi 5", 8192, 4}; printf("%s: %dMB RAM, %d cores\n", pi5.model, pi5.ram_mb, pi5.cores); return 0; }

Header Files and Makefiles

Real C projects split code across multiple files. Header files (.h) declare function prototypes and struct definitions. Source files (.c) contain the implementations. Makefiles automate the compilation of multi-file projects.

/* gpio.h -- header file (declarations) */ #ifndef GPIO_H #define GPIO_H struct gpio_pin { int number; int value; }; void gpio_init(struct gpio_pin *pin, int num); void gpio_write(struct gpio_pin *pin, int val); int gpio_read(struct gpio_pin *pin); #endif
/* gpio.c -- implementation */ #include <stdio.h> #include "gpio.h" void gpio_init(struct gpio_pin *pin, int num) { pin->number = num; pin->value = 0; printf("GPIO %d initialized\n", num); } void gpio_write(struct gpio_pin *pin, int val) { pin->value = val; printf("GPIO %d set to %d\n", pin->number, val); } int gpio_read(struct gpio_pin *pin) { return pin->value; }
/* main.c -- uses the gpio module */ #include <stdio.h> #include "gpio.h" int main(void) { struct gpio_pin led; gpio_init(&led, 17); gpio_write(&led, 1); printf("LED state: %d\n", gpio_read(&led)); return 0; }
# Makefile CC = gcc CFLAGS = -Wall -Wextra all: main main: main.o gpio.o $(CC) $(CFLAGS) -o main main.o gpio.o main.o: main.c gpio.h $(CC) $(CFLAGS) -c main.c gpio.o: gpio.c gpio.h $(CC) $(CFLAGS) -c gpio.c clean: rm -f *.o main
# Build and run $ make $ ./main GPIO 17 initialized GPIO 17 set to 1 LED state: 1
Compiler Flags:

-Wall enables all standard warnings. -Wextra enables additional warnings. Always compile with these flags -- they catch bugs before they become runtime crashes. On the Pi, also consider -O2 for optimized builds.

C vs Python: When to Use Which

C and Python are not competitors -- they serve different roles. Understanding the tradeoffs lets you choose the right tool for each task on your Pi.

Dimension C Python
Speed Compiled to native machine code. 10-100x faster for CPU-bound work. Interpreted. Slower for computation but fast enough for most Pi projects.
Memory Manual management. You allocate and free memory yourself. Automatic garbage collection. Higher memory overhead.
Development Speed Slower to write. More boilerplate. Compilation step required. Faster to write. Less code. Run immediately.
Safety Manual. Buffer overflows, null pointers, memory leaks possible. Managed. Exceptions, bounds checking, garbage collection.
Use on Pi Kernel modules, drivers, performance-critical GPIO, real-time. Scripting, web servers, GPIO prototyping, data processing.
Rule of Thumb:

Prototype in Python, optimize in C. Use Python for rapid development and most Pi projects. Use C when you need direct hardware access, real-time performance, or are building something that will run on a microcontroller like the Pico.

Key Takeaways

  • C is the language of the system -- kernel, drivers, and hardware interfaces are written in C
  • gcc compiles C source to native machine code; always use -Wall -Wextra for warnings
  • C requires explicit type declarations -- the compiler catches type errors at build time
  • Pointers store memory addresses; & gets an address, * dereferences it
  • Structs group related data into custom types -- C's version of objects
  • Header files separate declarations from implementation; Makefiles automate multi-file builds
  • Prototype in Python, optimize in C -- choose the right tool for each task
