I2C and SPI
Bus Protocols | OLED Display | Multi-Device Communication
Until now, your projects used simple digital and analog signals -- single wires carrying on/off or voltage levels. I2C and SPI are structured communication protocols that let the Pico talk to complex peripherals: OLED displays, real-time clocks, memory chips, and hundreds of breakout boards. Two wires (I2C) or four wires (SPI) open the entire ecosystem.

I2C Protocol
Two wires, many devices. The Pico is master, peripherals are slaves.
SDA (Serial Data)
Bidirectional data line. Shared by all devices. Open-drain with pull-up resistors (usually built into breakout boards).
SCL (Serial Clock)
Clock generated by the master (Pico). Slaves read on clock edges. Typical speeds: 100 kHz (standard), 400 kHz (fast).
Addressing
Each I2C device has a unique 7-bit address (0x00-0x7F). The master sends the address before each transaction. Only the addressed device responds. This is how 127 devices can share two wires without collisions.

I2C Scanning
Before talking to a device, find it on the bus.
from machine import I2C, Pin i2c = I2C(0, sda=Pin(0), scl=Pin(1), freq=400000) devices = i2c.scan() print(f"Found {len(devices)} device(s):") for addr in devices: print(f" 0x{addr:02X}") # Typical output: # Found 1 device(s): # 0x3C (SSD1306 OLED)
No Devices Found?
Check wiring (SDA to SDA, SCL to SCL, not swapped). Verify power (3.3V or 5V depending on device). Check that pull-up resistors are present. Try a different I2C bus (bus 0 vs bus 1). Use the scan as your first debugging step.

OLED Display (SSD1306)
128x64 pixel OLED over I2C. The most common Pico display module.
from machine import I2C, Pin from ssd1306 import SSD1306_I2C i2c = I2C(0, sda=Pin(0), scl=Pin(1), freq=400000) oled = SSD1306_I2C(128, 64, i2c) oled.fill(0) # Clear screen oled.text("Hello Pico!", 0, 0) # Row 0 oled.text("Temp: 26.3C", 0, 16) # Row 16 oled.show() # Push buffer to display
Driver Library
The ssd1306 module is not built into MicroPython. Install it: mpremote mip install ssd1306 or copy the ssd1306.py file to the Pico. The driver handles I2C commands for you -- you just call text(), pixel(), fill(), and show().

I2C Read/Write
Low-level I2C operations for devices without a driver library.
# Write bytes to device at address 0x3C i2c.writeto(0x3C, bytes([0x00, 0xAE])) # Read 2 bytes from device at address 0x68 data = i2c.readfrom(0x68, 2) # Write to a specific register, then read i2c.writeto(0x68, bytes([0x00])) # Set register pointer data = i2c.readfrom(0x68, 7) # Read 7 bytes # Combined write-then-read (register access pattern) i2c.readfrom_mem(0x68, 0x00, 7) # Same result

SPI Protocol
Four wires, full-duplex, very fast. Used for displays, SD cards, and high-speed peripherals.
MOSI (Master Out Slave In)
Data from Pico to peripheral. One direction only.
MISO (Master In Slave Out)
Data from peripheral to Pico. Simultaneous with MOSI -- full duplex.
SCK (Serial Clock)
Clock from master. Speeds up to 62.5 MHz on the Pico. Orders of magnitude faster than I2C.
CS (Chip Select)
One CS pin per device. Pull LOW to select, HIGH to deselect. No addresses needed -- hardware selection.
Slide 7 of 12
I2C vs. SPI
Different tools for different jobs. Choose based on your project requirements.
Choose I2C When
Many devices on one bus. Short distances. Low-to-medium speed is acceptable. Fewer wires matter (2 vs 4+). Most sensors and small displays use I2C.
Choose SPI When
Speed matters (displays, SD cards, flash memory). Full-duplex needed. Fewer devices (each needs a CS pin). Distance can be longer than I2C.
Speed Comparison
I2C standard mode: 100 kbps. I2C fast mode: 400 kbps. SPI on Pico: up to 62.5 Mbps. SPI is ~150x faster at maximum settings. For a 128x64 OLED, I2C is fine. For a 320x240 color TFT display, SPI is essential.

SPI in MicroPython
Initialize the bus, manage CS manually, send and receive data.
from machine import SPI, Pin spi = SPI(0, baudrate=1000000, # 1 MHz polarity=0, phase=0, # Mode 0 (most common) sck=Pin(2), mosi=Pin(3), miso=Pin(4)) cs = Pin(5, Pin.OUT, value=1) # CS starts HIGH # Send data cs.value(0) # Select device spi.write(bytes([0x01, 0x02])) cs.value(1) # Deselect # Read data cs.value(0) buf = bytearray(4) spi.readinto(buf) cs.value(1)

Multi-Device I2C Bus
Multiple devices on the same two wires. Each responds only to its own address.
# Same I2C bus, different addresses i2c = I2C(0, sda=Pin(0), scl=Pin(1), freq=400000) # OLED display at 0x3C oled = SSD1306_I2C(128, 64, i2c) # BME280 sensor at 0x76 data = i2c.readfrom_mem(0x76, 0xF7, 8) # DS3231 RTC at 0x68 time_data = i2c.readfrom_mem(0x68, 0x00, 7) # All three share SDA and SCL # Total wires: 4 (SDA, SCL, VCC, GND)
Address Conflicts
If two devices have the same address, they collide. Most devices have an address pin or solder bridge to select an alternate address. The SSD1306 can be 0x3C or 0x3D. The Pico also has two I2C buses (bus 0 and bus 1) for complete separation.
Slide 10 of 12
Pico Pin Mapping
Which pins can do I2C and SPI on the Pico.
I2C Bus 0
SDA: GP0, GP4, GP8, GP12, GP16, GP20. SCL: GP1, GP5, GP9, GP13, GP17, GP21. Pick any matching pair.
I2C Bus 1
SDA: GP2, GP6, GP10, GP14, GP18, GP26. SCL: GP3, GP7, GP11, GP15, GP19, GP27. Independent from Bus 0.
SPI Bus 0
SCK: GP2, GP6, GP18. MOSI: GP3, GP7, GP19. MISO: GP0, GP4, GP16. CS: any GPIO.
SPI Bus 1
SCK: GP10, GP14. MOSI: GP11, GP15. MISO: GP8, GP12. CS: any GPIO. Independent from Bus 0.

OLED Temperature Display
Combining chapters 8 and 10: read temperature, display on OLED.
from machine import ADC, I2C, Pin from ssd1306 import SSD1306_I2C import time sensor = ADC(4) i2c = I2C(0, sda=Pin(0), scl=Pin(1), freq=400000) oled = SSD1306_I2C(128, 64, i2c) while True: raw = sensor.read_u16() v = raw * 3.3 / 65535 tc = 27 - (v - 0.706) / 0.001721 oled.fill(0) oled.text("PiVerse Temp", 16, 0) oled.text(f"{tc:.1f} C", 32, 28) oled.show() time.sleep(1)

Key Takeaways: I2C and SPI
Two protocols that connect the Pico to the hardware ecosystem.
1I2C uses two wires (SDA, SCL) with addresses. Up to 127 devices on one bus. 400 kHz fast mode. Best for sensors and small displays.
2SPI uses four wires (MOSI, MISO, SCK, CS). Full-duplex, up to 62.5 MHz. Best for high-speed peripherals: TFT displays, SD cards, flash memory.
3i2c.scan() is your first debugging step. If scan finds no devices, check wiring and power before writing any driver code.
4Driver libraries simplify device communication. The SSD1306 OLED driver gives you text() and show() instead of raw byte manipulation.
5The Pico has two buses for each protocol. Use separate buses when devices have address conflicts or when you need to isolate high-speed and low-speed peripherals.
