Connecting to WiFi
Activate the wireless interface, provide SSID and password, wait for DHCP.
import network import time wlan = network.WLAN(network.STA_IF) wlan.active(True) wlan.connect("YourSSID", "YourPassword") # Wait for connection (timeout after 10 seconds) timeout = 10 while not wlan.isconnected() and timeout > 0: time.sleep(1) timeout -= 1 if wlan.isconnected(): config = wlan.ifconfig() print(f"IP: {config[0]}") else: print("Connection failed")
Pico W Only
The original Pico does not have the CYW43439 wireless chip. This code only works on the Pico W. The network module will raise an error on a standard Pico.

TCP/IP Basics
The Pico W speaks the same network protocols as your laptop and phone.
IP Address
Unique identifier on the network. DHCP assigns one automatically (e.g., 192.168.1.42). Use wlan.ifconfig() to check.
Port
A number (0-65535) that identifies which application on a device to talk to. HTTP uses port 80. HTTPS uses 443. You pick the port for your server.
Socket
The programming interface for network communication. Create a socket, connect or listen, send and receive data. Like a phone call -- dial, talk, hang up.
HTTP
Hypertext Transfer Protocol. Request-response model. Client sends GET/POST, server responds with headers + body. The language of the web.

Making HTTP Requests
Fetch data from the internet -- APIs, time servers, weather data.
import urequests # GET request to a JSON API response = urequests.get("http://worldtimeapi.org/api/ip") if response.status_code == 200: data = response.json() print(f"Time: {data['datetime']}") response.close() # Always close! # POST request (send sensor data) import json payload = json.dumps({"temp": 26.3, "device": "pico-01"}) r = urequests.post("http://yourserver.com/api/data", data=payload, headers={"Content-Type": "application/json"}) r.close()
Memory Warning
Always call response.close() after reading the data. The Pico W has limited RAM. Unclosed responses leak sockets and memory. After 5-10 unclosed requests, the Pico runs out of sockets and new connections fail.

Building a Web Server
Serve sensor data on a web page. Any device on your network can view it in a browser.
import socket addr = socket.getaddrinfo("0.0.0.0", 80)[0][-1] s = socket.socket() s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1) s.bind(addr) s.listen(1) print(f"Listening on {wlan.ifconfig()[0]}:80") while True: cl, addr = s.accept() request = cl.recv(1024).decode() # Send response cl.send("HTTP/1.1 200 OK\r\n") cl.send("Content-Type: text/html\r\n\r\n") cl.send("<h1>Pico W Server</h1>") cl.close()

Dynamic HTML Response
Embed live sensor readings in the HTML response.
def build_page(temp_c, temp_f): return f"""<!DOCTYPE html> <html><head><meta charset="UTF-8"> <meta http-equiv="refresh" content="5"> <title>Pico W Sensor</title> <style>body{{font-family:sans-serif;background:#0d0a0c; color:#e0e0e0;text-align:center;padding:40px}} .temp{{font-size:3rem;color:#c51a4a}}</style> </head><body> <h1>Pico W Temperature</h1> <div class="temp">{temp_c:.1f} C / {temp_f:.1f} F</div> <p>Auto-refreshes every 5 seconds</p> </body></html>"""
Auto-Refresh
The meta http-equiv="refresh" content="5" tag makes the browser reload the page every 5 seconds. No JavaScript needed. Each reload triggers a new HTTP request, and the server sends fresh sensor data. Simple but effective for dashboards.

Connection Resilience
WiFi drops. Handle it gracefully instead of crashing.
def ensure_wifi(ssid, password): wlan = network.WLAN(network.STA_IF) if not wlan.isconnected(): print("Reconnecting...") wlan.active(True) wlan.connect(ssid, password) retries = 10 while not wlan.isconnected() and retries > 0: time.sleep(1) retries -= 1 return wlan.isconnected() # In main loop: if not ensure_wifi(SSID, PASS): print("WiFi down -- logging locally") # Fall back to file logging

Credential Management
Never hardcode WiFi passwords in your main script.
# secrets.py (separate file, never share) SSID = "MyNetwork" PASSWORD = "MyPassword123" # main.py try: from secrets import SSID, PASSWORD except ImportError: print("No secrets.py found!") print("Create secrets.py with SSID and PASSWORD") raise SystemExit
Security Practice
Keep credentials in a separate secrets.py file. If you share your code, remove or exclude secrets.py. This is the same principle as .env files in web development. Never commit passwords to version control.

NTP Time Sync
Use WiFi to get the real date and time from a network time server.
import ntptime import time # Sync Pico's internal clock with NTP server ntptime.settime() # Now time.localtime() returns real date/time t = time.localtime() print(f"{t[0]}-{t[1]:02d}-{t[2]:02d} {t[3]:02d}:{t[4]:02d}:{t[5]:02d}") # Output: 2026-04-21 14:30:15
Real Timestamps
In Chapter 9, data logging used elapsed seconds because the Pico has no RTC. With WiFi, you can sync to NTP on boot and use real calendar timestamps in your logs. This makes data analysis much easier.

IoT Patterns
Common architectures for connected sensor projects.
Push Model
Pico posts sensor data to a cloud server at regular intervals. Server stores and displays. Used by commercial IoT platforms.
Pull Model
Pico runs a web server. Users browse to its IP address to see data. No cloud needed. Works on local network only.
Hybrid
Pico logs to flash locally, pushes to cloud when WiFi is available. Best of both worlds. Survives network outages.

Key Takeaways: WiFi Networking
From isolated device to connected IoT node.
1network.WLAN(network.STA_IF) connects to WiFi. Provide SSID and password. Wait for DHCP. Check isconnected() before using the network.
2urequests makes HTTP calls. GET fetches data. POST sends data. Always close the response to free sockets and memory.
3A web server is ~15 lines of socket code. Bind to port 80, accept connections, send HTML. Any browser on the network can view your sensor data.
4Handle WiFi drops gracefully. Check connection before every network call. Reconnect automatically. Fall back to local logging when offline.
5Keep credentials in secrets.py. Never hardcode passwords. Never share or commit credential files.
