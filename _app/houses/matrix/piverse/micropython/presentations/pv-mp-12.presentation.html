BLE vs. Classic Bluetooth
Same name, completely different protocols.
Bluetooth Classic
Continuous streaming: audio, file transfer. Higher power. Persistent connection. Think: wireless headphones, phone calls.
Bluetooth Low Energy
Short bursts of data: sensor readings, button presses. Very low power. Coin cell battery lasts months. Think: fitness tracker, temperature beacon.
Pico W Supports BLE Only
The CYW43439 chip on the Pico W supports BLE (Bluetooth 5.2), not Classic Bluetooth. You cannot stream audio or transfer files. You can exchange small amounts of data -- perfect for sensor readings, control commands, and notifications.
Slide 3 of 12
GATT Architecture
Generic Attribute Profile: the structure of BLE data exchange.
1Profile -- a collection of services. Your device has one profile.
2Service -- a group of related data. Example: "Environmental Sensing" service contains temperature and humidity.
3Characteristic -- a single data value within a service. Example: "Temperature" is one characteristic with a value of 26.3.
4Descriptor -- metadata about a characteristic. Example: units (Celsius), readable/writable/notifiable flags.
Analogy
Think of GATT like a file system. Profile = drive. Service = folder. Characteristic = file. Descriptor = file properties. A phone connects and browses this structure to find and read/write data.
Slide 4 of 12
Advertising
The Pico broadcasts its presence. Phones scan and see it in their BLE scanner app.
import bluetooth ble = bluetooth.BLE() ble.active(True) # Advertising payload: device name name = "PicoSensor" adv_data = bytearray([2, 0x01, 0x06]) # Flags adv_data += bytearray([len(name)+1, 0x09]) adv_data += name.encode() # Start advertising every 100ms ble.gap_advertise(100000, adv_data)
Advertising Interval
The interval (in microseconds) controls how often the Pico broadcasts. 100,000 us = 100 ms is a good balance. Lower = discovered faster but uses more power. Higher = saves power but takes longer to discover.

Defining Services
Create a GATT service with characteristics that phones can read.
import bluetooth from micropython import const # Standard Environmental Sensing Service UUID _ENV_SENSE_UUID = bluetooth.UUID(0x181A) # Temperature Characteristic (read + notify) _TEMP_CHAR = ( bluetooth.UUID(0x2A6E), bluetooth.FLAG_READ | bluetooth.FLAG_NOTIFY, ) # LED Control Characteristic (write) _LED_CHAR = ( bluetooth.UUID(0x2A57), bluetooth.FLAG_WRITE, ) # Register service _ENV_SERVICE = (_ENV_SENSE_UUID, (_TEMP_CHAR, _LED_CHAR)) ((temp_h, led_h),) = ble.gatts_register_services((_ENV_SERVICE,))

Reading and Writing
Update characteristic values. Handle write events from connected devices.
# Update temperature value (server writes) def update_temp(temp_c): # BLE spec: temperature in 0.01 degree units value = int(temp_c * 100) ble.gatts_write(temp_h, value.to_bytes(2, "little")) # Notify connected clients ble.gatts_notify(0, temp_h) # Handle writes from phone (client writes) def ble_irq(event, data): if event == 3: # _IRQ_GATTS_WRITE conn_h, attr_h = data if attr_h == led_h: val = ble.gatts_read(led_h) led.value(val[0]) ble.irq(ble_irq)
Two-Way Communication
The Pico updates the temperature characteristic -- the phone reads it. The phone writes to the LED characteristic -- the Pico toggles the LED. Bidirectional data flow over Bluetooth with no WiFi needed.
Slide 7 of 12
Notifications
Push data to connected clients without them asking. Efficient and real-time.
Read (Pull)
Client asks for the value. Server responds. Client must poll repeatedly for updates. Uses more power on the client side.
Notify (Push)
Server sends the value whenever it changes. Client receives it automatically. No polling. More efficient for frequently changing data like temperature.
# Server-initiated notification def notify_temp(conn_handle, temp_c): value = int(temp_c * 100) ble.gatts_write(temp_h, value.to_bytes(2, "little")) ble.gatts_notify(conn_handle, temp_h) # Call every time temperature changes significantly
Slide 8 of 12
Connection Events
Know when a phone connects or disconnects.
connected = False conn_handle = None def ble_irq(event, data): global connected, conn_handle if event == 1: # _IRQ_CENTRAL_CONNECT conn_handle = data[0] connected = True print("Phone connected") led.value(1) # LED on = connected elif event == 2: # _IRQ_CENTRAL_DISCONNECT connected = False conn_handle = None print("Phone disconnected") led.value(0) # Resume advertising ble.gap_advertise(100000, adv_data)
Re-Advertise on Disconnect
When a client disconnects, the Pico stops advertising by default. You must call gap_advertise() again to make it discoverable. Otherwise it disappears from BLE scans and new clients cannot find it.

Slide 10 of 12
Custom UUIDs
Standard UUIDs for standard services. Custom UUIDs for your own data.
# Standard 16-bit UUIDs (Bluetooth SIG defined) # 0x181A = Environmental Sensing # 0x2A6E = Temperature # 0x180F = Battery Service # Custom 128-bit UUID (generate your own) MY_SERVICE = bluetooth.UUID( "12345678-1234-5678-1234-56789abcdef0") MY_CHAR = bluetooth.UUID( "12345678-1234-5678-1234-56789abcdef1")
When to Use Custom UUIDs
Use standard UUIDs when your data matches a defined Bluetooth SIG profile (temperature, heart rate, battery). Use custom 128-bit UUIDs for proprietary data that does not fit a standard profile. Phone apps use the UUID to identify what kind of data a characteristic contains.

Key Takeaways: Bluetooth BLE
Wireless communication without WiFi infrastructure.
1BLE is for small, intermittent data. Not audio or file transfer. Sensor readings, control commands, notifications. Low power -- coin cell battery viable.
2GATT structures data into services and characteristics. Each characteristic has a UUID, value, and read/write/notify flags. Phones browse this structure to find data.
3Advertising makes the Pico discoverable. gap_advertise() broadcasts the device name. Re-advertise after disconnect to remain visible.
4Notifications push data without polling. More efficient than repeated reads. Use gatts_notify() when values change.
5nRF Connect is your testing tool. Free app that scans, connects, reads, writes, and subscribes to notifications. Essential for BLE development.
