Data Logging
File I/O | CSV Format | Timestamps | Storage Management
Collecting sensor data without recording it is like running an experiment without a lab notebook. Data logging writes readings to the Pico's flash filesystem as CSV files. Leave the Pico running overnight, collect the data in the morning, open it in a spreadsheet. This is how real environmental monitoring, industrial telemetry, and field research work.

File I/O on the Pico
Standard Python file operations work on the Pico's 1.4 MB flash filesystem.
import os # List files print(os.listdir()) # Write a file with open("test.txt", "w") as f: f.write("Hello from Pico\n") # Append to a file with open("test.txt", "a") as f: f.write("Second line\n") # Read a file with open("test.txt", "r") as f: print(f.read())
File Modes
"w" = write (overwrites). "a" = append (adds to end). "r" = read. Always use with blocks -- they automatically close the file, even if an error occurs. Unclosed files can corrupt data on power loss.

CSV Format
Comma-Separated Values: the universal data exchange format.
# CSV header + data rows with open("data.csv", "w") as f: f.write("timestamp,temp_c,temp_f,raw_adc\n") f.write("0,26.3,79.3,27845\n") f.write("10,26.5,79.7,27812\n") f.write("20,26.4,79.5,27830\n")
Why CSV?
Opens directly in Excel, Google Sheets, LibreOffice, Python Pandas, and every data analysis tool. Plain text, human-readable, no special libraries needed to write.
Header Row
The first row names each column. Write it once when creating the file. All subsequent rows are data. Tools auto-detect this as the column label row.

Timestamps
The Pico has no real-time clock. Use elapsed seconds from boot as your timestamp.
import time start = time.ticks_ms() def elapsed_seconds(): return time.ticks_diff(time.ticks_ms(), start) // 1000 # Log entry with timestamp ts = elapsed_seconds() line = f"{ts},{temp_c:.1f},{temp_f:.1f},{raw}\n"
No RTC on Pico
The Pico does not have a battery-backed real-time clock. It cannot know the actual date and time. Timestamps are relative -- "seconds since boot." If you need calendar timestamps, add an RTC module (DS3231, ~$2) via I2C (covered in Chapter 10).

Robust Logging
Open, write one line, close. Every time. Do not hold files open.
def log_reading(filename, ts, temp_c, temp_f, raw): with open(filename, "a") as f: f.write(f"{ts},{temp_c:.1f},{temp_f:.1f},{raw}\n") # Main loop: log every 10 seconds while True: raw = read_avg(sensor, 16) voltage = raw * 3.3 / 65535 tc = 27 - (voltage - 0.706) / 0.001721 tf = tc * 9/5 + 32 log_reading("data.csv", elapsed_seconds(), tc, tf, raw) time.sleep(10)
Why Open/Close Each Time?
If the Pico loses power while a file is open, all buffered writes are lost and the file may corrupt. Opening with append mode, writing one line, and closing ensures each reading is safely flushed to flash. The overhead is negligible at 10-second intervals.

Storage Management
The Pico has ~1.4 MB of flash. Know how much you are using.
import os def disk_usage(): s = os.statvfs("/") block_size = s[0] total = s[2] * block_size free = s[3] * block_size used = total - free print(f"Total: {total//1024} KB") print(f"Used: {used//1024} KB") print(f"Free: {free//1024} KB") return free # Check before logging if disk_usage() < 10240: # Less than 10 KB free print("WARNING: Low storage!")

Reading Logged Data
Retrieve data via Thonny, mpremote, or serial console.
Thonny File Browser
Open Thonny, connect to Pico, use the file browser panel to download CSV files to your computer. Drag and drop.
mpremote cp
mpremote cp :data.csv data.csv copies the file from Pico to your computer via command line. Fast and scriptable.
Serial Dump
Write a script that reads the file and prints it to serial. Copy from the terminal. Works with any serial monitor.
Self-Delete
os.remove("data.csv") deletes the file after download. Keeps storage clean for the next logging session.

Error Handling
Flash writes can fail. Wrap file operations in try/except.
def safe_log(filename, line): try: with open(filename, "a") as f: f.write(line) return True except OSError as e: print(f"Write failed: {e}") # Flash full? Try deleting old logs return False
OSError Causes
Filesystem full (ENOSPC), file not found (ENOENT), or flash wear (rare but possible after millions of writes). Always check the return value or catch exceptions. A data logger that silently fails is worse than useless.
Slide 10 of 12
Logging Frequency Tradeoffs
How often you log determines storage life and data resolution.
Every 1 Second
~30 bytes/line. 30 bytes x 86,400/day = ~2.5 MB/day. Fills 1.4 MB flash in ~13 hours. High resolution, short life.
Every 10 Seconds
~250 KB/day. Fills flash in ~5 days. Good balance for temperature monitoring. Detects trends without wasting space.
Every 60 Seconds
~42 KB/day. Fills flash in ~33 days. Month-long deployment with no intervention. Sufficient for slow-changing environments.

Complete Data Logger
All pieces assembled into a deployable logging system.
from machine import ADC, Pin import time, os sensor = ADC(4) led = Pin(25, Pin.OUT) LOG = "data.csv" INTERVAL = 10 # seconds # Initialize log file with header if LOG not in os.listdir(): with open(LOG, "w") as f: f.write("elapsed_s,temp_c,raw\n") start = time.ticks_ms() while True: raw = read_avg(sensor, 16) v = raw * 3.3 / 65535 tc = 27 - (v - 0.706) / 0.001721 ts = time.ticks_diff(time.ticks_ms(), start) // 1000 safe_log(LOG, f"{ts},{tc:.1f},{raw}\n") led.toggle() # Blink = still running time.sleep(INTERVAL)

Key Takeaways: Data Logging
From transient readings to permanent records.
1Standard Python file I/O works on the Pico. open(), read(), write(), with blocks. Files persist across power cycles on the flash filesystem.
2CSV is the universal data format. Header row + comma-separated values. Opens in every spreadsheet and data analysis tool.
3Open, write, close for every entry. Never hold files open. Power loss during an open write corrupts data. Append mode + close = safety.
4Monitor storage space. os.statvfs("/") reports free space. Implement file rotation or cleanup when space runs low.
5Logging frequency is a tradeoff. Faster = more detail but fills flash sooner. 10-second intervals balance resolution and storage for most applications.
