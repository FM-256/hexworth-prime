Game Flow
Five phases in each round of the reaction game.
1WAIT -- All LEDs off. Player waits. Random delay (2-5 seconds) to prevent anticipation.
2SIGNAL -- LED turns on. Timer starts. The clock is running from this exact millisecond.
3REACT -- Player presses button. Timer stops. Reaction time = press time - signal time.
4RESULT -- Display reaction time in milliseconds via serial. Show rating (fast/medium/slow).
5RESET -- Wait for button release, brief pause, then start next round.
Slide 3 of 12
Random Delays
urandom provides randomness. Without it, players learn the timing and anticipate the signal.
import urandom import utime # Random integer between 2000 and 5000 (milliseconds) delay = urandom.randint(2000, 5000) utime.sleep_ms(delay) # Alternative: using getrandbits # Generate a random 10-bit number (0-1023) # Scale to 2000-5000 range raw = urandom.getrandbits(10) delay = 2000 + (raw * 3000) // 1024
True Randomness
The RP2040 has a hardware random number generator (ROSC-based). urandom uses this hardware source, not a pseudo-random algorithm. The delay is genuinely unpredictable.

Measuring Reaction Time
Record the exact millisecond when the LED turns on. Record the exact millisecond when the button is pressed. Subtract.
# Core measurement logic led.value(1) start = utime.ticks_ms() # LED on -- clock starts while button.value() == 1: # Wait for press pass end = utime.ticks_ms() # Button pressed -- clock stops reaction = utime.ticks_diff(end, start) print(f"Reaction time: {reaction} ms") led.value(0)
Precision
ticks_ms() has 1-millisecond resolution. For most human reaction tests (150-400 ms), this is more than adequate. For sub-millisecond precision, use ticks_us() (microseconds).

Cheat Detection
If the player presses the button before the LED turns on, they are cheating. Detect and penalize.
# During the random wait period, check for early press def wait_random(): delay = urandom.randint(2000, 5000) start = utime.ticks_ms() while utime.ticks_diff(utime.ticks_ms(), start) < delay: if button.value() == 0: print("Too early! Cheater detected.") # Blink LED rapidly as penalty for _ in range(6): led.toggle() utime.sleep_ms(100) led.value(0) return False return True

Scoring System
Categorize reaction times and track the best score across multiple rounds.
def rate_reaction(ms): if ms < 200: return "LIGHTNING" elif ms < 300: return "FAST" elif ms < 400: return "AVERAGE" else: return "SLOW" # Track best score best = 9999 scores = [] # After each round: scores.append(reaction) if reaction < best: best = reaction print(f"New best: {best} ms!") # After all rounds: avg = sum(scores) // len(scores) print(f"Average: {avg} ms Best: {best} ms")

LED Feedback Patterns
Use visual feedback to communicate game state without the serial console.
Waiting
LED off. Player is waiting. The suspense is the random delay.
Signal
LED on solid. React now. The clock is running.
Good Result
LED blinks slowly 3 times. Under 300 ms. Well done.
Foul
LED blinks rapidly 6 times. Player pressed too early. Round does not count.

Adding a Countdown
Three quick blinks before the random wait begins. Tells the player the round is starting.
def countdown(): # Three blinks: "ready... set..." for _ in range(3): led.value(1) utime.sleep_ms(150) led.value(0) utime.sleep_ms(300) # Now begin the random wait # Player knows: after the last blink, # the LED will turn on ONCE -- that is the signal
User Experience
Without the countdown, players do not know when the round starts. The three blinks serve as a "ready, set..." cue. The LED staying off after the blinks means "wait for the signal." Simple but effective feedback design.

Timeout Handling
If the player does not press the button within a reasonable time, end the round.
def measure_reaction(): led.value(1) start = utime.ticks_ms() while button.value() == 1: if utime.ticks_diff(utime.ticks_ms(), start) > 3000: led.value(0) print("Timeout! Too slow.") return -1 end = utime.ticks_ms() led.value(0) return utime.ticks_diff(end, start)
Why Timeout?
Without a timeout, the program hangs forever if the player walks away. A 3-second timeout is generous -- average human reaction is 200-300 ms. Anything over 1 second is clearly a missed round.

Key Takeaways: Reaction Game
Everything you have learned, combined into one project.
1urandom.randint() for unpredictable delays. Hardware RNG on the RP2040 provides genuine randomness. Prevents players from anticipating the signal.
2ticks_ms() + ticks_diff() for precision timing. 1-millisecond resolution. Record start, record end, subtract. Handles wraparound correctly.
3Cheat detection during the wait period. Poll the button while the random delay runs. Early press = foul. Teaches defensive input handling.
4Timeout prevents hangs. If no press within 3 seconds, end the round. Never let user input block the program indefinitely.
5Functions + data = clean architecture. Each function does one thing. Configuration is separate from logic. The entire game is testable piece by piece in the REPL.
