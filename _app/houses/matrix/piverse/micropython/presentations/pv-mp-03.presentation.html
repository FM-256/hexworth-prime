GPIO Output: Controlling an LED
Pin(pin_number, Pin.OUT) configures a pin to send voltage. value(1) = HIGH, value(0) = LOW.
from machine import Pin import utime # On-board LED: GP25 (Pico) or "LED" (Pico W) led = Pin(25, Pin.OUT) # Turn on led.value(1) # Turn off led.value(0) # Toggle shortcut led.toggle()
Pin.OUT
When a pin is configured as OUTPUT, the RP2040 drives it to 3.3V (HIGH) or 0V (LOW). The pin actively pushes current. Never connect two output pins together -- they will fight and potentially damage the chip.
Slide 3 of 12
Blink: The Hello World of Hardware
Turn the LED on, wait, turn it off, wait, repeat. The fundamental pattern of embedded programming.
from machine import Pin import utime led = Pin(25, Pin.OUT) while True: led.value(1) # LED on utime.sleep(0.5) # Wait 500ms led.value(0) # LED off utime.sleep(0.5) # Wait 500ms
utime.sleep(seconds)
Blocks execution for the specified number of seconds. Accepts floats: 0.5 = 500ms, 0.1 = 100ms.
utime.sleep_ms(ms)
Blocks for milliseconds. More readable for short delays. sleep_ms(500) = half second.

External LED Circuit
GPIO pin to resistor to LED to ground. The first circuit you build outside the board.
1GP15 drives HIGH (3.3V) or LOW (0V) based on your code.
2330-ohm resistor limits current to ~10 mA. Without it, the LED draws too much current and may damage the GPIO.
3LED -- long leg (anode, +) faces the resistor side. Short leg (cathode, -) faces ground. Polarity matters.
4GND completes the circuit. Current flows from GP15, through the resistor, through the LED, to ground.

GPIO Input: Reading a Button
Pin(pin_number, Pin.IN) configures a pin to read voltage. value() returns 0 or 1.
from machine import Pin # Button on GP14, internal pull-up enabled button = Pin(14, Pin.IN, Pin.PULL_UP) # Read the button state state = button.value() # Returns 1 when NOT pressed (pulled up) # Returns 0 when pressed (connected to GND) print(f"Button: {state}")
Pin.PULL_UP
Internal resistor pulls the pin to 3.3V when nothing is connected. Button wired to GND pulls it LOW when pressed. Default state = 1 (not pressed).
Pin.PULL_DOWN
Internal resistor pulls the pin to 0V. Button wired to 3.3V pulls it HIGH when pressed. Default state = 0 (not pressed).
Slide 6 of 12
Why Pull Resistors Matter
Without a pull-up or pull-down, an unconnected input pin floats between HIGH and LOW randomly.
Floating Pin
No pull resistor. The pin picks up electrical noise and reads random values. Completely unreliable. Never leave an input pin floating.
Pull-Up
Pin sits at 3.3V (reads 1) until the button connects it to GND (reads 0). Active-LOW logic. Most common pattern for buttons.
Pull-Down
Pin sits at 0V (reads 0) until the button connects it to 3.3V (reads 1). Active-HIGH logic. Less common but more intuitive.
Rule
Every input pin must have a defined state when nothing is pressing/connecting to it. Use Pin.PULL_UP or Pin.PULL_DOWN in the Pin constructor. The RP2040's internal pull resistors are approximately 50K ohm.
Slide 7 of 12
Button-Controlled LED
Read the button, control the LED. The simplest input-to-output program.
from machine import Pin led = Pin(15, Pin.OUT) button = Pin(14, Pin.IN, Pin.PULL_UP) while True: if button.value() == 0: # Pressed (active LOW) led.value(1) # LED on else: led.value(0) # LED off
Polling Loop
This is a polling approach -- the program continuously checks the button state in a tight loop. It works but uses 100% CPU. Later you will learn interrupt-driven approaches that are more efficient.
Slide 8 of 12
The Debouncing Problem
Mechanical buttons bounce. One press can register as dozens of rapid on/off transitions.
What Happens
When you press a button, the metal contacts physically bounce for 5-50 milliseconds. Each bounce creates a rising and falling edge that the microcontroller reads as a separate press/release event.
Why It Matters
A toggle program (press to turn on, press again to turn off) will appear to randomly work or not work. A counter will increment by 3-10 instead of 1. Bouncing makes raw button reads unreliable.
# Software debounce: wait after detecting a change from machine import Pin import utime button = Pin(14, Pin.IN, Pin.PULL_UP) led = Pin(15, Pin.OUT) led_state = 0 while True: if button.value() == 0: # Press detected utime.sleep_ms(50) # Wait for bounce to settle if button.value() == 0: # Still pressed? Real press. led_state = 1 - led_state led.value(led_state) while button.value() == 0: # Wait for release pass

Hardware Interrupts
Instead of polling in a loop, let the hardware notify your code when a pin changes state.
from machine import Pin import utime led = Pin(15, Pin.OUT) button = Pin(14, Pin.IN, Pin.PULL_UP) last_press = 0 def button_handler(pin): global last_press now = utime.ticks_ms() if utime.ticks_diff(now, last_press) > 200: led.toggle() last_press = now button.irq(trigger=Pin.IRQ_FALLING, handler=button_handler)
IRQ_FALLING
Triggers when pin transitions from HIGH to LOW (button pressed with pull-up). This is the falling edge.
IRQ_RISING
Triggers when pin transitions from LOW to HIGH (button released with pull-up). This is the rising edge.
Slide 10 of 12
Multiple LEDs
Control several LEDs independently or create patterns by managing multiple output pins.
from machine import Pin import utime # Three LEDs on GP15, GP16, GP17 leds = [Pin(i, Pin.OUT) for i in (15, 16, 17)] # Chase pattern: one LED at a time while True: for i in range(len(leds)): for j in range(len(leds)): leds[j].value(1 if j == i else 0) utime.sleep_ms(200)
List Comprehension
[Pin(i, Pin.OUT) for i in (15, 16, 17)] creates three Pin objects in one line. Standard Python list comprehension works in MicroPython. This pattern scales to any number of pins.
Slide 11 of 12
toggle() vs value()
Two ways to control an output pin. Choose based on whether you know the desired state.
value(n) -- Set Explicitly
Use when you know exactly what state you want. led.value(1) always turns it on. led.value(0) always turns it off. Deterministic. No ambiguity.
toggle() -- Flip Current State
Use when you want the opposite of the current state. If on, turn off. If off, turn on. Perfect for blink loops and button toggles. Shorter code.
# Blink with toggle -- cleaner while True: led.toggle() utime.sleep_ms(500) # Blink with value -- explicit while True: led.value(1) utime.sleep_ms(500) led.value(0) utime.sleep_ms(500)
Slide 12 of 12
Key Takeaways: Digital I/O
Outputs drive LEDs. Inputs read buttons. Debouncing makes it reliable.
1Pin(n, Pin.OUT) for outputs. value(1) = 3.3V (HIGH). value(0) = 0V (LOW). toggle() flips current state.
2Pin(n, Pin.IN, Pin.PULL_UP) for inputs. Internal pull-up keeps the pin at 3.3V when nothing is connected. Button to GND pulls it LOW.
3Always use a current-limiting resistor (220-330 ohm) with external LEDs. The resistor protects both the LED and the GPIO pin.
4Debounce mechanical buttons. Wait 50ms after detecting a press, then re-read. Or use interrupts with a ticks-based cooldown.
5Interrupts beat polling. pin.irq(trigger=Pin.IRQ_FALLING, handler=fn) lets the hardware notify your code instead of burning CPU in a tight loop.
