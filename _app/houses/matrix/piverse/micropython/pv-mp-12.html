Hardware Requirement:

This module requires a Pico W with MicroPython firmware v1.21 or later (BLE support). You also need a smartphone with a BLE scanner app (nRF Connect for Android/iOS is recommended). The original Pico does not have Bluetooth hardware.

BLE vs. Bluetooth Classic

Bluetooth Low Energy (BLE) is a completely different protocol from classic Bluetooth, even though they share the name. Classic Bluetooth is designed for continuous streaming (audio, file transfer) and consumes significant power. BLE is designed for intermittent data exchange (sensor readings, notifications) and consumes very little power -- a BLE sensor can run for months on a coin cell battery.

Bluetooth Classic Continuous streaming, higher power, used for audio (headphones, speakers), file transfer, serial port emulation. Not supported on Pico W.
BLE (Bluetooth Low Energy) Short data bursts, very low power, used for sensors, fitness trackers, beacons, IoT devices. Supported on Pico W via CYW43439.

GATT Architecture

BLE communication is structured using GATT (Generic Attribute Profile). Think of it as a database that other devices can read from and write to. The hierarchy is: Profile > Service > Characteristic > Value.

GATT Concept Description Analogy
Service A group of related data and behaviors A table in a database
Characteristic A single data point within a service A column in the table
UUID Unique identifier for services and characteristics A primary key
Descriptor Metadata about a characteristic (units, format) Column description / data type
Read / Write / Notify Permissions: what the client can do with the characteristic SELECT / UPDATE / trigger

BLE Advertising

Before a phone can connect to the Pico W, the Pico must advertise its presence. Advertising broadcasts the device name and available services at regular intervals. Nearby BLE scanners see this advertisement and can initiate a connection.

Temperature Sensor BLE Service

A complete BLE peripheral that exposes the Pico's temperature as a readable and notifiable characteristic. A connected phone can read the current temperature or subscribe to notifications for automatic updates.

LED Control via BLE

This example creates a writable characteristic that lets a connected phone toggle the Pico's LED. When the phone writes a value (0 or 1) to the characteristic, the Pico reads it and sets the LED accordingly -- remote control over Bluetooth.

# ble_led_control.py -- Control LED from phone via BLE import bluetooth import time from machine import Pin from micropython import const _IRQ_CENTRAL_CONNECT = const(1) _IRQ_CENTRAL_DISCONNECT = const(2) _IRQ_GATTS_WRITE = const(3) # Custom UUID for LED service _LED_SERVICE_UUID = bluetooth.UUID("12345678-1234-1234-1234-123456789abc") _LED_CHAR_UUID = bluetooth.UUID("12345678-1234-1234-1234-123456789abd") _FLAG_READ = const(0x0002) _FLAG_WRITE = const(0x0008) _LED_SERVICE = ( _LED_SERVICE_UUID, ( (_LED_CHAR_UUID, _FLAG_READ | _FLAG_WRITE), ), ) led = Pin("LED", Pin.OUT) ble = bluetooth.BLE() ble.active(True) conn_handle = None # Register service ((led_handle,),) = ble.gatts_register_services((_LED_SERVICE,)) ble.gatts_write(led_handle, bytes([0])) # Initial: LED off def ble_irq(event, data): global conn_handle if event == _IRQ_CENTRAL_CONNECT: conn_handle = data[0] print("Connected!") elif event == _IRQ_CENTRAL_DISCONNECT: conn_handle = None led.off() print("Disconnected.") advertise() elif event == _IRQ_GATTS_WRITE: # Client wrote to a characteristic buffer = ble.gatts_read(led_handle) value = buffer[0] if buffer else 0 led.value(value) print(f"LED set to: {'ON' if value else 'OFF'}") ble.irq(ble_irq) def advertise(): name = "PicoW-LED" payload = bytes([len(name) + 1, 0x09]) + name.encode() ble.gap_advertise(100000, adv_data=payload) print("Advertising as 'PicoW-LED'...") advertise() print("BLE LED Control active.") print("Connect with nRF Connect and write 0x01 to turn on, 0x00 to turn off.\n") while True: time.sleep(1)

Testing with nRF Connect

nRF Connect (by Nordic Semiconductor) is a free BLE scanner and debugging app for Android and iOS. It lets you discover nearby BLE devices, connect to them, read and write characteristics, and subscribe to notifications.

Step 1: Scan Open nRF Connect, tap "Scan". You should see "PicoW-Temp" or "PicoW-LED" in the device list. If not, check that BLE is active on the Pico.
Step 2: Connect Tap "Connect" on the Pico device. The app shows the GATT service tree with services and characteristics.
Step 3: Read Tap the down-arrow icon on a characteristic to read its current value. For temperature, it shows the raw bytes.
Step 4: Write / Notify Tap the up-arrow to write a value (e.g., 0x01 to turn on LED). Tap the triple-down-arrow to enable notifications.
UUID Formats:

Standard Bluetooth SIG UUIDs are 16-bit (e.g., 0x181A for Environmental Sensing). Custom UUIDs are 128-bit strings. Use standard UUIDs when your service matches a Bluetooth standard. Use custom UUIDs for proprietary services -- generate them at uuidgenerator.net.

BLE vs. WiFi for IoT

Factor BLE WiFi
Range ~10-30 meters ~30-100 meters
Power Very low (coin cell for months) Higher (needs wall power or large battery)
Data Rate ~1 Mbps max (small packets) ~10-100 Mbps
Infrastructure None required (direct connection) Requires WiFi router
Best For Wearables, sensors, proximity, phone control Web servers, cloud APIs, data streaming

Key Takeaways

  • BLE is designed for low-power, intermittent data exchange -- fundamentally different from Bluetooth Classic
  • GATT provides a structured database of services and characteristics that clients can read, write, and subscribe to
  • The Pico W acts as a BLE peripheral (server) that advertises, accepts connections, and exposes data
  • Standard UUIDs (0x181A, 0x2A6E) identify common services -- use custom 128-bit UUIDs for proprietary ones
  • Notifications push data to connected clients automatically -- no polling needed from the phone side
  • nRF Connect is the essential debugging tool for BLE development -- use it to verify services and characteristics
