Track Context:

Until now, your projects used simple digital and analog signals -- single wires carrying on/off or voltage levels. I2C and SPI are structured communication protocols that let the Pico talk to complex peripherals: displays, memory chips, sensors with digital output, real-time clocks, and more. These two protocols connect the Pico to the vast ecosystem of breakout boards and modules.

I2C Protocol

I2C (Inter-Integrated Circuit, pronounced "eye-squared-see") is a two-wire serial bus. It uses SDA (Serial Data) and SCL (Serial Clock) lines shared by all devices on the bus. Each device has a unique 7-bit address (0x00-0x7F). The Pico acts as the master -- it initiates all communication, generates the clock, and addresses specific devices.

I2C Advantages Only 2 wires for any number of devices. Each device has a unique address. Simple wiring. Can have up to 127 devices on one bus.
I2C Limitations Slower than SPI (typically 100-400 kHz). Shared bus means only one device talks at a time. Requires pull-up resistors on SDA and SCL.

I2C Scanning and Setup

# i2c_scan.py -- Scan for I2C devices from machine import Pin, I2C # Create I2C bus on I2C0: SDA=GP0, SCL=GP1 i2c = I2C(0, sda=Pin(0), scl=Pin(1), freq=400000) # Scan for devices devices = i2c.scan() if devices: print(f"Found {len(devices)} device(s):") for addr in devices: print(f" Address: 0x{addr:02X} ({addr})") else: print("No I2C devices found. Check wiring.")

Driving an OLED Display

The SSD1306 is a popular 128x64 pixel OLED display module. MicroPython includes a built-in driver for it. The display connects via I2C (4 wires: VCC, GND, SDA, SCL) and can show text, simple graphics, and sensor readouts.

# oled_display.py -- SSD1306 OLED over I2C from machine import Pin, I2C from ssd1306 import SSD1306_I2C # Initialize I2C and display i2c = I2C(0, sda=Pin(0), scl=Pin(1), freq=400000) oled = SSD1306_I2C(128, 64, i2c) # Clear display oled.fill(0) # Draw text oled.text("Raspberry Pi", 0, 0) oled.text("Pico", 0, 12) oled.text("MicroPython", 0, 24) # Draw a horizontal line oled.hline(0, 38, 128, 1) # Draw a rectangle oled.rect(0, 42, 128, 20, 1) oled.text("PV-MP-10", 30, 48) # Push buffer to display oled.show()
# oled_temp.py -- Live temperature on OLED from machine import Pin, I2C, ADC from ssd1306 import SSD1306_I2C import time i2c = I2C(0, sda=Pin(0), scl=Pin(1), freq=400000) oled = SSD1306_I2C(128, 64, i2c) sensor = ADC(4) def read_temp(): raw = sum(sensor.read_u16() for _ in range(16)) // 16 v = raw * 3.3 / 65535 return round(27 - (v - 0.706) / 0.001721, 1) while True: temp = read_temp() oled.fill(0) oled.text("TEMPERATURE", 20, 5) oled.hline(0, 18, 128, 1) oled.text(f"{temp} C", 30, 30) temp_f = round(temp * 9/5 + 32, 1) oled.text(f"{temp_f} F", 30, 45) oled.show() time.sleep(1)

SPI Protocol

SPI (Serial Peripheral Interface) uses four wires: SCK (clock), MOSI (Master Out Slave In), MISO (Master In Slave Out), and CS (Chip Select). Unlike I2C, SPI is full-duplex -- data flows in both directions simultaneously. Each device has its own CS line, so the master selects which device to talk to by pulling its CS low.

# spi_setup.py -- Initialize SPI on the Pico from machine import Pin, SPI # SPI0: SCK=GP18, MOSI=GP19, MISO=GP16 spi = SPI(0, baudrate=1000000, sck=Pin(18), mosi=Pin(19), miso=Pin(16)) # Chip select is a regular GPIO pin (active low) cs = Pin(17, Pin.OUT, value=1) # Start high (deselected) # Write data to SPI device cs.value(0) # Select device spi.write(bytes([0x01, 0x02])) # Send 2 bytes cs.value(1) # Deselect device # Read data from SPI device cs.value(0) buf = bytearray(4) spi.readinto(buf) # Read 4 bytes into buffer cs.value(1) print("Read:", [hex(b) for b in buf])

I2C vs. SPI Comparison

Feature I2C SPI
Wires 2 (SDA, SCL) + power 4+ (SCK, MOSI, MISO, CS per device)
Speed 100 kHz - 3.4 MHz 1 MHz - 80+ MHz
Multi-device Shared bus with addresses Separate CS pin per device
Direction Half-duplex (one direction at a time) Full-duplex (both directions simultaneously)
Best For Sensors, RTCs, small displays, EEPROMs Fast displays, SD cards, high-speed ADCs, flash memory
Pico Support 2 controllers (I2C0, I2C1) 2 controllers (SPI0, SPI1)
When to Choose Which:

Use I2C when you have multiple slow devices and want simple wiring (2 wires). Use SPI when speed matters (displays with fast refresh, high-speed data transfer) or when you need full-duplex communication. Many projects use both -- I2C for sensors and SPI for the display.

Key Takeaways

  • I2C uses 2 wires (SDA, SCL) and addresses to communicate with up to 127 devices on a shared bus
  • i2c.scan() discovers all connected devices -- always scan first when debugging I2C wiring
  • SPI uses 4+ wires and is much faster than I2C -- ideal for displays and high-speed peripherals
  • SPI is full-duplex (send and receive simultaneously); I2C is half-duplex (one direction at a time)
  • The SSD1306 OLED display is a practical I2C peripheral for showing sensor data without a computer
  • The Pico has 2 I2C controllers and 2 SPI controllers, each mappable to several pin combinations
