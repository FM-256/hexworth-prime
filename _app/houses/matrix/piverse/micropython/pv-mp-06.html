Track Context:

This project builds on digital I/O (buttons, LEDs) and adds timing precision and random number generation. The reaction game is a classic embedded project that teaches you to think about real-time measurement -- how fast can your code respond, and how accurately can it measure human input?

Random Numbers on MicroPython

MicroPython provides the urandom module (a micro version of Python's random module) for generating random numbers. For a reaction game, you need random delays so the player cannot predict when the LED will light up.

# random_demo.py -- Generating random numbers import urandom import time # Random integer in a range (inclusive) delay_ms = urandom.randint(2000, 5000) # 2-5 seconds print(f"Random delay: {delay_ms} ms") # Random choice from a list pins = [13, 14, 15] chosen = pins[urandom.randint(0, len(pins) - 1)] print(f"Random pin: GP{chosen}") # Random float between 0 and 1 val = urandom.getrandbits(16) / 65535 print(f"Random float: {val:.4f}")

Precise Timing Measurement

The time.ticks_ms() function returns a millisecond counter that wraps around periodically. To measure elapsed time correctly, always use time.ticks_diff(end, start) -- never subtract directly. The ticks_diff function handles the wraparound correctly.

# timing_demo.py -- Measuring elapsed time import time # Measure how long something takes start = time.ticks_ms() time.sleep(0.5) end = time.ticks_ms() elapsed = time.ticks_diff(end, start) print(f"Elapsed: {elapsed} ms") # Should be ~500 # WRONG: Direct subtraction can fail on wraparound # elapsed = end - start # DO NOT DO THIS # For microsecond precision (1/1000 of a millisecond) start_us = time.ticks_us() # ... fast operation ... elapsed_us = time.ticks_diff(time.ticks_us(), start_us) print(f"Elapsed: {elapsed_us} microseconds")
Why ticks_diff?

The ticks counter is an unsigned integer that wraps around. If start = 0xFFFFFFF0 and end = 0x00000010, simple subtraction gives a negative number. ticks_diff handles this correctly and always returns the right positive duration.

Single-Player Reaction Game

The game flow: wait a random delay, turn on the LED, measure how long it takes the player to press the button. If they press before the LED lights, that is a false start. After several rounds, display the average reaction time.

# reaction_game.py -- Single-player reaction time game from machine import Pin import time import urandom led = Pin(15, Pin.OUT) button = Pin(16, Pin.IN, Pin.PULL_DOWN) NUM_ROUNDS = 5 results = [] print("=== REACTION GAME ===") print(f"Press the button when the LED lights up!") print(f"{NUM_ROUNDS} rounds. Press button to start...\n") # Wait for initial button press while button.value() == 0: time.sleep(0.01) time.sleep(0.5) # Debounce for round_num in range(1, NUM_ROUNDS + 1): print(f"--- Round {round_num} ---") led.off() # Random delay (2-5 seconds) delay = urandom.randint(2000, 5000) # Check for false start during the wait false_start = False start_wait = time.ticks_ms() while time.ticks_diff(time.ticks_ms(), start_wait) < delay: if button.value() == 1: false_start = True break time.sleep(0.01) if false_start: print(" FALSE START! Wait for the LED.") results.append(9999) # Penalty time.sleep(1) continue # Signal: turn on LED and start timing led.on() signal_time = time.ticks_ms() print(" GO!") # Wait for button press while button.value() == 0: time.sleep_ms(1) reaction_ms = time.ticks_diff(time.ticks_ms(), signal_time) led.off() results.append(reaction_ms) print(f" Reaction time: {reaction_ms} ms") time.sleep(1) # Final results print("\n=== RESULTS ===") valid = [r for r in results if r < 9999] for i, r in enumerate(results, 1): status = "FALSE START" if r == 9999 else f"{r} ms" print(f" Round {i}: {status}") if valid: avg = sum(valid) // len(valid) best = min(valid) print(f"\n Average: {avg} ms") print(f" Best: {best} ms") else: print(" All rounds were false starts!")

Two-Player Competitive Mode

The two-player version adds a second button. Both players watch the LED. When it lights up, the first to press their button wins the round. The program must detect which button was pressed first -- a race condition in the physical world.

# reaction_2player.py -- Two-player competitive reaction game from machine import Pin import time import urandom led = Pin(15, Pin.OUT) btn_p1 = Pin(16, Pin.IN, Pin.PULL_DOWN) # Player 1 btn_p2 = Pin(17, Pin.IN, Pin.PULL_DOWN) # Player 2 NUM_ROUNDS = 5 score = [0, 0] # [P1 wins, P2 wins] print("=== 2-PLAYER REACTION GAME ===") print("Player 1: GP16 button") print("Player 2: GP17 button") print("First to press after LED = wins the round\n") time.sleep(2) for round_num in range(1, NUM_ROUNDS + 1): print(f"--- Round {round_num} ---") led.off() # Random delay delay = urandom.randint(2000, 5000) # Check for false starts false_start = 0 start_wait = time.ticks_ms() while time.ticks_diff(time.ticks_ms(), start_wait) < delay: if btn_p1.value() == 1: false_start = 1 break if btn_p2.value() == 1: false_start = 2 break time.sleep(0.01) if false_start: winner = 2 if false_start == 1 else 1 # Other player wins print(f" Player {false_start} FALSE START! Point to Player {winner}") score[winner - 1] += 1 time.sleep(1) continue # Signal! led.on() signal_time = time.ticks_ms() # Wait for either button while True: if btn_p1.value() == 1: react = time.ticks_diff(time.ticks_ms(), signal_time) print(f" Player 1 wins! ({react} ms)") score[0] += 1 break if btn_p2.value() == 1: react = time.ticks_diff(time.ticks_ms(), signal_time) print(f" Player 2 wins! ({react} ms)") score[1] += 1 break time.sleep_ms(1) led.off() print(f" Score: P1={score[0]} P2={score[1]}") time.sleep(1.5) # Final result print("\n=== FINAL SCORE ===") print(f" Player 1: {score[0]}") print(f" Player 2: {score[1]}") if score[0] > score[1]: print(" Player 1 WINS!") elif score[1] > score[0]: print(" Player 2 WINS!") else: print(" TIE!")

Adding Sound Feedback

A buzzer adds audio feedback: a countdown beep before each round, a high tone for the signal, and a low tone for false starts. This makes the game more engaging and demonstrates combining multiple output devices.

# reaction_sound.py -- Reaction game with buzzer feedback from machine import Pin, PWM import time import urandom led = Pin(15, Pin.OUT) button = Pin(16, Pin.IN, Pin.PULL_DOWN) buzzer = PWM(Pin(14)) def beep(freq, duration_ms): """Play a tone for a given duration.""" buzzer.freq(freq) buzzer.duty_u16(16384) # 25% duty = moderate volume time.sleep_ms(duration_ms) buzzer.duty_u16(0) def countdown(): """Three beeps before each round.""" for _ in range(3): beep(440, 100) time.sleep(0.5) def win_sound(): beep(880, 100) beep(1100, 100) beep(1320, 200) def fail_sound(): beep(200, 400) NUM_ROUNDS = 5 results = [] for rnd in range(1, NUM_ROUNDS + 1): print(f"Round {rnd}...") countdown() delay = urandom.randint(1500, 4000) false_start = False t0 = time.ticks_ms() while time.ticks_diff(time.ticks_ms(), t0) < delay: if button.value() == 1: false_start = True break time.sleep_ms(5) if false_start: fail_sound() print(" Too early!") results.append(None) time.sleep(1) continue led.on() beep(1000, 50) # Short signal beep t_signal = time.ticks_ms() while button.value() == 0: time.sleep_ms(1) react = time.ticks_diff(time.ticks_ms(), t_signal) led.off() win_sound() results.append(react) print(f" {react} ms") time.sleep(0.5) buzzer.deinit() valid = [r for r in results if r is not None] if valid: print(f"\nBest: {min(valid)} ms | Average: {sum(valid)//len(valid)} ms")

Programming Concepts Applied

Game Loop Pattern Initialize, loop through rounds, accumulate results, display summary. This pattern appears in every game and many real-time monitoring systems.
Edge Case Handling False starts, all-false-start games, button bounce during timing. Robust code anticipates and handles every case, not just the happy path.
Timing Precision Polling at 1ms intervals gives ~1ms measurement accuracy. For sub-millisecond precision, use ticks_us() or hardware interrupts (covered in Module 7).
Data Collection Storing results in a list, filtering invalid entries, computing statistics. This is the same pattern used in data logging (Module 9).

Key Takeaways

  • urandom.randint() generates random integers -- essential for unpredictable game timing
  • Always use time.ticks_diff() for elapsed time -- never subtract ticks values directly
  • False start detection requires monitoring the button during the random delay period
  • Two-player mode demonstrates polling multiple inputs and racing for first response
  • Sound feedback via PWM buzzer makes physical projects more engaging and intuitive
  • The game loop pattern (init, rounds, accumulate, summarize) is reusable across many project types
