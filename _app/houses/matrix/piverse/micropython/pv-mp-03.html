Track Context:

Digital I/O is the foundation of all embedded programming. Every sensor reading, every motor command, every communication protocol ultimately reduces to pins going high (3.3V) or low (0V). Master this and everything else builds on top.

GPIO Output: Driving LEDs

A GPIO pin configured as an output can be set high (3.3V) or low (0V). When high, the pin sources current -- enough to light a standard LED through a current-limiting resistor. The RP2040 can source or sink up to 12 mA per pin, with a total chip limit of 50 mA across all GPIO.

# led_output.py -- Control an external LED on GP15 from machine import Pin import time # Configure GP15 as digital output led = Pin(15, Pin.OUT) # Turn on and off led.value(1) # HIGH = 3.3V = LED on time.sleep(1) led.value(0) # LOW = 0V = LED off # Shorthand methods led.on() # Same as led.value(1) led.off() # Same as led.value(0) led.toggle() # Flip current state # Blink loop using toggle while True: led.toggle() time.sleep(0.25)
# multi_led.py -- Control multiple LEDs independently from machine import Pin import time # Three LEDs on GP15, GP14, GP13 red = Pin(15, Pin.OUT) amber = Pin(14, Pin.OUT) green = Pin(13, Pin.OUT) # Sequential pattern leds = [red, amber, green] while True: for led in leds: led.on() time.sleep(0.3) led.off()
Resistor Value:

A 330-ohm resistor limits current to about 9 mA at 3.3V -- safe for both the LED and the Pico. Never connect an LED directly to a GPIO pin without a resistor. Without it, the current is uncontrolled and can damage both the LED and the RP2040.

GPIO Input: Reading Buttons

A GPIO pin configured as an input reads the voltage on the pin and returns 0 (low, below ~1V) or 1 (high, above ~2V). To read a button, you connect one side to the GPIO pin and the other side to either 3.3V or GND. The internal pull-up or pull-down resistor defines the default state when the button is not pressed.

# button_input.py -- Read a button with pull-down resistor from machine import Pin import time # Button on GP16, internal pull-down enabled # Default state = 0 (LOW). Pressing button connects to 3V3 = 1 (HIGH). button = Pin(16, Pin.IN, Pin.PULL_DOWN) while True: if button.value() == 1: print("Button pressed!") time.sleep(0.1)
# button_pullup.py -- Read a button with pull-up resistor from machine import Pin import time # Button on GP16, internal pull-up enabled # Default state = 1 (HIGH). Pressing button connects to GND = 0 (LOW). # Note: logic is inverted -- pressed = 0, released = 1 button = Pin(16, Pin.IN, Pin.PULL_UP) while True: if button.value() == 0: # Inverted: 0 = pressed print("Button pressed!") time.sleep(0.1)
Configuration Default (Not Pressed) Pressed Button Connects To
PULL_DOWN 0 (LOW) 1 (HIGH) 3V3
PULL_UP 1 (HIGH) 0 (LOW) GND

Understanding Pull Resistors

Without a pull resistor, an unconnected input pin is "floating" -- its voltage is undefined. It picks up electrical noise and gives random readings. Pull resistors define a known default state.

A pull-up resistor connects the pin to 3.3V through a high-value resistor (~50k ohm internal on RP2040). The pin reads HIGH by default. When you press a button that connects the pin to GND, the low-impedance path to ground wins over the high-impedance pull-up, and the pin reads LOW.

A pull-down resistor connects the pin to GND through a high-value resistor. The pin reads LOW by default. Pressing a button that connects to 3.3V overrides the pull-down and the pin reads HIGH.

Floating Pin Danger:

A floating input pin does not just read zero -- it reads random values caused by electromagnetic interference, capacitive coupling from nearby traces, and static charge. This is the number one cause of "my button code is acting erratic." Always use a pull resistor.

Software Debouncing

Mechanical buttons do not make clean contact. When pressed, the metal contacts bounce multiple times over 1-10 milliseconds, producing rapid on/off transitions. Without debouncing, a single press registers as 5-20 presses. Software debouncing ignores these bounces by requiring the signal to be stable for a minimum time.

# debounce.py -- Simple time-based debouncing from machine import Pin import time button = Pin(16, Pin.IN, Pin.PULL_DOWN) led = Pin(15, Pin.OUT) last_press_time = 0 DEBOUNCE_MS = 200 # Ignore presses within 200ms of each other led_state = False while True: if button.value() == 1: current_time = time.ticks_ms() if time.ticks_diff(current_time, last_press_time) > DEBOUNCE_MS: led_state = not led_state led.value(led_state) print(f"LED: {'ON' if led_state else 'OFF'}") last_press_time = current_time time.sleep(0.01) # Small delay to reduce CPU usage
# debounce_class.py -- Reusable debounce wrapper from machine import Pin import time class DebouncedButton: def __init__(self, pin_num, pull=Pin.PULL_DOWN, debounce_ms=200): self.pin = Pin(pin_num, Pin.IN, pull) self.debounce_ms = debounce_ms self.last_time = 0 self.active = 1 if pull == Pin.PULL_DOWN else 0 def is_pressed(self): if self.pin.value() == self.active: now = time.ticks_ms() if time.ticks_diff(now, self.last_time) > self.debounce_ms: self.last_time = now return True return False # Usage btn = DebouncedButton(16) led = Pin(15, Pin.OUT) while True: if btn.is_pressed(): led.toggle() time.sleep(0.01)

Combining Input and Output

Real projects combine inputs and outputs. Here is a practical example: a button-controlled LED with three brightness modes (off, dim via rapid toggling, full brightness) that cycles through states on each press.

# button_led_modes.py -- Three LED modes cycled by button from machine import Pin import time button = Pin(16, Pin.IN, Pin.PULL_DOWN) led = Pin(15, Pin.OUT) mode = 0 # 0=off, 1=blink, 2=solid last_press = 0 while True: # Check for button press with debounce if button.value() == 1: now = time.ticks_ms() if time.ticks_diff(now, last_press) > 300: mode = (mode + 1) % 3 print(f"Mode: {['OFF', 'BLINK', 'SOLID'][mode]}") last_press = now # Apply current mode if mode == 0: led.off() elif mode == 1: led.toggle() elif mode == 2: led.on() time.sleep(0.05)

Pin Object Reference

The machine.Pin class is the primary interface for digital I/O in MicroPython. Here are the essential methods and configurations.

Method / Constant Description
Pin(n, Pin.OUT) Configure pin n as digital output
Pin(n, Pin.IN) Configure pin n as digital input (floating -- avoid)
Pin(n, Pin.IN, Pin.PULL_UP) Input with internal pull-up (default HIGH)
Pin(n, Pin.IN, Pin.PULL_DOWN) Input with internal pull-down (default LOW)
.value() Read current pin value (0 or 1)
.value(1) Set pin HIGH (output mode)
.on() / .off() Set HIGH / LOW (output mode)
.toggle() Flip current output state

Key Takeaways

  • GPIO output pins drive 3.3V (HIGH) or 0V (LOW) -- always use a current-limiting resistor with LEDs
  • GPIO input pins read HIGH or LOW -- always enable a pull-up or pull-down to avoid floating
  • Pull-down: default LOW, button connects to 3.3V. Pull-up: default HIGH, button connects to GND
  • Mechanical buttons bounce -- software debouncing with a 200ms delay prevents false triggers
  • time.ticks_ms() and time.ticks_diff() provide millisecond-accurate timing for debounce logic
  • The RP2040 can source/sink up to 12 mA per pin -- enough for LEDs but not motors or relays
