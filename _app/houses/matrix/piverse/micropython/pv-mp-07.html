Track Context:

Up to this point, all input reading has been done by polling -- checking pin values in a loop. Interrupts are a fundamentally different approach: the hardware notifies your code when something happens, even if your code is doing something else. This is how real embedded systems work -- they do not waste CPU cycles checking buttons in tight loops.

PIR Sensor Basics

A PIR (Passive Infrared) sensor detects changes in infrared radiation -- specifically, the heat signature of a person or animal moving through its detection zone. The sensor outputs a digital HIGH signal when motion is detected and returns to LOW after a timeout period (typically 2-5 seconds, adjustable via a potentiometer on the sensor board).

PIR Pin Pico Connection Notes
VCC VBUS (5V) Most PIR sensors need 5V. VBUS provides USB 5V.
OUT GP16 Digital output: HIGH = motion, LOW = no motion. 3.3V safe.
GND GND Common ground.
Warm-up Time:

PIR sensors need 30-60 seconds to calibrate when first powered on. During this period, the output may trigger randomly. Good code accounts for this by ignoring readings during the first minute after boot.

Polling vs. Interrupts

Polling means your code continuously checks a pin's value in a loop. This works but wastes CPU cycles and can miss very short events if the loop is doing other work. Interrupts are hardware-triggered: when a pin changes state, the RP2040 automatically pauses your code, runs a callback function, then resumes. No events are missed, and the CPU is free for other work between events.

Polling (Previous Modules) Check pin value every iteration. Simple to understand. Can miss fast events. CPU is always busy checking. Works fine for buttons with human-speed input.
Interrupts (This Module) Hardware triggers callback on pin change. Never misses an edge. CPU is free between events. Required for time-critical or power-sensitive applications.
# polling_vs_interrupt.py -- Side-by-side comparison from machine import Pin import time pir = Pin(16, Pin.IN) # === POLLING APPROACH === # while True: # if pir.value() == 1: # print("Motion!") # time.sleep(0.1) # Can miss events shorter than 100ms # === INTERRUPT APPROACH === def motion_handler(pin): print("Motion detected!") # Register interrupt on rising edge (LOW -> HIGH transition) pir.irq(trigger=Pin.IRQ_RISING, handler=motion_handler) # Main code is free to do other work while True: # CPU can sleep, process data, update display, etc. time.sleep(1)

Hardware Interrupts (IRQ)

The pin.irq() method registers an interrupt handler. The trigger parameter specifies which edge triggers the interrupt: rising (LOW to HIGH), falling (HIGH to LOW), or both. The handler function receives the pin object as its argument.

# irq_edges.py -- Detect both motion start and end from machine import Pin import time pir = Pin(16, Pin.IN) led = Pin(15, Pin.OUT) def pir_handler(pin): if pin.value() == 1: led.on() print("MOTION START") else: led.off() print("MOTION END") # Trigger on both edges pir.irq(trigger=Pin.IRQ_RISING | Pin.IRQ_FALLING, handler=pir_handler) print("PIR monitor running. Ctrl+C to stop.") while True: time.sleep(1)
Trigger Fires When Use Case
Pin.IRQ_RISING Pin goes LOW to HIGH Detect motion start, button press (pull-down)
Pin.IRQ_FALLING Pin goes HIGH to LOW Detect motion end, button press (pull-up)
IRQ_RISING | IRQ_FALLING Pin changes either direction Track both transitions of any signal
IRQ Handler Rules:

Interrupt handlers must be fast -- no sleep(), no heavy computation, no memory allocation. If you need to do complex processing when motion is detected, set a flag in the handler and process it in the main loop. This is called "top half / bottom half" processing.

Motion-Activated Alarm

A practical alarm system that turns on an LED and buzzer when motion is detected, with a configurable cooldown period to prevent continuous re-triggering. The interrupt sets a flag, and the main loop handles the alarm logic.

# alarm.py -- Motion-activated alarm with cooldown from machine import Pin, PWM import time pir = Pin(16, Pin.IN) led = Pin(15, Pin.OUT) buzzer = PWM(Pin(14)) # Configuration ALARM_DURATION = 3000 # Alarm sounds for 3 seconds COOLDOWN_MS = 10000 # 10 second cooldown between alarms WARMUP_MS = 60000 # 60 second sensor warmup # State variables (shared with interrupt) motion_flag = False last_alarm = 0 def motion_irq(pin): global motion_flag motion_flag = True def sound_alarm(): """Two-tone alarm for ALARM_DURATION ms.""" end = time.ticks_add(time.ticks_ms(), ALARM_DURATION) while time.ticks_diff(end, time.ticks_ms()) > 0: led.on() buzzer.freq(800) buzzer.duty_u16(32768) time.sleep_ms(200) led.off() buzzer.freq(1200) time.sleep_ms(200) buzzer.duty_u16(0) led.off() # Warmup period print("Sensor warming up...") time.sleep_ms(WARMUP_MS) print("Alarm system ACTIVE") # Register interrupt after warmup pir.irq(trigger=Pin.IRQ_RISING, handler=motion_irq) while True: if motion_flag: motion_flag = False now = time.ticks_ms() # Check cooldown if time.ticks_diff(now, last_alarm) > COOLDOWN_MS: print("ALARM! Motion detected.") sound_alarm() last_alarm = time.ticks_ms() else: remaining = COOLDOWN_MS - time.ticks_diff(now, last_alarm) print(f"Cooldown active ({remaining}ms remaining)") time.sleep(0.1)

Event Logging

Recording motion events with timestamps creates an activity log. This combines interrupts with the file I/O concepts that will be expanded in Module 9 (Data Logging). Each event is stored with its timestamp so you can review when activity occurred.

# motion_logger.py -- Log motion events with timestamps from machine import Pin import time pir = Pin(16, Pin.IN) led = Pin(15, Pin.OUT) motion_flag = False event_count = 0 def motion_irq(pin): global motion_flag motion_flag = True def log_event(message): """Append event to log file.""" global event_count event_count += 1 uptime = time.ticks_ms() // 1000 line = f"{event_count:04d},{uptime},{message}\n" with open("motion_log.csv", "a") as f: f.write(line) print(f" Logged: {line.strip()}") # Initialize log file with header with open("motion_log.csv", "w") as f: f.write("event_id,uptime_sec,type\n") print("Warming up sensor (60s)...") time.sleep(60) print("Motion logger active. Events saved to motion_log.csv") pir.irq(trigger=Pin.IRQ_RISING, handler=motion_irq) COOLDOWN = 5000 last_event = 0 while True: if motion_flag: motion_flag = False now = time.ticks_ms() if time.ticks_diff(now, last_event) > COOLDOWN: led.on() log_event("MOTION") time.sleep(0.5) led.off() last_event = now time.sleep(0.05)

Interrupt Best Practices

Keep Handlers Short Set a flag and return. Do all heavy work in the main loop. Long handlers block other interrupts and can cause missed events.
Debounce in Software PIR sensors have their own hold time, but other sensors may bounce. Check elapsed time since last trigger in the main loop, not in the handler.
Use Global Flags The handler sets a boolean flag; the main loop checks and clears it. This avoids race conditions and keeps the handler fast.
Disable During Critical Sections Use machine.disable_irq() and machine.enable_irq() to protect code that must not be interrupted (e.g., writing to flash).
# critical_section.py -- Protecting code from interrupts import machine # Disable all interrupts state = machine.disable_irq() # Critical section: this code cannot be interrupted # ... write to flash, update shared variables, etc. ... # Re-enable interrupts (restores previous state) machine.enable_irq(state)

Key Takeaways

  • PIR sensors output HIGH on motion, LOW when clear -- they need 30-60 seconds warmup at power-on
  • Interrupts (IRQ) respond to pin changes instantly without CPU polling -- set a flag in the handler, process in main loop
  • Pin.IRQ_RISING detects LOW-to-HIGH transitions; Pin.IRQ_FALLING detects HIGH-to-LOW; combine both with the OR operator
  • Interrupt handlers must be fast -- no sleep(), no file I/O, no heavy computation inside the handler
  • Cooldown timers prevent alarm fatigue by enforcing a minimum interval between triggers
  • Event logging with timestamps creates an audit trail for motion activity review
