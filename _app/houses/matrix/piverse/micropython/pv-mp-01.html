Track Context:

This is Module 1 of the MicroPython on Pico track. Before writing a single line of code, you need to understand the hardware you are programming. Every register, every pin, every bus has a purpose. Knowing the board means knowing what your software can and cannot do.

The RP2040 Microcontroller

The RP2040 is the custom silicon at the heart of every Raspberry Pi Pico. Designed by Raspberry Pi Ltd, it is built around two ARM Cortex-M0+ processor cores running at up to 133 MHz. Dual cores means the chip can execute two instruction streams simultaneously -- a significant advantage over single-core microcontrollers like the ATmega328P in the Arduino Uno.

The Cortex-M0+ is the smallest and most energy-efficient ARM processor core. It uses a 2-stage pipeline, executes most instructions in a single cycle, and supports the Thumb instruction set (16-bit compressed ARM instructions). Despite its small size, it is a 32-bit processor -- it works with 32-bit data natively, unlike 8-bit AVR microcontrollers.

Processor Dual ARM Cortex-M0+ @ 133 MHz
SRAM 264 KB in 6 independent banks
Flash 2 MB external QSPI (Pico board)
GPIO 30 multi-function GPIO pins
ADC 4 channels, 12-bit, 500 ksps
PIO 2 Programmable I/O blocks (8 state machines)

The 264 KB of SRAM is split across six independent banks. This is not just a design detail -- it means both cores and DMA controllers can access different banks simultaneously without bus contention. The flash memory is external to the RP2040 die and connected via a QSPI (Quad SPI) bus, which provides four data lines instead of one for faster read speeds.

Why Dual Cores Matter:

In MicroPython, the second core is accessible via the _thread module. One core can handle sensor readings while the other manages display updates or communication -- genuine hardware parallelism, not just time-slicing.

Pico Board Layout

The Raspberry Pi Pico exposes the RP2040's capabilities through a 40-pin DIP (Dual Inline Package) form factor. The board measures 51mm x 21mm and is designed to be soldered into a breadboard or connected via pre-soldered headers.

The 40-pin header exposes 26 GPIO pins, 3 analog input pins, power pins (VBUS, VSYS, 3V3), ground pins, and special pins like 3V3_EN (enable pin for the voltage regulator) and ADC_VREF (reference voltage for the analog-to-digital converter). The three debug pins at the bottom of the board (SWCLK, SWDIO, GND) are for SWD debugging with a hardware probe.

Pin Types and Functions

Every pin on the Pico has a primary function and potentially multiple alternate functions. Understanding these categories is essential before wiring anything.

Pin Type Pins Description
GPIO (Digital) GP0 - GP28 General-purpose digital I/O. Each can be input or output, with configurable pull-up/pull-down.
ADC (Analog In) GP26, GP27, GP28 12-bit ADC inputs (ADC0, ADC1, ADC2). GP29/ADC3 reads VSYS/3 on the board.
PWM All GPIO pins Every GPIO pin supports hardware PWM (16 channels, 8 slices x 2 outputs).
I2C GP0/GP1, GP4/GP5, etc. Two I2C controllers (I2C0, I2C1) mappable to several pin pairs.
SPI GP0-GP7, GP16-GP19 Two SPI controllers (SPI0, SPI1) mappable to specific pin groups.
UART GP0/GP1, GP4/GP5, etc. Two UART interfaces (UART0, UART1) for serial communication.
Power VBUS, VSYS, 3V3, 3V3_EN VBUS = USB 5V, VSYS = system input (1.8-5.5V), 3V3 = regulated output.
Ground 8 GND pins Common ground. Always connect ground between Pico and external circuits.
Pin Multiplexing:

A single GPIO pin can serve as digital I/O, PWM, UART, SPI, or I2C -- but only one function at a time. The function is selected in software by configuring the pin's function register. In MicroPython, this happens automatically when you create a Pin, PWM, I2C, or SPI object.

BOOTSEL and Firmware Flashing

The BOOTSEL (Boot Select) button is a physical button on the Pico board that puts the RP2040 into USB mass storage mode. When you hold BOOTSEL while plugging in the USB cable, the Pico appears as a removable drive named RPI-RP2 on your computer. This is how you load firmware -- including MicroPython itself.

The UF2 (USB Flashing Format) file format was designed by Microsoft for flashing microcontrollers via USB mass storage. The Pico's bootloader reads the .uf2 file, writes it to flash memory, and automatically reboots. No special software or programmer hardware is needed -- just a USB cable and a file manager.

Recovery Path:

If your Pico becomes unresponsive or you need to wipe MicroPython, you can always return to BOOTSEL mode by holding the button and reconnecting USB. This is a hardware-level recovery that cannot be bricked by software. Even if your code crashes in an infinite loop, BOOTSEL always works.

USB and Power

The Pico's micro-USB port serves dual purposes: power delivery and data communication. When connected to a computer, the USB connection provides 5V power and a serial link that MicroPython uses as its REPL (Read-Eval-Print Loop) console.

Power Source Voltage Use Case
USB (VBUS) 5V Development -- power and data via single cable
VSYS pin 1.8V - 5.5V Battery or external supply for standalone projects
3V3 pin 3.3V output Powers external 3.3V sensors and peripherals (max 300mA)

The on-board switching regulator converts VBUS or VSYS down to 3.3V. The 3V3_EN pin controls this regulator -- pulling it low disables the 3.3V output and puts the Pico in a very low power state. For battery-powered projects, you feed voltage into VSYS rather than USB.

Pico vs. Pico W

The Pico W adds an Infineon CYW43439 wireless chip that provides 2.4 GHz Wi-Fi (802.11n) and Bluetooth 5.2 (including BLE). The wireless chip connects to the RP2040 via SPI, using GP23, GP24, and GP25 internally. This means GP25 -- which drives the on-board LED on the original Pico -- is not available on the Pico W. Instead, the LED is controlled through the wireless chip's GPIO.

Pico (Original) No wireless. On-board LED on GP25. Lower cost. Ideal for wired projects, learning GPIO, and applications where wireless is unnecessary.
Pico W Wi-Fi + Bluetooth 5.2. LED via wireless chip (not GP25). Required for IoT, web servers, and remote data collection projects.
Code Difference:

On the original Pico, you blink the LED with Pin(25, Pin.OUT). On the Pico W, the LED is accessed via Pin("LED", Pin.OUT). This distinction matters when writing portable code.

The PIO Subsystem

One of the RP2040's most distinctive features is its Programmable I/O (PIO) subsystem. The chip contains two PIO blocks, each with four state machines. These state machines execute tiny assembly-like programs independently of the main CPU cores, allowing the RP2040 to implement custom communication protocols at hardware speed.

PIO programs are written in a special 9-instruction assembly language. Each state machine has a 32-instruction memory, shift registers, and configurable clock dividers. This is how the RP2040 can bit-bang protocols like WS2812 (NeoPixel), VGA video, and DPI displays without consuming CPU cycles.

Why PIO Matters:

Traditional microcontrollers are limited to the communication protocols built into their hardware (UART, SPI, I2C). PIO lets the RP2040 implement virtually any digital protocol in hardware. This is an advanced topic covered later, but understanding that PIO exists helps explain why the Pico can do things other microcontrollers in its price range cannot.

Key Takeaways

  • The RP2040 has dual Cortex-M0+ cores at 133 MHz with 264 KB of SRAM in 6 banks
  • The Pico board has 40 pins: 26 GPIO, 3 ADC, power, ground, and debug
  • Every GPIO pin supports multiple functions (digital, PWM, UART, SPI, I2C) but only one at a time
  • BOOTSEL mode is a hardware-level recovery that always works -- it cannot be bricked by software
  • The Pico W adds Wi-Fi and Bluetooth but reassigns GP25 -- LED access code differs between variants
  • The PIO subsystem provides 8 programmable state machines for custom hardware-speed protocols
