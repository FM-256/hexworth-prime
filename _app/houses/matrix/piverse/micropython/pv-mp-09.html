Data Logging

Learning Objectives

  • Write data to the Pico's internal flash filesystem in CSV format
  • Implement a robust logging system that survives power loss
  • Track elapsed time as a timestamp for each reading
  • Manage limited storage space with file rotation and size checks
  • Retrieve logged data for analysis on a computer
Track Context:

Collecting data without recording it is like running an experiment without a lab notebook. Data logging turns your Pico from a real-time monitor into a portable data collection platform. Leave it running overnight, collect in the morning, analyze on your computer. This is how real environmental monitoring, field research, and industrial telemetry work.

File I/O on the Pico

MicroPython provides standard Python file I/O using open(), read(), write(), and close(). Files are stored on the Pico's flash filesystem. The filesystem is typically 1.4 MB after MicroPython firmware uses its share of the 2 MB flash.

# file_basics.py -- File I/O operations on the Pico import os # List all files print("Files:", os.listdir()) # Write a file with open("test.txt", "w") as f: f.write("Line 1\n") f.write("Line 2\n") # Append to a file with open("test.txt", "a") as f: f.write("Line 3 (appended)\n") # Read entire file with open("test.txt", "r") as f: content = f.read() print(content) # Read line by line (memory-efficient for large files) with open("test.txt", "r") as f: for line in f: print(">", line.strip()) # Check file size and filesystem space stat = os.stat("test.txt") print(f"File size: {stat[6]} bytes") vfs = os.statvfs("/") block_size = vfs[0] free = vfs[3] * block_size total = vfs[2] * block_size print(f"Storage: {free // 1024} KB free / {total // 1024} KB total") # Delete a file os.remove("test.txt")

CSV Temperature Logger

CSV (Comma-Separated Values) is the simplest structured data format. Each row is a record, columns are separated by commas, and the first row is usually a header. CSV files can be opened directly in any spreadsheet application for analysis and charting.

# temp_logger.py -- Log temperature readings to CSV from machine import ADC, Pin import time import os sensor = ADC(4) led = Pin("LED", Pin.OUT) LOG_FILE = "temp_log.csv" INTERVAL_SEC = 30 # Log every 30 seconds MAX_FILE_SIZE = 500000 # ~500 KB max per log file def read_temp(samples=16): total = 0 for _ in range(samples): total += sensor.read_u16() raw = total // samples voltage = raw * 3.3 / 65535 return round(27 - (voltage - 0.706) / 0.001721, 1) def file_size(filename): try: return os.stat(filename)[6] except: return 0 def init_log(): """Create log file with header if it doesn't exist.""" if LOG_FILE not in os.listdir(): with open(LOG_FILE, "w") as f: f.write("reading,uptime_sec,temp_c,temp_f\n") print(f"Created {LOG_FILE}") else: size = file_size(LOG_FILE) print(f"Resuming {LOG_FILE} ({size} bytes)") init_log() reading_num = 0 start_time = time.ticks_ms() print(f"Logging every {INTERVAL_SEC}s. Ctrl+C to stop.\n") while True: reading_num += 1 uptime = time.ticks_diff(time.ticks_ms(), start_time) // 1000 temp_c = read_temp() temp_f = round(temp_c * 9 / 5 + 32, 1) # Write to CSV line = f"{reading_num},{uptime},{temp_c},{temp_f}\n" with open(LOG_FILE, "a") as f: f.write(line) # Blink LED to confirm write led.on() time.sleep_ms(50) led.off() print(f"[{reading_num:4d}] {temp_c}C / {temp_f}F ({uptime}s uptime)") # Check file size if file_size(LOG_FILE) > MAX_FILE_SIZE: print("Log file reached max size. Stopping.") break time.sleep(INTERVAL_SEC)

Robust Logging: Surviving Power Loss

Flash writes on the Pico are not instantaneous. If power is lost during a write, the file can become corrupted. Two strategies protect against this: flushing after each write (ensures data reaches flash) and using append mode (existing data is preserved even if the last write is incomplete).

# robust_logger.py -- Power-safe data logging from machine import ADC import time import os sensor = ADC(4) LOG_FILE = "data.csv" def safe_write(filename, line): """Append a line to file with explicit flush.""" f = open(filename, "a") f.write(line) f.flush() # Force buffer to filesystem os.sync() # Force filesystem to flash (if available) f.close() def count_lines(filename): """Count existing lines to resume numbering.""" try: count = 0 with open(filename, "r") as f: for _ in f: count += 1 return max(0, count - 1) # Subtract header row except: return 0 # Resume from existing log or create new existing = count_lines(LOG_FILE) if existing == 0: safe_write(LOG_FILE, "id,uptime_s,temp_c\n") print("New log created.") else: print(f"Resuming log with {existing} existing entries.") reading = existing while True: reading += 1 uptime = time.ticks_ms() // 1000 raw = sensor.read_u16() v = raw * 3.3 / 65535 temp = round(27 - (v - 0.706) / 0.001721, 1) safe_write(LOG_FILE, f"{reading},{uptime},{temp}\n") print(f"[{reading}] {temp}C") time.sleep(10)

File Rotation

With limited flash storage, you need a strategy for managing log files. File rotation renames the current log and starts a new one when it reaches a size limit. This keeps the most recent data accessible while preserving history.

# log_rotation.py -- Rotate log files when they get too large import os MAX_SIZE = 200000 # 200 KB per log file MAX_FILES = 5 # Keep 5 log files max BASE_NAME = "data" def rotate_logs(): """Rotate log files: data.csv -> data_1.csv -> data_2.csv ...""" # Delete oldest if at max oldest = f"{BASE_NAME}_{MAX_FILES}.csv" if oldest in os.listdir(): os.remove(oldest) # Shift existing files up by 1 for i in range(MAX_FILES - 1, 0, -1): old_name = f"{BASE_NAME}_{i}.csv" new_name = f"{BASE_NAME}_{i + 1}.csv" if old_name in os.listdir(): os.rename(old_name, new_name) # Current log becomes _1 current = f"{BASE_NAME}.csv" if current in os.listdir(): os.rename(current, f"{BASE_NAME}_1.csv") def check_and_rotate(): """Rotate if current log exceeds MAX_SIZE.""" current = f"{BASE_NAME}.csv" try: size = os.stat(current)[6] if size > MAX_SIZE: print(f"Rotating logs ({size} bytes > {MAX_SIZE})") rotate_logs() # Create new log with header with open(current, "w") as f: f.write("id,uptime_s,temp_c\n") return True except: pass return False

Multi-Sensor Logger

A practical data logger reads multiple sensors and records all values in each CSV row. This example logs temperature and light level (from an LDR on ADC0) with configurable interval.

# multi_logger.py -- Log temperature + light to CSV from machine import ADC, Pin import time import os temp_sensor = ADC(4) # Internal temp light_sensor = ADC(Pin(26)) # LDR on GP26 led = Pin("LED", Pin.OUT) LOG_FILE = "environment.csv" INTERVAL = 15 # seconds def read_temp(): raw = sum(temp_sensor.read_u16() for _ in range(16)) // 16 v = raw * 3.3 / 65535 return round(27 - (v - 0.706) / 0.001721, 1) def read_light(): raw = sum(light_sensor.read_u16() for _ in range(16)) // 16 return round(raw * 100 / 65535, 1) # Percentage # Initialize if LOG_FILE not in os.listdir(): with open(LOG_FILE, "w") as f: f.write("reading,uptime_s,temp_c,light_pct\n") n = 0 print("Multi-sensor logger started.") while True: n += 1 uptime = time.ticks_ms() // 1000 temp = read_temp() light = read_light() line = f"{n},{uptime},{temp},{light}\n" with open(LOG_FILE, "a") as f: f.write(line) led.on(); time.sleep_ms(30); led.off() print(f"[{n:4d}] Temp:{temp}C Light:{light}%") time.sleep(INTERVAL)

Retrieving Data

After a logging session, connect the Pico to your computer and use Thonny's file manager to download the CSV files. Alternatively, read the file over the REPL and copy/paste the output, or use Thonny's "Download" button in the Files panel.

# read_log.py -- Display logged data over REPL import os filename = "temp_log.csv" if filename in os.listdir(): size = os.stat(filename)[6] print(f"File: {filename} ({size} bytes)\n") with open(filename, "r") as f: for line in f: print(line.strip()) else: print("No log file found.")
Data Analysis Tip:

Once you download the CSV to your computer, open it in a spreadsheet (Excel, Google Sheets, LibreOffice Calc) or use Python with pandas and matplotlib to create time-series charts. The CSV format is universally compatible with data analysis tools.

Key Takeaways

  • The Pico has ~1.4 MB of user-accessible flash storage for files -- enough for thousands of sensor readings
  • CSV format (comma-separated values) is the simplest way to log structured data that opens in any spreadsheet
  • Use append mode ("a") so existing data is preserved even if the program restarts after power loss
  • Call f.flush() after writes to ensure data reaches flash -- unflushed data lives only in RAM
  • File rotation prevents a single log from filling all available storage
  • Use Thonny's file manager or the REPL to retrieve logged data for analysis on your computer
