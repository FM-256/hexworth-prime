Hardware Requirement:

This module requires a Pico W (with WiFi). The original Pico does not have wireless hardware. If you are using an original Pico, read through the concepts and code for understanding -- the networking knowledge applies when you move to a Pico W or other WiFi-capable microcontroller.

Connecting to WiFi

The Pico W's CYW43439 wireless chip supports 2.4 GHz WiFi (802.11b/g/n). MicroPython provides the network module to manage WiFi connections. The connection process: activate the interface, scan for networks (optional), connect with SSID and password, wait for DHCP to assign an IP address.

# wifi_connect.py -- Connect Pico W to WiFi import network import time # WiFi credentials SSID = "YourNetworkName" PASSWORD = "YourPassword" # Create WiFi station interface wlan = network.WLAN(network.STA_IF) wlan.active(True) # Connect print(f"Connecting to {SSID}...") wlan.connect(SSID, PASSWORD) # Wait for connection (timeout after 10 seconds) timeout = 10 while timeout > 0: if wlan.isconnected(): break time.sleep(1) timeout -= 1 print(f" Waiting... ({timeout}s)") if wlan.isconnected(): config = wlan.ifconfig() print("Connected!") print(f" IP Address: {config[0]}") print(f" Subnet Mask: {config[1]}") print(f" Gateway: {config[2]}") print(f" DNS: {config[3]}") else: print("Connection failed.")
Security Note:

Never hardcode WiFi credentials in main.py on a shared device. Store them in a separate config.py file or use the REPL to set them. If your Pico is connected to USB, anyone with Thonny can read your files and see the password.

Making HTTP Requests

Once connected to WiFi, the Pico W can make HTTP requests to web APIs. MicroPython includes the urequests module for simple HTTP GET and POST operations. This lets the Pico fetch data from the internet -- weather, time, or any REST API.

# http_get.py -- Fetch data from a web API import urequests import ujson # Fetch current time from a public API url = "http://worldtimeapi.org/api/ip" print(f"Fetching: {url}") response = urequests.get(url) if response.status_code == 200: data = response.json() print(f"Timezone: {data['timezone']}") print(f"DateTime: {data['datetime']}") else: print(f"Error: HTTP {response.status_code}") response.close() # Always close to free memory
# http_post.py -- Send sensor data to a server import urequests import ujson from machine import ADC sensor = ADC(4) def read_temp(): raw = sum(sensor.read_u16() for _ in range(16)) // 16 v = raw * 3.3 / 65535 return round(27 - (v - 0.706) / 0.001721, 1) # POST sensor data as JSON temp = read_temp() payload = ujson.dumps({ "device": "pico-w-01", "temp_c": temp, "type": "temperature" }) # Replace with your server URL url = "http://192.168.1.100:5000/api/data" headers = {"Content-Type": "application/json"} try: response = urequests.post(url, data=payload, headers=headers) print(f"Response: {response.status_code}") response.close() except Exception as e: print(f"POST failed: {e}")

Building a Web Server

The Pico W can also act as a web server -- it listens for incoming HTTP requests and responds with HTML pages. This turns the Pico into a standalone IoT device that any browser on the local network can access to read sensor data or control outputs.

# web_server.py -- Serve sensor data as a web page import network import socket import time from machine import ADC, Pin # Connect to WiFi first (using wifi_connect code) wlan = network.WLAN(network.STA_IF) wlan.active(True) wlan.connect("YourSSID", "YourPassword") while not wlan.isconnected(): time.sleep(1) ip = wlan.ifconfig()[0] print(f"Server running at http://{ip}") sensor = ADC(4) led = Pin("LED", Pin.OUT) def read_temp(): raw = sum(sensor.read_u16() for _ in range(16)) // 16 v = raw * 3.3 / 65535 return round(27 - (v - 0.706) / 0.001721, 1) def build_html(temp): return f"""HTTP/1.0 200 OK\r\nContent-Type: text/html\r\n\r\n <!DOCTYPE html><html> <head><title>Pico W Sensor</title> <meta http-equiv="refresh" content="5"> <style> body {{ font-family: sans-serif; background: #1a1a2e; color: #eee; display: flex; justify-content: center; padding-top: 60px; }} .card {{ background: #16213e; padding: 40px; border-radius: 12px; border: 1px solid #c51a4a; text-align: center; }} h1 {{ color: #c51a4a; margin-bottom: 20px; }} .temp {{ font-size: 3rem; font-weight: bold; color: #fff; }} .label {{ color: #888; margin-top: 10px; }} </style></head> <body><div class="card"> <h1>Pico W Temperature</h1> <div class="temp">{temp} C</div> <div class="label">Auto-refreshes every 5 seconds</div> </div></body></html>""" # Create TCP socket server on port 80 addr = socket.getaddrinfo(ip, 80)[0][-1] s = socket.socket() s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1) s.bind(addr) s.listen(1) print("Listening on port 80...") while True: try: client, client_addr = s.accept() request = client.recv(1024).decode() led.on() temp = read_temp() response = build_html(temp) client.send(response) client.close() led.off() print(f"Served {client_addr[0]} - Temp: {temp}C") except Exception as e: print(f"Error: {e}")

TCP/IP Fundamentals

Understanding the network stack helps you debug connectivity issues and build more sophisticated applications.

Concept Description
IP Address Unique identifier for a device on the network (e.g., 192.168.1.42). Assigned by DHCP from the router.
Port Number (0-65535) that identifies a specific service. HTTP uses port 80, HTTPS uses 443.
TCP Reliable, ordered delivery. Used for HTTP, where every byte must arrive correctly.
UDP Fast, unreliable delivery. Used for real-time data where speed matters more than completeness.
HTTP Application protocol over TCP. Client sends a request (GET /path), server sends a response (200 OK + body).
Socket Programming interface for network communication. Create, bind, listen, accept, send, receive, close.

Connection Resilience

WiFi connections drop. Good IoT code reconnects automatically and handles network errors gracefully.

# wifi_resilient.py -- Auto-reconnecting WiFi helper import network import time class WiFiManager: def __init__(self, ssid, password): self.ssid = ssid self.password = password self.wlan = network.WLAN(network.STA_IF) def connect(self, timeout=15): if self.wlan.isconnected(): return True self.wlan.active(True) self.wlan.connect(self.ssid, self.password) for _ in range(timeout): if self.wlan.isconnected(): print(f"WiFi connected: {self.ip}") return True time.sleep(1) print("WiFi connection failed.") return False def ensure_connected(self): if not self.wlan.isconnected(): print("WiFi lost. Reconnecting...") self.wlan.disconnect() time.sleep(1) return self.connect() return True @property def ip(self): return self.wlan.ifconfig()[0] # Usage wifi = WiFiManager("YourSSID", "YourPassword") wifi.connect() # In main loop, periodically check: # wifi.ensure_connected()

Key Takeaways

  • The Pico W connects to WiFi using the network.WLAN module -- requires SSID and password
  • urequests provides HTTP GET and POST for fetching data from and sending data to web servers
  • The Pico W can act as a web server using raw socket programming -- serve HTML to any browser on the network
  • Always close HTTP responses and sockets to free limited RAM on the microcontroller
  • WiFi connections drop -- production IoT code must detect disconnection and reconnect automatically
  • Never hardcode WiFi credentials in shared code -- use a separate config file
