From Pi to Pico: Why the RP2040?
The Raspberry Pi runs Linux on a Cortex-A application processor. The RP2040 is a microcontroller -- no OS, bare metal, real-time.
Cortex-A (Pi 5)
Application processor. Runs Linux. 2.4 GHz quad-core. 4-8 GB external RAM. Full OS with file system, networking, multitasking. Power: 2-5W.
Cortex-M0+ (RP2040)
Microcontroller. Bare metal or RTOS. 133 MHz dual-core. 264 KB on-chip SRAM. No OS -- your code runs directly on hardware. Power: ~25mA at 48 MHz.
Why This Matters for Board Design
A microcontroller needs fewer external components than an application processor. No external RAM, no display pipeline, no complex power management IC. The RP2040 needs: one crystal, one flash chip, a few capacitors, and a voltage regulator. That simplicity makes it the perfect chip for learning PCB design.

ARM Cortex-M0+ Architecture
The smallest, lowest-power ARM core. Two of them on one chip.
Dual Core
Two independent M0+ cores with separate stack pointers and program counters. Core 0 boots first, can wake Core 1.
ARMv6-M ISA
56 base instructions. 2-stage pipeline. Most instructions execute in one cycle. Thumb-2 encoding for code density.
133 MHz Max
Default 125 MHz from 12 MHz crystal via PLL. Overclockable beyond 250 MHz in many cases (no guarantees).
Dual-Core Pattern
Core 0 handles communication (USB, UART, I2C). Core 1 runs a tight real-time control loop. They share 264 KB SRAM via a striped bus arbiter -- both cores can access memory simultaneously without bus contention on different banks.
Slide 4 of 12
PIO State Machines
Programmable I/O: the RP2040's secret weapon. Eight tiny processors that manipulate GPIO pins at clock speed.
2 PIO Blocks, 4 State Machines Each
Each state machine runs a program of up to 32 instructions. Programs execute at up to 133 MHz independently of the CPU cores. Zero jitter.
9-Instruction ISA
JMP, WAIT, IN, OUT, PUSH, PULL, MOV, IRQ, SET. That is the entire PIO instruction set. Each instruction takes exactly one cycle plus configurable delays.
; PIO program: drive WS2812B NeoPixel LEDs .program ws2812 .side_set 1 .wrap_target bitloop: out x, 1 side 0 [T3-1] ; Shift 1 bit from OSR to X jmp !x do_zero side 1 [T1-1] ; Drive high, branch on value do_one: jmp bitloop side 1 [T2-1] ; Bit=1: stay high longer do_zero: nop side 0 [T2-1] ; Bit=0: go low earlier .wrap
Board Design Impact
PIO means the RP2040 can bit-bang nearly any digital protocol: WS2812B, VGA, DPI, custom serial, even DVI/HDMI. This affects your PCB because you can route almost any GPIO to almost any function -- the pin assignment is extremely flexible.

RP2040 Memory Map
A flat 32-bit address space. Everything -- flash, RAM, peripherals, boot ROM -- lives in one contiguous map.

External Flash and XIP
The RP2040 has zero internal flash. All code lives on an external QSPI flash chip.
QSPI Interface
Four data lines (QSPI) instead of one (SPI). 4x bandwidth. The RP2040 dedicates 6 pins to flash: SCLK, SS, SD0-SD3. These are NOT general-purpose GPIO.
Execute-in-Place (XIP)
The XIP cache makes flash look like internal memory. Code executes directly from flash addresses (0x10000000+). A 16 KB cache reduces flash access latency.
PCB Design Implication
The flash chip must be placed close to the RP2040 with short, matched-length traces. QSPI runs at high speed -- long traces or poor routing will cause read errors. The Pico uses a Winbond W25Q16JV (2 MB). For custom boards, you can use up to 16 MB.
Slide 7 of 12
SRAM Architecture
264 KB of on-chip SRAM split across 6 banks for concurrent access.
Bank 0-3 (64 KB each)
Main SRAM. Striped across 4 banks so both cores can access different banks simultaneously without contention.
Bank 4-5 (4 KB each)
Small banks typically used for stack or critical data. Can also be assigned to USB or other peripherals.
No External RAM
Unlike the Pi with gigabytes of LPDDR4X, the RP2040 has only on-chip SRAM. This simplifies PCB design -- no DDR routing, no impedance matching for RAM.
Why Striped Banks Matter
The bus arbiter stripes consecutive 32-bit words across banks. Word at 0x20000000 is in bank 0, word at 0x20000004 is in bank 1, and so on. This means Core 0 and Core 1 accessing sequential memory rarely collide. It is hardware-level concurrency without software effort.
Slide 8 of 12
Boot Sequence
From power-on to your code running: a deterministic four-step process.
1 Boot ROM executes. Core 0 starts at address 0x00000000. Core 1 is held in sleep (WFE). The boot ROM is mask-programmed at the factory -- it cannot be modified.
2 Check external flash. Boot ROM reads the first 256 bytes of flash. It verifies a CRC32 checksum to confirm the second-stage bootloader is valid.
3 Second-stage boot. This 256-byte program configures the QSPI flash for XIP mode. It is chip-specific -- different flash chips need different configuration sequences.
4 User code runs. Execution jumps to the main application. If using the Pico SDK, this enters the C runtime init (crt0) before calling main(). Your program takes over.
BOOTSEL Mode
If the BOOTSEL button is held during power-on, the boot ROM skips flash and presents the RP2040 as a USB mass storage device. Drag-and-drop a UF2 file to program it. No special programmer hardware needed. This is why you need a button connected to the QSPI_SS pin on your custom board.
Slide 9 of 12
GPIO and Pin Multiplexing
30 general-purpose GPIO pins, each configurable for multiple functions.
30 GPIO Pins (GP0-GP29)
Each pin can be: SPI, UART, I2C, PWM, PIO, ADC (GP26-GP29 only), or plain digital I/O. Function is selected via peripheral mux registers.
6 Dedicated Pins
QSPI_SCLK, QSPI_SS, QSPI_SD0-SD3 are permanently assigned to the external flash interface. They are not available as GPIO.
Design Flexibility
Unlike many microcontrollers with rigid pin assignments, the RP2040 lets you put UART, SPI, or I2C on almost any pin combination. PIO makes it even more flexible. When designing your PCB, you choose pin assignments based on routing convenience, not chip limitations.

On-Ramp: Schematics and PCBs
Bridging from breadboards to board engineering.
Schematic
A diagram of electrical connections using standardized symbols. Shows WHAT connects to WHAT. Does not show physical layout, size, or shape. It is the blueprint.
PCB (Printed Circuit Board)
The physical board with copper traces replacing jumper wires. Shows WHERE components sit and HOW traces route between them. It is the building.
The Workflow
Design the schematic first (logical connections), then lay out the PCB (physical arrangement). The schematic drives the PCB -- every connection in the schematic becomes a trace or via on the board. You cannot skip the schematic and go straight to PCB layout.

Why Not Just Use a Breadboard?
Breadboards work for prototypes but fail for production. Here is why.
Unreliable Connections
Spring contacts corrode, loosen, and intermittently disconnect. A production device cannot use push-fit connections.
Parasitic Capacitance
Breadboard rows act as tiny capacitors. Above 10-20 MHz, signals degrade. USB, SPI at speed, and anything RF is impossible on a breadboard.
No Shielding
Open wires radiate electromagnetic interference. A PCB with ground planes contains EMI and passes regulatory certification.
Size and Weight
A breadboard prototype is 10x the size of the equivalent PCB. For any embedded product, size matters.
Bottom Line
A breadboard is a sketch. A PCB is the finished painting. This track teaches you to create the painting.

Key Takeaways: Inside the RP2040
The chip is understood. Now you are ready to read the schematic that surrounds it.
1Dual-core Cortex-M0+ at 133 MHz. No OS, bare metal, 264 KB on-chip SRAM, external QSPI flash. The simplicity makes PCB design approachable.
2PIO state machines execute tiny programs at clock speed, driving any digital protocol without CPU involvement. 8 state machines across 2 PIO blocks.
3Flat 32-bit memory map. Flash at 0x10000000, SRAM at 0x20000000, peripherals at 0x40000000+. Everything is memory-mapped.
4Boot sequence: ROM checks flash CRC, runs second-stage bootloader, jumps to user code. BOOTSEL mode enables drag-and-drop programming.
