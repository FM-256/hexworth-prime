USB HID Protocol
Human Interface Device -- the USB class that lets the controller work without custom drivers.
What is HID?
USB HID is a device class defined in the USB specification. Keyboards, mice, and gamepads all use HID. The operating system has built-in HID drivers, so your device works the instant you plug it in -- no software installation required.
HID Report Descriptor
A data structure that tells the host what inputs the device has: how many buttons, how many axes, their value ranges. The RP2040 firmware defines this descriptor using TinyUSB. The host parses it to understand your controller's layout.
RP2040 USB Advantage
The RP2040 has a built-in USB 1.1 PHY. No external USB controller chip needed. Combined with the TinyUSB library, implementing a gamepad HID device takes about 50 lines of configuration code. The hardware handles low-level USB signaling. You focus on the application logic.

Controller Specification
Define the inputs before designing the PCB.
12 Buttons
4 face buttons (A/B/X/Y), 4 directional pad buttons, 2 shoulder buttons, Start, Select. Each is a tactile switch (SKQG series or similar). Active low with internal pull-ups.
2 Analog Joysticks
Each joystick has two potentiometers (X and Y axis) connected to ADC inputs. Four analog channels total: GP26 (LX), GP27 (LY), GP28 (RX), GP29 (RY). 10-bit resolution (0-1023).
USB-C Connection
USB-C for durability and reversible insertion. Bus-powered (no external supply). Total current draw under 100mA -- well within USB spec. The entire controller runs from the 5V USB VBUS.

Button Matrix vs Direct GPIO
With 12 buttons and 30 GPIO pins, you have a choice: direct wiring or matrix scanning.
Direct GPIO (Simpler)
Each button connects to its own GPIO pin. 12 buttons = 12 GPIO pins. Simple code: digitalRead each pin. No ghosting issues. Best when you have enough pins, which the RP2040 does.
Matrix Scanning (Saves Pins)
Arrange buttons in a grid (e.g., 4 rows x 3 columns = 7 GPIO for 12 buttons). Scan rows sequentially, read columns. Saves pins but adds code complexity and potential ghosting. Add diodes for N-key rollover.
Our Choice: Direct GPIO
The RP2040 has 30 GPIO pins. We use 4 for ADC (joysticks), 2 for USB (D+/D-), 6 for QSPI (flash). That leaves 18 free GPIO. 12 buttons fit easily with direct wiring. No matrix, no diodes, no ghosting. Simpler PCB, simpler code, faster response.

Analog Joystick Circuit
Each joystick axis is a potentiometer forming a voltage divider.
Wiring
Potentiometer: one end to 3.3V, other end to GND, wiper to ADC input. As the stick moves, the wiper voltage varies from 0V to 3.3V. The ADC reads this as 0 to 4095 (12-bit) or 0 to 1023 (10-bit).
Filtering
A 100nF capacitor from the ADC pin to ground filters high-frequency noise. A 1K series resistor between the potentiometer wiper and the ADC pin limits inrush current and provides additional RC filtering.
ADC Reference
The RP2040 ADC uses IOVDD (3.3V) as its reference by default. The ADC_AVDD pin needs its own 1uF decoupling cap for clean readings. Noisy ADC readings cause joystick jitter. Route ADC traces away from switching signals and use a ground pour underneath.

PCB Shape Design
A game controller PCB is not rectangular. The board shape IS the product.
Custom Outline
The Edge.Cuts layer defines the controller shape. Use bezier curves for ergonomic grips. The PCB itself forms the controller body -- no separate enclosure needed for a prototype. Mounting holes at stress points.
Button Placement
Tactile switches solder to the PCB surface. Their position IS the button position. D-pad buttons in a cross pattern on the left. Face buttons in a diamond pattern on the right. This means the schematic placement follows ergonomic layout, not electrical convenience.
Board Thickness
Standard 1.6mm FR-4 works for a handheld controller. For a thinner feel, JLCPCB offers 0.8mm and 1.0mm boards. Thinner boards flex more, which can be an issue with repeated button presses. Add mounting standoffs and a bottom plate for rigidity.

Power Design
A USB gamepad is the simplest power design possible.
USB Bus Powered
5V from USB VBUS. AP2112K LDO drops to 3.3V for the RP2040 and peripherals. Total current: ~30-50mA (RP2040) + ~5mA (LEDs) + ~2mA (joystick pots). Well under USB 500mA limit.
No Battery, No Motor
Unlike the motor controller, there is no high-current secondary power domain. No switching converter noise. A simple LDO with proper decoupling is all you need. The simplest power design in this entire track.

USB Routing Revisited
The USB connection is the only critical signal path on this board.
1USB-C connector at top center. Cable exits straight up. CC1 and CC2 pins need 5.1K pull-down resistors to identify the device as a USB device (not a host).
2ESD protection IC (USBLC6-2SC6) placed within 5mm of the connector. Protects against static discharge from cable insertion.
327-ohm series resistors on D+ and D-, placed within 10mm of the RP2040. Match USB PHY output impedance to trace impedance.
490-ohm differential pair routed directly from connector to resistors to RP2040. No layer changes. Length matched within 2mm. Ground plane continuous underneath.

Status LEDs
Visual feedback for the user: power on, USB connected, button press indicators.
Power LED
Green LED on 3.3V rail with 1K series resistor. Always on when the controller is powered. Confirms the LDO is working and the board has power.
USB Activity LED
Connected to a GPIO pin. Firmware blinks it when USB HID reports are being sent. Confirms the USB connection is active and the host is reading input data.
Player Indicator LEDs
Optional: 4 LEDs for player number (like Xbox controllers). Connected to GPIO via 1K resistors. Firmware lights the correct LED based on the HID player assignment.

Firmware Architecture
How the RP2040 firmware turns button presses into USB HID reports.
1Initialize TinyUSB. Configure as HID gamepad device. Define report descriptor: 12 buttons (1 bit each), 4 axes (8 bits each). Set polling interval to 1ms for minimal latency.
2Main loop: scan inputs. Read 12 GPIO pins for buttons. Read 4 ADC channels for joystick axes. Pack results into a HID report structure.
3Send HID report. Call tud_hid_gamepad_report() with the packed data. TinyUSB handles USB protocol, ACK/NAK, and bus scheduling. The host receives the report and updates the game input state.
4Debouncing. Apply 5ms debounce to button inputs. Either timer-based or integration-based. Prevents a single physical press from registering as multiple presses.

Manufacturing Considerations
Unique challenges for a custom-shaped controller PCB.
Custom Board Outline
Non-rectangular outlines cost more to route at the fab. V-scoring only works for straight edges. For curves, the fab uses a milling bit. JLCPCB handles custom outlines at no extra charge up to moderate complexity.
Through-Hole Components
Joystick modules and some tactile switches are through-hole. If using JLCPCB assembly, through-hole components may need to be hand-soldered after SMD assembly. Plan your assembly in two stages: SMD reflow first, THT hand soldering second.
Enclosure Integration
For a production controller, the PCB mounts inside a plastic shell. Add mounting holes that align with the enclosure bosses. Use standoffs for spacing. The silkscreen on the top layer shows button labels visible through the enclosure cutouts. Design the PCB and enclosure together.
