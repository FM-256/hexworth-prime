From Pi to Pico: Why the RP2040?

The Raspberry Pi runs Linux on a powerful Cortex-A application processor. The RP2040 is a microcontroller -- no operating system, no file system, no multitasking kernel. Your code runs directly on the hardware. This makes it faster for real-time tasks, lower power, and cheaper ($0.80 per chip), but it requires a fundamentally different approach to programming and hardware design.

This track teaches you to design the PCB that the RP2040 lives on. Before you can design a board, you need to understand what the chip needs -- power, clock, flash, and how its pins connect to the outside world.

ARM Cortex-M0+ Architecture

The RP2040 has two ARM Cortex-M0+ cores running at up to 133MHz. The M0+ is the smallest, lowest-power ARM core available. It uses the ARMv6-M instruction set -- a subset of the full ARM architecture with only 56 base instructions.

Feature Cortex-M0+ (RP2040) Cortex-A76 (Pi 5)
Clock speed Up to 133 MHz Up to 2.4 GHz
Cores 2 4
Pipeline 2-stage 13-stage (out-of-order)
Cache None (XIP cache for flash) L1: 64KB I + 64KB D, L2: 512KB, L3: 2MB shared
RAM 264KB SRAM (on-chip) 4-8GB LPDDR4X (external)
OS Bare metal or RTOS Linux (Raspberry Pi OS)
Power ~25mA at 48MHz ~2-5W under load
Dual-Core Usage:

The RP2040's two cores share memory but each has its own stack pointer and program counter. Core 0 boots first and can launch Core 1. A common pattern: Core 0 handles communication (USB, UART) while Core 1 runs a tight real-time control loop.

PIO State Machines

PIO (Programmable I/O) is what makes the RP2040 unique. It has two PIO blocks, each containing four state machines. These state machines execute tiny programs (up to 32 instructions each) that manipulate GPIO pins at the system clock rate -- independently of the CPU.

This means the RP2040 can bit-bang any protocol: WS2812B LED strips, VGA video, DPI displays, custom serial protocols, even HDMI -- all without using CPU cycles. The PIO instruction set has only 9 instructions: JMP, WAIT, IN, OUT, PUSH, PULL, MOV, IRQ, SET.

; PIO program to drive WS2812B NeoPixel LEDs ; Each bit is encoded as a timed pulse on the data pin .program ws2812 .side_set 1 .wrap_target bitloop: out x, 1 side 0 [T3 - 1] ; Shift 1 bit from OSR to X jmp !x do_zero side 1 [T1 - 1] ; Drive high, branch on bit value do_one: jmp bitloop side 1 [T2 - 1] ; Bit=1: stay high longer do_zero: nop side 0 [T2 - 1] ; Bit=0: go low earlier .wrap
No CPU Involvement PIO runs at clock speed (up to 133MHz) without consuming CPU cycles. The CPU can sleep while PIO drives protocols.
Exact Timing Each PIO instruction takes exactly one clock cycle (plus configurable delays). No interrupt jitter, no OS scheduling variance.

Memory Map

The RP2040 uses a flat 32-bit address space. Everything -- flash, RAM, peripherals, and boot ROM -- is mapped into this single address space.

RP2040 Memory Map (simplified) 0x00000000 - 0x00003FFF Boot ROM (16KB, read-only) Contains USB bootloader, flash routines 0x10000000 - 0x10FFFFFF External Flash via XIP (up to 16MB) Execute-in-place: code runs directly from flash Pico has 2MB (W25Q16JV) 0x20000000 - 0x20041FFF SRAM (264KB total) 6 banks: 4x 64KB + 2x 4KB Striped for concurrent access by both cores 0x40000000 - 0x40FFFFFF APB Peripherals UART, SPI, I2C, PWM, ADC, timers 0x50000000 - 0x50FFFFFF AHB Peripherals DMA, USB, PIO, SIO (inter-core comms) 0xD0000000 SIO (Single-cycle I/O) GPIO direct access, spinlocks, divider 0xE0000000 ARM Core Peripherals SysTick, NVIC, debug

Boot Sequence

When the RP2040 powers on, it follows a deterministic boot sequence controlled by the built-in boot ROM:

1. Boot ROM Starts Core 0 begins executing from the boot ROM at address 0x00000000. Core 1 is held in sleep until explicitly woken.
2. Check Flash Boot ROM reads the first 256 bytes of external flash. It looks for a valid CRC32 checksum to verify the second-stage bootloader.
3. Second-Stage Boot The 256-byte bootloader configures the flash chip's SPI interface for XIP (execute-in-place) mode. This is chip-specific.
4. User Code After flash is configured, execution jumps to the main application code. If using the Pico SDK, this enters the runtime initialization before calling main().
BOOTSEL Button:

If the BOOTSEL button is held during power-on, the boot ROM skips flash entirely and presents the RP2040 as a USB mass storage device. You drag-and-drop a UF2 file to program it. This is why the Pico is so beginner-friendly -- no special programmer required.

On-Ramp: What Are Schematics and PCBs?

If you are coming from the Electronics track and have worked with breadboards and jumper wires, this section bridges the gap to board engineering.

Schematic A schematic is a diagram of the electrical connections in a circuit. It shows what connects to what, using standardized symbols for components (resistors, capacitors, ICs). It does NOT show physical layout or size.
PCB (Printed Circuit Board) A PCB is the physical board that holds and connects the components. Copper traces replace the jumper wires from your breadboard. The PCB layout determines where components physically sit and how traces route between them.

The workflow is: design the schematic (logical connections) first, then lay out the PCB (physical arrangement). The schematic is the blueprint. The PCB is the building. You cannot skip the blueprint.

This track will take you through both: reading existing schematics (like the Pi Pico's), understanding PCB construction, and ultimately designing your own boards around the RP2040.

Why Not Just Use a Breadboard?

Breadboards work for prototypes but fail for production: unreliable connections, no shielding, parasitic capacitance between rows, and a maximum frequency of roughly 10-20MHz before signal integrity collapses. A PCB provides reliable, repeatable, compact, and high-frequency-capable connections.

Key Takeaways

  • The RP2040 is a dual-core Cortex-M0+ microcontroller -- no OS, bare-metal code, 264KB SRAM, external flash
  • PIO state machines execute tiny programs at clock speed, driving protocols without CPU involvement
  • The memory map is flat 32-bit: flash at 0x10000000, SRAM at 0x20000000, peripherals at 0x40000000+
  • Boot sequence: ROM checks flash CRC, runs second-stage bootloader, jumps to user code
  • BOOTSEL mode makes the RP2040 appear as USB storage -- no programmer needed
  • A schematic is the logical diagram; a PCB is the physical board -- this track covers both
