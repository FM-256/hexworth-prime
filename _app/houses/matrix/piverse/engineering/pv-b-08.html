Project Specification

We are designing a custom game controller that appears as a standard USB gamepad on any computer -- no drivers needed. The RP2040's built-in USB controller and the TinyUSB library make this straightforward. The challenge is fitting everything onto a comfortable, ergonomic PCB.

USB HID Protocol

USB HID (Human Interface Device) is a standard USB device class. When the RP2040 presents itself as an HID gamepad, the host computer loads a built-in driver automatically. The device sends periodic reports describing the current state of all buttons and axes.

// HID Gamepad Report Descriptor (simplified) // Defines what the controller sends to the host Report Structure: Byte 0: Button states (bits 0-7 = buttons 1-8) Byte 1: Button states (bits 0-3 = buttons 9-12, bits 4-7 = hat switch) Byte 2: Left stick X (0-255, center = 128) Byte 3: Left stick Y (0-255, center = 128) Byte 4: Right stick X (0-255, center = 128) Byte 5: Right stick Y (0-255, center = 128) // Sent every 1ms (1000Hz polling rate) over USB interrupt endpoint // Total latency: <2ms from button press to host receiving the report
Why RP2040 for USB HID?

The RP2040 has a built-in USB 1.1 controller with device and host support. No external USB transceiver needed. Combined with the TinyUSB library (included in the Pico SDK), implementing HID is roughly 50 lines of C. The 1ms polling rate matches commercial controllers.

Button Matrix

A button matrix reads N x M buttons using only N + M GPIO pins. Instead of dedicating one pin per button (16 buttons = 16 pins), a 4x4 matrix reads 16 buttons with 8 pins. The matrix scans one row at a time: drive a row low, read all columns, advance to the next row.

// 4x4 button matrix: 16 buttons with 8 GPIO pins Rows (outputs): GPIO 2, 3, 4, 5 Drive one low at a time Columns (inputs): GPIO 6, 7, 8, 9 Read with internal pull-ups Scan algorithm: for each row: Set row LOW (all others HIGH) for each column: if column reads LOW: button[row][column] = PRESSED else: button[row][column] = RELEASED Delay 1us (debounce settling time) Full scan of 16 buttons takes ~10us Run scan at 1kHz (every 1ms) to match USB polling rate Debouncing: require 3 consecutive identical readings before registering a state change (3ms debounce)

Analog Stick Interface

Analog thumbsticks are potentiometers: two variable resistors (X and Y axes) that output a voltage proportional to stick position. The RP2040's ADC reads this voltage and maps it to a 0-255 range for the HID report.

// Analog stick connections Left Stick X: GPIO 26 (ADC0) -- center ~1.65V, range 0-3.3V Left Stick Y: GPIO 27 (ADC1) Right Stick X: GPIO 28 (ADC2) Right Stick Y: GPIO 29 (ADC3) Stick Click L: GPIO 10 (digital, active low) Stick Click R: GPIO 11 (digital, active low) // ADC configuration adc_init(); adc_gpio_init(26); // Configure GPIO 26 for ADC adc_select_input(0); // Select ADC channel 0 uint16_t raw = adc_read(); // 12-bit: 0-4095 uint8_t axis = raw >> 4; // Map to 8-bit: 0-255 // Deadzone: ignore small movements near center // Center = 128. Deadzone = +/- 10 if (abs(axis - 128) < 10) axis = 128;

PCB Ergonomics

A game controller PCB is not rectangular -- the board shape IS the controller. KiCad allows arbitrary board outlines defined as edge cuts. The physical design must consider hand comfort, button reach, and mechanical stability.

Board Outline Define the controller shape in the Edge.Cuts layer. Use arcs for comfortable grip contours. The PCB itself is the enclosure (some designs add a 3D-printed shell).
Button Placement D-pad and face buttons follow standard console layouts. Thumb-to-button distance and angle must feel natural. Test with cardboard mockups before committing to PCB.
Component Height Tall components (USB connector, thumbstick modules) go on one side. Flat SMD components (RP2040, passives) go on the other. This allows a flat back surface for comfortable grip.
USB Cable Strain Relief The USB-C connector takes mechanical stress from cable pulling. Add through-hole mounting pins or a PCB cutout for the cable to loop through as strain relief.

TinyUSB HID Firmware

// Simplified TinyUSB HID gamepad firmware (Pico SDK + TinyUSB) #include "tusb.h" #include "pico/stdlib.h" #include "hardware/adc.h" // HID report structure typedef struct { uint16_t buttons; // 16 button bits uint8_t hat; // D-pad (hat switch) uint8_t lx, ly; // Left stick uint8_t rx, ry; // Right stick } gamepad_report_t; gamepad_report_t report; void main() { stdio_init_all(); tusb_init(); adc_init(); init_button_matrix(); while (1) { tud_task(); // TinyUSB device task (must call frequently) if (tud_hid_ready()) { scan_buttons(&report); // Read matrix read_analog_sticks(&report); // Read ADC tud_hid_gamepad_report( REPORT_ID_GAMEPAD, report.buttons, report.hat, report.lx, report.ly, report.rx, report.ry, 0, 0 // No triggers in this design ); } } }

USB Routing Checklist

The USB section of this board must follow the same signal integrity rules from PV-B-05. Here is the specific checklist for this controller design:

USB routing checklist for the game controller PCB: [ ] 90 ohm differential impedance (use stackup calculator) [ ] D+ and D- length matched within 0.15mm [ ] 27 ohm series resistors close to RP2040 USB pins [ ] No vias in the differential pair routing [ ] Continuous ground plane under the USB traces [ ] USB connector shield connected to ground via 1M resistor + 100nF cap [ ] ESD protection TVS diodes on D+ and D- (recommended: USBLC6-2SC6) [ ] VBUS connected through Schottky diode or ideal diode to VSYS [ ] 5.1K resistors on CC1 and CC2 for USB-C device identification

Key Takeaways

  • The RP2040's built-in USB controller + TinyUSB library enables HID devices with no external hardware
  • A button matrix reads N*M buttons with N+M pins -- essential for keeping GPIO count manageable
  • Analog sticks are potentiometers read by the RP2040's ADC -- apply deadzones to prevent drift
  • Controller PCB shape IS the ergonomic design -- test with cardboard mockups before manufacturing
  • USB-C requires 5.1K resistors on CC pins for device identification, plus ESD protection on data lines
  • USB HID devices are driverless on every modern OS -- plug in and play
