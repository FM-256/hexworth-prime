01 / 06

APT Deep Dive -- Repository Management

APT (Advanced Package Tool) is the package management system for Debian-based distributions including Ubuntu 22.04. It resolves dependencies, manages repositories, and maintains a package database. Understanding how APT locates packages is prerequisite to troubleshooting installs and configuring offline or custom repositories.

# Sync the local package index with all configured repositories apt update # List all packages with available upgrades apt list --upgradable # Install a package apt install -y nginx # Remove a package (keep config files) apt remove nginx # Remove a package and its configuration files apt purge nginx # Remove automatically installed dependencies no longer needed apt autoremove # Show detailed package metadata apt show nginx # Search for packages matching a keyword apt-cache search web server # Show a package's dependencies apt-cache depends nginx # Show what packages depend on a given package apt-cache rdepends nginx

Repository configuration: /etc/apt/sources.list (legacy format) and /etc/apt/sources.list.d/*.list or *.sources (modular format). Each entry specifies a URL, distribution name (e.g., jammy), and components (e.g., main restricted universe). Third-party repositories are added as separate files in sources.list.d/.

Understanding how cells reach the armory -- and what to do when they can't -- is core operator knowledge. APT is the interface; the repository is the armory.
02 / 06

Package Pinning and Version Management

Production cells often require specific software versions. A routine apt upgrade that replaces a tested library version with an untested one can break a running service. Package pinning prevents unwanted upgrades while still allowing the package manager to operate normally for all other packages.

# Install a specific version of a package apt install nginx=1.18.0-0ubuntu1.4 # Hold a package at its current version (survives apt upgrade) apt-mark hold nginx # Remove a hold apt-mark unhold nginx # List all held packages apt-mark showhold # Advanced pinning via /etc/apt/preferences.d/nginx # Package: nginx # Pin: version 1.18.0* # Pin-Priority: 1001 # Verify the pinning took effect apt-cache policy nginx

apt-mark hold is the simplest pinning method: the package is excluded from all upgrades until explicitly unheld. The /etc/apt/preferences.d/ method is more flexible -- pin-priority 1001 forces installation of a specific version even if a newer one is available. Priority 100 is the default; priorities above 1000 override even downgrades. Use apt-cache policy to verify which version would be installed and why.

A production cell that silently upgrades a critical library during a routine update window is an incident waiting to happen. Pinning is how operators prevent it.
03 / 06

GPG Keys and Repository Signing

APT verifies the integrity of packages using GPG signatures. Every repository ships a signed metadata file. APT checks that signature against a trusted key before trusting the package index. Without this verification, a compromised or spoofed repository could serve trojanized packages that APT would install without warning.

# Add a third-party GPG key (Docker example) curl -fsSL https://download.docker.com/linux/ubuntu/gpg \ | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg # Add the repository with explicit keyring reference echo "deb [arch=amd64 signed-by=/etc/apt/keyrings/docker.gpg] \ https://download.docker.com/linux/ubuntu jammy stable" \ | sudo tee /etc/apt/sources.list.d/docker.list # Verify a downloaded .deb package against its signature file gpg --verify package.deb.sig package.deb # List keys in the APT keyring apt-key list # Verify a package's SHA256 checksum (standard for tarballs) sha256sum -c package.sha256

The signed-by= field in the sources entry binds a specific repository to a specific key file, preventing key cross-contamination between repositories. The older apt-key add method (pre-Ubuntu 22.04) added keys to a global keyring that all repositories shared -- a security weakness. Modern practice stores each repository's key separately in /etc/apt/keyrings/.

An untrusted armory could serve trojanized packages. GPG verification ensures you only install what you intended. Never skip this step on a production cell.
04 / 06

Dependency Resolution and Troubleshooting

APT resolves dependencies automatically during normal installs. In field scenarios -- offline cells, partial installs, manual .deb installs -- the dependency graph must be understood and managed manually. Knowing how to diagnose and repair broken package states is an operational necessity.

# Fix broken dependencies (runs the configure step on unconfigured packages) apt-get -f install # Configure all unpacked but unconfigured packages dpkg --configure -a # Manually install a .deb file dpkg -i package.deb # List all packages and their states (ii=installed, rc=removed+config remains) dpkg -l # Show packages that were removed but still have config files on disk dpkg -l | grep ^rc # Clean up config files from removed packages dpkg -l | grep ^rc | awk '{print $2}' | xargs sudo apt purge -y # Show files installed by a specific package dpkg -L nginx

When a manual dpkg -i fails due to missing dependencies, run apt-get -f install to let APT resolve and fetch the missing packages. The rc state in dpkg -l output means the package binary was removed but configuration files remain -- apt purge removes those. On an offline cell, download all required packages and their dependencies on a connected cell, transfer them, and install in the correct dependency order with dpkg -i.

In field assembly scenarios, the grid armory is offline. Manual dependency resolution is the only path to provisioning the cell.
05 / 06

Compiling from Source -- The Complete Sequence

When a required tool is not available as a package, or when the package version is too old, source compilation is the answer. The sequence is fixed: verify integrity, extract, configure, compile, install. Skipping any step risks installing a corrupt or miscompiled binary on a production cell.

# Install essential build tools apt install build-essential libssl-dev libcurl4-openssl-dev # Download and verify the tarball wget https://archive.example.net/tools/gridmon-2.1.0.tar.gz sha256sum -c gridmon-2.1.0.tar.gz.sha256 # Extract the archive tar -xzf gridmon-2.1.0.tar.gz cd gridmon-2.1.0 # Configure the build (set install prefix and optional features) ./configure --prefix=/usr/local --with-network-support # Compile using all available CPU cores make -j$(nproc) # Install the compiled binary, libraries, and man pages sudo make install # Update the dynamic linker cache so the new libraries are found sudo ldconfig

Common ./configure options: --prefix=PATH (where to install; default is /usr/local), --sysconfdir=PATH (configuration file directory), --with-FEATURE (enable optional feature with its library), --enable-FEATURE (enable a compiled-in feature). When ./configure fails with "headers not found" errors, the needed -dev package is missing. Runtime libraries and development headers are separate packages on Debian-based systems.

The field assembly mission requires compiling from source when the armory is offline. This sequence is the operational standard. Know it before you need it.
06 / 06

checkinstall -- Package Tracking for Source Installs

make install copies compiled files into the system without creating any record in the package database. The files become invisible to APT and dpkg. A future operator inheriting the cell cannot determine what was installed or how to remove it. checkinstall wraps make install to create a proper package database entry.

# Install checkinstall apt install checkinstall # Replace 'make install' with checkinstall (run from the source directory) sudo checkinstall --pkgname=gridmon \ --pkgversion=2.1.0 \ --backup=no \ --fstrans=no \ make install # checkinstall creates a .deb in the source directory ls gridmon_2.1.0-1_amd64.deb # The tool is now tracked in the package database dpkg -l | grep gridmon # Remove it cleanly when no longer needed apt remove gridmon

The flags: --pkgname (name for the package database entry), --pkgversion (version string), --backup=no (do not create a tarball backup of replaced files), --fstrans=no (disable filesystem translation, which can cause issues in some environments). The resulting .deb can also be transferred to other cells and installed with dpkg -i, making source-compiled tools portable across the sector.

Cells that install tools from source without checkinstall accumulate untracked files. The next operator cannot determine what was installed manually or how to undo it.

Key Takeaways

  • apt update syncs the package index; apt purge removes binaries AND config files; apt remove keeps config files
  • apt-mark hold prevents a package from being upgraded during apt upgrade
  • GPG signed-by= in sources entries binds a repository to a specific key -- never skip signature verification
  • apt-get -f install repairs broken dependency states after manual dpkg -i installs
  • Source compilation sequence: verify checksum, ./configure, make -j$(nproc), sudo make install, ldconfig
  • checkinstall wraps make install to create a tracked dpkg entry -- source installs must use it on managed cells
