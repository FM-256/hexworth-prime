Operational Context:

Advanced Pipes and Process Substitution

Standard pipes connect one command's stdout to another's stdin. Process substitution goes further: it lets you use the output of a command anywhere a filename is expected, without writing a temporary file. This is critical for comparing live data against baselines under operational pressure.

# Compare two directory listings inline -- no temp files diff <(ls /etc/cron.d) <(ls /etc/cron.daily) # Paste two columns from /etc/passwd side by side paste <(cut -d: -f1 /etc/passwd) <(cut -d: -f3 /etc/passwd) # Pipe output to tee while simultaneously compressing a copy some-command | tee >(gzip > /tmp/backup.log.gz) # Named pipe (FIFO): connect two separate processes mkfifo /tmp/cellpipe command1 > /tmp/cellpipe & command2 < /tmp/cellpipe

The syntax <(command) substitutes command output as a readable file descriptor. The syntax >(command) substitutes command input as a writable file descriptor. Named pipes created with mkfifo persist in the filesystem until deleted, allowing inter-process communication across separate terminals.

Operational Note:

When diagnosing a cell under operational pressure, you rarely have the luxury of writing intermediate files. Process substitution removes that bottleneck.

Command Chaining and Conditional Execution

Command chaining operators control whether subsequent commands execute based on the exit code of the previous command. Exit code 0 means success. Any non-zero value means failure. These operators enforce logic inline without requiring a script.

# Check the exit code of the last command echo $? # ; runs commands sequentially regardless of exit codes apt-get update; apt-get upgrade # && runs next command only if previous succeeded (exit 0) systemctl start networking && systemctl start sshd && echo "Stack online" # || runs next command only if previous failed (non-zero exit) systemctl start grid-sync || echo "GRID-SYNC FAILED -- alert operations" # Combine both to create inline conditional logic systemctl start networking && systemctl start sshd || echo "STARTUP FAILED"

&& is the logical AND: the right side only runs if the left side exits 0. || is the logical OR: the right side only runs if the left side exits non-zero. Combining them creates conditional sequences: start A, then start B only if A succeeded, or alert if B fails.

Operational Note:

Startup sequences in a cell are conditional. If networking fails, nothing else should start. Command chaining enforces this logic inline.

Subshells and Command Groups

A subshell forks a child process to run commands in isolation. The parent shell is unaffected by anything the subshell does to its environment, including directory changes. A command group runs in the current shell -- changes persist.

# Subshell: cd does NOT affect parent shell's $PWD (cd /tmp && ls) echo $PWD # still the original directory # Command group: cd DOES affect current shell's $PWD { cd /tmp; ls; } echo $PWD # now /tmp # Capture command output into a variable with $( ) failed=$(systemctl status --all | grep -c "failed") echo "Failed units: $failed" # Combine multiple command outputs using process substitution result=$(cat <(ps aux) <(ss -tuln)) # Nested subshells for complex scoping outer=$(echo "grid-$(hostname)-$(date +%s)")

Use $() instead of backticks for command substitution -- it nests cleanly, reads left-to-right, and handles quoting correctly. The distinction between subshell () and command group { } is critical in scripts where directory context must be controlled precisely.

Operational Note:

Scripted diagnostics use subshells to scope destructive operations. An operator who changes directory in the current shell rather than a subshell occasionally destroys their session context.

Job Control Under Terminal Multiplexers

Background jobs tied to a terminal die when the terminal closes. Terminal multiplexers (screen and tmux) maintain sessions on the server independently of the client SSH connection. This is non-negotiable for long-running operations.

# screen: create a named session screen -S diagnostics # screen: detach from session (keyboard shortcut) # Ctrl+A then D # screen: list and reattach screen -ls screen -r diagnostics # tmux: create a named session tmux new -s grid-ops # tmux: detach (keyboard shortcut) # Ctrl+B then D # tmux: list sessions and reattach tmux ls tmux attach -t grid-ops # tmux: split the window horizontally for side-by-side panes tmux split-window -h

Prefer tmux for new workflows -- it has a more active development community, better scripting support, and persistent configuration via ~/.tmux.conf. Both tools achieve the same primary goal: work that survives SSH disconnections.

Operational Note:

Long-running operations (AIDE scans, compilation, log analysis) must survive SSH disconnections. Operators who use screen or tmux never lose work when a secure link drops.

Advanced find and xargs Patterns

Basic find was covered in ALA-R1. Here we combine it with xargs for bulk parallel operations and use time-based predicates for forensic sweeps.

# Find large log files and show disk usage for each find /var -name "*.log" -size +50M -exec du -sh {} \; # Find files newer than /etc/passwd (modified after the baseline) find /etc -newer /etc/passwd -type f # Find all .ssh dirs and list their contents via xargs find /home -name ".ssh" -type d | xargs -I{} ls -la {} # -execdir is safer: changes to the file's directory first find /var/log -name "*.gz" -execdir ls -lh {} \; # Parallel md5sum on all .conf files using 4 workers find /etc -name "*.conf" -print0 | xargs -0 -P 4 md5sum > /tmp/checksums.md5

-exec runs from the original working directory; -execdir changes into the file's parent directory first, which prevents path traversal issues in scripts. Use xargs -P N to parallelize work across N workers -- essential when computing checksums over thousands of files.

Operational Note:

Post-incident forensics often involve scanning the entire filesystem for files modified within a time window. These patterns are operationally verified.

Shell History and Session Forensics

When investigating a compromised account, the bash history is often the first evidence you examine. Knowing how to extract, timestamp, and preserve it is part of incident response.

# Search history for SSH commands history | grep ssh # Show history with timestamps (requires HISTTIMEFORMAT to be set) HISTTIMEFORMAT="%F %T " history # Read the raw history file directly (bypasses session buffering) cat ~/.bash_history # List the last 20 commands from the history file fc -l -20 # Enforce history settings for all users via profile.d # Add to /etc/profile.d/history-settings.sh: # export HISTTIMEFORMAT="%F %T " # export HISTSIZE=10000 # export HISTFILESIZE=20000 # export HISTCONTROL=ignoredups:erasedups

The in-memory history and the on-disk ~/.bash_history file may differ -- the in-memory buffer is written to disk on clean shell exit. If an attacker killed the shell abruptly, only the disk file exists. Always read both sources during investigation. Setting HISTTIMEFORMAT in /etc/profile.d/ ensures timestamps are available for all users going forward.

Operational Note:

When investigating an incident, the bash history of compromised accounts is often the first evidence you examine. Preserve it before touching anything else.

Brace Expansion and Parameter Expansion

Brace expansion generates multiple strings from a single pattern. Parameter expansion manipulates variable values inline. Both reduce command count and prevent scripts from breaking on empty or malformed variables.

# Create a full directory tree in one command mkdir -p /opt/cell-services/{bin,lib,log,conf} # Generate a sequence of hostnames echo cell-{01..05}.matrix.net # Backup a config file in place (appends .bak to original name) cp config.conf{,.bak} # Default value if variable is unset or empty echo "${LOG_DIR:-/var/log/cell}" # Length of a string variable echo "${#HOSTNAME}" # Strip a suffix from a variable (remove file extension) filename="alert.2026-04-09.log" echo "${filename%.log}" # Strip a prefix from a variable (remove path component) fullpath="/var/log/cell/ops.log" echo "${fullpath##*/}"

Parameter expansion patterns: ${var:-default} (use default if unset), ${#var} (string length), ${var%suffix} (strip shortest suffix), ${var%%suffix} (strip longest suffix), ${var#prefix} (strip shortest prefix), ${var##prefix} (strip longest prefix). These eliminate the need for basename and dirname calls in many script contexts.

Operational Note:

Operators who use brace expansion create directory trees in one command instead of five. Parameter expansion prevents scripts from breaking on empty variables.

Key Takeaways

  • Process substitution with <() and >() eliminates intermediate temp files in diagnostic workflows
  • && and || create conditional inline logic based on exit codes -- exit 0 is success
  • Subshells () isolate environment changes; command groups {} run in the current shell
  • tmux and screen decouple work from the SSH connection -- sessions survive disconnections
  • xargs -P N parallelizes bulk operations; -execdir is safer than -exec for path-sensitive work
  • Parameter expansion handles string manipulation without external tools like basename or dirname
