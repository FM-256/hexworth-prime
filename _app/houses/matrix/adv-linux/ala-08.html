01 / 05

ClamAV Architecture

ClamAV is an open-source antivirus engine designed for server-side use. It has four main components: clamd (the background daemon that keeps virus databases loaded in memory), clamscan (standalone scanner that loads databases fresh each run), clamdscan (client that submits scan requests to a running clamd), and freshclam (signature database updater).

# Install ClamAV and the daemon package apt install clamav clamav-daemon # Stop freshclam before manually updating (it holds a lock) systemctl stop clamav-freshclam # Update signatures manually freshclam # Start the freshclam update service systemctl start clamav-freshclam systemctl enable clamav-freshclam # Start the clamd daemon systemctl start clamav-daemon systemctl enable clamav-daemon # Verify both services are running systemctl status clamav-freshclam clamav-daemon

Configuration files: /etc/clamav/clamd.conf controls the daemon behavior (socket type, memory limits, log settings, on-access scanning). /etc/clamav/freshclam.conf controls signature update frequency and mirror selection. On Ubuntu 22.04, the default socket is a Unix socket at /run/clamav/clamd.ctl.

Every cell that processes external data -- packages, files, uploads -- must run ClamAV. A cell without a sentinel is an unmonitored entry point.
02 / 05

Signature Database Management

ClamAV's detection capability depends entirely on current signature databases. Outdated databases produce false negatives -- the scanner reports clean on files that are actually infected. freshclam manages three databases: main.cvd (core signatures), daily.cvd (daily updates), and bytecode.cvd (bytecode-based detection rules).

# Run freshclam with verbose output to verify updates freshclam --verbose # View the freshclam update log cat /var/log/clamav/freshclam.log # Inspect a CVD database file for metadata sigtool --info /var/lib/clamav/main.cvd # Check the build date of the daily database sigtool --info /var/lib/clamav/daily.cvd | grep 'Build time' # Configure update frequency in /etc/clamav/freshclam.conf # Checks 24 (check for updates 24 times per day = every hour) # DatabaseMirror database.clamav.net

On a first install, freshclam downloads several hundred megabytes of signature data. For air-gapped cells, configure DatabaseMirror in freshclam.conf to point to an internal mirror server. The Checks directive controls how many times per day freshclam polls for updates -- 24 is the default and the practical maximum enforced by the ClamAV mirror network.

A sentinel with outdated signatures is a false security blanket. freshclam must run successfully before any scan result can be trusted.
03 / 05

Manual Scanning with clamscan

clamscan performs on-demand scans without requiring the clamd daemon. It loads the virus database fresh on each run, which makes it slower than clamdscan but completely standalone. Use it for targeted scans after a suspected compromise or before deploying files from untrusted sources.

# Recursively scan a directory, show all files clamscan -r /home/operator/ # Show only infected files (suppress clean output) clamscan -r --infected /tmp/ # Scan and automatically remove infected files clamscan -r --infected --remove /tmp/ # Scan with logging to a file clamscan -r -l /var/log/clamav/scan.log /opt/ # Scan with size limits (avoid spending hours on huge files) clamscan --max-filesize=100M --max-scansize=400M /var/www/ # Check the exit code: 0=clean, 1=virus found, 2=error clamscan /tmp/ ; echo "Exit code: $?"

Key options: -r (recursive), --infected (report only infected files), --remove (delete infected files -- use with caution in production), --log FILE (write scan report to file), --max-filesize (skip files larger than this limit), --max-scansize (limit total data scanned per invocation). The exit code is critical for scripted alerting: exit 0 means the scan completed and found nothing; exit 1 means infected files were found.

Manual scans are used after a suspected compromise or before field assembly from untrusted sources. Know the flags before you need them under pressure.
04 / 05

clamd -- Daemon Mode and On-Access Scanning

clamd keeps virus databases loaded in memory, making repeated scans dramatically faster than standalone clamscan. Clients connect to it via a Unix socket or TCP port. clamdscan submits scan requests to the running daemon. On-access scanning extends this to real-time protection -- every file access triggers an automatic scan.

# Key directives in /etc/clamav/clamd.conf: # LocalSocket /run/clamav/clamd.ctl # TCPSocket 3310 (optional: also listen on TCP) # MaxConnectionQueueLength 30 # User clamav # Scan a directory using the running daemon (faster than clamscan) clamdscan /opt/cell-services/ # Pass file descriptors to the daemon (avoids permission issues) clamdscan --fdpass /home/operator/downloads/ # On-access scanning configuration in clamd.conf: # OnAccessMountPath /home (monitor this path) # OnAccessExcludeUID 0 (exclude root-owned processes) # clamonacc is the on-access daemon companion to clamd systemctl start clamav-daemon # clamonacc starts automatically when OnAccessMountPath is configured

On-access scanning requires both clamd and the clamonacc process. When a file under the monitored path is opened or executed, clamonacc intercepts the access, submits the file to clamd, and can block access if the file is infected. OnAccessExcludeUID 0 prevents root processes from being scanned, which avoids locking system operations that access many files rapidly.

On-access scanning provides real-time protection rather than periodic manual sweeps. A cell that only scans on a schedule has a window of exposure between scans.
05 / 05

Scheduled Scans and Reporting

Scheduled scans complement on-access protection by catching threats that bypassed real-time detection and by producing regular compliance-ready scan reports. Cron is the standard scheduling mechanism. The scan script checks the exit code and triggers an alert when infected files are found.

# Daily scan of high-risk paths, log results to a datestamped file # Add to /etc/cron.d/clamav-daily: # 0 2 * * * clamav /usr/bin/clamscan -r --infected \ # -l /var/log/clamav/daily_scan.log /home /opt /var/www # Alert wrapper script: scan and email if exit code is 1 # /usr/local/bin/clamav-alert-scan.sh: #!/bin/bash # /usr/bin/clamscan -r --infected -l /var/log/clamav/scan.log /home # if [ $? -eq 1 ]; then # mail -s "CELL-ALERT: ClamAV infection detected" soc@sector7.matrix.net \ # < /var/log/clamav/scan.log # fi # Weekly full-system scan (resource-intensive; run during low-traffic window) # 0 1 * * 0 clamav /usr/bin/clamscan -r --infected \ # -l /var/log/clamav/weekly_scan.log / # Verify the cron entry was saved correctly crontab -u clamav -l

Run daily scans as the clamav user (not root) to limit privilege exposure. Scope daily scans to the highest-risk paths: /home, /opt, /var/www, and any directory where external files are written. Run full-system scans weekly during a maintenance window because recursive filesystem scans are CPU and I/O intensive. Log files grow -- implement logrotation for /var/log/clamav/ to prevent disk exhaustion.

Automated scans mean your sentinel works the night shift. A threat that arrives at 02:00 is detected before the 09:00 briefing.

Key Takeaways

  • ClamAV has four components: clamd (daemon), clamscan (standalone), clamdscan (daemon client), freshclam (updater)
  • Signatures must be current before any scan result is trustworthy -- freshclam must succeed first
  • clamscan exit code 0 = clean, 1 = infected files found, 2 = error; use this in alerting scripts
  • clamdscan is faster than clamscan because it connects to clamd with databases already in memory
  • On-access scanning requires both clamd and clamonacc; OnAccessExcludeUID 0 prevents scanning root processes
  • Daily scans target high-risk paths; weekly scans cover the full filesystem during maintenance windows
