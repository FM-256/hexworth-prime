Week 2 Review -- The Four Hardening Pillars

Week 2 covered the four pillars of cell hardening. Each pillar addresses a distinct attack surface. A hardened cell has all four active and verified.

Pillar 1 -- Perimeter

  • iptables / nftables rule chains
  • UFW for daily management
  • Default deny INPUT and FORWARD
  • Rate limiting on SSH port
  • Rules persisted via iptables-save

Pillar 2 -- Authentication

  • SSH key auth, PasswordAuthentication no
  • TOTP via libpam-google-authenticator
  • fail2ban with maxretry=3, bantime=600
  • PAM limits and access.conf policies
  • Login auditing via auth.log

Pillar 3 -- Scanning

  • ClamAV with clamd daemon running
  • freshclam signatures current
  • Daily cron scan of high-risk paths
  • On-access scanning via clamonacc
  • Exit code alerting in scan scripts

Pillar 4 -- Software

  • apt-mark hold for version-pinned packages
  • GPG key verification for repositories
  • Checksum verification for tarballs
  • checkinstall for source-compiled tools
  • dpkg -l to audit installed state
A cell that is hardened in three pillars but exposed in the fourth is not hardened. All four must hold before connecting to the grid.

Pre-Hardening Audit Checklist

Before hardening any new cell, run this five-command audit to establish the baseline. These commands reveal the attack surface before you close it. Run them again after hardening to verify your changes took effect.

Command What it reveals
ss -tulnp All listening TCP/UDP sockets and the processes that own them. Every open port is an attack surface.
systemctl list-units --type=service --state=active All running services. Identify and disable any service that should not be running on this cell.
last -20 The 20 most recent successful logins. Establishes who has accessed the cell and from where.
find / -perm /4000 -type f 2>/dev/null All SUID binaries on the system. Each is a potential privilege escalation path if compromised.
iptables -L -v -n Current firewall state. On a fresh install, INPUT policy is ACCEPT and no rules exist.

These five commands together answer: what is exposed, what is running, who has been here, where are the privilege escalation paths, and what is the current firewall state. An operator who skips this audit before hardening may close some attack surfaces while leaving others open without knowing it.

Know the cell before you harden it. The audit baseline is also your post-hardening verification benchmark.
