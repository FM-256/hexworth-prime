Script Structure and Best Practices

Every operational bash script starts with three things: a shebang line that specifies the interpreter, strict mode settings that prevent silent failures, and a clear section structure with comments. These are not stylistic preferences -- they are operational requirements.

#!/usr/bin/env bash # cell-health-check.sh -- checks service, disk, and connectivity status # Usage: ./cell-health-check.sh --cell <hostname> [--verbose] # set -e: exit immediately on error # set -u: treat unset variables as errors # set -o pipefail: pipe returns exit code of first failed command set -euo pipefail # --- Constants --- readonly LOG_DIR="/var/log/cell-ops" readonly LOG_FILE="${LOG_DIR}/health.log" readonly TIMESTAMP="$(date '+%F %T')" # Script permissions: 700 for operational scripts (owner-only execute) # chmod 700 cell-health-check.sh

#!/usr/bin/env bash is preferred over #!/bin/bash because it searches the PATH for bash rather than assuming its location. On some systems, bash is not at /bin/bash. Using env makes the script portable without any change to the shebang line.

Operational Context:

Poorly written scripts that silently succeed when they have actually failed create false confidence and downstream failures across the sector.

Variables, Arrays, and String Manipulation

Variables, arrays, and string operations handle the cell lists, IP ranges, and file paths that appear in every automation script. Mastery of bash string manipulation eliminates the need for external tools like awk or sed for simple transformations.

# Variable declarations CELL_IP="10.0.1.71" readonly LOG_DIR="/var/log/cell-ops" -- cannot be reassigned export PATH="$PATH:/opt/cell-services/bin" -- available to child processes # Array: list of cells to iterate CELLS=("cell-071" "cell-014" "cell-027" "cell-033") echo "${#CELLS[@]}" -- count: 4 echo "${CELLS[0]}" -- first element: cell-071 echo "${CELLS[@]}" -- all elements # String manipulation without external tools FILENAME="cell-071.sector7.matrix.net.log" echo "${FILENAME,,}" -- lowercase echo "${FILENAME^^}" -- uppercase echo "${FILENAME//cell/node}" -- replace 'cell' with 'node' echo "${FILENAME%.*}" -- strip last extension: cell-071.sector7.matrix.net echo "${FILENAME##*/}" -- basename (strip path) # Default value: use fallback if variable is unset TIMEOUT="${TIMEOUT:-30}"
Operational Context:

Every automation script manages cell lists, IP ranges, and file paths. Bash string manipulation handles most transformations without spawning external processes.

Conditionals and Exit Codes

Conditionals determine what the script does when something fails. Exit codes are how scripts communicate success or failure to the calling process. Every health check script, every automated directive, must use both correctly.

# [[ ]] is preferred over [ ] in bash -- supports regex and avoids word splitting if [[ -f "/etc/bind/named.conf" ]]; then echo "BIND config exists" fi # Test operators # -f: file exists -d: directory exists -z: empty string # -n: non-empty -eq: numeric equal -lt/-gt: less/greater than # =~: regex match ==: string equal # Regex match: check if variable looks like an IP address IP="10.0.1.71" if [[ "$IP" =~ ^([0-9]{1,3}\.){3}[0-9]{1,3}$ ]]; then echo "Valid IP format" fi # Check if a service is active; restore it if not if ! systemctl is-active --quiet sshd; then systemctl start sshd echo "[$(date '+%F %T')] RESTORED: sshd" | tee -a "$LOG_FILE" fi # Exit codes: 0 = success, non-zero = failure check_connectivity() { ping -c 1 -W 2 10.0.1.1 >/dev/null 2>&1 || return 1 return 0 } if ! check_connectivity; then echo "ERROR: gateway unreachable" >&2 exit 1 fi
Operational Context:

Every automated directive must handle failure as a first-class case. A script that exits cleanly with an error message is safer than one that silently continues with bad data.

Loops and Iteration

Loops iterate over cell lists, IP ranges, and log files. Without proper loop constructs, operating on multiple cells requires one command per cell -- which does not scale to a sector with dozens of nodes.

# Iterate over an array of cells -- always quote "${CELLS[@]}" CELLS=("cell-071" "cell-014" "cell-027" "cell-033") for cell in "${CELLS[@]}"; do echo "Checking: $cell" done # Range loop for i in {1..5}; do echo "Attempt $i" done # Glob loop: process all logs in a directory for logfile in /var/log/cell-ops/*.log; do wc -l "$logfile" done # Read lines from a file without word splitting issues while IFS= read -r line; do echo "Processing: $line" done < /etc/cell-manifest.txt # Polling loop: check every 60 seconds until condition is met while true; do if systemctl is-active --quiet named; then echo "BIND is up" break fi sleep 60 done # break: exit loop early continue: skip to next iteration for cell in "${CELLS[@]}"; do [[ "$cell" == "cell-000" ]] && continue -- skip reserved cell process_cell "$cell" done

Never use $CELLS or ${CELLS} when iterating an array -- these expand only the first element. Always use "${CELLS[@]}" with double quotes to correctly handle element values that may contain spaces.

Operational Context:

Night shift scripts iterate over cell lists to perform operations across the sector. Without proper loop constructs, this requires one command per cell.

Functions

Functions prevent code duplication across automation scripts. A health check script that calls check_service(), check_disk(), and check_connectivity() as individual functions is readable, testable, and reusable.

# Function declaration -- two equivalent syntaxes log() { local message="$1" echo "[$(date '+%F %T')] ${message}" | tee -a "$LOG_FILE" } function check_disk() { local threshold="${1:-85}" -- default threshold: 85% local usage usage=$(df /var --output=pcent | tail -1 | tr -d ' %') if (( usage >= threshold )); then log "WARN: disk at ${usage}% (threshold: ${threshold}%)" return 1 fi return 0 } # Return a value via stdout capture -- not via 'return' (return is exit code only) get_cell_ip() { local hostname="$1" dig +short A "${hostname}.sector7.matrix.net" @10.0.1.1 } CELL_IP="$(get_cell_ip cell-071)" echo "Resolved: $CELL_IP" # Call functions with arguments log "Starting health check" check_disk 90 -- override threshold to 90% # $1 $2 = positional args $@ = all args $# = argument count

local variables inside functions do not leak into the calling scope. Without local, a variable named result inside a function overwrites any variable named result in the script's global scope. Always use local for function-internal variables.

Operational Context:

Functions prevent code duplication. The health check script calls check_service(), check_disk(), and check_connectivity() as individual, independently testable units.

getopts and Input Validation

Scripts that accept command-line arguments must validate them. An automation script that silently accepts a malformed IP address and runs anyway causes more damage than one that exits cleanly with an error message.

#!/usr/bin/env bash set -euo pipefail CELL="" VERBOSE=false # getopts parses short options: -c <cell>, -v (verbose), -h (help) while getopts "hvc:" opt; do case "$opt" in c) CELL="$OPTARG" ;; v) VERBOSE=true ;; h) echo "Usage: $0 -c <cell> [-v]"; exit 0 ;; *) echo "Unknown option: -$opt" >&2; exit 1 ;; esac done # Validate required argument if [[ -z "$CELL" ]]; then echo "ERROR: -c <cell> is required" >&2 exit 1 fi # Validate IP address format validate_ip() { local ip="$1" if [[ ! "$ip" =~ ^([0-9]{1,3}\.){3}[0-9]{1,3}$ ]]; then echo "ERROR: invalid IP address: $ip" >&2 return 1 fi } # Check that required tools are available before using them for tool in dig ping systemctl; do command -v "$tool" >/dev/null 2>&1 || { echo "ERROR: required tool not found: $tool" >&2 exit 1 } done $VERBOSE && echo "Verbose mode enabled -- checking cell: $CELL"
Operational Context:

Scripts that accept malformed input and run anyway cause more damage than scripts that exit cleanly with an error message. Validate early, fail loudly.
