DNS Record Reference

A complete reference for the record types covered in ALA-11 and the BIND deployment commands from ALA-12.

Record Type Purpose Key Detail
A Hostname to IPv4 address Most common record; target is a bare IPv4 address
AAAA Hostname to IPv6 address Same as A but for IPv6
CNAME Alias pointing to another hostname Target FQDN must end with a trailing dot
MX Mail exchanger Priority field required; lower value = higher priority
NS Nameserver delegation Required in every zone alongside SOA
SOA Zone authority and timing parameters Serial must increment on every zone change
PTR Reverse DNS (IP to hostname) Stored in .in-addr.arpa zone; last octet only
TXT Arbitrary text data Used for SPF records and verification tokens

BIND Operational Command Reference

The operational commands for validating, loading, and managing BIND9.

Command What It Does
named-checkconf Validate named.conf syntax; no output = no errors
named-checkzone <zone> <file> Validate a zone file syntax; must be run before reloading
rndc reload <zone> Reload a specific zone without restarting named
rndc flush Clear the entire resolver cache
rndc zonestatus <zone> Show zone serial, last transfer time, and expiry
dig AXFR <zone> @<server> Request a full zone transfer from a nameserver
dig +trace <name> Trace full delegation chain from root

Bash Script Checklist

Every operational bash script must satisfy this checklist before deployment.

# 1. Correct shebang and strict mode #!/usr/bin/env bash set -euo pipefail # 2. All variables declared and quoted CELL_IP="${1:?Usage: $0 <ip>}" # 3. Arrays iterated with "${ARRAY[@]}" for cell in "${CELLS[@]}"; do echo "$cell"; done # 4. Functions use 'local' for internal variables check_service() { local svc="$1"; systemctl is-active --quiet "$svc"; } # 5. String values returned via stdout, captured with $() IP="$(get_cell_ip cell-071)" # 6. Input validated before use [[ "$IP" =~ ^([0-9]{1,3}\.){3}[0-9]{1,3}$ ]] || { echo "Bad IP" >&2; exit 1; } # 7. Required tools checked at startup command -v dig >/dev/null 2>&1 || { echo "dig not found" >&2; exit 1; } # 8. All output to log file (not just stdout) exec >> /var/log/cell-ops/script.log 2>&1

Scheduling Tool Comparison

When to use cron vs systemd timers, and the key commands for each.

Factor cron systemd Timer
Logging Manual redirect to file Automatic via journalctl
Missed run handling Skipped silently Tracked; runs on next boot with Persistent=true
Dependencies None Full systemd dependency graph
Randomized delay Not supported natively RandomizedDelaySec=
Use for Simple, well-understood recurring tasks New directives; tasks requiring logging or dependencies
List active crontab -l systemctl list-timers --all
Operational Context:

Both tools serve cells in production. Know which to use when, and know the command to verify each is configured correctly.
