Deep Sleep and Power Management
Taking the ESP32 from 240mA wall-powered to 5uA coin-cell. Sleep modes, wake sources, ULP co-processor, and RTC memory.

Why Power Management Matters
The ESP32 draws 240mA at full power with WiFi active. A 2000mAh battery lasts 8 hours. Deep sleep extends that to months or years.
The Problem
At 240mA with WiFi on, a 3.7V 2000mAh LiPo battery drains in about 8 hours. For a sensor that reports temperature once every 15 minutes, that is 99.97% wasted power keeping WiFi and CPUs alive between readings.
The Solution
Deep sleep drops consumption to 10uA -- 24,000 times less. The same battery now lasts over 22 years in theory. In practice, wake-transmit-sleep cycles at 15-minute intervals yield 1-3 years depending on transmit duration.
Use Cases
Weather stations, soil moisture monitors, mailbox alerts, wildlife cameras, cold chain trackers, remote gate sensors -- any device that wakes briefly, measures, transmits, and sleeps. Battery + solar makes these truly wireless and indefinite.
Key Metric
Power budget math is simple: Battery capacity (mAh) / Average current draw (mA) = Hours of runtime. The entire goal of power management is minimizing that average current draw by spending as much time as possible in the lowest-power state.
Slide 3 of 12
The Five Power States
The ESP32 provides a spectrum of power states, each trading functionality for current reduction.
1 Active Mode (~240mA with WiFi, ~68mA CPU only) -- Both CPU cores running at 240MHz, WiFi and Bluetooth active, all peripherals available. This is normal operating mode. Full power, full capability.
2 Modem Sleep (~20mA) -- WiFi/BT radio powered down, both CPUs still running. Useful when doing extended local computation without network access. The radio can be restarted without a full reboot.
3 Light Sleep (~0.8mA) -- CPUs paused (clock gated), RAM contents preserved, WiFi off. Wakes in microseconds and resumes execution exactly where it stopped. Good for interactive devices that need fast response.
4 Deep Sleep (~10uA) -- Main CPUs and most peripherals powered off. Only the RTC controller, RTC memory (8KB), and selected wake sources remain powered. Waking triggers a full reboot -- setup() runs again.
5 Hibernation (~5uA) -- Everything off except the RTC timer and one RTC GPIO for wake. No ULP, no RTC memory retention beyond the timer. The absolute minimum power state. Waking is a cold boot with no state.

Slide 5 of 12
Entering Deep Sleep
One function call puts the ESP32 to sleep. The critical detail: waking from deep sleep is a full reboot.
// Basic deep sleep with timer wake #define uS_TO_S_FACTOR 1000000ULL // microseconds to seconds #define TIME_TO_SLEEP 300 // sleep for 5 minutes void setup() { Serial.begin(115200); delay(1000); Serial.println("Awake! Taking sensor reading..."); // ... do work here: read sensor, transmit data ... esp_sleep_enable_timer_wakeup(TIME_TO_SLEEP * uS_TO_S_FACTOR); Serial.println("Going to deep sleep for 5 minutes..."); esp_deep_sleep_start(); // Execution never reaches here } void loop() { // Never called -- deep sleep reboots to setup() }
Reboot, Not Resume
Deep sleep is not like pausing a program. When the ESP32 wakes, it runs through the bootloader and starts setup() fresh. All RAM variables are lost. loop() is never called in deep-sleep-based designs -- all logic goes in setup().
Timer Resolution
esp_sleep_enable_timer_wakeup() takes microseconds as a 64-bit unsigned integer. The multiplier 1000000ULL converts seconds to microseconds. The RTC timer has ~5% drift, so do not rely on it for precise timekeeping over long periods.
Slide 6 of 12
Wake Sources
The ESP32 supports multiple ways to wake from deep sleep. You can configure several simultaneously -- whichever triggers first wins.
Timer Wake
esp_sleep_enable_timer_wakeup(us) -- The most common wake source. Set a duration in microseconds. The RTC timer counts down and triggers wake. Used for periodic sensor readings, heartbeat transmissions, and duty-cycle patterns.
Touch Pin Wake
esp_sleep_enable_touchpad_wakeup() -- Wakes when a capacitive touch pin detects contact. Configure the touch threshold before sleeping. Used for user-activated devices like touch-to-wake displays or interactive installations.
External Wake (ext0)
esp_sleep_enable_ext0_wakeup(pin, level) -- Wakes when a single RTC GPIO reaches the specified level (HIGH or LOW). Only one pin, but simple to configure. Used for button press, motion sensor trigger, or door switch.
External Wake (ext1)
esp_sleep_enable_ext1_wakeup(mask, mode) -- Monitors multiple RTC GPIO pins simultaneously. Wakes when ANY pin goes high (or ALL pins go low). The bitmask selects which GPIOs to monitor. Used for multi-sensor arrays.
ULP Wake
The ULP co-processor can wake the main CPUs based on programmed conditions -- for example, when an ADC reading exceeds a threshold. This allows sensor monitoring during deep sleep without waking the main system for every reading.
Identifying Wake Cause
esp_sleep_get_wakeup_cause() returns an enum telling you why the ESP32 woke up. Check this in setup() to branch your logic -- first boot vs timer wake vs button press may require very different behavior.
Slide 7 of 12
Detecting Wake Cause
Since deep sleep reboots the system, your setup() must determine why it woke up and act accordingly.
void setup() { Serial.begin(115200); delay(1000); esp_sleep_wakeup_cause_t cause = esp_sleep_get_wakeup_cause(); switch (cause) { case ESP_SLEEP_WAKEUP_TIMER: Serial.println("Woke from timer -- taking scheduled reading"); readSensorAndTransmit(); break; case ESP_SLEEP_WAKEUP_EXT0: Serial.println("Woke from button press -- entering config mode"); startConfigPortal(); break; case ESP_SLEEP_WAKEUP_TOUCHPAD: Serial.println("Woke from touch -- showing display"); showLastReading(); break; default: Serial.println("First boot or reset -- initializing"); firstTimeSetup(); break; } esp_sleep_enable_timer_wakeup(300 * 1000000ULL); esp_sleep_enable_ext0_wakeup(GPIO_NUM_33, 1); esp_deep_sleep_start(); }
Multiple Wake Sources
You can enable timer AND ext0 AND touchpad wake simultaneously. The ESP32 wakes on whichever triggers first. Use esp_sleep_get_wakeup_cause() to determine which one fired and branch your logic accordingly.

RTC Memory -- State Across Sleep
Deep sleep erases all RAM. But 8KB of RTC memory survives. Use it to persist counters, calibration data, and boot state.
// RTC_DATA_ATTR persists across deep sleep cycles RTC_DATA_ATTR int bootCount = 0; RTC_DATA_ATTR float lastTemp = 0.0; RTC_DATA_ATTR unsigned long totalAwakeMs = 0; void setup() { unsigned long wakeTime = millis(); bootCount++; Serial.begin(115200); Serial.printf("Boot #%d | Last temp: %.1fC\n", bootCount, lastTemp); lastTemp = readTemperature(); totalAwakeMs += (millis() - wakeTime); Serial.printf("Total awake time: %lu ms over %d boots\n", totalAwakeMs, bootCount); esp_sleep_enable_timer_wakeup(60 * 1000000ULL); esp_deep_sleep_start(); }
RTC_DATA_ATTR
Prefix any global variable with RTC_DATA_ATTR to place it in RTC slow memory. This 8KB region stays powered during deep sleep. On first boot, variables initialize normally. On subsequent boots, they retain their last-written values.
What to Store
Boot counters, last sensor readings, accumulated statistics, calibration offsets, WiFi channel and BSSID (to speed reconnection), error counts. Keep it small -- you only have 8KB. For larger persistent data, use NVS flash (covered in Core 11).

The ULP Co-Processor
An ultra-low-power co-processor that runs independently during deep sleep, monitoring sensors without waking the main CPUs.
What Is the ULP?
The ULP (Ultra Low Power) co-processor is a separate, simple processor inside the ESP32 RTC domain. It runs its own program stored in RTC slow memory. It draws only ~150uA while active and can read ADC channels, monitor GPIO pins, and perform basic math.
When to Use It
When you need to monitor a sensor continuously but only wake the main CPUs when a threshold is crossed. Example: monitoring soil moisture -- the ULP reads the ADC every 30 seconds and only wakes the ESP32 when moisture drops below 30%.
ULP Capabilities
Read ADC (up to 2 channels), read/write GPIO, perform basic arithmetic and comparisons, access RTC memory, control RTC I2C peripheral, and trigger main CPU wake. It cannot access WiFi, Bluetooth, SPI, or main memory.
The ULP is like a night watchman: the main building (CPUs) is shut down and dark, but the watchman patrols with a flashlight, only calling the manager (waking the CPUs) if something requires attention.
ULP Programming
The ULP has its own assembly language (or can use the ULP-RISC-V C compiler on ESP32-S2/S3). Programs are loaded into RTC slow memory before entering deep sleep. The ULP program runs in a loop, checking conditions and either going back to sleep or waking the main CPU. Programming the ULP is an advanced topic typically handled through ESP-IDF rather than Arduino.

Battery-Powered Design Patterns
Practical strategies for building ESP32 devices that run on batteries for months or years.
Wake-Measure-Transmit-Sleep
The fundamental pattern: wake from deep sleep, read sensor, connect WiFi, transmit data, go back to sleep. Minimize awake time -- every millisecond of WiFi costs power. Cache WiFi channel and BSSID in RTC memory to skip scanning on wake.
Batch and Burst
Instead of transmitting every reading, store multiple readings in RTC memory and transmit in batches. Example: take a reading every 5 minutes, transmit a batch of 12 readings every hour. Reduces the number of expensive WiFi connections by 12x.
Adaptive Intervals
Adjust sleep duration based on conditions. If temperature is stable, sleep 30 minutes. If it is changing rapidly, sleep 2 minutes. Store the trend in RTC memory to make this decision. Use longer intervals at night when nobody is monitoring.
Disable Unused Hardware
Before sleeping, explicitly power down peripherals you do not need. Turn off the ADC, Bluetooth, WiFi radio, and unused GPIO pull-ups. Use esp_wifi_stop() and esp_bt_controller_disable() before entering light sleep.
Voltage Monitoring
Use an ADC pin with a voltage divider to monitor battery level. If the battery is critically low, skip the WiFi transmission and go straight to hibernation to preserve the last charge. Transmit a low-battery warning at 20% and shut down at 5%.
Fast WiFi Reconnect
Normal WiFi connection takes 2-5 seconds. Store the WiFi channel and router BSSID in RTC memory. On wake, use WiFi.begin(ssid, pass, channel, bssid) to skip scanning. Reconnection drops to 300-800ms, saving significant power per wake cycle.

Solar + Deep Sleep Duty Cycling
Combining solar charging with deep sleep creates devices that run indefinitely without maintenance.
Solar Charging Circuit
A small 1W-2W solar panel feeds a TP4056 lithium charge controller, which charges a 3.7V LiPo cell. The ESP32 draws power from the battery through a low-dropout (LDO) voltage regulator. Even on cloudy days, a 2W panel provides enough energy to sustain a device that sleeps 99% of the time.
Duty Cycle Math
If the ESP32 is awake for 3 seconds every 5 minutes: duty cycle = 3/300 = 1%. Average current = (240mA * 1%) + (10uA * 99%) = 2.41mA. A 2000mAh battery alone lasts 830 hours (34 days). With solar input of even 5mA average, the device runs indefinitely.
1 Size the panel for worst case: Assume 3-4 hours of effective sun on cloudy winter days. A 2W panel at 5V produces 400mA peak, but average over 24 hours might be only 50mA for 4 hours = ~8.3mA average.
2 Size the battery for night: At 2.41mA average draw, 16 hours of darkness consumes ~38.6mAh. A 500mAh battery covers multiple days of zero sun. Use 1000-2000mAh for safety margin.
3 Monitor both sides: Use ADC to read battery voltage AND solar panel voltage. If solar input drops to zero for extended periods (buried in snow, dirty panel), increase sleep interval to extend battery life.
Real World Example
A weather station reading temperature, humidity, and barometric pressure every 10 minutes, transmitting via WiFi: ~2mA average draw. With a 2W solar panel and 2000mAh LiPo, this system runs year-round in most climates without any maintenance.

Core 10 Summary
Everything you need to remember from this presentation.
1Five power states exist: Active (240mA), Modem Sleep (20mA), Light Sleep (0.8mA), Deep Sleep (10uA), and Hibernation (5uA). Deep sleep is the workhorse for battery-powered designs -- 24,000x less current than active mode.
2Deep sleep is a reboot. Call esp_deep_sleep_start() to enter. Waking runs through the bootloader and calls setup() again. All RAM is lost. All logic goes in setup(), not loop().
3Multiple wake sources: timer, touch pin, ext0 (single GPIO), ext1 (multiple GPIOs), and ULP co-processor. Configure multiple sources simultaneously -- whichever fires first wakes the chip.
4RTC memory (8KB) persists across deep sleep. Use RTC_DATA_ATTR to store boot counters, last readings, WiFi credentials cache, and state flags. This is how you maintain continuity despite the reboot.
5Design for minimum awake time. Cache WiFi channel/BSSID for fast reconnect, batch readings before transmitting, and adapt sleep intervals to conditions. Solar + deep sleep enables indefinite runtime for remote sensors.
