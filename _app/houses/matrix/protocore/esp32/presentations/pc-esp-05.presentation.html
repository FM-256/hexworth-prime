ESP32 as HTTP Client: GET Requests
The ESP32 can fetch data from any web API -- weather, time, stock prices. It speaks HTTP natively over WiFi.
// HTTP GET request #include <WiFi.h> #include <HTTPClient.h> void fetchData() { HTTPClient http; http.begin("http://api.example.com/sensor/1"); int httpCode = http.GET(); if (httpCode == 200) { String payload = http.getString(); Serial.println(payload); } else { Serial.printf("HTTP error: %d\n", httpCode); } http.end(); // Always close the connection }
HTTPClient
The built-in HTTPClient library handles connection, request formatting, and response parsing. Call begin(url), execute the method (GET/POST), read the response, then end().
Status Codes
200 = success. 301/302 = redirect. 404 = not found. 500 = server error. Always check the return code before reading the payload. Negative values mean a connection or DNS failure.
Memory
The ESP32 has ~320KB of usable RAM. Large HTTP responses can exhaust it. Use getStream() for chunked reading of large payloads instead of getString() which buffers everything in RAM.

HTTP POST: Sending Data
POST sends sensor data to a cloud API or database. The ESP32 formats JSON, sets headers, and sends the request.
// HTTP POST with JSON body #include <ArduinoJson.h> void sendSensorData(float temp, float humidity) { HTTPClient http; http.begin("http://api.example.com/data"); http.addHeader("Content-Type", "application/json"); JsonDocument doc; doc["temperature"] = temp; doc["humidity"] = humidity; doc["device"] = "ESP32-001"; String json; serializeJson(doc, json); int httpCode = http.POST(json); Serial.printf("POST response: %d\n", httpCode); http.end(); }
ArduinoJson Library
The de-facto JSON library for embedded systems. JsonDocument allocates memory for your JSON tree. serializeJson() converts it to a string. deserializeJson() parses incoming JSON. Install it via the Arduino Library Manager -- it is the most-downloaded Arduino library in existence.
Headers Matter
Always set Content-Type: application/json when sending JSON. APIs that expect JSON will reject requests without this header. You can also add authentication headers: Authorization: Bearer YOUR_TOKEN. The addHeader() method accepts any key-value pair.
JSON Parsing on Response
When a GET response returns JSON, parse it with ArduinoJson: deserializeJson(doc, payload). Then access fields like doc["temperature"].as<float>(). Always check the return value of deserializeJson() -- it returns DeserializationError::Ok on success, or an error code if the JSON is malformed or too large for your allocated buffer.

ESP32 as Web Server: Serve HTML
The ESP32 runs a web server on port 80. Browsers connect to its IP and receive HTML pages served from flash memory.
// Basic web server #include <WebServer.h> WebServer server(80); void handleRoot() { server.send(200, "text/html", "<h1>ESP32 Web Server</h1>" "<p>Uptime: " + String(millis() / 1000) + " seconds</p>" ); } void setup() { WiFi.begin("SSID", "password"); while (WiFi.status() != WL_CONNECTED) delay(500); server.on("/", handleRoot); server.begin(); } void loop() { server.handleClient(); }
Routes
server.on("/path", handler) maps a URL path to a callback function. You can define as many routes as you need: / for the homepage, /api/data for JSON, /config for settings.
server.send()
Three arguments: HTTP status code, content type, and body. Use text/html for web pages, application/json for API responses. The response is sent immediately to the client.
handleClient()
Must be called in loop() continuously. It checks for incoming HTTP connections and dispatches them to the correct route handler. If you block loop() with delays, the server becomes unresponsive.

Dynamic Pages: Sensor Data in HTML
Build HTML strings that include live sensor readings. Every time the browser refreshes, it gets the latest values.
// Dynamic sensor dashboard void handleDashboard() { float temp = readTemperature(); float hum = readHumidity(); String html = "<!DOCTYPE html><html><head>"; html += "<meta http-equiv='refresh' content='5'>"; html += "<style>body{font-family:sans-serif;background:#111;color:#eee;padding:40px;}"; html += ".card{background:#1a1a2e;border:1px solid #0088ff;border-radius:12px;"; html += "padding:20px;margin:10px;display:inline-block;}</style></head><body>"; html += "<h1>ESP32 Sensor Dashboard</h1>"; html += "<div class='card'><h2>" + String(temp) + " C</h2><p>Temperature</p></div>"; html += "<div class='card'><h2>" + String(hum) + " %</h2><p>Humidity</p></div>"; html += "</body></html>"; server.send(200, "text/html", html); }
Auto-Refresh
The meta http-equiv='refresh' content='5' tag tells the browser to reload the page every 5 seconds. Simple but causes a full page flash on each reload. For smoother updates, use JavaScript with fetch() or WebSocket (covered in slide 10).
String Building
Building HTML with String concatenation works for small pages but fragments heap memory on large ones. For production dashboards, store HTML templates in PROGMEM or SPIFFS and use placeholder replacement (%TEMP% replaced with the actual value at serve time).
SPIFFS / LittleFS
The ESP32 has a flash file system (SPIFFS or LittleFS) where you can store HTML, CSS, JavaScript, and image files. Upload a complete website to the flash and serve it with server.serveStatic("/", SPIFFS, "/"). This separates your web frontend from your Arduino C++ code, making both easier to maintain. LittleFS is the recommended replacement for SPIFFS -- it handles wear leveling and power-loss recovery better.

Form Handling: POST Data Parsing
HTML forms let users configure the ESP32 from a browser -- set WiFi credentials, adjust thresholds, name the device.
HTML Form
<form method="POST" action="/config"> <label>LED Brightness:</label> <input type="range" name="bright" min="0" max="255" value="128"> <label>Update Interval (s):</label> <input type="number" name="interval" value="5"> <button type="submit">Apply</button> </form>
Server Handler
void handleConfig() { if (server.method() == HTTP_POST) { String bright = server.arg("bright"); String interval = server.arg("interval"); analogWrite(LED_PIN, bright.toInt()); updateInterval = interval.toInt() * 1000; server.send(200, "text/html", "<p>Settings saved.</p>"); } } server.on("/config", HTTP_POST, handleConfig);
server.arg()
Extracts a named form field from the POST body. server.arg("bright") returns the value of the input named "bright". Works with both URL-encoded form data and query string parameters. Use server.hasArg("name") to check if a field exists before reading it.
Persistent Settings
Form values disappear on reboot unless you save them. Use the ESP32's Preferences library to store settings in NVS (Non-Volatile Storage). preferences.putInt("bright", val) writes to flash. preferences.getInt("bright", 128) reads with a default fallback.

HTTPS and TLS: Encrypted Communication
HTTP sends data in plaintext. HTTPS wraps it in TLS encryption. The ESP32 supports both as client and server.
HTTPS Client
Use WiFiClientSecure instead of WiFiClient. Set the CA certificate with setCACert() to verify the server's identity. Without certificate verification, you are vulnerable to man-in-the-middle attacks -- the same as ignoring browser SSL warnings.
Certificate Pinning
Embed the server's root CA certificate in your firmware. The ESP32 verifies the server's certificate chain against this root. If someone intercepts the connection with a fake certificate, the TLS handshake fails. Store certificates in PROGMEM to save RAM.
HTTPS Server
The ESP32 can serve HTTPS using a self-signed or CA-signed certificate stored in flash. TLS handshakes are CPU-intensive -- the ESP32 handles 2-3 concurrent HTTPS clients at most. Use HTTPS for configuration pages, not high-traffic sensor APIs.
// HTTPS client with certificate verification #include <WiFiClientSecure.h> const char* rootCA = \ "-----BEGIN CERTIFICATE-----\n" "MIIFYjCCBEqgAwIBAgIQ...\n" "-----END CERTIFICATE-----\n"; WiFiClientSecure client; client.setCACert(rootCA); HTTPClient http; http.begin(client, "https://api.example.com/secure"); int code = http.GET();
Never Skip Verification
Calling client.setInsecure() disables certificate verification entirely. This makes HTTPS pointless -- you get encryption but no authentication. An attacker can present any certificate and your ESP32 will accept it. Only use setInsecure() during development. In production, always pin a CA certificate.

REST API Design: Structured Routes
Organize your ESP32 web server like a real API. Clean routes, proper HTTP methods, JSON responses.
// RESTful API routes on ESP32 server.on("/", HTTP_GET, serveDashboard); server.on("/api/sensors", HTTP_GET, getSensors); // GET = read data server.on("/api/led", HTTP_POST, setLED); // POST = change state server.on("/api/config", HTTP_GET, getConfig); server.on("/api/config", HTTP_POST, updateConfig); server.onNotFound(handle404); void getSensors() { JsonDocument doc; doc["temperature"] = readTemp(); doc["humidity"] = readHumidity(); doc["uptime"] = millis() / 1000; String json; serializeJson(doc, json); server.send(200, "application/json", json); } void handle404() { server.send(404, "application/json", "{\"error\":\"not found\"}"); }
HTTP Methods
GET reads data without changing state. POST creates or modifies state. PUT replaces a resource. DELETE removes one. The ESP32 WebServer supports all methods. Using them correctly makes your API predictable and self-documenting.
CORS Headers
If your dashboard's JavaScript makes fetch() calls to the ESP32 API from a different origin, the browser blocks it (CORS policy). Add server.sendHeader("Access-Control-Allow-Origin", "*") to allow cross-origin requests. Handle OPTIONS preflight requests too.

Async Web Server: ESPAsyncWebServer
The built-in WebServer is blocking -- one client at a time. ESPAsyncWebServer handles multiple concurrent connections without blocking loop().
// Async web server (non-blocking) #include <ESPAsyncWebServer.h> AsyncWebServer server(80); void setup() { WiFi.begin("SSID", "password"); while (WiFi.status() != WL_CONNECTED) delay(500); server.on("/", HTTP_GET, [](AsyncWebServerRequest *request) { request->send(200, "text/html", "<h1>Async!</h1>"); }); server.on("/api/temp", HTTP_GET, [](AsyncWebServerRequest *request) { request->send(200, "application/json", "{\"temp\":" + String(readTemp()) + "}"); }); server.begin(); } void loop() { // No handleClient() needed -- server runs in background readSensors(); delay(100); }
Why Async?
The synchronous WebServer blocks during each request. If a client is slow, all other clients wait. ESPAsyncWebServer uses the ESP32's RTOS task system to handle connections in parallel. Your loop() stays free for sensor reading, motor control, or whatever else the device needs to do.
Template Processor
ESPAsyncWebServer has a built-in template processor. Store HTML in SPIFFS with placeholders like %TEMPERATURE%. The processor calls your function to replace each placeholder at serve time: request->send(SPIFFS, "/index.html", "text/html", false, processor).

WebSocket: Real-Time Bidirectional
HTTP is request-response. WebSocket is a persistent, full-duplex channel. The ESP32 pushes data to the browser the instant it changes.
ESP32 (Server)
AsyncWebSocket ws("/ws"); void onWsEvent(AsyncWebSocket *s, AsyncWebSocketClient *c, AwsEventType type, void *arg, uint8_t *data, size_t len) { if (type == WS_EVT_DATA) { // Client sent a message String msg = String((char*)data); if (msg == "LED_ON") digitalWrite(LED, HIGH); } } // In loop: push data ws.textAll(sensorJson);
Browser (Client)
const ws = new WebSocket( "ws://" + location.host + "/ws" ); ws.onmessage = (e) => { const data = JSON.parse(e.data); tempEl.textContent = data.temperature + " C"; }; // Send command to ESP32 btn.onclick = () => { ws.send("LED_ON"); };
Why WebSocket Over HTTP Polling?
HTTP polling sends a request every N seconds, each with full HTTP headers (~300 bytes overhead). WebSocket opens one connection and keeps it open. After the initial handshake, messages are just 2-10 bytes of framing overhead. For a dashboard updating every 100ms, WebSocket uses 100x less bandwidth than HTTP polling. The ESP32 can handle 4-8 concurrent WebSocket clients.

mDNS: Access by Hostname
Instead of remembering 192.168.1.47, type "esp32.local" in your browser. mDNS makes the ESP32 discoverable by name on the local network.
// mDNS setup #include <ESPmDNS.h> void setup() { WiFi.begin("SSID", "password"); while (WiFi.status() != WL_CONNECTED) delay(500); if (MDNS.begin("sensor-hub")) { Serial.println("mDNS: http://sensor-hub.local"); MDNS.addService("http", "tcp", 80); } server.begin(); }
How mDNS Works
mDNS (Multicast DNS) broadcasts hostname-to-IP mappings on the local network using multicast UDP on port 5353. When you type "sensor-hub.local" in a browser, your computer sends a multicast query. The ESP32 responds with its IP address. No DNS server needed.
Service Discovery
MDNS.addService("http", "tcp", 80) announces that the ESP32 is running an HTTP service on port 80. Tools like Bonjour Browser or avahi-browse can discover all mDNS services on the network automatically. This is how printers advertise themselves.
Platform Support
macOS and Linux support mDNS natively (via Bonjour / Avahi). Windows requires Bonjour to be installed (comes with iTunes) or uses the built-in mDNS resolver in modern versions. Android does not support .local domains in browsers -- use the IP address or a dedicated app.

Core 5 Summary: The ESP32 Web Stack
HTTP client, web server, REST APIs, WebSocket, HTTPS, mDNS -- all running on a $4 microcontroller.
1HTTP Client with HTTPClient. http.begin(url), GET() or POST(json), check the status code, read the response, end(). Use ArduinoJson for JSON serialization and parsing.
2Web Server with WebServer. Define routes with server.on("/path", handler). Respond with server.send(200, type, body). Call server.handleClient() in loop(). ESPAsyncWebServer removes the blocking constraint.
3Dynamic pages embed sensor data in HTML. Build HTML strings with String() concatenation or use template processors with SPIFFS-stored files. Auto-refresh with meta tags or JavaScript fetch() for smoother updates.
4WebSocket enables real-time push. One persistent connection, minimal framing overhead. The ESP32 pushes sensor data the instant it changes. The browser sends commands back. No polling, no page reloads.
5HTTPS and mDNS round out the stack. WiFiClientSecure + CA pinning for encrypted API calls. ESPmDNS for hostname access. Together they make the ESP32 a professional-grade edge device.
