The ESP32 Family Tree
Espressif Systems makes a family of chips. Each variant targets different use cases and price points.
ESP32 (Classic)
Xtensa LX6 dual-core @ 240MHz. WiFi + Bluetooth Classic + BLE. The original workhorse. Most documentation, most libraries, most community support.
ESP32-S2
Xtensa LX7 single-core. WiFi only, no Bluetooth. Native USB (HID/CDC). Lower power, lower cost. Good for USB peripherals and simple IoT.
ESP32-S3
Xtensa LX7 dual-core @ 240MHz. WiFi + BLE 5.0. Vector instructions for AI/ML at the edge. Native USB. The premium variant.
ESP32-C3
RISC-V single-core @ 160MHz. WiFi + BLE 5.0. Smallest, cheapest. Open-source CPU architecture. Drop-in replacement for ESP8266.
ESP32-C6
RISC-V single-core. WiFi 6 + BLE 5.0 + 802.15.4 (Thread/Zigbee). The Matter/smart-home chip. Future of IoT connectivity.
ESP32-H2
RISC-V single-core. BLE 5.0 + 802.15.4 only. No WiFi. Purpose-built for Thread, Zigbee, and Matter mesh networks.
Which One Are We Using?
This track uses the original ESP32 (Xtensa LX6 dual-core). It has the widest library support, the most tutorials, and the most forgiving ecosystem for learners. Everything you learn here transfers directly to the S3, C3, and C6 variants -- the APIs are nearly identical. Master the classic, and the rest are just pin count and feature flag differences.

Family at a Glance
Side-by-side comparison of key specifications across the ESP32 family.
Xtensa vs RISC-V
The older chips (ESP32, S2, S3) use Tensilica's proprietary Xtensa cores. The newer chips (C3, C6, H2) use RISC-V, an open-source instruction set. Both run the same ESP-IDF framework and Arduino libraries. The switch to RISC-V lowers Espressif's licensing costs and opens the CPU architecture for inspection.
The Trend Line
Espressif is moving toward specialization. The classic ESP32 does everything. Newer chips pick specific niches -- USB devices (S2), edge AI (S3), budget IoT (C3), smart home (C6), mesh-only (H2). Pick the chip that fits the job; do not overpay for features you will not use.

Xtensa LX6 Dual-Core Architecture
Two independent processor cores running at 240MHz. One handles your application, the other handles WiFi/Bluetooth.
Why Two Cores Matter
On a single-core Arduino, calling delay(1000) blocks everything -- including WiFi. On the ESP32, your application code runs on Core 1 while Core 0 keeps WiFi and Bluetooth alive. Network packets keep flowing even when your loop is busy with sensor reads or calculations.
FreeRTOS Under the Hood
The ESP32 runs FreeRTOS, a real-time operating system, to schedule tasks across both cores. When you write Arduino code, it runs as a single FreeRTOS task pinned to Core 1. Advanced users can create additional tasks and pin them to specific cores -- but that is a Core 7 topic.
Key Difference from Arduino
The Arduino Uno has one core running at 16MHz with no OS. The ESP32 has two cores running at 240MHz with FreeRTOS. That is a 15x clock speed advantage per core and two cores instead of one. The tradeoff: more power means more complexity. This track builds up that complexity layer by layer.

3.3V Logic -- Level Shifting Warning
The ESP32 runs on 3.3V logic. Arduino runs on 5V. Mixing them without a level shifter can destroy the ESP32.
Never Do This
Never connect a 5V output directly to an ESP32 GPIO pin. The pin's maximum voltage is 3.3V. Exceeding it will permanently damage the GPIO or destroy the chip entirely. This includes 5V sensors, 5V Arduino outputs, and 5V logic ICs.
Level Shifter
A bidirectional level shifter converts 5V signals to 3.3V and vice versa. Modules cost under $2. Connect the high side to 5V, the low side to 3.3V, and run your signals through it. Required whenever mixing voltage domains.
Voltage Divider
For one-way conversion (5V to 3.3V input), two resistors in a voltage divider work. A 1K/2K divider drops 5V to 3.33V. Cheap and fast for simple input signals. Not suitable for bidirectional or high-speed data lines.
Rule of Thumb
If a component says "5V logic" in its datasheet and you are connecting it to an ESP32, you need a level shifter or voltage divider. No exceptions. The ESP32 will not warn you -- it will simply stop working. Check voltage compatibility before every new connection.

Development Boards
The ESP32 chip is tiny. Development boards add USB, voltage regulation, buttons, and headers to make it breadboard-friendly.
ESP32 DevKit V1 (DOIT)
The most common board. 30 or 38 pins, micro-USB, onboard LED, EN and BOOT buttons. CP2102 or CH340 USB-to-serial chip. Costs $4-8. This is the "Arduino Uno" of the ESP32 world -- the default recommendation for beginners. Works with every tutorial.
ESP-WROOM-32
Espressif's reference module. The ESP32 chip plus flash memory, crystal oscillator, and PCB antenna in a shielded metal can. Most third-party boards use WROOM modules. When a board says "WROOM-32," it means the official Espressif module is soldered on.
TTGO T-Display
ESP32 board with a built-in 1.14" color TFT display. Great for projects that need a screen without wiring one. USB-C, 135x240 pixel display. More expensive (~$10) but eliminates display wiring entirely.
NodeMCU-32S
Community-designed board similar to the popular NodeMCU ESP8266 boards. Wider than DevKit V1, sometimes easier to use on a breadboard because it leaves more open rows. Good alternative if DevKit V1 is unavailable.
Which Board for This Track?
Any ESP32 DevKit V1 clone will work. They cost $4-8 and are available everywhere. Look for: USB connector, EN button, BOOT button, 30+ pins, and "ESP32-WROOM-32" printed on the metal shield. Avoid boards labeled "ESP8266" -- that is the older, single-core predecessor with no Bluetooth and less memory.

Two Frameworks: ESP-IDF vs Arduino-ESP32
You can program the ESP32 two ways. This track uses Arduino-ESP32 for familiarity, but you should know both exist.
ESP-IDF (Official SDK)
// Espressif IoT Development Framework // C-based, uses CMake build system // Full access to all hardware features // FreeRTOS tasks, event loops, components // Steeper learning curve // Professional / production use #include "esp_wifi.h" #include "esp_event.h" void app_main(void) { // Your entry point }
Arduino-ESP32 (Arduino Core)
// Arduino framework running on ESP32 // Same setup()/loop() you already know // Uses ESP-IDF under the hood // Thousands of Arduino libraries work // Easier learning curve // Prototyping / education / hobby #include <WiFi.h> void setup() { } void loop() { }
ESP-IDF: Full Power
Direct access to every ESP32 feature. Component-based architecture. CMake build system. Required for commercial products, advanced power management, and custom WiFi/BLE stacks. The learning curve is significant but the control is total.
Arduino-ESP32: Fast Start
Wraps ESP-IDF in the familiar Arduino API. Your existing Arduino knowledge transfers directly. Most Arduino libraries work without modification. You can even call ESP-IDF functions from Arduino code when you need lower-level access.
This Track Uses Arduino-ESP32
You already know setup() and loop() from the Arduino track. Arduino-ESP32 lets you use that knowledge immediately while adding WiFi, Bluetooth, and dual-core capabilities. When you outgrow Arduino, ESP-IDF is waiting -- and everything you learn about the hardware transfers directly.

Board Manager Setup
Adding ESP32 support to the Arduino IDE takes three steps.
1 Open Preferences. In Arduino IDE 2.x, go to File > Preferences. Find the "Additional Boards Manager URLs" field at the bottom of the dialog.
2 Add the ESP32 URL. Paste this URL into the field:
https://espressif.github.io/arduino-esp32/package_esp32_index.json
3 Install via Board Manager. Open Tools > Board > Boards Manager. Search for "esp32". Install "esp32 by Espressif Systems." This downloads the toolchain, compiler, and all ESP32 board definitions. Takes 1-3 minutes.
4 Select your board. After installation, go to Tools > Board > esp32 > "ESP32 Dev Module" (or "DOIT ESP32 DEVKIT V1"). Select the correct COM port under Tools > Port.
USB Driver Note
Most ESP32 DevKit boards use a CP2102 or CH340 USB-to-serial chip. Windows usually auto-installs the driver. If your board does not appear in the Port list, download the driver from Silicon Labs (CP2102) or WCH (CH340) and install manually.
Upload Speed
The default upload speed for ESP32 is 921600 baud -- much faster than Arduino's 115200. If uploads fail, try lowering to 115200 under Tools > Upload Speed. Cheap USB cables sometimes cannot sustain high baud rates.

First Blink on ESP32
The same Blink concept, adapted for ESP32 hardware. The built-in LED is on GPIO 2 (not pin 13).
// ESP32 Blink -- built-in LED on GPIO 2 #define LED_BUILTIN 2 void setup() { pinMode(LED_BUILTIN, OUTPUT); } void loop() { digitalWrite(LED_BUILTIN, HIGH); delay(1000); digitalWrite(LED_BUILTIN, LOW); delay(1000); }
GPIO 2, Not Pin 13
Most ESP32 DevKit boards wire the onboard LED to GPIO 2. Some boards (like the T-Display) have no onboard LED at all. Check your board's pinout diagram. The #define LED_BUILTIN 2 line makes the code explicit.
Upload Sequence
Some ESP32 boards require you to hold the BOOT button while uploading. Press and hold BOOT, click Upload, wait for "Connecting..." in the output, then release BOOT. Newer boards with auto-reset circuitry do not need this.
Same API, Different Hardware
Notice the code is identical to Arduino Blink except for the pin number. pinMode(), digitalWrite(), and delay() work exactly the same. The Arduino-ESP32 core maps these familiar functions to ESP32 hardware registers behind the scenes.

Serial Output on ESP32
Serial communication works the same way, but with one important difference: default baud rate is 115200.
void setup() { Serial.begin(115200); // ESP32 default baud rate delay(1000); // Wait for Serial Monitor to connect Serial.println("ESP32 booted"); Serial.print("CPU Freq: "); Serial.print(getCpuFrequencyMhz()); Serial.println(" MHz"); Serial.print("Free heap: "); Serial.print(ESP.getFreeHeap()); Serial.println(" bytes"); } void loop() { Serial.println("Running..."); delay(2000); }
115200 Baud, Not 9600
The ESP32 ecosystem uses 115200 baud as the default. This is 12x faster than Arduino's traditional 9600. Make sure the Serial Monitor baud rate matches. If you see garbled characters, the baud rates are mismatched. Some ESP32 boot messages also print at 115200 by default.
ESP32-Specific Functions
getCpuFrequencyMhz() returns the CPU clock speed. ESP.getFreeHeap() reports available RAM. ESP.getChipModel() identifies the chip variant. These ESP32-only functions help you understand what hardware your code is running on.
The delay(1000) After Serial.begin
The delay(1000) after Serial.begin() gives the USB-to-serial chip time to initialize and the Serial Monitor time to connect. Without it, early print statements may be lost. This is an ESP32-specific quirk -- the USB connection negotiation takes longer than on Arduino boards.

ESP32 vs Arduino Uno
Same programming model, vastly different hardware. Here is what changes and what stays the same.
Clock Speed
Arduino Uno: 16MHz, single core. ESP32: 240MHz, dual core. That is a 30x raw compute advantage. Code that was too slow on Arduino often runs effortlessly on ESP32.
Memory
Uno: 32KB flash, 2KB SRAM. ESP32: 4MB flash, 520KB SRAM. You can store large web pages, JSON configs, and SSL certificates directly in ESP32 flash. Memory is rarely a constraint.
Connectivity
Uno: none built in (shields required). ESP32: WiFi 802.11 b/g/n + Bluetooth Classic + BLE. The ESP32 is a network device out of the box. No shields, no add-on modules.
Voltage
Uno: 5V logic, 5V tolerant. ESP32: 3.3V logic, NOT 5V tolerant. This is the most dangerous difference. Always check voltage compatibility before connecting components.
ADC Resolution
Uno: 10-bit ADC (0-1023). ESP32: 12-bit ADC (0-4095). Four times the resolution for analog readings. However, the ESP32 ADC is non-linear and requires calibration for accuracy.
Programming Model
Both use setup() and loop(). Both use pinMode(), digitalWrite(), Serial.println(). If your Arduino code does not use hardware-specific features, it often compiles for ESP32 with zero changes.
