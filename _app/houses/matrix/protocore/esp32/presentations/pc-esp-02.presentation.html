On the Arduino Uno, each pin has a fixed purpose. On the ESP32, the GPIO matrix lets you assign almost any peripheral function to almost any pin. Touch sensing, analog-to-digital conversion, digital-to-analog output, Hall effect magnetic detection -- all built into the silicon, no external components required.

The GPIO Matrix
A crossbar switch inside the chip that routes any peripheral signal to (almost) any GPIO pin.
How It Works
The GPIO matrix is a programmable routing table inside the ESP32. When you call a function like SPI.begin(CLK, MISO, MOSI, CS) with custom pin numbers, the matrix routes those peripheral signals to the physical pins you specified. On Arduino, SPI pins are fixed. On ESP32, you choose.
Exceptions
GPIO 34-39 are input-only (no output capability, no internal pull-up). GPIO 6-11 are connected to the onboard flash memory and must not be used for general I/O. GPIO 0, 2, 5, 12, 15 have special boot-mode functions -- avoid them for critical inputs that might be held low during boot.
Arduino vs ESP32 Pin Philosophy
On Arduino, you memorize which pins do what. On ESP32, you tell the chip which pins should do what. This is a fundamental shift in hardware thinking. Instead of "SPI is on pins 10-13," you write SPI.begin(18, 19, 23, 5) and the GPIO matrix handles the routing. Change your mind? Change the pin numbers. The hardware adapts to your software, not the other way around.
Slide 3 of 12
Digital I/O
Reading and writing digital signals. Same API as Arduino, with ESP32-specific considerations.
// Digital output -- blink an LED on GPIO 2 pinMode(2, OUTPUT); digitalWrite(2, HIGH); // 3.3V (not 5V) // Digital input -- read a button on GPIO 4 pinMode(4, INPUT_PULLUP); int state = digitalRead(4); // LOW when pressed (active low) // Internal pull-up and pull-down both available pinMode(15, INPUT_PULLDOWN); // ESP32-only: pull-down resistor
OUTPUT: 3.3V
digitalWrite(pin, HIGH) outputs 3.3V on ESP32 (not 5V like Arduino). Current limit per pin is about 12mA recommended, 40mA absolute max. Enough for LEDs with a resistor, not enough for motors.
INPUT_PULLUP
Works identically to Arduino. Enables the internal pull-up resistor (~45K ohm). Pin reads HIGH by default, LOW when grounded. Standard for buttons. Available on GPIO 0-33 (not on input-only pins 34-39).
INPUT_PULLDOWN
ESP32-only feature -- Arduino Uno does not have internal pull-down resistors. Pin reads LOW by default, HIGH when connected to 3.3V. Useful when you want active-high button logic without external resistors.
Slide 4 of 12
Touch Pins -- Capacitive Sensing
10 GPIO pins double as capacitive touch sensors. Detect finger contact with no external hardware.
// Read capacitive touch value on GPIO 4 (Touch0) int touchValue = touchRead(4); Serial.println(touchValue); // Typical values: // Not touched: 60-80 // Touched: 10-20 // Threshold varies by environment // Touch-triggered interrupt touchAttachInterrupt(4, callback, 40); // threshold = 40
Touch Pin Map
Touch0 = GPIO 4, Touch1 = GPIO 0, Touch2 = GPIO 2, Touch3 = GPIO 15, Touch4 = GPIO 13, Touch5 = GPIO 12, Touch6 = GPIO 14, Touch7 = GPIO 27, Touch8 = GPIO 33, Touch9 = GPIO 32. Ten channels total. Wire a bare copper pad, foil strip, or even a fruit to the pin and detect touch.
How It Works
The ESP32 measures the capacitance on the pin. Your finger adds capacitance (human body is a conductor). The measured value drops when you touch the electrode. No buttons, no mechanical parts, no wear-out. Perfect for waterproof enclosures, custom keypads, and proximity detection.
No External Hardware Required
This is the key advantage. On Arduino, capacitive touch sensing requires an external MPR121 or similar IC plus a library. On ESP32, the hardware is built into the silicon. Just connect a conductive surface to the GPIO pin and call touchRead(). Calibrate the threshold for your specific setup by reading untouched values first.
Slide 5 of 12
Hall Effect Sensor
A magnetic field detector built into the ESP32 silicon. No external sensor needed.
// Read the built-in Hall effect sensor void setup() { Serial.begin(115200); } void loop() { int hallValue = hallRead(); Serial.print("Hall sensor: "); Serial.println(hallValue); delay(500); } // No magnet: ~0 to +/-30 (baseline noise) // North pole near chip: large positive value // South pole near chip: large negative value
What Is It?
The Hall effect sensor detects magnetic fields. It is integrated directly into the ESP32 die, near the center of the chip. When a magnet approaches the chip package, the sensor output changes proportionally to the magnetic field strength and polarity.
Use Cases
Door/window open-close detection (magnet on door, ESP32 on frame). RPM measurement (magnet on rotating shaft). Contactless switches. Proximity sensing for magnets. The sensitivity is moderate -- the magnet needs to be within a few centimeters of the chip.
Limitations
The built-in Hall sensor is convenient but not precision-grade. It shares ADC channels internally, so simultaneous ADC readings can affect accuracy. For precise magnetic field measurement, use an external sensor like the HMC5883L or MLX90393. The built-in sensor is best for binary detection (magnet present or not) rather than precise field measurement.
Slide 6 of 12
12-bit ADC -- Analog to Digital
Two ADC units with 18 channels total. 12-bit resolution (0-4095). But beware: the ADC is non-linear.
// Read analog voltage on GPIO 34 (ADC1_CH6) int raw = analogRead(34); // 0-4095 (12-bit) float voltage = raw * 3.3 / 4095; // Convert to voltage // Change resolution (default = 12) analogReadResolution(10); // Now returns 0-1023 like Arduino // Attenuation controls input voltage range analogSetAttenuation(ADC_11db); // 0-3.3V (default) // ADC_0db = 0-1.1V (most accurate) // ADC_2_5db = 0-1.5V // ADC_6db = 0-2.2V // ADC_11db = 0-3.3V (full range, least accurate)
Non-Linear Warning
The ESP32 ADC is notoriously non-linear, especially at the extremes. Readings near 0V and 3.3V are inaccurate. The middle range (0.15V-2.45V) is reasonable. For precision, use a lookup table calibration or an external ADC like the ADS1115.
ADC1 vs ADC2
ADC1 (GPIO 32-39) works independently. ADC2 (GPIO 0, 2, 4, 12-15, 25-27) cannot be used while WiFi is active. If you need analog reads with WiFi, use ADC1 pins only. This is a common trap that causes mysterious failures.
Attenuation
Attenuation controls the input voltage range. At 0dB, the ADC reads 0-1.1V with the best accuracy. At 11dB (default), it reads the full 0-3.3V range but with reduced accuracy. Choose the attenuation that matches your signal range for best results.
Slide 7 of 12
DAC -- Digital to Analog Output
Two 8-bit DAC channels output true analog voltages. Not PWM approximation -- real analog.
// DAC output on GPIO 25 (DAC1) or GPIO 26 (DAC2) dacWrite(25, 0); // 0V dacWrite(25, 128); // ~1.65V (half of 3.3V) dacWrite(25, 255); // ~3.3V // Generate a sawtooth wave void loop() { for (int i = 0; i < 256; i++) { dacWrite(25, i); delayMicroseconds(100); } }
True Analog Output
Unlike PWM (which rapidly switches between 0V and 3.3V to approximate intermediate voltages), the DAC outputs a genuine steady voltage. GPIO 25 is DAC channel 1, GPIO 26 is DAC channel 2. Only these two pins support DAC output. 8-bit resolution means 256 voltage steps from 0V to 3.3V.
Use Cases
Audio output (simple waveforms, tones). Voltage references for comparator circuits. Driving analog meters. Signal generation for testing. Note: for quality audio, use an external I2S DAC -- the built-in DAC has limited resolution and can introduce noise.
Arduino Uno Has No DAC
The Arduino Uno can only approximate analog output using PWM (analogWrite()). The ESP32 has two hardware DAC channels that output true analog voltages plus a far more capable PWM system (LEDC). This gives you both options -- real analog for steady voltages and PWM for motor/LED dimming.
Slide 8 of 12
LEDC PWM -- Software-Defined PWM
16 independent PWM channels with configurable frequency and resolution. Far more capable than Arduino's fixed PWM.
// ESP32 Arduino Core 3.x API (ledcAttach) const int ledPin = 2; void setup() { // Attach pin to LEDC with frequency and resolution ledcAttach(ledPin, 5000, 8); // 5kHz, 8-bit (0-255) } void loop() { // Fade LED up for (int duty = 0; duty <= 255; duty++) { ledcWrite(ledPin, duty); delay(10); } // Fade LED down for (int duty = 255; duty >= 0; duty--) { ledcWrite(ledPin, duty); delay(10); } }
Configurable Frequency
Arduino PWM is fixed at ~490Hz or ~980Hz depending on the pin. ESP32 LEDC lets you set any frequency from 1Hz to 40MHz. Need 1kHz for a buzzer? 25kHz for a silent motor driver? 50Hz for a servo? Just specify the frequency.
Configurable Resolution
Choose from 1-bit to 16-bit resolution. 8-bit gives 256 steps (like Arduino). 16-bit gives 65,536 steps for ultra-smooth fading. Higher resolution requires lower frequency -- the product of frequency x 2^resolution cannot exceed 80MHz.
16 Independent Channels
The ESP32 has 16 LEDC channels (8 high-speed, 8 low-speed). Each channel can have its own frequency and duty cycle. Multiple pins can share a channel for synchronized output. Arduino Uno has only 6 PWM pins with fixed frequencies.
Slide 9 of 12
PWM Frequency vs Resolution
There is a tradeoff: higher frequency means lower maximum resolution. The timer clock is 80MHz.
The Math
Max resolution bits = log2(80,000,000 / frequency). At 5kHz: log2(80M / 5K) = log2(16000) = ~13.9 bits, so 13-bit max. At 1kHz: log2(80K) = ~16.3 bits, so 16-bit max. At 312.5kHz: log2(256) = 8 bits max. Choose the combination that fits your application.
Common Configurations
LED dimming: 5kHz, 8-bit or 13-bit. Motor control: 25kHz, 8-bit (silent operation above human hearing). Servo control: 50Hz, 16-bit (precise positioning). Buzzer/tone: variable frequency, 1-bit (on/off is enough). Match the config to the device.
Slide 10 of 12
GPIO Interrupts
React to pin state changes instantly without polling. Every GPIO pin on the ESP32 supports interrupts.
volatile bool buttonPressed = false; void IRAM_ATTR handleButton() { buttonPressed = true; } void setup() { Serial.begin(115200); pinMode(4, INPUT_PULLUP); attachInterrupt(4, handleButton, FALLING); } void loop() { if (buttonPressed) { Serial.println("Button pressed!"); buttonPressed = false; } }
IRAM_ATTR Required
Interrupt handlers on ESP32 MUST be marked with IRAM_ATTR. This places the function in internal RAM instead of flash. Flash access can be blocked during WiFi operations -- if the ISR is in flash, the system crashes. This attribute is not needed on Arduino Uno.
Trigger Modes
RISING -- low to high transition. FALLING -- high to low. CHANGE -- any transition. LOW -- while pin is low. HIGH -- while pin is high. All five modes are supported on every GPIO pin.
ISR Rules
Keep interrupt handlers short. No Serial.print, no delay, no WiFi calls inside the ISR. Set a volatile flag and handle the work in loop(). The ISR fires on Core 0 by default -- keep it fast to avoid blocking WiFi. Debounce buttons in software using millis() in loop().

ESP32 Pin Reference
Quick reference for which pins do what. Bookmark this slide.
Safe General Purpose
GPIO 4, 13, 14, 16, 17, 18, 19, 21, 22, 23, 25, 26, 27, 32, 33. These pins have no boot-mode conflicts and work reliably for input, output, and peripheral routing. Start here.
Input Only (34-39)
GPIO 34, 35, 36 (VP), 39 (VN). No output, no internal pull-up/pull-down. ADC1 channels only. Good for sensor inputs and analog reads. Cannot drive LEDs or outputs.
Do Not Touch (6-11)
GPIO 6, 7, 8, 9, 10, 11. Connected to the onboard SPI flash. Using these pins will crash the ESP32 or corrupt the firmware. They are exposed on some boards but must never be used.
Boot-Mode Sensitive
GPIO 0 (must be HIGH to boot normally), GPIO 2 (must float or be LOW for download mode), GPIO 5 (affects SDIO timing), GPIO 12 (affects flash voltage), GPIO 15 (affects boot log output). Usable after boot but avoid pull-down resistors on these during startup.
Touch Pins
GPIO 0, 2, 4, 12, 13, 14, 15, 27, 32, 33. Ten capacitive touch channels. Use touchRead(pin). Can also be used as normal GPIO when touch sensing is not needed.
DAC Pins
GPIO 25 (DAC1), GPIO 26 (DAC2). Only these two pins support true analog output via dacWrite(). All other pins are limited to digital output or PWM.
