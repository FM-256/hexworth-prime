The ESP32's killer feature is built-in WiFi. No shields, no add-on modules -- the radio is on the same chip as the processor. In this core you learn to connect to networks, create hotspots, scan the airwaves, and handle the connection lifecycle. This is where your microcontroller joins the network.

802.11 b/g/n at 2.4GHz
The ESP32 supports WiFi on the 2.4GHz band. Here is what that means in practical terms.
802.11b (1999)
Up to 11 Mbps. Long range, high compatibility. The slowest standard but still useful for IoT devices that send small packets. The ESP32 supports it for backward compatibility with old access points.
802.11g (2003)
Up to 54 Mbps. Backward compatible with 802.11b. Good balance of speed and range. Most IoT devices negotiate this standard automatically.
802.11n (2009)
Up to 150 Mbps (single spatial stream on 2.4GHz). The fastest standard the ESP32 supports. Uses wider channels and MIMO techniques. Preferred when available.
2.4GHz Only
The classic ESP32 operates exclusively on the 2.4GHz band. It cannot connect to 5GHz networks. If your router broadcasts separate SSIDs for 2.4GHz and 5GHz, the ESP32 can only see the 2.4GHz one. Most routers also have a combined mode where the ESP32 will auto-select the 2.4GHz band.
Range and Interference
2.4GHz has better wall penetration than 5GHz but more interference (microwaves, Bluetooth, other WiFi devices, baby monitors). The ESP32's onboard PCB antenna has a typical range of 10-30 meters indoors. External antenna connectors (U.FL) on some boards extend this significantly.
For IoT, 2.4GHz Is Actually Ideal
IoT devices typically send small amounts of data infrequently. They need range and wall penetration more than raw speed. 2.4GHz delivers both. A sensor that sends a temperature reading every 30 seconds does not need 5GHz gigabit speeds -- it needs reliable connectivity through walls and across rooms.

Station Mode -- Connect to WiFi
Station mode (STA) connects the ESP32 to an existing WiFi network, just like your phone or laptop.
#include <WiFi.h> const char* ssid = "YourNetworkName"; const char* password = "YourPassword"; void setup() { Serial.begin(115200); WiFi.mode(WIFI_STA); WiFi.begin(ssid, password); Serial.print("Connecting"); while (WiFi.status() != WL_CONNECTED) { delay(500); Serial.print("."); } Serial.println("\nConnected!"); Serial.print("IP: "); Serial.println(WiFi.localIP()); }
WiFi.mode(WIFI_STA)
Explicitly sets the ESP32 to station mode. The ESP32 defaults to STA+AP mode if not set. Best practice is to always declare the mode explicitly. WIFI_STA means "client only" -- it connects to an access point but does not create one.
WiFi.status()
Returns the connection state. WL_CONNECTED means success. Other values: WL_DISCONNECTED, WL_CONNECT_FAILED (wrong password), WL_NO_SSID_AVAIL (network not found). Always check status before assuming connectivity.
Security: Never Hardcode Credentials in Production
The example above hardcodes the SSID and password directly in the source code. This is fine for learning and prototyping. In production, store credentials in NVS (non-volatile storage) or use a WiFi provisioning flow where the user enters credentials via a captive portal or Bluetooth.

AP Mode -- Create a Hotspot
Access Point mode turns the ESP32 into a WiFi hotspot. Other devices connect to it directly.
#include <WiFi.h> void setup() { Serial.begin(115200); WiFi.mode(WIFI_AP); WiFi.softAP("ESP32-Hotspot", "password123"); Serial.print("AP IP: "); Serial.println(WiFi.softAPIP()); // Default AP IP: 192.168.4.1 } void loop() { Serial.print("Connected stations: "); Serial.println(WiFi.softAPgetStationNum()); delay(5000); }
When to Use AP Mode
Initial device configuration (user connects to ESP32, opens a web page, enters their real WiFi credentials). Direct device-to-phone communication without a router. Field deployments where no infrastructure WiFi exists. Sensor hubs that collect data from nearby devices.
AP Limitations
Maximum 10 connected stations (configurable, default is 4). No internet access through the AP unless you also connect to a router in STA+AP mode. The AP runs its own DHCP server, assigning IPs in the 192.168.4.x range. Channel defaults to 1 but is configurable.
softAP() Parameters
WiFi.softAP(ssid, password, channel, hidden, max_connection). Password must be at least 8 characters for WPA2. Pass an empty string for an open network (not recommended). Channel 1-13 (varies by region). Hidden = 1 hides the SSID from scans. max_connection caps the number of clients.
Slide 5 of 12
STA+AP Simultaneous Mode
The ESP32 can connect to a WiFi network AND run its own hotspot at the same time.
WiFi.mode(WIFI_AP_STA); WiFi.begin(ssid, password); // Connect to router (STA) WiFi.softAP("ESP32-Config", "pass"); // Create hotspot (AP)
Use Case: Provisioning
Start in AP mode so the user can connect and enter WiFi credentials via a web page. Once configured, switch to STA mode (or STA+AP) to connect to the real network while keeping the configuration portal accessible as a fallback.
Use Case: Bridge
The ESP32 connects to the internet via STA, and nearby devices connect to it via AP. The ESP32 acts as a local gateway -- collecting sensor data from AP clients and forwarding it to a cloud server over the STA connection.

WiFi Scanning
Discover nearby networks: SSID, signal strength (RSSI), channel, and encryption type.
#include <WiFi.h> void setup() { Serial.begin(115200); WiFi.mode(WIFI_STA); WiFi.disconnect(); // Ensure clean state int n = WiFi.scanNetworks(); Serial.println("Scan complete"); for (int i = 0; i < n; i++) { Serial.printf("%2d) %-32s Ch:%2d RSSI:%4d %s\n", i + 1, WiFi.SSID(i).c_str(), WiFi.channel(i), WiFi.RSSI(i), (WiFi.encryptionType(i) == WIFI_AUTH_OPEN) ? "Open" : "Encrypted" ); } }
RSSI
Received Signal Strength Indicator, measured in dBm. -30 = excellent (very close to AP). -50 = good. -70 = fair. -80 = weak. -90 = barely usable. Useful for determining optimal device placement or building a signal strength map.
Channel
2.4GHz WiFi uses channels 1-13. Non-overlapping channels: 1, 6, 11. Knowing which channel a network uses helps avoid interference. The ESP32 scans all channels during WiFi.scanNetworks().
Encryption Type
WIFI_AUTH_OPEN, WIFI_AUTH_WEP, WIFI_AUTH_WPA_PSK, WIFI_AUTH_WPA2_PSK, WIFI_AUTH_WPA3_PSK. The scan reveals the security posture of every nearby network. Useful for security auditing labs.

WiFi Events and Auto-Reconnection
React to connection changes without polling. Event callbacks fire when WiFi state changes.
void onWiFiEvent(WiFiEvent_t event) { switch (event) { case ARDUINO_EVENT_WIFI_STA_CONNECTED: Serial.println("Connected to AP"); break; case ARDUINO_EVENT_WIFI_STA_GOT_IP: Serial.print("Got IP: "); Serial.println(WiFi.localIP()); break; case ARDUINO_EVENT_WIFI_STA_DISCONNECTED: Serial.println("Disconnected -- reconnecting..."); WiFi.reconnect(); break; } } void setup() { WiFi.onEvent(onWiFiEvent); WiFi.begin(ssid, password); }
Event-Driven Architecture
Instead of polling WiFi.status() in every loop iteration, register an event handler with WiFi.onEvent(). The callback fires asynchronously when state changes occur. This is cleaner and more responsive than polling.
Auto-Reconnection
WiFi connections drop. Routers reboot, signals fluctuate, interference spikes. Robust ESP32 code always handles disconnection gracefully. Call WiFi.reconnect() in the disconnect event handler. Add a backoff delay for persistent failures.
FreeRTOS Connection
WiFi events run on FreeRTOS tasks under the hood. The WiFi stack runs on Core 0, and event callbacks execute in the system event loop task. Core 7 explains why this works -- how FreeRTOS schedules tasks across both cores and why your loop() on Core 1 is not blocked by WiFi processing on Core 0.

Static IP vs DHCP
By default, the ESP32 gets an IP address from DHCP. You can also assign a fixed IP.
DHCP (Default)
// Let the router assign an IP WiFi.begin(ssid, password); // IP assigned automatically // Changes if DHCP lease expires // Simplest approach // Good for most projects
Static IP
IPAddress ip(192,168,1,200); IPAddress gw(192,168,1,1); IPAddress sn(255,255,255,0); IPAddress dns(8,8,8,8); WiFi.config(ip, gw, sn, dns); WiFi.begin(ssid, password); // Always at 192.168.1.200
When to Use DHCP
Most projects. The router manages IP assignment, and you read the IP after connection with WiFi.localIP(). For devices that report to a cloud server (MQTT, HTTP POST), the device initiates the connection, so its local IP does not matter.
When to Use Static IP
When the ESP32 runs a web server that other devices need to find. When you need predictable addressing for firewall rules. When DHCP is slow and you want faster connection times (skipping DHCP negotiation saves 1-3 seconds on boot).
Static IP Gotcha
If you set a static IP, you must also set the gateway, subnet mask, and DNS server. If any of these are wrong, the ESP32 will appear connected but will not be able to reach the internet. The gateway is usually your router's IP. DNS can be your router or a public DNS like 8.8.8.8 (Google) or 1.1.1.1 (Cloudflare).

WiFi Security
Understanding WPA2, WPA3, and the security implications of IoT devices on your network.
WPA2-PSK (Current Standard)
Pre-Shared Key authentication. All devices on the network share the same password. AES-CCMP encryption. The ESP32 fully supports WPA2-PSK. This is what most home and office networks use today. Secure enough for most IoT applications when combined with a strong password.
WPA3-PSK (Next Generation)
Simultaneous Authentication of Equals (SAE) replaces the 4-way handshake. Resistant to offline dictionary attacks. Forward secrecy protects past traffic even if the password is later compromised. The ESP32 supports WPA3 in newer IDF versions (v4.3+). Not all access points support WPA3 yet.
Open Networks
No encryption, no authentication. Anyone can see all traffic. Never use for anything sensitive. The ESP32 can connect to open networks but should only do so for initial provisioning or testing.
WEP (Broken)
Wired Equivalent Privacy from 1999. Cracked in minutes with freely available tools. The ESP32 supports WEP for backward compatibility, but you should never use it. If your network uses WEP, upgrade immediately.
WPA2-Enterprise
Uses RADIUS authentication with individual usernames and passwords (or certificates). Common in corporate and university networks. The ESP32 supports WPA2-Enterprise with EAP-PEAP and EAP-TTLS. Configuration is more complex but provides per-user authentication.

IoT Security Best Practices
Your ESP32 is a network device. Treat it like one.
Use HTTPS
Never send sensitive data over plain HTTP. The ESP32 supports TLS/SSL for encrypted connections. Use WiFiClientSecure for HTTPS requests. Pin certificates for extra security.
Credential Storage
Store WiFi passwords and API keys in NVS (Non-Volatile Storage), not in source code. Use the Preferences library for simple key-value storage that survives reboots and reflashing.
OTA Updates
Over-The-Air firmware updates should be signed and verified. An attacker on the network could push malicious firmware if OTA is unprotected. Use ArduinoOTA with a password at minimum.
Network Isolation
Put IoT devices on a separate VLAN or guest network. If an ESP32 is compromised, the attacker should not have access to your main network, file shares, or other sensitive devices.
Minimize Attack Surface
Disable WiFi when not needed. Do not run a web server if you only need outbound connections. Close ports you do not use. The fewer services exposed, the smaller the attack surface.
Monitor and Log
Log connection attempts, failed authentications, and unusual traffic patterns. The Serial Monitor is your first debugging tool, but consider sending logs to a syslog server for persistent monitoring.

Practical WiFi Patterns
Common patterns you will use in almost every WiFi project.
Connection with Timeout
Do not wait forever for WiFi to connect. Set a timeout (10-30 seconds). If connection fails, enter AP mode so the user can reconfigure. This prevents the device from hanging indefinitely if the network is down or credentials are wrong.
Hostname
Set a custom hostname so the ESP32 appears with a readable name on your router's device list: WiFi.setHostname("esp32-sensor"). Call this before WiFi.begin(). Much easier than identifying devices by MAC address.
MAC Address
Every ESP32 has a unique MAC address. Read it with WiFi.macAddress(). Useful for device identification, MAC-based access control lists on routers, and device provisioning systems. The MAC persists across reboots and reflashing.
WiFi Power Management
The WiFi radio draws ~100-170mA when active. For battery projects, use WiFi.setSleep(true) for light sleep mode or disconnect WiFi entirely between transmissions. Deep sleep (covered in a later core) can reduce consumption to microamps.
// Connection with timeout pattern WiFi.begin(ssid, password); unsigned long startAttempt = millis(); while (WiFi.status() != WL_CONNECTED && millis() - startAttempt < 15000) { delay(100); } if (WiFi.status() != WL_CONNECTED) { Serial.println("Failed -- starting AP mode"); WiFi.mode(WIFI_AP); WiFi.softAP("ESP32-Setup"); }

Core 3 Summary
Everything you need to remember from this presentation.
1The ESP32 supports 802.11 b/g/n on 2.4GHz only. No 5GHz support on the classic ESP32. Range is typically 10-30 meters indoors with the onboard antenna. 2.4GHz provides good wall penetration for IoT applications.
2Three WiFi modes: STA, AP, and STA+AP. Station mode connects to a router. AP mode creates a hotspot. STA+AP runs both simultaneously. Use WiFi.mode() to set explicitly.
3WiFi scanning reveals SSID, RSSI, channel, and encryption type. Use WiFi.scanNetworks() to discover nearby networks. RSSI values: -30 excellent, -50 good, -70 fair, -80 weak.
4WiFi events replace polling. Register callbacks with WiFi.onEvent(). Handle disconnection by calling WiFi.reconnect(). WiFi events run on FreeRTOS tasks under the hood. Core 7 explains why this works.
5Security is not optional. Use WPA2 or WPA3, store credentials in NVS, use HTTPS for data transmission, isolate IoT devices on a separate network, and always implement connection timeout with AP-mode fallback.
