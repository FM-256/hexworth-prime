What is ESP-NOW?
A connectionless, peer-to-peer wireless protocol developed by Espressif. No WiFi access point needed.
No Infrastructure
ESP-NOW uses raw 802.11 vendor-specific action frames. It does not need a WiFi router, an access point, or an internet connection. Two ESP32 boards in the middle of a desert can communicate with nothing but power and firmware.
Range and Speed
Line-of-sight range is approximately 200-480 meters depending on antenna and environment. Data rate is not high (250 bytes per packet), but latency is extremely low (~1ms). Perfect for control signals, sensor readings, and status updates.
Protocol Layer
ESP-NOW operates on top of the WiFi data link layer (802.11). It uses vendor-specific action frames that bypass the entire TCP/IP stack. No DHCP, no IP addresses, no sockets. Devices are identified solely by their 6-byte MAC address. This is why it is so fast -- the overhead of an entire networking stack is eliminated.

Broadcast vs Unicast
Send to one specific device (unicast) or to every device in range (broadcast).
Unicast (to one peer)
// Target a specific MAC address uint8_t peerMAC[] = { 0xAA, 0xBB, 0xCC, 0xDD, 0xEE, 0xFF }; // Must register peer first esp_now_peer_info_t peer; memcpy(peer.peer_addr, peerMAC, 6); peer.channel = 0; peer.encrypt = false; esp_now_add_peer(&peer); // Send to that specific peer esp_now_send(peerMAC, data, len);
Broadcast (to all)
// Broadcast MAC = all 0xFF uint8_t broadcastMAC[] = { 0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF }; // Register broadcast "peer" esp_now_peer_info_t peer; memcpy(peer.peer_addr, broadcastMAC, 6); peer.channel = 0; peer.encrypt = false; esp_now_add_peer(&peer); // Send to everyone in range esp_now_send(broadcastMAC, data, len);
Unicast: Delivery Confirmation
Unicast sends include a delivery callback. The onSend callback reports whether the target acknowledged the packet. This does not mean the data was processed -- just that the receiver's WiFi radio got it. Broadcast never gets acknowledgment.
Broadcast: Discovery
Broadcast is essential for device discovery. A new node broadcasts its MAC address, and existing nodes add it as a peer. Once peers are registered, switch to unicast for reliable communication with delivery confirmation.

Peer Registration
Before sending to a specific device, you must register it as a peer using its MAC address.
#include <esp_now.h> #include <WiFi.h> void setup() { Serial.begin(115200); WiFi.mode(WIFI_STA); // Station mode (required for ESP-NOW) // Print this device's MAC address Serial.print("MAC: "); Serial.println(WiFi.macAddress()); // Initialize ESP-NOW if (esp_now_init() != ESP_OK) { Serial.println("ESP-NOW init failed"); return; } // Register a peer esp_now_peer_info_t peerInfo = {}; uint8_t peerMAC[] = {0x24, 0x6F, 0x28, 0xA1, 0xB2, 0xC3}; memcpy(peerInfo.peer_addr, peerMAC, 6); peerInfo.channel = 0; // 0 = current channel peerInfo.encrypt = false; esp_now_add_peer(&peerInfo); }
1 WiFi.mode(WIFI_STA) -- ESP-NOW requires WiFi to be initialized in Station mode. You do not need to connect to a network -- just set the mode.
2 esp_now_init() -- Initializes the ESP-NOW protocol. Must be called after WiFi.mode().
3 esp_now_add_peer() -- Registers a peer by MAC address. You can register up to 20 peers (6 encrypted + 14 unencrypted, or 20 unencrypted).
Getting the MAC Address
Every ESP32 has a unique MAC address burned into its eFuse at the factory. Upload a sketch that prints WiFi.macAddress() to the Serial Monitor to find each board's address. Write them down -- you will need to hardcode them into your firmware. Dynamic discovery via broadcast is possible but adds complexity.

Sending and Receiving Data
ESP-NOW sends raw bytes. Define a struct to give your data structure, then cast it for transmission.
// Define a data structure (must be <= 250 bytes) typedef struct { uint8_t nodeId; float temperature; float humidity; uint32_t timestamp; char message[32]; } SensorPacket_t; // Total: 45 bytes // SENDER SensorPacket_t outgoing; outgoing.nodeId = 1; outgoing.temperature = 23.5; outgoing.humidity = 65.2; outgoing.timestamp = millis(); strcpy(outgoing.message, "sensor-room-A"); esp_now_send(peerMAC, (uint8_t *)&outgoing, sizeof(outgoing)); // RECEIVER (in onReceive callback) SensorPacket_t incoming; memcpy(&incoming, data, sizeof(incoming)); Serial.printf("Node %d: %.1fC, %.1f%%\n", incoming.nodeId, incoming.temperature, incoming.humidity);
250-Byte Limit
ESP-NOW packets have a maximum payload of 250 bytes. Your struct must fit within this limit. Use sizeof() to verify. If you need to send more data, split it across multiple packets with sequence numbers.
Struct Alignment
Both sender and receiver must use identical struct definitions. If the struct layout differs (due to packing or member order), the receiver will interpret garbage. Use #pragma pack(1) or __attribute__((packed)) for consistent alignment across different compilers.

Callback Functions
ESP-NOW uses two callbacks: onSend (delivery status) and onReceive (incoming data). Both fire asynchronously.
// Called when a packet is sent (or fails to send) void onSend(const uint8_t *mac, esp_now_send_status_t status) { Serial.print("Send to "); for (int i = 0; i < 6; i++) Serial.printf("%02X%s", mac[i], i < 5 ? ":" : ""); Serial.println(status == ESP_NOW_SEND_SUCCESS ? " OK" : " FAIL"); } // Called when a packet is received void onReceive(const uint8_t *mac, const uint8_t *data, int len) { Serial.printf("Received %d bytes from ", len); for (int i = 0; i < 6; i++) Serial.printf("%02X%s", mac[i], i < 5 ? ":" : ""); Serial.println(); // Process data here (or copy to queue for task processing) } void setup() { // ... after esp_now_init() ... esp_now_register_send_cb(onSend); esp_now_register_recv_cb(onReceive); }
onSend Callback
Reports delivery status for unicast packets. ESP_NOW_SEND_SUCCESS means the receiver acknowledged the frame at the radio level. ESP_NOW_SEND_FAIL means no acknowledgment was received. Broadcast always reports success (no ACK expected).
onReceive Callback
Fires on the WiFi task (Core 0) when data arrives. Keep processing minimal -- copy data to a FreeRTOS queue and return quickly. Heavy processing in the callback blocks WiFi operations. The data pointer is only valid during the callback.
Callback Context Warning
ESP-NOW callbacks run in the WiFi task context on Core 0 at a high priority. Do not call blocking functions, heavy computation, or Serial.print() with large strings inside callbacks. Copy the data to a queue and let a normal task process it. Violating this rule causes watchdog timeouts and WiFi instability.

Multi-Node Mesh
ESP-NOW does not natively support mesh routing, but you can build relay logic to extend range: A sends to B, B forwards to C.
// Relay node: receive from A, forward to C uint8_t nodeC_MAC[] = {0x30, 0xAE, 0xA4, 0x12, 0x34, 0x56}; void onReceive(const uint8_t *mac, const uint8_t *data, int len) { // Forward the packet to Node C esp_now_send(nodeC_MAC, data, len); Serial.printf("Relayed %d bytes to Node C\n", len); }
Hop Count
Add a hop counter to your struct. Each relay increments it. Set a maximum (e.g., 5 hops) to prevent infinite loops. If a packet exceeds max hops, drop it. This is basic TTL (Time To Live) logic.
Packet ID
Include a unique packet ID (sender MAC + sequence number). Relay nodes track recently seen IDs and drop duplicates. Without this, a packet can loop between nodes forever, consuming bandwidth and triggering watchdogs.
Routing Table
For complex meshes, each node maintains a table: "To reach Node C, forward to Node B." This table can be built manually (hardcoded) or dynamically via periodic broadcast discovery messages.
Slide 8 of 12
ESP-NOW + WiFi Simultaneously
ESP-NOW and WiFi can coexist on the same ESP32, but they must share the same channel.
Same Channel Requirement
ESP-NOW transmits on the WiFi channel. If you connect to a WiFi network on channel 6, ESP-NOW also uses channel 6. All ESP-NOW peers must be on the same channel to communicate. Set peer.channel = 0 to use the current channel.
Gateway Pattern
One ESP32 acts as a gateway: it receives ESP-NOW data from sensor nodes and forwards it to a server via WiFi/HTTP/MQTT. Sensor nodes use only ESP-NOW (low power). The gateway uses both ESP-NOW and WiFi simultaneously.
// Gateway node: ESP-NOW receiver + WiFi uplink void setup() { WiFi.mode(WIFI_AP_STA); // AP+STA mode for both protocols WiFi.begin("MyRouter", "password"); // Wait for WiFi connection while (WiFi.status() != WL_CONNECTED) { delay(500); } // Initialize ESP-NOW (works alongside WiFi) esp_now_init(); esp_now_register_recv_cb(onReceive); // Now this device receives ESP-NOW packets // AND can make HTTP/MQTT requests via WiFi }
Channel Mismatch Pitfall
If your WiFi router uses channel 11, all ESP-NOW peers must also be on channel 11. If a sensor node is not connected to WiFi, set its channel manually: esp_wifi_set_channel(11, WIFI_SECOND_CHAN_NONE). If the channels do not match, ESP-NOW packets are silently dropped -- no error, no callback, just silence.

ESP-NOW Encryption
ESP-NOW supports CCMP encryption (the same used in WPA2) for peer-to-peer communication. Optional but recommended for sensitive data.
// Shared key (must be same on both sender and receiver) uint8_t pmk[] = {0x01,0x02,0x03,0x04,0x05,0x06,0x07,0x08, 0x09,0x0A,0x0B,0x0C,0x0D,0x0E,0x0F,0x10}; uint8_t lmk[] = {0x11,0x12,0x13,0x14,0x15,0x16,0x17,0x18, 0x19,0x1A,0x1B,0x1C,0x1D,0x1E,0x1F,0x20}; esp_now_set_pmk(pmk); // Primary Master Key (device-level) esp_now_peer_info_t peer = {}; memcpy(peer.peer_addr, peerMAC, 6); memcpy(peer.lmk, lmk, 16); // Local Master Key (per-peer) peer.encrypt = true; // Enable encryption for this peer esp_now_add_peer(&peer);
Two-Key System
PMK (Primary Master Key) is device-wide -- set once per ESP32. LMK (Local Master Key) is per-peer -- different keys for different peers. Both are 16 bytes. The PMK and LMK together derive the session encryption key. Both sides must have matching keys.
Encrypted Peer Limit
You can register up to 6 encrypted peers and 14 unencrypted peers (20 total). If all peers need encryption, you are limited to 6 simultaneous connections. For larger networks, use application-layer encryption (AES in software) instead of ESP-NOW's built-in encryption.

ESP-NOW Use Cases
Where ESP-NOW shines over WiFi, Bluetooth, and other protocols.
Sensor Networks
Multiple battery-powered sensors reporting temperature, humidity, motion to a central gateway. Low power, no router needed.
Remote Controls
Handheld controller sending joystick data to a robot or drone at ~1ms latency. Faster than Bluetooth pairing and lower latency than WiFi.
Distributed Systems
Multiple ESP32s coordinating LED displays, audio sync, or environmental control across a building without network infrastructure.
Alarm Systems
Door/window sensors broadcasting open/close status to a central alarm node. No WiFi dependency means no network-based attacks.
Data Loggers
Field sensors collecting data in remote locations with no internet. A mobile gateway device drives nearby and collects logged data via ESP-NOW.
Vehicle Telemetry
ESP32 in an RC car sending speed, battery, and sensor data to a base station at the track. Real-time, low-latency, no infrastructure.
When NOT to Use ESP-NOW
ESP-NOW is wrong for: large file transfers (250-byte limit), internet-connected applications (use WiFi), phone/tablet communication (use BLE), or networks with more than 20 peers. If you need TCP reliability, HTTP APIs, or cloud connectivity, use standard WiFi. ESP-NOW is for fast, local, lightweight device-to-device communication.

Complete Sender Example
A full working sketch that sends sensor data to a peer every 2 seconds.
#include <esp_now.h> #include <WiFi.h> uint8_t receiverMAC[] = {0x24, 0x6F, 0x28, 0xAA, 0xBB, 0xCC}; typedef struct { uint8_t id; float value; uint32_t seq; } Packet_t; uint32_t seqNum = 0; void onSend(const uint8_t *mac, esp_now_send_status_t s) { Serial.println(s == ESP_NOW_SEND_SUCCESS ? "ACK" : "NACK"); } void setup() { Serial.begin(115200); WiFi.mode(WIFI_STA); esp_now_init(); esp_now_register_send_cb(onSend); esp_now_peer_info_t peer = {}; memcpy(peer.peer_addr, receiverMAC, 6); peer.channel = 0; peer.encrypt = false; esp_now_add_peer(&peer); } void loop() { Packet_t pkt = {1, analogRead(34) * 0.1, seqNum++}; esp_now_send(receiverMAC, (uint8_t*)&pkt, sizeof(pkt)); delay(2000); }

Core 9 Summary
ESP-NOW Mesh Networking -- key takeaways from this core.
01ESP-NOW is a connectionless, peer-to-peer protocol. No router, no IP addresses, no TCP/IP stack. Just MAC addresses and raw bytes.
02Maximum payload is 250 bytes per packet. Latency is approximately 1ms. Range is 200-480 meters line-of-sight.
03Broadcast (FF:FF:FF:FF:FF:FF) reaches all devices in range. Unicast targets one peer and provides delivery confirmation.
04Peers must be registered with esp_now_add_peer() before unicast sending. Up to 20 peers (6 encrypted).
05Define structs for data packaging. Both sender and receiver must use identical struct definitions.
06onSend reports delivery status. onReceive fires when data arrives. Keep callbacks fast -- offload to queues.
07Mesh relaying is manual: receive on Node B, forward to Node C. Add hop counts and packet IDs to prevent loops.
08ESP-NOW and WiFi coexist on the same channel. Gateway pattern: ESP-NOW from sensors, WiFi to cloud.
09Use ESP-NOW for fast, local, lightweight device-to-device communication. Use WiFi for internet, BLE for phones.
