Arduino gives you analogWrite() and that is about it. The ESP32 has dedicated hardware peripherals that handle motor control, LED strip timing, audio streaming, and pulse counting entirely in hardware -- zero CPU load. These are not software abstractions. These are silicon circuits on the chip that Arduino boards simply do not have.

MCPWM -- Motor Control PWM
A dedicated hardware peripheral for generating precise PWM signals with dead-time insertion, fault detection, and synchronized outputs.
Not Just Another PWM
Arduino's analogWrite() generates a basic PWM signal using software timers. MCPWM is a dedicated silicon block with its own clock, comparators, and fault pins. It generates complementary PWM pairs, inserts dead-time between transitions, and shuts down automatically on fault -- all in hardware.
Two MCPWM Units
The ESP32 has 2 MCPWM units, each with 3 operators and 2 comparators per operator. That is 6 independent PWM output pairs. Each pair can generate complementary signals (PWMxA and PWMxB) for driving H-bridge motor controllers. More than enough for a dual-motor robot or a 3-phase BLDC motor.
Fault Handling
Each MCPWM unit has hardware fault input pins. When a fault signal is detected (overcurrent, overtemperature), the PWM outputs immediately force to a safe state -- both LOW, both HIGH, or tri-state. This happens in nanoseconds, faster than any software interrupt could react. Critical for motor safety.
Why Motors Need Dedicated PWM Hardware
When driving motors through an H-bridge, both the high-side and low-side transistors must never be ON simultaneously -- that creates a shoot-through short circuit that destroys the bridge. Dead-time insertion adds a brief gap (100-500ns) between turning one transistor off and the other on. Software PWM cannot guarantee this timing. MCPWM handles it in hardware with configurable dead-time registers.

MCPWM in Code
Configuring MCPWM for DC motor speed and direction control via ESP-IDF API.
#include "driver/mcpwm_prelude.h" // 1. Create timer mcpwm_timer_handle_t timer; mcpwm_timer_config_t timer_cfg = { .group_id = 0, .clk_src = MCPWM_TIMER_CLK_SRC_DEFAULT, .resolution_hz = 10000000, // 10MHz resolution .period_ticks = 10000, // 1kHz PWM frequency .count_mode = MCPWM_TIMER_COUNT_MODE_UP, }; mcpwm_new_timer(&timer_cfg, &timer); // 2. Create operator and comparator mcpwm_oper_handle_t oper; mcpwm_new_operator(&(mcpwm_operator_config_t){.group_id = 0}, &oper); mcpwm_operator_connect_timer(oper, timer); // 3. Set duty cycle (0-10000 ticks = 0-100%) mcpwm_comparator_set_compare_value(comparator, 5000); // 50% duty
Timer, Operator, Comparator
MCPWM uses a three-layer hierarchy. The timer generates the base frequency. The operator manages a PWM output pair. The comparator sets the duty cycle by defining when the output transitions within each period. This separation allows multiple operators to share one timer for synchronized multi-channel output.
ESP-IDF vs Arduino
MCPWM is an ESP-IDF API -- there is no Arduino wrapper. You include driver/mcpwm_prelude.h and use ESP-IDF functions directly inside your Arduino sketch. This is common for ESP32-specific peripherals. The Arduino framework and ESP-IDF coexist in the same project.
Dead-Time Configuration
Add dead-time with mcpwm_dead_time_config_t. Set .posedge_delay_ticks and .negedge_delay_ticks independently. At 10MHz timer resolution, each tick is 100ns. A dead-time of 5 ticks = 500ns -- a safe margin for most MOSFET H-bridge drivers. The dead-time is enforced by hardware regardless of CPU load, interrupt latency, or WiFi activity.

RMT -- Remote Control Transceiver
Originally designed for infrared remote control signals, but its real superpower is driving addressable LEDs.
NeoPixel / WS2812B Driver
WS2812B LEDs require precisely timed pulses: 0.4us HIGH + 0.85us LOW for a '0' bit, 0.8us HIGH + 0.45us LOW for a '1' bit. On Arduino, this is done by disabling interrupts and bit-banging. On ESP32, that fails because WiFi interrupts corrupt the timing. RMT generates the pulses in hardware -- perfect timing, zero CPU involvement, WiFi keeps running.
IR Transmit and Receive
RMT's original purpose. Record incoming IR pulse trains (carrier frequency, mark/space timings) and replay them. Build a universal remote, clone an IR signal, or create an IR-controlled device. The RMT peripheral handles 38kHz carrier modulation in hardware. No timing-critical loops needed.
8 RMT Channels
The ESP32 has 8 RMT channels (4 TX, 4 RX on newer ESP-IDF). Each channel can independently drive a NeoPixel strip, decode an IR signal, or generate any arbitrary pulse pattern. You can run 4 independent LED strips simultaneously without any CPU overhead. Each channel has its own 256-word memory block for storing pulse definitions.

RMT NeoPixel Code
Driving WS2812B addressable LEDs using ESP-IDF's RMT driver. No bit-banging, no interrupt conflicts.
#include "led_strip.h" // ESP-IDF LED strip component #define LED_PIN 48 #define NUM_LEDS 30 led_strip_handle_t strip; void setup() { led_strip_config_t strip_cfg = { .strip_gpio_num = LED_PIN, .max_leds = NUM_LEDS, }; led_strip_rmt_config_t rmt_cfg = { .resolution_hz = 10000000, // 10MHz }; led_strip_new_rmt_device(&strip_cfg, &rmt_cfg, &strip); led_strip_clear(strip); } void loop() { for (int i = 0; i < NUM_LEDS; i++) { led_strip_set_pixel(strip, i, 0, 0, 255); // Blue } led_strip_refresh(strip); // Push to LEDs via RMT delay(100); }
FastLED Alternative
The popular FastLED library also uses RMT on ESP32 automatically. Install FastLED from Library Manager and it detects ESP32 at compile time, routing all LED data through RMT channels instead of bit-banging. Same API as Arduino, but backed by hardware timing. If you already know FastLED, it just works on ESP32.
NeoPixelBus Library
Another option that explicitly exposes RMT channel selection. NeoPixelBus<NeoGrbFeature, NeoEsp32RmtNWs2812xMethod> lets you specify which RMT channel to use. Useful when you need fine-grained control over channel allocation, especially when mixing LED strips with IR receivers.
Arduino's analogWrite() Cannot Do This
NeoPixel timing requires sub-microsecond precision on a single data line. This is not PWM -- it is a custom serial protocol where the pulse width encodes each bit. Arduino disables interrupts during transmission to guarantee timing. On ESP32, WiFi interrupts fire every few milliseconds and cannot be disabled without breaking connectivity. RMT solves this by generating the pulse train entirely in dedicated hardware, independent of the CPU and its interrupts.

I2S -- Inter-IC Sound
A hardware peripheral for streaming digital audio data at high speed. Input (microphones) and output (speakers/DACs).
PDM Microphones
INMP441, SPH0645. Digital MEMS microphones that output audio as a Pulse Density Modulation stream. I2S decodes it to PCM samples in hardware. No ADC needed. Studio-quality audio capture from a $2 chip.
DAC Audio Output
Stream PCM audio samples to an external I2S DAC (MAX98357A, PCM5102) for high-quality speaker output. Or use the ESP32's built-in 8-bit DAC for simple audio playback. The I2S peripheral handles the continuous data stream without CPU intervention.
Two I2S Ports
The ESP32 has 2 independent I2S interfaces (I2S0 and I2S1). Run a microphone on I2S0 and a speaker on I2S1 simultaneously for real-time audio processing, voice recording, or intercom systems.
DMA Buffering
I2S uses DMA to stream audio data between memory and the peripheral. You configure a ring buffer of DMA descriptors. The hardware cycles through them continuously, reading or writing audio samples without any CPU involvement.
Sample Rates
I2S supports 8kHz to 48kHz (and beyond) at 16-bit or 32-bit depth. Phone quality is 8kHz/16-bit. CD quality is 44.1kHz/16-bit. The ESP32 handles CD-quality audio in both directions simultaneously.
Beyond Audio
I2S is just a high-speed serial interface. People use it for driving LED matrices (parallel output mode), reading camera sensors, and any application that needs a continuous, clocked data stream. The LCD_CAM peripheral on ESP32-S3 evolved from I2S.
Arduino Cannot Do Audio Streaming
The Arduino Uno has no I2S peripheral. Playing audio on Arduino means using tone() for square waves or hacking the PWM timer for crude 8-bit playback. The ESP32's I2S peripheral streams 16-bit stereo audio at 44.1kHz through DMA with zero CPU load. This is a fundamentally different capability, not just a speed improvement.

I2S Microphone Recording
Capturing audio from an INMP441 PDM microphone using the ESP32's I2S peripheral.
#include "driver/i2s_std.h" i2s_chan_handle_t rx_chan; void setup() { i2s_chan_config_t chan_cfg = I2S_CHANNEL_DEFAULT_CONFIG(I2S_NUM_0, I2S_ROLE_MASTER); i2s_new_channel(&chan_cfg, NULL, &rx_chan); i2s_std_config_t std_cfg = { .clk_cfg = I2S_STD_CLK_DEFAULT_CONFIG(16000), // 16kHz sample rate .slot_cfg = I2S_STD_PHILIPS_SLOT_DEFAULT_CONFIG( I2S_DATA_BIT_WIDTH_16BIT, I2S_SLOT_MODE_MONO), .gpio_cfg = { .bclk = GPIO_NUM_26, .ws = GPIO_NUM_25, .din = GPIO_NUM_33, }, }; i2s_channel_init_std_mode(rx_chan, &std_cfg); i2s_channel_enable(rx_chan); } void loop() { int16_t samples[512]; size_t bytes_read; i2s_channel_read(rx_chan, samples, sizeof(samples), &bytes_read, portMAX_DELAY); // Process 512 audio samples here }
INMP441 Wiring
INMP441 needs 4 wires: WS (word select / left-right clock), SCK (bit clock), SD (serial data), and L/R (tie to GND for left channel or VCC for right). No analog amplifier needed -- the microphone outputs digital audio directly.
Audio Processing
Once you have the sample buffer, you can calculate volume (RMS), detect frequency (FFT), apply filters, or stream to a server. The ESP32-S3 with vector instructions can perform real-time FFT at 16kHz. For the classic ESP32, the arduinoFFT library handles spectrum analysis.

PCNT -- Pulse Counter
Hardware pulse counting at up to 40MHz. Rotary encoders, frequency measurement, and RPM sensing without CPU involvement.
Rotary Encoder Decoding
A quadrature encoder outputs two square waves (A and B) 90 degrees apart. Counting pulses on A while checking B's level determines direction. On Arduino, this requires interrupts that fire thousands of times per second. PCNT does it in hardware -- count and direction at any speed, zero CPU load. The counter updates in silicon.
8 PCNT Units
The ESP32 has 8 independent PCNT units, each with 2 channels. Each channel has a signal input and a control input. The control input determines count direction. Configure edge detection (rising, falling, both), count limits, and watchpoint interrupts. Read the counter value at any time -- it is a hardware register.
#include "driver/pulse_cnt.h" pcnt_unit_handle_t pcnt_unit; pcnt_unit_config_t unit_cfg = { .high_limit = 1000, .low_limit = -1000, }; pcnt_new_unit(&unit_cfg, &pcnt_unit); pcnt_chan_config_t chan_cfg = { .edge_gpio_num = 34, // Encoder A .level_gpio_num = 35, // Encoder B (direction) }; pcnt_channel_handle_t chan; pcnt_new_channel(pcnt_unit, &chan_cfg, &chan); // Read count value int count; pcnt_unit_get_count(pcnt_unit, &count);
Why Not Use Interrupts?
Software interrupts on Arduino work for slow encoders (manual knobs). But a motor encoder at 10,000 RPM with 1,000 pulses per revolution generates 166,667 interrupts per second. Each interrupt takes microseconds to service. At high speeds, the CPU spends all its time in interrupt handlers and your main loop never runs. PCNT counts at 40MHz in hardware -- the CPU just reads a register when it needs the current position.

SDMMC -- Native SD Card
The ESP32 has a dedicated SD/MMC host controller that reads SD cards 4-10x faster than SPI mode.
SPI Mode (Slow)
Arduino SD libraries use SPI mode: one data line, shared bus, limited speed. Typical throughput: 1-4 MB/s. Uses standard SPI pins. Simple wiring (4 wires). Good enough for logging sensor data at low rates. This is what most Arduino projects use.
1-Bit SD Mode
SDMMC in 1-bit mode uses the native SD protocol with one data line. Faster than SPI mode due to the dedicated SD protocol (no SPI overhead). Typical throughput: 5-10 MB/s. Uses GPIO 15 (CMD), GPIO 14 (CLK), GPIO 2 (DATA0). Conflicts with the built-in LED on GPIO 2.
4-Bit SD Mode
Full 4-bit SDMMC bus: 4 data lines, clock, and command. Typical throughput: 10-20 MB/s. Uses GPIO 2, 4, 12, 13 for data. GPIO 12 conflict with flash voltage selection requires special handling. Maximum SD card performance on ESP32.
#include "SD_MMC.h" void setup() { Serial.begin(115200); // Mount SD card in 1-bit mode (fewer GPIO conflicts) if (!SD_MMC.begin("/sdcard", true)) { // true = 1-bit mode Serial.println("SD mount failed"); return; } Serial.printf("Card size: %lluMB\n", SD_MMC.cardSize() / (1024 * 1024)); }
When to Use SDMMC vs SPI SD
Use SPI SD when you just need to log sensor data or serve small files. Use SDMMC when you are recording audio (I2S microphone to SD), capturing images (camera module), or serving large files from a web server. The 4-10x speed difference matters when you are writing continuous audio at 44.1kHz/16-bit (176KB/s) or streaming JPEG frames.

LED PWM vs MCPWM
The ESP32 has two separate PWM systems. They serve different purposes. Using the wrong one wastes hardware capabilities.
LED PWM (LEDC) -- For LEDs and Servos
// 16 independent channels // Up to 40MHz frequency // Up to 20-bit resolution // Hardware fade (smooth dimming) // No dead-time, no fault pins ledcSetup(0, 5000, 8); // ch0, 5kHz, 8-bit ledcAttachPin(2, 0); // GPIO 2 to ch0 ledcWrite(0, 128); // 50% duty // Hardware fade (no loop needed) ledcFade(0, 0, 255, 2000); // 0-255 in 2s
MCPWM -- For Motors and Power
// 2 units x 3 operators = 6 pairs // Complementary output (A + B) // Dead-time insertion // Hardware fault detection // Synchronized multi-channel // Use for: // - DC motor H-bridge control // - BLDC motor 3-phase drive // - Power converter switching // - Any application where // shoot-through protection matters
Use LEDC For
LED brightness control, servo motors (50Hz PWM), buzzer tones, simple speed control with single-direction motor drivers (L298N enable pin), backlight dimming. 16 channels means you can independently control 16 LEDs or servos. Hardware fade generates smooth dimming without a loop.
Use MCPWM For
H-bridge motor control, BLDC motor driving, half-bridge and full-bridge power converters, any application requiring complementary PWM signals with dead-time protection. MCPWM's fault input pins provide hardware-level safety shutoff that LEDC does not have.

ESP32 Peripheral Map
All the dedicated hardware peripherals that separate the ESP32 from Arduino. Every one of these runs independently of the CPU.
MCPWM x2
Motor control PWM with dead-time, fault pins, and complementary outputs. 6 output pairs total. Not available on any Arduino board.
RMT x8
Remote Control Transceiver. Generates and captures precise pulse trains. NeoPixels, IR, and custom protocols. 8 channels, 4 TX + 4 RX.
I2S x2
Digital audio interface. Stream PCM audio in/out via DMA. Microphones, DACs, speakers. Two independent ports for full duplex.
PCNT x8
Hardware pulse counter. Quadrature encoder decoding, frequency measurement, RPM sensing. 8 units, each with 2 channels.
SDMMC x1
Native SD card host controller. 1-bit or 4-bit bus mode. 10-20 MB/s throughput. Dedicated silicon, not SPI emulation.
LEDC x16
LED PWM controller. 16 independent channels with hardware fade. Up to 20-bit resolution. For LEDs, servos, and simple PWM output.
The GPIO Matrix Enables Everything
Unlike Arduino where each peripheral is hard-wired to specific pins, the ESP32's GPIO matrix lets you route any peripheral to (almost) any GPIO pin. MCPWM channel 0 can output on GPIO 15 or GPIO 25 -- you choose. RMT channel 3 can use any available GPIO. This flexibility means you design your PCB first, then assign peripherals to pins in software. The only exceptions are ADC, DAC, and a few strapping pins.

Core 14 Summary
Everything you need to remember from this presentation.
1MCPWM is dedicated motor control hardware. Complementary PWM outputs, dead-time insertion, and hardware fault detection. Two units with 6 output pairs. Use it for H-bridge and BLDC motor control where shoot-through protection is critical. LEDC is for LEDs and servos.
2RMT generates and captures precision pulse trains in hardware. Originally for IR remote signals, but its killer application is driving WS2812B NeoPixel LEDs without disabling interrupts. 8 channels, zero CPU load, WiFi keeps running.
3I2S streams digital audio through DMA. Two independent ports for microphones (INMP441) and speakers (MAX98357A) simultaneously. Supports 8kHz to 48kHz at 16 or 32-bit depth. CD-quality audio on a $5 chip.
4PCNT counts pulses in hardware at up to 40MHz. Quadrature encoder decoding without interrupts. 8 units, each with 2 channels. Read the counter register anytime -- the count never misses a pulse regardless of CPU load.
5SDMMC provides native SD card access 4-10x faster than SPI. Use 1-bit mode to avoid GPIO 12 conflicts. Essential for audio recording, image capture, and high-throughput data logging applications.
