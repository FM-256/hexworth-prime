Arduino in the Cybersecurity Context
Why security professionals reach for microcontrollers during hardware assessments.
Offensive
Enumerate debug ports (JTAG, UART, SWD). Dump firmware from flash chips. Inject signals into bus protocols. Emulate USB HID devices. Bypass physical access controls. Arduino is the Swiss army knife of hardware pentesting.
Defensive
Monitor for tamper events. Detect unauthorized USB devices. Log physical access attempts. Create tripwires for server rooms. Build honeypot hardware. Verify cable integrity. Arduino makes physical security programmable.
Forensic
Capture serial bus traffic for analysis. Record timing of signals. Extract data from damaged storage. Replicate communication protocols for testing. Arduino as a low-cost logic analyzer and protocol decoder.
Why Arduino Over Professional Tools?
Professional hardware hacking tools (JTAGulator, Bus Pirate, Saleae) cost $50-$500+. An Arduino Uno costs $5. It runs custom firmware you write yourself -- no vendor lock-in, no feature limitations. In a CTF competition or a field assessment, the tool you can program yourself is the tool that adapts to the unknown.

Hardware Hacking Overview
The attack surface of any embedded device starts at its physical interfaces.
Debug Ports
JTAG, SWD, UART, SPI debug interfaces left enabled in production. Give full access to firmware, memory, and CPU control if discovered.
Flash Chips
SPI flash (25-series) and I2C EEPROM chips can be read externally. Firmware extraction reveals hardcoded credentials, encryption keys, and logic.
Bus Sniffing
SPI, I2C, and UART traffic between chips can be passively captured. Data in transit often includes unencrypted commands, passwords, and tokens.
USB Interfaces
USB devices can enumerate as keyboards (HID injection), storage (data exfiltration), or network adapters (MITM). Arduino Leonardo/Pro Micro can emulate any USB device.
Signal Analysis
Radio signals (433 MHz, 315 MHz, NFC), IR remote codes, and proprietary wireless protocols can be captured and replayed with Arduino + appropriate receiver modules.
Voltage Glitching
Brief power supply disruptions can skip security checks, bypass lock bits, or corrupt conditional branches. Arduino can generate precisely-timed glitch pulses.
Legal Notice
Hardware hacking techniques must only be used on devices you own or have explicit written authorization to test. Unauthorized access to electronic devices is a federal crime under the Computer Fraud and Abuse Act (CFAA). All techniques in this core are taught for defensive security, CTF competitions, and authorized penetration testing.

JTAG Protocol and JTAGenum
The most powerful debug interface on embedded devices -- and how to find it with an Arduino.
What Is JTAG?
Joint Test Action Group (IEEE 1149.1). A standard debug interface present on most microprocessors and FPGAs. Provides full read/write access to CPU registers, memory, and flash. Four signals: TDI (data in), TDO (data out), TCK (clock), TMS (mode select), plus optional TRST (reset).
JTAGenum Tool
An Arduino sketch that brute-forces JTAG pin assignments on unknown PCBs. It systematically tries every combination of pins for TDI, TDO, TCK, and TMS, looking for valid JTAG responses. Upload the sketch, connect wires to test points, open Serial Monitor, and wait for results.
// JTAGenum workflow (simplified concept) // 1. Connect Arduino pins to suspected JTAG test points on target PCB // 2. Upload JTAGenum sketch from GitHub // 3. Open Serial Monitor at 115200 baud // 4. Send 's' to start scan // The sketch tries all pin permutations: // Pin 2=TDI, Pin 3=TDO, Pin 4=TCK, Pin 5=TMS -- no response // Pin 2=TDI, Pin 3=TCK, Pin 4=TDO, Pin 5=TMS -- no response // Pin 2=TCK, Pin 3=TDI, Pin 4=TMS, Pin 5=TDO -- FOUND JTAG! // IDCODE: 0x4BA00477 (ARM Cortex-M)
1Visual inspection: Look for groups of 4-5 unpopulated pads or header holes on the target PCB. JTAG headers are often 2x5 or 2x10 pin layouts near the main processor.
2Identify ground: Use a multimeter in continuity mode to find ground pads (connected to the ground plane). This narrows the search by eliminating known pins.
3Run JTAGenum: Connect remaining candidate pins to Arduino digital pins. The scan tests all permutations and reports which combination produces valid JTAG communication.

UART Discovery and Enumeration
Finding hidden TX/RX serial ports on unknown PCBs -- the most common debug interface left enabled.
1Find candidate pins: Look for 3-4 pin headers or test pads labeled TX, RX, GND, VCC. Use a multimeter to identify ground and voltage pins first.
2Identify TX: The transmit pin idles HIGH (3.3V or 5V) and drops LOW during data transmission. Use an oscilloscope or monitor Arduino analog input to spot the active pin during device boot.
3Determine baud rate: Common rates: 9600, 19200, 38400, 57600, 115200. Try each one. Garbled output means wrong baud rate. Arduino can auto-detect by measuring pulse widths of incoming bits.
4Connect and capture: Wire target TX to Arduino RX (via SoftwareSerial). Open Serial Monitor. Boot logs, shell prompts, and debug output often appear -- sometimes with root access.
What You Might Find
Many consumer routers, IoT devices, and embedded systems output a full Linux boot log on UART at startup. Some provide a root shell with no authentication. Others leak WiFi credentials, firmware versions, and internal IP addresses. UART is the single most commonly exploited hardware debug interface because manufacturers rarely disable it.

RS232 Protocol and RS232enum
The industrial serial standard -- different voltage levels, same enumeration approach.
RS232 vs TTL UART
UART uses 0V/3.3V or 0V/5V logic levels. RS232 uses -12V to +12V (inverted logic). Never connect RS232 directly to Arduino -- it will destroy the pin. You need a MAX3232 level shifter chip or a USB-to-RS232 adapter cable between the RS232 port and the Arduino.
Where RS232 Lives
Industrial control systems (SCADA/ICS), medical devices, point-of-sale terminals, older networking equipment, building management systems, and laboratory instruments. RS232 is the most common serial interface in operational technology (OT) environments -- the infrastructure that runs power grids and factories.
// RS232enum: brute-force baud rate and pin assignment // Similar approach to JTAGenum but for serial ports #include <SoftwareSerial.h> int bauds[] = {300, 1200, 2400, 4800, 9600, 19200, 38400, 57600, 115200}; void tryBaud(int rxPin, int txPin, long baud) { SoftwareSerial ss(rxPin, txPin); ss.begin(baud); delay(2000); // Wait for target boot output while (ss.available()) { char c = ss.read(); if (c >= 0x20 && c <= 0x7E) { // Printable ASCII? Serial.print(c); // Readable = correct baud rate } } }
Voltage Warning
RS232 voltages (+/-12V) will permanently damage Arduino pins rated for 0-5V. Always use a MAX3232 breakout board or equivalent level shifter. These boards cost under $2 and convert between RS232 and TTL voltage levels bidirectionally.

Bus Piracy Concepts
Intercepting and injecting data on SPI, I2C, and other communication buses.
Passive Sniffing
Connect Arduino to the bus as a listener. Read SPI MOSI/MISO traffic, I2C SDA/SCL messages, or UART TX data without interfering. Log everything to Serial Monitor or SD card. The target device does not know you are watching.
Active Injection
Send crafted messages onto the bus to impersonate a legitimate device. Write to I2C slave addresses, send SPI commands to flash chips, or inject serial commands. Requires understanding the protocol and timing.
Flash Extraction
SPI flash chips (W25Q series) on target PCBs can be read by connecting an Arduino directly to the chip's MISO, MOSI, SCK, and CS pins. Desolder the chip or use SOIC-8 test clips. Dump the entire firmware for offline analysis.
// I2C bus scanner -- find all devices on the bus #include <Wire.h> void setup() { Wire.begin(); Serial.begin(115200); for (byte addr = 1; addr < 127; addr++) { Wire.beginTransmission(addr); if (Wire.endTransmission() == 0) { Serial.print(F("Device at 0x")); Serial.println(addr, HEX); } } }
Common I2C Addresses
0x3C/0x3D: OLED displays. 0x50-0x57: EEPROM chips (AT24Cxx). 0x68: DS3231 RTC, MPU-6050 IMU. 0x76/0x77: BME280/BMP280 sensors. 0x27: PCF8574 I/O expander (LCD backpacks). Finding unexpected addresses on a target PCB reveals hidden components.

Arduino as Logic Analyzer & Signal Generator
Capture and generate digital signals for protocol analysis and testing.
Logic Analyzer (capture)
// Sample pin states at high speed // and send to PC for analysis byte samples[512]; int idx = 0; // Wait for trigger (rising edge) while (!(PIND & (1<<PD2))); // Capture 512 samples while (idx < 512) { samples[idx++] = PIND; // ~1 MHz sample rate } // Send to PC for decoding for (int i=0; i<512; i++) Serial.println(samples[i],BIN);
Signal Generator (output)
// Generate test signals to // probe target device responses // Square wave at exact frequency // using Timer1 CTC mode TCCR1A = (1<<COM1A0); TCCR1B = (1<<WGM12)|(1<<CS10); OCR1A = 159; // 50 kHz on pin 9 // Bit-bang custom protocol void sendBit(bool b) { PORTD |= (1<<PD4); delayMicroseconds(b?600:200); PORTD &= ~(1<<PD4); delayMicroseconds(b?200:600); }
Limitations
Arduino's 16 MHz clock limits logic analysis to about 1 MHz sample rate (adequate for UART, I2C, slow SPI). For faster signals (USB, Ethernet, high-speed SPI), you need a dedicated logic analyzer. But for most embedded device protocols -- especially during hardware pentests -- 1 MHz is sufficient to decode traffic.
SIGROK Integration
Flash the "OLS" (Open Logic Sniffer) firmware onto an Arduino to turn it into a SIGROK-compatible logic analyzer. SIGROK's PulseView software can then decode captured data as I2C, SPI, UART, 1-Wire, and dozens of other protocols automatically -- with a graphical waveform display.

Building a Hardware Keylogger Detector
Detect inline USB keyloggers that intercept keyboard traffic.
1The threat: Hardware keyloggers are small USB devices inserted between a keyboard and a computer. They record every keystroke to internal memory. Invisible to software antivirus because they operate at the physical layer.
2Detection approach: Monitor USB data lines (D+ and D-) for abnormal signal patterns. A legitimate keyboard has direct USB connection. A keylogger introduces an additional USB hub or device in the path, changing the enumeration sequence.
3Arduino role: Use an Arduino with USB Host Shield to enumerate all USB devices and compare against a known-good baseline. Alert (LED, buzzer, Serial message) if an unexpected device descriptor or hub appears in the chain.
4Physical inspection: Combine electronic detection with visual checks. Measure cable length (keyloggers add length). Check for unexpected weight. Compare USB connector color and branding against manufacturer specs.
Deployment
Place the detector Arduino behind locked workstations in secure environments (SOC, SCIF, executive offices). It continuously monitors the USB bus and triggers an alert if the device topology changes -- indicating someone has inserted or removed a device. Log events with timestamps to SD card for forensic review.

Building a USB Device Identifier
Identify unknown USB devices by their descriptor data before connecting them to a real computer.
The Problem
A found USB drive could be a legitimate storage device, a rubber ducky (HID injection attack), a USB killer (voltage surge device), or a data exfiltration implant. Plugging an unknown USB device into your workstation is a security risk. You need a safe way to identify it first.
The Solution
Arduino Mega + USB Host Shield acts as a standalone USB analyzer. When you plug a device in, the Arduino reads the USB descriptor (VID, PID, device class, manufacturer string, product string) and displays it on an OLED or Serial Monitor. No PC involved -- no risk of execution.
// USB descriptor fields to examine: // VID:PID -- Vendor ID : Product ID (unique per manufacturer) // bDeviceClass -- 0x00=composite, 0x03=HID, 0x08=storage // bInterfaceClass -- 0x03=HID (keyboard/mouse), 0x08=mass storage // iManufacturer -- "Kingston", "SanDisk", etc. // iProduct -- "DataTraveler 3.0", etc. // RED FLAGS: // - Device claims to be HID (keyboard) but looks like a flash drive // - VID:PID matches known attack tools (Hak5 Rubber Ducky, etc.) // - Device enumerates as multiple device classes simultaneously // - Manufacturer string is blank or generic
Known Bad VID:PID Database
Maintain a list of VID:PID values associated with attack tools. Hak5 Rubber Ducky: 0x05AC:0x0001 (spoofs Apple keyboard). O.MG Cable: various spoofed VIDs. BadUSB devices: often use 0x1B4F (SparkFun) or 0x2341 (Arduino) VIDs. Compare every plugged device against this database and flag matches.

Arduino in CTF Competitions
Capture The Flag events increasingly include hardware challenges that require physical tools.
UART Challenges
Connect to a hidden serial port on the CTF hardware. Extract boot logs, find shell access, or read flag strings transmitted during startup.
EEPROM Dumps
Read I2C EEPROM chips on the target board. Flags are often stored in specific memory addresses. Arduino + Wire library reads the entire chip in seconds.
Signal Decoding
Capture IR, RF, or serial signals and decode the data. Flags encoded in Manchester encoding, Morse code, or custom bit patterns require logic analysis.
Side-Channel
Measure power consumption or timing variations to extract secrets. Arduino's ADC can sample current draw during cryptographic operations to find key bits.
Firmware RE
Dump SPI flash containing the CTF firmware. Analyze in Ghidra/IDA to find hidden commands, backdoor passwords, or flag storage locations.
Replay Attacks
Capture a valid authentication signal and replay it. Arduino records the bitstream, then transmits it back to unlock the target. Common with IR and RF challenges.
CTF Hardware Toolkit
Arduino Uno/Nano, USB Host Shield, logic level shifter (3.3V/5V), jumper wires, multimeter, SOIC-8 test clip, MAX3232 breakout, breadboard. Total cost: under $30. This kit covers 90% of hardware CTF challenges. The remaining 10% require an oscilloscope or SDR.

Defensive Applications: Tamper Detection
Use Arduino for physical security monitoring and tamper-evident systems.
Tamper Detection System
Reed switches on server rack doors. Vibration sensors on cable conduits. Light sensors inside sealed enclosures (light = opened). Arduino monitors all sensors, logs events to EEPROM with timestamps, and sends alerts via serial or network module when tamper is detected.
Physical Security Monitor
PIR motion sensors for after-hours monitoring. Magnetic door contacts for entry logging. Pressure mats under server room tiles. Trip wires across restricted areas. All feeding into an Arduino data logger that creates a forensic audit trail independent of the network.
