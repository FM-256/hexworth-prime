millis() vs delay()
delay() blocks. millis() liberates. Understanding the difference is the single biggest upgrade in your Arduino programming.
Blocking (Bad for Complex Projects)
void loop() { digitalWrite(13, HIGH); delay(1000); // CPU frozen 1 sec digitalWrite(13, LOW); delay(1000); // CPU frozen 1 sec }
Non-Blocking (Professional)
unsigned long prev = 0; void loop() { if (millis() - prev >= 1000) { prev = millis(); toggleLED(); // instant, no freeze } checkSensors(); // runs every loop }
Key Insight
millis() returns the number of milliseconds since the Arduino powered on. It is an unsigned long (32 bits), which overflows after approximately 49.7 days. The non-blocking pattern stores the previous timestamp and checks whether enough time has elapsed on every pass through loop(). The CPU stays free to do other work between checks.
Slide 3 of 12
Non-Blocking Timing Pattern
The fundamental pattern that replaces every delay() in professional Arduino code.
unsigned long previousMillis = 0; const long interval = 1000; // 1 second void loop() { unsigned long currentMillis = millis(); if (currentMillis - previousMillis >= interval) { previousMillis = currentMillis; // reset the timer // --- Your periodic action goes here --- digitalWrite(LED_BUILTIN, !digitalRead(LED_BUILTIN)); } // Other code runs freely here every loop iteration readButton(); updateDisplay(); }
Overflow Safety
The subtraction currentMillis - previousMillis handles the 49.7-day overflow correctly because unsigned arithmetic wraps around. You never need to reset millis(). The pattern works indefinitely.
Slide 4 of 12
Measuring Pulse Duration
pulseIn() waits for a pin to change state and measures how long it stays there.
// HC-SR04 ultrasonic distance sensor digitalWrite(trigPin, HIGH); delayMicroseconds(10); digitalWrite(trigPin, LOW); long duration = pulseIn(echoPin, HIGH); // microseconds float distanceCm = duration * 0.034 / 2; // speed of sound / 2 (round trip)
pulseIn(pin, HIGH)
Waits for the pin to go HIGH, starts a timer, then stops when the pin goes LOW. Returns the duration in microseconds. Has a default timeout of 1 second. If no pulse arrives, returns 0.
pulseIn(pin, LOW)
Same concept but measures the LOW portion. Waits for LOW, times it until it goes HIGH. Useful for measuring PWM duty cycles or decoding signals where the LOW duration carries the information.
Warning
pulseIn() is a blocking function -- it halts execution while waiting for and measuring the pulse. For time-critical applications, consider using interrupts with micros() to measure pulse durations without blocking.
Slide 5 of 12
Periodic Callbacks Without delay()
Run multiple tasks at different intervals -- the foundation of real-time Arduino systems.
unsigned long ledTimer = 0; unsigned long sensorTimer = 0; unsigned long serialTimer = 0; void loop() { unsigned long now = millis(); if (now - ledTimer >= 500) { // blink every 500ms ledTimer = now; toggleLED(); } if (now - sensorTimer >= 2000) { // read sensor every 2s sensorTimer = now; readTemperature(); } if (now - serialTimer >= 5000) { // report every 5s serialTimer = now; printReport(); } }
Task 1: LED
Blinks every 500ms. The LED toggle takes microseconds, then control immediately returns to loop() so other tasks can run.
Task 2: Sensor
Reads temperature every 2 seconds. The sensor reading is independent of LED timing. Both run without interfering with each other.
Task 3: Report
Prints a Serial report every 5 seconds. A third independent timer. All three tasks coexist peacefully in a single loop().
Pattern Name
This is called "cooperative multitasking." Each task cooperates by checking its timer and returning quickly. No task hogs the CPU. This is how professional embedded systems handle multiple concurrent operations on a single-threaded processor.
Slide 6 of 12
Arduino as a Clock
millis() counts time since power-on, but it does not know what day or year it is. Understanding its limits.
What millis() Can Do
Measure elapsed time. Schedule periodic tasks. Create timeouts and debounce windows. Time events relative to power-on. Works perfectly for short and medium-duration projects.
What millis() Cannot Do
Tell you the current date or time of day. Survive a power cycle (resets to 0). Maintain accuracy over weeks (crystal drift ~50ppm = 4.3 seconds/day). Track real-world time.
Crystal Accuracy
The Arduino Uno uses a 16 MHz ceramic resonator, not a crystal oscillator. Resonators drift roughly 0.5% -- that is 7 minutes per day. For projects that need real-world time (data logging, alarms, scheduling), you need an external Real-Time Clock module with its own crystal and battery backup.
Slide 7 of 12
RTC Modules: DS1307 & DS3231
External Real-Time Clock chips that keep time even when the Arduino is powered off.
DS1307 -- Budget
Uses an external 32.768 kHz crystal. Drifts up to 2 seconds per day depending on temperature. No temperature compensation. Good for hobby projects where a few minutes of drift per month is acceptable. Very cheap (~$1).
DS3231 -- Precision
Built-in temperature-compensated crystal oscillator (TCXO). Drifts only 2 ppm -- roughly 1 minute per year. Has a built-in temperature sensor and two alarm registers. The professional choice for data logging, scheduling, and anything time-critical.
Both Share
I2C interface at address 0x68. CR2032 coin cell battery backup (keeps time for years without main power). BCD-encoded time registers for year, month, day, day-of-week, hours, minutes, seconds. Both work with the RTClib library.
Slide 8 of 12
Alarm Scheduling
The DS3231 has two hardware alarm registers that can trigger an interrupt pin -- wake-up without polling.
// Set Alarm 1 to fire at 07:30:00 every day rtc.setAlarm1(DateTime(0, 0, 0, 7, 30, 0), DS3231_A1_Hour); rtc.writeSqwPinMode(DS3231_OFF); // enable interrupt mode // In your ISR or poll the alarm flag: if (rtc.alarmFired(1)) { rtc.clearAlarm(1); triggerMorningRoutine(); // water plants, turn on lights, etc. }
Power Saving
The SQW/INT pin can be connected to an Arduino interrupt pin (D2 or D3). Combined with sleep modes, the Arduino can go into deep sleep and wake up only when the alarm fires. This enables battery-powered projects that run for months on a single charge -- the Arduino draws microamps while sleeping, and the DS3231 draws only 3 microamps with its backup battery.
Slide 9 of 12
Time Libraries
Arduino libraries that make working with dates, times, and RTC modules straightforward.
RTClib
Adafruit's library. Works with DS1307 and DS3231. DateTime class with year, month, day, hour, minute, second. rtc.now() returns current time.
TimeLib
Software-only time tracking. Uses now(), hour(), minute(). Can sync to an RTC or GPS as a time source. Unix epoch based.
DS3232RTC
Specialized DS3231 library with full alarm support, temperature reading, and EEPROM access. More features than RTClib for DS3231-specific projects.
DateTime Class
DateTime now = rtc.now(); gives you now.year(), now.month(), now.day(), now.hour(), now.minute(), now.second().
Unix Timestamp
now.unixtime() returns seconds since 1970-01-01. Ideal for time math -- add 3600 for one hour, 86400 for one day. One number, no date parsing.
Setting the Clock
rtc.adjust(DateTime(F(__DATE__), F(__TIME__))) sets the RTC to the compile time. Run once, then remove the line or it resets every upload.
Install
In Arduino IDE: Sketch -> Include Library -> Manage Libraries. Search "RTClib" by Adafruit. Install. Then #include "RTClib.h" at the top of your sketch. Create an RTC object: RTC_DS3231 rtc; and call rtc.begin() in setup().

micros() & High-Resolution Timing
When milliseconds are not precise enough -- microsecond timing for fast signals and precise control.
Timing a Function (Profiling)
unsigned long start = micros(); readAccelerometer(); unsigned long elapsed = micros() - start; Serial.print("Read took: "); Serial.print(elapsed); Serial.println(" us");
Non-Blocking Microsecond Timer
unsigned long prevUs = 0; const long intervalUs = 500; // 500us void loop() { if (micros() - prevUs >= intervalUs) { prevUs += intervalUs; togglePin(); // 1kHz signal } }
Overflow Warning
micros() overflows after approximately 71.6 minutes (2^32 microseconds). The same unsigned subtraction pattern handles this correctly, but be aware that micros() is not suitable for timing events longer than about an hour. For long durations, use millis(). For short, precise measurements, use micros().
Slide 11 of 12
Hardware Timer Interrupts
When cooperative multitasking is not precise enough -- hardware timers fire ISRs at exact intervals.
// Timer1 CTC interrupt at exactly 1 Hz (1 second) void setup() { cli(); // disable interrupts TCCR1A = 0; TCCR1B = 0; // clear timer registers TCNT1 = 0; // reset counter OCR1A = 15624; // compare value: 16MHz / 1024 / 1Hz - 1 TCCR1B |= (1 << WGM12); // CTC mode TCCR1B |= (1 << CS12) | (1 << CS10); // prescaler 1024 TIMSK1 |= (1 << OCIE1A); // enable compare interrupt sei(); // enable interrupts } ISR(TIMER1_COMPA_vect) { // fires exactly every 1 second toggleLED(); // runs in interrupt context }
When to Use
Timer interrupts are for hard real-time tasks: generating precise frequencies, sampling ADC at exact rates, driving stepper motors at constant speed. For most projects, millis()-based cooperative timing is simpler and sufficient. Use hardware timers only when precision matters more than simplicity.

Key Takeaways: Timing Mastered
Time is the foundation of every embedded system. Master these concepts and every project improves.
1millis() replaces delay() for responsive code. Store the previous timestamp, check elapsed time each loop, execute when the interval passes. The CPU stays free for other tasks between checks. This pattern is the single most important upgrade from beginner to intermediate Arduino programming.
2Multiple timers run independent tasks. Each task gets its own previousMillis variable and interval. They coexist in the same loop() without interfering. This is cooperative multitasking on a single-threaded processor.
3micros() for microsecond precision. 4-microsecond resolution, overflows after ~71.6 minutes. Use for profiling function execution time, generating precise signals, or measuring fast pulses with pulseIn().
4RTC modules keep real-world time. DS3231 is the gold standard -- temperature-compensated, battery-backed, drifts only 1 minute per year. Communicates over I2C. Use RTClib for easy access to DateTime objects.
5Hardware timer interrupts for hard real-time. Timer1 CTC mode fires an ISR at mathematically exact intervals. Use for precise frequency generation, constant-rate sampling, and stepper motor control. Keep ISRs short and avoid Serial inside them.
