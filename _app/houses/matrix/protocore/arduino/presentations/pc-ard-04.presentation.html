What is Serial?
UART: Universal Asynchronous Receiver-Transmitter. Two wires, one bit at a time.
How UART Works
Serial sends data one bit at a time over a single wire. TX (transmit) sends data out; RX (receive) brings data in. There is no shared clock signal -- both devices must agree on the same baud rate beforehand. Each byte is framed: a start bit signals "data coming," then 8 data bits, then a stop bit. At 9600 baud, each bit lasts about 104 microseconds.
Why 9600?
9600 baud is the Arduino default because it is slow enough to be reliable over the USB-to-serial converter, yet fast enough for most debugging and sensor data. Higher rates (115200) are common for data-intensive projects. The critical rule: both ends must match. If the Arduino sends at 9600 but the Serial Monitor is set to 115200, you get garbled characters.
Key Concept
On the Arduino Uno, pins 0 (RX) and 1 (TX) are wired to the USB-to-serial chip (ATmega16U2). When you use Serial, data flows through these pins to USB to your computer. This means pins 0 and 1 are occupied during serial communication -- do not connect sensors or LEDs to them while using Serial.
Slide 3 of 12
Serial.begin() & Serial.print()
Open the channel, send your first message, see it appear on your screen.
Setup + Print
void setup() { Serial.begin(9600); // open at 9600 baud Serial.println("Boot complete"); } void loop() { Serial.print("Uptime: "); Serial.println(millis()); delay(1000); }
Serial Monitor Output
Boot complete Uptime: 1002 Uptime: 2004 Uptime: 3006 Uptime: 4008 ... (every second)
Serial.begin(baud)
Call once in setup(). Initializes the UART hardware. Common baud rates: 9600, 19200, 38400, 57600, 115200. Must match the Serial Monitor setting exactly.
print() vs println()
print() sends text with no newline -- next output continues on the same line. println() appends a carriage return + line feed, moving to the next line. Use print for inline labels, println for complete messages.
Formatting
You can print strings, integers, floats, and variables. Serial.println(42) prints the number. Serial.println(3.14, 4) prints with 4 decimal places. Chain print calls for complex output.
Common Mistake
Forgetting Serial.begin() in setup and calling Serial.print() in loop -- nothing appears. The UART hardware was never initialized. Always begin before you print.
Slide 4 of 12
Formatted Output
Numbers in decimal, hexadecimal, binary. Tab-separated columns. CSV for spreadsheets.
int val = 255; Serial.println(val, DEC); // 255 Serial.println(val, HEX); // FF Serial.println(val, BIN); // 11111111 Serial.println(val, OCT); // 377
Tab-Separated Columns
Use Serial.print('\t') to insert a tab character between values. This creates aligned columns in the Serial Monitor, making it easy to read sensor data with multiple fields: "Temp\tHumidity\tPressure".
CSV Format
Print values separated by commas: Serial.print(sensorA); Serial.print(","); Serial.println(sensorB);. Copy from Serial Monitor, paste into a .csv file, open in Excel or Google Sheets. Instant data analysis.
Tab-Separated
Serial.print("Temp"); Serial.print('\t'); Serial.print("Humidity"); Serial.print('\t'); Serial.println("Light"); // Output: Temp Humidity Light
CSV Output
Serial.print(millis()); Serial.print(","); Serial.print(temp); Serial.print(","); Serial.println(humidity); // Output: 15230,23.5,45.2
Pro Tip
Use Serial.println(analogRead(A0), BIN) to visualize the raw 10-bit ADC value as binary. Watching the bits flip in real time builds intuition for how analog-to-digital conversion works.
Slide 5 of 12
Receiving Data
The Arduino can listen, not just talk. Read bytes from the Serial Monitor or another device.
void loop() { if (Serial.available() > 0) { char c = Serial.read(); // read one byte Serial.print("Received: "); Serial.println(c); } }
Serial.available()
Returns the number of bytes waiting in the receive buffer (64 bytes on the Uno). Always check this before reading -- calling read() on an empty buffer returns -1 and creates bugs.
Serial.read()
Reads one byte from the buffer and removes it. Returns the byte as an int (0-255), or -1 if nothing is available. To get a character, cast it: char c = Serial.read();
Serial.parseInt()
Reads characters from serial and converts them to an integer. Blocks until a non-digit character is received or timeout (1 second default). Useful for receiving numeric commands: type "255" in Serial Monitor, get the int 255.
// Building a receive buffer for full messages char buffer[64]; int idx = 0; void loop() { while (Serial.available()) { char c = Serial.read(); if (c == '\n') { buffer[idx] = '\0'; // null-terminate processMessage(buffer); idx = 0; } else if (idx < 63) { buffer[idx++] = c; } } }
Buffer Overflow Warning
The Uno's serial buffer holds only 64 bytes. If data arrives faster than your code reads it, bytes are dropped silently. Always process incoming data promptly inside loop() -- never use long delay() calls when expecting serial input.

Parsing Messages
Split comma-separated fields. Extract commands and values from structured messages.
You send "LED,13,ON" from the Serial Monitor. The Arduino must split that into command="LED", pin=13, state="ON" and act on it.
// Parse "LED,13,ON" into command, pin, state void processMessage(char* msg) { char* cmd = strtok(msg, ","); // "LED" char* pinStr = strtok(NULL, ","); // "13" char* state = strtok(NULL, ","); // "ON" if (cmd && pinStr && state) { int pin = atoi(pinStr); if (strcmp(state, "ON") == 0) { digitalWrite(pin, HIGH); } else { digitalWrite(pin, LOW); } } }
strtok() -- The C Tokenizer
strtok(string, delimiter) splits a string at each delimiter. First call takes the string. Subsequent calls use NULL to continue where the last call left off. It modifies the original string by inserting null terminators at each delimiter position. Simple but effective for embedded parsing.
Protocol Design
Define a simple message format: COMMAND,PARAM1,PARAM2\n. Use commas as field separators and newline as the message terminator. Set the Serial Monitor to "Newline" line ending. This gives you a clean, parseable command protocol with zero libraries.
Alternative Approach
For simpler protocols, use single-character commands: 'H' for HIGH, 'L' for LOW, '1'-'9' for brightness levels. char c = Serial.read(); if (c == 'H') digitalWrite(13, HIGH); -- no parsing needed. Start simple, add complexity only when the project demands it.
Slide 7 of 12
Binary Data
Serial.write() sends raw bytes. Serial.print() sends human-readable ASCII. Know the difference.
Serial.print(65)
Serial.print(65); // Sends two ASCII chars: '6' and '5' // Bytes on wire: 0x36, 0x35 // Monitor shows: 65
Serial.write(65)
Serial.write(65); // Sends one raw byte: 0x41 // Bytes on wire: 0x41 // Monitor shows: A (ASCII 65)
When to Use write()
Communicating with sensors, GPS modules, or other microcontrollers that expect raw binary data. Sending byte arrays, protocol packets, or binary sensor readings. Maximum efficiency -- one byte per value instead of multiple ASCII characters.
When to Use print()
Debugging with the Serial Monitor (humans read text, not raw bytes). Logging data in CSV format. Any time you need human-readable output. Print converts numbers to their text representation before sending.
Sending Multi-Byte Data
Serial.write(buf, len) sends an array of bytes. For a 16-bit integer, split into two bytes: Serial.write(highByte(val)); Serial.write(lowByte(val));. The receiving end reconstructs: val = (high << 8) | low;
Efficiency Comparison
Sending the number 1023 via print() transmits 4 bytes ("1","0","2","3"). Sending via write() transmits 2 bytes (0x03, 0xFF). For high-speed data streams, binary is 2-4x more efficient -- but harder to debug since you cannot read raw bytes in the Serial Monitor.
Slide 8 of 12
Multi-Serial: Multiple Channels
The Mega has 4 hardware serial ports. The Uno can add more with SoftwareSerial.
Arduino Mega -- 4 Hardware Ports
The Mega has Serial (USB), Serial1, Serial2, and Serial3. Each is a dedicated hardware UART with its own buffer and interrupt handler. Use Serial1.begin(9600) exactly like Serial.begin(9600). Full-speed, zero CPU overhead while waiting.
SoftwareSerial -- Extra Ports for Uno
The Uno has only one hardware serial port. SoftwareSerial creates additional ports on any digital pins using bit-banging. Include the library, create an instance: SoftwareSerial mySerial(2, 3); (RX=2, TX=3). Limitations: one SoftwareSerial port can listen at a time, max ~57600 baud.
// SoftwareSerial example -- GPS on pins 2/3, debug on USB #include <SoftwareSerial.h> SoftwareSerial gps(2, 3); // RX, TX void setup() { Serial.begin(9600); // USB to PC gps.begin(9600); // GPS module } void loop() { if (gps.available()) { Serial.write(gps.read()); // relay GPS to PC } }
Slide 9 of 12
Data Logging
Send timestamped sensor data to your PC. Build CSV files. Visualize with Processing or a spreadsheet.
// Timestamped CSV data logger void setup() { Serial.begin(115200); Serial.println("timestamp_ms,temp_c,humidity_pct"); // CSV header } void loop() { float temp = readTemp(); float hum = readHumidity(); Serial.print(millis()); Serial.print(","); Serial.print(temp, 1); Serial.print(","); Serial.println(hum, 1); delay(2000); }
millis() as Timestamp
The millis() function returns milliseconds since the Arduino booted. It is your free, always-available timestamp. Overflows after ~49 days. For real-world timestamps, add an RTC (Real Time Clock) module.
Capturing on the PC
Use the Arduino IDE's Serial Monitor to copy/paste data. For automated capture, use CoolTerm, PuTTY, or a Python script with pyserial that writes directly to a .csv file. Processing can read serial and plot graphs in real time.
Processing Integration
Processing (the Java-based creative coding tool) has built-in serial support. Read Arduino data, plot live charts, build dashboards. The Arduino and Processing teams designed them to work together from day one.
High-Speed Logging
For fast sampling (100+ readings/sec), use 115200 baud, minimize print() calls per line, and avoid delay(). Use millis()-based timing to hit exact intervals without blocking. The bottleneck is usually the serial transmission speed, not the ADC.

Arduino to Raspberry Pi
Serial bridge: the Arduino reads sensors, the Pi processes data and connects to the internet.
Arduino Side (C++)
void setup() { Serial.begin(9600); } void loop() { int val = analogRead(A0); Serial.println(val); delay(1000); }
Pi Side (Python)
import serial ser = serial.Serial('/dev/ttyACM0', 9600) while True: line = ser.readline().decode().strip() print(f"Sensor: {line}") # Save to file, database, or API
Why This Pattern Matters
The Arduino excels at real-time I/O (microsecond-level pin control) but lacks WiFi, databases, and processing power. The Pi excels at networking, data processing, and running full applications but has poor real-time GPIO. Together they combine strengths: the Arduino handles the physical world, the Pi handles the digital world.

Debugging with Serial
Serial is your debugger. No breakpoints, no step-through -- just strategic print statements.
Print Variable State
Sprinkle Serial.print("var="); Serial.println(var); throughout your code. Track exactly what the Arduino sees at each step. Name your prints so you know which line produced the output.
Checkpoint Messages
Add Serial.println("reached setup"); at key points. If a checkpoint never prints, the code crashed or hung before that line. Binary search: move the checkpoint to narrow down where the hang occurs.
Common Pitfall: Baud Mismatch
Code says Serial.begin(9600) but the Serial Monitor dropdown is set to 115200. Result: garbled characters or nothing at all. Always verify both ends match. This is the number one serial debugging mistake beginners make.
Buffer Overflow
Printing too much too fast in a tight loop fills the 64-byte TX buffer. Serial.print() blocks until buffer space opens. This slows your loop and can cause timing-sensitive code to fail. Print only what you need, or use a flag to print every Nth iteration.
Timing Side Effects
Serial.print() takes time. A single println() at 9600 baud takes ~1ms per character. Printing 50 characters takes 50ms -- that changes your loop timing. Be aware that debug prints can mask or create timing bugs.
Remove Before Deploy
Once debugging is done, remove or comment out serial prints. They waste flash memory (string literals), consume RAM, and slow execution. Use #define DEBUG and #ifdef DEBUG to toggle debug output with one flag.
// Conditional debug macro -- toggle with one line #define DEBUG 1 #if DEBUG #define DBG(x) Serial.println(x) #else #define DBG(x) #endif void loop() { int val = analogRead(A0); DBG(val); // prints when DEBUG=1, compiled out when DEBUG=0 }

Key Takeaways
Serial communication is the foundation of Arduino debugging, data logging, and device-to-device communication.
1Serial is UART. Two wires (TX/RX), one bit at a time, no clock. Both sides must agree on the baud rate. 9600 is the default, 115200 is common for fast data. On the Uno, pins 0 and 1 are the hardware serial pins -- the USB chip bridges them to your computer.
2Serial.begin() then Serial.print(). Initialize in setup, print in loop. print() stays on the same line, println() adds a newline. Format numbers with DEC, HEX, BIN. Build CSV output by printing commas between values.
3Receiving data requires checking first. Always call Serial.available() before Serial.read(). Build a buffer for full messages. Use strtok() to parse comma-separated fields. The 64-byte buffer overflows silently if you do not read fast enough.
4write() sends raw bytes; print() sends ASCII text. Use write for efficiency and binary protocols. Use print for human-readable debugging. Sending 1023 as binary takes 2 bytes; as text it takes 4.
5Serial is your debugger. No breakpoints on Arduino -- you debug with print statements. Watch for baud mismatch (garbled output), buffer overflow (lost data), and timing side effects (prints slow your loop). Use #ifdef DEBUG to toggle debug output cleanly.
