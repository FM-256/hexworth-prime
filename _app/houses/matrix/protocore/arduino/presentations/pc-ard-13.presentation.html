Bus Protocols: I2C & SPI
Wire Library  |  Addressing  |  SPI.transfer()  |  Multi-Device Buses
A single Arduino has limited pins, but the world has thousands of sensors, displays, and memory chips. Bus protocols let you connect dozens of devices using just 2-4 wires. I2C and SPI are the two dominant bus standards in embedded systems -- master them and you can talk to virtually any peripheral ever made.

I2C Concept: Master/Slave, SDA/SCL
Inter-Integrated Circuit -- two wires to connect up to 127 devices.
SDA (Data)
Bidirectional data line. Both master and slaves send data on this wire. Only one device talks at a time -- the master controls who speaks and when.
SCL (Clock)
Clock signal generated by the master. Every data bit is clocked in on an SCL pulse. Standard mode: 100 kHz. Fast mode: 400 kHz. The master always drives the clock.
7-Bit Address
Each slave has a unique address (0x00-0x7F). The master sends the address first; only the matching slave responds. Up to 127 devices on one bus (minus reserved addresses).
Pull-Up Resistors Required
I2C is an open-drain bus. Both SDA and SCL need pull-up resistors (typically 4.7k ohm) to VCC. Many breakout boards include pull-ups on-board. If you are connecting bare chips, you must add your own. Without pull-ups, the bus stays LOW and nothing works.
Slide 3 of 12
The Wire Library
Arduino's built-in I2C library. No install needed -- just #include Wire.h.
// Reading temperature from a sensor at address 0x48 #include <Wire.h> void setup() { Wire.begin(); // join I2C bus as master Serial.begin(9600); } void loop() { Wire.requestFrom(0x48, 2); // request 2 bytes from slave 0x48 if (Wire.available() >= 2) { byte msb = Wire.read(); // high byte byte lsb = Wire.read(); // low byte int raw = (msb << 8) | lsb; float tempC = raw / 256.0; Serial.println(tempC); } delay(1000); }
1Wire.begin() -- Initialize the I2C hardware as master. No address parameter means master mode. Call once in setup().
2Wire.beginTransmission(addr) -- Start a write transaction to a slave. Queues the address byte.
3Wire.write(data) -- Queue one or more bytes to send. Does not transmit yet.
4Wire.endTransmission() -- Actually sends all queued bytes. Returns 0 on success, non-zero on error.
5Wire.requestFrom(addr, count) -- Ask a slave for count bytes. Slave responds immediately.
6Wire.read() -- Read one byte from the receive buffer. Call after requestFrom().
Slide 4 of 12
Scanning for I2C Devices
The I2C scanner -- the first sketch you run when connecting any new I2C device.
// I2C Scanner -- finds all devices on the bus #include <Wire.h> void setup() { Wire.begin(); Serial.begin(9600); Serial.println("I2C Scanner starting..."); for (byte addr = 1; addr < 127; addr++) { Wire.beginTransmission(addr); byte error = Wire.endTransmission(); if (error == 0) { Serial.print("Device found at 0x"); if (addr < 16) Serial.print("0"); Serial.println(addr, HEX); } } Serial.println("Scan complete."); }
How It Works
For each possible address (1-126), the scanner sends a start condition followed by the address. If a device at that address responds with an ACK (acknowledge), endTransmission() returns 0 and the device is found. If no device responds, it returns a non-zero error code. The scan takes less than a second.
Common Addresses
0x3C/0x3D: OLED displays. 0x48-0x4F: TMP102/LM75 temp sensors. 0x68: DS3231 RTC, MPU-6050. 0x76/0x77: BME280/BMP280 pressure sensors. 0x27: PCF8574 I/O expander. 0x50: AT24C32 EEPROM. Always verify with a scan first.
Pro Tip
Keep the I2C scanner sketch saved in your library. Every time you wire up a new I2C device, run the scanner first to confirm the device is detected and to verify its address. Many devices have configurable address pins (A0, A1, A2) that let you change the address to avoid conflicts.
Slide 5 of 12
Multiple I2C Devices
One bus, many devices. Each addressed independently -- no extra wires needed.
// Read RTC (0x68) + display on OLED (0x3C) + read temp (0x48) #include <Wire.h> #include "RTClib.h" #include <Adafruit_SSD1306.h> RTC_DS3231 rtc; Adafruit_SSD1306 display(128, 64, &Wire); void setup() { Wire.begin(); // one begin() for all devices rtc.begin(); // talks to 0x68 display.begin(SSD1306_SWITCHCAPVCC, 0x3C); // talks to 0x3C }
Shared Bus
All devices connect to the same A4 (SDA) and A5 (SCL) pins. Only 2 wires for the entire bus, plus VCC and GND. Each library internally calls Wire functions with the correct address.
Address Conflicts
If two devices share the same address, you need a TCA9548A I2C multiplexer. This chip creates 8 separate I2C channels. Select the channel before talking to each device. Costs about $2.
Bus Capacitance
Each device adds capacitance to the bus. Practical limit is about 8-10 devices on short wires. For longer cables (over 1m), reduce bus speed to 100 kHz or use an I2C bus extender chip.
Wiring Rule
Every I2C device on the bus connects its SDA to Arduino A4, its SCL to Arduino A5, its VCC to 5V (or 3.3V if the device requires it -- use a level shifter for mixed voltages), and GND to GND. Only one set of pull-up resistors is needed for the entire bus. Multiple pull-ups from different breakout boards add up -- if you have issues, remove extras.

SPI Concept: MOSI/MISO/CLK/CS
Serial Peripheral Interface -- 4 wires, full-duplex, and much faster than I2C.
SPI Advantages
Much faster than I2C (up to 8 MHz on Uno). Full-duplex -- send and receive in the same clock cycle. No addressing overhead. No pull-up resistors needed. Simple protocol -- just shift bytes in and out.
SPI Disadvantages
Needs 4 wires + 1 extra CS pin per slave device. No built-in acknowledgment -- you cannot tell if a slave is present. Short-range only. More wiring complexity for multiple devices.
Slide 7 of 12
SPI.transfer()
The core SPI function: send a byte, receive a byte -- simultaneously, in one call.
#include <SPI.h> const int csPin = 10; void setup() { pinMode(csPin, OUTPUT); digitalWrite(csPin, HIGH); // deselect slave SPI.begin(); // init SPI hardware Serial.begin(9600); } void loop() { digitalWrite(csPin, LOW); // select slave (active LOW) byte response = SPI.transfer(0x42); // send 0x42, get response digitalWrite(csPin, HIGH); // deselect slave Serial.print("Received: 0x"); Serial.println(response, HEX); delay(1000); }
1SPI.begin() -- Initializes SPI hardware. Sets SCK (pin 13), MOSI (pin 11) as output, MISO (pin 12) as input.
2digitalWrite(CS, LOW) -- Pull the chip select pin LOW to activate the slave. The slave ignores all bus traffic until CS goes LOW.
3SPI.transfer(data) -- Simultaneously sends data out on MOSI and receives data in on MISO. Returns the received byte. One clock cycle per bit, 8 bits total.
4digitalWrite(CS, HIGH) -- Deselect the slave. The transaction is complete. Other slaves can now be selected.
SPI Settings
SPI.beginTransaction(SPISettings(1000000, MSBFIRST, SPI_MODE0)) configures clock speed (1 MHz), bit order, and clock polarity/phase. Call before each transaction and SPI.endTransaction() after. Mode 0 (CPOL=0, CPHA=0) is the most common.
Slide 8 of 12
Multiple SPI Devices
MOSI, MISO, and SCK are shared. Each device gets its own CS pin.
// Talk to SD card (CS=10), then ADC (CS=9) digitalWrite(10, LOW); // select SD card SPI.transfer(0x51); // send command to SD digitalWrite(10, HIGH); // deselect SD card digitalWrite(9, LOW); // select ADC byte val = SPI.transfer(0x00); // read from ADC digitalWrite(9, HIGH); // deselect ADC
Pin 10 Warning
On the Arduino Uno, pin 10 is the hardware SS (Slave Select) pin. Even if you use a different pin for your CS, pin 10 must be set as OUTPUT for SPI master mode to work. If pin 10 is set as INPUT and goes LOW, the SPI hardware switches to slave mode and your communication fails.
Slide 9 of 12
I2C Port Expander: PCF8574
Turn 2 I2C wires into 8 extra GPIO pins. Stack up to 8 expanders for 64 extra pins.
// Write to PCF8574 -- set pin P0 HIGH, all others LOW Wire.beginTransmission(0x20); Wire.write(0b00000001); // P0=HIGH, P1-P7=LOW Wire.endTransmission(); // Read from PCF8574 -- check if button on P4 is pressed Wire.requestFrom(0x20, 1); byte pins = Wire.read(); bool buttonPressed = !(pins & 0b00010000); // P4, active LOW
Address Pins
The PCF8574 has 3 address pins (A0, A1, A2) that can be tied HIGH or LOW, giving 8 possible addresses from 0x20 to 0x27. This means you can have 8 chips on one I2C bus for 64 extra I/O pins. The PCF8574A variant uses addresses 0x38-0x3F, giving you up to 16 chips (128 pins) total.
Slide 10 of 12
Inter-Arduino I2C Communication
One Arduino as master, another as slave. Distribute workload across multiple boards.
Master Arduino
#include <Wire.h> void setup() { Wire.begin(); // master (no addr) } void loop() { Wire.beginTransmission(8); Wire.write("Hello"); Wire.endTransmission(); delay(500); }
Slave Arduino (Address 8)
#include <Wire.h> void receiveEvent(int bytes) { while (Wire.available()) { char c = Wire.read(); Serial.print(c); } Serial.println(); } void setup() { Wire.begin(8); // slave addr 8 Wire.onReceive(receiveEvent); Serial.begin(9600); }
Wire.begin(address)
When you pass an address to Wire.begin(), the Arduino joins the I2C bus as a slave at that address. The master can then send data to it or request data from it, just like any other I2C device.
Use Cases
Sensor node networks (one master collects from multiple slave Arduinos). Distributed processing (slave handles motor control while master handles UI). Modular robot systems. I2C is perfect for short-range, low-speed inter-board communication.
Slide 11 of 12
Real-World I2C: Wii Nunchuck
The Nintendo Nunchuck is an I2C slave at address 0x52 -- joystick, buttons, and accelerometer over 2 wires.
// Initialize the Nunchuck (disable encryption) Wire.beginTransmission(0x52); Wire.write(0xF0); Wire.write(0x55); Wire.endTransmission(); Wire.beginTransmission(0x52); Wire.write(0xFB); Wire.write(0x00); Wire.endTransmission(); // Read 6 bytes of sensor data Wire.requestFrom(0x52, 6); byte data[6]; for (int i = 0; i < 6; i++) data[i] = Wire.read(); int joyX = data[0]; // joystick X (0-255) int joyY = data[1]; // joystick Y (0-255) int accelX = (data[2] << 2) | ((data[5] >> 2) & 3); bool btnZ = !(data[5] & 1); // Z button (active LOW) bool btnC = !((data[5] >> 1) & 1); // C button
Joystick
X and Y axes, each 0-255. Center is ~128. Map to motor speed, servo position, or cursor movement. Two bytes of the 6-byte packet.
Accelerometer
3-axis, 10-bit resolution. Detects tilt and motion. Data split across bytes 2-5. Useful for gesture control and orientation sensing.
Buttons
Z and C buttons, active LOW. Packed into bit 0 and bit 1 of byte 5. Two buttons for game-style input at zero extra pin cost.
Why This Matters
The Nunchuck demonstrates I2C's power: a complex multi-sensor device with joystick, accelerometer, and buttons communicates entirely over 2 wires. No analog pins consumed, no digital pins used for buttons. Just SDA, SCL, VCC, and GND. This is why I2C dominates the sensor world.

Key Takeaways: Bus Protocols Mastered
Two protocols, one goal: connect your Arduino to the world of peripherals.
1I2C uses 2 wires (SDA + SCL) for up to 127 devices. Each device has a unique 7-bit address. The master controls the clock. The Wire library handles everything. Pull-up resistors (4.7k) are required. Standard speed is 100 kHz, fast mode is 400 kHz.
2SPI uses 4 wires + 1 CS per device. MOSI, MISO, SCK are shared; each slave gets its own Chip Select pin. Full-duplex, much faster than I2C (up to 8 MHz). No addressing -- selection is done by pulling CS LOW.
3Always run the I2C scanner first. Before writing any I2C code, scan the bus to confirm your device is detected and verify its address. Many debugging hours are saved by this one sketch.
4I2C for sensors, SPI for speed. Use I2C when you have many slow devices (sensors, RTCs, displays, EEPROMs). Use SPI when you need speed (SD cards, TFT displays, high-speed ADCs). Many projects use both buses simultaneously.
5Port expanders multiply your pins. The PCF8574 gives 8 extra GPIO pins over I2C. Stack 8 chips for 64 pins. Inter-Arduino I2C lets you distribute processing across multiple boards.
