What Are Arduino Libraries?
Pre-written code packages that extend Arduino functionality without rewriting common operations from scratch.
Abstraction Layer
A library hides complex register-level operations behind simple function calls. When you write myServo.write(90), the Servo library handles Timer1 configuration, PWM duty cycle calculation, and interrupt management. You get one clean line instead of 30 lines of register manipulation.
How They Work
Libraries are C/C++ source files (.h and .cpp) that get compiled alongside your sketch. The #include directive tells the compiler to pull in the library's header file, which exposes classes and functions. The linker then combines everything into a single binary that gets uploaded to the board.
Key Concept
Arduino ships with dozens of built-in libraries. The community has published over 6,000 more through the Library Manager. Every sensor, display, motor driver, and communication protocol you can think of likely has a library ready to use. The entire Arduino ecosystem is built on the idea that code should be shared, not rewritten.

Built-in Libraries: Servo, Wire, SPI, SD
Libraries that ship with the Arduino IDE -- no installation required.
Servo
Controls RC servo motors. Supports up to 12 servos on most boards. Uses Timer1 for PWM signal generation. Servo.write(angle) positions 0-180 degrees.
Wire (I2C)
Communicates with I2C/TWI devices on SDA (A4) and SCL (A5). Supports master and slave modes. Addresses 0-127. Used by most sensors, displays, and RTCs.
SPI
High-speed synchronous serial on pins 10-13 (SS, MOSI, MISO, SCK). Faster than I2C. Used by SD cards, displays, and radio modules. Full-duplex communication.
SD
Reads and writes files on SD/microSD cards via SPI. FAT16/FAT32 support. Create, open, read, write, and delete files. Data logging workhorse.
EEPROM
Reads and writes the 1KB persistent EEPROM on ATmega328P. Survives power cycles. EEPROM.read(addr) and EEPROM.write(addr, val).
SoftwareSerial
Creates additional serial ports on any digital pins. Useful when hardware UART (pins 0/1) is occupied by USB communication or another device.
Using a Built-in Library
Add #include <Wire.h> at the top of your sketch. The IDE knows where built-in libraries live and links them automatically. No download, no installation, no configuration. They are always available in every sketch.

The Library Manager
The IDE's built-in tool for discovering, installing, and updating community libraries.
1Open Library Manager: In Arduino IDE 2.x, click the book icon in the left sidebar. In IDE 1.x, go to Sketch > Include Library > Manage Libraries.
2Search: Type a library name or keyword (e.g., "NeoPixel", "temperature", "OLED"). Results show library name, author, version, and description.
3Install: Click the Install button next to the library you want. The IDE downloads the ZIP, extracts it to your libraries folder, and makes it available immediately.
4Dependencies: Some libraries depend on others. The Library Manager will prompt you to install dependencies automatically. Always accept.
5Updates: When a new version is available, the Manager shows an Update button. Review changelogs before updating -- breaking changes happen.
Pro Tip
After installing a library, go to File > Examples to find example sketches bundled with it. These examples are the fastest way to learn how a library works. Every well-written library includes at least one working example.

Installing Libraries from ZIP
For libraries not in the Library Manager -- downloaded from websites, forums, or email.
Method 1: IDE Menu
Go to Sketch > Include Library > Add .ZIP Library. Navigate to the downloaded .zip file and select it. The IDE extracts it into your Arduino/libraries/ folder automatically. Restart the IDE if the library does not appear immediately.
Method 2: Manual Extraction
Extract the ZIP yourself and place the folder in ~/Documents/Arduino/libraries/ on Windows/Mac or ~/Arduino/libraries/ on Linux. The folder name must match the library name. Restart the IDE after placing the folder.
// After installing, include the library in your sketch: #include <MyCustomLibrary.h> // The IDE resolves the path automatically: // ~/Documents/Arduino/libraries/MyCustomLibrary/src/MyCustomLibrary.h
Common Pitfall
GitHub downloads often create a folder named LibraryName-main or LibraryName-master. You must rename it to just LibraryName (remove the branch suffix) or the IDE may not recognize it. The folder name must exactly match the library name referenced in the header file.
ZIP Structure Requirement
The ZIP must contain a single top-level folder with the library files inside it. If the ZIP extracts to loose files (no containing folder), the IDE will fail to install it properly. Repackage it with a containing folder before importing.

Libraries from GitHub
The largest source of Arduino libraries outside the Library Manager.
1Find the repo: Search GitHub for "Arduino" + your sensor/module name. Look for repos with recent commits, good documentation, and many stars.
2Download ZIP: Click the green "Code" button, then "Download ZIP". Or use git clone https://github.com/author/LibName.git into your libraries folder.
3Check for Releases: Go to the Releases tab for stable, tagged versions. Downloading from Releases is safer than cloning the latest development branch.
4Read the README: It contains wiring diagrams, API documentation, and example code. A library without a README is a red flag -- find a better one.
Evaluating Quality
Check the star count, last commit date, open issues, and whether the author responds to bug reports. A library with 500 stars and recent activity is likely reliable. A library with 3 stars and no updates in 4 years may have unpatched bugs or incompatibilities with current IDE versions.

Library Folder Structure
Every Arduino library follows a standard directory layout that the IDE expects.
MyLibrary/ src/ MyLibrary.h // Header file -- class declarations, prototypes MyLibrary.cpp // Implementation -- actual function code examples/ BasicUsage/ BasicUsage.ino // Example sketch (folder name must match .ino name) AdvancedDemo/ AdvancedDemo.ino keywords.txt // Syntax highlighting definitions library.properties // Metadata: name, version, author, description README.md // Documentation LICENSE // Open-source license
keywords.txt
Defines syntax highlighting for the IDE. Format: ClassName KEYWORD1 (tab-separated). KEYWORD1 colors class names orange. KEYWORD2 colors methods. LITERAL1 colors constants. This file is optional but professional libraries always include it.
library.properties
Required metadata file. Contains name=, version=, author=, maintainer=, sentence= (short description), paragraph= (long description), category=, url=, and architectures=.
The src/ Folder
Modern libraries place source files in src/. The IDE automatically searches this directory. Older libraries (pre-1.5 format) placed .h and .cpp files directly in the library root. Both formats work, but src/ is the current standard. If your library has subdirectories inside src/, all .h and .cpp files in those subdirectories are compiled automatically.

Modifying Existing Libraries
When a library almost does what you need -- but not quite.
1Fork first: Never edit a library directly in the Arduino libraries folder if it was installed via Library Manager. Updates will overwrite your changes. Copy the library to a new folder with a different name.
2Rename the copy: Change the folder name, the library.properties name field, and the header file name. This prevents conflicts with the original. Example: Servo becomes ServoCustom.
3Read the source: Open the .h file to understand the class structure. Open the .cpp file to see how functions are implemented. Trace the logic before changing anything.
4Make targeted changes: Add a new public method, adjust a constant, change a default value. Keep changes minimal. Test after every change.
5Update the header: If you add a new public method to the .cpp, declare it in the .h file. The compiler reads the .h to know what functions exist.
Original Servo.h (excerpt)
class Servo { public: void write(int angle); int read(); };
Modified ServoCustom.h
class ServoCustom { public: void write(int angle); int read(); void sweep(int from, int to, int step); };
Warning
If you modify a library installed by the Library Manager without copying it first, the next time you update that library through the Manager, all your changes will be destroyed. Always fork to a new name.

Creating Your Own Library
Turn reusable code from your sketches into a proper library that any project can include.
1Identify reusable code: If you are copying the same sensor-reading function between sketches, that code belongs in a library. Libraries eliminate copy-paste duplication.
2Create the folder structure: Make a folder in ~/Arduino/libraries/ with your library name. Inside, create src/, examples/, keywords.txt, and library.properties.
3Write the header (.h): Declare your class, public methods, private variables, and include guards (#ifndef). This is the public API of your library.
4Write the implementation (.cpp): Include your header, then implement every function you declared. Include Arduino.h for access to Arduino functions like digitalWrite().
5Write an example sketch: Create at least one example in examples/BasicUsage/BasicUsage.ino. This proves your library works and teaches others how to use it.
Naming Conventions
Library name: PascalCase (e.g., MotorDriver). Header file: matches library name (MotorDriver.h). Class name: matches library name. Method names: camelCase (setSpeed(), getDirection()). Constants: ALL_CAPS (MAX_SPEED). Following these conventions makes your library feel native to the Arduino ecosystem.
Slide 10 of 12
Header Files (.h) and Implementation (.cpp)
The two-file pattern that every C/C++ library follows.
Blinker.h -- The Header
// Include guard prevents double-inclusion #ifndef BLINKER_H #define BLINKER_H #include <Arduino.h> class Blinker { public: Blinker(int pin); void begin(); void blink(int delayMs); void on(); void off(); private: int _pin; }; #endif
Blinker.cpp -- The Implementation
#include "Blinker.h" Blinker::Blinker(int pin) { _pin = pin; } void Blinker::begin() { pinMode(_pin, OUTPUT); } void Blinker::blink(int delayMs) { on(); delay(delayMs); off(); delay(delayMs); } void Blinker::on() { digitalWrite(_pin, HIGH); } void Blinker::off() { digitalWrite(_pin, LOW); }
Include Guards
#ifndef / #define / #endif prevents the header from being processed twice if multiple files include it. Without guards, the compiler throws "redefinition" errors. Every header file must have include guards. The guard name is conventionally the filename in ALL_CAPS with underscores.
Scope Resolution (::)
In the .cpp file, Blinker::begin() means "the begin() function that belongs to the Blinker class." The :: operator connects a method to its class. Without it, the compiler treats the function as a standalone global function, not a class method.

Library Versioning
How Arduino libraries track versions and why it matters for your projects.
MAJOR (1.x.x)
Breaking changes. API changed in incompatible ways. Functions renamed, removed, or signatures changed. Upgrading may require modifying your sketch code.
MINOR (x.4.x)
New features added. Backwards compatible. Existing code still works. New classes, methods, or capabilities introduced without breaking old API.
PATCH (x.x.2)
Bug fixes only. No new features, no API changes. Safe to update without testing. Fixes crashes, memory leaks, or incorrect behavior.
// library.properties version field name=Blinker version=1.4.2 author=Your Name maintainer=Your Name <email@example.com> sentence=A simple LED blinking library paragraph=Provides non-blocking blink patterns for any digital pin category=Signal Input/Output url=https://github.com/yourname/Blinker architectures=*

Publishing to the Library Manager
Share your library with the global Arduino community.
1Complete your library: Ensure you have library.properties, at least one example, a README, and a LICENSE file. The Library Manager requires all of these.
2Host on GitHub: Push your library to a public GitHub repository. The Library Manager pulls directly from GitHub repos.
3Create a Release: Tag a version in GitHub (e.g., v1.0.0). The Library Manager indexes releases, not raw commits. Go to Releases > Create new release > Tag version.
4Submit a pull request: Open a PR to the arduino/library-registry repo on GitHub. Add a single line with your repo URL to the list. Arduino's CI validates your library automatically.
5Wait for review: Arduino maintainers review the PR. Common rejection reasons: missing library.properties fields, no examples, name conflicts with existing libraries, or non-compliant folder structure.
Checklist Before Publishing
Unique library name (search Library Manager first). Valid library.properties with all required fields. At least one working example sketch. Include guards in all header files. No absolute paths in source code. Compiles cleanly for at least architectures=* (all boards). README with installation instructions and API reference.
