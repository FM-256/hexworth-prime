Arithmetic: The Basics
Addition, subtraction, multiplication, and division -- with one critical gotcha that trips up every beginner.
// Integer arithmetic int a = 10, b = 3; int sum = a + b; // 13 int diff = a - b; // 7 int prod = a * b; // 30 int quot = a / b; // 3 -- NOT 3.333! Integer division truncates. // The fix: use float float result = (float)a / (float)b; // 3.333333 // Real-world: converting analog reading to voltage int raw = analogRead(A0); // 0-1023 float volts = raw * 5.0 / 1023.0; // correct -- 5.0 forces float math int wrong = raw * 5 / 1023; // WRONG -- integer overflow possible
Integer Division Gotcha
When both operands are integers, the result is an integer with the fractional part discarded. 5 / 2 = 2, 1 / 3 = 0. This is not rounding -- it is truncation toward zero. Cast at least one operand to float to get a decimal result.
Overflow Danger
int on AVR holds -32,768 to 32,767. raw * 5 where raw = 1023 gives 5115 -- fine. But raw * 1000 gives 1,023,000 which overflows int silently, wrapping to a garbage value. Use long for large intermediate values.

Increment & Decrement
The ++ and -- operators add or subtract 1. The position (prefix vs postfix) determines when the change takes effect.
Post-increment (i++)
int a = 5; int b = a++; // b = 5 (original value used first) // a = 6 (then incremented) // Most common in for loops: for (int i = 0; i < 10; i++) { // i incremented after each // iteration's body executes }
Pre-increment (++i)
int a = 5; int b = ++a; // a = 6 (incremented first) // b = 6 (new value used) // Decrement works the same: int count = 10; count--; // now 9 --count; // now 8 // Standalone: no difference. // Only matters in expressions.
In practice, the difference rarely matters because most uses are standalone statements (i++; on its own line). But inside expressions like array[i++] = val; vs array[++i] = val;, it determines which index is written. When in doubt, do the increment on a separate line for clarity.

Modulo & Remainder
The % operator gives the remainder after division. It is one of the most useful tools for cycling, wrapping, and periodic behavior.
// Basic modulo int result = 7 % 3; // 1 (7 = 2*3 + 1) int result = 10 % 5; // 0 (evenly divisible) int result = 3 % 7; // 3 (3 < 7, so remainder is 3) // Circular buffer index int readings[10]; int index = 0; void loop() { readings[index] = analogRead(A0); index = (index + 1) % 10; // wraps: 0,1,2...9,0,1,2... } // Run code every Nth iteration static int loopCount = 0; loopCount++; if (loopCount % 100 == 0) { Serial.println("Every 100 loops"); }
Cycling Through Values
Cycle through LED colors: colorIndex = (colorIndex + 1) % NUM_COLORS;. Wraps automatically from the last index back to 0. No if/else needed.
Even/Odd Check
if (n % 2 == 0) tests for even numbers. n % 2 == 1 for odd. Use for alternating behavior, blinking patterns, or split processing.
Integer Only
The % operator works only on integers in C/C++. For float remainder, use fmod(a, b). On Arduino, fmod is available but rarely needed.

abs() & constrain()
Two utility functions that handle the most common sensor data problems: negative values and out-of-range readings.
// abs() -- returns the absolute value int diff = sensorA - sensorB; int magnitude = abs(diff); // always positive // constrain(val, min, max) -- clamps a value to a range int raw = analogRead(A0); int safe = constrain(raw, 100, 900); // If raw = 50, safe = 100 (clamped to min) // If raw = 500, safe = 500 (within range, unchanged) // If raw = 950, safe = 900 (clamped to max) // Real-world: protect a servo from over-rotation int angle = map(raw, 0, 1023, 0, 180); angle = constrain(angle, 10, 170); // mechanical safety limits servo.write(angle);
abs() Warning
Arduino's abs() is a macro. Avoid abs(a++) because the argument gets evaluated twice. Use a temporary variable: int tmp = a++; int val = abs(tmp);.
Clamping Sensor Data
Sensors often produce outlier readings -- spikes, noise, or transients. constrain() after reading prevents those outliers from driving actuators to dangerous positions. Always constrain before writing to servos, motors, or PWM outputs.
Slide 6 of 12
min(), max() & map()
map() is one of the most-used Arduino functions. It scales a value from one range to another -- the bridge between raw sensor data and useful output.
// min() and max() int smaller = min(10, 25); // 10 int larger = max(10, 25); // 25 // map(value, fromLow, fromHigh, toLow, toHigh) int raw = analogRead(A0); // 0-1023 int pwm = map(raw, 0, 1023, 0, 255); // scale to PWM range analogWrite(9, pwm); // map() with inverted range -- sensor reads high when dark int light = map(raw, 0, 1023, 100, 0); // invert: 1023 -> 0% // map() for servo control int potVal = analogRead(A0); int angle = map(potVal, 0, 1023, 0, 180); servo.write(angle); // map() does NOT constrain -- values outside the range extrapolate int oops = map(1100, 0, 1023, 0, 255); // returns ~274, not 255!
map() Parameters
Five arguments: the value, then the source range (fromLow, fromHigh), then the target range (toLow, toHigh). The math: (val - fromLow) * (toHigh - toLow) / (fromHigh - fromLow) + toLow. Integer math only -- no fractional results.
map + constrain Combo
Always pair map() with constrain() when driving outputs: int pwm = constrain(map(raw, 0, 1023, 0, 255), 0, 255);. This prevents extrapolated values from damaging hardware or producing unexpected behavior.
min/max as Macros
Like abs(), min() and max() are macros on Arduino. Avoid side effects in arguments: min(a++, b) will increment a unpredictably. Use temporary variables for safety.
Slide 7 of 12
Powers & Roots
pow() and sqrt() handle exponentiation and square roots -- essential for distance calculations, signal processing, and physics simulations.
// pow(base, exponent) -- returns float float squared = pow(5, 2); // 25.0 float cubed = pow(3, 3); // 27.0 float root = pow(27, 1.0/3); // 3.0 (cube root) // sqrt(x) -- square root float side = sqrt(144); // 12.0 // Euclidean distance between two points float dx = x2 - x1; float dy = y2 - y1; float distance = sqrt(pow(dx, 2) + pow(dy, 2)); // Faster alternative for squaring (avoid pow overhead): float distFast = sqrt(dx * dx + dy * dy);
Performance
pow() and sqrt() are slow on AVR (no hardware FPU). For simple squares, use multiplication: x * x is 10-50x faster than pow(x, 2). Save pow() for fractional exponents and cube roots.
Distance Calculations
Ultrasonic sensors return distance in microseconds. Thermistors use exponential curves. GPS modules provide lat/lon that require Haversine distance with pow() and sqrt(). These functions bridge raw numbers and real-world measurements.

Trigonometry
sin(), cos(), and tan() take arguments in radians. They produce smooth, periodic motion -- essential for servo sweeps, LED fades, and circular patterns.
// Trig functions use RADIANS, not degrees // Convert: radians = degrees * PI / 180 float angle = 45.0 * PI / 180.0; // 0.7854 radians float s = sin(angle); // 0.7071 float c = cos(angle); // 0.7071 // Smooth LED breathing effect void loop() { float t = millis() / 1000.0; // time in seconds float brightness = (sin(t * 2.0 * PI) + 1.0) * 127.5; analogWrite(9, (int)brightness); // smooth 0-255 cycle } // Servo smooth sweep (sinusoidal instead of linear) float pos = 90.0 + 80.0 * sin(millis() / 2000.0); servo.write((int)pos); // sweeps 10-170 smoothly
Radians vs Degrees
Arduino trig functions require radians. Full circle = 2*PI radians = 360 degrees. PI is predefined as 3.14159265. Use radians(deg) and degrees(rad) helper macros for conversion.
sin() for Smooth Motion
sin() oscillates from -1 to +1. Scale and shift it: (sin(t) + 1.0) * 127.5 maps to 0-255 for PWM. The result is a smooth breathing pattern instead of a linear ramp -- more natural and visually pleasing.
Circular Patterns
Plot a circle: x = cx + r * cos(angle), y = cy + r * sin(angle). Useful for OLED display animations, LED ring effects, or robotic arm kinematics where joints move in arcs.
Slide 9 of 12
Random Numbers
random() generates pseudo-random numbers. randomSeed() makes them unpredictable -- and an unconnected analog pin provides the entropy.
// random(max) -- returns 0 to max-1 long r = random(100); // 0 to 99 // random(min, max) -- returns min to max-1 long r = random(10, 50); // 10 to 49 // Without randomSeed, the sequence is the same every power-on! void setup() { // Read floating analog pin for noise-based seed randomSeed(analogRead(A7)); // A7 unconnected = random noise } // Random LED blink timing void loop() { digitalWrite(13, HIGH); delay(random(50, 500)); // random on-time digitalWrite(13, LOW); delay(random(50, 500)); // random off-time }
randomSeed() Is Essential
Without calling randomSeed(), random() produces the exact same sequence every boot. Seed with analogRead() on an unconnected pin -- the floating input picks up electrical noise, giving a different seed each time.
Not Cryptographic
Arduino's random() is a pseudo-random number generator (PRNG) -- fine for games, animations, and randomized delays, but not for security. For cryptographic randomness on ESP32, use esp_random() which reads a hardware RNG.

Bit Operations
Setting, clearing, and reading individual bits. Essential for hardware register manipulation, feature flags, and compact data storage.
// Setting a bit (turn bit ON) byte flags = 0b00000000; flags |= (1 << 3); // Set bit 3: 0b00001000 // Clearing a bit (turn bit OFF) flags &= ~(1 << 3); // Clear bit 3: 0b00000000 // Reading a bit bool isSet = (flags >> 3) & 1; // true if bit 3 is set // Toggling a bit flags ^= (1 << 5); // Flip bit 5 // Bit masks for multiple flags #define FLAG_ARMED (1 << 0) // bit 0 #define FLAG_RUNNING (1 << 1) // bit 1 #define FLAG_ERROR (1 << 2) // bit 2 flags |= FLAG_ARMED | FLAG_RUNNING; // set both if (flags & FLAG_ERROR) { handleError(); }
Why Bits Matter
Hardware registers (PORTB, DDRB, TCCR1A) are controlled bit by bit. Each bit has a specific function -- pin direction, timer prescaler, interrupt enable. Bit operations are the only way to change one setting without affecting others in the same register.
Compact Flag Storage
A single byte holds 8 boolean flags using 1 byte of RAM instead of 8 bytes. On a 2 KB microcontroller, this matters. Name your flags with #define for readability: if (status & FLAG_READY) is cleaner than if ((status >> 4) & 1).
Slide 11 of 12
Byte Manipulation
Arduino provides helper functions for working with individual bits and bytes -- cleaner than raw bitwise operators for common operations.
// Arduino bit/byte helper functions int value = 0xABCD; // 43981 decimal byte hi = highByte(value); // 0xAB (171) byte lo = lowByte(value); // 0xCD (205) // Reconstruct the int from bytes int rebuilt = (hi << 8) | lo; // 0xABCD // Read/write individual bits byte reg = 0b10110100; bool bit3 = bitRead(reg, 3); // 0 (bit 3 is off) bool bit5 = bitRead(reg, 5); // 1 (bit 5 is on) bitWrite(reg, 3, 1); // Set bit 3: 0b10111100 bitClear(reg, 5); // Clear bit 5: 0b10011100 bitSet(reg, 0); // Set bit 0: 0b10011101 // bit() macro -- creates a bitmask byte mask = bit(4); // 0b00010000 -- same as (1 << 4)
Multi-Byte Sensor Data
Many I2C sensors return 16-bit readings as two separate bytes (high byte first, then low byte). Use highByte() and lowByte() to split, or (hi << 8) | lo to combine. The BMP280 barometric sensor does exactly this.
bitRead / bitWrite
More readable than raw bitwise ops: bitRead(PORTB, 5) vs (PORTB >> 5) & 1. Same compiled code, better readability. Use these helpers when working with registers or protocol bytes in your own code.
Serial Communication
When sending multi-byte data over Serial, SPI, or I2C, you split values into bytes for transmission and reassemble on the receiving end. lowByte()/highByte() is the standard pattern for this split.

Key Takeaways
Math & Logic -- the Arduino functions that transform raw sensor data into meaningful behavior.
1Integer division truncates. 5 / 2 = 2, not 2.5. Cast to float when you need decimal precision. Watch for int overflow in intermediate calculations.
2map() scales, constrain() clamps. Always pair them: constrain(map(raw, 0, 1023, 0, 255), 0, 255). map() alone can extrapolate beyond your target range.
3Trig uses radians. sin(), cos(), tan() expect radians, not degrees. Use degrees * PI / 180.0 or the radians() macro to convert.
4Seed your random. Without randomSeed(analogRead(A7)), random() produces the same sequence every boot. An unconnected analog pin provides the noise-based entropy.
5Bit helpers are your friends. bitRead(), bitWrite(), highByte(), lowByte() -- cleaner than raw bitwise ops, same compiled output. Use them for registers and multi-byte sensor data.
