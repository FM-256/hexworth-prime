ATmega328P Register Architecture
Every hardware feature is controlled by writing values to special memory addresses called registers.
What Is a Register?
An 8-bit memory location mapped to hardware. Writing a value to a register changes how the chip behaves -- pin directions, timer speeds, interrupt enables. The ATmega328P has 224 I/O registers at addresses 0x00-0xFF, each controlling a specific hardware function.
Register Types
DDRx: Data Direction Register (input/output). PORTx: Output register (HIGH/LOW). PINx: Input register (read pin state). TCCRnA/B: Timer control. OCRnA/B: Timer compare values. SREG: Status register.
Why Go Direct?
digitalWrite() takes ~5 microseconds. Direct port write takes ~0.06 microseconds -- 80x faster. For time-critical operations (bit-banging protocols, high-frequency PWM, precise pulse measurement), Arduino functions are too slow. Registers are the only option.
// Arduino function: ~5us per call digitalWrite(13, HIGH); // Direct register: ~62ns per call (80x faster) PORTB |= (1 << PB5); // Set bit 5 of PORTB = pin 13 HIGH // Why so much faster? digitalWrite() must: // 1. Look up the port from a table // 2. Look up the bit mask // 3. Disable interrupts // 4. Read-modify-write the port // 5. Re-enable interrupts // Direct register access skips all of that.

Direct Port Manipulation: PORTB, DDRB, PINB
Control all 8 pins of a port simultaneously with a single instruction.
// Port B maps to Arduino pins 8-13 (bits 0-5) // Port D maps to Arduino pins 0-7 (bits 0-7) // Port C maps to Arduino pins A0-A5 (bits 0-5) // Set pin 13 (PB5) as output DDRB |= (1 << PB5); // Same as pinMode(13, OUTPUT) // Set pin 13 HIGH PORTB |= (1 << PB5); // Same as digitalWrite(13, HIGH) // Set pin 13 LOW PORTB &= ~(1 << PB5); // Same as digitalWrite(13, LOW) // Toggle pin 13 PINB |= (1 << PB5); // Writing 1 to PINx toggles the pin // Set ALL of port D as output at once DDRD = 0xFF; // All 8 pins output in one instruction // Read pin 8 (PB0) state bool state = PINB & (1 << PB0); // Same as digitalRead(8)
Bitwise Operations Cheat Sheet
|= sets bits (OR). &= ~ clears bits (AND NOT). ^= toggles bits (XOR). << shifts left (selects bit position). & masks bits for reading. These six operations are the entire vocabulary of register programming.

Pin Change Interrupts (PCINT)
Respond to pin state changes on ANY digital pin -- not just pins 2 and 3.
External vs Pin Change
attachInterrupt() only works on pins 2 (INT0) and 3 (INT1) and supports RISING, FALLING, CHANGE, LOW. Pin Change Interrupts (PCINT) work on ALL 24 pins but only detect CHANGE (any toggle). You must determine direction in the ISR.
Three PCINT Groups
PCINT0 (pins 8-13, Port B), PCINT1 (pins A0-A5, Port C), PCINT2 (pins 0-7, Port D). Each group shares one ISR. When any enabled pin in the group changes, the group ISR fires. You must read the port to determine which pin triggered it.
// Enable pin change interrupt on pin 4 (PCINT20, Port D) PCICR |= (1 << PCIE2); // Enable PCINT group 2 (Port D) PCMSK2 |= (1 << PCINT20); // Enable PCINT on pin 4 specifically volatile byte lastPortD = 0; ISR(PCINT2_vect) { byte changed = PIND ^ lastPortD; // XOR to find which pin changed lastPortD = PIND; if (changed & (1 << PD4)) { // Pin 4 changed! Check PIND for HIGH/LOW if (PIND & (1 << PD4)) { // Pin 4 went HIGH (rising edge) } else { // Pin 4 went LOW (falling edge) } } }
ISR Rules
Keep interrupt service routines (ISRs) as short as possible. No Serial.print(), no delay(), no millis() reads inside an ISR. Set a volatile flag and process it in loop(). Long ISRs block other interrupts and break timing-dependent functions.

Timer0 / Timer1 / Timer2 Configuration
Three hardware timers that power millis(), PWM, tone(), and custom timing.
Timer0 (8-bit)
Powers millis(), micros(), and delay(). Also drives PWM on pins 5 and 6. Modifying Timer0 breaks all time-keeping functions. Prescaler: 64. Overflow interrupt fires every ~1ms.
Timer1 (16-bit)
Most versatile timer. 16-bit counter (0-65535). Drives PWM on pins 9 and 10. Used by the Servo library. Supports Input Capture for measuring external pulses with high precision. CTC mode for arbitrary frequencies.
Timer2 (8-bit)
Drives PWM on pins 3 and 11. Used by tone(). Has an asynchronous mode for use with a 32.768 kHz external crystal (real-time clock applications). Safest timer to modify without side effects.
// Configure Timer1 for a 1 Hz interrupt (CTC mode) cli(); // Disable interrupts during setup TCCR1A = 0; // Clear control registers TCCR1B = 0; TCNT1 = 0; // Reset counter OCR1A = 15624; // Compare value: 16MHz/1024/1Hz - 1 TCCR1B |= (1 << WGM12); // CTC mode (Clear Timer on Compare) TCCR1B |= (1 << CS12) | (1 << CS10); // Prescaler 1024 TIMSK1 |= (1 << OCIE1A); // Enable compare match interrupt sei(); // Re-enable interrupts ISR(TIMER1_COMPA_vect) { // This fires exactly once per second PINB |= (1 << PB5); // Toggle pin 13 }

Setting PWM Frequency via Timer Registers
analogWrite() defaults to ~490 Hz or ~980 Hz. Direct timer control gives you any frequency.
Default PWM Frequencies
// Pins 5, 6 (Timer0): ~980 Hz // Pins 9, 10 (Timer1): ~490 Hz // Pins 3, 11 (Timer2): ~490 Hz analogWrite(9, 128); // Outputs 490 Hz, 50% duty // Cannot change frequency // without touching registers
Custom: 25 kHz on pin 9
// Timer1 Fast PWM, TOP = ICR1 TCCR1A = (1<<COM1A1) | (1<<WGM11); TCCR1B = (1<<WGM13) | (1<<WGM12) | (1<<CS10); // No prescaler ICR1 = 639; // TOP: 16M/25k - 1 OCR1A = 319; // 50% duty cycle // Pin 9 now outputs 25 kHz PWM // Perfect for PC fan control
Common Custom Frequencies
25 kHz (PC fan control, motor drivers), 38 kHz (IR remote control), 1 kHz (audio tones), 20 kHz (ultrasonic range, above human hearing for silent motor control). The formula is: frequency = clock / (prescaler * (TOP + 1)). For Timer1 with no prescaler (16 MHz clock): TOP = (16,000,000 / desired_freq) - 1.
Timer Conflicts
Changing Timer0 breaks millis() and delay(). Changing Timer1 breaks the Servo library. Changing Timer2 breaks tone(). Always check which timer your libraries use before modifying prescalers or modes. Timer1 is the safest choice for custom PWM because Servo can be replaced with direct register control.

Pulse Generation & Accurate Measurement
Create precise output pulses and measure incoming pulse widths with hardware-level accuracy.
Pulse Generation (CTC Mode)
Timer1 in CTC mode with OC1A output (pin 9) toggling on compare match generates a clean, jitter-free square wave. Frequency = clock / (2 * prescaler * (OCR1A + 1)). No CPU intervention needed once configured -- the timer hardware runs autonomously.
Input Capture (ICP1 = Pin 8)
Timer1's Input Capture unit snapshots the 16-bit counter value the instant a signal edge arrives on pin 8 (ICP1). This gives microsecond-precision pulse measurement without the jitter of pulseIn(), which relies on a software polling loop.
// Measure pulse width on pin 8 using Input Capture volatile unsigned int risingEdge, fallingEdge, pulseWidth; void setup() { TCCR1A = 0; TCCR1B = (1<<ICES1) | (1<<CS11); // Rising edge, prescaler 8 TIMSK1 = (1<<ICIE1); // Enable input capture interrupt } ISR(TIMER1_CAPT_vect) { if (TCCR1B & (1<<ICES1)) { risingEdge = ICR1; TCCR1B &= ~(1<<ICES1); // Switch to falling edge } else { fallingEdge = ICR1; pulseWidth = fallingEdge - risingEdge; // In timer ticks TCCR1B |= (1<<ICES1); // Switch back to rising edge } }

Reducing Power: Sleep Modes
Drop power consumption from 15 mA to under 1 uA by shutting down unused hardware.
IDLE
CPU halted. Timers, UART, I2C, SPI still run. Wakes on any interrupt. ~15 mA to ~6 mA. millis() still works.
ADC Noise Reduction
CPU + most I/O halted. ADC runs for a clean reading. Wakes on ADC complete, external interrupt, or WDT.
Power-save
Only Timer2 (async) and external interrupts active. ~1 uA with 32 kHz crystal. Good for RTC wakeup.
Standby
Main oscillator runs but CPU and peripherals halted. Fast wake-up (6 clock cycles). ~0.2 mA.
Power-down
Everything off. Wakes only on external interrupt, WDT, or TWI address match. ~0.36 uA. Maximum battery life.
Extended Standby
Like Power-save but main oscillator keeps running for fast wake-up. Useful when Timer2 async and quick recovery are both needed.
#include <avr/sleep.h> set_sleep_mode(SLEEP_MODE_PWR_DOWN); // Deepest sleep sleep_enable(); sleep_mode(); // CPU stops here until interrupt sleep_disable(); // Execution continues here after wake

The Watchdog Timer
A self-contained timer that resets the chip if your program freezes or enters an infinite loop.
#include <avr/wdt.h> void setup() { wdt_enable(WDTO_2S); // Reset if not fed within 2 seconds // Options: WDTO_15MS, _30MS, _60MS, _120MS, _250MS, // _500MS, _1S, _2S, _4S, _8S } void loop() { wdt_reset(); // "Feed" the watchdog -- must call before timeout // ... your normal code ... // If this loop takes longer than 2 seconds, // or if the code hangs, the WDT resets the MCU. }
Reset Mode
If wdt_reset() is not called before the timeout expires, the watchdog triggers a full MCU reset. The program restarts from setup(). This is critical for unattended devices -- a sensor node in the field that freezes will recover automatically instead of staying dead.
Interrupt Mode
The WDT can also fire an interrupt instead of resetting. This is useful as a periodic wake-up source from power-down sleep mode. Set WDIE bit in WDTCSR to enable interrupt mode. Combine with sleep for ultra-low-power periodic sensing.
Bootloader Warning
Some older Arduino bootloaders do not clear the watchdog flag on reset, causing an infinite reset loop. The Optiboot bootloader (default on modern Uno boards) handles this correctly. If you encounter a reset loop after enabling WDT, you may need to burn a newer bootloader via ISP.

Uploading via ISP Programmer
Bypass the bootloader entirely -- program the chip directly through the ICSP header.
1Why ISP? ISP (In-System Programming) writes directly to flash without needing a bootloader. Recovers bricked boards, programs bare chips, and frees up the 512 bytes the bootloader occupies.
2Programmer hardware: USBasp, AVR ISP mkII, or use another Arduino as an ISP programmer (File > Examples > ArduinoISP). Connect MISO, MOSI, SCK, RST, VCC, GND between programmer and target.
3Upload via ISP: In the IDE, select Tools > Programmer > your programmer type. Then use Sketch > Upload Using Programmer (Ctrl+Shift+U). This overwrites the bootloader area.
4Restore bootloader: To use USB uploading again, go to Tools > Burn Bootloader with the ISP programmer connected. This re-installs the bootloader and restores normal upload capability.

Fuse Bytes: Lock Bits, Clock, Brownout
Low-level chip configuration that persists even when you erase the program.
Low Fuse (lfuse)
Controls clock source and startup time. Default 0xFF: external 16 MHz crystal, maximum startup delay. Change to 0x62 for internal 8 MHz RC oscillator (no crystal needed). Wrong value = board appears dead.
High Fuse (hfuse)
Controls bootloader size, EEPROM preservation on chip erase, watchdog always-on, and reset pin disable. Default 0xDE: 512-byte bootloader, EEPROM erased on chip erase. Critical for bootloader configuration.
Extended Fuse (efuse)
Controls brownout detection (BOD) voltage threshold. Default 0xFD: BOD at 2.7V. Options: 1.8V, 2.7V, 4.3V, or disabled. BOD resets the chip if voltage drops below threshold -- prevents corrupted operation from low battery.
// Read fuses with avrdude (via ISP programmer) avrdude -c usbasp -p m328p -U lfuse:r:-:h -U hfuse:r:-:h -U efuse:r:-:h // Write fuses (DANGEROUS -- wrong values can brick the chip) avrdude -c usbasp -p m328p -U lfuse:w:0xFF:m -U hfuse:w:0xDE:m // Lock bits: prevent reading back firmware (anti-piracy) avrdude -c usbasp -p m328p -U lock:w:0x0C:m
Extreme Caution
Writing wrong fuse values can make the chip unresponsive to normal programming. If you set the clock source to "external crystal" but have no crystal connected, the chip will not run and cannot be programmed via USB. Recovery requires a high-voltage programmer or connecting the correct clock source. Always use an online fuse calculator and triple-check before writing.

Replacing the Bootloader
Install a different bootloader or remove it entirely for maximum flash space.
1Optiboot (default): 512 bytes, 115200 baud upload speed. Ships on all modern Uno boards. Fast, reliable, handles WDT reset correctly. The standard choice for most projects.
2No bootloader: Upload via ISP only. Recovers 512 bytes of flash. Program starts instantly on power-up (no bootloader delay). Best for production devices that will never be reprogrammed via USB.
3Custom bootloaders: MicroBoot (tiny, wireless update capable), DualOptiboot (two firmware slots), STK500v2 (for Mega boards). Each has trade-offs in size, speed, and features.
