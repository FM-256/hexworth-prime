How Sound Works
Sound is a pressure wave traveling through air. Frequency determines pitch. Amplitude determines volume. Arduino generates sound by vibrating a speaker or buzzer at specific frequencies.
Frequency (Pitch)
Measured in Hertz (Hz) -- cycles per second. Middle C = 262 Hz. Concert A = 440 Hz. Human hearing range: 20 Hz to 20,000 Hz. Higher frequency = higher pitch.
Amplitude (Volume)
The height of the wave. Larger amplitude = louder sound. Arduino's digital output is either 0V or 5V -- you cannot easily control volume with tone(). External amplifiers or PWM tricks are needed for volume control.
Waveform (Timbre)
Square wave, sine wave, sawtooth, triangle -- the shape of the wave determines the character of the sound. tone() produces a square wave. For richer sounds, you need synthesis libraries like Mozzi.
Piezo Buzzer
A small ceramic disc that deforms when voltage is applied, producing a click. Toggling voltage at audio frequencies produces a tone. Two types: active buzzers (built-in oscillator, just apply voltage) and passive buzzers (you generate the frequency). For Arduino, passive buzzers + tone() give you control over pitch.
Speaker
An electromagnetic driver with a cone that pushes air. Much louder and wider frequency response than a piezo. Small 8-ohm speakers work well with Arduino. For higher volume, add a transistor amplifier or use a PAM8403 amplifier module between the Arduino and speaker.

The tone() Function
Arduino's built-in function for generating a square wave at a specific frequency on any digital pin.
// Three ways to use tone() tone(8, 440); // Play 440 Hz on pin 8 until noTone() tone(8, 440, 500); // Play 440 Hz for 500ms, then stop automatically noTone(8); // Immediately stop any tone on pin 8 // Simple alarm: two alternating tones void loop() { tone(8, 1000, 200); // High tone delay(300); tone(8, 500, 200); // Low tone delay(300); }
tone(pin, frequency)
Starts a continuous square wave on the specified pin at the given frequency in Hz. The tone plays indefinitely until noTone() is called. Uses Timer2 internally, which means PWM on pins 3 and 11 is affected while a tone is playing.
tone(pin, frequency, duration)
Same as above, but stops automatically after the specified duration in milliseconds. Note: the function returns immediately -- it does NOT block. If you want silence between notes, you must add a delay() after the tone() call.

Playing Melodies
Melodies are sequences of notes with specific frequencies and durations. Store them in arrays and iterate through them.
// Note frequency definitions (Hz) #define NOTE_C4 262 #define NOTE_D4 294 #define NOTE_E4 330 #define NOTE_F4 349 #define NOTE_G4 392 #define NOTE_A4 440 #define NOTE_B4 494 #define NOTE_C5 523 #define REST 0 // Twinkle Twinkle Little Star int melody[] = { NOTE_C4, NOTE_C4, NOTE_G4, NOTE_G4, NOTE_A4, NOTE_A4, NOTE_G4, REST, NOTE_F4, NOTE_F4, NOTE_E4, NOTE_E4, NOTE_D4, NOTE_D4, NOTE_C4 }; int durations[] = { 4, 4, 4, 4, 4, 4, 2, 4, 4, 4, 4, 4, 4, 4, 2 }; // 4=quarter, 2=half void playMelody() { int numNotes = sizeof(melody) / sizeof(melody[0]); for (int i = 0; i < numNotes; i++) { int noteDuration = 1000 / durations[i]; if (melody[i] != REST) tone(8, melody[i], noteDuration); delay(noteDuration * 1.3); // 30% gap between notes noTone(8); } }
Duration Convention
A common convention: store durations as note fractions (4 = quarter note, 8 = eighth, 2 = half, 1 = whole). Calculate actual milliseconds as 1000/duration at a baseline of 1 second per whole note. Adjust the divisor to change tempo. The 1.3 multiplier on delay creates a small gap between notes so they sound distinct rather than blurred together.
pitches.h
The Arduino examples include a file called pitches.h that defines constants for all standard musical note frequencies from B0 (31 Hz) through D#8 (4978 Hz). You can include it in your sketch instead of defining each note manually. It is available in the Arduino IDE under Examples -- Digital -- toneMelody.

Multi-Tone Limitations
Arduino's tone() function can only play one note at a time on one pin. True polyphony requires creative workarounds.
The Limitation
tone() uses a single hardware timer (Timer2 on Uno). You cannot call tone() on two different pins simultaneously. The second call overrides the first. This means no chords, no harmony, no two-voice music with the built-in function.
Workaround: Rapid Switching
Alternate between two frequencies fast enough that the ear perceives them as simultaneous. Play note A for 2ms, note B for 2ms, repeat. The result is a rough chord. Sounds harsh but demonstrates the concept.
Workaround: Mozzi Library
The Mozzi audio synthesis library bypasses tone() entirely. It uses direct timer manipulation and DDS to generate complex waveforms, multiple oscillators, and real-time effects. It is the go-to library for serious Arduino audio projects.
// Crude two-tone simulation (rapid switching) void pseudoChord(int freq1, int freq2, int durationMs) { unsigned long start = millis(); while (millis() - start < durationMs) { tone(8, freq1); delay(2); tone(8, freq2); delay(2); } noTone(8); }
Multiple Buzzers
Another approach: connect multiple piezo buzzers to different pins and manage each one manually using direct port manipulation instead of tone(). This requires understanding timer registers, but it allows true simultaneous tones on separate output devices. Libraries like Tone.h (not the built-in one) support multiple simultaneous tones on multiple pins.

PWM Audio & DDS Concepts
Beyond square waves: using PWM and Direct Digital Synthesis to generate arbitrary waveforms from a digital output.
analogWrite() for Audio
The default analogWrite() PWM frequency (~490 Hz or ~980 Hz on Uno) is too low for clean audio. But by reconfiguring Timer registers to run at 31 kHz or 62 kHz, you can use PWM as a crude DAC (Digital-to-Analog Converter). Each PWM cycle represents one audio sample. Feed samples fast enough and the output smooths into an analog waveform.
Direct Digital Synthesis (DDS)
DDS generates waveforms mathematically. Store one cycle of a sine wave in a lookup table (e.g., 256 values). A phase accumulator steps through the table at a rate determined by the desired frequency. Output each value via high-speed PWM. The result is a smooth, frequency-accurate waveform from pure software.
1 Set timer to fast PWM mode at the highest possible frequency (62.5 kHz on Uno). This eliminates the audible PWM whine and makes the output behave like a DAC.
2 Use a timer interrupt to fire at a fixed sample rate (e.g., 8 kHz or 16 kHz). Each interrupt reads the next sample value from the wavetable and writes it to the PWM register.
3 Add an RC low-pass filter on the output pin (e.g., 1K resistor + 100nF capacitor) to smooth the PWM into a clean analog waveform before it reaches the speaker.
Why This Matters
This is the foundation of how Mozzi, PCM audio playback, and Arduino speech synthesis all work. The ATmega328P has no DAC, but high-speed PWM + a low-pass filter creates a functional one. Understanding DDS unlocks audio synthesis, waveform generation for testing, and even software-defined radio concepts.

MIDI -- Musical Instrument Digital Interface
MIDI does not transmit sound -- it transmits instructions. Note on, note off, velocity, channel. Your Arduino becomes a controller for professional synthesizers.
// Send MIDI note on/off messages over Serial void setup() { Serial.begin(31250); // MIDI baud rate } void noteOn(byte channel, byte note, byte velocity) { Serial.write(0x90 | channel); // Note On, channel 0-15 Serial.write(note); // Note number (60 = middle C) Serial.write(velocity); // Velocity 0-127 } void noteOff(byte channel, byte note) { Serial.write(0x80 | channel); // Note Off Serial.write(note); Serial.write((byte)0); // Velocity 0 } void loop() { noteOn(0, 60, 100); // Play middle C, velocity 100 delay(500); noteOff(0, 60); // Release middle C delay(500); }
MIDI Message Structure
Every MIDI message starts with a status byte (0x90 = Note On, 0x80 = Note Off, 0xB0 = Control Change) followed by one or two data bytes. Note numbers range from 0-127 (middle C = 60). Velocity ranges from 0-127 and controls how hard the note is struck. Channels 0-15 allow 16 independent instruments on a single MIDI cable.
Slide 8 of 12
MIDI Control
Turn your Arduino into a MIDI controller that drives external synthesizers, DAWs, and lighting systems.
MIDI Shield
A shield with proper MIDI DIN connectors (5-pin), optocoupler for MIDI IN isolation, and the required 220-ohm resistors on MIDI OUT. Plugs directly onto an Uno. SparkFun and others make Arduino MIDI shields.
USB-MIDI
Arduino Leonardo/Micro (ATmega32U4) or Teensy boards can appear as native USB-MIDI devices. No MIDI cable needed -- plug USB into a computer and the Arduino shows up as a MIDI instrument in any DAW (Ableton, Logic, FL Studio).
Control Change (CC)
Beyond note on/off, MIDI supports Control Change messages for knobs, sliders, and buttons. Read a potentiometer with analogRead(), map to 0-127, send as CC. Build custom MIDI controllers for live performance.
// Potentiometer as MIDI CC controller void setup() { Serial.begin(31250); } void sendCC(byte channel, byte control, byte value) { Serial.write(0xB0 | channel); // Control Change Serial.write(control); // CC number (0-127) Serial.write(value); // Value (0-127) } int lastVal = -1; void loop() { int raw = analogRead(A0); int val = map(raw, 0, 1023, 0, 127); if (val != lastVal) { sendCC(0, 1, val); // CC#1 (Mod Wheel) on channel 0 lastVal = val; } delay(10); }
DIY MIDI Circuit
If you do not have a MIDI shield, you can build a MIDI OUT circuit with a single 220-ohm resistor and a 5-pin DIN connector. Pin 5 of the DIN connects to Arduino TX through a 220-ohm resistor. Pin 2 connects to GND. Pin 4 connects to 5V through a 220-ohm resistor. That is the complete circuit -- three wires and two resistors.

Audio Synthesis: Mozzi Library
Mozzi turns an Arduino into a real-time audio synthesizer with oscillators, envelopes, filters, and modulation -- all running on an 8-bit microcontroller.
Wavetable Synthesis
Store one cycle of a waveform (sine, saw, square, triangle, or custom) in a lookup table. An oscillator object steps through the table at the desired frequency. Multiple oscillators can be mixed for complex timbres. Mozzi provides sine, saw, triangle, and square tables out of the box.
Mozzi Architecture
Two callback functions: updateControl() runs at a slow rate (64 Hz default) for reading sensors and updating parameters. updateAudio() runs at the sample rate (16384 Hz default) and must return the next audio sample as fast as possible. This two-rate design keeps audio glitch-free.
// Mozzi basic sine wave example #include <MozziGuts.h> #include <Oscil.h> #include <tables/sin2048_int8.h> Oscil<SIN2048_NUM_CELLS, AUDIO_RATE> aSin(SIN2048_DATA); void setup() { aSin.setFreq(440); // A4 startMozzi(); } void updateControl() { // Read sensors, update parameters here (runs at 64 Hz) } int updateAudio() { return aSin.next(); // Return next sample (runs at 16384 Hz) } void loop() { audioHook(); // Required -- drives the audio engine }
What Mozzi Can Do
FM synthesis, AM synthesis, wavetable mixing, ADSR envelopes, low-pass/high-pass filters, delay effects, sample playback, and even rudimentary speech synthesis. All running on an ATmega328P at 16 MHz with 2KB of RAM. The output pin goes through an RC filter to a speaker. Mozzi is a masterclass in optimized embedded audio.

Sound Detection
Microphone modules let your Arduino listen to the environment -- detecting sound levels, claps, knocks, and audio patterns.
Analog Sound Sensor
An electret microphone + amplifier module that outputs an analog voltage proportional to sound level. Connect to an analog pin. Quiet room reads ~512 (midpoint). Loud sounds create swings above and below this center. Use analogRead() to sample the level. The KY-038 and MAX4466 are common modules.
Digital Sound Sensor
Same microphone module but with an onboard comparator and potentiometer. The digital output pin goes HIGH when sound exceeds the threshold set by the pot. Simpler than analog: just use digitalRead(). Good for clap detection and basic triggers. Cannot measure sound levels.
// Clap detection using analog sound sensor const int MIC_PIN = A0; const int LED_PIN = 13; const int THRESHOLD = 600; // Adjust based on your sensor bool ledOn = false; void setup() { pinMode(LED_PIN, OUTPUT); Serial.begin(9600); } void loop() { int soundLevel = analogRead(MIC_PIN); if (soundLevel > THRESHOLD) { ledOn = !ledOn; digitalWrite(LED_PIN, ledOn ? HIGH : LOW); Serial.print("Clap detected! Level: "); Serial.println(soundLevel); delay(300); // Debounce -- ignore echoes } }
Sampling for Audio Analysis
To analyze actual audio content (not just loudness), you need fast sampling. analogRead() takes ~100 microseconds, giving roughly 10 kHz sample rate. For basic frequency detection, sample a window of 128-256 readings rapidly, then apply a simple algorithm like zero-crossing counting to estimate the dominant frequency. True FFT is possible with the ArduinoFFT library but pushes the ATmega's limits.

Practical Audio Projects
Real-world applications: alarms, doorbells, metronomes, and sensor-driven audio feedback.
Alarm System
Two alternating tones (1000 Hz / 500 Hz) with 200ms each. Add a PIR motion sensor as the trigger. Use a flag variable to arm/disarm with a button.
Doorbell
Play a short melody when a button is pressed. Use a "playing" flag to prevent re-triggering mid-melody. Add a second button for a different tune.
Metronome
Short tone() click at a regular interval. Use a potentiometer to set BPM (40-200). Calculate interval: 60000/BPM milliseconds. Accent beat 1 with a higher pitch.
Distance Sonar
Ultrasonic sensor + buzzer. Closer objects = faster beeping. Map distance to delay between beeps. Under 10cm = continuous tone. Classic parking sensor pattern.
Temperature Alert
Read a thermistor or DHT11. Map temperature to pitch. Normal range = silence. Above threshold = ascending alarm tone. Audible environmental monitoring.
Simon Game
Four buttons, four tones. Play a sequence, player repeats. Each round adds a note. Wrong press = failure buzzer. Combines arrays, input, randomness, and audio.
Design Principle
Audio feedback works best when it is brief, distinct, and mapped to meaning. A short rising tone for "success," a low buzz for "error," a click for "acknowledged." Long or repetitive tones annoy users. The best audio interfaces convey information without demanding attention -- like a microwave beep vs. a car alarm.

Key Takeaways: Sound & Audio
From a single beep to MIDI controllers to real-time synthesis -- audio is now in your toolkit.
1tone(pin, frequency, duration) generates a square wave on any digital pin. It uses Timer2, so PWM on pins 3 and 11 is affected. Only one tone can play at a time. noTone() stops it. This is your starting tool for all audio output.
2Melodies are arrays of frequencies and durations. Store notes as Hz values and durations as note fractions. Loop through the arrays with tone() and delay(). The 30% gap between notes (delay * 1.3) creates articulation. pitches.h provides all standard musical note constants.
3MIDI sends instructions, not sound. Serial at 31250 baud. Note On = 0x90 + channel, note number, velocity. Note Off = 0x80 + channel, note number, 0. Control Change = 0xB0 for knobs and sliders. Arduino becomes a professional instrument controller.
4Mozzi enables real synthesis. Wavetable oscillators, ADSR envelopes, filters, and effects -- all running on an ATmega328P at 16 MHz. The two-callback architecture (updateControl at 64 Hz, updateAudio at 16384 Hz) keeps audio glitch-free while still reading sensors.
5Microphones add input. Analog sound sensors read loudness levels (clap detection, volume triggers). Digital sensors provide simple threshold triggers. Fast sampling + zero-crossing or FFT enables basic frequency detection. Sound in + sound out = interactive audio systems.
