What is Arduino?
An open-source electronics platform with easy-to-use hardware and software. Born in 2005 at the Interaction Design Institute in Ivrea, Italy.
Not a Computer
Arduino has no operating system, no file system, no multitasking. It runs exactly one program in an infinite loop. When you cut power, the program stays in flash memory. When you restore power, it starts running again instantly. This is a microcontroller, not a PC.
Why Arduino Matters
Before Arduino, programming hardware required expensive tools and deep electrical engineering knowledge. Arduino made it accessible: plug in USB, write code, upload. It democratized physical computing and launched the maker movement.
Origin Story
Arduino was created in 2005 by Massimo Banzi and his team at the Interaction Design Institute Ivrea in Italy. The goal: give design students an affordable, easy way to create interactive projects. The name comes from a bar in Ivrea frequented by the founders. The project went open-source, and the rest is history.

Meet the Board: Arduino Uno R3
The most popular Arduino board. Your first hardware platform.
Digital Pins (0-13)
14 pins that read or write HIGH (5V) or LOW (0V). Pins 3, 5, 6, 9, 10, 11 support PWM (analog-like output). Pin 13 is wired to the built-in LED.
Analog Pins (A0-A5)
6 pins that read voltages from 0V to 5V and convert them to values 0-1023 using a 10-bit ADC. Used for sensors like temperature, light, and potentiometers.
Power Pins
5V and 3.3V output pins supply power to external components. GND (ground) completes every circuit. Multiple GND pins are available on the board.
Slide 4 of 12
The Arduino Ecosystem
One platform, many boards. Different boards for different jobs. Plus a vast shield ecosystem for add-on functionality.
Uno R3
ATmega328P, 14 digital, 6 analog. The standard beginner board. 32KB flash.
Mega 2560
ATmega2560, 54 digital, 16 analog. For projects that need more pins and memory (256KB flash).
Nano
Same ATmega328P as Uno but in a tiny breadboard-friendly form factor. Perfect for embedded projects.
MKR Series
ARM-based boards with built-in WiFi, LoRa, or GSM. For IoT and connected devices. 3.3V logic.
Leonardo
ATmega32U4 with native USB. Can emulate a keyboard or mouse. Used for HID projects and game controllers.
Shields
Plug-on boards that add WiFi, motor control, SD cards, LCD screens, GPS, and more. Stack directly on the Uno.
Why Start with Uno?
The Uno R3 is the most documented, most supported, and most forgiving Arduino board. Every tutorial, every library, and every shield is designed for it first. Master the Uno, and every other Arduino board becomes familiar territory. It is the reference platform for this entire ProtoCore track.
Slide 5 of 12
The Arduino IDE
Your command center. Write code, compile it, and upload it to the board -- all from one application.
Verify (Compile)
Checks your code for syntax errors and compiles it to machine code. Does NOT upload to the board. Use this to catch mistakes before uploading. The output panel shows errors with line numbers.
Upload
Compiles AND sends the compiled code to the Arduino board via USB. The board resets, the bootloader receives the code, and the ATmega starts executing your program immediately.
Sketch = Arduino Program
Arduino calls its programs "sketches." A sketch is a .ino file containing your code. The IDE stores each sketch in its own folder. The concept comes from Processing, the visual programming language that inspired Arduino's software design. Every sketch needs at minimum a setup() function and a loop() function.
Slide 6 of 12
Anatomy of a Sketch
Every Arduino program has two required functions: setup() runs once, loop() runs forever.
setup() -- Runs Once
void setup() { // Initialize pins pinMode(13, OUTPUT); // Start serial communication Serial.begin(9600); }
loop() -- Runs Forever
void loop() { // This code repeats endlessly digitalWrite(13, HIGH); delay(1000); digitalWrite(13, LOW); delay(1000); }
Why Two Functions?
Hardware needs initialization. Pins must be configured, serial ports opened, sensors calibrated. That happens once in setup(). Then the actual work -- reading sensors, controlling motors, blinking LEDs -- runs continuously in loop().
Simplest Valid Sketch
An empty setup() and empty loop() is a valid Arduino program. It does nothing, but it compiles and uploads. The Arduino will sit there running an empty loop forever, consuming about 15mA, waiting for you to give it purpose.

Blink: Your First Sketch
The "Hello World" of hardware. Four lines of code that make an LED blink on and off.
void setup() { pinMode(13, OUTPUT); // Configure pin 13 as an output } void loop() { digitalWrite(13, HIGH); // Turn LED ON (5V to pin 13) delay(1000); // Wait 1 second (1000 milliseconds) digitalWrite(13, LOW); // Turn LED OFF (0V to pin 13) delay(1000); // Wait 1 second }
1 pinMode(13, OUTPUT) -- tells the ATmega328P that pin 13 will send voltage out (not read it). This configuration is stored in a hardware register and stays set until power-off or reset.
2 digitalWrite(13, HIGH) -- sets pin 13 to 5 volts. Current flows through the built-in LED. The LED lights up. HIGH = 5V, LOW = 0V. Binary. On or off. No in-between.
3 delay(1000) -- pauses execution for 1000 milliseconds (1 second). The processor does nothing during this time. The LED stays on because the pin register still holds HIGH.
4 digitalWrite(13, LOW) -- drops pin 13 to 0 volts. Current stops. LED goes dark. Then another delay, and loop() starts over from the top.
Slide 8 of 12
Upload & Verify: The AllSpark Moment
You click Upload. The board resets. The bootloader receives your code. The LED blinks. Hardware obeys software. It is alive.
Before You Upload
1. Connect the Arduino to your computer via USB cable. 2. In the IDE, select Tools > Board > Arduino Uno. 3. Select Tools > Port > COM3 (or whichever port your Arduino is on). 4. Click the Upload button (right arrow icon).
What Happens Inside
The IDE compiles your .ino file into a .hex binary. The USB chip on the Arduino triggers a reset. The bootloader (a tiny program already on the ATmega) receives the hex data and writes it to flash memory. The ATmega reboots and starts executing your code. Total time: 5-10 seconds.
The LED blinks. Dead silicon is now a machine under your command. This is the AllSpark moment.
Slide 9 of 12
Modify the Blink: Control Time
Change one number and the hardware responds differently. You control how fast the world blinks.
delay(1000) -- 1 second
The default Blink. One second on, one second off. A calm, steady heartbeat. The LED blinks once per two seconds.
delay(100) -- 0.1 second
Ten times faster. The LED flickers rapidly -- almost too fast to see individual blinks. You are pushing the visual threshold of human perception.
delay(2000) -- 2 seconds
Slow, deliberate. Two seconds on, two seconds off. Each blink feels intentional and weighty. The board breathes slowly.
Symmetric Blink
digitalWrite(13, HIGH); delay(1000); // ON for 1s digitalWrite(13, LOW); delay(1000); // OFF for 1s
Asymmetric Blink
digitalWrite(13, HIGH); delay(200); // ON for 0.2s digitalWrite(13, LOW); delay(800); // OFF for 0.8s
Experiment
Try delay(50) -- the LED appears to stay on continuously because your eyes cannot process 50ms transitions. Try delay(5000) -- five seconds feels like an eternity when you are watching hardware. These experiments build the intuition that millisecond timing is the language of embedded systems.

Serial Monitor: The Board Talks Back
Until now, communication was one-way. Serial Monitor opens a two-way channel between your computer and the Arduino.
void setup() { Serial.begin(9600); // Open serial port at 9600 baud Serial.println("AllSpark activated"); } void loop() { Serial.println("Hello from Arduino"); delay(1000); // Print once per second }
Serial.begin(9600)
Opens the serial port at 9600 bits per second (baud rate). This must be called in setup() before any Serial.print calls. The baud rate in the IDE's Serial Monitor must match -- if the board sends at 9600 but the monitor listens at 115200, you get garbage text.
Serial.println()
Sends text over USB to your computer. println adds a newline after each message. print does not. You can send numbers, strings, and variable values. This is your primary debugging tool -- the Arduino equivalent of console.log().
Why 9600?
9600 baud is the Arduino default -- reliable and universally supported. It means 9600 bits per second, or roughly 960 characters per second (each character is 10 bits: 8 data + 1 start + 1 stop). For printing text it is plenty fast. Higher baud rates (115200, 250000) exist for data-heavy applications, but 9600 is where every beginner starts.
Slide 11 of 12
Beyond Blink: First External Circuit
The built-in LED is training wheels. Now the board controls something outside itself -- an LED on a breadboard.
1 Pin 9 sends a HIGH or LOW signal, just like pin 13 did for the built-in LED. But now the signal leaves the board and travels through a wire to the breadboard.
2 220-ohm resistor limits current to protect the LED. Without it, too much current flows and the LED burns out. The resistor is not optional -- it is the first safety lesson in electronics.
3 LED (Light Emitting Diode) has two legs: the longer leg (anode, +) connects to the resistor side; the shorter leg (cathode, -) connects to GND. Polarity matters -- reverse it and nothing happens.
4 GND wire completes the circuit back to the Arduino. Current flows from pin 9 through the resistor, through the LED, and back to GND. A circuit must be complete or nothing works.
Slide 12 of 12
Key Takeaways: AllSpark Complete
You brought silicon to life. Here are the five facts that matter.
1Arduino is a microcontroller, not a computer. No OS, no multitasking. One program runs in an infinite loop on an ATmega328P at 16 MHz. When power is cut, the program stays in flash memory and restarts when power returns.
2Every sketch has setup() and loop(). Setup runs once for initialization (pin modes, serial ports). Loop runs forever for the actual work. This two-function structure is the foundation of every Arduino program you will ever write.
3Upload flow: code to .hex to flash. The IDE compiles your .ino sketch into a hex binary, sends it over USB, and the bootloader writes it to the ATmega's flash memory. The entire upload takes seconds.
4Serial Monitor is your debugging tool. Serial.begin(9600) opens the channel. Serial.println() sends text back to your computer. This is how you see what the Arduino is thinking -- the hardware equivalent of console.log().
5External circuits need resistors. The first circuit outside the board -- pin to resistor to LED to GND -- teaches the most important lesson in electronics: current must be limited, polarity matters, and the circuit must be complete.
