The Serial Monitor is a debugging tool, not a user interface. Real embedded systems need displays -- screens that show data without a computer attached. From a 16x2 character LCD showing "Temp: 23.5C" to a full-color TFT rendering sensor dashboards, displays transform your Arduino from a hidden processor into a visible, interactive device.

Display Types
Four families of displays, each with different capabilities, interfaces, and use cases.
Character LCD (16x2, 20x4)
Text-only display with fixed character cells. Each cell is a 5x8 pixel grid. HD44780 controller, parallel or I2C interface. Cheap ($2-5), easy to use, but limited to predefined characters. Green or blue backlight. The workhorse of embedded systems.
Graphical LCD (128x64)
Monochrome pixel-level control. ST7565 or PCD8544 (Nokia 5110) controller. Draw shapes, lines, custom fonts, and bitmaps. No color, but full graphical freedom. SPI interface. Great for graphs and custom UIs.
OLED (128x64, 128x32)
Self-emitting pixels -- no backlight needed. SSD1306 controller. Deep blacks, wide viewing angles, ultra-thin. I2C or SPI. Excellent contrast ratio. Small form factor (0.96" typical). Best for wearables and compact projects.
Full-Color TFT (240x320+)
65K or 262K colors. ST7735 (1.8"), ILI9341 (2.4"+). SPI interface. Draw images, gradients, multiple fonts, and touch overlay. Requires more memory and processing power. The closest to a phone screen you can get on an Arduino.
Choosing a Display
Need just text and numbers? Character LCD -- cheapest and simplest. Need graphics on a budget? OLED 128x64 -- beautiful contrast, tiny footprint, I2C simplicity. Need color and images? TFT -- more complex but stunning results. Need maximum battery life? OLED -- individual pixel control means only lit pixels consume power.

Character LCD: 16x2 HD44780
16 characters wide, 2 rows tall. The most common Arduino display. HD44780 controller, 4-bit parallel mode.
// Basic 16x2 LCD in 4-bit mode #include <LiquidCrystal.h> // RS, EN, D4, D5, D6, D7 LiquidCrystal lcd(12, 11, 5, 4, 3, 2); void setup() { lcd.begin(16, 2); // 16 cols, 2 rows lcd.print("Hello, World!"); } void loop() { lcd.setCursor(0, 1); // col 0, row 1 lcd.print(millis() / 1000); }
4-Bit Mode Wiring
The HD44780 has a 16-pin interface but only 6 Arduino pins are needed in 4-bit mode: RS (register select), EN (enable), and D4-D7 (data). The remaining D0-D3 are unused. A potentiometer on V0 controls contrast. Pin A/K power the backlight.
LiquidCrystal Library
Built into the Arduino IDE -- no installation needed. lcd.begin(16,2) initializes the display dimensions. lcd.print() writes text at the current cursor position. lcd.clear() erases everything and resets the cursor to (0,0).

Text Formatting
Cursor positioning, scrolling, autoscroll, and custom character creation on character LCDs.
1 setCursor(col, row): Move the cursor to any position. Column 0-15, row 0-1 on a 16x2 LCD. lcd.setCursor(5, 1) positions at column 5, row 1 (second line). All subsequent print() calls write from that position.
2 print() and write(): lcd.print() handles strings, ints, and floats with automatic type conversion. lcd.write() sends a single byte -- used for custom characters. Print integers with a base: lcd.print(255, HEX) shows "FF".
3 scrollDisplayLeft() / Right(): Shift the entire display content one position. Call in a loop with delay to create a scrolling marquee effect. Content wraps from one end to the other. Does not change cursor position.
4 autoscroll(): When enabled, each new character pushes the existing text one position to the left. Useful for right-to-left scrolling effects. Disable with lcd.noAutoscroll().
// Scrolling marquee effect void loop() { lcd.setCursor(0, 0); lcd.print("ProtoCore Arduino!"); for (int i = 0; i < 16; i++) { lcd.scrollDisplayLeft(); delay(300); } }
Custom Characters
The HD44780 allows up to 8 custom characters (indices 0-7). Each character is a 5x8 pixel bitmap defined as an array of 8 bytes, where each byte represents one row. Use lcd.createChar(index, byteArray) to register a custom character, then lcd.write(index) to display it. You can create arrows, symbols, progress bars, and simple icons this way.

I2C LCD: 2-Wire Connection
The PCF8574 backpack reduces 16 pins to just 4: VCC, GND, SDA, SCL.
// I2C LCD -- only 2 data wires #include <Wire.h> #include <LiquidCrystal_I2C.h> LiquidCrystal_I2C lcd(0x27, 16, 2); // address, cols, rows void setup() { lcd.init(); lcd.backlight(); lcd.print("I2C LCD Ready"); }
Why I2C?
Parallel mode uses 6 Arduino pins. I2C uses 2 (SDA on A4, SCL on A5). The PCF8574 chip on the backpack translates I2C serial commands into the parallel signals the HD44780 expects. This saves 4 pins for sensors and actuators.
Address Discovery
Most I2C LCD backpacks use address 0x27 or 0x3F. If your LCD does not respond, run an I2C scanner sketch that loops through all 127 addresses and reports which ones respond. Solder pads on the backpack let you change the address for multi-LCD setups.

Graphical LCD
Pixel-level control. Draw lines, rectangles, circles, and custom bitmaps on monochrome screens.
PCD8544 (Nokia 5110)
84x48 pixels, monochrome. SPI interface (5 pins: CLK, DIN, DC, CE, RST). Very low power, visible in direct sunlight. The classic retro display. Uses the Adafruit PCD8544 library. Good for simple menus and dashboards.
ST7565 (128x64)
Larger monochrome graphical LCD. SPI interface. 128x64 pixels gives you real estate for graphs, multi-line text, and complex layouts. Uses the U8g2 library for high-quality font rendering and drawing primitives.
// Drawing on a graphical LCD with U8g2 #include <U8g2lib.h> U8G2_ST7565_64128N_F_4W_SW_SPI u8g2(U8G2_R0, 13, 11, 10, 9, 8); void setup() { u8g2.begin(); } void loop() { u8g2.clearBuffer(); u8g2.setFont(u8g2_font_ncenB08_tr); u8g2.drawStr(10, 20, "ProtoCore"); u8g2.drawFrame(5, 5, 118, 54); // rectangle outline u8g2.drawLine(0, 32, 127, 32); // horizontal divider u8g2.sendBuffer(); }
Drawing Primitives
U8g2 provides: drawPixel(x,y), drawLine(x0,y0,x1,y1), drawFrame(x,y,w,h) (rectangle outline), drawBox(x,y,w,h) (filled rectangle), drawCircle(x,y,r), drawDisc(x,y,r) (filled circle), drawTriangle(), and drawBitmap(). You can also render XBM images and use dozens of built-in fonts.

OLED Displays: SSD1306
128x64 pixels, self-emitting, infinite contrast ratio. The best small display for Arduino.
// SSD1306 OLED with Adafruit library #include <Wire.h> #include <Adafruit_GFX.h> #include <Adafruit_SSD1306.h> Adafruit_SSD1306 display(128, 64, &Wire, -1); void setup() { display.begin(SSD1306_SWITCHCAPVCC, 0x3C); display.clearDisplay(); display.setTextSize(1); display.setTextColor(SSD1306_WHITE); display.setCursor(0, 0); display.println("OLED Ready"); display.display(); // push buffer to screen }
Why OLED?
Each pixel emits its own light. Black pixels are truly off (zero power). Contrast ratio is essentially infinite. Viewing angle is nearly 180 degrees. No backlight bleed. Thinner than any LCD.
Adafruit GFX
The GFX library provides a common drawing API across all Adafruit displays. Same functions work on OLED, TFT, and e-ink: drawPixel, drawLine, drawRect, drawCircle, print, setFont. Learn once, use everywhere.
Memory Cost
128x64 pixels = 1024 bytes for the frame buffer. The SSD1306 library allocates this in SRAM. On an Uno with only 2048 bytes of SRAM, that is 50% of memory used by the display alone. Plan your variables carefully.

Full-Color LCD
ST7735 (1.8") and ILI9341 (2.4"+). SPI interface, 65K colors, images, gradients, and touch.
ST7735 (128x160, 1.8")
Small, affordable color TFT. SPI interface (5-6 pins). 65K colors (RGB565 format). Fast enough for simple animations. Use Adafruit_ST7735 library. Perfect for data dashboards, sensor readouts, and small game UIs.
ILI9341 (240x320, 2.4"+)
Larger, higher resolution. Often comes with a resistive touch overlay (XPT2046 controller). SPI at up to 40MHz. Use Adafruit_ILI9341 + Adafruit_GFX. Needs an Arduino Mega or ESP32 for complex UIs due to memory constraints.
// Color TFT with ST7735 #include <Adafruit_GFX.h> #include <Adafruit_ST7735.h> Adafruit_ST7735 tft(10, 9, 8); // CS, DC, RST void setup() { tft.initR(INITR_BLACKTAB); tft.fillScreen(ST77XX_BLACK); tft.setTextColor(ST77XX_YELLOW); tft.setTextSize(2); tft.setCursor(10, 10); tft.println("ProtoCore"); tft.fillRect(10, 50, 100, 20, ST77XX_BLUE); // filled rect }
RGB565 Color Format
TFT displays use 16-bit color (RGB565): 5 bits red, 6 bits green, 5 bits blue. Total: 65,536 colors. Common constants: ST77XX_BLACK (0x0000), ST77XX_WHITE (0xFFFF), ST77XX_RED (0xF800), ST77XX_GREEN (0x07E0), ST77XX_BLUE (0x001F). For custom colors, use tft.color565(r, g, b) where each value is 0-255.

Custom Characters
Design 5x8 pixel icons for character LCDs. Create arrows, battery indicators, and animation frames.
// Define and display a custom heart character byte heart[8] = { 0b00000, 0b01010, 0b11111, 0b11111, 0b01110, 0b00100, 0b00000, 0b00000 }; void setup() { lcd.begin(16, 2); lcd.createChar(0, heart); // register as character 0 lcd.setCursor(0, 0); lcd.write((byte)0); // display it lcd.print(" Health: 100"); }
Animation with Custom Characters
Create multiple frames of a simple animation (e.g., a spinning loading icon) as custom characters 0-7. In loop(), cycle through them with a delay to create the illusion of movement. Since you only have 8 slots, keep animations short or swap characters dynamically using createChar() during runtime.

Display Buffering
Direct write vs frame buffer. Managing flicker, partial updates, and rendering performance.
Direct Write
Send each pixel/character directly to the display as you compute it. Simple, low memory usage. But if you clear and redraw, there is a visible flash (flicker) between the clear and the new content. Character LCDs use this approach.
Frame Buffer
Draw everything into a memory buffer first (an array in SRAM), then send the entire buffer to the display at once. No flicker because the old content is replaced in a single transfer. OLED and graphical LCDs use this pattern.
1 Flicker prevention: Instead of lcd.clear() followed by lcd.print(), overwrite specific positions using setCursor() + print(). Pad shorter strings with spaces to erase leftover characters. Never clear the whole screen unless the layout changes.
2 Partial updates: Only redraw the parts of the screen that changed. If a temperature value updates from "23.5" to "24.0", set the cursor to that position and overwrite. Leave static labels untouched. This is the fastest approach.
3 Double buffering: For OLED and TFT, draw everything to the off-screen buffer using clearDisplay(), then push it all at once with display() or sendBuffer(). The old frame stays visible until the new one is fully ready.
4 Update rate: Character LCDs are slow -- updating the full 16x2 display takes several milliseconds. OLED over I2C at 400kHz can push a 128x64 buffer (~1KB) in about 3ms. SPI displays are fastest: full TFT refresh in under 10ms at 40MHz SPI.
The Golden Rule
Never call lcd.clear() inside loop(). It causes visible flicker on every iteration. Instead, overwrite specific character positions. For graphical displays, use the buffer pattern: clear the buffer (not the screen), draw everything, then push the buffer. Your users will see smooth, flicker-free updates.

Multi-Display Systems
Driving multiple displays from one Arduino using I2C addressing and SPI chip select.
I2C Multi-Display
Each I2C device has a unique address. Two SSD1306 OLEDs can coexist at 0x3C and 0x3D (set via solder jumper on the module). Create two display objects, each initialized with a different address. Both share the same SDA/SCL wires.
SPI Chip Select
SPI displays share MOSI, MISO, and SCK lines but each has a unique CS (Chip Select) pin. Pull CS LOW to activate a specific display, HIGH to deactivate it. Three TFTs on one Arduino: share 3 SPI pins + 3 individual CS pins.
Mixed Display Types
Combine a 16x2 I2C LCD for text status with an SSD1306 OLED for graphs. Or use a TFT for the main UI and a character LCD for debugging output. Each display has its own library instance and operates independently.
// Two OLEDs on I2C with different addresses Adafruit_SSD1306 display1(128, 64, &Wire, -1); Adafruit_SSD1306 display2(128, 64, &Wire, -1); void setup() { display1.begin(SSD1306_SWITCHCAPVCC, 0x3C); // OLED #1 display2.begin(SSD1306_SWITCHCAPVCC, 0x3D); // OLED #2 display1.clearDisplay(); display1.setTextSize(1); display1.setTextColor(SSD1306_WHITE); display1.println("Sensor Data"); display1.display(); display2.clearDisplay(); display2.setTextSize(2); display2.setTextColor(SSD1306_WHITE); display2.println("Alerts"); display2.display(); }
Memory Consideration
Each SSD1306 OLED uses ~1KB of SRAM for its frame buffer. Two OLEDs = ~2KB, which exceeds the Uno's total 2KB SRAM. For multi-display setups with graphical screens, use an Arduino Mega (8KB SRAM) or ESP32 (520KB SRAM). Character LCDs have no buffer and work fine on the Uno in multi-display configurations.
