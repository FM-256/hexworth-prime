Digital vs Analog
Binary (HIGH/LOW) vs continuous (0-1023). Two fundamentally different ways to read the world.
Digital Input
Only two states: HIGH (5V) or LOW (0V). Think of a light switch -- it is on or off. digitalRead(pin) returns 1 or 0. Used for buttons, switches, PIR motion sensors, limit switches, and any binary sensor. Pins 0-13 can read digital input. The threshold is roughly 2.5V: above = HIGH, below = LOW.
Analog Input
A continuous range of values from 0 to 1023, representing 0V to 5V. Think of a dimmer knob -- infinite positions between off and full. analogRead(pin) returns a 10-bit value. Used for potentiometers, temperature sensors, light sensors, flex sensors, and anything that produces a variable voltage. Only pins A0-A5 can read analog input.
When to Use Each
Use digital input when the answer is yes/no: Is the button pressed? Is the door open? Is motion detected? Use analog input when you need a measurement: How hot is it? How bright is the room? How far is the knob turned? If you connect a digital sensor to an analog pin, it works but wastes ADC resolution. If you connect an analog sensor to a digital pin, you lose all the nuance -- it snaps to 0 or 1.

Reading a Switch
digitalRead(), INPUT_PULLUP, and wiring a button to the Arduino.
void setup() { pinMode(2, INPUT_PULLUP); // enable internal pull-up resistor Serial.begin(9600); } void loop() { int state = digitalRead(2); if (state == LOW) { // LOW = pressed (pull-up inverts logic) Serial.println("Button pressed"); } delay(50); }
digitalRead(pin)
Returns HIGH (1) or LOW (0). The pin samples voltage at the exact moment you call it. If the pin is connected to 5V, it reads HIGH. If connected to GND, it reads LOW. If connected to nothing? It floats -- random noise gives unpredictable readings.
INPUT_PULLUP
Activates a built-in 20k-ohm resistor that pulls the pin to 5V (HIGH) when nothing is connected. Wire the button between the pin and GND. When pressed, the pin reads LOW. No external resistor needed. This is the standard Arduino button wiring.
Floating Pins
A pin set to INPUT with nothing connected floats between HIGH and LOW, picking up electromagnetic noise. The LED flickers randomly. Always use INPUT_PULLUP or wire an external pull-down resistor (10k to GND). Never leave an input pin floating.
Wiring a Button
With INPUT_PULLUP: one leg to the digital pin, the other leg to GND. Two wires, no resistor. The internal pull-up holds the pin HIGH when the button is open. Pressing the button connects the pin directly to GND, overriding the pull-up. Logic is inverted: LOW = pressed, HIGH = released.

Debouncing
Why switches bounce, and how to filter it in software.
You press the button once but the Serial Monitor prints "pressed" five times. The metal contacts inside the switch bounce for a few milliseconds before settling -- the Arduino reads each bounce as a separate press.
// millis()-based debounce const int BTN = 2; int lastState = HIGH; int currentState; unsigned long lastDebounceTime = 0; const unsigned long DEBOUNCE_DELAY = 50; // ms void loop() { int reading = digitalRead(BTN); if (reading != lastState) { lastDebounceTime = millis(); } if ((millis() - lastDebounceTime) > DEBOUNCE_DELAY) { if (reading != currentState) { currentState = reading; if (currentState == LOW) { Serial.println("Confirmed press"); } } } lastState = reading; }
Why Switches Bounce
Mechanical switches have metal contacts that physically vibrate when pressed. For 1-10ms, the signal oscillates between HIGH and LOW before settling. The Arduino samples in microseconds -- it sees every bounce as a distinct state change. This is not a software bug; it is a hardware reality.
Bounce2 Library
For cleaner code, use the Bounce2 library: #include <Bounce2.h>. Create a Bounce object, attach it to a pin, call update() in loop, then check fell() for press detection. Handles all timing internally. Recommended for production projects.
Never Use delay() for Debouncing
delay(50) after a read technically works for debounce, but it blocks the entire program for 50ms on every loop iteration. That means the Arduino cannot read other sensors, update LEDs, or respond to serial during the delay. Use the millis()-based approach above -- it is non-blocking and allows your loop to keep running at full speed.

How Long Was It Pressed?
Measuring press duration. Short press vs long press. Timed interactions.
unsigned long pressStart = 0; bool wasPressed = false; void loop() { int reading = digitalRead(2); if (reading == LOW && !wasPressed) { pressStart = millis(); // record press start time wasPressed = true; } if (reading == HIGH && wasPressed) { unsigned long duration = millis() - pressStart; wasPressed = false; if (duration > 1000) { Serial.println("LONG press"); } else { Serial.println("Short press"); } } }
Capture the Moment
Record millis() when the button goes LOW (pressed). Record again when it goes HIGH (released). The difference is the press duration in milliseconds. This is the same technique used in every phone, game controller, and TV remote.
Long-Press Detection
Threshold at 1000ms (1 second) separates short press from long press. Short press: toggle LED. Long press: reset system, enter configuration mode, or trigger a different action. Multiple thresholds enable double-long press, triple-tap, and more.
Real-World Applications
Smart home buttons (short = lights, long = all off). Game controllers (tap to jump, hold to charge). Industrial safety (press and hold 3 seconds to engage machinery). One button, multiple functions based on timing.
Slide 6 of 12
Reading a Keypad
Matrix scanning: 16 keys using only 8 pins. The Keypad library makes it simple.
Matrix Scanning
A 4x4 keypad has 16 keys but only 8 connections: 4 row wires and 4 column wires. The Arduino sets each row LOW one at a time and reads the columns. If a column reads LOW, the key at that row-column intersection is pressed. One full scan takes microseconds.
Keypad Library
Install the Keypad library by Mark Stanley. Define a key map (char array), row pins, column pins. Call keypad.getKey() in loop -- it returns the character of the pressed key or NO_KEY if nothing is pressed. Handles scanning and debouncing internally.
Use Case
Door locks, security panels, menu navigation, calculator projects, password entry. The membrane keypad costs about $2 and uses 8 pins. For fewer pins, add a resistor ladder and read the keypad as a single analog value on one pin -- but the Keypad library approach is more reliable.

Reading Analog Values
analogRead(), 10-bit ADC, and how the Arduino converts voltage to a number.
void setup() { Serial.begin(9600); } void loop() { int raw = analogRead(A0); // 0-1023 float voltage = raw * (5.0 / 1023.0); // convert to volts Serial.print("Raw: "); Serial.print(raw); Serial.print(" Voltage: "); Serial.println(voltage, 3); delay(200); }
10-Bit ADC
The ATmega328P has a 10-bit analog-to-digital converter (ADC). 10 bits = 2^10 = 1024 steps. The range 0-1023 maps to 0V-5V. Each step represents 5V / 1024 = 4.88mV. An analogRead() call takes about 100 microseconds (10,000 reads per second max).
Reference Voltage
By default, the ADC uses the 5V supply as its reference. analogReference(INTERNAL) switches to the internal 1.1V reference for higher resolution on small signals (1.1V / 1024 = 1.07mV per step). analogReference(EXTERNAL) uses whatever voltage you apply to the AREF pin.
No Setup Needed
Unlike digital pins, analog pins do not need pinMode(). They default to input. Just call analogRead(A0) directly. The pins are labeled A0-A5 on the board. You can also use them as digital pins (14-19) if you run out of digital pins.
Common Sensors
Potentiometer (variable resistor, outputs 0-5V), TMP36 temperature sensor (10mV per degree C), LDR/photoresistor in a voltage divider (light level), force-sensitive resistor (pressure), flex sensor (bending), and soil moisture probe. All produce a variable voltage that analogRead() converts to a number.

Mapping Values
map() scales readings from one range to another. constrain() keeps them safe.
map() -- Scale to New Range
int raw = analogRead(A0); // 0-1023 // Map to percentage (0-100) int pct = map(raw, 0, 1023, 0, 100); // Map to PWM range (0-255) int pwm = map(raw, 0, 1023, 0, 255); analogWrite(9, pwm); // Map to servo angle (0-180) int angle = map(raw, 0, 1023, 0, 180);
constrain() -- Safety Clamp
// Sensor reads 200-800 in practice, // not the full 0-1023 int raw = analogRead(A0); // Clamp to expected range first raw = constrain(raw, 200, 800); // Then map to output range int pct = map(raw, 200, 800, 0, 100); // Result: 0-100 with no overshoot
map(value, fromLow, fromHigh, toLow, toHigh)
Linear interpolation. Scales a number from one range to another. Uses integer math -- no floats, no rounding. Works with negative ranges too. Does NOT clamp: if value is outside fromLow-fromHigh, the output will be outside toLow-toHigh.
constrain(value, min, max)
Clamps a value to a range. If value is below min, returns min. If above max, returns max. Otherwise returns value unchanged. Always constrain before mapping if your sensor does not use the full 0-1023 range. Prevents unexpected negative numbers or overflow.
Pro Tip
Real sensors rarely use the full 0-1023 range. A potentiometer might read 3-1020. A light sensor might range 50-900. Measure your actual min and max, then use those as the fromLow and fromHigh in map(). This gives you the full output range from your actual sensor range, not the theoretical one.

Multiple Analog Inputs
Reading 6 channels (A0-A5). Multiplexing for more. Managing multiple sensors.
// Read all 6 analog channels and log as CSV void loop() { Serial.print(millis()); for (int ch = 0; ch < 6; ch++) { Serial.print(","); Serial.print(analogRead(A0 + ch)); } Serial.println(); delay(500); } // Output: 15230,512,380,720,1,1023,445
6 Built-In Channels
The Uno has 6 analog input pins: A0-A5. The single ADC multiplexes between them -- it reads one channel at a time, switching internally. Reading all 6 takes about 600 microseconds. The Mega has 16 analog inputs (A0-A15).
Analog Multiplexer (CD4051)
Need more than 6 analog inputs? Use a CD4051 8-channel multiplexer. It routes one of 8 input lines to a single output line using 3 digital select pins. One multiplexer gives you 8 channels on one analog pin. Cascade two for 16 channels.
ADC Crosstalk
Switching channels fast can cause crosstalk -- residual charge from the previous channel bleeds into the new reading. Fix: read the channel twice and discard the first reading, or add a small delay between channel switches. High-impedance sensors are more susceptible.
Design Pattern
Store readings in an array: int sensors[6]; for (int i = 0; i < 6; i++) sensors[i] = analogRead(A0 + i);. This makes it easy to loop through sensors, apply thresholds, calculate averages, or find the min/max. Arrays turn repetitive sensor code into clean, scalable logic.

Voltage Measurement
Voltage dividers for voltages above 5V. Measuring battery level safely.
Voltage Divider
Two resistors in series between the measured voltage and GND. The Arduino reads the voltage at the junction between them. By choosing R1 and R2 correctly, you scale any input voltage down to the 0-5V range the ADC can safely read. Formula: Vout = Vin * R2 / (R1 + R2).
Battery Monitoring
For a 12V battery with R1=10k and R2=3.3k: max Vout = 12 * 3.3 / 13.3 = 2.98V. Safe. The ADC reading at full charge: 2.98 / 5 * 1023 = 610. Map this back to voltage: float vBat = analogRead(A0) * (12.0 / 610.0);
Safety Warning
Never connect more than 5V directly to an Arduino analog pin. Voltages above 5.5V will damage the ATmega328P permanently. Always use a voltage divider when measuring batteries, power supplies, or any source above 5V. Double-check your resistor math before connecting.

Responding to Changes
Threshold detection, change detection, and hysteresis for stable behavior.
Threshold Detection
Set a threshold value: if (analogRead(A0) > 500) { alarm(); }. When the sensor crosses the line, the action fires. Simple, but problematic when the reading hovers around the threshold -- the output flickers on and off rapidly.
Change Detection
Only react when the value changes significantly: if (abs(current - previous) > 10) { update(); previous = current; }. The deadband (10) filters out noise. Useful for knobs and sliders where you want to send updates only when the user actually moves the control.
Hysteresis
Two thresholds instead of one: turn ON above 600, turn OFF below 400. The gap (200) prevents rapid on/off cycling. if (val > 600) state = ON; if (val < 400) state = OFF;. Between 400-600, the state does not change. This is how thermostats work.
// Hysteresis example -- stable threshold switching const int THRESHOLD_HIGH = 600; const int THRESHOLD_LOW = 400; bool alarmOn = false; void loop() { int val = analogRead(A0); if (!alarmOn && val > THRESHOLD_HIGH) { alarmOn = true; Serial.println("ALARM ON"); digitalWrite(13, HIGH); } if (alarmOn && val < THRESHOLD_LOW) { alarmOn = false; Serial.println("ALARM OFF"); digitalWrite(13, LOW); } delay(100); }
Why Hysteresis Matters
Without hysteresis, a noisy sensor reading near 500 flips the output dozens of times per second. A relay clicking on and off rapidly damages equipment. An LED flickering looks broken. Hysteresis adds stability by requiring a clear, decisive transition past a dead zone before changing state.

Key Takeaways
Digital and analog input are the foundation of every interactive Arduino project.
1Digital = binary, Analog = continuous. digitalRead() returns HIGH or LOW (5V or 0V). analogRead() returns 0-1023, mapping 0V-5V through a 10-bit ADC. Use digital for buttons and switches, analog for sensors that produce variable voltage.
2Always handle floating pins. Use INPUT_PULLUP for buttons (no external resistor needed). Wire button between pin and GND. Logic is inverted: LOW = pressed. Never leave an input pin unconnected without a pull-up or pull-down.
3Debounce every button. Mechanical switches bounce for 1-10ms. Use millis()-based debouncing, not delay(). The Bounce2 library is the clean production solution. Without debouncing, one press registers as multiple presses.
4map() and constrain() are essential. Map scales readings from one range to another (ADC to percentage, PWM, servo angle). Constrain clamps values to prevent overflow. Always constrain before mapping when your sensor does not use the full 0-1023 range.
5Use hysteresis for stable thresholds. Two thresholds (high to activate, low to deactivate) prevent rapid flickering when a sensor reading hovers near a single threshold. This is how thermostats, light sensors, and industrial controls work in the real world.
