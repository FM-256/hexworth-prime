Wireless Communication
433MHz  |  XBee  |  ZigBee  |  Bluetooth Classic  |  BLE
Wires limit your project to a table. Wireless communication breaks the tether -- your Arduino can now talk to other devices across a room, a building, or a field. Each technology trades range, power, data rate, and cost differently. Choosing the right one is an engineering decision, not a preference.

Wireless Overview: The Tradeoff Triangle
Every wireless technology balances three variables: range, power consumption, and data rate. You cannot maximize all three.
License-Free Bands
ISM bands (315MHz, 433MHz, 868MHz, 915MHz, 2.4GHz) are free to use without a radio license. Most Arduino wireless modules operate in these bands. Regulations limit transmit power to keep interference low.
Modulation Matters
ASK (on/off keying) is cheap but noisy. FSK shifts frequency for better noise immunity. Spread spectrum (used by WiFi, Bluetooth) hops across frequencies, resisting interference and enabling higher data rates.
Antenna Design
A coil of wire, a PCB trace, or a ceramic chip -- the antenna determines real-world range more than the radio chip. Orientation, obstacles, and frequency all affect propagation. Higher frequencies travel shorter distances but carry more data.
Key Insight
WiFi gives high data rates but drains batteries in hours. BLE sips power but sends tiny packets. 433MHz reaches kilometers but moves data at walking speed. There is no universal wireless solution -- only the right tool for the right job.

433MHz Modules: Cheap Radio Links
The simplest wireless option: a transmitter and receiver pair for under $2. Perfect for one-way sensor data over short to medium range.
// Transmitter side -- VirtualWire library #include <VirtualWire.h> void setup() { vw_setup(2000); // 2000 bits/sec vw_set_tx_pin(12); // Data pin } void loop() { const char *msg = "TEMP:23.5"; vw_send((uint8_t *)msg, strlen(msg)); vw_wait_tx(); // Wait until sent delay(1000); }
ASK Modulation
Amplitude Shift Keying turns the carrier signal on and off to represent 1s and 0s. Simple and cheap, but vulnerable to noise. The VirtualWire library adds error detection and Manchester encoding to improve reliability over raw ASK.
Range & Limitations
Indoors: 20-50 meters. Open air with antenna: up to 200 meters. Data rate maxes out around 2-4 kbps. One-way only per module pair -- you need two pairs for bidirectional communication. No encryption, no addressing, no acknowledgments.

XBee Introduction: Professional Wireless
Digi XBee modules bring reliable, addressable, bidirectional wireless communication to Arduino projects. Two modes: AT (transparent) and API (programmable).
AT Mode (Transparent)
Data sent to the XBee serial port comes out the other XBee's serial port. It works like a wireless serial cable. No framing, no addressing in code -- the module handles everything. Configure with XCTU software or AT commands (+++ to enter command mode).
API Mode (Structured)
Data is wrapped in frames with headers, addresses, and checksums. You can address specific nodes, read signal strength, get delivery confirmations, and send remote AT commands. More complex but far more powerful for multi-node networks.
1 Hardware setup: XBee modules use 3.3V logic. Use an XBee Explorer board or a level shifter between the 5V Arduino and the 3.3V XBee. Direct 5V will damage the module permanently.
2 XCTU configuration: Digi's free XCTU software lets you read/write XBee parameters, update firmware, test range, and monitor traffic. Set the PAN ID (network ID) to the same value on all modules in your network.
3 Serial bridge: In AT mode, Arduino sends data with Serial.print() to the XBee, which transmits it wirelessly. The receiving XBee outputs the data on its serial pins to the second Arduino's Serial.read().
XBee Variants
XBee Series 1 (802.15.4): point-to-point, simple, no mesh. XBee Series 2 (ZigBee): mesh networking, coordinator/router/end device roles. XBee Pro: higher power for longer range (up to 1.6 km line of sight). XBee3: combines ZigBee, 802.15.4, DigiMesh, and BLE in one module.
Slide 5 of 12
ZigBee Mesh: Self-Healing Networks
ZigBee creates mesh networks where messages hop between nodes to reach their destination. If one node dies, the network routes around it automatically.
Coordinator
One per network. Forms the PAN, assigns short addresses, manages routing tables. Must be always on. Cannot sleep.
Router
Relays messages between nodes. Extends network range. Must be mains-powered (no sleep). The more routers, the more redundant paths exist.
End Device
Sensors and actuators. Can sleep to save power. Talks only to its parent router. Lowest power consumption of any role.
Self-Healing
If Router A fails, messages automatically reroute through Router B or C. The network discovers new paths without any code changes. This is why ZigBee is used in industrial automation, smart home systems (Philips Hue, SmartThings), and environmental monitoring.
Slide 6 of 12
XBee API Mode: Structured Frames
API mode wraps every transmission in a frame with a start delimiter, length, type, payload, and checksum. Full control over addressing and delivery status.
// XBee API frame structure // [Start] [Length MSB] [Length LSB] [Frame Type] [Frame Data...] [Checksum] // 0x7E 0x00 0x0A 0x01 [payload] 0xXX // Example: TX Request frame (type 0x01) byte frame[] = { 0x7E, // Start delimiter 0x00, 0x0A, // Length (10 bytes) 0x01, // Frame type: TX Request (16-bit addr) 0x01, // Frame ID (for ACK tracking) 0x00, 0x02, // Destination address (node 2) 0x00, // Options 'H', 'E', 'L', 'L', 'O', // Data payload 0xXX // Checksum (0xFF - sum of bytes after length) };
Remote AT Commands
From the coordinator, you can read or change settings on any remote XBee in the network -- read signal strength, change power level, toggle a DIO pin. This enables remote management of sensor nodes without physical access.
Delivery Confirmation
Every TX request generates a TX Status response frame. Frame ID links request to response. Status code tells you if delivery succeeded, failed (no ACK), or the destination was unreachable. Essential for reliable sensor networks.
Library Support
The xbee-arduino library by Andrew Rapp abstracts frame construction and parsing. You create request objects, send them, and receive typed response objects instead of manually building byte arrays. This is the recommended approach for API mode projects.

Bluetooth Classic: HC-05 / HC-06
Serial Port Profile (SPP) over Bluetooth. Pair once, then it works like a wireless serial cable. Range: 10 meters. Data rate: up to 2 Mbps theoretical.
// Arduino to HC-05 via SoftwareSerial #include <SoftwareSerial.h> SoftwareSerial BT(2, 3); // RX=2, TX=3 void setup() { Serial.begin(9600); BT.begin(9600); // HC-05 default baud } void loop() { if (BT.available()) { char c = BT.read(); Serial.print(c); // Echo BT data to Serial Monitor } if (Serial.available()) { BT.write(Serial.read()); // Send Serial data to BT } }
HC-05 (Master/Slave)
Can initiate or accept connections. Configurable via AT commands (enter AT mode by holding the button during power-on). Set name, PIN, baud rate, role. Can connect to other HC-05 modules or phones.
HC-06 (Slave Only)
Can only accept incoming connections. Simpler, cheaper. Fewer AT commands. Good for phone-to-Arduino projects where the phone always initiates the connection. Default PIN: 1234.
Pairing Process
Power on HC-05 -- LED blinks rapidly (discoverable). Phone finds "HC-05" in Bluetooth settings. Enter PIN (default 1234). LED blinks slowly (paired). Now Serial data flows wirelessly between phone app and Arduino.

BLE Concepts: Low Energy, Big Impact
Bluetooth Low Energy (BLE 4.0+) is a completely different protocol from Bluetooth Classic. Designed for coin-cell batteries and tiny data packets.
GATT
Generic Attribute Profile. Defines how BLE devices exchange data using services and characteristics. The backbone of all BLE communication.
Service
A collection of related data. Each service has a UUID. Example: "Environmental Sensing" service (UUID 0x181A) contains temperature and humidity characteristics.
Characteristic
A single data point within a service. Has a UUID, a value, and properties (read, write, notify). Example: "Temperature" characteristic holds 23.5 degrees as a 16-bit integer.
Advertising
BLE devices broadcast advertising packets every 20ms to 10s. These packets contain the device name, available services, and TX power. No connection needed to see them -- passive scanning works.
Notifications
Server pushes data to client without the client asking. Far more efficient than polling. Client subscribes to a characteristic, and the server sends updates when values change.
Low Power
BLE transmits in short bursts (microseconds) then sleeps. A coin cell (CR2032) can power a BLE sensor for months or years. Classic Bluetooth would drain it in hours.
BLE vs Classic Bluetooth
Classic Bluetooth streams continuous data (audio, serial). BLE sends small packets infrequently (sensor readings, button presses). They are not compatible -- a Classic-only device cannot talk to a BLE-only device. Modern phones support both.

BLE with HM-10: Phone to Arduino
The HM-10 module adds BLE 4.0 to any Arduino via serial. Configure with AT commands, connect with phone apps like nRF Connect or LightBlue.
// HM-10 BLE module -- AT command examples // Send these via Serial at 9600 baud AT // Test -- responds "OK" AT+NAMEMySensor // Set device name AT+UUID0xFFE0 // Set service UUID AT+CHAR0xFFE1 // Set characteristic UUID AT+ROLE0 // Peripheral mode (default) AT+NOTI1 // Enable connection notifications
1 Wire HM-10 to Arduino: VCC to 3.3V (or 5V if module has regulator), GND to GND, TXD to Arduino RX pin (e.g., pin 2 via SoftwareSerial), RXD to Arduino TX pin (e.g., pin 3).
2 Send AT commands: Power on, open Serial Monitor at 9600 baud, type AT -- expect OK response. Set name and other parameters as needed.
3 Connect from phone: Open nRF Connect app, scan for your device name, tap Connect. The HM-10 LED goes solid (connected). Now any data written to the characteristic appears on Arduino's serial port and vice versa.
4 Notifications: Enable notify on the FFE1 characteristic from the phone app. Arduino sends data with BT.print("23.5"), and the phone receives it instantly without polling.
HM-10 Clones Warning
Many cheap HM-10 modules are clones using the CC2541 chip with non-standard firmware. They may not support all AT commands or behave differently. Genuine JNHuaMao (JDY) modules are recommended. Always test AT commands before deploying.

Wireless Security: Invisible Threats
Radio signals do not stop at walls. Anyone within range can listen, inject, or replay your wireless traffic unless you actively defend against it.
Sniffing
433MHz modules transmit in plaintext. Anyone with a $5 RTL-SDR dongle can capture and decode every message. Bluetooth can be sniffed with tools like Ubertooth One. Even encrypted protocols leak metadata (timing, packet sizes, who is talking to whom).
Replay Attacks
An attacker records a valid "unlock door" command and replays it later. Without timestamps, nonces, or rolling codes, the receiver cannot distinguish a replay from a legitimate command. This is how $30 devices clone garage door remotes.
Encryption
ZigBee uses 128-bit AES encryption at the network layer. BLE 4.2+ supports LE Secure Connections with ECDH key exchange. 433MHz has no built-in encryption -- you must encrypt payloads in your Arduino code (AES library) before transmitting.
Pairing Security
Bluetooth Classic pairing with a fixed PIN (1234) is trivially broken. BLE "Just Works" pairing has no MITM protection. Passkey or OOB (Out of Band) pairing provides better security. For critical applications, mutual authentication is essential.
Security Mindset
If your wireless project controls physical things -- locks, motors, valves, heaters -- security is not optional. Assume every packet is observed. Add encryption, timestamps, and sequence numbers. Validate everything on the receiving end. A compromised wireless channel means a compromised physical system.

Choosing Wireless Tech: Decision Matrix
Match the technology to the requirements. No single wireless standard wins everywhere.
433MHz
Best for: one-way sensor data, long range, lowest cost. Worst for: bidirectional, security, multi-node. Cost: under $2/pair.
XBee / ZigBee
Best for: mesh networks, industrial sensors, reliable delivery. Worst for: high data rate, cost-sensitive projects. Cost: $25-40 per module.
Bluetooth Classic
Best for: phone-to-Arduino, audio streaming, serial replacement. Worst for: battery-powered sensors, multi-device. Cost: $3-8 per module.
BLE
Best for: battery sensors, phone apps, iBeacons, wearables. Worst for: large data transfer, continuous streaming. Cost: $3-10 per module.
nRF24L01
Best for: Arduino-to-Arduino, low latency, 2.4GHz, up to 2Mbps. Worst for: phone connectivity. Cost: $1-3 per module. Popular in drones and RC.
LoRa
Best for: extreme range (2-15 km), low power, IoT. Worst for: data rate (under 50 kbps), latency. Cost: $8-15 per module. Used in agriculture and city-scale monitoring.
Decision Checklist
Ask five questions: (1) How far does the signal need to travel? (2) How much data per second? (3) Battery-powered or mains-powered? (4) How many nodes? (5) Does it need to talk to a phone? The answers eliminate most options and leave one or two clear winners.

Key Takeaways: Wireless Mastery
You now understand the wireless landscape from cheap 433MHz links to full ZigBee mesh networks. Choose wisely.
1433MHz modules are the cheapest wireless option -- a TX/RX pair costs under $2. They use ASK modulation, the VirtualWire library, and are best for one-way sensor data over short to medium range. No encryption, no addressing, no acknowledgments.
2XBee modules offer professional-grade wireless with AT mode (transparent serial) and API mode (structured frames with addressing and delivery confirmation). ZigBee firmware enables self-healing mesh networks with coordinator, router, and end device roles.
3Bluetooth Classic (HC-05/06) replaces serial cables with SPP profile. Pair via PIN, then Serial.print() flows wirelessly to a phone or another Arduino. Range: 10m. HC-05 can be master or slave; HC-06 is slave only.
4BLE is a separate protocol from Classic Bluetooth. It uses GATT with services and characteristics, advertises presence, supports notifications, and runs on coin-cell batteries for months. The HM-10 module adds BLE to any Arduino via AT commands.
5Wireless security is not optional for physical systems. 433MHz is plaintext. Bluetooth pairing with "1234" is trivially broken. ZigBee uses AES-128. Always encrypt payloads, add timestamps, and validate on the receiving end. A compromised radio channel means a compromised system.
