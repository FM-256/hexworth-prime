Every remote control in your home sends invisible light pulses -- infrared signals modulated at 38kHz, encoding button presses into timed bursts. With an Arduino, a $2 receiver, and an IR LED, you can decode those signals, clone them, and build your own universal remote. This is where physical computing meets consumer electronics.

Infrared Communication
Invisible light, visible results. IR sits just below the red end of the visible spectrum at 940nm wavelength.
What is IR?
Infrared light at 940nm wavelength -- invisible to human eyes but detectable by silicon photodiodes. It travels in a straight line, cannot pass through walls, and has a typical range of 5-10 meters indoors. Every TV remote uses it.
38kHz Carrier
The IR LED does not just turn on and off. It blinks at 38,000 times per second (38kHz). This carrier frequency lets the receiver filter out ambient light from sunlight and lamps. Without the carrier, IR communication would be unreliable indoors.
Modulation
Data is encoded by switching the 38kHz carrier on and off in specific timing patterns. A "mark" is carrier ON (burst of pulses). A "space" is carrier OFF (silence). The duration of marks and spaces encodes the bits -- 1s and 0s.
Line of Sight
IR requires a clear path between emitter and receiver. It bounces off walls and ceilings (which is why you can sometimes aim a remote at a wall), but it cannot penetrate solid objects. This is both a limitation and a security feature -- your remote will not accidentally control your neighbor's TV.

IR Receiver: TSOP38238
A 3-pin sensor that demodulates the 38kHz carrier and outputs clean digital pulses.
// IR Receiver -- decode remote buttons #include <IRremote.hpp> const int IR_PIN = 2; void setup() { Serial.begin(9600); IrReceiver.begin(IR_PIN); } void loop() { if (IrReceiver.decode()) { Serial.println(IrReceiver.decodedIRData.decodedRawData, HEX); IrReceiver.resume(); } }
IRremote Library
Install via the Arduino Library Manager (Sketch > Include Library > Manage Libraries > search "IRremote"). The library handles all the 38kHz demodulation timing for you. IrReceiver.decode() returns true when a complete code is received. IrReceiver.resume() resets the receiver to listen for the next code.

IR Protocols
Different manufacturers use different timing patterns. The protocol determines how marks and spaces encode bits.
NEC
Most common. 32-bit codes. 9ms leader pulse + 4.5ms space. Used by Samsung, LG, and most Chinese manufacturers.
Sony (SIRC)
12, 15, or 20-bit codes. 2.4ms leader pulse. Codes are sent 3 times for reliability. Sony TVs and PlayStation.
RC5
Philips protocol. Manchester encoding (bi-phase). 14-bit codes. Toggle bit changes with each button press for repeat detection.
RC6
Philips updated protocol. More efficient than RC5. Used in modern Philips devices and Microsoft MCE remotes.
Raw Timing
When the protocol is unknown, capture raw mark/space microsecond timings. Store the entire timing array and replay it verbatim.
Protocol ID
IRremote auto-detects the protocol. Check decodedIRData.protocol to identify NEC, Sony, RC5, etc.
NEC Encoding Detail
NEC uses pulse-distance encoding: a logical "1" is a 562us mark + 1687us space. A logical "0" is a 562us mark + 562us space. The mark duration is always the same -- only the space duration changes. A full NEC frame takes 67.5ms. The 32 bits contain 8-bit address + 8-bit inverted address + 8-bit command + 8-bit inverted command, providing built-in error checking.
Slide 5 of 12
IR Transmitter
An IR LED on pin 3, a resistor, and the IRremote library. You are now the remote.
// Send an NEC code -- clone a remote button #include <IRremote.hpp> const int IR_SEND_PIN = 3; void setup() { IrSender.begin(IR_SEND_PIN); } void loop() { IrSender.sendNEC(0x00, 0x45, 0); // address, command, repeats delay(2000); }
Pin 3 Required
The IRremote library uses hardware PWM on pin 3 (Uno) to generate the precise 38kHz carrier wave. Software PWM is not accurate enough for reliable IR transmission. Do not use other pins unless you check the library docs for your board.
Cloning a Remote
Step 1: Use the receiver to decode the hex code from a real remote. Step 2: Note the protocol (NEC, Sony, etc.) and the hex value. Step 3: Use the transmitter to send that same code. You have cloned the button. Repeat for every button you want.

Imitating Remotes
Record, store, and replay. Build a universal remote from decoded signals.
1 Record phase: Point each remote at your TSOP38238 receiver. Press each button and log the protocol type, address, command, and raw timing data to Serial Monitor. Save the output.
2 Store phase: Create arrays or structs in your sketch mapping button names to their IR codes. For example: tvPower = {NEC, 0x00, 0x45}, tvVolUp = {NEC, 0x00, 0x46}. Store raw timing arrays for unknown protocols.
3 Replay phase: Wire physical buttons to Arduino digital pins. When a button is pressed, transmit the corresponding IR code through the IR LED. Each button on your Arduino project maps to a function on the target device.
4 Multi-device: Store codes from multiple remotes (TV, sound bar, projector). Use a mode switch to select the target device. One Arduino replaces every remote on your coffee table.
// Raw timing replay for unknown protocols uint16_t rawData[] = { 9000, 4500, // leader pulse 560, 560, // bit 0 560, 1690, // bit 1 560, 560, // bit 0 // ... full timing array }; IrSender.sendRaw(rawData, sizeof(rawData)/sizeof(rawData[0]), 38);
Universal Remote Concept
Commercial universal remotes work the same way -- they ship with a database of thousands of IR codes. When you "program" the remote by entering a device code, you are selecting which set of stored IR codes to use. Your Arduino can do the same thing, but you build the database yourself by recording from your actual remotes.

Controlling AC Devices
Combining IR decoding with relay modules to control real-world appliances safely.
Relay Modules
A relay is an electrically operated switch. The Arduino sends a 5V signal to the relay coil, which mechanically closes a contact that can carry mains AC power (120V/240V). The relay provides galvanic isolation between the low-voltage Arduino circuit and the high-voltage AC circuit.
Safety Warning
Mains AC voltage (120V/240V) is lethal. Never work with AC wiring while it is plugged in. Use pre-built relay modules with proper insulation. If you are not comfortable with mains wiring, use the relay to control low-voltage DC devices instead. Safety is not optional.
// IR-controlled relay: press remote button to toggle lamp const int RELAY_PIN = 7; bool lampOn = false; void loop() { if (IrReceiver.decode()) { if (IrReceiver.decodedIRData.command == 0x45) { lampOn = !lampOn; digitalWrite(RELAY_PIN, lampOn ? HIGH : LOW); } IrReceiver.resume(); } }

RF Communication
433MHz radio modules -- no line-of-sight needed, longer range, but less precision than IR.
433MHz Basics
Cheap ($1-2) radio modules operating at 433.92MHz. The transmitter sends On-Off Keying (OOK) modulated signals. No line of sight needed -- RF passes through walls. Range: 20-200m depending on antenna and power.
Simple Protocol
Use the RadioHead or VirtualWire library. Send a byte array from TX to RX. The library handles preamble, sync, and error detection. Basic use: vw_send(msg, len) on TX, vw_get_message(buf, &len) on RX.
Common Uses
Garage door openers, wireless doorbells, weather stations, car key fobs, and home automation switches all use 433MHz. Many off-the-shelf RF outlets can be controlled by sniffing and replaying their codes.
Range vs IR
IR: 5-10m, line of sight, no wall penetration, very low interference. RF 433MHz: 20-200m, penetrates walls and floors, subject to interference from other 433MHz devices. IR is better for in-room device control. RF is better for remote sensors, garage doors, and multi-room communication.

Beyond IR: Modern Alternatives
WiFi, Bluetooth LE, Zigbee, and Z-Wave are replacing IR and simple RF for smart home control.
WiFi (ESP8266/ESP32)
Add an ESP8266 or ESP32 module to your project and control devices over your local network or the internet. Send HTTP requests, use MQTT for home automation, or build a web-based remote control UI. Range: entire network. Latency: 10-100ms.
Bluetooth LE (BLE)
Low-power, short-range wireless. Arduino Nano 33 BLE has it built in. Control devices from a phone app. Range: 10-30m. Power consumption far lower than WiFi. Ideal for wearables and battery-powered remote controls.
Zigbee / Z-Wave
Mesh networking protocols used by smart home devices (Philips Hue, SmartThings). Devices relay messages to extend range. Low power, high reliability. Requires specific radio modules (XBee for Zigbee).
When to Use What
IR: controlling existing consumer electronics (TVs, ACs). 433MHz: simple on/off for cheap devices. WiFi: internet-connected projects, dashboards. BLE: phone-controlled, battery-sensitive. Zigbee: large-scale smart home mesh networks.
The Convergence
Modern smart devices use WiFi or Zigbee, but millions of legacy devices still use IR. The Arduino "IR blaster" pattern -- WiFi receiver that translates network commands into IR codes -- is one of the most popular DIY smart home projects. It bridges old IR devices into modern smart home ecosystems. The Broadlink RM Mini is a commercial version of this exact concept.

Building a Remote System
Arduino as the brain: IR receiver decodes commands, relay controller executes actions.
1 Hardware setup: TSOP38238 on pin 2 (receiver input). Relay module on pin 7. Optional: status LED on pin 13, LCD on I2C for feedback display. Power the relay from a separate 5V supply if controlling multiple relays.
2 Learning mode: On startup, enter "learn mode" where the Arduino captures IR codes from your existing remote. Store each code in EEPROM with a label (power, volume up, channel 1, etc.). Exit learn mode with a long-press on a physical button.
3 Command mapping: Create a lookup table that maps received IR codes to relay actions. Code 0x45 = toggle relay 1. Code 0x46 = toggle relay 2. Code 0x47 = all relays off (panic button). Use switch/case for clean routing.
4 Feedback loop: Blink the status LED when a valid code is received. Display the action name on the LCD. Log all received codes to Serial for debugging. Ignore unknown codes gracefully.
5 Debouncing: IR remotes send repeat codes when a button is held down. Implement a minimum interval (250ms) between accepted commands to prevent rapid toggling. The NEC repeat code (0xFFFFFFFF) signals a held button.
EEPROM Persistence
Store learned IR codes in the ATmega's 1KB EEPROM using EEPROM.write() and EEPROM.read(). EEPROM survives power cycles and code uploads. This means your remote system remembers its learned codes even after being unplugged. EEPROM has a 100,000 write-cycle limit per byte, so avoid writing on every loop iteration.

Security Considerations
IR and simple RF are fundamentally insecure. Understanding why matters for building secure systems.
Replay Attacks
Record a valid IR or 433MHz signal with a receiver, then retransmit it later. The target device cannot distinguish between the original remote and the replay. This is why IR-controlled door locks and garage openers with fixed codes are insecure.
Rolling Codes
Modern garage openers and car key fobs use rolling codes (KeeLoq, AUT64). Each button press generates a new code from a synchronized PRNG. The receiver rejects previously used codes. Recording and replaying does not work.
Why IR is Insecure
IR codes are static -- the same button always sends the same code. There is no encryption, no authentication, no nonce. Anyone with a $2 TSOP38238 can record your codes. IR was designed for convenience, not security. It was never meant to protect anything.
Defense Strategies
For your Arduino projects: add a rolling code layer on top of 433MHz (each message includes an incrementing counter that both sides track). Use encryption (AES-128 via Arduino Crypto library). Require two-factor: IR code + physical button press. Or use WiFi with TLS for actual security.
Ethical Considerations
The ability to clone and replay IR/RF signals is a powerful tool. Use it to control your own devices. Do not use it to interfere with devices you do not own. In many jurisdictions, jamming or spoofing RF signals is illegal. Build responsibly.
Real-World Impact
In 2015, researchers demonstrated that many "smart" IoT devices (garage doors, power outlets, alarm systems) used fixed 433MHz codes with zero encryption. A $5 Arduino + RF receiver could record and replay signals to open garage doors from a car driving past. This research led to industry improvements, but millions of vulnerable devices remain deployed. Understanding these weaknesses is the first step to building secure systems.

Key Takeaways: Remote Control Complete
You can now decode, clone, and transmit IR signals -- and understand why RF and WiFi are replacing them.
1IR uses 940nm light modulated at 38kHz. The carrier frequency allows the receiver (TSOP38238) to filter out ambient light. Data is encoded in the timing of marks (carrier on) and spaces (carrier off). Line-of-sight only, 5-10m range.
2Protocols define the encoding. NEC (32-bit, pulse-distance), Sony SIRC (12/15/20-bit, sent 3x), RC5/RC6 (Philips, Manchester encoding). The IRremote library auto-detects protocols and provides sendNEC(), sendSony(), etc.
3Cloning is decode + replay. Receive a code with TSOP38238, note the protocol and hex value, then transmit the same code from an IR LED on pin 3. Raw timing arrays handle unknown protocols. Store learned codes in EEPROM for persistence.
4433MHz RF passes through walls. Simple OOK modulation, 20-200m range, no line of sight required. Use RadioHead library. Good for garage doors, wireless sensors, and multi-room control. More range but more interference than IR.
5IR and fixed-code RF are insecure. Static codes enable replay attacks. Rolling codes (KeeLoq) and encryption (AES) are required for security. Modern alternatives (WiFi + TLS, BLE, Zigbee) provide authenticated, encrypted communication.
