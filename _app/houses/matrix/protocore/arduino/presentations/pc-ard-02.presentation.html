Variables & Data Types
Every piece of data your sketch works with lives in a variable. The type determines how much memory it uses and what values it can hold.
int
16-bit signed integer on AVR, 32-bit on ARM. Range: -32,768 to 32,767 (AVR). Use for counters, pin numbers, loop indices.
float
32-bit floating point. 6-7 decimal digits of precision. Use for temperature readings, voltage calculations. Avoid when possible -- float math is slow on AVR.
long
32-bit signed integer. Range: -2,147,483,648 to 2,147,483,647. Essential for millis() timestamps which overflow int after ~32 seconds.
byte
8-bit unsigned. Range: 0 to 255. Perfect for storing single sensor readings, register values, or bit flags. Uses 1 byte of RAM.
boolean
Stores true or false. Uses 1 byte of RAM (not 1 bit). Use for state flags: bool ledOn = false;
char
8-bit signed. Stores a single ASCII character or value -128 to 127. Foundation of C strings. char grade = 'A';
// Declaration and initialization int sensorPin = A0; // analog input pin float temperature = 0.0; // will hold converted reading long lastMillis = 0; // timestamp for millis() byte brightness = 255; // PWM value (0-255) bool isRunning = true; // state flag char initial = 'H'; // single character
Rule of thumb: use the smallest type that fits your data. On an ATmega328P (Arduino Uno), you only have 2 KB of RAM. An int uses 2 bytes, a long uses 4. Wasting memory on oversized types can crash your sketch when the stack collides with the heap.

Strings: String Class vs char[]
Arduino gives you two ways to handle text -- the String object (capital S) for convenience, and C-style char arrays for control and efficiency.
Arduino String Object
String msg = "Hello"; msg += " World"; // concatenation int len = msg.length(); // 11 char c = msg.charAt(0); // 'H' int pos = msg.indexOf("Wo"); // 6 String sub = msg.substring(0,5); // sub = "Hello"
C char Array
char buf[20] = "Hello"; strcat(buf, " World"); // concat int len = strlen(buf); // 11 char c = buf[0]; // 'H' char *pos = strstr(buf, "Wo"); // pos points to "World" // No built-in substring
String Methods
length(), charAt(n), indexOf(str), substring(start, end), toUpperCase(), toLowerCase(), trim(), toInt(), toFloat(). These work like Java/JavaScript string methods.
Memory Warning
The String class uses dynamic memory allocation (heap). Repeated concatenation fragments the heap, eventually crashing your sketch. For long-running programs on AVR, prefer char arrays with snprintf() for formatted output.
When to Use Which
Use String for quick prototyping and Serial output. Use char[] for production code, long-running programs, and when memory is tight. On ESP32/ARM boards with more RAM, String is safer.

Arrays: Collections of Data
Arrays store multiple values of the same type in contiguous memory. Essential for sensor readings, pin lists, and lookup tables.
// Declaration and initialization int readings[10]; // 10 ints, uninitialized int pins[] = {2, 3, 5, 8, 13}; // 5 elements, size inferred float temps[5] = {0.0}; // all 5 initialized to 0.0 // Indexing (0-based) readings[0] = analogRead(A0); // store first reading int val = readings[0]; // retrieve it // Iteration -- read 10 sensor samples for (int i = 0; i < 10; i++) { readings[i] = analogRead(A0); delay(100); }
Array Bounds
C/C++ does NOT check array bounds. Accessing readings[10] in a 10-element array reads garbage memory and can crash your sketch. Always use a constant or sizeof(arr)/sizeof(arr[0]) to track the length.
Sensor Buffer Pattern
Store the last N readings in a circular buffer, then average them to smooth noise: readings[index % BUFFER_SIZE] = newValue; This is one of the most common Arduino patterns for analog sensors.

Conditions: if / else / switch
Decision-making is the core of embedded logic. Your sketch reads inputs and decides what to do next.
if / else if / else
int temp = readSensor(); if (temp > 100) { digitalWrite(ALARM_PIN, HIGH); Serial.println("OVERHEAT"); } else if (temp > 75) { digitalWrite(FAN_PIN, HIGH); } else { digitalWrite(FAN_PIN, LOW); digitalWrite(ALARM_PIN, LOW); }
switch / case
char cmd = Serial.read(); switch (cmd) { case 'F': moveForward(); break; case 'B': moveBackward(); break; case 'S': stop(); break; default: Serial.println("Unknown"); }
Comparison Operators
== equal, != not equal, < less than, > greater than, <= and >=. Common bug: using = (assignment) instead of == (comparison) inside an if statement.
Logical Operators
&& (AND), || (OR), ! (NOT). Combine conditions: if (temp > 50 && humidity < 30). Short-circuit evaluation: if the left side of && is false, the right side is never evaluated.
switch vs if
Use switch when comparing one variable against multiple constant values (menu commands, states). Use if/else for ranges and complex conditions. Always include break; in switch cases -- without it, execution falls through to the next case.

Loops: for, while, do-while
Loops repeat a block of code. The loop() function itself is an infinite while loop -- your internal loops handle specific repetitions.
for Loop
Best for counted iterations. for (int i = 0; i < 10; i++) { ... } -- init, condition, increment in one line. Use for iterating arrays, LED sequences, timed repetitions. The loop variable i is scoped to the for block.
while Loop
Repeats while a condition is true. while (Serial.available() == 0) { ... } -- wait for input. The condition is checked before each iteration. If initially false, the body never executes. Use for waiting on events.
do-while Loop
Executes the body at least once, then checks the condition. do { val = analogRead(A0); } while (val < threshold); -- useful when you need at least one reading before deciding whether to continue.
// Nested loops -- scan a 4x4 button matrix int rows[] = {2, 3, 4, 5}; int cols[] = {6, 7, 8, 9}; for (int r = 0; r < 4; r++) { digitalWrite(rows[r], LOW); for (int c = 0; c < 4; c++) { if (digitalRead(cols[c]) == LOW) { handleKey(r, c); } } digitalWrite(rows[r], HIGH); } // break exits the loop immediately for (int i = 0; i < 100; i++) { if (analogRead(A0) > 900) break; // stop early }

Functions: Modular Code
Functions break your sketch into reusable, testable blocks. Every Arduino sketch already has two: setup() and loop().
// Function with parameters and return value float celsiusToFahrenheit(float celsius) { return (celsius * 1.8) + 32.0; } // Function with no return (void) void blinkLED(int pin, int delayMs) { digitalWrite(pin, HIGH); delay(delayMs); digitalWrite(pin, LOW); delay(delayMs); } // Calling functions void loop() { float tempC = readTemperature(); float tempF = celsiusToFahrenheit(tempC); if (tempF > 100.0) { blinkLED(13, 200); // fast blink = warning } }
Why Modularize
Functions make code readable, reusable, and debuggable. Instead of 200 lines in loop(), break it into readSensors(), processData(), updateOutputs(). Each function does one thing.
Parameters
Parameters are passed by value in C -- the function gets a copy. To modify the original, pass a pointer: void update(int *val) { *val = 42; }. Arduino's analogRead(pin) takes a pin number as its parameter.
Return Types
void returns nothing. int, float, bool, char return a single value. C cannot return arrays -- use pointers or modify arrays passed as parameters. Return type must match the actual returned value.

Variable Scope
Where you declare a variable determines where it can be accessed. Misunderstanding scope is one of the most common Arduino bugs.
Global Scope
// Declared outside any function int ledPin = 13; // visible everywhere long lastTime = 0; // shared across functions bool systemReady = false; void setup() { pinMode(ledPin, OUTPUT); systemReady = true; // modify global } void loop() { if (systemReady) { // read global blinkLED(); } }
Local Scope
void readSensor() { int raw = analogRead(A0); // 'raw' only exists here float volts = raw * 5.0 / 1023.0; Serial.println(volts); } // raw and volts are destroyed // when readSensor() returns for (int i = 0; i < 5; i++) { // 'i' only exists inside // this for block } // i does not exist here
When to Use Global
Pin assignments, configuration constants, state variables shared between setup() and loop(), ISR (interrupt) flags. Keep globals to a minimum -- too many makes debugging harder because any function can change them.
Static Local Variables
static int count = 0; inside a function retains its value between calls but is not visible outside the function. Best of both worlds: persistence without global pollution. Use for call counters and local state machines.

Constants & #define
Named constants make your code self-documenting and protect against accidental changes.
const (preferred)
const int LED_PIN = 13; const int SENSOR_PIN = A0; const float VOLTAGE_REF = 5.0; const int BAUD_RATE = 9600; // Typed, scoped, debuggable // Compiler enforces immutability
#define (preprocessor)
#define LED_PIN 13 #define SENSOR_PIN A0 #define VOLTAGE_REF 5.0 #define BAUD_RATE 9600 // Text replacement before compile // No type checking // No semicolon at the end
const Advantages
Type-safe, respects scope, appears in debugger, follows normal C++ rules. The compiler can optimize const int just as well as #define. Modern best practice: always prefer const.
#define Use Cases
Conditional compilation (#ifdef DEBUG), macro functions, and legacy Arduino libraries that expect #define. Also used for include guards in header files. Not a variable -- it is literal text substitution.
Pin Naming Convention
Name pins by function, not number: const int BUZZER_PIN = 9; not const int PIN_9 = 9;. When you rewire the circuit, change one line instead of hunting through the entire sketch.

Operators: Arithmetic, Logical, Bitwise
Beyond basic math, bitwise operators let you manipulate individual bits -- critical for registers, flags, and hardware control.
Arithmetic
+ - * / % (modulo). Integer division truncates: 5 / 2 = 2, not 2.5. Use 5.0 / 2.0 for float result. Modulo (%) gives the remainder: 7 % 3 = 1.
Bitwise
& AND, | OR, ^ XOR, ~ NOT, << left shift, >> right shift. AND masks bits, OR sets bits, XOR toggles bits. 1 << 3 creates the bitmask 0b00001000.
Combined Assignment
+= -= *= /= %= &= |= ^= <<= >>=. Shorthand: x += 5; means x = x + 5;. Cleaner and sometimes faster.
// Bitwise operations in practice byte flags = 0b00000000; flags |= (1 << 3); // Set bit 3: 0b00001000 flags |= (1 << 5); // Set bit 5: 0b00101000 flags &= ~(1 << 3); // Clear bit 3: 0b00100000 flags ^= (1 << 5); // Toggle bit 5: 0b00000000 bool bit3set = (flags >> 3) & 1; // Read bit 3
Bitwise operators are not academic curiosities on Arduino -- they are essential. Hardware registers like PORTB and DDRB are controlled bit by bit. Setting pin 13 HIGH at the register level: PORTB |= (1 << 5); is significantly faster than digitalWrite(13, HIGH);.

Type Conversion
Converting between types is constant in Arduino work -- sensor readings come in as ints, but you need floats for math and Strings for display.
// Explicit casting int raw = analogRead(A0); // 0-1023 float voltage = (float)raw * 5.0 / 1023.0; // cast to float first // Without cast: raw * 5 / 1023 uses integer math = wrong result // String to int String input = "42"; int value = input.toInt(); // 42 // int to String int count = 255; String s = String(count); // "255" String hex = String(count, HEX); // "ff" String bin = String(count, BIN); // "11111111" // C-style: atoi, itoa char numStr[] = "123"; int num = atoi(numStr); // 123 char buf[10]; itoa(42, buf, 10); // buf = "42" (base 10)
Implicit Conversion Pitfalls
C automatically widens types (int to float) but truncates when narrowing (float to int drops the decimal). int x = 3.7; gives you 3, not 4. Always cast explicitly so your intent is clear.
Float Precision
Arduino's float has only 6-7 digits of precision. float f = 123456.789; may store as 123456.7890625. Never compare floats with ==. Use abs(a - b) < 0.001 instead.

Key Takeaways
Programming Foundations -- the C/C++ building blocks every Arduino sketch depends on.
1Choose the smallest type that fits. byte for 0-255, int for general use, long for millis(), float only when you need decimals. Every byte matters on a 2 KB ATmega328P.
2Prefer char[] over String for production. The String class fragments heap memory on AVR. Use snprintf() and char arrays for long-running sketches.
3Arrays have no bounds checking. Going past the end corrupts memory silently. Always track size with a constant: const int SIZE = 10;.
4Functions = modularity. Break loop() into named functions. Each function should do one thing. Name them by action: readSensor(), updateDisplay(), checkAlarm().
5Bitwise operators control hardware. |= sets bits, &= ~ clears bits, ^= toggles bits. Direct register manipulation with bitwise ops is 10-50x faster than digitalWrite().
