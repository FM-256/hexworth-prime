Module 04 // Week 4

Password Cracking Techniques and Countermeasures

EHE v1 // EC-Council Ethical Hacking Essentials

Passwords remain the most prevalent authentication mechanism in use today, and compromising them is among the most reliable techniques in an attacker's playbook. This module covers the mechanics of how systems store and verify credentials, the authentication frameworks Windows uses, the full spectrum of password attack techniques, the tools that implement them, and the countermeasures organizations can deploy to make credential compromise significantly harder.

40 min reading 6 sections Auth / Cracking / Defense
01 // Authentication Methods

The Three Factors of Authentication

Authentication is the process of verifying that an entity is who it claims to be. All authentication mechanisms fall into one of three categories based on the nature of the evidence they rely upon. These categories are commonly called "factors," and combining multiple factors is the foundational principle behind multi-factor authentication.

🔑
Factor 1
Something You Know
  • Passwords and passphrases
  • PINs
  • Security questions
  • Pattern unlocks
  • Shared secrets
📱
Factor 2
Something You Have
  • Hardware tokens (YubiKey)
  • Smart cards (CAC/PIV)
  • TOTP authenticator apps
  • SMS OTP (less secure)
  • Push notification apps
👁
Factor 3
Something You Are
  • Fingerprint recognition
  • Facial recognition
  • Iris / retinal scan
  • Voice recognition
  • Behavioral biometrics
ℹ Single-Factor vs. Multi-Factor Authentication (MFA): Single-factor authentication (SFA) relies on one factor — almost universally a password — and is easily compromised if that factor is stolen, guessed, or cracked. Multi-factor authentication (MFA) requires two or more factors from different categories. Defeating MFA requires an attacker to compromise multiple, independent credential types simultaneously — dramatically raising the cost of a successful attack. CISA and NIST both mandate MFA for all privileged access.

A fourth category — somewhere you are — is sometimes considered an additional factor, encompassing location-based controls (network segment, geolocation). Context-aware authentication systems may restrict access based on IP address, GPS location, or time of day.

⚠ SMS OTP is Weak MFA: SMS-based one-time passwords are vulnerable to SIM swapping attacks where an attacker convinces a mobile carrier to transfer the victim's number to an attacker-controlled SIM. For high-value accounts, hardware security keys (FIDO2/WebAuthn) or authenticator apps (TOTP) are significantly more resilient.
02 // Password Storage Mechanisms

Hashing, Salting, and Where Credentials Live

Properly implemented systems never store passwords in plaintext. Instead, they store a cryptographic hash — the output of a one-way function that transforms the password into a fixed-length digest. When a user authenticates, the system hashes the provided password and compares it to the stored hash. If they match, authentication succeeds. The original password never needs to be retained.

Hash Examples — Input: "Password123"
MD5 42f749ade7f9e195bf475f37a44cafcb 128-bit
SHA-1 b2e98ad6f6eb8508dd6a14cfa704bad7f05f6fb1 160-bit
SHA-256 ef92b778bafe771e89245b89ecbc08a44a4e166c06659911881f383d4473e94f 256-bit
bcrypt $2b$12$EixZaYVK1fsbw1ZfbX3OXePaWxn96p36WQoeG6Lruj3vjPGga31lW Adaptive

Not all hash algorithms are equal for password storage. MD5 and SHA-1 are fast general-purpose hashing algorithms — exactly the wrong property for password storage, since speed enables high-volume cracking. bcrypt, scrypt, and Argon2 are purpose-built password hashing algorithms designed to be computationally expensive and configurable — as hardware improves, the work factor can be increased to maintain security.

Salting — Defeating Precomputed Attacks

A salt is a random value appended or prepended to a password before hashing. Each user's salt is unique and stored alongside the hash. Salting means that two users with identical passwords will have different hashes — making precomputed rainbow table attacks useless, since the attacker would need to rebuild tables for every possible salt value. Salting is mandatory in any correctly implemented password storage system.

Credential Storage Locations
🪟
Windows SAM
The Security Accounts Manager (SAM) database at C:\Windows\System32\config\SAM stores local account password hashes. It is locked by the OS while running. Hashes are encrypted with the SYSKEY (also called BootKey). Attackers extract SAM using Volume Shadow Copies or by booting to an external OS.
🏢
Windows NTDS.dit
The Active Directory database stored on Domain Controllers at C:\Windows\NTDS\NTDS.dit. Contains password hashes for all domain accounts. This is the highest-value credential store in a Windows environment — compromise of NTDS.dit with the SYSTEM hive gives an attacker every domain credential.
🐧
Linux /etc/shadow
Modern Linux systems store password hashes in /etc/shadow, which is only readable by root. The older /etc/passwd file (world-readable) contained hashes historically — a practice long since abandoned. Shadow entries include the algorithm identifier, salt, and hash in a standardized format.
☁
Cloud / SSO Providers
Modern enterprise environments increasingly rely on identity providers (Azure AD, Okta, Ping Identity) that centralize authentication. Password cracking in these environments shifts toward credential stuffing, token theft (OAuth/SAML token hijacking), and adversary-in-the-middle (AiTM) phishing proxies.
03 // Default Authentication in Windows

Kerberos, NTLM, and LM Hash Weaknesses

Windows environments support multiple authentication protocols, each with different security properties. Understanding these protocols — and their weaknesses — is fundamental to both offensive exploitation and defensive hardening in Windows/Active Directory environments.

Kerberos is the default authentication protocol in Windows Active Directory environments (introduced in Windows 2000). It is a ticket-based, mutual authentication protocol designed to eliminate the need to send passwords over the network. The Key Distribution Center (KDC), hosted on the Domain Controller, issues encrypted tickets that prove identity.

Kerberos Authentication Flow
1 →
AS-REQ (Authentication Service Request)
Client sends username and timestamp encrypted with the user's password-derived key to the KDC's Authentication Service. This requests a Ticket Granting Ticket (TGT).
2 ←
AS-REP (Authentication Service Reply)
KDC verifies credentials and returns a TGT encrypted with the krbtgt account's hash, plus a session key encrypted with the user's hash. The client cannot read the TGT itself.
3 →
TGS-REQ (Ticket Granting Service Request)
Client presents TGT to the KDC's Ticket Granting Service to request a Service Ticket for a specific service (e.g., a file share). This is the target of Kerberoasting attacks.
4 ←
TGS-REP (Service Ticket)
KDC returns a Service Ticket encrypted with the target service account's NTLM hash. In Kerberoasting, attackers request these tickets and crack them offline to obtain service account passwords.
5 →
AP-REQ (Application Request)
Client presents the Service Ticket to the target service. The service decrypts it with its own password hash, verifying the client's identity without contacting the KDC again.
Golden Ticket Attack: If an attacker obtains the krbtgt account's NTLM hash (e.g., via DCSync), they can forge Ticket Granting Tickets for any user in the domain — including non-existent accounts with Domain Admin privileges. These forged "Golden Tickets" persist for 10 years by default and survive password resets of other accounts.

NTLM (NT LAN Manager) is a legacy challenge-response authentication protocol used when Kerberos is unavailable — such as authenticating to IP addresses, cross-forest authentication without trusts, or legacy applications. NTLM v2 is the current version; NTLM v1 is deprecated and deeply insecure.

In NTLM authentication, the server sends a random challenge (nonce) to the client. The client encrypts the challenge using the NTLM hash of the user's password and returns the result. The server (or DC) verifies the response. Critically, the NTLM hash itself is sufficient to authenticate — you do not need the plaintext password. This is the foundation of Pass-the-Hash (PtH) attacks.

NTLM Relay Attacks: Because NTLM includes no server authentication (in its basic form), an attacker can position themselves between a client and server to relay authentication attempts. Tools like Responder capture NTLM hashes from misdirected authentication attempts on local networks, which can then be cracked or relayed directly.

The LAN Manager (LM) hash is an extremely weak legacy password representation from the Windows 9x/NT era. It is disabled by default in Windows Vista and later, but may still be present in older environments or enabled via Group Policy.

Critical LM Hash Weaknesses:
  • Passwords are converted to uppercase before hashing, eliminating case sensitivity and drastically reducing keyspace.
  • The password is padded or truncated to exactly 14 characters, then split into two 7-character halves, each hashed independently with DES. This means a 14-character password is cracked as two 7-character passwords — reducing the attack space enormously.
  • No salt is used, making precomputed rainbow table attacks trivially effective.
  • The DES algorithm used is computationally weak by modern standards.

If LM hashes are still present in the SAM or NTDS.dit, an attacker can crack a complex 14-character password in seconds or minutes using rainbow tables. NTLM hashes are significantly stronger, but still vulnerable to offline brute-force and dictionary attacks, especially for common passwords.

04 // Types of Password Attacks

Dictionary, Brute Force, Rainbow Table, and More

Password attacks are broadly divided into online attacks (attempted against live authentication endpoints) and offline attacks (performed against a captured hash file). Online attacks are constrained by account lockout policies and network latency; offline attacks are limited only by available compute power and the efficiency of the cracking algorithm.

Dictionary Attack
Offline / Online
Tests passwords from a precompiled wordlist (dictionary) of common passwords, leaked credential datasets, and known patterns. Extremely effective because the majority of users choose passwords from a predictable vocabulary. Rockyou.txt (14 million entries) is the canonical starting wordlist.
Effectiveness
85%
Brute Force Attack
Offline / Online
Systematically tests every possible character combination within defined parameters (charset and length). Guaranteed to succeed eventually but impractical for long, complex passwords — a 10-character password with full charset requires trillions of attempts. Used for short PINs or as a final resort after other methods fail.
Effectiveness
40%
Rule-Based Attack
Offline
Applies transformation rules to wordlist entries to generate likely variations. Rules encode common substitution patterns: a→@, e→3, appending years (2024, 2025), capitalizing first letters, adding common suffixes (!, #, 123). Hashcat and John the Ripper both have extensive rule sets. Often more effective than pure brute force at a fraction of the cost.
Effectiveness
92%
Rainbow Table Attack
Offline
Precomputes a massive lookup table mapping hash values back to their plaintext passwords. Cracking becomes a simple table lookup rather than computation. Devastating against unsalted hashes (MD5, SHA-1, LM). Completely defeated by salting — a unique salt per user makes precomputed tables useless. Tables for LM hashes cover virtually all possible passwords.
Effectiveness (unsalted)
99%
Pass-the-Hash (PtH)
Online (Lateral Movement)
Rather than cracking the NTLM hash, the attacker authenticates directly using the hash value itself — since NTLM authentication only requires the hash, not the plaintext. Extracted via Mimikatz from LSASS memory. Enables lateral movement across Windows environments without ever knowing the actual password. Mitigated by Protected Users group and Credential Guard.
Impact
95%
Credential Stuffing
Online
Automated testing of username/password pairs from previously breached datasets against other services, exploiting password reuse. With billions of credentials in public breach databases (Have I Been Pwned), even a 0.1% success rate against millions of accounts yields thousands of valid logins. Target services include banking, email, and corporate VPNs.
Scale Impact
High
LLMNR / NBT-NS Poisoning
Online (Network)
Link-Local Multicast Name Resolution (LLMNR) and NetBIOS Name Service (NBT-NS) are fallback name resolution protocols used when DNS fails. An attacker on the local network responds to these broadcast queries, intercepting NTLM authentication hashes from victims attempting to reach non-existent hosts. Responder automates this attack. Results in NTLMv2 hash capture for offline cracking.
Impact
88%
✦ Online vs. Offline Cracking: Online attacks hit live login pages — limited by lockout policies, CAPTCHA, and rate limiting. Offline attacks work against captured hash files with no such constraints, achieving billions of hash tests per second on modern GPUs. Always prefer offline cracking when hashes are available.
05 // Password Cracking Tools

The Attacker's Toolkit

Modern password cracking tools leverage GPU acceleration to achieve billions of hash computations per second, enabling attacks that would have taken years on CPU-only hardware to complete in hours or days. Understanding these tools is essential for both offensive security work and for defenders designing password policies and hash storage practices.

John the Ripper
Open Source // Openwall
The classic, cross-platform password cracker. Handles hundreds of hash types and supports dictionary, brute force, and rule-based attacks. Particularly well-suited to Unix/Linux hash formats and has extensive built-in rule sets. The "jumbo" community patch adds even broader hash support.
  • Automatic hash format detection
  • Supports Linux shadow, NTLM, MD5, SHA, bcrypt
  • Extensive built-in wordlist mangling rules
  • Incremental (brute force) mode
  • MPI support for distributed cracking
Hashcat
Open Source // GPU-Accelerated
The world's fastest and most advanced password recovery tool. Leverages GPU compute (CUDA/OpenCL) to crack hashes orders of magnitude faster than CPU-based tools. Supports over 350 hash types and seven attack modes. The tool of choice for serious penetration testers and CTF competitors.
  • GPU acceleration: billions of hashes/second
  • Dictionary, combinator, mask, rule, hybrid modes
  • 350+ supported hash algorithms
  • Distributed cracking with multiple GPUs
  • Session save/restore for long attacks
L0phtCrack
Commercial // Windows-Focused
A Windows password auditing tool with a long history (originally released in 1997 by the L0pht hacker collective). Specializes in Windows LM and NTLM hashes, supporting SAM import, SNMP extraction, and network capture. Offers a GUI workflow suited for Windows administrators auditing local and domain password strength.
  • Import from SAM, NTDS.dit, registry
  • Network packet capture for hash extraction
  • Scheduled auditing and reporting
  • Dictionary, brute force, and hybrid attacks
  • LM, NTLM, SHA, MD5 support
Responder
Open Source // Network Poisoning
A Python tool that poisons LLMNR, NBT-NS, and MDNS responses on the local network to capture NTLM authentication hashes. Also runs rogue servers (SMB, HTTP, LDAP, FTP, etc.) to capture credentials from misdirected authentication attempts. A staple of internal penetration testing engagements. Captured NTLMv2 hashes are fed to Hashcat for offline cracking.
  • LLMNR / NBT-NS / MDNS poisoning
  • Multiple rogue server protocols
  • NTLMv1/v2 hash capture
  • Relay mode (via ntlmrelayx)
  • Analyze mode for passive capture
CeWL
Open Source // Wordlist Generator
Custom Word List generator — a Ruby tool that crawls a target website and extracts words to build a customized wordlist for password attacks. Organizations frequently use words from their own website, product names, and industry jargon in passwords. CeWL creates targeted wordlists that dramatically improve cracking rates on organization-specific passwords compared to generic lists.
  • Web crawler with configurable depth
  • Minimum word length filtering
  • Email address extraction mode
  • Metadata extraction from documents
  • Outputs directly to Hashcat/JtR wordlist format
Tool Primary Use Speed Best For
John the Ripper Offline hash cracking CPU (moderate) Unix/Linux hashes, quick analysis
Hashcat Offline hash cracking GPU (very fast) High-volume, professional cracking
L0phtCrack Windows password audit CPU/GPU Windows AD environments, GUI workflow

06 // Password Cracking Countermeasures

Defending the Credential Layer

The countermeasures to password cracking attacks operate at multiple layers: policy, technology, architecture, and user behavior. No single control is sufficient — defense in depth requires combining several of these measures so that the failure of one does not result in a complete credential compromise.

📋
Strong Password Policy
NIST SP 800-63B (2017) revised password guidance: prioritize length (minimum 12–16 characters) over complexity, check against breach databases (HaveIBeenPwned API), avoid forced rotation schedules that encourage predictable patterns like "Summer2025!" incrementing to "Fall2025!"
🔐
Multi-Factor Authentication
MFA is the single most impactful password security control. Even a compromised password cannot be used without the second factor. Implement MFA for all remote access, privileged accounts, and cloud services. FIDO2/WebAuthn hardware keys are the gold standard — resistant to phishing, SIM swap, and replay attacks.
🔒
Account Lockout Policies
Lock accounts after a threshold of failed authentication attempts (typically 5–10). Implement progressive delays or temporary lockouts to slow online attacks. Alert on lockout events and failed authentication spikes — these are indicators of active attacks. Balance lockout aggressiveness against denial-of-service risk from lockout abuse.
🗄
Salted, Modern Hash Algorithms
Use Argon2id (winner of Password Hashing Competition), bcrypt, or scrypt for password storage. Never use MD5, SHA-1, or unsalted SHA-256 for passwords. Enforce unique per-user salts. For Windows environments, ensure LM hash storage is disabled via Group Policy (NoLMHash). Enable Credential Guard to protect LSASS from Mimikatz extraction.
🔑
Password Managers
Password managers (1Password, Bitwarden, LastPass) enable users to maintain unique, cryptographically random passwords for every service without the cognitive burden that leads to reuse and predictable patterns. Eliminate the conditions that make credential stuffing effective. Enterprise password vaults (CyberArk, HashiCorp Vault) extend this to service accounts and secrets.
🛡
Disable LLMNR / NBT-NS
Disable LLMNR via Group Policy (Computer Configuration > Administrative Templates > Network > DNS Client > Turn off multicast name resolution: Enabled) and disable NBT-NS via WINS settings on network adapters. This eliminates the most common Responder attack vector on Windows networks. Deploy DNS suffix search lists to reduce name resolution fallback.
🔮
Protected Users Group
Adding privileged accounts to the Protected Users security group in Active Directory enforces additional protections: no NTLM authentication (Kerberos only), no credential caching, no DES or RC4 encryption, TGT lifetime reduced to 4 hours. This makes pass-the-hash and credential theft significantly harder for high-value accounts.
📡
Breach Password Monitoring
Integrate with breach intelligence databases (HaveIBeenPwned, SpyCloud) to detect when employee passwords appear in public breach datasets. Enforce immediate password resets when credentials are found in breach data. Use the HIBP API to check passwords at account creation and during authentication to block known compromised passwords proactively.
✦ Defense Priority Order: (1) Enable MFA everywhere, (2) Disable LLMNR/NBT-NS on Windows networks, (3) Migrate to modern password hashing with salts, (4) Deploy Credential Guard on Windows endpoints, (5) Add privileged accounts to Protected Users group, (6) Implement breach password screening, (7) Deploy a password manager program. These controls together make credential-based attacks significantly harder and more expensive for attackers.
07 // Key Takeaways

Module Summary

  • Authentication relies on three factors: something you know (passwords/PINs), something you have (tokens/smart cards), and something you are (biometrics). MFA combines multiple factors and is the most impactful single security control for credential protection.
  • Passwords are stored as one-way cryptographic hashes. MD5 and SHA-1 are dangerously fast for password hashing — use bcrypt, scrypt, or Argon2id with unique per-user salts. Salting defeats rainbow table attacks entirely.
  • Windows stores local hashes in the SAM (encrypted with SYSKEY) and domain hashes in NTDS.dit on Domain Controllers. Linux systems store shadow hashes in /etc/shadow, readable only by root.
  • Kerberos is the default Windows AD authentication protocol — ticket-based, mutual authentication. NTLM is the legacy challenge-response protocol used as a fallback. LM hashes are critically weak and should never be stored in modern environments.
  • Password attacks include: dictionary (wordlist testing), brute force (exhaustive search), rule-based (wordlist mutations), rainbow table (precomputed hash lookup, defeated by salts), pass-the-hash (authenticate with hash directly), credential stuffing (breach database replay), and LLMNR/NBT-NS poisoning (network hash capture).
  • John the Ripper and Hashcat are the primary offline cracking tools; Hashcat's GPU acceleration achieves billions of hashes per second. Responder captures NTLM hashes via LLMNR poisoning. CeWL generates targeted wordlists from victim websites.
  • Key countermeasures: enforce MFA, disable LLMNR/NBT-NS, use Argon2id/bcrypt for password storage, enable Windows Credential Guard, add privileged accounts to Protected Users group, screen passwords against breach databases, and deploy password managers.
