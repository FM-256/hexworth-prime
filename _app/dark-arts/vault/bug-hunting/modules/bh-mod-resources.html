🎓 Free Practice Platforms

These platforms provide intentionally vulnerable environments where you can practice exploitation techniques without legal risk. They range from structured academy-style courses to open-ended virtual machines. Start with the most structured option and progress toward less guided environments as your skills develop.

PortSwigger Web Security Academy

This is the single best free resource for learning web application security. Created by the team behind Burp Suite, every lab uses real vulnerability patterns found in production applications. The labs are organized by topic and difficulty, making it possible to focus on a single vulnerability class and progress from apprentice to expert level within that class.

◆
Lab Categories and Bounty Relevance
Which PortSwigger topics map directly to bounty payouts
▼

Not all PortSwigger topics carry equal weight in bug bounty. Prioritize the categories that map to the highest-payout vulnerability classes:

  • High bounty relevance: Server-Side Request Forgery (SSRF), SQL Injection, Authentication vulnerabilities, Access Control, Business Logic, OAuth authentication
  • Medium bounty relevance: Cross-Site Scripting (XSS), Cross-Site Request Forgery (CSRF), XML External Entities (XXE), Server-Side Template Injection (SSTI)
  • Lower bounty relevance (but still valuable): Information disclosure, Clickjacking, DOM-based vulnerabilities, WebSocket vulnerabilities

Complete all labs in the high-relevance categories before touching the others. A researcher who has mastered SSRF and authentication bypass labs will earn more bounties than one who has completed every XSS lab but never studied access control flaws.

OWASP WebGoat and Juice Shop

OWASP maintains two complementary vulnerable applications. WebGoat is a traditional teaching application with guided lessons that explain each vulnerability before asking you to exploit it. Juice Shop is a more realistic modern web application (Angular frontend, REST API, Node.js backend) with 100+ challenges hidden throughout the application, many of which require no hints to discover.

# Running OWASP Juice Shop locally via Docker docker pull bkimminich/juice-shop docker run --rm -p 3000:3000 bkimminich/juice-shop # Access at http://localhost:3000 # Score board hidden at http://localhost:3000/#/score-board # Running OWASP WebGoat locally via Docker docker pull webgoat/webgoat docker run -it -p 127.0.0.1:8080:8080 -p 127.0.0.1:9090:9090 webgoat/webgoat # WebGoat at http://localhost:8080/WebGoat # WebWolf (companion tool) at http://localhost:9090/WebWolf

HackTheBox and TryHackMe

HackTheBox and TryHackMe occupy different positions in the learning pipeline. TryHackMe is better for absolute beginners because its rooms include step-by-step instructions and theory sections before each practical exercise. HackTheBox assumes more prior knowledge and provides less guidance, making it better for intermediate learners who want to develop independent problem-solving skills.

✓
Recommended Progression
Start with TryHackMe's "Introduction to Web Hacking" and "OWASP Top 10" learning paths. Move to PortSwigger Web Security Academy for deep web vulnerability practice. Use Juice Shop for realistic application testing. Graduate to HackTheBox when you can solve PortSwigger labs without hints. PentesterLab fills gaps with focused exercises on specific exploitation techniques.

PentesterLab

PentesterLab takes an exercise-based approach where each lab focuses on a single exploitation technique. The free tier covers fundamental web vulnerabilities, while the Pro subscription adds advanced topics like JWT attacks, deserialization vulnerabilities, and OAuth exploitation. The exercises are shorter and more focused than PortSwigger's, making them useful for targeted practice on specific weaknesses.

Section 02

🤖 AI Security Practice

AI security is the fastest-growing attack surface in the industry, and the practice resources are evolving rapidly. Unlike traditional web security where practice platforms have existed for decades, AI security practice is being invented in real time. The platforms listed here are the current best options, and they teach skills that directly transfer to AI bug bounty programs.

Gandalf by Lakera

Gandalf is the most widely used AI security practice platform. It presents a series of levels where you must extract a secret password from an AI model that has been instructed not to reveal it. Each level adds more sophisticated defenses, creating a progressive difficulty curve that maps directly to real-world AI guardrail bypass techniques.

Level Defense Mechanism Pass Rate Skill Taught
Level 1 No defense — model has the password and will share if asked ~95% Understanding baseline model behavior
Level 2 Basic instruction to not reveal the password ~80% Simple prompt injection framing
Level 3 Instruction reinforcement and basic output filtering ~60% Indirect extraction techniques
Level 4 AI-based output analysis scans responses before delivery ~8% Encoding, obfuscation, and output manipulation
Level 5 Combined input and output filtering ~12% Chained bypass techniques
Level 6 Multi-layer defense with context analysis ~10% Advanced context manipulation
Level 7 Combined strongest defenses ~8% Full defense bypass chains
Level 8 Self-learning adaptive defense Varies Adversarial creativity under adaptive pressure
ℹ
The Level 4 Wall
The drop from ~60% pass rate at Level 3 to ~8% at Level 4 represents the transition from trivial prompt injection to genuine AI security research. Level 4 introduces AI-based output scanning — a second model evaluates the first model's response before it reaches you. Bypassing this requires techniques like character-by-character extraction, encoding schemes, or convincing the model to express the password in a format the output scanner does not recognize. This is where the real learning begins.

Gandalf Agent Breaker

A newer addition to the Gandalf platform, Agent Breaker goes beyond simple password extraction. It presents 10 agentic AI applications — AI systems that can take actions in the world (send emails, query databases, execute code) — and challenges you to make them perform unintended actions. This practice maps directly to the emerging bug class of agentic AI vulnerabilities, where the attack surface extends beyond the model itself to the tools and integrations it controls.

  • 10 different agentic applications with distinct tool access
  • 80M+ data points collected from player interactions
  • Teaches indirect prompt injection (attacking through data the agent reads)
  • Teaches tool abuse (making the agent misuse its own capabilities)
  • Teaches privilege escalation through agent chains

Dreadnode Crucible

Dreadnode Crucible provides AI security challenges that focus on model manipulation and adversarial machine learning. While Gandalf emphasizes prompt injection, Crucible includes challenges around model behavior manipulation, output poisoning, and adversarial input crafting. The platform is more technically demanding and assumes some familiarity with how machine learning models process inputs.

HackAPrompt

HackAPrompt is a competition-format platform that presents a series of prompt injection challenges with specific success criteria. Each challenge provides a system prompt and a goal (typically making the model produce a specific output). The competitive element and leaderboard create motivation to develop increasingly creative bypass techniques. Past competitions have attracted thousands of participants and generated research-grade datasets of prompt injection techniques.

Arcanum AI Security Lab Hub

Created by Jason Haddix's Arcanum Security, the AI Security Lab Hub is the most comprehensive collection of AI security practice resources available under one roof.

23 Labs
Structured exercises covering prompt injection, jailbreaking, model manipulation, and AI application security. Each lab includes objectives, hints, and solution walkthroughs.

Section 03

🏆 CTF Platforms & Competitions

Capture The Flag competitions develop security skills in a competitive format. While CTF challenges are more artificial than real-world bug bounty targets, they build foundational skills — particularly in areas like reverse engineering, cryptography, and binary exploitation — that complement web application security knowledge. More importantly, CTF teams often evolve into bug bounty collaborators.

Major CTF Platforms

CTFtime
Competition Directory
The central directory for CTF competitions worldwide. Lists upcoming events, team rankings, and writeups from past competitions. Register with a team to track your participation and ranking over time. Hundreds of competitions annually across all skill levels.
PicoCTF
Beginner CTF Platform
Created by Carnegie Mellon University, PicoCTF is designed for students and beginners. Challenges are organized by difficulty and category with clear instructions. The annual competition is one of the largest beginner CTFs. Past challenges remain available for practice year-round.
Google CTF
Advanced CTF Competition
Google's annual CTF features challenges created by Google security engineers. Difficulty ranges from intermediate to extremely advanced. The "Beginners Quest" track provides a more accessible entry point. Past challenges and solutions are published for study.
HackTheBox Challenges
Diverse Challenge Categories
Beyond its virtual machine labs, HackTheBox hosts standalone challenges in categories including web, crypto, forensics, reversing, and pwn. Challenges are rated by difficulty and community solves. Retiring challenges get walkthroughs published.

CTF Skills That Transfer to Bug Bounty

Not all CTF categories are equally relevant to bug bounty work. The following mapping shows which CTF skills directly transfer and which develop general security thinking:

CTF Category Bounty Relevance Transfer Mechanism
Web Exploitation Direct Identical vulnerability classes (SQLi, XSS, SSRF, IDOR). CTF web challenges use the same techniques as production bug hunting.
Cryptography High JWT attacks, weak encryption, padding oracle, crypto misuse in APIs. Understanding crypto weaknesses is essential for authentication bypass.
Forensics Moderate Log analysis, traffic capture analysis, data exfiltration patterns. Useful for understanding what defenders see when you test.
Reversing Moderate Mobile app analysis, API key extraction, obfuscated JavaScript analysis. Relevant for mobile and thick-client bounty programs.
Pwn (Binary) Lower Buffer overflows and memory corruption are rare in web bounty programs. Valuable for IoT and embedded device bounties.
Misc/OSINT High Reconnaissance, data correlation, creative problem-solving. OSINT skills directly support the recon phase of bounty methodology.
⚠
CTF Trap
A common trap for new security researchers is spending all their time on CTF competitions and never transitioning to real-world bounty hunting. CTFs are valuable for building skills, but they can become a comfort zone because they provide clear success criteria and immediate feedback. Real bug bounty is messier: targets are complex, success is uncertain, and feedback takes days or weeks. Use CTFs to build skills, but set a deadline for when you will start hunting on real programs.

Reading Strategy
Do not read security books cover to cover. Use them as reference material. This just-in-time learning approach retains better than front-loading theory before you have context to anchor it to.

Essential Wordlists and Payloads

SecLists
Wordlist Collection
The definitive collection of wordlists for security testing. Includes username lists, password lists, directory brute-forcing wordlists, fuzzing payloads, web shells, and more. Every serious hunter has SecLists installed. Used by default in most reconnaissance tool configurations.
PayloadsAllTheThings
Exploitation Payloads
Comprehensive collection of exploitation payloads organized by vulnerability class. Each category includes technique explanations, example payloads, and bypass variations. Covers SQL injection, XSS, SSRF, XXE, SSTI, and dozens more. Your reference during active exploitation.
HackTricks
Methodology Wiki
A massive wiki covering penetration testing and bug bounty methodology. Organized by technique and target type. Includes checklists, cheat sheets, and detailed walkthroughs. Searchable and regularly updated by the community. The closest thing to a complete offensive security encyclopedia.
awesome-bugbounty
Curated Resource List
Community-maintained list of bug bounty resources including tools, writeups, platforms, and methodology guides. A meta-resource that aggregates the best content from across the community. Check periodically for newly added resources.

Setting Up Your Toolkit

A functional bounty hunting toolkit does not require hundreds of tools. Start with a minimal set and add tools only when you encounter a specific need:

Subdomain enumeration go install -v github.com/projectdiscovery/subfinder/v2/cmd/subfinder@latest # 3. HTTP probing — check which subdomains are alive go install -v github.com/projectdiscovery/httpx/cmd/httpx@latest # 4. Directory and file brute-forcing go install -v github.com/ffuf/ffuf/v2@latest # 5. Vulnerability scanning go install -v github.com/projectdiscovery/nuclei/v3/cmd/nuclei@latest # 6. Wordlists git clone https://github.com/danielmiessler/SecLists.git ~/wordlists/SecLists # 7. JavaScript analysis go install -v github.com/tomnomnom/waybackurls@latest # That is enough to start. Add tools as needed, not in advance.
⚠
Tool Hoarding
A common beginner mistake is spending weeks configuring an elaborate toolkit before ever testing a target. This is procrastination disguised as preparation. The tools listed above are sufficient to find bugs. Every additional tool you install before hunting your first real target is a delay, not an investment. Install the minimum, start hunting, and add tools when you hit a specific wall that requires them.

Section 07

📋 Building a Learning Path

With the volume of resources available, the challenge is not finding material but sequencing it effectively. The following progression is based on patterns observed in successful hunters who went from zero to their first bounty payout within a reasonable timeframe.

Recommended Progression

  1. Fundamentals (Weeks 1-4): Complete TryHackMe's "Introduction to Web Hacking" path. Set up Burp Suite Community Edition and learn to intercept, modify, and replay requests. Understand HTTP methods, status codes, cookies, and headers at a practical level.
  2. Web Vulnerabilities (Weeks 5-12): Work through PortSwigger Web Security Academy labs, starting with SQL injection and XSS. Complete at least the Apprentice and Practitioner levels for SSRF, Authentication, and Access Control. Run OWASP Juice Shop locally and solve at least 30 challenges.
  3. First Bug Attempts (Weeks 13-20): Create accounts on HackerOne and Bugcrowd. Read 20+ disclosed reports in your chosen vulnerability class. Pick 3 wide-scope programs and begin systematic reconnaissance. Focus on government VDPs for initial target practice. Expect to find nothing for weeks and treat that as normal.
  4. Specialization (Weeks 21-36): Choose one vulnerability class and go deep. Complete all PortSwigger labs in that class including Expert level. Read every disclosed report you can find in that class. Build custom automation for detecting your specialty. Hunt exclusively for that class across multiple programs.
  5. Advanced Techniques (Months 9-12): Add a second vulnerability class. Begin studying business logic flaws and chained vulnerabilities. Explore AI security practice platforms (Gandalf, Crucible). Start writing public methodology posts. Participate in CTF competitions for cross-training.
  6. Continuous Evolution (Year 2+): Pursue private program invitations. Consider TBHM course for advanced methodology. Begin speaking at BSides events. Mentor newer researchers. Evaluate career path options from the previous module. Never stop hunting while adding adjacent skills.

Time Investment Expectations

Set realistic expectations for time investment at each stage. These estimates assume focused practice time, not passive reading or watching:

Phase Weekly Hours Duration Expected Outcome
Fundamentals 8-12 hours 4 weeks Comfortable intercepting and analyzing HTTP traffic
Web Vulnerabilities 10-15 hours 8 weeks Can identify and exploit common web vulnerabilities in labs
First Bug Attempts 10-20 hours 8 weeks Submitted first reports (may be informative/duplicate)
Specialization 10-15 hours 16 weeks First paid bounty in specialty class
Advanced 10-15 hours 16 weeks Consistent finding rate, multiple paid bounties
Continuous 8-20 hours Ongoing Private program access, sustainable income
⚠
The Year-One Reality
Most successful bounty hunters report that their first year was primarily about learning, not earning. If you approach Year 1 expecting significant income, you will likely quit before the compounding effect of your skill development pays off. Frame Year 1 as an investment in a skill set that will pay returns for a decade or more. The timeline above is aggressive but realistic for someone who shows up consistently.

Tracking Progress

Maintain a simple log of your hunting sessions and learning activities. This does not need to be elaborate — a plain text file or spreadsheet works:

# Example session log format Date: 2026-02-28 Duration: 3 hours Target: example.com (HackerOne public program) Focus: IDOR testing on API endpoints Tools: Burp Suite, ffuf for endpoint discovery Findings: None (tested 14 endpoints, all properly authorized) Learned: This target uses UUID v4 for object IDs, making sequential enumeration impractical. Need to look for IDOR through other vectors (GraphQL, cached responses). Next: Test GraphQL introspection on same target

The "Learned" and "Next" fields are the most valuable. They force you to extract a lesson from every session, even unproductive ones, and create continuity between sessions so you do not waste time re-discovering what you already know.

Setting Goals

Effective goals for bounty hunting are process-based, not outcome-based. You cannot control whether you find a bug, but you can control how many hours you practice, how many labs you complete, and how many programs you enumerate.

Weak Goals (Outcome-Based)

  • ◆ "Find 5 bugs this month"
  • ◆ "Earn $10,000 in Q1"
  • ◆ "Get invited to a private program"
  • ◆ "Find a critical vulnerability"

Strong Goals (Process-Based)

  • ◆ "Hunt for 15 hours per week minimum"
  • ◆ "Complete 10 PortSwigger labs this month"
  • ◆ "Read 5 disclosed reports per week"
  • ◆ "Write one methodology post per month"

The Continuous Learning Mindset

Security is a field where the attack surface changes faster than any individual can track. New frameworks, new deployment patterns, new API standards, new AI integrations — each creates new vulnerability classes. The hunters who sustain long-term success treat learning as a permanent condition, not a phase that ends once they find their first bug.

Allocate at least 20% of your hunting time to learning activities: reading disclosed reports, completing new labs, studying unfamiliar vulnerability classes, and exploring new tools. The remaining 80% goes to active hunting. This ratio ensures that your skills grow even as you earn, preventing the plateau that catches hunters who stop learning once they reach competence.

✓
Start Today
The single most common failure mode in bug bounty is indefinite preparation. Researchers spend months reading about methodology, configuring tools, watching tutorials, and bookmarking resources without ever hunting a real target. If you have completed the earlier modules in this course, you have enough knowledge to start. Pick a wide-scope program, open Burp Suite, and browse the target. Your first real session will teach you more than another week of preparation.
