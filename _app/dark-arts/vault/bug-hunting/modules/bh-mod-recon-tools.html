Section 01

Passive Reconnaissance

Passive recon gathers intelligence without sending a single packet to the target. You are querying third-party databases, search engines, and public records — sources that have already indexed the target's infrastructure. The target has no way to detect passive reconnaissance because you never interact with their systems directly.

Subdomain Enumeration

Subdomain discovery is the foundation of web application recon. Every subdomain is a potential entry point. Tools like subfinder and amass query dozens of passive sources simultaneously — certificate transparency logs, DNS datasets, search engines, and web archives.

subfinder — passive subdomain enumeration
$ subfinder -d target.com -silent www.target.com api.target.com staging.target.com dev.target.com mail.target.com cdn.target.com admin.target.com docs.target.com beta.target.com internal-api.target.com legacy.target.com jenkins.target.com [INF] Found 12 subdomains for target.com in 4.2s
amass — comprehensive OSINT enumeration
$ amass enum -passive -d target.com -o amass-results.txt [*] Querying data sources: AlienVault, BufferOver, CertSpotter, Crtsh, DNSdumpster, HackerTarget, Riddler, Shodan, Spyse, Sublist3r, ThreatCrowd, VirusTotal, Wayback target.com www.target.com api.target.com staging.target.com dev.target.com mail.target.com old.target.com vpn.target.com sso.target.com grafana.target.com prometheus.target.com k8s-dashboard.target.com [+] 15 names discovered - amass-results.txt

Certificate Transparency

Certificate Transparency (CT) logs are a public record of every SSL/TLS certificate issued. When an organization requests a certificate for staging.internal.target.com, that hostname becomes publicly discoverable through CT log search — even if DNS for that host is restricted. This is one of the richest sources for subdomain discovery.

crt.sh query via curl
$ curl -s "https://crt.sh/?q=%25.target.com&output=json" | jq -r '.[].name_value' | sort -u *.target.com api.target.com cdn.target.com dev-api.target.com internal.target.com mail.target.com payments.target.com staging-api.target.com staging.target.com vpn.target.com www.target.com

WHOIS & DNS Intelligence

WHOIS Records
Domain registration data reveals registrar, creation date, name servers, and sometimes registrant contact details. Historical WHOIS (via DomainTools or SecurityTrails) shows ownership changes and previous DNS configurations.
Passive
Reverse DNS
Given an IP address, reverse DNS lookups reveal all hostnames pointing to it. This uncovers shared hosting relationships and internal naming conventions that forward DNS queries would never expose.
Low Noise
Wayback Machine
The Internet Archive's Wayback Machine stores historical snapshots of web pages. Archived pages may contain old endpoints, deprecated APIs, leaked credentials in JavaScript files, and removed functionality that still exists server-side.
Historical
Google Dorking
Advanced search operators extract targeted intelligence from Google's index. site:target.com filetype:pdf finds documents, inurl:admin finds admin panels, intitle:"index of" finds directory listings.

Section 02

Active Reconnaissance

Active recon involves direct interaction with the target — sending packets, probing ports, and requesting resources. This is detectable by the target's security monitoring, so technique selection and scan intensity matter. The goal is thorough coverage without triggering automated defenses that block your IP.

Port Scanning with Nmap

nmap — service version detection
$ nmap -sV --top-ports 1000 -T3 target.com Starting Nmap 7.94 ( https://nmap.org ) PORT STATE SERVICE VERSION 22/tcp open ssh OpenSSH 8.9p1 Ubuntu 80/tcp open http nginx 1.22.1 443/tcp open ssl/http nginx 1.22.1 3000/tcp open http Grafana 8080/tcp open http Jetty 9.4.51 9200/tcp open http Elasticsearch 7.17.9 Nmap done: 1 IP address (1 host up) scanned in 28.4s
Scan Intensity
Use Nmap timing templates T2 or T3 for bug bounty targets. T4 and T5 are too aggressive for internet-facing systems — they trigger IDS alerts and WAF blocks. Some programs explicitly prohibit port scanning. Always verify the program policy before running active scans.

HTTP Probing with httpx

httpx — web probing with tech detection
$ cat subdomains.txt | httpx -silent -status-code -title -tech-detect -web-server https://www.target.com [200] [Target Corp] [nginx] [React,webpack] https://api.target.com [200] [] [nginx] [Express] https://staging.target.com [403] [403 Forbidden] [nginx] https://docs.target.com [200] [Documentation] [nginx] [Hugo] https://admin.target.com [401] [Login Required] [Apache] [PHP,WordPress] http://jenkins.target.com:8080 [200] [Jenkins] [Jetty] [Jenkins] http://grafana.target.com:3000 [200] [Grafana] [Grafana] [INF] 7 results from 12 hosts

The httpx output immediately reveals interesting targets: a Jenkins server on port 8080, a Grafana dashboard on port 3000, a WordPress admin panel returning 401, and a staging server returning 403 (worth probing for access bypass). This is why HTTP probing is essential before manual testing — it triages your entire subdomain list in seconds.

Section 03

Content Discovery

Content discovery goes beyond what is linked in the application's UI. Hidden directories, backup files, configuration endpoints, and debug pages are invisible to normal users but discoverable through systematic enumeration. These forgotten assets are where critical vulnerabilities hide.

Directory Enumeration with ffuf

ffuf — fast web fuzzer
$ ffuf -w /usr/share/seclists/Discovery/Web-Content/raft-medium-directories.txt \ -u https://target.com/FUZZ -mc 200,301,302,403 -o results.json /'___\ /'___\ /'___\ /\ \__/ /\ \__/ __ __ /\ \__/ \ \ ,__\\ \ ,__\/\ \/\ \ \ \ ,__\ \ \ \_/ \ \ \_/\ \ \_\ \ \ \ \_/ \ \_\ \ \_\ \ \____/ \ \_\ \/_/ \/_/ \/___/ \/_/ v2.1.0 [Status: 200, Size: 14832, Words: 672] - /api [Status: 301, Size: 0, Words: 0] - /admin -> /admin/ [Status: 403, Size: 548, Words: 14] - /server-status [Status: 200, Size: 892, Words: 28] - /robots.txt [Status: 200, Size: 2104, Words: 56] - /backup [Status: 301, Size: 0, Words: 0] - /docs -> /docs/ [Status: 200, Size: 4521, Words: 140] - /.env [Status: 200, Size: 9244, Words: 312] - /debug :: Progress: [30000/30000] :: Job [1/1] :: 142 req/sec :: Errors: 0 ::
Critical Findings in This Output
The /.env file likely contains environment variables including database credentials, API keys, and secret keys. The /debug endpoint may expose stack traces, internal paths, and configuration details. The /backup directory could contain source code or database dumps. Each of these is a potentially high or critical severity finding.

Parameter Discovery

Beyond directory enumeration, parameter discovery finds hidden query parameters and form fields that the application processes but does not expose in its UI. Tools like Arjun and ParamSpider automate this process.

arjun — parameter discovery
$ arjun -u https://target.com/api/users -m GET [*] Probing the target for stability [*] Analysing HTTP response for parameter hints [*] Testing with 2588 parameters from default wordlist [+] id (reflected in response body) [+] user (reflected in response body) [+] admin (different response size: 4821 vs 2104) [+] format (reflected in response body) [+] debug (different response size: 8912 vs 2104) [*] Parameters found: 5
Section 04

Automated Scanning

Automation multiplies your effectiveness. While you manually test one application, automated scanners can probe hundreds of subdomains for known vulnerabilities, misconfigurations, and exposed services. The key is using automation for breadth and manual testing for depth.

Nuclei Template Categories

Category Templates Use Case
cves/ 2000+ CVE detection templates Known vulnerability scanning; first pass on any new target
exposures/ Sensitive file and config detection Environment files, backups, source code, API keys in JS
misconfigurations/ Server and service misconfigs Open redirects, CORS, directory listing, debug endpoints
technologies/ Tech stack fingerprinting Identify frameworks, CMS, WAFs, load balancers
takeovers/ Subdomain takeover detection Dangling DNS records pointing to unclaimed cloud services
default-logins/ Default credential checks Admin panels, databases, management consoles with factory creds

Custom Nuclei Templates

Writing custom templates for recurring patterns is what separates tool users from tool builders. If you find a vulnerability pattern in one target, write a template and scan every target in your pipeline for the same issue.

# custom-debug-endpoint.yaml id: custom-debug-endpoint info: name: Debug Endpoint Exposure severity: high description: Application debug endpoint accessible without authentication http: - method: GET path: - "{{BaseURL}}/debug" - "{{BaseURL}}/_debug" - "{{BaseURL}}/api/debug" matchers-condition: and matchers: - type: status status: - 200 - type: word words: - "stack trace" - "environment" - "debug info" condition: or

Template Sharing
The Nuclei community maintains thousands of templates in the nuclei-templates repository. Contributing your own templates earns recognition and helps the community. Keep your competitive-advantage templates private; share generic detection patterns publicly.

Section 06

Building Your Toolkit

A professional recon setup requires a dedicated environment. Running tools from your personal laptop works for learning, but serious hunting demands a VPS with proper networking, tool management, and output organization.

Recommended VPS Setup

VPS initial setup
$ sudo apt update && sudo apt install -y golang python3-pip git jq # Install Go-based tools $ go install github.com/projectdiscovery/subfinder/v2/cmd/subfinder@latest $ go install github.com/projectdiscovery/httpx/cmd/httpx@latest $ go install github.com/projectdiscovery/nuclei/v3/cmd/nuclei@latest $ go install github.com/ffuf/ffuf/v2@latest $ go install github.com/tomnomnom/anew@latest # Install Python tools $ pip3 install arjun # Download wordlists $ git clone https://github.com/danielmiessler/SecLists.git ~/wordlists # Update Nuclei templates $ nuclei -update-templates [INF] Templates updated successfully (4892 templates)

Directory Organization

# Recommended directory structure per target ~/bounties/ target-name/ recon/ subdomains/ # Raw subdomain lists from each tool dns/ # DNS resolution results ports/ # Nmap/masscan output screenshots/ # gowitness/aquatone galleries scans/ nuclei/ # Nuclei scan results ffuf/ # Directory enumeration output findings/ vuln-001/ # One folder per finding request.txt # Raw HTTP request response.txt # Raw HTTP response screenshots/ # Visual evidence notes.md # Reproduction steps draft notes.md # Target-specific observations

Proxy Configuration

Route all active testing through Burp Suite or a similar intercepting proxy. This captures every request and response for documentation. Configure your browser and CLI tools to use the proxy — nothing should touch the target without being logged.
