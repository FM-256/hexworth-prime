Q01 During source code review of a Node.js application, you find: exec("convert " + req.query.file + " output.png"). What is the vulnerability and the best remediation?
  • Path traversal - validate the file extension
  • OS command injection - replace exec() with execFile() and pass arguments as an array, never concatenating user input into shell commands
  • XSS - HTML-encode the filename
  • SSRF - block localhost connections
Q02 You chain three bugs: (1) self-XSS in profile name, (2) CSRF on profile update, (3) stored XSS renders to admin panel. Individually they are low/medium severity. What is the combined impact?
  • Still low severity since self-XSS is out of scope
  • Medium severity since CSRF alone is medium
  • Critical - the chain achieves stored XSS in the admin panel without authentication, enabling admin account takeover
  • The bugs cancel each other out

  • Match if the response size is greater than 0 bytes
  • Match if Content-Type is text/plain

Q07 You find a Python function that uses eval() on user-supplied mathematical expressions. The developer added a check: if "import" not in expr. Is this sufficient?
  • No - eval() can be exploited without "import" using __builtins__, __class__.__mro__, or encoded strings to achieve code execution
  • Yes, blocking "import" prevents all code execution
  • eval() in Python is safe for mathematical expressions
  • The check is sufficient if you also block "exec"
Q08 In the Log4Shell (CVE-2021-44228) case study, what made this vulnerability so devastating compared to other Java deserialization bugs?
  • It only affected a single application
  • It required physical access to exploit
  • It was already patched before public disclosure
  • Log4j was ubiquitous across millions of applications, the attack string could appear in any logged field (headers, user agents, form data), and exploitation was trivial with a single JNDI lookup string
Q09 You want to chain an open redirect with an OAuth flow. The OAuth provider validates redirect_uri against a whitelist of "*.example.com". How could the open redirect help?
  • The open redirect is irrelevant to OAuth flows
  • Use the open redirect on an in-scope *.example.com page as the redirect_uri, which passes validation, then the redirect bounces the OAuth code/token to your attacker-controlled server
  • Bypass the whitelist by using URL encoding
  • Replace the redirect_uri with an attacker domain directly
Q10 What is the primary advantage of using Semgrep over traditional regex-based grep for source code security review?
  • Semgrep is faster than grep
  • Semgrep only works on Python code
  • Semgrep understands code structure (AST-based), so it can match patterns regardless of formatting, variable names, or comment placement - reducing false positives
  • Semgrep automatically fixes vulnerabilities it finds
