Section 02

📡 Reconnaissance Tools

Reconnaissance is the foundation of every successful bug hunt. These tools map the attack surface before you test a single endpoint — discovering subdomains, open ports, technology stacks, and exposed services that define where bugs live.

Amass
Recon

OWASP's open-source attack surface mapping tool. Performs both passive (DNS records, certificate transparency, web archives) and active (DNS brute-force, zone transfer attempts) subdomain enumeration. Integrates with 40+ data sources including VirusTotal, SecurityTrails, Censys, and Shodan via API keys.

# Passive enumeration (no direct target contact) $ amass enum -passive -d target.com -o passive-subs.txt # Active enumeration (brute-force + resolving) $ amass enum -active -d target.com -brute -w /usr/share/wordlists/dns.txt # Intel mode — discover root domains from ASN or CIDR $ amass intel -asn 12345 # Use config file with API keys for data sources $ amass enum -d target.com -config ~/.config/amass/config.ini
FlagEffect
-d <domain>Target domain to enumerate
-passiveOnly use passive data sources (no DNS queries)
-activePerform active DNS queries and zone transfers
-bruteEnable DNS brute-force subdomain discovery
-o <file>Output results to file
-config <file>Path to config with API keys
Lab 01 — Recon Pipeline
subfinder
Recon

A fast passive subdomain discovery tool by ProjectDiscovery. Queries certificate transparency logs (crt.sh), search engines, DNS datasets, and threat intelligence feeds. Designed for speed and pipeline integration — output pipes directly into httpx, nuclei, or other ProjectDiscovery tools.

# Basic subdomain enumeration $ subfinder -d target.com -o subs.txt # Recursive enumeration (find subdomains of subdomains) $ subfinder -d target.com -recursive # Multiple domains from file $ subfinder -dL domains.txt -o all-subs.txt # Pipe into httpx for live host detection $ subfinder -d target.com -silent | httpx -sc -td
FlagEffect
-d <domain>Target domain
-dL <file>File containing list of domains
-recursiveRecursive subdomain enumeration
-silentShow only subdomains (clean for piping)
-o <file>Output to file
Lab 01 — Recon Pipeline
httpx
Recon

A fast HTTP toolkit by ProjectDiscovery. Probes a list of hosts for live HTTP services, extracts status codes, content lengths, page titles, technology stacks (via Wappalyzer signatures), TLS certificate info, and web server headers. Essential for filtering recon output down to live, testable targets.

# Probe subdomains with status codes and tech detection $ cat subs.txt | httpx -sc -td -title # Filter for specific status codes $ cat subs.txt | httpx -mc 200,301,302,403 # Extract response headers and content length $ cat subs.txt | httpx -sc -cl -server # JSON output for downstream processing $ cat subs.txt | httpx -json -o probed.json
FlagEffect
-scShow HTTP status code
-tdTechnology detection (Wappalyzer)
-titleShow page title
-mc <codes>Match specific status codes
-clShow content length
-jsonOutput in JSON format

nmap
Recon

The industry-standard network scanner. In bug bounty context, nmap identifies open ports, running services and versions, and OS fingerprints. The NSE scripting engine extends it with vulnerability detection, brute-force, and information-gathering scripts. Use judiciously — active scanning generates significant traffic.

# Service version + default scripts $ nmap -sV -sC target.com # Top 1000 ports, fast scan $ nmap -T4 --top-ports 1000 target.com # Full port scan with version detection $ nmap -p- -sV -T4 target.com # Vuln scan using NSE scripts $ nmap --script vuln target.com # Scan specific ports $ nmap -p 80,443,8080,8443 -sV target.com
FlagEffect
-sVService version detection
-sCDefault NSE scripts
-p-Scan all 65,535 ports
-T4Aggressive timing (faster)
--script <name>Run specific NSE scripts
-oA <base>Output in all formats (nmap, xml, grep)

Section 03

Web Testing Tools

Web application testing tools intercept, modify, and replay HTTP traffic. The intercepting proxy is the core of every bug hunter's workflow — it reveals how an application communicates with its backend, exposing hidden parameters, authentication tokens, and business logic that can be exploited.

Burp Suite
Web Testing

The industry-standard web application security testing platform. Community Edition provides an intercepting proxy, repeater (manual request replay), decoder, and comparer. Professional Edition adds an automated scanner, intruder (fuzzing), and extensions via BApp Store. Used by the vast majority of professional bug bounty hunters. Stok recommends running it passively with Logger++ to learn how applications behave before attacking.

# Proxy setup: configure browser to 127.0.0.1:8080 # Install Burp CA certificate for HTTPS interception # Key workflow tabs: # Proxy → Intercept and modify requests in real-time # Repeater → Manually replay and tweak individual requests # Intruder → Automated fuzzing with payload positions # Scanner → (Pro) Automated vulnerability scanning # Essential extensions (BApp Store): # Logger++ — enhanced request/response logging # Autorize — automated authorization testing # Param Miner — hidden parameter discovery # Turbo Intruder — high-speed race condition testing
Pro Tip from Stok
Run Burp Suite passively while browsing target applications normally. Use Logger++ to monitor all requests. Learn how the application works before you attempt any active testing. Understanding the app's logic is more valuable than running automated scans.

Caido
Web Testing

A modern, Rust-based web security testing proxy. Offers similar core functionality to Burp Suite (intercept, replay, automate) with a faster, more responsive UI and built-in workflow automation. Growing rapidly in the bug bounty community as a lightweight alternative. Free tier available.

# Launch Caido (default proxy on 127.0.0.1:8080) $ caido # Core features: # Intercept → proxy with real-time request/response editing # Replay → manual request modification and resend # Automate → built-in fuzzing and automation workflows # Search → full-text search across all captured traffic # HTTPQL → query language for filtering traffic
Lab 02 — XSS
ffuf
Web Testing

Fuzz Faster U Fool — a fast web fuzzer written in Go. Discovers hidden directories, files, parameters, vhosts, and API endpoints by replacing the FUZZ keyword in URLs, headers, or POST bodies with wordlist entries. Filters results by status code, content length, word count, or regex to cut through noise.

# Directory brute-force $ ffuf -u https://target.com/FUZZ -w /usr/share/wordlists/dirb/common.txt # Filter by status code (exclude 404s) $ ffuf -u https://target.com/FUZZ -w wordlist.txt -fc 404 # Parameter fuzzing (GET) $ ffuf -u "https://target.com/page?FUZZ=value" -w params.txt # Vhost discovery $ ffuf -u https://target.com -H "Host: FUZZ.target.com" -w subs.txt -fs 4242 # POST body fuzzing with filter $ ffuf -u https://target.com/login -X POST \ -d "user=admin&pass=FUZZ" -w passwords.txt -fc 401
FlagEffect
-u <URL>Target URL (FUZZ = injection point)
-w <file>Wordlist file
-fc <codes>Filter (exclude) by status code
-mc <codes>Match (include) only specific codes
-fs <size>Filter by response size
-H <header>Add custom header
-t <N>Number of concurrent threads (default 40)

Section 04

Exploitation Tools

Exploitation tools automate the detection and validation of specific vulnerability classes. While manual testing with a proxy is essential for logic bugs, these tools accelerate discovery of injection flaws, known CVEs, and misconfigurations across large attack surfaces.

nuclei
Exploit

A fast, template-based vulnerability scanner by ProjectDiscovery. Community-maintained templates cover CVEs, misconfigurations, exposed panels, default credentials, and technology-specific checks. Scans thousands of hosts in minutes. Templates are YAML-based and easy to write custom checks for.

# Scan single target with all templates $ nuclei -u https://target.com # Scan with specific template tags $ nuclei -u https://target.com -tags cve,misconfig # Scan list of URLs from recon pipeline $ cat live-hosts.txt | nuclei -severity critical,high # Use custom template directory $ nuclei -u target.com -t ~/custom-templates/ # Rate-limited scan (stay under WAF radar) $ nuclei -u target.com -rl 10 -c 2
FlagEffect
-u <URL>Single target URL
-l <file>List of URLs to scan
-tags <tags>Filter templates by tag
-severity <s>Filter by severity (info, low, medium, high, critical)
-rl <N>Rate limit (requests per second)
-t <dir>Custom template directory
Lab 02 — XSS Lab 07 — Full Scope
sqlmap
Exploit

The de facto standard for automated SQL injection detection and exploitation. Tests for union-based, boolean-blind, time-based blind, error-based, stacked queries, and out-of-band injection across MySQL, PostgreSQL, MSSQL, Oracle, SQLite, and more. Can extract databases, tables, columns, and dump data once injection is confirmed.

# Test a URL parameter for SQL injection $ sqlmap -u "https://target.com/page?id=1" --dbs # Test with specific parameter $ sqlmap -u "https://target.com/page?id=1&name=test" -p id # Use saved Burp request file $ sqlmap -r request.txt --batch # Enumerate tables in a specific database $ sqlmap -u "url?id=1" -D dbname --tables # Dump specific table data $ sqlmap -u "url?id=1" -D dbname -T users --dump # Tamper scripts to bypass WAF $ sqlmap -u "url?id=1" --tamper space2comment,between
FlagEffect
-u <URL>Target URL with injectable parameter
-r <file>Load HTTP request from file (Burp export)
--dbsEnumerate databases
--tablesEnumerate tables
--dumpDump table contents
--batchNever ask for user input (use defaults)
--tamper <scripts>Use tamper scripts for WAF evasion
--level <1-5>Test depth level (higher = more tests)
--risk <1-3>Risk level (higher = more dangerous payloads)
Authorized Testing Only
sqlmap with --dump can extract sensitive data. Only use on targets where you have explicit written authorization. In bug bounty, demonstrate the injection exists without dumping real user data — use --technique=B (boolean blind) to prove impact without exfiltration.
Lab 03 — SQL Injection
XSStrike
Exploit

An advanced XSS detection suite that uses context-aware analysis to generate payloads that match the specific injection context (HTML attribute, JavaScript string, DOM sink). Goes beyond dumb fuzzing by parsing the response and constructing payloads that will actually execute. Includes a DOM XSS scanner, fuzzer, and WAF detection/evasion.

# Scan a URL parameter for reflected XSS $ python3 xsstrike.py -u "https://target.com/search?q=test" # Crawl and scan for XSS $ python3 xsstrike.py -u "https://target.com" --crawl # Fuzzing mode (test all parameters) $ python3 xsstrike.py -u "url?p1=a&p2=b" --fuzzer # Blind XSS (out-of-band callback) $ python3 xsstrike.py -u "url?q=test" --blind
Lab 02 — XSS
dalfox
Exploit

A fast, Go-based parameter analysis and XSS scanning tool. Excels at testing multiple parameters simultaneously, identifying DOM-based XSS sinks, and integrating into automated recon pipelines. Supports Burp/ZAP integration and custom payload injection.

# Scan single URL $ dalfox url "https://target.com/search?q=test" # Pipe from parameter discovery tool $ cat params.txt | dalfox pipe # With custom blind XSS callback $ dalfox url "url?q=test" -b https://your-server.com

Section 05

API Testing Tools

API security testing requires specialized tools for authentication token manipulation, schema analysis, and endpoint discovery. Modern applications expose REST and GraphQL APIs that often contain BOLA, broken authentication, and mass assignment vulnerabilities invisible to traditional web scanners.

jwt_tool
API

A Python toolkit for testing, forging, and attacking JSON Web Tokens. Decodes JWT headers and payloads, tests for the "none" algorithm bypass, performs key confusion attacks (RS256→HS256), brute-forces weak signing keys, and generates tampered tokens with modified claims for authorization testing.

# Decode and inspect a JWT $ python3 jwt_tool.py TOKEN # Test all known attack vectors $ python3 jwt_tool.py TOKEN -M at # Tamper with claims (e.g., escalate role) $ python3 jwt_tool.py TOKEN -T -S hs256 -p "secret" # Test "none" algorithm bypass $ python3 jwt_tool.py TOKEN -X a # Key confusion attack (RS256 → HS256) $ python3 jwt_tool.py TOKEN -X k -pk public.pem # Brute-force HMAC signing key $ python3 jwt_tool.py TOKEN -C -d /usr/share/wordlists/rockyou.txt
FlagEffect
-M atRun all attack tests
-TTamper mode (modify claims)
-X aExploit: algorithm "none" bypass
-X kExploit: key confusion attack
-CCrack HMAC signing key
-S <alg>Signing algorithm to use

Postman
API

An API development and testing platform. In bug bounty context, use it to organize API endpoints into collections, manage authentication tokens across environments (dev/staging/prod), run automated test sequences, and replay requests with modified parameters for IDOR and authorization testing.

# Key workflow for bug bounty: # 1. Import OpenAPI/Swagger spec or build collection manually # 2. Set up environments (tokens, base URLs, user IDs) # 3. Create test sequences for auth bypass scenarios # 4. Use Collection Runner for automated testing # Pro tip: use Postman Interceptor to capture browser traffic # and auto-build API collections from observed requests # Alternatives: Insomnia (open-source), Bruno (git-friendly)
Lab 05 — API Hunting
GraphQL Voyager
API

A browser-based tool that visualizes GraphQL API schemas as interactive graphs. Feed it an introspection query result and it renders the entire type system, showing relationships between queries, mutations, and types. Invaluable for identifying sensitive fields, hidden mutations, and authorization boundaries in GraphQL APIs.

# Step 1: Run introspection query against target $ curl -X POST https://target.com/graphql \ -H "Content-Type: application/json" \ -d '{"query":"{__schema{types{name fields{name type{name}}}}}"}' # Step 2: Paste introspection result into GraphQL Voyager # Step 3: Explore the visual schema map # Look for: user PII fields, admin mutations, nested relationships # Full introspection query (for complex schemas): # Use IntrospectionQuery from graphql-js specification
ℹ
GraphQL Attack Surface
If introspection is enabled, the API is telling you its entire schema. Check for: mutations that modify other users' data (BOLA), fields that expose PII, nested queries that bypass pagination (DoS), and batch queries that allow brute-force attacks.

☁ Cloud & Secret Scanning

Cloud misconfigurations and leaked secrets are among the highest-impact bug bounty findings. Exposed S3 buckets, leaked API keys in git history, and overly permissive IAM roles can lead to critical data breaches. These tools detect such issues at scale.

aws CLI
Cloud

The official AWS command-line interface. In bug bounty context, used for unauthenticated S3 bucket enumeration, testing for public object access, and validating leaked AWS credentials. Many targets expose S3 buckets through subdomain patterns, JavaScript source maps, or error messages.

# List S3 bucket contents (unauthenticated) $ aws s3 ls s3://target-bucket --no-sign-request # Try to download a file from public bucket $ aws s3 cp s3://target-bucket/file.txt . --no-sign-request # Check bucket ACL (access control list) $ aws s3api get-bucket-acl --bucket target-bucket --no-sign-request # Validate leaked credentials (check identity) $ aws sts get-caller-identity # Enumerate accessible services with found creds $ aws iam list-users $ aws s3 ls $ aws ec2 describe-instances --region us-east-1
FlagEffect
--no-sign-requestMake unauthenticated request (public access test)
--region <r>Specify AWS region
--profile <p>Use named credential profile
Lab 07 — Full Scope
trufflehog
Cloud

A secret scanning tool that searches git repositories, S3 buckets, filesystems, and other data sources for leaked credentials (API keys, passwords, tokens). Uses both regex patterns and entropy analysis to detect secrets with high accuracy. Scans entire git history including deleted commits.

# Scan a public git repository $ trufflehog git https://github.com/target/repo.git # Scan with verified-only results (reduced false positives) $ trufflehog git https://github.com/target/repo.git --only-verified # Scan an entire GitHub organization $ trufflehog github --org target-org # Scan an S3 bucket for exposed secrets $ trufflehog s3 --bucket target-bucket # Scan local filesystem $ trufflehog filesystem --directory /path/to/code
FlagEffect
--only-verifiedOnly show secrets verified as active
--jsonOutput in JSON format
--org <name>Scan entire GitHub organization
--since <date>Scan commits after date

Utility Tools

Utility tools handle the data transformation, encoding, and HTTP communication tasks that glue the entire bug hunting workflow together. Mastering curl, jq, and CyberChef makes you faster at every other phase of testing.

CyberChef
Utility

GCHQ's open-source "Cyber Swiss Army Knife" — a browser-based tool for encoding, decoding, encryption, compression, data analysis, and format conversion. Chain multiple operations into "recipes" for complex transformations. Essential for decoding JWT payloads, base64 strings, URL encoding, and analyzing obfuscated JavaScript.

# Common recipes for bug bounty: # Base64 Decode → reveals encoded tokens/payloads # URL Decode → decodes %xx encoded strings # JWT Decode → splits header.payload.signature # From Hex → converts hex dumps to readable text # Magic → auto-detects encoding and decodes # Entropy → measures randomness (detect encryption) # Access at: gchq.github.io/CyberChef # Can run entirely offline (download from GitHub)
Lab 06 — Report Writing
curl
Utility

The universal command-line HTTP client. Every bug hunter's most-used tool for quick endpoint checks, header inspection, cookie manipulation, and API calls. Supports every HTTP method, custom headers, certificates, proxies, and output formatting. Burp Suite can export any captured request as a curl command.

# Verbose request with all headers $ curl -v https://target.com # Send custom headers (auth, content-type) $ curl -H "Authorization: Bearer TOKEN" \ -H "Content-Type: application/json" https://api.target.com/users # POST JSON data $ curl -X POST https://api.target.com/login \ -H "Content-Type: application/json" \ -d '{"user":"admin","pass":"test"}' # Follow redirects and show response headers $ curl -L -D - https://target.com/redirect # Send request through Burp proxy $ curl -x http://127.0.0.1:8080 -k https://target.com # SSRF testing — internal metadata endpoint $ curl http://target.com/fetch?url=http://169.254.169.254/latest/meta-data/
FlagEffect
-vVerbose output (show headers)
-H <header>Add custom request header
-X <method>HTTP method (GET, POST, PUT, DELETE)
-d <data>POST request body
-x <proxy>Use HTTP proxy
-kAllow insecure SSL (skip cert check)
-LFollow redirects
-o <file>Save response to file

jq
Utility

A lightweight command-line JSON processor. Extracts, filters, and transforms JSON data from API responses, recon tool output, and configuration files. Essential for parsing large JSON API responses and automating data extraction in bug bounty pipelines.

# Pretty-print JSON response $ curl -s https://api.target.com/users | jq '.' # Extract specific fields $ curl -s https://api.target.com/users | jq '.data[] | {id, email}' # Filter by condition $ curl -s https://api.target.com/users | jq '.data[] | select(.role == "admin")' # Count results $ curl -s https://api.target.com/users | jq '.data | length' # Extract URLs from nuclei JSON output $ cat nuclei-results.json | jq -r '.matched_at'

Pipeline Automation
The ProjectDiscovery suite (subfinder, httpx, nuclei) is designed for piping: subfinder -d target.com -silent | httpx -silent | nuclei -severity high,critical. This single command discovers subdomains, filters live hosts, and scans for critical vulnerabilities in one pipeline.
