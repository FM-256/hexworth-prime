Section 01

🤖 Android Analysis Tools

Android static analysis begins with decompiling the APK to examine its manifest, resources, and decompiled source code. Android applications are packaged as APK files containing Dalvik bytecode (DEX files), which can be converted back to Java source with varying degrees of accuracy. These tools form the foundation of any Android security assessment.

apktool
Android

Decodes APK resources to near-original form, including AndroidManifest.xml, layouts, strings, and smali bytecode. Essential for examining app permissions, exported components, deep links, and custom URL schemes. Can also repackage modified APKs for testing.

# Decode APK to directory $ apktool d target.apk -o target_decoded # Decode without decompiling sources (resources only) $ apktool d -s target.apk # Rebuild modified APK $ apktool b target_decoded -o modified.apk # Sign rebuilt APK for installation $ jarsigner -keystore debug.keystore modified.apk androiddebugkey
FlagEffect
dDecode (decompile) APK
bBuild (repackage) APK from decoded directory
-sSkip decompiling sources (resources only)
-o <dir>Output directory or file
-fForce overwrite existing output
jadx
Android

Decompiles Android DEX and APK files directly to readable Java source code. The jadx-gui provides a full IDE-like interface with search, cross-references, and syntax highlighting. More readable output than smali for source code review. Use jadx for reading logic; use apktool for modifying and rebuilding.

# Decompile APK to Java source $ jadx target.apk -d output_dir # Open in GUI for interactive analysis $ jadx-gui target.apk # Search for hardcoded secrets in decompiled source $ grep -rn "api_key\|secret\|password\|token" output_dir/ # Export with deobfuscation mapping $ jadx target.apk --deobf -d output_dir
dex2jar
Android

Converts Android DEX bytecode to standard Java JAR files, enabling analysis with any Java decompiler (JD-GUI, CFR, Procyon). Useful when jadx fails on heavily obfuscated apps or when you need to use a specific Java analysis tool.

# Convert APK's DEX to JAR $ d2j-dex2jar target.apk -o target.jar # Open resulting JAR in JD-GUI $ jd-gui target.jar # Handle multi-DEX APKs $ d2j-dex2jar classes2.dex -o classes2.jar
adb
Android

Android Debug Bridge — the primary command-line interface for communicating with Android devices and emulators. Handles app installation, file transfer, log collection, shell access, and intent broadcasting. Every Android testing workflow depends on adb.

# List connected devices $ adb devices # Install APK on device $ adb install target.apk # Pull APK from device $ adb shell pm path com.target.app $ adb pull /data/app/com.target.app/base.apk # Open shell on device $ adb shell # View application logs $ adb logcat --pid=$(adb shell pidof com.target.app) # Pull app's private data directory (root required) $ adb shell su -c "cp -r /data/data/com.target.app /sdcard/appdata" $ adb pull /sdcard/appdata # Send intent to exported activity $ adb shell am start -n com.target.app/.DeepLinkActivity \ -d "https://target.com/callback?token=test"
CommandEffect
adb devicesList all connected devices/emulators
adb install <apk>Install APK on connected device
adb pull <path>Copy file from device to host
adb push <src> <dst>Copy file from host to device
adb logcatView device log output in real-time
adb shellOpen interactive shell on device
Section 02

⚡ Dynamic Android Tools

Dynamic analysis tools attach to running applications to intercept function calls, modify return values, bypass security controls, and observe runtime behavior. Frida is the industry standard for mobile dynamic instrumentation, with objection providing a higher-level automation layer built on top of it.

Frida
Dynamic

A dynamic instrumentation toolkit that lets you inject JavaScript into running processes on Android, iOS, Windows, macOS, and Linux. In mobile security, Frida is used to hook functions, bypass SSL pinning, disable root detection, trace API calls, and modify application behavior at runtime.

# List running processes on device $ frida-ps -U # Attach to running app $ frida -U com.target.app # Spawn app with script injection $ frida -U -f com.target.app -l bypass.js # SSL pinning bypass script example # bypass.js: Java.perform(function() { var TrustManager = Java.use('javax.net.ssl.X509TrustManager'); var SSLContext = Java.use('javax.net.ssl.SSLContext'); // Override checkServerTrusted to accept all certs var TrustManagerImpl = Java.registerClass({ name: 'com.custom.TrustManager', implements: [TrustManager], methods: { checkServerTrusted: function(chain, authType) { }, checkClientTrusted: function(chain, authType) { }, getAcceptedIssuers: function() { return []; } } }); });
objection
Dynamic

A runtime mobile exploration toolkit built on Frida. Provides pre-built commands for common tasks like SSL pinning bypass, root detection bypass, dumping keychain entries, exploring the filesystem, and hooking methods — without writing custom Frida scripts.

# Connect to running app $ objection -g com.target.app explore # Inside objection REPL: # Bypass SSL pinning > android sslpinning disable # Bypass root detection > android root disable # List activities > android hooking list activities # List classes matching pattern > android hooking list classes com.target # Hook a method and print arguments > android hooking watch class_method com.target.app.AuthManager.login --dump-args # Dump shared preferences > android sharedpreferences dump # Explore filesystem > env > ls /data/data/com.target.app/
Magisk
Android

A systemless root solution for Android that modifies the boot image without altering the system partition. MagiskHide (or its successors like Shamiko and Zygisk DenyList) can hide root from applications that perform root detection. Essential for testing apps that refuse to run on rooted devices.

# Root detection bypass workflow: # 1. Install Magisk on test device # 2. Enable Zygisk in Magisk settings # 3. Install Shamiko module (or configure DenyList) # 4. Add target app to DenyList # 5. Force stop and relaunch target app # If app still detects root, escalate to Frida hooks: # Hook Runtime.exec() to block 'su', 'which su' commands # Hook File.exists() for known root paths # Hook PackageManager for Magisk/SuperSU package names
⚠
Root Detection vs. Integrity
Bypassing root detection is a testing technique, not a vulnerability in itself. Most programs consider root/jailbreak bypass out of scope unless it leads to a security-relevant finding (e.g., accessing encrypted data, bypassing authentication). Always check the program policy before reporting root detection bypass alone.
Section 03

🍎 iOS Analysis Tools

iOS testing requires a jailbroken device or specialized tools to work around Apple's code signing and sandboxing. iOS applications are distributed as IPA files containing Mach-O binaries encrypted with FairPlay DRM, which must be decrypted before static analysis.

class-dump
iOS

Extracts Objective-C class declarations from Mach-O binaries. Reveals class names, method signatures, properties, and protocols without needing source code. Useful for understanding app architecture and identifying interesting methods to hook with Frida.

# Dump class headers from decrypted binary $ class-dump TargetApp > headers.h # Search for auth-related classes $ grep -i "auth\|login\|token\|session\|credential" headers.h # Search for API endpoint classes $ grep -i "api\|request\|endpoint\|url" headers.h # Dump with full method types $ class-dump -A TargetApp > headers_full.h
Cycript
iOS

A runtime manipulation tool that blends JavaScript and Objective-C syntax. Attaches to running iOS processes to inspect and modify objects, call methods, and explore the runtime. Useful for quick exploration, though Frida has largely replaced it for complex instrumentation.

# Attach to running process $ cycript -p TargetApp # Inside Cycript REPL: # Get the root view controller cy# UIApp.keyWindow.rootViewController # List all view controllers in hierarchy cy# UIApp.keyWindow.rootViewController.childViewControllers # Call a method on a specific object cy# [obj performSelector:@selector(isAuthenticated)] # Modify a property at runtime cy# obj.isPremiumUser = true
Hopper Disassembler
iOS

A reverse-engineering tool for macOS that disassembles, decompiles, and debugs Mach-O binaries. Provides pseudocode output, control flow graphs, and string cross-references. The primary tool for analyzing iOS app binaries when source code review is needed beyond what class-dump provides.

# Workflow: # 1. Extract IPA (rename .ipa to .zip, unzip) # 2. Decrypt binary (use frida-ios-dump or flexdecrypt) # 3. Open decrypted binary in Hopper # 4. Navigate to Labels > search for method names # 5. Use pseudocode view (Shift+Cmd+Y) for readability # IPA extraction via command line: $ unzip TargetApp.ipa -d extracted/ $ ls extracted/Payload/TargetApp.app/ # Decrypt on jailbroken device using frida-ios-dump: $ python3 dump.py com.target.app
otool
iOS

A macOS command-line utility for inspecting Mach-O object files. Displays linked libraries, load commands, header information, and sections. Quick way to check which frameworks an app uses, whether PIE is enabled, and what encryption status the binary has.

# Check encryption status (0 = decrypted, 1 = encrypted) $ otool -l TargetApp | grep -A4 LC_ENCRYPTION_INFO # List linked shared libraries $ otool -L TargetApp # Check for PIE (Position Independent Executable) $ otool -hv TargetApp | grep PIE # Dump string references $ strings TargetApp | grep -i "http\|api\|key\|secret"
Section 04

🔒 Network Interception

Intercepting mobile app network traffic reveals API endpoints, authentication mechanisms, and data handling practices that are invisible from the client side alone. SSL/TLS interception requires installing a trusted CA certificate on the device and, for apps with certificate pinning, using Frida or objection to bypass the pinning logic.

mitmproxy
Network

An open-source interactive HTTPS proxy with a terminal UI (mitmproxy), web interface (mitmweb), and scriptable Python API (mitmdump). Lighter than Burp Suite for mobile-specific testing and excels at scripted traffic manipulation. Free and fully featured.

# Start proxy on port 8080 $ mitmproxy -p 8080 # Web interface (browser-based UI) $ mitmweb -p 8080 # Dump all traffic to file $ mitmdump -p 8080 -w traffic.flow # Filter for specific domain $ mitmproxy -p 8080 --set view_filter="~d api.target.com" # Install CA certificate: # 1. Configure device proxy to [your-ip]:8080 # 2. Visit mitm.it on device browser # 3. Download and install cert for your platform # 4. Android 7+: must install as system cert (requires root)
Burp Suite (Mobile)
Network

Burp Suite's proxy works with mobile devices by configuring the device's WiFi proxy settings. The same Repeater, Intruder, and Scanner features that work for web testing apply to mobile API traffic. Requires installing Burp's CA certificate on the device.

# Mobile proxy setup: # 1. Burp > Proxy > Options > Bind to all interfaces # 2. Device WiFi > Proxy > Manual > [your-ip]:8080 # 3. Visit http://burp on device > download CA cert # 4. Install certificate on device # Android system cert install (root required): $ openssl x509 -inform DER -in burp-cert.der -out burp-cert.pem $ HASH=$(openssl x509 -inform PEM -subject_hash_old -in burp-cert.pem | head -1) $ cp burp-cert.pem ${HASH}.0 $ adb push ${HASH}.0 /system/etc/security/cacerts/ $ adb shell chmod 644 /system/etc/security/cacerts/${HASH}.0
Pinning Bypass Methods
Network

Certificate pinning prevents MITM proxying by validating the server's certificate against a hardcoded value. Multiple bypass techniques exist depending on the pinning implementation (OkHttp, TrustManager, NSURLSession).

# Method 1: objection (easiest) $ objection -g com.target.app explore > android sslpinning disable # Method 2: Frida script (universal-ssl-pinning-bypass) $ frida -U -f com.target.app -l frida-universal-pinning-bypass.js # Method 3: Patch APK (for apps that detect Frida) # 1. Decompile with apktool # 2. Modify network_security_config.xml to trust user certs # 3. Rebuild, sign, install # network_security_config.xml patch: # <network-security-config> # <base-config> # <trust-anchors> # <certificates src="user" /> # <certificates src="system" /> # </trust-anchors> # </base-config> # </network-security-config>
Section 05

💻 Mobile Testing Platforms

Testing platforms provide the device environments needed for mobile security testing. Options range from cloud-based virtual devices to local emulators and physical hardware. The right choice depends on your budget, testing requirements, and target app complexity.

Corellium
Platform

Cloud-based ARM virtual devices for iOS and Android. Provides jailbroken iOS devices without needing physical hardware. Supports snapshots, network monitoring, and Frida integration. The gold standard for professional mobile testing but requires a paid subscription.

# Corellium features for bug bounty: # - Pre-jailbroken iOS devices (any iOS version) # - Rooted Android devices # - Kernel debugging support # - Network traffic capture built-in # - Snapshot and restore for clean testing # - Frida pre-installed # - SSH access to device filesystem
Genymotion
Platform

Fast x86 Android emulator built on VirtualBox. Supports multiple Android versions, Google Play Services installation, and proxy configuration. Free for personal use. Good for testing Android apps when you do not need ARM binary compatibility or hardware features.

# Setup for bug bounty testing: # 1. Create device (Pixel, Samsung, etc.) # 2. Install Open GApps for Google Play access # 3. Root: Settings > Developer > SuperUser # 4. Install Frida server via adb push # 5. Configure proxy in WiFi settings # Push and start Frida server: $ adb push frida-server /data/local/tmp/ $ adb shell chmod 755 /data/local/tmp/frida-server $ adb shell /data/local/tmp/frida-server &
Physical Devices
Platform

Physical rooted/jailbroken devices provide the most realistic testing environment. Required for testing hardware-specific features (NFC, Bluetooth, biometrics, GPS), apps with emulator detection, and ARM-only binaries. Recommended: a dedicated testing phone separate from your personal device.

# Recommended physical test devices: # # Android: Google Pixel (any generation) # - Unlockable bootloader # - Magisk root support # - Fast OS updates for version testing # # iOS: iPhone SE or older model # - Check jailbreak compatibility before buying # - checkra1n supports A5-A11 chips (hardware exploit) # - Keep on jailbreak-compatible iOS version
★
Budget Setup
If you are starting mobile bug bounty on a budget, begin with Genymotion (free) for Android testing and focus on API traffic interception through Burp Suite or mitmproxy. Most mobile vulnerabilities are actually server-side issues (IDOR, broken auth, SSRF) discoverable through API traffic analysis without needing advanced on-device instrumentation.
