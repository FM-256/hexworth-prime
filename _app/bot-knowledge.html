What Is Hexworth Prime?

Hexworth Prime is a gamified cybersecurity and IT education platform. It is a web-based application where students join houses, complete interactive modules, earn XP (experience points), hack CTF (Capture The Flag) boxes, build hardware projects, troubleshoot IT scenarios, and level up their skills. The platform is designed for students pursuing careers in cybersecurity, IT operations, networking, cloud computing, programming, and related technical fields.

Think of it as a hacking academy crossed with a Hogwarts-style house system, rendered in neon cyan on a dark background. Students are sorted into houses based on their interests and career goals, and each house has its own themed content, color scheme, mascot, and emblem.

Key Facts About Hexworth Prime

  • Current version: 5.1.0, codename "THE DOSSIER"
  • The platform is a production B2B educational product used by instructors and students
  • Built with raw HTML, CSS, and JavaScript — no frameworks, no build step
  • Hosted on Firebase (Google Cloud)
  • Uses Firebase Firestore for user data, progress tracking, and class management
  • Works entirely in the browser — no software installation required for students
  • Contains hundreds of interactive modules, labs, presentations, games, and challenges
  • Features an achievement system, XP tracking, leaderboards, and daily missions
  • Includes instructor tools (Handler Dashboard) for managing classes and tracking student progress

Who Is Hexworth Prime For?

  • College students studying cybersecurity, IT, networking, or computer science
  • Career changers entering the tech field
  • IT professionals preparing for certifications (CompTIA, AWS, Cisco, etc.)
  • Anyone who wants hands-on practice with cybersecurity concepts
  • Instructors and professors who need interactive lab content for their classes

What Makes Hexworth Prime Different?

  • Everything is interactive — not just videos or readings, but hands-on labs, simulated terminals, and real exploitation scenarios
  • The gamification layer (houses, XP, achievements, leaderboards) keeps students engaged
  • Content spans from absolute beginner to expert level
  • The CTF Arena provides realistic penetration testing practice without needing to set up virtual machines
  • The Dispatch simulator provides real-world IT troubleshooting scenarios
  • Hardware projects in The Signal teach physical security and IoT concepts
  • All content runs in the browser — no VMs, no Docker, no setup headaches

Interactive Terminal Labs

Many modules in Hexworth Prime include interactive terminal emulators built directly into the browser. These terminals simulate real Linux and Windows command-line environments where students can:

  • Practice Linux commands in a safe sandbox
  • Run network scanning tools like nmap
  • Execute SQL queries against simulated databases
  • Navigate simulated file systems
  • Practice shell scripting
  • Test exploitation techniques in CTF boxes

The terminal is not a real SSH connection — it is a sophisticated browser-based simulation that mimics the behavior of a real terminal. Commands are processed by a JavaScript engine that simulates operating system responses, file systems, and network services. This means students can practice dangerous commands (like SQL injection or privilege escalation) without any risk to real systems.

CTF Arena - Capture The Flag Challenges

What Is the CTF Arena?

The CTF Arena is Hexworth Prime's penetration testing playground. It contains a growing collection of "boxes" — self-contained hacking challenges that simulate real-world cybersecurity scenarios. Each box presents a vulnerable system that students must reconnaissance, enumerate, exploit, and escalate privileges on — all within the browser.

Each box is config-driven, meaning all the scenarios, commands, flags, hints, and lore are defined in a JavaScript configuration file. The BoxEngine processes these configs to generate interactive terminal environments with simulated operating systems, file systems, networks, web applications, and databases.

How CTF Boxes Work

  1. Read the briefing — Each box has a lore-driven scenario explaining the context. You might be investigating a criminal organization, infiltrating a corporate network, or analyzing a compromised IoT device.
  2. Start with reconnaissance — Use simulated tools like nmap to discover open ports and running services on the target.
  3. Enumerate — Explore discovered services. Browse web applications, test for vulnerabilities, look for misconfigurations.
  4. Exploit — Use the appropriate technique to exploit the vulnerability (SQL injection, XSS, command injection, etc.).
  5. Capture flags — Each box contains multiple flags hidden at different stages. Flags prove you completed each phase.
  6. Escalate — After initial access, escalate privileges to get deeper access to the system. Find the root/admin flag.

Tutorial Mode

Many boxes include a tutorial mode that guides beginners through the attack chain step by step. Tutorial mode provides:

  • Step-by-step instructions for what to do next
  • Hints that appear when you get stuck
  • Trigger-based progression that detects when you complete each step
  • Explanations of why each technique works

Tutorial mode can be enabled or disabled, allowing beginners to learn while advanced students can challenge themselves without guidance.

Phase System

CTF boxes use a multi-layer phase system. Each box has defined phases (typically reconnaissance, enumeration, exploitation, and exfiltration/escalation). Completing phases unlocks the next one. Each phase is mapped to MITRE ATT&CK techniques, connecting the hands-on practice to industry-standard threat frameworks.

Dispatch — IT Troubleshooting Simulator

What Is Dispatch?

Dispatch is Hexworth Prime's IT troubleshooting simulator. Unlike the CTF Arena (which focuses on offensive security), Dispatch focuses on real-world IT support scenarios that IT professionals encounter daily. Each Dispatch box simulates a help desk ticket where something is broken and the student must diagnose and fix it.

Dispatch boxes are designed to prepare students for CompTIA A+, Microsoft MD-100, Security+, and similar certifications that test practical troubleshooting skills.

How Dispatch Works

  1. Read the help desk ticket — Each scenario begins with a user complaint describing the symptoms
  2. Observe the symptoms — Try booting the system, check error messages, listen for beep codes, observe LED indicators
  3. Diagnose the problem — Use available tools to narrow down the root cause. Check hardware, software, network settings, or configuration
  4. Fix the issue — Apply the correct solution (reseat hardware, change settings, update drivers, etc.)
  5. Verify the fix — Confirm that the system is working properly after your repair
  6. Capture the flag — Each Dispatch box has flags that prove you completed the troubleshooting process correctly

  • HW001 — Dead Workstation: It's Dead, Jim
    • Category: CompTIA A+ Core 1 — Hardware Troubleshooting
    • Difficulty: Intermediate

Features 5 distinct scenarios with unique symptoms, POST codes, and flag locations. Includes a tutorial mode that walks beginners through the troubleshooting process. Uses a simulated desktop environment with icons for the help desk ticket, power button, open case inspection, and POST code reference.
  • NT1 — Network Rescue
    • Category: Windows Networking Troubleshooting — MD-100
    • Difficulty: Beginner
    • Description: A user cannot connect to the network. Diagnose and fix Windows networking issues including IP configuration, DNS, gateway, and connectivity problems. Tutorial mode walks you through the process of checking network configuration at each layer.
  • OS001 — Boot Failure: It Won't Start
    • Category: Windows Boot Troubleshooting — MD-100 Objective 4.1
    • Difficulty: Intermediate
    • Description: A Windows system fails to boot. Troubleshoot boot issues using recovery tools, repair commands, and boot configuration data.
  • PR001 — Printer Nightmare: The Floor Is Screaming
    • Category: A+ Core 2 Printer Troubleshooting
    • Difficulty: Beginner

  • AD001 — Lockout Storm
    • Category: Active Directory and Authentication Troubleshooting — Security+
    • Difficulty: Advanced

Dispatch Tips for Students

  • Start with Network Rescue (NT1) or Printer Nightmare (PR001) — they are marked Beginner difficulty

CTF Arena Questions

What is a CTF?

CTF stands for "Capture The Flag." It is a cybersecurity competition format where participants must find hidden strings of text (flags) by exploiting vulnerabilities in simulated systems. In Hexworth Prime's CTF Arena, each "box" is a self-contained challenge with its own story, target system, and flags to find.

How do I find flags in CTF boxes?

Flags are hidden throughout the box at different stages. You find them by:

  • Scanning the target with reconnaissance tools
  • Exploiting vulnerabilities in web applications or services
  • Reading configuration files on compromised systems
  • Escalating privileges to access restricted areas
  • Each flag is typically a formatted string like HEX{some_text_here}

I am stuck on a CTF box. What should I do?

  1. Enable tutorial mode if available — it provides step-by-step guidance
  2. Use the built-in hint system — hints become available as you progress
  3. Re-read the box briefing and lore — they often contain clues
  4. Try a different approach — there are often multiple paths to each flag
  5. Start with reconnaissance — have you scanned all ports? Have you explored all web directories?
  6. Ask your instructor or classmates for a hint (not the answer)
  7. If the box is too hard, try an easier one first and come back later

What is the easiest CTF box to start with?

Start with A1 (The Ancient Ledger). It teaches SQL injection, one of the most fundamental web vulnerabilities, and has a comprehensive tutorial mode that walks you through every step. A2 (The Whispering Wall) is also beginner-friendly and teaches XSS (Cross-Site Scripting).

What order should I do the CTF boxes in?

The A-series is numbered in approximate difficulty order:

  • Beginner: A1, A2
  • Intermediate: A3, A4, A5, A6, A7, A8
  • Intermediate-Advanced: A9, A10
  • Advanced: A11, A12, A13
  • Expert: A14, A15, A16, A17, A18, A19
  • Expert (Extreme): A20 (the capstone challenge)

Are the CTF boxes real hacking?

The CTF boxes simulate real exploitation techniques in a safe, browser-based environment. The tools (nmap, SQL injection, XSS, etc.) are the same ones used by real penetration testers, but they operate against simulated targets — not real systems. You are learning real skills without any legal or ethical risk.

Technical Questions

How does the terminal work?

The terminal in labs and CTF boxes is a browser-based emulator. It is not connected to a real Linux server — instead, a JavaScript engine processes your commands and generates realistic responses. The terminal supports common commands like ls, cd, cat, nmap, curl, and many others specific to each box's scenario. Commands are matched against the box's configuration to produce appropriate output.

Can I break anything?

No. Everything runs in your browser. There is no connection to real servers, no risk of breaking anything, and no legal concerns. The simulated environments reset when you reload the page. Your progress (flags captured, modules completed) is saved, but the simulated systems themselves are ephemeral.

My progress is not saving. What do I do?

  • Make sure you are logged in — progress is tied to your account
  • Check your internet connection — progress syncs to Firebase (cloud database)
  • Try refreshing the page
  • Make sure you are not in incognito/private browsing mode — some progress may be stored locally
  • Contact your instructor if the issue persists

The page is not loading correctly. What should I do?

  • Clear your browser cache and reload
  • Try a different browser (Chrome or Firefox recommended)
  • Disable browser extensions that might interfere (especially ad blockers)
  • Make sure JavaScript is enabled in your browser
  • Check if you are behind a firewall that might block Firebase connections

Platform Technical Details

Technology Stack

  • Frontend: Raw HTML, CSS, and vanilla JavaScript. No frameworks (no React, Angular, or Vue). No build step. No bundler (no Webpack, Vite, or Rollup). All code is served as-is by Firebase Hosting.
  • Backend: Firebase (Google Cloud)
    • Firebase Hosting — static file serving with CDN
    • Firebase Firestore — NoSQL document database for user profiles, progress data, class management, and activity feeds
    • Firebase Cloud Functions — server-side logic for XP authority, data exports, and server-side validation
    • Firebase Security Rules — field-level whitelist for data access control
  • Content: All content is static HTML files. No server-side rendering. No database queries for content. This means the platform loads fast and works reliably.
  • Components: Custom JavaScript components handle shared functionality:
    • AccessGuard.js — authentication and access control
    • AchievementManager.js — achievement tracking and display
    • ModuleProgress.js — progress tracking for individual modules
    • ContentCatalog.js — registry of all content with metadata
    • GlobalSearch.js — Ctrl+K search overlay
    • LearningPaths.js — prerequisite chains and course progression
    • StateFederation.js — cross-device progress synchronization
    • HouseRenderer.js — shared house page rendering
    • BoxEngine.js — CTF Arena box engine for simulated environments
  • Icons: All icons are custom WebP images (no emoji in the codebase). 125 custom icons are available.

Browser Requirements

  • Any modern web browser with JavaScript enabled
  • Chrome, Firefox, Edge, or Safari (latest versions recommended)
  • JavaScript must be enabled (required for all interactive features)
  • Internet connection required for login, progress sync, and initial page loads
  • Keyboard recommended for terminal-based labs and CTF boxes

Data and Privacy

  • Student data (progress, XP, achievements) is stored in Firebase Firestore (Google Cloud)
  • Some progress data is also cached in browser localStorage for faster access
  • Firestore security rules restrict data access — students can only read/write their own data
  • Handlers (instructors) can view student progress within their assigned classes
  • No personal data is shared publicly — leaderboards may show display names

Tips for Success on Hexworth Prime

General Study Tips

  • Be consistent — short daily sessions are more effective than long cramming sessions
  • Do the labs — reading is important, but hands-on practice is where real learning happens
  • Do not skip the fundamentals — Linux command line skills and networking basics are prerequisites for almost everything in cybersecurity
  • Take notes — especially on commands and techniques you learn in labs and CTF boxes
  • Check daily missions — they keep you engaged and earn bonus XP
  • Use the search — press Ctrl+K to find any topic quickly
  • Follow the learning paths — they are designed to build knowledge in the right order

CTF Tips

  • Always start with reconnaissance — run nmap before trying anything else
  • Read error messages carefully — they often reveal what technology is being used, which tells you what exploits to try
  • Try the obvious things first — default credentials, common injection payloads, directory traversal
  • Take notes on what you try — it helps you avoid repeating failed approaches
  • Use tutorial mode — there is no penalty for using it, and it teaches the methodology
  • Do not brute force — CTF boxes are designed to be solved with technique, not exhaustive guessing

Certification Study Tips

  • Use the certification path pages — they organize content by exam objectives
  • Take the quizzes seriously — they simulate exam conditions
  • Supplement with the presentations — they provide visual overviews of complex topics
  • Practice in labs — certifications increasingly test practical skills, not just memorization
  • Track your weak areas — focus study time on objectives where you score lowest on quizzes
