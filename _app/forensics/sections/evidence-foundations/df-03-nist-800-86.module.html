NIST SP 800-86: Guide to Integrating Forensic Techniques

NIST Special Publication 800-86 is the foundational framework for digital forensics in organizations. Published by the National Institute of Standards and Technology, it defines a four-phase forensic process and provides guidance on handling data from multiple sources. Every forensic examiner should understand this framework — it is referenced in certifications, court proceedings, and organizational policies.

Learning Objectives

  • Describe the four phases of the NIST forensic process
  • Identify data source categories and their forensic significance
  • Apply organizational readiness recommendations to a forensic program
  • Map the NIST framework to real investigation workflows

The Four-Phase Forensic Process

NIST 800-86 defines forensic investigation as a linear four-phase process. Each phase feeds into the next, and documentation is continuous throughout all phases.

Phase 1: Collection

Identify, label, record, and acquire data from possible sources while preserving data integrity. This phase follows the order of volatility (RFC 3227) and uses forensically sound acquisition methods.

Key activities:

  • Identify all potential data sources relevant to the investigation
  • Acquire data using validated tools and write blockers
  • Verify integrity through cryptographic hashing
  • Document the collection process and maintain chain of custody

Phase 2: Examination

Process collected data to extract relevant information while protecting its integrity. This involves making the data visible and usable without altering the original. Examples include filtering log files, extracting files from disk images, and decrypting protected data.

Key activities:

  • Assess and extract data from collected sources
  • Use forensic tools to parse data structures
  • Filter and reduce data to relevant subsets
  • Document tools, techniques, and any transformations applied

Phase 3: Analysis

Analyze the results of the examination to derive useful information that addresses the questions driving the investigation. This is where the examiner draws conclusions from the data.

Key activities:

  • Correlate data from multiple sources
  • Construct timelines of events
  • Identify patterns, anomalies, and indicators of compromise
  • Draw conclusions supported by the evidence

Phase 4: Reporting

Report the results of the analysis, including describing the actions taken, explaining tool and procedure choices, recommending improvements, and presenting findings appropriate for the audience.

Key activities:

  • Document all findings with supporting evidence references
  • Explain methodology so results are reproducible
  • Tailor the report to the intended audience (legal, technical, executive)
  • Include alternative explanations where applicable

Continuous Documentation: NIST emphasizes that documentation is not a separate phase but a continuous activity throughout all four phases. Every action, decision, and finding should be recorded in real time, not reconstructed after the fact.

Data Source Categories

NIST 800-86 categorizes forensic data sources into four primary groups, each requiring different collection and examination techniques:

Category Examples Forensic Considerations
Files Documents, images, executables, configs, databases Metadata analysis, hash matching, signature analysis, carving from unallocated space
OS Data Registry, event logs, user accounts, scheduled tasks, installed software Volatile vs non-volatile; requires OS internals knowledge; artifacts vary by OS
Network Traffic Packet captures, flow data, IDS/IPS logs, firewall logs, DNS queries Highly volatile; requires proactive capture infrastructure; privacy and legal concerns
Application Data Browser history, email, chat logs, application-specific logs Format varies widely; may require application-specific tools; authentication artifacts

Organizational Readiness Recommendations

NIST 800-86 dedicates significant guidance to preparing organizations for forensic activities before incidents occur:

Policy and Procedures

  • Define roles and responsibilities for forensic activities
  • Establish evidence handling, analysis, and reporting procedures
  • Create guidelines for coordinating with law enforcement
  • Develop acceptable use policies that support forensic investigation

Personnel

  • Maintain trained forensic staff or retainer with external forensic firms
  • Provide ongoing training and certification support
  • Define escalation paths for incidents requiring forensic analysis

Technical Infrastructure

  • Deploy centralized logging with sufficient retention periods
  • Enable audit trails on critical systems
  • Maintain forensic workstations with validated tool suites
  • Implement write-blocking capabilities for evidence acquisition
  • Ensure NTP synchronization across all systems for timeline accuracy

Proactive Logging: NIST emphasizes that organizations must establish logging before incidents occur. If adequate logs are not available when an incident happens, critical evidence may be permanently lost. Configure systems to log at appropriate detail levels and retain logs per your retention policy.

Mapping NIST to Real Investigations

NIST Phase Malware Incident Insider Threat Data Breach
Collection Memory dump, disk image, network PCAP Workstation image, email archives, USB logs Server images, firewall logs, DB transaction logs
Examination Extract malware, parse C2 traffic, timeline FS changes Recover deleted files, parse browser history, USB artifacts Parse access logs, extract SQL queries, identify exfil records
Analysis Determine infection vector, map lateral movement, assess impact Correlate file access with logins, establish motive/opportunity Determine scope, identify attack vector, attribute threat actor
Reporting IOCs for remediation, executive summary, technical writeup Evidence summary for HR/legal, activity timeline Breach notification, regulatory filing, remediation plan

Practice: Apply the NIST Framework

You receive a report that a company's web application has been defaced. Using the NIST four-phase framework, outline your approach:

  1. Collection: What data sources would you collect? In what order?
  2. Examination: What tools and techniques would you use to process the collected data?
  3. Analysis: What questions are you trying to answer? What correlations would you look for?
  4. Reporting: Who are your audiences? What format would each report take?

Key Takeaways

  • NIST 800-86 defines four phases: Collection, Examination, Analysis, Reporting
  • Documentation is continuous across all phases, not a standalone step
  • Four data source categories: Files, OS Data, Network Traffic, Application Data
  • Organizational readiness (logging, personnel, tools) must be established before incidents
  • The framework applies to all investigation types with scenario-specific adaptations
