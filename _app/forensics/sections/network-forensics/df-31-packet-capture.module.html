Why Packet Capture Matters

Network traffic is the ground truth of digital communication. While logs can be tampered with and endpoints can be compromised, packets on the wire represent what actually happened. Packet capture provides bit-level evidence of data in transit -- the exact bytes sent and received, with precise timestamps.

In forensic investigations, packet captures answer questions that no other evidence source can: What data was exfiltrated? What commands did the attacker send? What credentials were transmitted? What was the exact sequence of network events?

tcpdump -- Command-Line Capture

tcpdump is the foundational packet capture tool on Unix/Linux systems. It uses the libpcap library and Berkeley Packet Filter (BPF) syntax for filtering.

Essential tcpdump Commands
# Capture all traffic on eth0, write to file
$ sudo tcpdump -i eth0 -w capture.pcap

# Capture with packet count limit (first 1000 packets)
$ sudo tcpdump -i eth0 -c 1000 -w capture.pcap

# Capture with no DNS resolution (faster, cleaner output)
$ sudo tcpdump -i eth0 -nn -w capture.pcap

# Capture specific host traffic
$ sudo tcpdump -i eth0 host 192.168.1.100 -w suspect.pcap

# Capture specific port (HTTP)
$ sudo tcpdump -i eth0 port 80 -w http_traffic.pcap

# Read a capture file with hex dump
$ tcpdump -r capture.pcap -X

# Complex BPF filter: HTTP to/from specific subnet
$ sudo tcpdump -i eth0 'tcp port 80 and net 10.0.0.0/24' -w filtered.pcap

# Capture with snaplen (full packet, not truncated)
$ sudo tcpdump -i eth0 -s 0 -w full_capture.pcap
Flag Purpose Example
-i Interface to capture on -i eth0, -i any
-w Write packets to file (PCAP format) -w evidence.pcap
-r Read packets from file -r evidence.pcap
-n No DNS resolution; -nn also skips port names -nn
-c Capture count limit -c 5000
-X Print hex and ASCII payload -X
-s Snaplen (bytes per packet); 0 = full packet -s 0

Wireshark -- GUI Capture and Analysis

Wireshark is the industry-standard graphical packet analyzer. It provides deep protocol inspection, powerful display filters, and visual tools for traffic analysis. While Wireshark can capture live traffic, it is more commonly used to analyze PCAP files captured by other tools.

Capture Interfaces Select from available network interfaces. Supports promiscuous mode for capturing all traffic on the segment, not just traffic to/from the capture host.
Ring Buffer Continuous capture with file rotation. Set maximum file size and count to prevent disk exhaustion during long captures. Essential for production monitoring.
Capture Filters (BPF) Applied before packets are captured. Uses BPF syntax. Reduces capture volume. Cannot be changed after capture starts.
Display Filters Applied to already-captured packets. Uses Wireshark filter syntax (different from BPF). Can be changed at any time during analysis.

tshark -- Command-Line Wireshark

tshark provides Wireshark's protocol dissection capabilities in a command-line interface. It is ideal for scripted analysis, remote capture over SSH, and processing large PCAP files.

tshark Examples
# Capture traffic and write to PcapNG
$ tshark -i eth0 -w capture.pcapng

# Read PCAP and apply display filter
$ tshark -r capture.pcap -Y "http.request.method == POST"

# Extract specific fields (CSV-style output)
$ tshark -r capture.pcap -T fields \
    -e frame.time -e ip.src -e ip.dst -e tcp.dstport \
    -E separator=, -E quote=d

# Export HTTP objects from capture
$ tshark -r capture.pcap --export-objects http,./extracted_files/

# Protocol statistics
$ tshark -r capture.pcap -z io,stat,1
$ tshark -r capture.pcap -z conv,tcp

PCAP vs PcapNG Formats

Feature PCAP (libpcap) PcapNG
File extension .pcap, .cap .pcapng
Multiple interfaces No (one per file) Yes
Timestamp resolution Microsecond Nanosecond
Comments/annotations No Yes (per-packet and per-file)
Interface metadata Limited (link type only) Full (name, speed, OS, filter)
Name resolution No Embedded DNS records
Tool support Universal Most modern tools
Default in Wireshark No (legacy) Yes (since Wireshark 1.8+)

Forensic Best Practice

Use PCAP format when compatibility is paramount -- every tool reads it. Use PcapNG when you need annotations, nanosecond timestamps, or multi-interface captures. For court submissions, PCAP is safer because more tools can independently verify the contents.

Capture Placement

Where you place your capture point determines what traffic you see. The wrong placement can mean missing critical evidence entirely.

Network TAP Passive hardware device that copies traffic without affecting the network. Full-duplex, no packet loss. Gold standard for forensic capture. Requires physical access to the cable.
SPAN/Mirror Port Switch configuration that copies traffic from one or more ports to a monitoring port. Easier to deploy but can drop packets under high load. May miss full-duplex traffic.
Inline Capture Device placed directly in the traffic path (like an IPS). Sees all traffic but adds latency and introduces a single point of failure. Used by IDS/IPS appliances.
Host-Based Capture Capturing on the endpoint itself (tcpdump on the suspect machine). Only sees traffic to/from that host. Useful for targeted capture but may be detected by attackers.

Placement Strategy

For incident response: capture at the network perimeter (TAP on firewall uplink) to see external communications, AND at the access layer (SPAN port on the suspect's switch) to see lateral movement. A single capture point always has blind spots.

Legal Considerations

Packet capture records the content of communications, which invokes significant legal obligations:

Wiretap Act (18 USC 2511) Federal law prohibiting interception of communications without authorization. Employer monitoring on owned networks generally falls under the "provider exception" or requires consent via acceptable use policy.
ECPA / Stored Communications The Electronic Communications Privacy Act governs access to stored electronic communications. PCAPs containing email or message content may be subject to ECPA restrictions.
Consent / AUP An Acceptable Use Policy signed by employees provides legal authorization for monitoring. Without it, capturing employee traffic -- even on company networks -- can be legally problematic.
International Considerations GDPR (EU), PIPEDA (Canada), and other privacy laws may restrict packet capture of personal data. Cross-border captures add jurisdictional complexity.

Always Get Legal Authorization

Before initiating any packet capture during an investigation, confirm authorization with your legal team. Document who authorized the capture, the scope, and the retention period. Unauthorized capture can make evidence inadmissible and expose the organization to liability.

Practice: Build Your Capture Commands

Write the tcpdump command for each scenario:

  1. Capture all DNS traffic (port 53) on interface eth0, no name resolution, write to dns_investigation.pcap
  2. Capture traffic between host 10.0.0.15 and subnet 192.168.1.0/24, full packets, limited to 10000 packets
  3. Capture only TCP SYN packets (port scans) on any interface
  4. Read an existing capture and display only HTTP POST requests in hex

Answers:

1. sudo tcpdump -i eth0 port 53 -nn -w dns_investigation.pcap

2. sudo tcpdump -i eth0 host 10.0.0.15 and net 192.168.1.0/24 -s 0 -c 10000 -w host_traffic.pcap

3. sudo tcpdump -i any 'tcp[tcpflags] == tcp-syn' -nn

4. tcpdump -r capture.pcap -X 'tcp dst port 80 and tcp[((tcp[12:1] & 0xf0) >> 2):4] = 0x504F5354'

Key Takeaways

  • tcpdump is the foundational CLI capture tool; use -s 0 to capture full packets
  • Wireshark provides GUI analysis with deep protocol dissection; tshark provides the same on CLI
  • PCAP is universally compatible; PcapNG adds annotations and nanosecond timestamps
  • Capture placement determines visibility -- use TAPs for forensic-grade capture
  • Always secure legal authorization before initiating packet capture
  • BPF filters reduce capture volume; apply them at capture time when possible
