Capstone Objectives

  • Analyze described PCAP evidence to reconstruct a complete network intrusion
  • Identify the initial access vector from network traffic evidence
  • Trace lateral movement across the network using flow and session data
  • Detect data exfiltration and map attacker infrastructure
  • Write a professional investigation report with a complete attack timeline

Scenario: Network Intrusion at Atlas Engineering

Atlas Engineering, a defense contractor, detected unusual outbound traffic patterns during a routine security review. The SIEM flagged high-volume DNS queries to a single domain and large HTTPS uploads to an unrecognized IP address. You have been brought in to analyze 48 hours of PCAP data from the perimeter firewall TAP and IDS alerts from the Suricata deployment.

Scenario Parameters

  • Organization: Atlas Engineering (defense contractor -- ITAR-regulated data)
  • PCAP window: 2024-03-18 00:00 to 2024-03-19 23:59 UTC
  • Capture point: Network TAP on firewall uplink (sees all ingress/egress)
  • Internal network: 172.16.0.0/16
  • DMZ: 10.10.10.0/24 (web servers, mail server)
  • IDS: Suricata with ET Open ruleset

Capstone Deliverable: Investigation Report

Grading Rubric (100 points)

Section Points Requirements
Executive Summary 10 Non-technical summary including data loss assessment, business impact, and regulatory implications (ITAR).
Attack Timeline 20 Complete chronological reconstruction from initial exploitation through exfiltration. Minimum 10 events with timestamps and evidence source references.
Initial Access Analysis 15 Detailed Log4j exploit chain analysis. Attacker IP, vulnerability exploited, callback mechanism, staging infrastructure.
Lateral Movement Map 15 Network diagram showing the hop-by-hop path from DMZ to internal file server. Protocols, ports, and data volumes at each hop.
Data Exfiltration Assessment 15 Total data exfiltrated, exfiltration method, destination infrastructure, timing analysis. Assessment of what data may have been stolen.
IOC List 10 Comprehensive, actionable IOC list: IPs, domains, JA3 hashes, certificates, URIs, Suricata SIDs. Formatted for SIEM ingestion.
Recommendations 15 Immediate: containment actions. Short-term: patching, hunting, credential resets. Long-term: network segmentation, monitoring improvements, ITAR notification requirements.

Answer Key: Attack Reconstruction

Complete Attack Chain

  • 09:14 -- Attacker (203.0.113.100) exploits Log4j (CVE-2021-44228) on DMZ web server (10.10.10.5:8443) via JNDI injection in User-Agent header
  • 09:14 -- Web server calls back to attacker's LDAP server (45.33.32.156:1389) to download exploit payload
  • 09:15 -- Payload downloads and executes on web server (Python-based implant, JA3 confirms Python requests library)
  • 09:16 -- DNS tunnel established via data-sync-service.xyz for C2 (2847 TXT queries over 48 hours)
  • 14:22 -- Lateral movement: web server pivots to internal network via SMB to 172.16.1.50 and 172.16.1.51 (DLL deployment)
  • 14:25 -- Second hop: 172.16.1.50 compromises 172.16.5.10 (file server) via SMB
  • 15:00-18:00 -- Port scanning from file server across 172.16.5.0/24 subnet
  • 01:00-02:00 -- Data staging: 12.8 GB copied from 172.16.5.20 (another file server) to 172.16.5.10
  • 02:15-03:45 -- Data exfiltration: 12.2 GB total uploaded in three chunks to 185.220.101.34 via HTTPS (Cobalt Strike beacon)

Critical IOCs

  • 203.0.113.100 -- Initial attacker IP (Log4j exploitation)
  • 45.33.32.156 -- LDAP/staging server, hosts data-sync-service.xyz NS
  • 185.220.101.34 -- Exfiltration server (cloud-backup-service.net)
  • data-sync-service.xyz -- DNS tunnel C2 domain (registered 3 days prior)
  • cloud-backup-service.net -- Exfiltration cover domain
  • JA3: e35df3e00ca4ef31d42b34bebaa2f86e (Python implant)
  • JA3: a0e9f5d64349fb13191bc781f81f42e1 (Cobalt Strike exfil)
  • MITRE: T1190 (Initial Access), T1572 (Protocol Tunneling), T1021.002 (SMB Lateral), T1041 (Exfiltration Over C2)

Regulatory Impact

As a defense contractor, Atlas Engineering is subject to ITAR (International Traffic in Arms Regulations). Unauthorized access to or exfiltration of ITAR-controlled data requires notification to the Directorate of Defense Trade Controls (DDTC) within 60 days. Additionally, if the attacker is a nation-state actor, DFARS 252.204-7012 requires notification to DoD CIO within 72 hours. This incident has significant regulatory and legal consequences beyond the technical compromise.

Key Takeaways

  • Network forensics requires correlating IDS alerts, flow data, DNS logs, and TLS metadata
  • The attack chain follows a predictable pattern: exploit, establish C2, move laterally, stage data, exfiltrate
  • DNS tunneling provided the initial C2 channel; Cobalt Strike over HTTPS handled the exfiltration
  • Timing analysis reveals attacker operational patterns (exfiltration at 2 AM, 30-minute chunks)
  • JA3 fingerprints distinguished between tools used at different attack phases
  • Regulatory context (ITAR, DFARS) determines notification requirements and investigation urgency
  • The investigation report is the deliverable that drives containment, remediation, and legal response
