Capture Filters vs Display Filters

Wireshark uses two completely different filter systems. Confusing them is a common mistake that wastes investigation time.

Aspect Capture Filter (BPF) Display Filter
When applied Before capture starts After packets are captured
Syntax Berkeley Packet Filter Wireshark display filter
Changeable No (must restart capture) Yes (any time)
Performance Reduces capture load No effect on capture
Host filter host 10.0.0.1 ip.addr == 10.0.0.1
Port filter port 443 tcp.port == 443
Protocol filter tcp tcp

Forensic Rule

When in doubt, capture everything and filter later. You cannot analyze packets you did not capture. Use capture filters only when disk space or performance demands it. Display filters let you explore the full capture without losing data.

Essential Display Filters for Forensics

Investigation-Ready Display Filters
# Find all DNS queries
dns.qry.name contains "suspicious-domain"

# HTTP requests with specific methods
http.request.method == "POST"
http.request.method == "GET" and http.host contains "evil"

# Find failed TCP connections (SYN without SYN-ACK)
tcp.flags.syn == 1 and tcp.flags.ack == 0

# TLS Client Hello (identify outbound encrypted connections)
tls.handshake.type == 1

# SMB file access (lateral movement)
smb2.cmd == 5  # Create Request

# Large data transfers (potential exfiltration)
tcp.len > 10000

# Traffic to/from specific country (using GeoIP if configured)
ip.geoip.dst_country == "RU"

# Exclude known-good traffic to focus on unknowns
!(ip.addr == 10.0.0.0/8) and !(dns) and !(arp)

# Find cleartext credentials (FTP login)
ftp.request.command == "USER" or ftp.request.command == "PASS"

# ICMP tunneling indicators (unusually large ICMP packets)
icmp and data.len > 64

Statistical Analysis Tools

Before diving into individual packets, use Wireshark's statistical tools to get the big picture.

Protocol Hierarchy (Statistics menu) Shows percentage breakdown of all protocols in the capture. Unusual protocols (IRC, Telnet, custom ports) stand out immediately. A capture dominated by DNS might indicate DNS tunneling.
Conversations (Statistics menu) Lists all communication pairs with byte counts and packet counts. Sort by bytes to find the largest data transfers. High-volume conversations to unknown IPs are immediate red flags.
Endpoints (Statistics menu) Lists all unique IP addresses and MAC addresses with traffic volume. Identifies the busiest hosts. Unknown endpoints with high traffic warrant investigation.
IO Graphs (Statistics menu) Visualize traffic volume over time. Beaconing shows as regular spikes at consistent intervals. Data exfiltration shows as sustained high-volume periods.

Following Streams

Stream following is one of Wireshark's most powerful features. It reconstructs the full conversation between two endpoints, showing you the data as it was exchanged.

Stream Types
# Right-click any packet > Follow > [Stream Type]

TCP Stream -- Reconstructs the full TCP session
  Use for: HTTP sessions, FTP commands, Telnet sessions,
           any TCP-based protocol

UDP Stream -- Groups related UDP packets
  Use for: DNS conversations, DHCP exchanges,
           custom UDP protocols

HTTP Stream -- Reconstructs HTTP request/response pairs
  Use for: Web traffic analysis, file downloads,
           API calls, form submissions

TLS Stream -- Shows encrypted TLS data
  Use for: Identifying TLS versions, seeing handshake
           details (requires decryption keys for content)
Example: Following an HTTP POST (credential theft)
# TCP Stream reveals cleartext POST data:

POST /login.php HTTP/1.1
Host: internal-portal.company.com
Content-Type: application/x-www-form-urlencoded
Content-Length: 47

username=admin&password=P@ssw0rd123&remember=on

HTTP/1.1 302 Found
Location: /dashboard.php
Set-Cookie: session=a8f3d2e1b4c5...

Credential Exposure

HTTP POST forms transmit credentials in cleartext. Any packet capture on the network segment will contain these passwords. This is why TLS everywhere matters -- and why you should always check for cleartext credential transmission during forensic analysis.

Expert Information

Wireshark's Expert Information system (Analyze > Expert Information) automatically flags protocol anomalies, errors, and warnings. It categorizes findings by severity:

Severity Meaning Forensic Relevance
Error Protocol errors, malformed packets May indicate crafted packets, exploit attempts, or tool artifacts
Warning Unusual but valid protocol behavior TCP retransmissions, out-of-order segments, connection resets
Note Notable events TCP window updates, keep-alive packets, reassembly events
Chat Normal protocol operations Connection establishment, protocol negotiations

Decode As

When traffic uses non-standard ports, Wireshark may not decode it correctly. The "Decode As" feature (right-click packet > Decode As) lets you tell Wireshark to interpret traffic on any port as a specific protocol.

Common Decode As Scenarios

  • HTTP on port 8080, 8443, or 8888 -- decode as HTTP
  • C2 traffic on port 4444 that is actually HTTP -- decode as HTTP to see commands
  • Custom ports running TLS -- decode as TLS to see handshake details
  • DNS on non-standard ports (tunneling) -- decode as DNS

Practice: Build Forensic Filters

Write a Wireshark display filter for each investigation scenario:

  1. Show all traffic from IP 10.0.0.50 that is NOT DNS and NOT to the internal network (10.0.0.0/8)
  2. Find all HTTP requests that download executable files (.exe, .dll, .scr)
  3. Identify potential port scanning (TCP SYN to more than one destination port)
  4. Show all TLS Client Hello messages to identify what encrypted connections were established
  5. Find ICMP packets larger than 100 bytes (possible ICMP tunneling)

Answers:

1. ip.src == 10.0.0.50 and !dns and !ip.dst == 10.0.0.0/8

2. http.request.uri matches "\.(exe|dll|scr)$"

3. tcp.flags.syn == 1 and tcp.flags.ack == 0 (then check Conversations for hosts with many destination ports)

4. tls.handshake.type == 1

5. icmp and data.len > 100

Key Takeaways

  • Capture filters (BPF) reduce what is captured; display filters explore what was captured
  • Protocol Hierarchy and Conversations give the big picture before packet-level analysis
  • Following streams reconstructs full conversations -- essential for credential and data analysis
  • Expert Information automatically flags anomalies and protocol errors
  • Decode As handles traffic on non-standard ports
  • IO Graphs reveal beaconing patterns and exfiltration events over time
