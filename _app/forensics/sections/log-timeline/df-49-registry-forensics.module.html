Learning Objectives

  • Understand Windows Registry structure: hives, keys, values, and types
  • Extract forensic artifacts from SAM, SYSTEM, SOFTWARE, and NTUSER.DAT hives
  • Identify persistence mechanisms in registry Run keys and services
  • Analyze USB device history from USBSTOR registry entries
  • Use Registry Explorer and RegRipper for automated analysis

Registry Structure

The Windows Registry is a hierarchical database that stores OS configuration, user preferences, installed software, and hardware information. For forensic investigators, the registry is a goldmine -- it records user activity, persistence mechanisms, connected devices, network connections, and application usage, often with timestamps.

Hive File Disk Location Mounted At
SAM C:\Windows\System32\config\SAM HKLM\SAM
SYSTEM C:\Windows\System32\config\SYSTEM HKLM\SYSTEM
SOFTWARE C:\Windows\System32\config\SOFTWARE HKLM\SOFTWARE
SECURITY C:\Windows\System32\config\SECURITY HKLM\SECURITY
NTUSER.DAT C:\Users\[username]\NTUSER.DAT HKCU (per-user)
UsrClass.dat C:\Users\[username]\AppData\Local\Microsoft\Windows\UsrClass.dat HKCU\Software\Classes

Transaction Logs

Each hive has associated transaction log files (.LOG1, .LOG2) that contain recent changes not yet flushed to the main hive file. When analyzing offline hives, use tools that merge transaction logs to ensure you see the most recent data. Registry Explorer does this automatically.

SAM Hive -- User Accounts

The SAM (Security Account Manager) hive contains local user account information including usernames, RIDs (Relative Identifiers), account creation timestamps, last login times, password hashes, and account flags.

Key SAM Registry Paths
# User account list
SAM\Domains\Account\Users\Names\

# User account details (per RID)
SAM\Domains\Account\Users\000001F4   # RID 500 = Administrator
SAM\Domains\Account\Users\000003E9   # RID 1001 = first created user

# Forensic data per account:
# - Account creation time
# - Last login timestamp
# - Login count
# - Password last changed
# - Account disabled/enabled flag
# - NT hash and LM hash (if stored)

SYSTEM Hive -- Services, Devices, Network

Key SYSTEM Registry Paths
# Installed services (persistence mechanism)
SYSTEM\CurrentControlSet\Services\
# Look for: ImagePath pointing to unusual locations (Temp, AppData)
# Look for: Start value = 2 (auto-start) with suspicious names

# USB device history (USBSTOR)
SYSTEM\CurrentControlSet\Enum\USBSTOR\
# Records: Device class, vendor, product, serial number
# Timestamps: First connected, last connected, last removed

# Computer name
SYSTEM\CurrentControlSet\Control\ComputerName\ComputerName

# Timezone (critical for timestamp correlation)
SYSTEM\CurrentControlSet\Control\TimeZoneInformation

# Network interfaces
SYSTEM\CurrentControlSet\Services\Tcpip\Parameters\Interfaces\
# IP addresses, DHCP settings, DNS servers, gateway

# Last shutdown time
SYSTEM\CurrentControlSet\Control\Windows\ShutdownTime

USB Forensics via USBSTOR

The USBSTOR key records every USB storage device ever connected. Cross-reference with SYSTEM\MountedDevices to find drive letter assignments and with NTUSER.DAT\Software\Microsoft\Windows\CurrentVersion\Explorer\MountPoints2 to tie devices to specific user accounts. This chain of evidence proves that a specific user connected a specific device at a specific time.

SOFTWARE Hive -- Applications and Persistence

Key SOFTWARE Registry Paths
# Auto-start programs (persistence)
SOFTWARE\Microsoft\Windows\CurrentVersion\Run
SOFTWARE\Microsoft\Windows\CurrentVersion\RunOnce
SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Run

# Installed programs
SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\
# Install dates, versions, publisher information

# Network profiles (Wi-Fi/Ethernet history)
SOFTWARE\Microsoft\Windows NT\CurrentVersion\NetworkList\Profiles\
# Network names, first/last connection timestamps, network type

# OS information
SOFTWARE\Microsoft\Windows NT\CurrentVersion\
# Build number, install date, registered owner, product name

NTUSER.DAT -- User Activity

Each user profile has an NTUSER.DAT hive that records user-specific activity. This is often the most forensically rich hive for understanding what a user did.

Key NTUSER.DAT Paths
# User-specific auto-start (persistence per user)
NTUSER\Software\Microsoft\Windows\CurrentVersion\Run
NTUSER\Software\Microsoft\Windows\CurrentVersion\RunOnce

# Recent documents
NTUSER\Software\Microsoft\Windows\CurrentVersion\Explorer\RecentDocs\

# Typed paths in Explorer address bar
NTUSER\Software\Microsoft\Windows\CurrentVersion\Explorer\TypedPaths

# Run dialog history (Win+R)
NTUSER\Software\Microsoft\Windows\CurrentVersion\Explorer\RunMRU

# UserAssist -- program execution tracking (ROT13 encoded)
NTUSER\Software\Microsoft\Windows\CurrentVersion\Explorer\UserAssist\
# Execution count, last execution time, focus time

# Mounted network shares
NTUSER\Software\Microsoft\Windows\CurrentVersion\Explorer\MountPoints2\

UserAssist Decoding

UserAssist entries are ROT13 encoded to prevent casual observation. For example, PNYPF.RKR decodes to CALCS.EXE. Registry Explorer and RegRipper automatically decode these entries, but if you are working manually, apply ROT13 to the value names to reveal the actual program paths.

Forensic Tools

RegRipper -- Automated Registry Analysis
# Run RegRipper against a hive file
rip.pl -r /evidence/SYSTEM -p compname
rip.pl -r /evidence/SYSTEM -p services
rip.pl -r /evidence/SYSTEM -p usbstor
rip.pl -r /evidence/SAM -p samparse
rip.pl -r /evidence/NTUSER.DAT -p userassist
rip.pl -r /evidence/SOFTWARE -p autoruns

# Run all plugins for a hive type
rip.pl -r /evidence/NTUSER.DAT -a > ntuser_full_analysis.txt
Tool Type Strength
Registry Explorer GUI (Eric Zimmerman) Merges transaction logs, bookmarks forensic keys, hex/decoded views, timeline generation
RegRipper CLI (Harlan Carvey) Plugin-based, automated extraction, scriptable for batch processing
regedit Built-in Windows Load hives via File > Load Hive for quick inspection on live systems

Practice: Extract Forensic Artifacts

Given the following registry entries found during an investigation, identify the forensic significance of each:

  1. HKLM\SYSTEM\CurrentControlSet\Services\WinUpdateSvc -- ImagePath: C:\Windows\Temp\svchost.exe, Start: 2
  2. HKCU\Software\Microsoft\Windows\CurrentVersion\Run -- "SystemCheck" = "powershell -ep bypass -w hidden -f C:\Users\jsmith\AppData\beacon.ps1"
  3. HKLM\SYSTEM\CurrentControlSet\Enum\USBSTOR\Disk&Ven_SanDisk&Prod_Ultra&Rev_1.00 -- Serial: 4C530000110823
  4. HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\RunMRU -- a: "cmd /c net user hacker P@ss /add"

Analysis: (1) Malicious service persistence -- legitimate svchost.exe does not run from Temp directory; auto-start on boot. (2) PowerShell-based persistence -- bypasses execution policy, runs hidden, executes beacon script on every user logon. (3) SanDisk Ultra USB device was connected -- serial number uniquely identifies the specific device for evidence tracking. (4) User executed a command to create a backdoor account named "hacker" -- preserved in Run dialog history even if command prompt was closed.

Key Takeaways

  • Registry hives (SAM, SYSTEM, SOFTWARE, NTUSER.DAT) are stored as files under C:\Windows\System32\config\ and user profiles
  • SAM hive reveals user accounts, creation times, login counts, and password hashes
  • SYSTEM hive contains services (persistence), USBSTOR (device history), and timezone info
  • SOFTWARE hive stores Run keys (persistence) and installed program records
  • NTUSER.DAT records user activity: recent docs, typed paths, RunMRU, UserAssist (execution tracking)
  • Always collect transaction logs (.LOG1, .LOG2) alongside hive files
  • Registry Explorer and RegRipper are the primary analysis tools for offline hive examination
