The Super Timeline Concept

A super timeline is a unified, chronologically ordered view of every timestamped artifact from a forensic image. Rather than examining file system timestamps, event logs, browser history, and registry entries separately, a super timeline merges them all into a single stream. This approach, pioneered by Kristinn Gudjonsson, revolutionized forensic analysis by making it possible to see exactly what happened on a system at any given moment.

Plaso (Plaso Langar Yfir Stafla -- "Plaso parses logs from all over") is the open-source implementation of the super timeline framework. It consists of two primary tools: log2timeline.py for extraction and psort.py for processing and output.

pip3 install plaso

docker pull log2timeline/plaso

Processing Pipeline

The Plaso workflow follows a three-stage pipeline: extract, process, and output.

Stage 1: Extraction with log2timeline.py
# Process a forensic disk image (E01 format)
log2timeline.py --storage-file timeline.plaso /evidence/disk.E01

# Process a raw DD image
log2timeline.py --storage-file timeline.plaso /evidence/disk.dd

# Process a mounted directory (live system artifacts)
log2timeline.py --storage-file timeline.plaso /mnt/evidence/

# Use specific parsers only (faster, targeted)
log2timeline.py --parsers "winevtx,prefetch,mft,winreg" \
    --storage-file timeline.plaso /evidence/disk.E01

# Process with status updates
log2timeline.py --status_view linear --storage-file timeline.plaso /evidence/disk.E01
Stage 2: Processing with psort.py
# Output as CSV (most common for analysis)
psort.py -o l2tcsv -w timeline.csv timeline.plaso

# Output as dynamic format (includes all fields)
psort.py -o dynamic -w timeline_dynamic.csv timeline.plaso

# Filter by date range
psort.py -o l2tcsv -w filtered.csv timeline.plaso \
    "date > '2026-03-14 00:00:00' AND date < '2026-03-16 00:00:00'"

# Filter by source type
psort.py -o l2tcsv -w evtx_only.csv timeline.plaso \
    "source_short == 'EVT'"

# Output as XLSX for spreadsheet analysis
psort.py -o xlsx -w timeline.xlsx timeline.plaso

Processing Time and Storage

Super timeline generation is resource-intensive. A 500GB disk image can take 6-12 hours to process and produce a timeline file exceeding 10GB. Plan accordingly. Use targeted parsers (--parsers) and date filters to reduce scope when investigating a known time window.

Timeline Analysis Methodology

A raw super timeline can contain millions of events. Without a systematic approach, you will drown in data. Follow this methodology:

1. Establish Known Pivots Start with known indicators: a specific timestamp from an IDS alert, a filename from malware analysis, a user account from the incident report. Filter the timeline around these pivots.
2. Define Time Windows Narrow the timeline to the relevant period. If the IDS alert was at 14:23, start your analysis window at 14:00 (or earlier) and extend 2-4 hours past the last known indicator.
3. Identify Anomalies Look for events that break the pattern: executable files created in temp directories, services installed at unusual hours, user accounts created outside business hours.
4. Map to Attack Framework Categorize findings into MITRE ATT&CK phases: Initial Access, Execution, Persistence, Privilege Escalation, Lateral Movement, Exfiltration.

Practice: Build a Super Timeline Analysis Plan

You have received a forensic image from a compromised Windows workstation. The IDS alert indicates suspicious outbound traffic to a known C2 server starting at 2026-03-15T14:23:00Z. Plan your Plaso analysis:

  1. What log2timeline.py command would you run? Which parsers would you prioritize?
  2. What psort.py filter would you apply to focus your analysis?
  3. What time window would you initially examine?
  4. What MACB patterns would indicate the malware delivery?

Sample Answers: (1) log2timeline.py --parsers "winevtx,prefetch,mft,winreg,chrome_history,lnk" --storage-file case.plaso evidence.E01. (2) psort.py -o l2tcsv -w focused.csv case.plaso "date > '2026-03-15 12:00:00' AND date < '2026-03-16 00:00:00'". (3) Start 2+ hours before the alert (12:00) to capture initial access vectors. (4) Look for "...B" (Born/Created) entries in suspicious directories like \Users\*\AppData\Local\Temp\ or \Windows\Temp\ just before the C2 traffic began.

Key Takeaways

  • A super timeline merges all timestamped artifacts into one chronological view
  • Plaso pipeline: log2timeline.py (extract) -> psort.py (filter/output)
  • Use targeted parsers (--parsers flag) to reduce processing time when the scope is known
  • L2T CSV is the standard output format with MACB, source, user, host, and description fields
  • Always start analysis from known pivot points -- do not try to read millions of events linearly
  • Super timeline processing is resource-intensive -- plan for hours of processing time on large images
  • Map timeline findings to MITRE ATT&CK phases for structured reporting
