Learning Objectives

  • Construct a forensic timeline from multiple log sources

  • Organize evidence chronologically with source attribution
  • Write timeline entries with proper evidence citations
  • Complete a web server compromise investigation from raw log data

Scenario: Web Server Compromise

Your organization's web server (webprod01, IP 10.1.1.50) triggered an IDS alert for outbound connections to a known malicious IP (198.51.100.42) on 2026-03-15 at 16:45 UTC. You have been tasked with determining how the server was compromised and what the attacker did after gaining access.

You have collected the following evidence sources from the server. Your job is to analyze each source, construct an ordered timeline, and classify each event into the appropriate attack phase.

Your Task: Construct the Timeline

Using the six sources above, construct an ordered timeline. Use the template below. For each entry, cite the specific source and classify the ATT&CK phase.

Time (UTC) Event Source ATT&CK Phase
15:31:02 Attacker (203.0.113.77) probes /admin/ -- 403 denied Apache access + error Reconnaissance
15:31:05-25 Brute-force admin login (3 attempts, success on 3rd) Apache access Initial Access
15:34:12 Webshell (shell.php) uploaded via file manager Apache access + error + file timestamps Execution
15:35:01-08 Webshell accessed, exec() called -- command execution Apache access + error Execution
15:36:22-44 SSH brute force, successful login as www-data auth.log Persistence
15:37:11 sudo apt update (testing privilege escalation) auth.log Privilege Escalation
15:38:02-15 Downloaded attack tools from C2 server auth.log + file timestamps + bash_history Execution
16:01:33-02:11 Created backdoor user "sysadm" with sudo access auth.log Persistence
16:05:01 Cron job installed for C2 beacon (every 5 minutes) cron log + file timestamps Persistence / C2
16:10:01+ C2 beacon executing on schedule cron log Command & Control
After 16:10 Network scanning (10.1.1.0/24), SSH to .51, MySQL to .52 bash_history (sysadm) Lateral Movement

Analysis Questions

  1. What was the initial access vector? -- Admin panel brute force via web application
  2. How many persistence mechanisms did the attacker establish? -- Three: webshell, backdoor user account, cron job C2 beacon
  3. What evidence suggests lateral movement planning? -- Network scanner execution and SSH/MySQL connection attempts to internal hosts
  4. What remediation actions are needed? -- Remove webshell, delete sysadm user, remove cron job, change all credentials, patch admin panel, investigate 10.1.1.51 and 10.1.1.52 for compromise
  5. What logs should be collected from other systems? -- auth.log and access logs from 10.1.1.51 and 10.1.1.52, firewall logs for connections from webprod01, DNS logs for 198.51.100.42 lookups

Key Takeaways

  • Multiple log sources tell different parts of the same story -- no single source is complete
  • Chronological ordering reveals the attack progression from recon to lateral movement
  • ATT&CK phase classification structures your analysis for reporting
  • Bash history provides attacker intent, but is easily deleted -- always collect early
  • File timestamps corroborate log entries and fill gaps where logs are missing
  • A compromise investigation does not end at the compromised host -- lateral movement requires expanding scope
