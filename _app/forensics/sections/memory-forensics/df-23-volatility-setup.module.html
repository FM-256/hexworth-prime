Volatility 2 vs Volatility 3

Volatility is the dominant open-source memory forensics framework. Version 2 (Python 2, profile-based) dominated the field for over a decade. Version 3 (Python 3, symbol-table-based) is the current release and the focus of this track.

Feature Volatility 2 Volatility 3
Python Version Python 2.7 Python 3.7+
OS Identification Profiles (e.g., Win7SP1x64) Automatic via ISF symbol tables
Plugin Syntax vol.py --profile=X plugin vol -f image plugin
Plugin Naming pslist windows.pslist.PsList
Output Formats Text, JSON Text, JSON, CSV, tree rendering
Status Legacy (no new development) Active development

Which Version to Use

Use Volatility 3 for all new work. Many tutorials and CTF writeups still reference Vol2 syntax. The commands in this track use Vol3 syntax exclusively, but we note the Vol2 equivalent where it helps with legacy documentation.

Installation

Volatility 3 Installation
# Clone the repository
$ git clone https://github.com/volatilityfoundation/volatility3.git
$ cd volatility3

# Install dependencies
$ pip3 install -r requirements.txt

# Verify installation
$ python3 vol.py -h
Volatility 3 Framework 2.5.2
usage: vol.py [-h] [-c CONFIG] [-e EXTEND] [-p PLUGIN_DIRS]
              [-s SYMBOL_DIRS] [-v] [-l LOG] [-o OUTPUT_DIR]
              [-q] [-r RENDERER] [-f FILE] [--write-config]
              [plugin] ...

# Download Windows symbol tables (ISF files)
$ cd volatility3/symbols
$ wget https://downloads.volatilityfoundation.org/volatility3/symbols/windows.zip
$ unzip windows.zip

Symbol Tables are Essential

Volatility 3 uses Intermediate Symbol Format (ISF) files instead of profiles. Without the correct symbol tables, plugins cannot parse kernel structures. Download the symbol packs for Windows, Linux, and macOS from the Volatility Foundation website.

Basic Plugin Workflow

Volatility plugins follow a consistent pattern. You specify the memory image, the plugin namespace (windows/linux/mac), and optional output formatting:

Plugin Syntax Pattern
# General syntax
$ python3 vol.py -f <image> <plugin> [options]

# List all available plugins
$ python3 vol.py -f memory.raw --help | grep windows
    windows.pslist.PsList
    windows.psscan.PsScan
    windows.pstree.PsTree
    windows.netscan.NetScan
    windows.malfind.Malfind
    windows.dlllist.DllList
    windows.cmdline.CmdLine
    windows.handles.Handles
    ...

# Quick process listing (your first triage command)
$ python3 vol.py -f memory.raw windows.pslist
PID   PPID  ImageFileName     Offset(V)        Threads  Handles  Wow64
4     0     System            0xfa8000c62040   104      --       False
88    4     Registry          0xfa8000d15080   4        --       False
348   4     smss.exe          0xfa8001735300   2        --       False
444   436   csrss.exe         0xfa80018f4080   10       --       False
...

# Output to JSON for scripting
$ python3 vol.py -f memory.raw -r json windows.pslist > processes.json

Common First-Run Plugins

windows.info Identifies the OS version, kernel base, system time, and number of processors. Always run this first to validate your image.
windows.pslist Lists running processes from the EPROCESS linked list. Fast but can be evaded by rootkits that unlink processes.
windows.pstree Shows parent-child process relationships as a tree. Essential for spotting anomalous process hierarchies.
windows.cmdline Extracts the full command line for each process. Reveals encoded PowerShell commands, suspicious arguments, and malware parameters.

Practice: Volatility First Run

Download a sample memory image from the Volatility Foundation's sample repository and perform initial triage:

  1. Run windows.info to identify the OS version and capture time
  2. Run windows.pslist and count the total number of processes
  3. Run windows.pstree and identify which process has the most child processes
  4. Run windows.cmdline and look for any processes launched with unusual arguments
  5. Export the pslist output to JSON using -r json

Key Takeaways

  • Volatility 3 uses Python 3 and automatic symbol table resolution -- no manual profile selection
  • Download ISF symbol packs before your first analysis -- plugins fail without them
  • Always start with windows.info to validate the image and identify the OS build
  • Plugin names follow the pattern: os.category.PluginName (e.g., windows.pslist.PsList)
  • Vol2 profiles like "Win7SP1x64" are replaced by automatic ISF matching in Vol3
  • JSON output (-r json) enables scripted analysis and integration with other tools
