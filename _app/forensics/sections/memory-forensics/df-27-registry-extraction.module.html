DF-27

Registry Hive Extraction from Memory

< Forensics Hub
Dashboard / Forensics Hub / Memory Forensics / DF-27: Registry Hive Extraction

Learning Objectives

  • Enumerate registry hives loaded in memory using hivelist
  • Extract specific registry keys and values with printkey
  • Recover SAM database entries for user account analysis
  • Identify cached credentials and password hashes from memory
  • Detect persistence mechanisms through autorun registry keys

Why Registry from Memory?

The Windows registry is loaded into memory for active use. Extracting it from a memory dump has a key advantage over disk-based analysis: the in-memory version reflects the most recent state, including changes not yet flushed to disk. If malware modifies the registry and the system crashes or is captured before the next flush cycle, only the memory version contains those changes.

Additionally, some registry-resident malware stores payloads in registry values that are loaded into memory but may be encrypted or obfuscated on disk. The in-memory version may contain the decrypted payload.

Reading Registry Keys

printkey - Extracting Registry Values
# Check the most common autorun location
$ python3 vol.py -f memory.raw windows.registry.printkey \
    --key "Software\Microsoft\Windows\CurrentVersion\Run"

Key:       Software\Microsoft\Windows\CurrentVersion\Run
Last write: 2026-03-12 14:16:02.000000

  Value      Type      Data
  SecurityHealth  REG_EXPAND_SZ  %ProgramFiles%\Windows Defender\MSASCuiL.exe
  OneDrive        REG_SZ         "C:\Users\admin\AppData\Local\Microsoft\OneDrive\OneDrive.exe" /background
  WindowsUpdate   REG_SZ         C:\ProgramData\svchost.exe -k netsvcs

# That last entry is suspicious: svchost.exe in ProgramData with service args
# Legitimate svchost.exe lives in C:\Windows\System32\

# Check SYSTEM hive for service-based persistence
$ python3 vol.py -f memory.raw windows.registry.printkey \
    --key "ControlSet001\Services\WindowsUpdateSvc"

Key:       ControlSet001\Services\WindowsUpdateSvc
Last write: 2026-03-12 14:16:01.000000

  Value        Type       Data
  Type         REG_DWORD  16
  Start        REG_DWORD  2
  ImagePath    REG_SZ     C:\ProgramData\svchost.exe
  DisplayName  REG_SZ     Windows Update Service
  ObjectName   REG_SZ     LocalSystem

Credential Extraction from Memory

Memory dumps can contain plaintext credentials if wdigest authentication is enabled (common on older systems and some domain configurations). Even on modern systems, NTLM hashes and Kerberos tickets in memory enable pass-the-hash and pass-the-ticket attacks. This is why memory forensics is critical for understanding the full scope of a breach.

Persistence Detection via Registry

Run / RunOnce Keys HKLM and HKCU Run keys execute programs at logon. The most common persistence mechanism. Check both machine and user hives.
Services ControlSet001\Services entries start automatically at boot. Attackers create services with legitimate-sounding names pointing to malicious executables.
Scheduled Tasks Task entries in SOFTWARE\Microsoft\Windows NT\CurrentVersion\Schedule\TaskCache. Survive reboots and can run with SYSTEM privileges.
Winlogon / Shell SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon Shell and Userinit values. Replacing these hijacks the logon sequence.

Key Autorun Locations to Check

  • Software\Microsoft\Windows\CurrentVersion\Run
  • Software\Microsoft\Windows\CurrentVersion\RunOnce
  • SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon (Shell, Userinit)
  • ControlSet001\Services\* (ImagePath values)
  • Software\Microsoft\Windows\CurrentVersion\Explorer\Shell Folders (Startup folder)

Practice: Registry Investigation

Using the printkey plugin on a memory dump, investigate these scenarios:

  1. Check all four Run key locations (HKLM Run, HKLM RunOnce, HKCU Run, HKCU RunOnce) for unfamiliar entries
  2. Look at the SAM hive to identify any user accounts created within the last 24 hours before capture
  3. Examine the Services registry for entries with ImagePath values pointing outside of C:\Windows\
  4. Check the Winlogon key to ensure Shell is set to "explorer.exe" and Userinit to "C:\Windows\system32\userinit.exe,"

Key Takeaways

  • In-memory registry reflects the most current state, including unflushed changes
  • hivelist enumerates all loaded hives; printkey reads specific keys and values
  • SAM extraction reveals local accounts, including backdoor accounts created by attackers
  • hashdump extracts NTLM password hashes for offline cracking or pass-the-hash analysis
  • Check Run keys, Services, Winlogon, and Scheduled Tasks for persistence mechanisms
  • Compare registry timestamps with your incident timeline to identify attacker modifications
