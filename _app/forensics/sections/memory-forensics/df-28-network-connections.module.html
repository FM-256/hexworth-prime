Learning Objectives

  • Extract active and recently closed network connections using netscan
  • Correlate network connections with process IDs from process analysis
  • Identify C2 beacon patterns in connection data
  • Detect data exfiltration indicators through connection analysis
  • Cross-reference network findings with other memory artifacts

Network State in Memory

Network connections are among the most volatile artifacts in memory. Active TCP connections, listening sockets, and UDP endpoints are maintained in kernel structures that change continuously. A memory capture preserves a snapshot of all network activity at the exact moment of acquisition -- something that netstat on a live system cannot guarantee due to the observer effect.

This is particularly valuable for identifying Command and Control (C2) communications. Malware that connects to C2 servers intermittently may have an active connection at capture time, providing direct evidence of the C2 infrastructure.

Netscan: The Primary Network Plugin

netscan Output - Active Connections
$ python3 vol.py -f memory.raw windows.netscan

Three entries are immediately suspicious. PID 3284 (svchost.exe) -- already flagged in process analysis -- has connections to two external IPs on ports 443 and 8443, plus a lateral movement connection to an internal host on SMB (445). PID 3312 (powershell.exe) has an SSH connection to another internal host.

Identifying C2 Beacons

Command and Control beacons have recognizable patterns in network connection data. Understanding these patterns helps distinguish malicious connections from legitimate traffic.

Unusual Ports C2 servers often use high ports (8443, 4444, 8080) or standard ports (443, 80) to blend in. HTTPS on port 8443 from svchost.exe is suspicious.
Unexpected Processes svchost.exe making external HTTPS connections is abnormal. Legitimate svchost connections go to Microsoft services, not arbitrary IPs.
Non-Standard Destinations Connections to IP addresses rather than hostnames, or to hosting providers in unusual geolocations. Residential ISP IPs used as C2 redirectors.
Lateral Movement SMB (445), WinRM (5985/5986), RDP (3389), SSH (22) connections from compromised processes to other internal hosts indicate lateral spread.

Correlating PIDs to Processes

Always cross-reference the PID from netscan with your pslist/pstree output. A connection from PID 3284 is meaningless without knowing that PID 3284 is the suspicious svchost.exe you identified in process analysis. Build a map: PID to process name to parent process to network connections to injected code.

Building the Connection Map

Cross-Referencing Network and Process Data
# Step 1: Identify suspicious connections
# PID 3284 (svchost.exe) -> 185.234.72.19:443 (C2 #1)
# PID 3284 (svchost.exe) -> 45.77.123.88:8443 (C2 #2)
# PID 3284 (svchost.exe) -> 192.168.1.10:445 (lateral movement)
# PID 3312 (powershell.exe) -> 10.0.1.100:22 (lateral movement)

# Step 2: Correlate with process tree
svchost.exe (PID 784, legitimate) 
  -> cmd.exe (PID 3284)                   # Exploitation chain
     -> powershell.exe (PID 3312)          # Post-exploitation

# Step 3: Build IOC summary
C2 Infrastructure:
  185.234.72.19:443   (Primary C2)
  45.77.123.88:8443   (Secondary C2 / exfil)
Lateral Movement Targets:
  192.168.1.10:445    (SMB - file share access or PsExec)
  10.0.1.100:22       (SSH - Linux host pivot)

Closed Connections

netscan can also recover recently closed TCP connections from residual kernel pool memory. These appear with state CLOSED or TIME_WAIT. They represent connections that were active recently but have since terminated. These are valuable for building a complete timeline of network activity.

Listening Sockets: Backdoor Detection

Listening sockets that were not present before the incident may indicate backdoors. An attacker who binds a reverse shell to a port creates a LISTENING socket that netscan will capture.

Detecting Backdoor Listeners
# Filter netscan output for LISTENING sockets
$ python3 vol.py -f memory.raw windows.netscan | grep LISTENING

0xe00001a52900  TCPv4  0.0.0.0   135    0.0.0.0  0  LISTENING  884   svchost.exe
0xe00001a71230  TCPv4  0.0.0.0   445    0.0.0.0  0  LISTENING  4     System
0xe00001a89340  TCPv4  0.0.0.0   3389   0.0.0.0  0  LISTENING  1048  svchost.exe
0xe00002f10500  TCPv4  0.0.0.0   4444   0.0.0.0  0  LISTENING  3284  svchost.exe
0xe00003110600  TCPv4  0.0.0.0   8888   0.0.0.0  0  LISTENING  3312  powershell.exe

# Port 4444 (classic Metasploit) and 8888 from compromised processes
# These are bind shell backdoors waiting for attacker connections

Practice: Network Analysis

Given this netscan output, identify all suspicious connections and explain your reasoning:

  1. PID 784 (svchost.exe, PPID services.exe) -> 10.0.1.50:49700 to 20.190.151.70:443 ESTABLISHED
  2. PID 3500 (notepad.exe, PPID explorer.exe) -> 10.0.1.50:49800 to 91.215.85.142:443 ESTABLISHED
  3. PID 2100 (chrome.exe, PPID explorer.exe) -> 10.0.1.50:49900 to 142.250.80.46:443 ESTABLISHED
  4. PID 608 (lsass.exe) -> 0.0.0.0:49155 LISTENING
  5. PID 3500 (notepad.exe) -> 0.0.0.0:9999 LISTENING

Analysis: #1: Likely legitimate (svchost to Microsoft IP on 443). #2: Suspicious (notepad.exe should never make network connections). #3: Legitimate (Chrome to Google IP). #4: Normal (LSASS listens for authentication). #5: Highly suspicious (notepad.exe listening on a high port = bind shell backdoor).

Key Takeaways

  • netscan captures a frozen snapshot of all active, listening, and recently closed connections
  • Always correlate connection PIDs with process analysis results for full context
  • C2 indicators: unusual ports, unexpected processes making external connections, non-standard destinations
  • Lateral movement shows as SMB/WinRM/RDP/SSH connections from compromised processes to internal hosts
  • Unexpected LISTENING sockets on high ports from non-service processes indicate backdoors
  • Build a connection map linking processes to network activity for your investigation report
