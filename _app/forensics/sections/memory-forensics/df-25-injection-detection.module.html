Learning Objectives

  • Understand the major code injection techniques used by malware

  • Analyze DLL lists with dlllist and ldrmodules for discrepancies

  • Recognize reflective DLL injection artifacts

Code Injection Techniques

Attackers inject code into legitimate processes to evade detection, inherit process privileges, and blend into normal system activity. Memory forensics is uniquely positioned to detect these techniques because the injected code must reside in memory to execute.

Classic DLL Injection Uses CreateRemoteThread + LoadLibrary to force a target process to load a malicious DLL. The DLL appears on disk and in the process's module list.
Reflective DLL Injection Loads a DLL from memory without using LoadLibrary. The DLL never touches disk and does not appear in the PEB module lists. Detected by malfind.
Process Hollowing Creates a legitimate process in suspended state, unmaps its memory, replaces it with malicious code, then resumes. The process name looks legitimate but the code is not.
Shellcode Injection Allocates executable memory in a remote process via VirtualAllocEx, writes shellcode with WriteProcessMemory, executes via CreateRemoteThread.

Malfind: Detecting Injected Code

The malfind plugin searches for memory regions with suspicious characteristics: executable permissions (PAGE_EXECUTE_READWRITE), no associated file on disk, and content that looks like executable code (MZ headers, shellcode patterns).

Malfind Output - Injected Code Detected
$ python3 vol.py -f memory.raw windows.malfind

PID   Process          Start VPN       End VPN         Tag   Protection          Hexdump / Disasm

3284  svchost.exe      0x00400000      0x00410000      VadS  PAGE_EXECUTE_READWRITE
4d 5a 90 00 03 00 00 00  MZ......    <-- MZ header = PE file injected
04 00 00 00 ff ff 00 00  ........
b8 00 00 00 00 00 00 00  ........
40 00 00 00 00 00 00 00  @.......

1852  explorer.exe     0x02b10000      0x02b15000      VadS  PAGE_EXECUTE_READWRITE
fc 48 83 e4 f0 e8 c0 00  .H......    <-- Shellcode (no MZ header)
00 00 41 51 41 50 52 51  ..AQAPRQ
56 48 31 d2 65 48 8b 52  VH1.eH.R
60 48 8b 52 18 48 8b 52  `H.R.H.R

Reading Malfind Output

  • PAGE_EXECUTE_READWRITE -- Memory that is both writable and executable. Legitimate code is typically PAGE_EXECUTE_READ (not writable).
  • MZ header (4d 5a) -- A PE executable has been injected into the process. This is a DLL or EXE loaded without the loader.
  • fc 48 83 e4 f0 -- Common Metasploit/Cobalt Strike shellcode prologue. The fc is a CLD instruction, followed by stack alignment.
  • VadS tag -- Indicates a private (non-shared) memory allocation, typical for injected code.

DLL Analysis: dlllist vs ldrmodules

Comparing the DLL lists from different sources reveals hidden or injected modules. The Windows PEB maintains three separate linked lists for loaded modules. Discrepancies between them indicate manipulation.

DLL List Analysis
# List DLLs loaded by a specific process
$ python3 vol.py -f memory.raw windows.dlllist --pid 3284

PID   Process       Base             Size   Name                    Path
3284  svchost.exe   0x7ff678a30000   0x1e000  svchost.exe            C:\Windows\system32\svchost.exe
3284  svchost.exe   0x7ffc8b1f0000   0x1f8000 ntdll.dll              C:\Windows\SYSTEM32\ntdll.dll
3284  svchost.exe   0x7ffc89e60000   0x10d000 KERNEL32.DLL           C:\Windows\System32\KERNEL32.DLL
3284  svchost.exe   0x7ffc88cc0000   0x2f1000 KERNELBASE.dll         C:\Windows\System32\KERNELBASE.dll

# Cross-reference with ldrmodules to find hidden DLLs
$ python3 vol.py -f memory.raw windows.ldrmodules --pid 3284

PID   Process       Base             InLoad  InInit  InMem   MappedPath
3284  svchost.exe   0x7ff678a30000   True    True    True    \Windows\system32\svchost.exe
3284  svchost.exe   0x7ffc8b1f0000   True    True    True    \Windows\SYSTEM32\ntdll.dll
3284  svchost.exe   0x00400000       False   False   False   <-- Not in any list = injected

ldrmodules False/False/False

A module showing False for InLoad, InInit, and InMem with no mapped path is almost certainly injected code. Legitimate DLLs appear in at least one of the three PEB module lists. This is one of the strongest indicators of reflective DLL injection or process hollowing.

Process Hollowing Detection

In process hollowing, the attacker creates a legitimate process (e.g., svchost.exe) in a suspended state, unmaps the original executable from memory, maps malicious code in its place, then resumes the process. The process appears legitimate in Task Manager but executes entirely different code.

Detecting Hollowed Processes
# Step 1: Check if the process image on disk matches memory
$ python3 vol.py -f memory.raw windows.pslist --pid 3284
PID   PPID  ImageFileName     Offset(V)        CreateTime
3284  588   svchost.exe       0xfa800321a080   2026-03-12 14:15:33

# Step 2: Dump the process executable from memory
$ python3 vol.py -f memory.raw windows.procdump --pid 3284 --dump-dir ./dump/
PID   Process       ImageBase       Result
3284  svchost.exe   0x00400000      file.3284.0x400000.dmp

# Step 3: Check if dumped PE matches known svchost.exe hash
$ sha256sum ./dump/file.3284.0x400000.dmp
e4b9c2f1a3d5e7f8... (does NOT match known svchost.exe hash)

# Step 4: Check the PEB image path vs actual code
# The PEB says "svchost.exe" but the code is something else entirely
# This confirms process hollowing

Practice: Injection Analysis

Given the following malfind output, classify each finding:

  1. svchost.exe PID 784 at 0x10000 with PAGE_EXECUTE_READWRITE and bytes 4d 5a 90 00
  2. chrome.exe PID 2100 at 0x7ffc0000 with PAGE_EXECUTE_READ and bytes 4d 5a 90 00
  3. explorer.exe PID 3100 at 0x50000 with PAGE_EXECUTE_READWRITE and bytes fc 48 83 e4
  4. notepad.exe PID 4200 at 0x400000 with PAGE_EXECUTE_READWRITE and bytes 4d 5a 90 00, but ldrmodules shows False/False/False

Analysis: #1: Reflective DLL injection (RWX + MZ in svchost). #2: Likely legitimate (RX, not RWX -- normal DLL mapping). #3: Shellcode injection (RWX + no MZ header). #4: Process hollowing (RWX + MZ + not in any PEB list).

Key Takeaways

  • malfind detects executable memory regions without associated files -- the primary injection indicator
  • PAGE_EXECUTE_READWRITE permission on private memory is almost always suspicious
  • MZ headers (4d 5a) in unexpected locations indicate PE injection; raw shellcode lacks this header
  • ldrmodules False/False/False entries are strong evidence of reflective injection or hollowing
  • Process hollowing creates processes that look legitimate but execute malicious code
  • Cross-referencing dlllist with ldrmodules reveals DLLs hidden from normal enumeration
