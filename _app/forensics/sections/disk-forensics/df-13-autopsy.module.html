Autopsy: Digital Forensics Platform Walkthrough

Autopsy is the premier open-source digital forensics platform, built on top of The Sleuth Kit (TSK). It provides a GUI for case management, data source analysis, keyword searching, timeline generation, and reporting. This module walks through a complete investigation workflow in Autopsy.

Learning Objectives

  • Create a case and add data sources in Autopsy
  • Configure and run ingest modules for automated analysis
  • Navigate file analysis, keyword search, and timeline views
  • Tag, bookmark, and generate reports for findings

Step 1: Case Creation

Every investigation starts with creating a case. The case container holds all data sources, analysis results, tags, and bookmarks for the investigation.

  1. Launch Autopsy and select "Create New Case"
  2. Enter the case name (e.g., "CASE-2026-0142") and base directory for case files
  3. Enter case number, examiner name, and organization
  4. Click "Finish" — Autopsy creates the case directory structure

Case directory structure: Autopsy creates a .aut file and subdirectories for modules, reports, and logs. The case database (SQLite) stores all metadata, analysis results, and bookmarks. Keep the case directory on a fast local drive — network storage significantly degrades performance.

Step 2: Adding Data Sources

Autopsy supports multiple data source types:

Source TypeSupported FormatsUse Case
Disk ImageRaw (.dd, .img, .raw), E01, VHD, VMDKForensic disk images
Local DiskPhysical or logical drive (requires admin)Live analysis of attached media
Logical FilesIndividual files or directory treesTriage or targeted collection
Unallocated SpaceRaw unallocated space imageCarved data from unallocated regions

Step 3: Ingest Modules

Ingest modules perform automated analysis as data sources are processed. Select modules based on your investigation needs:

ModuleFunctionWhen to Use
Hash LookupCompares file hashes against known-good (NSRL) and known-bad databasesAlways — identifies OS files and known malware
File Type IDIdentifies files by content signature, not extensionAlways — detects renamed/disguised files
Keyword SearchIndexes content and searches for terms, regex, phone numbers, emailsMost investigations — configure search lists per case
Email ParserParses PST, OST, MBOX, and EML filesWhen email analysis is relevant
Web ArtifactsExtracts browser history, cookies, bookmarks, downloadsInternet activity investigations
EXIF ParserExtracts EXIF metadata from images (GPS, camera, timestamps)Image-related investigations
Interesting FilesFlags files matching custom rules (extensions, paths, sizes)Targeted searches (e.g., .enc, .pgp files)
Encryption DetectionIdentifies encrypted files and volumesWhen encryption is suspected

Ingest module order matters. Hash Lookup and File Type ID should run first, as other modules depend on their results. Keyword Search is resource-intensive — configure your keyword lists before starting ingest to avoid re-running.

Step 4: File Analysis

The left panel provides multiple views into the data:

  • Data Sources: Browse the file system tree as it existed on the original media
  • Views > File Types: Files organized by type (documents, images, executables, archives)
  • Views > Deleted Files: Files with deleted status in the file system metadata
  • Views > File Size: Files organized by size range (useful for finding large archives or databases)
  • Results: Output from ingest modules (extracted content, keyword hits, web history)

Content Viewer

Selecting a file in the results table shows it in the content viewer tabs:

  • Hex: Raw hexadecimal view of file contents
  • Strings: Extracted printable strings
  • Application: Rendered view (images, documents, text files)
  • Metadata: File system metadata (timestamps, permissions, MFT entry number)
  • Results: Ingest module results specific to this file

Step 5: Keyword Search

Autopsy provides two keyword search modes:

  • Indexed search: Searches the pre-built index created during ingest. Fast but limited to indexed content.
  • Ad-hoc search: Searches raw content on demand. Slower but can find content not captured by the index.

Keyword lists can include literal strings, regular expressions, phone number patterns, email address patterns, IP addresses, and credit card numbers. Create case-specific keyword lists based on investigation requirements.

Step 6: Timeline View

The timeline aggregates all timestamped events from file system metadata, web history, email, and other artifacts into a chronological view. Use it to:

  • Identify activity clusters around specific dates/times
  • Detect unusual after-hours or weekend activity
  • Correlate file operations with other events (logins, network connections)
  • Find files created/modified around the time of a known incident

Step 7: Tagging and Bookmarking

As you find relevant evidence, tag items for inclusion in your report:

  • Tags: Categorize items (e.g., "Notable", "Follow Up", "Suspicious", custom tags)
  • Bookmarks: Save specific items with comments for report generation
  • Comments: Add examiner notes to any file or artifact

Step 8: Reporting

Generate reports from tagged/bookmarked items:

  • HTML Report: Comprehensive report with embedded file previews and metadata
  • Excel Report: Spreadsheet of tagged items for data analysis
  • KML Report: Geographic data for Google Earth (from EXIF GPS data)
  • Portable Case: Self-contained case export for sharing with other examiners

Practice: Autopsy Investigation Workflow

Download a practice forensic image (such as those from Digital Forensics Tool Testing Images at dftt.sourceforge.net) and complete the following in Autopsy:

  1. Create a new case with appropriate case information
  2. Add the disk image as a data source
  3. Run Hash Lookup, File Type ID, and Keyword Search ingest modules
  4. Browse the file system and identify any deleted files
  5. Use the timeline view to identify activity clusters
  6. Tag three items of interest and generate an HTML report

Key Takeaways

  • Autopsy provides a complete forensic analysis workflow: case creation, data ingest, analysis, reporting
  • Ingest modules automate common analysis tasks (hashing, keyword search, web artifacts, email parsing)
  • The timeline view is one of the most powerful features for correlating events across data sources
  • Tag and bookmark evidence as you find it — do not rely on memory
  • Autopsy is open source, free, and widely accepted in court proceedings
