Slack Space & Hidden Data

Data hides in the gaps between what a file uses and what the disk allocates. Slack space, alternate data streams, host-protected areas, and device configuration overlays are all locations where evidence — or hidden data — can reside. This module covers each hiding location, how data gets there, and tools for analysis.

Learning Objectives

  • Distinguish between RAM slack, file slack, volume slack, and partition slack
  • Explain how NTFS Alternate Data Streams hide data
  • Identify Host-Protected Areas (HPA) and Device Configuration Overlays (DCO)
  • Use forensic tools to examine slack space for hidden evidence

Types of Slack Space

RAM Slack

When a file does not fill its last sector (512 bytes), the OS pads the remainder with data from RAM. On older systems (pre-Windows Vista), this RAM slack could contain fragments of passwords, documents, or other data that happened to be in memory. Modern Windows versions zero-fill RAM slack.

File Slack (Drive Slack)

File systems allocate space in clusters (typically 4096 bytes). A 5000-byte file requires two 4096-byte clusters (8192 bytes total), leaving 3192 bytes of slack. This slack may contain remnants of a previously deleted file that occupied those clusters. File slack is the most forensically significant type.

Volume Slack

The space between the end of the file system and the end of the partition. This occurs when the partition size is not an exact multiple of the cluster size. Volume slack can contain remnants of a previous, larger file system or intentionally hidden data.

Partition Slack (Inter-Partition Gaps)

Space between partitions on a disk that is not allocated to any partition. This space is invisible to the operating system and can be used to hide entire file systems or data containers.

NTFS Alternate Data Streams (ADS)

NTFS allows files to have multiple data streams. The default (unnamed) stream is what you see when you open a file. Additional named streams are invisible to standard directory listings and most applications.

# Create a file with an alternate data stream (Windows) echo "visible content" > normal.txt echo "hidden content" > normal.txt:secret # The file appears normal dir normal.txt # Shows: normal.txt 16 bytes # But the hidden stream exists more < normal.txt:secret # Output: hidden content # List ADS on a file (Windows) dir /r normal.txt # Shows: normal.txt:secret:$DATA # On forensic Linux tools: # Autopsy shows ADS in the file properties # Sleuth Kit: fls -r image.dd | grep ":" # Common legitimate ADS uses: # Zone.Identifier — marks files downloaded from internet # Thumbs.db streams — cached thumbnails # encryptable — encryption status

Malware and ADS: Attackers have historically used ADS to hide malicious executables. While modern Windows Defender scans ADS, the technique can still be used for data exfiltration or hiding configuration files. Always check for unexpected ADS during forensic examination.

Host-Protected Area (HPA)

The HPA is a region at the end of a hard drive that is hidden from the BIOS and operating system. Originally designed for recovery partitions and diagnostic tools, it can be used to hide data from forensic examination.

# Detect HPA using hdparm (Linux) sudo hdparm -N /dev/sda # Output shows: # max sectors = 976773168 (actual disk size) # max visible = 976773168 (what OS sees) # If max visible < max sectors, an HPA exists # Remove HPA temporarily (for imaging) sudo hdparm -N p976773168 /dev/sda # Sets visible sectors to actual maximum # IMPORTANT: Document the original HPA size before removing it # The presence of an HPA is itself evidence

Device Configuration Overlay (DCO)

DCO is similar to HPA but operates at a lower level. It can hide the existence of an HPA and reduce the reported maximum capacity of the drive. DCO persists across power cycles and is harder to detect.

# Detect DCO using hdparm sudo hdparm --dco-identify /dev/sda # Shows the DCO configuration including real maximum LBA # Compare real size vs reported size sudo hdparm -I /dev/sda | grep "device size" # If discrepancy exists, a DCO may be hiding sectors

Examining Slack Space

# Extract file slack using Sleuth Kit # blkls extracts unallocated and slack space blkls -s image.dd > slack_space.bin # Search slack space for strings strings slack_space.bin | grep -i "password\|secret\|confidential" # blkstat: Show details about a specific block blkstat image.dd 12345 # Shows whether the block is allocated, unallocated, or in slack # FTK Imager can visualize slack space per file: # Right-click file > Show Slack Space # Displays the slack bytes after the file's logical end

Practice: Finding Hidden Data

  1. Create an NTFS-formatted USB drive, write a large text file, delete it, then write a smaller file to the same area. Use Sleuth Kit to examine the file slack of the smaller file — do you find remnants of the deleted file?
  2. On Windows, create a file with an alternate data stream. Verify it is invisible in Explorer but detectable with dir /r
  3. Use hdparm -N on a test drive to check for an HPA
  4. Extract slack space from a forensic image and search for email addresses or URLs

Key Takeaways

  • Four types of slack: RAM slack, file slack (most important), volume slack, partition slack
  • File slack contains remnants of previously deleted files and is a rich source of evidence
  • NTFS Alternate Data Streams can hide arbitrary data attached to any file
  • HPA and DCO can hide disk regions from the OS and standard forensic tools
  • Always compare reported disk size with actual physical capacity to detect hidden areas
