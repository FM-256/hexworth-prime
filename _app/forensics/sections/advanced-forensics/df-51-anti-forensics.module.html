What is Anti-Forensics?

Anti-forensics encompasses techniques used to hinder, confuse, or prevent forensic analysis. Sophisticated attackers do not just compromise systems -- they actively work to eliminate evidence of their presence. Understanding these techniques is essential because detecting anti-forensics activity is itself strong evidence of malicious intent.

Anti-forensics techniques fall into several categories: timestamp manipulation, log destruction, secure deletion, encryption, steganography, and data hiding. Each leaves its own forensic footprint when examined with the right tools.

Timestomping Detection

Timestomping modifies file timestamps to blend malicious files with legitimate system files. On NTFS, each file has two sets of timestamps stored in the MFT (Master File Table):

$STANDARD_INFORMATION (SI) Easily modified by user-mode tools like timestomp.exe or PowerShell Set-ItemProperty. Contains Created, Modified, Accessed, MFT Entry Modified (MACE).
$FILE_NAME (FN) Only modifiable by kernel-mode operations. Updated when a file is created, moved, or renamed. Not changed by timestomp tools. Serves as the ground truth.
Timestomping Detection via MFT Analysis
# Suspicious: $SI timestamps show 2020, but $FN shows 2026
File: C:\Windows\System32\svchost_update.exe

$STANDARD_INFORMATION:
  Created:  2020-07-14 09:00:00  # Appears old/legitimate
  Modified: 2020-07-14 09:00:00

$FILE_NAME:
  Created:  2026-03-15 08:33:28  # Actual creation date
  Modified: 2026-03-15 08:33:28

# Detection: $FN timestamp is NEWER than $SI timestamp
# This is physically impossible without timestamp manipulation

Key Rule

The $FILE_NAME creation timestamp can never be newer than the $STANDARD_INFORMATION creation timestamp under normal conditions. If $FN Created > $SI Created, the file has been timestomped. Tools: MFTECmd (Eric Zimmerman), analyzeMFT, Plaso MFT parser.

Log Clearing Detection

Platform Indicator Detection Method
Windows Event ID 1102 in Security log This event is generated when the Security log is cleared. Ironically, clearing the log creates this evidence. The event records the account that performed the clearing.
Windows Event ID 104 in System log Generated when any event log is cleared (not just Security). Includes log name and clearing account.
Linux Truncated/empty log files A 0-byte auth.log or syslog with a recent mtime is suspicious. Use stat to check file metadata.
Linux Time gaps in continuous logs Parse timestamps and flag gaps where a normally chatty log suddenly has no entries for minutes or hours.
Linux Missing rotated log files If auth.log exists but auth.log.1 through auth.log.4.gz are missing, historical logs were deleted.

Secure Deletion and Data Hiding

Secure Deletion Tools SDelete (Sysinternals), shred, DBAN, Eraser. These overwrite file content before deletion. Artifacts: SDelete creates temp files with predictable patterns. Prefetch/ShimCache may record execution.
Alternate Data Streams (ADS) NTFS ADS allows data to be hidden inside a file without changing its visible size. Detectable with dir /r, streams.exe, or MFT analysis. Common hiding location for malware configuration.
Slack Space Data hidden in file slack (space between EOF and end of cluster) or volume slack. Not visible to normal file operations. Recoverable with tools like Autopsy, FTK, or Sleuth Kit.
HPA/DCO (Hard Drive) Host Protected Area and Device Configuration Overlay hide sectors at the end of a hard drive. The OS cannot see them. Detectable by comparing drive reported size vs actual capacity with hdparm.
Detecting Anti-Forensics Artifacts
# Detect Alternate Data Streams
dir /r C:\Users\suspect\Documents\
# Look for entries like: report.docx:hidden_data:$DATA

# Check for HPA/DCO on Linux
sudo hdparm -N /dev/sda
# Compare "max visible sectors" vs "max native sectors"
# If they differ, HPA is set

# Check for SDelete execution (Prefetch)
ls C:\Windows\Prefetch\SDELETE*.pf
# Presence proves SDelete was run

# Detect shred on Linux (bash_history or process accounting)
grep -i "shred\|wipe\|srm" /home/*/.bash_history

Encryption Indicators

Full-disk or file-level encryption can prevent forensic access to evidence. Detecting that encryption is in use -- even if you cannot decrypt -- is important for investigation scoping.

Technology Detection Indicators
BitLocker -FVE- metadata at beginning of volume. Registry key HKLM\SOFTWARE\Microsoft\BitLocker. manage-bde -status on live system. Recovery key may be in Active Directory.
LUKS LUKS magic bytes at offset 0 of partition (4C 55 4B 53). cryptsetup luksDump shows header info. /etc/crypttab configuration file.
VeraCrypt No clear header signature (designed for deniability). Look for VeraCrypt process in memory, prefetch files, or registry entries from installation. High-entropy partition without filesystem signature.

Practice: Identify Anti-Forensics Techniques

For each finding below, identify the anti-forensics technique used and describe how you detected it:

  1. A file named svchost.exe in C:\Windows\Temp\ has $SI Created of 2019-04-12 and $FN Created of 2026-03-15
  2. The Windows Security event log contains only one event: Event ID 1102, dated 2026-03-15 22:00
  3. A partition on the suspect's external drive shows 100% entropy with no recognizable filesystem signature
  4. Running dir /r on a Word document reveals report.docx:config.ini:$DATA (3,421 bytes)
  5. Prefetch files show SDELETE.EXE-*.pf with last run time of 2026-03-15 21:55

Answers: (1) Timestomping -- $FN is newer than $SI, which is impossible without manipulation. Detected via MFT analysis. (2) Log clearing -- the only remaining event is the "log cleared" event itself, proving the entire Security log was wiped. (3) Encryption -- likely VeraCrypt hidden volume (no header signature + high entropy). Alternatively could be securely wiped. (4) Alternate Data Streams -- data hidden inside an ADS attached to a legitimate document. (5) Secure deletion -- SDelete was executed 5 minutes before the log clearing, likely to destroy files before covering tracks.

Key Takeaways

  • Timestomping is detected by comparing $STANDARD_INFORMATION and $FILE_NAME timestamps in the MFT
  • Log clearing creates its own evidence: Event ID 1102 (Security) and 104 (System)
  • Secure deletion tools leave artifacts in Prefetch, ShimCache, and bash_history
  • Alternate Data Streams hide data without changing visible file size -- detect with dir /r
  • HPA/DCO hide hard drive sectors -- compare reported vs native capacity with hdparm
  • VeraCrypt is designed for deniability and has no clear header signature
  • The presence of anti-forensics activity is itself strong evidence of malicious intent
