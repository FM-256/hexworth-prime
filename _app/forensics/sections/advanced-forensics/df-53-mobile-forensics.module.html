Acquisition Levels

Mobile forensic acquisition varies in depth and invasiveness. The level you can achieve depends on the device model, OS version, lock state, and available tools. Higher levels yield more evidence but require more specialized techniques.

LevelMethodData RecoveredDifficulty
LogicalBackup extraction via iTunes/ADB, API-based accessContacts, messages, call logs, photos, app data accessible via backup APIsLow -- works on most unlocked devices
FilesystemFull filesystem access via jailbreak (iOS) or root (Android)All files including databases, caches, deleted-but-not-overwritten data, system logsMedium -- requires exploit or root access
PhysicalBit-for-bit image of flash storage via bootloader exploit or JTAGComplete storage including unallocated space, deleted data, wear-leveling remnantsHigh -- device/chip specific
Chip-OffPhysical removal of flash memory chip from circuit boardRaw NAND dump -- requires decryption if FDE enabled (usually impossible for modern devices)Very high -- destructive, specialized equipment

iOS Forensic Artifacts

iOS devices store data in well-defined locations. Even logical acquisitions (iTunes backups) contain rich forensic data stored in plist files and SQLite databases.

Call History CallHistory.storedata (SQLite). Contains call records with timestamps, duration, phone numbers, and whether the call was incoming, outgoing, or missed.
Messages (SMS/iMessage) sms.db (SQLite). Full message content, timestamps, read receipts, attachments metadata. iMessage data includes delivery/read status.
Location Data consolidated.db / cache_encryptedA.db. Significant location history, Wi-Fi triangulation data, cell tower connections. GPS coordinates with timestamps.
Safari/Browser History History.db (SQLite). Browsing history with timestamps. BookmarksMixed.db for bookmarks. TabsSavedState for open tabs.
Keychain Encrypted credential store. Contains saved passwords, Wi-Fi credentials, VPN configs, authentication tokens. Accessible with device passcode.
Health Data healthdb_secure.sqlite. Steps, heart rate, sleep data with precise timestamps. Can prove or disprove physical location and activity claims.

iOS Encryption

Since iOS 8, all user data is encrypted with keys derived from the device passcode. Without the passcode (or a valid backup password), filesystem and physical acquisitions yield encrypted data. BFU (Before First Unlock) state limits data to only what is accessible without the full encryption key hierarchy.

Mobile Backup Forensics

Device backups are often the most accessible forensic source. iTunes backups (iOS) and Google backups (Android) can be obtained without physical access to the device.

iOS Backup Locations
# Windows
%APPDATA%\Apple Computer\MobileSync\Backup\

# macOS
~/Library/Application Support/MobileSync/Backup/

# Each backup contains:
# - Manifest.plist (backup metadata)
# - Manifest.db (file index -- SQLite)
# - Status.plist (backup completion status)
# - Info.plist (device info, phone number, IMEI)
# - Files stored by SHA-1 hash of domain + relative path

Practice: Mobile Forensics Decision Making

For each scenario, determine the appropriate acquisition level and justify your choice:

  1. An unlocked iPhone 15 belonging to a fraud suspect. Device passcode is known.
  2. A locked Samsung Galaxy S24 found at a crime scene. No passcode available.
  3. A company-owned iPad managed by MDM with a known enrollment profile.
  4. A damaged Android phone recovered from a fire -- screen destroyed but board intact.

Answers: (1) Filesystem acquisition via GrayKey or Cellebrite with passcode -- maximum data including deleted items. Encrypted backup with passcode also viable for Keychain data. (2) Physical or advanced logical via exploit-based tools (GrayKey, Cellebrite Premium). Without passcode, logical backup is not possible. (3) Logical via MDM -- the MDM profile allows remote backup extraction and device management. May not need physical possession. (4) Chip-off as last resort -- physical removal of eMMC/UFS chip, then read with chip reader. Data will be encrypted on modern Android; success depends on encryption implementation.

Key Takeaways

  • Four acquisition levels: logical, filesystem, physical, chip-off -- each with increasing evidence yield and difficulty
  • iOS encrypts all user data with passcode-derived keys since iOS 8 -- no passcode means limited access
  • Android forensics benefits from ADB access when USB debugging is enabled
  • iOS encrypted backups contain MORE data than unencrypted backups (Keychain, Health)
  • Cloud-synced data (Google Takeout, iCloud) may be available even when the device is inaccessible
  • MDM-managed devices offer additional forensic collection options through the management platform
  • Health data (steps, heart rate) provides timestamped physical activity evidence
