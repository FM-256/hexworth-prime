Learning Objectives

  • Apply the NIST 800-61R2 four-phase incident response framework

  • Balance parallel tracks: remediation vs investigation
  • Conduct effective post-incident lessons learned

NIST 800-61R2 Framework

NIST Special Publication 800-61 Revision 2 defines the standard incident response lifecycle. Forensics is not a separate process -- it is integrated into every phase. Understanding where forensic activities fit ensures that evidence is preserved while the organization responds to the threat.

Phase 1: Preparation Build forensic capability before incidents occur. Pre-stage tools, train responders, establish evidence handling procedures, define escalation criteria, configure centralized logging, deploy EDR agents.
Phase 2: Detection & Analysis Identify that an incident is occurring and understand its scope. Forensic activities: triage affected systems, collect volatile evidence, analyze IOCs, determine attack vector, assess impact scope.
Phase 3: Containment, Eradication, Recovery Stop the attack, remove the threat, restore operations. Forensic activities: image systems before remediation, identify all persistence mechanisms, verify eradication completeness, monitor for re-compromise.
Phase 4: Post-Incident Activity Learn from the incident and improve defenses. Forensic activities: complete timeline reconstruction, finalize investigation report, identify root cause, recommend security improvements, archive evidence.

Evidence Collection Under Pressure

During an active incident, the business demands rapid containment while forensics demands careful evidence preservation. These goals can conflict -- reimaging a compromised server restores operations but destroys evidence. The key is to collect evidence before remediation actions.

Live Response Evidence Collection Priority
# Priority 1: Volatile data (disappears on reboot)
1. Running processes and network connections
2. Memory dump (RAM acquisition)
3. Logged-in users and active sessions
4. Open files and handles

# Priority 2: Semi-volatile data
5. Scheduled tasks and startup items
6. Temporary files
7. Clipboard contents

# Priority 3: Non-volatile but at-risk data
8. Event logs (may be clearing)
9. Registry hives
10. Disk image (full or targeted)

# Priority 4: External sources
11. Network device logs
12. SIEM data export
13. Cloud service logs

The Remediation vs Investigation Tension

Never let the urgency of containment destroy forensic evidence. Before reimaging a system, before resetting passwords, before blocking IPs -- capture the evidence. A 30-minute delay to image a disk can save months of investigation. Establish this protocol before an incident occurs.

Chain of Custody Under Pressure

Maintaining chain of custody during a chaotic incident is challenging but essential. Use pre-printed evidence forms, document every action with timestamps, photograph evidence before and after collection, and designate a single evidence custodian for each incident.

ActionDocumentation Required
Memory acquisitionTool used, version, hash of output file, start/end time, operator name, target system identifier
Disk imagingSource drive serial, imaging tool, write blocker used, source/destination hashes, any errors during imaging
Log collectionLog source, time range collected, collection method, hash of collected files, storage location
Evidence transferFrom whom, to whom, date/time, purpose, both parties sign

Lessons Learned

The post-incident review (also called a "lessons learned" or "after-action review") is where forensic findings drive security improvements. This meeting should occur within 1-2 weeks of incident closure while details are fresh.

What happened? Complete timeline from initial access to detection to containment. How long was the dwell time? How was the incident detected?
What went well? Effective detection rules, fast containment actions, successful evidence collection, good cross-team communication.
What could improve? Missing logging, slow escalation, evidence handling gaps, tool deficiencies, communication breakdowns, unclear authority.
What actions will we take? Specific, assigned, time-bound improvements. New detection rules, additional logging, updated playbooks, training needs, tool purchases.

Practice: IR Phase Mapping

For each forensic activity, identify which NIST 800-61 phase it belongs to:

  1. Creating a forensic image of a compromised web server before it is rebuilt
  2. Writing YARA rules based on malware found during the investigation
  3. Deploying EDR agents to endpoints before any incident occurs
  4. Analyzing Sysmon logs to determine the initial infection vector
  5. Recommending network segmentation based on lateral movement findings

Answers: (1) Phase 3 -- Containment (evidence preservation before eradication). (2) Phase 3 -- Eradication (using IoCs to detect remaining compromise) or Phase 4 (improving future detection). (3) Phase 1 -- Preparation. (4) Phase 2 -- Detection & Analysis. (5) Phase 4 -- Post-Incident Activity (lessons learned driving improvements).

Key Takeaways

  • Forensics is integrated into all four NIST 800-61 phases, not a standalone process
  • Evidence collection must happen before remediation -- 30 minutes of imaging saves months of investigation
  • Volatile evidence (RAM, network connections) has highest collection priority during live response
  • Chain of custody documentation is required for every evidence item, even under time pressure
  • Parallel tracks (remediation and investigation) must be coordinated to avoid evidence destruction
  • Post-incident lessons learned should produce specific, assigned, time-bound improvement actions
