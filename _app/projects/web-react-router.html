Subject

Build a Dynamic Product Site

Operative 90 min 500 XP
Mission Brief

Your assignment is to build a working dynamic product catalog site using React, Vite, and React Router. When you finish you will have a multi-page single-page application running at http://localhost:5173 with a persistent navbar, live search and category filtering, individual product detail pages driven by URL parameters, and a shopping cart backed by React Context and useReducer — all styled with styled-components so there is not a single external CSS file in the project.

This is a zero-knowledge walkthrough. Every phase shows the exact terminal commands to run, the exact files to create, and the complete code to paste. Observable checkpoints tell you what you should see in the browser before moving on. No prior Vite or React Router experience is required.

Important library note: React Router is currently at version 7/8, and the package name changed from react-router-dom to react-router. Every hook and component in this project (BrowserRouter, Routes, Route, Link, NavLink, Outlet, useParams, useNavigate, useSearchParams) is imported from "react-router" — not from "react-router-dom". The walkthrough uses this current API throughout.

Agent Requirements
  • Node.js LTS v22.x or v20.19+ — Vite 8 requires Node 20.19 or 22.12 at minimum. Download the LTS installer from nodejs.org/en/download. After installing, open a terminal and confirm: node --version must print v20.x.x or higher. If it prints v18 or lower, update Node first.
  • A terminal (Windows: PowerShell or Command Prompt; Mac: Terminal; Linux: any shell). Every command in this project is shown exactly as you type it.
  • VS Code (code.visualstudio.com) as a code editor — any plain-text editor works, but VS Code provides JSX syntax highlighting that makes the code easier to read.
  • A modern browser (Chrome, Edge, or Firefox). You will use the browser at http://localhost:5173 throughout and open DevTools (F12) to catch any console errors.
  • React fundamentals: JSX, functional components, props, and useState. Familiarity with ES6 destructuring and arrow functions. No prior Vite, React Router, or styled-components experience needed.
  • No paid accounts, no cloud services, no database — the entire project runs locally.

Error: useNavigate() / useParams() / useSearchParams() — “may be used only in the context of a <Router> component”?
  • The component calling the hook is not rendered inside a <BrowserRouter>. Every hook that reads from the router tree (useNavigate, useParams, useSearchParams, NavLink) requires a BrowserRouter ancestor somewhere above it.
  • The most common cause: calling a router hook at the top level of main.jsx or in a component that is rendered outside the <BrowserRouter> tag. For example, if you placed const navigate = useNavigate() inside CartProvider before the router is mounted, you will see this error.
  • Fix: confirm that in App.jsx the <BrowserRouter> wraps <Routes> and all page components, and that any component calling a router hook is a child of that <BrowserRouter>.
Error: Cannot find module 'react-router'?
  • You either ran npm install react-router-dom (the old v6 package name) instead of npm install react-router, or you forgot to run npm install at all.
  • Fix: run npm install react-router from inside my-shop/. Then stop and restart the dev server.
Blank white page in the browser?
  • Open DevTools (F12) and check the Console tab. A blank page almost always means a JavaScript error is stopping React from mounting. Read the error and compare your code line by line.
  • Common cause: you left the import './index.css' line in main.jsx after deleting the file. Remove that import line.
Port 5173 already in use?
  • Vite will automatically try the next available port (5174, 5175, etc.) and print the actual URL in the terminal. Navigate to the URL it shows.
  • Alternatively, stop whatever is running on 5173, or kill it with npx kill-port 5173.

  2. Create the CartContext. Create src/context/CartContext.jsx and paste this complete file:
    // src/context/CartContext.jsx // CartContext exposes { state, dispatch } to any component that calls useCart(). // useReducer keeps all cart logic in one place and avoids scattered useState calls. import { createContext, useContext, useReducer } from "react"; // ── Reducer ────────────────────────────────────────────────────────────────── // state.items is an array of { ...product, quantity } objects. function cartReducer(state, action) { switch (action.type) { case "ADD_ITEM": { const existing = state.items.find(i => i.id === action.product.id); if (existing) { // Product already in cart: increase its quantity. return { ...state, items: state.items.map(i => i.id === action.product.id ? { ...i, quantity: i.quantity + (action.quantity || 1) } : i ), }; } // New product: add with the requested quantity (default 1). return { ...state, items: [...state.items, { ...action.product, quantity: action.quantity || 1 }], }; } case "REMOVE_ITEM": return { ...state, items: state.items.filter(i => i.id !== action.id) }; case "CLEAR_CART": return { ...state, items: [] }; default: return state; } } const initialState = { items: [] }; // ── Context ─────────────────────────────────────────────────────────────────── const CartContext = createContext(null); // CartProvider wraps the app and makes state + dispatch available everywhere. export function CartProvider({ children }) { const [state, dispatch] = useReducer(cartReducer, initialState); return ( <CartContext.Provider value={{ state, dispatch }}> {children} </CartContext.Provider> ); } // Custom hook: call useCart() in any component to read state or dispatch actions. export function useCart() { const ctx = useContext(CartContext); if (!ctx) throw new Error("useCart must be used inside CartProvider"); return ctx; }
    Why useReducer instead of useState? The cart has multiple related actions (add, remove, clear). useReducer collects all that logic into one function with named cases, making it easier to test and extend than multiple useState calls scattered across components. The pattern is identical to Redux, without the external library.
  3. Wrap the app in CartProvider. Open src/main.jsx and add the import and wrapper:
    // src/main.jsx import { StrictMode } from "react"; import { createRoot } from "react-dom/client"; import App from "./App"; import { CartProvider } from "./context/CartContext"; createRoot(document.getElementById("root")).render( <StrictMode> <CartProvider> <App /> </CartProvider> </StrictMode> );
    Why wrap at main.jsx and not inside App.jsx? CartProvider must be an ancestor of every component that calls useCart(). Navbar is one such component, and it renders inside the router tree. Placing CartProvider in main.jsx so it wraps <App /> guarantees that. The router context and the cart context are independent of each other — the ordering between them does not matter; what matters is that CartProvider is above any component that consumes it.
