Subject

My First Scan

Recruit 250 XP
Mission Brief

Use Nmap to scan a network for the first time — discover hosts, identify services, and see a network through a security engineer's eyes. Nmap is the industry-standard network scanner used by penetration testers, security engineers, and system administrators worldwide. This project is authorized reconnaissance on systems you own or have explicit permission to test.

You will discover live hosts on your own machine and local network, enumerate open ports and their services, detect service version numbers, and read port state output. Every piece of information Nmap reveals is a potential attack surface — understanding it is the first step in hardening it.

You will finish by writing a real scan report: target, ports, services, and one security recommendation. This is the format used in professional vulnerability assessments and penetration test deliverables.

Agent Requirements
  • A computer running Windows, macOS, or Linux (all are covered in Phase 1)
  • Internet access to download Nmap — the installer is free and about 30 MB
  • Administrator or sudo access on your own machine (needed for certain scan types)
  • Targets you own or have explicit written permission to scan — covered in the legal notice before Phase 1
  • A plain-text editor to write your scan report in Phase 4
Legal & Ethical Boundary
Read this before you touch any scan command.
Scanning a network or host without authorization is illegal under the Computer Fraud and Abuse Act (US), the Computer Misuse Act (UK), and equivalent laws in most countries. Unauthorized scanning can result in criminal charges, civil liability, and expulsion — regardless of whether you cause any harm or whether you are on the same network as the target.

The only sanctioned targets in this project are:
(1) Your own machine — 127.0.0.1 / localhost — which never leaves your computer.
(2) A network you personally own and fully control as the administrator — meaning every device connected to it belongs to you or has consented in writing.
(3) scanme.nmap.org — the Nmap project's official public practice host, which explicitly grants scanning permission.

Never point Nmap at any other target without explicit written permission from the system owner. When in doubt, scan only 127.0.0.1.

Install Nmap and Verify It Works
Before any scanning, you need to install Nmap, open a terminal, and confirm the tool is ready. This phase has no commands that touch the network — everything runs locally.
Legal and ethical boundary — read this before you scan anything.
Scanning a network or host without authorization is illegal under the Computer Fraud and Abuse Act (US), the Computer Misuse Act (UK), and equivalent laws in most countries. Unauthorized scanning can result in criminal charges, civil liability, and expulsion. In this project you will only scan: (1) your own machine using 127.0.0.1 or localhost, (2) your own home or lab network, and (3) Nmap's official public practice host scanme.nmap.org, which exists specifically for this purpose and explicitly grants permission. Never point Nmap at a target you do not own or have written permission to test.
  1. Download and install Nmap for your operating system.
    Windows: Go to nmap.org/download.html and download the "Latest stable release self-installer" (a file named nmap-<version>-setup.exe). Double-click the installer and accept all defaults. The installer also installs Npcap, the packet-capture driver Nmap needs on Windows — let it install. When setup finishes, Nmap is on your system.
    macOS: The cleanest path is the Homebrew package manager. Open Terminal (press Cmd+Space, type Terminal, press Enter) and run:
    brew install nmap
    If Homebrew is not installed, go to brew.sh and follow the one-line install command shown there first. Alternatively, download the macOS installer from nmap.org/download.html and open the .dmg file.
    Linux (Debian/Ubuntu and derivatives): Open a terminal and run:
    sudo apt update && sudo apt install nmap
    On Fedora/RHEL-based systems: sudo dnf install nmap. Kali Linux ships with Nmap pre-installed.
  2. Open a terminal.
    Windows: Most nmap scans that go beyond a basic TCP connect require an elevated (Admin) terminal. Press the Windows key, type cmd, then right-click Command Prompt and choose Run as administrator. A User Account Control (UAC) prompt will appear — click Yes. The title bar will say "Administrator: Command Prompt". You can also use PowerShell the same way. For basic scans a regular terminal works, but starting with an Admin terminal avoids permission errors later in the project.
    macOS / Linux: Open Terminal from your Applications folder or app launcher. You will prefix privileged commands with sudo when needed (Phase 3); you do not need to be root to start.
  3. Verify nmap installed correctly. In your terminal, type this and press Enter:
    nmap --version
    You should see output that starts with something like:
    expected outputNmap version 7.95 ( https://nmap.org ) Platform: x86_64-pc-windows-windows Compiled with: nmap-liblua-5.4.6 openssl-3.0.13 ... Compiled without: ... Available nsock engines: iocp poll select
    The exact version number and details will differ; what matters is that you see "Nmap version" and no error saying "command not found" or "not recognized".
    Command not found / not recognized?
    • Windows: Close the terminal and open a new one. The installer adds Nmap to the system PATH, but an already-open terminal does not pick up the change. If a fresh terminal still fails, the installer may not have completed — re-run it as administrator.
    • macOS / Linux: The package manager should have handled PATH automatically. If not, confirm Nmap is at /usr/local/bin/nmap or /usr/bin/nmap with: which nmap. If that returns nothing, the install did not complete — re-run the install command.
Checkpoint — what you should see
Running nmap --version prints a version line (7.x or higher) with no errors. Your terminal stays open. That is all this phase requires — you have not scanned anything yet.

2
Your First Scan — Scan Your Own Machine
The safest target to start with is your own computer. 127.0.0.1 (also written as localhost) always refers to the machine you are typing on — it never goes out onto the network. You will run a basic scan, read the output table, and understand what open/closed/filtered means.
  1. Run a basic scan against localhost. In your terminal:
    nmap 127.0.0.1
    This runs Nmap's default scan: TCP SYN or TCP connect probes against the top 1,000 most common ports. It finishes in a few seconds on your own machine.
  2. Read the output table. You will see something like this (your results will differ based on what is running on your machine):
    sample output — yours will varyStarting Nmap 7.95 ( https://nmap.org ) at 2026-06-18 10:32 EDT Nmap scan report for localhost (127.0.0.1) Host is up (0.0000080s latency). Not shown: 994 closed tcp ports (conn-refused) PORT STATE SERVICE 22/tcp open ssh 80/tcp open http 443/tcp open https 631/tcp open ipp 3306/tcp open mysql 8080/tcp open http-proxy Nmap done: 1 IP address (1 host up) scanned in 0.12 seconds
  3. Understand each column.
    PORT — the port number and protocol. TCP is the most common. 22/tcp means TCP port 22.
    STATE — what Nmap found:
      open means a service is actively listening and accepted the probe. This is the interesting finding.
      closed means the host responded (it's up) but nothing is listening on that port.
      filtered means a firewall dropped the probe silently — no response at all.
    SERVICE — Nmap's guess for the service based on the port number. At this stage it's a lookup from a list, not a verified detection (that comes in Phase 3).
  4. Scan a specific port range using the -p flag. This limits the scan to the ports you name, which is faster and quieter:
    nmap -p 22,80,443,8080 127.0.0.1
    You can also specify a range: -p 1-1024 scans the first 1,024 ports (the "well-known" range). Try both.
  5. Scan Nmap's official practice host. scanme.nmap.org is a real public server maintained by the Nmap project. The project explicitly grants permission for anyone to scan it for practice. This is a live internet host, so the scan takes longer than localhost (typically 20–60 seconds):
    nmap scanme.nmap.org
    Be considerate — it is a shared public service: do not use aggressive timing flags (-T4, -T5), -A, -p- (all 65,535 ports), or rapid repeated scans against scanme.nmap.org. Run it no more than once or twice per session. Heavy or repeated use degrades the host for every other student using it worldwide.
    sample output — yours will varyStarting Nmap 7.95 ( https://nmap.org ) at 2026-06-18 10:35 EDT Nmap scan report for scanme.nmap.org (45.33.32.156) Host is up (0.072s latency). Not shown: 996 closed tcp ports (conn-refused) PORT STATE SERVICE 22/tcp open ssh 80/tcp open http 9929/tcp open nping-echo 31337/tcp open Elite Nmap done: 1 IP address (1 host up) scanned in 4.21 seconds
    Port 9929 and 31337 are intentionally open on scanme.nmap.org for demonstration purposes. In a real assessment, port 31337 would warrant immediate investigation (it is associated with the Back Orifice malware historically, though here it is benign).
    scanme.nmap.org is slow or times out?
    • The host is publicly accessible and is occasionally slow due to high usage. Wait 30 seconds and try again.
    • Your school or workplace firewall may block outbound Nmap probes (ICMP and raw TCP SYN packets are commonly restricted). If the scan hangs past 90 seconds, use nmap -Pn scanme.nmap.org to skip the host-discovery ping and go straight to port scanning.
    • If a firewall blocks everything and you only see "filtered" results, the problem is the outbound policy, not your Nmap install. Scan 127.0.0.1 to confirm Nmap itself is working.
  6. Find your own local IP address so you can optionally scan yourself from your own machine by network IP (rather than loopback). On Windows: run ipconfig and look for "IPv4 Address" under your active adapter. On macOS/Linux: run ip addr or ifconfig and look for the inet address on your active interface (commonly eth0, en0, or wlan0). Your local IP will start with 192.168., 10., or 172.16.–172.31.
Checkpoint — what you should see
You have run at least two scans: nmap 127.0.0.1 and nmap scanme.nmap.org. Both produced an output table with PORT, STATE, and SERVICE columns. You can name at least one open port from each scan and say what service runs on it. If every port on localhost shows "closed," that means your machine is not running background services, which is normal for a minimal install — the scan still worked correctly.

Service Version Detection and Host Discovery
The default scan only guesses the service by port number. The -sV flag tells Nmap to send additional probes and actually identify the software name and version running behind each open port. You will also discover all live hosts on your local network using a ping scan.
  1. Run version detection against your own machine. The -sV flag adds service/version probes:
    nmap -sV 127.0.0.1
    Compare the SERVICE column to the basic scan you ran in Phase 2. Instead of a generic name like "http", you now see the actual software:
    sample output — yours will varyPORT STATE SERVICE VERSION 22/tcp open ssh OpenSSH 9.2p1 Debian 2+deb12u4 (protocol 2.0) 80/tcp open http Apache httpd 2.4.62 ((Debian)) 3306/tcp open mysql MySQL 8.0.39
    The version string matters for security. If a service shows "OpenSSH 7.2", that specific version has known vulnerabilities that an attacker can look up in the CVE database. Version detection is one of the most valuable Nmap features.
  2. Run version detection against scanme.nmap.org.
    Be considerate — it is a shared public service: do not use aggressive timing flags (-T4, -T5), -A, -p- (all 65,535 ports), or rapid repeated scans against scanme.nmap.org. Run it no more than once or twice per session. Heavy or repeated use degrades the host for every other student using it worldwide.
    nmap -sV scanme.nmap.org
    sample output — yours will varyPORT STATE SERVICE VERSION 22/tcp open ssh OpenSSH 6.6.1p1 Ubuntu 2ubuntu2.13 (Ubuntu Linux; protocol 2.0) 80/tcp open http Apache httpd 2.4.7 ((Ubuntu)) 9929/tcp open nping-echo Nping echo 31337/tcp open tcpwrapped
    Notice that scanme.nmap.org runs an older OpenSSH version. In a real assessment, "OpenSSH 6.6.1p1" is worth noting because it predates several security patches.
  3. Discover live hosts on your local network (ping scan). First, identify your network's CIDR range from your IP address found in Phase 2. If your IP is 192.168.1.45, your network range is typically 192.168.1.0/24 (the /24 means the last number can be 0–255 — it covers all 254 possible hosts on that subnet).
    Shared-network restriction — required reading before running this command.
    Only run a subnet sweep on a network where you own or control every connected device — for example, your own home router where you are the admin and every device on the network is yours, or a dedicated lab network you control. Do not run this command on a shared network such as a dorm building, apartment-complex WiFi, campus wireless, office network, or any connection where other people's devices are present. Scanning someone else's device without their permission is illegal even when you are on the same subnet. "I'm on my home network" alone is not sufficient if any household member, roommate, or guest has a device connected to it without having granted you permission to scan it.
    Run:
    nmap -sn 192.168.1.0/24
    Replace 192.168.1 with the first three numbers of your own IP. The -sn flag means "ping scan only" — Nmap sends discovery probes but does not scan ports. This is the least intrusive scan type.
    sample output — yours will varyStarting Nmap 7.95 at 2026-06-18 10:41 EDT Nmap scan report for 192.168.1.1 Host is up (0.0018s latency). Nmap scan report for 192.168.1.45 Host is up (0.000040s latency). Nmap scan report for 192.168.1.102 Host is up (0.0041s latency). Nmap scan report for 192.168.1.118 Host is up (0.0062s latency). Nmap done: 256 IP addresses (4 hosts up) scanned in 2.44 seconds
    Each listed IP is a live device on your network. 192.168.1.1 is almost always your router. Try to identify the other IPs: your phone, smart TV, another laptop, a printer, etc.
    Windows: "You requested a scan type which requires root privileges" or empty results?
    • On Windows, ARP-based host discovery requires an Admin terminal. Close your terminal, right-click Command Prompt, and choose "Run as administrator", then re-run the scan — only on a network you fully own and control (see the legal note above).
    • On macOS/Linux, prefix the command with sudo: sudo nmap -sn 192.168.1.0/24 — again, only on a network where every connected device is yours or has granted written permission.
    • If you see "0 hosts up" but you know devices are present, your network may use a different subnet. Confirm your actual IP with ipconfig (Windows) or ip addr (Linux/Mac) and adjust the range accordingly.
  4. Understand what to ignore. Nmap output sometimes includes lines like "Host seems down" or warnings about rate limiting. These are informational. The lines that matter are those listing a PORT, STATE, and SERVICE. Warning lines starting with "WARNING:" or "NOTE:" are safe to read but do not indicate a problem with your scan or your machine.
What is sudo and why does it matter? Certain scan types — like raw SYN scans (-sS) and OS fingerprinting (-O) — require the ability to send crafted packets at a low network level. On macOS and Linux, only the root user (or a user with sudo) can do this. On Windows, running as Administrator gives the same access. Without elevated privileges, Nmap falls back to a TCP connect scan (-sT), which works but is slower and more visible to the target.
Checkpoint — what you should see
The -sV scan shows at least one open port with a full version string (not just a service name). The ping scan lists at least two live hosts on your network (your router and your own machine at minimum). You can identify which IP is your router. If the only host up is your own machine, you may be on a heavily firewalled network or a VPN — the tools are working correctly even if fewer hosts respond.

Write Your Scan Report
A scan that isn't documented is just noise. Security professionals always produce a written record of what they found, what it means, and what should be fixed. You will write a short report using real data from your scans in Phases 2 and 3.
  1. Open a plain-text editor. Use Notepad (Windows), TextEdit in plain-text mode (macOS), or any editor you have. Do not use Microsoft Word — the goal is a simple text document. Name the file scan-report.txt.
  2. Structure your report with these five sections. Copy this template and fill in your own data from your scan output:
    scan report templateSCAN REPORT =========== Target: 127.0.0.1 (my own machine, hostname: [your hostname]) Scan date: 2026-06-18 Tool: Nmap 7.95 Scan type: Default TCP + service version detection (-sV) OPEN PORTS ---------- PORT STATE SERVICE VERSION 22/tcp open ssh OpenSSH 9.2p1 80/tcp open http Apache httpd 2.4.62 [add each open port from your output] ADDITIONAL TARGET: scanme.nmap.org ----------------------------------- PORT STATE SERVICE VERSION 22/tcp open ssh OpenSSH 6.6.1p1 80/tcp open http Apache httpd 2.4.7 9929/tcp open nping-echo Nping echo 31337/tcp open tcpwrapped HOST DISCOVERY (local network) ------------------------------- Network scanned: 192.168.1.0/24 Hosts up: [number] IPs found: [list each IP and your best guess at the device] SECURITY RECOMMENDATION ------------------------ [Write one specific, concrete recommendation based on an actual finding.]
  3. Write a concrete security recommendation — the last section. The recommendation must reference a specific port or service from your own scan output. Generic statements like "apply patches" do not count. Here are examples of what a real recommendation looks like:
    Example A: Port 80/tcp is open running Apache 2.4.7. This version is from 2013 and has numerous publicly documented vulnerabilities. Recommendation: update Apache to the current stable release (2.4.62 or later) and redirect all HTTP traffic to HTTPS on port 443 to eliminate unencrypted web traffic.
    Example B: Port 22/ssh is open on all live hosts including the router. If SSH access is not required on the router from internal hosts, close or restrict it with firewall rules. If SSH is required, disable password authentication and require SSH key pairs only.
    Example C: My local network scan found 4 live hosts but I can only account for 3 devices I own. The fourth IP (192.168.1.118) should be investigated — an unrecognized device on a home network may indicate an unauthorized connection or an IoT device with default credentials.
  4. Save your report. Your document now contains real reconnaissance data from real scans you ran. This is the same type of artifact a junior security analyst produces after a network scan engagement.
Why write a report at all? In professional security work, the report is the deliverable — not the scan itself. A penetration test engagement ends when the client receives a document they can act on. Practicing the report format from your first scan builds the habit that separates a professional from someone who just runs tools.
Not sure what to put in the recommendation?
  • If all ports show "closed" or "filtered" on your machine, that is itself a finding: "My local machine shows no open ports to the network, which reflects a hardened default posture. Recommendation: verify this is intentional and document the firewall rules that produce this result."
  • If scanme.nmap.org was the only host that gave you interesting output, write your recommendation based on that — just note in the report that it is a public practice host, not your own infrastructure.
Checkpoint — what you should see
Your scan-report.txt file has all five sections filled with real data from your scans — not placeholder text, not invented numbers. The security recommendation names a specific port and version string from your actual output and explains the risk in one or two sentences. You can read the report to someone who was not in the room and they can understand what you found and why it matters.
