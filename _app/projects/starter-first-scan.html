Subject

My First Scan

Beginner 30 min 250 XP
Mission Brief

Use Nmap to scan your own network for the first time — discover hosts, identify services, and see your network through a hacker's eyes. Nmap is the industry-standard network scanner used by penetration testers, security engineers, and system administrators worldwide. This is authorized reconnaissance on your own infrastructure.

You will discover all live hosts on your network, enumerate open ports and their services, detect version numbers, and attempt OS fingerprinting. Every piece of information Nmap reveals is a potential attack surface — understanding it is the first step in hardening it.

You will finish by writing a real scan report: target, ports, services, OS, and one security recommendation. This is the format used in professional vulnerability assessments and penetration test deliverables. Scan only systems you own or have written permission to test.

Agent Requirements
  • Nmap installed: nmap.org/download — available for Windows, macOS, Linux
  • A terminal with admin/sudo access (OS detection requires elevated privileges)
  • Your own home network or a lab environment you control — never scan external targets
  • A text editor to write your scan report in Phase 4
  • Basic understanding of IP addresses and ports from the My First Network project
Operation Phases
Progress
0 / 4
✓
1
Install and Ping Scan
Install nmap from nmap.org. Verify with nmap --version in your terminal. Find your network's CIDR range from the My First Network project (e.g., 192.168.1.0/24). Run nmap -sn 192.168.1.0/24 — the -sn flag does a ping scan only, no port scanning. Nmap sends ARP requests (local) or ICMP pings (remote) and reports which hosts respond. Each responding host is "up" — a live device on your network.
Checkpoint
The scan output lists all live hosts with their IP addresses and sometimes their hostnames or MAC addresses. Count the hosts. Can you match each IP to a device you recognize (router, phone, laptop, TV)? Your own machine should appear in the list.
✓
2
Port Scan a Target
Pick one target — your own machine's IP or your router's IP. Run nmap <target-ip> (default scan: top 1000 ports, TCP SYN). Read the output table: each row shows a port number, state (open / closed / filtered), and service name. Open means the service is listening. Closed means nothing is listening but the host responded. Filtered means a firewall is blocking the probe — no response.
Checkpoint
Name at least 3 open ports on your target and their services. For each, explain what that service does: port 22 is SSH (remote shell), port 80 is HTTP (web), port 443 is HTTPS (encrypted web), port 53 is DNS. If no ports are open, your firewall is blocking everything — try scanning your router instead.
✓
3
Service Version Detection
Run nmap -sV <target-ip> to add version detection. Nmap sends additional probes to each open port and tries to identify the exact software name and version number. For example: 22/tcp open ssh OpenSSH 8.9p1 Ubuntu. Run sudo nmap -O <target-ip> to attempt OS detection — Nmap analyzes TCP/IP stack behavior to guess the operating system and kernel version. OS detection requires raw packet access, so sudo is needed.
Checkpoint
Your scan output shows exact version strings for at least 2 open services. The OS detection section shows a best guess for the target operating system. Note: version strings matter for security — knowing a service runs OpenSSH 7.2 means you can look up known CVEs for that exact version.
✓
4
Document Your Findings
Write a 1-page scan report with these sections: Target IP, Open Ports (list each with service name and version), OS guess, and one security Recommendation. Example recommendation: "Port 23/telnet is open — telnet transmits credentials in plaintext and should be disabled; replace with SSH." or "Port 80/http is open on a device that should not be running a web server — investigate and disable if not needed." Be specific — the recommendation must reference the actual finding.
Checkpoint
Your report has all required sections filled with real data from your scan. The recommendation is specific to an actual open port you found — not a generic statement. You can explain why an open port is a risk: it is an exposed service that could be exploited if it has a vulnerability or weak configuration.
