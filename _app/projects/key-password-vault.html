Subject

Build a Password Vault

Advanced 2H 1000 XP
Mission Brief

This operation requires the construction of a command-line encrypted password vault that stores credentials — site, username, and password — inside a single portable vault.json file. Every entry is encrypted individually using AES-256-GCM, an authenticated encryption scheme that simultaneously protects confidentiality and detects tampering. The vault file contains no readable plaintext whatsoever: site names, usernames, passwords, and notes are all stored as base64-encoded ciphertext blobs alongside their associated IV and authentication tag.

The master password is never stored. Instead, it is transformed into an encryption key at runtime using PBKDF2-HMAC-SHA256 with a randomly generated 16-byte salt and a minimum of 100,000 iterations. The salt and iteration count are stored in plaintext at the top of the vault file — this is by design and not a vulnerability. The vault supports the full operational lifecycle: add, get, list, search, delete, generate, and export subcommands wired through a clean argparse interface. Passwords retrieved from the vault are copied directly to the system clipboard via xclip or pbcopy and automatically cleared after 15 seconds, ensuring they never persist beyond the intended session window.

Beyond the finished artifact, this operation builds deep fluency with the cryptographic patterns that real-world secure applications depend on every day. You will learn why plaintext passwords must never be stored in any form, why keys must always be derived rather than hard-coded, why every encryption operation requires a unique IV, and why authenticated encryption modes like GCM are mandatory in modern systems. These are not academic concepts — they are the precise failure points exploited in the majority of real credential breach incidents, and understanding them at the implementation level is what separates a practitioner from a user.

Agent Requirements
  • Solid Python fundamentals: classes, file I/O, and exception handling with try/except blocks
  • Comfortable installing packages with pip and working inside a virtual environment
  • Basic understanding of encryption concepts — what symmetric keys, plaintext, and ciphertext mean at a conceptual level
  • Familiar with JSON and working with structured data: reading, writing, and nesting dictionaries and lists
  • No prior cryptography implementation experience required — this project teaches the primitives from first principles
Operation Phases
Progress
0 / 5
✓
1
Master Key & Key Derivation
Implement PBKDF2-HMAC-SHA256 key derivation from the master password using Python's hashlib.pbkdf2_hmac. Generate a random 16-byte salt with os.urandom(16) on first vault creation and store it alongside the vault metadata. Derive a 256-bit (32-byte) key with a configurable iteration count defaulting to 100,000. Write a VaultKey class that encapsulates derivation and exposes a derive(password, salt, iterations) method returning the raw key bytes.
Checkpoint: Project Setup
  • Run the application and confirm the master password prompt appears
  • Verify the encryption library (e.g., cryptography or crypto) imports correctly
  • Confirm the vault data file is created on first run
✓
2
Encryption Engine
Build encrypt() and decrypt() functions using AES-256-GCM from the cryptography library (cryptography.hazmat.primitives.ciphers.aead.AESGCM). Generate a unique 12-byte nonce via os.urandom(12) for every encryption call — never reuse a nonce under the same key. GCM mode appends a 16-byte authentication tag automatically; verify it on decryption and raise a clear error on mismatch. Encode all binary output to base64 for safe embedding in JSON.
✓
3
Vault Data Structure
Design the vault format as a top-level JSON object with salt, iterations, version, and entries fields. Each entry is a dictionary holding id, site_enc, username_enc, password_enc, notes_enc, and created_at. Implement add(), get(), list_entries(), search(), and delete() methods in a Vault class. Encrypt each field individually so metadata leakage is minimized.
Checkpoint: Encryption & Storage
  • Store a password entry and verify the vault file contains only encrypted data (not plaintext)
  • Retrieve the entry using the master password and confirm it decrypts correctly
  • Attempt retrieval with the wrong master password and verify it fails with an error
✓
4
Password Generator
Build a cryptographically secure password generator using Python's secrets module — never random. Support configurable length (default 20) and character class toggles for uppercase, lowercase, digits, and symbols. After generation, calculate and display entropy in bits using the formula log2(charset_size ** length). Output a visual strength rating: Weak (<40 bits), Fair (40-60), Strong (60-80), Cryptographic (80+). Guarantee at least one character from each enabled class using a shuffle-and-fill approach.
Checkpoint: Security Hardening
  • Verify the master password is hashed (never stored in plaintext) using a strong KDF like PBKDF2 or Argon2
  • Confirm the vault locks after a period of inactivity or after the session ends
  • Test with a weak master password and verify the app warns or rejects it
✓
5
CLI Interface & Clipboard
Wire all vault operations to argparse subcommands: vault add, vault get, vault list, vault delete, vault generate, vault export. Prompt for the master password using getpass.getpass() so it never echoes to the terminal. Implement clipboard copy via subprocess calling xclip -sel clip on Linux or pbcopy on macOS, then spawn a background thread that sleeps 15 seconds and clears the clipboard by writing an empty string. Add a configurable vault lock timeout that clears the derived key from memory after inactivity.
Checkpoint: CRUD Operations
  • Add, retrieve, update, and delete a password entry — verify each operation works
  • List all stored entries and confirm they display site names but not plaintext passwords
  • Search for an entry by name and verify the correct result is returned
