Subject

Build a Password Vault

Operator 2H 1000 XP
Mission Brief

This operation requires the construction of a command-line encrypted password vault that stores credentials — site, username, and password — inside a single portable vault.json file. Every entry is encrypted individually using AES-256-GCM, an authenticated encryption scheme that simultaneously protects confidentiality and detects tampering. The vault file contains no readable plaintext whatsoever: site names, usernames, and passwords are all stored as base64-encoded ciphertext blobs, each with its own random nonce.

The master password is never stored. Instead, it is transformed into an encryption key at runtime using PBKDF2-HMAC-SHA256 with a randomly generated 16-byte salt and 600,000 iterations — the NIST-recommended minimum as of 2023. The salt and iteration count are stored in plaintext at the top of the vault file; this is by design and not a vulnerability. The key derivation is deterministic: the same password and salt always produce the same key, which is how decryption works on the next run.

Beyond the finished artifact, this operation builds deep fluency with the cryptographic patterns that real-world secure applications depend on. You will understand why plaintext passwords must never be stored in any form, why a fresh random nonce is required for every single encryption call, why GCM mode detects tampering automatically, and why a wrong master password produces InvalidTag rather than garbled output. These are the precise failure points exploited in real credential breach incidents.

    #!/usr/bin/env python3 """ phase1_kdf.py Derive a 256-bit AES key from a master password using PBKDF2-HMAC-SHA256. Proves determinism: same password + salt always yields the same key bytes. """ import os import hashlib # A random 16-byte salt is generated once when the vault is first created. # It is stored in vault.json in plaintext -- that is correct and expected. # Without the salt, an attacker cannot precompute keys (rainbow table attack). salt = os.urandom(16) # 600,000 is the NIST SP 800-132 recommended minimum for PBKDF2-HMAC-SHA256 # as of 2023. Higher iterations = slower brute force. On a modern laptop this # takes roughly 0.3 seconds, which is fine for interactive use. ITERATIONS = 600_000 password = b"CorrectHorseBatteryStaple" # bytes, not str key = hashlib.pbkdf2_hmac("sha256", password, salt, ITERATIONS) print("=== Phase 1: Key Derivation ===") print(f"Salt (hex): {salt.hex()}") print(f"Iterations: {ITERATIONS}") print(f"Key (hex): {key.hex()}") print(f"Key length: {len(key)} bytes ({len(key) * 8} bits)") # Prove determinism: derive again with the same inputs key2 = hashlib.pbkdf2_hmac("sha256", password, salt, ITERATIONS) print(f"Second derive matches: {key == key2}") # Output must be True -- if it is ever False, something is wrong.
  3. Run the script.
    python3 phase1_kdf.py
Why not Argon2? Argon2 is the stronger modern KDF (memory-hard, GPU-resistant) but requires the argon2-cffi package and has a more complex parameter surface. PBKDF2-HMAC-SHA256 at 600,000 iterations is the standard choice for production password managers (Bitwarden, 1Password) and is correct and safe for this project.
pbkdf2_hmac slows to a crawl?
  • That is intentional. 600,000 iterations takes about 0.3 s on a modern CPU. That wait is the entire point: it makes brute-force attacks 600,000× slower than a raw hash.
  • While developing and testing, you can temporarily lower to 10,000 in your scripts. Restore to 600,000 before building the final vault.

AES-256-GCM Encrypt / Decrypt Round-Trip
Use cryptography.hazmat.primitives.ciphers.aead.AESGCM to encrypt a secret, decrypt it back, tamper with the ciphertext to trigger InvalidTag, and attempt decryption with the wrong password. These three tests together prove the cipher works correctly and that both corruption and wrong passwords are caught at the crypto layer.
  1. Create phase2_gcm.py and paste this complete script.
    #!/usr/bin/env python3 """ phase2_gcm.py AES-256-GCM encrypt/decrypt demonstration. Tests: round-trip, tamper detection, wrong-password rejection. """ import os import base64 import hashlib from cryptography.hazmat.primitives.ciphers.aead import AESGCM from cryptography.exceptions import InvalidTag # ── Key setup (same as Phase 1) ─────────────────────────────────────────── password = b"CorrectHorseBatteryStaple" salt = os.urandom(16) key = hashlib.pbkdf2_hmac("sha256", password, salt, 600_000) aesgcm = AESGCM(key) # AESGCM expects exactly 32 bytes for AES-256 # ── Encrypt ──────────────────────────────────────────────────────────────── # CRITICAL: generate a FRESH random 12-byte (96-bit) nonce for EVERY # encryption call. Reusing a nonce with the same key catastrophically # breaks GCM -- an attacker can recover the key from two messages that # share a (key, nonce) pair. os.urandom(12) makes collision negligible. plaintext = b"hunter2!" nonce = os.urandom(12) ciphertext = aesgcm.encrypt(nonce, plaintext, None) # aesgcm.encrypt appends a 16-byte GCM authentication tag automatically. # The returned bytes are: ciphertext_bytes + 16_byte_tag (concatenated). print("=== Phase 2: AES-256-GCM Encrypt / Decrypt ===") print(f"Plaintext: {plaintext}") print(f"Nonce (hex): {nonce.hex()} ({len(nonce)} bytes)") print(f"Ciphertext: {base64.b64encode(ciphertext).decode()}" f" ({len(ciphertext)} bytes, includes 16-byte GCM tag)") # ── Decrypt round-trip ──────────────────────────────────────────────────── recovered = aesgcm.decrypt(nonce, ciphertext, None) print(f"Decrypted: {recovered}") print(f"Round-trip: {recovered == plaintext}") # ── Tamper test ─────────────────────────────────────────────────────────── # Flip one bit in the ciphertext. GCM verifies an authentication tag # over the entire ciphertext + nonce before decrypting. Any modification -- # even one bit -- raises InvalidTag. The plaintext is NEVER returned. print() print("=== Phase 2: Tamper Test ===") tampered = bytearray(ciphertext) tampered[0] ^= 0xFF # flip all bits in first ciphertext byte try: aesgcm.decrypt(nonce, bytes(tampered), None) print("ERROR: tamper was not detected -- this should never happen") except InvalidTag: print("InvalidTag raised on tampered ciphertext" " -- authentication works correctly") # ── Wrong-password test ─────────────────────────────────────────────────── # A wrong password produces a different key. Decryption with the wrong key # produces the wrong tag, which raises InvalidTag. The vault never exposes # a traceback to the user -- it catches InvalidTag and prints a clean error. print() print("=== Phase 2: Wrong Password Test ===") wrong_key = hashlib.pbkdf2_hmac("sha256", b"wrongpassword", salt, 600_000) wrong_aesgcm = AESGCM(wrong_key) try: wrong_aesgcm.decrypt(nonce, ciphertext, None) print("ERROR: wrong password was accepted -- this should never happen") except InvalidTag: print("InvalidTag raised for wrong master password" " -- vault remains sealed")
  2. Run the script.
    python3 phase2_gcm.py
Nonce reuse trap — read this before writing any loop.
  • AES-GCM becomes completely broken if you encrypt two messages with the same (key, nonce) pair. An attacker who sees both ciphertexts can XOR them to cancel the keystream and recover both plaintexts, and can also forge valid-looking messages. This is not theoretical — it is a standard attack.
  • The fix is always nonce = os.urandom(12) inside your encrypt function, called fresh for every single call. Never pass a nonce in from outside. Never increment a counter unless you are using a proper nonce counter scheme. os.urandom is cryptographically secure and the probability of a collision across billions of entries is negligible.

vault.json Schema and Adding Entries
Design the vault file format and write the add operation. The vault is a JSON object. The top level holds the KDF parameters (salt, iterations, version). Each entry stores the site, username, and password as separate encrypted blobs — each blob is a JSON object containing the base64-encoded nonce and ciphertext.
  1. Create phase3_vault_add.py and paste this complete script.
    #!/usr/bin/env python3 """ phase3_vault_add.py Build the vault.json schema and add two encrypted credential entries. """ import os import base64 import hashlib import json import uuid from datetime import datetime, timezone from cryptography.hazmat.primitives.ciphers.aead import AESGCM # ── Key setup ───────────────────────────────────────────────────────────── password = b"CorrectHorseBatteryStaple" salt = os.urandom(16) ITERATIONS = 600_000 key = hashlib.pbkdf2_hmac("sha256", password, salt, ITERATIONS) aesgcm = AESGCM(key) def encrypt_field(plaintext_str): """Encrypt a single string field. Returns a dict with nonce + ciphertext both base64-encoded for safe embedding in JSON. A FRESH nonce is generated for every call -- never reused.""" nonce = os.urandom(12) ct = aesgcm.encrypt(nonce, plaintext_str.encode(), None) return { "nonce": base64.b64encode(nonce).decode(), "ciphertext": base64.b64encode(ct).decode() } # ── vault.json top-level structure ──────────────────────────────────────── # salt and iterations are stored in plaintext -- this is correct. # They are NOT secret. Without the master password they are useless. vault = { "version": 1, "kdf": "pbkdf2-hmac-sha256", "iterations": ITERATIONS, "salt": base64.b64encode(salt).decode(), "entries": [] } # ── Add two credential entries ──────────────────────────────────────────── credentials = [ ("github.com", "agent007", "SecretPw#1"), ("email.example.com", "j.doe@example.com", "P@ss!word99"), ] for site, username, password_val in credentials: entry = { "id": str(uuid.uuid4()), "site": encrypt_field(site), "username": encrypt_field(username), "password": encrypt_field(password_val), "created_at": datetime.now(timezone.utc).isoformat() } vault["entries"].append(entry) # ── Write to disk ───────────────────────────────────────────────────────── with open("vault.json", "w") as f: json.dump(vault, f, indent=2) print("=== Phase 3: vault.json structure ===") with open("vault.json") as f: print(f.read()) print(f"Entries stored: {len(vault['entries'])}") print("No plaintext site names or passwords appear in the JSON.")
  2. Run the script.
    python3 phase3_vault_add.py
Why encrypt each field separately? If you encrypt a single JSON blob per entry, an attacker who sees that two entries have ciphertexts of the same length can infer they contain the same number of fields. Encrypting site, username, and password as separate blobs with independent nonces leaks less structural information and makes the scheme easier to extend later.

List and Retrieve Entries
Write the list and get operations that read vault.json, derive the key from the master password, and decrypt entries on demand. The list command decrypts only the site name for display — passwords remain encrypted until explicitly requested.
  1. This phase requires vault.json from Phase 3. If you do not have it, run python3 phase3_vault_add.py first. Then create phase4_list_get.py and paste this complete script.
    #!/usr/bin/env python3 """ phase4_list_get.py Read vault.json, derive the key, and decrypt entries on demand. Demonstrates list (site + username only) and full get (all fields). """ import base64 import hashlib import json from cryptography.hazmat.primitives.ciphers.aead import AESGCM from cryptography.exceptions import InvalidTag VAULT_FILE = "vault.json" def load_vault(): with open(VAULT_FILE) as f: return json.load(f) def derive_key(password_bytes, vault): salt = base64.b64decode(vault["salt"]) iterations = vault["iterations"] return hashlib.pbkdf2_hmac("sha256", password_bytes, salt, iterations) def decrypt_field(field_obj, aesgcm): nonce = base64.b64decode(field_obj["nonce"]) ct = base64.b64decode(field_obj["ciphertext"]) return aesgcm.decrypt(nonce, ct, None).decode() # ── Load vault and build cipher ─────────────────────────────────────────── vault = load_vault() # In the real vault, use getpass.getpass("Master password: ") password = b"CorrectHorseBatteryStaple" key = derive_key(password, vault) aesgcm = AESGCM(key) # ── list: decrypt site + username only ──────────────────────────────────── print("=== Phase 4: List Entries ===") for i, entry in enumerate(vault["entries"]): site = decrypt_field(entry["site"], aesgcm) username = decrypt_field(entry["username"], aesgcm) print(f"[{i}] site={site} user={username} (password hidden)") # ── get: decrypt all fields for entry 0 ────────────────────────────────── print() print("=== Phase 4: Retrieve and Decrypt Entry 0 ===") e = vault["entries"][0] print(f" site: {decrypt_field(e['site'], aesgcm)}") print(f" username: {decrypt_field(e['username'], aesgcm)}") print(f" password: {decrypt_field(e['password'], aesgcm)}")
  2. Run the script.
    python3 phase4_list_get.py

Update, Delete, and Master Password Change
Write the three mutation operations. Update re-encrypts a single field with a fresh nonce. Delete removes an entry by its UUID. Master password change decrypts every entry under the old key and re-encrypts it under a new key derived from the new password — a new salt is generated for the new key. After the change, the old key can no longer decrypt anything.
  1. Create phase5_mutate.py and paste this complete script.

Lost master password means the vault is permanently unrecoverable — by design.
  • There is no back door. The key is derived entirely from the password and salt. Without the correct password, InvalidTag is raised and no plaintext is returned. This is the correct security behavior.
  • In a real vault, prompt users to write down a recovery phrase before creating the vault. This project does not implement a recovery path because building one securely is a separate project.
  • If vault.json is corrupted or partially written (power loss during save), no amount of correct password will help. In production you would write to a temp file and rename atomically: os.replace("vault.json.tmp", "vault.json").

Complete CLI: argparse, getpass, and Clipboard
Wire all operations into a single vault.py with argparse subcommands. The master password is read silently via getpass so it never echoes to the terminal. The get command copies the password to the clipboard and clears it automatically after 15 seconds. Wrong password is caught and shown as a clean error.
  1. Create vault.py and paste this complete script.
    #!/usr/bin/env python3 """ vault.py -- Command-line AES-256-GCM password vault. Usage: python3 vault.py init python3 vault.py add --site github.com --username agent007 python3 vault.py list python3 vault.py get --site github.com python3 vault.py delete --id <uuid> python3 vault.py change-password """ import argparse import base64 import getpass import hashlib import json import os import subprocess import sys import threading import uuid from datetime import datetime, timezone from cryptography.hazmat.primitives.ciphers.aead import AESGCM from cryptography.exceptions import InvalidTag VAULT_FILE = "vault.json" ITERATIONS = 600_000 # ── Vault I/O helpers ───────────────────────────────────────────────────── def load_vault(): if not os.path.exists(VAULT_FILE): sys.exit(f"No vault found at {VAULT_FILE}. Security notes before you ship this vault.
  • Clipboard exposure: get blocks for 15 seconds while the clear thread runs (the CLI uses t.join() so the process stays alive until the clipboard is wiped). Do not close the terminal during that window or the clear will not fire. On Linux, xclip also holds the clipboard only while the owning process is alive, so closing the terminal before the 15 s elapses drops the clipboard immediately with xclip, but not with xsel or wl-copy. Warn users not to paste into untrusted windows.
  • Vault.json permissions: after creating the vault, restrict permissions: chmod 600 vault.json. This prevents other users on the same system from reading the file.
  • Swap / core dumps: Python does not give you direct control over whether the master password string gets swapped to disk. On Linux, disable swap or use an encrypted swap partition when running any password manager in production.
  • Screen capture / shoulder surfing: getpass suppresses terminal echo but does not protect against screen-capture malware. The site name and username are printed in plaintext on list — be aware of your environment.
