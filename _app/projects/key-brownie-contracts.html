Subject

Deploy Smart Contracts with Brownie

Operative 60 min 500 XP
Mission Brief

Ethereum smart contracts are immutable programs deployed to a global state machine. This operation puts Brownie — the Python-native smart contract framework — in your hands and walks you through the complete development lifecycle from first Solidity line to live testnet deployment. You will write a simple ERC-20 token contract in Solidity, compile it with brownie compile, and immediately run a comprehensive test suite with brownie test backed by pytest and a local Ganache EVM instance.

The deployment pipeline uses a Python script that leverages Brownie's account system to sign and broadcast transactions. You will configure environment variables for a Sepolia testnet RPC endpoint and a funded test wallet, then deploy using brownie run deploy --network sepolia. Post-deployment, you will interact with the live contract from the Brownie interactive console: calling view functions, sending transactions, and reading emitted events from the receipt object.

The non-obvious depth of this project is test design for irreversible code. Unlike web applications, a bug in a deployed contract cannot be patched — it can only be abandoned. Writing tests that cover revert conditions, access control violations, and arithmetic edge cases is not optional hygiene; it is the only meaningful defense before real value is at stake. This project ingrains that discipline.

Agent Requirements
  • Comfortable with Python: functions, classes, and working with virtual environments
  • Basic understanding of what a blockchain is — blocks, transactions, and wallet addresses
  • Familiar with pytest for writing and running automated tests
  • Node.js installed (required for Ganache, Brownie's local EVM backend)
  • No prior Solidity or smart contract experience required — syntax is introduced line by line

Environment Setup & Project Initialization

  • Run brownie init in a new directory and verify the project structure is created
  • Confirm Ganache or a local blockchain is running on the expected port
✓
2
Smart Contract Development in Solidity
Write a Solidity ERC-20 token contract inheriting from OpenZeppelin's ERC20 base. Add a mint(address to, uint256 amount) function gated by an onlyOwner modifier. Include a Paused event, a pause() and unpause() function, and a whenNotPaused modifier on all state-changing operations. Compile with brownie compile and inspect the ABI output.
✓
3
Automated Test Suite
Write four pytest test files using Brownie's test fixtures. test_deploy.py asserts the initial supply and owner address. test_mint.py calls mint() and verifies balance changes. test_transfer.py validates ERC-20 transfer and approval flows. test_revert.py uses brownie.exceptions.VirtualMachineError to assert that unauthorized callers are correctly rejected. Run with brownie test -v.
Checkpoint: Smart Contract Development
  • Compile your Solidity contract with brownie compile and verify zero errors
  • Check the build/contracts/ directory for the compiled ABI and bytecode
  • Verify the contract's constructor parameters are correctly defined
✓
4
Deployment Script & Testnet Deploy
Write scripts/deploy.py that loads the deployer account from an encrypted keystore using accounts.load('deployer'), deploys the contract with Token.deploy({'from': account}), and prints the contract address and transaction hash to stdout. Execute against Sepolia with brownie run deploy --network sepolia and verify the deployment on Etherscan Sepolia.
Checkpoint: Deployment
  • Deploy to a testnet and verify the contract address is returned
  • Interact with the deployed contract using brownie console and confirm methods work
  • Verify the contract is visible on the testnet block explorer
✓
5
Interactive Console & Event Inspection
Connect to the live contract from the Brownie console with brownie console --network sepolia. Load the contract object using Token.at(address), call token.totalSupply(), send a mint() transaction, and decode the emitted Transfer event from tx.events. Call pause() and verify that a subsequent mint() reverts with the expected error string.
Checkpoint: Testing
  • Run brownie test and verify all test cases pass
  • Check test coverage with brownie test --coverage and confirm key functions are covered
  • Test an edge case (e.g., transferring more tokens than balance) and verify it reverts correctly
