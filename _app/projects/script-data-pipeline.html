Build a Data Pipeline with Dashboard

Operative 90 MIN 500 XP
Mission Brief

Heads up: Kedro is an intermediate framework with a genuine learning curve — if you hit a cryptic error during setup or wiring, that is normal and expected, not a sign that you made a mistake. Every troubleshooting box in this project exists because real engineers hit that exact wall.

Your assignment is to build a working data pipeline using the Kedro framework and visualize its output through an interactive hvPlot dashboard served by Panel. You will go from an empty folder to a running browser dashboard in five phases, following every command exactly as written. No prior Kedro, hvPlot, or Panel experience is required.

Kedro treats a data pipeline as a directed acyclic graph (DAG) of pure Python functions called nodes. Each node has named inputs and outputs that Kedro resolves automatically from a central Data Catalog defined in YAML. You never hardcode file paths inside functions — you name a dataset, and Kedro loads or saves it for you. This separation means every node is independently testable and every dataset is reproducible. kedro run executes the full graph in dependency order with a single command.

The dashboard layer uses hvPlot 0.12.2 on top of pandas to produce interactive Bokeh charts — line plots, bar charts, scatter plots — all with zoom, pan, and hover built in. Panel 1.9.3 composes those charts into a web application and serves it locally. The result is a self-contained analytics product: run the pipeline to produce data, then launch the dashboard to explore it in your browser without writing a single line of JavaScript.

Agent Requirements
  • Python 3.10 or higher — Kedro 1.4.0 requires Python 3.10 or higher. Run python --version or python3 --version in your terminal to check. If you see 3.9 or lower, install a newer Python from python.org/downloads before starting.
  • A terminal (Windows: PowerShell or Command Prompt; Mac/Linux: any shell). Every command in this project is shown exactly as you type it.
  • Comfortable writing Python functions that accept a pandas DataFrame and return a DataFrame. Kedro nodes are exactly that. No classes, no frameworks, just functions.
  • Basic pandas familiarity: reading a CSV with pd.read_csv(), filtering rows, adding columns, and groupby(). Phase 3 builds on this directly.
  • No Kedro, hvPlot, or Panel experience needed. No paid accounts. No cloud services. The entire project runs on your laptop.

Transformation Nodes
Write the pure Python functions that do the actual data work. In Kedro, a node wraps one of these functions and declares its inputs and outputs by name. The functions themselves know nothing about Kedro — they accept pandas DataFrames (or scalars for parameters) and return DataFrames. This makes them trivially unit-testable and reusable. You will write two transformation functions in nodes.py inside a new pipeline subdirectory.
Why a pipelines/ subfolder? Kedro encourages organizing related nodes into modular pipelines, each in their own subdirectory under src/sales_pipeline/pipelines/. Each subfolder contains nodes.py (functions), pipeline.py (DAG wiring), and __init__.py. This project has one pipeline called reporting.
  1. Create the reporting pipeline directory.
    # Mac / Linux mkdir -p src/sales_pipeline/pipelines/reporting # Windows PowerShell New-Item -ItemType Directory -Force -Path src\sales_pipeline\pipelines\reporting
  2. Create src/sales_pipeline/pipelines/reporting/__init__.py. This file must exist (even if empty) for Python to treat the folder as a package. Create it and leave it blank:
    # __init__.py — intentionally empty
  3. Create src/sales_pipeline/pipelines/reporting/nodes.py with the following complete content:
    """ nodes.py — Transformation functions for the reporting pipeline. Each function is a pure Python function: it accepts pandas DataFrames (and optional scalar parameters) and returns a transformed DataFrame. No Kedro imports are needed here. The functions have no side effects beyond their return value. """ import pandas as pd def clean_sales(raw_sales: pd.DataFrame, min_units: int) -> pd.DataFrame: """ Clean and type-cast the raw sales data. Steps: - Parse 'date' column to datetime - Compute a 'revenue' column (units_sold * unit_price) - Drop rows where units_sold is below the min_units threshold - Drop any rows with null values - Reset the index so the output has a clean integer index Args: raw_sales: Raw DataFrame loaded from data/01_raw/sales.csv min_units: Minimum units threshold; rows below this are dropped. Returns: Cleaned DataFrame with added 'revenue' column. """ df = raw_sales.copy() # Parse date strings to actual datetime objects df["date"] = pd.to_datetime(df["date"]) # Compute revenue for each row df["revenue"] = df["units_sold"] * df["unit_price"] # Filter out low-volume rows df = df[df["units_sold"] >= min_units] # Drop any remaining nulls and reset the index df = df.dropna().reset_index(drop=True) return df def aggregate_sales(clean_sales: pd.DataFrame) -> pd.DataFrame: """ Aggregate cleaned sales data into a summary by region and product. Groups the cleaned data by region and product, computing: - total_units: sum of units_sold - total_revenue: sum of revenue - avg_unit_price: mean of unit_price Args: clean_sales: The cleaned DataFrame produced by clean_sales(). Returns: Aggregated summary DataFrame. """ summary = ( clean_sales .groupby(["region", "product"], as_index=False) .agg( total_units=("units_sold", "sum"), total_revenue=("revenue", "sum"), avg_unit_price=("unit_price", "mean"), ) ) # Round monetary values to 2 decimal places summary["total_revenue"] = summary["total_revenue"].round(2) summary["avg_unit_price"] = summary["avg_unit_price"].round(2) return summary
    Notice: neither function imports anything from Kedro. They are plain pandas functions. Kedro calls them and handles loading/saving the DataFrames before and after. This is the key Kedro discipline: your code does data work; Kedro does I/O orchestration.
IndentationError when running the pipeline later? Python requires consistent indentation. If you mixed tabs and spaces, Python will error. In VS Code, open the file, look at the bottom status bar for “Spaces: 4” or “Tab Size” — click it and choose “Convert Indentation to Spaces” to normalize everything.
NameError: name 'pd' is not defined? The import pandas as pd line at the top of nodes.py is missing or has a typo. Every file that uses pandas must import it independently.

Pipeline DAG Wiring & Execution
Wire the node functions into a Kedro pipeline by declaring each Node with its catalog dataset names as inputs and outputs. Register the pipeline so kedro run can find it. Then run the pipeline and observe the execution log confirming each node fires in dependency order. After this phase, data/03_primary/sales_summary.parquet exists on disk and is ready for the dashboard.
  1. Create src/sales_pipeline/pipelines/reporting/pipeline.py with the following complete content:
    """ pipeline.py — Assemble the reporting pipeline DAG. A Pipeline is an ordered collection of Nodes. Kedro reads the inputs/outputs of each Node and determines execution order automatically (topological sort). You do not specify order manually. Naming convention: the catalog dataset name in inputs/outputs must exactly match the key in conf/base/catalog.yml or a params: reference. """ from kedro.pipeline import Node, Pipeline def create_pipeline(**kwargs) -> Pipeline: """ Create and return the reporting pipeline. Returns: A Pipeline containing all nodes for the reporting workflow. """ return Pipeline( [ Node( # The function to call func=clean_sales_node, # Inputs: names must match catalog.yml keys or params: prefix inputs=["raw_sales", "params:min_units"], # Output: must match a catalog.yml key or be a memory-only name outputs="clean_sales", name="clean_sales_node", ), Node( func=aggregate_sales_node, inputs="clean_sales", outputs="sales_summary", name="aggregate_sales_node", ), ] ) # Import the actual transformation functions # We import at the bottom to keep the create_pipeline function readable. from .nodes import clean_sales as clean_sales_node # noqa: E402 from .nodes import aggregate_sales as aggregate_sales_node # noqa: E402
    How Kedro resolves the DAG: Node 1 outputs clean_sales. Node 2 lists clean_sales as its input. Kedro sees this dependency and automatically runs Node 1 before Node 2. If you add a third node that also consumes clean_sales, Kedro can run it in parallel with Node 2 when using a parallel runner. You never specify order manually — the DAG infers it from catalog names.
  2. Register the pipeline in src/sales_pipeline/pipeline_registry.py. Open the existing file (Kedro generates a skeleton) and replace its contents with:
    """ pipeline_registry.py — Register all pipelines for kedro run. register_pipelines() must return a dict mapping pipeline name strings to Pipeline objects. The special key "__default__" is what kedro run executes when you do not pass a --pipeline flag. """ from typing import Dict from kedro.pipeline import Pipeline from sales_pipeline.pipelines.reporting.pipeline import create_pipeline def register_pipelines() -> Dict[str, Pipeline]: """Register the project's pipelines.""" reporting_pipeline = create_pipeline() return { "reporting": reporting_pipeline, # __default__ runs when you type: kedro run (no --pipeline flag) "__default__": reporting_pipeline, }
    This is the most important wiring step. If __default__ is missing or the import path has a typo, kedro run will complete instantly with “0 nodes ran” and no output files. Kedro will not error — it just finds no nodes to execute. Always verify the import path matches the exact package and module names on disk.
  3. Run the pipeline. Make sure your terminal is in the project root (the directory with pyproject.toml) and the venv is active, then:

INFO Loading data from 'clean_sales' (ParquetDataset)... Interactive Dashboard with hvPlot & Panel
Load the pipeline output from data/03_primary/sales_summary.parquet, build interactive charts with hvPlot, and compose them into a Panel web application. Serve the dashboard with panel serve and open it in your browser at http://localhost:5006/dashboard. The charts are interactive — zoom, pan, and hover tooltips work without any additional code. A dropdown widget lets you filter the chart by product without reloading the page.
  1. Create the dashboard script. In the Kedro project root (next to pyproject.toml), create a new file named dashboard.py with the following complete content:
    """ dashboard.py Interactive sales dashboard powered by hvPlot 0.12.2 and Panel 1.9.3. Run with: panel serve dashboard.py --dev Then open: http://localhost:5006/dashboard The dashboard loads the pipeline output from data/03_primary/sales_summary.parquet, which kedro run must have already produced (Phase 4). Re-run kedro run any time to refresh the data. """ import panel as pn import pandas as pd import hvplot.pandas # noqa: F401 — registers the .hvplot accessor on DataFrames # ── 1. Bootstrap Panel ───────────────────────────────────────────────────── # pn.extension() loads Panel's JavaScript dependencies into the page. # It must be called before any Panel or hvPlot objects are constructed. pn.extension(sizing_mode="stretch_width") # ── 2. Load the pipeline output ──────────────────────────────────────────── df = pd.read_parquet("data/03_primary/sales_summary.parquet") # ── 3. Widgets ───────────────────────────────────────────────────────────── # A Select widget lets the user filter the bar chart by product. product_select = pn.widgets.Select( name="Filter by product", options=["All"] + sorted(df["product"].unique().tolist()), value="All", ) # ── 4. Reactive chart functions ──────────────────────────────────────────── # These functions take the current widget value and return an hvPlot chart. # Panel calls them automatically whenever a widget changes. def revenue_bar(product): """Total revenue by region, optionally filtered by product.""" data = df if product == "All" else df[df["product"] == product] grouped = ( data.groupby("region", as_index=False)["total_revenue"].sum() ) return grouped.hvplot.bar( x="region", y="total_revenue", title=f"Total Revenue by Region ({product})", color="steelblue", ylabel="Revenue ($)", xlabel="Region", height=320, responsive=True, ) def units_bar(product): """Total units sold by region as a bar chart, optionally filtered by product.""" data = df if product == "All" else df[df["product"] == product] grouped = ( data.groupby("region", as_index=False)["total_units"].sum() ) return grouped.hvplot.bar( x="region", y="total_units", title=f"Total Units Sold by Region ({product})", color="seagreen", ylabel="Units Sold", xlabel="Region", height=320, responsive=True, ) def price_scatter(_product): """Average unit price vs total revenue scatter (all products).""" return df.hvplot.scatter( x="avg_unit_price", y="total_revenue", by="product", title="Avg Unit Price vs Total Revenue (all products)", ylabel="Total Revenue ($)", xlabel="Avg Unit Price ($)", size=80, height=320, responsive=True, legend="top_right", ) # ── 5. Bind widgets to chart functions ───────────────────────────────────── # pn.bind() creates a reactive expression: when product_select changes, # Panel re-calls the function with the new value and updates the display. revenue_chart = pn.bind(revenue_bar, product_select) units_chart = pn.bind(units_bar, product_select) scatter_chart = pn.bind(price_scatter, product_select) # ── 6. Layout and serve ──────────────────────────────────────────────────── dashboard = pn.template.FastListTemplate( title="Sales Pipeline Dashboard", sidebar=[ pn.pane.Markdown("## Controls"), product_select, pn.pane.Markdown( "**Data source:** `data/03_primary/sales_summary.parquet`\n\n" "Re-run `kedro run` to refresh." ), ], main=[ pn.pane.Markdown("## Revenue by Region"), revenue_chart, pn.pane.Markdown("## Units Sold by Region"), units_chart, pn.pane.Markdown("## Price vs Revenue"), scatter_chart, ], ) # .servable() registers this layout with Panel's server. # It must be called for panel serve to render the app. dashboard.servable()
  2. Serve the dashboard. Make sure your terminal is in the Kedro project root (where dashboard.py is) and the venv is active, then:

    2026-06-18 10:15:32,841 Starting Bokeh server version 3.x.x (running on Tornado 6.x.x) 2026-06-18 10:15:32,847 User authentication hooks NOT provided (default user enabled) 2026-06-18 10:15:32,852 Bokeh app running at: http://localhost:5006/dashboard 2026-06-18 10:15:32,852 Starting Bokeh server with process id: 12345

  • The import hvplot.pandas line is missing or was removed. This import registers the .hvplot accessor on pandas DataFrames. Without it, df.hvplot.bar() raises AttributeError: 'DataFrame' object has no attribute 'hvplot'.

FileNotFoundError: data/03_primary/sales_summary.parquet not found? You must run kedro run from the Kedro project root before launching the dashboard. panel serve dashboard.py does not run the pipeline — it only reads an already-produced output file. Run the pipeline first, then the dashboard.
panel serve fails with EADDRINUSE or “port 5006 is already in use”? A previous panel serve process is still running. Press Ctrl+C in its terminal window to stop it, then run panel serve dashboard.py --dev again. Alternatively, use a different port: panel serve dashboard.py --dev --port 5007 and navigate to http://localhost:5007/dashboard.
Dropdown widget changes but charts do not update? The reactive binding is not in place. In the dashboard script, confirm that pn.bind(revenue_bar, product_select) (and the equivalent for the other two charts) is called and the result is passed into the main= list, not the raw function reference. Passing the function directly instead of the pn.bind() result means Panel calls it once at startup and does not re-call it on widget changes.
