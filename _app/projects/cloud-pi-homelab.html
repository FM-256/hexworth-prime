Subject

Build a Pi Home Lab Server

Journeyman 120 min 500 XP
Mission Brief

This operation transforms a Raspberry Pi 4B into a self-hosted home lab running production-grade containerized services — the same Docker-based infrastructure pattern used in enterprise cloud deployments, compressed onto a credit-card-sized computer.

You will harden the base OS with SSH lockdowns and firewall rules, install Docker and Docker Compose for container orchestration, deploy Pi-hole as a network-wide DNS sinkhole that blocks ads and trackers for every device on your network, stand up Portainer as a web-based container management GUI, and front everything with an Nginx reverse proxy configured with SSL/TLS certificates.

The end result is a silent, always-on server that filters your DNS, manages its own containers through a clean web interface, and serves everything over HTTPS. This is the foundational pattern behind every cloud deployment — containers, reverse proxies, DNS, and TLS — running on your own hardware.

Agent Requirements
  • A Raspberry Pi 4B with 4GB+ RAM and a quality microSD card (32GB+)
  • Ethernet connection recommended for server stability
  • Basic Linux command line comfort (cd/ls/nano/sudo)
  • Understanding of what DNS and IP addresses are
  • No prior Docker or container experience required — the project teaches from scratch
Operation Phases
1
OS Installation & SSH Hardening
Flash Raspberry Pi OS Lite (64-bit), enable SSH, disable password auth in favor of key-based login, change the default port, install and configure ufw firewall to allow only SSH, HTTP, HTTPS, and DNS traffic.
Checkpoint: OS & SSH Setup
  • SSH login works from another device on the network
  • Root login via SSH is disabled in sshd_config
  • Firewall (ufw) is active with only port 22 allowed
2
Docker & Docker Compose Setup
Install Docker Engine and Docker Compose on the Pi. Verify the installation with docker run hello-world. Create a project directory structure and a docker-compose.yml skeleton that will orchestrate all services.
Checkpoint: Docker Installation
  • docker --version and docker compose version return valid output
  • Your non-root user can run docker commands without sudo
  • A test container (hello-world) runs and exits successfully
3
Deploy Pi-hole for DNS Filtering
Add Pi-hole as a service in your Compose file with proper volume mounts for persistent configuration. Start the container, access the Pi-hole admin dashboard, configure your router to use the Pi as its DNS server, and verify ad-blocking across network devices.
Checkpoint: Pi-hole Deployment
  • Pi-hole admin dashboard loads at the configured address
  • DNS queries from a client device route through Pi-hole
  • Ad-blocking is functional — test with a known ad domain
4
Portainer for Container Management
Add Portainer CE to your Compose stack, binding its web UI to a dedicated port. Use Portainer to visualize running containers, inspect logs, manage volumes, and monitor resource usage — all from a browser instead of the command line.
Checkpoint: Portainer Setup
  • Portainer web UI is accessible and shows running containers
  • Pi-hole container appears in the Portainer dashboard
  • You can start/stop a container from the Portainer interface
5
Nginx Reverse Proxy with SSL
Deploy Nginx as a reverse proxy that routes pihole.local and portainer.local to their respective containers. Generate self-signed TLS certificates with openssl (or use Let's Encrypt with a domain), configure HTTPS listeners, and redirect all HTTP traffic to HTTPS.
Checkpoint: Reverse Proxy & SSL
  • Services are accessible via subdomain or path through Nginx
  • SSL certificate is valid and HTTPS connections succeed
  • Direct port access to backend services is blocked by firewall
  • Nginx error logs show no upstream connection failures
