Subject

Build a Task Manager with Local Storage

Beginner 90 min 400 XP
Mission Brief

Your assignment is to build a fully functional task manager web application using vanilla JavaScript, HTML, and CSS. The application allows users to create tasks with a title and priority level, mark them complete, edit them inline, and delete them — the classic CRUD cycle that powers every productivity tool on the planet.

All data persists between page reloads using localStorage. Tasks are stored as a JSON array and serialized/deserialized on every mutation. The UI includes filter tabs (All / Active / Completed), a sort-by-priority toggle, and a count of remaining items. Zero external dependencies — no frameworks, no libraries, no build step.

This project teaches the model-view separation pattern at its simplest: your task array is the single source of truth, the storage layer persists it, and the renderer reads it to paint the DOM. Every mutation flows through the same save-then-render pipeline. Master this loop and you understand the core of every frontend framework.

Agent Requirements
  • Comfortable writing semantic HTML and CSS layouts (flexbox or grid)
  • JavaScript fundamentals: arrays, objects, functions, template literals
  • DOM selection and manipulation (querySelector, createElement)
  • Event delegation and addEventListener
  • Basic understanding of JSON serialization (JSON.stringify / JSON.parse)
Operation Phases
1
Task Model and localStorage Layer
Define the task object shape: { id, title, priority, done, createdAt }. Write loadTasks() and saveTasks(tasks) functions that read from and write to localStorage using JSON serialization. Generate unique IDs with Date.now() or a simple counter.
Checkpoint: Data Layer
  • Tasks persist in localStorage across page refreshes
  • Each task has a unique ID, title, priority, and completed status
  • Corrupted localStorage data is handled without crashing the app
2
UI Renderer and Add/Delete Operations
Build a renderList() function that clears the container and loops through the task array to create DOM elements for each task. Wire up the form submit to push a new task, and add a delete button per row that removes by ID. Every mutation calls saveTasks() then renderList().
Checkpoint: Core Operations
  • Adding a task appends it to the visible list immediately
  • Delete button removes the task from both the UI and localStorage
  • Empty task titles are rejected with a visible validation message
3
Toggle Complete and Inline Edit
Add a checkbox per task that toggles the done boolean. Completed tasks get a strikethrough style. Add double-click to enter inline edit mode: replace the title text with an input field, save on Enter or blur, cancel on Escape. Use event delegation on the parent container rather than attaching listeners to each row.
Checkpoint: Edit & Toggle
  • Clicking the checkbox toggles the completed state visually
  • Double-clicking a task title enables inline editing
  • Pressing Enter or clicking away saves the edited title
4
Filter Tabs and Sort-by-Priority
Add three filter tabs — All, Active, Completed — that control which tasks are visible. Use Array.filter() before rendering. Add a priority dropdown (low / medium / high) on the add form and a sort toggle that reorders the list by priority level using Array.sort(). Display a count of remaining active tasks in the footer.
Checkpoint: Filtering & Sorting
  • All, Active, and Completed tabs filter the list correctly
  • Sorting by priority places high-priority tasks at the top
  • Filter and sort state persists when tasks are added or removed
5
Polish: Animations, Clear Completed, and Stats
Add a "Clear Completed" button that bulk-removes all done tasks. Add CSS transitions for task entry and removal (fade-in, slide-out). Display a small stats bar showing total tasks, completed percentage, and tasks per priority level. Ensure the app is fully usable on mobile with responsive layout.
Checkpoint: Polish & Stats
  • Tasks animate in on add and fade out on delete
  • Clear Completed removes all done tasks in one action
  • Stats bar shows total, active, and completed counts
