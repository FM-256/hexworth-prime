Subject

Build a Memory Card Game

Recruit 60 min 250 XP
Mission Brief

Your assignment is to build an interactive memory card matching game using React and Vite. The board displays a 4×4 grid of face-down cards containing symbol pairs. The player flips two cards per turn — a match keeps both face-up permanently and a mismatch flips them back after a short delay. The game ends when all eight pairs are found.

You will build this with idiomatic React: functional components, useState for card state and flip tracking, and a useEffect that watches the two flipped cards and triggers the match check. A useRef-backed interval drives the move timer. A lock flag prevents the classic “third-card double-flip” bug during the comparison window.

Prerequisite — Node.js is required. This project uses Vite as the development server, which runs on Node.js. You need Node.js LTS installed on your machine before starting Phase 1. Everything else is covered step by step.

Agent Requirements
  • Node.js 20 LTS installed — download from nodejs.org; verify with node -v and npm -v in your terminal
  • A free code editor such as VS Code (code.visualstudio.com)
  • Basic comfort opening a terminal (Command Prompt / PowerShell on Windows; Terminal on Mac)
  • No prior React experience required — every concept is introduced in context as you need it

    import { useState } from 'react'; import './App.css'; import Card from './Card'; /* ── 8 symbols, duplicated to make 16 cards ── */ const SYMBOLS = ['A', 'B', 'C', 'D', 'E', 'F', 'G', 'H']; /* Fisher-Yates shuffle: returns a NEW shuffled array, never mutates input */ function shuffle(arr) { const a = [...arr]; /* copy so original is untouched */ for (let i = a.length - 1; i > 0; i--) { const j = Math.floor(Math.random() * (i + 1)); [a[i], a[j]] = [a[j], a[i]]; /* swap */ } return a; } /* Build a fresh deck: each symbol gets two card objects with unique ids */ function buildDeck() { const pairs = [...SYMBOLS, ...SYMBOLS]; /* 16 items */ return shuffle(pairs).map((symbol, index) => ({ id: index, symbol, isFlipped: false, isMatched: false, })); } export default function App() { const [cards, setCards] = useState(buildDeck); const [moves, setMoves] = useState(0); /* Flip a card by its id */ function handleFlip(id) { setCards(prev => prev.map(c => c.id === id ? { ...c, isFlipped: true } : c) ); } return ( <div className="app"> <h1>Memory Game</h1> <div className="stats"> Moves: <span>{moves}</span> </div> <div className="board"> {cards.map(card => ( <Card key={card.id} card={card} onFlip={handleFlip} /> ))} </div> <button className="btn-new" onClick={() => { setCards(buildDeck()); setMoves(0); }}> New Game </button> </div> ); }

Match Logic, Lock-Out, and Flip-Back with useEffect
Track the two flipped cards with a second piece of state. A useEffect watches that array: when it reaches length two it compares symbols, locks the board to block a third click, then either marks the pair as matched or flips both back after a 900 ms delay.
Why the lock flag is not optional: Without it, a fast player can click a third card while the 900 ms timer is running. That third card gets added to the “flipped” array, the comparison runs on the wrong pair, and one card permanently disappears from play. The lock flag sets isLocked = true the instant two cards are up, blocks handleFlip entirely until the timer fires, then clears itself.
  1. Replace src/App.jsx entirely with this updated version, which adds flipped state, the isLocked ref, and the useEffect match checker:
    import { useState, useEffect, useRef } from 'react'; import './App.css'; import Card from './Card'; const SYMBOLS = ['A', 'B', 'C', 'D', 'E', 'F', 'G', 'H']; function shuffle(arr) { const a = [...arr]; for (let i = a.length - 1; i > 0; i--) { const j = Math.floor(Math.random() * (i + 1)); [a[i], a[j]] = [a[j], a[i]]; } return a; } function buildDeck() { return shuffle([...SYMBOLS, ...SYMBOLS]).map((symbol, index) => ({ id: index, symbol, isFlipped: false, isMatched: false, })); } export default function App() { const [cards, setCards] = useState(buildDeck); const [flipped, setFlipped] = useState([]); /* ids of currently flipped cards */ const [moves, setMoves] = useState(0); const isLocked = useRef(false); /* ref so it never causes a re-render */ /* ── Match-check effect: fires every time `flipped` changes ── */ useEffect(() => { if (flipped.length !== 2) return; /* wait until exactly two are up */ const [idA, idB] = flipped; const cardA = cards.find(c => c.id === idA); const cardB = cards.find(c => c.id === idB); if (cardA.symbol === cardB.symbol) { /* Match: mark both permanently face-up, clear flipped list */ setCards(prev => prev.map(c => c.id === idA || c.id === idB ? { ...c, isMatched: true } : c ) ); setFlipped([]); isLocked.current = false; } else { /* No match: flip both back after 900 ms */ setTimeout(() => { setCards(prev => prev.map(c => c.id === idA || c.id === idB ? { ...c, isFlipped: false } : c ) ); setFlipped([]); isLocked.current = false; }, 900); } }, [flipped]); /* only run when flipped array changes */ /* ── Card click handler ── */ function handleFlip(id) { if (isLocked.current) return; /* board locked: ignore click */ if (flipped.includes(id)) return; /* same card clicked twice: ignore */ if (cards.find(c => c.id === id).isMatched) return; /* already matched */ const nextFlipped = [...flipped, id]; /* Flip the card visually */ setCards(prev => prev.map(c => c.id === id ? { ...c, isFlipped: true } : c) ); if (nextFlipped.length === 2) { isLocked.current = true; /* lock the board as soon as two cards are up */ setMoves(m => m + 1); /* count this as one move */ } setFlipped(nextFlipped); } /* ── Reset ── */ function newGame() { isLocked.current = false; setFlipped([]); setMoves(0); setCards(buildDeck()); } return ( <div className="app"> <h1>Memory Game</h1> <div className="stats"> Moves: <span>{moves}</span> </div> <div className="board"> {cards.map(card => ( <Card key={card.id} card={card} onFlip={handleFlip} /> ))} </div> <button className="btn-new" onClick={newGame}>New Game</button> </div> ); }
    Expected ESLint warning — safe to ignore. Vite’s default ESLint config may flag the match-check useEffect with: React Hook useEffect has a missing dependency: ‘cards’. This warning is correct by ESLint’s rule but harmless here. The effect reads cards to look up the two flipped cards at the exact moment two are selected — it must not re-run every time cards changes, because that would re-trigger the match check on every state update (including the ones caused by the match itself). The dependency array [flipped] is intentional design: the effect’s job is to respond to new flip pairs, not to card-state changes. Do not add cards to the dependency array — doing so creates an infinite loop where matching a pair triggers a re-run, which tries to match again, which triggers another re-run.
  2. Save and test in the browser. Flip two cards that do not match: both should hold for about a second, then flip back. Flip two cards with the same letter: both should stay face-up and glow green. Try clicking a third card immediately after the second — it should do nothing while the comparison is in progress.
Stale state — cards not flipping back / match state looks wrong?
  • The most common React beginner mistake: writing cards[index].isFlipped = true directly. This mutates the existing state object. React uses reference equality to detect changes, and since the array reference did not change, it does not re-render. Always use setCards(prev => prev.map(...)) to return a new array.
  • If the useEffect never fires, check that its dependency array is [flipped] — not [] (which runs only once on mount) and not missing entirely (which runs on every render).
Third-card double-flip bug still happening? Check that isLocked.current = true is set before setFlipped(nextFlipped), and that handleFlip returns early at the top when isLocked.current is true. The order matters: React batches state updates, but the useRef mutation is synchronous and takes effect immediately.
Checkpoint — what you should see
Two cards flip up on the first two clicks. A matching pair stays face-up with a green glow and the matched cards no longer respond to clicks. A non-matching pair holds briefly then flips back. Clicking a third card while two are exposed does nothing. The move counter increments by one for each pair of cards you flip. New Game reshuffles and resets everything cleanly.

Timer with useRef, Win Detection, and localStorage Best Score
Add a seconds timer that starts on the first card click and stops when all pairs are matched. Detect the win condition, then compare the move count against the personal best stored in localStorage. Show a win banner that updates the record when a new best is set.
Why useRef for the interval, not useState? Calling setInterval returns a numeric ID you need later to call clearInterval. If you stored that ID in state, updating it would trigger a re-render, which could create another interval. A useRef holds the ID across renders without causing any re-renders — the right tool for a value that is internal bookkeeping, not display data.

Timer keeps running after the win / does not stop?
  • Check that stopTimer() is called inside the win-detection useEffect, and that the dependency array is [cards]. If the array is empty ([]), the effect only runs once at mount and never sees the win state.
  • If clearInterval is called but the seconds keep ticking, a second interval was started. This usually means started.current was not reset to false in newGame() — so the next game starts without resetting the guard, and startTimer skips setting a new interval while the old one is still running. Confirm started.current = false is in newGame.
Win condition fires immediately on a new game (all cards show matched)? The win useEffect depends on [cards], so it runs every time cards is set. The guard if (cards.length === 0) return handles the instant when newGame sets a fresh deck. Make sure buildDeck() always returns cards with isMatched: false.

When you click “Hard”, setDifficulty('hard') schedules a state update but React does not apply it until after the current event handler finishes. So if newGame() reads difficulty from the closure, it still sees the old value (e.g. ‘easy’) and builds the wrong deck size. Passing the new key as a parameter — newGame(key) — bypasses the stale closure entirely: newGame uses whatever value you hand it directly, regardless of when React commits the state update.
    Expected ESLint note on the win-detection useEffect. ESLint may warn that moves and difficulty are used inside the win-detection effect but are not listed in its dependency array [cards]. This is intentional. The win effect’s only job is to respond when the card state changes — specifically when every card flips to matched. Adding moves or difficulty to the dep array would cause it to re-run every time the move counter ticks or the player switches difficulty, which would incorrectly re-evaluate the win condition mid-game. The effect reads moves and difficulty at the single moment it actually fires (all matched), so stale-closure risk is not a concern here. Do not add those deps to silence the warning.
