Subject

Build a Smart Contract Marketplace

Operator 120 MIN 1000 XP
Mission Brief

This operation builds a fully functional NFT marketplace on the Ethereum blockchain using Solidity smart contracts and the Hardhat 2 LTS development framework. You will write an ERC-721 token contract using OpenZeppelin Contracts v5, then build a Marketplace contract on top — enabling listing and buying NFTs with on-chain ownership guarantees. The entire development cycle runs against a local Hardhat Network node so no real money is ever at risk.

Every marketplace transaction executes as an immutable smart contract call. When a seller lists an NFT, they approve the marketplace to transfer it on their behalf. When a buyer sends the exact asking price in ETH, the contract atomically transfers the token to the buyer and forwards payment to the seller — no intermediary and no trust required. You will implement ReentrancyGuard from OpenZeppelin on the buy function so that a malicious contract cannot re-enter the function mid-execution and drain funds.

Security note: the contracts you build here are for learning. Smart contracts that hold real value require a professional audit before deployment to mainnet. NFT markets have been exploited for millions of dollars through reentrancy bugs, approval misuse, and integer overflows — this project teaches you exactly why those patterns are dangerous and how to defend against them. Never deploy this code with real funds without a thorough review.

Agent Requirements
  • Node.js v18.0.0 or later — required by Hardhat 2 LTS. Node 20 LTS or Node 22 LTS is recommended. Check your version with node --version. Install from nodejs.org (use the LTS download).
  • npm v7 or later — ships with Node.js 18+. Check with npm --version.
  • Basic JavaScript knowledge — you need to read async/await code. You do not need to know TypeScript; Hardhat generates working TypeScript config automatically.
  • For the optional Sepolia testnet phase only: a throwaway Ethereum wallet private key stored in a .env file (never your main wallet), a small amount of Sepolia ETH from a faucet, and a free Alchemy or Infura RPC URL. The .env file must be in .gitignore.
  • No prior Solidity experience required — every construct used is explained where it appears.

Write the ERC-721 NFT Contract (OpenZeppelin v5)
Author contracts/HexNFT.sol — an ERC-721 token that extends OpenZeppelin's ERC721URIStorage and Ownable. Only the owner can mint. Each token stores its own metadata URI. You will compile the contract and verify zero errors before moving on.
  1. Create the NFT contract file. Create contracts/HexNFT.sol with this complete source:
    // SPDX-License-Identifier: MIT pragma solidity ^0.8.20; import "@openzeppelin/contracts/token/ERC721/extensions/ERC721URIStorage.sol"; import "@openzeppelin/contracts/access/Ownable.sol"; /** * @title HexNFT * @notice A simple ERC-721 token. Only the contract owner can mint. * Each token stores its metadata URI on-chain via ERC721URIStorage. */ contract HexNFT is ERC721URIStorage, Ownable { /// @notice Increments with each mint; first token ID will be 1. uint256 private _nextTokenId; /// @notice Emitted when a new token is minted. event Minted(uint256 indexed tokenId, address indexed to, string tokenURI); /** * @dev OpenZeppelin v5 Ownable requires the initial owner address * as a constructor argument. Passing msg.sender sets the deployer. * ERC721 requires a name and symbol string. */ constructor(address initialOwner) ERC721("HexNFT", "HNFT") Ownable(initialOwner) {} /** * @notice Mint a new NFT to `to` with the given metadata URI. * @param to Recipient address. * @param tokenURI IPFS or HTTPS metadata URI (e.g. ipfs://Qm...). * @return tokenId The newly minted token ID. */ function mintNFT(address to, string calldata tokenURI) external onlyOwner returns (uint256 tokenId) { _nextTokenId++; tokenId = _nextTokenId; _safeMint(to, tokenId); _setTokenURI(tokenId, tokenURI); emit Minted(tokenId, to, tokenURI); } }
    Why Ownable(initialOwner)? OpenZeppelin v5 changed the Ownable constructor to require an explicit address initialOwner argument instead of defaulting to msg.sender. This makes the initial owner visible and auditable at deploy time. If you copy a v4 snippet that passes no argument to Ownable, it will not compile against v5 — this is one of the most common beginner errors when mixing OZ versions.
  2. Compile the contract.
    npx hardhat compile
    Expected output:
    Compiling 1 file with 0.8.24 Compilation finished successfully
    Hardhat also generates TypeScript type bindings in typechain-types/ automatically. These bindings give you type-checked contract interaction in your tests.

  • This error on the Ownable() call means you installed OZ v5 but used a v4-style constructor with no argument. The fix: pass msg.sender as shown above — Ownable(initialOwner) where initialOwner is a constructor parameter you accept, or Ownable(msg.sender) directly.

  • OpenZeppelin is not installed. Run npm install @openzeppelin/contracts and try again. Confirm with ls node_modules/@openzeppelin/contracts/token/ERC721/extensions/ — you should see ERC721URIStorage.sol.

Write the Marketplace Contract (List, Buy, ReentrancyGuard)
Author contracts/HexMarketplace.sol. The marketplace allows NFT owners to list tokens at a fixed ETH price. Buyers send ETH to purchase — the contract transfers the NFT to the buyer and forwards payment to the seller. ReentrancyGuard from OpenZeppelin protects the buy function. The critical approval requirement is explained step by step.
  1. Understand the approval requirement before writing code. ERC-721 tokens are owned by addresses. For the marketplace contract to transfer a token from a seller to a buyer, the seller must first call approve(marketplaceAddress, tokenId) on the NFT contract. Without this, the marketplace has no permission to move the token and the transfer will revert. This is not a bug — it is the ERC-721 standard's access control system working correctly. The test in Phase 5 will demonstrate both the happy path (with approval) and the failure case (without approval).
  2. Understand the reentrancy risk. The buy function sends ETH to the seller using a low-level call: payable(listing.seller).call{value: listing.price}(""). If the seller is a malicious contract, its fallback function could call back into buyNFT before the listing state is cleared, allowing it to drain the contract. The checks-effects-interactions pattern defends against this: update all state before making external calls. OpenZeppelin's ReentrancyGuard provides a mutex-style modifier (nonReentrant) as a belt-and-suspenders guard alongside the pattern. Note that safeTransferFrom itself also opens a re-entrancy window: when the buyer is a smart contract, ERC-721 requires calling onERC721Received on the recipient before returning — an external call that executes mid-transaction — which is exactly why listing.active = false must be set before the transfer, not after.
  3. Create contracts/HexMarketplace.sol with this complete source:
    // SPDX-License-Identifier: MIT pragma solidity ^0.8.20; import "@openzeppelin/contracts/token/ERC721/IERC721.sol"; import "@openzeppelin/contracts/utils/ReentrancyGuard.sol"; /** * @title HexMarketplace * @notice Fixed-price NFT marketplace. Sellers list tokens by approving * this contract as an operator, then calling listNFT(). Buyers * call buyNFT() with the exact ETH price. * * Security: * - ReentrancyGuard on buyNFT prevents re-entrancy attacks. * - Checks-effects-interactions: state is updated before the ETH * transfer so a malicious receiver cannot re-enter in a dirty state. * - The NFT is transferred AFTER state is updated. */ contract HexMarketplace is ReentrancyGuard { struct Listing { address seller; uint256 price; // in wei bool active; } // nftContract => tokenId => Listing mapping(address => mapping(uint256 => Listing)) public listings; event Listed( address indexed nftContract, uint256 indexed tokenId, address indexed seller, uint256 price ); event Sold( address indexed nftContract, uint256 indexed tokenId, address indexed buyer, address seller, uint256 price ); event Delisted( address indexed nftContract, uint256 indexed tokenId, address indexed seller ); // ──────────────────────────────────────────────────────────── // List // ──────────────────────────────────────────────────────────── /** * @notice List an NFT for sale. * * IMPORTANT: Before calling this function, the seller must call * nftContract.approve(address(this), tokenId) * on the NFT contract. Without approval the marketplace cannot * transfer the token when a buyer purchases it. * * @param nftContract Address of the ERC-721 contract. * @param tokenId Token to list. * @param price Price in wei (must be > 0). */ function listNFT( address nftContract, uint256 tokenId, uint256 price ) external { require(price > 0, "Price must be above zero"); IERC721 nft = IERC721(nftContract); require(nft.ownerOf(tokenId) == msg.sender, "Not token owner"); // Verify the marketplace is approved to transfer this token. // Without this check the listing appears valid but buyNFT would revert. require( nft.getApproved(tokenId) == address(this) || nft.isApprovedForAll(msg.sender, address(this)), "Marketplace not approved: call approve() first" ); listings[nftContract][tokenId] = Listing({ seller: msg.sender, price: price, active: true }); emit Listed(nftContract, tokenId, msg.sender, price); } // ──────────────────────────────────────────────────────────── // Buy // ──────────────────────────────────────────────────────────── /** * @notice Purchase a listed NFT. Send exactly the listed price in ETH. * * Uses checks-effects-interactions pattern + ReentrancyGuard: * 1. Check: verify listing is active and msg.value matches price. * 2. Effect: mark listing inactive and record buyer. * 3. Interact: transfer NFT then transfer ETH. * * @param nftContract Address of the ERC-721 contract. * @param tokenId Token to purchase. */ function buyNFT( address nftContract, uint256 tokenId ) external payable nonReentrant { Listing storage listing = listings[nftContract][tokenId]; // ── Checks ────────────────────────────────────────────── require(listing.active, "Listing not active"); require(msg.value == listing.price, "Wrong ETH amount"); address seller = listing.seller; uint256 price = listing.price; // ── Effects ───────────────────────────────────────────── // Clear the listing BEFORE any external calls. This prevents // a reentrant buy() call from seeing an active listing. listing.active = false; // ── Interactions ───────────────────────────────────────── // Transfer the NFT from the seller to the buyer. // safeTransferFrom checks that the receiver can handle ERC-721 tokens. IERC721(nftContract).safeTransferFrom(seller, msg.sender, tokenId); // Forward the ETH payment to the seller. // Using call{value} is the recommended pattern (avoids gas limit issues // that transfer() and send() have with smart contract receivers). (bool sent, ) = payable(seller).call{value: price}(""); require(sent, "ETH transfer to seller failed"); emit Sold(nftContract, tokenId, msg.sender, seller, price); } // ──────────────────────────────────────────────────────────── // Delist // ──────────────────────────────────────────────────────────── /** * @notice Cancel an active listing. Only the original seller can delist. */ function delistNFT(address nftContract, uint256 tokenId) external { Listing storage listing = listings[nftContract][tokenId]; require(listing.active, "Listing not active"); require(listing.seller == msg.sender, "Not the seller"); listing.active = false; emit Delisted(nftContract, tokenId, msg.sender); } }

  4. Create the end-to-end flow script scripts/flow.ts:
    import hre from "hardhat"; import { readFileSync } from "fs"; async function main() { const addresses = JSON.parse(readFileSync("deployed.json", "utf-8")); const [owner, seller, buyer] = await hre.ethers.getSigners(); // Attach to deployed contracts using their on-chain addresses. const nft = await hre.ethers.getContractAt("HexNFT", addresses.nft); const market = await hre.ethers.getContractAt("HexMarketplace", addresses.marketplace); console.log("\n=== STEP 1: MINT ==="); const mintTx = await nft.connect(owner).mintNFT( seller.address, "ipfs://QmExampleCIDForThisNFTMetadataABC123" ); const mintReceipt = await mintTx.wait(); console.log("Minted token #1 to seller:", seller.address); console.log("Token owner:", await nft.ownerOf(1n)); console.log("\n=== STEP 2: APPROVE ==="); // Seller must approve the marketplace to transfer token #1. const marketAddress = await market.getAddress(); const approveTx = await nft.connect(seller).approve(marketAddress, 1n); await approveTx.wait(); console.log("Seller approved marketplace for token #1"); console.log("Approved operator:", await nft.getApproved(1n)); console.log("\n=== STEP 3: LIST ==="); const price = hre.ethers.parseEther("0.5"); const listTx = await market.connect(seller).listNFT( addresses.nft, 1n, price ); await listTx.wait(); const listing = await market.listings(addresses.nft, 1n); console.log("Token #1 listed for:", hre.ethers.formatEther(listing.price), "ETH"); console.log("Listing active:", listing.active); console.log("\n=== STEP 4: BUY ==="); const sellerBalanceBefore = await hre.ethers.provider.getBalance(seller.address); const buyTx = await market.connect(buyer).buyNFT( addresses.nft, 1n, { value: price } ); const buyReceipt = await buyTx.wait(); const sellerBalanceAfter = await hre.ethers.provider.getBalance(seller.address); console.log("Purchase complete. Gas used:", buyReceipt?.gasUsed.toString()); console.log("New token owner:", await nft.ownerOf(1n)); console.log("Buyer address: ", buyer.address); console.log("Seller earned (ETH):", hre.ethers.formatEther(sellerBalanceAfter - sellerBalanceBefore)); const listingAfter = await market.listings(addresses.nft, 1n); console.log("Listing active after sale:", listingAfter.active); console.log("\n=== FLOW COMPLETE ==="); } main().catch((error) => { console.error(error); process.exitCode = 1; });
  5. Run the end-to-end flow.
    npx hardhat run scripts/flow.ts --network localhost
    Expected output:

Script fails: "network not found: localhost"?
  • The local node must be running first. Open a separate terminal, run npx hardhat node, and leave it open. Then run the scripts in your original terminal.
Script fails: "could not detect network" or connection refused?
  • The Hardhat node listens on http://127.0.0.1:8545. If your machine has a firewall blocking localhost ports, try adding networks: { localhost: { url: "http://127.0.0.1:8545" } } explicitly to hardhat.config.ts.

Optional: Deploy to Sepolia Testnet and View on Etherscan
Deploy the contracts to Sepolia — the current Ethereum public testnet. You will need a throwaway private key stored in a .env file (never a real-funds wallet), a small amount of Sepolia ETH from a faucet, and a free RPC endpoint. Once deployed, you can view the contracts on the Sepolia Etherscan block explorer and run the mint-list-buy flow against a real public network.
  1. Create a throwaway wallet for testing. Never use a wallet that holds real funds on any mainnet. Generate a new one:
    # In Node.js REPL (type: node) const { ethers } = require("ethers"); const wallet = ethers.Wallet.createRandom(); console.log("Address:", wallet.address); console.log("Private key:", wallet.privateKey);
    Save the address and private key. Keep the private key secret — it goes in .env, which must never be committed to git.
  2. Get Sepolia ETH from a faucet. You need a small amount to pay for gas (a few transactions cost less than 0.01 Sepolia ETH). Use the official Alchemy Sepolia Faucet at sepoliafaucet.com or the Infura faucet at www.infura.io/faucet/sepolia. Enter your throwaway wallet address.
  3. Get a free RPC endpoint. Register at alchemy.com (free tier). Create a new app, select Ethereum, select Sepolia testnet, and copy the HTTPS URL (it looks like https://eth-sepolia.g.alchemy.com/v2/YOUR_API_KEY).
  4. Create a .env file in the project root:
    SEPOLIA_RPC_URL=https://eth-sepolia.g.alchemy.com/v2/YOUR_API_KEY PRIVATE_KEY=0xYOUR_THROWAWAY_PRIVATE_KEY_HERE
    Then create or confirm .gitignore contains:
    .env node_modules/ artifacts/ cache/ typechain-types/ deployed.json
    Private key security: the private key in .env controls who can spend the ETH in your throwaway wallet. If it is committed to git or shared publicly, anyone can drain the wallet. For this project that means a small amount of worthless testnet ETH is at risk — but the habit of keeping keys out of version control is critical before you ever work with real funds.
  5. Install dotenv and add Sepolia to hardhat.config.ts.
    npm install --save-dev dotenv
    Update hardhat.config.ts:
    import { HardhatUserConfig } from "hardhat/config"; import "@nomicfoundation/hardhat-toolbox"; import * as dotenv from "dotenv"; dotenv.config(); const config: HardhatUserConfig = { solidity: "0.8.24", networks: { sepolia: { url: process.env.SEPOLIA_RPC_URL || "", accounts: process.env.PRIVATE_KEY ? [process.env.PRIVATE_KEY] : [], }, }, }; export default config;
  6. Deploy to Sepolia.
    npx hardhat run scripts/deploy.ts --network sepolia
    Expected output (takes 15–60 seconds while transactions confirm on Sepolia):
    Deploying from: 0xYourThrowawayAddress HexNFT deployed to: 0xabc...123 HexMarketplace deployed to: 0xdef...456 Addresses saved to deployed.json
  7. View the contracts on Sepolia Etherscan. Go to sepolia.etherscan.io and paste each deployed contract address into the search box. You will see the deployment transaction, the bytecode, and (after a few blocks) the contract creation. Click "Contract" then "Read Contract" to call view functions like owner() directly from the browser.
  8. Run the flow script against Sepolia.
    npx hardhat run scripts/flow.ts --network sepolia
    Each transaction will take 10–30 seconds to confirm. The same output as the local run will appear — but this time every transaction is permanently recorded on a public blockchain. Look up your throwaway wallet address on sepolia.etherscan.io to see all four transactions listed in the history.
Deployment fails: "insufficient funds for gas"?
  • Your throwaway wallet does not have enough Sepolia ETH. Visit the faucet again. Each contract deployment costs roughly 0.002–0.005 Sepolia ETH in gas. The flow script (mint + approve + list + buy) costs another 0.002–0.004 Sepolia ETH.
Error: "PRIVATE_KEY not set" or RPC URL empty?
  • Confirm the .env file exists in the project root (same directory as hardhat.config.ts) and that dotenv.config() is called before the network config is read. Check with: node -e "require('dotenv').config(); console.log(process.env.PRIVATE_KEY ? 'SET' : 'MISSING')"
Contracts deployed but etherscan shows "Contract Source Code Not Verified"?
  • Verification is optional for this project. If you want to verify: install @nomicfoundation/hardhat-verify, add your Etherscan API key to .env, and run npx hardhat verify --network sepolia CONTRACT_ADDRESS CONSTRUCTOR_ARGS. The free Etherscan API key is available at etherscan.io/apis.
  • Note: contracts deployed to Sepolia are immutable. If you find a bug after deployment, you must redeploy to a new address — the original contract cannot be patched. This is why thorough local testing in Phases 3–5 matters.
Checkpoint — what you should see
Both contract addresses appear on sepolia.etherscan.io and show the deployment transaction. The flow script completes all four steps against Sepolia. The buyer's address is shown as the token owner on Etherscan under the NFT contract's "Read Contract" tab. Your throwaway wallet's transaction history on Etherscan shows the mint, approve, list, and buy transactions with their gas costs.
