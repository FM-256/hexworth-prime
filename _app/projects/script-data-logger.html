Subject

Build an Arduino Data Logger

Recruit 90 min 250 XP
Mission Brief

This operation builds a standalone data acquisition system. An Arduino Uno reads temperature, humidity, and light level every ten seconds, timestamps each reading from a battery-backed real-time clock, and writes every record as a CSV row to a microSD card — producing a file that is immediately readable in Python, Excel, or any data tool the moment you pull the card out. No serial cable required once the system is running. No cloud. No network. The Arduino logs autonomously for as long as the card has space.

The build uses four hardware modules — an SD card reader, a DS3231 RTC, a DHT11 temperature/humidity sensor, and a photoresistor voltage divider — that together cover the two dominant hardware bus protocols (SPI for the SD card, I2C for the RTC, and analog/digital GPIO for sensors). Every phase is a working, testable checkpoint before the next layer is added. Phase 5 closes the loop with a Python script that reads the CSV off the card and plots all three sensor channels.

This is the foundational pattern behind every SCADA historian, weather station, environmental sensor array, and IoT edge node: automated data collection on constrained hardware, producing analysis-ready structured output.

Agent Requirements
  • Arduino Uno + USB-A to USB-B cable. The Uno is the reference board for this walkthrough — SPI pins are fixed at MOSI=11, MISO=12, SCK=13, and I2C at SDA=A4, SCL=A5. Other boards work but you will need to look up their pin mappings.
  • Arduino IDE 2.x installed on your computer. Download from arduino.cc/en/software. The IDE includes the built-in SD library (no separate install needed for that one).
  • MicroSD card module (SPI interface — the common 6-pin breakout sold on Amazon/AliExpress for under $2). Requires a microSD card formatted FAT16 or FAT32. Cards 32 GB and under format to FAT32 by default on most systems; 64 GB+ cards format exFAT by default and will NOT work — you must re-format them to FAT32.
  • DS3231 RTC module (strongly preferred over DS1307 — the DS3231 has a built-in temperature-compensated crystal and holds accurate time without drift). Available on breakout boards with a CR2032 battery holder for under $3. Install the Adafruit RTClib library via Arduino IDE Library Manager (search: RTClib, install by Adafruit).
  • DHT11 sensor (or a breakout board labeled DHT11). Install the DHT sensor library by Adafruit via Library Manager — it will prompt you to also install Adafruit Unified Sensor, which is required. Accept that prompt.
  • Photoresistor (LDR) + one 10 kΩ resistor for the voltage divider.
  • Full-size breadboard + at least 20 male-to-male jumper wires.
  • Python 3.x (3.9 or higher) installed on your computer, plus pip install "pandas>=2.0" matplotlib for Phase 5. pandas 2.0 or higher is required — the visualization script uses on_bad_lines="warn" (needs pandas ≥ 1.3) and date_format (needs pandas ≥ 2.0). You do not need Python for Phases 1–4.

SD Card Module Wiring & File Write Test
Wire the SD card module to the Arduino via SPI, format the card if needed, install the SD library, and write a test line to a file. The observable result is a file called TEST.TXT on the card containing the text SD card OK, verified both by the Serial Monitor and by plugging the card into your computer.
How SPI works for the SD module. SPI (Serial Peripheral Interface) uses four wires: MOSI (data from Arduino to device), MISO (data from device to Arduino), SCK (clock), and CS/SS (Chip Select — tells the device "this transmission is for you"). On the Arduino Uno, MOSI is fixed at pin 11, MISO at pin 12, and SCK at pin 13. These three are shared across all SPI devices. CS can be any digital pin — this project uses pin 10, which is the conventional default for a single SD module. The SD library is built into the Arduino IDE; no Library Manager install is needed.
  1. Format your microSD card. Insert the card into your computer using an adapter.
    • Windows: Right-click the card in File Explorer → Format → set File system to FAT32 → click Start.
    • Mac: Open Disk Utility → select the card → Erase → set Format to MS-DOS (FAT) → click Erase.
    • Linux: sudo mkfs.vfat -F 32 /dev/sdX1 (replace sdX1 with your card's device node).
    Cards 32 GB and under will usually already be FAT32. Cards 64 GB and above default to exFAT, which the Arduino SD library cannot read — you must reformat them. After formatting, eject the card safely and insert it into the SD card module on your breadboard.
  2. Wire the SD card module to the Arduino. Use jumper wires on a breadboard. Make every connection before powering on.
    SD Module Pin --> Arduino Uno Pin --------------------------------- VCC --> 5V (or 3.3V if your module has a voltage regulator) GND --> GND MOSI --> Pin 11 MISO --> Pin 12 SCK (CLK) --> Pin 13 CS (SS) --> Pin 10
    VCC voltage: Most SD breakout modules sold on Amazon/AliExpress include an onboard 3.3 V regulator and level shifter, so you connect VCC to the Arduino's 5V pin. A bare SD socket without a module PCB needs 3.3 V directly — 5 V will damage the card. If you are unsure, look for a voltage regulator IC on your PCB. When in doubt, use 3.3 V.
  3. Open the Arduino IDE. Go to File → New Sketch. Delete the default empty sketch and paste this complete test sketch:
    // Phase 1: SD card write test // Arduino built-in SD library -- no Library Manager install needed. // Verified against: docs.arduino.cc/libraries/sd // // SPI pins on Uno: MOSI=11, MISO=12, SCK=13 (hardware fixed) // CS pin: 10 (chosen -- must match the #define below) #include <SPI.h> #include <SD.h> #define SD_CS_PIN 10 void setup() { Serial.begin(9600); // Wait briefly for a USB host (Serial Monitor). On the Uno this exits // instantly because Serial is always ready. On CDC-class boards // (Leonardo, Micro, Zero) a bare "while (!Serial)" hangs forever if no // host is connected -- the 3-second timeout prevents that. unsigned long _t = millis(); while (!Serial && millis() - _t < 3000) { ; } Serial.println("Initializing SD card..."); if (!SD.begin(SD_CS_PIN)) { Serial.println("SD.begin() failed. Check wiring and card format."); // Halt here -- nothing else will work without the SD card. while (true) { ; } } Serial.println("SD card initialized OK."); // Open TEST.TXT in write mode. // FILE_WRITE opens the file for appending if it exists, // or creates it if it does not. File testFile = SD.open("TEST.TXT", FILE_WRITE); if (!testFile) { Serial.println("Failed to open TEST.TXT for writing."); while (true) { ; } } testFile.println("SD card OK"); // write a line + newline testFile.close(); // ALWAYS close -- flushes data to card Serial.println("Wrote 'SD card OK' to TEST.TXT"); // Read it back to confirm the write succeeded. File readFile = SD.open("TEST.TXT"); if (readFile) { Serial.println("Reading TEST.TXT:"); while (readFile.available()) { Serial.write(readFile.read()); } readFile.close(); } else { Serial.println("Could not open TEST.TXT for reading."); } } void loop() { // Nothing to do -- this is a one-shot test. }
  4. Select your board and port. In the Arduino IDE: Tools → Board → Arduino AVR Boards → Arduino Uno. Then Tools → Port and select the COM port (Windows) or /dev/cu.usbmodem... (Mac) or /dev/ttyACM0 (Linux) that appeared when you plugged in the Arduino.
  5. Upload the sketch. Click the Upload button (right-arrow icon) or press Ctrl+U (Mac: Cmd+U). Wait for "Done uploading" in the status bar.
  6. Open the Serial Monitor. Tools → Serial Monitor (or Ctrl+Shift+M). Set the baud rate dropdown in the bottom-right to 9600. You should see:
    Initializing SD card... SD card initialized OK. Wrote 'SD card OK' to TEST.TXT Reading TEST.TXT: SD card OK
  7. Verify on your computer. Power off the Arduino, remove the microSD card, and insert it into your computer. You should see a file named TEST.TXT containing the line SD card OK. This confirms the write was actually flushed to the card — not just held in a buffer.
Serial Monitor shows "SD.begin() failed"?
  • Check that the CS wire is on pin 10 and the #define SD_CS_PIN says 10. This is the single most common cause of failure.
  • Check all five wires: VCC, GND, MOSI (11), MISO (12), SCK (13), CS (10). A single missing or swapped wire prevents initialization.
  • Confirm the card is formatted FAT16 or FAT32, not exFAT. Re-format if needed.
  • Try a different microSD card. Some cards are incompatible with the Arduino SD library's SPI mode.
  • If your module has both 3.3 V and 5 V pins, try connecting VCC to the other voltage level.
The file appears on the card but it is empty? You forgot to call testFile.close() before removing power. The SD library buffers writes in RAM and only flushes to the card on close(). Always close your file after every write session — this is the most important SD library rule and the source of most "my data is missing" bugs.
Checkpoint — what you should have
The Serial Monitor prints "SD card initialized OK" and "SD card OK" as read-back. The microSD card, when inserted into your computer, shows a file TEST.TXT containing the text SD card OK. The SD module is wired and confirmed working. Proceed to Phase 2.

RTC Module Setup for Real Timestamps
Wire the DS3231 RTC over I2C, install the Adafruit RTClib library, set the clock once to the compile-time date/time, then read it back and print formatted YYYY-MM-DD HH:MM:SS timestamps to the Serial Monitor every second. Verify the time keeps running after you power-cycle the Arduino (proving the RTC battery is backing the clock).
How I2C works for the RTC. I2C (Inter-Integrated Circuit) uses two wires — SDA (data) and SCL (clock) — shared by all I2C devices on the bus. Each device has a fixed address baked in; the DS3231 uses address 0x68. On the Arduino Uno, SDA is pin A4 and SCL is pin A5. These wires stay connected at the same time as the SPI wires from Phase 1 because I2C and SPI are separate buses. You can have both modules wired simultaneously.
  1. Install the Adafruit RTClib library. In the Arduino IDE: Sketch → Include Library → Manage Libraries. In the search box type RTClib. Find RTClib by Adafruit and click Install. When prompted to install dependencies, click Install All.
  2. Wire the DS3231 RTC module to the Arduino. Keep the SD card module wired from Phase 1 — these wires are in addition to it.
    DS3231 Module Pin --> Arduino Uno Pin ----------------------------------------- VCC --> 5V GND --> GND SDA --> A4 SCL --> A5
    Most DS3231 breakout boards include pull-up resistors on SDA and SCL, so you do not need to add external resistors. The module also has a CR2032 battery slot — make sure the battery is installed. Without the battery the clock resets to 2000-01-01 00:00:00 every time the Arduino loses power.
  3. Create a new sketch and paste this complete Phase 2 sketch:
    // Phase 2: DS3231 RTC -- real timestamp reading // Adafruit RTClib verified against: // adafruit.github.io/RTClib/html/class_r_t_c___d_s3231.html // // I2C pins on Uno: SDA=A4, SCL=A5 (hardware fixed) // DS3231 I2C address: 0x68 (handled internally by RTClib) #include <Wire.h> #include "RTClib.h" RTC_DS3231 rtc; void setup() { Serial.begin(9600); // Wait briefly for a USB host (Serial Monitor). On the Uno this exits // instantly. On CDC-class boards (Leonardo, Micro, Zero) a bare // "while (!Serial)" hangs forever without a host -- the timeout prevents that. unsigned long _t = millis(); while (!Serial && millis() - _t < 3000) { ; } if (!rtc.begin()) { Serial.println("Could not find DS3231 RTC. Check SDA/SCL wiring."); while (true) { ; } } // Set the RTC clock to the date and time this sketch was compiled. // F(__DATE__) and F(__TIME__) read the compiler's system clock at // build time and store the strings in flash memory. // // IMPORTANT: Comment out the rtc.adjust() line after you have set // the clock once. Re-uploading with adjust() uncommented resets the // clock to the new compile time on every upload. // // The lostPower() check is the safe pattern: only set the time if // the RTC lost power (battery died or was never set). This means you // can re-flash the sketch without resetting the clock. if (rtc.lostPower()) { Serial.println("RTC lost power -- setting clock to compile time."); rtc.adjust(DateTime(F(__DATE__), F(__TIME__))); } Serial.println("RTC initialized. Reading timestamps:"); } void loop() { DateTime now = rtc.now(); // Build a formatted timestamp: YYYY-MM-DD HH:MM:SS // Use print/println with padding for zero-filled fields. Serial.print(now.year()); Serial.print("-"); if (now.month() < 10) Serial.print("0"); Serial.print(now.month()); Serial.print("-"); if (now.day() < 10) Serial.print("0"); Serial.print(now.day()); Serial.print(" "); if (now.hour() < 10) Serial.print("0"); Serial.print(now.hour()); Serial.print(":"); if (now.minute() < 10) Serial.print("0"); Serial.print(now.minute()); Serial.print(":"); if (now.second() < 10) Serial.print("0"); Serial.println(now.second()); delay(1000); }
  4. Upload and open the Serial Monitor at 9600 baud. You should see timestamps advancing one second at a time:
    RTC initialized. Reading timestamps: 2026-06-19 14:32:07 2026-06-19 14:32:08 2026-06-19 14:32:09
    The time shown will reflect when you compiled and uploaded the sketch. If the time is slightly off (e.g., 10–30 seconds behind), that is the upload delay between compile time and the moment the Arduino first ran. For a data logger this level of accuracy is fine. If you need exact clock setting, upload once with rtc.adjust() active, immediately power off and on, and the RTC will now hold that time independently of future uploads.
  5. Verify the clock persists. Close the Serial Monitor, disconnect the USB cable for 10 seconds, reconnect, and re-open the Serial Monitor. The timestamps should resume from where they left off (not reset to 2000-01-01). This confirms the CR2032 battery is powering the RTC during the power gap.
Serial Monitor shows "Could not find DS3231 RTC"?
  • Check SDA is on A4 and SCL is on A5. Swapping these two is very common.
  • Confirm VCC and GND are connected.
  • Run File → Examples → Wire → i2c_scanner to scan the I2C bus and confirm your DS3231 shows up at address 0x68. If the scanner finds nothing, the wiring is the problem.
Clock resets to 2000-01-01 after every power cycle? The CR2032 battery is either missing, dead, or seated backwards. Remove it, check the polarity markings on the holder (+ side up on most breakout boards), and re-insert. A fresh CR2032 should last 5–10 years powering only the RTC oscillator. If the clock shows 2000-01-01 but lostPower() is NOT auto-correcting it — because the DS3231's oscillator-stop flag (OSF) was previously cleared by another sketch — temporarily comment out the if (rtc.lostPower()) guard so the rtc.adjust() call runs unconditionally, upload once to force-set the clock, then uncomment the guard and upload again to restore the safe pattern.
Clock resets to compile time every time you re-upload a new sketch? You left rtc.adjust() outside the if (rtc.lostPower()) guard. The lostPower() check is exactly what prevents this. Make sure the adjust call is inside the if block, not at the top level of setup().
Checkpoint — what you should see
The Serial Monitor prints one timestamp per second in YYYY-MM-DD HH:MM:SS format, counting up in real time. After a power cycle, the timestamps resume from the correct time rather than resetting. Both the SD module (Phase 1) and the RTC module are now wired simultaneously. Proceed to Phase 3.

DHT11 & Photoresistor Sensor Readings
Wire the DHT11 and the photoresistor voltage divider. Read temperature (°C), humidity (%), and raw light level (0–1023) from all three sensors and print them to the Serial Monitor every two seconds. Verify the readings change when you cover the photoresistor, breathe on the DHT11, or warm it gently with your fingers.
Why two separate protocols for two sensors. The DHT11 uses a proprietary single-wire protocol on a digital pin — the library handles all the timing internally. The photoresistor uses no protocol at all: it is one half of a voltage divider connected to an analog pin. analogRead(A0) returns a 10-bit value from 0 (no voltage) to 1023 (full 5 V). Bright light decreases the photoresistor's resistance, increasing the voltage at the midpoint of the divider, producing higher ADC values. Darkness increases resistance, reducing the midpoint voltage, producing lower values. The number is relative, not calibrated lux.
  1. Install the DHT sensor library. Sketch → Include Library → Manage Libraries. Search for DHT sensor library. Find DHT sensor library by Adafruit and click Install. When prompted to install Adafruit Unified Sensor, click Install All. Both are required — the DHT library uses the Unified Sensor framework for hardware abstraction.
  2. Wire the DHT11 sensor. Keep all previous wires in place.
    DHT11 Pin --> Arduino Uno Pin -------------------------------- VCC (pin 1) --> 5V DATA (pin 2) --> Pin 2 (any digital pin works; we use pin 2) (pin 3 N/C) --> not connected GND (pin 4) --> GND
    Pull-up resistor: The DHT11 data line requires a 4.7 kΩ–10 kΩ pull-up resistor between DATA and VCC. Many DHT11 breakout boards (the small PCB with three header pins) include this resistor on the board. If you have a bare four-pin DHT11 with no PCB, add a 10 kΩ resistor between DATA and VCC on your breadboard. Without the pull-up, readings will return NaN.
  3. Wire the photoresistor voltage divider.
    Build this circuit on the breadboard: Arduino 5V ---+--- [LDR / Photoresistor] ---+--- A0 | [10 kOhm resistor] | Arduino GND -----------------------------------|---GND
    The junction between the LDR and the 10 kΩ resistor connects to analog pin A0. When the LDR is in bright light its resistance drops (e.g., 1 kΩ), the voltage at A0 rises toward 5 V, and analogRead(A0) returns a high value (close to 1023). In darkness the LDR resistance rises (e.g., 1 MΩ), A0 drops toward 0 V, and the reading drops toward 0. The exact values depend on your specific LDR and the ambient light level — there is no universal calibration.
  4. Create a new sketch and paste this complete Phase 3 sketch:
    // Phase 3: DHT11 + photoresistor sensor readings // DHT sensor library by Adafruit -- install via Library Manager. // Also requires: Adafruit Unified Sensor (installed as dependency). // Verified against: github.com/adafruit/DHT-sensor-library (DHT.h) // // DHT constructor: DHT(pin, type) // pin = digital pin number // type = DHT11 (constant defined in DHT.h, value 11) // // readTemperature(bool S) -- S=false returns Celsius (default) // readHumidity() -- returns % relative humidity // Both return NaN (not-a-number) on read failure. #include "DHT.h" #define DHT_PIN 2 #define DHT_TYPE DHT11 #define LDR_PIN A0 DHT dht(DHT_PIN, DHT_TYPE); void setup() { Serial.begin(9600); // Wait briefly for a USB host (Serial Monitor). On the Uno this exits // instantly. On CDC-class boards (Leonardo, Micro, Zero) a bare // "while (!Serial)" hangs forever without a host -- the timeout prevents that. unsigned long _t = millis(); while (!Serial && millis() - _t < 3000) { ; } dht.begin(); Serial.println("Sensor readings -- every 2 seconds:"); Serial.println("Temp(C) Humidity(%) Light(0-1023)"); } void loop() { // DHT11 requires at least ~1 second between reads. // We use 2 seconds to stay safely within the spec. delay(2000); float temp = dht.readTemperature(); // Celsius float hum = dht.readHumidity(); int light = analogRead(LDR_PIN); // 0-1023 // isnan() checks for IEEE 754 NaN -- returned by the DHT library // when a read times out or the sensor is not responding. if (isnan(temp) || isnan(hum)) { Serial.println("DHT11 read failed -- check wiring and pull-up."); return; } Serial.print(temp); Serial.print(" C "); Serial.print(hum); Serial.print(" % "); Serial.println(light); }
  5. Upload and open the Serial Monitor at 9600 baud. Readings appear every two seconds:
    Sensor readings -- every 2 seconds: Temp(C) Humidity(%) Light(0-1023) 23.00 C 55.00 % 712 23.00 C 55.00 % 714 23.00 C 56.00 % 718
  6. Verify sensors are live. Cover the photoresistor with your finger — the Light value should drop significantly. Breathe gently on the DHT11 — Humidity should rise within the next reading cycle. Warm the DHT11 between your fingers — Temperature should rise by 1–2 °C over several readings. DHT11 resolution is 1 °C / 1%, so changes smaller than one unit will not show.
DHT11 always returns "DHT11 read failed"?
  • Confirm the data wire is on digital pin 2 and DHT_PIN is set to 2.
  • If you have a bare DHT11 (no PCB), add a 10 kΩ pull-up between DATA and VCC. Without it, the open-drain data line floats and every read times out.
  • The DHT11 is slow: only one read per second is reliable. Using delay(2000) keeps you safely within the timing spec. Using delay(500) or less causes read failures.
  • The DHT11 needs ~1 second to stabilize after power-on. The sketch's 2-second delay loop covers this, but if you reset immediately after upload, the first read may fail. A second read will succeed.
Light readings are stuck at 0 or 1023 regardless of light level?
  • Reading 0 in all conditions: the LDR and resistor are probably swapped. The midpoint (A0) must be between the LDR and the 10 kΩ resistor, not outside the divider.
  • Reading 1023 in all conditions: A0 may be connected directly to 5 V with no voltage divider path to GND. Confirm the 10 kΩ resistor goes from the A0 junction to GND.
Checkpoint — what you should see
The Serial Monitor prints a row of three values every 2 seconds. Temperature is close to room temperature (18–30 °C typical). Humidity reflects the room (30–80% typical). Light value changes when you cover or illuminate the LDR. No NaN errors appear after the first read. The SD module and RTC were validated in Phases 1 and 2; this phase validates the DHT11 and photoresistor. All four modules are now on the breadboard and ready for Phase 4.

CSV Logging with RTC Timestamps and Headers
Combine everything: read the RTC timestamp, read DHT11 and LDR, format a CSV row, and append it to a log file on the SD card every 10 seconds. Write the header row only once (by checking whether the file already exists before creating it). The observable result is a file on the SD card that grows by one row every 10 seconds and opens correctly in Excel or a text editor.
The header-once pattern. SD.exists("DATALOG.CSV") returns true if the file is already on the card. The sketch checks this flag before opening the file: if the file does not exist yet, it creates it and writes the header row first; if it already exists, it opens it in append mode and skips the header. This means you can power-cycle the Arduino without duplicating the header in your dataset. The header will only ever appear as the first line.
  1. Keep all hardware from Phases 1–3 wired. No new hardware is added in Phase 4. The full wiring at this point:
    SD module: VCC->5V, GND->GND, MOSI->11, MISO->12, SCK->13, CS->10 DS3231 RTC: VCC->5V, GND->GND, SDA->A4, SCL->A5 DHT11: VCC->5V, GND->GND, DATA->pin 2 LDR divider: 5V -> [LDR] -> A0 -> [10kOhm] -> GND
  2. Create a new sketch. This is the full data logger — paste the complete sketch:
    // Phase 4: Full CSV data logger // Combines: SD (SPI), DS3231 RTC (I2C), DHT11, LDR voltage divider. // // Libraries: // SD -- built in to Arduino IDE // RTClib -- Adafruit (install via Library Manager: "RTClib") // DHT.h -- Adafruit DHT sensor library + Adafruit Unified Sensor // // Log file: DATALOG.CSV on the microSD card // Log interval: every LOG_INTERVAL_MS milliseconds (default 10 000 = 10 s) // CSV columns: timestamp,temp_c,humidity_pct,light_raw #include <SPI.h> #include <SD.h> #include <Wire.h> #include "RTClib.h" #include "DHT.h" // ── Pin assignments ────────────────────────────────────────────── #define SD_CS_PIN 10 #define DHT_PIN 2 #define DHT_TYPE DHT11 #define LDR_PIN A0 // ── Logging interval ───────────────────────────────────────────── #define LOG_INTERVAL_MS 10000UL // 10 seconds between rows // ── Global objects ─────────────────────────────────────────────── RTC_DS3231 rtc; DHT dht(DHT_PIN, DHT_TYPE); unsigned long lastLogTime = 0; unsigned long rowCount = 0; bool headerWritten = false; // ── Helpers ────────────────────────────────────────────────────── // Zero-pad a number to two digits and print to a String. String twoDigit(int n) { return (n < 10 ? "0" : "") + String(n); } // Build a formatted timestamp string from the RTC now() object. String buildTimestamp(DateTime &t) { return String(t.year()) + "-" + twoDigit(t.month()) + "-" + twoDigit(t.day()) + " " + twoDigit(t.hour()) + ":" + twoDigit(t.minute()) + ":" + twoDigit(t.second()); } // ── Setup ───────────────────────────────────────────────────────── void setup() { Serial.begin(9600); // Wait briefly for a USB host (Serial Monitor). On the Uno this exits // instantly. On CDC-class boards (Leonardo, Micro, Zero) a bare // "while (!Serial)" hangs forever without a host -- the timeout prevents that. // This sketch is designed for autonomous deploy-and-walk-away use (no Serial // cable required once running), so a blocking wait would defeat the mission. unsigned long _t = millis(); while (!Serial && millis() - _t < 3000) { ; } // --- SD card --- Serial.print("SD init... "); if (!SD.begin(SD_CS_PIN)) { Serial.println("FAILED. Check wiring and card format (must be FAT32)."); while (true) { ; } } Serial.println("OK"); // --- RTC --- Serial.print("RTC init... "); if (!rtc.begin()) { Serial.println("FAILED. Check SDA=A4, SCL=A5 wiring."); while (true) { ; } } if (rtc.lostPower()) { Serial.println("RTC lost power -- setting to compile time."); rtc.adjust(DateTime(F(__DATE__), F(__TIME__))); } Serial.println("OK"); // --- DHT11 --- dht.begin(); Serial.println("DHT11 started."); // --- Write CSV header if the file does not already exist --- // SD.exists() returns true if DATALOG.CSV is already on the card. // This lets us resume logging across power cycles without // duplicating the header row. if (!SD.exists("DATALOG.CSV")) { File f = SD.open("DATALOG.CSV", FILE_WRITE); if (f) { f.println("timestamp,temp_c,humidity_pct,light_raw"); f.close(); headerWritten = true; Serial.println("Created DATALOG.CSV with header."); } else { Serial.println("ERROR: Could not create DATALOG.CSV."); while (true) { ; } } } else { headerWritten = true; Serial.println("DATALOG.CSV already exists -- resuming log."); } Serial.println("Logger ready. Writing one row every 10 seconds."); Serial.println("timestamp,temp_c,humidity_pct,light_raw"); } // ── Loop ────────────────────────────────────────────────────────── void loop() { unsigned long now = millis(); // Log on first iteration (lastLogTime=0) and every LOG_INTERVAL_MS after. if (now - lastLogTime >= LOG_INTERVAL_MS) { lastLogTime = now; // Read sensors float temp = dht.readTemperature(); // Celsius float hum = dht.readHumidity(); int light = analogRead(LDR_PIN); // 0-1023 // Validate DHT11 reading if (isnan(temp) || isnan(hum)) { Serial.println("DHT11 read failed -- skipping this row."); return; } // Get timestamp from RTC DateTime t = rtc.now(); String ts = buildTimestamp(t); // Build the CSV row String row = ts + "," + String(temp, 1) + "," + String(hum, 1) + "," + String(light); // Append to the log file File logFile = SD.open("DATALOG.CSV", FILE_WRITE); if (logFile) { logFile.println(row); logFile.close(); // Flush to card immediately rowCount++; Serial.print(row); Serial.print(" [row "); Serial.print(rowCount); Serial.println("]"); } else { Serial.println("ERROR: Could not open DATALOG.CSV to append."); } } }
  3. Upload and open Serial Monitor at 9600 baud. You should see setup messages and then one row logged every 10 seconds:
    SD init... OK RTC init... OK DHT11 started. Created DATALOG.CSV with header. Logger ready. Writing one row every 10 seconds. timestamp,temp_c,humidity_pct,light_raw 2026-06-19 14:35:00,23.0,55.0,712 [row 1] 2026-06-19 14:35:10,23.0,55.0,714 [row 2] 2026-06-19 14:35:20,23.0,56.0,708 [row 3]
  4. Let the logger run for at least 2 minutes (12 rows), then power off the Arduino. Insert the microSD card into your computer and open DATALOG.CSV in a text editor. You should see:
    timestamp,temp_c,humidity_pct,light_raw 2026-06-19 14:35:00,23.0,55.0,712 2026-06-19 14:35:10,23.0,55.0,714 2026-06-19 14:35:20,23.0,56.0,708 2026-06-19 14:35:30,23.0,56.0,705 ...
  5. Test the resume-without-duplicate-header behavior. Put the card back in the module, power the Arduino on again. The Serial Monitor should say "DATALOG.CSV already exists -- resuming log." and continue appending new rows below the existing ones. Open the file again after a few rows — the header should appear exactly once, at the top.
The CSV file on the card is empty or missing rows? Every write session must end with logFile.close(). The sketch already calls this after each println(), so data is flushed to the card after every row. If you power off mid-write (during the println() call), the current row may be lost but all previous rows are already safe because they were closed. This is why we open, write one row, and close on every loop iteration rather than holding the file open across iterations.
The header appears multiple times in the file? The SD.exists() check runs in setup() before the file is created. If the sketch was previously writing to a file named differently (e.g., you changed the filename between uploads), SD.exists("DATALOG.CSV") returns false even though a different log file exists, and a new header is written. Always use a consistent filename across uploads, or delete the old file from the card before testing a renamed sketch.
All light_raw values are 0? The LDR wire to A0 may be disconnected. analogRead() on an unconnected floating pin can return any value, including stuck-at-zero. Confirm the midpoint of the voltage divider is connected to A0.
Checkpoint — what you should have

Power-cycling the Arduino resumes logging without duplicating the header. The Serial Monitor echoes every row with a row counter. You now have a self-contained, autonomous data logger. Python Data Visualization Script
Pull the microSD card, copy DATALOG.CSV to your computer, and run a Python script that reads the CSV, parses the timestamp column, and produces a three-panel chart (temperature, humidity, light level over time) saved as datalog_chart.png. The script also prints a summary table of min, max, and average for each sensor channel.
Why pandas + matplotlib. pandas.read_csv() reads the file in one call and handles the timestamp parsing. matplotlib plots the data. Together they are the standard Python data pipeline for CSV files of this type. Both are installed with a single command.
  1. Install the Python dependencies. Open a terminal (not the Arduino IDE — your OS terminal: Terminal on Mac/Linux, PowerShell or Command Prompt on Windows). Run:
    pip install "pandas>=2.0" matplotlib
    pandas 2.0 or higher is required: the script uses on_bad_lines="warn" (added in pandas 1.3) and date_format (added in pandas 2.0). If you have both Python 2 and Python 3 on your machine and pip installs to Python 2, use pip3 install "pandas>=2.0" matplotlib instead. Confirm your Python version with python --version or python3 --version; you need 3.9 or higher.
  2. Copy DATALOG.CSV to your computer. Eject the microSD card from the Arduino module safely (power off the Arduino first). Insert the card into your computer via adapter. Copy DATALOG.CSV to a convenient folder — for example, your Desktop. The script below assumes the CSV is in the same directory as the script itself.
  3. Create the Python visualization script. In any text editor or IDE, create a new file named visualize.py in the same folder as DATALOG.CSV. Paste this complete script:
    #!/usr/bin/env python3 """ visualize.py Reads DATALOG.CSV produced by the Arduino data logger (Phase 4), plots temperature, humidity, and light level over time, saves the chart to datalog_chart.png, and prints a summary table. Requires: pip install pandas matplotlib Tested with: Python 3.9+, pandas 2.x, matplotlib 3.x """ import sys import pandas as pd import matplotlib.pyplot as plt import matplotlib.dates as mdates from pathlib import Path CSV_FILE = "DATALOG.CSV" CHART_OUT = "datalog_chart.png" # ── Load the CSV ────────────────────────────────────────────────── csv_path = Path(CSV_FILE) if not csv_path.exists(): print(f"ERROR: {CSV_FILE} not found in the current directory.") print("Make sure the script and CSV file are in the same folder.") sys.exit(1) # parse_dates=['timestamp'] converts the column to datetime objects. # date_format tells pandas the exact format, suppressing the FutureWarning # emitted by pandas 2.2+ when the format is not explicitly declared. try: df = pd.read_csv( csv_path, parse_dates=["timestamp"], date_format="%Y-%m-%d %H:%M:%S", on_bad_lines="warn" # skip garbled rows, print a warning ) except Exception as e: print(f"ERROR reading {CSV_FILE}: {e}") sys.exit(1) # Drop rows where timestamp parsing failed (NaT) or sensor columns are NaN. df = df.dropna(subset=["timestamp", "temp_c", "humidity_pct", "light_raw"]) if df.empty: print("ERROR: No valid rows found in the CSV after cleaning.") sys.exit(1) # Sort by timestamp in case the logger restarted mid-session. df = df.sort_values("timestamp").reset_index(drop=True) print(f"Loaded {len(df)} rows spanning " f"{df['timestamp'].min()} to {df['timestamp'].max()}") # ── Summary statistics ──────────────────────────────────────────── print("\n--- Summary ---") for col, label, unit in [ ("temp_c", "Temperature", "C"), ("humidity_pct", "Humidity", "%"), ("light_raw", "Light", "0-1023"), ]: mn = df[col].min() mx = df[col].max() avg = df[col].mean() print(f" {label:12s} min={mn:.1f}{unit} " f"max={mx:.1f}{unit} avg={avg:.1f}{unit}") # ── Plot ────────────────────────────────────────────────────────── fig, axes = plt.subplots(3, 1, figsize=(12, 9), sharex=True) fig.suptitle("Arduino Data Logger -- Session Summary", fontsize=13, y=0.98) # Panel 1: Temperature ax1 = axes[0] ax1.plot(df["timestamp"], df["temp_c"], color="#f97316", linewidth=1.4) ax1.set_ylabel("Temp (C)", fontsize=9) ax1.set_ylim(df["temp_c"].min() - 2, df["temp_c"].max() + 2) ax1.grid(True, alpha=0.3) ax1.set_title("Temperature", fontsize=9, loc="left") # Panel 2: Humidity ax2 = axes[1] ax2.plot(df["timestamp"], df["humidity_pct"], color="#38bdf8", linewidth=1.4) ax2.set_ylabel("Humidity (%)", fontsize=9) ax2.set_ylim(0, 100) ax2.grid(True, alpha=0.3) ax2.set_title("Humidity", fontsize=9, loc="left") # Panel 3: Light level (area fill to show relative changes clearly) ax3 = axes[2] ax3.fill_between(df["timestamp"], df["light_raw"], alpha=0.4, color="#a78bfa") ax3.plot(df["timestamp"], df["light_raw"], color="#a78bfa", linewidth=1.2) ax3.set_ylabel("Light (0-1023)", fontsize=9) ax3.set_ylim(0, 1023) ax3.grid(True, alpha=0.3) ax3.set_title("Light Level (raw ADC)", fontsize=9, loc="left") # Format the shared x-axis as readable timestamps. ax3.xaxis.set_major_formatter(mdates.DateFormatter("%H:%M")) fig.autofmt_xdate(rotation=30, ha="right") ax3.set_xlabel("Time", fontsize=9) plt.tight_layout() fig.savefig(CHART_OUT, dpi=150, bbox_inches="tight") print(f"\nChart saved to: {CHART_OUT}") # Show the chart in a window (if running interactively). plt.show()
  4. Run the script. In your terminal, navigate to the folder containing both visualize.py and DATALOG.CSV, then run:
    python visualize.py
    On Mac/Linux, you may need python3 visualize.py if python still points to Python 2 on your system. Use whichever command your earlier version check showed as 3.x.
  5. Verify the output. The terminal should print something like:
    Loaded 48 rows spanning 2026-06-19 14:35:00 to 2026-06-19 15:02:50 --- Summary --- Temperature min=22.0C max=24.0C avg=22.9C Humidity min=54.0% max=58.0% avg=55.8% Light min=420.0 0-1023 max=840.0 0-1023 avg=710.4 0-1023 Chart saved to: datalog_chart.png
    A window showing the three-panel chart will open. After you close the window, datalog_chart.png is saved in the same folder and can be shared or embedded in a report.
Script prints "ERROR: DATALOG.CSV not found"? The terminal's current working directory is not the folder that contains the CSV. Run ls (Mac/Linux) or dir (Windows) to confirm what files are in the current directory. Navigate to the correct folder with cd, then re-run the script.
Script prints "No valid rows found after cleaning"?
  • Open the CSV in a text editor. If the file has only the header row and no data rows, the logger never wrote a complete row. Check that you let the Phase 4 sketch run for at least 10 seconds before removing the card.
  • If there are rows but the timestamp column contains values like 2000-01-01 00:00:00, the RTC lost power and reset. See the Phase 2 battery troubleshooting section.
  • If rows contain nan in temp or humidity columns, the DHT11 failed on those reads. The script drops those rows with dropna(). If most rows are dropped, revisit the DHT11 wiring from Phase 3.
Chart x-axis shows wrong times or garbled labels? The parse_dates=["timestamp"] argument requires the column to be named exactly timestamp (lowercase, no spaces) and the values to be in YYYY-MM-DD HH:MM:SS format. Open the CSV and confirm the first column header and a sample value match this format exactly. A typo in the Arduino sketch's timestamp string (e.g., using a slash instead of a dash) will cause parsing to fail.
