Subject

My First Hack

Recruit 45 min 250 XP
Mission Brief

Complete your first ethical hacking challenge — scan a target, find the vulnerability, exploit it, and capture the flag. All legal, all guided, all on a purpose-built vulnerable practice target. This is your introduction to the offensive security mindset: think like an attacker to build better defenses.

You will use nmap to discover open ports on your own machine, research what services those ports expose, then set up DVWA (Damn Vulnerable Web Application) — a legally-designed, intentionally broken web app — and perform your first SQL injection and command injection attacks against it.

Nothing here targets systems you do not own. Everything runs on your local machine or a Docker container you control. The final deliverable is a 3-sentence pentest finding — the same format professional security researchers use when reporting vulnerabilities to organizations.

Agent Requirements
  • nmap installed: sudo apt install nmap (Linux) or via Homebrew/nmap.org
  • Docker installed (docker.com/get-started)
  • A web browser
  • Legal reminder: only scan and exploit systems you own or have explicit written permission to test
Operation Phases
Progress
0 / 4
✓
1
Reconnaissance
nmap is a network scanner that discovers open ports and services on a machine. Run it against your own localhost: nmap localhost. The output shows each port number (e.g., 22, 80, 3306), its state (open/closed), and the service name (ssh, http, mysql). Run a version-detection scan for more detail: nmap -sV localhost. The -sV flag probes each open port to determine the exact software and version running on it.
Checkpoint
You can read the nmap output and identify at least 3 open ports on your machine by number, state, and service name. For example: "Port 22 is open, running OpenSSH 8.9. Port 80 is open, running Apache 2.4." If nmap is not found, install it with sudo apt install nmap on Linux or brew install nmap on macOS.
✓
2
Find the Vulnerability
Every open port is a potential entry point. For each service you found, research its attack surface. Search Google for "[service name] default credentials" — many services ship with well-known default username/password combinations that are never changed. Also search "[service name] CVE" to find known public vulnerabilities in the version you identified. Document what you find. The goal is to understand the concept, not to exploit a live production system.
Checkpoint
You have identified one potential weakness for one of your services and can explain it in one sentence. For example: "Apache 2.4.49 has CVE-2021-41773, a path traversal vulnerability allowing unauthenticated file read." If you cannot find anything for your services, look up default credentials for MySQL or SSH — those are always relevant starting points.
✓
3
Exploit It (Safely)
Set up DVWA — a legal, intentionally vulnerable practice web app. Run it in Docker: docker run -d -p 80:80 vulnerables/web-dvwa. Open http://localhost in your browser. Log in with the default credentials: username admin, password password. Click "Create / Reset Database" on the setup page. Navigate to the SQL Injection page in the DVWA menu. In the User ID field, enter: ' OR 1=1 -- and click Submit.
Checkpoint
The SQL injection payload bypasses the normal login check and returns all users from the database instead of one specific user. This works because the input is concatenated directly into the SQL query without sanitization — OR 1=1 always evaluates to true, and -- comments out the rest. You have just exploited a real vulnerability class used in real-world breaches.
✓
4
Capture the Flag
Navigate to the DVWA Command Injection page. There is an input field that pings an IP address. Enter your IP: 127.0.0.1 first to see normal output. Then enter: 127.0.0.1; cat /etc/passwd. The semicolon chains a second command after the ping — the server executes both. The contents of /etc/passwd are displayed in the output. Write a 3-sentence finding: what you found, how you exploited it, and how to fix it.
Checkpoint
The DVWA command injection page displays the contents of /etc/passwd from the Docker container. You have a written 3-sentence pentest finding. Example format: "The Command Injection page at /dvwa/vulnerabilities/exec/ does not sanitize user input. By appending ; cat /etc/passwd to the ping target field, an attacker can execute arbitrary OS commands as the web server user. Fix: use input validation to allow only valid IP addresses and never pass raw user input to shell functions."
