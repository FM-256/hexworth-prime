Subject

Auto-Summarize Videos with Python

Operative 90 min 500 XP
Mission Brief

A one-hour YouTube lecture contains the same information as a five-paragraph summary — the gap is the pipeline to extract it. This project builds that pipeline in Python from first principles: pull the public caption transcript via the youtube-transcript-api library (no API key, no YouTube account required), process the raw text through nltk's tokenization and stopword filtering, score every sentence by its term-frequency weight, and select the top-N sentences that carry the highest informational density. The result is printed to your terminal and saved as a text file.

This is an extractive summary, not an AI-generated or abstractive one. The tool does not write new sentences or paraphrase anything. It ranks existing sentences from the transcript by how many high-frequency content words they contain, then returns the top scorers in their original order. The output reads naturally because the sentences are verbatim from the video — but understand that what you get is a selection, not a rewrite. A sentence the speaker considered a throwaway aside might outscore a nuanced argument if it happens to repeat key terms more often.

Beyond the core algorithm, this project adds a word-cloud PNG of dominant terms using wordcloud and a command-line interface so the tool runs on any YouTube URL from the terminal. By the end you will have a single script, summarizer.py, that accepts a URL, prints the summary, and writes wordcloud.png to disk — a reusable research accelerator you can run on any captioned video.

Agent Requirements
  • Python 3.x installed — download the installer from python.org/downloads (choose the latest stable release). After installing, open a terminal and run python --version or python3 --version to confirm it prints a version number. On Windows, also confirm pip --version works.
  • A terminal you are comfortable typing in: PowerShell or Command Prompt on Windows, Terminal on Mac, any shell on Linux. Every command in this project is shown exactly as you type it.
  • A text editor for creating a single Python file. VS Code (code.visualstudio.com) is recommended but any plain-text editor works.
  • Comfortable writing Python functions and working with lists, dictionaries, and string methods. No prior NLP or natural language processing experience required — all concepts are introduced inline.
  • No YouTube account, no Google account, no API key. The library fetches the same public captions a viewer would read. It does not use the YouTube Data API.
  • Internet access during the transcript-fetch step. NLTK resource downloads also require internet access once, during setup.
Two honest caveats before you start.
(1) Not every video has a transcript. The tool only works when the video has captions available — either human-uploaded subtitles or auto-generated captions that YouTube has made accessible. Many videos have captions disabled, are in a language the library cannot retrieve, or are too short to have been captioned. Phase 1 shows you how the tool handles this gracefully with a plain-language error message instead of a crash.

(2) This is extractive, not AI-generated. The algorithm picks the highest-scoring sentences that already exist in the transcript. It cannot synthesize an idea that spans multiple sentences, catch irony, or understand context. For dense academic lectures it works well. For casual conversational videos where the speaker circles back repeatedly, the top-scored sentences may feel repetitive.

This is the standard Python pattern for "failed gracefully" — you never get a raw exception stack trace in the user's face.

Text Preprocessing with NLTK
Install NLTK, download the required language resources, and write the preprocessing function that turns the raw transcript string into two things: a list of sentences (for scoring) and a flat list of clean words (for building the frequency dictionary). At the end of this phase you will see a count of sentences found and the first ten clean tokens from the transcript.
What NLTK resources are required? NLTK separates the library (installed via pip) from its language models (downloaded separately). For this project you need two resources: punkt_tab for sentence and word tokenization, and stopwords for the English stop-word list. The resource name changed from punkt to punkt_tab in NLTK 3.9 (August 2024) as part of a security update that replaced pickled models with a safer pickle-free format. If you use the old name punkt on NLTK 3.9+, you get a LookupError. Use punkt_tab.

Word-Frequency Scoring Algorithm
Build a word-frequency dictionary over all clean tokens, normalize every frequency to the 0–1 range, then score each sentence as the sum of the normalized frequencies of its content words. At the end of this phase you will print the five highest-scored sentences from the transcript — your first real extractive summary.
Why normalize? Without normalization, a short video with 200 tokens and a long video with 5000 tokens would produce incompatible absolute frequency counts. Dividing every count by the maximum count squashes all frequencies into the same 0–1 range regardless of video length. A word that appears most often gets score 1.0; a word that appears once gets a very small fraction. Sentence scores are then comparable across different videos and different summary lengths.

--------------------------------------------------------------------------- # New in Phase 3: build a normalized word-frequency table. # Returns a dict mapping each clean word to its normalized frequency (0-1). # --------------------------------------------------------------------------- def build_frequency_table(clean_words: list[str]) -> dict[str, float]: """ Count every clean word, then divide each count by the maximum count so all frequencies fall in the range [0, 1]. """ counts = collections.Counter(clean_words) if not counts: return {} max_count = counts.most_common(1)[0][1] return {word: count / max_count for word, count in counts.items()} # --------------------------------------------------------------------------- # New in Phase 3: score each sentence. # A sentence's score is the sum of the normalized frequencies of its # content words (stop-words and punctuation tokens contribute 0). # --------------------------------------------------------------------------- def score_sentences( sentences: list[str], freq_table: dict[str, float] ) -> dict[int, float]: """ Returns a dict mapping sentence index (its original position in the transcript) to its float score. Sentences whose every token is a stop-word or punctuation receive a score of 0. """ scores: dict[int, float] = {} for idx, sentence in enumerate(sentences): score = 0.0 for token in word_tokenize(sentence): lowered = token.lower() if lowered in freq_table: score += freq_table[lowered] scores[idx] = score return scores # --------------------------------------------------------------------------- # Phase 3 entry point: print the top-5 sentences as a first real summary. # --------------------------------------------------------------------------- if __name__ == '__main__': test_url = 'https://www.youtube.com/watch?v=8jPQjjsBbIc' n_sentences = 5 video_id = extract_video_id(test_url) if video_id is None: raise SystemExit(1) text = get_transcript(video_id) if not text: raise SystemExit(1) sentences, clean_words = preprocess(text) freq_table = build_frequency_table(clean_words) sentence_scores = score_sentences(sentences, freq_table) # Pick the top-n sentence indices by score. top_indices = heapq.nlargest( n_sentences, sentence_scores, key=lambda idx: sentence_scores[idx] ) # Re-sort by original position so the summary reads in transcript order. top_indices_ordered = sorted(top_indices) print(f"\n=== SUMMARY ({n_sentences} sentences) ===\n") for i, idx in enumerate(top_indices_ordered, start=1): print(f"[{i}] {sentences[idx]}\n")
    Why heapq.nlargest? Python's heapq.nlargest(n, iterable, key) is the idiomatic way to find the top-N items from a collection without sorting the entire thing. It is faster than sorting for large collections and expresses the intent clearly: "give me the N largest sentence-score values." The key function tells it to rank by the score value, not the dictionary key (the index).
