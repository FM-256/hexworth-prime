Subject

Build a Container Health Checker

Journeyman 90 min 500 XP
Mission Brief

This operation requires the construction of a Python-based container health checker that continuously monitors Docker containers for health status, resource consumption, and restart behavior. The tool interfaces with the Docker Engine through subprocess calls to the Docker CLI or directly via the requests library against the Docker Unix socket API, collecting real-time container stats and translating them into actionable health signals.

The checker tracks CPU percentage, memory usage and limits, network I/O, and container uptime across all running containers on the host. A configurable rules engine evaluates each container against defined thresholds — flagging crash-loops, sustained CPU saturation, and memory pressure before they become production incidents. Alerts are written to a timestamped log and surfaced in a color-coded terminal dashboard using ANSI escape codes.

Beyond the finished artifact, this operation builds the exact skills that separate a container-aware engineer from someone who simply runs docker ps: parsing structured JSON output from the Docker daemon, computing derived metrics from raw cgroup data, reasoning about container lifecycle states, and designing configurable monitoring pipelines that can be wired into any alerting or observability stack. These are the patterns that underpin professional-grade infrastructure tooling.

Agent Requirements
  • Python basics — comfortable with subprocess, JSON parsing, loops, and conditional logic
  • Docker installed and running on the target machine — able to execute docker ps and docker stats from the terminal
  • Basic understanding of containers — knows what images, containers, ports, and volumes are at a conceptual level
  • Familiar with terminal output formatting — has printed tabular data or used f-strings before
  • No prior experience with monitoring systems, container orchestration, or Docker API integration is required
Operation Phases
Progress
0 / 5
✓
1
Docker API Client
Build a Python wrapper around the core Docker CLI commands — docker ps, docker stats, and docker inspect. Use subprocess.run() with the --format json flag to capture machine-readable output, then parse each response through json.loads() into normalized Python dicts. Each container object should expose a consistent interface: ID, name, image, status, uptime, and exposed ports.
Checkpoint: Docker API Client
  • Run the wrapper against docker ps and verify the output is parsed into a Python dict with keys: ID, name, image, status
  • Test with no running containers and confirm the function returns an empty list without errors
  • Verify docker inspect wrapper returns port mappings and network configuration for a running container
✓
2
Resource Monitoring
Implement real-time stats collection by streaming docker stats --no-stream --format json for all running containers. Parse the raw output into structured metrics: CPU percentage, memory used vs. memory limit, and network I/O in/out bytes. Calculate derived signals — memory utilization percentage, CPU delta between two consecutive polls, and block I/O totals. Store each snapshot in a collections.deque for trend analysis.
✓
3
Health Check Engine
Define a rule set that evaluates each container on every polling cycle: memory utilization exceeding a configurable threshold, CPU sustained above limit for N consecutive samples, restart count incrementing beyond an allowed ceiling, and container transitioning to exited or dead unexpectedly. Track state transitions with a per-container history dict so rules only fire on change — not on every tick.
Checkpoint: Health Check Engine
  • Spin up a container with --memory=50m and a memory-intensive process — verify the memory threshold rule fires
  • Confirm alerts only fire on state transitions, not on every polling tick — check the per-container history dict
  • Manually stop a container and verify the exited state transition triggers an alert
✓
4
Alert System & Dashboard
Build a terminal dashboard that renders all containers in a formatted table using ANSI escape codes — green for healthy, yellow for warning, red for critical. Use os.system('clear') or \033[2J\033[H to refresh in-place without scroll pollution. When health rules trigger, append a structured alert entry (container name, rule violated, timestamp, metric value) to an in-memory list and write it to a log file via the logging module.
✓
5
Reporting & Persistence
Export full health snapshots as JSON reports with --report flag support via argparse. Each report includes per-container metric history, fired alert summaries, and an overall health score. Add configurable thresholds through a config.json file or command-line arguments (--cpu-threshold, --mem-threshold, --restart-limit). Compute rolling averages from the stored deque to surface trend lines in the dashboard footer.
Checkpoint: Reporting
  • Run with --report flag and verify a JSON file is generated with per-container metrics and alert summaries
  • Test --cpu-threshold 50 and confirm the threshold changes the alerting behavior
  • Verify rolling averages appear in the dashboard footer showing trend lines for CPU and memory
