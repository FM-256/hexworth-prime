Build a Container Health Checker

Operative 90 min 500 XP
Mission Brief

Your assignment is to build a working container health monitoring system using only Docker and Python 3. When you finish, you will have: a running nginx container with a live HEALTHCHECK, a second container deliberately configured to fail its health check so you can watch it go unhealthy, and a Python script that polls every running container, reads each one's health state via docker inspect, and prints a status table that flags unhealthy containers in the terminal. Everything runs on your local machine — no cloud account, no cost, no paid tools.

This project is a zero-knowledge walkthrough. Every phase shows the exact files to create, the exact commands to run, and the observable output that confirms you are on track before moving on. Phase 1 starts from verifying Docker is installed and covers every step. The monitor script in Phase 4 and 5 uses only Python 3 standard library modules — subprocess, json, time, and datetime — so there is nothing to install with pip.

By the end you will understand how Docker's HEALTHCHECK instruction works, how health state progresses from starting to healthy or unhealthy, how to read that state programmatically with docker inspect, and how to write a polling script that surfaces container problems before they become production incidents. These are the skills that separate container-aware engineers from operators who only know docker ps.

Agent Requirements
  • Docker installed and running. On Mac or Windows use Docker Desktop (download from docs.docker.com/get-started/get-docker/). On Linux install Docker Engine. After installing, open a terminal and run docker --version — you need 20.10 or higher. Then run docker run hello-world to confirm the daemon is responding. If that command prints "Hello from Docker!" you are ready. On Linux, if you see permission denied see the fix note in Phase 1.
  • Python 3.8 or higher. Run python3 --version in your terminal. On Windows the command may be python --version. You do not need to install any packages — everything used in this project is in the standard library.
  • A terminal. Mac: Terminal or iTerm2. Windows: PowerShell (recommended) or Command Prompt. Linux: any shell. Every command in this project is shown exactly as you type it.
  • A text editor. VS Code (code.visualstudio.com) is recommended. Any plain-text editor works.
  • No cloud account, no paid tools, no pip installs — the entire project runs on your laptop.

Verify Docker and Run Your First Container
Before touching a Dockerfile you need to confirm Docker is installed, the daemon is running, and you can pull and start a container. This phase runs an nginx container in the background, maps port 8080 on your machine to port 80 inside the container, and confirms you can reach it. You also learn how to read the STATUS column in docker ps — which is where health state will appear in later phases.
  1. Verify Docker is installed. Open your terminal and run:
    docker --version
    Expected output looks like Docker version 27.x.x, build xxxxxxx. If you see command not found or docker: command not found, Docker is not installed. Download and run the installer from docs.docker.com/get-started/get-docker/, then restart your terminal and try again. On Mac and Windows you must also start Docker Desktop (the whale icon in the menu bar / system tray) before any docker command will work.
  2. Confirm the daemon is running. Run:
    docker run hello-world
    Docker downloads the tiny hello-world image, starts a container, prints a message that includes "Hello from Docker!", then the container exits. If you see that message, Docker is fully functional. If you see Cannot connect to the Docker daemon, the daemon is not running — start Docker Desktop and wait for the whale icon to stop animating, then try again.
  3. Create a project folder. Choose a location (Desktop is fine) and run:
    mkdir container-checker cd container-checker
    Windows note: mkdir and cd work the same way in PowerShell and Command Prompt. All commands in this project work on Mac, Windows, and Linux unless noted otherwise.
  4. Run an nginx container in the background. The -d flag detaches (runs in background), --name gives it a memorable name, and -p 8080:80 maps port 8080 on your machine to port 80 inside the container:
    docker run -d --name web-test -p 8080:80 nginx:alpine
    Docker pulls the nginx:alpine image if you do not already have it (about 8 MB), then starts the container and prints a long hex container ID. The terminal returns immediately to the prompt because -d detaches the container to the background.
  5. Check that the container is running. Run:
    docker ps
    You should see a table with one row for web-test. The STATUS column will say something like Up 5 seconds. There is no health state yet because this container has no HEALTHCHECK — that comes in Phase 2. The PORTS column should show 0.0.0.0:8080->80/tcp.
  6. Confirm nginx is serving. Open your browser and navigate to:
    http://localhost:8080
    You should see the "Welcome to nginx!" page. Alternatively, from the terminal:
    curl http://localhost:8080
    curl prints the HTML source of the nginx welcome page. If the browser or curl returns a connection error, the container is not running — check docker ps and docker logs web-test.
  7. Teardown after verifying. Stop and remove the test container to keep your environment clean:
    docker stop web-test docker rm web-test
    You will build a new container with a HEALTHCHECK in Phase 2. The nginx:alpine image stays cached locally — Docker will not re-download it. To also remove the cached image and reclaim disk space run docker image rm nginx:alpine, but that means Docker will re-pull it in Phase 2 so only do this if disk space is tight.
Permission denied on Linux?
  • On Linux, Docker commands require either sudo or membership in the docker group. Running sudo docker run hello-world is the fastest fix. To avoid typing sudo every time, add your user to the docker group: sudo usermod -aG docker $USER, then log out and back in. After that, all docker commands work without sudo.
  • Do not use sudo for the Python scripts in later phases — they call docker via subprocess and will inherit whatever permissions your shell has.
Port 8080 already in use? Another process on your machine is listening on port 8080. Change the host port to any unused number, for example: docker run -d --name web-test -p 9090:80 nginx:alpine. Remember to use port 9090 (or whatever you picked) when opening the browser.

Add a HEALTHCHECK — Watch Status Go “starting” then “healthy”
A HEALTHCHECK tells Docker to run a command inside the container on a schedule. Docker records the exit code: 0 means healthy, 1 means unhealthy. The health state shows up in the STATUS column of docker ps and in the JSON from docker inspect. This phase builds a custom nginx image with a HEALTHCHECK that curls localhost. You will watch the STATUS column transition from starting to healthy in real time.
How HEALTHCHECK timing works. The Dockerfile instruction accepts four options: --interval (how often to run the check, default 30s), --timeout (how long Docker waits for the check command to exit, default 30s), --start-period (grace period after container starts before failures count, default 0s), and --retries (how many consecutive failures trigger unhealthy, default 3). For this phase you use short values so you do not have to wait long to see state changes.
  1. Create the Dockerfile. Inside your container-checker/ folder, create a file named exactly Dockerfile (no extension) and paste this complete file:
    FROM nginx:alpine # Install curl so the health check command can make HTTP requests. # curl is not included in nginx:alpine by default. RUN apk add --no-cache curl # HEALTHCHECK instruction: # --interval=10s run the check every 10 seconds # --timeout=5s give the check command 5 seconds to exit # --start-period=5s wait 5 seconds after container starts before counting failures # --retries=3 three consecutive failures = unhealthy # CMD curl -f http://localhost/ # -f makes curl return exit code 22 on HTTP errors (4xx/5xx) # which Docker treats as a failed health check HEALTHCHECK --interval=10s --timeout=5s --start-period=5s --retries=3 \ CMD curl -f http://localhost/ || exit 1
    Why || exit 1? The HEALTHCHECK CMD must exit with 0 (healthy) or 1 (unhealthy). curl with -f already exits non-zero on HTTP errors, but adding || exit 1 makes the failure path explicit and handles any other error curl might produce. Docker reserves exit code 2 for its own internal use; a HEALTHCHECK CMD must only exit with 0 (healthy) or 1 (unhealthy). Never use exit 2 in a health check command.
  2. Build the image. From inside container-checker/, run:
    docker build -t web-healthy:v1 .
    The -t web-healthy:v1 flag tags the image with name web-healthy and tag v1. The . means "look for the Dockerfile in the current folder." Docker runs each Dockerfile instruction as a layer and caches them. The apk install step downloads curl; the rest is instant. You should see output ending in Successfully built or similar.
  3. Run a container from the image. Use a different port (8081) so it does not conflict with anything on 8080:
    docker run -d --name web-healthy -p 8081:80 web-healthy:v1
  4. Watch the STATUS column change. Run docker ps immediately after starting the container, then again every 5–10 seconds:
    docker ps
    During the first 5 seconds (the --start-period), STATUS shows:
    Up 3 seconds (health: starting)
    After the first successful check (around the 10-second mark, when the first interval fires after the start-period), STATUS changes to:
    Up 18 seconds (healthy)
    The health state in parentheses is added to the STATUS column only when a HEALTHCHECK is defined. Containers without a HEALTHCHECK show only the uptime (e.g., Up 18 seconds) with no parenthetical.
  5. Read the health state with docker inspect. Once the container shows healthy, run:
    docker inspect --format '{{if .State.Health}}{{.State.Health.Status}}{{else}}no healthcheck{{end}}' web-healthy
    Expected output:
    healthy
    Why the if/else wrapper? When a container has no HEALTHCHECK, .State.Health is null in the JSON. Accessing .State.Health.Status on a null value in a Go template causes a template execution error. Wrapping it in {{if .State.Health}}...{{else}}...{{end}} guards against that. The monitor script in Phase 4 uses the same pattern. Always use the guarded form.
  6. See the full health log. Docker keeps the last five health check results. To see them:
    docker inspect --format '{{json .State.Health}}' web-healthy
    The output is a JSON object with three fields: Status (the current state string), FailingStreak (consecutive failures, 0 when healthy), and Log (an array of the last check results, each with Start, End, ExitCode, and Output).
  7. Teardown. Keep the container running for now — you will reference it in Phase 3 alongside the unhealthy container. If you want to stop it: docker stop web-healthy && docker rm web-healthy. Leave the image; you will use it again.
STATUS still shows (health: starting) after two minutes?
  • The health check command is failing silently during the start period. Run docker inspect --format '{{json .State.Health}}' web-healthy and look at the Log array. Each entry has an Output field showing what the command printed before it exited. A common cause: curl was not installed into the image because the RUN apk add --no-cache curl line was missing or misspelled in the Dockerfile. Rebuild the image after fixing the Dockerfile.
  • Confirm you built from the right folder: the Dockerfile must be in container-checker/ and you must run docker build from that same folder.
docker: Error response from daemon: Conflict. The container name "/web-healthy" is already in use? A previous run left the container behind. Remove it: docker rm -f web-healthy, then rerun the docker run command.
Go template error: template: :1:2: executing "" at <.State.Health.Status>: nil pointer? The container has no HEALTHCHECK defined. Use the guarded form: {{if .State.Health}}{{.State.Health.Status}}{{else}}no healthcheck{{end}}. The monitor script in Phase 4 always uses this form.
Checkpoint — what you should see
docker ps shows web-healthy with STATUS Up X seconds (healthy). docker inspect --format '{{if .State.Health}}{{.State.Health.Status}}{{else}}no healthcheck{{end}}' web-healthy prints healthy. You understand the HEALTHCHECK Dockerfile syntax and know why the nil guard is required in the inspect template. Make a Container Go Unhealthy — Read the Failing State
Health checking is only useful if you understand what failure looks like. This phase builds a second image with a HEALTHCHECK that is designed to fail, runs it alongside the healthy container, and watches the STATUS column transition to unhealthy. You then read the failing streak count and the error output from docker inspect. At the end of this phase you have two running containers — one healthy, one unhealthy — ready for the monitor script to report on.
  1. If web-healthy is not still running, restart it.
    docker run -d --name web-healthy -p 8081:80 web-healthy:v1
    Wait about 20 seconds for it to reach the healthy state before continuing.
  2. Create the failing Dockerfile. Create a new file named Dockerfile.bad inside container-checker/ and paste:
    FROM nginx:alpine RUN apk add --no-cache curl # This HEALTHCHECK always fails because it checks port 9999, # which nothing inside this container is listening on. # After 3 consecutive failures (interval=10s, retries=3: checks at ~10s, ~20s, ~30s) Docker marks the container unhealthy. HEALTHCHECK --interval=10s --timeout=5s --start-period=5s --retries=3 \ CMD curl -f http://localhost:9999/ || exit 1
    Why port 9999? nginx listens on port 80 inside the container. Port 9999 is unused, so curl will immediately get a connection refused error and exit non-zero, causing the health check to fail every time. After 3 consecutive failures Docker sets the status to unhealthy. The container keeps running — Docker does not stop it automatically when it goes unhealthy. That is intentional: the HEALTHCHECK is a reporting mechanism, not an auto-restart trigger.
  3. Build the failing image. The -f flag tells Docker which Dockerfile to use when it is not named exactly Dockerfile:
    docker build -f Dockerfile.bad -t web-unhealthy:v1 .
  4. Run the failing container.
    docker run -d --name web-bad -p 8082:80 web-unhealthy:v1
  5. Watch both containers. Run docker ps repeatedly every 10–15 seconds. After about 30 seconds from when web-bad started you should see:
    CONTAINER ID IMAGE STATUS a3f9c2e81b40 web-healthy:v1 Up 2 minutes (healthy) b71da09c34fe web-unhealthy:v1 Up 45 seconds (unhealthy)
    The timing: after the 5s start-period, the first check fires at ~10s, the second at ~20s, and the third at ~30s — three consecutive failures means unhealthy is declared at roughly 30s. The exact seconds depend on when Docker starts the container internally.
  6. Read the failing streak and error log. Run:
    docker inspect --format '{{if .State.Health}}{{.State.Health.Status}} (failing streak: {{.State.Health.FailingStreak}}){{else}}no healthcheck{{end}}' web-bad
    Expected output once unhealthy:
    unhealthy (failing streak: 3)
    Then see the raw check output:
    docker inspect --format '{{json .State.Health}}' web-bad
    Look at the Log array entries. The Output field for each failed check will contain the curl error message (curl: (7) Failed to connect to localhost port 9999) and the ExitCode will be 1.
  7. Do not teardown yet. Leave both containers running — one healthy, one unhealthy. The monitor script in Phase 4 will report on both simultaneously.
web-bad still shows (health: starting) after 60 seconds? The start period plus retries should push it to unhealthy by ~40s. If it is stuck in starting, check docker inspect --format '{{json .State.Health}}' web-bad and look at the Log array. If ExitCode is 0 in any entry, the check is accidentally passing — confirm the Dockerfile uses port 9999, not port 80.
Only one container shows in docker ps? The other container may have exited with an error unrelated to the health check (for example, a Dockerfile syntax error). Run docker ps -a to show all containers including stopped ones. Read the exit status and run docker logs <container-name> to see what went wrong.
Checkpoint — what you should see
docker ps shows two containers: web-healthy with STATUS (healthy) and web-bad with STATUS (unhealthy). The inspect command returns unhealthy (failing streak: 3) for web-bad. You understand that a HEALTHCHECK failure does not stop the container — it only changes the reported state. Phase 4 writes the Python monitor script that reads both containers and prints a status table.

The Monitor Script — Poll All Containers, Print a Status Table
This phase builds the Python monitor script. It uses subprocess to call docker ps (to list running containers) and docker inspect (to read each container's health state). It then prints a formatted table showing container name, image, uptime, and health status, with unhealthy containers flagged. No pip installs — only Python standard library. At the end of this phase you run the script manually and confirm it correctly reports one healthy and one unhealthy container.
Why subprocess instead of the Docker SDK? The official Docker SDK for Python (docker package) is the right tool for production tooling, but it requires pip install docker. Using subprocess to call the Docker CLI keeps this project at zero pip dependencies, works on any machine with Docker installed, and teaches you the inspect JSON structure that you would interact with in any language or tool.
  1. Create the monitor script. Inside container-checker/, create a file named monitor.py and paste this complete file:
    #!/usr/bin/env python3 """ monitor.py Container health monitor using the Docker CLI via subprocess. No pip installs required -- standard library only. Verified against Docker CLI 27.x behavior. """ import subprocess import json import datetime def run(cmd): """Run a command list and return stdout as a string. Returns '' on error; does not raise.""" result = subprocess.run( cmd, capture_output=True, text=True, ) return result.stdout.strip() def list_running_containers(): """ Return a list of dicts, one per running container. Fields: Id, Names, Image, Status (uptime string from docker ps). Uses --format json to get machine-readable output (Docker 20.10+). """ output = run(["docker", "ps", "--format", "json"]) if not output: return [] containers = [] # docker ps --format json prints one JSON object per line (not a JSON array). for line in output.splitlines(): line = line.strip() if not line: continue try: containers.append(json.loads(line)) except json.JSONDecodeError: continue return containers def get_health_status(container_name): """ Read the health state of a single container via docker inspect. Returns one of: 'healthy', 'unhealthy', 'starting', 'none'. 'none' means the container has no HEALTHCHECK defined. Uses a Go template with a nil guard so containers without a HEALTHCHECK do not cause a template execution error. """ output = run([ "docker", "inspect", "--format", "{{if .State.Health}}{{.State.Health.Status}}{{else}}none{{end}}", container_name, ]) # Strip whitespace; docker inspect returns a trailing newline. return output.strip() if output else "unknown" def get_failing_streak(container_name): """ Return the number of consecutive health check failures for a container. Returns 0 if the container has no HEALTHCHECK or is currently healthy. """ output = run([ "docker", "inspect", "--format", "{{if .State.Health}}{{.State.Health.FailingStreak}}{{else}}0{{end}}", container_name, ]) try: return int(output.strip()) except (ValueError, AttributeError): return 0 def print_table(containers): """Print a formatted status table to the terminal.""" now = datetime.datetime.now().strftime("%Y-%m-%d %H:%M:%S") print(f"\n=== Container Health Report {now} ===\n") # Column headers print(f" {'NAME':<22} {'IMAGE':<26} {'UPTIME':<22} {'HEALTH':<12} {'NOTE'}") print(f" {'-'*22} {'-'*26} {'-'*22} {'-'*12} {'-'*20}") for c in containers: # docker ps --format json uses 'Names' (with an 's') for the name field. # It includes a leading slash on older Docker versions; strip it. name = c.get("Names", c.get("Name", "?")).lstrip("/") image = c.get("Image", "?") uptime = c.get("Status", "?") # This is the uptime string, e.g. "Up 2 minutes" health = get_health_status(name) streak = get_failing_streak(name) if health == "unhealthy" else 0 # Build a note for unhealthy containers. if health == "unhealthy": note = f"ALERT: {streak} consecutive failures" elif health == "none": note = "no healthcheck" else: note = "" # Truncate long strings so the table stays readable. name_col = name[:21] image_col = image[:25] uptime_col = uptime[:21] # Mark unhealthy rows with an asterisk in the health column. health_col = f"* {health}" if health == "unhealthy" else health print(f" {name_col:<22} {image_col:<26} {uptime_col:<22} {health_col:<12} {note}") print() def main(): containers = list_running_containers() if not containers: print("\nNo running containers found.\n") return print_table(containers) # Report unhealthy count as a summary line. unhealthy = [ c.get("Names", "?").lstrip("/") for c in containers if get_health_status(c.get("Names", c.get("Name", "?")).lstrip("/")) == "unhealthy" ] if unhealthy: print(f" UNHEALTHY CONTAINERS ({len(unhealthy)}): {', '.join(unhealthy)}\n") else: print(" All containers healthy or no healthcheck defined.\n") if __name__ == "__main__": main()
    Why docker ps --format json? This flag (available since Docker 20.10) outputs one JSON object per line rather than the human-readable table. Parsing JSON is unambiguous — the plain text table format breaks if a container name contains spaces or special characters. Each line is a self-contained JSON object, not a JSON array, so the script reads them line by line.
  2. Confirm both containers from Phase 3 are still running.
    docker ps
    You should see web-healthy (healthy) and web-bad (unhealthy). If either is missing, re-run the appropriate docker run command from Phase 2 or Phase 3, then wait 40 seconds for health states to settle before proceeding.
  3. Run the monitor script.
    python3 monitor.py
    On Windows if python3 is not recognized, try:
    python monitor.py
    The script calls docker ps and then docker inspect once per container. It should complete in under two seconds. There is no loop yet — it runs once and exits. The watch loop comes in Phase 5.
  4. Expected output. You should see a table like this (exact uptime will differ):
    === Container Health Report 2026-06-19 14:23:07 === NAME IMAGE UPTIME HEALTH NOTE ---------------------- -------------------------- ---------------------- ------------ -------------------- web-healthy web-healthy:v1 Up 8 minutes healthy web-bad web-unhealthy:v1 Up 6 minutes * unhealthy ALERT: 3 consecutive failures UNHEALTHY CONTAINERS (1): web-bad
ModuleNotFoundError or ImportError? The script uses only standard library modules (subprocess, json, datetime). If you see a module not found error for one of these, confirm you are running Python 3.8 or higher: python3 --version. All three modules ship with every Python 3 installation.
The table shows all containers as none for health? The inspect template is not matching. Possible causes: (a) you are running Docker older than 20.10 where --format json on docker ps is not supported — update Docker; (b) the container names in docker ps have a leading slash that was not stripped — add a print statement to debug: print(repr(name)) before the get_health_status call to see the exact string being passed to inspect.
Script exits with No running containers found but docker ps shows containers? On some Docker versions, docker ps --format json outputs a JSON array ([{...},{...}]) rather than newline-delimited objects. If that is the case, replace the list_running_containers function's parsing block with: containers = json.loads(output) if output.startswith('[') else [json.loads(l) for l in output.splitlines() if l.strip()].

The summary line at the bottom reads UNHEALTHY CONTAINERS (1): web-bad. The script runs cleanly to completion in under 2 seconds. Phase 5 adds a watch loop, alert logging, and teardown.

Watch Loop, Alert Log, and Teardown
The monitor script currently runs once and exits. This phase adds a continuous watch loop that re-polls every 15 seconds, logs alerts to a file when a container becomes unhealthy, and clears the terminal between each poll so the table refreshes in-place instead of scrolling endlessly. After verifying the loop works, you tear down all test containers and images from this project so nothing is left consuming resources.
  1. Replace monitor.py with the full polished version. This is a complete file — paste it entirely, replacing what you had:
    #!/usr/bin/env python3 """ monitor.py -- v2: watch loop + alert log Polls all running containers every POLL_INTERVAL seconds. Logs unhealthy alerts to health-alerts.log in the same folder. Press Ctrl+C to stop. """ import subprocess import json import datetime import time import os import sys POLL_INTERVAL = 15 # seconds between polls LOG_FILE = "health-alerts.log" def run(cmd): """Run a command list and return stdout. Returns empty string on error.""" try: result = subprocess.run( cmd, capture_output=True, text=True, ) return result.stdout.strip() except FileNotFoundError: # Docker CLI not found at all. print("ERROR: 'docker' command not found. Is Docker installed and in PATH?") sys.exit(1) def list_running_containers(): """Return list of running container dicts from docker ps --format json.""" output = run(["docker", "ps", "--format", "json"]) if not output: return [] containers = [] # Handle both newline-delimited JSON objects and a JSON array. stripped = output.strip() if stripped.startswith("["): try: return json.loads(stripped) except json.JSONDecodeError: return [] for line in stripped.splitlines(): line = line.strip() if not line: continue try: containers.append(json.loads(line)) except json.JSONDecodeError: continue return containers def get_health(container_name): """ Return (status_string, failing_streak) for a container. status_string is one of: 'healthy', 'unhealthy', 'starting', 'none', 'unknown'. 'none' = container has no HEALTHCHECK defined. Nil guard prevents template errors on containers without a HEALTHCHECK. """ status_out = run([ "docker", "inspect", "--format", "{{if .State.Health}}{{.State.Health.Status}}{{else}}none{{end}}", container_name, ]) streak_out = run([ "docker", "inspect", "--format", "{{if .State.Health}}{{.State.Health.FailingStreak}}{{else}}0{{end}}", container_name, ]) status = status_out.strip() if status_out else "unknown" try: streak = int(streak_out.strip()) except (ValueError, AttributeError): streak = 0 return status, streak def log_alert(message): """Append a timestamped alert line to LOG_FILE.""" ts = datetime.datetime.now().strftime("%Y-%m-%d %H:%M:%S") with open(LOG_FILE, "a") as f: f.write(f"[{ts}] {message}\n") def clear_screen(): """Clear the terminal. Works on Mac, Linux, and Windows.""" os.system("cls" if os.name == "nt" else "clear") def print_table(containers): """Print the status table and return a list of unhealthy container names.""" now = datetime.datetime.now().strftime("%Y-%m-%d %H:%M:%S") print(f"=== Container Health Monitor {now} (Ctrl+C to stop) ===\n") print(f" {'NAME':<22} {'IMAGE':<26} {'UPTIME':<22} {'HEALTH':<14} {'NOTE'}") print(f" {'-'*22} {'-'*26} {'-'*22} {'-'*14} {'-'*28}") unhealthy_names = [] for c in containers: name = c.get("Names", c.get("Name", "?")).lstrip("/") image = c.get("Image", "?") uptime = c.get("Status", "?") status, streak = get_health(name) if status == "unhealthy": note = f"ALERT: {streak} consecutive failures" health_col = f"* unhealthy" unhealthy_names.append(name) elif status == "none": note = "no healthcheck defined" health_col = "none" elif status == "starting": note = "waiting for first check..." health_col = "starting" else: note = "" health_col = status print(f" {name[:21]:<22} {image[:25]:<26} {uptime[:21]:<22} {health_col:<14} {note}") print() return unhealthy_names def main(): print(f"Starting monitor. Polling every {POLL_INTERVAL}s. Alerts logged to {LOG_FILE}.") print("Press Ctrl+C to stop.\n") time.sleep(1) previously_unhealthy = set() try: while True: clear_screen() containers = list_running_containers() if not containers: now = datetime.datetime.now().strftime("%Y-%m-%d %H:%M:%S") print(f"[{now}] No running containers found. Polling again in {POLL_INTERVAL}s...") else: unhealthy_now = set(print_table(containers)) # Log new unhealthy transitions (only when state changes to unhealthy). newly_unhealthy = unhealthy_now - previously_unhealthy for name in newly_unhealthy: msg = f"UNHEALTHY: container '{name}' transitioned to unhealthy state." log_alert(msg) print(f" [ALERT logged] {msg}") # Log recoveries (unhealthy -> healthy). recovered = previously_unhealthy - unhealthy_now for name in recovered: msg = f"RECOVERED: container '{name}' is now healthy." log_alert(msg) print(f" [ALERT logged] {msg}") previously_unhealthy = unhealthy_now if unhealthy_now: print(f" UNHEALTHY ({len(unhealthy_now)}): {', '.join(sorted(unhealthy_now))}") else: print(" All containers healthy or no healthcheck defined.") print(f"\n Next poll in {POLL_INTERVAL}s...") time.sleep(POLL_INTERVAL) except KeyboardInterrupt: print("\n\nMonitor stopped by user (Ctrl+C).") if __name__ == "__main__": main()
    How the transition tracking works. previously_unhealthy is a set of container names that were unhealthy in the last poll. Each poll computes unhealthy_now and takes the set difference to find newly unhealthy containers (transition in) and recovered containers (transition out). This means the log file only gets one alert when a container first goes unhealthy, not an alert on every poll. That is the correct pattern for health alerting — log the event, not the state.
  2. Confirm both test containers are still running.
    docker ps
    You should see web-healthy (healthy) and web-bad (unhealthy). Restart them from Phase 2/3 if needed.
  3. Start the monitor loop.
    python3 monitor.py
    The screen clears and the table appears. It will refresh every 15 seconds. On the first poll, if web-bad is unhealthy, you should immediately see an alert line like:
    [ALERT logged] UNHEALTHY: container 'web-bad' transitioned to unhealthy state.
    and a new file health-alerts.log appears in container-checker/.
  4. Verify the log file. Open a second terminal window (leave the monitor running in the first) and run:
    cat health-alerts.log
    Expected output:
    [2026-06-19 14:31:02] UNHEALTHY: container 'web-bad' transitioned to unhealthy state.
    The log only has one line per transition event, not one per poll.
  5. Stop the monitor. In the first terminal, press Ctrl+C. The script prints Monitor stopped by user (Ctrl+C). and exits cleanly.
  6. Full teardown. Stop and remove all test containers, then remove the custom images to reclaim disk space:
    docker stop web-healthy web-bad docker rm web-healthy web-bad docker image rm web-healthy:v1 web-unhealthy:v1
    Confirm everything is gone:
    docker ps -a
    The nginx:alpine base image stays in your local cache because you did not specifically remove it, and it is useful for future projects. To remove it too: docker image rm nginx:alpine. To see all locally cached images: docker images. To remove all stopped containers and unused images in one sweep (be careful on a shared machine): docker system prune.
Terminal does not clear between polls on Windows? The os.system("cls") call requires that cls is available in the shell. In PowerShell it works. In some restricted environments it may not. If the screen does not clear, the table still prints correctly — it just scrolls instead of refreshing in-place. This is cosmetic only and does not affect the alerting or logging logic.
docker stop fails with "No such container"? The container already exited or was removed. Run docker ps -a to see all containers including stopped ones. Use docker rm <name> to remove a stopped container. The -f flag on docker rm -f <name> force-stops and removes in one step.
Checkpoint — mission complete
Run through this verification from top to bottom: (1) python3 monitor.py starts the loop. (2) The table shows web-healthy as healthy and web-bad as unhealthy with a failing streak count. (3) health-alerts.log contains at least one timestamped UNHEALTHY alert. (4) Ctrl+C stops the monitor cleanly. (5) docker stop web-healthy web-bad && docker rm web-healthy web-bad removes the test containers. (6) docker ps -a shows no remaining containers from this project. If all six pass, the Container Health Checker is complete.
