Subject

Build a RESTful API with Express

Intermediate 90 min 400 XP
Mission Brief

This operation requires the construction of a production-grade RESTful API using Express.js and MongoDB that implements full CRUD operations, JWT-based authentication, role-based access control, file uploads, and paginated responses. The API follows REST conventions strictly — proper HTTP methods, status codes, resource-based URLs, and consistent JSON response envelopes.

The architecture separates concerns cleanly: routes define endpoint mappings, controllers handle request/response logic, models define Mongoose schemas with validation and hooks, and middleware handles cross-cutting concerns like authentication, input validation, and centralized error handling. Every endpoint returns structured JSON with status codes, data payloads, and pagination metadata.

Beyond the finished artifact, this operation builds the backend engineering muscle memory that surfaces in every web project: designing clean API contracts, securing endpoints with JWT and RBAC, handling file uploads with Multer, implementing cursor-based pagination, and writing centralized error handlers that return consistent error shapes. These patterns form the backbone of every modern web application.

Agent Requirements
  • Comfortable writing JavaScript with ES6+ syntax (arrow functions, destructuring, async/await)
  • Node.js 18+ and npm installed on your machine
  • Basic understanding of HTTP methods (GET, POST, PUT, DELETE) and status codes
  • Familiar with JSON format and how APIs communicate
  • No prior experience with Express, MongoDB, or JWT is required — the project teaches each from scratch
Operation Phases
Progress
0 / 5
✓
1
Express Scaffold & MongoDB Connection
Initialize the project with npm init, install Express and Mongoose, and build the application entry point. Configure middleware for JSON parsing, CORS, and request logging. Connect to MongoDB using mongoose.connect() with a connection string from environment variables via dotenv.
Checkpoint: Project Setup
  • Start the API server and verify it responds to GET / with a 200 status
  • Confirm the server runs on the expected port and logs incoming requests
  • Verify the database connection is established (check server logs for connection success)
✓
2
Mongoose Models & CRUD Controllers
Define a User schema with Mongoose including field validation, unique constraints, and a pre('save') hook for password hashing with bcrypt. Build controllers for all five CRUD operations: list (with pagination), create, read by ID, update, and delete. Each returns proper HTTP status codes and consistent JSON envelopes.
✓
3
JWT Authentication & Role-Based Access
Build registration and login endpoints that issue JWT tokens with jsonwebtoken. Create an authGuard middleware that verifies the Bearer token on protected routes. Add a roleGuard that checks the user's role (admin, editor, viewer) against the required permission level for each endpoint.
Checkpoint: CRUD Endpoints
  • Send a POST request to create a resource and verify a 201 response with the created object
  • Send a GET request and verify the resource is returned with correct data
  • Send PUT and DELETE requests and verify updates and deletions work
✓
4
File Uploads & Pagination
Add file upload support using multer with file type validation and size limits. Implement offset-based pagination on list endpoints with page and limit query parameters, returning total count, current page, and total pages in the response metadata. Add sorting and filtering query parameter support.
Checkpoint: Authentication
  • Make a request without an auth token and verify the API returns 401 Unauthorized
  • Obtain a valid token (login or API key) and verify authenticated requests succeed
  • Verify the token expires after the configured TTL and subsequent requests are rejected
✓
5
Error Handling & Input Validation
Build a centralized error handling middleware that catches all errors and returns consistent JSON error responses with status code, error type, and message. Add input validation using express-validator on all mutation endpoints. Implement rate limiting with express-rate-limit. Test every endpoint with curl or Postman to verify correct behavior for both success and error cases.
Checkpoint: Validation & Errors
  • Send a request with missing required fields and verify a 400 response with an error message
  • Request a non-existent resource ID and confirm a 404 is returned
  • Send malformed JSON in the request body and verify the API returns a clear error, not a 500
