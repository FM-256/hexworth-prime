Subject

Build a RESTful API with Express

Operative 90 min 400 XP
Mission Brief

Your assignment is to build a working production-grade RESTful API using Node.js, Express 4, and MongoDB. When you finish, you will have a running server that handles user registration and login with JWT tokens, protects routes based on user role, accepts file uploads, and paginates list responses — all testable with a single curl command from your terminal.

This project is structured as a zero-knowledge walkthrough. Every phase shows the exact files to create, the exact code to paste, the terminal commands to run, and a curl command with its expected JSON output that confirms you are on track before moving on. You do not need prior Express or MongoDB experience — Phase 1 starts from an empty folder.

By the end you will understand the layered architecture that powers every modern API: routes map URLs to handlers, controllers contain the request/response logic, models define the Mongoose schema and validation, and middleware handles cross-cutting concerns like auth and error formatting. These patterns appear in every Node.js backend you will ever work with.

Agent Requirements
  • Node.js LTS installed — download the LTS installer from nodejs.org/en/download. After installing, open a terminal and run node --version and npm --version to confirm both respond. This project requires Node 18 or higher.
  • A terminal (Windows: PowerShell or Command Prompt; Mac: Terminal; Linux: any shell). Every command in this project is shown exactly as you type it, including the expected output.
  • VS Code (code.visualstudio.com) as your editor — any plain-text editor works, but VS Code's syntax highlighting makes the code far easier to read and debug.
  • A free MongoDB Atlas account — Atlas is MongoDB's cloud service and its free M0 tier requires no credit card. Phase 1 walks you through signup, cluster creation, and copying your connection string. Alternatively, a local mongod on port 27017 works as a drop-in replacement.
  • curl to test endpoints — it is pre-installed on Mac, Linux, and Windows 10+ (PowerShell). Every checkpoint shows the exact command to run. If you prefer a GUI, the Thunder Client extension for VS Code or Postman (postman.com) both work; import the curl commands directly.
  • Comfortable writing JavaScript with ES6+ async/await. No prior Express, MongoDB, or JWT experience required — the project teaches each concept from scratch with explanations.

Express Scaffold & MongoDB Atlas Connection
Initialize the project, install all packages, create the folder structure, connect to a free MongoDB Atlas cluster, and verify the server starts and the database connection succeeds — all before writing a single route.
  1. Verify Node.js is installed. Open your terminal and run:
    node --version npm --version
    Expected: something like v22.x.x and 10.x.x. If you see command not found, download and run the LTS installer from nodejs.org/en/download, then restart your terminal.
  2. Create the project folder and enter it.
    mkdir my-rest-api cd my-rest-api
  3. Initialize the project. The -y flag accepts all defaults:
    npm init -y
    Why: This creates package.json, which tracks your project name and its dependencies. npm needs it to exist before you can install anything.
  4. Install all dependencies in one command.
    npm install express mongoose dotenv bcryptjs jsonwebtoken multer cors
    What each package does: express is the web framework. mongoose is the MongoDB client. dotenv loads secrets from a .env file. bcryptjs hashes passwords. jsonwebtoken signs and verifies JWT tokens. multer handles file uploads. cors allows browser clients to reach your API.
  5. Create your .env file at the root of my-rest-api/. This is where your secrets live — it is never committed to git:
    MONGO_URI=your_connection_string_here JWT_SECRET=replace_with_a_long_random_string_at_least_32_chars PORT=3000
    JWT_SECRET: Pick any long random string, for example x9kQ!mP2#vLz8dR0sYwN3bCjFtHuAeGo. It is used to sign tokens — keep it secret and never expose it in code.
  6. Create .gitignore so secrets and dependencies are never committed:
    node_modules/ .env uploads/
  7. Get your MongoDB Atlas connection string. If you do not already have an Atlas account:
    1. Go to mongodb.com/cloud/atlas/register and sign up with email, GitHub, or Google. No credit card required.
    2. After signing in, click Create a deployment. Choose M0 Free, pick any cloud/region, name the cluster anything (e.g. Cluster0), and click Create Deployment.
    3. Atlas opens a Connect dialog. Create a database user: enter a username (e.g. apiuser) and a password. Click Create Database User. Write down the password — you need it in the connection string.
    4. In the same dialog, click Network Access in the left sidebar. Click Add IP Address and enter 0.0.0.0/0 to allow all IPs (fine for learning). Click Confirm.
    5. Back on the Connect dialog, choose Drivers, select Node.js. Atlas shows a connection string that looks like:
      mongodb+srv://apiuser:<password>@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority
    6. Copy it, replace <password> with your actual password, and insert the database name before the ? so the URI ends with .mongodb.net/myrestapi?retryWrites=true&w=majority. Paste the completed string as the value of MONGO_URI in your .env file.
      The path segment between the hostname and the ? is the database name (/myrestapi). Without it, Mongoose connects to a database called test by default, and your data will appear in Atlas under that name instead of a dedicated one.
    Using a local mongod instead? Set MONGO_URI=mongodb://localhost:27017/myrestapi and make sure mongod is running. Everything else in this project is identical.
  8. Create the folder structure. From inside my-rest-api/:
    mkdir src src/models src/controllers src/routes src/middleware uploads
    Why this layout: Separating concerns means each folder has one job. models/ = database schemas, controllers/ = request/response logic, routes/ = URL mapping, middleware/ = auth and error handling. This is the standard Express project layout you will see on every team.
  9. Create src/server.js — the application entry point. Paste this complete file:
    // src/server.js // Express 4.x API — verified against expressjs.com/en/4x/api.html // Mongoose 9.x API — verified against mongoosejs.com/docs/api/mongoose.html 'use strict'; require('dotenv').config(); const express = require('express'); const mongoose = require('mongoose'); const cors = require('cors'); const path = require('path'); const app = express(); // ── Global middleware ────────────────────────────────────────────── // express.json() parses incoming JSON bodies into req.body. // Without it, req.body is always undefined. app.use(cors()); app.use(express.json()); // Serve uploaded files as static URLs: GET /uploads/filename app.use('/uploads', express.static(path.join(__dirname, '..', 'uploads'))); // ── Health check ─────────────────────────────────────────────────── app.get('/api/health', (req, res) => { res.json({ status: 'ok', time: new Date().toISOString() }); }); // ── Routes (wired in later phases) ──────────────────────────────── // app.use('/api/auth', require('./routes/authRoutes')); // app.use('/api/users', require('./routes/userRoutes')); // app.use('/api/upload',require('./routes/uploadRoutes')); // ── Error handler (MUST be last app.use) ────────────────────────── // Signature: four arguments (err, req, res, next) — Express identifies // error-handling middleware by arity. Register it AFTER all routes. app.use((err, req, res, next) => { const status = err.status || 500; res.status(status).json({ error: err.message || 'Internal server error' }); }); // ── Connect to MongoDB, then start the server ────────────────────── // mongoose.connect() returns a Promise; we await it before listening // so the server only accepts requests once the DB is ready. const PORT = process.env.PORT || 3000; const MONGO_URI = process.env.MONGO_URI; mongoose .connect(MONGO_URI) .then(() => { console.log('MongoDB connected'); app.listen(PORT, () => { console.log('Server running at http://localhost:' + PORT); }); }) .catch((err) => { console.error('MongoDB connection error:', err.message); process.exit(1); });
    Why connect-then-listen: If the server starts before the database is ready, the first request that touches MongoDB fails. Chaining .then(() => app.listen(...)) guarantees the DB handshake completes first.
  10. Start the server. In your terminal, from inside my-rest-api/:
    node src/server.js
    Expected output (two lines, in this order):
    MongoDB connected
    Server running at http://localhost:3000
    The terminal cursor stays there — the server is running. Press Ctrl+C to stop it.
  11. Hit the health check endpoint. Open a second terminal and run:
    curl http://localhost:3000/api/health
    Expected response:
    {"status":"ok","time":"2026-06-18T12:00:00.000Z"}
Terminal shows MongooseServerSelectionError or connection timed out?
  • Your Atlas IP allow-list does not include your current IP. Log into Atlas, go to Network Access, and confirm 0.0.0.0/0 is listed and shows Active. Changes can take 60 seconds to propagate.
  • Your .env still contains the literal text <password>. Replace it with your actual database user password. If the password contains special characters such as @, #, or !, they must be percent-encoded (e.g. ! becomes %21).
  • Run node -e "require('dotenv').config(); console.log(process.env.MONGO_URI)" from your project root to print the URI that will actually be used — spot typos before they reach MongoDB.
curl returns curl: (7) Failed to connect? The server is not running. Check the first terminal for an error message. The two most common causes are a bad MONGO_URI (the process exits before app.listen is reached) or a port conflict (EADDRINUSE means something else is on port 3000 — change PORT=3001 in .env and retry).
req.body is undefined in a later phase? You removed or commented out app.use(express.json()) in server.js, or you added a route before that line. The middleware must appear before any route that reads req.body.
Checkpoint — what you should have
Two terminal lines: MongoDB connected followed by Server running at http://localhost:3000. A second terminal running curl http://localhost:3000/api/health returns JSON with "status":"ok". Your folder contains: src/server.js, .env, .gitignore, package.json, node_modules/, src/models/, src/controllers/, src/routes/, src/middleware/, uploads/. Stop the server with Ctrl+C before moving to Phase 2.

Mongoose Models & CRUD Controllers
Define a User schema with validation, unique constraints, and a pre('save') hook that hashes the password automatically. Build controllers for all five CRUD operations with proper HTTP status codes and consistent JSON envelopes, then wire them to routes.
  1. Create src/models/User.js — the Mongoose schema. Paste this complete file:
    // src/models/User.js // Mongoose 9.x Schema API — mongoosejs.com/docs/api/mongoose.html 'use strict'; const mongoose = require('mongoose'); const bcrypt = require('bcryptjs'); const userSchema = new mongoose.Schema( { name: { type: String, required: [true, 'Name is required'], trim: true, maxlength: [100, 'Name cannot exceed 100 characters'] }, email: { type: String, required: [true, 'Email is required'], unique: true, // creates a unique index in MongoDB lowercase: true, trim: true, match: [/^\S+@\S+\.\S+$/, 'Please enter a valid email address'] }, password: { type: String, required: [true, 'Password is required'], minlength: [6, 'Password must be at least 6 characters'], select: false // never returned by default in query results }, role: { type: String, enum: ['viewer', 'editor', 'admin'], default: 'viewer' }, avatar: { type: String, default: null } }, { timestamps: true } // adds createdAt and updatedAt automatically ); // ── pre('save') hook ─────────────────────────────────────────────── // Runs before every .save() call. We use it to hash the password so // the raw string is never stored in the database. // bcryptjs v3 API: bcrypt.hash(data, saltRounds) -> Promise<string> userSchema.pre('save', async function (next) { // Only hash if the password field was modified (or is new). // Without this check, re-saving the user would hash the already- // hashed value, making all future logins fail. if (!this.isModified('password')) return next(); this.password = await bcrypt.hash(this.password, 12); next(); }); // ── Instance method: compare a candidate password against the hash ─ userSchema.methods.comparePassword = async function (candidatePassword) { // bcrypt.compare(plaintext, hash) -> Promise<boolean> return bcrypt.compare(candidatePassword, this.password); }; module.exports = mongoose.model('User', userSchema);
    Why select: false on password: Any User.find() or User.findById() call will omit the password field from the result automatically. To access it (e.g. during login), you must explicitly opt in with .select('+password'). This prevents accidentally leaking password hashes in API responses.
  2. Create src/controllers/userController.js — the five CRUD handlers. Paste this complete file:
    // src/controllers/userController.js // Mongoose 9.x query API — mongoosejs.com/docs/api/mongoose.html 'use strict'; const User = require('../models/User'); // ── GET /api/users?page=1&limit=10 ────────────────────────────── // Returns a paginated list of users. // .skip() and .limit() implement offset-based pagination. exports.getUsers = async (req, res, next) => { try { const page = Math.max(1, parseInt(req.query.page) || 1); const limit = Math.min(100, parseInt(req.query.limit) || 10); const skip = (page - 1) * limit; const [users, total] = await Promise.all([ User.find().skip(skip).limit(limit).lean(), User.countDocuments() ]); res.json({ data: users, page, limit, total, totalPages: Math.ceil(total / limit) }); } catch (err) { next(err); // pass to the centralized error handler in server.js } }; // ── GET /api/users/:id ────────────────────────────────────────────── exports.getUserById = async (req, res, next) => { try { const user = await User.findById(req.params.id).lean(); if (!user) return res.status(404).json({ error: 'User not found' }); res.json({ data: user }); } catch (err) { next(err); } }; // ── POST /api/users ───────────────────────────────────────────────── // Creates a new user. Mongoose schema validation runs automatically. // The pre('save') hook hashes the password before it reaches MongoDB. exports.createUser = async (req, res, next) => { try { const { name, email, password, role } = req.body; const user = await User.create({ name, email, password, role }); // Return the new user without the password field const userObj = user.toObject(); delete userObj.password; res.status(201).json({ data: userObj }); } catch (err) { // Duplicate email: MongoDB error code 11000 if (err.code === 11000) { return res.status(409).json({ error: 'Email already registered' }); } next(err); } }; // ── PUT /api/users/:id ────────────────────────────────────────────── // { new: true } returns the updated document instead of the original. exports.updateUser = async (req, res, next) => { try { const { name, role, avatar } = req.body; const user = await User.findByIdAndUpdate( req.params.id, { name, role, avatar }, { new: true, runValidators: true } ).lean(); if (!user) return res.status(404).json({ error: 'User not found' }); res.json({ data: user }); } catch (err) { next(err); } }; // ── DELETE /api/users/:id ─────────────────────────────────────────── exports.deleteUser = async (req, res, next) => { try { const user = await User.findByIdAndDelete(req.params.id); if (!user) return res.status(404).json({ error: 'User not found' }); res.json({ message: 'User deleted' }); } catch (err) { next(err); } };
    Why next(err) instead of res.status(500).json(...): Passing the error to next() routes it to the centralized error-handling middleware registered at the bottom of server.js. This means all error formatting lives in one place. If you call res.json() directly in the catch block, you duplicate that logic across every controller.
  3. Create src/routes/userRoutes.js. Paste this complete file:
    // src/routes/userRoutes.js 'use strict'; const router = require('express').Router(); const ctrl = require('../controllers/userController'); router.get('/', ctrl.getUsers); router.get('/:id', ctrl.getUserById); router.post('/', ctrl.createUser); router.put('/:id', ctrl.updateUser); router.delete('/:id', ctrl.deleteUser); module.exports = router;
  4. Update src/server.js to wire the user routes. Replace the commented-out routes block with:
    // ── Routes ──────────────────────────────────────────────────────── app.use('/api/users', require('./routes/userRoutes')); // (auth and upload routes added in Phases 3 and 4)
    This line mounts every route defined in userRoutes.js under the /api/users prefix. A router.get('/') in that file becomes GET /api/users on the server.
  5. Restart the server (Ctrl+C, then node src/server.js), then run these test commands from a second terminal:
    # 1. Create a user curl -s -X POST http://localhost:3000/api/users \ -H "Content-Type: application/json" \ -d '{"name":"Alice","email":"alice@example.com","password":"secret123","role":"admin"}' \ | cat
    Expected response (the _id will differ):
    {"data":{"_id":"664a...","name":"Alice","email":"alice@example.com","role":"admin","avatar":null,"createdAt":"2026-06-18T12:00:00.000Z","updatedAt":"2026-06-18T12:00:00.000Z","__v":0}}
    Windows Command Prompt (cmd.exe): single-quoted JSON does not work. The backslash-continuation lines above use Unix shell syntax (single quotes, line continuation with \). On Windows cmd.exe, single quotes are passed literally to curl and the server receives an empty body, producing a 400 error.
    Option A (recommended): Run the commands in Git Bash (installed with Git for Windows) — it handles Unix quoting and line continuation identically to Mac/Linux.
    Option B — cmd.exe escape: Use double quotes on the outside and escape inner quotes with \":
    curl -s -X POST http://localhost:3000/api/users -H "Content-Type: application/json" -d "{\"name\":\"Alice\",\"email\":\"alice@example.com\",\"password\":\"secret123\",\"role\":\"admin\"}"
    All subsequent curl commands in this project that contain JSON bodies follow the same pattern: single-quote form works on Mac, Linux, and Git Bash; cmd.exe requires the double-quote-escaped form above.
    # 2. List all users (save the _id from step 1 for the next command) curl -s http://localhost:3000/api/users | cat
    Expected response:
    {"data":[{...Alice...}],"page":1,"limit":10,"total":1,"totalPages":1}
req.body is empty ({}) or undefined? You are missing -H "Content-Type: application/json" in the curl command, or app.use(express.json()) is not present in server.js before the routes. Express only parses JSON bodies when that middleware is active AND the request carries the Content-Type: application/json header.
Creating a second user with the same email returns a 500 instead of 409? The unique index on the email field has not been built yet. This happens when you already had documents in the collection before adding the unique: true constraint. Drop the collection in Atlas (Clusters → Browse Collections → select the collection → trash icon) and re-create the users. Mongoose builds the unique index on first connect to an empty collection.
Cast to ObjectId failed error when fetching by ID? The ID in the URL is not a valid MongoDB ObjectId format (24 hex characters). Make sure you copied the full _id value from the create response, including no extra spaces or quotes.
Checkpoint — what you should see
POST /api/users returns 201 with the new user object (no password field). GET /api/users returns a paginated envelope with data, page, total, and totalPages. GET /api/users/:id returns that specific user. PUT /api/users/:id with -d '{"name":"Alice Updated"}' returns the updated document. DELETE /api/users/:id returns {"message":"User deleted"}. Atlas Collections view shows a users collection with the hashed password stored (not the plain text).

JWT Authentication & Role-Based Access
Build POST /api/auth/register and POST /api/auth/login endpoints that issue JWT tokens. Create an authGuard middleware that verifies the Bearer token on every protected route, and a roleGuard that checks the user's role before allowing access.
How JWT auth works in one paragraph: When a user logs in, the server signs a token with jwt.sign(payload, secret, options). The token is a compact string the client stores (e.g. in memory or localStorage). On every subsequent request, the client sends it in the Authorization: Bearer <token> header. The authGuard middleware calls jwt.verify(token, secret) — if the signature is valid and the token has not expired, the decoded payload (which contains the user's id and role) is attached to req.user. If verification fails, jwt.verify throws a JsonWebTokenError or TokenExpiredError and the middleware returns 401. No database lookup happens on every request — that is the stateless property of JWT.
  1. Create src/controllers/authController.js. Paste this complete file:
    // src/controllers/authController.js // jsonwebtoken API — github.com/auth0/node-jsonwebtoken // jwt.sign(payload, secret, { expiresIn }) -> string // jwt.verify(token, secret) -> decoded payload (throws on failure) // bcryptjs v3 — bcrypt.compare(plain, hash) -> Promise<boolean> 'use strict'; const jwt = require('jsonwebtoken'); const User = require('../models/User'); const JWT_SECRET = process.env.JWT_SECRET; // Helper: sign a token for a given user document function signToken(user) { return jwt.sign( { id: user._id, role: user.role }, JWT_SECRET, { expiresIn: '24h' } ); } // ── POST /api/auth/register ───────────────────────────────────────── exports.register = async (req, res, next) => { try { const { name, email, password } = req.body; // User.create() triggers the pre('save') hook which hashes the password const user = await User.create({ name, email, password }); const token = signToken(user); res.status(201).json({ token, userId: user._id }); } catch (err) { if (err.code === 11000) { return res.status(409).json({ error: 'Email already registered' }); } next(err); } }; // ── POST /api/auth/login ──────────────────────────────────────────── exports.login = async (req, res, next) => { try { const { email, password } = req.body; // .select('+password') overrides the schema's select:false // so we get the hash back for comparison const user = await User.findOne({ email }).select('+password'); if (!user) { // Return 401 for both "user not found" and "wrong password" // so attackers cannot enumerate valid email addresses return res.status(401).json({ error: 'Invalid credentials' }); } // comparePassword() is the instance method defined on the schema. // It calls bcrypt.compare(candidatePassword, this.password). const match = await user.comparePassword(password); if (!match) { return res.status(401).json({ error: 'Invalid credentials' }); } const token = signToken(user); res.json({ token, userId: user._id, role: user.role }); } catch (err) { next(err); } };
  2. Create src/middleware/authGuard.js. Paste this complete file:
    // src/middleware/authGuard.js // Verifies the Authorization: Bearer <token> header on every request // that mounts this middleware. Attaches decoded payload to req.user. 'use strict'; const jwt = require('jsonwebtoken'); const JWT_SECRET = process.env.JWT_SECRET; module.exports = function authGuard(req, res, next) { const header = req.headers['authorization'] || ''; const token = header.startsWith('Bearer ') ? header.slice(7) : null; if (!token) { return res.status(401).json({ error: 'No token provided' }); } try { // jwt.verify() throws JsonWebTokenError if the signature is wrong // or TokenExpiredError if the token has passed its expiresIn time. const decoded = jwt.verify(token, JWT_SECRET); req.user = decoded; // { id, role, iat, exp } next(); } catch (err) { return res.status(401).json({ error: 'Invalid or expired token' }); } };
  3. Create src/middleware/roleGuard.js. This factory function returns a middleware that checks req.user.role against an allowed list:
    // src/middleware/roleGuard.js // Usage: roleGuard('admin') or roleGuard('editor', 'admin') // Always place roleGuard AFTER authGuard on a route — authGuard must // run first to populate req.user. 'use strict'; module.exports = function roleGuard(...allowedRoles) { return function (req, res, next) { if (!req.user) { return res.status(401).json({ error: 'Not authenticated' }); } if (!allowedRoles.includes(req.user.role)) { return res.status(403).json({ error: 'Insufficient permissions' }); } next(); }; };
  4. Create src/routes/authRoutes.js.
    // src/routes/authRoutes.js 'use strict'; const router = require('express').Router(); const ctrl = require('../controllers/authController'); router.post('/register', ctrl.register); router.post('/login', ctrl.login); module.exports = router;
  5. Update src/routes/userRoutes.js to protect mutation endpoints. Replace the entire file:
    // src/routes/userRoutes.js // GET /api/users — public (list users) // GET /api/users/:id — public (read one user) // POST /api/users — admin only (create user directly) // PUT /api/users/:id — editor or admin // DELETE /api/users/:id — admin only 'use strict'; const router = require('express').Router(); const ctrl = require('../controllers/userController'); const authGuard = require('../middleware/authGuard'); const roleGuard = require('../middleware/roleGuard'); router.get('/', ctrl.getUsers); router.get('/:id', ctrl.getUserById); router.post('/', authGuard, roleGuard('admin'), ctrl.createUser); router.put('/:id', authGuard, roleGuard('editor', 'admin'), ctrl.updateUser); router.delete('/:id', authGuard, roleGuard('admin'), ctrl.deleteUser); module.exports = router;
  6. Update src/server.js to mount the auth routes. Add this line alongside the user routes line:
    app.use('/api/auth', require('./routes/authRoutes')); app.use('/api/users', require('./routes/userRoutes'));
  7. Restart the server and test the full login flow. Copy the token from the login response — you will use it in subsequent curl commands:

    Expected:
    {"token":"eyJhbGci...","userId":"664b..."}
    # 2. Login and capture the token curl -s -X POST http://localhost:3000/api/auth/login \ -H "Content-Type: application/json" \ -d '{"email":"bob@example.com","password":"secret123"}' \ | cat
    Expected:
    {"token":"eyJhbGci...","userId":"664b...","role":"viewer"}
    # 3. Try a protected route WITHOUT a token — expect 401 curl -s -X DELETE http://localhost:3000/api/users/664b... | cat
    Expected:
    {"error":"No token provided"}
    # 4. Try the same route WITH the token but role=viewer — expect 403 curl -s -X DELETE http://localhost:3000/api/users/664b... \ -H "Authorization: Bearer eyJhbGci..." | cat
    Expected:
    {"error":"Insufficient permissions"}
401 Invalid or expired token even though you just got the token?
  • The Authorization header must be spelled exactly right — capital A, no typos. The value must be Bearer (with a space) followed immediately by the token string with no quotes around the token.
  • Confirm JWT_SECRET in your .env file has not changed since the token was issued. If you edit the secret, all previously issued tokens become invalid.
  • Check that your curl command uses double quotes on the outside and that the token string does not have a trailing newline (copy just the token value from the JSON response, not the entire JSON line).
Login returns 401 Invalid credentials even with the correct password? The select: false on the password field means a plain User.findOne({ email }) returns the user without the password hash, so bcrypt.compare is comparing against undefined. Confirm your authController.js login function includes .select('+password') on the findOne call.
CORS error when testing from a browser or Postman? Confirm app.use(cors()) appears in server.js before any route definitions. The cors middleware must process the request before Express routes handle it.
Checkpoint — what you should see
POST /api/auth/register returns 201 with a JWT token and userId. POST /api/auth/login with the correct credentials returns 200 with a token; wrong password returns 401. DELETE /api/users/:id without a token returns {"error":"No token provided"}. DELETE /api/users/:id with a valid token from a viewer-role user returns {"error":"Insufficient permissions"}. Manually update a user's role to admin in the Atlas Collections view, log in again to get a fresh token, and the DELETE succeeds.

File Uploads & Pagination
Add an authenticated file upload endpoint using multer with file type filtering and size limits. Demonstrate the existing pagination on GET /api/users by seeding multiple users and querying with page and limit query parameters.
How multer works: Multer is an Express middleware that intercepts multipart/form-data requests (the encoding used by HTML file inputs). When you attach upload.single('avatar') to a route, multer reads the file from the request stream, saves it to disk (in the uploads/ folder), and populates req.file with metadata: fieldname, originalname, mimetype, size, filename (the renamed file on disk), and path. Your controller reads req.file to know where the file landed and can then store that path in the database.
  1. Create src/middleware/upload.js — the configured multer instance. Paste this complete file:

Error Handling & Input Validation
Harden every mutation endpoint with Mongoose's built-in schema validation, add a global error handler that formats every error consistently, handle invalid ObjectId formats gracefully, and verify that bad inputs produce informative 400 responses rather than 500 crashes.
Why use Mongoose validation instead of express-validator: The Mongoose schema already declares which fields are required, what their types are, and what constraints apply (minlength, match, enum). When you call User.create() or save a document, Mongoose validates the data before touching MongoDB and throws a ValidationError if anything fails. Catching that error in the controller and returning a 400 response gives you field-level validation for free without a separate library. For beginners this is the cleaner starting point — one tool, one place, zero duplication.
  1. Upgrade the centralized error handler in src/server.js. Replace the existing four-argument app.use error block with this enhanced version. It handles Mongoose validation errors, duplicate key errors, and invalid ObjectId format in one place:
    // ── Centralized error handler (MUST be the last app.use in the file) ── // Express identifies error-handling middleware by the four-argument signature. // All controllers call next(err) to reach this handler. app.use((err, req, res, next) => { // Mongoose validation error: e.g. required field missing, minlength if (err.name === 'ValidationError') { const messages = Object.values(err.errors).map((e) => e.message); return res.status(400).json({ error: 'Validation failed', details: messages }); } // MongoDB duplicate key: unique constraint violated (e.g. duplicate email). // NOTE: both authController.register and userController.createUser catch // err.code 11000 themselves and return 409 before reaching this handler. // This branch handles any duplicate-key error that slips through (e.g. a // controller that forgets its own 11000 catch). if (err.code === 11000) { return res.status(409).json({ error: 'Email already registered' }); } // Mongoose cast error: invalid ObjectId format in a URL param like /:id if (err.name === 'CastError' && err.kind === 'ObjectId') { return res.status(400).json({ error: 'Invalid ID format' }); } // Multer file size limit exceeded if (err.code === 'LIMIT_FILE_SIZE') { return res.status(413).json({ error: 'File too large. Maximum size is 2 MB.' }); } // JWT verification failure (passed via next(err) from authGuard) if (err.name === 'JsonWebTokenError' || err.name === 'TokenExpiredError') { return res.status(401).json({ error: 'Invalid or expired token' }); } // All other errors: log the stack trace server-side, return generic message console.error(err.stack); res.status(err.status || 500).json({ error: err.message || 'Internal server error' }); });
    Critical ordering rule: This app.use call must appear after every app.use('/api/...') route registration. Express processes middleware in the order it is registered. If the error handler is registered first, none of the routes' errors ever reach it.
