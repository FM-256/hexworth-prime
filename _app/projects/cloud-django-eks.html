Subject

Deploy to Amazon EKS

Advanced 120 min 1000 XP
Mission Brief

Your assignment is to containerize a Django e-library application and deploy it on Amazon Elastic Kubernetes Service (EKS) — the production-grade managed Kubernetes platform used across enterprise and government cloud environments. This operation covers the full deployment pipeline from local Docker build to a live, load-balanced application running in an AWS VPC.

You will write a Dockerfile for the Django application, push the image to Amazon ECR, provision an EKS cluster using eksctl, author Kubernetes manifest files for the Deployment and Service resources, and configure an AWS Load Balancer Controller to expose the application externally. IAM roles for service accounts (IRSA) will gate pod-level AWS access following least-privilege principles.

The final phase covers rolling deployments: updating the image tag, watching the rollout proceed with zero downtime, and executing a rollback if health checks fail. By mission end you will understand how AWS-managed control planes, node groups, ECR, and the Kubernetes object model interlock to serve production traffic.

Agent Requirements
  • AWS account with IAM permissions for EKS, ECR, EC2, and IAM
  • AWS CLI configured with access keys (aws configure)
  • eksctl and kubectl installed and on PATH
  • Docker installed; understanding of multi-stage builds and image layers
  • Basic Django project structure and requirements.txt management
  • Comfort reading YAML and understanding networking concepts (VPC, subnets, ports)
Operation Phases
1
Containerize the Django Application
Write a multi-stage Dockerfile using a Python 3.11 slim base image. Install dependencies from requirements.txt, collect static files, and run Gunicorn on port 8000. Build with docker build -t django-lib:v1 . and validate locally with docker run -p 8000:8000. Confirm /health/ returns 200 OK before moving on.
2
Push to Amazon ECR
Create a private ECR repository with aws ecr create-repository. Authenticate Docker to the registry using the ECR credential helper. Tag the image with the full ECR URI and push with docker push. Verify the image appears in the AWS Console under ECR with the correct digest and size.
3
Provision the EKS Cluster
Write an eksctl cluster config YAML specifying the region, VPC CIDR, two availability zones, and a managed node group of t3.medium instances (min 2, max 4). Run eksctl create cluster -f cluster.yaml and wait for the CloudFormation stacks to complete. Confirm cluster access with kubectl get nodes.
4
Deploy Manifests and Load Balancer
Author deployment.yaml referencing the ECR image URI, setting 3 replicas, resource requests and limits, and liveness/readiness probes against /health/. Create a service.yaml of type LoadBalancer to trigger the AWS Load Balancer Controller. Verify the external DNS hostname appears in kubectl get svc within two minutes.
5
Configure IAM Roles for Service Accounts
Enable OIDC on the cluster with eksctl utils associate-iam-oidc-provider. Create an IAM policy granting the Django pod read access to an S3 bucket holding e-library assets. Bind the policy to a Kubernetes service account using IRSA. Annotate the pod spec and verify AWS credential injection with aws s3 ls from inside the pod.
6
Rolling Deployment and Rollback
Build and push django-lib:v2 with a visible change to the home page. Update the Deployment image tag and apply. Watch the rolling update with kubectl rollout status deployment/django-lib. Simulate a broken build by referencing a non-existent image tag, observe pods stuck in ImagePullBackOff, then execute kubectl rollout undo to restore the previous version.
