Subject

Deploy Serverless Django on AWS

Advanced 120 min 1000 XP
Mission Brief

Your assignment is to take a Django web application and deploy it as a fully serverless, highly available system on AWS — eliminating EC2 instance management entirely. Using Zappa and the AWS Serverless Application Model, you will wrap Django in a Lambda function and expose it through API Gateway, achieving pay-per-request billing with automatic scaling to thousands of concurrent users.

The operation covers the complete stack: API Gateway handles incoming HTTP traffic, Lambda executes your Django WSGI application using aws-wsgi, RDS Postgres provides persistent relational storage with connection pooling via RDS Proxy, and S3 hosts static and media files served through CloudFront. Environment secrets are managed through AWS Secrets Manager and injected at runtime.

By the end of this operation you will understand Lambda cold starts and their mitigation strategies, how to configure zappa_settings.json for multiple stages, how to run Django management commands on Lambda, and how to monitor performance with CloudWatch metrics and X-Ray distributed tracing.

Agent Requirements
  • Working Django project with a virtual environment and requirements.txt
  • AWS CLI configured with sufficient IAM permissions (Lambda, API Gateway, S3, RDS, IAM)
  • Python 3.10 or 3.11 — must match the Lambda runtime version
  • Familiarity with Django settings, DATABASES, and STATIC_ROOT configuration
  • Basic understanding of serverless concepts and AWS billing model
Operation Phases
1
Django Preparation and Zappa Installation
Install Zappa and aws-wsgi into your virtual environment with pip install zappa django-s3-storage aws-wsgi. Run zappa init to generate zappa_settings.json and configure the S3 bucket for deployment packages, AWS region, and Django settings module. Update settings.py to use environment variables for SECRET_KEY, DEBUG, and ALLOWED_HOSTS. Add django-environ or python-decouple for clean environment variable management.
2
RDS Postgres and Database Configuration
Provision an RDS Postgres instance in a private VPC subnet using the AWS Console or aws rds create-db-instance. Configure the Django DATABASES setting to use the RDS endpoint. Since Lambda functions are stateless, install django-db-geventpool or limit CONN_MAX_AGE to prevent connection exhaustion. Run zappa manage dev migrate to execute database migrations directly on the Lambda function, and zappa manage dev createsuperuser to create an admin account.
3
S3 Static Files and CloudFront CDN
Configure django-s3-storage to serve static files from S3. Set STATICFILES_STORAGE and DEFAULT_FILE_STORAGE in settings to the S3 backend classes. Run python manage.py collectstatic to upload all static assets to the designated S3 bucket. Create a CloudFront distribution pointing to the S3 bucket origin with appropriate cache headers. Update STATIC_URL and MEDIA_URL to use the CloudFront domain for low-latency asset delivery globally.
4
Lambda Deployment and API Gateway
Deploy to AWS with zappa deploy dev. Zappa packages your virtualenv, uploads it to S3, creates the Lambda function, and wires up API Gateway automatically. Inspect the generated API Gateway in the console to understand the ANY /{proxy+} route that forwards all paths to Lambda. Configure a custom domain in API Gateway with an ACM certificate for HTTPS. Test the live URL with curl and verify the Django admin panel loads correctly with static assets from CloudFront.
5
CloudWatch Monitoring and Alarm Setup
Enable AWS X-Ray tracing on the Lambda function to get distributed request traces through API Gateway and into Lambda. Create CloudWatch alarms for Lambda error rate exceeding 1%, duration exceeding 10 seconds, and throttle count greater than zero. Configure a CloudWatch Dashboard to display invocation count, duration p50/p95/p99, and error rate on a single pane. Enable Lambda Insights for enhanced metrics including memory utilization and initialization duration.
6
Cold Start Mitigation and Production Hardening
Measure cold start latency by forcing Lambda initialization and checking CloudWatch Init Duration. Add a CloudWatch Events rule to ping your endpoint every 5 minutes to keep the Lambda warm. Configure Lambda Provisioned Concurrency for guaranteed warm instances under production load. Set keep_warm: true in zappa_settings.json. Deploy a staging update with zappa update dev and verify zero-downtime updates. Review total AWS costs for the serverless stack and compare against equivalent EC2 pricing.
