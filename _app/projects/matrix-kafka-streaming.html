Subject

Build a Streaming Data Pipeline

Journeyman 90 min 500 XP
Mission Brief

Batch processing is the past. Production data systems run on streams. This operation gets a full Apache Kafka cluster running locally via Docker Compose — a Zookeeper node plus three Kafka brokers — and walks you through the entire producer-consumer lifecycle from first message to multi-partition consumer group. You will write a Python producer using kafka-python that serializes JSON events and writes them to a topic with configurable partition routing. Then you will build a consumer that polls, deserializes, processes, and commits offsets explicitly.

The intermediate layer is stream processing. Using Kafka Streams concepts implemented in Python, you will build a stateless filter step that drops malformed events, a stateful windowed aggregation that counts events per 30-second tumbling window, and a sink writer that persists aggregated output to a PostgreSQL table. The pipeline runs continuously and handles backpressure without message loss.

The final deliverable is a live visualization dashboard that reads the aggregated output table and renders a real-time line chart refreshed every 5 seconds. This project solidifies the mental model of event-driven architecture: topics as durable logs, consumers as stateful readers, and the broker as the single source of truth that decouples producers from consumers completely.

Agent Requirements
  • Comfortable with Python: functions, classes, loops, and exception handling
  • Docker and Docker Compose installed; understand the concept of containers and services
  • Basic SQL familiarity: CREATE TABLE, INSERT, SELECT
  • Understand JSON serialization: json.dumps() and json.loads()
  • No prior Kafka experience required — all broker concepts are introduced from first principles

✓
1
Cluster Deployment with Docker Compose
Write a docker-compose.yml that provisions one Zookeeper container and three Kafka broker containers with internal listener configuration. Set KAFKA_OFFSETS_TOPIC_REPLICATION_FACTOR=3 and KAFKA_DEFAULT_REPLICATION_FACTOR=3. Verify the cluster with kafka-topics.sh --list from inside the broker container. Create a topic named events with 6 partitions and replication factor of 2.
Checkpoint: Kafka Setup
  • Start Zookeeper and Kafka broker and verify both are running with jps or docker ps
  • Create a test topic with kafka-topics.sh --create and verify it appears in the topic list
  • Produce a test message and consume it to verify end-to-end connectivity
✓
2
Producer Implementation
Implement a Python producer using KafkaProducer with a JSON value serializer set via value_serializer=lambda v: json.dumps(v).encode(). Generate synthetic clickstream events with a unique session_id as the partition key so all events from a session land on the same partition. Configure acks='all' and retries=5 for durable delivery guarantees.
✓
3
Consumer & Offset Management
Build a KafkaConsumer in a dedicated consumer group with enable_auto_commit=False and manual offset commits using consumer.commit() after each successful batch processing cycle. Handle partition rebalancing via the on_assign callback to log which partitions are assigned. Print each deserialized message with its partition number and offset for observability.
Checkpoint: Producer Implementation
  • Run your producer script and verify messages are published to the topic
  • Check the topic offset with kafka-consumer-groups.sh and confirm messages are accumulating
  • Verify the message serialization format (JSON, Avro, etc.) is correct
✓
4
Stream Processing: Filter, Aggregate, Sink
Build a three-stage processing loop: a filter step that drops any event missing required fields, a windowed counter that accumulates event counts per 30-second tumbling window using Python's collections.defaultdict, and a sink step that flushes completed windows to a PostgreSQL table via psycopg2. Flush triggers when the current event timestamp advances past the window boundary.
Checkpoint: Monitoring & Scaling
  • Verify Kafka metrics are accessible via JMX or a monitoring dashboard
  • Add a second partition and confirm messages are distributed across both
  • Test consumer group rebalancing by adding a second consumer instance
✓
5
Live Visualization Dashboard
Build a lightweight Python script using matplotlib.animation.FuncAnimation() that queries the PostgreSQL sink table every 5 seconds and re-renders a line chart of events-per-window over time. The chart updates in place without clearing the figure, giving a rolling 10-minute view of throughput. Add a horizontal threshold line at the 95th-percentile window count to visualize traffic spikes.
Checkpoint: Consumer & Processing
  • Start the consumer and verify it reads messages from the correct topic and partition
  • Process a batch of messages and confirm the output data is correct
  • Stop and restart the consumer and verify it resumes from the last committed offset
