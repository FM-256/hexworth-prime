Subject

Build an Arduino-Python Pipeline

Recruit 60 min 250 XP
Mission Brief

Your assignment is to build a working end-to-end sensor data pipeline: an Arduino Uno reads an analog sensor and streams raw values over USB serial every 500 milliseconds, a Python script on your computer opens that serial port, reads each line, prints it to the terminal, and simultaneously writes a timestamped row to a CSV file. When you finish, you will have a live-growing spreadsheet of hardware readings produced from real physical input.

This project is structured as a zero-knowledge walkthrough. Every phase shows you exactly which buttons to click, the exact code to paste, and the observable result you should see before moving on. Phase 1 begins with downloading the Arduino IDE from scratch — no prior Arduino or Python experience is assumed beyond being able to open a terminal.

The pattern you are building is called an ETL pipeline (Extract, Transform, Load): the Arduino extracts a physical measurement from the world and streams it over the serial link, Python transforms it by adding a timestamp and validating the number, and the CSV file is the load destination. This exact architecture appears in every industrial IoT system, compressed here into two scripts and a USB cable.

Agent Requirements
  • Arduino Uno (or compatible clone) plus its USB-B cable. This is the standard board included in every Arduino starter kit. An Arduino Mega or Nano will also work — the sketch is the same.
  • A potentiometer (any value, 10kΩ is typical) and 3 jumper wires. The potentiometer is included in every standard Arduino starter kit. Exact wiring is shown step-by-step in Phase 2.
  • Arduino IDE 2.x installed on your computer — download the free installer for your OS from arduino.cc/en/software. If you already have the older IDE 1.x, the steps below still apply but some menu locations differ slightly.
  • Python 3.x installed — run python --version or python3 --version in a terminal to check. If you see Python 3.x.x you are ready. If not, download the installer from python.org/downloads.
  • No paid accounts, no cloud services, no breadboard required for the basic wiring.

Install the Arduino IDE, Select Board and Port, Upload Blink
Before writing any sensor code you need to confirm the entire toolchain works end-to-end: IDE installed, board detected, code compiled, and uploaded. The standard test for this is the built-in Blink example — it makes the onboard LED flash. If Blink works, your setup is solid. If it does not, you find out now instead of after writing 50 lines of sketch code.
  1. Download and install the Arduino IDE 2.x. Open a browser and go to arduino.cc/en/software. Under the "Arduino IDE 2" section, click the download button for your operating system (Windows, macOS, or Linux). Run the installer and accept the defaults. When the installer asks whether to install USB drivers, click Yes — these are required for the board to appear as a serial port.
    Why Arduino IDE 2 specifically? Arduino IDE 2.x includes an integrated Serial Monitor, a port/board selector dropdown directly in the toolbar, and real-time error feedback. These are all visible at the top of the IDE window without navigating menus.
  2. Connect the Arduino Uno to your computer using the USB-B cable (the wide, square-ended connector goes into the board). The onboard power LED (labeled ON) should light up immediately. On Windows you may hear the "device connected" sound.
  3. Open the Arduino IDE. At the top of the IDE window you will see a toolbar. In the center of the toolbar is a dropdown that shows the board name and port, for example Select Board if nothing is selected yet. Click that dropdown.
    In Arduino IDE 2.x the board and port are combined into a single selector in the toolbar. You do not need to use the Tools menu at all for basic setup, though Tools > Board and Tools > Port still exist as an alternative route.
  4. Select your board and port. The dropdown will show detected boards. You should see an entry like Arduino Uno with a port name next to it (for example COM3 on Windows, /dev/cu.usbmodemXXXX on Mac, or /dev/ttyACM0 on Linux). Click that entry to select it. The toolbar dropdown now shows your board and port name.
    No board appears in the dropdown?
    • Confirm the USB cable is fully seated. Some USB-B cables are charge-only with no data wires — try a different cable if the board never appears.
    • On Linux, your user account may need permission to access the serial port. Run sudo usermod -aG dialout $USER and then log out and back in. After that, the port should be visible without sudo.
    • On Windows, if the port appears in Device Manager under "Other Devices" with a yellow warning icon, the USB driver did not install. Re-run the Arduino IDE installer and choose "Install USB Drivers" when prompted.
  5. Open the Blink example sketch. In the menu bar go to File > Examples > 01.Basics > Blink. A new editor window opens containing about 20 lines of code. This is the standard first-program for every Arduino.
    You do not need to understand the Blink code right now. Its only job is to confirm the toolchain works.
  6. Upload the sketch. In the toolbar, click the Upload button — it is the right-pointing arrow icon (the second button from the left, next to the checkmark Verify button). The IDE will compile the sketch (you will see "Compiling sketch..." at the bottom status bar) and then upload it to the board (you will see "Uploading..."). The orange TX/RX LEDs on the Uno will flicker rapidly during upload.
    The full upload sequence takes 5–15 seconds. When complete, the status bar shows Done uploading or Upload complete.
    Upload fails with "avrdude: stk500_recv(): programmer is not responding"?
    • The most common cause is the wrong board selected. Confirm the toolbar shows Arduino Uno, not Mega or Leonardo. Go to the board selector dropdown and reselect.
    • If you have another program that has the serial port open (including the Arduino IDE's own Serial Monitor from a previous session), close it first. A port can only be used by one program at a time.
Checkpoint — what you should see
After a successful upload, the small L LED on the Arduino Uno board (mounted next to pin 13) begins blinking on and off at a one-second interval: one second ON, one second OFF, repeating continuously. This confirms the IDE is installed correctly, the board was detected, the sketch compiled without errors, and the upload succeeded. If the LED blinks, you are fully set up. Move to Phase 2.

Wire the Potentiometer and Upload the Sensor Sketch
A potentiometer is a dial with three legs: a voltage reference leg, a ground leg, and a wiper leg whose voltage slides between the two as you turn the knob. Connecting the wiper to Arduino analog pin A0 lets analogRead(A0) measure where the knob is positioned. The value returned is a 10-bit integer from 0 (knob fully counterclockwise) to 1023 (knob fully clockwise). The sketch sends that number over serial once every 500 milliseconds.
  1. Wire the potentiometer. The potentiometer has three legs. Hold the potentiometer with the three legs pointing toward you and the knob or shaft facing away:
    • Left outer leg → connect with a jumper wire to the Arduino 5V pin (labeled "5V" on the board header)
    • Middle leg (wiper) → connect with a jumper wire to Arduino pin A0 (the analog input pins are labeled A0–A5 on the right side of the board)
    • Right outer leg → connect with a jumper wire to any Arduino GND pin (labeled "GND" on the board header; there are three, any one works)
    Which direction is "left" and "right"? It depends on how you orient the potentiometer. What matters is that one outer leg goes to 5V, the other outer leg goes to GND, and the middle leg goes to A0. Reversing the two outer legs just reverses the direction the knob reads — it does not damage anything.
    No potentiometer in your kit? You can skip the wiring entirely and leave A0 disconnected. A floating analog pin picks up ambient electrical noise and returns fluctuating numbers — typically values that jump around between 200 and 800. This is enough to verify the pipeline works, though the values will not be as clean or controllable as with the potentiometer.
  2. Open a new sketch in the Arduino IDE. Go to File > New Sketch (or press Ctrl+N on Windows/Linux, Cmd+N on Mac). A blank sketch opens with empty setup() and loop() functions.
  3. Replace the entire contents with the following sketch. Select all the existing text (Ctrl+A / Cmd+A) and paste this complete file:
    // sensor_pipeline.ino // Reads analog pin A0 and sends the value over serial once per 500ms. // Wire: potentiometer outer pins to 5V and GND, middle pin to A0. // analogRead(A0) returns 0-1023 (10-bit ADC, 0V=0, 5V=1023). void setup() { Serial.begin(9600); // Open serial at 9600 baud -- must match Python } void loop() { int sensorValue = analogRead(A0); // Read wiper voltage as 0-1023 Serial.println(sensorValue); // Send value + newline over USB delay(500); // Wait 500ms before next reading }
    What Serial.begin(9600) does: it initializes the hardware serial port at 9600 bits per second. The number 9600 is the baud rate — both the Arduino and Python must use the same value or every byte will be misread as garbage. 9600 is the standard starting baud rate for beginner projects. What Serial.println() does: it sends the integer as ASCII digits followed by a carriage-return and newline character (\r\n). Python's readline() uses the newline to know when one complete reading has arrived.
  4. Upload the sketch. Click the Upload arrow button. Wait for "Done uploading" in the status bar.
  5. Open the Serial Monitor to confirm values are flowing. Go to Tools > Serial Monitor (or click the magnifying-glass icon in the top-right of the Arduino IDE toolbar). At the bottom of the Serial Monitor window there is a baud rate dropdown — set it to 9600 to match Serial.begin(9600) in the sketch.
    If the baud rate does not match, the Serial Monitor shows garbled characters or nothing. Always confirm the Serial Monitor baud rate matches the sketch.
  6. Turn the potentiometer knob. You should see numbers scrolling in the Serial Monitor, one per line, approximately twice per second. Turning the knob all the way left should produce values near 0; all the way right should produce values near 1023; the middle position produces values near 512.
    The exact values at the extremes depend on your potentiometer and wiring. Values within a few digits of 0 and 1023 are normal — you do not need to reach exactly 0 or exactly 1023.
Serial Monitor shows only question marks or garbage characters? The baud rate in the Serial Monitor does not match Serial.begin(9600). Click the baud rate dropdown at the bottom of the Serial Monitor and select 9600. If the output is still garbled, re-upload the sketch to reset the serial state.
Serial Monitor shows nothing at all?
  • Confirm the sketch uploaded successfully (the status bar said "Done uploading").
  • Confirm the Serial Monitor baud rate is set to 9600.
  • Try pressing the Reset button on the Arduino board (the small button near the USB connector). This restarts the sketch from the beginning.
Checkpoint — what you should see
The Serial Monitor shows a stream of numbers scrolling at roughly 2 lines per second. The numbers change when you turn the potentiometer knob. Values range from near 0 to near 1023. Before moving to Phase 3, close the Serial Monitor. The serial port can only be held open by one program at a time. If the Serial Monitor is still open when Python tries to connect, Python will throw an error. Close it with the X button in the Serial Monitor tab, or close the entire Serial Monitor window.

Install pyserial and Read the Serial Port from Python
With the Arduino transmitting numbers, the next step is to receive them in Python. The pyserial library (version 3.5, available on PyPI) gives Python the ability to open a serial port, read lines, and close the connection cleanly. This phase writes a minimal Python script that opens the port, reads each line as it arrives, decodes it from bytes to a string, and prints it to the terminal. The observable result is the same numbers that were appearing in the Serial Monitor now appearing in your Python terminal instead.
Critical trap — port conflict. The Arduino IDE Serial Monitor and the Python script cannot both have the port open at the same time. The operating system only allows one program to hold a serial port open. If the Serial Monitor is still open when you run the Python script, Python will raise serial.SerialException: could not open port ... Access is denied (Windows) or ... [Errno 16] Device or resource busy (Linux/Mac). The fix is always the same: close the Serial Monitor before running any Python script. Go back to the Arduino IDE and close the Serial Monitor tab, then run Python.
  1. Confirm Python is installed. Open a terminal (Windows: search for "Command Prompt" or "PowerShell"; Mac: open Terminal from Applications/Utilities; Linux: open your shell). Run:
    python --version
    You should see output like Python 3.12.3. If you see command not found, try python3 --version instead — on Mac and Linux the command is often python3 rather than python.
    All commands in the remaining phases that show python should be replaced with python3 if that is the command that worked on your system.
  2. Install pyserial. In the same terminal, run:
    pip install pyserial
    You will see a progress bar and then a line like Successfully installed pyserial-3.5.
    pip command not found? Try pip3 install pyserial or python -m pip install pyserial. On some systems pip is only accessible as pip3 when Python is installed as python3.
    Permission error on Mac or Linux? Do not use sudo pip install. Instead, add the --user flag: pip install --user pyserial. This installs the package into your home directory, which you always have permission to write to.
  3. Find your serial port name. You need the exact port name to give to Python. The easiest way is to look in the Arduino IDE — the board selector dropdown in the toolbar shows the port name next to the board name. Common values:
    • Windows: COM3, COM4, COM5 (the exact number varies per machine)
    • Mac: /dev/cu.usbmodemXXXX where XXXX is a number (e.g. /dev/cu.usbmodem14101)
    • Linux: /dev/ttyACM0 or /dev/ttyUSB0 (ACM0 is most common for genuine Arduino boards)
    Not sure which port is which on Windows? Open Device Manager (right-click Start > Device Manager), expand "Ports (COM & LPT)", and look for "Arduino Uno (COMx)". The number in parentheses is your port.
    Not sure on Mac? In a terminal run ls /dev/cu.* with the Arduino unplugged, then run it again with the Arduino plugged in. The new entry that appears is your port.
  4. Create a new Python file. Open any text editor (VS Code, Notepad, TextEdit on Mac, or nano in the terminal). Create a new file and save it as reader.py in a convenient location such as your Desktop or a new project folder.
  5. Paste this complete script. Replace COM3 in the PORT line with your actual port name from Step 3:
    """ reader.py Minimal serial reader -- opens the Arduino's port and prints each line. IMPORTANT: Close the Arduino IDE Serial Monitor before running this script. """ import serial PORT = 'COM3' # <-- Replace with your port: COM3, /dev/ttyACM0, etc. BAUD = 9600 # Must match Serial.begin(9600) in the Arduino sketch ser = serial.Serial(PORT, BAUD, timeout=1) print(f"Opened {PORT} at {BAUD} baud. Press Ctrl+C to stop.\n") try: while True: raw = ser.readline() # Returns bytes; blocks up to timeout=1s line = raw.decode('utf-8').strip() # Decode bytes to string, remove \r\n if line: # Skip blank lines (timeout returns b'') print(line) except KeyboardInterrupt: print("\nStopped by user.") finally: ser.close() print("Port closed.")
    What each line does: serial.Serial(PORT, BAUD, timeout=1) opens the port at 9600 baud with a 1-second read timeout. The timeout ensures readline() returns an empty bytes object b'' rather than blocking forever if no newline arrives within 1 second. raw.decode('utf-8').strip() converts the bytes the Arduino sent into a Python string and removes the trailing \r\n. The finally block ensures ser.close() always runs, even if an error occurs, so the port is released cleanly.
  6. Run the script. In your terminal, navigate to where you saved reader.py and run:
    python reader.py
    The terminal will print one number per line, twice per second, identical to what was showing in the Serial Monitor. Turn the potentiometer knob and the numbers change. Press Ctrl+C to stop cleanly.
Python prints "could not open port COM3: Access is denied" (Windows) or "Device or resource busy" (Linux/Mac)? The Arduino IDE Serial Monitor is still open. Go to the Arduino IDE, find the Serial Monitor tab, and close it. Then run the Python script again. This is the most common error beginners hit in this project.
Python prints "could not open port COM3: [Errno 2] No such file or directory"?
  • The port name is wrong. Double-check your port in the Arduino IDE board selector and update the PORT line in reader.py.
  • On Linux, also try /dev/ttyUSB0 if /dev/ttyACM0 does not work.
Python prints garbled characters or question marks? The baud rate in reader.py does not match Serial.begin(9600) in the sketch. Confirm both say 9600.
Checkpoint — what you should see
The terminal shows a new integer on each line, arriving about twice per second, like this:
Opened COM3 at 9600 baud. Press Ctrl+C to stop.
512
498
703
1023
Turning the potentiometer knob changes the numbers. Pressing Ctrl+C prints "Stopped by user." and "Port closed." and returns you to the terminal prompt. If you see this, the hardware-to-Python link is working. Move to Phase 4.

4
Log Every Reading to a CSV File with Timestamps
The Phase 3 script prints readings to the screen but discards them when you stop it. This phase extends the script to simultaneously write each reading — with a timestamp — to a CSV file. When you are done, opening sensor_log.csv in any spreadsheet application will show two columns: a timestamp and the sensor value. The file grows by one row every 500 milliseconds for as long as the script runs.
  1. Create a new file called logger.py in the same folder as reader.py. This is the complete, final script. Paste it in full, replacing COM3 with your port:
    """ logger.py Reads Arduino sensor values from USB serial and writes timestamped rows to sensor_log.csv. Press Ctrl+C to stop cleanly. IMPORTANT: Close the Arduino IDE Serial Monitor before running this script. Port can only be held open by one program at a time. """ import serial import csv import datetime PORT = 'COM3' # <-- Replace with your port name BAUD = 9600 # Must match Serial.begin(9600) in the sketch CSV_FILE = 'sensor_log.csv' # Created in the same folder as this script def main(): ser = serial.Serial(PORT, BAUD, timeout=1) print(f"Opened {PORT} at {BAUD} baud.") print(f"Logging to: {CSV_FILE}") print("Press Ctrl+C to stop.\n") # Open CSV file for appending (newline='' required by csv module on Windows) with open(CSV_FILE, 'a', newline='') as csvfile: writer = csv.writer(csvfile) # Write header row only if the file is new (size == 0) csvfile.seek(0, 2) # Seek to end to check file size if csvfile.tell() == 0: writer.writerow(['timestamp', 'sensor_value']) row_count = 0 try: while True: raw = ser.readline() # bytes, up to 1s timeout line = raw.decode('utf-8').strip() # string, no \r\n if not line: # Skip blank/timeout lines continue try: value = int(line) # Validate: must be an integer except ValueError: print(f" [skip] non-integer line: {repr(line)}") continue timestamp = datetime.datetime.now().strftime('%Y-%m-%d %H:%M:%S.%f')[:-3] writer.writerow([timestamp, value]) csvfile.flush() # Write to disk immediately row_count += 1 print(f" {timestamp} {value:>5} (row {row_count})") except KeyboardInterrupt: print(f"\nStopped by user. {row_count} rows written to {CSV_FILE}.") finally: ser.close() print("Port closed.") if __name__ == '__main__': main()
    Key decisions in this script: open(CSV_FILE, 'a', newline='') opens in append mode so you can run the script multiple times and accumulate data rather than overwriting previous sessions. The newline='' argument is required by the Python csv module on all platforms — the csv module handles its own line endings; without this flag Windows adds an extra blank line between every row. csvfile.flush() after each row forces the data to disk immediately so the file is readable even while the script is running. The try/except ValueError block skips any line that is not a plain integer (for example a partial line captured during Arduino startup) without crashing the script.
  2. Confirm the Arduino IDE Serial Monitor is closed, then run the logger:
    python logger.py
  3. Let it run for at least 30 seconds. You should see timestamped rows scrolling in the terminal. Turn the potentiometer knob and watch the values in the right column change.
  4. Press Ctrl+C to stop. The script prints the row count and closes the port.
  5. Open sensor_log.csv in any spreadsheet (Excel, LibreOffice Calc, Google Sheets). The file should have a header row and one data row per reading, with timestamps in the first column and sensor values in the second.
CSV opens in Excel and all data is in one column? Excel is using the wrong delimiter. In Excel, use Data > From Text/CSV and select comma as the delimiter, or open the file in LibreOffice Calc which auto-detects CSV format.
Every other row in Excel is blank? You opened the file with newline='' missing from the open() call. The csv module added an extra \r, which Windows interprets as a blank row. Confirm the open() call in your script includes newline='' exactly as shown above.
Script crashes immediately with "could not open port"? The Serial Monitor is still open in the Arduino IDE. Close it and run the script again.
Checkpoint — what you should see
The terminal shows timestamped rows like 2026-06-18 10:01:32.447 512 (row 1). After stopping with Ctrl+C, opening sensor_log.csv in a spreadsheet shows a header row (timestamp,sensor_value) followed by one row per reading. The timestamp column shows real wall-clock times. The sensor_value column shows integers 0–1023 that changed as you turned the knob. This is a complete, persistent hardware data log.

Harden the Pipeline — Graceful Shutdown, Error Handling, Port Discovery
The Phase 4 logger already handles the most common errors, but real pipelines need a few more protections: a startup delay for the Arduino's bootloader reset, automatic port discovery so you are not hardcoding COM3, and a clear summary printed on exit. This phase adds all three to produce the final version of the script.
  1. Understand the Arduino bootloader reset. Every time Python opens the serial port, the Arduino Uno resets automatically — the same as pressing the physical Reset button. The bootloader runs for about 2 seconds before your sketch starts. During that 2-second window, the Arduino transmits nothing. If Python starts reading immediately, it will get empty lines or bootloader noise. The fix is a brief pause after opening the port.
    This is why you sometimes see garbage characters in the first few lines when a script connects. Adding time.sleep(2) after serial.Serial() allows the board to complete its reset before Python starts reading.
  2. Create the final version of the script. Save this as pipeline.py — this is the complete, hardened pipeline. Replace COM3 only if auto-detection fails on your machine:
    """ pipeline.py -- Final hardened Arduino-Python pipeline Reads analog sensor values from a potentiometer on A0 and writes timestamped CSV rows. Includes: bootloader reset delay, auto port discovery, graceful Ctrl+C shutdown, and per-line error recovery. IMPORTANT: Close the Arduino IDE Serial Monitor before running this script. """ import serial import serial.tools.list_ports import csv import datetime import time BAUD = 9600 CSV_FILE = 'sensor_log.csv' RESET_DELAY = 2 # seconds to wait for Arduino bootloader after connect def find_arduino_port(): """Return the first serial port that looks like an Arduino, or None.""" ports = serial.tools.list_ports.comports() for p in ports: desc = (p.description or '').lower() mfr = (p.manufacturer or '').lower() if 'arduino' in desc or 'arduino' in mfr or 'ch340' in desc: return p.device return None def main(): # -- Port discovery --------------------------------------------------- port = find_arduino_port() if port is None: print("Auto-detection failed. Common port names:") print(" Windows: COM3, COM4, COM5 ...") print(" Mac: /dev/cu.usbmodemXXXX") print(" Linux: /dev/ttyACM0 or /dev/ttyUSB0") port = input("Enter your port name: ").strip() print(f"Connecting to {port} at {BAUD} baud...") ser = serial.Serial(port, BAUD, timeout=1) # -- Bootloader reset delay ------------------------------------------- print(f"Waiting {RESET_DELAY}s for Arduino to finish resetting...") time.sleep(RESET_DELAY) ser.reset_input_buffer() # Discard any bootloader noise print("Ready.\n") # -- Open CSV --------------------------------------------------------- with open(CSV_FILE, 'a', newline='') as csvfile: writer = csv.writer(csvfile) # Write header only if file is new csvfile.seek(0, 2) if csvfile.tell() == 0: writer.writerow(['timestamp', 'sensor_value']) row_count = 0 err_count = 0 print(f"Logging to {CSV_FILE}. Press Ctrl+C to stop.\n") try: while True: raw = ser.readline() line = raw.decode('utf-8', errors='replace').strip() if not line: continue # Timeout -- no data this second, keep waiting try: value = int(line) except ValueError: err_count += 1 if err_count <= 5: # Log first 5 errors, then silence print(f" [skip] bad line ({err_count}): {repr(line)}") continue ts = datetime.datetime.now().strftime('%Y-%m-%d %H:%M:%S.%f')[:-3] writer.writerow([ts, value]) csvfile.flush() row_count += 1 print(f" {ts} {value:>5} (row {row_count})") except KeyboardInterrupt: pass # Clean exit -- handled in finally finally: ser.close() print(f"\n--- Session complete ---") print(f"Rows written : {row_count}") print(f"Lines skipped: {err_count}") print(f"File : {CSV_FILE}") print("Port closed.") if __name__ == '__main__': main()
    What is new in this version: serial.tools.list_ports.comports() returns all detected serial ports with their descriptions. The find_arduino_port() function checks each port's description and manufacturer string for the word "arduino" or "ch340" (a common USB chip in Arduino clones) and returns the first match. ser.reset_input_buffer() discards any bytes that arrived during the reset delay so the first real reading is clean. decode('utf-8', errors='replace') substitutes a Unicode replacement character for any byte that is not valid UTF-8, preventing a crash if bootloader output slips through.
  3. Run the final pipeline:
    python pipeline.py
    If auto-detection works you will see Connecting to COM3 at 9600 baud... (or your actual port) immediately. If it fails, you will be prompted to type the port name manually.
  4. Let it run for a minute, turn the knob through its full range, then press Ctrl+C. The session summary shows how many rows were written and how many lines were skipped.
  5. Open sensor_log.csv in a spreadsheet. If you ran the Phase 4 script first, you will see those rows followed by the Phase 5 rows — the file accumulates across sessions because both scripts use append mode.
Auto-detection finds the wrong port (a Bluetooth device, for example)? The function returns the first match. If you have multiple serial devices, it may pick the wrong one. In that case, set the port manually: edit the line port = find_arduino_port() and replace the function call with your port string in quotes, for example port = 'COM5'.
Script hangs on "Waiting 2s for Arduino to finish resetting..." and never proceeds? The port opened successfully but no data is arriving. The clearest symptom that the wrong sketch is loaded is that the Serial Monitor shows no scrolling numbers, or the values do not change when you turn the knob. If that is what you see, re-upload sensor_pipeline.ino from Phase 2, then close the Serial Monitor and run the script again. Also confirm the Arduino is still connected by USB.
Checkpoint — the complete pipeline test
Run through this test from top to bottom: (1) Upload sensor_pipeline.ino to the Arduino and confirm numbers appear in the Serial Monitor. (2) Close the Serial Monitor. (3) Run python pipeline.py and confirm timestamped rows scroll in the terminal. (4) Turn the potentiometer knob and confirm the values in the right column change. (5) Press Ctrl+C and read the session summary. (6) Open sensor_log.csv in a spreadsheet and confirm it has a header row and data rows with real timestamps. If all six steps pass, you have built and shipped a complete hardware-to-spreadsheet data pipeline.
