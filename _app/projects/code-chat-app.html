Subject

Build a Real-Time Multi-User Chat App

Operative 90 min 500 XP
Mission Brief

Your assignment is to build a working real-time multi-user chat application using Node.js, Express 5, and Socket.IO v4. When you finish, two or more browser tabs open at http://localhost:3000 will exchange messages instantly — no page reload, no polling. You type in one tab, press Enter, and the message appears in every other tab within milliseconds. That is the WebSocket model in action.

This project is structured as a zero-knowledge walkthrough. Every phase shows the exact files to create, the exact code to paste, the terminal commands to run, and the observable result that confirms you are on track before moving on. You do not need prior Node.js experience — Phase 1 starts from installing Node.js and covers every command.

By the end you will understand the architectural difference between HTTP (request → response, then the connection closes) and WebSockets (a persistent two-way channel that stays open). You will know how io.emit fans a message out to every connected client, why Socket.IO wraps the raw WebSocket protocol, and how the same Node.js process serves both the static HTML page and the live socket connection on port 3000.

Agent Requirements
  • Node.js LTS v24.x installed — download the LTS installer from nodejs.org/en/download (the green “LTS” button). After installing, open a terminal and run node --version and npm --version to confirm both are present. Express 5 requires Node 18 or higher.
  • A terminal (Windows: PowerShell or Command Prompt; Mac: Terminal; Linux: any shell). Every command in this project is shown exactly as you type it.
  • VS Code (code.visualstudio.com) as a code editor — any plain-text editor works, but VS Code gives you syntax highlighting that makes the code easier to read.
  • A modern browser (Chrome, Edge, or Firefox). You will open two tabs side-by-side to see real-time sync in Phase 5.
  • No paid accounts, no cloud services, no database — the entire project runs on your laptop.

Create the Project Folder and Install Dependencies
Before any code you need a project folder, a package.json that describes your app, and two installed packages: express (the web server) and socket.io (the real-time layer). npm handles all of this. At the end of this phase you will verify that both packages installed correctly by checking the version they report.
  1. Verify Node.js is installed. Open your terminal and run both commands. You need Node 18 or higher; v24.x is current LTS:
    node --version npm --version
    Expected output looks like v24.17.0 and 10.x.x. If you see command not found, download and run the LTS installer from nodejs.org/en/download, then restart your terminal and try again.
  2. Create your project folder. Choose a location (your Desktop is fine). Run these two commands — the first creates the folder, the second moves you into it:
    mkdir my-chat-app cd my-chat-app
    Windows note: If you are in PowerShell or Command Prompt, mkdir and cd work exactly the same way.
  3. Initialize the project. The -y flag accepts all defaults so npm does not ask you questions:
    npm init -y
    npm creates a file called package.json in your folder. This file tracks your project name, version, and the packages it depends on. You do not need to edit it manually.
  4. Install Express and Socket.IO. This one command installs both packages and records them in package.json:
    npm install express socket.io
    npm downloads the packages into a new node_modules/ folder. This may take 20–40 seconds on a typical connection. You will see a progress bar and then a summary line like added 82 packages. The exact count varies.
  5. Confirm versions. Run this command to see the exact versions that were installed:
    node -e "console.log('express:', require('./node_modules/express/package.json').version, '| socket.io:', require('./node_modules/socket.io/package.json').version)"
    Expected output: express: 5.x.x | socket.io: 4.x.x. If you see a 4.x Express or a 3.x Socket.IO, that is fine — the code in this project works with Express 4 or 5 and Socket.IO 4. The APIs used here are stable across those versions.
  6. Open the project in VS Code. Run:
    code .
    The . means “open the current folder”. If VS Code is not in your PATH (common on Mac after a fresh install), open VS Code manually, then go to File → Open Folder… and navigate to my-chat-app.
npm install fails with ENOENT: no such file or directory?

  • Confirm your terminal is still inside the my-chat-app folder. Run pwd (Mac/Linux) or cd with no arguments (Windows) to print your current directory.
npm install fails with EACCES: permission denied on Mac or Linux? Do not use sudo npm install — that can corrupt your npm setup. Instead, fix the npm prefix ownership by following the guide at docs.npmjs.com/resolving-eacces-permissions-errors-when-installing-packages-globally.

2
Minimal Express Server Serving a Static Page
Before adding Socket.IO, you will confirm that Node.js + Express can start a web server, serve a file, and respond to your browser. This phase creates two files: server.js (the Node.js process) and public/index.html (the page the browser downloads). The goal is a working “Hello” in the browser at http://localhost:3000 — nothing more.
Why a public/ folder? Express has a built-in function called express.static() that serves every file inside a named folder as a downloadable URL. Putting index.html in public/ means the browser can fetch it at / without writing an explicit route handler for it. This is the standard pattern for serving frontend files from a Node.js server.
  1. Create the public folder. In your terminal (still inside my-chat-app):
    mkdir public
  2. Create public/index.html. In VS Code, click the public folder in the left panel, then click the New File icon (a page with a +). Name it index.html. Paste this complete file:
    <!DOCTYPE html> <html lang="en"> <head> <meta charset="UTF-8"> <meta name="viewport" content="width=device-width, initial-scale=1.0"> <title>Chat App</title> </head> <body> <h1>Hello from the chat server</h1> <p>Socket.IO wiring comes in Phase 3.</p> </body> </html>
    Save the file with Ctrl+S (Mac: Cmd+S).
  3. Create server.js at the root of your project. In VS Code, click on the my-chat-app folder name (not inside public) and create a new file named server.js. Paste this complete file:
    // server.js // Verified against expressjs.com/en/5x/starter/hello-world.html // and expressjs.com/en/5x/starter/static-files.html const express = require('express'); const { createServer } = require('node:http'); const { join } = require('node:path'); const app = express(); const server = createServer(app); // Serve every file in the public/ folder as a static URL. // index.html becomes available at http://localhost:3000/ app.use(express.static(join(__dirname, 'public'))); const PORT = 3000; server.listen(PORT, () => { console.log('Server running at http://localhost:' + PORT); });
    Why createServer(app) instead of just app.listen()? Socket.IO (Phase 3) needs access to the raw Node.js HTTP server object to attach its WebSocket upgrade handler. createServer(app) creates that object and passes the Express app as its request handler. app.listen() creates an HTTP server internally but does not expose it — Socket.IO cannot hook into it. This is the pattern shown in the official Socket.IO v4 documentation.
  4. Start the server. In your terminal:
    node server.js
    Expected terminal output: Server running at http://localhost:3000. The terminal cursor does not return to the prompt — that is correct. The server is running and listening for requests. To stop it press Ctrl+C.
  5. Open the browser and navigate to:
    http://localhost:3000
    You should see the heading Hello from the chat server and the paragraph below it.
Terminal shows Error: Cannot find module 'express'?
  • You ran node server.js from the wrong folder. The node_modules/ folder must be in the same directory as server.js. In your terminal, run ls (Mac/Linux) or dir (Windows). You should see node_modules, package.json, and server.js all listed. If not, use cd to navigate back to my-chat-app.
Browser shows “This site can’t be reached” or “Connection refused”?
  • The server is not running. Go back to the terminal — did you see Server running at http://localhost:3000? If the server exited with an error, read the error message and compare it against your server.js line by line.
  • Make sure you typed http://localhost:3000 exactly, not https:// (no S) and not port 8080.
Browser shows a blank white page (no heading)?
  • The file is in the wrong place. index.html must be inside the public/ folder, not at the root next to server.js. Your folder structure should look like: my-chat-app/public/index.html.
  • After moving the file, stop the server (Ctrl+C) and restart it (node server.js), then refresh the browser.
Checkpoint — what you should see
The browser at http://localhost:3000 shows the heading Hello from the chat server. The terminal shows Server running at http://localhost:3000 and stays active (no prompt returned). Your project now has: server.js, package.json, package-lock.json, node_modules/, and public/index.html. Stop the server with Ctrl+C before moving to Phase 3.

3
Wire Socket.IO — Log “a user connected”
This phase adds Socket.IO to both sides of the connection: the server learns to accept WebSocket connections and log them, and the browser page loads the Socket.IO client script and calls io() to open the connection. The observable result is a terminal message every time a browser tab connects or disconnects.
How Socket.IO serves its own client script. When you initialize Socket.IO on the server, it automatically registers a route at /socket.io/socket.io.js that serves the client-side library. You do not need to install anything on the browser side or use a CDN — the script comes from your own server. The <script src="/socket.io/socket.io.js"></script> tag in your HTML fetches it from there.
  1. Replace the entire contents of server.js with this updated version. It adds Socket.IO to the existing Express setup without changing the static-file serving:
    // server.js // Socket.IO v4 API verified against socket.io/docs/v4/ // Pattern: createServer(app) -> new Server(server) -> server.listen() const express = require('express'); const { createServer } = require('node:http'); const { join } = require('node:path'); const { Server } = require('socket.io'); const app = express(); const server = createServer(app); // Attach Socket.IO to the HTTP server. // Socket.IO now intercepts WebSocket upgrade requests on the same port. const io = new Server(server); // Serve the frontend from public/ app.use(express.static(join(__dirname, 'public'))); // io.on('connection') fires every time a new browser tab connects. // The 'socket' argument represents that one individual connection. io.on('connection', (socket) => { console.log('a user connected socket.id:', socket.id); // 'disconnect' fires when that tab closes or navigates away. socket.on('disconnect', () => { console.log('user disconnected socket.id:', socket.id); }); }); const PORT = 3000; server.listen(PORT, () => { console.log('Server running at http://localhost:' + PORT); });
  2. Update public/index.html to load the Socket.IO client and open the connection. Replace the entire file:
    <!DOCTYPE html> <html lang="en"> <head> <meta charset="UTF-8"> <meta name="viewport" content="width=device-width, initial-scale=1.0"> <title>Chat App</title> </head> <body> <h1>Chat App</h1> <p id="status">Connecting...</p> <!-- Socket.IO client script is served automatically by the Socket.IO server. --> <!-- No CDN needed. The server registers /socket.io/socket.io.js itself. --> <script src="/socket.io/socket.io.js"></script> <script> // io() connects to the same host and port that served this HTML page. // No URL argument needed when connecting back to the same origin. const socket = io(); socket.on('connect', () => { document.getElementById('status').textContent = 'Connected. My socket ID: ' + socket.id; }); socket.on('disconnect', () => { document.getElementById('status').textContent = 'Disconnected.'; }); </script> </body> </html>
  3. Restart the server. In your terminal, press Ctrl+C to stop the running server, then start it again:
    node server.js
    You must restart the server after every change to server.js. Changes to files inside public/ (HTML, CSS, JS) take effect on browser refresh with no restart needed.
  4. Open http://localhost:3000 in your browser. The page should show your socket ID. Switch to the terminal — you should see a line like:
    a user connected socket.id: abc123XYZ
  5. Test disconnect. Close the browser tab. The terminal should immediately print:
    user disconnected socket.id: abc123XYZ
Page shows “Connecting...” and never updates?
  • Open browser DevTools (right-click the page → Inspect → Console tab). Look for a red error. A common one is GET /socket.io/socket.io.js 404 — this means Socket.IO was not initialized on the server. Confirm your server.js contains const { Server } = require('socket.io') and const io = new Server(server) before server.listen().
  • Confirm you restarted the server after editing server.js. The old process does not pick up changes automatically.
Terminal shows Error: Cannot find module 'socket.io'? The package was not installed. Stop the server, run npm install socket.io, then restart.
Checkpoint — what you should see
The browser page shows a socket ID (a string of random characters). Every time you open a new tab to http://localhost:3000, a new “a user connected” line appears in the terminal with a different ID. Closing the tab produces a matching “user disconnected” line. The WebSocket pipeline is live. No messages are sent yet — that is Phase 4.

4
Send and Broadcast Chat Messages
The socket connection is live but no messages travel through it. This phase adds: a text input + Send button to the HTML page, a socket.emit('chat message', text) call when the user submits, a socket.on('chat message') listener on the server that broadcasts the message back out with io.emit(), and a socket.on('chat message') listener on the client that appends each incoming message to a list. When Phase 4 is done, sending in one tab shows the message in the same tab — the two-tab multi-user demo comes in Phase 5.
io.emit() vs socket.broadcast.emit(). io.emit('chat message', msg) sends the event to every connected socket, including the sender. socket.broadcast.emit('chat message', msg) sends to everyone except the sender. The official Socket.IO tutorial uses io.emit() for simplicity — the sender sees their own message arrive via the broadcast just like everyone else. This project uses the same approach.
  1. Replace server.js with this complete version. The only addition is the socket.on('chat message') handler that calls io.emit():
    // server.js const express = require('express'); const { createServer } = require('node:http'); const { join } = require('node:path'); const { Server } = require('socket.io'); const app = express(); const server = createServer(app); const io = new Server(server); app.use(express.static(join(__dirname, 'public'))); io.on('connection', (socket) => { console.log('a user connected socket.id:', socket.id); // Listen for a 'chat message' event from this socket. // msg is whatever string the client passed to socket.emit(). socket.on('chat message', (msg) => { console.log('message received:', msg); // io.emit() sends the event to ALL connected sockets, // including the socket that sent this message. // Verified: socket.io/docs/v4/tutorial/step-5 io.emit('chat message', msg); }); socket.on('disconnect', () => { console.log('user disconnected socket.id:', socket.id); }); }); const PORT = 3000; server.listen(PORT, () => { console.log('Server running at http://localhost:' + PORT); });

  4. Send a test message. Type hello world in the input and click Send. The message should appear immediately in the list below the input. Check the terminal — you should see:
    message received: hello world
Clicking Send does nothing and there is no terminal output?
  • Open browser DevTools Console. A socket is not defined error means the Socket.IO client script did not load. Confirm the <script src="/socket.io/socket.io.js"></script> line is present in your HTML before the second <script> block. Order matters — you must load the library before using it.
  • A form is null error means the script ran before the HTML was parsed. Confirm both <script> tags are inside <body>, not in <head>.
You type a message, click Send, and nothing appears anywhere — no new line in the chat list AND no “message received” in the terminal? The event name in socket.emit() on the client does not exactly match the event name in socket.on() on the server. Event names are case- and spelling-sensitive strings: 'chat message' and 'Chat Message' are two different events. The server listens for the one it was given; if the client emits a different string, the server never fires its handler, so nothing reaches the list and nothing prints in the terminal. Open both files and confirm both sides say exactly 'chat message'.
Checkpoint — what you should see
You type a message, click Send, and it appears immediately in the message list. The terminal shows message received: <your text>. The input field clears after sending. Sending multiple messages builds a scrollable list. The multi-user test — where a second browser tab sees the messages — is Phase 5.

5
The Multi-User Win — Two Tabs, One Room, Live Sync
The server code from Phase 4 already broadcasts to all connected sockets — io.emit() fans the message out to everyone. This phase confirms that the multi-user model works by opening a second tab and observing real-time sync. Then it adds optional username support so each message identifies its sender, and covers the four classic beginner traps in a single consolidated troubleshooting block.
Why it already works. io.emit('chat message', msg) inside io.on('connection') sends to every socket in the io namespace, which is every connected client. When Tab A sends a message, the server receives it and immediately emits it back to Tab A and Tab B. Each tab’s socket.on('chat message') handler appends the message to its own list. No changes to server.js are needed for multi-user to work.

    node server.js
  2. Open two browser tabs side by side, both pointing to http://localhost:3000. The terminal will show two “a user connected” lines with different socket IDs.
  3. Type a message in Tab A and press Send. The message should appear in both Tab A and Tab B simultaneously. Then type in Tab B — both tabs receive it. That is the real-time multi-user loop working correctly.

Classic trap 1 — EADDRINUSE: address already in use :::3000. Another process is already using port 3000. This usually means a previous node server.js is still running in another terminal window.
  • Easiest fix (recommended for beginners): change const PORT = 3000 in server.js to any unused number like 3001, save the file, restart the server, and navigate to http://localhost:3001. No need to hunt for another process.
  • Mac/Linux (kill the process): lsof -ti:3000 | xargs kill then restart.
  • Windows PowerShell (kill the process): Run netstat -ano | findstr :3000. The PID is the number in the last (rightmost) column. There may be more than one row (one for IPv4, one for IPv6) — they will share the same PID. Run taskkill /PID <pid> /F with that number, then restart the server.
Classic trap 2 — forgot to load the Socket.IO client script. The browser console shows io is not defined. The <script src="/socket.io/socket.io.js"></script> line must appear in your HTML before any code that calls io(). It must also be exactly /socket.io/socket.io.js (served by your Node server) — not a CDN URL and not a local file path.
Classic trap 3 — CORS error in the browser console. Access to XMLHttpRequest blocked by CORS policy appears when the browser and the server are on different origins. This should not happen when both are on localhost:3000. If you accidentally opened the HTML file directly from the filesystem (file:///) instead of from http://localhost:3000, the origin will not match. Always open the app by navigating to http://localhost:3000 in the browser — never by double-clicking the HTML file.
Classic trap 4 — edited server.js but forgot to restart Node. Node.js reads your file once at startup. It does not watch for changes. After every edit to server.js, you must press Ctrl+C in the terminal and then run node server.js again. If you want automatic restarts during development, install nodemon with npm install --save-dev nodemon and run npx nodemon server.js instead.
Checkpoint — the complete multi-user test
Run through this test from top to bottom: (1) Start the server with node server.js. (2) Open http://localhost:3000 in Tab A, enter username Alice. (3) Open a second tab to the same URL, enter username Bob. The terminal shows two “a user connected” lines. (4) Alice types Hello Bob! and clicks Send. The message appears in both Tab A and Tab B, labeled Alice with a timestamp. (5) Bob replies. Both tabs show the exchange. (6) Close Tab B. The terminal shows “user disconnected” for Bob’s socket ID. If all six steps pass, your real-time multi-user chat application is complete and fully functional.
