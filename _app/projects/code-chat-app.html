Subject

Build a Real-Time Chat App

Journeyman 90 min 500 XP
Mission Brief

Your assignment is to build a real-time chat application using WebSockets via Socket.IO, a Node.js backend powered by Express, and a responsive frontend served from the same server. Users can register, authenticate, join named chat rooms, and exchange messages that appear on all connected clients within milliseconds — no page refresh required.

Message history is persisted in SQLite via the better-sqlite3 driver. When a new user joins a room, the server replays the last 50 messages so they have context before they start typing. User sessions are managed with express-session and bcrypt-hashed passwords are stored alongside usernames in the database.

This project builds fluency with the WebSocket protocol, the Socket.IO event model, server-side session management, and the architectural separation between HTTP (auth, page delivery) and the persistent WebSocket channel (real-time messaging). It mirrors the stack behind production chat systems at scale.

Agent Requirements

  • Express routing: app.get, app.post, middleware, and req.session
  • Basic understanding of the HTTP request/response cycle and status codes
  • Familiarity with HTML forms, fetch API, and DOM manipulation
  • Comfort with asynchronous JavaScript: callbacks, Promises, or async/await
  • Basic SQL: CREATE TABLE, INSERT, SELECT, WHERE
Operation Phases
1
Project Scaffold and Express Server
Initialize the project with npm init and install express, socket.io, better-sqlite3, express-session, and bcrypt. Create server.js as the entry point. Configure Express to serve static files from a public/ directory, attach the Socket.IO server to the same HTTP instance, and listen on port 3000.
2
SQLite Schema and Authentication Routes
Define two tables: users(id, username, password_hash) and messages(id, room, user_id, content, created_at). Write POST /register and POST /login routes that hash passwords with bcrypt.hash() and verify them with bcrypt.compare(). Store the authenticated user in req.session.user on success.
3
Socket.IO Room Logic and Message Broadcast
Inside the io.on('connection') handler, listen for a join-room event that places the socket in the named room via socket.join(room) and replays the 50 most recent messages from SQLite. On send-message, validate the payload, persist it to the database, then broadcast to all room members with io.to(room).emit('new-message', payload).
4
Responsive Frontend with Rooms and Message Display
Build a single-page layout in public/index.html with a sidebar listing available rooms and an online-users count, a scrollable message feed, and a fixed input bar. Use the Socket.IO client library from the CDN. On login success, emit join-room and append incoming new-message events to the feed, auto-scrolling to the latest message.
5
Typing Indicators and Presence Events
Emit a typing-start event when the user begins typing and typing-stop after a 1-second debounce. Relay these to room members with socket.to(room).emit() and render a live “alice is typing...” indicator in the message feed. Broadcast a user-joined and user-left system message on socket connect and disconnect events.
6
Polish: Input Sanitization and Error Handling
Sanitize all message content server-side before persisting: strip HTML tags, trim whitespace, and enforce a 500-character maximum. Add a character counter to the input bar. Handle socket disconnection gracefully with a reconnection toast. Add an auth middleware to Express routes so unauthenticated clients receive a 401 redirect rather than raw data.
