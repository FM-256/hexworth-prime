Subject

Train an Agent with Reinforcement Learning

Operative 90 min 500 XP
Mission Brief

Your assignment is to train a reinforcement learning agent from scratch to solve the Taxi-v4 navigation problem using tabular Q-learning. The agent must learn to pick up a passenger at one grid location and drop them off at the correct destination while avoiding illegal actions — without any guidance beyond the reward signal provided by the environment.

You will build a Q-table using NumPy, implement an epsilon-greedy exploration strategy with exponential decay, run a 5,000-episode training loop, and then evaluate the trained agent in greedy mode to prove it works. Every line of code is written step by step with the full expected output shown — no prior RL experience required.

By the end you will understand the core RL feedback loop (state → action → reward → next state), the Bellman update equation, why exploration must decrease over time, and why the old gym library will crash your code while gymnasium works correctly — a trap that catches most first-timers.

Agent Requirements
  • Python 3.10 or newer (type python --version in a terminal to check)
  • gymnasium 1.x — install with pip install "gymnasium[toy-text]" (this pulls the Taxi environment; plain pip install gymnasium also works)

  • Basic Python: variables, for-loops, if/else, importing a module — no ML background needed
  • A terminal and any text editor or Jupyter notebook; all code in this project runs from a single .py file

Install, Import, and Explore the Environment
Before writing any learning code, verify that the library is installed correctly and understand what the environment actually gives you on every step.
  1. Install the library. Open a terminal and run:
    pip install "gymnasium[toy-text]" numpy
    Why not gym? The original OpenAI gym library is abandoned and uses a 4-tuple step API that will crash with newer Python. gymnasium is the maintained successor — same environments, fixed API, actively developed by the Farama Foundation. Every tutorial you find that says import gym is outdated.
  2. Create a file named taxi_rl.py and paste these imports at the top:
    import gymnasium as gym import numpy as np
  3. Make the environment. Add this block after the imports:
    # Create the Taxi-v4 environment with ANSI text rendering env = gym.make("Taxi-v4", render_mode="ansi") # Inspect the spaces obs_n = env.observation_space.n # number of distinct states act_n = env.action_space.n # number of distinct actions print(f"Observation space: {obs_n} states") print(f"Action space: {act_n} actions")
    Expected output:
    Observation space: 500 states Action space: 6 actions
    The 500 states encode every combination of taxi position (5×5 grid = 25 cells), passenger location (4 pickup spots + 1 if already in taxi = 5), and destination (4 spots). The 6 actions are: 0=South, 1=North, 2=East, 3=West, 4=Pickup, 5=Dropoff.
  4. Reset the environment and take a few random steps. Add this after the print statements:
    # reset() returns a 2-tuple: (initial_observation, info_dict) obs, info = env.reset(seed=42) print(f"\nInitial state: {obs}") print(env.render()) # shows the 5x5 grid in the terminal # Walk through 8 random actions to see the reward signal print("\n--- Random steps ---") for step in range(8): action = env.action_space.sample() # random action (int 0-5) # step() returns a 5-tuple -- NOT the old 4-tuple from gym obs, reward, terminated, truncated, info = env.step(action) print(f"step {step+1}: action={action} reward={reward:+.0f} state={obs} done={terminated or truncated}") if terminated or truncated: obs, info = env.reset() break
    Reading the output: reward -1 is a normal movement step; -10 means you tried to pick up or drop off illegally (no passenger there / wrong destination); +20 means a correct dropoff — episode over. terminated=True signals the agent delivered the passenger; truncated=True signals the 200-step time limit was hit. Always check terminated or truncated, never just done.
  5. Close the environment when done exploring:
    env.close()
Common trap — importing the wrong library: if you see ImportError: No module named 'gym' you have the old package installed. Run pip uninstall gym then pip install "gymnasium[toy-text]". If you see ValueError: too many values to unpack on the env.step() line, you are unpacking a 5-tuple into 4 variables — add truncated as the fourth variable (before info).

Terminal prints Observation space: 500 states and Action space: 6 actions with no errors. The ANSI render shows a 5×5 grid with a colored taxi square and letter markers (R, G, Y, B) for the pickup/dropoff locations. The random-step loop prints reward values of -1, -10, or +20 with no crash. If you hit a crash on the env.step() unpack line, read the fix box above.

Build the Q-Table and Run the Training Loop
The Q-table is a NumPy array with one row per state and one column per action. Training updates it using the Bellman equation over 5,000 episodes with an epsilon-greedy exploration strategy.
  1. Start a fresh file (or clear below the imports). Create the training environment and Q-table:
    import gymnasium as gym import numpy as np # Training environment -- no rendering during training (much faster) env = gym.make("Taxi-v4") obs_n = env.observation_space.n # 500 act_n = env.action_space.n # 6 # Q-table: rows = states, columns = actions, all zeros to start Q = np.zeros((obs_n, act_n)) print(f"Q-table shape: {Q.shape}") # expect (500, 6)
  2. Set the hyperparameters. Add these constants after the Q-table:
    # Learning rate: how much each new experience overwrites old knowledge alpha = 0.1 # Discount factor: how much the agent values future rewards vs. immediate # 0.99 means future rewards are nearly as valuable as immediate ones gamma = 0.99 # Exploration: start fully random, decay toward mostly-greedy epsilon = 1.0 # current exploration probability epsilon_min = 0.01 # floor -- always keep 1% exploration epsilon_decay = 0.995 # multiply epsilon by this after every episode episodes = 5000 # total training episodes
  3. Write the training loop. This is the heart of Q-learning:
    rewards_per_episode = [] # track progress for ep in range(episodes): obs, info = env.reset() # 2-tuple: (obs, info) total_reward = 0 while True: # Epsilon-greedy action selection if np.random.random() < epsilon: action = env.action_space.sample() # explore: random action else: action = int(np.argmax(Q[obs])) # exploit: best known action # Take the action -- 5-tuple return (gymnasium API) next_obs, reward, terminated, truncated, info = env.step(action) # Bellman update: Q(s,a) += alpha * (r + gamma * max_Q(s') - Q(s,a)) best_next = np.max(Q[next_obs]) Q[obs, action] += alpha * (reward + gamma * best_next - Q[obs, action]) obs = next_obs total_reward += reward if terminated or truncated: break # episode over: passenger delivered OR 200-step limit hit # Decay epsilon after each episode epsilon = max(epsilon_min, epsilon * epsilon_decay) rewards_per_episode.append(total_reward) # Print a rolling average every 500 episodes so you can watch progress if (ep + 1) % 500 == 0: avg = np.mean(rewards_per_episode[-100:]) print(f"Episode {ep+1:5d} | avg reward (last 100): {avg:+.1f} | epsilon: {epsilon:.3f}") env.close() print("\nTraining complete.")
Why does the update use np.max(Q[next_obs])? Q-learning is off-policy: it always bootstraps from the best possible next action regardless of what the agent would actually do. This makes it learn the optimal policy even while exploring. (SARSA, by contrast, uses the action the agent would actually choose under epsilon-greedy — that is the on-policy difference you will hear about.)
  • Trap: forgetting obs = next_obs. Without this line the agent replays the same state forever — the loop never advances.
Expected training output (values will vary slightly due to random seeding):
Episode 500 | avg reward (last 100): -78.3 | epsilon: 0.082 Episode 1000 | avg reward (last 100): +2.1 | epsilon: 0.010 Episode 1500 | avg reward (last 100): +7.4 | epsilon: 0.010 Episode 2000 | avg reward (last 100): +8.1 | epsilon: 0.010 Episode 2500 | avg reward (last 100): +8.3 | epsilon: 0.010 ... Episode 5000 | avg reward (last 100): +8.5 | epsilon: 0.010 Training complete.
The reward climbs from deeply negative (pure random exploration) to around +8 as the agent learns. Anything above +6 at episode 5000 means the Q-table has converged.
Checkpoint — what you should see
The training loop runs without crashing. By episode 1000 the rolling average crosses zero. By episode 2500 it stabilizes between +7 and +9 and stops changing much. Epsilon reaches 0.010 (the floor) by around episode 1000 and stays there. If rewards stay at -100 or worse through episode 2000, check that obs = next_obs is inside the while loop and that you are using terminated or truncated, not a variable called done.

Evaluate the Trained Agent in Greedy Mode
Training mixes exploration with learning. Evaluation uses the Q-table in pure greedy mode (epsilon = 0) to measure the true quality of the learned policy and watch the agent drive.
  1. Add an evaluation block after training. Append this to taxi_rl.py (after env.close()):
    # Evaluation: run 100 episodes with the learned policy, no exploration eval_env = gym.make("Taxi-v4", render_mode="ansi") eval_rewards = [] eval_steps = [] successes = 0 for ep in range(100): obs, info = eval_env.reset() total_reward = 0 steps = 0 while True: action = int(np.argmax(Q[obs])) # greedy: always pick best action obs, reward, terminated, truncated, info = eval_env.step(action) total_reward += reward steps += 1 if terminated or truncated: if terminated: # True only on correct passenger dropoff successes += 1 break eval_rewards.append(total_reward) eval_steps.append(steps) eval_env.close() print(f"\n--- Evaluation over 100 episodes ---") print(f"Mean reward: {np.mean(eval_rewards):+.2f}") print(f"Mean steps: {np.mean(eval_steps):.1f}") print(f"Success rate: {successes / len(eval_rewards) * 100:.0f}%")
  2. Watch the agent solve one episode. Add this at the very end of the file to see a visual playthrough:
    # Visual demo: one episode rendered step-by-step demo_env = gym.make("Taxi-v4", render_mode="ansi") obs, info = demo_env.reset(seed=7) print("\n--- Live demo (one episode) ---") print(demo_env.render()) step_count = 0 while True: action = int(np.argmax(Q[obs])) obs, reward, terminated, truncated, info = demo_env.step(action) step_count += 1 print(f"Step {step_count:2d} | action={action} | reward={reward:+.0f}") print(demo_env.render()) if terminated or truncated: result = "DELIVERED" if terminated else "TIMEOUT" print(f"Episode ended: {result} in {step_count} steps") break demo_env.close()
Trap: render_mode must be set at gym.make() time. You cannot call env.render_mode = "ansi" after the environment is already created — gymnasium locks the render mode at construction. If the visual demo shows nothing, make sure you pass render_mode="ansi" inside gym.make(), not afterward. The training environment intentionally has no render_mode (omitting it is faster).
Expected evaluation output:
--- Evaluation over 100 episodes --- Mean reward: +8.31 Mean steps: 13.4 Success rate: 100%
A well-trained agent delivers the passenger in roughly 10–15 steps and scores around +8 per episode (reward = +20 delivery − ~12 movement steps). 100% success rate is normal for a converged Q-table on Taxi-v4.
Checkpoint — what you should see
Evaluation prints a mean reward of +7 or higher and a success rate of 90% or better. The live demo shows the taxi navigating the grid, picking up the passenger (a color change in the ANSI render), and driving to the correct destination in under 20 steps. If success rate is below 80%, re-run training with a fixed seed (env.reset(seed=0) in the training loop) to rule out variance, or increase episodes to 8000.

Plot the Learning Curve
A single chart of rolling average reward over training episodes shows exactly when and how fast the agent learned — and is the standard way to present RL results.
  1. Install Matplotlib if you do not have it:
    pip install matplotlib
  2. Add the import at the top of taxi_rl.py (with the other imports):
    import matplotlib.pyplot as plt
  3. Compute a rolling average and plot it. Add this after the evaluation block (before the demo):
    # Rolling average reward (window = 100 episodes) window = 100 rolling_avg = [ np.mean(rewards_per_episode[max(0, i - window):i + 1]) for i in range(len(rewards_per_episode)) ] plt.figure(figsize=(10, 4)) plt.plot(rewards_per_episode, color="#8b5cf6", alpha=0.2, linewidth=0.6, label="Episode reward") plt.plot(rolling_avg, color="#8b5cf6", linewidth=2, label=f"Rolling avg (window={window})") plt.axhline(y=0, color="white", linewidth=0.5, linestyle="--", alpha=0.3) plt.xlabel("Episode") plt.ylabel("Total Reward") plt.title("Q-Learning on Taxi-v4 — Training Curve") plt.legend() plt.tight_layout() plt.savefig("taxi_learning_curve.png", dpi=150, facecolor="#0a0c10") plt.show() print("Chart saved to taxi_learning_curve.png")
What the chart should look like: raw episode rewards start at around −200 (random) and spike wildly. The rolling average line starts negative, crosses zero somewhere between episode 500 and 1500, then flattens near +8 to +9 for the remainder. The transition from chaotic negatives to a stable positive plateau is the moment the Q-table found the optimal policy.
Trap: plt.show() blocks the script. If your terminal hangs after the chart opens, close the Matplotlib window to let the script continue. Alternatively, move plt.show() to the very last line of the file so everything else runs first.
Checkpoint — what you should see
A PNG file named taxi_learning_curve.png appears in your project folder. The rolling-average line in the chart starts below zero, rises steadily, and plateaus between +7 and +9 before episode 3000. If the rolling average never crosses zero, your Q-table is not updating — re-check that obs = next_obs is present and that the Bellman update writes back into Q[obs, action].

Tune Hyperparameters and Analyze Convergence
Now that you have a working agent, change one variable at a time and measure the effect. This is how real RL researchers find the settings that matter.
  1. Run three experiments by changing only alpha each time. Try alpha = 0.5, then alpha = 0.01, then the original alpha = 0.1. Record the episode at which the rolling average first crosses +5:
    # Helper: find the first episode where the rolling average crosses a threshold def episodes_to_threshold(rolling, threshold=5.0): for i, v in enumerate(rolling): if v >= threshold: return i return None # never reached print(f"First episode above +5: {episodes_to_threshold(rolling_avg)}")
  2. Try a fast decay vs. slow decay. Set epsilon_decay = 0.99 (faster decay) and epsilon_decay = 0.999 (slower decay, stays exploratory longer). Note how total episodes needed to converge changes. The slowest decay may never converge in 5000 episodes.
  3. Try gamma = 0.5 and observe what breaks. A low discount factor makes the agent care only about immediate reward — it will learn to avoid the -10 illegal pickup/dropoff but may fail to plan the multi-step path to the correct destination. Print the mean evaluation reward to see the drop:
    print(f"gamma=0.5 mean eval reward: {np.mean(eval_rewards):+.2f}") # Expected: significantly lower than the gamma=0.99 result
  4. Document your findings. Create a simple table in a comment at the top of the file:
    # Hyperparameter sweep results: # alpha=0.5, gamma=0.99, decay=0.995 | converged ep: ~600 | eval: ~+8.2 # alpha=0.1, gamma=0.99, decay=0.995 | converged ep: ~1200 | eval: ~+8.5 # alpha=0.01, gamma=0.99, decay=0.995 | converged ep: ~4500 | eval: ~+7.8 # alpha=0.1, gamma=0.5, decay=0.995 | converged ep: N/A | eval: ~+2.1
Key insight: alpha controls how fast you learn (too high = unstable, too low = slow); gamma controls planning horizon (too low = short-sighted, misses the +20 delivery reward); epsilon_decay controls when you stop exploring (too slow = spends too many episodes randomly and never commits to the learned policy). Q-learning is robust on Taxi-v4 — it converges over a wide range of values. Noticing what breaks and why is the skill that carries to larger problems.
Checkpoint — what you should see
You can answer these questions with numbers from your own runs: Which alpha value converged fastest? What happens to evaluation performance when gamma drops to 0.5? Does a slower epsilon decay lead to better or worse final performance? If alpha=0.5 and alpha=0.1 both reach +8 evaluation reward but at different speeds, you have successfully replicated the core RL hyperparameter tradeoff. Record your numbers in the comment block — that table is your lab report.
