Subject

Data Augmentation for ML Datasets

Operative 60 min 500 XP
Mission Brief

Your assignment is to build a real image data-augmentation pipeline using Albumentations 2.x — the actively maintained industry standard for augmentation in computer-vision projects. You will load an image, define a composable transform pipeline, generate a grid of augmented variants, and finally wire the pipeline into a PyTorch Dataset so a training loop can consume it.

Data augmentation artificially expands a small dataset by producing realistic variations of each image — a horizontal flip is still a cat, a slightly rotated photo of a stop sign is still a stop sign. Models trained with augmentation generalize better because they see more variety without requiring more labelled data.

Every phase builds directly on the previous one. By the end you will have a single augment.py (or notebook) that loads an image, augments it ten ways, saves a visualization grid, and feeds augmented tensors into a training-ready PyTorch dataset.

Load an Image and Understand the Format Albumentations Expects
Before any augmentation can happen you need to get your image into the right shape. Albumentations requires a NumPy array in HWC order (height × width × channels) with uint8 values 0–255 and RGB channel order.
  1. Create augment.py in the same folder as your sample.jpg. Open it in any editor and add the imports at the top:
    import cv2 import numpy as np import matplotlib.pyplot as plt import albumentations as A
  2. Load the image with OpenCV and convert it to RGB. OpenCV reads files in BGR order by default — Albumentations expects RGB:
    # Load from disk (BGR by default in OpenCV) img_bgr = cv2.imread("sample.jpg") # Convert BGR -> RGB so colors are correct img = cv2.cvtColor(img_bgr, cv2.COLOR_BGR2RGB) print("Shape:", img.shape) # should print (H, W, 3) print("Dtype:", img.dtype) # should print uint8 print("Min/Max:", img.min(), img.max()) # should be 0 .. 255
  3. Display the raw image to confirm it loaded correctly:
    plt.figure(figsize=(4, 4)) plt.imshow(img) plt.title("Original") plt.axis("off") plt.tight_layout() plt.savefig("original.png", dpi=100) plt.show() print("Saved original.png")
Trap — file not found. cv2.imread() returns None silently when the path is wrong. Add this check right after the imread line:
  • if img_bgr is None: raise FileNotFoundError("sample.jpg not found — check your working directory")
  • Run the script from the same folder as the image: cd /path/to/project && python augment.py
Checkpoint — what you should see
The terminal prints a shape like (480, 640, 3), dtype uint8, and min/max of 0 255. A window or saved file shows your image in correct colors (not blue-shifted). If it looks blue, you forgot the BGR2RGB conversion — add it.

2
Define an Albumentations Pipeline and Apply It
Albumentations transforms are composed with A.Compose([...]). You call the pipeline like a function, passing your image as a named argument (image=arr), and it returns a dict — your augmented image lives at result['image'].
  1. Define the transform pipeline. Each transform has a p= parameter that controls the probability it fires on any given call. A value of 0.5 means it fires roughly half the time:
    transform = A.Compose([ A.HorizontalFlip(p=0.5), A.RandomBrightnessContrast( brightness_limit=(-0.2, 0.2), contrast_limit=(-0.2, 0.2), p=0.7, ), A.Affine( rotate=(-15, 15), # degrees scale=(0.85, 1.15), # zoom in/out translate_percent={"x": (-0.08, 0.08), "y": (-0.08, 0.08)}, p=0.6, ), A.GaussNoise( std_range=(0.05, 0.15), # fraction of pixel range p=0.4, ), A.CoarseDropout( num_holes_range=(1, 4), hole_height_range=(0.08, 0.18), hole_width_range=(0.08, 0.18), fill=0, # black holes p=0.3, ), ])
  2. Apply the pipeline once and inspect the result. The named argument image=img is required — Albumentations will raise a TypeError if you pass it as a positional argument:
    # Call with keyword argument -- positional raises TypeError result = transform(image=img) # The augmented image lives in the returned dict aug = result['image'] print("Augmented shape:", aug.shape) # same as original print("Augmented dtype:", aug.dtype) # still uint8
  3. Show original vs. augmented side by side:
    fig, axes = plt.subplots(1, 2, figsize=(8, 4)) axes[0].imshow(img); axes[0].set_title("Original"); axes[0].axis("off") axes[1].imshow(aug); axes[1].set_title("Augmented"); axes[1].axis("off") plt.tight_layout() plt.savefig("compare.png", dpi=100) plt.show() print("Saved compare.png")
Trap — var_limit no longer exists in Albumentations 2.x. If you copy an older tutorial, GaussNoise(var_limit=(10, 50)) will raise a TypeError: unexpected keyword argument. The parameter was renamed to std_range in v2. Use std_range=(0.05, 0.15) (values are fractions of the pixel range, not raw variance).
Trap — ShiftScaleRotate is deprecated. Many tutorials still use it. In v2 it still runs but prints a deprecation warning. Use A.Affine instead as shown above — it is a strict superset.
Checkpoint — what you should see
A two-panel figure saves as compare.png. The right panel should look visibly different from the left on most runs — maybe flipped, a bit darker, slightly rotated, or with small black rectangles. Because transforms fire probabilistically, some runs may look nearly identical — run the script several times to see variation.

Generate an Augmented Grid — 10 Variants from One Image
A visualization grid is the fastest way to verify that your pipeline is producing sensible, diverse outputs. You will call the same pipeline ten times on the same source image and tile the results into a 2×5 grid.
  1. Generate 10 augmented copies in a loop. Each call to transform(image=img) applies a fresh random draw, so each result is different:
    NUM_VARIANTS = 10 augmented_variants = [] for i in range(NUM_VARIANTS): result = transform(image=img) augmented_variants.append(result['image'])
  2. Build and save the 2×5 grid:
    fig, axes = plt.subplots(2, 5, figsize=(15, 6)) axes = axes.flatten() # make indexing easy for idx, aug_img in enumerate(augmented_variants): axes[idx].imshow(aug_img) axes[idx].set_title(f"Aug {idx + 1}", fontsize=9) axes[idx].axis("off") plt.suptitle("Augmentation Grid (10 variants from 1 image)", fontsize=12) plt.tight_layout() plt.savefig("aug_grid.png", dpi=100) plt.show() print("Saved aug_grid.png")
  3. Verify diversity: scan the grid row by row. You should see at least 3–4 distinct visual effects across the 10 panels (some combination of flips, brightness shifts, rotations, noise, dropout patches). If all 10 look identical, check that p= values in your pipeline are not all set to 0 or 1.0.
    Why this matters for training: each epoch, the dataloader calls transform(image=img) once per sample per batch. Over 50 epochs and 1000 images your model sees up to 50,000 unique versions of that image — all generated on the fly, with no extra storage required.
Checkpoint — what you should see
A saved aug_grid.png contains a 2-row by 5-column grid. Each cell shows the same scene with clearly different visual characteristics — at least some panels should be mirrored, at least some should be brighter or darker, and at least one should show small black rectangles from CoarseDropout. All 10 panels should have exactly the same pixel dimensions as the original.

4
Wire Augmentation into a PyTorch Dataset
A visualization loop and a training loop are different things. In training, augmentation must happen inside Dataset.__getitem__ so that PyTorch's DataLoader gets a fresh random augment every time it requests a sample. You will also add ToTensorV2 to convert the NumPy HWC array into a PyTorch CHW tensor.
  1. Add the tensor-conversion import at the top of your file alongside the other imports:
    import torch from torch.utils.data import Dataset, DataLoader from albumentations.pytorch.transforms import ToTensorV2
  2. Define a training-time transform that ends with ToTensorV2. A.Normalize converts the uint8 array to float32 and shifts values into the normalized range; ToTensorV2 then transposes HWC→CHW and wraps the result in a torch tensor, preserving whatever dtype A.Normalize produced:
    train_transform = A.Compose([ A.HorizontalFlip(p=0.5), A.RandomBrightnessContrast( brightness_limit=(-0.2, 0.2), contrast_limit=(-0.2, 0.2), p=0.7, ), A.Affine( rotate=(-15, 15), scale=(0.85, 1.15), translate_percent={"x": (-0.08, 0.08), "y": (-0.08, 0.08)}, p=0.6, ), A.GaussNoise(std_range=(0.05, 0.15), p=0.4), A.CoarseDropout( num_holes_range=(1, 4), hole_height_range=(0.08, 0.18), hole_width_range=(0.08, 0.18), fill=0, p=0.3, ), A.Normalize( mean=(0.485, 0.456, 0.406), # ImageNet mean -> float32, normalized range std=(0.229, 0.224, 0.225), ), ToTensorV2(), # transposes HWC -> CHW, wraps in torch tensor (preserves dtype) ])
  3. Build a minimal dataset class that wraps a list of image file paths:
    class ImageFolderDataset(Dataset): def __init__(self, image_paths, transform=None): self.image_paths = image_paths self.transform = transform def __len__(self): return len(self.image_paths) def __getitem__(self, idx): # Load image and convert BGR->RGB (same as Phase 1) path = self.image_paths[idx] img_bgr = cv2.imread(path) img_rgb = cv2.cvtColor(img_bgr, cv2.COLOR_BGR2RGB) if self.transform is not None: # Albumentations requires the named keyword argument result = self.transform(image=img_rgb) img_rgb = result['image'] # now a CHW tensor after ToTensorV2 # Return (tensor, label) -- label is 0 here as a placeholder return img_rgb, 0
  4. Instantiate the dataset and dataloader, then pull one batch to verify the shapes:
    # Use your sample image -- the dataset can hold any number of paths image_paths = ["sample.jpg"] dataset = ImageFolderDataset(image_paths, transform=train_transform) loader = DataLoader(dataset, batch_size=1, shuffle=True) # Pull one batch and inspect for batch_imgs, batch_labels in loader: print("Batch tensor shape:", batch_imgs.shape) # expected: torch.Size([1, 3, H, W]) print("Dtype:", batch_imgs.dtype) # expected: torch.float32 print("Value range:", batch_imgs.min().item(), "..", batch_imgs.max().item()) # expected: roughly -2.1 .. 2.6 (normalized, not 0..1) break # only need one batch for the check
Trap — ToTensorV2 wrong import. Some older code uses from albumentations.core.transforms_interface import ToTensorV2 — that will raise an ImportError. The correct path in Albumentations 2.x is from albumentations.pytorch.transforms import ToTensorV2.
Trap — wrong order: ToTensorV2 before Normalize. A.Normalize is a NumPy-array transform. If ToTensorV2 runs first, it converts the array into a torch tensor; A.Normalize then receives that tensor instead of a NumPy array and raises a TypeError. Always put A.Normalize immediately before ToTensorV2 so normalization operates on the NumPy array, and ToTensorV2 receives the already-normalized float32 array.
Checkpoint — what you should see
The terminal prints Batch tensor shape: torch.Size([1, 3, H, W]) where H and W match your image dimensions, Dtype: torch.float32, and a value range roughly in -2.1 .. 2.6. The float32 dtype and the normalized value range both come from A.Normalize; ToTensorV2 only transposes HWC→CHW and wraps the array in a torch tensor — it preserves whatever dtype A.Normalize produced. If you see dtype uint8, A.Normalize is missing or misplaced. If you see shape [1, H, W, 3], ToTensorV2 is not in the pipeline at all.

Tune Your Pipeline — Verify Diversity and Save a Summary
A pipeline that always produces the same output, or one that produces outputs too distorted to be recognizable, is not useful. This phase gives you a concrete method for evaluating and tuning augmentation strength before attaching it to a real training run.
  1. Build a side-by-side 1×4 strip that shows the original and three augmented variants together. This is your "sanity strip" — it should be clear at a glance what each variant looks like relative to the source:
    fig, axes = plt.subplots(1, 4, figsize=(16, 4)) axes[0].imshow(img) axes[0].set_title("Original", fontsize=10) axes[0].axis("off") for i in range(1, 4): aug_result = transform(image=img) # uses the Phase-2 pipeline (no ToTensorV2) axes[i].imshow(aug_result['image']) axes[i].set_title(f"Variant {i}", fontsize=10) axes[i].axis("off") plt.suptitle("Augmentation sanity strip", fontsize=12) plt.tight_layout() plt.savefig("sanity_strip.png", dpi=100) plt.show() print("Saved sanity_strip.png")
  2. Evaluate pipeline strength: look at the strip and apply these criteria.
    Under-augmented (too weak): all 3 variants look nearly identical to the original. Fix: increase p= values and widen the range params (e.g. rotate=(-30, 30) instead of (-15, 15)).
    Over-augmented (too strong): variants look unrecognizable — completely blown-out brightness, massive black rectangles covering most of the image. Fix: lower p= values and narrow the range params, or reduce num_holes_range upper bound.
  3. Print a pipeline summary — Albumentations can describe the whole pipeline as a dict for logging:
    import json pipeline_dict = train_transform.to_dict() print(json.dumps(pipeline_dict, indent=2, default=str))
    Save this output alongside your model checkpoints. It lets you reproduce the exact augmentation used during training months later, which matters when comparing experiment runs.
  4. Save all outputs to one folder to keep your project tidy:
    import os os.makedirs("aug_outputs", exist_ok=True) # Re-save your earlier outputs into the folder for fname in ["original.png", "compare.png", "aug_grid.png", "sanity_strip.png"]: if os.path.exists(fname): os.rename(fname, os.path.join("aug_outputs", fname)) print("All outputs moved to aug_outputs/")
Checkpoint — what you should see
sanity_strip.png shows four panels. The three augmented panels are recognizably the same scene but each has at least one visible difference from the original (brightness shift, flip, rotation, noise, or dropout patch). The to_dict() output prints valid JSON listing all five transforms by name with their parameters. An aug_outputs/ folder exists and contains all four PNG files.
