Subject

Create Custom Helm Charts for K8s

Advanced 120 min 1000 XP
Mission Brief

Your assignment is to author, test, and publish a production-grade Helm chart for a containerized application running on Kubernetes. You will build the full chart directory structure from scratch, write parameterized YAML templates using Go template syntax, and manage default values through values.yaml with runtime overrides via --set flags.

The chart must deploy a multi-resource application: a Deployment with configurable replica count and image tag, a Service exposing the workload, an optional Ingress controlled by a values flag, a ServiceAccount, and a ConfigMap. Helper templates in _helpers.tpl provide reusable label blocks and name-generation functions using {{ include }}.

Chart dependencies are declared in Chart.yaml under the dependencies key and resolved with helm dependency update. After validating with helm lint and dry-running with helm template, you will package the chart and publish it to a public repository on Artifact Hub using an OCI-compatible registry or a GitHub Pages-hosted index.

Agent Requirements
  • A running Kubernetes cluster (minikube, kind, or a cloud-managed cluster)
  • kubectl configured and able to list pods in the default namespace
  • helm v3 installed; familiarity with helm install and helm upgrade
  • Comfort reading YAML and understanding Kubernetes Deployment and Service specs
  • Basic Go template syntax: {{ .Values.key }}, {{ if }}, {{ range }}
  • A Docker Hub or GitHub Container Registry account for the published chart

Scaffold the Chart and Populate Chart.yaml
Run helm create mychart to generate the scaffolded structure, then delete the generated template files and start fresh. Edit Chart.yaml to set apiVersion: v2, meaningful name, version (SemVer), appVersion, description, and type: application. Add a dependencies entry for a bitnami subchart (e.g., Redis) with a specific version and repository URL to demonstrate dependency management.
Checkpoint: Chart Scaffold
  • Verify Chart.yaml contains apiVersion: v2, a valid SemVer version, and a dependencies block
  • Confirm the scaffolded directory structure includes templates/, charts/, and values.yaml
  • Run helm dependency update and verify the subchart tarball appears in charts/
✓
2
Design values.yaml and Helper Templates
Write a well-documented values.yaml covering: replicaCount, image.repository, image.tag, image.pullPolicy, service.type, service.port, ingress.enabled, ingress.host, resources.requests, and resources.limits. In _helpers.tpl, define a mychart.fullname template that truncates to 63 characters and a mychart.labels template emitting standard Kubernetes recommended labels.
✓
3
Write Deployment, Service, and Ingress Templates
Author deployment.yaml using {{ .Values.replicaCount }} for replicas, {{ .Values.image.repository }}:{{ .Values.image.tag }} for the container image, and {{ include "mychart.labels" . | indent 4 }} for labels. Wrap the resource and limits blocks in {{- with .Values.resources }} so they are omitted when unset. Write ingress.yaml wrapped in {{- if .Values.ingress.enabled }} so the resource is only rendered when opted in.
Checkpoint: Templates
  • Run helm template myrelease . and verify the rendered deployment.yaml uses values from values.yaml
  • Confirm ingress.yaml is only rendered when ingress.enabled: true is set
  • Check that resource limits/requests are omitted from the rendered output when not defined in values
✓
4
Lint, Template, and Install
Run helm dependency update to pull subchart tarballs into the charts/ directory. Execute helm lint . and resolve any warnings before proceeding. Use helm template myrelease . to dry-run and inspect the rendered YAML locally. Install to the cluster with helm install myrelease . --values custom-values.yaml and verify the Deployment and Service appear with kubectl get all. Test an upgrade by bumping the image tag with --set image.tag=v2 and confirming a rolling update.
✓
5
Write Chart Tests and Validate with helm test
Create a templates/tests/ directory containing a test Pod spec annotated with helm.sh/hook: test. The Pod runs a wget or curl command against the Service endpoint and exits 0 on success. Run helm test myrelease to execute the test and review the output. Add a second test that validates the ConfigMap content contains expected values.
Checkpoint: Chart Tests
  • Run helm test myrelease and verify the test Pod exits with status 0 (success)
  • Confirm the test Pod makes a successful HTTP request to the Service endpoint
  • Verify the ConfigMap content test validates expected key-value pairs
✓
6
Package and Publish to Artifact Hub
Run helm package . to create a versioned .tgz archive. Push to an OCI registry with helm push mychart-1.0.0.tgz oci://ghcr.io/yourname, or generate a index.yaml with helm repo index . and host it on GitHub Pages. Register the repository URL on Artifact Hub by adding the artifacthub.io/repository-name annotation in Chart.yaml and submitting through the Artifact Hub UI.
