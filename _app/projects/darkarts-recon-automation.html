Subject

Automate Recon with Python

Operative 120 min 600 XP
Mission Brief

This operation tasks you with building a Python reconnaissance automation pipeline that takes a target domain and systematically maps its entire attack surface: subdomains, DNS records, open ports, running services, and technology stack. Each stage feeds its output into the next, creating a chain that transforms a single domain name into a comprehensive intelligence report in under five minutes.

The pipeline is built module by module. Subdomain enumeration combines wordlist brute-forcing with dns.resolver and passive sources (crt.sh certificate transparency logs). Discovered subdomains are resolved to IP addresses, then fed into a concurrent port scanner built with socket and concurrent.futures.ThreadPoolExecutor. Open ports trigger service banner grabbing and HTTP header analysis to fingerprint the technology stack — web server, CDN, frameworks, and CMS.

The finished tool runs from the command line with --domain and produces a structured JSON report alongside a human-readable summary. Every module is designed as a standalone function that can be imported and reused in other tools, following the Unix philosophy of small, composable utilities chained together into powerful pipelines.

Agent Requirements
  • Python fundamentals — functions, file I/O, exception handling, and working with JSON
  • Basic networking concepts — DNS, IP addresses, ports, and what HTTP headers contain
  • Comfortable running scripts from the command line and installing packages with pip
  • Understanding of what subdomain enumeration and port scanning accomplish at a high level
  • No prior offensive security or reconnaissance tool experience required — the project teaches every technique from scratch
Operation Phases
1
Subdomain Enumeration
Build a subdomain discovery module that combines two approaches: active brute-forcing using a wordlist of common subdomain prefixes resolved via dns.resolver, and passive enumeration by querying the crt.sh certificate transparency API for historically issued certificates. Merge results from both sources, deduplicate, and validate each subdomain with a DNS lookup. Handle NXDOMAIN and timeout errors gracefully. Use ThreadPoolExecutor with configurable thread count to parallelize DNS lookups for speed.
Checkpoint: Subdomain Discovery
  • Subdomain enumeration tool runs against the target domain without errors
  • Results include subdomains from multiple sources (DNS, certificate logs)
  • Output is deduplicated and saved to a text file for the next stage
2
DNS Resolution & Record Collection
For each validated subdomain, query multiple DNS record types: A, AAAA, CNAME, MX, TXT, and NS using dns.resolver. Map subdomains to IP addresses and identify shared hosting (multiple subdomains resolving to the same IP). Detect CDN usage by checking CNAME chains for known CDN domains (Cloudflare, AWS, Akamai). Flag subdomains that resolve to internal RFC 1918 addresses as potential misconfigurations. Store all records in a structured dictionary for downstream processing.
Checkpoint: DNS Resolution
  • All discovered subdomains are resolved to IP addresses
  • DNS record types (A, AAAA, CNAME, MX) are collected and stored
  • Unresolvable subdomains are flagged but do not halt the pipeline
3
Port Scanning
Build a TCP connect scanner using socket.connect_ex() targeting the top 100 most common ports (or a custom list via --ports). Use ThreadPoolExecutor to scan multiple ports concurrently with a configurable timeout per connection attempt. For each open port, attempt a banner grab by reading the first 1024 bytes from the socket. Record port number, state (open/closed/filtered), service name from a built-in port-to-service mapping, and any banner text received.
Checkpoint: Port Scan Stage
  • Port scan runs against resolved IPs with a defined port range
  • Open ports are recorded with their associated IP and subdomain
  • Scan rate is throttled to avoid triggering rate limits or IDS alerts
4
Service Detection & Tech Fingerprinting
For HTTP/HTTPS services detected on open ports, send GET requests with requests and analyze response headers: Server, X-Powered-By, X-Frame-Options, and security headers like CSP and HSTS. Parse HTML responses to extract meta generator tags, framework-specific paths, and JavaScript library references. Build a technology profile for each subdomain listing web server, CDN, CMS, frameworks, and notable security header presence or absence. Flag missing security headers as potential findings.
Checkpoint: Service Fingerprinting
  • Service versions are identified on open ports (e.g., nginx 1.x, OpenSSH 8.x)
  • Technology stack detection identifies frameworks and CMS platforms
  • Results are merged with port scan data into a unified record per host
5
Pipeline Assembly & Reporting
Wire all four modules into a sequential pipeline orchestrated by a main runner function. Build a CLI with argparse accepting --domain, --threads, --ports, and --output flags. Generate two output formats: a comprehensive JSON report containing all raw data (subdomains, DNS records, ports, tech stacks) and a human-readable terminal summary with color-coded output using ANSI escape codes. Include timing metrics for each pipeline stage. Add a --modules flag to run individual stages in isolation for targeted reconnaissance.
Checkpoint: Pipeline & Report
  • All stages run sequentially with the output of one feeding the next
  • Final report consolidates subdomains, IPs, ports, and services
  • Report is saved in a structured format (JSON, CSV, or Markdown)
