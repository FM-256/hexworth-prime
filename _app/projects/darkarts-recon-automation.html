Subject

Automate Recon with Python

Operative 120 min 600 XP
Mission Brief

This operation tasks you with building a Python reconnaissance automation pipeline that takes a target domain and systematically maps its entire attack surface: subdomains, DNS records, open ports, running services, and technology stack. Each stage feeds its output directly into the next, transforming a single domain name into a structured intelligence report.

The pipeline is built module by module. Subdomain enumeration combines certificate transparency records from crt.sh (passive) with a wordlist resolved via dnspython 2.6.x. Discovered subdomains are resolved to IP addresses using dns.resolver, then fed into a concurrent port scanner built with socket and concurrent.futures.ThreadPoolExecutor. Open ports trigger HTTP header analysis and banner grabbing to fingerprint the technology stack. A final orchestrator wires every stage together and outputs a JSON report.

The finished tool runs from the command line and produces output you can read, share, or feed into downstream tools. Every module is a standalone function you can import and reuse — the Unix philosophy of small, composable utilities chained into powerful pipelines.

Agent Requirements
  • Python 3.10 or newer — verify with python3 --version. The orchestrator uses str | None union-type annotations in function signatures, which require Python 3.10+. Everything else is 3.9-compatible. Install from python.org or your distro package manager.
  • pip packages — dnspython 2.6.1 (DNS queries) and requests 2.31.0 (HTTP fingerprinting). Install with pip install dnspython==2.6.1 requests==2.31.0. Everything else is stdlib.
  • Python fundamentals — functions, file I/O, exception handling, working with JSON and dictionaries
  • Basic networking concepts — what DNS, IP addresses, ports, and HTTP headers are
  • Comfortable running scripts from the terminal and installing packages with pip
  • A domain you own or explicit written authorization to assess — DNS and subdomain stages run against your own domain. Port scanning stages run against scanme.nmap.org, which Nmap explicitly provides as a sanctioned public target for this purpose. No other third-party targets.

Authorization, Scope, and the Passive vs. Active Distinction
Before writing a single line of recon code, you must understand the legal and ethical boundaries. Reconnaissance automation touches networks. Whether that contact is legal depends entirely on authorization. This phase defines exactly what you are allowed to do and why the passive/active distinction matters before every other phase.
Authorization Requirement — Read Before Proceeding Recon automation is a dual-use tool. The same pipeline that maps your own attack surface can be aimed at someone else's infrastructure — and doing so without permission is illegal in most jurisdictions under laws such as the U.S. Computer Fraud and Abuse Act (CFAA), the UK Computer Misuse Act, and equivalent statutes worldwide. You may only target domains and IP ranges that you own, that you have a signed penetration-testing scope agreement to assess, or that a bug-bounty program explicitly lists as in-scope for the registered domain you intend to use.
  • For DNS and subdomain phases: use a domain registered in your name (e.g., a personal or lab domain). If you do not own one, use scanme.nmap.org for DNS lookups only — Nmap grants permission to query it.
  • For port scanning: use scanme.nmap.org (45.33.32.156). Nmap explicitly states on scanme.nmap.org: "We set up this machine to help folks learn about Nmap and also to test and make sure that their Nmap installation (or internet connection) is working fine... you are authorized to scan this machine with Nmap."
  • Do not scan IP addresses or domains belonging to any other party, even to test your tool. "Testing my tool" is not a legal defense.
Passive Recon
Observes public data without contacting the target. Examples: querying certificate transparency logs at crt.sh, looking up DNS records using the public DNS infrastructure, reading WHOIS records. The target receives no connection from you. Low legal risk, no authorization gap.
Active Recon
Sends packets or requests directly to target infrastructure. Examples: TCP port scanning, service banner grabbing, HTTP requests to enumerate paths. The target's logs will record your IP address. Requires explicit authorization — you are making contact with a system that belongs to someone.
  1. Define your scope document. Before running any tool, write down three things: (1) the domain(s) you are authorized to assess, (2) the IP ranges in scope, (3) the name of the authorization (owner = you, signed scope doc, or bug-bounty program name + date). Even for your own lab domain, document it. Real pentesters sign a statement of work before touching anything.

    mkdir recon-pipeline && cd recon-pipeline python3 -m venv venv source venv/bin/activate # Windows: venv\Scripts\activate pip install dnspython==2.6.1 requests==2.31.0
    Confirm installed versions:

Phases 4 and 5 are active (port scanning and HTTP requests reach the target host directly). Phase 6 wires everything into a pipeline. The authorization requirement escalates at Phase 4.
    Why the line matters: a CDN like Cloudflare sits in front of many targets. Even a DNS lookup against Cloudflare's nameservers does not touch the origin server. A TCP connection to port 443 does reach a system someone owns. Know which side of the line each operation is on.

DNS Enumeration — A, AAAA, MX, NS, TXT Records
Build the DNS module. It queries multiple record types for a domain using dns.resolver, stores results in a structured dictionary, and gracefully handles missing records. This is passive reconnaissance: you are querying the public DNS infrastructure, not contacting the target directly.
  1. Create the DNS module. Save this as recon_dns.py in your project directory:
    #!/usr/bin/env python3 """ recon_dns.py -- DNS record enumeration module. Queries A, AAAA, MX, NS, TXT records for a domain. Passive recon: uses public DNS infrastructure, no direct contact with the target. """ import dns.resolver from typing import Any RECORD_TYPES = ["A", "AAAA", "MX", "NS", "TXT"] def enumerate_dns(domain: str, timeout: float = 5.0) -> dict[str, Any]: """ Query common DNS record types for *domain*. Returns a dict with keys matching RECORD_TYPES. Values are lists of strings on success, or an error string. """ results: dict[str, Any] = {"domain": domain, "records": {}} for rtype in RECORD_TYPES: try: answers = dns.resolver.resolve(domain, rtype, lifetime=timeout) results["records"][rtype] = [str(r) for r in answers] except dns.resolver.NXDOMAIN: results["records"][rtype] = "NXDOMAIN" except dns.resolver.NoAnswer: results["records"][rtype] = "NO_RECORD" except dns.resolver.Timeout: results["records"][rtype] = "TIMEOUT" except dns.exception.DNSException as e: results["records"][rtype] = f"ERROR: {type(e).__name__}" return results if __name__ == "__main__": import sys, json target = sys.argv[1] if len(sys.argv) > 1 else "scanme.nmap.org" data = enumerate_dns(target) print(json.dumps(data, indent=2))
  2. Run it against a sanctioned domain and verify the output. The examples below use nmap.org and scanme.nmap.org, both operated by the Nmap project and permitted for query:
    python3 recon_dns.py nmap.org
    Actual output (run 2026-06-20):
    { "domain": "nmap.org", "records": { "A": ["50.116.1.184"], "AAAA": ["2600:3c01:e000:3e6::6d4e:7061"], "MX": [ "5 ALT2.ASPMX.L.GOOGLE.COM.", "10 ASPMX2.GOOGLEMAIL.COM.", "1 ASPMX.L.GOOGLE.COM.", "10 ASPMX3.GOOGLEMAIL.COM.", "5 ALT1.ASPMX.L.GOOGLE.COM." ], "NS": [ "ns4.linode.com.", "ns1.linode.com.", "ns3.linode.com.", "ns2.linode.com.", "ns5.linode.com." ], "TXT": [ "\"v=spf1 a mx ptr ip4:50.116.1.184 ip6:2600:3c01::f03c:91ff:fe98:ff4e include:_spf.google.com ~all\"", "\"google-site-verification=SrtYpJGxZzMTcczZG44XtLVK-sEPit9bputDjWc0lF4\"" ] } }
    What this tells you: MX records pointing at Google means the organization uses Google Workspace for email. NS at Linode means DNS is hosted on Linode's nameservers. The SPF TXT record tells you which servers are authorized to send email for this domain — all useful context for a full assessment.
  3. Now run it against your own domain (the domain you listed in scope.txt). Compare your A record output to what your DNS provider shows in its management panel to confirm the resolver is working correctly.
    python3 recon_dns.py yourdomain.com
dns.resolver.NXDOMAIN even though the domain exists?
  • Your system may be using a local stub resolver (e.g., 127.0.0.53 on Ubuntu with systemd-resolved) that has a negative cache entry. Force a fresh query: python3 -c "import dns.resolver; r = dns.resolver.Resolver(); r.nameservers = ['8.8.8.8']; print(r.resolve('yourdomain.com','A'))"
  • If you get NoNameservers: your internet connection dropped or your network blocks outbound DNS (port 53 UDP/TCP). Test with nslookup nmap.org 8.8.8.8.
  • TXT or MX returning NO_RECORD is normal — not every domain publishes all record types. The module handles this gracefully; the pipeline continues.
Checkpoint — what you should see

Subdomain Discovery — crt.sh Passive Enum + Wordlist Brute-Force
Build the subdomain module. It combines two sources: certificate transparency logs at crt.sh (passive, no target contact) and a wordlist resolved concurrently via ThreadPoolExecutor (active DNS queries — passive-ish since they hit the public DNS system, not the target directly). Critically, it detects and filters wildcard DNS, which would otherwise report hundreds of false-positive subdomains.
Active Scanning Reminder Wordlist DNS resolution sends queries through the public DNS system for candidate subdomains. This does not contact the target host directly, but it does generate DNS traffic that resolves against the target domain's nameservers. Only run this against domains you are authorized to enumerate. crt.sh lookups are fully passive — they query crt.sh's database of public certificate logs, not the target.
  1. Create the subdomain module. Save as recon_subdomains.py:
    #!/usr/bin/env python3 """ recon_subdomains.py -- Subdomain enumeration module. Two sources: 1. crt.sh certificate transparency (passive) 2. Wordlist brute-force via concurrent DNS resolution Wildcard detection filters false positives before returning results. """ import dns.resolver import urllib.request import json import random import string from concurrent.futures import ThreadPoolExecutor, as_completed from typing import Optional # Common subdomain prefixes to brute-force WORDLIST = [ "www", "mail", "ftp", "api", "dev", "staging", "vpn", "admin", "blog", "shop", "cdn", "app", "portal", "remote", "git", "docs", "ns1", "ns2", "smtp", "imap", "pop", "status", "test", "demo", "auth", "login", "dashboard", "help", "support", "beta", "prod", ] def _random_label(length: int = 16) -> str: """Generate a random string unlikely to be a real subdomain.""" return "".join(random.choices(string.ascii_lowercase, k=length)) def detect_wildcard(domain: str, timeout: float = 4.0) -> Optional[str]: """ Resolve a random subdomain. If it resolves, the domain has wildcard DNS. Returns the wildcard IP (to filter against) or None. Known limitation: probes a single IP only. Round-robin / multi-IP domains (e.g. behind a CDN load balancer) may return different IPs on each query, so this single-probe check can miss wildcard DNS that rotates across addresses. A robust implementation would collect 3-5 probe IPs and filter against all of them. """ probe = f"{_random_label()}.{domain}" try: ans = dns.resolver.resolve(probe, "A", lifetime=timeout) return str(list(ans)[0]) # wildcard IP except Exception: return None # no wildcard def passive_crtsh(domain: str, timeout: float = 15.0) -> set[str]: """ Query crt.sh certificate transparency logs for subdomains. Fully passive: no contact with the target domain's infrastructure. Returns a set of unique subdomain strings. """ found: set[str] = set() url = f"https://crt.sh/?q=%.{domain}&output=json" try: req = urllib.request.Request( url, headers={"User-Agent": "Mozilla/5.0 recon-pipeline/1.0"} ) with urllib.request.urlopen(req, timeout=timeout) as resp: data = json.loads(resp.read()) for entry in data: for name in entry.get("name_value", "").split("\n"): name = name.strip().lstrip("*.") if name.endswith(f".{domain}") or name == domain: found.add(name) except Exception as e: print(f" [crt.sh] warning: {e}") return found def _resolve_one(host: str, timeout: float) -> tuple[str, Optional[list[str]]]: """Try to resolve host to A records. Returns (host, ips) or (host, None).""" try: ans = dns.resolver.resolve(host, "A", lifetime=timeout) return host, [str(r) for r in ans] except Exception: return host, None def brute_wordlist( domain: str, wordlist: list[str] = WORDLIST, threads: int = 20, timeout: float = 3.0, ) -> dict[str, list[str]]: """ Resolve candidate subdomains concurrently. Returns {subdomain: [ip, ...]} for all that resolved. """ candidates = [f"{w}.{domain}" for w in wordlist] resolved: dict[str, list[str]] = {} with ThreadPoolExecutor(max_workers=threads) as ex: futures = {ex.submit(_resolve_one, h, timeout): h for h in candidates} for fut in as_completed(futures): host, ips = fut.result() if ips: resolved[host] = ips return resolved def enumerate_subdomains( domain: str, threads: int = 20, skip_crtsh: bool = False, ) -> dict: """ Full subdomain enumeration for *domain*. 1. Detect wildcard DNS 2. crt.sh passive enum 3. Wordlist brute-force 4. Merge, filter wildcards, dedup Returns structured results dict. """ print(f"[subdomains] Checking for wildcard DNS on {domain}...") wildcard_ip = detect_wildcard(domain) if wildcard_ip: print(f" [!] WILDCARD DETECTED: *.{domain} resolves to {wildcard_ip}") print(" Wordlist results will be filtered against wildcard IP.") else: print(" [ok] No wildcard DNS detected.") passive: set[str] = set() if not skip_crtsh: print(f"[subdomains] Querying crt.sh for {domain}...") passive = passive_crtsh(domain) print(f" [crt.sh] {len(passive)} names found in certificate logs") print(f"[subdomains] Brute-forcing {len(WORDLIST)} wordlist candidates...") resolved = brute_wordlist(domain, threads=threads) # Filter wildcard hits from brute-force results if wildcard_ip: resolved = { h: ips for h, ips in resolved.items() if wildcard_ip not in ips } print(f" [filter] {len(resolved)} survive wildcard filter") else: print(f" [brute] {len(resolved)} resolved from wordlist") # Merge passive crt.sh names with brute-force confirmed resolutions all_names = passive | set(resolved.keys()) return { "domain": domain, "wildcard_ip": wildcard_ip, "crtsh_count": len(passive), "wordlist_resolved": resolved, "all_subdomains": sorted(all_names), "total": len(all_names), } if __name__ == "__main__": import sys target = sys.argv[1] if len(sys.argv) > 1 else "nmap.org" skip = "--skip-crtsh" in sys.argv result = enumerate_subdomains(target, skip_crtsh=skip) print(json.dumps(result, indent=2))
  2. Run it and observe the wildcard trap in action. nmap.org is a perfect teaching example because it has wildcard DNS:
    python3 recon_subdomains.py nmap.org
    Actual output (run 2026-06-20 — crt.sh returned 84 certificate entries; wildcard filter applied):
    [subdomains] Checking for wildcard DNS on nmap.org... [!] WILDCARD DETECTED: *.nmap.org resolves to 50.116.1.184 Wordlist results will be filtered against wildcard IP. [subdomains] Querying crt.sh for nmap.org... [crt.sh] 5 names found in certificate logs [subdomains] Brute-forcing 30 wordlist candidates... [filter] 0 survive wildcard filter { "domain": "nmap.org", "wildcard_ip": "50.116.1.184", "crtsh_count": 5, "wordlist_resolved": {}, "all_subdomains": [ "issues.nmap.org", "nmap.org", "svn.nmap.org", "www.nmap.org", "www.svn.nmap.org" ], "total": 5 }
    Without the wildcard filter, the brute-force would have returned all 30 wordlist candidates as "live" (they all resolved to 50.116.1.184 — the wildcard IP). The filter reduces 30 false positives to zero, leaving only the 5 names confirmed by certificate transparency logs.
  3. Run it against your own domain (the one in scope.txt). Domains without wildcard DNS will show real wordlist hits.
    python3 recon_subdomains.py yourdomain.com
    crt.sh rate limits: crt.sh has a rate limit of approximately 10 requests per minute per IP. If you get a 503 or timeout, wait 60 seconds and retry. The module handles the error gracefully and continues with wordlist results only. You can pass --skip-crtsh if the service is unavailable.
All wordlist entries resolve even for subdomains that shouldn't exist?
  • That is wildcard DNS — the domain owner configured *.domain.com to resolve to their main IP. The wildcard detection in step 2 of the module catches this automatically. Check the "wildcard_ip" field in the output — if it is set, the filter is active.
  • crt.sh returns empty results? The service is sometimes slow or returns 404 for less-common domains. Retry, or set skip_crtsh=True in the call and rely on wordlist only.
  • ThreadPoolExecutor raises BrokenPipeError on macOS: add multiprocessing.set_start_method("fork") before the executor call, or reduce threads to 5.
Checkpoint — what you should see
python3 recon_subdomains.py nmap.org prints the wildcard detection warning, shows 5 unique subdomains from crt.sh, and 0 wordlist survivors (all filtered as wildcard hits). The output JSON includes "wildcard_ip" set to 50.116.1.184. Running against your own domain shows whatever real subdomains exist, with no wildcard interference.

Port Scanning — Concurrent TCP Connect Scanner
Build the port scanner. It uses socket.connect_ex() with ThreadPoolExecutor to scan ports concurrently, then attempts a banner grab on each open port. This is active reconnaissance and requires authorization. Run it against scanme.nmap.org (45.33.32.156) which Nmap explicitly authorizes as a public scanning target.
Active Scanning — Authorization Required Port scanning sends TCP SYN or connect packets to the target host. This phase must only be run against scanme.nmap.org or your own infrastructure. Do not scan any other host. Unauthorized port scanning violates the CFAA and equivalent laws. The target's firewall, IDS, or hosting provider may flag and block your IP even for authorized scans — this is normal and expected.
  1. Create the port scanner module. Save as recon_portscan.py:
    #!/usr/bin/env python3 """ recon_portscan.py -- TCP connect port scanner with banner grabbing. Uses socket.connect_ex() + ThreadPoolExecutor for concurrent scanning. ACTIVE RECON: only run against authorized targets. """ import socket import time from concurrent.futures import ThreadPoolExecutor, as_completed from typing import Optional # Top 100 most common ports (condensed to key services for this lab) TOP_PORTS = [ 21, 22, 23, 25, 53, 80, 110, 111, 135, 139, 143, 443, 445, 465, 587, 993, 995, 1723, 3306, 3389, 5432, 5900, 8080, 8443, 8888, 9200, 9929, 27017, 31337, ] PORT_SERVICE_MAP = { 21: "FTP", 22: "SSH", 23: "Telnet", 25: "SMTP", 53: "DNS", 80: "HTTP", 110: "POP3", 111: "RPCbind", 135: "MS-RPC", 139: "NetBIOS-SSN", 143: "IMAP", 443: "HTTPS", 445: "SMB", 465: "SMTPS", 587: "SMTP-submission", 993: "IMAPS", 995: "POP3S", 1723: "PPTP", 3306: "MySQL", 3389: "RDP", 5432: "PostgreSQL", 5900: "VNC", 8080: "HTTP-Alt", 8443: "HTTPS-Alt", 8888: "HTTP-Alt2", 9200: "Elasticsearch", 9929: "nping-echo", 27017: "MongoDB", 31337: "Back-Orifice/Elite", } def grab_banner(ip: str, port: int, timeout: float = 2.5) -> Optional[str]: """ Attempt to read up to 1024 bytes from an open port. Sends an HTTP HEAD request on common web ports (80, 8080, 8888). On non-HTTP ports (e.g. 22/SSH) a blind recv() returns the service greeting (e.g. "SSH-2.0-OpenSSH_...") or None if nothing is sent. Returns decoded banner string or None. """ try: with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as s: s.settimeout(timeout) s.connect((ip, port)) if port in (80, 8080, 8888): s.send(b"HEAD / HTTP/1.0\r\nHost: " + ip.encode() + b"\r\n\r\n") banner = s.recv(1024).decode("utf-8", errors="replace").strip() return banner[:256] if banner else None except Exception: return None def scan_port(ip: str, port: int, timeout: float) -> dict: """Attempt TCP connect to ip:port. Returns result dict.""" s = socket.socket(socket.AF_INET, socket.SOCK_STREAM) s.settimeout(timeout) result = s.connect_ex((ip, port)) s.close() is_open = result == 0 banner = grab_banner(ip, port) if is_open else None return { "port": port, "state": "open" if is_open else "closed", "service": PORT_SERVICE_MAP.get(port, "unknown"), "banner": banner, } def scan_host( ip: str, ports: list[int] = TOP_PORTS, threads: int = 30, timeout: float = 2.0, ) -> dict: """ Scan all *ports* on *ip* concurrently. Returns structured results with open ports only. """ print(f"[portscan] Scanning {ip} ({len(ports)} ports, {threads} threads)...") start = time.time() open_ports = [] with ThreadPoolExecutor(max_workers=threads) as ex: futures = { ex.submit(scan_port, ip, p, timeout): p for p in ports } for fut in as_completed(futures): result = fut.result() if result["state"] == "open": open_ports.append(result) elapsed = time.time() - start open_ports.sort(key=lambda x: x["port"]) print(f" [done] {len(open_ports)} open ports found in {elapsed:.1f}s") return { "ip": ip, "open_ports": open_ports, "elapsed_sec": round(elapsed, 2), } if __name__ == "__main__": import sys, json # Default: scanme.nmap.org -- explicitly authorized public scan target # Per https://scanme.nmap.org: "you are authorized to scan this machine" ip = sys.argv[1] if len(sys.argv) > 1 else "45.33.32.156" result = scan_host(ip) print(json.dumps(result, indent=2))
  2. Run it against scanme.nmap.org (45.33.32.156). This is the only host you are authorized to scan in this project unless you own additional infrastructure:
    python3 recon_portscan.py 45.33.32.156
    Actual output (run 2026-06-20):
    [portscan] Scanning 45.33.32.156 (29 ports, 30 threads)... [done] 4 open ports found in 2.0s { "ip": "45.33.32.156", "open_ports": [ { "port": 22, "state": "open", "service": "SSH", "banner": "SSH-2.0-OpenSSH_6.6.1p1 Ubuntu-2ubuntu2.13" }, { "port": 80, "state": "open", "service": "HTTP", "banner": "HTTP/1.1 200 OK\r\nDate: Sat, 20 Jun 2026 09:32:20 GMT\r\nServer: Apache/2.4.7 (Ubuntu)\r\nAccept-Ranges: bytes\r\nVary: Accept-Encoding\r\nConnection: close\r\nContent-Type: text/html" }, { "port": 9929, "state": "open", "service": "nping-echo", "banner": null }, { "port": 31337, "state": "open", "service": "Back-Orifice/Elite", "banner": null } ], "elapsed_sec": 2.02 }
    Why port 22 returns an SSH string, not HTTP: grab_banner only sends an HTTP HEAD request on ports 80, 8080, and 8888. On port 22 it does a blind recv(), which returns the SSH protocol greeting that OpenSSH sends immediately on connect. Port 9929 (nping-echo) returns binary protocol data that does not decode cleanly, so it renders as null here. Port 31337 sends nothing on connect, so its banner is also null. The Apache HTTP header belongs exclusively to port 80.
    Port 31337 on scanme.nmap.org: this port is intentionally open as a test service. The name "Back-Orifice/Elite" in the service map is the historic association (the port was used by the Back Orifice RAT in the late 1990s), but on scanme.nmap.org it is a legitimate Nmap test service — not malware.
  3. Run it against your own host (a VM on your local network or a VPS you control):
    python3 recon_portscan.py YOUR.OWN.IP
    Compare the output to the services you know are running on that machine. Every service you see should be one you recognize. Unexpected open ports are the finding.
All ports return "closed" even on known-open services?
  • The default timeout of 2.0 seconds may be too short over a slow or high-latency link. Increase it: modify timeout=2.0 to timeout=5.0 in the scan_host call.
  • A local firewall (iptables, ufw, Windows Defender) may be blocking outbound connections on port 22 or 443. Test one port manually: python3 -c "import socket; s=socket.socket(); s.settimeout(3); print(s.connect_ex(('45.33.32.156', 80)))". Return value 0 = open, anything else = blocked or closed.
  • On macOS, connect_ex to a filtered port sometimes hangs until timeout rather than returning immediately. This is expected — the scan will complete but take longer.
  • Do not increase threads beyond 100 — most OS have a limit on concurrent connections per process. 30 is the safe default for scanning a single host.
Checkpoint — what you should see
python3 recon_portscan.py 45.33.32.156 returns exactly 4 open ports: 22 (SSH), 80 (HTTP), 9929 (nping-echo), and 31337. Port 22 banner is SSH-2.0-OpenSSH_6.6.1p1 Ubuntu-2ubuntu2.13. Port 80 banner contains Apache/2.4.7 (Ubuntu). Ports 9929 and 31337 return null banners. The scan completes in under 5 seconds. Any other open port count indicates network conditions have changed on scanme.nmap.org — verify with nmap -p 22,80,9929,31337 scanme.nmap.org if installed.

Tech-Stack Fingerprinting — HTTP Headers and Security Posture
Build the fingerprinting module. It sends a GET request to HTTP/HTTPS services discovered in Phase 4, parses the response headers for server software and framework hints, and evaluates the presence or absence of key security headers. This is active recon (you are sending an HTTP request to the target) but is equivalent to what a browser does on every page load.
  1. Create the fingerprinting module. Save as recon_fingerprint.py:
    #!/usr/bin/env python3 """ recon_fingerprint.py -- HTTP header analysis and tech-stack fingerprinting. Sends GET requests to HTTP/HTTPS services and parses response headers for server software, CDN indicators, and security header presence. ACTIVE RECON: only run against authorized targets. """ import requests import re from urllib3.exceptions import InsecureRequestWarning requests.packages.urllib3.disable_warnings(InsecureRequestWarning) # Headers that reveal server software or framework DISCLOSURE_HEADERS = [ "Server", "X-Powered-By", "X-Generator", "X-AspNet-Version", "X-AspNetMvc-Version", "Via", "X-Forwarded-By", ] # Security headers and their expected presence SECURITY_HEADERS = { "Strict-Transport-Security": "HSTS", "Content-Security-Policy": "CSP", "X-Frame-Options": "Clickjacking protection", "X-Content-Type-Options": "MIME-sniff protection", "Referrer-Policy": "Referrer-Policy", "Permissions-Policy": "Permissions-Policy", } # CDN fingerprints from response headers CDN_FINGERPRINTS = { "cloudflare": "Cloudflare", "fastly": "Fastly", "akamai": "Akamai", "awselb": "AWS ELB", "x-cache": "Caching layer", "x-amz-cf-id": "AWS CloudFront", } def fingerprint_url(url: str, timeout: float = 8.0) -> dict: """ GET *url*, parse headers, return fingerprint dict. Follows redirects. Verifies TLS only for HTTPS. Known limitation: when fingerprinting by IP (e.g. http://45.33.32.156/) the request carries no Host header matching a virtual-host name, so multi-site servers may return a default vhost page rather than the intended site's headers. Pass a hostname URL (http://example.com/) when you want vhost-accurate results. """ result = { "url": url, "status_code": None, "server": None, "tech_hints": [], "cdn": None, "security_headers": {}, "missing_security_headers": [], "raw_headers": {}, "error": None, } try: resp = requests.get( url, timeout=timeout, verify=False, # accept self-signed in labs allow_redirects=True, headers={"User-Agent": "Mozilla/5.0 recon-pipeline/1.0"}, ) result["status_code"] = resp.status_code headers_lower = {k.lower(): v for k, v in resp.headers.items()} result["raw_headers"] = dict(resp.headers) # Server and framework disclosure for h in DISCLOSURE_HEADERS: val = resp.headers.get(h) if val: if h == "Server": result["server"] = val else: result["tech_hints"].append(f"{h}: {val}") # CDN detection for key, label in CDN_FINGERPRINTS.items(): if key in headers_lower: result["cdn"] = label break if not result["cdn"]: server = (result["server"] or "").lower() if "cloudflare" in server: result["cdn"] = "Cloudflare" # Security header audit for header, label in SECURITY_HEADERS.items(): val = resp.headers.get(header) if val: result["security_headers"][header] = val else: result["missing_security_headers"].append(header) except requests.exceptions.RequestException as e: result["error"] = str(e) return result def fingerprint_host(host: str, open_ports: list[dict]) -> list[dict]: """ For each open port that serves HTTP or HTTPS, fingerprint it. Returns list of fingerprint results. """ http_ports = {80, 8080, 8888} https_ports = {443, 8443} results = [] for entry in open_ports: port = entry["port"] if port in http_ports: url = f"http://{host}:{port}/" if port != 80 else f"http://{host}/" results.append(fingerprint_url(url)) elif port in https_ports: url = f"https://{host}:{port}/" if port != 443 else f"https://{host}/" results.append(fingerprint_url(url)) return results if __name__ == "__main__": import sys, json # scanme.nmap.org port 80 -- authorized target host = sys.argv[1] if len(sys.argv) > 1 else "scanme.nmap.org" open_ports = [{"port": 80}] # from Phase 4 output results = fingerprint_host(host, open_ports) print(json.dumps(results, indent=2))

SSL: CERTIFICATE_VERIFY_FAILED on HTTPS targets?
  • The module passes verify=False to skip certificate validation in lab environments with self-signed certs. For production assessments, use verify=True (the default) so TLS verification errors surface as a finding rather than being silenced.
  • requests raises ConnectionError if the host is not reachable on the specified port. Confirm the port is open from Phase 4 before passing it to fingerprint_host.
  • InsecureRequestWarning is suppressed at the top of the module. If you see a warning in your output, it means the import-time suppression ran before a different version of urllib3 was imported. This is cosmetic — the request completes successfully.
