Subject

Build a Typing Speed Test

Recruit 60 min 300 XP
Mission Brief

Your mission is to build a typing speed test entirely in a single HTML file — no libraries, no install, no command line. You will create the file in VS Code, open it by double-clicking it, and watch it work immediately in your browser.

The finished app shows a short passage of words. When you start typing, a 30-second countdown begins. Every character you type lights up green (correct) or red (wrong) in real time. When time runs out, the page shows your words per minute (WPM) and accuracy percentage. A reset button lets you try again. Your best score is saved so it persists between visits.

This project teaches the three patterns behind every interactive web page: DOM manipulation (reading and changing what the browser shows), event-driven programming (reacting to keystrokes), and timer management (counting down with setInterval). Follow each phase in order — every step is shown in full with the exact code to paste.

Agent Requirements
  • A computer with a free text editor — we recommend VS Code (code.visualstudio.com); any plain-text editor works except Microsoft Word
  • A web browser (Chrome, Firefox, or Edge)
  • No prior coding experience required — every command is shown in full and explained line by line
  • Completed “My First Web Page” or know how to create an .html file and open it in a browser; Phase 1 reviews this from scratch

The passage display area is empty because no code has filled it yet. This phase adds a word pool array and a buildPassage() function that picks 30 random words and injects them into the page as individual <span> elements — one span per character including the spaces. Each span can later receive a correct or error CSS class independently.
Why one span per character? You cannot colour part of a word without wrapping each letter individually. span.correct turns one letter green; span.error turns one letter red. If you put the whole word in one span you can only colour the whole word at once.

Wire the Timer, Input Handler, and Stats Calculator
This is the core phase. Three things happen here: the timer starts on the first keystroke and counts down every second; the input handler compares each character you type against the passage and colours the span green or red; and the stats calculator updates WPM and accuracy live, then fires the results panel when time expires. Timer never starts when I type?
  • The input event only fires when the value of the input changes. Click the input box first (give it focus), then type. If the input box is not focused the keystroke goes nowhere.
  • Open the Console and check for a red error. Cannot read properties of null (reading 'addEventListener') on the inputEl line means id="tst-input" in the HTML does not match the string 'tst-input' in the JavaScript — check for a hyphen vs underscore or any other mismatch.
WPM shows Infinity or NaN?
  • Infinity appears when you divide by zero. This happens if elapsedMin is 0 — i.e. less than one second has passed. The guard elapsedMin > 0 ? … : 0 in updateStats() prevents this. If you see Infinity, confirm that guard is present and that you did not accidentally delete it.
  • NaN means a variable that should be a number contains something else (like undefined). Check that correctCount and timerSecs are initialised to numbers (= 0 and = 30) before any event fires.
Characters are not highlighting — they stay grey?
  • Open the Console and check for a red error. If you see Cannot set properties of null on a span, the id="ch-0" naming inside buildPassage() is not matching the getElementById('ch-' + pos) lookup. Confirm sp.id = 'ch-' + i is present inside the buildPassage loop.
  • Confirm .tst-passage span.correct and .tst-passage span.error are in your CSS (from Phase 2). If you see the span getting the class but no colour appears, the CSS rule is missing or misspelled.
