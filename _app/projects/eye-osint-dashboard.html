Subject

Build an OSINT Recon Dashboard

Operative 90 min 500 XP
Authorization & Scope — Read Before You Start
  • Only run this tool against domains you own or have explicit written authorization to assess. Targeting third-party infrastructure without permission is illegal under the Computer Fraud and Abuse Act and equivalent laws worldwide.
  • All techniques in this project are passive. They query public DNS servers, the WHOIS protocol, the certificate transparency log at crt.sh, and public HTTP headers only. No ports are scanned, no credentials are tested, no active exploitation occurs.
  • Purpose is defensive. Every phase is framed as "know your own attack surface" — discover what an adversary could learn about your domain from entirely public sources, then act on any gaps you find.
  • Respect rate limits and terms of service for every public API used. Add delays between automated requests. crt.sh enforces rate limiting and may return 503 under load — the code below handles this gracefully.
  • Public data only. This project does not scrape login pages, test authentication endpoints, or access any information that is not deliberately made public by its owner.
Mission Brief

This operation builds a passive OSINT recon dashboard in Python that aggregates publicly available intelligence about a domain you own or are authorized to assess. The pipeline queries DNS records, WHOIS registration data, certificate transparency logs, and public HTTP security headers — then aggregates every finding into a self-contained Flask dashboard rendered in your browser. Zero active scanning. Zero packets sent to target infrastructure beyond a normal HTTP HEAD request for header inspection.

The goal is defensive: surface exactly what an adversary can learn about your domain from public sources in under five minutes. DNS records expose your mail infrastructure and hosting providers. WHOIS data reveals registration timelines and contact exposure. Certificate transparency logs surface every subdomain ever covered by a certificate — including development and staging hosts you may have forgotten. HTTP headers show whether you have deployed security controls like Strict-Transport-Security, Content-Security-Policy, and X-Frame-Options.

Each module is a standalone Python function. You build them one phase at a time, verify each produces real output for your domain, then wire them together into a Flask app that renders a clean single-page dashboard. The full tool is under 200 lines of Python using only four pip packages.

Agent Requirements
  • Python 3.10 or higher — confirm with python3 --version
  • Basic Python: variables, functions, for loops, import statements — no networking experience required
  • A domain name you own or have explicit written authorization to assess — use it everywhere you see yourdomain.com in the examples
  • pip access to install four packages: dnspython 2.8.0, python-whois 0.9.6, requests 2.34.2, Flask 3.1.3
  • A terminal and a text editor — no IDE required

Environment Setup & DNS Enumeration
Install the four pip packages, create the project folder, and build the DNS module that queries A, AAAA, MX, NS, and TXT records using dns.resolver.resolve() from dnspython 2.x. The resolver API changed from query() to resolve() in dnspython 2.0 — the note below covers the alias if you see a deprecation warning.
  1. Create the project folder and install packages. Run these two commands in your terminal:
    mkdir osint-dashboard cd osint-dashboard pip install dnspython==2.8.0 python-whois==0.9.6 requests==2.34.2 Flask==3.1.3
    Install takes 30–60 seconds. If pip is not found, try pip3 or python3 -m pip. On Windows, open an Administrator terminal if you encounter permission errors.
  2. Verify the install. Confirm all four packages import cleanly:
    python3 -c "import dns.resolver, whois, requests, flask; print('all packages OK')"
    Expected output:
    all packages OK
  3. Create dns_enum.py in your osint-dashboard folder and paste this complete module:
    import dns.resolver # dns.resolver.resolve() is the canonical dnspython 2.x method. # The older dns.resolver.query() still works but prints a DeprecationWarning. RECORD_TYPES = ['A', 'AAAA', 'MX', 'NS', 'TXT'] def enumerate_dns(domain): """ Query public DNS for common record types on domain. Returns a dict mapping record type to a list of string values. Handles NXDOMAIN, NoAnswer, and Timeout gracefully. """ results = {} for rtype in RECORD_TYPES: try: answers = dns.resolver.resolve(domain, rtype, lifetime=5.0) # Convert each record to a plain string for easy serialization. results[rtype] = [rdata.to_text() for rdata in answers] except dns.resolver.NXDOMAIN: results[rtype] = ['NXDOMAIN -- domain does not exist'] except dns.resolver.NoAnswer: # Domain exists but has no record of this type. results[rtype] = [] except dns.resolver.Timeout: results[rtype] = ['TIMEOUT -- resolver did not respond in 5s'] except dns.exception.DNSException as exc: results[rtype] = [f'ERROR: {exc}'] return results if __name__ == '__main__': import json # Replace with your own authorized domain. TARGET = 'yourdomain.com' data = enumerate_dns(TARGET) print(json.dumps(data, indent=2))
  4. Run it against your domain (replace yourdomain.com with your own):
    python3 dns_enum.py
    Example output for a domain using Cloudflare DNS:
    { "A": ["104.21.48.2", "172.67.181.44"], "AAAA": ["2606:4700:3035::6815:3002", "2606:4700:3034::ac43:b52c"], "MX": ["10 mail.yourdomain.com."], "NS": ["ns1.cloudflare.com.", "ns2.cloudflare.com."], "TXT": ["v=spf1 include:_spf.google.com ~all"] }
dns.resolver.NXDOMAIN for a domain that definitely exists?
  • Your system resolver may be caching a stale result. Try dns.resolver.resolve('yourdomain.com', 'A') using a specific nameserver: add resolver = dns.resolver.Resolver(); resolver.nameservers = ['8.8.8.8'] before calling resolver.resolve().
  • Double-check the domain spelling. A single typo returns NXDOMAIN.
  • If you see ImportError: cannot import name 'resolve', your installed dnspython is older than 2.0. Run pip install --upgrade dnspython==2.8.0 to fix it.
Checkpoint — what you should see
Running python3 dns_enum.py prints a JSON object with at least an A record containing one or more IP addresses for your domain. MX shows your mail server. NS shows your authoritative nameservers. Record types with no data return an empty list [] rather than crashing. If the script exits with no output, confirm the TARGET variable at the bottom was changed from yourdomain.com to your actual domain.

WHOIS Registration Lookup
Query WHOIS registration data with python-whois to surface registrar, creation date, expiration date, and nameservers. WHOIS output is notoriously inconsistent across TLDs and many domains now enable privacy protection that redacts registrant contact fields — the code below handles both cases cleanly.
  1. Create whois_lookup.py in your osint-dashboard folder:
    import whois from datetime import datetime, timezone def lookup_whois(domain): """ Query WHOIS for domain registration details. Returns a dict with registrar, dates, nameservers, and a privacy_protected flag. Always returns a dict -- never raises. """ result = { 'domain': domain, 'registrar': None, 'creation_date': None, 'expiration_date': None, 'updated_date': None, 'name_servers': [], 'privacy_protected': False, 'raw_available': False, 'error': None, } try: w = whois.whois(domain) # python-whois returns dates as datetime objects or lists of them. # Normalize to ISO 8601 string for easy display. def _normalize_date(val): if val is None: return None if isinstance(val, list): val = val[0] # take the first when multiple dates returned if isinstance(val, datetime): return val.strftime('%Y-%m-%d') return str(val) result['registrar'] = w.registrar or 'Not disclosed' result['creation_date'] = _normalize_date(w.creation_date) result['expiration_date'] = _normalize_date(w.expiration_date) result['updated_date'] = _normalize_date(w.updated_date) result['raw_available'] = bool(w.text) # Name servers come back as a list or None. ns_raw = w.name_servers or [] result['name_servers'] = [ns.lower() for ns in ns_raw if ns] # Privacy protection: registrar contact fields are redacted. # Common indicators across privacy providers. registrar_str = str(result['registrar']).lower() if any(kw in registrar_str for kw in ['privacy', 'redact', 'protect', 'whoisguard']): result['privacy_protected'] = True except whois.exceptions.PywhoisError as exc: result['error'] = f'WHOIS parse error: {exc}' except Exception as exc: result['error'] = f'Lookup failed: {exc}' return result if __name__ == '__main__': import json TARGET = 'yourdomain.com' data = lookup_whois(TARGET) print(json.dumps(data, indent=2))
  2. Run it:
    python3 whois_lookup.py
    Example output for a domain with privacy protection enabled:
    { "domain": "yourdomain.com", "registrar": "NameCheap, Inc.", "creation_date": "2021-04-17", "expiration_date": "2027-04-17", "updated_date": "2024-04-18", "name_servers": ["ns1.cloudflare.com", "ns2.cloudflare.com"], "privacy_protected": false, "raw_available": true, "error": null }
  3. Note the expiration date. If expiration_date is within 60 days of today your domain is at risk of expiring. This is a real defensive finding the dashboard will highlight in Phase 5.
WHOIS returns None for most fields or error: Lookup failed?
  • Rate limiting: WHOIS servers enforce per-IP rate limits. If you query the same domain repeatedly in quick succession, the server may return a terse response with no parsed fields. Wait 30 seconds and retry.
  • ccTLD inconsistency: Country-code TLDs (.io, .co, .uk, etc.) use non-standard WHOIS formats that python-whois may not fully parse. The raw_available flag will be true even when structured fields are null — inspect w.text directly if you need the raw record for a ccTLD.
  • Privacy protection: Domains using registrar privacy services will return null for registrant contact fields. That is expected — it means the domain owner has opted in to WHOIS privacy, which is itself a finding worth recording.
Checkpoint — what you should see
Running python3 whois_lookup.py prints a JSON object with a non-null creation_date and expiration_date for your domain, and at least one entry in name_servers. The error field is null. If registrar is Not disclosed and error is null, your domain's registrar has opted into WHOIS privacy — that is valid output, not a failure.

Certificate Transparency Subdomain Discovery
Query the crt.sh public certificate transparency log API to discover every subdomain that has ever appeared in a TLS certificate for your domain. The endpoint is https://crt.sh/?q=%25.yourdomain.com&output=json — the %25 is a URL-encoded % wildcard. Each JSON object returned has a name_value field containing the Subject Alternative Names, which may include multiple subdomains separated by newlines.
  1. Create ct_lookup.py in your osint-dashboard folder:
    import requests import time CRT_SH_URL = 'https://crt.sh/' def discover_subdomains(domain, timeout=15, max_retries=3): """ Query crt.sh certificate transparency log for all subdomains of domain. Uses the public JSON API -- no authentication required, no active probing. Returns a sorted, deduplicated list of subdomain strings. crt.sh enforces rate limits and may return 502/503 under load; this function retries up to max_retries times with exponential back-off. """ params = { 'q': f'%.{domain}', 'output': 'json', } for attempt in range(1, max_retries + 1): try: resp = requests.get( CRT_SH_URL, params=params, timeout=timeout, headers={'Accept': 'application/json'}, ) if resp.status_code == 200: break elif resp.status_code in (429, 502, 503): # Rate-limited or temporarily unavailable -- back off and retry. wait = 2 ** attempt print(f' crt.sh returned {resp.status_code}, retrying in {wait}s (attempt {attempt}/{max_retries})') time.sleep(wait) else: return { 'domain': domain, 'subdomains': [], 'count': 0, 'error': f'crt.sh returned HTTP {resp.status_code}', } except requests.exceptions.Timeout: if attempt == max_retries: return { 'domain': domain, 'subdomains': [], 'count': 0, 'error': 'Request timed out after all retries', } time.sleep(2 ** attempt) except requests.exceptions.RequestException as exc: return { 'domain': domain, 'subdomains': [], 'count': 0, 'error': str(exc), } else: return { 'domain': domain, 'subdomains': [], 'count': 0, 'error': 'crt.sh unavailable after all retries', } # Each JSON object has a 'name_value' field that may contain # multiple SANs separated by newline characters. # Fields confirmed: id, issuer_ca_id, issuer_name, common_name, # name_value, entry_timestamp, not_before, not_after. entries = resp.json() seen = set() for entry in entries: # name_value contains wildcard and SAN entries separated by \n for name in entry.get('name_value', '').split('\n'): name = name.strip().lower() # Include only names that are actual subdomains of our target # and are not wildcard placeholders. if name.endswith('.' + domain) and '*' not in name: seen.add(name) # Also capture the common_name if it is a subdomain. cn = entry.get('common_name', '').strip().lower() if cn.endswith('.' + domain) and '*' not in cn: seen.add(cn) subdomains = sorted(seen) return { 'domain': domain, 'subdomains': subdomains, 'count': len(subdomains), 'error': None, } if __name__ == '__main__': import json TARGET = 'yourdomain.com' data = discover_subdomains(TARGET) print(json.dumps(data, indent=2))
  2. Run it:
    python3 ct_lookup.py
    Example output for a domain with several subdomains in CT logs:
    { "domain": "yourdomain.com", "subdomains": [ "api.yourdomain.com", "dev.yourdomain.com", "mail.yourdomain.com", "staging.yourdomain.com", "www.yourdomain.com" ], "count": 5, "error": null }
    You may see old subdomains that no longer resolve. CT logs are permanent — a certificate issued for staging.yourdomain.com three years ago will still appear even if that subdomain was decommissioned. This is precisely the defensive value: it tells you what an adversary sees in historical logs, which is often more than what currently resolves in DNS.
  3. Cross-check a discovered subdomain. Pick one subdomain from the output and confirm whether it still resolves in DNS:
    python3 -c "import dns.resolver; print(dns.resolver.resolve('api.yourdomain.com', 'A'))"
    If it raises NXDOMAIN, the subdomain existed historically in certificates but has no current DNS record — a ghost in the logs.
Script returns "error": "crt.sh unavailable after all retries"?
  • crt.sh is a free public service that sometimes experiences load spikes. The built-in retry logic handles transient 502/503 errors but cannot recover from prolonged outages. Wait 5–10 minutes and try again.
  • Confirm you have internet access: curl -s "https://crt.sh/?q=example.com&output=json" | python3 -m json.tool | head -20
  • If the domain is very new (registered in the last few days), it may have no CT log entries yet. New domains only appear after a TLS certificate has been issued and logged.
Checkpoint — what you should see
Running python3 ct_lookup.py prints a JSON object with a non-empty subdomains list and a positive count. At minimum you should see www.yourdomain.com if your domain has ever had a TLS certificate. The error field is null. If count is 0 and error is null, your domain has no entries in certificate transparency logs — either it has never had a TLS certificate issued, or you queried a domain that has never been public-facing.

HTTP Security Header Inspection
Send a single HTTPS GET request to your domain's root URL and inspect the response headers for the presence or absence of key security controls. This is framed as "are my security headers deployed?" not as active probing — it is the same request your browser makes every time a user visits the site.
  1. Create header_check.py in your osint-dashboard folder:
    import requests # The six headers every public HTTPS site should set. SECURITY_HEADERS = [ 'Strict-Transport-Security', 'Content-Security-Policy', 'X-Frame-Options', 'X-Content-Type-Options', 'Referrer-Policy', 'Permissions-Policy', ] # Informational headers that reveal server technology stack. TECH_HEADERS = [ 'Server', 'X-Powered-By', 'X-AspNet-Version', 'X-Generator', ] def inspect_headers(domain, timeout=10): """ Send one HTTPS GET to https://domain and inspect response headers. Returns a dict with: - security_headers: present/absent status for each security header - tech_headers: values of technology-revealing headers (or None) - final_url: the URL after any redirects - status_code: HTTP status of the final response - error: None on success, string on failure """ url = f'https://{domain}' result = { 'url': url, 'final_url': None, 'status_code': None, 'security_headers': {}, 'tech_headers': {}, 'error': None, } try: resp = requests.get( url, timeout=timeout, # Follow redirects (http -> https, www -> non-www, etc.) allow_redirects=True, # Identify as a standard browser request -- some servers # return different headers for unrecognized user agents. headers={'User-Agent': 'Mozilla/5.0 (compatible; security-header-check/1.0)'}, ) result['final_url'] = resp.url result['status_code'] = resp.status_code # Check security headers -- report present=True/False and value. for header in SECURITY_HEADERS: value = resp.headers.get(header) result['security_headers'][header] = { 'present': value is not None, 'value': value, } # Report technology-revealing headers. for header in TECH_HEADERS: result['tech_headers'][header] = resp.headers.get(header) except requests.exceptions.SSLError as exc: result['error'] = f'SSL/TLS error: {exc}' except requests.exceptions.ConnectionError as exc: result['error'] = f'Connection failed: {exc}' except requests.exceptions.Timeout: result['error'] = f'Request timed out after {timeout}s' except requests.exceptions.RequestException as exc: result['error'] = str(exc) return result if __name__ == '__main__': import json TARGET = 'yourdomain.com' data = inspect_headers(TARGET) print(json.dumps(data, indent=2))
  2. Run it:
    python3 header_check.py
    Example output showing a site missing two security headers:
    { "url": "https://yourdomain.com", "final_url": "https://yourdomain.com/", "status_code": 200, "security_headers": { "Strict-Transport-Security": { "present": true, "value": "max-age=31536000; includeSubDomains" }, "Content-Security-Policy": { "present": false, "value": null }, "X-Frame-Options": { "present": true, "value": "SAMEORIGIN" }, "X-Content-Type-Options": { "present": true, "value": "nosniff" }, "Referrer-Policy": { "present": false, "value": null }, "Permissions-Policy": { "present": true, "value": "geolocation=()" } }, "tech_headers": { "Server": "cloudflare", "X-Powered-By": null, "X-AspNet-Version": null, "X-Generator": null }, "error": null }
    Missing security headers are real findings. A missing Content-Security-Policy means your site has no XSS protection policy declared. Missing Strict-Transport-Security means browsers are not forced to use HTTPS on subsequent visits. These are actionable gaps you can fix by updating your web server or CDN configuration.
  3. Count the gaps. Run this one-liner to tally how many security headers are missing:
    python3 -c " import json, header_check d = header_check.inspect_headers('yourdomain.com') missing = [h for h,v in d['security_headers'].items() if not v['present']] print(f'Missing {len(missing)}/6 security headers: {missing}') "
Script returns SSL/TLS error?
  • Your domain may not have a valid TLS certificate, or the certificate is expired or self-signed. This is itself a significant security finding to record.
  • To confirm, open https://yourdomain.com in a browser. If you see a certificate warning, the SSL error in the script is accurate.
  • To inspect a site that only serves HTTP (not HTTPS), change the URL prefix in the function from https:// to http:// for testing purposes — note that a site not serving HTTPS at all is a critical gap.
Checkpoint — what you should see
Running python3 header_check.py prints a JSON object with status_code: 200 (or a 3xx redirect) and a populated security_headers dict showing true or false for each header. At least one of Server, X-Powered-By, or X-Generator in tech_headers will be non-null for most real sites. The error field is null. Review which security headers your domain is missing — those are actionable findings.

Flask Dashboard — Aggregate & Render
Wire all four modules into a single Flask application that accepts a domain as a URL parameter, runs the pipeline, and renders a clean HTML dashboard summarizing every finding. The full app is under 60 lines of Python.
  1. Create app.py in your osint-dashboard folder:
    from flask import Flask, request, render_template_string from dns_enum import enumerate_dns from whois_lookup import lookup_whois from ct_lookup import discover_subdomains from header_check import inspect_headers from datetime import date from urllib.parse import urlparse app = Flask(__name__) DASHBOARD_TEMPLATE = """ OSINT Report: {{ domain }}

    OSINT Recon Dashboard

    Passive / public sources only — DNS, WHOIS, Certificate Transparency, HTTP headers. Only run against domains you own or have written authorization to assess.

    {% if domain %}

    1. DNS Records

    {% for rtype, records in dns_data.items() %}
    {{ rtype }} {% if records %} {% for r in records %} {{ r }}{% endfor %} {% else %} no records {% endif %}
    {% endfor %}

    2. WHOIS Registration

    {% if whois_data.error %} Error: {{ whois_data.error }} {% else %}
    Registrar: {{ whois_data.registrar or 'Not disclosed' }}
    Created: {{ whois_data.creation_date or 'Unknown' }}
    Expires: {% if whois_data.expiration_date %} {{ whois_data.expiration_date }} {% if days_to_expire is not none %} ({{ days_to_expire }} days) {% endif %} {% else %} Unknown {% endif %}
    Nameservers: {% for ns in whois_data.name_servers %} {{ ns }}{% endfor %}
    {% if whois_data.privacy_protected %}
    Privacy protection detected on registrar record.
    {% endif %} {% endif %}

    3. Certificate Transparency Subdomains

    {% if ct_data.error %} Error: {{ ct_data.error }} {% elif ct_data.count == 0 %} No subdomains found in CT logs. {% else %}
    {{ ct_data.count }} subdomain(s) found in public CT logs:
    {% for sub in ct_data.subdomains %}
    {{ sub }}
    {% endfor %} {% endif %}

    4. HTTP Security Headers

    {% if header_data.error %} Error: {{ header_data.error }} {% else %}
    {{ header_data.final_url }} — HTTP {{ header_data.status_code }}
    {% for header, info in header_data.security_headers.items() %}
    {{ 'OK' if info.present else 'MISSING' }} {{ header }} {% if info.value %} — {{ info.value[:80] }}{% endif %}
    {% endfor %} {% if header_data.tech_headers.Server %}
    Server header: {{ header_data.tech_headers.Server }}
    {% endif %} {% endif %}
    {% endif %} """ @app.route('/') def dashboard(): """ Render the OSINT dashboard for the domain query parameter. Runs the full passive pipeline on each request. """ domain = request.args.get('domain', '').strip().lower() # Normalize user input: handle full URLs like https://example.com/some/path. # A sequential prefix-strip loop leaves the path intact, so urlparse is used # instead to correctly extract just the hostname. if domain: raw = domain if '://' in domain else 'https://' + domain host = urlparse(raw).hostname or domain if host.startswith('www.'): host = host[4:] domain = host dns_data = {} whois_data = {} ct_data = {} header_data = {} days_to_expire = None if domain: dns_data = enumerate_dns(domain) whois_data = lookup_whois(domain) ct_data = discover_subdomains(domain) header_data = inspect_headers(domain) # Calculate days until domain expires for expiration warning. exp = whois_data.get('expiration_date') if exp: try: from datetime import datetime exp_date = datetime.strptime(exp, '%Y-%m-%d').date() days_to_expire = (exp_date - date.today()).days except ValueError: days_to_expire = None return render_template_string( DASHBOARD_TEMPLATE, domain=domain, dns_data=dns_data, whois_data=whois_data, ct_data=ct_data, header_data=header_data, days_to_expire=days_to_expire, ) if __name__ == '__main__': # debug=True reloads the app on code changes -- use only locally. app.run(debug=True, port=5000)
  2. Run the Flask app:
    python3 app.py
    Expected terminal output:
    * Running on http://127.0.0.1:5000 * Debug mode: on
  3. Open the dashboard in your browser. Navigate to:
    http://127.0.0.1:5000/?domain=yourdomain.com
    The page runs all four pipeline modules and renders the aggregated findings. The first load will take 5–15 seconds as the WHOIS and crt.sh calls complete.
  4. Review the findings panel by panel in order: DNS records, WHOIS registration (note the expiration warning if applicable), CT subdomains (look for any forgotten staging or dev hosts), HTTP headers (any red MISSING badges are real security gaps to remediate).
  5. Stop the app when done: press Ctrl+C in the terminal.
ImportError when starting app.py?
  • Confirm all four module files (dns_enum.py, whois_lookup.py, ct_lookup.py, header_check.py) are in the same folder as app.py.
  • If Flask is not found, confirm it was installed: python3 -m flask --version. If the command fails, re-run pip install Flask==3.1.3.
  • Port 5000 already in use? Change port=5000 to port=5001 (or any free port) in the app.run() call and update the browser URL accordingly.
Defensive hygiene — validate domain input before using it as a network target. The dashboard above is for local, authorized use only, but it is good practice to understand why production tools always validate domain format before making outbound requests. A bare input of localhost, 127.0.0.1, or 169.254.169.254 (the AWS metadata endpoint) would direct the tool’s lookups at internal infrastructure rather than a public domain — a class of vulnerability known as Server-Side Request Forgery (SSRF). A simple guard that rejects inputs not matching a public-domain pattern closes this gap entirely. Add the following check at the top of the if domain: block in app.py before calling any lookup function:
import re DOMAIN_RE = re.compile(r'^[A-Za-z0-9]([A-Za-z0-9\-]{0,61}[A-Za-z0-9])?(\.[A-Za-z0-9]([A-Za-z0-9\-]{0,61}[A-Za-z0-9])?)*\.[A-Za-z]{2,}$') if not DOMAIN_RE.match(domain): return "Invalid domain", 400
This rejects loopback addresses, bare hostnames without a TLD, and any input that does not look like a valid public domain name — consistent with the ethics and passive-only framing throughout this project.

Navigating to http://127.0.0.1:5000/?domain=yourdomain.com loads a dark-themed dashboard with four labelled sections. Section 1 shows DNS records. Section 2 shows your registrar and expiration date (with a yellow warning if expiry is within 60 days). Section 3 lists subdomains from CT logs. Section 4 shows green OK badges for present security headers and red MISSING badges for absent ones. No stack traces appear in the terminal during a normal run. You now have a complete passive OSINT attack-surface snapshot of your own domain built from entirely public data.
