Subject

Build a Flashcard Study Engine

Beginner 60 min 250 XP
Mission Brief

Your objective is to engineer a fully functional command-line flashcard study engine in Python. Starting from a structured JSON deck file, you will construct the complete study pipeline: loading cards into memory, presenting questions to the operator, evaluating typed responses, and tracking performance metrics across each session.

The primary engineering challenge is implementing a simplified version of the SM-2 spaced-repetition algorithm — the same scheduling logic that powers tools like Anki. Cards answered correctly get pushed further into the future; cards the operator struggles with resurface sooner. By the end of this operation, you will have a system that genuinely adapts its review schedule based on demonstrated recall.

Along the way you will practice field-tested Python patterns: loading structured data with the json module, persisting progress files between sessions, handling user input with proper normalization, and building a scoring engine with streak tracking. These are foundational techniques that surface constantly in backend tooling, automation scripts, and engineering infrastructure.

Agent Requirements
  • Python 3 basics — variables, functions, loops, conditionals
  • Familiarity with Python dictionaries and lists
  • Understanding of reading and writing files in Python
  • Comfort using the terminal to run a Python script
Operation Phases
1
Card Data Model and Deck Loading
Define the data structure for a flashcard and write a loader that reads a JSON deck file into memory. Validate the schema and handle missing or malformed entries gracefully.
2
Quiz Loop — Display, Input, and Evaluation
Build the core study loop: display a question, accept a typed answer, and compare it against the correct response. Handle case normalization and whitespace trimming so minor variations do not count as wrong.
3
Scoring Engine with Streak Tracking
Add a session scoring system that tracks correct answers, wrong answers, and the current streak. Display live feedback after each card and print a summary table when the session ends.
4
Spaced Repetition Scheduling (SM-2 Simplified)
Implement a stripped-down version of the SM-2 algorithm. Each card stores an interval and an ease factor. Correct answers push the next review date further out; incorrect answers reset the card. Use datetime to schedule and filter due cards.
5
Progress Persistence and Session Summary
Save each card's scheduling state back to a progress JSON file at the end of every session. On startup, load that file so the engine remembers what is due. Print a final summary showing total cards reviewed, accuracy rate, and the next scheduled review date.
