Subject

Deploy an API Behind Nginx

Intermediate 90 min 500 XP
Mission Brief

Your assignment is to deploy a backend API behind an Nginx reverse proxy — the exact architecture used in production at companies from startups to Fortune 500. Nginx sits in front of your application servers, handling SSL termination, request caching, rate limiting, and load balancing so your API code only has to worry about business logic.

You will configure Nginx as a reverse proxy that forwards client requests to one or more upstream API servers running on internal ports. You will add HTTPS using a self-signed certificate (or Let's Encrypt for a real domain), set up rate limiting to protect against abuse, enable response caching for read-heavy endpoints, and configure load balancing across multiple backend instances.

The emphasis is on understanding the request lifecycle: a client hits Nginx on port 443, the TLS handshake terminates, Nginx checks its cache, applies rate limits, selects an upstream server, forwards the request over HTTP, and returns the response with proper headers. By the end, you will have a production-grade reverse proxy configuration you can use on any project.

Agent Requirements
  • Nginx installed (nginx -v returns a version number)
  • A simple backend API (Node.js, Python Flask, or any HTTP server on a local port)
  • Basic understanding of HTTP: methods, status codes, headers
  • Familiarity with editing config files and restarting services
  • Comfort with curl for testing HTTP requests from the terminal
Operation Phases
1
Basic Reverse Proxy Configuration
Start a simple API server on localhost:3000. Write an Nginx server block that listens on port 80 and uses proxy_pass http://localhost:3000; to forward all requests. Add proxy_set_header directives for Host, X-Real-IP, and X-Forwarded-For. Test with curl http://localhost.
2
SSL/TLS Termination with HTTPS
Generate a self-signed certificate with openssl req -x509 (or use Let's Encrypt via certbot for a real domain). Configure Nginx to listen on port 443 with ssl_certificate and ssl_certificate_key. Add a redirect block that sends all HTTP port 80 traffic to HTTPS. Verify with curl -k https://localhost.
3
Rate Limiting to Protect the API
Define a limit_req_zone in the http context keyed by $binary_remote_addr with a rate of 10 requests per second. Apply limit_req in your location block with a burst=20 and nodelay. Test by sending rapid requests with a loop and confirm that excess requests receive a 503.
4
Load Balancing Across Multiple Backends
Start three instances of your API on ports 3001, 3002, and 3003. Define an upstream block listing all three servers. Configure the load balancing method: start with round-robin (default), then try least_conn and ip_hash. Add health checks with max_fails and fail_timeout. Watch logs to confirm traffic distribution.
5
Response Caching and Access Logging
Configure proxy_cache_path with a 10MB zone and a 5-minute expiry. Add proxy_cache and proxy_cache_valid directives to cache GET responses. Add an X-Cache-Status header using add_header so you can see HIT/MISS in responses. Set up structured access logging with log_format to capture request time, upstream response time, and cache status.
