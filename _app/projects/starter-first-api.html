Subject

My First API

Recruit 30 min 250 XP
Mission Brief

Build your first web API with Python and Flask — create endpoints that return data, accept input, and respond to the world. This is where backend development begins: a running HTTP server that speaks JSON and listens for requests from any client on earth.

You will install Flask, wire up routes, handle URL parameters and query strings, and finally accept POST data — the four pillars of every REST API ever built. By the end you will have a live local server with five working endpoints and a mental model of how every API on the internet actually functions.

This project uses nothing but Python and a browser. No databases, no authentication, no deployment — just the raw mechanics of request in, JSON out, the loop that powers every web service from Twitter to GitHub to AWS.

Agent Requirements
  • Python 3 installed — open a terminal and run python --version (Windows) or python3 --version (Mac/Linux). You need version 3.8 or higher. If it prints a version number you are ready. (Phase 1 walks through installing it if you don't have it.)
  • VS Code — free editor from code.visualstudio.com. Any plain-text editor works, but VS Code highlights Python errors as you type. Not Microsoft Word.
  • A terminal — Windows: Command Prompt, PowerShell, or the terminal built into VS Code. Mac: Terminal app. Linux: any shell. Phase 1 shows how to open one.
  • A web browser — Chrome, Firefox, or Edge. You will use it to test GET endpoints by visiting a URL, exactly like visiting a web page.
  • No prior Python experience required — every line of code is shown in full and explained. If you can copy and paste, you can complete this project.

Set Up Python and Install Flask
Before writing a single line of API code you need Python and Flask on your machine. Go slowly — nothing here assumes you've done it before.
  1. Check whether Python is already installed. Open a terminal (Windows: press Windows key, type cmd, press Enter — or open VS Code and press Ctrl+` to open its built-in terminal. Mac: open Applications → Utilities → Terminal). Type this and press Enter:
    python --version
    If it prints something like Python 3.12.3 you are ready. On Mac or Linux you may need to type python3 --version instead. Either works — just remember which word your machine responds to (you'll use the same word in every step).
    No output, or "python is not recognized"? Python is not installed. Download the installer from python.org/downloads, run it, and on the first screen check "Add Python to PATH" before clicking Install. Then close and reopen your terminal and run python --version again. On Windows, the py launcher also works: try py --version.
  2. Make a project folder. Using File Explorer (Mac: Finder), right-click your Desktop → New → Folder, and name it my-first-api (no spaces, all lowercase). All your files go in here.
  3. Open that folder in VS Code. In VS Code choose File → Open Folder, navigate to your Desktop, select my-first-api, and click Open. The folder name appears in the left panel.
  4. Open the VS Code terminal. Press Ctrl+` (the backtick key, top-left on most keyboards — Mac: Ctrl+` or Terminal → New Terminal). A terminal panel opens at the bottom of VS Code. It is already in your my-first-api folder.
  5. Install Flask. In the terminal, type this and press Enter:
    pip install flask
    You will see several lines of output as Flask and its dependencies download. Wait for it to finish — it usually takes 10–30 seconds. The last line will say something like Successfully installed flask-3.x.x ....
    "pip is not recognized" or "pip: command not found"? Try one of these alternatives instead — use whichever matches how Python responds on your machine:
    • python -m pip install flask
    • python3 -m pip install flask
    • py -m pip install flask (Windows py launcher)
    If you get a permissions error on Mac/Linux, add --user at the end: python3 -m pip install flask --user.
    Flask installed successfully but python app.py still says "ModuleNotFoundError: No module named 'flask'"? pip may have installed Flask into a different Python version than the one your terminal runs when you type python. The safest fix is to install using the same interpreter you use to run the file: replace pip install flask with python -m pip install flask (or python3 -m pip install flask on Mac, or py -m pip install flask on Windows). When it finishes, confirm the install landed correctly by running python -m flask --version — you should see Flask 3.x.x. If that prints a version, python app.py will now find Flask.
  6. Create your Python file. In VS Code's left panel, hover over the folder name — small icons appear — and click the New File icon (a page with a +). Type app.py and press Enter. This file is your entire API.
  7. Paste the starter code. Click inside the empty app.py file and paste this exactly:
    from flask import Flask, jsonify app = Flask(__name__) @app.route('/') def home(): return jsonify({"message": "Hello, World!"}) if __name__ == '__main__': app.run(debug=True)
    What each part means: from flask import Flask, jsonify loads Flask and the tool that converts Python data to JSON. app = Flask(__name__) creates your API application. @app.route('/') is a decorator — it tells Flask "when someone visits the address /, run the function below it." jsonify({...}) takes a Python dictionary (curly braces with key-value pairs) and turns it into a proper JSON response the browser can read. if __name__ == '__main__': app.run(debug=True) starts the server when you run the file; debug=True means Flask will reload automatically when you save a change.
  8. Save and run your API. Save with Ctrl+S (Mac: Cmd+S). In the terminal type:
    python app.py
    (Use python3 app.py or py app.py if that is what your machine uses.) Flask prints several lines ending with:
    * Running on http://127.0.0.1:5000 * Debug mode: on
    Your API is now live on your own computer. Leave this terminal running — do not close it. To stop the server later press Ctrl+C.
  9. Open your browser and visit your API. Open Chrome, Firefox, or Edge. In the address bar type:
    http://localhost:5000
    and press Enter. The browser shows the JSON response your function returned.
Checkpoint — what you should see
The browser displays: {"message": "Hello, World!"} — plain JSON text on the screen. At the same time, your terminal shows a new line like 127.0.0.1 - - [18/Jun/2026 ...] "GET / HTTP/1.1" 200 - — that is the request log confirming Flask received your visit and answered with status 200 (success). If you see those two things, your API is running.
Browser shows "This site can't be reached" or "Connection refused"?
  • The server is not running — go back to the terminal and run python app.py again.
  • Make sure you typed http://localhost:5000 (not https:// and not port 3000).
  • On some machines port 5000 is already in use. Flask will print an error like Address already in use. To use a different port, change app.run(debug=True) to app.run(debug=True, port=5001) and visit http://localhost:5001 instead.
  • On macOS Monterey or later AirPlay uses port 5000. Go to System Settings → AirDrop & Handoff and turn off AirPlay Receiver, or use port=5001 as above.

Add More Routes — /about and /time
Right now your API only answers at one address (/). Real APIs have many addresses — each one is called a route or endpoint. You will add two more: one that returns information about yourself, and one that returns the current time generated live by Python. Each new route is just another decorated function added to app.py.
  1. Add the /about route. Go back to app.py in VS Code. Click at the end of the closing curly brace of your home() function (the line that says return jsonify(...)). Press Enter twice to leave a blank line between functions, then paste these lines:
    @app.route('/about') def about(): return jsonify({ "name": "Alex", "role": "API builder", "language": "Python" })
    Change "Alex" to your own name and the other values to whatever you like. The structure — the @app.route line followed immediately by def — is exactly the same pattern as the home route.
    About indentation: Python uses spaces to group code. Every line inside a function must be indented by exactly 4 spaces from the left edge. VS Code does this automatically when you press Enter after a def ...() line ending in a colon. If you see an IndentationError in the terminal, delete the offending line and let VS Code re-indent it.
  2. Add one import line at the top of the file. The next route uses Python's built-in datetime module. Find the very first line of app.py — from flask import Flask, jsonify — and add this line right below it:
    from datetime import datetime
  3. Add the /time route below your /about function (leave one blank line between them):
    @app.route('/time') def current_time(): now = datetime.now().strftime("%Y-%m-%d %H:%M:%S") return jsonify({"current_time": now})
    datetime.now() reads the current date and time from your computer's clock. .strftime("%Y-%m-%d %H:%M:%S") formats it as a readable string such as 2026-06-18 14:32:05.
  4. Your complete app.py now:
    app.py — full filefrom flask import Flask, jsonify from datetime import datetime app = Flask(__name__) @app.route('/') def home(): return jsonify({"message": "Hello, World!"}) @app.route('/about') def about(): return jsonify({ "name": "Alex", "role": "API builder", "language": "Python" }) @app.route('/time') def current_time(): now = datetime.now().strftime("%Y-%m-%d %H:%M:%S") return jsonify({"current_time": now}) if __name__ == '__main__': app.run(debug=True)
  5. Save and let Flask reload. Save with Ctrl+S (Mac: Cmd+S). Because the server is running with debug=True Flask detects the change and restarts automatically — you will see * Restarting with stat in the terminal. You do not need to stop and restart manually.
    Terminal shows a Python error after saving? Read the last line. SyntaxError means a typo such as a missing colon, a misplaced parenthesis, or wrong indentation. NameError: name 'datetime' is not defined means the import line at the top is missing or misspelled. Fix the line, save again, and Flask will retry.
  6. Test both endpoints in your browser. Visit each address in the browser address bar:
    http://localhost:5000/about
    http://localhost:5000/time
Checkpoint — what you should see
/about shows JSON with your name, role, and language — something like {"language": "Python", "name": "Alex", "role": "API builder"} (Flask alphabetizes keys by default, which is normal). /time shows {"current_time": "2026-06-18 14:32:05"} with today's actual date and time. Press refresh on /time a few seconds later — the seconds tick forward. That proves the value is generated live each time, not hardcoded. If either endpoint shows a 404 page, check that the function name and the route string match exactly and that there are no typos.

Accept Input — URL Parameters and Query Strings
So far every endpoint returns the same answer every time. Real APIs are dynamic — you pass them data and they respond based on what you sent. You will add two routes that accept input from the URL itself: one using a path parameter (a value embedded in the URL like /greet/Maria), and one using a query string (values after a ? like /add?a=5&b=3). Both patterns appear in every real-world API on the internet.
  1. Update your import line. At the top of app.py, find the line from flask import Flask, jsonify and add request to the list so it reads:
    from flask import Flask, jsonify, request
    request gives your functions access to what the caller sent — URL data, headers, body — whenever someone visits one of your endpoints.
  2. Add the /greet/<name> route. The angle brackets in the route string tell Flask: "this part of the URL is a variable." Flask captures whatever the caller types there and passes it to your function as an argument with the same name. Paste this below your /time function:
    @app.route('/greet/<name>') def greet(name): return jsonify({"greeting": "Hello, " + name + "!"})
    What the angle brackets do: when a browser visits /greet/Maria, Flask sees the pattern /greet/<name>, extracts Maria, and passes it to greet(name) as the string "Maria". The plus signs (+) join strings together in Python: "Hello, " + "Maria" + "!" produces "Hello, Maria!".
  3. Add the /add route. Query strings are the ?key=value&key2=value2 part of a URL. request.args.get("a") reads the value of a from the query string. Values from URLs are always strings, so you must convert them to integers with int() before doing math. Paste this below your /greet function:
    @app.route('/add') def add(): a = int(request.args.get("a", 0)) b = int(request.args.get("b", 0)) return jsonify({"result": a + b})
    The second argument to .get("a", 0) is a default value: if the caller forgets to include a in the URL, the value defaults to 0 instead of crashing.
  4. Your full app.py now:
    app.py — full filefrom flask import Flask, jsonify, request from datetime import datetime app = Flask(__name__) @app.route('/') def home(): return jsonify({"message": "Hello, World!"}) @app.route('/about') def about(): return jsonify({ "name": "Alex", "role": "API builder", "language": "Python" }) @app.route('/time') def current_time(): now = datetime.now().strftime("%Y-%m-%d %H:%M:%S") return jsonify({"current_time": now}) @app.route('/greet/<name>') def greet(name): return jsonify({"greeting": "Hello, " + name + "!"}) @app.route('/add') def add(): a = int(request.args.get("a", 0)) b = int(request.args.get("b", 0)) return jsonify({"result": a + b}) if __name__ == '__main__': app.run(debug=True)
  5. Save (Ctrl+S / Cmd+S) and wait for Flask to auto-reload in the terminal.
  6. Test in your browser:
    http://localhost:5000/greet/Maria
    http://localhost:5000/greet/Jordan
    http://localhost:5000/add?a=5&b=3
    http://localhost:5000/add?a=100&b=250
    Try different names and numbers each time.
Checkpoint — what you should see
Visiting /greet/Maria returns {"greeting": "Hello, Maria!"}. Visiting /greet/Jordan returns {"greeting": "Hello, Jordan!"}. The response changes based on what you typed in the URL — that is a dynamic API. /add?a=5&b=3 returns {"result": 8}. /add?a=100&b=250 returns {"result": 350}.
ValueError: invalid literal for int() with base 10? This crash happens when the query-string value is not a valid integer — for example, visiting /add?a=hello&b=3. The 0 defaults handle a completely missing parameter, but int("hello") still raises a ValueError. When Flask is in debug mode this shows as a full error page in the browser; the server is still running — you have not broken anything, you just sent bad input. Go back and use valid numbers. For now, always include numeric values in the query string. Handling invalid input with proper error messages is a real API skill covered in more advanced courses.
404 on /greet/Maria? Check that your route string in the code uses angle brackets exactly: '/greet/<name>'. If you typed /greet/{name} (curly braces) Flask will not recognize it as a dynamic route.
✓

Accept POST Data — Send Data to Your API
Every endpoint so far has only read data from a URL. The other half of an API is accepting data that a caller sends. That uses the POST method — the caller sends a JSON body and your server processes it. You will build a simple notes endpoint: POST a note to save it, GET all notes to retrieve them. This is the create-and-retrieve pattern that powers todo lists, message boards, form submissions, and most of what the web does.
What is a POST request? So far every request your browser made was a GET — "give me the data at this address." A POST is "here is data I want you to store or process." Browsers send GETs when you type a URL. Sending a POST requires a tool that lets you include a body — you will use curl, which is already installed on Windows, Mac, and Linux.
  1. Add a notes list above your routes. Open app.py. Find the line app = Flask(__name__) and add one blank line below it, then paste:
    notes = []
    This creates a list at the module level — meaning it is shared across all requests. While the server is running, every POST adds to this list and every GET reads from it.
  2. Add the /note route. This route handles both GET and POST. You declare that by passing methods=['GET', 'POST'] to the decorator. Paste this below your /add function:
    @app.route('/note', methods=['GET', 'POST']) def note(): if request.method == 'POST': data = request.get_json() if data is None: return jsonify({"error": "Send JSON with Content-Type: application/json"}), 400 text = data.get("text", "") notes.append(text) return jsonify({"saved": True, "note": text}), 201 return jsonify({"notes": notes})
    Line by line: request.method == 'POST' checks which verb was used. request.get_json() reads the JSON body the caller sent and returns it as a Python dictionary — but returns None if the Content-Type: application/json header is missing. The if data is None guard catches that case and returns a clear 400 error instead of crashing. data.get("text", "") extracts the value of the key "text" from the dictionary (defaulting to an empty string if it is missing). notes.append(text) adds it to the shared list. Returning 201 as a second value tells Flask to use HTTP status code 201 (Created) instead of the default 200 — the correct status for "I created a new resource." If the method is GET, the if block is skipped and the function returns all saved notes.
  3. Your final app.py:
    app.py — complete final filefrom flask import Flask, jsonify, request from datetime import datetime app = Flask(__name__) notes = [] @app.route('/') def home(): return jsonify({"message": "Hello, World!"}) @app.route('/about') def about(): return jsonify({ "name": "Alex", "role": "API builder", "language": "Python" }) @app.route('/time') def current_time(): now = datetime.now().strftime("%Y-%m-%d %H:%M:%S") return jsonify({"current_time": now}) @app.route('/greet/<name>') def greet(name): return jsonify({"greeting": "Hello, " + name + "!"}) @app.route('/add') def add(): a = int(request.args.get("a", 0)) b = int(request.args.get("b", 0)) return jsonify({"result": a + b}) @app.route('/note', methods=['GET', 'POST']) def note(): if request.method == 'POST': data = request.get_json() if data is None: return jsonify({"error": "Send JSON with Content-Type: application/json"}), 400 text = data.get("text", "") notes.append(text) return jsonify({"saved": True, "note": text}), 201 return jsonify({"notes": notes}) if __name__ == '__main__': app.run(debug=True)
  4. Save (Ctrl+S / Cmd+S) and wait for Flask to reload in the terminal.
  5. Test GET first — in your browser: Visit http://localhost:5000/note. The list is empty so you will see:
    {"notes": []}
    That is correct — no notes yet.
  6. Send a POST request with curl. Open a new terminal window (keep the one running Flask open). On Mac and Linux, paste this command exactly:
    curl -X POST http://localhost:5000/note \ -H "Content-Type: application/json" \ -d '{"text": "My first note"}'
    On Windows Command Prompt use double quotes for the JSON body (single quotes are not supported):
    curl -X POST http://localhost:5000/note -H "Content-Type: application/json" -d "{\"text\": \"My first note\"}"
    On Windows PowerShell, type curl in PowerShell and it becomes an alias for Invoke-WebRequest, which uses different flags and returns a response object rather than printing the JSON directly. To use the real curl binary and get the same output as the other platforms, use the .exe suffix to bypass the alias:
    curl.exe -X POST http://localhost:5000/note -H "Content-Type: application/json" -d "{\"text\": \"My first note\"}"
    The terminal should print back:
    {"note": "My first note", "saved": true}
    What -X POST does: tells curl to use the POST method instead of GET. -H "Content-Type: application/json" adds a header telling Flask "the body I'm sending is JSON." -d '{"text": "My first note"}' is the body data. In PowerShell the inner quotes in the JSON body must be escaped as \" because the outer delimiters are double quotes.
  7. Check that the note was saved. Go back to your browser and visit:
    http://localhost:5000/note
    You should now see:
    {"notes": ["My first note"]}
  8. Send a second note with curl (change the text), then visit /note in the browser again. Both notes appear in the list.
Checkpoint — what you should see
After sending two POST requests, visiting http://localhost:5000/note in the browser returns {"notes": ["My first note", "Second note"]} — both notes in the list. The list grows with each POST and survives as long as the server is running. Stop the server (Ctrl+C) and restart it and the list empties — because data is stored in memory, not on disk. That is expected and is the foundation of every create-and-retrieve API pattern. Note also that because Flask auto-reloads whenever you save app.py (the convenience from Phase 2), saving the file while the server is running also resets the in-memory notes list — that is not a bug, just a side-effect of the reload; only notes added since the last save are kept. You have built a working REST API from scratch.
curl: command not found? On Windows, curl is built into Command Prompt and PowerShell since Windows 10. If it is missing, install it from curl.se/windows. Alternatively, use Postman (free at postman.com): create a new request, set method to POST, URL to http://localhost:5000/note, choose Body → raw → JSON, and paste {"text": "My first note"}.
curl returns nothing, or "Failed to connect"? Confirm Flask is still running in the other terminal window — it may have crashed after a syntax error. Read the error, fix the code, save, and Flask will restart. Then try curl again.
Browser shows {"notes": []} even after you ran curl? Check that the curl command actually printed {"saved": true, ...}. If it printed an error, the POST did not reach Flask. If it did print success but the browser still shows an empty list, make sure notes = [] is at the module level (not inside a function) in app.py.
curl prints a 500 error or Flask's terminal shows AttributeError: 'NoneType' object has no attribute 'get'? This means request.get_json() returned None because the request was sent without the Content-Type: application/json header. Flask cannot parse the body as JSON without that header, so it returns None and the next line crashes. The if data is None guard in the route code above catches this and returns a clear 400 message instead. Make sure your curl command includes -H "Content-Type: application/json" exactly as shown.
