Subject

Manage Infrastructure with Terraform

Intermediate 150 min 700 XP
Mission Brief

Your assignment is to provision and manage cloud infrastructure entirely through code using HashiCorp Terraform. Instead of clicking through a cloud console, you will define every resource — VPCs, subnets, security groups, compute instances — in declarative .tf files written in HCL (HashiCorp Configuration Language).

You will follow the standard Terraform workflow: terraform init to install the provider, terraform plan to preview changes, and terraform apply to execute them. State is tracked in a terraform.tfstate file that records what exists in the real world. You will learn to read the plan diff, manage state safely, and use modules to organize reusable infrastructure blocks.

The emphasis is on the infrastructure-as-code mindset: your .tf files are the single source of truth, versioned in Git, reviewed in pull requests, and applied through a pipeline. By the end of this operation, you will be able to spin up a full network + compute stack from scratch with a single command.

Agent Requirements
  • Terraform CLI installed (terraform version returns 1.x)
  • A cloud provider account (AWS free tier, GCP, or Azure) or LocalStack for local simulation
  • Basic understanding of cloud networking: VPC, subnets, security groups
  • Comfort reading structured config files (YAML, JSON, or similar)
  • Git installed for version-controlling your Terraform files
Operation Phases
1
Provider Configuration and Init
Create a main.tf with a provider block (AWS, GCP, or Azure). Configure authentication via environment variables. Run terraform init to download the provider plugin. Create a variables.tf with region and project_name inputs and a terraform.tfvars to set values.
2
Network Layer: VPC, Subnets, and Routing
Define a VPC resource with a CIDR block. Add public and private subnets across two availability zones. Create an internet gateway, a route table with a default route to the gateway, and associate it with the public subnets. Run terraform plan to preview, then terraform apply to create.
3
Compute: Instance with Security Group
Add a security group that allows SSH (port 22) and HTTP (port 80) inbound. Define a compute instance resource referencing the public subnet and security group. Use user_data to run a startup script that installs Nginx. Add an outputs.tf that prints the public IP after apply.
4
Modules: Reusable Infrastructure Blocks
Refactor the network resources into a modules/network directory with its own main.tf, variables.tf, and outputs.tf. Call the module from the root with module "network". Do the same for compute. Verify the plan shows no changes — proving the refactor is purely structural.
5
State Management, Destroy, and Remote Backend
Inspect terraform.tfstate to understand what Terraform tracks. Practice terraform state list and terraform state show. Configure a remote backend (S3 + DynamoDB for locking) so state is shared safely across team members. Finally, run terraform destroy to tear down all resources cleanly.
