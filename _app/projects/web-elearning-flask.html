Mission Brief

Your assignment is to build a working e-learning platform from scratch using Python and Flask. When you finish, you will have a multi-user web application running at http://127.0.0.1:5000 where visitors can browse a course catalog, register an account, log in, enroll in courses, and track their progress through lessons — all persisted in a SQLite database on your own machine.

This project is a zero-knowledge walkthrough. Every phase shows the exact files to create, the exact code to paste, the terminal commands to run, and the observable result in the browser that confirms you are on track. No prior Flask experience is assumed — Phase 1 starts from installing Python and covers every command including how to activate a virtual environment.

By the end you will understand how Flask routes HTTP requests to Python functions, how Jinja2 templates inherit from a shared base.html layout, how Flask-SQLAlchemy maps Python classes to database tables, and how Flask-Login protects pages so only authenticated users can reach them. Everything runs server-side — no JavaScript framework, no build step, no paid accounts.

Agent Requirements
  • Python 3.x installed. Download the installer from python.org/downloads (pick the latest stable release, 3.12 or newer). After installing, open a terminal and run python --version or python3 --version to confirm. If you see a version number, you are ready.
  • A terminal (Windows: PowerShell or Command Prompt; Mac: Terminal; Linux: any shell). Every command in this project is shown exactly as you type it.
  • VS Code (code.visualstudio.com) as your editor. Install the Python extension from Microsoft for syntax highlighting and import hints.
  • A modern browser (Chrome, Edge, or Firefox). You will open the app in the browser to verify each phase.
  • No paid accounts, no external database, no cloud services. SQLite is built into Python — no installation needed. Everything runs on your laptop.

Project Structure, Virtual Environment, and Database Models
Before any Flask code runs, you need a project folder, a Python virtual environment, and the three packages installed inside it. Then you define the database models and create the tables. At the end of this phase you will see Flask start and serve the home page at http://127.0.0.1:5000.
Why a virtual environment? A venv is an isolated copy of Python just for this project. Packages you install into it do not affect any other project or your system Python. This is standard practice for every Python project. You activate it once per terminal session.
  1. Verify Python is installed. Open your terminal and run:
    python --version
    If you see Python 3.x.x you are ready. On Mac or Linux the command may be python3 --version. If you see command not found, download the installer from python.org/downloads, run it (check "Add Python to PATH" on Windows), then restart your terminal.
  2. Create your project folder and move into it.
    mkdir elearn cd elearn
    Windows note: mkdir and cd work identically in PowerShell and Command Prompt.
  3. Create the virtual environment.
    python -m venv venv
    This creates a folder named venv/ inside your project. It contains a private copy of Python. On Windows the command is the same.
  4. Activate the virtual environment.
    Mac / Linux:
    source venv/bin/activate
    Windows (PowerShell):
    venv\Scripts\activate
    After activating, your terminal prompt will show (venv) at the start. That prefix tells you the venv is active. Every pip install and every flask run for the rest of this project must be run with the venv active. If you close the terminal and reopen it, activate again before continuing.
  5. Install the three packages.
    pip install Flask Flask-SQLAlchemy Flask-Login
    This installs Flask 3.x, Flask-SQLAlchemy 3.x (which pulls in SQLAlchemy 2.x), and Flask-Login 0.7.x. Werkzeug (the password hashing library) is installed automatically as a Flask dependency. SQLite is already built into Python — nothing extra needed.
  6. Open the project in VS Code.
    code .
    The . means "open the current folder." If VS Code is not in your PATH, open VS Code manually and choose File → Open Folder… and navigate to your elearn folder.
  7. Create the templates folder. In your terminal (venv still active):
    mkdir templates
    Flask looks for HTML templates in a folder called templates/ next to your app.py. All Jinja2 HTML files go here.

Calling db.create_all() at the module level without the context raises RuntimeError: No application found. The with app.app_context() block provides that context when the file is first imported. This is the pattern shown in the official Flask-SQLAlchemy documentation.
    Security: the open-redirect fix in the login route. After calling login_user(user), the route reads a next query parameter so Flask-Login can return the user to the page they originally tried to visit. Without validation, a crafted link like /login?next=https://evil.com would silently forward a freshly-authenticated user to an attacker-controlled phishing site. The fix is one line: urlparse(next_page).netloc == "" returns True only for relative paths such as /dashboard (no domain) and False for absolute URLs like https://evil.com. If the check fails, the code falls through to the safe default url_for("dashboard"). This pattern is the Flask documentation’s recommended approach for validating redirect targets.
    N+1 query note for the dashboard route. The dashboard() view fetches all enrollments in one query, then calls db.session.get(Course, enr.course_id) inside a loop — one extra database round-trip per enrolled course. For a handful of enrollments this is fine. A production application would eliminate the loop by eager-loading the related course in the initial query: db.select(Enrollment).where(...).options(selectinload(Enrollment.course)). SQLAlchemy 2.x resolves all related Course rows in a single IN query instead of N separate lookups. The simple loop is kept here for readability; the comma-separated lessons field has the same intentional trade-off.

ModuleNotFoundError: No module named 'flask'?
  • The virtual environment is not active. Look for the (venv) prefix on your terminal prompt. If it is missing, activate the venv again: source venv/bin/activate (Mac/Linux) or venv\Scripts\activate (Windows), then retry flask run --debug.

RuntimeError: No application found? This happens when you run flask run but Flask cannot locate your app file. The fix: run flask --app app run --debug explicitly (the --app app tells Flask to look in app.py), or rename your file to app.py if you named it something else.
OSError: address already in use on port 5000? On macOS, AirPlay Receiver occupies port 5000 by default. Use a different port: flask --app app run --debug --port 5001 and navigate to http://127.0.0.1:5001.

User Authentication — Register, Log In, Log Out
The routes in app.py already contain the register, login, and logout logic. This phase creates the two remaining templates that power those routes, then walks through the full registration and login flow so you can verify it works before moving on. No code changes to app.py are needed in this phase.
Why passwords are never stored as plain text. generate_password_hash(password) (Werkzeug 3.x) runs the password through the scrypt key derivation function and stores a salted hash like scrypt:32768:8:1$aBcD...<hash>. When a user logs in, check_password_hash(stored_hash, password) re-derives the hash from the candidate password and compares. Even if someone reads the database file, they cannot recover the original passwords.

How the search query works. Course.title.ilike(f"%{q}%") generates a SQL LIKE clause that matches the search term anywhere in the title, case-insensitively. The or_() from SQLAlchemy combines it with the description check so a search returns courses where either field matches. Why the enroll form uses POST. Enrolling a user creates a row in the database — it changes state. HTTP GET should be idempotent (safe to repeat with no side effects). A POST form protects against the browser re-submitting the enrollment when the user presses the back button, and prevents accidental enrollment via a prefetched link.

Dashboard and Progress Tracking
The /dashboard and /progress/<enrollment_id>/<lesson_index> routes are already in app.py. This phase creates dashboard.html, which shows every course the current user is enrolled in, a Bootstrap progress bar per course, and completion counts. Clicking Mark Complete from the course detail page updates the progress in real time — revisiting the dashboard reflects the new percentage immediately.
How progress percentage is calculated. The dashboard() route fetches all enrollments for the current user, then for each one counts the completed lessons from the Progress table and divides by the total lessons in the course. The result is rounded to a whole number and passed to the template as pct. The Progress table stores one row per completed lesson, keyed by (enrollment_id, lesson_index). A duplicate check in mark_progress prevents the same lesson from being counted twice.

CSRF caveat — be aware for production. The enrollment and progress forms in this project do not include a CSRF token. A malicious page could submit a hidden form to /enroll/1 and enroll a logged-in user without their knowledge. In a real production application, add Flask-WTF (pip install Flask-WTF) and include {{ form.hidden_tag() }} in every form. This project omits it deliberately to keep the code minimal and teachable. Do not deploy to the public internet without CSRF protection.
SECRET_KEY reminder for production. The hardcoded "change-this-before-deploying" value is for development only. Before any public deployment, generate a real key: run python -c "import secrets; print(secrets.token_hex())" and set the output as an environment variable (SECRET_KEY=<value>). Read it in app.py with app.config["SECRET_KEY"] = os.environ["SECRET_KEY"].
