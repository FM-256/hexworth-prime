Subject

Build an ETL Data Pipeline

Operative 90 min 400 XP
Mission Brief

Your assignment is to build a working ETL (Extract, Transform, Load) data pipeline in Python that pulls records from three sources — a live public REST API, a CSV file, and a JSON file — normalizes them into a common shape, cleans and validates the data, then loads everything into a local SQLite database using an upsert that prevents duplicates on repeated runs. The pipeline schedules itself with a Python loop and logs a summary of every run: how many records were extracted, transformed, loaded, and skipped.

This is a zero-knowledge walkthrough. Every phase shows the exact files to create, exact code to paste, every terminal command, and an observable checkpoint — a printed count or a SELECT you run in your terminal — that proves the step worked before you move on. You do not need prior database or data-engineering experience. Phase 1 starts from creating a virtual environment.

The public API used throughout is JSONPlaceholder (jsonplaceholder.typicode.com), a free, no-account, no-rate-limit mock REST API. The endpoint /users returns 10 user records. The extractor keeps five of those fields — id, name, username, email, phone — and adds a synthetic source field set to "api" to track where each record came from. No signup required — the URL is the only thing you need.

Agent Requirements
  • Python 3.8 or higher installed. Run python3 --version in your terminal to confirm. Python 3.12 is current. If you see command not found, download the installer from python.org/downloads and reopen your terminal after installing.
  • A terminal (Mac: Terminal or iTerm; Linux: any shell; Windows: PowerShell or WSL). Every command in this project is shown exactly as you type it.
  • The only third-party package you will install is requests (HTTP calls). SQLite, csv, json, logging, time, and datetime are all Python standard library — no install needed.
  • Internet access for Phase 2 only (to reach jsonplaceholder.typicode.com). All other phases work offline once you have created the sample CSV and JSON files.
  • No paid accounts, no cloud services, no database server — SQLite is a file on your hard drive, managed entirely by Python's built-in sqlite3 module.

Extract Layer — API, CSV, and JSON Ingestion
Build three extractors. The API extractor calls jsonplaceholder.typicode.com/users with requests.get(), a 10-second timeout, and retry logic that waits and tries again on network errors. The CSV extractor reads a local file with csv.DictReader. The JSON extractor reads a local file with json.load(). Each extractor returns a list of plain Python dicts all shaped to the same six fields: id, name, username, email, phone, source. This common shape is what makes the transform stage simple.
  1. Create the sample CSV file. Create a new file named users_supplement.csv in your project folder and paste this content exactly:
    id,name,username,email,phone 101,Ada Lovelace,ada.lovelace,ada@example.com,555-0101 102,Grace Hopper,grace.hopper,grace@example.com,555-0102 103,Alan Turing,alan.turing,,555-0103
    Row 103 has no email — that missing value is intentional. The transform stage (Phase 3) will catch and handle it. The id values start at 101 so they do not collide with the API's 1–10 range.
  2. Create the sample JSON file. Create a file named users_extra.json and paste:
    [ { "id": 201, "name": "Margaret Hamilton", "username": "mhamilton", "email": "margaret@example.com", "phone": "555-0201" }, { "id": 202, "name": "Linus Torvalds", "username": "linus.t", "email": "linus@example.com", "phone": "" } ]
    Record 202 has an empty phone string. The transform stage will treat empty strings as missing just like true nulls.
  3. Paste this complete file into extract.py.
    """ extract.py -- Pull records from three sources and return a unified list. Each extractor returns a list of dicts with these keys: id (int) name (str) username (str) email (str or None) phone (str or None) source (str) -- 'api' | 'csv' | 'json' API: jsonplaceholder.typicode.com/users Free, no auth, no rate limit, 10 users. requests.get() verified at docs.python-requests.org/en/latest/user/quickstart/ """ import csv import json import logging import time import requests log = logging.getLogger(__name__) # ── API extractor ───────────────────────────────────────── API_URL = "https://jsonplaceholder.typicode.com/users" MAX_RETRIES = 3 RETRY_DELAY = 2 # seconds; doubles on each failure (exponential backoff) def extract_api(): """Fetch users from the JSONPlaceholder API with retry logic. Returns a list of normalised dicts, or an empty list on failure. """ delay = RETRY_DELAY for attempt in range(1, MAX_RETRIES + 1): try: log.info("API extract attempt %d/%d url=%s", attempt, MAX_RETRIES, API_URL) response = requests.get(API_URL, timeout=10) # raise_for_status() raises requests.exceptions.HTTPError # for any 4xx or 5xx response (docs.python-requests.org quickstart). response.raise_for_status() raw_users = response.json() # list of dicts from the API log.info("API extract OK: %d records received", len(raw_users)) # Normalise to our common shape. records = [] for u in raw_users: records.append({ "id": int(u["id"]), "name": u.get("name", ""), "username": u.get("username", ""), "email": u.get("email") or None, "phone": u.get("phone") or None, "source": "api", }) return records except requests.exceptions.Timeout: log.warning("API timeout on attempt %d (waited 10 s)", attempt) except requests.exceptions.ConnectionError as exc: log.warning("API connection error on attempt %d: %s", attempt, exc) except requests.exceptions.HTTPError as exc: log.error("API HTTP error: %s -- aborting retries", exc) return [] # HTTP error (404, 500…) won't fix itself on retry if attempt < MAX_RETRIES: log.info("Waiting %d s before retry...", delay) time.sleep(delay) delay *= 2 # exponential backoff: 2, 4, 8 seconds log.error("API extract failed after %d attempts. Returning empty list.", MAX_RETRIES) return [] # ── CSV extractor ───────────────────────────────────────── def extract_csv(filepath="users_supplement.csv"): """Read users from a CSV file using csv.DictReader. File must be opened with newline='' as required by the csv module docs. The first row is the header; subsequent rows become dicts keyed by header. """ records = [] try: # newline='' is required by the Python csv module to handle # line endings correctly across platforms (docs.python.org/3/library/csv). with open(filepath, newline="", encoding="utf-8") as f: reader = csv.DictReader(f) for row in reader: records.append({ "id": int(row["id"]), "name": row.get("name", ""), "username": row.get("username", ""), "email": row.get("email") or None, "phone": row.get("phone") or None, "source": "csv", }) log.info("CSV extract OK: %d records from %s", len(records), filepath) except FileNotFoundError: log.error("CSV file not found: %s", filepath) except (KeyError, ValueError) as exc: log.error("CSV parse error: %s", exc) return records # ── JSON extractor ──────────────────────────────────────── def extract_json(filepath="users_extra.json"): """Read users from a JSON file using json.load(). Expects a JSON array at the top level, each element matching the same field set as the CSV and API sources. """ records = [] try: with open(filepath, encoding="utf-8") as f: raw = json.load(f) # json.load() reads from a file object for u in raw: records.append({ "id": int(u["id"]), "name": u.get("name", ""), "username": u.get("username", ""), "email": u.get("email") or None, "phone": u.get("phone") or None, "source": "json", }) log.info("JSON extract OK: %d records from %s", len(records), filepath) except FileNotFoundError: log.error("JSON file not found: %s", filepath) except (json.JSONDecodeError, KeyError, ValueError) as exc: log.error("JSON parse error: %s", exc) return records # ── Combined extractor ──────────────────────────────────── def extract_all(): """Run all three extractors and return a single combined list.""" api_records = extract_api() csv_records = extract_csv() json_records = extract_json() total = api_records + csv_records + json_records log.info("Extract complete: %d total records (api=%d csv=%d json=%d)", len(total), len(api_records), len(csv_records), len(json_records)) return total
    Why or None on email and phone? An empty string "" is falsy in Python, so u.get("email") or None converts both "" and a missing key to None. This gives the transform stage a single consistent value to test with if record["email"] is None, rather than having to check both "" and None in two places.

Transform Layer — Clean, Validate, and Enrich
Pass every record through three sequential steps: clean (strip whitespace, normalise empty strings to None, cast types), validate (drop records missing required fields and log why), and enrich (add a loaded_at timestamp and a display_name derived field). Records that fail validation are counted as “skipped” and written to the log but never reach the database.
  1. Paste this complete file into transform.py.
    """ transform.py -- Clean, validate, and enrich a list of raw records. Input: list of dicts from extract.extract_all() Output: (good_records, skipped_count) good_records -- list of dicts ready to load skipped_count -- int, number of records dropped during validation """ import logging from datetime import datetime, timezone log = logging.getLogger(__name__) # ── Step 1: Clean ───────────────────────────────────────── def _clean(record): """Return a copy of record with whitespace stripped and empty strings normalised to None. Does NOT modify the original dict. """ cleaned = {} for key, value in record.items(): if isinstance(value, str): value = value.strip() # remove leading/trailing whitespace if value == "": value = None # treat empty string as missing cleaned[key] = value return cleaned # ── Step 2: Validate ────────────────────────────────────── REQUIRED_FIELDS = {"id", "name", "username"} # email + phone are optional def _validate(record): """Return True if the record passes all validation rules. Rules: 1. id must be a positive integer. 2. name and username must be non-empty strings. Logs the reason for every dropped record so the run summary is auditable. """ record_id = record.get("id") # Rule 1: id must exist and be a positive integer. if not isinstance(record_id, int) or record_id <= 0: log.warning("SKIP id=%s -- id is not a positive integer", record_id) return False # Rule 2: name and username must be present and non-empty. for field in ("name", "username"): if not record.get(field): log.warning("SKIP id=%s -- required field '%s' is missing or empty", record_id, field) return False return True # ── Step 3: Enrich ──────────────────────────────────────── def _enrich(record): """Add derived fields to a validated record. loaded_at -- ISO-8601 UTC timestamp of this pipeline run. display_name -- username in parentheses after the full name, e.g.: "Leanne Graham (Bret)" """ enriched = dict(record) # shallow copy so we don't mutate the input enriched["loaded_at"] = datetime.now(timezone.utc).isoformat() enriched["display_name"] = "{} ({})".format( enriched.get("name", ""), enriched.get("username", ""), ) return enriched # ── Combined transform ──────────────────────────────────── def transform(raw_records): """Apply clean -> validate -> enrich to every record. Returns (good_records, skipped_count). """ good = [] skipped = 0 for raw in raw_records: cleaned = _clean(raw) if not _validate(cleaned): skipped += 1 continue enriched = _enrich(cleaned) good.append(enriched) log.info("Transform complete: %d passed %d skipped", len(good), skipped) return good, skipped
    Why chain clean then validate (not validate then clean)? Cleaning first means the validator never has to handle both "" and None as “missing” — after cleaning, missing values are always None. This is the standard ETL pattern: normalise the representation first, then check the rules against a predictable shape.
  2. Update pipeline.py to call the transform layer. Replace the entire file:

""" import logging import sqlite3 from extract import extract_all from transform import transform LOG_FILE = "etl.log" logging.basicConfig( level=logging.INFO, format="%(asctime)s %(levelname)-8s %(name)s %(message)s", datefmt="%Y-%m-%d %H:%M:%S", handlers=[ logging.FileHandler(LOG_FILE), logging.StreamHandler(), ], ) log = logging.getLogger("pipeline") log.info("SQLite version: %s (upsert requires 3.24+)", sqlite3.sqlite_version) raw_records = extract_all() good_records, skipped = transform(raw_records) log.info("Phase 3 complete: %d good %d skipped", len(good_records), skipped) # Show a sample enriched record to confirm the new fields. if good_records: sample = good_records[0] log.info("Sample enriched: display_name=%r loaded_at=%r", sample["display_name"], sample["loaded_at"])

Load Layer — SQLite Upsert & Deduplication
Create the SQLite database and users table with a UNIQUE constraint on the id column, then load every good record using an INSERT ... ON CONFLICT(id) DO UPDATE SET ... upsert. Because the upsert is keyed on id, running the pipeline a second time with the same data produces zero duplicates — it updates the existing rows instead. Finish by running a SELECT directly in your terminal to prove the rows landed.
The most important concept in this phase: the UNIQUE constraint is not optional. SQLite's ON CONFLICT(id) DO UPDATE syntax requires a UNIQUE constraint or PRIMARY KEY on the conflict-target column. Without it, SQLite raises OperationalError: no such constraint and the upsert never runs. The table definition below uses id INTEGER PRIMARY KEY, which SQLite treats as an implicit UNIQUE constraint and the required target. This was verified against the official SQLite upsert documentation at sqlite.org/lang_upsert.html.
  1. Paste this complete file into load.py.
    """ load.py -- Write transformed records into SQLite with upsert + dedup. SQLite upsert syntax (INSERT ... ON CONFLICT DO UPDATE) was introduced in SQLite 3.24.0 (2018-06-04). Python's bundled sqlite3 module ships with SQLite 3.24+ on all modern Python 3.x installations. Verify at runtime: import sqlite3; print(sqlite3.sqlite_version) The conflict target column (id) MUST have a UNIQUE or PRIMARY KEY constraint. Without it SQLite raises: OperationalError: no such constraint. Source: sqlite.org/lang_upsert.html Parameterised queries use ? placeholders (never string concatenation) to prevent SQL injection. Source: docs.python.org/3/library/sqlite3 """ import logging import sqlite3 log = logging.getLogger(__name__) DB_PATH = "etl_pipeline.db" # ── SQL statements ──────────────────────────────────────── CREATE_TABLE_SQL = """ CREATE TABLE IF NOT EXISTS users ( id INTEGER PRIMARY KEY, -- UNIQUE constraint; upsert target name TEXT NOT NULL, username TEXT NOT NULL, email TEXT, -- nullable: some records have no email phone TEXT, -- nullable: some records have no phone source TEXT NOT NULL, -- 'api' | 'csv' | 'json' display_name TEXT, loaded_at TEXT ); """ # ON CONFLICT(id) requires that `id` has a UNIQUE or PRIMARY KEY constraint. # INTEGER PRIMARY KEY satisfies this. # # excluded.column_name refers to the NEW values being inserted. # Omitting `excluded.` refers to the EXISTING row's values. # # This upsert pattern is idempotent: running the pipeline twice with the # same data leaves exactly the same rows in the table. UPSERT_SQL = """ INSERT INTO users (id, name, username, email, phone, source, display_name, loaded_at) VALUES (?, ?, ?, ?, ?, ?, ?, ?) ON CONFLICT(id) DO UPDATE SET name = excluded.name, username = excluded.username, email = excluded.email, phone = excluded.phone, source = excluded.source, display_name = excluded.display_name, loaded_at = excluded.loaded_at; """ def load(records): """Insert or update every record in the users table. Returns (upserted_count, error_count). upserted counts both new inserts AND updates to existing rows, so running the pipeline twice with the same data returns upserted=15 both times -- that is the expected deduplication proof (the table COUNT stays at 15 because the upsert updates in place, not inserts again). """ upserted = 0 errors = 0 conn = sqlite3.connect(DB_PATH) try: cursor = conn.cursor() # Create the table if it does not already exist. cursor.execute(CREATE_TABLE_SQL) for rec in records: try: cursor.execute(UPSERT_SQL, ( rec["id"], rec["name"], rec["username"], rec.get("email"), # None becomes SQL NULL rec.get("phone"), rec["source"], rec.get("display_name"), rec.get("loaded_at"), )) upserted += 1 except sqlite3.Error as row_err: log.error("Row load error id=%s: %s", rec.get("id"), row_err) errors += 1 # conn.commit() is REQUIRED. sqlite3 does NOT auto-commit DML. # Without it, all inserts exist only in the transaction and are lost # when conn.close() is called. conn.commit() log.info("Load complete: %d upserted %d errors db=%s", upserted, errors, DB_PATH) except sqlite3.Error as db_err: log.error("Database error: %s -- rolling back", db_err) conn.rollback() finally: conn.close() return upserted, errors
  2. Update pipeline.py to call the load layer. Replace the entire file:
    """ pipeline.py -- ETL entry point and logging configuration. """ import logging import sqlite3 from extract import extract_all from transform import transform from load import load LOG_FILE = "etl.log" logging.basicConfig( level=logging.INFO, format="%(asctime)s %(levelname)-8s %(name)s %(message)s", datefmt="%Y-%m-%d %H:%M:%S", handlers=[ logging.FileHandler(LOG_FILE), logging.StreamHandler(), ], ) log = logging.getLogger("pipeline") log.info("SQLite version: %s (upsert requires 3.24+)", sqlite3.sqlite_version) raw_records = extract_all() good_records, skipped = transform(raw_records) upserted, errors = load(good_records) log.info( "Run summary -- extracted=%d good=%d skipped=%d upserted=%d errors=%d", len(raw_records), len(good_records), skipped, upserted, errors, )

    This is the key test. The count must stay at 15 — not 30. If you see 30, the upsert is not working. The most common cause is that the table was created without INTEGER PRIMARY KEY on the id column. Delete etl_pipeline.db (just the database file, not your Python files), re-run python pipeline.py, and the table will be recreated correctly with the CREATE TABLE IF NOT EXISTS statement that includes the constraint.
OperationalError: no such constraint? The upsert's ON CONFLICT(id) clause could not find a UNIQUE or PRIMARY KEY constraint on the id column. This happens if the users table was created by a previous version of the code without the PRIMARY KEY declaration. Fix: delete etl_pipeline.db and re-run. The CREATE TABLE IF NOT EXISTS only runs when the table does not exist, so deleting the database file forces a fresh create with the correct schema.
Rows doubled (30 instead of 15 after second run)? The upsert SQL is not matching on id. Open load.py and verify: (1) the CREATE TABLE statement has id INTEGER PRIMARY KEY, and (2) the ON CONFLICT(id) clause spells id exactly as it appears in the table definition. Column names in SQLite are case-insensitive but must match the constraint target exactly.
Rows are 0 after running? You forgot conn.commit(). Without it, the INSERT statements execute in an open transaction that is discarded when conn.close() is called. The load.py code above includes conn.commit() before conn.close(); re-paste to be sure.
Checkpoint — the deduplication proof
After the first run: SELECT COUNT(*) FROM users returns 15.
After the second run of python pipeline.py with identical input: SELECT COUNT(*) FROM users still returns 15.
The log summary line reads: Run summary -- extracted=15 good=15 skipped=0 upserted=15 errors=0
upserted=15 on re-run is correct and expected — the upsert counts every row it processed (both new inserts and in-place updates), which is why the table COUNT stays at 15 rather than growing to 30. That stable COUNT is the real dedup proof.
Record 103 query: SELECT id, name, email FROM users WHERE id=103 returns (103, 'Alan Turing', None) — the missing email is stored as SQL NULL, not the string 'None'.

Scheduling, Error Handling & Monitoring
Wire the pipeline into a scheduler so it runs automatically at a set interval. The walkthrough shows two options: a portable Python loop using time.sleep that you can run right now with no extra installs, and a note on production-grade cron scheduling for real deployment. It also adds a top-level try/except so a failure in one run logs the error and the scheduler continues — a single bad API response does not kill the whole schedule. The run-summary log line (extracted / good / skipped / loaded / errors) becomes the monitoring record for every execution.
  1. Replace pipeline.py with the final complete version. This adds the scheduler loop, per-run try/except, and the elapsed-time summary:
    """ pipeline.py -- ETL entry point, scheduler, and run-level error handling. Run once: python pipeline.py Run with loop: python pipeline.py --loop """ import logging import sqlite3 import sys import time from datetime import datetime, timezone from extract import extract_all from transform import transform from load import load LOG_FILE = "etl.log" RUN_INTERVAL_SECONDS = 3600 * 6 # 6 hours between runs (change freely) logging.basicConfig( level=logging.INFO, format="%(asctime)s %(levelname)-8s %(name)s %(message)s", datefmt="%Y-%m-%d %H:%M:%S", handlers=[ logging.FileHandler(LOG_FILE), logging.StreamHandler(), ], ) log = logging.getLogger("pipeline") log.info("SQLite version: %s (upsert requires 3.24+)", sqlite3.sqlite_version) def run_once(): """Execute one full ETL pass and return a summary dict. The try/except here is intentionally at the pipeline level, not inside the individual modules. Each module already logs its own errors and returns a safe empty-list / zero-count value on failure. The top-level guard catches anything unexpected so the scheduler loop keeps running even if this run crashes. """ start = time.monotonic() summary = { "extracted": 0, "good": 0, "skipped": 0, "upserted": 0, "errors": 0, "status": "OK", } try: raw_records = extract_all() good_records, skipped = transform(raw_records) upserted, errors = load(good_records) summary["extracted"] = len(raw_records) summary["good"] = len(good_records) summary["skipped"] = skipped summary["upserted"] = upserted summary["errors"] = errors except Exception as exc: # Catch-all: log the full exception and mark the run as FAILED. # The scheduler loop in run_loop() will still schedule the next run. log.exception("Unhandled exception during pipeline run: %s", exc) summary["status"] = "FAILED" elapsed = time.monotonic() - start log.info( "Run summary [%s] -- extracted=%d good=%d skipped=%d " "upserted=%d errors=%d elapsed=%.2fs", summary["status"], summary["extracted"], summary["good"], summary["skipped"], summary["upserted"], summary["errors"], elapsed, ) return summary def run_loop(interval_seconds=RUN_INTERVAL_SECONDS): """Run the pipeline immediately, then repeat every interval_seconds. This is the portable in-process scheduler. It is appropriate for development and light workloads. For production, use cron (see below). To stop the loop: press Ctrl+C in the terminal. """ log.info( "Scheduler started -- interval=%ds (%.1f hours). Press Ctrl+C to stop.", interval_seconds, interval_seconds / 3600, ) run_number = 0 while True: run_number += 1 log.info("--- Run #%d starting at %s ---", run_number, datetime.now(timezone.utc).isoformat()) run_once() log.info("Next run in %d seconds...", interval_seconds) try: time.sleep(interval_seconds) except KeyboardInterrupt: log.info("Scheduler stopped by user (Ctrl+C).") break # ── Entry point ─────────────────────────────────────────── if __name__ == "__main__": if "--loop" in sys.argv: run_loop() else: run_once()
    Why time.monotonic() for elapsed time? time.monotonic() counts seconds from an arbitrary fixed point and never goes backwards (unlike time.time() which can jump if the system clock is adjusted by NTP). It is the right choice for measuring elapsed duration.

The Python loop exits immediately after one run? You ran python pipeline.py without the --loop flag. The if "--loop" in sys.argv check controls which mode runs. Add --loop to the command to start the scheduler.
Cron entry saved but pipeline never runs? Three most common causes: (1) The path to venv/bin/python is wrong — run which python inside your active venv to get the exact path. (2) The path to pipeline.py is wrong — run pwd inside your project folder to get the absolute path. (3) On Mac, cron has been blocked by macOS privacy permissions — go to System Preferences > Privacy & Security > Full Disk Access and add /usr/sbin/cron.
log.exception() vs log.error() — which should I use? log.exception() is like log.error() but it also appends the full traceback to the log entry. Use it inside an except block when you want the stack trace preserved for debugging. log.error() logs the message only — use it when you already know the error and the traceback adds no information.
