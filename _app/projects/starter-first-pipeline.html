Subject

My First Pipeline

Recruit 30 min 250 XP
Mission Brief

Set up your first CI/CD pipeline with GitHub Actions — every push automatically tests and validates your code. CI/CD stands for Continuous Integration / Continuous Deployment. It is the practice of automating the verification of code every single time a change is pushed. Every professional software team runs this.

You will write a simple Python function and tests, define a GitHub Actions workflow in YAML, push to GitHub, and watch the pipeline execute automatically in the cloud. Then you will intentionally break the tests to see the red failure indicator — and fix it to go green again. The red/green cycle is the foundation of test-driven development.

By the end your README will display a live status badge that updates automatically on every push. This is the same infrastructure used by every open-source project and most production engineering teams. You will never push code without thinking about CI again.

Agent Requirements
  • A GitHub account (free) — github.com
  • Git installed on your machine and a terminal for running git commands
  • Python 3 and pytest installed (pip install pytest)
  • VS Code or any text editor for writing Python and YAML
  • Basic Python knowledge — functions and simple arithmetic
  • Familiarity with git commit and push workflow
Operation Phases
Progress
0 / 4
✓
1
Create a Repo with Tests
Create a new GitHub repository, clone it locally. Create math_utils.py with a function def add(a, b): return a + b and optionally def multiply(a, b): return a * b. Create test_math.py importing your functions: write def test_add(): assert add(2, 3) == 5 and def test_add_negative(): assert add(-1, 1) == 0. Run pytest locally to verify both tests pass.
Checkpoint
Running pytest in your terminal shows 2 passed with green dots or a passing indicator. Both math_utils.py and test_math.py are in your repo directory. The tests are real assertions — they would catch a broken add() function.
✓
2
Write the Workflow
Create the directory .github/workflows/ in your repo. Inside it create test.yml. The file structure: name: Tests, on: [push], then a jobs: block with a test: job, runs-on: ubuntu-latest, and steps: containing: uses: actions/checkout@v4, uses: actions/setup-python@v5 with python-version 3.11, run: pip install pytest, and run: pytest. YAML indentation is 2 spaces — every level must be consistent.
Checkpoint
The file exists at .github/workflows/test.yml. The YAML structure is valid — you can check with an online YAML linter or VS Code's YAML extension. Each step has either a uses or a run key, not both. Indentation errors are the most common failure — double-check every level.
✓
3
Push and Watch
Stage all files with git add ., commit with a meaningful message like git commit -m "add math utils and CI workflow", and push with git push. Open your repository on github.com. Click the Actions tab. Watch the workflow trigger automatically within seconds of your push. Click the running workflow to see each step execute live in the logs. The checkout, Python setup, pip install, and pytest run steps all appear sequentially.
Checkpoint
The Actions tab shows a completed run with a green checkmark. Clicking into the run shows the pytest output in the logs — "2 passed" visible inside the Actions runner. The total run time is typically 30-60 seconds. Your code is now automatically verified on every future push.
✓
4
Break It, Fix It
In test_math.py, intentionally write a failing test: def test_broken(): assert add(2, 2) == 5. Commit and push. Watch the Actions tab — the run shows a red X. Click in to see which test failed and the assertion error. Now fix the test: change == 5 to == 4. Commit and push again — watch it go green. Finally, add a badge to README.md: ![Tests](https://github.com/USER/REPO/actions/workflows/test.yml/badge.svg) replacing USER and REPO with your actual values.
Checkpoint
Your README now displays a green "passing" badge that automatically updates on every push. You have seen both the red failure state and the green passing state. You understand the red/green cycle: red means something broke — the pipeline is working correctly by catching it. Green means the code meets its tests. Both states are valuable.
