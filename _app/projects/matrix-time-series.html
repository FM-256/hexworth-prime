Subject

Predictive Time Series Analysis

Operator 120 min 500 XP
Mission Brief

This operation builds a complete SARIMA-based time series forecasting pipeline in Python using the classic AirPassengers dataset — 144 monthly observations of international airline passengers from 1949 to 1960. The dataset is loaded via statsmodels.datasets.get_rdataset, which fetches it from the Rdatasets GitHub repository on the first run and caches it locally; an internet connection is required that one time, after which the script runs fully offline. The pipeline runs start-to-finish in a single script using statsmodels 0.14.6, pandas 3.0.3, numpy 2.4.6, matplotlib 3.11.0, and scikit-learn 1.9.0.

The five phases follow the canonical forecasting workflow: load and set a proper DatetimeIndex with monthly frequency, decompose the series to visualize trend and seasonality, test stationarity with the Augmented Dickey-Fuller test and apply log + differencing to achieve it, fit a SARIMAX(1,1,1)(1,1,1,12) model on the training split, then forecast the held-out test period and compute MAE and RMSE against the actual values. Every phase ends with a concrete observable checkpoint so you know when to move on.

Beyond the finished artifact, this operation builds muscle memory for the entire statistical forecasting toolkit: decomposition, stationarity testing, ARIMA order selection, seasonal differencing, and confidence-interval forecasting. These patterns transfer directly to any domain where you need to predict the future from a historical sequence — inventory demand, network traffic, financial returns, or IoT sensor readings.

Environment Setup & Data Loading
Install the five libraries, load the AirPassengers dataset, and attach a proper monthly DatetimeIndex with an explicit frequency so downstream tools do not produce warnings.
  1. Install the libraries. Run this one command in your terminal. The five packages together are under 100 MB.
    pip install "statsmodels==0.14.6" "pandas==3.0.3" "numpy==2.4.6" "matplotlib==3.11.0" "scikit-learn==1.9.0"
  2. Create the project file. Make a new file called ts_forecast.py in any folder you choose. Every snippet in this project goes in this single file, in order.
  3. Paste the setup block at the top of ts_forecast.py:
    import warnings warnings.filterwarnings("ignore") import pandas as pd import numpy as np import matplotlib.pyplot as plt import matplotlib.dates as mdates from statsmodels.datasets import get_rdataset from statsmodels.tsa.seasonal import seasonal_decompose from statsmodels.tsa.stattools import adfuller from statsmodels.tsa.statespace.sarimax import SARIMAX from sklearn.metrics import mean_absolute_error # ── Load AirPassengers (fetched from Rdatasets on first run, then cached) ── data = get_rdataset("AirPassengers", "datasets").data # The dataset has columns 'time' (fractional year) and 'value'. # Build a proper monthly DatetimeIndex from the fractional year column. start_year = int(data["time"].iloc[0]) n_months = len(data) idx = pd.date_range(start=f"{start_year}-01-01", periods=n_months, freq="MS") series = pd.Series(data["value"].values, index=idx, name="passengers") print("Series loaded.") print(series.head(12)) print(f"\nDate range : {series.index[0].date()} to {series.index[-1].date()}") print(f"Observations: {len(series)}") print(f"Index freq : {series.index.freq}")
    Why freq="MS"? MS = Month Start. statsmodels SARIMA requires a DatetimeIndex with an explicit frequency. Without it you get a ValueWarning: No frequency information was provided and the model may refuse to set forecast dates correctly. Setting it here once prevents all downstream issues.
  4. Run the script to confirm the data loads cleanly:
    python ts_forecast.py

Exploratory Analysis & Decomposition
Plot the raw series, apply a 12-month rolling mean to surface the trend, and run seasonal_decompose to isolate trend, seasonality, and residual components. This step tells you whether you need seasonal differencing.

    # ── EDA: raw series + 12-month rolling mean ── fig, ax = plt.subplots(figsize=(12, 4)) series.plot(ax=ax, color="#00ff41", linewidth=1.4, label="Monthly passengers") series.rolling(window=12).mean().plot( ax=ax, color="#4ade80", linewidth=2, linestyle="--", label="12-mo rolling mean" ) ax.set_title("AirPassengers: Raw Series + Trend", color="#00ff41") ax.set_xlabel("Date") ax.set_ylabel("Passengers (thousands)") ax.legend() ax.set_facecolor("#0a0c10") fig.patch.set_facecolor("#0a0c10") for spine in ax.spines.values(): spine.set_edgecolor("#00ff41") ax.tick_params(colors="#00ff41") ax.xaxis.label.set_color("#00ff41") ax.yaxis.label.set_color("#00ff41") plt.tight_layout() plt.savefig("01_raw_series.png", dpi=100) plt.show() # ── Seasonal decomposition (multiplicative: amplitude grows with level) ── # model="multiplicative" is correct here because the seasonal swings # grow proportionally larger as the trend rises. decomp = seasonal_decompose(series, model="multiplicative", period=12) fig2 = decomp.plot() fig2.set_size_inches(12, 8) fig2.suptitle("Seasonal Decomposition (multiplicative)", color="#00ff41", y=1.01) plt.tight_layout() plt.savefig("02_decomposition.png", dpi=100) plt.show() print("\nDecomposition saved to 02_decomposition.png")

Decomposition plot shows a jagged trend or NaN gaps at the edges? This is normal. seasonal_decompose uses a centered moving average internally, which loses period/2 observations at each end. The NaN gaps at the first and last 6 months are expected and do not affect the SARIMA model in Phase 4, which uses raw data.

The Residual panel fluctuates within a narrow band around 1.0 with no drift. If the seasonal panel amplitude changes dramatically over time, switch to model="additive" and compare. Stationarity Testing & Train / Test Split
Run the Augmented Dickey-Fuller test on the raw series, apply log-transformation and first + seasonal differencing to achieve stationarity, confirm with a second ADF test, then split the log-transformed series into train and test sets respecting time order — no shuffling.
  1. Append the stationarity block to ts_forecast.py:
    # ── ADF test on the raw series ── def run_adf(ts, label=""): result = adfuller(ts.dropna(), autolag="AIC") print(f"\nADF test: {label}") print(f" ADF statistic : {result[0]:.4f}") print(f" p-value : {result[1]:.4f}") print(f" Critical 5% : {result[4]['5%']:.4f}") stationary = result[1] < 0.05 print(f" Stationary? : {'YES' if stationary else 'NO <-- differencing needed'}") return stationary run_adf(series, "raw series") # ── Log-transform to stabilise variance, then difference to remove trend ── log_series = np.log(series) # First difference removes the linear trend. log_diff1 = log_series.diff(1).dropna() run_adf(log_diff1, "log + 1st difference") # Seasonal difference (lag 12) removes the annual cycle. log_diff12 = log_series.diff(12).diff(1).dropna() run_adf(log_diff12, "log + seasonal + 1st difference")
  2. Append the train/test split block immediately after:
    # ── Train / test split (no shuffling -- time order is sacred) ── # Hold out the last 24 months (2 years) as the test set. # SARIMA is fit on log(series), not the differenced series -- # the model handles differencing internally via the d and D orders. TRAIN_END = "1958-12-01" TEST_START = "1959-01-01" train = log_series[:TRAIN_END] test = log_series[TEST_START:] print(f"\nTrain: {len(train)} months ({train.index[0].date()} to {train.index[-1].date()})") print(f"Test : {len(test)} months ({test.index[0].date()} to {test.index[-1].date()})")
  3. Run the script to see the ADF output:
    python ts_forecast.py
ADF p-value on the raw series is already below 0.05? Unlikely for AirPassengers (which is strongly non-stationary), but if it happens with your own data you can skip differencing and use d=0, D=0 in the SARIMA order in Phase 4. The ADF test result drives the order selection — do not difference a series that is already stationary.
Checkpoint — what you should see
Three ADF blocks print. The raw series p-value is greater than 0.05 (typically ~0.99), labelled NO. The log + 1st difference p-value should be below 0.05. The log + seasonal + 1st difference p-value is below 0.01 and labelled YES. The split summary shows Train: 120 months and Test: 24 months. The ADF statistic must be more negative than the 5% critical value for stationarity to hold.

4
SARIMA Model Fitting & Forecasting
Fit a SARIMAX(1,1,1)(1,1,1,12) model on the log-transformed training series using the current statsmodels import path, generate a 24-step forecast with 95% confidence intervals, and back-transform predictions to original passenger counts.
  1. Append the SARIMA block to ts_forecast.py:
    # ── Fit SARIMA(1,1,1)(1,1,1,12) ── # CURRENT import (statsmodels 0.14.x): # from statsmodels.tsa.statespace.sarimax import SARIMAX # The old statsmodels.tsa.arima_model.ARIMA was REMOVED in 0.14.0. # Do NOT use: from statsmodels.tsa.arima_model import ARIMA <-- removed model = SARIMAX( train, order=(1, 1, 1), # p=1, d=1, q=1 (non-seasonal) seasonal_order=(1, 1, 1, 12), # P=1, D=1, Q=1, s=12 (annual) enforce_stationarity=False, enforce_invertibility=False, ) results = model.fit(disp=False) print("\nSARIMA model fitted.") print(results.summary().tables[1]) # ── Forecast the 24-month test window ── forecast_obj = results.get_forecast(steps=len(test)) forecast_log = forecast_obj.predicted_mean # log scale conf_int_log = forecast_obj.conf_int(alpha=0.05) # 95% CI on log scale # Back-transform: exp() reverses np.log() forecast_orig = np.exp(forecast_log) conf_lo_orig = np.exp(conf_int_log.iloc[:, 0]) conf_hi_orig = np.exp(conf_int_log.iloc[:, 1]) actual_orig = np.exp(test) # test set in original units # Align forecast index to the test dates explicitly forecast_orig.index = test.index conf_lo_orig.index = test.index conf_hi_orig.index = test.index
  2. Run the script to confirm the model fits without error:
    python ts_forecast.py
    The summary table prints coefficient estimates for ar.L1, ma.L1, ar.S.L12, ma.S.L12. All p-values should be below 0.05.
ImportError or cannot import name 'ARIMA' from 'statsmodels.tsa.arima_model'? You are using the removed legacy import path. The statsmodels.tsa.arima_model module was deleted in statsmodels 0.14.0. The replacement is:
  • For SARIMA (seasonal): from statsmodels.tsa.statespace.sarimax import SARIMAX
  • For plain ARIMA (non-seasonal): from statsmodels.tsa.arima.model import ARIMA
  • Never use from statsmodels.tsa.arima_model import ARIMA — that module no longer exists in any version of statsmodels from 0.14 onward.
Checkpoint — what you should see
The model fits without a warning or traceback and prints a coefficient table. The ar.L1 and ma.L1 rows appear with estimates and p-values. The model does not raise LinAlgError or ConvergenceWarning with these orders on AirPassengers. If you see Maximum Likelihood optimization failed to converge, add maxiter=200 to model.fit() as a keyword argument.

Evaluation & Forecast Visualization
Compute MAE and RMSE on the held-out 24-month test set, plot actual vs. forecast with confidence intervals, and save the finished chart to disk.
  1. Append the evaluation block to ts_forecast.py:
    # ── Compute error metrics on the test set ── mae = mean_absolute_error(actual_orig, forecast_orig) rmse = np.sqrt(np.mean((actual_orig - forecast_orig) ** 2)) print(f"\nTest-set evaluation (24 months: 1959-01 to 1960-12)") print(f" MAE : {mae:.2f} thousand passengers") print(f" RMSE : {rmse:.2f} thousand passengers")
  2. Append the forecast plot block:
    # ── Forecast plot: actual vs predicted + 95% CI ── fig3, ax3 = plt.subplots(figsize=(13, 5)) # Full history in original units for context np.exp(log_series).plot( ax=ax3, color="#00ff41", linewidth=1.3, label="Historical (actual)" ) # Forecast line forecast_orig.plot( ax=ax3, color="#4ade80", linewidth=2, linestyle="--", label="SARIMA forecast" ) # 95% confidence band ax3.fill_between( forecast_orig.index, conf_lo_orig, conf_hi_orig, color="#4ade80", alpha=0.15, label="95% CI", ) # Vertical line at train/test boundary ax3.axvline( pd.Timestamp(TEST_START), color="#ffffff40", linewidth=1, linestyle=":", label="Train | Test" ) ax3.set_title( f"SARIMA(1,1,1)(1,1,1,12) Forecast | MAE={mae:.1f} RMSE={rmse:.1f}", color="#00ff41", ) ax3.set_xlabel("Date") ax3.set_ylabel("Passengers (thousands)") ax3.set_facecolor("#0a0c10") fig3.patch.set_facecolor("#0a0c10") for spine in ax3.spines.values(): spine.set_edgecolor("#00ff41") ax3.tick_params(colors="#00ff41") ax3.xaxis.label.set_color("#00ff41") ax3.yaxis.label.set_color("#00ff41") ax3.legend(facecolor="#0a0c10", labelcolor="#b6ffca") plt.tight_layout() plt.savefig("03_forecast.png", dpi=100) plt.show() print("Forecast plot saved to 03_forecast.png")

forecast_orig.index does not match test.index and the plot shows a date gap? The get_forecast method constructs future dates from the model's fitted index. If the training DatetimeIndex had freq=None (missing frequency), the forecast index will be integers instead of dates.
  • Confirm Phase 1 set freq="MS" on the pd.date_range call.
  • After fitting, run print(results.model.data.dates) — you should see a DatetimeIndex, not a RangeIndex.
  • The line forecast_orig.index = test.index in the Phase 4 block explicitly re-assigns the index as a safety net, so the plot will align even if the model returned integer steps.
