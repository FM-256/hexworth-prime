Subject

User Auth with AWS Cognito

Journeyman 60 min 500 XP
Mission Brief

Authentication is not a feature you bolt on at the end. This operation builds it correctly from the start using AWS Cognito — Amazon's managed identity service that handles user registration, login, MFA, password policies, and token issuance without a single line of custom session management code. You will create a User Pool with enforced password complexity, configure a hosted UI for OAuth2 login flows, enable TOTP-based MFA, and wire up an App Client with the Authorization Code + PKCE grant type for a web application.

The authentication tokens Cognito issues are JSON Web Tokens. You will decode and validate them manually using the python-jose library: verifying the RS256 signature against Cognito's JWKS endpoint, checking the exp claim against current time, validating the aud claim against your App Client ID, and extracting the cognito:groups claim to drive role-based access control. An AWS API Gateway Lambda authorizer implements this validation pipeline for every protected endpoint.

The Identity Pool layer federates Cognito identities to IAM roles, granting authenticated users temporary AWS credentials scoped by role. You will configure two IAM roles — AuthenticatedRole and UnauthenticatedRole — with least-privilege policies, then test the access boundary by attempting S3 operations from both contexts. This project builds the full mental model of modern identity: from login to token to credentials to resource access.

Agent Requirements
  • AWS account with IAM permissions to create Cognito User Pools, Identity Pools, and Lambda functions
  • Familiar with REST API concepts: HTTP headers, status codes, and request/response structure
  • Basic Python knowledge: installing packages, writing functions, and using dictionaries
  • Understand what JSON is and what base64 encoding means at a conceptual level
  • No prior Cognito or OAuth2 experience required — all flows are explained from first principles
Operation Phases
Progress
0 / 5
✓
1
User Pool Configuration
Create a Cognito User Pool via the AWS Console. Configure password policy: minimum 12 characters, require uppercase, lowercase, numbers, and symbols. Enable TOTP-based MFA as optional (users can enroll post-signup). Add custom schema attributes: custom:role (string, mutable). Configure a Pre Sign-up Lambda trigger that auto-confirms users from a trusted email domain to streamline testing. Note the Pool ID and region for SDK configuration.
Checkpoint: Cognito Setup
  • Create a User Pool in the AWS Console and verify the Pool ID is generated
  • Configure an App Client and confirm the Client ID is returned
  • Verify the required attributes (email, password policy) are configured correctly
✓
2
App Client & OAuth2 Flow Setup
Create an App Client with the Authorization Code + PKCE grant type enabled. Add a callback URL of http://localhost:3000/callback and a sign-out URL. Enable the Cognito Hosted UI and configure the domain prefix. Open the OAuth2 login URL in a browser, complete signup and TOTP enrollment, and capture the authorization code from the redirect. Exchange it for tokens using a requests.post() call to the token endpoint.
✓
3
JWT Validation with python-jose
Fetch Cognito's public keys from https://cognito-idp.{region}.amazonaws.com/{pool_id}/.well-known/jwks.json. Build a validator function using jose.jwt.decode() that verifies the RS256 signature, checks exp, validates aud against the App Client ID, and extracts the sub and cognito:groups claims. Return a structured principal dict for downstream authorization logic.
Checkpoint: User Registration
  • Register a test user and verify the confirmation code is sent to the provided email
  • Confirm the account with the verification code and verify the user status changes to CONFIRMED
  • Attempt to register with an already-used email and verify the appropriate error is returned
✓
4
Lambda Authorizer & API Gateway Integration
Deploy a Lambda function that receives a TOKEN type authorizer event, extracts the Authorization header, calls the JWT validator, and returns an IAM policy document granting or denying execute-api:Invoke on the requested resource ARN. Attach this authorizer to an API Gateway REST API and verify that requests with valid tokens return 200 while expired or tampered tokens return 401 at the Gateway layer before Lambda is invoked.
Checkpoint: Integration
  • Protect an API endpoint with a Cognito authorizer and verify unauthenticated requests are rejected
  • Pass a valid access token in the Authorization header and confirm the request succeeds
  • Verify token expiration is enforced — an expired token should return 401
✓
5
Identity Pool & Role-Based AWS Access
Create a Cognito Identity Pool federated with the User Pool. Configure two IAM roles: AuthenticatedRole with s3:GetObject on a test bucket, and UnauthenticatedRole with no S3 permissions. Use boto3.client('cognito-identity').get_credentials_for_identity() to obtain temporary credentials, then call s3.get_object() with those credentials. Verify the access boundary by attempting the same call from the unauthenticated role and confirming the AccessDenied error.
Checkpoint: Authentication
  • Log in with valid credentials and verify an ID token, access token, and refresh token are returned
  • Decode the JWT access token and confirm it contains the expected claims (sub, email, groups)
  • Attempt login with incorrect credentials and verify the error response does not leak user existence info
