Subject

Build a Multi-Protocol Field Terminal

Specialist 150 min 2000 XP
Authorization Requirement — Read Before Building

This project builds a passive wireless reconnaissance and diagnostics tool. Every capability covered here — WiFi scanning, BLE discovery, network diagnostics, and frame counting in promiscuous mode — must be used only on networks and devices you own or have explicit written authorization to assess.

WiFi scanning and BLE discovery observe publicly broadcast beacon frames. These are passive, read-only observations of information devices advertise to the world by design, and are legal in most jurisdictions when performed for your own assessment purposes. Promiscuous mode frame capture in this project is a frame counter only, operating on your own network — it does not reassemble payloads, log content, or capture credentials.

This project does not cover and you must not implement: deauthentication attacks, beacon flooding, evil-twin access points, packet injection, or any form of active disruption. Unauthorized interception of others' wireless traffic is illegal under the Electronic Communications Privacy Act (United States), Computer Fraud and Abuse Act, and equivalent laws in most other countries. If in doubt, stay on your own network.

Mission Brief

This operation builds a portable, touchscreen-driven wireless assessment multi-tool on the ESP32 "Cheap Yellow Display" (CYD) — the ESP32-2432S028R, a ~$10–15 development board combining an ESP32 microcontroller, a 2.8-inch 240×320 ILI9341 TFT display, and an XPT2046 resistive touchscreen into a single compact package. When finished you carry a self-contained field terminal in your pocket.

The terminal has four tabs you navigate by touch: a WiFi Scanner that lists nearby networks with SSID, signal strength, channel, and encryption type; a BLE Recon tab that discovers advertising Bluetooth Low Energy devices; a Network Tools tab that pings your own gateway and resolves DNS names; and a Passive Frame Counter tab that runs the ESP32 radio in promiscuous mode and counts 802.11 frame types on your own network. All four tools share one 240×320 screen and one touch controller through a unified tab-switching framework you build from scratch.

The build requires the physical ESP32-2432S028R board. There is no faithful desktop simulator for real WiFi scanning, BLE discovery, or promiscuous-mode capture — the RF hardware must be present. The board is widely available from AliExpress and Amazon for roughly $10–15 USD and is self-contained: no breadboard, no soldering, and no additional shields are required. A micro-USB or USB-C cable (check your specific board revision) connects it to your computer for programming.

Agent Requirements
  • ESP32-2432S028R (CYD board) — the ~$10–15 "Cheap Yellow Display". Search AliExpress or Amazon for "ESP32 Cheap Yellow Display" or "ESP32-2432S028R". No simulator substitutes for this project's RF features.
  • A micro-USB cable (most CYD revisions) or USB-C cable — check your board's port before ordering
  • A Windows, macOS, or Linux computer with Arduino IDE 2.x installed (free download at arduino.cc)
  • Basic C/C++ comfort: you can read a for-loop and an if-statement. Full sketches are provided.
  • A WiFi network you own or are authorized to assess, with known SSID and password for Phases 3, 5, and 6
  • No soldering, no breadboard, no additional hardware required

Toolchain Setup — Arduino IDE, ESP32 Core, TFT_eSPI with CYD Config
Install the Arduino IDE 2.x, add the Espressif ESP32 board package, install TFT_eSPI with the exact CYD-specific User_Setup.h configuration, and upload a "Hello" sketch that lights the backlight and draws text on the ILI9341 display. Getting TFT_eSPI configured correctly is the single biggest wall in this project — a wrong pin definition produces a permanently blank white screen with no error message.
  1. Install Arduino IDE 2.x. Download from arduino.cc/en/software. Choose the installer for your OS. The 2.x series is required — it includes the integrated library manager and board manager needed for the steps below. After installation, launch the IDE before continuing.
  2. Add the Espressif ESP32 board package. Open File > Preferences. In the "Additional Boards Manager URLs" field, paste this URL exactly:
    https://raw.githubusercontent.com/espressif/arduino-esp32/gh-pages/package_esp32_index.json
    Click OK. Then open Tools > Board > Boards Manager, search for esp32, find "esp32 by Espressif Systems", and click Install. The current stable release is 3.x. Installation downloads roughly 300 MB and takes a few minutes.
    Board selection after install: go to Tools > Board > esp32 > ESP32 Dev Module. The CYD does not have a dedicated board entry; "ESP32 Dev Module" is correct and is what the CYD community uses universally.
  3. Install the TFT_eSPI library. Open Sketch > Include Library > Manage Libraries, search for TFT_eSPI, find the entry by Bodmer, and click Install. The current version is 2.5.x. After install the library files land at Documents/Arduino/libraries/TFT_eSPI/ (Windows/macOS) or ~/Arduino/libraries/TFT_eSPI/ (Linux).
  4. Apply the CYD-specific User_Setup.h — the critical step. TFT_eSPI ships with a generic User_Setup.h configured for different hardware. The CYD (ESP32-2432S028R) uses specific pins that differ from the defaults: the display SPI bus uses IO13/14/12/15/2, the backlight is on IO21, and the XPT2046 touch controller runs on its own separate SPI bus on IO25/32/33/36/39. If you use the wrong config you get a white screen.

    Navigate to your TFT_eSPI library folder and open User_Setup.h in a text editor. Replace the entire contents with the following. This is the canonical config from the official CYD repository (github.com/witnessmenow/ESP32-Cheap-Yellow-Display):
    // CYD (ESP32-2432S028R) TFT_eSPI User_Setup.h // Source: github.com/witnessmenow/ESP32-Cheap-Yellow-Display #define USER_SETUP_INFO "CYD ESP32-2432S028R" // Driver: ILI9341_2_DRIVER is the correct variant for the CYD. // Do NOT use ILI9341_DRIVER (standard) -- the _2 variant fixes // colour and init differences present on this specific panel. #define ILI9341_2_DRIVER // Display dimensions (portrait storage, landscape in use) #define TFT_WIDTH 240 #define TFT_HEIGHT 320 // TFT SPI pins (HSPI bus on ESP32) #define TFT_MISO 12 #define TFT_MOSI 13 #define TFT_SCLK 14 #define TFT_CS 15 // Chip select #define TFT_DC 2 // Data/Command (labelled RS on some boards) #define TFT_RST -1 // RST tied to ESP32 EN pin on the CYD; -1 = use EN // Backlight #define TFT_BL 21 #define TFT_BACKLIGHT_ON HIGH // Use HSPI port (not default VSPI) because the CYD display is wired to HSPI #define USE_HSPI_PORT // SPI speeds #define SPI_FREQUENCY 55000000 #define SPI_READ_FREQUENCY 20000000 #define SPI_TOUCH_FREQUENCY 2500000 // Fonts #define LOAD_GLCD #define LOAD_FONT2 #define LOAD_FONT4 #define LOAD_FONT6 #define LOAD_FONT7 #define LOAD_FONT8 #define LOAD_GFXFF #define SMOOTH_FONT
    Save the file. Do not change anything else in the TFT_eSPI folder.
    Why ILI9341_2_DRIVER? The CYD uses a panel variant that requires a slightly different initialization sequence. The standard ILI9341_DRIVER may produce washed-out colours or fail to init cleanly on some CYD units. The official CYD repository specifies ILI9341_2_DRIVER as the tested-correct choice.
    Disable TFT_eSPI's own touch driver: some TFT_eSPI versions ship a #define TOUCH_CS 21 line in User_Setup.h. We drive the XPT2046 touch with the separate XPT2046_Touchscreen library on its own SPI bus (Phase 2), so leave TOUCH_CS commented out / undefined here — if both try to own the touch controller you get ghost touches or a dead screen.
  5. Install the XPT2046_Touchscreen library. In the Library Manager, search for XPT2046_Touchscreen by Paul Stoffregen and install it. This handles the resistive touch controller on the CYD's separate SPI bus. The current version is 1.4.x.
  6. Connect the CYD and select port and board settings. Plug the CYD into your computer via USB. In Arduino IDE:
    • Tools > Board > ESP32 Dev Module
    • Tools > Port > select the COM port (Windows) or /dev/ttyUSB0 (Linux) or /dev/cu.usbserial-... (macOS) that appeared when you plugged in
    • Tools > Upload Speed > 921600 (default, leave as-is)
    • Tools > Flash Size > 4MB (32Mb)
    • All other settings remain at default
  7. Upload the Hello sketch to verify display and backlight. Create a new sketch (File > New Sketch) and paste:
    /* * CYD Phase 1 -- Display Hello World * Board: ESP32-2432S028R (Cheap Yellow Display) * Requires: TFT_eSPI with CYD User_Setup.h applied */ #include <TFT_eSPI.h> TFT_eSPI tft = TFT_eSPI(); void setup() { Serial.begin(115200); // Init display and turn on backlight tft.init(); tft.setRotation(1); // Landscape: 320 wide, 240 tall pinMode(TFT_BL, OUTPUT); digitalWrite(TFT_BL, HIGH); // Backlight on // Draw background and text tft.fillScreen(TFT_BLACK); tft.setTextColor(TFT_GREEN, TFT_BLACK); tft.setTextSize(2); tft.setCursor(20, 80); tft.println("CYD Field Terminal"); tft.setTextSize(1); tft.setCursor(20, 120); tft.setTextColor(TFT_CYAN, TFT_BLACK); tft.println("Display: ILI9341 240x320"); tft.setCursor(20, 136); tft.println("Phase 1: Display OK"); Serial.println("CYD display initialized."); } void loop() { // Nothing needed -- display holds its content }
    Click the Upload arrow (right-pointing triangle). Compilation takes 20–40 seconds on first run. After "Done uploading" appears in the status bar, the CYD resets automatically.
White or blank screen after upload?
  • The most common cause is a wrong User_Setup.h. Open the file at Arduino/libraries/TFT_eSPI/User_Setup.h and verify ILI9341_2_DRIVER is defined and USE_HSPI_PORT is uncommented. A single wrong pin or missing define produces a white screen.
  • If the screen is white immediately at power-on (before upload), the display is initializing to its default white state, which is normal. The screen should change after a successful upload.
  • Backlight stays off? Confirm TFT_BL 21 is in your User_Setup.h and that pinMode(TFT_BL, OUTPUT) and digitalWrite(TFT_BL, HIGH) are both present in setup().
  • Compile error "TFT_eSPI.h not found": the library was not installed, or you forgot to save User_Setup.h before compiling. Re-install via Library Manager and retry.
Board not found / no serial port?
  • Windows: install the CH340 USB-to-serial driver. Search "CH340 driver Windows" and download from wch-ic.com. After install, unplug and replug the CYD — the COM port should appear in Device Manager.
  • Linux: add yourself to the dialout group: sudo usermod -aG dialout $USER, then log out and back in. The CYD should appear at /dev/ttyUSB0.
  • macOS: the CH340 driver is usually not needed on macOS 10.15+. If the port does not appear, download the CH341SER_MAC.ZIP from wch-ic.com.
Checkpoint — what you see on the device
After upload the CYD screen shows a black background with "CYD Field Terminal" in green text and "Phase 1: Display OK" in cyan. The backlight is fully bright. The Arduino IDE serial monitor (set to 115200 baud) prints "CYD display initialized." If you see this, your TFT_eSPI config is correct and the display is fully functional.

Touch Input — XPT2046 on Its Own SPI Bus + Tabbed UI Skeleton
The CYD's XPT2046 touch controller is wired to a separate SPI bus from the display (IO25/32/33/36/39 vs. the display's IO13/14/12/15/2). This dual-SPI architecture is the second common wall: treating them as one bus causes touch to not respond or produce wildly wrong coordinates. In this phase you initialize both buses independently and build the four-tab skeleton that all later phases plug into.
  1. Understand the two SPI buses. The CYD uses the ESP32's HSPI bus for the ILI9341 display (handled by TFT_eSPI with USE_HSPI_PORT). The XPT2046 touch controller is wired to a completely separate set of pins and requires its own SPI instance. Pins confirmed from the official CYD repository:
    // Touch controller pins (XPT2046) -- separate from display SPI #define TOUCH_CS 33 #define TOUCH_CLK 25 #define TOUCH_MOSI 32 #define TOUCH_MISO 39 #define TOUCH_IRQ 36
  2. Install NimBLE-Arduino now (needed for Phase 4, install early to avoid interrupting flow). In Library Manager, search NimBLE-Arduino by h2zero and install version 2.5.x or newer (do NOT use 1.x, and avoid early 2.0–2.2 releases — they had documented crashes when re-initializing BLE between tab switches, which this project does every time you re-open the BLE tab). This library uses the ESP32's built-in Bluetooth stack but with a much lower memory footprint than the default Arduino BLE library — critical because BLE and WiFi both need RAM on the ESP32.
    NimBLE 2.x vs 1.x API difference: if you previously used NimBLE 1.x, note that the scan callback class is now NimBLEScanCallbacks (not NimBLEAdvertisedDeviceCallbacks) and the method to register it is setScanCallbacks(). Phase 4 uses the 2.x API throughout.
  3. Upload the tabbed UI skeleton. This sketch creates the four-tab framework and verifies touch coordinates are correctly mapped. All later phases slot into this structure by replacing the placeholder tab content functions:
    /* * CYD Phase 2 -- Tabbed UI + Touch Skeleton * Board: ESP32-2432S028R * Requires: TFT_eSPI (CYD User_Setup.h applied), XPT2046_Touchscreen */ #include <TFT_eSPI.h> #include <SPI.h> #include <XPT2046_Touchscreen.h> // ── Touch pins (XPT2046 on its own VSPI instance) ────────────── #define TOUCH_CS 33 #define TOUCH_CLK 25 #define TOUCH_MOSI 32 #define TOUCH_MISO 39 #define TOUCH_IRQ 36 SPIClass touchSPI(VSPI); XPT2046_Touchscreen ts(TOUCH_CS, TOUCH_IRQ); TFT_eSPI tft = TFT_eSPI(); // ── Tab state ─────────────────────────────────────────────────── const int NUM_TABS = 4; const char* tabNames[NUM_TABS] = {"WiFi", "BLE", "Net", "Pkt"}; int activeTab = 0; // Tab bar geometry (landscape: 320x240) const int TAB_Y = 0; const int TAB_H = 28; const int TAB_W = 320 / NUM_TABS; // 80px each const int CONTENT_Y = TAB_H; const int CONTENT_H = 240 - TAB_H; // Forward declarations so drawTabContent() can call the per-tab functions // regardless of where they are defined later (added across Phases 3-6). // Without these, pasting the phases in order can fail to compile. void drawWifiTab(); void drawBleTab(); void drawPktTab(); void drawNetTab(); // Touch calibration for CYD (adjust if your screen is off) // Raw touch ranges: X typically 200-3800, Y typically 300-3800 const int TOUCH_X_MIN = 200; const int TOUCH_X_MAX = 3800; const int TOUCH_Y_MIN = 300; const int TOUCH_Y_MAX = 3800; // ── Draw tab bar ──────────────────────────────────────────────── void drawTabs() { for (int i = 0; i < NUM_TABS; i++) { int x = i * TAB_W; bool active = (i == activeTab); tft.fillRect(x, TAB_Y, TAB_W, TAB_H, active ? TFT_MAGENTA : TFT_DARKGREY); tft.drawRect(x, TAB_Y, TAB_W, TAB_H, TFT_WHITE); tft.setTextColor(active ? TFT_BLACK : TFT_WHITE, TFT_TRANSPARENT); tft.setTextSize(1); // Centre text in tab int tx = x + (TAB_W - strlen(tabNames[i]) * 6) / 2; int ty = TAB_Y + (TAB_H - 8) / 2; tft.setCursor(tx, ty); tft.print(tabNames[i]); } } // ── Draw placeholder content for active tab ───────────────────── void drawTabContent() { tft.fillRect(0, CONTENT_Y, 320, CONTENT_H, TFT_BLACK); tft.setTextColor(TFT_CYAN, TFT_BLACK); tft.setTextSize(1); tft.setCursor(10, CONTENT_Y + 10); tft.print("Tab: "); tft.print(tabNames[activeTab]); tft.setCursor(10, CONTENT_Y + 26); tft.setTextColor(TFT_WHITE, TFT_BLACK); tft.print("Touch a tab above to switch"); } // ── Map raw touch to screen coordinates ───────────────────────── // Returns true if a valid touch was detected, sets sx/sy to screen coords bool getTouch(int &sx, int &sy) { if (!ts.touched()) return false; TS_Point p = ts.getPoint(); // Map raw ADC values to screen pixels (landscape rotation 1) sx = map(p.x, TOUCH_X_MIN, TOUCH_X_MAX, 0, 320); sy = map(p.y, TOUCH_Y_MIN, TOUCH_Y_MAX, 0, 240); sx = constrain(sx, 0, 319); sy = constrain(sy, 0, 239); return true; } void setup() { Serial.begin(115200); // Init display tft.init(); tft.setRotation(1); pinMode(TFT_BL, OUTPUT); digitalWrite(TFT_BL, HIGH); tft.fillScreen(TFT_BLACK); // Init touch on VSPI with explicit pin assignment touchSPI.begin(TOUCH_CLK, TOUCH_MISO, TOUCH_MOSI, TOUCH_CS); ts.begin(touchSPI); ts.setRotation(1); drawTabs(); drawTabContent(); Serial.println("Tabbed UI ready. Touch tabs to switch."); } void loop() { int sx, sy; if (getTouch(sx, sy)) { // Check if touch is in the tab bar if (sy < TAB_H) { int newTab = sx / TAB_W; if (newTab >= 0 && newTab < NUM_TABS && newTab != activeTab) { activeTab = newTab; drawTabs(); drawTabContent(); Serial.print("Switched to tab: "); Serial.println(tabNames[activeTab]); } } delay(200); // Debounce } }
Touch not responding at all?
  • Confirm XPT2046_Touchscreen by Paul Stoffregen is installed in Library Manager — not a different XPT2046 library. There are several; the Stoffregen version is the correct one for this setup.
  • Confirm touchSPI.begin(TOUCH_CLK, TOUCH_MISO, TOUCH_MOSI, TOUCH_CS) uses the exact pin numbers above. A single transposed pin will silence the touch controller.
  • The IRQ pin (IO36) is input-only on the ESP32 and cannot be driven high. This is correct behavior — do not attempt to pinMode(TOUCH_IRQ, OUTPUT).
Touch coordinates are inverted or wrong quadrant?
  • The XPT2046 raw ADC values vary between individual boards. If tapping the left side registers as right (or top as bottom), adjust TOUCH_X_MIN/TOUCH_X_MAX and similarly for Y. Open Serial Monitor at 115200 baud, add Serial.printf("raw %d %d\n", p.x, p.y); after ts.getPoint() to read your board's actual raw range, then update the constants accordingly.
  • If ts.setRotation(1) produces a 90-degree offset, try values 0, 2, or 3 until tab taps line up with the drawn tabs.
Checkpoint — what you see on the device
The CYD shows four tabs across the top (WiFi / BLE / Net / Pkt) with the active tab highlighted in magenta. Tapping each tab changes which tab is highlighted and updates the content area text to show the new tab name. The Serial Monitor prints "Switched to tab: WiFi" (or BLE/Net/Pkt) each time you tap. All four tabs respond to touch.

WiFi Scanner Tab — SSID, RSSI, Channel, Encryption
Wire the WiFi Scanner into the Phase 2 tab skeleton. When the WiFi tab is active the ESP32 calls WiFi.scanNetworks() (blocking scan), waits for results, and renders each network as a row showing SSID, RSSI in dBm, channel number, and encryption type.
Authorization reminder: WiFi scanning observes beacon frames that access points broadcast publicly to announce their presence. This is a passive, read-only operation. You are not associating with, connecting to, or transmitting to any of these networks.
  1. Extend your Phase 2 sketch with WiFi scanning. Add #include <WiFi.h> at the top. Add the following function before setup():
    // ── WiFi Scanner Tab ──────────────────────────────────────────── // Maps WiFi encryption type enum to a short label const char* encLabel(wifi_auth_mode_t enc) { switch (enc) { case WIFI_AUTH_OPEN: return "Open"; WiFi.scanNetworks() always returns 0?
  • Call WiFi.mode(WIFI_STA) before scanning. Without setting station mode, the scan may return 0 results.
  • The CYD's antenna is the small PCB trace on the board edge. Ensure the board is not inside a metal enclosure. Moving the board away from a dense RF environment (computers, monitors) often reveals more networks.
  • Some dual-band routers broadcast only on 5 GHz. The ESP32 supports only 2.4 GHz. 5 GHz-only networks will not appear — this is expected.
Checkpoint — what you see on the device
Tapping the WiFi tab triggers a scan. Signal strength is colour-coded: green for strong (>= -55 dBm), yellow for medium, red for weak. The footer shows the total network count. Tapping the WiFi tab again triggers a fresh rescan.

BLE Recon Tab — NimBLE-Arduino 2.x Device Discovery
Add the BLE discovery tab using NimBLE-Arduino 2.5.x. NimBLE uses roughly 25 KB of heap vs. ~100 KB for the stock Bluedroid library — critical on the ESP32 where BLE and WiFi compete for the same RAM. The BLE tab performs a 5-second passive scan, collects advertising devices, and displays each device's name (or MAC if unnamed), address, and RSSI. Note: NimBLE 2.x changed the scan callback class from NimBLEAdvertisedDeviceCallbacks (1.x) to NimBLEScanCallbacks (2.x). The code below uses the current API.
Authorization reminder: BLE advertisement scanning observes packets that Bluetooth devices broadcast publicly to announce their presence to any receiver within range. Devices advertise by design — it is how Bluetooth pairing works. This is a passive receive-only operation. You are not connecting to, pairing with, or sending any data to any device.
  1. Add NimBLE includes at the top of your sketch. The NimBLE 2.x API initializes BLE in a single call and provides a scan object that collects advertising reports:
    // Add these at the top of your sketch with the other includes: #include <NimBLEDevice.h> #include <NimBLEScan.h> #include <NimBLEAdvertisedDevice.h>
  2. Add global BLE state variables. Declare these after your tab constants (outside any function):
    // ── BLE state ─────────────────────────────────────────────────── struct BleEntry { char name[32]; char addr[18]; int rssi; }; const int MAX_BLE = 20; BleEntry bleDevices[MAX_BLE]; int bleCount = 0;
  3. Add the NimBLE 2.x scan callback class and scan function. In NimBLE 2.x the callback class is NimBLEScanCallbacks and the discovery method is onResult(). Add this before setup():
    // ── NimBLE 2.x scan callback ──────────────────────────────────── // NimBLEScanCallbacks replaces NimBLEAdvertisedDeviceCallbacks from 1.x class BleScanCallbacks : public NimBLEScanCallbacks { void onResult(const NimBLEAdvertisedDevice* device) override { if (bleCount >= MAX_BLE) return; BleEntry& e = bleDevices[bleCount]; // Get device name (empty string if not advertised) std::string nameStr = device->getName(); if (nameStr.empty()) { strncpy(e.name, "(unnamed)", sizeof(e.name) - 1); } else { strncpy(e.name, nameStr.c_str(), sizeof(e.name) - 1); } e.name[sizeof(e.name) - 1] = '\0'; // Get MAC address string std::string addrStr = device->getAddress().toString(); strncpy(e.addr, addrStr.c_str(), sizeof(e.addr) - 1); e.addr[sizeof(e.addr) - 1] = '\0'; e.rssi = device->getRSSI(); bleCount++; } }; // Run a 5-second BLE passive scan and populate bleDevices[] void runBleScan() { bleCount = 0; NimBLEDevice::init("CYD-Terminal"); NimBLEScan* pScan = NimBLEDevice::getScan(); // setScanCallbacks(callbacks, wantDuplicates) pScan->setScanCallbacks(new BleScanCallbacks(), false); pScan->setActiveScan(false); // passive scan -- no SCAN_REQ packets sent pScan->setInterval(97); pScan->setWindow(37); pScan->start(5, false); // 5-second blocking scan NimBLEDevice::deinit(true); // release BLE stack memory after scan } // ── BLE Tab Draw ──────────────────────────────────────────────── void drawBleTab() { tft.fillRect(0, CONTENT_Y, 320, CONTENT_H, TFT_BLACK); Compile error: NimBLEScanCallbacks not found or wrong method signature?
  • Confirm you installed NimBLE-Arduino 2.x (h2zero) via Library Manager. If you have NimBLE 1.x installed, the class name is different (NimBLEAdvertisedDeviceCallbacks). Update to 2.5.x in Library Manager and re-compile.
  • The onResult parameter changed between versions. In 2.x the signature is void onResult(const NimBLEAdvertisedDevice* device) with a const pointer. Missing const will cause a virtual method override error.
Guru Meditation Error / crash when entering BLE tab?
  • The most common cause is running BLE and WiFi concurrently without adequate stack. The sketch above calls WiFi.scanDelete() at the end of the WiFi tab draw and NimBLEDevice::deinit(true) at the end of BLE scan. Make sure both are present — leaving the BLE stack initialized while starting a WiFi scan (or vice versa) exhausts heap on the ESP32.
  • If you see ENOMEM in the panic trace, check heap in setup with Serial.printf("Free heap: %d\n", ESP.getFreeHeap());. If heap is below 50 KB before scanning, reduce MAX_BLE from 20 to 10.
0 BLE devices found even though you have phones nearby?
  • Modern phones randomize their Bluetooth advertising MAC addresses and reduce advertising frequency when the screen is off. Turn your phone screen on and open a Bluetooth settings screen to increase advertising rate. You should see the phone appear within the 5-second window.
  • Bluetooth earbuds in pairing mode advertise aggressively and are excellent test targets. Put a pair of earbuds in pairing mode and they will reliably appear in the scan.

Passive Frame Counter Tab — Promiscuous Mode on Your Own Network
The ESP32 WiFi radio can be placed in promiscuous mode, where it receives all 802.11 frames on a channel — not just frames addressed to it. This phase uses esp_wifi_set_promiscuous(true) and a callback to count Management, Data, and Control frames per second, displaying live counts on the CYD screen. This is a frame counter only: no payload content is read, stored, or displayed.
Authorization gate — promiscuous mode. Promiscuous mode receives all radio frames on a channel regardless of their destination address. Use this only on your own home or lab WiFi network on a channel you control. This sketch counts frame types but does not decode, store, or display any packet content, addresses, or payloads. Running promiscuous capture on a network you do not own or control constitutes unauthorized interception and is illegal in most jurisdictions.
  1. Remove the old drawPktTab() stub from Phase 3 since you are about to define the real version below — otherwise the sketch will fail to compile with a redefinition of 'void drawPktTab()' error.
  2. Add the ESP-IDF WiFi headers. The promiscuous API is in the ESP-IDF layer, accessible directly from Arduino sketches:
    // Add at the top with your other includes: #include <esp_wifi.h>
  3. Add global frame counter state. The promiscuous callback runs in the WiFi task context — use volatile counters and only read them from the main loop:
    // ── Promiscuous frame counters (volatile: written in callback) ── volatile uint32_t pktMgmt = 0; volatile uint32_t pktData = 0; volatile uint32_t pktCtrl = 0; volatile uint32_t pktTotal = 0; uint32_t lastPktTotal = 0; uint32_t pktPerSec = 0; unsigned long lastPktTime = 0; bool promiscActive = false; int sniffChannel = 6; // Channel to sniff -- change to your AP's channel
  4. Add the promiscuous callback and tab functions. IRAM_ATTR places the callback in fast IRAM to minimize latency when the WiFi task fires it:
    // ── Promiscuous RX callback (called by WiFi task) ─────────────── void IRAM_ATTR promiscRxCb(void* buf, wifi_promiscuous_pkt_type_t type) { pktTotal++; if (type == WIFI_PKT_MGMT) pktMgmt++; else if (type == WIFI_PKT_DATA) pktData++; else if (type == WIFI_PKT_CTRL) pktCtrl++; } // Start promiscuous mode on sniffChannel void startPromiscuous() { if (promiscActive) return; WiFi.disconnect(true); WiFi.mode(WIFI_STA); esp_wifi_set_channel(sniffChannel, WIFI_SECOND_CHAN_NONE); esp_wifi_set_promiscuous_rx_cb(promiscRxCb); esp_wifi_set_promiscuous(true); promiscActive = true; pktMgmt = 0; pktData = 0; pktCtrl = 0; pktTotal = 0; lastPktTotal = 0; lastPktTime = millis(); } // Stop promiscuous mode and return WiFi to normal void stopPromiscuous() { if (!promiscActive) return; esp_wifi_set_promiscuous(false); esp_wifi_set_promiscuous_rx_cb(nullptr); promiscActive = false; } // ── Packet tab: initial draw (called when tab becomes active) ─── void drawPktTab() { stopPromiscuous(); // Clear any prior state tft.fillRect(0, CONTENT_Y, 320, CONTENT_H, TFT_BLACK); tft.setTextColor(TFT_CYAN, TFT_BLACK); tft.setTextSize(1); tft.setCursor(4, CONTENT_Y + 4); tft.printf("PASSIVE FRAME COUNTER CH:%d", sniffChannel); tft.drawLine(0, CONTENT_Y + 14, 320, CONTENT_Y + 14, TFT_DARKGREY); tft.setTextColor(TFT_YELLOW, TFT_BLACK); tft.setCursor(4, CONTENT_Y + 20); tft.print("OWN NETWORK ONLY -- READ AUTH NOTICE"); tft.setCursor(4, CONTENT_Y + 36); tft.setTextColor(TFT_WHITE, TFT_BLACK); tft.print("MGMT: counting..."); tft.setCursor(4, CONTENT_Y + 54); tft.print("DATA: counting..."); tft.setCursor(4, CONTENT_Y + 72); tft.print("CTRL: counting..."); tft.setCursor(4, CONTENT_Y + 90); tft.print("TOTAL: counting..."); tft.setCursor(4, CONTENT_Y + 108); tft.print("PPS: --"); startPromiscuous(); } // Update counters in place (called from loop() when pkt tab is active) void updatePktTab() { unsigned long now = millis(); uint32_t d = pktData; uint32_t c = pktCtrl; uint32_t t = pktTotal; tft.setTextSize(1); tft.setTextColor(TFT_GREEN, TFT_BLACK); // Redraw numeric values only (not the static labels) tft.fillRect(60, CONTENT_Y + 36, 100, 10, TFT_BLACK); tft.setCursor(60, CONTENT_Y + 72); tft.printf("%lu", (unsigned long)c); tft.fillRect(60, CONTENT_Y + 90, 100, 10, TFT_BLACK); tft.setCursor(60, CONTENT_Y + 90); tft.printf("%lu", (unsigned long)t); tft.fillRect(60, CONTENT_Y + 108, 100, 10, TFT_BLACK); Frame counter stays at 0 even on your own network?
  • Confirm sniffChannel matches the actual channel your access point uses. Use the Phase 3 WiFi scanner to read it. If your AP is on channel 11 and you sniff channel 6, you will see 0 frames from your network.
  • Confirm WiFi.mode(WIFI_STA) runs before esp_wifi_set_promiscuous(true). Without STA mode the WiFi driver may not be initialized.
  • The callback must be registered before enabling promiscuous mode: esp_wifi_set_promiscuous_rx_cb(promiscRxCb) must come before esp_wifi_set_promiscuous(true).
High MGMT frame count but 0 DATA frames?
  • This is normal on a quiet network. Management frames (beacons, probe responses) are sent at roughly 10 per second by every access point regardless of data traffic. DATA frames only appear when devices are actively transferring data. Stream a video on a device connected to the AP you are monitoring and the DATA count will rise immediately.
Checkpoint — what you see on the device
Tapping the Pkt tab immediately begins counting. Within 1–2 seconds the MGMT counter starts incrementing (your access point broadcasts beacon frames at ~10/second). The TOTAL counter and PPS value update every second. When a device on your network transfers data (stream a video on your phone), the DATA counter increases noticeably. No payload content, MAC addresses, or SSID data is displayed — only the aggregate frame-type counts. Tapping any other tab stops promiscuous mode cleanly and the counters freeze.

Network Diagnostics Tab + Portable Power
Add the Net tab: connect to your own WiFi network and run three diagnostics on demand — a gateway ping (round-trip time via WiFiClient TCP connect timing), a DNS resolution via WiFi.hostByName(), and a TCP reachability check to port 80 on your gateway. Then cover powering the CYD from a USB battery bank so it operates as a true untethered field terminal without a computer.
  1. Set your WiFi credentials as constants. Near the top of your sketch, add your network credentials. The Net tab joins this network for diagnostics. Change these to match your own network:
    // ── Your WiFi credentials (Net tab diagnostics only) ────────── const char* STA_SSID = "YourNetworkName"; const char* STA_PASS = "YourPassword"; // ── Your gateway IP (typical home router defaults) ──────────── const char* GATEWAY_IP = "192.168.1.1"; // Change to match your router const char* DNS_HOST = "google.com"; // Hostname to resolve via DNS const int TCP_PORT = 80; // Port to check on GATEWAY_IP
    Finding your gateway IP: on Windows run ipconfig and read "Default Gateway". On macOS/Linux run ip route | grep default. Common values are 192.168.1.1 or 192.168.0.1.
  2. Add the Net tab draw function. This function connects to your WiFi, then runs three sequential diagnostics and prints results on the screen. Add before setup():
    // ── Net Diagnostics Tab ───────────────────────────────────────── void drawNetTab() { tft.fillRect(0, CONTENT_Y, 320, CONTENT_H, TFT_BLACK); tft.setTextSize(1); tft.setTextColor(TFT_CYAN, TFT_BLACK); tft.setCursor(4, CONTENT_Y + 4); tft.print("NET DIAGNOSTICS -- OWN NETWORK ONLY"); tft.drawLine(0, CONTENT_Y + 14, 320, CONTENT_Y + 14, TFT_DARKGREY); int lineY = CONTENT_Y + 20; // ── 1. Connect to WiFi ─────────────────────────────────────── tft.setTextColor(TFT_WHITE, TFT_BLACK); tft.setCursor(4, lineY); tft.printf("WiFi: connecting to %s", STA_SSID); lineY += 14; WiFi.mode(WIFI_STA); WiFi.begin(STA_SSID, STA_PASS); unsigned long t0 = millis(); while (WiFi.status() != WL_CONNECTED && millis() - t0 < 8000) { delay(200); } if (WiFi.status() != WL_CONNECTED) { tft.setTextColor(TFT_RED, TFT_BLACK); tft.setCursor(4, lineY); tft.print("FAILED -- check SSID/password"); WiFi.disconnect(true); return; } tft.setTextColor(TFT_GREEN, TFT_BLACK); tft.setCursor(4, lineY); tft.printf("OK IP: %s", WiFi.localIP().toString().c_str()); lineY += 20; // ── 2. Ping (TCP RTT to gateway port 80) ──────────────────── // The ESP32 Arduino SDK does not expose ICMP ping directly. // We measure TCP connect time to the gateway as a reliable RTT proxy. tft.setTextColor(TFT_WHITE, TFT_BLACK); tft.setCursor(4, lineY); tft.printf("PING %s (TCP RTT)", GATEWAY_IP); lineY += 14; WiFiClient client; client.setTimeout(2000); uint32_t rttSum = 0; int rttOk = 0; for (int i = 0; i < 4; i++) { unsigned long ts = millis(); bool ok = client.connect(GATEWAY_IP, TCP_PORT); unsigned long rtt = millis() - ts; client.stop(); tft.setCursor(4 + i * 76, lineY); if (ok) { tft.setTextColor(TFT_GREEN, TFT_BLACK); tft.printf("%lums", rtt); rttSum += rtt; rttOk++; } else { tft.setTextColor(TFT_RED, TFT_BLACK); tft.print("tout"); } delay(100); } lineY += 14; if (rttOk > 0) { tft.setTextColor(TFT_CYAN, TFT_BLACK); tft.setCursor(4, lineY); tft.printf("avg RTT: %lums (%d/4 OK)", rttSum / rttOk, rttOk); } else { tft.setTextColor(TFT_RED, TFT_BLACK); tft.setCursor(4, lineY); tft.print("gateway not reachable on TCP:80"); } lineY += 20; // ── 3. DNS resolution ──────────────────────────────────────── tft.setTextColor(TFT_WHITE, TFT_BLACK); tft.setCursor(4, lineY); tft.printf("DNS: resolving %s", DNS_HOST); lineY += 14; IPAddress resolvedIP; unsigned long dnsStart = millis(); bool dnsOk = WiFi.hostByName(DNS_HOST, resolvedIP); unsigned long dnsMs = millis() - dnsStart; if (dnsOk) { tft.setTextColor(TFT_GREEN, TFT_BLACK); tft.setCursor(4, lineY); tft.printf("-> %s %lums", resolvedIP.toString().c_str(), dnsMs); } else { tft.setTextColor(TFT_RED, TFT_BLACK); tft.setCursor(4, lineY); tft.print("DNS FAILED -- check WiFi/ISP"); } lineY += 20; // ── 4. Summary footer ──────────────────────────────────────── tft.setTextColor(TFT_DARKGREY, TFT_BLACK); tft.setCursor(4, lineY); tft.print("Tap Net tab to run diagnostics again."); WiFi.disconnect(true); }
  3. Remove the old drawNetTab() stub from Phase 3 since you just defined the real version. Upload the sketch. Tap the Net tab to run a full diagnostic cycle.
  4. Go portable: power the CYD from a USB battery bank. The CYD draws roughly 80–130 mA at 5V when the display is on and the radio is active. A standard 10,000 mAh USB power bank supplies over 60 hours of runtime — far more than practical field use requires. Any USB-A to micro-USB cable and a bank rated at 1A or higher will work. Notes:
    • Some power banks shut off when current draw is too low (the CYD in idle sometimes drops below 100 mA cutoff thresholds). If the bank shuts off, connect a small passive load alongside the CYD or choose a bank marketed as "always-on" or compatible with low-current devices.
    • The CYD has no battery charging circuit on-board. The USB port is power-in only. Do not attempt to add a LiPo directly to VCC without a proper battery management IC.
    • For a belt-clip or pocket form factor, a 2000–5000 mAh flat slim bank (such as the Anker PowerCore Slim 5000) fits alongside the CYD inside a small pouch and runs the terminal for 15–40 hours.
WiFi fails to connect in the Net tab?
  • Verify STA_SSID and STA_PASS are correct and that you are connecting to a 2.4 GHz network (the ESP32 does not support 5 GHz). Most dual-band routers broadcast both — look for the 2.4 GHz band SSID specifically.
  • The Net tab calls WiFi.disconnect(true) at exit to cleanly release the connection before other tabs use the WiFi radio for scanning. If switching tabs rapidly, wait 1–2 seconds for the disconnect to complete before tapping the Net tab again.
  • If WiFi connects but the gateway ping shows all timeouts: your gateway may not accept TCP connections on port 80. Try changing TCP_PORT to 443. Most home routers accept connections on at least one of these ports from the LAN side.
DNS resolves but shows an unexpected IP?
  • This is normal when your ISP uses DNS-based content filtering or returns a redirect IP for blocked domains. Try resolving a hostname you control, such as the hostname of a device on your LAN. Your router typically responds to DNS queries for its own admin hostname.
Checkpoint — what you see on the device
Tapping the Net tab shows "WiFi: connecting to [YourSSID]", then within a few seconds "OK IP: 192.168.x.x". Below that, four RTT measurements appear for the gateway (e.g. 4ms, 6ms, 5ms, 4ms) with an average. The DNS line resolves to an IP address (e.g. 142.250.80.46 for google.com). The final line invites another run. Unplugging from the computer and connecting a USB power bank, the terminal continues running all four tabs identically, with no computer attached.
