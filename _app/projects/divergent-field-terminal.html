Subject

Build a Multi-Protocol Field Terminal

Pro 150 min 2000 XP
Mission Brief

This operation is the capstone hardware build — a portable, touchscreen-driven multi-tool that combines WiFi scanning, Bluetooth Low Energy reconnaissance, network diagnostics, and packet sniffing into a single handheld field terminal. The ESP32 CYD becomes a Swiss Army knife for wireless assessment: a tabbed touch interface lets you switch between specialized tools, each running independently and sharing a common framework.

The WiFi tab scans and analyzes nearby networks with the full detail view from the WiFi Scanner project. The BLE tab discovers nearby Bluetooth devices, enumerates their advertised services, and logs device appearances. The Network Tools tab provides ping, DNS lookup, and port checking capabilities over an active WiFi connection. The Packet Sniffer tab drops into promiscuous mode for raw 802.11 frame capture with type filtering.

You will architect a tabbed UI framework with smooth touch transitions, implement four independent tool modules that share display and touch resources, manage the ESP32's WiFi radio state switching between station mode, scan mode, and promiscuous mode, and deliver a polished, production-quality embedded application. This is a Pro-level build that integrates every skill from the previous ESP32 projects into one cohesive instrument.

Agent Requirements
  • ESP32-2432S028R (CYD — Cheap Yellow Display)
  • Arduino IDE or PlatformIO with ESP32 board support
  • Solid C/C++ skills (classes/state machines/memory management)
  • Completed or familiar with the WiFi Scanner and Packet Dashboard projects
  • Understanding of BLE concepts (advertising/services/characteristics) is helpful
Operation Phases
1
Tab-Based Touch UI Framework
Design and implement a tabbed interface with 4 tabs rendered at the top of the 320x240 screen. Each tab has a label and icon indicator. Touch detection switches between tabs with a smooth visual transition. Build a base "Screen" class that each tool module inherits from, providing init(), update(), draw(), and handleTouch() methods.
Checkpoint: Tab-Based UI
  • All tabs render correctly on the touchscreen without overlap
  • Swiping or tapping switches between tabs with visual feedback
  • Status bar displays battery, WiFi, and time indicators
2
WiFi Scanner Tab
Implement the full WiFi scanner as a tab module: scan for networks, display a sorted scrollable list with RSSI bars, tap to drill into detail view, auto-refresh with new network alerts. Reuse the architecture from the WiFi Recon Scanner project, adapted to the tab framework's Screen interface.
Checkpoint: WiFi Scanner Tab
  • Scan results populate the list with SSID, RSSI, and encryption type
  • Signal strength bars update in real-time during continuous scanning
  • Tapping a network entry shows detailed information
3
BLE Scanner Tab
Switch to BLE scanning mode using BLEDevice::init() and BLEScan. Discover nearby BLE devices and display their name (or "Unknown"), MAC address, RSSI, and advertised service UUIDs in a scrollable list. Tap a device to see its full advertisement data. Track device appearances and disappearances over time.
Checkpoint: BLE Scanner Tab
  • BLE scan discovers nearby devices and displays their names and MAC addresses
  • RSSI values update as you move the terminal closer or farther from devices
  • Scan starts and stops cleanly without crashing the display
4
Network Tools Tab
Connect to a saved WiFi network (configurable SSID/password). Implement three sub-tools: (1) Ping — send ICMP echo requests to a user-entered IP and display round-trip time, (2) DNS Lookup — resolve a hostname to IP using the ESP32's DNS client, (3) Port Check — test if a specific port is open on a target IP using WiFiClient.connect(). Render results on the TFT with a touch keypad for IP entry.
Checkpoint: Network Tools Tab
  • Ping function sends ICMP packets and displays round-trip time
  • Port scanner identifies open ports on a target IP address
  • DNS lookup resolves hostnames and displays the IP result
5
Packet Sniffer Tab
Drop into promiscuous mode and display a live scrolling feed of captured frames showing: frame type, source MAC, destination MAC, RSSI, channel, and size. Add touch filter buttons to show only management, data, or control frames. Display a packets-per-second counter and total capture count. Handle the WiFi radio state transition cleanly between station mode (Network Tools) and promiscuous mode (Sniffer).
Checkpoint: Packet Sniffer Tab
  • Promiscuous mode captures packets on the current WiFi channel
  • Captured packets display source/destination MAC addresses and type
  • Packet count increments in real-time as traffic is captured
