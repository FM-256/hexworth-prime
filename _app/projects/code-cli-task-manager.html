Subject

Build a CLI Task Manager

Recruit 45 min 250 XP
Mission Brief

You are going to build a real, working command-line task manager in Python — start to finish, from a blank file. No prior terminal experience required. Every step tells you exactly what to type, where to type it, and what you should see when it works.

The finished tool lets you run commands like python tasks.py add "Buy milk", python tasks.py list, python tasks.py done 1, and python tasks.py remove 1 from any terminal. Tasks are saved to a file called tasks.json so nothing is lost when you close the window. The same pattern — subcommands, JSON storage, argparse — powers tools like git, aws, and docker.

Work through the phases in order. Each phase has a paste-ready code snapshot so you always know exactly what your file should look like, and a checkpoint that tells you exactly what to run and what to expect. If something goes wrong, the red troubleshooting boxes at the bottom of each phase cover the most common errors and how to fix them.

Agent Requirements
  • Python installed on your machine. If you are not sure whether you have it, Phase 1 walks you through checking and installing it. No prior Python experience is required — every line of code is provided.
  • VS Code (code.visualstudio.com, free) as your text editor. Do not use Notepad, TextEdit, or Microsoft Word — they can silently corrupt Python files with invisible characters.
  • A terminal. Mac and Linux have one built in. Windows users: the built-in PowerShell or Command Prompt both work — Phase 1 shows you how to open them. No Git Bash or WSL installation is required for this project.
  • Minimal disk space — the script and its data file are a few kilobytes.

Install Python, Open a Terminal, and Create tasks.py
Before writing any code you need Python running and a project folder set up. Go slowly — nothing here assumes you have done this before.
  1. Check whether Python is already installed.
    Mac / Linux: Open Terminal (Mac: press Cmd+Space, type Terminal, press Enter; Linux: press Ctrl+Alt+T). Type:
    python3 --version
    If you see something like Python 3.11.4 you are ready. Skip to step 3.
    Windows: Open PowerShell — press Win+R, type powershell, press Enter. Then try each of these in order and stop at the first one that prints a version number:
    python --version python3 --version py --version
    Make a note of which command worked. You will use that same command throughout this project.
    Why three commands? Windows does not standardize Python's name. python works on most Windows installs. python3 is the standard on Mac/Linux. py is the Windows Python Launcher and always works if Python was installed correctly. The rest of this project uses python in examples — substitute whichever command worked for you.
  2. Install Python if none of the commands above worked. Go to python.org/downloads and download the latest Python 3 installer for your operating system.
    Windows users — critical: on the first screen of the installer you will see a checkbox labeled Add Python to PATH at the very bottom. Check that box before clicking Install Now. If you miss it, Python installs but the terminal cannot find it. Do not click Modify — use Add to PATH only during a fresh install. After installation, close and reopen PowerShell and run python --version again.
    Mac users: the installer will ask you to agree to a license and then installs automatically. After it finishes, run python3 --version in a new terminal window.
    Windows: still "not recognized" after install. You installed Python without checking Add to PATH. The fix is to uninstall Python (Start → Settings → Apps, find Python, click Uninstall), then reinstall from python.org — this time check Add to PATH on the first screen. Do not use the Modify option; it does not reliably fix PATH.
  3. Create a project folder. In your terminal, run these two commands, pressing Enter after each:
    mkdir task-manager cd task-manager
    mkdir creates a new folder. cd moves you into it. Confirm you are inside it:
    pwd
    The output should end with task-manager. If it does not, re-run cd task-manager.
    What is pwd? It stands for “print working directory” — it tells you which folder your terminal is currently looking at. Every command you run operates on this folder, so it matters.
  4. Open the folder in VS Code. In VS Code, choose File → Open Folder. Navigate to your home folder and select task-manager. Once it opens, hover your mouse over the task-manager folder name in the Explorer panel on the left — a row of icons appears to the right of the folder name. Click the New File icon (it looks like a page with a plus sign). A text box appears in the Explorer panel. Type exactly tasks.py and press Enter.
    Spelling matters. The file must be named tasks.py — lowercase, with the .py extension. Do not use Ctrl+N or Cmd+N — that shortcut opens an untitled buffer, not a named file in your project folder. If VS Code shows the file without the .py extension, rename it in the Explorer panel by right-clicking and choosing Rename.
  5. Type this first line into tasks.py — just this one line for now:
    print("tasks.py is working")
  6. Save the file. Press Ctrl+S (Windows/Linux) or Cmd+S (Mac). The dot in the tab title disappears when the file is saved.
  7. Run it from the terminal. Switch back to your terminal window. Make sure you are still in the task-manager folder (run pwd if unsure), then run:
    python tasks.py
    (Use python3 tasks.py on Mac/Linux, or py tasks.py on Windows if that is what worked in step 1.)
"python is not recognized" / "command not found": Python is not installed or not on PATH. Follow step 2 above. On Windows, uninstall and reinstall with Add to PATH checked.
"No such file or directory: tasks.py": your terminal is not in the task-manager folder. Run pwd to see where you are, then run cd task-manager to get there. Then try again.
Checkpoint — what you should see
Running python tasks.py prints exactly one line: tasks.py is working. Nothing else. The prompt returns below it. If you see that line, Python is installed, the terminal is in the right folder, and VS Code saved the file correctly. Proceed to Phase 2.

Storage Layer — Load and Save Tasks as JSON
Before any commands exist you need a place to keep tasks between runs. You will write two functions that read from and write to tasks.json. Everything else in this project sits on top of these two functions.
  1. Replace the entire contents of tasks.py with this code. Select all (Ctrl+A / Cmd+A), delete, then paste the block below exactly. Indentation is made with 4 spaces per level — never mix spaces and tabs:
    tasks.py (complete file after phase 2)import json import os TASKS_FILE = "tasks.json" def load_tasks(): if not os.path.exists(TASKS_FILE): return [] try: with open(TASKS_FILE, "r") as f: content = f.read().strip() if not content: return [] return json.loads(content) except json.JSONDecodeError: print("Warning: tasks.json is corrupted. Starting with an empty list.") return [] def save_tasks(tasks): with open(TASKS_FILE, "w") as f: json.dump(tasks, f, indent=2) # Quick test tasks = load_tasks() print("Loaded", len(tasks), "tasks") save_tasks(tasks) print("tasks.json written successfully")
  2. Save the file (Ctrl+S / Cmd+S).
  3. Run it:
    python tasks.py
  4. Confirm tasks.json was created:
    dir
    On Mac/Linux use ls instead. You should see both tasks.py and tasks.json in the listing.
  5. Open tasks.json in VS Code to see what is inside. It should contain exactly:
    tasks.json contents[]
    That is an empty JSON array — a list with nothing in it yet. This is correct.
What the code does: load_tasks checks whether tasks.json exists before trying to read it — so the first run never crashes with "file not found." The try/except block catches a corrupt file (e.g. you accidentally saved something invalid) and starts fresh instead of crashing. save_tasks writes the full list back with json.dump, using indent=2 so the file is human-readable.
IndentationError: Python is strict about spacing. Every block inside a function must be indented 4 spaces. If you mixed tabs and spaces, VS Code shows a red squiggle. The simplest fix is to select all, delete, and paste the snapshot above again.
JSONDecodeError on the test run (not the warning): if tasks.json already existed from a previous experiment and contains invalid content, the except block catches it and prints the warning. The program still runs. Delete tasks.json and re-run to start clean.
Checkpoint — what you should see
Running python tasks.py prints: Loaded 0 tasks tasks.json written successfully A file named tasks.json exists in the task-manager folder and contains []. Running the script a second time produces the same output — no errors. Proceed to Phase 3.

Add the add and list Commands with argparse
Now you will wire up your first two real subcommands: add puts a new task into the file, and list prints all tasks to the screen. After this phase the tool is already useful.
  1. Replace the entire contents of tasks.py with the snapshot below. Select all, delete, paste. Every line matters — especially the indentation:
    tasks.py (complete file after phase 3)import json import os import argparse TASKS_FILE = "tasks.json" def load_tasks(): if not os.path.exists(TASKS_FILE): return [] try: with open(TASKS_FILE, "r") as f: content = f.read().strip() if not content: return [] return json.loads(content) except json.JSONDecodeError: print("Warning: tasks.json is corrupted. Starting with an empty list.") return [] def save_tasks(tasks): with open(TASKS_FILE, "w") as f: json.dump(tasks, f, indent=2) def next_id(tasks): if not tasks: return 1 return max(t["id"] for t in tasks) + 1 def cmd_add(args): tasks = load_tasks() task = { "id": next_id(tasks), "title": args.title, "done": False } tasks.append(task) save_tasks(tasks) print("Added task", task["id"], ":", task["title"]) def cmd_list(args): tasks = load_tasks() if not tasks: print("No tasks yet. Add one with: python tasks.py add \"your task\"") return for t in tasks: status = "[x]" if t["done"] else "[ ]" print(status, str(t["id"]).rjust(3), " ", t["title"]) def main(): parser = argparse.ArgumentParser( prog="tasks", description="A simple command-line task manager" ) subparsers = parser.add_subparsers(dest="command") # add p_add = subparsers.add_parser("add", help="Add a new task") p_add.add_argument("title", help="Task description in quotes") p_add.set_defaults(func=cmd_add) # list p_list = subparsers.add_parser("list", help="List all tasks") p_list.set_defaults(func=cmd_list) args = parser.parse_args() if args.command is None: parser.print_help() return args.func(args) if __name__ == "__main__": main()
  2. Save the file (Ctrl+S / Cmd+S).
  3. Add your first task:
    python tasks.py add "Buy milk"
  4. Add a second task:
    python tasks.py add "Read chapter 3"
  5. List all tasks:
    python tasks.py list
    Expected output:
    expected terminal output[ ] 1 Buy milk [ ] 2 Read chapter 3
  6. Open tasks.json in VS Code and confirm it now contains two entries with "done": false.
What argparse does: argparse.ArgumentParser reads the words you type after python tasks.py and routes them to the right function. add_subparsers creates the subcommand layer. When you type python tasks.py add "Buy milk", argparse sets args.command = "add" and args.title = "Buy milk", then calls cmd_add(args). Each subparser is wired to its function with set_defaults(func=...).
"error: argument command: invalid choice" or "unrecognized arguments": you may have a typo in the subcommand name. The valid commands right now are exactly add and list (lowercase). Running python tasks.py with no arguments prints the help text listing valid commands.
"tasks.json not found" when listing: your terminal may be in a different folder than where you ran the add command. tasks.json is created in whichever folder your terminal is in at the time. Run pwd, confirm it ends in task-manager, then try again.
IndentationError on any line: Python requires consistent 4-space indentation. Do not use the Tab key for indentation in Python files — use the spacebar, or paste the snapshot above exactly. VS Code shows red squiggles on lines with bad indentation.
Checkpoint — what you should see
After adding two tasks and running python tasks.py list, the terminal shows two lines: [ ] 1 Buy milk and [ ] 2 Read chapter 3. Opening tasks.json shows a JSON array with two objects, each with an id, title, and "done": false. Running python tasks.py with no arguments prints the help text. Proceed to Phase 4.

4
Mark Tasks Done with done N
You will add a done subcommand that marks a task complete by its ID number. After running python tasks.py done 1, the task appears with [x] in the list and stays marked across restarts.
  1. Replace the entire contents of tasks.py with the snapshot below. The new code adds cmd_done and its subparser. Everything from Phase 3 is preserved:
    tasks.py (complete file after phase 4)import json import os import argparse TASKS_FILE = "tasks.json" def load_tasks(): if not os.path.exists(TASKS_FILE): return [] try: with open(TASKS_FILE, "r") as f: content = f.read().strip() if not content: return [] return json.loads(content) except json.JSONDecodeError: print("Warning: tasks.json is corrupted. Starting with an empty list.") return [] def save_tasks(tasks): with open(TASKS_FILE, "w") as f: json.dump(tasks, f, indent=2) def next_id(tasks): if not tasks: return 1 return max(t["id"] for t in tasks) + 1 def cmd_add(args): tasks = load_tasks() task = { "id": next_id(tasks), "title": args.title, "done": False } tasks.append(task) save_tasks(tasks) print("Added task", task["id"], ":", task["title"]) def cmd_list(args): tasks = load_tasks() if not tasks: print("No tasks yet. Add one with: python tasks.py add \"your task\"") return for t in tasks: status = "[x]" if t["done"] else "[ ]" print(status, str(t["id"]).rjust(3), " ", t["title"]) def cmd_done(args): tasks = load_tasks() for t in tasks: if t["id"] == args.task_id: t["done"] = True save_tasks(tasks) print("Marked done:", t["title"]) return print("Error: no task with ID", args.task_id) def main(): parser = argparse.ArgumentParser( prog="tasks", description="A simple command-line task manager" ) subparsers = parser.add_subparsers(dest="command") # add p_add = subparsers.add_parser("add", help="Add a new task") p_add.add_argument("title", help="Task description in quotes") p_add.set_defaults(func=cmd_add) # list p_list = subparsers.add_parser("list", help="List all tasks") p_list.set_defaults(func=cmd_list) # done p_done = subparsers.add_parser("done", help="Mark a task complete by ID") p_done.add_argument("task_id", type=int, help="Task ID number") p_done.set_defaults(func=cmd_done) args = parser.parse_args() if args.command is None: parser.print_help() return args.func(args) if __name__ == "__main__": main()
  2. Save the file (Ctrl+S / Cmd+S).
  3. Mark task 1 as done:
    python tasks.py done 1
    Expected output: Marked done: Buy milk
  4. List all tasks to see the updated status:
    python tasks.py list
    Expected output:
    expected terminal output[x] 1 Buy milk [ ] 2 Read chapter 3
  5. Close and reopen your terminal (close the window entirely, open a new one, and cd task-manager again). Run python tasks.py list. Task 1 should still show [x] — it survived the restart because it is saved in tasks.json.
Why type=int? When you type python tasks.py done 1, argparse receives the string "1". The type=int argument converts it to the number 1 automatically, so the comparison t["id"] == args.task_id works correctly. Without it you would be comparing the number 1 to the string "1" and no task would ever match.
"Error: no task with ID 1" even though task 1 exists: open tasks.json in VS Code and check whether the "id" values are numbers (like 1) or strings (like "1"). If they are strings, the type=int conversion creates a mismatch. Replace tasks.json by deleting the file, then re-adding your tasks from scratch using the current version of the script.
"invalid int value" error: you passed a word instead of a number to done. The command is python tasks.py done 1 — the number goes directly after done with no extra words.
Checkpoint — what you should see
Running python tasks.py done 1 prints Marked done: Buy milk. Running python tasks.py list shows [x] 1 Buy milk and [ ] 2 Read chapter 3. Closing and reopening the terminal, navigating back to task-manager, and listing again shows the same state. Proceed to Phase 5.

Delete Tasks with remove N — Finished Tool
The final command lets you permanently remove a task by its ID. After this phase you have a fully working CLI task manager: add, list, done, and remove — the complete CRUD cycle.
  1. Replace the entire contents of tasks.py with the final snapshot below. This adds cmd_remove and its subparser:
    tasks.py (finished — complete file)import json import os import argparse TASKS_FILE = "tasks.json" def load_tasks(): if not os.path.exists(TASKS_FILE): return [] try: with open(TASKS_FILE, "r") as f: content = f.read().strip() if not content: return [] return json.loads(content) except json.JSONDecodeError: print("Warning: tasks.json is corrupted. Starting with an empty list.") return [] def save_tasks(tasks): with open(TASKS_FILE, "w") as f: json.dump(tasks, f, indent=2) def next_id(tasks): if not tasks: return 1 return max(t["id"] for t in tasks) + 1 def cmd_add(args): tasks = load_tasks() task = { "id": next_id(tasks), "title": args.title, "done": False } tasks.append(task) save_tasks(tasks) print("Added task", task["id"], ":", task["title"]) def cmd_list(args): tasks = load_tasks() if not tasks: print("No tasks yet. Add one with: python tasks.py add \"your task\"") return for t in tasks: status = "[x]" if t["done"] else "[ ]" print(status, str(t["id"]).rjust(3), " ", t["title"]) def cmd_done(args): tasks = load_tasks() for t in tasks: if t["id"] == args.task_id: t["done"] = True save_tasks(tasks) print("Marked done:", t["title"]) return print("Error: no task with ID", args.task_id) def cmd_remove(args): tasks = load_tasks() original_count = len(tasks) tasks = [t for t in tasks if t["id"] != args.task_id] if len(tasks) == original_count: print("Error: no task with ID", args.task_id) return save_tasks(tasks) print("Removed task", args.task_id) def main(): parser = argparse.ArgumentParser( prog="tasks", description="A simple command-line task manager" ) subparsers = parser.add_subparsers(dest="command") # add p_add = subparsers.add_parser("add", help="Add a new task") p_add.add_argument("title", help="Task description in quotes") p_add.set_defaults(func=cmd_add) # list p_list = subparsers.add_parser("list", help="List all tasks") p_list.set_defaults(func=cmd_list) # done p_done = subparsers.add_parser("done", help="Mark a task complete by ID") p_done.add_argument("task_id", type=int, help="Task ID number") p_done.set_defaults(func=cmd_done) # remove p_remove = subparsers.add_parser("remove", help="Delete a task by ID") p_remove.add_argument("task_id", type=int, help="Task ID number") p_remove.set_defaults(func=cmd_remove) args = parser.parse_args() if args.command is None: parser.print_help() return args.func(args) if __name__ == "__main__": main()
  2. Save the file (Ctrl+S / Cmd+S).
  3. Run the full workflow from start to finish to confirm the finished tool works:
    python tasks.py add "Fix the login bug" python tasks.py add "Write the report" python tasks.py add "Call the client" python tasks.py list python tasks.py done 4 python tasks.py list python tasks.py remove 2 python tasks.py list
  4. Expected terminal output — run each command in sequence and compare:
    expected terminal output (all commands in sequence)Added task 3 : Fix the login bug Added task 4 : Write the report Added task 5 : Call the client [x] 1 Buy milk [ ] 2 Read chapter 3 [ ] 3 Fix the login bug [ ] 4 Write the report [ ] 5 Call the client Marked done: Write the report [x] 1 Buy milk [ ] 2 Read chapter 3 [ ] 3 Fix the login bug [x] 4 Write the report [ ] 5 Call the client Removed task 2 [x] 1 Buy milk [ ] 3 Fix the login bug [x] 4 Write the report [ ] 5 Call the client
    IDs do not reset after removal. After removing task 2, the remaining tasks keep their original IDs (1, 3, 4, 5). The next task you add will be ID 6. This is intentional — IDs never reuse so you can always refer to a task by the same number you noted down.
  5. Test the error case — try to remove a task that does not exist:
    python tasks.py remove 99
    Expected output: Error: no task with ID 99
  6. Test persistence one more time. Close the terminal completely, open a new one, navigate back to task-manager, and run:
    python tasks.py list
    Your tasks should appear exactly as you left them. This confirms that tasks.json is correctly saving and loading data between sessions.
"Error: no task with ID N" when the task clearly exists: delete tasks.json and start fresh. A file created by an earlier version of the script may have stored IDs as strings ("1") instead of integers (1). The current script stores them as integers. Deleting the old file and re-adding tasks with the final version of the script resolves this permanently.
The list still shows a removed task: you may have two copies of tasks.py in different folders, and the terminal ran the old copy. Run pwd and confirm you are in the right folder. Then run python tasks.py list again.
JSONDecodeError on startup: tasks.json was partially written (e.g. the script crashed mid-save). Delete the file and re-add your tasks. The load_tasks function will print a warning and start with an empty list automatically.
Checkpoint — what you should see
Running all eight commands in sequence produces output that matches the expected block above: task 1 remains [x] from Phase 4 throughout; done 4 marks "Write the report" done; remove 2 removes "Read chapter 3" and the final list shows IDs 1, 3, 4, 5 with tasks 1 and 4 marked [x]. python tasks.py remove 99 prints an error, not a crash. Closing and reopening the terminal and running python tasks.py list shows your tasks intact. You have a working command-line task manager: add, list, done, and remove — built from scratch using Python's built-in argparse and json modules.
