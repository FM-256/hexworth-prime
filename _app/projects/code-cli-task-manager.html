Subject

Build a CLI Task Manager

Recruit 45 min 250 XP
Mission Brief

Your assignment is to design and build a command-line task manager entirely in Python. The application will allow operatives to create, view, update, and delete tasks directly from the terminal. Each task carries a title, priority level, optional due date, and one or more tags. All data persists between sessions in a local JSON file on disk — no database or external service required.

You will leverage Python's built-in argparse module to expose a clean subcommand interface — the same pattern used by tools like git and apt. This project drills the fundamental CRUD pattern that underpins virtually every real-world application. By the end of this operation, you will have a working tool you can deploy day-to-day.

The emphasis throughout is on clean structure over clever code. Keep your functions small, your data model explicit, and your error messages human-readable. A well-built CLI tool should feel intuitive on the first run without anyone needing to consult a manual.

Agent Requirements
  • Python 3.8 or later installed and runnable from your terminal
  • Comfort writing functions, loops, and conditionals in Python
  • Basic understanding of JSON structure (keys, values, arrays)
  • Familiarity with running scripts from the command line
  • Understanding of what command-line arguments and flags are
Operation Phases
1
Data Model and JSON Storage Layer
Define your task schema as a Python dictionary and write the two core storage functions: one that reads the JSON file from disk (or returns an empty list if it does not exist), and one that writes the full task list back. This layer is the foundation everything else sits on.
Checkpoint: Storage Layer
  • tasks.json is created automatically on first run if it does not exist
  • Each task has a unique ID, title, status, and created_at timestamp
  • File read/write operations handle missing or corrupted JSON gracefully
2
Add, List, and Delete Commands with argparse
Wire up your first three subcommands using argparse.add_subparsers(). task add "Buy milk" should append a new task, task list should print all tasks to the terminal, and task delete 3 should remove by ID. Confirm each action with a one-line success message.
Checkpoint: Core Commands
  • Adding a task prints the new task with its assigned ID
  • Listing tasks shows all tasks in a readable format
  • Deleting by ID removes the task and confirms the deletion
3
Priority Levels and Due Date Support
Extend the add command with optional --priority (low / medium / high, defaulting to medium) and --due (YYYY-MM-DD format) flags. Validate the date format on input and surface a clear error if it is malformed. Sort the list output by priority then due date.
Checkpoint: Priority & Dates
  • Tasks accept --priority with values like high, medium, low
  • Due dates are validated and stored in a consistent format
  • Listing tasks with --sort priority orders them correctly
4
Tags, Filtering, and Search
Add a --tags flag to add that accepts a comma-separated list of labels (e.g. work,urgent). Extend list with --tag and --search options that narrow output to matching tasks. Store tags as a JSON array per task.
Checkpoint: Tags & Search
  • Tasks can be tagged with one or more labels via --tags
  • Filtering by tag returns only matching tasks
  • Search by keyword matches against title and description fields
5
Status Transitions and Formatted Table Output
Add a task done ID subcommand that marks a task complete and records a timestamp. Refactor list to render output as a padded table with columns for ID, status, priority, due date, tags, and title. Completed tasks should appear dimmed using ANSI escape codes.
Checkpoint: Status & Output
  • Tasks can be moved between todo, in-progress, and done states
  • Formatted table output aligns columns properly in the terminal
  • A summary line shows total counts per status category
