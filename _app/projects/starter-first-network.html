Subject

My First Network

Beginner 30 min 250 XP
Mission Brief

Discover your own network — find your IP, trace a route across the internet, and understand how data travels from your machine to the world. Most people use networks every day without ever looking at them. This project changes that.

Using only the tools already on your operating system, you will identify every device on your local network, watch DNS resolution happen live, count the hops between your machine and Google's servers, and learn why your private IP address is different from the one the internet sees.

No software to install. No cloud accounts. Just your terminal, your network, and the commands that every network engineer, sysadmin, and security professional uses as reflexes. This is situational awareness — you cannot defend or build on a network you cannot see.

Agent Requirements
  • Any operating system: Windows, macOS, or Linux — all commands covered
  • A terminal, command prompt, or PowerShell window
  • An active internet connection (wired or Wi-Fi)
  • A text editor or paper to draw a network diagram in Phase 4
  • No prior networking knowledge required — concepts introduced with each command
Operation Phases
Progress
0 / 4
✓
1
Find Yourself
On Windows run ipconfig, on Linux/Mac run ip addr or ifconfig. Find your IPv4 address (typically 192.168.x.x or 10.x.x.x), your subnet mask (typically 255.255.255.0), and your default gateway (your router's IP). Run ping 8.8.8.8 to test basic internet connectivity. Observe the round-trip time in milliseconds. Run ping -c 4 8.8.8.8 (Linux/Mac) or ping -n 4 8.8.8.8 (Windows) to send exactly 4 packets.
Checkpoint
State your IP address, subnet mask, and default gateway. Explain in one sentence what each means: your IP identifies your device, the subnet mask defines which addresses are local, the gateway is the door to the internet. Ping to 8.8.8.8 shows replies with latency.
✓
2
Map Your Network
Run arp -a to see your ARP table — the list of IP addresses and their corresponding MAC addresses that your machine has seen on the local network. Count the devices. Each entry is a device that has communicated recently on your LAN. Then run nslookup google.com to see DNS resolution in action: your machine asks a DNS server for Google's IP address and receives an answer. Note the DNS server IP and the resolved address.
Checkpoint
List at least 3 devices visible in your ARP table with their IPs. Explain what DNS does in one sentence: it translates human-readable domain names into IP addresses. Note the DNS server IP from nslookup — is it your router's IP or a public resolver?
✓
3
Trace the Route
Run traceroute google.com on Linux/Mac or tracert google.com on Windows. Each line is a router ("hop") your packets pass through. The first hop is your router (gateway). The next few hops are your ISP's network. Later hops belong to Google's infrastructure. Lines showing * * * are routers configured not to respond to traceroute probes — this is normal and not an error. Count the total number of hops to reach Google.
Checkpoint
You can identify: (1) your router hop, (2) approximately where your ISP's network begins and ends, (3) where Google's network starts (look for hostnames containing "google" or "googlebot"). You can explain why * * * appears without calling it a problem.
✓
4
Test and Document
Run curl ifconfig.me (or visit ifconfig.me in a browser) to find your public IP address. Compare it to your private IP from Phase 1 — they are different because your router uses NAT (Network Address Translation) to map many private devices to one public IP. Draw a simple network diagram with labeled segments: Your PC, your home router, your ISP, the internet backbone, and a destination server like Google. Include IP ranges where you know them.
Checkpoint
Your diagram shows at least 4 labeled network segments. You can explain NAT in one sentence: your router translates your private IP to its public IP when sending traffic out, and reverse-translates incoming replies back to your device. The diagram becomes your reference for every networking concept from this point forward.
