Subject

My First Network

Recruit 30 min 250 XP
Mission Brief

Discover your own network — find your IP, trace a route across the internet, and understand how data travels from your machine to the world. Most people use networks every day without ever looking at them. This project changes that.

Using only the tools already on your operating system, you will identify your machine’s address on the local network, watch DNS resolution happen live, count the hops between your machine and Google’s servers, and learn why your private IP address is different from the one the internet sees.

No software to install. No cloud accounts. Just your terminal, your network, and the commands that every network engineer, sysadmin, and security professional uses as reflexes. This is situational awareness — you cannot defend or build on a network you cannot see.

Agent Requirements
  • Any operating system: Windows, macOS, or Linux — every command is covered for all three
  • A terminal window — Phase 1 shows you exactly how to open one on your OS
  • An active internet connection (wired or Wi-Fi)
  • Paper or a text editor to sketch a network diagram in Phase 4
  • No prior networking knowledge required — every concept is introduced when you need it

Find Yourself — Open a Terminal and Read Your IP
Before any command, you need a terminal window. A terminal is a text box where you type instructions directly to your operating system. Here is how to open one, then how to ask your machine: “what is my address on this network?”
  1. Open a terminal on your OS.
    Windows: Press the Windows key, type cmd, and press Enter. A black window with a blinking cursor appears — that is Command Prompt. Alternatively, type PowerShell and press Enter for a blue window; either works for every command in this project.

    Mac: Press Cmd + Space to open Spotlight, type Terminal, and press Enter. A white or black window with a $ prompt appears.

    Linux: Press Ctrl + Alt + T. A terminal window opens. If that shortcut does nothing, right-click the desktop and look for “Open Terminal” in the menu.
  2. Ask your machine for its network address (Windows). Click inside the terminal window and type this exactly, then press Enter:
    ipconfig
    What you will see: Several blocks of text. Look for the block labelled Ethernet adapter (wired) or Wireless LAN adapter Wi-Fi (wireless). Inside that block, find three lines — your output will have real numbers, not the examples shown here:
    example output (your numbers will differ)Wireless LAN adapter Wi-Fi: IPv4 Address. . . . . : 192.168.1.105 Subnet Mask . . . . . : 255.255.255.0 Default Gateway . . . : 192.168.1.1
    IPv4 Address = your machine’s address on the local network.
    Subnet Mask = which part of the address identifies your local network (255.255.255.0 means “/24” — the first three numbers are the network, the last number is your device).
    Default Gateway = your router’s address — every packet going to the internet passes through this address first.
  3. Ask your machine for its network address (Mac). On macOS, ipconfig does not exist in the Windows sense. Use Apple’s native tool instead. en0 is the Wi-Fi adapter on most Macs; Ethernet is typically en1 or another numbered interface — if the command below returns nothing, try en1, en2, etc.
    ipconfig getifaddr en0
    This prints a single line: your IPv4 address (e.g., 192.168.1.105). To see the subnet mask at the same time, run:
    ifconfig en0
    Look for the inet line in the output. It shows your IP address and the subnet mask in hexadecimal notation — for example, inet 192.168.1.105 netmask 0xffffff00. The hex mask 0xffffff00 equals 255.255.255.0, which is a /24 network. On macOS, ifconfig is the native tool and always installed; ignore any suggestion that it is “deprecated” on Mac — that deprecation note applies only to Linux.

    To find your default gateway on Mac, run either of these:
    netstat -nr | grep default
    or
    route -n get default | grep gateway
    The gateway IP (e.g., 192.168.1.1) appears in the output. Write it down — you need both your IP and your gateway IP for the Phase 4 diagram.
  4. Ask your machine for its network address (Linux). On Linux, use the modern ip command from the iproute2 package:
    ip addr
    Look for a block starting with eth0 (wired) or wlan0 (wireless). Your IP address appears after the word inet, typically in the form 192.168.x.x/24 or 10.x.x.x/24 — the number after the slash is the subnet prefix length. To find your default gateway, run:
    ip route
    Look for the line beginning with default via — the IP immediately after those words is your gateway.

    Note: On modern Linux distributions (Ubuntu 20.04+, Fedora 30+), the older ifconfig command may not be installed by default. Use ip addr and ip route instead — they are the current standard tools.
  5. Test that your internet connection is working with ping. Type this command and press Enter:
    ping 8.8.8.8
    What this does: ping sends a small “are you there?” message to Google’s public DNS server at address 8.8.8.8 and measures how long the reply takes. The time is called round-trip time (RTT) and is measured in milliseconds (ms).

    On Windows this sends 4 packets and stops automatically. On Mac/Linux it runs forever — press Ctrl + C to stop it.

    Example output (numbers vary):
    Windows examplePinging 8.8.8.8 with 32 bytes of data: Reply from 8.8.8.8: bytes=32 time=14ms TTL=118 Reply from 8.8.8.8: bytes=32 time=13ms TTL=118 Reply from 8.8.8.8: bytes=32 time=15ms TTL=118 Reply from 8.8.8.8: bytes=32 time=14ms TTL=118 Ping statistics for 8.8.8.8: Packets: Sent = 4, Received = 4, Lost = 0 (0% loss)
    Mac / Linux examplePING 8.8.8.8 (8.8.8.8): 56 data bytes 64 bytes from 8.8.8.8: icmp_seq=0 ttl=118 time=14.2 ms 64 bytes from 8.8.8.8: icmp_seq=1 ttl=118 time=13.8 ms ^C --- 8.8.8.8 ping statistics --- 2 packets transmitted, 2 packets received, 0.0% packet loss
  6. Send exactly 4 pings (optional, for practice). The flag to limit packets differs per OS:
    ping -n 4 8.8.8.8
    The -n 4 flag is for Windows and means “send 4 packets then stop.” On Mac and Linux, the flag is -c instead:
    ping -c 4 8.8.8.8
Ping says “Request timed out” or “100% packet loss”?
  • First verify your internet works: open a browser and load any website. If the browser works but ping fails, your firewall or router is blocking ICMP (the protocol ping uses) — this is common on corporate or school networks. Try ping google.com (domain name instead of IP) to rule out a DNS issue. If that also fails but the browser loads pages, ICMP is blocked and you should move on to the next phase; everything still works.
  • If the browser also fails to load pages, your internet connection itself is down. Check your Wi-Fi or cable connection and try again.
Checkpoint — what you should have
Write down your three values: your IPv4 address (e.g., 192.168.1.105), your subnet mask (e.g., 255.255.255.0), and your default gateway (e.g., 192.168.1.1). Ping replies show a time value in milliseconds — under 50ms is excellent for a home network; 100–200ms is typical for connections crossing continents. You will use these values in Phase 4 to build your network diagram.

Map Your Network — Who Else Is Here? What Is DNS?
Your machine keeps a local record of every device it has recently talked to on the LAN — a table of IP addresses and their hardware identifiers. You can read it with one command. Then you will watch the Domain Name System turn a website name into a number, live.
  1. Read the ARP table to see nearby devices. Type this and press Enter (works on Windows, Mac, and Linux — same command):
    arp -a
    What you will see: A list of IP addresses and the corresponding MAC addresses (physical hardware identifiers, formatted as six pairs of hex digits like a4-c3-f0-11-22-33). Each line is one device your machine has communicated with on the LAN. The first entry is almost always your router (your default gateway IP).
    example output (your addresses will differ)Interface: 192.168.1.105 --- 0x5 Internet Address Physical Address Type 192.168.1.1 a4-c3-f0-11-22-33 dynamic 192.168.1.112 b8-27-eb-44-55-66 dynamic 192.168.1.128 dc-a6-32-77-88-99 dynamic 192.168.1.255 ff-ff-ff-ff-ff-ff static
    dynamic means the entry was learned automatically. static entries are special broadcast or multicast addresses — not real devices. Ignore the ff-ff-ff-ff-ff-ff line; it is a broadcast address, not an individual machine.
    Why are not all my devices listed? ARP only records devices your machine has recently exchanged data with. A phone that is sleeping and not sending traffic may not appear. This list is not a full scan — it is a record of recent conversations. That is expected behaviour.
  2. Watch DNS resolution happen. Type this and press Enter (works on Windows, Mac, and Linux):
    nslookup google.com
    What you will see:
    example outputServer: 192.168.1.1 Address: 192.168.1.1#53 Non-authoritative answer: Name: google.com Address: 142.250.80.46
    Server: the DNS server your machine asked (often your router, which relays the question upstream). The #53 means port 53 — the standard port for DNS.
    Name: what you asked for.
    Address: the IP address that google.com resolves to right now. Google uses many IPs — yours may be different and that is correct. “Non-authoritative answer” means this came from a cache, not directly from Google’s own name servers; this is normal.
  3. Look up a second domain to see DNS respond differently.
    nslookup cloudflare.com
    Notice that the DNS server line stays the same (same resolver) but the returned IP address is different. This shows that DNS is a lookup service — you give it a name, it gives you a number, and each name maps to its own set of numbers.
nslookup shows “can’t find server” or “NXDOMAIN”?
  • Can’t find server name for address: This warning at the start of nslookup output means your DNS server does not have a reverse-lookup entry for itself. It does not affect forward lookups (name to IP). Ignore it and read the Name / Address lines below it.
  • NXDOMAIN means “non-existent domain” — you typed the domain name incorrectly. Check spelling and try again.
  • If you get no response at all and ping also failed in Phase 1, your internet connection is down.
Checkpoint — what you should have
Count the entries in your ARP table and write down at least two device IPs (your router + one other). Note what DNS server IP nslookup reports — if it matches your Default Gateway from Phase 1, your router is acting as the DNS resolver (forwarding questions to your ISP or to a public resolver like Google’s 8.8.8.8). If it shows 8.8.8.8 or 1.1.1.1 directly, your machine is configured to use a public resolver. Either is normal.

Trace the Route — Follow a Packet to Google
Every piece of data you send to the internet passes through a series of routers before it arrives. Traceroute reveals each one of those “hops,” shows you the IP address of each router, and measures how long each leg of the journey takes.
  1. Run traceroute. The command name differs by OS.
    Windows (Command Prompt or PowerShell):
    tracert google.com
    Mac and Linux (Terminal):
    traceroute google.com
    The command takes 30–60 seconds to complete. You will see lines appearing one by one as each router responds.
  2. Read the output.
    example output (Windows — your IPs and times will differ)Tracing route to google.com [142.250.80.46] over a maximum of 30 hops: 1 2 ms 1 ms 2 ms 192.168.1.1 2 12 ms 11 ms 12 ms 10.20.1.1 3 14 ms 13 ms 13 ms 72.14.232.1 4 15 ms 15 ms 14 ms 142.251.48.13 5 14 ms 14 ms 15 ms lax17s55-in-f14.1e100.net [142.250.80.46] Trace complete.
    Hop 1: Always your router (matches your Default Gateway from Phase 1). RTT under 5ms is normal — it is on your LAN.
    Hops 2–3: Your ISP’s routers. Latency rises as packets move farther away.
    Later hops: Hostnames containing google or 1e100.net (Google’s internal domain) mark where you entered Google’s network. 1e100 is scientific notation for the number “googol” — that is where the company name comes from.
    Three time values per hop: Traceroute sends three probes to each router. The three numbers are the RTT for each probe. Small variation (1–5ms) is normal.
  3. Understand asterisks. Some lines look like this:
    6 * * * Request timed out.
    This is not an error. It means that router is configured to ignore traceroute probes — many ISP and backbone routers do this for security and performance reasons. Your packet still passed through the router; it just did not reply to the probe. If you see a few * * * lines in the middle but the route continues afterward, everything is working correctly. The trace only truly “failed” if every remaining line after a certain point is * * *.
  4. Count your hops. How many numbered lines appeared before the trace completed? A home connection to Google typically reaches its destination in 8–15 hops. More hops do not necessarily mean slower — latency (the time values) matters more than hop count.
tracert / traceroute hangs for minutes or every line shows * * *?
  • On some networks (corporate, school, or mobile hotspot) ICMP traffic is blocked entirely. Try adding the -T flag on Linux (sudo traceroute -T google.com) to use TCP instead of ICMP — TCP is harder to block. What is sudo? It runs the command with administrator rights. Your terminal will prompt you for your account password; the cursor will not move and no dots or stars will appear as you type — that is normal, it is intentional. If you do not have admin rights on this machine, or if ICMP remains blocked after trying the TCP flag, skip ahead to Phase 4 — the remaining steps work without traceroute. On Windows, tracert has no TCP mode; the result will simply show all asterisks if ICMP is blocked, which is expected on locked-down networks.
  • If the trace stalls at hop 1 (your own router does not respond), check that you typed the command correctly and that you have an active internet connection.
Checkpoint — what you should be able to explain
You can identify: (1) hop 1 as your router — does its IP match the Default Gateway you found in Phase 1? (2) approximately where your ISP’s network ends and a backbone or Google’s network begins — watch for the RTT to jump from under 20ms to 30ms or more; (3) the hostname in the last successful hop — does it contain google or 1e100? Write down the total hop count. You can explain to someone else why * * * appears without calling it a problem.

4
Test and Document — Public IP, NAT, and Your Network Map
You have a private IP that identifies your machine inside your home network. The internet sees a different, public IP — your router’s address. This phase reveals both and explains why they are different. You then draw a network diagram that ties everything together.
  1. Find your public IP address. Run this in your terminal:
    curl ifconfig.me
    What you will see: A single IP address printed on one line — for example, 203.0.113.72. This is how the rest of the internet sees your connection. It belongs to your ISP and is assigned to your router, not to your machine directly.

    If curl is not installed (rare on modern systems): Open a browser and go to ifconfig.me — the page shows your public IP. On Windows PowerShell you can also run:
    Invoke-WebRequest -Uri "https://ifconfig.me/ip" -UseBasicParsing | Select-Object -ExpandProperty Content
  2. Compare your public IP to your private IP from Phase 1.
    They are different. Your private IP (e.g., 192.168.1.105) is a RFC 1918 private address — a range reserved for local networks that is never routed on the public internet. Millions of home networks use the same 192.168.x.x space, which is why those addresses are private: they only mean something inside your house.

    Your router bridges the two worlds using a process called NAT (Network Address Translation): when your machine sends a packet out, the router replaces your private source IP with its own public IP and keeps a translation table so it knows to route incoming replies back to the correct device inside your LAN.
  3. Draw your network diagram. Use paper or any text editor. Draw these five components in a left-to-right line and label each one with the information you collected:
    your diagram layout — fill in YOUR values from Phases 1–4[Your PC] [Home Router] [ISP Network] [Internet Backbone] [google.com] [your PC IP] [your gateway IP] (tracert hop 2-3) (tracert later hops) 142.250.80.46 private LAN NAT boundary [your public IP] multiple routers destination private IP on LAN side assigned by your ISP owned by ISP/carriers
    Write in the actual IP addresses you found. For the ISP and backbone hops, use the IPs from your traceroute output. You do not need to know who owns every hop — just label what you know. The diagram should make it obvious visually where private addresses end and public addresses begin (at the router).
  4. Add subnet information. Under your PC box, note the subnet. A subnet mask of 255.255.255.0 means your local network can hold up to 254 devices all sharing the same first three octets. Under your router box, write your public IP and note that it is your ISP’s address assigned to you.
curl gives an error like “curl: command not found”?
  • Windows (older than Windows 10 build 1803): curl is not built in. Open a browser and go to ifconfig.me instead. On modern Windows 10 and Windows 11, curl is included and should work in both Command Prompt and PowerShell.
  • Mac: curl is always present. If you get an SSL error, use the browser fallback instead: open ifconfig.me or whatismyip.com in any browser — the page will display your public IP without requiring curl.
  • Linux: Install curl with sudo apt install curl (Ubuntu/Debian) or sudo dnf install curl (Fedora/RHEL). Or use the browser alternative above.
Your public IP matches your private IP (e.g., both are 192.168.x.x)?
  • This is unusual but can happen if you are on a VPN or a corporate network where NAT is applied at a higher level. If you are on a VPN, your public IP will reflect the VPN server’s IP rather than your ISP’s — that is by design. Disconnect from the VPN temporarily to see your actual ISP-assigned public IP, then reconnect.
Checkpoint — what your diagram must show
Your finished diagram has at least four labelled segments: your PC with its private IP, your router with both its private LAN IP and its public IP, at least one ISP hop from your traceroute, and Google’s server. The NAT boundary — where private addresses stop and the public internet begins — is clearly marked at the router. You can explain NAT in one sentence: your router swaps your private source IP for its public IP on every outgoing packet, and reverses the swap on incoming replies so the right device receives the response. This diagram is your reference for every networking concept from this point forward.
