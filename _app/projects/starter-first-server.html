Subject

My First Server

Recruit Recruit Level 250 XP
Mission Brief

Spin up your first virtual machine, connect via SSH, and serve your first web page to the world. This is the foundational skill of every cloud engineer, sysadmin, and DevOps practitioner — the ability to provision a machine, access it remotely, and put software on it.

You will create a VM in VirtualBox with Ubuntu Server 22.04, find its IP address, install OpenSSH so you can connect remotely, install the Nginx web server, and finally replace the default page with your own HTML. Every cloud server you ever spin up — AWS, GCP, Azure — works the same way under the hood.

When this project is complete, you will understand exactly what happens when you type an IP address into a browser — and you will have controlled every step of that chain yourself.

Agent Requirements
  • VirtualBox 7.x installed on your host machine — free download at virtualbox.org. Install it before you start; the installer requires a restart on Windows.
  • Ubuntu Server 22.04 LTS ISO downloaded to your computer — free at ubuntu.com/download/server. The file is about 2 GB; download it before you begin so you are not waiting mid-lab.
  • At least 8 GB of RAM on your host machine (you will give 2 GB to the VM and keep the rest for your host OS and browser).
  • A terminal on your host machine. Windows: Git Bash (free, from gitforwindows.org) is recommended — it gives you a Unix-style shell where all commands in this project work exactly as written. PowerShell also works for SSH on Windows 10 (build 1809+) and Windows 11, which include the OpenSSH client by default. Mac: press Cmd+Space, type Terminal, and open it. Linux: press Ctrl+Alt+T.
  • No prior server experience required — every command is shown exactly as you type it.

Create the Virtual Machine
A virtual machine (VM) is a computer running inside your computer — it gets its own IP address, its own OS, and its own disk, but it is just a window on your screen. VirtualBox is the free software that creates and runs VMs. You will build one now and install Ubuntu Server on it.
  1. Open VirtualBox. You should see a mostly empty window with a blue "New" button in the toolbar. Click New. This opens the Create Virtual Machine wizard.
  2. Name the machine, pick the OS, and skip unattended install. The first wizard page has several fields:
    • Name: type ubuntu-server
    • Folder: leave as the default location
    • ISO Image: leave this empty for now (you will attach the ISO after the wizard, which avoids the unattended installer)
    • Type: Linux
    • Version: Ubuntu (64-bit)
    Why leave the ISO field empty here? If you select an ISO on this page and VirtualBox detects it as Ubuntu, it automatically enables Unattended Installation — which creates its own username and password behind the scenes, so the credentials you set in the Ubuntu installer may be ignored. Leaving the ISO field empty skips that path entirely. You will attach the ISO manually in step 5 and then run the standard Ubuntu installer yourself. (Alternatively, if you do select the ISO, tick the Skip Unattended Installation checkbox that appears on this same page — that also bypasses it.)
    Don't see a "64-bit" option? Your CPU's virtualization feature is turned off. Restart your computer, enter the BIOS/UEFI settings (usually by pressing F2, F10, or Delete during boot — the key shows briefly on screen), find a setting called Intel VT-x or AMD-V or SVM Mode, enable it, save, and reboot. Then try again in VirtualBox.
    Click Next.
  3. Allocate RAM. On the Hardware page, set Base Memory to 2048 MB (that is 2 GB). Leave the processor count at 1 and leave EFI unchecked. Click Next.
  4. Create a virtual hard disk. Leave Create a Virtual Hard Disk Now selected. Set the size to 25 GB and leave allocation as Dynamically Allocated (so it only uses real disk space as Ubuntu fills it). Click Next, then Finish on the summary screen. The VM now appears in the VirtualBox list on the left.
  5. Attach the Ubuntu ISO. Select your new VM in the list, then click Settings → Storage. Under Controller: IDE, click the CD icon that says Empty. On the right side, click the small CD icon next to Optical Drive and choose Choose a Disk File…. Navigate to your downloaded .iso file and select it. Click OK.
  6. Set the network to Bridged Adapter. Still in Settings, click Network. Change Attached to: from NAT to Bridged Adapter. The Name field below it should auto-fill with your active network card — leave it as-is. Click OK.
    What is a Bridged Adapter? The default setting (NAT) hides the VM behind your host's IP. Bridged makes the VM appear on the same network as your computer, so it gets its own address like 192.168.1.42 that you can open in your browser. Without this, Phase 3 will not work.
    Bridged Adapter won't work on school, work, or public WiFi. Many campus and corporate networks use client isolation, which blocks traffic between devices on the same WiFi. If SSH won't connect even with the right IP, this is likely why. Fallback that works anywhere: shut the VM down, go to Settings → Network, switch Attached to: back to NAT, then click Advanced → Port Forwarding and add a rule: Name SSH, Host Port 2222, Guest Port 22, leave both IP fields blank. Start the VM, then connect with ssh -p 2222 username@127.0.0.1 instead of the VM's IP. For Phase 3, add a second rule: Name HTTP, Host Port 8080, Guest Port 80, and browse to http://127.0.0.1:8080 on your host.
  7. Start the VM. Double-click the machine in the list (or click Start in the toolbar). A new window opens with a black screen, then the Ubuntu installer begins loading.
  8. Install Ubuntu Server. The installer is text-only and uses arrow keys, Enter, and Space to navigate. Follow these steps in order:
    • Language: English → Enter
    • If it offers an installer update, choose Continue without updating
    • Keyboard layout: accept the default (English US) → Done → Enter
    • Installation type: Ubuntu Server (first option) → Done
    • Network: wait for it to detect an IP — if it shows a number like 192.168.1.XX under the network card, bridged is working. Done.
    • Proxy: leave blank → Done
    • Mirror: leave default → Done
    • Storage: Use an entire disk → Done → Continue on the confirmation screen
    • Profile: fill in your name, a server name (e.g. myserver), a username (e.g. admin), and a password. Write these down. Done.
    • SSH: press Space to tick Install OpenSSH server. Done. (This saves you a step later.)
    • Featured snaps: press Done without selecting any
    • The installer now copies files. Wait until you see Install complete! → select Reboot Now → Enter
    The reboot may pause with a message about removing the installation media. Press Enter to continue. VirtualBox usually ejects the ISO automatically; if the VM boots back into the installer again, go to Settings → Storage and click the CD icon → Remove Disk from Virtual Drive, then restart the VM.
What the Ubuntu installer flow looks likeLanguage → Keyboard → Ubuntu Server → Network (gets IP) → Proxy → Mirror → Storage → Profile (your username+password) → SSH (tick it) → Snaps (skip) → Install → Reboot
Checkpoint — what you should see
After reboot, the VM window shows a text login prompt: myserver login:. Type your username and press Enter, then your password (the cursor does not move while typing — that is normal), then Enter. You should land at a prompt ending in $, for example admin@myserver:~$. If you reach this prompt, the OS is running correctly.

Connect via SSH
SSH (Secure Shell) lets you control the server from your own terminal window instead of typing in the tiny VirtualBox screen. After this phase you can close the VirtualBox console window and work entirely from your host machine's terminal — exactly how professionals manage cloud servers.
  1. Log in to the VM console (the VirtualBox window). Type your username, press Enter, type your password, press Enter. You are at the $ prompt.
  2. Find the VM's IP address. Run:
    ip addr show
    Look for a line starting with inet under the enp0s3 or eth0 section. The address looks like 192.168.1.42/24 — everything before the slash is the IP you need. Write it down.
    Only see a loopback address (127.0.0.1)? That means bridged networking is not set correctly. Shut down the VM (sudo shutdown -h now), go to VirtualBox Settings → Network, confirm Bridged Adapter is selected and your correct network card is in the Name field, then start the VM again.
    Shorthand: ip a is an exact shortcut for ip addr show — both work.
  3. Verify OpenSSH is running. If you ticked it during the Ubuntu installer, it should already be active. Confirm:
    sudo systemctl status ssh
    You will be asked for your password (you are using sudo, which runs the command as administrator). The output should include Active: active (running). If the unit says inactive or failed, start and enable it:
    sudo systemctl start ssh sudo systemctl enable ssh
    If the status command says the unit could not be found, the package was not installed during setup. Install it first, then start and enable it:
    sudo apt update sudo apt install openssh-server -y sudo systemctl start ssh sudo systemctl enable ssh
  4. Open a terminal on your HOST machine (not inside VirtualBox):
    • Windows: open Git Bash from your Start menu
    • Mac: Cmd+Space → type Terminal → Enter
    • Linux: Ctrl+Alt+T
  5. Connect to the VM over SSH. In your host terminal, type (replace both parts with your real username and the IP you wrote down):
    ssh admin@192.168.1.42
    The first time you connect, SSH asks you to confirm the server's fingerprint:
    The authenticity of host '192.168.1.42' can't be established. ECDSA key fingerprint is SHA256:xxxx... Are you sure you want to continue connecting (yes/no/[fingerprint])?
    Type yes and press Enter. Then enter your password.
    What that fingerprint message means: SSH is saying "I have never talked to this server before — is it really yours?" Typing yes saves the key so you will not be asked again. This is safe for a VM you just built.
ssh: connect to host 192.168.1.42 port 22: Connection refused
  • The SSH service is not running — go back to the VirtualBox console and run sudo systemctl start ssh.
  • The IP you copied is wrong — run ip addr show in the VM console again and double-check the number.
  • The VM is on NAT, not Bridged — shut the VM down, fix the Network setting, restart. Exception: if you deliberately chose the NAT + Port Forwarding fallback in Phase 1, ignore this bullet — connect with ssh -p 2222 username@127.0.0.1 instead of the VM's IP.
ssh: command not found (Windows) — Windows 10 (build 1809 and later) and Windows 11 include the OpenSSH client built in, so ssh works directly in PowerShell or cmd without Git Bash. If you are on an older Windows version or the OpenSSH optional feature was never installed, open Settings → Optional Features, search for OpenSSH Client, and install it. Git Bash also works and is recommended if you want a Unix-style shell for the rest of this project.
Permission denied (publickey,password) — you typed the wrong password. Note: the cursor does not move while you type your password in a terminal — that is intentional. Type carefully and press Enter.
Checkpoint — what you should see
Your host terminal now shows a prompt like admin@myserver:~$. You are inside the VM from your own terminal — you no longer need to type anything in the VirtualBox window. You can minimize or ignore that window for the rest of this project. Every command from here on runs in your host terminal SSH session.

Install the Nginx Web Server
Nginx (pronounced "engine-x") is a web server — software that listens for incoming browser requests and responds with web pages. You will install it from Ubuntu's package system in four commands, then verify it is serving pages by opening a browser on your host machine and navigating to the VM's IP address.
  1. Update the package list. This tells Ubuntu what software is currently available for download. Always run this before installing anything:
    sudo apt update
    You will see a stream of lines ending in "Reading package lists... Done". That is correct.
    What is apt? It is Ubuntu's built-in package manager — the equivalent of an app store you use entirely from the command line. sudo in front of a command means "run this as administrator" (like right-clicking "Run as administrator" on Windows). Ubuntu will ask for your password the first time you use sudo in a session.
  2. Install Nginx:
    sudo apt install nginx -y
    The -y flag automatically answers "yes" to any confirmation prompts. Installation takes 10–30 seconds depending on your internet speed.
  3. Start Nginx and enable it to survive reboots:
    sudo systemctl start nginx sudo systemctl enable nginx
    start runs it now; enable tells Ubuntu to start it automatically every time the VM boots.
  4. Confirm Nginx is running:
    sudo systemctl status nginx
    Expected output (look for the highlighted line):
    expected terminal output* nginx.service - A high performance web server and a reverse proxy server Loaded: loaded (/lib/systemd/system/nginx.service; enabled) Active: active (running) since Wed 2026-06-18 10:23:41 UTC; 5s ago Main PID: 1234 (nginx) Tasks: 3 (limit: 2234) Memory: 3.2M CPU: 12ms CGroup: /system.slice/nginx.service |-1234 nginx: master process /usr/sbin/nginx -g daemon on; |-1235 nginx: worker process +-1236 nginx: worker process
    Press q to exit the status view.
  5. Allow port 80 through Ubuntu's firewall (UFW). Ubuntu Server sometimes has its firewall active by default:
    sudo ufw allow 'Nginx HTTP' sudo ufw status
    If UFW says Status: inactive, the firewall is off and port 80 is already open — that is fine, move on. If it says active, confirm you see Nginx HTTP ALLOW Anywhere in the output.
  6. Open your host browser and navigate to the VM's IP. The address bar format is exactly:
    http://192.168.1.42
    Replace 192.168.1.42 with the IP you wrote down. Do not add https:// — at this stage Nginx only speaks plain HTTP.
    Why HTTP and not HTTPS? HTTPS requires a certificate. A brand-new Nginx installation has none, so the browser would refuse to connect on port 443. HTTP on port 80 works immediately. Adding HTTPS is a more advanced step covered in later modules.
The browser shows "This site can't be reached" or times out
  • Confirm Nginx is running: sudo systemctl status nginx must say active (running).
  • Confirm you are typing the VM's IP, not your host machine's IP — run ip addr show in the SSH session to recheck.
  • Confirm port 80 is open: sudo ufw allow 80/tcp then try again.
  • Confirm the VM is on Bridged Adapter, not NAT — if it is on NAT, the VM's IP is unreachable from your browser. Shut down, fix the setting, restart, and get the new IP with ip addr show.
Checkpoint — what you should see
Your host machine's browser shows the Nginx default welcome page: a white page with a large green heading that reads Welcome to nginx! and text below it explaining it is the default page. That page is being served from the VM over your local network. If you see this, Nginx is working correctly.

Serve Your Own Page
The Nginx default page is a file on disk at /var/www/html/index.nginx-debian.html. When a browser requests http://your-vm-ip/, Nginx looks in /var/www/html/ and serves the first index file it finds. You will create your own index.html there — Nginx picks it up automatically, no restart needed. This is the exact model used by every web hosting provider in the world.
  1. Navigate to the web root. In your SSH session:
    cd /var/www/html
    Then list the files in that directory:
    ls -la
    You should see the default Nginx files. cd means "change directory" — it is how you move between folders on the command line. ls -la lists all files including hidden ones.
  2. Create your own index.html. You will write it using nano, a simple text editor built into Ubuntu. It works like a plain-text editor — you just type:
    sudo nano /var/www/html/index.html
    Nano opens a blank editing screen. The toolbar at the bottom shows keyboard shortcuts (the ^ symbol means Ctrl).
    Why sudo? The /var/www/html/ directory is owned by the system; you need administrator permission to create files there. sudo grants that permission for the duration of this single command.
  3. Type (or paste) your HTML page. Here is a complete working page — replace "Your Name" with your name:
    <!DOCTYPE html> <html lang="en"> <head> <meta charset="UTF-8"> <title>My First Server</title> <style> body { font-family: Arial, sans-serif; max-width: 600px; margin: 60px auto; padding: 0 20px; background: #f4f4f4; } h1 { color: #0369a1; } p { color: #334155; line-height: 1.7; } </style> </head> <body> <h1>Hello from my server!</h1> <p>This page is served by Nginx running on an Ubuntu VM.</p> <p>Built by: Your Name</p> </body> </html>
    Pasting into nano over SSH: If you are on Windows in Git Bash, right-click in the terminal window to paste (Ctrl+V may not work in the terminal itself). On Mac, use Cmd+V. On Linux, use Ctrl+Shift+V.
  4. Save the file and exit nano. The two shortcuts you need, in order:
    • Press Ctrl+O (that is the letter O, not zero) — nano shows File Name to Write: at the bottom. Press Enter to confirm the filename.
    • Press Ctrl+X to exit nano and return to the command prompt.
  5. Verify the file is there:
    cat /var/www/html/index.html
    This prints the file contents to the terminal. You should see the HTML you just typed.
  6. Open your browser and refresh the tab showing http://your-vm-ip. Press F5 (Mac: Cmd+R) to force a reload. You should now see your own page instead of the Nginx default.
    Why no Nginx reload? Nginx serves static files straight from disk on every request — your edited index.html is picked up immediately, no restart or reload needed. sudo systemctl reload nginx is only required when you change Nginx configuration files (files inside /etc/nginx/). For a content change like this, a browser refresh is all you need.
    Browser is still showing the old Nginx default page? Try a hard refresh: Ctrl+Shift+R (Mac: Cmd+Shift+R). This forces the browser to re-download the page instead of using a cached copy.
Your completed file structure on the VM/var/www/html/ ├── index.html ← your page (Nginx serves this) └── index.nginx-debian.html ← the original default (leave it; Nginx ignores it now that index.html exists)
Browser still shows the Nginx default page after saving
  • Confirm the file saved: cat /var/www/html/index.html should print your HTML. If it prints the old Nginx page content, nano did not save — open nano again and repeat Ctrl+O → Enter → Ctrl+X.
  • Do a hard refresh in the browser: Ctrl+Shift+R (Mac: Cmd+Shift+R).
  • If nothing changes, reload Nginx: sudo systemctl reload nginx. Then check for errors: sudo nginx -t — it should say syntax is ok and test is successful. If it reports an error, your HTML likely has a syntax problem; check that all tags are closed.
sudo nano opens but the file is empty when saved — you may have typed sudo nano index.html without the full path. The file landed in your home directory, not /var/www/html/. Confirm where you are with pwd (print working directory). If you see /home/admin instead of /var/www/html, run sudo nano /var/www/html/index.html with the full path this time.
How to stop and restart the SSH session — to disconnect from the VM, type exit and press Enter. Your local terminal returns. To reconnect, run the same ssh admin@192.168.1.42 command again. The VM keeps running in VirtualBox — you do not need to stop it.
How to shut down the VM properly. Do not close the VirtualBox window with the X — that hard-kills the machine and can corrupt the virtual disk. Instead, from your SSH session (or the VirtualBox console), run:
sudo shutdown now
The VM will power off cleanly within a few seconds and VirtualBox will show it as Powered Off. You can also use VirtualBox Machine menu → ACPI Shutdown from the VM window toolbar, which sends the same signal. To start it again, double-click the machine in the VirtualBox list.
Checkpoint — what you should see
Your host machine's browser at http://your-vm-ip now shows your custom page — a blue heading that reads Hello from my server! and your name below it. The Nginx default page is gone. This is a real HTTP server, running on a real OS, serving real HTML over a real network. That is the same model behind every web host, VPS, and cloud VM in the industry. You built one from scratch.
