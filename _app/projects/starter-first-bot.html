My First Bot

Recruit 45 min 250 XP
Mission Brief

Build your first Discord bot that responds to commands, tells jokes, and runs 24/7 in your server. Bots are the entry point to event-driven programming — code that waits for something to happen and reacts. Every Slack integration, every webhook, every automation pipeline runs on this same pattern.

You will register a bot with the Discord Developer Portal, install discord.py, bring the bot online, and build five interactive commands. No web servers, no databases — just Python listening for messages and responding with wit and randomness.

By the end you will understand API tokens, the event loop, async/await programming, and how to handle unknown commands gracefully. The Discord bot is also a gateway project — the same architecture powers Slack bots, Telegram bots, GitHub webhooks, and every automated system that listens and responds to the world.

Note on style: This project uses discord.Client with an on_message event handler — the manual, explicit approach that makes every moving part visible. Most tutorials you find online use discord.ext.commands and the @bot.command() decorator shorthand instead. Both work; the manual approach here is intentionally more verbose so you can see exactly what Discord is doing before the framework hides it.

Agent Requirements
  • A free Discord account — sign up at discord.com if you don't have one
  • A Discord server you own or can administer — Phase 1 shows you how to create one in 60 seconds; use a personal test server, not a shared class server
  • Python 3.8 or newer — download free at python.org/downloads; discord.py 2.x requires at minimum Python 3.8
  • A free text editor — VS Code (code.visualstudio.com) works well; any plain-text editor that saves .py files will work
  • A terminal (Command Prompt or PowerShell on Windows, Terminal on Mac) — you'll type one install command and then run your bot
  • Basic Python familiarity — you should know what a function, a list, and an if/elif block look like; no async knowledge required, the code is explained line by line

Create the Bot Account and Invite It to Your Server
Before any code, you need three things: a bot registered in the Discord Developer Portal, a token copied and stored safely, and the bot invited into a server you control. Do not skip steps — the order matters.
  1. Make a test server if you don't have one. Open Discord. Click the + button in the left sidebar (Add a Server) → Create My Own → For me and my friends. Give it any name, like My Bot Lab. This is your personal test space — never test on a shared class or club server.
  2. Open the Discord Developer Portal. In your browser go to discord.com/developers/applications. Sign in with your Discord account if prompted. You'll see the Applications page.
  3. Create a new application. Click New Application (top-right). Type a name — something like MyFirstBot — accept the Terms of Service, and click Create. You land on the General Information page for your new app.
  4. Add a Bot user. In the left sidebar click Bot. You see your bot's username (same as your app name). This page controls the bot user — the account that shows up in Discord.
  5. Copy the token — this is the bot's password. Under Token click Reset Token, confirm the prompt, and your token appears. Click Copy immediately and paste it somewhere safe on your computer (a plain text file called token.txt on your Desktop is fine for now). You will not be able to see it again without resetting it a second time, so do not close this page until you have it pasted.
    Token security — read this once, follow it always: The token is the master key to your bot. Anyone who has it can control your bot completely. Never paste it directly inside your bot.py file if you plan to push that file to GitHub — even a private repo. Never post it in Discord, a screenshot, or a chat message. If you accidentally share it or commit it to version control, click Reset Token in the Developer Portal immediately — the old token becomes permanently invalid within seconds of reset.
  6. Enable the MESSAGE CONTENT Intent. Still on the Bot page, scroll down to the section labeled Privileged Gateway Intents. Find the toggle labeled Message Content Intent and switch it on (it turns blue/green). Click Save Changes. Without this toggle, your bot will see that messages exist but their text will be blank — none of your commands will ever match.
    Why is it "privileged"? Discord treats message content as sensitive data because it includes everything users type. Bots in large servers (100+ guilds) need Discord's approval to use it. For your personal test server, simply enabling the toggle is all you need.
  7. Generate the invite link. In the left sidebar click OAuth2, then click URL Generator in the sub-menu. Under Scopes tick bot. A Bot Permissions section appears below. Tick Send Messages and Read Message History. Scroll down, copy the generated URL from the Generated URL box at the bottom.
  8. Invite the bot to your test server. Paste the URL you just copied into your browser's address bar and press Enter. Discord shows an authorization page. Choose your test server from the drop-down, click Authorize, complete any CAPTCHA, and you're done. The bot now appears in your server's member list — offline for now (gray dot).
    What your portal left sidebar should show (in order)General Information Bot ← token + intents live here OAuth2 > URL Generator ← invite link lives here Installation
Checkpoint — what you should have
Your bot appears in your test server's member list with a gray (offline) status dot. You have the token saved in a plain text file on your computer. The Message Content Intent toggle is on (blue) and you have clicked Save Changes. You have not put the token inside any code file yet.

Install discord.py and Bring the Bot Online
Now install the library, write the minimum code that connects to Discord, and confirm the bot shows as online in your server. Do not add commands yet — get the connection solid first.
  1. Open a terminal. Windows: press Windows key, type cmd, press Enter (or search for PowerShell). Mac: press Cmd+Space, type Terminal, press Enter. A black or white window with a cursor appears — this is where you type commands.
  2. Install discord.py. Type this command and press Enter. Wait for it to finish — you'll see lines scrolling and then a "Successfully installed" message:
    python3 -m pip install -U discord.py
    Windows alternative if python3 is not recognized: try py -3 -m pip install -U discord.py. If neither works, try python -m pip install -U discord.py. One of the three will work depending on how Python was installed. The -U flag means "upgrade to latest" — you want discord.py 2.x, not an old 1.x version.
    Use the same Python prefix for both install and run. Whichever command makes python3 --version (or py --version / python --version) print a version number is your Python. Use that exact same prefix when you run bot.py later. Mixing prefixes — installing with py -3 but running with python3 — puts discord.py on a different interpreter than the one running your script, which causes a ModuleNotFoundError.
    pip: command not found / pip is not recognized: Python was installed without adding it to your PATH. The fix on Windows: uninstall Python, re-download it from python.org/downloads, and on the first installer screen tick Add Python to PATH before clicking Install. On Mac: if Python came with Xcode tools, use pip3 instead of pip, or install Python from python.org directly.
  3. Create a project folder. Make a new folder on your Desktop named my-first-bot (no spaces). Open VS Code, click File → Open Folder, navigate to Desktop, select my-first-bot.
  4. Create bot.py. In VS Code's left panel hover over the folder name and click the New File icon (page with a +). Type bot.py and press Enter.
  5. Paste this starter code exactly. Click inside the empty file and paste it. Every line is explained in the note below:
    import discord intents = discord.Intents.default() intents.message_content = True client = discord.Client(intents=intents) @client.event async def on_ready(): print(f'Logged in as {client.user}') client.run('PASTE_YOUR_TOKEN_HERE')
    What each line does: import discord loads the library. intents tells Discord which events to send your bot — message_content = True is the intent you enabled in the portal (without it, message text arrives empty). discord.Client is the bot object. @client.event is a decorator that says "run this function when the named event fires." async def on_ready fires once when the bot successfully connects — it just prints a confirmation. client.run() starts the WebSocket connection and keeps the program running.
  6. Replace the placeholder with your real token. Open the token.txt file you saved in Phase 1. Copy the token string. In bot.py, replace PASTE_YOUR_TOKEN_HERE with your actual token — keep the single quotes around it. Example (not a real token):
    client.run('MTM4NDkxNzQ2NjAxNDg4NDMzNA.GaXb9c.abc123fake')
    For a class submission, store the token separately: create a file named config.py in the same folder containing just TOKEN = 'your-token-here', then in bot.py write from config import TOKEN and use client.run(TOKEN). Never submit or push config.py to GitHub. For this exercise, the inline approach is fine as long as you don't share the file.
  7. Save the file (Ctrl+S / Cmd+S).
  8. Run the bot. Back in your terminal, navigate into your project folder and run it:
    cd Desktop/my-first-bot python3 bot.py
    Windows alternatives for the run command: py -3 bot.py or python bot.py if python3 isn't recognized.
    discord.errors.LoginFailure: Improper token has been passed: your token is wrong. Common causes: you accidentally copied extra whitespace before or after it; you copied the Application ID (a long number) instead of the token; or you reset the token after copying the old one (always copy fresh after a reset). Go back to the Developer Portal, click Reset Token, copy it again carefully, and replace the value in bot.py.
    ModuleNotFoundError: No module named 'discord': discord.py installed into a different Python version than the one running bot.py. Install using the same Python you're running: python3 -m pip install discord.py then python3 bot.py (keeping both commands using python3). On Windows, keep both using py -3.
Checkpoint — what you should see
Your terminal prints Logged in as MyFirstBot#1234 (with your actual bot name). In Discord, open your test server — your bot's status dot in the member list turns from gray to green. The bot is now connected to Discord's WebSocket gateway and listening for events in real time. Leave the terminal running. If you close it, the bot goes offline.

Timing note: if the terminal already shows Logged in as ... but the member-list dot is still gray in Discord, wait about 30 seconds and then refresh Discord (Ctrl+R on Windows/Linux, Cmd+R on Mac). The terminal message is the authoritative "it worked" signal — Discord's presence update can lag slightly on first connect.
Bot is online (green dot) but doesn't reply to anything — check this FIRST: the most common cause is that the Message Content Intent toggle in the Developer Portal is off, or that intents.message_content = True is missing in your code. Go to discord.com/developers/applications, select your app, click Bot, scroll to Privileged Gateway Intents, confirm Message Content Intent is toggled on (blue/green), click Save Changes, then stop and restart bot.py. Both the portal toggle AND the code line must be present — one without the other is enough to break it.

Add Commands — the Bot Responds to Messages
Now wire up the bot so it actually does something. You'll add an on_message event handler and three commands. Each time someone types in your server, Discord fires the event and your code decides whether to respond.
  1. Stop the running bot first. In the terminal press Ctrl+C to stop it. You'll edit the file, then restart it. The bot goes offline while you work — that's expected.
  2. Add the random import. At the very top of bot.py, add this line directly below import discord:
    import random
  3. Add the on_message handler. Paste this block into bot.py after the on_ready function and before the final client.run() line:
    @client.event async def on_message(message): if message.author == client.user: return if message.content == '!hello': await message.channel.send(f'Hello, {message.author.name}!') elif message.content == '!flip': result = random.choice(['Heads', 'Tails']) await message.channel.send(f'Coin flip: {result}') elif message.content == '!roll': result = random.randint(1, 6) await message.channel.send(f'You rolled a {result}!')
    What each part does: @client.event registers this as a Discord event handler. async def on_message(message) runs every time any message is sent in any channel the bot can see. if message.author == client.user: return is the self-ignore guard — without it the bot would see its own replies and potentially loop. message.content is the text of the message. await message.channel.send(...) posts a reply in the same channel. The await keyword is needed because sending is an async network operation — without it you'd get a warning and the message would never send. random.choice picks one item from a list randomly. random.randint(1, 6) generates a whole number from 1 to 6 inclusive.
  4. Your full bot.py now looks like this — verify yours matches before running:
    This snapshot is for comparison only. If you copy the whole block, the last line will read client.run('PASTE_YOUR_TOKEN_HERE') — you must replace that placeholder with your real bot token. Do not ship PASTE_YOUR_TOKEN_HERE.

  5. Save and restart the bot. Save with Ctrl+S (Cmd+S), then in the terminal run:
    python3 bot.py
    Wait for the Logged in as ... message before testing.
  6. Test in your Discord server. Open Discord, go to any text channel in your test server, and type each command:
    Commands to test!hello → bot replies "Hello, YourName!" !flip → bot replies "Coin flip: Heads" or "Coin flip: Tails" !roll → bot replies "You rolled a 4!" (random 1-6)
    Bot is online (green dot) but doesn't reply to anything: the most common cause is that the Message Content Intent toggle in the Developer Portal is off. The second common cause is that the bot is not in the channel — check that it appears in the server's member list.
    Bot is offline (gray dot) even though the script is running: the token is wrong or has been reset. Go to the Developer Portal, click Reset Token, copy the new token, paste it into client.run('...') in bot.py, save, and restart.
    Bot is not in the server at all (doesn't appear in member list): you either skipped the invite step in Phase 1 or invited it to the wrong server. Go back to Phase 1 step 7, generate the OAuth2 URL again, paste it in the browser, and choose the correct server.

Make It Smart — Jokes, the Magic 8-Ball, and Graceful Error Handling
Add two commands that use data lists for dynamic responses, and add a graceful fallback so the bot never silently ignores a mistyped command. Same rhythm as Phase 3: stop the bot, edit, save, restart, test.
  1. Stop the bot with Ctrl+C in the terminal.
  2. Add the JOKES list. Paste this near the top of bot.py, directly below the two import lines and above the intents lines. These are the strings the bot picks from at random:
    JOKES = [ "Why don't scientists trust atoms? Because they make up everything.", "I told my computer I needed a break. Now it won't stop sending me KitKat ads.", "Why do programmers prefer dark mode? Because light attracts bugs.", "How many programmers does it take to change a light bulb? None — that's a hardware problem.", "Why did the scarecrow win an award? Because he was outstanding in his field.", "I asked the router if it was hungry. It said it was just a little packet.", "What do you call 8 hobbits? A hobbyte.", "A SQL query walks into a bar, walks up to two tables, and asks: 'Can I join you?'", "Why did the developer go broke? Because they used up all their cache.", "What do you call a fish with no eyes? A fsh.", ]
  3. Add the EIGHT_BALL list. Paste this directly below the JOKES list:
    EIGHT_BALL = [ "It is certain.", "Without a doubt.", "You may rely on it.", "Most likely.", "Ask again later.", "Cannot predict now.", "Don't count on it.", "My sources say no.", ]
  4. Add three new elif branches inside the on_message handler, after the existing !roll block and before the closing of the function. Your full handler should now look exactly like this — the new lines are the !joke, !8ball, and unknown-command branches:
    @client.event async def on_message(message): if message.author == client.user: return if message.content == '!hello': await message.channel.send(f'Hello, {message.author.name}!') elif message.content == '!flip': result = random.choice(['Heads', 'Tails']) await message.channel.send(f'Coin flip: {result}') elif message.content == '!roll': result = random.randint(1, 6) await message.channel.send(f'You rolled a {result}!') elif message.content == '!joke': await message.channel.send(random.choice(JOKES)) elif message.content.startswith('!8ball '): question = message.content.split(' ', 1)[1] answer = random.choice(EIGHT_BALL) await message.channel.send(f'Question: {question}\nAnswer: {answer}') elif message.content.startswith('!'): await message.channel.send('Unknown command. Try !hello, !flip, !roll, !joke, or !8ball <question>.')
    Three things to notice: (1) message.content.startswith('!8ball ') has a space after !8ball — type exactly one space between !8ball and your question, then the rest of your sentence can contain any spaces you like. (2) message.content.split(' ', 1)[1] splits on the first space only and takes everything after it — because startswith('!8ball ') already guarantees that space exists, this is safe and avoids any oddities with extra leading spaces. (3) The final elif message.content.startswith('!') is the catch-all — it only fires for unmatched ! commands, so normal conversation in the channel doesn't get a "Unknown command" reply.
  5. Your complete final bot.py — verify yours matches before running:
