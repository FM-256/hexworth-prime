Subject

Build a Pi Network IDS

Advanced 120 min 1000 XP
Mission Brief

This operation deploys a Raspberry Pi as a passive network intrusion detection system — a silent watchdog that inspects every packet flowing through your network, matches traffic against known attack signatures, and surfaces alerts through a custom dashboard the moment something suspicious appears.

You will configure the Pi's network interface in promiscuous mode to capture all traffic on the segment, install and tune Suricata — the same open-source IDS engine used by enterprise security operations centers — write custom rules and enable community rulesets, build a Python-based log parser that extracts and classifies alerts by severity, render those alerts on a real-time dashboard, and implement automated response by feeding confirmed threats into iptables blocking rules.

This is the exact defensive monitoring pattern deployed in production SOCs worldwide, scaled down to a single-board computer you control entirely.

Agent Requirements
  • A Raspberry Pi 4B with 4GB RAM (8GB recommended)
  • Ethernet connection (required for promiscuous mode sniffing)
  • Intermediate Linux command line skills (pipes/grep/systemctl)
  • Basic understanding of network protocols (TCP/IP/HTTP/DNS)
  • Familiarity with reading log files and JSON data
Operation Phases
1
Network Tap Setup & Promiscuous Mode
Connect the Pi via Ethernet to a mirrored/span port on your switch (or use a network tap). Configure the interface for promiscuous mode with ip link set eth0 promisc on. Verify capture capability with tcpdump by observing traffic from other hosts.
2
Suricata IDS Installation & Rule Configuration
Install Suricata from the package manager, configure suricata.yaml with your network's HOME_NET range, enable the ET Open ruleset for community threat signatures, and start Suricata as a systemd service monitoring eth0. Verify it's generating eve.json alert logs.
3
Log Parsing & Alert Extraction
Write a Python script that tails /var/log/suricata/eve.json, parses each JSON line, filters for alert events, and extracts key fields: timestamp, signature, severity, source IP, destination IP, and protocol. Store parsed alerts in an SQLite database for historical querying.
4
Custom Alert Dashboard
Build a Python-based web dashboard (Flask or simple HTTP server) that reads from the SQLite alert database and renders a live feed of recent alerts, color-coded by severity (red for high, yellow for medium, green for low). Add summary statistics: total alerts, top signatures, top source IPs, and alerts-per-hour graph.
5
Automated Blocking with iptables
Implement an auto-response module that monitors high-severity alerts and, after configurable thresholds (e.g., 3+ alerts from the same source IP), automatically adds an iptables DROP rule to block the offending IP. Log all automated blocks and provide a whitelist mechanism to prevent blocking legitimate hosts.
