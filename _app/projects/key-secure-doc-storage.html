Subject

Secure Document Storage with Blockchain

Advanced 120 MIN 1000 XP
Mission Brief

This operation constructs a blockchain-backed document storage system that guarantees authenticity, tamper-evidence, and auditable access control without relying on any trusted central authority. Documents are hashed with SHA-256 before storage, and only the cryptographic fingerprint — never the document itself — is written to the blockchain, creating an immutable record that proves a document's exact contents existed at a specific point in time.

On-chain access control lists (ACLs) govern who may read each document. Permissions are granted and revoked through signed transactions, and every permission change is permanently recorded in the contract's event log. A Merkle tree over all stored document hashes enables batch verification proofs, letting any party verify a document's inclusion in the registry by providing only a logarithmic-length proof rather than the full dataset. The tamper-proof audit trail records every upload, access grant, revocation, and verification check with block timestamp and caller address.

The system separates concerns cleanly: the Solidity contract handles on-chain state and access enforcement, an IPFS layer stores encrypted document bytes, and an Express API bridges the browser client to both layers. You will implement client-side AES-256 encryption before IPFS upload so that even the storage layer cannot read document contents without the decryption key held only by authorized users.

Agent Requirements
  • Understanding of cryptographic hash functions: SHA-256 properties and collision resistance
  • Familiarity with Solidity basics: mappings, events, modifiers, and payable functions
  • Comfortable with Node.js and Express for REST API development
  • Basic understanding of public-key cryptography and digital signatures
  • No prior IPFS experience required — the project covers IPFS content addressing from scratch
Operation Phases
1
Document Registry Contract
Author the DocumentRegistry Solidity contract. Define a Document struct with docHash, ipfsCID, owner, timestamp, and exists fields. Implement registerDocument(bytes32 docHash, string ipfsCID) that maps the hash to its metadata, rejects duplicate registrations, and emits a DocumentRegistered event. Add a verifyDocument(bytes32 hash) view function that returns the registration record or reverts if not found.
2
On-Chain Access Control Lists
Add permission management to the registry. Implement a mapping(bytes32 => mapping(address => bool)) accessList scoped per document hash. The document owner may call grantAccess(bytes32 hash, address grantee) and revokeAccess(bytes32 hash, address grantee). Guard sensitive read functions with an onlyAuthorized(bytes32 hash) modifier. Emit AccessGranted and AccessRevoked events with block-level timestamps for the audit trail.
3
Client-Side Encryption & IPFS Upload
Implement browser-side document processing using the Web Crypto API. Generate a random AES-256-GCM key for each document upload, encrypt the file bytes before sending to IPFS via Pinata's API, and compute the SHA-256 hash of the original plaintext for on-chain registration. Store the encryption key encrypted with the owner's public key so only they can recover it. Build the Express middleware that proxies authenticated IPFS requests and returns the IPFS CID to the frontend.
4
Merkle Proof Verification
Build a Merkle tree over all registered document hashes using the merkletreejs library with SHA-256 as the leaf hash function. Implement generateProof(docHash) that returns the sibling hashes needed to reconstruct the path to the Merkle root. Add a verifyInclusion(proof, root, leaf) function that validates the proof without requiring access to the full tree. Store the current Merkle root on-chain and update it whenever new documents are registered.
5
Tamper-Proof Audit Trail
Build an audit log viewer that reconstructs the complete history of any document by querying all relevant contract events from genesis using ethers.queryFilter. Events to surface: DocumentRegistered, AccessGranted, AccessRevoked, and DocumentVerified. Display the timeline with block number, timestamp, action type, and actor address. Add a tamper detection mode that re-hashes the current IPFS content and compares it against the on-chain hash, flagging any discrepancy as a tampering alert.
6
React Dashboard & Test Suite
Build a React dashboard with four views: document upload with drag-and-drop, my documents list with access management controls, document verification tool accepting a file or hash input, and the audit log viewer. Write Hardhat tests covering registration uniqueness enforcement, ACL grant/revoke correctness, Merkle proof validity, and unauthorized access rejection. Include a fuzz test that generates random document hashes and verifies they cannot be registered twice.
