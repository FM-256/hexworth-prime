Subject

Build a Budget App with FERN Stack

Operative 90 min 500 XP
Mission Brief

Your assignment is to build a real-time budget management application using the FERN stack: Firebase for the Firestore NoSQL database and Google authentication, Express and Node.js as a lightweight REST API that validates every write server-side before it touches the database, and React (scaffolded with Vite) for the frontend. Users sign in with Google, then add income and expense entries that persist instantly in Firestore.

This is a zero-knowledge walkthrough. Every phase shows the exact files to create, the exact code to paste, and the observable result that confirms you are on track before moving on. You never have to guess where a snippet goes — each phase that changes a file gives you the complete new version of that file, not just a fragment. The total cost of running this project is $0: the Firebase Spark (free) plan covers Firestore reads/writes and Google Auth for a personal project with no credit card required.

By the end, entries you add in one browser tab appear in another tab within milliseconds via Firestore’s onSnapshot real-time listener. A running income/expense balance updates automatically, a category breakdown shows spending by type, and a month filter plus CSV export let you analyze your data. You will have built the complete modern full-stack pattern: React frontend → Express API → Firebase Admin SDK → Firestore.

Agent Requirements
  • Node.js LTS v22.x or higher — download the LTS installer from nodejs.org/en/download. After installing, open a terminal and run node --version and npm --version to confirm both are present.
  • A terminal (Windows: PowerShell or Command Prompt; Mac: Terminal; Linux: any shell). Every command in this project is shown exactly as you type it.
  • VS Code (code.visualstudio.com) recommended — any plain-text editor works, but VS Code gives you syntax highlighting for JSX.
  • A free Google account to create a Firebase project. No credit card. The Firebase Spark (free) plan covers everything in this project: Firestore allows 50,000 reads and 20,000 writes per day free; Google Auth has no free-tier limit.
  • Basic comfort with JavaScript variables, functions, and async/await. React hook experience is helpful but not required — every hook is explained when it appears.

Express API Server with Firebase Admin Auth Middleware
Build the Node.js + Express backend in a separate folder. Every budget write goes through this server, which uses the Firebase Admin SDK to verify that the request comes from a legitimately authenticated user before touching Firestore. This is the server-side trust boundary: the frontend passes the user’s Firebase ID token in each request header, and the Express middleware verifies it cryptographically.
  1. Download a service account key. In the Firebase console click Project settings → Service accounts. Click Generate new private key, then Generate key. A JSON file downloads to your computer. Name it serviceAccountKey.json.
    This JSON file is a secret. It grants admin access to your entire Firebase project. Never commit it to Git, never put it in the React client folder, and never share it. Keep it only in the server folder and add it to .gitignore before doing anything else.
  2. Create the server project folder alongside (not inside) budget-fern-client:
    mkdir budget-fern-server cd budget-fern-server npm init -y npm install express firebase-admin cors
    cors is needed because the React dev server runs on port 5173 and the Express server runs on port 4000 — two different origins. Without the cors middleware the browser blocks the fetch calls with a CORS error.
  3. Copy your service account key into budget-fern-server/serviceAccountKey.json. Then create .gitignore immediately:
    node_modules/ serviceAccountKey.json
  4. Create server.js in budget-fern-server/. This is the complete server file for Phase 2 and 3:
    // server.js // Firebase Admin SDK verified against firebase.google.com/docs/admin/setup // verifyIdToken pattern from firebase.google.com/docs/auth/admin/verify-id-tokens const express = require('express'); const cors = require('cors'); const { initializeApp, cert } = require('firebase-admin/app'); const { getAuth } = require('firebase-admin/auth'); const { getFirestore } = require('firebase-admin/firestore'); // Initialize Firebase Admin with the service account key. // cert() reads the JSON file and uses it as the admin credential. const adminApp = initializeApp({ credential: cert(require('./serviceAccountKey.json')) }); const adminAuth = getAuth(adminApp); const db = getFirestore(adminApp); const app = express(); app.use(express.json()); // Allow requests from the Vite dev server on port 5173. app.use(cors({ origin: 'http://localhost:5173' })); // ── Auth middleware ────────────────────────────────────────── // Every protected route calls this function first. // It reads the Bearer token from the Authorization header, // calls verifyIdToken() to cryptographically verify it, // and attaches the decoded token (containing uid) to req.user. // If the token is missing or invalid, it returns 401 immediately. async function requireAuth(req, res, next) { const header = req.headers.authorization || ''; const token = header.startsWith('Bearer ') ? header.slice(7) : null; if (!token) return res.status(401).json({ error: 'No token provided' }); try { req.user = await adminAuth.verifyIdToken(token); next(); } catch (err) { return res.status(401).json({ error: 'Invalid or expired token' }); } } // ── GET /transactions ──────────────────────────────────────── // Returns all transactions for the authenticated user, // ordered by date descending. app.get('/transactions', requireAuth, async (req, res) => { try { const uid = req.user.uid; const colRef = db .collection('users').doc(uid) .collection('transactions') .orderBy('date', 'desc'); const snapshot = await colRef.get(); const items = snapshot.docs.map(doc => ({ id: doc.id, ...doc.data() })); res.json(items); } catch (err) { res.status(500).json({ error: err.message }); } }); // ── POST /transactions ─────────────────────────────────────── // Validates the request body, then writes a new transaction // to the user's sub-collection in Firestore. app.post('/transactions', requireAuth, async (req, res) => { try { const uid = req.user.uid; const { description, amount, category, type, date } = req.body; // Server-side validation: reject incomplete or malformed data. if (!description || typeof description !== 'string' || !description.trim()) { return res.status(400).json({ error: 'description is required' }); } const parsedAmount = parseFloat(amount); if (isNaN(parsedAmount) || parsedAmount <= 0) { return res.status(400).json({ error: 'amount must be a positive number' }); } const CATEGORIES = ['food', 'housing', 'transport', 'entertainment', 'income', 'other']; if (!CATEGORIES.includes(category)) { return res.status(400).json({ error: 'invalid category' }); } if (type !== 'income' && type !== 'expense') { return res.status(400).json({ error: 'type must be income or expense' }); } const docRef = await db .collection('users').doc(uid) .collection('transactions') .add({ description: description.trim(), amount: parsedAmount, category, type, date: date || new Date().toISOString().slice(0, 10), createdAt: new Date().toISOString() }); res.status(201).json({ id: docRef.id }); } catch (err) { res.status(500).json({ error: err.message }); } }); // ── DELETE /transactions/:id ───────────────────────────────── // Verifies the document belongs to the authenticated user // before deleting it, preventing cross-user deletion. app.delete('/transactions/:id', requireAuth, async (req, res) => { try { const uid = req.user.uid; const docRef = db .collection('users').doc(uid) .collection('transactions') .doc(req.params.id); const snap = await docRef.get(); if (!snap.exists) return res.status(404).json({ error: 'Not found' }); await docRef.delete(); res.json({ ok: true }); } catch (err) { res.status(500).json({ error: err.message }); } }); const PORT = 4000; app.listen(PORT, () => console.log('API server running on http://localhost:' + PORT));
  5. Start the API server. In your terminal (inside budget-fern-server):
    node server.js
    Expected output: API server running on http://localhost:4000
  6. Update Firestore security rules. Even though the Express server does all writes, the frontend’s onSnapshot listener (Phase 4) reads Firestore directly. In the Firebase console go to Firestore Database → Rules and replace the test-mode rules with user-scoped rules:
    rules_version = '2'; service cloud.firestore { match /databases/{database}/documents { // Clients may only READ their own documents (needed for onSnapshot). // Writes go through the Express server, which uses the Admin SDK -- // Admin SDK calls bypass security rules entirely, so no write rule // is needed here, and granting clients write access would allow them // to skip Express validation. Read-only for clients is correct. match /users/{userId}/{document=**} { allow read: if request.auth != null && request.auth.uid == userId; } } }
    Click Publish. The rule takes effect within seconds.
    Why read-only for clients? The onSnapshot listener in Phase 4 reads Firestore directly from the browser, so clients need read permission. All writes, however, go through the Express server using the Firebase Admin SDK. The Admin SDK runs with full service-account credentials and bypasses Firestore security rules completely — that is by design, and it is why the Admin SDK must stay server-side. Because writes never come from the client, there is no need to grant clients write access, and doing so would let a user bypass the Express validation layer entirely.
Server exits with Error: ENOENT: serviceAccountKey.json? The key file is not where Node.js expects it. require('./serviceAccountKey.json') looks for the file in the same directory as server.js. Confirm both are inside budget-fern-server/. Run ls to verify.
Server exits with FirebaseAppError: Failed to parse service account? The JSON key file is corrupted or was partially downloaded. Go back to Firebase console → Project settings → Service accounts and generate a new key. Delete the old file and replace it.
React fetch later fails with a CORS error even after adding cors()? The origin in the CORS option must exactly match the Vite dev URL. Vite uses port 5173 by default. If it started on a different port (check the Vite terminal output), update the origin value in server.js, restart the API server, and retry.
Checkpoint — what you should see
The terminal running node server.js shows API server running on http://localhost:4000. Open a second terminal tab and run: curl http://localhost:4000/transactions. You should receive {"error":"No token provided"} — the auth middleware is working. You now have two terminals running: Vite on 5173 and Express on 4000. The Firestore security rules are published and no longer in test mode.

  1. Create src/api.js in budget-fern-client/. This module handles the token-fetch-and-send pattern so you never repeat it:
    // src/api.js // Helper that attaches the Firebase ID token to every API request. // getIdToken() (no argument) returns the cached token and auto-refreshes // only when it is actually close to expiry -- no unnecessary network calls. import { auth } from './firebase'; const BASE = 'http://localhost:4000'; async function authHeaders() { const token = await auth.currentUser.getIdToken(); return { 'Content-Type': 'application/json', 'Authorization': 'Bearer ' + token }; } export async function getTransactions() { const res = await fetch(BASE + '/transactions', { headers: await authHeaders() }); if (!res.ok) throw new Error(await res.text()); return res.json(); } export async function addTransaction(data) { const res = await fetch(BASE + '/transactions', { method: 'POST', headers: await authHeaders(), body: JSON.stringify(data) }); if (!res.ok) throw new Error(await res.text()); return res.json(); } export async function deleteTransaction(id) { const res = await fetch(BASE + '/transactions/' + id, { method: 'DELETE', headers: await authHeaders() }); if (!res.ok) throw new Error(await res.text()); return res.json(); }

Real-Time Transaction List with Running Balance
Replace the placeholder paragraph with a live transaction list that uses Firestore’s onSnapshot to update the moment any transaction is added or deleted — no page refresh, no polling. A summary bar above the list shows total income, total expenses, and the running net balance. Delete buttons on each row call the Express API to remove the document.
  1. Create src/Dashboard.jsx — the main view component:
