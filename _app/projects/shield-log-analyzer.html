Subject

Build a Log Analyzer

Journeyman 90 min 500 XP
Mission Brief

This operation requires the construction of a Python-based log analysis engine capable of ingesting raw security logs from multiple sources — including syslog, auth.log, Apache access logs, and Windows Event Log exports — and extracting structured, actionable intelligence from the noise. Every log line is parsed using re-based pattern matching into normalized event dictionaries carrying timestamps, source IPs, severity levels, and event classifications.

The engine implements a detection rule layer that flags known attack patterns in real time: brute-force login attempts identified by repeated failures from a single IP within a configurable time window, port scan signatures, privilege escalation chains involving su and sudo events, and anomalous access timing outside expected operational hours. Events are then correlated across log sources by aligning timestamps and shared IP addresses, producing unified attack timelines that link the initial probe to the eventual breach.

The final output is a structured incident report delivered as both formatted terminal output and a machine-readable JSON artifact. Each alert carries a severity score, an event chain with evidence references, and a recommended response action — the same output format used by professional SIEM platforms. Upon completion, you will have built a working threat detection tool and developed the analytical mindset that separates a passive log consumer from an active threat hunter.

Agent Requirements
  • Comfortable with Python basics — reading files, working with dicts, and using string methods
  • Familiar with common log formats such as syslog, Apache access logs, and auth.log entry structure
  • Basic understanding of security events including failed logins, port scans, and privilege escalation
  • Know how to read and write files in Python and work with structured data formats like CSV and JSON
  • No prior SIEM or log analysis experience required — detection rules and correlation logic are built from scratch
Operation Phases
Progress
0 / 5
✓
1
Log Ingestion & Parsing
Build dedicated parsers for syslog, auth.log, and Apache access log formats using re.compile() pattern objects. Each parser extracts timestamps, source IPs, severity levels, and event type into a normalized dict, creating a unified event stream regardless of the originating log format.
Checkpoint: Project Setup
  • Run the log analyzer on a sample log file and verify it produces output
  • Confirm the script supports the expected log format (syslog, Apache, JSON, etc.)
  • Verify the required parsing libraries are installed and importable
✓
2
Pattern Detection Engine
Implement modular detection rules using collections.defaultdict to track per-IP event histories. Rules include brute-force detection (N failed logins from the same IP within M minutes), port scan detection (connections to N+ distinct ports from a single source), su and sudo privilege escalation events, and access outside configured time windows.
✓
3
Cross-Source Correlation
Link related events across log files by grouping on IP address and aligning datetime timestamps within configurable correlation windows. Build an event timeline that chains related activity — for example, repeated SSH failures followed by a successful login followed by a privilege escalation — into a single coherent attack narrative.
Checkpoint: Parsing & Extraction
  • Parse a 1,000-line log file and verify all entries are processed without parse errors
  • Confirm extracted fields (timestamp, severity, source, message) match the raw log entries
  • Verify the parser handles malformed lines gracefully (skip and log, not crash)
✓
4
Severity Scoring & Alerts
Assign severity scores (INFO / LOW / MEDIUM / HIGH / CRITICAL) to each detected pattern based on configurable rule weights. Generate alert objects that include the full event chain, supporting evidence lines, the triggering rule, and a recommended response action such as block, investigate, or escalate.
Checkpoint: Reporting
  • Generate a summary report and verify it includes time range, total entries, and severity breakdown
  • Confirm the report highlights anomalies or events that exceed configured thresholds
  • Verify the report exports to the specified format (HTML, PDF, or text)
✓
5
Report Generation & Output
Export findings as structured json.dumps() output and a formatted ANSI-colored terminal report. The summary includes total events ingested, top offending IPs, per-severity alert counts, a condensed attack timeline, and per-alert detail blocks. Wire up argparse so the tool accepts log file paths, output format flags, and detection thresholds from the command line.
Checkpoint: Analysis & Patterns
  • Run the analysis and verify it identifies the top 10 most frequent log messages
  • Confirm error and warning counts match a manual grep of the log file
  • Verify the analyzer detects any suspicious patterns (repeated auth failures, unusual IPs)
