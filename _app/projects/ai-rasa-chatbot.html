Subject

Build a Conversational AI with Rasa

Operative 90 min 500 XP
Mission Brief

Your assignment is to build a fully functional AI chatbot using Rasa Open Source 3.6.21, the open-source conversational AI framework that gives you complete control over your NLU pipeline and dialogue management — no API keys, no black boxes, no data leaving your infrastructure.

You will author training data in Rasa's YAML format: nlu.yml for labeled user utterances, stories.yml for multi-turn conversation paths, rules.yml for deterministic single-turn responses, and domain.yml to declare every intent, entity, slot, action, and bot response. After rasa train builds a model, you will test it live in your terminal with rasa shell.

The final phase adds a custom action — a Python function that Rasa calls when scripted responses are not enough. You will run it in a second terminal with rasa run actions, wire it to Rasa via endpoints.yml, and watch the bot return dynamically generated text at runtime.

Agent Requirements
  • Python 3.8, 3.9, or 3.10 only. Rasa 3.6.21 declares python <3.11,>=3.8 on PyPI — it will not install on Python 3.11 or 3.12. Check with python --version. If you have 3.11+, install 3.10 via pyenv or the python.org installer and use a dedicated venv.
  • A virtual environment is strongly recommended — Rasa pins many dependencies (TensorFlow, protobuf, etc.) that will conflict with other projects if installed globally. Phase 1 walks you through creating one.
  • 4 GB RAM minimum for rasa train; 8 GB recommended. Training the default starter bot takes 2–5 minutes on a modern laptop.
  • Basic Python comfort: you should be able to read a function and follow indentation. No prior NLP experience required.
  • Basic YAML comfort: YAML uses indentation for structure. Two-space indent is the standard. A single tab instead of spaces will break your config files.

Environment Setup and Project Scaffold
Create an isolated Python 3.10 virtual environment, install Rasa 3.6.21, and scaffold a starter project with rasa init. The venv is not optional — Rasa's pinned dependencies will silently break other tools if you install globally.
  1. Confirm your Python version. Rasa 3.6.21 requires Python 3.8, 3.9, or 3.10. Run:
    python --version
    If the output shows 3.11 or higher, you must install Python 3.10 from python.org (Windows/Mac) or via pyenv install 3.10.14 (Linux/Mac) before continuing. Use that Python binary for the next step.
  2. Create a project folder and a virtual environment inside it.
    mkdir rasa-bot cd rasa-bot python3.10 -m venv venv
    On Windows, use py -3.10 -m venv venv if you installed Python 3.10 via the official installer. On Mac/Linux, replace python3.10 with the path pyenv printed after install (e.g. ~/.pyenv/versions/3.10.14/bin/python).
  3. Activate the virtual environment.
    # Mac / Linux source venv/bin/activate # Windows (PowerShell) .\venv\Scripts\Activate.ps1 # Windows (Command Prompt) venv\Scripts\activate.bat
    Your prompt changes to show (venv) at the start. Every command from here on must be run with the venv active.
  4. Upgrade pip and install Rasa 3.6.21.
    pip install --upgrade pip pip install rasa==3.6.21
    This downloads ~400 MB of dependencies including TensorFlow and many NLP libraries. It will take 3–10 minutes depending on your connection. Do not interrupt it.
  5. Verify the install.
    rasa --version
    Expected output:
    Rasa Version : 3.6.21 Minimum Compatible Version: 3.6.0 Rasa SDK Version : 3.6.2 Python Version : 3.10.x ...
  6. Scaffold a starter bot. Run rasa init inside the rasa-bot folder. Rasa will ask a few questions — answer as shown:

    ? Please enter a path for the project (or press enter to use the current directory) [.]: -> press Enter (use current directory) ? Do you want to train an initial model? [Y/n]: -> n (we will train manually in Phase 3)
    Answering n to training skips the 2–5 minute wait for now. You will run rasa train manually after editing the data files.
  7. Inspect the generated file tree. You should now have:

Author Training Data and Domain
Replace the starter placeholder content with a real help-desk chatbot that handles IT support requests. You will edit four files: nlu.yml, stories.yml, rules.yml, and domain.yml. Replace each file's contents completely — do not merge with the generated placeholder text.
  1. Replace data/nlu.yml with labeled training examples. Rasa needs at least 10 examples per intent to train reliably. Open the file and paste this content (replacing everything):
    version: "3.1" nlu: - intent: greet examples: | - hey - hello - hi - good morning - good afternoon - hey there - howdy - hi bot - hello there - yo - intent: goodbye examples: | - bye - goodbye - see you - see ya - later - take care - thanks bye - good night - cya - I'm done - intent: report_issue examples: | - my laptop won't boot - I can't log in - the VPN keeps disconnecting - my email is not loading - printer is offline - I'm locked out of my account - wifi is down - the software keeps crashing - I forgot my password - the screen is black - intent: ask_status examples: | - what is the status of my ticket? - any update on my issue? - has my problem been resolved? - is my request being worked on? - can you check my ticket? - where is my support request? - give me an update please - how long will this take? - is anyone looking at my issue? - when will it be fixed? - intent: provide_ticket_number examples: | - it is [TKT-1042](ticket_number) - my ticket number is [TKT-2201](ticket_number) - [TKT-0099](ticket_number) - the ticket is [TKT-3314](ticket_number) - [TKT-5500](ticket_number) is my reference - number [TKT-8871](ticket_number) - I have ticket [TKT-0012](ticket_number) - reference [TKT-4400](ticket_number) - it's [TKT-6603](ticket_number) - [TKT-7712](ticket_number) please - intent: affirm examples: | - yes - yeah - yep - correct - that's right - sure - absolutely - ok - okay - sounds good - intent: deny examples: | - no - nope - not really - I don't think so - negative - wrong - that's not it - no thanks - nah - definitely not
    The [TKT-1042](ticket_number) syntax is Rasa entity annotation: the text in brackets is the example value, the text in parentheses is the entity name. Rasa learns to extract ticket numbers from user messages using these examples.
  2. Replace data/stories.yml with multi-turn conversation paths. Stories teach Rasa's dialogue policy what to do next based on conversation history:
    version: "3.1" stories: - story: user reports issue and gets confirmation steps: - intent: greet - action: utter_greet - intent: report_issue - action: utter_ask_ticket_number - intent: provide_ticket_number - action: utter_ticket_received - story: user asks status with ticket number steps: - intent: greet - action: utter_greet - intent: ask_status - action: utter_ask_ticket_number - intent: provide_ticket_number - action: action_check_ticket_status - story: user reports issue then leaves steps: - intent: report_issue - action: utter_ask_ticket_number - intent: deny - action: utter_no_ticket - intent: goodbye - action: utter_goodbye
  3. Replace data/rules.yml with deterministic single-turn responses that always trigger regardless of conversation history:
    version: "3.1" rules: - rule: respond to greeting steps: - intent: greet - action: utter_greet - rule: respond to goodbye steps: - intent: goodbye - action: utter_goodbye
  4. Replace domain.yml completely. The domain declares every intent, entity, slot, and response the bot knows about. If something is not declared here, Rasa will reject it during training:
    version: "3.1" intents: - greet - goodbye - report_issue - ask_status - provide_ticket_number - affirm - deny entities: - ticket_number slots: ticket_number: type: text mappings: - type: from_entity entity: ticket_number responses: utter_greet: - text: "Hello! I'm the IT Help Desk bot. How can I help you today?" utter_goodbye: - text: "Goodbye! If you have more issues, don't hesitate to ask." utter_ask_ticket_number: - text: "Do you have a ticket number? If so, please share it (format: TKT-XXXX)." utter_ticket_received: - text: "Got it! I've logged your issue. A support agent will follow up on ticket {ticket_number} shortly." utter_no_ticket: - text: "No problem. I've noted your issue without a ticket number. Would you like me to create a new ticket?" utter_default: - text: "I'm not sure I understood that. Could you rephrase? You can report an issue, ask for a status update, or say goodbye." actions: - action_check_ticket_status session_config: session_expiration_time: 60 carry_over_slots_to_new_session: true
YAML indentation error during rasa train? YAML is whitespace-sensitive. Two spaces per indent level is the standard; tabs are forbidden. If you see Error: Failed to load domain.yml or InvalidDomain, paste your YAML into an online YAML validator (e.g. yamllint.com) to find the offending line. The most common mistake is mixing tabs and spaces, or copying from a rich-text source that converts spaces to non-breaking spaces.

Run rasa data validate from the rasa-bot folder with the venv active. It should print No errors found. If it reports errors, read the error message carefully — it tells you the file name, line number, and what is wrong. Fix the indicated line before proceeding to Phase 3. Attempting to train with invalid data will fail at the same error.

Configure the NLU Pipeline and Train
Edit config.yml to set the NLU pipeline and dialogue policies, then run rasa train to build the model. Training takes 2–5 minutes and produces a single .tar.gz model file in models/.
  1. Replace config.yml with this pipeline. The components listed here are the standard Rasa 3.x recommended stack for a small task-oriented bot without a pre-trained language model:
    recipe: default.v1 language: en pipeline: - name: WhitespaceTokenizer - name: RegexFeaturizer - name: LexicalSyntacticFeaturizer - name: CountVectorsFeaturizer - name: CountVectorsFeaturizer analyzer: char_wb min_ngram: 1 max_ngram: 4 - name: DIETClassifier epochs: 100 constrain_similarities: true - name: EntitySynonymMapper - name: ResponseSelector epochs: 100 policies: - name: MemoizationPolicy - name: TEDPolicy max_history: 5 epochs: 100 - name: RulePolicy
    What each component does: WhitespaceTokenizer splits text into tokens by whitespace. RegexFeaturizer and LexicalSyntacticFeaturizer add character-level and part-of-speech features. CountVectorsFeaturizer (word-level and char n-gram) converts tokens to numeric vectors. DIETClassifier is Rasa's joint intent classification + entity extraction model. MemoizationPolicy memorises exact story paths. TEDPolicy handles unseen conversation paths. RulePolicy enforces deterministic rules.
  2. Train the model.
    rasa train
    You will see output like:
    Training NLU model... Fitting 2 folds for each of 3 candidates, totalling 6 fits ... Training Core model... Epochs: 100%|##########| 100/100 [01:42<00:00, 0.97it/s] ... Your Rasa model is trained and saved at 'models/20260619-143022-calm-ratio.tar.gz'
    The filename contains a timestamp and two random words. The exact name does not matter — Rasa always picks the newest model automatically.
  3. Test the bot in your terminal.
    rasa shell
    Type a greeting and interact:
    Your input -> hello Bot: Hello! I'm the IT Help Desk bot. How can I help you today? Your input -> my email is not loading Bot: Do you have a ticket number? If so, please share it (format: TKT-XXXX). Your input -> TKT-1042 Bot: Got it! I've logged your issue. A support agent will follow up on ticket TKT-1042 shortly. Your input -> bye Bot: Goodbye! If you have more issues, don't hesitate to ask.
    Press Ctrl+C to exit rasa shell.
  4. Check NLU confidence scores to see what the model predicts for a specific message without entering interactive mode:
    rasa shell nlu
    Type any message and Rasa will print its intent prediction with a confidence score, plus any extracted entities. Press Ctrl+C to exit.
rasa train fails with "Action 'action_check_ticket_status' is listed in the domain but is not a default action." This is expected at this stage if you see it as a warning, not an error — the custom action is declared in domain.yml but not yet implemented in actions.py. Training will still complete. If it is an error that stops training, check that you spelled the action name identically in domain.yml and stories.yml.
rasa shell responds "I'm not sure I understood that." to everything? This is the utter_default fallback firing because intent confidence is too low. It usually means you have fewer than 10 training examples for the intent you typed, or you typed something very different from the training examples. Add more varied examples to nlu.yml, then re-run rasa train (you must retrain after every data change — the running shell does not hot-reload).
Checkpoint — what you should see
rasa train completes without errors and prints a path to a .tar.gz file inside models/. Running rasa shell and typing "hello" returns the greeting response. Typing "my laptop won't boot" triggers the ask-for-ticket-number response. Typing a ticket number like "TKT-1042" returns the ticket-received confirmation with the number echoed back. That slot-filling working end-to-end confirms your NLU, stories, and domain are all consistent.

Write a Custom Action
Custom actions let the bot run arbitrary Python code — look up a database, call an API, or compute a response dynamically. You will implement action_check_ticket_status, which reads the ticket number the user provided and returns a simulated status message. The action runs in a separate process (rasa run actions) that Rasa calls over HTTP.
  1. Replace actions/actions.py with this implementation:
    from typing import Any, Text, Dict, List from rasa_sdk import Action, Tracker from rasa_sdk.executor import CollectingDispatcher # Simulated ticket database. # In a real deployment you would query a database or REST API here. TICKET_STATUS = { "TKT-1042": "In Progress - assigned to Level 2 support", "TKT-2201": "Resolved - solution emailed to you on Monday", "TKT-0099": "Open - queued, estimated response within 4 hours", "TKT-3314": "Pending - waiting for additional information from you", "TKT-5500": "Closed - marked resolved on 2026-06-18", } class ActionCheckTicketStatus(Action): """Look up the status of a support ticket by ticket number.""" def name(self) -> Text: # This string must match exactly what is in domain.yml and stories.yml. return "action_check_ticket_status" def run( self, dispatcher: CollectingDispatcher, tracker: Tracker, domain: Dict[Text, Any], ) -> List[Dict[Text, Any]]: # Retrieve the ticket_number slot value filled in earlier conversation. ticket_number = tracker.get_slot("ticket_number") if not ticket_number: dispatcher.utter_message( text="I don't have a ticket number on file. " "Please provide your ticket number (format: TKT-XXXX)." ) return [] # Normalize to uppercase so TKT-1042 and tkt-1042 both match. ticket_number = ticket_number.upper() status = TICKET_STATUS.get(ticket_number) if status: dispatcher.utter_message( text=f"Ticket {ticket_number}: {status}." ) else: dispatcher.utter_message( text=f"I could not find ticket {ticket_number} in the system. " "Please double-check the number, or contact support@helpdesk.example.com." ) # Returning an empty list means no slots are modified after this action. return []
  2. Uncomment the action server URL in endpoints.yml. Open the file and make sure this section is present and not commented out:
    action_endpoint: url: "http://localhost:5055/webhook"
    The default endpoints.yml has this line commented out with a #. Remove the # characters from both lines. If the file is missing entirely, create it with just those two lines.
  3. Start the action server in a second terminal. Open a new terminal tab or window, navigate to the rasa-bot folder, activate the venv, then run:
    source venv/bin/activate # or the Windows equivalent rasa run actions
    You should see:
    Starting action endpoint server... Action endpoint is up and running on http://0.0.0.0:5055
    Leave this terminal open and running. The action server must stay alive for the bot to call custom actions.
  4. Retrain so Rasa picks up the updated domain with the action declared. In your original terminal (venv active):
    rasa train
  5. Test the custom action end-to-end. In the original terminal, run:
    rasa shell
    Walk through the status-check flow:
    Your input -> hello Bot: Hello! I'm the IT Help Desk bot. How can I help you today? Your input -> can you check my ticket? Bot: Do you have a ticket number? If so, please share it (format: TKT-XXXX). Your input -> TKT-2201 Bot: Ticket TKT-2201: Resolved - solution emailed to you on Monday.
    Try a ticket number not in the lookup table to see the "not found" branch:
    Your input -> TKT-9999 Bot: I could not find ticket TKT-9999 in the system. Please double-check the number...
Bot responds "Sorry, I'm having trouble with that." when you trigger the status check? This is Rasa's fallback for when the action server is unreachable. The most common causes:
  • The rasa run actions terminal is not running or crashed — check it for error output.
  • endpoints.yml still has the action_endpoint URL commented out with # — remove the hash signs and retrain.
  • Port 5055 is blocked by a firewall or already in use — check with lsof -i :5055 (Mac/Linux) or netstat -ano | findstr 5055 (Windows).
ImportError: No module named 'rasa_sdk'? The action server and the main Rasa process both need rasa_sdk which is installed automatically with pip install rasa. If it is missing, the venv is not active in the second terminal. Re-run the activate command before rasa run actions.
Checkpoint — what you should see
In the action-server terminal, when the bot calls action_check_ticket_status you should see a log line like Received request to run 'action_check_ticket_status' and then Finished running 'action_check_ticket_status'. In the rasa shell terminal, the bot replies with the ticket status from the lookup table rather than a scripted YAML response. That confirms the full round-trip: Rasa NLU extracts the ticket number, Rasa Core calls your Python action, and the action returns dynamic text.

Expose the REST API and Build a Web Chat Interface
Start the Rasa server with --enable-api --cors "*" to expose the REST webhook at http://localhost:5005/webhooks/rest/webhook, then build a single-file HTML chat interface that sends messages to that endpoint using fetch().
  1. Start the Rasa REST server. In a terminal with the venv active (the action server must still be running in its own terminal):
    rasa run --enable-api --cors "*"
    You should see:
    Starting Rasa server on http://0.0.0.0:5005 ... Rasa server is up and running.
  2. Verify the endpoint with curl before touching the HTML:
    curl -s -X POST http://localhost:5005/webhooks/rest/webhook \ -H "Content-Type: application/json" \ -d '{"sender": "test-user", "message": "hello"}'
    Expected response (array of message objects):
    [{"recipient_id": "test-user", "text": "Hello! I'm the IT Help Desk bot. How can I help you today?"}]
    If you get this JSON back, the server is working and CORS is enabled.
  3. Create chat.html in the rasa-bot folder (outside the data/ or actions/ subfolders) and paste this complete file:
    <!DOCTYPE html> <html lang="en"> <head> <meta charset="UTF-8"> <title>IT Help Desk Bot</title> <style> body { margin: 0; font-family: Arial, sans-serif; background: #f0f0f0; display: flex; justify-content: center; align-items: center; height: 100vh; } #chat-container { width: 420px; height: 580px; background: #fff; border-radius: 12px; box-shadow: 0 4px 24px rgba(0,0,0,0.15); display: flex; flex-direction: column; overflow: hidden; } #chat-header { background: #6d28d9; color: #fff; padding: 16px 20px; font-weight: bold; font-size: 1rem; } #chat-messages { flex: 1; overflow-y: auto; padding: 16px; display: flex; flex-direction: column; gap: 10px; } .msg { max-width: 80%; padding: 10px 14px; border-radius: 16px; font-size: 0.9rem; line-height: 1.5; word-break: break-word; } .msg-user { background: #6d28d9; color: #fff; align-self: flex-end; border-bottom-right-radius: 4px; } .msg-bot { background: #f3f0ff; color: #1e1b4b; align-self: flex-start; border-bottom-left-radius: 4px; } #chat-input-row { display: flex; border-top: 1px solid #e5e7eb; } #chat-input { flex: 1; padding: 14px 16px; border: none; outline: none; font-size: 0.95rem; } #chat-send { padding: 14px 20px; background: #6d28d9; color: #fff; border: none; cursor: pointer; font-size: 0.95rem; } #chat-send:hover { background: #5b21b6; } </style> </head> <body> <div id="chat-container"> <div id="chat-header">IT Help Desk Bot</div> <div id="chat-messages"></div> <div id="chat-input-row"> <input id="chat-input" type="text" placeholder="Type a message..." autocomplete="off"> <button id="chat-send">Send</button> </div> </div> <script> // Rasa REST webhook URL. Change the host if Rasa runs on a remote server. const RASA_URL = 'http://localhost:5005/webhooks/rest/webhook'; // Use a unique sender ID per browser session so Rasa tracks conversation state. const SENDER_ID = 'user-' + Math.random().toString(36).slice(2, 9); const messagesEl = document.getElementById('chat-messages'); const inputEl = document.getElementById('chat-input'); const sendBtn = document.getElementById('chat-send'); function appendMessage(text, role) { const div = document.createElement('div'); div.className = 'msg ' + (role === 'user' ? 'msg-user' : 'msg-bot'); div.textContent = text; messagesEl.appendChild(div); messagesEl.scrollTop = messagesEl.scrollHeight; } async function sendMessage() { const text = inputEl.value.trim(); if (!text) return; inputEl.value = ''; appendMessage(text, 'user'); try { const response = await fetch(RASA_URL, { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ sender: SENDER_ID, message: text }) }); const messages = await response.json(); // Rasa returns an array; each element may have a "text" field. messages.forEach(msg => { if (msg.text) appendMessage(msg.text, 'bot'); }); } catch (err) { appendMessage('Error: could not reach the bot server. Is rasa run running?', 'bot'); console.error(err); } } sendBtn.addEventListener('click', sendMessage); inputEl.addEventListener('keydown', e => { if (e.key === 'Enter') sendMessage(); }); // Greet the user automatically on page load. (async () => { const response = await fetch(RASA_URL, { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ sender: SENDER_ID, message: 'hello' }) }).catch(() => null); if (response) { const messages = await response.json(); messages.forEach(msg => { if (msg.text) appendMessage(msg.text, 'bot'); }); } })(); </script> </body> </html>
  4. Open chat.html in your browser. Because the page makes a cross-origin request to localhost:5005, open it via a local HTTP server rather than double-clicking the file (the file:// protocol blocks cross-origin fetches in most browsers):
    # In a third terminal, from the rasa-bot folder: python -m http.server 8080
    Then open http://localhost:8080/chat.html in your browser.
  5. Test the full conversation flow in the browser. The bot should greet you automatically on load. Try the complete status-check flow: report an issue, provide a ticket number, then ask for status with a different ticket number.
Fetch error or empty response in the browser?
  • Confirm rasa run --enable-api --cors "*" is running — without --cors "*", the browser blocks the request with a CORS policy error visible in the browser console (F12).
  • Make sure you opened the page at http://localhost:8080/chat.html and not the file:// path.
  • Confirm the action server (rasa run actions) is still running in its own terminal — if it crashed, the bot will respond to greet/goodbye but hang on the ticket-status action.
rasa run says "No trained model found."? You started the server before completing rasa train in Phase 3 (or Phase 4's retrain step). Run rasa train first, then rasa run --enable-api --cors "*". Rasa always loads the newest file from the models/ folder automatically.

Typing "TKT-2201" causes the bot to call the custom action and reply "Ticket TKT-2201: Resolved - solution emailed to you on Monday."
