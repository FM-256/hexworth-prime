Subject

Build a RAG Chatbot

Operative 120 min 600 XP
Mission Brief

This operation tasks you with building a Retrieval-Augmented Generation chatbot that answers questions grounded in your own documents rather than relying on the LLM's pre-trained knowledge alone. Feed it PDFs, markdown files, or plain text — the bot will index every document into a vector store, retrieve the most relevant chunks at query time, and inject them as context into the language model's prompt before generating a response. The result: answers that cite your data, not hallucinated guesses.

The entire primary path runs 100% locally and free using Ollama as both the LLM server and the embedding provider. You pull two models to your machine — llama3.2 for generation and nomic-embed-text for embeddings — and nothing ever leaves your computer. No API key required. The pipeline is wired through LangChain using the current split-package layout: langchain-ollama, langchain-chroma, langchain-text-splitters, and langchain-community for document loaders. Vectors are persisted in ChromaDB, a lightweight local vector database that survives restarts.

At query time, the user's question is embedded into the same vector space, the top-4 most similar chunks are retrieved, and a LangChain LCEL chain assembles a grounded prompt and sends it to the local LLM. The finished chatbot runs as an interactive terminal loop — ask a question, get a sourced answer with chunk excerpts, repeat. An optional OpenAI sidebar is provided for those who already have an API key and want cloud-hosted generation instead.

Agent Requirements
  • Python 3.10 or higher — check with python --version or python3 --version
  • At least 8 GB RAM for the local Ollama models. llama3.2 (3B) uses roughly 2 GB; nomic-embed-text uses roughly 500 MB. 16 GB recommended for comfortable multi-tasking.
  • Ollama installed and running — Phase 1 covers the install. It is a single binary for Mac, Windows, and Linux.
  • Python fundamentals: functions, loops, pip, and reading a stack trace. No prior LangChain or vector database experience required.
  • At least one document to index — a PDF, a .txt file, or a markdown file works. Phase 1 tells you exactly where to put it.

Environment Setup & Ollama Install
Install Ollama, pull the two local models, create a Python virtual environment, and install all LangChain packages. Everything here is free and runs offline once the models are downloaded.
  1. Install Ollama. Go to ollama.com and download the installer for your OS. It installs a background service that serves local models over a REST API on port 11434. After installing, open a terminal and confirm it is running:
    ollama --version
    Expected output (version number will vary):
    ollama version 0.6.5
  2. Pull the LLM. This downloads the llama3.2 3B model (~2 GB). It only downloads once; after that it is cached locally.
    ollama pull llama3.2
    This takes 2–5 minutes on a typical broadband connection. You will see a progress bar. Do not close the terminal while it is running.
  3. Pull the embedding model. This downloads nomic-embed-text v1.5 (~274 MB), which converts text chunks into vectors.
    ollama pull nomic-embed-text
  4. Verify both models are available:
    ollama list
    Expected output (dates will differ):
    NAME ID SIZE MODIFIED llama3.2:latest a80c4f17acd5 2.0 GB 2 minutes ago nomic-embed-text:latest 0a109f422b47 274 MB 1 minute ago
  5. Create your project folder and a Python virtual environment.
    mkdir rag-chatbot cd rag-chatbot python -m venv .venv
    Then activate it:
    # Mac / Linux: source .venv/bin/activate # Windows (Command Prompt): .venv\Scripts\activate.bat # Windows (PowerShell): .venv\Scripts\Activate.ps1
    You will see (.venv) at the start of your prompt when it is active.
  6. Install all Python dependencies.
    pip install langchain==1.3.10 \ langchain-ollama==1.1.0 \ langchain-chroma==1.1.0 \ langchain-text-splitters==1.1.2 \ langchain-community==0.4.2 \ pypdf==6.13.3
    Why so many langchain packages? LangChain split its codebase into separate integration packages in 2024. langchain is the core; langchain-ollama wires in local models; langchain-chroma wires in the vector store; langchain-text-splitters handles chunking; langchain-community provides the document loaders. Installing one big package like "langchain" alone will give you ImportErrors for all the integrations.
  7. Add your documents. Create a docs/ folder inside rag-chatbot/ and put at least one file in it. PDFs, plain text files (.txt), and markdown files (.md) all work.
    mkdir docs # then copy at least one .pdf, .txt, or .md file into docs/
    Example: copy a company policy PDF, a research paper, or even a plain text file with a few paragraphs of unique facts. The chatbot will only be able to answer questions about what is in these files.
  8. Your project folder should look like this:
    rag-chatbot/ .venv/ docs/ my_document.pdf (scripts will be created in later phases)
Ollama command not found after installing?
  • On Mac: Ollama installs to /usr/local/bin/ollama. If it is not found, open a new terminal window — the PATH may not have refreshed yet.
  • On Windows: reboot after installing. The installer adds Ollama to PATH but Windows needs a restart to pick it up in some shells.
  • On Linux: the install script places the binary in /usr/local/bin. Run which ollama to confirm. If the Ollama service is not running, start it with ollama serve in a separate terminal.
Checkpoint — what you should see
ollama list shows both llama3.2:latest and nomic-embed-text:latest. Your virtual environment is activated (you see (.venv) in the prompt). Running python -c "import langchain, langchain_ollama, langchain_chroma; print('OK')" prints OK without errors. The docs/ folder contains at least one file.

Document Loading & Chunking
Load all documents from the docs/ folder using LangChain's loaders, then split the text into retrieval-sized chunks. This script is the ingestion pipeline — run it once and it populates the vector store.
  1. Create ingest.py in your rag-chatbot/ folder and paste this complete script:
    """ ingest.py -- Load documents, split into chunks, embed, and store in Chroma. Run this once before using chat.py. Re-run any time you add new docs. """ import os from pathlib import Path # ── Document loaders (langchain-community 0.4.2) ────────────────────────── from langchain_community.document_loaders import PyPDFLoader, TextLoader, DirectoryLoader # ── Text splitter (langchain-text-splitters 1.1.2) ───────────────────────── from langchain_text_splitters import RecursiveCharacterTextSplitter # ── Embeddings via local Ollama (langchain-ollama 1.1.0) ─────────────────── from langchain_ollama import OllamaEmbeddings # ── Chroma vector store (langchain-chroma 1.1.0) ─────────────────────────── from langchain_chroma import Chroma # ── Configuration ─────────────────────────────────────────────────────────── DOCS_DIR = "./docs" # folder containing your documents CHROMA_DIR = "./chroma_db" # where the vector index is persisted EMBED_MODEL = "nomic-embed-text" # must be pulled: ollama pull nomic-embed-text CHUNK_SIZE = 512 # characters per chunk (not tokens) CHUNK_OVERLAP = 64 # overlap keeps context across chunk boundaries def load_documents(docs_dir: str) -> list: """Load PDF, TXT, and MD files from the given directory.""" docs_path = Path(docs_dir) if not docs_path.exists(): raise FileNotFoundError(f"Docs folder not found: {docs_dir}") all_docs = [] # Load PDFs page-by-page. Each page becomes one Document object. for pdf_file in docs_path.glob("*.pdf"): print(f" Loading PDF: {pdf_file.name}") loader = PyPDFLoader(str(pdf_file)) all_docs.extend(loader.load()) # Load plain text and markdown files. for ext in ("*.txt", "*.md"): for txt_file in docs_path.glob(ext): print(f" Loading text: {txt_file.name}") loader = TextLoader(str(txt_file), encoding="utf-8") all_docs.extend(loader.load()) return all_docs def main(): print("=== RAG Ingest Pipeline ===\n") # Step 1: Load raw documents. print("[1/3] Loading documents...") raw_docs = load_documents(DOCS_DIR) if not raw_docs: raise RuntimeError( f"No documents loaded from {DOCS_DIR}. " "Add at least one .pdf, .txt, or .md file to the docs/ folder." ) print(f" Loaded {len(raw_docs)} page(s) / section(s).\n") # Step 2: Split into chunks. # RecursiveCharacterTextSplitter tries to split on paragraphs, then # sentences, then words -- preserving semantic boundaries as much as # possible given the chunk_size constraint. print("[2/3] Splitting into chunks...") splitter = RecursiveCharacterTextSplitter( chunk_size=CHUNK_SIZE, chunk_overlap=CHUNK_OVERLAP, add_start_index=True, # adds 'start_index' to metadata for debugging ) chunks = splitter.split_documents(raw_docs) print(f" Created {len(chunks)} chunks " f"(avg ~{sum(len(c.page_content) for c in chunks)//len(chunks)} chars each).\n") # Step 3: Embed chunks and write to Chroma. # OllamaEmbeddings calls the local Ollama server at localhost:11434. # Chroma.from_documents embeds every chunk and persists the index to disk. print("[3/3] Embedding and writing to Chroma (this may take a minute)...") embeddings = OllamaEmbeddings(model=EMBED_MODEL) vectorstore = Chroma.from_documents( documents=chunks, embedding=embeddings, persist_directory=CHROMA_DIR, collection_name="rag_docs", ) print(f" Done. {len(chunks)} vectors stored in {CHROMA_DIR}/\n") # Quick sanity check: retrieve the top result for a generic query. print("[check] Running a test similarity search...") test_results = vectorstore.similarity_search("what is this document about", k=1) if test_results: preview = test_results[0].page_content[:120].replace("\n", " ") print(f" Top result preview: \"{preview}...\"") print("\nIngest complete. Run chat.py to start the chatbot.") if __name__ == "__main__": main()
  2. Run it:
    python ingest.py
    Expected output (numbers depend on your documents):
    === RAG Ingest Pipeline === [1/3] Loading documents... Loading PDF: employee_handbook.pdf Loaded 42 page(s) / section(s). [2/3] Splitting into chunks... Created 187 chunks (avg ~318 chars each). [3/3] Embedding and writing to Chroma (this may take a minute)... Done. 187 vectors stored in ./chroma_db/ [check] Running a test similarity search... Top result preview: "Section 3 - Remote Work Policy: Employees may work remotely up to..." Ingest complete. Run chat.py to start the chatbot.
  3. Confirm the Chroma directory was created:
    ls chroma_db/
    You should see files including chroma.sqlite3. This is your persisted vector index.
ConnectionError: ollama server not running? The OllamaEmbeddings call in step 3 hits http://localhost:11434. If you see a connection error:
  • On Mac/Windows: open the Ollama desktop app or check the system tray icon — the server must be running before you call the Python API.
  • On Linux: run ollama serve in a separate terminal (keep it open), then re-run ingest.py.
  • Confirm the server is up: curl http://localhost:11434 should print Ollama is running.
PyPDFLoader ImportError or "No module named pypdf"?
  • Make sure your virtual environment is active (you see (.venv) in the prompt) before running pip install or the script.
  • Re-run: pip install pypdf==6.13.3
  • If you see from langchain.document_loaders import PyPDFLoader in an old tutorial online, that is the old import path. The correct current path is from langchain_community.document_loaders import PyPDFLoader.
Checkpoint — what you should see
The script prints all three numbered steps and exits cleanly. The chroma_db/ folder now exists and contains chroma.sqlite3. The test similarity search returns a preview of real text from your document — if it does, you know embeddings are being generated correctly and the vector index is populated.

Build the RAG Chain
Wire the Chroma retriever to the local LLM using LangChain's LCEL pipe operator. This produces a chain that takes a question, fetches the top-4 relevant chunks, and passes them as context to llama3.2 before generating an answer.
  1. Create chain.py in your rag-chatbot/ folder and paste this complete module:
    """ chain.py -- Builds and returns the RAG chain. Imported by chat.py. Not meant to be run directly. """ # ── LangChain core (langchain 1.3.10) ────────────────────────────────────── from langchain_core.prompts import ChatPromptTemplate from langchain_core.output_parsers import StrOutputParser from langchain_core.runnables import RunnablePassthrough # ── Local LLM via Ollama (langchain-ollama 1.1.0) ────────────────────────── from langchain_ollama import ChatOllama # ── Embeddings via Ollama (langchain-ollama 1.1.0) ───────────────────────── from langchain_ollama import OllamaEmbeddings # ── Chroma vector store (langchain-chroma 1.1.0) ─────────────────────────── from langchain_chroma import Chroma # ── Configuration ─────────────────────────────────────────────────────────── CHROMA_DIR = "./chroma_db" LLM_MODEL = "llama3.2" # must be pulled: ollama pull llama3.2 EMBED_MODEL = "nomic-embed-text" # must match what was used in ingest.py TOP_K = 4 # number of chunks to retrieve per query # ── Prompt template ───────────────────────────────────────────────────────── # The system message instructs the LLM to stay grounded in the context. # {context} is filled by the retriever; {question} is the user's query. RAG_PROMPT = ChatPromptTemplate.from_messages([ ("system", "You are a helpful assistant that answers questions using only the " "context provided below. If the answer is not in the context, say " "\"I don't know based on the provided documents\" -- do not make up " "information.\n\nContext:\n{context}"), ("human", "{question}"), ]) def format_docs(docs: list) -> str: """Concatenate retrieved chunks into a single context string.""" return "\n\n---\n\n".join(doc.page_content for doc in docs) def build_chain(): """ Construct and return the RAG chain. Chain shape (LCEL pipe operator): retriever --> format_docs --> prompt --> llm --> str parser The RunnablePassthrough keeps the original question available for the prompt. """ # Load the persisted Chroma index (must have been created by ingest.py). embeddings = OllamaEmbeddings(model=EMBED_MODEL) vectorstore = Chroma( persist_directory=CHROMA_DIR, embedding_function=embeddings, collection_name="rag_docs", ) # as_retriever() wraps Chroma so it returns Document objects on .invoke(). retriever = vectorstore.as_retriever(search_kwargs={"k": TOP_K}) # LLM: ChatOllama is the current class for chat models in langchain-ollama. # temperature=0.2 keeps answers factual; higher values allow more creativity. llm = ChatOllama(model=LLM_MODEL, temperature=0.2) # LCEL chain: assign retriever output to "context", pass question through, # then run prompt -> llm -> string parser. rag_chain = ( { "context": retriever | format_docs, "question": RunnablePassthrough(), } | RAG_PROMPT | llm | StrOutputParser() ) return rag_chain, retriever
  2. Test the chain in isolation to confirm retrieval works before adding the chat loop. Save this as test_chain.py in your rag-chatbot/ project folder:
    from chain import build_chain rag_chain, retriever = build_chain() # Test retrieval directly (no LLM call yet). test_query = "what is this document about" results = retriever.invoke(test_query) print(f"Retrieved {len(results)} chunk(s) for: '{test_query}'") for i, doc in enumerate(results, 1): src = doc.metadata.get("source", "unknown") print(f" [{i}] {src} -- {doc.page_content[:80].strip()}...")
  3. Run the test:
    python test_chain.py
    Expected output (content will reflect your actual documents):
    Retrieved 4 chunk(s) for: 'what is this document about' [1] docs/employee_handbook.pdf -- Section 1 - Introduction: This handbook outlines... [2] docs/employee_handbook.pdf -- Section 3 - Remote Work Policy: Employees may... [3] docs/employee_handbook.pdf -- Section 7 - Benefits: Full-time employees are... [4] docs/employee_handbook.pdf -- Section 2 - Code of Conduct: All staff are...
Chroma directory not found error?
  • You must run python ingest.py (Phase 2) before chain.py or anything that loads Chroma. The chroma_db/ directory must exist with data in it.
  • If you moved the project folder, Chroma's persist_directory path must still resolve correctly. Use an absolute path if needed: CHROMA_DIR = "/full/path/to/rag-chatbot/chroma_db"
Embedding dimension mismatch error from Chroma? This happens when ingest.py used one embedding model and chain.py uses a different one. nomic-embed-text produces 768-dimensional vectors; if you accidentally ran ingest with a different model, delete chroma_db/ and re-run ingest.
  • Delete and rebuild: rm -rf chroma_db && python ingest.py
  • Both scripts must use the same EMBED_MODEL value.
Checkpoint — what you should see
python test_chain.py prints exactly 4 chunks. Each chunk shows the source filename and a short text preview pulled from your actual document. If the preview text contains real sentences from your file, the retrieval pipeline is working end-to-end. The LLM has not been called yet — that is Phase 4's job.

Interactive Chat Loop
Wrap the RAG chain in a terminal chat loop. Each query retrieves chunks, sends them to llama3.2, and prints the grounded answer alongside the source excerpts so you can see exactly which parts of your documents drove the response.
  1. Create chat.py in your rag-chatbot/ folder and paste this complete script:
    """ chat.py -- Interactive RAG chatbot terminal loop. Usage: python chat.py Commands inside the loop: /sources -- show raw retrieved chunks for the last query /quit -- exit """ from chain import build_chain def print_banner(): print("\n" + "="*60) print(" RAG Chatbot (powered by llama3.2 + nomic-embed-text)") print(" Your documents are the only source of truth.") print(" Commands: /sources /quit") print("="*60 + "\n") def main(): print("Loading RAG chain (connecting to Ollama)...") rag_chain, retriever = build_chain() print("Ready.\n") print_banner() # Store the last retrieved chunks so /sources can display them. last_sources = [] while True: try: query = input("You: ").strip() except (KeyboardInterrupt, EOFError): print("\nExiting.") break if not query: continue # ── Built-in commands ─────────────────────────────────────────────── if query == "/quit": print("Goodbye.") break if query == "/sources": if not last_sources: print(" (no previous query -- ask a question first)\n") else: print(f"\n Retrieved {len(last_sources)} source chunk(s):\n") for i, doc in enumerate(last_sources, 1): src = doc.metadata.get("source", "unknown") page = doc.metadata.get("page", "") page_str = f" p.{page}" if page != "" else "" print(f" [{i}] {src}{page_str}") print(f" {doc.page_content[:200].strip()}...") print() continue # ── RAG query ─────────────────────────────────────────────────────── # Retrieve chunks separately so we can show them via /sources. last_sources = retriever.invoke(query) # Invoke the full chain: retriever -> prompt -> LLM -> string. print("\nBot: ", end="", flush=True) answer = rag_chain.invoke(query) print(answer) # Print a compact source summary after every answer. source_names = list(dict.fromkeys( doc.metadata.get("source", "unknown") for doc in last_sources )) print(f"\n Sources: {', '.join(source_names)}") print(f" (type /sources to see full chunk text)\n") if __name__ == "__main__": main()
  2. Run the chatbot:
    python chat.py
    It will print "Loading RAG chain..." then "Ready." then the banner. The first LLM call takes 3–10 seconds as llama3.2 loads into memory; subsequent calls are faster.
  3. Ask a question that IS answered in your document. For example, if you indexed an employee handbook:
    You: how many days of PTO do full-time employees get?
    The bot will return an answer citing text that exists only in your document, not from the LLM's general training.
  4. Ask a question that is NOT in your document to test the grounding guard:
    You: what is the capital of France?
    Expected behaviour: the bot says it does not know based on the provided documents, instead of answering from its training data.
  5. Type /sources to inspect the raw chunks that drove the last answer:
    You: /sources
    You will see the 4 retrieved chunks, their source filenames, page numbers (for PDFs), and the first 200 characters of each chunk.
The bot answers questions about France even though that is not in my document? ChatOllama's temperature and the grounding prompt do most of the work, but local models sometimes "leak" training knowledge. Tighten the system prompt in chain.py: add "Do not use any knowledge from your training data" to the system message. You can also lower temperature to 0.0 for more literal retrieval-only answers.
Answers are cut off or the model seems to loop?
  • llama3.2's default context window is 2048 tokens. If your 4 retrieved chunks are very long and the question is also long, the total may overflow. Reduce TOP_K to 2 or reduce CHUNK_SIZE in ingest.py (then re-run ingest).
  • Set num_predict=512 in the ChatOllama constructor to cap response length: ChatOllama(model=LLM_MODEL, temperature=0.2, num_predict=512).
Checkpoint — what you should see
The chatbot answers a question using a fact that exists only in your indexed document. When asked something not in the document, it says it does not know rather than hallucinating. Typing /sources shows the 4 raw text chunks that the retriever pulled, with source filenames and previews. That source grounding is the core behaviour of RAG — when you see it working, the pipeline is complete.
Optional: Use OpenAI instead of Ollama (requires an API key + costs money)
If you prefer cloud-hosted generation, install pip install langchain-openai==0.3.18 and set your key: export OPENAI_API_KEY=sk-...
Then in chain.py, replace the two Ollama imports with:

from langchain_openai import ChatOpenAI, OpenAIEmbeddings

And replace the instantiation lines:

embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0.2)

You must also re-run ingest.py with the same change so the stored vectors match the embedding model. text-embedding-3-small produces 1536-dimensional vectors, different from nomic-embed-text's 768 — mixing them will cause a dimension mismatch error in Chroma. Delete chroma_db/ before re-ingesting.

Live Re-Ingestion & Relevance Tuning
Add new documents to the running chatbot without restarting, and tune chunk size and overlap to see how they affect answer quality. This phase develops the intuition to diagnose and fix a bad RAG pipeline.
  1. Add a second document to your docs/ folder — a different PDF or a plain text file with distinct content. Then re-run ingest to rebuild the index:
    python ingest.py
    Re-running ingest always rebuilds from scratch. Chroma.from_documents creates a new collection. If you want to add documents incrementally without rebuilding, use vectorstore.add_documents(new_chunks) instead. For this project, full rebuild is the simplest approach.
  2. Test cross-document retrieval. Start chat.py again and ask a question that requires information from both documents. Then type /sources to confirm chunks from both files appear in the retrieval set.
    python chat.py
  3. Experiment with chunk size. Open ingest.py and change CHUNK_SIZE from 512 to 256. Delete chroma_db/ and re-run ingest:
    rm -rf chroma_db python ingest.py
    Now ask the same question in chat.py. Smaller chunks mean the retriever returns more focused snippets but may miss context that spanned the chunk boundary. Note whether the answer quality improves or degrades for your specific documents.
  4. Experiment with TOP_K. In chain.py, change TOP_K from 4 to 8. Restart chat.py and ask a multi-part question. More chunks give the LLM more context but also more noise — watch whether the answer becomes more complete or more confused.
  5. Write a score sheet. In your terminal, run a series of 5 questions and note for each whether the answer was: correct and grounded, correct but general (LLM leaked training data), or incorrect. This is informal retrieval evaluation — the starting point for measuring RAG quality in production systems.
    # Example score sheet format (paste into a notes file): # Q1: "what is the vacation accrual rate?" # Answer grounded: YES | Source cited: YES | Score: PASS # Q2: "what is the speed of light?" # Answer grounded: NO | Model replied "I don't know": YES | Score: PASS # Q3: "summarize section 7" # Answer grounded: YES | Source cited: YES | Score: PASS
After changing CHUNK_SIZE, old answers are still showing up? Chroma caches the existing collection. If you change chunk size or the embedding model, you must delete chroma_db/ entirely before re-ingesting — otherwise old vectors from the previous run mix with the new ones.
  • Mac/Linux: rm -rf chroma_db
  • Windows: rmdir /s /q chroma_db
Retrieval returns irrelevant chunks for short questions? Short one-word queries often match poorly because the embedding vector has little signal. Try rephrasing as a full sentence: instead of "PTO" ask "how many days of paid time off do employees receive?" Retrieval quality is strongly tied to query length and phrasing.
Checkpoint — what you should see
After adding a second document and re-ingesting, a question about the new document returns chunks from that file (visible via /sources). A question spanning both documents returns chunks from both source files. Your informal score sheet shows at least 4 out of 5 questions returning grounded answers. When chunk size is halved, the ingest script reports roughly twice as many chunks in the output line Created N chunks — confirming the split setting took effect.
