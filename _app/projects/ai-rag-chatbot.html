Subject

Build a RAG Chatbot

Operative 120 min 600 XP
Mission Brief

This operation tasks you with building a Retrieval-Augmented Generation chatbot that answers questions grounded in your own documents rather than relying on the LLM's pre-trained knowledge alone. Feed it PDFs, markdown files, or plain text — the bot will index every document into a vector store, retrieve the most relevant chunks at query time, and inject them as context into the language model's prompt before generating a response. The result: answers that cite your data, not hallucinated guesses.

The pipeline is orchestrated through LangChain, using its document loaders to ingest files, RecursiveCharacterTextSplitter to chunk them into retrieval-friendly segments with configurable overlap, and OpenAIEmbeddings (or a local alternative) to convert each chunk into a high-dimensional vector. Those vectors are persisted in ChromaDB, a lightweight local vector database that supports similarity search out of the box.

At query time, the user's question is embedded into the same vector space, the top-k most similar chunks are retrieved, and a RetrievalQA chain sends the assembled prompt to the LLM. The finished chatbot runs in the terminal as an interactive loop — ask a question, get a sourced answer, repeat. Along the way you will learn how embedding models work, why chunk size and overlap matter, and how to evaluate retrieval quality with relevance scoring.

Agent Requirements
  • Python fundamentals — functions, classes, file I/O, and package management with pip
  • Basic understanding of APIs — sending requests, handling JSON responses, and API keys
  • Familiarity with the command line for running scripts and managing virtual environments
  • Conceptual understanding of what a language model does (input text in, generated text out)
  • No prior experience with LangChain, vector databases, or embeddings required — the project teaches these from scratch
Operation Phases
Progress
0 / 5
✓
1
Document Ingestion
Set up a LangChain document loader pipeline that accepts PDF, plain text, and markdown files from a local directory. Use PyPDFLoader for PDFs and TextLoader for raw text. Each loader returns a list of Document objects containing the page content and metadata (filename, page number). Normalize all loaded documents into a unified list for downstream processing, handling encoding edge cases and empty pages gracefully.
Checkpoint: Document Ingestion
  • Load at least 3 documents (mix of PDF, TXT, and MD) and verify len(documents) shows all pages loaded
  • Check that each Document object has populated metadata with filename and page number
  • Verify no empty documents by checking all(len(doc.page_content) > 0 for doc in documents)
✓
2
Text Splitting & Chunking
Apply RecursiveCharacterTextSplitter to break documents into retrieval-sized chunks. Configure chunk_size (target 512 tokens) and chunk_overlap (50 tokens) to balance context preservation with retrieval granularity. Experiment with different splitter strategies — character-based vs. token-based — and measure how chunk size affects downstream answer quality. Log chunk counts and average lengths for each ingested document to build intuition about the splitting process.
✓
3
Embedding & Vector Store
Initialize an embedding model using OpenAIEmbeddings (or the local HuggingFaceEmbeddings alternative for offline work) and embed every chunk into a 1536-dimensional vector. Store the resulting vectors in ChromaDB using Chroma.from_documents() with persistent storage so the index survives across sessions. Verify the store by running a raw similarity search with similarity_search_with_score() and inspecting the returned documents and cosine distances.
Checkpoint: Embedding and Vector Store
  • Verify ChromaDB persistent storage directory is created and contains index files
  • Run a test query with similarity_search_with_score("test query", k=3) and confirm 3 results are returned
  • Check that cosine distances are between 0.0 and 2.0 — values near 0 indicate high similarity
✓
4
Retrieval Chain Assembly
Build a RetrievalQA chain by connecting the ChromaDB retriever (configured with search_kwargs={"k": 4}) to an LLM instance. Craft a custom prompt template that instructs the model to answer only from the provided context and to say "I don't know" when the documents lack the answer. Set temperature=0.2 to keep responses factual. Test the chain with a suite of questions — some answerable from the documents, some intentionally unanswerable — to validate grounding behavior.
✓
5
Interactive Chat Loop
Wrap the retrieval chain in a terminal-based interactive loop using Python's input(). Each user query is passed through the chain, and the response is printed alongside the source document names and chunk excerpts for transparency. Add a /sources command that displays the raw retrieved chunks with their similarity scores. Implement conversation memory using ConversationBufferMemory so follow-up questions have context. Include a /ingest command to add new documents to the vector store without restarting the session.
Checkpoint: Interactive Chat Loop
  • Ask a question answerable from the documents and verify the response cites correct source material
  • Ask an unanswerable question and confirm the model responds with "I don't know" instead of hallucinating
  • Run /sources command and verify raw chunk text and similarity scores are displayed
  • Test follow-up questions to confirm ConversationBufferMemory maintains context across turns
