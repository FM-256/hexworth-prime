Subject

Build a Threat Classification Bot

Operative 90 min 500 XP
Mission Brief

Your mission is to build a supervised machine learning classifier that reads raw security alert text and labels each one as either threat or benign. You will generate a realistic synthetic dataset of 2,000 labeled alerts — no download required, no account needed — then transform each alert into numbers using TF-IDF vectorization (term frequency-inverse document frequency), which measures how distinctive each word is across the corpus.

Two classifiers compete head-to-head: a Logistic Regression baseline (fast, interpretable, coefficient weights you can read) and a Random Forest ensemble (more powerful, feature-importance scores). You will evaluate both using precision, recall, F1-score, a confusion matrix, and ROC-AUC — the metrics that actually matter when false negatives mean a missed attack. The final phase reveals which words push the model toward "threat" by inspecting the top TF-IDF coefficients from Logistic Regression.

Everything runs in a single Python file with no external dataset URL. The synthetic data is seeded for reproducibility, so your numbers will match the checkpoints exactly.

Agent Requirements
  • Python 3.11 or higher — check with python --version or python3 --version
  • pip packages: scikit-learn 1.9.0, pandas 3.0.3, numpy 2.4.6 (Phase 1 gives exact install command)
  • Basic Python: variables, loops, functions, lists — no prior machine learning or data science experience required
  • Understanding that classification means sorting inputs into labeled categories — threat vs. benign in this case
  • No external dataset download, no API keys, no account creation — all data is generated in-script from a fixed random seed

Dataset Generation and Train/Test Split
Build a self-contained synthetic dataset of 2,000 security alerts using random.seed(42) for reproducibility. Threat alerts are seeded with vocabulary pulled from real alert taxonomy; benign alerts use neutral system-log language. Split with stratification so both halves have the same class ratio.

TF-IDF Vectorization and Model Training
Transform alert text into numbers with TfidfVectorizer, then train two classifiers: LogisticRegression (interpretable baseline) and RandomForestClassifier (ensemble). The critical rule: fit the vectorizer on training data only, then use transform (not fit_transform) on the test set.
  1. Open train.py and append this block below your Phase 2 code (keep everything from Phase 2 intact — just add what follows):
    from sklearn.feature_extraction.text import TfidfVectorizer from sklearn.linear_model import LogisticRegression from sklearn.ensemble import RandomForestClassifier # ── TF-IDF vectorization ────────────────────────────────── # CRITICAL: fit ONLY on training data. # Fitting on test data would leak future information into the model. # max_features=2000 keeps the feature space manageable for a beginner machine. vectorizer = TfidfVectorizer( max_features=2000, ngram_range=(1, 2), # unigrams + bigrams (e.g. "lateral movement" as one token) sublinear_tf=True, # apply log(1+tf) to compress high-frequency terms strip_accents="unicode", lowercase=True, ) # fit_transform on train: learns vocabulary AND transforms in one step. X_train_tfidf = vectorizer.fit_transform(X_train) # transform on test: uses the ALREADY-FITTED vocabulary -- no new learning. X_test_tfidf = vectorizer.transform(X_test) print(f"Feature matrix shape (train): {X_train_tfidf.shape}") # Expected: (1600, 2000) -- 1600 docs, up to 2000 TF-IDF features # ── Logistic Regression baseline ───────────────────────── # class_weight='balanced' compensates when one class dominates. # max_iter=1000 prevents convergence warnings on small datasets. lr_clf = LogisticRegression( class_weight="balanced", max_iter=1000, random_state=42, ) lr_clf.fit(X_train_tfidf, y_train) print("Logistic Regression trained.") # ── Random Forest ───────────────────────────────────────── # n_estimators=200: 200 independent decision trees, majority vote predicts. # class_weight='balanced': each tree sees reweighted class samples. rf_clf = RandomForestClassifier( n_estimators=200, class_weight="balanced", random_state=42, n_jobs=-1, # use all CPU cores for parallel tree training ) rf_clf.fit(X_train_tfidf, y_train) print("Random Forest trained.")
  2. Run train.py again (it now runs all code top-to-bottom):
    python train.py
    You should see the split output from Phase 2 plus:
    Feature matrix shape (train): (1600, 2000) Logistic Regression trained. Random Forest trained.
Common traps at this phase:
  • Using fit_transform on the test set is a data-leakage bug. The vectorizer would learn word frequencies from test data, making evaluation falsely optimistic. Always: fit_transform on train, transform only on test.
  • ConvergenceWarning from LogisticRegression? Raise max_iter to 2000. The warning appears when the solver has not fully converged — the model still works but may be slightly sub-optimal.
  • Very slow Random Forest? Drop n_estimators to 100 for faster runs during development. The checkpoint numbers will be similar.
Checkpoint — what you should see
The feature matrix shape is (1600, 2000) — 1,600 training rows and up to 2,000 TF-IDF columns. Both "trained." lines print without error. If the shape shows fewer than 2000 columns (e.g. (1600, 847)), the dataset has fewer unique tokens than the limit — that is fine, it just means max_features was not the binding constraint.

Evaluation: Precision, Recall, F1, Confusion Matrix, ROC-AUC
Accuracy alone is misleading when security stakes are unequal — missing a real threat (false negative) is far worse than flagging a benign alert (false positive). Precision, recall, F1, and ROC-AUC all capture this nuance. Generate all five metrics for both classifiers and print a terminal confusion matrix.
  1. Append this evaluation block to train.py after the Phase 3 code:
    from sklearn.metrics import ( classification_report, confusion_matrix, roc_auc_score, ) def evaluate(name, clf, X_test_vec, y_test): """Print a full evaluation report for one classifier.""" y_pred = clf.predict(X_test_vec) y_prob = clf.predict_proba(X_test_vec)[:, 1] # P(threat) print(f"\n{'='*52}") print(f" {name}") print(f"{'='*52}") # classification_report prints per-class precision, recall, F1 # and macro/weighted averages. print(classification_report(y_test, y_pred, target_names=["benign", "threat"])) # ROC-AUC: 1.0 = perfect, 0.5 = random guess. auc = roc_auc_score(y_test, y_prob) print(f" ROC-AUC : {auc:.4f}") # Confusion matrix: rows = actual class, cols = predicted class. cm = confusion_matrix(y_test, y_pred) tn, fp, fn, tp = cm.ravel() print(f"\n Confusion matrix (actual vs predicted):") print(f" Pred benign Pred threat") print(f" Act benign {tn:>10} {fp:>10}") print(f" Act threat {fn:>10} {tp:>10}") print(f"\n TN={tn} FP={fp} FN={fn} TP={tp}") print(f" False negative rate: {fn/(fn+tp):.3f} (missed threats)") print(f" False positive rate: {fp/(fp+tn):.3f} (wasted triage)") # Evaluate both classifiers on the held-out test set. evaluate("Logistic Regression", lr_clf, X_test_tfidf, y_test) evaluate("Random Forest", rf_clf, X_test_tfidf, y_test)
  2. Run train.py:
    python train.py
    The evaluation block prints two full reports. Your exact numbers will vary — the figures below show the approximate shape to expect; exact values depend on scikit-learn version and platform:
    ==================================================== Logistic Regression ==================================================== precision recall f1-score support benign ~0.97 ~0.99 ~0.98 340 threat ~0.92 ~0.83 ~0.87 60 accuracy ~0.97 400 macro avg ~0.94 ~0.91 ~0.93 400 weighted avg ~0.97 ~0.97 ~0.97 400 ROC-AUC : ~0.99 Confusion matrix (actual vs predicted): Pred benign Pred threat Act benign ~336 ~4 Act threat ~10 ~50 False negative rate: ~0.17 (missed threats) False positive rate: ~0.01 (wasted triage) ==================================================== Random Forest ==================================================== precision recall f1-score support benign ~0.97 ~0.99 ~0.98 340 threat ~0.93 ~0.82 ~0.87 60 accuracy ~0.97 400 macro avg ~0.95 ~0.91 ~0.93 400 weighted avg ~0.97 ~0.97 ~0.97 400 ROC-AUC : ~0.99
    Notice the imbalance effect: overall accuracy looks high (~0.97) because 85% of alerts are benign and the model learns to lean that way. But the threat F1 (~0.85–0.90) and false negative rate (~0.15–0.20) tell a different story — roughly 1 in 6 real threats may be missed. This is exactly why F1 per class and ROC-AUC are the right metrics for security classifiers, not accuracy alone. class_weight="balanced" counteracts this bias during training; without it, threat recall would be even lower.
  3. Read the confusion matrix. In the Logistic Regression output, the FN cell (Act threat / Pred benign) shows real threats that slipped through — these would go uninvestigated in a real SOC. The FP cell (Act benign / Pred threat) shows wasted analyst triage time. Because threats are the minority class (15% of the dataset), even a small absolute FN count translates to a meaningful false-negative rate. This is the core reason class_weight="balanced" exists.
Why not just report accuracy? Accuracy = correct predictions / total. If 95% of alerts were benign in a real dataset, a model that always predicts "benign" would score 95% accuracy while catching zero threats. F1 and ROC-AUC penalize this behavior. Always report F1 per class for imbalanced problems.

Feature Inspection: Which Words Signal a Threat?
Logistic Regression assigns a coefficient weight to every TF-IDF feature. Positive coefficients push toward "threat"; negative push toward "benign". Inspect the top 20 in each direction to verify the model learned real threat vocabulary, not noise. Then predict a new alert live from the command line.
  1. Append this final block to train.py after the Phase 4 code:
    import numpy as np # ── Top threat-signal features (Logistic Regression) ───── # LogisticRegression stores coef_ as shape (1, n_features) for binary # problems -- one row representing the positive class (threat=1). # .flatten() converts that (1, n_features) matrix to a plain 1-D array # so argsort() and indexing work as expected on a single coefficient list. coefs = lr_clf.coef_.flatten() feature_names = vectorizer.get_feature_names_out() # Top 20 features pointing toward THREAT (highest positive coef) top_threat_idx = np.argsort(coefs)[-20:][::-1] # Top 20 features pointing toward BENIGN (most negative coef) top_benign_idx = np.argsort(coefs)[:20] print("\n" + "="*52) print(" TOP 20 THREAT TOKENS (Logistic Regression coefs)") print("="*52) for idx in top_threat_idx: print(f" {feature_names[idx]:<30} {coefs[idx]:+.4f}") print("\n" + "="*52) print(" TOP 20 BENIGN TOKENS") print("="*52) for idx in top_benign_idx: print(f" {feature_names[idx]:<30} {coefs[idx]:+.4f}") # ── Live prediction on a new alert ─────────────────────── # Pass any raw string through the fitted vectorizer + classifier. def predict_alert(text, vectorizer, clf, clf_name): """Predict threat or benign for a single new alert string.""" vec = vectorizer.transform([text]) # transform (NOT fit_transform) pred = clf.predict(vec)[0] prob = clf.predict_proba(vec)[0] label = "THREAT" if pred == 1 else "benign" print(f"\n [{clf_name}]") print(f" Alert : {text}") print(f" Label : {label} (P(threat)={prob[1]:.3f} P(benign)={prob[0]:.3f})") print("\n" + "="*52) print(" LIVE PREDICTIONS") print("="*52) TEST_ALERTS = [ "ransomware detected on host WIN-DC01", "c2 beacon to 198.51.100.7 on port 4444", "scheduled backup completed on LINUX-WEB02", "user jsmith logged in from 10.0.0.14", "powershell obfuscation on MAC-DEV05", "antivirus definitions updated on WIN-SRV08", ] for alert in TEST_ALERTS: predict_alert(alert, vectorizer, lr_clf, "LogReg") predict_alert(alert, vectorizer, rf_clf, "RF ")
  2. Run the complete script one final time:

  3. Read the top-token table. You should see terms like ransomware, c2 beacon, lateral movement, credential dump at the top of the threat list — the actual attack vocabulary from the dataset. The benign list should show terms like backup completed, definitions updated, patch applied. This is the interpretability payoff: you can show a stakeholder why the model made a decision.
  4. Try your own alert. Add this line at the bottom of train.py and re-run to predict any text you write:
    predict_alert("suspicious outbound dns tunnel detected on WIN-DC01", vectorizer, lr_clf, "LogReg")
The top-threat token list shows generic words instead of attack terms? This happens if the dataset shuffle put too many benign samples in the vocabulary. If you modified the phrase lists, your vocabulary will differ from the expected terms — that is expected.
