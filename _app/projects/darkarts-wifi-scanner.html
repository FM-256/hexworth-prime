Subject

Build a WiFi Recon Scanner

Operative 90 min 500 XP
Authorization Requirement — Read Before Building

This project builds a passive WiFi reconnaissance tool. WiFi access points continuously broadcast beacon frames to announce their presence — this is how your phone discovers nearby networks. Observing those public broadcasts is legal, like reading the signs on shop fronts. This scanner listens to those public beacon frames. It does not connect to, authenticate with, transmit to, or interfere with any network.

This project does not cover and you must not implement: deauthentication attacks, beacon flooding, evil-twin access points, packet injection, WPS cracking, or handshake capture for offline cracking. Connecting to or interfering with wireless networks you do not own is illegal under the Computer Fraud and Abuse Act, the Electronic Communications Privacy Act (United States), and equivalent laws in most countries. Use this scanner only for your own site surveys, network inventory, and defensive RF assessment — understanding what your environment looks like to an attacker.

This is the same passive recon pattern used by wireless security auditors performing authorized site surveys. The skill is learning to read the RF environment, not attack it.

Mission Brief

This operation turns an ESP32-2432S028R — the "Cheap Yellow Display" (CYD), a ~$10–15 board that packages an ESP32 microcontroller, a 2.8-inch 240×320 ILI9341 TFT display, and an XPT2046 resistive touchscreen into a single unit — into a handheld WiFi reconnaissance scanner. The finished device fits in your palm and needs no laptop attached to operate.

The scanner lists every 2.4 GHz network it can hear, sorted by signal strength. Each entry shows the SSID, RSSI value with color-coded animated signal bars, channel number, and encryption type (Open / WPA / WPA2 / WPA3 / WEP). A channel distribution view reveals congestion at a glance. Tap the screen to trigger a fresh scan at any time. The build requires the physical ESP32-2432S028R board — there is no faithful desktop simulator for real RF scanning. The board is available from AliExpress and Amazon; search "ESP32 Cheap Yellow Display" or "ESP32-2432S028R". No soldering, no breadboard, and no additional hardware is required.

This project is the focused single-purpose sibling of the Multi-Protocol Field Terminal (DH-FT-002). It uses the same proven CYD hardware configuration and WiFi scan API but goes deeper on signal visualization, channel analysis, and the display layout for a dedicated scanner tool.

Toolchain Setup — Arduino IDE, ESP32 Core, TFT_eSPI with CYD Config
Install the Arduino IDE 2.x, add the Espressif ESP32 board package, configure TFT_eSPI with the exact CYD-specific User_Setup.h, and upload a display-verify sketch that lights the backlight and draws text on screen. Getting TFT_eSPI configured correctly is the single biggest wall in this project — a wrong pin definition produces a permanently blank white screen with no error message.
  1. Install Arduino IDE 2.x. Download from arduino.cc/en/software and run the installer for your operating system. The 2.x series is required for its integrated Board Manager and Library Manager. Launch the IDE before continuing.
  2. Add the Espressif ESP32 board package. Open File > Preferences. In the "Additional Boards Manager URLs" field paste this URL exactly:
    https://raw.githubusercontent.com/espressif/arduino-esp32/gh-pages/package_esp32_index.json
    Click OK. Open Tools > Board > Boards Manager, search esp32, find "esp32 by Espressif Systems", and click Install. The current stable release is 3.x. Download is roughly 300 MB and takes a few minutes. After install, go to Tools > Board > esp32 > ESP32 Dev Module. The CYD has no dedicated board entry; "ESP32 Dev Module" is what the entire CYD community uses.
  3. Install the TFT_eSPI library. Open Sketch > Include Library > Manage Libraries, search TFT_eSPI, find the entry by Bodmer (current version 2.5.x), and click Install. After install, the library lands at Documents/Arduino/libraries/TFT_eSPI/ on Windows/macOS or ~/Arduino/libraries/TFT_eSPI/ on Linux.
  4. Apply the CYD User_Setup.h — the critical step. TFT_eSPI ships with a generic User_Setup.h for different hardware. The CYD's ILI9341 panel is wired to specific pins that differ from the defaults, and it requires the ILI9341_2_DRIVER variant (not ILI9341_DRIVER). Using the wrong config gives a white screen or washed-out colors.

    Navigate to your TFT_eSPI library folder, open User_Setup.h in a text editor, and replace the entire contents with:
    // CYD (ESP32-2432S028R) TFT_eSPI User_Setup.h // Source: github.com/witnessmenow/ESP32-Cheap-Yellow-Display #define USER_SETUP_INFO "CYD ESP32-2432S028R" // ILI9341_2_DRIVER is correct for the CYD panel variant. // Do NOT use ILI9341_DRIVER (standard) -- the _2 variant fixes // colour and init differences on this specific panel. #define ILI9341_2_DRIVER #define TFT_WIDTH 240 #define TFT_HEIGHT 320 // TFT SPI pins (ESP32 HSPI bus) #define TFT_MISO 12 #define TFT_MOSI 13 #define TFT_SCLK 14 #define TFT_CS 15 #define TFT_DC 2 #define TFT_RST -1 // RST tied to ESP32 EN pin on the CYD // Backlight #define TFT_BL 21 #define TFT_BACKLIGHT_ON HIGH // The CYD display is on HSPI; this is mandatory #define USE_HSPI_PORT // SPI speeds #define SPI_FREQUENCY 55000000 #define SPI_READ_FREQUENCY 20000000 #define SPI_TOUCH_FREQUENCY 2500000 // Fonts #define LOAD_GLCD #define LOAD_FONT2 #define LOAD_FONT4 #define LOAD_FONT6 #define LOAD_FONT7 #define LOAD_FONT8 #define LOAD_GFXFF #define SMOOTH_FONT
    Save the file. Do not change anything else inside the TFT_eSPI folder.
    Leave TOUCH_CS undefined here. Some TFT_eSPI versions include a #define TOUCH_CS 21 line in the default setup. Leave it commented out or remove it. In this project the XPT2046 touch controller is driven by the separate XPT2046_Touchscreen library on its own SPI bus (Phase 2). If both TFT_eSPI and XPT2046_Touchscreen try to own the touch controller, you get ghost taps or a dead touch panel.
  5. Install the XPT2046_Touchscreen library. In the Library Manager, search XPT2046_Touchscreen by Paul Stoffregen (version 1.4.x) and install it. This handles the resistive touch controller on the CYD's separate SPI bus. There are multiple XPT2046 libraries in the manager — the Stoffregen version is the correct one.
  6. Connect the CYD and configure port settings. Plug the board into your computer via USB, then in Arduino IDE select:
    • Tools > Board > ESP32 Dev Module
    • Tools > Port > the COM port (Windows) or /dev/ttyUSB0 (Linux) or /dev/cu.usbserial-... (macOS) that appeared when you plugged in
    • Tools > Flash Size > 4MB (32Mb)
    • All other settings at default
  7. Upload the display-verify sketch. Create a new sketch (File > New Sketch) and paste:
    /* * CYD Phase 1 -- Display Verify * Board: ESP32-2432S028R (Cheap Yellow Display) * Requires: TFT_eSPI with CYD User_Setup.h applied */ #include <TFT_eSPI.h> TFT_eSPI tft = TFT_eSPI(); void setup() { Serial.begin(115200); tft.init(); tft.setRotation(1); // Landscape: 320 wide, 240 tall pinMode(TFT_BL, OUTPUT); digitalWrite(TFT_BL, HIGH); // Backlight on tft.fillScreen(TFT_BLACK); tft.setTextColor(TFT_GREEN, TFT_BLACK); tft.setTextSize(2); tft.setCursor(20, 80); tft.println("WiFi Scanner"); tft.setTextSize(1); tft.setCursor(20, 120); tft.setTextColor(TFT_CYAN, TFT_BLACK); tft.println("Display: ILI9341 320x240"); tft.setCursor(20, 136); tft.println("Phase 1: Display OK"); Serial.println("CYD display initialized."); } void loop() { // Display holds its content -- nothing needed here }
    Click the Upload arrow. First compile takes 20–40 seconds. After "Done uploading" the CYD resets automatically.
White or blank screen after upload?
  • Open Arduino/libraries/TFT_eSPI/User_Setup.h and confirm ILI9341_2_DRIVER is defined, USE_HSPI_PORT is uncommented, and all pin numbers match the values above. A single wrong pin produces a white screen with no error output.
  • A white screen at cold power-on (before any upload) is normal — it is the panel's default state. It should change after a successful upload.
  • Backlight stays dark? Confirm TFT_BL 21 is in User_Setup.h and that both pinMode(TFT_BL, OUTPUT) and digitalWrite(TFT_BL, HIGH) are present in setup().
Board not found / no serial port?
  • Windows: download and install the CH340 USB-to-serial driver from wch-ic.com. Unplug and replug the CYD after install — a COM port should appear in Device Manager.
  • Linux: run sudo usermod -aG dialout $USER then log out and back in. The CYD should appear at /dev/ttyUSB0.
  • macOS: the CH340 driver is usually not needed on 10.15+. If the port does not appear, download CH341SER_MAC.ZIP from wch-ic.com.
Checkpoint — what you see on the device
After upload the CYD shows a black screen with "WiFi Scanner" in green text and "Phase 1: Display OK" in cyan. The backlight is fully bright. Serial Monitor at 115200 baud prints "CYD display initialized." If you see this, TFT_eSPI is correctly configured and the display is fully functional.

First WiFi Scan to Serial — SSID, RSSI, Channel, Encryption
Before drawing anything on the TFT, get the WiFi scan data flowing to the Serial Monitor. This confirms the ESP32's radio is working and you understand what the scan API returns before building the display layer on top. WiFi.scanNetworks() does all the work; there is no extra library to install because WiFi.h ships with the Espressif ESP32 core.
Passive-only reminder: WiFi.scanNetworks() causes the ESP32 to listen for beacon frames that access points broadcast publicly. It does not associate with, authenticate to, or transmit data frames to any network. The ESP32 never "joins" anything during a scan.
  1. Understand the scan API. Four calls do everything:
    WiFi.mode(WIFI_STA); // Put radio in station mode (required before scan) WiFi.disconnect(true); // Clear stored creds; prevents partial-connection stall on core 3.x int n = WiFi.scanNetworks(); // Blocking scan; returns count of found networks // Returns WIFI_SCAN_RUNNING (-1) or WIFI_SCAN_FAILED (-2) // if called before previous scan finishes for (int i = 0; i < n; i++) { WiFi.SSID(i) // String -- empty string for hidden SSIDs WiFi.RSSI(i) // int -- signal strength in dBm (e.g. -55) WiFi.channel(i) // int -- 1-13 for 2.4 GHz WiFi.encryptionType(i) // wifi_auth_mode_t enum (see mapping below) WiFi.BSSIDstr(i) // String -- MAC address e.g. "AC:84:C6:3F:2A:01" } WiFi.scanDelete(); // Free the scan result memory when done
    Results are automatically sorted by RSSI (strongest first) by the ESP32 Arduino core.
  2. Map the encryption type enum. WiFi.encryptionType(i) returns a wifi_auth_mode_t value. Map it to a readable label with a switch:
    const char* encLabel(wifi_auth_mode_t enc) { switch (enc) { case WIFI_AUTH_OPEN: return "Open"; case WIFI_AUTH_WEP: return "WEP"; case WIFI_AUTH_WPA_PSK: return "WPA"; case WIFI_AUTH_WPA2_PSK: return "WPA2"; case WIFI_AUTH_WPA_WPA2_PSK: return "WPA/2"; case WIFI_AUTH_WPA3_PSK: return "WPA3"; case WIFI_AUTH_WPA2_ENTERPRISE: return "ENT"; default: return "???"; } }
  3. Upload the serial-scan sketch. Keep the Phase 1 display init — it gives you a "Scanning..." message on screen while the scan runs. Add #include <WiFi.h> at the top:
    /* * CYD Phase 2 -- WiFi Scan to Serial * Board: ESP32-2432S028R * Requires: TFT_eSPI (CYD User_Setup.h applied), WiFi.h (built-in) */ #include <TFT_eSPI.h> #include <WiFi.h> TFT_eSPI tft = TFT_eSPI(); const char* encLabel(wifi_auth_mode_t enc) { switch (enc) { case WIFI_AUTH_OPEN: return "Open"; case WIFI_AUTH_WEP: return "WEP"; case WIFI_AUTH_WPA_PSK: return "WPA"; case WIFI_AUTH_WPA2_PSK: return "WPA2"; case WIFI_AUTH_WPA_WPA2_PSK: return "WPA/2"; case WIFI_AUTH_WPA3_PSK: return "WPA3"; case WIFI_AUTH_WPA2_ENTERPRISE: return "ENT"; default: return "???"; } } void setup() { Serial.begin(115200); // Init display tft.init(); tft.setRotation(1); pinMode(TFT_BL, OUTPUT); digitalWrite(TFT_BL, HIGH); tft.fillScreen(TFT_BLACK); tft.setTextColor(TFT_CYAN, TFT_BLACK); tft.setTextSize(1); tft.setCursor(10, 110); tft.print("Scanning... check Serial Monitor"); // WiFi scan WiFi.mode(WIFI_STA); WiFi.disconnect(true); // true = clear stored credentials; prevents partial-connection stall on core 3.x delay(100); Serial.println("\n=== WiFi Scan ==="); int n = WiFi.scanNetworks(false, true); // false=blocking, true=include hidden if (n == 0) { Serial.println("No networks found."); } else { Serial.printf("%-20s %5s %4s %6s %s\n", "SSID", "RSSI", "CH", "ENC", "BSSID"); Serial.println("-----------------------------------------------------------"); for (int i = 0; i < n; i++) { String ssid = WiFi.SSID(i); if (ssid.length() == 0) ssid = "(hidden)"; Serial.printf("%-20s %5d %4d %6s %s\n", ssid.c_str(), WiFi.RSSI(i), WiFi.channel(i), encLabel(WiFi.encryptionType(i)), WiFi.BSSIDstr(i).c_str()); } Serial.printf("Total: %d networks\n", n); } WiFi.scanDelete(); tft.setCursor(10, 126); tft.setTextColor(TFT_GREEN, TFT_BLACK); tft.printf("Scan done. %d networks. See Serial.", n); } void loop() {}
  4. Open Serial Monitor at 115200 baud (Tools > Serial Monitor) before or immediately after uploading. The scan takes 2–4 seconds. You should see a table of SSIDs with RSSI, channel, encryption type, and BSSID.
scanNetworks() always returns 0?
  • Confirm WiFi.mode(WIFI_STA) runs before the scan. Without station mode the driver may return 0 results.
  • The CYD's antenna is a PCB trace on the board edge. Move the board away from dense RF sources (monitors, computers, metal enclosures) and retry.
  • The ESP32 supports 2.4 GHz only. Dual-band routers that broadcast exclusively on 5 GHz will not appear. This is expected behavior, not an error.
  • Returns -1 (WIFI_SCAN_RUNNING) or -2 (WIFI_SCAN_FAILED)? You called a second scan before the first finished, or called without WIFI_STA mode. Call WiFi.scanDelete() first and ensure mode is set.
Checkpoint — what you see on the device
Serial Monitor prints a formatted table of nearby networks: SSID names left-aligned, RSSI values like -48 or -71, channel numbers (1, 6, and 11 are most common in the US), encryption labels (WPA2, Open, WPA3), and BSSID MAC addresses. The TFT shows "Scan done. N networks." in green. This confirms the ESP32 radio is working and the scan API is returning correct data.

Render Scan Results on the TFT — Scrollable Network List
Move the scan results from Serial onto the 320×240 display. Build a header row, a fixed-height network list with SSID, RSSI, channel, and encryption label per row, and a footer showing total count. Fit up to ten rows in the content area below the header. This is the core display that every later phase builds on.
  1. Plan the layout. In landscape rotation, the display is 320px wide and 240px tall. Reserve 18px for a header bar, 12px for a footer bar, and 16px for a status line at the bottom. That leaves 194px for the network list, which fits roughly 11 rows at 17px each.
    // Layout constants (landscape 320x240) const int HEADER_H = 18; // header bar height const int FOOTER_Y = 226; // y position of footer status line const int ROW_H = 17; // pixels per network row const int MAX_ROWS = 11; // (240 - HEADER_H - 14) / ROW_H const int LIST_Y = HEADER_H + 2; // first row top
  2. Upload the TFT list sketch. This replaces the Phase 2 sketch; it reuses the same encLabel() function and adds a drawScan() function that renders the full list:

SSID text bleeds into the RSSI column?
  • The sketch truncates SSIDs at 20 characters and appends a tilde. At TFT_eSPI text size 1, each character is 6px wide, so 20 chars = 120px, leaving the RSSI column at x=198 clear.
  • If you see overlap, increase the truncation limit in the sketch or reduce text size to 1 if you accidentally changed it to 2.

Signal Bars + Touch-to-Rescan — XPT2046 on Its Own SPI Bus
Replace the plain RSSI number with animated stacked signal bars (4 bars, 1 to 4 lit based on signal strength) and wire up the XPT2046 touch controller so a tap on the screen triggers a fresh scan. The CYD's touch controller runs on a completely separate SPI bus from the display — mixing them causes ghost taps or a dead touch panel.
  1. Understand the dual SPI architecture. The CYD runs TFT_eSPI on the ESP32's HSPI bus (pins 12/13/14/15/2). The XPT2046 touch controller is wired to a separate set of pins and needs its own SPI instance. Pins confirmed from the official CYD repository:

Touch not responding at all?
  • Confirm you installed XPT2046_Touchscreen by Paul Stoffregen (not a different XPT2046 library). In Library Manager search for "XPT2046" and verify the author name.
  • Confirm the pin numbers in the sketch exactly match the values above. A single transposed pin silences the touch controller with no error output.
  • IO36 (TOUCH_IRQ) is an input-only pin on the ESP32. Never call pinMode(TOUCH_IRQ, OUTPUT) on it.
Touch taps register in the wrong position?
  • The XPT2046 raw ADC range varies between individual boards. Add Serial.printf("raw %d %d\n", ts.getPoint().x, ts.getPoint().y); in loop() to read your board's actual values, then update TOUCH_X_MIN / TOUCH_X_MAX and the Y equivalents in the sketch accordingly. This page's touch code does not need coordinate mapping because any tap triggers a rescan — but Phase 5 will if you add a channel-view button.

  2. Portable power. The CYD draws roughly 150–200 mA during a WiFi scan and 80–120 mA in steady display-on state at full backlight. A standard 5000 mAh USB power bank provides 18–25 hours of runtime at the steady-state draw. Any USB power bank that does not auto-shutoff under low load (some power banks cut off at below 100 mA; the CYD may trigger this threshold between scans) will work. Test by leaving the device running unplugged for 5 minutes before relying on a specific power bank.
    Reduce backlight for longer battery life (ESP32 core 3.x): The CYD backlight pin (GPIO 21) is controlled via the ESP32 LEDC peripheral. On Arduino-ESP32 core 3.x, use ledcAttach(TFT_BL, 5000, 8) once in setup() after tft.init(), then call ledcWrite(TFT_BL, 160) to dim (range 0–255, 255 = full brightness). Do not go below 80 or the display becomes unreadable indoors. Note: analogWrite() does not exist on the ESP32 Arduino core — using it will produce a compile error.
Final ethics recap — what this device is and is not. This scanner performs passive beacon-frame observation — the same operation your phone does every few seconds when it searches for known WiFi networks. It does not connect, authenticate, transmit data frames, capture handshakes, attempt deauthentication, spoof access points, or inject packets. Legitimate uses include: knowing which 2.4 GHz channels are congested in your building before placing a new access point; inventorying which networks are visible from a given location during your own site survey; studying how RSSI varies with distance and obstructions on your own property. Unauthorized use of this or any wireless scanning tool to assess networks you do not own or have written authorization to assess is illegal and unethical. The line is clear: observation of public broadcasts on your own equipment is legal; intercepting or interfering with others' communications is not.
