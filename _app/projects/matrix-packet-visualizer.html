Subject

Build a Packet Visualizer

Advanced 2H 1000 XP
Mission Brief

This operation tasks you with building a live packet visualizer from the ground up in Python — a tool that captures raw network traffic in real time or reads recorded captures from pcap files, then decodes each packet layer by layer from the Ethernet frame all the way up through IP, TCP/UDP, and application protocols like HTTP and DNS. The goal is not to run Wireshark and read its output, but to understand, at the byte level, exactly what Wireshark is doing under the hood when it parses a packet capture.

The visualizer displays a scrollable packet list in the terminal, showing timestamp, source address, destination address, protocol, length, and a one-line summary for each captured frame. Selecting a packet expands a full decoded header tree — a Wireshark-style detail pane rendered in ASCII — allowing you to inspect every field at every protocol layer. Traffic statistics update live: top talkers by IP, protocol distribution percentages, packets-per-second rate, and conversation tracking across unique source/destination pairs are all computed from the raw capture stream using collections.Counter and timestamp math.

Built with scapy for packet parsing and rich or curses for terminal rendering, this project teaches the craft of binary data interpretation at the protocol level. You will work directly with struct.unpack() to extract header fields from raw byte buffers, implement BPF filter strings to focus the capture on traffic that matters, and detect behavioral patterns like port scans and DNS tunneling from aggregated flow data. When you are done, you will have both a functional network forensics tool and a deep, hands-on understanding of how network protocols encode information inside layered byte sequences.

Agent Requirements
  • Solid Python skills including classes, binary data handling, and basic use of the struct module for packing and unpacking byte sequences
  • Basic networking knowledge covering IP addressing, ports, the difference between TCP and UDP, and what HTTP requests look like at a high level
  • Comfortable running commands with sudo or administrator privileges, since live packet capture requires elevated access to network interfaces
  • Familiar with terminal-based interfaces and reading dense text output; you will spend most of your time in a fullscreen terminal UI
  • No prior experience with packet analysis or scapy is required — this project builds the decoder stack from the ground up, explaining each protocol field as it is implemented
Operation Phases
1
Packet Capture & Ingestion
Build a capture engine using scapy's sniff() function with BPF filter support so you can focus on specific traffic types, ports, or hosts from the command line. Implement an iface argument to select the network interface and a --read flag to load an existing pcap file via rdpcap(). Back the capture with a thread-safe ring buffer of configurable maximum size so the UI is never blocked by the capture thread.
2
Protocol Decoder Stack
Write a layered decoder chain that normalizes each captured packet into a structured dictionary. Implement decoders for Ethernet (source/destination MAC, EtherType), IPv4 and IPv6 (addresses, TTL, protocol number), TCP (source/destination port, sequence number, acknowledgment number, flags as named booleans), UDP (ports, length), DNS (query name, record type, response addresses), and HTTP (method, URI, status code, content type). Use struct.unpack() directly on raw bytes alongside scapy layer accessors to reinforce how header fields map to byte offsets.
3
Packet List & Detail View
Build a scrollable terminal UI displaying captured packets in a fixed-column table: #, Time, Source, Destination, Protocol, Length, and Info. Implement keyboard navigation so pressing Enter on a selected packet expands a full decoded header tree in a split pane, showing every field at every protocol layer the way Wireshark's detail view does. Color-code rows by protocol family — TCP connections, UDP datagrams, and DNS traffic each get a distinct accent.
4
Traffic Analysis Engine
Layer a live statistics engine over the capture stream using collections.Counter and timestamp arithmetic. Track top talkers (ranked by packet count and byte volume), protocol distribution percentages, live packets-per-second rate, and average packet size across the session. Build a conversation tracker keyed on (src_ip, dst_ip, src_port, dst_port) tuples, accumulating packet counts and byte totals per flow. Implement heuristic detection for port scan signatures (many unique destination ports from one source IP) and DNS tunneling indicators (abnormally long query names or high query frequency to a single resolver).
5
Visualization & Export
Render ASCII-art protocol distribution bar charts, sortable conversation tables, and a rolling traffic timeline in the terminal status panel. Wire up a JSON export that writes the full decoded packet list, conversation summary, and statistical report to disk with a single keypress. Add a filtered pcap write mode: accept a BPF expression at runtime and use wrpcap() to save only matching packets, enabling surgical extraction of attack traffic from a larger capture.
