Subject

Headless Scraping with Puppeteer

Operative 60 MIN 500 XP
Responsible Use — Read Before You Proceed

Puppeteer is a legitimate browser automation library used by developers, QA engineers, and security researchers worldwide. The techniques in this project apply to public, openly accessible data only. Before scraping any site, you are responsible for checking three things: the site's robots.txt file (which declares which paths may be crawled), the Terms of Service (which may prohibit automated access), and applicable law in your jurisdiction (in the U.S., the Computer Fraud and Abuse Act; in the EU, the CFAA equivalent plus GDPR data minimisation obligations).

This project uses only sanctioned practice targets that exist for exactly this purpose:

  • quotes.toscrape.com/js — a scraping practice site operated by the Scrapy team, explicitly designed for automated access
  • books.toscrape.com — companion site from the same team, used here for pagination demonstration

These rules are not optional courtesies. Violating them moves the activity from data collection into territory that can constitute unauthorized access, tortious interference, or DoS. Even against sites that permit scraping: add polite delays between requests (1–3 seconds minimum), identify your bot with a descriptive User-Agent string, and never parallelize to the point that you saturate the server. Do not scrape behind login walls, paywalls, or any endpoint that requires credentials you were not given for automated use. If an official API exists, use it. This project pairs with darkarts-web-scraping, which covers the distinction between static HTML scraping and the JavaScript-rendered targets that require a headless browser.

Mission Brief

This operation deploys a headless Chromium browser under programmatic control to extract intelligence from JavaScript-rendered web targets. Using Puppeteer 25.x and Node.js, you will automate full browser sessions — navigating pages, waiting for dynamic content to render, interacting with pagination controls, intercepting network requests, and pulling structured data that traditional HTTP scrapers cannot reach. The finished toolset works against any JS-rendered page, not just the practice targets used here.

Modern web applications render their data exclusively in JavaScript, making static HTML scraping obsolete for many collection scenarios. Puppeteer gives you direct access to the Chrome DevTools Protocol (CDP), enabling fine-grained control over every browser subsystem: the DOM, network stack, JavaScript runtime, and input simulation. In Phase 4 you will intercept and modify network requests to block resource-heavy assets, cutting page load time significantly on scraping runs. Phase 5 addresses the common failure modes — timing issues, sandbox restrictions on Linux and Docker, and selector drift — and closes with the responsible-use checklist every practitioner should run before deploying a scraper.

Agent Requirements
  • Node.js 22.12 or later (LTS recommended) — Puppeteer 25.x requires Node 22.12+. Verify with node --version. Download from nodejs.org if needed; the LTS installer includes npm.
  • npm 10+ (bundled with Node 22 LTS) — verify with npm --version. No separate install needed.
  • ~450 MB of disk space for the Chromium binary that npm install puppeteer downloads automatically
  • Comfortable writing asynchronous JavaScript with async/await — every Puppeteer API is async; if Promises are unfamiliar, review them in Script House first
  • Basic understanding of the browser DOM: what a CSS selector is, what document.querySelectorAll() returns
  • General awareness of HTTP: what a request is, what a status code means, what a User-Agent header does
  • No prior Puppeteer or web scraping experience required — every API is introduced from first principles

Project Setup, First Launch, and Screenshot
Initialize a Node.js project, install Puppeteer (which downloads a compatible Chromium binary automatically), choose ESM or CJS module format, then write and run a minimal script that launches a headless browser, navigates to quotes.toscrape.com/js, reads the page title, and saves a full-page screenshot. The screenshot is your first proof the browser ran.
  1. Create a project directory and initialize it.
    mkdir puppeteer-lab && cd puppeteer-lab npm init -y
    This creates package.json with default values. The -y flag accepts all defaults so you do not need to answer prompts.
  2. Choose your module format. Puppeteer 25.x works in both ESM (import) and CommonJS (require). This project uses CommonJS because it requires no extra configuration: Node.js treats .js files as CJS by default unless "type": "module" is set in package.json. All scripts below use const puppeteer = require('puppeteer').
    To use ESM instead: add "type": "module" to package.json, rename files to .mjs or keep .js with the type field set, and replace require('puppeteer') with import puppeteer from 'puppeteer'. Both work identically for every API used here.
  3. Install Puppeteer.
    npm install puppeteer
    This installs Puppeteer 25.x and automatically downloads a compatible version of Chrome for Testing into node_modules/.cache/puppeteer/. The download is roughly 400–450 MB. It runs once; subsequent installs use the cached binary.
    puppeteer vs. puppeteer-core: the puppeteer package bundles Chromium. puppeteer-core is a smaller package with no bundled browser — you point it at a browser you already have installed. Use puppeteer for this project.
  4. Write the first script. Create phase1.js in your project directory with this complete script:
    // phase1.js -- Launch, navigate, title, screenshot 'use strict'; const puppeteer = require('puppeteer'); (async () => { const browser = await puppeteer.launch({ headless: true, // true = new headless mode (default in Puppeteer 25.x) args: ['--no-sandbox', '--disable-setuid-sandbox'] // required on Linux/Docker }); const page = await browser.newPage(); // Set a descriptive User-Agent so the server knows who we are await page.setUserAgent( 'PuppeteerLab/1.0 (scraping-practice; quotes.toscrape.com)' ); console.log('Navigating to quotes.toscrape.com/js ...'); await page.goto('https://quotes.toscrape.com/js/', { waitUntil: 'networkidle2' // wait until fewer than 3 pending network requests for 500ms }); const title = await page.title(); console.log('Page title:', title); await page.screenshot({ path: 'phase1-screenshot.png', fullPage: true }); console.log('Screenshot saved to phase1-screenshot.png'); await browser.close(); console.log('Browser closed. Phase 1 complete.'); })();
  5. Run the script.
    node phase1.js
    Expected terminal output:
    Navigating to quotes.toscrape.com/js ... Page title: Quotes to Scrape Screenshot saved to phase1-screenshot.png Browser closed. Phase 1 complete.
    Open phase1-screenshot.png in any image viewer. You should see a rendered page with ten quotes, author names, and tag links — proof that Chromium executed the JavaScript that built the DOM.
Error: Running as root without --no-sandbox is not supported on Linux?
  • This error appears on any Linux system (including WSL, Docker, and CI environments) when Chromium's sandbox is incompatible with the current user or kernel configuration. The fix is already in the script above: the args: ['--no-sandbox', '--disable-setuid-sandbox'] lines in puppeteer.launch() disable the sandbox. This is safe in a controlled lab environment. On a production server, use a user namespace sandbox instead.
Error: Could not find Chrome (please install it manually)?
  • The Chromium download may have failed silently (common behind corporate proxies). Run npx puppeteer browsers install chrome to retry the download manually. If a proxy blocks the download host, set HTTPS_PROXY=http://proxy:port npm install puppeteer in your environment before installing.
  • On Linux, the Chromium binary may require shared libraries that are not present. Run node -e "const { executablePath } = require('puppeteer'); console.log(executablePath());" to find the binary path, then run it directly (./chrome --version) to see the missing library error. Install the listed packages with sudo apt-get install <package>.
Checkpoint — what you should see
node phase1.js prints "Page title: Quotes to Scrape" and exits cleanly. phase1-screenshot.png exists in the project directory and contains a rendered page showing ten quote entries with author names visible. If the screenshot is blank or shows only the page frame without quotes, increase the waitUntil value to 'networkidle0' (stricter: waits until zero pending requests for 500ms) and re-run.

Extract Structured Data from a JS-Rendered Page
Use page.waitForSelector() to block until dynamic content is present, then use page.$$eval() to run a selector against all matching elements and return data from the browser context to Node.js. Target quotes.toscrape.com/js and extract every quote's text, author name, and tags as a structured array, then write it to quotes.json.
  1. Understand the page's DOM structure. The HTML that Chromium renders for each quote looks like this (confirmed via curl https://quotes.toscrape.com/ which shows the same structure as the JS-rendered version):
    <div class="quote"> <span class="text">"The world as we have created it..."</span> <span>by <small class="author">Albert Einstein</small></span> <div class="tags"> <a class="tag" href="/tag/change/page/1/">change</a> <a class="tag" href="/tag/thinking/page/1/">thinking</a> </div> </div>
    The selectors you need: .quote (outer container), .text (quote text), .author (author name), .tag (individual tag links).
  2. Create phase2.js with this complete script:
    // phase2.js -- Extract structured data from JS-rendered quotes 'use strict'; const puppeteer = require('puppeteer'); const fs = require('fs'); (async () => { const browser = await puppeteer.launch({ headless: true, args: ['--no-sandbox', '--disable-setuid-sandbox'] }); const page = await browser.newPage(); await page.setUserAgent( 'PuppeteerLab/1.0 (scraping-practice; quotes.toscrape.com)' ); await page.goto('https://quotes.toscrape.com/js/', { waitUntil: 'networkidle2' }); // Block until at least one .quote element exists in the DOM await page.waitForSelector('.quote', { timeout: 10000 }); // page.$$eval(selector, fn) runs fn inside the browser with all matching // elements as the first argument. The return value is serialised back to Node. const quotes = await page.$$eval('.quote', nodes => nodes.map(node => ({ text: node.querySelector('.text').innerText.replace(/[""]/g, '').trim(), author: node.querySelector('.author').innerText.trim(), tags: [...node.querySelectorAll('.tag')].map(a => a.innerText.trim()) })) ); console.log(`Extracted ${quotes.length} quotes from page 1:`); quotes.forEach((q, i) => console.log(` ${i + 1}. "${q.text.slice(0, 55)}..." -- ${q.author}`) ); fs.writeFileSync('quotes.json', JSON.stringify(quotes, null, 2)); console.log('\nSaved to quotes.json'); await browser.close(); })();
  3. Run the script.
    node phase2.js
    Expected terminal output (your quotes may vary slightly):
    Extracted 10 quotes from page 1: 1. "The world as we have created it is a process of our..." -- Albert Einstein 2. "It is our choices, Harry, that show what we truly are..." -- J.K. Rowling 3. "There are only two ways to live your life. One is as t..." -- Albert Einstein 4. "The person, be it gentleman or lady, who has not pleas..." -- Jane Austen 5. "Imperfection is beauty, madness is genius and it's bet..." -- Marilyn Monroe 6. "Try not to become a man of success. Rather become a ma..." -- Albert Einstein 7. "It is better to be hated for what you are than to be l..." -- Andre Gide 8. "I have not failed. I've just found 10,000 ways that wo..." -- Thomas A. Edison 9. "A woman is like a tea bag; you never know how strong it..." -- Eleanor Roosevelt 10. "A day without sunshine is like, you know, night." -- Steve Martin Saved to quotes.json
    page.$$eval vs. page.evaluate: page.$$eval(selector, fn) is shorthand for "query all matching elements and pass them to fn". page.evaluate(fn) runs fn in the browser with no pre-selected elements — you query the DOM yourself inside fn using document.querySelectorAll(). Use $$eval when you know the selector upfront; use evaluate for more complex multi-step DOM operations.
  4. Inspect the output file.
    cat quotes.json
    The first entry should look like:
    [ { "text": "The world as we have created it is a process of our thinking. It cannot be changed without changing our thinking.", "author": "Albert Einstein", "tags": ["change", "deep-thoughts", "thinking", "world"] }, ... ]
waitForSelector times out?
  • The default timeout for waitForSelector is 30 000 ms. If you are getting a timeout error on a much shorter run, the selector is wrong or the page did not load. Double-check by running the script with headless: false (see Phase 5) to watch what the browser actually renders.
  • If quotes.json is written but the array is empty, the $$eval selector did not match anything. Confirm you are on the /js/ path (the non-JS version at quotes.toscrape.com/ uses the same selectors but does not require waitForSelector).
Checkpoint — what you should see
node phase2.js prints exactly 10 quote lines to the terminal. quotes.json is created and contains a JSON array of 10 objects, each with text, author, and tags fields. The tags field is an array of strings, not a single string.

Interact with Dynamic Elements and Paginate
Click the "Next" pagination control, wait for the new page content to load, and loop through all pages until no Next button remains. This produces a complete multi-page dataset. The target is quotes.toscrape.com/js which has 10 pages of quotes (100 total).
  1. Understand the pagination structure. At the bottom of each page, the Next link has the class next and links to /js/page/2/, /js/page/3/, etc. On the last page the .next element is absent. The selector for the button itself is .next a.
  2. Create phase3.js with this complete script:
    // phase3.js -- Paginate through all pages and collect every quote 'use strict'; const puppeteer = require('puppeteer'); const fs = require('fs'); // Polite delay between page loads (milliseconds) const DELAY_MS = 1500; function sleep(ms) { return new Promise(resolve => setTimeout(resolve, ms)); } async function extractQuotesFromPage(page) { await page.waitForSelector('.quote', { timeout: 10000 }); return page.$$eval('.quote', nodes => nodes.map(node => ({ text: node.querySelector('.text').innerText.replace(/[""]/g, '').trim(), author: node.querySelector('.author').innerText.trim(), tags: [...node.querySelectorAll('.tag')].map(a => a.innerText.trim()) })) ); } (async () => { const browser = await puppeteer.launch({ headless: true, args: ['--no-sandbox', '--disable-setuid-sandbox'] }); const page = await browser.newPage(); await page.setUserAgent( 'PuppeteerLab/1.0 (scraping-practice; quotes.toscrape.com)' ); await page.goto('https://quotes.toscrape.com/js/', { waitUntil: 'networkidle2' }); const allQuotes = []; let pageNum = 1; while (true) { console.log(`Scraping page ${pageNum} ...`); const quotes = await extractQuotesFromPage(page); allQuotes.push(...quotes); console.log(` -> ${quotes.length} quotes collected (running total: ${allQuotes.length})`); // Check for a Next button const nextLink = await page.$('.next a'); if (!nextLink) { console.log('No Next button found. Reached the last page.'); break; } // Click Next and wait for new content to load await Promise.all([ page.waitForNavigation({ waitUntil: 'networkidle2' }), nextLink.click() ]); pageNum++; await sleep(DELAY_MS); // polite delay between pages } fs.writeFileSync('all-quotes.json', JSON.stringify(allQuotes, null, 2)); console.log(`\nDone. ${allQuotes.length} total quotes saved to all-quotes.json`); await browser.close(); })();
  3. Run the script.
    node phase3.js
    Expected output (each page takes 1.5–3 seconds with the polite delay):
    Scraping page 1 ... -> 10 quotes collected (running total: 10) Scraping page 2 ... -> 10 quotes collected (running total: 20) Scraping page 3 ... -> 10 quotes collected (running total: 30) Scraping page 4 ... -> 10 quotes collected (running total: 40) Scraping page 5 ... -> 10 quotes collected (running total: 50) Scraping page 6 ... -> 10 quotes collected (running total: 60) Scraping page 7 ... -> 10 quotes collected (running total: 70) Scraping page 8 ... -> 10 quotes collected (running total: 80) Scraping page 9 ... -> 10 quotes collected (running total: 90) Scraping page 10 ... -> 10 quotes collected (running total: 100) No Next button found. Reached the last page. Done. 100 total quotes saved to all-quotes.json
  4. Verify the output count.
    node -e "const d = require('./all-quotes.json'); console.log(d.length + ' quotes');"
    Expected: 100 quotes
Navigation hangs or Promise.all times out?
  • The Promise.all([waitForNavigation, click]) pattern is important: you must set up the navigation listener before you click, otherwise the navigation can complete before the listener is registered and the promise never resolves. If you get a timeout, check that both the waitForNavigation and the click are inside the same Promise.all call.
  • If the browser lands on a page but waitForSelector('.quote') times out, the JS-rendered version of the site may be responding slowly. Increase the timeout: { timeout: 20000 }.
  • On very slow connections, increase DELAY_MS to 3000 to give the server more recovery time between requests.
Checkpoint — what you should see
node phase3.js logs 10 page lines and exits with "100 total quotes saved to all-quotes.json". The output file exists and the in-Node verification command prints 100 quotes. Timestamps between lines should show the 1.5-second polite delay.

Intercept Network Requests and Block Heavy Assets
Enable Puppeteer's request interception layer to inspect every outgoing request before it leaves the browser. Block images, stylesheets, fonts, and media to cut page load time. Log each intercepted request type so you can see what you are blocking and what passes through.
  1. Understand request interception. When you call page.setRequestInterception(true), every request the browser makes stalls until your code calls one of:
    • request.continue() — let the request proceed normally
    • request.abort() — cancel the request (the resource never loads)
    • request.respond({ ... }) — return a fake response from Node.js
    You attach a handler with page.on('request', handler). Every intercepted request has a resourceType() method that returns a string: 'document', 'script', 'image', 'stylesheet', 'font', 'media', 'xhr', 'fetch', etc.
  2. Create phase4.js with this complete script:
    // phase4.js -- Request interception: block images, CSS, fonts 'use strict'; const puppeteer = require('puppeteer'); // These resource types add load time without contributing to data extraction const BLOCKED_TYPES = new Set(['image', 'stylesheet', 'font', 'media']); (async () => { const browser = await puppeteer.launch({ headless: true, args: ['--no-sandbox', '--disable-setuid-sandbox'] }); const page = await browser.newPage(); await page.setUserAgent( 'PuppeteerLab/1.0 (scraping-practice; quotes.toscrape.com)' ); // Enable interception -- every request will stall until handled await page.setRequestInterception(true); const requestLog = []; page.on('request', request => { const type = request.resourceType(); const url = request.url(); if (BLOCKED_TYPES.has(type)) { requestLog.push({ action: 'BLOCKED', type, url: url.slice(0, 80) }); request.abort(); } else { requestLog.push({ action: 'ALLOWED', type, url: url.slice(0, 80) }); request.continue(); } }); console.log('Loading page with request interception enabled ...'); const t0 = Date.now(); await page.goto('https://quotes.toscrape.com/js/', { waitUntil: 'networkidle2' }); const elapsed = Date.now() - t0; console.log(`Page loaded in ${elapsed} ms`); await page.waitForSelector('.quote', { timeout: 10000 }); const quoteCount = await page.$$eval('.quote', nodes => nodes.length); console.log(`Quotes found in DOM: ${quoteCount}`); console.log('\n--- Request Log ---'); requestLog.forEach(r => console.log(`[${r.action.padEnd(7)}] (${r.type.padEnd(10)}) ${r.url}`) ); const blocked = requestLog.filter(r => r.action === 'BLOCKED').length; const allowed = requestLog.filter(r => r.action === 'ALLOWED').length; console.log(`\nSummary: ${allowed} allowed, ${blocked} blocked`); await browser.close(); })();
  3. Run the script.
    node phase4.js
    Expected output (illustrative — your load time, the exact resource URLs, and the allowed/blocked counts will vary by connection speed and any CDN/analytics the site serves at the time; the load time on a slow link or in Docker/WSL can be several seconds and is still normal):
    Loading page with request interception enabled ... Page loaded in ~400 ms (varies) Quotes found in DOM: 10 --- Request Log --- [ALLOWED] (document ) https://quotes.toscrape.com/js/ [ALLOWED] (script ) https://quotes.toscrape.com/static/bootstrap.min.js [ALLOWED] (script ) https://quotes.toscrape.com/static/main.js [BLOCKED] (stylesheet) https://quotes.toscrape.com/static/main.css [BLOCKED] (stylesheet) https://quotes.toscrape.com/static/bootstrap.min.css Summary: 3 allowed, 2 blocked
    Why does blocking CSS still let the page work? Because the data is in the DOM, not the visual layout. Puppeteer's $$eval reads the DOM tree, which exists regardless of whether CSS was loaded. Blocking CSS and images typically cuts load time by 30–60% on image-heavy pages while leaving all scraped content intact.
  4. Extend the script to capture XHR/fetch responses (common when sites load data via an internal API). Add this block after setRequestInterception:
    // Log responses from XHR and fetch requests page.on('response', async response => { const req = response.request(); const type = req.resourceType(); if (type === 'xhr' || type === 'fetch') { const url = req.url().slice(0, 80); const status = response.status(); console.log(`[RESPONSE] ${status} ${type} ${url}`); // To read the body: const body = await response.json(); } });
    quotes.toscrape.com does not use an internal JSON API (it inlines the data in a <script> tag), so you will not see XHR responses here. On sites that do use XHR APIs, this listener lets you intercept the raw JSON payload directly, bypassing DOM parsing entirely.
Request handler fires but calling request.continue() throws "Request is already handled"?
  • Each request may only be handled once. If you have multiple page.on('request') listeners registered, both fire for every request and the second call to continue() or abort() throws. Keep a single handler that covers all cases.
  • If setRequestInterception(true) is called after page.goto() starts, some requests may have already fired without a handler, causing them to stall permanently. Always call setRequestInterception and attach the page.on('request') listener before calling page.goto().

The summary line shows both an "allowed" and a "blocked" count.

Robustness, Debugging, and Responsible-Use Checklist
Real scraping jobs fail: pages time out, selectors change, sites go down. This phase covers the headful debugging workflow (launching with a visible browser window), wrapping phases in try/catch with retry logic, the --no-sandbox requirement on Linux and Docker, and a pre-flight checklist to run before targeting any new site.
  1. Debug with a visible browser window. When a script behaves unexpectedly, set headless: false and add slowMo to slow every Puppeteer action by a fixed number of milliseconds. You will see exactly what the browser is doing.
    // Debug mode -- visible browser, slowed down const browser = await puppeteer.launch({ headless: false, // open a real browser window slowMo: 150, // slow each action by 150ms so you can watch args: ['--no-sandbox', '--disable-setuid-sandbox'] });
    Run any of your earlier scripts with this launch config. You will see the browser open, navigate to the URL, and execute each action in slow motion. This is the single most effective debugging tool.
    headless: 'shell' (the chrome-headless-shell binary): headless: 'shell' launches chrome-headless-shell — a separate, lighter-weight binary that is faster and uses less memory but lacks some full-browser features. Use it when you want raw speed and don't need the complete rendering stack. The default headless: true uses the new headless mode introduced in Chrome 112, which is a full Chromium render process running without a display server — more capable than the old shell mode.
  2. Add timeout handling and per-page retry logic. Wrap your per-page extraction in a helper that retries up to N times before logging the failure and moving on:
    // Retry wrapper -- attempt fn up to maxRetries times async function withRetry(fn, maxRetries = 3, delayMs = 2000) { for (let attempt = 1; attempt <= maxRetries; attempt++) { try { return await fn(); } catch (err) { if (attempt === maxRetries) { console.error(` Failed after ${maxRetries} attempts: ${err.message}`); return null; } console.warn(` Attempt ${attempt} failed (${err.message}), retrying in ${delayMs}ms ...`); await new Promise(r => setTimeout(r, delayMs)); } } } // Usage in your pagination loop: const quotes = await withRetry(() => extractQuotesFromPage(page)); if (quotes === null) { console.log('Skipping this page due to repeated errors.'); continue; }
  3. Always close the browser in a finally block. If your script throws before reaching browser.close(), the Chromium process stays alive and leaks memory. The safe pattern:
    let browser; try { browser = await puppeteer.launch({ ... }); // ... all your page code here } catch (err) { console.error('Fatal error:', err.message); } finally { if (browser) await browser.close(); }
  4. The sandbox note for Linux and Docker. Chromium's built-in sandbox requires Linux user namespaces, which are not available in all environments (containers, restricted VMs, some CI systems). The --no-sandbox flag disables the sandbox at the OS level. It is appropriate in controlled lab environments where you trust the pages being loaded. Do not use --no-sandbox when your scraper may load untrusted or attacker-controlled pages, as a malicious page could then escape the Chromium process.
    // Safe in a controlled lab: args: ['--no-sandbox', '--disable-setuid-sandbox'] // Safer alternative if your kernel supports user namespaces: // omit these flags entirely and Chromium manages its own sandbox
  5. Selector breakage. Selectors are the most fragile part of any scraper. Sites redesign their layouts; class names change without notice. Defensive practices:
    • Prefer stable attributes: data-testid, aria-label, or semantic tags (h1, article) over generated class names like css-1a2b3c.
    • Check page.$(selector) returns non-null before calling page.click() on it to avoid "cannot click null" errors.
    • Log the count of matched elements at the start of each scrape run so selector drift is visible immediately.
  6. Run the responsible-use pre-flight checklist before scraping any new target. Answer all five questions affirmatively before proceeding:
    Pre-flight checklist for new scraping target ========================================== 1. robots.txt reviewed? curl https://targetsite.com/robots.txt -> Confirm the path you intend to scrape is not Disallow'd. 2. Terms of Service reviewed? -> Check for clauses prohibiting automated access or data harvesting. -> If ToS prohibits it, stop here regardless of technical feasibility. 3. Official API exists? -> If yes, use it. APIs are faster, more stable, and explicitly permitted. 4. Polite delay configured? -> Minimum 1-2 seconds between page requests. -> Lower delays at quiet hours (overnight) if needed. 5. Data is public and not personal? -> No scraping behind login walls, CAPTCHA gates, or paywalls. -> No collection of personal data (names, emails, addresses) without a documented legal basis (e.g., GDPR legitimate interest assessment).
networkidle2 vs. networkidle0: which waitUntil value should I use?
  • 'networkidle2': waits until there are no more than 2 in-flight network requests for at least 500 ms. The right choice for most pages — it handles the common case where a few analytics or tracking beacons remain active.
  • 'networkidle0': stricter — waits until zero in-flight requests for 500 ms. Use this when networkidle2 exits too early and your data is not yet in the DOM. It may time out on pages with persistent WebSocket connections or long-poll requests.
  • 'domcontentloaded': fires as soon as the HTML is parsed, before JS runs. Too early for JS-rendered content. Use this only when you know the data is server-rendered in the initial HTML.
  • 'load': fires after HTML, JS, CSS, and images all load. Slower than networkidle2 but does not wait for zero network activity.
  • When in doubt: 'networkidle2' + a waitForSelector call for the element you actually need. This is the most reliable combination.
Script runs on macOS but hangs on a Linux server?
  • Linux servers typically lack a display (X11/Wayland). Puppeteer's new headless mode does not require a display, but the Chromium binary on some distributions still tries to connect to one. If you see errors mentioning DISPLAY or Xvfb, add '--headless=new' to the args array or ensure headless: true is set (the default).
  • Some minimal server distributions (Alpine Linux, for example) are missing shared libraries that Chromium requires (libatk, libdrm, libgbm). Run ldd $(node -e "console.log(require('puppeteer').executablePath())") to see which libraries are missing, then install them via the package manager.
