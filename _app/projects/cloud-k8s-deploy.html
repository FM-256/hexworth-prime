Subject

Deploy to Kubernetes

Intermediate 120 min 600 XP
Mission Brief

Your assignment is to take a containerized application from a local Docker build all the way to a running Kubernetes deployment with multiple replicas, health checks, and external access through a Service and Ingress. This is the standard production deployment pipeline used at every major cloud provider.

You will write a Dockerfile to containerize a simple web application, push the image to a registry, then author Kubernetes manifest files in YAML to define the Deployment, Service, and Ingress resources. You will use kubectl to apply these manifests, scale replicas up and down, perform rolling updates, and inspect pod health in real time.

The emphasis is on understanding the declarative model: you describe the desired state in YAML, and Kubernetes continuously reconciles the cluster to match. By the end of this operation, you will understand how pods, replica sets, services, and ingress controllers work together to serve traffic at scale.

Agent Requirements
  • Docker installed and working (docker build / docker run)
  • A local Kubernetes cluster (minikube, kind, or Docker Desktop K8s)
  • Basic understanding of containers: images, layers, port mapping
  • Comfort reading and editing YAML configuration files
  • Familiarity with the terminal and basic networking (ports, HTTP)
Operation Phases
1
Dockerfile and Container Build
Write a multi-stage Dockerfile for a simple Node.js or Python web server. Build the image with docker build -t app:v1 . and verify it runs locally with docker run -p 8080:8080 app:v1. Confirm the /healthz endpoint returns 200 OK.
2
Deployment Manifest with Replicas
Write a deployment.yaml manifest specifying 3 replicas, resource limits (CPU and memory), and environment variables from a ConfigMap. Apply with kubectl apply -f deployment.yaml. Verify all 3 pods reach Running status with kubectl get pods -w.
3
Health Checks: Liveness and Readiness Probes
Add livenessProbe and readinessProbe to the container spec targeting your /healthz and /ready endpoints. Configure initialDelaySeconds, periodSeconds, and failureThreshold. Test by temporarily breaking the health endpoint and watching Kubernetes restart the pod automatically.
4
Service and Ingress for External Access
Create a service.yaml of type ClusterIP that targets your pods by label selector. Then write an ingress.yaml that routes external HTTP traffic to the service. Verify end-to-end connectivity with curl. Add TLS termination using a self-signed certificate for HTTPS access.
5
Scaling, Rolling Updates, and Monitoring
Scale to 5 replicas with kubectl scale. Update the image tag to app:v2 and watch the rolling update proceed with zero downtime. Use kubectl rollout status and kubectl rollout undo to practice rollback. Inspect pod logs and resource usage with kubectl top pods.
