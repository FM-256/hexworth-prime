Subject

My First Container

Recruit 30 min 250 XP
Mission Brief

Run your first Docker container, build your first image, and understand why containers changed everything. Before Docker, deploying software meant praying that the server matched your laptop. Containers solved that permanently — the same image runs identically everywhere.

You will pull an image from Docker Hub, run it, expose ports, build your own custom image from a Dockerfile, and master the container lifecycle commands every cloud engineer uses daily. Everything runs locally — no cloud account required.

By the end you will understand the fundamental difference between an image (the blueprint) and a container (the running instance) — a distinction that unlocks Kubernetes, CI/CD pipelines, and every modern deployment system.

Agent Requirements
  • Docker Desktop installed (Windows/Mac) or Docker Engine (Linux) — docker.com/get-started
  • A terminal or command prompt for running Docker CLI commands
  • A web browser to verify running containers
  • A text editor to create an HTML file and Dockerfile
  • No prior Docker knowledge needed — all commands are introduced step by step
Operation Phases
Progress
0 / 4
✓
1
Run Hello World
With Docker installed, run docker run hello-world in your terminal. Docker pulls the image from Docker Hub, creates a container, runs it, and exits. Read the output carefully — it explains exactly what happened. Run docker ps -a to see all containers including stopped ones. The hello-world container shows with status "Exited". Note the container ID, the image name, and the command that ran.
Checkpoint
The "Hello from Docker!" message appeared. You can run docker ps -a and see the hello-world container in the list. In one sentence: explain the difference between a Docker image and a Docker container. If you cannot, re-read the output Docker printed — it tells you directly.
✓
2
Run a Real App
Run docker run -d -p 8080:80 nginx. The -d flag runs it detached (in the background). The -p 8080:80 maps port 8080 on your machine to port 80 inside the container. Open http://localhost:8080 in your browser — the Nginx welcome page appears. Run docker ps (without -a) to see only running containers. Stop it with docker stop <container-id> using the ID from docker ps.
Checkpoint
The Nginx welcome page is visible at http://localhost:8080. docker ps shows the container running before you stop it. After docker stop, the browser can no longer reach the page and docker ps shows no running containers.
✓
3
Build Your Own Image
Create a new folder. Inside it, create index.html with your name and a short bio as HTML. Create a file named Dockerfile (no extension) with two lines: FROM nginx:latest on line 1 and COPY index.html /usr/share/nginx/html/ on line 2. From that folder, run docker build -t mysite . — the dot is the build context (current directory). Then run docker run -d -p 9090:80 mysite and open http://localhost:9090.
Checkpoint
Your custom HTML page is served at http://localhost:9090. Run docker images and see mysite in the list alongside nginx and hello-world. This is your first custom Docker image — it packages your code and its runtime together.
✓
4
Manage Containers
Run 3 nginx containers on different ports: 8081, 8082, 8083 using -p flags. List them all with docker ps. Stop one with docker stop <id> and remove it with docker rm <id>. Remove an image with docker rmi hello-world (make sure no containers use it first). Run docker system prune to clean up stopped containers and unused images. Observe how disk space is reclaimed.
Checkpoint
You can list, stop, remove containers and remove images from the command line. Explain the full lifecycle in order: pull, run, stop, rm, rmi. You understand that removing a container does not remove the image — you can create a new container from the same image instantly.
