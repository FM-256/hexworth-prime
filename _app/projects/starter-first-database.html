My First Database

Recruit 45 min 250 XP
Mission Brief

Create your first database, write your first SQL queries, and build a Python app that stores and retrieves real data. This is the foundation of nearly every application ever built — from Instagram to banking systems, data lives in tables and SQL is the language that moves it.

You will use Python's built-in sqlite3 module — no installation required — to create a contacts database, insert records with safe parameterized queries, search by name, update emails, and delete records through a menu-driven interface.

By the end you will have a working CRUD application, a real .db file on disk, and a clear mental model of how Create, Read, Update, Delete maps to SQL commands — the same four operations every backend developer uses daily.

Agent Requirements
  • Python 3 installed — sqlite3 is built into Python, so no extra downloads are needed beyond Python itself. Check by opening a terminal and typing python --version or python3 --version — if a version number appears, you have it. If not, download Python 3 from python.org and run the installer (Windows: tick Add Python to PATH before clicking Install).
  • VS Code (free) from code.visualstudio.com — for writing your Python file. Any plain-text editor works, but VS Code is recommended because it highlights Python syntax and has a built-in terminal.
  • A terminal — the built-in terminal in VS Code is used in every phase, so you do not need a separate app. Phase 1 shows exactly how to open it.
  • No database or SQL experience required — this is your first project. Every command is shown exactly as you type it.

Set Up Your Project and Create the Database
Before any SQL you need a folder, a Python file, and a terminal. Go slowly — nothing here assumes you have done this before.
  1. Make a project folder. Right-click an empty spot on your Desktop → New Folder (Mac: right-click → New Folder). Name it my-first-database — no spaces, all lowercase. Everything you create in this project lives in here.
  2. Open that folder in VS Code. Open VS Code, then go to File → Open Folder…, click Desktop, select my-first-database, and click Open. The folder name appears in the left panel.
  3. Create your Python file. In the left panel, hover over the folder name and click the New File icon (a page with a +). Type contacts.py and press Enter. The file opens in the editor.
  4. Open the built-in terminal. In VS Code go to Terminal → New Terminal. A panel slides up at the bottom. You will type all run commands here — no separate app needed.
    Windows note: if the terminal shows PS at the start of the line, that is PowerShell and it works fine. If it shows > it is the older Command Prompt — also fine. Both run Python identically.
  5. Paste this code into contacts.py exactly as shown — indentation matters in Python, so paste rather than retype:
    import sqlite3 conn = sqlite3.connect('mydata.db') cursor = conn.cursor() cursor.execute(''' CREATE TABLE IF NOT EXISTS contacts ( id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT, email TEXT, phone TEXT ) ''') conn.commit() conn.close() print('Database ready. Table created (or already existed).')
    What each line does: import sqlite3 loads the database tool (already inside Python — nothing to download). sqlite3.connect('mydata.db') opens the database; if the file does not exist Python creates it automatically. cursor is the object you use to send SQL commands. CREATE TABLE IF NOT EXISTS creates the contacts table if it is not already there — safe to run again later without breaking anything. The four lines inside are the columns: id is a number that increments automatically; name, email, and phone are text. conn.commit() saves the change; conn.close() closes the connection.
  6. Save the file with Ctrl+S (Mac: Cmd+S).
  7. Run it. Click the terminal panel and type:
    python contacts.py
    On Mac or Linux, if that gives an error, try:
    python3 contacts.py
    On Windows, if neither works, try the py launcher:
    py contacts.py
    Use whichever one prints output — it is the same Python underneath.
Error: "python is not recognized" or "command not found"
  • Windows — fastest workaround: The py launcher is installed by Python even when python is not on your PATH. Try py --version in the terminal — if you see a version number, use py contacts.py for every run command in this project and skip the reinstall below.
  • Windows — permanent fix (if py also fails): Uninstall Python from Settings → Apps, then reinstall from python.org. On the first installer screen, tick Add python.exe to PATH before clicking Install Now. Then close and reopen VS Code.
  • Mac: Try python3 contacts.py instead. If that also fails, download Python 3 from python.org and run the .pkg installer.
  • After fixing it, run the command again.
Error: "IndentationError" or "SyntaxError"
  • Python cares about spaces. Make sure the four column lines inside CREATE TABLE each start with exactly eight spaces (two levels of four). The safest fix: delete what you typed and paste again from above.
Checkpoint — what you should see
The terminal prints: Database ready. Table created (or already existed). A file named mydata.db appears in your my-first-database folder (check the VS Code left panel — refresh it by clicking the folder icon if needed). That .db file is your database. Running the script a second time prints the same message and does not break anything — IF NOT EXISTS protects you.

Insert Contacts and Read Them Back
Now you will add rows to your table using INSERT, and read every row back using SELECT. Both run through Python — you never need a separate tool.
  1. Open contacts.py in VS Code (click it in the left panel). Replace all the code with the full version below. Read the comments (lines starting with #) — each one explains the line next to it:
    import sqlite3 # --- helpers ------------------------------------------------------- def get_conn(): """Open the database and return (conn, cursor).""" conn = sqlite3.connect('mydata.db') cursor = conn.cursor() return conn, cursor # --- CREATE table (safe to run again) ------------------------------ conn, cursor = get_conn() cursor.execute(''' CREATE TABLE IF NOT EXISTS contacts ( id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT, email TEXT, phone TEXT ) ''') conn.commit() conn.close() # --- INSERT three contacts ----------------------------------------- def add_contact(name, email, phone): conn, cursor = get_conn() # The ? marks are placeholders -- Python fills them in safely. # NEVER build SQL by gluing strings together: that causes # SQL injection bugs. Always use ? placeholders. cursor.execute( 'INSERT INTO contacts (name, email, phone) VALUES (?, ?, ?)', (name, email, phone) ) conn.commit() conn.close() print(f'Added: {name}') add_contact('Ana Rivera', 'ana@example.com', '555-0101') add_contact('Ben Okafor', 'ben@example.com', '555-0102') add_contact('Chris Nakamura','chris@example.com', '555-0103') # --- SELECT all contacts ------------------------------------------- def show_all(): conn, cursor = get_conn() cursor.execute('SELECT * FROM contacts') rows = cursor.fetchall() conn.close() print() print('ID Name Email Phone') print('-- ---------------- ------------------- ----------') for row in rows: # row is a tuple: (id, name, email, phone) print(str(row[0]).ljust(3), row[1].ljust(17), row[2].ljust(20), row[3]) print(f'({len(rows)} rows)') show_all()
  2. Save (Ctrl+S / Cmd+S), then run it in the terminal:
    python contacts.py
Why question marks instead of putting values directly in the string? Writing VALUES ('{name}', ...) is dangerous — if someone types a name like '; DROP TABLE contacts; -- the database would execute it as SQL and wipe your data. The ? placeholder tells Python to hand the value to SQLite as pure data, never as code. This is called a parameterized query and it is how every professional writes INSERT/UPDATE statements.
Seeing duplicate rows every time you run the script?
  • Each run calls add_contact three more times, adding three more rows. That is expected for now. In Phase 4 you will restructure the script so INSERT only happens when you choose it from a menu. For this phase, if your output shows 6 or 9 rows instead of 3, that is because you ran the script multiple times — nothing is broken. You can delete mydata.db from the folder (it is safe to delete — the script recreates it), then run once cleanly.
Error: "no such table: contacts"
  • Your terminal is not open in the my-first-database folder. In VS Code go to Terminal → New Terminal — it always opens in the folder that VS Code has open, which is correct. If you are in a different folder, the script creates mydata.db there and the table does not exist in the one you expect.
Checkpoint — what you should see
The terminal prints three "Added:" lines and then a formatted table:

Search by Name with WHERE and LIKE
So far you can see all rows. Now add a search that finds contacts by partial name — the same kind of search a real address book uses. The SQL keyword is WHERE, and the pattern-matching operator is LIKE.
  1. Understand the SQL first — read this before you type anything:
    SELECT * FROM contacts WHERE name LIKE ?
    SELECT * means "give me all columns". FROM contacts says which table. WHERE name LIKE ? filters rows — only return rows where the name column matches the pattern you supply. The ? is the same safe placeholder you used in Phase 2. The pattern you pass uses % as a wildcard: %naka% means "anything, then 'naka', then anything" — case-insensitive in SQLite by default.
  2. Replace contacts.py with the complete version below. Select all (Ctrl+A / Cmd+A), delete, then paste this. It includes everything from Phase 2 plus the new search_by_name function and demo calls. Notice the seed block now checks whether the table is empty first — this means you can run the script as many times as you like and always get exactly three rows with the same IDs:
    import sqlite3 # --- helpers ------------------------------------------------------- def get_conn(): """Open the database and return (conn, cursor).""" conn = sqlite3.connect('mydata.db') cursor = conn.cursor() return conn, cursor # --- CREATE table (safe to run again) ------------------------------ conn, cursor = get_conn() cursor.execute(''' CREATE TABLE IF NOT EXISTS contacts ( id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT, email TEXT, phone TEXT ) ''') conn.commit() conn.close() # --- INSERT three contacts (only if the table is empty) ------------ # Checking the row count before inserting means re-running this # script never creates duplicate rows -- the output is always the same. def add_contact(name, email, phone): conn, cursor = get_conn() cursor.execute( 'INSERT INTO contacts (name, email, phone) VALUES (?, ?, ?)', (name, email, phone) ) conn.commit() conn.close() print(f'Added: {name}') conn, cursor = get_conn() cursor.execute('SELECT COUNT(*) FROM contacts') row_count = cursor.fetchone()[0] conn.close() if row_count == 0: add_contact('Ana Rivera', 'ana@example.com', '555-0101') add_contact('Ben Okafor', 'ben@example.com', '555-0102') add_contact('Chris Nakamura','chris@example.com', '555-0103') # --- SELECT all contacts ------------------------------------------- def show_all(): conn, cursor = get_conn() cursor.execute('SELECT * FROM contacts') rows = cursor.fetchall() conn.close() print() print('ID Name Email Phone') print('-- ---------------- ------------------- ----------') for row in rows: print(str(row[0]).ljust(3), row[1].ljust(17), row[2].ljust(20), row[3]) print(f'({len(rows)} rows)') show_all() # --- SEARCH by partial name ---------------------------------------- def search_by_name(term): conn, cursor = get_conn() # % on both sides = match anywhere in the name pattern = '%' + term + '%' cursor.execute( 'SELECT * FROM contacts WHERE name LIKE ?', (pattern,) # must be a tuple -- the trailing comma matters ) rows = cursor.fetchall() conn.close() if not rows: print(f'No contacts found matching "{term}".') return print(f'\nResults for "{term}":') for row in rows: print(f' ID {row[0]}: {row[1]} | {row[2]} | {row[3]}') search_by_name('ana') # should find Ana Rivera search_by_name('naka') # should find Chris Nakamura search_by_name('xyz') # should find nobody
    Why (pattern,) with a trailing comma? Python requires the second argument to cursor.execute to be a tuple. A tuple with one item looks like ('hello',) — the comma is what makes it a tuple, not parentheses alone. Without the comma, ('hello') is just the string 'hello' in parentheses, and SQLite will raise a confusing error.
  3. Save and run:
    python contacts.py
    Run it a second time to confirm the output is identical — the seed guard keeps the row count at three.
What "case-insensitive" means: searching ana also matches Ana and ANA. SQLite's LIKE ignores upper/lower case for plain letters by default — accented characters like ñ are an edge case you do not need to worry about in this project.
The search returns no rows even though the name is in the table
  • Make sure your pattern variable wraps the term in % on both sides. Print it to check: add print(pattern) just before the cursor.execute call and look at what it says.
  • Check that (pattern,) has the trailing comma. Without it the error message is confusing but the cause is always the missing comma.
  • If you deleted and recreated mydata.db, just run the script again — the seed block will detect the empty table and re-insert the three demo contacts automatically.
Seeing more than three rows in the table
  • Your mydata.db still has rows from a Phase 2 run that inserted without the guard. Delete mydata.db from the folder (it is safe — the script recreates it), then run once. The seed block starts fresh and inserts exactly three rows with IDs 1, 2, and 3.
Checkpoint — what you should see
The terminal prints the table then the three search results. The output is identical every time you run the script — including on re-runs — because the seed guard only inserts when the table is empty:

Added: Ben Okafor

ID Name Email Phone
-- ---------------- ------------------- ----------
1 Ana Rivera ana@example.com 555-0101
2 Ben Okafor ben@example.com 555-0102

Results for "ana":

Update, Delete, and Build the Full Menu App
Add UPDATE and DELETE, then tie everything together into a menu-driven app. When you run it, you will type a number to choose an action — exactly like a real command-line tool. This is the complete version of contacts.py.
  1. Understand UPDATE and DELETE first:
    UPDATE contacts SET email = ? WHERE id = ?
    UPDATE changes existing rows. SET email = ? says which column to change. WHERE id = ? limits the change to the row with that exact ID — without WHERE, every row in the table would be updated, so always include it.
    DELETE FROM contacts WHERE id = ?
    DELETE FROM contacts removes rows. WHERE id = ? makes it remove only the one row you specify. Without WHERE, this would delete the entire table's contents.
  2. Replace contacts.py with the complete final version. Select all (Ctrl+A / Cmd+A), delete, then paste this:
    import sqlite3 # =================================================================== # HELPERS # =================================================================== def get_conn(): conn = sqlite3.connect('mydata.db') cursor = conn.cursor() return conn, cursor def setup(): """Create the table if it does not exist yet.""" conn, cursor = get_conn() cursor.execute(''' CREATE TABLE IF NOT EXISTS contacts ( id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT, email TEXT, phone TEXT ) ''') conn.commit() conn.close() # =================================================================== # CRUD FUNCTIONS # =================================================================== def add_contact(name, email, phone): conn, cursor = get_conn() cursor.execute( 'INSERT INTO contacts (name, email, phone) VALUES (?, ?, ?)', (name, email, phone) ) conn.commit() conn.close() print(f'Added contact: {name}') def show_all(): conn, cursor = get_conn() cursor.execute('SELECT * FROM contacts') rows = cursor.fetchall() conn.close() if not rows: print('No contacts yet.') return print() print('ID Name Email Phone') print('-- ---------------- ------------------- ----------') for row in rows: print(str(row[0]).ljust(3), row[1].ljust(17), row[2].ljust(20), row[3]) print(f'({len(rows)} rows)') def search_by_name(term): conn, cursor = get_conn() cursor.execute( 'SELECT * FROM contacts WHERE name LIKE ?', ('%' + term + '%',) ) rows = cursor.fetchall() conn.close() if not rows: print(f'No contacts found matching "{term}".') return print(f'\nResults for "{term}":') for row in rows: print(f' ID {row[0]}: {row[1]} | {row[2]} | {row[3]}') def update_email(contact_id, new_email): conn, cursor = get_conn() cursor.execute( 'UPDATE contacts SET email = ? WHERE id = ?', (new_email, contact_id) ) # cursor.rowcount tells us how many rows were changed changed = cursor.rowcount conn.commit() conn.close() if changed == 0: print(f'No contact with ID {contact_id}.') else: print(f'Email updated for ID {contact_id}.') def delete_contact(contact_id): conn, cursor = get_conn() cursor.execute( 'DELETE FROM contacts WHERE id = ?', (contact_id,) ) changed = cursor.rowcount conn.commit() conn.close() if changed == 0: print(f'No contact with ID {contact_id}.') else: print(f'Contact ID {contact_id} deleted.') # =================================================================== # MENU LOOP # =================================================================== def menu(): setup() # make sure the table exists every time we start print('\n=== My First Database ===') while True: print(''' 1. Add contact 2. View all 3. Search by name 4. Update email 5. Delete contact 6. Quit''') choice = input('\nEnter a number: ').strip() if choice == '1': name = input(' Name: ').strip() email = input(' Email: ').strip() phone = input(' Phone: ').strip() add_contact(name, email, phone) elif choice == '2': show_all() elif choice == '3': term = input(' Search term: ').strip() search_by_name(term) elif choice == '4': show_all() try: cid = int(input(' Enter ID to update: ')) new_email = input(' New email: ').strip() update_email(cid, new_email) except ValueError: print(' Please enter a number for the ID.') elif choice == '5': show_all() try: cid = int(input(' Enter ID to delete: ')) confirm = input(f' Delete ID {cid}? Type yes to confirm: ').strip().lower() if confirm == 'yes': delete_contact(cid) else: print(' Cancelled.') except ValueError: print(' Please enter a number for the ID.') elif choice == '6': print('Goodbye.') break else: print(' Unrecognised choice -- enter a number 1-6.') # run the menu menu()
  3. Save (Ctrl+S / Cmd+S), then run:
    python contacts.py
    The terminal shows the menu and waits for your input. Type 1 and press Enter to add a contact. Try each option.
  4. Full end-to-end test — do these steps in order:
    1. Choose 1 and add a contact of your own choosing.
    2. Choose 2 to view all — your new contact appears with an ID.
    3. Choose 3, enter a partial name — the matching row appears.
    4. Choose 4, enter the ID of one contact, supply a new email — the update message appears. Choose 2 again to confirm the change is saved.
    5. Choose 5, enter an ID, type yes to confirm — the row is deleted. Choose 2 again to confirm it is gone.
    6. Choose 6 to quit.
  5. Prove that the database persisted — this step is required. After quitting in the previous step, run the script again:
    python contacts.py
    When the menu appears, choose 2 (View all). Every contact you did not delete is still there, with the same IDs and the updated email you set. Then choose 6 to quit again.
    Why this matters: Most beginner programs lose all data when they close. Your data survived because Python wrote it to mydata.db on disk — a real file that exists independently of your script. This is what a database is: persistent, structured storage that outlives the program that created it.
What CRUD means: Create = INSERT, Read = SELECT, Update = UPDATE, Delete = DELETE. Every database application ever built — social media, banking, medical records — is some version of these four operations on tables. You have now built all four.
cursor.rowcount is the number of rows the last statement actually changed. Checking it after UPDATE or DELETE lets you detect a "that ID does not exist" mistake without crashing.
Menu keeps printing but nothing happens when I type
  • Make sure you press Enter after typing your number — the input() function waits for Enter before continuing.
  • If the terminal seems frozen, press Ctrl+C to stop the script, then run it again.
ValueError when I enter an ID
  • The ID field must be a plain number like 2, not ID 2 or #2. Type only the digits.
Data is gone when I restart the script
  • Check that mydata.db exists in your my-first-database folder. If you run the script from a different folder (for example your Desktop or Documents), Python creates a second database file there. Open VS Code's built-in terminal (Terminal → New Terminal) each time — it always opens in the correct project folder.
