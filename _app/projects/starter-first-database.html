Subject

My First Database

Recruit 45 min 250 XP
Mission Brief

Create your first database, write your first SQL queries, and build a Python app that stores and retrieves real data. This is the foundation of nearly every application ever built — from Instagram to banking systems, data lives in tables and SQL is the language that moves it.

You will use Python's built-in sqlite3 module — no installation required — to create a contacts database, insert records with safe parameterized queries, search by name, update emails, and delete records through a menu-driven interface.

By the end you will have a working CRUD application, a real .db file on disk, and a clear mental model of how Create, Read, Update, Delete maps to SQL commands — the same four operations every backend developer uses daily.

Agent Requirements
  • Python 3 installed — sqlite3 is included in the standard library, no pip needed
  • A text editor or VS Code for writing Python files
  • A terminal to run scripts and optionally the sqlite3 CLI for verification
  • Basic Python knowledge — functions, loops, and f-strings
  • Curiosity about how applications actually store data persistently
Operation Phases
Progress
0 / 4
✓
1
Create the Database
Import sqlite3 in a new Python file. Use sqlite3.connect('mydata.db') to create and open the database — the file is created automatically if it does not exist. Get a cursor with conn.cursor(). Execute a CREATE TABLE IF NOT EXISTS contacts statement with columns: id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT, email TEXT, phone TEXT. Call conn.commit() and conn.close().
Checkpoint
mydata.db exists in your project folder after running the script. Open it with the sqlite3 CLI (sqlite3 mydata.db) and run .tables — the contacts table appears. Run .schema contacts to verify all four columns are correct.
✓
2
Insert Data
Write a function add_contact(name, email, phone) that opens a connection, executes an INSERT INTO contacts (name, email, phone) VALUES (?, ?, ?) statement using the tuple (name, email, phone) as the second argument — this is a parameterized query that prevents SQL injection. Call conn.commit() after inserting. Call this function three times with different contact data to populate the table.
Checkpoint
In the sqlite3 CLI, run SELECT * FROM contacts; — exactly 3 rows appear with the correct data. The id column is auto-incremented (1, 2, 3). The question-mark placeholders in the INSERT kept your data safe from injection attacks.
✓
3
Query and Search
Write get_all() that fetches and prints all contacts using cursor.fetchall(). Format each row clearly: ID, name, email, phone. Write search(name) using SELECT * FROM contacts WHERE name LIKE ? with ('%' + name + '%',) as the parameter tuple — the percent signs enable partial matching so searching "An" finds "Ana" and "Anthony". Print results or a "no results" message.
Checkpoint
get_all() prints all 3 contacts in a readable format. Searching for a partial name returns matching contacts — searching a substring that appears in one contact name returns only that contact. Searching a string that matches no one prints a "not found" message.
✓
4
Update and Delete
Write update_email(id, new_email) using UPDATE contacts SET email=? WHERE id=?. Write delete_contact(id) using DELETE FROM contacts WHERE id=?. Build a while True menu loop that prints options and reads user input: 1 = Add, 2 = View All, 3 = Search, 4 = Update Email, 5 = Delete, 6 = Quit. Each choice calls the corresponding function. Use input() for prompts and wrap the loop in a try/except for clean exits.
Checkpoint
The full CRUD menu works end to end: add a new contact, view all, search by partial name, update an email, delete a contact, and verify the deletion with view all. The database file persists between runs — restarting the script and choosing View All still shows your data.
