Subject

Automated Web Testing with Selenium

Intermediate 2H 900 XP
Mission Brief

This operation requires the construction of a complete automated web testing framework using Python and Selenium WebDriver. You will build a test suite that navigates real web applications, fills forms, clicks buttons, waits for dynamic content to load, and asserts that the application behaves correctly — all without a human touching the browser. The framework follows the Page Object Model design pattern, separating page structure from test logic so that tests remain maintainable as the application under test evolves.

Each test case follows the arrange-act-assert pattern: set up the browser state, perform user actions through Selenium's WebDriver API, and verify outcomes with explicit assertions. The framework handles dynamic content using explicit waits with WebDriverWait and expected conditions rather than fragile sleep calls. Failed tests automatically capture full-page screenshots and browser console logs as evidence, and all results are compiled into a self-contained HTML report with pass/fail summaries, timing data, and embedded screenshots.

Automated testing is a cornerstone of both software quality and security validation. This project teaches the practical skills needed to verify web application behavior at scale — skills directly applicable to regression testing, security scanning pre-checks, and continuous integration pipelines where manual testing is simply not feasible.

Agent Requirements
  • Solid Python fundamentals: classes, inheritance, and decorator patterns
  • Basic understanding of HTML structure: elements, attributes, forms, and the DOM
  • Familiar with web browsers and developer tools — inspecting elements, viewing console output
  • Comfortable installing packages with pip and managing Chrome or Firefox on your system
  • No prior Selenium or test automation experience required — this project teaches everything from driver setup to report generation
Operation Phases
1
Test Suite & Driver Setup
Configure selenium with webdriver-manager for automatic ChromeDriver installation. Build a BaseTest class using unittest that handles browser initialization in setUp() and teardown with screenshot-on-failure in tearDown(). Configure headless mode for CI environments and visible mode for local debugging. Set default timeouts, window size, and browser options. Write the first test that simply opens a URL and verifies the page title.
2
Page Object Model
Implement the Page Object Model pattern with a BasePage class that encapsulates common operations: find(), click(), type_text(), wait_for_element(), and get_text(). Create concrete page objects for a login page, dashboard, and settings page, each exposing domain-specific methods like login(user, password) rather than raw Selenium calls. Store all locators as class constants using By.CSS_SELECTOR or By.XPATH strategies.
3
Dynamic Content & Waits
Master explicit waits using WebDriverWait combined with expected_conditions: element visibility, clickability, text presence, staleness, and custom conditions. Handle AJAX-loaded content, modal dialogs, dropdown menus, and infinite scroll patterns. Implement retry logic for flaky elements using a custom wait decorator. Test against dynamic SPAs where elements appear, disappear, and change state based on JavaScript execution.
4
Evidence Capture & Assertions
Build an evidence capture system that takes full-page screenshots at key test milestones and on every failure. Capture browser console logs using driver.get_log('browser') to detect JavaScript errors. Implement custom assertion methods that log detailed failure messages with element state, URL, and timestamp. Add visual diff capabilities that compare screenshots against baseline images to detect unintended UI changes.
5
HTML Report Generation
Build a self-contained HTML test report that includes: test name, status (pass/fail/skip), execution time, failure message, and embedded base64 screenshots. Generate the report using Python's html module or Jinja2 templates. Include a summary dashboard at the top showing total pass rate, slowest tests, and failure trends. Add command-line arguments for selecting test suites, setting the base URL, and choosing the browser. Wire everything into a run_tests.py entry point.
