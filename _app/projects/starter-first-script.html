Subject

My First Script

Recruit 30 min 250 XP
Mission Brief

Write your first Bash script that organizes messy files into folders automatically — your first taste of automation. This is the moment you stop doing things by hand and start making the computer do them for you: the core principle behind every sysadmin, DevOps engineer, and power user.

You will create an executable shell script with a shebang line, make target directories with mkdir -p, move files by extension using glob patterns, and generate a summary report with file counts using command substitution. The same techniques power deployment scripts, backup jobs, and CI/CD pipelines.

By the end you will have a real, executable automation tool and a clear mental model of how Bash scripts are structured, executed, and extended. Caution: mv moves files permanently — not to a Recycle Bin. Test in the practice folder this project creates, not in a real folder containing files you care about.

Agent Requirements
  • A terminal. Mac and Linux have one built in. Windows users: use Git Bash (installed automatically with Git for Windows — free at git-scm.com, under a minute). Git Bash runs on your normal Windows filesystem — no Ubuntu install, no username/password setup. Phase 1 walks you through it.
  • VS Code (code.visualstudio.com, free) — use it on all operating systems. You will write organize.sh in VS Code and run it from the terminal. Do not use Notepad or Microsoft Word.
  • No prior scripting experience. Every command is shown in full, including how to open the terminal, create a folder, and navigate to it.
  • Minimal disk space required — the script and test files are a few kilobytes.

Open a Terminal and Create Your Script
Before any code you need a running terminal and a project folder. Go slowly — nothing here assumes you have done this before.
  1. Open a terminal.
    Mac: Press Cmd+Space, type Terminal, press Enter. A black or white window appears with a blinking cursor. That is your terminal.
    Linux: Press Ctrl+Alt+T. If that doesn’t work, right-click the desktop and choose Open Terminal.
    Windows (primary — Git Bash): Install Git for Windows from git-scm.com (free, under a minute, accept all defaults). Afterward open Start, type Git Bash, and press Enter. A terminal window opens directly on your normal Windows filesystem — no Ubuntu setup or password required. Use this for the rest of the project.
    Windows (advanced alternative — WSL): WSL (Windows Subsystem for Linux) gives you a full Ubuntu environment and is more representative of real sysadmin work — but it requires more setup. From an elevated PowerShell run wsl --install, restart your machine, then complete the Ubuntu first-run (create a username and password; the cursor will not move when you type the password — that is normal). WSL uses a separate Linux filesystem and takes 1–4 GB of disk space. To edit files inside WSL with VS Code, open a WSL terminal and type code . (this launches VS Code in Remote-WSL mode so paths work correctly).
    What the prompt means: you will see something like alex@laptop:~$. Everything before $ just tells you who you are and where you are. You type your commands after the $ and press Enter to run them.
  2. Create a project folder and move into it. Type each command and press Enter after each one:
    mkdir ~/my-first-script cd ~/my-first-script
    mkdir makes a folder. ~ means “your home folder” — the same place as your user's Documents and Desktop. cd moves you into it. You should see the prompt change to show my-first-script at the end, or you can confirm with:
    pwd
    That prints your current location. It should end with /my-first-script.
  3. Create the script file in VS Code. In VS Code, open the folder you just created: choose File → Open Folder, navigate to your home folder, and select my-first-script. Then click the New File icon in the Explorer panel (or press Ctrl+N / Cmd+N), name the file organize.sh, and press Enter. The file is now open and ready to edit.
    Git Bash users: your home folder is at C:\Users\YourName. VS Code’s Open Folder navigates normal Windows paths, so browse there and select my-first-script directly.
  4. Type the shebang line. The very first line of every Bash script must be:
    #!/bin/bash
    This tells the operating system “run this file using Bash.” Without it, the OS doesn’t know what language your script is written in. Type it exactly — the #! pair is called a shebang (a contraction of “hash-bang”).
  5. Add a first echo line on the line directly below the shebang:
    echo "Starting file organizer..."
    echo prints text to the terminal. This line is a quick sanity check that the script runs at all before you add the real logic.
  6. Your file so far — it should look exactly like this:
    organize.sh (complete file so far)#!/bin/bash echo "Starting file organizer..."
  7. Save the file. Press Ctrl+S (Windows/Linux) or Cmd+S (Mac). Switch back to your terminal window.
  8. Make the script executable. Right now the file is just text. This command tells the OS “this file is allowed to run as a program”:
    chmod +x organize.sh
    chmod changes permissions. +x adds the “execute” permission. You only need to do this once per script.
  9. Run the script:
    ./organize.sh
    The ./ means “run the file in my current folder.” You must include it — just typing organize.sh won’t work because the terminal only looks in system folders by default.
Permission denied: you skipped chmod +x organize.sh. Run it now, then try ./organize.sh again.
bash: ./organize.sh: No such file or directory: you are not in the right folder. Run pwd to see where you are, then run cd ~/my-first-script to get back.
Windows — bad interpreter or “\r” errors: this happens when the file was saved with Windows line endings (CRLF) instead of Unix line endings (LF). In VS Code, look at the bottom-right status bar — it will say CRLF. Click it, choose LF, then save (Ctrl+S). Alternatively, fix it from the terminal: sed -i 's/\r//' organize.sh, then re-run.
Checkpoint — what you should see
Running ./organize.sh prints exactly one line: Starting file organizer.... Nothing else should happen yet. The prompt returns underneath it. If you see that one line, your terminal, file, permissions, and shebang are all working — proceed to Phase 2.
✓
2
Add the Folder-Creation Commands
Now you will open the script and add the lines that create destination folders. Every addition in Phases 2–4 follows the same rhythm: open the file, add lines, save, run, verify.
  1. Return to VS Code — the file is still open. Click at the end of the echo line and press Enter to start a new line. VS Code auto-saves when you switch focus, but press Ctrl+S / Cmd+S after each edit to be sure.
  2. Add a blank line for readability, then add four mkdir commands, one per line. Type them exactly:
    mkdir -p Images mkdir -p Documents mkdir -p Videos mkdir -p Other
    mkdir stands for “make directory” (directory = folder). The -p flag means “don’t complain if the folder already exists” — without it, running the script twice would print an error. With it, the script is safe to run many times.
  3. Add a confirmation echo after each mkdir so you can see the script’s progress. Add these four lines below your mkdir block:
    echo "Folders ready: Images/ Documents/ Videos/ Other/"
  4. Your complete file right now:
    organize.sh (complete file so far)#!/bin/bash echo "Starting file organizer..." mkdir -p Images mkdir -p Documents mkdir -p Videos mkdir -p Other echo "Folders ready: Images/ Documents/ Videos/ Other/"
  5. Save in VS Code. Press Ctrl+S (Windows/Linux) or Cmd+S (Mac).
  6. Run the script:
    ./organize.sh
  7. Check that the folders were created:
    ls
    You should see Images, Documents, Videos, Other, and organize.sh listed.
  8. Run the script a second time to confirm no errors appear:
    ./organize.sh
    The output should be identical to the first run. The -p flag suppresses “directory already exists” errors.
What to ignore: if the terminal briefly shows nothing between commands, that is normal. Bash executes silently unless you print something. The only output you should see is what your echo lines print.
mkdir: cannot create directory ‘Images’: File exists — you forgot the -p flag on one of the lines. Open the file and add -p after mkdir on every line. Make sure there is a space between mkdir and -p and another space before the folder name.
Checkpoint — what you should see
Running the script prints two lines: Starting file organizer... Folders ready: Images/ Documents/ Videos/ Other/ Running ls shows the four new folders alongside organize.sh. Running the script a second time produces the same output with no error messages. If ls shows any folders missing, re-open the file and confirm each mkdir line is on its own line with no extra spaces at the start.
✓
3
Move Files by Extension Using Glob Patterns
This is the core automation step. You will create dummy test files, then add mv commands that use wildcards to sort them by extension into the right folder — automatically.
  1. Create test files in the project folder. Make sure you are still in my-first-script (run pwd to confirm). Then run:
    touch photo.jpg portrait.png report.pdf notes.txt clip.mp4 random.xyz
    touch creates empty files instantly — perfect for testing. Run ls to confirm the six files exist alongside the four folders and organize.sh.
    What to ignore: the files are truly empty (0 bytes). That is fine. The script only looks at the filename extension (.jpg, .pdf, etc.), not the contents.
  2. Switch to VS Code. The file is still open. Click at the end of the echo "Folders ready..." line and press Enter to start a new line.
  3. Add a blank line and the heading echo:
    echo "Sorting files..."
  4. Add the move commands, one per file type. A * wildcard means “match anything.” So *.jpg means “every file whose name ends in .jpg.” Add these four lines:
    mv *.jpg *.png *.gif Images/ 2>/dev/null mv *.pdf *.docx *.txt Documents/ 2>/dev/null mv *.mp4 *.avi *.mov Videos/ 2>/dev/null mv *.xyz Other/ 2>/dev/null
    What 2>/dev/null does: each mv line tries to move every pattern on that line. If there are no .gif files, Bash would normally print an error. 2> redirects error messages away from the screen; /dev/null is a built-in trash can that discards whatever is sent to it. Your real output (the echo lines) still prints normally.
  5. Your complete file right now:
    organize.sh (complete file so far)#!/bin/bash echo "Starting file organizer..." mkdir -p Images mkdir -p Documents mkdir -p Videos mkdir -p Other echo "Folders ready: Images/ Documents/ Videos/ Other/" echo "Sorting files..." mv *.jpg *.png *.gif Images/ 2>/dev/null mv *.pdf *.docx *.txt Documents/ 2>/dev/null mv *.mp4 *.avi *.mov Videos/ 2>/dev/null mv *.xyz Other/ 2>/dev/null
  6. Save in VS Code (Ctrl+S / Cmd+S).
  7. Run the script:
    ./organize.sh
  8. Verify the files moved to the right folders:
    ls Images/ ls Documents/ ls Videos/ ls Other/
    Expected output per folder:
    expected ls outputImages/ photo.jpg portrait.png Documents/ notes.txt report.pdf Videos/ clip.mp4 Other/ random.xyz
Files did not move — all four folders show empty: confirm the test files were created in the same folder as organize.sh. Run ls in my-first-script before running the script. If you created the files somewhere else (e.g. your home folder), cd into my-first-script and run touch photo.jpg portrait.png report.pdf notes.txt clip.mp4 random.xyz again, then re-run the script.
mv: cannot stat ‘*.jpg’: No such file or directory (without 2>/dev/null): this is exactly why 2>/dev/null is there. Confirm you have it on every mv line. If the error still appears, you may have a typo — the two characters are 2 (the digit), > (greater-than), /dev/null.
organize.sh itself disappeared: the wildcard * matched the script. This should not happen with this specific pattern list, but if you expand it with something like mv * Other/ you could accidentally move the script itself. Always use specific extensions (*.jpg, *.pdf) rather than bare *.
Checkpoint — what you should see
After running ./organize.sh, the terminal prints: Starting file organizer... Folders ready: Images/ Documents/ Videos/ Other/ Sorting files... Running ls Images/ shows photo.jpg and portrait.png. Running ls Documents/ shows report.pdf and notes.txt. Running ls Videos/ shows clip.mp4. Running ls Other/ shows random.xyz. The root folder (ls) now shows only the four folders and organize.sh — all six test files have been sorted.

4
Add a Self-Reporting Summary
The script sorts files but currently says nothing about how many it moved. You will add a summary that uses variables and command substitution to count what ended up in each folder and print a clean report.
  1. Re-create the test files so there is something to sort. Run these two commands: the first moves back into my-first-script in case you navigated elsewhere; the second re-creates the test files:
    cd ~/my-first-script touch photo.jpg portrait.png report.pdf notes.txt clip.mp4 random.xyz
    Confirm with ls — you should see the six test files plus the four folders plus organize.sh.
  2. Switch to VS Code. The file is still open. Click at the end of the last line (mv *.xyz Other/ 2>/dev/null) and press Enter to add a new line.
  3. Add the count variables. $() is command substitution: Bash runs the command inside the parentheses and gives its output to the variable. ls Images/ lists files in the folder; wc -l counts lines (one per file). Add these four lines:
    img_count=$(ls Images/ | wc -l) doc_count=$(ls Documents/ | wc -l) vid_count=$(ls Videos/ | wc -l) other_count=$(ls Other/ | wc -l)
    Variable naming rules: no spaces around the = sign; spaces break it. The name before = is the variable; the $ before the name is only used when you read back the value (as in the echo lines below).
  4. Add the report echo lines directly below the variable lines:
    echo "--- Summary ---" echo "Images: $img_count files" echo "Documents: $doc_count files" echo "Videos: $vid_count files" echo "Other: $other_count files" echo "Done."
    The $img_count syntax tells Bash “insert the value of the variable named img_count here.” The quotes around the entire echo string are needed so the shell treats the whole message as one piece of text.
  5. Your finished script — the complete file from top to bottom:
    organize.sh (finished — complete file)#!/bin/bash echo "Starting file organizer..." mkdir -p Images mkdir -p Documents mkdir -p Videos mkdir -p Other echo "Folders ready: Images/ Documents/ Videos/ Other/" echo "Sorting files..." mv *.jpg *.png *.gif Images/ 2>/dev/null mv *.pdf *.docx *.txt Documents/ 2>/dev/null mv *.mp4 *.avi *.mov Videos/ 2>/dev/null mv *.xyz Other/ 2>/dev/null img_count=$(ls Images/ | wc -l) doc_count=$(ls Documents/ | wc -l) vid_count=$(ls Videos/ | wc -l) other_count=$(ls Other/ | wc -l) echo "--- Summary ---" echo "Images: $img_count files" echo "Documents: $doc_count files" echo "Videos: $vid_count files" echo "Other: $other_count files" echo "Done."
  6. Save in VS Code (Ctrl+S / Cmd+S).
  7. Run the finished script:
    ./organize.sh
  8. Expected terminal output:
    expected terminal outputStarting file organizer... Folders ready: Images/ Documents/ Videos/ Other/ Sorting files... --- Summary --- Images: 2 files Documents: 2 files Videos: 1 files Other: 1 files Done.
    The numbers match the six test files you created: 2 images (photo.jpg, portrait.png), 2 documents (report.pdf, notes.txt), 1 video (clip.mp4), 1 other (random.xyz).
  9. Test accumulation. This is how professionals verify automation tools. Run:
    touch a.jpg b.jpg c.jpg d.pdf e.mp4 ./organize.sh
    The counts reflect whatever is currently in each folder, and they accumulate across runs — any files already sorted from earlier runs are already counted. Adding 3 new .jpg files and re-running should raise the Images count by 3 compared to the previous run. Any category that does not increase as expected points to a typo in the matching mv line.
All counts show 0: the mv commands in Phase 3 moved the files, but then you re-created them inside a subfolder rather than in my-first-script itself. Confirm pwd shows /home/yourname/my-first-script before running touch. If counts still show 0, run ls Images/ manually — if it is empty, re-run touch photo.jpg portrait.png in the right folder and try again.
The count is higher than expected: the count reflects every file currently in the folder, including files placed there by earlier runs. The script accumulates — it does not clear the folders before sorting. If you want a clean baseline, empty the subfolders first: rm -i Images/* (the -i flag prompts before each deletion), then recreate your test files and re-run.
Script runs but prints no summary lines: check for a typo in the variable names. The name after $ in the echo lines must exactly match the name before = in the assignment lines — Bash variables are case-sensitive: $img_count and $Img_count are different names.
Checkpoint — what you should see
The finished script runs from start to finish, prints a two-line header, a sorting status line, a four-line summary with the correct file counts, and “Done.” Re-creating the test files and re-running the script produces updated counts each time. That is a real, working automation tool — and you wrote it from scratch. When you want to use it on real files, copy it into a test folder first — mv moves files permanently, so always verify it in a safe location before pointing it at files you care about.
