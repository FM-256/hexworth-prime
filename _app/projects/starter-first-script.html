Subject

My First Script

Beginner 30 min 250 XP
Mission Brief

Write your first Bash script that organizes messy files into folders automatically — your first taste of automation. This is the moment you stop doing things by hand and start making the computer do them for you: the core principle behind every sysadmin, DevOps engineer, and power user.

You will create an executable shell script with a shebang line, make target directories with mkdir -p, move files by extension using glob patterns, and generate a summary report with file counts using command substitution. The same techniques power deployment scripts, backup jobs, and CI/CD pipelines.

By the end you will have a real, executable automation tool that you can drop into any messy downloads folder and run — and a clear mental model of how Bash scripts are structured, executed, and extended.

Agent Requirements
  • A Linux or macOS terminal (or WSL on Windows)
  • Basic familiarity with navigating directories using cd and ls
  • A text editor accessible from the terminal (nano, vim, or VS Code)
  • No prior scripting experience required
Operation Phases
Progress
0 / 4
✓
1
Create the Script
Create a new file called organize.sh in a test folder. The very first line must be the shebang: #!/bin/bash. This tells the OS to use Bash to execute the script. Add a line below it: echo "Starting file organizer...". Save the file. Make it executable with: chmod +x organize.sh. Run it with: ./organize.sh.
Checkpoint
Running ./organize.sh prints "Starting file organizer..." to the terminal. If you see "Permission denied", the chmod +x step was missed. If you see "No such file", confirm you are in the same directory as the script.
✓
2
Create Target Folders
After the echo line, add four mkdir -p commands to create destination folders: mkdir -p Images, mkdir -p Documents, mkdir -p Videos, and mkdir -p Other. The -p flag prevents errors if the folder already exists. Add an echo statement after each to confirm creation, for example: echo "Created: Images/".
Checkpoint
Running the script creates four folders and prints four confirmation messages. Run ls to confirm Images, Documents, Videos, and Other all exist. Run the script a second time — the -p flag should prevent "already exists" errors.
✓
3
Move Files by Extension
Create test files first: touch test.jpg photo.png doc.pdf notes.txt clip.mp4 random.xyz. Add move commands to the script using glob patterns and error suppression: mv *.jpg *.png *.gif Images/ 2>/dev/null. Add: mv *.pdf *.docx *.txt Documents/ 2>/dev/null. Add: mv *.mp4 *.avi *.mov Videos/ 2>/dev/null. Add: mv *.xyz Other/ 2>/dev/null. The 2>/dev/null suppresses errors when no matching files exist.
Checkpoint
After running the script, the test files have moved to their correct folders. Check with ls Images/, ls Documents/, and ls Videos/. The random.xyz file should be in Other/. If files are missing, confirm the touch command created them in the same directory as the script.
✓
4
Add a Summary
After the move commands, add a summary report using command substitution to count files in each folder. For each folder, assign the count to a variable: img_count=$(ls Images/ | wc -l). Do the same for Documents, Videos, and Other. Then print the report: echo "--- Summary ---", echo "Images: $img_count files", echo "Documents: $doc_count files", echo "Videos: $vid_count files", echo "Other: $other_count files".
Checkpoint
The script ends with a printed summary showing the correct file count for each category. Re-create the test files with touch and run the script again from scratch — the counts should match the number of files you created. The script is now a complete, self-reporting automation tool.
