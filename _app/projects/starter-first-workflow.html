Subject

My First Workflow

Adaptive · L1–5 30 min – 3 hr 250 – 1500 XP
Mission Brief

A workflow is automation that runs without you. Strip away the buzzwords and it is four things you wire together: a trigger (when to start), actions (what to do), logic (how to decide), and, when it matters, an AI step and a human approval. This is the plumbing AI agents actually run on, so it is the natural next build after My First Agent.

You will build one real thing and grow it across five levels: a Help-Desk Ticket Intake flow in Microsoft Power Automate (no code). Level 1 is a single trigger and action you finish in half an hour. Each level after adds exactly one capability to the same flow: branching, then AI classification, then a human approval gate, and finally a scheduled daily operation with error handling. Stop at any level and you still have a working automation.

The progression is deliberately safe. Early levels only notify and log; the consequential actions (creating accounts, changing data) never run until you have built the approval gate in Level 4. By the end you will have automated a small business process end to end, and you will understand exactly which piece does what.

Agent Requirements
  • A Microsoft account with Power Automate access (a free/developer plan works for Levels 1–2)
  • AI Builder or a GPT/AI action available in your environment (for Level 3 onward)
  • A web browser — the flow is built entirely in the Power Automate maker portal, no installs
  • The provided sample pack: a request form, a tracking spreadsheet, and a sample ticket list
  • No production systems and no real accounts — Levels 1–3 only notify and log
  • No prior automation or programming experience required to start
Operation Phases — Five Levels, One Growing Flow

1
Level 1: Trigger and Action
Beginner~30 min+250 XP
Open Power Automate and build your first automated flow: a trigger plus one action. When a help-desk request form is submitted (or a new row lands in a request spreadsheet), the flow automatically posts a notification to your help-desk channel or email. No code; you connect a trigger to an action and turn it on.
Skills: triggers, actions, connectors, the flow maker portal.
Win conditionSubmitting the request form fires the flow automatically (no manual run) and a notification arrives within about a minute.
Checkpoint — how to verify
Submit a test entry to the form/sheet. Open the flow's Run history; you should see a run marked Succeeded, and the notification should appear in your channel/inbox. If no run shows up, confirm the trigger points at the correct form/sheet and the flow toggle is On.
✓
2
Level 2: Multi-Step and Branching
Beginner+~45 min+250 XP
Make the flow decide. Add a Condition that branches on the request's category (Password / Hardware / Other) and route each branch differently: notify the right team, set a priority, and log the ticket to the matching tracking list. Chain three or four actions across the branches using the form's fields as dynamic content.
Skills: conditions and branching, multiple actions, dynamic content, basic expressions.
Win conditionA Password request and a Hardware request take different branches and reach different teams/lists.
Checkpoint — how to verify
Submit one Password request and one Hardware request. In Run history, open each run and confirm it followed the correct branch and the right team/list received it. If both take the same path, check the Condition's chosen field and its compare value.
✓
3
Level 3: AI-Powered Flow
Intermediate~1 hr+300 XP
Add intelligence. Insert an AI step (AI Builder or a GPT action) that reads the free-text request, classifies its urgency as Low / Medium / High, and writes a one-line summary. Feed the AI's output back into the flow: set the ticket priority from the urgency and route High items to the front of the queue.
Skills: AI Builder / GPT action, prompt design inside a flow, using AI output in later steps.
Win conditionA vague free-text request gets an AI urgency label and a readable summary, and a High item is routed or flagged differently than a Low one.
Checkpoint — how to verify
Submit a clearly urgent request ("server down, whole office offline") and a trivial one ("how do I change my desktop wallpaper"). Confirm the AI tags them High and Low, the one-line summaries are sensible, and the High one is escalated. If the label is always the same, refine the AI prompt with one example of each urgency level.
✓
4
Level 4: Approval Flow
Intermediate+~1.5 hr+350 XP
Put a human in the loop. Before the flow takes a consequential action (auto-creating an account, resetting a password, or closing a ticket), add an Approval step that pauses and asks a person to Approve or Reject. The action runs only on approval; on rejection the flow stops and tells the requester why.
Skills: approvals, human-in-the-loop, waiting on a response, conditional branches.
Guardrails. Any consequential action (account changes, password resets, anything that touches a real user or system) must sit behind an approval. The flow never auto-executes those on its own.
Win conditionA request that would trigger the consequential action pauses for approval; approving runs it, rejecting stops it and notifies the requester.
Checkpoint — how to verify
Trigger the consequential path and confirm the flow pauses and sends an approval request (an email or Teams card). Approve it and confirm the action completes. Run it again and Reject, then confirm the action did not happen and the requester was notified. If the action runs before you respond, the approval step is placed after the action instead of before it.
✓
5
Level 5: Scheduled Operations Flow
Advanced~2-3 hr+350 XP
Run the desk on a timer. Build a scheduled flow (for example, every weekday at 8am) that pulls the day's open tickets, has AI summarize the backlog, posts a digest report to the team, and alerts a manager if the backlog exceeds a threshold. Add error handling (configure run-after, or a Try/Catch scope) so a failed step raises an alert instead of failing silently.
Skills: scheduled (recurrence) triggers, multi-connector orchestration, AI summarization, error handling, governance.
Guardrails. The scheduled flow reports and alerts; it does not silently change data. Failures must surface as an alert, never pass unnoticed.
Win conditionThe flow runs end to end on its schedule (pull → summarize → report → conditional alert), and when a step is made to fail it sends a failure alert rather than dying silently.
Checkpoint — how to verify
Run the flow manually (don't wait for the schedule). Confirm the digest posts with an AI summary and that the manager alert fires only when the backlog is over the threshold (test both above and below). Then deliberately break a step (point it at a missing list) and confirm the error-handling path sends you a failure alert. If a broken step fails silently, the run-after / scope error handling isn't wired.
