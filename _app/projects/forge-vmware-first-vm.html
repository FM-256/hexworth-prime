Subject

Build a VM with VMware Workstation

Recruit 90 min 200 XP
Mission Brief

Install VMware Workstation Pro on your Windows or Linux host and build a running Ubuntu Server 26.04 LTS virtual machine from scratch. VMware Workstation Pro is the industry-standard Type 2 hypervisor used in enterprise environments and professional home labs worldwide. As of November 2024, Broadcom makes it free for personal use — no license key required.

This project uses Ubuntu Server, not Ubuntu Desktop. Ubuntu Server has no graphical desktop environment — you interact with it entirely through the terminal, exactly as real servers operate. That is intentional. You will complete the Ubuntu installer in a text-driven subiquity interface, log in at a command prompt, and run shell commands from there. If you have never done this before, this project is your first real taste of server administration.

By the end you will have a fully booted, network-connected Ubuntu Server VM you can SSH into, install packages on, and use as a lab target for other Forge and Shield projects.

Agent Requirements
  • 64-bit host computer running Windows 10/11 or a 64-bit Linux distribution — VMware Workstation Pro 17.x does not run on 32-bit operating systems.
  • Hardware virtualization enabled in BIOS/UEFI — called Intel VT-x or AMD-V. Most machines have this on by default; if Workstation shows a warning during install, see Phase 1 for how to enable it.
  • At least 8 GB of RAM on the host — you will assign 2 GB to the VM, leaving enough for Windows plus Workstation. 4 GB hosts will work but will feel slow.
  • At least 25 GB of free disk space — the Ubuntu Server VM disk image grows to roughly 5–8 GB after install, but Workstation pre-allocates or expands into the space you configure (20 GB recommended for the VM).
  • A free Broadcom account — required to download Workstation Pro from the Broadcom Support Portal. Registration is free; see Phase 1.
  • No prior Linux or VMware experience required — every step is explained from the beginning.

Verify Prereqs, Enable VT-x / AMD-V, and Install VMware Workstation Pro
Check that hardware virtualization is on, create a free Broadcom account, and install VMware Workstation Pro 17.x (free for personal use since November 2024).
  1. Check whether hardware virtualization is already enabled. On Windows 10/11, press Ctrl + Shift + Esc to open Task Manager, click the Performance tab, then click CPU. Look for the line that reads Virtualization: Enabled. If it says Enabled, skip to step 3. If it says Disabled, continue to step 2.
    On Linux hosts: run grep -E --color 'vmx|svm' /proc/cpuinfo in a terminal. Output with highlighted vmx (Intel) or svm (AMD) flags means virtualization is enabled. No output means it is disabled in BIOS.
  2. Enable VT-x or AMD-V in BIOS/UEFI if it was disabled. Restart your computer and enter the BIOS/UEFI setup utility. The key to press during boot varies by manufacturer: typically F2, Delete, or F10. Once inside, look for a section named Advanced, CPU Configuration, or Virtualization Technology. Set Intel Virtualization Technology (VT-x) or AMD-V / SVM Mode to Enabled. Save and exit (usually F10). Your computer will reboot normally.
    Cannot find the virtualization setting in BIOS?
    • Search for your exact laptop/motherboard model plus "enable VT-x BIOS" — the setting location varies widely by manufacturer.
    • Some recent machines ship with virtualization under Security rather than Advanced.
    • If the setting is grayed out: this can mean your CPU does not support virtualization (rare on machines purchased after 2015) or the firmware is locked by a corporate policy (common on managed work laptops).
  3. Check for a Hyper-V conflict (Windows hosts only). Hyper-V is Microsoft's built-in hypervisor. When Hyper-V's hypervisor is active, VMware Workstation versions older than 17.x cannot run VMs because they cannot both own VT-x at the same time. Workstation Pro 17.x added support for running alongside Hyper-V on Windows 10/11 (version 2004 and later), so in most cases you no longer need to disable Hyper-V — though running alongside Hyper-V can reduce VM performance and turns off nested virtualization. Note that WSL 2, Windows Sandbox, and Credential Guard also hold the hypervisor. Try launching your VM first; only use the fix below if you actually hit the conflict error. If you see an error message from Workstation during install or first VM launch that reads "VMware Workstation and Hyper-V are not compatible", your Windows build may be below the required version, or you may be running an older Workstation. The fix in that case is:
    bcdedit /set hypervisorlaunchtype off
    Run this in an Administrator Command Prompt, then reboot. This disables the Hyper-V hypervisor (but keeps the Hyper-V management tools installed). To re-enable Hyper-V later:
    bcdedit /set hypervisorlaunchtype auto
    What this affects: disabling hypervisorlaunchtype turns off WSL 2, Windows Sandbox, and Android app support in Windows 11 until you re-enable it. If you need WSL 2 or Sandbox, do NOT run this command — Workstation 17.x already co-exists with Hyper-V on Windows 10/11 2004+ (at a small VM-performance cost), so run your VM first and only disable Hyper-V if it genuinely fails.
  4. Create a free Broadcom account. Go to support.broadcom.com and click Register. Fill in your name, email, and country. You may also be prompted to complete a Trade Compliance step (an export-control requirement) — if it appears, fill it out honestly with your actual country. After confirming your email, your account is active.
    Why a Broadcom account is required: Broadcom acquired VMware in 2023. All VMware software downloads moved to the Broadcom Support Portal. The free personal-use tier still requires an account for identity and export-control verification. This is a one-time registration.
  5. Download VMware Workstation Pro 17.x. Log in to support.broadcom.com. In the top navigation, click Software, then My Downloads. In the search or product list, find VMware Workstation Pro. Select the current 17.x release (use the latest version the portal offers). Choose your platform: Workstation 17.x Pro for Windows or Workstation 17.x Pro for Linux. Accept the end-user license agreement and start the download. The Windows installer is approximately 620 MB (filename: VMware-workstation-full-17.x.x-XXXXXXXX.exe).
    Can't find the download in My Downloads?
    • After login, some accounts require you to visit the product page directly. Try navigating to support.broadcom.com/group/ecx/productdownloads?subfamily=VMware+Workstation+Pro.
    • If you were shown a Trade Compliance step and did not finish it, downloads may be blocked even after login. Check your account profile for a pending compliance step.
    • The portal can be slow. If the page shows no products after login, wait 60 seconds and refresh.
  6. Run the installer (Windows). Double-click the .exe you downloaded. When Windows asks "Do you want to allow this app to make changes?" click Yes. The VMware Workstation Pro Setup Wizard opens. Click Next through the welcome screen. On the License Agreement screen, check I accept the terms and click Next. On the Custom Setup screen, leave all defaults and click Next. On the User Experience Settings screen, uncheck Help improve VMware Workstation Pro if you prefer not to send usage data, then click Next. Click Install. Installation takes 2–4 minutes. When it finishes, click Finish. You do not need to enter a license key — leave that field blank and the application launches in personal-use free mode.
    Linux install: after downloading the .bundle file, make it executable and run it as root: chmod +x VMware-Workstation-Full-17.x.x-XXXXXXXX.x86_64.bundle && sudo ./VMware-Workstation-Full-17.x.x-XXXXXXXX.x86_64.bundle. Follow the GUI wizard. Kernel headers must be installed first: sudo apt install linux-headers-$(uname -r) on Ubuntu/Debian.
Checkpoint — what you should see
VMware Workstation Pro 17.x opens. The home screen shows a Library panel on the left (currently empty) and a Create a New Virtual Machine link in the center. The title bar reads VMware Workstation with no "trial" or "expired" banner. If a license key dialog appears, close it without entering anything — personal-use mode requires no key.

Download the Ubuntu Server 26.04 LTS ISO
Get the official Ubuntu Server installer image from Canonical. This is the file you will point VMware at when creating the VM.
  1. Go to the Ubuntu Server download page. Open a browser and navigate to ubuntu.com/download/server. The page recommends Ubuntu Server 26.04 LTS (Resolute Raccoon) as the current long-term support release. LTS releases are supported for five years of standard updates, making them the right choice for a lab environment you want to stay stable.
    What LTS means: Canonical releases a new Ubuntu LTS every two years. The 26.04 designation means April 2026 release. Non-LTS releases (like 25.10) get only nine months of updates and are not recommended for learning environments.
  2. Click the green Download button for Ubuntu Server 26.04 LTS. The download is the server install image for 64-bit PC (AMD64): ubuntu-26.04-live-server-amd64.iso, approximately 2.7–3 GB. Save it somewhere you will remember — your Downloads folder is fine.
    Do not download the Desktop image (ubuntu-26.04-desktop-amd64.iso, about 6 GB). The Desktop ISO installs a full graphical desktop environment (GNOME), which consumes significantly more RAM and disk and is not what real servers use. The Server ISO gives you a lean system accessed entirely by terminal, which is what this project targets.
  3. Verify the download completed without corruption (optional but recommended). On the same Ubuntu download page, find the Verify your download section and copy the SHA-256 checksum for 26.04. On Windows, open PowerShell and run:
    Get-FileHash "$env:USERPROFILE\Downloads\ubuntu-26.04-live-server-amd64.iso" -Algorithm SHA256
    Compare the output hash to the value from the Ubuntu page. They must match exactly. A mismatch means the file is corrupted or was tampered with — delete it and re-download.
    On Linux hosts: sha256sum ~/Downloads/ubuntu-26.04-live-server-amd64.iso and compare to Canonical's published value.
Checkpoint — what you should see
The file ubuntu-26.04-live-server-amd64.iso is in your Downloads folder and is approximately 2.7–3 GB. If you ran the checksum, it matches the value published on ubuntu.com exactly.
✓
3
Create the Virtual Machine in VMware
Configure a new VM using VMware's New Virtual Machine Wizard. Set hardware resources and attach the Ubuntu ISO so the VM boots from it.
  1. Open the New Virtual Machine Wizard. In VMware Workstation, click File > New Virtual Machine (or press Ctrl+N). The wizard opens. Select Typical (recommended) and click Next.
  2. Point the wizard at your Ubuntu ISO. On the Guest Operating System Installation screen, select Installer disc image file (iso). Click Browse and navigate to the ubuntu-26.04-live-server-amd64.iso you downloaded in Phase 2. Select it and click Open.
    VMware's Easy Install detection: when you select an Ubuntu ISO, VMware reads the ISO metadata and may display an "Easy Install" section where you enter a full name, username, and password. If this appears, fill in your preferred username and a password you will remember. Easy Install tells VMware to pre-answer some installer prompts automatically — however, for Ubuntu Server 26.04 using the modern subiquity installer, Easy Install's automation is limited and you will still walk through the installer screens manually in Phase 4. Filling in the username/password here is still useful because Workstation will display it as a reminder during install.
  3. Set the guest operating system type. The wizard should auto-detect Linux / Ubuntu 64-bit. If it shows anything else, use the dropdown to select Linux as the Guest OS and Ubuntu 64-bit as the version. Click Next.
  4. Name the VM and choose where to store it. Give your VM a name — something like ubuntu-server-2604 is clear and searchable. The Location field shows where the VM files will be saved. The default is inside your Documents or home folder. Make sure the destination drive has at least 25 GB free. Click Next.
  5. Set the virtual disk size. On the Specify Disk Capacity screen, set the disk size to 20 GB. Leave Split virtual disk into multiple files selected (this is the default and makes the VM easier to move or back up). Click Next.
    This is a thin-provisioned disk by default. VMware does not immediately consume 20 GB of your drive space. It starts near zero and grows as Ubuntu writes data to the virtual disk, up to the 20 GB ceiling. The actual disk file will be around 5–8 GB after a clean Ubuntu Server install.
  6. Customize hardware before finishing. On the final summary screen, click Customize Hardware before clicking Finish.
    • Memory: set to 2048 MB (2 GB). This is sufficient for Ubuntu Server. If your host has 16 GB or more, you can use 4096 MB for faster builds.
    • Processors: set to 2 processor cores. Leave Virtualize Intel VT-x/EPT or AMD-V/RVI checked (it usually is by default).
    • Network Adapter: leave as NAT. This gives the VM internet access through your host machine's connection without needing its own IP on your LAN. You can change this later — see the networking explanation in Phase 5.
    • CD/DVD (SATA): confirm the ISO path shown here matches your downloaded file. It should already be set from step 2.
    Click Close on the hardware dialog, then click Finish on the wizard.
Checkpoint — what you should see
The VM named ubuntu-server-2604 (or whatever you called it) now appears in the Library panel on the left side of VMware Workstation. The VM summary tab shows the hardware you configured: 2 GB RAM, 2 CPUs, 20 GB disk, NAT network, and the Ubuntu ISO attached to the CD/DVD drive. The VM is powered off.

Run the Ubuntu Server Installer
Boot the VM from the ISO and walk through the subiquity text installer. Ubuntu Server 26.04 uses a keyboard-driven (not graphical) installer called subiquity. Navigate with arrow keys, Tab to move between elements, and Space or Enter to select.
  1. Power on the VM. Click the green Power On This Virtual Machine button in the VM summary tab, or press Ctrl+B. The VMware console window opens and the VM screen shows the VM booting. You will see a short BIOS/EFI screen, then the Ubuntu Server installer loads. Click inside the console window once to "capture" your mouse and keyboard — to release them back to Windows, press Ctrl+Alt.
  2. Language selection. The installer's first screen says Willkommen! Bienvenue! Welcome! with a language list. Use the arrow keys to highlight English and press Enter.
  3. Installer update prompt. The installer may offer to update itself before continuing. It shows two options: Update to the new installer or Continue without updating. Select Continue without updating and press Enter. This avoids a wait while the VM downloads an update during install.
  4. Keyboard layout. The installer guesses your layout. Confirm English (US) is selected (or choose your actual keyboard layout) and press Enter on Done.
  5. Installation type. The screen offers Ubuntu Server and Ubuntu Server (minimized). Leave Ubuntu Server selected (the default) and press Enter on Done. The minimized option removes some standard utilities to reduce image size — not what you want for a learning lab.
  6. Network configuration. The installer detects the VM's NAT adapter and configures it via DHCP automatically. You should see an interface (named ens33 or similar in Workstation VMs) with an IP address assigned in the 192.168.x.x range. Tab to Done and press Enter.
    Interface shows "not connected" or no IP?
    • In VMware Workstation, confirm the VM's network adapter is set to NAT: go to VM > Settings > Network Adapter while the VM is paused or off. The VMware NAT service must be running on the host — check via Edit > Virtual Network Editor and confirm vmnet8 (NAT) is listed.
    • If the network editor shows vmnet8 missing, click Restore Defaults to rebuild the default virtual networks.
  7. Proxy address. Leave this blank unless your network routes through a proxy. Tab to Done and press Enter.
  8. Ubuntu archive mirror. The installer tests your internet connection and displays the default mirror (archive.ubuntu.com or a regional mirror). Leave it as-is and press Enter on Done. The installer will confirm the mirror is reachable before proceeding.
  9. Storage configuration. On the Guided storage configuration screen, leave Use an entire disk selected. The installer shows your 20 GB virtual disk (/dev/sda or /dev/nvme0n1). Leave all defaults and Tab to Done, then press Enter.
    LVM is enabled by default. The installer sets up LVM (Logical Volume Manager) by default, which is shown as a checkbox that is already checked. This is fine for a lab VM — leave it checked. LVM lets you resize partitions later without reinstalling.
  10. Storage layout confirmation. The installer shows the partition layout it will create. A red warning at the bottom says "Confirm destructive action" — this is expected. Since the entire virtual disk is empty, there is nothing to destroy. Tab to Continue and press Enter.
  11. Profile setup. This is the most important screen. Fill in four fields:
    • Your name: your full name (e.g., Jane Smith)
    • Your server's name: a hostname for the VM (e.g., labserver — lowercase, no spaces)
    • Pick a username: your login username (e.g., jane)
    • Choose a password: a password you will remember — you will type this every time you log in
    • Confirm your password: type it again
    Tab to Done and press Enter.
  12. Ubuntu Pro upgrade offer. The installer offers to enroll in Ubuntu Pro for extended security updates. Select Skip for now and press Enter. Ubuntu Pro is not needed for a personal lab.
  13. SSH setup. The installer offers to install OpenSSH server. Press Space to check Install OpenSSH server. This enables you to SSH into the VM from your host using a terminal after install. Tab to Done and press Enter.
  14. Featured snaps. The installer offers additional software packages called snaps (docker, microk8s, etc.). Do not select any for now — you can install them later. Tab to Done and press Enter.
  15. Wait for installation to complete. The installer now runs, showing a progress log at the bottom of the screen. This takes 5–15 minutes depending on your host disk speed and internet connection (it downloads security updates during install). When finished, the screen shows Install complete! and a Reboot Now button. Press Enter on Reboot Now.
  16. Remove the ISO when prompted. After clicking Reboot Now, the installer may pause and show: Please remove the installation medium, then press ENTER. In VMware, first press Ctrl+Alt to release your mouse and keyboard from the console (otherwise you cannot reach the menus), then disconnect the ISO: go to VM > Settings > CD/DVD (SATA), uncheck Connect at power on and set the connection to Use physical drive: Auto detect (or simply uncheck Connected). Then press Enter in the VM console. The VM reboots into the installed Ubuntu Server system.
    If the VM boots back into the installer instead of the installed system: the ISO is still attached and being booted from. Disconnect it in VM settings as described above, then use VM > Power > Restart Guest.
Checkpoint — what you should see
After the reboot, the VM console shows boot messages scrolling by, then arrives at a text login prompt: labserver login: (where labserver is whatever hostname you set). There is no graphical desktop — this black text prompt is the correct, expected final state for Ubuntu Server, not an error or an unfinished boot. This is your Ubuntu Server. Type your username and press Enter, then type your password and press Enter. The prompt changes to something like jane@labserver:~$. You are now logged in to your VM.

First Boot: Verify Networking, Update Packages, and Install open-vm-tools
Confirm the VM has a network connection, update the package list and installed packages, then install VMware's guest tools (open-vm-tools) for better integration with the host. All commands run inside the Ubuntu Server VM — type them at the $ prompt after logging in.
  1. Check your network interface and confirm an IP address was assigned.
    ip a
    Expected output (abbreviated):
    1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 inet 127.0.0.1/8 scope host lo 2: ens33: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 inet 192.168.80.131/24 brd 192.168.80.255 scope global dynamic ens33
    Your VM's interface name will be ens33 (common in VMware) or ens160. The IP address in the 192.168.x.x or 192.168.80.x range is the NAT address assigned by VMware. Write this down — you will use it to SSH in from your host.
    No IP address shown, or interface shows DOWN?
    • Run sudo dhclient ens33 (replace ens33 with your interface name) to manually request a DHCP lease. If it succeeds, run ip a again — the IP should appear.
    • If dhclient fails, go back to VMware's settings (VM > Settings > Network Adapter) and confirm the adapter is set to NAT and is Connected.
    • In VMware Workstation, the NAT service runs as a Windows service called VMware NAT Service. If it stopped, open Services in Windows and restart it.
  2. Test internet connectivity from inside the VM.
    ping -c 4 8.8.8.8
    Expected output:
    PING 8.8.8.8 (8.8.8.8) 56(84) bytes of data. 64 bytes from 8.8.8.8: icmp_seq=1 ttl=55 time=14.3 ms 64 bytes from 8.8.8.8: icmp_seq=2 ttl=55 time=13.8 ms 64 bytes from 8.8.8.8: icmp_seq=3 ttl=55 time=14.1 ms 64 bytes from 8.8.8.8: icmp_seq=4 ttl=55 time=13.9 ms --- 8.8.8.8 ping statistics --- 4 packets transmitted, 4 received, 0% packet loss
    Zero packet loss confirms internet access through the VMware NAT gateway. If all packets are lost, there is a networking misconfiguration (see the fix box above).
  3. Update the package list and upgrade installed packages. Run both commands. The first fetches the latest package metadata from Ubuntu's servers. The second upgrades any packages that have available updates (common right after a fresh install because security patches arrive faster than ISO builds).
    sudo apt update
    sudo apt upgrade -y
    The sudo prefix runs the command as root (the system administrator). The terminal will prompt you for your password the first time you use sudo in a session. Type it and press Enter — the cursor does not move while you type a password in Linux; that is normal.
    Why update immediately after install? The Ubuntu 26.04 ISO you downloaded was built at a specific point in time. Security patches released after that date are not in the ISO. Running apt upgrade right after install closes those gaps immediately.
  4. Install open-vm-tools. This is VMware's guest integration package for Linux VMs. It enables clipboard sharing between your host and the VM, automatic time synchronization, and better CPU/memory performance.
    sudo apt install -y open-vm-tools
    Expected output ends with:
    Setting up open-vm-tools (2:13.0.10-1ubuntu1) ... Processing triggers for man-db ...
    After installation, open-vm-tools starts automatically as a systemd service. You do not need to reboot.
    Why not use "VM > Install VMware Tools" from the menu?
    • The VM > Install VMware Tools menu option in Workstation mounts a legacy CDROM-based package. For Ubuntu 26.04, the open-vm-tools package from the Ubuntu repository (what you just installed with apt) is the correct, recommended method. It is better maintained, gets security updates through Ubuntu's normal channels, and does not require a reboot after install.
    • If you already ran VM > Install VMware Tools from the menu, those legacy tools conflict with open-vm-tools. Remove them and use the apt version instead: sudo apt remove vmware-tools then sudo apt install -y open-vm-tools.
  5. Verify open-vm-tools is running.
    systemctl status open-vm-tools
    Expected output includes:
    open-vm-tools.service - Open VMware Tools Loaded: loaded (/lib/systemd/system/open-vm-tools.service; enabled; ...) Active: active (running) since ...
    The active (running) line confirms the service is up.
  6. Understand NAT vs. bridged networking (important context for future projects). Your VM is currently on NAT, which means: the VM can reach the internet through your host, but other machines on your LAN cannot reach the VM directly (they see the host's IP, not the VM's). For most beginner projects this is fine. For projects that need the VM to be reachable from other machines on your network (or from your host without special port-forwarding), switch the adapter to Bridged: go to VM > Settings > Network Adapter > Bridged: Connected directly to the physical network. After switching, run sudo dhclient ens33 inside the VM to get a new IP on your real LAN.
    Host-only mode is a third option: the VM can talk to the host but not to the internet or the rest of your LAN. Use it when you want a completely isolated lab environment (for example, when practicing attacks that should never reach a real network).
Checkpoint — what you should see
ip a shows your VM's interface with an IP address in the VMware NAT range (commonly 192.168.80.x or 192.168.x.x). ping -c 4 8.8.8.8 returns zero packet loss. sudo apt upgrade completed without errors. systemctl status open-vm-tools shows active (running). Your VM is connected, updated, and has VMware guest tools running.

Take a Snapshot and SSH In from Your Host (Optional but Recommended)
Protect your clean install with a snapshot — a saved point you can restore to instantly if anything goes wrong. Then connect to the VM via SSH from your host terminal, which is more comfortable than the VMware console for daily use.
  1. Take a snapshot named "Clean Install". In VMware Workstation, with the VM running, click VM > Snapshot > Take Snapshot. In the Name field type Clean Install. In the Description field type something like Ubuntu Server 26.04 fresh install, open-vm-tools installed, packages updated. Click Take Snapshot. This takes 10–30 seconds. A snapshot saves the VM's full state (RAM, disk, and CPU state) at this moment.
    What snapshots do: if you later break something inside the VM — a bad config change, a failed package install, or anything else — you can restore to this Clean Install snapshot in seconds: VM > Snapshot > Snapshot Manager, select "Clean Install", click Go To. The VM returns exactly to the state it was in when you took the snapshot, with no reinstall required. This is one of the most powerful things a hypervisor gives you that bare-metal servers cannot match.
  2. Find the VM's IP address. If you are still logged into the VM console, run:
    ip a show ens33
    Note the IP next to inet (example: 192.168.80.131). If your interface is named differently, run ip a and find the non-loopback interface.
  3. SSH into the VM from your host. Open a terminal on your host computer (PowerShell, Windows Terminal, or Command Prompt on Windows; any terminal on Linux/Mac). Run:
    ssh jane@192.168.80.131
    Replace jane with your Ubuntu username and 192.168.80.131 with your VM's actual IP. The first time you connect, SSH shows a fingerprint prompt:
    The authenticity of host '192.168.80.131 (192.168.80.131)' can't be established. ED25519 key fingerprint is SHA256:xXxXxXxXxXxXxXxXxXxXxXxXxXxXxXxXxXxXxXxXxX. Are you sure you want to continue connecting (yes/no/[fingerprint])?
    Type yes and press Enter. This is expected — SSH is recording that you trust this VM's identity. Type your VM password when prompted. You are now in a remote terminal session inside your Ubuntu Server VM, from the comfort of your host's terminal.
    Why SSH instead of the VMware console? The VMware console window does not support copy-paste from your host clipboard easily. SSH gives you a full terminal with host clipboard integration, scrollback history, and the ability to run multiple sessions simultaneously. SSH is also how you would administer a real cloud or data center server — there is no "console window" on production hardware.
  4. Shut down the VM cleanly when done. From inside the VM (via console or SSH), run:
    sudo shutdown now
    The VM powers off within a few seconds. You can also use VM > Power > Shut Down Guest from the Workstation menu, which sends a graceful shutdown signal. Never use VM > Power > Power Off (the hard cut) unless the guest OS is unresponsive — it is equivalent to yanking the power cord and can corrupt the filesystem.
Checkpoint — what you should see
In VM > Snapshot > Snapshot Manager, the snapshot tree shows a node labeled Clean Install. Running ssh jane@<vm-ip> from your host terminal connects and drops you to a jane@labserver:~$ prompt. Running sudo shutdown now inside the VM causes the VMware console to show the VM as powered off. Your lab is ready for future projects.
