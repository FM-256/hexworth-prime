Subject

Build a Perimeter Alarm System

Recruit 60 min 250 XP
Mission Brief

This operation builds a physical perimeter alarm on a Raspberry Pi. A passive infrared (PIR) motion sensor watches a zone; an active buzzer sounds the alarm the moment an intruder crosses it. You will wire the sensor, read it with gpiozero 2.0.1, implement arm/disarm logic with a warm-up delay, add a cooldown to suppress re-trigger noise, and write every event to a timestamped log file. A working no-hardware simulation path using gpiozero's built-in MockFactory is included so you can complete the full logic on any computer without the kit.

The pattern here -- sensor input drives a state machine that gates an actuator and emits a log -- is the same architecture behind every commercial alarm panel, from Ring doorbells to enterprise perimeter grids. The fifth phase makes the daemon persistent using a systemd service so it survives reboots with no manual intervention.

Ethics note: only monitor spaces you own or are explicitly authorized to monitor. Surveillance of others without consent is illegal in most jurisdictions.

Agent Requirements
  • Hardware path (recommended): a Raspberry Pi with GPIO headers (any model with a 40-pin header -- Pi 3B+, Pi 4, Pi 5), an HC-SR501 PIR motion sensor, an active buzzer module (3.3 V or 5 V), jumper wires, and a half-size breadboard
  • No-hardware path: any computer running Python 3.9 or higher -- gpiozero's MockFactory simulates the PIR and buzzer in software so you can run and observe every phase without a kit
  • Python 3.9 or higher -- check with python3 --version
  • pip and the ability to install packages -- Phase 1 gives the exact install command; gpiozero 2.0.1 requires lgpio as its backend on Pi 5 (RPi.GPIO does not support Pi 5)
  • Basic Python skills: variables, loops, functions, and reading error messages -- no prior electronics experience required

Wiring and Environment Setup
Install gpiozero 2.0.1, wire the HC-SR501 PIR and active buzzer to the Pi's GPIO header, and verify that gpiozero can communicate with both devices. Covers both the hardware wiring and the no-hardware MockFactory path.
  1. Install gpiozero and the lgpio backend. Run this on the Pi (or on any machine for the mock path):
    pip install gpiozero==2.0.1 lgpio
    Pi 5 note: gpiozero 2.0 made LGPIOFactory the default backend. RPi.GPIO does not support the Pi 5 chip; if you have a Pi 5 and see RuntimeError: No module named RPi, run pip install lgpio and it will resolve. Pi 3 and Pi 4 work with either backend.
  2. Wire the HC-SR501 PIR sensor (hardware path only). The HC-SR501 has three pins labeled on the board:
    HC-SR501 VCC --> Pi physical pin 2 (5V) HC-SR501 GND --> Pi physical pin 6 (GND) HC-SR501 OUT --> Pi physical pin 7 (BCM GPIO 4)
    HC-SR501 has two potentiometers on the back. The left one (Sx) adjusts sensitivity (range 3 m to 7 m -- turn clockwise for wider range). The right one (Tx) sets the hold time, i.e., how long the output pin stays HIGH after motion stops (2 s to 200 s -- turn counter-clockwise for shortest delay). Set both to their minimum for initial testing. There is also a small jumper: L position = single-trigger (output drops after hold time, can re-trigger immediately), H position = re-trigger (output stays HIGH as long as motion continues). Use L for this project.
  3. Wire the active buzzer (hardware path only). An active buzzer has a built-in oscillator -- applying voltage makes it sound without any PWM from the Pi:
    Buzzer + (longer leg / marked +) --> Pi physical pin 11 (BCM GPIO 17) Buzzer - (shorter leg / GND) --> Pi physical pin 9 (GND)
    Active vs passive buzzer: an active buzzer emits a fixed tone when you call buzzer.on(). A passive buzzer requires PWM to generate a tone and will not sound with on() alone. Active buzzers usually have a label or sticker on top; passive ones look identical but remain silent with DC. If yours is passive, replace Buzzer with TonalBuzzer (both import from gpiozero), add from gpiozero.tones import Tone, and use buzzer.play(Tone("A4")) to sound it / buzzer.stop() to silence it -- TonalBuzzer has no on() or off().
  4. Verify the install. Create check_install.py and paste:
    import gpiozero print("gpiozero version:", gpiozero.__version__) print("Default factory:", gpiozero.Device.pin_factory)
    Run it:
    python3 check_install.py
    Expected output on a Pi:
    gpiozero version: 2.0.1 Default factory: <gpiozero.pins.lgpio.LGPIOFactory object at 0x...>
    Expected output on a non-Pi (mock path):
    gpiozero version: 2.0.1 Default factory: None
    The None factory on a non-Pi is expected -- gpiozero defers factory selection until a device is constructed. Phase 2 sets the mock factory explicitly so all code runs without GPIO hardware.
ImportError: No module named 'lgpio'? Run pip install lgpio. On Pi 5, lgpio is required; RPi.GPIO will not work. On Pi 3/4, you can also try pip install RPi.GPIO as a fallback, but lgpio is preferred.
gpiozero.exc.BadPinFactory on import? This means gpiozero cannot find any backend. Run pip install lgpio and try again. If you are on a non-Pi machine, set GPIOZERO_PIN_FACTORY=mock in your environment or use the MockFactory pattern in Phase 2.
Checkpoint -- what you should see
check_install.py prints gpiozero version: 2.0.1 and exits without error. On the Pi with hardware wired: power cycling the PIR and waiting 10 seconds, then waving your hand in front of the dome, the OUT pin goes HIGH (you can verify with a multimeter or by proceeding to Phase 2). The buzzer gives a brief tone when you briefly connect its + leg to 3.3 V.

PIR Motion Detection with Warm-Up and Mock Fallback
Read the PIR sensor using MotionSensor, implement the mandatory 45-second warm-up delay (the HC-SR501 emits false triggers during capacitor charging at power-on), and provide a complete no-hardware simulation using MockFactory so you can run and test without the kit.
  1. Understand the warm-up requirement. The HC-SR501 charges an internal capacitor on power-on and fires false motion events for the first 30-60 seconds. Your code must wait for the sensor to settle before treating its output as real. The standard pattern is a printed countdown followed by a blocking wait:
    gpiozero MotionSensor API (v2.0.1): pir = MotionSensor(4) creates a sensor on BCM GPIO 4. Key attributes: pir.motion_detected (True/False), pir.wait_for_motion() (blocks until motion), pir.wait_for_no_motion() (blocks until clear), pir.when_motion (callback on motion), pir.when_no_motion (callback on clear).
  2. Create pir_read.py in your project folder. This script runs on both real hardware and in mock simulation mode -- edit the USE_MOCK flag at the top:
    import time from gpiozero import MotionSensor, Device # ── CONFIGURATION ──────────────────────────────────────────────────────────── USE_MOCK = False # Set True if you have no Raspberry Pi / no hardware PIR_PIN = 4 # BCM GPIO 4 = physical pin 7 on the 40-pin header WARMUP_SECS = 45 # HC-SR501 needs 30-60s to settle at power-on # ── NO-HARDWARE FALLBACK: MockFactory ──────────────────────────────────────── # MockFactory makes gpiozero run on any OS without GPIO hardware. # Drive the simulated PIR pin high/low in code to simulate motion events. if USE_MOCK: from gpiozero.pins.mock import MockFactory Device.pin_factory = MockFactory() print("[MOCK MODE] No hardware required. Simulating PIR on GPIO", PIR_PIN) # ── SENSOR SETUP ───────────────────────────────────────────────────────────── pir = MotionSensor(PIR_PIN) # ── WARM-UP DELAY ──────────────────────────────────────────────────────────── # The HC-SR501 fires false triggers while its capacitor charges at power-on. # 45 seconds is a conservative safe window that covers all unit variants. # Skip to 0 in mock mode since there is no real hardware to stabilise. warmup = 0 if USE_MOCK else WARMUP_SECS if warmup > 0: print(f"Waiting {warmup}s for PIR warm-up -- do not enter the detection zone...") for remaining in range(warmup, 0, -1): print(f" {remaining}s remaining...", end="\r", flush=True) time.sleep(1) print("\nWarm-up complete. Monitoring for motion. Press Ctrl+C to stop.") else: print("Monitoring for motion (mock mode). Press Ctrl+C to stop.") # ── MOCK: schedule a simulated motion event after 2 seconds ───────────────── if USE_MOCK: import threading def _simulate_motion(): time.sleep(2) # drive_high() on the pin triggers the MotionSensor's when_motion callback pir.pin.drive_high() time.sleep(1) pir.pin.drive_low() threading.Thread(target=_simulate_motion, daemon=True).start() print("[MOCK] Simulated motion event scheduled in 2 seconds.") # ── DETECTION LOOP ──────────────────────────────────────────────────────────── try: while True: pir.wait_for_motion() print(f"MOTION DETECTED at {time.strftime('%H:%M:%S')}") pir.wait_for_no_motion() print(f" Zone clear at {time.strftime('%H:%M:%S')}") except KeyboardInterrupt: print("\nStopped.")
  3. Run on hardware:
    python3 pir_read.py
    Wave your hand slowly in front of the PIR dome. Expected output (after warm-up):
    Warm-up complete. Monitoring for motion. Press Ctrl+C to stop. MOTION DETECTED at 14:23:07 Zone clear at 14:23:10
  4. Run in mock mode (no hardware required). Edit the file and set USE_MOCK = True, then:
    python3 pir_read.py
    Expected output:
    [MOCK MODE] No hardware required. Simulating PIR on GPIO 4 Monitoring for motion (mock mode). Press Ctrl+C to stop. [MOCK] Simulated motion event scheduled in 2 seconds. MOTION DETECTED at 14:23:02 Zone clear at 14:23:03
pir.wait_for_motion() returns immediately at startup? The PIR is still warming up and its output is HIGH from capacitor charging. Let the warm-up countdown complete, then test again. If it persists after 60 seconds, the HC-SR501's hold-time potentiometer (Tx) may be turned too high -- rotate it counter-clockwise to minimum.
mock mode: AttributeError on pir.pin.drive_high()? Confirm Device.pin_factory = MockFactory() runs before MotionSensor(PIR_PIN) is constructed. The factory must be set first or the pin is not a MockPin and will not have drive_high.
Checkpoint -- what you should see
Hardware path: after the warm-up countdown, waving a hand in front of the PIR dome causes MOTION DETECTED at HH:MM:SS to print within 1-2 seconds. Stopping motion causes Zone clear at HH:MM:SS to follow. Mock path: without any hardware, the script automatically prints MOTION DETECTED approximately 2 seconds after launch, then Zone clear one second later, then keeps waiting for further motion -- press Ctrl+C to stop it cleanly.

Buzzer Alarm with Arm / Disarm State Machine
Add the active buzzer, implement an arm/disarm flag so the alarm only fires when the system is armed, and add a cooldown timer so a single motion event does not re-trigger the buzzer for several seconds. The mock path drives both the simulated PIR and the simulated buzzer so all logic is exercised without hardware.
  1. Understand gpiozero's Buzzer API. Buzzer(17) wraps BCM GPIO 17 as a digital output. Key methods: buzzer.on() powers it (alarm sounds), buzzer.off() silences it, buzzer.beep(on_time, off_time, n) pulses n times with given on/off durations. A single motion event will call buzzer.beep(0.3, 0.3, 5) -- five 300 ms beeps, then silence automatically.
  2. Create alarm.py in your project folder:
    import time import threading from gpiozero import MotionSensor, Buzzer, Device # ── CONFIGURATION ──────────────────────────────────────────────────────────── USE_MOCK = False # Set True for no-hardware simulation PIR_PIN = 4 # BCM GPIO 4 = physical pin 7 BUZZER_PIN = 17 # BCM GPIO 17 = physical pin 11 WARMUP_SECS = 45 # HC-SR501 false-trigger settling window COOLDOWN_SECS = 10 # minimum seconds between alarm triggers # ── NO-HARDWARE MOCK ───────────────────────────────────────────────────────── if USE_MOCK: from gpiozero.pins.mock import MockFactory Device.pin_factory = MockFactory() print("[MOCK MODE] Simulating PIR on GPIO", PIR_PIN, "and Buzzer on GPIO", BUZZER_PIN) # ── DEVICES ────────────────────────────────────────────────────────────────── pir = MotionSensor(PIR_PIN) buzzer = Buzzer(BUZZER_PIN) # ── ALARM STATE ────────────────────────────────────────────────────────────── armed = True # start armed; toggle with arm()/disarm() functions last_alarm_time = 0.0 # tracks cooldown def arm(): global armed armed = True print(f"[{time.strftime('%H:%M:%S')}] SYSTEM ARMED") def disarm(): global armed armed = False buzzer.off() # silence immediately if alarm was sounding print(f"[{time.strftime('%H:%M:%S')}] SYSTEM DISARMED") def trigger_alarm(): global last_alarm_time now = time.time() if not armed: return if (now - last_alarm_time) < COOLDOWN_SECS: return # within cooldown window -- suppress re-trigger last_alarm_time = now print(f"[{time.strftime('%H:%M:%S')}] ALARM -- MOTION DETECTED") # Five 300 ms beeps, non-blocking (background thread) buzzer.beep(on_time=0.3, off_time=0.3, n=5, background=True) def on_motion(): trigger_alarm() def on_clear(): print(f"[{time.strftime('%H:%M:%S')}] Zone clear") pir.when_motion = on_motion pir.when_no_motion = on_clear # ── WARM-UP ────────────────────────────────────────────────────────────────── warmup = 0 if USE_MOCK else WARMUP_SECS if warmup > 0: print(f"Warming up PIR -- {warmup}s delay...") for remaining in range(warmup, 0, -1): print(f" {remaining}s...", end="\r", flush=True) time.sleep(1) print("\nReady.") else: print("Ready (mock mode).") # ── MOCK: simulate motion after 2 s, disarm after 8 s, re-arm after 12 s ──── if USE_MOCK: def _mock_scenario(): time.sleep(2) print("[MOCK] Driving PIR high (motion)") pir.pin.drive_high() time.sleep(1) pir.pin.drive_low() time.sleep(5) disarm() time.sleep(2) pir.pin.drive_high() # should NOT trigger alarm (disarmed) time.sleep(1) pir.pin.drive_low() time.sleep(1) arm() time.sleep(2) pir.pin.drive_high() # SHOULD trigger alarm (re-armed) time.sleep(1) pir.pin.drive_low() threading.Thread(target=_mock_scenario, daemon=True).start() # ── MAIN LOOP ──────────────────────────────────────────────────────────────── print("Monitoring. Press Ctrl+C to stop.") try: while True: time.sleep(0.5) except KeyboardInterrupt: buzzer.off() print("\nStopped.")
  3. Run on hardware:
    python3 alarm.py
    Wave your hand in front of the PIR. Expected output:
    [14:30:01] SYSTEM ARMED Ready. Monitoring. Press Ctrl+C to stop. [14:30:09] ALARM -- MOTION DETECTED [14:30:11] Zone clear
    The buzzer should sound five short beeps then go silent.
  4. Run in mock mode (set USE_MOCK = True):
    python3 alarm.py
    Expected output -- note the disarmed event silences the second trigger:
    [MOCK MODE] Simulating PIR on GPIO 4 and Buzzer on GPIO 17 Ready (mock mode). Monitoring. Press Ctrl+C to stop. [14:30:02] ALARM -- MOTION DETECTED [14:30:03] Zone clear [14:30:08] SYSTEM DISARMED [14:30:10] Zone clear [14:30:13] SYSTEM ARMED [14:30:15] ALARM -- MOTION DETECTED [14:30:16] Zone clear
Buzzer beeps once then stops immediately? You likely have a passive buzzer, not an active one. A passive buzzer needs a PWM frequency to generate sound. Swap Buzzer for TonalBuzzer, add the import from gpiozero.tones import Tone, then call buzzer.play(Tone("A4")) followed by time.sleep(0.3); buzzer.stop() in a loop. TonalBuzzer has no on()/off() -- use play()/stop().
Alarm keeps retriggering every few seconds with no motion? The HC-SR501's Tx potentiometer (hold time) is set too high. Rotate it counter-clockwise to its minimum. Also verify the retrigger jumper is in the L (single-trigger) position.
Checkpoint -- what you should see
Hardware: waving your hand in front of the PIR causes ALARM -- MOTION DETECTED to print and the buzzer to sound five short beeps. Waving again within 10 seconds produces the Zone clear line but no second buzzer sequence (cooldown active). Mock: the simulated scenario runs to completion, showing that the disarmed event suppresses the second motion trigger and the re-arm restores alarm functionality -- all without any GPIO hardware. The main loop keeps running after the scenario; press Ctrl+C to stop.

Timestamped Event Log to File
Extend the alarm script to write every state change -- ARMED, DISARMED, MOTION, ALARM, CLEAR -- to a persistent log file with ISO-8601 wall-clock timestamps. Each run appends to the same file so the log survives restarts. A summary of total events and alarm count prints on exit.
  1. Create alarm_logged.py in your project folder. This builds on Phase 3 -- the key addition is the log_event() function that writes to alarm_events.log:
    import time import threading from datetime import datetime from gpiozero import MotionSensor, Buzzer, Device # ── CONFIGURATION ──────────────────────────────────────────────────────────── USE_MOCK = False PIR_PIN = 4 BUZZER_PIN = 17 WARMUP_SECS = 45 COOLDOWN_SECS = 10 LOG_FILE = "alarm_events.log" # ── MOCK SETUP ─────────────────────────────────────────────────────────────── if USE_MOCK: from gpiozero.pins.mock import MockFactory Device.pin_factory = MockFactory() # ── DEVICES ────────────────────────────────────────────────────────────────── pir = MotionSensor(PIR_PIN) buzzer = Buzzer(BUZZER_PIN) # ── EVENT COUNTERS ─────────────────────────────────────────────────────────── event_count = 0 alarm_count = 0 def log_event(event_type, detail=""): global event_count event_count += 1 ts = datetime.now().strftime("%Y-%m-%dT%H:%M:%S") line = f"{ts} [{event_type:<12}] {detail}" print(line) with open(LOG_FILE, "a") as f: f.write(line + "\n") # ── ALARM STATE ────────────────────────────────────────────────────────────── armed = True last_alarm_time = 0.0 def arm(): global armed armed = True log_event("ARMED") def disarm(): global armed armed = False buzzer.off() log_event("DISARMED") def trigger_alarm(): global last_alarm_time, alarm_count now = time.time() if not armed: log_event("MOTION", "ignored -- system disarmed") return if (now - last_alarm_time) < COOLDOWN_SECS: log_event("MOTION", "suppressed -- within cooldown window") return last_alarm_time = now alarm_count += 1 log_event("ALARM", f"trigger #{alarm_count}") buzzer.beep(on_time=0.3, off_time=0.3, n=5, background=True) pir.when_motion = trigger_alarm pir.when_no_motion = lambda: log_event("CLEAR") # ── WARM-UP ────────────────────────────────────────────────────────────────── warmup = 0 if USE_MOCK else WARMUP_SECS log_event("BOOT", f"USE_MOCK={USE_MOCK} PIR=GPIO{PIR_PIN} BUZZER=GPIO{BUZZER_PIN}") arm() if warmup > 0: log_event("WARMUP", f"waiting {warmup}s for PIR to settle") for remaining in range(warmup, 0, -1): print(f" warm-up: {remaining}s remaining...", end="\r", flush=True) time.sleep(1) print() log_event("WARMUP", "complete -- monitoring active") # ── MOCK SCENARIO ──────────────────────────────────────────────────────────── if USE_MOCK: def _mock_run(): time.sleep(1); pir.pin.drive_high() time.sleep(1); pir.pin.drive_low() time.sleep(2); disarm() time.sleep(1); pir.pin.drive_high() # ignored (disarmed) time.sleep(1); pir.pin.drive_low() time.sleep(1); arm() time.sleep(5); pir.pin.drive_high() # fires alarm #2 (waits out the 10s cooldown) time.sleep(1); pir.pin.drive_low() threading.Thread(target=_mock_run, daemon=True).start() # ── MAIN LOOP ──────────────────────────────────────────────────────────────── try: while True: time.sleep(0.5) except KeyboardInterrupt: pass finally: buzzer.off() log_event("SHUTDOWN", f"total events: {event_count} alarms triggered: {alarm_count}") print(f"\nLog saved to {LOG_FILE}")
  2. Run it:
    python3 alarm_logged.py
    After triggering a few motion events, press Ctrl+C. Then inspect the log:
    cat alarm_events.log
    Expected log contents:
    2026-06-19T14:30:00 [BOOT ] USE_MOCK=False PIR=GPIO4 BUZZER=GPIO17 2026-06-19T14:30:00 [ARMED ] 2026-06-19T14:30:00 [WARMUP ] waiting 45s for PIR to settle 2026-06-19T14:30:45 [WARMUP ] complete -- monitoring active 2026-06-19T14:31:02 [ALARM ] trigger #1 2026-06-19T14:31:04 [CLEAR ] 2026-06-19T14:31:58 [SHUTDOWN ] total events: 5 alarms triggered: 1
Log file is empty after running? The file is only written inside log_event(). If no events appeared on screen either, the PIR is not triggering -- confirm wiring and that the warm-up completed. If you see events on screen but no file, check that the script's working directory is writable: ls -la alarm_events.log after running.
Log file fills with thousands of MOTION lines per second? The PIR OUT pin is floating or the GND connection is loose. A floating GPIO pin reads noise as rapid state transitions. Confirm the GND jumper is fully seated in the breadboard rail and the PIR's GND pin connects to the same rail.
Checkpoint -- what you should see
After running and triggering at least one alarm event, alarm_events.log exists in the project folder and contains timestamped lines for BOOT, ARMED, WARMUP, ALARM, CLEAR, and SHUTDOWN. The ISO-8601 timestamps match the actual wall clock. Appending a second run adds new lines below the previous ones without overwriting them. Mock path: the script completes the full scenario and writes every event type to the log, confirming the logging logic works independently of hardware.

Run on Boot with systemd
Package the alarm script as a systemd service so it starts automatically on every boot -- including after a power cut -- without any manual login. Covers the service unit file, enabling it, and checking status and logs via journalctl.
  1. Find your Python path and project path. You need the full absolute paths for the systemd unit:
    which python3 pwd
    Sample output:
    /usr/bin/python3 /home/pi/perimeter-alarm
  2. Create the systemd unit file. This file tells systemd what to run, as which user, and when:
    sudo nano /etc/systemd/system/perimeter-alarm.service
    Paste this content, replacing the User and paths to match your system:
    [Unit] Description=Perimeter Alarm -- PIR motion sensor daemon After=network.target [Service] Type=simple User=pi WorkingDirectory=/home/pi/perimeter-alarm ExecStart=/usr/bin/python3 /home/pi/perimeter-alarm/alarm_logged.py Restart=on-failure RestartSec=5 StandardOutput=journal StandardError=journal [Install] WantedBy=multi-user.target
    USE_MOCK must be False when running as a service on real hardware. The service runs as the user specified in User= -- that user must be in the gpio group: sudo usermod -aG gpio pi (replace pi with your username), then log out and back in for the group change to take effect.
  3. Reload systemd, enable, and start the service:
    sudo systemctl daemon-reload sudo systemctl enable perimeter-alarm.service sudo systemctl start perimeter-alarm.service
  4. Verify it is running:
    sudo systemctl status perimeter-alarm.service
    Expected output:
    perimeter-alarm.service - Perimeter Alarm -- PIR motion sensor daemon Loaded: loaded (/etc/systemd/system/perimeter-alarm.service; enabled) Active: active (running) since Thu 2026-06-19 14:30:00 BST; 12s ago Main PID: 1234 (python3) Tasks: 4 CGroup: /system.slice/perimeter-alarm.service 1234 /usr/bin/python3 /home/pi/perimeter-alarm/alarm_logged.py
  5. Stream live journal output to watch alarm events in real time:
    sudo journalctl -u perimeter-alarm.service -f
    Wave your hand in front of the PIR. You should see alarm log lines appear in the journal stream.
  6. Test the reboot persistence. Reboot the Pi:
    sudo reboot
    After the Pi comes back up (about 30-60 seconds), check status without logging in to the desktop:
    sudo systemctl status perimeter-alarm.service
    The service should be active (running) automatically.
Service exits immediately with exit code 1? Run sudo journalctl -u perimeter-alarm.service --no-pager -n 30 to see the error. The most common causes: wrong Python path in ExecStart (fix with which python3), wrong working directory, or the pi user is not in the gpio group (fix with sudo usermod -aG gpio pi and reboot).
gpiozero raises PermissionError or RuntimeError: No access to /dev/gpiomem? The service user does not have GPIO access. Run sudo usermod -aG gpio pi and sudo systemctl restart perimeter-alarm.service. On Pi 5 with lgpio, you may also need sudo usermod -aG dialout pi.
Checkpoint -- what you should see
systemctl status perimeter-alarm.service shows active (running). The journal stream (journalctl -u perimeter-alarm.service -f) shows a BOOT line and ARMED line after the service starts, and ALARM lines appear when you wave your hand in front of the PIR. After a full sudo reboot, the service restarts automatically and the alarm log file (alarm_events.log) shows a new BOOT line appended below the previous session's SHUTDOWN line, confirming cross-reboot persistence.
