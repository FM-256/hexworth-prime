Subject

AWS Networking and VPC Security

Journeyman 60 min 500 XP
Mission Brief

Your assignment is to build a secure, production-grade AWS network from scratch by creating a custom Virtual Private Cloud and launching an EC2 instance into it with precisely controlled access paths. This is the foundational network architecture pattern used in every serious AWS deployment.

You will design a dual-subnet layout separating public-facing and private resources, configure an Internet Gateway for outbound public access, and deploy a NAT Gateway so private instances can reach the internet without being directly reachable. Security Groups will act as instance-level firewalls while Network ACLs enforce subnet-level stateless filtering. Route tables will steer traffic through the correct egress path depending on subnet classification.

By the end of this operation you will understand the difference between stateful Security Groups and stateless NACLs, how 0.0.0.0/0 routes interact with gateways, and how to verify connectivity using aws ec2 describe-vpcs and instance reachability checks.

Agent Requirements
  • AWS account with IAM permissions for VPC, EC2, and networking resources
  • AWS CLI installed and configured with access key and secret (aws configure)
  • Basic understanding of IPv4 CIDR notation and subnetting
  • Familiarity with SSH key pairs for EC2 instance access
  • Understanding of TCP/IP ports and protocol concepts (HTTP, HTTPS, SSH)
Operation Phases
1
VPC Creation and CIDR Planning
Create a VPC with CIDR block 10.0.0.0/16 using the AWS Console or CLI with aws ec2 create-vpc --cidr-block 10.0.0.0/16. Enable DNS hostnames and DNS resolution on the VPC. Plan your subnet layout: a public subnet at 10.0.1.0/24 and a private subnet at 10.0.2.0/24 in the same Availability Zone. Create both subnets and tag them appropriately.
2
Internet Gateway and Route Tables
Create and attach an Internet Gateway to your VPC with aws ec2 create-internet-gateway followed by aws ec2 attach-internet-gateway. Create a public route table with a default route 0.0.0.0/0 pointing to the IGW. Associate it with the public subnet. Create a separate private route table and associate it with the private subnet. Enable auto-assign public IPs on the public subnet.
3
NAT Gateway for Private Subnet Egress
Allocate an Elastic IP address for the NAT Gateway with aws ec2 allocate-address --domain vpc. Create the NAT Gateway in the public subnet using the allocated EIP. Update the private route table to route 0.0.0.0/0 through the NAT Gateway. Verify that instances in the private subnet can reach the internet while remaining unreachable from external sources. Note the cost implications of a running NAT Gateway.
4
Security Groups and Network ACLs
Create a Security Group for the public EC2 instance allowing inbound SSH on port 22 from your IP only, and HTTP/HTTPS from 0.0.0.0/0. Create a private SG allowing only traffic from the public SG on your application port. Configure Network ACLs for each subnet with explicit inbound and outbound rules, remembering that NACLs are stateless and require rules for both directions including ephemeral ports 1024-65535.
5
EC2 Launch and Connectivity Verification
Launch a bastion EC2 instance into the public subnet with your public SG. Launch a second instance into the private subnet with the private SG. SSH into the bastion using its public IP, then hop to the private instance using its private IP. Verify the private instance can reach the internet through NAT by running curl https://checkip.amazonaws.com. Confirm it appears with the NAT Gateway's EIP, not its own IP.
6
VPC Flow Logs and Cleanup
Enable VPC Flow Logs to capture accepted and rejected traffic to CloudWatch Logs. Generate some traffic, then query the logs to verify your Security Group and NACL rules are behaving as expected. Attempt a blocked connection and confirm the rejection appears in flow log records with the REJECT action. After verification, terminate instances and delete NAT Gateway to stop charges, then release the Elastic IP.
