Subject

Build a Crossword Puzzle Generator

Recruit 60 MIN 250 XP
Mission Brief

This operation builds a crossword puzzle generator using Vite 8 as the build tool and Vitest 4 for unit testing. You will write a grid-placement algorithm from scratch in TypeScript: it accepts a word list with clues, finds every position where a new word can share a letter with an existing word, scores each candidate by intersection count, places the best-scoring one, and renders the finished grid as an interactive puzzle in the browser. No external puzzle libraries are used — you own every line of the algorithm.

Word placement operates in two passes. In the first pass, the generator sorts words longest-first (long words provide more intersection opportunities and constrain the space more usefully), then greedily places each one at the highest-scoring candidate position found by scanning all occupied cells for shared letters. Each candidate is validated against four rules: the word must fit within grid bounds, no letter in an existing cell may conflict with the new word, no cell immediately before or after the word in its direction may be occupied, and no empty cell in the new word's span may have a parallel neighbour (which would create an unintended merged word). In the second pass, numberGrid assigns sequential clue numbers following the standard crossword convention: left-to-right, top-to-bottom.

The interactive frontend renders the grid as an HTML table with input cells for letters and dark cells for gaps. Typing in a cell immediately shows green for a correct letter and red for a wrong one. A completion banner fires when every cell is filled correctly. Vitest unit tests cover createGrid, placeWord, canPlace, findCandidates, numberGrid, and generateCrossword — 29 tests, all passing in under 200 ms.

Agent Requirements
  • Node.js LTS (v20 or v22) and npm 10+ — verify with node --version and npm --version before starting. Download from nodejs.org if missing.
  • JavaScript fundamentals: arrays, objects, loops, and functions. TypeScript syntax is introduced step by step — prior TypeScript experience is not required.
  • Basic understanding of the terminal: changing directories, running commands, reading error output.
  • No algorithm or data-structures background needed — the placement logic is built up incrementally across five observable phases.
  • Curiosity about how puzzle generation differs from puzzle solving. Generation is a constraint-satisfaction problem; solving is search. You are building the generator.

Intersection-Finding Placement Algorithm and Clue Numbering
Replace the stub findCandidates with the full intersection-scanning algorithm. Add canPlace to validate each candidate against four rules. Add numberGrid for standard clue numbering. Add generateCrossword as the top-level entry point. Extend the test file to cover all four functions.
  1. Add canPlace to generator.ts. This is the core validity check. It returns the number of letter intersections, or -1 if the placement is illegal:
    export function canPlace( grid: Cell[][], word: string, row: number, col: number, direction: Direction ): number { const rows = grid.length; const cols = grid[0].length; const upper = word.toUpperCase(); const len = upper.length; // Rule 1 -- bounds check if (direction === 'across') { if (col < 0 || col + len > cols || row < 0 || row >= rows) return -1; } else { if (row < 0 || row + len > rows || col < 0 || col >= cols) return -1; } // Rule 2 -- no occupied cell immediately before or after the word if (direction === 'across') { if (col > 0 && grid[row][col - 1].letter !== '') return -1; if (col + len < cols && grid[row][col + len].letter !== '') return -1; } else { if (row > 0 && grid[row - 1][col].letter !== '') return -1; if (row + len < rows && grid[row + len][col].letter !== '') return -1; } let intersections = 0; for (let i = 0; i < len; i++) { const r = direction === 'across' ? row : row + i; const c = direction === 'across' ? col + i : col; const existing = grid[r][c].letter; if (existing !== '') { // Rule 3 -- intersecting letters must match if (existing !== upper[i]) return -1; intersections++; } else { // Rule 4 -- empty cells must not have parallel neighbours if (direction === 'across') { const above = r > 0 ? grid[r - 1][c].letter : ''; const below = r < rows - 1 ? grid[r + 1][c].letter : ''; if (above !== '' || below !== '') return -1; } else { const left = c > 0 ? grid[r][c - 1].letter : ''; const right = c < cols - 1 ? grid[r][c + 1].letter : ''; if (left !== '' || right !== '') return -1; } } } return intersections; }
    Rule 4 explained. Imagine the grid has the word PYTHON placed across row 7. If you try to place CODE across row 8 at the same columns, each empty cell of CODE has the corresponding PYTHON letter directly above it. Rule 4 catches this: an empty cell in the new word's span may not have a letter in the parallel direction. This prevents two words from running side-by-side without sharing a letter, which would produce an unsolvable grid.
  2. Replace the stub findCandidates with the full version. The key change is the inner loop that scans every occupied cell for a matching character in the candidate word, then tries placing the word in both directions so that character lands at the intersection:
    export function findCandidates( grid: Cell[][], word: string, placedWords: PlacedWord[] ): Array<{ row: number; col: number; direction: Direction; intersections: number }> { const rows = grid.length; const cols = grid[0].length; const upper = word.toUpperCase(); const candidates: Array<{ row: number; col: number; direction: Direction; intersections: number }> = []; if (placedWords.length === 0) { const row = Math.floor(rows / 2); const col = Math.floor((cols - upper.length) / 2); const score = canPlace(grid, upper, row, col, 'across'); if (score >= 0) candidates.push({ row, col, direction: 'across', intersections: 0 }); return candidates; } for (let r = 0; r < rows; r++) { for (let c = 0; c < cols; c++) { const cellLetter = grid[r][c].letter; if (cellLetter === '') continue; for (let i = 0; i < upper.length; i++) { if (upper[i] !== cellLetter) continue; // Try placing with upper[i] at (r, c), going across const acrossScore = canPlace(grid, upper, r, c - i, 'across'); if (acrossScore > 0) { // Only accept if the existing word at this cell runs in the other direction const existingDir = placedWords.find(pw => { for (let k = 0; k < pw.word.length; k++) { const pr = pw.direction === 'across' ? pw.row : pw.row + k; const pc = pw.direction === 'across' ? pw.col + k : pw.col; if (pr === r && pc === c) return true; } return false; })?.direction; if (existingDir !== 'across') { candidates.push({ row: r, col: c - i, direction: 'across', intersections: acrossScore }); } } // Try placing going down const downScore = canPlace(grid, upper, r - i, c, 'down'); if (downScore > 0) { const existingDir = placedWords.find(pw => { for (let k = 0; k < pw.word.length; k++) { const pr = pw.direction === 'across' ? pw.row : pw.row + k; const pc = pw.direction === 'across' ? pw.col + k : pw.col; if (pr === r && pc === c) return true; } return false; })?.direction; if (existingDir !== 'down') { candidates.push({ row: r - i, col: c, direction: 'down', intersections: downScore }); } } } } } // Deduplicate identical row/col/direction triples const seen = new Set<string>(); const unique = candidates.filter(cd => { const key = `${cd.row},${cd.col},${cd.direction}`; if (seen.has(key)) return false; seen.add(key); return true; }); return unique.sort((a, b) => b.intersections - a.intersections); }

    export function numberGrid(grid: Cell[][], placedWords: PlacedWord[]): void { const rows = grid.length; const cols = grid[0].length; for (let r = 0; r < rows; r++) for (let c = 0; c < cols; c++) grid[r][c].clueNumber = 0; let clueNum = 1; for (let r = 0; r < rows; r++) { for (let c = 0; c < cols; c++) { if (grid[r][c].letter === '') continue; const startsAcross = (c === 0 || grid[r][c - 1].letter === '') && c + 1 < cols && grid[r][c + 1].letter !== ''; const startsDown = (r === 0 || grid[r - 1][c].letter === '') && r + 1 < rows && grid[r + 1][c].letter !== ''; if (startsAcross || startsDown) grid[r][c].clueNumber = clueNum++; } } } // WordEntry was already defined and exported in Phase 2 — reuse it here, do not redeclare it. export function generateCrossword( entries: WordEntry[], rows = 15, cols = 15 ): { grid: Cell[][]; placed: PlacedWord[] } { if (entries.length === 0) return { grid: createGrid(rows, cols), placed: [] }; const sorted = [...entries].sort((a, b) => b.word.length - a.word.length); const grid = createGrid(rows, cols); const placed: PlacedWord[] = []; for (const entry of sorted) { const candidates = findCandidates(grid, entry.word, placed); if (candidates.length === 0) continue; const best = candidates[0]; placeWord(grid, entry.word, best.row, best.col, best.direction); placed.push({ word: entry.word.toUpperCase(), clue: entry.clue, row: best.row, col: best.col, direction: best.direction, }); } numberGrid(grid, placed); return { grid, placed }; }

A test fails because canPlace returns -1 when you expect 0 or more?
  • Parallel-adjacency false positive: the most common trap is forgetting that Rule 4 only applies to empty cells in the new word's span. Cells that already hold a matching letter are intersections (Rule 3), not adjacency violations. Confirm your loop checks if (existing !== '') { ... intersections++ } else { /* check adjacency */ } — not the other way around.
  • First-word returns -1: the bounds check fires if the word is longer than the grid minus the starting column. For a 15-column grid and a 6-letter word, col = floor((15-6)/2) = 4. col + len = 10, which is less than 15 — valid. If you are using a different starting formula, verify col + len <= cols.
  • findCandidates returns 0 candidates for the second word: confirm that canPlace requires acrossScore > 0 (strictly positive), meaning at least one intersection. A return value of 0 means no intersections — a parallel, non-crossing placement is rejected. The algorithm only accepts placements that cross an existing word.

The grid renders but shows no clue numbers or all cells are dark?
  • If all cells are dark, generateCrossword returned no placed words (the word list produced no intersections). Clicking a letter highlights the wrong word, or the clue panel is empty?
  • The highlightWord function finds the first placed word whose span covers the clicked cell. If a cell belongs to two words (an intersection), only one is highlighted. Click the clue panel item instead to highlight a specific word.
  • If the clue panel is empty, placed is an empty array. See the previous trap. Check console.log(placed).
  • Vite hot-module replacement (HMR) automatically reloads the page when you save main.ts or generator.ts. If changes are not reflected, check the terminal for compilation errors — HMR stops updating when TypeScript compilation fails.
