Subject

Build a Crossword Puzzle Generator

Recruit 60 MIN 250 XP
Mission Brief

This operation constructs a crossword puzzle generator using Vite as the build tool and Vitest for unit testing. You will implement an automated grid layout algorithm that accepts a word list with clues, attempts to place words by finding letter intersections, scores candidate placements to maximize grid density, and renders the result as an interactive puzzle in the browser. No external puzzle libraries are used — the algorithm is written from scratch to give you full understanding of how grid-based constraint satisfaction works.

Word placement operates in two phases. First, the generator sorts words by length (longest first, since they constrain more space) and finds all possible positions where a new word could intersect an already-placed word at a shared letter. Each candidate position is scored by the number of intersections it creates with existing words, with higher-intersection placements preferred. Second, a validation pass ensures no two word segments are adjacent without a shared letter, since this would make the grid unsolvable without ambiguity.

The interactive frontend renders the grid as a CSS Grid of input cells. Cells are numbered for clue references. Correct letters highlight in green on input, wrong letters highlight in red, and a completion check fires when every cell has an entry. Vitest unit tests cover the placement algorithm, the validation logic, the numbering system, and the answer checking function — giving you exposure to test-driven development at a practical scale.

Agent Requirements
  • JavaScript fundamentals: arrays, objects, loops, and functions
  • Basic understanding of the DOM and how to manipulate elements dynamically
  • Comfortable running npm commands and working with a Vite dev server
  • No algorithm or data structures background required — the placement logic is built up step by step
  • Curiosity about how puzzle generation differs from puzzle solving (they are not the same problem)
Operation Phases
1
Vite Project Setup & Grid Model
Scaffold the project with npm create vite@latest crossword -- --template vanilla-ts. Define the core data structures: a Cell type with letter, blocked, and clueNumber fields, and a PlacedWord type with word, clue, row, col, and direction fields. Implement a createGrid(rows, cols) factory that fills a 2D array with default cell objects. Write the first Vitest test that verifies grid dimensions and default field values.
Checkpoint: Vite Setup & Grid Model
  • npm run dev launches the Vite dev server without errors
  • Grid model creates a 2D array of the configured dimensions
  • TypeScript types for Cell and PlacedWord compile without type errors
2
Word Placement Algorithm
Implement findCandidates(grid, word, placedWords) that returns all valid positions where word can be placed by scanning every cell that contains a letter matching any character in the candidate word. For each intersection, check that the word fits on the grid in the perpendicular direction, that no adjacent parallel cells are occupied, and that intersecting letters match exactly. Return candidates sorted by intersection count descending. Implement placeWord(grid, word, row, col, dir) that mutates the grid and appends to the placed list.
Checkpoint: Word Placement Algorithm
  • First word places horizontally in the center of the grid
  • Subsequent words intersect existing words at shared letters
  • Algorithm rejects placements that create invalid adjacencies
3
Clue Numbering & Validation
Implement numberGrid(grid, placedWords) that assigns sequential clue numbers to the starting cell of each placed word following standard crossword convention: left-to-right, top-to-bottom. A cell gets a number only when a word starts there (no letter immediately before it in the word's direction). Implement validateGrid(grid) that checks for isolated letter islands (cells with a letter but no valid across or down word passing through them). Write Vitest tests for both functions with hand-crafted grids.
Checkpoint: Clue Numbering
  • Clue numbers follow standard crossword sequencing (left-to-right, top-to-bottom)
  • Each word's starting cell displays the correct clue number
  • Across and Down clue lists contain the correct number of entries
4
Interactive Grid Renderer
Build the DOM renderer in render.ts. Map the 2D grid array to an HTML table where blocked cells are dark, letter cells are input elements, and numbered cells show the clue number as a superscript positioned with CSS. Wire an input event listener that compares the typed character against the solution letter (stored in a data attribute), adds a correct or incorrect CSS class, and triggers a completion check when all inputs are filled. Keep the solution out of the visible DOM to prevent inspection cheating.
Checkpoint: Interactive Grid
  • Letter cells accept keyboard input and blocked cells are non-interactive
  • Arrow keys and Tab move focus between cells in the correct direction
  • Clicking a clue highlights all cells belonging to that word
5
Clue Panel & Controls
Build a two-column clue panel alongside the grid listing Across clues and Down clues by number. Clicking a clue highlights all cells of that word by toggling an active CSS class. Add a reveal button that shows the answer for the active word after a confirmation. Implement a resetPuzzle() function that clears all inputs and removes all state classes. Add a timer that starts on first keypress and stops on completion, displaying elapsed time in the completion banner.
Checkpoint: Clue Panel & Controls
  • Across and Down clue panels list all clues with correct numbering
  • Check button highlights incorrect letters in red
  • Reveal button fills all cells with the correct solution
6
Vitest Suite & Custom Word Lists
Write a comprehensive Vitest test suite with describe blocks for: grid creation, word placement with intersection validation, clue numbering correctness, grid validation detecting isolated cells, answer checking returning true only when all letters match, and the timer start/stop behavior. Target at least 85% branch coverage as reported by vitest --coverage. Add a word list import UI that accepts a JSON file of [{ word, clue }] objects and regenerates the puzzle on upload, allowing instructors to create custom themed puzzles.
Checkpoint: Vitest Suite & Word Lists
  • Running npx vitest passes all unit tests for grid and placement logic
  • Custom word list input generates a valid crossword from user-provided words
  • Edge cases (single word, no intersections possible) are handled gracefully
