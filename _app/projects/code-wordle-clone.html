Subject

Build a Wordle Clone

Recruit 60 min 250 XP
Mission Brief

Your assignment is to build a faithful Wordle clone as a real React + Vite application that runs in a local development server. You will scaffold the project with one command, write functional components with hooks, and end up with a playable game that lives in your own folder.

The player has six attempts to guess a hidden five-letter word. After each guess, each letter tile receives a color-coded result: green for correct position, yellow for present but wrong position, and gray for absent. The same feedback is mirrored on a virtual on-screen keyboard. Physical keyboard input and the on-screen keys both route through the same handler.

Honest prerequisite: this is not a double-click-and-open project. It requires Node.js installed on your machine and a terminal. Phase 1 walks you through that from zero. Once Node is installed the rest is copy-and-paste JSX.

Agent Requirements
  • Node.js LTS installed — download free from nodejs.org; Phase 1 covers this step by step. Version 20.19 or 22.12 or newer is required by Vite 8.
  • A terminal — Terminal on Mac, PowerShell or Command Prompt on Windows (both work)
  • A code editor — VS Code is recommended (code.visualstudio.com); any plain-text editor works
  • No prior React experience required — every concept is introduced before the code that uses it
  • Basic familiarity with opening a terminal and navigating to a folder with cd is helpful but not mandatory — Phase 1 explains each command

Install Node.js, Scaffold the Project, and Tour the Files
Before any React code you need Node.js on your machine. Then one command builds the entire project skeleton — index.html, src/main.jsx, src/App.jsx, vite.config.js, and a package.json listing every dependency. After that you start the dev server and see the live preview at localhost:5173.
  1. Install Node.js LTS. Open your browser and go to nodejs.org. Click the large Download Node.js (LTS) button — LTS means Long-Term Support, which is the stable version. Run the installer and accept all defaults. When it finishes, close and reopen your terminal so the new node command is on your PATH.
  2. Confirm the install worked. In your terminal, run these two commands one at a time:
    node -v npm -v
    Each should print a version number, for example v22.14.0 and 10.9.2. If you see command not found, close the terminal completely and reopen it — the installer adds Node to PATH only for new terminal sessions.
  3. Choose where to put your project. Navigate to the folder where you keep your code. For example, to put it on the Desktop:
    cd ~/Desktop
    On Windows PowerShell use the same command — PowerShell understands ~/Desktop. If you prefer a different location, cd there instead.
  4. Scaffold the React + Vite project. Run this single command exactly as written, including the -- before --template:
    npm create vite@latest my-wordle -- --template react
    Vite will ask two questions: Project name (press Enter to accept my-wordle) and Select a framework (if it prompts, choose React). You should see output ending with lines like Done. Now run:.
    Why two dashes before --template? The first -- tells npm "stop reading npm flags here; everything after this goes to the create-vite script." Without it, npm tries to interpret --template as its own flag and ignores it.
  5. Enter the project folder and install dependencies.
    cd my-wordle npm install
    npm install reads package.json and downloads React, ReactDOM, and Vite into a node_modules/ folder. This takes 15–30 seconds.
  6. Start the development server.
    npm run dev
    Vite prints something like:
    VITE v8.0.16 ready in 312 ms ➜ Local: http://localhost:5173/ ➜ Network: use --host to expose
    Open your browser and go to http://localhost:5173. You should see the default Vite + React starter page with a spinning logo. The terminal keeps running — that is the dev server. Leave it open while you work.
  7. Open the project in VS Code. Keep the terminal running. In a second terminal window (or in VS Code's built-in terminal), open the project:
    code my-wordle
    If code is not recognized, open VS Code manually: File → Open Folder → navigate to Desktop → my-wordle → confirm. The left panel shows the project files.
  8. Understand what Vite generated. In VS Code's left panel you will see:
    my-wordle/ index.html ← the one HTML page; loads src/main.jsx via a script tag vite.config.js ← Vite configuration (you won't need to change this) package.json ← project name, scripts, and dependency list node_modules/ ← all downloaded packages (never edit this) src/ main.jsx ← entry point; mounts <App /> into the #root div in index.html App.jsx ← the root React component (this is where your game goes) App.css ← styles imported by App.jsx index.css ← global styles; imported by main.jsx
    How React gets on screen: index.html has a <div id="root"></div> and a <script> tag pointing at src/main.jsx. That file calls ReactDOM.createRoot(document.getElementById('root')).render(<App />), which tells React to take over the #root div and draw whatever <App /> returns. Everything you build from here on lives inside App.jsx or files it imports. Only edit App.jsx and files you create yourself (like words.js and App.css). Do not edit main.jsx — it is the entry-point glue that Vite expects to stay intact.
  9. Test hot-reload. Open src/App.jsx in VS Code. Find the text Vite + React or count is and change one word — anything. Save with Ctrl+S (Mac: Cmd+S). Switch to the browser: the page updates instantly without a manual refresh. That is Vite's Hot Module Replacement (HMR) — every save you make from here on appears in the browser immediately.
node -v says "command not found" even after closing and reopening the terminal?
  • On Windows: search the Start Menu for Node.js Command Prompt — the installer may have added a dedicated shortcut. Also try reopening PowerShell as Administrator.
  • On Mac: if you used nvm or Homebrew to install Node, you may need to add a line to ~/.zshrc. The nodejs.org installer handles this automatically — use that if in doubt.
  • The simplest fix on any system: restart the computer fully, then open a fresh terminal.
npm create vite prompts me for a framework name even though I passed --template react? If Vite 8's interactive prompt appears anyway, use the arrow keys to select React (not React + TypeScript), then press Enter. The result is identical to what --template react produces.
Port 5173 is already in use? Another app is running on that port. Either close that app and re-run npm run dev, or Vite will automatically try the next port (5174, 5175 …) and tell you the URL in the terminal output.
The browser shows a completely blank white page with no error in the Console? This usually means main.jsx cannot mount React onto the page. Check two things: (1) index.html still contains <div id="root"></div> — if that div was accidentally deleted, React has nowhere to render. (2) src/main.jsx still contains the line ReactDOM.createRoot(document.getElementById('root')).render(<App />). If either file was edited or corrupted, delete it and let Vite regenerate it (stop the dev server, delete the file, run npm create vite@latest . to re-scaffold into the same folder and say "yes" to overwrite, then npm install and npm run dev again).
Checkpoint — what you should see
The browser at http://localhost:5173 shows the default Vite + React page: a Vite logo, a React logo, a counter button, and some text. The terminal shows no errors. When you edit and save src/App.jsx the browser updates without a manual refresh. If the browser shows a blank white page, open the browser's developer tools (right-click → Inspect → Console tab) — a red JSX or import error will be visible there. If the Console is also empty (no error at all), see the troubleshooting box directly above about the React root div and main.jsx.

SyntaxError or blank white page after pasting?
  • Open the browser Console (right-click → Inspect → Console). The error message will say which file and line caused the problem. The most common mistakes are a missing > after a JSX tag, a stray comma inside JSX, or a missing closing tag.
  • "Adjacent JSX elements must be wrapped in an enclosing tag" — a component can only return one root element. Wrap everything in a single <div> or use a React fragment: <>...</>.
  • "className" instead of "class" — in JSX, HTML's class attribute is spelled className. Writing class= in JSX causes an error.
Module not found: './words.js'? The file must be named exactly words.js and saved inside the src/ folder, not in the project root. Check the left panel in VS Code — it should appear under src/ alongside App.jsx.

Keyboard Input: handleKey, Physical Keyboard, and the On-Screen Keyboard
Wire up a single handleKey(key) function that handles letter keys, Backspace, and Enter. A useEffect attaches it to the physical keyboard; an on-screen keyboard component fires the same function. After this phase you can type letters, see them appear in tiles, and delete them with Backspace.
Why useEffect for the keyboard listener? React functional components re-run on every state change. If you called window.addEventListener directly inside the component body, you would add a new listener on every render and never remove old ones. useEffect runs once after the first render (empty dependency array []) and returns a cleanup function that removes the listener when the component unmounts — keeping exactly one listener alive at all times.
  1. Replace the entire contents of src/App.jsx with the version below. This is a complete replacement — delete everything that is there now and paste this:
    // src/App.jsx — Phase 3: handleKey + physical & on-screen keyboard import { useState, useEffect } from 'react'; import { TARGETS, VALID } from './words.js'; import './App.css'; const todayIndex = Math.floor(Date.now() / 86400000) % TARGETS.length; const TARGET = TARGETS[todayIndex].toUpperCase(); const ROWS = 6; const COLS = 5; function makeBoard() { return Array.from({ length: ROWS }, () => Array.from({ length: COLS }, () => ({ letter: '', status: '' })) ); } // ── On-screen keyboard component ─────────────────────────────────────────── // Renders three rows of keys. Each key fires onKey(key) when clicked. // keyColors maps each letter to its best revealed status so far. const KEYBOARD_ROWS = [ ['Q','W','E','R','T','Y','U','I','O','P'], ['A','S','D','F','G','H','J','K','L'], ['ENTER','Z','X','C','V','B','N','M','DEL'], ]; function Keyboard({ onKey, keyColors }) { return ( <div className="keyboard"> {KEYBOARD_ROWS.map((row, r) => ( <div key={r} className="keyboard-row"> {row.map((key) => ( <button key={key} className={`key ${keyColors[key] || ''} ${key.length > 1 ? 'key-wide' : ''}`} onClick={() => onKey(key)} > {key} </button> ))} </div> ))} </div> ); } // ── Root App component ───────────────────────────────────────────────────── export default function App() { const [board, setBoard] = useState(makeBoard()); const [currentRow, setCurrentRow] = useState(0); const [currentCol, setCurrentCol] = useState(0); const [gameOver, setGameOver] = useState(false); const [keyColors, setKeyColors] = useState({}); // handleKey receives a string: a single uppercase letter, 'ENTER', or 'DEL'/'BACKSPACE'. function handleKey(key) { if (gameOver) return; // do nothing after win or loss const k = key.toUpperCase(); if (k === 'BACKSPACE' || k === 'DEL') { // Remove the last typed letter in the current row if (currentCol === 0) return; // nothing to delete setBoard(prev => { const next = prev.map(r => r.map(c => ({ ...c }))); // deep copy next[currentRow][currentCol - 1].letter = ''; next[currentRow][currentCol - 1].status = ''; return next; }); setCurrentCol(c => c - 1); return; } if (k === 'ENTER') { // Submission is handled in Phase 4; do nothing here yet. return; } // Single letter key: A-Z only if (!/^[A-Z]$/.test(k)) return; if (currentCol >= COLS) return; // row is full setBoard(prev => { const next = prev.map(r => r.map(c => ({ ...c }))); next[currentRow][currentCol].letter = k; next[currentRow][currentCol].status = 'tbd'; // typed but not evaluated return next; }); setCurrentCol(c => c + 1); } // Attach handleKey to the physical keyboard. // The cleanup function (returned from useEffect) removes the listener // when the component unmounts, preventing duplicate listeners. useEffect(() => { function onKeyDown(e) { handleKey(e.key); } window.addEventListener('keydown', onKeyDown); return () => window.removeEventListener('keydown', onKeyDown); // eslint-disable-next-line react-hooks/exhaustive-deps }, [currentRow, currentCol, gameOver]); // ^ Re-register whenever these values change so handleKey always // "sees" the current row/col (avoids a stale-closure bug). return ( <div className="game-container"> <header className="game-header"> <h1>Wordle Clone</h1> </header> <div className="board"> {board.map((row, r) => ( <div key={r} className="board-row"> {row.map((cell, c) => ( <div key={c} className={`tile ${cell.status}`}> {cell.letter} </div> ))} </div> ))} </div> <Keyboard onKey={handleKey} keyColors={keyColors} /> </div> ); }

Two-Pass Color Evaluation and Keyboard Sync
Wire the Enter key: validate the guess against the word list, evaluate colors with a two-pass algorithm that handles duplicate letters correctly, update the board tiles, and sync the on-screen keyboard to show each letter's best status. This is the core game logic.
Why two passes? Consider guessing SPEED when the target is CREEK. The letter E appears once in CREEK but twice in SPEED. A naive one-pass algorithm would color both Es yellow, which is wrong — only one yellow should appear. The fix: Pass 1 locks in exact matches (green) and removes those letters from a frequency map of the target. Pass 2 only marks a letter yellow if the frequency map still has remaining count for it, then decrements that count. This guarantees you never get more yellows for a letter than the target actually contains.

Tile Flip Animation, Streak Tracking, and the Complete App
Add the staggered tile-flip animation that reveals colors left-to-right, persist a streak counter in localStorage, and add a New Game button. After this phase the project is a complete, polished Wordle clone.
How the flip animation works: Each tile rotates from 0 to 90 degrees on the X axis (face disappears), then back from 90 to 0 degrees (face reappears). The status class (correct, present, or absent) is applied to the tile at the same moment it begins to rotate, so by the time the tile is face-forward again the class-based background color is already in effect — the colored face is what reappears. The keyframe only controls rotation; it never overrides background or border-color, which is what keeps the revealed colors stable. Each tile in the row has a different animation-delay (0ms, 150ms, 300ms, 450ms, 600ms), creating the left-to-right cascade. We apply the flip class only to the row just submitted, not to all rows.
