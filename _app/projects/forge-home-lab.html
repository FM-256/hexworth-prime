Subject

Build a 3-VM Home Lab

Operative 3 hrs 500 XP
Mission Brief

Build a complete cybersecurity home lab with three virtual machines: a Windows Server domain controller, a Windows 10 workstation joined to the domain, and a Kali Linux attacker. All three communicate on an isolated virtual network.

This is the lab environment used across Hexworth for Active Directory attacks, network forensics, and enterprise security exercises. Building it yourself teaches you how enterprise networks actually work — domain controllers, DNS, DHCP, group policy, and domain-joined clients.

By the end, you will have a miniature corporate network on your laptop that you can attack, defend, and rebuild at will.

Agent Requirements
  • VirtualBox or VMware Workstation installed
  • At least 16 GB total RAM (10 GB allocatable to run all three VMs concurrently: 4 + 4 + 2)
  • Windows Server 2022 evaluation ISO (free 180-day eval from Microsoft)
  • Windows 10 Enterprise evaluation ISO (free 90-day eval from Microsoft)
  • Kali Linux ISO from kali.org
  • 80+ GB free disk space
Operation Phases
Progress
0 / 5
✓
1
Create the Isolated Network
In your hypervisor, create a host-only or internal network (e.g., 10.0.0.0/24). All three VMs will connect to this network only. No internet access for the lab network — isolation prevents accidental exposure.
Checkpoint — how to verify
  • Create a host-only/internal network and confirm VMs on it can reach each other but not the internet unless intended
  • Confirm the lab is isolated from your production LAN
✓
2
Build the Domain Controller
Create a Windows Server VM (2 CPU, 4 GB RAM, 40 GB disk). Install Windows Server 2022. Set a static IP (10.0.0.1). Install Active Directory Domain Services via Server Manager. Promote to domain controller for hexlab.local. AD automatically configures DNS.
Checkpoint — how to verify
  • Install the AD DS role and promote the server to a domain controller for hexlab.local
  • In PowerShell, run Get-ADDomain and confirm it returns hexlab.local; confirm AD DS appears under Roles in Server Manager
✓
3
Build the Workstation
Create a Windows 10 VM (2 CPU, 4 GB RAM, 40 GB disk). Set DNS to 10.0.0.1 (the DC). Join the domain: Settings > System > About > Rename this PC (advanced) > Change > Domain: hexlab.local. Log in with domain admin credentials.
Checkpoint — how to verify
  • Join the workstation to hexlab.local and reboot
  • Log in as hexlab\Administrator, then open Settings > System > About and confirm "Domain: hexlab.local" appears under Device specifications
✓
4
Build the Attacker
Create a Kali VM (2 CPU, 2 GB RAM, 30 GB disk). Set its network to the same isolated network. Assign IP 10.0.0.100. Verify connectivity: ping 10.0.0.1 should reach the DC. Run nmap 10.0.0.0/24 to see all three machines.
Checkpoint — how to verify
  • Build the attacker VM and confirm it sits on the same isolated network
  • From the attacker, run ping 10.0.0.1 to reach the DC and nmap 10.0.0.0/24 to see all three machines
✓
5
Snapshot Everything
Take a snapshot of each VM in its current clean state. Name them "Lab-Ready". These are your restore points. After every attack exercise, revert all three to Lab-Ready. Document the network diagram: IPs, hostnames, credentials.
Checkpoint — how to verify
  • Take a clean snapshot of all three VMs so you can reset the lab
  • Restore one snapshot and confirm the VM returns to its clean state
