Subject

Build a Blockchain from Scratch

Advanced 3H 1200 XP
Mission Brief

This operation requires the construction of a fully functional blockchain implemented in Python from the ground up. You will build the core data structures — blocks, chains, and transactions — then layer on proof-of-work mining, wallet generation with public/private key pairs, and a REST API that allows external clients to interact with your chain. The result is a working distributed ledger that demonstrates every fundamental concept behind cryptocurrency and blockchain technology without relying on any existing blockchain framework.

Each block in the chain contains a SHA-256 hash that cryptographically binds it to its predecessor, creating an immutable audit trail. The proof-of-work algorithm forces miners to expend computational effort finding a nonce that produces a hash with a configurable number of leading zeros, making it prohibitively expensive to tamper with the chain after the fact. Transactions are validated against sender balances, signed with private keys, and batched into blocks via a mempool. The consensus mechanism resolves conflicts between nodes by adopting the longest valid chain, exactly as described in the original Bitcoin whitepaper.

Beyond the finished artifact, this project delivers deep understanding of the cryptographic primitives that underpin modern decentralized systems. You will internalize why hash functions create tamper-evident data structures, why proof-of-work makes double-spending economically infeasible, and why public-key cryptography enables trustless ownership — all at the implementation level where the real learning happens.

Agent Requirements
  • Solid Python fundamentals: classes, dictionaries, and JSON serialization
  • Basic understanding of hash functions — what it means for a function to be one-way and collision-resistant
  • Comfortable with HTTP concepts: GET, POST, request bodies, and status codes
  • Familiar with pip and virtual environments for dependency management
  • No prior blockchain or cryptocurrency experience required — this project teaches every concept from first principles
Operation Phases
1
Block Structure & Hashing
Design the Block class with fields for index, timestamp, transactions, previous_hash, nonce, and hash. Implement the hashing method using hashlib.sha256() over a deterministic JSON serialization of the block data. Build the genesis block with index 0 and a hardcoded previous hash of "0" * 64. Verify that any modification to block data produces a completely different hash.
Checkpoint: Block Structure & Hashing
  • Block hash changes when any field is modified
  • Genesis block is created with index 0 and a predefined previous hash
  • Hash output matches the expected SHA-256 digest for known inputs
2
Chain Validation & Integrity
Build the Blockchain class that maintains an ordered list of blocks. Implement is_valid() to walk the entire chain verifying that each block's previous_hash matches the actual hash of the preceding block and that each block's stored hash matches its recomputed hash. Add tamper detection that immediately identifies which block in the chain has been modified. Write unit tests that deliberately corrupt blocks and confirm validation fails.
Checkpoint: Chain Validation
  • is_valid() returns True for an unmodified chain
  • Tampering with any block data causes validation to fail
  • Broken previous_hash links are detected and reported
3
Proof-of-Work Mining
Implement the proof-of-work algorithm with a configurable difficulty parameter that specifies the required number of leading zeros in the hash. The mine_block() method iterates through nonce values starting from 0, recomputing the SHA-256 hash each time until the difficulty target is satisfied. Log mining time and nonce attempts to demonstrate the computational cost. Add a difficulty adjustment mechanism that increases difficulty as blocks are mined faster than the target interval.
Checkpoint: Proof-of-Work Mining
  • Mining loop finds a nonce producing a hash with required leading zeros
  • Increasing difficulty results in measurably longer mining times
  • Mined block hash starts with the correct number of zeros
4
Transaction Pool & Validation
Build a Transaction class with sender, recipient, amount, and signature fields. Implement a transaction mempool that queues pending transactions until the next block is mined. Validate that senders have sufficient balance by scanning the entire chain history. Reject duplicate transactions and enforce that coinbase (mining reward) transactions can only be created by the mining process itself.
Checkpoint: Transaction Pool
  • Valid transactions are added to the mempool
  • Transactions with invalid signatures are rejected by the pool
  • Mining a block clears included transactions from the mempool
5
Wallet & Key Pair Generation
Generate RSA or ECDSA key pairs using the cryptography library. Derive wallet addresses from the public key hash. Implement transaction signing with the private key and verification with the public key so that only the rightful owner of a wallet can spend its balance. Serialize keys to PEM format for persistence. Build a Wallet class that encapsulates key generation, signing, and balance lookup against the chain.
Checkpoint: Wallet & Key Pairs
  • Key pair generation produces a valid public and private key
  • Wallet address is derived deterministically from the public key hash
  • Signed transaction verifies against the corresponding public key
6
REST API & Node Communication
Expose the blockchain through a Flask REST API with endpoints: GET /chain (full chain), POST /transactions/new (submit transaction), GET /mine (mine next block), POST /nodes/register (add peer), and GET /nodes/resolve (consensus). Implement the longest-chain consensus algorithm that queries all registered peers and adopts the longest valid chain. Test with multiple Flask instances running on different ports to simulate a peer-to-peer network.
Checkpoint: REST API
  • GET /chain returns the full blockchain as JSON
  • POST /transactions/new adds a transaction and returns confirmation
  • GET /mine triggers mining and returns the new block
