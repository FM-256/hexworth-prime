Build a Calculator App

Recruit 1 hr 200 XP
Mission Brief

Build a fully functional calculator in HTML, CSS, and JavaScript. This is the classic first interactive project — it teaches you how to capture user input, process it, and display results in real time.

The calculator will handle addition, subtraction, multiplication, and division. It will have a display screen, number buttons, operator buttons, and a clear button. You will learn event handling, DOM manipulation, and basic state management.

This project is small enough to complete in one sitting but rich enough to teach patterns you will use in every interactive application.

Agent Requirements
  • A computer with a free text editor — we recommend VS Code (code.visualstudio.com); any plain-text editor works, but not Microsoft Word
  • A web browser (Chrome, Firefox, or Edge)
  • No prior coding experience required — every command is shown in full and explained line by line
  • Completed “My First Web Page” or know how to create an .html file and open it in a browser; Phase 1 reviews this in two steps

Wire the Buttons with JavaScript
The buttons look right but do nothing. JavaScript listens for clicks, reads the button's label, and updates the display. This phase adds three variables to track calculator state, then two event listeners — one for digit buttons and one for operator buttons. Equals and clear are wired in Phase 4.
Three state variables, one rule: currentInput holds what the user is currently typing (e.g. "8"). previousInput holds the first number once an operator is pressed (e.g. "5"). operator holds the pending operation (e.g. "+"). Every button press updates one or more of these, then the display is refreshed.
  1. Find the script comment inside <script> … </script> at the bottom of your file and replace it with the code below. The comment is /* JavaScript goes here in Phase 3 and 4 */. Replace only that comment — keep the <script> and </script> tags:
    /* ── State ── */ var currentInput = ''; /* digits being typed right now */ var previousInput = ''; /* first number, saved when op is pressed */ var operator = ''; /* + - * / pending */ var justCalculated = false; /* true right after = is pressed */ /* ── Helper: put a value on the display ── */ var display = document.getElementById('display'); function showDisplay(val) { display.textContent = (val === '' || val === undefined) ? '0' : val; } /* ── Digit / decimal-point buttons ── */ document.querySelectorAll('.btn-num').forEach(function(btn) { btn.addEventListener('click', function() { var digit = this.dataset.num; /* reads data-num="7" etc. */ /* After = was pressed, start fresh */ if (justCalculated) { currentInput = ''; previousInput = ''; operator = ''; justCalculated = false; } /* Block a second decimal point */ if (digit === '.' && currentInput.includes('.')) return; /* Block leading zeros (e.g. "007") */ if (digit === '0' && currentInput === '0') return; currentInput += digit; showDisplay(currentInput); }); }); /* ── Operator buttons (+ - * /) ── */ /* Phase 3: save first number and the pending operator. Operator chaining (5 + 3 * 2) is added in Phase 4 once the compute() function exists. */ document.querySelectorAll('.btn-op').forEach(function(btn) { btn.addEventListener('click', function() { /* Ignore if nothing has been typed yet */ if (currentInput === '') return; previousInput = currentInput; /* save first number */ currentInput = ''; /* clear for second number */ operator = this.dataset.op; /* save which op was pressed */ justCalculated = false; }); });

  3. Test it. Click several digit buttons: 1, 2, 3. The display should show 123. Click the decimal: display shows 123. Click 5: display shows 123.5. Click decimal again: nothing extra appears (the duplicate-dot block worked).

4
Compute the Result — Equals, Clear, and Chaining
The three remaining pieces: a compute() function that does the arithmetic, the = button that calls it and shows the answer, the C button that resets everything, and a small upgrade to the operator handler so a second operator press chains correctly instead of being ignored.
Why no eval()? You may find tutorials that use eval(displayValue) to run math. It works in a toy project but it is a serious security hole in any real application because eval() executes arbitrary code, not just arithmetic. The approach here uses a plain if/else switch — four lines, safe, and you can see exactly what it does.
  1. Replace the entire contents of your <script> block. Select everything between the <script> and </script> tags — all of the Phase 3 code — and delete it. Then paste this complete, final script in its place. This single block contains every piece: state variables, digit handler, compute function, equals, clear, and the upgraded operator handler with chaining. Do not add or keep any other code between the script tags:
    /* ── State ── */ var currentInput = ''; /* digits being typed right now */ var previousInput = ''; /* first number, saved when op is pressed */ var operator = ''; /* + - * / pending */ var justCalculated = false; /* true right after = is pressed */ /* ── Helper: put a value on the display ── */ var display = document.getElementById('display'); function showDisplay(val) { display.textContent = (val === '' || val === undefined) ? '0' : val; } /* ── compute: perform one arithmetic operation ── */ /* Returns a number, or the string 'Error' for divide-by-zero */ function compute(a, b, op) { if (op === '+') return a + b; if (op === '-') return a - b; if (op === '*') return a * b; if (op === '/') { if (b === 0) return 'Error'; /* division by zero: safe message */ return a / b; } return b; /* no operator saved: just return the second number */ } /* ── Digit / decimal-point buttons ── */ document.querySelectorAll('.btn-num').forEach(function(btn) { btn.addEventListener('click', function() { var digit = this.dataset.num; /* reads data-num="7" etc. */ /* After = was pressed, or after an Error, start fresh */ if (justCalculated || currentInput === 'Error') { currentInput = ''; previousInput = ''; operator = ''; justCalculated = false; } /* Block a second decimal point */ if (digit === '.' && currentInput.includes('.')) return; /* Treat a lone leading dot as 0. */ if (digit === '.' && currentInput === '') currentInput = '0'; /* Block leading zeros (e.g. "007") */ if (digit === '0' && currentInput === '0') return; currentInput += digit; showDisplay(currentInput); }); }); /* ── Operator buttons (+ - * /) — with chaining ── */ document.querySelectorAll('.btn-op').forEach(function(btn) { btn.addEventListener('click', function() { /* If the display holds an Error, pressing an operator resets */ if (currentInput === 'Error') { currentInput = ''; previousInput = ''; operator = ''; justCalculated = false; return; } if (currentInput === '' && previousInput === '') return; /* Chain: if we already have two numbers and an op, compute first */ if (currentInput !== '' && previousInput !== '' && operator !== '') { var chained = compute(Number(previousInput), Number(currentInput), operator); previousInput = String(chained); showDisplay(previousInput); currentInput = ''; } else if (currentInput !== '') { previousInput = currentInput; currentInput = ''; } operator = this.dataset.op; justCalculated = false; }); }); /* ── Equals button ── */ document.getElementById('btn-eq').addEventListener('click', function() { /* Need both numbers and an operator to compute */ if (previousInput === '' || currentInput === '' || operator === '') return; var a = Number(previousInput); var b = Number(currentInput); var result = compute(a, b, operator); showDisplay(result); /* show the answer */ currentInput = String(result); /* result becomes input for next chain */ previousInput = ''; operator = ''; justCalculated = true; /* next digit clears the screen */ }); /* ── Clear button ── */ document.getElementById('btn-clear').addEventListener('click', function() { currentInput = ''; previousInput = ''; operator = ''; justCalculated = false; showDisplay('0'); /* reset screen to 0 */ });
  2. Save and refresh. Test the full flow: click 8, then +, then 5, then =. The display should show 13.
Display shows NaN instead of a number?
  • NaN means “Not a Number” and happens when Number() tries to convert something that isn't a valid numeric string — for example an empty string or the word “Error”. The most common cause: you pressed an operator before typing any digits, so previousInput was still ''. The guard if (previousInput === '' ...) return; in the = listener prevents this — make sure that line is present.
  • If NaN appears after chaining (+, -, etc.), check that the old short operator handler from Phase 3 is fully removed; two listeners on the same buttons can fire in the wrong order.
Dividing by zero shows a crash or freezes? The if (b === 0) return 'Error'; line inside compute catches this and returns the string 'Error', which showDisplay puts on screen. If you see a crash instead, the guard is missing or the operator is something other than '/' — double-check the data-op on the divide button is exactly /.

A full working calculator: digits build a number, operators save it, = computes and shows the result, C resets to 0. Test each of the four operations: 3 + 4 = 7, 9 − 2 = 7, 6 × 3 = 18, 8 ÷ 4 = 2. Also test recovery after an error: 5 ÷ 0 = Error, then start a fresh calculation by typing a number — the Error clears automatically (for example 6 + 2 = 8). You should never see NaN. Keyboard Support and the Complete File
A good calculator responds to both mouse clicks and keyboard input. One keydown listener maps keyboard keys to the same logic the buttons already use, so you aren't duplicating any arithmetic code. After that, the finished file is shown in full so you can compare your version line by line.
  1. Add the keyboard listener. Paste this block at the very end of your <script> block, after all the button listeners:
    /* ── Keyboard support ── */ /* Maps physical keys to the same buttons already on screen. This re-uses the existing click handlers via .click() so all the guard logic (duplicate dot, chaining, etc.) applies. */ document.addEventListener('keydown', function(event) { var key = event.key; /* Digits 0-9 and decimal point */ if (/^[0-9.]$/.test(key)) { var numBtn = document.querySelector('[data-num="' + key + '"]'); if (numBtn) numBtn.click(); return; } /* Operators */ if (key === '+' || key === '-' || key === '*' || key === '/') { var opBtn = document.querySelector('[data-op="' + key + '"]'); if (opBtn) opBtn.click(); return; } /* Equals: Enter key or = key */ if (key === 'Enter' || key === '=') { document.getElementById('btn-eq').click(); return; } /* Clear: Escape key or Delete key */ if (key === 'Escape' || key === 'Delete') { document.getElementById('btn-clear').click(); return; } });
  2. Save and refresh. Before testing keyboard input, click anywhere on the page so it has keyboard focus — the browser delivers key events to whichever window or tab is in front, and a fresh page load may not have focus until you click. Then type 9, *, 8, Enter. The display should show 72. Press Escape to clear back to 0.
Keyboard does nothing?
  • Click anywhere on the page first to give it keyboard focus. The browser only sends keydown events to the focused window — if you haven't clicked, the page may not have focus yet.
  • If pressing / opens the browser's Quick Find bar (Firefox only), Firefox is intercepting the key before your code sees it. The finished snapshot already includes event.preventDefault(); at the top of the operators branch to block this — make sure that line is present in your script.
  • Make sure the listener is inside <script> and the <script> tag is before </body>.
