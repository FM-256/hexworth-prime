Subject

Build a Sensor Dashboard

Recruit 60 min 250 XP
Mission Brief

This operation turns an Arduino Mega 2560 and a breadboard of sensors into a live hardware dashboard — a physical instrument panel that reads real-world data and displays it on a 16x2 LCD with LED threshold indicators. You will wire a parallel 16x2 LCD using the built-in LiquidCrystal library, connect a DHT22 sensor for temperature and humidity, add a photoresistor (LDR) for ambient light level, and build a multi-screen display that cycles readings while LEDs signal threshold crossings.

No hardware? No problem. Every phase of this project is completable without any physical components using Wokwi (wokwi.com) — a free, browser-based Arduino simulator that supports the Mega 2560, the LCD1602 in parallel mode, DHT22, photoresistors, and LEDs. Wokwi is the primary path in this project, not a footnote. The real-hardware path is offered in parallel for those who have the kit.

This is the foundational pattern behind every IoT sensor node, industrial control panel, and embedded monitoring system: reading real-world data, processing it in firmware, and presenting it on a constrained display. An ELEGOO Mega R3 Ultimate Starter Kit or equivalent includes every physical component listed in the Asset Manifest.

Agent Requirements
  • Primary path (no hardware needed): a modern web browser and a free account at wokwi.com. Everything runs in the browser — no install required.
  • Parallel hardware path: Arduino Mega 2560 (or ELEGOO Mega R3 kit), 16x2 character LCD display + 10K contrast potentiometer, DHT22 temperature/humidity sensor, photoresistor (LDR) + 10K resistor, three LEDs (green, yellow, red) + three 220-ohm resistors, breadboard and jumper wires, USB-A to USB-B cable.
  • Arduino IDE 2.3.x installed — download free at arduino.cc/en/software. The IDE is needed for hardware uploads; Wokwi has its own in-browser editor.
  • Basic understanding of circuits: what voltage, ground, and digital/analog pins mean. No prior Arduino experience required — each phase introduces components step by step.
  • Comfort with C/C++ syntax at the level of variables, functions, and if-statements. Complete beginners can follow the paste-ready sketches and read the inline explanations.

Set Up Your Environment and Print "Hello" on the LCD
Get the 16x2 LCD wired and printing text. This phase uses the built-in LiquidCrystal library (parallel 4-bit mode) — no extra library to install. Completing this phase proves your LCD, wiring, and toolchain are all functional before adding any sensors.
  1. Choose your path: Wokwi (browser) or hardware.
    Wokwi path (recommended for beginners): go to wokwi.com and click New Project. Select Arduino Mega as the board. In the diagram panel, click the + button and search for LCD1602 to add it. Confirm the pins attribute is "full" (parallel mode, not I2C) — this is the default. Wire per the table below. You may add a Potentiometer for the V0 contrast pin to mirror the real circuit, but Wokwi does not simulate LCD contrast, so the text shows clearly regardless — the pot is optional in the simulator. No install, no upload cable needed.
    Hardware path: install Arduino IDE 2.3.x from arduino.cc/en/software. The LiquidCrystal library is bundled with the IDE — no Library Manager step needed for Phase 1. Connect the board via USB.
  2. Wire the LCD to the Arduino Mega. The LCD runs in 4-bit parallel mode: only pins D4-D7 carry data, which saves digital pins. Use this wiring table:
    LCD Pin Arduino Mega Pin Notes ----------- ----------------- --------------------- VSS (1) GND LCD ground VDD (2) 5V LCD power V0 (3) Potentiometer wiper Contrast adjust (0-5V) RS (4) Pin 12 Register Select RW (5) GND Always write mode E (6) Pin 11 Enable strobe D4 (11) Pin 5 Data bit 4 D5 (12) Pin 4 Data bit 5 D6 (13) Pin 3 Data bit 6 D7 (14) Pin 2 Data bit 7 A (15) 5V via 220-ohm Backlight anode K (16) GND Backlight cathode
    The contrast potentiometer: connect its two outer legs to 5V and GND; connect the middle wiper leg to LCD pin V0.
    In Wokwi: click each LCD pin in the diagram and drag a wire to the corresponding Mega pin. The potentiometer already appears as a component in Wokwi; connect its output terminal to V0.
  3. Open the sketch editor and paste the Hello World sketch. In Arduino IDE: File → New Sketch. In Wokwi: the sketch.ino tab is already open. Paste this complete sketch:
    // Phase 1: LCD Hello World // Uses the built-in LiquidCrystal library (parallel, no I2C adapter needed). #include <LiquidCrystal.h> // LiquidCrystal(rs, en, d4, d5, d6, d7) // These pin numbers match the wiring table above. LiquidCrystal lcd(12, 11, 5, 4, 3, 2); void setup() { lcd.begin(16, 2); // 16 columns, 2 rows lcd.setCursor(0, 0); // column 0, row 0 (top-left) lcd.print("Hello, Forge!"); lcd.setCursor(0, 1); // column 0, row 1 (bottom row) lcd.print("LCD is ready."); } void loop() { // Nothing to loop yet -- the LCD holds its last text. }
  4. Upload or run the sketch.
    Wokwi: click the green Play button at the top of the simulator. The LCD component in the diagram will turn on and show your text immediately. No board selection or COM port needed.
    Hardware: in Arduino IDE, select Tools → Board → Arduino AVR Boards → Arduino Mega or Mega 2560. Select Tools → Port → the COM port your Mega appeared on when you plugged it in. Click the Upload arrow (right-pointing). The IDE compiles and flashes in about 10 seconds.
LCD is blank (no characters, backlight off)?
  • Check VSS=GND and VDD=5V. A reversed power connection will keep the LCD dark.
  • Check the backlight: pin A (15) needs 5V through a 220-ohm resistor; pin K (16) needs GND. Without this the panel is dark even if everything else is correct.
  • In Wokwi: make sure you added the LCD as a LCD1602 component with the pins attribute set to "full" (not "i2c"). The I2C variant uses a different library and different wiring.
LCD shows a solid row of filled blocks on row 1, row 2 is blank?
  • This is a contrast problem — and a hardware-only one: rotate the contrast potentiometer slowly from end to end while powered on; there is a sweet spot near mid-range. (In Wokwi this does not occur — V0 contrast is not simulated, so the LCD text always renders clearly regardless of the pot.)
  • If V0 is wired directly to GND (no pot), maximum contrast shows filled blocks. Wire V0 to the pot wiper instead.
Garbled characters or random symbols?
  • The RS, E, D4-D7 pin order in the LiquidCrystal() constructor must match your physical wiring exactly. Double-check each pin number against the wiring table. A single transposition scrambles the character mapping.
Checkpoint — what you should see
Wokwi: after clicking Play, the LCD1602 component shows "Hello, Forge!" on row 0 and "LCD is ready." on row 1. The characters are crisp and correctly formed.

Hardware: the physical LCD backlight glows, row 0 shows "Hello, Forge!", row 1 shows "LCD is ready." Characters are not garbled. If you turn the contrast potentiometer, text visibility changes and disappears at the extremes.

Read the DHT22 Sensor and Display Temp/Humidity
Add the DHT22 temperature and humidity sensor. Install the Adafruit DHT sensor library, wire the sensor to a digital pin, read both values, and format them onto two LCD rows so the display shows a live climate readout.
  1. Install the required libraries.
    Wokwi: library installation is automatic. Wokwi resolves #include "DHT.h" from the Adafruit DHT sensor library without any manual step. Add a DHT22 component (wokwi-dht22) from the diagram + button and wire it as shown below.
    Hardware / Arduino IDE: open Sketch → Include Library → Manage Libraries. Search for DHT sensor library (by Adafruit). Click Install. When prompted to install dependencies, click Install all — this installs the required Adafruit Unified Sensor library. Both must be present or the sketch will not compile.
  2. Wire the DHT22 sensor.
    DHT22 Pin Arduino Mega Pin Notes ----------- ----------------- --------------------- Pin 1 (VCC) 5V Sensor power Pin 2 (DATA) Pin 7 Signal -- add a 10K pull-up resistor between DATA and 5V Pin 3 not connected (some modules have 3 pins, some have 4 -- pin 3 is NC) Pin 4 (GND) GND Sensor ground
    The 10K pull-up resistor between the DATA pin and 5V is required on bare DHT22 modules. Pre-wired sensor breakout boards (with three pins labeled VCC/DATA/GND) usually include this resistor on the board already.
    Wokwi: the wokwi-dht22 component has VCC, GND, and SDA pins. Connect VCC to 5V, GND to GND, SDA to Pin 7. No external pull-up resistor is needed in the simulator. Once wired, click the DHT22 component during simulation to set a custom temperature and humidity value.
  3. Paste and upload the Phase 2 sketch. This sketch replaces the Phase 1 sketch entirely.
    // Phase 2: DHT22 temperature and humidity on LCD // Requires: Adafruit DHT sensor library + Adafruit Unified Sensor #include <LiquidCrystal.h> #include "DHT.h" // LCD: same wiring as Phase 1 LiquidCrystal lcd(12, 11, 5, 4, 3, 2); // DHT22 sensor on digital pin 7 #define DHT_PIN 7 #define DHT_TYPE DHT22 DHT dht(DHT_PIN, DHT_TYPE); void setup() { lcd.begin(16, 2); dht.begin(); lcd.print("Sensor init..."); delay(2000); // DHT22 needs ~1-2 s after power-on before first read lcd.clear(); } void loop() { float humidity = dht.readHumidity(); float tempC = dht.readTemperature(); // Celsius (default) // isnan() checks for a failed read -- DHT22 returns NaN on error if (isnan(humidity) || isnan(tempC)) { lcd.clear(); lcd.setCursor(0, 0); lcd.print("Sensor error"); lcd.setCursor(0, 1); lcd.print("Check wiring"); delay(2000); return; } // Row 0: temperature with one decimal place lcd.setCursor(0, 0); lcd.print("Temp: "); lcd.print(tempC, 1); // "24.3" lcd.print("C "); // trailing spaces clear leftover chars // Row 1: humidity lcd.setCursor(0, 1); lcd.print("Hum: "); lcd.print(humidity, 1); lcd.print("% "); delay(2000); // DHT22 minimum read interval is 2 seconds }
LCD shows "Sensor error / Check wiring" on every cycle?
  • The most common cause is a missing 10K pull-up resistor on the DATA pin. Without it the signal floats and the DHT22 never delivers valid data. Add a 10K resistor between DATA (pin 7) and 5V.
  • The DHT22 needs 2 seconds from power-on before the first read is valid. The delay(2000) in setup() handles this; do not remove it or shorten it.
  • Confirm the DHT type constant: DHT22 for the AM2302 sensor. If you have a blue four-legged chip (DHT11 instead), change DHT_TYPE to DHT11. Using the wrong type constant produces NaN reads even with correct wiring.
  • In Wokwi: verify the component is wokwi-dht22 and its SDA pin connects to the same pin number referenced in the sketch (DHT_PIN 7). Mismatched pin numbers cause NaN exactly like wiring errors.
Checkpoint — what you should see
Wokwi: after clicking Play, row 0 shows something like Temp: 24.0C and row 1 shows Hum: 50.0%. Click the DHT22 component in the diagram and change the temperature slider to 30 degrees — the LCD updates to Temp: 30.0C within the next 2-second cycle.

Hardware: the LCD cycles through a 2-second update showing live temperature in Celsius and relative humidity in percent. Breathing on the DHT22 sensor raises the humidity reading noticeably.

Add the Photoresistor (LDR) and Show Light Level
Wire the photoresistor in a voltage divider with a 10K resistor. Read the analog voltage with analogRead(), map it to a 0-100% scale, and display a light level percentage plus a descriptive label (Dark / Dim / Bright / Sunny) on the second LCD row while temperature continues on row 0.
  1. Wire the photoresistor voltage divider. A photoresistor changes resistance with light: bright light lowers resistance, darkness raises it. The voltage divider converts this to a readable analog voltage.
    Component Arduino Mega Pin Notes -------------- ----------------- --------------------- LDR leg 1 5V One end to power LDR leg 2 A0 (analog pin 0) Junction point -- read here AND 10K resistor A0 to GND Divider pull-down (one end on A0, other on GND)
    So the circuit reads from top to bottom: 5V → LDR → junction (A0) → 10K resistor → GND. In bright light the LDR is low-resistance, junction voltage is high, analogRead returns a high number (toward 1023). In darkness the LDR is high-resistance, voltage drops, analogRead returns a low number (toward 0).
    Wokwi: add a Photoresistor Sensor (wokwi-photoresistor-sensor) from the + menu. Connect its VCC to 5V, GND to GND, and AO to Arduino Mega pin A0. The sensor module already includes the 10K divider resistor internally. Note: unlike the DHT22, Wokwi's photoresistor has no live drag-slider — to change the light level, click the photoresistor part and edit its lux attribute in the properties panel (e.g. 10 for dark, 800 for bright), then restart the simulation (the Play button) to apply it.
  2. Paste the Phase 3 sketch. Temperature is kept on row 0; light level takes row 1.
    // Phase 3: DHT22 + photoresistor on LCD // LDR connected in voltage divider to A0. #include <LiquidCrystal.h> #include "DHT.h" LiquidCrystal lcd(12, 11, 5, 4, 3, 2); #define DHT_PIN 7 #define DHT_TYPE DHT22 DHT dht(DHT_PIN, DHT_TYPE); #define LDR_PIN A0 // analog pin 0 on the Mega // Map a raw 0-1023 ADC value to a descriptive label. // Thresholds are approximate -- adjust to your environment. String lightLabel(int pct) { if (pct < 15) return "Dark "; if (pct < 40) return "Dim "; if (pct < 75) return "Bright"; return "Sunny "; } void setup() { lcd.begin(16, 2); dht.begin(); delay(2000); lcd.clear(); } void loop() { // --- Temperature (row 0) --- float tempC = dht.readTemperature(); lcd.setCursor(0, 0); if (isnan(tempC)) { lcd.print("Temp: ---C "); } else { lcd.print("Temp: "); lcd.print(tempC, 1); lcd.print("C "); } // --- Light level (row 1) --- int raw = analogRead(LDR_PIN); // 0 (dark) to 1023 (bright) int pct = map(raw, 0, 1023, 0, 100); // scale to 0-100% lcd.setCursor(0, 1); lcd.print("Lgt:"); if (pct < 10) lcd.print(" "); // keep alignment for single digits lcd.print(pct); lcd.print("% "); lcd.print(lightLabel(pct)); delay(500); // LDR can update faster than DHT22 -- 500 ms is comfortable }
analogRead always returns 0 or always returns 1023?
  • Value stuck at 0: the A0 pin is wired directly to GND somewhere, or the 10K resistor leg that should go to A0 is connected to GND instead. Trace the divider: 5V → LDR → A0 → 10K → GND.
  • Value stuck at 1023: A0 is wired directly to 5V, or the LDR and resistor roles are swapped. Check which component is on the top half (power side) and which is on the bottom half (ground side) of the divider.
  • Value does not change when you cover the LDR: confirm A0 is reading the junction between the LDR and the 10K resistor, not one of the endpoints.
  • analogRead must be called on an analog pin (A0-A15 on the Mega). Calling it on a plain digital pin number (e.g., pin 0) may compile but reads the wrong channel.
Light label flickers between two values rapidly?
  • Normal near a threshold boundary. Add a small deadband: instead of comparing to a single threshold, keep the last label and only change it when the value moves more than 3-5% past the boundary. For a simple fix, add delay(200) after the analogRead and average two reads: int raw = (analogRead(LDR_PIN) + analogRead(LDR_PIN)) / 2;
Checkpoint — what you should see
Wokwi: row 0 shows the temperature from the DHT22 component. Row 1 shows something like Lgt:72% Bright. Set the photoresistor's lux attribute to a low value (e.g. 5) and restart the simulation — row 1 now reads Lgt: 3% Dark . Set lux high (e.g. 900) and restart to see Bright or Sunny.

Hardware: covering the photoresistor with your thumb drops the percentage and changes the label toward Dark. Shining a phone flashlight on it pushes it toward Sunny. The temperature on row 0 continues updating every 2 seconds independently.

Add LED Threshold Indicators
Wire three LEDs — green, yellow, and red — and drive them based on sensor readings. Green means all readings are in normal range. Yellow lights when humidity is high or light is very low. Red lights when temperature exceeds the alert threshold. All three LEDs can be on simultaneously if multiple conditions are met.
  1. Wire the three LEDs. Each LED needs a current-limiting resistor (220 ohm) in series to prevent burning out.
    LED Color Arduino Mega Pin Resistor ----------- ----------------- -------- Green Pin 8 220 ohm in series, then LED anode (+) Yellow Pin 9 220 ohm in series, then LED anode (+) Red Pin 10 220 ohm in series, then LED anode (+) All cathodes GND Connect all LED cathodes (-) to GND
    Wiring pattern for each: Mega pin → 220-ohm resistor → LED anode (longer leg) → LED cathode (shorter leg) → GND.
    Wokwi: add three LED components from the + menu. Each LED has A (anode) and C (cathode) pins. Add three resistors (set value to 220 ohms each). Wire: Mega pin → resistor → LED A; LED C → GND. Default LED colors in Wokwi are red; change the color attribute to "green", "yellow", and "red" in the component properties.
  2. Paste the Phase 4 sketch. Thresholds are defined as constants at the top so you can adjust them without hunting through the code.
    // Phase 4: DHT22 + LDR on LCD with LED threshold indicators #include <LiquidCrystal.h> #include "DHT.h" LiquidCrystal lcd(12, 11, 5, 4, 3, 2); #define DHT_PIN 7 #define DHT_TYPE DHT22 DHT dht(DHT_PIN, DHT_TYPE); #define LDR_PIN A0 #define LED_GREEN 8 #define LED_YELLOW 9 #define LED_RED 10 // --- Threshold constants --- // Adjust these to match your environment / use case. const float TEMP_RED_THRESHOLD = 30.0; // degrees C -- red LED above this const float HUM_YELLOW_THRESHOLD = 70.0; // % -- yellow LED above this const int LDR_YELLOW_THRESHOLD = 10; // % -- yellow LED below this (very dark) String lightLabel(int pct) { if (pct < 15) return "Dark "; if (pct < 40) return "Dim "; if (pct < 75) return "Bright"; return "Sunny "; } void setup() { lcd.begin(16, 2); dht.begin(); pinMode(LED_GREEN, OUTPUT); pinMode(LED_YELLOW, OUTPUT); pinMode(LED_RED, OUTPUT); delay(2000); lcd.clear(); } void loop() { float humidity = dht.readHumidity(); float tempC = dht.readTemperature(); int raw = analogRead(LDR_PIN); int ldrPct = map(raw, 0, 1023, 0, 100); // --- Update LCD --- lcd.setCursor(0, 0); if (isnan(tempC)) { lcd.print("Temp: ---C "); } else { lcd.print("Temp: "); lcd.print(tempC, 1); lcd.print("C "); } lcd.setCursor(0, 1); lcd.print("Lgt:"); if (ldrPct < 10) lcd.print(" "); lcd.print(ldrPct); lcd.print("% "); lcd.print(lightLabel(ldrPct)); // --- Drive LEDs --- // Red: temperature too high bool redOn = (!isnan(tempC) && tempC >= TEMP_RED_THRESHOLD); // Yellow: humidity too high OR very dark bool yellowOn = (!isnan(humidity) && humidity >= HUM_YELLOW_THRESHOLD) || (ldrPct <= LDR_YELLOW_THRESHOLD); // Green: on whenever red is not on (system within normal temperature range) bool greenOn = !redOn; digitalWrite(LED_GREEN, greenOn ? HIGH : LOW); digitalWrite(LED_YELLOW, yellowOn ? HIGH : LOW); digitalWrite(LED_RED, redOn ? HIGH : LOW); delay(500); }
LED stays off even when the threshold is crossed?
  • Check that pinMode(LED_GREEN/YELLOW/RED, OUTPUT) is called in setup() before any digitalWrite. Pins default to INPUT mode and cannot source current to light an LED.
  • Confirm the physical LED is not inserted backwards. The anode (longer leg) must face the resistor/power side; cathode (shorter leg) must face GND. LEDs are one-directional: backward insertion means no light and no damage.
  • Verify the 220-ohm resistor is present. Without the resistor the LED may flicker briefly then burn out (on hardware) or show as always-on in Wokwi without correct resistance.
All three LEDs are always on?
  • The LED cathode may be wired to 5V instead of GND. The current flows in reverse, which can illuminate some LEDs from leakage. Swap the cathode wire to the GND rail.
  • In Wokwi, double-check that LED A and C pins are correctly identified in the component — A is anode, C is cathode.
Checkpoint — what you should see
Wokwi: at default temperature (around 24 C), the green LED is on and red is off. Click the DHT22 component and raise temperature above 30 C — red LED turns on, green turns off. Lower temperature back and green returns. Set the photoresistor's lux attribute to a low value (e.g. 5) and restart — the yellow LED turns on. Set lux back above the threshold and restart, and yellow turns off.

Hardware: at room temperature (below 30 C) the green LED glows. Hold your finger on the DHT22 (body heat) for 30 seconds until the reading crosses 30 C — red turns on. Cover the photoresistor completely — yellow turns on. Release both and the LEDs return to green-only.

Multi-Screen Cycling Dashboard
Combine everything into a polished dashboard that rotates between two screens on a 3-second timer: Screen 1 shows temperature and humidity; Screen 2 shows light level and percentage. LEDs continue reacting to thresholds across all screens. This is the final deliverable: a self-contained, continuously updating sensor dashboard.
  1. Understand the screen-cycling design. The 16x2 display only has 32 character positions. With three sensor values to show, a rotating approach gives each sensor adequate room and clear labels. The rotation uses millis() (a non-blocking timer) rather than delay() so the LED logic runs continuously without pausing.
    Why millis() instead of delay(): delay(3000) would freeze the entire sketch for 3 seconds. During that freeze, LED threshold checks stop updating. millis() lets you check elapsed time without blocking — the loop keeps running and LEDs react instantly to sensor changes even while the display is mid-cycle.
  2. Paste the complete Phase 5 sketch (final dashboard, replaces all previous sketches):
    // Phase 5: Multi-screen cycling dashboard // Screen 1 (3 s): temperature + humidity // Screen 2 (3 s): light level percentage + label // LEDs: green = temp OK, yellow = high humidity or very dark, red = high temp #include <LiquidCrystal.h> #include "DHT.h" LiquidCrystal lcd(12, 11, 5, 4, 3, 2); #define DHT_PIN 7 #define DHT_TYPE DHT22 DHT dht(DHT_PIN, DHT_TYPE); #define LDR_PIN A0 #define LED_GREEN 8 #define LED_YELLOW 9 #define LED_RED 10 // --- Thresholds --- const float TEMP_RED_THRESHOLD = 30.0; // C const float HUM_YELLOW_THRESHOLD = 70.0; // % const int LDR_YELLOW_THRESHOLD = 10; // % // --- Timing --- const unsigned long SCREEN_INTERVAL = 3000; // ms per screen const unsigned long SENSOR_INTERVAL = 2000; // ms between DHT reads (min 2 s) unsigned long lastScreenSwitch = 0; unsigned long lastSensorRead = 0; int currentScreen = 0; // 0 = temp/hum, 1 = light // --- Cached sensor values (updated on SENSOR_INTERVAL) --- float cachedTemp = 0.0; float cachedHum = 0.0; int cachedLdr = 0; // percentage 0-100 String lightLabel(int pct) { if (pct < 15) return "Dark "; if (pct < 40) return "Dim "; if (pct < 75) return "Bright"; return "Sunny "; } void drawScreen0() { // Screen 0: temperature (row 0) + humidity (row 1) lcd.setCursor(0, 0); lcd.print("Temp: "); if (isnan(cachedTemp)) { lcd.print("---C "); } else { lcd.print(cachedTemp, 1); lcd.print("C "); } lcd.setCursor(0, 1); lcd.print("Hum: "); if (isnan(cachedHum)) { lcd.print("---% "); } else { lcd.print(cachedHum, 1); lcd.print("% "); } } void drawScreen1() { // Screen 1: light level (row 0) + label (row 1) lcd.setCursor(0, 0); lcd.print("Light: "); if (cachedLdr < 10) lcd.print(" "); lcd.print(cachedLdr); lcd.print("% "); lcd.setCursor(0, 1); lcd.print("Level: "); lcd.print(lightLabel(cachedLdr)); } void updateLEDs() { bool redOn = (!isnan(cachedTemp) && cachedTemp >= TEMP_RED_THRESHOLD); bool yellowOn = (!isnan(cachedHum) && cachedHum >= HUM_YELLOW_THRESHOLD) || (cachedLdr <= LDR_YELLOW_THRESHOLD); bool greenOn = !redOn; digitalWrite(LED_GREEN, greenOn ? HIGH : LOW); digitalWrite(LED_YELLOW, yellowOn ? HIGH : LOW); digitalWrite(LED_RED, redOn ? HIGH : LOW); } void setup() { lcd.begin(16, 2); dht.begin(); pinMode(LED_GREEN, OUTPUT); pinMode(LED_YELLOW, OUTPUT); pinMode(LED_RED, OUTPUT); lcd.print("Dashboard init"); delay(2000); lcd.clear(); // Seed the cache with the first read cachedHum = dht.readHumidity(); cachedTemp = dht.readTemperature(); cachedLdr = map(analogRead(LDR_PIN), 0, 1023, 0, 100); } void loop() { unsigned long now = millis(); // --- Refresh sensor cache on interval --- if (now - lastSensorRead >= SENSOR_INTERVAL) { lastSensorRead = now; float h = dht.readHumidity(); float t = dht.readTemperature(); if (!isnan(h)) cachedHum = h; if (!isnan(t)) cachedTemp = t; cachedLdr = map(analogRead(LDR_PIN), 0, 1023, 0, 100); } // --- Switch screen on interval --- if (now - lastScreenSwitch >= SCREEN_INTERVAL) { lastScreenSwitch = now; currentScreen = (currentScreen + 1) % 2; lcd.clear(); } // --- Draw the active screen --- if (currentScreen == 0) { drawScreen0(); } else { drawScreen1(); } // --- Update LEDs every loop iteration (no blocking) --- updateLEDs(); delay(100); // small yield to avoid hammering the LCD bus }
  3. Upload and observe the full dashboard.
    Wokwi: click Play. The LCD shows Screen 0 (Temp + Hum) for 3 seconds, then switches to Screen 1 (Light level + label) for 3 seconds, then back. Interact with both sensors during the cycle: click the DHT22 to raise temperature above 30 C and watch the red LED turn on while the cycling continues uninterrupted. (To exercise the light path, set the photoresistor's lux attribute low and restart — the yellow LED turns on regardless of which screen is active.)
    Calibration tip: the lightLabel() thresholds (15%, 40%, 75%) are approximations. Indoors near a window might read 50-70% in Wokwi's default lux setting. Adjust the constants at the top of the sketch to match your actual environment after observing a few readings.
LCD flickers or shows garbage between screen transitions?
  • lcd.clear() takes about 1.5-2 ms and sends a home command. Calling it every loop iteration causes constant flicker. In this sketch it is called only once per screen switch (inside the millis timer block). If you see flicker, confirm you did not accidentally move lcd.clear() into the draw functions.
  • Trailing spaces after each printed value (e.g., lcd.print("C ");) clear leftover characters from longer previous values without needing a full lcd.clear(). If values seem to overlap, add more trailing spaces to the shorter strings.
LEDs stop responding when a screen is active?
  • This happens if you accidentally introduced a delay(3000) somewhere in the loop. The millis() approach in this sketch never blocks. Search your sketch for any delay() calls longer than ~200 ms and remove them.
Checkpoint — what you should see
Wokwi: the LCD alternates every 3 seconds between Screen 0 (Temp: 24.0C / Hum: 50.0%) and Screen 1 (Light: 72% / Level: Bright ). The green LED glows continuously at default sensor values. Raising DHT22 temperature above 30 C turns on red and turns off green — the LED state holds through both screens without resetting on each switch. Setting the photoresistor's lux attribute to a low value (e.g. 5) and restarting turns on yellow while all other cycling behavior continues without interruption.

Hardware: the dashboard cycles autonomously. Green LED is on at room temperature. Triggering both a high-temp and a dark-room condition simultaneously causes red and yellow to both glow at once. The display cycles every 3 seconds regardless of LED state. You have a working embedded sensor dashboard.
