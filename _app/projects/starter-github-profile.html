Subject

Create Your GitHub Profile README

Recruit 30 min 100 XP
Mission Brief

Your GitHub profile is one of the first things a recruiter, hiring manager, or future collaborator will look at. By default it shows almost nothing. This project fixes that: you will build a professional profile README that appears at the top of your GitHub page and tells your story in plain text.

GitHub has a hidden mechanic: if you create a repository whose name is exactly your GitHub username, and that repository is public and contains a file named README.md, GitHub automatically displays the contents of that file on your profile page. No settings to toggle, no dashboard to configure. Just those three conditions.

You will create that repository entirely in the browser, write Markdown to build a bio section, learn how to add technology badges and a GitHub stats card, and end with a live profile page visible to anyone in the world. No software to install, no command line required.

Agent Requirements
  • A free GitHub account — create one at github.com if you do not have one yet. The username you pick becomes part of your public URL, so choose something professional.
  • A web browser (Chrome, Firefox, Edge, or Safari). Everything in this project happens in the browser — no software to install, no terminal to open.
  • Two or three sentences about yourself ready to type. What are you studying? What interests you? What have you built or want to build? That is all you need to start.

1
Create the Special Repository
The whole mechanic rests on one thing: a repository whose name is exactly your GitHub username. GitHub intercepts that exact name and uses it as your profile page. Every step below is done in the browser.
  1. Sign in to GitHub at github.com. After signing in you land on your GitHub dashboard. Your avatar appears in the top-right corner of the header, with a + icon just to its left.
  2. Start a new repository. Click the + icon just to the left of your avatar in the top-right header. A small dropdown appears. Click New repository.
  3. In the Owner dropdown above the name field, confirm it shows your personal username, not an organization. If it shows an org name, click the dropdown and select your personal account. Creating this repository under an org will break the profile-README mechanic entirely.
  4. Set the repository name to your exact username. In the Repository name field, type your GitHub username. As you type the last character, GitHub shows a confirmation message just below the repository-name field indicating this is a special repository that will appear on your profile — that message (whatever its exact wording) is your confirmation you typed the name right. If it does not appear, you have a mismatch — check the fix box below.
    Copy your username exactly. The safest approach is to open a second tab, go to github.com, click your avatar, and copy your username from under your display name. This avoids any accidental character difference such as a typo or a trailing space.
  5. Set visibility to Public. Under Visibility, confirm the Public radio button is selected. A private repository will never display on your profile, even if the name matches.
  6. Check "Add a README file". Under Initialize this repository with:, tick the checkbox labelled Add a README file. This creates the README.md file automatically so you do not have to.
  7. Click "Create repository". GitHub creates the repository and takes you directly to its main page. You will see a file called README.md already listed in the file table.
The confirmation message did not appear when I typed my name.
  • The name in the field does not exactly match your username. Open a second tab, go to github.com, and click your avatar — your username is shown under your display name. Copy it exactly to avoid any accidental character difference such as a typo or trailing space.
  • You may have a space or trailing character in the field. Click into the field and use Home/End keys to check for hidden characters.
  • The repository may already exist. If you created it before, GitHub will say the name is taken. Go to github.com/yourusername/yourusername — if it exists, skip to Phase 2.
Checkpoint — what you should see
You are on the repository page at github.com/yourusername/yourusername. A file called README.md is listed. Open the editor on that file — you will see the auto-generated content: a heading with your username (# yourusername) and below it a block of commented-out suggestions wrapped in <!-- --> tags. Those commented lines are invisible when the README is rendered, so your profile page currently shows only your username as a plain heading. You will replace all of this in the next phase.
✓
2
Write Your README in the Browser
You will edit README.md entirely in the GitHub web editor. No software needed. This phase teaches you enough Markdown to write a complete bio, and gives you a full starter file to paste and personalise.
What is Markdown? Markdown is a plain-text shorthand for formatting. You write # Heading instead of clicking a "Bold heading" button, and GitHub converts it to styled HTML when it renders your profile. You are not writing HTML — just plain text with a few symbols. Every symbol is explained below as you use it.
  1. Open the editor. On your repository page at github.com/yourusername/yourusername, click the filename README.md in the file table to open the file view. Then click the pencil icon near the top-right of the file content area (tooltip: "Edit this file"). The browser-based editor opens. You will see the auto-generated content GitHub placed there.
  2. Select all and delete the existing content. Click anywhere in the editor, press Ctrl+A (Mac: Cmd+A) to select everything, then press Delete or Backspace. The editor is now blank.
  3. Paste the starter README below into the empty editor. Then replace every placeholder (shown in CAPITALS) with your own words — keep all the symbols (#, **, -, [, etc.) exactly as written:
    # Hi, I'm YOUR NAME YOUR ONE-LINE DESCRIPTION (e.g. "Cybersecurity student at Valencia College | Aspiring SOC analyst") ## About Me - I am studying WHAT YOU ARE STUDYING - I am interested in TOPIC 1 and TOPIC 2 - I am currently learning SKILL OR TOOL - Outside of tech I enjoy HOBBY ## Connect [LinkedIn](https://www.linkedin.com/in/YOURPROFILE) [Email](mailto:YOUREMAIL@example.com)
    Markdown symbols used above and what each one does:
    # at the start of a line = biggest heading (your name). ## = a smaller section heading.
    - at the start of a line = one bullet in a list. Each - is a separate list item.
    [text](url) = a clickable link. The text in square brackets is what the reader sees; the URL in parentheses is where it goes.
    A blank line between two paragraphs = a paragraph break. A single line break with no blank line between them renders as a space in the same paragraph.
  4. Preview before saving. Click the Preview tab above the editor (next to "Edit"). GitHub shows you exactly how the README will render on your profile — headings styled, bullets as a proper list, links as clickable text. Switch back to Edit to make changes.
  5. Commit your changes. Click the green Commit changes… button (top right of the editor). A dialog appears. Leave the commit message as-is or type something like Add profile README. Make sure Commit directly to the main branch is selected. Click Commit changes.
The Commit changes button is grey or unavailable.
  • The editor may still show the original content unchanged. Make sure you pasted new content and the editor text is different from when you opened it.
  • You may not be signed in. Check your avatar in the top-right corner.
My README shows on the repository page but not on my profile page.
  • The repository must be Public. Go to the repository → Settings (tab at the top) → scroll down to the Danger Zone → Change repository visibility → set to Public.
  • The file must be named exactly README.md (capital R, capital E, capital A, capital D, capital M, lowercase d). Open the repository and confirm the filename in the file list.
  • The repository name must exactly match your username. Check both at github.com/settings/profile (your username is shown there) and on the repository's URL bar.
  • GitHub can take up to a minute to update your profile page after a commit. Hard-refresh your profile tab with Ctrl+Shift+R (Mac: Cmd+Shift+R).
Checkpoint — what you should see
Visit github.com/yourusername. Your name appears as a large heading above your pinned repositories, followed by your description, your "About Me" bullet list, and your Connect links. If you see raw Markdown symbols instead of formatted text, the file is being displayed as plain text rather than rendered — confirm the filename ends in .md (not .txt or no extension).

3
Add a Markdown Table and a Link
Markdown supports tables and image syntax. In this phase you will add a two-column table that lists what you are currently learning, and a clickable image badge using shields.io — the service that generates those coloured label pills you see on almost every GitHub project.
Markdown image syntax: ![alt text](image URL). The exclamation mark at the front is what makes it an image instead of a plain link. The alt text goes in square brackets; the direct image URL goes in parentheses. If the URL is wrong or not a direct image link, you will see the alt text or a broken icon.
  1. Open the editor again. Go to github.com/yourusername/yourusername, click the filename README.md to open the file view, then click the pencil icon near the top-right of the file content area (tooltip: "Edit this file").
  2. Add a table. Click at the end of your current content, press Enter twice to leave a blank line, then paste this table block. Replace the placeholder rows with your own:
    ## Currently Learning | Topic | Resource | |---|---| | Linux command line | OverTheWire: Bandit | | Python scripting | Python.org docs | | Networking fundamentals | Professor Messer CompTIA N+ |
    How the table syntax works: Each row is one line. Columns are separated by |. The second row (|---|---|) is the separator that tells Markdown "the first row is the header." You can add or remove rows by adding or removing | text | text | lines. Spacing inside the cells does not matter — Markdown ignores extra spaces.
  3. Add a technology badge. Shields.io generates badge images from a URL alone — no account needed. Paste this section after your table (leave a blank line first):
    ## Tools ![Python](https://img.shields.io/badge/Python-3776AB?style=flat&logo=python&logoColor=white) ![Linux](https://img.shields.io/badge/Linux-FCC624?style=flat&logo=linux&logoColor=black) ![Git](https://img.shields.io/badge/Git-F05032?style=flat&logo=git&logoColor=white)
    How to read the badge URL: https://img.shields.io/badge/LABEL-COLOR?style=flat&logo=LOGONAME&logoColor=white. Change LABEL to any tool name, COLOR to a hex code, and LOGONAME to the Simple Icons slug for that tool (look up slugs at simpleicons.org — search your tool, copy the name shown). Add as many badges as you like, one per line or separated by a single space to flow them inline.
  4. Preview, then commit using the same steps as Phase 2 — Preview tab to verify the table and badges render, then Commit changes… → Commit directly to the main branch → Commit changes.
Badge shows as a broken image or alt text on my profile.
  • The most common cause: you copied the URL from this page and it contains HTML-escaped ampersands (&amp; instead of &). In your README.md, the URL must use real & characters, not &amp;. The & you paste into the Markdown editor is a literal ampersand.
  • The URL must be a direct image link ending in a file-like path (shields.io URLs qualify). A URL to a web page (like a GitHub profile page) will not render as an image.
  • Shields.io can occasionally be slow. Wait a few seconds and hard-refresh the profile page.
Checkpoint — what you should see
Your profile page now shows a two-column table with your learning topics and three coloured badge pills under a "Tools" heading. The badges are coloured images, not broken icons or raw alt text. Click the Preview tab in the editor before committing if you want to confirm rendering without making your profile live first.
✓
4
Your Complete README — Full Snapshot
Before adding the stats card in Phase 5, this phase gives you the full README as it stands — bio, table, badges, and a projects section with links. Use it as a reference: your finished file should look like this after you personalise all the placeholders.
  1. Add a Projects section to link to your repositories. Go to your repository page, click README.md to open the file view, click the pencil icon near the top-right of the file content area, go to the end of your content, add a blank line, and paste:
    ## Projects - [My First Web Page](https://github.com/YOURUSERNAME/my-first-webpage) - A personal page built with HTML and CSS - [PROJECTNAME](https://github.com/YOURUSERNAME/REPONAME) - One sentence describing it
    If you do not have any repositories yet, write a placeholder like "Coming soon — check back after Week 3" and replace it later. An honest placeholder beats an empty section.
  2. Your complete README now looks like this — paste this into a blank editor as a clean restart if your file has gotten messy, then fill in your own words everywhere you see CAPITALS:
    # Hi, I'm YOUR NAME YOUR ONE-LINE DESCRIPTION ## About Me - I am studying WHAT YOU ARE STUDYING - I am interested in TOPIC 1 and TOPIC 2 - I am currently learning SKILL OR TOOL - Outside of tech I enjoy HOBBY ## Connect [LinkedIn](https://www.linkedin.com/in/YOURPROFILE) [Email](mailto:YOUREMAIL@example.com) ## Currently Learning | Topic | Resource | |---|---| | Linux command line | OverTheWire: Bandit | | Python scripting | Python.org docs | | Networking fundamentals | Professor Messer CompTIA N+ | ## Tools ![Python](https://img.shields.io/badge/Python-3776AB?style=flat&logo=python&logoColor=white) ![Linux](https://img.shields.io/badge/Linux-FCC624?style=flat&logo=linux&logoColor=black) ![Git](https://img.shields.io/badge/Git-F05032?style=flat&logo=git&logoColor=white) ## Projects - [My First Web Page](https://github.com/YOURUSERNAME/my-first-webpage) - A personal page built with HTML and CSS
  3. Preview the full file using the Preview tab in the editor. Every section should render: headings as large text, bullets as a list, the table as a grid, badges as coloured images, and links as underlined clickable text.
  4. Commit when satisfied.
My commit went to a branch, not main — the profile still shows the old version.

A branch is a separate draft copy of your files, and a pull request asks to move that draft into the live version. If you accidentally chose "Create a new branch," your changes are sitting in a draft and are not yet live on your profile.

  • In the commit dialog, make sure Commit directly to the main branch is selected, not "Create a new branch." GitHub defaults to main, but if you accidentally selected the other option, your change is in a pull request and not live yet.
  • If you committed to a branch by mistake: go to the repository, click Pull requests, find your open PR, and click Merge pull request → Confirm merge. Your profile will update within a minute.
Checkpoint — what you should see
Visit github.com/yourusername. Your profile shows all five sections: your name and description at the top, About Me bullets, a Connect row, a Currently Learning table, coloured tool badges, and a Projects list with working links. This is a complete, professional profile README. Phase 5 adds one more element: a stats card that updates itself automatically as you commit more work.
✓
5
Add a GitHub Stats Card
GitHub-readme-stats is an open-source service that reads your public GitHub activity and returns a badge-style image showing your commit count, total stars, and top languages. You embed it with a single Markdown image line — it updates automatically every time you push code.
How it works: The URL https://github-readme-stats.vercel.app/api?username=YOURUSERNAME returns a real .svg image file with your live stats baked in. Markdown's image syntax (![alt](url)) fetches it just like any other image. Because the URL is a live API endpoint, the image changes every time GitHub fetches it — no manual updates needed.
  1. Open the editor. Go to your repository page, click README.md to open the file view, then click the pencil icon near the top-right of the file content area (tooltip: "Edit this file"). Scroll to the very end of the file.
  2. Add a blank line after your last section, then paste this line. Replace YOURUSERNAME with your actual GitHub username — no brackets, no quotes, just the username:
    ## GitHub Stats ![GitHub Stats](https://github-readme-stats.vercel.app/api?username=YOURUSERNAME&show_icons=true&theme=dark&hide_border=true)
    Parameters explained: username= tells the service whose stats to show. show_icons=true adds small icons next to each stat. theme=dark sets a dark background that matches most GitHub profiles. hide_border=true removes the card's outer border for a cleaner look. You can remove any parameter you do not want.
  3. Preview the result using the Preview tab. The stats card should appear as a dark image showing your commit count, pull requests, issues, and a star count. If it shows a card that says "No contributions yet" — that is correct for a brand-new account; the numbers will grow as you commit more.
  4. Commit directly to main using the same process as earlier phases.
  5. Visit your profile at github.com/yourusername and scroll down. The stats card sits below your Projects list and updates automatically from this point on.
The stats card shows a blank or error image.
  • The most common cause: your username in the URL has a typo, or you left the placeholder YOURUSERNAME literally. Open the file in the editor and check the URL character by character.
  • Rate-limiting: If the card works in the Preview tab but shows an error image on your live profile, that is almost always rate-limiting on the public Vercel instance — especially during class when many students hit it at the same time. This is NOT your mistake. Wait a few minutes and hard-refresh (Ctrl+Shift+R / Cmd+Shift+R) your profile page. If the error image persists after about 5 minutes, then check for a typo in your username in the URL.
  • Your GitHub account must be public and have at least one public repository for the card to show real numbers. The special repository you just created counts.
I want a "Top Languages" card too. Add this on its own line below the stats card line (same section, just paste it directly after):
![Top Languages](https://github-readme-stats.vercel.app/api/top-langs?username=YOURUSERNAME&layout=compact&theme=dark&hide_border=true)
Replace YOURUSERNAME with your username. layout=compact makes it narrower so it fits beside the stats card. This is optional — your profile is complete without it.
Checkpoint — final verification
Open github.com/yourusername in a new incognito/private window (this ensures you are seeing what a visitor sees, not your own cached view). Your profile should display, from top to bottom: your name as a heading, your one-line description, an About Me bullet list, a Connect row, a Currently Learning table, coloured tool badges, a Projects list with clickable links, and a dark-themed GitHub Stats card showing real numbers. That is a complete, professional GitHub profile README built entirely in the browser with no software installed.
