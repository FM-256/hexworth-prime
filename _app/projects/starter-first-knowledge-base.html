Subject

My First Knowledge Base

Adaptive · L1–5 30 min – 2 hr 250 – 1500 XP
Mission Brief

A knowledge base is the grounded memory an AI answers from. Without one, a model guesses from training data and sometimes confidently makes things up. With one, it does retrieve then generate: look up the relevant passage in your sources first, then answer from it, with a citation. This is the data layer of the AI stack — the natural sibling of My First Database.

You will build one real knowledge base and grow it across five levels: a Help-Desk Knowledge Base in Microsoft Copilot Studio — the same help-desk world as My First Agent and My First Workflow. Level 1 grounds an assistant in a single document. Each level adds one capability to the same base: more sources organized with clear titles, then retrieval quality by shaping your documents for clean chunking, then citations and anti-hallucination guardrails, and finally freshness so it never serves stale answers.

The throughline is trust. A base that cites its sources, says “I don’t know” when it should, and stays current is one you can safely put in front of real users. Every level is executable on a free Copilot Studio trial in the test panel — no publish step required.

Agent Requirements
  • A Microsoft account with access to copilotstudio.microsoft.com — a free Copilot Studio trial lets you create agents and test them in the test panel, which is all five levels require; publishing needs a licensed environment
  • A web browser — the base is built in the maker portal at copilotstudio.microsoft.com, no installs or code
  • The three inline sample documents below (FAQ, IT Use Policy, How-To Guide) — they are copy-ready on this page; no download or external file is needed
  • An existing agent in Copilot Studio to attach knowledge to — if you completed My First Agent, use the Campus Help Desk Assistant; otherwise create a new agent with a one-line description like A campus IT help-desk assistant
  • Dataverse search must be enabled in your environment for file uploads to work; on a personal trial tenant it is usually on by default (your admin controls it for organization tenants)
  • No prior AI, database, or programming experience required to start

Level 1: Ingest One Source
Beginner+250 XP
Upload one document to Copilot Studio and watch the agent answer from it instead of guessing. This is retrieval-augmented generation (RAG) at its simplest: the agent looks up the answer in your source before it replies. You build everything right in the test panel — no publish step needed. Start with your Campus Help Desk Assistant (or any agent you have open):
  1. Open your agent. Go to copilotstudio.microsoft.com, sign in, and open the Campus Help Desk Assistant from the Home page. If you do not have one yet, enter A campus IT help-desk assistant that answers questions about passwords, Wi-Fi, accounts, and lab access in the describe box on the Home page and let Copilot Studio create it, then open it.
  2. Go to the Knowledge section. On the agent’s Overview page, scroll to the Knowledge section. You will see an Add knowledge button and, if this is a fresh agent, a Web Search toggle. Leave Web Search alone for now.
  3. Create the FAQ file. Open a plain-text editor on your computer (Notepad on Windows, TextEdit on Mac — make sure TextEdit is in plain-text mode: Format → Make Plain Text). Copy every line from the block below and paste it in. Save the file as faq.txt.
    faq.txt — copy this entire block

    Sample content for this exercise. The URLs in all three documents (passwords.campus.edu, itportal.campus.edu, vpn.campus.edu, aka.ms/mfasetup) are placeholders — do not try to visit them. Note: aka.ms/mfasetup is a real Microsoft URL for organizational accounts and will not apply to your student tenant.

    Campus IT Help Desk — Frequently Asked Questions

    Q: How do I reset my campus password?
    Go to passwords.campus.edu, choose “Reset Password,” and follow the prompts. Changes apply within about 5 minutes.

    Q: My account is locked. What do I do?
    After 5 failed sign-ins the account locks for 15 minutes. Wait 15 minutes, then reset at passwords.campus.edu. If it is still locked after a reset, contact the IT desk.

    Q: How do I connect to campus Wi-Fi?
    Select the “CampusSecure” network and sign in with your student email and password. “CampusGuest” is for visitors only and does not allow access to campus systems.

    Q: How do I get into the computer labs?
    The Library lab and Tech Building lab open with your student ID card, Monday through Friday 7 am to 11 pm. Weekend hours vary; check the campus portal.

    Q: My email will not sync on my phone.
    Remove the account from your phone and re-add it using your full student email address and current password. If it still fails after a password reset, contact the IT desk.

    Q: How do I request software for a lab computer?
    Submit a software request through the IT portal at itportal.campus.edu. Only IT-approved software may be installed on lab computers.

  4. Upload the file as a knowledge source. In the Knowledge section select Add knowledge. In the Add knowledge dialog, choose Files. Either drag faq.txt into the upload area or select Browse and pick it. Once it appears in the list, give it the name Help Desk FAQ and a description like Frequently asked questions about campus IT: passwords, Wi-Fi, account lockouts, lab access, email, and software requests. Then select Add to agent. The file is now ingested and indexed.
    If you see an error about Dataverse search: file uploads require Dataverse search to be enabled in your Power Platform environment. On a personal trial tenant it is usually on. On an organization tenant, ask your administrator to enable it at Power Platform admin center → Environments → [your env] → Settings → Features → Search.
  5. Confirm generative orchestration is on. This setting controls whether knowledge grounding works. Select the Settings gear (top right of the agent editor) → Generative AI. Under Orchestration, make sure it is set to Generative. New agents default to Generative; if yours shows Classic, switch it and select Save.
  6. What to ignore. On the Overview page you may see suggestions for triggers, channels, and extra tools. None take effect unless you add them; leave them alone at this level.
  7. Test it. In the Test your agent panel on the right, ask: How do I reset my campus password? The agent should answer using the FAQ’s steps, not generic advice. Use the Start new test session icon (refresh symbol at the top of the panel) to reset the conversation between tries.
    Trial note: a free Copilot Studio trial lets you create agents and test them in this panel. The Publish button is visible but greyed out or blocked — that is expected. You do not need to publish to complete any level here.
Fix — agent invents an answer instead of using the FAQ: confirm the file appears in the Knowledge section of the Overview page with a green status indicator. If it shows “processing,” wait a moment and refresh. Also verify orchestration is set to Generative in Settings → Generative AI. Start a new test session after any change.
Skills: file knowledge sources, document ingestion, generative orchestration, basic RAG, test panel.
Win conditionIn the Test your agent panel the agent answers a question from the FAQ using the FAQ’s actual wording (not generic advice), and when you ask something the FAQ does not cover (for example, “what is the campus mascot?”) it says it does not have that information rather than inventing an answer.
Checkpoint — how to verify
Ask How do I connect to campus Wi-Fi? — the answer should mention CampusSecure and your student email, matching the FAQ. Then ask What time does the bookstore close? (not in the FAQ) — it should say it does not have that information. If it answers the bookstore question with confident details, the grounding setting is not yet locked; proceed to Level 2 to enable that control.

Level 2: Organize Many Sources
Beginner++250 XP
Grow the base to three documents and lock it to answer only from them. The new controls are: (1) clear names and descriptions on every source so the agent routes questions to the right one, and (2) the Allow ungrounded responses and Web Search toggles that prevent invented answers. Continue with the same agent from Level 1:
  1. Add the IT Use Policy. Copy the block below into a plain-text file named policy.txt. Then in the Knowledge section select Add knowledge → Files, upload policy.txt, give it the name IT Use Policy and the description Rules for campus IT accounts and lab computers: acceptable use, password requirements, software installation, data storage, and incident reporting. Select Add to agent.
    policy.txt — copy this entire block

    Campus IT Use Policy (excerpt)

    Section 1 — Acceptable Use: Campus accounts and lab computers are for coursework and official campus activity only. Personal commercial use is prohibited.

    Section 2 — Password Requirements: Passwords must be at least 12 characters, changed at least every 180 days, and never shared with anyone, including IT staff.

    Section 3 — Software Installation: Only IT-approved software may be installed on lab computers. Unauthorized software will be removed.

    Section 4 — Data Storage: Do not store personal, sensitive, or confidential data on lab computers. Files saved locally are wiped nightly. Use campus OneDrive for persistent file storage.

    Section 5 — Incident Reporting: Report a lost ID card, suspected phishing email, or compromised account to the IT desk within 24 hours. Failure to report may result in disciplinary action.

  2. Add the How-To Guide. Copy the block below into a plain-text file named howto.txt. Upload it as How-To Guide with the description Step-by-step instructions for common campus IT tasks: setting up MFA, connecting to VPN, accessing campus OneDrive, and printing from lab computers. Select Add to agent.
    howto.txt — copy this entire block

    Campus IT How-To Guide

    How to set up multi-factor authentication (MFA):
    1. Sign in to aka.ms/mfasetup with your student account.
    2. Select “Add sign-in method” and choose “Authenticator app.”
    3. Install the Microsoft Authenticator app on your phone and scan the QR code shown.
    4. Approve the test notification. MFA is now active on your account.

    How to connect to the campus VPN:
    1. Download the GlobalProtect VPN client from itportal.campus.edu under “Downloads.”
    2. Install it and launch it. Enter the gateway address vpn.campus.edu.
    3. Sign in with your student email and password. Approve the MFA prompt.
    4. The VPN icon in your system tray turns green when connected.

    How to access campus OneDrive:
    Sign in to office.com with your student email. Select the OneDrive tile. Your campus OneDrive has 1 TB of storage and is the recommended location for all assignment files.

    How to print from a lab computer:
    1. Open your file and choose Print. Select the printer named “CampusPrint.”
    2. Confirm page count and select Print.
    3. Walk to any campus print station, tap your student ID card, and select “Release all.” Jobs expire after 24 hours.

  3. Lock the agent to your sources. Select Settings (gear, top right) → Generative AI. In the Knowledge section, find Allow ungrounded responses and turn it off. This means: if the agent cannot pull an answer from one of your uploaded documents, it blocks the response and falls back rather than inventing. (Note: this blocks answers where no source retrieval occurred at all. When the agent does retrieve from your docs but then adds some general phrasing while composing the reply, that is expected model behavior and is separate from the grounding toggle.) Also turn off the Use information from the web toggle (also in Knowledge — you can also reach it from the Web Search toggle on the Overview page). Select Save.
    What these toggles do: Allow ungrounded responses OFF = the agent blocks any answer it did not retrieve from a knowledge source or tool. Use information from the web OFF = no Bing search fallback; only your uploaded documents. Together they mean: answer from my files or say nothing.
  4. Sharpen source names and descriptions. In the Knowledge section, select the three-dot menu next to each source to edit it. Make sure each name and description clearly states what topic that document covers. The agent uses these descriptions to decide which source to search when more than one exists — vague descriptions cause wrong-source retrieval.
  5. Test source routing. In the Test your agent panel ask: How often must I change my password? The agent should answer every 180 days — a fact only in the policy, not the FAQ. Then ask: How do I connect to the campus VPN? — only in the how-to. Then ask: What time does the library open on Saturday? (in none of the docs) — it should say it does not have that information.
Fix — agent pulls the wrong source or blends answers: the most common cause is a vague or overlapping source description. Edit the descriptions so each one names a distinct topic set. If two documents genuinely cover the same topic, decide which is authoritative and remove the overlap from the other. Re-test with a new session after each edit.
Fix — agent still invents answers with Allow ungrounded responses OFF: confirm that orchestration is set to Generative in Settings → Generative AI — the toggle only works in Generative mode.
Skills: multi-document knowledge bases, source names and descriptions, Allow ungrounded responses, Web Search toggle, source routing.
Win conditionWith Allow ungrounded responses off, a policy question returns the policy answer (180-day password change), a how-to question returns the how-to steps, and an out-of-scope question returns an honest “I don’t have that information” — each from the correct source.
Checkpoint — how to verify
Ask How often must I change my password? — answer should be 180 days (only in policy.txt). Ask How do I set up MFA? — answer should list the four Authenticator steps (only in howto.txt). Ask What time does the bookstore close? — agent should decline. If sources cross-contaminate (e.g. the password-change answer comes mixed with FAQ content), edit the source descriptions to make their topic areas more distinct, then re-test with a new session.

Level 3: Retrieval Quality
Intermediate+300 XP
Learn why some answers are vague or wrong, and fix them by shaping your source documents. Copilot Studio automatically splits your documents into chunks (passages) and stores them as embeddings (mathematical vectors); when a question arrives, it retrieves the chunks closest to the question. You cannot adjust chunk size directly — but you control the document structure, and structure determines where the chunks land. A question gets a vague answer when the relevant information is split across two chunks, or buried inside a long unbroken paragraph. The fix is always in the document. Continue with your agent:
  1. Run the spanning question. In the Test your agent panel, ask: How do I print from a lab computer and how long until my print job expires? This question spans two pieces of information in howto.txt — the print steps and the 24-hour expiry. Note what the agent returns. With a short document like this sample you will often get both facts in a single answer, because the entire print section fits in one retrieval chunk. That is the correct result, not a failure — short documents chunk favorably. The lesson here is about the technique you reach for when a real document is long enough that related facts end up in different chunks and retrieval misses one of them.
  2. Understand the chunking principle. Copilot Studio splits each uploaded document into overlapping passages (chunks) and stores each as a vector embedding. When a question arrives, it retrieves the chunks whose embeddings are closest to the question. On a longer document the print steps and the expiry note might land in separate chunks — and only the higher-scoring chunk gets returned, leaving the other fact out of the answer. The fix is always in the document structure, not in any setting (chunk size is not user-adjustable). The exercise below teaches exactly that fix.
  3. Apply the structure fix anyway — this is the skill. Open howto.txt in your text editor. Find the “How to print from a lab computer” section. Make sure the 24-hour expiry note is a numbered sub-step immediately after the print steps — not separated by a blank line or a heading. A clear heading at the start of the section and no gaps between related facts keeps them in the same chunk on any document, short or long.
    revised print section — replace in howto.txt

    How to print from a lab computer (print jobs expire after 24 hours):
    1. Open your file and choose Print. Select the printer named “CampusPrint.”
    2. Confirm the page count and select Print.
    3. Walk to any campus print station, tap your student ID card, and select “Release all.”
    4. Collect your pages. Print jobs that are not released within 24 hours are automatically deleted.

  4. Re-upload the revised file. In the Knowledge section, find the How-To Guide entry. Select the three-dot menu next to it and choose Delete (you are removing the old version). Then select Add knowledge → Files and upload your revised howto.txt. Give it the same name How-To Guide and the same description as before. Select Add to agent. Copilot Studio re-chunks and re-indexes the new version.
  5. Re-test. Start a new test session and ask the same spanning question: How do I print from a lab computer and how long until my print job expires? The answer should now include both the steps and the 24-hour expiry in one coherent response.
  6. General rule to apply to any weak answer: find the relevant section in the source document, make sure all the facts that belong together are in one contiguous block under one clear heading, remove any blank lines or sub-headings that break them apart, then re-upload and re-test.
What chunking actually is: Copilot Studio (via Dataverse) splits your document into overlapping passages of roughly 512 tokens each. Each passage becomes a vector embedding. When a question arrives, the system finds the passages whose embeddings are mathematically closest to the question embedding and returns them as context for the answer. You never see the chunks directly, but you can infer where they are by which facts get included or dropped in the answer.
Fix — revised document still gives incomplete answers: the re-index may not have completed yet; wait 30 seconds and start a new test session. If it still misses the fact, the section may still be breaking at an unexpected point — try moving the expiry information to the section heading itself (as shown in the revised block above) so it appears in the first sentence of the chunk.
Skills: chunking concepts, embeddings, vector retrieval, document structure for retrieval quality, re-upload and re-index.
Win conditionYou have restructured the print section of howto.txt so the expiry fact sits in the same contiguous block as the print steps, re-uploaded the revised file, and confirmed in a new test session that the spanning question returns both the steps and “24 hours” in one answer. Whether or not you saw an incomplete answer before the edit, you have practiced the structural technique that prevents retrieval gaps on longer real-world documents.
Checkpoint — how to verify
Ask How do I print from a lab computer and how long until my print job expires? before and after your document edit. With this short sample document you may get both facts both times — that is fine. The checkpoint is the edit itself: the expiry note must appear as a numbered step in the same block as the print steps under one clear heading, and after re-uploading the revised file, a new test session must return both facts together. If the after answer still misses the expiry, confirm you deleted the old source, uploaded the revised file, and started a fresh test session; the re-index takes a moment.

Level 4: Citations and Grounding Guardrails
Intermediate++350 XP
Make the base trustworthy. Copilot Studio automatically adds a citation to the source document for every answer it retrieves — you will verify that behavior here, then stress-test the guardrails by asking questions the docs do not cover. This is the anti-hallucination layer that makes a knowledge base safe to put in front of real users. Continue with your agent:
  1. Check for grounded wording and citations. In the Test your agent panel, ask: How do I set up MFA? Look at the response. The answer should use the document’s exact phrasing (for example, “Select ‘Add sign-in method’”) — that is the primary signal that the agent retrieved from your source rather than guessing. In many environments you will also see a citation badge (a numbered reference or source label like “How-To Guide”) beneath or beside the answer text. That badge is generated automatically by Copilot Studio when it retrieves from a named knowledge source; you do not need to add citation instructions to the Instructions field. If no badge appears, grounded wording is still a reliable confirmation that retrieval is working.
    Citation format note: the visual format of the citation badge (inline number, footnote, or a source link) varies by channel, interface version, and trial-vs-licensed environment. Treat it as a helpful confirmation, not the only one.
  2. Verify Allow ungrounded responses is off. Select Settings → Generative AI → Knowledge. Confirm Allow ungrounded responses is toggled off (set in Level 2). If it got switched on, turn it off and Save.
  3. Stress-test with out-of-scope questions. In the Test your agent panel ask these three questions and record what happens:
    test questions — ask each in a new session

    1. What is our VPN vendor’s stock price? (plausible-sounding but completely out of scope)

    2. Can I use lab computers to mine cryptocurrency? (policy topic but with a specific edge the policy does not address)

    3. What is the capital of France? (general knowledge, not in any doc)

    For each, the agent should either say it does not have that information or clearly state the limit of what the policy says — not invent an answer. Question 2 may return the policy’s acceptable-use rule (that is correct behavior — the policy does address personal commercial use). Questions 1 and 3 should produce a “not in my sources” response.
  4. Add an escalation path (optional but recommended). If you want the agent to offer a next step when it cannot answer, open the Instructions field on the Overview page and add one line at the end: When you cannot find an answer in your knowledge sources, say: "That is not covered in my sources. For further help, contact the IT desk at itdesk@campus.edu." This turns a dead end into a useful handoff.
  5. Confirm in-scope answers still cite a source. Ask How long must campus passwords be? (in the policy). The answer should say at least 12 characters and should cite the IT Use Policy source. If no citation appears, verify that generative orchestration is on and the knowledge source shows as active (green) in the Knowledge section.
Fix — agent still invents answers for out-of-scope questions: with Allow ungrounded responses off, the fallback topic triggers when no knowledge source is used. If the agent still answers, check whether Web Search is accidentally on (Settings → Generative AI → Knowledge → Use information from the web — it should be off). Also check that you are not running in Classic orchestration mode, which ignores the Allow ungrounded responses toggle.
Fix — citations are not appearing: citations are generated automatically only when the agent retrieves from a named knowledge source in Generative mode. If they are absent, confirm the source name is set (not blank), orchestration is Generative, and the source status shows as ready. Do not add citation-writing instructions to the Instructions field — that can cause the agent to hallucinate fake source names.
Skills: automatic citations, Allow ungrounded responses, grounding guardrails, out-of-scope refusal, escalation paths.
Guardrails. The base must cite its source for in-scope answers and must say “I don’t have that in my sources” for out-of-scope questions. It must never present an ungrounded guess as fact. An honest refusal is always better than a confident wrong answer.
Win conditionIn-scope answers use the document’s exact wording (a sign that retrieval, not invention, produced the answer), and the three stress-test questions each yield an honest “not in my sources” response (or the policy’s actual rule, for question 2) rather than a fabricated answer. Most environments also show a source citation badge beneath the answer text — if yours does, that confirms the source name; if the badge is absent, grounded wording is still the reliable signal.
Checkpoint — how to verify
Ask How long must campus passwords be? — answer should say at least 12 characters, using the policy’s exact wording; most environments also show a citation to IT Use Policy. Ask What is our VPN vendor’s stock price? — agent should decline or say it does not have that information. If it invents a stock price, confirm Allow ungrounded responses is off and Use information from the web is off, then start a fresh test session. If citation badges disappear from in-scope answers, the most common cause is switching to Classic orchestration — set it back to Generative.

Level 5: Freshness and Maintenance
Advanced+350 XP
Keep the knowledge base current. Stale knowledge is worse than none — it confidently gives outdated answers. In this level you edit a source document, re-upload it, and confirm the agent’s answer changes. Then you retire a document and confirm its content disappears from answers. These are the manual freshness skills; the licensed real-world path to automated refresh is noted at the end. Continue with your agent:
  1. Establish a baseline answer. In the Test your agent panel ask: How often must I change my campus password? Note the exact answer — it should say every 180 days, from policy.txt.
  2. Edit the source document to change the answer. Open policy.txt in your text editor. Find the line in Section 2 that says “changed at least every 180 days” and change it to “changed at least every 90 days” (simulating a policy update). Save the file.
  3. Replace the old source with the updated file. In the Knowledge section, find IT Use Policy. Select the three-dot menu → Delete to remove the old version. Then select Add knowledge → Files, upload the revised policy.txt, give it the same name IT Use Policy and the same description, and select Add to agent. Copilot Studio re-indexes the new version.
    Why delete and re-upload? Copilot Studio does not have an in-place “update file” option for uploaded files — you replace by deleting the old entry and uploading the revised file. Always keep a versioned copy locally (e.g., policy-v2.txt) so you can roll back if needed.
  4. Verify the answer changed. Start a new test session and ask: How often must I change my campus password? The answer should now say every 90 days, not 180. If it still says 180, wait 30 seconds (indexing takes a moment) and start another new session.
  5. Retire a document and confirm it disappears. In the Knowledge section, select the three-dot menu next to Help Desk FAQ and choose Delete to remove it from the agent. Now ask: How do I reset my campus password? The agent should say it does not have that information (the FAQ was the only source for that answer). If it still answers, start a new test session and ask again.
  6. Restore the FAQ (optional). If you want to keep a working agent, re-upload your original faq.txt with the same name and description. This is also a test of the restore path — retirement is reversible as long as you keep the source files.
In the real world — automated refresh: in a licensed Copilot Studio environment you can automate this replace cycle by connecting a Power Automate flow to the agent. The flow watches a SharePoint document library; when a file is updated, it triggers a re-index so the agent always reflects the current version without manual intervention. That path requires Power Automate and a licensed environment (not the create+test trial), but the manual replace-and-re-index skill you just practiced is exactly what the automation does under the hood.
Fix — old answer persists after re-upload: the most common cause is forgetting to start a new test session. The test panel caches context from prior turns. Always use the Start new test session icon after any knowledge source change. If a new session still returns the old answer, the re-index has not completed — wait 30–60 seconds and try again.
Fix — retired document content still appears in answers: deleting a knowledge source removes it from the agent immediately, but the test panel’s current session may have retrieved that content in a prior turn. Start a new test session and ask the question fresh; retired content should no longer appear.
Skills: manual re-index, source versioning, document retirement, freshness verification, the real-world automated refresh path.
Guardrails. Outdated information must not persist: changed sources are deleted and re-uploaded so the base reflects current truth, not last month’s. Retired documents are removed so their content no longer surfaces in answers.
Win conditionThe agent answers the password-change question with the updated value (90 days, not 180) after re-uploading the revised policy, and stops answering password-reset questions after the FAQ is retired — all verified in the test panel with new sessions.
Checkpoint — how to verify
Ask How often must I change my campus password? before editing — it should say 180 days. Edit policy.txt to 90 days, delete and re-upload, then ask again in a new session — it should say 90 days. Then delete the Help Desk FAQ and ask How do I reset my campus password? in a new session — the agent should say it does not have that information. If the old answer persists, confirm you deleted the old source entry (not just the local file) and start a fresh test session.
