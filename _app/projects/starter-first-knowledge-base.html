Subject

My First Knowledge Base

Adaptive · L1–5 30 min – 2 hr 250 – 1500 XP
Mission Brief

A knowledge base is the grounded memory an AI answers from. Without one, a model guesses from training data and sometimes confidently makes things up. With one, it does retrieve then generate: look up the relevant passage in your sources first, then answer from it, with a citation. This is the data layer of the AI stack, the natural sibling of My First Database.

You will build one real base and grow it across five levels: a Help-Desk Knowledge Base (the same help-desk world as My First Agent and My First Workflow). Level 1 grounds an assistant in a single document in about thirty minutes. Each level adds one capability to the same base: more sources organized cleanly, then retrieval quality (chunking and embeddings), then citations and anti-hallucination guardrails, and finally freshness so it never serves stale answers.

The throughline is trust. A base that cites its sources, says "I don't know" when it should, and stays current is one you can safely put in front of real users. By the end you will understand exactly why RAG beats a bare model, and how each piece, ingestion, retrieval, grounding, and freshness, earns that trust.

Agent Requirements
  • A Microsoft account with Copilot Studio access (a free trial works for Levels 1–2)
  • A web browser — the base is built in the maker portal, no installs or code
  • The provided sample sources: a help-desk FAQ, a policy document, and a how-to guide
  • Optionally, the Power Automate flow from My First Workflow (for the Level 5 scheduled refresh)
  • No prior AI, database, or programming experience required to start

1
Level 1: Ingest One Source
Beginner~30 min+250 XP
Create your first knowledge base from one document (the help-desk FAQ) in Copilot Studio's knowledge feature. Connect it so an assistant answers questions grounded in that document instead of guessing. This is retrieval-augmented generation (RAG) at its simplest: the AI looks up the answer in your source before it replies.
Skills: knowledge sources, grounding, basic RAG, document ingestion.
Win conditionThe assistant answers a question using the FAQ's content (not generic advice) and says "that's not in my knowledge base" for a topic the FAQ doesn't cover.
Checkpoint — how to verify
Ask a question the FAQ answers ("how do I reset my password?"); the reply should match the FAQ's wording, not generic web advice. Then ask something the FAQ does not cover; it should decline rather than invent. If it invents answers, confirm the document is attached as a knowledge source and the "answer only from sources" grounding setting is on.
✓
2
Level 2: Organize Many Sources
Beginner+~45 min+250 XP
Grow the base to several documents (FAQ + policy + a how-to guide). Give each a clear title and tags so retrieval pulls from the right source, and handle overlap: when two documents touch the same topic, the answer should be coherent, not contradictory.
Skills: multi-document knowledge bases, titles and tags, source organization, handling overlap.
Win conditionA question answerable only in the policy doc pulls from the policy doc, and a how-to question pulls from the how-to: the correct source each time.
Checkpoint — how to verify
Ask one question whose answer lives only in the policy doc and one only in the how-to. Confirm each answer comes from the correct source (check the cited document). If answers blend or pull the wrong source, sharpen the document titles and tags so the topics are clearly distinct, then re-test.
✓
3
Level 3: Retrieval Quality
Intermediate~1 hr+300 XP
Look under the hood. Documents are split into chunks and stored as embeddings (vectors); the base retrieves the chunks closest to the question. When answers are vague or off, the cause is usually chunking, too big, too small, or split mid-topic. Tune chunk size and add clear headings so the right passage is retrieved.
Skills: chunking, embeddings, vector retrieval, retrieval tuning.
Win conditionA question that previously returned a vague or wrong answer now retrieves the correct passage and answers precisely.
Checkpoint — how to verify
Find a question your base answers poorly and inspect which passage it retrieved (use the tool's citation / retrieval view). Restructure the source, clear headings, right-sized sections, so the full answer lives in one chunk, then re-index. Confirm the same question now retrieves the correct passage. If it still misses, the answer is being split across two chunks, keep it together in one section.
✓
4
Level 4: Citations and Grounding Guardrails
Intermediate+~1.5 hr+350 XP
Make the base trustworthy. Configure it to cite the source for every answer and to refuse or escalate when it cannot find grounding, instead of hallucinating. This is the anti-hallucination layer that makes a knowledge base safe to put in front of real users.
Skills: citations, grounding thresholds, refusal and escalation, anti-hallucination.
Guardrails. The base must cite its source and must say "I don't know / let me escalate" when the answer is not in the sources. It must never present an ungrounded guess as fact.
Win conditionEvery answer shows a source citation, and an out-of-scope question yields an honest "I don't have that in my sources" plus an escalation path, not a fabricated answer.
Checkpoint — how to verify
Ask three in-scope questions and confirm each answer includes a working citation you can open to the source. Then ask a plausible but out-of-scope question ("what is our VPN vendor's stock price?") and confirm it declines or escalates rather than inventing. If it fabricates, raise the grounding requirement and add an explicit "only answer from sources, otherwise say you don't know" instruction.
✓
5
Level 5: Freshness and Maintenance
Advanced~2 hr+350 XP
Keep it current. Stale knowledge is worse than none, it confidently gives outdated answers. Build a refresh process: re-index when a source changes, date and version your documents, retire stale ones, and optionally automate the refresh on a schedule (tie it to the Power Automate flow from My First Workflow).
Skills: re-indexing, versioning, freshness and staleness, knowledge-base maintenance, automation.
Guardrails. Outdated information must not persist: changed sources get re-indexed and stale documents retired, so the base reflects current truth, not last month's.
Win conditionUpdating a source document changes the assistant's answer after re-index, and a retired document no longer surfaces in answers.
Checkpoint — how to verify
Note the current answer to a question, edit the source document to change that answer, and re-index the base. Ask the same question and confirm the answer now reflects the edit, not the old value. Then retire/remove a document and confirm its content no longer appears in answers. If the old answer persists, the base did not re-index, trigger a manual re-index or wire the refresh into a scheduled flow.
