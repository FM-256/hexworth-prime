Subject

Set Up Your Kali Linux Attack VM

Recruit 90 min 200 XP
Authorization & Legal Notice

Kali Linux is a penetration-testing distribution. Its tools are designed to test the security of systems. Using them against systems you do not own or have explicit written authorization to test is illegal under laws including the Computer Fraud and Abuse Act (CFAA) in the United States and equivalent statutes in other countries. Unauthorized scanning, exploitation, or interception carries serious criminal and civil penalties.

This project covers only installation and configuration of the VM — that act is entirely benign. What you do with Kali after setup is governed by authorization and law. Practice only in your own isolated lab environment or on platforms that explicitly authorize testing (such as HackTheBox, TryHackMe, or your school's designated lab range). Never run offensive tools against your home router, your ISP, your school's network, or any other system without documented written permission from its owner.

Mission Brief

Kali Linux 2026.1 is the industry-standard penetration-testing distribution, maintained by Offensive Security and used by security professionals worldwide. In this project you will download the official prebuilt VirtualBox image, import it, log in, update the system, install tool metapackages, configure your environment with kali-tweaks, and run a first tool verification scan against your own VM to confirm everything is working.

The recommended path for beginners is the prebuilt VirtualBox image — it arrives already configured, ready to import in minutes, with no manual partitioning or installer required. The default login credentials for all Kali prebuilt images are kali / kali (username / password). You will change this password in Phase 3. Every subsequent Dark Arts lab assumes you have a working, updated Kali VM with this project complete.

If you already have VirtualBox installed from another Hexworth project, skip straight to Phase 1. If you have not installed a hypervisor yet, the Related Training card at the bottom links to the Forge House virtualbox project that walks you through that step.

Agent Requirements
  • 64-bit host computer with hardware virtualization enabled — Intel VT-x or AMD-V must be on in your BIOS/UEFI. Most machines ship with this enabled; if VirtualBox fails to start the VM, this is the first thing to check.
  • 8 GB RAM minimum on the host (16 GB recommended) — you will allocate 2–4 GB to the Kali VM. Running with less than 8 GB on the host causes the host OS to page heavily while the VM runs.
  • 40–80 GB of free disk space — the prebuilt image unpacks to roughly 14 GB. With snapshots and tool installs you will grow toward 30–40 GB over time. SSD strongly preferred; spinning disk makes boots and tool launches noticeably slow.
  • VirtualBox 7.x installed — free from virtualbox.org. The Forge House project "Create Your First Virtual Machine" covers installation if you need it.
  • 7-Zip installed — needed to extract the .7z Kali image archive. Download free from 7-zip.org (Windows) or install via sudo apt install p7zip-full / brew install p7zip (macOS).
  • Internet connection — the download is roughly 3–4 GB. The post-import update in Phase 3 pulls additional packages (size varies).

Download and Verify the Kali Prebuilt Image
Choose between the prebuilt VM image (recommended for beginners — no installer wizard required) and the full installer ISO. Download from the official site, then verify the SHA256 checksum to confirm the file was not corrupted or tampered with in transit.
  1. Go to the official download page. Open a browser and navigate to https://www.kali.org/get-kali/. You will see several tabs: Installer, Live, Virtual Machines, ARM, Mobile, and Cloud. Click Virtual Machines.
    Prebuilt VM vs. Installer ISO — which one? The prebuilt VM image is a ready-to-run virtual machine. You extract it, click Add in VirtualBox, and boot. The Installer ISO requires you to manually create a VM shell, attach the ISO, and run the full Kali installer (15–30 minutes, partitioning steps, user account creation). For this project, use the prebuilt VM. The ISO path is documented in the fix box below if you prefer it.
  2. Select VirtualBox and download. On the Virtual Machines tab, click the VirtualBox icon. The current release is Kali Linux 2026.1. The download file is named kali-linux-2026.1-virtualbox-amd64.7z and is roughly 3–4 GB. A torrent link is also available if your connection is slow or unreliable — both produce the same verified file.
  3. Download the SHA256 checksum file. Directly below the download button is a link labeled "SHA256" or a fingerprint icon. Download that file or copy the hash value shown on the page. You will use it in the next step.
  4. Verify the checksum after the download finishes. Open a terminal (or PowerShell on Windows) in the folder where you saved the .7z file and run the appropriate command for your OS:
    # On Linux or macOS: sha256sum kali-linux-2026.1-virtualbox-amd64.7z # On Windows (PowerShell): Get-FileHash kali-linux-2026.1-virtualbox-amd64.7z -Algorithm SHA256
    Compare the output hash against the value on the Kali download page. They must match exactly — every character. A mismatch means the file is corrupt; delete it and re-download.
  5. Extract the archive. The .7z file contains the actual VirtualBox VM files. Extract it with 7-Zip:
    # On Linux or macOS (command line): 7z x kali-linux-2026.1-virtualbox-amd64.7z # On Windows: right-click the .7z file → 7-Zip → Extract Here
    After extraction you will find a folder containing a .vbox file and one or more .vdi disk image files. Leave them in place; do not move them after the next step or VirtualBox will lose track of the disk.
Installer ISO path (alternate route):
  • On the kali.org/get-kali/ page, click the Installer tab and download the standard 64-bit ISO (not Live, not NetInstaller). Create a new VM in VirtualBox manually: 2 CPUs, 4 GB RAM, 40 GB dynamically allocated VDI disk, attach the ISO as the optical drive. Boot and follow the graphical installer. Select "Guided — use entire disk," accept the default partition layout, create a non-root user during setup (the Kali installer no longer creates a root-only setup by default). After install completes and the system reboots, remove the ISO from the VM's optical drive in VirtualBox settings.
  • The prebuilt image is faster for setup but the ISO path teaches you more about VM configuration. Either results in an identical Kali system for this project's purposes.
Checkpoint — what you should see
The sha256sum output matches the hash on the kali.org download page character-for-character. The extracted folder contains a .vbox file and at least one .vdi file. You have not moved or renamed these files.

Import the VM into VirtualBox and First Boot
Add the prebuilt VM to VirtualBox, review the network and hardware settings, and boot Kali for the first time. The prebuilt image comes pre-configured with sensible defaults but you should verify the network adapter type before booting.
  1. Add the VM to VirtualBox. Open VirtualBox. In the top toolbar, click Add (the icon shows a folder with a plus sign, or use the menu Machine → Add). In the file browser that opens, navigate to the extracted folder and select the kali-linux-2026.1-virtualbox-amd64.vbox file. Click Open. The VM will appear in the left sidebar.
    Why "Add" instead of "Import"? VirtualBox's "Import Appliance" function (File → Import Appliance) is for .ova files, which are a different format. The Kali prebuilt image for VirtualBox ships as a .vbox + .vdi pair. You must use Add, not Import. Using Import on the wrong file type will fail or produce a broken VM.
  2. Review the VM settings before first boot. Select the Kali VM in the sidebar and click Settings. Check the following:
    • System → Motherboard: confirm Base Memory is at least 2048 MB. Increase to 4096 MB if your host has 16 GB or more.
    • System → Processor: confirm CPU count is at least 2.
    • Network → Adapter 1: the default is NAT. NAT works fine for this project (Kali gets internet access through your host). If you later want Kali to appear as a separate host on your LAN (useful for scanning exercises), switch to Bridged Adapter. Leave it on NAT for now.
    • Display → Screen: set Video Memory to 128 MB. This prevents display glitches at higher resolutions.
    Click OK to close Settings.
  3. Start the VM. Double-click the Kali VM or click Start. A new window opens and Kali boots. The first boot takes 30–60 seconds as the XFCE desktop initializes. You will see the Kali XFCE login screen with the Kali dragon logo.
  4. Log in with the default credentials. The prebuilt image default account is:
    Username: kali Password: kali
    Type kali in the username field, press Tab or click the password field, type kali, and press Enter. The XFCE desktop loads. You are now inside Kali Linux 2026.1.
  5. Verify the OS version at the terminal. Right-click the desktop and choose Open Terminal Here, or click the terminal icon in the taskbar. Run:
    uname -a cat /etc/os-release
    Expected output:
    Linux kali 6.x.x-amd64 #1 SMP PREEMPT_DYNAMIC Kali ... x86_64 GNU/Linux NAME="Kali GNU/Linux" VERSION="2026.1" ID=kali ID_LIKE=debian PRETTY_NAME="Kali GNU/Linux 2026.1" VERSION_ID="2026.1"
    The exact kernel version number will vary; what matters is that NAME="Kali GNU/Linux" and VERSION shows 2026.1 (or later).
VT-x / AMD-V error on launch ("VT-x is disabled in the BIOS")?
  • Reboot your host computer and enter BIOS/UEFI (typically Del, F2, or F10 during the manufacturer splash screen). Find settings labeled Intel Virtualization Technology, VT-x, AMD-V, SVM, or Hardware Virtualization and set them to Enabled. Save and reboot. Then try starting the Kali VM again.
  • On Windows 11 hosts: if Hyper-V or WSL2 is enabled, VirtualBox may conflict. Open "Turn Windows features on or off" and disable Hyper-V and Windows Hypervisor Platform if you do not need them. A restart is required.
VM starts but screen is black or frozen at Kali logo?
  • In VirtualBox Settings → Display, try switching the Graphics Controller from VMSVGA to VBoxVGA (or vice versa). Restart the VM.
  • Reduce Video Memory to 64 MB temporarily if the boot freezes at the graphics stage.
  • If the VM boots but resolution is stuck at 800x600: this is expected before you install Guest Additions in Phase 4. Proceed — the fix comes later.
Checkpoint — what you should see
The Kali XFCE desktop is visible after logging in with kali / kali. A terminal shows cat /etc/os-release returning NAME="Kali GNU/Linux" and the 2026.1 version line. The taskbar at the bottom is visible and the desktop is responsive to mouse and keyboard input.

Change the Default Password and Update the System
The default kali / kali credentials are publicly known. Change the password immediately before putting this VM on any network. Then run a full system update to pull the latest versions of all packages — this is essential before doing any security work because tool versions matter.
  1. Open a terminal. Click the terminal icon in the taskbar, or right-click the desktop and select Open Terminal Here.
  2. Change the kali user password. Run:
    passwd
    You will be prompted for the current password (kali), then for a new password twice. Choose a password you will remember. It does not need to be your most sensitive password — this is a lab VM — but it should not be kali.
    Why change it? The prebuilt image credentials are published on kali.org and known to everyone. Any script or attacker on the same network segment can log into your VM with kali / kali if SSH is enabled or if you are on a bridged adapter. Change the password before enabling any services.
  3. Update the package list.
    sudo apt update
    Type your new password when prompted. You will see lines of package metadata being fetched from the Kali mirrors. This should complete in under a minute.
  4. Run the full upgrade.
    sudo apt full-upgrade -y
    full-upgrade (not upgrade) allows the package manager to remove obsolete packages and resolve dependency changes — necessary on Kali because new tool versions frequently replace older ones. This step downloads and installs all pending updates. Depending on how long ago the image was built and your internet speed, this can take anywhere from 5 minutes to 30 minutes. Let it run.
  5. Remove orphaned packages and clean the cache.
    sudo apt autoremove -y sudo apt clean
    autoremove removes packages that were installed as dependencies but are no longer needed. clean deletes cached package files from /var/cache/apt/ to reclaim disk space.
  6. Reboot the VM to apply any kernel updates.
    sudo reboot
    Log back in with kali and your new password after the VM restarts.
apt update fails with "Failed to fetch" or GPG errors?
  • If you see Certificate verification failed: the VM clock may be wrong. Run sudo timedatectl set-ntp true and wait 10 seconds, then try sudo apt update again. NTP sync fixes most certificate date mismatch errors.
  • If you see EXPKEYSIG or NO_PUBKEY: the Kali GPG archive key needs refreshing. Run sudo apt install --reinstall kali-archive-keyring then retry the update. (The deprecated apt-key tool was removed from current Debian/Kali — reinstalling the keyring package is the supported way to refresh the archive key.)
  • If apt update is simply slow or timing out: Kali mirrors can be congested. Edit /etc/apt/sources.list and confirm the mirror URL is the official load-balanced https://http.kali.org/kali, then retry.
  • Confirm the VM has internet access: run ping -c 3 8.8.8.8. If pings fail, check VirtualBox Network settings (NAT should work out of the box; Bridged requires your host network to assign an IP to the VM).
Checkpoint — what you should see
passwd completed without error and you can log back in after reboot with your new password. After the reboot, running sudo apt update shows "All packages are up to date." or a very small number of remaining items (sometimes packages are uploaded to the mirror after your upgrade ran). Running uname -r shows the current kernel version line.

4
Install Tool Metapackages and VirtualBox Guest Additions
The prebuilt image ships with kali-linux-default tools already installed. This phase explains the metapackage tiers so you can expand your toolset deliberately, then installs VirtualBox Guest Additions for clipboard sharing and proper screen resolution.
  1. Understand the Kali metapackage tiers. Kali organizes its 600+ tools into metapackages. The prebuilt image includes kali-linux-default. The full ladder:
    # See what is currently installed: dpkg -l | grep kali-linux
    • kali-linux-core — base OS only, minimal tools. Not useful on its own.
    • kali-linux-default — the standard toolset included in prebuilt images. Covers ~70% of common penetration-testing tasks: nmap, Metasploit, Burp Suite, Wireshark, Hydra, John the Ripper, sqlmap, and more.
    • kali-linux-large — extends default with more specialized tools for specific domains (RFID, hardware, SDR, forensics). Adds several gigabytes.
    • kali-linux-everything — all 600+ tools. Requires approximately 15 GB of additional disk space. Only install this if you have the disk and a specific reason.
  2. Install the large metapackage (recommended addition). For most learners, expanding from default to large is the right balance:
    sudo apt install -y kali-linux-large
    This adds tools for wireless attacks, VoIP, Bluetooth, and more advanced web exploitation. The download is 2–5 GB depending on what is already installed.
    Alternative: use kali-tweaks instead. If you want a menu-driven approach, skip this step and use kali-tweaks in the next step to select metapackages visually.
  3. Run kali-tweaks to configure the system graphically.
    sudo kali-tweaks
    A text-based interactive menu appears. Navigate it with arrow keys and Enter. Key sections:
    • Metapackages — check the boxes for the metapackage tiers you want and apply. This is the menu alternative to running apt install kali-linux-large manually.
    • Network Repositories — enables additional Kali-contrib and non-free repositories if you need commercial or non-free tools.
    • Hardening — optionally enables SSH hardening and disables services you do not need.
    • Shell & Prompt — switches the default shell between bash and zsh (zsh with powerlevel10k is the default in new Kali installs).
    Exit kali-tweaks when finished (press Escape or select the Quit option).
  4. Install VirtualBox Guest Additions for clipboard and resolution. Guest Additions are VirtualBox-specific drivers that enable shared clipboard, drag-and-drop between host and VM, and automatic screen scaling.
    sudo apt install -y virtualbox-guest-x11
    After installation, restart the VM:
    sudo reboot
    After rebooting, the VM window will auto-resize when you drag the VirtualBox window corner, and copy-paste between your host and the VM will work.
  5. Confirm Guest Additions are active after the reboot. In the VirtualBox menu bar (the menu above the VM window), go to View and confirm that "Auto-resize Guest Display" has a checkmark. Then drag the VM window to a larger size — the Kali desktop should resize with it within a few seconds.
    Shared clipboard setup: in the VirtualBox menu bar, click Devices → Shared Clipboard → Bidirectional. This allows you to copy commands from your host browser and paste them into the Kali terminal — essential for following lab guides.
virtualbox-guest-x11 fails to install or the display still does not resize after reboot?
  • Confirm you are running an updated kernel: uname -r. If a kernel update was installed in Phase 3, the running kernel and the installed kernel may differ until a reboot. Guest Additions driver compilation requires the current running kernel headers. Rebooting after Phase 3 resolves this.
  • If virtualbox-guest-x11 is not found: run sudo apt update first, then retry. The package is in the main Kali repo.
  • On very new VirtualBox releases, Kali may ship a newer kernel that the Guest Additions package has not yet caught up to. In that case, use the VirtualBox-provided installer instead: in the VM menu bar click Devices → Insert Guest Additions CD Image, then in Kali run sudo mount /dev/cdrom /mnt && sudo /mnt/VBoxLinuxAdditions.run. Reboot after.
  • If clipboard sharing does not work: go to VirtualBox Devices → Shared Clipboard → Bidirectional and confirm it is selected. Also confirm Guest Additions installed without errors in the previous step's output.
Checkpoint — what you should see
Running dpkg -l | grep kali-linux shows at least kali-linux-default (and kali-linux-large if you installed it) with status ii (installed). Dragging the VirtualBox window corner causes the Kali desktop to resize automatically. Copy-pasting text between the host and VM works when Devices → Shared Clipboard → Bidirectional is selected.

Configure the Working Environment and Take a Clean Snapshot
Configure the terminal, set timezone and locale, create a targets directory for your lab work, and take a VirtualBox snapshot of this clean configured state. The snapshot is your recovery point — after any lab exercise that might damage the VM, you restore to this snapshot instead of rebuilding from scratch.
  1. Set the correct timezone. By default the prebuilt image may be set to UTC. Update it to your local timezone:
    sudo timedatectl set-timezone America/New_York
    Replace America/New_York with your timezone. To list all valid names run timedatectl list-timezones | grep America (or replace America with your region). Correct timezone prevents log timestamps from being confusing during lab exercises.
  2. Configure locale if the terminal shows encoding warnings. If you see warnings about LC_ALL or LANG not being set:
    sudo dpkg-reconfigure locales
    In the text menu, scroll to en_US.UTF-8 UTF-8 (or your language), press Space to mark it, press Enter to confirm, and select it as the default locale.
  3. Install Terminator for split-pane terminal work. Many pentesting workflows require watching multiple outputs simultaneously (e.g., a running scan in one pane, log output in another). Terminator is the most beginner-friendly split-pane terminal on Kali:
    sudo apt install -y terminator
    After install, right-click the Kali desktop → Applications → Terminal Emulators → Terminator to open it. Inside Terminator, right-click to split the terminal horizontally or vertically.
    zsh vs. bash: Kali 2026.1 defaults to zsh with the powerlevel10k prompt. If you find the prompt configuration wizard runs on first terminal open, follow the prompts or press q to skip it. Both zsh and bash work for every command in these labs. Do not switch shells unless you have a specific reason.
  4. Create a directory structure for lab work.
    mkdir -p ~/targets ~/loot ~/notes ~/tools
    Convention used across Dark Arts labs:
    • ~/targets/ — one subdirectory per engagement or lab target IP (e.g., ~/targets/10.10.10.10/)
    • ~/loot/ — credential files, hashes, flags captured during labs
    • ~/notes/ — markdown notes, command output saves
    • ~/tools/ — manually installed tools not in the Kali repos
  5. Take a VirtualBox snapshot of the clean configured state. Shut down or leave the VM running, then in the VirtualBox Manager window (not the VM window itself) click the VM name in the left sidebar. In the right pane, click the three-dot menu or use the Machine menu inside the running VM window and select Take Snapshot. Name the snapshot:
    Snapshot name: Kali 2026.1 Clean — Post-Update Description: Updated, kali-linux-large installed, Guest Additions active, directories created
    Click OK. VirtualBox writes the snapshot. This takes 30–60 seconds for a Kali VM.
    How to use the snapshot: after any future lab that corrupts files or breaks tools, open the VirtualBox snapshot manager (Machine → Snapshots in the VM menu, or the Snapshots tab in the Manager), right-click this snapshot, and choose Restore. The VM reverts to this exact state in under 30 seconds. Always take a new snapshot before any lab that involves exploitation or system modification.
Snapshot option is greyed out?
  • The VM must be in a saved, powered-off, or running state to take a snapshot. If it is in the "Aborted" state (crashed), start it, log in, then take the snapshot.
  • On some VirtualBox versions the snapshot button only appears when the VM is selected in the Manager window, not when the VM console window is focused. Switch to the Manager window (not the VM display window) and click the VM name before trying the menu.
Checkpoint — what you should see
Running timedatectl shows your correct local timezone and NTP service: active. The directories ~/targets, ~/loot, ~/notes, and ~/tools exist (confirm with ls ~/). In VirtualBox Manager, the Snapshots tab for the Kali VM shows at least one snapshot named "Kali 2026.1 Clean" with a timestamp.
✓
6
Verify the Toolkit and Run Your First Authorized Scan
Confirm that the core tools installed correctly by checking their versions from the terminal. Then run a first safe scan against localhost to prove the network stack and tool execution path work end-to-end. Localhost is always authorized — you own it. Take a second snapshot after verification.
  1. Verify key tool versions. Open a terminal and run each of the following. Every command should print a version line with no "command not found" error:
    nmap --version msfconsole --version sqlmap --version hydra --version john --version
    Expected output (versions will vary with updates):
    Nmap version 7.95 ( https://nmap.org ) Framework Version: 6.4.x Usage: sqlmap [options] sqlmap 1.8.12#stable Hydra v9.5 (c) 2023 by van Hauser ... John the Ripper 1.9.0-jumbo-1+ [linux-gnu 64-bit x86_64 AVX2 AC]
    If any command returns "command not found," run sudo apt install -y <toolname> (replace with the actual package name). For Metasploit use sudo apt install -y metasploit-framework.
  2. Launch Burp Suite to confirm the GUI tools work.
    burpsuite &
    The & runs it in the background so the terminal remains usable. Burp Suite Community Edition opens a splash screen and then the main interface. Close it when you have confirmed it launches. If Burp requires Java and shows an error, install it:
    sudo apt install -y default-jdk
  3. Run an nmap scan against localhost. Scanning your own VM is always authorized. This confirms that nmap can execute, send packets, and return results:
    nmap -sV 127.0.0.1
    A fresh prebuilt Kali ships with SSH (and most services) NOT running, so the expected result is zero open ports — what matters is that Nmap runs, sends packets, and reports "1 host up":
    Starting Nmap 7.9x ( https://nmap.org ) at 2026-06-20 14:35 EDT Nmap scan report for localhost (127.0.0.1) Host is up (0.000013s latency). All 1000 scanned ports on localhost (127.0.0.1) are in state: closed Nmap done: 1 IP address (1 host up) scanned in 1.20 seconds
    If you have manually started a service (e.g. sudo systemctl start ssh), you would instead see that port listed as open with its version — but on a stock image, zero open ports is the correct, expected result.
    Authorization reminder: scanning 127.0.0.1 (your own VM) is always safe and authorized. Do NOT run nmap against your host machine's external IP, your router, your campus network, or any other target without explicit written authorization from the system owner. Even a basic port scan is illegal against unauthorized targets in most jurisdictions.
  4. Check Wireshark launches and can see the loopback interface.
    sudo wireshark &
    Wireshark opens. In the interface list you should see at least lo (loopback) and eth0 (or similar). Double-click lo to start a capture. You will immediately see packets appear (loopback traffic from system processes). Click the red Stop button. Close Wireshark.
  5. Take a second "Verified" snapshot. This snapshot records the state after you have confirmed everything works:
    Snapshot name: Kali 2026.1 Verified — Tools Confirmed Description: nmap, msfconsole, sqlmap, hydra, burpsuite, wireshark all verified. Localhost scan clean.
    You now have two recovery points: the clean post-update state and the verified post-check state.
nmap returns "Operation not permitted" or requires sudo?
  • Some scan types (SYN scan -sS) require root privileges. The version scan -sV against localhost should work without sudo, but if you see permission errors, prefix with sudo: sudo nmap -sV 127.0.0.1.
  • If nmap is not found: sudo apt install -y nmap. It is part of kali-linux-default but confirm with which nmap.
msfconsole takes a very long time to start?
  • On first run, Metasploit initializes its database and caches module metadata. This can take 2–5 minutes on a VM with limited RAM. Subsequent launches are much faster. Let it run. If it times out, increase VM RAM to 4 GB in VirtualBox Settings.
  • If msfconsole exits with a PostgreSQL error: run sudo msfdb init to initialize the Metasploit database, then relaunch msfconsole.
Checkpoint — what you should see
nmap --version, msfconsole --version, sqlmap --version, hydra --version, and john --version all print version lines without errors. nmap -sV 127.0.0.1 completes and shows "1 host up." Burp Suite and Wireshark open to their main interfaces. The VirtualBox snapshot manager shows two snapshots for this VM. Your Kali attack platform is ready.
