Subject

Build an AI Research Agent

Operator 150 min 750 XP
Mission Brief

Your mission is to build a tool-calling AI research agent that takes a question, reasons about how to answer it, executes real tools (web search and a safe math evaluator) in a loop, and returns a sourced answer — all running locally on your machine with no paid API key required.

The core mechanism is the ReAct loop (Reason + Act): the model sees your question, decides which tool to call, receives the tool's output, reasons again, and repeats until it has enough information to answer. You will wire this loop using create_agent from LangChain 1.3 (the current canonical agent factory, built on top of LangGraph). The local LLM is served by Ollama running qwen3:4b — a 4-billion-parameter model that natively supports tool/function calling. The search tool uses DuckDuckGo via the ddgs package, which is free and requires no account.

You will watch the agent's reasoning trace in real time as it decides to call a tool, see the tool result come back, and then watch the model incorporate that result into its next reasoning step. The finished script accepts any research question and prints a sourced, formatted answer to the terminal.

Agent Requirements
  • Python 3.11 or higher — check with python --version or python3 --version
  • Basic Python skills: functions, decorators, and installing packages with pip — no prior AI or LangChain experience required
  • Ollama installed and running — Ollama is free software that serves local LLMs. Phase 1 covers the full install. Requires roughly 3 GB of free disk space for the qwen3:4b model.
  • Free RAM: qwen3:4b requires approximately 4–6 GB of free RAM to load. On a machine with less available memory, Ollama will stall silently with no error message — the model simply never responds. Close other applications before starting Ollama if you are near the limit.
  • Internet access for DuckDuckGo searches (the agent calls DuckDuckGo at runtime). No API key, no account needed.
  • WSL2 / Linux / macOS note: Ollama runs natively on all three. On Windows without WSL2, install the Ollama Windows binary (ollama.com/download). The Python packages install identically on all platforms.

Install Ollama and Pull the Tool-Capable Model
Set up the local LLM server and download the model. This is the only phase that requires a significant download (~2.5 GB). The model choice matters: most small local models silently ignore tool definitions. qwen3:4b is verified to support Ollama's OpenAI-compatible tool-calling spec.
  1. Install Ollama. Visit ollama.com/download and follow the one-click installer for your OS. On Linux you can also run:
    curl -fsSL https://ollama.com/install.sh | sh
    After installing, Ollama runs as a background service on port 11434 automatically.
  2. Pull the qwen3:4b model. Open a terminal and run:
    ollama pull qwen3:4b
    This downloads ~2.5 GB. It only happens once; the model is cached locally. If you have a faster machine with more RAM, qwen3:8b gives better reasoning quality. If disk is tight, qwen3:1.7b also supports tool calling but produces shorter answers.
  3. Verify Ollama is running and the model is loaded. In a new terminal:
    ollama list
    You should see qwen3:4b in the output. Then confirm the server is reachable:
    curl http://localhost:11434/api/tags
    Expected: a JSON response listing your pulled models. If you get "connection refused", Ollama is not running — start it with ollama serve in a terminal and leave it running.
  4. Create the project folder.
    mkdir research-agent cd research-agent
  5. Install the Python packages.
    pip install langchain==1.3.10 langchain-ollama==1.1.0 ddgs==9.14.4
    What each package does: langchain provides create_agent and the @tool decorator. langchain-ollama provides the ChatOllama class that connects to your running Ollama server. ddgs is the DuckDuckGo search client (the package was renamed from duckduckgo-search to ddgs, and the import is now from ddgs import DDGS).
  6. Verify the installs.
    python -c "import langchain, langchain_ollama; from ddgs import DDGS; print('langchain:', langchain.__version__); print('langchain_ollama:', langchain_ollama.__version__); print('ddgs: OK')"
    Expected output:
    langchain: 1.3.10 langchain_ollama: 1.1.0 ddgs: OK
Ollama not found after install?
  • On Linux/macOS: close and reopen your terminal so the PATH update takes effect, then run ollama --version.
  • On Windows: make sure you installed the Ollama Windows binary, not just the Linux installer via WSL. The binary installs to %LOCALAPPDATA%\Programs\Ollama and adds itself to PATH.
  • ollama serve prints its logs to the terminal — check that line for error messages if the server fails to start.
Checkpoint — what you should see
ollama list shows qwen3:4b. curl http://localhost:11434/api/tags returns JSON. The Python verify command prints three lines without error. If the curl fails with "connection refused", run ollama serve in a separate terminal and leave it open for the rest of this project.

Define the Tools with the @tool Decorator
A LangChain tool is any Python function decorated with @tool. The function's docstring becomes the tool description that the LLM reads to decide when and how to call it. Write clear, concise docstrings — the model cannot call a tool correctly if it does not understand what the tool does.
  1. Create tools.py in your research-agent folder and paste this complete file:
    # tools.py # Tool definitions for the research agent. # Each @tool function becomes a callable the LLM can invoke. from langchain.tools import tool from ddgs import DDGS @tool def web_search(query: str) -> str: """Search the web for current information about a topic. Use this tool when the question requires facts, recent events, statistics, or information you cannot answer from memory. Returns a formatted list of the top 5 search results with titles, URLs, and snippets. Args: query: The search query string. """ try: results = DDGS().text(query, max_results=5) if not results: return "No results found for that query." lines = [] for i, r in enumerate(results, 1): lines.append(f"[{i}] {r['title']}") lines.append(f" URL: {r['href']}") lines.append(f" {r['body']}") lines.append("") return "\n".join(lines) except Exception as e: return f"Search failed: {e}. Try a shorter or simpler query." @tool def calculate(expression: str) -> str: """Evaluate a safe mathematical expression and return the result. Use this tool when you need to compute a number: arithmetic, percentages, unit conversions, or any calculation the question requires. Only arithmetic expressions are supported (no code execution). Args: expression: A math expression as a string, e.g. '(42 * 1.08) / 3' """ # Restrict to safe characters to prevent code injection. allowed = set("0123456789+-*/()., eE") if not all(c in allowed for c in expression.replace(" ", "")): return "Error: expression contains unsupported characters. Use only numbers and +-*/()" try: result = eval(expression, {"__builtins__": {}}, {}) return f"{expression} = {result}" except Exception as e: return f"Could not evaluate '{expression}': {e}"
    Why two tools? web_search handles fact-finding. calculate handles any arithmetic the question involves (e.g., "How much is 15% tip on $47?"). Together they cover most research-question shapes.
  2. Test each tool directly before wiring them to the agent. In your terminal:
    python -c "from tools import web_search, calculate; print(web_search.invoke('Python programming language')); print('---'); print(calculate.invoke('(100 * 1.15)'))"
    Note the .invoke() call. LangChain tools are not called as plain functions — they are BaseTool objects with an .invoke() method. Calling web_search("query") directly also works because @tool preserves the original function call, but .invoke() is the standard pattern inside agents.
DuckDuckGo search returns empty results or raises an error?
  • DuckDuckGo rate-limits aggressive scrapers. Wait 30 seconds and try again — it is not a code problem.
  • If you are on a network that blocks DuckDuckGo, the tool will return "Search failed: ..." with the error message. The agent will still run; it just cannot use search results for that query.
  • If results come back but are empty, try a more specific query string. Very short queries like "AI" return sparse results.
Checkpoint — what you should see
The web_search.invoke() call prints a numbered list of up to 5 results, each with a title, URL, and snippet. The calculate.invoke() call prints (100 * 1.15) = 115.0. No errors. If you see the results, the tools work independently and are ready to be given to the agent.

Build the Agent with create_agent and ChatOllama
create_agent from langchain.agents (LangChain 1.3) is the current canonical agent factory. It accepts a model instance and a list of tools, then builds the full ReAct loop internally using LangGraph. The agent is a compiled state graph that you run with .stream() or .invoke().
  1. Create agent.py in your research-agent folder and paste this complete file:
    # agent.py # Builds and runs the research agent. from langchain.agents import create_agent from langchain_ollama import ChatOllama from tools import web_search, calculate # Connect to the Ollama server running on your machine. # base_url defaults to http://localhost:11434 -- change it if Ollama # is running on a different host or port. llm = ChatOllama( model="qwen3:4b", temperature=0, # deterministic answers for research tasks base_url="http://localhost:11434", ) # create_agent builds the full ReAct loop. # Pass the tools list -- the model will receive their names and docstrings # so it can decide which tool to call and when. agent = create_agent( model=llm, tools=[web_search, calculate], system_prompt=( "You are a research assistant. When you need facts, always search first. " "For any math in the question, use the calculate tool. " "Cite the URLs from your search results in your final answer." ), ) QUESTION = "What is the current population of Tokyo, and how does that compare to New York City?" print(f"Question: {QUESTION}") print("=" * 60) # stream() yields one update dict per agent step. # stream_mode='updates' gives us each node's output as it runs, # so we can see the tool calls and their results in real time. for chunk in agent.stream( {"messages": [{"role": "user", "content": QUESTION}]}, stream_mode="updates", ): # Each chunk is a dict like {"agent": {...}} or {"tools": {...}} for node_name, node_output in chunk.items(): print(f"\n[{node_name.upper()}]") messages = node_output.get("messages", []) for msg in messages: # AIMessage may have tool_calls before the final answer. if hasattr(msg, "tool_calls") and msg.tool_calls: for tc in msg.tool_calls: print(f" Tool call: {tc['name']}({tc['args']})") elif hasattr(msg, "content") and msg.content: print(f" {msg.content}")
  2. Run the agent:
    python agent.py
    The first run may take 10–30 seconds while the model loads into RAM. Subsequent runs in the same Ollama session are faster.
ConnectionRefusedError or httpx.ConnectError? Ollama is not running. Open a new terminal, run ollama serve, leave it running, then retry python agent.py.
The agent returns an answer but never calls any tools? This is the most important trap: the model you pulled does not support tool calling. qwen3:4b explicitly supports it. If you pulled a different model (e.g., llama3.2, mistral, or phi3) by mistake, run ollama pull qwen3:4b and update the model= line in agent.py. A model that does not support tool calling will ignore the tools list and answer from memory only, with no [TOOLS] steps appearing in the trace.
Checkpoint — what you should see
The terminal shows alternating [AGENT] and [TOOLS] blocks. Under [AGENT] you see lines like Tool call: web_search({'query': 'Tokyo population 2024'}). Under [TOOLS] you see the raw search results come back. After one or more tool rounds, the final [AGENT] block contains the synthesized answer with numbers and — if the model is behaving well — references to the URLs it found. If you only see one [AGENT] block with a direct answer and no tool calls, the model is not calling tools.

Multi-Step Query: Force the Agent to Use Both Tools
A single-fact question usually triggers one search call. A compound question that requires both a fact lookup AND a calculation forces the agent to reason across multiple tool calls. This phase makes the ReAct loop visible in a way that a one-shot question does not.
  1. Create multistep.py in your research-agent folder and paste this complete file:
    # multistep.py # Runs a multi-step query that requires both search and calculation. from langchain.agents import create_agent from langchain_ollama import ChatOllama from tools import web_search, calculate llm = ChatOllama(model="qwen3:4b", temperature=0) agent = create_agent( model=llm, tools=[web_search, calculate], system_prompt=( "You are a precise research assistant. " "Always use web_search for current facts. " "Always use calculate for any arithmetic. " "Show your reasoning. Cite sources in the final answer." ), ) QUESTION = ( "What is the average monthly salary in Germany in 2024? " "If someone saves 20 percent of that salary each month, " "how much will they have saved after one year?" ) print(f"Question:\n {QUESTION}\n") print("=" * 60) print("Agent trace:") print() final_answer = "" for chunk in agent.stream( {"messages": [{"role": "user", "content": QUESTION}]}, stream_mode="updates", ): for node_name, node_output in chunk.items(): messages = node_output.get("messages", []) for msg in messages: if hasattr(msg, "tool_calls") and msg.tool_calls: for tc in msg.tool_calls: print(f" [{node_name}] Calling {tc['name']} with: {tc['args']}") elif hasattr(msg, "content") and msg.content: if node_name == "agent": final_answer = msg.content # capture the last agent message else: # Tool result -- show a truncated preview preview = msg.content[:200].replace("\n", " ") print(f" [{node_name}] Result preview: {preview}...") print() print("=" * 60) print("FINAL ANSWER:") print(final_answer)
  2. Run it:
    python multistep.py
    Watch the trace. You should see the agent call web_search first (to look up the salary figure), then call calculate with the found number, then produce a final answer that combines both results.
  3. Try your own compound question. Change QUESTION to something like: "What is the current price of gold per ounce? If I have 5 ounces, what is the total value in euros assuming 1 USD = 0.92 EUR?"
Agent only calls one tool and skips the calculation?
  • This is a model reasoning limitation, not a bug. Smaller models sometimes answer with math from memory rather than calling calculate. Strengthen the system prompt: add "You must use the calculate tool for ALL arithmetic, even simple multiplication."
  • Setting temperature=0 makes the model more literal and rule-following, which usually improves tool adherence. Confirm it is set in your ChatOllama() call.
Checkpoint — what you should see
The trace shows at least two [agent] Calling ... lines: one for web_search and one for calculate. The FINAL ANSWER section contains a number produced by the calculation (not pulled from memory), and references the search result it used to get the salary figure. If the agent calls the same tool twice (e.g., two searches), that is also valid reasoning — it may be refining its query.

Format and Save a Sourced Answer Report
Wire everything into a clean CLI script that accepts any question as a command-line argument and writes a markdown report to disk. This is the deliverable: a reusable research tool you can point at any question.
  1. Create research.py in your research-agent folder and paste this complete file:
    # research.py # CLI research agent -- accepts any question, writes a markdown report. # Usage: python research.py "your question here" # python research.py "your question" --out report.md import argparse import sys import datetime from langchain.agents import create_agent from langchain_ollama import ChatOllama from tools import web_search, calculate def build_agent(verbose: bool = False): """Construct the research agent.""" llm = ChatOllama( model="qwen3:4b", temperature=0, base_url="http://localhost:11434", ) return create_agent( model=llm, tools=[web_search, calculate], system_prompt=( "You are a thorough research assistant. " "Always search before answering factual questions. " "Use the calculate tool for any arithmetic. " "In your final answer, list the sources (URLs) you found." ), ) def run_research(question: str, verbose: bool = False) -> dict: """Run the agent and collect the trace and final answer.""" agent = build_agent(verbose) tool_calls = [] # log each tool call for the report tool_results = [] # log each tool result (truncated) final_answer = "" for chunk in agent.stream( {"messages": [{"role": "user", "content": question}]}, stream_mode="updates", ): for node_name, node_output in chunk.items(): messages = node_output.get("messages", []) for msg in messages: if hasattr(msg, "tool_calls") and msg.tool_calls: for tc in msg.tool_calls: tool_calls.append(f"{tc['name']}({tc['args']})") if verbose: print(f" [tool call] {tc['name']}({tc['args']})") elif hasattr(msg, "content") and msg.content: if node_name == "agent": final_answer = msg.content elif node_name == "tools": preview = msg.content[:300].replace("\n", " ") tool_results.append(preview) if verbose: print(f" [tool result] {preview}") return { "question": question, "tool_calls": tool_calls, "tool_results": tool_results, "answer": final_answer, } def write_report(result: dict, output_path: str): """Write the research result to a markdown file.""" ts = datetime.datetime.now().strftime("%Y-%m-%d %H:%M") lines = [ f"# Research Report", f"", f"**Question:** {result['question']}", f"", f"**Generated:** {ts}", f"**Model:** qwen3:4b via Ollama", f"", f"---", f"", f"## Answer", f"", result["answer"], f"", f"---", f"", f"## Research Trace", f"", f"**Tools called ({len(result['tool_calls'])}):**", ] for i, tc in enumerate(result["tool_calls"], 1): lines.append(f"{i}. `{tc}`") lines += ["", "**Tool result previews:**", ""] for i, tr in enumerate(result["tool_results"], 1): lines.append(f"{i}. {tr}") lines.append("") with open(output_path, "w", encoding="utf-8") as f: f.write("\n".join(lines)) print(f"Report saved to: {output_path}") def main(): parser = argparse.ArgumentParser( description="AI Research Agent -- answers questions using web search and calculation." ) parser.add_argument("question", help="The research question to answer.") parser.add_argument( "--out", default="report.md", help="Output file path for the markdown report (default: report.md)." ) parser.add_argument( "--verbose", action="store_true", help="Print the agent's tool calls and results to the terminal as they happen." ) args = parser.parse_args() print(f"Researching: {args.question}") print("(This may take 15-60 seconds on first run while the model loads.)") print() result = run_research(args.question, verbose=args.verbose) print() print("=" * 60) print("ANSWER:") print(result["answer"]) print("=" * 60) print(f"Tool calls made: {len(result['tool_calls'])}") write_report(result, args.out) if __name__ == "__main__": main()
  2. Run it with a research question:
    python research.py "What is the unemployment rate in the United States as of 2024?" --verbose
  3. Try a multi-step question and save the report:
    python research.py "What is the speed of light in km/s, and how long would it take to travel from Earth to the Moon at that speed?" --out moon-light.md --verbose
  4. Open the saved markdown file (report.md or moon-light.md) in any Markdown viewer (VS Code preview, Typora, or GitHub) to see the formatted report with the answer, tool call log, and source previews.
Agent enters an infinite loop (tool calls keep repeating)?
  • create_agent includes a built-in recursion limit (default 25 steps). If you hit it, the agent raises a GraphRecursionError and stops. This usually means the model is calling the same tool repeatedly without making progress — tighten the system prompt to include "If search returns results, synthesize them and answer rather than searching again."
  • You can also set a lower limit: add config={"recursion_limit": 10} as a second argument to agent.stream().
Want to use an OpenAI model instead of Ollama? This is the optional paid-API path. Replace the ChatOllama setup with:
# pip install langchain-openai # export OPENAI_API_KEY="sk-..." from langchain_openai import ChatOpenAI llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)
Then pass llm to create_agent identically. Every other line of code stays the same because create_agent accepts any LangChain chat model. gpt-4o-mini has strong tool-calling support and is the cheapest OpenAI option that reliably calls tools.
Checkpoint — what you should see
Running python research.py "..." --verbose prints the agent's tool calls in real time, then prints the FINAL ANSWER, then saves a markdown file. The markdown file contains the answer, a numbered list of tools called (e.g., web_search({'query': '...'})), and previews of the results. Open the file — it should be readable as a self-contained research note with sources. If the answer section is empty or the file is blank, check that final_answer is being set: add a print(f"DEBUG final_answer={final_answer!r}") after the stream loop to inspect what the agent returned.
