Subject

Build a Discord Security Bot

Advanced 3H 1100 XP
Mission Brief

This operation requires the construction of a Discord security and moderation bot built with TypeScript and Discord.js that monitors server events, enforces moderation policies, and maintains a complete audit trail of every action taken. The bot listens for guild events — messages, joins, leaves, role changes, and channel modifications — routing them through a moderation engine that detects spam floods, raid attempts, and phishing links in real time. All moderation actions are logged to a SQLite database for accountability and review.

The bot exposes slash commands for moderators: /ban, /kick, /mute, /warn, /audit, and /lockdown. Each command validates the invoker's permissions, executes the action through the Discord API, logs the event with actor, target, reason, and timestamp, and sends a formatted embed to a designated mod-log channel. The warning system tracks infractions per user and automatically escalates: three warnings trigger a mute, five trigger a kick, and repeat offenders are banned with full history attached.

This project bridges software engineering and security operations. You will learn how to build event-driven architectures, design permission hierarchies, implement automated threat response, and maintain audit trails — patterns that apply far beyond Discord to any system where security monitoring and access control are critical.

Agent Requirements
  • Solid TypeScript fundamentals: types, interfaces, async/await, and module imports
  • Basic understanding of Discord: servers, channels, roles, and permissions
  • Familiar with npm for package management and running scripts
  • A Discord account with a test server where you have administrator permissions
  • No prior Discord.js or bot development experience required — this project teaches the full API from application registration to deployment
Operation Phases
1
Bot Client & Gateway Connection
Register a Discord application and bot user through the Developer Portal. Configure GatewayIntentBits for guild members, messages, and message content. Initialize the Client with discord.js v14 and connect to the gateway. Set the bot's presence and status. Implement the ready event to confirm connection and log the number of guilds served. Store the token in environment variables loaded with dotenv.
2
Event Listeners & Monitoring
Register listeners for security-relevant events: messageCreate, messageDelete, messageUpdate, guildMemberAdd, guildMemberRemove, and guildBanAdd. Implement a rate limiter that detects message spam (more than 5 messages in 3 seconds) and mass-join raids (more than 10 joins in 10 seconds). Scan message content for known phishing URL patterns using regex matching against a configurable blocklist. Log all detected anomalies to the mod-log channel.
3
Command Router & Slash Commands
Build a command registration system using SlashCommandBuilder and the REST API to deploy commands to the guild. Implement a command router that dispatches interactionCreate events to handler functions. Each command validates that the invoker has the required permissions (BAN_MEMBERS, KICK_MEMBERS, etc.) before execution. Build /ban, /kick, /mute (using timeout), /warn, /audit, and /lockdown commands with proper option types and autocomplete.
4
Moderation Engine & Escalation
Build the moderation engine that tracks infractions per user and automatically escalates based on configurable thresholds. The /warn command adds an infraction record; at 3 warnings the user is automatically muted for 1 hour, at 5 they are kicked, and at 7 they are banned. Send DM notifications to the target user explaining the action and reason. Implement /lockdown that removes SEND_MESSAGES permission from @everyone in the specified channel and restores it with /unlock.
5
SQLite Storage & Audit Log
Set up better-sqlite3 with tables for warnings, bans, kicks, mutes, and a unified audit log. Every moderation action writes a row with: action type, moderator ID, target user ID, reason, timestamp, and guild ID. Implement the /audit <user> command that queries the database and returns a paginated embed showing the user's complete infraction history. Add /modstats to show moderation activity: actions per moderator, most common infractions, and weekly trends.
6
Security Alerts & Embed Formatting
Build rich EmbedBuilder messages for all moderation notifications. Color-code embeds by severity: yellow for warnings, orange for mutes, red for kicks and bans. Include fields for moderator, target, reason, infraction count, and timestamp. Route all mod actions to a configurable #mod-log channel. Implement security alert embeds for detected spam, raids, and phishing attempts with details about the detected pattern and the automated response taken.
