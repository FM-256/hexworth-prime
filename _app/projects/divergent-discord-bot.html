Subject

Build a Discord Security Bot

Operative 3H 1100 XP
Mission Brief

This operation requires the construction of a Discord security and moderation bot built with TypeScript and discord.js v14 that monitors server events, enforces moderation policies, and maintains a complete audit trail of every action taken. The bot listens for guild events — messages, joins, leaves, and role changes — routing them through a moderation engine that detects keyword violations in real time. All moderation actions are logged to a SQLite database for accountability and review.

The bot exposes slash commands for moderators: /status, /warn, /kick, /timeout, and /audit. Each command validates the invoker's permissions before executing. The warning system tracks infractions per user and automatically escalates: three warnings trigger a one-hour timeout, and five warnings trigger a kick with full history attached. Every action generates a formatted embed posted to a designated #mod-log channel.

Ethics note: this is a defensive moderation bot for a server you own or administer. You are protecting your own community. The bot token must be kept secret — stored in an environment variable, never committed to source control. Do not deploy this bot to a server where you do not have administrator permissions.

Hard requirement: this project requires a Discord account, a Discord bot token obtained from the Discord Developer Portal, and a test server where you have administrator permissions. There is no way around this — the bot cannot run without a real token and a server to connect to.

Agent Requirements
  • A Discord account — free at discord.com. You need a test server where you are the owner or have the Administrator permission. Create a new server if you do not have one.
  • Node.js 18 or higher — discord.js 14.26.4 requires Node.js ≥18. Verify with node --version. Download from nodejs.org if needed.
  • npm (bundled with Node.js) and basic comfort running commands in a terminal.
  • TypeScript fundamentals: types, interfaces, async/await, and ES module imports. Completing a beginner TypeScript tutorial before this project is strongly recommended.
  • Basic Discord concepts: servers (guilds), channels, roles, and permissions. Understanding the role hierarchy matters for Phase 4.
  • No prior discord.js or bot development experience required — this project teaches the full API from application registration to a working moderation system.

Create the Bot in the Developer Portal and Get Online
Register a Discord application, create a bot user, copy the token, enable the two privileged intents discord.js needs, generate an invite URL, and write the minimal TypeScript that connects to Discord and logs "Logged in as BotName#0000" to your console.
  1. Create a Discord application. Go to discord.com/developers/applications and click New Application. Name it anything (e.g. "SecurityBot"). This is the application container — the bot user lives inside it.
  2. Add a bot user. In the left sidebar choose Bot, then click Add Bot and confirm. Discord creates a bot user attached to your application. Under the bot's username you will see a Reset Token button. Click it, confirm, then immediately copy the token that appears. Store it somewhere safe — you will not be able to see it again.
  3. Enable the two privileged intents. Still on the Bot page, scroll down to the Privileged Gateway Intents section. Enable both:
    • Server Members Intent — required to receive join/leave events and member data
    • Message Content Intent — required for your bot to read the text of messages
    Why this is the #1 beginner wall: if you enable these intents in code but not in the Developer Portal, Discord silently ignores the intent. You will receive member events and message events but with empty member data and empty message content. Nothing will throw an error — things just will not work. Enable them in BOTH places: the Portal and in the intents array in your code (step 8 below).
  4. Generate the OAuth2 invite URL. In the left sidebar click OAuth2, then URL Generator. Under Scopes check bot and applications.commands (slash commands require the second scope). Under Bot Permissions check: Kick Members, Moderate Members (timeout), Manage Messages, View Audit Log, Send Messages, Embed Links, Read Message History. Copy the generated URL from the bottom of the page.
  5. Invite the bot to your test server. Open the invite URL in a browser. Select your test server from the dropdown. Confirm the permissions. The bot will appear in the server member list as offline until you run it.
  6. Set up the TypeScript project. In a terminal, create a project folder and initialize it:
    mkdir security-bot cd security-bot npm init -y npm install discord.js better-sqlite3 dotenv npm install --save-dev typescript @types/node @types/better-sqlite3 tsx
    Package versions used in this project: discord.js 14.26.4 (requires Node.js ≥18), better-sqlite3 for synchronous SQLite queries, dotenv to load the token from a .env file, tsx to run TypeScript directly without a compile step.
  7. Create tsconfig.json. In the project root create this file:
    { "compilerOptions": { "target": "ES2022", "module": "NodeNext", "moduleResolution": "NodeNext", "strict": true, "esModuleInterop": true, "skipLibCheck": true, "outDir": "./dist" }, "include": ["src/**/*"] }
  8. Create .env in the project root. Replace the placeholder with your real token from step 2. Add your test server's ID (right-click the server icon in Discord → Copy Server ID — Developer Mode must be on under User Settings → Advanced):
    DISCORD_TOKEN=your-bot-token-here GUILD_ID=your-test-server-id-here CLIENT_ID=your-application-client-id-here
    Never commit .env to git. Add it to .gitignore immediately: echo ".env" >> .gitignore. Your bot token is equivalent to a password. Anyone who obtains it can control your bot and potentially cause harm in any server it is in. If a token is ever exposed, go back to the Bot page in the Developer Portal and click Reset Token to invalidate it.
  9. Create src/index.ts with the minimal bot that connects to Discord:
    import 'dotenv/config'; import { Client, GatewayIntentBits, Partials, Events, } from 'discord.js'; const client = new Client({ intents: [ GatewayIntentBits.Guilds, GatewayIntentBits.GuildMembers, // privileged GatewayIntentBits.GuildMessages, GatewayIntentBits.MessageContent, // privileged ], partials: [Partials.Message, Partials.Channel, Partials.GuildMember], }); client.once(Events.ClientReady, (readyClient) => { console.log(`Logged in as ${readyClient.user.tag}`); console.log(`Serving ${readyClient.guilds.cache.size} guild(s)`); }); const token = process.env.DISCORD_TOKEN; if (!token) throw new Error('DISCORD_TOKEN not set in .env'); client.login(token);
  10. Run the bot. In your terminal:
    npx tsx src/index.ts
    In the Discord server member list, the bot should switch from offline to online.
Error: TOKEN_INVALID
  • You copied the Client ID instead of the bot Token. The Token is on the Bot page; the Client ID is on the General Information page. They are different values.
  • The token in .env has extra spaces or line breaks. Open the file and confirm the token is on one line with no trailing whitespace.
  • You reset the token after copying it. Tokens are invalidated the moment you click Reset Token again. Copy the new one and update .env.

The terminal prints Logged in as YourBotName#0000 and Serving 1 guild(s). The bot appears online (green dot) in your test server's member list. No errors are thrown. The .env file exists, is not committed to git, and contains a real token.

Event Monitoring and the Audit-Log Channel
Register listeners for security-relevant guild events and route all of them to a designated #mod-log channel as formatted embeds. This is the passive monitoring layer — it records what is happening in the server without taking action.
  1. Create a #mod-log channel in your test server. In Discord, create a text channel named exactly mod-log. Your bot needs Send Messages and Embed Links permissions in this channel. The bot's role must be positioned above the @everyone role in the server's role list to manage those permissions later.
  2. Create src/modlog.ts — a helper that finds the mod-log channel and posts an embed:
    import { Client, EmbedBuilder, TextChannel } from 'discord.js'; const MOD_LOG_NAME = 'mod-log'; export async function postModLog( client: Client, guildId: string, embed: EmbedBuilder, ): Promise<void> { const guild = client.guilds.cache.get(guildId); if (!guild) return; const channel = guild.channels.cache.find( (ch) => ch.name === MOD_LOG_NAME && ch.isTextBased(), ) as TextChannel | undefined; if (!channel) { console.warn(`[ModLog] No #${MOD_LOG_NAME} channel found in guild ${guildId}`); return; } await channel.send({ embeds: [embed] }); }
  3. Add event listeners in src/index.ts. Import postModLog at the top and add these listeners after your existing handlers:
    import { postModLog } from './modlog.js'; // Member joins client.on(Events.GuildMemberAdd, async (member) => { const embed = new EmbedBuilder() .setColor(0x22c55e) .setTitle('Member Joined') .setDescription(`<@${member.id}> joined the server`) .addFields( { name: 'Account Created', value: member.user.createdAt.toUTCString(), inline: true }, { name: 'User ID', value: member.id, inline: true }, ) .setThumbnail(member.user.displayAvatarURL()) .setTimestamp(); await postModLog(client, member.guild.id, embed); }); // Member leaves client.on(Events.GuildMemberRemove, async (member) => { const embed = new EmbedBuilder() .setColor(0xf59e0b) .setTitle('Member Left') .setDescription(`${member.user.tag} left the server`) .addFields({ name: 'User ID', value: member.id, inline: true }) .setTimestamp(); await postModLog(client, member.guild.id, embed); }); // Messages deleted client.on(Events.MessageDelete, async (message) => { if (!message.guild || !message.author) return; if (message.author.bot) return; const embed = new EmbedBuilder() .setColor(0xef4444) .setTitle('Message Deleted') .setDescription(`Message by <@${message.author.id}> in <#${message.channelId}> was deleted`) .addFields( { name: 'Content', value: message.content?.slice(0, 1024) || '(no content cached)' }, ) .setTimestamp(); await postModLog(client, message.guild.id, embed); }); // Keyword filter on incoming messages const BLOCKED_KEYWORDS = ['badword1', 'badword2', 'http://discord.gift']; client.on(Events.MessageCreate, async (message) => { if (!message.guild || message.author.bot) return; const lower = message.content.toLowerCase(); const matched = BLOCKED_KEYWORDS.find((kw) => lower.includes(kw)); if (!matched) return; // Delete the offending message try { await message.delete(); } catch { /* already deleted */ } const embed = new EmbedBuilder() .setColor(0xdc2626) .setTitle('Keyword Filter Triggered') .setDescription(`Message from <@${message.author.id}> in <#${message.channelId}> deleted`) .addFields( { name: 'Matched Keyword', value: matched }, { name: 'User ID', value: message.author.id, inline: true }, ) .setTimestamp(); await postModLog(client, message.guild.id, embed); });

Test the keyword filter by sending a message containing one of the blocked keywords — the message should be deleted and an embed should appear in mod-log.
Bot cannot delete messages / "Missing Permissions"
  • The bot's role must have the Manage Messages permission. Go to Server Settings → Roles → find the bot's role → enable Manage Messages.
  • Message Content Intent is enabled in the Portal but not in code, or vice versa — the lower string will be empty for every message and no keyword will ever match. Recheck Phase 1 step 3 and step 8.
  • message.content is empty even though the intent is enabled: certain system messages (join notifications, etc.) have no content field by design. Only user-typed messages have content.
  • The keyword list entries use uppercase — the filter lowercases the message but not the keyword array. Ensure all entries in BLOCKED_KEYWORDS are lowercase.

Moderation Commands with Permission Checks
Implement /warn, /kick, and /timeout with full permission validation. Each command checks that the invoker has the required permission, that the bot has the required permission, and that the bot's role is above the target's highest role in the hierarchy — without that last check, Discord will reject the action.
  1. Set your bot's role above members in the role hierarchy. In Discord: Server Settings → Roles. Drag the bot's role above the @everyone role and any member roles you want to moderate. Discord enforces this server-side — a bot cannot kick or timeout members whose highest role is equal to or above the bot's highest role, regardless of permissions.
  2. Create src/moderation.ts with the three command handlers:
    import { ChatInputCommandInteraction, EmbedBuilder, GuildMember, PermissionFlagsBits, } from 'discord.js'; import { postModLog } from './modlog.js'; import { addWarning, getWarnings, type Warning } from './database.js'; // Helper: reply with an error embed and return async function replyError( interaction: ChatInputCommandInteraction, message: string, ): Promise<void> { await interaction.reply({ embeds: [new EmbedBuilder().setColor(0xef4444).setDescription(message)], ephemeral: true, }); } // Helper: resolve the target GuildMember or error out async function resolveMember( interaction: ChatInputCommandInteraction, optionName: string, ): Promise<GuildMember | null> { const user = interaction.options.getUser(optionName, true); const member = await interaction.guild!.members.fetch(user.id).catch(() => null); if (!member) { await replyError(interaction, 'Could not find that member in the server.'); return null; } return member; } export async function handleWarn(interaction: ChatInputCommandInteraction): Promise<void> { if (!interaction.memberPermissions?.has(PermissionFlagsBits.ModerateMembers)) { return replyError(interaction, 'You need the Moderate Members permission to warn users.'); } const target = await resolveMember(interaction, 'member'); if (!target) return; const reason = interaction.options.getString('reason', true); addWarning(target.id, interaction.user.id, reason, interaction.guildId!); const warnings = getWarnings(target.id, interaction.guildId!); const count = warnings.length; const embed = new EmbedBuilder() .setColor(0xf59e0b) .setTitle('Warning Issued') .addFields( { name: 'Member', value: `<@${target.id}>`, inline: true }, { name: 'Moderator', value: `<@${interaction.user.id}>`, inline: true }, { name: 'Total Warnings', value: `${count}`, inline: true }, { name: 'Reason', value: reason }, ) .setTimestamp(); await interaction.reply({ embeds: [embed] }); await postModLog(interaction.client, interaction.guildId!, embed); // Auto-escalation: 3 warnings -> 1-hour timeout; 5 warnings -> kick if (count >= 5) { // Guard first: a kick only works if the bot's role is above the target's. Report instead of failing silently. if (target.kickable) { try { await target.kick(`Auto-kick: ${count} warnings accumulated`); const kickEmbed = new EmbedBuilder() .setColor(0xdc2626) .setTitle('Auto-Kick Triggered') .setDescription(`<@${target.id}> was auto-kicked after reaching ${count} warnings.`) .setTimestamp(); await postModLog(interaction.client, interaction.guildId!, kickEmbed); } catch (err) { console.error('[AutoKick]', err); } } else { // Bot lacks the role hierarchy to kick this member — surface it to the mod-log rather than swallowing it const skipEmbed = new EmbedBuilder() .setColor(0xf59e0b) .setTitle('Auto-Kick Skipped') .setDescription(`<@${target.id}> hit ${count} warnings but could not be auto-kicked — move the bot's role above the member's highest role.`) .setTimestamp(); await postModLog(interaction.client, interaction.guildId!, skipEmbed); } } else if (count >= 3) { // Same hierarchy guard for timeout (member.moderatable) if (target.moderatable) { try { await target.timeout(60 * 60 * 1000, `Auto-timeout: ${count} warnings`); const timeoutEmbed = new EmbedBuilder() .setColor(0xf97316) .setTitle('Auto-Timeout Triggered') .setDescription(`<@${target.id}> was auto-timed-out (1 hour) after reaching ${count} warnings.`) .setTimestamp(); await postModLog(interaction.client, interaction.guildId!, timeoutEmbed); } catch (err) { console.error('[AutoTimeout]', err); } } else { // Bot lacks the role hierarchy to time out this member — surface it to the mod-log const skipEmbed = new EmbedBuilder() .setColor(0xf59e0b) .setTitle('Auto-Timeout Skipped') .setDescription(`<@${target.id}> hit ${count} warnings but could not be auto-timed-out — move the bot's role above the member's highest role.`) .setTimestamp(); await postModLog(interaction.client, interaction.guildId!, skipEmbed); } } } export async function handleKick(interaction: ChatInputCommandInteraction): Promise<void> { if (!interaction.memberPermissions?.has(PermissionFlagsBits.KickMembers)) { return replyError(interaction, 'You need the Kick Members permission to use this command.'); } if (!interaction.guild?.members.me?.permissions.has(PermissionFlagsBits.KickMembers)) { return replyError(interaction, 'The bot is missing the Kick Members permission.'); } const target = await resolveMember(interaction, 'member'); if (!target) return; const reason = interaction.options.getString('reason') ?? 'No reason provided'; if (!target.kickable) { return replyError( interaction, 'Cannot kick this member. Their role may be equal to or above the bot\'s role in the hierarchy.', ); } await target.kick(reason); const embed = new EmbedBuilder() .setColor(0xdc2626) .setTitle('Member Kicked') .addFields( { name: 'Member', value: target.user.tag, inline: true }, { name: 'Moderator', value: `<@${interaction.user.id}>`, inline: true }, { name: 'Reason', value: reason }, ) .setTimestamp(); await interaction.reply({ embeds: [embed] }); await postModLog(interaction.client, interaction.guildId!, embed); } export async function handleTimeout(interaction: ChatInputCommandInteraction): Promise<void> { if (!interaction.memberPermissions?.has(PermissionFlagsBits.ModerateMembers)) { return replyError(interaction, 'You need the Moderate Members permission to use this command.'); } if (!interaction.guild?.members.me?.permissions.has(PermissionFlagsBits.ModerateMembers)) { return replyError(interaction, 'The bot is missing the Moderate Members permission.'); } const target = await resolveMember(interaction, 'member'); if (!target) return; const minutes = interaction.options.getInteger('minutes', true); const reason = interaction.options.getString('reason') ?? 'No reason provided'; if (!target.moderatable) { return replyError( interaction, 'Cannot timeout this member. Their role may be equal to or above the bot\'s role in the hierarchy.', ); } await target.timeout(minutes * 60 * 1000, reason); const embed = new EmbedBuilder() .setColor(0xf97316) .setTitle('Member Timed Out') .addFields( { name: 'Member', value: `<@${target.id}>`, inline: true }, { name: 'Duration', value: `${minutes} minute(s)`, inline: true }, { name: 'Moderator', value: `<@${interaction.user.id}>`, inline: true }, { name: 'Reason', value: reason }, ) .setTimestamp(); await interaction.reply({ embeds: [embed] }); await postModLog(interaction.client, interaction.guildId!, embed); }
  3. Wire the handlers into the interaction router in src/index.ts. Replace the placeholder else branch with real dispatching. At the top of the file add:
    import { handleWarn, handleKick, handleTimeout } from './moderation.js';
    Then inside the Events.InteractionCreate listener, after the /status block:
    if (cmd === 'warn') { await handleWarn(interaction); return; } if (cmd === 'kick') { await handleKick(interaction); return; } if (cmd === 'timeout') { await handleTimeout(interaction); return; }
  4. Test each command. Restart the bot. In your test server, create a second account (Discord allows you to test with a friend or an alt account). As the server owner:
    • Run /warn member:<alt> reason:Test warning three times. The third warn should auto-trigger a one-hour timeout on the alt account.
    • Run /kick member:<alt> reason:Testing kick command and confirm the alt is removed from the server.
    • Run /timeout member:<alt> minutes:5 reason:Testing timeout and confirm the alt cannot send messages for 5 minutes.
Unknown Member or Missing Permissions errors
  • member.kickable returns false: the target's highest role is at or above the bot's role in the Server Settings → Roles list. Drag the bot's role higher.
  • member.moderatable returns false: same cause. The timeout (Moderate Members) permission also requires the bot to be above the target in the role hierarchy — the permission alone is not sufficient.
  • Trying to kick/timeout the server owner: Discord does not allow any action against the server owner regardless of permissions. Test with a member account, not the owner.
  • DiscordAPIError[50013]: Missing Permissions: the bot's role has the permission checked in the Bot Permissions list in your invite URL, but that permission was not actually granted when inviting. Kick the bot from the server, regenerate the invite URL with the correct permissions, and re-invite.
Checkpoint — what you should see
Running /warn three times on the same member auto-triggers a visible timeout — the member gets a yellow clock icon in Discord indicating they are timed out. Running /kick removes the member from the server. Running /timeout applies a timed communication restriction. All three actions post an embed to #mod-log with moderator, target, and reason fields. Commands issued by users without the required permission receive an ephemeral error embed rather than executing.

SQLite Audit Trail and the /audit Command
Wire up a SQLite database using better-sqlite3 to persist every warning, kick, and timeout across restarts. Implement /audit so moderators can query the full infraction history of any member. Because better-sqlite3 is synchronous, database calls are fast and simple — no Promises needed.
  1. Create src/database.ts — the schema, insert, and query functions:
    import Database from 'better-sqlite3'; import path from 'node:path'; import { fileURLToPath } from 'node:url'; const __dirname = path.dirname(fileURLToPath(import.meta.url)); const DB_PATH = path.join(__dirname, '..', 'moderation.db'); export const db = new Database(DB_PATH); // Create tables on first run (idempotent) db.exec(` CREATE TABLE IF NOT EXISTS warnings ( id INTEGER PRIMARY KEY AUTOINCREMENT, user_id TEXT NOT NULL, moderator TEXT NOT NULL, reason TEXT NOT NULL, guild_id TEXT NOT NULL, timestamp INTEGER NOT NULL DEFAULT (unixepoch()) ); CREATE TABLE IF NOT EXISTS audit_log ( id INTEGER PRIMARY KEY AUTOINCREMENT, action TEXT NOT NULL, actor_id TEXT NOT NULL, target_id TEXT NOT NULL, reason TEXT, guild_id TEXT NOT NULL, timestamp INTEGER NOT NULL DEFAULT (unixepoch()) ); CREATE INDEX IF NOT EXISTS idx_warnings_user ON warnings (user_id, guild_id); CREATE INDEX IF NOT EXISTS idx_audit_target ON audit_log (target_id, guild_id); `); export interface Warning { id: number; user_id: string; moderator: string; reason: string; guild_id: string; timestamp: number; } const stmtInsertWarning = db.prepare( `INSERT INTO warnings (user_id, moderator, reason, guild_id) VALUES (?, ?, ?, ?)`, ); const stmtGetWarnings = db.prepare( `SELECT * FROM warnings WHERE user_id = ? AND guild_id = ? ORDER BY timestamp ASC`, ); const stmtInsertAudit = db.prepare( `INSERT INTO audit_log (action, actor_id, target_id, reason, guild_id) VALUES (?, ?, ?, ?, ?)`, ); const stmtGetAudit = db.prepare( `SELECT * FROM audit_log WHERE target_id = ? AND guild_id = ? better-sqlite3 fails to install or load on Windows
  • better-sqlite3 is a native Node.js addon and requires build tools. On Windows, install Visual Studio Build Tools 2022 with the "Desktop development with C++" workload (or re-run the official Node.js installer and tick "Automatically install the necessary tools"), then re-run npm install. (The old windows-build-tools npm package is deprecated — do not use it.) On macOS run xcode-select --install; on Debian/Ubuntu sudo apt-get install -y build-essential python3.
  • On macOS, install Xcode Command Line Tools: xcode-select --install.
  • On Linux, install build-essential: sudo apt-get install -y build-essential python3.
  • If the Node.js version changed after installing the package, the prebuilt binary may be mismatched. Run npm rebuild better-sqlite3 to recompile it for the current Node.js version.
Rate limits from Discord
  • Discord rate limits bot API calls per route. If you send many mod-log embeds in rapid succession (e.g. during testing with a fast script), you may see DiscordAPIError[429]: You are being rate limited. discord.js's REST client handles rate limits automatically with a queue — slow down your test rate and the bot will recover without changes to code.
  • Slash commands themselves have a per-user rate limit of roughly 5 per second in a guild. Space out test commands by a second or two.
Checkpoint — what you should see
Running /audit member:<any member who has been warned> returns an ephemeral embed listing all warnings with reasons, moderator tags, and timestamps, plus an action history section showing every WARN, KICK, and TIMEOUT action taken against that member. Stopping and restarting the bot does not clear the data — the moderation.db file persists on disk and all history is present after restart. The database file exists at the project root and grows in size as actions accumulate.
