Subject

Build an RFID Access Controller

Operative 90 min 500 XP
Mission Brief

This operation builds a physical access control system — a hardware security checkpoint that authenticates users through RFID badge scanning and a keypad PIN before rotating a servo-driven lock mechanism open. The Arduino Mega 2560 orchestrates the full authentication flow: an RC522 RFID reader scans proximity cards and fobs over SPI, comparing UIDs against an authorized list stored in EEPROM; a 4x4 membrane keypad provides a secondary PIN so that both factors must pass; and an SG90 servo simulates a door bolt, rotating to 90° on success and returning to 0° after five seconds.

You do not need to own any hardware to complete this project. Wokwi (wokwi.com) is a free browser-based Arduino simulator that supports all three components — the board-mfrc522 RFID reader, the wokwi-membrane-keypad, and the wokwi-servo — and provides six built-in card presets you can tap to simulate badge scans. The physical kit path (Arduino Mega + RC522 + 4x4 keypad + SG90 servo + jumpers, total under $20) is fully documented alongside Wokwi at every step. Both paths produce identical Serial Monitor output and are observable without any extra software.

Security framing: this is an educational access controller. Authenticating on the card UID alone is not strong security — UIDs are factory-set identifiers that can be read and cloned with inexpensive tools. Real access-control systems authenticate against the card's cryptographic secure element, not just its UID. This project teaches you the fundamentals of two-factor physical security (something you have + something you know) and the programming patterns used in commercial badge readers, not a production-ready deployment.

Agent Requirements
  • Path A (no hardware) — a modern web browser. Go to wokwi.com, create a free account, and start a new Arduino Mega project. All three components used here (RC522, 4x4 keypad, SG90 servo) are built into the Wokwi parts library. No install needed.
  • Path B (physical kit) — Arduino Mega 2560 or compatible (Uno SPI pins differ; the pin mapping in each phase notes both). Connect via USB to a computer running Arduino IDE 2.x.
  • Path B — RC522 RFID reader module (~$2) with at least one MIFARE card or key fob. Most "ELEGOO Mega starter kits" include this. Power it at 3.3 V only — see the voltage warning in Phase 1.
  • Path B — 4x4 membrane keypad (~$3) with an 8-pin ribbon connector. The Keypad library by Mark Stanley and Alexander Brevig handles the matrix scanning.
  • Path B — SG90 micro servo (~$3) and a breadboard with jumper wires.
  • Arduino IDE 2.x with three libraries installed via Library Manager: MFRC522 (v1.4.12) by Miguel Balboa (the miguelbalboa/rfid library; the Library Manager may list the author as GithubCommunity or Miguel Balboa), Keypad by Mark Stanley (v3.1.1), and Servo (built into the Arduino IDE — no separate install).
  • Basic comfort reading code line by line. You do not need prior Arduino experience — every sketch is complete and paste-ready.

Toolchain Setup, Wiring the RC522, and Reading a Card UID
Install the libraries, wire the RC522 RFID reader to the Arduino, and confirm the reader works by printing a raw card UID to the Serial Monitor. This is the proof-of-life step — nothing else builds until this works.
3.3 V WARNING — read before wiring. The RC522 module's VCC pin accepts 3.3 V only. Connecting it to the Arduino's 5 V pin permanently destroys the module. The Arduino Mega has a dedicated 3.3 V pin (labeled "3V3") next to the power headers — use that pin, not 5 V. The SPI signal lines (MOSI, MISO, SCK, SDA/SS, RST) run at 3.3 V logic from the RC522 but the Mega's digital pins output 5 V. In practice the RC522's inputs tolerate 5 V signal lines and most builds work without a level shifter; however, adding a simple voltage divider or logic-level converter on each data line is the strictly correct approach and extends module longevity. In Wokwi the simulator handles this transparently.
  1. Install the MFRC522 library. In Arduino IDE 2.x, open the Library Manager (Ctrl+Shift+I on Windows/Linux, Cmd+Shift+I on Mac). Search for MFRC522 and install the library by Miguel Balboa (the miguelbalboa/rfid library; the Library Manager may list the author as GithubCommunity or Miguel Balboa) version 1.4.12. Then search for Keypad and install Keypad by Mark Stanley version 3.1.1. The Servo library is built into the IDE — no action needed.
    Wokwi path: libraries are pre-loaded in the simulator. Click the library icon in the left sidebar to verify MFRC522 and Keypad appear. No install step needed.
  2. Wire the RC522 to the Arduino Mega. Use the table below. All connections use short jumper wires; the order does not matter as long as each signal lands on the correct pin.
    RC522 Pin → Arduino Mega Pin --------- ----------------- VCC → 3.3V (NOT 5V -- see warning above) GND → GND RST → D5 SDA (SS) → D53 (hardware SPI chip-select on Mega) MOSI → D51 (hardware SPI MOSI on Mega) MISO → D50 (hardware SPI MISO on Mega) SCK → D52 (hardware SPI clock on Mega) Uno/Nano alternative SPI pins (if using Uno instead of Mega): SDA (SS) → D10 MOSI → D11 MISO → D12 SCK → D13
    Wokwi path: add the board-mfrc522 part from the parts panel. Wokwi shows the same 7-pin layout. Wire SDA→D53, SCK→D52, MOSI→D51, MISO→D50, RST→D5, VCC→3V3, GND→GND in the diagram editor. The simulator ignores the voltage issue but use 3V3 anyway to match real hardware habits.

    Wokwi card presets — important: use Cards 1–4 or the Key Fob (Card 6). Card 5 (labeled "NFC Tag") has a 7-byte UID; the sketches in this project reject any UID that is not exactly 4 bytes, so Card 5 will always be denied.
  3. Upload the UID-reader sketch. Create a new sketch, paste the code below, and upload to the Mega (or click Run in Wokwi). Open the Serial Monitor at 9600 baud.
    /* Phase 1 -- RC522 UID Reader Prints the UID of any scanned card to Serial Monitor. Libraries: MFRC522 v1.4.12 by Miguel Balboa (miguelbalboa/rfid) */ #include <SPI.h> #include <MFRC522.h> #define SS_PIN 53 // Mega SPI chip-select (D10 on Uno) #define RST_PIN 5 // Reset pin MFRC522 mfrc522(SS_PIN, RST_PIN); void setup() { Serial.begin(9600); SPI.begin(); mfrc522.PCD_Init(); Serial.println(F("RC522 ready. Hold a card near the reader...")); Serial.println(F("-------------------------------------------")); } void loop() { // Wait for a new card if (!mfrc522.PICC_IsNewCardPresent()) return; if (!mfrc522.PICC_ReadCardSerial()) return; // Print UID bytes Serial.print(F("Card UID: ")); for (byte i = 0; i < mfrc522.uid.size; i++) { if (mfrc522.uid.uidByte[i] < 0x10) Serial.print(F("0")); Serial.print(mfrc522.uid.uidByte[i], HEX); if (i < mfrc522.uid.size - 1) Serial.print(F(" ")); } Serial.println(); // Halt the card so it is not read again immediately mfrc522.PICC_HaltA(); delay(1000); }
  4. Scan a card and record the UID. Hold the MIFARE card near the RC522 antenna (the large square coil on the module face). In Wokwi, click one of the six built-in preset cards in the MFRC522 component panel.
    Wokwi card presets: Wokwi provides six simulated cards labeled Card 1 through Card 6. Each has a distinct UID. Click any card label in the component's property panel to simulate a scan. The Serial Monitor updates instantly.
Nothing prints to Serial Monitor?
  • Confirm baud rate is set to 9600 in the Serial Monitor dropdown.
  • Re-check the VCC wire: if you accidentally used 5V, the module may be dead. Swap to 3V3 and try a replacement module.
  • "SPI initialization failed" or the loop never prints: the most common cause is SDA/SS wired to the wrong pin. On the Mega, SS is D53, not D10. Verify with a multimeter continuity check from the SDA pin on the module to D53 on the board.
  • The card does not read: hold it flat against the antenna coil, within 1-3 cm. Key fobs read up to ~5 cm; cards read up to ~3 cm. At an angle or too far away, reads fail silently.
  • Wokwi: confirm the wiring diagram has no red "unconnected" warnings. Click the MFRC522 component and then a preset card in the right-side panel.
Checkpoint — what you should see
The Serial Monitor prints one line per scan, for example: Card UID: A1 B2 C3 D4. Each time you present a different card or fob (or click a different Wokwi preset), a distinct UID appears. Write down at least one UID — you will paste it into the authorized list in Phase 2.

Authorized UID List — Accept and Deny on Scan
Add an in-memory authorized UID list and a comparison function. The Serial Monitor now prints ACCESS GRANTED for known cards and ACCESS DENIED for unknown ones. No keypad or servo yet — just clean accept/deny logic.
  1. Get your authorized UIDs. From Phase 1 you recorded the UID of at least one card. You will hardcode it into the sketch. Use the exact hex bytes printed by the Phase 1 sketch, for example A1 B2 C3 D4. In Wokwi you can use the UID of any preset card — hover the preset to see its four bytes.
    Wokwi card selection: use Cards 1–4 or the Key Fob (Card 6) — Card 5 (NFC Tag) has a 7-byte UID that these sketches don’t handle, so it will always be denied.
  2. Paste and upload the sketch below. Replace the bytes in authorizedUIDs[0] with the UID you recorded. Add more rows for additional cards.
    /* Phase 2 -- Authorized UID List Scans a card and accepts or denies it against a stored list. Libraries: MFRC522 v1.4.12 */ #include <SPI.h> #include <MFRC522.h> #define SS_PIN 53 #define RST_PIN 5 MFRC522 mfrc522(SS_PIN, RST_PIN); // ── Authorized UID list ────────────────────────────────────── // Each row is one card: {byte0, byte1, byte2, byte3} // Replace with the UIDs printed by Phase 1. const byte NUM_AUTHORIZED = 2; byte authorizedUIDs[NUM_AUTHORIZED][4] = { {0xA1, 0xB2, 0xC3, 0xD4}, // Card 1 -- replace with your UID {0xF0, 0x1E, 0x2A, 0x3B} // Card 2 -- optional second card }; // Returns true if scannedUID matches any entry in authorizedUIDs bool isAuthorized(byte *uid, byte uidSize) { if (uidSize != 4) return false; // only 4-byte UIDs handled here for (byte i = 0; i < NUM_AUTHORIZED; i++) { bool match = true; for (byte b = 0; b < 4; b++) { if (uid[b] != authorizedUIDs[i][b]) { match = false; break; } } if (match) return true; } return false; } void printUID(byte *uid, byte size) { for (byte i = 0; i < size; i++) { if (uid[i] < 0x10) Serial.print(F("0")); Serial.print(uid[i], HEX); if (i < size - 1) Serial.print(F(" ")); } } void setup() { Serial.begin(9600); SPI.begin(); mfrc522.PCD_Init(); Serial.println(F("Access Controller ready. Scan a badge...")); } void loop() { if (!mfrc522.PICC_IsNewCardPresent()) return; if (!mfrc522.PICC_ReadCardSerial()) return; Serial.print(F("Scanned UID: ")); printUID(mfrc522.uid.uidByte, mfrc522.uid.size); Serial.println(); if (isAuthorized(mfrc522.uid.uidByte, mfrc522.uid.size)) { Serial.println(F(">> ACCESS GRANTED")); } else { Serial.println(F(">> ACCESS DENIED")); } mfrc522.PICC_HaltA(); delay(1500); }
  3. Test both paths. Scan the card whose UID you entered — expect ACCESS GRANTED. Scan any other card (or a different Wokwi preset) — expect ACCESS DENIED.
Every card shows ACCESS DENIED even for the one I entered?
  • The UID bytes must match exactly, including leading zeros. If Phase 1 printed 04 A3 2F B1, the array entry is {0x04, 0xA3, 0x2F, 0xB1}. A common mistake is omitting the leading zero: 0x4 is not the same as 0x04 in a byte comparison.
  • Some MIFARE Ultralight and NTAG cards use 7-byte UIDs. The sketch above only handles 4-byte UIDs (if (uidSize != 4) return false). If your card uses 7 bytes, change the array width to 7 and remove that guard, or swap to a standard MIFARE Classic 1K card (the white cards in most starter kits).
Checkpoint — what you should see
Scanning the authorized card prints >> ACCESS GRANTED. Scanning any other card or Wokwi preset prints >> ACCESS DENIED. The UID prints on the line above the result in both cases.

Add the 4x4 Keypad — Read and Echo a PIN
Wire the membrane keypad and confirm it reads key presses correctly. The sketch echoes each digit to Serial Monitor and prints the full PIN when # is pressed, or clears the buffer when * is pressed. Authentication logic is not connected yet — proving the keypad works first avoids debugging two systems at once.
  1. Wire the keypad to the Arduino Mega. The 4x4 membrane keypad has an 8-pin ribbon connector. Wire row pins to digital I/O and column pins to separate digital I/O. Use the mapping below, which matches the sketch.
    Keypad Pin Connector label → Arduino Mega Pin ---------- --------------- ---------------- Pin 1 Row 1 (top) → D22 Pin 2 Row 2 → D23 Pin 3 Row 3 → D24 Pin 4 Row 4 (bottom) → D25 Pin 5 Col 1 (left) → D26 Pin 6 Col 2 → D27 Pin 7 Col 3 → D28 Pin 8 Col 4 (right) → D29
    Wokwi path: add the wokwi-membrane-keypad part. In the diagram editor, connect R1→D22, R2→D23, R3→D24, R4→D25, C1→D26, C2→D27, C3→D28, C4→D29. In Wokwi, after clicking the keypad component to focus it, keyboard keys 0-9, A-D, #, and * activate the corresponding pad buttons.
  2. Upload the keypad test sketch.
    /* Phase 3 -- Keypad PIN Reader Reads key presses from a 4x4 membrane keypad. # confirms the PIN, * clears it. Libraries: Keypad v3.1.1 by Mark Stanley */ #include <Keypad.h> const byte ROWS = 4; const byte COLS = 4; char keys[ROWS][COLS] = { {'1','2','3','A'}, {'4','5','6','B'}, {'7','8','9','C'}, {'*','0','#','D'} }; byte rowPins[ROWS] = {22, 23, 24, 25}; byte colPins[COLS] = {26, 27, 28, 29}; Keypad keypad = Keypad(makeKeymap(keys), rowPins, colPins, ROWS, COLS); const byte PIN_LENGTH = 4; char enteredPIN[PIN_LENGTH + 1]; // +1 for null terminator byte pinIndex = 0; void setup() { Serial.begin(9600); Serial.println(F("Keypad ready. Enter PIN then press #")); Serial.println(F("Press * to clear.")); } void loop() { char key = keypad.getKey(); if (!key) return; if (key == '*') { // Clear pinIndex = 0; memset(enteredPIN, 0, sizeof(enteredPIN)); Serial.println(F("[cleared]")); return; } if (key == '#') { // Confirm enteredPIN[pinIndex] = '\0'; Serial.print(F("PIN entered: ")); Serial.println(enteredPIN); pinIndex = 0; memset(enteredPIN, 0, sizeof(enteredPIN)); return; } // Digit or letter key if (pinIndex < PIN_LENGTH) { enteredPIN[pinIndex++] = key; Serial.print(F("*")); // echo asterisk, not the actual digit } }
  3. Test the keypad. Press four digit keys (e.g. 1, 2, 3, 4) and watch four asterisks print. Press # and see PIN entered: 1234. Press * at any point to clear the buffer.
No output when pressing keypad keys?
  • The most common cause is the row/column pin mapping being swapped or shifted by one. The ribbon connector on cheap keypads is not always pin-1 on the left — check the silk screen on your specific keypad. If pressing "1" prints "4", your rows are shifted; adjust the rowPins array. If pressing "1" prints "2", your columns are shifted; adjust colPins.
  • In Wokwi, confirm the keypad component is focused (click it once) before pressing keyboard keys. Wokwi requires focus on the component for keyboard input to route to it.
  • If multiple keys register per press (ghosting), add 10k pull-up resistors on each column line to 5V. Most membrane keypads work without them at low scan rates, but some require pull-ups.
Checkpoint — what you should see
Pressing four numeric keys prints four * characters in a row. Pressing # prints PIN entered: 1234 (or whatever digits you pressed). Pressing * prints [cleared] and the buffer resets. Every key press is observable without any hardware beyond the keypad and a Serial Monitor.

Two-Factor Authentication — Card AND PIN Drive the Servo Lock
Combine the RFID reader and keypad into a full two-factor authentication flow. A valid card scan starts a PIN prompt window. Entering the correct PIN drives the SG90 servo from 0° (locked) to 90° (unlocked) for five seconds, then re-locks. Any mismatch denies access immediately.
  1. Wire the SG90 servo. The SG90 has a 3-pin connector with a brown/red/orange wire order:
    Servo Wire Color → Arduino Mega Pin ----------- ------ ---------------- Ground Brown → GND Power Red → 5V (servo runs on 5V, unlike RC522) Signal Orange → D9 Note: powering a servo from the Arduino's 5V pin works for the SG90 in a no-load bench test. Under real mechanical load (spring-loaded bolt), draw spikes can brown-out the Arduino. Use a separate 5V supply sharing GND with the Arduino for a real door installation.
    Wokwi path: add the wokwi-servo part. Connect PWM→D9, V+→5V, GND→GND. The servo's horn animates in the simulator when servo.write() is called.
  2. Upload the two-factor sketch. Replace the UID in authorizedUIDs with your own card's UID from Phase 1. The default PIN is 1234 — change SECRET_PIN to any 4-digit string.
    /* Phase 4 -- Two-Factor Access Controller Card UID check + PIN check -> servo unlock. Libraries: MFRC522 v1.4.12, Keypad v3.1.1, Servo (built-in) */ #include <SPI.h> #include <MFRC522.h> #include <Keypad.h> #include <Servo.h> // ── Pin definitions ───────────────────────────────────────── #define SS_PIN 53 #define RST_PIN 5 #define SERVO_PIN 9 // ── Authorized UIDs ───────────────────────────────────────── const byte NUM_AUTHORIZED = 1; byte authorizedUIDs[NUM_AUTHORIZED][4] = { {0xA1, 0xB2, 0xC3, 0xD4} // replace with your card's UID }; // ── Secret PIN ────────────────────────────────────────────── const char SECRET_PIN[] = "1234"; // change to your desired PIN const byte PIN_LENGTH = 4; // ── Keypad layout ─────────────────────────────────────────── const byte ROWS = 4; const byte COLS = 4; char keys[ROWS][COLS] = { {'1','2','3','A'}, {'4','5','6','B'}, {'7','8','9','C'}, {'*','0','#','D'} }; byte rowPins[ROWS] = {22, 23, 24, 25}; byte colPins[COLS] = {26, 27, 28, 29}; MFRC522 mfrc522(SS_PIN, RST_PIN); Keypad keypad = Keypad(makeKeymap(keys), rowPins, colPins, ROWS, COLS); Servo lockServo; // ── State machine ──────────────────────────────────────────── enum State { WAIT_CARD, WAIT_PIN }; State state = WAIT_CARD; char enteredPIN[PIN_LENGTH + 1]; byte pinIndex = 0; unsigned long pinDeadline = 0; // millis() deadline for PIN entry const unsigned long PIN_TIMEOUT = 10000; // 10 seconds to enter PIN // ── Helpers ────────────────────────────────────────────────── bool isAuthorized(byte *uid, byte uidSize) { if (uidSize != 4) return false; for (byte i = 0; i < NUM_AUTHORIZED; i++) { bool match = true; for (byte b = 0; b < 4; b++) { if (uid[b] != authorizedUIDs[i][b]) { match = false; break; } } if (match) return true; } return false; } void unlock() { Serial.println(F("** ACCESS GRANTED -- unlocking for 5 seconds")); lockServo.write(90); // rotate to unlock position delay(5000); lockServo.write(0); // return to locked position Serial.println(F("** Re-locked.")); } void deny(const __FlashStringHelper *reason) { Serial.print(F("!! ACCESS DENIED: ")); Serial.println(reason); } void resetPIN() { pinIndex = 0; memset(enteredPIN, 0, sizeof(enteredPIN)); state = WAIT_CARD; } void setup() { Serial.begin(9600); SPI.begin(); mfrc522.PCD_Init(); lockServo.attach(SERVO_PIN); lockServo.write(0); // start locked Serial.println(F("=== Access Controller Online ===")); Serial.println(F("Scan your badge to begin.")); } void loop() { // ── State: waiting for RFID card ──────────────────────── if (state == WAIT_CARD) { if (!mfrc522.PICC_IsNewCardPresent()) return; if (!mfrc522.PICC_ReadCardSerial()) return; Serial.print(F("Badge scanned: ")); for (byte i = 0; i < mfrc522.uid.size; i++) { if (mfrc522.uid.uidByte[i] < 0x10) Serial.print(F("0")); Serial.print(mfrc522.uid.uidByte[i], HEX); if (i < mfrc522.uid.size - 1) Serial.print(F(" ")); } Serial.println(); if (isAuthorized(mfrc522.uid.uidByte, mfrc522.uid.size)) { Serial.println(F("Badge OK. Enter 4-digit PIN then press #")); state = WAIT_PIN; pinDeadline = millis() + PIN_TIMEOUT; } else { deny(F("badge not recognized")); } mfrc522.PICC_HaltA(); return; } // ── State: waiting for PIN on keypad ──────────────────── if (state == WAIT_PIN) { // Timeout check if (millis() > pinDeadline) { deny(F("PIN entry timed out")); resetPIN(); return; } char key = keypad.getKey(); if (!key) return; if (key == '*') { Serial.println(F("[PIN cleared -- rescan badge]")); resetPIN(); return; } if (key == '#') { enteredPIN[pinIndex] = '\0'; if (strcmp(enteredPIN, SECRET_PIN) == 0) { unlock(); } else { deny(F("wrong PIN")); } resetPIN(); return; } // Digit key if (pinIndex < PIN_LENGTH) { enteredPIN[pinIndex++] = key; Serial.print(F("*")); } } }
  3. Test the full flow. Scan the authorized card → see "Badge OK." Type your 4-digit PIN and press # → see "ACCESS GRANTED" and the servo horn rotates 90° (or animates in Wokwi). After five seconds it returns to 0°. Then test a wrong PIN → see "ACCESS DENIED: wrong PIN". Test an unauthorized card → see "ACCESS DENIED: badge not recognized".
Servo jitters or Arduino resets when servo moves?
  • This is a power brown-out. The SG90 can draw 500-700 mA during movement, which exceeds what a USB port can supply cleanly when also running the Arduino. Add a 100μF electrolytic capacitor across the servo's V+ and GND pins to smooth the spike. Or power the servo from a separate 5V USB charger with a shared GND wire.
  • In Wokwi the servo always animates smoothly regardless of power because simulation does not model current limits.
Servo goes to a random position on startup instead of 0°?
  • lockServo.attach(SERVO_PIN) must be called before lockServo.write(0). The sketch does this correctly, but if you move those lines around, attach always comes first.
  • Some SG90 clones have a slightly different center point. If 0° is not fully closed, try lockServo.write(10) for your locked position and adjust until the bolt sits flush.
Checkpoint — what you should see
(1) Unknown card prints !! ACCESS DENIED: badge not recognized and no PIN prompt appears. (2) Authorized card prints Badge OK. Enter 4-digit PIN then press #. (3) Correct PIN prints ** ACCESS GRANTED and the servo moves to 90° then returns to 0° five seconds later. (4) Wrong PIN prints !! ACCESS DENIED: wrong PIN and the servo does not move. (5) Ten seconds with no keypad input after a valid card scan prints !! ACCESS DENIED: PIN entry timed out.

Lockout After Failed Attempts & Access Logging
Add two production-grade features: a brute-force lockout (3 consecutive failures trigger a 30-second cooldown, during which all scans are rejected) and an access log to the Serial Monitor that records every authentication event with a timestamp in milliseconds. Optional: wire a green LED to D4 (granted) and a red LED to D7 (denied/locked) for visible status.
  1. Wire the optional LEDs (or skip and observe only via Serial Monitor).
    LED → Arduino Pin (add 220-ohm resistor in series) ---------- ----------- Green LED → D4 (ACCESS GRANTED indicator) Red LED → D7 (ACCESS DENIED / LOCKED OUT indicator)
    Wokwi path: add two wokwi-led parts, one green and one red. Connect through 220-ohm resistors to D4 and D7 respectively, with the other leg to GND.
  2. Upload the full sketch with lockout logic and logging. This extends Phase 4. Replace the UIDs and PIN with your own values.

memset(enteredPIN, 0, sizeof(enteredPIN)); state = WAIT_CARD; } void setup() { Serial.begin(9600); SPI.begin(); mfrc522.PCD_Init(); lockServo.attach(SERVO_PIN); lockServo.write(0); pinMode(LED_GREEN, OUTPUT); pinMode(LED_RED, OUTPUT); digitalWrite(LED_GREEN, LOW); digitalWrite(LED_RED, LOW); logEvent("BOOT", "Access controller online"); } void loop() { // ── Locked-out state ───────────────────────────────────── if (state == LOCKED_OUT) { if (millis() < lockoutEnd) { // Print countdown every second on hardware Serial static unsigned long lastPrint = 0; if (millis() - lastPrint >= 1000) { lastPrint = millis(); unsigned long remaining = (lockoutEnd - millis()) / 1000; Serial.print(F(" LOCKED OUT -- ")); Serial.print(remaining); Serial.println(F("s remaining")); } return; } // Lockout expired failCount = 0; state = WAIT_CARD; digitalWrite(LED_RED, LOW); logEvent("UNLOCKED", "lockout expired -- ready"); return; } // ── Waiting for RFID card ──────────────────────────────── if (state == WAIT_CARD) { if (!mfrc522.PICC_IsNewCardPresent()) return; if (!mfrc522.PICC_ReadCardSerial()) return; // Build UID string for logging char uidStr[15]; snprintf(uidStr, sizeof(uidStr), "%02X %02X %02X %02X", mfrc522.uid.uidByte[0], mfrc522.uid.uidByte[1], mfrc522.uid.uidByte[2], mfrc522.uid.uidByte[3]); logEvent("SCAN", uidStr); if (isAuthorized(mfrc522.uid.uidByte, mfrc522.uid.size)) { logEvent("BADGE_OK", "awaiting PIN"); Serial.println(F("Enter 4-digit PIN then press # (* to cancel)")); state = WAIT_PIN; pinDeadline = millis() + PIN_TIMEOUT; } else { denyAccess("badge not recognized"); } mfrc522.PICC_HaltA(); return; } // ── Waiting for PIN ────────────────────────────────────── if (state == WAIT_PIN) { if (millis() > pinDeadline) { denyAccess("PIN timed out"); resetPIN(); return; } char key = keypad.getKey(); if (!key) return; if (key == '*') { logEvent("CANCEL", "user cleared PIN"); resetPIN(); return; } if (key == '#') { enteredPIN[pinIndex] = '\0'; if (strcmp(enteredPIN, SECRET_PIN) == 0) { grantAccess(); } else { denyAccess("wrong PIN"); } resetPIN(); return; } if (pinIndex < PIN_LENGTH) { enteredPIN[pinIndex++] = key; Serial.print(F("*")); } } }
  3. Test the lockout. Enter a wrong PIN three times in a row. After the third denial the system enters lockout mode and prints a countdown to Serial Monitor. Scanning a card during lockout is ignored. After 30 seconds, the system resets automatically.
Lockout never triggers even after 3 wrong PINs?
  • The failure counter failCount only increments on a completed wrong PIN attempt (pressing # with the wrong PIN) or a timeout or an unknown badge scan. Pressing * to cancel does not count as a failure. Make sure you are pressing # after typing each wrong attempt.
  • A successful authentication resets failCount to zero. If you grant access between failed attempts, the count resets.
Checkpoint — what you should see
Each authentication event prints a timestamped log line, for example: [12345ms] SCAN -- A1 B2 C3 D4, [12900ms] DENIED -- wrong PIN. After three consecutive failures: [15000ms] LOCKOUT -- LOCKOUT for 30 s followed by countdown lines. The red LED (if wired) stays on during lockout. After 30 seconds the system prints [45000ms] UNLOCKED -- lockout expired -- ready and the LED turns off.

EEPROM Persistence, Security Caveats, and Extensions
Store the authorized UID list in EEPROM so it survives power cycles without recompiling. Then read the honest security analysis of what this build does and does not protect against, and choose extension challenges.
  1. Understand EEPROM on the Arduino Mega. The Mega has 4096 bytes of on-chip EEPROM that persists across power cycles and resets. You can store UIDs there so that you can add new cards without touching the sketch code. Each byte is written individually with EEPROM.write(address, value) and read with EEPROM.read(address). The EEPROM endurance is rated at 100,000 write cycles per byte; do not write inside loop() unconditionally or you will wear it out.
  2. Add EEPROM storage to the Phase 5 sketch. Insert these additions at the top and in setup(). The sketch writes UIDs to EEPROM once and reads them back on every boot.
    // Add to includes: #include <EEPROM.h> // EEPROM layout: // Byte 0: number of stored UIDs (0-10) // Bytes 1-4: UID 0, bytes 0-3 // Bytes 5-8: UID 1, bytes 0-3 // ... and so on (4 bytes per UID, up to 10 UIDs = 41 bytes total) const byte EEPROM_COUNT_ADDR = 0; const byte EEPROM_UID_START = 1; const byte MAX_STORED_UIDS = 10; // Call once in setup() to write UIDs into EEPROM (run only when adding cards) void writeUIDsToEEPROM() { EEPROM.write(EEPROM_COUNT_ADDR, NUM_AUTHORIZED); for (byte i = 0; i < NUM_AUTHORIZED; i++) { for (byte b = 0; b < 4; b++) { EEPROM.write(EEPROM_UID_START + i * 4 + b, authorizedUIDs[i][b]); } } Serial.println(F("UIDs written to EEPROM.")); } // Call in setup() to load UIDs from EEPROM into RAM byte storedCount = 0; byte storedUIDs[MAX_STORED_UIDS][4]; void loadUIDsFromEEPROM() { storedCount = EEPROM.read(EEPROM_COUNT_ADDR); if (storedCount == 0xFF || storedCount > MAX_STORED_UIDS) { storedCount = 0; // EEPROM uninitialized (all 0xFF on fresh chip) Serial.println(F("EEPROM empty -- no UIDs loaded.")); return; } for (byte i = 0; i < storedCount; i++) { for (byte b = 0; b < 4; b++) { storedUIDs[i][b] = EEPROM.read(EEPROM_UID_START + i * 4 + b); } } Serial.print(F("Loaded ")); Serial.print(storedCount); Serial.println(F(" UID(s) from EEPROM.")); } // Use storedUIDs instead of authorizedUIDs in isAuthorized(): bool isAuthorizedEEPROM(byte *uid, byte uidSize) { if (uidSize != 4 || storedCount == 0) return false; for (byte i = 0; i < storedCount; i++) { bool match = true; for (byte b = 0; b < 4; b++) { if (uid[b] != storedUIDs[i][b]) { match = false; break; } } if (match) return true; } return false; }
    In setup() call writeUIDsToEEPROM() once to write, then comment it out and replace it with loadUIDsFromEEPROM() for all subsequent boots. This pattern avoids unnecessary EEPROM wear.
  3. Power-cycle test. After writing UIDs to EEPROM, comment out writeUIDsToEEPROM(), upload again, and unplug then replug the Arduino. The Serial Monitor on boot should print Loaded 1 UID(s) from EEPROM. The authorized card still grants access without the hardcoded array.
    Wokwi note: Wokwi does not persist EEPROM between simulation runs by default (the chip state resets). The EEPROM logic can be tested by calling both write and load within the same simulation run, which verifies the read/write logic works correctly. For power-cycle EEPROM persistence, test on physical hardware.
Security analysis — what this build does and does not protect against.

What it does: requires two independent factors (something you have: the badge; something you know: the PIN) before unlocking. A stolen card alone cannot open the lock without the PIN, and vice versa. Brute-force PIN attempts are throttled by the 30-second lockout. All events are logged.

What it does NOT do:
(1) UID cloning. Standard MIFARE Classic UIDs are factory-programmed identifiers broadcast in plaintext. An attacker with a cheap NFC reader and a writable "magic card" (available online for ~$1) can clone any UID in seconds. Your system sees the cloned card as authorized. Real-world access systems authenticate using the card's cryptographic sector keys (MIFARE Classic has 48-bit sector keys, though they are also broken by the Crypto1 attack). Modern systems use MIFARE DESFire EV3 or ISO 14443-4 cards with AES-128 mutual authentication — not UID comparison.

(2) Relay attacks. An attacker with an NFC relay (two phones and an app) can bridge the signal from an authorized card in a victim's wallet to your reader without the card ever leaving the victim's pocket.

(3) Physical bypass. The servo can be overcome mechanically; a servo controlling a real bolt needs to be inside a reinforced enclosure.

For a learning project, this build is correct and educational. For a production deployment guarding anything of value, move to a cryptographic-authentication card platform and a commercial-grade electronic strike, not a servo.
Extension challenges (optional).
(A) Add a master card: scan a designated "admin" card to enter programming mode, then scan new cards to add them to the EEPROM list without recompiling.
(B) Add a buzzer (D6) with distinct tone patterns: two short beeps for granted, one long low beep for denied, three rapid beeps for lockout.
(C) Add a 16x2 I2C LCD (address 0x27) to replace Serial Monitor output with on-screen messages: "SCAN BADGE", "ENTER PIN", "ACCESS GRANTED", "LOCKED OUT Ns". The LiquidCrystal_I2C library handles this with SDA→D20 and SCL→D21 on the Mega.
Checkpoint — what you should see
After writing UIDs to EEPROM and power-cycling (or starting a new simulation run with write-then-load in the same run), the Serial Monitor prints Loaded 1 UID(s) from EEPROM. on boot. The authorized card still grants access. Reading EEPROM.read(0) returns 1 (the count byte). Reading bytes 1-4 returns the four UID bytes you stored.
