Subject

Build a Serial Command Console

Recruit 60 min 250 XP
Mission Brief

Your assignment is to build a working two-way serial console between an Arduino Uno and Python running on your computer. When you finish, you will type on or off in the Python terminal, the Arduino’s built-in LED (pin 13) will obey the command, and the board will send a confirmation line back that Python prints in your console. Type blink and the LED flashes three times. Type anything else and the board replies Unknown command.

This project is structured as a zero-knowledge walkthrough. Every phase shows the exact files to create, the exact commands to run, the expected output at each step, and the observable hardware result that confirms you are on track before moving on. No prior Arduino or Python serial experience is required — Phase 1 starts from downloading the IDE.

This is the same pattern used in firmware debugging, industrial automation, and embedded device control: a human-readable text protocol running over a USB serial wire. By the end you will understand why Python must send bytes (not strings), why the Arduino resets when Python opens the port, and why the Arduino IDE Serial Monitor must be closed before Python can connect.

Agent Requirements
  • Arduino Uno (or any compatible board — Nano, Mega, Leonardo all work) and a USB cable that fits your board. No wiring, no breadboard, no external components — the project uses only the built-in LED already on pin 13.
  • Arduino IDE 2.x — download the installer from arduino.cc/en/software (the large green download button). Version 2.3.x or newer is current as of 2026. The older IDE 1.8.x also works; the UI differs slightly in board/port selection but all sketch code is identical.
  • Python 3.x — any version from 3.8 onward. Confirm by running python --version or python3 --version in your terminal. If you need to install it, download from python.org/downloads.
  • pyserial library installed via pip. The install command is in Phase 3. You do not need it until then.
  • A terminal you are comfortable with (Windows: PowerShell or Command Prompt; Mac/Linux: Terminal). Every command is shown exactly as you type it.

1
Install Arduino IDE 2.x, Select Board & Port, Upload Blink to Confirm Toolchain
Before writing any serial code, you need to confirm the entire upload chain is working: IDE installed, driver loaded, board recognized, sketch compiled and uploaded. The Arduino IDE ships with a built-in Blink example. Uploading it is the fastest way to confirm that everything between your computer and the board works before adding serial logic.
  1. Download and install Arduino IDE 2.x. Go to arduino.cc/en/software. Click the large green download button for your operating system (Windows, macOS, or Linux). Run the installer and accept the defaults. On Windows, accept the driver installation prompt — this installs the USB serial driver that lets your computer recognize the Arduino.
    Windows note: If Windows asks “Do you want to install this device software? — Arduino USB Driver,” click Install. Without the driver, the board will not appear as a COM port.
  2. Plug your Arduino into the computer with the USB cable. The power LED on the board (labeled ON) should light up immediately. Wait a few seconds for the driver to finish loading.
  3. Open the IDE and select your board. Click the board selector dropdown at the top of the IDE (it may say “Select Board” or show a previous selection). In the search box that appears, type Arduino Uno. Click the result that matches your board. If you are using a Nano, Mega, or other model, search for that model name instead.
    You can also reach this via the menu: Tools → Board → Arduino AVR Boards → Arduino Uno.
  4. Select the correct port. The port selector is next to the board selector at the top of the IDE. Click it and look for an entry that shows your board name alongside the port.
    Windows: looks like COM3 (Arduino Uno) or COM4. The exact number varies. Mac: looks like /dev/cu.usbmodem1101 (Arduino Uno). Linux: looks like /dev/ttyACM0 (Arduino Uno). If the port does not appear, unplug and re-plug the USB cable, wait five seconds, and look again. If it still does not appear on Windows, the driver may not have installed — check Device Manager for a yellow warning icon on a USB Serial Device.
  5. Open the Blink example. In the IDE menu, go to File → Examples → 01.Basics → Blink. A new editor window opens with a short sketch that turns LED_BUILTIN on and off every second.
  6. Upload the sketch. Click the Upload button — it is the right-pointing arrow icon in the top-left toolbar, to the right of the checkmark. The IDE compiles the sketch and uploads it. Watch the bottom Output panel for the message avrdude done. Thank you. or Uploading... followed by Done uploading.
    The RX/TX LEDs on the Arduino will flicker rapidly during upload — that is normal. The small LED labeled ‘L’ next to pin 13 (its color varies by board — amber on a genuine Uno, sometimes green or blue on clones) will start blinking once per second when the upload is complete.
Upload fails with “avrdude: stk500_recv(): programmer is not responding”?
  • The wrong port is selected. In the IDE toolbar, re-open the port selector and confirm you picked the COM port or /dev/tty port that belongs to the Arduino.
  • On Mac, if you see /dev/tty.usbmodem and /dev/cu.usbmodem for the same board, choose /dev/cu.usbmodem.
  • If you have a clone board (common with Nano clones), it may use a CH340 USB chip instead of the standard FTDI/ATmega chip. Download the CH340 driver from the manufacturer’s site, install it, then restart the IDE and try again.
IDE shows “Board at COM3 is not available” after selecting the port? Another application has the port open — possibly a serial terminal from a previous session. Close any other programs that might be using the serial port and try the upload again.
Checkpoint — what you should see
The ‘L’ LED next to pin 13 on your Arduino is blinking once per second — on for one second, off for one second. The IDE Output panel shows Done uploading with no red error text. Your toolchain is confirmed working. You can now replace Blink with your own sketch in Phase 2.

2
Write & Upload the Arduino Command Sketch — Test with Serial Monitor
This phase adds serial communication to the Arduino. The sketch waits for a line of text to arrive over USB, reads it with Serial.readStringUntil('\n'), trims whitespace with .trim(), compares the command to on / off / blink, acts on it, and replies with a confirmation line. You will verify it works using the IDE’s built-in Serial Monitor before Python ever enters the picture — this isolates hardware success from Python issues.
Why test with Serial Monitor first? The Serial Monitor lets you type commands and see replies directly from the IDE. If something is wrong with the sketch logic, you find it here without debugging Python at the same time. Only after the Serial Monitor test passes do you close it and move to Python.
  1. Open a new sketch. In the IDE, go to File → New Sketch. A blank sketch with empty setup() and loop() functions opens.
  2. Paste the complete Arduino sketch. Select all the placeholder text in the editor, delete it, and paste this full sketch exactly:
    // serial_console.ino // Arduino command sketch — LED_BUILTIN control via serial // Accepts: "on", "off", "blink" (newline-terminated) // Replies with a confirmation string on each command void setup() { pinMode(LED_BUILTIN, OUTPUT); digitalWrite(LED_BUILTIN, LOW); Serial.begin(9600); // Wait for USB serial to connect on native-USB boards (Leonardo/Micro). // Times out after 2 s so it can never hang; instant on Uno. unsigned long _t = millis(); while (!Serial && millis() - _t < 2000) { ; } } void loop() { if (Serial.available() > 0) { String cmd = Serial.readStringUntil('\n'); cmd.trim(); // remove trailing \r and any whitespace if (cmd == "on") { digitalWrite(LED_BUILTIN, HIGH); Serial.println("LED is ON"); } else if (cmd == "off") { digitalWrite(LED_BUILTIN, LOW); Serial.println("LED is OFF"); } else if (cmd == "blink") { Serial.println("Blinking..."); for (int i = 0; i < 3; i++) { digitalWrite(LED_BUILTIN, HIGH); delay(300); digitalWrite(LED_BUILTIN, LOW); delay(300); } Serial.println("Done"); } else { Serial.print("Unknown command: "); Serial.println(cmd); } } }
    Key functions used: pinMode(LED_BUILTIN, OUTPUT) configures pin 13 as an output. Serial.begin(9600) starts serial communication at 9600 baud — this number must match on both sides (sketch and Python). Serial.available() returns the number of bytes waiting in the receive buffer; the if guard ensures the code only runs when data has arrived. Serial.readStringUntil('\n') reads characters until it sees a newline, then returns them as an Arduino String. .trim() removes the carriage return (\r) that Windows Serial Monitor appends, plus any stray whitespace. Without trim(), the comparison cmd == "on" fails silently because cmd actually contains "on\r".
  3. Upload the sketch. Click the Upload arrow button. Wait for Done uploading in the Output panel. The LED will stop blinking (it was running Blink) and go dark — correct, because the new sketch starts with digitalWrite(LED_BUILTIN, LOW).
  4. Open the Serial Monitor. Click the magnifying-glass icon in the top-right of the IDE toolbar, or go to Tools → Serial Monitor. The Serial Monitor panel opens at the bottom of the IDE.
  5. Set the baud rate to 9600. In the Serial Monitor panel, find the baud rate dropdown on the right side (it may currently say 115200 or another value). Change it to 9600. This must match Serial.begin(9600) in the sketch.
    Also confirm the line-ending dropdown next to the baud rate says Newline (not No line ending and not Carriage return). With Newline selected, the Serial Monitor appends \n when you press Enter, which is what readStringUntil('\n') waits for.
  6. Test the commands. In the input field at the top of the Serial Monitor, type on and press Enter (or click Send). The LED on the board lights up and the monitor shows LED is ON. Type off and press Enter — LED goes dark, monitor shows LED is OFF. Type blink and press Enter — the LED flashes three times and the monitor shows Blinking... then Done. Type hello and press Enter — monitor shows Unknown command: hello.
Serial Monitor is blank — no output when I send commands?
  • The baud rate in the Serial Monitor does not match the sketch. Confirm the dropdown shows 9600.
  • The line-ending dropdown is set to No line ending. Change it to Newline. Without \n, readStringUntil('\n') waits forever and the Arduino never processes your input.
  • You forgot to upload the new sketch after editing. The Blink sketch (Phase 1) does not use serial. Re-upload.
LED turns on but the confirmation text shows garbled characters? The baud rate is mismatched. Change the Serial Monitor dropdown to exactly 9600 to match Serial.begin(9600).
Checkpoint — what you should see
In the Serial Monitor: sending on lights the LED and prints LED is ON. Sending off extinguishes the LED and prints LED is OFF. Sending blink flashes the LED three times and prints Blinking... then Done. Sending any other text prints Unknown command: followed by what you typed. Hardware and sketch are confirmed working. Close the Serial Monitor now — you must close it before Python can open the port in Phase 3.

3
Install pyserial & Write a One-Shot Python Script
This phase introduces Python serial communication. You will install pyserial, identify your port name, and write a minimal script that opens the port, waits for the Arduino to finish resetting, sends a hardcoded on command, reads the Arduino’s reply, and prints it. The goal is one successful command/reply cycle before you build the interactive loop.
The two traps every beginner hits on first run:
Trap 1 — Port busy: The Arduino IDE Serial Monitor is single-owner. If it is open when Python tries to open the port, Python fails immediately with could not open port / Access is denied (Windows) or device busy (Linux/Mac). Close the Serial Monitor before running any Python script.
Trap 2 — Reset sleep: When Python calls serial.Serial(...), the Uno’s hardware resets itself (it is wired to do this on DTR signal changes). The Arduino takes about 1–2 seconds to reboot and reach Serial.begin(9600). If you send a command immediately after opening the port, the Arduino is still in its bootloader and the bytes are lost. The fix is time.sleep(2) right after opening the port.
  1. Confirm the Serial Monitor is closed. Go back to the Arduino IDE and verify the Serial Monitor panel is not open. If it is, click the X on the panel to close it.
  2. Install pyserial. Open your terminal and run:
    pip install pyserial
    If pip is not recognized, try pip3 install pyserial (Mac/Linux) or python -m pip install pyserial (Windows). A successful install ends with a line like Successfully installed pyserial-3.5. Version 3.5 is current; any 3.x version works.
  3. Find your exact port name. You already saw it in Phase 1 when you selected it in the IDE. Use that same name. Common formats:
    Windows : COM3 (or COM4, COM5, etc.) Mac : /dev/cu.usbmodem1101 (exact suffix varies) Linux : /dev/ttyACM0 (or /dev/ttyACM1, /dev/ttyUSB0)
    Finding the port name without the IDE: Windows: open Device Manager, expand “Ports (COM & LPT)” — the Arduino appears as “USB Serial Device (COM3)” or similar. Mac: run ls /dev/cu.* in Terminal. Linux: run ls /dev/ttyACM* /dev/ttyUSB* in Terminal. The entry that appears when you plug in the Arduino and disappears when you unplug it is your board.
  4. Create the script file. Open any plain-text editor (VS Code, Notepad, nano, etc.) and create a file named serial_test.py. Paste this complete script, then change the PORT value on line 5 to match your actual port name from the previous step:
    """ serial_test.py — Phase 3: one-shot command test Sends 'on', reads reply, then closes port. """ import serial import time PORT = 'COM3' # <-- CHANGE THIS to your port (e.g. '/dev/cu.usbmodem1101') BAUD = 9600 # Open the serial port. timeout=3 means readline() waits at most 3 seconds. ser = serial.Serial(PORT, BAUD, timeout=3) # CRITICAL: wait 2 seconds for the Arduino to finish resetting. # The Uno resets when the serial port is opened. Without this sleep, # the first command arrives while the board is still in its bootloader # and is silently lost. time.sleep(2) # Send the command. ser.write() requires BYTES, not a string. # Appending '\n' is required because the Arduino reads until '\n'. # Without the '\n', readStringUntil('\n') waits forever. ser.write(b'on\n') # Read the Arduino's reply (up to 3 seconds wait due to timeout=3). reply = ser.readline() # readline() returns bytes. Decode to str, strip trailing \r\n. print('Arduino replied:', reply.decode().strip()) ser.close()
    Why b'on\n' and not 'on\n'? pyserial’s write() method requires a bytes object. Passing a plain string raises TypeError: unicode-objects must be encoded before writing. The b'' prefix makes it a bytes literal. Alternatively, you can write ser.write(('on' + '\n').encode()) which encodes a string to bytes — both are equivalent.
  5. Run the script. In your terminal, navigate to the folder where you saved serial_test.py and run:
    python serial_test.py
    On Mac/Linux you may need python3 serial_test.py. The script pauses for 2 seconds (the reset sleep), then prints one line and exits. This is normal.
Error: could not open port COM3: Access is denied (Windows) or could not open port /dev/ttyACM0: [Errno 16] Device or resource busy (Linux/Mac)?
  • The Arduino IDE Serial Monitor is still open. Close it and run the script again.
  • Another terminal window has a Python serial script still running. Kill it and try again.
  • On Linux: your user may not have permission to access the serial port. Run sudo usermod -aG dialout $USER, log out and back in, then try again.
Error: serial.serialutil.SerialException: [Errno 2] No such file or directory: '/dev/ttyACM0'? The port name in your script does not match the actual port. Double-check the name using the IDE or the OS-level commands in step 3, and update PORT = in the script.
Script runs but prints Arduino replied: with nothing after the colon? The reply came back empty. Most likely the 2-second sleep was not enough on a slow machine, or the port name is wrong and the write was silently ignored. Try increasing time.sleep(2) to time.sleep(3) and run again.
Checkpoint — what you should see
Your terminal prints Arduino replied: LED is ON and the built-in LED on pin 13 is now lit. This confirms: pyserial is installed, your port name is correct, the reset sleep is working, byte-encoded writes are reaching the Arduino, and the reply round-trip is complete. The LED will stay on until the board is powered off or the next command is sent. Phase 4 adds the interactive loop.

4
Make It Interactive — The Command Loop
Replace the one-shot script with an interactive loop that reads a command from your keyboard, sends it to the Arduino, prints the reply, and repeats until you type quit. This is the final working console.
  1. Create a new file named serial_console.py. Paste this complete script, changing PORT to your port name:
    """ serial_console.py — Phase 4: interactive command loop Type 'on', 'off', or 'blink'. Type 'quit' to exit. """ import serial import time PORT = 'COM3' # <-- CHANGE THIS to your port BAUD = 9600 print(f"Opening {PORT} at {BAUD} baud...") ser = serial.Serial(PORT, BAUD, timeout=3) print("Waiting for Arduino to reset (2 seconds)...") time.sleep(2) print("Ready. Commands: on off blink quit\n") try: while True: cmd = input("> ").strip() if cmd == "quit": print("Closing port.") break if not cmd: continue # ignore empty input (user pressed Enter with nothing) # Encode the command string to bytes and append a newline terminator. ser.write((cmd + '\n').encode()) # Read the Arduino's reply line. reply = ser.readline() if reply: # Decode bytes to str, strip trailing \r\n before printing. print(reply.decode().strip()) # Some commands send two lines (blink sends "Blinking..." then "Done"). # Read a second line if one arrives within the timeout. extra = ser.readline() if extra: print(extra.decode().strip()) except KeyboardInterrupt: # User pressed Ctrl+C — exit gracefully. print("\nInterrupted. Closing port.") finally: # Always close the port, even if an error occurs. ser.close() print("Port closed.")
    Why (cmd + '\n').encode() instead of b'on\n'? In a loop where cmd is a variable (whatever the user typed), you cannot use a bytes literal. .encode() converts a Python string to bytes using UTF-8, which covers all ASCII characters used here. The result is identical to the b'' form for ASCII text.

    Why read a second readline()? The blink command makes the Arduino send two separate Serial.println() lines: Blinking... and then Done. Each println() sends one line followed by \r\n. The first readline() captures the first line. The second call captures the second line if it arrives within the 3-second timeout, or returns an empty bytes object b'' if nothing more arrived. The if extra: guard suppresses empty lines so on and off do not print a blank second line.
  2. Make sure the Serial Monitor is closed in the Arduino IDE.
  3. Run the console:
    python serial_console.py
    The script prints its ready message and displays a > prompt. Type on and press Enter.
  4. Test all four commands one by one:
    Opening COM3 at 9600 baud... Waiting for Arduino to reset (2 seconds)... Ready. Commands: on off blink quit > on LED is ON > off LED is OFF > blink Blinking... Done > hello Unknown command: hello > quit Closing port. Port closed.
    Watch the board while you type each command. on should light the LED, off should extinguish it, and blink should flash it three times. The LED states and the text replies together confirm the full two-way round-trip.
The script prints LED is ON but the LED does not light up?
  • Confirm you uploaded the serial_console.ino sketch from Phase 2. If the board is still running Blink from Phase 1, it will not respond to serial commands.
  • Try re-uploading: open the Arduino IDE, open the Phase 2 sketch, click Upload, wait for Done uploading, then close Serial Monitor and run the Python script again.
The prompt hangs after I type a command — no reply? The timeout=3 argument means readline() waits at most 3 seconds. If it hangs longer, the script is stuck in input() (waiting for you to press Enter), not in readline(). Make sure you pressed Enter after typing the command.
Typing blink only shows one line, not both Blinking... and Done? The blink loop runs 3 cycles of 300 ms on + 300 ms off = 3 × 600 ms = 1800 ms before Done is sent. With timeout=3 already set in the serial.Serial() call above, the second readline() has a full 3-second window, which is more than enough margin. If you still do not see Done, confirm you are running the script shown in this phase (not an older copy with timeout=1).
Checkpoint — the complete end-to-end test
Run through this test in order: (1) Run python serial_console.py. (2) At the > prompt, type on — LED lights, console prints LED is ON. (3) Type off — LED goes dark, console prints LED is OFF. (4) Type blink — LED flashes three times, console prints Blinking... then Done. (5) Type hello — console prints Unknown command: hello, LED unchanged. (6) Type quit — console prints Closing port. then Port closed. and returns to the shell prompt. All six steps passing means your two-way serial console is fully functional.

5
Polish — Port Discovery Helper, Clean Exits & Robust Readline
The console works. This phase adds three production-quality improvements: a port-listing helper so you never have to guess the port name, a robust reply-reader that handles a timed-out readline returning an empty bytes object, and a validated final full-file snapshot of both the sketch and the script with every improvement integrated.
  1. Add the port discovery helper. pyserial ships a utility module called serial.tools.list_ports that lists every detected serial port. Run this one-liner in your terminal at any time to see what is connected:
    python -m serial.tools.list_ports --verbose
    Expected output (Windows example): COM3 desc: USB Serial Device (COM3) hwid: USB VID:PID=2341:0043 SER=... LOCATION=1-1.3 The VID 2341 is Arduino’s USB Vendor ID — any port with that VID is an Arduino. On Mac the hwid shows VID:PID=2341:0043 as well. This is the definitive way to find your port without opening the IDE.
  2. Review the complete final sketch (no changes needed from Phase 2 — shown here as the definitive reference):
    // serial_console.ino — FINAL VERSION // Commands: on / off / blink // Replies: one or two Serial.println() lines per command void setup() { pinMode(LED_BUILTIN, OUTPUT); digitalWrite(LED_BUILTIN, LOW); Serial.begin(9600); unsigned long _t = millis(); while (!Serial && millis() - _t < 2000) { ; } // wait up to 2 s for native-USB boards (Leonardo/Micro); instant on Uno } void loop() { if (Serial.available() > 0) { String cmd = Serial.readStringUntil('\n'); cmd.trim(); // strips \r and leading/trailing whitespace if (cmd == "on") { digitalWrite(LED_BUILTIN, HIGH); Serial.println("LED is ON"); } else if (cmd == "off") { digitalWrite(LED_BUILTIN, LOW); Serial.println("LED is OFF"); } else if (cmd == "blink") { Serial.println("Blinking..."); for (int i = 0; i < 3; i++) { digitalWrite(LED_BUILTIN, HIGH); delay(300); digitalWrite(LED_BUILTIN, LOW); delay(300); } Serial.println("Done"); } else { Serial.print("Unknown command: "); Serial.println(cmd); } } }
  3. Review the complete final Python script with all improvements integrated:
    """ serial_console.py — FINAL VERSION Two-way serial console: Python <-> Arduino Uno Built-in LED control via on / off / blink commands. Usage: 1. Upload serial_console.ino to the Arduino (Arduino IDE 2.x). 2. Close the Arduino IDE Serial Monitor. 3. Run: python serial_console.py 4. Type commands at the '>' prompt. Type 'quit' to exit. Port name formats: Windows : COM3 (check Device Manager > Ports) Mac : /dev/cu.usbmodem1101 (run: ls /dev/cu.*) Linux : /dev/ttyACM0 (run: ls /dev/ttyACM* /dev/ttyUSB*) Any OS : python -m serial.tools.list_ports --verbose """ import serial import time # ── Configuration ───────────────────────────────────────────── PORT = 'COM3' # <-- change to your port name BAUD = 9600 TIMEOUT = 3 # seconds to wait for a reply line def read_reply(ser): """Read up to two reply lines. Returns a list of non-empty strings.""" lines = [] for _ in range(2): raw = ser.readline() # returns b'' on timeout if raw: lines.append(raw.decode('utf-8', errors='replace').strip()) else: break # nothing more arrived within TIMEOUT return lines # ── Main ────────────────────────────────────────────────────── print(f"Opening {PORT} at {BAUD} baud...") try: ser = serial.Serial(PORT, BAUD, timeout=TIMEOUT) except serial.SerialException as e: print(f"Error: {e}") print("Check that:") print(" 1. The port name is correct (see module docstring above).") print(" 2. The Arduino IDE Serial Monitor is closed.") print(" 3. The Arduino is plugged in.") raise SystemExit(1) print("Waiting for Arduino to reset (2 seconds)...") time.sleep(2) print("Ready. Commands: on off blink quit\n") try: while True: cmd = input("> ").strip() if cmd == "quit": print("Closing port.") break if not cmd: continue # ignore empty Enter presses ser.write((cmd + '\n').encode('utf-8')) for line in read_reply(ser): print(line) except KeyboardInterrupt: print("\nInterrupted.") finally: ser.close() print("Port closed.")
    What changed from Phase 4: (1) read_reply() loops and collects non-empty lines, handling the empty b'' that readline() returns on timeout. (2) The serial.Serial() call is wrapped in a try/except SerialException that prints actionable troubleshooting text instead of a raw traceback. (3) TIMEOUT = 3 gives the blink command enough time for both reply lines to arrive. (4) decode('utf-8', errors='replace') replaces any garbled bytes (from baud mismatch or noise) with the Unicode replacement character instead of crashing.
  4. Run the final version and repeat the full end-to-end test from the Phase 4 checkpoint to confirm all improvements hold.
Still getting an empty reply after switching to TIMEOUT = 3? The Arduino may have received a partial command without a newline. In the Python console, type a command and watch whether the Arduino LED responds. If the LED reacts but no text reply comes back, the reply line is arriving faster than the readline timeout (unlikely) or Serial.println() in the sketch is not executing (confirm the correct sketch is uploaded via File → Save As and re-upload).
Connection works but Ctrl+C does not exit cleanly on Windows? Windows sometimes requires pressing Ctrl+C twice before the KeyboardInterrupt is raised inside input(). The finally block runs either way, so the port will close. This is a known Python/Windows behavior, not a bug in the script.
Checkpoint — observable win
Run python serial_console.py with the final version. Type on → LED on, LED is ON printed. Type off → LED off, LED is OFF printed. Type blink → LED flashes 3 times, Blinking... and Done both printed on separate lines. Type hello → Unknown command: hello printed. Type quit → Closing port. and Port closed. printed, script exits cleanly. All five behaviors pass: your two-way serial console is complete and production-ready.
