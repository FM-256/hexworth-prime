Subject

Build an E-Commerce Store with Stripe

Operative 90 min 500 XP
Mission Brief

Your assignment is to build a fully functional e-commerce storefront using Node.js and Express on the backend with the Stripe API handling all payment processing. The store will serve a static product catalog, manage a server-side shopping cart via sessions, and guide customers through a complete checkout experience ending in order confirmation.

Stripe integration goes beyond a simple charge call. You will implement PaymentIntents for PCI-compliant card collection, use Stripe Elements on the frontend to render a hosted card form, and set up a webhook endpoint to receive asynchronous payment events such as payment_intent.succeeded and payment_intent.payment_failed. Webhook signatures must be verified using your endpoint secret.

This project drills server-side routing, session management, third-party API integration, and the critical distinction between client-side and server-side trust. Real payment amounts must always be calculated server-side — never trust a price submitted from the browser.

Agent Requirements
  • Node.js installed; comfortable with npm init and installing packages
  • Basic Express routing: app.get, app.post, middleware
  • Understanding of HTTP request/response cycle and JSON APIs
  • Familiarity with environment variables and .env files via dotenv
  • Basic HTML and JavaScript for rendering the product catalog and card form
  • A free Stripe test account with publishable and secret keys available
Operation Phases
1
Project Setup and Product Catalog
Initialize a Node.js project and install express, stripe, dotenv, and express-session. Define a product catalog as a JavaScript array with id, name, price in cents, and description. Build a GET /products route that returns the catalog as JSON and a static HTML frontend that fetches and renders it as a product grid with "Add to Cart" buttons.
Checkpoint: Product Catalog
  • Product catalog page displays items with name, price, and image
  • Product data loads from the database or config file, not hardcoded HTML
  • Individual product detail pages render correctly
2
Shopping Cart with Server-Side Sessions
Implement cart routes: POST /cart/add accepts a product id and quantity, looks up the price server-side, and stores the line item in req.session.cart. Build GET /cart to return current cart contents with computed totals, and DELETE /cart/:id to remove items. Never accept a client-submitted price — always derive it from your server-side catalog.
Checkpoint: Shopping Cart
  • Adding an item to the cart updates the cart count in the UI
  • Cart contents persist across page navigations within the session
  • Removing an item from the cart updates totals correctly
3
Stripe PaymentIntent and Checkout Page
Create a POST /checkout/create-intent route that calculates the cart total server-side and calls stripe.paymentIntents.create with the amount and currency: 'usd'. Return the client_secret to the frontend. On the checkout page, load Stripe.js, mount a Card Element into a div, and call stripe.confirmCardPayment(clientSecret, ...) on form submit.
Checkpoint: Stripe Checkout
  • Stripe.js loads and displays the card input element on the checkout page
  • PaymentIntent is created server-side with the correct amount in cents
  • Test card 4242424242424242 processes successfully in test mode
4
Webhook Handler for Payment Events
Register a POST /webhook route using Express raw body middleware (express.raw). Verify the event signature with stripe.webhooks.constructEvent(payload, sig, endpointSecret) — reject any request that fails verification with a 400 response. Handle payment_intent.succeeded to mark the order fulfilled and log the event. Use the Stripe CLI (stripe listen) to forward webhook events during local development.
Checkpoint: Webhook Processing
  • Stripe CLI forwards webhook events to your local endpoint
  • payment_intent.succeeded events update the order status in your database
  • Webhook signature verification rejects tampered payloads
5
Order Confirmation and Error Handling
On successful payment, redirect to a /order-confirmation page that displays the order summary and a confirmation number. Clear the cart from the session after confirmation. Add client-side error handling for declined cards — display the error message returned by Stripe directly in the UI. Test with Stripe's built-in test card numbers (4242 4242 4242 4242 for success, 4000 0000 0000 9995 for decline).
Checkpoint: Order Flow
  • Successful payment redirects to a confirmation page with order details
  • Failed payments display a user-friendly error message
  • The cart is cleared after a successful purchase
6
Polish: Cart Persistence and UX Refinement
Add a persistent cart badge in the navigation that updates on every cart change via a GET /cart/count endpoint. Implement a loading state on the checkout button while the PaymentIntent is being created and while confirmCardPayment is processing. Add quantity controls (increment/decrement) on the cart page that call the cart update route and re-render totals without a full page reload.
Checkpoint: UX Polish
  • Cart survives a browser refresh without losing items
  • Loading states appear during payment processing
  • Edge cases like zero-quantity or negative prices are rejected
