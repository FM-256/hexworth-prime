Subject

Your First Git Repository

Beginner 30 min 100 XP
Mission Brief

Every software project starts with a repository. In this project, you will create your first Git repo from scratch, make commits, and push to GitHub. These are the three operations you will perform thousands of times in your career.

You will learn the difference between your local repository and the remote on GitHub, how staging works, and what a commit message should look like. No shortcuts, no GUI — pure command line.

This is the foundation of everything. Every project after this one assumes you can clone, commit, and push.

Agent Requirements
  • Git installed on your computer (git --version should return a version number)
  • A GitHub account
  • A terminal / command prompt
Operation Phases
Progress
0 / 5
✓
1
Configure Git Identity
Set your name and email: git config --global user.name "Your Name" and git config --global user.email "your@email.com". These appear on every commit you make.
Checkpoint: Git Installation
  • Run git --version and confirm Git is installed
  • Verify git config user.name and git config user.email are set
  • Confirm you have a GitHub (or GitLab) account and can authenticate via SSH or HTTPS
✓
2
Create a Local Repository
Create a new directory, navigate into it, and run git init. Create a README.md file with a project title. Run git status to see the untracked file.
✓
3
Stage and Commit
Run git add README.md to stage the file, then git commit -m "Initial commit: add README". Run git log to see your first commit with its hash, author, and timestamp.
Checkpoint: First Commit
  • Run git init in your project folder and verify the .git/ directory is created
  • Stage a file with git add and confirm it appears in git status as staged
  • Create a commit and verify it appears in git log with your message
✓
4
Connect to GitHub
Create a new empty repository on GitHub (no README, no .gitignore). Copy the remote URL. Run git remote add origin https://github.com/username/repo.git to link your local repo to GitHub.
Checkpoint: Branching Basics
  • Create a new branch with git checkout -b feature and verify you switched to it
  • Make a commit on the branch and confirm it does not appear on main
  • Merge the branch back into main and verify the commit is now present
✓
5
Push to Remote
Run git push -u origin main. Refresh your GitHub page — your README is now live. Make another change, commit it, and push again to confirm the workflow.
Checkpoint: Remote & Push
  • Add a remote with git remote add origin [URL] and verify with git remote -v
  • Push to the remote and confirm your files appear on GitHub/GitLab in the browser
  • Verify the commit history on the remote matches your local git log
