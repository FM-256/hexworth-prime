Subject

Build a Multi-Tool Swiss Army CLI

Pro 2H 30M 2000 XP
Mission Brief

This operation demands the construction of a modular CLI multi-tool built on a pluggable subcommand framework where each tool is a completely independent module. The architecture uses a plugin discovery system: drop a Python file into the plugins/ directory and it auto-registers as a subcommand at runtime via importlib dynamic imports. A base Plugin class enforces a consistent interface across every module, and argparse subparsers wire the entire system together into a unified CLI with shared configuration and consistent output formatting. This is not a script — this is a deployable tool with real architecture behind it.

The tool spans four domains simultaneously. Networking delivers a threaded TCP port scanner, ICMP ping sweep, and DNS record lookup with record type selection. Cryptography provides a multi-algorithm file and string hasher, a base64/hex/URL encoder-decoder, and a cryptographically secure password generator with configurable entropy display. Forensics contributes a formatted hex viewer with ASCII sidebar and a metadata extractor that reads magic bytes, timestamps, and permissions. Automation rounds out the suite with a live log watcher with pattern highlighting and a batch file renamer with regex support and dry-run mode. Every subcommand shares the same output style, the same config system, and the same error-handling conventions.

Make no mistake: this is the hardest project in the catalog. It is the capstone that ties together skills from every house into a single deployable artifact. Where other projects ask you to code a solution, this one asks you to design a system. You will need to think about plugin contracts, dynamic loading, thread safety in a network scanner, binary parsing in a hex viewer, and packaging for pip-installable distribution. Completing this operation means you have crossed from writing Python to engineering Python — and that distinction matters in the field.

Agent Requirements
  • Strong Python skills including classes, decorators, dynamic imports with importlib, and argparse subparser configuration
  • Completed at least two other house projects — practical cross-domain experience is required, not optional
  • Understanding of software architecture patterns including plugins, registries, and dependency injection principles
  • Comfortable working with file I/O, raw networking via sockets, and subprocess management for system-level tasks
  • Ready for a longer, harder build — this is a 2.5-hour capstone designed to test everything you know
Operation Phases
1
Core Framework & Plugin Loader
Design the plugin architecture: a base Plugin class with register(), execute(), and help() methods that every module must implement. Build a dynamic loader that scans the plugins/ directory, imports each module via importlib, and registers it in a command registry. Wire up argparse with subparsers that auto-populate from discovered plugins — adding a new plugin file should require zero changes to the core framework.
2
Network Tools Module
Implement three network subcommands: scan performs a threaded TCP port scanner across a target host and port range using threading.Thread with a configurable thread pool size; ping sweeps an entire subnet with ICMP probes and reports live hosts; dns performs forward and reverse DNS lookups with selectable record types (A, MX, NS, TXT). Each subcommand outputs structured, consistently formatted results with timing information.
3
Crypto Tools Module
Implement three crypto subcommands: hash hashes files or inline strings across MD5, SHA-1, SHA-256, and SHA-512 simultaneously using hashlib; encode performs base64, hex, and URL encoding and decoding in both directions from a single flag; passgen generates cryptographically secure passwords via secrets with configurable length, character sets, and entropy calculation displayed in bits.
4
Forensics & Automation Modules
Forensics: hexdump renders a formatted hex viewer with a 16-byte row layout, byte offsets in the left column, and a printable ASCII sidebar on the right, using struct for binary unpacking; metadata extracts file size, creation and modification timestamps, permissions, and the first 16 magic bytes from any file using pathlib and os. Automation: watch tails a log file in real time with regex-based pattern highlighting; rename batch-renames files with configurable regex patterns and a mandatory --dry-run preview mode before any changes hit disk.
5
Config, Testing & Polish
Add a shared configuration system backed by a TOML or JSON file that stores per-module defaults (timeout values, thread counts, default algorithms). Build a --list flag that prints all available plugins with their descriptions, versions, and categories in a formatted table. Add colored terminal output using ANSI codes, progress indicators for long-running operations, and consistent error handling with actionable messages. Write unittest test cases for at least three modules. Package the tool with pyproject.toml so it is installable via pip install . and exposes a named CLI entry point.
