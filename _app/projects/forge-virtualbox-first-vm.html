Subject

Create Your First Virtual Machine

Recruit 1–2 hr 200 XP
Mission Brief

Install VirtualBox and create your first virtual machine running Ubuntu Linux. This is the gateway skill for every lab in Hexworth — you cannot do hands-on security, networking, or systems work without virtual machines.

A virtual machine (VM) is a complete computer running as software inside your existing computer. VirtualBox creates an isolated container with its own virtual CPU, RAM, disk, and network card. Everything you do inside the VM stays inside the VM. You can break things, experiment, and restore to a clean state in seconds. Your main computer is never at risk.

By the end of this project you will have a working Ubuntu 26.04 LTS desktop environment, the ability to resize the window and use a shared clipboard, and a saved snapshot you can always return to. Every subsequent Forge, Shield, and Code project assumes you have this baseline.

Agent Requirements
  • 64-bit host computer — any Windows 10/11, macOS 12+, or Linux machine from the past 8 years qualifies. 32-bit hosts cannot run 64-bit guest VMs.
  • Hardware virtualization enabled in BIOS/UEFI — Intel calls this VT-x; AMD calls it AMD-V. It is enabled by default on most modern machines, but some older or budget systems ship with it disabled. Phase 1 covers how to verify and enable it if needed.
  • At least 8 GB of RAM on your host — 4 GB is the minimum that will technically work, but your host OS will feel sluggish while the VM is running. 8 GB or more is the comfortable baseline.
  • At least 30 GB of free disk space — the Ubuntu ISO is 6 GB; the VM virtual disk will grow to approximately 10–15 GB after installation. 30 GB gives comfortable headroom.
  • Internet connection — needed to download VirtualBox (approximately 130 MB) and the Ubuntu ISO (6 GB). Download the ISO before starting if your connection is slow.
  • Windows users: Hyper-V and WSL2 awareness — if you have Hyper-V or WSL2 active, VirtualBox 7.x can coexist via its Hyper-V backend. Phase 1 covers this specifically. No configuration is required in most cases on VirtualBox 7.x.

Verify Prereqs and Install VirtualBox 7.2
Confirm your hardware supports virtualization, resolve any Windows Hyper-V concerns, then download and install VirtualBox 7.2.10 (the current stable release as of June 2026).
  1. Check how much RAM your host has.
    Windows: press Win + R, type msinfo32, press Enter. Look for "Installed Physical Memory (RAM)." You need at least 8 GB to work comfortably.
    macOS: Apple menu > About This Mac > Memory.
    Linux: open a terminal and run:
    free -h
    The "total" column under "Mem" is your installed RAM.
  2. Check free disk space. You need at least 30 GB free.
    Windows: open File Explorer, right-click your C: drive > Properties.
    macOS: Apple menu > About This Mac > Storage.
    Linux:
    df -h /
    The "Avail" column shows free space on your root partition.
  3. Verify hardware virtualization is enabled.
    Windows: press Ctrl + Shift + Esc to open Task Manager, click the Performance tab, select CPU. Look for Virtualization: Enabled at the bottom right. If it says Disabled, see the fix box below before proceeding.
    macOS Apple Silicon (M1/M2/M3): virtualization is always enabled; skip this step.
    Linux: run this command — any output means virtualization is available:
    grep -cw vmx /proc/cpuinfo || grep -cw svm /proc/cpuinfo
    A result of 0 means the feature is not visible to the OS; reboot into BIOS to enable it.
    Virtualization shows Disabled in Task Manager?
    • Reboot your computer. During the startup logo screen, press the BIOS/UEFI key for your manufacturer: Del or F2 (most desktops), F2 (Dell laptops), Esc then F10 (HP), F1 (Lenovo ThinkPads).
    • Navigate to the Advanced or CPU Configuration section. Look for a setting named Intel Virtualization Technology, Intel VT-x, or SVM Mode (AMD). Set it to Enabled.
    • Save and exit (usually F10). Windows will boot normally. Return to Task Manager to confirm Virtualization now shows Enabled.
    • If you cannot find the setting, search "[your laptop model] enable VT-x BIOS" for a model-specific guide.
  4. Windows only: check Hyper-V / WSL2 status. VirtualBox 7.x includes a Hyper-V backend that lets it coexist with WSL2 and Hyper-V without any changes. You do NOT need to disable WSL2. If you run into a VERR_VMX_NO_VMX error after installing VirtualBox, it means Hyper-V is active but VirtualBox's Hyper-V backend did not activate automatically — see the fix box in Phase 4.
    Secure Boot note: on some Windows 11 machines with Secure Boot enabled, VirtualBox may show a driver signing prompt during install. Accept it and reboot when prompted. Secure Boot does not need to be disabled for VirtualBox 7.x on Windows.
  5. Download VirtualBox 7.2.10. Go to virtualbox.org/wiki/Downloads and click the link for your host OS:
    • Windows hosts — downloads VirtualBox-7.2.10-174163-Win.exe (approximately 130 MB)
    • macOS / Intel hosts — downloads a .dmg file; double-click to mount and run the .pkg inside
    • macOS / Apple Silicon — a separate ARM64 .dmg is listed; use that one
    • Linux — click "Linux distributions" to get distro-specific packages, or use the .run installer
    Extension Pack (optional): also on the Downloads page is the VirtualBox Extension Pack. It adds USB 2.0/3.0 passthrough, VRDP remote display, host webcam passthrough, and disk image encryption. It is free for personal and educational use under Oracle's PUEL license. You do not need it to complete this project, but it is worth installing if you plan to connect USB drives to VMs.
  6. Install VirtualBox.
    Windows: double-click the .exe. Click through the setup wizard accepting defaults. When prompted that network interfaces will be reset briefly, click Yes. If Windows Defender SmartScreen appears, click "More info" then "Run anyway."
    macOS: open the .dmg, run the .pkg, follow prompts. macOS will ask you to allow the Oracle kernel extension in System Preferences > Privacy & Security. Click Allow, then reboot.
    Linux (Ubuntu/Debian): if you downloaded the .deb package:
    sudo apt-get install ./VirtualBox-7.2.10_Ubuntu_*.deb
  7. Launch VirtualBox and confirm the version. Open VirtualBox from your applications or Start menu. Go to Help > About VirtualBox. The version should read 7.2.10.
Checkpoint — what you should see
The VirtualBox Manager window is open and shows an empty VM list with a "New" button in the toolbar. Help > About shows version 7.2.10. Task Manager (Windows) shows Virtualization: Enabled. You have at least 30 GB free disk and 8 GB RAM confirmed.

Download the Ubuntu 26.04 LTS ISO
Ubuntu 26.04 LTS (codenamed "Resolute Raccoon") is the current Long-Term Support release, available since April 2026. LTS means it receives 5 years of security updates — it is the right choice for a learning environment you want to keep working reliably.
  1. Go to ubuntu.com/download/desktop. The page will offer Ubuntu 26.04 LTS as the primary download. Click the green Download Ubuntu 26.04 LTS button for the Intel/AMD 64-bit build.
    Which architecture to download: choose the Intel/AMD 64-bit option (labeled "amd64") for any x86 Windows or Linux machine. If you are on a Mac with Apple Silicon (M1/M2/M3), choose the ARM 64-bit option. The ISO file name is ubuntu-26.04-desktop-amd64.iso at approximately 6 GB for the Intel/AMD build.
  2. Let the download complete. At 6 GB the download takes 5–30 minutes depending on your connection speed. Do not close the browser tab — many browsers cancel downloads if the tab is closed. Save the file somewhere you can find it easily, such as your Desktop or Downloads folder.
  3. Verify the ISO is not corrupted (recommended). Ubuntu publishes SHA256 checksums at releases.ubuntu.com/26.04/SHA256SUMS. To verify on Windows (PowerShell):
    Get-FileHash .\ubuntu-26.04-desktop-amd64.iso -Algorithm SHA256
    On macOS or Linux:
    sha256sum ubuntu-26.04-desktop-amd64.iso
    Compare the output to the checksum listed for your file on the Ubuntu releases page. If they match, the file is intact. If they do not match, the file is corrupted and you need to re-download it.
    Skip verification? For a learning environment, a corrupted ISO typically makes itself obvious immediately — the installer either crashes or shows garbled text. Verification is fastest way to rule out a bad download before spending time troubleshooting the VM.
Checkpoint — what you should see
The file ubuntu-26.04-desktop-amd64.iso (approximately 6 GB) is present in your Downloads or Desktop folder. If you ran the checksum command, its output matches the SHA256 value from the Ubuntu releases page. You are ready to create the VM.

3
Create the VM and Configure Resources
Use the VirtualBox New VM wizard to define a virtual machine: its name, how much RAM and CPU it gets, and how large its virtual hard disk is. VirtualBox 7.x includes an Unattended Install option that automates the Ubuntu installation — you will use the manual path instead because it gives you control over your username, password, and partition layout, and because the Unattended path for Ubuntu 26.04 is less reliable than a standard install.
  1. Open the New VM wizard. In the VirtualBox Manager, click the blue New button in the toolbar (or go to Machine > New).
  2. Fill in the Name and Operating System page.
    • Name: type Ubuntu-Lab
    • Folder: leave as the default (your home folder / VirtualBox VMs)
    • ISO Image: click the folder icon and browse to your ubuntu-26.04-desktop-amd64.iso file
    • After selecting the ISO, VirtualBox will auto-fill Type: Linux and Version: Ubuntu (64-bit). Confirm these are correct.
    • Skip Unattended Installation: check the box labeled "Skip Unattended Installation" so you can install Ubuntu manually. This gives you full control and is the more reliable path.
    Why manual install? The Unattended Install path automatically provisions a user and runs the installer in the background. It works, but creates a user named "vboxuser" with a generic password, skips the partition review screen, and does not give you the GNOME first-run setup. Manual install takes 10 additional minutes and gives you a cleaner, more understandable result.
  3. Click Next. Set the memory and CPU on the Hardware page.
    • Base Memory: set to 4096 MB (4 GB). The slider turns red if you go past the green safe zone; stay inside the green zone. Ubuntu 26.04 desktop needs at least 2 GB; 4 GB makes it comfortable.
    • Processors: set to 2. Two CPUs makes the installer and desktop noticeably faster. Do not allocate more than half your host CPU cores.
  4. Click Next. Configure the Virtual Hard Disk.
    • Select Create a Virtual Hard Disk Now.
    • Set the size to 25 GB. Ubuntu needs about 10 GB for a base install; 25 GB leaves room for tools and experiments.
    • Leave the format as VDI (VirtualBox Disk Image) and the allocation as Dynamically allocated. A dynamically allocated disk only uses actual host disk space as files are written inside the VM — the 25 GB cap is the maximum it will ever reach, not what it reserves immediately.
  5. Click Next, then Finish. VirtualBox creates the VM. It now appears in the left sidebar of VirtualBox Manager labeled "Ubuntu-Lab" with a status of "Powered Off."
  6. Adjust display settings before first boot (recommended). Select Ubuntu-Lab in the sidebar, click Settings > Display. Set Video Memory to 128 MB (drag the slider all the way right). This prevents the VM display from defaulting to a tiny fixed resolution during install.
Checkpoint — what you should see
The VirtualBox Manager sidebar shows Ubuntu-Lab with status Powered Off. In the Details panel on the right you can see: Base Memory 4096 MB, Processors 2, Storage shows the ubuntu-26.04 ISO attached to the IDE controller, and a 25.00 GB VDI disk. Video Memory is 128 MB.

Boot the VM and Install Ubuntu
Start the VM for the first time. It will boot from the Ubuntu ISO, present the installer, and walk you through setting your language, timezone, username, and password. The install takes 10–20 minutes depending on host disk speed.
  1. Start the VM. Double-click Ubuntu-Lab in the sidebar, or select it and click the green Start arrow. A VM window opens. The first thing you will see is the Ubuntu boot logo on a dark screen. Wait 20–30 seconds.
    VM window shows "VERR_VMX_NO_VMX" or "VT-x is not available"?
    • This means hardware virtualization is disabled in your BIOS. Return to Phase 1 step 3 and enable VT-x (Intel) or SVM/AMD-V (AMD) in your BIOS/UEFI settings.
    • Windows with Hyper-V: VirtualBox 7.x should handle this automatically via its Hyper-V backend. If the error persists, open an Administrator PowerShell and run bcdedit /set hypervisorlaunchtype off, then reboot. This turns off the Hyper-V hypervisor at boot — note that WSL2, Windows Sandbox, and Credential Guard rely on it and will stop working until you re-enable it with bcdedit /set hypervisorlaunchtype auto and reboot again. Restart VirtualBox after rebooting.
    • If the error says "no 64-bit option available": this is the same root cause — virtualization is not enabled or is being blocked. A 32-bit guest can run without VT-x, but Ubuntu desktop requires 64-bit. VT-x/AMD-V must be enabled.
    VM window is tiny or black after boot?
    • If the window is tiny: this is normal until Guest Additions are installed (Phase 5). The installer will still be usable; you can scroll inside it.
    • If the screen stays black for more than 60 seconds: press the Right Ctrl key once (this is the VirtualBox "Host Key" that releases your mouse if it was captured), then click inside the VM window and press Enter. If still black, close the VM, go to Settings > Display, and enable 3D acceleration, then retry.
  2. The Ubuntu welcome screen appears. You will see a screen with two options: Try Ubuntu and Install Ubuntu. Click Install Ubuntu.
    Mouse capture: when you click inside the VM window, VirtualBox captures your mouse pointer. To release it and use your host desktop, press the Right Ctrl key (Windows/Linux) or Left Command key (macOS). This is shown in the status bar at the bottom of the VM window.
  3. Work through the installer screens.
    • Choose your language: select your language and click Next.
    • Accessibility: adjust if needed, or click Next to skip.
    • Keyboard layout: English (US) is the default. Click Next.
    • Connect to the Internet: choose "Use wired connection" if shown, or skip for now — updates can be applied after install. Click Next.
    • Try or install Ubuntu: click Install Ubuntu (the "Try Ubuntu" option just runs a temporary live session without installing anything).
    • How would you like to install Ubuntu? select Interactive installation. (This is the current installer's label — it replaced the older "Normal installation" wording.) Click Next.
    • What apps would you like to start with? select Default selection for a standard desktop. "Extended selection" adds extra office/utility apps and is optional. Click Next.
    • Proprietary software: optionally tick "Install third-party software for graphics and Wi-Fi hardware" and the media-codecs box, then click Next.
    • How do you want to install Ubuntu? (disk setup) select Erase disk and install Ubuntu. This erases the VIRTUAL disk only — not your real hard drive. The VM lives entirely inside a file on your host machine. Click Next.
    • Create your account: fill in:
      • Your name: anything (e.g., Student)
      • Your computer's name: leave as generated or set it to ubuntu-lab
      • Username: something short, all lowercase, no spaces (e.g., student)
      • Password and confirm password: choose something you will remember
      • Leave "Require my password to log in" selected
    • Select your timezone: it auto-detects from your network, or type your city. Click Next.
    • Review and install: a summary screen appears. Click Install to begin.
    The installation now begins.
  4. Wait for installation to complete. A progress bar shows the installer copying files, installing packages, and configuring the system. This typically takes 10–20 minutes. You can watch the slideshow or leave and come back. Do not close the VM window.
  5. When prompted "Installation Complete," click Restart Now. The VM will display a message: "Please remove the installation medium, then press ENTER." Press Enter in the VM window. VirtualBox will automatically detach the ISO. The VM reboots.
  6. The VM reboots into the installed Ubuntu system. You will see the Ubuntu boot logo, then a login screen. Click your username and type your password. You reach the Ubuntu GNOME desktop.
Checkpoint — what you should see
You are logged in to the Ubuntu 26.04 LTS GNOME desktop inside the VM window. The desktop shows a dock at the left, a top bar with the time, and a "Files" icon. Right-click the desktop and you see a context menu. Open a terminal (right-click > Open in Terminal, or press the Super key and search "terminal") and run uname -a. The output includes Linux ubuntu-lab and a kernel version number starting with 6. or higher.

Install Guest Additions and Verify Usability
VirtualBox Guest Additions is a small software package installed inside the Ubuntu VM that enables automatic window resizing, shared clipboard between host and VM, drag-and-drop file transfer, and significantly better display performance. Without it, the VM is stuck at a fixed resolution and clipboard sharing does not work. This phase installs it.
  1. Install the required build dependencies inside the VM. Open a terminal in Ubuntu (press the Super key, type "terminal," press Enter). Run:
    sudo apt-get update && sudo apt-get install -y build-essential linux-headers-$(uname -r) dkms
    Enter your password when prompted. This installs the compiler and kernel headers that the Guest Additions installer needs to build its kernel module. This takes 1–3 minutes.
    Why is this step needed? Guest Additions includes a kernel driver that must be compiled specifically for the running kernel version. The build-essential package provides GCC and Make; linux-headers provides the kernel source headers; dkms handles automatic module rebuilding when the kernel updates.
  2. Mount the Guest Additions CD Image from the VirtualBox menu. In the VirtualBox window title bar, click Devices (in the menu at the very top of the VM window, not inside Ubuntu). Click Insert Guest Additions CD Image...
    A file manager window may pop up inside Ubuntu asking if you want to run the software on the CD. Click Run if prompted — this is the same as the terminal command in the next step. If no pop-up appears, proceed to the terminal method.
  3. Run the Guest Additions installer from the terminal.
    sudo sh /media/$USER/VBox_GAs_7.2.10/VBoxLinuxAdditions.run
    If the path above does not work: the CD mount point name includes the exact VirtualBox version. Find it with ls /media/$USER/ and substitute the actual folder name. For example, if it shows VBox_GAs_7.2.8, use that path instead.
    Expected output (abbreviated):
    Verifying archive integrity... 100% MD5 checksums are OK. All good. Uncompressing VirtualBox 7.2.10 Guest Additions for Linux......... VirtualBox Guest Additions installer Copying additional installer modules ... Installing additional modules ... VirtualBox Guest Additions: Starting. VirtualBox Guest Additions: Building the modules for kernel 6.x.x-xx-generic. VirtualBox Guest Additions: Running kernel modules will not be replaced ... VirtualBox Guest Additions: Starting. VirtualBox Guest Additions: modprobe vboxguest succeeded
    The install finishes with no error messages about "failed to build."
    Error: "This system is currently not set up to build kernel modules"?
    • The build dependencies from step 1 were not installed. Run sudo apt-get install -y build-essential linux-headers-$(uname -r) dkms again, then re-run the VBoxLinuxAdditions.run installer.
    • If apt-get update fails with "Could not resolve archive.ubuntu.com": your VM does not have internet access. Go to the VirtualBox Settings for your VM > Network > Adapter 1, confirm "Attached to: NAT" is selected, then click OK and try again.
  4. Reboot the VM.
    sudo reboot
    Wait for Ubuntu to boot back to the login screen. Log in with your password.
  5. Enable shared clipboard. In the VirtualBox menu for your running VM, click Devices > Shared Clipboard > Bidirectional. Now you can copy text in Ubuntu and paste it into your host, and vice versa.
    Also available: Devices > Drag and Drop > Bidirectional enables file drag-and-drop between host and VM.
  6. Verify auto-resize works. Click and drag the corner of the VM window to make it larger. Ubuntu's desktop should automatically resize to fill the new window size within 1–2 seconds. If it does not resize, wait 10 seconds and try again — the vboxvideo driver sometimes takes a moment on first boot after Guest Additions installation.
    Screen does not resize automatically after Guest Additions install?
    • Confirm Guest Additions was installed for the running kernel: in the Ubuntu terminal run lsmod | grep vboxguest. If it returns an empty result, the kernel module is not loaded. Try sudo modprobe vboxguest and then resize the window again.
    • If modprobe vboxguest says "not found": the build step failed silently. Re-run sudo sh /media/$USER/VBox_GAs_7.2.10/VBoxLinuxAdditions.run and look carefully for any "failed to build" lines in the output. Install missing packages and retry.
    • Green-screen or display corruption during resize: go to VM Settings > Display, uncheck "Enable 3D Acceleration," restart the VM. 3D acceleration in VirtualBox can conflict with some desktop environments.
  7. Verify the terminal works end-to-end. Open a terminal in Ubuntu and run:
    uname -a
    Example output:
    Linux ubuntu-lab 6.x.x-xx-generic #xx-Ubuntu SMP PREEMPT_DYNAMIC ... x86_64 x86_64 x86_64 GNU/Linux
    Then run:
    lsb_release -a
    Expected output:
    No LSB modules are available. Distributor ID: Ubuntu Description: Ubuntu 26.04 LTS Release: 26.04 Codename: resolute
Checkpoint — what you should see
The VM window auto-resizes when you drag its corner. lsmod | grep vboxguest returns a line starting with vboxguest. lsb_release -a shows Ubuntu 26.04 LTS. Copy text inside Ubuntu (Ctrl+C) and paste into a host application (Ctrl+V) — the text arrives. Your VM is fully operational.

Take a Snapshot and Learn Safe Shutdown
A snapshot captures the exact state of the VM — every file, every setting, every running process — at a moment in time. You can return to it in under 10 seconds no matter how badly you break things. This is the single most important habit for safe VM experimentation. Do this now, while the system is clean.
  1. Make sure the VM is running and logged in. You want to snapshot the working, post-Guest-Additions state.
  2. Take a snapshot. In the VirtualBox menu bar, click Machine > Take Snapshot...
    • Snapshot Name: type Clean Install - Guest Additions OK
    • Snapshot Description: optionally note the date and VirtualBox version
    Click OK. VirtualBox pauses the VM for 1–3 seconds while it takes the snapshot, then resumes it. The snapshot appears in the VirtualBox Snapshot Manager.
    When to snapshot: take a snapshot any time you are about to do something that could break the system: installing unfamiliar software, modifying system files, following a lab guide for the first time. The habit costs 3 seconds and saves hours of reinstalling.
  3. Test snapshot restore (optional but highly recommended). Make a deliberate change inside the VM to prove restore works. For example, create a test file:
    touch ~/THIS_WILL_BE_GONE_AFTER_RESTORE.txt ls ~
    Confirm the file exists. Now restore the snapshot: in VirtualBox Manager, go to Machine > Restore Snapshot... (or use the Snapshots panel on the right). Select your Clean Install snapshot and click Restore. VirtualBox warns that the current state will be discarded; click Restore again. Start the VM. Open a terminal and run:
    ls ~
    The THIS_WILL_BE_GONE_AFTER_RESTORE.txt file is not there. The restore worked.
  4. Learn the two correct ways to shut down the VM.
    • Graceful shutdown (preferred): inside Ubuntu, click the top-right corner power icon > Power Off > Power Off. Ubuntu shuts down cleanly, just like a real computer.
    • ACPI shutdown from VirtualBox menu: Machine > ACPI Shutdown. This sends a power button signal to Ubuntu, which triggers a normal shutdown. Useful when the VM desktop is frozen.
    Do NOT use Machine > Reset or close the VM window with "Power off the machine" unless Ubuntu is completely frozen. These are equivalent to yanking the power cord. The disk may be left in an inconsistent state. Always use a graceful shutdown when you can.
Checkpoint — what you should see
In the VirtualBox Manager, click the hamburger icon next to Ubuntu-Lab in the sidebar and select Snapshots. Your Clean Install - Guest Additions OK snapshot appears in the list with a timestamp. The VM powers off cleanly when you use the Ubuntu shutdown menu. You know how to restore a snapshot. Your lab environment is complete and recoverable.
