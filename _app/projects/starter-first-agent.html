Subject

My First Agent

Adaptive · L1–5 30 min – 4 hr 250 – 1500 XP
Mission Brief

Everyone says "AI agent" like it is magic. It is not. An agent is four things you control: instructions (how it behaves), knowledge (what it knows), actions (what it can do), and boundaries (what it must never do). In this project you build one from scratch and watch it grow from a chatbot into an operator.

This is an adaptive project with five levels. Level 1 takes about thirty minutes and needs zero code. Each level after adds one real capability, and you can stop at any level and still have built something that works. The progression is deliberately safe: your agent learns to read, then answer from sources, then draft, then act with approval, and only at the top does it operate on its own inside guardrails you wrote.

You will build in Microsoft Copilot Studio, which lets you create an agent by describing what you want in plain language before any code is involved. This is the AI sibling of My First Website and My First App: the same "zero to a real thing in one sitting" path, for the AI stack.

What an Agent Actually Does

A chatbot answers. An agent acts. That one distinction sets your expectations for the whole project. Inside the boundaries you set, an agent does three things in sequence — the loop you build and re-build at every level below:

1
Assess
It reads the incoming context — a student's question, an exception in a process, a message that just hit the inbox — and works out what it is being asked to handle.
2
Reason
It decides the next action from its instructions, the business rules you wrote, and the knowledge and tools it can reach — not a guess, a decision grounded in what it can actually see.
3
Act
It drafts, summarizes, routes, or executes — then returns the result for human review or approval at the gates you defined. You stay responsible for the call that matters.

This is also what separates an agent from a plain workflow. A workflow runs a fixed script — perfect for predictable, repeatable steps. An agent decides the right action from context, and calls a workflow when consistency matters. The two work together: the agent brings the judgment, the workflow brings the guarantee. People set the guardrails, approve the outputs, and own the exceptions.

Why a Help-Desk Agent?

Not every process makes a good first agent. The ones that pay off fastest share four traits Microsoft sees across real deployments — and a campus IT help desk hits all four, which is exactly why it is your training ground here:

  • Touches many people. Everyone files help-desk tickets, so time saved compounds across every student and staffer the agent serves.
  • Predictable outcome. Password resets and policy questions follow clear rules, which makes the agent's answers easy to validate — you can tell at a glance if it got it right.
  • Low change-management. Nobody learns a new way to work; people ask for help the way they already do, and just get it faster.
  • Inside systems you already use. Email, a knowledge base, a ticket list — no new tool to adopt, no migration project hiding inside the AI project.

This is not a toy scenario invented for a tutorial. Employee support and IT triage is one of the starting points Microsoft sees rise to the top across real organizations — the same shape of work you are about to automate, one level at a time.

Level 1: The Talking Agent
Beginner~30 min+250 XP
Create your first agent in Microsoft Copilot Studio — no code. You describe what you want in plain language, let Copilot Studio generate a starting agent, then shape it into a campus help-desk assistant that answers from one document and politely refuses everything else. The exact path:
  1. Sign in. Go to copilotstudio.microsoft.com and sign in — you land on the Home page with a “describe your agent” box.
    No describe box? Your tenant uses manual creation. Select + New agent → Configure, type the name Campus Help Desk Assistant, paste the Instructions from step 4 straight into the Instructions field, then jump to step 5 (you skip the auto-generate in step 2).
  2. Describe your agent. In the box, paste this starter prompt: A friendly campus IT help-desk assistant that answers student questions about passwords, Wi-Fi, accounts, and lab access using only its attached knowledge sources, and politely declines anything off-topic. Copilot Studio reads it and auto-generates a name and a first draft of the instructions — you refine, you don't start from a blank page — then opens the Overview page.
  3. Ignore the suggestions for now. On the way in, Copilot Studio suggests triggers, channels, tools, and extra knowledge. None of them take effect unless you add them, so for Level 1 just leave them alone — you only need instructions + one knowledge source.
  4. Set the instructions. On the Overview page open Instructions (the AI already drafted some). Make them read close to this — paste it in to be safe: You are the Campus Help Desk Assistant. Answer questions about campus IT — passwords, Wi-Fi, accounts, and computer-lab access — using ONLY the knowledge sources attached to this agent. Keep answers short and friendly. If a question is not about campus IT, reply: "I can only help with campus IT questions."
  5. Add a knowledge source. Your agent needs a document to answer from. Copy the five Q&As below into a plain-text file named faq.txt, then in the Knowledge section select Add → choose Files → upload faq.txt → Add → Add to agent.
    faq.txt — copy this

    Q: How do I reset my campus password?
    Go to passwords.campus.edu, choose “Reset Password,” and follow the prompts. Changes apply within about 5 minutes.

    Q: I'm locked out of my account.
    After 5 failed sign-ins the account locks for 15 minutes. Wait 15 minutes, then reset at passwords.campus.edu. Still stuck? Contact the IT desk.

    Q: How do I connect to campus Wi-Fi?
    Join the “CampusSecure” network and sign in with your student email and password. “CampusGuest” is for visitors only.

    Q: How do I get into the computer labs?
    The Library and Tech building labs open with your student ID card, 7am–11pm on weekdays.

    Q: My email won't sync on my phone.
    Remove and re-add the account using your full student email and current password. If it still fails after a password reset, contact the IT desk.

  6. Test it. In the Test your agent panel on the right, ask one of the FAQ questions — it should answer in persona, from the FAQ. Use the Start new test session icon to reset between tries.
    A free trial can create and test — that's all you need here. Ignore the Publish button for now; publishing needs a licensed environment (Level 5).
Skills: writing agent instructions, grounding on a knowledge source, agent identity, testing in Copilot Studio.
Win conditionIn the Test your agent panel the agent answers 5 FAQ questions correctly in its defined persona, and politely refuses an off-topic request (e.g. “I can only help with campus IT questions”).
Checkpoint — how to verify
In the Test your agent panel, ask something the FAQ covers (e.g. “my password is locked, what do I do?”). It should reply in persona using the FAQ's steps. Then ask an off-topic question (“what's the weather?”); it should decline and point you to campus IT. If it answers off-topic asks, add an explicit scope line to the Instructions (“only answer campus IT questions”) and re-test with a new session.

Level 2: The Knowledge Agent
Beginner+~45 min+250 XP
Now make your agent answer only from documents — and admit when it doesn't know. That's retrieval-augmented generation (RAG): the agent retrieves from your sources and grounds its answer in them instead of guessing. You'll add a second document, lock the agent to your sources, and watch it cite where each answer came from. Continue with the Campus Help Desk Assistant from Level 1:
  1. Open your Level 1 agent. From the Copilot Studio Home page, open the Campus Help Desk Assistant you already built (it already has faq.txt as knowledge).
  2. Confirm generative orchestration. Open Settings (the gear, top right) → Generative AI, and make sure the orchestration option is set to Generative. The grounding controls in step 4 need it. (New agents are usually Generative already.)
  3. Add a second source. Copy the policy below into a plain-text file lab-policy.txt, then Knowledge → Add → choose Files → upload lab-policy.txt → Add → Add to agent. Your agent now grounds on two docs.
    lab-policy.txt — copy this

    Campus IT Use Policy (excerpt)

    1. Acceptable use: campus accounts and lab computers are for coursework and official campus activity only.

    2. Passwords: must be at least 12 characters, changed at least every 180 days, and never shared.

    3. Software: only IT-approved software may be installed on lab computers; request other software through the IT desk.

    4. Data: do not store personal or sensitive data on lab computers — saved files are wiped nightly.

    5. Incidents: report a lost ID card, suspected phishing, or a compromised account to the IT desk within 24 hours.

  4. Lock it to your sources. In Settings → Generative AI → Knowledge section, turn off “Allow ungrounded responses” (now the agent blocks any answer it didn't pull from a source, and falls back instead) and turn off “Use information from the web” (no Bing — only your two docs). Save.
  5. Citations are automatic. When the agent answers from a doc, Copilot Studio adds a citation to that source by itself — you don't write or format citations. Just confirm they appear; don't add instructions trying to change them.
  6. Test grounding. In the Test your agent panel ask a policy-only question, e.g. “How often must I change my password?” — it should answer 180 days and cite lab-policy.txt. Then ask something neither doc covers, e.g. “Who is the campus mascot?” — it should decline (“that's not in my sources”) instead of inventing.
Skills: RAG, knowledge grounding, multi-source knowledge, automatic citations, fallback / “I don't know” behavior.
Win conditionWith Allow ungrounded responses off, the agent answers a policy question from the uploaded docs with a visible citation, and declines a question neither doc covers instead of inventing an answer.
Checkpoint — how to verify
Ask “How often must I change my password?” — the agent should answer every 180 days with a citation to lab-policy.txt (a fact that's only in the policy, not the FAQ). Then ask “Who is the campus mascot?” — it should say it doesn't have that information. If it invents an answer, confirm both files are attached, Allow ungrounded responses and Use information from the web are off, orchestration is set to Generative, and the agent's Instructions don't restrict it to one document by name.

Level 3: The Inbox Agent
Intermediate~45 min+300 XP
Teach your agent to triage: read a batch of incoming help-desk messages, sort each by priority, and draft a suggested reply for the urgent ones — without ever sending anything. You'll feed it a sample inbox right in the test panel, so there's no mailbox to connect and nothing it can accidentally send. Continue with your Campus Help Desk Assistant:
  1. Open your agent. From the Copilot Studio Home page, open the Campus Help Desk Assistant from Levels 1–2.
  2. Add triage instructions. On the Overview page open Instructions and add this rule below what's already there:
    add to Instructions

    When the user pastes a list of help-desk messages, triage them. Label each message Urgent, Routine, Spam, or Escalation, give a one-line reason, and for each Urgent message also draft a short suggested reply. Use these rules: Urgent = blocked work or a deadline; Escalation = a security or safety issue such as a hacked account; Spam = unsolicited promotions or scams; Routine = everything else. You can only draft replies — never claim to have sent, deleted, or forwarded anything.

  3. Feed it a sample inbox. Copy these six messages and paste them into the Test your agent panel, then ask: Triage these messages.
    sample inbox — paste into the test panel

    1. “I can't log in and my exam submission is due in 1 hour — my password won't work.”

    2. “How do I connect my laptop to CampusSecure Wi-Fi?”

    3. “CONGRATULATIONS! You've won a $500 gift card — click here to claim now!!!”

    4. “I think my account was hacked — there are messages sent from it I never wrote.”

    5. “What are the library computer-lab hours this weekend?”

    6. “The library lab printer is jammed and 30 students are waiting on exam printouts.”

  4. Read the result. Each message should get one label + a one-line reason; the two urgent ones (#1, #6) should each get a short draft reply, #3 flagged Spam, #4 Escalation. Use the Start new test session icon to retry.
  5. Refine. If a message is mislabeled, add one example of that category to your triage instructions and test again — the same tighten-and-retest loop from Level 1.
In the real world: to triage a live mailbox you'd add the Office 365 Outlook connector and a Power Automate flow to fetch messages — that needs a licensed environment and Copilot Studio capacity. The triage logic you wrote here is exactly what that production agent runs.
Skills: AI classification, triage rules, instruction refinement, draft-not-send safety.
Guardrails. The agent only drafts. With no email connector attached it cannot send, delete, or forward — the safety is built in, not bolted on. Sample messages only; no real inbox or credentials.
Win conditionGiven the six sample messages, the agent labels each Urgent / Routine / Spam / Escalation with a reason, drafts a reply for each Urgent one, and never claims to send, delete, or forward.
Checkpoint — how to verify
Paste the six sample messages and ask the agent to triage. Each should get exactly one label with a one-line reason; #1 and #6 should be Urgent with a draft reply, #3 Spam, #4 Escalation, #2 and #5 Routine. Triage has judgment calls: #1 is Urgent because of the explicit 1-hour deadline (a password failure can also hint at a hacked account → Escalation, but the deadline wins here), and #6 is Urgent as blocked work affecting many students — if your agent labels a borderline case differently with sound reasoning, that's fine; the skill is consistent, rule-based labeling. There's no Sent or Deleted folder to check — with no connector, the agent can't send by design. If a message is clearly mislabeled, add one example of that category to the triage instructions and re-test with a new session.

Level 4: The Action Agent
Intermediate+~45 min+350 XP
This is the skill that makes autonomy safe: human-in-the-loop approval. Before an agent does anything that changes the world — create a ticket, schedule a meeting — it should propose the action and wait for a person to approve. You'll build that gate as instructions and prove it works both ways. Because no live system is connected on a trial, the action runs as an honest dry run (the agent shows what it would do) — the gate is the lesson, not the plumbing. Continue with your Campus Help Desk Assistant:
  1. Open your agent. From the Copilot Studio Home page, open the Campus Help Desk Assistant from the earlier levels.
  2. Add an approval-gate rule. On the Overview page open Instructions and add this below what's already there:
    add to Instructions

    When the user asks you to perform an action that changes something — for example create a ticket, schedule a meeting, or update a record — do NOT do it right away. First reply with a structured Action Request: the action on one line, then the key details as a short bulleted list. Then ask the user to reply approve or deny. Only after the user replies approve do you confirm the action, and prefix that confirmation with "DRY RUN —" because no live system is connected. If the user replies deny, cancel and do nothing. Never carry out an action without an explicit approve.

  3. Test the approve path. In the Test your agent panel, type: Create a help-desk ticket for a broken projector in Room 204. The agent should reply with an Action Request (the ticket details) and stop, asking you to approve or deny. Reply approve — it should confirm with something like “DRY RUN — would create ticket: …”.
  4. Test the deny path. Start a new test session, ask the same thing, and this time reply deny. The agent should cancel and create nothing. That is the guardrail working.
  5. Refine. If the agent ever “acts” without pausing for approval, strengthen the rule (“never carry out an action without an explicit approve”) and re-test — the same tighten-and-retest loop from the earlier levels.
In the real world: to make the action actually create a ticket, you'd add an agent flow as a tool (Tools → Add a tool → Flow) — a Power Automate flow with a real Approvals action — which needs Power Automate and a licensed environment. The approve/deny gate you wrote here is exactly what that production flow enforces before it runs.
Skills: human-in-the-loop approval, structured action proposals, approval gates, safe autonomy.
Guardrails. The agent never carries out a state-changing action without an explicit human “approve” — it proposes, waits, and only then proceeds. On a trial that proceed-step is a dry run; in production the same gate sits in front of a real flow.
Win conditionAsked to perform an action, the agent replies with a structured Action Request and waits; on “approve” it confirms the action as a DRY RUN; on “deny” it does nothing. It never proceeds without an explicit approve.
Checkpoint — how to verify
Ask the agent to “create a help-desk ticket for a broken projector in Room 204.” It must reply with the proposed ticket details and pause for approve/deny — not act immediately. Reply approve and confirm it reports the ticket as a DRY RUN. Start a new session, ask again, reply deny, and confirm it creates nothing. If it ever acts without pausing, strengthen the “never act without an explicit approve” rule and re-test.

5
Level 5: The Autonomous Operations Agent
Advanced~3-4 hr+350 XP
Combine everything into a department assistant: multiple tools, multiple workflows, memory, and decision logic. It reads email, creates tickets, schedules meetings, updates a project board, and produces a daily report, orchestrating the steps itself and pausing only at the approval gates you defined. You also write its governance: what it may decide alone, what always needs a human, and how it logs what it did.
Skills: agent orchestration, tool calling, context management, AI governance.
Guardrails. Autonomy is bounded by written governance: defined approval gates, a clear "never do this alone" list, and an action log. Nothing ships to real users or real email without sign-off.
Win conditionThe agent runs a full multi-step business process end to end with minimal intervention (approvals only at the defined gates) and produces an auditable log of every action it took.
Checkpoint — how to verify
Start the daily run; the agent should triage the inbox, create needed tickets (pausing at the approval gate), schedule meetings, update the board, and output a daily report. Open the action log and confirm every state-changing step is recorded and every gated action shows an approval. If a step ran that should have been gated, add it to the "never do this alone" list and route it through approval.
