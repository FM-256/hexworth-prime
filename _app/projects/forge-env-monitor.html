Subject

Build an Environmental Monitor

Recruit 60–90 min 250 XP
Mission Brief

This operation builds a focused environmental monitoring station around a single sensor — the DHT11 temperature and humidity module — wired to an Arduino Mega 2560. The Mega reads live conditions, evaluates them against comfort thresholds, and provides immediate visual and audio feedback through three LEDs and a buzzer while printing a live status dashboard to the Serial Monitor.

No hardware required to complete this project. The primary path uses Wokwi — a free, browser-based Arduino simulator that supports the Mega, a DHT sensor, LEDs, and a buzzer. You build the circuit on-screen, paste in the sketch, and watch the Serial Monitor respond. If you own the physical kit (Arduino Mega 2560, DHT11 sensor, LEDs, resistors, buzzer, breadboard) the exact same sketch runs on real hardware with a matching wiring diagram.

Every industrial HVAC monitor, server-room sensor, and greenhouse controller starts with exactly this pattern: read a sensor, compare to thresholds, drive outputs. You will implement that pattern from scratch.

Agent Requirements
  • Path A — Wokwi (browser only, no hardware needed): a modern web browser (Chrome, Firefox, Edge) and a free account at wokwi.com. No software to install.
  • Path B — Real hardware: Arduino Mega 2560, DHT11 temperature/humidity sensor, one green LED, one yellow LED, one red LED, three 220Ω resistors, one 10KΩ resistor, one active buzzer (5V), a breadboard, and jumper wires. USB-A to USB-B cable. Arduino IDE 2.3.10 installed on your computer.
  • No prior Arduino or electronics experience required — every step is numbered and explained from scratch.
  • Basic comfort reading a list of instructions and copy-pasting code.

Set Up Your Toolchain & Blink the Onboard LED
Get your development environment running and confirm the Mega can execute code. Blinking the built-in LED is the "hello world" of embedded programming — if it blinks, the toolchain is working and you are ready to add sensors.
Wokwi path (recommended): go to wokwi.com/projects/new/arduino-mega. This opens a new project with an Arduino Mega already on the canvas. Skip directly to step 4. No installation needed.
  1. Download and install Arduino IDE 2.3.10. Go to arduino.cc/en/software and download the installer for your OS (Windows, macOS, or Linux). Run the installer and accept all defaults. When it finishes, launch the IDE.
    Why IDE 2.x? Arduino IDE 2.x (current: 2.3.10) includes an integrated Library Manager, autocompletion, and a built-in Serial Monitor plotter — everything you need for this project in one window. The older IDE 1.x is still downloadable but lacks these features.
  2. Connect your Arduino Mega via USB. Plug the USB-B end into the Mega and the USB-A end into your computer. In the IDE, click the board selector at the top. Choose Arduino Mega or Mega 2560 from the list. Then select the correct port — on Windows it will appear as COM3 or similar; on macOS as /dev/cu.usbmodem...; on Linux as /dev/ttyACM0.
    Port not showing up?
    • Try a different USB cable — many cables are charge-only and carry no data.
    • On Windows: open Device Manager and look for "Ports (COM & LPT)". If the Mega appears with a yellow warning triangle, install the CH340 or FTDI driver from the Arduino website.
    • On Linux: you may need to add yourself to the dialout group: sudo usermod -aG dialout $USER, then log out and back in.
  3. Open a new sketch in the IDE. Go to File > New Sketch. Delete any existing content and replace it with the blink sketch in step 4.
  4. Paste this blink sketch. This flashes the Mega's onboard LED (connected internally to pin 13) once per second.
    // Phase 1: Blink the onboard LED to confirm the toolchain works. // Pin 13 is the built-in LED on the Arduino Mega 2560. void setup() { pinMode(13, OUTPUT); // configure pin 13 as an output Serial.begin(9600); // open the serial port at 9600 baud Serial.println("ENV MONITOR - Phase 1 online"); } void loop() { digitalWrite(13, HIGH); // LED on delay(500); // wait 500 ms digitalWrite(13, LOW); // LED off delay(500); // wait 500 ms }
    In Wokwi: paste this code into the code editor on the left panel, then click the green Play button. The simulation starts immediately. You will see the onboard LED (labeled L on the Mega board) flash on and off. In the Serial Monitor tab at the bottom, you will see "ENV MONITOR - Phase 1 online" printed once when the board boots.
  5. Upload and verify. Click the Upload button (right-pointing arrow) in the IDE toolbar. The IDE compiles, uploads, and the onboard LED on the Mega starts blinking once per second. Open the Serial Monitor (magnifying glass icon, top right) and set the baud rate to 9600. You should see the boot message printed once.
Checkpoint — what you should see
The Mega's onboard LED blinks at a steady once-per-second rate. The Serial Monitor shows ENV MONITOR - Phase 1 online printed once after upload. This confirms: the board is recognized, the sketch compiled without errors, and the Serial Monitor is communicating at the correct baud rate (9600). Both Wokwi and real hardware show identical behavior.

2
Wire the DHT Sensor & Read Temperature / Humidity
Install the Adafruit DHT sensor library, connect the sensor to the Mega, and read live temperature and humidity values to the Serial Monitor every two seconds. This is the core data source for everything that follows.
Wokwi sensor note: Wokwi provides a DHT22 part (wokwi-dht22) but not a DHT11 part. The DHT22 is electrically compatible and uses the same library; the only difference is the sensor type constant in code. The Wokwi path uses DHT22 in the sketch. If you are on real hardware with a DHT11 chip (blue plastic body, 4 pins), use DHT11 instead — both are noted in the code below.
  1. Install the Adafruit DHT sensor library (real hardware / IDE only). In the Arduino IDE, go to Sketch > Include Library > Manage Libraries. Search for DHT sensor library by Adafruit. Install version 1.4.7 (or latest). The IDE will ask if you want to install the dependency Adafruit Unified Sensor — click Install All. Both are required.
    In Wokwi: libraries are bundled automatically. You do not need to install anything. Skip to step 2.
  2. Wire the DHT sensor.
    Real hardware wiring (DHT11, 4-pin module): the leftmost pin (VCC) goes to the Mega's 5V pin. The second pin (DATA) goes to Mega digital pin 2 AND through a 10KΩ resistor to 5V (this pull-up resistor is required — without it the line floats and reads NaN). The third pin (NC) is not connected. The fourth pin (GND) goes to any GND pin on the Mega. If your DHT11 is a 3-pin breakout module (common in starter kits), it already has the pull-up resistor built in — just connect VCC, DATA, and GND.
    In Wokwi: in the canvas, click the plus (+) icon to add a component. Search for DHT22 and place it. Then draw wires: DHT22 VCC pin to the Mega's 5V pin; DHT22 SDA pin (labeled SDA in Wokwi — it is the data line) to Mega pin 2; DHT22 GND pin to any Mega GND. In Wokwi you do not need to add a pull-up resistor — the simulated DHT22 reads fine without one.
  3. Paste this sketch and upload.
    // Phase 2: Read DHT sensor and print to Serial Monitor. // Uses Adafruit DHT sensor library v1.4.7 // (requires Adafruit Unified Sensor as a dependency) #include "DHT.h" // ── Pin and sensor type ────────────────────────────────────── #define DHTPIN 2 // DATA wire connected to digital pin 2 // CHOOSE ONE: // For real hardware with a DHT11 chip (blue body): // #define DHTTYPE DHT11 // For Wokwi (uses DHT22 part) OR real hardware with a DHT22: #define DHTTYPE DHT22 DHT dht(DHTPIN, DHTTYPE); void setup() { Serial.begin(9600); dht.begin(); Serial.println("ENV MONITOR - Phase 2: DHT sensor active"); } void loop() { // The DHT11/22 needs at least ~2 seconds between reads. // Polling faster just returns the library's cached last reading. delay(2000); float humidity = dht.readHumidity(); float tempC = dht.readTemperature(); // Celsius float tempF = dht.readTemperature(true); // Fahrenheit // Check for failed read (library returns NAN on error) if (isnan(humidity) || isnan(tempC)) { Serial.println("ERROR: DHT read failed. Check wiring."); return; // skip the rest of this loop iteration } Serial.print("Temp: "); Serial.print(tempC, 1); // 1 decimal place Serial.print(" C / "); Serial.print(tempF, 1); Serial.print(" F Humidity: "); Serial.print(humidity, 1); Serial.println(" %"); }
  4. Open the Serial Monitor and confirm readings. In the IDE, click the Serial Monitor icon and set the baud rate to 9600. You should see a line printed every 2 seconds showing temperature and humidity. In Wokwi, click the DHT22 sensor on the canvas to open a control panel with sliders — drag the temperature and humidity sliders up and down and watch the Serial Monitor update in real time.
    Expected Serial Monitor output (Wokwi default values):
    ENV MONITOR - Phase 2: DHT sensor active Temp: 24.0 C / 75.2 F Humidity: 50.0 % Temp: 24.0 C / 75.2 F Humidity: 50.0 %
Serial Monitor shows "ERROR: DHT read failed" repeatedly?
  • Missing pull-up resistor (real hardware only): the DHT11 DATA pin must be pulled up to 5V through a 10KΩ resistor. Without it the line floats and reads fail. If using a 3-pin breakout board, the resistor is already on the board.
  • Wrong sensor type constant: if you have a DHT11 chip but the sketch uses DHT22 (or vice versa) every read will return NaN. Check the markings on your sensor. In Wokwi, always use DHT22.
  • Polling too fast: calling readTemperature() faster than every 2 seconds returns stale data or NaN. The delay(2000) in the loop prevents this.
  • Wiring error: confirm DATA is on pin 2, VCC on 5V (not 3.3V), GND on GND. A single swapped wire causes every read to fail.
  • Baud mismatch: if the Serial Monitor shows garbled characters, the baud rate does not match. Set the dropdown in the Serial Monitor to 9600 to match Serial.begin(9600).
Checkpoint — what you should see
The Serial Monitor prints a new line every 2 seconds. Temperature reads in a realistic range (roughly 15–40 C indoors). Humidity reads in a realistic range (20–90%). No NaN or "ERROR" lines appear. In Wokwi, dragging the sensor sliders changes the printed values within the next 2-second interval. On real hardware, breathing gently on the sensor raises the humidity reading within a few cycles.

Add Three Threshold LEDs (Green / Yellow / Red)
Wire three LEDs to the Mega and implement threshold logic: green for comfortable, yellow for warm, red for hot. Only one LED is on at a time. The thresholds are: below 25 C = green (OK), 25–30 C = yellow (warm), above 30 C = red (hot).
  1. Wire the three LEDs.
    Real hardware wiring: connect each LED's anode (longer leg, +) through a 220Ω resistor to its Mega pin, and each cathode (shorter leg, -) to any GND pin.
    Green LED anode → 220Ω → Mega pin 10  |  Green cathode → GND
    Yellow LED anode → 220Ω → Mega pin 11  |  Yellow cathode → GND
    Red LED anode → 220Ω → Mega pin 12  |  Red cathode → GND
    In Wokwi: add three LED components (search "LED"). Place them on the canvas. For each LED: wire the anode (A) pin through a 220Ω resistor (add from the component list) to the Mega pin (10, 11, 12). Wire each cathode (C) to GND. Use the Properties panel to set the LED colors to green, yellow, and red for visual clarity.
  2. Paste this updated sketch and upload.
    // Phase 3: DHT sensor + three threshold LEDs. #include "DHT.h" #define DHTPIN 2 #define DHTTYPE DHT22 // use DHT11 for real DHT11 hardware DHT dht(DHTPIN, DHTTYPE); // ── LED pins ───────────────────────────────────────────────── const int LED_GREEN = 10; const int LED_YELLOW = 11; const int LED_RED = 12; // ── Thresholds (degrees Celsius) ──────────────────────────── const float THRESH_WARN = 25.0; // green < 25 | yellow >= 25 const float THRESH_CRIT = 30.0; // yellow < 30 | red >= 30 void setup() { Serial.begin(9600); dht.begin(); pinMode(LED_GREEN, OUTPUT); pinMode(LED_YELLOW, OUTPUT); pinMode(LED_RED, OUTPUT); Serial.println("ENV MONITOR - Phase 3: LEDs active"); } // Turn off all LEDs, then light exactly one. void setLED(int pin) { digitalWrite(LED_GREEN, LOW); digitalWrite(LED_YELLOW, LOW); digitalWrite(LED_RED, LOW); digitalWrite(pin, HIGH); } void loop() { delay(2000); float humidity = dht.readHumidity(); float tempC = dht.readTemperature(); if (isnan(humidity) || isnan(tempC)) { Serial.println("ERROR: DHT read failed. Check wiring."); return; } // ── Threshold logic ────────────────────────────────────── String status; if (tempC < THRESH_WARN) { setLED(LED_GREEN); status = "OK"; } else if (tempC < THRESH_CRIT) { setLED(LED_YELLOW); status = "WARM"; } else { setLED(LED_RED); status = "HOT"; } Serial.print("Temp: "); Serial.print(tempC, 1); Serial.print(" C Hum: "); Serial.print(humidity, 1); Serial.print(" % Status: "); Serial.println(status); }
  3. Test the threshold transitions.
    In Wokwi: click the DHT22 sensor to open the slider panel. Drag the temperature slider below 25 — the green LED lights. Drag it to 27 — the yellow LED lights and green goes off. Drag above 30 — the red LED lights. Only one LED should be on at a time.
    On real hardware: at room temperature the green LED should be on. Warm the sensor by holding your finger against the DHT11 casing for 30–60 seconds. When your body heat raises the reading past 25 C, the yellow LED should switch on.
More than one LED on at the same time?
  • The setLED() function turns all three off before lighting one. If two are on, check that all three LED_x pin numbers are correctly defined and wired. A wrong pin number means the correct pin goes HIGH but a different physical LED also stays on from a previous iteration.
  • LEDs wired backwards (cathode to pin, anode to GND) will always appear off. Swap the legs — the longer leg (anode) goes to the resistor/Mega side.
  • No LED lights at all: confirm the 220Ω resistors are present. Without them the current may be too low to light the LED (or too high, which can damage the Mega's output pin).
Checkpoint — what you should see
Exactly one LED is lit at any given time. Serial Monitor shows "Status: OK" with green LED on at room temperature (below 25 C). Raising the temperature past 25 C switches to yellow and "WARM". Raising above 30 C switches to red and "HOT". In Wokwi you can test all three transitions instantly using the sensor sliders. On real hardware the green LED is on at typical indoor temperatures.

Add the Buzzer Alert on Critical Conditions
Wire a buzzer to the Mega and sound a pulsing alarm whenever temperature exceeds 30 C or humidity exceeds 80%. The buzzer uses the Arduino tone() function. When conditions return to safe levels the buzzer silences automatically.
  1. Wire the buzzer.
    Real hardware — active vs. passive buzzer: starter kits typically include an active buzzer (has a built-in oscillator; makes sound when you simply apply 5V). Connect the positive leg (longer, or labeled +) to Mega pin 9. Connect the negative leg (shorter, or labeled -) to GND. The tone() function is designed for a passive buzzer. On an active buzzer it does not play the requested pitch — the buzzer ignores the tone() frequency and sounds at its own fixed built-in pitch whenever the pin is driven. If your buzzer sounds wrong (one fixed note, or nothing useful), swap it for a passive buzzer (black epoxy base, no label), which needs the oscillating signal from tone().
    In Wokwi: add a "Buzzer" component (search buzzer). Connect its positive pin to Mega pin 9 and its negative pin to GND. Wokwi's buzzer is passive and responds correctly to tone(). When the alarm fires in simulation you will hear a tone through your computer's speakers.
  2. Paste this updated sketch and upload.
    // Phase 4: DHT sensor + LEDs + buzzer alarm. #include "DHT.h" #define DHTPIN 2 #define DHTTYPE DHT22 // use DHT11 for real DHT11 hardware DHT dht(DHTPIN, DHTTYPE); const int LED_GREEN = 10; const int LED_YELLOW = 11; const int LED_RED = 12; const int BUZZER_PIN = 9; const float THRESH_WARN = 25.0; // yellow threshold (C) const float THRESH_CRIT = 30.0; // red + alarm threshold (C) const float THRESH_HUMIDITY = 80.0; // humidity alarm (%) void setup() { Serial.begin(9600); dht.begin(); pinMode(LED_GREEN, OUTPUT); pinMode(LED_YELLOW, OUTPUT); pinMode(LED_RED, OUTPUT); pinMode(BUZZER_PIN, OUTPUT); Serial.println("ENV MONITOR - Phase 4: Buzzer active"); } void setLED(int pin) { digitalWrite(LED_GREEN, LOW); digitalWrite(LED_YELLOW, LOW); digitalWrite(LED_RED, LOW); digitalWrite(pin, HIGH); } void loop() { delay(2000); float humidity = dht.readHumidity(); float tempC = dht.readTemperature(); if (isnan(humidity) || isnan(tempC)) { Serial.println("ERROR: DHT read failed. Check wiring."); noTone(BUZZER_PIN); return; } // ── Threshold logic ────────────────────────────────────── bool alarm = false; String status; if (tempC < THRESH_WARN) { setLED(LED_GREEN); status = "OK"; } else if (tempC < THRESH_CRIT) { setLED(LED_YELLOW); status = "WARM"; } else { setLED(LED_RED); status = "HOT"; alarm = true; } if (humidity >= THRESH_HUMIDITY) { alarm = true; if (tempC < THRESH_CRIT) { // humidity alarm but temperature still in yellow/green zone status = status + "+HUM"; } } // ── Buzzer ─────────────────────────────────────────────── // tone(pin, frequency_Hz) plays continuously until noTone(). // 880 Hz is a piercing A5 tone, clearly audible as an alarm. if (alarm) { tone(BUZZER_PIN, 880); } else { noTone(BUZZER_PIN); } // ── Serial output ──────────────────────────────────────── Serial.print("Temp: "); Serial.print(tempC, 1); Serial.print(" C Hum: "); Serial.print(humidity, 1); Serial.print(" % Status: "); Serial.print(status); Serial.println(alarm ? " [ALARM]" : ""); }
  3. Test the alarm trigger.
    In Wokwi: open the DHT22 slider panel. Drag the temperature above 30 — the red LED lights, the buzzer sounds through your speakers, and "[ALARM]" appears in Serial Monitor. Drag the humidity above 80 while keeping temperature at 24 — the buzzer sounds even though temperature is in the yellow/green zone. Bring both values back to safe levels — the buzzer stops.
    On real hardware: the alarm fires when conditions go out of range. To test without heating the room to 30 C, temporarily lower the threshold in the code: change THRESH_CRIT to 20.0, upload, and the red LED and buzzer should activate at a typical room temperature. Change it back to 30.0 when done.
Buzzer makes no sound?
  • Active buzzer — continuous tone only: some active buzzers sound the moment you apply power regardless of tone(). Try connecting the positive leg directly to 5V (not via a pin) to test if the buzzer works at all. If it sounds, it is active; use digitalWrite(BUZZER_PIN, HIGH) and digitalWrite(BUZZER_PIN, LOW) instead of tone() / noTone().
  • Pin wiring wrong: confirm the buzzer's positive leg is on pin 9 and negative on GND. Swapping them means the pin can only sink current, not source it through the buzzer.
  • Wokwi speakers: make sure your system volume is not muted. Wokwi emits buzzer sound through your browser's Web Audio API.
  • Conditions not triggering alarm: confirm temperature is above THRESH_CRIT (30.0 C) or humidity above THRESH_HUMIDITY (80%). In Wokwi, drag the sliders past these values.
Checkpoint — what you should see
When temperature exceeds 30 C: red LED is on, buzzer sounds, Serial Monitor shows "[ALARM]". When temperature drops below 30 C and humidity below 80%: buzzer stops, yellow or green LED takes over based on temperature, "[ALARM]" disappears. In Wokwi, all transitions are immediate using the slider panel. The buzzer responds to either trigger independently: high temperature alone triggers it, high humidity alone triggers it, both together trigger it.

Polish: Configurable Thresholds & Live Status Dashboard
Consolidate all thresholds into a single configuration block at the top of the sketch so tuning them never requires hunting through code. Add a formatted Serial Monitor dashboard that prints a clean status line with min/max tracking, making the output look like a real monitoring console.
  1. Paste the complete final sketch. This is the production-ready version of the environmental monitor. All previous phases are included; only the top configuration block and the Serial output format are new.
    // ════════════════════════════════════════════════════════════ // ENV MONITOR v1.0 — Arduino Mega 2560 // Sensor: DHT22 (Wokwi) or DHT11 (real hardware) // Adafruit DHT sensor library v1.4.7 + Adafruit Unified Sensor // ════════════════════════════════════════════════════════════ #include "DHT.h" // ── CONFIGURATION BLOCK — edit only this section to tune ──── #define DHTPIN 2 // DHT DATA wire pin #define DHTTYPE DHT22 // DHT22 for Wokwi; DHT11 for real DHT11 hardware const int LED_GREEN = 10; const int LED_YELLOW = 11; const int LED_RED = 12; const int BUZZER_PIN = 9; // Temperature thresholds (Celsius) const float T_WARN = 25.0; // below this = green / OK const float T_ALARM = 30.0; // above this = red / ALARM // Humidity alarm threshold (%) const float H_ALARM = 80.0; // Buzzer frequency (Hz) — 880 = A5, clearly audible const int BUZZER_HZ = 880; // Sensor read interval (milliseconds) — minimum 2000 for DHT const unsigned long READ_INTERVAL = 2000; // ── END CONFIGURATION ──────────────────────────────────────── DHT dht(DHTPIN, DHTTYPE); float minTemp = 999.0; float maxTemp = -999.0; float minHum = 999.0; float maxHum = -999.0; unsigned long lastRead = 0; unsigned long readCount = 0; void setup() { Serial.begin(9600); dht.begin(); pinMode(LED_GREEN, OUTPUT); pinMode(LED_YELLOW, OUTPUT); pinMode(LED_RED, OUTPUT); pinMode(BUZZER_PIN, OUTPUT); // Start with all outputs off digitalWrite(LED_GREEN, LOW); digitalWrite(LED_YELLOW, LOW); digitalWrite(LED_RED, LOW); noTone(BUZZER_PIN); Serial.println("╔══════════════════════════════╗"); Serial.println("║ ENV MONITOR v1.0 ONLINE ║"); Serial.println("╠══════════════════════════════╣"); Serial.print ("║ Sensor: "); Serial.println(DHTTYPE == DHT22 ? "DHT22 ║" : "DHT11 ║"); Serial.print ("║ T-WARN: "); Serial.print(T_WARN, 1); Serial.println(" C ║"); Serial.print ("║ T-ALARM: "); Serial.print(T_ALARM, 1); Serial.println(" C ║"); Serial.print ("║ H-ALARM: "); Serial.print(H_ALARM,1); Serial.println(" % ║"); Serial.println("╚══════════════════════════════╝"); Serial.println(); } void setLED(int pin) { digitalWrite(LED_GREEN, LOW); digitalWrite(LED_YELLOW, LOW); digitalWrite(LED_RED, LOW); digitalWrite(pin, HIGH); } void loop() { unsigned long now = millis(); if (now - lastRead < READ_INTERVAL) return; lastRead = now; float humidity = dht.readHumidity(); float tempC = dht.readTemperature(); if (isnan(humidity) || isnan(tempC)) { Serial.println("[ERROR] DHT read failed — check wiring and sensor type."); noTone(BUZZER_PIN); return; } readCount++; // Update session min/max if (tempC < minTemp) minTemp = tempC; if (tempC > maxTemp) maxTemp = tempC; if (humidity < minHum) minHum = humidity; if (humidity > maxHum) maxHum = humidity; // ── Threshold logic ────────────────────────────────────── bool alarm = false; String tempStatus; if (tempC < T_WARN) { setLED(LED_GREEN); tempStatus = "OK "; } else if (tempC < T_ALARM) { setLED(LED_YELLOW); tempStatus = "WARM"; } else { setLED(LED_RED); tempStatus = "HOT "; alarm = true; } bool humAlarm = (humidity >= H_ALARM); if (humAlarm) alarm = true; if (alarm) { tone(BUZZER_PIN, BUZZER_HZ); } else { noTone(BUZZER_PIN); } // ── Dashboard line ─────────────────────────────────────── // Format: [NNN] T:24.5C(OK ) H:62.0% Min:21.3/Max:31.0 HUM:OK Serial.print("["); if (readCount < 100) Serial.print("0"); if (readCount < 10) Serial.print("0"); Serial.print(readCount); Serial.print("] T:"); Serial.print(tempC, 1); Serial.print("C("); Serial.print(tempStatus); Serial.print(") H:"); Serial.print(humidity, 1); Serial.print("% Min:"); Serial.print(minTemp, 1); Serial.print("/Max:"); Serial.print(maxTemp, 1); Serial.print(" HUM:"); Serial.print(humAlarm ? "ALARM" : "OK "); Serial.println(alarm ? " *** ALARM ***" : ""); }
  2. Tune the configuration block. All adjustable values live at the top of the sketch between the CONFIGURATION BLOCK comments. Change T_WARN and T_ALARM to match your environment. Change H_ALARM if you are monitoring a space where humidity matters more (server rooms typically alarm at 60%). Change BUZZER_HZ to alter the tone (440 Hz = A4, a lower pitch; 1760 Hz = A6, a higher pitch). After any change, re-upload the sketch.
    Why millis() instead of delay()? The final sketch uses millis() to time the sensor reads instead of delay(2000). This is a better pattern: the Mega is never blocked waiting, so future additions (like button input) can still respond between sensor reads. The behavior is identical for this project.
  3. Observe the live Serial Monitor dashboard.
    In Wokwi: use the DHT22 sliders to move temperature and humidity across thresholds. Watch the dashboard line update every 2 seconds. Notice: the Min/Max columns track the session's extreme values; they only update when a new extreme is reached. After 10+ readings with varied slider positions the Min and Max columns should diverge from the current reading.
    ╔══════════════════════════════╗ ║ ENV MONITOR v1.0 ONLINE ║ ╠══════════════════════════════╣ ║ Sensor: DHT22 ║ ║ T-WARN: 25.0 C ║ ║ T-ALARM: 30.0 C ║ ║ H-ALARM: 80.0 % ║ ╚══════════════════════════════╝ [001] T:24.0C(OK ) H:50.0% Min:24.0/Max:24.0 HUM:OK [002] T:27.3C(WARM) H:52.1% Min:24.0/Max:27.3 HUM:OK [003] T:31.8C(HOT ) H:83.5% Min:24.0/Max:31.8 HUM:ALARM *** ALARM *** [004] T:22.1C(OK ) H:47.0% Min:22.1/Max:31.8 HUM:OK
Sketch won't compile after edits?
  • The most common compile error after editing the configuration block is a missing semicolon. Every line ending with a value must end with ;.
  • If you see "DHT does not name a type": the Adafruit DHT sensor library and Adafruit Unified Sensor dependency are not both installed. Go to Sketch > Include Library > Manage Libraries, search for each, and install both.
  • If isnan() is not recognized: it is part of the standard C math library and should always be available in Arduino IDE. If the error appears, try adding #include <math.h> at the top of the sketch.
  • Min/Max values stuck at 999 or -999: these reset every time the sketch is uploaded because they are stored in RAM (not EEPROM). They accumulate correctly within a single power-on session.
Checkpoint — what you should see
Serial Monitor prints the boot header once showing the configured thresholds, then prints a new numbered dashboard line every 2 seconds. The Min/Max columns update whenever a new session extreme is reached. All three LEDs respond to temperature position relative to the thresholds. The buzzer sounds when temperature exceeds T_ALARM (30 C) or humidity exceeds H_ALARM (80%) and silences when both return to safe levels. Changing values in the configuration block and re-uploading takes effect immediately with no changes needed elsewhere in the sketch.
