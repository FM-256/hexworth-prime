Subject — AI Series Capstone

Build Your First Department

Capstone · L1–5 45 min – 2 hr 300 – 2500 XP
Mission Brief

This is the capstone of the AI series. You have built the four pieces of the AI stack one at a time, an Agent (the brain), a Workflow (the automation), a Knowledge Base (the grounding), and a Tool (the hands). Now you assemble them into something that is more than the sum of its parts: a self-running Help-Desk Department.

The lesson here is multi-agent orchestration, how a team of focused specialists coordinate. A router triages each request and delegates it to the right specialist; agents hand off work with the context intact; a supervisor approves high-impact actions and catches what no agent can handle; and the whole department is observed and improved over time. This is how real AI systems are built, not one giant model trying to do everything, but a team of narrow agents with a coordinator and a human in the loop.

You will grow it across five levels: assemble the team, route the work, make the hand-offs seamless, add supervision and guardrails, then operate and improve it as a live operation. By the end you will have a working department, and you will understand the architecture behind every serious AI system you will build after this.

Prerequisites — Bring Your Four Components
This capstone assembles the projects you have already built. Complete these first, you will wire each one into the department.
  • My First Agent — the brain that converses and decides
  • My First Workflow — the multi-step automation behind the scenes
  • My First Knowledge Base — the grounded answers the department gives
  • My First Tool — the create-ticket action the department takes

Level 1: Assemble the Team
Intermediate~45 min+300 XP
A department isn't one agent, it's several specialists working together. Bring the pieces you already built into one solution: the help-desk Agent (the brain that talks to users), the Knowledge Base (what it knows), the Tool (how it acts, create-ticket), and the Workflow (the automation behind the scenes). Define the department's job and decide which component owns which responsibility.
Skills: system composition, separation of responsibilities, multi-component architecture.
Win conditionAll four components are connected in one department, and you can state in one sentence what each one is responsible for.
Checkpoint — how to verify
List the four components and write one sentence per component naming its single responsibility (Agent: converse and decide; KB: ground answers; Tool: take actions; Workflow: run multi-step automation). Confirm no two components own the same job and nothing is unowned. If two components do the same thing you have redundancy, collapse it; if a needed job has no owner you have a gap, assign it.
✓
2
Level 2: Route the Work
Intermediate+~1 hr+400 XP
With specialists in place you need a coordinator. Build a router (triage) agent that receives every request and sends it to the right specialist: a simple question goes to the KB-grounded answerer, a request to do something goes to the Tool, a complex multi-step case goes to the Workflow. This is multi-agent orchestration, agents handing work to other agents.
Skills: orchestration, triage and routing, agent-to-agent delegation.
Win conditionThree different requests, a question, an action, and a complex case, each get routed to the correct specialist automatically, without you intervening.
Checkpoint — how to verify
Send the department three distinct requests: an informational question, an action request ("create a ticket"), and a multi-step case. Confirm each is routed to the right specialist (check the trace showing which agent handled it). If a request lands on the wrong specialist, sharpen the router's decision criteria, what signals route where.
✓
3
Level 3: Hand-offs and Shared Context
Advanced~1.5 hr+500 XP
When one agent hands work to another, the context has to travel with it, or the next agent makes the user repeat themselves and the department feels broken. Define the hand-off contract: exactly what information passes between agents so work continues seamlessly from one specialist to the next.
Skills: context passing, hand-off contracts, state continuity across agents.
Win conditionA case that passes through two agents keeps its context, the second agent never asks the user for something the first already collected.
Checkpoint — how to verify
Run a case that requires two agents (triage gathers the problem, a resolver acts on it). Confirm the second agent uses the details the first collected and does NOT re-ask the user. If the second agent re-asks, the hand-off is dropping context, add the missing fields to what passes between them and re-run.
✓
4
Level 4: Supervision and Guardrails
Advanced~2 hr+600 XP
An autonomous department needs a supervisor. Add a layer that requires human approval before high-impact actions, escalates to a person when no agent can handle a case, and sets hard limits so the department can't loop or run away. This is what makes a multi-agent system safe to actually run.
Skills: supervisor pattern, human-in-the-loop approval, escalation paths, runaway limits.
Guardrails. High-impact actions require human approval before they run. Any case no agent can resolve escalates to a human, it is never silently dropped or guessed at. The department has hard step/hand-off limits so it cannot loop forever.
Win conditionA high-impact request pauses for approval, an unhandleable case escalates to a human with its full context, and a request that would loop is stopped by a limit instead of running away.
Checkpoint — how to verify
Trigger a high-impact action and confirm it waits for human approval before executing. Send a request no specialist can handle and confirm it escalates to a human with the context attached (not dropped, not guessed). Confirm a max-steps / max-handoff limit exists and stops a runaway case. If any of these fails, an action fires without approval, a case vanishes, or it loops, add the missing supervisor control.
✓
5
Level 5: Operate and Improve the Department
Pro~2 hr+700 XP
A real department is measured and improved. Add observability across all the agents, logs and a dashboard showing what came in, who handled it, and how it ended. Measure the resolution rate, find where the department fails most, and feed fixes back: re-train the KB, fix a tool, adjust the router. Run it as a live operation that gets better over time.
Skills: cross-agent observability, metrics (resolution rate), failure analysis, the improve loop.
Guardrails. Every request and every agent action is logged, nothing the department does is invisible. A failed or escalated case is recorded honestly, never hidden, so the failure can be found and fixed.
Win conditionA dashboard or log shows each case end-to-end across every agent that touched it, you can state your department's resolution rate, and you have made at least one improvement based on what the data showed.
Checkpoint — how to verify
Open the department's logs/dashboard and trace one case from arrival to resolution across every agent that touched it. State the resolution rate (resolved vs escalated) over your test cases. Identify the single biggest failure source and make one fix (a KB gap, a tool error, or a routing rule), then confirm that case type now succeeds. If you can't trace a case end-to-end, your observability has a blind spot, add logging where the trail goes cold.
