Subject — AI Series Capstone

Build Your First Department

Capstone · L1–5 45 min – 2 hr 300 – 2500 XP
Mission Brief

This is the capstone of the AI series. You have built the four pieces of the AI stack one at a time, an Agent (the brain), a Workflow (the automation), a Knowledge Base (the grounding), and a Tool (the hands). Now you assemble them into one working agent: a Help-Desk Department Agent that handles real requests end to end.

The lesson here is single-agent integration: how one well-built agent can route different request types through Topics, answer questions from a Knowledge source, call a Tool to take action, escalate to a human when it cannot help, and continuously improve based on what you observe in testing. This is the architecture pattern behind every practical AI assistant you will build: one agent with structured routing, grounded knowledge, callable tools, and a human safety net.

You will grow it across five levels: assemble the pieces, route the work with Topics, wire the Tool and pass context, add a confirmation gate and an escalation path, then observe and improve the agent through the Test pane. By the end you will have a working Help-Desk agent and a repeatable method for diagnosing and fixing gaps.

Level 1: Assemble the Team
Intermediate~45 min+300 XP
A single well-structured agent can behave like a whole department by routing different request types through different Topics. You will create the Help-Desk agent in Copilot Studio, attach the Knowledge source from your Knowledge-Base project, and verify that the agent's instructions describe its scope clearly.
  1. Sign in. Go to copilotstudio.microsoft.com and sign in with your work or school account.
  2. Create the Help-Desk agent. On the Home page, select Create an agent under "Start building from scratch." In the name field type Help Desk, then select Create. Copilot Studio provisions the agent and opens its Overview page.
  3. Write the agent instructions. In the Instructions section of the Overview page, select Edit. Paste the text below exactly, then select Save.
    You are the Help Desk agent for a small IT department. Your job is to answer IT support questions using the knowledge base, create support tickets when a user reports a problem, and escalate to a human when you cannot resolve an issue. Do not guess at answers. If the knowledge base does not contain the answer, say so and escalate.
  4. Add the Knowledge source. Select Knowledge in the left navigation. Select Add knowledge. In the dialog choose the source type you used in your Knowledge-Base project (Public website URL or uploaded file). Enter the URL or upload the file, give the source the name IT Help Desk FAQ, and select Add. Wait for the status to show Ready.
  5. Open the Test pane. Select Test at the top of the page. The Test your agent panel opens on the right.
  6. Send a test question that your knowledge source can answer, for example: How do I reset my password? The agent should reply with content from your knowledge source, not a generic response.
Agent says "I don't know" even though the answer is in your knowledge source?
  • Check the Knowledge page — the source status must say Ready, not Indexing. Indexing can take several minutes after you add a source.
  • Confirm the knowledge source name and description are filled in. Generative orchestration uses the description to decide when to search each source — a blank description means the agent may skip it.
  • Select Reset (the circular arrow at the top of the Test pane) to clear the conversation and start fresh after any change.
Checkpoint — what you should see
The Test pane shows the agent answering a question with content drawn from your knowledge source. The agent's name reads Help Desk in the top-left of the studio. The Knowledge page shows at least one source with status Ready.

Level 2: Route the Work with Topics
Intermediate+~1 hr+400 XP
With the agent and knowledge in place, you now define routing logic. You will create two Topics that give the agent explicit paths for the two most common request types: "I have a problem (create a ticket)" and "I need information (search the KB)." Generative orchestration selects the right topic automatically based on what the user types.
  1. Open Topics. In the left navigation, select Topics. You see a list of system topics that Copilot Studio created automatically.
  2. Create the Create-Ticket topic. Select Add a topic > From blank. A Trigger node appears on the canvas.
  3. Add trigger phrases. Select the three dots (...) on the Trigger node, select Properties, then select the Phrases area. Add the following phrases one per line:
    I have a problem something is broken I need to report an issue create a ticket open a support request
    Select outside the panel to close it.
  4. Name the topic. Select Details on the toolbar, set the Name to Create Support Ticket, and set the Description to User reports a problem and wants a support ticket created. Select Save.
  5. Add a Question node. Under the Trigger node, select the + icon and choose Ask a question. In the question field type: What is the issue you are experiencing? Please describe it briefly. Under Identify, select User's entire response. Copilot Studio automatically creates an output variable with a default name such as Var1.
  6. Rename the variable to IssueDescription. Select the variable name in the Question node (the pill that shows the auto-generated name). The Variable properties panel opens on the right. Under Variable name, clear the existing text and type IssueDescription, then press Enter or click away to save. The variable is now referenced as Topic.IssueDescription throughout this topic. You will need this exact name in Phase 3 when you map it to the tool input.
  7. Add a Message node below the Question node. Select + > Send a message. Type: Got it. I am creating a support ticket for: {Topic.IssueDescription}. A technician will follow up with you shortly.
  8. Save the topic. Select Save in the top bar.
  9. Test routing. Open the Test pane, select Reset, then type: I have a problem with my laptop. The agent should enter the Create Support Ticket topic and ask you to describe the issue.
  10. Repeat for an informational request. Reset the Test pane and type: How do I connect to the VPN? The agent should answer from the knowledge source instead of entering the ticket topic, because the trigger phrases do not match.
Both questions trigger the ticket topic (or neither does)?
  • In generative orchestration mode (the default), the agent matches based on meaning, not exact words. If the topic description says "user reports a problem," phrases like "something is not working" will match it even without being in the trigger list.
  • If the topic is never triggered, confirm the topic is turned on. On the Topics page, the toggle to the right of the topic name must be enabled.
  • If the topic fires for informational questions, tighten the description: make it say "user explicitly asks to create or open a ticket" rather than just "user has a problem."
Checkpoint — what you should see
Typing I need to report a broken printer in the Test pane starts the Create Support Ticket topic and the agent asks for a description. Typing How do I reset my password? returns an answer from the knowledge source without entering the ticket topic. Two different request types, two different paths.

Level 3: Wire the Tool and Pass Context
Advanced~1.5 hr+500 XP
Right now the Create Support Ticket topic only sends a message. You will connect it to the real Tool from your My First Tool project (a Power Automate flow that actually creates a ticket), and make sure the description the user typed is passed into the flow so the ticket contains real information.
  1. Open your agent's Tools page. In the left navigation, select Tools. This shows all tools connected to the Help Desk agent.
  2. Connect your existing My First Tool flow. Select Add a tool. In the Add tool pane, select Flow to show the list of your published flows. Locate the flow you built in the My First Tool project (it must be published in Power Automate to appear here), select it, then select Add and configure.
    The flow does not appear in the list?
    • The flow must be published (turned on) in Power Automate and must use the When an agent calls the flow trigger. Flows with other triggers (manual, recurrence, etc.) do not appear here.
    • If you have not yet built the My First Tool flow, create one now: in the Add tool pane, select New tool > Agent flow. Power Automate opens a new flow with the correct trigger pre-set. Add an input called IssueDescription (type: Text), add a Send email or Create item action as a stand-in, then publish and return here to add it.
  3. Name and describe the tool. On the tool configuration page, set the Name to Create Ticket. Set the Description to Creates a support ticket in the ticketing system. Use this when a user reports a problem and wants a ticket opened. The description is what generative orchestration reads to decide when to call this tool. Select Save.
  4. Edit the Create Support Ticket topic to call the tool. Go to Topics, open the Create Support Ticket topic. Delete the Message node you added in Phase 2 (select its three dots > Delete). In its place, select + > Add a tool and choose the Create Ticket tool you just configured.
  5. Map the input. In the tool node, find the input that expects an issue description. Set its Fill using to Custom value and pick the variable Topic.IssueDescription from the variable picker. This passes what the user typed directly into the flow.
  6. Add a confirmation message below the tool node: Done — your ticket has been created. A technician will follow up with you shortly.
  7. Save the topic and open the Test pane. Select Reset, type My monitor is flickering, describe it when asked, then watch the tool node fire.
The tool node shows an error or asks you to authorize a connection?
  • Some connectors (SharePoint, Outlook, etc.) require you to sign in. In the tool configuration page, under Authentication, select Sign in and complete the OAuth flow for your account.
  • If using End user credentials, the Test pane will prompt you to sign in before the tool can run. Select Manage connections at the top of the test panel (three-dot menu) and authorize the connection.
  • If the flow itself does not exist yet, create a simple Power Automate cloud flow with one input variable called IssueDescription and a Create item or Send email action as a stand-in for the ticket system.
Checkpoint — what you should see
In the Test pane, after reporting an issue and describing it, the agent's tool node fires and the confirmation message appears. The issue description the user typed is visible in the tool node's inputs (select the node in the canvas to inspect). The variable Topic.IssueDescription was passed from the Question node into the tool call without asking the user to repeat themselves.

Level 4: Supervision and the Escalation Path
Advanced~2 hr+600 XP
An autonomous department needs a safety net. You will configure two things: a human-escalation topic that fires when the agent cannot handle a request, and an approval gate that pauses the ticket-creation tool and asks the user to confirm before the ticket is actually submitted.
  1. Enable confirmation on the Create Ticket tool. Go to Tools, open the Create Ticket tool. Under Details, find Ask the end user before running and set it to Yes. Save. Now when the agent is about to call the tool it will show the user a confirmation card and wait for approval before proceeding.
  2. Test the approval gate. Open the Test pane, select Reset, report a problem. When the agent is ready to create the ticket it will say something like "I am going to create a support ticket. Do you want to proceed?" Select Yes to confirm, then verify the tool fires. Select No in a separate test — the tool should not fire.
  3. Create the Escalation topic. Go to Topics > Add a topic > From blank. Name it Escalate to Human, description: Use when the agent cannot answer the question and a human technician must take over.
  4. Add trigger phrases on the Escalation topic:
    I need to speak to a person transfer me to a technician this is urgent none of that helped
  5. Add a Message node: I am transferring you to a human technician now. Please stay on the line.
  6. Add an End Conversation node. Select + > Topic management > Transfer to agent. In the Private message to agent field type: Customer was unable to resolve issue through self-service. Please review the conversation above. Select Save.
  7. Update the main agent instructions to reference escalation. Go to Overview > Instructions > Edit and add to the bottom:
    If you cannot find an answer in the knowledge base and the issue cannot be resolved by creating a ticket, tell the user you are escalating and use the Escalate to Human topic. Never guess at answers. Never silently drop a request.
  8. Test escalation. Reset the Test pane. Type: I need to speak to a person. The agent should enter the Escalate to Human topic and display the transfer message.
The Transfer to agent node is greyed out or unavailable?
  • The Transfer to agent capability requires a configured handoff integration (such as Omnichannel for Customer Service or a Teams channel). In the trial environment it is available in the canvas but the actual transfer will not route to a live person without that integration.
  • As a stand-in for the trial: replace the Transfer node with a Message node that reads "A technician has been notified and will contact you shortly" and an End conversation node. The behavior from the user's perspective is identical; only the backend routing differs.
Checkpoint — what you should see
Ticket creation now pauses for user confirmation before the tool fires. Typing "I need to speak to a person" in the Test pane enters the Escalate to Human topic and displays the transfer message. Two guardrails are active: an approval gate before high-impact actions, and an explicit escalation path for cases the agent cannot handle.

Level 5: Observe, Diagnose, and Improve
Pro~2 hr+700 XP
A real department is always improving. In this level you run a structured battery of test conversations, read the Test pane results directly (the Analytics dashboard does not capture Test-pane activity on a trial), identify a specific gap in your agent, make one targeted fix, then re-run the same conversation to confirm the improvement. The observable evidence is the before and after behavior in the Test pane itself.
Why you will not use the Analytics dashboard here: Per Microsoft documentation, the Copilot Studio Analytics page explicitly excludes activity from the Test pane — the dashboard only populates from conversations in published channels. Because the trial does not allow publishing, your Analytics page will show no data regardless of how many test conversations you run. This level uses the Test pane as your measurement instrument instead. The improvement loop is identical; only the data source differs.
  1. Design a test battery of five conversations. Before you open the Test pane, write down five specific inputs that cover all paths your agent should handle:
    Conversation A: a question your knowledge source can answer (e.g. "How do I reset my password?") Conversation B: a problem report that triggers the Create Support Ticket topic (e.g. "My monitor is not turning on") Conversation C: a deliberate escalation trigger (e.g. "I need to speak to a person") Conversation D: a question your knowledge source probably cannot answer (e.g. a very specific policy question not in your FAQ) Conversation E: an ambiguous input that could go either way (e.g. "I have a question about my computer")
    Writing these down first lets you compare before/after results objectively.
  2. Run Conversation A through E. Open the Test pane, select Reset, then run each conversation. After each one, note the result:
    • Did the agent give a correct, grounded answer?
    • Did the right topic trigger?
    • Did the tool call fire and return a confirmation?
    • Did escalation work cleanly?
    • What happened on the ambiguous input — which path did it take?
  3. Tally your results. Count how many of the five conversations reached their intended outcome without the agent giving a wrong answer, routing to the wrong topic, or failing silently. Write down your score (e.g. "3 of 5 resolved correctly"). This is your baseline.
  4. Identify the single biggest failure. Choose one conversation that produced the worst outcome. Diagnose the root cause using this decision tree:
    Agent said "I don't know" when KB should have answered → Knowledge source may be missing the answer, or description is blank → Fix: Knowledge page > edit source or add a new one Wrong topic fired (e.g. KB question triggered ticket creation) → Topic description or trigger phrases are too broad → Fix: Topics page > open that topic > tighten the description Agent never asked for the issue description / skipped the Question node → Topic may not be enabled, or the trigger is too narrow → Fix: Topics page > confirm the topic toggle is ON; add more trigger phrases Tool call failed or produced an error → Flow may not be published, or the input variable name does not match → Fix: Power Automate > confirm flow is ON; re-check IssueDescription input mapping Escalation topic did not fire when user typed the escalation phrase → Topic toggle is off, or the phrase did not match → Fix: Topics page > Escalate to Human > add the exact phrase the user typed
  5. Make one fix. Apply only the fix that addresses the root cause you identified. Avoid changing multiple things at once — you want to know which change made the difference.
    • Knowledge gap: Knowledge page > edit the source description or add a new source.
    • Routing error: Topics > open the topic > improve the description and/or trigger phrases > Save.
    • Instructions too vague: Overview > Instructions > Edit > add a more specific directive > Save.
    • Variable or tool mismatch: correct the input mapping as described in Phase 3.
  6. Re-run the conversation that failed. Reset the Test pane and send the exact same input that failed before. Confirm the agent now reaches the intended outcome.
  7. Record your final score. Re-run all five conversations and tally again. Write down the new score (e.g. "5 of 5 resolved correctly"). The improvement from your baseline to your final score is the measurable result of this level. Your checkpoint below will ask you to state both numbers.
Checkpoint — what you should see
You can state both your before and after scores (e.g. "3 of 5 baseline → 5 of 5 after fix"). You identified one specific root cause, made one targeted change, and confirmed in the Test pane that the failing conversation now succeeds. The improvement loop — observe, diagnose, fix, verify — is the same process used in production; only the data source changes when a paid channel is available.
