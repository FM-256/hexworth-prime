Subject

Build a Port Scanner in Python

Recruit 60 min 250 XP
Mission Brief

In this project you will write a Python port scanner from scratch using only the standard library — no pip install, no third-party packages. Starting with a single raw socket connection, you will progressively build the tool up to a concurrent, multi-threaded scanner that sweeps thousands of ports in seconds, grabs service banners, and produces clean structured JSON output you can pipe into other scripts.

Port scanning is the first active step in any security engagement. It reveals which services a host is exposing and defines the attack surface for the next move. Building one from scratch means you will understand exactly what packets are sent, why connect_ex returns 0 for an open port versus errno.ECONNREFUSED for a refused connection, and how defenders see this traffic in their IDS logs. That knowledge makes you a better operator and a better defender.

Every phase produces a runnable script that you verify against 127.0.0.1 (your own machine) before moving on. By the final phase you have a real command-line tool driven by argparse with configurable targets, port ranges, thread counts, timeout values, banner grabbing, and JSON or table output.

Authorization Required — Read Before Running Any Script

Port scanning without explicit written authorization is illegal in most jurisdictions. In the United States the Computer Fraud and Abuse Act (CFAA) makes unauthorized network scanning a federal crime. The EU Network and Information Security Directive and equivalent national laws carry similar penalties. Many ISPs and cloud providers also prohibit scanning in their acceptable-use policies, regardless of the target.

Only run the scripts in this project against one of these three target classes:

  • Your own machine — 127.0.0.1 or localhost. This is the primary target throughout all six phases. You own it. No authorization paperwork required.
  • A VM you control on an isolated lab network — a VirtualBox or VMware guest with host-only or internal networking. You own the host OS and the guest. Still no external connectivity to worry about.
  • A target that explicitly grants written permission for your type of scan — for example, a penetration testing engagement contract, a Hack The Box machine you have activated, or a lab range provided by your instructor. Keep documentation of the permission.

Hexworth Prime builds offensive skills for defensive understanding and authorized penetration testing. Scanning production systems, cloud instances, or networks belonging to others without written authorization is illegal and will get you banned, prosecuted, or both. When in doubt, scan localhost.

Agent Requirements
  • Python 3.11 or newer — verify with python3 --version. The scripts use only socket, concurrent.futures, threading, argparse, json, errno, and time. Zero pip installs required.
  • Python fundamentals: variables, loops, functions, importing modules. You do not need to know about sockets yet — this project teaches that from zero.
  • Basic TCP/IP understanding: what an IP address and port number represent. You should know that port 22 is usually SSH and port 80 is usually HTTP, but nothing beyond that is assumed.
  • Comfortable running scripts from a terminal and reading error messages. If you can run python3 hello.py and read a traceback, you are ready.
  • A terminal on macOS, Linux, or Windows (WSL2 recommended on Windows). All commands shown work on any of these platforms.
  • No root or administrator privileges required. TCP connect scanning works as a normal user.

One Socket, One Port — TCP Connect Basics
Open a raw TCP socket with Python's socket module and attempt one connection. Learn what connect_ex returns for open, closed, and filtered ports, and why you must set a timeout to avoid hanging forever.
  1. Create the script. Open a new file called scan1.py and paste this complete script:
    #!/usr/bin/env python3 """ scan1.py -- Phase 1: connect to one TCP port and report its state. Run only against systems you own or have written authorization to test. """ import socket import errno TARGET = "127.0.0.1" # localhost -- a machine you own PORT = 22 # try 22, 80, 8080, or any port you know about TIMEOUT = 1.0 # seconds before we give up and call it filtered sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM) sock.settimeout(TIMEOUT) # connect_ex returns 0 on success (open) or an OS errno on failure result = sock.connect_ex((TARGET, PORT)) sock.close() if result == 0: print(f"{TARGET}:{PORT} OPEN") elif result == errno.ECONNREFUSED: # errno.ECONNREFUSED = TCP RST received (111 on Linux, 61 on macOS, 10061 on Windows) print(f"{TARGET}:{PORT} CLOSED (connection refused)") else: # any other non-zero errno, including ETIMEDOUT, means filtered print(f"{TARGET}:{PORT} FILTERED / ERROR (errno {result})")
  2. Run it against a closed port first to see the refused response:
    python3 scan1.py
    With PORT = 22 on a machine with no SSH server running, you get:
    127.0.0.1:22 CLOSED (connection refused)
    Why errno.ECONNREFUSED? When no process is listening on the target port, the OS kernel immediately sends back a TCP RST packet. Python receives this as the symbolic constant errno.ECONNREFUSED, which resolves to the correct numeric value per platform: 111 on Linux, 61 on macOS, and 10061 on Windows. Using the symbolic constant makes the script portable across all three. This response arrives in milliseconds — much faster than a timeout. ECONNREFUSED is unambiguous: the host is up, but nothing is listening on that port.
  3. Test against an open port. Start a quick listening server in a second terminal, then re-run the scanner. The server just needs to accept the connection; it does not need to send anything:
    # Terminal 2: start a listener on port 9001 python3 -m http.server 9001
    Now edit scan1.py, set PORT = 9001, and run:
    127.0.0.1:9001 OPEN
    Stop the listener (Ctrl+C in terminal 2) and run again — you get CLOSED immediately.
  4. Understand the three outcomes. connect_ex has exactly three meaningful results:
    0 -- open: TCP SYN sent, SYN-ACK received, connection established errno.ECONNREFUSED -- closed: TCP SYN sent, RST received back from the OS kernel errno.ETIMEDOUT -- filtered: TCP SYN sent, nothing received until our timeout expires
    Filtered vs. closed: a firewall that silently drops packets produces errno.ETIMEDOUT after your full timeout period. A closed port produces errno.ECONNREFUSED in milliseconds. The difference tells you whether a firewall is sitting between you and the host. Slow scans with many timeouts usually mean a firewall in the path.
Trap: never use connect() directly for scanning.
  • Use connect_ex(), not connect(). The regular connect() raises a ConnectionRefusedError exception that you would have to catch with a try/except for every port. connect_ex() returns the errno as an integer instead, which is cleaner to test in a loop across many ports.
  • Always call sock.settimeout() before connect_ex(). Without a timeout, a filtered port will block the script forever. Start with 1.0 second for localhost and a VM, and tune down to 0.3–0.5 for faster scans once you add threading in Phase 4.
  • Always call sock.close() after the connection attempt, even when the port is closed. Failing to close sockets accumulates file descriptors and you will hit the OS per-process limit during long scans.
Checkpoint — what you should see
With no listener running, python3 scan1.py (PORT = 22) prints 127.0.0.1:22 CLOSED (connection refused) in under 50ms. After starting python3 -m http.server 9001 and setting PORT = 9001, it prints 127.0.0.1:9001 OPEN. Both results appear instantly — no waiting. Mark this phase complete and move on.

Port Range Scanning — Parse Specs and Loop
Accept a port specification string like 22,80,443 or 1-1024 on the command line, iterate through every port in the range, and print a live status line for each result. Collect open ports into a results list for the summary.
  1. Create scan2.py with this complete script:
    #!/usr/bin/env python3 """ scan2.py -- Phase 2: scan a port range on localhost sequentially. Usage: python3 scan2.py 127.0.0.1 1-1024 python3 scan2.py 127.0.0.1 22,80,443,8080 Run only against systems you own or have written authorization to test. """ import socket import sys def parse_ports(spec): """Parse '22,80,443' or '1-1024' or '22,80,100-200' into a sorted list.""" ports = set() for part in spec.split(','): part = part.strip() if '-' in part: lo, hi = part.split('-', 1) ports.update(range(int(lo), int(hi) + 1)) else: ports.add(int(part)) return sorted(ports) def scan_port(host, port, timeout=0.5): """Return True if the port is open, False otherwise.""" sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM) sock.settimeout(timeout) result = sock.connect_ex((host, port)) sock.close() return result == 0 if len(sys.argv) != 3: print("Usage: python3 scan2.py <host> <ports>") print(" <ports> examples: 22,80,443 or 1-1024") sys.exit(1) host = sys.argv[1] ports = parse_ports(sys.argv[2]) print(f"Scanning {host} -- {len(ports)} ports") print("-" * 40) open_ports = [] for port in ports: is_open = scan_port(host, port) if is_open: open_ports.append(port) print(f" {port:<6}/tcp OPEN") else: # print closed ports only if scanning a small range if len(ports) <= 20: print(f" {port:<6}/tcp closed") print("-" * 40) print(f"Found {len(open_ports)} open port(s): {open_ports}")
  2. Start a few listeners in separate terminals so the scan has something to find:
    # Terminal 2 python3 -m http.server 8080 # Terminal 3 python3 -m http.server 9090
  3. Run a small named-port scan to see open and closed mixed:
    python3 scan2.py 127.0.0.1 22,80,443,8080,9090,9999
    Expected output (your open ports will differ based on what is running on your machine):
    Scanning 127.0.0.1 -- 6 ports ---------------------------------------- 22 /tcp closed 80 /tcp closed 443 /tcp closed 8080 /tcp OPEN 9090 /tcp OPEN 9999 /tcp closed ---------------------------------------- Found 2 open port(s): [8080, 9090]
  4. Run a range scan. This takes a moment because it runs sequentially:
    python3 scan2.py 127.0.0.1 8000-9100
    With listeners on 8080 and 9090:
    Scanning 127.0.0.1 -- 1101 ports ---------------------------------------- 8080 /tcp OPEN 9090 /tcp OPEN ---------------------------------------- Found 2 open port(s): [8080, 9090]
    Why is a 1000-port sequential scan slow? Each connection attempt waits up to 0.5 seconds for a response before moving on. On localhost where everything responds immediately (open or refused), 1000 ports takes roughly 1–2 seconds total. Against a real host across a network where some ports are filtered, that same 1000 ports could take minutes because you wait the full timeout for each filtered port. Phase 4 solves this with threads.
Trap: the format specifier :< in f-strings.
  • The line print(f" {port:<6}/tcp OPEN") uses Python's f-string alignment: :<6 means left-align in a 6-character-wide field. This keeps the columns tidy. If you get a ValueError on this line, you are on Python 3.5 or older — upgrade to 3.11+.
  • The parse_ports function handles three input formats: comma-separated (22,80), a hyphen range (1-1024), and combinations (22,80,100-200). Using a set internally deduplicates overlapping specs before sorting.
Checkpoint — what you should see
With two listeners running, python3 scan2.py 127.0.0.1 22,80,443,8080,9090,9999 prints exactly two OPEN lines matching your listeners and four closed lines. The final summary correctly counts 2 open ports. The parse_ports function returns sorted, deduplicated integers for any spec format. Mark done and proceed to Phase 3.

Timeouts and the Three Port States
Distinguish cleanly between open, closed, and filtered using the errno module. Handle the case where a port neither responds nor refuses — a filtered port will block your scan for the full timeout period if you do not tune carefully.
  1. Create scan3.py with explicit errno classification:
    #!/usr/bin/env python3 """ scan3.py -- Phase 3: classify open / closed / filtered with errno codes. Run only against systems you own or have written authorization to test. """ import socket import errno import sys import time def classify_port(host, port, timeout=0.5): """ Returns a tuple: (state_string, elapsed_seconds) States: 'open', 'closed', 'filtered' """ sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM) sock.settimeout(timeout) t0 = time.monotonic() code = sock.connect_ex((host, port)) elapsed = time.monotonic() - t0 sock.close() if code == 0: return "open", elapsed elif code == errno.ECONNREFUSED: # RST received -- resolves per OS return "closed", elapsed elif code in (errno.ETIMEDOUT, # 110 -- timed out waiting errno.EHOSTUNREACH, # 113 -- no route to host 10060): # 10060 = WSAETIMEDOUT on Windows return "filtered", elapsed else: return f"unknown(errno {code})", elapsed def parse_ports(spec): ports = set() for part in spec.split(','): part = part.strip() if '-' in part: lo, hi = part.split('-', 1) ports.update(range(int(lo), int(hi) + 1)) else: ports.add(int(part)) return sorted(ports) if len(sys.argv) < 3: print("Usage: python3 scan3.py <host> <ports> [timeout_secs]") sys.exit(1) host = sys.argv[1] ports = parse_ports(sys.argv[2]) timeout = float(sys.argv[3]) if len(sys.argv) > 3 else 0.5 print(f"Scanning {host} -- {len(ports)} ports -- timeout {timeout}s per port") print(f"{'PORT':<8} {'STATE':<12} {'ELAPSED'}") print("-" * 36) results = {"open": [], "closed": 0, "filtered": 0} for port in ports: state, elapsed = classify_port(host, port, timeout) if state == "open": results["open"].append(port) flag = " <-- OPEN" elif state == "filtered": results["filtered"] += 1 flag = " (no response)" else: results["closed"] += 1 flag = "" print(f" {port:<6}/tcp {state:<12} {elapsed*1000:.1f}ms{flag}") print("-" * 36) print(f"Open: {results['open']} Closed: {results['closed']} Filtered: {results['filtered']}")
  2. Test with localhost listeners running (keep them from Phase 2 or start new ones):
    python3 scan3.py 127.0.0.1 22,80,8080,9090,9999
    Expected output (with listeners on 8080 and 9090):
    Scanning 127.0.0.1 -- 5 ports -- timeout 0.5s per port PORT STATE ELAPSED ------------------------------------ 22 /tcp closed 0.1ms 80 /tcp closed 0.1ms 8080 /tcp open 0.0ms <-- OPEN 9090 /tcp open 0.1ms <-- OPEN 9999 /tcp closed 0.0ms ------------------------------------ Open: [8080, 9090] Closed: 3 Filtered: 0
    Notice the timing. Closed ports respond in under 1ms because the kernel sends an RST immediately. Open ports take slightly longer because the TCP handshake completes. Filtered ports would take the full 500ms timeout. This timing difference is why defenders can detect scanning: hundreds of connections per second to random ports is not normal application traffic.
  3. Tune the timeout for your environment. For localhost, 0.1 seconds is plenty:
    python3 scan3.py 127.0.0.1 8000-9100 0.1
    For a VM on a local network, use 0.3–0.5 seconds. For hosts across the internet on an authorized test, use 1.0–2.0 seconds to account for latency. Never set timeout below 0.05 seconds — even localhost occasionally needs a few milliseconds and you will get false filtered results.
Trap: filtered ports kill scan speed.
  • On a real network, firewall-protected ports produce errno 110 (ETIMEDOUT) after your full timeout value. If you scan 10,000 ports with a 1-second timeout and 9,000 are filtered, that is 9,000 seconds of waiting — 2.5 hours. The solution is threading (Phase 4), which runs hundreds of these waits in parallel rather than one at a time.
  • On localhost, you will almost never see filtered results because the loopback interface processes every packet immediately and either accepts or rejects it. Filtered is primarily a network phenomenon (firewalls) not a localhost phenomenon.
  • Windows uses errno 10060 (WSAETIMEDOUT) instead of errno 110 (ETIMEDOUT). The script above handles both. If you are on Windows and see unexpected "unknown(errno X)" results, print the errno and add it to the filtered set.
Checkpoint — what you should see
Running python3 scan3.py 127.0.0.1 22,80,8080,9090,9999 with listeners on 8080 and 9090 shows exactly those two ports as open with sub-millisecond elapsed times. Closed ports also report in under 2ms. No port shows "filtered" because localhost does not firewall packets. The errno classification correctly separates all three states.

Concurrent Scanning with ThreadPoolExecutor
Replace the sequential loop with a ThreadPoolExecutor to fire hundreds of connection attempts simultaneously. See the speed difference, understand why thread count needs tuning, and collect results thread-safely using a list guarded by a lock.
  1. Create scan4.py with concurrent execution:
    #!/usr/bin/env python3 """ scan4.py -- Phase 4: concurrent port scanning with ThreadPoolExecutor. Run only against systems you own or have written authorization to test. """ import socket import errno import sys import time import threading from concurrent.futures import ThreadPoolExecutor, as_completed # Thread-safe accumulator for open port records results_lock = threading.Lock() open_ports = [] def parse_ports(spec): ports = set() for part in spec.split(','): part = part.strip() if '-' in part: lo, hi = part.split('-', 1) ports.update(range(int(lo), int(hi) + 1)) else: ports.add(int(part)) return sorted(ports) def scan_one(host, port, timeout): """ Scan a single port. Returns (port, state) where state is 'open', 'closed', or 'filtered'. Called from the thread pool. """ sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM) sock.settimeout(timeout) code = sock.connect_ex((host, port)) sock.close() if code == 0: return port, "open" elif code == errno.ECONNREFUSED: return port, "closed" else: return port, "filtered" if len(sys.argv) < 3: print("Usage: python3 scan4.py <host> <ports> [threads] [timeout]") print(" threads default: 100 timeout default: 0.5s") sys.exit(1) host = sys.argv[1] port_list = parse_ports(sys.argv[2]) max_workers = int(sys.argv[3]) if len(sys.argv) > 3 else 100 timeout = float(sys.argv[4]) if len(sys.argv) > 4 else 0.5 print(f"Scanning {host} -- {len(port_list)} ports -- {max_workers} threads -- timeout {timeout}s") t_start = time.monotonic() with ThreadPoolExecutor(max_workers=max_workers) as executor: # Submit every port scan as a separate future futures = {executor.submit(scan_one, host, p, timeout): p for p in port_list} for future in as_completed(futures): port, state = future.result() if state == "open": with results_lock: open_ports.append(port) elapsed = time.monotonic() - t_start open_ports.sort() print(f"\nCompleted in {elapsed:.2f}s") print(f"Open ports: {open_ports}") print(f"Total scanned: {len(port_list)}") if open_ports: for p in open_ports: print(f" {p}/tcp OPEN")
  2. Start listeners, then run a large concurrent scan:
    # Terminal 2 python3 -m http.server 8080 # Terminal 3 python3 -m http.server 9090
    python3 scan4.py 127.0.0.1 1-10000 200 0.3
    Expected output (timing varies by machine; the key is the speed):
    Scanning 127.0.0.1 -- 10000 ports -- 200 threads -- timeout 0.3s Completed in 0.68s Open ports: [8080, 9090] Total scanned: 10000 8080/tcp OPEN 9090/tcp OPEN
    The speed difference is dramatic. The same 10,000-port scan done sequentially at 0.5s timeout would take up to 83 minutes if everything were filtered. With 200 threads it completes in under a second against localhost (where nothing is filtered). Against a real network target the improvement is the same — all the waits run in parallel instead of serially.
  3. Tune thread count for your environment. Try different values and observe:
    python3 scan4.py 127.0.0.1 1-5000 50 0.3 python3 scan4.py 127.0.0.1 1-5000 200 0.3 python3 scan4.py 127.0.0.1 1-5000 500 0.3
    On most Linux/macOS systems, the sweet spot for local scanning is 100–300 threads. Above that, thread-creation overhead and OS socket limits start to slow things down rather than speed them up. The default OS limit for open files (which includes sockets) is typically 1024. Check yours:
    ulimit -n
    Keep max_workers well under that number, or raise the limit with ulimit -n 4096 before running.
  4. Understand thread safety. The results_lock protects open_ports from concurrent list appends. In CPython, simple list appends are actually thread-safe due to the GIL, but the lock is explicit best practice. For any more complex shared state (dicts, counters, files), always use a lock.
Trap: "Too many open files" error.
  • Each thread opens a socket, which is a file descriptor. If you use 500 threads and the OS limit is 256, you get OSError: [Errno 24] Too many open files. Fix: ulimit -n 4096 in your terminal session before running. On macOS you may also need sudo launchctl limit maxfiles 4096 4096.
  • If you are scanning too fast and hitting a rate limiter on the target, add a small sleep between submitting batches or reduce max_workers. Against localhost this never happens. Against a remote authorized target it can cause temporary blocks.
  • as_completed(futures) yields futures as they finish — not in port order. That is why the final open_ports.sort() call is necessary before printing. If you iterate futures.items() instead, you lose the concurrency benefit because you wait for each future in submission order.
Checkpoint — what you should see
Running python3 scan4.py 127.0.0.1 1-10000 200 0.3 with two listeners active completes in under 2 seconds (most machines: under 1 second) and correctly identifies both open ports. Repeat without listeners — zero open ports found, same speed. The completion time should be dramatically faster than a sequential scan of the same range would be.

Banner Grabbing — Reading What Services Say
For each open port, attempt to read the first bytes the service sends after a connection. Many services (SSH, FTP, SMTP) send a version banner immediately. HTTP requires a minimal probe request first. Handle ports that never send a banner with a short second timeout.
  1. Create scan5.py adding banner grabbing to the Phase 4 concurrent scanner:
    #!/usr/bin/env python3 """ scan5.py -- Phase 5: concurrent scan + banner grabbing on open ports. Run only against systems you own or have written authorization to test. """ import socket import errno import sys import time import threading from concurrent.futures import ThreadPoolExecutor, as_completed # Well-known port to service name (local lookup -- no network call needed) WELL_KNOWN = { 21: "ftp", 22: "ssh", 23: "telnet", 25: "smtp", 53: "dns", 80: "http", 110: "pop3", 143: "imap", 443: "https", 445: "smb", 3306: "mysql", 3389: "rdp", 5432: "pg", 6379: "redis", 8080: "http-alt", 8443: "https-alt", 27017: "mongo" } results_lock = threading.Lock() open_ports = [] def parse_ports(spec): ports = set() for part in spec.split(','): part = part.strip() if '-' in part: lo, hi = part.split('-', 1) ports.update(range(int(lo), int(hi) + 1)) else: ports.add(int(part)) return sorted(ports) def grab_banner(sock, port, banner_timeout=1.0): """ Try to read a banner from an already-connected socket. Only plaintext HTTP ports (80, 8080, 8888) receive a probe request first. TLS ports (443, 8443) are excluded: a plaintext HEAD request to a TLS port returns TLS handshake bytes, not a readable HTTP response. Returns a stripped first-line string, or empty string if no banner. """ sock.settimeout(banner_timeout) try: # Plaintext HTTP ports need a request to send a response header if port in (80, 8080, 8888): sock.sendall(b"HEAD / HTTP/1.0\r\nHost: localhost\r\n\r\n") raw = sock.recv(1024) # Decode safely, take only the first line, strip control chars first_line = raw.decode("utf-8", errors="replace").split("\n")[0] return first_line.strip() except (socket.timeout, ConnectionResetError, OSError): # Port is open but the service did not send anything -- no banner return "" def scan_one(host, port, timeout): """Scan one port and grab a banner if open.""" sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM) sock.settimeout(timeout) code = sock.connect_ex((host, port)) if code == 0: banner = grab_banner(sock, port) sock.close() service = WELL_KNOWN.get(port, "") with results_lock: open_ports.append({"port": port, "service": service, "banner": banner}) return port, "open" else: sock.close() if code == errno.ECONNREFUSED: return port, "closed" return port, "filtered" if len(sys.argv) < 3: print("Usage: python3 scan5.py <host> <ports> [threads] [timeout]") sys.exit(1) host = sys.argv[1] port_list = parse_ports(sys.argv[2]) max_workers = int(sys.argv[3]) if len(sys.argv) > 3 else 100 timeout = float(sys.argv[4]) if len(sys.argv) > 4 else 0.5 print(f"Scanning {host} -- {len(port_list)} ports -- {max_workers} threads") t_start = time.monotonic() with ThreadPoolExecutor(max_workers=max_workers) as executor: futures = {executor.submit(scan_one, host, p, timeout): p for p in port_list} for future in as_completed(futures): future.result() # re-raises any exception from inside the thread elapsed = time.monotonic() - t_start open_ports.sort(key=lambda r: r["port"]) print(f"\nCompleted in {elapsed:.2f}s -- {len(open_ports)} open port(s)\n") print(f" {'PORT':<8} {'SERVICE':<12} BANNER") print(" " + "-" * 60) for r in open_ports: svc = r["service"] or "unknown" banner = r["banner"] or "(no banner)" print(f" {r['port']:<8}/tcp {svc:<12} {banner}")
  2. Test with a real SSH listener. If your machine has SSH running on port 22, point the scanner at it. If not, Python's built-in HTTP server sends a banner too:
    # Terminal 2 -- serves HTTP with a response header python3 -m http.server 8080
    python3 scan5.py 127.0.0.1 22,8080,9999 100 0.5
    Expected output (SSH not running, HTTP listener on 8080):
    Scanning 127.0.0.1 -- 3 ports -- 100 threads Completed in 0.01s -- 1 open port(s) PORT SERVICE BANNER ------------------------------------------------------------ 8080 /tcp http-alt HTTP/1.0 200 OK
    If your system does have SSH on port 22, expect an additional row:
    22 /tcp ssh SSH-2.0-OpenSSH_9.6p1 Ubuntu-3ubuntu13.4
  3. Understand which services send banners and which do not.
    Services that send a banner immediately on connect (no probe needed): SSH -- "SSH-2.0-OpenSSH_9.6p1 ..." FTP -- "220 ProFTPD 1.3.8 Server ..." SMTP -- "220 mail.example.com ESMTP Postfix ..." POP3 -- "+OK Dovecot ready." Services that need a probe request first: HTTP -- send "HEAD / HTTP/1.0\r\n\r\n" to get "HTTP/1.0 200 OK" Services that send nothing (banner grab returns empty string): MySQL (3306) -- handshake is binary, not plain text Redis (6379) -- expects commands first RDP (3389) -- TLS/binary protocol TLS-wrapped anything -- negotiate TLS before any readable text appears
    Why does the banner timeout need to be separate from the connect timeout? After the connection succeeds, some services take a moment to send their banner. If you use the same 0.5-second scan timeout for the banner read, you may miss banners from services that are slow to respond. The banner read uses a separate 1.0-second timeout, which only runs for open ports — there are typically very few of those, so the extra wait is acceptable.
Trap: banner grab hangs on binary protocols.
  • If a port serves a binary protocol (TLS, MySQL wire protocol, RDP), recv(1024) either returns binary garbage or blocks until the banner timeout expires. The script handles this: the socket.timeout exception in grab_banner catches the hang and returns an empty string. You will see "(no banner)" in the output, which is accurate — there is no readable text banner.
  • Do not send the HTTP probe to every port. Sending HEAD / HTTP/1.0\r\n\r\n to an SSH server causes it to close the connection and log an error. The if port in (80, 8080, 8888) guard limits the probe to plaintext HTTP ports only. TLS ports (443, 8443) are intentionally excluded: a plaintext HEAD to a TLS port returns TLS handshake bytes, not a readable HTTP banner.
  • Banner grabbing adds latency. Each open port now waits up to 1 second for a banner. Against a scan that finds many open ports this adds up. In Phase 6 you will add a --banner flag to make it opt-in.
Checkpoint — what you should see
Running against localhost with an HTTP server on 8080, the output table shows port 8080 as http-alt with a real HTTP/1.0 200 OK banner. A closed port returns nothing (it never reaches the banner-grab code). A port that is open but serves a binary protocol shows "(no banner)" rather than hanging. The script exits cleanly in all three cases.

CLI Tool — argparse, JSON Output, and the Authorization Check
Polish the scanner into a real command-line tool: argparse for all options, a formatted table view, a JSON output mode for piping into other tools, a summary block, and the authorization reminder baked into --help so it appears every time anyone runs it.
  1. Create the final tool portscanner.py:
    #!/usr/bin/env python3 """ portscanner.py -- Pure-Python TCP connect port scanner. stdlib only: socket, concurrent.futures, argparse, json, errno, time, sys AUTHORIZATION: Run only against systems you OWN or have EXPLICIT WRITTEN authorization to test. Unauthorized port scanning violates the Computer Fraud and Abuse Act (US), NIS Directive (EU), and equivalent laws worldwide. Only plaintext HTTP ports (80, 8080, 8888) receive a HEAD probe first. TLS ports (443, 8443) are excluded: a plaintext HEAD to a TLS port returns TLS handshake bytes, not a readable HTTP response. Returns the first line of the response stripped, or '' on timeout/error. """ sock.settimeout(timeout) try: # Plaintext HTTP ports need a request before they send a response if port in (80, 8080, 8888): sock.sendall(b"HEAD / HTTP/1.0\r\nHost: localhost\r\n\r\n") raw = sock.recv(1024) return raw.decode("utf-8", errors="replace").split("\n")[0].strip() except (socket.timeout, ConnectionResetError, OSError): return "" # ── Per-port worker ───────────────────────────────────────────────────────── def scan_one(host, port, timeout, do_banner): sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM) sock.settimeout(timeout) code = sock.connect_ex((host, port)) if code == 0: banner = grab_banner(sock, port) if do_banner else "" sock.close() return { "port": port, "state": "open", "service": WELL_KNOWN.get(port, ""), "banner": banner } sock.close() state = "closed" if code == errno.ECONNREFUSED else "filtered" return {"port": port, "state": state, "service": "", "banner": ""} # ── Main ───────────────────────────────────────────────────────────────────── def main(): args = build_parser().parse_args() port_list = parse_ports(args.ports) print(f"[*] Target: {args.target}", file=sys.stderr) print(f"[*] Ports: {args.ports} ({len(port_list)} total)", file=sys.stderr) print(f"[*] Threads: {args.threads} Timeout: {args.timeout}s Banner: {args.banner}", file=sys.stderr) print(f"[*] AUTHORIZED USE ONLY -- scanning unauthorized hosts is illegal.", file=sys.stderr) print("", file=sys.stderr) t_start = time.monotonic() all_results = [] with ThreadPoolExecutor(max_workers=args.threads) as executor: futures = { executor.submit(scan_one, args.target, p, args.timeout, args.banner): p for p in port_list } for future in as_completed(futures): result = future.result() with results_lock: all_results.append(result) elapsed = time.monotonic() - Traps in the final tool.
  • Scanning too fast triggers IDS alerts. Against any real network target (an authorized lab or pen-test engagement), 200 threads at 0.3s timeout will flood SYN packets and likely trigger a Snort or Suricata "ET SCAN" signature within seconds. This is expected in a pen-test, but it means the target knows you are scanning. For stealthy scans (authorized only), reduce to 10–20 threads and raise the timeout to 2–3 seconds to spread the scan over several minutes.
  • The --output json flag redirects stderr separately. Status messages print to sys.stderr so they do not pollute the JSON output going to stdout. When piping to another tool, use 2>/dev/null to suppress the stderr messages. When writing to a file, both stdout and stderr are visible in the terminal.
  • The 2>/dev/null redirect suppresses stderr on Linux/macOS. On Windows use 2>NUL instead.
  • f-string alignment in code blocks: the :<8 and :<10 format specs use a literal < character (less-than) which is left-align in Python format strings. If you copy this from the page, confirm the characters are correct in your editor.
