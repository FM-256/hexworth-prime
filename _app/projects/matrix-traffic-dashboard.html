Subject

Build a Packet Traffic Dashboard

Operator 120 min 1000 XP
Authorization & Scope — Read Before You Start
  • Only capture traffic on networks you own or have explicit written authorization to monitor. Capturing packets on a network you do not control is a federal crime under the Electronic Communications Privacy Act and equivalent laws worldwide.
  • Live capture requires admin/root privileges on your machine (Windows: run as Administrator; Linux/macOS: use sudo). If you cannot get root, use the PCAP file fallback described in Phase 1 — you can complete the entire project without ever running live capture.
  • Practice on your own machine only. Run all examples against a PCAP file from your own network, a loopback interface, or a dedicated lab VM with no third-party hosts in range.
  • Recommended starting point: download a sample PCAP from https://www.wireshark.org/download/automated/captures/ (public Wireshark test captures) or generate one yourself with tcpdump on your own interface for 30 seconds. No real-world traffic analysis needed to finish this project.
Mission Brief

This operation builds a Python network traffic dashboard that ingests packets from a .pcap capture file, extracts per-packet features into a pandas DataFrame, computes dashboard metrics — throughput over time, top talkers by IP, protocol mix, and port frequency — then renders a four-panel matplotlib figure saved as dashboard.png. The entire pipeline runs without root privileges when you supply a PCAP file, making it safe and portable on any machine.

The packet ingestion layer uses scapy 2.7.0 with PcapReader for memory-efficient streaming of large files. Feature extraction builds a structured DataFrame with columns for timestamp, source IP, destination IP, protocol, packet length, and source/destination ports. From that DataFrame the dashboard computes: (1) packets-per-second throughput bucketed into 1-second windows, (2) top-10 source IPs by packet count, (3) protocol distribution as a pie chart, and (4) a port frequency heatmap for the top destination ports. All four panels are arranged in a single 1920×1080 figure using matplotlib 3.11.0.

This is the same pipeline architecture used by professional network monitoring tools like ntopng and Zeek — ingest, extract, aggregate, visualize — running in under 100 lines of Python.

Agent Requirements
  • Python 3.11 or higher — check with python --version or python3 --version
  • pip packages: scapy==2.7.0, pandas==3.0.3, matplotlib==3.11.0 (Phase 1 gives the exact install command)
  • A .pcap file to analyze — Phase 1 shows three ways to obtain one, no root required
  • Comfortable running Python scripts from a terminal and reading basic DataFrame output
  • No networking experience required — every concept is explained at the step where it first appears
  • Headless / WSL note: matplotlib will not open GUI windows in headless environments. All plots are saved to disk with savefig() — open the PNG in your OS image viewer
  • Windows note: scapy requires Npcap (free) for live capture; for PCAP file reading no driver is needed. Install Npcap from https://npcap.com only if you intend to do optional live capture in Phase 5

Packet Ingestion and Feature Extraction
Stream every packet from the PCAP with PcapReader and extract six features — timestamp, source IP, destination IP, protocol, packet length, source port, and destination port — into a pandas DataFrame. Use haslayer() guards so that non-IP or non-TCP/UDP packets never raise an AttributeError.
  1. Create ingest.py in your traffic-dashboard folder and paste this complete script:
    import pandas as pd from scapy.all import PcapReader from scapy.layers.inet import IP, TCP, UDP PCAP_FILE = 'sample.pcap' def extract_features(pcap_path): """ Stream packets from a PCAP file and extract per-packet features. Uses PcapReader (not rdpcap) to avoid loading the entire file into memory. haslayer() guards prevent AttributeError on non-IP, non-TCP/UDP packets. """ rows = [] with PcapReader(pcap_path) as reader: for pkt in reader: # Skip packets that have no IP layer (ARP, STP, etc.) if not pkt.haslayer(IP): continue ip = pkt[IP] ts = float(pkt.time) # Unix timestamp (float) src_ip = ip.src dst_ip = ip.dst proto = ip.proto # 6=TCP, 17=UDP, 1=ICMP, etc. length = len(pkt) # total packet length in bytes # Extract ports only for TCP/UDP; set -1 for other protocols. if pkt.haslayer(TCP): sport = pkt[TCP].sport dport = pkt[TCP].dport elif pkt.haslayer(UDP): sport = pkt[UDP].sport dport = pkt[UDP].dport else: sport = -1 dport = -1 rows.append({ 'timestamp': ts, 'src_ip': src_ip, 'dst_ip': dst_ip, 'proto': proto, 'length': length, 'sport': sport, 'dport': dport, }) df = pd.DataFrame(rows) if df.empty: raise ValueError(f"No IP packets found in {pcap_path}. " "Check that the file is a valid PCAP and contains IP traffic.") # Convert the Unix timestamp column to a proper datetime for easier bucketing. df['time'] = pd.to_datetime(df['timestamp'], unit='s', utc=True) df = df.sort_values('time').reset_index(drop=True) return df if __name__ == '__main__': df = extract_features(PCAP_FILE) print(f"Loaded {len(df)} IP packets from {PCAP_FILE}") print(f"Time range: {df['time'].min()} to {df['time'].max()}") print(f"\nColumn dtypes:\n{df.dtypes}") print(f"\nFirst 5 rows:\n{df[['time','src_ip','dst_ip','proto','length','sport','dport']].head().to_string()}")
  2. Run it:
    python ingest.py
    Expected output (using the synthetic Option A PCAP):
    Loaded 500 IP packets from sample.pcap Time range: 2026-06-19 00:00:... to 2026-06-19 00:01:... Column dtypes: timestamp float64 src_ip object dst_ip object proto int64 length int64 sport int64 dport int64 time datetime64[ns, UTC] dtype: object First 5 rows: time src_ip dst_ip proto length sport dport 0 2026-06-19 ... 10.0.0.3 10.0.0.11 6 87 1842 80 1 2026-06-19 ... 10.0.0.9 10.0.0.4 17 124 2910 53 2 2026-06-19 ... 10.0.0.1 10.0.0.7 6 201 5544 443 3 2026-06-19 ... 10.0.0.6 10.0.0.12 6 74 3301 8080 4 2026-06-19 ... 10.0.0.2 10.0.0.5 17 92 6104 22
AttributeError on pkt[IP].src or similar?
  • This means a packet passed the haslayer(IP) check but a sub-layer is missing. Confirm you are using scapy 2.7.0; older versions had inconsistent haslayer() behavior on malformed frames.
  • If the PCAP contains packets with IP-over-non-Ethernet encapsulation (e.g., IP-in-IP tunnels), add pkt.haslayer(IP) twice and access pkt.getlayer(IP, nb=2) for the inner header.
ValueError: No IP packets found?
  • If you used Option C (downloaded PCAP), some community-hosted captures contain only ARP or Ethernet frames with no IP layer. Use the Wireshark-hosted http.cap URL given in Option C, or switch to Option A (synthetic generator) which always produces IP/TCP/UDP packets.

Dashboard Metric Computation
Compute the four metrics that power the dashboard panels: throughput over time, top source IPs, protocol distribution, and top destination ports. Each metric is a simple pandas aggregation on the DataFrame from Phase 2.
  1. Create metrics.py in your folder and paste this complete script:
    import pandas as pd from ingest import extract_features PCAP_FILE = 'sample.pcap' # Protocol number to readable name mapping (IANA assigned numbers) PROTO_NAMES = {1: 'ICMP', 6: 'TCP', 17: 'UDP', 47: 'GRE', 50: 'ESP', 58: 'ICMPv6'} def compute_metrics(df): """ Returns four metrics as pandas objects ready for plotting. """ # ── Metric 1: Throughput (packets per second, 1-second buckets) ────── # Set the datetime index, then resample into 1-second windows and count rows. df_ts = df.set_index('time') throughput = df_ts.resample('1s')['length'].agg( pkt_count='count', bytes_total='sum' ).fillna(0) # ── Metric 2: Top 10 source IPs by packet count ─────────────────────── top_talkers = (df['src_ip'] .value_counts() .head(10) .rename_axis('src_ip') .reset_index(name='pkt_count')) # ── Metric 3: Protocol distribution ────────────────────────────────── proto_counts = (df['proto'] .map(lambda p: PROTO_NAMES.get(p, f'proto-{p}')) .value_counts() .rename_axis('protocol') .reset_index(name='count')) # ── Metric 4: Top 20 destination ports (TCP/UDP only) ──────────────── port_df = df[df['dport'] > 0] # exclude -1 (non-TCP/UDP) top_ports = (port_df['dport'] .value_counts() .head(20) .rename_axis('dport') .reset_index(name='pkt_count')) return throughput, top_talkers, proto_counts, top_ports if __name__ == '__main__': df = extract_features(PCAP_FILE) throughput, top_talkers, proto_counts, top_ports = compute_metrics(df) print("=== Throughput (first 5 seconds) ===") print(throughput.head().to_string()) print("\n=== Top Talkers (src IP) ===") print(top_talkers.to_string(index=False)) print("\n=== Protocol Mix ===") print(proto_counts.to_string(index=False)) print("\n=== Top Destination Ports ===") print(top_ports.head(10).to_string(index=False))
  2. Run it:
    python metrics.py
    Expected output (synthetic Option A PCAP, values are approximate):

Build and Save the Four-Panel Dashboard
Arrange the four metrics into a 2×2 matplotlib figure and save it as dashboard.png. The dashboard uses a dark theme consistent with the Matrix House aesthetic: black background, green accent for bars and lines, yellow highlights for the pie chart, and monospace axis labels. All colors are specified as hex strings — no rgba() CSS values in Python.
  1. Create dashboard.py in your folder and paste this complete script:
    import matplotlib matplotlib.use('Agg') # headless-safe: write PNG, no GUI window import matplotlib.pyplot as plt import matplotlib.ticker as ticker import pandas as pd from ingest import extract_features from metrics import compute_metrics PCAP_FILE = 'sample.pcap' OUTPUT_FILE = 'dashboard.png' BG_COLOR = '#0a0c10' # panel + figure background GRID_COLOR = '#1e2530' # subtle grid lines TEXT_COLOR = '#aaaaaa' # axis labels and tick text ACCENT_GREEN = '#00ff41' # primary bars / lines ACCENT_LIME = '#4ade80' # secondary bars PROTO_COLORS = ['#00ff41', '#4ade80', '#facc15', '#f87171', '#60a5fa'] def style_ax(ax): """Apply the shared dark theme to any Axes object.""" ax.set_facecolor(BG_COLOR) ax.tick_params(colors=TEXT_COLOR, labelsize=8) ax.xaxis.label.set_color(TEXT_COLOR) ax.yaxis.label.set_color(TEXT_COLOR) ax.title.set_color(ACCENT_GREEN) ax.title.set_fontsize(10) ax.title.set_fontweight('bold') for spine in ax.spines.values(): spine.set_edgecolor(GRID_COLOR) ax.yaxis.set_major_formatter(ticker.FuncFormatter(lambda x, _: f'{int(x):,}')) def build_dashboard(throughput, top_talkers, proto_counts, top_ports, output_path): fig, axes = plt.subplots(2, 2, figsize=(16, 9)) fig.patch.set_facecolor(BG_COLOR) fig.suptitle('PACKET TRAFFIC DASHBOARD', color=ACCENT_GREEN, fontsize=13, fontweight='bold', fontfamily='monospace', y=0.98) # ── Panel 1 (top-left): Throughput over time ───────────────────────── ax1 = axes[0, 0] ax1.bar(range(len(throughput)), throughput['pkt_count'], color=ACCENT_GREEN, alpha=0.75, width=0.9) ax1.set_title('Packets per Second') ax1.set_xlabel('Time (seconds from start)') ax1.set_ylabel('Packet Count') ax1.grid(axis='y', color=GRID_COLOR, linewidth=0.6) style_ax(ax1) # ── Panel 2 (top-right): Top source IPs ───────────────────────────── ax2 = axes[0, 1] ips = top_talkers['src_ip'].tolist() counts = top_talkers['pkt_count'].tolist() y_pos = range(len(ips)) ax2.barh(y_pos, counts, color=ACCENT_LIME, alpha=0.8) ax2.set_yticks(y_pos) ax2.set_yticklabels(ips, fontsize=8, fontfamily='monospace') ax2.invert_yaxis() # highest count at top ax2.set_title('Top Source IPs') ax2.set_xlabel('Packet Count') ax2.grid(axis='x', color=GRID_COLOR, linewidth=0.6) style_ax(ax2) # Override y-axis formatter: IPs are strings, not numbers ax2.yaxis.set_major_formatter(ticker.NullFormatter()) ax2.set_yticklabels(ips, fontsize=8, fontfamily='monospace', color=TEXT_COLOR) # ── Panel 3 (bottom-left): Protocol distribution pie ──────────────── ax3 = axes[1, 0] colors_n = PROTO_COLORS[:len(proto_counts)] wedges, texts, autotexts = ax3.pie( proto_counts['count'], labels=proto_counts['protocol'], colors=colors_n, autopct='%1.1f%%', startangle=90, textprops={'color': TEXT_COLOR, 'fontsize': 9}, ) for at in autotexts: at.set_color(BG_COLOR) at.set_fontweight('bold') ax3.set_title('Protocol Distribution') ax3.set_facecolor(BG_COLOR) ax3.title.set_color(ACCENT_GREEN) ax3.title.set_fontsize(10) ax3.title.set_fontweight('bold') # ── Panel 4 (bottom-right): Top destination ports ─────────────────── ax4 = axes[1, 1] port_labels = [str(p) for p in top_ports['dport'].tolist()] port_counts = top_ports['pkt_count'].tolist() ax4.bar(port_labels, port_counts, color=ACCENT_GREEN, alpha=0.75) ax4.set_title('Top Destination Ports') ax4.set_xlabel('Destination Port') ax4.set_ylabel('Packet Count') ax4.tick_params(axis='x', rotation=45, labelsize=7) ax4.grid(axis='y', color=GRID_COLOR, linewidth=0.6) style_ax(ax4) # x-axis labels are strings, override the numeric formatter ax4.xaxis.set_major_formatter(ticker.NullFormatter()) ax4.set_xticklabels(port_labels, rotation=45, ha='right', fontsize=7, fontfamily='monospace', color=TEXT_COLOR) plt.tight_layout(rect=[0, 0, 1, 0.96]) plt.savefig(output_path, dpi=120, facecolor=BG_COLOR, bbox_inches='tight') print(f"Dashboard saved: {output_path}") if __name__ == '__main__': df = extract_features(PCAP_FILE) throughput, top_talkers, proto_counts, top_ports = compute_metrics(df) build_dashboard(throughput, top_talkers, proto_counts, top_ports, OUTPUT_FILE)

ValueError: could not convert string to float?
  • This usually means a CSS rgba() string was passed as a matplotlib color argument. matplotlib only accepts hex strings like '#00ff41', named colors like 'green', or RGB tuples like (0.0, 1.0, 0.25). Check that all color variables in the script use hex notation, not rgba(0,255,65,0.75).
Dashboard PNG is blank or shows a white square?
  • Confirm matplotlib.use('Agg') appears before import matplotlib.pyplot as plt. If pyplot was imported earlier (e.g., inside ingest.py or metrics.py), the backend switch is ignored. Move the use('Agg') call to the very first line of dashboard.py.
  • If running on a macOS system with a display, you can also use the macosx backend to get a live window: remove the use('Agg') line and call plt.show() instead of savefig().

Wire It Together and Read Your Dashboard
Create a single run.py entry point that chains all three scripts into one command, print a summary report to the terminal, and learn how to interpret each panel so the dashboard produces actionable insight, not just a pretty chart.
  1. Create run.py in your folder — this is the single command you will use going forward:
    """ run.py -- single entry point for the packet traffic dashboard. Usage: python run.py [path/to/capture.pcap] python run.py (uses sample.pcap by default) """ import sys from ingest import extract_features from metrics import compute_metrics, PROTO_NAMES from dashboard import build_dashboard, OUTPUT_FILE PCAP_FILE = sys.argv[1] if len(sys.argv) > 1 else 'sample.pcap' print(f"\n[1/3] Loading packets from {PCAP_FILE} ...") df = extract_features(PCAP_FILE) print(f" {len(df):,} IP packets | " f"{df['time'].min().strftime('%H:%M:%S')} to " f"{df['time'].max().strftime('%H:%M:%S')} UTC") print("\n[2/3] Computing dashboard metrics ...") throughput, top_talkers, proto_counts, top_ports = compute_metrics(df) capture_secs = max(1, int((df['time'].max() - df['time'].min()).total_seconds())) avg_pps = len(df) / capture_secs total_bytes = df['length'].sum() print(f" Capture window : {capture_secs}s") print(f" Avg throughput : {avg_pps:.1f} pkt/s | {total_bytes/1024:.1f} KB total") print(f" Unique src IPs : {df['src_ip'].nunique()}") print(f" Unique dst IPs : {df['dst_ip'].nunique()}") print("\n[3/3] Rendering dashboard ...") build_dashboard(throughput, top_talkers, proto_counts, top_ports, OUTPUT_FILE) print("\n=== HOW TO READ YOUR DASHBOARD ===") print("Panel 1 (Packets/sec): spikes = traffic bursts; flat = idle periods.") print("Panel 2 (Top talkers): investigate any IP generating >> average volume.") print("Panel 3 (Protocols): unexpected GRE/ESP may indicate a tunnel or VPN.") print("Panel 4 (Ports): port 53 = DNS (normal); unusual high ports = check app logs.")
  2. Run the full pipeline:
    python run.py
    Expected output:
    [1/3] Loading packets from sample.pcap ... 500 IP packets | 00:00:00 to 00:01:03 UTC [2/3] Computing dashboard metrics ... Capture window : 63s Avg throughput : 7.9 pkt/s | 52.3 KB total Unique src IPs : 15 Unique dst IPs : 15 [3/3] Rendering dashboard ... Dashboard saved: dashboard.png === HOW TO READ YOUR DASHBOARD === Panel 1 (Packets/sec): spikes = traffic bursts; flat = idle periods. Panel 2 (Top talkers): investigate any IP generating >> average volume. Panel 3 (Protocols): unexpected GRE/ESP may indicate a tunnel or VPN. Panel 4 (Ports): port 53 = DNS (normal); unusual high ports = check app logs.
  3. Run against a different PCAP by passing it as an argument:
    python run.py /path/to/your/other.pcap
    Optional live capture (requires root + Npcap on Windows). To capture live traffic for 30 seconds and pipe straight into the dashboard, run:
    # Linux / macOS -- requires sudo sudo tcpdump -i any -w /tmp/live.pcap -G 30 -W 1 && python run.py /tmp/live.pcap
    Only do this on your own authorized network. The dashboard is identical whether the PCAP is live-captured or downloaded.
  4. Interpreting anomalies:
    • Traffic spike in Panel 1: cross-reference the timestamp bucket against Panel 2 to find which IP generated the burst.
    • Single IP dominates Panel 2: check whether it is a known server (your router, DNS, NTP) or an unexpected host. Calculate its percentage: count / total_packets * 100.
    • Unknown protocol in Panel 3: protocol 47 = GRE (VPN tunnel), 50 = IPsec ESP (encrypted tunnel). Either can be legitimate or suspicious depending on context.
    • High non-standard port in Panel 4: cross-reference the src_ip for that port using df[df['dport']==<port>]['src_ip'].value_counts() at the Python prompt.
