Subject

Build a Packet Traffic Dashboard

Operator 120 min 1000 XP
Mission Brief

This operation puts the ESP32 into WiFi promiscuous mode — a raw packet capture state where the radio receives every wireless frame on the current channel regardless of which network it belongs to. The CYD's touchscreen becomes a real-time traffic dashboard: live graphs show packet rates per second, classification bars break traffic into management, data, and control frames, a "top talkers" list ranks MAC addresses by traffic volume, and touch controls let you hop channels and apply filters on the fly.

You will configure the ESP32's low-level WiFi promiscuous callback using esp_wifi_set_promiscuous(), classify captured frames by type and subtype from the 802.11 header, build animated bar graphs that update multiple times per second on the TFT display, track and rank source MAC addresses by packet count, and implement channel hopping with touch-driven filter controls.

This is the exact packet inspection architecture used by wireless protocol analyzers like Kismet and Wireshark's wireless capture — running on a $15 device with its own screen.

Agent Requirements
  • ESP32-2432S028R (CYD — Cheap Yellow Display)
  • Arduino IDE or PlatformIO with ESP32 board support
  • Understanding of basic networking concepts (packets/MAC addresses/channels)
  • Comfort with C structs and pointer manipulation
  • Prior ESP32 or Arduino experience recommended
Operation Phases
Progress
0 / 5
✓
1
Promiscuous Mode Setup & Raw Frame Capture
Disconnect from all WiFi networks and configure the ESP32 radio in promiscuous mode using esp_wifi_set_promiscuous(true). Register a callback function that receives every raw 802.11 frame. Count incoming packets per second and display the live rate on the TFT screen to verify capture is working.
Checkpoint: Data Source Setup
  • Load the traffic dataset and verify it contains timestamp, location, and vehicle count columns
  • Check for missing values and confirm the dataset covers the expected date range
  • Verify the data frequency (hourly, daily) matches your dashboard's expected granularity
✓
2
Packet Type Classification
Parse the first two bytes of each captured frame to extract the type and subtype fields from the 802.11 header. Classify frames into three categories: management (beacons, probes, auth), data (actual payload traffic), and control (ACK, RTS/CTS). Maintain running counters for each category.
✓
3
Live Bar Graph of Packet Rates
Render three animated horizontal bar graphs on the TFT, one for each packet type. Update the graph every 500ms with the current packets-per-second rate. Use color coding: green for management, blue for data, yellow for control. Add numeric labels showing the exact count and percentage breakdown.
Checkpoint: Dashboard Layout
  • Start the dashboard server and verify the main page loads with all panels visible
  • Confirm the map component renders and displays traffic monitoring locations
  • Verify the time-range selector filters data correctly across all charts
✓
4
Top MAC Addresses by Traffic Volume
Extract the source MAC address from each data frame. Maintain a hash map (or sorted array) of MAC addresses ranked by total packet count. Display the top 8 talkers on a dedicated screen section with their MAC, packet count, and a proportional bar. Update the ranking in real time as new packets arrive.
Checkpoint: Alerts & Export
  • Set a traffic threshold and verify an alert triggers when the count exceeds it
  • Export the dashboard view as a PDF or image and confirm all charts are included
  • Verify the alert history log stores all triggered alerts with timestamps
✓
5
Channel Hopping & Touch Controls
Implement WiFi channel hopping that cycles through channels 1–13 using esp_wifi_set_channel(). Display the current channel on screen. Add touch buttons: "Pause" to freeze on the current channel, "Next/Prev" to manually step channels, and a "Filter" toggle that shows only data frames, only management frames, or all frames.
Checkpoint: Real-Time Updates
  • Simulate new data arriving and verify the dashboard updates without a full page reload
  • Confirm the refresh interval is configurable and does not overload the data source
  • Verify the dashboard handles empty data gracefully during off-peak periods
