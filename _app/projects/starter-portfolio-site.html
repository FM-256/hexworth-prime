Subject

Build a Portfolio Website with GitHub Pages

Recruit 2 hrs 300 XP
Mission Brief

Build a personal portfolio website using only HTML and CSS, then deploy it for free using GitHub Pages. No frameworks, no JavaScript, no hosting fees. When you are done, you will have a live URL you can put on your resume.

The site will have an About section, a Skills section with visual indicators, a Projects section linking to your GitHub repos, and a Contact section. The design will be clean, responsive, and professional.

This project teaches you the core web technologies that underpin every website on the internet. Even if you never become a web developer, understanding HTML and CSS is a fundamental IT skill.

Agent Requirements
  • A free GitHub account — sign up at github.com if you do not have one yet. You will need to verify your email address before GitHub Pages will activate.
  • A free text editor — we recommend VS Code (code.visualstudio.com). Any plain-text editor works; do not use Microsoft Word or Google Docs.
  • A web browser (Chrome, Firefox, or Edge).
  • No prior web or git experience required — every click is spelled out.

HTML Structure
Make your project folder, create index.html in VS Code, and paste a complete semantic HTML5 skeleton with a header, nav, four content sections, and a footer. Nothing requires prior experience — follow each step exactly.
  1. Install VS Code if you have not already. Go to code.visualstudio.com, download the installer for your operating system, and run it. Accept all defaults. Open VS Code and close the Welcome tab.
  2. Turn on file extensions so you can see the .html and .css endings that make everything work. Windows 11: open File Explorer → View → Show → tick File name extensions. Windows 10: File Explorer → View tab → tick File name extensions. Mac: Finder → Settings (or Preferences on older macOS) → Advanced → tick Show all filename extensions.
  3. Create your project folder. Right-click an empty spot on your Desktop → New → Folder (Mac: right-click → New Folder). Name it my-portfolio — no spaces, all lowercase.
  4. Open that folder in VS Code. In VS Code: File → Open Folder…, navigate to your Desktop, select my-portfolio, and click Open. The folder name appears in the left panel.
  5. Create index.html. In the left panel, hover over the folder name — small icons appear — and click the New File icon (a page with a + sign). Type index.html and press Enter. The file opens blank in the editor.
    Why index.html? Every web server looks for a file called index.html when someone visits the root of a site. GitHub Pages does the same thing. If you name it anything else, the site shows a blank page or an error.
  6. Paste the complete HTML skeleton below. Click inside the blank file and paste the entire block. Then read the explanation below the block so you know what each part does.
    <!DOCTYPE html> <html lang="en"> <head> <meta charset="UTF-8"> <meta name="viewport" content="width=device-width, initial-scale=1.0"> <title>Your Name — Portfolio</title> </head> <body> <header> <h1>Your Name</h1> <nav> <a href="#about">About</a> <a href="#projects">Projects</a> <a href="#contact">Contact</a> </nav> </header> <main> <section id="about"> <h2>About Me</h2> <p>Write a sentence or two about yourself here.</p> </section> <section id="projects"> <h2>Projects</h2> <p>Project cards go here in Phase 3.</p> </section> <section id="contact"> <h2>Contact</h2> <p>Your email or GitHub link goes here.</p> </section> </main> <footer> <p>&copy; 2026 Your Name</p> </footer> </body> </html>
    What each part means: <!DOCTYPE html> tells the browser this is a modern HTML5 page. <html lang="en"> wraps everything and declares the language. <head> holds invisible settings — the tab title, charset (so accented characters show correctly), and the viewport line that makes your page fit phone screens. <body> is everything a visitor sees. Inside <body>: <header> holds your name and the navigation bar; <main> holds your actual content; the three <section> elements with id attributes are the three areas the nav links will scroll to; <footer> sits at the very bottom. The &copy; code becomes the © symbol in the browser.
  7. Replace "Your Name" with your real name in the <title>, the <h1>, and the <footer>.
  8. Save and open in the browser. Press Ctrl+S (Mac: Cmd+S). Open File Explorer (Mac: Finder), go to Desktop → my-portfolio, and double-click index.html. It opens in your default browser.
    If double-clicking opens the file back in VS Code instead of a browser, right-click index.html → Open with → choose Chrome, Edge, or Firefox.
Your full index.html right now is the skeleton you pasted above, with your name substituted. Nothing else has been added yet.
Checkpoint — what you should see
The browser shows your name as a large heading, the three nav links (About / Projects / Contact) below it, three section headings with their placeholder text, and a footer copyright line. The page is unstyled — black text on white, no layout. That is correct. The browser tab shows Your Name — Portfolio. If the tab shows a file path instead, check that your <title> line is inside <head>…</head>.

About and Skills Sections
Fill in the About section with a real bio paragraph and add a Skills section using an unordered list. Everything goes inside the existing <section id="about"> — you will be replacing the placeholder text you left there in Phase 1.
  1. Find your About section in index.html. Look for the line that says:
    <section id="about"> <h2>About Me</h2> <p>Write a sentence or two about yourself here.</p> </section>
  2. Replace the placeholder paragraph with a real bio and a skills list. Delete the old <p>Write a sentence…</p> line and paste this block in its place (inside the same <section id="about">), substituting your own words:
    <p> I am a first-year IT student learning web development, networking, and cybersecurity fundamentals. I enjoy solving problems and building things that other people can use. </p> <h3>Skills</h3> <ul> <li>HTML and CSS</li> <li>Windows and Linux basics</li> <li>Python scripting</li> <li>Networking fundamentals</li> <li>Git and version control</li> </ul>
    What <ul> and <li> mean: <ul> is an "unordered list" — it creates the bullet points. Each <li> is one "list item." You can have as many <li> entries as you like between the opening <ul> and the closing </ul>. Change these to match your own skills — a recruiter reads this section.
  3. Your <section id="about"> should now look like this in full:
    <section id="about"> <h2>About Me</h2> <p> I am a first-year IT student learning web development, networking, and cybersecurity fundamentals. I enjoy solving problems and building things that other people can use. </p> <h3>Skills</h3> <ul> <li>HTML and CSS</li> <li>Windows and Linux basics</li> <li>Python scripting</li> <li>Networking fundamentals</li> <li>Git and version control</li> </ul> </section>
  4. Save and refresh. Save with Ctrl+S (Mac: Cmd+S), switch to your browser, press F5 (Mac: Cmd+R) to reload.
Common mistake: accidentally deleting the closing </section> tag while editing. If your Projects and Contact sections disappear from the page, open VS Code and check that </section> still appears after your </ul> and before <section id="projects">. A missing closing tag breaks everything below the place where it should be.
Checkpoint — what you should see
The About section now shows your bio paragraph followed by the heading Skills and a bulleted list of five items. The Projects and Contact sections are still visible below it. Nothing is styled yet — that comes in Phase 4. If the bullet points do not appear, make sure <ul> and </ul> wrap all the <li> items and that none of the closing tags are missing.

Projects Section
Replace the placeholder inside <section id="projects"> with real project cards. Each card contains a project title, a one-line description, and a clickable link to your GitHub repo. You will learn how <a> links work and what target="_blank" does.
  1. Find the Projects section in your file:
    <section id="projects"> <h2>Projects</h2> <p>Project cards go here in Phase 3.</p> </section>
  2. Delete the placeholder paragraph (<p>Project cards go here in Phase 3.</p>) and replace it with this block. Substitute your own project titles, descriptions, and GitHub repo URLs:
    <div class="projects-grid"> <div class="project-card"> <h3>My First Web Page</h3> <p>A personal page built with raw HTML and CSS.</p> <a href="https://github.com/yourusername/my-first-webpage" target="_blank"> View on GitHub </a> </div> <div class="project-card"> <h3>Python Calculator</h3> <p>A command-line calculator script written in Python 3.</p> <a href="https://github.com/yourusername/python-calculator" target="_blank"> View on GitHub </a> </div> <div class="project-card"> <h3>Linux Lab Notes</h3> <p>Documented commands and concepts from my Linux course labs.</p> <a href="https://github.com/yourusername/linux-lab-notes" target="_blank"> View on GitHub </a> </div> </div>
    How the link tag works: <a href="https://...">link text</a>. The href attribute holds the full URL the link opens — it must start with https://. target="_blank" tells the browser to open the link in a new tab rather than navigating away from your portfolio. Replace yourusername in the URLs with your actual GitHub username. If you do not have a repo yet, leave the URL as a placeholder for now — the link will still appear, it just will not go anywhere useful until the repo exists.
  3. Replace the placeholder URLs and text with your own. If you have more or fewer than three projects, add or remove <div class="project-card">…</div> blocks as needed. Each block is self-contained.
  4. Your full <section id="projects"> block should look like this:
    <section id="projects"> <h2>Projects</h2> <div class="projects-grid"> <div class="project-card"> <h3>My First Web Page</h3> <p>A personal page built with raw HTML and CSS.</p> <a href="https://github.com/yourusername/my-first-webpage" target="_blank"> View on GitHub </a> </div> <div class="project-card"> <h3>Python Calculator</h3> <p>A command-line calculator script written in Python 3.</p> <a href="https://github.com/yourusername/python-calculator" target="_blank"> View on GitHub </a> </div> <div class="project-card"> <h3>Linux Lab Notes</h3> <p>Documented commands and concepts from Linux course labs.</p> <a href="https://github.com/yourusername/linux-lab-notes" target="_blank"> View on GitHub </a> </div> </div> </section>
  5. Fill in your Contact section — scroll up to the <section id="contact"> from Phase 1 and replace the placeholder line <p>Your email or GitHub link goes here.</p> with real links, using the same <a> tag you just learned. Use a mailto: link for email and your full profile URL for GitHub:
    <section id="contact"> <h2>Contact</h2> <p><a href="mailto:you@example.com">you@example.com</a></p> <p><a href="https://github.com/yourusername" target="_blank">github.com/yourusername</a></p> </section>
    Don't ship the placeholder text — this site goes on your resume, and "Your email or GitHub link goes here" tells a recruiter you didn't finish.
  6. Save and refresh. The links will be plain blue underlined text for now. You will style the cards into a proper grid in Phase 4.
Link opens the wrong page or gives a 404? The URL in href must be the full web address of your actual GitHub repo. A common mistake is writing just the repo name without the full URL (e.g., href="my-first-webpage" instead of href="https://github.com/yourusername/my-first-webpage"). The browser treats a bare name as a relative path, which points to a file on your computer instead of GitHub.
Checkpoint — what you should see
The Projects section shows three blocks of text, each with a project title (<h3>), a description paragraph, and a View on GitHub link. Clicking a link should open GitHub in a new browser tab (if the repo exists). The layout is unstyled — the three cards stack vertically. The grid layout comes in Phase 4.

CSS Styling
Create a separate style.css file, link it from your HTML, and paste the complete stylesheet. This gives you a dark theme, a Google Font, a sticky nav bar, a responsive project grid using CSS Grid, and hover effects on cards — all with zero guesswork.
  1. Create style.css in VS Code. In the left panel, hover over the my-portfolio folder name, click the New File icon (the page with a +), type style.css, and press Enter. It appears next to index.html.
    your folder should look like thismy-portfolio/ ├─ index.html └─ style.css
  2. Link the stylesheet from index.html. Open index.html. Find the closing </head> tag and add the <link> tag on the line right above it, so it looks exactly like this:
    <meta name="viewport" content="width=device-width, initial-scale=1.0"> <title>Your Name — Portfolio</title> <link rel="preconnect" href="https://fonts.googleapis.com"> <link rel="preconnect" href="https://fonts.gstatic.com" crossorigin> <link href="https://fonts.googleapis.com/css2?family=Inter:wght@400;600;700&amp;display=swap" rel="stylesheet"> <link rel="stylesheet" href="style.css"> </head>
    What these lines do: the three fonts.googleapis.com lines load the Inter font from Google Fonts — a professional sans-serif used by major tech companies. The <link rel="stylesheet" href="style.css"> line tells the browser to load your style.css file and apply it to the page. The href="style.css" is a relative path: because style.css sits in the same folder as index.html, no folder prefix is needed. If you ever move the CSS file into a subfolder you would update this path.
  3. Paste the complete stylesheet into style.css. Click the style.css tab in VS Code and paste this entire block:
    /* ── Reset and base ─────────────────────────── */ *, *::before, *::after { box-sizing: border-box; margin: 0; padding: 0; } body { font-family: 'Inter', Arial, sans-serif; background-color: #0f172a; color: #e2e8f0; line-height: 1.6; } /* ── Layout container ───────────────────────── */ header, main, footer { max-width: 900px; margin: 0 auto; padding: 0 24px; } /* ── Header and nav ─────────────────────────── */ header { position: sticky; top: 0; background-color: #0f172a; border-bottom: 1px solid #1e293b; padding-top: 20px; padding-bottom: 20px; z-index: 100; } header h1 { font-size: 1.8rem; font-weight: 700; color: #4ade80; margin-bottom: 8px; } nav { display: flex; gap: 24px; } nav a { color: #94a3b8; text-decoration: none; font-size: 0.9rem; font-weight: 600; letter-spacing: 0.05em; transition: color 0.2s; } nav a:hover { color: #4ade80; } /* ── Sections ───────────────────────────────── */ main { padding-top: 48px; padding-bottom: 80px; } section { margin-bottom: 64px; scroll-margin-top: 80px; /* so a clicked nav link doesn't hide the heading under the sticky header */ } section h2 { font-size: 1.4rem; font-weight: 700; color: #f1f5f9; margin-bottom: 16px; padding-bottom: 8px; border-bottom: 2px solid #4ade80; display: inline-block; } section p { color: #94a3b8; font-size: 1rem; max-width: 640px; } /* ── Skills list ────────────────────────────── */ #about h3 { font-size: 1rem; font-weight: 600; color: #cbd5e1; margin-top: 24px; margin-bottom: 10px; } #about ul { list-style: none; display: flex; flex-wrap: wrap; gap: 10px; } #about ul li { background-color: #1e293b; color: #4ade80; font-size: 0.85rem; font-weight: 600; padding: 6px 14px; border-radius: 999px; border: 1px solid #334155; } /* ── Project grid ───────────────────────────── */ .projects-grid { display: grid; grid-template-columns: repeat(auto-fill, minmax(260px, 1fr)); gap: 20px; } .project-card { background-color: #1e293b; border: 1px solid #334155; border-radius: 8px; padding: 20px; transition: border-color 0.2s, transform 0.2s; } .project-card:hover { border-color: #4ade80; transform: translateY(-3px); } .project-card h3 { font-size: 1rem; font-weight: 700; color: #f1f5f9; margin-bottom: 8px; } .project-card p { font-size: 0.88rem; color: #94a3b8; margin-bottom: 14px; } .project-card a { font-size: 0.82rem; font-weight: 600; color: #4ade80; text-decoration: none; letter-spacing: 0.04em; } .project-card a:hover { text-decoration: underline; } /* ── Contact section ────────────────────────── */ #contact a { color: #4ade80; } /* ── Footer ─────────────────────────────────── */ footer { text-align: center; padding: 24px; border-top: 1px solid #1e293b; font-size: 0.8rem; color: #475569; }
    How the rules stack: each block starts with a selector (like body, nav a, or .project-card) that picks which elements get styled. The properties inside the curly braces change one thing each — color, spacing, layout. The display: grid rule on .projects-grid automatically puts the project cards side by side; repeat(auto-fill, minmax(260px, 1fr)) means "as many columns as fit, each at least 260px wide" — which collapses to a single column on a phone automatically. The transition lines create the smooth hover animation on the cards. You never need to write a media query for this grid.
  4. Save both files (index.html and style.css) with Ctrl+S (Mac: Cmd+S), then refresh your browser.
Styles not appearing at all? The most common causes:
  • The <link rel="stylesheet" href="style.css"> line is missing from <head> in index.html.
  • The href says styles.css (with an s) but your file is named style.css. The name must match exactly, including capitalisation.
  • The style.css file is in a subfolder but href="style.css" still points at the root. Make sure both files are in the same my-portfolio folder with nothing between them.
  • You saved style.css but forgot to refresh the browser (press F5 / Cmd+R).
Font not loading (still shows a default serif or sans-serif)? The three Google Fonts <link> lines require an internet connection to fetch the font. If you are offline, the browser falls back to Arial, which looks fine — this is expected and intentional. The &amp;display=swap parameter in the URL prevents a flash of invisible text while the font loads.
Checkpoint — what you should see
The page now has a dark background, your name appears in green in a sticky header that stays at the top when you scroll, the nav links turn green on hover, the About section shows your skills as green pill badges instead of plain bullets, and the project cards appear side by side in a grid. Hovering over a card makes it lift slightly. Narrowing the browser window to phone width should collapse the grid to a single column automatically. If any of that is missing, check the troubleshooting boxes above.

5
Deploy to GitHub Pages
Upload your two files to GitHub and turn on GitHub Pages. Within a few minutes you will have a live public URL you can put on your resume. This phase uses the GitHub website only — no command line required.
Two URL patterns — know which one you are getting: If you name your repository exactly yourusername.github.io (replace yourusername with your actual GitHub username, all lowercase), your site lives at https://yourusername.github.io with no path after it. That is the cleanest URL for a portfolio and is what this phase builds. If you name the repository anything else (e.g., portfolio), the URL becomes https://yourusername.github.io/portfolio — which still works fine, and your in-page nav links (href="#about" etc.) keep working either way because they point within the same page. Choose the yourusername.github.io name for the simplest URL.
  1. Sign in to GitHub at github.com. If you do not have an account, click Sign up and complete the registration, including verifying your email address. GitHub Pages will not activate on an unverified account.
  2. Create a new repository. Click the + icon in the top-right corner of any GitHub page → New repository.
    Fill in the form exactly like this:
    • Owner: your GitHub username (pre-selected).
    • Repository name: type yourusername.github.io, substituting your actual username. Example: if your GitHub username is jsmith99, type jsmith99.github.io. GitHub will warn you if the name does not match your username.
    • Visibility: leave it on Public. GitHub Pages on a free account requires a public repository.
    • Leave Add a README file unchecked — you will upload your own files.
    • Leave Add .gitignore and Choose a license set to None.
    Click Create repository.
  3. Upload your files. GitHub shows your new empty repository. Click the link that says uploading an existing file (it appears in the quick-setup text near the top of the page, or click Add file → Upload files from the toolbar). You land on the upload page.
    • Open File Explorer (Mac: Finder) and navigate to your my-portfolio folder.
    • Drag both index.html and style.css into the upload area on the GitHub page, or click choose your files and select them both (hold Ctrl / Cmd to select two files at once).
    • Both filenames should appear in the upload list. Do not upload the folder itself — upload the individual files so they sit at the root of the repository.
    • Scroll down to the Commit changes section. Leave the default message ("Add files via upload") or type your own. Click Commit changes.
    your repository root should look like this after uploadyourusername.github.io/ ├─ index.html └─ style.css
  4. Turn on GitHub Pages.
    • In your repository, click the Settings tab (top of the page, after Code / Issues / Pull requests).
    • In the left sidebar under "Code and automation," click Pages.
    • Under "Build and deployment," the Source dropdown should say Deploy from a branch. If it says something else, click it and select Deploy from a branch.
    • Under Branch, click the branch dropdown (it probably says None) and select main.
    • The folder dropdown next to it should say / (root) — leave it there.
    • Click Save.
  5. Wait for the build to finish. After clicking Save, GitHub runs a build process in the background. According to the GitHub documentation, "It can take up to 10 minutes for changes to your site to publish after you push the changes to GitHub." In practice it is often under 2 minutes for a plain HTML/CSS site. Refresh the Settings → Pages page — when the build succeeds, a green banner appears at the top with your live URL: https://yourusername.github.io. You can also click the Actions tab in your repository to watch the deployment progress in real time.
  6. Visit your live site. Click the URL in the green banner, or open a new browser tab and type https://yourusername.github.io (your actual username). Your portfolio is now publicly accessible on the internet.
Common GitHub Pages failure modes — read before assuming something is broken:
  • 404 Not Found: Your home page file must be named exactly index.html (all lowercase) and it must be at the root of the repository — not inside a folder. A file named Index.html, index.HTML, or my-portfolio/index.html will produce a 404. GitHub's servers are case-sensitive.
  • Blank white page with no styles: The style.css file was not uploaded, or it was uploaded into a subfolder. Confirm both files appear at the repository root (not inside any folder) on the Code tab of your repository.
  • Pages says "Your site is ready to be published" but the URL gives a 404: The build has not finished yet. Wait another minute and refresh. If it persists beyond 10 minutes, click the Actions tab and look for a failed workflow run — click on it to see the error message.
  • Wrong branch selected: Go back to Settings → Pages and confirm the branch dropdown shows main (not None or a different branch name). Click Save again if you changed it.
  • Email not verified: GitHub Pages requires a verified email address. Go to your GitHub account Settings → Emails and complete the verification if you skipped it during sign-up.
  • Change you made is not showing up on the live site: After uploading a new version of a file, the site rebuilds automatically but "can take up to 10 minutes." Hard-refresh your browser (Ctrl+Shift+R on Windows, Cmd+Shift+R on Mac) to bypass your browser's cache.
Updating your site later: go to your repository on GitHub, click Add file → Upload files, upload the new version of the file, and commit. GitHub Pages rebuilds automatically. The live site reflects the new version within a few minutes.
Checkpoint — what you should see
Opening https://yourusername.github.io in any browser — on any device, anywhere in the world — shows your styled portfolio: dark background, green name in a sticky header, green nav links, pill-style skill badges, project cards in a grid, and a Contact section showing your real email/GitHub link (not the placeholder). The URL has no file path after the domain. Share it with someone on a different device and confirm they can see it too. That is the checkpoint: a public URL that works, that you own.
