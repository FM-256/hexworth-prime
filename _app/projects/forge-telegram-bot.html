Subject

Build a Telegram Monitoring Bot

Intermediate 2H 800 XP
Mission Brief

This operation requires the construction of a Telegram bot that monitors web pages for changes and uptime, sending instant alerts to your Telegram chat when something goes wrong. Built with Node.js and the Telegram Bot API, the bot accepts slash commands to add and remove monitored URLs, performs periodic HTTP health checks, detects content changes via hash comparison, and dispatches formatted alert messages with status codes, response times, and timestamps directly to your phone.

The bot runs as a long-polling process that simultaneously listens for Telegram commands and executes scheduled URL checks on configurable intervals. Each monitored URL is tracked with its last known status code, response hash, response time, and check history. When a status code changes (200 to 503), content is modified (hash mismatch), or a timeout occurs, the bot immediately sends an alert message with full diagnostic details. A /status command returns a dashboard-style summary of all monitored URLs with uptime percentages and current state.

This project delivers practical experience building real-world automation tools that solve actual operational problems. You will learn how to interact with external APIs, implement scheduled tasks, manage persistent state, and build a conversational command interface — skills that transfer directly to any bot platform or monitoring system.

Agent Requirements
  • Solid Node.js fundamentals: async/await, callbacks, and working with npm packages
  • Basic understanding of HTTP: status codes, GET requests, headers, and timeouts
  • Familiar with JSON for configuration and data storage
  • A Telegram account and the ability to create a bot via @BotFather
  • No prior bot development experience required — this project covers the full Telegram Bot API integration from scratch
Operation Phases
1
Bot Setup & Telegram Integration
Register a new bot with @BotFather on Telegram and obtain the API token. Initialize a Node.js project with node-telegram-bot-api in long-polling mode. Implement the /start command that sends a welcome message explaining available commands. Store the bot token in a .env file loaded with dotenv. Verify two-way communication by echoing back any message the user sends.
Checkpoint: Bot Setup & Telegram
  • Bot responds to /start with a welcome message in Telegram
  • API token is loaded from environment variables, not hardcoded
  • Long-polling mode connects without timeout errors
2
Command Handlers & URL Management
Build a command router that dispatches slash commands to handler functions: /monitor <url> to add a URL, /remove <url> to stop monitoring, /list to show all tracked URLs, and /status for a full health dashboard. Validate URLs before adding them (proper format, reachable). Persist the monitored URL list to a JSON file so the bot survives restarts. Limit the maximum number of monitored URLs per chat to prevent abuse.
Checkpoint: Command Handlers
  • /monitor adds a URL and confirms with a success message
  • /remove stops monitoring and confirms removal
  • /list displays all currently monitored URLs
3
URL Monitor & HTTP Polling
Implement the monitoring loop using setInterval with a configurable check frequency (default 60 seconds). For each URL, perform an HTTP GET with axios, recording status code, response time, and a SHA-256 hash of the response body. Handle timeouts (5-second default), DNS failures, SSL errors, and connection resets gracefully. Store the last 100 check results per URL for history and uptime calculation.
Checkpoint: URL Monitor & Polling
  • HTTP polling checks each URL at the configured interval
  • Timeouts and connection errors are caught without crashing the bot
  • Status code and response time are recorded for each check
4
Change Detection & Alert Dispatch
Compare each check result against the previous state. Trigger alerts on: status code change (e.g. 200 to 503), content hash mismatch (page modified), timeout (site unreachable), and recovery (site back up after downtime). Format alert messages with Telegram's MarkdownV2 syntax including the URL, old/new status, response time, and UTC timestamp. Implement cooldown periods to avoid spamming during prolonged outages — one alert per state change, not per check.
Checkpoint: Change Detection & Alerts
  • Status code change (200 to 503) triggers an immediate alert message
  • Content hash mismatch detects page modifications and notifies the user
  • Recovery alerts fire when a down URL returns to 200 status
5
Status Dashboard & History
Build the /status command that returns a formatted dashboard showing each monitored URL with its current state (UP/DOWN), uptime percentage over the last 24 hours, average response time, and last check timestamp. Implement /history <url> to show the last 10 state changes for a specific URL. Add a /ping <url> command for on-demand checks that bypass the scheduled interval. Calculate and display SLA-style uptime metrics.
Checkpoint: Status Dashboard
  • /status returns a formatted dashboard with UP/DOWN state and uptime percentage
  • History shows the last 10 check results with timestamps
  • Dashboard message is readable and well-formatted in Telegram
