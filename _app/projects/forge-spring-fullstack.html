Subject

Build a Full-Stack App with Spring Boot

Operative 90 MIN 500 XP
Mission Brief

This operation constructs a full-stack web application on the Spring Boot 4.1.0 platform using the MVC (Model-View-Controller) pattern with Thymeleaf server-side templates, a Spring Data JPA persistence layer backed by an H2 in-memory database, and complete CRUD (Create, Read, Update, Delete) operations — all wired together without a single line of XML configuration.

You will build a product catalog: five Java source files and three HTML templates are all that separate an empty project from a browser-accessible, database-backed web application. Spring Boot's auto-configuration handles embedded Tomcat, JPA dialect detection, and Thymeleaf template resolution automatically. You supply the domain logic; the framework supplies the plumbing.

Honest scope note: this is the heaviest software project in the catalog. You must install a JDK and a build tool before writing a single line of code. The Agent Requirements section states the exact prerequisites. Work through each phase in order — every phase ends at a URL you can load in a browser to confirm it is working before moving on.

Agent Requirements
  • JDK 21 (recommended) or JDK 17+ minimum — Spring Boot 4.1.0 requires Java 17 at minimum and supports up to Java 26. JDK 21 is the current LTS release and the safest choice. Verify with java -version before starting. If you see Java 11 or earlier, install a newer JDK first.
  • No separate Maven install needed — Spring Initializr generates a Maven Wrapper (mvnw) inside the project. You run ./mvnw spring-boot:run and it downloads the correct Maven version automatically. You do need internet access on first run (~40 MB download).
  • An IDE or a terminal with a text editor — IntelliJ IDEA Community Edition (free) gives you Java syntax checking and auto-import. VS Code with the Extension Pack for Java also works. A plain terminal with nano is sufficient but harder for Java beginners.
  • Java comfort level: classes, interfaces, annotations — you must be able to read and write a class with fields, a constructor, getters, and an annotation like @Override. Spring's conventions are introduced in the project steps; prior Spring experience is not required.
  • Basic HTTP understanding — know what GET and POST mean, what a URL path is, and that a form submission sends data to the server. Thymeleaf syntax is explained from the first template you write.

Generate the Project and Run the Empty App
Use Spring Initializr at start.spring.io to generate a pre-wired project with the correct dependencies, then confirm the embedded Tomcat starts and serves a response on port 8080 before writing any application code.
  1. Verify your JDK version. Open a terminal and run:
    java -version
    You should see a version line starting with openjdk 21 (or 17–26). If you see version 11 or earlier, install JDK 21 from adoptium.net before continuing.
  2. Open start.spring.io in a browser. Configure the project with these exact settings:
    Project: Maven Language: Java Spring Boot: 4.1.0 (select the current stable, not a SNAPSHOT) Group: com.hexworth Artifact: catalog Packaging: Jar Java: 21 Dependencies (click ADD DEPENDENCIES and search for each): - Spring Web - Thymeleaf - Spring Data JPA - H2 Database - Validation
    Click GENERATE. A file named catalog.zip downloads.
    Why H2? H2 is a pure-Java in-memory database that starts with the application — no separate database server to install or configure. It is not for production use, but it means your app has a real SQL database working in under a minute. In Phase 5 we note how to graduate to PostgreSQL.
  3. Unzip and open the project.
    unzip catalog.zip cd catalog
    The layout you will see:
    catalog/ src/ main/ java/com/hexworth/catalog/ CatalogApplication.java <-- entry point resources/ templates/ <-- Thymeleaf HTML goes here static/ <-- CSS, JS, images application.properties <-- all config here test/ mvnw <-- Maven Wrapper (run this, not mvn) pom.xml <-- dependency declarations

    ./mvnw spring-boot:run
    On first run Maven downloads ~40 MB of dependencies. When it finishes you will see output similar to:
    . ____ _ __ _ _ /\\ / ___'_ __ _ _(_)_ __ __ _ \ \ \ \ ( ( )\___ | '_ | '_| | '_ \/ _` | \ \ \ \ \\/ ___)| |_)| | | | | || (_| | ) ) ) ) ' |____| .__|_| |_|_| |_\__, | / / / / =========|_|==============|___/=/_/_/_/ :: Spring Boot :: (v4.1.0) Started CatalogApplication in 2.341 seconds (process running for 2.6)
    The app is now running. Open a browser and go to http://localhost:8080. You will see a Spring "Whitelabel Error Page" — that is correct. It means the server is up; there are just no controllers yet.

Port 8080 already in use?
  • Find what is using it: lsof -i :8080 (macOS/Linux) or netstat -ano | findstr :8080 (Windows). Kill that process, or add server.port=9090 to application.properties and use http://localhost:9090 instead.
  • On macOS, AirPlay Receiver uses port 5000 and sometimes 8080. Disable it under System Settings → General → AirDrop & Handoff.
mvnw: Permission denied?
  • The wrapper needs execute permission: chmod +x mvnw
  • If Maven cannot download dependencies, check your internet connection. Behind a corporate proxy, set the proxy in ~/.m2/settings.xml.
Checkpoint — what you should see
http://localhost:8080 loads a Spring Whitelabel Error Page (HTTP 404). http://localhost:8080/h2-console loads a login form. Both pages loading confirms the server is up, the H2 console is enabled, and you are ready to add application code.

The JPA Entity, Repository, and H2 Table
Create the Product entity class and a Spring Data repository interface. Spring Data JPA will generate the SQL table automatically when the app starts, and generate the repository implementation at runtime. You will verify the table exists using the H2 console.
  1. Create the model package and the Product entity. Create a new file at src/main/java/com/hexworth/catalog/model/Product.java:
    package com.hexworth.catalog.model; import jakarta.persistence.Entity; import jakarta.persistence.GeneratedValue; import jakarta.persistence.GenerationType; import jakarta.persistence.Id; import jakarta.validation.constraints.NotBlank; import jakarta.validation.constraints.Positive; @Entity public class Product { @Id @GeneratedValue(strategy = GenerationType.IDENTITY) private Long id; @NotBlank(message = "Name is required") private String name; @NotBlank(message = "Description is required") private String description; @Positive(message = "Price must be greater than zero") private Double price; // Required by JPA: a no-argument constructor public Product() {} public Product(String name, String description, Double price) { this.name = name; this.description = description; this.price = price; } // Getters and setters public Long getId() { return id; } public void setId(Long id) { this.id = id; } public String getName() { return name; } public void setName(String name) { this.name = name; } public String getDescription() { return description; } public void setDescription(String d) { this.description = d; } public Double getPrice() { return price; } public void setPrice(Double price) { this.price = price; } }
    jakarta.persistence, not javax.persistence. Spring Boot 3.x and 4.x use Jakarta EE 10+, which renamed all javax.* packages to jakarta.*. If you import javax.persistence.Entity your build will fail with "package javax.persistence does not exist". The correct import is jakarta.persistence.Entity.
  2. Create the repository interface. Create src/main/java/com/hexworth/catalog/repository/ProductRepository.java:
    package com.hexworth.catalog.repository; import com.hexworth.catalog.model.Product; import org.springframework.data.jpa.repository.JpaRepository; import org.springframework.stereotype.Repository; @Repository public interface ProductRepository extends JpaRepository<Product, Long> { // JpaRepository provides: findAll(), findById(), save(), deleteById() // and many more - no implementation needed. }
    No implementation class. Spring Data JPA reads your interface at startup and generates a working implementation automatically. The JpaRepository<Product, Long> declaration tells it: the entity type is Product and the primary key type is Long. That is enough.
  3. Seed the database on startup. Open CatalogApplication.java and add a CommandLineRunner bean:
    package com.hexworth.catalog; import com.hexworth.catalog.model.Product; import com.hexworth.catalog.repository.ProductRepository; import org.springframework.boot.CommandLineRunner; import org.springframework.boot.SpringApplication; import org.springframework.boot.autoconfigure.SpringBootApplication; import org.springframework.context.annotation.Bean; @SpringBootApplication public class CatalogApplication { public static void main(String[] args) { SpringApplication.run(CatalogApplication.class, args); } @Bean CommandLineRunner seedData(ProductRepository repo) { return args -> { if (repo.count() == 0) { repo.save(new Product("Raspberry Pi 5", "ARM Cortex-A76 quad-core SBC, 8GB RAM", 79.99)); repo.save(new Product("Arduino Uno R4", "32-bit Renesas RA4M1 microcontroller, WiFi variant", 27.50)); repo.save(new Product("USB-C Power Delivery Hub", "7-port hub, 100W PD passthrough, 4K HDMI", 45.00)); } }; } }
  4. Restart the app and verify the table in H2.
    ./mvnw spring-boot:run
    Watch the console for a line from Hibernate showing the CREATE TABLE statement (because spring.jpa.show-sql=true):
    Hibernate: create table product (id bigint generated by default as identity, description varchar(255), name varchar(255), price float(53), primary key (id))
    Then open http://localhost:8080/h2-console, connect, and run:
    SELECT * FROM PRODUCT;
    You should see the three seeded rows with ID, name, description, and price.
Table not created / HibernateJpaDialectException?
  • Confirm spring.jpa.hibernate.ddl-auto=update is in application.properties. Without it, Hibernate does not create tables automatically.
  • Confirm the JDBC URL in the H2 console is jdbc:h2:mem:catalogdb — an exact match to what you put in application.properties. The default URL in the H2 console form (jdbc:h2:~/test) connects to a different database and shows no tables.
  • If you see IllegalStateException: Failed to load ApplicationContext, the most common cause is a missing no-arg constructor on the Product entity. JPA requires it. Confirm your entity has public Product() {}.
Checkpoint — what you should see
The H2 console at http://localhost:8080/h2-console connects with URL jdbc:h2:mem:catalogdb. Running SELECT * FROM PRODUCT returns exactly three rows: Raspberry Pi 5, Arduino Uno R4, and USB-C Power Delivery Hub, each with an auto-incremented ID and a price.

The Controller and Thymeleaf List View (GET)
Wire a Spring MVC controller that reads all products from the repository and passes them to a Thymeleaf template. The template uses th:each to iterate and th:text to display values. This is the complete read side of the application.
  1. Create the controller. Create src/main/java/com/hexworth/catalog/controller/ProductController.java:
    package com.hexworth.catalog.controller; import com.hexworth.catalog.model.Product; import com.hexworth.catalog.repository.ProductRepository; import jakarta.validation.Valid; import org.springframework.stereotype.Controller; import org.springframework.ui.Model; import org.springframework.validation.BindingResult; import org.springframework.web.bind.annotation.*; @Controller @RequestMapping("/products") public class ProductController { private final ProductRepository repo; // Constructor injection (preferred over @Autowired on a field) public ProductController(ProductRepository repo) { this.repo = repo; } // GET /products -- list all products @GetMapping public String list(Model model) { model.addAttribute("products", repo.findAll()); return "products/list"; // resolves to templates/products/list.html } // GET /products/new -- show blank create form @GetMapping("/new") public String newForm(Model model) { model.addAttribute("product", new Product()); return "products/form"; } // GET /products/edit/{id} -- show pre-filled edit form @GetMapping("/edit/{id}") public String editForm(@PathVariable Long id, Model model) { Product product = repo.findById(id) .orElseThrow(() -> new IllegalArgumentException("Invalid product id: " + id)); model.addAttribute("product", product); return "products/form"; } // POST /products/save -- create or update @PostMapping("/save") public String save(@Valid @ModelAttribute Product product, BindingResult result, Model model) { if (result.hasErrors()) { return "products/form"; // re-render form with errors inline } repo.save(product); return "redirect:/products"; // Post-Redirect-Get prevents duplicate submission } // GET /products/delete/{id} -- delete and redirect @GetMapping("/delete/{id}") public String delete(@PathVariable Long id) { repo.deleteById(id); return "redirect:/products"; } }
    Why @Controller, not @RestController? @RestController serializes return values to JSON. @Controller returns a view name that Spring resolves to a Thymeleaf template. The string "products/list" maps to src/main/resources/templates/products/list.html.
    A note on delete via GET: this project deletes through a @GetMapping link to keep the first build simple. In a real deployed app, destructive actions should use a POST form protected by a CSRF token — a plain GET link can be fired by a browser prefetch or a crawler and silently delete data. You would add that hardening when you layer in Spring Security later.
  2. Create the template directory and the list view. Create the directory src/main/resources/templates/products/ and then create list.html inside it:
    <!DOCTYPE html> <html xmlns:th="http://www.thymeleaf.org"> <head> <meta charset="UTF-8"> <title>Product Catalog</title> <style> body { font-family: sans-serif; max-width: 800px; margin: 40px auto; padding: 0 20px; } table { width: 100%; border-collapse: collapse; margin-top: 20px; } th, td { text-align: left; padding: 10px 12px; border-bottom: 1px solid #e2e8f0; } th { background: #f8fafc; font-weight: 600; } a { color: #3b82f6; text-decoration: none; } a:hover { text-decoration: underline; } .btn { display: inline-block; padding: 8px 16px; background: #3b82f6; color: white; border-radius: 4px; margin-bottom: 16px; } </style> </head> <body> <h1>Product Catalog</h1> <a href="/products/new" class="btn">+ Add Product</a> <table> <thead> <tr> <th>ID</th> <th>Name</th> <th>Description</th> <th>Price</th> <th>Actions</th> </tr> </thead> <tbody> <!-- th:each iterates over the 'products' list from the controller --> <tr th:each="product : ${products}"> <td th:text="${product.id}"></td> <td th:text="${product.name}"></td> <td th:text="${product.description}"></td> <!-- th:text="${'$' + product.price}" formats as $79.99 --> <td th:text="${'$' + product.price}"></td> <td> <a th:href="@{/products/edit/{id}(id=${product.id})}">Edit</a> | <a th:href="@{/products/delete/{id}(id=${product.id})}" onclick="return confirm('Delete this product?')">Delete</a> </td> </tr> </tbody> </table> </body> </html>
  3. Restart and load the list page.
    ./mvnw spring-boot:run
    Open http://localhost:8080/products. You should see a table with the three seeded products. Edit and Delete links appear in each row but the form template does not exist yet — those will work after the next step.
Thymeleaf TemplateInputException / template not found?
  • The error "Error resolving template [products/list]" means the file does not exist at the path Spring is looking for. Confirm the file is at src/main/resources/templates/products/list.html — the products/ subdirectory must exist.
  • If you see the Whitelabel Error Page at /products instead of your table, the controller is not being found. Confirm ProductController.java is inside the com.hexworth.catalog package tree (any subpackage works). Spring Boot's @SpringBootApplication scans only classes under its own package and below.
Checkpoint — what you should see
http://localhost:8080/products renders a table with three data rows. The Name, Description, and Price columns show the seeded data. The header row shows ID, Name, Description, Price, Actions. An "Add Product" button appears above the table.

Full CRUD: Create, Edit, and Delete via POST Forms
Add the Thymeleaf form template used for both creating and editing products. The same form.html handles both cases — if the product has an ID it is an update, if not it is a create. Delete already works via the GET handler in the controller.
  1. Create the shared create/edit form template. Create src/main/resources/templates/products/form.html:
    <!DOCTYPE html> <html xmlns:th="http://www.thymeleaf.org"> <head> <meta charset="UTF-8"> <title th:text="${product.id} ? 'Edit Product' : 'New Product'">Product Form</title> <style> body { font-family: sans-serif; max-width: 600px; margin: 40px auto; padding: 0 20px; } label { display: block; font-weight: 600; margin-top: 16px; margin-bottom: 4px; } input[type=text], input[type=number], textarea { width: 100%; padding: 8px 10px; border: 1px solid #cbd5e1; border-radius: 4px; font-size: 1rem; } .error { color: #dc2626; font-size: 0.85rem; margin-top: 4px; } .btn-save { margin-top: 20px; padding: 10px 24px; background: #3b82f6; color: white; border: none; border-radius: 4px; font-size: 1rem; cursor: pointer; } .btn-save:hover { background: #2563eb; } a { color: #3b82f6; } </style> </head> <body> <!-- th:text on the h1 changes label based on whether this is create or edit --> <h1 th:text="${product.id} ? 'Edit Product' : 'New Product'">Product Form</h1> <!-- th:action: the URL to POST to. @{/products/save} resolves to /products/save. th:object: binds the form to the 'product' model attribute. method="post": HTML forms support only GET and POST. --> <form th:action="@{/products/save}" th:object="${product}" method="post"> <!-- Hidden field carries the ID during edits so save() knows it is an update --> <input type="hidden" th:field="*{id}"> <label for="name">Name</label> <!-- th:field="*{name}" binds to product.name; sets id, name, and value attributes --> <input type="text" th:field="*{name}" id="name" placeholder="Product name"> <!-- th:errors shows the validation message from @NotBlank on Product.name --> <p class="error" th:if="${#fields.hasErrors('name')}" th:errors="*{name}"></p> <label for="description">Description</label> <input type="text" th:field="*{description}" id="description" placeholder="Brief description"> <p class="error" th:if="${#fields.hasErrors('description')}" th:errors="*{description}"></p> <label for="price">Price (USD)</label> <input type="number" th:field="*{price}" id="price" step="0.01" min="0.01" placeholder="0.00"> <p class="error" th:if="${#fields.hasErrors('price')}" th:errors="*{price}"></p> <button type="submit" class="btn-save">Save Product</button> </form> <p style="margin-top:20px"><a href="/products">← Back to catalog</a></p> </body> </html>
  2. Test the full CRUD cycle without restarting. If the app is running, Thymeleaf detects template file changes immediately (no restart needed for HTML changes; Java changes need a restart). Try each operation:
    Create: Go to http://localhost:8080/products/new Fill in Name, Description, Price and click Save. You should land back at the list with the new row added. Edit: Click Edit on any row. The form loads pre-filled with that product's data. Change a field and Save. The row updates in the list. Delete: Click Delete on any row. Confirm the browser dialog. The row disappears from the list. Validate: Go to /products/new, leave Name empty, click Save. The form re-renders with the error "Name is required" in red below the Name field. The URL stays at /products/save. Fix the field and Save again to confirm the product saves.
  3. Confirm data survives across requests (not page refresh). The H2 in-memory database persists for the lifetime of the running JVM. Add a product, then stop the app (Ctrl+C) and restart it. The seeded products reappear but your manually added product does not — this is expected. The seedData runner uses if (repo.count() == 0) to avoid re-inserting the seeds if any data exists, so it only seeds on a completely empty table.
    Want persistence across restarts? Change the datasource URL in application.properties to a file-based H2 database: spring.datasource.url=jdbc:h2:file:./data/catalogdb. Spring Boot will create a data/ folder in the working directory and write a real file. No other changes needed.
Submitting the form returns HTTP 405 Method Not Allowed?
  • 405 on a POST usually means the controller has no @PostMapping matching the URL, or the form is posting to the wrong path. Confirm the form's th:action is @{/products/save} and the controller has @PostMapping("/save") under @RequestMapping("/products"). The combined URL is /products/save.
  • If the form loads but fields appear blank instead of pre-filled during an edit, the product ID is not being passed to the GET handler. Confirm the Edit link in list.html uses th:href="@{/products/edit/{id}(id=${product.id})}" (not a plain string concatenation).
Validation errors not showing?
  • Confirm the controller's save method signature includes both @Valid @ModelAttribute Product product AND BindingResult result in that exact order. The BindingResult must immediately follow the @Valid-annotated parameter. If placed anywhere else, Spring throws a MethodArgumentNotValidException instead of populating the result object.
  • Confirm the spring-boot-starter-validation dependency is in your pom.xml. If you selected "Validation" on Initializr it is already there. If missing, add it and restart.
Submitting a blank Price shows a generic error page instead of an inline message?
  • An empty form field arrives as an empty string "", and Spring cannot bind "" to a Double — it fails at the binding stage (a 400 / type-mismatch) BEFORE the @Positive validation runs, so you get a generic error page rather than "Price must be greater than zero". This is why the empty-Name test (a String field) shows a clean inline error but an empty Price does not.
  • For this build, always enter a number in Price. To handle it gracefully in a production app, bind the price as a String (or a nullable wrapper) and convert/validate it yourself, or register an @InitBinder with a custom editor that treats an empty string as null so @NotNull/@Positive can report it inline.
Checkpoint — what you should see
Four operations work end-to-end. (1) /products/new loads a blank form. (2) Submitting valid data redirects to /products and the new row appears in the table. (3) Clicking Edit pre-fills the form; saving updates the row in the list. (4) Clicking Delete removes the row. (5) Submitting with an empty Name field re-renders the form with the red error message "Name is required" visible below the Name input.

layout:decorate not recognized / TemplateProcessingException?
  • Confirm the Thymeleaf Layout Dialect dependency is in pom.xml and you restarted the app after adding it. The error "Cannot perform attribute resolution: prefix 'layout' is not known" means the dialect is not on the classpath.
  • If the layout renders but content is blank, confirm the fragment name in the page (layout:fragment="content") exactly matches the layout:fragment in the base template. Names are case-sensitive.
