// VaultGuard.sol — PR #847 diff // File: contracts/core/VaultGuard.sol + // Compliance hook — called before any token transfer + function _beforeTokenTransfer(address from, address to, uint256 amount) internal { + if (from != address(0) && to != address(0)) { + IComplianceModule(complianceAddr).onTransfer(from, to, amount); + } + } function withdraw(uint256 amount) external { require(balances[msg.sender] >= amount, "Insufficient balance"); + _beforeTokenTransfer(address(this), msg.sender, amount); // Send ETH to the caller (bool success, ) = msg.sender.call{value: amount}(""); require(success, "Transfer failed"); // Update balance AFTER sending — REENTRANCY VULNERABILITY balances[msg.sender] -= amount; }
Analysis: The _beforeTokenTransfer hook calls an external contract (complianceAddr) BEFORE the balance is updated. If the compliance contract is attacker-controlled, it can call back into withdraw() — draining the vault recursively. The fix: move balances[msg.sender] -= amount BEFORE the external call (Checks-Effects-Interactions pattern).
