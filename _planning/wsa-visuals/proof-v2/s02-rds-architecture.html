RDS Architecture
Remote Desktop Services — five tiers, one connection flow, port boundaries enforced
CTS1328C Objective #1 · AZ-800
1
Client
Remote user starts mstsc.exe or opens RD Web Access in a browser. From anywhere on the internet.
mstsc.exe · RDP
2
RD Gateway
TLS terminator. Only port the internet can see. CAP policy decides WHO; RAP policy decides WHAT.
TLS · 443 ← public
RD Web Access
Browser portal. Lists published RemoteApps as clickable .rdp feed entries.
3
Connection Broker
The orchestrator. Decides which session host gets your session. Reconnects you when the link drops. Keeps state in shared SQL when clustered.
RDP 3389 · internal only
4
RD Session Host (RDSH)
Where the user's desktop session actually runs. One server, many concurrent sessions, shared OS.
CAL per user / device
RD Virtualization Host
VDI alternative. Each user gets their own Hyper-V VM — pooled (random) or personal (sticky).
5
License Server (CAL)
Issues a Client Access License the first time a user (or device) connects. Without one, sessions get the 120-day grace clock.
Per-User or Per-Device
primary RDP path
alternate (RemoteApp via Web Access, VDI)
━ licensing check
