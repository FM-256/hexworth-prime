##CRISCc - Risk Response and Reporting Effectively

###Objectives:
At the end of this episode, I will be able to understand:

1. When it comes to controls, the third step with designing controls is to test new or changed controls in a non-production environment
2. The test environment should mirror the production environment as much as possible
3. Successful testing is necessary before considering a changeover
4. Change management can assist with making sure controls (changes) are tested and analyzed correctly
5. Implementation and testing should not be limited to technical controls
6. Administrative controls such as (SoD) can help with access permissions, etc.
7. When it comes to control implementation there are three primary types:
  * PARALLEL changeover means operating both the new system and the old system simultaneously. PROS--- Provides the safest and quickest means of changeover in case the changes need rolled back.  CONS – The cost of maintaining and monitoring both systems at the same time and ensuring that Data is consistent between BOTH systems.

  * PHASED changeover is conducted by replacing individual components or modules of the old system with new or modified components.  This reduces the risk by gradually rolling out the new modules in ways intended to protect the entire system.  PROS – mitigates a bit of the risk.  Less expensive.  CONS – Resource challenges, Operational challenges arising from having to maintain and monitor two different sets of user guides and procedures and knowing which sections are new and which are old.

  * ABRUPT changeover = a single instant change from old to new with the old system immediately taken offline.  This is the RISKIEST of the changeover processes because of the potential for the entire system to go down.
8. Risk practitioners should assess the process used for data migration to identify areas of concern
9. Procedures for data recovery should be in place before changeover
10. Areas to be concerned:
  * Completeness of Data conversion
  * Data integrity
  * Storage and Security
  * Data consistency
  * Business continuity
