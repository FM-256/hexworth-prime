 What do you need to know about Incident Response & Logging? -

 Packet analysis - frame-by-frame examination of captured frames

 Protocol analysis - using statistical tools to analyze a sequence of packets,
 or packet trace

      *** both rely on a sniffer tool to capture & decode the frames of data

 Traffic can be captured from a host or from a network segment:

      • Using a host means that only traffic directed at that host is captured

      • Capturing from a network segment can be performed by a Switched Port
      Analyzer (SPAN) port (or mirror port); network switch is configured to
      copy frames passing over designated source ports to a destination port,
      which the packet sniffer is connected to

 Sniffing can also be performed over a network cable segment by using a Test
 Access Port (TAP); device is inserted in the cabling to copy frames passing
 over it; passive and active (powered) versions


 tcpdump - command line packet capture utility for Linux

    • basic syntax of the command is tcpdump -i eth0
    • will then display captured packets until halted manually (Ctrl+C)
    • frames can be saved to a .pcap file using the -w option
    • can open a pcap file using the -r option


 Filter expressions to reduce the number of frames that are captured:

    • Type - by host, net, port, or portrange
    • Direction - by source (src) or destination (dst) parameters (host,
      network, or port)
    • Protocol - by a named protocol rather than port number


    Filter expressions can be combined by using Boolean operators:

    • and (&&)
    • or (||)
    • not (!)


 Filter syntax can be made even more detailed by using parentheses to group
 expressions; a complex filter expression should be enclosed by quotes

    The following command filters frames to those with the source IP 10.5.7.10
    and destination port 25 or 443:

    	tcpdump -i eth0 "src host 10.5.7.10 and (dst port 25 or dst port 443)"



 Wireshark - open-source graphical packet capture & analysis utility

    • can apply a capture filter using the same expression syntax as tcpdump or
    build via a GUI
    • can save the output to a .pcap file or load a file for analysis
    • supports display filters for live capture or a capture file
    • can adjust the coloring rules which control the row shading & font color
    for each frame


 Operating System Logs - The five main categories of Windows event logs are:

     Application - events generated by applications & services
     Security - audit events
     System - events generated by the operating system & its services
     Setup - events generated during the installation of Windows
     Forwarded Events - events that are sent to the local log from other hosts


 Network logs - generated by routers, firewalls, switches, & access points;
 record the operation & status of the appliance itself plus traffic & access
 logs recording network behavior

 Access logs - authentication attempts for each host; can also record access
 attempts to individual files & folders

 Vulnerability logs – vulnerability scan engine might log or alert when a scan
 report contains vulnerabilities

 Netflow logs - provide summary statistics about bandwidth & protocol usage &
 opportunity for detailed frame analysis


 Flow Collector - recording metadata & statistics about network traffic rather
 than recording each frame

 NetFlow - Cisco-developed means of reporting network flow information to a
 structured database

      • redeveloped as the IP Flow Information Export (IPFIX) IETF standard
      (tools.ietf.org/html/rfc7011)

      • a particular traffic flow can be defined by packets sharing the same
      characteristics, referred to as keys, such as IP source & destination
      addresses & protocol type

      • a selection of keys is called a flow label, while traffic matching a
      flow label is called a flow record 


 SiLK suite (tools.netsa.cert.org/silk/) & nfdump/nfsen (nfsen.sourceforge.net/)
 are examples of open-source implementations

 Argus (openargus.org); uses a different data format to NetFlow, but the client
 tools can read & translate NetFlow data


 What do you need to know about Indicators of Compromise? -

 Indicator of Compromise (IOC) - monitoring is reactive & therefore most
 effective when IOCs can be detected as early as possible; heavy emphasis is
 placed on log data & end user reporting of suspicious activities

      • SIEM tools play a critical role in monitoring for IOCs due to their
      ability to collect & process log information across many sources &
      reconstitute the data into actionable outputs

      • high priority alerts generated warrant immediate & close inspection;
      alerts should not be processed in the order in which they were received


 What do you need to know about IOC Notification Sources? -

 Security Information & Event Management (SIEM) - can be configured to automate
 much of the security intelligence cycle in the collection & processing phases,
 generating actionable insights more quickly; integration with SOAR platforms
 can automate some of the tasks involved in analysis, production, & dissemination

 Use case - a specific condition that should be reported

 Template - developed to support a use case & specifies the data sources that
 will contain indicators of the event, the query strings used to correlate
 indicators, & the actions that a detected event should trigger


 IDS/IPS - creates a log entry each time a rule is matched & may or may not take
 action; output formats include:

    • Unified output - creates machine-readable binary files; fast but requires
    an interpreter for a human to read

    • Syslog - uses the syslog format to record event details

    • Comma Separated Values (CSV) - uses character delimiters for fields &
    contents; easier to import into third-party applications or parse using
    regular expressions

    • Tcpdump - uses the pcap file format to record the packets underlying the
    event


 File Integrity Monitoring (FIM)

 Antivirus (AV)

 Data Leak/Loss Prevention (DLP) - automate the discovery & classification of
 data types & enforce rules so that data is not viewed or transferred without
 proper authorization

   • Policy server - to configure classification, confidentiality, privacy rules
   & policies, log incidents & compile reports

   • Endpoint agents - to enforce policy on client computers, even when they are
   not connected to the network

   • Network agents - to scan communications at network borders & interface with
   web & messaging servers to enforce policy


   Remediation is the action the DLP software takes when it detects a policy
   violation; typical remediation mechanisms are:

   Alert only - management system records an incident and may alert an administrator

   Block - user is prevented from copying the original file but retains access
   to it; user may or may not be alerted to the policy violation, but it will be
   logged as an incident by the management engine

   Quarantine - Access to the original file is denied to the user; might be
   accomplished by encrypting the file in place or by moving it to a quarantine
   area in the file system

   Tombstone - original file is quarantined & replaced with one describing the
   policy violation & how the user can release it again

 Infrastructure to leverage when responding to a valid IOC include:

  • Firewall rules
  • IPS/IDS rules

  • Signature rules
  • Behavior rules
  • DLP rules
  • Scripts/regular expressions
