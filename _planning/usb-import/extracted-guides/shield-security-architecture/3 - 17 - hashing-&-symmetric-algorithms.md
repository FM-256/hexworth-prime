Hashing & Symmetric Algorithms

 What do you need to know about Hashing? -

 Hash Functions - take a message and mix it with a hash to derive a unique output
 value, the Message Digest. Generated by the sender & sent along with the message
 to the recipient for two reasons:

  • verify the Integrity of the message
  • verify the authenticity of the message (proof of origin & non-repudiation)

 Message Digests are also called:

 • hashes
 • hash values
 • hash total
 • CRC
 • fingerprint
 • checksum
 • digital ID


 Secure Hashing Algorithm (SHA) - variable length input (up to 2,097,152
   terabytes) gives fixed output as noted:

 SHA-160 = 160 bits (using a 512 bit block size for processing the message data)
 SHA-224 = 224 bits (using a 512 bit block size for processing the message data)
 SHA-256 = 256 bits (using a 512 bit block size for processing the message data)
 SHA-384 = 384 bits (using a 1024 bit block size for processing the message data)
 SHA-512 = 512 bits (using a 1024 bit block size for processing the message data)

  *** SHA1 is considered to be weak, and has been replaced by the SHA2 series
 (SHA-224 | SHA-256 | SHA-384 | SHA-512)

 SHA2 is considered secure, but potentially has same weaknesses as SHA1, so SHA3
 has been produced, called the Keccak algorithm

 The SHA-3 family consists of four cryptographic hash functions and two
 extendable-output functions (XOFs). The cryptographic hash functions are called
 SHA3-224, SHA3-256, SHA3-384, and SHA3-512; and the XOFs are called SHAKE128
 and SHAKE256.

 An extendable-output function (XOF) is a function on bit strings (also called
 messages) in which the output can be extended to any desired length. The two
 SHA-3 XOFs are named SHAKE128 and SHAKE256.

 The suffixes “128” and “256” indicate the security strengths that these two
 functions can generally support, in contrast to the suffixes for the hash
 functions, which indicate the digest lengths. SHAKE128 and SHAKE256 are the
 first XOFs that NIST has standardized.

 Message Digest (2 | 4 | 5) - all produce a 128 bit output

 Hash of Variable Length (HAVAL) - 128 | 160 | 192 | 224 & 256 bits

 RACE integrity primitives evaluation message digest (RIPEMD) - can be used to
 generate outputs of 128, 160, 256, & 320 bits & is used within the PGP
 encryption program as well as the bitcoin standard


 What do you need to know about Message Authentication Codes? -

 Hash-based Message Authentication Code (HMAC) - a message authentication code
 allows both the source & the content of a message to be verified without the
 need to use any other means; a MAC constructed through the use of hashing is an
 HMAC

 Two parameters - the message & a secret key known only to the sender & receiver

    • Sender uses HMAC function to produce a MAC by providing the message &
    secret key to the hash function

    • Output is the MAC which is transmitted along with the message

    • Recipient can compute the MAC by using the message & the secret key,
    providing them both as inputs to the same HMAC function used by the sender
    in order to determine if the MAC matches what was received

    • MAC matches - recipient knows that the message is intact & that the sender
    knows the secret key & by extension is trustworthy


 Poly1305 - a MAC focused on speed & efficiency on devices that do not include
 AES hardware acceleration, such as older iPhone/iPad & Android devices

    • When Poly1305 is combined with alternative encryption algorithms (such as
      ChaCha or Salsa20), produces faster performance than traditional algorithms


 What do you need to know about Symmetric Algorithms? -

 Symmetric Key Algorithms - are SINGLE KEY !!! - We call that key the
 PRIVATE KEY | SECRET KEY | SHARED KEY

 Weaknesses:

  • Key distribution is a challenge / not scalable
  • NO Non-Repudiation possible because everyone has a copy of the key
  • Key must be regenerated whenever anyone leaves the group of keyholders

 Strength:

  • FAST !!! (in comparison to asymmetric)


 What do you need to know about Stream Ciphers? -

 Stream cipher - each digit of data in the plaintext is encrypted one at a time
 using a keystream (a stream of pseudorandom values)

    • Encrypting communications where the total length of the message is not known

    • Keystream is generated through the use of an Initialization Vector (IV)
    combined with a static key value to generate a unique keystream

    • IV is a continuously changing value to ensure that the key produces a
    unique ciphertext from the same plaintext; IV must not be reused with the
    same key

    • Streams must be synchronized; accomplished by exchanging the key during the
    setup of a communication session or transmitted separately

    • RC4 | Salsa20 | ChaCha


 What do you need to know about Block Ciphers? -

 Block cipher - plaintext is divided into equal-size blocks

    • not enough data in the plaintext, then data is padded to the correct size
    using values defined by the algorithm

 Data Encryption Standard (DES)
 Advanced Encryption Standard (AES)


 What do you need to know about Symmetric Block Cipher Modes of Operation? -

 Galois/Counter Mode (GCM) - authenticated encryption with associated data

    • Provides confidentiality & authenticity for the encrypted data & authenticity
    for the additional authenticated data (AAD); AAD is not encrypted

    • GCM mode requires that the IV is a nonce, i.e., the IV must be unique for
    each execution of the mode under the given key
