

# Evaluating COTS and third-party software security

After completing this episode, you should understand:

+ *Exam Objective 8.4.1: Commercial off-the-shelf (COTS); 8.4.3: Third-party

**Description:** In this episode, we will analyze the strategies and processes for evaluating the security impact of acquired software.

## Reducing Risks?

COTS and Third-party software.  Both are acquired so that we do not have to develop them but that doesn't means it's free from security risks.  It could reduce risks in terms cost, time, quality.  But it could introduce them as well.

Compare this to the internal risks of developing software?

* Can what we need be done in-house?
* Can what we need be done in-house with this much money?
* Can what we need to be done in-house with this much money and within a timeframe?
* Can we do all that securely?

## Considerations?

* Differences?
  * COTS is purchasing existing software to fit the need
  * Third-party is developing software to fit our own need.
* Licensing for each?
* Open source vs Proprietary?
* Do not control development process
* Can ask about CMMI level.

## General security evaluation?

* Security practices should be available for review
* Incident Response history
* Industry compliance or regulatory compliance on data protection 
* is it 3rd party tested?
* 

## Specific security evaluation?

* Will it integrate with current security and systems?
* Vulnerability assessment of open-source components used
* Update and patch management cycles
* SLAs and contractors
* Software Escrow?
