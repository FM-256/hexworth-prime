# 1-9-1: Change Management Processes

After completing this episode, you should be able to:

+ Identify and explain the importance of the change management process to security operations, given a scenario.

**Description:** In this episode, the learner examines change management processes and activities. We explore sources of guidance and best practices for change management.


+ Describe the change management  activities
  + Initiation of change/change proposal
  + Assessment and Evaluation
    + The change outlined in the RFC is evaluated for risk, impact, and benefits
    + Includes an understanding of how the change aligns with business objectives
    + Assesses potential disruptions
  + Authorization
    + Reviewed by the appropriate authority, \(often the Change Advisory Board or CAB\)
      + Decides whether to approve, reject, or request more information based on the change's risk and impact
  + Planning
    + If approved, detailed planning for implementing the change begins
    + The plan should align with the information provided in the RFC
  + Implementation and Deployment 
    + The change detailed in the RFC is executed according to the agreed-upon plan
  + Review and Close
    + The outcomes are reviewed against the objectives stated in the RFC
    + Ensure they have been achieved
    + Identify lessons learned for future RFCs
+ Describe sources for the security-centric change management process
  + NIST guidelines
  + NIST SP 800-53
    + Advises on security controls and assessing security effects during system changes.
  + NIST SP 800-37
    + Describes integrating security into the Risk Management Framework, particularly for system modifications.
+ ISO/IEC standards
  + ISO/IEC 27001
    + Establishes protocols for secure information management, highlighting security evaluation during changes.
  + ISO/IEC 27002
    + Offers best practices for information security management, focusing on secure change management.

+ Security Impact Analysis (SIA) 
  + Evaluates how changes to systems, applications, or processes might impact an organization's security stance.
+ Describe SIA activities
  + Change identification
    + Start with pinpointing and understanding the proposed change's scope and nature, from software updates to new hardware introduction.
  + Security baseline assessment
    + Understand the current security setup, including active measures and vulnerabilities, before assessing change impacts.
  + Impact evaluation
    + Analyze how changes might alter security controls and risk levels, and their potential effects on policy compliance.
  + Risk analysis
    + Assess the likelihood and impact of security threats that could exploit the proposed changes.
  + Mitigation strategies
    + Develop risk mitigation plans, which may include enhancing security controls or modifying the change.
  + Documentation and approval
    + Record all SIA outcomes and obtain approval from relevant authorities like the change board and security teams.
  + Monitoring and review
    + Post-implementation, monitor for security effectiveness and review the SIA process for continuous improvement.
+ Describe a Request for Change \(RFC\)
  + A formal proposal for an alteration to be made to a service or IT environment.
  + The RFC is typically created during this initial phase. It represents the formal initiation of a potential change, capturing all relevant details such as the reason for the change, the proposed action, the resources required, and the potential impacts.
