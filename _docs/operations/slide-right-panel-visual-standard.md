# Slide Right-Panel Visual Standard

**Status:** AUTHORITATIVE — defines the default visual register for slide right panels across WSA, ALA, PIS, and Ethics decks
**Created:** 2026-06-09
**Last revised:** 2026-06-09 (v2 — Graphviz pipeline added after fal.ai "advertising flyer" failure case)

**Trigger v1 (2026-06-08):** Operator correction after 85-SVG fan-out shipped (commits `53dd531c4`..`be6b11bdf`) — boxes-with-text instead of illustrated infographics.

**Trigger v2 (2026-06-09):** Operator correction after 321 fal.ai Recraft V3 images shipped (commits `925ba32c6` + `8515c478b` + `486fcc0a0`) — "advertising flyers" with garbled labels and decorative isometric scenes instead of real labeled architecture diagrams. Pipeline pivot: architecture / flow / comparison slides → Graphviz `dot` (deterministic, accurate labels). Image-gen retained for stylized illustration slides only.

---

## TLDR

**Default by slide shape, NOT by deck:**

| Slide output shape | Tool | Why |
|---|---|---|
| Architecture diagram, flow, hierarchy, state machine, comparison table | **Graphviz `dot`** (or D2/Mermaid) — diagram-as-code | Deterministic layout, real-font labels, $0 per render, source is reproducible in git |
| Illustrated educator-style infographic (Dan-Nanni / Cyber Edition style), concept poster | **fal.ai** image gen + (optional) animation pipeline | High visual register, character art, iconography |
| Structural reference (packet header byte layout, RFC field annotation, navigation map) | **Hand-authored SVG** with `<tspan>` annotations | Format demands explicit positional control |
| Tool / GUI walkthrough | **Recorded screencap → MP4 / animated WebP** | The actual UI is the lesson |

**Never default to one tool for all visuals.** Segment by shape first. Pick the tool to match. Prove one of each shape before fanning out.

**Hard NO:** LLM-authored topical illustration SVG (rectangles + text labels generated by Claude / GPT). That path produced the 2026-06-08 box-and-text failure and is documented in the case study below.

## What works for which use case (decision matrix)

| Slide output shape | Tool | Asset format | Cost / render |
|---|---|---|---|
| **Architecture diagram** — "RDS Architecture", "DNS resolution path", "PKI trust chain", "AD replication topology" | **Graphviz `dot`** | PNG → WebP | $0, ~1 sec |
| **Flow / sequence** — "RD Gateway path", "How NAT translates addresses", "Kerberos ticket flow" | **Graphviz `dot`** with numbered edge badges | PNG → WebP | $0, ~1 sec |
| **State machine** — "RDS session states", "TCP connection states", "GPO processing states" | **Graphviz `dot`** with state-machine layout | PNG → WebP | $0, ~1 sec |
| **Side-by-side comparison** — "Per-User vs Per-Device CALs", "Session vs VDI deployment", "CAP vs RAP policies" | **Graphviz `dot`** with subgraph cluster panels, OR hand SVG with explicit 2-column table | PNG → WebP / SVG | $0 |
| **Hierarchy** — "RDS role services", "AD OU structure", "Certificate template hierarchy" | **Graphviz `dot`** TB layout | PNG → WebP | $0 |
| **Illustrated educator-style infographic** — Dan Nanni / Cyber Edition register, character art, isometric icons, narrative-driven visuals | **fal.ai** (Recraft V3 or FLUX 1.1 Pro) | WebP / static + GIF | ~$0.05 |
| **Concept poster / lab preview / module summary** — slides that are scene-setting, not architecture | **fal.ai** image gen with per-slide prompt | WebP | ~$0.05 |
| **GUI / tool walkthrough** — Server Manager screens, IIS Manager, gpresult output | **Recorded screencap** → MP4 / animated WebP | MP4 / WebP | recording time |
| **Structural reference** — RFC byte layouts, packet header field annotations, regex anatomy | **Hand-authored SVG** with `<tspan>` positional annotations | inline SVG | spec time |
| **Module-map navigation** — slide-1 functional-summary 9-stop journey | **Hand-authored SVG** (existing pattern) | inline SVG | spec time |

**Key rule:** If the slide's takeaways read "X talks to Y over port Z" or "A vs B" or "states are S1/S2/S3" → it's a Graphviz job, not an image-gen job.

**LLM-authored topical SVG (rectangles + text labels generated by Claude/GPT as inline SVG strings) is now banned.** That path produced the 2026-06-08 box-and-text failure. Replace with Graphviz `dot` for diagrams, hand-SVG for structural references.

## Tooling — Graphviz `dot` (diagram-as-code, default for architecture / flow / comparison / state / hierarchy)

`dot` ships with `graphviz` (`apt install graphviz`) and is installed in the dev environment. Renders deterministic labeled diagrams from declarative source files.

### Canonical pipeline

1. **Read the slide's actual takeaways** from the module HTML. Each `<li>` and `<h3>` becomes a node or edge label. Each "→" or "vs" is an arrow direction or comparison panel.
2. **Author a `.dot` file** at `_planning/wsa-visuals/{module}/{slug}.dot` (tracked in git for reproducibility). Use the templates below.
3. **Render** with:
   ```
   dot -Tpng -Gsize=12.8,7.2! -Gratio=fill -Gdpi=130 input.dot -o output.png
   ```
4. **Convert PNG → WebP** for storage:
   ```python
   from PIL import Image
   Image.open('output.png').convert('RGB').save(
       '_app/assets/images/wsa-visuals/{module}/{slug}.webp',
       'webp', quality=92, method=6
   )
   ```
5. **Embed** in the slide's `slide-visual` div as `<img src="/assets/images/wsa-visuals/{module}/{slug}.webp" ...>`.

### Canonical example

The proof-of-concept lives in the repo:
- Source: `_planning/wsa-visuals/m12-remote-desktop/s02-rds-architecture.dot`
- Render: `_app/assets/images/wsa-visuals/m12-remote-desktop/rds-architecture.webp`
- Branch: `m12-proof-rds-arch` · commit `e35d88bc2`
- Preview channel: https://hexworth-prime--m12-proof-16a4vozy.web.app/houses/cloud/modules/wsa/m12-remote-desktop/cloud-presentation.module.html

### Style guide for WSA decks

| Attribute | Value | Why |
|---|---|---|
| `bgcolor` | `#0c1a2e` | Matches slide-visual panel dark navy |
| `fontname` | `Inter` (sans default) | Matches deck typography |
| Node `shape` | `box`, `style="rounded,filled"`, `penwidth=2` | Soft modern card look |
| Node `margin` | `"0.25,0.18"` | Breathing room around text |
| Edge `color` | `#7aa2ff` (default), `#f97316` (orange = service interaction), `#16a34a` (green = control) | Color encodes flow type |
| Edge `fontcolor` | `#ffd86b` | Labels read warm-yellow against navy |
| `rankdir` | `TB` for hierarchy/state, `LR` for short flow | TB renders 16:9 slide panels best |
| Numbered step badges | Use `①②③④⑤` Unicode in edge labels | Echoes the reference set's narrative numbering |
| Dashed edges | `style=dashed` for alternate paths / optional flows | Visual distinction without color overload |

### When NOT to use Graphviz

- Illustrated character art (use fal.ai)
- Scene-setting / lab preview / concept poster (use fal.ai)
- Animated data flow (use fal.ai Veo3 / Kling for the static, animate, export GIF)
- Pixel-precise positioning (use hand-authored SVG)

| Model | Endpoint | Cost (approx) | Notes |
|---|---|---|---|
| FLUX 1.1 Pro | `fal-ai/flux-pro/v1.1` | ~$0.05 | High quality, photorealistic-leaning |
| FLUX 1.1 Pro Ultra | `fal-ai/flux-pro/v1.1-ultra` | ~$0.10 | Higher resolution, more detailed |
| Recraft V3 | `fal-ai/recraft-v3` | ~$0.04-0.10 | Best for designed infographics with text + icons |
| Imagen 3 | `fal-ai/imagen3` | ~$0.04 | Strong on text rendering |

### Animated content

| Model | Endpoint | Cost (approx) | Output |
|---|---|---|---|
| Veo3 | `fal-ai/veo3` (image-to-video) | ~$1.50-2.00 per 6s clip | Highest quality, photorealistic motion |
| Kling 1.6 Pro | `fal-ai/kling-video/v1.6/pro` | ~$0.50-1.00 per 5s clip | Good motion, faster than Veo3 |
| Pika 2.2 | `fal-ai/pika/v2.2` | ~$0.20-0.40 per 5s clip | Faster + cheaper, lower quality |

### Pipeline

Recommended for WSA slides:
1. Generate static infographic with **Recraft V3** (best for designed text+icon layouts) or **FLUX 1.1 Pro Ultra** (more photorealistic). Prompt for the reference style explicitly.
2. (Optional) Animate via **Kling 1.6 Pro** or **Veo3** with image-to-video using the static as input
3. Convert MP4 → GIF via `ffmpeg -i input.mp4 -vf "fps=12,scale=800:-1:flags=lanczos,split[s0][s1];[s0]palettegen[p];[s1][p]paletteuse" output.gif`

Cost per slide: ~$0.10 (static only) to ~$2.00 (animated). Budget for 21 stub slides: ~$3-50 depending on path.

### Prompt template

For an animated infographic-style slide visual, prompt structure:

```
Educational infographic illustration in the style of Dan Nanni / Cyber Edition cybersecurity educators on social media. Topic: [X]. Show [main components] as illustrated isometric icons with colored data-flow arrows between them. Numbered steps 1, 2, 3, 4 labeling the flow. [Specific elements: e.g., "show a brick-pattern firewall between client and server", "use a hooded hacker silhouette for the attacker"]. Dark background, vibrant accent colors (red for threats, green for legitimate, blue for data). Bold title bar at top. Clean educational style, not photorealistic. 1280x720 aspect ratio.
```

Iterate prompts. Some topics need 2-3 attempts to hit the right composition.

## What NOT to do

❌ Author LLM-generated SVG with rectangles and text labels for topical illustration
❌ Use fal.ai / Recraft / FLUX to generate architecture diagrams — text labels will be garbled, layout will be hub-and-spoke regardless of prompt
❌ Use module-wide context as the prompt for every slide in a module (recycles the same bullet list as decorative poster — see case study below)
❌ Use one tool ("fal.ai for everything", "SVG for everything") regardless of slide output shape
❌ Make checklist-shape "table" SVGs and call them visuals
❌ Pretend a single 1-rect + 2-text "stub" placeholder is a visual
❌ QC by counting `slide-visual` div presence (the audit metric used 2026-06-08 missed all the stubs)
❌ QC by "looks good on a quick eyeball" — read every label, verify every port number, compare to reference set
❌ Default to "drop has-visual class so layout collapses" — that ditches the visual entirely
❌ Skip the Nancy review on the tool-choice itself (not just the prompt)

✓ DO segment slides by output shape FIRST, match tool to shape
✓ DO use Graphviz `dot` for any architecture / flow / state / hierarchy / comparison slide
✓ DO use fal.ai with PER-SLIDE specific prompts for illustrated educator-style infographics
✓ DO author illustrated animated GIFs ONLY for the slides whose shape calls for them
✓ DO QC by character density + label accuracy + render-look on a sample slide per module
✓ DO use SVG only where SVG is structurally the right format (packet headers, RFC byte layouts, navigation maps)
✓ DO study the reference set before generating any visual
✓ DO ship ONE proof of each shape before fanning out across N slides

## Failure mode case study — 2026-06-09 fal.ai flyer batch

**Symptom:** 321 fal.ai Recraft V3 images shipped to production across m01-m19 (commits `925ba32c6` + `8515c478b` + `486fcc0a0`). Operator pulled up m12 and called the result "a disaster... advertising flyers." Every slide image had the title stamped on top, a stock isometric office scene below, and the module-wide bullet list pasted as either a poster on the wall or a list overlay. Garbled text labels — "(CL)" instead of "(CAL)", "Virt Host VDIper V" instead of "VDI on Hyper-V", port numbers "35" "49" instead of "3389" "443". Same generic scene repeated across every slide in the module with only the title swapped.

**Root cause:** Prompt structure `title + per-module-context-bullet-list + style` — the model dutifully painted the same generic scene per module and swapped the title. The per-module context was a static dict like `m12-remote-desktop: "Session Hosts, Connection Brokers, Gateways, RemoteApp, Licensing, RDS topology"` — that line went into every m12 prompt. So every m12 slide encoded the same bullet list.

**Why the tool was wrong, not the prompt:**

Generative image models (Recraft, FLUX, SDXL, Imagen) **cannot reliably render structured text labels**. The reference set the operator pointed at (`datacenter-networking.jpg`, `routing protocols.jpg`, `reverse shell.jpg`) has crisp labels because they're composed in Illustrator with real fonts + icon libraries — not AI-generated. Trying to coerce Recraft V3 into producing accurate "Connection Broker" / "RD Gateway" / "License Server (CAL)" labels via prompt engineering was the wrong axis to optimize. The right move was tool substitution: Graphviz `dot` produces accurate labels because it lays out type with real system fonts, not generated pixels.

**Process failures:**

1. Locked onto `fal.ai` because it was already in the icon pipeline — didn't ask "what tool fits this output shape" at decision time
2. Optimized for parallel-batch throughput (194 images in 414s) rather than per-artifact quality
3. Treated the first-batch failure as a prompt-engineering problem (digital_illustration → vector_illustration → per-slide prompts) instead of a tool-choice problem
4. Skipped Nancy review on the pipeline architecture decision
5. Shipped 321 artifacts without reading the labels on a representative sample — "looks good on a quick eyeball" passed when text degradation was the actual defect

**Remediation:**

- Architecture / flow / comparison / state / hierarchy slides → migrate to Graphviz `dot` per the decision matrix above
- Pure illustration slides (concept posters, lab previews, module summaries) → keep fal.ai but re-spec per-slide prompts using the actual slide takeaways, not module-wide context
- All future visual pipelines: prove ONE artifact of each shape before fan-out; dispatch Nancy on the tool choice; do not ship without label-accuracy QC

**Memory:** `[[feedback_tool_selection_before_pipeline]]` captures the lesson for future similar tool-pipeline decisions.

## Known limitations of LLM SVG authoring

The fan-out on 2026-06-08 (85 SVGs across m10-m17, agents `a4890f22cd8443a3e` + 7 follow-ups) produced 85 information-dense but visually flat diagrams. LLM models (incl. Claude, GPT-4o, Sonnet) reach for templated SVG patterns because that maps cleanly to authoring SVG via stringified code. They do not reach for illustrative composition, depth, iconography, or real character art.

Lottie animations (from lottiefiles.com) are a middle ground but rarely match the exact topic narrative. Use for generic motion (loading, connecting, syncing) — not for technical content.

Pre-recorded GUI screencaps are appropriate for tool-heavy slides where the actual UI conveys the lesson better than abstract illustration.
